## Passing data between computations

The same `Vec<f64>` has different meanings and units for position, velocity, or concentration.
Types do not distinguish component meanings; document these conventions in prose and code comments.
Adaptive ODE output times are irregular and cannot directly feed FFTs requiring uniform samples.
Check the following conditions at every connection.

1. Align component order, dimensions, units, and coordinate systems.
   Reading state returned in $(x,y,v_x,v_y)$ order as $(x,v_x,y,v_y)$ can silently produce incorrect results.
2. Check domains and continuity required by interpolation or root finding.
   Bracketing methods such as Brent assume opposite endpoint signs and continuity between them.
3. Read inner termination reasons; do not pass incomplete values as completed computations.
   If integration stops at a step limit, the final state is not the terminal-time value.
4. Distinguish state errors from residuals and convert errors through observable sensitivities.
   Small residuals do not immediately imply small errors in the desired quantity.

The next example makes the fourth conversion concrete.
[Error propagation](../concepts/composition/) gives the general treatment.

## Inner errors and root-finding accuracy

Consider first-order concentration decay $c'=-kc$ with $c(t)$ and $c(0)=1$.
Time $t$ is in s, reaction rate constant $k$ in s⁻¹, and concentration is normalized by its initial value.
Find $k$ making concentration $c_*=0.3$ at time $T=2$ s.
The analytical solution is $c(T;k)=\exp(-kT)$, giving independent reference $k_*=-\log(c_*)/T\approx 0.601986$ s⁻¹.

Although solvable analytically, follow the procedure used when no analytical solution is known.
Numerically integrate the ODE concentration and use it in the root-finding objective.
Use the analytical solution only for the final comparison.

### Error propagation

The outer residual is $F(k)=c(T;k)-c_*$.
Writing numerical concentration as $\tilde c(T;k)=c(T;k)+\delta c(k)$, the actual function whose zero is sought is

$$
\tilde F(k)=F(k)+\delta c(k)
$$


Suppose the root finder obtains the zero $\tilde k$ of $\tilde F$ exactly.
First-order expansion of $F$ around $k_*$ gives $0=\tilde F(\tilde k)\approx F'(k_*)(\tilde k-k_*)+\delta c(\tilde k)$, so near simple root $F'(k_*)\neq 0$,

$$
|\tilde k-k_*|\approx\frac{|\delta c|}{|F'(k_*)|}
$$


Here $\partial c/\partial k=-T\exp(-kT)$, so $F'(k_*)=-Tc_*=-0.6$ s.
Concentration errors are amplified by about $1/0.6\approx 1.7$ into errors in the reaction rate constant.
When $\lvert F'(k_*)\rvert$ is small, meaning weak dependence of the observable on parameters, the same $\delta c$ yields larger parameter error.
$1/\lvert F'(k_*)\rvert$ is the absolute condition number of this inverse problem.

This is a first-order approximation; ODE local tolerance cannot simply substitute for $|\delta c|$.
Adaptive ODE solvers keep estimated local errors within tolerance at each step.
Terminal global error combines propagated local errors and can exceed or fall below that tolerance.
Check actual $|\delta c|$ against analytical solutions or tolerance refinement.

Also, $\delta c(k)$ is not smooth in $k$.
Small changes in $k$ alter the accepted step sequence, making errors fluctuate irregularly on the tolerance scale.
Thus $\tilde F$ perturbs $F$ with small irregularities; reducing outer tolerance below $|\delta c|/|F'(k_*)|$ does not improve proximity to $k_*$.
Tightening only outer tolerance does not remove inner evaluation errors.

### Outer root finding

Use `Brent` for outer root finding.
Brent maintains opposite-sign endpoints while attempting inverse quadratic or secant steps, switching to bisection when they do not sufficiently shrink the bracket.
Simple-root convergence is superlinear; bisection fallback guarantees convergence to an in-bracket zero for continuous functions.
Every iteration preserves opposite signs, so even if $\tilde F$ is irregular or discontinuous at step-sequence changes, the final bracket contains a sign-changing point of $\tilde F$.
Its distance from $k_*$ follows the preceding estimate.

For bracketing methods, step tolerance $(\tau_a,\tau_r)$ in `ScalarRootOptions` tests the width of the final bracket $[a,b]$ through

$$
b-a\le\tau_a+\tau_r\max(|a|,|b|)
$$

the criterion above.
Defaults are $\tau_a=\tau_r=4\varepsilon$ ($\varepsilon$ is f64 machine epsilon), with an iteration limit of 100.
Meeting this criterion gives termination `BracketTolerance` and true from `is_success()`.
Limit exhaustion gives `IterationLimit` with the best point at that stage.

### Cell structure

The following cell independently specifies inner and outer tolerances.
Inputs are ODE tolerance $10^{p}$ exponent $p$ and root tolerance $10^{q}$ exponent $q$.
Give the ODE both absolute and relative $10^{p}$, and root finding $\tau_a=\tau_r=10^{q}$.

The APIs are used in this order.

1. `Decay` implements `OdeSystem` and returns right-hand side $-kc$.
   State has one component, so `dimension` returns 1.
2. Objective closure `ScalarFn` constructs a terminal-time $T=2$ problem through `OdeProblem::new(&system, 2.0)` for each $k$.
3. `ErrorTolerance::scalar(atol, rtol, NormSelection::Infinity)` specifies shared component tolerances and the maximum norm.
   Steps are accepted when error estimate $e_i$ satisfies $|e_i|\le \mathrm{atol}+\mathrm{rtol}\,s_i$ for every component.
   $s_i$ scales with solution magnitude.
4. `DormandPrince5` combines fifth- and fourth-order explicit Runge–Kutta formulas, estimating local error from their difference and advancing the fifth-order solution.
   Allocate workspace through `workspace` and advance `state` to terminal time with `advance`.
   `advance` updates `state` in place; its returned report carries the termination reason.
5. If report `is_success()` is false, return an error instead of using a concentration that has not reached terminal time.
   The `solve` of `Brent` propagates closure errors unchanged.
6. Pass bracket $[0.1,2]$ s⁻¹ to `Brent.solve`.
   Endpoints give $F(0.1)\approx 0.52$ and $F(2)\approx-0.28$, with opposite signs.

The objective allocates workspace at every evaluation.
This costs little for one component; for large systems, prepare it outside the closure and reuse it.

The cell tabulates estimate, analytical value, their difference, and analytical concentration residual $\exp(-T\tilde k)-c_*$.
Analytical values and residuals use standard-library `exp` and `ln` independently of the ODE.
The final outcome gives root-finding termination and analytical error.

```rust
//| id: app-nested-tolerance
//| ref: app-nested-tolerance
//| title: "Reaction-rate estimation and inner integration error"
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg, scioxide-ode, scioxide-rootfind]
//| inputs:
//|   inner_exponent: {"type":"range","label":"ODE tolerance exponent","min":-10,"max":-3,"step":1,"value":-6}
//|   outer_exponent: {"type":"range","label":"Root-finding tolerance exponent","min":-12,"max":-4,"step":1,"value":-9}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"estimate","path":"/rows/0/2","range":{"max":1e-6}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
use scioxide_core::{
    ErrorTolerance, ExecutionContext, SciOxideError, Interval, NormSelection, StepTolerance,
};
use scioxide_linalg::Vector;
use scioxide_ode::{
    DormandPrince5, OdeMethod, OdeOptions, OdeProblem, OdeState, OdeSystem, OdeTrajectory,
};
use scioxide_rootfind::{Brent, ScalarFn, ScalarRootOptions, ScalarRootSolver};

struct Decay(f64);
impl OdeSystem<f64> for Decay {
    fn dimension(&self) -> usize {
        1
    }
    fn rhs(
        &self,
        _: f64,
        y: &[f64],
        dy: &mut [f64],
        _: &mut scioxide_core::SolveContext<'_, '_>,
    ) -> Result<(), SciOxideError> {
        dy[0] = -self.0 * y[0];
        Ok(())
    }
}
let inner = 10.0_f64.powf(inner_exponent);
let outer = 10.0_f64.powf(outer_exponent);
let objective = ScalarFn::new(|rate: f64| {
    let system = Decay(rate);
    let problem = OdeProblem::new(&system, 2.0);
    let tolerance = ErrorTolerance::scalar(inner, inner, NormSelection::Infinity)?;
    let options = OdeOptions::default().with_error_tolerance(tolerance);
    let method = DormandPrince5::new();
    let mut workspace = method.workspace(&problem, &options)?;
    let mut state = OdeState::new(0.0, Vector::from_vec(vec![1.0]));
    let mut path = OdeTrajectory::new();
    let report = method.advance(
        &problem,
        &options,
        &mut state,
        &mut path,
        &mut workspace,
        ExecutionContext::sequential(),
    )?;
    if !report.is_success() {
        return Err(SciOxideError::external("Inner integration did not reach terminal time"));
    }
    Ok(state.values()[0] - 0.3)
});
let options = ScalarRootOptions::default()
    .with_step_tolerance(StepTolerance::new(outer, outer).map_err(|e| e.to_string())?);
let root = Brent
    .solve(
        &objective,
        Interval::new(0.1, 2.0).map_err(|e| e.to_string())?,
        &options,
    )
    .map_err(|e| e.to_string())?;
// Check analytical solution and concentration independently using the standard library.
let exact = -0.3_f64.ln() / 2.0;
let residual = (-2.0 * root.point()).exp() - 0.3;
emit_table_with_columns!(
    serde_json::json!([
    {"key":"0","label":"Estimated k [s⁻¹]","type":"number","format":{"significantDigits":6},"nullText":"Undefined"},
    {"key":"1","label":"Analytical value [s⁻¹]","type":"number","format":{"significantDigits":6},"nullText":"Undefined"},
    {"key":"2","label":"Absolute error [s⁻¹]","type":"number","format":{"significantDigits":6},"nullText":"Undefined"},
    {"key":"3","label":"Analytical concentration residual [-]","type":"number","format":{"significantDigits":6},"nullText":"Undefined"}
    ]),
    vec![(root.point(), exact, (root.point() - exact).abs(), residual)],
    metadata = serde_json::json!({"id":"estimate"})
);
let outcome = if root.is_success() {
    Outcome::satisfied("Root-finding termination condition satisfied")
} else {
    Outcome::partial("Root-finding termination condition unmet")
};
emit_outcome!(outcome.status(root.termination().to_string()).diagnostic(
    "Absolute analytical difference",
    (root.point() - exact).abs(),
    Some("s⁻¹")
));
```

### Reading results

The analytical residual differs from the root finder's own residual $\tilde F(\tilde k)$.
Its residual uses numerically integrated concentration and is nearly zero at termination.
The analytical residual is approximately $F'(k_*)(\tilde k-k_*)$ to first order, about 0.6 times the tabulated absolute error.
When this holds, both columns express the same error in different quantities.

Compare two cases by changing inputs.

- Fix ODE tolerance and tighten only root tolerance.
  Absolute error eventually stops decreasing at the floor set by ODE error.
- Tighten both together.
  Absolute error decreases with ODE tolerance.

This distinguishes outer convergence from accuracy against the model equations.
Conversely, if root tolerance is looser than the ODE error estimate, it determines absolute error.
Choosing outer tolerance comparable to propagated inner error $|\delta c|/|F'(k_*)|$ avoids unnecessary work in either computation.

## Work and termination reasons

For $m$ outer evaluations, each inner integration averaging $n$ right-hand-side evaluations, main work is $mn$ right-hand-side evaluations.
`DormandPrince5` evaluates the right-hand side six times per accepted step, reusing its last stage as the next first stage.
Error estimates scale as $O(h^5)$ in step size $h$, so for smooth solutions the step count is approximately proportional to $\mathrm{tol}^{-1/5}$.
Tightening tolerance by four orders of magnitude increases step count by about $10^{4/5}\approx 6.3$.
Brent's evaluation count $m$ grows slowly with bracket-width digits because convergence is superlinear.

Excessive inner accuracy makes every outer evaluation more expensive.
Overly coarse inner computation enlarges irregularities in $\tilde F$, preventing comparison of small parameter changes.
First establish necessary inner accuracy through analytical solutions or refinement, then select outer stopping criteria.

Check termination from inner to outer.
Propagate any integration that misses terminal time as an error and stop outer root finding on it.
Inspect outer termination through `termination()`; if unsuccessful, emit outcome `partial`.
This prevents incomplete inner values from appearing as successful outer results.

## Summary and further reading

When combining crates, carry component order, units, domains, and termination reasons through the pipeline.
Inner error $\delta c$ propagates at scale $\delta c/\lvert F'\rvert$, so low-sensitivity inverse problems need more accurate inner computation.
Outer tolerance below this propagated error does not improve the result.
Measure inner error through analytical solutions or refinement, then select outer tolerance from it.
Consult [Error propagation](../concepts/composition/) for general formulas and limit allocation, then use invariants and sensitivity checks in the applications above.
