Tolerances specify the scale on which a computation is accepted and when it stops.
The configured value does not necessarily bound the error against the true solution.
Distinguish the roles of absolute and relative error, and choose a scale appropriate for the residual or error estimate.

---

## Mathematical roles of absolute and relative tolerances

For an error estimate or residual $e_i$ associated with component $i$, the following normalized ratio $\eta_i$ is widely used to determine when iteration terminates.

$$
\eta_i = \frac{|e_i|}{\tau_{\mathrm{abs}, i} + \tau_{\mathrm{rel}} |y_i|}.
$$

The denominator is the allowed error width, determined by adding two terms.

- The absolute tolerance $\tau_{\mathrm{abs}, i}$ has the same units as the error $e_i$ being compared.
  For errors in state quantities, these may be m, s, K, mol/L, or other units; this term determines the allowed width near zero.
- The relative tolerance $\tau_{\mathrm{rel}}$ is dimensionless and determines an allowed width proportional to the representative value $|y_i|$.
  When assessing a residual, use a representative value with the same units as the residual, rather than the state quantity.

| Computational situation | Role of absolute tolerance $\tau_{\mathrm{abs}}$ | Role of relative tolerance $\tau_{\mathrm{rel}}$ |
|---|---|---|
| **A state value crosses zero** | Prevents divergence near zero and enables a stopping test | Does not work alone as the denominator approaches zero |
| **State values vary across several orders of magnitude** | Provides a safeguard against underestimation in the small-value range | Automatically adjusts the allowed width in proportion to magnitude |
| **Instrument resolution is known** | Prevents excessive searches for physically meaningless trailing digits | Specifies significant digits according to a representative value |
| **A coupled system has components with different dimensions** | Specifies each component's physical scale separately | Specifies a shared accuracy criterion after nondimensionalization |

If absolute tolerance is zero, a zero representative value makes the denominator zero as well.
In this case, `ErrorTolerance::normalized_norm` assigns zero contribution when the error is also zero, and returns `NumericalInstability` when the error is nonzero.
`is_satisfied`, which only tests acceptance, returns `Ok(false)` for a nonzero error with zero allowed width.
A positive absolute tolerance maintains a finite allowed width even near zero.
Conversely, using only absolute tolerance makes the relative requirement looser for small values and stricter for large values, even with the same allowed width.

## Crossover scale $s_{\times}$ and transitions between dominant terms

When relative tolerance is positive, the ratio of the tolerances determines the state scale at which the two terms balance.

$$
s_{\times} = \frac{\tau_{\mathrm{abs}}}{\tau_{\mathrm{rel}}}.
$$

The absolute term dominates for $|y| \ll s_{\times}$, and the relative term for $|y| \gg s_{\times}$.
Choose both the required absolute and relative accuracy, and check whether their crossover fits the range of values under consideration.
Instrument resolution can inform this choice, but treat measurement error and numerical error as separate contributions.
The cells in [`scioxide-core` tolerance roles and acceptance contracts](../../scioxide-core/algorithms/error-and-tolerance-contracts/) demonstrate the relationship between the terms.

## Choosing and scaling vector norms

In multivariable systems and time integration, combine the componentwise normalized ratios $\eta_i$ into a single value for assessment.
Typical choices are the maximum norm and root-mean-square (RMS) norm.

$$
\|\boldsymbol{\eta}\|_\infty = \max_{1 \le i \le n} |\eta_i|,
\qquad
\|\boldsymbol{\eta}\|_{\mathrm{RMS}} = \sqrt{\frac{1}{n} \sum_{i=1}^n \eta_i^2}.
$$

A maximum norm of at most 1 means that every component is within its individual allowed width.
The RMS norm is unchanged when the same error distribution is replicated, but averaging can hide a small number of large components.
In particular, with only one nonzero component, the RMS norm is $1/\sqrt{n}$ times that component's magnitude.
Choose the maximum norm when you want to detect componentwise violations.
Both tests assess the supplied error estimates; they do not prove true error bounds or physical safety.

Do not feed components with different physical units (for example position $\mathrm{m}$, velocity $\mathrm{m/s}$, and temperature $\mathrm{K}$) directly into the Euclidean norm $\sqrt{\sum y_i^2}$.
Always nondimensionalize each component by its representative scale and construct normalized ratios $\eta_i$ before aggregating a norm.

The following cell replaces the error at just the central point of a grid with a spike, leaving uniform background error elsewhere.
Its inputs are normalized errors and are therefore dimensionless.
Compute four norms through `ErrorTolerance` and compare them with values obtained from their definitions.
The chart shows how they change with grid point count, demonstrating dilution of the local spike in RMS while the maximum norm preserves it.

```rust
//| id: concept-norm-selection-spike
//| title: "Comparing reductions of a local error spike on a grid using different norms"
//| run: reactive
//| crates: [scioxide-core]
//| inputs:
//|   spike_magnitude: {"type":"range","label":"Local spike error S [-]","description":"The magnitude of the local error at the central grid point.","min":0.1,"max":10.0,"step":0.1,"value":2.0}
//|   baseline_error: {"type":"range","label":"Background error ε_base [-]","description":"Smooth background error applied uniformly to every grid point.","min":0.001,"max":0.1,"step":0.001,"value":0.01}
//|   grid_size: {"type":"range","label":"Grid point count n [points]","description":"The subdivision count of the one-dimensional grid.","min":10,"max":500,"step":10,"value":100}
use scioxide_core::{ErrorTolerance, NormSelection};

let n = grid_size.round() as usize;
// Compare independently computed values from the definitions with each API result.
let squared = spike_magnitude.powi(2) + (n - 1) as f64 * baseline_error.powi(2);
let norms = [
    (
        "L₁",
        NormSelection::L1,
        spike_magnitude + (n - 1) as f64 * baseline_error,
    ),
    ("L₂", NormSelection::L2, squared.sqrt()),
    (
        "Maximum",
        NormSelection::Infinity,
        spike_magnitude.max(baseline_error),
    ),
    (
        "RMS",
        NormSelection::RootMeanSquare,
        (squared / n as f64).sqrt(),
    ),
];
let mut series = Vec::new();
let mut rows = Vec::new();
for (name, norm, reference) in norms {
    // With absolute tolerance 1 and relative tolerance 0, the input itself is the normalized error.
    let tolerance = ErrorTolerance::scalar(1.0, 0.0, norm).map_err(|e| e.to_string())?;
    let evaluate = |count: usize| -> Result<f64, String> {
        let mut errors = vec![baseline_error; count];
        errors[count / 2] = spike_magnitude;
        tolerance
            .normalized_norm(&errors, &vec![1.0; count])
            .map_err(|e| e.to_string())
    };
    let value = evaluate(n)?;
    rows.push((name, value, reference, (value - reference).abs()));
    let points = (10..=500)
        .step_by(10)
        .map(|k| Ok([k as f64, evaluate(k)?]))
        .collect::<Result<Vec<_>, String>>()?;
    series.push(serde_json::json!({"name":name, "points":points}));
}
// A normalized norm at or below the horizontal line at 1 satisfies the tolerance. The vertical line marks the n compared in the table.
emit_line_chart!(
    &series,
    options = &serde_json::json!({"xLabel": "Grid point count n [points]", "yLabel": "Normalized norm [-]", "yType": "log",
"annotations": [{"kind": "line", "axis": "y", "value": 1.0, "label": "Tolerance boundary"},
{"kind": "line", "axis": "x", "value": n as f64, "label": "Selected n"}]})
);
emit_table_with_columns!(
    serde_json::json!([
    {"key":"0","label":"Norm","type":"string","nullText":"Undefined"},
    {"key":"1","label":"API value","type":"number","format":{"significantDigits":6},"nullText":"Undefined"},
    {"key":"2","label":"Value from definition","type":"number","format":{"significantDigits":6},"nullText":"Undefined"},
    {"key":"3","label":"Absolute difference","type":"number","format":{"significantDigits":6},"nullText":"Undefined"}
    ]),
    rows
);
```

## Designing multiple stopping criteria

Residuals, changes in iterates, changes in the objective, and computation count limits express different reasons for stopping.
The following are example criteria; SciOxide solvers do not all use the same formulas or combinations.

1. **Residual test**: $\|\mathbf{f}(\mathbf{x}_k)\| \le \tau_{\mathrm{abs}} + \tau_{\mathrm{rel}} \|\mathbf{f}(\mathbf{x}_0)\|$ (how closely the equations are satisfied).
2. **Step size test**: $\|\mathbf{x}_{k+1} - \mathbf{x}_k\| \le \tau_{\mathrm{step}} (1 + \|\mathbf{x}_k\|)$ (whether iterates have effectively stopped moving).
3. **Objective change test**: $|f(\mathbf{x}_{k+1}) - f(\mathbf{x}_k)| \le \tau_{\mathrm{obj}}$ (whether improvement in optimization has leveled off).
4. **Limit guard**: Reaching the maximum iteration or function evaluation count (preventing infinite loops).

Even with small changes in iterates, stagnation can stop execution before the equations are satisfied.
Conversely, an ill-conditioned problem may have a large solution error even with a small residual.
Read the termination reason and check which condition was actually satisfied before using the result.

## Summary and further reading

Absolute tolerance supports the small-value range, while relative tolerance adjusts the allowed width according to magnitude.
For errors with multiple components, align their units before aggregating a norm.
The difference between RMS and maximum norms matters when local violations must not be missed.
