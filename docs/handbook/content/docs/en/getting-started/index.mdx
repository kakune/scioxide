Begin by solving a linear system with two unknowns, then substitute the computed values into the original equations to check them.
Through this small example, learn how to call SciOxide and interpret residuals, backward error, and condition numbers.

---

## Matrix notation and the exact solution of a linear system

Consider the following linear system with two unknowns.

$$
\begin{aligned}
3x_1 + x_2 &= 9, \\
x_1 + 2x_2 &= 8.
\end{aligned}
$$

Using the coefficient matrix $\mathbf{A} \in \mathbb{R}^{2 \times 2}$, unknown vector $\mathbf{x} \in \mathbb{R}^2$, and right-hand side vector $\mathbf{b} \in \mathbb{R}^2$ to write $\mathbf{A}\mathbf{x} = \mathbf{b}$, the entries are defined as follows.

$$
\mathbf{A} =
\begin{bmatrix}
3 & 1 \\
1 & 2
\end{bmatrix},
\qquad
\mathbf{x} =
\begin{bmatrix}
x_1 \\ x_2
\end{bmatrix},
\qquad
\mathbf{b} =
\begin{bmatrix}
9 \\ 8
\end{bmatrix}.
$$

Since the determinant is $\det(\mathbf{A}) = 3 \times 2 - 1 \times 1 = 5 \neq 0$, the matrix $\mathbf{A}$ is nonsingular.
The unique exact solution is $\mathbf{x}^* = (2, 3)^\mathsf{T}$.

## Numerical solution and objective checks through residuals and backward error

Let $\hat{\mathbf{x}}$ be the approximate solution obtained on a computer.
Floating-point numerical computations incur rounding error from finite precision, so independently check how closely the computed solution satisfies the equations.
The **residual vector** $\mathbf{r}$ and its Euclidean norm $\|\mathbf{r}\|_2$ provide objective measures.

$$
\mathbf{r} = \mathbf{A}\hat{\mathbf{x}} - \mathbf{b},
\qquad
\|\mathbf{r}\|_2 = \sqrt{\sum_{i=1}^n r_i^2}.
$$

Numerical linear algebra also emphasizes **backward error**, which is independent of the scale of the problem.
According to Wilkinson's backward error analysis, if the solution algorithm is stable, the computed solution $\hat{\mathbf{x}}$ can be regarded as the exact solution of a slightly perturbed coefficient system $(\mathbf{A} + \Delta\mathbf{A})\hat{\mathbf{x}} = \mathbf{b} + \Delta\mathbf{b}$.
The normalized, dimensionless backward error norm $\eta$ is defined as follows.

$$
\eta = \frac{\|\mathbf{A}\hat{\mathbf{x}} - \mathbf{b}\|}{\|\mathbf{A}\|_2 \|\hat{\mathbf{x}}\|_2 + \|\mathbf{b}\|_2}.
$$

If backward error remains at the level of machine precision (a few $u$, where $u \approx 1.11 \times 10^{-16}$ for double-precision `f64`), small input perturbations can explain the computed result.
A single example does not prove backward stability of the algorithm as a whole.

In SciOxide's `scioxide-linalg` crate, construct the LU factors with `LuDecomposition::factor(&a)` and solve for a right-hand side using the factors' `solve(&b)` method.
`factor` returns a `Singular` error upon encountering an exactly zero pivot, and `solve(&b)` returns the solution vector.
For a single right-hand side, `scioxide_linalg::solve(&a, &b)` combines factorization and solution.
Use `solve_with_options(&b, &DirectSolveOptions)` to specify acceptance conditions or diagnostics.
`DirectSolveOptions` specifies the rank determination policy (`RankPolicy`), a condition-number rejection threshold, and whether to request backward error diagnostics.
Even if the policy rejects the result, `solve_with_options` returns `Ok` rather than `Err`, with `solution()` set to `None` and the reason recorded in `report().termination()`.
Backward error diagnostics are not computed by default; they appear in `report().residual()` only when requested through `with_residual(Estimation::Estimate)`.
Their `scaled_norm()` is the infinity-norm backward error $\|\mathbf{b} - \mathbf{A}\hat{\mathbf{x}}\|_\infty / (\|\mathbf{A}\|_\infty\|\hat{\mathbf{x}}\|_\infty + \|\mathbf{b}\|_\infty)$ with respect to the original matrix, using a different norm from the 2-norm quantity $\eta$ above.
The following cell uses `solve_with_options` to read backward error diagnostics.
In addition to this API diagnostic, it independently computes the 2-norm of the residual using the original matrix and the forward error against the analytical exact solution.

```rust
//| id: first-linear-system
//| title: "Solving a two-variable linear system and checking residuals and backward error"
//| run: button
//| crates: [scioxide-linalg]
use scioxide_linalg::{
    DirectSolveOptions, Estimation, LuDecomposition, Matrix, RankPolicy, Vector,
};

// Construct A from a row-major array. The exact solution for the right-hand side b is (2, 3).
let a = Matrix::from_vec(2, 2, vec![3.0_f64, 1.0, 1.0, 2.0]).map_err(|e| e.to_string())?;
let b = Vector::from_vec(vec![9.0_f64, 8.0]);
let factor = LuDecomposition::factor(&a).map_err(|e| e.to_string())?;
// Determine rank exactly (only zero pivots count as rank deficiency) and explicitly request backward error diagnostics.
let solve = DirectSolveOptions::new(RankPolicy::Exact).with_residual(Estimation::Estimate);
let result = factor
    .solve_with_options(&b, &solve)
    .map_err(|e| e.to_string())?;
let x = result
    .solution()
    .ok_or("The specified policy did not accept the solution")?;

// Independently of the API diagnostics, multiply by the original A to compute the residual and forward error.
let ax = a.view().mul_vec(x).map_err(|e| e.to_string())?;
let residual = ax
    .as_slice()
    .iter()
    .zip(b.as_slice())
    .map(|(v, b)| (v - b).powi(2))
    .sum::<f64>()
    .sqrt();
let forward_error = x
    .as_slice()
    .iter()
    .zip([2.0, 3.0])
    .map(|(v, exact)| (v - exact).powi(2))
    .sum::<f64>()
    .sqrt();
let report = result.report().residual().ok_or("Residual diagnostics are absent")?;
emit_table_with_columns!(
    serde_json::json!([
    {"key":"0","label":"x₁","type":"number","format":{"significantDigits":6},"nullText":"Undefined"},
    {"key":"1","label":"x₂","type":"number","format":{"significantDigits":6},"nullText":"Undefined"},
    {"key":"2","label":"Residual 2-norm","type":"number","format":{"significantDigits":6},"nullText":"Undefined"},
    {"key":"3","label":"API backward error (infinity norm)","type":"number","format":{"significantDigits":6},"nullText":"Undefined"},
    {"key":"4","label":"Forward error","type":"number","format":{"significantDigits":6},"nullText":"Undefined"}
    ]),
    vec![(
        x.as_slice()[0],
        x.as_slice()[1],
        residual,
        report.scaled_norm(),
        forward_error
    )]
);
emit_outcome!(
    Outcome::satisfied("The direct solution was accepted")
        .status(format!("{:?}", result.report().termination()))
        .diagnostic("Independently computed residual", residual, None)
);
```

## Computational reasons to avoid forming an inverse

Writing the solution mathematically as $\mathbf{x}=\mathbf{A}^{-1}\mathbf{b}$ does not require forming the inverse on a computer.
Solving directly with factorization factors is often advantageous in operation count, error, and sparsity.

First, the operation counts differ.
Explicitly computing the inverse $\mathbf{A}^{-1}$ of an $n \times n$ matrix and multiplying it by a vector $\mathbf{b}$ requires forming the inverse and a matrix–vector product in addition to LU factorization.
Standard inverse formation using the triangular structure requires approximately $2n^3$ floating-point operations in total, counting only the leading terms.
In contrast, LU factorization with partial pivoting followed directly by forward and backward substitution for one right-hand side vector $\mathbf{b}$ takes approximately $\frac{2}{3}n^3 + 2n^2$ operations, about one third of the computational work of forming the inverse.

Second, accuracy differs in backward error analysis.
As James Wilkinson's analysis shows, computing $\hat{\mathbf{x}} = \mathbf{X}\mathbf{b}$ by multiplying by an explicitly formed approximate inverse $\mathbf{X} \approx \mathbf{A}^{-1}$ is more prone to numerical instability than directly applying LU factorization and triangular substitution, because the vector multiplication further amplifies rounding error in the inverse itself.

Third, the inverse of a sparse matrix is generally not sparse, increasing storage requirements.
For example, even a matrix constructed from local finite differences has an inverse that includes the influence between distant points.
Factorization also creates fill-in, so sparse direct methods require reordering and storage estimates as well.

The `LuDecomposition` in this example performs LU factorization with partial pivoting, $\mathbf{P}\mathbf{A}=\mathbf{L}\mathbf{U}$, using the permutation matrix $\mathbf{P}$ to represent row interchanges.
It then solves triangular equations to obtain the solution vector.
SciOxide also offers other factorizations and iterative methods, selected according to conditions such as symmetry and positive definiteness.

## Condition numbers and residuals diverge: error amplification in ill-conditioned systems

One of the phenomena that demands particular care in numerical analysis is a residual norm $\|\mathbf{r}\|_2$ at the level of machine precision accompanied by a very large error against the true solution (forward error).
A small residual does not immediately guarantee an accurate solution.

To observe this mechanism, consider the following nearly singular system with parameter $\varepsilon > 0$.

$$
\begin{bmatrix}
1 & 1 \\
1 & 1 + \varepsilon
\end{bmatrix}
\begin{bmatrix} x_1 \\ x_2 \end{bmatrix}
=
\begin{bmatrix} 2 \\ 2 + \varepsilon \end{bmatrix}.
$$

The determinant of this system is $\det(\mathbf{A}) = (1+\varepsilon) - 1 = \varepsilon$.
As long as $\varepsilon > 0$, the matrix is nonsingular, and the true solution is $\mathbf{x}^* = (1, 1)^\mathsf{T}$.
Now solve for $\tilde{\mathbf{x}}$ with a right-hand side vector $\tilde{\mathbf{b}} = (2, 2 + \varepsilon + \delta)^\mathsf{T}$ whose second component contains a small observation error or rounding perturbation $\delta$.
Algebra gives the following result.

$$
\tilde{x}_1 = 1 - \frac{\delta}{\varepsilon},
\qquad
\tilde{x}_2 = 1 + \frac{\delta}{\varepsilon}.
$$

The norm of the forward error against the true solution is $\|\tilde{\mathbf{x}} - \mathbf{x}^*\|_2 = \sqrt{2} \frac{|\delta|}{\varepsilon}$.
The input error $\delta$ is amplified by a factor of $1/\varepsilon$.
If $\varepsilon = 10^{-4}$ and $\delta = 10^{-7}$, the forward error reaches the level of $10^{-3}$.
Meanwhile, the residual from substituting the computed solution $\tilde{\mathbf{x}}$ into the measured equation $\mathbf{A}\tilde{\mathbf{x}} - \tilde{\mathbf{b}}$ remains at the double-precision rounding limit.

The physical and mathematical measure governing this amplification is the matrix **condition number** $\kappa(\mathbf{A}) = \|\mathbf{A}\| \|\mathbf{A}^{-1}\|$.
For a symmetric matrix, the 2-norm condition number equals the ratio of the largest to the smallest singular value, $\sigma_{\max} / \sigma_{\min}$; for this system, it approaches $\kappa_2(\mathbf{A}) \approx 4/\varepsilon$ as $\varepsilon \to 0$.
To assess the error against the original solution $x^*$, also compute the residual against the original right-hand side $b$.
The following inequality holds in the corresponding norm.

$$
\frac{\|\tilde{\mathbf{x}} - \mathbf{x}^*\|}{\|\mathbf{x}^*\|}
\le
\kappa(\mathbf{A}) \frac{\|\mathbf{A}\tilde{\mathbf{x}} - \mathbf{b}\|}{\|\mathbf{b}\|}.
$$

In an ill-conditioned system with a very large condition number $\kappa(\mathbf{A})$, even a tiny residual can accompany a severe loss of reliable significant digits in the solution.
A small residual against the measured right-hand side still leaves the discrepancy from the original right-hand side.
The following cell uses `scioxide_linalg::SvdValues` to compute the 2-norm condition number numerically through singular value decomposition and compares it with the theoretical prediction and measured forward error.
The measurements also include errors from converting the matrix and right-hand side to floating-point numbers, so for small $\delta$ they deviate from the theoretical values derived in real arithmetic.
This cell does not read diagnostics, so it obtains the solution through `scioxide_linalg::solve(&a, &b)`, which combines LU factorization and solution.

```rust
//| id: first-conditioned-linear-system
//| title: "Condition numbers and amplified forward error in a nearly singular two-variable system"
//| run: reactive
//| crates: [scioxide-linalg]
//| inputs:
//|   matrix_gap_exponent: {"type":"range","label":"log₁₀ ε (independence of the equations)","description":"As ε decreases, the two lines become nearly parallel and the system becomes ill-conditioned.","min":-8,"max":-1,"step":0.25,"value":-4}
//|   rhs_perturbation_exponent: {"type":"range","label":"log₁₀ δ (measurement error in the right-hand side)","description":"A small observation-error perturbation added to the right-hand side vector.","min":-10,"max":-3,"step":0.25,"value":-7}
use scioxide_linalg::{Matrix, SvdValues, Vector, solve};

// Compute the condition number, forward error, and residual of the measured equation for the same matrix.
fn evaluate(epsilon: f64, delta: f64) -> Result<(f64, f64, f64), String> {
    let a = Matrix::from_vec(2, 2, vec![1.0, 1.0, 1.0, 1.0 + epsilon])
        .map_err(|e| e.to_string())?;
    let b = Vector::from_vec(vec![2.0, 2.0 + epsilon + delta]);
    let svd = SvdValues::compute(&a).map_err(|e| e.to_string())?;
    let values = svd.singular_values();
    let condition = values[0] / values[1];
    // No diagnostics are read, so use solve to combine LU factorization and solution. A zero pivot returns an error.
    let x = solve(&a, &b).map_err(|e| e.to_string())?;
    let ax = a.view().mul_vec(&x).map_err(|e| e.to_string())?;
    let residual = ax
        .as_slice()
        .iter()
        .zip(b.as_slice())
        .map(|(v, b)| (v - b).powi(2))
        .sum::<f64>()
        .sqrt();
    let error = x
        .as_slice()
        .iter()
        .map(|v| (v - 1.0).powi(2))
        .sum::<f64>()
        .sqrt();
    Ok((condition, error, residual))
}
let epsilon = 10.0_f64.powf(matrix_gap_exponent);
let delta = 10.0_f64.powf(rhs_perturbation_exponent);
let (condition, error, residual) = evaluate(epsilon, delta)?;
emit_table_with_columns!(
    serde_json::json!([
    {"key":"0","label":"ε","type":"number","format":{"significantDigits":6},"nullText":"Undefined"},
    {"key":"1","label":"δ","type":"number","format":{"significantDigits":6},"nullText":"Undefined"},
    {"key":"2","label":"Condition number κ₂","type":"number","format":{"significantDigits":6},"nullText":"Undefined"},
    {"key":"3","label":"Measured forward error","type":"number","format":{"significantDigits":6},"nullText":"Undefined"},
    {"key":"4","label":"Theoretical forward error","type":"number","format":{"significantDigits":6},"nullText":"Undefined"},
    {"key":"5","label":"Residual of the measured system","type":"number","format":{"significantDigits":6},"nullText":"Undefined"}
    ]),
    vec![(
        epsilon,
        delta,
        condition,
        error,
        2.0_f64.sqrt() * delta / epsilon,
        residual
    )]
);

let mut measured = Vec::new();
let mut predicted = Vec::new();
let mut conditions = Vec::new();
let mut zeros = 0;
for i in 0..=112 {
    let gap = 10.0_f64.powf(-8.0 + 7.0 * i as f64 / 112.0);
    let (kappa, error, _) = evaluate(gap, delta)?;
    if error > 0.0 {
        measured.push([gap, error]);
    } else {
        zeros += 1;
    }
    predicted.push([gap, 2.0_f64.sqrt() * delta / gap]);
    conditions.push([gap, kappa]);
}
let series = vec![
    serde_json::json!({"name":"Measured forward error", "points":measured}),
    serde_json::json!({"name":"Theoretical value √2 δ/ε", "points":predicted, "style": {"lineType": "dashed"}}),
    serde_json::json!({"name":"Condition number κ₂", "points":conditions}),
];
emit_line_chart!(
    &series,
    options = &serde_json::json!({"xLabel": "Matrix difference ε [-]", "yLabel": "Error and condition number [-]", "xType": "log", "yType": "log",
"annotations": [{"kind": "line", "axis": "x", "value": epsilon, "label": "Selected ε"}]})
);
emit_text!(&format!("Points with zero forward error excluded from the logarithmic chart: {zeros}"));
```

## Interpreting solutions in scientific computing

The lessons from solving a linear system are directly reflected in the design philosophy throughout the SciOxide workspace, including nonlinear root finding, optimization, and differential equations.

1. **Opaque error types and structural categories**: Numerical computations return structured `Result<T, SciOxideError>` values without panicking.
   `SciOxideError` is an opaque struct; identify failure reasons structurally through `e.kind()` (the 20 `SciOxideErrorKind` kinds) or `e.view()` (`SciOxideErrorView`), rather than matching strings.
2. **Separating termination reasons from acceptance**: Stopping a computational loop does not mean that a solution has been accepted within tolerance.
   Identify termination due to a count limit or stagnation, and assess the reliability (`PartialResultTrust`) of the resulting approximate solution.
3. **Separating residuals from forward error**: Rather than relying only on the smallness of an observable residual, assess the condition number $\kappa$ and backward error $\eta$ together to establish grounds for using the result.

Solve a linear system by constructing factorization factors and then solving for the right-hand side.
Check the result against the original matrix, and distinguish residuals from forward error.
