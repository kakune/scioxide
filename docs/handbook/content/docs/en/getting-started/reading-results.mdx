In numerical computing, receiving a value does not mean that the required accuracy has been achieved.
First check for errors; when a result is available, read its termination reason and diagnostics.

Errors, termination reasons, partial results, and work counts convey different information.
Checking them individually lets you decide whether to use the result or change the conditions and recompute it.


---

## The opaque type `SciOxideError` and its 20 structural categories

Fallible numerical APIs in SciOxide mainly return their results through `Result<T, SciOxideError>`.
Because `SciOxideError` is a struct that keeps its internal structure private, inspect its category through `kind()` and its details through `view()`.

The following table lists representative causes.
[Errors and partial results](../../concepts/errors-and-partial-results/) explains the detailed categories and the state after a failure.

| Error kind (`SciOxideErrorKind`) | Main cause and meaning | Typical context |
|---|---|---|
| `InvalidInput` | Structural or logical inconsistency in parameters (such as an interval specified with $a > b$) | `Interval::new` |
| `DimensionMismatch` | Mismatched matrix or vector row counts, column counts, or dimensions | `Matrix`, linear solvers |
| `SizeOverflow` | Exceeding the representable index range or buffer capacity | Integer combinations, factorials |
| `AccountingInvariant` | Breakdown of internal consistency in solve counts (the sum of own/nested counts) | `SolveContext` |
| `ResourceLimit` | Exceeding a memory or search capacity limit configured by the caller | `Capacity` |
| `AllocationFailure` | Failure to allocate a workspace or temporary memory | `try_reserve` |
| `ExecutionFailure` | Startup or scheduling failure in an injected parallel executor | `ExecutionContext` |
| `CapabilityUnavailable` | Unavailable requested hardware capability (such as a particular SIMD instruction) | `ProcessorCapabilities` |
| `CapabilityFailure` | Runtime failure in an injected hardware capability | Kernel execution |
| `ExecutionStopped` | A running computation observes a cancellation request (`CancellationToken`) or a timeout (`Deadline`) | Long-running solves |
| `OutOfBounds` | Access to an index outside the valid range of a collection or array | View operations |
| `DomainError` | Violation of a mathematical domain (such as Cholesky factorization of a matrix that is not positive definite) | Factorizations, elementary functions |
| `NonFinite` | NaN (not a number) or infinity in the input or an intermediate computation | Arithmetic, quadrature |
| `ScalarConversion` | Failure of a safe conversion between scalar types (`try_from`) | Precision conversion |
| `ConvergenceFailure` | Non-convergence or refusal to execute because of a count limit is returned as an error | Boundaries requiring success, `Admission::require` |
| `Singular` | A singular matrix (no inverse mapping exists, for example because of an exactly zero pivot) | LU factorization, triangular solves |
| `NumericalInstability` | Extreme accumulation of floating-point rounding error or algorithmic breakdown | Krylov methods |
| `DifferentiationFailure` | Failure to obtain function values at stencil nodes or select a step size | Numerical differentiation |
| `NotImplemented` | An intentionally unsupported operation for the configuration or type | Backends |
| `External` | A failure reported by a callback, an injected provider, or the consuming application | User callbacks |

The following cell checks the `kind()` and `view()` outputs obtained from three typical failures: invalid interval input, factorization of a singular matrix, and summation of non-finite values.

```rust
//| id: error-classification-showcase
//| title: "Representative error kinds and structural inspection of SciOxideError"
//| run: button
//| crates: [scioxide-core, scioxide-linalg]
use scioxide_core::{Interval, checked_sum};
use scioxide_linalg::{LuDecomposition, Matrix};

let interval_error = Interval::new(5.0_f64, 1.0)
    .err()
    .ok_or("The expected interval error is absent")?;
let a = Matrix::from_vec(2, 2, vec![1.0_f64; 4]).map_err(|e| e.to_string())?;
let lu_error = LuDecomposition::factor(&a)
    .err()
    .ok_or("The expected singular matrix error is absent")?;
let sum_error = checked_sum(&[1.0_f64, f64::NAN])
    .err()
    .ok_or("The expected non-finite value error is absent")?;
let rows: Vec<_> = [
    ("Interval with reversed endpoints", interval_error),
    ("LU factorization of a singular matrix", lu_error),
    ("Sum containing NaN", sum_error),
]
.into_iter()
.map(|(name, e)| (name, format!("{:?}", e.kind()), format!("{:?}", e.view())))
.collect();
emit_table_with_columns!(
    serde_json::json!([
    {"key":"0","label":"Operation","type":"string","nullText":"Undefined"},
    {"key":"1","label":"Category kind()","type":"string","nullText":"Undefined"},
    {"key":"2","label":"Details view()","type":"string","nullText":"Undefined"}
    ]),
    rows
);
```

## Distinguishing termination reasons and domain-specific contracts

Even when `Ok(result)` is returned, check whether the solver converged within tolerance or stopped with a partial result after reaching an iteration or computation count limit.

SciOxide defines **termination enums** suited to each problem domain.
Obtain the termination reason through `.termination()` on the result or its report.

| Field and crate | Termination enum | Representative success states | Representative truncation or non-convergence states |
|---|---|---|---|
| Root finding (`scioxide-rootfind`) | [`RootTermination`](https://docs.rs/scioxide-rootfind/0.1.0/scioxide_rootfind/enum.RootTermination.html) | `ResidualTolerance`, `StepTolerance`, `BracketTolerance` | `IterationLimit`, `WorkLimit(_)`, `Stagnation` |
| Optimization (`scioxide-optimize`) | [`OptimizeTermination`](https://docs.rs/scioxide-optimize/0.1.0/scioxide_optimize/enum.OptimizeTermination.html) | `Converged`, `GradientSmall` | `IterationLimit`, `EvaluationLimit`, `Stagnation` |
| Direct linear methods (`scioxide-linalg`) | [`DirectSolveTermination`](https://docs.rs/scioxide-linalg/0.1.0/scioxide_linalg/enum.DirectSolveTermination.html) | `Accepted` | `RankDeficient`, `IllConditioned` |
| Iterative linear methods (`scioxide-linalg`) | [`LinearSolveTermination`](https://docs.rs/scioxide-linalg/0.1.0/scioxide_linalg/enum.LinearSolveTermination.html) | `Converged` | `IterationLimit`, `Breakdown` |
| Numerical differentiation (`scioxide-differentiate`) | [`DifferentiationTermination`](https://docs.rs/scioxide-differentiate/0.1.0/scioxide_differentiate/enum.DifferentiationTermination.html) | `Completed` (fixed stencil), `Converged` (adaptive extrapolation) | `RoundoffLimit`, `RefinementLimit`, `StepSizeLimit` |
| Ordinary differential equations (`scioxide-ode`) | [`OdeTermination`](https://docs.rs/scioxide-ode/0.1.0/scioxide_ode/enum.OdeTermination.html) | `ReachedEnd`, `TerminalEvent` | `BudgetLimit(BudgetKind::Proposal)`, `StepSizeLimit` |
| Partial differential equations (`scioxide-pde`) | [`PdeTermination`](https://docs.rs/scioxide-pde/0.1.0/scioxide_pde/enum.PdeTermination.html) | `Completed` | `TimeStepLimit`, `LinearIterationLimit`, `LinearBreakdown(_)` |

All the termination enums above provide `termination.is_success()`.
In numerical differentiation, even when execution stops with `RoundoffLimit`, `RefinementLimit`, or `StepSizeLimit`, `report().output_available()` is true and the values and error estimates are exposed if estimates were obtained for every component.
Read these values as partial results, rather than as success.
The direct linear method `solve(&b)` returns only the solution and converts rejection into an error (`Singular` or `NumericalInstability`).
With `solve_with_options(&b, &options)`, check whether `result.report().termination()` is `DirectSolveTermination::Accepted`.
Obtain an accepted solution through `result.solution()`.

## The difference between `Err` and an unsuccessful `Ok`, and partial results

Iterative solvers that return partial results expose the accepted state at the time a limit is reached, together with its residual and termination reason.
This value can serve as the next initial value or help diagnose the computation.

At a boundary that does not return partial results, the same failure to meet the target may become `ConvergenceFailure`.
For example, `Admission::require` converts a refusal to execute because of a count limit into an error.
[Errors and partial results](../../concepts/errors-and-partial-results/) explains these distinctions in detail.

### Reliability categories for partial results (`PartialResultTrust`)

`PartialResultTrust` organizes the mathematical or engineering support for an obtained state into levels.

1. **`DiagnosticOnly`**: A diagnostic state with finite values that makes no claim about feasibility or residuals.
2. **`Admissible`**: An accepted state satisfying constraints such as geometric boundaries of the search space or physical nonnegativity.
3. **`ResidualChecked`**: A state that passes an independent residual verification routine, with a residual satisfying the configured threshold.
4. **`CertificateVerified`**: A state whose API-defined certificate has been independently verified.
   In nonconvex optimization, KKT conditions alone do not guarantee global optimality, so also check what the certificate proves.

### Understanding work counts accurately (`SolveCounts` and `EvaluationCounts`)

Assessing computational performance requires detailed evaluation counts in addition to iteration counts.
Through `SolveCounts`, SciOxide separately records the counts consumed by the solver's own layer (`own()`) and by nested subsidiary solvers called internally (`nested()`); `total()` gives the total.
`EvaluationCounts` represents iterations, proposals, acceptances, rejections, and various provider calls, among other operations.

## Interactive demonstration: fixed-point iteration for the Dottie number and truncation by a count limit

The following interactive cell computes the **Dottie number** ($d \approx 0.7390851332151607$), the unique real fixed point of $x = \cos x$, using `scioxide_rootfind::FixedPointSolver` (Picard iteration).

Adjust the iteration limit with the slider to observe the transition from an unsuccessful `Ok` (`RootTermination::IterationLimit`) at a small limit to a successful `Ok` (`RootTermination::ResidualTolerance`) at a sufficiently large limit, together with changes in `is_success()`, the residual, and the iteration count.

```rust
//| id: fixed-point-budget-termination
//| title: "Termination reasons and partial results as the iteration limit changes"
//| run: reactive
//| crates: [scioxide-rootfind, scioxide-core]
//| inputs:
//|   iteration_budget: {"type":"range","label":"Iteration limit (iterations)","description":"The maximum number of permitted iterations. Small values stop execution when the count limit is reached.","min":2,"max":60,"step":2,"value":10}
use scioxide_core::{Budget, RealScalar};
use scioxide_rootfind::{FixedPointMethod, FixedPointOptions, FixedPointSolver, ResidualFn};

let budget = Budget::try_from(iteration_budget as usize).map_err(|e| e.to_string())?;
let options = FixedPointOptions::default().with_max_iterations(budget);
let result = FixedPointSolver::new(
    FixedPointMethod::Picard,
    scioxide_rootfind::FixedPointInput::Map,
    options,
)
.map_err(|e| e.to_string())?
.solve(
    &ResidualFn::new(1, |x: &[f64], out: &mut [f64]| {
        out[0] = RealScalar::cos(x[0]);
        Ok(())
    }),
    &[0.5_f64],
)
.map_err(|e| e.to_string())?;
let x = result.point()[0];
// Reevaluate the residual at the returned point and compare the error against the known fixed point.
let residual = (RealScalar::cos(x) - x).abs();
let error = (x - 0.7390851332151607_f64).abs();
emit_table_with_columns!(
    serde_json::json!([
    {"key":"0","label":"Iteration limit","type":"number","format":{"significantDigits":6},"nullText":"Undefined"},
    {"key":"1","label":"Termination reason","type":"string","nullText":"Undefined"},
    {"key":"2","label":"Success","type":"boolean","nullText":"Undefined"},
    {"key":"3","label":"Approximate solution","type":"number","format":{"significantDigits":6},"nullText":"Undefined"},
    {"key":"4","label":"Forward error","type":"number","format":{"significantDigits":6},"nullText":"Undefined"},
    {"key":"5","label":"Independent residual","type":"number","format":{"significantDigits":6},"nullText":"Undefined"},
    {"key":"6","label":"Iterations","type":"number","format":{"significantDigits":6},"nullText":"Undefined"}
    ]),
    vec![(
        iteration_budget,
        format!("{:?}", result.termination()),
        result.is_success(),
        x,
        error,
        residual,
        result.counts().iterations()
    )]
);
let outcome = if result.is_success() {
    Outcome::satisfied("The fixed-point iteration convergence condition was satisfied")
} else {
    Outcome::partial("The convergence condition was not satisfied within the limit")
};
emit_outcome!(
    outcome
        .status(result.termination().to_string())
        .diagnostic("Independently evaluated residual", residual, None)
        .diagnostic("Iteration count", result.counts().iterations() as f64, None)
);
```

## Separating forward error and residuals: interpretation through the condition number $\kappa$

Forward error and the residual are different quantities.
For example, for a nonsingular linear equation $Ax^*=b$, $b\ne0$, the condition number $\kappa(A)$ and the residual $r=A\hat{x}-b$, defined using the same norm, satisfy the following relation.

$$
\frac{\|\hat{\mathbf{x}} - \mathbf{x}^*\|}{\|\mathbf{x}^*\|} \le \kappa \frac{\|\mathbf{r}\|}{\|\mathbf{b}\|}.
$$

If the right-hand side has observation error, assess that separately as well.
Accurately solving the measured equation does not necessarily produce a result close to the true solution before observation.
Do not judge a result by a small residual alone; combine comparison with a known solution, condition numbers, backward error, and checks using independent methods.

## Summary and next steps

Before using a result, check for errors, then its termination reason, and then its residual.
For partial results, read the reliability category to determine which checks the state has passed.
Work counts also help you decide whether to increase a limit or change the method on a retry.

- `SciOxideError` is an opaque type; classify errors through `kind()` (20 kinds) and `view()`.
- Check solver termination through `is_success()` and the termination enum, and treat a nonconverged `Ok` as a partial result.
- Distinguish residuals from forward error, and assess solution accuracy using condition numbers and independent checks.
