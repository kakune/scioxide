Automatic differentiation decomposes a function into elementary operations and connects their local derivatives (partial derivatives) with the chain rule.
Derivative accuracy and robustness therefore depend on the formulas used for each operation's partial derivatives.
This page explains partial-derivative formulas for `Real` elementary functions, functions switching formulas by argument range, first and second derivatives of stable transforms, and derivative accuracy guarantees.
[Forward mode and dual numbers](../forward-mode/) and [Reverse mode and tapes](../reverse-mode-and-replay/) cover the modes' mechanisms.
[Differentiating normalization and matrix products](../normalization-and-matrix-products/) covers array-taking `logsumexp` and `softmax_into`, dot products and matrix products.

## Local rules for elementary functions

Let $y = f(x)$ be one elementary function.
For wrapper types (`Dual`, `MultiDual`, `Var`), `f` computes value $y$ using the next inner type `Primal` and evaluates partial derivative $f'(x)$ with `Primal` operations as well.
`Primal` is the wrapper's value-component type: `f64` for `Dual<f64>`, and `Dual<f64>` for `Dual<Dual<f64>>`.
`Dual` retains the tangent as $\dot y = f'(x)\,\dot x$.
`Var` stores $f'(x)$ as a statement's partial derivative (one tape record); the reverse sweep, traversing the recording from end to beginning, adds $f'(x)\,\bar y$ to $\bar x$.
$\bar x$ and $\bar y$ are adjoints, partial derivatives of the final output with respect to $x$ and $y$.
Values are exactly the result of `Primal` operations, so they agree bit for bit with evaluating the same function using the unwrapped type, independently of differentiation method.

Because partial derivatives use `Primal` operations, nesting types makes the outer type differentiate the partial-derivative expression itself.
For example, the second derivative with `Dual<Dual<f64>>` differentiates the $f'$ expression written by the inner rule (in its evaluated form) with the outer dual number.
Even for mathematically identical $f'$, expression form determines second-derivative rounding and domain.

`Real` provides the following elementary functions.
For binary functions, the method receiver is the first argument: `y.atan2(x)` returns the argument $\operatorname{atan2}(y, x) \in [-\pi, \pi]$ of point $(x, y)$, `x.log(b)` returns $\log_b x$, and `a.powf(b)` returns $a^b$.

| Category | Unary functions | Binary and other functions |
|---|---|---|
| Powers and roots | `recip`, `sqrt`, `cbrt` | `powf`, `powm1`, `powi(n)` |
| Exponentials and logarithms | `exp`, `exp2`, `exp_m1`, `ln`, `ln_1p`, `log2`, `log10` | `log`, `logaddexp`, `xlogy`, `xlog1py` |
| Trigonometric functions and inverses | `sin`, `cos`, `tan`, `asin`, `acos`, `atan` | `atan2`, `hypot`, `sin_cos` |
| Hyperbolic functions and inverses | `sinh`, `cosh`, `tanh`, `asinh`, `acosh`, `atanh` | |
| Angle conversion | `to_degrees`, `to_radians` | |
| Stable transforms | `softplus`, `sigmoid`, `log_sigmoid`, `logit`, `exprel`, `cosm1`, `sinc`, `sincpi`, `sin_pi`, `cos_pi`, `tan_pi`, `sin_degrees`, `cos_degrees`, `tan_degrees` | |
| Functions with kinks | `abs`, `signum`, `floor`, `ceil`, `round`, `trunc`, `fract` | `min`, `max`, `clamp`, `%` |

`sin_cos` agrees bit for bit with separate calls to `sin` and `cos`.
[Handling kinks and nonfinite values](../nonsmooth-and-nonfinite-policies/) covers derivatives of the last row's functions.

Partial-derivative expressions reuse the already computed value $y$ and avoid subtractive cancellation.
The main examples follow.

| Function | Partial-derivative formula | Reason for the formula |
|---|---|---|
| `recip`, `sqrt`, `cbrt` | $-y^2$, $0.5/y$, $(1/y)/(3y)$ | Reuses value $y$ |
| `exp_m1` | $e^x$ | $y + 1$ suffers cancellation at $x \ll 0$, while $e^x$ retains relative accuracy |
| `tan` | $1 + y^2$ | Reuses value $y$ |
| `asin`, `atanh` | $1/\sqrt{(1 - x)(1 + x)}$, $1/((1 - x)(1 + x))$ | $1 - x$ is exact when $x$ is close to 1, avoiding cancellation in $1 - x^2$ |
| $a / b$ | $(1/b,\ -q/b)$, $q = a/b$ | Reuses quotient $q$ |
| `powf` | $(\operatorname{azmul}(b, a^{b-1}),\ \operatorname{azmul}(a^b, \ln a))$ | Avoids making $0 \cdot (-\infty)$ NaN at $a = 0$ |
| `logaddexp` | $(\sigma(a - b),\ \sigma(b - a))$ | If $a - b$ is nonfinite, assigns 1 to the larger side and 0 to the other |

$\sigma(t) = 1/(1 + e^{-t})$ is the logistic function.
`azmul` is an absolute-zero product: if either factor is exactly 0, it returns $+0$ even if the other is infinity or NaN.
Under ordinary IEEE 754 multiplication (IEEE products below), $0 \cdot \infty$ is NaN.
The exponent partial derivative $a^b \ln a$ of `powf` becomes a product of value $a^b = 0$ and $\ln a = -\infty$ at $a = 0$ and $b > 0$; the IEEE product is NaN, but `azmul` gives the limiting value 0.
On tapes, this partial derivative is not computed when the exponent is passive (an input-independent constant).

`Dual` and `MultiDual` multiply tangents by partial derivatives of `×`, scalar multiplication, `to_degrees`, `to_radians`, `fract`, `exp`, `exp2`, `exp_m1`, `sin`, `cos`, `sinh`, `cosh`, `tanh`, `atan` and `asinh` using IEEE products; all other partial derivatives use `azmul`.
Tape sweeps use `azmul` for every update.
Chain-rule products use separate multiplication and addition (without `mul_add`), and results do not depend on FMA availability.
[Handling kinks and nonfinite values](../nonsmooth-and-nonfinite-policies/) examines examples where `azmul` changes derivatives and differs from IEEE products.

## Range-based formula switching

Some functions cannot retain accuracy across their full argument range with one expression.
For $\tanh' x = 1 - \tanh^2 x$, large $|x|$ makes $\tanh^2 x$ approach 1, causing cancellation.
Once $|x|$ exceeds about 19.06, $\tanh x$ rounds to 1 and this expression returns 0.
The true value $\operatorname{sech}^2 x \approx 4e^{-2|x|}$ remains representable as a normal number until around $|x| = 354$.
For $\operatorname{arsinh}' x = 1/\sqrt{x^2 + 1}$, $x^2$ overflows to infinity at $|x| > 2^{512} \approx 1.34 \times 10^{154}$, giving 0.

`scioxide-ad` uses different expressions by range for the following six functions.

| Function | Default formula | Switching condition and formula |
|---|---|---|
| `atan` | $1/(1 + x^2)$ | For $\lvert x\rvert > 1$: $r^2/(1 + r^2)$, $r = 1/x$ |
| `tanh` | $1 - y^2$ | For $\lvert x\rvert > 1$: $s^2$, $s = 2e/(1 + e^2)$, $e = e^{-\lvert x\rvert}$ |
| `asinh` | $1/\sqrt{x^2 + 1}$ | For $\lvert x\rvert > 1$: $1/\operatorname{hypot}(x, 1)$ |
| `acosh` | $1/\sqrt{(x - 1)(x + 1)}$ | For $x > 2$: $1/(\sqrt{x - 1}\,\sqrt{x + 1})$ |
| `hypot(a, b)` | $(u/n,\ v/n)$, $u = a/m$, $v = b/m$, $n = \operatorname{hypot}(u, v)$ | If $m$ is 0 or infinity: $(a/h,\ b/h)$, $h = \operatorname{hypot}(a, b)$. At the origin: $(0, 0)$ |
| `atan2(a, b)` | $(v,\ -u)/((u^2 + v^2)\,m)$, $u = a/m$, $v = b/m$ | At the origin or points with only one infinite argument: $(0, 0)$ |

Here $m = \max(|a|, |b|)$.
$s = 2e/(1 + e^2)$ for `tanh` equals $\operatorname{sech}|x|$; since $e = e^{-|x|} \le 1$, it avoids both cancellation and overflow.
`hypot` and `atan2` divide arguments by their maximum magnitude $m$ before forming partial derivatives, giving finite values even where $a^2 + b^2$ overflows.

Switching evaluates both expressions and selects with `select` using a mask from comparisons of base values (innermost values such as `f64`), rather than branching.
Even if the unselected expression becomes infinity or NaN, it does not enter the result because `select` only selects components without multiplication.
With `Lanes`, selection is per lane (one SIMD element), allowing different expressions in different lanes of the same operation.
Comparisons use base values, so outer derivatives in nested types differentiate only the selected expression, without differentiating the switching condition.
`select` and comparisons are not treated as kinks, so the tape does not count switches.
Computational cost is the sum of evaluating both expressions.

The next cell computes derivatives of `tanh`, `asinh` and `acosh` with `Dual::variable(x)` and compares single expressions ($1 - \tanh^2 x$, $1/\sqrt{x^2 + 1}$, $1/\sqrt{(x - 1)(x + 1)}$).
Inputs are the dimensionless `tanh` evaluation point $x$ and exponent $p$ of evaluation point $x = 10^p$ for `asinh` and `acosh`.
References evaluate alternative closed forms $\operatorname{sech}^2 x = 4e^{-2|x|}/(1 + e^{-2|x|})^2$, $r/\sqrt{1 + r^2}$ and $r/\sqrt{1 - r^2}$ ($r = 1/x$), free from cancellation and overflow, with f64's inherent methods.
The table measures SciOxide derivative error in ulp at the reference (the spacing between adjacent floating-point numbers), and single-expression error as relative error.
The chart plots relative error of $\tanh'$ over $x = 0.5, 1, \ldots, 40$ on a logarithmic axis; exactly zero-error points are excluded and counted in the second table.

use scioxide_core::RealScalar;

// SciOxide derivative: pass a dual number with tangent 1.

// Reference (f64's inherent methods): sech²x = 4e^{−2|x|}/(1 + e^{−2|x|})².

With the default $x = 20$, $\tanh x$ rounds to 1, so single expression $1 - \tanh^2 x$ returns 0 with relative error 1.
SciOxide computes the derivative with switched formula $s^2$, agreeing with reference $1.6993417021166355 \times 10^{-17}$ (0 ulp).
For `asinh` and `acosh` at $p = 200$, the single expression returns 0 because $x^2$ overflows to infinity, while SciOxide returns $10^{-200}$ as in the reference.

In the chart, single-expression relative error rises from $3.0 \times 10^{-13}$ at $x = 5$ to $1.1 \times 10^{-8}$ at $x = 10$ and $1.7 \times 10^{-4}$ at $x = 15$, reaching 1 at $x \ge 19.5$.
Absolute error in $1 - \tanh^2 x$ remains about $\varepsilon$ while the true value $\approx 4e^{-2x}$ shrinks, so relative error grows like $\varepsilon e^{2x}/4$.
SciOxide relative error stays below $5 \times 10^{-16}$ throughout, and is exactly 0 at 37 of 80 points.
Error does not increase across the $x = 1$ switch.

At $x = 2$ and $p = 10$, both expressions are correct: SciOxide's `tanh` error is 2 ulp and single-expression relative error is $3.9 \times 10^{-16}$.
At $x = 10$ and $p = 150$, single-expression $\tanh'$ relative error grows to $1.1 \times 10^{-8}$, but $x^2 = 10^{300}$ remains finite, so the single expressions for `asinh` and `acosh` return correct values.

## Stable-transform derivatives

The 14 stable transforms from `softplus` through `tan_degrees` (defined in [Elementary functions and stable transforms](../../../scioxide-core/algorithms/stable-transforms/)) use rules providing a tuple $[f(x), f'(x), f''(x)]$ of value and derivatives through order two.
Values come from `scioxide_core` stable-transform kernels and become NaN where the kernel returns an error (nonfinite or out-of-domain arguments).
Number-type operations return no errors, so they represent failures returned by `scioxide_core` functions through `Result` as NaN.
First and second derivatives evaluate transform-specific formulas in `f64` and round once to the output type.

Derivative expressions are also selected to avoid cancellation and overflow.
$\sigma'(x) = e^{-|x|}/(1 + e^{-|x|})^2$ avoids overflow regardless of the sign of $x$.
In $\sigma''(x) = \sigma'(x)(1 - 2\sigma(x))$, the second factor is rewritten using $1 - 2\sigma(x) = -\tanh(x/2)$ to avoid cancellation near 0.
The derivatives of `exprel` sum series $\sum_k x^k/(k!\,(k + 2))$ and $\sum_k x^k/(k!\,(k + 3))$ through $k = 24$ for $|x| < 2$; derivatives of `sinc` and `sincpi` use compensated double-length arithmetic for $|x| \ge 1$ (`sincpi` is $|\pi x| \ge 1$), obtaining product rounding residuals with explicit fused multiply-add.
Fused multiply-add returns identical values with or without hardware FMA, so these derivatives also do not depend on FMA availability.

The rule receiving tuple $[f, f', f'']$ uses the same mechanism as `map_scalar` in [Scalar-function derivative rules](../custom-primitives/), so it is exact through total order 2 (the sum of derivative orders at each nesting level) for `Dual`, `MultiDual`, `Var`, `Var<Dual>`, `Dual<Var>` and `Dual<Dual>`.
`Jet` computes the other 11 transforms with Taylor-coefficient recurrences; only `exprel`, `sinc` and `sincpi` have NaN coefficients above $c_2$ ([Taylor jets and higher-order coefficients](../taylor-jets/)).

Binary stable transforms `logaddexp`, `xlogy`, `xlog1py` and `powm1` also obtain values from `scioxide_core` kernels and give NaN at error points.
They therefore yield NaN even where IEEE operations would return a limit (`powm1(0, y < 0)`, `powm1(∞, 0)`, `logaddexp(∞, ∞)`).
Partial derivatives evaluate the local rules in the table above using `Primal` operations.
Since `xlogy` and `xlog1py` are 0 along $x = 0$, the partial derivative with respect to $y$ at $x = 0$ and $y = 0$ ($y = -1$ for `xlog1py`) is set to 0 instead of $0/0$.
The base partial derivative of `powf` computes $y\,x^{y-1}$ as $y\,(x^y/x)$, avoiding amplification of rounding in $y - 1$ by a factor $\lvert\ln x\rvert$.
The partial derivative of `logaddexp` corrects the rounding error in $x - y$ obtained with TwoSum.

## Derivative accuracy

`scioxide-ad` has the following accuracy guarantees.
“Within $N$ ulp” means tests verify a difference of at most $N$ ulp from a high-precision reference; it is not a proof of error for each individual computation.

| Target | Contract |
|---|---|
| Values | Preserve `scioxide_core` elementary-function accuracy. The eight lane kernels (`exp`, `exp_m1`, `ln`, `ln_1p`, `sin`, `cos`, `tanh`, `powf`) are within 4 ulp and may differ from scalar functions in the last digits |
| Unary first partial derivatives | Within 64 ulp. `log10` and `tanh` near boundaries: 6 ulp; constant multiples `log2`, `log10`, `exp2`: 2 ulp |
| Stable-transform first and second derivatives | Within 64 ulp |
| Binary first partial derivatives | Within 64 ulp |
| Binary second partial derivatives (through nesting) | Within 256 ulp |

Binary-function contracts apply only where arguments, values and partial derivatives are all either 0 or have magnitudes in $[\sqrt{\text{MIN\_POSITIVE}}, \sqrt{\text{MAX}}]$ (about $[1.5 \times 10^{-154}, 1.3 \times 10^{154}]$ for `f64`).
Outside this range, evaluating partial-derivative expressions directly with IEEE operations may overflow or underflow intermediate values.
Except for specific formulas such as the partial derivatives of `hypot` and `atan2`, number types evaluate without range adjustment (scaling).
[Elementary functions and stable transforms](../../../scioxide-core/algorithms/stable-transforms/) covers general value accuracy guarantees; [Number types, lanes and generic code](../number-types-and-lanes/) covers lane kernels.

## Summary

Elementary-function partial derivatives reuse values $y$ and quotients $q$ with formulas avoiding cancellation and overflow; wrapper values agree bit for bit with evaluating the same function using the unwrapped type.
`atan`, `tanh`, `asinh`, `acosh`, `hypot` and `atan2` evaluate two expressions and select with `select`, preserving relative accuracy where a single expression returns 0 from cancellation or overflow; cost is the sum of both evaluations.
The 14 stable transforms use rules providing values and derivatives through order two, exact through total order 2 for `Dual`, `MultiDual`, `Var`, `Var<Dual>`, `Dual<Var>` and `Dual<Dual>`.
First partial derivatives have a 64 ulp contract and nested binary second partial derivatives a 256 ulp contract; because binary contracts apply only when arguments, values and partials fit $[\sqrt{\text{MIN\_POSITIVE}}, \sqrt{\text{MAX}}]$, nondimensionalize inputs with extreme scales beforehand.
