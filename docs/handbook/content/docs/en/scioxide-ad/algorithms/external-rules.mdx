Automatic differentiation assumes that a function can be written using `Real` operations.
Computations such as eigensolvers that accept only matrices with floating-point components such as `f64` cannot accept `Dual` or `Var` and cannot be differentiated directly.
For iterative solution computations, derivatives derived from the conditions the solution satisfies can be preferable to recording and differentiating the iteration process.
`ExternalRule` is a rule through which callers supply such vector-function values and Jacobian–vector products; `Var::external` records it as one tape statement (one tape record).
This statement is called a call statement.
This page explains rule-method contracts, recording call statements and allocating workspace, and which methods each transformation uses, illustrated by the smallest eigenvalue of a symmetric matrix.
[Differentiation rules for scalar functions](../custom-primitives/) covers scalar-function rules `map_scalar` and `combine` that support all numeric types and how to choose a method; [Reverse mode and tapes](../reverse-mode-and-replay/) covers tape recording and sweeps.

## The three ExternalRule methods

`ExternalRule<V>` is a rule for treating a vector function $y = f(x)$ ($x \in \mathbb{R}^n$, $y \in \mathbb{R}^m$) as one tape call statement.
Writing the Jacobian as $J = \partial f/\partial x \in \mathbb{R}^{m \times n}$, the rule has three methods.

| Method | Computation | Writing behavior |
|---|---|---|
| `evaluate(inputs, outputs)` | $y = f(x)$ | Write to `outputs` |
| `pullback(inputs, outputs, output_adjoints, input_adjoints)` | $\bar x \mathrel{+}= J^{\mathsf T} \bar y$ | Add to `input_adjoints` |
| `pushforward(inputs, outputs, input_tangents, output_tangents)` | $\dot y = J \dot x$ | Write to `output_tangents`; the default returns `CapabilityUnavailable` |

$J^{\mathsf T} \bar y$ computed by `pullback` is called the pullback, and $J \dot x$ computed by `pushforward` the pushforward.
$\bar y$ is the output adjoint (the final output's partial derivative with respect to $y$), $\bar x$ the input adjoint, $\dot x$ the input tangent (direction of input motion), and $\dot y$ the output tangent.

The rule must be a pure function of its inputs.
The tape saves the rule's `Arc` and the call's input and output values, passing them to the rule on every product computation.
Rules have no per-call state, so intermediate quantities needed by a pullback must be recomputed from the supplied inputs and outputs or included in the outputs.
A rule generic over `V` (`impl<V: TapeValue> ExternalRule<V> for …`) also works on `Tape<Dual<S>>`, evaluating the pullback with dual numbers to give Hessian–vector products.
A rule able to call only `f64` functions implements only `ExternalRule<f64>` and is used with `Tape<f64>`.

## Recording with Var::external

`Var::external(&rule, inputs, outputs)` applies `rule: &Arc<dyn ExternalRule<V>>` to the inputs and writes results to `outputs`.
If all inputs are passive (constants not recorded on the tape), it only evaluates (allocating evaluation workspace on each call), and outputs are passive.
Otherwise, it records one call statement and saves input and output values.
A tape represents statements as a sequence of 64-bit statement words; a call statement consists of a header word, a word per input, a copy of the header, and a word per output.
A tape that has recorded the same function before allocates no storage during recording.
Errors from `evaluate` are returned unchanged; failure to allocate evaluation workspace on the first recording returns `AllocationFailure`.
Mixing values from two recordings makes outputs NaN and fails the transformation with `InvalidInput` (`Inconsistent`).
Computations inside the rule are not recorded, so kinks encountered there are not counted.

## Products using pullbacks and pushforwards

A reverse sweep (traversing the recording from end to start and adding adjoints) calls `pullback` at a call statement, so `gradient_into`, `vjp_into`, reverse-sweep `jacobian_into`, and `apply_adjoint_into` on `JacobianOperator` work with only a pullback.
A tangent sweep (traversing the recording from start to end and propagating tangents) calls `pushforward`, so a pushforward is required for `jvp_into`, `jacobian_into` using tangent sweeps (`JacobianMode::Forward`, or `Auto` when outputs are at least as numerous as inputs), `sparse_jacobian_into`, and `apply_into` on `JacobianOperator`.
Calling these with a rule without a pushforward returns `CapabilityUnavailable`.

## Smallest eigenvalue of a symmetric matrix

Compute the smallest eigenvalue of the $2 \times 2$ real symmetric matrix

$$
S = \begin{pmatrix} a & b \\ b & c \end{pmatrix}, \qquad
\lambda(a, b, c) = \frac{a + c}{2} - \sqrt{\Bigl(\frac{a - c}{2}\Bigr)^2 + b^2}
$$

using scioxide-linalg's `HermitianEigenDecomposition` ([Eigenproblems and Schur decomposition](../../../scioxide-linalg/algorithms/eigenproblems/)), and wrap this eigenvalue $\lambda$ in `ExternalRule`.
This solver accepts only matrices with `NumericScalar` components such as `f64` and cannot accept `Dual` or `Var`, so it cannot be written as a generic function.
Since scioxide-linalg types are used directly, also add scioxide-linalg to `Cargo.toml` in your own code.
If the smallest eigenvalue is simple (not repeated), let $v$ be its unit eigenvector; the Hellmann–Feynman theorem gives

$$
\mathrm{d}\lambda = v^{\mathsf T}\,\mathrm{d}S\,v, \qquad
\Bigl(\frac{\partial\lambda}{\partial a}, \frac{\partial\lambda}{\partial b}, \frac{\partial\lambda}{\partial c}\Bigr) = (v_0^2,\ 2 v_0 v_1,\ v_1^2)
$$


$b$ appears in two off-diagonal entries of $S$, giving a factor of 2 in its partial derivative.
The pullback is $\bar x \mathrel{+}= \bar y\,(v_0^2, 2v_0v_1, v_1^2)$ and the pushforward is $\dot y = v_0^2 \dot a + 2v_0v_1 \dot b + v_1^2 \dot c$.
Since rules have no per-call state, both recompute the eigenvector from the inputs.
Since $v_0^2 + v_1^2 = 1$, the identity $\partial\lambda/\partial a + \partial\lambda/\partial c = 1$ holds at every point ($\lambda(S + tI) = \lambda(S) + t$).

The following block contains definitions used by the next two cells.
`lowest` obtains eigenvalues and eigenvectors of $S$ with scioxide-linalg and returns $\lambda$ and partial derivatives $(v_0^2, 2v_0v_1, v_1^2)$.
`Lowest` is a pullback-only rule, and `LowestWithTangent` also has a pushforward.
`closed_form` expresses the closed form above using operations of numeric type `R` for checking.

```rust
//| id: ad-eigenvalue-rules
//| kind: definitions
//| title: "External rules and closed form for the smallest eigenvalue"
//| crates: [scioxide-ad, scioxide-core, scioxide-linalg]
use scioxide_ad::{ExternalRule, Real};
use scioxide_core::SciOxideError;
use scioxide_linalg::{HermitianEigenDecomposition, HermitianInput, Matrix};

/// Smallest eigenvalue λ of S = [[a, b], [b, c]], with derivatives from its unit eigenvector v:
/// ∂λ/∂(a, b, c) = (v₀², 2v₀v₁, v₁²) (Hellmann–Feynman theorem). Eigenvalues use scioxide-linalg.
pub(crate) fn lowest(s: &[f64]) -> Result<(f64, [f64; 3]), SciOxideError> {
    let matrix = Matrix::from_vec(2, 2, vec![s[0], s[1], s[1], s[2]])?;
    let eigen = HermitianEigenDecomposition::decompose(&matrix, HermitianInput::Exact)?;
    let vectors = eigen.eigenvectors().view();
    let v = [vectors.get(0, 0)?, vectors.get(1, 0)?];
    Ok((
        eigen.eigenvalues()[0],
        [v[0] * v[0], 2.0 * v[0] * v[1], v[1] * v[1]],
    ))
}

/// y = λ(S). Rule with only a pullback.
pub(crate) struct Lowest;

impl ExternalRule<f64> for Lowest {
    fn evaluate(&self, s: &[f64], y: &mut [f64]) -> Result<(), SciOxideError> {
        y[0] = lowest(s)?.0;
        Ok(())
    }
    fn pullback(&self, s: &[f64], _: &[f64], w: &[f64], g: &mut [f64]) -> Result<(), SciOxideError> {
        // Add to adjoints: x̄ += Jᵀ ȳ.
        for (target, d) in g.iter_mut().zip(lowest(s)?.1) {
            *target += w[0] * d;
        }
        Ok(())
    }
}

/// The same rule with the pushforward ẏ = J ẋ = vᵀ Ṡ v added.
pub(crate) struct LowestWithTangent;

impl ExternalRule<f64> for LowestWithTangent {
    fn evaluate(&self, s: &[f64], y: &mut [f64]) -> Result<(), SciOxideError> {
        Lowest.evaluate(s, y)
    }
    fn pullback(&self, s: &[f64], y: &[f64], w: &[f64], g: &mut [f64]) -> Result<(), SciOxideError> {
        Lowest.pullback(s, y, w, g)
    }
    fn pushforward(
        &self,
        s: &[f64],
        _: &[f64],
        t: &[f64],
        out: &mut [f64],
    ) -> Result<(), SciOxideError> {
        // Overwrite the output tangent.
        out[0] = lowest(s)?.1.iter().zip(t).map(|(d, t)| d * t).sum();
        Ok(())
    }
}

/// Closed form λ = (a + c)/2 − hypot((a − c)/2, b), written for numeric type R.
pub(crate) fn closed_form<R: Real>(s: &[R]) -> R {
    (s[0] + s[2]) * 0.5 - ((s[0] - s[2]) * 0.5).hypot(s[1])
}
```

The next cell compares the value and gradient of $\lambda$ wrapped in the pullback-only rule `Lowest` with those obtained by differentiating the closed form on a tape.
Inputs are $a$, $b$, and $c$ (dimensionless).
Both gradients are obtained with `Tape::gradient_into`.
The first table shows $\lambda$, the three gradient components, and $\partial\lambda/\partial a + \partial\lambda/\partial c$; the second shows the kink count of each recording with `TapeReport::kinks()`.

```rust
//| id: ad-external-eigenvalue
//| ref: ad-external-eigenvalue
//| title: "Gradient of a symmetric matrix's smallest eigenvalue wrapped in ExternalRule"
//| run: reactive
//| crates: [scioxide-ad, scioxide-core]
//| uses: [ad-eigenvalue-rules]
//| inputs:
//|   a: {"type":"range","label":"Diagonal entry a","min":-2,"max":2,"step":0.25,"value":1}
//|   b: {"type":"range","label":"Off-diagonal entry b","min":-1,"max":1,"step":0.25,"value":0.5}
//|   c: {"type":"range","label":"Diagonal entry c","min":-2,"max":2,"step":0.25,"value":-0.5}
//| cases:
//|   - {"id":"degenerate","label":"a = c = 0.5, b = 0","description":"The smallest eigenvalue is repeated and λ is not differentiable.","inputs":{"a":0.5,"b":0,"c":0.5}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"gradients","path":"/rows/0/1","approx":{"value":-0.6513878188659973,"rtol":1e-14}}
//|       - {"artifact":"gradients","path":"/rows/1/3","range":{"max":1e-14}}
//|       - {"artifact":"gradients","path":"/rows/2/3","range":{"max":1e-14}}
//|       - {"artifact":"gradients","path":"/rows/3/3","range":{"max":1e-14}}
//|       - {"artifact":"kinks","path":"/rows/0/1","equals":0}
//|       - {"artifact":"kinks","path":"/rows/1/1","equals":0}
//|   - case: degenerate
//|     expect:
//|       - {"artifact":"gradients","path":"/rows/1/1","approx":{"value":1,"atol":1e-15}}
//|       - {"artifact":"gradients","path":"/rows/1/2","approx":{"value":0.5,"atol":1e-15}}
//|       - {"artifact":"gradients","path":"/rows/3/2","approx":{"value":0.5,"atol":1e-15}}
//|       - {"artifact":"gradients","path":"/rows/4/1","approx":{"value":1,"atol":1e-14}}
//|       - {"artifact":"gradients","path":"/rows/4/2","approx":{"value":1,"atol":1e-14}}
//|       - {"artifact":"kinks","path":"/rows/0/1","equals":0}
//|       - {"artifact":"kinks","path":"/rows/1/1","equals":1}
use scioxide_ad::{ExternalRule, Real, Tape, TapeOptions, Var};
use scioxide_core::ExecutionContext;
use std::sync::Arc;

let cx = ExecutionContext::sequential();
let rule: Arc<dyn ExternalRule<f64>> = Arc::new(Lowest);
let point = [a, b, c];
// External-rule gradient and its recording's kink count.
let mut external = [0.0; 3];
let mut tape = Tape::<f64>::new(TapeOptions::new());
tape.gradient_into(
    |s| {
        let mut y = [Var::constant(0.0)];
        Var::external(&rule, s, &mut y)?;
        Ok(y[0])
    },
    &point,
    &mut external,
    cx,
)
.map_err(|e| e.to_string())?;
let external_kinks = tape.report().kinks();
// Check: gradient from differentiating the closed form on a tape.
let mut direct = [0.0; 3];
let mut closed_tape = Tape::<f64>::new(TapeOptions::new());
closed_tape
    .gradient_into(|s| Ok(closed_form(s)), &point, &mut direct, cx)
    .map_err(|e| e.to_string())?;
let closed_kinks = closed_tape.report().kinks();

let (value, _) = lowest(&point).map_err(|e| e.to_string())?;
let (e, d) = (external, direct);
let gradients: Vec<_> = [
    ("λ", value, closed_form(&point)),
    ("∂λ/∂a", e[0], d[0]),
    ("∂λ/∂b", e[1], d[1]),
    ("∂λ/∂c", e[2], d[2]),
    ("∂λ/∂a + ∂λ/∂c", e[0] + e[2], d[0] + d[2]),
]
.iter()
.map(|&(name, rule_value, closed)| (name, rule_value, closed, (rule_value - closed).abs()))
.collect();

let digits = serde_json::json!({ "significantDigits": 16 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let gradient_columns = serde_json::json!([
    { "key": "0", "label": "Quantity" },
    { "key": "1", "label": "External rule [-]", "type": "number", "format": digits },
    { "key": "2", "label": "Closed form differentiated on tape [-]", "type": "number", "format": digits },
    { "key": "3", "label": "Difference [-]", "type": "number", "format": sci2 }
]);
emit_table_with_columns!(
    gradient_columns,
    gradients,
    metadata = serde_json::json!({ "id": "gradients" })
);
emit_table_with_columns!(
    ["Recording", "Kink count [count]"],
    vec![("External rule", external_kinks), ("Closed form", closed_kinks)],
    metadata = serde_json::json!({ "id": "kinks" })
);
```

At the default $(a, b, c) = (1, 0.5, -0.5)$, the external rule's $\lambda = -0.6513878188659973$ agrees with the closed form, and gradient differences are at most $3.3 \times 10^{-16}$.
$\partial\lambda/\partial a + \partial\lambda/\partial c$ also equals 1 within rounding for both methods.
Neither recording counts any kink.

At $a = c = 0.5$ and $b = 0$, the smallest eigenvalue is repeated and $\lambda$ is not differentiable.
The closed form uses partial derivatives $(0, 0)$ at the origin kink of `hypot`, returning gradient $(0.5, 0, 0.5)$.
The external rule returns $(1, 0, 0)$ from the solver's eigenvector $v = (1, 0)$.
$\lambda$ is locally Lipschitz in $S$ and its Clarke generalized gradient here is $\operatorname{conv}\{(v_0^2, 2v_0v_1, v_1^2) : \|v\| = 1\}$, so both values belong to it but differ from each other.
The tape counts one kink for the closed form's `hypot`, but does not count the repeated eigenvalue inside the external rule.

The next cell uses one linearization recorded with `Tape::linearize` to call pullback products (`vjp_into`, `jacobian_into` with `JacobianMode::Auto`) and a pushforward product (`jvp_into`).
The point is fixed at the default $(a, b, c) = (1, 0.5, -0.5)$; the input chooses whether to use the rule `LowestWithTangent` implementing a pushforward.
The direction for `jvp_into` is $(\dot a, \dot b, \dot c) = (1, 0, 1)$, so the identity above predicts a result of 1.

```rust
//| id: ad-external-products
//| ref: ad-external-products
//| title: "External rules without pushforwards and linearization products"
//| run: reactive
//| crates: [scioxide-ad, scioxide-core]
//| uses: [ad-eigenvalue-rules]
//| inputs:
//|   tangent: {"type":"checkbox","label":"Use a rule implementing pushforward","description":"Without it, jvp_into returns CapabilityUnavailable.","value":false}
//| cases:
//|   - {"id":"with-pushforward","label":"With pushforward","description":"jvp_into also succeeds, returning 1 as predicted by the identity.","inputs":{"tangent":true}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"products","path":"/rows/0/2","equals":"Success"}
//|       - {"artifact":"products","path":"/rows/0/1","approx":{"value":0.08397485283107817,"rtol":1e-13}}
//|       - {"artifact":"products","path":"/rows/1/1","approx":{"value":-0.5547001962252293,"rtol":1e-13}}
//|       - {"artifact":"products","path":"/rows/2/1","equals":null}
//|       - {"artifact":"products","path":"/rows/2/2","equals":"CapabilityUnavailable（external rule pushforward）"}
//|       - {"artifact":"recording","path":"/rows/0/0","equals":10}
//|       - {"artifact":"recording","path":"/rows/0/1","equals":"Passive"}
//|   - case: with-pushforward
//|     expect:
//|       - {"artifact":"products","path":"/rows/2/1","approx":{"value":1,"atol":1e-14}}
//|       - {"artifact":"products","path":"/rows/2/2","equals":"Success"}
use scioxide_ad::{ExternalRule, Real, Tape, TapeOptions, Var};
use scioxide_core::{Capability, ExecutionContext, SciOxideErrorKind, SciOxideErrorView};
use std::sync::Arc;

let rule: Arc<dyn ExternalRule<f64>> = if tangent {
    Arc::new(LowestWithTangent)
} else {
    Arc::new(Lowest)
};
// Point fixed at the default (a, b, c) = (1, 0.5, −0.5).
let point = [1.0, 0.5, -0.5];
// Call pullback and pushforward products on a single linearization.
let cx = ExecutionContext::sequential();
let mut tape = Tape::<f64>::new(TapeOptions::new());
let mut linear = tape
    .linearize(
        |s, y| {
            let mut out = [Var::constant(0.0)];
            Var::external(&rule, s, &mut out)?;
            y.push(out[0]);
            Ok(())
        },
        &point,
        cx,
    )
    .map_err(|e| e.to_string())?;
let mut reverse = [0.0; 3];
let vjp = linear
    .vjp_into(&[1.0], &mut reverse, cx)
    .map(|()| reverse[0]);
let mut jacobian = [0.0; 3];
let full = linear
    .jacobian_into(&mut jacobian, cx)
    .map(|()| jacobian[1]);
let mut forward = [0.0];
let jvp = linear
    .jvp_into(&[1.0, 0.0, 1.0], &mut forward, cx)
    .map(|()| forward[0]);
let products: Vec<_> = [
    ("∂λ/∂a from vjp_into(ȳ = 1)", vjp),
    ("∂λ/∂b from jacobian_into (Auto, reverse sweep)", full),
    ("jvp_into(ẋ = (1, 0, 1))", jvp),
]
.into_iter()
.map(|(product, result)| match result {
    Ok(value) => (product, Some(value), "Success".to_string()),
    // Classify errors with kind() and view().
    Err(error) => match (error.kind(), error.view()) {
        (
            SciOxideErrorKind::CapabilityUnavailable,
            SciOxideErrorView::CapabilityUnavailable {
                capability: Capability::Operation(operation),
            },
        ) => (
            product,
            None,
            format!("CapabilityUnavailable（{operation}）"),
        ),
        _ => (product, None, error.to_string()),
    },
})
.collect();
let words = tape.report().words();

// Passive inputs trigger evaluation only and give passive outputs.
let constants = point.map(|v| Var::constant(v));
let mut passive = [Var::constant(0.0)];
Var::external(&rule, &constants, &mut passive).map_err(|e| e.to_string())?;
let activity = if passive[0].is_active() {
    "Active"
} else {
    "Passive"
};

let digits = serde_json::json!({ "significantDigits": 16 });
let product_columns = serde_json::json!([
    { "key": "0", "label": "Product" },
    { "key": "1", "label": "Result [-]", "type": "number", "format": digits, "nullText": "—" },
    { "key": "2", "label": "Status" }
]);
emit_table_with_columns!(
    product_columns,
    products,
    metadata = serde_json::json!({ "id": "products" })
);
emit_table_with_columns!(
    ["Recorded words [words]", "Output for passive inputs"],
    vec![(words, activity)],
    metadata = serde_json::json!({ "id": "recording" })
);
```

With a pullback-only rule, `vjp_into` and `jacobian_into` succeed.
Since one output is fewer than three inputs, `JacobianMode::Auto` selects reverse sweeps.
`jvp_into` returns `CapabilityUnavailable` (`external rule pushforward`).
With a rule implementing a pushforward, `jvp_into` also succeeds and returns $1.0000000000000002$ (1 ulp from 1), as predicted by the identity.
The recording's 10 words comprise one constant slot, three inputs, five call-statement words (header, three arguments, and a header copy), and one output, showing that `Var::external` was recorded as one call statement.
The output of `Var::external` called with passive inputs is passive.

## Summary

Wrap external computations that cannot use `Real` operations in an `ExternalRule` supplying values, a pullback, and optionally a pushforward, and record them as one tape call statement with `Var::external`.
Write rules as pure functions of their inputs, adding pullbacks to input adjoints and overwriting output tangents in pushforwards.
Rules without pushforwards still give gradients, VJPs, and reverse-sweep Jacobians, but products using tangent sweeps, such as `jvp_into`, return `CapabilityUnavailable`.
Computations inside rules are not recorded, so kinks or nondifferentiable points such as repeated eigenvalues inside them do not appear in tape kink counts; check rule derivatives against closed forms or other methods.
A rule generic over `V` also works with `Tape<Dual<S>>`, evaluating pullbacks with dual numbers to give Hessian–vector products.
