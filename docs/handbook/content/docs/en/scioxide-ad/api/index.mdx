`scioxide-ad` lets you write a function once for numeric type `R: Real` and obtain derivatives by choosing numeric types and transformations.
Its 62 public items (10 traits, 21 structs, 7 enums, and 24 functions) are grouped into four tables by purpose.
Item-name links point to the version 0.1.0 API reference on docs.rs.
Algorithm and error discussions appear in [Automatic differentiation algorithms](../algorithms/), accessible through the tables' “Discussion” and “Runnable example” columns.

The complex type `Complex` belongs to scioxide-core.
scioxide-differentiate supplies finite-difference derivatives when only function values are available.

## Type relationships

- `Real` is a sealed numeric-type trait implemented by `f32`, `f64`, `Lanes`, `Dual`, `MultiDual`, `Jet`, and `Var`.
  Associated type `Base` is the innermost value (`f32`, `f64`, or `Lanes`, trait `BaseReal`), `Primal` the value one level below, and `Mask` the comparison result (`bool` or `LaneMask`, trait `Mask`).
- `Dual`, `MultiDual`, and `Jet` wrap any `Real` and can be nested.
  `Var<'t, V>` is a value recorded on `Tape<V>`; `V` implements trait `TapeValue` (scalars, `Lanes`, and their `Dual`, `MultiDual`, and `Jet` wrappers).
  No type wraps `Var`.
- The caller owns `Tape` and selects policies with `TapeOptions`.
  `gradient_into` returns a gradient, `linearize` returns a recording `Linearization` at one point, and `Linearization` yields products, structural patterns, and a `JacobianOperator`.
  `Tape<Dual<S>>` provides `hvp_into`, `sparse_hessian_into`, and `HessianOperator`.
  `TapeRequirements` gives recording size and `TapeReport` facts about the latest transformation.
- One-shot functions (`grad`, `value_and_grad`, `vjp`, `jacobian`, `hvp`, `hessian`) create new tapes and allocate results.
  `jvp` and `jet` are forward-mode one-shot calls without tapes.
- `BatchPlan` sums `BatchFunction` over the items of `BatchData`, writes to `BatchOutputs`, and returns `BatchEstimate`.
  Memory is held in `BatchWorkspace`, with size `BatchRequirements`.
  Select the mode with `DerivativeMode` in `BatchOptions`; the used mode is returned as `BatchMode`.
- Structured operations (from `dot` to `checkpointed_loop`) are free functions working with every numeric type.
  Supply caller-defined rules through traits `ExternalRule`, `Residual`, and `LoopBody`.

## Minimal runnable example

Compute the same gradient in three forms.
These are one-shot `value_and_grad`, caller-owned tape `Tape::gradient_into`, and forward-mode `MultiDual<f64, 3>`.
The function is the three-variable extended Rosenbrock function

$$
f(x) = \sum_{i=0}^{1} \Bigl[(1 - x_i)^2 + 10\,(x_{i+1} - x_i^2)^2\Bigr]
$$

with input first component $x_0$ ($-1.5$ to $1.5$, dimensionless).
Fix the remaining components at $x_1 = 0.8$ and $x_2 = 0.5$.
The table shows each form's three gradient components, maximum difference from the closed-form gradient, and whether the function was recorded twice to expand the tape.
Call the tape form twice on the same tape and show the first and second calls in separate rows.

```rust
//| id: ad-api-gradient-forms
//| ref: ad-api-gradient-forms
//| title: "Compute the same gradient with one-shot calls, a tape, and forward mode"
//| run: reactive
//| crates: [scioxide-ad, scioxide-core]
//| inputs:
//|   first: {"type":"range","label":"First component x₀","description":"First component of the differentiation point (dimensionless). x₁ = 0.8 and x₂ = 0.5 are fixed.","min":-1.5,"max":1.5,"step":0.1,"value":0.3}
//| cases:
//|   - {"id":"negative-start","label":"x₀ = −1.2","description":"All three gradients agree even at a point with a large gradient.","inputs":{"first":-1.2}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"forms","path":"/rows/0/1","approx":{"value":-9.92,"rtol":1e-13}}
//|       - {"artifact":"forms","path":"/rows/0/4","range":{"max":1e-13}}
//|       - {"artifact":"forms","path":"/rows/1/4","range":{"max":1e-13}}
//|       - {"artifact":"forms","path":"/rows/2/4","range":{"max":1e-13}}
//|       - {"artifact":"forms","path":"/rows/3/4","range":{"max":1e-13}}
//|       - {"artifact":"forms","path":"/rows/1/5","equals":"Yes"}
//|       - {"artifact":"forms","path":"/rows/2/5","equals":"No"}
//|   - case: negative-start
//|     expect:
//|       - {"artifact":"forms","path":"/rows/0/4","range":{"max":1e-12}}
//|       - {"artifact":"forms","path":"/rows/3/4","range":{"max":1e-12}}
use scioxide_ad::{MultiDual, Real, Tape, TapeOptions, value_and_grad};
use scioxide_core::ExecutionContext;

// Write the extended Rosenbrock function once for numeric type R.
fn rosenbrock<R: Real>(x: &[R]) -> R {
    x.windows(2)
        .map(|w| (-w[0] + 1.0).powi(2) + (w[1] - w[0] * w[0]).powi(2) * 10.0)
        .sum()
}

let point = [first, 0.8, 0.5];
// Independent check: closed-form gradient (f64 arithmetic).
let exact = [
    -2.0 * (1.0 - point[0]) - 40.0 * point[0] * (point[1] - point[0] * point[0]),
    20.0 * (point[1] - point[0] * point[0])
        - 2.0 * (1.0 - point[1])
        - 40.0 * point[1] * (point[2] - point[1] * point[1]),
    20.0 * (point[2] - point[1] * point[1]),
];
let cx = ExecutionContext::sequential();
let mut rows = Vec::new();
let mut push = |name: &str, g: [f64; 3], twice: Option<bool>| {
    let error = (0..3).map(|i| (g[i] - exact[i]).abs()).fold(0.0, f64::max);
    let recorded = twice.map(|t| if t { "Yes" } else { "No" });
    rows.push((name.to_string(), g[0], g[1], g[2], error, recorded));
};

// One-shot call: create a new tape and allocate the result Vector.
let (_, gradient) = value_and_grad(|x| Ok(rosenbrock(x)), &point).map_err(|e| e.to_string())?;
let g = gradient.as_slice();
push("value_and_grad (one-shot)", [g[0], g[1], g[2]], None);

// Caller-owned tape: first call records twice to expand it; second call allocates nothing.
let mut tape = Tape::<f64>::new(TapeOptions::new());
let mut g = [0.0; 3];
for name in [
    "Tape::gradient_into (first call)",
    "Tape::gradient_into (second call)",
] {
    tape.gradient_into(|x| Ok(rosenbrock(x)), &point, &mut g, cx)
        .map_err(|e| e.to_string())?;
    push(name, g, Some(tape.report().recorded_twice()));
}

// Forward mode: carry three directional tangents in one evaluation.
let mut x = [MultiDual::<f64, 3>::constant(0.0); 3];
for (i, xi) in x.iter_mut().enumerate() {
    *xi = MultiDual::variable(point[i], i).map_err(|e| e.to_string())?;
}
push(
    "MultiDual<f64, 3> (forward mode)",
    rosenbrock(&x).gradient(),
    None,
);

let value = serde_json::json!({ "significantDigits": 15 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "Form" },
    { "key": "1", "label": "∂f/∂x₀ [-]", "type": "number", "format": value },
    { "key": "2", "label": "∂f/∂x₁ [-]", "type": "number", "format": value },
    { "key": "3", "label": "∂f/∂x₂ [-]", "type": "number", "format": value },
    { "key": "4", "label": "Maximum difference from closed form [-]", "type": "number", "format": sci3 },
    { "key": "5", "label": "Recorded twice", "nullText": "Tape not reused" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "forms" })
);
```

At the default $x_0 = 0.3$, all four gradient rows give $(-9.92, 18.28, -2.8)$, with closed-form differences at most $2 \times 10^{-15}$.
The first tape call counts statements that do not fit in an empty tape, expands it, and records the function again, giving “Yes”.
The second records the same function at the same size, so it needs only one execution and no allocation.
One-shot `value_and_grad` creates a new tape and executes the function twice per call; choose the tape form for repeated calls.
`MultiDual<f64, 3>` obtains three components in one evaluation without a tape.

## Reading results, errors, and diagnostics

- Numeric-type operations return no errors.
  Outside their domains, they produce IEEE 754 results (NaN or infinity), which propagate to derivatives.
  To detect them, select `TapeOptions::with_non_finite_policy(NonFinitePolicy::Error)`, producing `NonFinite` at transformation boundaries.
- Transformation and structured-operation failures return `SciOxideError`.
  Classify with `kind()` (`DimensionMismatch`, `NonFinite`, `DomainError`, `Singular`, `InvalidInput`, `ResourceLimit`, `AllocationFailure`, `ExecutionStopped`, `CapabilityUnavailable`, and others); read the argument and reason with `view()`.
  Function or rule errors propagate unchanged in kind.
- Failed transformations leave caller-owned output storage unchanged.
  Batch evaluation also writes outputs only after every block succeeds.
- `TapeReport` shows statement count, allocated bytes, kink encounters, and whether the latest transformation recorded again.
  `BatchEstimate` shows the value, standard error, directional derivative, item and block counts, used mode, and kink encounters.
- Automatic-differentiation transformations have no iterations, termination status, or convergence decision.
  Implicit differentiation checks the caller-computed solution residual against tolerance and returns `InvalidInput` if it fails.

## Summary

Write functions once for `R: Real` and choose numeric types and transformations for the desired derivatives.
For a single differentiation, use a one-shot function; for repeated differentiation of the same function, reuse a tape and output storage.
Classify failures through `kind()` on `SciOxideError`; failed calls leave outputs unchanged.
Find item specifications in the purpose-grouped tables and algorithms and errors through their “Discussion” columns.
