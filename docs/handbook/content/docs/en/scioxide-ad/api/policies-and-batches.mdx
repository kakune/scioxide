This table covers policies applied at transformation boundaries and batch items for evaluating sums and means of many independent items.
Select policies with `TapeOptions` and `BatchOptions`; numeric-type operations themselves always follow IEEE 754.
`BatchPlan` selects value, forward, or reverse mode according to whether gradients are requested; values have identical bits in every mode.
Since wasm cannot use threads, handbook cells show only sequential execution.
Item-name links point to the version 0.1.0 API reference on docs.rs.

## Batch plans and functions

|---|---|---|---|---|---|
| [`BatchPlan`](https://docs.rs/scioxide-ad/0.1.0/scioxide_ad/struct.BatchPlan.html) | Struct | Plan evaluating many independent items in groups of `W` | `new(items, parameters, inputs, data, reduction, options)` (`W = 0` or `Mean` with zero items gives `InvalidInput`; block-size overflow gives `SizeOverflow`). `evaluate_into`, `jvp_into`, `hvp_into`, `workspace_requirements`, `workspace` (1–64 workers), and accessors. Pairwise addition of block results by block index makes results independent of execution policy and worker count; values have identical bits in value/forward/reverse mode. Sum error is at most $\gamma_k \sum_i \lvert y_i \rvert$ ($k = b + \lceil \log_2 B \rceil$). Writes outputs only after all blocks succeed; calls `context.check()` before execution, per block, and before output writes. Overflow in differentiated-value counts or workspace sizes gives `SizeOverflow`. `input_product` from `hvp_into` differentiates per-item input gradients without reduction scaling, like `with_input_gradient`; for means, divide by $n$ to obtain the input part of the Hessian–vector product. `Clone`, `Send + Sync` | [`BatchPlan` and blocks](oxref:ad-batch-plan-blocks), [One-shot means and function providers](oxref:ad-batch-one-shot) | [Batch terminal-value expectations and gradients in value/forward/reverse modes](oxref:ad-batch-mean-gradient), [Compute and compare loss gradients with tape backpropagation and sample batching](oxref:ad-nn-gradients), [Estimate prices and Greeks by pathwise Monte Carlo differentiation and compare with closed forms in standard errors](oxref:ad-bs-monte-carlo) |

## Summary

Choose `NonFinitePolicy::Error` for early nonfinite detection and `KinkPolicy::Error` to reject points passing through kinks.
Evaluate sums and means of many items by passing `BatchFunction` to `BatchPlan` and obtain gradients with `BatchOutputs`.
`Mean` returns standard errors; gradient standard errors are estimated from at least two block means.
Construct workspace once with `workspace` and reuse it with the same plan.
