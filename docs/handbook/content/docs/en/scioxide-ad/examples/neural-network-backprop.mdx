Training a neural network repeatedly computes the gradient of a loss $L(\theta)$ with respect to weights $\theta \in \mathbb{R}^P$.
Backpropagation computes this gradient by reverse-mode automatic differentiation.
Gradient implementations are often verified by a gradient check against finite differences, but finite-difference error depends on step size and limits the accuracy of the comparison.

This example compares two gradients of a regression network with one tanh hidden layer: `value_and_grad`, which records on a tape, and `BatchPlan`, which averages over samples as items.
It then compares with scioxide-differentiate's central differences, showing a U-shaped relative-error curve against step size and a limit to the accuracy at which agreement can be checked.

## Regression network and loss

Input $x$ and output $\hat y$ are dimensionless scalars; let the hidden-layer width be $m$.

$$
\hat y(x; \theta) = \sum_{j=1}^{m} a_j \tanh(w_j x + b_j) + c,\qquad
L(\theta) = \frac{1}{N}\sum_{k=1}^{N} \ell_k(\theta),\qquad
\ell_k(\theta) = \tfrac12\bigl(\hat y(x_k; \theta) - y_k\bigr)^2
$$

Order the weights as $\theta = [w_1, \dots, w_m, b_1, \dots, b_m, a_1, \dots, a_m, c]$, with count $P = 3m + 1$ (widths 17–166 give $P$ from 52 to 499).
The training data contain $N = 24$ points: $x_k$ are equally spaced in $[-1, 1]$ and the targets are $y_k = \sin(\pi x_k)$.

Use random weights before training, drawing $w_j, b_j$ from the uniform distribution $[-2, 2)$ and $a_j$ from $[-1, 1)/\sqrt m$, with $c = 0$.
Generate random numbers with scioxide-random's SplitMix64 and a specified seed, so the same seed gives the same weights ([scioxide-random chapter](../../../scioxide-random/)).

## Backpropagation is a reverse sweep with cotangent 1

Let $J = \partial F/\partial\theta$ ($N\times P$) be the Jacobian of the prediction map $F(\theta) = [\hat y(x_1;\theta), \dots, \hat y(x_N;\theta)]$ and $r = F(\theta) - y$ the residual; then $\nabla L = J^{\mathsf T} r / N$.
Reverse mode records evaluation on a tape and traverses backward from the output adjoint $\bar L = 1$ to collect $\bar\theta = \nabla L$.
Its computational cost is a constant multiple of evaluating $L$, independently of the weight count $P$.
Computing the same gradient by forward mode requires $P$ directional derivatives in unit directions.

`value_and_grad` records the function on a new tape and returns the value and gradient (`scioxide_linalg::Vector`) with one reverse sweep from cotangent 1.
A new tape has no capacity, so the function executes twice: first to count the recording size, then to record on the expanded tape ([Tape lifecycle and reuse](../../algorithms/tape-lifecycle/)).
Pass a closure of the form `|t| Ok(loss(t, &data))`, evaluating the generic function `loss` with the reverse-mode numeric type `Var<f64>`.
The tape records individual operations as statements, so recording length is proportional to $N m$ ([Reverse mode and tapes](../../algorithms/reverse-mode-and-replay/)).

## Differentiating the sample mean in a batch

$L$ is the mean of per-sample losses $\ell_k$, each $\ell_k$ depending only on the same weights $\theta$ and its sample $(x_k, y_k)$.
`BatchPlan` computes a sum of this form, $\sum_k f(\theta, a_k, d_k)$, or its mean over many independent items.
$\theta$ denotes parameters shared by all items, $a_k$ per-item differentiated inputs, and $d_k$ per-item data excluded from differentiation.
Here items are samples, parameters are $P$ weights, there are no differentiated inputs, and each item has two data values $(x_k, y_k)$; average with `BatchReduction::Mean`.
Pass the data as an items × 2 row-major table (an `&[f64]` slice) and indicate the absence of differentiated inputs with an empty slice.

Write the function as a `BatchFunction`.
`prepare` constructs item-independent state from parameters and is called once per block (256 items by default).
`item` returns one item's value; when `R` has lanes (one SIMD element each), it evaluates $W$ consecutive items at once.
Data arrive as `R::Base` values; introduce them into arithmetic as nondifferentiated values with `R::passive`.

When computing gradients with default `DerivativeMode::Auto`, `BatchPlan` selects the numeric type automatically.
It uses forward-mode `MultiDual<Lanes<f64, W>, N>` if parameters and inputs total at most four, and reverse-mode `Var<Lanes<f64, W>>` otherwise.
This example has $P \ge 52$, so it uses reverse mode: on one tape per worker, record `prepare` once per block, then append and sweep through items in groups of $W = 8$ samples.
The 24 samples fit in one block and are evaluated as three groups of eight lanes.
Block results are added pairwise in block-index order, so the estimate and gradient have identical bits regardless of execution policy and worker count ([Batch evaluation of many items](../../algorithms/batches/)).
The cells on this page execute sequentially.

Tape and batch gradients agree at the rounding-error level but need not match bit for bit.
Batch `tanh` uses a lane arithmetic kernel and can differ from the scalar function by a few ulp (kernel error is at most 4 ulp).
The order of summing per-sample gradient contributions also differs.
The tape traverses statements in reverse order to add adjoint contributions, while batching sums lane adjoints in lane order at the block's end.

The following block defines the model shared by the two cells.
`samples` gives training data, `initial_weights` initial weights, `predict` corresponds to $\hat y$, and `loss` to $L$.

```rust
//| id: ad-nn-model
//| kind: definitions
//| title: "Regression network and mean squared error"
//| crates: [scioxide-ad, scioxide-core, scioxide-random]
use scioxide_ad::Real;
use scioxide_core::{SciOxideError, RealScalar};
use scioxide_random::{Rng, SeedableRng, SplitMix64};

/// Training data (x_k, y_k): 24 equally spaced points in [−1, 1] and y_k = sin(πx_k).
pub(crate) fn samples() -> Vec<[f64; 2]> {
    let n = 24;
    (0..n)
        .map(|k| {
            let x = -1.0 + 2.0 * k as f64 / (n - 1) as f64;
            [x, Real::sin_pi(x)]
        })
        .collect()
}

/// Initial weights θ = [w (m), b (m), a (m), c]: w, b from U(−2, 2), a from U(−1, 1)/√m, and c = 0.
pub(crate) fn initial_weights(width: usize, seed: u64) -> Result<Vec<f64>, SciOxideError> {
    let mut rng = SplitMix64::from_seed(seed);
    let mut theta = vec![0.0; 3 * width + 1];
    for (i, t) in theta.iter_mut().take(3 * width).enumerate() {
        let u: f64 = rng.next_float()?;
        *t = if i < 2 * width {
            4.0 * u - 2.0
        } else {
            (2.0 * u - 1.0) / RealScalar::sqrt(width as f64)
        };
    }
    Ok(theta)
}

/// ŷ(x; θ) = Σⱼ aⱼ tanh(wⱼ x + bⱼ) + c.
pub(crate) fn predict<R: Real>(theta: &[R], x: R) -> R {
    let m = (theta.len() - 1) / 3;
    let (w, rest) = theta.split_at(m);
    let (b, rest) = rest.split_at(m);
    let (a, c) = rest.split_at(m);
    let hidden: R = w
        .iter()
        .zip(b)
        .zip(a)
        .map(|((&w, &b), &a)| a * (w * x + b).tanh())
        .sum();
    hidden + c[0]
}

/// L(θ) = (1/N) Σ_k ½(ŷ(x_k; θ) − y_k)².
pub(crate) fn loss<R: Real>(theta: &[R], data: &[[f64; 2]]) -> R {
    let total: R = data
        .iter()
        .map(|&[x, y]| {
            let r = predict(theta, R::constant(x)) - y;
            r * r * 0.5
        })
        .sum();
    total / data.len() as f64
}
```

```rust
//| title: "Compute and compare loss gradients with tape backpropagation and sample batching"
//| run: reactive
//| uses: [ad-nn-model]
//| crates: [scioxide-ad, scioxide-core]
//| exports: [theta, gradient, loss]
//| inputs:
//|   width: {"type":"range","label":"Hidden-layer width m","description":"Weight count P = 3m + 1 (52–499).","min":17,"max":166,"step":1,"value":32}

//|   - {"id":"wide","label":"m = 166, seed 123","description":"Even with P = 499 weights, both gradients agree at the rounding-error level.","inputs":{"width":166,"seed":123}}

//|   - case: default

//|       - {"artifact":"gradients","path":"/rows/0/2","approx":{"value":0.402049784259763,"rtol":1e-13}}
//|       - {"artifact":"gradients","path":"/rows/0/3","approx":{"value":2.374398919533063,"rtol":1e-13}}
//|       - {"artifact":"gradients","path":"/rows/1/1","equals":"Reverse mode"}
//|       - {"artifact":"gradients","path":"/rows/1/4","range":{"max":1e-15}}
//|       - {"artifact":"gradients","path":"/rows/1/5","range":{"max":1e-14}}
//|   - case: wide
//|     expect:
//|       - {"artifact":"gradients","path":"/rows/0/3","approx":{"value":5.716510097729216,"rtol":1e-13}}
//|       - {"artifact":"gradients","path":"/rows/1/5","range":{"max":1e-14}}
//|   - case: narrow
//|     expect:
//|       - {"artifact":"gradients","path":"/rows/0/3","approx":{"value":1.0617748143601429,"rtol":1e-13}}
//|       - {"artifact":"gradients","path":"/rows/1/5","range":{"max":1e-14}}
use scioxide_ad::{
    BatchFunction, BatchMode, BatchOptions, BatchOutputs, BatchPlan, BatchReduction, Real,
    value_and_grad,
};
use scioxide_core::{ExecutionContext, SciOxideError, RealScalar};

/// Loss ½(ŷ(x; θ) − y)² for one sample. data = [x, y].
struct Regression;
impl BatchFunction for Regression {
    type Shared<R: Real> = Vec<R>;
    fn prepare<R: Real>(&self, theta: &[R]) -> Result<Vec<R>, SciOxideError> {
        Ok(theta.to_vec())
    }
    fn item<R: Real>(
        &self,
        theta: &Vec<R>,
        _: &[R],
        data: &[R::Base],
    ) -> Result<R, SciOxideError> {
        let r = predict(theta, R::passive(data[0])) - R::passive(data[1]);
        Ok(r * r * 0.5)
    }
}

let data = samples();
let theta = initial_weights(width as usize, seed as u64).map_err(|e| e.to_string())?;
// Tape backpropagation: record the loss once and reverse-sweep from cotangent 1.
let (tape_loss, tape_gradient) =
    value_and_grad(|t| Ok(loss(t, &data)), &theta).map_err(|e| e.to_string())?;
let tape_gradient = tape_gradient.as_slice();
// Batching: samples are items and weights are parameters; pack eight samples into lanes and average.
let table: Vec<f64> = data.iter().flatten().copied().collect();
let plan = BatchPlan::<8>::new(
    data.len(),
    theta.len(),
    0,
    2,
    BatchReduction::Mean,
    BatchOptions::new(),
)
.map_err(|e| e.to_string())?;
let mut workspace = plan.workspace(1).map_err(|e| e.to_string())?;
let mut batch_gradient = vec![0.0; theta.len()];
let estimate = plan
    .evaluate_into(
        &Regression,
        &theta,
        &[],
        &table[..],
        BatchOutputs::new().with_parameter_gradient(&mut batch_gradient),
        &mut workspace,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;
let mode = match estimate.mode() {
    BatchMode::Value => "Value",
    BatchMode::Forward { .. } => "Forward mode",
    BatchMode::Reverse => "Reverse mode",
};
let norm = |v: &[f64]| RealScalar::sqrt(v.iter().map(|x| x * x).sum::<f64>());
let difference: Vec<f64> = batch_gradient
    .iter()
    .zip(tape_gradient)
    .map(|(a, b)| a - b)
    .collect();
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let digits = serde_json::json!({ "significantDigits": 15 });
let columns = serde_json::json!([
    { "key": "0", "label": "Method" },
    { "key": "1", "label": "Numeric type" },
    { "key": "2", "label": "Loss L [-]", "type": "number", "format": digits },
    { "key": "3", "label": "‖∇L‖₂ [-]", "type": "number", "format": digits },
    { "key": "4", "label": "Relative loss difference [-]", "type": "number", "format": sci3, "nullText": "Reference" },
    { "key": "5", "label": "Relative gradient difference [-]", "type": "number", "format": sci3, "nullText": "Reference" }
]);
let rows = vec![
    (
        "value_and_grad",
        "Var<f64>",
        tape_loss,
        norm(tape_gradient),
        None,
        None,
    ),
    (
        "BatchPlan (mean)",
        mode,
        estimate.value(),
        norm(&batch_gradient),
        Some((estimate.value() - tape_loss).abs() / tape_loss.abs()),
        Some(norm(&difference) / norm(tape_gradient)),
    ),
];
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "gradients" })
);
export!(theta, &theta);
export!(gradient, &tape_gradient.to_vec());
export!(loss, &tape_loss);
```

At the default inputs ($m = 32$, $P = 97$, seed 7), the loss is $L = 0.402050$, the gradient norm is $\|\nabla L\|_2 = 2.374399$, and batching selects reverse mode.
The batch loss matches the tape loss bit for bit (environments whose `tanh` lane kernel differs from the scalar function may differ by a few ulp), and the relative gradient difference is $1.9\times 10^{-16}$.
With $m = 166$ and seed 123 ($P = 499$), $\|\nabla L\|_2 = 5.716510$ and the relative difference is $2.3\times 10^{-16}$; with $m = 17$ and seed 4242 ($P = 52$), $\|\nabla L\|_2 = 1.061775$ and the relative difference is $2.2\times 10^{-16}$.
Every relative difference is only a few times the double-precision unit roundoff (about $1.1\times 10^{-16}$), so both methods give the same gradient within rounding error.
This compares results applying the same derivative rules in different orders, however, and does not verify the rules themselves.
Next, compare with finite differences for a check independent of those rules.

## Gradient checks with central differences

Central differences approximate the gradient by $\partial L/\partial\theta_i \approx [L(\theta + h e_i) - L(\theta - h e_i)]/(2h)$.
Taylor expansion gives truncation error of order $\frac{h^2}{6}\,\partial^3 L/\partial\theta_i^3$, while rounding in values of $L$ (relative error of order machine epsilon $\varepsilon \approx 2.2\times 10^{-16}$) gives error of order $\varepsilon|L|/h$; their sum is minimized at $h \sim \varepsilon^{1/3}$.
[Rounding error, noise, and the optimal step size](../../../scioxide-differentiate/algorithms/roundoff-and-noisy-functions/) gives the derivation and step selection, which are not repeated here.

For the whole-gradient relative error $e(h) = \|g_{\mathrm{FD}} - \nabla L\|_2 / \|\nabla L\|_2$, treat rounding errors in $P$ entries as independent contributions and use the rounding-error scale $c_1/h$ ($c_1 = \varepsilon|L|\sqrt P/\|\nabla L\|_2$).
Write the truncation error as $c_2 h^2$; the step minimizing $c_1/h + c_2 h^2$ is $(c_1/2c_2)^{1/3}$.

Use scioxide-differentiate's `FiniteDifference` for differences.
Specify a common step $h$ for all entries with `FiniteDifference::default().with_step(DifferenceStep::absolute(h)?)`, and obtain the gradient of a function with $P$ inputs and one output using `gradient`.
The default step for a first derivative by central differences is $\varepsilon^{1/3}\max(1, |\theta_i|)$.
Central differences evaluate two points around each coordinate plus the base point $\theta$ once, giving $2P + 1$ evaluations per gradient (passing the known value $L(\theta)$ to `base` omits the base-point evaluation).
The fixed-step difference termination status `Completed` indicates only that the stencil was evaluated and makes no accuracy claim.

The difference callback evaluates the same generic function `loss` with `f64`.
Because it uses no derivative rules, it independently checks the AD gradient.

The following cell receives weights $\theta$, tape gradient, and loss from the previous cell, then computes 25 central-difference gradients at steps varying from $h = 10^{-1}$ to $10^{-13}$ by factors of $10^{1/2}$, a gradient at the tabulated step $h = 10^x$, and a gradient at the default step.
The log–log graph shows observations of $e(h)$ (symbols) and dashed lines for the two error slopes; vertical lines mark the selected $h$ and $\varepsilon^{1/3}$.
The truncation-error line takes only slope 2 from theory and fits coefficient $c_2$ to the observation at $h = 10^{-3}$.
The rounding-error line is the scale $c_1/h$ above, without fitting observations.
With $m = 166$, each finite-difference gradient evaluates the loss 999 times, and 27 gradients are computed in total, taking a few seconds in wasm.

At the default weights ($m = 32$, seed 7), errors are $e = 1.37\times 10^{-4}$ at $h = 10^{-1}$ and $1.37\times 10^{-10}$ at $h = 10^{-4}$: each tenfold decrease in $h$ reduces error a hundredfold, following the dashed truncation-error line.
The error reaches its minimum $1.5\times 10^{-11}$ at $h = 3.2\times 10^{-5}$; at smaller $h$ it increases tenfold per decade, reaching $2.2\times 10^{-3}$ at $h = 10^{-13}$.

The rounding-error scale gives $3.7\times 10^{-5}$ at $h = 10^{-11}$, about 1.5 times the observed $2.4\times 10^{-5}$ and the same order of magnitude.
The step $2.4\times 10^{-5}$ derived from the two lines agrees with the observed minimum's location, and the default-step error is $3.8\times 10^{-11}$.
The error at selected step $h = 10^{-5}$ is $2.6\times 10^{-11}$, with $2P + 1 = 195$ evaluations per finite-difference gradient.

Setting the table's step to $h = 10^{-9}$ gives error $2.3\times 10^{-7}$ on the rounding-error side, while $h = 10^{-1}$ gives $1.37\times 10^{-4}$ on the truncation-error side.
This gradient check establishes relative agreement of about $10^{-11}$ between AD and finite differences; smaller discrepancies are hidden by finite-difference error.

## Behavior when parameters change

Setting the previous cell's width to $m = 166$ ($P = 499$) and seed to 123 increases the gradient norm to 5.7, but barely moves the relative-error curve.
The minimum is $1.0\times 10^{-11}$ at $h = 3.2\times 10^{-5}$, the step from the two lines is $2.7\times 10^{-5}$, and the error at $h = 10^{-9}$ is $1.7\times 10^{-7}$.
In the rounding-error scale $c_1$, $\sqrt P$ and $\|\nabla L\|_2$ increase in nearly the same ratio, canceling the influence of $P$ in this example.
The finite-difference evaluation count, however, increases to $2P + 1 = 999$, and finite-difference gradient cost grows in proportion to $P$.
The tape gradient's computational cost remains a constant multiple of evaluating the loss.

With $m = 17$ and seed 4242 ($P = 52$), the error at $h = 10^{-1}$ increases to $3.3\times 10^{-4}$, its minimum is $2.6\times 10^{-11}$ at $h = 10^{-5}$, and the evaluation count is 105.
Choosing a step near $\varepsilon^{1/3}$, as the default does, gives errors between $2\times 10^{-11}$ and $4\times 10^{-11}$ for the three tested weight sets.
Disagreement orders of magnitude larger than this suggests an implementation error rather than step selection.

## Summary

`value_and_grad` returns the loss and gradient with one reverse sweep, costing a constant multiple of loss evaluation independently of the weight count $P$.
If the loss is a mean of samplewise terms, use the same generic function in `item` of a `BatchFunction` and differentiate with `BatchPlan` by packing samples into lanes.
When the total number of parameters and inputs exceeds four, reverse mode is selected and agrees with the tape gradient to a relative difference of about $10^{-16}$.
In central-difference gradient checks, the relative error forms a U-shaped curve as the sum of $h^2$ truncation error and $\varepsilon/h$ rounding error; here, agreement is limited to about $10^{-11}$ at $h \approx 3\times 10^{-5}$.
For a fixed-step gradient check, choose near $\varepsilon^{1/3}$ and avoid mistaking disagreements at much larger or smaller steps for AD error.
