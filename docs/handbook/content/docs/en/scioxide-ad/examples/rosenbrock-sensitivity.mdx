The Rosenbrock function, used by H. H. Rosenbrock in 1960 to test optimization methods, has its minimum at the bottom of a narrow curved valley.
Curvature across the valley is orders of magnitude greater than along it, so methods using only gradients bounce between valley walls and make slow progress along the valley.

This example obtains gradients in three ways—forward-mode dual numbers `Dual`, the reverse-mode one-shot call `value_and_grad`, and `Tape::gradient_into` on a caller-owned tape—and compares them with closed forms.
It then obtains the Hessian at a valley-floor point with `hessian` and uses scioxide-linalg's symmetric eigensolver for eigenvalues and condition numbers, comparing curvature along and across the valley with closed forms.

## The generalized Rosenbrock function

For dimension $n \ge 2$ and coefficients $a > 0$ and $b > 0$, consider

$$
f(\mathbf{x}) = \sum_{i=0}^{n-2} \left[ (a - x_i)^2 + b\,(x_{i+1} - x_i^2)^2 \right]
$$


Component indices start at zero; $\mathbf{x}$, $a$, $b$, and $f$ are dimensionless.
The first term draws each component toward $a$, and the second draws neighboring component pairs toward the parabola $x_{i+1} = x_i^2$ (the valley floor).
$b$ determines the steepness of the valley walls; standard values are $a = 1$ and $b = 100$.

For $n = 2$, the minimizer is $(a, a^2)$ and the minimum value is zero.
For $a = 1$, $(1, \dots, 1)$ is a minimizer for every $n$.
For $n \ge 3$ and $a \ne 1$, all conditions $x_i = a$ and $x_{i+1} = x_i^2$ cannot hold simultaneously, so the minimum value is positive.

The two terms containing $x_j$ give gradient component $j$ as

$$
\frac{\partial f}{\partial x_j}
= \underbrace{-2(a - x_j) - 4b\,x_j\,(x_{j+1} - x_j^2)}_{j \le n-2 \text{ holds}}
+ \underbrace{2b\,(x_j - x_{j-1}^2)}_{j \ge 1 \text{ holds}}
$$


Each component depends only on its neighbors, so the Hessian $\mathbf{H}$ is tridiagonal:

$$
H_{jj} = \underbrace{2 + 12b\,x_j^2 - 4b\,x_{j+1}}_{j \le n-2 \text{ holds}} + \underbrace{2b}_{j \ge 1 \text{ holds}}, \qquad
H_{j,j+1} = H_{j+1,j} = -4b\,x_j
$$


$a$ does not appear in the Hessian.
This is because the second derivative of $(a - x_j)^2$ is 2 independently of $a$.

The following block contains definitions shared by both cells; `rosenbrock` corresponds to $f$.
Write the function once for `R: Real`; the caller chooses a numeric type such as `f64`, `Dual<f64>`, or `Var` on a tape.
In generic code, place scalars on the right of operators (`-w[0] + a`, `… * b`).

```rust
//| id: ad-rosenbrock-model
//| kind: definitions
//| title: "Generalized Rosenbrock function"
//| crates: [scioxide-ad]
use scioxide_ad::Real;

/// f(x) = Σᵢ [(a − xᵢ)² + b (xᵢ₊₁ − xᵢ²)²]（i = 0, …, n − 2）.
pub(crate) fn rosenbrock<R: Real>(x: &[R], a: f64, b: f64) -> R {
    x.windows(2)
        .map(|w| (-w[0] + a).powi(2) + (w[1] - w[0] * w[0]).powi(2) * b)
        .sum()
}
```

## Three ways to obtain a gradient

Forward mode carries a derivative in one direction alongside each value.
Evaluating with input $x_k + \delta_{kj}\varepsilon$ in `Dual<f64>`, representing the dual number $x + \dot x\,\varepsilon$ ($\varepsilon^2 = 0$), gives $\partial f/\partial x_j$ as the coefficient of $\varepsilon$ in the result.
$\delta_{kj}$ is 1 when $k = j$ and zero otherwise.
This unit vector $\mathbf{e}_j$ is called a seed.
All gradient components require $n$ evaluations; one evaluation of this $f$ costs $O(n)$ operations, giving $O(n^2)$ overall.

Reverse mode records operations on a tape and accumulates adjoints $\bar v = \partial f/\partial v$ in reverse recording order, returning all gradient components in one reverse sweep.
Its cost is a small constant multiple of one function evaluation, and this multiplier is independent of the input count $n$.
`value_and_grad(function, point)` creates a new tape, records the function, performs one reverse sweep, and returns the value and a gradient in `scioxide_linalg::Vector`.
Each call allocates a tape and results; the execution context is fixed to `ExecutionContext::sequential_native()`.

To differentiate the same function at many points, construct a tape with `Tape::<f64>::new(TapeOptions::new())` and repeatedly call `gradient_into(function, point, gradient, cx)`.
It returns the value and writes the gradient to the caller's array `gradient`.
`gradient.len() != point.len()` gives `DimensionMismatch`; failure leaves `gradient` unchanged.
The first recording on an empty tape exceeds capacity but still counts statements.
The tape grows to the counted size and executes the function again, so one call executes the function at most twice.
The one-shot `value_and_grad` uses a new tape each time and executes the function twice on every call.
The function must produce the same recording at the same point (be deterministic).
If the second execution exceeds the size counted by the first, it returns `InvalidInput` (`Inconsistent`).
Once a tape has recorded the same function, subsequent calls perform one recording and one reverse sweep without allocating memory.
`words()` of the `TapeReport` returned by `report()` is the previous recording's statement-word count, including constant and input words.
For this function, every operation statement occupies one word.
`recorded_twice()` indicates whether the previous call grew the tape and recorded again.

Pass the tape a closure satisfying `for<'t> Fn(&[Var<'t, f64>]) -> Result<Var<'t, f64>, SciOxideError>`, written directly in the call's argument position.
Binding it with `let` before passing it prevents inference of this higher-ranked lifetime bound and fails compilation.

Every wrapper takes its value from its inner type (`Primal`), so values of $f$ are bitwise equal when evaluated with `f64`, `Dual`, or a tape.
For a single operation, reverse-mode derivatives are bitwise equal to derivatives from `Dual`.
Exceptions are exact zeros becoming $+0$ and rules using IEEE multiplication where an infinite partial derivative multiplies a zero tangent (`Dual` gives NaN while the tape gives a finite value).
In long recordings, accumulation order for adjoint contributions differs from forward evaluation, so the two agree within rounding error.
None of these modes has truncation error; differences from closed forms result from a few roundings per component.
[Forward mode and dual numbers](../../algorithms/forward-mode/) and [Reverse mode and tapes](../../algorithms/reverse-mode-and-replay/) cover mode rules; [Tape lifecycle and reuse](../../algorithms/tape-lifecycle/) covers tape capacity and reuse.

The next cell obtains the gradient at $\mathbf{x} = (p, q, p, q, \dots)$ in three ways and compares it with the closed-form gradient.
Inputs are dimension $n$ (2–64), coefficients $a$ and $b$, and evaluation-point components $p$ and $q$.
The defaults $n = 2$ and $(p, q) = (-1.2, 1)$ are the standard initial point for the Rosenbrock function.
`counted` counts function executions, shown for each method in the table's second column.
The chart reuses the tape from the second call onward and plots $\lVert\nabla f\rVert_\infty$ on a logarithmic axis along a section moving the even-indexed components through 161 points in $p \in [-2, 2]$.
The first table shows each method's execution count, value $f$, and difference $\lVert\Delta\nabla f\rVert_\infty$ from the closed form.
The second shows gradient magnitude, tape word count, whether the first call recorded again, growth in preallocated bytes over the section's 161 points, and the number of zero-gradient points excluded from the chart.
The checks are that differences from closed forms are at the rounding-error level, values of $f$ are mode-independent, and calls after the first execute the function once without growing preallocation.

            even_component
        } else {
            odd_component

## Valley-floor Hessian and curvature

Now restrict attention to $f(x, y) = (a - x)^2 + b\,(y - x^2)^2$ with $n = 2$ and examine curvature at the point $(t, t^2)$ on the valley floor $y = x^2$.
Setting $n = 2$ and $y = x^2$ in the tridiagonal formulas above gives

$$
\mathbf{H}(t, t^2) = \begin{bmatrix} 2 + 8b\,t^2 & -4b\,t \\ -4b\,t & 2b \end{bmatrix}, \qquad
\det\mathbf{H} = 4b, \qquad
\tau = \operatorname{tr}\mathbf{H} = 2 + 2b + 8b\,t^2
$$

with determinant $4b$ everywhere on the valley floor.
The eigenvalues are

$$
\lambda_\pm = \frac{\tau \pm \sqrt{\tau^2 - 16b}}{2}, \qquad \lambda_- = \frac{4b}{\lambda_+}
$$

where the smaller one is computed in the right-hand form to avoid cancellation.
For large $b$, $\lambda_+ \approx \tau$ and $\lambda_- \approx 4b/\tau$ give the condition-number approximation $\kappa \approx \tau^2/(4b) \approx b\,(1 + 4t^2)^2$ for $\kappa = \lambda_+/\lambda_-$.

From $\mathbf{H}$ above, curvatures (second directional derivatives) in the unit tangent direction $\mathbf{d} = (1, 2t)/\sqrt{1 + 4t^2}$ and unit normal direction $\mathbf{m} = (-2t, 1)/\sqrt{1 + 4t^2}$ of the valley floor are

$$
\mathbf{d}^\mathsf{T}\mathbf{H}\,\mathbf{d} = \frac{2}{1 + 4t^2}, \qquad
\mathbf{m}^\mathsf{T}\mathbf{H}\,\mathbf{m} = \frac{8t^2}{1 + 4t^2} + 2b\,(1 + 4t^2)
$$


Curvature along the valley is independent of $b$, while curvature across it grows proportionally to $b$.
The Rayleigh quotient $\mathbf{u}^\mathsf{T}\mathbf{H}\mathbf{u}$ of a unit vector $\mathbf{u}$ lies between a symmetric matrix's minimum and maximum eigenvalues, so $\lambda_- \le \mathbf{d}^\mathsf{T}\mathbf{H}\mathbf{d}$ and $\mathbf{m}^\mathsf{T}\mathbf{H}\mathbf{m} \le \lambda_+$.
Since $\mathbf{d}$ and $\mathbf{m}$ are orthonormal, the sum of the two curvatures equals $\operatorname{tr}\mathbf{H} = \lambda_+ + \lambda_-$.
Their product is $4b + 16t^2/(1 + 4t^2)^2$, close to $\lambda_+\lambda_- = \det\mathbf{H} = 4b$ when $b$ is large.
Equal sums and similar products give $\lambda_- \approx \mathbf{d}^\mathsf{T}\mathbf{H}\mathbf{d}$ and $\lambda_+ \approx \mathbf{m}^\mathsf{T}\mathbf{H}\mathbf{m}$ for large $b$, with eigenvectors nearly aligned with the valley's tangent and normal.

The condition number expresses the slow progress of gradient methods.
Approximating $f$ quadratically near the minimizer and applying steepest descent with exact line search gives a worst-case per-iteration contraction factor $\bigl((\kappa - 1)/(\kappa + 1)\bigr)^2$ for $f - f^*$.
At the minimizer $t = 1$ with $b = 100$ and $\kappa \approx 2508$, this factor is about $0.9984$, requiring about 1440 iterations to reduce $f - f^*$ by one order of magnitude.

`hessian(function, point)` returns the dense Hessian as a row-major `scioxide_linalg::Matrix`.
It records the function once per unit direction $\mathbf{e}_j$ on the dual-number tape `Tape<Dual<f64>>` and obtains column $j$, $\mathbf{H}\mathbf{e}_j$, by a reverse sweep (forward-over-reverse).
The cost is $n$ times a small constant multiple of a gradient computation.
A new tape is used on every call, adding one initial execution to count statements for $n + 1$ function executions in total.
The function type is `for<'t> Fn(&[Var<'t, Dual<f64>>]) -> Result<Var<'t, Dual<f64>>, SciOxideError>`, so generic `rosenbrock` can be used directly.
[Hessians and Hessian–vector products](../hessian-vector-product/) and [Second derivatives and Hessian operators](../../algorithms/second-order-derivatives/) cover Hessians and vector products in detail.

$H_{01}$ and $H_{10}$ come from separate recordings and can generally differ by rounding.
Eigenvalues use scioxide-linalg's `HermitianEigenvaluesResult::compute` with input interpreted as `HermitianInput::Projected(HermitianProjectionPolicy::Always)` to use $(\mathbf{H} + \mathbf{H}^\mathsf{T})/2$.
Eigenvalues are sorted in ascending order.
A backward-stable symmetric eigensolver has error on the order of $\varepsilon\lVert\mathbf{H}\rVert_2 = \varepsilon\lambda_+$, so relative error of $\lambda_-$ can grow to the order of $\varepsilon\kappa$.
This reflects poor conditioning of the small eigenvalue, rather than AD error ([Floating-point numbers and conditioning](../../../concepts/floating-point-and-conditioning/)).

The table shows quantities and relative differences at the selected $t$.
AD directional curvatures are computed from AD entries and tangent $(1, 2t)$ and normal $(-2t, 1)$.
The checks are that entries and directional curvatures agree with closed forms and the relative difference in $\lambda_-$ lies within $\varepsilon\kappa$.

use scioxide_ad::hessian;
use scioxide_linalg::{HermitianEigenvaluesResult, HermitianInput, HermitianProjectionPolicy};

let b = valley;
// AD Hessian (row-major) and scioxide-linalg eigenvalues λ₋ ≤ λ₊. Use a = 1 because a does not appear in the Hessian.
let curvature = |t: f64| -> Result<([f64; 4], f64, f64), String> {
    let h = hessian(|x| Ok(rosenbrock(x, 1.0, b)), &[t, t * t]).map_err(|e| e.to_string())?;
    let values = HermitianEigenvaluesResult::compute(
        &h,
        HermitianInput::Projected(HermitianProjectionPolicy::Always),
    )
    .map_err(|e| e.to_string())?;
    let entries = <[f64; 4]>::try_from(h.as_slice()).map_err(|_| "Not 2×2".to_string())?;
    Ok((entries, values.eigenvalues()[0], values.eigenvalues()[1]))
};
// Independent check: valley-floor closed forms (f64 arithmetic and inherent sqrt). τ = 2 + 2b + 8bt², det H = 4b.
let along = |t: f64| 2.0 / (1.0 + 4.0 * t * t);
let across = |t: f64| 8.0 * t * t / (1.0 + 4.0 * t * t) + 2.0 * b * (1.0 + 4.0 * t * t);
let eigen = |t: f64| {
    let trace = 2.0 + 2.0 * b + 8.0 * b * t * t;
    let large = 0.5 * (trace + (trace * trace - 16.0 * b).sqrt());
    (4.0 * b / large, large)
};

let mut large_points = Vec::new();
let mut small_points = Vec::new();
let mut along_curve = Vec::new();
let mut across_curve = Vec::new();
for i in 0..=60 {

    let (_, small, large) = curvature(t)?;
    large_points.push([t, large]);
    small_points.push([t, small]);
    along_curve.push([t, along(t)]);
    across_curve.push([t, across(t)]);
}

    })

let t = position;
let (h, small, large) = curvature(t)?;
let (exact_small, exact_large) = eigen(t);
let exact_h = [2.0 + 8.0 * b * t * t, -4.0 * b * t, -4.0 * b * t, 2.0 * b];
// Compute tangent (1, 2t) and normal (−2t, 1) curvatures from AD entries and divide by squared length 1 + 4t².
let stretch = 1.0 + 4.0 * t * t;
let off = 0.5 * (h[1] + h[2]);
let along_ad = (h[0] + 4.0 * t * off + 4.0 * t * t * h[3]) / stretch;
let across_ad = (4.0 * t * t * h[0] - 4.0 * t * off + h[3]) / stretch;
let relative = |ad: f64, exact: f64| (exact != 0.0).then(|| (ad - exact).abs() / exact.abs());
let rows: Vec<(&str, f64, f64, Option<f64>)> = [
    ("H₀₀", h[0], exact_h[0]),
    ("H₀₁", h[1], exact_h[1]),
    ("H₁₀", h[2], exact_h[2]),
    ("H₁₁", h[3], exact_h[3]),
    ("λ₊", large, exact_large),
    ("λ₋", small, exact_small),
    ("κ = λ₊/λ₋", large / small, exact_large / exact_small),
    ("Curvature along valley dᵀHd", along_ad, along(t)),
    ("Curvature across valley mᵀHm", across_ad, across(t)),
]
.into_iter()
.map(|(name, ad, exact)| (name, ad, exact, relative(ad, exact)))
.collect();

At the defaults $b = 100$ and $t = 1$, entries from `hessian` agree with closed forms $H_{00} = 802$, $H_{01} = H_{10} = -400$, and $H_{11} = 200$, and both off-diagonal entries are bitwise equal.
Eigenvalues are $\lambda_+ = 1001.6006$ and $\lambda_- = 0.39936$, and the condition number is $\kappa = 2508.0$.
The relative difference in $\lambda_-$ is $4.0 \times 10^{-14}$, within $\varepsilon\kappa = 5.6 \times 10^{-13}$.
Curvature along the valley is $0.4$ and across it $1001.6$, close to $\lambda_-$ and $\lambda_+$ respectively, and satisfying the Rayleigh-quotient inequalities $\lambda_- \le 0.4$ and $1001.6 \le \lambda_+$.

In the chart, $\lambda_+$ symbols nearly overlap the dashed cross-valley curvature, while $\lambda_-$ symbols nearly overlap the dashed along-valley curvature.
At $t = \pm 1.5$, $\lambda_+ = 2001.8$ and $\lambda_- = 0.1998$; the condition number varies with valley-floor position from 100 at $t = 0$ to about $10^4$.
At $t = 0$, $\mathbf{H} = \operatorname{diag}(2, 2b)$, so eigenvalues equal the two directional curvatures and $\kappa = b = 100$.
Off-diagonal entries are zero at this point, so the table leaves their relative difference undefined.

At $b = 1000$ and $t = 1.5$, $\kappa = 1.0002 \times 10^5$, close to the approximation $b(1 + 4t^2)^2 = 10^5$.
Entries and directional curvatures still agree with closed forms, but the relative difference in $\lambda_-$ grows to $6.3 \times 10^{-13}$, within $\varepsilon\kappa = 2.2 \times 10^{-11}$.
Since entries agree with closed forms, this difference arises from computing the small eigenvalue on the scale of $\lVert\mathbf{H}\rVert_2$.

## Summary

`Dual` returns one partial derivative per forward evaluation with seed $\mathbf{e}_j$, so a gradient requires $n$ evaluations.
Reverse mode returns the gradient with one recording and one reverse sweep independently of $n$; at the defaults, all three methods agree with closed forms to one ulp of the largest component.
For differentiating the same function at many points, create one tape and repeat `gradient_into`; from the second call onward, the function executes once and no memory is allocated.
The valley-floor Hessian from `hessian` matches the closed form; the ratio between along-valley curvature $2/(1 + 4t^2)$ and cross-valley curvature $\approx 2b(1 + 4t^2)$ determines the condition number $\kappa \approx b(1 + 4t^2)^2$.
Relative error in small eigenvalues can grow to the order of $\varepsilon\kappa$; interpret it separately from AD accuracy.
