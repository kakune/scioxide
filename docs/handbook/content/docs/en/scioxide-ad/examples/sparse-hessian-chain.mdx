In lattice vibrations, discretized field energies, and molecular force fields, each variable interacts only with nearby variables.
Most Hessian entries are then zero regardless of the evaluation point, and the nonzero count grows only in proportion to the number of variables $n$.
Knowing the nonzero positions (the structure) allows every nonzero to be read from Hessian–vector products (HVPs) in a few directions that group columns having no nonzeros in a common row.
Using a nonlinear atomic chain, this example determines the structure from a `scioxide-ad` tape, groups directions by column coloring to recover the Hessian, and compares it with dense computation.

## Atomic-chain energy and Hessian

Arrange $n$ atoms on a straight line, with displacements $x_0, \dots, x_{n-1}$ [m] from equilibrium.
Pairs of atoms separated by $d$ ($d = 1, \dots, r$) are connected by springs, with energy for an extension $s$ [m] defined by

$$
V_d(s) = \frac{k_d}{2} s^2 + \frac{\beta_d}{4} s^4, \qquad k_d = \frac{k}{d^2}, \quad \beta_d = \frac{\beta}{d^2}
$$


Here $k$ [N/m] is the linear spring constant and $\beta$ [N/m³] the quartic nonlinearity coefficient; $r = 1$ corresponds to the Fermi–Pasta–Ulam–Tsingou β model.
Atoms outside the chain are fixed: set $x_j = 0$ for $j < 0$ and $j \ge n$.
The total energy [J] is

$$
E(\boldsymbol{x}) = \sum_{d=1}^{r} \sum_{i=-d}^{n-1} V_d(x_{i+d} - x_i)
$$


For a spring $(p, q)$ ($q = p + d$) with extension $s = x_q - x_p$, its curvature is $\kappa = V_d''(s) = k_d + 3\beta_d s^2$.
The spring adds $\kappa\,(\boldsymbol{e}_q - \boldsymbol{e}_p)(\boldsymbol{e}_q - \boldsymbol{e}_p)^\mathsf{T}$ to the Hessian, giving, for indices inside the chain,

$$
H_{pp} \mathrel{+}= \kappa, \qquad H_{qq} \mathrel{+}= \kappa, \qquad H_{pq} = H_{qp} = -\kappa
$$

where $\boldsymbol{e}_j$ is the $j$th unit vector.
Entries with $|i - j| > r$ are zero regardless of the evaluation point, so the Hessian is banded with half-bandwidth $r$.
The number of structural nonzeros is

$$
\mathrm{nnz} = n + 2\sum_{d=1}^{r} (n - d) = (2r + 1)\,n - r(r + 1)
$$

for $n \ge r$; this is small compared with $n^2$ when $n$ is much larger than $r$.
Only the $3\beta_d s^2$ part of each nonzero depends on the evaluation point; when $\beta = 0$, the Hessian is constant.

## Structurally orthogonal columns and coloring

Two columns are structurally orthogonal when they have no nonzeros in a common row.
Partition the columns into colors $0, \dots, p - 1$ so that columns of the same color are mutually structurally orthogonal.
Let $\boldsymbol{d}_c = \sum_{\mathrm{color}(j) = c} \boldsymbol{e}_j$ be the sum of unit vectors for columns of color $c$; at most one column of color $c$ has a nonzero in row $i$, so denoting that column by $j$ gives

$$
(H \boldsymbol{d}_c)_i = H_{ij}
$$


Thus, computing one HVP $H\boldsymbol{d}_c$ per color lets each nonzero $H_{ij}$ be read directly from entry $i$ of the HVP for column $j$'s color.
This is called direct recovery because it solves no simultaneous equations.
This coloring is the Curtis–Powell–Reid column compression; [Sparse structure and column coloring](../../../scioxide-core/algorithms/sparse-structure-and-coloring/) covers the mathematics of Jacobian column coloring.

Every nonzero in one row needs a different color, so the number of colors cannot be smaller than the maximum number of nonzeros per row.
For a band with half-bandwidth $r$ and $n \ge 2r + 1$, rows $r, \dots, n - 1 - r$ have $2r + 1$ nonzeros, giving a lower bound of $2r + 1$ colors.
Columns $j$ and $l$ have nonzeros in a common row when $|j - l| \le 2r$.
`scioxide_sparse::derivative_coloring` is a greedy method that visits columns in increasing index order and assigns the smallest color not already used by a conflicting colored column.
For a band matrix, this gives exactly $\mathrm{color}(j) = j \bmod (2r + 1)$ and attains the lower bound.
For general structures, the greedy method does not guarantee the minimum color count, and the count also depends on column order.
This recovery does not use the Hessian symmetry $H_{ij} = H_{ji}$.
Methods exploiting symmetry, such as star coloring, can reduce the color count for general structures, but `scioxide-ad`'s sparse Hessian implementation does not provide them.

Each HVP uses forward-over-reverse with dual numbers `Dual<f64>` on the tape.
Record the function with variables $\mathrm{Dual}(x_i, (\boldsymbol{d}_c)_i)$; one reverse sweep gives the gradient $\nabla E$ in the value component and $H\boldsymbol{d}_c$ in the tangent component ([Second derivatives and Hessian operators](../../algorithms/second-order-derivatives/)).
A dense Hessian records once per unit-vector direction, $n$ times in total; colored recovery needs only one recording per color, $2r + 1$ in total, independently of $n$.

## Procedure in scioxide-ad

Recovery has three stages.

1. Record the function once with `Tape::<f64>::linearize` and determine the structure with `Linearization::hessian_pattern`.
   The recorded statements determine the structure independently of the evaluation-point values.
   Propagate the set of input dependencies of each value forward, and treat pairs of argument sets at nonlinear statements as Hessian nonzeros (Walther's nonlinear interaction domains).
   Linear statements such as $x + y$ and $c\,x$ create no interactions; the product $x \cdot y$ creates only pairs between its two argument sets, while a nonlinear unary function such as `exp` creates all pairs within its argument set.
   The structure is valid at evaluation points following the same branches; an output count other than exactly one produces `DimensionMismatch`.
2. Pass a view of the structure (`pattern.view()`) to `scioxide_sparse::derivative_coloring` to obtain a column coloring `ColoringSchedule`.
   The schedule owns a copy of the structure and returns the columns per color (`groups()`), the color per column (`colors()`), and the color count (`color_count()`).
3. Compute the nonzero values with `Tape::<Dual<f64>>::sparse_hessian_into(function, point, &coloring, &mut values, cx)`.
   `values` has length equal to the structural nonzero count, and values follow the structure's CSR order.
   The function is recorded once per color.
   A structure other than $n \times n$ or a `values` length differing from the nonzero count produces `DimensionMismatch`; recording failures use the same errors as `Tape::gradient_into`.
   Failure leaves `values` unchanged.

A new tape has no capacity, so the first execution only counts statements without saving a recording.
The transformation expands the tape to the counted size and executes the function again; the first call therefore executes the function once more than the color count, and the function must be deterministic ([Tape lifecycle and reuse](../../algorithms/tape-lifecycle/)).
On a tape with sufficient capacity from recording the same function, subsequent calls perform only as many recordings as there are colors and allocate no memory.
The one-shot `hessian` used for comparison creates a new tape on each call, records once per unit direction, and allocates and returns a dense matrix.

The following block defines the model shared by the two cells.
`chain_energy` implements $E(\boldsymbol{x})$ once for the numeric type `R: Real`, with `range` corresponding to $r$, `stiffness` to $k$, and `quartic` to $\beta$.
The exterior displacements $x_j = 0$ are represented by the passive constant `R::zero()`.
`chain_hessian` is the closed-form Hessian (row-major $n \times n$), summing the curvature $\kappa$ of each spring as an independent check without automatic differentiation.

```rust
//| id: ad-sparse-hessian-chain-model
//| kind: definitions
//| title: "Energy and closed-form Hessian of a nonlinear atomic chain coupled through rth neighbors"
//| crates: [scioxide-ad]
use scioxide_ad::Real;

/// Chain energy E(x) [J]. Set displacements outside the chain (j < 0, j ≥ n) to 0.
pub(crate) fn chain_energy<R: Real>(x: &[R], range: usize, stiffness: f64, quartic: f64) -> R {
    let n = x.len() as isize;
    let at = |j: isize| {
        if (0..n).contains(&j) {
            x[j as usize]
        } else {
            R::zero()
        }
    };
    let mut energy = R::zero();
    for d in 1..=range as isize {
        let scale = 1.0 / (d * d) as f64;
        for i in -d..n {
            // Extension s of spring (i, i + d) and V_d(s) = k_d s²/2 + β_d s⁴/4.
            let s = at(i + d) - at(i);
            let s2 = s * s;
            energy += s2 * (0.5 * stiffness * scale) + s2 * s2 * (0.25 * quartic * scale);
        }
    }
    energy
}

/// Closed-form Hessian [N/m] (row-major n × n). Add curvature κ = k_d + 3β_d s² per spring.
pub(crate) fn chain_hessian(x: &[f64], range: usize, stiffness: f64, quartic: f64) -> Vec<f64> {
    let n = x.len() as isize;
    let inside = |j: isize| (0..n).contains(&j);
    let at = |j: isize| if inside(j) { x[j as usize] } else { 0.0 };
    let mut hessian = vec![0.0; x.len() * x.len()];
    for d in 1..=range as isize {
        let scale = 1.0 / (d * d) as f64;
        for p in -d..n {
            let q = p + d;
            let s = at(q) - at(p);
            let curvature = (stiffness + 3.0 * quartic * s * s) * scale;
            for (row, column, sign) in [(p, p, 1.0), (q, q, 1.0), (p, q, -1.0), (q, p, -1.0)] {
                if inside(row) && inside(column) {
                    hessian[(row * n + column) as usize] += sign * curvature;
                }
            }
        }
    }
    hessian
}
```

## Dimension dependence of structure and color count

The following cell selects the interaction range $r$ (an integer from 1 to 3), records each chain of size $n = 8, 16, \dots, 256$ once with `Tape::<f64>::linearize`, and obtains the structure with `hessian_pattern` and color count with `derivative_coloring`.
Since the structure is independent of values, recording uses just one point with $k = 1$ N/m, $\beta = 1$ N/m³, and displacement $x_i = \sin(\pi (i + 1)/(n + 1))$ m.
Reuse one tape in increasing order of $n$, expanding it to the recording size whenever $n$ increases (the expanded tape has the same storage as a new tape of that size; see [Tape lifecycle and reuse](../../algorithms/tape-lifecycle/)).
The table compares the structural nonzero count with the closed form $(2r + 1)n - r(r + 1)$, checks whether each row's columns exactly match the band $|i - j| \le r$, shows the color count and lower bound $2r + 1$, and checks whether the colors match $j \bmod (2r + 1)$.
The graph compares HVP counts (function recordings): the color count for colored recovery and $n$ directions for a dense Hessian.

For $r = 1$, the structural nonzero count matches the closed form $3n - 2$ from 22 at $n = 8$ to 766 at $n = 256$, and every row's columns match the tridiagonal band exactly.
`hessian_pattern` determines the structure from statement types without examining values; for this chain, it includes neither extra nor missing positions.
The color count is 3 for every $n$, equal to the lower bound, with colors ordered as $j \bmod 3$.
The dashed graph line ($n$ directions for a dense Hessian) grows in proportion to $n$, while the number of colored directions remains horizontal.

Setting $r = 3$ gives 7 diagonals, $7n - 12$ nonzeros (1780 at $n = 256$), and 7 colors.
The band width alone determines the color count, which is unchanged when $n$ increases by a factor of 32.
A dense Hessian at $n = 256$ has 65536 entries and needs 256 recordings, while colored recovery obtains 1780 nonzeros with 7 recordings.

## Recovering values and counting recordings

The following cell selects the atom count $n$, interaction range $r$, quartic coefficient $\beta$, and displacement amplitude $A$, sets $k = 1$ N/m, and recovers the Hessian at $x_i = A \sin(\pi (i + 1)/(n + 1))$ [m].
This displacement has the shape of the lowest normal mode of a linear chain fixed at both ends with nearest-neighbor coupling only ($r = 1$, $\beta = 0$).
The procedure follows the three stages in the previous section; the closure passed to `sparse_hessian_into` counts calls with `Cell`.
It then repeats recovery at $\boldsymbol{x} = \boldsymbol{0}$ using the same tape and coloring.
The Hessian at $\boldsymbol{x} = \boldsymbol{0}$ is the linear chain's stiffness matrix, with no contribution from the quartic term.
For comparison, it computes a dense Hessian with the one-shot `hessian`, again counting function executions.

## Summary

For a function with only local variable interactions, determine its Hessian structure with `hessian_pattern` from one `Tape::linearize` recording, then color columns with `scioxide_sparse::derivative_coloring` to recover the Hessian using as many HVPs as there are colors.
For a band with half-bandwidth $r$, the color count equals the lower bound $2r + 1$ independently of the atom count $n$, reducing recordings from $n$ for a dense Hessian to $2r + 1$.
`Tape::<Dual<f64>>::sparse_hessian_into` writes values in the structure's CSR order and executes the function once more on a new tape, so the function must be deterministic.
For repeated evaluation at different points, reuse the structure, coloring, tape, and value array, and call only `sparse_hessian_into`.
The structure is valid only at evaluation points following the same branches, so functions containing branches need their structure recomputed per branch.
