Sparse matrix reordering, grid counting, and uniform sampling require exact factorials and binomial coefficients, lexicographic combination enumeration, and conversion between combinations and their sequential indices (ranks).
Combinatorial functions in `scioxide-core` compute exactly in `usize` integers and return `SizeOverflow` if the result does not fit `usize`.
They never return wrapped overflow values or rounded results.
Indices and ranks start at zero; enumeration and ranking use lexicographic order.

## Exact counting functions

| Function | Value | Complexity | Notes |
|---|---|---|---|
| `checked_factorial(n)` | $n!$ | $O(n)$ | $0! = 1$ |
| `checked_double_factorial(n)` | $n!! = n(n-2)(n-4)\cdots$ | $O(n)$ | $0!! = 1!! = 1$ |
| `checked_multifactorial(n, step)` | $n(n - s)(n - 2s)\cdots$ (stopping before a factor below 2) | $O(\lceil n/s \rceil)$ | `InvalidInput` if `step` is zero |
| `checked_rising_factorial(a, n)` | $a(a+1)\cdots(a+n-1)$ | $O(n)$ | The empty product ($n = 0$) is 1 |
| `checked_binomial(n, k)` | $C(n, k) = n!/(k!\,(n-k)!)$ | $O(\min(k, n-k))$ | Zero when $k > n$ |
| `checked_permutation_count(n, k)` | $n!/(n-k)!$ | $O(k)$ | Zero when $k > n$ |
| `checked_multiset_count(n, k)` | $C(n + k - 1, k)$ | $O(\min(k, n-1))$ | Choose $k$ items from $n$ kinds with repetition |
| `checked_stirling_first_kind(n, k)` | Signed first kind $s(n, k)$ | $k\,(n - k + 1)$ cells | Result is `isize` |
| `checked_stirling_second_kind(n, k)` | Second kind $S(n, k)$ | $k\,(n - k + 1)$ cells | Result is `usize` |

Binomial coefficients first replace $k$ with the smaller value through $C(n, k) = C(n, n - k)$, then update using $C(n - k + i,\, i) = C(n - k + i - 1,\, i - 1)\,(n - k + i) / i$ in $i = 1, \ldots, k$ order.
Cancellation by the greatest common divisor of $n - k + i$ and $i$ before multiplication keeps intermediate values no larger than the final result.
Thus `SizeOverflow` occurs only when $C(n, k)$ itself does not fit `usize`.

### Stirling numbers

The Stirling number of the second kind $S(n, k)$ counts partitions of $n$ elements into $k$ nonempty sets.
The unsigned Stirling number of the first kind $c(n, k)$ counts permutations of $n$ elements having exactly $k$ cycles; its signed value is $s(n, k) = (-1)^{n-k}\, c(n, k)$.
Both satisfy $S(0, 0) = s(0, 0) = 1$ and equal zero when $k > n$ or $k = 0 < n$.
The recurrences

$$
S(n, k) = k\,S(n-1, k) + S(n-1, k-1), \qquad c(n, k) = (n-1)\,c(n-1, k) + c(n-1, k-1)
$$

compute values by updating one row at a time in $n$.
For the first kind, compute the absolute value $c(n, k)$, then apply sign $(-1)^{n-k}$ at the end.

The functions allocate only one row of length $k + 1$ and update only cells contributing to the requested cell $(n, k)$.
There are $k\,(n - k + 1)$ updated cells, each requiring one checked multiplication and addition.
Skipping noncontributing columns prevents overflow in other columns from rejecting a representable answer.
Callers wishing to limit work compare $k\,(n - k + 1)$ with their own limit before calling.
An unrepresentable result or intermediate returns `SizeOverflow`; failure to allocate the row returns `AllocationFailure`.

### Limits from `usize` width

The result range depends on the bit width of `usize`.

- In a 64-bit environment, $20! \approx 2.43 \times 10^{18} < 2^{64} - 1 < 21!$, so values through $20!$ can be computed.
- In wasm32, `usize` is 32 bits and $12! = 479{,}001{,}600 < 2^{32} - 1 = 4{,}294{,}967{,}295 < 13! = 6{,}227{,}020{,}800$.
  Handbook cells run in browser wasm32, so $13!$ and larger produce `SizeOverflow`.

The following cell computes four quantities for integer $n$ (0–14) with SciOxide functions and displays independently computed reference values.

- $n!$.
  Its reference is a product in `u64`.
- The binomial row sum $\sum_k C(n, k)$.
  Its reference is $2^n$.
- The row sum of second-kind Stirling numbers $\sum_k S(n, k)$.
  This equals the total number of partitions of $n$ elements, the Bell number $B_n$.
  Compute the reference with Bell's triangle, without Stirling numbers.
- The row sum of absolute values of first-kind Stirling numbers $\sum_k c(n, k)$.
  Every permutation has one definite cycle count, so this equals the total permutation count $n!$.

Intermediate sums also use checked addition; quantities exceeding `usize` display "Exceeds usize."
The second table shows the environment's `usize` bit width and the largest $n$ for which `checked_factorial(n)` succeeds.

```rust
let n = n_val as usize;
// Treat SizeOverflow as an unrepresentable usize value, represented by None; return other errors as execution failures.
let representable = |value: Result<usize, SciOxideError>| match value {
    Ok(count) => Ok(Some(count)),
    Err(error) if matches!(error.kind(), SciOxideErrorKind::SizeOverflow) => Ok(None),
    Err(error) => Err(error.to_string()),
};
// Check overflow during summation with checked_add as well.
let add = |sum: Option<usize>, term: Option<usize>| {
    sum.zip(term)
        .and_then(|(total, count)| total.checked_add(count))
};

let mut bell = Some(0_usize);
let mut cycles = Some(0_usize);
for k in 0..=n {
    binomial_sum = add(binomial_sum, representable(checked_binomial(n, k))?);
    bell = add(bell, representable(checked_stirling_second_kind(n, k))?);
    // Sum c(n, k), the absolute values of signed s(n, k).

// Bell's triangle: each row starts with the previous row's final entry, then adds its left neighbor and the previous row's value.
let mut row = vec![1_u64];
for _ in 0..n {
    let mut next = vec![row[row.len() - 1]];
    for &value in &row {
        next.push(next[next.len() - 1] + value);
    }
    row = next;
}

]);

    vec![

        ("Σ S(n, k) (reference: Bell number)", widen(bell), bell_reference),

            "Σ c(n, k) (reference: n!)",
            widen(cycles),
            factorial_reference

);

    .last();

    { "key": "0", "label": "usize width [bit]", "type": "integer" },
    { "key": "1", "label": "Largest n with n! fitting usize", "type": "integer" }
]);
```

At the default $n = 5$, the values are $5! = 120$, $\sum_k C(5, k) = 2^5 = 32$, $B_5 = 52$, and $\sum_k c(5, k) = 120$; all four match their references.
At $n = 0$, both the empty product and the partition of the empty set have one possibility, so all four quantities are 1.
At $n = 12$, $12! = 479{,}001{,}600$ and $B_{12} = 4{,}213{,}597$ still fit a 32-bit `usize`.

In the browser, setting $n$ to at least 13 makes $n!$ and $\sum_k c(n, k)$ display "Exceeds usize."
For the latter, even if individual $c(13, k)$ values fit 32 bits, `checked_add` detects overflow as the sum approaches $13!$.
$2^n$ and the Bell number still fit 32 bits at $n = 14$ ($B_{14} = 190{,}899{,}322$).
The second table's largest $n$ is 12 in the browser and 20 in native 64-bit environments.

## Lexicographic enumeration and ranking

Represent combinations choosing $k$ items from $\{0, \ldots, n-1\}$ by ascending indices $c_0 < c_1 < \cdots < c_{k-1}$; there are $C(n, k)$ in lexicographic order.

### Enumerators

`CombinationEnumerator::first_into(n, storage)` writes the first combination $(0, 1, \ldots, k-1)$ into caller storage ($k$ is the storage length).
`first(n, k)` does the same while allocating storage.
Both return `InvalidInput` when $k > n$.
`advance()` advances to the next combination.
Starting from the right, find position $i$ below its upper bound $n - k + i$, increment it, then reset subsequent entries to consecutive values; each step costs $O(k)$.
At the final combination, return `false` without modifying state.
`indices()` returns the current combination, `reset()` resets to the first, and `into_inner()` returns storage.

`MultisetEnumerator` similarly enumerates combinations with repetition using nondecreasing indices $c_0 \le c_1 \le \cdots \le c_{k-1}$.
`PermutationEnumerator` enumerates permutations of $0, \ldots, n-1$, starting from the identity through `identity(n)` (which allocates storage) or `identity_into(storage)`.
The next permutation uses Narayana's algorithm.
Find the rightmost ascending pair $p_i < p_{i+1}$, swap $p_i$ with the rightmost element to its right larger than $p_i$, then reverse everything right of position $i$.
A step costs $O(1)$ on average over full enumeration and $O(n)$ in the worst case.
When resuming from existing state, `new` rejects invalid state as `InvalidInput` without changing it.
`PermutationEnumerator::new` also takes `scratch` of $\lceil n/8 \rceil$ bytes for validation, returning `DimensionMismatch` if it is too short.

### Ranking and unranking

A combination's rank is its zero-based sequential index in lexicographic order.
With indices before position $i$ fixed, combinations selecting a smaller value $v$ ($s_i \le v < c_i$) than $c_i$ at position $i$ all precede $\mathbf{c}$.
Here $s_i$ is the smallest value allowed at position $i$, with $s_0 = 0$ and $s_{i+1} = c_i + 1$.
The remaining $k - i - 1$ elements are chosen from $n - v - 1$ elements greater than $v$, giving $C(n - v - 1, k - i - 1)$ combinations.
Summing over $v$ and applying the binomial sum formula (the hockey-stick identity) $\sum_{v=s}^{c-1} C(n - v - 1,\, r - 1) = C(n - s,\, r) - C(n - c,\, r)$ gives

$$
\mathrm{rank}(\mathbf{c}) = \sum_{i=0}^{k-1} \left[ C(n - s_i,\, k - i) - C(n - c_i,\, k - i) \right]
$$


Expressing ranks as sums of binomial coefficients applies the same counting principle as the combinatorial number system to lexicographic order.

`combination_rank(n, &c)` computes this sum with $O(k^2)$ integer arithmetic.
Out-of-range or nonascending indices are rejected as `InvalidInput`; $C(n, k)$ exceeding `usize` produces `SizeOverflow`.
The inverse `combination_unrank_into(n, rank, &mut out)` uses binary search at each position to find the largest $v$ whose skipped combination count $C(n - s_i, k - i) - C(n - v, k - i)$ does not exceed the remaining rank, subtracts that count, and proceeds.
It costs $O(k^2 \log(n+1))$ and rejects out-of-range ranks as `OutOfBounds` before modifying output.

Combinations with repetition (`multiset_rank`, `multiset_unrank_into`) use the same formula after replacing nondecreasing indices $c_i$ with $c_i + i$, a combination from $n + k - 1$ elements.
Permutation ranking and unranking (`permutation_rank`, `permutation_unrank_into`) use Lehmer codes.
The digit at position $i$ counts elements smaller than $c_i$ after $i$; multiplying by weight $(n - 1 - i)!$ and summing gives the rank.
The cost is $O(n^2)$; lengths for which $n!$ exceeds `usize` produce `SizeOverflow`.
None of these functions allocates on the heap.

Ranks and combinations correspond one to one.
Thus uniform random ranks can sample combinations uniformly, or rank intervals can partition work, without constructing an enumeration table.

## Validated permutations

Permutations used in sparse matrix reordering and similar tasks are represented by `Permutation` (owned) and `PermutationView` (borrowed).
`Permutation` holds mappings `new_to_old[new] = old` and `old_to_new[old] = new`, checking at construction that every index in $0, \ldots, n-1$ occurs exactly once.

`Permutation::new(new_to_old)` rejects duplicates or out-of-range indices as `InvalidInput` and constructs the inverse mapping.
`identity(n)`, `inverse()`, and `compose(&other)` use $O(n)$ time and storage.
`compose` produces `new_to_old[i] = other.new_to_old[self.new_to_old[i]]`, equivalent to applying `other` first and `self` afterward to a vector.
`PermutationView::new(map, scratch)` validates borrowed mappings with $O(n)$.
Recording whether each index has appeared uses one bit per index, so `scratch` needs only $\lceil n/8 \rceil$ bytes (`permutation_validation_scratch_bytes(n)`) and is not retained after validation.
A short `scratch` returns `DimensionMismatch`.
`apply_into(input, output)` computes $\mathrm{output}_i = \mathrm{input}_{\mathrm{new\_to\_old}[i]}$; `inverse_into` computes the inverse $\mathrm{output}_{\mathrm{new\_to\_old}[i]} = \mathrm{input}_i$.
Length mismatches are rejected as `DimensionMismatch` without changing output.
Borrowed views also offer allocation-free `inverse_map_into` and `compose_into`.

```rust
// new checks bijectivity and constructs the inverse mapping old_to_new.
let permutation = Permutation::new(map).map_err(|e| e.to_string())?;
let rank = permutation_rank(permutation.as_view()).map_err(|e| e.to_string())?;

let x = [10.0_f64, 20.0, 30.0, 40.0];
let mut permuted = [0.0_f64; 4];
let mut restored = [0.0_f64; 4];
// permuted[i] = x[new_to_old[i]], restored[new_to_old[i]] = permuted[i].
permutation
    .apply_into(&x, &mut permuted)
    .map_err(|e| e.to_string())?;
permutation
    .inverse_into(&permuted, &mut restored)
    .map_err(|e| e.to_string())?;
let change = (0..4).fold(0.0_f64, |worst, i| worst.max((restored[i] - x[i]).abs()));
// Composing a permutation with its inverse gives the identity. Count moved positions.
let inverse = permutation.inverse().map_err(|e| e.to_string())?;
let composed = permutation.compose(&inverse).map_err(|e| e.to_string())?;
let moved = composed
    .new_to_old()
    .iter()
    .enumerate()
    .filter(|&(i, &old)| i != old)
    .count();

let rows: Vec<(usize, usize, usize, f64, f64)> = (0..4)
    .map(|i| {
        let new_to_old = permutation.new_to_old()[i];
        let old_to_new = permutation.old_to_new()[i];
        (i, new_to_old, old_to_new, permuted[i], restored[i])
    })
    .collect();
let fixed0 = serde_json::json!({ "fractionDigits": 0 });
let map_columns = serde_json::json!([
    { "key": "0", "label": "Position i", "type": "integer" },
    { "key": "1", "label": "new_to_old[i]", "type": "integer" },
    { "key": "2", "label": "old_to_new[i]", "type": "integer" },
    { "key": "3", "label": "apply_into output [-]", "type": "number", "format": fixed0 },
    { "key": "4", "label": "Restored value through inverse_into [-]", "type": "number", "format": fixed0 }
]);
emit_table_with_columns!(
    map_columns,
    rows,
    metadata = serde_json::json!({ "id": "maps" })
);
let summary_columns = serde_json::json!([
    { "key": "0", "label": "permutation_rank", "type": "integer" },
    { "key": "1", "label": "Maximum difference between restored values and x [-]", "type": "number", "format": fixed0 },
    { "key": "2", "label": "Positions moved by composing permutation and inverse", "type": "integer" }
]);
emit_table_with_columns!(
    summary_columns,
    vec![(rank, change, moved)],
    metadata = serde_json::json!({ "id": "summary" })
);
```

The default $\rho = 9$ has Lehmer code $(1, 1, 1, 0)$ from $9 = 1 \cdot 3! + 1 \cdot 2! + 1 \cdot 1!$, giving permutation `new_to_old` $= (1, 2, 3, 0)$.
`apply_into` produces $(20, 30, 40, 10)$, gathering the value from original position `new_to_old[i]` into position $i$.
The inverse mapping is `old_to_new` $= (3, 0, 1, 2)$, and `inverse_into` restores $(10, 20, 30, 40)$.
`permutation_rank` returns 9, and composing the permutation with its inverse moves zero positions.
$\rho = 0$ is the identity, and $\rho = 23 = 4! - 1$ is the reverse permutation $(3, 2, 1, 0)$; both round-trip to their original ranks.

## Summary

Compute factorials, binomial coefficients, Stirling numbers, and related quantities exactly within `usize` through `checked_*` functions, receiving `SizeOverflow` on range overflow.
In wasm32, `usize` is 32 bits, so values beyond $12!$ or large $C(n, k)$ exceed the range sooner than in native environments.
To constrain Stirling number work, compare $k\,(n - k + 1)$ with your own limit before calling.
Combinations, combinations with repetition, and permutations can be enumerated lexicographically in caller storage.
Combination ranks use binomial sums in $O(k^2)$; unranking uses per-position binary search in $O(k^2 \log(n+1))$, enabling uniform sampling or work partitioning without enumeration tables.
Permutations check bijectivity at construction; callers provide $\lceil n/8 \rceil$ bytes of workspace to validate borrowed mappings.
