Tolerance choices determine when iteration stops and when a result is accepted.
Absolute tolerance alone does not suit problems whose values span many orders of magnitude, while relative tolerance alone cannot assess values crossing zero.
`scioxide-core` defines a combined threshold as `Tolerance` and provides separate types for each acceptance role.
[Scaling theory for tolerances and residuals](../../../concepts/tolerances-and-residuals/) covers the general concepts; this page covers the types and acceptance rules in `scioxide-core`.

## Thresholds combining absolute and relative terms

Let $y^*$ be the true value, $\hat{y}$ the computed value, and $e = \hat{y} - y^*$ the forward error.
Absolute error $|e|$ has the same units as $y$, while relative error $|e| / |y^*|$ is dimensionless.
`Tolerance` combines the two in the following sum.

$$
|e| \le \tau(s) = \tau_{\mathrm{abs}} + \tau_{\mathrm{rel}}\, s, \qquad s \ge 0.
$$

$s$ is the representative scale used for assessment; the caller or solver chooses what it represents.
`Tolerance::threshold(scale)` returns $\tau(s)$.
`Tolerance::is_converged(current, previous)` compares two consecutive iterates, testing $|y_{\mathrm{current}} - y_{\mathrm{previous}}| \le \tau(s)$ with $s = \max(|y_{\mathrm{current}}|, |y_{\mathrm{previous}}|)$.
This test compares without forming the difference $y_{\mathrm{current}} - y_{\mathrm{previous}}$, avoiding difference overflow even for large finite values of opposite signs.

The scale where the two terms are equal is the **crossover scale**.

$$
s_\times = \frac{\tau_{\mathrm{abs}}}{\tau_{\mathrm{rel}}} \qquad (\tau_{\mathrm{rel}} > 0).
$$

The absolute term determines the threshold for $s \ll s_\times$, and the relative term for $s \gg s_\times$.
Choose the two tolerances so that $s_\times$ lies at a meaningful problem scale, such as instrument resolution or a physical quantity small enough to neglect.
Another convention combines the terms with $\max(\tau_{\mathrm{abs}}, \tau_{\mathrm{rel}} s)$ instead of a sum.
Since $\max(a, b) \le a + b \le 2 \max(a, b)$, the sum-based threshold is between one and two times the $\max$ threshold, reaching twice it at $s = s_\times$.

`Result` distinguishes construction and assessment failures.

- `Tolerance::new(absolute, relative)` rejects negative values as `InvalidInput` (`InvalidInputReason::OutOfRange`), and NaN or infinity as `NonFinite`.
- `threshold` rejects negative scales as `InvalidInput` and non-finite scales as `NonFinite`.
  If finite inputs produce an unrepresentable threshold, it returns `NumericalInstability` (`NumericalIssue::Overflow`).
- `is_residual_ok(residual_norm, problem_scale)` returns `Ok(false)` for a large but valid residual.
  Negative or non-finite residuals or scales are invalid inputs, rather than non-convergence, and produce `Err`.

## Role-specific tolerance types

The same `1e-6` has different units and meanings when applied to a state change, equation residual, or gradient.
`scioxide-core` defines types wrapping `Tolerance` for each assessment role, preventing confusion through types.

| Type | Assessed quantity | Assessment method | `Default` |
|---|---|---|---|
| `StepTolerance` | State change (step length) | `is_satisfied(magnitude, scale)` | $\tau_{\mathrm{abs}} = \tau_{\mathrm{rel}} = \sqrt{\varepsilon}$ |
| `ResidualTolerance` | Equation residual norm | `is_satisfied(magnitude, scale)` | As above |
| `GradientTolerance` | Objective gradient norm | `is_satisfied(magnitude, scale)` | As above |
| `RankThreshold` | Singular value or pivot determining numerical rank | `is_satisfied(magnitude, scale)` | As above |
| `FeasibilityTolerance` | Constraint violation | `is_satisfied(magnitude, scale)` | As above |
| `IntegralityTolerance` | Distance to the nearest integer | `is_satisfied(distance)` | $\sqrt{\varepsilon}$ |

$\varepsilon$ is machine epsilon; in double precision, $\sqrt{\varepsilon} \approx 1.5 \times 10^{-8}$.
The first five types share `new(absolute, relative)`, `from_tolerance`, `tolerance()`, and `threshold(scale)`, with the same validation rules as `Tolerance::new`.
`is_satisfied(magnitude, scale)` tests $\text{magnitude} \le \tau(\text{scale})$, with the same error conditions as `is_residual_ok`.

`IntegralityTolerance` has only an absolute value, restricted to $[0, 0.5)$.
Below $0.5$, at most one integer lies within the allowed width, so the rounding target of an almost-integer value is unique.
Values at least $0.5$ are rejected as `InvalidInput` (`OutOfRange`), and half-integers are not considered integers.

`Tolerance` has no defined default.
`Tolerance::from_sqrt_epsilon()` ($\tau_{\mathrm{abs}} = \tau_{\mathrm{rel}} = \sqrt{\varepsilon}$) and `Tolerance::from_machine_epsilon()` ($\tau_{\mathrm{abs}} = \tau_{\mathrm{rel}} = \varepsilon$) are named policies; each solver's options type documents which it adopts.
`Tolerance::from_decimal_places(p, q)` constructs $\tau_{\mathrm{abs}} = 10^{-p}$ and $\tau_{\mathrm{rel}} = 10^{-q}$.

Use `RelativeTolerance` for convergence criteria without an absolute term.
`RelativeTolerance::new(relative)` accepts only finite nonnegative relative thresholds, rejecting negatives as `InvalidInput` and NaN or infinity as `NonFinite`.
Zero requests the best accuracy achievable by the method; methods with an accuracy floor document it.
`Default` is machine epsilon $\varepsilon$.
This type has no assessment methods; read its value with `relative()`, or use `Tolerance::from` to convert it to the `Tolerance` of $\tau_{\mathrm{abs}} = 0$.

No tolerance type includes iteration or evaluation count limits.
Specify limits separately through `Budget` ([Solve lifecycle and computation count management](../solve-lifecycle-and-accounting/)).

## Componentwise normalized errors and the four norms of `ErrorTolerance`

For errors $\mathbf{e} \in \mathbb{R}^n$ in vector quantities, scales and allowed widths differ by component.
ODE step size control and local error assessment in adaptive quadrature have this form.
`ErrorTolerance` forms dimensionless quantities by dividing each component by its threshold $\tau_i = \tau_{\mathrm{abs}, i} + \tau_{\mathrm{rel}} s_i$ for component $i$,

$$
w_i = \frac{|e_i|}{\tau_{\mathrm{abs}, i} + \tau_{\mathrm{rel}}\, s_i}
$$

then applies the norm selected by `NormSelection` to $\mathbf{w}$.
`is_satisfied(errors, scales)` tests whether the norm is at most 1; `normalized_norm(errors, scales)` returns the norm value.
The absolute term is supplied as `AbsoluteTolerance`, either shared across components (`ErrorTolerance::scalar`) or componentwise (`ErrorTolerance::try_vector`); the relative term is a single shared value.
`try_vector` allocates on the heap to copy componentwise values; `normalized_norm` and `is_satisfied` compute in $O(n)$ time without allocation.

| `NormSelection` | Value | Computation |
|---|---|---|
| `L1` | $\sum_i w_i$ | Sum the floating-point values $w_i$ exactly through `RangeAccumulator`, then round once |
| `L2` | $\sqrt{\sum_i w_i^2}$ | Avoid square overflow with `ScaledNorm` (LASSQ-type scaling) |
| `RootMeanSquare` | $\sqrt{\sum_i w_i^2 / n}$ | Divide the scaled sum of squares of `ScaledNorm` by $n$, take its square root, and restore the scale |
| `Infinity` | $\max_i w_i$ | Maximum component |

Every norm of an empty vector is 0.
RMS is unchanged when the same error distribution is replicated, but a few large components are increasingly diluted as $n$ grows.
`Infinity` rejects a result if even one component exceeds its allowed width.
The default `ErrorTolerance` uses absolute and relative terms of $\sqrt{\varepsilon}$ and `RootMeanSquare`.

Components with a zero threshold follow these rules.

- A component with $\tau_i = 0$ is accepted only when its error is exactly 0.
  With nonzero error, $w_i$ has no finite representation.
- In that case, `is_satisfied` returns `Ok(false)`, while `normalized_norm` returns `NumericalInstability` (`Overflow`).
- Componentwise absolute tolerances whose length differs from the error vector produce `DimensionMismatch`.
  The same applies if error and scale lengths differ.

To assess multiple errors with the same component scales, `ErrorTolerance::prepare_norm(scales, storage)` can compute thresholds $\tau_i$ just once.
The returned `PreparedErrorNorm` borrows both the tolerance and the caller's threshold storage `storage`, preventing changes to either while it is reused.
`PreparedErrorNorm::normalized_norm_by` takes a closure returning error components by index and returns a normalized norm; `is_satisfied_by` returns the acceptance decision.
Both call the closure once per component, in index order.
The length of `storage` must equal the scale component count; a mismatch produces `DimensionMismatch`.
Here too, zero-threshold components are accepted only for zero error.
`threshold` and `prepare_norm` form the threshold with two roundings, one for the product $\tau_{\mathrm{rel}} s_i$ and one for the sum.
For at least two components, `normalized_norm` and `is_satisfied` use one rounding for the multiply-add on targets with a fused multiply-add instruction (`HARDWARE_FMA` is true), so thresholds from the two paths can differ in the last bit.
`ErrorTolerance::normalized_norm_by(dimension, component)` supplies pairs of errors and scales without constructing slices.

## Residual reports and `ResidualReport`

When a solver reports its final residual, the raw norm alone does not allow comparisons across different problem scales.
`ResidualReport` stores a raw residual together with its scaling rule.

- `raw_norm()`: The residual norm $\|F(\mathbf{x})\|$ in the problem's units.
- `norm()`: The norm used to reduce the residual (`NormSelection`).
- `scaling()`: A `ResidualScaling` containing scaling rule `ResidualScalingRule` and positive denominator $D$.
- `scaled_norm()`: A dimensionless value computing `raw_norm / D` by range-safe division (`checked_float_quotient`).

`ResidualScalingRule` records whether scaling used `Unscaled` (denominator 1), `Reference` (division by a reference), `ToleranceThreshold` (division by a threshold), `ComponentwiseTolerance` (componentwise normalization before reduction), or `BackwardError` (the normwise backward error denominator).
`ResidualScaling::new(rule, denominator)` rejects nonpositive denominators as `InvalidInput` and non-finite denominators as `NonFinite`.
`ResidualReport::new(raw_norm, norm, scaling)` returns `InvalidInput` for negative residual norms, `NonFinite` for non-finite norms, and `NumericalInstability` for quotient overflow.
With `ToleranceThreshold` using threshold $\tau(s)$ as denominator, `scaled_norm()` at most 1 corresponds to accepting the residual under the same tolerance.

Reports can also accompany failure diagnostics.
A report attached through `ConvergenceDiagnostics::with_residual` is available from `residual()` on the `diagnostics` of `SciOxideErrorView::ConvergenceFailure` (borrowed view `ConvergenceDiagnosticsView`).
For an iteration-limit failure with static-string details and diagnostics containing only own and nested iteration counts, the error stores just those counts without heap allocation.
In that case, `residual()`, `budget()`, and `algorithm()` return `None`, and `counts()` returns both iteration counts.

The following cell fixes residual tolerances at $\tau_{\mathrm{abs}} = 10^{-10}$ and $\tau_{\mathrm{rel}} = 10^{-8}$, taking residual norm exponent $\log_{10}\|r\|$ and representative scale $s$ (such as the right-hand side norm) as inputs.
All quantities are dimensionless in this example.
The first table shows the raw residual, denominator, scaled residual, and `ResidualTolerance::is_satisfied` result for a report constructed with `ToleranceThreshold` and denominator $D = \tau(s)$.
The second table constructs iteration-limit failures with counts-only diagnostics and with residual-and-algorithm-identifier diagnostics, comparing the contents read through `view()`.

let raw_norm = 10.0_f64.powf(residual_exponent);
let tolerance = ResidualTolerance::new(1e-10, 1e-8).map_err(|e| e.to_string())?;
// Denominator D is the threshold τ(s) = τ_abs + τ_rel s.
let denominator = tolerance.threshold(scale).map_err(|e| e.to_string())?;
let scaling = ResidualScaling::new(ResidualScalingRule::ToleranceThreshold, denominator)
    .map_err(|e| e.to_string())?;
let report =

    .is_satisfied(raw_norm, scale)
    .map_err(|e| e.to_string())?;

    ConvergenceReason::IterationLimit,

);

    ConvergenceReason::IterationLimit,

At the defaults ($\|r\| = 10^{-9}$, $s = 1$), the denominator is $D = 10^{-10} + 10^{-8} = 1.01 \times 10^{-8}$ and the scaled residual is approximately $0.099$, satisfying the tolerance.
Increasing the residual to $10^{-7}$ makes its scaled value approximately $9.9$, and `is_satisfied` returns `false`.
At $s = 0$, the denominator is $\tau_{\mathrm{abs}} = 10^{-10}$, and the same residual $10^{-9}$ has scaled value $10$, failing the tolerance.
Even for the same raw residual, the choice of denominator changes the scaled value by two orders of magnitude.

In the second table, the counts-only error returns `None` from `residual()` and `algorithm()`, whereas the residual-and-identifier diagnostics expose the same scaled residual and identifier `handbook/residual-report@1`.

A small residual does not imply small forward error.

## Summary

The threshold of `Tolerance` is $\tau_{\mathrm{abs}} + \tau_{\mathrm{rel}} s$; choose the two tolerances to place crossover scale $s_\times$ at a meaningful problem magnitude.
Use role-specific types according to whether you assess changes, residuals, gradients, rank, constraints, or integrality; when relying on defaults, check that $\sqrt{\varepsilon}$ is selected.
Normalize vector errors componentwise with `ErrorTolerance`; choose `Infinity` to avoid missing local violations, or `RootMeanSquare` for an average level independent of component count.
Zero-threshold components accept only zero error; write caller branches expecting acceptance decisions to return through `Ok(false)`.
When reading residual reports, inspect the rule and denominator in `scaling()` as well as `scaled_norm()`, establishing what the residual was divided by.
