SciOxide functions return invalid input, numerical breakdown, and insufficient execution capabilities through one type, `SciOxideError`.
Callers branch on the category and inspect the detailed view to establish what failed and how.
This page explains that interpretation.
[Error contracts and partial results](../../../concepts/errors-and-partial-results/) distinguishes `Err` from unsuccessful `Ok` and explains partial results; [Tolerance roles and acceptance contracts](../error-and-tolerance-contracts/) covers tolerance decisions.
[Estimate reliability categories](../estimate-reliability/) explains the basis of estimates attached to successful results.

## Categories `kind()` and detailed views `view()`

`SciOxideError` is an opaque struct; its internal variants cannot be matched directly.
`kind()` returns stable category `SciOxideErrorKind` by value, while `view()` returns `SciOxideErrorView<'_>` borrowing category-specific fields.
Both enums have 20 identically named variants corresponding one to one.
`kind()` suffices for branching; match `view()` when reading argument names, shapes, or reasons.
Text returned by `to_string()` is a human-readable English explanation, not intended for programmatic parsing.

| Category | Failure | Fields of `view()` |
|---|---|---|
| `InvalidInput` | Structurally invalid input or configuration | `argument`, `reason`（`InvalidInputReason`）, `detail` |
| `DimensionMismatch` | Shape mismatch | `expected`, `actual` (sequences of axis lengths) |
| `SizeOverflow` | Unrepresentable size or capacity calculation | `context`（`Quantity`） |
| `AccountingInvariant` | Inconsistent accounting records | `detail`, `partition` |
| `ResourceLimit` | Configured resource limit exceeded | `resource`（`Quantity`）, `required`, `limit` |
| `AllocationFailure` | Memory allocation failed | `context`（`Quantity`）, `requested` |
| `ExecutionFailure` | Injected executor failed | `partition`, `reason`（`ExecutionFailureReason`）, `detail` |
| `CapabilityUnavailable` | Required capability not supplied | `capability`（`Capability`） |
| `CapabilityFailure` | Supplied capability provider failed | `capability`, `detail` |
| `ExecutionStopped` | Cancellation or deadline stop | `reason`（`ExecutionStopReason`） |
| `OutOfBounds` | Index outside bounds | `collection`（`Quantity`）, `index`, `size` |
| `DomainError` | Finite argument outside the domain | `argument`, `reason`（`DomainReason`）, `detail` |
| `NonFinite` | Observed NaN or infinity | `origin`（`NonFiniteOrigin`）, `detail` |
| `ScalarConversion` | Checked scalar conversion failed | `from_type`, `to_type`（`ConversionType`）, `reason` |
| `ConvergenceFailure` | Valid finite iteration did not converge | `reason`（`ConvergenceReason`）, `diagnostics`, `detail` |
| `Singular` | Singular matrix | `pivot` (validated pivot position, when known) |
| `NumericalInstability` | Finite-precision numerical breakdown | `issue`（`NumericalIssue`）, `detail` |
| `DifferentiationFailure` | Differentiation callback failed | `frames` (sequence of `DifferentiationFrame`), `cause` |
| `NotImplemented` | An intentionally unavailable operation | `detail` |
| `External` | Failure reported by a callback or consuming code | `detail` |

The five numerical categories are defined without overlap.
`InvalidInput` concerns structural errors, while `DomainError` applies only to finite arguments outside a mathematical domain.
`NonFinite` concerns NaN or infinity, `NumericalInstability` finite-precision breakdown, and `ConvergenceFailure` iteration failing to converge on valid finite inputs.
For example, supplying a finite $x$ outside $0 < x < 1$ to `logit` gives `DomainError`, while supplying NaN gives `NonFinite`.
Infinity arising from finite operands is reported as `NumericalInstability` (`Overflow`), rather than `NonFinite`.

The three resource-related categories are also distinct.
`SizeOverflow` means a required-size calculation exceeds the integer type; `ResourceLimit` means it is representable but exceeds a caller-configured limit; `AllocationFailure` means allocation itself failed.
Category `ResourceLimit` differs from convergence reason `ConvergenceReason::ResourceLimit`: the latter indicates iteration stopped at a solve limit other than iterations or evaluations.

`DifferentiationFailure` wraps an underlying failure.
Its `kind()` returns `DifferentiationFailure`; inspect the original failure through `cause` of `view()` or through `Error::source()`.

Code outside SciOxide creates `External` errors through `SciOxideError::external(detail)`.
Errors returned by user callbacks propagate unchanged to the caller.
If a numerical differentiation callback fails, the failure is wrapped in `DifferentiationFailure` as above, retaining the returned error unchanged in `cause`.

Errors with static-string details, and `DimensionMismatch` with both shapes of rank at most 2, allocate no heap storage.
Iteration-limit failures also avoid allocation when details are static strings and diagnostics contain only iteration counts.
Owned detail strings, `ExecutionFailure` carrying partition indices, `CapabilityFailure` for capability `Operation`, `ConvergenceFailure` with diagnostics beyond iteration counts, and `DifferentiationFailure` use heap storage.

The following block defines helpers shared by this page's cells.
`kind_name` converts category `SciOxideErrorKind` to its variant-name string.
Because `SciOxideErrorKind` supports exhaustive matching, all 20 variants are listed.
`describe` matches `view()` and extracts failure location (argument, quantity, capability, or conversion direction), reason variant name, and detail text.
Reason enums cannot be exhaustively matched from external crates, so unlisted variants become “Other.”

```rust
//| id: core-error-kind-names
//| kind: definitions
//| title: "Category and reason variant names"
//| crates: [scioxide-core]
use scioxide_core::{
    Capability, DomainReason, SciOxideError, SciOxideErrorKind, SciOxideErrorView, InvalidInputReason,
    NonFiniteOrigin, NumericalIssue, ScalarConversionReason,
};

/// Return category variant names.
pub(crate) fn kind_name(kind: SciOxideErrorKind) -> &'static str {
    match kind {
        SciOxideErrorKind::InvalidInput => "InvalidInput",
        SciOxideErrorKind::DimensionMismatch => "DimensionMismatch",
        SciOxideErrorKind::SizeOverflow => "SizeOverflow",
        SciOxideErrorKind::AccountingInvariant => "AccountingInvariant",
        SciOxideErrorKind::ResourceLimit => "ResourceLimit",
        SciOxideErrorKind::AllocationFailure => "AllocationFailure",
        SciOxideErrorKind::ExecutionFailure => "ExecutionFailure",
        SciOxideErrorKind::CapabilityUnavailable => "CapabilityUnavailable",
        SciOxideErrorKind::CapabilityFailure => "CapabilityFailure",
        SciOxideErrorKind::ExecutionStopped => "ExecutionStopped",
        SciOxideErrorKind::OutOfBounds => "OutOfBounds",
        SciOxideErrorKind::DomainError => "DomainError",
        SciOxideErrorKind::NonFinite => "NonFinite",
        SciOxideErrorKind::ScalarConversion => "ScalarConversion",
        SciOxideErrorKind::ConvergenceFailure => "ConvergenceFailure",
        SciOxideErrorKind::Singular => "Singular",
        SciOxideErrorKind::NumericalInstability => "NumericalInstability",
        SciOxideErrorKind::DifferentiationFailure => "DifferentiationFailure",
        SciOxideErrorKind::NotImplemented => "NotImplemented",
        SciOxideErrorKind::External => "External",
    }
}

// Convert variant names to strings; unlisted variants become “Other.”
macro_rules! variant_name {
    ($value:expr; $ty:ident => $($variant:ident)|+) => {
        match $value {
            $($ty::$variant => stringify!($variant),)+
            _ => "Other",
        }
    };
}

/// Failure location, reason variant name, and details; fields absent from a category are `None`.
pub(crate) type ErrorDetail = (Option<String>, Option<&'static str>, Option<String>);

/// Read failure location (argument, quantity, capability, or conversion direction), reason, and details from `view()`.
pub(crate) fn describe(error: &SciOxideError) -> ErrorDetail {
    match error.view() {
        SciOxideErrorView::InvalidInput {
            argument,
            reason,
            detail,
        } => {
            let reason = variant_name!(reason; InvalidInputReason =>
                Empty | OutOfRange | Inconsistent | Malformed | UnsupportedConfiguration);
            (
                Some(format!("Argument {argument}")),
                Some(reason),
                Some(detail.to_string()),
            )
        }
        SciOxideErrorView::DomainError {
            argument,
            reason,
            detail,
        } => {
            let reason = variant_name!(reason; DomainReason => OutsideDomain | Pole | Undefined);
            (
                Some(format!("Argument {argument}")),
                Some(reason),
                Some(detail.to_string()),
            )
        }
        SciOxideErrorView::NonFinite { origin, detail } => {
            let origin =
                variant_name!(origin; NonFiniteOrigin => Input | Callback | Intermediate | Output);
            (None, Some(origin), Some(detail.to_string()))
        }
        SciOxideErrorView::ScalarConversion {
            from_type,
            to_type,
            reason,
        } => {
            let reason = variant_name!(reason; ScalarConversionReason =>
                NonFiniteInput | OutOfRange | Inexact | Unsupported);
            (Some(format!("{from_type} → {to_type}")), Some(reason), None)
        }
        SciOxideErrorView::NumericalInstability { issue, detail } => {
            let issue = variant_name!(issue; NumericalIssue =>
                ExponentOutOfRange | Overflow | Underflow | Cancellation | LossOfSignificance
                | IllConditioned | DefectiveEigenbasis | Breakdown);
            (None, Some(issue), Some(detail.to_string()))
        }
        SciOxideErrorView::SizeOverflow { context } => (Some(format!("Quantity {context}")), None, None),
        SciOxideErrorView::CapabilityUnavailable { capability } => {
            let name =
                variant_name!(capability; Capability => Clock | Entropy | Blas | ProcessorFeatures);
            (Some(format!("Capability {name}")), None, None)
        }
        SciOxideErrorView::CapabilityFailure { capability, detail } => {
            let name =
                variant_name!(capability; Capability => Clock | Entropy | Blas | ProcessorFeatures);
            (Some(format!("Capability {name}")), None, Some(detail.to_string()))
        }
        // For categories absent from this page's tables, show only Display text as details.
        _ => (None, None, Some(error.to_string())),
    }
}
```

## Failure locations through arguments and quantities

Errors identify an input or resource of the failed function, without retaining caller identity.
Input arguments use `Argument`, carried by `InvalidInput` and `DomainError`.
Resources such as sizes, capacities, counts, and collections use `Quantity`, carried by `SizeOverflow`, `ResourceLimit`, `AllocationFailure`, and `OutOfBounds`.

Both follow the same grammar: segments starting with lowercase letters or underscores and continuing with lowercase letters, digits, or underscores, joined by `.` (`options.max_steps`, `workspace.capacity`).
Separate types prevent putting a resource name in an argument field.
Identifiers name formal parameters of the failing function; for example, `Interval::new` attributes reversed endpoints to `lower`, while `checked_float_quotient` attributes a zero denominator to `denominator`.

`argument!` and `quantity!` validate literals at compile time to construct identifiers; invalid spellings cause compilation errors.
Spellings are retained without allocation and read through `as_str()` or `Display`.

## Reason enums

Many categories carry machine-readable reason enums.
All enums in the following table are `#[non_exhaustive]`, so external `match` expressions require a `_` arm.
`SciOxideErrorKind` and `ConversionType` support exhaustive matching.

| Enum | Category | Variants |
|---|---|---|
| `InvalidInputReason` | `InvalidInput` | `Empty` (required value absent), `OutOfRange` (outside the allowed range), `Inconsistent` (individually valid inputs contradict each other), `Malformed` (malformed format), `UnsupportedConfiguration` (combination unsupported in this configuration) |
| `DomainReason` | `DomainError` | `OutsideDomain` (outside the domain), `Pole` (a function pole), `Undefined` (mathematically undefined, such as division by zero) |
| `NonFiniteOrigin` | `NonFinite` | Where a non-finite value was observed: `Input`, `Callback`, `Intermediate`, `Output` |
| `NumericalIssue` | `NumericalInstability` | Eight variants including `Overflow`, `Underflow`, `Cancellation`, `IllConditioned`, and `Breakdown` ([Projection and range errors](oxref:core-projection-errors)) |
| `ConvergenceReason` | `ConvergenceFailure` | `IterationLimit`, `EvaluationLimit`, `ResourceLimit(BudgetKind)`, `TruncationLimit`, `Stagnation`, `StepSizeLimit`, `ReplayMismatch`, `Divergence`, `NestedSolver`, `NoSuccessfulCandidate` |
| `ScalarConversionReason` | `ScalarConversion` | `NonFiniteInput`, `OutOfRange`, `Inexact`, `Unsupported` |
| `ExecutionFailureReason` | `ExecutionFailure` | `WorkerCreation { os_error }`, `CallbackPanicked`, `ProviderFailure`, `UnknownPartition`, `DuplicatePartition`, `MissingPartition`, `ProtocolViolation` |
| `ExecutionStopReason` | `ExecutionStopped` | `Cancelled`, `DeadlineReached` |

Scalar conversion failures identify source and target representations through `ConversionType` (`F32`, `F64`, `Complex32`, `Complex64`, `I64`, `Isize`, `U128`, `Usize`).
`RealScalar::try_from_f64_exact` rejects value-changing conversions as `Inexact` (double-precision 0.1 is not exactly representable in single precision).
`try_from_f64_lossy` permits nearest rounding, rejecting only non-finite values and out-of-range results.

The `diagnostics` of `ConvergenceFailure` holds algorithm identity, iteration and evaluation counts, the limiting resource, last residual, last accepted state, and equivalent records for nested solves.
See [Residual reports and `ResidualReport`](oxref:core-residual-report-section) and [Nested limits and diagnostics](oxref:core-nested-diagnostics) for interpretation.

## Missing capabilities

Clocks, external entropy sources, and BLAS providers are caller-injected capabilities.
`Capability` represents execution capabilities through `Clock` (monotonic clocks and deadlines), `Entropy` (external entropy), `Blas` (BLAS providers), and `ProcessorFeatures` (processor feature observation); numerical operation capabilities place their name in `Operation(&'static str)`.
An absent capability produces `CapabilityUnavailable`; a supplied provider failure produces `CapabilityFailure`.
Adding a time limit through `with_time_limit` to `ExecutionContext` without a clock binding returns `CapabilityUnavailable` for capability `Clock`.
When BLAS is unavailable and fallback to the reference implementation is forbidden, scioxide-linalg returns `CapabilityUnavailable` for capability `Blas`.

Provider traits (`Clock::now`, `EntropySource::fill_bytes`) report failures as `CapabilityError` containing only detail text.
Construct `CapabilityError` through `new(detail)` and read it through `detail()`.
Through `into_detail()`, SciOxide moves that text without copying it into the `detail` of `CapabilityFailure`.
Wasm has no standard clock `StdClock`, so time limits are unavailable ([Clocks and time limits in Wasm](oxref:core-wasm-clocks)).

## Identifier validation

`Argument::new`, `Quantity::new`, and `AlgorithmComponent::new` are `const fn` methods validating spelling against a grammar; violations produce `IdentifierError`.
`IdentifierError::position()` returns the zero-based position of the first invalid byte.
If spelling ends with an empty segment, it returns the input length.
`into_scioxide()` converts this error without allocation into `InvalidInput` (argument `identifier`, reason `Malformed`).

`AlgorithmComponent` names the family and method forming algorithm identity `AlgorithmId`, following the case-sensitive grammar `[A-Za-z0-9_][A-Za-z0-9_.-]*`.
`algorithm_component!` validates literals, `concat!`, and `stringify!` expressions at compile time.
Validated parts combine through `AlgorithmId::from_components(family, method, version)` without revalidation.
`AlgorithmId` is recorded in solve identities and convergence failure diagnostics ([Solve identity and epochs](oxref:core-solve-identity)).

The following cell has no inputs; it passes valid and invalid spellings to three types, tabulating acceptance and `position()`.
Rejected rows also show the category and reason after conversion through `into_scioxide()`.
Check that `position()` equals the first invalid byte position (11, the uppercase `S` in `options.maxSteps`).

```rust
//| id: core-identifier-validation
//| ref: core-identifier-validation
//| title: "Checking identifier grammars and invalid byte positions"
//| run: reactive
//| uses: [core-error-kind-names]
//| crates: [scioxide-core]
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"identifiers","path":"/rows/0/2","equals":"Accepted"}
//|       - {"artifact":"identifiers","path":"/rows/0/3","equals":null}
//|       - {"artifact":"identifiers","path":"/rows/1/3","equals":11}
//|       - {"artifact":"identifiers","path":"/rows/1/4","equals":"InvalidInput"}
//|       - {"artifact":"identifiers","path":"/rows/1/5","equals":"Malformed"}
//|       - {"artifact":"identifiers","path":"/rows/2/3","equals":8}
//|       - {"artifact":"identifiers","path":"/rows/3/3","equals":0}
//|       - {"artifact":"identifiers","path":"/rows/4/2","equals":"Accepted"}
//|       - {"artifact":"identifiers","path":"/rows/5/3","equals":3}
use scioxide_core::{
    AlgorithmComponent, Argument, SciOxideErrorView, IdentifierError, InvalidInputReason,
    Quantity,
};

// Display acceptance, invalid byte position, and the category and reason from into_scioxide().
let row = |kind: &'static str, spelling: &'static str, checked: Result<(), IdentifierError>| {
    match checked {
        Ok(()) => (kind, spelling, "Accepted", None, None, None),
        Err(error) => {
            let converted = error.into_scioxide();
            let malformed = matches!(
                converted.view(),
                SciOxideErrorView::InvalidInput {
                    reason: InvalidInputReason::Malformed,
                    ..
                }
            );
            (
                kind,
                spelling,
                "Rejected",
                Some(error.position()),
                Some(kind_name(converted.kind())),
                malformed.then_some("Malformed"),
            )
        }
    }
};
let argument = |spelling| row("Argument", spelling, Argument::new(spelling).map(|_| ()));
let quantity = |spelling| row("Quantity", spelling, Quantity::new(spelling).map(|_| ()));
let component = |spelling| {
    row(
        "AlgorithmComponent",
        spelling,
        AlgorithmComponent::new(spelling).map(|_| ()),
    )
};
let rows = vec![
    argument("options.max_steps"),
    // Uppercase letters are outside the argument grammar.
    argument("options.maxSteps"),
    // The final segment is empty.
    argument("options."),
    // A segment cannot start with a digit.
    quantity("9lives"),
    // Algorithm parts may start with digits and include `.` and `-`.
    component("2-norm.v2"),
    component("bad method"),
];
let columns = serde_json::json!([
    { "key": "0", "label": "Type" },
    { "key": "1", "label": "Spelling" },
    { "key": "2", "label": "Validation" },
    { "key": "3", "label": "position() [bytes]", "type": "integer", "nullText": "—" },
    { "key": "4", "label": "kind() from into_scioxide()", "nullText": "—" },
    { "key": "5", "label": "Reason", "nullText": "—" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "identifiers" })
);
```

`options.max_steps` is accepted; `options.maxSteps` is rejected at uppercase `S`, position 11.
`options.` ends with an empty segment, so its input length 8 is returned.
`9lives` is rejected at position 0 because its segment starts with a digit.
`AlgorithmComponent` accepts `2-norm.v2` and rejects whitespace-containing `bad method` at position 3.
All four rejected rows become `Malformed` of `InvalidInput` through `into_scioxide()`.

## Dimension mismatches

The `view()` of `DimensionMismatch` returns expected shape `expected` and actual shape `actual` as axis-length sequences `&[usize]`.
Construct `Dimensions` through `Dimensions::scalar()` (rank zero), `one(n)`, or `two(m, n)`, or convert from `usize`, arrays of lengths 1 or 2, slices, array references, `Vec<usize>`, or `Box<[usize]>`.
`rank()` returns rank, and `axes()` returns axis lengths in their original order.
`SciOxideError::dimension_mismatch(expected, actual)` accepts `impl Into<Dimensions>` and stores both shapes without heap allocation when both ranks are at most 2.

Which shape is expected depends on the function.
`ErrorTolerance::normalized_norm` reports the error vector length as expected and the componentwise absolute tolerance length as actual.
Try this in the [componentwise normalized error cell](oxref:core-error-tolerance-norms).

## Differentiation failure locations

A failing numerical differentiation callback is wrapped in `DifferentiationFailure`, retaining locations and invocation counts as a sequence of `DifferentiationFrame` from the outer boundary inward.
Each frame has public fields `location` (`DifferentiationLocation`) and `evaluations` (invocation count including the failed call).
Nested differentiation uses `SciOxideError::differentiation_failure` to prepend a frame and combine the errors into one.

`DifferentiationLocation::site()` returns one of these `DifferentiationSite` values.

- `BasePoint`: Checking an unperturbed function value.
- `Direction`: A directional derivative (including base-point checks).
- `Variable(i)`: A derivative in one coordinate.
- `Variables(i, j)`: A derivative in two coordinates (including Hessian diagonal entries).

`component_index()` returns an output component index when known.
`scioxide-core` itself does not construct errors of this category; examples appear in [Shared contracts and structure of numerical differentiation algorithms](oxref:differentiate-failure-outputs).

## Invalid-input category examples

The following cell supplies invalid inputs to public `scioxide-core` functions and reads errors through `kind()` and `view()` into two tables.
The control selects a dimensionless function input $x$ from six finite values plus `NaN` and `inf`.

The first table contains six calls taking $x$.
`Interval::new(0.25, x)` has reversed endpoints at $x < 0.25$; `logit(x)` has domain $0 < x < 1$; `Tolerance::new(x, 1e-8)` rejects negative absolute tolerance.
The others are exact conversion to single precision, checked division of $1/x$, and finite-only `ReliableEstimate::new` ([Estimate reliability categories](../estimate-reliability/)).
Successful rows show values: upper endpoints for intervals, $\tau_{\mathrm{abs}}$ for tolerances, and the estimate value for estimates.

The second table contains four calls failing independently of $x$.
Try a zero computation limit, binomial coefficient $\binom{100}{50} \approx 1.0 \times 10^{29}$ (which exceeds `usize` in both 32-bit Wasm and 64-bit environments), a time limit without a clock, and a failing clock provider.

Variant names remain identifiers; details remain the English text returned by SciOxide.
Check that each row's category and reason match the definitions above.

```rust
//| id: core-error-view-gallery
//| ref: core-error-view-gallery
//| title: "Listing invalid-input categories and detailed views"
//| run: reactive
//| uses: [core-error-kind-names]
//| crates: [scioxide-core]
//| inputs:
//|   value: {"type":"select","label":"Function input x [-]","description":"Pass the same x to all six calls accepting x.","options":["-1","0","0.1","0.5","1e300","1e-310","NaN","inf"],"value":"-1"}

//|   - {"id":"nan","label":"x = NaN","description":"Five rows become NonFinite; single-precision conversion becomes ScalarConversion.","inputs":{"value":"NaN"}}
//|   - {"id":"tiny","label":"x = 1e-310","description":"Quotient 1/x exceeds double-precision range, producing NumericalInstability.","inputs":{"value":"1e-310"}}
//|   - {"id":"valid","label":"x = 0.5","description":"All six rows succeed, returning logit(0.5) = 0 and 1/x = 2.","inputs":{"value":"0.5"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"by-value","path":"/rows/0/2","equals":"InvalidInput"}
//|       - {"artifact":"by-value","path":"/rows/0/4","equals":"Inconsistent"}
//|       - {"artifact":"by-value","path":"/rows/1/2","equals":"DomainError"}
//|       - {"artifact":"by-value","path":"/rows/2/4","equals":"OutOfRange"}
//|       - {"artifact":"by-value","path":"/rows/3/1","approx":{"value":-1,"atol":1e-15}}
//|       - {"artifact":"by-value","path":"/rows/4/1","approx":{"value":-1,"atol":1e-15}}
//|       - {"artifact":"fixed","path":"/rows/0/1","equals":"InvalidInput"}
//|       - {"artifact":"fixed","path":"/rows/1/1","equals":"SizeOverflow"}
//|       - {"artifact":"fixed","path":"/rows/2/1","equals":"CapabilityUnavailable"}
//|       - {"artifact":"fixed","path":"/rows/3/1","equals":"CapabilityFailure"}
//|   - case: nan
//|     expect:
//|       - {"artifact":"by-value","path":"/rows/0/2","equals":"NonFinite"}
//|       - {"artifact":"by-value","path":"/rows/1/4","equals":"Input"}
//|       - {"artifact":"by-value","path":"/rows/3/2","equals":"ScalarConversion"}
//|       - {"artifact":"by-value","path":"/rows/3/4","equals":"NonFiniteInput"}
//|   - case: tiny
//|     expect:
//|       - {"artifact":"by-value","path":"/rows/3/4","equals":"Inexact"}
//|       - {"artifact":"by-value","path":"/rows/4/2","equals":"NumericalInstability"}
//|       - {"artifact":"by-value","path":"/rows/4/4","equals":"Overflow"}
//|   - case: valid
//|     expect:
//|       - {"artifact":"by-value","path":"/rows/0/1","approx":{"value":0.5,"atol":1e-15}}
//|       - {"artifact":"by-value","path":"/rows/1/1","approx":{"value":0,"atol":1e-15}}
//|       - {"artifact":"by-value","path":"/rows/4/1","approx":{"value":2,"atol":1e-15}}
//|       - {"artifact":"by-value","path":"/rows/5/2","equals":null}
use scioxide_core::{
    Budget, CapabilityError, Clock, ClockBinding, EstimateReliability, ExecutionContext,
    SciOxideError, Interval, MonotonicInstant, RealScalar, ReliableEstimate, Tolerance,
    checked_binomial, checked_float_quotient, logit,

let x: f64 = value.parse().map_err(|_| "Cannot read x as a number")?;
// Calls taking x. Convert successful values to f64.
let by_value: Vec<(&str, Result<f64, SciOxideError>)> = vec![
    (
        "Upper endpoint of Interval::new(0.25, x)",
        Interval::new(0.25, x).map(|interval| interval.upper()),
    ),
    ("logit(x)", logit(x)),
    (
        "τ_abs from Tolerance::new(x, 1e-8)",
        Tolerance::new(x, 1e-8).map(|tolerance| tolerance.absolute()),
    ),
    (
        "f32::try_from_f64_exact(x)",
        <f32 as RealScalar>::try_from_f64_exact(x).map(RealScalar::into_f64),
    ),
    (
        "checked_float_quotient(1, x)",
        checked_float_quotient(1.0, x),
    ),
    (
        "Value of ReliableEstimate::new(x, Heuristic)",
        ReliableEstimate::new(x, EstimateReliability::Heuristic)
            .map(|estimate| estimate.value()),
    ),
];
let mut value_rows = Vec::new();

    value_rows.push(match result {
        Ok(number) => (call, Some(number), None, None, None, None),
        Err(error) => {
            let (place, reason, detail) = describe(&error);
            (
```

At the default $x = -1$, `Interval::new` returns `InvalidInput` (`Inconsistent`, argument `lower`), `logit` returns `DomainError` (`OutsideDomain`, argument `x`), and `Tolerance::new` returns `InvalidInput` (`OutOfRange`, argument `absolute`).
Single-precision conversion, division, and `ReliableEstimate::new` succeed, returning $-1$.

Changing $x$ to `NaN` or `inf` makes all five rows except single-precision conversion become `NonFinite` (`Input`); the conversion becomes `ScalarConversion` (`NonFiniteInput`).
At $x = 0$, division produces `DomainError` (`Undefined`, argument `denominator`).
At $x = 10^{-310}$, quotient $10^{310}$ exceeds double-precision range, and division produces `NumericalInstability` (`Overflow`).
Single-precision conversion returns `Inexact` for $x = 0.1$ and $10^{-310}$, and `OutOfRange` for $x = 10^{300}$.
At $x = 0.5$, all six rows succeed, returning `logit(0.5) = 0` and $1/x = 2$.

In the second table, a zero computation limit gives `InvalidInput` (`OutOfRange`, argument `value`), while the binomial coefficient gives `SizeOverflow` for quantity `binomial_coefficient`.
The clock rows give `CapabilityUnavailable` and `CapabilityFailure` for capability `Clock`; the latter retains the provider's text supplied to `CapabilityError` unchanged.

## Summary

Use `kind()` to classify `SciOxideError` into one of 20 categories and branch; match `view()` only when arguments, quantities, shapes, or reasons are needed.
`InvalidInput`, `DomainError`, `NonFinite`, `NumericalInstability`, and `ConvergenceFailure` do not overlap, so the category alone can guide input correction.
Failure locations use `Argument` and `Quantity` identifiers; reason enums are `#[non_exhaustive]`, so include a `_` arm in `match`.
For computations requiring clocks or BLAS, inject capabilities on `CapabilityUnavailable` and inspect provider details on `CapabilityFailure`.
Detail text `detail` and `to_string()` is human-readable English, not intended for branching.
