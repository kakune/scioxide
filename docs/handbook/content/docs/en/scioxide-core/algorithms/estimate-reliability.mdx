Condition number and error estimates are returned as part of successful results, rather than as errors.
Separately from investigating failures, check what supports the returned numerical value.
`scioxide-core` defines `EstimateReliability` to categorize the basis of uncertified estimates and `ReliableEstimate` to pair a value with its category.
`scioxide-core` itself has no functions returning this type; methods in later chapters return these categories.
This page first explains their interpretation, then uses reciprocal condition estimates from scioxide-linalg for measurements.
[Error categories and detailed views](../errors-and-diagnostic-views/) explains failure categories and details.

## Three categories and `ReliableEstimate`

`EstimateReliability` divides estimates that are not proven bounds into three categories.

| Category | Basis |
|---|---|
| `Heuristic` | An indicator with no calibrated coverage claim |
| `ModelBased` | An estimate supported by a documented numerical model |
| `StatisticallyCalibrated` | An estimate calibrated by a documented statistical procedure |

These categories describe the basis of estimation, not its accuracy or a guarantee of containing the true value.
If a guaranteed enclosing interval is required, use a verified enclosure from [scioxide-validated](../../../scioxide-validated/).
Because `EstimateReliability` is `#[non_exhaustive]`, matching it requires a `_` arm.

`ReliableEstimate<S>` pairs a finite value with a category.
`ReliableEstimate::new(value, reliability)` rejects NaN and infinity as `NonFinite` (`NonFiniteOrigin::Input`), returning the value through `value()` and category through `reliability()`.
Only finiteness is checked; sign and magnitude are unrestricted.
Try this check in the last row of the [invalid-input classification cell](oxref:core-error-view-gallery).

Methods in later chapters return categorized values, including the following.

- scioxide-linalg's `ConditionEstimate::reciprocal()` returns a reciprocal condition estimate through `ReliableEstimate`.
  The Schur reordering report `SchurReorderReport::separation()` also returns separation estimates in the same type when requested.
- Root diagnostics in scioxide-poly hold root condition and inclusion-disk radius estimates through `ReliableEstimate`.
- Results carrying error estimates in scioxide-special return the same category through `reliability()`.

`PartialResultTrust` attached to the last accepted state is a separate classification describing which checks that state passed ([Error contracts and partial results](../../../concepts/errors-and-partial-results/)).

## Two reciprocal condition estimates and their basis

Compare two reciprocal condition estimates returned by scioxide-linalg to see how the categories differ.
Let reciprocal condition number be $\mathrm{rcond}_p(A) = 1/(\lVert A \rVert_p \lVert A^{-1} \rVert_p)$.
The scioxide-linalg pages [Separating factorization from solution acceptance](oxref:linalg-factorization-acceptance) and [Computing singular value decompositions](oxref:linalg-svd-method) explain the two functions.

`LuDecomposition::condition_estimate` estimates $\lVert A^{-1} \rVert_1$ with the Hager–Higham method using only a few solves with $A$ and $A^{\mathsf H}$ from LU factors.
Each solve costs $O(n^2)$, and the returned value is $\mathrm{rcond}_1$ (category `Heuristic`).
For $n \le 4$, $\lVert A^{-1} \rVert_1$ is computed exactly rather than estimated.
In exact arithmetic, the estimated value is the magnitude of $A^{-1}$ acting on a unit vector and cannot exceed $\lVert A^{-1} \rVert_1$, so the reciprocal estimate can err only by overestimating $\mathrm{rcond}_1$.
Floating-point rounding in the factors means even this direction is not guaranteed.

`SvdValues::condition_estimate` returns the computed singular value ratio $\sigma_{\min}/\sigma_{\max}$ as $\mathrm{rcond}_2$ (category `ModelBased`).
A backward-stable SVD returns singular values of $A + E$ satisfying $\lVert E \rVert_2 \le c(n)\,u\,\lVert A \rVert_2$, so Weyl's inequality gives $\lvert \hat\sigma_i - \sigma_i \rvert \le c(n)\,u\,\sigma_{\max}$.
Here $u = 2^{-53}$ is double-precision unit roundoff and $c(n)$ a constant growing slowly with matrix order.
The relative error in $\mathrm{rcond}_2$ is therefore bounded approximately by $c(n)\,u/\mathrm{rcond}_2$, and the estimate loses meaning as $\mathrm{rcond}_2$ approaches $u$.

## Measurements with Hilbert matrices

The following cell obtains both estimates for an order-$n$ Hilbert matrix $(H_n)_{ij} = 1/(i + j - 1)$ (one-based indices), displaying categories and estimates alongside exact values.
The input is order $n$ (2–12).
Exact values are computed independently from the closed-form inverse, whose entries are integers.
The 1-norm is the maximum absolute column sum; the 2-norm is the largest eigenvalue of the symmetric positive-definite matrix, obtained by power iteration.
Check that estimated/exact ratios are near 1 and categories match the descriptions above.
The scioxide-linalg example [Conditioning, forward error, and mixed-precision iterative refinement with Hilbert matrices](../../../scioxide-linalg/examples/hilbert-conditioning/) examines conditioning and forward error in more detail.

```rust
//| id: core-estimate-reliability
//| ref: core-estimate-reliability
//| title: "Comparing reciprocal condition estimates and reliability categories against exact Hilbert matrix values"
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg]
//| inputs:
//|   order: {"type":"range","label":"Hilbert matrix order n [-]","description":"H_ij = 1/(i + j − 1). The condition number rises rapidly with n.","min":2,"max":12,"step":1,"value":6}
//| cases:
//|   - {"id":"order-3","label":"n = 3","description":"κ₁(H₃) = 748 exactly, and the LU estimate is also exact.","inputs":{"order":3}}
//|   - {"id":"order-12","label":"n = 12","description":"rcond₂ falls below unit roundoff, and the estimated/exact ratio deviates from 1.","inputs":{"order":12}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"estimates","path":"/rows/0/2","equals":"Heuristic"}
//|       - {"artifact":"estimates","path":"/rows/0/4","approx":{"value":3.43994e-8,"rtol":1e-5}}
//|       - {"artifact":"estimates","path":"/rows/0/5","approx":{"value":1,"atol":1e-3}}
//|       - {"artifact":"estimates","path":"/rows/1/2","equals":"ModelBased"}
//|       - {"artifact":"estimates","path":"/rows/1/5","approx":{"value":1,"atol":1e-3}}
//|   - case: order-3
//|     expect:
//|       - {"artifact":"estimates","path":"/rows/0/4","approx":{"value":1.3368983957219251e-3,"rtol":1e-12}}
//|       - {"artifact":"estimates","path":"/rows/0/5","approx":{"value":1,"atol":1e-9}}
//|       - {"artifact":"estimates","path":"/rows/1/4","approx":{"value":1.90819e-3,"rtol":1e-5}}
//|       - {"artifact":"estimates","path":"/rows/1/5","approx":{"value":1,"atol":1e-9}}
//|   - case: order-12
//|     expect:
//|       - {"artifact":"estimates","path":"/rows/0/5","range":{"min":0.5,"max":1.5}}
//|       - {"artifact":"estimates","path":"/rows/1/5","range":{"min":0.5,"max":1.5}}
//|       - {"artifact":"estimates","path":"/rows/1/4","range":{"min":0,"max":1.1e-16}}
use scioxide_core::EstimateReliability;
use scioxide_linalg::{LuDecomposition, Matrix, SvdValues};

let n = order as usize;
// Store the Hilbert matrix row-major. With zero-based indices, H_ij = 1/(i + j + 1).
let entries = (0..n * n)
    .map(|k| 1.0 / (k / n + k % n + 1) as f64)
    .collect();
let a = Matrix::from_vec(n, n, entries).map_err(|e| e.to_string())?;
// Estimate reciprocal 1-norm conditioning from LU factorization and reciprocal 2-norm conditioning from singular values.
let lu = LuDecomposition::factor(&a)
    .and_then(|factor| factor.condition_estimate())
    .map_err(|e| e.to_string())?
    .reciprocal();
let sv = SvdValues::compute(&a)
    .and_then(|values| values.condition_estimate())
    .map_err(|e| e.to_string())?
    .reciprocal();

// Independent check: integer formula for the inverse (one-based indices).
// (H⁻¹)_ij = (−1)^(i+j) (i+j−1) C(n+i−1, n−j) C(n+j−1, n−i) C(i+j−2, i−1)².
// Construct binomial coefficients exactly with u64.
let binom = |p: u64, q: u64| (0..q).fold(1_u64, |c, t| c * (p - t) / (t + 1));
let m = n as u64;
let inverse = |i: usize, j: usize| {
    let (i, j) = (i as u64 + 1, j as u64 + 1);
    let sign = if (i + j) % 2 == 0 { 1.0 } else { -1.0 };
    let first = binom(m + i - 1, m - j) as f64;
    let second = binom(m + j - 1, m - i) as f64;
    let third = binom(i + j - 2, i - 1) as f64;
    sign * (i + j - 1) as f64 * first * second * third * third
};
let hilbert = |i: usize, j: usize| 1.0 / (i + j + 1) as f64;
// The 1-norm is the maximum absolute column sum.
let norm1 = |f: &dyn Fn(usize, usize) -> f64| {
    (0..n)
        .map(|j| (0..n).map(|i| f(i, j).abs()).sum::<f64>())
        .fold(0.0, f64::max)
};
// For a symmetric positive-definite matrix, the 2-norm is the largest eigenvalue. Perform 200 power iterations.
// This is a reference computation, so use f64's standard square root function.
let norm2 = |f: &dyn Fn(usize, usize) -> f64| {
    let mut v = vec![1.0 / (n as f64).sqrt(); n];
    let mut lambda = 0.0;
    for _ in 0..200 {
        let w: Vec<f64> = (0..n)
            .map(|i| (0..n).map(|j| f(i, j) * v[j]).sum())
            .collect();
        lambda = w.iter().map(|x| x * x).sum::<f64>().sqrt();
        v = w.iter().map(|x| x / lambda).collect();
    }
    lambda
};
let exact1 = 1.0 / (norm1(&hilbert) * norm1(&inverse));
let exact2 = 1.0 / (norm2(&hilbert) * norm2(&inverse));

// Display categories as variant names. The enum is non-exhaustive, so include a `_` arm.
let class = |reliability: EstimateReliability| match reliability {
    EstimateReliability::Heuristic => "Heuristic",
    EstimateReliability::ModelBased => "ModelBased",
    EstimateReliability::StatisticallyCalibrated => "StatisticallyCalibrated",
    _ => "Other category",
};
let rows: Vec<_> = [
    ("LuDecomposition::condition_estimate", "1", lu, exact1),
    ("SvdValues::condition_estimate", "2", sv, exact2),
]
.into_iter()
.map(|(method, norm, estimate, exact)| {
    (
        method,
        norm,
        class(estimate.reliability()),
        estimate.value(),
        exact,
        estimate.value() / exact,
    )
})
.collect();
let sci5 = serde_json::json!({ "notation": "scientific", "significantDigits": 5 });
let fixed3 = serde_json::json!({ "fractionDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "Estimation function" },
    { "key": "1", "label": "Norm p" },
    { "key": "2", "label": "Category" },
    { "key": "3", "label": "Estimated rcond [-]", "type": "number", "format": sci5 },
    { "key": "4", "label": "Exact rcond (independent check) [-]", "type": "number", "format": sci5 },
    { "key": "5", "label": "Estimated / exact [-]", "type": "number", "format": fixed3 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "estimates" })
);
```

At the default $n = 6$, the LU estimate $3.4399 \times 10^{-8}$ and singular value ratio $6.6885 \times 10^{-8}$ agree with the exact values to 10 digits ($\kappa_1 = 1/\mathrm{rcond}_1 \approx 2.91 \times 10^{7}$).
At $n = 3$, the exact value is $\mathrm{rcond}_1 = 1/748$, and the LU value agrees within rounding.
As the order increases, ratios depart from 1, with discrepancies of order $10^{-4}$ at $n = 10$ and $10^{-3}$ at $n = 11$.
At $n = 12$, $\mathrm{rcond}_2 \approx 5.8 \times 10^{-17}$ falls below $u \approx 1.1 \times 10^{-16}$, and the singular value ratio is a few percent smaller than the exact value (about 2% in the browser).
The LU estimate then differs from the exact value by less than 1%.

Exact values here refer to the Hilbert matrix before rounding.
Merely storing entries $1/(i+j-1)$ in double precision introduces relative perturbations of $u$, so at orders where $\mathrm{rcond}$ approaches $u$ this effect cannot be distinguished from estimation error.
An estimate categorized `Heuristic` being closer to the exact value than `ModelBased` in this example does not contradict the category definitions.
Categories describe kinds of evidence, not an accuracy ranking.

## Summary

When receiving an estimate, read its numerical `value()` together with the supporting category in `reliability()`.
`Heuristic` is an indicator, `ModelBased` uses a documented numerical model, and `StatisticallyCalibrated` uses a documented statistical procedure; none is a proven bound.
Because categories do not rank accuracy, determine where an estimate loses meaning from the method's error model, not its category (for singular value ratios, where $\mathrm{rcond}_2$ approaches $u$).
Use scioxide-validated enclosures for decisions requiring guaranteed inclusion of the true value.
Because `EstimateReliability` is `#[non_exhaustive]`, include a `_` arm in `match`.
