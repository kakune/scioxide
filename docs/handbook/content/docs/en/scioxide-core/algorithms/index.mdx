Algorithms in `scioxide-core` do not solve equations; they provide representations, accumulation, transformations, and contracts shared by solvers in other crates.
This page collects the shared notation and rules and maps the scope of each page.

## Notation

| Symbol | Meaning |
|---|---|
| $\varepsilon$ | Machine epsilon (`RealScalar::EPSILON`): the gap between 1 and the next larger floating-point number, $2^{-52}$ in double precision and $2^{-23}$ in single precision |
| $u = \varepsilon / 2$ | Unit roundoff: an upper bound on relative error from one round-to-nearest, ties-to-even operation |
| $\gamma_k = k u / (1 - k u)$ | An upper bound on relative error accumulated over $k$ roundings ($k u < 1$) |
| $\eta$ | The smallest positive subnormal number (`RealScalar::MIN_SUBNORMAL`): $2^{-1074}$ in double precision and $2^{-149}$ in single precision |
| ulp | The spacing between adjacent floating-point numbers at the exact value; $\eta$ in the subnormal range |
| $\tau_{\mathrm{abs}}, \tau_{\mathrm{rel}}$ | Absolute and relative tolerances |

$\gamma_k$ arises from the bound $(1 + u)^k - 1 \le \gamma_k$ after $k$ roundings with relative error at most $u$ (Higham, *Accuracy and Stability of Numerical Algorithms*, Chapter 3).
See [Floating-point numbers and condition numbers](../../concepts/floating-point-and-conditioning/) for floating-point structure and the general theory of conditioning.

## Accuracy contract categories

Functions in `scioxide-core` specify result accuracy in one of the following forms.
Distinguish them: even though each describes small error, the meanings differ.

| Category | Meaning | Examples |
|---|---|---|
| One rounding (0 ULP) | The mathematical value rounded once to nearest, ties to even | `checked_sum`, `checked_difference_of_products`, `RealScalar::sqrt` |
| $N$ ULP | An accuracy contract checked by tests; $\lvert \text{computed value} - \text{true value} \rvert \le N \cdot \mathrm{ulp}$ | Transcendental functions: 4 ULP; real stable transformations and real `logsumexp`: 16 ULP |
| Operation-count bound | A relative error bound expressed using $\gamma_k$ and $\eta$ | `checked_scaled_norm`, `checked_float_product_factors` |
| Residual bound | An upper bound on the residual after substituting the result into an equation; not a forward error guarantee | `checked_quadratic_roots` |
| Bound proportional to conditioning or a growth factor | An upper bound that grows in proportion to the problem condition number $\kappa$ or a function-specific growth factor | `weighted_logsumexp` with signed or complex weights; complex stable transformations |

Enclosing true values through interval arithmetic is outside `scioxide-core` and is provided by [scioxide-validated](../../scioxide-validated/).

## Failure and output rules

- Non-finite inputs return `NonFinite`; finite arguments outside the mathematical domain return `DomainError`; structurally invalid inputs return `InvalidInput`.
  An unrepresentable result from finite inputs returns `NumericalInstability` (such as `Overflow`).
- A successful result is never NaN.
  Infinity occurs only for documented mathematical limits, such as $-\infty$ from `logsumexp` on empty input.
- Predicates (such as tolerance comparisons) return `Ok(false)` for an unmet condition on valid input, rather than an error.
- Functions writing borrowed output (`*_into`) validate all inputs before writing, either producing a complete result or failing without modifying output.
  Work buffers may change on failure but can be reused as they are.
- Functions returning scalars (such as `checked_sum`, `logsumexp`, and `sin_pi`) and functions receiving sufficiently large workspaces do not allocate on the heap.
  Functions returning `Vec` (such as `softmax`) and construction of types owning tables, permutations, or colorings allocate and report allocation failures as `AllocationFailure`.

## Summary

When reading an algorithm page, first identify the kind of accuracy contract: one rounding, $N$ ULP, an operation-count bound, a residual bound, or a bound proportional to conditioning or a growth factor.
Failures are distinguished through `kind()` categories.
Functions writing borrowed output leave it unchanged on failure, so use `Result` to determine whether the output contains a new value.
If you only use solvers from other chapters, first read the tolerance and solve-accounting pages, then consult arithmetic, extended-range values, and logarithmic sums as needed.
If implementing your own operators or solvers, check workspace, output, and accounting contracts in the pages on borrowed layouts, operator protocols, execution policies, and nested solves.
When investigating an error, start with error categories and detailed views.
