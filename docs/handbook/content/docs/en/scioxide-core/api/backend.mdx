`scioxide_core::backend` exposes low-level contracts shared by SciOxide crates implementing their own kernels.
Application code rarely uses them directly, but many errors and guarantees in later APIs originate here.
Size and allocation functions name quantities through `Quantity` and report `SizeOverflow` or `AllocationFailure` without panicking.

## Real kernels and range-preserving accumulation

This section exposes real checked arithmetic and stable transformations for direct use by other crates' kernels.
Application computations should first choose higher-level checked arithmetic or stable transformations.

`real_*` evaluates corresponding real stable transformations in `f64` and rounds to `S`, returning failures as `ScalarKernelError` rather than `SciOxideError`.
`real_*` shares three error cases.
Non-finite input produces `NonFiniteInput`; failed `f64` evaluation or overflow produces `Overflow`; results outside `f32` produce `F32OutOfRange`.
Rows list only additional or different errors.

## Lanewise elementary functions

`lanes_*` evaluates one binary64 elementary function in each lane of a `[f64; W]` array.
Kernels use branch-free `IEEE` arithmetic and bit operations only, handling special values by selection.
No table lookups, branches, or fused multiply-adds.
Every lane performs identical operations, allowing vectorization for target features (SSE2 by default, AVX2 on recent x86-64 with `-C target-cpu=native`).
A lane's result depends only on its argument, remaining identical regardless of `W`, lane position, target environment, or FMA support.

Results are within 4 ULP of the exact value.
The last few ULP may differ from scalar `RealScalar` methods.
In tests against MPFR, `lanes_tanh` stays within 2 ULP of the correctly rounded value, and other functions within 1 ULP.

Each table row states its kernel domain.
Out-of-domain lanes return scalar-method results, including `IEEE` results for zero, infinity, and `NaN`.
Domain checking branches once per call, not per lane.
These functions do not fail or validate arguments.

## Summary

These items are building blocks for kernels implemented by SciOxide crates.
Application code should first consider root-level `checked_*` functions or stable transformations, consulting this namespace when implementing kernels that must preserve the same contracts.
Size and allocation functions report overflow and allocation failure through `SizeOverflow` and `AllocationFailure`.
`lanes_*` neither validates arguments nor fails; check each row's domain and 4 ULP accuracy before use.
