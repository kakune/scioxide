`scioxide-core` exposes scalar requirements, tolerances, domains, range-safe arithmetic, extended-range values, solve accounting, execution policies and capabilities, and operator protocols shared by other crates.
This guide identifies entry points by purpose.
Its 335 public items (227 at the root and 108 in the `backend` namespace) are organized in purpose-specific tables.
Item-name links point to the version 0.1.0 API reference on docs.rs.

## Entry points by purpose

Triangular orientation `Triangle` and diagonal representation `DiagonalKind` belong to scioxide-core.
Sparse storage and Hermitian structures belong to scioxide-sparse; numerical differentiation belongs to scioxide-differentiate.

## Type relationships

- `RealScalar` is a sealed trait implemented only by `f32` and `f64`.
  `NumericScalar` also forbids external implementations, with four implementations including `Complex<f32>` and `Complex<f64>`.
  `AlgebraicScalar` requires only field operations and permits implementations in other crates.
- Thresholds use `Tolerance` and role-specific wrappers; count limits use `Budget` and `SolveBudgets`.
  These are separate types.
- Obtain borrowed `SolveContext` from owned `SolveState` through `begin_solve`.
  Start child solves through `SolveScope`.
  Accounting separates `own()` and `nested()` in `SolveCounts`.
- Functions ending in `_scoped` take the caller's scope or context as their final argument and execute inside it.
  They obey caller cancellation and deadlines, with nested solves consuming caller limits.
  The `_scoped` methods of `LinearOperator`, `AdjointOperator`, and `Preconditioner` take `OperatorContext`.
  `OperatorContext` borrows `SolveContext` and may also carry a caller-resolved `DenseOperatorKernel`.
- `ExecutionPolicy` expresses parallelization intent.
  `ExecutionContext`, carrying an executor and capabilities, resolves it under `PlanLimits` into `ExecutionPlan`.
  Functions without context arguments use `ExecutionContext::sequential_native()`.
- `StridedLayout` borrows shape and strides; `NdView` / `NdViewMut` associate them with storage.
  Row-major layouts use `row_major` with shape alone.
  Axiswise normalization and log-sums (such as `softmax_axis_into` and `logsumexp_axis_into`) accept these views.
- `Scaled` (one component), `ScaledValue` (per-component scales), `ProjectiveValue` (shared exponent), and `LogValue` (phase and logarithm) share IEEE projection rules.

## Minimal example: three calling forms

The same computation has three calling forms.
Owned forms allocate and return results.
Borrowed forms (names ending in `_into`) write to caller-provided output and workspace.
Axiswise forms (`_axis_into`) take multidimensional views, execution policy `ExecutionPolicy`, and execution context `ExecutionContext`.

The following cell computes softmax of the two logarithms $c + \Delta$ and $c$ in all three forms.
Inputs are shared shift $c$ and logit difference $\Delta$, both dimensionless.
Outputs are probabilities $p_0$ and $p_1$ for each form, with the first probability's difference from the analytical value $p_0 = 1/(1 + e^{-\Delta})$.
Check agreement with the analytical value for every form and finite probabilities even when $e^{c}$ exceeds double-precision range at $c \ge 710$.
Pass `ExecutionContext::sequential_native()` to the axiswise form to match the context used by both context-free forms.

```rust
//| id: core-api-normalization-forms
//| ref: core-api-normalization-forms
//| title: "Computing softmax in owned, borrowed, and axiswise forms"
//| run: reactive
//| crates: [scioxide-core]
//| inputs:
//|   shift: {"type":"range","label":"Shared shift c [-]","description":"e^c overflows for c ≥ 710.","min":500,"max":1000,"step":50,"value":1000}
//|   logit_diff: {"type":"range","label":"Logit difference Δ [-]","description":"The second logarithm is c; the first is c + Δ.","min":0,"max":5,"step":0.5,"value":2}
//| cases:
//|   - {"id":"equal-logits","label":"Δ = 0","description":"Equal logarithms give probability 1/2 each.","inputs":{"logit_diff":0}}
//|   - {"id":"small-shift","label":"c = 500, Δ = 5","description":"The same formula applies when e^c is finite.","inputs":{"shift":500,"logit_diff":5}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"forms","path":"/rows/0/1","approx":{"value":0.8807970779778823,"atol":1e-12}}
//|       - {"artifact":"forms","path":"/rows/1/1","approx":{"value":0.8807970779778823,"atol":1e-12}}
//|       - {"artifact":"forms","path":"/rows/2/1","approx":{"value":0.8807970779778823,"atol":1e-12}}
//|       - {"artifact":"forms","path":"/rows/2/2","approx":{"value":0.11920292202211755,"atol":1e-12}}
//|       - {"artifact":"forms","path":"/rows/0/3","range":{"min":0,"max":1e-12}}
//|   - case: equal-logits
//|     expect:
//|       - {"artifact":"forms","path":"/rows/0/1","approx":{"value":0.5,"atol":1e-12}}
//|       - {"artifact":"forms","path":"/rows/1/2","approx":{"value":0.5,"atol":1e-12}}
//|       - {"artifact":"forms","path":"/rows/2/1","approx":{"value":0.5,"atol":1e-12}}
//|   - case: small-shift
//|     expect:
//|       - {"artifact":"forms","path":"/rows/0/1","approx":{"value":0.9933071490757153,"atol":1e-12}}
//|       - {"artifact":"forms","path":"/rows/1/1","approx":{"value":0.9933071490757153,"atol":1e-12}}
//|       - {"artifact":"forms","path":"/rows/2/1","approx":{"value":0.9933071490757153,"atol":1e-12}}
use scioxide_core::{
    ExecutionContext, ExecutionPolicy, NdView, NdViewMut, softmax, softmax_axis_into,
    softmax_into,
};

let logits = [shift + logit_diff, shift];
// Owned form: allocate and return the result Vec.
let owned = softmax(&logits).map_err(|e| e.to_string())?;
// Borrowed form: the caller supplies output and workspace.
let mut borrowed = [0.0; 2];
let mut scratch = [0.0; 2];
softmax_into(&logits, &mut borrowed, &mut scratch).map_err(|e| e.to_string())?;
// Axiswise form: supply row-major views, axis, policy, output, workspace, and execution context.
let shape = [2];
let mut along_axis = [0.0; 2];
softmax_axis_into(
    NdView::row_major(&logits, &shape).map_err(|e| e.to_string())?,
    0,
    ExecutionPolicy::Sequential,
    NdViewMut::row_major(&mut along_axis, &shape).map_err(|e| e.to_string())?,
    &mut scratch,
    ExecutionContext::sequential_native(),
)
.map_err(|e| e.to_string())?;

// Analytical value (a reference computed with intrinsic f64 methods).
let expected = 1.0 / (1.0 + (-logit_diff).exp());
let digits = serde_json::json!({ "significantDigits": 15 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "Form" },
    { "key": "1", "label": "p₀ [-]", "type": "number", "format": digits },
    { "key": "2", "label": "p₁ [-]", "type": "number", "format": digits },
    { "key": "3", "label": "|p₀ − analytical value| [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    vec![
        (
            "softmax (owned)",
            owned[0],
            owned[1],
            (owned[0] - expected).abs(),
        ),
        (
            "softmax_into (borrowed)",
            borrowed[0],
            borrowed[1],
            (borrowed[0] - expected).abs(),
        ),
        (
            "softmax_axis_into (axiswise)",
            along_axis[0],
            along_axis[1],
            (along_axis[0] - expected).abs(),
        ),
    ],
    metadata = serde_json::json!({ "id": "forms" })
);
```

Each table row is one form; the last column is the difference from the analytical value.
At the defaults ($c = 1000$, $\Delta = 2$), all three give $p_0 \approx 0.8808$ and $p_1 \approx 0.1192$, with the first probability's differences from its analytical value below $10^{-12}$.
Although $e^{1000}$ cannot be represented in double precision, every form subtracts the maximum logarithm before exponentiation, so probabilities depend only on $\Delta$.
At $\Delta = 0$, each probability is $0.5$; at $c = 500$ and $\Delta = 5$ the first probability is $p_0 \approx 0.9933$.

## Reading results, errors, and diagnostics

- Failures return the opaque `SciOxideError` type.
  Classify through the `SciOxideErrorKind` of `kind()` (20 kinds), then read arguments (`Argument`), quantities (`Quantity`), reasons, and details from the `SciOxideErrorView` of `view()`.
  Read `ConvergenceFailure` diagnostics (counts, limits, residuals, and others) through borrowed view `ConvergenceDiagnosticsView`.
  Errors retain no caller identifier.
  [Error categories and detailed views](../algorithms/errors-and-diagnostic-views/) explains category-specific interpretation.
- Valid inputs failing a predicate such as a tolerance comparison return `Ok(false)` rather than an error.
- Limit-based rejection returns values such as `Admission::Denied` or `Invocation::BudgetExhausted`.
  Cancellation and deadline stops return `Invocation::ExecutionStopped` as values.
  Only boundaries calling `require()` convert these into `ConvergenceFailure` and `ExecutionStopped` errors, respectively.
- Borrowed functions validate every input before writing output.
  They either write a complete result or fail with output unchanged.
  Workspace contents may change on failure.
- Individual contracts specify one rounding, $N$ ULP, a $\gamma_k$ bound, residual bounds, or similar guarantees.
  [The mathematics of the shared foundation](oxref:core-accuracy-contracts) distinguishes these categories.
