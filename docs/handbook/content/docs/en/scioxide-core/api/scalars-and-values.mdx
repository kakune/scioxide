These tables collect computational value types and the traits defining their bounds.
`RealScalar` and `NumericScalar` forbid external implementations, so only SciOxide-defined types implement them.
`RealScalar` covers `f32` and `f64`; `NumericScalar` adds `Complex<f32>` and `Complex<f64>` for four types.
[Extended-range values and logarithmic and projective representations](../../algorithms/extended-range-values/) explains these representations and IEEE projection rules.
[Elementary functions and stable transformations](oxref:core-scalar-hierarchy) explains the scalar hierarchy.

| [`FloatDecomposition`](https://docs.rs/scioxide-core/0.1.0/scioxide_core/enum.FloatDecomposition.html) | Enum | Exact decomposition of IEEE values into sign, integer significand, and binary exponent | `Finite { significand, exponent, negative }`, `Infinite { negative }`, `Nan`. | [`Complex`](https://docs.rs/scioxide-core/0.1.0/scioxide_core/struct.Complex.html) | Struct | Pair of real part `re` and imaginary part `im` | Elementary function component errors are at most $16\varepsilon\max(\lvert \operatorname{Re} w \rvert, \lvert \operatorname{Im} w \rvert)\,g$ for exact result $w$ ($g \ge 1$ is a function-specific growth factor). ## Extended-range values

| Item | Kind | Role | Contract essentials | Explanation | Executable example |
|---|---|---|---|---|---|
| [`Scaled`](https://docs.rs/scioxide-core/0.1.0/scioxide_core/struct.Scaled.html) | Struct | Real value represented by $m \cdot 2^{e}$ ($1 \le \lvert m \rvert < 2$, with $e$ of type `i64`) | Basic arithmetic, square roots, and differences of products round the exact result once to significand precision. No allocation. Exponents exceeding `i64` produce `ExponentOutOfRange`. Project to IEEE through `round` allowing gradual underflow, or `try_value` rejecting nonzero values rounded to zero with `Underflow`. Both return `Overflow` for results rounding to infinity | [Binary-normalized Scaled values](oxref:core-scaled) | [Computing n! in extended range and comparing with the Stirling series](oxref:core-scaled-factorial), [Recovering a one hidden by large terms through compensated summation](oxref:core-scaled-accumulator-vs-exact) |
| [`ScaledValue`](https://docs.rs/scioxide-core/0.1.0/scioxide_core/struct.ScaledValue.html) | Struct | Real or complex values with per-component scales | Converts finite IEEE values while preserving their bits. Addition, subtraction, and differences of products round once per component. Complex quotients have componentwise relative error at most $\gamma_3 = 3u/(1 - 3u)$ before IEEE projection ($u = \varepsilon/2$). `try_projective` converts to shared-exponent coordinates | [Per-component scales in ScaledValue and shared exponents in ProjectiveValue](oxref:core-scaled-and-projective-values) | [Component scale disparities and conversion to shared exponents](oxref:core-projective-frame) |
| [`ScaledAccumulator`](https://docs.rs/scioxide-core/0.1.0/scioxide_core/struct.ScaledAccumulator.html) | Struct | Compensated summation of `Scaled` (Neumaier) | Holds a running sum and correction with `i64` exponents. Failed updates leave the sum unchanged. Products are rounded before addition. Neither correct rounding nor sign correctness is guaranteed (use `RangeAccumulator` if needed). If `absorbs(exponent)` is `true`, adding values with exponents no larger than it leaves both sum and correction unchanged. `false` does not imply that adding a value changes the sum | [Compensated summation with ScaledAccumulator](oxref:core-scaled-accumulator) | [Recovering a one hidden by large terms through compensated summation](oxref:core-scaled-accumulator-vs-exact), [Summing the harmonic series in single precision four ways](oxref:core-harmonic-series-summation) |
| [`ProjectiveValue`](https://docs.rs/scioxide-core/0.1.0/scioxide_core/struct.ProjectiveValue.html) | Struct | Coordinates whose components share one binary exponent | The largest nonzero component magnitude lies in $[1, 2)$; preserves signed-zero components. Construct through `ScaledValue::try_projective`. A nonzero component becoming zero fails with `Underflow`; lost significand bits fail with `LossOfSignificance`. Defines no arithmetic | [Per-component scales in ScaledValue and shared exponents in ProjectiveValue](oxref:core-scaled-and-projective-values) | - |
| [`LogValue`](https://docs.rs/scioxide-core/0.1.0/scioxide_core/struct.LogValue.html) | Struct | A value representing $p\,e^{\ell}$ through unit-magnitude phase $p$ and finite natural logarithm $\ell$ | Zero is a separate state without a logarithm (`ZERO`). `from_log` rejects real phases other than $\pm 1$ and complex phases satisfying $\lvert \lvert p \rvert - 1 \rvert > 16\varepsilon$ with `InvalidInput`. `from_value` rounds the logarithm. `round` permits gradual underflow; `try_value` rejects nonzero components rounded to zero with `Underflow`. No allocation | [Logarithmic representation with LogValue](oxref:core-log-value) | [Axiswise logarithmic and weighted logarithmic sums](oxref:core-axis-logsumexp) |
| [`ValueAndDerivative`](https://docs.rs/scioxide-core/0.1.0/scioxide_core/struct.ValueAndDerivative.html) | Struct | A value/derivative pair obtained from one evaluation | `new`, `value()`, `derivative()`, `into_parts()`. Performs no value validation | [Value/derivative pairs with ValueAndDerivative](oxref:core-value-and-derivative) | - |

## Summary

Use `RealScalar` bounds for real computations and `NumericScalar` when complex numbers are also supported.
Choose `Scaled` or `ScaledValue` when intermediates exceed exponent range, or `LogValue` for logarithmic representations.
Use projections such as `try_value` to return to IEEE types and receive errors for range overflow or lost digits.
Borrow affine components through `AffineValue` and use `affine_combination_into` for single-rounding linear combinations.
