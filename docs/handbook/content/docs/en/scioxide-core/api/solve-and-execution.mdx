These tables collect iterative solve lifetimes and accounting, execution policies, and foundation capabilities.
Owned `SolveState` holds state; `SolveContext` borrows it for one solve to perform resource admission and accounting.
Pass execution intent `ExecutionPolicy` separately from `ExecutionContext` carrying an executor and clock.
Functions without context arguments use `ExecutionContext::sequential_native()`.
Functions ending in `_scoped` take the caller's scope or context last and obey its cancellation, deadlines, and limits.

## Summary

Iterative solvers keep state in `SolveState`, obtain admission through `SolveContext`, then count evaluations or iterations.
For nested solves, pass `SolveScope` to `_scoped` functions to consume shared limits.
Pass parallelization intent through `ExecutionPolicy` and executors, cancellation, and clocks through `ExecutionContext`.
In environments such as wasm32 without an executor or clock, use sequential contexts and set time limits only with a custom injected clock.
