Even when the final answer fits double precision, out-of-range intermediates or small terms lost to rounding can produce zero, `inf`, or `NaN`.
This example recomputes three such failures through range-safe `scioxide-core` arithmetic and compares each with an independently obtained value.
[Exact accumulation and range-safe arithmetic](../../algorithms/range-safe-arithmetic/) collects their accuracy contracts.

## Small terms between large terms

Consider $N + 2$ terms in order: $A$, $N$ copies of $s$, and $-A$.
The mathematical sum is $N s$.
When spacing in double precision near $A$ exceeds $2s$, every left-to-right addition rounds away $s$.
At spacing exactly $2s$, $A + s$ is a midpoint; the lowest significand bit of $A$ decides whether ties-to-even rounding returns $A$ or the next number.
Sorting by increasing magnitude forms $N s$ first, but adding $A$ afterward still incurs rounding.

`checked_sum` rounds the exact sum once, independently of term order.
The reference computes $N \times s$ with one double multiplication.
Since $N$ is exactly representable, this product correctly rounds $N$ times input $s$ (the double rounded from $10^p$), and should match `checked_sum` bit for bit.

Inputs are large-term exponent $\log_{10} A$ (12–20), small-term exponent $\log_{10} s$ ($-2$–2), and small-term count $N$ (1–1000).
The table shows three sums and differences from reference $N s$.

```rust
//| id: core-range-safe-sum
//| ref: core-range-safe-sum
//| title: "N small terms between large terms"
//| run: reactive
//| crates: [scioxide-core]
//| inputs:
//|   large_exp: {"type":"range","label":"Large term exponent log₁₀ A [-]","description":"Place terms between A and −A.","min":12,"max":20,"step":1,"value":16}
//|   small_exp: {"type":"range","label":"Small term exponent log₁₀ s [-]","description":"Repeat s = 10^p N times.","min":-2,"max":2,"step":1,"value":0}
//|   count: {"type":"range","label":"Small term count N [terms]","description":"The sum reference is N s.","min":1,"max":1000,"step":1,"value":999}
//| cases:
//|   - {"id":"even-count","label":"N = 1000","description":"A + N s fits double precision, removing the sorted sum discrepancy.","inputs":{"count":1000}}
//|   - {"id":"huge-term","label":"A = 10²⁰","description":"Even sorted summation absorbs N s into A.","inputs":{"large_exp":20}}
//|   - {"id":"inexact-term","label":"A = 10¹², s = 0.01","description":"s is not binary-representable and rounds at every addition.","inputs":{"large_exp":12,"small_exp":-2,"count":1000}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"sums","path":"/rows/0/1","equals":0}
//|       - {"artifact":"sums","path":"/rows/1/1","equals":1000}
//|       - {"artifact":"sums","path":"/rows/2/1","equals":999}
//|       - {"artifact":"sums","path":"/rows/2/2","equals":0}
//|   - case: even-count
//|     expect:
//|       - {"artifact":"sums","path":"/rows/1/2","equals":0}
//|       - {"artifact":"sums","path":"/rows/2/2","equals":0}
//|   - case: huge-term
//|     expect:
//|       - {"artifact":"sums","path":"/rows/1/1","equals":0}
//|       - {"artifact":"sums","path":"/rows/2/1","equals":999}
//|   - case: inexact-term
//|     expect:
//|       - {"artifact":"sums","path":"/rows/2/1","approx":{"value":10,"rtol":1e-15}}
//|       - {"artifact":"sums","path":"/rows/2/2","equals":0}
use scioxide_core::{RealScalar, checked_sum};

let a = RealScalar::powi(10.0_f64, large_exp as i32);
let s = RealScalar::powi(10.0_f64, small_exp as i32);
let n = count as usize;
let mut terms = vec![a];
terms.extend(std::iter::repeat_n(s, n));
terms.push(-a);

// Compare left-to-right summation with summation after sorting by increasing magnitude.
let left_to_right: f64 = terms.iter().sum();
let mut sorted = terms.clone();
sorted.sort_by(|x, y| x.abs().total_cmp(&y.abs()));
let ascending: f64 = sorted.iter().sum();
let exact = checked_sum(&terms).map_err(|e| e.to_string())?;
// Reference: N s correctly rounded by one multiplication.
let reference = n as f64 * s;
let digits = serde_json::json!({ "significantDigits": 12 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "Method" },
    { "key": "1", "label": "Sum [-]", "type": "number", "format": digits },
    { "key": "2", "label": "Sum − N s [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    vec![
        ("Left-to-right", left_to_right, left_to_right - reference),
        ("Increasing magnitude", ascending, ascending - reference),
        ("checked_sum", exact, exact - reference),
    ],
    metadata = serde_json::json!({ "id": "sums" })
);
```

At the defaults $A = 10^{16}$, $s = 1$, and $N = 999$, spacing near $A$ is 2 and $A + 1$ is a midpoint.
The significand of $10^{16}$ is even, so each left-to-right addition returns $A$; all ones are lost, giving zero.
Sorted summation first forms 999, but ties-to-even rounds $10^{16} + 999$ to $10^{16} + 1000$, giving 1000, one too large.
At $N = 1000$ this discrepancy disappears; at $A = 10^{20}$ (spacing 16384), even sorted summation gives zero.
With $A = 10^{12}$, $s = 0.01$, and $N = 1000$, rounding at spacing $1.2 \times 10^{-4}$ near $A$ accumulates, giving left-to-right sum 10.0098.
`checked_sum` has zero reference difference under every setting.

## Norms with overflowing or underflowing components

A vector of $n$ components, all equal to $x = 10^{q}$, has norm $\sqrt{n}\, 10^{q}$.
Direct $\sqrt{\sum_i x_i^2}$ makes $x^2$ exceed the largest double and become `inf` at $q \ge 155$; at $q \le -162$, $x^2$ rounds to zero and gives zero norm.
At $-161 \le q \le -154$, $x^2$ is subnormal, losing significand digits without becoming zero.
The norm itself remains a normal double throughout the cell's input range.

`checked_scaled_norm` sums squared ratios after division by the largest component, avoiding both failures.
The reference multiplies $\sqrt{n}$ by $x$ in double precision, with relative error of order $\varepsilon$.
The `checked_scaled_norm` bound is $\gamma_{8n+8}\,\lVert \mathbf{x} \rVert + \eta/2$ using nonzero component count $m = n$ ($\gamma_k = ku/(1 - ku)$, $u = \varepsilon/2$, smallest positive subnormal $\eta$).

Inputs are component exponent $q$ ($-200$–300 in steps of 5) and component count $n$ (2–64).
The table shows direct computation, `checked_scaled_norm`, the reference, the latter pair's difference, and the bound.
A direct result of `inf` appears as a missing value.

```rust
//| id: core-range-safe-norm
//| ref: core-range-safe-norm
//| title: "Norms when component squares exceed the range"
//| run: reactive
//| crates: [scioxide-core]
//| inputs:
//|   norm_exponent: {"type":"range","label":"Component exponent q [-]","description":"x = 10^q. Squares overflow for q ≥ 155 and round to zero for q ≤ −162.","min":-200,"max":300,"step":5,"value":200}
//|   length: {"type":"range","label":"Component count n [components]","description":"The norm is √n · 10^q.","min":2,"max":64,"step":1,"value":8}
//| cases:
//|   - {"id":"underflow","label":"q = −180","description":"Squares round to zero.","inputs":{"norm_exponent":-180}}
//|   - {"id":"subnormal-squares","label":"q = −160","description":"Squares become subnormal; direct computation loses digits.","inputs":{"norm_exponent":-160}}
//|   - {"id":"ordinary","label":"q = 0, n = 64","description":"No range issue; all three values agree.","inputs":{"norm_exponent":0,"length":64}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"norms","path":"/rows/0/0","equals":null}
//|       - {"artifact":"norms","path":"/rows/0/1","approx":{"value":2.8284271247461903e200,"rtol":1e-14}}
//|       - {"artifact":"norms","path":"/rows/0/3","range":{"min":0,"max":2.3e186}}
//|   - case: underflow
//|     expect:
//|       - {"artifact":"norms","path":"/rows/0/0","equals":0}
//|       - {"artifact":"norms","path":"/rows/0/1","approx":{"value":2.8284271247461903e-180,"rtol":1e-14}}
//|   - case: subnormal-squares
//|     expect:
//|       - {"artifact":"norms","path":"/rows/0/1","approx":{"value":2.8284271247461903e-160,"rtol":1e-14}}
//|   - case: ordinary
//|     expect:
//|       - {"artifact":"norms","path":"/rows/0/0","equals":8}
//|       - {"artifact":"norms","path":"/rows/0/1","equals":8}
use scioxide_core::{RealScalar, checked_scaled_norm};

let x = RealScalar::powi(10.0_f64, norm_exponent as i32);
let n = length as usize;
let values = vec![x; n];
// Comparison: evaluate the square root of the sum of squares directly, showing inf as None.
let naive = RealScalar::sqrt(values.iter().map(|v| v * v).sum::<f64>());
let naive = naive.is_finite().then_some(naive);
let scaled = checked_scaled_norm(&values).map_err(|e| e.to_string())?;
// Reference: √n · x (two roundings, for square root and product).
let reference = RealScalar::sqrt(n as f64) * x;
// Error bound γ_k‖x‖ + η/2 (k = 8n + 8, u = ε/2).
let k = (8 * n + 8) as f64;
let u = f64::EPSILON / 2.0;
let bound = k * u / (1.0 - k * u) * reference + f64::from_bits(1) / 2.0;
let digits = serde_json::json!({ "notation": "scientific", "significantDigits": 15 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "√(Σ x²) [-]", "type": "number", "format": digits, "nullText": "inf" },
    { "key": "1", "label": "checked_scaled_norm [-]", "type": "number", "format": digits },
    { "key": "2", "label": "Reference √n · x [-]", "type": "number", "format": digits },
    { "key": "3", "label": "|checked − reference| [-]", "type": "number", "format": sci3 },
    { "key": "4", "label": "Error bound [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    vec![(naive, scaled, reference, (scaled - reference).abs(), bound)],
    metadata = serde_json::json!({ "id": "norms" })
);
```

At the default $q = 200$, direct computation gives `inf`; at $q = -180$ it gives zero.
At $q = -160$, $x^2 = 10^{-320}$ is subnormal and direct computation gives $2.82841 \times 10^{-160}$, losing accuracy from the sixth digit onward.
For all these inputs, `checked_scaled_norm` has zero difference from reference $\sqrt{8} \times 10^{q}$ and is within its bound (about $8 \times 10^{-15}$ times the reference).
With $q = 0$ and $n = 64$, no range issue arises and all three values equal 8.

## Binomial probabilities

For $n$ tosses of a coin with heads probability $p$, the probability of exactly $k$ heads is

$$
P(k) = C(n, k)\, p^{k} (1 - p)^{n - k}
$$


At $n = 2000$, $k = 1000$, and $p = 1/2$, it is $P \approx 0.0178$, but in double precision, $C(2000, 1000) \approx 2 \times 10^{600}$ becomes `inf` and stays `inf` even after multiplying by $2^{-1000} \approx 9 \times 10^{-302}$.
Conversely, combining powers $p^k (1-p)^{n-k} = 2^{-2000}$ first gives zero.

`checked_float_product_factors` separates significands and exponents, adds exponents separately, and restores scale once, keeping intermediate products in range.
Factors are $C(n, k)$ split into $\prod_{i=0}^{k-1} (n - i)/(i + 1)$, $k$ copies of $p$, and $n - k$ copies of $1 - p$, totaling $n + k$.
Relative error against the product of supplied factors is at most $\gamma_{n+k-1} \approx (n + k)\,u$.
Rounding in each factor's division $(n - i)/(i + 1)$ separately adds relative error at most $u$ per factor.

The independent reference sums logarithms $\ln P = \sum \ln(\text{factors})$ through `RangeAccumulator`, then exponentiates.
Logarithmic summation avoids range problems, but individual logarithm rounding remains in the sum and becomes relative error after exponentiation.
The difference therefore includes both computations' errors.

Inputs are trial count $n$ (100–3000 in steps of 100) and heads probability $p$ (10%–90% in steps of 5%); $k$ is nearest to $np$.
The table shows $k$, ordinary double binomial coefficients and probabilities, `checked_float_product_factors`, the reference, and their relative difference.
Non-finite ordinary computation appears as a missing value.

```rust
//| id: core-range-safe-binomial
//| ref: core-range-safe-binomial
//| title: "Binomial probabilities with out-of-range intermediates"
//| run: reactive
//| crates: [scioxide-core]
//| inputs:
//|   trials: {"type":"range","label":"Trial count n [trials]","description":"Larger n drives C(n, k) and p^k out of range.","min":100,"max":3000,"step":100,"value":2000}
//|   success_percent: {"type":"range","label":"Heads probability p [%]","description":"k is the nearest integer to n p.","min":10,"max":90,"step":5,"value":50}
//| cases:
//|   - {"id":"small-n","label":"n = 100","description":"Ordinary double computation is also finite.","inputs":{"trials":100}}
//|   - {"id":"skewed","label":"n = 3000, p = 10 %","description":"The distribution peaks at k = 300.","inputs":{"trials":3000,"success_percent":10}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"binomial","path":"/rows/0/0","equals":1000}
//|       - {"artifact":"binomial","path":"/rows/0/1","equals":null}
//|       - {"artifact":"binomial","path":"/rows/0/3","approx":{"value":0.01783901114585432,"rtol":1e-12}}
//|       - {"artifact":"binomial","path":"/rows/0/5","range":{"min":0,"max":1e-11}}
//|   - case: small-n
//|     expect:
//|       - {"artifact":"binomial","path":"/rows/0/2","approx":{"value":0.07958923738717877,"rtol":1e-10}}
//|       - {"artifact":"binomial","path":"/rows/0/3","approx":{"value":0.07958923738717877,"rtol":1e-12}}
//|   - case: skewed
//|     expect:
//|       - {"artifact":"binomial","path":"/rows/0/0","equals":300}
//|       - {"artifact":"binomial","path":"/rows/0/3","approx":{"value":0.02427,"rtol":1e-3}}
//|       - {"artifact":"binomial","path":"/rows/0/5","range":{"min":0,"max":1e-11}}
use scioxide_core::{RangeAccumulator, RealScalar, checked_float_product_factors};

let n = trials as usize;
let p = success_percent / 100.0;
let k = RealScalar::round(n as f64 * p) as usize;
// Factors: k copies of (n − i)/(i + 1), k of p, and n − k of 1 − p.
let mut factors: Vec<f64> = (0..k).map(|i| (n - i) as f64 / (i + 1) as f64).collect();
factors.extend(std::iter::repeat_n(p, k));
factors.extend(std::iter::repeat_n(1.0 - p, n - k));

let probability = checked_float_product_factors(&factors).map_err(|e| e.to_string())?;
// Compare separately computed double binomial coefficients and powers, replacing non-finite values with None.
let binomial: f64 = factors[..k].iter().product();
let powers = RealScalar::powi(p, k as i32) * RealScalar::powi(1.0 - p, (n - k) as i32);
let naive = binomial * powers;
// Independent reference: accumulate logarithms exactly, then exponentiate.
let mut log_sum = RangeAccumulator::new();
for &factor in &factors {
    log_sum
        .add(RealScalar::ln(factor))
        .map_err(|e| e.to_string())?;
}
let reference = RealScalar::exp(log_sum.finish().map_err(|e| e.to_string())?);
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let digits = serde_json::json!({ "notation": "scientific", "significantDigits": 13 });
let columns = serde_json::json!([
    { "key": "0", "label": "k [heads]", "type": "integer" },
    {
        "key": "1",
        "label": "C(n, k) (double product) [-]",
        "type": "number",
        "format": sci3,
        "nullText": "inf"
    },
    {
        "key": "2",
        "label": "Ordinary double probability [-]",
        "type": "number",
        "format": digits,
        "nullText": "Non-finite"
    },
    {
        "key": "3",
        "label": "checked_float_product_factors [-]",
        "type": "number",
        "format": digits
    },
    { "key": "4", "label": "Reference exp(Σ ln factors) [-]", "type": "number", "format": digits },
    { "key": "5", "label": "Relative difference [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    vec![(
        k as u32,
        binomial.is_finite().then_some(binomial),
        naive.is_finite().then_some(naive),
        probability,
        reference,
        (probability - reference).abs() / reference,
    )],
    metadata = serde_json::json!({ "id": "binomial" })
);
```

At the defaults $n = 2000$ and $p = 0.5$, both the ordinary binomial coefficient and probability are non-finite; `checked_float_product_factors` returns $P = 1.78390111459 \times 10^{-2}$.
This agrees to the displayed digits with $C(2000, 1000)/2^{2000} = 1.78390111459 \times 10^{-2}$ computed using integer arithmetic.
Relative reference difference is of order $4 \times 10^{-14}$, below factor count times unit roundoff $(n + k)\,u \approx 3.3 \times 10^{-13}$.
Reducing to $n = 100$ makes ordinary computation finite, with all three agreeing through $7.9589237387 \times 10^{-2}$.
At $n = 3000$ and $p = 10\,\%$, $k = 300$; the binomial coefficient again becomes `inf`, but `checked_float_product_factors` returns $2.4272 \times 10^{-2}$ with relative reference difference still of order $4 \times 10^{-14}$.

## Summary

Intermediate ranges and small terms lost to rounding are difficult to detect from final results alone.
Use `checked_sum` for differently scaled sums, `checked_scaled_norm` for vectors with extreme components, and `checked_float_product_factors` for products with out-of-range factors to avoid intermediate failures when the final result fits.
Single-rounding sums, $\gamma_{8m+8}$ norm bounds, and $\gamma_{n-1}$ product bounds let you estimate before computation whether accuracy suffices from component or factor counts.
Reordering and manual scaling can improve results but do not guarantee correct answers for every input.
