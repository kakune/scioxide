`scioxide-core` is not a crate for solving equations; it is the lowest-level crate defining the types and rules that let all other crates compute under the same assumptions.
It defines once how to test tolerances, represent variable ranges, avoid overflow in intermediate values, count and limit iterations and evaluations, and specify parallelism or stopping.
[scioxide-differentiate](../scioxide-differentiate/algorithms/) provides numerical differentiation, [scioxide-ad](../scioxide-ad/) automatic differentiation, and [scioxide-linalg](../scioxide-linalg/) and [scioxide-sparse](../scioxide-sparse/) matrix factorizations and iterative methods; all use the types in this chapter.

## First computation: testing a tolerance

`Tolerance` is the basic type for deciding when to stop iteration or accept a result.
`Tolerance` pairs absolute tolerance $\tau_{\mathrm{abs}}$ with relative tolerance $\tau_{\mathrm{rel}}$ and accepts a quantity of magnitude $m \ge 0$ at representative scale $s \ge 0$

$$
m \le \tau(s) = \tau_{\mathrm{abs}} + \tau_{\mathrm{rel}}\, s
$$

when this inequality holds.
$\tau_{\mathrm{abs}}$ has the same units as the quantity being assessed, while $\tau_{\mathrm{rel}}$ is dimensionless.
The terms are equal at $s_\times = \tau_{\mathrm{abs}} / \tau_{\mathrm{rel}}$: the absolute term dominates for smaller $s$, and the relative term dominates for larger $s$.

`Tolerance::new(absolute, relative)` rejects negative values as `InvalidInput` and NaN or infinity as `NonFinite`.
`threshold(scale)` returns $\tau(s)$.
`is_residual_ok(residual_norm, problem_scale)` tests whether residual $r$ satisfies $r \le \tau(s)$, returning `Ok(false)` rather than an error when it does not.

The following cell takes $\tau_{\mathrm{abs}}$, $\tau_{\mathrm{rel}}$, representative scale $s$, and residual $r$ as inputs, and displays the threshold, crossover scale $s_\times$, margin $\tau(s) - r$, and decision in one table row.
All four inputs are dimensionless in this example; $s$ and $r$ are nonnegative, and both tolerances vary over positive ranges.
Check that `threshold` agrees with the formula $\tau_{\mathrm{abs}} + \tau_{\mathrm{rel}} s$ and that the decision agrees with the sign of the margin.

```rust
//| id: core-first-contract
//| ref: core-first-contract
//| title: "Tolerance thresholds and residual acceptance"
//| run: reactive
//| crates: [scioxide-core]
//| inputs:
//|   abs_tol: {"type":"range","label":"Absolute tolerance τ_abs [-]","description":"The same units as the quantity being assessed.","min":0.001,"max":0.05,"step":0.001,"value":0.01}
//|   rel_tol: {"type":"range","label":"Relative tolerance τ_rel [-]","description":"Dimensionless.","min":0.001,"max":0.05,"step":0.001,"value":0.02}
//|   scale: {"type":"range","label":"Representative scale s [-]","description":"Nonnegative.","min":0,"max":10,"step":0.5,"value":2}
//|   residual: {"type":"range","label":"Residual r [-]","description":"Nonnegative.","min":0,"max":0.15,"step":0.005,"value":0.04}
//| cases:
//|   - {"id":"rejected","label":"r = 0.06","description":"The residual exceeds the threshold 0.05, so the decision is false.","inputs":{"residual":0.06}}
//|   - {"id":"zero-scale","label":"s = 0","description":"The relative term vanishes, leaving only τ_abs as the threshold.","inputs":{"scale":0}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"decision","path":"/rows/0/0","approx":{"value":0.05,"rtol":1e-12}}
//|       - {"artifact":"decision","path":"/rows/0/1","approx":{"value":0.5,"rtol":1e-12}}
//|       - {"artifact":"decision","path":"/rows/0/3","approx":{"value":0.01,"atol":1e-12}}
//|       - {"artifact":"decision","path":"/rows/0/4","equals":"true"}
//|   - case: rejected
//|     expect:
//|       - {"artifact":"decision","path":"/rows/0/3","approx":{"value":-0.01,"atol":1e-12}}
//|       - {"artifact":"decision","path":"/rows/0/4","equals":"false"}
//|   - case: zero-scale
//|     expect:
//|       - {"artifact":"decision","path":"/rows/0/0","approx":{"value":0.01,"rtol":1e-12}}
//|       - {"artifact":"decision","path":"/rows/0/4","equals":"false"}
use scioxide_core::Tolerance;

let tolerance = Tolerance::new(abs_tol, rel_tol).map_err(|e| e.to_string())?;
let threshold = tolerance.threshold(scale).map_err(|e| e.to_string())?;
let accepted = tolerance
    .is_residual_ok(residual, scale)
    .map_err(|e| e.to_string())?;

let fixed4 = serde_json::json!({ "fractionDigits": 4 });
let columns = serde_json::json!([
    { "key": "0", "label": "Threshold τ(s) [-]", "type": "number", "format": fixed4 },
    { "key": "1", "label": "Crossover scale s× [-]", "type": "number", "format": fixed4 },
    { "key": "2", "label": "Residual r [-]", "type": "number", "format": fixed4 },
    { "key": "3", "label": "Margin τ(s) − r [-]", "type": "number", "format": fixed4 },
    { "key": "4", "label": "is_residual_ok(r, s)" }
]);
emit_table_with_columns!(
    columns,
    vec![(
        threshold,
        abs_tol / rel_tol,
        residual,
        threshold - residual,
        accepted.to_string(),
    )],
    metadata = serde_json::json!({ "id": "decision" })
);
```

At the defaults, $\tau(2) = 0.01 + 0.02 \times 2 = 0.05$, and residual $0.04$ is accepted with margin $0.01$.
The crossover scale is $s_\times = 0.01 / 0.02 = 0.5$, so at $s = 2$ the relative term accounts for 80% of the threshold.
Increasing the residual to $0.06$ makes the margin $-0.01$ and changes the decision to `false`.
Here `is_residual_ok` returns `Ok(false)`, and the cell does not fail.
Keeping the residual at $0.06$ while increasing the scale to at least $2.5$ raises the threshold to at least $0.06$ and restores acceptance.
At $s = 0$, the relative term vanishes, leaving threshold $\tau_{\mathrm{abs}} = 0.01$, and residual $0.04$ is not accepted.

## Reading results

Functions in `scioxide-core` return invalid inputs and numerical failures as `Result` errors, and express an unmet condition for valid inputs as values such as `Ok(false)`.
The error type `SciOxideError` keeps its internal representation private.
Read the category (20 kinds, including `InvalidInput`, `NonFinite`, `DomainError`, and `NumericalInstability`) through `kind()`, and details such as arguments, quantities, and reasons through `view()`.
[Error categories and detailed views](algorithms/errors-and-diagnostic-views/) explains how to read the details for each category.

Numerical accuracy is specified per function in forms such as "one rounding," "$N$ ULP," or "residual bound."
[The mathematics of the shared foundation](algorithms/) summarizes the distinctions between these kinds of contracts.

## Summary

`scioxide-core` defines the shared types and rules for five areas: tolerances, domains, limits, arithmetic, and execution.
It distinguishes thresholds expressed by $\tau_{\mathrm{abs}} + \tau_{\mathrm{rel}} s$, unmet thresholds expressed by `Ok(false)`, and invalid inputs expressed by `Err`.
When receiving `Err`, inspect its category through `kind()` and its argument or reason through `view()`.
Computations affected by intermediate range or rounding issues can be reformulated using range-safe arithmetic, extended-range values, or logarithmic sums.
