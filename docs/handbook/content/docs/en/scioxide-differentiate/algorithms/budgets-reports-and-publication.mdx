When differentiating inside optimization or time evolution, it may be necessary to limit function calls per evaluation or share an outer solve's limits.
Whether limit-stopped evaluations or interrupted extrapolations write output depends on termination and reports.
This page explains evaluation and iteration limits, reports after limits, publication rules, and function-passing forms.
Definitions of evaluations, iterations, termination, and publication appear in [Call forms](oxref:differentiate-call-forms-terms); workspaces and borrowed forms appear in [Reusing Plans, requirements, and workspaces](../plans-workspaces-and-reports/).
The cross-crate approach to partial results after limits appears in [Error contracts and partial results](../../../concepts/errors-and-partial-results/).

## Evaluation and iteration limits and solve accounting

Every function call is charged to scioxide-core solve accounting as a function evaluation (`EvaluationRole::Function`).
Calls returning errors also count once.
Report `evaluations()` counts function calls by that evaluation, excluding nested-solve evaluations within the function.
Specify limits with `with_budgets(SolveBudgets)` on method values and node-difference options `NodeDifferenceOptions`, for example `SolveBudgets::unbounded().with_limit(BudgetKind::Evaluation, Budget::try_from(n)?)`.
Plans use limits from the method or options supplied at construction.
Defaults impose no limits.

Work per iteration varies by family, as defined in the [Call forms](oxref:differentiate-call-forms-terms) table.
Fixed steps count one coordinate (diagonal or upper-triangular Hessian entry), adaptive differences one level per coordinate, and coloring one level per column.
Fixed-step, complex-step, adaptive, and colored methods evaluate base $f(\mathbf{x})$ before the first iteration and charge only an evaluation (omitted for fixed steps with supplied `base`).
Node differences evaluate zero-displacement nodes within iterations too.

Passing an active solve's `&mut SolveContext` to a borrowed form makes differentiation a nested solve.
Its evaluations also count against the parent limit, while iterations count only within that evaluation ([Nested solves, accounting, and diagnostics](../../../scioxide-core/algorithms/nested-solves-and-diagnostics/)).
Limit-stopped evaluations return a report in `Ok` with termination `EvaluationLimit` or `IterationLimit` rather than an error and write no output.
One-shot functions accept no limits.

## Report and publication rules

[`DifferentiationReport`](https://docs.rs/scioxide-differentiate/0.1.0/scioxide_differentiate/struct.DifferentiationReport.html) stores `source()`, `termination()`, `is_success()`, `evaluations()`, `iterations()`, `completed_entries()`, `output_available()`, and `require_success()`.
[`DerivativeSource`](https://docs.rs/scioxide-differentiate/0.1.0/scioxide_differentiate/enum.DerivativeSource.html) identifies the producing method: `FiniteDifference(scheme)` (fixed step), `AdaptiveDifference`, `ColoredDifference`, `NodeDifference` (node differences), or `ComplexStep`.
`completed_entries()` counts entries with finite estimates; `iterations()` counts attempted iterations.

See the [Reading results](oxref:differentiate-reading-results) table for termination [`DifferentiationTermination`](https://docs.rs/scioxide-differentiate/0.1.0/scioxide_differentiate/enum.DifferentiationTermination.html) and errors returned by `require_success()`.
`is_success()` is true only for `Completed` and `Converged`.
Termination implements `Display`; `to_string()` returns variant names such as `"Converged"`, suitable directly for tables or records.
Families and publication by termination reason follow.

| Termination | Family | Output publication |
|---|---|---|
| `Completed` | Fixed-step, node, complex-step | Published |
| `Converged` | Adaptive, coloring | Published |
| `RoundoffLimit`, `RefinementLimit`, `StepSizeLimit` | Adaptive, coloring | Published if every entry has an estimate |
| `EvaluationLimit`, `IterationLimit` | All | Not published |
| `Cancelled`, `DeadlineReached` | All | Not published |

Fixed-step, node, and complex-step `Completed` indicates only completion of every planned formula evaluation and makes no accuracy claim.
Adaptive and colored `Converged` means all entries' estimates at two consecutive levels and the best-estimate errors meet tolerance; estimates are not bounds ([Richardson extrapolation and Ridders' method](../richardson-and-ridders/)).

Only `output_available()` determines output publication.
Publication occurs on termination `Completed`, or when every entry has an estimate (`completed_entries()` equals output length) and no limit, cancellation, or deadline intervened.
Adaptive extrapolation proceeds coordinate by coordinate; if one stops without an estimate, remaining coordinates are not evaluated.
After a coordinate stops with an estimate (such as `RoundoffLimit`), remaining coordinates continue.
Unpublished results and errors leave borrowed output arrays unchanged.
In owned results, unpublished `values()` and `errors()` are `None`.

Function errors return wrapped in `DifferentiationFailure`.
`DifferentiationFailure` records sample position and evaluation count, retaining the function error unchanged as cause `source()`.
Nonfinite or incompletely written function output gives `DifferentiationFailure` with cause `NonFinite` (`Callback`).
Sample points or difference sums exceeding the finite range give cause `NumericalInstability`.

## Evaluations and outputs at limits

The next two cells compute the gradient of $f(\mathbf{x}) = \sum_i e^{x_i}$ at $\mathbf{x} = (0.1, 0.2, 0.3, 0.4)$ with evaluation or iteration limit $L$ through `gradient_into`.
The exact gradient is $\partial f / \partial x_i = e^{x_i}$.
Fill output with NaN beforehand to check unchanged arrays when unpublished.

The first takes method (fixed central or adaptive Ridders) and limit kind, evaluating once for each $L = 1, \ldots, 60$.
The table gives the smallest $L$ with $k$ estimated entries and the smallest $L$ publishing output, with termination at that $L$.
Each $L$ report and first output component pass to the next cell.

Central gradients evaluate $f(\mathbf{x})$ once and each coordinate twice, iterating once per coordinate; the minimum $L$ for $k$ estimates should be $1 + 2k$ evaluations or $k$ iterations.
Adaptive differences advance levels per coordinate and acquire estimates from level 2.
Each coordinate of this function converges in 6 levels, so $k$ estimates require $6(k - 1) + 2$ iterations or $1 + 2\{6(k - 1) + 2\}$ evaluations.

```rust
//| id: differentiate-budget-sweep
//| ref: differentiate-budget-sweep
//| title: "Evaluations for each limit L and minimum limit yielding all estimates"
//| run: reactive
//| crates: [scioxide-core, scioxide-differentiate]
//| exports: [method, records]
//| inputs:
//|   method: {"type":"select","label":"Method","options":["Fixed step (central)","Adaptive difference (Ridders)"],"value":"Fixed step (central)"}
//|   budget: {"type":"select","label":"Limit kind","options":["Evaluations","Iteration count"],"value":"Evaluations"}
//| cases:
//|   - {"id":"fixed-iterations","label":"Fixed step, iterations","description":"One iteration is one coordinate, so k estimates are available at L = k and publication starts at L = 4.","inputs":{"budget":"Iteration count"}}
//|   - {"id":"adaptive-evaluations","label":"Adaptive, evaluations","description":"Estimates accumulate at L = 5, 17, 29, 41; publication starts at L = 49, when all entries converge.","inputs":{"method":"Adaptive difference (Ridders)"}}
//|   - {"id":"adaptive-iterations","label":"Adaptive, iterations","description":"Estimates accumulate at L = 2, 8, 14, 20; publication starts at L = 24, when all entries converge.","inputs":{"method":"Adaptive difference (Ridders)","budget":"Iteration count"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"thresholds","path":"/rows/0/1","equals":3}
//|       - {"artifact":"thresholds","path":"/rows/1/1","equals":5}
//|       - {"artifact":"thresholds","path":"/rows/3/1","equals":9}
//|       - {"artifact":"thresholds","path":"/rows/3/2","equals":"Completed"}
//|       - {"artifact":"thresholds","path":"/rows/2/2","equals":"EvaluationLimit"}
//|       - {"artifact":"thresholds","path":"/rows/4/1","equals":9}
//|   - case: fixed-iterations
//|     expect:
//|       - {"artifact":"thresholds","path":"/rows/0/1","equals":1}
//|       - {"artifact":"thresholds","path":"/rows/2/2","equals":"IterationLimit"}
//|       - {"artifact":"thresholds","path":"/rows/4/1","equals":4}
//|   - case: adaptive-evaluations
//|     expect:
//|       - {"artifact":"thresholds","path":"/rows/0/1","equals":5}
//|       - {"artifact":"thresholds","path":"/rows/3/1","equals":41}
//|       - {"artifact":"thresholds","path":"/rows/3/2","equals":"EvaluationLimit"}
//|       - {"artifact":"thresholds","path":"/rows/4/1","equals":49}
//|       - {"artifact":"thresholds","path":"/rows/4/2","equals":"Converged"}
//|   - case: adaptive-iterations
//|     expect:
//|       - {"artifact":"thresholds","path":"/rows/1/1","equals":8}
//|       - {"artifact":"thresholds","path":"/rows/3/1","equals":20}
//|       - {"artifact":"thresholds","path":"/rows/4/1","equals":24}
use scioxide_core::{
    Budget, BudgetKind, ExecutionContext, SciOxideError, RealScalar, SolveBudgets,
};
use scioxide_differentiate::{
    AdaptiveDifference, AdaptiveDifferenceWorkspace, DerivativeRequest, DerivativeShape,
    FiniteDifference, FiniteDifferenceWorkspace,
};

let x = [0.1_f64, 0.2, 0.3, 0.4];
// f(x) = Σ e^{xᵢ}.
let f = |p: &[f64], y: &mut [f64]| {
    y[0] = p.iter().map(|&v| RealScalar::exp(v)).sum();
    Ok::<(), SciOxideError>(())
};
let kind = match budget.as_str() {
    "Evaluations" => BudgetKind::Evaluation,
    _ => BudgetKind::Iteration,
};
let adaptive_method = method != "Fixed step (central)";
let shape = DerivativeShape::gradient(4);
let (fixed, adaptive) = (FiniteDifference::default(), AdaptiveDifference::default());
let s = |e: SciOxideError| e.to_string();
let mut fixed_ws =
    FiniteDifferenceWorkspace::workspace(DerivativeRequest::new(&fixed, shape)).map_err(s)?;
let request = DerivativeRequest::new(&adaptive, shape);
let mut adaptive_ws = AdaptiveDifferenceWorkspace::<f64>::workspace(request).map_err(s)?;
// Evaluate once at each L = 1, …, 60; fill output with NaN and check whether it changes.
let mut records = Vec::new();
for l in 1..=60_usize {
    let budgets = SolveBudgets::unbounded().with_limit(kind, Budget::try_from(l).map_err(s)?);
    let (mut out, mut errors) = ([f64::NAN; 4], [f64::NAN; 4]);
    let scope = ExecutionContext::sequential();
    let report = if adaptive_method {
        let method = adaptive.clone().with_budgets(budgets);
        method.gradient_into(f, &x, None, &mut out, &mut errors, &mut adaptive_ws, scope)
    } else {
        let method = fixed.clone().with_budgets(budgets);
        method.gradient_into(f, &x, None, None, &mut out, &mut fixed_ws, scope)
    };
    let report = report.map_err(s)?;
    // Pass unchanged output (still NaN) as absent values (null).
    let first = (!out[0].is_nan()).then_some(out[0]);
    records.push((
        report.termination().to_string(),
        report.is_success(),
        report.output_available(),
        report.evaluations(),
        report.iterations(),
        report.completed_entries(),
        first,
    ));
}
// Minimum L yielding k estimates and minimum L publishing output.
let mut rows = Vec::new();
for k in 1..=4 {
    let found = records.iter().position(|r| r.5 >= k);
    let termination = found.map(|i| records[i].0.clone());
    rows.push((
        format!("Estimates for {k} entries"),
        found.map(|i| i + 1),
        termination,
    ));
}
let found = records.iter().position(|r| r.2);
let termination = found.map(|i| records[i].0.clone());
rows.push(("Output publication".to_string(), found.map(|i| i + 1), termination));
let columns = serde_json::json!([
    { "key": "0", "label": "Event" },
    { "key": "1", "label": "Minimum limit L [count]", "type": "integer", "nullText": "None up to 60" },
    { "key": "2", "label": "Termination at that L", "nullText": "—" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "thresholds" })
);
export!(method, method);
export!(records, records);
```

With default fixed-step evaluation limits, 1, 2, 3, and 4 estimates appear at $L = 3, 5, 7, 9$, matching prediction $1 + 2k$.
Even with up to 3 estimates at $L$, termination is `EvaluationLimit`; only $L = 9$ with all 4 gives `Completed` and publication.
Under iteration limits, estimates appear at $L = 1, 2, 3, 4$ and publication starts at $L = 4$.

Adaptive evaluation-limited estimates accumulate at $L = 5, 17, 29, 41$, matching prediction $1 + 2\{6(k - 1) + 2\}$.
From $L = 41$ through $48$, all 4 entries have estimates, but termination `EvaluationLimit` prevents publication.
Publication with `Converged` starts at $L = 49$, reaching the $1 + 4 \cdot 6 \cdot 2 = 49$ evaluations needed for all entries to converge.
Under iteration limits, estimates appear at $L = 2, 8, 14, 20$; publication starts at $L = 24$, covering 24 iterations.

With defaults (fixed central differences, evaluation limit 6), 1 call at $f(\mathbf{x})$ and 2 each for the first and second coordinates use 5; the third coordinate's first call uses 6, and its second is rejected.
Termination is `EvaluationLimit`, iterations 3, completed entries 2, but output is unpublished and remains NaN.

Adaptive evaluations stopped by limits likewise publish none of the estimated entries.
Limits are reported rather than errors; use termination and `output_available()` to choose the next action.

## Passing functions

Function-passing forms depend on the called function or method.

| Call | Accepted function |
|---|---|
| Method `derivative`, `second_derivative` (`FiniteDifference`, `AdaptiveDifference`), `FiniteDifference::derivative_into` | Closure taking `x` and returning `Ok(f(x))` (`FnMut(S) -> Result<T, SciOxideError>`; fixed steps use `T = S`) |
| `ComplexStep::derivative` | Closure taking complex `z` and returning `Ok(f(z))` |
| One-shot `derivative`, `second_derivative`, `physical_difference_derivative`, `complex_step_derivative` | Same-form `Fn` closures (`complex_step_derivative` uses complex arguments and values) |
| One-shot `gradient`, `hessian` | Value-returning `Fn(&[S]) -> Result<S, SciOxideError>` from a point |
| One-shot `jacobian`, `jvp`, `sparse_jacobian` | Output-writing `Fn(&[S], &mut [T]) -> Result<(), SciOxideError>` (cannot pass `Contextual` or `Parallel`) |
| Other method operations and Plan or node-method evaluations | Three forms below implementing sealed trait [`SampleFunction`](https://docs.rs/scioxide-differentiate/0.1.0/scioxide_differentiate/trait.SampleFunction.html) |

Only these three forms implement `SampleFunction`; other types cannot.
Every form receives a point array and overwrites all $m$ output entries with finite values.

| Form | Function type | Behavior |
|---|---|---|
| Closure | `FnMut(&[S], &mut [T]) -> Result<(), SciOxideError>` | Sequential calls on the caller's thread, stopping at the first error |
| [`Contextual`](https://docs.rs/scioxide-differentiate/0.1.0/scioxide_differentiate/struct.Contextual.html)`(f)` | `FnMut(&[S], &mut [T], &mut SolveContext) -> Result<(), SciOxideError>` | Receives active solve context and includes nested solves in shared accounting; called sequentially |
| [`Parallel`](https://docs.rs/scioxide-differentiate/0.1.0/scioxide_differentiate/struct.Parallel.html)`(f)` | `Fn(&[S], &mut [T]) -> Result<(), SciOxideError> + Sync` | Can evaluate independent samples in parallel on the context's executor |

A `Contextual` function can pass received `&mut SolveContext` to an inner borrowed `scope`.
Inner function calls then count against outer evaluation limits, and outer cancellation and deadlines reach the inner solve.
Calling `record_iteration()` inside the function charges iterations against the same limit as differentiation but excludes them from report `iterations()` ([Minimal example](oxref:differentiate-api-minimal-example)).

Whether `Parallel` samples dispatch to the executor follows execution policy `ExecutionPolicy` selected by method or option `with_execution`.
Default `Sequential` and `Auto` requiring only one worker evaluate sequentially inline.
`Auto` counts one work unit per sample and uses up to 16 workers; `Parallel(n)` dispatches even one sample to the executor.
In either case, a failed sample does not skip the remaining dispatched samples; after evaluating them, the first error in sample order returns.
Only adaptive differences (up to 8 samples per level) and coloring (up to 3 per color per level) batch samples; fixed-step, complex-step, and node differences evaluate one at a time.
Results combine in sample order rather than completion order, so deterministic functions give identical values regardless of worker count.
Owned forms always use context `sequential_native()`; this book's browser cells also run sequentially.

## Summary

Evaluation and iteration limits use `with_budgets` on method values or `NodeDifferenceOptions`; supplying `&mut SolveContext` to borrowed forms shares evaluations with outer limits.
Limit-stopped evaluations return reports with `EvaluationLimit` or `IterationLimit` rather than errors, writing no output even when some entries have estimates.
Output publishes only when `output_available()` is true; adaptive differences and coloring may publish without `Converged` if every entry has an estimate.
`Completed` makes no accuracy claim, so assess accuracy through estimates or independent checks.
Use `Contextual` to control nested solves or function-internal iterations with shared limits; use `Parallel` and execution policies for parallel evaluation.
