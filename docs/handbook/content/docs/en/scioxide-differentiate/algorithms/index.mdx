Methods in `scioxide-differentiate` form five families: fixed-step differences, specified-node differences, adaptive differences, colored Jacobians, and complex steps.
Algorithms differ by family, but share call forms, evaluation and iteration counting, input and value checks, and error and publication rules.
This page collects notation, terms, and contracts assumed by algorithm pages and lists those pages.
General discussion of errors and floating point appears in [Floating-point numbers and conditioning](../../concepts/floating-point-and-conditioning/), errors and partial results in [Error contracts and partial results](../../concepts/errors-and-partial-results/), and workspaces in [Execution forms, workspaces, and reproducibility](../../concepts/workspaces-and-reproducibility/).

## Notation

| Symbol | Meaning |
|---|---|
| $\mathbf{x} \in \mathbb{R}^n$, $\mathbf{F}(\mathbf{x}) \in \mathbb{R}^m$ | Evaluation point and function value (for scalar functions, $m = 1$ and notation $f$) |
| $h$, $h_i$ | Step size and coordinate $i$'s step |
| $\varepsilon = 2^{-52}$ | Double-precision machine epsilon (gap from 1 to the next floating-point number) |
| $u = \varepsilon / 2 = 2^{-53}$ | Unit roundoff (relative-error bound for correctly rounded operations) |
| $\varepsilon_f$ | Magnitude of relative error in function values |
| $p$, $m$ | Truncation-error order and derivative order (on multivariate and coloring pages, $m$ is output dimension) |
| $\Delta_j = x_j - x$ | Displacement of node $x_j$ from evaluation point $x$ |
| $w_j$, $s$, $A_w$ | Difference weights, displacement scale $\max_j \lvert \Delta_j \rvert$, and sum of absolute normalized weights |
| $\mathbf{J}$, $\mathbf{H}$, $\mathbf{v}$ | Jacobian, Hessian, and direction of directional derivative $\mathbf{J}\mathbf{v}$ |
| $r$ | Adaptive step-reduction ratio (1.4 for Ridders, 2 for Richardson extrapolation) |
| $L$ | Maximum levels (differences after one adaptive step reduction; `with_max_levels`, default 16) |

## Method families

| Family | Method values and Plans | Error estimates | Known base value `base` | Function values |
|---|---|---|---|---|
| Fixed-step differences | `FiniteDifference` | No | Yes | Real |
| Specified-node differences | `PhysicalDifferencePlan`, `RelativeDifference`, `FiniteDifferenceStencil` | No | No | Real or complex |
| Adaptive differences | `AdaptiveDifference` | Yes | No | Real or complex |
| Colored Jacobians | `ColoredJacobianPlan` | Yes | No | Real or complex |
| Complex steps | `ComplexStep`, `ComplexStepPlan`, `RelativeComplexStep` | No | No | Real (function evaluated with complex numbers) |

Coordinates are real (`f32` or `f64`) in every family.
Specified-node differences, adaptive differences, and coloring also accept complex-valued functions, differentiating real and imaginary parts separately with respect to real coordinates.
Complex steps accept an analytic complex extension of a real function and return real derivatives.
`FiniteDifferenceStencil` does not call functions; it constructs only weights for caller-held values.
Only adaptive differences and coloring return error estimates; completion `Completed` in other families indicates only that planned evaluations finished, without accuracy claims.

## Call forms

The same derivative can be computed through several forms according to the control needed.
This chapter names values and types by their roles as follows.

| Term | Types or functions | Contents and role |
|---|---|---|
| One-shot function | `derivative`, `second_derivative`, `gradient`, `jacobian`, `hessian`, `jvp`, `sparse_jacobian`, `physical_difference_derivative`, `complex_step_derivative` | Free function accepting a function and evaluation point and returning derivative values only |
| Method value | `FiniteDifference`, `AdaptiveDifference`, `ComplexStep` | Holds configuration only (formula, step, tolerance, levels, limits); methods select operations |
| Node method value | `RelativeDifference`, `RelativeComplexStep` | Stores displacement sequences per coordinate; receives evaluation points on each call |
| Plan | `ColoredJacobianPlan`, `PhysicalDifferencePlan`, `ComplexStepPlan` | Stores precomputed data (per-column rows and tolerances for coloring, node weights at fixed points) |
| Requirements | `*Requirements` such as `FiniteDifferenceRequirements` | Workspace size needed for one evaluation (`bytes()`) |
| Workspace | `*Workspace` such as `FiniteDifferenceWorkspace` | Storage for intermediate evaluation values, reusable within the family after reservation |
| Report | `DifferentiationReport` | Method used (`source()`), termination reason, evaluations, iterations, completed entries, and publication flag |
| Result | `DifferentiationResult` | Report, published values, and error estimates |

Method values are constructed with `default()` and `with_…`, deriving input dimension $n$ from point length and, for Jacobians and directional derivatives, output dimension $m$ from arguments; settings and dimensions are checked on each evaluation.
Plans and node methods are constructed with `new`, checking their accepted operations, dimensions, nodes, and settings at construction.
Evaluation points, bounds `bounds`, directions, and known base values are evaluation arguments; only `PhysicalDifferencePlan` and `ComplexStepPlan` fix points at construction and do not receive them during evaluation.
All are function-independent and can serve many evaluations once constructed.

There are three evaluation forms.

| Form | Example | Returns | Workspace and output | Execution context |
|---|---|---|---|---|
| One-shot function | `gradient(f, &x)` | Derivative values (scalar or `Vec`) | Allocated internally (`derivative` does not allocate) | `sequential_native()` |
| Owned | `method.gradient(f, &x, bounds, base)`, `plan.evaluate(f, bounds)` | `DifferentiationResult` | Allocated per call | `sequential_native()` |
| Borrowed | `method.gradient_into(f, &x, bounds, base, &mut out, &mut workspace, scope)`, `plan.evaluate_into(…)` | `DifferentiationReport` | Supplied by caller | Supplied `scope` |

One-shot functions except `derivative` construct a default method or Plan, call its owned form, and extract values with `into_values()`.
`derivative` calls borrowed `FiniteDifference::derivative_into` with stack storage alone and checks termination with `require_success()`, so it allocates nothing.
`derivative`, `second_derivative`, `gradient`, `jacobian`, `hessian`, and `jvp` use default-step central differences; `sparse_jacobian` uses coloring with default adaptive differences; `physical_difference_derivative` uses supplied-node differences; `complex_step_derivative` uses complex-step size $h = \varepsilon$.
Unsuccessful termination reasons become errors, so returned values always come from successful evaluations.
Use method values or Plans to change bounds, steps, tolerances, or limits, or read reports and error estimates.

Owned forms are methods without `_into` in their names, allocating workspace and result arrays per call.
Owned method forms are `derivative`, `second_derivative`, `gradient`, `jacobian`, `hessian`, and `jvp`; `ComplexStep` provides only `derivative`, `gradient`, `jacobian`, and `jvp`.
For Plans and node methods, the owned form is `evaluate`.
Owned and one-shot forms evaluate with context `ExecutionContext::sequential_native()`, which runs sequentially on the caller's thread without a clock or cancellation.

Borrowed names end in `_into`, write to caller-provided output arrays (also error-estimate arrays for adaptive differences and coloring) and workspace, and receive execution context as the last argument.
For top-level computations, pass a context such as `ExecutionContext::sequential()`; from within another solve, pass its `&mut SolveContext`.
Context lends parallel executors, cancellation, and deadlines, so only borrowed forms can use them.
Borrowed forms with sufficient workspace allocate no numerical storage.
`FiniteDifference::derivative_into` is a borrowed univariate first-derivative form using stack storage without workspace and accepting bounds as `ExtendedInterval`.
Requirement computation and workspace reservation and reuse are covered in [Reusing Plans, requirements, and workspaces](plans-workspaces-and-reports/).

The **termination reason** is why evaluation stopped (a `DifferentiationTermination` value); **publication** means writing result values.
Report `output_available()` indicates publication; unpublished evaluations leave borrowed output arrays unchanged.
Publication rules by termination reason appear in [Reading results](oxref:differentiate-reading-results).
An **error estimate** is an elementwise absolute-error estimate returned by adaptive differences and coloring, combining extrapolation-table differences with an upper bound on propagated rounding error.
Error estimates are not upper bounds.
Element $D$ is considered converged when estimated errors at 2 consecutive levels are at most $\mathrm{atol} + \mathrm{rtol}\,\lvert D \rvert$ and the selected best estimate also meets tolerance (see [Richardson extrapolation and Ridders' method](richardson-and-ridders/) for details).

**Evaluations** count function calls, including calls returning errors.
Even if a context-aware function invokes another solve, those evaluations are excluded from report evaluation counts (scioxide-core rules still count them against evaluation limits).
**Iterations** use the following family-specific units.

| Family | One iteration |
|---|---|
| Fixed-step and specified-node differences | One coordinate (gradient or Jacobian column), one diagonal or upper-triangular mixed Hessian entry, or one fixed-step directional derivative (node differences do not provide directional derivatives) |
| Complex steps | One coordinate; one ordered coordinate pair for Hessians from `ComplexStepPlan` and `RelativeComplexStep`; one directional derivative |
| Adaptive differences | One level per coordinate (coordinate pair for Hessians), or one level for directional derivatives |
| Coloring | One level per column |

**Evaluation limits** and **iteration limits** use scioxide-core `SolveBudgets`, passed as `SolveBudgets::unbounded().with_limit(BudgetKind::Evaluation, Budget::try_from(k)?)` to `with_budgets` of method values or node-difference options `NodeDifferenceOptions`.
Plans use limits from the method or options supplied at construction.
Evaluation limits are shared with outer solves; iteration limits count only within that evaluation.
Limit-stopped evaluations return reports with termination `EvaluationLimit` or `IterationLimit` rather than errors and publish no values.
One-shot functions accept no limits.

The experiment in [Call forms and measured evaluation counts](call-forms-and-evaluation-counts/) computes the same gradient through three forms and four families to check these evaluation and iteration counts and limit-stopping behavior.

## Input and function-value checks

Inputs are checked once at the start of each evaluation before passing to the algorithm.
Generated nodes and function outputs are checked whenever produced.
Main error kinds follow; read kinds through `e.kind()` (`SciOxideErrorKind`) and details through `e.view()`.

| Kind | Main causes |
|---|---|
| `InvalidInput` | Out-of-range settings (levels outside 3–64, complex steps below minimum normal), operation–dimension mismatches, empty bounds, out-of-bounds points (`OutOfRange`), unplaceable formulas, insufficient or duplicate nodes, incompatible policies (`Inconsistent`), or failed analytic-extension checks |
| `DimensionMismatch` | Length mismatches in points, bounds, directions, `base`, output, or per-coordinate steps; insufficient workspace capacity |
| `NonFinite` | Nonfinite points, directions, `base`, nodes, or complex steps (cause `Input`); nonfinite fixed-step final results (`Output`) |
| `DifferentiationFailure` | Function errors, nonfinite written values, sample points or difference sums outside the finite range, or unplaceable distinct points in fixed-step directional derivatives |
| `NumericalInstability` | Weight-recurrence breakdown; nonzero complex-step $\operatorname{Im} f$ becoming subnormal, or division by $h$ underflowing to 0 |
| `ResourceLimit`, `SizeOverflow`, `AllocationFailure` | Exceeded workspace limits, unrepresentable sizes, or allocation failures |
| `ConvergenceFailure`, `ExecutionStopped` | Unsuccessful termination converted by one-shot functions or `into_values()` |

`DifferentiationFailure` stores failure location (base point, coordinate, direction, etc.), evaluations so far, and the cause; function-returned errors remain unchanged as causes.
Evaluation or iteration limits appear as report termination reasons for owned and borrowed forms, and as `ConvergenceFailure` for one-shot functions.
An exactly zero complex-step $\operatorname{Im} f(x + ih)$ is indistinguishable from a truly zero derivative, so it returns derivative 0 without error ([Complex-step differentiation and analytic extensions](complex-step/)).

## Handling base values

Derivative weights sum to 0, so subtracting a constant from samples does not mathematically change the result.
The value subtracted to reduce rounding leakage depends on the family.

- Fixed-step, adaptive, and colored differences subtract evaluation-point value $f(\mathbf{x})$.
  Thus even central differences evaluate $f(\mathbf{x})$ (fixed-step methods can omit this with `base`).
- Specified-node differences subtract the midpoint of the nearest sample and its reflected counterpart, or the nearest sample if no counterpart exists; they do not separately evaluate the base point.
- Complex-step first derivatives use no subtraction.
  Base-point evaluation only checks that the value is real.

## Outputs on failure

Borrowed forms write caller arrays only when publishing; errors or unpublished results leave arrays unchanged.
The next cell computes the gradient of three-variable $f(\mathbf{x}) = \lVert \mathbf{x} \rVert_2^2$ under bounds $x_i \ge 0$ at $\mathbf{x} = (1, 2, 3)$.
It calls fixed-step central differences through borrowed `gradient_into`.
On the input-selected call, the function either returns an error or writes a nonfinite value.
It also tries a point containing NaN, an out-of-bounds point, a point of mismatched length, and a nonfailing function.
Central differences evaluate the base once and each coordinate twice, in order: base, coordinate 0, coordinate 0, coordinate 1, coordinate 1, coordinate 2, coordinate 2.
The table shows result kind (termination on success), cause kind of `DifferentiationFailure`, failure location, recorded evaluations, actual function calls, and output components whose values changed.

```rust
//| id: differentiate-error-contract
//| ref: differentiate-error-contract
//| title: "Error kinds and output arrays on failed evaluations"
//| run: reactive
//| crates: [scioxide-core, scioxide-differentiate]
//| inputs:
//|   failing: {"type":"range","label":"Failing call index k","description":"The function returns an error or writes a nonfinite value on call k.","min":1,"max":7,"step":1,"value":4}
//| cases:
//|   - {"id":"base-point","label":"k = 1","description":"The first call evaluates base f(x), so its failure location is the base point.","inputs":{"failing":1}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"failures","path":"/rows/0/1","equals":"DifferentiationFailure"}
//|       - {"artifact":"failures","path":"/rows/0/2","equals":"External"}
//|       - {"artifact":"failures","path":"/rows/0/3","equals":"Coordinate 1"}
//|       - {"artifact":"failures","path":"/rows/0/4","equals":4}
//|       - {"artifact":"failures","path":"/rows/0/6","equals":0}
//|       - {"artifact":"failures","path":"/rows/1/2","equals":"NonFinite"}
//|       - {"artifact":"failures","path":"/rows/1/6","equals":0}
//|       - {"artifact":"failures","path":"/rows/2/1","equals":"NonFinite"}
//|       - {"artifact":"failures","path":"/rows/2/5","equals":0}
//|       - {"artifact":"failures","path":"/rows/3/1","equals":"InvalidInput"}
//|       - {"artifact":"failures","path":"/rows/4/1","equals":"DimensionMismatch"}
//|       - {"artifact":"failures","path":"/rows/5/1","equals":"Completed"}
//|       - {"artifact":"failures","path":"/rows/5/5","equals":7}
//|       - {"artifact":"failures","path":"/rows/5/6","equals":3}
//|   - case: base-point
//|     expect:
//|       - {"artifact":"failures","path":"/rows/0/3","equals":"Base point"}
//|       - {"artifact":"failures","path":"/rows/0/4","equals":1}
//|       - {"artifact":"failures","path":"/rows/0/5","equals":1}
use scioxide_core::{
    Bounds, DifferentiationSite, ExecutionContext, SciOxideError, SciOxideErrorView,
};
use scioxide_differentiate::{
    DerivativeRequest, DerivativeShape, FiniteDifference, FiniteDifferenceWorkspace,
};

let failing = failing as usize;
let method = FiniteDifference::<f64>::default();
let request = DerivativeRequest::new(&method, DerivativeShape::gradient(3));
let mut workspace = FiniteDifferenceWorkspace::workspace(request).map_err(|e| e.to_string())?;
let bounds = Bounds::new(vec![(Some(0.0), None); 3]).map_err(|e| e.to_string())?;
let mut rows = Vec::new();
for case in [
    "Function error",
    "Nonfinite value",
    "Point containing NaN",
    "Out-of-bounds point",
    "Mismatched-length point",
    "Nonfailing function",
] {
    let x: Vec<f64> = match case {
        "Point containing NaN" => vec![1.0, f64::NAN, 3.0],
        "Out-of-bounds point" => vec![1.0, -2.0, 3.0],
        "Mismatched-length point" => vec![1.0, 2.0],
        _ => vec![1.0, 2.0, 3.0],
    };
    let mut count = 0;
    let initial = [7.0; 3];
    let mut out = initial;
    let result = method.gradient_into(
        |p: &[f64], y: &mut [f64]| {
            count += 1;
            if count == failing && case == "Function error" {
                return Err(SciOxideError::external("Model evaluation failed"));
            }
            y[0] = if count == failing && case == "Nonfinite value" {
                f64::NAN
            } else {
                p.iter().map(|v| v * v).sum()
            };
            Ok(())
        },
        &x,
        Some(&bounds),
        None,
        &mut out,
        &mut workspace,
        ExecutionContext::sequential(),
    );
    // (Kind or termination, cause kind, failure location, recorded evaluations)
    let (kind, cause, site, recorded) = match result {
        Ok(report) => (report.termination().to_string(), None, None, None),
        Err(e) => match e.view() {
            SciOxideErrorView::DifferentiationFailure { frames, cause } => {
                let place = match frames[0].location.site() {
                    DifferentiationSite::BasePoint => "Base point".to_string(),
                    DifferentiationSite::Variable(i) => format!("Coordinate {i}"),
                    other => format!("{other:?}"),
                };
                let kind = format!("{:?}", e.kind());
                (
                    kind,
                    Some(format!("{:?}", cause.kind())),
                    Some(place),
                    Some(frames[0].evaluations),
                )
            }
            _ => (format!("{:?}", e.kind()), None, None, None),
        },
    };
    let changed = out.iter().zip(&initial).filter(|(a, b)| a != b).count();
    rows.push((case, kind, cause, site, recorded, count, changed));
}
let columns = serde_json::json!([
    { "key": "0", "label": "Case" },
    { "key": "1", "label": "Result e.kind() or termination" },
    { "key": "2", "label": "Cause kind", "nullText": "－" },
    { "key": "3", "label": "Failure location", "nullText": "－" },
    { "key": "4", "label": "Recorded evaluations [count]", "type": "integer", "nullText": "－" },
    { "key": "5", "label": "Function calls [count]", "type": "integer" },
    { "key": "6", "label": "Changed output components [count]", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "failures" })
);
```

At default $k = 4$, call 4 (the first sample of coordinate 1) returns a function error, giving `DifferentiationFailure` with cause `External`.
The error records “Coordinate 1” and 4 evaluations; output remains at its initial value 7.
Writing a nonfinite value also gives `DifferentiationFailure` (cause `NonFinite`), leaving output unchanged.
NaN points give `NonFinite`, out-of-bounds points `InvalidInput`, and mismatched-length points `DimensionMismatch`, all rejected without function calls.
The nonfailing function gives `Completed` in 7 evaluations, overwriting all 3 output components.
At $k = 1$, the first call evaluates the base point, so failure location is the base and recorded evaluations are 1.

## Summary

Methods in `scioxide-differentiate` form five families, each callable through owned and borrowed forms, with one-shot functions for common computations.
Choose one-shot functions for values only, owned forms to read termination or estimates, and borrowed forms to avoid allocation or share limits and cancellation with outer solves.
Evaluations count function calls; iterations count coordinates, entries, or levels by family, and limit-stopped evaluations publish no values.
Inputs are checked once at evaluation start; function errors and nonfinite values return as `DifferentiationFailure` with location, evaluations, and cause.
Errors and unpublished results leave borrowed arrays unchanged, allowing the next action to follow error kinds and termination reasons.
