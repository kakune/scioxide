Multivariate derivatives are arrays—gradients, Jacobians, or Hessians—and their difference cost increases with variable count.
This page explains operations and output layouts in `scioxide-differentiate`, formulas and error orders, and evaluation-count breakdowns.
It assumes univariate formulas and default steps from [Taylor expansion and step-size selection](../taylor-and-step-size/).
If only the Jacobian–vector product $\mathbf{J}\mathbf{v}$ is needed, compute it as a directional derivative without forming a matrix ([Directional derivatives (Jacobian–vector products)](../directional-derivatives/)).

## Operations and output layout

Let input dimension be $n$ and output dimension $m$, writing the function as $\mathbf{F}: \mathbb{R}^n \to \mathbb{R}^m$ ($f$ when $m = 1$).
Method values `FiniteDifference`, `AdaptiveDifference`, and `ComplexStep` select derivative shapes by method; node method `RelativeDifference` and Plan `PhysicalDifferencePlan` specify them at construction with [`DerivativeOperation`](https://docs.rs/scioxide-differentiate/0.1.0/scioxide_differentiate/enum.DerivativeOperation.html).

| Method (`DerivativeOperation`) | Input and output | Output array | Available method values |
|---|---|---|---|
| `derivative` (`First`) | $n = m = 1$ | 1 entry of $f'(x)$ | All three |
| `second_derivative` (`Second`) | $n = m = 1$ | 1 entry of $f''(x)$ | `FiniteDifference`, `AdaptiveDifference` |
| `gradient` (`Gradient`) | $m = 1$ | $n$ entries of $\nabla f$ | All three |
| `jacobian` (`Jacobian`) | Any | Row-major $m \times n$; entry $(i, j) = \partial F_i / \partial x_j$ at $i n + j$ | All three |
| `hessian` (`Hessian`) | $m = 1$ | Row-major symmetric $n \times n$; entry $(i, j)$ at $i n + j$ | `FiniteDifference`, `AdaptiveDifference` |
| `jvp` (none) | Any | $m$ entries of $\mathbf{J}\mathbf{v}$ | All three |

Method values derive $n$ from point length and $m$ from argument `outputs` of `jacobian` and `jvp`.
Mismatched output-array or known-base `base` lengths give `DimensionMismatch`.
Node methods and Plans give `InvalidInput` (`UnsupportedConfiguration`, argument `operation`) at construction for operation–dimension mismatches.
`ComplexStep` has no second-derivative methods; compute second derivatives and Hessians with Plan `ComplexStepPlan` and node method `RelativeComplexStep` ([Complex-step second derivatives, Hessians, and directional derivatives](oxref:differentiate-complex-second)).
Node methods and Plans have no directional operation ([Directional derivatives (Jacobian–vector products)](../directional-derivatives/)).

For values alone with default central differences, one-shot `gradient(f, x)`, `hessian(f, x)`, `jacobian(f, x, m)`, and `jvp(f, x, v, m)` return values from `FiniteDifference::default()`.
`gradient` and `hessian` accept scalar-returning `Fn(&[S]) -> Result<S, SciOxideError>`; `jacobian` and `jvp` accept output-writing `Fn(&[S], &mut [S]) -> Result<(), SciOxideError>`.
Method `gradient` and `hessian` accept output-writing functions even with one output.
Coloring Plan `ColoredJacobianPlan` writes sparse Jacobians in structure-storage order ([Sparse-Jacobian compression by coloring](../sparse-coloring/)).

## Gradient and Jacobian differences

Let coordinate $j$'s unit vector be $\mathbf{e}_j$ and step $h_j$.
`FiniteDifference` constructs univariate differences per coordinate, obtaining Jacobian column $j$ with one stencil.

$$
\frac{\mathbf{F}(\mathbf{x} + h_j \mathbf{e}_j) - \mathbf{F}(\mathbf{x})}{h_j} = \frac{\partial \mathbf{F}}{\partial x_j} + \frac{h_j}{2} \frac{\partial^2 \mathbf{F}}{\partial x_j^2} + O(h_j^2),
\qquad
\frac{\mathbf{F}(\mathbf{x} + h_j \mathbf{e}_j) - \mathbf{F}(\mathbf{x} - h_j \mathbf{e}_j)}{2 h_j} = \frac{\partial \mathbf{F}}{\partial x_j} + \frac{h_j^2}{6} \frac{\partial^3 \mathbf{F}}{\partial x_j^3} + O(h_j^4).
$$

The left is forward and the right central.
One evaluation gives every one of the $m$ outputs, so Jacobian cost, like gradient cost, depends on column count $n$ rather than $m$.
Default coordinate steps are $h_j = c \max(1, \lvert x_j \rvert)$, with factor $c$ equal to $\varepsilon^{1/2}$ for forward or $\varepsilon^{1/3}$ for central differences ([SciOxide default steps](oxref:differentiate-default-steps)).
For smooth functions of magnitude about 1, errors are then about $\varepsilon^{1/2} \approx 1.5 \times 10^{-8}$ forward and $\varepsilon^{2/3} \approx 3.7 \times 10^{-11}$ central.

Columnwise values are written at row-major positions $i n + j$.
Base value $\mathbf{F}(\mathbf{x})$ is shared by all coordinates and evaluated once even centrally ([Subtracting base values and known base `base`](oxref:differentiate-base-argument)).

## Hessian differences and error orders

Diagonal $H_{ii} = \partial^2 f / \partial x_i^2$ of Hessian $\mathbf{H}$ uses univariate second differences.
$f_{ii}$, $f_{iii}$, and similar symbols denote partial derivatives.

$$
\frac{f(\mathbf{x} + h_i \mathbf{e}_i) - 2 f(\mathbf{x}) + f(\mathbf{x} - h_i \mathbf{e}_i)}{h_i^2} = f_{ii} + \frac{h_i^2}{12} f_{iiii} + O(h_i^4),
\qquad
\frac{f(\mathbf{x} + 2 h_i \mathbf{e}_i) - 2 f(\mathbf{x} + h_i \mathbf{e}_i) + f(\mathbf{x})}{h_i^2} = f_{ii} + h_i f_{iii} + O(h_i^2).
$$

The left is central and the right forward.
Mixed terms $H_{ij}$ ($i \ne j$) use tensor products of first differences in coordinates $i$ and $j$.
Writing the central first-difference operator as $D_i$, applying $D_i g = g_i + \tfrac{h_i^2}{6} g_{iii} + O(h_i^4)$ successively in two coordinates gives the following.

$$
D_i D_j f = \frac{f(\mathbf{x}{+}h_i\mathbf{e}_i{+}h_j\mathbf{e}_j) - f(\mathbf{x}{+}h_i\mathbf{e}_i{-}h_j\mathbf{e}_j) - f(\mathbf{x}{-}h_i\mathbf{e}_i{+}h_j\mathbf{e}_j) + f(\mathbf{x}{-}h_i\mathbf{e}_i{-}h_j\mathbf{e}_j)}{4 h_i h_j} = f_{ij} + \frac{h_i^2}{6} f_{iiij} + \frac{h_j^2}{6} f_{ijjj} + O(h^4).
$$

Forward mixed terms use four points $\mathbf{x}$, $\mathbf{x} + h_i \mathbf{e}_i$, $\mathbf{x} + h_j \mathbf{e}_j$, and $\mathbf{x} + h_i \mathbf{e}_i + h_j \mathbf{e}_j$ with leading error $\tfrac{h_i}{2} f_{iij} + \tfrac{h_j}{2} f_{ijj}$.
Truncation is $O(h^2)$ centrally and $O(h)$ forward.

Function-value error $\varepsilon \lvert f \rvert$ is amplified by division by $h^2$ ($h_i h_j$ for mixed terms), making rounding approximately proportional to $\varepsilon \lvert f \rvert / h^2$ for every formula.
The step minimizing truncation $C h^p$ plus rounding $\varepsilon \lvert f \rvert / h^2$ is $h \propto \varepsilon^{1/(p+2)}$, with error proportional to $\varepsilon^{p/(p+2)}$.

| Formula | Truncation order $p$ | Optimal step | Error magnitude | Double-precision value |
|---|---|---|---|---|
| Central | 2 | $\varepsilon^{1/4}$ | $\varepsilon^{1/2}$ | $1.5 \times 10^{-8}$ |
| Forward | 1 | $\varepsilon^{1/3}$ | $\varepsilon^{1/3}$ | $6.1 \times 10^{-6}$ |

`FiniteDifference` uses second-derivative default steps for both diagonal and mixed Hessian terms ($\varepsilon^{1/4} \max(1, \lvert x_i \rvert)$ centrally, $\varepsilon^{1/3} \max(1, \lvert x_i \rvert)$ forward).
Although mixed terms combine first differences, rounding error grows as $1/(h_i h_j)$, so using first-derivative steps makes the rounding error too large.
Coefficients $C$ and $\lvert f \rvert$ depend on the function, so table values indicate magnitude only.

Only upper triangle $j \ge i$ is computed and copied below, giving bitwise symmetry.
Within one `hessian` call, bitwise-identical floating-point points (distinguishing signed zeros) are evaluated only once and reused.
These include axis points shared by diagonal and mixed differences; values never persist across calls.
Diagonal and mixed terms use the same steps, so axis points coincide exactly without boundaries.

## Measuring Hessian steps and errors

The two cells here compute the Hessian of $f(x, y) = e^{xy}$ at $(x, y) = (1, 0.5)$ with `FiniteDifference::hessian` and compare with exact values.
Exact values are $f_{xx} = y^2 e^{xy}$ and $f_{xy} = (1 + xy) e^{xy}$; leading coefficients in the expansions also have closed forms.

$$
f_{xxx} = y^3 e^{xy}, \quad f_{xxxx} = y^4 e^{xy}, \quad f_{xxy} = y(2 + xy) e^{xy}, \quad f_{xyy} = x(2 + xy) e^{xy}, \quad f_{xxxy} = y^2(3 + xy) e^{xy}, \quad f_{xyyy} = x^2 (3 + xy) e^{xy}.
$$

The following block defines shared code for the two cells.
`hessian_errors` computes the Hessian with relative step $r$ (`DifferenceStep::relative`, step $h_i = r \max(1, \lvert x_i \rvert)$) or default steps and returns the absolute errors in $H_{00} = f_{xx}$ and $H_{01} = f_{xy}$ and the difference from the lower-triangle entry, $\lvert H_{01} - H_{10} \rvert$.
Input text selects type `f32` or `f64`.
Exact-value references use f64 standard functions.

```rust
//| id: differentiate-hessian-exp-model
//| kind: definitions
//| title: "Hessian errors of e^(xy)"
//| crates: [scioxide-core, scioxide-differentiate]
use scioxide_core::{SciOxideError, RealScalar};
use scioxide_differentiate::{DifferenceScheme, DifferenceStep, FiniteDifference};

/// Return [|H00 error|, |H01 error|, |H01 − H10|] for f(x, y) = exp(xy) at (1, 0.5).
/// Use default steps when relative is None.
fn errors_in<S: RealScalar>(
    scheme: DifferenceScheme,
    relative: Option<f64>,
) -> Result<[f64; 3], SciOxideError> {
    let x = [S::try_from_f64_lossy(1.0)?, S::try_from_f64_lossy(0.5)?];
    let mut method = FiniteDifference::default().with_scheme(scheme);
    if let Some(r) = relative {
        method = method.with_step(DifferenceStep::relative(S::try_from_f64_lossy(r)?)?);
    }
    let f = |p: &[S], y: &mut [S]| {
        y[0] = RealScalar::exp(p[0] * p[1]);
        Ok::<(), SciOxideError>(())
    };
    let h = method.hessian(f, &x, None, None)?.into_values()?;
    // Reference: f_xx = y² e^{xy}, f_xy = (1 + xy) e^{xy} (f64 standard functions).
    let e = 0.5_f64.exp();
    let (h00, h01, h10) = (h[0].into_f64(), h[1].into_f64(), h[2].into_f64());
    Ok([
        (h00 - 0.25 * e).abs(),
        (h01 - 1.5 * e).abs(),
        (h01 - h10).abs(),
    ])
}

/// Select type "f32" or "f64" and call errors_in.
pub(crate) fn hessian_errors(
    precision: &str,
    scheme: DifferenceScheme,
    relative: Option<f64>,
) -> Result<[f64; 3], SciOxideError> {
    match precision {
        "f32" => errors_in::<f32>(scheme, relative),
        _ => errors_in::<f64>(scheme, relative),
    }
}

/// Type machine epsilon ε.
pub(crate) fn machine_epsilon(precision: &str) -> f64 {
    match precision {
        "f32" => f64::from(f32::EPSILON),
        _ => f64::EPSILON,
    }
}
```

### Errors and relative steps

The next cell sweeps both formulas, reducing relative step $r$ from $10^{-1}$ at 4 samples per decade through $10^{-9}$ for `f64` or $10^{-5}$ for `f32`.
The upper chart shows absolute diagonal $H_{00}$ errors, the lower mixed $H_{01}$ errors, with linked step axes.
Dashed curves are leading truncation terms; vertical dotted lines mark default relative steps $\varepsilon^{1/3}$ (forward) and $\varepsilon^{1/4}$ (central).
The table compares sampled error-minimizing steps and errors with default relative steps.
Selecting type `f32` changes $\varepsilon$ to $1.19 \times 10^{-7}$, shifting optimal steps and error scales by the same power rules.

```rust
//| id: differentiate-hessian-step-error
//| ref: differentiate-hessian-step-error
//| title: "Errors and relative steps for diagonal and mixed Hessian terms"
//| run: reactive
//| uses: [differentiate-hessian-exp-model]
//| crates: [scioxide-core, scioxide-differentiate]
//| inputs:
//|   precision: {"type":"select","label":"Floating-point type","description":"Change machine epsilon ε.","options":["f64","f32"],"value":"f64"}
//| cases:
//|   - {"id":"single","label":"f32","description":"Larger ε increases optimal steps and raises the error floor.","inputs":{"precision":"f32"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"optimum","path":"/rows/0/3","range":{"min":6e-7,"max":6e-5}}
//|       - {"artifact":"optimum","path":"/rows/1/3","range":{"min":6e-7,"max":6e-5}}
//|       - {"artifact":"optimum","path":"/rows/2/3","range":{"min":1.2e-5,"max":1.2e-3}}
//|       - {"artifact":"optimum","path":"/rows/3/3","range":{"min":1.2e-5,"max":1.2e-3}}
//|       - {"artifact":"optimum","path":"/rows/0/4","range":{"min":1e-8,"max":6e-5}}
//|       - {"artifact":"optimum","path":"/rows/2/4","range":{"min":1e-12,"max":1.5e-8}}
//|       - {"artifact":"optimum","path":"/rows/3/4","range":{"min":1e-12,"max":1.5e-8}}
//|   - case: single
//|     expect:
//|       - {"artifact":"optimum","path":"/rows/0/3","range":{"min":4.9e-4,"max":4.9e-2}}
//|       - {"artifact":"optimum","path":"/rows/2/3","range":{"min":1.8e-3,"max":0.18}}
//|       - {"artifact":"optimum","path":"/rows/2/4","range":{"min":1e-6,"max":3.5e-4}}
use scioxide_differentiate::DifferenceScheme;

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let epsilon = machine_epsilon(&precision);
// Sweep relative steps from 10⁻¹ at 4 points per decade: 9 decades for f64, 5 for f32.
let last = if precision == "f32" { 16 } else { 32 };
let steps: Vec<f64> = (0..=last)
    .map(|k| 10.0_f64.powf(-1.0 - f64::from(k) / 4.0))
    .collect();
// Leading truncation terms (x = 1, y = 0.5 gives max(1, |xᵢ|) = 1, so h = r):
// [forward H00, forward H01, central H00, central H01].
let e = 0.5_f64.exp();
let leading = |k: usize, h: f64| match k {
    0 => h * 0.125 * e,
    1 => 0.5 * h * (1.25 + 2.5) * e,
    2 => h * h / 12.0 * 0.0625 * e,
    _ => h * h / 6.0 * (0.875 + 3.5) * e,
};
let schemes = [
    ("Forward difference", DifferenceScheme::Forward, epsilon.cbrt()),
    ("Central difference", DifferenceScheme::Central, epsilon.sqrt().sqrt()),
];
let (mut charts, mut rows, mut dropped) = ([Vec::new(), Vec::new()], Vec::new(), 0);
for (s, &(name, scheme, default_step)) in schemes.iter().enumerate() {
    let sweep: Vec<[f64; 3]> = steps
        .iter()
        .map(|&r| hessian_errors(&precision, scheme, Some(r)))
        .collect::<Result<_, _>>()
        .map_err(|e| e.to_string())?;
    for (entry, label) in ["H₀₀", "H₀₁"].iter().enumerate() {
        // Count and exclude exactly zero errors from logarithmic charts.
        let points: Vec<[f64; 2]> = steps
            .iter()
            .zip(&sweep)
            .map(|(&r, v)| [r, v[entry]])
            .filter(|p| p[1] > 0.0)
            .collect();
        dropped += steps.len() - points.len();
        let theory: Vec<[f64; 2]> = steps
            .iter()
            .map(|&r| [r, leading(2 * s + entry, r)])
            .collect();
        let best = points.iter().copied().min_by(|a, b| a[1].total_cmp(&b[1]));
        let reference = format!("{name} leading term");
        charts[entry].push(serde_json::json!({
            "name": name,
            "points": points,
            "style": { "showSymbol": true }
        }));
        charts[entry].push(serde_json::json!({
            "name": reference,
            "points": theory,
            "style": { "lineType": "dashed" }
        }));
        rows.push((
            name,
            *label,
            default_step,
            best.map(|p| p[0]),
            best.map(|p| p[1]),
        ));
    }
}
let columns = serde_json::json!([
    { "key": "0", "label": "Formula" },
    { "key": "1", "label": "Entry" },
    { "key": "2", "label": "Default relative step [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "Error-minimizing step [-]", "type": "number", "format": sci3, "nullText": "None" },
    { "key": "4", "label": "Minimum error [-]", "type": "number", "format": sci3, "nullText": "None" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "optimum" })
);
let defaults = [
    ("ε^(1/3)", epsilon.cbrt()),
    ("ε^(1/4)", epsilon.sqrt().sqrt()),
];
let annotations: Vec<_> = defaults
    .iter()
    .map(|&(label, value)| {
        serde_json::json!({
            "kind": "line",
            "axis": "x",
            "value": value,
            "label": label,
            "style": { "lineType": "dotted" }
        })
    })
    .collect();
for (series, y_label) in charts
    .iter()
    .zip(["H₀₀ absolute error [-]", "H₀₁ absolute error [-]"])
{
    emit_line_chart!(
        series,
        options = &serde_json::json!({
            "link": { "group": "hessian-step" },
            "xLabel": "Relative step r [-]",
            "yLabel": y_label,
            "xType": "log",
            "yType": "log",
            "annotations": annotations
        })
    );
}
emit_text!(format!("Zero-error points excluded from charts: {dropped}"));
```

At large steps, errors decrease along dashed leading terms with slope 1 forward or 2 central; at small steps, rounding grows proportionally to $r^{-2}$, giving V-shaped curves.
At default `f64`, error-minimizing relative steps for forward $H_{00}$ and $H_{01}$ are $1.0 \times 10^{-5}$ and $3.2 \times 10^{-6}$, and for central differences $3.2 \times 10^{-4}$ and $3.2 \times 10^{-5}$.
All are within a factor of 4 of defaults ($6.1 \times 10^{-6}$ forward, $1.2 \times 10^{-4}$ central).
Minimum errors are $6.9 \times 10^{-7}$ and $6.5 \times 10^{-6}$ forward, $1.7 \times 10^{-10}$ and $1.3 \times 10^{-10}$ central.

For `f32` (case single), defaults increase to $\varepsilon^{1/3} \approx 4.9 \times 10^{-3}$ and $\varepsilon^{1/4} \approx 1.9 \times 10^{-2}$, moving the V-shaped minima rightward.
Error-minimizing relative steps become $10^{-2}$ and $3.2 \times 10^{-3}$ forward, $5.6 \times 10^{-2}$ and $5.6 \times 10^{-3}$ central, again within a factor of 4 of defaults.

## Fixed-step evaluation counts

Gradients and Jacobians evaluate one point per coordinate forward or two centrally, sharing one base $\mathbf{x}$ call across coordinates.
Central Hessians use two axis points per diagonal and four points $\mathbf{x} \pm h_i \mathbf{e}_i \pm h_j \mathbf{e}_j$ per mixed term; forward Hessians use two axis points per diagonal and one new point $\mathbf{x} + h_i \mathbf{e}_i + h_j \mathbf{e}_j$ per mixed term.
The other three forward mixed points reuse base and diagonal-difference points.

Without boundaries or rounded node collapse, counts follow.
Passing $f(\mathbf{x})$ as known base `base` saves one call ([Subtracting base values and known base `base`](oxref:differentiate-base-argument)).

| Operation | Forward | Forward with `base` | Central | Central with `base` | Iterations `iterations()` |
|---|---|---|---|---|---|
| Gradient or Jacobian | $n + 1$ | $n$ | $2n + 1$ | $2n$ | $n$ |
| Hessian | $1 + 2n + n(n-1)/2$ | $2n + n(n-1)/2$ | $1 + 2n^2$ | $2n^2$ | $n + n(n-1)/2$ |

Central Hessians take $2n$ calls for $n$ diagonal entries and $4 \cdot n(n-1)/2$ for $n(n-1)/2$ upper-triangular mixed entries, totaling $1 + 2n + 2n(n-1) = 1 + 2n^2$ with the base.
Reported iterations `iterations()` count derivative units computed: coordinates or upper-triangular entries.
Directional derivatives need only 2 or 3 calls regardless of $n$ ([Directional evaluation counts](oxref:differentiate-jvp-costs)).

Near boundaries, forward differences choose a direction with enough room; if neither suffices, shrink steps in the roomier direction.
Central differences switch to same-order one-sided nodes in the roomier direction when room is insufficient ([Domain boundaries and one-sided differences](oxref:differentiate-bounded-fixed-nodes)).
Gradient and Jacobian counts remain unchanged in either case.
For central Hessians, each one-sided coordinate adds one diagonal second-difference point, and diagonal and mixed axis points no longer coincide; counts are at most $1 + 3n + 4n(n-1)$ before reuse.
Coordinates zeroed by `FixedCoordinatePolicy::FeasibleZero` are not sampled (available for gradients; [Coordinates with equal lower and upper bounds](oxref:differentiate-equal-bounds)).

Hessian evaluations scale with $n^2$ and are expensive with many variables.
If gradients are available, computing their Jacobian gives the Hessian with an evaluation count proportional to $n$; Hessian–vector products alone require only a directional derivative of the gradient.
Automatic differentiation (scioxide-ad), when available, is often more accurate and faster ([Choosing numerical differentiation](../../choosing/)).

## Adaptive and complex-step evaluation counts

`AdaptiveDifference` reduces steps and extrapolates per level until each entry converges ([Richardson extrapolation and Ridders' method](../richardson-and-ridders/)).
Away from boundaries, each level uses 2 calls per gradient or Jacobian coordinate or Hessian diagonal, and 4 per mixed Hessian entry, plus one base call.
One-sided near-boundary levels use 3 for Hessian diagonals and at most 8 mixed, while gradients and Jacobians remain at 2.
With coordinate $j$ level count $L_j$, gradients and Jacobians take $1 + 2\sum_j L_j$ evaluations.
Convergence needs 2 consecutive tolerance-satisfying estimates, first available at level 2; minimum 3 levels give $1 + 6n$ gradient calls.
Using all default 16 levels gives $1 + 32n$ gradient calls.
Report `iterations()` sums level counts.

`ComplexStep` computes gradients and Jacobians in $n + 1$ calls: one base check and one per coordinate.
The base call checks that $f(\mathbf{x})$ is real ([Complex-step differentiation and analytic extensions](../complex-step/)).

## Measuring counts versus variable count

The next cell varies $n$ from 2 to a selected maximum by 2, computing gradients and Hessians of $f(\mathbf{x}) = \sum_i \sin(x_i)\, x_{i+1}$ ($x_{n+1} = x_1$) with forward and central `FiniteDifference`.
The point is $x_i = 0.1 i$ ($i = 1, \dots, n$).
Each operation runs once without `base` and once passing $f(\mathbf{x})$ as `base`, comparing reported evaluations and iterations with the table formulas.
The table shows results at maximum $n$ and counts of values compared over every sampled $n$; the chart plots evaluations without `base` on logarithmic axes.

```rust
//| id: differentiate-evaluation-scaling
//| ref: differentiate-evaluation-scaling
//| title: "Gradient and Hessian evaluation counts versus variable count"
//| run: reactive
//| crates: [scioxide-core, scioxide-differentiate]
//| inputs:
//|   n_max: {"type":"range","label":"Maximum variables","description":"n shown in the table; the chart spans 2 through this value.","min":4,"max":16,"step":2,"value":16}
//| cases:
//|   - {"id":"small","label":"n = 4","description":"With few variables, central Hessian count 33 is close to gradient count 9.","inputs":{"n_max":4}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"counts","path":"/rows/0/2","equals":17}
//|       - {"artifact":"counts","path":"/rows/1/2","equals":33}
//|       - {"artifact":"counts","path":"/rows/1/4","equals":32}
//|       - {"artifact":"counts","path":"/rows/2/2","equals":153}
//|       - {"artifact":"counts","path":"/rows/3/2","equals":513}
//|       - {"artifact":"counts","path":"/rows/3/4","equals":512}
//|       - {"artifact":"counts","path":"/rows/3/6","equals":136}
//|       - {"artifact":"mismatch","path":"/rows/0/0","equals":96}
//|       - {"artifact":"mismatch","path":"/rows/0/1","equals":0}
//|   - case: small
//|     expect:
//|       - {"artifact":"counts","path":"/rows/0/2","equals":5}
//|       - {"artifact":"counts","path":"/rows/2/2","equals":15}
//|       - {"artifact":"counts","path":"/rows/3/2","equals":33}
//|       - {"artifact":"mismatch","path":"/rows/0/0","equals":24}
//|       - {"artifact":"mismatch","path":"/rows/0/1","equals":0}
use scioxide_core::{SciOxideError, RealScalar};
use scioxide_differentiate::{DifferenceScheme, FiniteDifference};

let n_max = n_max as usize;
let f = |p: &[f64], y: &mut [f64]| {
    let n = p.len();
    y[0] = (0..n).map(|i| RealScalar::sin(p[i]) * p[(i + 1) % n]).sum();
    Ok::<(), SciOxideError>(())
};
// Table evaluation counts (without base) and iterations; false hessian selects gradients.
let evaluations = |hessian: bool, central: bool, n: usize| match (hessian, central) {
    (false, false) => n + 1,
    (false, true) => 2 * n + 1,
    (true, false) => 1 + 2 * n + n * (n - 1) / 2,
    (true, true) => 1 + 2 * n * n,
};
let iterations = |hessian: bool, n: usize| if hessian { n + n * (n - 1) / 2 } else { n };
let (mut rows, mut series, mut checked, mut mismatches) = (Vec::new(), Vec::new(), 0, 0);
for (hessian, label) in [(false, "Gradient"), (true, "Hessian")] {
    for (central, scheme_name) in [(false, "Forward"), (true, "Central")] {
        let scheme = if central {
            DifferenceScheme::Central
        } else {
            DifferenceScheme::Forward
        };
        let method = FiniteDifference::default().with_scheme(scheme);
        let mut points = Vec::new();
        for n in (2..=n_max).step_by(2) {
            let x: Vec<f64> = (1..=n).map(|i| 0.1 * i as f64).collect();
            let mut value = [0.0];
            f(&x, &mut value).map_err(|e| e.to_string())?;
            let run = |known: Option<f64>| {
                let result = if hessian {
                    method.hessian(f, &x, None, known)
                } else {
                    method.gradient(f, &x, None, known)
                };
                result.map(|r| *r.report()).map_err(|e| e.to_string())

            let (plain, known) = (run(None)?, run(Some(value[0]))?);
            let expected = evaluations(hessian, central, n);
            let measured = [plain.evaluations(), known.evaluations(), plain.iterations()];
            let theory = [expected, expected - 1, iterations(hessian, n)];
            checked += 3;
            mismatches += measured.iter().zip(&theory).filter(|(a, b)| a != b).count();
            points.push([n as f64, plain.evaluations() as f64]);
            if n == n_max {
                rows.push((
                    label,
                    scheme_name,
                    measured[0],
                    theory[0],
                    measured[1],
                    theory[1],
                    measured[2],
                    theory[2],
                ));
            }
        }
        let name = format!("{label}, {scheme_name}");
        series.push(serde_json::json!({
            "name": name,
            "points": points,
            "style": { "showSymbol": true }
        }));
    }
}
let columns = serde_json::json!([
    { "key": "0", "label": "Operation" },
    { "key": "1", "label": "Formula" },
    { "key": "2", "label": "Evaluations [count]", "type": "integer" },
    { "key": "3", "label": "Theoretical count [count]", "type": "integer" },
    { "key": "4", "label": "Evaluations with base [count]", "type": "integer" },
    { "key": "5", "label": "Theoretical count [count]", "type": "integer" },
    { "key": "6", "label": "Iterations [count]", "type": "integer" },
    { "key": "7", "label": "Theoretical count [count]", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "counts" })
);
emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "Compared values [count]", "type": "integer" },
        { "key": "1", "label": "Mismatches from theory [count]", "type": "integer" }
    ]),
    vec![(checked, mismatches)],
    metadata = serde_json::json!({ "id": "mismatch" })

emit_line_chart!(
    &series,
    options = &serde_json::json!({

        "yType": "log"
    })
```

At $n = 16$, gradients take 17 forward or 33 central calls; Hessians take 153 forward or 513 central; supplying `base` saves one for each.
Gradient iterations are 16 and Hessian iterations 136, the upper-triangular entry count.
All 96 values compared at $n = 2, 4, \dots, 16$ match theory.
Logarithmic charts approach slope 1 for gradients and 2 for Hessians, displaying their different growth orders.
Central Hessians grow as $2n^2$ and forward as $n^2/2$, so cost ratios approach 4 for large $n$.
At $n = 4$ (case small), central Hessian count 33 is below 4 times gradient count 9; at $n = 16$, 513 versus 33 exceeds 15 times.

## Summary

Method methods (`DerivativeOperation` for node methods and Plans) select first or second derivatives, gradients, row-major Jacobians, symmetric row-major Hessians, or directions; input dimension follows point length.
Fixed central gradients and Jacobians use $2n + 1$ evaluations and Hessians $1 + 2n^2$, one fewer with known base `base`; for many variables, constructing Hessians from gradients or Jacobians saves calls.
Hessians use second-derivative defaults for diagonal and mixed terms, giving errors about $\varepsilon^{1/2}$ centrally or $\varepsilon^{1/3}$ forward, with bitwise symmetry through upper-triangle copying.
Default steps lie within a few times minimizing steps; since finding optima requires exact values, defaults are normally used.
Adaptive gradients require at least 3 levels per coordinate and hence at least $1 + 6n$ calls, in exchange for error estimates.
