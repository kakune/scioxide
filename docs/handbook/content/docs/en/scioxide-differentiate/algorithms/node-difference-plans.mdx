[Difference-stencil weights and arbitrary nodes](../stencil-weights/) constructs `FiniteDifferenceStencil` weights applied to caller-held values.
When the function is callable, supply only node positions and let the library evaluate and apply weights.
This suits fixed grids, high-order five- or seven-point formulas, and manually placed nodes near boundaries.
This page explains fixed-point Plan `PhysicalDifferencePlan`, displacement method `RelativeDifference`, and one-shot `physical_difference_derivative` contracts, then measures Hessian and scalar-derivative counts and errors.
Unlike fixed-step `FiniteDifference`, callers choose node positions and counts, with neither default steps nor node reselection at boundaries.

## Operations and options

`PhysicalDifferencePlan` and `RelativeDifference` select derivatives through [`DerivativeOperation`](https://docs.rs/scioxide-differentiate/0.1.0/scioxide_differentiate/enum.DerivativeOperation.html).
They support first derivatives (`First`, `Gradient`, `Jacobian`), second derivatives (`Second`), and Hessians (`Hessian`), without directions.
For directional derivatives, use `AdaptiveDifference::jvp` or `ComplexStep::jvp`, or compute the first derivative of $t \mapsto f(\mathbf{x} + t \mathbf{v})$ with these node methods.
`First` and `Second` require one-dimensional input and output; `Gradient` and `Hessian` require scalar output.
Mismatches make `new` return `InvalidInput` (`operation`, `UnsupportedConfiguration`).
Outputs are row-major; Jacobian $\partial f_i / \partial x_j$ occupies $i n + j$ ([Operations and output layout](oxref:differentiate-operations-layout)).
Real- and complex-valued functions are supported, differentiating real and imaginary parts separately over real coordinates.

Set execution policy, evaluation and iteration limits, and workspace limits through `with_execution`, `with_budgets`, and `with_max_workspace_bytes` of [`NodeDifferenceOptions`](https://docs.rs/scioxide-differentiate/0.1.0/scioxide_differentiate/struct.NodeDifferenceOptions.html).
Defaults are sequential without evaluation, iteration, or workspace limits.
There are no step or formula settings.

## Plans fixing evaluation points and nodes

[`PhysicalDifferencePlan`](https://docs.rs/scioxide-differentiate/0.1.0/scioxide_differentiate/struct.PhysicalDifferencePlan.html)`::new(operation, point, nodes, outputs, options)` fixes evaluation point `point` and per-coordinate physical node locations `nodes` at construction.
First-derivative weights per coordinate, plus second-derivative weights for `Second` and `Hessian`, are computed once with [Fornberg's recurrence](oxref:differentiate-fornberg).
Weight construction takes $O(k^2)$ operations for a coordinate with $k$ nodes.
Owned `evaluate(f, bounds)` and borrowed `evaluate_into(f, bounds, out, workspace, scope)` take no point, evaluating at the construction point.
This suits fixed-grid computations; another point requires new nodes and a new Plan.

## Node methods storing displacements

[`RelativeDifference`](https://docs.rs/scioxide-differentiate/0.1.0/scioxide_differentiate/struct.RelativeDifference.html)`::new(operation, offsets, outputs, options)` stores sequences `offsets` of per-coordinate displacements $\Delta$.
Zero displacement denotes the evaluation point itself.
`evaluate(f, x, bounds)` and `evaluate_into(f, x, bounds, out, workspace, scope)` relocate nodes to $x_i + \Delta$ at each evaluation.
Since relocation includes rounding, weights are recomputed from rounded displacements every time.
This takes $O(k^2)$ operations per coordinate ($k$ displacements) inside workspace without allocation.
It suits moving points with the same formula, such as optimization iterations or time-evolution stages.

Both obtain requirements and reserve workspace with `workspace_requirements::<T>(())` and `workspace::<T>(())` for each function-value type `T` ([Plans, requirements, and workspaces](oxref:differentiate-plans-requirements)).

## Construction and evaluation checks

`new` checks the following.
Each coordinate needs at least 2 nodes or displacements for first derivatives and 3 for `Second` and `Hessian`; too few give `InvalidInput` (`nodes` or `offsets`, `OutOfRange`).
Duplicate nodes or displacements give `InvalidInput` (`Inconsistent`).
Nonfinite `PhysicalDifferencePlan` points or nodes, or `RelativeDifference` displacements, give `NonFinite`.
For `PhysicalDifferencePlan`, node-sequence counts mismatching point dimension give `DimensionMismatch`.

Neither moves nodes to fit bounds; nodes outside `bounds` are rejected before function calls.
For `PhysicalDifferencePlan`, out-of-bounds points give `InvalidInput` (`bounds`, `OutOfRange`), and nodes give `InvalidInput` (`bounds`, `UnsupportedConfiguration`).
`RelativeDifference` checks points at every evaluation: nonfinite points give `NonFinite`, out-of-bounds points `InvalidInput` (`x`, `OutOfRange`).
Nonfinite relocated nodes, out-of-bounds nodes, or nodes rounded onto other nodes or the base give `InvalidInput` (`x`, `UnsupportedConfiguration`).
Near endpoints, callers choose displacements staying inside ([Domain boundaries and one-sided differences](../bounds-and-one-sided/)).

## Accuracy, evaluation counts, and termination

A coordinate formula with $k$ nodes differentiates polynomials through degree $k - 1$ exactly.
Order-$d$ derivatives with spacing $h$ have truncation error $O(h^{k - d})$; nodes symmetric about the evaluation point may raise the order ([Moment conditions](oxref:differentiate-moment-conditions)).
Function-value rounding is amplified by the absolute-weight sum, so overly small $h$ increases errors ([Absolute-weight sums and noise amplification](oxref:differentiate-noise-amplification)).

Counts depend on node counts; no argument supplies known values such as `base`.
First derivatives take $\sum_i k_i$ calls, the sum of coordinate node counts $k_i$.
No reuse occurs across axes, so zero-displacement nodes are evaluated for each axis.

Hessians use second-derivative stencils diagonally and tensor products of two first-derivative stencils for mixed terms, computing and reflecting the upper triangle.
Mixed term $H_{ij}$ uses $k_i k_j$ point values.
Within one evaluation, base and axis-point values (one coordinate moved) are retained, avoiding repeated evaluation of bitwise-identical points.
When every axis includes the base, mixed terms reuse base and axis points, giving the following count.

$$
1 + \sum_i (k_i - 1) + \sum_{i < j} (k_i - 1)(k_j - 1).
$$

Axes omitting the base reduce reuse and increase counts.

No estimates return; completing planned evaluations gives termination `Completed`.
This indicates completion only, without accuracy claims.
See [Outputs on failure](oxref:differentiate-failure-outputs) for limit termination and publication rules.

## Hessian measurements

Let the differentiated function be $f(x, y) = e^{x} \sin y$.
Its exact Hessian follows.

$$
\mathbf{H} = \begin{pmatrix} e^x \sin y & e^x \cos y \\ e^x \cos y & -e^x \sin y \end{pmatrix}.
$$

Five nodes $\{-2h, -h, 0, h, 2h\}$ per axis give five-point second-derivative diagonals and tensor products of five-point first derivatives for mixed terms.
The leading error of a five-point central first derivative is $-h^4 f^{(5)} / 30$.
Mixed terms apply it successively along $x$ and $y$, so leading terms add across directions.

$$
H_{01} - \partial_x \partial_y f \approx -\frac{h^4}{30} \left( \partial_x^5 \partial_y f + \partial_x \partial_y^5 f \right) = -\frac{h^4}{15} e^x \cos y .
$$

Diagonal leading term $-h^4 f^{(6)} / 90$ is smaller, so mixed terms usually determine maximum error.
The following definitions hold differentiated function `surface` and exact derivatives for checks.

```rust
//| id: differentiate-node-surface-model
//| kind: definitions
//| title: "Differentiated function f(x, y) = e^x sin y and exact derivatives"
//| crates: [scioxide-core]
use scioxide_core::RealScalar;

/// Differentiated f(x, y) = e^x sin y, evaluated with SciOxide functions.
pub(crate) fn surface(x: f64, y: f64) -> f64 {
    RealScalar::exp(x) * RealScalar::sin(y)
}

/// Exact Hessian, row-major. Reference from f64 inherent methods.
pub(crate) fn exact_hessian(x: f64, y: f64) -> [f64; 4] {
    let (s, c) = y.sin_cos();
    let g = x.exp();
    [g * s, g * c, g * c, -g * s]
}

/// Exact partial ∂f/∂x = e^x sin y. Reference from f64 inherent methods.
pub(crate) fn exact_slope(x: f64, y: f64) -> f64 {
    x.exp() * y.sin()
}
```

The next cell computes this Hessian with `RelativeDifference` and `PhysicalDifferencePlan` at points $(0.2, 0.4)$ and $(0.5, 1.0)$.
`RelativeDifference` reuses one method value at both points; `PhysicalDifferencePlan` places nodes and rebuilds the Plan per point.
The table compares evaluations with theoretical counts and shows maximum error, mixed $H_{01}$ error, and its leading-term prediction.
Exact values and leading predictions are references using f64 inherent methods.

```rust
//| id: differentiate-node-plans
//| ref: differentiate-node-plans
//| title: "Hessians and node relocation with physical and displacement nodes"
//| run: reactive
//| uses: [differentiate-node-surface-model]
//| crates: [scioxide-core, scioxide-differentiate]
//| inputs:
//|   spacing: {"type":"select","label":"Node spacing h","options":["0.001","0.01","0.1"],"value":"0.01"}
//| cases:
//|   - {"id":"coarse","label":"h = 0.1","description":"Truncation grows by 10⁴ proportionally to h⁴, remaining consistent with the leading prediction at order 10⁻⁶.","inputs":{"spacing":"0.1"}}
//|   - {"id":"fine","label":"h = 0.001","description":"The leading term falls to 10⁻¹³, but second-difference rounding raises actual error above prediction.","inputs":{"spacing":"0.001"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"hessian","path":"/rows/0/3","equals":25}
//|       - {"artifact":"hessian","path":"/rows/0/4","equals":25}
//|       - {"artifact":"hessian","path":"/rows/2/3","equals":25}
//|       - {"artifact":"hessian","path":"/rows/0/6","approx":{"value":-7.49991e-10,"rtol":0.01}}
//|       - {"artifact":"hessian","path":"/rows/1/6","approx":{"value":-5.93872e-10,"rtol":0.01}}
//|       - {"artifact":"hessian","path":"/rows/3/5","range":{"max":8e-10}}
//|   - case: coarse
//|     expect:
//|       - {"artifact":"hessian","path":"/rows/0/6","approx":{"value":-7.49991e-6,"rtol":0.02}}
//|       - {"artifact":"hessian","path":"/rows/3/6","approx":{"value":-5.93872e-6,"rtol":0.02}}
//|   - case: fine
//|     expect:
//|       - {"artifact":"hessian","path":"/rows/1/5","range":{"min":7e-11,"max":8.2e-10}}
use scioxide_core::SciOxideError;
use scioxide_differentiate::{
    DerivativeOperation, NodeDifferenceOptions, PhysicalDifferencePlan, RelativeDifference,
};

let h: f64 = spacing.parse().map_err(|_| "Cannot read spacing")?;
let f = |p: &[f64], y: &mut [f64]| {
    y[0] = surface(p[0], p[1]);
    Ok::<(), SciOxideError>(())
};
let offsets = [-2.0 * h, -h, 0.0, h, 2.0 * h];
// Count when all axes contain the base: 1 + Σ(k_i − 1) + Σ_{i<j}(k_i − 1)(k_j − 1).
let k = offsets.len() - 1;
let theory = 1 + 2 * k + k * k;
// Rows: (method, x, y, evaluations, theoretical count, maximum error, H₀₁ error, H₀₁ leading prediction).
let row = |name: &'static str, point: [f64; 2], hessian: &[f64], evaluations: usize| {
    let reference = exact_hessian(point[0], point[1]);
    let errors: Vec<f64> = hessian.iter().zip(reference).map(|(a, b)| a - b).collect();
    let max_error = errors.iter().fold(0.0_f64, |m, e| m.max(e.abs()));
    // Mixed leading term −h⁴ e^x cos y / 15.
    let predicted = -h.powi(4) * reference[1] / 15.0;
    (
        name,
        point[0],
        point[1],
        evaluations,
        theory,
        max_error,
        errors[1],
        predicted,
    )
};
let points = [[0.2_f64, 0.4], [0.5, 1.0]];
// RelativeDifference stores only displacements, so the same method serves different points.
let relative = RelativeDifference::new(
    DerivativeOperation::Hessian,
    &[&offsets, &offsets],
    1,
    NodeDifferenceOptions::default(),
)
.map_err(|e| e.to_string())?;
let mut rows = Vec::new();
for point in points {
    let result = relative
        .evaluate(f, &point, None)
        .map_err(|e| e.to_string())?;
    let hessian = result.values().ok_or("Hessian not published")?;
    rows.push(row(
        "RelativeDifference",
        point,
        hessian,
        result.report().evaluations(),
    ));
}
// PhysicalDifferencePlan fixes the base at construction, requiring node placement and construction per point.
for point in points {
    let nodes_x: Vec<f64> = offsets.iter().map(|d| point[0] + d).collect();
    let nodes_y: Vec<f64> = offsets.iter().map(|d| point[1] + d).collect();
    let physical = PhysicalDifferencePlan::new(
        DerivativeOperation::Hessian,
        &point,
        &[&nodes_x, &nodes_y],
        1,
        NodeDifferenceOptions::default(),
    )
    .map_err(|e| e.to_string())?;
    let result = physical.evaluate(f, None).map_err(|e| e.to_string())?;
    let hessian = result.values().ok_or("Hessian not published")?;
    rows.push(row(
        "PhysicalDifferencePlan",
        point,
        hessian,
        result.report().evaluations(),
    ));
}
let (fixed2, sci3) = (
    serde_json::json!({ "fractionDigits": 2 }),
    serde_json::json!({ "notation": "scientific", "significantDigits": 3 }),
);
let columns = serde_json::json!([
    { "key": "0", "label": "Method" },
    { "key": "1", "label": "Evaluation point x [-]", "type": "number", "format": fixed2 },
    { "key": "2", "label": "Evaluation point y [-]", "type": "number", "format": fixed2 },
    { "key": "3", "label": "Evaluations [count]", "type": "integer" },
    { "key": "4", "label": "Theoretical count [count]", "type": "integer" },
    { "key": "5", "label": "Maximum error [-]", "type": "number", "format": sci3 },
    { "key": "6", "label": "H₀₁ error [-]", "type": "number", "format": sci3 },
    { "key": "7", "label": "H₀₁ leading prediction [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "hessian" })
);
```

At default $h = 0.01$, both compute Hessians in 25 calls, matching theoretical $1 + 4 + 4 + 16 = 25$.
Maximum error is mixed $H_{01}$ error: $-7.50 \times 10^{-10}$ at $(0.2, 0.4)$ and $-5.94 \times 10^{-10}$ at $(0.5, 1.0)$, agreeing with prediction $-h^4 e^x \cos y / 15$ to 3 significant digits.
`RelativeDifference` reuses one method at both points and matches `PhysicalDifferencePlan` rebuilt per point.
Both round nodes in the same order as $x_i + \Delta$, yielding identical weights.

At $h = 0.1$ (case coarse), errors grow by $10^4$ proportionally to $h^4$, becoming $-7.50 \times 10^{-6}$ and $-5.94 \times 10^{-6}$ while matching leading predictions.
At $h = 0.001$ (case fine), leading truncation falls to order $10^{-13}$, but errors greatly exceed predictions.
Five-point second-derivative weights $(-1, 16, -30, 16, -1)/(12 h^2)$ have absolute sum $64/(12 h^2)$, giving rounding guideline $u \lvert f \rvert \cdot 64/(12 h^2)$ equal to $8 \times 10^{-10}$ at point $(0.5, 1.0)$.
Maximum error $5.0 \times 10^{-10}$ there is diagonal and below the rounding guideline ([Rounding, noise, and optimal step size](../roundoff-and-noisy-functions/)).

## One-shot functions for scalar functions

For scalar first derivatives alone, use one-shot [`physical_difference_derivative`](https://docs.rs/scioxide-differentiate/0.1.0/scioxide_differentiate/fn.physical_difference_derivative.html)`(f, x, nodes)`.
`f` is `Fn(S) -> Result<T, SciOxideError>`, with real or complex values.
It accepts physical node locations, constructs default-options `PhysicalDifferencePlan`, evaluates once, and returns only values.
Nodes may omit the base; fewer than 2 give `InvalidInput` (`nodes`, `OutOfRange`).
Displacement nodes have no one-shot function; construct `RelativeDifference` with `First` and call `evaluate`.

For the symmetric five-point first derivative $\{-2h, -h, 0, h, 2h\}$, the base weight is zero by symmetry.
The four-node formula $\{-2h, -h, h, 2h\}$ omitting the base has the same weights because moment-condition solutions are unique.
With four nodes, $N - m = 3$ is odd and symmetry raises order by one to 4 ([Moment conditions](oxref:differentiate-moment-conditions)).
Even a zero-weight base is evaluated; omitting it saves one call at unchanged accuracy.

The next cell computes the derivative of $g(x) = f(x, 0.4) = e^x \sin 0.4$ at $x = 0.2$ through `physical_difference_derivative` and first-derivative `RelativeDifference`, comparing with leading term $-h^4 g^{(5)}(0.2) / 30$.
Node input switches between five points including the base and four excluding it.
For value-only `physical_difference_derivative`, count function calls to obtain evaluations.

```rust
//| id: differentiate-node-scalar-derivative
//| ref: differentiate-node-scalar-derivative
//| title: "Scalar derivatives and evaluation counts with one-shot functions and displacement nodes"
//| run: reactive
//| uses: [differentiate-node-surface-model]
//| crates: [scioxide-core, scioxide-differentiate]
//| inputs:
//|   spacing: {"type":"select","label":"Node spacing h","options":["0.001","0.01","0.1"],"value":"0.01"}
//|   layout: {"type":"select","label":"Nodes","description":"Displacements from the evaluation point.","options":["5 nodes {−2h, −h, 0, h, 2h}","4 nodes {−2h, −h, h, 2h}"],"value":"5 nodes {−2h, −h, 0, h, 2h}"}
//| cases:
//|   - {"id":"without-center","label":"4 nodes without base","description":"The base weight is 0; omitting it saves one call without changing the leading error.","inputs":{"layout":"4 nodes {−2h, −h, h, 2h}"}}
//|   - {"id":"coarse","label":"h = 0.1","description":"Error grows by 10⁴ proportionally to h⁴, remaining consistent with leading prediction at order 10⁻⁶.","inputs":{"spacing":"0.1"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"scalar","path":"/rows/0/1","equals":5}
//|       - {"artifact":"scalar","path":"/rows/1/1","equals":5}
//|       - {"artifact":"scalar","path":"/rows/0/2","approx":{"value":-1.58546e-10,"rtol":0.02}}
//|       - {"artifact":"scalar","path":"/rows/1/2","approx":{"value":-1.58546e-10,"rtol":0.02}}
//|   - case: without-center
//|     expect:
//|       - {"artifact":"scalar","path":"/rows/0/1","equals":4}
//|       - {"artifact":"scalar","path":"/rows/1/1","equals":4}
//|       - {"artifact":"scalar","path":"/rows/0/2","approx":{"value":-1.58546e-10,"rtol":0.02}}
//|   - case: coarse
//|     expect:
//|       - {"artifact":"scalar","path":"/rows/0/2","approx":{"value":-1.58546e-6,"rtol":0.02}}
use scioxide_core::SciOxideError;
use scioxide_differentiate::{
    DerivativeOperation, NodeDifferenceOptions, RelativeDifference,
    physical_difference_derivative,
};

let h: f64 = spacing.parse().map_err(|_| "Cannot read spacing")?;
let offsets: Vec<f64> = if layout.starts_with("4") {
    vec![-2.0 * h, -h, h, 2.0 * h]
} else {
    vec![-2.0 * h, -h, 0.0, h, 2.0 * h]
};
let (x0, y0) = (0.2_f64, 0.4_f64);
// g(x) = f(x, 0.4). Count calls to measure evaluations of the value-only one-shot function.
let calls = std::cell::Cell::new(0_usize);
let g = |x: f64| {
    calls.set(calls.get() + 1);
    Ok::<f64, SciOxideError>(surface(x, y0))
};
let nodes: Vec<f64> = offsets.iter().map(|d| x0 + d).collect();
let by_nodes: f64 = physical_difference_derivative(g, x0, &nodes).map_err(|e| e.to_string())?;
let physical_calls = calls.get();
let first = RelativeDifference::new(
    DerivativeOperation::First,
    &[&offsets],
    1,
    NodeDifferenceOptions::default(),
)
.map_err(|e| e.to_string())?;
let sample = |x: &[f64], y: &mut [f64]| {
    y[0] = surface(x[0], y0);
    Ok::<(), SciOxideError>(())
};
let by_offsets = first
    .evaluate(sample, &[x0], None)
    .map_err(|e| e.to_string())?;
let value = by_offsets.values().ok_or("Derivative not published")?[0];
// Reference: g′(0.2) = e^0.2 sin 0.4 and leading −h⁴ g⁽⁵⁾(0.2) / 30 (g⁽⁵⁾ = g′).
let reference = exact_slope(x0, y0);
let predicted = -h.powi(4) * reference / 30.0;
let rows = vec![
    (
        "physical_difference_derivative",
        physical_calls,
        by_nodes - reference,
        predicted,
    ),
    (
        "RelativeDifference（First）",
        by_offsets.report().evaluations(),
        value - reference,
        predicted,
    ),
];
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "Call" },
    { "key": "1", "label": "Evaluations [count]", "type": "integer" },
    { "key": "2", "label": "g′(0.2) error [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "Leading prediction [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "scalar" })
);
```

At default $h = 0.01$ and five nodes, both calls take 5 evaluations; error $-1.59 \times 10^{-10}$ agrees with leading $-h^4 g^{(5)}(0.2)/30$ to 3 significant digits.
Four nodes without the base (case without-center) reduce calls to 4, giving the same error $-1.59 \times 10^{-10}$ within rounding difference $1.1 \times 10^{-16}$ from five nodes.
At $h = 0.1$ (case coarse), error grows by $10^4$ to $-1.59 \times 10^{-6}$, differing from the leading prediction by 0.1%.

## Summary

For callable functions with selected nodes, use Plan `PhysicalDifferencePlan` for fixed points or node method `RelativeDifference` to reuse displacements as points move.
Both select operations with `DerivativeOperation`, check node counts and duplicates at construction and out-of-bounds nodes before function calls, and never move nodes to fit bounds.
Counts depend on nodes; Hessians with every axis containing the base reuse base and axis points, taking $1 + \sum_i (k_i - 1) + \sum_{i<j} (k_i - 1)(k_j - 1)$ calls.
No estimates return and `Completed` makes no accuracy claim; assess errors from leading $O(h^{k-d})$ and rounding guidelines based on absolute-weight sums.
Use one-shot `physical_difference_derivative` for scalar first derivatives; symmetric nodes allow omitting the zero-weight base to save a call.
