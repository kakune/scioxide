`scioxide-differentiate` provides method values and one-shot functions for fixed-step, adaptive, and complex-step differentiation; node-difference and colored-Jacobian Plans; results; function-passing types; and derivative-source selection.
This guide identifies suitable items by task and groups all 48 public items into three table pages.
Item-name links point to the version 0.1.0 API reference on docs.rs.

## Type relationships

Method values `FiniteDifference`, `AdaptiveDifference`, and `ComplexStep` hold configuration only; `with_scheme`, `with_tolerance`, `with_step`, and similar methods create new values with changed settings.
Methods (`derivative`, `second_derivative`, `gradient`, `jacobian`, `hessian`, `jvp`) select operations; point length determines input dimension $n$, and arguments to `jacobian` and `jvp` determine function-output count $m$.
Settings are checked whenever an operation using them is called.
Method values hold no Plan; prepare workspace from method-and-operation pair `DerivativeRequest::new(&method, DerivativeShape::gradient(n))` using the workspace type's associated functions `workspace_requirements(request)` and `workspace(request)`.
`FixedCoordinatePolicy` (equal lower and upper coordinate bounds) and `ZeroDirectionPolicy` (`jvp` for a zero direction) are method settings.

Plans `ColoredJacobianPlan`, `PhysicalDifferencePlan`, and `ComplexStepPlan` and displacement-node method values `RelativeDifference` and `RelativeComplexStep` are constructed with `new`, checking dimensions, nodes, and settings at construction.
`PhysicalDifferencePlan` and `RelativeDifference` take operations through `DerivativeOperation` and settings through `NodeDifferenceOptions`.
They prepare requirements and workspaces with `plan.workspace_requirements(())` and `plan.workspace(())` and evaluate with `evaluate` and `evaluate_into`.
Requirements (such as `FiniteDifferenceRequirements`) return needed sizes without allocation; workspaces (such as `FiniteDifferenceWorkspace`) check capacity with `check` and grow to requirements with `try_reserve`.

Evaluation points and directional-derivative directions are supplied on each evaluation.
However, `PhysicalDifferencePlan` and `ComplexStepPlan` fix evaluation points at construction, so `evaluate` takes only the function and bounds.
Bounds `bounds` are accepted by multivariate `FiniteDifference` and `AdaptiveDifference` operations and evaluations of Plans and node methods, but not by `ComplexStep` operations.
Only `FiniteDifference` accepts a known base value $f(x)$ through `base`.

Functions are passed in two groups of forms.
Scalar `derivative`, `second_derivative`, and `FiniteDifference::derivative_into` accept closures taking $x$ and returning $f(x)$ (`ComplexStep::derivative` uses complex arguments and values).
Other operations and Plans accept one of three forms implementing sealed trait `SampleFunction`.
Closure `FnMut(&[S], &mut [T])` runs sequentially on the calling thread; `Contextual(f)` also receives evaluation solve context `&mut SolveContext`; `Parallel(f)` (`Fn + Sync`) evaluates independent samples on the executor according to method or Plan `ExecutionPolicy`.
Every form receives a point and overwrites every output-array element with a finite value.
Complex-step functions are analytic extensions of real functions, accepting complex points and returning complex values.

Owned forms return `DifferentiationResult` (values, estimated errors, and report); borrowed forms return only `DifferentiationReport`.
Reports store the producing method (`DerivativeSource`), termination reason (`DifferentiationTermination`), evaluation and iteration counts, completed-entry count, and whether output was published.

`DerivativeStrategy` and `DerivativeCandidate` are policies and candidates for solvers to try derivative sources (analytic, automatic, or differences) in order, rather than Plans.

## Call forms

An operation has the following three call forms.
Definitions appear in [Call forms](oxref:differentiate-call-forms-terms); choosing forms and handling workspaces appears in [Owned and borrowed forms](oxref:differentiate-owned-borrowed).

| Form | Example | Accepts | Returns | Execution context |
|---|---|---|---|---|
| One-shot function | `derivative(f, x)`, `gradient(f, &x)`, `jacobian(f, &x, m)`, `sparse_jacobian(f, &x, &schedule)` | Function and point (plus output count, direction, coloring, or nodes) | Values only; unsuccessful termination gives errors | `sequential_native()` |
| Owned form | `method.gradient(f, &x, bounds, base)`, `plan.evaluate(f, &x, bounds)` | Function, point, bounds, etc. | Newly allocated `DifferentiationResult` | `sequential_native()` |
| Borrowed `*_into` | `method.gradient_into(f, &x, bounds, base, &mut out, &mut workspace, scope)`, `plan.evaluate_into(…)` | Owned-form arguments plus output, workspace, and context | `DifferentiationReport` | Supplied context |

One-shot functions evaluate once with default settings and return values only.
These functions take `Fn` closures: functions with `gradient` and `hessian` return values from points; those with `jacobian`, `jvp`, and `sparse_jacobian` write output arrays, so `Contextual` and `Parallel` cannot be supplied.
Unsuccessful termination becomes errors through the same mapping as `require_success`.

Owned forms allocate workspace and results on every call and evaluate with `ExecutionContext::sequential_native()`, a context running sequentially on the caller's thread.
Borrowed forms borrow caller-provided output arrays, workspace, and context, allocating no numerical storage when workspace suffices.
Passing an outer solver's `&mut SolveContext` as context makes difference evaluation a nested solve, counting function evaluations against outer evaluation limits too ([Evaluation and iteration limits and solve accounting](oxref:differentiate-budgets)).

## Minimal example: three function-passing forms

The next cell computes the gradient of $f(\mathbf{x}) = \sum_i x_i^2 \sin x_i$ with default central-difference `FiniteDifference`.
Construct the method and workspace (sized by `DerivativeRequest`) once, then pass closures, `Contextual`, and `Parallel` functions to `gradient_into` using the same workspace.
Since these forms have different types, cell function `evaluate` accepts the function through trait bound `impl SampleFunction<f64, f64>`.
The evaluation point is $x_i = 0.4 + 0.3 i$; the computed gradient is compared with the exact gradient $\partial f / \partial x_i = 2 x_i \sin x_i + x_i^2 \cos x_i$.
On every call, the `Contextual` function charges 1 iteration to its received context.
Setting the method's iteration limit to $n$ through input shows that this work counts against the same limit as difference evaluation.

```rust
//| id: differentiate-api-minimal
//| ref: differentiate-api-minimal
//| title: "Three function-passing forms and reading reports"
//| run: reactive
//| crates: [scioxide-core, scioxide-differentiate]
//| inputs:
//|   n: {"type":"range","label":"Variable count n [-]","min":1,"max":6,"step":1,"value":3}
//|   limited: {"type":"checkbox","label":"Set iteration limit to n","value":false}
//| cases:
//|   - {"id":"iteration-limit","label":"Iteration limit n","description":"The n difference iterations fit the limit, but iterations charged by the Contextual function exceed it, making the function return an error.","inputs":{"limited":true}}
//|   - {"id":"one-variable-limit","label":"n = 1, limit 1","description":"The base-point evaluation exhausts the limit; differences stop with IterationLimit without publishing output.","inputs":{"n":1,"limited":true}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"forms","path":"/rows/0/1","equals":"Completed"}
//|       - {"artifact":"forms","path":"/rows/0/3","equals":"FiniteDifference(Central)"}
//|       - {"artifact":"forms","path":"/rows/0/4","equals":7}
//|       - {"artifact":"forms","path":"/rows/0/5","equals":3}
//|       - {"artifact":"forms","path":"/rows/0/6","equals":3}
//|       - {"artifact":"forms","path":"/rows/0/7","equals":true}
//|       - {"artifact":"forms","path":"/rows/0/8","range":{"max":1e-10}}
//|       - {"artifact":"forms","path":"/rows/1/4","equals":7}
//|       - {"artifact":"forms","path":"/rows/1/5","equals":3}
//|       - {"artifact":"forms","path":"/rows/2/4","equals":7}
//|       - {"artifact":"forms","path":"/rows/2/8","range":{"max":1e-10}}
//|   - case: iteration-limit
//|     expect:
//|       - {"artifact":"forms","path":"/rows/0/1","equals":"Completed"}
//|       - {"artifact":"forms","path":"/rows/0/5","equals":3}
//|       - {"artifact":"forms","path":"/rows/1/1","equals":null}
//|       - {"artifact":"forms","path":"/rows/1/2","equals":"DifferentiationFailure"}
//|       - {"artifact":"forms","path":"/rows/2/1","equals":"Completed"}
//|   - case: one-variable-limit
//|     expect:
//|       - {"artifact":"forms","path":"/rows/0/4","equals":3}
//|       - {"artifact":"forms","path":"/rows/1/1","equals":"IterationLimit"}
//|       - {"artifact":"forms","path":"/rows/1/4","equals":1}
//|       - {"artifact":"forms","path":"/rows/1/7","equals":false}
//|       - {"artifact":"forms","path":"/rows/1/8","equals":null}
use scioxide_core::{
    Budget, BudgetKind, ExecutionContext, SciOxideError, RealScalar, SolveBudgets, SolveContext,
};
use scioxide_differentiate::{
    Contextual, DerivativeRequest, DerivativeShape, FiniteDifference,
    FiniteDifferenceWorkspace, Parallel, SampleFunction,
};

// (Form, termination reason, error kind, source(), evaluations, iterations, completed entries, published, maximum error)
type Row = (
    &'static str,
    Option<String>,
    Option<String>,
    Option<String>,
    Option<usize>,
    Option<usize>,
    Option<usize>,
    Option<bool>,
    Option<f64>,
);
/// Accept functions through SampleFunction and pass them to gradient_into to support all three forms.
fn evaluate(
    form: &'static str,
    f: impl SampleFunction<f64, f64>,
    method: &FiniteDifference<f64>,
    x: &[f64],
    workspace: &mut FiniteDifferenceWorkspace<f64>,
    exact: &[f64],
) -> Row {
    let mut gradient = vec![0.0; x.len()];
    let context = ExecutionContext::sequential();
    match method.gradient_into(f, x, None, None, &mut gradient, workspace, context) {
        Ok(report) => {
            let error = report.output_available().then(|| {
                let gaps = gradient.iter().zip(exact).map(|(g, e)| (g - e).abs());
                gaps.fold(0.0, f64::max)
            });
            (
                form,
                Some(report.termination().to_string()),
                None,
                Some(format!("{:?}", report.source())),
                Some(report.evaluations()),
                Some(report.iterations()),
                Some(report.completed_entries()),
                Some(report.output_available()),
                error,
            )
        }
        Err(e) => {
            let kind = format!("{:?}", e.kind());
            (form, None, Some(kind), None, None, None, None, None, None)
        }
    }
}

let n = n as usize;
let x: Vec<f64> = (0..n).map(|i| 0.4 + 0.3 * i as f64).collect();
let value = |p: &[f64]| p.iter().map(|&v| v * v * RealScalar::sin(v)).sum::<f64>();
let budgets = if limited {
    let limit = Budget::try_from(n).map_err(|e| e.to_string())?;
    SolveBudgets::unbounded().with_limit(BudgetKind::Iteration, limit)
} else {
    SolveBudgets::unbounded()
};
let method = FiniteDifference::default().with_budgets(budgets);
let request = DerivativeRequest::new(&method, DerivativeShape::gradient(n));
let mut workspace = FiniteDifferenceWorkspace::workspace(request).map_err(|e| e.to_string())?;
// Reference: ∂f/∂x_i = 2 x_i sin x_i + x_i² cos x_i (f64 inherent methods).
let exact: Vec<f64> = x
    .iter()
    .map(|v| 2.0 * v * v.sin() + v * v * v.cos())
    .collect();
let closure = |p: &[f64], y: &mut [f64]| {
    y[0] = value(p);
    Ok::<(), SciOxideError>(())
};
// Charge work inside the function as iterations to the difference-evaluation context.
let contextual = Contextual(
    |p: &[f64], y: &mut [f64], context: &mut SolveContext<'_, '_>| {
        context.record_iteration()?.require()?;
        y[0] = value(p);
        Ok::<(), SciOxideError>(())
    },
);
let mut rows = Vec::new();
rows.push(evaluate(
    "Closure",
    closure,
    &method,
    &x,
    &mut workspace,
    &exact,
));
rows.push(evaluate(
    "Contextual",
    contextual,
    &method,
    &x,
    &mut workspace,
    &exact,
));
rows.push(evaluate(
    "Parallel",
    Parallel(closure),
    &method,
    &x,
    &mut workspace,
    &exact,
));
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "Function form" },
    { "key": "1", "label": "termination()", "nullText": "—" },
    { "key": "2", "label": "Error kind", "nullText": "None" },
    { "key": "3", "label": "source()", "nullText": "—" },
    { "key": "4", "label": "evaluations() [count]", "type": "integer", "nullText": "—" },
    { "key": "5", "label": "iterations() [count]", "type": "integer", "nullText": "—" },
    { "key": "6", "label": "completed_entries() [count]", "type": "integer", "nullText": "—" },
    { "key": "7", "label": "output_available()", "type": "boolean", "nullText": "—" },
    { "key": "8", "label": "Maximum gradient error [-]", "type": "number", "format": sci3, "nullText": "—" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "forms" })
);
```

At default $n = 3$, all three forms have `source()` equal to `FiniteDifference(Central)`, termination `Completed`, $2n + 1 = 7$ evaluations, and $n = 3$ iterations and completed entries.
The 7 evaluations comprise 1 at base point $f(\mathbf{x})$ and 2 at $f(\mathbf{x} \pm h \mathbf{e}_i)$ per coordinate; iterations count once per coordinate.
Maximum gradient error is $3.5 \times 10^{-11}$, matching the central-difference error scale $\varepsilon^{2/3} \approx 4 \times 10^{-11}$.
The 7 iterations charged by the `Contextual` function count toward the difference context but are absent from report `iterations()`.
The method's default policy is `Sequential`, so the `Parallel` function runs on the caller's thread and gives the same result as a closure.
All three forms reuse one workspace without reallocating it per evaluation.

With iteration limit $n$, the closure and `Parallel` fit within $n$ coordinate iterations and yield `Completed`.
For `Contextual`, function-charged iterations share the same limit as coordinate difference iterations and exceed it partway through.
For $n \ge 2$, function-internal charging is rejected first; `ConvergenceFailure` returned by `require()` is wrapped in `DifferentiationFailure` and returned to the caller.
For $n = 1$, the base-point evaluation uses the one available iteration; difference-side charging is rejected, producing an `Ok` report with termination `IterationLimit` and no published output.
Neither case overwrites the output array.
For nested solves inside a function, pass the context received by `Contextual` to that solve so its evaluations also count against difference-evaluation limits.

## Reading results, errors, and diagnostics

Only `output_available()` determines whether output may be used.
Fixed-step, node, and complex-step evaluations write output when termination is `Completed`.
Adaptive differences and coloring write when all entries have estimates and no evaluation or iteration limit, cancellation, or deadline intervened, so values are published on `Converged` as well as `RoundoffLimit`, `RefinementLimit`, and `StepSizeLimit`.
`Completed` indicates only completed formula evaluation, without an accuracy claim.
Only adaptive differences and coloring return error estimates, and these are not upper bounds.
See [Report and publication rules](oxref:differentiate-report-rules) for the meaning of each report value.
`require_success()` maps unsuccessful termination to `ConvergenceFailure` or `ExecutionStopped` errors, which `into_values()` and one-shot functions return.
Read the best estimate from early-stopped adaptive differences with `values()` or `into_parts()`.

Invalid inputs, function errors, and insufficient workspace return errors; read their kind with `e.kind()` and details with `e.view()`.
Failure to place nodes is an error (`InvalidInput`) for fixed-step coordinate and node differences; for fixed-step directional derivatives it gives `DifferentiationFailure` with cause `ConvergenceFailure` (`StepSizeLimit`); for adaptive differences and coloring it gives termination `StepSizeLimit`.
Function errors and nonfinite function values are wrapped in `DifferentiationFailure` with sample location and evaluation count; the original error is available through `source()`.
On errors or unpublished results, borrowed output arrays remain unchanged ([Shared contracts and structure of numerical-differentiation algorithms](oxref:differentiate-input-checks)).

## Summary

Use one-shot functions when only default values are needed; construct method values or Plans to change settings, and reuse requirements-based workspaces through borrowed forms inside iterations.
Pass functions as closures, `Contextual`, or `Parallel`; deterministic functions give the same results and evaluation counts in each form.
To charge function-internal iterations or nested solves, receive context through `Contextual` and control that work with difference-evaluation limits.
Check publication with `output_available()` and assess reliability through `termination()` and error estimates.
Look up item contracts, error kinds, and workspaces in the three purpose-grouped tables.
