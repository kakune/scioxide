Linear time-invariant (LTI) system responses, echo synthesis, and delay detection all rely on the Fourier convolution theorem.
`scioxide-fft` does not provide convolution or correlation functions.
These are provided by `convolve`, `convolve_circular`, and `correlate` in `scioxide-signal`, which select whichever of direct summation and FFT requires fewer operations.
This page constructs the same operations from `rfft`, `irfft`, `fft`, `ifft`, and `next_fast_len` in `scioxide-fft`, deriving the required zero-padding length and lag order.
Each cell compares against direct summation or the result from `scioxide-signal`.
[Analytic signals and the discrete Hilbert transform](../analytic-signal/) covers analytic signals, which also assume periodicity.

## Linear and circular convolution

Define the linear convolution of input $x_n$ (length $N_x$) and impulse response $h_n$ (length $N_h$), taking values outside their ranges as 0, by

$$
y_n = \sum_{m} x_m\, h_{n-m}, \qquad n = 0, \dots, N_x + N_h - 2
$$

as above.
The output length is $N_y = N_x + N_h - 1$, and direct summation costs $O(N_x N_h)$.

For the length-$L$ DFT $\mathcal{F}_L$, the elementwise spectral product corresponds to circular convolution with period $L$.

$$
\mathcal{F}_L^{-1}\left\{\mathcal{F}_L\{x\}\cdot\mathcal{F}_L\{h\}\right\}_n = \sum_{m=0}^{L-1} x_m\, h_{(n-m) \bmod L}
$$

Here $x$ and $h$ are sequences of length $L$, padded with 0 as needed.
Because the DFT treats the sequence as repeating with period $L$, output beyond index $L$ wraps to the beginning modulo $L$ and is added there.
This is called circular wraparound (circular aliasing).

### Zero-padding length

Wraparound is absent when the entire linear-convolution output fits in one period, that is, when

$$
L \ge N_x + N_h - 1
$$

the condition above holds.
Transforms in `scioxide-fft` use the supplied array length without implicit zero-padding, so the caller supplies the padding.
Choosing `next_fast_len(N_x + N_h - 1)` (the smallest product of 2, 3, 5, and 7 at least as large) for $L$ allows computation entirely with mixed-radix FFTs, avoiding Rader's or Bluestein's methods for prime lengths.

For real sequences, `rfft` returns $\lfloor L/2\rfloor + 1$ bins.
Pair the elementwise product with logical length $L$ using `HermitianSpectrum::from_vec(L, …)` and pass it to `irfft` to recover a real sequence of length $L$.
Using `Normalization::Inverse` for both transforms applies the round-trip factor $1/L$ exactly once, on the inverse side.

FFT convolution costs $O(L \log L)$, equivalent to 3 real FFTs of length $L$.
FFT rounding-error analysis gives a componentwise absolute-error bound of $\varepsilon \log_2 L\,\lVert x\rVert_2\lVert h\rVert_2$ up to a constant factor ($\varepsilon=2^{-52}$ is machine epsilon).
This bound applies to every component independently of its magnitude, so small output values, such as peak tails, can have larger relative errors than with direct summation.
`convolve` in `scioxide-signal` selects the method by comparing operation counts for direct summation and FFT.

The following cell uses this procedure to convolve a Gaussian pulse (64 samples, center 24, width 4 samples) with the response $h = \delta_0 + 0.55\,\delta_d$, consisting of a direct wave and an echo delayed by $d$.
Inputs are the echo delay $d$ [samples] and whether to zero-pad.
Without zero-padding, the transform keeps $L = 64$, and output beyond 64 samples wraps to the beginning.
Outputs are a response plot and a table of maximum differences from the $O(N_x N_h)$ direct sum (an independent check).

```rust
//| id: fft-convolution-delay
//| ref: fft-convolution-delay
//| title: "Compare FFT convolution with direct summation with and without zero-padding"
//| run: reactive
//| crates: [scioxide-core, scioxide-fft]
//| inputs:
//|   echo_delay: {"type":"range","label":"Echo delay d [samples]","description":"Change the number of samples between the direct wave and the echo.","min":4,"max":40,"step":1,"value":18}
//|   linear_padding: {"type":"checkbox","label":"Zero-pad to the linear-convolution length","description":"Unchecking keeps the input length at 64, giving circular convolution.","value":true}
//| cases:
//|   - {"id":"circular-short","label":"No zero-padding, d = 18","description":"Only the echo tail exceeds 64 samples, so the wraparound difference is small.","inputs":{"linear_padding":false}}
//|   - {"id":"circular-late","label":"No zero-padding, d = 40","description":"The echo center falls at sample 64, adding half its tail to the beginning.","inputs":{"echo_delay":40,"linear_padding":false}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":82}
//|       - {"artifact":"summary","path":"/rows/0/1","equals":84}
//|       - {"artifact":"summary","path":"/rows/0/3","range":{"max":1e-14}}
//|   - case: circular-short
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/1","equals":64}
//|       - {"artifact":"summary","path":"/rows/0/3","approx":{"value":1.5e-7,"rtol":0.1}}
//|   - case: circular-late
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/1","equals":64}
//|       - {"artifact":"summary","path":"/rows/0/3","approx":{"value":0.55,"rtol":0.01}}
use scioxide_core::Complex;
use scioxide_fft::{HermitianSpectrum, Normalization, irfft, next_fast_len, rfft};

// Gaussian pulse x (f64 exp is used only to generate input) and response h = δ0 + 0.55 δd
let delay = echo_delay.round() as usize;
let input: Vec<f64> = (0..64)
    .map(|i| {
        let z = (i as f64 - 24.0) / 4.0;
        (-0.5 * z * z).exp()
    })
    .collect();
let mut kernel = vec![0.0_f64; delay + 1];
kernel[0] = 1.0;
kernel[delay] = 0.55;
let needed = input.len() + kernel.len() - 1;

// Transform length L: next_fast_len(Nx + Nh − 1) for linear convolution, otherwise the original input length
let length = if linear_padding {
    next_fast_len(needed).map_err(|e| e.to_string())?
} else {
    input.len()
};
let padded = |values: &[f64]| {
    let mut v = vec![0.0; length];
    v[..values.len()].copy_from_slice(values);
    v
};
let x_bins = rfft(&padded(&input), Normalization::Inverse).map_err(|e| e.to_string())?;
let h_bins = rfft(&padded(&kernel), Normalization::Inverse).map_err(|e| e.to_string())?;
// Make the elementwise product a packed spectrum of logical length L and inverse-transform it (the inverse applies 1/L)
let product: Vec<Complex<f64>> = x_bins
    .bins()
    .iter()
    .zip(h_bins.bins())
    .map(|(a, b)| *a * *b)
    .collect();
let spectrum = HermitianSpectrum::from_vec(length, product).map_err(|e| e.to_string())?;
let output = irfft(&spectrum, Normalization::Inverse).map_err(|e| e.to_string())?;

// Independent check: O(Nx Nh) direct summation of linear convolution
let direct: Vec<f64> = (0..needed)
    .map(|n| {
        (0..kernel.len())
            .filter(|&m| m <= n && n - m < input.len())
            .map(|m| kernel[m] * input[n - m])
            .sum()
    })
    .collect();
let compared = needed.min(length);
let difference = (0..compared)
    .map(|n| (output[n] - direct[n]).abs())
    .fold(0.0_f64, f64::max);

let fft_curve: Vec<[f64; 2]> = output
    .iter()
    .take(needed)
    .enumerate()
    .map(|(n, &v)| [n as f64, v])
    .collect();
let direct_curve: Vec<[f64; 2]> = direct
    .iter()
    .enumerate()
    .map(|(n, &v)| [n as f64, v])
    .collect();
// Fix the horizontal axis to the longest output (64 + 40 samples), preserving the scale as delay changes
emit_line_chart!(
    &vec![
        serde_json::json!({ "name": "FFT convolution", "points": fft_curve }),
        serde_json::json!({
            "name": "Direct sum (linear convolution)",
            "points": direct_curve,
            "style": { "lineType": "dashed" }
        }),
    ],
    options = &serde_json::json!({
        "xLabel": "Time [samples]",
        "yLabel": "Response amplitude [-]",
        "xMin": 0.0,
        "xMax": 103.0,
        "annotations": [
            { "kind": "line", "axis": "x", "value": delay as f64 + 24.0, "label": "Echo center" }
        ]
    })
);
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "Linear-convolution length Nx+Nh−1", "type": "integer" },
    { "key": "1", "label": "Transform length L", "type": "integer" },
    { "key": "2", "label": "Samples compared", "type": "integer" },
    { "key": "3", "label": "Maximum difference from direct sum [-]", "type": "number", "format": sci2 }
]);
emit_table_with_columns!(
    columns,
    vec![(needed, length, compared, difference)],
    metadata = serde_json::json!({ "id": "summary" })
);
```

At the default delay of 18 samples, `next_fast_len` selects $L = 84 = 2^2\cdot 3\cdot 7$ for the required length 82; the maximum difference from direct summation is $4.4\times10^{-16}$.
For this input, $\lVert x\rVert_2\approx2.66$ and $\lVert h\rVert_2\approx1.14$, and the difference is one order of magnitude below the indicative bound $\varepsilon\log_2L\,\lVert x\rVert_2\lVert h\rVert_2\approx4.3\times10^{-15}$.
Disabling zero-padding gives $L = 64$.
At delay 18, only a small part of the echo pulse's tail (centered at sample 42) exceeds 64 samples, limiting the maximum difference to $1.5\times10^{-7}$.
At delay 40, the echo center falls at sample 64 and half the tail is added to the beginning, giving a maximum difference of 0.55.
The wraparound magnitude is determined by the output beyond 64 samples and is on a different scale from rounding error.

## Cross-correlation and lag order

For sequence $a$ of length $N$ and sequence $b$ of length $M$, define cross-correlation using the same convention as `scioxide_signal::correlate` by

$$
r[\ell] = \sum_{k} a[k]\, \overline{b[k - \ell]}, \qquad \ell = -(M-1), \dots, N-1
$$

as above.
The sum ranges over $0 \le k < N$ and $0 \le k - \ell < M$, with values outside the ranges taken as 0.
Conjugation has no effect for real sequences.
`correlate` returns these $N + M - 1$ values in increasing lag order, so array index $j$ corresponds to lag $\ell = j - (M-1)$; lag 0 is at index $M-1$.
If $r[\ell]$ is maximal at $\ell = d > 0$, a waveform resembling $b$ appears $d$ samples later in $a$.

This definition can be written as $r = a * \tilde b$ ($\tilde b[m] = \overline{b[-m]}$ is the conjugate time reversal of $b$).
Time reversal and conjugation correspond to complex conjugation in the Fourier domain, so for a DFT of length $L$,

$$
\mathcal{F}_L\{r\}_k = A_k\, \overline{B_k}
$$

the relation above holds.
For autocorrelation $a = b$, the right side is the power spectrum $\lvert A_k\rvert^2$; this is the discrete Wiener–Khinchin theorem.

The condition preventing wraparound is the same as for linear convolution: $L \ge N + M - 1$.
In the inverse-transformed sequence $c$ of length $L$, lag $\ell \ge 0$ is at index $\ell$, and negative lag $\ell$ is at the end index $L + \ell$.
To obtain the order used by `correlate`, extract $c[\ell \bmod L]$ for each lag $\ell = -(M-1), \dots, N-1$.
`fftshift` merely swaps the first and second halves of a sequence of length $L$, so it starts at lag $-\lfloor L/2\rfloor$, leaving zero-padding zeros before the negative lags or after the positive lags.
Extracting lags from their definition gives the same ordering as `correlate` regardless of $N$, $M$, and $L$.
[Correlation lag order](oxref:signal-correlation-lags) in the signal chapter covers conversion between lags and time differences and normalization to correlation coefficients.

The following cell places a complex linear chirp $b[m] = e^{i\pi m^2/(2M)}$ of length $M = 16$ at position $d$ in a received sequence $a$ of length $N = 64$, then adds an echo of amplitude 0.5 at position $d + 20$.
This is the same arrangement as a radar matched filter; the correlation maximum appears at lag $d$.
The main computation is the spectral product $A_k\overline{B_k}$ using `fft`; `scioxide_signal::correlate` and direct summation of the definition serve as independent reference computations.
Unchecking the box inverse-transforms $A_k B_k$ without conjugation, showing the discrepancy caused by computing convolution instead of correlation.

```rust
//| id: fft-correlation-lag-order
//| ref: fft-correlation-lag-order
//| title: "Compare FFT cross-correlation with signal's correlate"
//| run: reactive
//| crates: [scioxide-core, scioxide-fft, scioxide-signal]
//| inputs:
//|   delay: {"type":"integer","label":"Chirp position d [samples]","description":"Starting position of the length-16 chirp in received sequence a.","min":0,"max":40,"value":12}
//|   conjugate: {"type":"checkbox","label":"Conjugate B","description":"Unchecking inverse-transforms A·B, giving convolution instead of correlation.","value":true}
//| cases:
//|   - {"id":"zero-lag","label":"d = 0","description":"The maximum occurs at lag 0, that is, index M − 1 = 15.","inputs":{"delay":0}}
//|   - {"id":"no-conjugate","label":"No conjugation","description":"A·B disagrees with correlation, and the sharp maximum at lag d disappears.","inputs":{"conjugate":false}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"lags","path":"/rows/0/0","equals":80}
//|       - {"artifact":"lags","path":"/rows/0/1","equals":12}
//|       - {"artifact":"lags","path":"/rows/0/2","equals":12}
//|       - {"artifact":"lags","path":"/rows/0/3","range":{"max":1e-13}}
//|       - {"artifact":"lags","path":"/rows/0/4","range":{"max":1e-13}}
//|   - case: zero-lag
//|     expect:
//|       - {"artifact":"lags","path":"/rows/0/1","equals":0}
//|       - {"artifact":"lags","path":"/rows/0/2","equals":0}
//|       - {"artifact":"lags","path":"/rows/0/3","range":{"max":1e-13}}
//|   - case: no-conjugate
//|     expect:
//|       - {"artifact":"lags","path":"/rows/0/2","equals":12}
//|       - {"artifact":"lags","path":"/rows/0/3","range":{"min":1}}
use scioxide_core::Complex;
use scioxide_fft::{Normalization, fft, ifft, next_fast_len};

// Linear chirp b[m] = exp(iπ m²/(2M)) (f64 sin/cos are used only to generate input)
let (n, m) = (64_usize, 16_usize);
let delay = delay as usize;
let b: Vec<Complex<f64>> = (0..m)
    .map(|k| Complex::from_polar(1.0, std::f64::consts::PI * (k * k) as f64 / (2 * m) as f64))
    .collect();
// Received sequence a: chirp at position d and an amplitude-0.5 echo at d + 20 (truncated outside the range)
let mut a = vec![Complex::new(0.0, 0.0); n];
for (shift, gain) in [(delay, 1.0), (delay + 20, 0.5)] {
    for (k, &value) in b.iter().enumerate() {
        if shift + k < n {
            a[shift + k] += value * gain;
        }
    }
}

// Zero-pad to L ≥ N + M − 1 and inverse-transform A_k conj(B_k)
let length = next_fast_len(n + m - 1).map_err(|e| e.to_string())?;
let padded = |values: &[Complex<f64>]| {
    let mut v = vec![Complex::new(0.0, 0.0); length];
    v[..values.len()].copy_from_slice(values);
    v
};
let fa = fft(&padded(&a), Normalization::Inverse).map_err(|e| e.to_string())?;
let fb = fft(&padded(&b), Normalization::Inverse).map_err(|e| e.to_string())?;
let product: Vec<Complex<f64>> = fa
    .iter()
    .zip(&fb)
    .map(|(&x, &y)| if conjugate { x * y.conj() } else { x * y })
    .collect();
let circular = ifft(&product, Normalization::Inverse).map_err(|e| e.to_string())?;

// Reference computation: signal's correlate (in increasing lag order −(M−1), …, N−1)
let signal = scioxide_signal::correlate(&a, &b).map_err(|e| e.to_string())?;
let lags: Vec<i64> = (-(m as i64 - 1)..n as i64).collect();
// Lag ℓ is at circular-sequence index ℓ mod L
let from_fft: Vec<Complex<f64>> = lags
    .iter()
    .map(|&lag| circular[lag.rem_euclid(length as i64) as usize])
    .collect();
// Independent check: direct sum of the definition r[ℓ] = Σ_k a[k] conj(b[k − ℓ])
let direct: Vec<Complex<f64>> = lags
    .iter()
    .map(|&lag| {
        (0..n as i64)
            .filter(|&k| (0..m as i64).contains(&(k - lag)))
            .map(|k| a[k as usize] * b[(k - lag) as usize].conj())
            .sum()
    })
    .collect();
let max_diff = |x: &[Complex<f64>], y: &[Complex<f64>]| {
    x.iter()
        .zip(y)
        .map(|(p, q)| (*p - *q).norm())
        .fold(0.0_f64, f64::max)
};
let argmax = |values: &[Complex<f64>]| {
    let best = (0..values.len())
        .max_by(|&i, &j| values[i].norm().total_cmp(&values[j].norm()))
        .unwrap_or(0);
    lags[best]
};

let curve = |values: &[Complex<f64>]| -> Vec<[f64; 2]> {
    lags.iter()
        .zip(values)
        .map(|(&lag, value)| [lag as f64, value.norm()])
        .collect()
};
emit_line_chart!(
    &vec![
        serde_json::json!({ "name": "FFT spectral product", "points": curve(&from_fft) }),
        serde_json::json!({
            "name": "scioxide_signal::correlate",
            "points": curve(&signal),
            "style": { "lineType": "dashed" }
        }),
    ],
    options = &serde_json::json!({
        "xLabel": "Lag ℓ [samples]",
        "yLabel": "Correlation magnitude |r[ℓ]| [-]",
        "xMin": -15.0,
        "xMax": 63.0,
        "yMin": 0.0,
        "yMax": 17.0
    })
);
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "Transform length L", "type": "integer" },
    { "key": "1", "label": "Lag at maximum (FFT) [samples]", "type": "integer" },
    { "key": "2", "label": "Lag at maximum (signal) [samples]", "type": "integer" },
    { "key": "3", "label": "Maximum difference from signal [-]", "type": "number", "format": sci2 },
    { "key": "4", "label": "Maximum difference from direct sum [-]", "type": "number", "format": sci2 }
]);
let row = (
    length,
    argmax(&from_fft),
    argmax(&signal),
    max_diff(&from_fft, &signal),
    max_diff(&from_fft, &direct),
);
emit_table_with_columns!(
    columns,
    vec![row],
    metadata = serde_json::json!({ "id": "lags" })
);
```

At the default $d = 12$, $N + M - 1 = 79$ gives $L = 80$; correlation from the FFT spectral product agrees with `correlate` to $2.2\times10^{-15}$ and with direct summation to $1.9\times10^{-15}$.
The maximum appears at lag 12 and the second peak from the echo at lag 32.
At $d = 0$, the maximum occurs at lag 0, that is, index 15 in the `correlate` result.
Without conjugation, the FFT computes the convolution of $a$ and $b$, giving a difference of 15 from `correlate` and shifting the maximum to lag 38.
Because conjugation changes the result for complex sequences, check its position against the definition when applying conventions tested on real sequences to complex sequences.

## Summary

To compute linear convolution with the FFT, extend both sequences with zeros to $L \ge N_x + N_h - 1$ before transforming, choosing $L$ with `next_fast_len`.
Insufficient zero-padding gives circular convolution with the output tail wrapped to the beginning; its discrepancy is the wrapped output magnitude rather than rounding error.
Extracting index $\ell \bmod L$ for each lag $\ell = -(M-1), \dots, N-1$ from the inverse transform of $A_k\overline{B_k}$ gives cross-correlation with the same ordering and conjugation convention as `scioxide_signal::correlate`.
Use functions and plans in `scioxide-signal` for repeated operations or automatic selection between direct summation and FFT.
