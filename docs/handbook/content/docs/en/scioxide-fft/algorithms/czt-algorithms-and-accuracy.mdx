The CZT defined in [Chirp Z-transform and zoom FFT](../chirp-z-and-zoom-fft/),

$$
X_k = s\sum_{j=0}^{N-1}x_jA^{-j}W^{jk},\qquad z_k=AW^{-k}=\exp\bigl(\rho_0+k\rho+2\pi i(t_0+kt)\bigr)
$$

is computed by `CztPlan` using one of 2 algorithms.
One uses Bluestein's identity to turn the sum into a convolution and computes it by FFT in $O(L\log L)$ operations.
The other is direct summation with cost $O(NM)$.
This page derives the identity and explains why spiral contours amplify convolution rounding error, how preparation selects an algorithm, and the error bound for Bluestein's method.

## Bluestein's identity

Using $2jk = j^2 + k^2 - (k-j)^2$ and the same complex-logarithm branch for the half-integer powers $W^{j^2/2}$ gives

$$
X_k = s\,W^{k^2/2}\sum_{j=0}^{N-1}\left(x_jA^{-j}W^{j^2/2}\right)W^{-(k-j)^2/2}
$$

the identity above (Rabiner, Schafer & Rader 1969; Bluestein 1970).
The sum on the right is the linear convolution of the bracketed sequence of length $N$ with the chirp kernel $W^{-m^2/2}$ ($m=-(N-1),\ldots,M-1$).
Computing it by FFT as a circular convolution of length $L$ = `next_fast_len(N + M − 1)` avoids wraparound for the same reason as in [Zero-padding length](oxref:fft-zero-padding).
`next_fast_len` returns a length with only prime factors 2, 3, 5, and 7, so the FFT can use a mixed-radix algorithm.
The plan stores the kernel transform during preparation, so each evaluation requires 2 FFTs of length $L$ and $O(N+M)$ phase multiplications.
[Bluestein's algorithm](oxref:fft-bluestein) describes applying the same identity on a DFT contour for prime-length FFTs.

On the unit circle, $\lvert W^{j^2/2}\rvert=1$ and the chirp changes only the phase.
On a spiral ($\rho\ne0$), $\lvert W^{j^2/2}\rvert = e^{-\rho j^2/2}$ and $\lvert W^{-(k-j)^2/2}\rvert=e^{\rho(k-j)^2/2}$ grow or decay with the square of the index.
Intermediate convolution terms can be much larger than the final terms $x_jz_k^{-j}$, causing cancellation in summation and amplifying FFT rounding error.
In the bound below, the factor $e^{2\chi}$ expresses this amplification ($\chi$ is defined in the next section).
The starting-radius factor $e^{-j\rho_0}$, by contrast, is merely an input weight applied with a separate binary exponent and does not increase cancellation in the convolution.

## Algorithm selection

`CztPlan::algorithm()` returns the algorithm selected during preparation as `CztAlgorithm::Bluestein` or `CztAlgorithm::ScaledDirect` (direct summation with an extended exponent range).
Writing the spiral spread as $\chi = \lvert\rho\rvert\max(N,M)^2$, selection follows the order below.

| Contour and size | Selected algorithm |
|---|---|
| On the unit circle ($\rho_0=\rho=0$) | `Bluestein` |
| Off the unit circle with $NM\le4096$ | `ScaledDirect` |
| Off the unit circle with $NM>4096$, $\chi\le0.5$ | `Bluestein` |
| Off the unit circle with $NM>4096$, $\chi>0.5$ | `ScaledDirect` |

An arc of radius other than 1 ($\rho_0\ne0$, $\rho=0$) has $\chi=0$, so $NM>4096$ selects Bluestein's method.
Small problems off the unit circle use direct summation for its smaller componentwise error.

`ScaledDirect` costs $O(NM)$ per evaluation and stores coefficients during preparation when $NM\le4096$.
Each output is summed with compensated summation at working precision when the error assessment permits, and otherwise with extended-exponent arithmetic.
The summation order is fixed and independent of the thread count.
Cancellation requests and deadlines are checked at least every 256 terms.
Direct summation does not use FFTs, so `resolved_backends()` is empty.

## Error bound

With the built-in FFT, the error bound for Bluestein's method is, for each output component,

$$
\lvert X_k-\hat X_k\rvert \le \lvert s\rvert\, e^{2\chi}\bigl(128\,\varepsilon\, h\, B + 32\,\varepsilon_{64}(D+\chi B)\bigr) + U
$$

as above.
$\hat X_k$ is the computed value, $\varepsilon$ is the scalar type's machine epsilon, $\varepsilon_{64}$ is the machine epsilon of `f64`, and $h=\max(1,\log_2L)$.
$B=\sum_j(\lvert\operatorname{Re}x_j\rvert+\lvert\operatorname{Im}x_j\rvert)e^{-j\rho_0}$ represents the input magnitude weighted by the starting radius.
$D=\sum_j(\lvert\operatorname{Re}x_j\rvert+\lvert\operatorname{Im}x_j\rvert)e^{-j\rho_0}(1+\lvert j\rho_0\rvert)$ is the sum of the terms of $B$ multiplied by $1+\lvert j\rho_0\rvert$ and enters the error term for phase and radius factors computed in `f64`.
$U$ is the gradual-underflow contribution, negligible for inputs of ordinary magnitude.

The bound is on absolute error, so output values much smaller than $B$ may have large relative errors.
The restriction $\chi\le0.5$ keeps spiral amplification $e^{2\chi}$ at most $e\approx2.7$.
For `f64` and $L=480$, the leading term is $128\,\varepsilon\,h\,B\approx2.5\times10^{-13}B$.
With an injected FFT implementation, its own accuracy contributes separately.

The following cell varies contours and sizes to check selection rules and errors.
With fixed input $x_j=\cos(0.3j)+0.5\sin(0.71j)$, transform on 6 contours and list `algorithm()`, $\chi$, and the maximum difference from direct summation in `f64`, normalized by $B_k=\sum_j\lvert x_j\rvert\,\lvert z_k\rvert^{-j}$.
The direct sum is an independent reference computation constructing $z_k^{-j}=e^{-j(\rho_0+k\rho)}e^{-2\pi ij(t_0+kt)}$ with the intrinsic methods of `f64`; it too has rounding error of order $10^{-15}$.

```rust
//| id: fft-czt-algorithm-choice
//| ref: fft-czt-algorithm-choice
//| title: "Algorithm selection and error by contour and size"
//| run: reactive
//| crates: [scioxide-core, scioxide-fft]
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"choice","path":"/rows/0/5","equals":"Bluestein"}
//|       - {"artifact":"choice","path":"/rows/1/5","equals":"Bluestein"}
//|       - {"artifact":"choice","path":"/rows/2/5","equals":"ScaledDirect"}
//|       - {"artifact":"choice","path":"/rows/3/5","equals":"Bluestein"}
//|       - {"artifact":"choice","path":"/rows/4/5","equals":"ScaledDirect"}
//|       - {"artifact":"choice","path":"/rows/5/5","equals":"ScaledDirect"}
//|       - {"artifact":"choice","path":"/rows/3/3","approx":{"value":0.459,"atol":0.001}}
//|       - {"artifact":"choice","path":"/rows/0/6","range":{"max":1e-13}}
//|       - {"artifact":"choice","path":"/rows/3/6","range":{"max":1e-13}}
//|       - {"artifact":"choice","path":"/rows/5/6","range":{"max":1e-13}}
use scioxide_core::{Complex, ExecutionContext};
use scioxide_fft::{CztContour, CztPlan, CztPlanSpec, Normalization};

// (Contour description, N, M, ρ0, ρ): use starting phase 0.125 turns and increment 1/(4M) turns throughout
let cases = [
    ("Unit circle", 256_usize, 201_usize, 0.0_f64, 0.0_f64),
    ("Arc of radius 0.97", 256, 201, 0.97_f64.ln(), 0.0),
    ("Arc of radius 0.97 (small)", 32, 64, 0.97_f64.ln(), 0.0),
    ("Spiral ρ = 7e−6", 256, 201, 0.0, 7e-6),
    ("Spiral ρ = 1e−5", 256, 201, 0.0, 1e-5),
    ("Spiral ρ = 1e−4", 256, 201, 0.0, 1e-4),
];
let tau = 2.0 * std::f64::consts::PI;
let mut rows = Vec::new();
for (label, n, m, rho0, rho) in cases {
    // Use f64 intrinsic methods for input generation and reference direct summation
    let x: Vec<f64> = (0..n)
        .map(|j| (0.3 * j as f64).cos() + 0.5 * (0.71 * j as f64).sin())
        .collect();
    let (t0, t) = (0.125_f64, 0.25 / m as f64);
    let contour = CztContour::new(rho0, rho, t0, t).map_err(|e| e.to_string())?;
    let plan = CztPlan::new(CztPlanSpec::new(n, m, contour, Normalization::Unscaled))
        .map_err(|e| e.to_string())?;
    let mut workspace = plan.workspace(()).map_err(|e| e.to_string())?;
    let mut output = vec![Complex::new(0.0, 0.0); m];
    plan.execute_into(
        &x[..],
        &mut output[..],
        &mut workspace,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;
    let mut worst = 0.0_f64;
    for (k, value) in output.iter().enumerate() {
        let (log_r, turns) = (rho0 + k as f64 * rho, t0 + k as f64 * t);
        let mut sum = Complex::new(0.0, 0.0);
        let mut mass = 0.0;
        for (j, &v) in x.iter().enumerate() {
            let weight = (-(j as f64) * log_r).exp();
            sum += Complex::from_polar(v * weight, -tau * j as f64 * turns);
            mass += v.abs() * weight;
        }
        worst = worst.max((*value - sum).norm() / mass);
    }
    let chi = rho.abs() * (n.max(m) as f64).powi(2);
    rows.push((
        label,
        n,
        m,
        chi,
        n * m,
        format!("{:?}", plan.algorithm()),
        worst,
    ));
}
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let sig3 = serde_json::json!({ "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "Contour" },
    { "key": "1", "label": "N", "type": "integer" },
    { "key": "2", "label": "M", "type": "integer" },
    { "key": "3", "label": "χ = |ρ| max(N, M)² [-]", "type": "number", "format": sig3 },
    { "key": "4", "label": "NM", "type": "integer" },
    { "key": "5", "label": "Algorithm" },
    { "key": "6", "label": "Maximum difference from direct sum / B_k [-]", "type": "number", "format": sci2 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "choice" })
);
```

The selections in the output table agree with the rule table.
The radius-0.97 arc uses Bluestein's method for $NM=51456$ and direct summation for $NM=2048$.
The spiral uses Bluestein's method at $\chi=0.459$ and direct summation at $\chi=0.655$ and $6.55$.
The maximum difference in every row is between $1.3\times10^{-15}$ and $1.1\times10^{-14}$, indistinguishable from the reference direct sum's own rounding error.
It is more than one order of magnitude below the leading bound term $2.5\times10^{-13}$ for $L=480$.
These magnitudes apply to the chosen input and contours; assess accuracy for general contours with the bound above.

## Summary

The CZT uses Bluestein's method (2 FFTs of length `next_fast_len(N + M − 1)`) for unit-circle contours and large problems with $\chi=\lvert\rho\rvert\max(N,M)^2\le0.5$.
Off the unit circle, it uses direct summation when either $NM\le4096$ or $\chi>0.5$; read the selected algorithm with `algorithm()`.
Bluestein's error bound is an absolute error proportional to $B$; spiral amplification is limited to $e^{2\chi}\le e$, and the starting radius does not contribute to the amplification.
Output components much smaller than $B$ can have large relative errors, so compare the bound with the output magnitude when using such components.
