Applying a DFT to finite-interval data extends the data periodically, introducing a jump at the join if the endpoint values differ.
A jump produces high-frequency components and slows coefficient decay.
The discrete cosine transform (DCT) and discrete sine transform (DST) correspond to Fourier-transforming data extended at the endpoints by reflection (even symmetry) or sign reversal (odd symmetry); the extension determines the endpoint treatment.
This page explains the relation between extensions and boundary conditions, the defining sums and scales of the 4 types computed by `scioxide-fft`, and their algorithms and APIs.
[Diagonalizing the discrete Laplacian](../laplacian-diagonalization/) derives and checks that each type's kernels are eigenvectors of the second difference closed by those boundary conditions.

## Symmetric extensions and boundary conditions

Extending a function on $[0,L]$ evenly as $x(-t)=x(t)$ eliminates the sine terms in its Fourier series, leaving only a sum of $\cos(k\pi t/L)$.
Cosines have zero derivative at the endpoints, so this expansion fits Neumann conditions (zero normal derivative at the boundary).
Extending oddly as $x(-t)=-x(t)$ eliminates cosine terms, leaving only $\sin(k\pi t/L)$; sines vanish at the endpoints and thus fit Dirichlet conditions (zero boundary value).
An even extension removes value jumps, but whether derivatives also join smoothly depends on the original function.

In the discrete case, the symmetry center may lie on a sample (grid point) or halfway between adjacent samples (half-grid point).
The choices of even or odd symmetry and symmetry-center position at the left and right endpoints give DCT and DST types I–IV.
The following table lists each type's symmetry when its kernel $c_k[j]$ is viewed as a function of sample index $j=0,\ldots,n-1$.
“Grid point $-1$” is one grid point outside the first sample; “half-grid point $-\tfrac12$” is halfway to that outside point.

| Type | Kernel $c_k[j]$ | Left symmetry and boundary condition | Right symmetry and boundary condition |
|---|---|---|---|
| DCT-I | $\cos\frac{\pi jk}{n-1}$ | Even at grid point 0 (Neumann) | Even at grid point $n-1$ (Neumann) |
| DCT-II | $\cos\frac{\pi(j+\frac12)k}{n}$ | Even at half-grid point $-\tfrac12$ (Neumann) | Even at half-grid point $n-\tfrac12$ (Neumann) |
| DCT-III | $\cos\frac{\pi j(k+\frac12)}{n}$ | Even at grid point 0 (Neumann) | Odd at grid point $n$ (Dirichlet) |
| DCT-IV | $\cos\frac{\pi(j+\frac12)(k+\frac12)}{n}$ | Even at half-grid point $-\tfrac12$ (Neumann) | Odd at half-grid point $n-\tfrac12$ (Dirichlet) |
| DST-I | $\sin\frac{\pi(j+1)(k+1)}{n+1}$ | Odd at grid point $-1$ (Dirichlet) | Odd at grid point $n$ (Dirichlet) |
| DST-II | $\sin\frac{\pi(j+\frac12)(k+1)}{n}$ | Odd at half-grid point $-\tfrac12$ (Dirichlet) | Odd at half-grid point $n-\tfrac12$ (Dirichlet) |
| DST-III | $\sin\frac{\pi(j+1)(k+\frac12)}{n}$ | Odd at grid point $-1$ (Dirichlet) | Even at grid point $n-1$ (Neumann) |
| DST-IV | $\sin\frac{\pi(j+\frac12)(k+\frac12)}{n}$ | Odd at half-grid point $-\tfrac12$ (Dirichlet) | Even at half-grid point $n-\tfrac12$ (Neumann) |

For each $k$, the vector $(c_k[j])_j$ formed by varying $j$ is an eigenvector of the second difference $u_{j-1}-2u_j+u_{j+1}$ closed by the table's boundary conditions (G. Strang, "The discrete cosine transform", *SIAM Review* 41(1), 1999).
For example, the DST-I kernel vanishes at the grid points just outside both endpoints and is an eigenvector of the difference matrix with grid-point Dirichlet conditions.
The DCT-II kernel is reflected about half-grid points and is an eigenvector of the difference matrix with zero-flux Neumann conditions on a cell-centered grid.
[Diagonalizing the discrete Laplacian](oxref:fft-laplacian-diagonalization) derives the outside values and eigenvalues for all 8 types and checks them numerically.

## Definitions and scales of the 4 types

Let $n$ be the length and $0\le k<n$ the output index.
With `Normalization::Unscaled`, `scioxide-fft` computes the following sums, including endpoint weights (an empty sum is 0).

| Type | DCT $y_k$ | DST $y_k$ |
|---|---|---|
| I | $x_0+(-1)^kx_{n-1}+2\sum_{j=1}^{n-2}x_j\cos\frac{\pi jk}{n-1}$ | $\sum_{j=0}^{n-1}x_j\sin\frac{\pi(j+1)(k+1)}{n+1}$ |
| II | $\sum_{j=0}^{n-1}x_j\cos\frac{\pi(j+\frac12)k}{n}$ | $\sum_{j=0}^{n-1}x_j\sin\frac{\pi(j+\frac12)(k+1)}{n}$ |
| III | $x_0+2\sum_{j=1}^{n-1}x_j\cos\frac{\pi j(k+\frac12)}{n}$ | $(-1)^kx_{n-1}+2\sum_{j=0}^{n-2}x_j\sin\frac{\pi(j+1)(k+\frac12)}{n}$ |
| IV | $\sum_{j=0}^{n-1}x_j\cos\frac{\pi(j+\frac12)(k+\frac12)}{n}$ | $\sum_{j=0}^{n-1}x_j\sin\frac{\pi(j+\frac12)(k+\frac12)}{n}$ |

The inverse transform computes the dual type.
Types I and IV are self-dual; II and III are dual to each other.
Pass the type of the forward transform to invert to `idct`, `idst`, and inverse-direction plans.
For example, `idct(…, DctType::II, …)` computes DCT-III.

Applying an unscaled forward and inverse transform multiplies the input by the following round-trip factor $R$.

| Type | DCT $R$ | DST $R$ | Minimum length |
|---|---|---|---|
| I | $2(n-1)$ | $(n+1)/2$ | 2 for DCT-I, 1 for DST-I |
| II | $n$ | $n$ | 1 |
| III | $n$ | $n$ | 1 |
| IV | $n/2$ | $n/2$ | 1 |

`Normalization::Forward` divides the forward output by $R$, and `Normalization::Inverse` divides the inverse output by $R$.
Either returns the input on a round trip when the same normalization is used in both directions.
`Normalization::Orthonormal` makes the transform matrix orthogonal.
For the type actually computed (the dual type in an inverse plan), it weights the input endpoints, applies an overall factor, and divides the specified outputs by $\sqrt2$.

| Computed type | Input weights | Overall factor | Outputs divided by $\sqrt2$ |
|---|---|---|---|
| DCT-I | $\sqrt2$ at $x_0$, $x_{n-1}$ | $1/\sqrt{2(n-1)}$ | $y_0$, $y_{n-1}$ |
| DCT-II | None | $\sqrt{2/n}$ | $y_0$ |
| DCT-III | $\sqrt2$ at $x_0$ | $1/\sqrt{2n}$ | None |
| DCT-IV | None | $\sqrt{2/n}$ | None |
| DST-I | None | $\sqrt{2/(n+1)}$ | None |
| DST-II | None | $\sqrt{2/n}$ | $y_{n-1}$ |
| DST-III | $\sqrt2$ at $x_{n-1}$ | $1/\sqrt{2n}$ | None |
| DST-IV | None | $\sqrt{2/n}$ | None |

If the same endpoint appears twice in the table at $n=1$, adjust it only once.


### Checking definitions and scales

The following cell computes all 8 types with `RealTransformPlan` for the asymmetric input $x_j=1/(1+j)+0.5\,(j\bmod2)$ and compares them with the defining sums in the table.
The sums are independent reference values computed directly with `cos` and `sin` from `f64`.
It also measures the round-trip factor $R$ from successive unscaled forward and inverse plans, the difference between the round-trip result and $Rx$, and the deviation of $\lVert y\rVert/\lVert x\rVert$ from 1 under `Orthonormal`.
For types whose length is insufficient, the table shows the error classification returned by plan preparation.
The second table gives the relative difference between the convenience functions `idct` and `idst` applied to the same $y$ and the inverse-plan result.
It also applies `idct` and `idst` after `dct` and `dst` with `Normalization::Inverse`, calls the result $z$, and measures return to $x$ with $\max_j\lvert z_j-x_j\rvert/\max_j\lvert x_j\rvert$.

```rust
//| ref: fft-dct-dst-conventions
//| title: "Check defining sums, round-trip factors, and orthogonality for all 8 types"
//| run: reactive
//| crates: [scioxide-core, scioxide-fft]
//| inputs:
//|   length: {"type":"range","label":"Length n","description":"DCT-I accepts lengths of at least 2; other types accept at least 1.","min":1,"max":24,"step":1,"value":8}
//| cases:
//|   - {"id":"single","label":"n = 1","description":"The DCT-I plan returns InvalidInput; DCT-IV and DST-IV have R = 1/2.","inputs":{"length":1}}
//|   - {"id":"odd","label":"n = 7","description":"Odd length. Types II, III, and IV use a real FFT of length 7.","inputs":{"length":7}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"conventions","path":"/rows/0/1","equals":"Computation"}
//|       - {"artifact":"conventions","path":"/rows/0/2","range":{"max":1e-14}}
//|       - {"artifact":"conventions","path":"/rows/0/3","approx":{"value":14,"rtol":1e-12}}
//|       - {"artifact":"conventions","path":"/rows/1/3","approx":{"value":8,"rtol":1e-12}}
//|       - {"artifact":"conventions","path":"/rows/3/3","approx":{"value":4,"rtol":1e-12}}
//|       - {"artifact":"conventions","path":"/rows/4/3","approx":{"value":4.5,"rtol":1e-12}}
//|       - {"artifact":"conventions","path":"/rows/6/2","range":{"max":1e-14}}
//|       - {"artifact":"conventions","path":"/rows/6/5","range":{"max":1e-14}}
//|       - {"artifact":"conventions","path":"/rows/7/6","range":{"max":1e-14}}
//|       - {"artifact":"inverse-functions","path":"/rows/0/1","equals":"Computation"}
//|       - {"artifact":"inverse-functions","path":"/rows/1/2","range":{"max":1e-15}}
//|       - {"artifact":"inverse-functions","path":"/rows/1/3","range":{"max":1e-14}}
//|       - {"artifact":"inverse-functions","path":"/rows/6/2","range":{"max":1e-15}}
//|       - {"artifact":"inverse-functions","path":"/rows/6/3","range":{"max":1e-14}}
//|   - case: single
//|     expect:
//|       - {"artifact":"conventions","path":"/rows/0/1","equals":"InvalidInput"}
//|       - {"artifact":"conventions","path":"/rows/0/3","equals":null}
//|       - {"artifact":"conventions","path":"/rows/3/3","approx":{"value":0.5,"rtol":1e-12}}
//|       - {"artifact":"conventions","path":"/rows/4/3","approx":{"value":1,"rtol":1e-12}}
//|       - {"artifact":"inverse-functions","path":"/rows/0/1","equals":"InvalidInput"}
//|       - {"artifact":"inverse-functions","path":"/rows/0/3","equals":null}
//|       - {"artifact":"inverse-functions","path":"/rows/3/3","range":{"max":1e-14}}
//|   - case: odd
//|     expect:
//|       - {"artifact":"conventions","path":"/rows/1/2","range":{"max":1e-14}}
//|       - {"artifact":"conventions","path":"/rows/3/3","approx":{"value":3.5,"rtol":1e-12}}
//|       - {"artifact":"conventions","path":"/rows/5/5","range":{"max":1e-14}}
//|       - {"artifact":"inverse-functions","path":"/rows/2/2","range":{"max":1e-15}}
//|       - {"artifact":"inverse-functions","path":"/rows/7/3","range":{"max":1e-14}}
use scioxide_core::{ExecutionContext, SciOxideError};
use scioxide_fft::{DctType, DstType, FftDirection, Normalization, dct, dst, idct, idst};
use scioxide_fft::{RealTransformKind, RealTransformPlan, RealTransformPlanSpec};

let n = length.round() as usize;
let nf = n as f64;
let pi = std::f64::consts::PI;
let x: Vec<f64> = (0..n)
    .map(|j| 1.0 / (1.0 + j as f64) + 0.5 * (j % 2) as f64)
    .collect();
// Prepare a plan and execute it once. Pass the forward-transform type to an inverse plan.
let run = |kind: RealTransformKind,
           direction: FftDirection,
           normalization: Normalization,
           input: &[f64]|
 -> Result<Vec<f64>, SciOxideError> {
    let spec = RealTransformPlanSpec::new(input.len(), kind, direction, normalization);
    let plan = RealTransformPlan::<f64>::new(spec)?;
    let mut workspace = plan.workspace(())?;
    let mut output = vec![0.0; input.len()];
    plan.execute_into(
        input,
        &mut output,
        &mut workspace,
        ExecutionContext::sequential(),
    )?;
    Ok(output)
};
// Independent check: the table's defining sums (reference values using f64 cos and sin). Indices 0..3 are DCT, 4..7 DST.
let reference = |index: usize, k: usize| {
    let kf = k as f64;
    let kernel = |j: usize| {
        let jf = j as f64;
        match index {
            0 => (pi * jf * kf / (nf - 1.0)).cos(),
            1 => (pi * (jf + 0.5) * kf / nf).cos(),
            2 => (pi * jf * (kf + 0.5) / nf).cos(),
            3 => (pi * (jf + 0.5) * (kf + 0.5) / nf).cos(),
            4 => (pi * (jf + 1.0) * (kf + 1.0) / (nf + 1.0)).sin(),
            5 => (pi * (jf + 0.5) * (kf + 1.0) / nf).sin(),
            6 => (pi * (jf + 1.0) * (kf + 0.5) / nf).sin(),
            _ => (pi * (jf + 0.5) * (kf + 0.5) / nf).sin(),
        }
    };
    let inner = |range: std::ops::Range<usize>| range.map(|j| x[j] * kernel(j)).sum::<f64>();
    // Endpoint term (−1)ᵏ x[n−1].
    let alternating = if k % 2 == 0 { x[n - 1] } else { -x[n - 1] };
    match index {
        0 => x[0] + alternating + 2.0 * inner(1..n - 1),
        2 => x[0] + 2.0 * inner(1..n),
        6 => alternating + 2.0 * inner(0..n - 1),
        _ => inner(0..n),
    }
};
// Convenience functions: idct/idst when inverse is true (pass the forward type), dct/dst when false.
let convenience = |kind: RealTransformKind,
                   inverse: bool,
                   normalization: Normalization,
                   input: &[f64]| match (kind, inverse) {
    (RealTransformKind::Dct(ty), false) => dct(input, ty, normalization),
    (RealTransformKind::Dct(ty), true) => idct(input, ty, normalization),
    (RealTransformKind::Dst(ty), false) => dst(input, ty, normalization),
    (RealTransformKind::Dst(ty), true) => idst(input, ty, normalization),
};
let kinds: [(&str, RealTransformKind, f64); 8] = [
    ("DCT-I", DctType::I.into(), 2.0 * (nf - 1.0)),
    ("DCT-II", DctType::II.into(), nf),
    ("DCT-III", DctType::III.into(), nf),
    ("DCT-IV", DctType::IV.into(), nf / 2.0),
    ("DST-I", DstType::I.into(), (nf + 1.0) / 2.0),
    ("DST-II", DstType::II.into(), nf),
    ("DST-III", DstType::III.into(), nf),
    ("DST-IV", DstType::IV.into(), nf / 2.0),
];
let max_abs = |v: &[f64]| v.iter().fold(0.0_f64, |m, a| m.max(a.abs()));
let norm2 = |v: &[f64]| v.iter().map(|a| a * a).sum::<f64>().sqrt();
let mut rows = Vec::new();
let mut inverse_rows = Vec::new();
for (index, &(label, kind, factor)) in kinds.iter().enumerate() {
    let forward = run(kind, FftDirection::Forward, Normalization::Unscaled, &x);
    let y = match forward {
        Ok(y) => y,
        Err(e) => {
            rows.push((
                label,
                format!("{:?}", e.kind()),
                None,
                None,
                None,
                None,
                None,
            ));
            let status = match convenience(kind, true, Normalization::Unscaled, &x) {
                Ok(_) => "Computation".to_string(),
                Err(e) => format!("{:?}", e.kind()),
            };
            inverse_rows.push((label, status, None, None));
            continue;
        }
    };
    let expected: Vec<f64> = (0..n).map(|k| reference(index, k)).collect();
    let gaps: Vec<f64> = y.iter().zip(&expected).map(|(a, b)| a - b).collect();
    let back = run(kind, FftDirection::Inverse, Normalization::Unscaled, &y)
        .map_err(|e| e.to_string())?;
    // Measured R is ⟨z, x⟩ / ⟨x, x⟩. Divide the residual z − R x by max|x|.
    let measured = back.iter().zip(&x).map(|(a, b)| a * b).sum::<f64>() / norm2(&x).powi(2);
    let residual: Vec<f64> = back.iter().zip(&x).map(|(a, b)| a - factor * b).collect();
    let ortho = run(kind, FftDirection::Forward, Normalization::Orthonormal, &x)
        .map_err(|e| e.to_string())?;
    rows.push((
        label,
        "Computation".to_string(),
        Some(max_abs(&gaps) / max_abs(&expected)),
        Some(measured),
        Some(factor),
        Some(max_abs(&residual) / (factor * max_abs(&x))),
        Some((norm2(&ortho) / norm2(&x) - 1.0).abs()),
    ));
    // Apply idct/idst to the same y and compare with inverse-plan result back.
    let inverse =
        convenience(kind, true, Normalization::Unscaled, &y).map_err(|e| e.to_string())?;
    let plan_gaps: Vec<f64> = inverse.iter().zip(&back).map(|(a, b)| a - b).collect();
    // With Inverse normalization the forward transform is unscaled and the inverse scaled by 1/R, so a round trip restores x.
    let coefficients =
        convenience(kind, false, Normalization::Inverse, &x).map_err(|e| e.to_string())?;
    let restored = convenience(kind, true, Normalization::Inverse, &coefficients)
        .map_err(|e| e.to_string())?;
    let restore_gaps: Vec<f64> = restored.iter().zip(&x).map(|(a, b)| a - b).collect();
    inverse_rows.push((
        label,
        "Computation".to_string(),
        Some(max_abs(&plan_gaps) / max_abs(&back)),
        Some(max_abs(&restore_gaps) / max_abs(&x)),
    ));
}

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let digits10 = serde_json::json!({ "significantDigits": 10 });
let columns = serde_json::json!([
    { "key": "0", "label": "Type" },
    { "key": "1", "label": "Plan preparation" },
    { "key": "2", "label": "Relative difference from defining sum [-]", "type": "number", "format": sci3, "nullText": "—" },
    { "key": "3", "label": "Measured R [-]", "type": "number", "format": digits10, "nullText": "—" },
    { "key": "4", "label": "Tabulated R [-]", "type": "number", "format": digits10, "nullText": "—" },
    { "key": "5", "label": "Round-trip residual [-]", "type": "number", "format": sci3, "nullText": "—" },
    { "key": "6", "label": "Orthogonal |‖y‖/‖x‖ − 1| [-]", "type": "number", "format": sci3, "nullText": "—" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "conventions" })
);
let inverse_columns = serde_json::json!([
    { "key": "0", "label": "Type" },
    { "key": "1", "label": "idct/idst call" },
    { "key": "2", "label": "Relative difference from inverse plan [-]", "type": "number", "format": sci3, "nullText": "—" },
    { "key": "3", "label": "Relative round-trip residual with Inverse normalization [-]", "type": "number", "format": sci3, "nullText": "—" }
]);
emit_table_with_columns!(
    inverse_columns,
    inverse_rows,
    metadata = serde_json::json!({ "id": "inverse-functions" })
);
```

At the default $n=8$, all 8 types differ from the defining sums by at most $8.2\times10^{-16}$ relatively, showing that the tabulated sums are precisely SciOxide's convention.
Measured $R$ agrees with tabulated $14,8,8,4,4.5,8,8,4$ within relative $3\times10^{-16}$, and the difference between the round-trip result and $Rx$ is at most $3\times10^{-16}$.
Passing the forward type to the inverse plan and obtaining a round-trip factor $R$ shows that II and III are computed as dual types.
Under `Orthonormal`, the deviation of $\lVert y\rVert/\lVert x\rVert$ from 1 is at most $2.2\times10^{-16}$, consistent with orthogonality.
At $n=1$, the DCT-I plan returns `InvalidInput` while other types compute successfully, and type IV has $R$ equal to $1/2$.
At $n=24$ too, the relative difference from the defining sums is at most $2.4\times10^{-15}$.

In the second table, the `idct` and `idst` results match the inverse-plan result for every type, with difference 0.
Each convenience-function call prepares and executes an `RealTransformPlan` with the same type, direction, and normalization, so dual-type selection is identical to the plan's.
The relative round-trip residual with `Normalization::Inverse` is at most $3.3\times10^{-16}$ for the default $n=8$ and at most $3.9\times10^{-16}$ for $n=7$.
At $n=1$, `idct(…, DctType::I, …)` also returns `InvalidInput`, just as the plan does.


## Algorithms and APIs

Every type reduces to one FFT and costs $O(n\log n)$.

- DCT-I transforms a symmetric extension of length $2(n-1)$ and DST-I one of length $2(n+1)$ using a real FFT.
- Types II and III use a complex FFT of length $n/2$ for even lengths (Makhoul, 1980), and a real FFT of length $n$ for odd lengths.
- Type IV uses a complex FFT of length $n/2$ for even lengths and a real FFT of length $n$ for odd lengths.
- DST types II–IV reverse sample order and alternate signs to obtain the result from the same DCT type.

Convenience functions `dct(input, ty, normalization)`, `idct`, `dst`, and `idst` return a new `Vec` from one-dimensional input.
For repeated transforms of the same length, prepare an `RealTransformPlan` from `RealTransformPlanSpec::new(length, kind, direction, normalization)`.
`RealTransformKind` is either `Dct(DctType)` or `Dst(DstType)` and can be converted from a type, as in `DctType::II.into()`.
`kind` always denotes the forward type; an inverse plan computes its dual.
A plan fixes the direction and normalization, so prepare 2 plans for a round trip.
Pass the `FftWorkspace` returned by `workspace(())` to `execute_into(input, output, scratch, context)`; input and output are real slices of length $n$.

Errors are as follows.

- Length-0 input and length-1 DCT-I give `InvalidInput` during plan preparation (during the call for convenience functions).
- NaN or infinite input gives `NonFinite`; unrepresentable coefficients or results give `NumericalInstability` (`Overflow`).
- Input or output lengths differing from the plan, or insufficient workspace, give `DimensionMismatch`.

Multidimensional `dctn`, `idctn`, `dstn`, `idstn`, and `RealTransformNdPlan` specify a type for each selected axis.
[Multidimensional DCTs, DSTs, and workspaces](oxref:fft-real-transform-nd-workspace) covers workspaces and axis handling.

## Uses of each type

| Type | Main uses |
|---|---|
| DCT-I | Compute Chebyshev coefficients from values at endpoint-inclusive Chebyshev–Gauss–Lobatto points. Spectral methods with grid-point Neumann boundaries |
| DCT-II | Block transforms such as JPEG. Compute Chebyshev coefficients from values at Chebyshev points $\cos\frac{(2j+1)\pi}{2n}$. Cell-centered Neumann boundaries |
| DCT-III | Reconstruct from DCT-II coefficients |
| DCT-IV, DST-IV | Inside lapped transforms (MDCT, MDST) |
| DST-I | Second differences with grid-point Dirichlet boundaries ([Fast Poisson solvers](oxref:fft-fast-poisson)) |
| DST-II | Dirichlet boundaries on cell-centered grids (odd about both endpoint half-grid points) |
| DST-III | Reconstruct from DST-II coefficients |

An expansion in first-kind Chebyshev polynomials $T_k(\cos\theta)=\cos k\theta$ becomes a cosine series under $t=\cos\theta$.
Use DCT-II for function values at Chebyshev points and DCT-I for endpoint-inclusive points, adjusting normalization and endpoint weights in the sum to obtain Chebyshev coefficients.

## Summary

The 8 DCT and DST types are determined by even or odd extension at each endpoint and whether each symmetry center lies on a grid point or half-grid point.
The types in `scioxide-fft` use the defining sums above; an unscaled round trip multiplies input by $R$, `Forward` and `Inverse` select the direction divided by $R$, and `Orthonormal` selects an orthogonal matrix.
Pass the forward-transform type to inverse functions and inverse plans; types II and III are computed as duals.
Only DCT-I requires length at least 2; every other type supports length 1.
