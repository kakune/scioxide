The discrete Hankel transform in [Radial transforms and the discrete Hankel transform](../radial-transforms/) uses an approximately uniform grid and costs $O(n^2)$.
For functions spanning many decades in radius and wavenumber, such as power spectra and correlation functions, a uniform grid requires too many samples.
FFTLog (Talman 1978, Hamilton 2000) uses a uniform grid in $\ln r$ and computes the Hankel transform with 2 FFTs in $O(n\log n)$.
`scioxide-fft` provides `FftLogPlan` and convenience functions `fht` and `ifht`.

## Logarithmic grids and offset

The forward FFTLog transform approximates

$$
A(k) = \int_0^\infty a(r)\, J_\mu(kr)\, k\,dr
$$

where $J_\mu$ is the first-kind Bessel function of real order $\mu$.
Unlike the discrete Hankel transform, the integral has weight $k\,dr$ rather than $r\,dr$.

Input and output both lie on logarithmic grids of $n$ points with spacing $\Delta$.

$$
\ln r_j = \ln r_c + (j - j_c)\Delta, \qquad
\ln k_j = L - \ln r_c + (j - j_c)\Delta, \qquad
j_c = \frac{n-1}{2}
$$

$r_c$ is the central input radius, defaulting to 1.
$L = \ln(r_c k_c)$ is called the offset and determines the output center $k_c$.
The two grids satisfy $\ln r_j + \ln k_{n-1-j} = L$, so the input range $[r_0, r_{n-1}]$ and output range are approximately reciprocal.
The units of $r$ and $k$ need only be reciprocals; $L$ is dimensionless.

## Derivation with Mellin multipliers

Choose a bias exponent $q$ and consider $b(r) = a(r)\,(r/r_c)^{-q}$.
Interpolating $n$ samples of $b$ as a periodic function of $\ln r$ gives

$$
b(r) = \sum_m c_m \left(\frac{r}{r_c}\right)^{i\omega_m}, \qquad
\omega_m = \frac{2\pi m}{n\Delta}
$$

the expression above.
The coefficients $c_m$ are the DFT of samples $b(r_j)$.
Thus $a(r)$ is a sum of power functions $r^{x_m}$ ($x_m = q + i\omega_m$).

The Hankel transform of a power function has a closed form.

$$
\int_0^\infty r^{x} J_\mu(kr)\, k\,dr = k^{-x}\, U_\mu(x), \qquad
U_\mu(x) = 2^x\,\frac{\Gamma\!\left(\frac{\mu+1+x}{2}\right)}{\Gamma\!\left(\frac{\mu+1-x}{2}\right)}
$$

This integral converges for $-\mu - 1 < \operatorname{Re} x < 1/2$ (DLMF 10.22.43); outside this range, use the right side as the analytic continuation of the Γ ratio.
Transforming each term and substituting the output grid gives

$$
A(k_j)\,(k_j r_c)^{q} = \sum_m c_m\, u_m\, e^{-i\omega_m (j - j_c)\Delta}, \qquad
u_m = U_\mu(q + i\omega_m)\, e^{-i\omega_m L}
$$

the expression above.
Because the right side is also a DFT, FFTLog can be computed in 4 stages.

1. Multiply the input by the bias weights $(r_j/r_c)^{-q}$.
2. Compute $c_m$ with an FFT.
3. Multiply by the Mellin multipliers $u_m$.
4. Compute the right-hand sum using an inverse-direction FFT and index reversal ($e^{-i\omega_m (j - j_c)\Delta}$ is the inverse-DFT kernel with reversed indices).
   Multiply the output by the bias weights $(k_j r_c)^{-q}$.

The inverse plan uses $1/u_m$ and reciprocal power functions, so if no multiplier is zero, it exactly reverses the forward discrete map apart from rounding.

## Bias and periodization

FFTLog treats $b(r) = a(r)(r/r_c)^{-q}$ as a periodic function of $\ln r$ with period $n\Delta$.
It applies neither zero-padding nor a window.
If endpoint values $b(r_0)$ and $b(r_{n-1})$ differ greatly, the periodic extension has a jump that appears as output oscillations (ringing).
On the output side, $A(k)\,(k r_c)^{q}$ is also treated as periodic.

Choose the bias $q$ to reduce endpoint jumps.
If the input behaves as $a(r) \sim r^{s}$ for small $r$, its left-endpoint value is $b(r_0) \sim r_0^{s-q}$.
For a function sufficiently small at the right endpoint, decreasing $q$ reduces the input jump.
If the output behaves as $A(k) \sim k^{t}$ for small $k$, its left-endpoint value is of order $A(k_0)(k_0 r_c)^{q} \sim k_0^{t+q}$ and instead decreases as $q$ increases.
Moreover, restoring the output by the final weights $(k r_c)^{-q}$ also amplifies periodization error by those weights.
The weights grow on the small-$k$ side for $q > 0$, and on the large-$k$ side for $q < 0$.
Choose $q$ by balancing the input and output jumps and amplification by these weights.
If the input is exactly the power function $a(r) = r^{q}$, then $b$ is constant with no jump, and FFTLog agrees with the closed form within rounding error.
[Power-law closed form](oxref:fft-fftlog-power-law-check) uses this property to check conversion to a correlation function.

Function values outside the grid range are wrapped from the opposite side by periodic extension.
Increasing the sample count without changing the range $[r_0, r_{n-1}]$ does not reduce this wraparound.
Increase $\Delta$ or $n$ to widen the range.

## Low-ringing offset

For even $n$, the DFT Nyquist component $m = n/2$ represents the two frequencies $\pm\omega_{n/2}$ with one coefficient.
For real bias, the plan replaces the Nyquist multiplier $u_{n/2}$ by its real part.
Unless the phase $\varphi$ of $u_{n/2}$ is an integer multiple of $\pi$, this reduces the component's magnitude by a factor $\lvert\cos\varphi\rvert$.
Hamilton (2000) showed that an offset making this phase an integer multiple of $\pi$ reduces output oscillations (ringing).
When $\lvert\cos\varphi\rvert \le 64\varepsilon$, the multiplier is treated as 0.

The multiplier phase includes $-\omega_{n/2} L = -\pi L / \Delta$, so moving $L$ by $\Delta$ changes the phase by $\pi$.
`fftlog_low_ringing_offset(log_spacing, order, initial, bias)` returns the offset nearest `initial` among those making the phase an integer multiple of $\pi$.
The returned value differs from `initial` by at most $\Delta/2$.
This choice adjusts only Nyquist-component handling; it does not remove endpoint-jump errors or the difference from the continuous integral.

## Multiplier zeros and poles

$U_\mu(x)$ vanishes where the denominator Γ has a pole and becomes infinite where the numerator Γ has a pole.
For real bias, the following occurs in component $\omega_0 = 0$.

- If $(\mu + 1 - q)/2$ is a nonpositive integer ($q = \mu + 1, \mu + 3, \dots$), then $u_0 = 0$.
  The forward plan can run by discarding that component; the inverse plan returns `Singular` during execution.
- If $(\mu + 1 + q)/2$ is a nonpositive integer ($q = -\mu - 1, -\mu - 3, \dots$), then $u_0$ is a pole.
  The forward plan returns `Singular` during execution; the inverse plan discards that component.
- If both have poles, use the finite limiting ratio (the Pochhammer-symbol limit).
- If the preceding section's rule treats the Nyquist multiplier as 0, the forward direction likewise discards the component and the inverse returns `Singular`.

Plan preparation succeeds even for specifications containing zeros or poles.
The adjoint uses the same multipliers and therefore fails in the same cases.

## Cost and accuracy

Preparation evaluates $n$ Mellin multipliers in f64 using the complex logarithmic Γ function.
Even for large $\lvert\omega_m\rvert$, it takes differences in logarithmic form without forming Γ itself, avoiding overflow of Γ values.
Execution requires 2 complex FFTs of length $n$ in the selected scalar type and $O(n)$ multiplications; the workspace holds $n$ complex values plus the FFT workspace.
Multipliers and bias weights store significands and binary exponents separately, allowing intermediate values outside the scalar range when the result is in range.

`FftLogDiagnostics::log_multiplier_condition` is the natural logarithm of the ratio $\max_m\lvert u_m\rvert / \min_m\lvert u_m\rvert$ between the largest and smallest multiplier magnitudes.
At $q = 0$, the discrete map has singular values $\lvert u_m\rvert$, so this is the logarithm of its 2-norm condition number.
Furthermore, for real $\mu$ and $q = 0$, $\lvert U_\mu(i\omega)\rvert = 1$; hence the condition number is 1 (logarithm 0) when $n$ is odd or a low-ringing offset makes the Nyquist multiplier real.
For even $n$ at other offsets, the Nyquist multiplier shrinks by $\lvert\cos\varphi\rvert$, giving logarithm $-\ln\lvert\cos\varphi\rvert$.
Moving the bias away from 0 spreads the multiplier magnitudes and increases the condition number.
A zero or pole in either direction makes the value infinite.

The rustdoc states no numerical upper bound for FFTLog accuracy.
Rounding error in the discrete map can be estimated as FFT rounding error amplified by the spread in multiplier magnitudes (the condition number).
This is an estimate, not a bound verified by tests.
The difference from the continuous integral depends on periodization, wraparound from outside the range, and the coarseness of $\Delta$ described above, and varies by function.
Check against an analytic solution or a computation on a wider range, as in the following cell.

## Plans and convenience functions

- Specification `FftLogPlanSpec::new(length, log_spacing, order, offset, bias, direction)` takes sample count $n$, spacing $\Delta$, order $\mu$, offset $L$, complex bias $q$, and direction.
  `with_log_radius_center` sets $\ln r_c$ and shifts both grids (transform values depend only on $L$).
  `with_limits`, `with_iteration_budget` ($n$ iterations per transform), `with_execution_policy`, and `with_backend_strategy` configure limits, iteration limits, FFT execution policy, and implementation selection.
- Limits [`FftLogLimits`](https://docs.rs/scioxide-fft/0.1.0/scioxide_fft/struct.FftLogLimits.html) include preparation storage `preparation_bytes`, workspace storage `workspace_bytes`, and preparation work `preparation_work` (the total number of function calls and logarithmic Γ-function iterations).
  All default to unlimited.
  Exceeding a storage limit returns `ResourceLimit`; exhausting work returns `ConvergenceFailure`.
- Plan `FftLogPlan::new(spec)` owns its multipliers, weights, and FFT plans.
  `build(spec, planning, scope)` selects the FFT implementation or provider and charges preparation work to the parent solve's accounting.
- For grid coordinates, `log_radius(j)` and `log_frequency(j)` return $\ln r_j$ and $\ln k_j$ in `Result`.
  $j \ge n$ gives `OutOfBounds`.
- Execution `execute_into(input, output, workspace, scope)` takes a complex sequence of length $n$.
  Allocate the workspace once with `workspace(())` and reuse it for executions of the same plan.
  `execute_axis_into` transforms each sequence along one axis of a multidimensional array.
  Execution failures include `Singular` for multiplier poles (forward) or zeros (inverse), `NumericalInstability` for result overflow, and `ConvergenceFailure` for an iteration limit.
- Obtain diagnostics [`FftLogDiagnostics`](https://docs.rs/scioxide-fft/0.1.0/scioxide_fft/struct.FftLogDiagnostics.html) with `diagnostics()`.
  They contain `log_multiplier_condition` and the preparation work used, `preparation_work`.
- The plan implements `LinearOperator` and `AdjointOperator`.
  The adjoint applies the conjugate transpose of the plan's map.
- Convenience function `fht(a, dln, mu, offset, bias)` performs one forward transform of real samples with real bias and returns a real sequence (discarding imaginary rounding error).
  The central input radius is fixed at $r_c = 1$.
  `ifht` applies the inverse of `fht`'s discrete map; with no zero multiplier, `ifht(fht(a))` returns to `a` apart from rounding.

Preparation failures are as follows.
Length 0 or $\Delta \le 0$ gives `InvalidInput`; NaN or infinite order, spacing, offset, center, or bias gives `NonFinite`.
A nonzero multiplier rounding to 0 gives `NumericalInstability` (`Underflow`); weights or binary exponents exceeding range give `NumericalInstability` (`Overflow`).

The following cell transforms $a(r)=r^{3/2}/(1+r^2)^2$ on a $n$-point grid with $\Delta=0.1$, $\mu=1/2$, and $L=0$, checking convenience functions, plans, and limits.
Inputs are sample count $n$ and bias $q$.
It checks 2 things.
First, compare `fht` with the real part of the forward plan's `execute_into` result, then apply `ifht` to that real part and compare it with the real part of the inverse-plan result.
Differences are divided by the maximum magnitude of the plan output; both values from the forward plan's `FftLogDiagnostics` are also shown.
Second, examine `preparation_work` and `workspace_bytes` in `FftLogLimits`.
Use the preparation work reported by diagnostics and workspace bytes returned by `workspace_requirements(())` as reference values.
For each, try preparation and workspace allocation with a limit exactly equal to that value and with a limit one smaller.

        .map(|(x, z)| (*x - z.re).abs())

In every case, `fht` and `ifht` exactly match the real part of the plan result.
This is because the convenience functions create the same $r_c=1$ plan from the same arguments and return the real part of the complex result.
At the defaults $n=64$, $q=0$, the log multiplier condition number is 0.437 rather than 0.
Since $L=0$ is not a low-ringing offset, the Nyquist multiplier for even $n$ shrinks by $\lvert\cos\varphi\rvert=e^{-0.437}\approx0.65$ ([Cost and accuracy](#cost-and-accuracy)).
At $q=-0.5$ the logarithm rises to 2.391; storing bias weights for both grids also increases `plan_bytes()` from 2944 B to 4992 B.

Preparation work is 1665 for $n=64$, independent of $q$.
Setting `preparation_work` to 1665 permits preparation; 1664 gives `ConvergenceFailure`.
The workspace is 2048 B; setting `workspace_bytes` to 2047 gives `ResourceLimit`.
At $n=256$, work increases to 6657 and workspace to 8192 B.

## Checking a Gaussian function

The transform of $a(r) = r^{\mu+1} e^{-r^2/2}$ is $A(k) = k^{\mu+1} e^{-k^2/2}$ (Weber's integral, DLMF 10.22.51).
The input decays as $r^{\mu+1}$ for small $r$, and the output as $k^{\mu+1}$ for small $k$.
Thus periodized-function jumps are of order $r_0^{\mu+1-q}$ at the input's left endpoint and $k_0^{\mu+1+q}$ at the output's left endpoint.
Both right endpoints are sufficiently small because of Gaussian decay.
Jump errors can be amplified by up to the maximum output weight $k^{-q}$.

The following cell transforms $a$ on a grid with $n = 128$ points and $r_c = 1$, comparing it with the analytic solution.
Inputs are order $\mu$, spacing $\Delta$ (range $e^{\pm 63.5\Delta}$), and bias $q$.
The offset is chosen near 0 with `fftlog_low_ringing_offset`, so the output grid is also approximately $e^{\pm 63.5\Delta}$.
The first plot shows $A(k)$ and the analytic solution; the second shows pointwise absolute differences on a log axis, with the two wavenumber axes linked.
The table reports estimates of both jumps, maximum output weight, maximum difference divided by the maximum $A$, maximum difference after returning with `ifht`, log multiplier condition number, and preparation work.

// Input a(r) = r^{μ+1} e^{−r²/2}. Analytic solution A(k) has the same form (both evaluated with f64 functions)
let profile = |x: f64| x.powf(order + 1.0) * (-0.5 * x * x).exp();
let mut input = Vec::with_capacity(n);
for j in 0..n {
    let r = plan.log_radius(j).map_err(|e| e.to_string())?.exp();
    input.push(Complex::new(profile(r), 0.0));
}
let mut output = vec![Complex::new(0.0, 0.0); n];
let mut workspace = plan.workspace(()).map_err(|e| e.to_string())?;
plan.execute_into(
    &input,
    &mut output,
    &mut workspace,
    ExecutionContext::sequential(),
)
.map_err(|e| e.to_string())?;

// Independent check: compare with the analytic solution at k_j = exp(log_frequency(j))
let (mut computed, mut exact, mut errors) = (Vec::new(), Vec::new(), Vec::new());
let (mut largest, mut peak) = (0.0_f64, 0.0_f64);
for (j, value) in output.iter().enumerate() {
    let k = plan.log_frequency(j).map_err(|e| e.to_string())?.exp();
    let reference = profile(k);
    let error = (value.re - reference).abs();
    largest = largest.max(error);
    peak = peak.max(reference);
    computed.push([k, value.re]);
    exact.push([k, reference]);
    // Exclude points with exactly zero difference, which cannot be plotted on a log axis
    if error > 0.0 {
        errors.push([k, error]);
    }
}
// Return to the input grid with the real convenience function ifht and compare with original samples
let real_output: Vec<f64> = output.iter().map(|z| z.re).collect();
let back = ifht(&real_output, dln, order, offset, bias).map_err(|e| e.to_string())?;
let roundtrip = input
    .iter()
    .zip(&back)
    .map(|(a, b)| (a.re - b).abs())
    .fold(0.0_f64, f64::max);
// Estimates of periodized left-endpoint jumps (input r₀^{μ+1−q}, output k₀^{μ+1+q}) and output weights k^{−q}
let r0 = plan.log_radius(0).map_err(|e| e.to_string())?.exp();
let k0 = plan.log_frequency(0).map_err(|e| e.to_string())?.exp();
let k_last = plan.log_frequency(n - 1).map_err(|e| e.to_string())?.exp();
let diagnostics = plan.diagnostics();
let condition = Some(diagnostics.log_multiplier_condition).filter(|c| c.is_finite());

emit_line_chart!(
    &vec![
        serde_json::json!({
            "name": "FFTLog",
            "points": computed,
            "style": { "showSymbol": true }
        }),
        serde_json::json!({
            "name": "Analytic solution k^{μ+1} e^{−k²/2}",
            "points": exact,
            "style": { "lineType": "dashed" }
        }),
    ],
    options = &serde_json::json!({
        "xLabel": "Wavenumber k [1/length]",
        "yLabel": "A(k) [-]",
        "xType": "log",
        "xMin": 1e-3,
        "xMax": 1e3,
        "yMin": -0.5,
        "yMax": 1.5,
        "link": { "group": "fftlog-k" }
    })
);
emit_line_chart!(
    &vec![serde_json::json!({
        "name": "Absolute difference from analytic solution",
        "points": errors,
        "style": { "showSymbol": true }
    })],
    options = &serde_json::json!({
        "xLabel": "Wavenumber k [1/length]",
        "yLabel": "|A − analytic solution| [-]",
        "xType": "log",
        "yType": "log",
        "xMin": 1e-3,
        "xMax": 1e3,
        "yMin": 1e-18,
        "yMax": 100.0,
        "link": { "group": "fftlog-k" }
    })
);
let fixed4 = serde_json::json!({ "fractionDigits": 4 });
let fixed2 = serde_json::json!({ "fractionDigits": 2 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "offset L [-]", "type": "number", "format": fixed4 },
    { "key": "1", "label": "Input jump r₀^{μ+1−q} [-]", "type": "number", "format": sci2 },
    { "key": "2", "label": "Output jump k₀^{μ+1+q} [-]", "type": "number", "format": sci2 },
    { "key": "3", "label": "Maximum output weight max k^{−q} [-]", "type": "number", "format": sci2 },
    { "key": "4", "label": "Maximum difference / maximum A [-]", "type": "number", "format": sci2 },
    { "key": "5", "label": "Maximum ifht round-trip difference [-]", "type": "number", "format": sci2 },
    { "key": "6", "label": "Log multiplier condition number [-]", "type": "number", "format": fixed2, "nullText": "∞" },
    { "key": "7", "label": "Preparation work [count]", "type": "integer" }
]);
let row = (
    offset,
    r0.powf(order + 1.0 - bias),
    k0.powf(order + 1.0 + bias),
    k0.powf(-bias).max(k_last.powf(-bias)),
    largest / peak,
    roundtrip,
    condition,
    diagnostics.preparation_work,
);
emit_table_with_columns!(
    columns,
    vec![row],
    metadata = serde_json::json!({ "id": "summary" })

At the defaults $\mu = 0$, $\Delta = 0.1$, $q = 0$, the range is $r_0 = 1.7\times 10^{-3}$ to 573 and the offset is 0.0475.
Input and output jumps are $1.7\times 10^{-3}$ and $1.8\times 10^{-3}$; the maximum difference, $1.6\times 10^{-3}$ times the maximum $A$, is approximately the same magnitude.
Setting $\Delta = 0.15$ widens the range to $e^{\pm 9.5}$, reduces the jump to $7.3\times 10^{-5}$, and gives a difference ratio of $6.5\times 10^{-5}$.
At $\Delta = 0.05$, the jump rises to $4.2\times 10^{-2}$ and the difference ratio becomes $3.9\times 10^{-2}$.
At $\mu = 2$, the jump falls to $r_0^3 \approx 5.3\times 10^{-9}$ and the difference ratio becomes $3.9\times 10^{-9}$.
In every case the maximum difference is of the same order as the larger jump and changes with it.
This identifies endpoint jumps in the periodized function as the main error source for this input.

Setting $q = -0.5$ lowers the input jump to $7.3\times 10^{-5}$ but raises the output jump to $k_0^{0.5} = 4.3\times 10^{-2}$.
The output weight $k^{0.5}$ reaches 24.5 at the right endpoint, amplifying oscillations until the maximum difference reaches 1.6 times the maximum $A$.
At $q = 0.25$, the input jump $8.5\times 10^{-3}$ is amplified by weight $k^{-0.25}$, which reaches 4.8 at the left endpoint, giving a difference ratio of $3.9\times 10^{-2}$.
For functions such as Gaussians whose input and output endpoints decay at the same rate, $q = 0$ is a good choice.

The maximum difference after returning with `ifht` is $1.7\times 10^{-16}$ for $q = 0$, and the log multiplier condition number is 0.
At $q = -0.5$ the log condition number rises to 2.46 (condition number 12), and the round-trip difference increases to $1.3\times 10^{-14}$.
Round-trip differences show only that the discrete maps invert each other; closeness to the continuous Hankel transform depends on grid range and bias.

## Summary

FFTLog takes the DFT of biased input as a periodic function of $\ln r$, applies Mellin multipliers $u_m$, and transforms back, computing the Hankel transform in $O(n\log n)$.
The transform convention is $\int a(r) J_\mu(kr)\,k\,dr$; `fht` and `ifht` are real convenience functions for $r_c = 1$.
The main error sources are oscillations from endpoint jumps in input and output and wraparound from outside the range; increasing sample count alone does not reduce them.
Widen the range with $\Delta$ and $n$, choose bias $q$ by balancing input and output endpoint jumps, and select the offset with `fftlog_low_ringing_offset`.
Returning with `ifht` shows only that the discrete maps invert each other, so check closeness to the continuous integral against an analytic solution or a wider-range computation.
`fht` and `ifht` return the same results as plans; preparation exceeding `FftLogLimits` stops with `ResourceLimit` for storage limits or `ConvergenceFailure` for work limits.
