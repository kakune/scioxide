This part explains the definitions of the transforms computed by `scioxide-fft`, the algorithms that compute them efficiently, and the treatment of errors and failures.
Each page addresses one question; this page sets out the notation and conventions assumed by all of them.

## Notation for the discrete Fourier transform

For a complex sequence $x_0,\dots,x_{n-1}$ of length $n$, write the unnormalized forward and inverse transforms as

$$
X_k = \sum_{j=0}^{n-1} x_j\, e^{-2\pi i jk/n}, \qquad
x_j = \sum_{k=0}^{n-1} X_k\, e^{+2\pi i jk/n}
$$

($k, j = 0,\dots,n-1$).
`FftDirection::Forward` selects the sum with a negative exponent sign, and `FftDirection::Inverse` selects the positive sign.
Applying the two in succession multiplies the sequence by $n$ (derived in [DFT definition and inverse transform](oxref:fft-dft-definition)); the `Normalization` in the next section chooses where to place the factor $1/n$.
The sum in the definition requires $n^2$ complex multiplications; fast Fourier transform (FFT) is the collective name for algorithms that use a factorization of $n$ to compute the same values in $O(n\log n)$ operations.

The frequency of bin $k$ is $k/n$ when $k < n/2$, and $(k-n)/n$ when $k \ge n/2$, in cycles/sample.
For even lengths, the Nyquist bin $k = n/2$ is counted as $-1/2$.
For a sampling interval $\Delta t$, the physical frequency is this value divided by $\Delta t$.
`fftfreq(n, Δt)` returns this sequence (`rfftfreq` returns the nonnegative bins of a real transform), and `fftshift` moves bin 0 to the center ([Frequency axis and bin order](oxref:fft-frequency-axis)).

Multidimensional arrays are packed in row-major order (the last axis varies fastest) and described by `shape` and a sequence `axes` of axes to transform.
Unselected axes are treated as independent sequences (batches).

### Normalization

The four variants of `Normalization` distribute the round-trip factor $n$ (the product of the selected axis lengths in multiple dimensions): $1/n$ on the inverse transform (`Inverse`), $1/n$ on the forward transform (`Forward`), $1/\sqrt n$ on each direction (`Orthonormal`), or no factor (`Unscaled`).
Except for `Unscaled`, passing the same value in both directions restores the original sequence on a round trip; the packed representation of a real transform does not change the factor.
[Normalization and Parseval's identity](oxref:fft-normalization-conventions) derives Parseval's identity for each variant.

The meaning of $n$ changes for transforms other than the Fourier transform.

- DCT and DST use a type-specific round-trip factor ($n$ for DCT-II and $2(n-1)$ for DCT-I); `Orthonormal` also changes the endpoint weights to make the transform matrix orthogonal ([DCT, DST, and boundary conditions](dct-dst-and-boundaries/)).
- The chirp Z-transform has no direction: for input length $n$, `Forward` multiplies by $1/n$ and `Orthonormal` by $1/\sqrt n$; `Inverse` and `Unscaled` apply no factor.
- The nonuniform Fourier transform uses the number of terms in the sum (the number of points for types 1 and 3, and the product of the numbers of modes for type 2).
  `Forward` and `Inverse` divide by that number only when their names match the plan's direction; `Orthonormal` divides by its square root regardless of direction.
- The discrete Hankel transform and FFTLog have their own integral conventions and do not take `Normalization` ([Radial transforms and the discrete Hankel transform](radial-transforms/), [FFTLog and logarithmic grids](fftlog/)).

## Real input and packed spectra

The DFT of a real sequence satisfies $X_{n-k} = \overline{X_k}$ (Hermitian symmetry), so its independent values are the $\lfloor n/2\rfloor + 1$ values at $k = 0,\dots,\lfloor n/2\rfloor$.
`rfft` returns only these nonnegative-frequency bins.
Sequences of lengths $2m$ and $2m+1$ both give $m+1$ bins, so `HermitianSpectrum` stores the original length (logical length) alongside the bins to determine the inverse-transform length.
The multidimensional `HermitianSpectrumNd` packs only the last of the selected axes and stores the shape and axis sequence.

For plans, `FftLayout` (`Complex`, `Real`, `Hermitian`) selects the input and output representation; together with the direction it determines which of `rfft`, `irfft`, `hfft`, or `ihfft` applies ([Storage layouts in plans](oxref:fft-real-plan-layout)).
If the types of `FftInput` and `FftOutput` passed to `execute_into` do not match the layout, the result is `InvalidInput` (`UnsupportedConfiguration`).

## Input validation and failure handling

### Lengths and domains

One-dimensional transforms reject empty input with `InvalidInput`; DCT-I also rejects fewer than 2 points.
For multidimensional transforms, a transformed axis of length 0 gives `InvalidInput`, duplicate axes give `InvalidInput`, and an axis index at least equal to the number of dimensions gives `OutOfBounds`.
An array with an unselected axis of length 0 (an empty batch) is valid and succeeds without writing anything.
An empty NUFFT sum is 0.

The transform length is exactly the length of the supplied array; no zero-padding or truncation is implicit.
The caller extends the array when zero-padding is needed.

If an input value or parameter is NaN or infinite, the call returns `NonFinite` (origin `Input`) before computation.
If an injected external implementation (`FftProvider`) returns NaN or infinity, the error is also `NonFinite`, with origin `Callback`.

### Hermitian-symmetry validation

Transforms that reconstruct real values from a packed spectrum (`irfft`, `irfftn`, `hfft`, `hfftn`, and plans taking packed input) check that the input is Hermitian symmetric within rounding error.
For each independent spectrum, let $M$ be the maximum absolute real or imaginary component, $\varepsilon$ machine epsilon, and $\eta$ the smallest positive subnormal number, and set

$$
\tau = \max(8\varepsilon M,\ \eta)
$$

as above.

- Self-conjugate bins (DC and, for even lengths, Nyquist) must have imaginary parts of absolute value at most $\tau$.
- In multidimensional transforms, both members of a conjugate pair lie on the DC and Nyquist planes of the packed axis.
  The difference of their real parts and the sum of their imaginary parts must each have absolute value at most $2\tau$.

Deviations within this range are projected to exact Hermitian symmetry in the workspace, without changing the caller's input.
Input outside this range returns `InvalidInput` rather than being silently projected.
[Hermitian-symmetry validation](oxref:fft-hermitian-check) derives the projection rule and the upper bound on its effect on the transform.

### Value range and overflow

The kernel scales the input down by a power of 2 before transforming it, then restores the scale together with normalization in a single rounding step.
This allows input near the overflow threshold to be transformed without intermediate overflow.
Multidimensional transforms scale each batch independently, so a large-valued batch does not cause components of a small-valued batch to underflow to 0.
An unrepresentable output from finite input gives `NumericalInstability` (`Overflow`); output underflow to 0 is not an error.

### Output handling

A failure leaves the caller's output unchanged.
This includes gaps in strided output and every sequence in an axis transform.
A failure may change the workspace contents, but the workspace remains usable for the next call.

### Error classification

| `kind()` | Main causes |
|---|---|
| `InvalidInput` | Empty input, DCT-I input too short, failed Hermitian-symmetry validation, duplicate axes, invalid specification parameters, input/output types incompatible with the plan layout, or a requested CPU instruction set unavailable in the plan's context |
| `OutOfBounds` | Axis index at least equal to the number of dimensions |
| `NonFinite` | NaN or infinite input/parameters (`Input`), non-finite external-implementation output (`Callback`) |
| `NumericalInstability` | Output overflow from finite input (`Overflow`), failed internal rounding check in a packed real transform (`Breakdown`), or underflow of a nonzero coefficient computed during preparation (`Underflow`) |
| `DimensionMismatch` | Output, view, or workspace has an incompatible shape or insufficient length |
| `Singular` | An FFTLog multiplier is 0 when its reciprocal is required, or a Γ-function pole is encountered |
| `ResourceLimit`, `AllocationFailure`, `SizeOverflow` | Configured limit exceeded, allocation failure, or size overflow |
| `ConvergenceFailure` | Discrete Hankel transform or FFTLog preparation exceeds the work limit |
| `ExecutionStopped` | Stopped by a cancellation request or deadline |

Inspect the classification with `e.kind()` and read the details with `e.view()`.
[Error contracts and partial results](../../concepts/errors-and-partial-results/) covers general error classification and partial results.

## Accuracy contracts

For forward complex FFTs and packed real FFTs (SciOxide CPU kernels), tests against high-precision reference DFTs verify a relative $L^2$ error at most $2\varepsilon\max(1, \log_2 n)$ ($\varepsilon$ is machine epsilon; tested lengths are listed in [Cost and rounding error](oxref:fft-cost-and-accuracy)).
This is a normwise range verified by tests, not a proven upper bound or a guarantee of componentwise relative error.
Bins much smaller than the largest bin can have large relative errors.
The DC bin is computed with the same FFT rounding as other bins, so it is not the correctly rounded sum of cancelling inputs.
Injected external implementations are outside this contract and follow their own accuracy properties.

Accuracy is stated differently for other transforms.

| Transform | Accuracy statement |
|---|---|
| Chirp Z-transform, `zoom_fft` | Componentwise absolute-error upper bound for Bluestein's algorithm, proportional to the weighted input sum |
| Nonuniform Fourier transform | An error estimate relative to the input $\ell^1$ norm meets the requested accuracy. The estimate is not an upper bound |
| Discrete Hankel transform | Componentwise bound for the matrix-vector product. Quadrature error depends on the function |
| FFTLog | No numerical upper bound is stated. Continuous-integral error depends on the grid, bias, and function |

Each page distinguishes upper bounds, estimates, and ranges verified by tests.

## Plans and workspaces

Create a plan when repeating transforms of the same shape.
A plan is prepared from a specification (such as `FftPlanSpec`), fixing the length, direction, normalization, layout, execution policy, and CPU instruction set during preparation.
A prepared plan is immutable, so prepare a separate plan for the opposite direction.

Preparation (`new`, `build`) allocates storage for the plan.
A plan's `execute_into` uses only the caller-supplied output and workspace, with no heap allocation when the workspace is sufficient.
Functions such as `fft`, `rfft`, and `dct` create and discard a plan on each call and return the result in newly allocated storage.

Query workspace size with the plan's `workspace_requirements(request)` and allocate it with `workspace(request)`.
For transforms whose size is determined by the plan alone, `request` is `()`.
Pass `AxisWorkspaceRequest::Axis { shape, axis }` to `execute_axis_into` for chirp Z-transforms, nonuniform Fourier transforms, discrete Hankel transforms, and FFTLog along one axis of a multidimensional array.
This workspace also holds the entire output, which is written only after every sequence succeeds.

Plans for nonuniform Fourier transforms, discrete Hankel transforms, and FFTLog implement `LinearOperator` and `AdjointOperator`.
One application (and an axis call with at least one sequence) counts as one operator evaluation; internal FFTs are not counted.

[FFT plans, workspaces, and caches](plans-workspaces-and-providers/) explains plan ownership, workspace reuse and limits, and `FftPlanCache`; [External FFT implementations and CPU instruction sets](providers-and-cpu-backends/) explains CPU instruction-set selection and injection of an external implementation (`FftProvider`).
[Execution modes, workspaces, and reproducibility](../../concepts/workspaces-and-reproducibility/) covers general workspace and reproducibility concepts.
The cells in this book run sequentially on wasm32, so their results use the portable scalar kernel.

## Summary

Transforms in `scioxide-fft` use a negative exponent sign in the forward direction and distribute the round-trip factor through `Normalization` variants `Forward`, `Inverse`, `Orthonormal`, and `Unscaled`.
DCT, DST, the chirp Z-transform, and nonuniform Fourier transforms count the factor differently; the discrete Hankel transform and FFTLog do not take `Normalization`.
Real spectra carry a logical length and a packed axis; packed input is checked for Hermitian symmetry and returns `InvalidInput` when outside the allowed range.
A failed call leaves output unchanged, so inspect the error classification, correct the input, and call again.
Read accuracy statements according to their meaning: FFT accuracy is a normwise range verified by tests, chirp Z-transform and discrete Hankel transform accuracy uses upper bounds, and nonuniform Fourier transform accuracy uses estimates.
