PDE grids and images often require transforms of arrays with different boundary conditions on each axis.
A multidimensional DCT/DST successively applies a one-dimensional DCT or DST on each selected axis and is separable by axis, like the multidimensional DFT ([Axis separability and cost](oxref:fft-multidimensional)).
This page explains convenience functions, plans mixing types by axis, and workspace requirements and allocation, then compares with direct summation.

## Convenience functions and plans

`dctn`, `idctn`, `dstn`, and `idstn` are convenience functions taking a row-major slice, shape, axis sequence, and sequence of per-axis types.
Entry `i` of the type sequence gives the type of axis entry `i` in `axes`; `dctn` takes a sequence of `DctType` and `dstn` one of `DstType`.
To mix DCT and DST by axis, pass a sequence of `RealTransformKind` to `RealTransformNdPlanSpec::new(shape, axes, types, direction, normalization)` and prepare an `RealTransformNdPlan`.
[DCT, DST, and boundary conditions](../dct-dst-and-boundaries/) gives each type's definition and scale.
The unscaled round-trip factor is the product of the selected axes' factors.

`RealTransformNdPlan` uses `RealTransformNdWorkspace`, which has separate real and complex workspace regions and is a different type from the complex FFT's `FftWorkspace`.
`RealTransformNdWorkspaceRequirements` returns real-region element count `real_len()`, byte count `real_bytes()`, alignment `real_alignment()`, complex-region requirements `complex()`, total byte count `bytes()`, and maximum accepted capacity `byte_limit()`.
The real region holds $V$ values for assembling the result plus temporary storage for gathering strided sequences into contiguous order.
Temporary length depends on the longest sequence and the one-dimensional plan's requirements and may exceed $V$.
The one-dimensional plans for each axis use the complex region successively, so its length is their maximum requirement.

Allocate the workspace with `plan.workspace(())`, or create an empty one with `RealTransformNdWorkspace::new()` and expand it with `try_reserve(&requirements)`.
`check(&requirements)` returns `Capacity` indicating whether both regions are long enough.
Workspaces grow without shrinking and can be reused across plans.
However, combined region capacities exceeding a plan's limit give `ResourceLimit`; insufficient lengths during execution give `DimensionMismatch`.

## Checking a mixed DCT/DST plan and its workspace

The following cell prepares an unscaled `RealTransformNdPlan` applying DCT-II on axis 0 and DST-II on axis 1 to an asymmetric real array of shape $M\times N$.
It creates an empty workspace with `RealTransformNdWorkspace::new()`, applies `check` with plan requirements `RealTransformNdWorkspaceRequirements`, expands it with `try_reserve`, and calls `check` again.
Compare execution using the expanded workspace with an $O(M^2N^2)$ direct sum combining the defining sums for both axes.
The direct sum is an independent reference value computed with `cos` and `sin` from `f64`.
Also compare with applying `dctn` on axis 0 and then `dstn` on axis 1 to the same array.
Finally, apply `dstn` with `Orthonormal` and axis types DST-I and DST-IV, followed by `idstn`, and measure return to the original array.
Every difference is relative to the maximum absolute direct-sum value (the original array for a round trip).
The requirements table reports element and byte counts, alongside total bytes independently computed from element sizes (8 bytes for `f64`, 16 for `Complex<f64>`).

```rust
//| id: fft-nd-mixed-real-transforms
//| ref: fft-nd-mixed-real-transforms
//| title: "Plans mixing DCT and DST by axis and their workspace requirements"
//| run: reactive
//| crates: [scioxide-core, scioxide-fft]
//| inputs:
//|   rows_count: {"type":"range","label":"Rows M","description":"Axis-0 length. Axis 0 uses DCT-II.","min":1,"max":16,"step":1,"value":6}
//|   cols_count: {"type":"range","label":"Columns N","description":"Axis-1 length. Axis 1 uses DST-II.","min":1,"max":16,"step":1,"value":8}
//| cases:
//|   - {"id":"odd-sizes","label":"M = 5, N = 9","description":"Odd lengths. Type II uses a real FFT of the same length.","inputs":{"rows_count":5,"cols_count":9}}
//|   - {"id":"single-row","label":"M = 1, N = 7","description":"Axis 0 has length 1. Length-1 DCT-II leaves values unchanged, so only the DST-II of each row remains.","inputs":{"rows_count":1,"cols_count":7}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"capacity","path":"/rows/0/1","equals":"NeedsGrowth"}
//|       - {"artifact":"capacity","path":"/rows/1/1","equals":"Sufficient"}
//|       - {"artifact":"nd-errors","path":"/rows/0/1","range":{"max":1e-14}}
//|       - {"artifact":"nd-errors","path":"/rows/1/1","range":{"max":1e-14}}
//|       - {"artifact":"nd-errors","path":"/rows/2/1","range":{"max":1e-14}}
//|       - {"artifact":"requirements","path":"/rows/0/1","approx":{"value":160,"atol":0.5}}
//|       - {"artifact":"requirements","path":"/rows/2/1","approx":{"value":8,"atol":0.5}}
//|       - {"artifact":"requirements","path":"/rows/4/1","approx":{"value":1408,"atol":0.5}}
//|       - {"artifact":"requirements","path":"/rows/5/1","approx":{"value":1408,"atol":0.5}}
//|   - case: odd-sizes
//|     expect:
//|       - {"artifact":"capacity","path":"/rows/1/1","equals":"Sufficient"}
//|       - {"artifact":"nd-errors","path":"/rows/0/1","range":{"max":1e-14}}
//|       - {"artifact":"nd-errors","path":"/rows/2/1","range":{"max":1e-14}}
//|       - {"artifact":"requirements","path":"/rows/2/1","approx":{"value":26,"atol":0.5}}
//|       - {"artifact":"requirements","path":"/rows/4/1","approx":{"value":1712,"atol":0.5}}
//|       - {"artifact":"requirements","path":"/rows/5/1","approx":{"value":1712,"atol":0.5}}
//|   - case: single-row
//|     expect:
//|       - {"artifact":"nd-errors","path":"/rows/0/1","range":{"max":1e-14}}
//|       - {"artifact":"nd-errors","path":"/rows/1/1","range":{"max":1e-14}}
//|       - {"artifact":"nd-errors","path":"/rows/2/1","range":{"max":1e-14}}
//|       - {"artifact":"capacity","path":"/rows/1/1","equals":"Sufficient"}
//|       - {"artifact":"requirements","path":"/rows/4/1","approx":{"value":896,"atol":0.5}}
use scioxide_core::{ExecutionContext, NdView, NdViewMut};
use scioxide_fft::{DctType, DstType, FftDirection, Normalization, RealTransformKind};
use scioxide_fft::{RealTransformNdPlan, RealTransformNdPlanSpec, RealTransformNdWorkspace};
use scioxide_fft::{RealTransformNdWorkspaceRequirements, dctn, dstn, idstn};

let (m, n) = (rows_count.round() as usize, cols_count.round() as usize);
let shape = [m, n];
let pi = std::f64::consts::PI;
// Asymmetric real array (constructed with arithmetic alone). In row-major order, element (j, k) is at position j·N + k.
let x: Vec<f64> = (0..m * n)
    .map(|i| 1.0 / (1.0 + i as f64) + 0.5 * ((i * 7) % 5) as f64)
    .collect();
// types[i] is the type for axes[i]: DCT-II on axis 0 and DST-II on axis 1.
let kinds: [RealTransformKind; 2] = [DctType::II.into(), DstType::II.into()];
let spec = RealTransformNdPlanSpec::new(
    &shape,
    &[0, 1],
    &kinds,
    FftDirection::Forward,
    Normalization::Unscaled,
)
.map_err(|e| e.to_string())?;
let plan = RealTransformNdPlan::<f64>::new(spec).map_err(|e| e.to_string())?;
let requirements: RealTransformNdWorkspaceRequirements =
    plan.workspace_requirements(()).map_err(|e| e.to_string())?;
// An empty workspace is created without allocation; try_reserve expands it to meet the requirements.
let mut workspace = RealTransformNdWorkspace::<f64>::new();
let before = workspace.check(&requirements).map_err(|e| e.to_string())?;
workspace
    .try_reserve(&requirements)
    .map_err(|e| e.to_string())?;
let after = workspace.check(&requirements).map_err(|e| e.to_string())?;
let mut mixed = vec![0.0; m * n];
plan.execute_into(
    NdView::row_major(&x, &shape).map_err(|e| e.to_string())?,
    NdViewMut::row_major(&mut mixed, &shape).map_err(|e| e.to_string())?,
    &mut workspace,
    ExecutionContext::sequential(),
)
.map_err(|e| e.to_string())?;
// Independent check: Σ_j Σ_k x_jk cos(π(j+½)p/M) sin(π(k+½)(q+1)/N) (reference values using f64 cos and sin).
let mut direct = vec![0.0; m * n];
for p in 0..m {
    for q in 0..n {
        let mut sum = 0.0;
        for j in 0..m {
            let cosine = (pi * (j as f64 + 0.5) * p as f64 / m as f64).cos();
            for k in 0..n {
                let sine = (pi * (k as f64 + 0.5) * (q as f64 + 1.0) / n as f64).sin();
                sum += x[j * n + k] * cosine * sine;
            }
        }
        direct[p * n + q] = sum;
    }
}
let norm = Normalization::Unscaled;
let along_rows = dctn(&x, &shape, &[0], &[DctType::II], norm).map_err(|e| e.to_string())?;
let composed =
    dstn(&along_rows, &shape, &[1], &[DstType::II], norm).map_err(|e| e.to_string())?;
// Round trip with orthogonal DST-I (axis 0) and DST-IV (axis 1).
let sine_types = [DstType::I, DstType::IV];
let ortho = Normalization::Orthonormal;
let coefficients = dstn(&x, &shape, &[0, 1], &sine_types, ortho).map_err(|e| e.to_string())?;
let restored =
    idstn(&coefficients, &shape, &[0, 1], &sine_types, ortho).map_err(|e| e.to_string())?;
let max_abs = |v: &[f64]| v.iter().fold(0.0_f64, |a, b| a.max(b.abs()));
let relative_gap = |a: &[f64], b: &[f64]| {
    let gap = a
        .iter()
        .zip(b)
        .fold(0.0_f64, |g, (p, q)| g.max((p - q).abs()));
    gap / max_abs(b)
};

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let error_columns = serde_json::json!([
    { "key": "0", "label": "Comparison" },
    { "key": "1", "label": "Difference / maximum absolute value [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    error_columns,
    vec![
        (
            "RealTransformNdPlan versus direct sum",
            relative_gap(&mixed, &direct)
        ),
        (
            "dctn (axis 0) → dstn (axis 1) versus direct sum",
            relative_gap(&composed, &direct)
        ),
        ("Orthogonal idstn(dstn(x)) versus x", relative_gap(&restored, &x)),
    ],
    metadata = serde_json::json!({ "id": "nd-errors" })
);
// Independently compute total bytes from element sizes (8 for f64, 16 for Complex<f64>).
let complex_len = requirements.complex().complex_len();
let expected_bytes = 8 * requirements.real_len() + 16 * complex_len;
let requirement_columns = serde_json::json!([
    { "key": "0", "label": "Quantity" },
    { "key": "1", "label": "Value", "type": "integer" }
]);
emit_table_with_columns!(
    requirement_columns,
    vec![
        ("Real region real_len() [elements]", requirements.real_len()),
        ("Total element count V = MN [elements]", m * n),
        ("Complex region complex().complex_len() [elements]", complex_len),
        (
            "Real region real_bytes() [bytes]",
            requirements.real_bytes()
        ),
        ("Total bytes() [bytes]", requirements.bytes()),
        ("8·real_len + 16·complex_len [bytes]", expected_bytes),
    ],
    metadata = serde_json::json!({ "id": "requirements" })
);
let capacity_columns = serde_json::json!([
    { "key": "0", "label": "Stage" },
    { "key": "1", "label": "check result" }
]);
emit_table_with_columns!(
    capacity_columns,
    vec![
        ("Immediately after new()", format!("{before:?}")),
        ("After try_reserve", format!("{after:?}")),
    ],
    metadata = serde_json::json!({ "id": "capacity" })
);
```

For the default 6×8 array, the plan–direct-sum difference divided by the maximum absolute direct-sum value is $7.9\times10^{-16}$.
Successively applying `dctn` and `dstn` by axis gives the same $7.9\times10^{-16}$, consistent with type entry $i$ applying to axis entry $i$ in `axes`.
A round trip applying orthogonal DST-I and DST-IV with `dstn` followed by `idstn` gives difference $5.7\times10^{-16}$ and a round-trip factor of 1.
For odd lengths 5×9, the plan–direct-sum difference also remains $1.3\times10^{-15}$.

`check` returns `NeedsGrowth` immediately after `new()` and `Sufficient` after `try_reserve`; the expanded workspace can then be used directly for execution.
The 6×8 requirements are 160 real elements and 8 complex elements, so the real region exceeds $V=48$ values.
The total of 1408 bytes from `bytes()` agrees with $8\cdot160+16\cdot8$ and equals `real_bytes()` plus the complex-region bytes.
For 5×9, the complex region grows to 26 elements and the total to 1712 bytes; requirements vary with shape.

## Summary

`dctn`, `idctn`, `dstn`, and `idstn` are convenience functions applying per-axis types to a row-major slice; type entry $i$ applies to axis entry $i$ in `axes`.
To mix DCT and DST by axis, pass a sequence of `RealTransformKind` to `RealTransformNdPlanSpec` and prepare an `RealTransformNdPlan`.
The plan uses `RealTransformNdWorkspace` with separate real and complex regions; query requirements with `RealTransformNdWorkspaceRequirements` and allocate with `try_reserve`.
The real region holds $V$ values plus sequence temporaries and can exceed $V$, so consult the requirements when sizing it.
Differences from direct sums are on the scale of rounding error, and the unscaled round-trip factor is the product of selected axes' factors.
