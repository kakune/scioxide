The 3 types in [Nonuniform Fourier transforms](../nonuniform-fft/) compute exponential sums by moving them onto uniform grids with a kernel and using FFTs, rather than summing directly.
Approximation error depends on kernel width and grid spacing; plan preparation selects the smallest width meeting the requested accuracy.
This page explains kernel and grid construction, requested accuracy, preparation's error estimates, work and storage, then compares estimates and actual errors for type 3 at irregular observation times.

## Kaiser–Bessel kernels and oversampled grids

Type 1 spreads each point value onto a uniform oversampled grid using a kernel $w$ grid points wide (spreading), transforms the grid with an FFT, and divides by the kernel's Fourier transform to recover mode values (deconvolution).
Type 2 reverses this order: divide coefficients by the kernel's Fourier transform, FFT back to a grid, then interpolate point values from the grid with the kernel.
Type 3 scales points onto a grid and interpolates at frequency positions after the FFT, performing both spreading and interpolation (Barnett, Magland & af Klinteberg 2019).

The kernel is the Kaiser–Bessel function $I_0\bigl(\beta\sqrt{1-(2u/w)^2}\bigr)/I_0(\beta)$, where $u$ ($\lvert u\rvert\le w/2$) is distance in grid-point units and $I_0$ is the modified Bessel function of the first kind.
The shape parameter is

$$
\beta = \pi\sqrt{\bigl(w(1-1/(2\sigma_o))\bigr)^2-0.8}
$$

as above (Beatty, Nishimura & Pauly 2005).
$\sigma_o\ge2$ is the minimum oversampling factor, changed with `NufftPlanSpec::with_oversampling` (default 2).
For an axis with $N_a>1$, the grid has the smallest power-of-2 point count at least $\max(\lceil\sigma_oN_a\rceil, w+2)$, so the actual oversampling factor is at least $\sigma_o$.
Kernel shape $\beta$ and estimate $E_a$ in the next section use the specified $\sigma_o$ rather than the actual grid ratio.
For type 3, the point-box half-width $X_a$ and frequency-box half-width $S_a$ determine base count $2\lceil X_aS_a\sigma_o/\pi\rceil+w+1$, then the same rule determines the grid.
Type-3 grid size depends on the product $X_aS_a$ of spatial and frequency spread, rather than point count.

Spreading or interpolating one point visits $w^d$ grid points; type 3 visits them for both points and frequencies.
With grid point count $G$, one transform costs $O(Mw^d+G\log G)$ (for type 3, $M$ is the sum of point and frequency counts).
In addition to FFT tables, the plan stores $O(Md+\sum_aN_a+dw)$ values; most workspace storage holds 2 oversampled grids.
For few points or modes, the cost including preparation can exceed direct summation.

## Requested accuracy and error estimates

Requested accuracy $\varepsilon_r$ ($0<\varepsilon_r<1$) specifies maximum output error relative to the input 1-norm.

$$
\max_\ell\bigl\lvert \hat f_\ell-f_\ell\bigr\rvert \lesssim \varepsilon_r\,\lvert s\rvert\sum_j\lvert c_j\rvert
$$

$\hat f_\ell$ is the computed value, $f_\ell$ the exact sum, and $s$ the normalization factor.
For type 2, the sum on the right becomes the mode-coefficient 1-norm $\sum_{\mathbf k}\lvert f_{\mathbf k}\rvert$.
The reference is input magnitude rather than output magnitude, so relative error of outputs made small by cancellation is outside the request.

Preparation searches for the smallest $w\ge4$ whose aliasing estimate $E_a$ plus rounding estimate $E_r$ is at most $\varepsilon_r$.

$$
E_a=(1+a)^r-1,\qquad a=3\exp\bigl(-\pi(w-1)\sqrt{1-1/\sigma_o}\bigr)
$$

$$
E_r=\varepsilon\,(4+C+\log_2\max(2,G))+\varepsilon_{64}\,(2P+8d)
$$

$r$ is $d$ for types 1 and 2, and $2d$ for type 3, which uses 2 grid stages.
$\varepsilon$ is the scalar type's machine epsilon, and $\varepsilon_{64}$ is that of `f64`.
$C$ is 64 for `f64` and 4 for `f32` when three-dimensional spreading groups points into local bins, and 0 without grouping.
For types 1 and 2, $P$ is the sum of $N_a$ over axes containing coordinates with absolute value exceeding $\pi$; it is 0 when all coordinates lie in $[-\pi,\pi]$.
The decay rate of $a$ comes from Kaiser–Bessel theory, but coefficient 3 is empirical, determined by comparisons with direct sums.
Both quantities are estimates rather than upper bounds; cancellation can make actual error much smaller.

If $E_r\ge\varepsilon_r$, widening the kernel cannot meet the request, so preparation returns `NumericalInstability`.
For `f64`, $E_r$ is already of order $4\times10^{-15}$ even in small one-dimensional problems, and increases with grid size, coordinate range, and dimension.
Increasing $\sigma_o$ makes $a$ decay faster, allowing a narrower kernel but enlarging the grid.

## Type 3 at irregular observation times

Type 3 directly handles sums with both nonuniform times and nonuniform frequencies.
The following cell uses the same observation times and light curve as [Variable-star period estimation](../../../scioxide-signal/examples/variable-star-period/) in the signal chapter (period $P=0.567$ days, 240 points over 40 nights with 6 per night), without added noise.
From mean-subtracted brightness $c_j$ [mag] and times $t_j$ [days], compute $F(\nu)=\sum_jc_je^{-2\pi i\nu t_j}$ at 1901 frequencies spanning 0.2–4 day⁻¹.
Pass times [days] and angular frequencies $\omega=2\pi\nu$ [rad/day] to type 3.
Inputs are the requested-accuracy exponent and minimum oversampling factor $\sigma_o$.
As an independent check, report the maximum difference from direct sums at all 1901 points (using intrinsic methods of `f64`), divided by the input 1-norm.
Period estimation and false-alarm probabilities are covered in the signal chapter, and type-1 comparisons at different requested accuracies in the example; here examine type-3 estimates and grid sizes.

```rust
//| id: fft-nufft-direct-sum
//| ref: fft-nufft-direct-sum
//| title: "Compute Fourier sums at irregular observation times with type 3 and compare with direct summation"
//| run: reactive
//| crates: [scioxide-core, scioxide-fft]
//| inputs:
//|   accuracy_exponent: {"type":"integer","label":"Requested-accuracy exponent p (ε_r = 10^p)","description":"Requested maximum error relative to the input 1-norm.","min":-12,"max":-3,"value":-6}
//|   oversampling: {"type":"range","label":"Minimum oversampling factor σ_o [-]","description":"Larger values narrow the kernel and enlarge the grid.","min":2,"max":4,"step":0.5,"value":2}
//| cases:
//|   - {"id":"strict","label":"ε_r = 10⁻¹²","description":"The kernel widens, increasing spreading visits.","inputs":{"accuracy_exponent":-12}}
//|   - {"id":"oversampled","label":"σ_o = 3","description":"The kernel narrows at the expense of a larger grid.","inputs":{"oversampling":3}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"accuracy","path":"/rows/0/1","range":{"max":1e-6}}
//|       - {"artifact":"accuracy","path":"/rows/0/4","approx":{"value":9,"atol":0.5}}
//|   - case: strict
//|     expect:
//|       - {"artifact":"accuracy","path":"/rows/0/1","range":{"max":1e-12}}
//|       - {"artifact":"accuracy","path":"/rows/0/4","range":{"min":15}}
//|   - case: oversampled
//|     expect:
//|       - {"artifact":"accuracy","path":"/rows/0/1","range":{"max":1e-6}}
//|       - {"artifact":"accuracy","path":"/rows/0/4","range":{"max":8.5}}
use scioxide_core::{Complex, ExecutionContext, NdView, StridedLayout};
use scioxide_fft::{FftDirection, Normalization, NufftPlan, NufftPlanSpec, NufftTransform};

let tau = 2.0 * std::f64::consts::PI;
let period = 0.567_f64; // Period [days]
// 40 nights × 6 observation times [days] and brightness [mag] (f64 sin is used only to generate input)
let times: Vec<f64> = (0..240)
    .map(|j| (j / 6) as f64 + 0.05 + 0.25 * (j as f64 * 0.618_033_988_749_894_9).fract())
    .collect();
let light: Vec<f64> = times
    .iter()
    .map(|&t| {
        let phase = tau * t / period;
        0.3 * phase.sin() + 0.1 * (2.0 * phase + 0.7).sin()
    })
    .collect();
let mean = light.iter().sum::<f64>() / light.len() as f64;
let c: Vec<Complex<f64>> = light.iter().map(|&y| Complex::new(y - mean, 0.0)).collect();
// Pass frequencies ν = 0.2–4 day⁻¹ (1901 points) as angular frequencies ω = 2πν [rad/day]
let nu: Vec<f64> = (0..1901).map(|k| 0.2 + 0.002 * k as f64).collect();
let omegas: Vec<f64> = nu.iter().map(|v| tau * v).collect();

let (point_shape, target_shape) = ([times.len(), 1], [omegas.len(), 1]);
let point_layout = StridedLayout::new(&point_shape, &[1, 1]).map_err(|e| e.to_string())?;
let target_layout = StridedLayout::new(&target_shape, &[1, 1]).map_err(|e| e.to_string())?;
let transform = NufftTransform::Type3 {
    points: NdView::new(&times, point_layout).map_err(|e| e.to_string())?,
    frequencies: NdView::new(&omegas, target_layout).map_err(|e| e.to_string())?,
};
let accuracy = 10f64.powi(accuracy_exponent);
let spec = NufftPlanSpec::new(FftDirection::Forward, Normalization::Unscaled, accuracy)
    .with_oversampling(oversampling);
let plan = NufftPlan::new(transform, spec).map_err(|e| e.to_string())?;
let mut workspace = plan.workspace(()).map_err(|e| e.to_string())?;
let mut output = vec![Complex::new(0.0, 0.0); omegas.len()];
plan.execute_into(
    &c[..],
    &mut output[..],
    &mut workspace,
    ExecutionContext::sequential(),
)
.map_err(|e| e.to_string())?;

// Independent check: direct sum Σ_j c_j exp(−i ω t_j) at every frequency
let l1: f64 = c.iter().map(|v| v.norm()).sum();
let mut worst = 0.0_f64;
for (value, &omega) in output.iter().zip(&omegas) {
    let direct: Complex<f64> = c
        .iter()
        .zip(&times)
        .map(|(cj, &t)| *cj * Complex::from_polar(1.0, -omega * t))
        .sum();
    worst = worst.max((*value - direct).norm() / l1);
}

let curve: Vec<[f64; 2]> = nu
    .iter()
    .zip(&output)
    .map(|(&v, z)| [v, z.norm()])
    .collect();
emit_line_chart!(
    &vec![serde_json::json!({ "name": "|F(ν)| (type 3)", "points": curve })],
    options = &serde_json::json!({
        "xLabel": "Frequency ν [day⁻¹]",
        "yLabel": "Fourier-sum magnitude |F| [mag]",
        "xMin": 0.2,
        "xMax": 4.0,
        "annotations": [
            { "kind": "line", "axis": "x", "value": 1.0 / period, "label": "Fundamental frequency" },
            { "kind": "line", "axis": "x", "value": 2.0 / period, "label": "Second harmonic" }
        ]
    })
);
let d = plan.diagnostics();
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "Requested accuracy ε_r [-]", "type": "number", "format": sci2 },
    { "key": "1", "label": "Measured error / Σ|c_j| [-]", "type": "number", "format": sci2 },
    { "key": "2", "label": "Estimate E_a [-]", "type": "number", "format": sci2 },
    { "key": "3", "label": "Estimate E_r [-]", "type": "number", "format": sci2 },
    { "key": "4", "label": "Kernel width w", "type": "integer" },
    { "key": "5", "label": "Grid points G", "type": "integer" },
    { "key": "6", "label": "Total grid-point visits", "type": "integer" },
    { "key": "7", "label": "Direct-sum terms MK", "type": "integer" }
]);
let row = (
    accuracy,
    worst,
    d.approximation_error,
    d.roundoff_error,
    d.kernel_support,
    d.grid_points,
    d.stencil_visits,
    times.len() * omegas.len(),
);
emit_table_with_columns!(
    columns,
    vec![row],
    metadata = serde_json::json!({ "id": "accuracy" })
);
```

The largest plotted peak is at the fundamental $1/(0.567\ \text{days})\approx1.764$ day⁻¹, with a second-harmonic peak at twice that frequency and daily aliases spaced 1 day⁻¹ on both sides.
At the defaults $\varepsilon_r=10^{-6}$, $\sigma_o=2$, kernel width is 9, the grid has 1024 points, and the direct-sum difference is $3.2\times10^{-9}$ times the input 1-norm.
Grid count is determined by the product of the time half-width (about 20 days) and angular-frequency half-width (about 11.9 rad/day), rather than being proportional to 240 observations.
At $\varepsilon_r=10^{-12}$, kernel width grows to 15 and total visits from 19269 to 32115, while the grid is unchanged in this example.
At $\sigma_o=3$, kernel width narrows to 8 and the grid grows to 2048 points.
In every case measured error is below estimate $E_a+E_r$ and the request, but this is a result for this configuration and these coefficients; the estimate is not an upper bound.

## Summary

NUFFT approximates exponential sums by spreading onto or interpolating from an oversampled grid with a Kaiser–Bessel kernel, combining FFTs with correction by the kernel's Fourier transform.
Requested accuracy is maximum error relative to the input 1-norm; preparation selects the smallest width whose estimate $E_a+E_r$ is below the request and returns `NumericalInstability` if $E_r$ is at least the requested accuracy.
Increasing oversampling factor $\sigma_o$ narrows the kernel but enlarges the grid; the type-3 grid depends on the product of point and frequency spread.
Because estimates are not upper bounds, compare selected outputs with direct summation in important computations.
