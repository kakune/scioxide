`scioxide-fft` exposes functions and plans computing one-dimensional and multidimensional complex and real discrete Fourier transforms (DFTs) with fast Fourier transforms (FFTs).
It also provides transforms of Hermitian-symmetric samples, type-I–IV discrete cosine (DCT) and sine (DST) transforms, chirp Z-transforms (CZT), nonuniform FFTs (NUFFT), discrete Hankel transforms on Bessel-zero grids, FFTLog on logarithmic grids, frequency-axis and transform-length helpers, and a mechanism for passing external FFT implementations to preparation.
This guide maps tasks to entry points, explains type relationships, and groups all 93 public items by purpose.
Item-name links point to the version 0.1.0 API reference on docs.rs.

## Type relationships

Single-call functions (such as `fft`, `rfft`, `dct`, `czt`, `nufft_type1`, `dht`, and `fht`) prepare a plan per call, execute it once, and return results in a new `Vec`.
Real FFT results are returned as `HermitianSpectrum` (`HermitianSpectrumNd` in multiple dimensions), carrying packed bins and original length.
These functions accept contiguous slices; multidimensional functions accept a shape and a row-major packed slice (last axis varying fastest).

For repeated same-size transforms, strided arrays, or nondefault settings, prepare a plan from a specification (`…Spec` such as `FftPlanSpec`).
The 8 plan types are `FftPlan`, `FftNdPlan`, `RealTransformPlan`, `RealTransformNdPlan`, `CztPlan`, `NufftPlan`, `DiscreteHankelPlan`, and `FftLogPlan`; they write into caller-supplied output (`execute_into`, `execute_in_place`, `execute_axis_into`).
Direction (`FftDirection`), normalization (`Normalization`), and layout (`FftLayout`) are specification values fixed in the plan during preparation, so an inverse requires a separate plan.
Select execution policy and CPU instruction set with specification `with_execution_policy` and `with_backend_strategy`.
`DiscreteHankelPlanSpec` uses no FFT and has no instruction-set selection.

Input/output acceptance differs by plan.
`FftPlan` and `CztPlan`/`NufftPlan` accept input as `FftInput` and output as `FftOutput`; real/complex slices, arrays, `Vec`, `VectorView`, and `&HermitianSpectrum` convert into these and can be passed directly.
CZT and NUFFT reject packed bins and require complex output.
`FftNdPlan` accepts `NdView`/`NdViewMut` converted into `FftNdInput`/`FftNdOutput` and directly handles strided arrays.
`RealTransformPlan` takes real slices, `RealTransformNdPlan` takes real `NdView`/`NdViewMut`, and `DiscreteHankelPlan` and `FftLogPlan` take complex slices.

There are two workspace-passing forms.
`execute_into` on `FftPlan`, `FftNdPlan`, `RealTransformPlan`, and `CztPlan` takes temporary complex storage as `&mut [Complex<S>]`; `FftWorkspace` dereferences to a slice and can be passed directly.
`execute_into` on `NufftPlan`/`DiscreteHankelPlan`/`FftLogPlan` and `execute_axis_into` on CZT/NUFFT/Hankel/FFTLog plans take `&mut FftWorkspace`.
This workspace also holds solve state counting operator evaluations.
`RealTransformNdPlan` uses `RealTransformNdWorkspace` with separate real and complex regions.
`workspace_requirements(request)` returns required sizes; allocate through the plan's `workspace(request)` or workspace's `try_reserve`.
Request `request` is `()` for a single transform and `AxisWorkspaceRequest::Axis { shape, axis }` for CZT/NUFFT/Hankel/FFTLog axis execution.

Ownership and reuse rules are as follows.
Plans retain no preparation context.
`FftPlanningContext` borrows the execution context and external FFT implementation (`FftProvider`) only during preparation.
Clones of `FftPlan` share prepared tables; caller-owned `FftPlanCache` shares tables among plans with equal length, layout category (complex or packed), execution policy, and instruction set.
Prepared plans allocate no storage during execution with sufficiently large workspace.

Component order and units depend on the transform.
`fft` results follow `fftfreq` order (nonnegative frequencies then negative frequencies); `fftshift` moves zero frequency to the center.
Frequency units from `fftfreq` and `rfftfreq` are cycles per unit of sampling interval $d$.
NUFFT modes increase from $-\lfloor N/2\rfloor$ on each axis and use row-major order in multiple dimensions.
Type-3 NUFFT frequencies are angular frequencies in radians per coordinate unit.

## Real FFT round trips and symmetry validation

The DFT of length-4 cosine $x = (1, 0, -1, 0)$ is $X = (0, 2, 0, 2)$; `rfft` returns 3 nonnegative-frequency bins $(0, 2, 0)$ with logical length 4.
Logical length is the unpacked sequence length; lengths 4 and 5 both pack to 3 bins, so the inverse uses it to determine output length.

The following cell takes a round trip through `rfft` and `irfft`, comparing bins with analytic values and reconstructed output with the original sequence.
It then constructs a spectrum with `HermitianSpectrum::from_vec` after adding the input-selected imaginary part to DC and passes it to `irfft`.
Setting $k = 0$ in Hermitian symmetry $X_{n-k} = \overline{X_k}$ gives $X_0 = \overline{X_0}$, so the DC bin must be real, allowing only rounding-scale imaginary values.
Tolerance is $\tau = \max(8\varepsilon M, \eta)$, where $M$ is the maximum absolute real or imaginary spectral component, $\varepsilon = 2^{-52}$ machine epsilon, and $\eta$ the smallest positive subnormal number.
The cell manually computes this $\tau$ and shows it beside the `irfft` decision.
Beyond tolerance, `irfft` returns an error, whose classification the cell reads with `e.kind()`.
Within tolerance, `irfft` zeroes the imaginary part in a workspace copy before transformation, so the result should match the unperturbed round trip.

```rust
//| id: fft-api-real-roundtrip
//| ref: fft-api-real-roundtrip
//| title: "Real FFT round trip and DC-bin symmetry validation"
//| run: reactive
//| crates: [scioxide-core, scioxide-fft]
//| inputs:
//|   dc_imag: {"type":"select","label":"Imaginary part added to DC [-]","description":"irfft returns InvalidInput above tolerance τ = 8εM ≈ 3.55e-15.","options":["1e-3","1e-14","1e-16"],"value":"1e-3"}
//| cases:
//|   - {"id":"just-above","label":"Imaginary part 1e-14","description":"About 3 times tolerance τ; even a slight excess is rejected.","inputs":{"dc_imag":"1e-14"}}
//|   - {"id":"within","label":"Imaginary part 1e-16","description":"Below tolerance τ, the imaginary part is zeroed before transformation, matching the unperturbed round trip.","inputs":{"dc_imag":"1e-16"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"bins","path":"/rows/1/1","approx":{"value":2,"atol":1e-15}}
//|       - {"artifact":"bins","path":"/rows/1/4","range":{"max":1e-15}}
//|       - {"artifact":"summary","path":"/rows/0/0","approx":{"value":4,"atol":0.5}}
//|       - {"artifact":"summary","path":"/rows/0/1","approx":{"value":3,"atol":0.5}}
//|       - {"artifact":"summary","path":"/rows/0/3","range":{"max":1e-15}}
//|       - {"artifact":"perturbed","path":"/rows/0/1","approx":{"value":3.552713678800501e-15,"rtol":1e-12}}
//|       - {"artifact":"perturbed","path":"/rows/0/2","equals":"InvalidInput"}
//|       - {"artifact":"perturbed","path":"/rows/0/3","equals":null}
//|   - case: just-above
//|     expect:
//|       - {"artifact":"perturbed","path":"/rows/0/0","approx":{"value":1e-14,"rtol":1e-12}}
//|       - {"artifact":"perturbed","path":"/rows/0/2","equals":"InvalidInput"}
//|   - case: within
//|     expect:
//|       - {"artifact":"perturbed","path":"/rows/0/2","equals":"Accepted"}
//|       - {"artifact":"perturbed","path":"/rows/0/3","range":{"max":0}}
use scioxide_core::Complex;
use scioxide_fft::{HermitianSpectrum, Normalization, irfft, rfft};

let dc_imag: f64 = dc_imag
    .parse()
    .map_err(|e: std::num::ParseFloatError| e.to_string())?;
// Period-4 cosine x = (1, 0, −1, 0). Inverse normalization leaves the forward transform unscaled.
let input = [1.0_f64, 0.0, -1.0, 0.0];
let spectrum = rfft(&input, Normalization::Inverse).map_err(|e| e.to_string())?;
// Reconstruct a real sequence from bins of logical length 4. The inverse applies 1/4.
let output = irfft(&spectrum, Normalization::Inverse).map_err(|e| e.to_string())?;
// Independent check: the 3 nonnegative-frequency bins of analytic DFT X = (0, 2, 0, 2).
let expected = [0.0, 2.0, 0.0];
let bins: Vec<(usize, f64, f64, f64, f64)> = spectrum
    .bins()
    .iter()
    .zip(expected)
    .enumerate()
    .map(|(k, (z, x))| (k, z.re, z.im, x, (*z - Complex::new(x, 0.0)).norm()))
    .collect();
let bin_error = bins.iter().map(|row| row.4).fold(0.0_f64, f64::max);
// Maximum round-trip difference. f64 abs and max are used only for reference calculations.
let max_difference = |a: &[f64], b: &[f64]| {
    a.iter()
        .zip(b)
        .map(|(x, y)| (x - y).abs())
        .fold(0.0_f64, f64::max)
};
let roundtrip = max_difference(&input, &output);

// Add an imaginary part to DC. from_vec checks only bin count; irfft checks symmetry.
let mut perturbed = spectrum.clone().into_vec();
perturbed[0].im += dc_imag;
// Independent check: manually compute tolerance τ = max(8εM, η), where M is the maximum absolute real or imaginary component.
let mass = perturbed
    .iter()
    .map(|z| z.re.abs().max(z.im.abs()))
    .fold(0.0_f64, f64::max);
let tau = (8.0 * f64::EPSILON * mass).max(f64::from_bits(1));
let perturbed = HermitianSpectrum::from_vec(4, perturbed).map_err(|e| e.to_string())?;
// Report the classification if rejected, or the difference from the unperturbed round trip if accepted.
let (verdict, deviation) = match irfft(&perturbed, Normalization::Inverse) {
    Ok(values) => ("Accepted".to_string(), Some(max_difference(&values, &output))),
    Err(e) => (format!("{:?}", e.kind()), None),
};

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let fixed2 = serde_json::json!({ "fractionDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "Bin k", "type": "integer" },
    { "key": "1", "label": "Re X_k [-]", "type": "number", "format": fixed2 },
    { "key": "2", "label": "Im X_k [-]", "type": "number", "format": fixed2 },
    { "key": "3", "label": "Analytic value [-]", "type": "number", "format": fixed2 },
    { "key": "4", "label": "Difference from analytic value [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    bins,
    metadata = serde_json::json!({ "id": "bins" })
);
let columns = serde_json::json!([
    { "key": "0", "label": "Logical length n", "type": "integer" },
    { "key": "1", "label": "Bin count", "type": "integer" },
    { "key": "2", "label": "Maximum bin difference from analytic values [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "Maximum round-trip difference [-]", "type": "number", "format": sci3 }
]);
let summary = vec![(spectrum.logical_len(), spectrum.len(), bin_error, roundtrip)];
emit_table_with_columns!(
    columns,
    summary,
    metadata = serde_json::json!({ "id": "summary" })
);
let columns = serde_json::json!([
    { "key": "0", "label": "DC imaginary part [-]", "type": "number", "format": sci3 },
    { "key": "1", "label": "Tolerance τ [-]", "type": "number", "format": sci3 },
    { "key": "2", "label": "irfft result" },
    { "key": "3", "label": "Difference from unperturbed round trip [-]", "type": "number", "format": sci3, "nullText": "Rejected" }
]);
let rows = vec![(dc_imag, tau, verdict, deviation)];
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "perturbed" })
);
```

The first table shows `rfft` bins matching analytic values $(0, 2, 0)$.
The second table gives logical length 4, bin count $\lfloor 4/2\rfloor + 1 = 3$, and zero round-trip difference (this input introduces no rounding error).
The third table's tolerance is $\tau = 16\varepsilon \approx 3.55\times 10^{-15}$ for $M = 2$.
Default imaginary part $10^{-3}$ and $10^{-14}$ exceed $\tau$, so `irfft` returns `InvalidInput`.
$10^{-16}$ is within tolerance and accepted, giving zero difference from the unperturbed round trip.
An imaginary part above tolerance cannot be explained by rounding, so `scioxide-fft` reports invalid input rather than setting it to 0.

## Reading results, errors, and diagnostics

Failures return `scioxide_core::SciOxideError`.
Read classifications with `kind()` and arguments and details with `view()`.
The main classifications in this chapter are as follows.

| Classification | Main causes |
|---|---|
| `InvalidInput` | Zero one-dimensional transform length or selected-axis length, length-1 DCT-I, Hermitian-symmetry violation beyond tolerance, duplicate axes, empty selected-axis sequence for real/Hermitian layouts, `FftInput`/`FftOutput` variants incompatible with plan layout, out-of-range specification values (NUFFT accuracy, Hankel order, nonpositive spacing, and others), instruction set unavailable from the context, or a length declined by an external implementation (`FftProviderPolicy::Required`) |
| `OutOfBounds` | Axis index at least equal to array rank |
| `DimensionMismatch` | Incompatible input/output/view shape or length, logical length, insufficient workspace, or mismatch between Hankel zero and sample counts |
| `NonFinite` | NaN/infinite input or specification (origin `Input`), or NaN/infinite external-implementation output (origin `Callback`) |
| `NumericalInstability` | Output overflow from finite input (`Overflow`), failed internal rounding check in packed real transforms (`Breakdown`), nonzero prepared coefficient rounding to 0 (`Underflow`), or NUFFT accuracy request stricter than the rounding estimate |
| `Singular` | FFTLog execution encounters a multiplier pole (forward) or zero (inverse), depending on direction |
| `ConvergenceFailure` | Hankel/FFTLog preparation work limit or execution iteration limit reached |
| `ScalarConversion` | `fftfreq`/`rfftfreq` length or index not exactly representable in the scalar type, or indistinguishable adjacent frequencies |
| `ResourceLimit`, `AllocationFailure`, `SizeOverflow` | Configured byte or other limit exceeded, allocation failure, or size-computation overflow |
| `ExecutionStopped` | Execution-context cancellation or deadline |

Length 0 is accepted in some contexts and rejected in others.
Zero one-dimensional transform length or selected multidimensional-axis length gives `InvalidInput`.
In contrast, unselected length-0 axes (empty batches), length-0 axes in `fftshift_nd`, `fftshift` on empty input, and NUFFT with 0 points (empty sums are 0) are accepted.

Plans write output only after all checks and computations succeed.
Failure leaves output unchanged; even success leaves elements outside the view, such as stride gaps, unchanged.
Axis execution writes all sequences together only after every sequence succeeds.
Single-call functions prepare plans and allocate results within each call.

Accuracy information has different meanings for different transforms.
Relative 2-norm error $2\varepsilon\max(1, \log_2 n)$ for built-in forward complex and packed real FFTs is accuracy verified by tests against high-precision reference DFTs, not a proven upper bound.
Because it is normwise, bins much smaller than the largest bin can have large relative errors.
This accuracy does not apply to external implementations.
`CztPlan` (Bluestein with the built-in FFT) and `DiscreteHankelPlan` specify componentwise rounding bounds.
NUFFT errors in `NufftDiagnostics` are estimates, not certified error enclosures.
FFTLog `FftLogDiagnostics` reports the spread of multiplier magnitudes and preparation work, without an error assessment.
Round-trip agreement checks only inversion of discrete maps; investigate continuous-integral approximation accuracy separately.

`FftPlan::diagnostics()` returns the selected algorithm and stage count; `CztPlan::algorithm()` returns the CZT algorithm.
`plan_bytes()` returns retained plan bytes; `resolved_backends()` returns the actual child FFT implementations.
This iterator is empty for plans without child FFTs, such as direct-sum CZT or discrete Hankel transforms.
NUFFT, discrete Hankel, and FFTLog `execute_into` and their `execute_axis_into` with at least one sequence count one operator evaluation through `SolveScope`.
Discrete Hankel transforms and FFTLog additionally count $n$ iterations per sequence, limited by specification `with_iteration_budget`.
CZT `execute_axis_into` counts neither evaluations nor iterations.

## Summary

Choose transform type and normalization, using single-call functions for one-off work or preparing a plan from its specification and using it with workspace for repeated work.
Carry real-FFT packed bins with logical length (shape and axes in multiple dimensions) in `HermitianSpectrum`/`HermitianSpectrumNd`; inverse transforms check DC/Nyquist symmetry against tolerance $\max(8\varepsilon M, \eta)$.
Classify failures with `kind()`.
Plans preserve output on failure, leaving previous values in place afterward.
Assess result reliability by distinguishing tested FFT accuracy, componentwise rounding bounds for CZT (Bluestein) and discrete Hankel transforms, and NUFFT diagnostic estimates.
