## External FFT implementations and preparation contexts

| Item | Kind | Role | Contract essentials | Explanation | Executable example |
|---|---|---|---|---|---|
| [`FftPlanningContext`](https://docs.rs/scioxide-fft/0.1.0/scioxide_fft/struct.FftPlanningContext.html) | Struct | Borrowed preparation capabilities | Converts from `ExecutionContext`, then uses no external implementation. `Default` is `ExecutionContext::sequential_native`. `with_provider(execution, provider, policy)`, `with_provider_limits` (limits can only be lowered), `execution()`. Plans do not retain the context | [Injecting an external FFT implementation](oxref:fft-providers), [CPU instruction sets and execution policies](oxref:fft-execution-environment), [Plan preparation and ownership](oxref:fft-plan-preparation) | [Examine how external-implementation policy and limits change preparation results](oxref:fft-provider-fallback) |
| [`FftProvider`](https://docs.rs/scioxide-fft/0.1.0/scioxide_fft/trait.FftProvider.html) | Trait | External FFT plan preparation | `prepare` prepares unscaled transforms in both directions for each length. `Ok(None)` declines a length; `FftProviderPolicy` decides CPU fallback. Errors propagate directly without CPU fallback | [Injecting an external FFT implementation](oxref:fft-providers), [Plans and workspaces](oxref:fft-plans-and-workspaces) | [Examine how external-implementation policy and limits change preparation results](oxref:fft-provider-fallback) |
| [`FftProviderPlan`](https://docs.rs/scioxide-fft/0.1.0/scioxide_fft/trait.FftProviderPlan.html) | Trait | Prepared external transform | Computes unscaled complex DFTs in place using the declared temporary-storage length. SciOxide handles normalization, power-of-2 scaling, and output NaN/infinity checks. Implementations must neither allocate nor mutate state during execution. `preparation_bytes` below `plan_bytes` gives `InvalidInput` during preparation. `workspace_len`, `plan_bytes`, `preparation_bytes`, `diagnostics`, `execute` | [Injecting an external FFT implementation](oxref:fft-providers), [SciOxide checks and implementer responsibilities](oxref:fft-provider-contract) | [Examine how external-implementation policy and limits change preparation results](oxref:fft-provider-fallback) |
| [`FftProviderPolicy`](https://docs.rs/scioxide-fft/0.1.0/scioxide_fft/enum.FftProviderPolicy.html) | Enum | External-implementation usage | `Preferred` (CPU implementation for declined lengths) and `Required` (declined lengths give `InvalidInput` (`UnsupportedConfiguration`) during preparation) | [Injecting an external FFT implementation](oxref:fft-providers), [SciOxide checks and implementer responsibilities](oxref:fft-provider-contract) | [Examine how external-implementation policy and limits change preparation results](oxref:fft-provider-fallback) |
| [`FftProviderLimits`](https://docs.rs/scioxide-fft/0.1.0/scioxide_fft/struct.FftProviderLimits.html) | Struct | External preparation and workspace byte limits | `preparation_bytes` and `workspace_bytes` (default `usize::MAX`). Providers respect limits before allocation; SciOxide checks reported sizes after preparation and returns `ResourceLimit` on excess | [Resource limits](oxref:fft-provider-limits) | [Examine how external-implementation policy and limits change preparation results](oxref:fft-provider-fallback) |
| [`FftBackend`](https://docs.rs/scioxide-fft/0.1.0/scioxide_fft/enum.FftBackend.html) | Enum | Actual FFT implementation | `Cpu(KernelBackend)` and `Provider`. Each plan's `resolved_backends()` returns one per contained complex FFT | [CPU instruction sets and execution policies](oxref:fft-execution-environment), [Plan diagnostics](oxref:fft-plan-diagnostics), [Injecting an external FFT implementation](oxref:fft-providers) | [Examine how external-implementation policy and limits change preparation results](oxref:fft-provider-fallback) |
