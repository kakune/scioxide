The discrete cosine transform (DCT), central to image compression such as JPEG, helps represent blocks of similar neighboring pixel values with a few low-frequency coefficients.
The DFT assumes periodic boundaries, treating differences between a block's left and right edges as a jump that produces high-frequency components.
DCT-II corresponds to an even extension whose values join continuously at the endpoints, avoiding such jumps.

This example transforms a $8\times8$-pixel block with `dctn`, retains only $K$ low-frequency coefficients, and reconstructs with `idctn`.
It checks from Parseval's identity that total squared reconstruction error equals discarded coefficient energy, and compares coefficients themselves with the defining sum.

## Even extension and energy concentration

The orthonormal one-dimensional DCT-II of length $N$ is

$$
C_k = \alpha_k\sum_{n=0}^{N-1} x_n\cos\left[\frac{\pi}{N}\left(n + \frac{1}{2}\right)k\right], \qquad
\alpha_0 = \sqrt{\frac{1}{N}},\quad \alpha_k = \sqrt{\frac{2}{N}}\ (k \ge 1)
$$

as above.
In `scioxide-fft`, DCT-II with `Normalization::Orthonormal` matches this definition ([Definitions and scales of the 4 types](oxref:fft-dct-types)).
The DCT-II basis corresponds to the Fourier series of a sequence reflected about a half-pixel-shifted position and extended to length $2N$.
Since reflected extensions join continuously in value, high-frequency coefficients tend to be smaller than in a DFT whose periodic extension has a value jump.
Coefficient decay still depends on smoothness of values and derivatives and is not uniform across arbitrary images.

DC coefficient $C_0=\sqrt{1/N}\sum_nx_n=\sqrt N\,\bar x$ is proportional to average block brightness.
Coefficients at $k\ge1$ describe brightness stripes with increasingly many zero crossings as $k$ grows.
For smoothly varying blocks, constant and slowly varying basis functions carry most energy; a constant block has only a nonzero DC coefficient.
Blocks containing jumps or fine patterns also need high-frequency coefficients.

## Separability of the two-dimensional transform

The two-dimensional DCT-II of an $N\times N$ block $X$ can be written using products of one-dimensional bases as

$$
C_{vu} = \alpha_u\alpha_v\sum_{y=0}^{N-1}\sum_{x=0}^{N-1} X_{yx}\cos\left[\frac{\pi}{N}\left(x + \frac{1}{2}\right)u\right]\cos\left[\frac{\pi}{N}\left(y + \frac{1}{2}\right)v\right]
$$

above ($u$ is horizontal and $v$ vertical frequency).
Writing the one-dimensional orthogonal DCT-II matrix as $A$ gives $C=AXA^\mathsf{T}$: apply the one-dimensional transform to each row, then each column.
`dctn` takes a row-major slice and shape, applies the specified transform type on each selected axis, and returns a new `Vec` of the same shape.
In a row-major $8\times8$ array, axis 0 is vertical and axis 1 horizontal; pass shape `&[8, 8]`, axes `&[0, 1]`, and types `&[DctType::II, DctType::II]`.
Pass the forward-transform type to invert (II here) to `idctn`; internally it executes DCT-III.
For many blocks of the same shape, create `RealTransformNdPlan` once and reuse the workspace.

## Parseval's identity and truncation error

Since $A$ is orthogonal, $C=AXA^\mathsf{T}$ preserves the Frobenius norm (square root of the sum of squared entries).

$$
\lVert X\rVert_F^2 = \sum_{y,x} X_{yx}^2 = \sum_{v,u} C_{vu}^2 = \lVert C\rVert_F^2
$$

Retaining coefficients only on frequency-index set $S$, setting others to 0 to form $\hat C$, and reconstructing $\hat X=A^\mathsf{T}\hat CA$ makes total squared error equal discarded coefficient energy.

$$
\lVert X - \hat X\rVert_F^2 = \lVert C - \hat C\rVert_F^2 = \sum_{(u, v)\notin S} C_{vu}^2
$$

Pixel mean squared error is $\mathrm{MSE}=\frac{1}{N^2}\sum_{(u,v)\notin S}C_{vu}^2$; for pixel range $[0,1]$, peak signal-to-noise ratio is $\mathrm{PSNR}=-10\log_{10}\mathrm{MSE}$ [dB].
For a fixed retained count $K$, retaining the $K$ largest-magnitude coefficients minimizes MSE.
Compression avoids encoding retained coefficient positions by scanning in increasing $u+v$ order (a low-frequency-first order close to JPEG zigzag scanning).

## Truncation experiment

The following cell transforms a synthetic $8\times8$ image combining a horizontal linear gradient, a slowly varying vertical cosine, and a diagonal jump at $x+y\ge8$ (height $0.25c$), then reconstructs retaining $K$ coefficients in $(u+v,v,u)$ order.
It plots original and reconstructed images on the same color range, a signed-error heatmap, and discarded coefficient energy ratio against $K$ on a logarithmic vertical axis.
The first table reports MSE, PSNR, and maximum pixel error.
The second reports discarded coefficient energy (the Parseval prediction), measured total squared error, relative difference between image and coefficient sums of squares, and maximum coefficient difference from the defining double sum.
The defining sum is an independent reference computation using `f64` cosine.
At $K=64$ no coefficients are discarded, so the ratio curve shows only $K\le63$.

```rust
//| id: fft-dct-image-compression
//| ref: fft-dct-image-compression
//| title: "DCT coefficient truncation and image reconstruction"
//| run: reactive
//| crates: [scioxide-fft]
//| inputs:
//|   retained_coefficients: {"type":"range","label":"Retained DCT coefficients K [count]","description":"Number of coefficients retained from low frequencies (in increasing u + v order), up to 64.","min":1,"max":64,"step":1,"value":12}
//|   edge_contrast: {"type":"range","label":"Diagonal-jump contrast c [-]","description":"Change jump height 0.25c.","min":0,"max":1,"step":0.05,"value":0.55}
//| cases:
//|   - {"id":"dc-only","label":"K = 1","description":"Retain only DC, making the block uniformly equal to its mean brightness.","inputs":{"retained_coefficients":1}}
//|   - {"id":"all-coefficients","label":"K = 64","description":"Retain every coefficient, reducing error to rounding level.","inputs":{"retained_coefficients":64}}
//|   - {"id":"no-edge","label":"c = 0","description":"Smooth block without a jump. Error is over one order of magnitude smaller at the same K.","inputs":{"edge_contrast":0}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":12}
//|       - {"artifact":"summary","path":"/rows/0/1","approx":{"value":0.9963,"atol":5e-4}}
//|       - {"artifact":"summary","path":"/rows/0/3","approx":{"value":30.6,"atol":0.1}}
//|       - {"artifact":"checks","path":"/rows/0/0","approx":{"value":0.05555,"rtol":1e-3}}
//|       - {"artifact":"checks","path":"/rows/0/2","range":{"max":1e-14}}
//|       - {"artifact":"checks","path":"/rows/0/3","range":{"max":1e-13}}
//|   - case: dc-only
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/3","approx":{"value":14.7,"atol":0.1}}
//|   - case: all-coefficients
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/4","range":{"max":1e-14}}
//|       - {"artifact":"checks","path":"/rows/0/0","equals":0}
//|   - case: no-edge
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/3","approx":{"value":47.0,"atol":0.1}}
use scioxide_fft::{DctType, Normalization, dctn, idctn};

let side = 8_usize;
let keep = retained_coefficients as usize;
let pi = std::f64::consts::PI;
// 8×8 synthetic image (row-major [y, x]): horizontal gradient + slowly varying vertical cosine + diagonal jump at x + y ≥ 8.
let mut image = Vec::with_capacity(side * side);
for y in 0..side {
    for x in 0..side {
        let smooth = 0.18 + 0.42 * x as f64 / 7.0 + 0.10 * (pi * y as f64 / 7.0).cos();
        let edge = if x + y >= side {
            0.25 * edge_contrast
        } else {
            0.0
        };
        image.push(smooth + edge);
    }
}
let (shape, axes, types) = ([side, side], [0, 1], [DctType::II, DctType::II]);
// Two-dimensional orthogonal DCT-II (axis 0 = vertical v, axis 1 = horizontal u).
let coefficients = dctn(&image, &shape, &axes, &types, Normalization::Orthonormal)
    .map_err(|e| e.to_string())?;
// Independent check: defining double sum C_vu = α_u α_v Σ X_yx cos(π(x+½)u/N) cos(π(y+½)v/N).
let alpha = |k: usize| if k == 0 { (1.0 / 8.0_f64).sqrt() } else { 0.5 };
let basis = |k: usize, n: usize| (pi * (n as f64 + 0.5) * k as f64 / side as f64).cos();
let mut direct_difference = 0.0_f64;
for v in 0..side {
    for u in 0..side {
        let sum: f64 = (0..side * side)
            .map(|i| image[i] * basis(u, i % side) * basis(v, i / side))
            .sum();
        let difference = (alpha(u) * alpha(v) * sum - coefficients[v * side + u]).abs();
        direct_difference = direct_difference.max(difference);
    }
}
// Sort by (u + v, v, u) and retain K coefficients from low frequencies.
let mut order: Vec<(usize, usize)> = (0..side)
    .flat_map(|v| (0..side).map(move |u| (u, v)))
    .collect();
order.sort_by_key(|&(u, v)| (u + v, v, u));
let energies: Vec<f64> = order
    .iter()
    .map(|&(u, v)| coefficients[v * side + u].powi(2))
    .collect();
let total: f64 = energies.iter().sum();
let mut truncated = vec![0.0; side * side];
for &(u, v) in order.iter().take(keep) {
    truncated[v * side + u] = coefficients[v * side + u];
}
// Pass forward type II to the inverse (which executes DCT-III).
let reconstructed = idctn(
    &truncated,
    &shape,
    &axes,
    &types,
    Normalization::Orthonormal,
)
.map_err(|e| e.to_string())?;
let differences: Vec<f64> = reconstructed
    .iter()
    .zip(&image)
    .map(|(r, o)| r - o)
    .collect();
let squared_error: f64 = differences.iter().map(|d| d * d).sum();
let maximum_error = differences.iter().fold(0.0_f64, |m, d| m.max(d.abs()));
let image_energy: f64 = image.iter().map(|x| x * x).sum();
let mse = squared_error / (side * side) as f64;
// Discarded coefficient energy (sum backward to avoid cancellation in 1 − cumulative ratio).
let tails: Vec<f64> = (0..=side * side)
    .map(|k| energies[k..].iter().sum())
    .collect();
let discarded = tails[keep];
let psnr = (mse > 0.0).then(|| -10.0 * mse.log10());
let fraction: Vec<[f64; 2]> = (1..side * side)
    .filter(|&k| tails[k] > 0.0)
    .map(|k| [k as f64, tails[k] / total])
    .collect();

let map = |values: &[f64]| {
    (0..side * side)
        .map(|i| [(i % side) as f64, (i / side) as f64, values[i]])
        .collect::<Vec<_>>()
};
// Plot original and reconstructed images on the same color range [0, 1], comparing color differences as brightness differences.
let picture = |values: &[f64], title: &str| {
    serde_json::json!({
        "kind": "heatmap",
        "data": map(values),
        "xLabel": "Column x [pixels]",
        "yLabel": "Row y [pixels]",
        "colorMin": 0.0,
        "colorMax": 1.0,
        "tooltip": true,
        "style": { "animation": false, "showGrid": false },
        "title": title
    })
};
emit_chart!(picture(&image, "Original image"));
emit_chart!(picture(&reconstructed, "Reconstructed image"));
// Signed errors use a diverging color scale centered at 0.
emit_chart!(serde_json::json!({
    "kind": "heatmap",
    "data": map(&differences),
    "xLabel": "Column x [pixels]",
    "yLabel": "Row y [pixels]",
    "title": "Signed error (reconstructed − original)",
    "colorScale": "diverging",
    "center": 0.0,
    "colorMin": -0.5,
    "colorMax": 0.5,
    "tooltip": true,
    "style": { "animation": false, "showGrid": false }
}));
emit_line_chart!(
    &vec![serde_json::json!({
        "name": "Discarded coefficient energy ratio",
        "points": fraction,
        "style": { "symbol": "circle", "showSymbol": true }
    })],
    options = &serde_json::json!({
        "xLabel": "Retained coefficients K [count]",
        "yLabel": "Discarded coefficient energy / total energy [-]",
        "yType": "log",
        "xMin": 1.0,
        "xMax": 64.0,
        "annotations": [{ "kind": "line", "axis": "x", "value": keep as f64, "label": "Selected K" }]
    })
);
let fixed4 = serde_json::json!({ "significantDigits": 4 });
let fixed3 = serde_json::json!({ "significantDigits": 3 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let summary_columns = serde_json::json!([
    { "key": "0", "label": "K [count]", "type": "integer" },
    { "key": "1", "label": "Retained energy ratio [-]", "type": "number", "format": fixed4 },
    { "key": "2", "label": "MSE [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "PSNR [dB]", "type": "number", "format": fixed3, "nullText": "∞ (zero error)" },
    { "key": "4", "label": "Maximum pixel error [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    summary_columns,
    vec![(keep, 1.0 - discarded / total, mse, psnr, maximum_error)],
    metadata = serde_json::json!({ "id": "summary" })
);
let check_columns = serde_json::json!([
    { "key": "0", "label": "Discarded coefficient energy [-]", "type": "number", "format": sci3 },
    { "key": "1", "label": "Total squared error [-]", "type": "number", "format": sci3 },
    { "key": "2", "label": "Relative Parseval difference [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "Maximum difference from defining sum [-]", "type": "number", "format": sci3 }
]);
let parseval = ((image_energy - total) / total).abs();
emit_table_with_columns!(
    check_columns,
    vec![(discarded, squared_error, parseval, direct_difference)],
    metadata = serde_json::json!({ "id": "checks" })
);
```

At the defaults $K=12$, $c=0.55$, retained coefficients contain 99.63% of total energy; MSE is $8.68\times10^{-4}$ (PSNR 30.6 dB) and maximum pixel error 0.070.
Discarded coefficient energy and total squared error are both $5.555\times10^{-2}$, agreeing to displayed precision.
The relative difference between image and coefficient sums of squares is $8\times10^{-16}$, and the defining-sum difference is $6\times10^{-15}$, both at rounding level.

Removing the jump ($c=0$) at the same $K=12$ raises the retained energy ratio to 0.99989 and PSNR to 47.0 dB.
At $c=1$, PSNR falls to 25.5 dB.
At $K=1$, only DC remains, giving retained energy ratio 0.856 and PSNR 14.7 dB.
At $K=64$, every coefficient is retained, leaving maximum pixel error $3.3\times10^{-16}$ from rounding alone; PSNR 318 dB merely reflects rounding magnitude.

Discarded energy ratio decreases with $K$, but more slowly when a jump is present.
Representing the jump also needs coefficients with large $u+v$, which a low-frequency-first scan discards until $K$ becomes large.

## Error shape and blocking artifacts

At $K=1$ the block is uniformly equal to its mean brightness.
Increasing $K$ to around 3–6 recovers broad gradients, but leaves Gibbs-like ripples near the diagonal jump.
Higher jump contrast requires higher-frequency coefficients to represent it, increasing MSE and maximum pixel error at the same $K$.

Dividing a whole image into $8\times8$ blocks and truncating them independently can give neighboring blocks inconsistent means or gradients, producing visible jumps at block boundaries.
These are called blocking artifacts.
Image and video coding suppresses them by smoothing block boundaries or using transforms with bases overlapping neighboring blocks.

## Truncation and quantization

This example idealizes truncation by retaining selected coefficients in double precision and setting the rest to 0.
Actual coding quantizes coefficients with frequency-dependent step sizes $Q_{vu}$.

$$
\tilde{C}_{vu} = \mathrm{round}\left(\frac{C_{vu}}{Q_{vu}}\right), \qquad \hat{C}_{vu} = \tilde{C}_{vu}\,Q_{vu}
$$

Human vision is less sensitive to brightness changes at high spatial frequencies, so JPEG's standard quantization table assigns small $Q_{vu}$ to low frequencies and large $Q_{vu}$ to high frequencies.
Many high-frequency coefficients then become 0, allowing compact downstream Huffman or arithmetic coding.
For quantization error too, orthogonality equates total squared pixel error with squared coefficient error, so MSE can be computed from coefficients.

## Summary

The two-dimensional DCT-II is a product of one-dimensional row and column transforms; pass shape, axes, and types to `dctn` to compute it in one call.
Pass the forward-transform type to inverse `idctn`.
An orthonormal DCT preserves the Frobenius norm, so total squared error after discarding coefficients equals discarded energy, agreeing at rounding level in this example.
Smooth blocks concentrate energy in a few low-frequency coefficients; blocks with jumps require high-frequency coefficients.
