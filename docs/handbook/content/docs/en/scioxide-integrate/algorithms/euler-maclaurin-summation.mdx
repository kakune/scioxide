If the terms sample a smooth function, $a_n = f(n)$, and the integral and derivatives of $f$ can be supplied analytically, the series remainder can be bounded above rather than estimated empirically.
This page explains tail evaluation with the Euler–Maclaurin formula and the conditional upper bound returned by `SeriesMethod::EulerMaclaurin` in `SeriesSummation`.
The Plan, state, workspace, and report contracts are shared by all three methods and are collected in [Infinite series acceleration (Levin u and Wynn ε)](oxref:integrate-series-plan-state).

---

## Euler–Maclaurin formula for the tail

If $f$ is $2p$ times continuously differentiable on $[n, N]$, repeated integration by parts with the periodic Bernoulli function $\tilde B_m(x)$ (Bernoulli polynomial $B_m(x - \lfloor x\rfloor)$) gives

$$
\sum_{k=n}^{N} f(k) = \int_n^N f(x)\,dx + \frac{f(n) + f(N)}{2} + \sum_{j=1}^{p} \frac{B_{2j}}{(2j)!}\Bigl(f^{(2j-1)}(N) - f^{(2j-1)}(n)\Bigr) - \int_n^N \frac{\tilde B_{2p}(x)}{(2p)!} f^{(2p)}(x)\,dx
$$


Here $B_{2j}$ are Bernoulli numbers; this is the same formula as the trapezoidal error expansion in [Euler–Maclaurin expansion and Romberg extrapolation](../romberg-extrapolation/).
If $f$ and its odd derivatives tend to 0 as $N \to \infty$ and $f^{(2p)}$ is absolutely integrable, the sum from $n$ onward is

$$
\sum_{k=n}^{\infty} f(k) = \int_n^{\infty} f(x)\,dx + \frac{f(n)}{2} - \sum_{j=1}^{p} \frac{B_{2j}}{(2j)!} f^{(2j-1)}(n) + R_p, \qquad
|R_p| \le \frac{|B_{2p}|}{(2p)!} \int_n^{\infty} \bigl|f^{(2p)}(x)\bigr|\,dx
$$


The remainder bound follows from the property $|\tilde B_{2p}(x)| \le |B_{2p}|$ of the periodic Bernoulli function.
The estimate adds this right-hand side to the partial sum below $n$, and the remainder bound can be evaluated analytically.

The Euler–Maclaurin expansion is asymptotic, rather than a convergent series.
Since $B_{2j}/(2j)! \approx 2(-1)^{j+1}/(2\pi)^{2j}$, for example, the correction terms for $f(x) = x^{-s}$ have magnitude about $2n^{1-s}(s)_{2j-1}/(2\pi n)^{2j}$ ($(s)_m = s(s+1)\cdots(s+m-1)$ is the rising factorial).
The ratio of adjacent correction terms is about $(s + 2j - 1)(s + 2j)/(2\pi n)^2$, so increasing $j$ makes them start growing when $j$ exceeds approximately $\pi n - s/2$.
At fixed $n$, increasing the correction order $p$ cannot reduce the error indefinitely; using a large $p$ requires increasing the number $n$ of explicitly summed terms.

## Provider and assumptions

In addition to the term `term` (`SeriesTerms`), `EulerMaclaurinProvider` supplies the tail integral `tail_integral` and odd derivatives `odd_derivative` (each with a value and absolute error bound), and an upper bound `even_derivative_l1_bound` on the $L^1$ norm of an even derivative.
Each term requires $p + 3$ provider calls: the term, tail integral, $p$ odd derivatives, and one upper bound.
Set the correction order $p$ in the range 1–12 with `SeriesOptions::with_order`.
The user is responsible for ensuring that $f$ extends smoothly on $[n, \infty)$, its odd derivatives tend to 0 at infinity, and $f^{(2p)}$ is absolutely integrable.
SciOxide does not verify these assumptions.
Negative or non-finite returned error bounds give `InvalidInput`.

---

## Error breakdown and stopping

`SeriesError` separately returns `provider`, the supplied errors weighted by Bernoulli coefficients; `tail_bound`, the remainder upper bound; and `roundoff`, the floating-point error floor.
If their sum is at most the tolerance, computation stops with `BoundedTailReached`.
Among states for which `is_success()` is true, this is the only one accompanied by a remainder bound (the others are `ExactEmpty` for terms without components and `HeuristicToleranceReached` for acceleration).
This bound holds only if the user-supplied smoothness, decay, and derivative values are correct.
The floating-point error floor sums $64\varepsilon$ times the absolute value of each summand forming the estimate (the rounded partial sum, tail integral, half-term, and each correction); a tolerance below this floor cannot be reached.
Reaching the term limit terminates with `TermLimit`, returning the last estimate and upper bound.
Euler–Maclaurin providers are always evaluated sequentially.

## Euler–Maclaurin summation of ζ(s)

Compute $\zeta(s) = \sum_{n\ge1} n^{-s}$ by supplying the derivatives $f^{(m)}(x) = (-1)^m (s)_m\,x^{-s-m}$ of $f(x) = x^{-s}$ analytically ($(s)_m$ is the rising factorial).
Since $f^{(2p)} > 0$, $\int_n^\infty |f^{(2p)}|\,dx = (s)_{2p}\,n^{1-s-2p}/(s + 2p - 1)$.
Provider values use `RealScalar::powf`, and supplied errors are set to the rounding scale $64\varepsilon|\text{value}|$.
Use `scioxide_special::riemann_zeta` as an independent reference.

The following definitions block supplies the provider for both cells on this page.
`rising` corresponds to the rising factorial $(s)_m$; `PowerLaw` supplies the term $n^{-s}$ (`SeriesTerms`), tail integral, odd derivatives, and $L^1$-norm upper bound (`EulerMaclaurinProvider`).

```rust
//| id: integrate-euler-maclaurin-power-law
//| kind: definitions
//| title: "Euler–Maclaurin provider for f(x) = x^(−s)"
//| crates: [scioxide-core, scioxide-integrate]
use scioxide_core::{SciOxideError, RealScalar};
use scioxide_integrate::{EulerMaclaurinProvider, SeriesTerms};

/// Rising factorial (s)_m = s (s + 1) ⋯ (s + m − 1).
pub(crate) fn rising(s: f64, m: usize) -> f64 {
    (0..m).fold(1.0, |acc, k| acc * (s + k as f64))
}

/// f(x) = x^(−s). Derivatives and integrals use analytical formulas; supplied errors use the rounding scale 64ε|value|.
pub(crate) struct PowerLaw(pub(crate) f64);
impl SeriesTerms<f64> for PowerLaw {
    fn term(&self, n: usize, out: &mut [f64]) -> Result<(), SciOxideError> {
        out[0] = RealScalar::powf(n as f64, -self.0);
        Ok(())
    }
}
impl EulerMaclaurinProvider<f64> for PowerLaw {
    fn tail_integral(
        &self,
        at: usize,
        value: &mut [f64],
        error: &mut [f64],
    ) -> Result<(), SciOxideError> {
        // ∫_n^∞ x^(−s) dx = n^(1−s) / (s − 1)
        value[0] = RealScalar::powf(at as f64, 1.0 - self.0) / (self.0 - 1.0);
        error[0] = 64.0 * f64::EPSILON * value[0];
        Ok(())
    }
    fn odd_derivative(
        &self,
        at: usize,
        order: usize,
        value: &mut [f64],
        error: &mut [f64],
    ) -> Result<(), SciOxideError> {
        // f^(m)(n) = (−1)^m (s)_m n^(−s−m). Since m is odd, the sign is negative.
        value[0] = -rising(self.0, order) * RealScalar::powf(at as f64, -self.0 - order as f64);
        error[0] = 64.0 * f64::EPSILON * value[0].abs();
        Ok(())
    }
    fn even_derivative_l1_bound(
        &self,
        at: usize,
        order: usize,
        bound: &mut [f64],
    ) -> Result<(), SciOxideError> {
        // Since f^(2p) > 0, ∫_n^∞ |f^(2p)| = (s)_{2p} n^(1−s−2p) / (s+2p−1). Add an allowance for rounding.
        let (s, m) = (self.0, order as f64);
        let exact = rising(s, order) * RealScalar::powf(at as f64, 1.0 - s - m) / (s + m - 1.0);
        bound[0] = exact * (1.0 + 64.0 * f64::EPSILON);
        Ok(())
    }
}
```

## Upper bound and actual error as the term count increases

The first cell calls `advance` while retaining state and workspace ([Resumption contract](oxref:integrate-series-plan-state)), advances one term per call (`with_terms_per_advance(Budget::ONE)`), and records the estimate and stated bound at each stage.
The term limit is 40; stop when a termination status other than `CallLimit` appears.
Check in the plot that actual error is at most the bound.
Inputs are the exponent $s$, correction order $p$, and absolute tolerance exponent.
Stages with actual error exactly 0 cannot be plotted logarithmically, so they are omitted and their count is shown in the table.
“Provider calls in the last advance” counts calls used to add one term and equals $p + 3$.

```rust

//| ref: integrate-series-euler-maclaurin-zeta

//| uses: [integrate-euler-maclaurin-power-law]

//|   tolerance_exponent: {"type":"range","label":"Absolute tolerance exponent q [-]","description":"Set the tolerance compared with the conditional bound to 10^q.","min":-14,"max":-4,"step":1,"value":-12}

//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: order-12
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/1","equals":5}
//|       - {"artifact":"summary","path":"/rows/0/4","approx":{"value":1.11e-13,"atol":5e-15}}
//|       - {"artifact":"summary","path":"/rows/0/5","approx":{"value":3.17e-13,"atol":5e-15}}

//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/1","equals":40}
//|       - {"artifact":"summary","path":"/rows/0/5","approx":{"value":2.604e-6,"atol":5e-10}}

use scioxide_integrate::{

};
use scioxide_special::riemann_zeta;

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let digits15 = serde_json::json!({ "significantDigits": 15 });
let tolerance = 10.0_f64.powf(tolerance_exponent);
let options = SeriesOptions::default()
    .with_max_terms(Budget::try_from(40).map_err(|e| e.to_string())?)
    .with_order(Budget::try_from(correction_order as usize).map_err(|e| e.to_string())?)
    .with_tolerance(
        ErrorTolerance::scalar(tolerance, 0.0, NormSelection::Infinity)
            .map_err(|e| e.to_string())?,
    )
    .with_terms_per_advance(Budget::ONE);

            &mut state,

    options = &serde_json::json!({
        "xLabel": "Explicitly summed terms n [terms]",
        "yLabel": "Error [-]",
        "yType": "log",
        "xMin": 0,
        "xMax": 40,
        "annotations": [tolerance_line]

);

let last_bound = bound.last().map(|point| point[1]);

    { "key": "4", "label": "Actual error [-]", "type": "number", "format": sci3 },
    { "key": "5", "label": "Conditional upper bound [-]", "type": "number", "format": sci3, "nullText": "Not computed" },
    { "key": "6", "label": "Termination status" },
    { "key": "7", "label": "Provider calls in the last advance [count]", "type": "integer" },
    { "key": "8", "label": "Stages omitted from plot [stages]", "type": "integer" }

let row = (
    exponent,
    state.terms(),
    value,
    exact,
    gap,
    last_bound,
    status.clone(),
    report.provider_calls(),
    zero_errors,
);
emit_table_with_columns!(
    columns,
    vec![row],
    metadata = serde_json::json!({ "id": "summary" })
);

let outcome = if termination.is_success() {
    Outcome::satisfied("The conditional upper bound satisfies the tolerance")
        .explanation("The bound holds provided the provider's derivative and tail information is correct.")
} else {
    Outcome::partial("The term limit was reached before the bound satisfied the tolerance")
        .explanation("The estimate and bound correspond to the stage of the last added term.")
};
let outcome = outcome
    .status(status)
    .diagnostic("Terms used", state.terms() as f64, None)
```

With the defaults ($s = 2$, $p = 3$, tolerance $10^{-12}$), `BoundedTailReached` was reached after 31 terms, with actual error about $10^{-15}$ against a bound of $8.9 \times 10^{-13}$.
At $p = 12$, computation stops after 5 terms (bound $3.2 \times 10^{-13}$, actual error $1.1 \times 10^{-13}$), but the estimate at stage $n = 1$ differs from $\zeta(2)$ by as much as $8 \times 10^4$.
Since the Euler–Maclaurin expansion is asymptotic, higher correction orders require larger $n$.
At $p = 1$, even 40 terms reduce the bound only to $2.6 \times 10^{-6}$, terminating with `TermLimit` and giving outcome `partial`.
Setting the tolerance to $10^{-14}$ makes it unreachable because the floating-point error floor (about $64\varepsilon\,\zeta(2) \approx 2.3 \times 10^{-14}$) exceeds it; after 40 terms, the bound is $1.7 \times 10^{-13}$ with `TermLimit`.

## Correction order and asymptotic series

The second cell fixes the number $n$ of explicitly summed terms, varies the correction order $p$ from 1 to 12, and compares estimates and bounds after adding $n$ terms.
A tolerance $10^{-20}$ below the floating-point error floor is unreachable, so each Plan advances exactly $n$ terms with `sum` and stops with `TermLimit`, exposing its estimate and bound.
Correction terms are smallest at $j \approx \pi n - s/2$, so the error and bound are expected to reach minima near this order and increase beyond it.
The vertical line in the plot is $p = \pi n - s/2$.
Inputs are the term count $n$ and exponent $s$.

```rust
        .map_err(|e| e.to_string())?;
```

With the defaults ($n = 1$, $s = 2$), actual error is minimized at $p = 2$ with $1.16 \times 10^{-2}$, and the bound at $p = 3$ with $2.38 \times 10^{-2}$; at $p = 12$, actual error grows to $8.1 \times 10^4$.
This growth explains why the first cell's estimate after one term at $p = 12$ was far from $\zeta(2)$.
At $n = 2$, both actual error and the bound are smallest at $p = 6$ ($1.54 \times 10^{-5}$ and $3.09 \times 10^{-5}$), close to $\pi n - s/2 \approx 5.3$.
At $n = 4$, the minimum is beyond $p = 12$, and actual error continues decreasing to $3.8 \times 10^{-11}$ at $p = 12$.
At every order, the bound exceeds actual error, controlling error even when the asymptotic series diverges.
At $s = 6$, the rising factorial $(s)_{2j-1}$ is large, so actual error at $n = 1$ is smallest at $p = 1$.

## Summary

If terms sample a smooth function and the tail integral and odd derivatives can be supplied analytically, Euler–Maclaurin summation returns a remainder bound and stops with `BoundedTailReached`.
This bound holds only when the values and error bounds supplied through `EulerMaclaurinProvider`, and the smoothness and decay assumptions, are correct.
Since the Euler–Maclaurin expansion is asymptotic, increasing correction order $p$ at fixed explicitly summed term count $n$ eventually increases error (at about $\pi n - s/2$ for $x^{-s}$); using a large $p$ requires larger $n$.
Choose a tolerance above the floating-point error floor (the sum of $64\varepsilon$ times each summand's magnitude), and treat `TermLimit` when it is unreachable as an estimate.
