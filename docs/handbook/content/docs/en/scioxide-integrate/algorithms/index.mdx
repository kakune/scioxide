Numerical quadrature approximates the definite-integral functional on a function space,

$$
I[f] = \int_\Omega f(\boldsymbol{x})\,w(\boldsymbol{x})\,d\boldsymbol{x}
$$

by a finite sum with nodes $\boldsymbol{x}_i \in \Omega$ and weights $w_i$,

$$
Q_n[f] = \sum_{i=1}^n w_i\,f(\boldsymbol{x}_i)
$$


Both $I$ and $Q_n$ are linear in $f$, so the quadrature error $I[f]-Q_n[f]$ is also a linear functional.
A method is characterized by its choice of nodes and weights, degree of polynomial exactness, asymptotic remainder behavior, and rules for locally adding evaluation points.
This page collects notation and contracts shared by the algorithm pages.

## Notation

| Symbol | Meaning |
|---|---|
| $f$ | Integrand; returns a real number, complex number, or vector of either |
| $w(\boldsymbol x)$ | Known weight separated from the integrand (classical orthogonal polynomial weight, endpoint singularity, oscillatory factor, etc.). Without separation, $w\equiv1$ |
| $\boldsymbol x_i,\ w_i$ | Quadrature nodes and weights |
| $n$ | Node count; evaluations per application |
| $\mu_0 = \int_\Omega w\,d\boldsymbol x$ | Zeroth moment of the weight; domain measure when $w\equiv1$ |
| $\Lambda_n = \sum_i \lvert w_i\rvert$ | Sum of absolute weights; amplification of function-value errors |
| $d$ | Integration dimension |
| $\varepsilon$ | Machine epsilon of the computational scalar type ($2^{-52}\approx2.2\times10^{-16}$ for `f64`) |
| $\varepsilon_{\mathrm{abs}},\ \varepsilon_{\mathrm{rel}}$ | Absolute and relative tolerances |
| $E$ | Error estimate; estimates the true error $\lvert I-Q\rvert$ and is not an upper bound |

## Degree of exactness and stability

A quadrature rule's degree of exactness is the largest $m$ such that $Q_n[p]=I[p]$ for every polynomial $p$ of degree at most $m$.
This is an exact-arithmetic property; floating-point arithmetic adds rounding error.
On simplices use total degree; on spheres use spherical harmonic degree.
The better $f$ is approximated by a degree-$m$ polynomial, the smaller the error of a rule with degree of exactness $m$.

With absolute function-value errors $\delta_i$, the sum's error is bounded by

$$
\Bigl|\sum_i w_i\,\delta_i\Bigr| \le \Lambda_n \max_i \lvert\delta_i\rvert
$$


If every weight is positive, a rule exact for the constant $1$ has $\Lambda_n = \sum_i w_i = \mu_0$.
$\mu_0$ equals the domain measure only for $w\equiv1$; for example, Gauss–Hermite with weight $e^{-x^2}$ has $\mu_0=\sqrt\pi$.
`GaussianRulePlan::zeroth_moment()` returns this $\mu_0$.
Rules with negative weights (higher-order Newton–Cotes and Grundmann–Möller) have $\Lambda_n$ exceeding $\mu_0$, amplifying function-value errors.

## Four kinds of uncertainty

Distinguish four kinds of uncertainty accompanying results from this crate.

- An error estimate (`ErrorReliability::Estimated`) comes from differences between two rules (embedded pairs), two levels (extrapolation), or a rounding error model.
- An empirical estimate (`ErrorReliability::Heuristic`) is inferred from observed decay of contributions (DE tails, Fourier cycle contributions, and so on); it cannot reveal structure outside the observed range.
- A guaranteed enclosure is an interval guaranteed to contain the integral; `scioxide-integrate` does not return one.
  The one-shot function `scioxide_validated::integrate` and verifier `QuadratureVerifier` in `scioxide-validated` construct these from user-supplied interval extensions.
- Statistical uncertainty consists of Monte Carlo sample standard errors and confidence intervals, assuming finite integrand variance.

Euler–Maclaurin summation of infinite series provides a remainder bound assuming user-supplied tail integrals and derivative bounds.
This bound holds only if the assumptions are correct; the assumptions themselves are not verified.

## Result report `IntegrationReport`

Plans return `IntegrationReport` with the value, except for stored-sample Plans, series, sensitivities, and VEGAS and MISER training.
Monte Carlo also returns this report; read standard errors through the workspace's `statistics()`.
Values are written to caller-supplied output or returned together with the report by `integrate` in APIs returning owned values.

| Method | Returned value |
|---|---|
| `termination()` | Single authoritative termination reason `IntegrationTermination` |
| `is_success()` | `termination().is_success()` |
| `evaluations()` | Integrand evaluation count; includes inner-integral evaluations for iterated integration |
| `subdivisions()` | Bisection count; 0 for methods without subdivision |
| `error_components()` | Error-estimate breakdown `IntegrationErrorComponents`; `None` for fixed rules without embedded pairs and for Monte Carlo |
| `error_estimate()` | Breakdown total `total()` |

For complex or vector values, the report's error breakdown is the componentwise maximum (envelope) over real components.
Read per-component breakdowns with `component_errors()` on the workspace that produced the report.

## Termination reasons `IntegrationTermination`

There are 11 termination reasons; `is_success()` is true for the first 5.
An `Ok` result always has an estimate covering the entire domain.
Stopping before that estimate exists returns the error in the rightmost column instead of a value.

| Termination reason | Success | Meaning | Error if no full-domain estimate exists |
|---|---|---|---|
| `FixedRuleCompleted` | Success | Applied a fixed-order rule once; tolerance was not checked | — |
| `ToleranceReached` | Success | The error estimate satisfied the tolerance | — |
| `HeuristicToleranceReached` | Success | An empirical error estimate (such as observed tail decay) satisfied the tolerance | — |
| `SampleBudgetCompleted` | Success | Monte Carlo used all requested samples | — |
| `DegenerateDomain` | Success | The domain has measure 0; the result is exactly 0 | — |
| `BudgetLimit(kind)` | — | The next work unit exceeds a limit such as evaluation or bisection count | `ConvergenceFailure` (`EvaluationLimit` for `Evaluation`, `IterationLimit` for `Iteration`, otherwise `ResourceLimit(kind)`) |
| `ExecutionStopped(reason)` | — | Cancellation or deadline | `ExecutionStopped` |
| `RefinementLimit` | — | Reached the maximum level or term count | `ConvergenceFailure`（`TruncationLimit`） |
| `Stagnation` | — | The estimate no longer changes in floating-point arithmetic | `ConvergenceFailure`（`Stagnation`） |
| `ProbablyDivergent` | — | Extrapolation indicates divergence or very slow convergence | `ConvergenceFailure`（`Divergence`） |
| `GeometryFailure` | — | No representable evaluation point for the next subdivision | `NumericalInstability`（`Breakdown`） |

Success means the method finished as configured; it does not bound the true error.
Other report types define success separately.

- `SeriesTermination::is_success()` is true for `BoundedTailReached` (Euler–Maclaurin remainder bound meets the tolerance), `ExactEmpty`, and `HeuristicToleranceReached` (successive Levin u or Wynn ε accelerated values agree).
  Only `BoundedTailReached` carries an upper bound.
- `TrainingReport::is_success()` (VEGAS and MISER training) is true when training runs to completion.
- `SensitivityReport` has no `is_success()`; read `report.termination().is_success()` instead.

## Error-estimate breakdown

`ErrorEstimate` pairs a nonnegative magnitude `magnitude()` with kind `reliability()` (`ErrorReliability::Estimated` or `Heuristic`).
`IntegrationErrorComponents` fills only components estimated by the method and sets unestimated components to `None`.
`None` means “not estimated,” rather than “known to be 0.”

| Component | Content | Main methods supplying it |
|---|---|---|
| `discretization()` | Difference between two embedded rules or levels | Embedded pairs, adaptive methods, extrapolation |
| `roundoff()` | Sum rounding error estimate; smaller discretization estimates are meaningless | Same as above |
| `inner()` | Inner-integral errors weighted by the outer rule in iterated integration | `IteratedDomainPlan` |
| `moments()` | Modified-moment errors in weighted rules | `WeightedQuadraturePlan`, `FourierTailPlan` |
| `extrapolation()` | Sequence extrapolation error | `with_extrapolation`, `FourierTailPlan` |
| `tail()` | Estimated contribution of a truncated tail | `DoubleExponentialIntegrator`, `FourierTailPlan` |
| `tail_diagnostics()` | Tail exploration range and status `TailDiagnostics` | Same as above |

The total `total()` is

$$
E = \max(\text{discretization},\ \text{roundoff}) + \text{inner} + \text{moments} + \text{extrapolation} + \text{tail}
$$

with missing components other than `discretization` counted as 0.
Since discretization estimates below rounding error are meaningless, take the maximum with rounding rather than adding it.
If `discretization` is absent, tail diagnostics exist without a tail magnitude, or the sum overflows, `total()` returns `None`.
For details of `TailDiagnostics` and `TailStatus`, see [Double-exponential transformations for improper integrals and endpoint singularities](improper-singular-and-oscillatory/) for DE tails and [Cancellation in oscillatory integrals and tails of Fourier integrals](fourier-integrals-and-tails/) for Fourier tails.

## Plans, workspaces, and execution contexts

A Plan (such as `AdaptiveIntegrator` or `CubaturePlan`) validates options once during construction and is an immutable value usable repeatedly.
A workspace is caller-owned memory reusable across calls to Plans of the same kind.
Execution proceeds as follows.

1. Obtain required size `IntegrationRequirements` with `plan.workspace_requirements(..)`.
2. Create a workspace with `plan.workspace(..)`, or apply `check(&requirements)` and `try_reserve(&requirements)` to an existing one.
3. Compute with `plan.integrate_into(f, .., &mut out, &mut workspace, scope)`.
   Pass `scope` an execution context such as `ExecutionContext::sequential()` or a solve scope with a computation-count limit.

In APIs returning owned values, `integrate(f, ..)` creates a workspace for each call, executes sequentially, and returns a value and report.
Pass integrands by value; to reuse the same closure in successive calls, pass `&f`.
One-shot functions for a single integration with defaults (such as `integrate` and `integrate_box`) create a Plan and workspace on the spot and return a value and error estimate in `Integral` only on success ([One-shot functions and configured Plans](oxref:integrate-choosing-one-shot)).
With a sufficiently large workspace, `integrate_into` allocates no memory.
Output is unchanged on error.

`IntegrationRequirements::components()` returns the number of real components in a value (1 for real, 2 for complex, and the length for a vector).
A workspace corresponds to one component count and, for multidimensional Plans, one dimension; if either differs, `check` returns `Capacity::NeedsGrowth`.
`try_reserve` keeps the larger of current and requested capacity, allowing one workspace to serve multiple Plans of the same kind.
A request from another Plan kind gives `InvalidInput`.
`last_attempt()` returns a record of the preceding call (result classification, evaluation count, and report).

“Validation and record” indicates whether `check`, `try_reserve`, and `last_attempt` are available.

## Vector- and complex-valued quadrature

Quadrature weights $w_i$ are real, so the same nodes and weights apply to every component even when $f$ returns complex or vector values.

$$
Q_n[\boldsymbol f] = \Bigl(\sum_i w_i f_1(x_i),\ \dots,\ \sum_i w_i f_m(x_i)\Bigr).
$$

Integrand values can use types implementing `AffineValue` from `scioxide-core` (real numbers, `Complex<S>`, `Vec<V>`, and `[V; N]`); `integrate_into` output also accepts slices `[V]`.
Owned-value APIs `integrate` and one-shot functions require `Copy` values (real, complex, or fixed-length arrays), so runtime-length vector values use `integrate_into` with `Vec` or slice output.
Complex numbers are two real components, real and imaginary; size workspaces by real component count (`workspace(2)` for complex).
Tolerances are checked by combining componentwise normalized errors with the norm in `ErrorTolerance`.
An integrand returning NaN or infinity gives an error `NonFinite` (originating in the callback).

The `FixedRule` trait represents fixed rules.
`map_nodes_into(interval, &mut nodes)` writes mapped nodes and weights into a sequence of `FixedRuleNode` without evaluating the integrand.
`FixedRuleNode` contains node `point()`, main-rule weight `primary_weight()`, and embedded-rule weight `embedded_weight()` (`None` for rules without embedded pairs), and is constructed with `FixedRuleNode::new(point, primary_weight, embedded_weight)`.
`integrate_into` maps and validates all nodes before calling the integrand, and uses compensated summation (retaining rounding errors separately and adding them back) for weighted sums.
If intermediate products or sums exceed the scalar range, computation continues using a representation with extended exponent range.
Compensated summation substantially reduces rounding error but guarantees neither an exact sum nor a single rounding.

The next cell integrates the complex-valued integrand $f(x)=e^{i\kappa x}$ over $[0,1]$ using a Gauss–Kronrod rule.
The exact value is

$$
\int_0^1 e^{i\kappa x}\,dx = \frac{\sin\kappa}{\kappa} + i\,\frac{1-\cos\kappa}{\kappa}
$$


Inputs are wavenumber $\kappa$ and Gauss–Kronrod pair; a workspace created for G7K15 then undergoes `check` and `try_reserve` with the selected pair's requirements.
Outputs are a table of per-component estimates and actual errors, a table of the report and absolute-weight sum $\Lambda_n$, and a termination-reason assessment.
Check whether per-component estimates exceed actual errors, whether the report estimate equals their maximum, and whether $\Lambda_n$ equals interval length 1.

```rust
//| id: integrate-affine-complex-moments
//| ref: integrate-affine-complex-moments
//| title: "Integrate a complex-valued integrand componentwise with Gauss–Kronrod quadrature"
//| run: reactive
//| crates: [scioxide-core, scioxide-integrate]
//| inputs:
//|   wave_number: {"type":"range","label":"Wavenumber κ [-]","description":"Change the oscillation count κ/(2π) on [0, 1].","min":1,"max":60,"step":1,"value":20}
//|   pair: {"type":"select","label":"Gauss–Kronrod pair","description":"More nodes increase the degree of exactness.","options":["G7K15","G10K21","G15K31","G20K41","G25K51"],"value":"G7K15"}
//| cases:
//|   - {"id":"larger-pair","label":"G15K31","description":"The 31-node pair resolves oscillations at κ = 20, reducing error to rounding level.","inputs":{"pair":"G15K31"}}
//|   - {"id":"fast-oscillation","label":"κ = 60","description":"15 nodes do not resolve the oscillations; estimates and actual errors are both large.","inputs":{"wave_number":60}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"components","path":"/rows/0/2","range":{"min":1e-10,"max":1e-8}}
//|       - {"artifact":"components","path":"/rows/0/3","range":{"min":0.1,"max":1}}
//|       - {"artifact":"report","path":"/rows/0/3","approx":{"value":1.0,"rtol":1e-14}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: larger-pair
//|     expect:
//|       - {"artifact":"components","path":"/rows/0/2","range":{"min":0,"max":1e-14}}
//|       - {"artifact":"report","path":"/rows/0/1","equals":31}
//|   - case: fast-oscillation
//|     expect:
//|       - {"artifact":"components","path":"/rows/0/2","range":{"min":1e-3,"max":1}}
//|       - {"artifact":"components","path":"/rows/1/2","range":{"min":1e-3,"max":1}}
use scioxide_core::{Complex, ExecutionContext, Interval, RealScalar};
use scioxide_integrate::{FixedRule, FixedRuleNode, GaussKronrod, GaussKronrodRule};

let kappa = wave_number;
let selected = match pair.as_str() {
    "G10K21" => GaussKronrodRule::G10K21,
    "G15K31" => GaussKronrodRule::G15K31,
    "G20K41" => GaussKronrodRule::G20K41,
    "G25K51" => GaussKronrodRule::G25K51,
    _ => GaussKronrodRule::G7K15,
};
let interval = Interval::new(0.0, 1.0).map_err(|e| e.to_string())?;

// Create workspace for 15 nodes and 2 real components (complex), then expand it to the chosen pair's requirements.
let mut workspace = GaussKronrod::<f64>::new(GaussKronrodRule::G7K15)
    .map_err(|e| e.to_string())?
    .workspace(2)
    .map_err(|e| e.to_string())?;
let rule = GaussKronrod::new(selected).map_err(|e| e.to_string())?;
let requirements = rule.workspace_requirements(2).map_err(|e| e.to_string())?;
let capacity = workspace.check(&requirements).map_err(|e| e.to_string())?;
workspace
    .try_reserve(&requirements)
    .map_err(|e| e.to_string())?;

// f(x) = e^{iκx} = cos κx + i sin κx. Call SciOxide functions through RealScalar.
let integrand = |x: f64| {
    Ok(Complex::new(
        RealScalar::cos(kappa * x),
        RealScalar::sin(kappa * x),
    ))
};
let mut output = Complex::new(0.0_f64, 0.0);
let report = rule
    .integrate_into(
        &integrand,
        interval,
        &mut output,
        &mut workspace,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;

// Reference (closed form using f64 standard functions).
let exact = [kappa.sin() / kappa, (1.0 - kappa.cos()) / kappa];
let computed = [output.re, output.im];
let errors = workspace
    .component_errors()
    .ok_or("No componentwise error estimates")?;
let sig15 = serde_json::json!({ "significantDigits": 15 });
let sig16 = serde_json::json!({ "significantDigits": 16 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let component_columns = serde_json::json!([
    { "key": "0", "label": "Component" },
    { "key": "1", "label": "Integral [-]", "type": "number", "format": sig15 },
    { "key": "2", "label": "Actual error [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "Discretization estimate [-]", "type": "number", "format": sci3, "nullText": "Not estimated" },
    { "key": "4", "label": "Rounding error floor [-]", "type": "number", "format": sci3, "nullText": "Not estimated" },
    { "key": "5", "label": "Total total() [-]", "type": "number", "format": sci3, "nullText": "Undefined" }
]);
let rows: Vec<_> = ["Real part", "Imaginary part"]
    .into_iter()
    .zip(computed.iter().zip(&exact))
    .zip(errors)
    .map(|((name, (&value, &reference)), parts)| {
        (
            name,
            value,
            (value - reference).abs(),
            parts.discretization().map(|estimate| estimate.magnitude()),
            parts.roundoff(),
            parts.total(),
        )
    })
    .collect();
emit_table_with_columns!(
    component_columns,
    rows,
    metadata = serde_json::json!({ "id": "components" })
);

// Compute Λ = Σ|w_i| from mapped nodes and weights. Positive weights make this equal to interval length 1.
let mut nodes = vec![FixedRuleNode::new(0.0, 0.0, None); rule.node_count()];
rule.map_nodes_into(interval, &mut nodes)
    .map_err(|e| e.to_string())?;
let lebesgue: f64 = nodes.iter().map(|node| node.primary_weight().abs()).sum();
let report_columns = serde_json::json!([
    { "key": "0", "label": "Capacity before expansion" },
    { "key": "1", "label": "Evaluation count [count]", "type": "integer" },
    { "key": "2", "label": "Report error estimate [-]", "type": "number", "format": sci3, "nullText": "Undefined" },
    { "key": "3", "label": "Λ = Σ|w_i| [-]", "type": "number", "format": sig16 },
    { "key": "4", "label": "Termination reason" }
]);
emit_table_with_columns!(
    report_columns,
    vec![(
        format!("{capacity:?}"),
        report.evaluations(),
        report.error_estimate(),
        lebesgue,
        report.termination().to_string(),
    )],
    metadata = serde_json::json!({ "id": "report" })
);

// A fixed-rule application ends with FixedRuleCompleted. The tolerance is not checked.
let mut outcome = Outcome::satisfied("Applied the fixed rule once")
    .explanation("There is no accuracy claim; read the table's error estimates and closed-form discrepancies.")
    .status(report.termination().to_string())
    .diagnostic("Evaluation count", report.evaluations() as f64, None);
if let Some(estimate) = report.error_estimate() {
    outcome = outcome.diagnostic("Error estimate", estimate, None);
}
emit_outcome!(outcome);
```

With the defaults ($\kappa=20$, G7K15), 15 evaluations gave actual real and imaginary errors $1.3\times10^{-9}$ and $8.3\times10^{-10}$, but discretization estimates $0.61$ and $0.64$.
G7K15 estimates come from differences between 7-node Gauss and 15-node Kronrod values, so oscillations unresolved by 7 nodes yield large estimates even when 15-node values are far more accurate (the formula is covered in [Embedded pairs and globally adaptive quadrature](adaptive-quadrature/)).
The report estimate $0.64$ is the larger of the two components; componentwise breakdowns must be read from the workspace.
Selecting G15K31 classifies workspace capacity as `NeedsGrowth` and expands it; 31 evaluations give actual error at most $2\times10^{-16}$ and estimate about $10^{-14}$.
The imaginary total $7.1\times10^{-15}$ then equals the rounding error floor rather than the discretization estimate $5.5\times10^{-15}$, demonstrating that `total()` takes their maximum.
At $\kappa=60$, the 15-node rule cannot resolve oscillations: actual errors are $0.07$ and $0.43$, and estimates $0.41$ and $0.62$.
In every case, $\Lambda_n$ is 1, confirming no amplification of function-value errors for positive-weight rules.

## Summary

Interpret quadrature as a value, a single authoritative termination reason, and an error-estimate breakdown.
Success means the method finished as configured and includes `HeuristicToleranceReached` for both integrals and series.
The total error estimate adds other components to $\max(\text{discretization},\text{roundoff})$; none of the components is an upper bound.
Plans are immutable and workspaces caller-owned; `check` and `try_reserve` allow reuse for other Plans.
Complex and vector values use the same rule per real component; read componentwise estimates with the workspace's `component_errors()`.
