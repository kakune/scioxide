Many quantities, including total heat-source output, probabilistic expectations, and wavefunction matrix elements, are expressed as multiple integrals over a box:

$$
I[f] = \int_B f(\boldsymbol x)\,d\boldsymbol x, \qquad B = [a_1, b_1] \times \cdots \times [a_d, b_d]
$$


One-dimensional quadrature rules extend to each axis, but deterministic evaluation counts grow rapidly with dimension $d$.
In contrast, Monte Carlo standard error decreases as $N^{-1/2}$ regardless of dimension.
The dimension at which Monte Carlo becomes preferable depends on integrand smoothness and the required accuracy; there is no single threshold.
For high-accuracy integration of smooth functions, deterministic rules often remain preferable up to about 5–10 dimensions; for discontinuous functions or only two or three digits of accuracy, Monte Carlo can be preferable even in low dimensions.

This page covers two deterministic box methods: tensor products using the same fixed rule on every axis, and Genz–Malik adaptive cubature refining subboxes with large errors.
[Monte Carlo integration estimators and statistics](../monte-carlo-integration/) covers uniform Monte Carlo; [Iterated integration with variable bounds and coordinate maps](../domains-and-geometric-rules/) and [Simplex and sphere quadrature rules](../simplex-and-sphere-rules/) cover non-box domains; [Sparse grids and randomized quasi-Monte Carlo](../sparse-grids-and-qmc/) covers smooth, moderate-dimensional integrals.
[Choosing numerical integration methods](../../choosing/) summarizes method selection.

## Tensor-product rules and evaluation counts

Map a one-dimensional fixed rule with nodes $x_i$ and weights $w_i$ ($i = 1, \dots, n$) to each axis $[a_k, b_k]$, writing the mapped nodes and weights as $x_{k,i}$ and $w_{k,i}$.
Fubini's theorem rewrites the multiple integral as iterated axis integrals; approximating each axis with the same rule gives the tensor-product rule

$$
Q[f] = \sum_{i_1=1}^{n} \cdots \sum_{i_d=1}^{n} w_{1,i_1} \cdots w_{d,i_d}\, f(x_{1,i_1}, \dots, x_{d,i_d})
$$


If the one-dimensional rule integrates polynomials through degree $p$ exactly, its tensor product exactly integrates monomials $x_1^{k_1} \cdots x_d^{k_d}$ ($k_j \le p$) whose degree in each variable is at most $p$.

The evaluation count is $N = n^d$.
With $n = 10$, this is 1000 points at $d = 3$, but $10^6$ points at $d = 6$ and $10^8$ points at $d = 8$.
Expressing error in terms of evaluation count explains the consequence of this growth.
For a function with bounded derivatives of order $r$ along each axis, an $n$-point Gaussian rule has per-axis error of order $O(n^{-r})$, and total error has the same order.
Substituting $n = N^{1/d}$ gives error $O(N^{-r/d})$, so accuracy at a fixed evaluation count decreases with dimension.
This is the curse of dimensionality.

`ProductRule::new(rule, ProductOptions)` is a tensor-product rule using one fixed `rule` on every axis, such as a Gauss–Legendre rule or Gauss–Kronrod pair implementing [`FixedRule`](oxref:integrate-vector-valued-quadrature).
Different rules cannot be selected for different axes.
Nodes are evaluated in row-major order, with the last axis varying fastest.
If the rule has embedded weights, as in a Gauss–Kronrod pair, the difference between tensor sums using primary and embedded weights estimates error, bounded below by the roundoff floor $50\varepsilon\sum|w f|$.
Without embedded weights, there is no error estimate.
Termination is `FixedRuleCompleted`; a zero-width axis returns 0 and `DegenerateDomain` without evaluation.

`ProductOptions` holds a per-call evaluation limit (none by default) and execution policy.
A call whose $n^d$ exceeds the limit fails before evaluation with `ConvergenceFailure`.
`plan.workspace((d, c))` constructs `ProductWorkspace` for dimension $d$ and real-component count $c$, storing mapped nodes and 64 evaluation points in $O(nd + 64(d+c))$ memory.
Rules with the same dimension and component count and no greater node count can share workspace; `integrate_into` does not allocate.
`component_errors()` returns componentwise errors from the last successful call with an embedded-weight rule.

## Genz–Malik adaptive cubature

Instead of placing a uniform grid over the whole domain, refining only high-error subboxes concentrates evaluations on local peaks and boundary layers.
For $d = 1$, `CubaturePlan::new(&bounds, SubdivisionOptions)` uses [globally adaptive G7K15 quadrature](../adaptive-quadrature/), matching `AdaptiveIntegrator` in value, error, and evaluation count when no breakpoints are supplied; for $d \ge 2$, it uses the Genz–Malik degree-7 rule and embedded degree-5 rule with the same priority-based refinement.

### Node placement and evaluation counts

The Genz–Malik rule maps a subbox centered at $\boldsymbol c$ with axis half-widths $h_j$ to the reference cube $[-1, 1]^d$ and evaluates four symmetric point types.
The generators are $\lambda_2 = \sqrt{9/70}$, $\lambda_3 = \sqrt{9/10}$, and $\lambda_5 = \sqrt{9/19}$.

- One center point.
- $4d$ axis points at $\pm\lambda_2$ and $\pm\lambda_3$.
- $2d(d-1)$ points with two axis coordinates equal to $\pm\lambda_3$.
- $2^d$ vertex-direction points with all coordinates equal to $\pm\lambda_5$.

The evaluation count per region is

$$
n(d) = 2^d + 2d(d-1) + 4d + 1
$$

This gives 17, 33, 57, and 93 points at $d = 2, 3, 4, 5$.
The degree-7 rule uses every point; the degree-5 rule excludes vertex-direction points.
Both rules share function values, so error estimation requires no extra evaluations.
Each split evaluates both children from scratch, costing $2n(d)$ evaluations.
The $2^d$ term dominates in high dimensions, making $d \lesssim 10$ the practical range.

### Fourth differences for split-axis selection

Choose the split axis using the fourth difference along each axis:

$$
D_j = \Bigl| f(\boldsymbol c + \lambda_2 h_j \boldsymbol e_j) + f(\boldsymbol c - \lambda_2 h_j \boldsymbol e_j) - 2f(\boldsymbol c)
- \frac{\lambda_2^2}{\lambda_3^2}\bigl(f(\boldsymbol c + \lambda_3 h_j \boldsymbol e_j) + f(\boldsymbol c - \lambda_3 h_j \boldsymbol e_j) - 2f(\boldsymbol c)\bigr) \Bigr|
$$

Here $\boldsymbol e_j$ is the unit vector for axis $j$.
Setting $g(t) = f(\boldsymbol c + t h_j \boldsymbol e_j)$, Taylor expansion gives

$$
g(\lambda) + g(-\lambda) - 2g(0) = \lambda^2 g''(0) + \frac{\lambda^4}{12} g^{(4)}(0) + O(\lambda^6)
$$


Taking the difference with coefficient $\lambda_2^2/\lambda_3^2 = 1/7$ cancels the second-derivative term, leaving

$$
D_j \approx \frac{\lambda_2^2(\lambda_3^2 - \lambda_2^2)}{12}\,\bigl|g^{(4)}(0)\bigr|
$$


The degree-5 rule exactly integrates polynomials through degree 5, so its difference from the degree-7 rule comes from Taylor terms of degree 6 and above.
After canceling second-order terms, $D_j$ measures higher-order variation along axis $j$ and identifies axes with large variation.
Bisect the region at the midpoint of the axis with largest $D_j$ into congruent subboxes.
For axes tied within $10^{-d}$ times the embedded error or the roundoff scale, choose the widest axis to avoid overly elongated regions.
Axis assessment reuses function values from error estimation, requiring no extra evaluations.

### Error estimation and termination

For a region of volume $V$, the error estimate is four times the difference between the degree-7 and degree-5 estimates:

$$
E = 4\,|Q_7 - Q_5|
$$


After a split, each child's error estimate is the larger of its own $4|Q_7 - Q_5|$ and half of $4|Q_{\text{left}} + Q_{\text{right}} - Q_{\text{parent}}|$, four times the change in value from splitting.
Together, the children retain an error at least four times the change caused by the split.
Neither estimate falls below the roundoff floor $50\varepsilon V \sum|w_7| \max|f|$, where $w_7$ are degree-7 weights for a unit-volume region and $\max|f|$ is the largest magnitude evaluated in that region.

The total error estimate sums region errors; split the highest-error region until the [`SubdivisionOptions`](oxref:integrate-adaptive-options-workspace) tolerance $E \le \varepsilon_{\mathrm{abs}} + \varepsilon_{\mathrm{rel}}|Q|$ is satisfied.
The factor 4 is the same empirical safety factor as in one-dimensional adaptive quadrature; it does not prove an error bound.
Thus error estimates for $d \ge 2$ carry `ErrorReliability::Heuristic`, and reaching tolerance gives `HeuristicToleranceReached` rather than `ToleranceReached`.
G7K15 in $d = 1$ returns `ToleranceReached`.

Each region's roundoff floor is at least $50\varepsilon\sum|w_7|$ times the magnitude of its degree-7 value.
Consequently, the total error estimate is at least $50\varepsilon\sum|w_7|$ times the integral estimate's magnitude.
Tolerance below this floor cannot be reached by further subdivision.
In that case, stop with `Stagnation` once two consecutive splits of the highest-error region change its value by no more than the children's error floors.
Attempting to split a region too narrow to distinguish nodes also stops with `Stagnation`.

Evaluation and subdivision limits count separately for each call.
Stopping at a limit, cancellation, or deadline before evaluating every initial region (subboxes cut by breakpoints) returns `ConvergenceFailure` or `ExecutionStopped` as an error because no whole-domain estimate exists.
Stopping later returns the whole-domain estimate and error estimate with termination status `BudgetLimit` or `ExecutionStopped`.
A split is authorized before evaluation as a single unit covering both children, so it never stops midway.
A box with a zero-width axis returns exact 0 and `DegenerateDomain` without evaluation.

The `CubatureWorkspace` returned by `plan.workspace(components)` stores up to $r = k + m$ regions from initial count $k$ and subdivision limit $m$, using $O(r(d + c))$ memory for component count $c$; `integrate_into` does not allocate.
`component_errors()` returns componentwise errors from the last successful call.
`plan.integrate(f)` is the convenience form that allocates workspace and runs sequentially.
The one-shot `integrate_box` integrates once with default settings; see [One-shot integrate_box](#one-shot-integrate_box).
[Presplitting known features inside a box](oxref:integrate-box-breakpoints) covers `with_breakpoints` for initial subdivisions at known corners or discontinuities.

## Cubature and tensor products for peaks

Integrate two kinds of peak centered at $\boldsymbol u$ inside the unit cube $[0,1]^d$:

$$
f_{\mathrm G}(\boldsymbol x) = \exp\Bigl(-a^2 \sum_{j=1}^d (x_j - u_j)^2\Bigr), \qquad
f_{\mathrm K}(\boldsymbol x) = \exp\Bigl(-a \sum_{j=1}^d |x_j - u_j|\Bigr)
$$


$f_{\mathrm G}$ is an analytic Gaussian peak, while $f_{\mathrm K}$ has kinks at each coordinate plane $x_j = u_j$; $a$ controls sharpness, with width about $1/a$.
The exact values are products of one-dimensional axis integrals:

$$
I_{\mathrm G} = \prod_{j=1}^d \frac{\sqrt\pi}{2a}\bigl[\operatorname{erf}(a(1 - u_j)) + \operatorname{erf}(a u_j)\bigr], \qquad
I_{\mathrm K} = \prod_{j=1}^d \frac{2 - e^{-a u_j} - e^{-a(1-u_j)}}{a}
$$


The following definitions block contains the integrand `peak` and exact value `exact_peak` shared by two cells.
The center $\boldsymbol u$ uses the first $d$ entries of `CENTERS`, offset differently on each axis to avoid symmetry.
Compute exact values with SciOxide `erf` and `exp` as independent references.

```rust
//| id: integrate-peak-integrands
//| kind: definitions
//| title: "Gaussian and kinked peaks and their exact integrals"
//| crates: [scioxide-core, scioxide-special]
use scioxide_core::RealScalar;
use scioxide_special::erf;

// Peak centers u_j (d ≤ 5).
pub(crate) const CENTERS: [f64; 5] = [0.37, 0.52, 0.61, 0.45, 0.29];

// Gaussian: exp(−a² Σ (x_j − u_j)²); kinked: exp(−a Σ |x_j − u_j|).
pub(crate) fn peak(x: &[f64], a: f64, smooth: bool) -> f64 {
    let exponent: f64 = x
        .iter()
        .zip(CENTERS)
        .map(|(x, c)| {
            if smooth {
                a * a * (x - c) * (x - c)
            } else {
                a * (x - c).abs()
            }
        })
        .sum();
    RealScalar::exp(-exponent)
}

// Exact value: product of one-dimensional axis integrals.
pub(crate) fn exact_peak(d: usize, a: f64, smooth: bool) -> Result<f64, String> {
    let mut exact = 1.0;
    for &c in &CENTERS[..d] {
        exact *= if smooth {
            let sum = erf(a * (1.0 - c)).map_err(|e| e.to_string())?
                + erf(a * c).map_err(|e| e.to_string())?;
            RealScalar::sqrt(std::f64::consts::PI) / (2.0 * a) * sum
        } else {
            (2.0 - RealScalar::exp(-a * c) - RealScalar::exp(-a * (1.0 - c))) / a
        };
    }
    Ok(exact)
}
```

The evaluation count is the initial region's 17 plus 34 per split, confirming that splits count both children as one unit.
Error estimates exceed actual errors by two to four orders of magnitude and decrease by about one order each time tolerance is tightened.
The estimate is pessimistic both because of the factor-4 safety margin and because the degree-7/degree-5 difference mainly reflects the degree-5 error, exceeding the degree-7 rule's own error.
Switching to the kinked peak refines near the kinks, reaching difference $2.5\times10^{-10}$ in 24599 evaluations.

At $d = 3$, tolerance $10^{-4}$ uses about 56000 evaluations; the next tolerance $10^{-5}$ reaches limit $10^5$ and stops with `BudgetLimit(Evaluation)`, giving a partial outcome.
At $d = 5$, each region uses 93 points and each split 186 evaluations, reaching the limit before the first tolerance $10^{-2}$.
In both cases the final table row is a whole-domain estimate with an error estimate.

```rust
        .and_then(|e| e[0].discretization());
    let estimate = component.map(|e| e.magnitude());
    let error = (value - exact).abs();
    rows.push((
        "G7K15 (15 Kronrod points)",
        15,
        report.evaluations(),
        error,
        estimate,
    ));
}
let series = serde_json::json!({
    "name": "Gauss–Legendre tensor-product rule",
    "points": curve,
    "style": { "showSymbol": true }
});
emit_line_chart!(
    &vec![series],
    options = &serde_json::json!({
        "xLabel": "Integrand evaluations n^d [count]",
        "yLabel": "Difference from exact value [-]",
        "xType": "log",
        "yType": "log"
    })
);
let columns = serde_json::json!([
    { "key": "0", "label": "One-dimensional rule" },
    { "key": "1", "label": "Points per axis n", "type": "integer" },
    { "key": "2", "label": "Evaluations [count]", "type": "integer" },
    { "key": "3", "label": "Difference from exact value [-]", "type": "number", "format": sci3 },
    { "key": "4", "label": "Error estimate [-]", "type": "number", "format": sci3, "nullText": "None" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "rules" })
);
```

With defaults ($d = 2$, Gaussian), Gauss–Legendre tensor-product error decreases exponentially with $n$, reaching the roundoff scale $10^{-16}$ at 32 points per axis (1024 evaluations).
Compared with about 14000 Genz–Malik evaluations for $6\times10^{-12}$ on the same integrand, tensor-product Gaussian rules achieve better accuracy with fewer evaluations for low-dimensional analytic integrands.
The G7K15 product (225 evaluations) has error estimate $1.3\times10^{-4}$, larger than the actual difference $1.8\times10^{-5}$, reflecting the error of the embedded 7-point Gauss product.

For the kinked peak, Gauss–Legendre error remains around $4\times10^{-4}$ even at 1024 evaluations and is not monotonic in point count.
Kinks slow polynomial approximation on each axis, and tensor products have no mechanism to concentrate nodes at those locations.
Genz–Malik reaches $2.5\times10^{-10}$ in 24599 evaluations on the same function; concentrating refinement where smoothness is lost is adaptive cubature's advantage.
At $d = 4$, the evaluation limit $10^5$ permits at most 16 points per axis, leaving error around $5\times10^{-8}$.

## One-shot integrate_box

The one-shot `integrate_box(f, &lower, &upper)` constructs a box from lower and upper corner coordinates and integrates with `CubaturePlan` using default `SubdivisionOptions` settings.
Defaults are absolute and relative tolerances $\sqrt\varepsilon \approx 1.5\times10^{-8}$, 50 subdivisions, and no evaluation limit; workspace is allocated internally and execution is sequential with `ExecutionContext::sequential_native()`.
It returns `Integral` containing the value and combined error estimate, without a report.
Unsuccessful termination becomes an error, so stopping at the subdivision limit returns no partial estimate.
[One-shot functions and configured plans](oxref:integrate-choosing-one-shot) summarizes the correspondence with other one-shot functions.

The following cell integrates the Gaussian peak with `integrate_box`, `CubaturePlan` with identical defaults, and `CubaturePlan` with its subdivision limit raised to $10^4$.
Plan rows show evaluation counts and termination statuses from `plan.integrate(f)` reports; the `integrate_box` row shows value and error estimate on success or error classification on failure.

```rust
//| id: integrate-box-one-shot
//| ref: integrate-box-one-shot
//| title: "Vary peak sharpness to compare one-shot integrate_box with plans"
//| run: reactive
//| uses: [integrate-peak-integrands]
//| crates: [scioxide-core, scioxide-integrate, scioxide-special]
//| inputs:
//|   dimension: {"type":"range","label":"Dimension d [-]","description":"Dimension of the integration cube.","min":2,"max":3,"step":1,"value":2}
//|   sharpness: {"type":"range","label":"Peak sharpness a [-]","description":"Gaussian peak width is about 1/a.","min":1,"max":10,"step":1,"value":1}
//| cases:
//|   - {"id":"sharper-peak","label":"a = 4","description":"The default 50 subdivisions do not reach tolerance, so integrate_box returns an error.","inputs":{"sharpness":4}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"one-shot","path":"/rows/0/5","equals":"Success"}
//|       - {"artifact":"one-shot","path":"/rows/0/2","range":{"min":0,"max":1e-12}}
//|       - {"artifact":"one-shot","path":"/rows/1/4","equals":1377}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: sharper-peak
//|     expect:
//|       - {"artifact":"one-shot","path":"/rows/0/5","equals":"ConvergenceFailure"}
//|       - {"artifact":"one-shot","path":"/rows/1/5","equals":"BudgetLimit(Subdivision)"}
//|       - {"artifact":"one-shot","path":"/rows/2/5","equals":"HeuristicToleranceReached"}
//|       - {"path":"/outputs/1/state","equals":"failed"}
use scioxide_core::{Budget, Interval};
use scioxide_integrate::{CubaturePlan, SubdivisionOptions, integrate_box};

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let sig12 = serde_json::json!({ "significantDigits": 12 });
let (d, a) = (dimension.round() as usize, sharpness);
let f = |x: &[f64]| Ok(peak(x, a, true));
let exact = exact_peak(d, a, true)?;
let (lower, upper) = (vec![0.0_f64; d], vec![1.0_f64; d]);
// One-shot call: default SubdivisionOptions. Unsuccessful termination becomes an error.
let mut rows = vec![match integrate_box(&f, &lower, &upper) {
    Ok(r) => {
        let error = Some((r.value() - exact).abs());
        (
            "integrate_box",
            Some(r.value()),
            error,
            Some(r.error_estimate()),
            None,
            "Success".into(),
        )
    }
    Err(e) => (
        "integrate_box",
        None,
        None,
        None,
        None,
        format!("{:?}", e.kind()),
    ),
}];
// A plan with identical defaults and a plan with only the subdivision limit raised. Both return reports and estimates even when stopped.
let bounds = vec![Interval::new(0.0_f64, 1.0).map_err(|e| e.to_string())?; d];
for (name, limit) in [
    ("CubaturePlan (50 subdivisions)", 50),
    ("CubaturePlan (10⁴ subdivisions)", 10_000),
] {
    let budget = Budget::try_from(limit).map_err(|e| e.to_string())?;
    let options = SubdivisionOptions::default().with_max_subdivisions(budget);
    let plan = CubaturePlan::new(&bounds, options).map_err(|e| e.to_string())?;
    let (value, report) = plan.integrate(&f).map_err(|e| e.to_string())?;
    let error = Some((value - exact).abs());
    let status = report.termination().to_string();
    let evaluations = Some(report.evaluations());
    rows.push((
        name,
        Some(value),
        error,
        report.error_estimate(),
        evaluations,
        status,
    ));
}
let columns = serde_json::json!([
    { "key": "0", "label": "Call" },
    { "key": "1", "label": "Integral value [-]", "type": "number", "format": sig12, "nullText": "None" },
    { "key": "2", "label": "Difference from exact value [-]", "type": "number", "format": sci3, "nullText": "None" },
    { "key": "3", "label": "Error estimate [-]", "type": "number", "format": sci3, "nullText": "None" },
    { "key": "4", "label": "Evaluations [count]", "type": "integer", "nullText": "No report" },
    { "key": "5", "label": "Termination status or error" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "one-shot" })
);
// Use the one-shot call's success or failure as the conclusion, with the identical-default plan's termination status.
let (status, evaluations) = (rows[1].5.clone(), rows[1].4.unwrap_or(0) as f64);
let outcome = if rows[0].1.is_some() {
    Outcome::satisfied("integrate_box succeeded with default settings")
        .explanation("Error estimates are heuristic estimates, not bounds.")
} else {
    Outcome::failed("integrate_box returned no estimate")
        .explanation("The plan with identical defaults stops at its subdivision limit and returns the estimate at that point.")
};
emit_outcome!(
    outcome
        .status(status)
        .diagnostic("Default-plan evaluation count", evaluations, None)
);
```

With defaults ($d = 2$, $a = 1$), `integrate_box` succeeds with difference $4\times10^{-16}$ from the exact value and error estimate $2.7\times10^{-8}$.
The plan with identical defaults returns the same value with 1377 evaluations (40 splits) and `HeuristicToleranceReached`; raising the subdivision limit changes nothing.
Sharpening the peak to $a = 4$ makes the default plan stop after 1717 evaluations (50 splits) with `BudgetLimit(Subdivision)`, while `integrate_box` returns a `ConvergenceFailure` error.
The stopped plan's estimate is accurate, differing from exact by $8.1\times10^{-9}$, but error estimate $7.2\times10^{-6}$ exceeds tolerance $\sqrt\varepsilon\,(1 + |Q|) \approx 1.8\times10^{-8}$, so it is not considered successful.
Raising the subdivision limit to $10^4$ lets the plan reach tolerance after 12665 evaluations.
A one-shot call suffices for smooth low-dimensional integrals within default tolerance and 50 subdivisions; use `CubaturePlan` to retain stopped estimates, change tolerances or limits, or read evaluation counts.

## Summary

For smooth box integrals, `ProductRule` uses the same fixed rule per axis, with evaluation count $n^d$ and error $O(N^{-r/d})$; efficiency falls with dimension, but exponential convergence makes Gaussian rules most efficient for low-dimensional analytic integrands.
At $d \ge 2$, `CubaturePlan` uses the Genz–Malik degree-7/5 rule with $2^d + 2d(d-1) + 4d + 1$ points per region, bisecting along the largest fourth difference to concentrate evaluations on local changes such as kinks or peaks.
Its heuristic error estimate is four times the degree-7/degree-5 difference, and success is `HeuristicToleranceReached`; check actual error using known values or comparisons across tolerances.
Even when an evaluation limit stops a run, it returns a whole-domain estimate and error estimate; read termination status and treat these as partial results.
One-shot `integrate_box` uses default tolerance $\sqrt\varepsilon$ and 50 subdivisions, returning an error without an estimate if tolerance is not reached; use `CubaturePlan` to change limits or retain partial estimates.
