Approximating a definite integral

$$
I[f] = \int_\Omega f(\boldsymbol{x})\,w(\boldsymbol{x})\,d\boldsymbol{x}
$$

from finitely many function evaluations arises in weak formulations of partial differential equations, partition functions in statistical mechanics, marginalization in Bayesian inference, and uncertainty propagation.
Here $f$ is the integrand, $w$ is a known weight function ($w \equiv 1$ if no weight is needed), and $\Omega$ is the integration domain.
Only a limited set of integrands have antiderivatives expressible in elementary functions, so in general the integral is approximated by the weighted sum over nodes $\boldsymbol{x}_i$ and weights $w_i$,

$$
Q_n[f] = \sum_{i=1}^n w_i\,f(\boldsymbol{x}_i)
$$


This approximation is called quadrature, or also cubature in multiple dimensions.

## Role of the crate

`scioxide-integrate` computes definite integrals of real-, complex-, and vector-valued integrands and sums of infinite series with `f32` and `f64`.
The supported problems and main APIs are as follows.

- One-dimensional fixed rules: `NewtonCotes` for equally spaced nodes, `GaussianRulePlan` for Gaussian rules with classical weights, `ClenshawCurtis` for Chebyshev extrema, `GaussKronrod` for embedded pairs, and `Romberg` for extrapolation of the trapezoidal rule.
- One-dimensional adaptive quadrature: `AdaptiveIntegrator` for global adaptation and `DoubleExponentialIntegrator` for endpoint singularities and infinite intervals.
- Weighted quadrature and oscillatory integrals: `WeightedQuadraturePlan` for endpoint weights, principal values, and Fourier weights; `FourierTailPlan` for Fourier integrals on a semi-infinite interval; `OscillatoryQuadraturePlan` for nonlinear phases; and `ContourPlan` for complex contours.
- Sampled data and series: `SampledTrapezoidPlan`, `SampledSimpsonPlan`, and `SampledRombergPlan` for stored samples, and `SeriesSummation` for series acceleration and Euler–Maclaurin summation.
- Multidimensional quadrature: `ProductRule` for tensor product rules, `CubaturePlan` for adaptive cubature, `IteratedDomainPlan` for domains whose endpoints depend on outer coordinates, `SimplexRule`, `LebedevRule`, and `SphereProductRule` for simplices and spheres, and `SparseGridPlan` for sparse grids.
- Monte Carlo: `MonteCarloIntegrator` for uniform, importance, and stratified sampling, and `VegasTrainer` and `MiserTrainer` for learned mappings and stratification.
- Parameter sensitivities: `QuadratureSensitivityPlan` for JVPs and VJPs of integrals with respect to parameters.

Use a one-shot function if you only need the answer with default settings.
There are 11: `scioxide_integrate::integrate` (finite intervals), `integrate_piecewise` (known breakpoints), `integrate_fourier` (Fourier weights), `integrate_unbounded` (infinite intervals), `integrate_box` (hyperrectangles), `integrate_iterated` (variable endpoints), `integrate_monte_carlo` (Monte Carlo), `trapezoid`, `simpson`, and `cumulative_trapezoid` (sampled data), and `sum_series` (infinite series).
Each creates a Plan with default settings and a workspace on the spot, executes sequentially, and turns unsuccessful termination into an error.
The six functions from `integrate` through `integrate_iterated` return a value and error estimate in `Integral`.
`integrate_monte_carlo` returns the statistics `MonteCarloStatistics`, `sum_series` returns `SeriesResult`, and the three sampled-data functions return only the value (`Vec` for cumulative integration).
Configure one of the Plans or integrators above to change the method, tolerances, or limits, or to inspect the termination reason and evaluation count.

Errors returned by this crate are estimates and do not prove an upper bound on the true error.
If you need an interval guaranteed to contain the integral (a guaranteed enclosure), use the one-shot function `scioxide_validated::integrate` or verifier `QuadratureVerifier` in `scioxide-validated`.
There, the user supplies interval extensions of the integrand (functions enclosing values or higher derivatives in intervals), and interval arithmetic encloses the remainder terms of the trapezoidal and four-point Gauss–Legendre rules.
No crate provides symbolic integration that produces an antiderivative as an expression.

## First computation: an integral representation of a Bessel function

The Bessel function of the first kind $J_0$ appears in diffraction by circular apertures and sideband amplitudes in frequency modulation, and has the following integral representation.

$$
J_0(x) = \frac{1}{\pi}\int_0^\pi \cos(x\sin\theta)\,d\theta .
$$

The integrand is smooth, but for large $x$ it oscillates about $x/\pi$ times over $[0,\pi]$.
The next cell computes this integral with the one-shot function `integrate(f, a, b)` and compares it with `bessel_j` from `scioxide-special`.
`integrate` combines a globally adaptive Gauss–Kronrod rule (G7K15) with extrapolation using Wynn's ε algorithm, with absolute and relative tolerances both $\sqrt\varepsilon \approx 1.5\times10^{-8}$ and a limit of 50 bisections.
The returned `Integral` contains the value `value()` and error estimate `error_estimate()`.
The input is the argument $x$, and the output is a table of the integral, reference value, actual error, and error estimate.

```rust
//| id: integrate-first-one-shot
//| ref: integrate-first-one-shot
//| title: "Evaluate an integral representation of the Bessel function J₀ with a one-shot function"
//| run: reactive
//| crates: [scioxide-core, scioxide-integrate, scioxide-special]
//| inputs:
//|   argument: {"type":"range","label":"Argument x [-]","description":"Larger values increase integrand oscillations.","min":0,"max":80,"step":1,"value":10}
//| cases:
//|   - {"id":"many-oscillations","label":"x = 80","description":"The tolerance is satisfied within the default limit even with more oscillations.","inputs":{"argument":80}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"one-shot","path":"/rows/0/0","approx":{"value":-0.245935764451348,"atol":1e-9}}
//|       - {"artifact":"one-shot","path":"/rows/0/2","range":{"min":0,"max":1e-8}}
//|   - case: many-oscillations
//|     expect:
//|       - {"artifact":"one-shot","path":"/rows/0/2","range":{"min":0,"max":1e-8}}
use scioxide_core::RealScalar;
use scioxide_integrate::integrate;

let x = argument;
// Integrand cos(x sin θ)/π. Call SciOxide functions through RealScalar.
let integrand =
    |theta: f64| Ok(RealScalar::cos(x * RealScalar::sin(theta)) / std::f64::consts::PI);
let result = integrate(integrand, 0.0, std::f64::consts::PI).map_err(|e| e.to_string())?;
// Independent reference value: J₀(x) from scioxide-special's series and asymptotic expansions.
let reference = scioxide_special::bessel_j(0.0, x).map_err(|e| e.to_string())?;
let sig15 = serde_json::json!({ "significantDigits": 15 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "Integral Q [-]", "type": "number", "format": sig15 },
    { "key": "1", "label": "Reference J₀(x) [-]", "type": "number", "format": sig15 },
    { "key": "2", "label": "Actual error |Q − J₀| [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "Error estimate [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    vec![(
        result.value(),
        reference,
        (result.value() - reference).abs(),
        result.error_estimate(),
    )],
    metadata = serde_json::json!({ "id": "one-shot" })
);
```

At the default $x = 10$, the integral $-0.245935764451349$ differed from the reference by about $2\times10^{-16}$, while the error estimate was $7.7\times10^{-9}$.
The estimate is about 7 orders of magnitude larger than the actual error; it only indicates that the computation stopped when the tolerance $\sqrt\varepsilon$ was met and is not an upper bound.
At $x = 80$, the difference was also about $10^{-16}$ and the estimate was $1.5\times10^{-8}$.
Since `integrate` returns an error on failure, returning a value itself indicates success.

Use a configured integrator to set tolerances and limits yourself or inspect the termination reason, evaluation count, and error-estimate breakdown.
The next cell computes the same integral with the Gauss–Kronrod rule (G7K15) in `AdaptiveIntegrator`, without extrapolation.
The inputs are the argument $x$, tolerance exponent $q$, and bisection limit.
The tolerance is used as both the absolute tolerance $\varepsilon_{\mathrm{abs}} = 10^q$ and relative tolerance $\varepsilon_{\mathrm{rel}} = 10^q$; computation stops when the total error estimate $E$ is at most $\varepsilon_{\mathrm{abs}} + \varepsilon_{\mathrm{rel}}|Q|$.
Because $J_0$ oscillates around 0 as $x$ varies, a relative tolerance alone makes the criterion too strict.
The outputs are a table of the value and evaluation count, a table breaking down the error estimate, and an assessment of the termination reason.
In the breakdown table, $E$ is `error_estimate()`; it is $E = \max(\text{discretization}, \text{rounding}) + \text{inner} + \text{moments} + \text{extrapolation} + \text{tail}$ rather than the sum of the discretization estimate and the accuracy floor due to rounding error (the last 4 terms are not estimated in this example and contribute 0).

```rust
//| id: integrate-first-bessel-j0
//| ref: integrate-first-bessel-j0
//| title: "Evaluate an integral representation of the Bessel function J₀ with adaptive Gauss–Kronrod quadrature"
//| run: reactive
//| crates: [scioxide-core, scioxide-integrate, scioxide-special]
//| inputs:
//|   argument: {"type":"range","label":"Argument x [-]","description":"Larger values increase integrand oscillations.","min":0,"max":80,"step":1,"value":10}
//|   tolerance_exponent: {"type":"range","label":"Tolerance exponent q [-]","description":"Set absolute and relative tolerances both to 10^q.","min":-14,"max":-4,"step":1,"value":-10}
//|   max_subdivisions: {"type":"range","label":"Bisection limit [count]","description":"Stops with BudgetLimit when the limit is reached.","min":1,"max":50,"step":1,"value":50}
//| cases:
//|   - {"id":"many-oscillations","label":"x = 80","description":"More oscillations increase the evaluation and bisection counts.","inputs":{"argument":80}}
//|   - {"id":"subdivision-limit","label":"At most 2 bisections","description":"At x = 80, limiting bisection to 2 stops with BudgetLimit before the tolerance is met.","inputs":{"argument":80,"max_subdivisions":2}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","approx":{"value":-0.245935764451348,"atol":1e-9}}
//|       - {"artifact":"summary","path":"/rows/0/2","range":{"min":0,"max":1e-10}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: many-oscillations
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/2","range":{"min":0,"max":1e-10}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: subdivision-limit
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/6","equals":"BudgetLimit(Subdivision)"}
//|       - {"path":"/outputs/2/state","equals":"partial"}
use scioxide_core::{Budget, ErrorTolerance, Interval, NormSelection, RealScalar};
use scioxide_integrate::{AdaptiveIntegrator, AdaptiveRule, SubdivisionOptions};

let x = argument;
let requested = 10.0_f64.powf(tolerance_exponent);
let options = SubdivisionOptions::default()
    .with_tolerance(
        ErrorTolerance::scalar(requested, requested, NormSelection::Infinity)
            .map_err(|e| e.to_string())?,
    )
    .with_max_subdivisions(
        Budget::try_from(max_subdivisions as usize).map_err(|e| e.to_string())?,
    );
let plan =
    AdaptiveIntegrator::new(AdaptiveRule::GaussKronrod, options).map_err(|e| e.to_string())?;

// Integrand cos(x sin θ)/π. Call SciOxide functions through RealScalar.
let integrand =
    |theta: f64| Ok(RealScalar::cos(x * RealScalar::sin(theta)) / std::f64::consts::PI);
let domain = Interval::new(0.0, std::f64::consts::PI).map_err(|e| e.to_string())?;
let (value, report) = plan
    .integrate(integrand, domain)
    .map_err(|e| e.to_string())?;

// Independent reference value: J₀(x) from scioxide-special's series and asymptotic expansions.
let reference = scioxide_special::bessel_j(0.0, x).map_err(|e| e.to_string())?;
let threshold = requested + requested * value.abs();
let termination = report.termination();
let sig15 = serde_json::json!({ "significantDigits": 15 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let value_columns = serde_json::json!([
    { "key": "0", "label": "Integral Q [-]", "type": "number", "format": sig15 },
    { "key": "1", "label": "Reference J₀(x) [-]", "type": "number", "format": sig15 },
    { "key": "2", "label": "Actual error |Q − J₀| [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "Threshold ε_abs + ε_rel|Q| [-]", "type": "number", "format": sci3 },
    { "key": "4", "label": "Evaluation count [count]", "type": "integer" },
    { "key": "5", "label": "Bisection count [count]", "type": "integer" },
    { "key": "6", "label": "Termination reason" }
]);
emit_table_with_columns!(
    value_columns,
    vec![(
        value,
        reference,
        (value - reference).abs(),
        threshold,
        report.evaluations(),
        report.subdivisions(),
        termination.to_string(),
    )],
    metadata = serde_json::json!({ "id": "summary" })
);

// Error-estimate breakdown. Adaptive Gauss–Kronrod fills the discretization and rounding components.
let components = report.error_components();
let discretization = components.and_then(|parts| parts.discretization());
let reliability = discretization.map(|estimate| format!("{:?}", estimate.reliability()));
let error_columns = serde_json::json!([
    { "key": "0", "label": "Discretization error estimate [-]", "type": "number", "format": sci3, "nullText": "Not estimated" },
    { "key": "1", "label": "Estimate kind", "nullText": "None" },
    { "key": "2", "label": "Rounding error floor [-]", "type": "number", "format": sci3, "nullText": "Not estimated" },
    { "key": "3", "label": "Total error estimate E [-]", "type": "number", "format": sci3, "nullText": "Undefined" }
]);
emit_table_with_columns!(
    error_columns,
    vec![(
        discretization.map(|estimate| estimate.magnitude()),
        reliability,
        components.and_then(|parts| parts.roundoff()),
        report.error_estimate(),
    )],
    metadata = serde_json::json!({ "id": "error-parts" })
);

let outcome = if termination.is_success() {
    Outcome::satisfied("The estimated error satisfies the tolerance")
        .explanation("The estimate is not an upper bound; check against the reference value.")
} else {
    Outcome::partial("Stopped before satisfying the tolerance")
        .explanation("Read the tabulated integral as an estimate covering the entire interval, then increase the limit and recompute.")
};
let mut outcome = outcome
    .status(termination.to_string())
    .diagnostic("Evaluation count", report.evaluations() as f64, None)
    .diagnostic("Actual error", (value - reference).abs(), None);
if let Some(estimate) = report.error_estimate() {
    outcome = outcome.diagnostic("Error estimate", estimate, None);
}
emit_outcome!(outcome);
```

With the defaults ($x = 10$, $q = -10$), 7 bisections and 225 ($15 + 30 \times 7$) evaluations gave `ToleranceReached`.
The integral $-0.245935764451349$ differs from the reference by about $4\times10^{-16}$, while the error estimate $E \approx 8\times10^{-13}$ meets the threshold $1.2\times10^{-10}$ and is about 3 orders of magnitude larger than the actual error.
When a smooth integrand is resolved, Gauss–Kronrod error estimates are often conservative (pessimistic) in this way.
At $x = 80$, increased oscillation required 41 bisections and 1245 evaluations.
Limiting bisection to 2 gave `BudgetLimit(Subdivision)` after 75 evaluations; the integral differed from the reference by $4.7\times10^{-3}$, and the error estimate was $0.62$.
The assessment is then `partial`: although the tabulated integral is an estimate covering the entire interval, it does not satisfy the tolerance.

## Reading the results

One-shot functions turn unsuccessful termination into errors (for example, `EvaluationLimit` or `ResourceLimit` of `ConvergenceFailure` for limits, or `Stagnation` for stagnation).
You therefore read either the value and error estimate in `Integral` or the error classification.
A configured integrator returns a value and `IntegrationReport`.
The report contains the single authoritative termination reason `termination()`, evaluation count `evaluations()`, bisection count `subdivisions()`, error estimate `error_estimate()`, and its breakdown `error_components()`.
Read them in this order.

1. Check `is_success()` for success.
   There are five successful reasons: `ToleranceReached` (the error estimate satisfies the tolerance), `HeuristicToleranceReached` (an empirical estimate such as observed decay satisfies the tolerance), `FixedRuleCompleted` (a fixed rule was applied once; the tolerance was not checked), `SampleBudgetCompleted` (Monte Carlo used all requested samples), and `DegenerateDomain` (the domain has measure 0, so the result is exactly 0).
2. On unsuccessful termination, inspect reasons such as `BudgetLimit`, `RefinementLimit`, or `Stagnation` and choose whether to increase the limit, subdivide the domain in advance, or change the method.
   The returned value is an estimate covering the entire domain and does not imply that the tolerance is met.
   If computation stops before an estimate of the entire domain is available, an error (such as `ConvergenceFailure`) is returned instead of a value.
3. Check the kind of error estimate.
   `ErrorReliability::Estimated` is an estimate from the difference between two rules or stages, and `ErrorReliability::Heuristic` is an estimate inferred from observed decay of contributions; neither is an upper bound.
   Estimates can be arbitrarily wrong if structure absent from the samples exists, such as a narrow peak hidden between nodes.
4. Check independently.
   Assess the estimate against a known value, a different method, or comparisons with different tolerances or orders.

Monte Carlo returns a sample standard error and confidence interval instead of a deterministic error estimate; these estimate statistical uncertainty.

## Summary

Use a one-shot function when you only need a value with default settings, and read the error classification if it does not succeed.
To choose the method or limits, compute with a configured Plan and reusable workspace, receiving a value and report.
Read `is_success()` and the termination reason first; do not confuse `FixedRuleCompleted` or `BudgetLimit` with satisfaction of the tolerance.
Neither `Estimated` nor `Heuristic` is an upper bound, so check error estimates against known values, other methods, or comparisons with different settings.
If a proven upper bound is needed, use `scioxide_validated::integrate` or `QuadratureVerifier` from `scioxide-validated`.
