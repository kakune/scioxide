Surface methods depend strongly on sample geometry.
Rectilinear grids allow closed local interpolation per cell.
Scattered observations use distance-based radial kernels or [Delaunay interpolation](../scattered-tessellations/).
This page covers bilinear, bicubic, and RBF matrices and conditioning.

## Rectangular grids and bilinear interpolation

Assume values on Cartesian products of $x$ nodes $x_0<x_1<\dots<x_{n_x-1}$ and $y$ nodes $y_0<\dots<y_{n_y-1}$.
Spacing may be irregular.
Binary axis searches locate cell $[x_i,x_{i+1}]\times[y_j,y_{j+1}]$ containing $(x,y)$ in $O(\log n_x+\log n_y)$ work.

Using local cell coordinates

$$
u=\frac{x-x_i}{x_{i+1}-x_i},\qquad v=\frac{y-y_j}{y_{j+1}-y_j}\qquad(0\le u,v\le1)
$$

bilinear interpolation combines corners $z_{00},z_{10},z_{01},z_{11}$, indexed by offsets in $x$ then $y$, as follows.

$$
z(u,v)=(1-u)(1-v)z_{00}+u(1-v)z_{10}+(1-u)vz_{01}+uvz_{11}
$$


Four nonnegative weights sum to one, making convex combinations within corner extrema.
Surfaces are boundary-continuous ($C^0$), but first partials generally jump.
Cell terms $uv$ give hyperbolic paraboloids rather than planes.
Smooth data at spacing $h$ have error $O(h^2)$.

`BilinearInterpolator` implements only `Interpolant`, not `Differentiable`.
Interior formulas differentiate formally, but boundary gradients are undefined.

## Bicubic Hermite patches

For continuous cross-cell gradients, represent cells by bicubics

$$
z(u,v)=\sum_{a=0}^3\sum_{b=0}^3c_{ab}u^av^b=\boldsymbol u^\mathsf T C\boldsymbol v,\qquad
\boldsymbol u=[1,u,u^2,u^3]^\mathsf T,\ \boldsymbol v=[1,v,v^2,v^3]^\mathsf T
$$


with sixteen coefficients $c_{ab}$ determined uniquely by corner values $z$, local partials $z_u$ and $z_v$, and mixed partials $z_{uv}$.
Let the univariate cubic-Hermite matrix mapping $[p(0),p(1),p'(0),p'(1)]$ to coefficients $[a_0,a_1,a_2,a_3]$ be

$$
B=\begin{bmatrix}
1&0&0&0\\
0&0&1&0\\
-3&3&-2&-1\\
2&-2&1&1
\end{bmatrix}
$$

then the coefficient matrix is $C=BMB^\mathsf T$.
Here $M$ is $4\times4$, arranging corner $z,z_u,z_v,z_{uv}$ with $u$-direction rows $[\,\cdot(0),\cdot(1),\partial_u\cdot(0),\partial_u\cdot(1)]$ and matching $v$-direction columns.
Local derivatives multiply physical derivatives by widths $h_x=x_{i+1}-x_i$ and $h_y=y_{j+1}-y_j$, giving $z_u=h_x\,\partial z/\partial x$, $z_v=h_y\,\partial z/\partial y$, and $z_{uv}=h_xh_y\,\partial^2z/\partial x\partial y$.
Adjacent cells share values and tangential and transverse edge derivatives.
Physical nodal derivatives agree from every cell, producing $C^1$ surfaces.

Without derivative data, `BicubicInterpolator::new` estimates from quadratics through three consecutive nodes per axis.
Use centered triples internally and inward-shifted triples at ends, exactly differentiating quadratics even with irregular spacing.
Two-node axes use secant slopes.
Mixed partials tensor both axis estimates.
With at least three nodes per axis, biquadratics through degree two per axis, including $x^2y^2$, reproduce within rounding.
Second derivatives generally jump across cells, so global surfaces are not $C^2$.
Very unequal gaps can amplify sample errors in derivative estimates; successful construction guarantees no accuracy.

Named `BicubicInterpolator::monotone(x, y, z)` constructs both-axis-monotone $C^1$ surfaces from monotone grid values.
Every real component must have one global increasing/decreasing direction per axis; direction reversals give `InvalidInput`.
Constant intervals are allowed; wholly constant axes count as increasing.
Nodal first partials are PCHIP slopes reduced by sufficient Bernstein conditions; mixed partials are zero.
Monotonicity holds throughout closed cells within rounding, avoiding corner overshoot.
Planes reproduce, but general quadratics or bilinear $xy$ do not, and surfaces may flatten excessively.
Monotonicity does not extend to extrapolation.
Separation always uses `NodeSeparation::Exact`; there is no settings-taking form.

Preparation costs $O(n_xn_y)$ work and storage per component, sixteen coefficients per cell.
Queries cost $O(\log n_x+\log n_y)$; reserved `evaluate_into` and similar forms allocate nothing.
`BicubicInterpolator` implements `Differentiable` and `TwiceDifferentiable`, returning physical gradients/Hessians.
Hessians are within-cell second derivatives, not necessarily boundary-continuous.
Under `Clamp`, outside-axis derivatives vanish; `BoundedContinue` and `MethodDefined` extend outermost cells.

## Grid-value layout

`BilinearInterpolator::new(x, y, z)` and `BicubicInterpolator::new(x, y, z)` accept two axes and flattened values.
Change separation by passing `SampleOptions` to each `with_options(x, y, z, options)`.
Values use row-major $n_y\times n_x$ with `z[j * nx + i]` equal to value $(x_i,y_j)$.
Thus index $x$ varies fastest.
Each axis needs two or more strictly increasing nodes, otherwise `InvalidInput`.
Value counts unequal to $n_xn_y$ give `DimensionMismatch`.
Real, complex, or array values interpolate identically per real component.
Two-dimensional tensor B-spline controls use last-axis-fastest row-major; axes ordered `(x, y)` make $y$ vary fastest.
Index roles reverse relative to grid interpolation; check shape and components first.

## Reproduction and derivatives on irregular grids

The next cell gives $f(x,y)=x+2y+x^2y^2$ values on grids of $n$ nodes per axis and compares bilinear, bicubic, and monotone bicubic surfaces.
$f$ is quadratic per axis and increasing on both $[0,1]^2$ axes, permitting monotone construction.
Axis $x$ uses $x_i=(1-w)t_i+wt_i^2$ for $t_i=i/(n-1)$, clustering near the origin as $w$ grows.
Axis $y$ is uniform.
$f$ is asymmetric in $x$ and $y$; wrong layouts give large errors.
Outputs show maximum value errors over $41\times41$ points and gradient/Hessian errors at $(0.3,0.7)$.
Independent checks use analytic gradient $(1+2xy^2,\ 2+2x^2y)$ and Hessian $\begin{bmatrix}2y^2&4xy\\4xy&2x^2\end{bmatrix}$.
Bicubic biquadratic reproduction predicts rounding-sized errors on every $n\ge3$ grid.

```rust
//| id: interp-grid-biquadratic
//| ref: interp-grid-biquadratic
//| title: "Compare bilinear, bicubic, and monotone bicubic errors on irregular grids"
//| run: reactive
//| crates: [scioxide-interp]
//| inputs:
//|   nodes: {"type":"range","label":"Nodes n per axis","min":3,"max":12,"step":1,"value":5}
//|   grading: {"type":"range","label":"x-node bias w [-]","description":"Uniform at 0; xᵢ = tᵢ² at 1.","min":0,"max":1,"step":0.05,"value":0.5}
//| cases:
//|   - {"id":"three-uniform","label":"n = 3, uniform","description":"Three nodes per axis still reproduce biquadratics bicubically; bilinear errors are large.","inputs":{"nodes":3,"grading":0}}
//|   - {"id":"fine-graded","label":"n = 12, w = 1","description":"Added nodes reduce bilinear and monotone errors; bicubic remains at rounding.","inputs":{"nodes":12,"grading":1}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"errors","path":"/rows/0/1","approx":{"value":0.03481406250000019,"rtol":1e-6}}
//|       - {"artifact":"errors","path":"/rows/0/2","equals":null}
//|       - {"artifact":"errors","path":"/rows/1/1","range":{"max":1e-14}}
//|       - {"artifact":"errors","path":"/rows/1/3","range":{"max":1e-12}}
//|       - {"artifact":"errors","path":"/rows/2/1","approx":{"value":0.004335392891359202,"rtol":1e-6}}
//|   - case: three-uniform
//|     expect:
//|       - {"artifact":"errors","path":"/rows/0/1","approx":{"value":0.0806558593750002,"rtol":1e-6}}
//|       - {"artifact":"errors","path":"/rows/1/1","range":{"max":1e-14}}
//|   - case: fine-graded
//|     expect:
//|       - {"artifact":"errors","path":"/rows/1/1","range":{"max":1e-14}}
//|       - {"artifact":"errors","path":"/rows/2/1","approx":{"value":0.0006365129048719886,"rtol":1e-6}}
use scioxide_interp::{
    BicubicInterpolator, BilinearInterpolator, Differentiable, ExtrapolationPolicy,
    Interpolant, TwiceDifferentiable,
};

// f(x, y) = x + 2y + x²y², quadratic per axis and increasing on [0, 1]²
let f = |x: f64, y: f64| x + 2.0 * y + x * x * y * y;
let n = nodes as usize;
let t = |i: usize| i as f64 / (n - 1) as f64;
// x nodes blend tᵢ and tᵢ² by w; y is uniform
let x: Vec<f64> = (0..n)
    .map(|i| (1.0 - grading) * t(i) + grading * t(i) * t(i))
    .collect();
let y: Vec<f64> = (0..n).map(t).collect();
// Row-major z[j * nx + i] = f(x[i], y[j]), x fastest
let z: Vec<f64> = y
    .iter()
    .flat_map(|&yj| x.iter().map(move |&xi| f(xi, yj)))
    .collect();
let bilinear =
    BilinearInterpolator::new(x.clone(), y.clone(), z.clone()).map_err(|e| e.to_string())?;
let bicubic =
    BicubicInterpolator::new(x.clone(), y.clone(), z.clone()).map_err(|e| e.to_string())?;
let monotone = BicubicInterpolator::monotone(x, y, z).map_err(|e| e.to_string())?;
let policy = ExtrapolationPolicy::Reject;
let mut errors = [0.0_f64; 3];
for i in 0..=40 {
    for j in 0..=40 {
        let point = [i as f64 / 40.0, j as f64 / 40.0];
        let exact = f(point[0], point[1]);
        let values = [
            bilinear
                .evaluate(point, policy)
                .map_err(|e| e.to_string())?,
            bicubic.evaluate(point, policy).map_err(|e| e.to_string())?,
            monotone
                .evaluate(point, policy)
                .map_err(|e| e.to_string())?,
        ];
        for (error, value) in errors.iter_mut().zip(values) {
            *error = error.max((value - exact).abs());
        }
    }
}
// Independent analytic gradient/Hessian at (0.3, 0.7), row-major
let (px, py) = (0.3, 0.7);
let gradient = [1.0 + 2.0 * px * py * py, 2.0 + 2.0 * px * px * py];
let hessian = [2.0 * py * py, 4.0 * px * py, 4.0 * px * py, 2.0 * px * px];
let derivative_errors = |model: &BicubicInterpolator<f64>| -> Result<(f64, f64), String> {
    let g = model
        .gradient([px, py], policy)
        .map_err(|e| e.to_string())?;
    let h = model.hessian([px, py], policy).map_err(|e| e.to_string())?;
    let largest = |m: f64, (a, b): (&f64, f64)| m.max((a - b).abs());
    let gradient_error = g.iter().zip(gradient).fold(0.0, largest);
    Ok((
        gradient_error,
        h.as_flattened().iter().zip(hessian).fold(0.0, largest),
    ))
};
let (cubic_gradient, cubic_hessian) = derivative_errors(&bicubic)?;
let (monotone_gradient, monotone_hessian) = derivative_errors(&monotone)?;
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "Method" },
    { "key": "1", "label": "Maximum value error [-]", "type": "number", "format": sci3 },
    {
        "key": "2",
        "label": "Gradient error [-]",
        "type": "number",
        "format": sci3,
        "nullText": "No Differentiable"
    },
    {
        "key": "3",
        "label": "Hessian error [-]",
        "type": "number",
        "format": sci3,
        "nullText": "No TwiceDifferentiable"
    }
]);
let rows = vec![
    ("Bilinear", errors[0], None, None),
    (
        "Bicubic",
        errors[1],
        Some(cubic_gradient),
        Some(cubic_hessian),
    ),
    (
        "Monotone bicubic",
        errors[2],
        Some(monotone_gradient),
        Some(monotone_hessian),
    ),
];
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "errors" })
);
```

At defaults $n=5$ and $w=0.5$, maximum bicubic error is $4.4\times10^{-16}$; gradient and Hessian errors are rounding-sized too.
Bilinear maximum is $3.5\times10^{-2}$ and monotone bicubic $4.3\times10^{-3}$.
Monotone Hessian error 0.37 greatly exceeds value and gradient errors.
Zero mixed partials and reduced slopes prevent overshoot rather than matching second derivatives.
Even uniform grids with three nodes per axis (`three-uniform`) retain bicubic error $8.9\times10^{-16}$, while bilinear error rises to $8.1\times10^{-2}$.
At $n=12$ and $w=1$ (`fine-graded`), bilinear error falls to $8.4\times10^{-3}$ and monotone bicubic error to $6.4\times10^{-4}$, while the bicubic Hessian error is $1.2\times10^{-14}$.
Bicubic errors remain at rounding scale regardless of node count or bias because $f$ belongs to the space of biquadratic polynomials; this does not indicate accuracy for general functions.

## Scattered radial-basis interpolation

Without grid structure for points $\boldsymbol x_1,\dots,\boldsymbol x_N\in\mathbb R^2$ and values $y_i$, combine sample-centered kernels $\phi(r)$ linearly as

$$
s(\boldsymbol x)=\sum_{j=1}^Nw_j\,\phi(\|\boldsymbol x-\boldsymbol x_j\|_2)
$$

Interpolation $s(\boldsymbol x_i)=y_i$ makes weights $\boldsymbol w$ solve

$$
K\boldsymbol w=\boldsymbol y,\qquad K_{ij}=\phi(\|\boldsymbol x_i-\boldsymbol x_j\|_2)
$$

$K$ is a symmetric dense $N\times N$ matrix.

### Kernels and nonsingularity

`RbfKernel` kernels and matrix $K$ properties follow.
$r\ge0$ is Euclidean distance; shape $c$ must be finite positive.

| Kernel | $\phi(r)$ | $K$ for distinct points |
| :--- | :--- | :--- |
| `Gaussian(c)` | $\exp(-c^2r^2)$ | Positive definite, $C^\infty$, rapidly decaying |
| `InverseMultiquadric(c)` | $1/\sqrt{1+(cr)^2}$ | Positive definite, slowly decaying like $1/(cr)$ |
| `Multiquadric(c)` | $\sqrt{1+(cr)^2}$ | Nonsingular indefinite; at $N\ge2$ one positive eigenvalue and $N-1$ negative |
| `ThinPlateSpline` | $r^2\ln r$, zero at $r=0$ | Conditionally positive definite of order two; potentially singular without polynomial terms |

Positive-definite kernels always give nonsingular $K$ at distinct points.
Multiquadric matrices are also nonsingular there (Micchelli 1986).
Thin plates need affine polynomial terms and weights orthogonal to them, with noncollinear samples, for uniqueness.
The interpolant then minimizes bending energy $\int_{\mathbb R^2}(s_{xx}^2+2s_{xy}^2+s_{yy}^2)\,dx\,dy$.
Without polynomial terms, three pairwise-distance-one points have $\ln1=0$ and zero matrix $K$.
`RbfInterpolator` solves kernel matrices alone, without polynomial terms.
Thus even thin plates reproduce no affine functions exactly and lack the variational property.
Use [Local RBFs](oxref:interp-local-samples) for neighborhood polynomial augmentation.

### Shape parameters and conditions

Gaussian/inverse multiquadric shape $c$ controls width about $1/c$.
Large $c$ gives fast decay and $K$ near identity, with condition near 1.
Between samples, however, values fall toward zero and accuracy worsens.
Small $c$ near the flat limit may yield polynomial-like accuracy for smooth functions.
But similar columns of $K$ rapidly worsen conditioning.
This inverse accuracy/conditioning relationship is the uncertainty or trade-off principle (Schaback 1995).
Multiquadric does not make $K$ identity-like for large $c$, so this interpretation does not directly apply.

## RBF construction and diagnostics

Kernels define results and are arguments alongside samples rather than settings.
`RbfInterpolator::new(points, values, kernel)` owns coordinates/values and solves default $K\boldsymbol w=\boldsymbol y$.
`RbfInterpolator::with_options(points, values, kernel, options)` uses `RbfOptions` settings and solves $(K+\lambda I)\boldsymbol w=\boldsymbol y$ if regularized.
`build(points, values, kernel, options, scope)` performs the same preparation in caller scopes, counting one proposal.
`new` and `with_options` prepare sequentially on the calling thread.

`RbfOptions::new()`, equivalent to `Default`, defaults to no regularization, `NodeSeparation::Exact`, rank threshold `RankThreshold` with absolute/relative $\varepsilon$ (f64 $2.2\times10^{-16}$), minimum reciprocal condition 0, policy `Auto`, and unlimited memory.
Infallible setters change settings, checked at construction start.
`with_regularization` accepts `RbfRegularization::None` or `Diagonal(lambda)` adding diagonal $\lambda$, with finite positive $\lambda$.
`with_node_separation` governs duplicates; `with_rank_threshold` numerical rank.
`with_minimum_rcond` specifies minimum reciprocal condition in $[0,1]$; `with_maximum_bytes` estimated preparation memory limit; `with_execution_policy` factorization workers.

Construction errors follow.
An out-of-range shape parameter, $\lambda$, or minimum reciprocal condition number gives `InvalidInput`; a nonfinite value gives `NonFinite`.
Empty or indistinguishable points under separation give `InvalidInput`; count/shape mismatches `DimensionMismatch`.
Duplicates force equal rows in $K$ and singularity, so reject before factorization as invalid input.
Estimated memory above limits gives `ResourceLimit` before work.

Gaussian/inverse multiquadric use Cholesky; multiquadric/thin plates use partially pivoted LU.
Breakdown or failed rank/condition acceptance triggers SVD refactoring.
SVD treats singular values at most `abs_tol + rel_tol * σ_max` relative to maximum $\sigma_{\max}$ as deficient.
Rank below $N$ or reciprocal conditions below minimum still give `Singular` without truncated solutions.
Preparation uses $O(N^2)$ storage and $O(N^3)$ work; value queries cost $O(N)$ per component, allocation-free in reserved forms.

`RbfConditioning` from `conditioning()` holds `matrix_size()`, `numerical_rank()`, `rank_threshold()`, `factorization()` (`FitFactorization`), `used_fallback()`, `condition_norm()` (`FitConditionNorm`), and `reciprocal_condition_number()`.
Read reciprocal conditions for the solved regularized matrix in the actual factor's norm.
Cholesky/LU use 1-norm estimates, SVD smallest/largest 2-norm ratios; 1-norm values are not bounds.
Adding $\lambda$ improves conditioning but relaxes sample agreement.
This is smoothing rather than interpolation; $\lambda$ shares kernel-value units.

`RbfInterpolator` implements only `Interpolant<S, 2>`, without gradients/integrals.
Domains are axis-aligned bounding rectangles rather than hulls.
Even inside rectangles, far-sample values depend on kernel decay/growth without accuracy guarantees.
Extended-exponent kernel arithmetic handles intermediate out-of-range products, returning representable final values including subnormals.

## Kernel matrices versus shapes

The next cell constructs Gaussian matrices at five $x$-axis points $\{0,0.2,0.5,0.75,1\}$ ($y=0$), varying shape $c$.
Input shape $c$ [1/m] uses coordinates in m.
The first column independently checks maximum differences between `RbfKernel::evaluate` and f64 `exp` reference $e^{-(cr)^2}$.
Remaining columns report interpolation of values $\sin(\pi x)$.
Success shows rank, factors, condition and norm; `Singular` failures leave rank/condition blank.
Detailed `with_options` uses `with_rank_threshold` to set relative rank threshold $10^{-14}$, absolute zero.
The final column measures maximum $\sin(\pi x)$ error at four nonsample midpoints.
Matrix heatmaps fix color range $[0,1]$.

```rust
//| id: interp-rbf-shape-matrix
//| ref: interp-rbf-shape-matrix
//| title: "Vary Gaussian RBF shape parameters and interpolation matrices"
//| run: reactive
//| crates: [scioxide-core, scioxide-interp]
//| inputs:
//|   shape_parameter: {"type":"range","label":"Shape c [1/m]","description":"Change radial basis width.","min":0.01,"max":8,"step":0.01,"value":1.5}
//| cases:
//|   - {"id":"flat","label":"c = 0.5 /m","description":"Near-flat kernels reduce midpoint errors but reciprocal conditions fall to about 10⁻⁸.","inputs":{"shape_parameter":0.5}}
//|   - {"id":"fallback","label":"c = 0.07 /m","description":"Rejected Cholesky retries SVD, constructing rank 5.","inputs":{"shape_parameter":0.07}}
//|   - {"id":"singular","label":"c = 0.05 /m","description":"Rank falls below 5, stopping with Singular.","inputs":{"shape_parameter":0.05}}
//|   - {"id":"narrow","label":"c = 8 /m","description":"Near-identity matrices give nearly zero intersample values.","inputs":{"shape_parameter":8}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"construction","path":"/rows/0/0","range":{"max":1e-15}}
//|       - {"artifact":"construction","path":"/rows/0/1","equals":"Success"}
//|       - {"artifact":"construction","path":"/rows/0/2","equals":5}
//|       - {"artifact":"construction","path":"/rows/0/3","equals":"Cholesky"}
//|       - {"artifact":"construction","path":"/rows/0/4","approx":{"value":4.276266906633815e-4,"rtol":1e-6}}
//|       - {"artifact":"construction","path":"/rows/0/6","approx":{"value":2.111164088090256e-3,"rtol":1e-6}}
//|   - case: flat
//|     expect:
//|       - {"artifact":"construction","path":"/rows/0/4","approx":{"value":6.447990555305157e-8,"rtol":1e-3}}
//|       - {"artifact":"construction","path":"/rows/0/6","approx":{"value":5.077625752578085e-4,"rtol":1e-3}}
//|   - case: fallback
//|     expect:
//|       - {"artifact":"construction","path":"/rows/0/3","equals":"Svd"}
//|       - {"artifact":"construction","path":"/rows/0/5","equals":"Two"}
//|       - {"artifact":"construction","path":"/rows/0/6","approx":{"value":1.0306003338398928e-3,"rtol":1e-3}}
//|   - case: singular
//|     expect:
//|       - {"artifact":"construction","path":"/rows/0/1","equals":"Singular"}
//|       - {"artifact":"construction","path":"/rows/0/4","equals":null}
//|   - case: narrow
//|     expect:
//|       - {"artifact":"construction","path":"/rows/0/4","approx":{"value":0.8514407041576785,"rtol":1e-6}}
//|       - {"artifact":"construction","path":"/rows/0/6","approx":{"value":0.5181426536359379,"rtol":1e-6}}
use scioxide_core::{SciOxideErrorKind, RankThreshold, RealScalar};
use scioxide_interp::{ExtrapolationPolicy, Interpolant, RbfInterpolator, RbfKernel, RbfOptions};

// Five x-axis points, y = 0, in m
let xs = [0.0_f64, 0.2, 0.5, 0.75, 1.0];
let pi = std::f64::consts::PI;
let kernel = RbfKernel::Gaussian(shape_parameter);
let mut matrix = Vec::new();
let mut kernel_gap = 0.0_f64;
for (row, &a) in xs.iter().enumerate() {
    for (column, &b) in xs.iter().enumerate() {
        let value = kernel.evaluate((a - b).abs()).map_err(|e| e.to_string())?;
        // Independent f64 exp comparison against exp(-(c r)^2)
        let reference = (-(shape_parameter * (a - b)).powi(2)).exp();
        kernel_gap = kernel_gap.max((value - reference).abs());
        matrix.push([column as f64, row as f64, value]);
    }
}
let points: Vec<[f64; 2]> = xs.iter().map(|&x| [x, 0.0]).collect();
let values: Vec<f64> = xs.iter().map(|&x| RealScalar::sin(pi * x)).collect();
// No regularization; relative singular values at most 1e-14 are deficient
let threshold = RankThreshold::new(0.0_f64, 1.0e-14).map_err(|e| e.to_string())?;
let options = RbfOptions::new().with_rank_threshold(threshold);
// Show small-c Singular failures in the result table too
let row = match RbfInterpolator::with_options(points, values, kernel, options) {
    Ok(rbf) => {
        let c = rbf.conditioning();
        let mut error = 0.0_f64;
        for pair in xs.windows(2) {
            let x = 0.5 * (pair[0] + pair[1]);
            let value = rbf
                .evaluate([x, 0.0], ExtrapolationPolicy::Reject)
                .map_err(|e| e.to_string())?;
            error = error.max((value - RealScalar::sin(pi * x)).abs());
        }
        (
            kernel_gap,
            "Success".to_string(),
            Some(c.numerical_rank()),
            Some(format!("{:?}", c.factorization())),
            Some(c.reciprocal_condition_number()),
            Some(format!("{:?}", c.condition_norm())),
            Some(error),
        )
    }
    Err(e) if e.kind() == SciOxideErrorKind::Singular => (
        kernel_gap,
        "Singular".to_string(),
        None,
        None,
        None,
        None,
        None,
    ),
    Err(e) => return Err(e.to_string()),
};

let columns = serde_json::json!([
    { "key": "0", "label": "Kernel implementation difference [-]", "type": "number", "format": sci3 },
    { "key": "1", "label": "Construction" },
```

## Summary

Bilinear convex corners create no new extrema but lack continuous gradients and `Differentiable`.
Bicubic sixteen-coefficient patches use estimated first/mixed derivatives, reproducing per-axis quadratics in $C^1$ surfaces.
Use `BicubicInterpolator::monotone` for monotonicity, losing quadratic reproduction.
Pass row-major `z[j * nx + i]` grids and verify layouts with functions asymmetric in $x$ and $y$.
Scattered RBF dense matrices can change condition strongly with shape; inspect rank and reciprocal conditions in `RbfConditioning`.
For poor conditions enlarge shape or regularize through `RbfRegularization::Diagonal`, trading accuracy or sample agreement.
