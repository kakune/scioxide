This table collects contracts independent of interpolant type.
Evaluation capabilities are split among four traits.
`Interpolant` gives values, `Differentiable` gradients, `TwiceDifferentiable` Hessians, and `Integrable` definite integrals over boxes.
Interpolants implement only supported traits, rejecting unsupported combinations at compile time.

Gradients are supported by barycentric, Newton, Hermite, Akima, PCHIP, cubic splines, B-splines, NURBS, bicubic, simplex-linear, Clough–Tocher, and spherical splines.
Hessians are supported by B-splines, NURBS, bicubic, and spherical splines; integrals by Akima, PCHIP, cubic splines, B-splines, and spherical splines.
Neville, Bulirsch–Stoer, Floater–Hormann, `BarycentricRational`, Padé, bilinear, RBF, nearest, natural-neighbor, local-model, and Gaussian-process predictions provide values only.
Global polynomial integrals (barycentric, Newton, Hermite) use antiderivatives prepared with `prepare_antiderivative` rather than `Integrable`.
Every univariate interpolant implements scalar trait `Univariate` fixed to extrapolation policy `Reject`.

Policies have no defaults and must be specified on every policy-taking call.
Boundary points are inside; each method defines its domain as an interval, box, hull, or similar set.

Workspace has two layers.
For one point, pass interpolant `workspace()` workspace to `evaluate_into` or similar.
For batches, `BatchEvaluator::workspace(request)` preallocates per-worker model workspaces and temporary storage for every result.
Both avoid allocation after reservation; failed calls leave caller output unchanged.
Owned-result API `evaluate_many` without supplied workspace allocates a workspace and value array each call.
General workspace and partial-result contracts appear in [Workspaces and reproducibility](../../../concepts/workspaces-and-reproducibility/) and [Errors and partial results](../../../concepts/errors-and-partial-results/).

## Point evaluation and coordinate reports

The next cell evaluates at a single point a Newton interpolant of $p(x) = (x, x^2)$ constructed at three nodes $x = 0, 1, 2$.
Values are two-component vectors ordered $x$, $x^2$.
Pass interpolant `workspace()` workspace and caller array `[f64; 2]` to `evaluate_into_with_report` to receive values and coordinates together.
Controls are dimensionless evaluation $x$ from $-0.5$ to $2.5$ and extrapolation policy.
Fix the `BoundedContinue` limit at $0.25$.
Three-point quadratics reproduce quadratics exactly, including Newton extension; use $(t, t^2)$ at reported coordinate $t$ as an independent check.
On evaluation errors, leave value and report columns empty and show the kind.

```rust
use scioxide_interp::{ExtrapolationPolicy, Interpolant, NewtonInterpolator};

// Newton through p(x) = (x, x²) at three points; component order (x, x²), domain [0, 2]
let model = NewtonInterpolator::new(
    vec![0.0_f64, 1.0, 2.0],
    vec![[0.0, 0.0], [1.0, 1.0], [2.0, 4.0]],
)
.map_err(|e| e.to_string())?;
let extrapolation = match policy.as_str() {
    "bounded" => ExtrapolationPolicy::BoundedContinue { max_distance: 0.25 },
    "method" => ExtrapolationPolicy::MethodDefined,
    _ => ExtrapolationPolicy::Clamp,
};
// Create point workspace once and write caller arrays; failures leave value unchanged
let mut workspace = model.workspace().map_err(|e| e.to_string())?;
let mut value = [0.0; 2];
let evaluated =
    model.evaluate_into_with_report([query_x], extrapolation, &mut value, &mut workspace);
let row = match evaluated {
    Ok(report) => {
        let [effective] = report.effective();
        let [distance] = report.outside_distance();
        // Independent check: exact value at used t is (t, t²)
        let check = (value[1] - effective * effective).abs();
        (
            query_x,
            Some(effective),
            Some(distance),
            Some(value[0]),
            Some(value[1]),
            Some(check),
            None,
        )
    }
    Err(e) => (
        query_x,
        None,
        None,
        None,
        None,
        None,
        Some(format!("{:?}", e.kind())),
    ),
};

let sig = serde_json::json!({ "significantDigits": 15 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "x [-]", "type": "number", "format": fixed3 },
    { "key": "1", "label": "Used coordinate t [-]", "type": "number", "format": sig, "nullText": "—" },
    { "key": "2", "label": "Outside-domain distance [-]", "type": "number", "format": sig, "nullText": "—" },
    { "key": "3", "label": "First component [-]", "type": "number", "format": sig, "nullText": "—" },
    { "key": "4", "label": "Second component [-]", "type": "number", "format": sig, "nullText": "—" },
    { "key": "5", "label": "Second component minus t² [-]", "type": "number", "format": sci3, "nullText": "—" },
    { "key": "6", "label": "Error kind", "nullText": "—" }
]);

    columns,
    vec![row],

);
```

At defaults $x = 2.3$ and `Clamp`, used coordinate is $t = 2$ and distance about $0.3$, including rounded binary $2.3$ representation, $0.2999999999999998$.
Boundary value $(2, 4)$ and the report show `Clamp` projecting the query.
Switching to `MethodDefined` removes projection, giving $t = 2.3$ and value $(2.3, 5.29)$ with unchanged distance $0.3$.
`BoundedContinue` with limit $0.25$ rejects distance $0.3$ with `DomainError`, returning neither values nor reports.
Coordinate preparation compares limits before evaluation, rejecting overly distant queries first.
Moving $x$ inside $[0, 2]$ makes all policies use $t = x$ and zero distance, matching components $x$ and $x^2$ within rounding.

## Whole-batch success and failure

The next cell evaluates the same model twice at three points with `BatchEvaluator::new(&model, ExecutionPolicy::Sequential)`, checking unchanged output after failure.
Queries are row-major `[query, coordinate]` = `[3, 1]` and outputs `[query, component]` = `[3, 2]`.
Preallocate once with `BatchRequest::values(3)` and reuse for both calls.
The first evaluates in-domain $x = 0, 0.5, 2$.
The second evaluates $x = 1, 1.5$ and input-selected dimensionless third point from $1.5$ to $3$ under `Reject`.
A third point outside $[0, 2]$ should make call 2 give `DomainError`, preserving call-1 output.

```rust
//| id: interp-affine-batch-transaction
//| ref: interp-affine-batch-transaction
//| title: "Check failed batches preserve caller output"
//| run: reactive
//| crates: [scioxide-core, scioxide-interp]
//| inputs:
//|   third_x: {"type":"range","label":"Second-call third point x [-]","min":1.5,"max":3,"step":0.25,"value":2.5}
//| cases:
//|   - {"id":"boundary","label":"Third x = 2, boundary","description":"Boundary points are inside; call 2 succeeds and updates output.","inputs":{"third_x":2}}
//|   - {"id":"inside","label":"Third x = 1.5","description":"All points are inside, updating output to second-call (x, x²).","inputs":{"third_x":1.5}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"status","path":"/rows/0/0","equals":"Failed"}
//|       - {"artifact":"status","path":"/rows/0/1","equals":"DomainError"}
//|       - {"artifact":"batch","path":"/rows/0/4","equals":0}
//|       - {"artifact":"batch","path":"/rows/1/5","approx":{"value":0.25,"atol":1e-15}}
//|       - {"artifact":"batch","path":"/rows/2/5","approx":{"value":4,"atol":1e-14}}
//|   - case: boundary
//|     expect:
//|       - {"artifact":"status","path":"/rows/0/0","equals":"Success"}
//|       - {"artifact":"batch","path":"/rows/0/5","approx":{"value":1,"atol":1e-14}}
//|       - {"artifact":"batch","path":"/rows/2/5","approx":{"value":4,"atol":1e-14}}
//|   - case: inside
//|     expect:
//|       - {"artifact":"status","path":"/rows/0/0","equals":"Success"}
//|       - {"artifact":"batch","path":"/rows/1/5","approx":{"value":2.25,"atol":1e-14}}
//|       - {"artifact":"batch","path":"/rows/2/4","approx":{"value":1.5,"atol":1e-15}}
use scioxide_core::{ExecutionContext, ExecutionPolicy, NdView, NdViewMut, StridedLayout};
use scioxide_interp::{BatchEvaluator, BatchRequest, ExtrapolationPolicy, NewtonInterpolator};

// Newton through p(x) = (x, x²) at three points, domain [0, 2]
let model = NewtonInterpolator::new(
    vec![0.0_f64, 1.0, 2.0],
    vec![[0.0, 0.0], [1.0, 1.0], [2.0, 4.0]],
)
.map_err(|e| e.to_string())?;
let policy = ExtrapolationPolicy::Reject;
// Borrow the interpolant in a sequential one-worker evaluator
let evaluator = BatchEvaluator::new(&model, ExecutionPolicy::Sequential);
// Preallocate for three value queries once and reuse across two evaluations
let mut workspace = evaluator
    .workspace(BatchRequest::values(3))
    .map_err(|e| e.to_string())?;
// Queries [3, 1], outputs [3, 2], row-major
let query_layout = StridedLayout::new(&[3, 1], &[1, 1]).map_err(|e| e.to_string())?;
let output_layout = StridedLayout::new(&[3, 2], &[2, 1]).map_err(|e| e.to_string())?;
let mut values = [0.0; 6];

// First: three in-domain points
let first_points = [0.0, 0.5, 2.0];
let first = NdView::new(&first_points, query_layout).map_err(|e| e.to_string())?;
{
    let mut out = NdViewMut::new(&mut values, output_layout).map_err(|e| e.to_string())?;
    evaluator
        .evaluate_into(
            &first,
            policy,
            &mut out,
            None,
            &mut workspace,
            ExecutionContext::sequential_native(),
        )
        .map_err(|e| e.to_string())?;
}
let after_first = values;

// Second: only point 3 is controlled; outside [0, 2] makes Reject fail the entire batch
let second_points = [1.0, 1.5, third_x];
let second = NdView::new(&second_points, query_layout).map_err(|e| e.to_string())?;
let outcome = {
    let mut out = NdViewMut::new(&mut values, output_layout).map_err(|e| e.to_string())?;
    evaluator.evaluate_into(
        &second,
        policy,
        &mut out,
        None,
        &mut workspace,
        ExecutionContext::sequential_native(),
    )
};
let status = match outcome {
    Ok(()) => ("Success", None),
    Err(e) => ("Failed", Some(format!("{:?}", e.kind()))),
};
emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "Second batch" },
        { "key": "1", "label": "Error kind", "nullText": "—" }
    ]),
    vec![status],
    metadata = serde_json::json!({ "id": "status" })
);

// Independent check: every second component equals the square of x from the call that wrote that row
let rows: Vec<_> = (0..3)
    .map(|row| {
        (
            row + 1,
            first_points[row],
            after_first[2 * row + 1],
            second_points[row],
            values[2 * row],
            values[2 * row + 1],
        )
    })
    .collect();
let digits = serde_json::json!({ "significantDigits": 15 });
let columns = serde_json::json!([
    { "key": "0", "label": "Row", "type": "integer" },
    { "key": "1", "label": "First-call x [-]", "type": "number", "format": digits },
    { "key": "2", "label": "Second component after call 1 [-]", "type": "number", "format": digits },
    { "key": "3", "label": "Second-call x [-]", "type": "number", "format": digits },
    { "key": "4", "label": "First component after call 2 [-]", "type": "number", "format": digits },
    { "key": "5", "label": "Second component after call 2 [-]", "type": "number", "format": digits }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "batch" })
);
```

Default third point $x = 2.5$ makes call 2 give `DomainError`; its output columns retain first-call $(0, 0)$, $(0.5, 0.25)$, and $(2, 4)$.
Even the in-domain first two points are not written; no partial failed-batch result remains.
Third points at most $2$ make call 2 succeed, updating rows to $(x, x^2)$.
Boundary $x = 2$ belongs to the closed domain and is evaluable even under `Reject`.
This contract avoids callers partially accepting failed batches.

## Summary

For gradients, Hessians, or integrals, first check implementations of `Differentiable`, `TwiceDifferentiable`, and `Integrable`.
Pass policies per call; for extended values such as `Clamp`, inspect used coordinates and outside distances through `report` or `evaluate_into_with_report`.
For repeated points, construct `workspace()` workspace once and pass to `evaluate_into`; for many points, obtain arrays with `evaluate_many` or preallocate `BatchWorkspace` and write caller arrays with `BatchEvaluator::evaluate_into`.
Both preserve outputs on failure; ignore outputs on errors and read kind `e.kind()`.
