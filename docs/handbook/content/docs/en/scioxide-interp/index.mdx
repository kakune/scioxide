`scioxide-interp` constructs functions and curves from discrete points and values for evaluation between samples.
It supports interpolation through every sample and smoothing that need not match noisy samples.
Constructed functions return values and, where supported, derivatives and definite integrals.
This page computes one interpolant, interprets its results, then outlines method selection, extrapolation, and evaluation forms.

## First interpolation

The next cell interpolates monotone calibration table $(x_i, y_i) = (0, 0), (1, 0.8), (2, 1.0), (3, 1.5)$ using PCHIP, a piecewise cubic Hermite method.
Piecewise cubic Hermite interpolation uses a cubic on each $[x_i, x_{i+1}]$ matching endpoint values $y_i, y_{i+1}$ and nodal slopes $d_i, d_{i+1}$.
PCHIP chooses slopes from adjacent secants $\delta_i = (y_{i+1} - y_i)/(x_{i+1} - x_i)$, preserving monotonicity of monotone data.
With coordinates in m and values in V, slopes have units V/m.
The input is coordinate $x$ within calibration range $[0, 3]$.
Output tabulates interpolated values and slopes, independent cubic-Hermite reconstruction from nodal slopes, and the two sample values bracketing $x$.
`PchipInterpolator::new(x, y)` constructs from samples alone; univariate `value_at` and `derivative_at` (trait `Univariate`) return in-range values and slopes.
Samples do not uniquely determine a true function; interpret slopes as derivatives of the selected model.

```rust
//| id: interp-first-calibration
//| ref: interp-first-calibration
//| title: "Values and slopes of monotone samples"
//| run: reactive
//| crates: [scioxide-interp]
//| inputs:
//|   position: {"type":"range","label":"Coordinate x [m]","description":"Evaluation point within [0, 3]; nodes 0, 1, 2, 3 return calibration values unchanged.","min":0,"max":3,"step":0.05,"value":1.5}
//| cases:
//|   - {"id":"at-node","label":"Node x = 2","description":"At the node, returns 1.0 V and nodal slope 2/7 V/m.","inputs":{"position":2}}
//|   - {"id":"last-interval","label":"x = 2.5","description":"The last interval sets right slope to 0.65 V/m by a one-sided three-point formula, giving slope 0.516 V/m at x = 2.5.","inputs":{"position":2.5}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"calibration","path":"/rows/0/1","approx":{"value":0.904285714285714,"atol":1e-12}}
//|       - {"artifact":"calibration","path":"/rows/0/2","approx":{"value":0.148571428571429,"atol":1e-12}}
//|       - {"artifact":"calibration","path":"/rows/0/3","approx":{"value":0.904285714285714,"atol":1e-12}}
//|   - case: at-node
//|     expect:
//|       - {"artifact":"calibration","path":"/rows/0/1","approx":{"value":1.0,"atol":1e-14}}
//|       - {"artifact":"calibration","path":"/rows/0/2","approx":{"value":0.285714285714286,"atol":1e-12}}
//|   - case: last-interval
//|     expect:
//|       - {"artifact":"calibration","path":"/rows/0/1","approx":{"value":1.20446428571429,"atol":1e-12}}
//|       - {"artifact":"calibration","path":"/rows/0/2","approx":{"value":0.516071428571429,"atol":1e-12}}
//|       - {"artifact":"calibration","path":"/rows/0/3","approx":{"value":1.20446428571429,"atol":1e-12}}
use scioxide_interp::{PchipInterpolator, Univariate};

let x = vec![0.0_f64, 1.0, 2.0, 3.0];
let y = vec![0.0, 0.8, 1.0, 1.5];
let model = PchipInterpolator::new(x.clone(), y.clone()).map_err(|e| e.to_string())?;
// Scalar forms evaluate only within [0, 3], rejecting outside points with DomainError
let value = model.value_at(position).map_err(|e| e.to_string())?;
let slope = model.derivative_at(position).map_err(|e| e.to_string())?;
// The interval containing position has index equal to the number of internal nodes at or below position
let i = x[1..x.len() - 1]
    .iter()
    .filter(|&&node| node <= position)
    .count();
// Independent check: reconstruct interval i from nodal slopes d and cubic Hermite bases
let d = model.slopes();
let h = x[i + 1] - x[i];
let t = (position - x[i]) / h;
let hermite = (2.0 * t * t * t - 3.0 * t * t + 1.0) * y[i]
    + (t * t * t - 2.0 * t * t + t) * h * d[i]
    + (-2.0 * t * t * t + 3.0 * t * t) * y[i + 1]
    + (t * t * t - t * t) * h * d[i + 1];
let fixed2 = serde_json::json!({ "fractionDigits": 2 });
let digits6 = serde_json::json!({ "significantDigits": 6 });
let columns = serde_json::json!([
    { "key": "0", "label": "Coordinate x [m]", "type": "number", "format": fixed2 },
    { "key": "1", "label": "Interpolated value [V]", "type": "number", "format": digits6 },
    { "key": "2", "label": "Slope [V/m]", "type": "number", "format": digits6 },
    { "key": "3", "label": "Hermite-form check [V]", "type": "number", "format": digits6 },
    { "key": "4", "label": "Left-node value [V]", "type": "number", "format": digits6 },
    { "key": "5", "label": "Right-node value [V]", "type": "number", "format": digits6 }
]);
emit_table_with_columns!(
    columns,
    vec![(position, value, slope, hermite, y[i], y[i + 1])],
    metadata = serde_json::json!({ "id": "calibration" })
);
```

Inputs at nodes return original calibration values unchanged.
At default $x = 1.5$, value 0.904286 V lies between 0.8 V and 1.0 V, with positive slope 0.148571 V/m.
Nodal-slope Hermite reconstruction also gives 0.904286 V, matching through a different evaluation path.

This can also be computed by hand.
Secants are $\delta_0 = 0.8$, $\delta_1 = 0.2$, and $\delta_2 = 0.5$ V/m; equal 1 m gaps make interior slopes harmonic means $d_i = 2/(1/\delta_{i-1} + 1/\delta_i)$ of adjacent secants.
They are $d_1 = 0.32$ V/m and $d_2 = 2/7 \approx 0.285714$ V/m.
At interval midpoints, cubic Hermite forms are

```text
s(xᵢ + h/2)  = (yᵢ + yᵢ₊₁)/2 + h (dᵢ − dᵢ₊₁)/8
s′(xᵢ + h/2) = 3δᵢ/2 − (dᵢ + dᵢ₊₁)/4
```

with $h$ the interval width; inserting $i = 1$ gives 0.904286 V and 0.148571 V/m.
Mean interval slope equals the secant; endpoints 0.32 and 0.285714 V/m exceed secant 0.2 V/m, so midpoint slope lies below it.
On the last interval (case “x = 2.5”), the right endpoint slope is set by the one-sided three-point formula $((2h_2 + h_1)\delta_2 - h_2\delta_1)/(h_1 + h_2) = 0.65$ V/m; this gives slope 0.516071 V/m and value 1.204464 V at $x = 2.5$.

PCHIP preserves each monotone interval, keeping values between neighbors and slopes nonnegative for every $x$.
Second derivatives may jump at nodes; choose cubic splines for continuous curvature.
To avoid fitting measurement noise, choose smoothing rather than interpolation.
Slope rules and monotonicity are derived in [PCHIP, cubic splines, and Akima](./algorithms/pchip-and-splines/).

## Decisions from samples

Infinitely many functions pass through the same points.
An interpolation method chooses a function space and shape constraints among them.
First identify coordinate geometry, value types, monotonicity or smoothness, and required calculus.

| Input and goal | Main options | Properties to check |
|---|---|---|
| One global one-dimensional representation | Barycentric, Newton, Hermite, Neville, Bulirsch–Stoer | Node placement, derivative samples, nearby poles |
| Real-axis interpolation, resonances, Taylor coefficients | Floater–Hormann, AAA, Padé | Degree, poles, errors outside samples |
| Monotone tables, sharp local changes | PCHIP, Akima, Makima | Monotonicity and overshoot |
| Smooth curves, geometric design | Cubic splines, B-splines, NURBS | Boundaries, knots, curvature |
| Curves through spatial point sequences | Parametric splines | Parameterization, residual targets, termination |
| Noisy values | Penalized or adaptive splines | Fit, roughness, termination |
| Rectilinear grids | Bilinear, bicubic, tensor splines | Axis and component ordering, derivative continuity |
| Scattered points | RBF, Delaunay interpolation, local models | Convex hull, neighborhoods, rank, conditioning |
| Covariance-based prediction | Gaussian processes, kriging | Mean assumptions, noise, predictive variance |
| Global fields | Spherical splines | Poles, periodicity, angles, spherical area |

[Choosing interpolation](./choosing/) compares continuity, locality, and error orders.

## Extrapolation and coordinate reports

Univariate scalar forms such as `value_at` evaluate only inside domains, returning `DomainError` outside.
Queries accepting extrapolation require explicit `ExtrapolationPolicy` on every call, without implicit defaults.
Domains are closed; boundary points count as inside.

| Policy | Outside-domain behavior |
|---|---|
| `Reject` | Reject with `DomainError` |
| `Clamp` | Evaluate at the nearest domain point; extend intervals and boxes constantly using boundary values, or compose with nearest-point convex-hull projection |
| `BoundedContinue { max_distance }` | Extend the method's representation when each axis lies at distance at most `max_distance` from the boundary, equality included; reject farther points |
| `MethodDefined` | Extend global formulas or outermost interval polynomials without distance limits, reporting poles or unrepresentable values as errors |

Permitted extrapolation does not guarantee accuracy.
`ExtrapolationReport` returned by `Interpolant::report` reports geometric information—original and actual coordinates and per-axis domain distances—not accuracy or stability estimates.

Domain definitions vary by method.
For univariate and grid interpolants, domains are node-spanned intervals or boxes; for `RbfInterpolator`, the bounding rectangle rather than convex hull; for Delaunay methods, the point convex hull.
Spherical longitude wraps, placing every finite longitude inside; only colatitude follows policy relative to $[0, \pi]$.
Natural-neighbor interpolation accepts only `Clamp` outside its hull; other policies give `DomainError`.

For intervals or boxes extended by `Clamp`, derivatives along outside axes are zero; integrals add boundary values times exterior lengths.
For hull projection, differentiate composition with the projection.
If one-sided derivatives disagree beyond rounding at projection switches, that query gives `DomainError`.

## Evaluation and interpretation

Construct default interpolants with samples alone through `new`; change node tests, boundaries, or similar settings with named constructors such as `with_options` or `CubicSpline::with_boundary`.
Evaluate through `evaluate` of `Interpolant` with real-coordinate arrays and policies; use `evaluate_many` for many points at once.
Univariate interpolants also support `value_at`, `values_at`, `derivative_at`, and `integrate` of `Univariate`.
Values may be real, complex, arrays, or vectors; components share geometry such as nodes, triangulations, and neighborhoods.
Derivatives and integrals use supported traits `Differentiable`, `TwiceDifferentiable`, and `Integrable`; methods without those implementations cannot be called.
Caller-output-and-workspace `*_into` forms write complete finite results on success and leave outputs unchanged on errors.
Convenient owned results and reserved allocation-free repeated forms have different costs.
[Prepared and batch evaluation](./algorithms/prepared-evaluation-and-batches/) explains that distinction.

For iterative preparation, one-shot `aaa`, `fit_parametric_spline`, `fit_spherical_spline`, and `CloughTocherInterpolator::new` return `ConvergenceFailure` when targets are unmet.
Detailed forms (`aaa_with_options`, `fit_*_with_options`, `CloughTocherInterpolator::with_options`) also return unmet models with reports; read termination first.
Small sample residuals guarantee neither intersample, extrapolation, nor true-derivative errors.
[Tolerances and residuals](../concepts/tolerances-and-residuals/) collects error types and shared numerical contracts.

## Summary

Choose interpolants from sample geometry and required properties.
Sample agreement, shape preservation (monotonicity), smoothness through second derivatives, and noise smoothing are separate demands; no single method necessarily satisfies all.
PCHIP values can be reconstructed by hand from slopes and cubic Hermite forms and stay between neighboring monotone values.
For outside-domain evaluation, specify policies and check each method's domain and calculus support.
Read iterative-preparation termination and independently check nonsample points.
