`scioxide-linalg` algorithms handle four problem classes—linear systems, least squares, eigenvalue problems, and matrix functions/equations—using both direct and iterative methods.
This page collects shared notation and error measures, call forms and execution control, conventions separating factorization from solution acceptance, and output rules on failure, then maps topics to pages.

## Notation

Handbook-wide notation and terminology follow [Numerical notation and terminology](../../reference/).
This chapter writes matrices as $A, B$ and vectors as $x, b$ in lightface, denoting the same objects as $\mathbf{A}$ and $\mathbf{x}$ in the notation index.

| Symbol | Meaning |
|---|---|
| $\mathbb{K}$ | Scalar field: $\mathbb{R}$ (`f32`, `f64`) or $\mathbb{C}$ (`Complex<f32>`, `Complex<f64>`) |
| $A^{\mathsf T}, A^{\mathsf H}$ | Transpose and conjugate transpose (adjoint) |
| $\hat x$ | Computed approximate solution; $x$ is the exact solution for stored $A$ and $b$ |
| $\varepsilon$, $u = \varepsilon/2$ | Machine epsilon ($\epsilon_{\mathrm{mach}}$ in the notation index) and unit roundoff; $u = 2^{-53} \approx 1.1 \times 10^{-16}$ in double precision, $2^{-24} \approx 6.0 \times 10^{-8}$ in single precision |
| $\gamma_k = k u / (1 - k u)$ | Relative-error bound from $k$ accumulated roundings (when $k u < 1$) |
| $\lVert \cdot \rVert_1$, $\lVert \cdot \rVert_2$, $\lVert \cdot \rVert_\infty$, $\lVert \cdot \rVert_F$ | 1-norm (maximum absolute column sum for matrices), 2-norm, $\infty$-norm (maximum absolute row sum for matrices), and Frobenius norm |
| $\sigma_1 \ge \dots \ge \sigma_n$ | Singular values |
| $\kappa(A) = \lVert A \rVert \lVert A^{-1} \rVert$ | Condition number, with norms indicated by subscripts such as $\kappa_1$, $\kappa_2 = \sigma_1 / \sigma_n$, and $\kappa_\infty$ |
| $\mathrm{rcond}_1 = 1/\kappa_1(A)$ | Reciprocal condition number, estimated by direct methods' `condition_estimate` |
| $\lvert A \rvert$ | Matrix of componentwise absolute values |

General floating-point and conditioning theory appears in [Floating-point numbers and condition numbers](../../concepts/floating-point-and-conditioning/).

## Error measures

Distinguish the following three measures of the quality of approximate solution $\hat x$ to $Ax = b$.

| Quantity | Definition | Interpretation |
|---|---|---|
| Residual | $r = b - A\hat x$ | Directly computable from $\hat x$; depends on the scales of $A$ and $b$ |
| Backward error | $\eta = \lVert r \rVert / (\lVert A \rVert \lVert \hat x \rVert + \lVert b \rVert)$ | How nearby a problem has $\hat x$ as its exact solution; measures algorithmic stability |
| Forward error | $\lVert \hat x - x \rVert / \lVert x \rVert$ | Relative discrepancy from the exact solution; at most $2\kappa(A)\,\eta / (1 - \kappa(A)\,\eta)$ when $\kappa(A)\,\eta < 1$ |

Algorithms with backward errors as small as order $u$ are called backward stable.
Even backward-stable algorithms can have forward errors amplified by the condition number, so a small residual alone does not establish solution accuracy.
The forward-error bound above is relative to stored $A$ and $b$.
Rounding or measurement errors in the inputs themselves contribute separately.
Componentwise backward error (Oettli–Prager) is covered in [Mixed-precision iterative refinement and backward error](iterative-refinement/).

## Call forms and execution control

Each algorithm page describes APIs calling a computation in several forms distinguished by name suffixes.
These include ordinary forms taking only problem data (`factor(&a)`, `solve(&b)`, `norm2()`), detailed forms taking settings last (`*_with_options`), borrowed forms taking caller outputs, workspaces, and contexts (`*_into`), and scoped forms where value-returning operations take contexts (`*_scoped`).
There are also one-call functions returning only answers (such as `solve` and `least_squares`), plans computing reusable data during construction (`…Plan`), and method values holding only settings (such as `ExponentialAction` and `CgSolver`).
Definitions and choices appear in [Workspaces, execution contexts, and attempt records](oxref:linalg-execution-forms).

Ordinary and detailed forms (collectively owned forms), and one-call functions, run sequentially with `ExecutionContext::sequential_native()`, without clocks or cancellation.
Thus time limits in owned forms yield `CapabilityUnavailable`; parallelism, cancellation, deadlines, and external BLAS providers are available only in borrowed and scoped forms.
Execution control is collected in one `LinalgExecutionOptions` value containing execution policy, product-accuracy tier, elapsed-time and byte limits, and iteration limits.
Each method's options compose this once through `with_execution_options`; remaining fields contain only mathematical settings.

## Separating factorization and acceptance

Factorization construction makes only structural decisions and never implicitly applies numerical-rank thresholds.
It rejects only invalid shapes, nonfinite entries, violations of explicit structures (such as Hermitian symmetry), algebraic breakdowns such as exactly zero pivots, and overflowing factor entries.
For Cholesky, LDL, and Hermitian eigenproblems, `HermitianInput` must explicitly specify how to interpret input as Hermitian.
The three choices are `Exact` requiring exact symmetry, `Triangle` reading only one triangle, and `Projected` explicitly projecting onto $(A + A^{\mathsf H})/2$.
Numerical interpretation of results is determined by the following caller-supplied values.

- `RankPolicy`: rules for counting singular values or factor diagonals toward rank.
  Choices are `Exact` (exclude only exact zeros), `DimensionScaledEpsilon` (threshold at $\min(\max(m, n)\,\varepsilon,\ 1/2) \times$ the maximum), and `Threshold` (absolute/relative thresholds using core's `RankThreshold`).
  Returns `RankReport` (rank, maximum rank, threshold, and scale).
- `ConditionEstimate`: a threshold-independent reciprocal-condition estimate paired with its reliability (such as `Heuristic` in `EstimateReliability`).
  LU and Cholesky `condition_estimate` estimate $1/\kappa_1(A)$ in original coordinates; for order at most 4, compute $\lVert A^{-1} \rVert_1$ from inverse columns, and for higher orders use Higham's improvement of Hager's method.
  In exact arithmetic this estimate is a lower bound on $\lVert A^{-1} \rVert_1$ and often at least one tenth of its true value, but this is not guaranteed.
- `DirectSolveOptions`: acceptance criteria when solving from a factorization.
  Holds a rank policy, optional minimum reciprocal condition number `ReciprocalConditionThreshold`, backward-error diagnostic selection (`with_residual`, default `Estimation::Skip`; reporting alone does not reject solutions), and execution control (`with_execution_options`).
  Condition estimation occurs only when a minimum is specified.
  `DirectSolveOptions::default()` uses `RankPolicy::Exact`, has no minimum condition requirement, and does not compute backward error.
- `DirectSolveResult` and `DirectSolveTermination`: detailed `solve_with_options(&b, &options)` returns policy rejection in an `Ok` result rather than an error.
  `solution()` returns `Some` only when report `DirectSolveReport` has termination reason `Accepted`.
  Other termination reasons are `RankDeficient` (insufficient rank under policy), `IllConditioned` (estimated reciprocal condition below minimum), `ResidualRejected` (original-equation residual exceeds tolerance), and `StabilityRejected` (a Riccati solution fails closed-loop stability verification).
  `ResidualRejected` is used by structured matrices such as Toeplitz, composite operators, and matrix-equation solvers; only Riccati equations use `StabilityRejected`.
  Ordinary `solve(&b)` and one-call functions convert rejections to errors through `DirectSolveTermination::require_accepted`: `RankDeficient` becomes `Singular`, and others become `NumericalInstability`.
  `into_accepted()` converts detailed results by the same rule.
- `EquilibrationMetadata`: power-of-two row and column scales applied by LU before factorization (`equilibration()`).
  Cholesky also uses symmetric power-of-two scaling $DAD$ internally.
  Both return factors, solutions, and diagnostics for the original matrix.

This separation keeps factorization results unchanged across policies and leaves raw quantities such as singular values always accessible.

## Failure and output rules

Failures return `SciOxideError`; inspect classifications with `kind()`.
The chapter's main failure classifications are as follows.

| `kind()` | Conditions |
|---|---|
| `DimensionMismatch` | Shape mismatches, nonsquare matrices where square is required, or insufficient output/borrowed workspace |
| `InvalidInput` | Out-of-range settings, input not exactly Hermitian under `HermitianInput::Exact`, or matrix structures incompatible with the solve type |
| `NonFinite` | Nonfinite inputs or nonfinite values returned by operator/preconditioner callbacks |
| `Singular` | Exactly zero pivots or `RankDeficient` in ordinary solves |
| `DomainError` | Cholesky input not numerically positive definite, matrix functions with eigenvalues at undefined points (such as branch cuts), or minimum conditioning requested for empty matrices |
| `NumericalInstability` | Results (determinants, solutions, eigenvalues) or factor entries unrepresentable in the scalar type, eigenvector residual/linear-independence checks, failed swaps in Schur reordering, or `IllConditioned`/`ResidualRejected`/`StabilityRejected` in ordinary solves |
| `ConvergenceFailure` | Internal eigendecomposition/SVD iteration limits, ordinary iterative methods stopping before tolerance, or iterative methods stopping without usable iterates |
| `ExecutionStopped` | Cancellation or deadlines in borrowed and scoped forms |
| `ResourceLimit`, `AllocationFailure` | Workspace exceeding byte limits or inability to allocate storage |
| `CapabilityUnavailable` | Required capabilities absent from the execution context (time limits in owned forms, provider-unsupported calls under `BlasFallbackPolicy::Error`, etc.) |
| `CapabilityFailure` | External BLAS provider errors or invalid outputs (negative norms, out-of-range indices, etc.) |

Output handling follows these rules.

- Borrowed forms update outputs only after all checks and computations succeed, leaving outputs unchanged on failure or policy rejection.
- Detailed and borrowed iterative solvers, method values for operator actions and partial spectra, and iterative refinement return meaningful intermediate results in `Ok` even after limits, cancellation, recurrence breakdown, or stagnation (for iterative solvers, the best iterate whose true residual was checked).
  The report's termination reason indicates success; do not interpret `Ok` as convergence.
  Only ordinary `solve(a, b)` for iterative solves with a single right-hand side turns the same stop into a `ConvergenceFailure` error.
- With sufficiently sized workspace and output, SciOxide numerical computation does not allocate ([Workspaces, execution contexts, and attempt records](workspaces-and-execution/)).

General error classifications and partial results are covered in [Error contracts and partial results](../../concepts/errors-and-partial-results/).

## Summary

The chapter's algorithm pages assume the notation above, the three quantities residual/backward error/forward error, and conventions separating factorization from acceptance.
Assess solution accuracy by combining reported backward error with estimated reciprocal condition number, rather than inferring accuracy from a small residual alone.
Use detailed forms to change acceptance criteria or inspect termination reasons; ordinary and one-call forms report rejection and nonconvergence as errors.
For parallelism, cancellation, deadlines, external BLAS, or repeated allocation-free calls, supply workspaces and execution contexts to borrowed and scoped forms.
For detailed, borrowed, and iterative results, receiving `Ok` alone does not establish success; use the termination reason's `is_success()`.
