Single-precision (`f32`) LU uses half the storage of double precision and is faster in many environments, but solution accuracy is limited by single-precision unit roundoff $u_f = 2^{-24} \approx 6 \times 10^{-8}$.
Iterative refinement uses lower-precision factors only for corrections, computing residuals and solution updates in higher precision to recover double-precision backward error when conditions permit.
This page explains convergence conditions and limits, error measures, and use of `IterativeRefinement`.

---

## Iterative-refinement steps and convergence conditions

Starting from approximate solution $x_k$, repeat:

1. Compute residual $r_k = b - A x_k$ in working precision (double precision, unit roundoff $u$).
2. Approximately solve correction equation $A d_k = r_k$ using lower-precision factors.
3. Update $x_{k+1} = x_k + d_k$ in working precision.

Suppose the computed correction satisfies $(A + E_k)\, d_k = r_k$ for some $E_k$ and let $\lVert A^{-1} E_k \rVert \le \theta$.
With exact residual computation, $r_k = A(x - x_k)$ gives

$$
x_{k+1} - x = -A^{-1} E_k (A + E_k)^{-1} r_k \quad\Rightarrow\quad
\lVert x_{k+1} - x \rVert \le \frac{\theta}{1 - \theta}\, \lVert x_k - x \rVert
$$

so errors contract each step when $\theta < 1/2$ (residual rounding contributes to the limits described below).
For single-precision LU, $\theta$ is approximately $c\,\kappa(A)\, u_f$ ($c$ depends on $n$ and the growth factor), so $\kappa(A) u_f$ well below 1, or $\kappa(A) \ll 1/u_f \approx 1.7 \times 10^{7}$, guides convergence.
Beyond this conditioning level, corrections stop reducing error and refinement stagnates.

There are two limits after convergence.
Backward error falls to working-precision unit-roundoff scale $u$ (about $10^{-16}$ in double precision).
The forward-error limit depends on residual accuracy.
Refinement computing residuals by ordinary working-precision arithmetic stops at forward-error scale $\kappa(A) u$, the backward error multiplied by conditioning.
For explicit matrices (`Dense` and `Sparse` below), `scioxide-linalg` forms residuals by accumulating each row's sum of products $b_i - \sum_j a_{ij} x_j$ without rounding, then rounding once to working precision.
This is classical refinement with residuals computed above working precision; when $\kappa(A) u_f$ is well below 1, forward error relative to the exact solution of stored $A$ and $b$ can theoretically also reach order $u$.
Refinement cannot remove errors already in $A$ and $b$ themselves (measurement or rounding), amplified by $\kappa(A)$.
Matrix-free systems form residuals from working-precision actions and do not have this advantage.
Solution updates use working precision in both cases.

## Normwise and componentwise backward error

Refinement targets backward error in the original system.

$$
\eta_N = \frac{\lVert r \rVert_\infty}{\lVert A \rVert_\infty \lVert x \rVert_\infty + \lVert b \rVert_\infty}, \qquad
\eta_C = \max_i \frac{\lvert r_i \rvert}{(\lvert A \rvert \lvert x \rvert + \lvert b \rvert)_i}
$$

$\eta_N$ (Rigal–Gaches) is the minimum perturbation making $x$ exact, measured relative to norms of $A$ and $b$; $\eta_C$ (Oettli–Prager) is the minimum measured with perturbations proportional to each entry; they satisfy $\eta_N \le \eta_C$.
Small componentwise backward error is a stronger statement for systems with extreme component scales or sparse systems.
Componentwise values are computed only when matrix entries are known, not for matrix-free operators.
Both are floating-point estimates, not forward-error bounds or interval guarantees; bounding forward error also requires conditioning.

## IterativeRefinement inputs and results

Refinement settings and the system to refine are separate values.
`IterativeRefinement::new(options)` is a method object holding only `RefinementOptions` settings, precomputing neither matrices nor factors, so one value can serve many problems.
Construction checks that factor precision `L` and residual precision `H` form `f32/f32`, `f64/f64`, `f32/f64`, or their complex counterparts; other pairs give `InvalidInput` (`UnsupportedConfiguration`).
Bundle the system and inverse operators in `RefinementProblem::new(system, inverse, scaling, fallback)`, passed to the method object per call.
`RefinementProblem::new` borrows them and validates shapes and finiteness.
Neither value implicitly factors or converts matrices; callers construct lower-precision factors.
Below, fallback means switching once to a working-precision inverse operator when lower-precision corrections fail or refinement stops progressing.

| Input | Type | Role |
|---|---|---|
| `system` | `RefinementSystem` | Original system in working precision: dense `Dense`, CSR `Sparse`, or `Operator` pairing an operator with a positive upper bound on $\lVert A \rVert_\infty$ |
| `inverse` | `&(dyn LinearOperator<L> + Sync)` | Lower-precision inverse operator for corrections (for example, `inverse_operator()` of `LuDecomposition` in `f32`) |
| `scaling` | `Option<&EquilibrationMetadata>` | Power-of-two scales when the inverse operator solves equilibrated system $D_r A D_c$ |
| `fallback` | `Option<&(dyn LinearOperator<H> + Sync)>` | Fallback: working-precision inverse operator applying $A^{-1}$ for the original, unequilibrated system |
| `options` (method object) | `RefinementOptions` | Tolerance `ResidualTolerance`, `with_criterion` (default `RefinementCriterion::Normwise`, `Componentwise`), `with_fallback` (default `RefinementFallback::Disabled`, `OnFailure`), `with_execution_options` |

Convergence means the selected backward error is at most $\tau_{\mathrm{abs}} + \tau_{\mathrm{rel}}$ of `ResidualTolerance` (reference scale 1, since backward error is already relative).
The correction limit is iteration limit `with_iteration_budget` in `LinalgExecutionOptions` passed through `with_execution_options`, counted per right-hand side and defaulting to 10 including fallback corrections.
The same value's byte limit bounds workspace; execution policy, product accuracy, and time limits apply throughout refinement.
Owning-result `refine` runs with `ExecutionContext::sequential_native()` and no clock, so time limits give `CapabilityUnavailable` (owning-result and caller-provided-output APIs are defined in [Calling forms](oxref:linalg-execution-forms)).

`EquilibrationMetadata::prepare(system)` chooses power-of-two row scales from dense or CSR matrices to place largest absolute entries in $[1, 2)$, then chooses column scales; operator systems are rejected.
`scale_matrix_into(a, &mut low)` writes into a lower-precision matrix while applying scales, avoiding conversion overflow even for entries above single-precision range (entries erased to zero cause `NumericalInstability`).
Each correction divides equilibrated residual $D_r r$ by a power of two near its $\infty$ norm before rounding to lower precision, then restores scaling after converting the correction to working precision.
Only components smaller than $\varepsilon_L \lVert D_r r \rVert_\infty$ ($\varepsilon_L$ is lower-precision machine epsilon) may disappear as unrepresentable; larger unrepresentable components cause conversion failure.

`refine(&problem, rhs, initial)` accepts an initial guess and returns the improved solution paired with `RefinementReport`.
Caller-provided-output `refine_into(&problem, rhs, solution, &mut ws, cx)` independently refines each column of `solution` as an initial guess and returns per-column reports.
Preallocate `RefinementWorkspace` using `RefinementRequirements` obtained by passing `RefinementWorkspaceRequest::new(&problem).with_right_hand_sides(m)` to `workspace_requirements`, or construct through `workspace(&request)`.
Selecting `OnFailure` without fallback gives `InvalidInput` (`Inconsistent`); selecting componentwise checks for operator systems gives `InvalidInput` (`UnsupportedConfiguration`); both are rejected during requirement queries.

Accept a correction only if it strictly lowers the selected backward error or meets tolerance.
Componentwise checks make an exception when unrepresentable residual components were dropped: a correction with unchanged backward error is also accepted if residual norm decreases.
Discard corrections that do not lower backward error as stagnation; `OnFailure` switches to fallback once, otherwise stops with `Stagnation`.
Residual-conversion failure or a lower-precision inverse operator returning `NumericalInstability` or `Singular` also uses fallback under `OnFailure`, otherwise stops with `CorrectionFailed`.

Determine success from report `termination()` or `is_success()`.
Termination reason `RefinementTermination` maps to cell outcomes as follows.

| Termination reason | Meaning | outcome |
|---|---|---|
| `Converged` | Selected backward error meets tolerance (the only value making `is_success()` true) | satisfied |
| `Stagnation` | Correction did not reduce backward error | partial |
| `IterationLimit` | Per-right-hand-side correction limit reached | partial |
| `EvaluationLimit` | Evaluation limits prevented residual or inverse-operator computation | partial |
| `ExecutionStopped(reason)` | Stopped by cancellation or deadline | partial |
| `CorrectionFailed` | Lower-precision conversion or correction failed without allowed fallback | failed |

Even without success, commits the best accepted iterate so far and returns `Ok`.
Cancellation and deadlines also return reports in `ExecutionStopped` rather than errors.
Reports also contain attempted correction count `iterations()` (including rejected corrections), initial and returned backward errors `initial_error()` and `final_error()`, fallback reason `fallback_reason()`, fallback-call count `fallback_iterations()`, and precisions `factor_precision()` and `residual_precision()`.
Backward-error value `BackwardError` contains `normwise()`, `componentwise()` (`None` for operator systems), and `uses_operator_bound()` indicating use of an upper bound instead of $\lVert A \rVert_\infty$ for operator systems.
Fallback reason `RefinementFallbackReason` is `Conversion` (conversion failure), `NumericalFailure` (lower-precision inverse numerical failure), or `Stagnation` (stagnation).

## Experiment varying conditioning

The following cell solves $Ax = b$, $x^{\star} = (1, \dots, 1)$ for an $40 \times 40$ matrix $A = H_u \Sigma H_v$ ($H_u, H_v$ are Householder reflections) whose singular values form a geometric progression from 1 to $10^{-t}$.
The reflections are orthogonal, fixing $\kappa_2(A) = 10^{t}$ exactly.
Convert equilibrated $A$ to `f32`, factor by LU, and refine from zero with `IterativeRefinement`.
Inputs are condition exponent $t$ for the plot and outcome, stopping criterion (backward-error kind compared with tolerance $10^{-15}$), and whether fallback to `f64` LU is allowed.
The table gives results after up to 10 corrections for $t = 0, \dots, 10$; forward error is the difference from $x^{\star}$, with $\kappa_2 u$ as reference.
The plot gives backward errors at selected $t$ as maximum correction count $k$ varies through $1, \dots, 10$, with a horizontal tolerance line.
The outcome maps the selected $t$'s termination reason after at most 10 corrections using the table above.

```rust
//| id: linalg-mixed-precision-refinement
//| ref: linalg-mixed-precision-refinement
//| title: "Iterative refinement with f32 LU and f64 residuals"
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg]
//| inputs:
//|   condition_exponent: {"type":"range","label":"t in condition number κ₂ = 10^t","description":"Matrix condition number used in the plot and outcome.","min":0,"max":10,"step":1,"value":8}
//|   criterion: {"type":"select","label":"Stopping criterion","description":"Backward error compared with tolerance 10^−15.","options":["Normwise","Componentwise"],"value":"Normwise"}
//|   use_fallback: {"type":"checkbox","label":"Fall back to f64 LU","description":"Switch once to an f64 inverse operator when refinement stops progressing.","value":false}
//| cases:
//|   - {"id":"stagnation","label":"t = 10","description":"Single-precision factors stop reducing backward error, terminating with Stagnation.","inputs":{"condition_exponent":10}}
//|   - {"id":"fallback","label":"t = 10, with fallback","description":"Switches to f64 LU on stagnation and converges.","inputs":{"condition_exponent":10,"use_fallback":true}}
//|   - {"id":"componentwise","label":"t = 9, componentwise","description":"Componentwise checks stop at the correction-count limit.","inputs":{"condition_exponent":9,"criterion":"Componentwise"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/1","equals":"Converged"}
//|       - {"artifact":"summary","path":"/rows/8/1","equals":"Converged"}
//|       - {"artifact":"summary","path":"/rows/8/3","range":{"max":1e-15}}
//|       - {"artifact":"summary","path":"/rows/9/3","range":{"min":1e-14}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: stagnation
//|     expect:
//|       - {"path":"/outputs/2/state","equals":"partial"}
//|   - case: fallback
//|     expect:
//|       - {"artifact":"summary","path":"/rows/10/1","equals":"Converged"}
//|       - {"artifact":"summary","path":"/rows/10/7","equals":"Stagnation"}
//|       - {"artifact":"summary","path":"/rows/10/8","range":{"min":1}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: componentwise
//|     expect:
//|       - {"artifact":"summary","path":"/rows/9/1","equals":"IterationLimit"}
//|       - {"artifact":"summary","path":"/rows/9/2","equals":10}
//|       - {"path":"/outputs/2/state","equals":"partial"}
use scioxide_core::{Budget, LinearOperator, ResidualTolerance};
use scioxide_linalg::{
    EquilibrationMetadata, IterativeRefinement, LinalgExecutionOptions, LuDecomposition,
    Matrix, RefinementCriterion, RefinementFallback, RefinementFallbackReason,
    RefinementOptions, RefinementProblem, RefinementReport, RefinementSystem,
    RefinementTermination,
};

let n = 40_usize;
let u: Vec<f64> = (0..n).map(|i| ((i + 1) as f64).sqrt()).collect();
let v: Vec<f64> = (0..n).map(|i| 1.0 + (i % 5) as f64).collect();
let (uu, vv) = (
    u.iter().map(|x| x * x).sum::<f64>(),
    v.iter().map(|x| x * x).sum::<f64>(),
);
// Entry (i, k) of reflection H = I − 2 w wᵀ / (wᵀ w).
let reflect = |w: &[f64], ww: f64, i: usize, k: usize| {
    (if i == k { 1.0 } else { 0.0 }) - 2.0 * w[i] * w[k] / ww
};
let rule = if criterion == "Componentwise" {
    RefinementCriterion::Componentwise
} else {
    RefinementCriterion::Normwise
};
let fallback_policy = if use_fallback {
    RefinementFallback::OnFailure
} else {
    RefinementFallback::Disabled
};
let tolerance = ResidualTolerance::new(0.0, 1e-15).map_err(|e| e.to_string())?;
let name = |t: RefinementTermination| match t {
    RefinementTermination::Converged => "Converged",
    RefinementTermination::Stagnation => "Stagnation",
    RefinementTermination::IterationLimit => "IterationLimit",
    RefinementTermination::EvaluationLimit => "EvaluationLimit",
    RefinementTermination::ExecutionStopped(_) => "ExecutionStopped",
    RefinementTermination::CorrectionFailed => "CorrectionFailed",
};
let reason = |r: RefinementFallbackReason| match r {
    RefinementFallbackReason::Conversion => "Conversion",
    RefinementFallbackReason::NumericalFailure => "NumericalFailure",
    RefinementFallbackReason::Stagnation => "Stagnation",
};
// Construct A = H_u Σ H_v (σ_j = 10^(−t j/(n−1))) and refine with at most k corrections.
let run = |t: f64, k: usize| -> Result<(RefinementReport<f64>, f64), String> {
    let s: Vec<f64> = (0..n)
        .map(|j| 10.0_f64.powf(-t * j as f64 / (n - 1) as f64))
        .collect();
    let entry = |i: usize, j: usize| -> f64 {
        (0..n)
            .map(|m| reflect(&u, uu, i, m) * s[m] * reflect(&v, vv, m, j))
            .sum()
    };
    let data: Vec<f64> = (0..n * n).map(|idx| entry(idx / n, idx % n)).collect();
    let a = Matrix::from_vec(n, n, data).map_err(|e| e.to_string())?;
    let b: Vec<f64> = (0..n)
        .map(|i| a.as_slice()[i * n..(i + 1) * n].iter().sum())
        .collect();
    // Convert equilibrated A to f32, factor it, and use its inverse operator for corrections.
    let meta = EquilibrationMetadata::prepare(RefinementSystem::Dense(a.view()))
        .map_err(|e| e.to_string())?;
    let mut low = Matrix::<f32>::zeros(n, n).map_err(|e| e.to_string())?;
    meta.scale_matrix_into(a.view(), &mut low.view_mut())
        .map_err(|e| e.to_string())?;
    let lu32 = LuDecomposition::factor(&low).map_err(|e| e.to_string())?;
    let lu64 = LuDecomposition::factor(&a).map_err(|e| e.to_string())?;
    let (inverse, fallback_inverse) = (lu32.inverse_operator(), lu64.inverse_operator());
    let fallback: Option<&(dyn LinearOperator<f64> + Sync)> = if use_fallback {
        Some(&fallback_inverse)
    } else {
        None
    };
    // The correction limit is the execution iteration limit, including fallback corrections.
    let budget = Budget::try_from(k).map_err(|e| e.to_string())?;
    let options = RefinementOptions::new(tolerance)
        .with_criterion(rule)
        .with_fallback(fallback_policy)
        .with_execution_options(LinalgExecutionOptions::new().with_iteration_budget(budget));
    // Method objects hold only settings; borrow systems and inverse operators as problems on each call.
    let problem = RefinementProblem::new(
        RefinementSystem::Dense(a.view()),
        &inverse,
        Some(&meta),
        fallback,
    )
    .map_err(|e| e.to_string())?;
    let refinement = IterativeRefinement::new(options).map_err(|e| e.to_string())?;
    let zero = vec![0.0_f64; n];
    let (x, report) = refinement
        .refine(&problem, &b[..], &zero[..])
        .map_err(|e| e.to_string())?;
    let forward = x
        .as_slice()
        .iter()
        .fold(0.0_f64, |m, &xi| m.max((xi - 1.0).abs()));
    Ok((report, forward))
};
let sci1 = serde_json::json!({ "notation": "scientific", "significantDigits": 1 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "κ₂ [-]", "type": "number", "format": sci1 },
    { "key": "1", "label": "Termination reason" },
    { "key": "2", "label": "Corrections [count]", "type": "integer" },
    { "key": "3", "label": "Normwise backward error [-]", "type": "number", "format": sci2 },
    { "key": "4", "label": "Componentwise backward error [-]", "type": "number", "format": sci2 },
    { "key": "5", "label": "Forward error [-]", "type": "number", "format": sci2 },
    { "key": "6", "label": "κ₂ u [-]", "type": "number", "format": sci2 },
    { "key": "7", "label": "Fallback reason" },
    { "key": "8", "label": "Fallback calls [count]", "type": "integer" }
]);
let mut rows = Vec::new();
for t in 0..=10 {
    let (report, forward) = run(t as f64, 10)?;
    let error = report.final_error();
    rows.push((
        10.0_f64.powi(t),
        name(report.termination()),
        report.iterations(),
        error.map(|e| e.normwise()),
        error.and_then(|e| e.componentwise()),
        forward,
        10.0_f64.powi(t) * f64::EPSILON / 2.0,
        report.fallback_reason().map_or("—", reason),
        report.fallback_iterations(),
    ));
}
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "summary" })
);
let mut history = Vec::new();
for k in 1..=10 {
    let (report, _) = run(condition_exponent, k)?;
    // Omit exactly zero backward errors, which cannot appear on a logarithmic axis.
    if let Some(e) = report.final_error().filter(|e| e.normwise() > 0.0) {
        history.push([k as f64, e.normwise()]);
    }
}
let label = format!("κ₂ = 1e{condition_exponent}");
emit_line_chart!(
    &vec![
        serde_json::json!({ "name": label, "points": history, "style": { "showSymbol": true } })
    ],
    options = &serde_json::json!({
        "xLabel": "Maximum corrections k [count]",
        "yLabel": "Normwise backward error [-]",
        "yType": "log",
        "annotations": [{ "kind": "line", "axis": "y", "value": 1e-15, "label": "Tolerance 1e-15" }]
    })
);
// Determine the outcome by refining the selected t with at most 10 corrections.
let (report, forward) = run(condition_exponent, 10)?;
let termination = report.termination();
let outcome = match termination {
    RefinementTermination::Converged => {
        Outcome::satisfied("Selected backward error meets tolerance 1e-15")
    }
    RefinementTermination::CorrectionFailed => Outcome::failed("Correction computation failed"),
    _ => Outcome::partial("Stopped before meeting tolerance")
        .explanation("The returned solution is the best accepted iterate; its backward error exceeds tolerance."),
};
let mut outcome = outcome
    .status(name(termination))
    .diagnostic("Correction count", report.iterations() as f64, None)
    .diagnostic("Forward error", forward, None);
if let Some(e) = report.final_error() {
    outcome = outcome.diagnostic("Normwise backward error", e.normwise(), None);
}
emit_outcome!(outcome);
```

For $\kappa_2 \le 10^{8}$, 3–6 corrections give `Converged` with normwise backward errors $1.7 \times 10^{-17}$–$4.2 \times 10^{-16}$.
Rounding alone when forming $b$ in `f64` (relative order $u$) can move the stored system's exact solution from $x^{\star}$ by order $\kappa_2 u$, so tabulated forward errors include data-rounding effects.
Converged rows' forward errors are 0.07–0.16 times $\kappa_2 u$ for $\kappa_2 \ge 10^{3}$ (eight times $u$ for $\kappa_2 = 1$), growing proportionally to conditioning.
For $\kappa_2 \ge 10^{9}$, corrections stop reducing backward error and terminate with `Stagnation`, leaving single-precision-scale backward errors about $10^{-9}$ and forward errors 0.18 for $10^{9}$ and 130 for $10^{10}$, no longer meaningful as solutions.
The earlier guide $\kappa \ll 1/u_f \approx 1.7 \times 10^{7}$ is approximate: this matrix converges through $10^{8}$ and fails to converge at $10^{9}$.

At plotted $\kappa_2 = 10^{8}$, each correction reduces backward error by about two orders, falling below tolerance $10^{-15}$ at correction 6 with $3.2 \times 10^{-17}$.
Selecting $t = 10$ gives a partial outcome with `Stagnation`; the returned solution is the best accepted iterate, with forward error 130.
Enabling fallback switches once to `f64` LU on stagnation (reason `Stagnation`, one fallback call); $10^{9}$ converges in five corrections and $10^{10}$ in four, with backward errors $1.3 \times 10^{-17}$ and $7.5 \times 10^{-16}$ respectively.
Under componentwise checks, $\kappa_2 \le 10^{8}$ rows converge in the same counts; at $10^{9}$, componentwise backward error continues decreasing slightly each correction and stops with `IterationLimit` (10 corrections, normwise backward error $6.2 \times 10^{-14}$).
Table values are Wasm results for this page; native libm differences change matrix rounding and may alter correction counts or termination reasons for borderline $10^{9}$ rows.

## Summary

Iterative refinement computes corrections with lower-precision factors and residuals/updates in working precision, reaching working-precision backward error in a few corrections when $\kappa(A) u_f$ is well below 1.
Exact residual accumulation for explicit matrices can also reduce forward error relative to the stored system, but cannot remove input $A$ and $b$ errors amplified by $\kappa(A)$.
`IterativeRefinement` holds only settings; original systems, lower-precision inverse operators, equilibration scales, and fallback operators are borrowed per call as `RefinementProblem`, with success determined by report `termination()` or `is_success()`.
Correction limits come from `LinalgExecutionOptions`'s iteration limit (default 10); even limits or stagnation return the best iterate, so inspect termination before using it.
For stagnation from poor conditioning, supply `RefinementFallback::OnFailure` and a working-precision inverse operator to switch once and obtain convergence.
