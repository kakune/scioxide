Even for a sparse matrix with tens of thousands of dimensions, $e^{tA}$ and a matrix of eigenvectors are usually dense, so forming and storing $n^2$ entries is impractical.
Many applications, however, need much less information than the full matrix: an action on a vector $e^{tA}v$, a few eigenvalues, or the largest singular values.
`scioxide-linalg` computes these with seven methods that use only operator products $x \mapsto Ax$ (and adjoint products $x \mapsto A^{\mathsf H}x$).
This page explains the conventions shared by the seven methods and the action of matrix functions on vectors.
A few eigenpairs are covered in [A few eigenpairs of large operators](../partial-spectra/), leading singular values and low-rank approximations in [Partial SVD and randomized low-rank approximation](../partial-svd-and-low-rank/), and norm estimation in [Estimating the 1-norm and exact operator norms](../norm-estimation/).

## Shared conventions

### Method objects

Construct an operator-only method as a value containing only settings.
This value is called a **method object**.
A method object stores neither the operator dimensions nor the number of input columns; it reads them from the operator and input on each call.
Unlike a Plan (`…Plan`), which holds reusable precomputation such as a factorization or ordering, a method object prepares nothing before computation, so the same value can be used directly with operators of different dimensions.
Settings are also checked at call time, and `workspace_requirements` and the execution functions return the same errors before computation starts.

| Method object | Computes | Operator | Dimensions read on each call | API returning owned values | API with caller-provided output / scoped API | Report |
|---|---|---|---|---|---|---|
| `ExponentialAction` | $\varphi_k(tA)B$ | Square `AdjointOperator` | $n$, number of columns in $B$ | `apply` | `apply_into` | `ExponentialActionReport` |
| `FunctionAction` | $f(A)B$ | Square `LinearOperator` | $n$, number of columns in $B$ | `apply` | `apply_into` | `FunctionActionReport` |
| `PartialSpectrumSolver` | A few eigenpairs | `SpectrumOperator` | $n$ | `solve` | `solve_into` | `PartialSpectrumReport` |
| `LobpcgSolver` | Extreme eigenpairs of a Hermitian definite pair | `LobpcgOperator` | $n$, number of constraint columns $c$ | `solve` | `solve_into` | `LobpcgReport` |
| `PartialSvdSolver` | Leading singular triplets | `AdjointOperator` | Number of rows $m$, number of columns $n$ | `solve` | `solve_into` | `PartialSvdReport` |
| `RandomizedLowRank` | Low-rank SVD and column interpolative decomposition | `AdjointOperator` | $m$, $n$, number of sketch columns $w$ | `svd`, `interpolative` | `svd_into`, `interpolative_into` | `LowRankReport` |
| `OneNormEstimator` | Estimate of $\lVert A \rVert_1$ | Square `AdjointOperator` | $n$ | `estimate` | `estimate_scoped` | `OneNormReport` |

`LinearOperator` and `AdjointOperator` are scioxide-core traits; the latter also provides adjoint products $A^{\mathsf H}x$.
A dense matrix becomes an operator with an adjoint through `matrix.view().try_finite()?`, and a tridiagonal matrix through `matrix.view()`.
Only `FunctionAction` uses `FunctionAction::default()` to construct default settings; the others use `new`.
The argument to `new` is a 1-norm upper bound for `ExponentialAction`, the requested count for `PartialSpectrumSolver`, `LobpcgSolver`, and `PartialSvdSolver`, and the target rank for `RandomizedLowRank`; `OneNormEstimator::new()` takes no arguments.

### Workspace requirements and reservation

Obtain the workspace size from the method object and operator with `method.workspace_requirements(&op, …)` (`…` supplies dimensions from the table's “Dimensions read on each call” column that cannot be read from the operator, such as the number of columns or constraints).
Each method has distinct requirement and workspace types (`ExponentialActionRequirements` and `ExponentialActionWorkspace` for `ExponentialAction`); passing requirements for another method is a compile error.
Requirements provide the bytes needed for a new workspace through `required_bytes()` and the execution options' byte limit through `byte_limit()`.
Create an empty workspace with `new()`, use `check(&requirements)` to check whether its capacity is sufficient (`Capacity::Sufficient`) or needs growth (`Capacity::NeedsGrowth`), and grow it with `try_reserve(&requirements)`.
`method.workspace(&op, …)` creates an empty workspace and reserves its storage in one step.
The required bytes include storage for nested dense factorizations, such as eigenvalue computations on small projected matrices; requirements exceeding the limit in `LinalgExecutionOptions::with_byte_limit` are rejected with `ResourceLimit` before computation.

### APIs returning owned values and APIs with caller-provided output

The call-form names (APIs returning owned values, APIs with caller-provided output, and scoped APIs) are defined in [Workspaces, execution contexts, and attempt records](../workspaces-and-execution/).
APIs returning owned values (`apply`, `solve`, `svd`, `interpolative`, `estimate`) allocate the output and workspace on the spot, execute sequentially with `ExecutionContext::sequential_native()`, and return the output and report.
APIs with caller-provided output (`*_into`) write to the caller's output and reserved workspace, observing cancellation and deadlines through the execution context passed as the last argument.
Calls with caller-provided output allocate no storage as long as the reserved workspace is used for problems of the same size.
`OneNormEstimator` returns only one value and provides the scoped API `estimate_scoped` in place of an API with caller-provided output.
The workspace's `last_attempt()` returns an `AttemptRecord` recording the most recent attempt.
An attempt becomes `Succeeded` on `Converged`, `Stopped` for other termination reasons, and `Failed` for errors during computation; a call rejected by argument checking before computation becomes `PreflightRejected`.

### Execution limits and termination reasons

Every method object has a limit `with_applications` on applications of the operator (and preconditioner or mass matrix); the default is 64 for `OneNormEstimator` and 100,000 for the others.
Set execution options on the method object with `with_execution_options(LinalgExecutionOptions)` rather than on individual calls.
What its iteration limit (`with_iteration_budget`) counts depends on the method.
`ExponentialAction` counts Taylor terms and estimation products, `FunctionAction` counts Arnoldi steps, `PartialSpectrumSolver` and `PartialSvdSolver` count restart cycles, `LobpcgSolver` counts outer iterations, `RandomizedLowRank` counts sketch columns and subspace-iteration steps, and `OneNormEstimator` counts applications.
Without an explicit iteration limit, restart cycles and LOBPCG outer iterations are limited to 100.

The termination reason `SpectralTermination` has the following six variants and no method for determining success.

| Variant | Meaning | Outcome in this handbook |
|---|---|---|
| `Converged` | All requested results passed residual or accuracy checks | satisfied |
| `EvaluationLimit` | The application limit or the outer solve's evaluation limit was reached | partial |
| `IterationLimit` | The iteration, restart, Taylor-degree, or projection-dimension limit was reached | partial |
| `InvariantSubspace` | The Krylov subspace became invariant or reached the full dimension before all pairs passed the checks | partial |
| `AccuracyLimit` | The approximation was completed but failed the accuracy check | failed |
| `ExecutionStopped(reason)` | Stopped by cancellation or deadline | partial |

Even for termination reasons other than `Converged`, the call returns `Ok` and writes the partial results accepted so far to the output.
The contents of partial results depend on the report type and are explained in each method's section.
Invalid input and numerical breakdown return `Err`.
The following definitions block provides a function that converts termination reasons to variant names, which the two cells on this page use in tables and outcomes.

```rust
//| id: linalg-action-termination-name
//| kind: definitions
//| title: "Termination reason names"
//| crates: [scioxide-linalg]
use scioxide_linalg::SpectralTermination;

/// Convert a termination reason to its variant name (the cancellation reason is omitted from the table).
pub(crate) fn termination_name(termination: SpectralTermination) -> &'static str {
    match termination {
        SpectralTermination::Converged => "Converged",
        SpectralTermination::EvaluationLimit => "EvaluationLimit",
        SpectralTermination::IterationLimit => "IterationLimit",
        SpectralTermination::InvariantSubspace => "InvariantSubspace",
        SpectralTermination::AccuracyLimit => "AccuracyLimit",
        SpectralTermination::ExecutionStopped(_) => "ExecutionStopped",
    }
}
```

## Exponential, φ-function, and analytic-function actions

### Exponential actions by the truncated Taylor method

`ExponentialAction` computes $\varphi_k(tA)B$ for an $n \times n$ operator $A$ and a block $B$ containing $c$ vectors of dimension $n$.
The $\varphi$ functions are defined by

```text
φ₀(z) = eᶻ,   φₖ(z) = Σ_{j ≥ 0} zʲ / (j + k)!   (k ≥ 1)
```

and appear in time integration with exponential integrators.
For example, the solution of $\dot u = Au + g$ with constant forcing $g$ is $u(t) = e^{tA}u_0 + t\varphi_1(tA)g$.
Pass the function and time $t$ at call time with `PhiFunction::exp(t)` or `PhiFunction::phi(k, t)`.

The method is the truncated Taylor method of Al-Mohy and Higham (2011).
With a shift $\mu$, the degree-$m$ Taylor polynomial $T_m(X) = \sum_{j=0}^{m} X^j/j!$, and $s$ steps, the method computes

```text
e^{tA} b ≈ e^{tμ} ( T_m( t(A − μI)/s ) )^s b
```

This requires $s$ polynomial actions, or at most $ms$ products.
$\theta_m$ is the largest value such that $\lVert X \rVert_1 \le \theta_m$ implies $T_m(X) = e^{X + \Delta X}$ and $\lVert \Delta X \rVert_1 \le u \lVert X \rVert_1$ ($u = \varepsilon/2$ is the unit roundoff); in double precision, $\theta_{10} = 0.144$ and $\theta_{55} = 9.9$.
The degree and step count are selected by the following rule from a quantity $\alpha$ used in place of $\lVert t(A - \mu I) \rVert_1$:

```text
s = ⌈ α / θₘ ⌉,   (m, s) = argmin_{m ≤ m_max} m·s
```

Here $m_{\max}$ is the maximum Taylor degree, 55 by default.
Using the caller's upper bound, set $\alpha$ to $\lvert t \rvert \times$ the upper bound.
When this exceeds $2p_{\max}(p_{\max} + 3)\theta_{m_{\max}}/(m_{\max} c)$ (about $31.7/c$ by default, where $c$ is the column count), the expected savings exceed the products needed for 1-norm estimation.
An estimator using adjoint products therefore computes $d_p = \lVert (t(A - \mu I))^p \rVert_1^{1/p}$ for $p = 2, \dots, p_{\max} + 1$ and uses $\alpha = \min(\lvert t \rvert \times \text{upper bound}, \max(d_p, d_{p+1}))$ for degrees $m$ satisfying $p(p-1) \le m + 1$ ($p_{\max}$ is the largest $p$ satisfying $p(p-1) \le m_{\max} + 1$, and is 8 by default).
$d_p$ does not exceed $\lVert t(A - \mu I) \rVert_1$ and can be much smaller for nonnormal matrices, allowing fewer steps.
Each step stops adding terms when the sum of the 1-norms of the last two terms is at most $(\tau_{\mathrm{abs}} \lVert b \rVert_1 + \tau_{\mathrm{rel}} \lVert y \rVert_1)/s$ ($\lVert y \rVert_1$ is the largest 1-norm of a partial sum in that step and measures the scale of rounding error in the partial sums).
The exponential uses one $(m, s)$ for all columns, whereas $\varphi$ functions select it separately for each column.

For $k \ge 1$, obtain $\varphi_k(tA)b$ from the following augmented matrix of order $n + k$, formed with $\hat b = b/\lVert b \rVert_1$ and the $k \times k$ upper-shift matrix $J$ ($Je_{j+1} = e_j$), as in Al-Mohy and Higham (2011), Theorem 2.1:

```text
Ã = ⎡ tA   b̂ e₁ᵀ ⎤ ,     φₖ(tA) b̂ = first n components of ( e^Ã e_{n+k} )
    ⎣ 0      J   ⎦
```


A product with $\tilde A$ requires only one product with $A$ and a shift of the additional $k$ components, so the augmented matrix is never formed.
The trailing $k \times k$ block is nilpotent apart from the shift and is advanced exactly; the Taylor series and its stopping test (including the norms of $b$ and $y$ above) apply only to the first $n$ components of the augmented vector.
For $\varphi$ functions, selection of $(m, s)$ uses the augmented-matrix norm bound $\max(\lvert t \rvert \times \text{upper bound}, 1 + \lvert t\mu \rvert)$.
Each step adds terms up to the maximum degree, rather than the selected degree, to check the tolerance; failure to meet it gives `IterationLimit`.

The upper bound is required: `bound` in `ExponentialAction::new(bound)` must bound $\lVert A - \mu I \rVert_1$ from above.
The method cannot verify this bound, and a bound that is too small can make the result inaccurate.
Estimated norms are used only to select $(m, s)$ and do not replace the upper bound.
`with_shift(μ)` uses $e^{tA} = e^{t\mu} e^{t(A - \mu I)}$ and can reduce $\lVert A - \mu I \rVert_1$ and the number of steps.
The commonly used $\mu = \operatorname{tr}(A)/n$ cannot be computed from a general operator, so the caller supplies it.
The factor $e^{t\mu}$ is multiplied using an extended exponent range, so its magnitude need not be representable as a floating-point number on its own.
For $\varphi$ functions, the shift applies to the entire augmented matrix, and the trailing block decays as $e^{-t\mu}$.
A large shift causes cancellation in the $\varphi$ series at each step; for $\lVert A - \mu I \rVert_1 = 1$ and $t\mu = 100$ through $800$, the relative errors of $\varphi_1$ through $\varphi_3$ range from $2 \times 10^{-13}$ to $4 \times 10^{-11}$ in double precision.

Defaults are shift 0, tolerances $\tau_{\mathrm{abs}} = 0$ and $\tau_{\mathrm{rel}} = u$, at most 100,000 applications, Taylor degree at most 55 (`with_terms`, with values above 55 rejected), and the exponential only (`with_max_phi(0)`).
Setting $\tau_{\mathrm{rel}}$ below $u$ lowers $\theta_m$ and increases the step count.
To use $\varphi$ functions, prepare augmented-matrix storage with `with_max_phi(k)` ($k$ must not exceed the maximum Taylor degree); a larger index gives `InvalidInput` (`OutOfRange`) at call time.
With exact arithmetic and exact norm estimates, the selected $(m, s)$ keeps the relative backward error of the truncated series at most $u$ (or $\tau_{\mathrm{rel}}$ if $\tau_{\mathrm{rel}}$ is smaller).
Non-finite bounds or shifts are rejected as `NonFinite` when requirements are computed; a negative bound, Taylor degree above 55, or `max_phi` above the maximum Taylor degree is rejected as `InvalidInput` (`OutOfRange`).
Overflow in the product of $\lvert t \rvert$ and the bound, in $t\mu$, or in intermediate values gives `NumericalInstability` (`Overflow`); underflow of a normalized $\varphi$-function term before restoring the factor $\lVert b \rVert_1$ gives `NumericalInstability` (`Underflow`).

The report `ExponentialActionReport` holds a termination reason `termination()` shared by all columns and an application count `applications()` including norm estimation.
Read per-column diagnostics through the `ExponentialActionAccepted` returned by the workspace's `last_accepted()`.
`progress()` returns the fraction $f$ of $[0, t]$ covered by completed steps, `estimated_errors()` returns the sum of the truncation indicators of completed steps, and `completed()` reports whether all steps completed.
The truncation indicator is the 1-norm of the last two terms in each step: an estimate of truncation error, rather than an upper bound on forward error.
`last_accepted()` returns `None` before the first call, after `try_reserve`, and after a call returning `Err`.
On a limit or cancellation, each output column contains the result through its completed steps, which is $e^{ftA}b$ for the exponential.
A column with no completed steps contains $b$ for the exponential and 0 for $\varphi$ functions.

### Semidiscrete solution of the heat equation

Semidiscretizing the heat equation $u_t = \kappa u_{xx}$ ($\kappa = 1$ m²/s, $x \in [0, 1]$ m, $u(0) = u(1) = 0$) with second differences on a grid of spacing $h = 1/(n+1)$ gives $\dot u = Au$ with $A = \operatorname{tridiag}(1, -2, 1)/h^2$, whose solution is $u(t) = e^{tA}u_0$.
The discrete Laplacian has eigenvectors $\sin(k\pi x_i)$ and eigenvalues $\lambda_k = -\tfrac{4}{h^2}\sin^2\tfrac{k\pi h}{2}$, so the following expansion of the initial value gives the exact semidiscrete solution:

```text
u₀ = Σₖ cₖ sin(kπxᵢ),   cₖ = 2h Σᵢ u₀(xᵢ) sin(kπxᵢ)
```

The exact semidiscrete solution is then $\sum_k c_k e^{\lambda_k t}\sin(k\pi x_i)$.
For the dimensionless initial temperature $u_0 = 4x(1-x)$, the continuous problem has the Fourier-series solution $\sum_{k\,\text{odd}} \tfrac{32}{(k\pi)^3} e^{-(k\pi)^2 t}\sin(k\pi x)$; its difference from the semidiscrete solution is the spatial discretization error $O(h^2)$.
$\lVert A \rVert_1 = 4/h^2$, and shifting by $\mu = \operatorname{tr}(A)/n = -2/h^2$ gives $\lVert A - \mu I \rVert_1 = 2/h^2$.

The following definitions block shares this model between two cells.
`heat_matrix(n, scale)` returns $A$ multiplied by scale ($A$ for scale = 1 and $tA$ for scale = $t$); `grid` provides the grid and initial temperature, and `semi_discrete` and `continuum` provide the two solutions used for verification.
The verification functions use the standard functions of `f64`.

```rust
//| id: linalg-heat-model
//| kind: definitions
//| title: "Semidiscrete heat equation and verification solutions"
//| crates: [scioxide-core, scioxide-linalg]
use scioxide_core::SciOxideError;
use scioxide_linalg::TridiagonalMatrix;

/// Interior points xᵢ = i h (h = 1/(n + 1)) and initial temperature u₀ = 4x(1 − x).
pub(crate) fn grid(n: usize) -> (Vec<f64>, Vec<f64>) {
    let h = 1.0 / (n + 1) as f64;
    let x: Vec<f64> = (1..=n).map(|i| i as f64 * h).collect();
    let u0 = x.iter().map(|&xi| 4.0 * xi * (1.0 - xi)).collect();
    (x, u0)
}

/// scale · tridiag(1, −2, 1)/h². With scale = t, this gives tA.
pub(crate) fn heat_matrix(n: usize, scale: f64) -> Result<TridiagonalMatrix<f64>, SciOxideError> {
    let s = scale * ((n + 1) as f64).powi(2);
    TridiagonalMatrix::new(vec![s; n - 1], vec![-2.0 * s; n], vec![s; n - 1])
}

/// Exact semidiscrete solution Σₖ cₖ e^{λₖ t} sin(kπxᵢ) (reference value using standard f64 functions).
pub(crate) fn semi_discrete(n: usize, t: f64) -> Vec<f64> {
    let (x, u0) = grid(n);
    let h = 1.0 / (n + 1) as f64;
    let pi = std::f64::consts::PI;
    let modes: Vec<(f64, f64)> = (1..=n)
        .map(|k| {
            let w = k as f64 * pi;
            let c: f64 = x
                .iter()
                .zip(&u0)
                .map(|(&xi, &ui)| ui * (w * xi).sin())
                .sum();
            let lambda = -4.0 / (h * h) * (0.5 * w * h).sin().powi(2);
            (w, 2.0 * h * c * (lambda * t).exp())
        })
        .collect();
    x.iter()
        .map(|&xi| modes.iter().map(|&(w, c)| c * (w * xi).sin()).sum())
        .collect()
}

/// Evaluate the continuous solution Σ_{k odd} 32/(kπ)³ e^{−(kπ)² t} sin(kπx) at interior points (reference value).
pub(crate) fn continuum(n: usize, t: f64) -> Vec<f64> {
    let (x, _) = grid(n);
    let pi = std::f64::consts::PI;
    x.iter()
        .map(|&xi| {
            (1..400)
                .step_by(2)
                .map(|k| {
                    let w = k as f64 * pi;
                    32.0 / w.powi(3) * (-w * w * t).exp() * (w * xi).sin()
                })
                .sum()
        })
        .collect()
}

/// Difference between two vectors measured in the maximum norm.
pub(crate) fn max_gap(p: &[f64], q: &[f64]) -> f64 {
    p.iter().zip(q).fold(0.0, |m, (u, v)| m.max((u - v).abs()))
}
```

### f(A)b by restarted Arnoldi

`FunctionAction` computes general matrix-function actions $f(A)b$ with a restarted Arnoldi process.
Select the function with `MatrixFunction`: in addition to `Exp`, `Log`, `Sqrt`, `Power(p)`, `Sign`, and others, a caller-supplied analytic function `Analytic` is supported.
For each column, construct an Arnoldi basis of length $m$ (the restart length) starting from $b/\lVert b \rVert_2$, then restart from the last basis vector.
The Hessenberg matrices from all cycles are retained together as one Hessenberg matrix $H$ of order up to $p$ (the projection dimension); each cycle adds the correction $\lVert b \rVert_2 V_k (f(H)e_1)_k$ ($V_k$ is that cycle's basis and $(\cdot)_k$ the corresponding rows; Eiermann and Ernst, 2006).
$f(H)$ is computed from a complex Schur decomposition, and each cycle requires dense computation of cost $O(p^3)$ up to order $p$.
Storage is limited to $O(nm)$ for the basis and $O(p^2)$ for $H$.
A column stops when its error indicator meets the tolerance or its Krylov subspace becomes invariant; reaching projection dimension $p$ first gives `IterationLimit`.

Defaults are restart length 16 (`with_restart`), projection dimension 64 (`with_projection`, which must be at least the restart length or gives `InvalidInput` (`Inconsistent`)), at most 100,000 applications, tolerances $\tau_{\mathrm{abs}} = \tau_{\mathrm{rel}} = \sqrt{\varepsilon}$, and the default `with_function_settings` settings for dense evaluation of $f$ on the projected matrix.
The stopping test requires the per-column error indicator to be at most $\tau_{\mathrm{abs}} \lVert b \rVert_2 + \tau_{\mathrm{rel}} \lVert y \rVert_2$, where $y$ is the current approximation.
The error indicator is $\lVert b \rVert_2\, \beta\, \lvert e_l^{\mathsf T} f(H) e_1 \rvert$, but at least $\varepsilon \lVert y \rVert_2$, using the final subdiagonal entry $\beta$ in the Arnoldi recurrence and the order $l$ of $H$; it becomes 0 when the subspace is invariant.
This indicator is an error estimate, rather than an upper bound.
A real operator can also produce complex output, such as the square root of a matrix with negative eigenvalues.
For real output, the real part of each approximation is written; if the discarded imaginary part (for a real-valued result, the error in evaluating $f(H)$ by the complex Schur method) exceeds the larger of the stopping threshold and error indicator, the result is `DomainError`.
The assumptions of `MatrixFunction::Analytic` must hold for the eigenvalues of each cycle's projection $H$ as well as those of $A$.

For restart length $m$, projection dimension $p$, and $c$ columns, `FunctionActionWorkspace` holds $O(nm + p^2 + nc)$ scalars; its size is given by the requirements `FunctionActionRequirements`.
The report `FunctionActionReport` holds a termination reason shared by all columns, the application count, and the total number `cycles()` of completed restart cycles across all columns.
Read per-column diagnostics through the `FunctionActionAccepted` returned by the workspace's `last_accepted()`: `estimated_errors()` gives the error indicator from the last completed cycle, and `completed()` reports whether the stopping test was met.
On a limit or cancellation, each output column contains the approximation through its completed cycles; a column with no completed cycles contains 0.

The following cell computes $e^{tA}u_0$ for the same heat equation as the preceding cell, as $\exp(B)u_0$ for $B = tA$, with the API of `FunctionAction` that accepts caller-provided output.
Inputs are time $t$, the number $n$ of interior points, and maximum projection dimension $p$ (32, 64, or 128); the tolerance is set to $\tau_{\mathrm{rel}} = 10^{-13}$ for comparison.
The table places the termination reason, application count, cycle count, error indicator, and actual error (difference from the exact semidiscrete solution) side by side to check how the indicator estimates the error.

    _ => Outcome::partial("Stopped at the projection-dimension limit; the output is the approximation obtained so far")

With the defaults $t = 0.02$ s, $n = 100$, and $p = 64$, `FunctionAction` reaches the projection-dimension limit after 4 cycles and 64 applications, stopping with `IterationLimit`.
The approximation's 2-norm error is $8.5 \times 10^{-5}$, and its error indicator $2.1 \times 10^{-3}$ is about 25 times larger.
The output at termination can be read as a partial result whose accuracy is estimated by the error indicator.
With $p = 128$, 8 cycles and 128 applications reduce the error to $7.8 \times 10^{-11}$ (indicator $5.4 \times 10^{-9}$), but the tolerance $10^{-13}$ is still unmet and the termination reason remains `IterationLimit`.
At $t = 0.001$ s, `Converged` occurs after 3 cycles and 48 applications, an order of magnitude fewer than `ExponentialAction` at the same time (539 applications).
Here the indicator $6.3 \times 10^{-15}$ is smaller than the actual error $1.7 \times 10^{-14}$, both at rounding-error level, also showing that the indicator is not an upper bound.
For an unrestarted Krylov-subspace approximation with eigenvalues in the negative-real-axis interval $[-\lVert tA \rVert_2, 0]$, the dimension needed to make the error sufficiently small grows roughly as the square root of $\lVert tA \rVert_2$ (Hochbruck and Lubich, 1997).
It therefore needs fewer applications than `ExponentialAction`, whose count is proportional to $t\lVert A \rVert_1$.
For this example's $\sqrt{816} \approx 29$, however, `FunctionAction` with restart length 16 still misses tolerance $10^{-13}$ even at dimension 128.
Choose `FunctionAction` to reduce the application count, or `ExponentialAction` to avoid the projection's $O(p^3)$ computation and $O(p^2)$ storage and advance all steps using the application count determined by the upper bound.

## Summary

The seven methods using only operator products are method objects containing only settings; they read operator and input dimensions on each call, so one value can serve problems of different sizes.
For repeated calls, obtain requirements with `workspace_requirements`, reserve storage with `try_reserve`, and use an API with caller-provided output to avoid allocations on calls of the same size.
`SpectralTermination` provides no success predicate, and termination reasons other than `Converged` still return partial results in `Ok`, so read the termination reason and report diagnostics before using a result.
Compute $e^{tA}b$ with `ExponentialAction` when an upper bound on $\lVert A - \mu I \rVert_1$ is known; output stopped by a limit can be used as the solution at time $ft$.
Use `FunctionAction` when no upper bound is available or for functions other than the exponential; it needs fewer applications but can stop with `IterationLimit` at the projection-dimension limit, so check the error indicator.
