The 18 items in this table are public only when `scioxide-linalg`'s `blas` feature is enabled.
Implement `BlasProvider` wrapping a CBLAS-compatible library and attach `BlasDispatch` to a context with `LinalgExecutionContext::with_blas`; matching borrowed and scoped dense-matrix operations are dispatched to that provider.
SciOxide passes only initialized, bounds-checked slices and exposes no raw pointers.
Mutable outputs are staged separately from public inputs and outputs before writing, so provider failures leave public outputs unchanged.
Scalar types are distinguished by scioxide-core's `ScalarKind` (`F32`, `F64`, `Complex32`, `Complex64`); scioxide-core's `Triangle` specifies the triangle referenced by banded and packed matrices.
The handbook's browser cells cannot use external libraries, so no executable example uses this feature.

## Providers and selection

| Item | Kind | Role | Contract essentials | Explanation | Executable example |
|---|---|---|---|---|---|
| [`BlasProvider`](https://docs.rs/scioxide-linalg/0.1.0/scioxide_linalg/trait.BlasProvider.html) | Trait | Caller-implemented safe wrapper for external BLAS (`Sync`) | `name`, `capabilities`, and per-scalar-type `execute_f32`, `execute_f64`, `execute_complex32`, `execute_complex64` (accept one `BlasCall` and a worker count, returning library failures through `CapabilityError`). May call external code internally. `Err` and invalid values such as negative norms yield `CapabilityFailure`; nonfinite results yield `NonFinite`; all leave outputs unchanged | [Role of the blas feature](oxref:linalg-blas-feature) | - |
| [`BlasDispatch`](https://docs.rs/scioxide-linalg/0.1.0/scioxide_linalg/struct.BlasDispatch.html) | Struct | Provider selection and handling unsupported operations | `new(provider, fallback)`, `provider`, `fallback`. Owned by the caller and attached to an execution context | [Role of the blas feature](oxref:linalg-blas-feature) | - |
| [`BlasFallbackPolicy`](https://docs.rs/scioxide-linalg/0.1.0/scioxide_linalg/enum.BlasFallbackPolicy.html) | Enum | Handling calls unsupported by a provider | `Reference` (compute with SciOxide's native implementation) or `Error` (return `CapabilityUnavailable`). Unsupported calls include operations, storage orders, transforms, alignments, or integer widths absent from `BlasCapabilities`; operands without direct BLAS encodings that are not copied; operations with nonzero `BlasUlp` under `Accuracy::Exact`; and modified Givens calls requiring extended-range intermediates. Dense views are directly encodable if they are stored matrices with leading dimensions in a declared storage order or their transposes; conjugated complex views are encodable only when transposed (passed as `BlasTransform::Adjoint`). Level 3 (GEMM, SYRK, HERK, SYMM, HEMM, SYR2K, HER2K, TRMM, TRSM) copies other views into the workspace's provider packing region, becoming unsupported only if that region is insufficient. GEMV does not copy matrices and requires direct encoding; no operation copies input vector views (nonzero strides are required, and conjugated views require declared `BlasTransform::Conjugate`) | [Dispatch rules](oxref:linalg-blas-dispatch) | - |
| [`BlasCapabilities`](https://docs.rs/scioxide-linalg/0.1.0/scioxide_linalg/struct.BlasCapabilities.html) | Struct | Provider capability declaration | Build from `empty(BlasIntegerWidth)` (alignment 1, `SingleThreaded`, no operations) with `with_layout`, `with_transform`, `with_operation` (ULP per scalar-type/operation pair; scalar types where an operation is undefined yield `InvalidInput`), `with_minimum_alignment` (zero or non-power-of-two values yield `InvalidInput` before calling the provider), and `with_threading`. Inspect through `supports_layout`, `supports_transform`, `operation_ulp`, `integer_width`, `minimum_alignment`, and `threading` | [Capability declarations](oxref:linalg-blas-capabilities) | - |
| [`BlasUlp`](https://docs.rs/scioxide-linalg/0.1.0/scioxide_linalg/struct.BlasUlp.html) | Struct | Provider's promised componentwise accuracy | `new(maximum)` and maximum ULP distance `maximum`. SciOxide does not verify values and uses this only for dispatch. Calls requesting `Exact` reach the provider only for operations declaring 0 | [Capability declarations](oxref:linalg-blas-capabilities) | - |
| [`BlasIntegerWidth`](https://docs.rs/scioxide-linalg/0.1.0/scioxide_linalg/enum.BlasIntegerWidth.html) | Enum | Integer ABI for sizes, strides, and leading dimensions | `Lp64` (signed 32-bit) or `Ilp64` (signed 64-bit). Calls with values beyond the maximum follow the fallback policy without reaching the provider | [Capability declarations](oxref:linalg-blas-capabilities) | - |
| [`BlasThreading`](https://docs.rs/scioxide-linalg/0.1.0/scioxide_linalg/enum.BlasThreading.html) | Enum | How the provider uses worker counts | `SingleThreaded` (SciOxide always passes one worker) or `Budgeted` (obey the worker count of each call) | [Capability declarations](oxref:linalg-blas-capabilities) | - |

## Summary

To use an external BLAS library, enable `blas` and implement `BlasProvider` wrapping the library.
In `BlasCapabilities`, declare the provider's storage orders, transforms, integer widths, alignments, and operation ULP values per scalar type.
Use `BlasFallbackPolicy` to choose whether unmatched calls continue with the native implementation or stop with `CapabilityUnavailable`.
Calls requesting `Accuracy::Exact` reach providers only for operations declaring 0 ULP.
Attach `BlasDispatch` to the context with `LinalgExecutionContext::with_blas` and pass it to borrowed and scoped calls.
