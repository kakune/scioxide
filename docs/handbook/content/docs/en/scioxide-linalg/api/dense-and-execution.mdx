This table summarizes the dense matrix and vector types used as inputs and outputs throughout the crate, accuracy and execution controls for dense kernels corresponding to BLAS levels 1–3, and workspace types.
`Matrix` uses row-major order (entry $(i, j)$ is `data[i * cols + j]`); views carry separate row and column strides, allowing transposes and blocks to be borrowed without copying.
`LinalgExecutionOptions` combines the parallelism policy, product accuracy, time and byte limits, and iteration allowance.
With-options forms (`*_with_options`), caller-provided-output APIs (`*_into`), and scoped APIs (`*_scoped`) for dense matrix operations and factorizations accept this value directly; standard forms without settings execute sequentially with defaults.
The calling forms are defined in [Calling forms](oxref:linalg-api-forms).

`Accuracy` is read from `scioxide_core`.

## Summary

Own matrices and vectors with `Matrix` and `Vector`, and pass borrowed views of transposes and blocks without copying.
Use standard forms for a single product, inner product, or norm; when `Accuracy::Exact` accuracy or a byte limit is needed, pass `LinalgExecutionOptions` to a with-options form or scoped API.
For repeated computations of the same size, obtain `LinalgWorkspace` requirements from request values and preallocate once, then use caller-provided-output APIs to avoid allocation.
When passing dense matrices to iterative methods or operator actions, use a `FiniteMatrixView` checked once with `try_finite` as the operator.
