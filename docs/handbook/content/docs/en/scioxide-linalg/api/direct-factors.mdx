This table summarizes functions for solving linear systems once, direct dense factorizations, types deciding whether to accept solutions obtained from factors, and iterative-refinement types.
Factorizations return `Err` only for structural failures such as incompatible shapes, non-finite values, or exactly zero pivots; `DirectSolveOptions` decides solution acceptance at solve time.
Standard `solve(&b)` applies the default criteria (`RankPolicy::Exact`), returns a solution `Vector`, and turns rejection into an error (`Singular` for rank deficiency, `NumericalInstability` otherwise).
With-options `solve_with_options(&b, &options)` returns `DirectSolveResult` in `Ok` even on rejection, with `solution()` equal to `None`.
Caller-provided-output `solve_into` returns a report and leaves output unchanged on rejection.
Caller-provided-output and scoped APIs (such as `factor_into`, `solve_into`, `inverse_into`, and `condition_estimate_scoped`) replace workspace `last_attempt()` on every call, including empty or rejected solves, distinguishing stops due to limits or cancellation (`Stopped`), numerical failures (`Failed`), and rejection during validation (`PreflightRejected`).
`inverse_into` and `condition_estimate_scoped`, which have no plan, explicitly accept `LinalgExecutionOptions` and check all retained workspace capacity against its byte limit.
The calling forms are defined in [Calling forms](oxref:linalg-api-forms).

## One-shot functions

The following four functions construct factors or plans with default settings, solve once, and return only the solution `Vector`.
Rejection becomes an error; no report is returned.
One-shot functions for matrix functions and matrix equations (`matrix_function`, `solve_sylvester`, `solve_lyapunov`, and `solve_riccati`) appear in [Matrix functions and matrix equations](../functions-and-equations/).

## Summary

For a single solve, use `solve`, `least_squares`, `solve_triangular`, or `solve_structured` and receive rejection as an error.
For repeated solves with the same matrix, construct LU, Cholesky, LDL, or Householder QR factors once according to matrix properties and solve with standard `solve`.
To decide acceptance by numerical rank, condition number, or backward error, pass `DirectSolveOptions` to the with-options form and inspect the termination reason, allowing for `solution()` to be `None` even in `Ok`.
For least-squares problems that may lose rank, obtain minimum-norm solutions with `HouseholderMinimumNormPlan`; for continuing row or column insertion/deletion, update factors with `QrUpdateDecomposition`.
When lower-precision factors must achieve higher-precision backward error, pass `RefinementProblem` to `IterativeRefinement` and determine success through `RefinementTermination`.
