This table summarizes types computing matrix functions $f(A)$ as dense or sparse matrices and types solving Sylvester, Lyapunov, and Riccati matrix equations.

For a single solve, use the one-shot functions `matrix_function`, `solve_sylvester`, `solve_lyapunov`, and `solve_riccati`.
They construct plans with default settings, execute sequentially with `ExecutionContext::sequential_native()`, and return the resulting matrices.
Unaccepted solutions become errors.
For repeated evaluations or solves with the same coefficients, construct a plan (`MatrixFunctionPlan`, `SylvesterPlan`, `LyapunovPlan`, `RiccatiPlan`, `SparsePowerPlan`, or `SparseFunctionPlan`).
Plans validate inputs and perform preparation such as Schur decomposition or symbolic multiplication once.
Calling forms are defined in [Calling forms](oxref:linalg-api-forms).

A matrix-equation plan's `solve` returns the solution and diagnostics for the original equation, using the same `DirectSolveTermination` termination reasons as direct methods to decide acceptance.
Candidates failing residual or closed-loop stability checks remain `Ok` with `solution()` equal to `None`; `into_accepted()` turns this into a `NumericalInstability` error.
Plans' owning-result APIs (`new` and `solve`, and sparse plans' `evaluate`) execute in a sequential context without a clock, so a time limit gives `CapabilityUnavailable`.
Use `build`, `solve_into`, and `evaluate_into` to supply a context.

## Summary

For one matrix-function evaluation use `matrix_function`; for one matrix-equation solve use `solve_sylvester`, `solve_lyapunov`, or `solve_riccati`, receiving unaccepted solutions as errors.
For repeated evaluations with the same matrix, Fréchet derivatives or condition numbers, or complex results from real matrices, construct `MatrixFunctionPlan` and evaluate through caller-provided-output APIs.
Plans for sparse matrix powers and functions determine the output pattern in advance by filling connected blocks densely, so check fill with `structural_fill` before evaluation.
Matrix-equation plans' `solve` returns `Ok` even for candidates failing residual or stability checks; inspect `report().termination()` or convert rejection to an error with `into_accepted()`.
Report separation and condition-number fields are estimates and do not bound solution error.
