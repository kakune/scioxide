`scioxide-linalg` exposes storage and products for dense and structured matrices, direct factorizations and solution acceptance, eigenvalues and singular values, iterative methods, matrix functions and matrix equations, matrix-function actions on vectors, and partial spectra.
This guide identifies starting points by task and groups all 342 public items in purpose-specific tables.
Of these 342 items, 324 are available with default features; the remaining 18 require the `blas` feature.
The eight items in the `backend` module are lower-level components used by other SciOxide crates.
They may modify scratch storage on failure and have neither rank policies nor diagnostics.
Item-name links point to the version 0.1.0 API reference on docs.rs.

There are eight one-shot functions.
Linear-system functions `solve`, `least_squares`, `solve_triangular`, and `solve_structured` appear in the [One-shot functions](oxref:linalg-api-one-shot) table; matrix-function and matrix-equation functions `matrix_function`, `solve_sylvester`, `solve_lyapunov`, and `solve_riccati` appear in the respective tables in [Matrix functions and matrix equations](functions-and-equations/).

scioxide-sparse provides sparse storage (such as `CsrMatrix`) and preconditioners (`JacobiPreconditioner`, `IncompleteFactor`, `AmgPreconditioner`).
scioxide-core provides operator traits (`LinearOperator`, `AdjointOperator`, `Preconditioner`), tolerances, limits, and execution contexts.
These types are excluded from this guide's tables; consult the corresponding chapters' API guides.

## Type relationships

The basic owned storage types are `Matrix` (row-major) and `Vector`.
`view()` borrows strided `MatrixView` and `VectorView` views; matrix/vector arguments have forms `impl Into<MatrixView>` and `impl Into<VectorView>`, so `&Matrix` and `&[S]` can be passed directly.
A `FiniteMatrixView` checked for non-finite values with `try_finite()` implements `LinearOperator` and can serve as an operator in iterative methods and operator actions.

Factorization types (such as `LuDecomposition`) report errors only for structural failures such as shape mismatch, non-finite values, or exactly zero pivots.
`DirectSolveOptions` decides solution acceptance at solve time.
It contains numerical-rank policy `RankPolicy`, an optional lower limit `ReciprocalConditionThreshold` on reciprocal condition number, and whether to compute backward error (`Estimation`).
The default `RankPolicy::Exact` rejects solutions only for exactly singular factors, computing neither condition numbers nor backward errors.
The `solve` of banded, tridiagonal, and triangular factorizations and plans takes `StructuredOperation` first, selecting coefficient matrix $A$, $A^{\mathsf T}$, or $A^{\mathsf H}$.

A single `LinalgExecutionOptions` combines parallelism policy, product accuracy `Accuracy`, time and byte limits, and iteration allowance.
Dense operation and factorization forms accepting settings (the next section's with-options, caller-provided-output, and scoped APIs) take this value directly; each feature's settings (such as `DirectSolveOptions`, `StructuredSolveOptions`, and iterative solvers) incorporate it once through `with_execution_options`.
This leaves only mathematical choices in feature settings.

Plans (`…Plan`) compute and retain reusable data such as factors, coefficients, and Schur forms once at construction.
Method objects (such as `ExponentialAction`, `LobpcgSolver`, `IterativeRefinement`, and `CgSolver`) hold only settings, receiving operators and dimensions on each call.
Unlike plans, they contain no precomputed data, allowing a single value to serve differently sized problems.

## Call forms

An operation has the following forms distinguished by name suffixes.
Definitions and selection are in [calling forms](oxref:linalg-execution-forms).

| Form | Naming | Example |
|---|---|---|
| One-shot function | Free function | `solve(&a, &b)`, `least_squares(&a, &b)` |
| Standard form | No suffix | `LuDecomposition::factor(&a)`, `lu.solve(&b)`, `x.norm2()` |
| Options form | `*_with_options` | `LuDecomposition::factor_with_options(&a, &options)`, `lu.solve_with_options(&b, &accept)` |
| Caller-provided-output API | `*_into`, `*_in_place` | `lu.solve_into(&b, &accept, out, &mut ws, cx)` |
| Scoped API | `*_scoped` | `x.norm2_scoped(&options, cx)`, `lu.condition_estimate_scoped(&options, &mut ws, cx)` |

Standard and with-options forms together are called owning-result APIs.
Owning-result APIs execute in a sequential context without a clock, so time limits give `CapabilityUnavailable` before computation begins.
Caller-provided-output and scoped APIs accept `ExecutionContext` (root of a new operation) or `&mut SolveContext` (child of the caller's operation, charging usage against higher-level limits as well) and convert it internally to `LinalgExecutionContext`.
Parallel execution, cancellation, deadlines, and external BLAS providers are used through this context.

Query workspace size with `workspace_requirements` from one request value (such as `LuWorkspaceRequest`), check capacity with workspace `check`, and preallocate with `try_reserve`.
Repeated caller-provided-output calls of the same size allocate no new memory after preallocation.

Iterative solvers hold no preconditioner, borrowing it per call through `Preconditioning` (`None`, `Inverse`, `InverseAdjoint`).
Standard `solve(a, b)` of the 16 single-right-hand-side solvers starts from zero without preconditioning and returns `ConvergenceFailure` if tolerance is not met.
With-options `solve_with_options(a, b, preconditioning, x0)` and caller-provided-output `solve_into` return termination reasons.
All solvers use one `IterativeWorkspace`, retaining attempt records `last_attempt()` and results `last_accepted()` from solves that succeed or stop with usable iterates.

## Minimal executable example: pivoting and calling forms

For small $\varepsilon$, matrix $A = \begin{bmatrix} \varepsilon & 1 \\ 1 & 1 \end{bmatrix}$ and right-hand side $b = (1, 2)$ have exact solution $x_1 = 1/(1-\varepsilon)$, $x_2 = (1-2\varepsilon)/(1-\varepsilon)$.
Eliminating with pivot $a_{11} = \varepsilon$ without pivoting produces a large multiplier $1/\varepsilon$ that erases information in $a_{22}$, severely corrupting $x_1$.
LU with partial pivoting selects the largest-magnitude entry as pivot at each step, keeping multiplier magnitudes at most 1.

The following cell solves the same system with one-shot `solve`, standard factorization `lu.solve`, with-options `lu.solve_with_options`, and caller-provided-output `lu.solve_into`, alongside values obtained by directly evaluating elimination formulas without pivoting.
Inputs are exponent $t$ ($-20 \le t \le -1$) expressing the top-left entry as $\varepsilon = 10^{t}$ and exponent $s$ ($-6 \le s \le 0$) expressing the acceptable reciprocal-condition lower limit as $\tau = 10^{s}$.
With-options and caller-provided-output forms receive the same `DirectSolveOptions` specifying rank policy `DimensionScaledEpsilon`, lower limit $\tau$, and backward-error estimation.
The first table shows each route's termination reason, solution, and maximum relative difference from the exact solution, displaying unaccepted solutions as “Output unchanged.”
The second table shows the row selected as the first pivot, the numerical rank and estimated reciprocal condition number $\mathrm{rcond}_1$ from the with-options report, and backward error.
Tests check solution differences from the exact solution, the $\mathrm{rcond}_1$ estimate against hand-computed $1/4$, and unpivoted-elimination errors.

```rust
//| id: linalg-api-pivoted-solve
//| ref: linalg-api-pivoted-solve
//| title: "Comparing partially pivoted LU across calling forms"
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg]
//| inputs:
//|   epsilon_exponent: {"type":"range","label":"t in top-left entry ε = 10^t","description":"Smaller values make unpivoted elimination less stable.","min":-20,"max":-1,"step":1,"value":-12}
//|   rcond_floor_exponent: {"type":"range","label":"s in acceptable reciprocal-condition lower limit τ = 10^s","description":"Acceptance criterion for with-options and caller-provided-output forms. At s = 0, τ = 1 rejects this matrix's solution because rcond₁ ≈ 0.25.","min":-6,"max":0,"step":1,"value":-3}
//| cases:
//|   - {"id":"strict-floor","label":"τ = 1","description":"rcond₁ ≈ 0.25 falls below the lower limit, so with-options and caller-provided-output forms do not commit solutions.","inputs":{"rcond_floor_exponent":0}}
//|   - {"id":"mild-pivot","label":"ε = 0.1","description":"The multiplier is small, so even unpivoted-elimination error stays at the rounding-error level.","inputs":{"epsilon_exponent":-1}}
//|   - {"id":"tiny-pivot","label":"ε = 10⁻¹⁷","description":"Unpivoted elimination gives x₁ = 0.","inputs":{"epsilon_exponent":-17}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"paths","path":"/rows/0/2","approx":{"value":1.000000000001,"rtol":1e-14}}
//|       - {"artifact":"paths","path":"/rows/2/4","range":{"max":1e-15}}
//|       - {"artifact":"paths","path":"/rows/3/1","equals":"Accepted"}
//|       - {"artifact":"paths","path":"/rows/4/4","approx":{"value":2.2e-5,"rtol":0.05}}
//|       - {"artifact":"diagnostics","path":"/rows/0/1","equals":2}
//|       - {"artifact":"diagnostics","path":"/rows/0/2","approx":{"value":0.25,"rtol":1e-6}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: strict-floor
//|     expect:
//|       - {"artifact":"paths","path":"/rows/1/4","range":{"max":1e-15}}
//|       - {"artifact":"paths","path":"/rows/2/1","equals":"IllConditioned"}
//|       - {"artifact":"paths","path":"/rows/2/2","equals":null}
//|       - {"artifact":"paths","path":"/rows/3/2","equals":null}
//|       - {"artifact":"diagnostics","path":"/rows/0/3","equals":null}
//|       - {"path":"/outputs/2/state","equals":"failed"}
//|   - case: mild-pivot
//|     expect:
//|       - {"artifact":"paths","path":"/rows/4/4","range":{"max":1e-15}}
//|       - {"artifact":"diagnostics","path":"/rows/0/2","approx":{"value":0.225,"rtol":1e-6}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: tiny-pivot
//|     expect:
//|       - {"artifact":"paths","path":"/rows/1/4","range":{"max":1e-15}}
//|       - {"artifact":"paths","path":"/rows/4/2","approx":{"value":0.0,"atol":1e-12}}
//|       - {"artifact":"paths","path":"/rows/4/4","approx":{"value":1.0,"atol":1e-12}}
use scioxide_core::ExecutionContext;
use scioxide_linalg::{
    DirectSolveOptions, DirectSolveTermination as T, Estimation, LinalgExecutionOptions,
    LuDecomposition, LuWorkspaceRequest, Matrix, RankPolicy, ReciprocalConditionThreshold,
    Vector, solve,
};

let eps = 10.0_f64.powf(epsilon_exponent);
let tau = 10.0_f64.powf(rcond_floor_exponent);
let a = Matrix::from_rows(&[[eps, 1.0], [1.0, 1.0]]).map_err(|e| e.to_string())?;
let b = Vector::from_vec(vec![1.0, 2.0]);
// Exact solution (for independent comparison).
let exact = [1.0 / (1.0 - eps), (1.0 - 2.0 * eps) / (1.0 - eps)];

// One-shot function: factors and solves together, returning only the solution.
let x_once = solve(&a, &b).map_err(|e| e.to_string())?;
// Standard form: retains factors for reuse. Rejection becomes an error.
let lu = LuDecomposition::factor(&a).map_err(|e| e.to_string())?;
let x_plain = lu.solve(&b).map_err(|e| e.to_string())?;
// With-options form: accepts acceptance criteria and returns a solution and report. Returns Ok even on rejection.
let floor = ReciprocalConditionThreshold::new(tau).map_err(|e| e.to_string())?;
let accept = DirectSolveOptions::new(RankPolicy::DimensionScaledEpsilon)
    .with_minimum_reciprocal_condition(floor)
    .with_residual(Estimation::Estimate);
let detailed = lu
    .solve_with_options(&b, &accept)
    .map_err(|e| e.to_string())?;
// Caller-provided-output API: accepts output, workspace, and context. Rejection leaves output unchanged.
let request = LuWorkspaceRequest::solve(2, &LinalgExecutionOptions::new());
let mut workspace = LuDecomposition::<f64>::workspace(&request).map_err(|e| e.to_string())?;
let mut borrowed = Vector::zeros(2).map_err(|e| e.to_string())?;
let report = lu
    .solve_into(
        &b,
        &accept,
        borrowed.view_mut(),
        &mut workspace,
        ExecutionContext::sequential_native(),
    )
    .map_err(|e| e.to_string())?;

// Evaluate elimination formulas without pivoting directly (for independent comparison).
let x2 = (2.0 - 1.0 / eps) / (1.0 - 1.0 / eps);
let naive = [(1.0 - x2) / eps, x2];

// Show termination reasons by variant name.
let name = |t: T| match t {
    T::Accepted => "Accepted",
    T::RankDeficient => "RankDeficient",
    T::IllConditioned => "IllConditioned",
    T::ResidualRejected => "ResidualRejected",
    T::StabilityRejected => "StabilityRejected",
};
let diff = |x: &[f64]| {
    (0..2).fold(0.0_f64, |m, i| {
        m.max((x[i] - exact[i]).abs() / exact[i].abs())
    })
};
let row = |path: &'static str, status: Option<&'static str>, x: Option<&[f64]>| {
    (path, status, x.map(|x| x[0]), x.map(|x| x[1]), x.map(diff))
};
let accepted = report.termination() == T::Accepted;
let rows = vec![
    row("solve (one-shot call)", None, Some(x_once.as_slice())),
    row("lu.solve (standard form)", None, Some(x_plain.as_slice())),
    row(
        "lu.solve_with_options (with-options form)",
        Some(name(detailed.report().termination())),
        detailed.solution().map(|x| x.as_slice()),
    ),
    row(
        "lu.solve_into (caller-provided-output API)",
        Some(name(report.termination())),
        accepted.then_some(borrowed.as_slice()),
    ),
    row("Unpivoted elimination (formula)", None, Some(&naive[..])),
];
let full = serde_json::json!({ "significantDigits": 16 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "Path" },
    { "key": "1", "label": "Termination reason", "nullText": "None" },
    { "key": "2", "label": "x₁", "type": "number", "format": full, "nullText": "Output unchanged" },
    { "key": "3", "label": "x₂", "type": "number", "format": full, "nullText": "Output unchanged" },
    { "key": "4", "label": "Maximum relative difference from exact solution", "type": "number", "format": sci2, "nullText": "-" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "paths" })
);

let diagnostics = detailed.report();
let rcond = diagnostics.condition().map(|c| c.reciprocal().value());
let backward = diagnostics.residual().map(|r| r.scaled_norm());
let columns = serde_json::json!([
    { "key": "0", "label": "First pivot row (0-based)", "type": "integer" },
    { "key": "1", "label": "Numerical rank", "type": "integer" },
    { "key": "2", "label": "Estimated rcond₁", "type": "number", "format": sci3, "nullText": "Not estimated" },
    { "key": "3", "label": "Backward error η", "type": "number", "format": sci2, "nullText": "Not computed" }
]);
emit_table_with_columns!(
    columns,
    vec![(
        lu.permutation()[0],
        diagnostics.rank().rank(),
        rcond,
        backward
    )],
    metadata = serde_json::json!({ "id": "diagnostics" })
);

let termination = diagnostics.termination();
let outcome = if termination.is_success() {
    Outcome::satisfied("The with-options solution satisfies the acceptance criteria")
} else {
    Outcome::failed("With-options and caller-provided-output forms did not commit solutions").explanation(
        "Standard and one-shot forms accept under default criteria. Lowering τ allows solutions to be committed.",
    )
};
let mut outcome = outcome.status(name(termination));
if let Some(value) = rcond {
    outcome = outcome.diagnostic("Estimated rcond₁", value, None);
}
if let Some(value) = backward {
    outcome = outcome.diagnostic("Backward error η", value, None);
}
emit_outcome!(outcome);
```

With default $\varepsilon = 10^{-12}$, the factorization selects the second row (index 1) as the first pivot.
All four routes return the same solution, with zero relative difference from the exact solution obtained from formulas.
With-options and caller-provided-output termination reasons are `Accepted`, numerical rank is 2, and backward error $\eta$ is zero.
$\lVert A \rVert_1 = 2$ and $\lVert A^{-1} \rVert_1 = 2/(1-\varepsilon)$ give $\mathrm{rcond}_1 = (1-\varepsilon)/4$.
For $n \le 4$, LU computes $\lVert A^{-1} \rVert_1$ from each inverse column rather than estimating it, so the estimate 0.25 agrees with this value within rounding error.
Unpivoted elimination gives relative difference $2.2 \times 10^{-5}$ in $x_1$.

Setting $s = 0$ raises lower limit $\tau = 1$ above the estimate 0.25, giving termination reason `IllConditioned` for with-options and caller-provided-output forms.
The with-options form remains `Ok` without committing a solution; the caller-provided-output form leaves output unchanged, so solution fields show “Output unchanged.”
Since no solution is computed, backward error is also absent, shown as “Not computed” in the second table.
One-shot and standard forms accept under defaults and return the same solution.
At $\varepsilon = 10^{-1}$, the elimination multiplier is small, so even without pivoting the relative difference $4.0 \times 10^{-16}$ stays at the rounding-error level; the $\mathrm{rcond}_1$ estimate becomes 0.225.
At $\varepsilon = 10^{-17}$, unpivoted elimination gives $x_1$ equal to zero, entirely missing the correct value 1.
This matrix's condition number $\kappa_1(A) = 4/(1-\varepsilon)$ is about 4, so unpivoted error reflects algorithmic instability rather than an ill-conditioned problem.

## Reading results, errors, and diagnostics

- Failures return scioxide-core's `SciOxideError`, classified through `kind()` into `DimensionMismatch`, `NonFinite`, `Singular`, `DomainError`, `NumericalInstability`, `ConvergenceFailure`, `ResourceLimit`, `AllocationFailure`, `ExecutionStopped`, `CapabilityUnavailable`, and others.
  Errors describe what failed and carry no caller identity.
- Standard direct-method forms and one-shot functions return solutions alone.
  `DirectSolveTermination::require_accepted` turns rejection into errors: `Singular` for rank deficiency and `NumericalInstability` otherwise.
- Direct methods' with-options and caller-provided-output APIs, structured solves, and matrix equations return `Ok` even when unaccepted.
  Results communicate through shared termination reason `DirectSolveTermination` (`Accepted`, `RankDeficient`, `IllConditioned`, `ResidualRejected`, `StabilityRejected`) and presence or absence of `solution()`; `into_accepted()` converts rejection to the same errors as standard forms.
  Rejected candidates retain rank and conditioning diagnostics in reports (also residuals for residual-based rejection); caller-provided output changes only for `Accepted`.
- With-options and caller-provided-output iterative methods, operator actions, partial spectra, and iterative refinement return their best accepted results in `Ok` even on limits, cancellation, deadlines, or stagnation.
  Determine success solely from termination reasons in `LinearSolveTermination`, `SpectralTermination`, and `RefinementTermination`.
  Iterative reports classify returned iterates as `ResidualChecked` only on success and `Admissible` on stopping.
  Cancellation and deadline stops use `ExecutionStopped(reason)`; evaluation-count and iteration-count limits are distinguished by `EvaluationLimit` and `IterationLimit`.
- Caller-provided-output APIs write output after successful validation and computation; `Err` leaves output unchanged.
  Workspace `last_attempt()` records results as `Succeeded`, `Stopped`, `Failed`, or `PreflightRejected`.
- Factorization backward-error bounds (of the form $c\,n\,\varepsilon$), `Accuracy` inner-product error bounds, and reported residuals and backward errors do not guarantee forward error.
  Interpret forward error together with condition estimates.
  The full conventions are in [Linear algebra mathematics and shared conventions](../algorithms/).

## Summary

With a task in mind, select an item from the task-based API table and check its contract and explanation in the purpose-specific tables.
For a single solve, use a one-shot function or standard form, receiving rejection as an error.
To select acceptance criteria and read reports, use with-options forms and inspect termination reasons, allowing `solution()` to be `None` even in `Ok`.
For repeated computations of the same size, preallocate workspace once from request values and use caller-provided-output APIs to avoid allocation.
Determine iterative-method and operator-action success from report termination reasons rather than whether the result is `Ok`.
