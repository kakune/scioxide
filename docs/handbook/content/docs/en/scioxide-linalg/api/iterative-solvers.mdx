This table summarizes iterative methods for square-operator equations $Ax = b$ and rectangular least-squares problems, and their shared workspace, report, and termination-reason types.
Solver types (`…Solver`) are method objects holding only settings such as tolerances, iteration limits, and execution settings; they retain neither operators nor preconditioners.
Preconditioning is borrowed through `Preconditioning` on each call.

Single-right-hand-side solvers offer three calling forms.
Their definitions are in [Calling forms](oxref:linalg-api-forms).
Standard `solve(a, b)` starts from zero without preconditioning and returns a solution `Vector`.
Termination without meeting tolerance gives `ConvergenceFailure` (`NestedSolver`).
With-options `solve_with_options(a, b, preconditioning, x0)` accepts preconditioning and an initial guess (zero for `None`), returning `IterativeSolveResult` including the termination reason.
Caller-provided-output `solve_into(a, b, preconditioning, x, workspace, context)` starts from the values in `x`, uses `IterativeWorkspace` and a context, and returns `IterativeSolveReport`.
LSQR, LSMR, and matrix-splitting stationary iterations have no preconditioner argument.
Block methods' `solve(a, b, preconditioning, x0)` returns `BlockKrylovResult` including the termination reason.

Iterations are bounded by the smaller of the limit passed to `new` and the iteration allowance incorporated through `with_execution_options`.
With-options and caller-provided-output APIs return `Ok` even when stopped by iteration or evaluation limits, stagnation, breakdown, cancellation, or deadlines; the solution is the verified iterate with the smallest true residual.
Determine success from termination reason `LinearSolveTermination`.
The report's reliability class is `ResidualChecked` only on success and `Admissible` when stopped.
Stagnation (`Stagnation`) is detected when an update leaves the iterate unchanged, or when the verified true residual does not improve its previous minimum and that minimum is at or below the rounding-error floor $\varepsilon c(\lVert b \rVert_2 + \lVert A(s \circ x) \rVert_2)$.
Here $x$ is the verified iterate with the smallest residual, $s$ is a fixed sequence of $\pm 1$ signs, and $c$ is 16 for real types and 32 for complex types.
Computing $A(s \circ x)$ also counts against the evaluation limit.
Stationary iterations that compute true residuals every iteration (Richardson and matrix splittings) check the floor only at 50-iteration checkpoints; GMRES methods, including LGMRES, GCROT, and block variants, check only at cycle ends and verifications where the projected residual meets tolerance.
The floor does not change the tolerance.
The main causes of `Err` are shape mismatches (rejected before numerical computation), non-finite values, recurrence overflow, operator or preconditioner provider errors, resource allocation failure, reaching the evaluation limit before computing the initial residual, and solver-specific rejections listed below (such as non-Hermitian MINRES inputs or zero diagonals in stationary iterations); these leave output unchanged.

## Summary

Choose `CgSolver` for Hermitian positive-definite systems, `MinresSolver` for Hermitian indefinite systems, `GmresSolver` or `BicgstabSolver` for nonsymmetric systems, and `LsqrSolver` or `LsmrSolver` for rectangular least squares.
When only the solution is needed, use standard `solve(a, b)` and receive nonconvergence as an error.
For preconditioning, initial guesses, or iterates and residuals on stopping, use the with-options form and determine success from the termination reason in `IterativeSolveResult`.
For repeated solves of the same shape, preallocate workspace from `IterativeWorkspaceRequest` and use caller-provided-output APIs, reading attempt records and accepted state from `IterativeWorkspace`.
For repeated solves changing only the right-hand side of the same operator, LGMRES/GCROT's `solve_recycled_into` carries recycled spaces across calls.
