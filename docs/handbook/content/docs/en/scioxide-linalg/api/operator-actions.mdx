This page's tables summarize types using operator $A$ only through products $Av$ (and adjoint products $A^{\mathsf H}v$) to compute matrix-function actions on vectors, selected eigenpairs or singular triplets, low-rank approximations, and 1-norm estimates.
The API types (`ExponentialAction`, `FunctionAction`, `PartialSpectrumSolver`, `LobpcgSolver`, `PartialSvdSolver`, `RandomizedLowRank`, and `OneNormEstimator`) are method objects.
Method objects hold only settings such as tolerances and operator-application limits, unlike plans (`…Plan`), which hold prepared numerical data.
Operator dimensions and column counts are read from the operator and inputs on each call, allowing one value to serve problems of different sizes.
Settings are also validated at call time; invalid settings return errors such as `InvalidInput` while obtaining workspace requirements.

Each family consists of a method object, output (`…Buffer` or caller-owned columns), report (`…Report`), workspace (`…Workspace`), and requirements (`…Requirements`).
Obtain requirements by passing the operator and call dimensions, such as column or constraint counts, to the method object's `workspace_requirements`; check them with workspace `check` and `try_reserve`.
Calling forms are defined in [Calling forms](oxref:linalg-api-forms).
Owning-result APIs (`apply`, `solve`, `svd`, `interpolative`, and `estimate`) allocate output and workspace and execute sequentially with `ExecutionContext::sequential_native()`.
Caller-provided-output APIs (`apply_into`, `solve_into`, `svd_into`, and `interpolative_into`) and scoped `estimate_scoped` use caller-owned workspace and contexts; preallocated workspace avoids allocation for calls of the same size.

Stopping at application or iteration limits, cancellation, or deadlines returns an unsuccessful termination reason `SpectralTermination` and accepted partial results in `Ok`.
`Err` leaves output unchanged.
Report error indicators are estimates based on truncation or residuals, not forward-error bounds.

## Summary

To compute $e^{tA}b$ without forming a matrix, supply an upper bound on $\lVert A - \mu I \rVert_1$ to `ExponentialAction`; use `FunctionAction` when no upper bound is known or for functions other than exponentials.
For selected eigenpairs, choose `PartialSpectrumSolver` for general operators or `LobpcgSolver` for extremal eigenvalues of Hermitian pencils with preconditioning; use shift-invert `SpectrumOperator::ShiftInvert` for interior eigenvalues.
Use `PartialSvdSolver` for singular values and `RandomizedLowRank` for low-rank approximations whose randomness you manage, checking the approximation through residuals of test vectors excluded from construction.
Every method object holds only settings, allowing one value to serve differently sized operators; workspace requirements come from call dimensions.
Results stopped by limits or cancellation return `Ok`, so check whether `SpectralTermination` is `Converged`.
