This table summarizes storage formats for matrices not stored densely, their factorizations and solves, structured-matrix generators, operators combining matrices, and general operator operations.
Solves from banded, tridiagonal, and triangular factorizations and plans take `StructuredOperation` (`Normal`, `Transpose`, `Adjoint`) as their first argument to select system $A$, $A^{\mathsf T}$, or $A^{\mathsf H}$.
Standard `solve(op, rhs)` returns the solution and makes rejection an error; with-options `solve_with_options(op, rhs, &DirectSolveOptions)` returns `DirectSolveResult` in `Ok` even when unaccepted.
Standard factorization `factor(view)` executes sequentially with default settings; use with-options `factor_with_options(view, &options)` to select accuracy or limits.
The calling forms are defined in [Calling forms](oxref:linalg-api-forms).
Workspace uses shared `LinalgWorkspace`; query its size with one `StructuredWorkspaceRequest`.
Owned banded, Hermitian banded, packed, and tridiagonal types do not implement operators; views borrowed through `view()` implement product and operator contracts.

## Summary

Store tridiagonal, banded, packed, and triangular matrices in dedicated types, passing views as operators or solving through the corresponding factorizations or plans (tridiagonal factorization costs $O(n)$; band Cholesky with bandwidth $k$ costs $O(nk^2)$).
Select $A$, $A^{\mathsf T}$, or $A^{\mathsf H}$ through `StructuredOperation` when solving; use standard forms for solutions alone and with-options forms for acceptance reports.
Solve Toeplitz, Hankel, and circulant systems once with `solve_structured` or use `StructuredSolvePlan` for many right-hand sides, selecting backward-error tolerances and dense-LU fallback.
Solve Kronecker-product or block-diagonal systems through `solve_into` with factor inverse operators, checking acceptance through the termination reason in `CompositeSolveReport`.
Use `operator_norm` to compute operator norms exactly, or `MatrixView::norm` for dense matrices.
