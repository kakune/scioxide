An iterative solve of a large system can stop before convergence.
A user may interrupt it, iteration or operator-evaluation limits may be reached, or violated assumptions may prevent the algorithm from continuing.
The caller then needs to know what the output contains and how much confidence to place in it.
This example stops conjugate gradients (CG) for a one-dimensional Poisson equation in several ways and reads the report, output, and workspace records from the API `solve_into` accepting caller-provided output.
In this call form the caller supplies the output vector, workspace, and execution context ([Workspaces, execution contexts, and attempt records](oxref:linalg-execution-forms)).

---

## Verified solutions and committing output

CG updates the residual $r_k$ by recurrence, but rounding makes this value drift from the true residual $b - Ax_k$.
`CgSolver` checks at initialization, every 50 iterations, on a convergence candidate, when an update leaves the iterate unchanged, and at the iteration limit, recomputing the true residual by an operator evaluation.
Here an iterate whose true residual has been checked at a checkpoint is called a verified solution.
The solver retains the verified solution with the smallest true residual, choosing the later one in a tie.
Replacement every 50 iterations restores the recurrence residual to its true value while preserving search directions and conjugacy.
When a checkpoint's true residual does not improve the previous minimum, the solver checks whether that minimum has reached the rounding-error residual floor; if so, it stops with `Stagnation`.
This test uses one product of $A$ with a sign-modified iterate, counted as an operator evaluation ([Rounding-error residual floor](../preconditioned-cg/#residual-floor-from-rounding-errors) gives the formula).

`CgSolver::solve_into` uses the current output-vector $x$ as the initial value and writes a result to $x$ only when returning `Ok`.
On convergence it writes the solution whose convergence was verified; on stopping, it writes the verified solution with smallest true residual, including the initial value.
Returning `Err` leaves $x$ unchanged.
`Ok` does not mean convergence alone.
It also returns report and solution in `Ok` on iteration limits (`IterationLimit`), evaluation limits (`EvaluationLimit`), stagnation (`Stagnation`), cancellation or deadlines (`ExecutionStopped(reason)`), or violated assumptions such as curvature $p^{\mathsf T}Ap \le 0$ (`Breakdown(NonPositiveCurvature)`).
Determine success from the report's `termination()`; `is_success()` is true for `Converged` and `LeastSquaresConverged`.
The standard-form `solve` uses `IterativeSolveResult::into_converged_solution` to convert `ExecutionStopped(reason)` to an `ExecutionStopped` error and other non-convergence to `ConvergenceFailure` errors.

`Err` covers shape mismatch (`DimensionMismatch`) or non-finite input (`NonFinite`) rejected before computation, non-finite values or errors from operators or preconditioners, and workspace allocation failures (`ResourceLimit`, `AllocationFailure`).
If even the first residual evaluation is rejected by the count limit, no usable iterate exists and the result is `ConvergenceFailure`.
The owned-value API `solve_with_options` allocates output and workspace and follows the same procedure, returning the solution in `IterativeSolveResult`.

## Attempt records and accepted state

The workspace `IterativeWorkspace` leaves two records on each call.

- `last_attempt()` returns an `AttemptRecord` recording the last call.
  `outcome()` classifies it as `Succeeded` (success), `Stopped` (stopped with a usable solution), `Failed` (error after computation began), or `PreflightRejected` (rejected by checks before computation).
  `counts()` counts iterations and operator or preconditioner evaluations; these are 0 for `PreflightRejected`.
- `last_accepted()` returns accepted state `IterativeAccepted` for successful or stopped attempts and becomes `None` after `Failed` or `PreflightRejected`.
  `solution()` returns the committed solution, `history()` its residual history, and `progress()` its termination reason, iteration count, true residual, and trust class.

The trust class `PartialResultTrust` describes how far accepted state has been checked, in increasing order: `DiagnosticOnly` (diagnostic state without a residual claim), `Admissible` (meets only the algorithm's own acceptance conditions), `ResidualChecked` (an independent computation confirms the residual meets the configured tolerance), and `CertificateVerified` (an independently verified certificate).
`Display` displays lowercase names such as `diagnostic-only` and `residual-checked`.
CG assigns `ResidualChecked` only to converged solutions whose true residual meets tolerance.
A non-converged stop gives `Admissible` even when returning a verified solution with checked true residual; stopping before the first true residual is computed gives `DiagnosticOnly`.

## Setting limits and cancellation

Set the iteration limit at solver construction with the `Budget` in `CgSolver::new(tolerance, max_iterations)`.
If `with_execution_options` composes `LinalgExecutionOptions::with_iteration_budget` or `LinalgExecutionContext::with_iteration_budget` adds a context limit, the smaller limit applies.

Set the operator and preconditioner evaluation limit by configuring `BudgetKind::Evaluation` in scioxide-core's `SolveBudgets` and passing the caller-owned `SolveContext` created by `SolveState::begin_solve` to `solve_into` ([Solve lifecycle and computational accounting](../../../scioxide-core/algorithms/solve-lifecycle-and-accounting/)).
CG then runs as a nested solve in that context; evaluations count against the caller's limit, while iterations count only against CG's own limit.
The `SolveIdentity` accepted by `begin_solve` is matched when resuming intermediate state; any value is sufficient here.

Request cancellation through the `CancellationToken` passed to `ExecutionContext::with_cancellation`.
The solver checks at solve entry and the start of each iteration, detecting a request made inside an operator evaluation at the next iteration's start.
Browser cells run on one thread without a clock.
This cell can therefore demonstrate only cancellation before the call or requested on the same thread inside an operator evaluation.
It cannot demonstrate cancellation from another thread or deadline stops.
Set a deadline with `with_time_limit` on a context with a clock (`with_clock`); without a clock, it gives a `CapabilityUnavailable` error ([Cancellation, clocks, and deadlines](../../../scioxide-core/algorithms/cancellation-clocks-and-deadlines/)).
A deadline stop has termination reason `ExecutionStopped(DeadlineReached)` and follows the same output and record rules as cancellation.

## Results for each stopping condition

The following block defines helpers shared by two cells.
`Probe` implements scioxide-core's `LinearOperator`, applying $A = \operatorname{tridiag}(-1, 2, -1)$ ($-A$ for `sign = -1`) without forming a matrix.
It counts applications and either requests cancellation or inserts NaN during a specified application.
`poisson` returns the right-hand side $b_i = h^2 x_i$ from second-difference discretization of $-u'' = x$ ($u(0) = u(1) = 0$) at $N$ interior points, and the exact discrete solution $u_i = x_i(1 - x_i^2)/6$ (second differences are exact for cubics).
`relative_residual` recomputes $\lVert b - Ax \rVert_2/\lVert b \rVert_2$ for verification without counting evaluations; `termination_name` returns termination variant names.

```rust
//| id: linalg-context-contracts-model
//| kind: definitions
//| title: "One-dimensional Poisson operator counting evaluations"
//| crates: [scioxide-core, scioxide-linalg]
use core::cell::Cell;
use scioxide_core::{CancellationToken, Dimensions, SciOxideError, LinearOperator};
use scioxide_linalg::LinearSolveTermination;

/// Apply A = tridiag(−1, 2, −1) without a matrix (−A for sign = −1).
/// Count applications and request cancellation or return NaN during a specified application.
pub(crate) struct Probe<'a> {
    pub(crate) n: usize,
    pub(crate) sign: f64,
    pub(crate) calls: Cell<usize>,
    pub(crate) cancel_at: Option<(usize, &'a CancellationToken)>,
    pub(crate) nan_at: Option<usize>,
}

impl Probe<'_> {
    pub(crate) fn new(n: usize) -> Self {
        Probe {
            n,
            sign: 1.0,
            calls: Cell::new(0),
            cancel_at: None,
            nan_at: None,
        }
    }
}

impl LinearOperator<f64> for Probe<'_> {
    fn rows(&self) -> usize {
        self.n
    }

    fn cols(&self) -> usize {
        self.n
    }

    fn apply_workspace_len(&self) -> Result<usize, SciOxideError> {
        Ok(0)
    }

    fn apply_into(&self, x: &[f64], y: &mut [f64], _: &mut [f64]) -> Result<(), SciOxideError> {
        if x.len() != self.n || y.len() != self.n {
            return Err(SciOxideError::dimension_mismatch(
                Dimensions::two(self.n, self.n),
                Dimensions::two(x.len(), y.len()),
            ));
        }
        let call = self.calls.get() + 1;
        self.calls.set(call);
        for i in 0..self.n {
            let left = if i > 0 { x[i - 1] } else { 0.0 };
            let right = if i + 1 < self.n { x[i + 1] } else { 0.0 };
            y[i] = self.sign * (2.0 * x[i] - left - right);
        }
        if let Some((at, token)) = self.cancel_at
            && at == call
        {
            token.cancel();
        }
        if self.nan_at == Some(call) {
            y[0] = f64::NAN;
        }
        Ok(())
    }
}

/// Right-hand side b_i = h² x_i for −u'' = x, u(0) = u(1) = 0 discretized at n interior points, and
/// exact discrete solution u_i = x_i(1 − x_i²)/6 (second differences are exact for cubics).
pub(crate) fn poisson(n: usize) -> (Vec<f64>, Vec<f64>) {
    let h = 1.0 / (n + 1) as f64;
    let x = |i: usize| (i + 1) as f64 * h;
    let b = (0..n).map(|i| h * h * x(i)).collect();
    let exact = (0..n).map(|i| x(i) * (1.0 - x(i) * x(i)) / 6.0).collect();
    (b, exact)
}

/// Termination variant name.
pub(crate) fn termination_name(t: LinearSolveTermination) -> String {
    match t {
        LinearSolveTermination::Converged => "Converged".to_string(),
        LinearSolveTermination::LeastSquaresConverged => "LeastSquaresConverged".to_string(),
        LinearSolveTermination::ConditionLimit => "ConditionLimit".to_string(),
        LinearSolveTermination::IterationLimit => "IterationLimit".to_string(),
        LinearSolveTermination::EvaluationLimit => "EvaluationLimit".to_string(),
        LinearSolveTermination::Stagnation => "Stagnation".to_string(),
        LinearSolveTermination::Breakdown(cause) => format!("Breakdown({cause:?})"),
        LinearSolveTermination::ExecutionStopped(reason) => format!("ExecutionStopped({reason:?})"),
    }
}

/// Residual ‖b − sign·A x‖₂ / ‖b‖₂ (verification without counting operator evaluations).
pub(crate) fn relative_residual(sign: f64, b: &[f64], x: &[f64]) -> f64 {
    let n = x.len();
    let mut squared = 0.0;
    for i in 0..n {
        let left = if i > 0 { x[i - 1] } else { 0.0 };
        let right = if i + 1 < n { x[i + 1] } else { 0.0 };
        let r = b[i] - sign * (2.0 * x[i] - left - right);
        squared += r * r;
    }
    (squared / b.iter().map(|v| v * v).sum::<f64>()).sqrt()
}
```

The 103 evaluations comprise one initial residual, 100 iterations, and two checkpoint evaluations at iterations 50 and 100.
At iteration 50 the true residual exceeds the initial residual, triggering the residual-floor check.
The minimum-residual iterate is still the initial $x = 0$, however, so the floor formula's product $A(s \circ x)$ is zero and no operator evaluation is needed.
The attempt outcome is `Succeeded` and trust class `residual-checked`, with relative error only $3.5 \times 10^{-15}$.
Without rounding, CG finishes within $N = 100$ iterations; here it converges in exactly that many.

At the default iteration limit 70, it returns `Ok` and `IterationLimit`, with attempt outcome `Stopped` and trust class `admissible`.
There are 73 evaluations; iteration 70 at the limit is also a checkpoint.
Its true residual $0.55\lVert b \rVert$ is smaller than initial residual $\lVert b \rVert$, so output is the iteration-70 solution (relative error $2.9 \times 10^{-2}$).
This problem's residual grows to 5.7 times $\lVert b \rVert$ at iteration 1 and stays above $\lVert b \rVert$ through iteration 59 (next section).
A limit at most 59 therefore leaves every checkpoint residual above the initial residual and returns the initial value (relative residual 1), as in case “59 iterations, cancel at application 102.”

With evaluation limit 90, an operator evaluation is refused at iteration 89, giving `EvaluationLimit` and leaving initial output unchanged.
An evaluation limit prevents computation of the current true residual; among earlier checkpoints (initialization and iteration 50), the initial value has the smaller residual and is returned.
In case “100 iterations, 102 evaluations,” the iteration-limited solve converges at iteration 100 with `Converged`.
The evaluation-limited solve reaches a convergence candidate at iteration 100 but lacks the confirming evaluation and again returns the initial value.
In both evaluation-limited cases, the returned solution is not the iterate at the report's iteration count.

Default cancellation before the call returns `Ok` and `ExecutionStopped(Cancelled)`.
No operator evaluation occurs, so trust is `diagnostic-only`, reported residual is absent, and output remains at its initial value.
In case “Cancel at application 75,” cancellation requested inside the operator evaluation at iteration 73 is detected at the start of iteration 74.
Trust is `admissible`; the initial value still has the smallest checkpoint residual and is again returned.
Application 102 is the product at iteration 100.
Cancellation at application 102 or later therefore allows iteration 100 to finish and its true residual to establish convergence; there is no iteration 101 to check cancellation, giving the same `Converged` as the unlimited run (case “59 iterations, cancel at application 102”).
At application 101, the request occurs during iteration 99, stopping at the start of iteration 100 and returning the initial value.

## Quality of early-terminated solutions

The CG iterate at step $k$ minimizes the error's $A$-norm $\lVert x - x^\ast \rVert_A$ in the Krylov subspace $x_0 + \mathcal K_k(A, r_0)$; in exact arithmetic, this $A$-norm error decreases monotonically with iterations.
Residual $\lVert b - Ax_k \rVert_2$ need not be monotonic, however, and the $A$-norm error cannot be measured without the exact solution.
Only true residuals are comparable at termination, so the committed solution is selected by residual and may discard a newer iterate with smaller $A$-norm error.

let n = 100_usize;

let operator = Probe::new(n);

## Summary

Iterative `solve_into` and `solve_with_options` return `Ok` even at limits, cancellation, or curvature breakdown, so assess success through report `termination().is_success()` rather than `Ok`.
Stopped solutions retain trust class `admissible`; before using them, check whether the reported true residual improves the initial residual, and extend iteration or add preconditioning if output remains initial.
On `Err`, output is unchanged and its original value remains usable; distinguish causes by the `last_attempt()` outcome (`Failed` or `PreflightRejected`) and evaluation count.
Set evaluation limits through `SolveBudgets` of the caller's `SolveContext` to stop before an excessive application; request cancellation through the context's `CancellationToken` to stop at the next iteration's start.
Committed solutions are selected by residual and can discard later iterates with smaller $A$-norm error, so compare with known solutions or other estimates when error magnitude matters.
