`scioxide-linalg` solves linear systems, least-squares problems, eigenvalue problems, matrix functions, and matrix equations.
It provides dense-matrix storage and products; LU, Cholesky, LDL, QR, and singular value decompositions; solvers for structured matrices such as tridiagonal and Toeplitz matrices; Krylov subspace methods and stationary iterations; matrix exponentials and logarithms; and Sylvester, Lyapunov, and Riccati equations under shared conventions.
It supports real and complex `f32` and `f64` scalars.
Tolerances, limits (`Budget`), execution contexts, and operator traits use [scioxide-core](../scioxide-core/) types; [scioxide-sparse](../scioxide-sparse/) provides sparse-matrix storage, sparse direct methods, and preconditioners.

## First computation: nodal equations for a resistive circuit

Connect three nodes with resistors, ground each node through a 1 kΩ resistor, and inject a current of $I = 1$ mA into node 1.
Let the resistance between nodes 1 and 2 be $R$ and that between nodes 2 and 3 be 1 kΩ, with conductances $g_a = 1/R$ and $g_0 = g_b = 10^{-3}$ S.
By Kirchhoff's current law, the node voltages $v$ [V] satisfy the following equation $Av = b$.

$$
\begin{bmatrix} g_0 + g_a & -g_a & 0 \\ -g_a & g_a + g_0 + g_b & -g_b \\ 0 & -g_b & g_b + g_0 \end{bmatrix}
\begin{bmatrix} v_1 \\ v_2 \\ v_3 \end{bmatrix}
=
\begin{bmatrix} 10^{-3} \\ 0 \\ 0 \end{bmatrix}
$$

Solving by series and parallel reduction gives an equivalent conductance to ground beyond node 2 of $G_2 = g_0 + g_bg_0/(g_b + g_0)$, yielding $v_1 = I/(g_0 + g_aG_2/(g_a + G_2))$, $v_2 = v_1\,g_a/(g_a + G_2)$, and $v_3 = v_2\,g_b/(g_b + g_0)$.
Because these formulas contain no subtraction, they give reference values accurate to rounding error even for extreme $R$.

The condition number $\kappa_1(A) = \lVert A \rVert_1 \lVert A^{-1} \rVert_1$ is a property of the problem indicating how much small relative input changes can amplify into relative solution changes ($\lVert \cdot \rVert_1$ is the maximum absolute column sum).
Every column sum of this $A$ equals $g_0$ ($\mathbf 1^{\mathsf T} A = g_0 \mathbf 1^{\mathsf T}$), so $\mathbf 1^{\mathsf T} A^{-1} = \mathbf 1^{\mathsf T}/g_0$.
Because $A$ is strictly diagonally dominant with nonpositive off-diagonal entries (an M-matrix), $A^{-1}$ has nonnegative entries and $\lVert A^{-1} \rVert_1 = 1/g_0$.
When $g_b = g_0$, $\lVert A \rVert_1 = 2g_a + 3g_0$, giving $\kappa_1(A) = 3 + 2g_a/g_0$.
As $R$ decreases, nodes 1 and 2 approach a short circuit and the condition number grows in proportion to $g_a/g_0$.

The following block defines the circuit model shared by the two cells on this page.
`circuit` constructs the coefficient matrix $A$ and right-hand side $b$ from $R = 10^t$ Ω; `reference` returns reference values from series and parallel reduction, and `condition_one` returns the closed-form $\kappa_1(A)$.
The reference values and condition number are checks computed with `f64` arithmetic.

```rust
//| id: linalg-overview-circuit
//| kind: definitions
//| title: "Resistive-circuit nodal equations and reference values"
//| crates: [scioxide-linalg]
use scioxide_linalg::{Matrix, Vector};

/// Grounding and node 2–3 conductances g₀ = g_b [S], and injected current I [A].
pub(crate) const G0: f64 = 1e-3;
pub(crate) const GB: f64 = 1e-3;
pub(crate) const CURRENT: f64 = 1e-3;

/// Nodal equations A v = b for R = 10^t Ω (g_a = 1/R).
pub(crate) fn circuit(t: f64) -> Result<(Matrix<f64>, Vector<f64>), String> {
    let ga = 1.0 / 10.0_f64.powf(t);
    let a = Matrix::from_rows(&[
        [G0 + ga, -ga, 0.0],
        [-ga, ga + G0 + GB, -GB],
        [0.0, -GB, GB + G0],
    ])
    .map_err(|e| e.to_string())?;
    Ok((a, Vector::from_vec(vec![CURRENT, 0.0, 0.0])))
}

/// Reference values (v₁, v₂, v₃) from series and parallel reduction. No subtraction.
pub(crate) fn reference(t: f64) -> [f64; 3] {
    let ga = 1.0 / 10.0_f64.powf(t);
    let g2 = G0 + GB * G0 / (GB + G0);
    let v1 = CURRENT / (G0 + ga * g2 / (ga + g2));
    let v2 = v1 * ga / (ga + g2);
    [v1, v2, v2 * GB / (GB + G0)]
}

/// Closed-form condition number κ₁(A) = 3 + 2 g_a / g₀.
pub(crate) fn condition_one(t: f64) -> f64 {
    3.0 + 2.0 / (10.0_f64.powf(t) * G0)
}
```

The following cell solves these equations with the one-call function `solve`.
`solve(&a, &b)` performs LU factorization with partial pivoting and forward and backward substitution together, returning only the solution vector when no pivot is exactly zero.
The input is the exponent $t$ in $R = 10^t$ Ω ($-9 \le t \le 6$).
The first table shows node voltages, reference values, and relative differences.
The second table shows the closed-form $\kappa_1(A)$, its product $\kappa_1(A)\,u$ with unit roundoff $u = 2^{-53}$, and the maximum relative difference.
The tests compare $v_1$ and $\kappa_1(A)$ against reference values and check that the relative difference does not exceed $\kappa_1(A)\,u$.

```rust
//| id: linalg-overview-first-solve
//| ref: linalg-overview-first-solve
//| title: "Solve resistive-circuit nodal equations with a one-call function"
//| run: reactive
//| uses: [linalg-overview-circuit]
//| crates: [scioxide-linalg]
//| inputs:
//|   resistance_exponent: {"type":"range","label":"t in the node 1–2 resistance R = 10^t Ω","description":"Smaller values approach a short circuit and increase the condition number.","min":-9,"max":6,"step":1,"value":0}
//| cases:
//|   - {"id":"near-short","label":"R = 10⁻⁹ Ω","description":"The condition number becomes 2 × 10¹², and the relative difference grows to order 10⁻⁵.","inputs":{"resistance_exponent":-9}}
//|   - {"id":"open-branch","label":"R = 10⁶ Ω","description":"Node 1 becomes nearly disconnected, and the condition number is approximately 3.","inputs":{"resistance_exponent":6}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"voltages","path":"/rows/0/1","approx":{"value":0.4003597841295223,"rtol":1e-12}}
//|       - {"artifact":"conditioning","path":"/rows/0/0","approx":{"value":2003,"rtol":1e-14}}
//|       - {"artifact":"conditioning","path":"/rows/0/2","range":{"max":2.2e-13}}
//|   - case: near-short
//|     expect:
//|       - {"artifact":"voltages","path":"/rows/0/1","approx":{"value":0.40000000000036,"rtol":1e-3}}
//|       - {"artifact":"conditioning","path":"/rows/0/0","approx":{"value":2.000000000003e12,"rtol":1e-12}}
//|       - {"artifact":"conditioning","path":"/rows/0/2","range":{"max":2.2e-4}}
//|   - case: open-branch
//|     expect:
//|       - {"artifact":"voltages","path":"/rows/0/1","approx":{"value":0.9990016638935109,"rtol":1e-14}}
//|       - {"artifact":"conditioning","path":"/rows/0/0","approx":{"value":3.002,"rtol":1e-12}}
use scioxide_linalg::solve;

let t = resistance_exponent;
let (a, b) = circuit(t)?;
// One-call function: perform factorization and solving together, returning only the solution.
let v = solve(&a, &b).map_err(|e| e.to_string())?;
let exact = reference(t);
let names = ["v₁", "v₂", "v₃"];
let rows: Vec<(&str, f64, f64, f64)> = (0..3)
    .map(|i| {
        let x = v.as_slice()[i];
        (names[i], x, exact[i], (x - exact[i]).abs() / exact[i])
    })
    .collect();
let worst = rows.iter().fold(0.0_f64, |m, row| m.max(row.3));
let fixed12 = serde_json::json!({ "significantDigits": 12 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let sci4 = serde_json::json!({ "notation": "scientific", "significantDigits": 4 });
let columns = serde_json::json!([
    { "key": "0", "label": "Node voltage" },
    { "key": "1", "label": "solve solution [V]", "type": "number", "format": fixed12 },
    { "key": "2", "label": "Reference [V]", "type": "number", "format": fixed12 },
    { "key": "3", "label": "Relative difference [-]", "type": "number", "format": sci2 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "voltages" })
);

// Use the closed-form κ₁(A) times unit roundoff u = 2⁻⁵³ as an indicator of relative difference.
let kappa = condition_one(t);
let unit_roundoff = f64::EPSILON / 2.0;
let columns = serde_json::json!([
    { "key": "0", "label": "Condition number κ₁(A) [-]", "type": "number", "format": sci4 },
    { "key": "1", "label": "κ₁(A) u [-]", "type": "number", "format": sci2 },
    { "key": "2", "label": "Maximum relative difference [-]", "type": "number", "format": sci2 }
]);
emit_table_with_columns!(
    columns,
    vec![(kappa, kappa * unit_roundoff, worst)],
    metadata = serde_json::json!({ "id": "conditioning" })
);
```

At the default $R = 1$ Ω, $\kappa_1(A) = 2003$, and the node voltages agree with the reference to a relative difference of $1.5 \times 10^{-13}$.
Each tenfold reduction of $R$ below 1 Ω increases $\kappa_1(A)$ tenfold, and the relative difference grows roughly proportionally ($2.5 \times 10^{-11}$ at $R = 10^{-3}$ Ω, $5.7 \times 10^{-8}$ at $10^{-6}$ Ω, and $5.6 \times 10^{-5}$ at $10^{-9}$ Ω).
At $R = 10^{6}$ Ω, node 1 is nearly disconnected, $v_1 \approx 0.999$ V and $\kappa_1(A) = 3.002$, and the relative difference is at most $2 \times 10^{-16}$.

The relative difference grows because rounding of relative size $u$ introduced when storing matrix entries as floating-point numbers is amplified in the solution by the condition number.
Indeed, computing the exact solution of the stored matrix at $R = 10^{-9}$ Ω using rational arithmetic gives a relative difference of $4 \times 10^{-13}$ from the cell's solution; most of the difference $5.6 \times 10^{-5}$ from the reference comes from storage rounding.
Thus $\kappa_1(A)\,u$ indicates the relative difference, and the cell's relative differences remain below it for every $R$ in $t = -9, \ldots, 6$.
The backward error in the next section measures the error added by LU factorization itself.

## Interpreting results

One-call functions such as `solve` return only a solution, without information on the computation's reliability.
To retain and reuse a factorization, use ordinary forms such as `LuDecomposition::factor(&a)` and `lu.solve(&b)` that take only problem data.
We call `lu.solve_with_options(&b, &options)`, which takes settings as its last argument and returns a report with the solution, the detailed form.
[Workspaces, execution contexts, and attempt records](oxref:linalg-execution-forms) defines call forms, including borrowed and scoped forms using the caller's workspace and context, plans, and method values.

In this chapter, determining that a computed solution may be exposed as a result is called acceptance.
Factorization rejects only structural breakdowns (such as an exactly zero pivot) as errors; acceptance of the resulting solution depends on the rank policy and minimum reciprocal condition number passed when solving.
The reciprocal condition number is $\mathrm{rcond}_1 = 1/\kappa_1(A)$; values closer to 0 indicate worse conditioning.

The following cell factors the same equations with `LuDecomposition::factor`, passes acceptance criteria `DirectSolveOptions` to the detailed `solve_with_options`, and receives a solution and report.
The criteria include rank policy `RankPolicy::DimensionScaledEpsilon`, backward-error computation (`with_residual(Estimation::Estimate)`), and a minimum reciprocal condition number selected by the input.
This rank policy treats pivots no larger in absolute value than $3\varepsilon$ times the largest absolute pivot as zero ($3$ is the order and $\varepsilon = 2^{-52}$ is machine epsilon).
The backward error is measured against the original matrix by

$$
\eta = \frac{\lVert b - A\hat x \rVert_\infty}{\lVert A \rVert_\infty \lVert \hat x \rVert_\infty + \lVert b \rVert_\infty}
$$

and indicates how nearby a problem has the computed solution $\hat x$ as its exact solution.
When a minimum reciprocal condition number is selected, solving estimates $\mathrm{rcond}_1$ with the factorization's `condition_estimate`; if the estimate is below the minimum, it returns termination reason `IllConditioned` without exposing a solution.

The inputs are the exponent $t$ in $R = 10^t$ Ω and the minimum reciprocal condition number (none, $10^{-6}$, or $10^{-9}$).
The table shows the termination reason, numerical rank, backward error, $\mathrm{rcond}_1$ computed from the factorization, $v_1$ exposed by the detailed form, and the result of extracting the solution with `into_accepted()`.
When a solution is not accepted, the $v_1$ column shows “Not exposed.”
The final outcome uses the termination reason: `Accepted` indicates satisfaction, and other reasons indicate rejection.
The test compares $\mathrm{rcond}_1$ against the closed-form $1/\kappa_1(A) = 1/(3 + 2g_a/g_0)$.

```rust
//| id: linalg-overview-acceptance
//| ref: linalg-overview-acceptance
//| title: "Pass acceptance criteria to the detailed LU interface and inspect the report"
//| run: reactive
//| uses: [linalg-overview-circuit]
//| crates: [scioxide-linalg]
//| inputs:
//|   resistance_exponent: {"type":"range","label":"t in the node 1–2 resistance R = 10^t Ω","description":"Smaller values approach a short circuit and decrease the reciprocal condition number.","min":-9,"max":6,"step":1,"value":0}
//|   threshold: {"type":"select","label":"Minimum reciprocal condition number","description":"The detailed form rejects a solution if its estimate is below this value.","options":["None","1e-6","1e-9"],"value":"None"}
//| cases:
//|   - {"id":"near-short","label":"R = 10⁻⁹ Ω","description":"Without a minimum, even rcond₁ = 5 × 10⁻¹³ is accepted.","inputs":{"resistance_exponent":-9}}
//|   - {"id":"rcond-threshold","label":"R = 10⁻⁶ Ω, minimum 10⁻⁶","description":"The reciprocal condition number is below the minimum, and the detailed form returns IllConditioned.","inputs":{"resistance_exponent":-6,"threshold":"1e-6"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"report","path":"/rows/0/0","equals":"Accepted"}
//|       - {"artifact":"report","path":"/rows/0/1","equals":3}
//|       - {"artifact":"report","path":"/rows/0/2","range":{"max":1e-16}}
//|       - {"artifact":"report","path":"/rows/0/3","approx":{"value":4.992511233150275e-4,"rtol":1e-12}}
//|       - {"artifact":"report","path":"/rows/0/4","approx":{"value":0.4003597841295223,"rtol":1e-12}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: near-short
//|     expect:
//|       - {"artifact":"report","path":"/rows/0/0","equals":"Accepted"}
//|       - {"artifact":"report","path":"/rows/0/3","approx":{"value":4.9999999999925e-13,"rtol":1e-3}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: rcond-threshold
//|     expect:
//|       - {"artifact":"report","path":"/rows/0/0","equals":"IllConditioned"}
//|       - {"artifact":"report","path":"/rows/0/3","approx":{"value":4.9999999925e-10,"rtol":1e-6}}
//|       - {"artifact":"report","path":"/rows/0/4","equals":null}
//|       - {"artifact":"report","path":"/rows/0/5","equals":"Err(NumericalInstability)"}
//|       - {"path":"/outputs/1/state","equals":"failed"}
use scioxide_linalg::{
    DirectSolveOptions, DirectSolveTermination, Estimation, LuDecomposition, RankPolicy,
    ReciprocalConditionThreshold,
};

let (a, b) = circuit(resistance_exponent)?;
// Retain the factorization, pass acceptance criteria to the detailed form, and receive the solution and report.
let lu = LuDecomposition::factor(&a).map_err(|e| e.to_string())?;
let mut options = DirectSolveOptions::new(RankPolicy::DimensionScaledEpsilon)
    .with_residual(Estimation::Estimate);
if threshold != "None" {
    let limit = threshold.parse::<f64>().map_err(|e| e.to_string())?;
    let limit = ReciprocalConditionThreshold::new(limit).map_err(|e| e.to_string())?;
    options = options.with_minimum_reciprocal_condition(limit);
}
let result = lu
    .solve_with_options(&b, &options)
    .map_err(|e| e.to_string())?;
let report = *result.report();
let accepted_v1 = result.solution().map(|s| s.as_slice()[0]);
// The report includes the estimate only when a minimum is supplied; compute it directly from the factorization for display.
let rcond = lu
    .condition_estimate()
    .map_err(|e| e.to_string())?
    .reciprocal()
    .value();
// into_accepted() converts rejection to an error under the same rules as the ordinary solve form.
let converted = match result.into_accepted() {
    Ok(_) => "Ok".to_string(),
    Err(e) => format!("Err({:?})", e.kind()),
};

// Display termination reasons by their enum variant names.
let termination = report.termination();
let name = match termination {
    DirectSolveTermination::Accepted => "Accepted",
    DirectSolveTermination::RankDeficient => "RankDeficient",
    DirectSolveTermination::IllConditioned => "IllConditioned",
    DirectSolveTermination::ResidualRejected => "ResidualRejected",
    DirectSolveTermination::StabilityRejected => "StabilityRejected",
};
let backward = report.residual().map(|r| r.scaled_norm());
let fixed12 = serde_json::json!({ "significantDigits": 12 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "Termination reason" },
    { "key": "1", "label": "Numerical rank", "type": "integer" },
    { "key": "2", "label": "Backward error η [-]", "type": "number", "format": sci2, "nullText": "None" },
    { "key": "3", "label": "Reciprocal condition number rcond₁ [-]", "type": "number", "format": sci3 },
    { "key": "4", "label": "Detailed-form v₁ [V]", "type": "number", "format": fixed12, "nullText": "Not exposed" },
    { "key": "5", "label": "into_accepted() result" }
]);
let rank = report.rank().rank();
emit_table_with_columns!(
    columns,
    vec![(name, rank, backward, rcond, accepted_v1, converted)],
    metadata = serde_json::json!({ "id": "report" })
);

let outcome = if termination.is_success() {
    Outcome::satisfied("The detailed solve accepted the solution")
} else {
    Outcome::failed("The detailed solve rejected the solution")
        .explanation("Extracting a solution with into_accepted() turns this rejection into an error.")
};
let mut outcome = outcome
    .status(name)
    .diagnostic("Reciprocal condition number rcond₁", rcond, None);
if let Some(eta) = backward {
    outcome = outcome.diagnostic("Backward error η", eta, None);
}
emit_outcome!(outcome);
```

At the default $R = 1$ Ω, the termination reason is `Accepted`, the numerical rank is 3, and the backward error is $\eta = 1.9 \times 10^{-17}$; the detailed form's $v_1$ equals the `solve` solution in the previous cell.
For matrices of order 4 or less, `condition_estimate` computes $\lVert A^{-1} \rVert_1$ from each column of the inverse rather than estimating it.
Therefore $\mathrm{rcond}_1 = 4.99 \times 10^{-4}$ agrees with the closed-form $1/\kappa_1(A) = 1/2003$ to a relative difference of $1.5 \times 10^{-13}$.
As $R$ varies, the backward error stays at most $10^{-16}$, indicating backward-stable factorization and solving.

With a minimum reciprocal condition number of $10^{-6}$, the termination reason becomes `IllConditioned` at $R = 10^{-3}$ Ω and below, where $\mathrm{rcond}_1 = 5.0 \times 10^{-7}$, and the detailed solution and backward error are not exposed.
The `into_accepted()` column shows that attempting to convert this rejection into a solution produces a `NumericalInstability` error.
Setting the minimum to $10^{-9}$ produces the same behavior at $R \le 10^{-6}$ Ω.
For the same $R$, the one-call `solve` has no minimum and returns a solution as in the previous cell.

Combining backward error and the condition number allows forward error to be estimated.
When $\eta$ is the normalized backward error above and $\kappa_\infty(A)\,\eta < 1$, the relative forward error against the exact solution $x$ of the stored $A$ and $b$ is bounded by

$$
\frac{\lVert \hat x - x \rVert_\infty}{\lVert x \rVert_\infty} \le \frac{2\,\kappa_\infty(A)\,\eta}{1 - \kappa_\infty(A)\,\eta}
$$

(Higham, 2002, Theorem 7.2).
Because this matrix is symmetric, $\kappa_\infty(A) = \kappa_1(A)$; at the default $R = 1$ Ω, the right-hand side is $2 \cdot 2003 \cdot 1.9 \times 10^{-17} \approx 7.7 \times 10^{-14}$.
The relative difference $1.5 \times 10^{-13}$ from the previous cell's reference is larger because the bound is relative to the stored $A$ and $b$, and storage rounding adds a separate difference of order $\kappa_1(A)\,u$.
For matrices of order 5 or greater, `condition_estimate` is an estimate; its properties are described in [Separating factorization and acceptance](oxref:linalg-acceptance-contract).

The handling of failure and rejection depends on the call form as follows.

- Invalid input and numerical breakdown return `Err(SciOxideError)`; inspect their classification with `kind()`.
  Shape mismatches produce `DimensionMismatch`, inputs containing NaN or infinity produce `NonFinite`, an exactly zero LU pivot produces `Singular`, and Cholesky factorization of a matrix that is not numerically positive definite produces `DomainError`.
- Direct-method one-call functions and ordinary `solve` return only accepted solutions.
  On rejection, `DirectSolveTermination::require_accepted` converts the termination reason into an error: `RankDeficient` becomes `Singular` and other reasons become `NumericalInstability`.
  The ordinary form's default criteria use only `RankPolicy::Exact`, so an LU solve is not rejected once factorization succeeds.
- Detailed `solve_with_options` returns `DirectSolveResult` in `Ok` even on rejection.
  `solution()` becomes `None`; the termination reason in `report()` explains the rejection, retaining rank and condition-number diagnostics for the rejected candidate and, when residual checking caused rejection, that residual too.
- Borrowed `solve_into` returns only a report and leaves the output unchanged on rejection.
- For iterative methods solving a single right-hand side, such as CG and GMRES, ordinary `solve(a, b)` returns a `ConvergenceFailure` error if it stops without meeting the tolerance.
  Detailed `solve_with_options(a, b, preconditioning, x0)` returns the best iterate whose true residual was checked in `Ok` even at a limit, so determine success from `is_success()` on the report's termination reason `LinearSolveTermination`.

The general distinction between `Err` and an unsuccessful `Ok` is covered in [Error contracts and partial results](../concepts/errors-and-partial-results/); error measures and acceptance conventions are collected in [Mathematics and shared conventions of linear algebra](algorithms/).

## Summary

For a single solve, use the one-call `solve`, which performs factorization and solving together and returns only the solution; to reuse a factorization, use ordinary `LuDecomposition::factor` and `solve`.
Rounding when storing inputs alone can cause relative solution errors of order $\kappa_1(A)\,u$, so inspect the condition number or reciprocal condition number when ill-conditioning is suspected.
Use detailed `solve_with_options` to inspect termination reasons, backward errors, and reciprocal condition numbers, and determine success from the termination reason's `is_success()` rather than from receiving `Ok`.
Even when the backward error is of order $10^{-17}$, the forward-error bound depends on its product with the condition number; combine both to assess accuracy.
For applications with solution-accuracy requirements, specify a minimum reciprocal condition number in `with_minimum_reciprocal_condition` to reject ill-conditioned problems as `IllConditioned`.
