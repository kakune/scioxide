Circuit nodal equations, fast chemical equilibria, and constrained mechanics combine differential equations with algebraic equations containing no time derivatives.
These are differential-algebraic equations (DAEs): initial values cannot be chosen arbitrarily, and ODE solvers cannot be applied directly.
This page explains residual-form DAEs, index-1 conditions, consistent initial values, and the variable-step, variable-order BDF used by `DaeBdf`.
[Linear multistep methods](../multistep-methods/) covers ODE BDF coefficients and order selection; [Jacobians and linear stage equations](../jacobians-and-linear-stages/) covers implicit-stage Newton iteration and linear-solver selection.

## Residual form and variable partitioning

A DAE in `scioxide-ode` consists of $n$ equations in time $t$, state $y \in \mathbb K^n$, and time derivative $\dot y$:

$$
F(t, y, \dot y) = 0, \qquad F(t, y, \dot y) \in \mathbb K^n
$$


The field $\mathbb K$ is real or complex as represented by state scalar type `T`; time is real.
The trait `DaeSystem` writes residual $F$ through `residual` and returns equation count through `dimension`.
Use `DaeFn::new(dimension, residual)` to supply only a residual closure.

The type `DaePartition::new(variables, equations)` marks variables and equations as differential or algebraic with sequences of `bool`.
A variable $y_i$ whose $\dot y_i$ appears in $F$ is differential $x$; others are algebraic $z$.
Likewise, equations partition into differential equations containing differential-variable derivatives and algebraic equations containing no derivatives.
Both sequences must have equal length and equal counts of `true` (differential entries), but their orderings may differ.
Mismatched lengths, empty sequences, or unequal differential counts give `InvalidInput`.

For complex states, $F$ must be holomorphic in $y$ and $\dot y$.
Rewrite nonholomorphic expressions (including conjugates or absolute values) using separate real and imaginary coordinates.

The system $M\dot y = f(t, y)$ with singular mass matrix $M$ can be written in residual form as $F = M\dot y - f$.
The solver `DaeBdf` never forms the inverse of $M$, so it handles index-1 systems with singular $M$.
Mark equations corresponding to zero rows of $M$ as algebraic in `DaePartition`.
[Implicit Runge–Kutta methods and mass matrices](../implicit-runge-kutta-and-mass-matrices/) covers supplying mass matrices through `OdeSystem` for implicit Runge–Kutta.

## Index-1 conditions

In partitioned variables, the DAE is

$$
\begin{aligned}
f(t, x, z, \dot x) &= 0 && (\text{differential equations}), \\
g(t, x, z) &= 0 && (\text{algebraic equations})
\end{aligned}
$$


The solver `DaeSystem` requires two conditions.
Structurally, differential equations contain only differential-variable derivatives, while algebraic equations contain no derivatives.
The index-1 condition requires the consistency Jacobian

$$
J_{\mathrm c} = \begin{bmatrix} f_{\dot x} & f_z \\ 0 & g_z \end{bmatrix}
$$

to be nonsingular.
Columns of $J_{\mathrm c}$ use columns of $F_{\dot y}$ for differential variables and $F_y$ for algebraic variables.
The structural condition makes the lower-left block zero, so $J_{\mathrm c}$ is nonsingular exactly when both $f_{\dot x}$ and $g_z$ are nonsingular.

With nonsingular $g_z$, the implicit function theorem locally solves algebraic equations as $z = \zeta(t, x)$.
Differentiating algebraic equations once in time determines $\dot z$ from $g_t + g_x \dot x + g_z \dot z = 0$, turning the full system into an ODE.
The number of differentiations needed is the (differentiation) index; an index-1 DAE becomes an ODE after one differentiation.
Systems with singular $g_z$, such as a constrained pendulum, have index at least 2; applying BDF directly can reduce accuracy or prevent Newton convergence.
The solver `DaeBdf` does not determine or reduce index, or discover variable partitions automatically.
For higher-index systems, differentiate constraints to rewrite as index 1, or use RATTLE from [Geometric integration](../geometric-integrators/) for holonomically constrained dynamics.

Each `DaeBdf` call factors $J_{\mathrm c}$ once at the initial values, identifying initial singularity before the first step.
Approaching singular $g_z$ during integration (at index changes or singular points) appears as Newton failure and shrinking steps.

## Consistent initial values

Unlike ODEs, DAE initial values $(y_0, \dot y_0)$ cannot be arbitrary.
Algebraic equations $g(t_0, x_0, z_0) = 0$ determine $z_0$, and differential equations $f = 0$ determine $\dot x_0$.
Initial pairs whose differential and algebraic residual blocks $F(t_0, y_0, \dot y_0)$ each satisfy tolerance are called consistent.
Algebraic-variable derivatives $\dot z_0$ do not appear in $F$ and are excluded from consistency checks.

The policy `DaeInitialization` selects initial-pair treatment through `DaeNumericalOptions::with_initialization`.

- `Check` (default) checks residuals without changing the supplied pair.
  Inconsistency gives a `InvalidInput` error (reason `Inconsistent`).
- `Project` fixes differential state $x_0$ and solves for $z_0$ and $\dot x_0$ using Newton with $J_{\mathrm c}$.
  Nonconvergence gives a `ConvergenceFailure` error carrying the Newton stopping reason and iteration count.

Since `Project` leaves $x_0$ unchanged, the caller must check that the projected pair represents the intended physical initial values.
The projected $\dot z_0$ remains as supplied and need not be tangent to the continuous solution.
The `DaeConsistencyReport` returned by `DaeReport::consistency` holds supplied-pair differential and algebraic residuals (`initial_differential_residual`, `initial_algebraic_residual`), accepted-pair residuals (`differential_residual`, `algebraic_residual`), algebraic-state changes (`state_correction`), and differential-derivative changes (`derivative_correction`), all in infinity norm.

If terminal `end` of `DaeProblem::new(system, end)` equals state time, `advance` only validates or projects initial values and returns `ReachedEnd`.
Receive the consistent pair in `DaeState` and inspect it before integration.

## Variable-step, variable-order residual BDF

Order-$q$ BDF approximates $\dot y_{n+1}$ by the derivative at $t_{n+1}$ of a polynomial interpolating states at accepted times $t_{n+1}, t_n, \dots, t_{n+1-q}$.

$$
\dot y_{n+1} \approx \frac{1}{h_n}\sum_{j=0}^{q} \alpha_j\, y_{n+1-j}, \qquad h_n = t_{n+1} - t_n
$$

Coefficients $\alpha_j$ are recomputed from actual times, preserving order under step changes.
Substituting into the residual gives

$$
F\!\left(t_{n+1},\; y_{n+1},\; \frac{1}{h_n}\sum_{j=0}^{q} \alpha_j\, y_{n+1-j}\right) = 0
$$

which Newton solves for $y_{n+1}$.
The Newton matrix is

$$
A = F_y + \frac{\alpha_0}{h_n} F_{\dot y}
$$

with an initial guess extrapolated from the interpolant through past states.
For dense and sparse solvers, failed stages retry at most twice, first with a factorization at the current step size, then newly evaluated derivative blocks.
Newton iterates are accepted only when the residual itself meets differential and algebraic residual tolerances.
Approximate Jacobians therefore change iteration counts but not the accepted solution.

Orders are 1–5; BDF orders 1 and 2 are A-stable, while orders 3–5 are stable on the whole negative real axis but not A-stable.
Local error estimates multiply the $(q+1)$-order divided difference through $q + 2$ new and past values by a coefficient determined by the time arrangement.
Compare estimates at orders $q - 1$, $q$, and $q + 1$ to choose the next order.
I control selects the step as $h_{\mathrm{new}} = 0.9\,h\,E^{-1/(q+1)}$ from normalized error estimate $E$.
Growth is capped at fivefold for order 1 and twofold otherwise, with no growth immediately after rejection.

The first step has no past values.
Differential-variable errors use predictor $x_0 + h\dot x_0$ difference $e_x = (h/2)(\dot x_1 - \dot x_0)$; algebraic errors use response $g_z^{-1} g_x e_x$ of linearized algebraic equations to $e_x$.
Every call starts at order 1 without history, so successive `advance` calls each restart from the first step.

Differential and algebraic local errors are normalized separately against one-quarter of tolerances `with_differential_error` and `with_algebraic_error`.
Accept the step if the larger normalized estimate is at most 1.
The remaining three-quarters of tolerance allow for error propagation and nonlinear-equation error.
These estimate local errors and do not bound global error.
Consecutive rejections are limited by `with_rejection_limit` (default 12), stopping with `RejectionLimit` when exhausted.

Without an initial step supplied through `DaeOptions::with_initial_step`, use

$$
h_0 = \min\!\left(\frac{|t_{\mathrm{end}} - t_0|}{1000},\; \frac{0.5}{\lVert \dot x_0 \rVert}\right)
$$

(the DASSL rule).
Here $\lVert \dot x_0 \rVert$ is the `with_differential_error` norm of differential-variable derivatives with scale $|x_0|$, making initial increment $h_0 \lVert \dot x_0 \rVert$ at most half the differential tolerance.

## Derivative evaluation

Newton matrices need $F_y$ and $F_{\dot y}$.
The trait `DaeSystem` accepts derivatives through three optional callbacks.

| Callback | Linear solver (`OdeStageBackend`) | Output written |
|---|---|---|
| `derivatives` | `Dense` (dense LU) | Dense blocks of $F_y$ and $F_{\dot y}$ |
| `sparse_derivatives` | `Sparse` (sparse LU) | Values of $F_y$ and $F_{\dot y}$ on a shared nonzero pattern |
| `derivative_product` | `Krylov`（GMRES） | Directional product $F_y u + F_{\dot y} v$ |

Callbacks return `Ok(Some(()))` after writing or `Ok(None)` when unavailable; defaults return `Ok(None)`.
Derivative evaluation follows `DerivativeStrategy` in `DaeNumericalOptions::with_derivative_strategy`, defaulting to callbacks first and residual forward differences on `Ok(None)`.
DAE residuals have no automatic-differentiation source, so that candidate is skipped.
Only `Ok(None)` advances to the next candidate; callback errors propagate unchanged.
Difference steps are $\sqrt{\varepsilon}$ times coordinate magnitude ($\varepsilon^{1/3}$ for central differences).
Magnitude scales are bounded below by partition-specific absolute state tolerances for states and absolute initialization-derivative tolerances for differential derivatives; zero absolute tolerances use 1.
Writing nonzero $F_{\dot y}$ entries in partition-forbidden positions (algebraic-equation rows or algebraic-variable columns) gives `InvalidInput`.
Krylov solvers accept right preconditioning through `preconditioner`.

## Settings, states, and workspaces

The settings `DaeNumericalOptions` collect error control, residual tolerances, initialization, and iteration limits, supplied to `DaeOptions` through `DaeOptions::with_numerics`.
Defaults are absolute and relative $\sqrt{\varepsilon}$ tolerances (infinity norm) for differential and algebraic states and initialization derivatives, absolute $\sqrt{\varepsilon}$ and relative 0 for differential and algebraic residuals, unit residual reference scales, `Check` initialization, 12 Newton iterations per attempt, and 12 consecutive rejections.
Here $\varepsilon$ is the scalar type's machine epsilon.
Componentwise tolerances use indices within each partition; entry $k$ corresponds to differential (or algebraic) variable $k$.
DAE adjoints (`DaeAdjointOptions`) accept the same `DaeNumericalOptions` ([Gradients with adjoints](../adjoint-gradients/)).

The settings `DaeOptions` add initial step, attempted-step limit (`with_max_steps`), and callback-evaluation limit (`with_max_evaluations`) to numerical settings.
Setters cannot fail; `advance` validates consistency with the partition before integration.

State `DaeState` contains time, state, and derivative; `advance` reads initial values there and leaves the last accepted pair.
Failure before initial acceptance leaves state unchanged.
The sink `DaeOutputSink` receives `emit(t, y, ẏ)` per accepted step; the initial pair is not emitted.
The sink `()` discards output; closure `FnMut(t, y, ẏ) -> Result<(), SciOxideError>` can also be a sink.

The method `DaeBdf::workspace` or `DaeWorkspace::try_reserve` allocates BDF history, Newton, and linear-solver memory matching `DaeRequirements` (dimension and linear solver).
The method `advance` reallocates workspace for a different dimension or linear solver.
With sufficient workspace and nonallocating callbacks and sinks, `advance` does not allocate.
The record `DaeWorkspace::last_attempt` retains the latest call result, work counts, and progress `DaeReport`.
The method `DaeBdf::solve` creates workspace and executes sequentially, returning `DaeSolution` (final pair and report).
Failure returns error and progress through `PartialFailure`.

## Termination statuses and reports

Only `ReachedEnd` of `DaeTermination` is successful.
The status `BudgetLimit(kind)` indicates work limits (`Proposal` for steps, `Evaluation` evaluations, `Iteration` Newton iterations), `StepSizeLimit` no step advancing toward the endpoint, `ExecutionStopped` cancellation or deadline, and `RejectionLimit` the consecutive-rejection limit.
The status `TerminalEvent` never occurs because DAEs have no events.
These stops follow initial-pair acceptance; `advance` returns `Ok` with an unsuccessful report, leaving the last accepted pair in state.
Inconsistent initial values, failed projection, and stops before initial acceptance give errors.

The report `DaeReport` holds termination status (`termination`, `is_success`), last accepted time (`final_time`), accepted and rejected step counts, evaluation and iteration counts (`counts`, `accounting`), differential and algebraic residuals at the last pair, normalized local error estimates for the last accepted step (`differential_error`, `algebraic_error`), and last attempted-step estimate (`last_step_error_estimate`).
The value `trust` is `ResidualChecked` after accepting a pair and `DiagnosticOnly` before; it does not prove accuracy.

## Consistency and integration experiments

The model has differential variable $x$ and algebraic variable $z$:

$$
F(t, y, \dot y) = \begin{bmatrix} \dot x + z - t \\ z - x^2 - t \end{bmatrix} = 0, \qquad x(0) = 1
$$


Algebraic equations give $z = x^2 + t$; substituting into differential equations gives $\dot x = -x^2$, so the analytical solution is

$$
x(t) = \frac{1}{1 + t}, \qquad z(t) = \frac{1}{(1 + t)^2} + t
$$


The consistency Jacobian is $J_{\mathrm c} = \begin{bmatrix} 1 & 1 \\ 0 & 1 \end{bmatrix}$, nonsingular everywhere.
Values consistent with $x(0) = 1$ are $z(0) = 1$ and $\dot x(0) = -1$.

The following block defines the model and settings shared by three cells.
In `DecayConstraint`, `residual` is $F$, `derivatives` gives dense blocks of $F_y$ and $F_{\dot y}$ (row-major), and `exact` corresponds to the analytical solution.
The function `bdf_plan` creates the partition and dense-LU Plan; `bdf_options` creates settings with the same tolerance $\varepsilon$ for differential and algebraic states; `accepted_state` reads the pair passed by the consistency cell.

```rust
//| id: ode-dae-index-one-model
//| kind: definitions
//| title: "Residual and analytical solution of a model with algebraic constraints"
//| crates: [scioxide-core, scioxide-differentiate, scioxide-linalg, scioxide-ode]
use scioxide_core::{ErrorTolerance, SciOxideError, NormSelection, SolveContext, Tolerance};
use scioxide_differentiate::DerivativeStrategy;
use scioxide_linalg::MatrixViewMut;
use scioxide_ode::{
    DaeBdf, DaeInitialization, DaeNumericalOptions, DaeOptions, DaePartition, DaeState, DaeSystem,
    OdeStageBackend,
};

/// F(t, y, y') = (x' + z − t, z − x² − t). y = (x, z), with differential x and algebraic z.
pub(crate) struct DecayConstraint;

impl DaeSystem<f64> for DecayConstraint {
    fn dimension(&self) -> usize {
        2
    }

    fn residual(
        &self,
        t: f64,
        y: &[f64],
        dy: &[f64],
        out: &mut [f64],
        _: &mut SolveContext<'_, '_>,
    ) -> Result<(), SciOxideError> {
        out[0] = dy[0] + y[1] - t;
        out[1] = y[1] - y[0] * y[0] - t;
        Ok(())
    }

    // state_block = ∂F/∂y = [[0, 1], [−2x, 1]], derivative_block = ∂F/∂y' = [[1, 0], [0, 0]].
    fn derivatives(
        &self,
        _: f64,
        y: &[f64],
        _: &[f64],
        state_block: &mut MatrixViewMut<'_, f64>,
        derivative_block: &mut MatrixViewMut<'_, f64>,
        _: &mut SolveContext<'_, '_>,
    ) -> Result<Option<()>, SciOxideError> {
        let state = [0.0, 1.0, -2.0 * y[0], 1.0];
        let derivative = [1.0, 0.0, 0.0, 0.0];
        for k in 0..4 {
            state_block.set(k / 2, k % 2, state[k])?;
            derivative_block.set(k / 2, k % 2, derivative[k])?;
        }
        // Some indicates analytical blocks were written; None switches to residual differences.
        Ok(Some(()))
    }
}

/// Partition variables and equations with differential first and algebraic second, using dense-LU residual BDF.
pub(crate) fn bdf_plan() -> Result<DaeBdf, SciOxideError> {
    let partition = DaePartition::new(&[true, false], &[true, false])?;
    DaeBdf::new(partition, OdeStageBackend::Dense)
}

/// Settings with differential and algebraic state tolerances both ε (absolute and relative, infinity norm).
pub(crate) fn bdf_options(
    epsilon: f64,
    initialization: DaeInitialization,
    strategy: DerivativeStrategy,
) -> Result<DaeOptions<f64>, SciOxideError> {
    let tolerance =
        ErrorTolerance::from_tolerance(Tolerance::new(epsilon, epsilon)?, NormSelection::Infinity);
    let numerics = DaeNumericalOptions::new()
        .with_differential_error(tolerance.clone())
        .with_algebraic_error(tolerance)
        .with_initialization(initialization)
        .with_derivative_strategy(strategy);
    Ok(DaeOptions::new().with_numerics(numerics))
}

/// Read the pair passed by the consistency cell. Rejection (Check) passes null and gives an error.
pub(crate) fn accepted_state(exports: &serde_json::Value) -> Result<DaeState<f64>, String> {
    let read = |key: &str| {
        serde_json::from_value::<Option<Vec<f64>>>(exports[key].clone())
            .map_err(|e| e.to_string())?
            .ok_or_else(|| "Inconsistent initial values (set the preceding cell to Project)".to_string())
    };
    DaeState::from_slices(0.0, &read("initial_values")?, &read("initial_derivative")?)
        .map_err(|e| e.to_string())
}

/// Analytical solution (x, z) = (1/(1 + t), 1/(1 + t)² + t). Reference for verification.
pub(crate) fn exact(t: f64) -> (f64, f64) {
    let x = 1.0 / (1.0 + t);
    (x, x * x + t)
}
```

    ),

emit_table_with_columns!(

let outcome = match (&initialized, accepted) {
    (Ok(_), Some(report)) => Outcome::satisfied("Accepted consistent initial values")
        .status(mode.to_string())
        .diagnostic("Algebraic-state correction", report.state_correction(), None)

With defaults ($z_0 = 0$, `Project`), supplied algebraic residual is 1 and differential residual 0.
Projection fixes $x(0) = 1$ and changes values to $z(0) = 1$ and $\dot x(0) = -1$, making both residuals zero.
Under `Check`, algebraic residual 1 exceeds tolerance $\sqrt{\varepsilon} \approx 1.5 \times 10^{-8}$, giving `InvalidInput`.
Even with $z_0 = 1$, $\dot x(0) = 0$ leaves differential residual 1, so `Check` returns the same error.
Constructing consistency by hand requires $z_0$ and $\dot x_0$ satisfying both algebraic and differential equations.

use scioxide_differentiate::DerivativeStrategy;

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });

    .map(|t| [t, exact(t).0, exact(t).1])
    .collect();

};

With defaults ($\varepsilon = 10^{-8}$, $T = 4$), 129 steps reach `ReachedEnd` without rejection; at $t = 4$, analytical differences are $2.9 \times 10^{-8}$ for $x$ and $1.2 \times 10^{-8}$ for $z$.

## Tolerances and global error

Selecting steps from local error estimates does not make global error a fixed multiple of tolerance.
The next cell integrates the same consistent initial values through $T = 4$ with tolerances $\varepsilon = 10^{-3}, 10^{-4}, \dots, 10^{-11}$, comparing terminal analytical differences and work.
A derivative-policy input switches analytical blocks (`AnalyticOrForward`, default) against residual forward differences only (`Forward`).
Newton continues until residual tolerances hold, so forward-difference Jacobians should leave error columns nearly unchanged while changing only evaluation counts.
The log–log plot shows error versus tolerance; the dashed reference is error = tolerance.

//| cases:

let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });

let initial = accepted_state(initialization)?;
let strategy = if strategy == "Forward" {
    DerivativeStrategy::Forward
} else {
    DerivativeStrategy::AnalyticOrForward

let end_time = 4.0;
let (x_exact, z_exact) = exact(end_time);
let plan = bdf_plan().map_err(|e| e.to_string())?;
// Reuse workspace across all tolerances.

        (state.values()[1] - z_exact).abs(),

        counts.provider(EvaluationRole::Jacobian),
        usize::from(!report.is_success()),
    ));
}
let errors: Vec<[f64; 2]> = rows.iter().map(|r| [r.0, r.2]).collect();
let diagonal: Vec<[f64; 2]> = rows.iter().map(|r| [r.0, r.0]).collect();
emit_line_chart!(

## Summary

The solver `DaeBdf` integrates index-1 residual-form $F(t, y, \dot y) = 0$ DAEs with differential and algebraic variables specified through `DaePartition`.
Validate initial values with `Check` or recompute algebraic states and derivatives with `Project`, inspecting correction magnitudes through `DaeConsistencyReport`.
Residual BDF uses orders 1–5 with coefficients from actual times, comparing differential and algebraic local errors separately against one-quarter of tolerance.
Local error control does not guarantee global error; compare with known solutions or solutions at different tolerances.
Supply analytical derivative blocks or use differences through `Ok(None)`; residual tolerances determine accepted solutions.
