This chapter's mathematics pages cover methods approximating the initial value problem

$$
M\,\frac{dy}{dt} = f(t, y), \qquad y(t_0) = y_0 \in \mathbb{C}^d
$$

at discrete times $t_0 < t_1 < \dots$ and related problems (DAEs, DDEs, SDEs, Hamiltonian systems, and boundary value problems).
This page collects notation and contracts shared by all pages.

## Notation

| Symbol | Meaning |
|---|---|
| $y_n$ | Numerical solution at time $t_n$ |
| $h_n = t_{n+1} - t_n$ | Step size (negative for backward integration) |
| $p$ | Method order (local error $O(h^{p+1})$, global error $O(h^p)$ over a finite interval) |
| $J = \partial f / \partial y$ | Right-hand-side Jacobian |
| $z = h\lambda$ | Product of step size and eigenvalue for the test equation $y' = \lambda y$ |
| $R(z)$ | Stability function (one-step amplification factor $y_{n+1} = R(z) y_n$) |
| $\varepsilon_{\mathrm{abs}}, \varepsilon_{\mathrm{rel}}$ | Absolute and relative tolerances for local error |
| $\varepsilon$ | Machine epsilon of the time type (`f64` or `f32`) |

## Shared contracts

Adaptive methods use embedded formulas or similar techniques to estimate the one-step local error $e_i$ componentwise.
A step is accepted if the norm after division by $\varepsilon_{\mathrm{abs},i} + \varepsilon_{\mathrm{rel}}\max(|y_{i,n}|, |y_{i,n+1}|)$ (root-mean-square by default) is at most 1.
Estimates do not bound error, so check global error against known solutions or solutions at different tolerances.

Methods that do not adjust steps from error estimates (classical explicit Runge–Kutta, implicit Runge–Kutta other than `RadauIia`, fixed-order multistep methods, and Hamiltonian splitting methods) use a supplied step size.
If no step size is supplied through `OdeOptions::with_initial_step`, fixed-step methods in `OdeMethod` keep using an initial step estimated in the same way as adaptive methods.

Only each problem's termination status determines success.
Initial value problems return `OdeTermination`, DAEs `DaeTermination`, DDEs `DdeTermination`, SDEs `SdeTermination`, Hamiltonian systems `MechanicalTermination`, boundary value problems `BvpTermination`, and adjoints `AdjointTermination`.
Results stopped at a limit or by cancellation may also return `Ok`, so check the report's `is_success()` before using values.

Callback errors, allocation failures, nonfinite values, and numerical breakdown return `SciOxideError`.
The caller's state then retains the last accepted point, and the workspace's attempt record (`last_attempt`) retains progress.
An unaccepted candidate never overwrites the accepted state.
[Solving procedure and result contracts](solve-lifecycle-and-contracts/) explains the detailed procedure.

Reports record right-hand-side, Jacobian, and event-function evaluations, and attempted, accepted, and rejected steps.
Limits are supplied through `with_max_steps` (attempt count) and `with_max_evaluations` (evaluation count) in `OdeOptions`, or through scioxide-core execution contexts (cancellation, deadlines, and work limits).
A nested solve inside a callback also counts toward the same context's work limit.

Method coefficients belong to the integrator object; dimension-dependent memory belongs to caller-owned workspace.
Workspace can be reused after checking capacity through `check` and `try_reserve`.
Each call to `advance` starts afresh from the supplied state, without reusing the preceding call's step size or history.
The caller-selected output sink allocates storage for trajectories and event records.

Time is real; states may be real or complex.
Implicit methods, Jacobians, and adjoint products assume holomorphic right-hand sides, so write nonholomorphic models with separate real and imaginary parts.

Public APIs take no caller identity or provenance arguments.
Errors describe what failed: kind, `Argument` and `Quantity`, and detail.

## Summary

This chapter's methods share contracts for accepting steps using local error estimates and tolerances, one authoritative termination status, preserving accepted states on failure, and caller-owned workspace.
Error estimates are not bounds; compare results with known solutions or solutions at different tolerances.
Start with [Error, order, and stability](error-order-and-stability/) for theory, [Solving procedure and result contracts](solve-lifecycle-and-contracts/) for receiving results and handling failures, or the [API guide](../api/) for a type index.
