The crate `scioxide-ode` solves ordinary differential equation initial value problems, residual-form index-1 differential-algebraic equations (DAEs), constant-delay differential equations (DDEs), stochastic differential equations (SDEs), separable Hamiltonian systems and holonomically constrained systems, and two-point boundary value problems.
It computes solution derivatives with respect to parameters and initial values using forward sensitivities and adjoints.
Time is real, `f32` or `f64`, and states may be real or complex (DDE and RATTLE states are real only).
This guide identifies initial entry points by purpose and collects the 177 public items listed in rustdoc's `all.html` into tables on five child pages.
Item-name links point to the version 0.1.0 API reference on docs.rs.

## APIs by use

Start with one-shot functions if you need only answers at default settings.
The function `solve_ivp` returns the terminal state, while `solve_ivp_at` returns a matrix whose rows are states at specified times.
Both use Dormand–Prince 5(4) with absolute tolerance $10^{-6}$, relative tolerance $10^{-3}$, and RMS-norm error control.
The function `solve_dde` solves constant-delay DDEs by the method of steps with Dormand–Prince 5(4), returning the terminal state.
The function `solve_sde` computes Euler–Maruyama paths from caller-supplied Wiener increments, returning states on the time grid.
The function `solve_hamiltonian` advances separable Hamiltonian systems by fixed-step Störmer–Verlet, returning final positions and momenta.
The function `solve_bvp` solves two-point boundary value problems with the default collocation method and residual tolerance $10^{-3}$, returning a piecewise cubic solution.
The function `solve_ensemble_into` solves many problems differing only in parameters in one execution, writing each member's result into a caller-supplied array.

One-shot functions return every unsuccessful termination as an error.
Errors from time-evolution functions (`solve_ivp`, `solve_ivp_at`, `solve_dde`, `solve_sde`, `solve_hamiltonian`) are `PartialFailure`, carrying progress through the last accepted point.
The function `solve_bvp` returns only `SciOxideError` errors.

## Type relationships

One-shot functions create a method with default settings and workspace locally, execute sequentially, and return the answer.

For initial value problems, the system, problem, integrator object, settings, state, output sink, and workspace are separate values.
The trait `OdeSystem` requires a dimension and right-hand side $f(t, y)$, with optional Jacobian, mass matrix, time partial derivative, step-size limit, and trial-state rejection predicate (`admits`).
The type `OdeFn` implements `OdeSystem` from closures.
The problem `OdeProblem` borrows the system, terminal time, event functions, and implicit stage solver; start time and initial values belong to the caller-owned `OdeState`.
Integrator objects (such as `DormandPrince5::new()`) hold only coefficients and method-specific settings, executing through `OdeMethod` trait methods.
The method `validate(options, dimension)` validates settings, and `workspace(problem, options)` allocates reusable workspace `OdeWorkspace`.
The method `advance(problem, options, state, sink, workspace, scope)` advances the state in place, sends accepted points to output sink `OdeOutputSink`, and returns `OdeSolveReport`.
The method `solve(problem, options, initial)` prepares new workspace and `OdeTrajectory`, calls `advance` sequentially, and returns `OdeSolution`.
The settings `OdeOptions` collect tolerances, initial step, step-size bounds, controller (`OdeStepControl`), output times (`OdeOutputSchedule`), event search (`OdeEventOptions`), and attempt and evaluation limits, supplied per call.
Convert an integrator object to `BuiltinOdeMethod` to select the method at runtime.

Other problems follow the same separation.
Supply the problem (or system), settings, state, output sink, and workspace to integrator objects `DaeBdf` for DAEs, `SdeMethod` for SDEs, and `StormerVerlet` and `Rattle` for Hamiltonian systems.
At construction, the DDE `DdePlan` computes the derivative-discontinuity schedule from delays and the interval, while the boundary value `BvpPlan` computes the initial mesh and singular-term pseudoinverse, each only once.
Neither Plan borrows a system; both can be reused for problems of the same dimension.
The adjoint Plans `OdeAdjointSolver` and `DaeAdjointSolver` also validate only dimensions and settings, accepting `OdeAdjointProblem` and `DaeAdjointProblem` that borrow the system, objective, initial values, and integration interval.
Forward sensitivity treats the augmented system created by `ForwardSensitivitySystem::bind` as an ordinary `OdeSystem` and integrates it with initial value problem methods.

## Minimal executable example

The following cell solves $y' = -y$, $y(0) = 1$ through $t = 1$ using classical fourth-order Runge–Kutta (`ClassicalRk4`), comparing with the analytical solution $e^{-1}$.
Since `ClassicalRk4` is fixed-step, the value supplied to `OdeOptions::with_initial_step` directly gives the step size $h$; only steps overshooting the endpoint are shortened to it.
The step size is $h = 2^{-k}$, with exponent $k$ varied by input.
Powers of two are exactly representable in binary floating point, so multiples of $h$ reach $t = 1$ exactly.
For steps not exactly representable, such as $h = 0.1$, time sums accumulate rounding error; a step with remaining time at most the rounding-error bound $1024\,\varepsilon\max(|t|, |t_\text{end}|)$ ends at the endpoint, avoiding an extra short step.
Construct the integrator object and workspace once and reuse them for two calls to `advance` with steps $h$ and $h/2$.
If global error $e_h$ is proportional to $h^4$, the observed order $\log_2(e_h / e_{h/2})$ from the ratio of the two errors approaches 4.
The table shows step size, termination status, accepted steps, points received by the output sink, numerical solution, difference from the analytical solution, and observed order.
The default output `FinalOnly` sends only the terminal state, so one point is received.

```rust
//| id: ode-api-exponential-decay
//| ref: ode-api-exponential-decay
//| title: "Solve exponential decay with fixed-step RK4 and read the report and error"
//| run: reactive
//| crates: [scioxide-ode, scioxide-core, scioxide-linalg]
//| inputs:
//|   step_exponent: {"type":"range","label":"Step-size exponent k (h = 2⁻ᵏ)","description":"Vary step size by powers of two. RK4 global error varies in proportion to h⁴.","min":2,"max":7,"step":1,"value":3}
//| cases:
//|   - {"id":"coarse","label":"h = 0.25","description":"The observed order is near 4 even with four steps.","inputs":{"step_exponent":2}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"runs","path":"/rows/0/1","equals":"ReachedEnd"}
//|       - {"artifact":"runs","path":"/rows/0/2","equals":8}
//|       - {"artifact":"runs","path":"/rows/0/3","equals":1}
//|       - {"artifact":"runs","path":"/rows/0/5","approx":{"value":8.3075e-7,"rtol":1e-3}}
//|       - {"artifact":"runs","path":"/rows/1/6","approx":{"value":4.075,"atol":0.01}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: coarse
//|     expect:
//|       - {"artifact":"runs","path":"/rows/0/2","equals":4}
//|       - {"artifact":"runs","path":"/rows/0/5","approx":{"value":1.4758e-5,"rtol":1e-3}}
//|       - {"artifact":"runs","path":"/rows/1/6","approx":{"value":4.151,"atol":0.01}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
use scioxide_core::ExecutionContext;
use scioxide_linalg::Vector;
use scioxide_ode::{
    ClassicalRk4, OdeFn, OdeMethod, OdeOptions, OdeProblem, OdeState, OdeTrajectory,
};

let sig12 = serde_json::json!({ "significantDigits": 12 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let sig4 = serde_json::json!({ "significantDigits": 4 });
let fixed2 = serde_json::json!({ "fractionDigits": 2 });

// One-component system y' = -y.
let system = OdeFn::new(1, |_t: f64, y: &[f64], dy: &mut [f64]| {
    dy[0] = -y[0];
    Ok(())
})
.map_err(|e| e.to_string())?;
let problem = OdeProblem::new(&system, 1.0);
let method = ClassicalRk4::new();
// Allocate workspace once and reuse it for two advance calls.
let mut workspace = method
    .workspace(&problem, &OdeOptions::new())
    .map_err(|e| e.to_string())?;

let mut rows = Vec::new();
let mut errors = Vec::new();
let mut all_reached = true;
// Power-of-two steps are exactly representable in binary, so multiples of h reach t = 1 exactly.
let step_size = 0.5_f64.powi(step_exponent as i32);
for h in [step_size, step_size / 2.0] {
    // For fixed-step methods, the initial step becomes the step size.
    let options = OdeOptions::new().with_initial_step(h);
    let mut state = OdeState::new(0.0, Vector::from_vec(vec![1.0]));
    let mut output = OdeTrajectory::new();
    let report = method
        .advance(
            &problem,
            &options,
            &mut state,
            &mut output,
            &mut workspace,
            ExecutionContext::sequential(),
        )
        .map_err(|e| e.to_string())?;
    all_reached &= report.is_success();
    // Independent check: analytical solution e^{-t} at reached time t (f64 reference).
    let value = state.values()[0];
    let error = (value - (-report.final_time()).exp()).abs();
    // Define the observed order only in the second row.
    let order = errors.last().map(|&coarse: &f64| (coarse / error).log2());
    errors.push(error);
    rows.push((
        h,
        report
            .termination()
            .map_or_else(String::new, |t| t.to_string()),
        report.accepted_steps(),
        output.times().len(),
        value,
        error,
        order,
    ));
}
let observed = rows[1].6.unwrap_or(f64::NAN);

let columns = serde_json::json!([
    { "key": "0", "label": "Step h [-]", "type": "number", "format": sig4 },
    { "key": "1", "label": "Termination" },
    { "key": "2", "label": "Accepted steps [count]", "type": "integer" },
    { "key": "3", "label": "Output points [count]", "type": "integer" },
    { "key": "4", "label": "Numerical solution y(t) [-]", "type": "number", "format": sig12 },
    { "key": "5", "label": "Analytical-solution difference [-]", "type": "number", "format": sci3 },
    { "key": "6", "label": "Observed order [-]", "type": "number", "format": fixed2, "nullText": "-" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "runs" })
);

// Use the observed order in the conclusion only if both runs reach the endpoint.
let outcome = if all_reached && observed.is_finite() {
    Outcome::satisfied("Reached the endpoint with both step sizes")
        .explanation("Fixed-step methods do not estimate error. Assess accuracy from the analytical-solution difference and observed order.")
        .diagnostic("Observed order", observed, None)
} else {
    Outcome::partial("Stopped before reaching the endpoint")
        .explanation("The table gives the state at the last accepted time.")
};
emit_outcome!(outcome.status(rows[1].1.clone()));
```

With the default $k = 3$ ($h = 0.125$), both step sizes terminate with `ReachedEnd`, accepting eight and 16 steps.
Differences from the analytical solution are $8.31 \times 10^{-7}$ at $h = 0.125$ and $4.93 \times 10^{-8}$ at $h = 0.0625$, giving observed order 4.08.
Four steps at $k = 2$ ($h = 0.25$) increase the difference to $1.48 \times 10^{-5}$, but observed order is 4.15, showing fourth-order convergence even with coarse steps.
At $k = 7$ ($h = 2^{-7}$), the difference falls to $1.15 \times 10^{-11}$ and observed order is 4.01.
Fixed-step methods have no error estimate, so the report's `last_step_error_estimate()` is `None`.
Assess accuracy against independent references such as analytical solutions or comparisons at different step sizes.

## Reading results, errors, and diagnostics

Each time-evolution solver has one termination-status enum.
The enums `OdeTermination`, `DaeTermination`, `DdeTermination`, `SdeTermination`, `MechanicalTermination`, and `AdjointTermination` add problem-specific variants to the shared variants `ReachedEnd`, `TerminalEvent`, `BudgetLimit(kind)`, `StepSizeLimit`, and `ExecutionStopped(reason)`.
Problem-specific variants are DDE's `HistoryCapacity` (history capacity limit), DAE's `RejectionLimit` (consecutive-rejection limit), RATTLE's `ProjectionLimit` (a step unable to satisfy constraint tolerance), and adjoints' `ReplayMismatch` (recomputation mismatch) and `EventDerivativeUnavailable` (missing terminal-event derivative).
The report's `is_success()` determines success; `ReachedEnd` and `TerminalEvent` are successful.
DAEs, SDEs, and dynamical systems without events do not return `TerminalEvent`.
Boundary value problems have a separate enum `BvpTermination`, with only `Converged` successful.

On attempt or evaluation limits, minimum step size, cancellation, or deadline, `advance` returns a report with an unsuccessful status as `Ok`, leaving the last accepted point in the state.
Other failures return `SciOxideError`.
Input validation precedes callbacks; rejected calls do not change state.
Even after a failure during integration, the state retains the last accepted point, and workspace `last_attempt()` records the attempt result and progress (`OdeProgress` for initial value problems).
Points sent to the output sink are not retracted after later failure.
For APIs returning owned values, `solve` returns progress after an integration failure in `PartialFailure`.
One-shot functions convert stops at attempt or evaluation limits or minimum step sizes to `ConvergenceFailure`, DDE history capacity limits to `ResourceLimit`, and cancellation or deadlines to `ExecutionStopped`.
Adjoints write both gradients only on success, and boundary value `solve_into` leaves output unchanged on errors.

Read error classifications through `e.kind()`.
The variant `InvalidInput` covers invalid settings (such as nonpositive maximum step sizes), unsupported features (scheduled output or events for methods without dense output, or controllers for fixed-step methods), and equal start and end times.
The variant `NonFinite` covers NaN or infinity in inputs (source `Input`) or callback outputs (source `Callback`); `DimensionMismatch` covers mismatched system, state, or output array lengths.
The variants `ConvergenceFailure`, `Singular`, and `NumericalInstability` describe failed fixed-step stage solves or failed DAE initial-value projection.
Adaptive methods halve the step and retry after a failed stage solve, stopping with `StepSizeLimit` when no further reduction is possible.
The variants `ResourceLimit`, `AllocationFailure`, and `SizeOverflow` indicate that workspace, history, or checkpoint memory exceeds configured limits or cannot be allocated.
Callback errors propagate unchanged.

The value `last_step_error_estimate()` estimates normalized local error for the last attempted step; a value at most 1 accepts the step.
It does not bound global error.
DDE estimates exclude history-interpolation error.
SDE estimates use the difference between one step and two half-steps and are present only when refinement is configured.
Dynamical-system reports have no estimate.
Boundary value interval residuals, DAE residuals, and adjoints' `AdjointErrorReport` are also diagnostics rather than error bounds.
The value `trust()` gives the trust level (`PartialResultTrust`) of the last accepted state; it does not prove accuracy.

The fields `accepted_steps()` and `rejected_steps()` count accepted and rejected time steps; for adjoints they count only the initial forward integration.
The value `counts()` counts evaluations and iterations of that call itself, excluding nested solvers.
The value `accounting()` aggregates counts including nested solvers.

For initial value problems and DDEs with events configured, the report's `events()` gives the detected event count and `terminal_event()` the index of the event stopping integration.
The method `event_search()` returns the search policy and event-function evaluation count, including localization.
Event times and states pass to `OdeOutputSink::event` and remain in `OdeTrajectory::events()` as `EventInfo`.
A search uses finitely many samples, so failure to detect an event does not prove its absence.
