An initial value problem (IVP) for an ordinary differential equation (ODE), whose rate of change of state $y(t) \in \mathbb{R}^d$ (or $\mathbb{C}^d$) depends on its state at that time,

$$
M\,\frac{dy}{dt} = f(t, y), \qquad y(t_0) = y_0
$$

appears in many models, including celestial motion, chemical concentrations, ecosystem populations, and electrical circuit transients.
Here $M$ is a constant mass matrix, defaulting to the identity.
Numerical integration becomes difficult with stiffness from widely separated component timescales, event-driven discontinuities, dependence on past states, or stochastic forcing.

The crate `scioxide-ode` handles the following problems.

| Problem | Formula | One-shot function | Configurable type |
|---|---|---|---|
| Initial value problems (including nonsingular mass matrices) | $M y' = f(t, y)$ | `solve_ivp`, `solve_ivp_at` | Methods implementing `OdeMethod` (such as `DormandPrince5`, `RadauIia`, and `Bdf`) |
| Index-1 differential-algebraic equations (DAEs) | $F(t, y, y') = 0$ | None | `DaeBdf` |
| Constant-delay differential equations (DDEs) | $y' = f(t, y(t), y(t - \tau_j))$ | `solve_dde` | `DdePlan` |
| Stochastic differential equations (SDEs) | $dY = a\,dt + B\,dW$ | `solve_sde` | `SdeMethod` |
| Separable Hamiltonian systems and holonomic constraints | $q' = \partial H/\partial p$, $p' = -\partial H/\partial q$ | `solve_hamiltonian` | `StormerVerlet`, `Rattle` |
| Two-point boundary value problems (BVPs) | $y' = f(x, y, p)$, $g(y(a), y(b), p) = 0$ | `solve_bvp` | `BvpPlan` |
| Solution derivatives with respect to parameters | Forward sensitivities and adjoints | None | `ForwardSensitivitySystem`, `OdeAdjointSolver`, `DaeAdjointSolver` |
| Many independent initial value problems | An IVP per parameter set | `solve_ensemble_into` | `EnsembleWorkspace` |

Time is real, `f32` or `f64`; states may be real or complex.
For complex states with implicit methods, the right-hand side must be holomorphic.
Write nonholomorphic models as real systems with separate real and imaginary parts.

## First computation: logistic growth

For population $y$ [individuals], growth rate $r$ [1/day], and carrying capacity $K$ [individuals], the equation $y' = r\,y(1 - y/K)$ has solution

$$
y(t) = \frac{K}{1 + (K/y_0 - 1)e^{-rt}}
$$


With $K = 1000$ and $y_0 = 10$, compute the value after 20 days in three ways and compare with the closed form.

1. Pass a right-hand-side closure, start and end times, and initial values to the one-shot function `solve_ivp`.
   It uses the Dormand–Prince 5(4) method with fixed default tolerances $\varepsilon_\text{abs} = 10^{-6}$ and $\varepsilon_\text{rel} = 10^{-3}$.
   It returns only the state at the endpoint.
2. Supply tolerances and a step limit through `OdeOptions` to the integrator objects `DormandPrince5` and the order-8(5,3) `DormandPrince853`, and solve with `solve`.
   The returned `OdeSolution` holds the endpoint state and a report `OdeSolveReport` recording termination status, step counts, and evaluation counts.

The cell inputs are growth rate, tolerances for the integrator objects, and the maximum attempted step count.
The output is a three-row table and an outcome indicating whether both integrator objects succeeded.

```rust
//| id: ode-first-logistic
//| ref: ode-first-logistic
//| title: "Solve logistic growth with solve_ivp and two integrator objects, and read their reports"
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg, scioxide-ode]
//| inputs:
//|   growth_rate: {"type":"range","label":"Growth rate r [1/day]","description":"Larger values approach saturation faster within 20 days.","min":0.2,"max":2,"step":0.1,"value":0.5}
//|   tolerance_exponent: {"type":"range","label":"Exponent q in tolerance 10^q","description":"Relative tolerance and absolute tolerance [individuals] for the integrator objects. solve_ivp keeps its defaults.","min":-12,"max":-3,"step":1,"value":-6}
//|   max_steps: {"type":"range","label":"Maximum attempted steps [count]","description":"Includes rejected steps. Small values stop integration early.","min":5,"max":500,"step":5,"value":500}
//| cases:
//|   - id: step-limit
//|     label: "Step limit 10"
//|     inputs: {"max_steps":10}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"methods","path":"/rows/0/4","range":{"max":1e-1}}
//|       - {"artifact":"methods","path":"/rows/1/1","equals":"ReachedEnd"}
//|       - {"artifact":"methods","path":"/rows/2/4","range":{"max":1e-4}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: step-limit
//|     expect:
//|       - {"artifact":"methods","path":"/rows/1/1","equals":"BudgetLimit(Proposal)"}
//|       - {"artifact":"methods","path":"/rows/1/2","range":{"max":10}}
//|       - {"path":"/outputs/1/state","equals":"partial"}
use scioxide_core::{Budget, ErrorTolerance, NormSelection};
use scioxide_linalg::Vector;
use scioxide_ode::{
    DormandPrince5, DormandPrince853, OdeFn, OdeMethod, OdeOptions, OdeProblem, OdeSolution,
    OdeState, solve_ivp,
};

let (capacity, initial, horizon) = (1000.0_f64, 10.0_f64, 20.0_f64);
// Right-hand side y' = r y (1 − y/K). One state component.
let logistic = move |_t: f64, y: &[f64], dy: &mut [f64]| {
    dy[0] = growth_rate * y[0] * (1.0 - y[0] / capacity);
    Ok(())
};
// Independent check: closed-form solution at time t (reference exponential from f64).
let exact = |t: f64| capacity / (1.0 + (capacity / initial - 1.0) * (-growth_rate * t).exp());

// 1. One-shot call. Use DormandPrince5 with default tolerances and return the endpoint state.
let one_shot = solve_ivp(logistic, 0.0, horizon, &[initial])
    .map_err(|e| e.error().to_string())?;
let one_shot_value = one_shot.as_slice()[0];

// 2. Integrator objects. Supply tolerances and the step limit through OdeOptions.
let tol = 10.0_f64.powf(tolerance_exponent);
let budget = Budget::try_from(max_steps as usize).map_err(|e| e.to_string())?;
let options = OdeOptions::new()
    .with_error_tolerance(
        ErrorTolerance::scalar(tol, tol, NormSelection::RootMeanSquare)
            .map_err(|e| e.to_string())?,
    )
    .with_max_steps(budget);
let rhs = OdeFn::new(1, logistic).map_err(|e| e.to_string())?;
let problem = OdeProblem::new(&rhs, horizon);
let initial_state = || OdeState::new(0.0, Vector::from_vec(vec![initial]));
let solutions: [(&str, OdeSolution<f64>); 2] = [
    (
        "DormandPrince5",
        DormandPrince5::new()
            .solve(&problem, &options, initial_state())
            .map_err(|e| e.error().to_string())?,
    ),
    (
        "DormandPrince853",
        DormandPrince853::new()
            .solve(&problem, &options, initial_state())
            .map_err(|e| e.error().to_string())?,
    ),
];

let mut rows = vec![(
    "solve_ivp (default tolerances)".to_string(),
    "ReachedEnd".to_string(),
    horizon,
    one_shot_value,
    (one_shot_value - exact(horizon)).abs(),
    None,
    None,
    None,
)];
for (name, solution) in &solutions {
    let report = solution.report();
    // Even after an early stop, compare with the closed form at the reached time.
    let time = solution.state().time();
    let value = solution.state().values()[0];
    let evaluations = report.counts().total_providers().map_err(|e| e.to_string())?;
    rows.push((
        name.to_string(),
        report.termination().map_or_else(String::new, |t| t.to_string()),
        time,
        value,
        (value - exact(time)).abs(),
        Some(report.accepted_steps()),
        Some(report.rejected_steps()),
        Some(evaluations),
    ));
}
let sig4 = serde_json::json!({ "significantDigits": 4 });
let sig10 = serde_json::json!({ "significantDigits": 10 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "Method" },
    { "key": "1", "label": "Termination" },
    { "key": "2", "label": "Reached time t [days]", "type": "number", "format": sig4 },
    { "key": "3", "label": "y(t) [individuals]", "type": "number", "format": sig10 },
    { "key": "4", "label": "Difference from closed form [individuals]", "type": "number", "format": sci2 },
    { "key": "5", "label": "Accepted steps [count]", "type": "integer", "nullText": "No report" },
    { "key": "6", "label": "Rejected steps [count]", "type": "integer", "nullText": "No report" },
    { "key": "7", "label": "Right-hand-side evaluations [count]", "type": "integer", "nullText": "No report" }
]);
emit_table_with_columns!(columns, rows, metadata = serde_json::json!({ "id": "methods" }));

let all_success = solutions.iter().all(|(_, s)| s.report().is_success());
let first = solutions[0].1.report();
let outcome = if all_success {
    Outcome::satisfied("Both integrator objects reached the endpoint")
        .explanation("Tolerances target local error; check accuracy through differences from the closed form.")
} else {
    Outcome::partial("Stopped before the endpoint at the step limit")
        .explanation("The table gives the state at the last accepted time, rather than at day 20.")
};
emit_outcome!(
    outcome
        .status(first.termination().map_or_else(String::new, |t| t.to_string()))
        .diagnostic("DormandPrince5 reached time", first.final_time(), Some("days"))
);
```

With the default $r = 0.5$ and tolerance $10^{-6}$, all three table rows end at `ReachedEnd`.
The function `solve_ivp` uses default tolerances (relative $10^{-3}$), giving a larger difference from the closed form, $6.6\times10^{-2}$ individuals.
For the integrator objects, `DormandPrince5` accepts 29 steps, rejects two, and evaluates the right-hand side 188 times, giving difference $1.3\times10^{-4}$ individuals; `DormandPrince853` accepts 10, rejects two, and evaluates it 146 times, giving difference $5.4\times10^{-6}$ individuals.
Tightening tolerance to $10^{-12}$ gives $1.8\times10^{-10}$ individuals difference after 2444 evaluations with `DormandPrince5` and $6.8\times10^{-11}$ individuals after 686 evaluations with `DormandPrince853`.
High-order methods gain an evaluation-count advantage under tight tolerances such as these.

Setting the step limit to 10 stops both integrator objects before the endpoint with `BudgetLimit(Proposal)`, giving outcome `partial`.
The method `DormandPrince5` exhausts its 10 attempts at day 4.38 and `DormandPrince853` at day 15.8.
In this case `solve` does not return an error; table values are states at the reached times, both differing from their corresponding closed forms by at most $4\times10^{-5}$ individuals.
In contrast, the one-shot `solve_ivp` returns unsuccessful termination as an error.

## Reading results

Only the report's termination status `report.termination()` (`Option<OdeTermination>`) determines success; `report.is_success()` summarizes it.
Only `ReachedEnd` (reached the endpoint) and `TerminalEvent` (stopped at a terminal event) count as success.
The integrator objects' `solve` and `advance` also return `Ok` at attempt limit `BudgetLimit(Proposal)`, evaluation limit `BudgetLimit(Evaluation)`, minimum step size `StepSizeLimit`, or cancellation `ExecutionStopped`.
Always check the termination status before using values.

Callback errors, allocation failure, and numerical breakdown return `Err`.
The method `solve` and one-shot functions return `PartialFailure`, including the last accepted time and state (`OdeProgress`) if the error occurs after integration begins.
With `advance`, the caller's `OdeState` retains the last accepted point, and the workspace's `last_attempt()` gives the attempt result.
[Solving procedure and result contracts](algorithms/solve-lifecycle-and-contracts/) explains the details.

Tolerances target an estimate of one-step local error; they do not bound global error at the endpoint.
Check using a closed form, conserved quantities, or solutions at different tolerances, as in this cell.
The fields `accepted_steps()` and `rejected_steps()` count accepted and rejected time steps, while `counts()` counts right-hand-side and other callback evaluations.

## Summary

The crate `scioxide-ode` centers on initial value problems and also handles DAEs, DDEs, SDEs, Hamiltonian systems, two-point boundary value problems, and solution derivatives (forward sensitivities and adjoints).
Use `solve_ivp` when only the endpoint value at default settings is needed; use integrator objects and `OdeOptions` for configurable tolerances, output, limits, or workspace reuse.
For integrator-object results, first check success with `report.is_success()`, then compare the approximate values, based on error estimates, with closed forms or independent computations.
Continue to [Choosing a method](choosing/) to select a method.
Continue to [Error, order, and stability](algorithms/error-order-and-stability/) to examine how tolerances relate to global error.
