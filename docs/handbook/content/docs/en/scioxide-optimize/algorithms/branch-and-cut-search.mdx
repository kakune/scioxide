Branch-and-cut trees can grow exponentially in the worst case, so practical searches limit nodes or memory and extract useful information even when stopped at a limit.
This page explains `BranchAndBound` limits, search state (`MipSearchState`, `MipNode`), work counting (`MipStatistics`), and replacement relaxation solvers (`MipRelaxationSolver`).
Branching rules, cutting planes, and gap definitions are in [Mixed-integer programming and branch and cut](../mixed-integer-programming/).

## Limits and optional work

Defaults for `BranchAndBound` follow; all setting methods are infallible.

| Setting | Default | Meaning |
|---|---|---|
| `with_max_nodes` | 1000 | Processed nodes (including root) |
| `with_max_lp_iterations` | 1000 | Pivots per relaxation solve (including repair) |
| `with_integrality_tolerance` | $\sqrt{\epsilon}$ | Distance treated as integral |
| `with_relaxation_tolerances` | $10^{-8}$ per role | Relaxation and gap tolerances |
| `with_branching` | `Reliability` | Branching rule |
| `with_presolve` | `true` | Root preprocessing |
| `with_limits` | `MipLimits::default()` | Memory and optional-work limits |

`MipLimits` allows 1000 pending nodes (excluding the node being processed), depth 1000 (root 0), 64 MiB for search tree and scratch arrays (`max_search_bytes`), and 64 MiB per relaxation solve (`max_relaxation_bytes`).
Optional-work limits also include 128 added cuts and 8192 nonzero coefficients, 2 cut rounds per node, 4 strong-branching candidates and 32 pivots, 2 observations before trusting pseudocosts, and repair enabled by default.
Setting an optional-work limit to 0 disables that work.
Reaching limits stops with `NodeLimit` for node count, `DepthLimit` for depth, and `MemoryLimit` for pending-node count or memory; none is successful.

## Search state and work

`BranchAndBoundWorkspace` created by `BranchAndBound::workspace(&problem)` holds the relaxation solver and search state.
After solving with `solve_into`, read even limit-stopped search state from `MipSearchState` returned by `BranchAndBoundWorkspace::state()`.

- `open_nodes()` contains pending nodes in storage order, not processing order.
- `incumbent()` and `incumbent_objective()` are the incumbent and its objective recomputed in the original problem.
- `active_node()` is the node being processed when a limit stopped the search.
- `presolve_map()` is the preprocessing map, becoming `Some` after preprocessing finishes.
- `cut_provenance(node)` returns cut types (`MipCutKind`) effective at a pending or active node and original row indices in the preprocessed model.
  Other nodes give `InvalidInput`; map row indices back to original rows with `MipPresolveMap::original_rows`.

`MipNode` is a node; `id()` its creation index, `depth()` depth with root 0, and `lower_bound()` a lower bound from its own or its parent's relaxation.
Result `global_lower_bound()` is the global lower bound: the minimum of bounds on pending nodes (also the active node on limit stops), tolerance-pruned nodes, and the incumbent objective.
If pending nodes without known bounds remain, it is `None`.
Even successful searches can leave `open_nodes()` nonempty because nodes whose bounds reach the incumbent within tolerance need not be processed.

`MipStatistics` records search work, obtained from `MipResult::statistics()` or `MipSearchState::statistics()`.
`nodes()` counts processed nodes (excluding strong-branching probes), `relaxations()` LP relaxation solves including probes and repair, `iterations()` all relaxation pivots and bound flips, and `probes()` strong-branching probes (one per direction).
`cuts()` and `cut_nonzeros()` count added cuts and nonzero coefficients; `repairs()` counts rounding and fixing repair attempts; `basis_reuses()` counts relaxation solves starting from the preceding basis; `peak_search_bytes()` is peak search-tree memory compared with `max_search_bytes`.

Every solve starts a new search.
No API supplies the previous search tree or incumbent as the next solve's initial state (MIP warm start).
Given an integer solution, add a row bounding the objective by its value to exclude worse regions.

## Replacing the relaxation solver

`BranchAndBound::workspace` uses `SimplexSolver` for relaxations.
Its workspace `MipSimplexWorkspace` fixes objective and rows during preparation, changes only variable bounds per node, and reoptimizes from the preceding basis.
The basis uses dense LU; constraint rows supplied as CSR remain sparse.

`BranchAndBoundWorkspace::new(relaxation)` incorporates a custom `MipRelaxationSolver`.
This trait has four methods.

- `workspace_bytes(p)`: return an upper bound on workspace and solution memory.
- `workspace(p)`: construct workspace with fixed objective and rows.
- `reused_basis(w)`: report whether the solve started from the preceding solve's recorded basis.
- `solve_into(p, w, output, iterations, max_workspace_bytes, context)`: solve an LP differing only in bounds within pivot and memory limits.

Search checks the relaxation's point, objective, and certificates against the original problem, preventing incorrect relaxation results from producing incorrect optimality claims.
If the relaxation solver's point or objective is nonfinite or inconsistent with the problem, `BranchAndBound::solve_into` returns `InvalidInput`.
Tree search remains sequential even with a parallel executor in the execution context.

## A node-limited search

Solve a $n=20$-item 0–1 knapsack problem with varying node limits.
Item $j$ has integer weight $w_j$ from 10–60 kg generated from a seed and value $v_j=w_j+10$ points; capacity is half total weight, rounded down.
Maximize $\sum_jv_jx_j$ subject to $\sum_jw_jx_j\le C$ and $x_j\in\{0,1\}$ (mapped to minimization of $-\mathbf{v}$).
Knapsack problems whose values equal weights plus a constant are called strongly correlated and are known as difficult branch-and-bound examples (Kellerer, Pferschy and Pisinger, 2004).
The LP-relaxation upper bound is close to the integer optimum, but closing the gap requires many nodes.
As an independent check, use integer weights to compute an exact optimum by dynamic programming.
Inputs are the processed-node limit and random seed.
The table gives termination, incumbent value, search upper bound (negated `global_lower_bound()`), dynamic-programming optimum, pending nodes, and work counts.

```rust
//| id: optimize-mip-search-state
//| ref: optimize-mip-search-state
//| title: "Compare node-limited branch-and-cut incumbents and upper bounds with exact solutions"
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg, scioxide-optimize, scioxide-random]
//| inputs:
//|   max_nodes: {"type":"range","label":"Processed-node limit [count]","min":5,"max":300,"step":5,"value":50}
//|   seed: {"type":"range","label":"Random seed [-]","min":1,"max":10,"step":1,"value":1}
//| cases:
//|   - {"id":"enough-nodes","label":"Node limit 200","description":"Search stops with Converged and the incumbent matches the dynamic-programming optimum 487. Pending nodes remain, but their lower bounds reach the incumbent.","inputs":{"max_nodes":200}}
//|   - {"id":"few-nodes","label":"Node limit 5","description":"Stops with NodeLimit and a large incumbent/upper-bound gap. The upper bound stays above the optimum.","inputs":{"max_nodes":5}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"search","path":"/rows/0/0","equals":"NodeLimit"}
//|       - {"artifact":"search","path":"/rows/0/4","equals":487}
//|       - {"artifact":"search","path":"/rows/0/6","range":{"min":0}}
//|       - {"artifact":"search","path":"/rows/0/5","range":{"min":0}}
//|       - {"path":"/outputs/2/state","equals":"partial"}
//|   - case: enough-nodes
//|     expect:
//|       - {"artifact":"search","path":"/rows/0/0","equals":"Converged"}
//|       - {"artifact":"search","path":"/rows/0/1","approx":{"value":487,"atol":1e-9}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: few-nodes
//|     expect:
//|       - {"artifact":"search","path":"/rows/0/0","equals":"NodeLimit"}
//|       - {"artifact":"search","path":"/rows/0/6","range":{"min":0}}
use scioxide_core::{Bounds, Budget, ExecutionContext};
use scioxide_linalg::Matrix;
use scioxide_optimize::{BranchAndBound, LinearConstraints, LpProblem, MipProblem, MipResult};
use scioxide_random::{SeedableRng, Xoshiro256StarStar, uniform_index};

let fixed2 = serde_json::json!({ "fractionDigits": 2 });
let n = 20;
let mut rng = Xoshiro256StarStar::from_seed(seed.round() as u64);
let mut weight = Vec::with_capacity(n);
for _ in 0..n {
    weight.push(10 + uniform_index(51, &mut rng).map_err(|e| e.to_string())?);
}
let value: Vec<usize> = weight.iter().map(|&w| w + 10).collect();
let capacity = weight.iter().sum::<usize>() / 2;
// Independent check: integer weights allow dynamic programming for maximum value at each capacity.
let mut best = vec![0_usize; capacity + 1];
for (&w, &v) in weight.iter().zip(&value) {
    for c in (w..=capacity).rev() {
        best[c] = best[c].max(best[c - w] + v);
    }
}
let optimum = best[capacity];
let row = Matrix::from_vec(1, n, weight.iter().map(|&w| w as f64).collect())
    .map_err(|e| e.to_string())?;
let lp = LpProblem::new(value.iter().map(|&v| -(v as f64)).collect())
    .and_then(|p| {
        p.with_constraints(LinearConstraints::less_equal(row, vec![capacity as f64])?)
    })
    .and_then(|p| p.with_bounds(Bounds::new(vec![(Some(0.0), Some(1.0)); n])?))
    .map_err(|e| e.to_string())?;
let problem = MipProblem::new(lp, (0..n).collect()).map_err(|e| e.to_string())?;
let limit = Budget::try_from(max_nodes.round() as usize).map_err(|e| e.to_string())?;
let solver = BranchAndBound::default().with_max_nodes(limit);
let mut workspace = solver.workspace(&problem).map_err(|e| e.to_string())?;
let mut result = MipResult::empty();
solver
    .solve_into(
        &problem,
        &mut result,
        &mut workspace,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;
let state = workspace.state();
// Convert minimization bounds back to profit. None without an incumbent.
let incumbent = state.incumbent_objective().map(|f| -f);
let upper = result.global_lower_bound().map(|b| -b);
let search = vec![(
    result.termination().to_string(),
    incumbent,
    upper,
    result.absolute_gap(),
    optimum,
    incumbent.map(|f| optimum as f64 - f),
    upper.map(|u| u - optimum as f64),
)];
let columns = serde_json::json!([
    { "key": "0", "label": "Termination reason" },
    { "key": "1", "label": "Incumbent value [points]", "type": "number", "format": fixed2, "nullText": "None" },
    { "key": "2", "label": "Search upper bound [points]", "type": "number", "format": fixed2, "nullText": "None" },
    { "key": "3", "label": "Reported absolute gap [points]", "type": "number", "format": fixed2, "nullText": "None" },
    { "key": "4", "label": "Dynamic-programming optimum [points]", "type": "integer" },
    { "key": "5", "label": "Optimum − incumbent [points]", "type": "number", "format": fixed2, "nullText": "None" },
    { "key": "6", "label": "Upper bound − optimum [points]", "type": "number", "format": fixed2, "nullText": "None" }
]);
emit_table_with_columns!(
    columns,
    search,
    metadata = serde_json::json!({ "id": "search" })
);
let open = state.open_nodes();
let deepest = open.iter().map(|node| node.depth()).max();
let mut cuts_in_open_nodes = 0;
for node in open {
    cuts_in_open_nodes += state
        .cut_provenance(node)
        .map_err(|e| e.to_string())?
        .count();
}
let stats = result.statistics();
let work_columns = serde_json::json!([
    { "key": "0", "label": "Processed nodes [count]", "type": "integer" },
    { "key": "1", "label": "Pending nodes [count]", "type": "integer" },
    { "key": "2", "label": "Maximum pending-node depth [-]", "type": "integer", "nullText": "None" },
    { "key": "3", "label": "LP relaxation solves [count]", "type": "integer" },
    { "key": "4", "label": "Strong-branching probes [count]", "type": "integer" },
    { "key": "5", "label": "Added cuts [count]", "type": "integer" },
    { "key": "6", "label": "Total cuts effective across pending nodes [count]", "type": "integer" },
    { "key": "7", "label": "Repairs [count]", "type": "integer" }
]);
emit_table_with_columns!(
    work_columns,
    vec![(
        stats.nodes(),
        open.len(),
        deepest,
        stats.relaxations(),
        stats.probes(),
        stats.cuts(),
        cuts_in_open_nodes,
        stats.repairs()
    )],
    metadata = serde_json::json!({ "id": "work" })
);
let outcome = if result.is_success() {
    Outcome::satisfied("Search stopped with the gap within tolerance")
} else if result.has_incumbent() {
    Outcome::partial("Stopped at a limit. Compare incumbent/upper-bound gap with application tolerance")
} else {
    Outcome::failed("Search stopped without an incumbent")
};
let mut outcome = outcome.status(result.termination().to_string()).diagnostic(
    "Processed nodes",
    stats.nodes() as f64,
    None,
);
if let Some(gap) = result.absolute_gap() {
    outcome = outcome.diagnostic("Absolute gap", gap, None);
}
emit_outcome!(outcome);
```

At default limit 50 nodes, search stops with `NodeLimit` and outcome partial.
The incumbent value is 485 points, search upper bound 487.82, and reported absolute gap 2.82.
The dynamic-programming optimum 487 points is 2 above the incumbent and 0.82 below the upper bound, lying between the returned bounds.
There are 46 pending nodes (maximum depth 9) and 61 added cuts.

With limit 200, `Converged` is reached after 113 nodes and the incumbent matches optimum 487.
Even then 47 pending nodes remain, but their bounds reach the incumbent within tolerance and need no processing.
With limit 5, the incumbent is 483 and upper bound 488.30; only 4 points of the 5.30-point gap are actual possible improvement.
Search is deterministic, so increasing the node limit follows the same initial search; the incumbent never decreases and upper bound never increases.
Both bounds approach while continuing to bracket the optimum.

## Summary

`BranchAndBound` limits nodes, depth, pending nodes, and memory; limit-stopped search is unsuccessful but exposes an incumbent and global lower bound.
For limit-stopped results, the incumbent-objective/lower-bound difference bounds improvements available from unexplored subtrees.
Read pending and active nodes, preprocessing maps, and per-node cut provenance from `BranchAndBoundWorkspace::state()` and inspect work with `MipStatistics`.
To solve relaxations with a custom solver, implement and install `MipRelaxationSolver`; search checks its results against the original problem too.
There is no warm start carrying over the previous search, so each solve begins a new search.
