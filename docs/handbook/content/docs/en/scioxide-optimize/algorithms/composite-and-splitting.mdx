Consider minimizing $F(x)=f(x)+g(x)$.
Assume $f$ is smooth with a Lipschitz gradient ($\|\nabla f(x)-\nabla f(z)\|\le L_f\|x-z\|$).
$g$ may have nondifferentiable points, provided its proximal map in the next section is computable.
For example, $\ell_1$ regularization $\lambda\|x\|_1$ is nondifferentiable at zero but has a componentwise proximal formula.
For convergence discussions, assume $f$ and $g$ convex and $g$ proper closed convex (finite somewhere, never $-\infty$, and lower semicontinuous).
When a proximal map has no closed form, as in $g(Dx)$ evaluating $g$ after a linear map, split variables and use [ADMM](../admm-splitting/).

## Deriving the proximal map

If $L\ge L_f$ bounds the Lipschitz constant of $\nabla f$, use the quadratic upper bound

$$
f(z)\le f(x)+\nabla f(x)^T(z-x)+\frac L2\|z-x\|^2
$$

shown above.
Minimizing this bound plus $g(z)$ over $z$ gives

$$
x^+=\operatorname{prox}_{g/L}(x-\nabla f(x)/L),\qquad
\operatorname{prox}_{tg}(v)=\arg\min_z\left(g(z)+\frac{\|z-v\|^2}{2t}\right)
$$

That is, take a step of size $1/L$ using the gradient of $f$, then apply the proximal map of $g$.
For $g(z)=\lambda\|z\|_1$, separating positive, negative, and zero cases componentwise gives $\operatorname{sign}(v_i)\max(|v_i|-t\lambda,0)$.
This is soft thresholding.
If $g$ is the indicator of convex set $C$ (0 on $C$, $+\infty$ outside), its proximal map projects onto $C$, giving componentwise clipping for box constraints.
$\operatorname{prox}_{tg}$ is nonexpansive ($\|\operatorname{prox}(u)-\operatorname{prox}(v)\|\le\|u-v\|$), so it does not amplify input rounding errors.

In the API, `SmoothGradient` supplies values and gradients of $f$, `ProximalMap` supplies the proximal map, and `CompositeProblem::new(&smooth, &prox)` borrows both.
`ProximalMap::apply_into(point, step, output)` writes $\operatorname{prox}_{\text{step}\cdot g}(\text{point})$; the solver passes $1/L$ to `step`.
Vanishing of the stopping gradient mapping $G_L(x)=L(x-x^+)$ is equivalent to composite stationarity $0\in\nabla f(x)+\partial g(x)$.

## Proximal-gradient convergence and stopping

Proximal gradient repeats $x_{k+1}=\operatorname{prox}_{g/L}(x_k-\nabla f(x_k)/L)$.
Each iteration uses one value of $f$, one gradient of $f$, and one proximal map.
If $f,g$ is convex with minimizer $x^*$, $F(x_k)-F(x^*)\le L\|x_0-x^*\|^2/(2k)$ holds (Beck and Teboulle, 2009).
If $f$ has strong convexity constant $\mu$, iterate error $\|x_k-x^*\|$ converges linearly with ratio $1-\mu/L$.
Thus overestimating $L$ shortens steps and slows convergence.

`ProximalOptions::new(L)` uses fixed $L$ without checking the upper bound by default.
At $L<L_f$ the bound need not hold; excessive steps can cause oscillation or divergence.
If $L_f$ is unknown, enable upper-bound checks (backtracking) with `with_backtracking(growth, trials)`.
Check $f(x^+)\le f(y)+\nabla f(y)^T(x^+-y)+\frac L2\|x^+-y\|^2$ at trial point $x^+$; if it fails, multiply $L$ by `growth` (finite and greater than 1) and retry from the proximal map.
Nonfinite $f(x^+)$ and trial coordinates unrepresentable in floating point are also treated as failed bounds.
If `trials` trials in one iteration find no acceptable point, or the next $L$ is unrepresentable, stop with `Stagnation`.
With backtracking, each trial adds one value evaluation of $f$.
$L$ carries across iterations and only increases.

Stop when the gradient-mapping maximum norm $\|G_L\|_\infty=L\|x^+-y\|_\infty$ is at most the `GradientTolerance` threshold, with reason `Converged`.
$y$ is the point starting the gradient step: $x_k$ for proximal gradient, the next section's extrapolated point for FISTA.
Default thresholds use absolute and relative $\sqrt{\varepsilon}$ at scale 1, giving $2\sqrt{\varepsilon}\approx2.98\times10^{-8}$ for `f64`.
The outer-iteration limit defaults to 1000 (change with `with_max_iterations`); reaching it gives `IterationLimit`.
If rounding returns the smooth step to $y$ and the proximal map also leaves it unchanged while gradient components exceed tolerance, stop with `Stagnation` rather than declaring stationarity.
Nonfinite $f(y)$, gradients, or proximal values give error `NonFinite`, not a termination reason.

`ProximalResult` returns last accepted point `x()`, `mapping_norm()`, final-iteration `lipschitz()`, `iterations()`, `restarts()`, `termination()`, and `counts()`, but not objective $F(x)$.
If needed, compute $f(x)+g(x)$ on the caller side.
`mapping_norm()` is `None` if no iteration finished.
`is_success()` is true only for `Converged`; `IterationLimit` and `Stagnation` also return the last accepted point.
`mapping_norm()` estimates stationarity and does not certify an objective gap.

## FISTA acceleration

FISTA uses the preceding displacement to create extrapolated point $y_k$ and takes a proximal-gradient step there.
Acceleration uses $t_0=1$, $t_{k+1}=(1+\sqrt{1+4t_k^2})/2$, with extrapolation $y_{k+1}=x_{k+1}+\frac{t_k-1}{t_{k+1}}(x_{k+1}-x_k)$.
Under convexity, Lipschitz gradients, exact proximal maps, and related assumptions, this basic form's objective error is bounded by $2L\|x_0-x^*\|^2/(k+1)^2=O(k^{-2})$.
This is faster than ordinary proximal gradient's $O(k^{-1})$, but objective values need not decrease monotonically at individual finite-precision iterations.

`Fista` defaults to gradient-based restart (O'Donoghue and Candès, 2015).
Since $y_k-x_{k+1}=G_L(y_k)/L$, $\langle y_k-x_{k+1},\,x_{k+1}-x_k\rangle>0$ means the preceding displacement makes an acute angle with the gradient mapping and acceleration acted toward increasing objective.
Then reset to $y_{k+1}=x_{k+1}$ and $t_{k+1}=1$.
On strongly convex problems, restarts recover linear convergence speed.
Read restart counts with `ProximalResult::restarts()`; select the basic form with `with_restart(false)`.
Per-iteration evaluation counts and errors match `ProximalGradient`.

`minimize(&problem, &x0)` allocates workspace and results per call.
For repeated same-dimension solves, query requirements with `workspace_requirements(n)` and reuse `ProximalWorkspace` and `ProximalResult::empty()` through `minimize_into`.
`ProximalWorkspaceRequirements` returned by `workspace_requirements(n)` holds dimension `dimension()` and bytes `bytes()` for seven times that many components.
An error from `minimize_into` leaves output results unchanged.
`ProximalWorkspace` records the last call; `ProximalProgress` returned by `progress()` of `last_attempt()` exposes iterations through the accepted point, `iterations()`, and last gradient mapping `mapping_norm()`.

## Checking soft thresholding

Solve $\tfrac12(x-a)^2+\lambda|x|$ with `ProximalGradient` and `Fista`.
The analytical solution is soft threshold $S_\lambda(a)=\operatorname{sign}(a)\max(|a|-\lambda,0)$.
The function $f$ has gradient Lipschitz constant $L_f=1$ and strong convexity constant $\mu=1$, so $L=1$ makes proximal gradient reach the analytical solution in its first iteration.
Inputs are $a$, $\lambda$, initial $L$, and backtracking choice.
$L>1$ shortens step $1/L$, while $L<1$ gives an excessively long step violating the bound.
Outputs include a table of both solutions, differences from analytical solutions computed with inherent f64 methods in the cell, iterations, restarts, final $L$, gradient-mapping norms, and termination; the outcome combines both methods' statuses.

// f(x) = ½(x − a)². ∇f has Lipschitz constant 1.
struct Quadratic(f64);
impl SmoothGradient<f64> for Quadratic {
    fn dimension(&self) -> usize {
        1
    }
    fn value(&self, x: &[f64]) -> Result<f64, SciOxideError> {
        let residual = x[0] - self.0;
        Ok(0.5 * residual * residual)
    }
    fn gradient_into(&self, x: &[f64], out: &mut [f64]) -> Result<(), SciOxideError> {
        out[0] = x[0] - self.0;
        Ok(())
    }
}

        let shrunk = RealScalar::max(NumericScalar::abs(x[0]) - step * self.0, 0.0);
        out[0] = RealScalar::copysign(shrunk, x[0]);
        Ok(())
    }

At default $a=2$, $\lambda=0.5$, and $L=1$, both methods match analytical solution 1.5 on the first iteration.
The second iteration has zero gradient mapping and stops with `Converged`.
Overestimating as $L=10$ makes the step 1/10; proximal-gradient error contracts by $1-\mu/L=0.9$ and stops after 170 iterations, while FISTA takes 33 including 2 restarts.
Contracting from $1.5$ to threshold $3\times10^{-8}$ requires $\ln(5\times10^7)/\ln(1/0.9)\approx168$ iterations, consistent with the strongly convex linear-rate estimate.
Analytical-solution differences are $2.5\times10^{-8}$ and $1.6\times10^{-8}$; for this $\mu=1$ problem, solution error is of the same order as the gradient-mapping norm.
At $\lambda=2.5>|a|$ the first proximal map gives solution 0.

At $L=0.5$ without backtracking, step $2$ violates bound $f(x^+)\le f(y)+\nabla f(y)^T(x^+-y)+\frac L2\|x^+-y\|^2$.
Proximal-gradient iterates alternate between $x=0$ and $x=3$, with gradient mapping unchanged at $0.5\times3=1.5$.
The 1000-iteration limit gives `IterationLimit` and returned $x=0$ is 1.5 from the analytical solution.
FISTA diverges until $f$ becomes nonfinite, returning error `NonFinite`.
Because a method returns no iterate, the outcome is failed.
With backtracking, $f(x^+)=0.5$ exceeds upper-bound value $-1.75$ on the first trial, raising $L$ to 1; subsequent iterations match the $L=1$ case.
The table's “Final L” of 1 confirms backtracking increased $L$.

## Choosing a solver

`ProximalGradient` implements basic proximal gradient; `Fista` adds extrapolation and restarts.
With a closed-form proximal map for $g$, try `Fista` first and compare iterations and restarts with `ProximalGradient`.
If no upper bound for $L_f$ is known, enable backtracking and inspect the final $L$ through result `lipschitz()`.
When a linear map prevents a closed-form proximal map, as in $g(Dx)$, split as $z=Dx$ and use [ADMM](../admm-splitting/).

## Summary

Separating nonsmooth terms into proximal maps solves objectives with nondifferentiable points through repeated gradient steps and proximal maps.
Proximal-gradient step size is $1/L$; overestimating $L$ slows convergence, while values below $L_f$ can oscillate or diverge, so check unknown bounds with `with_backtracking`.
FISTA acceleration assumes convexity and related conditions; interpret extrapolation with gradient-mapping norms, iterations, and restarts.
Termination reasons other than `Converged` also return the last accepted point; assess it with `is_success()` before using it as a minimizer.
Results omit objective values, so compute $f(x)+g(x)$ on the caller side.
