[First-order methods, nonlinear conjugate gradients and quasi-Newton methods](../first-order-and-quasi-newton/) derived that the iteration count is proportional to the condition number $\kappa$ for steepest descent and to $\sqrt{\kappa}$ for conjugate gradients, while learning curvature weakens this dependence in quasi-Newton methods.
This page runs the four methods with the same settings on quadratic functions that differ only in eigenvalue spread, and examines their differences through iteration and evaluation counts.

## Theoretical convergence rates

For the quadratic function $f(\mathbf{x}) = \tfrac12\mathbf{x}^\mathsf{T}\mathbf{A}\mathbf{x}$ (with positive-definite $\mathbf{A}$ and condition number $\kappa$), the minimum is 0, and the objective itself is half the squared energy norm of the error.
Steepest descent with an exact line search multiplies the objective by at most $r = ((\kappa - 1)/(\kappa + 1))^2$ in one iteration (Kantorovich's inequality).
In conjugate gradients, the energy norm of the error contracts by a factor of at most $2((\sqrt\kappa - 1)/(\sqrt\kappa + 1))^k$, and exact arithmetic gives termination within $n$ iterations.
BFGS with an exact line search also terminates within $n$ iterations on a quadratic function, but SciOxide's default line search is inexact, so this finite termination property does not hold.
All these bounds assume an exact line search and therefore do not bound iteration counts with SciOxide's default settings.

## Comparing four methods

Consider the quadratic function $f(\mathbf{x}) = \frac{1}{2}\sum_i \lambda_i x_i^2$ in $n=20$ variables.
Arrange its eigenvalues $\lambda_i=\kappa^{i/(n-1)}$ ($i=0,\dots,19$) geometrically from 1 to $\kappa$, making the Hessian condition number equal to the input $\kappa$.
Minimize from $(1,\dots,1)$ using default `GradientDescent`, `NonlinearCg`, `Bfgs` and `Lbfgs` ($m = 10$) settings, and compare the objective histories.
Construct each history from final values of independent runs with iteration limits $k = 1, 2, \dots, 400$, and stop the method's series when it succeeds.
A run that reaches the limit terminates with `IterationLimit` and returns its last accepted point, whose objective is therefore the value after $k$ iterations.
The dashed line plots the worst-case bound $f_k\le r^k f_0$ for steepest descent with an exact line search, evaluated directly from the formula for comparison.
The table gives each method's termination reason, iteration and evaluation counts, final objective, distance from the origin, curvature update breakdown (damped and skipped) or restart count, and number of zero-objective points omitted from the logarithmic axis, all with an iteration limit of 1000.
All four use the stopping test `GradientSmall` based on the gradient 2-norm and the default tolerances (both absolute and relative $\sqrt{\varepsilon_{\mathrm{mach}}}$).
The final cell outcome follows the termination reason of `Bfgs`.

```rust
//| id: optimize-bfgs-condition
//| ref: optimize-bfgs-condition
//| title: "Vary the condition number and compare convergence of steepest descent, conjugate gradients, BFGS and L-BFGS"
//| run: reactive
//| crates: [scioxide-core, scioxide-optimize]
//| inputs:
//|   condition_number: {"type":"range","label":"Hessian condition number κ [-]","description":"Vary the eigenvalue spread of the quadratic function.","min":2,"max":10000,"step":2,"value":400}
//| cases:
//|   - {"id":"kappa-2","label":"κ = 2","description":"The eigenvalues are nearly equal, and all four methods reach GradientSmall in 11–12 iterations.","inputs":{"condition_number":2}}
//|   - {"id":"kappa-10000","label":"κ = 10⁴","description":"GradientDescent stops at the 1000-iteration limit with IterationLimit (objective 8.9×10⁻¹¹); Bfgs, NonlinearCg and Lbfgs reach GradientSmall in 139, 247 and 758 iterations, respectively.","inputs":{"condition_number":10000}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"methods","path":"/rows/0/1","equals":"GradientSmall"}
//|       - {"artifact":"methods","path":"/rows/1/1","equals":"GradientSmall"}
//|       - {"artifact":"methods","path":"/rows/2/1","equals":"GradientSmall"}
//|       - {"artifact":"methods","path":"/rows/3/1","equals":"GradientSmall"}
//|       - {"artifact":"methods","path":"/rows/2/6","range":{"min":0,"max":1e-7}}
//|       - {"artifact":"methods","path":"/rows/0/9","equals":0}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: kappa-2
//|     expect:
//|       - {"artifact":"methods","path":"/rows/0/2","range":{"min":9,"max":15}}
//|       - {"artifact":"methods","path":"/rows/1/2","range":{"min":9,"max":15}}
//|       - {"artifact":"methods","path":"/rows/2/2","range":{"min":9,"max":15}}
//|       - {"artifact":"methods","path":"/rows/3/2","range":{"min":9,"max":15}}
//|   - case: kappa-10000
//|     expect:
//|       - {"artifact":"methods","path":"/rows/0/1","equals":"IterationLimit"}
//|       - {"artifact":"methods","path":"/rows/0/2","equals":1000}
//|       - {"artifact":"methods","path":"/rows/0/5","range":{"min":1e-12,"max":1e-7}}
//|       - {"artifact":"methods","path":"/rows/1/1","equals":"GradientSmall"}
//|       - {"artifact":"methods","path":"/rows/2/1","equals":"GradientSmall"}
//|       - {"artifact":"methods","path":"/rows/3/1","equals":"GradientSmall"}
use scioxide_core::{Budget, RealScalar};
use scioxide_optimize::{
    Bfgs, BfgsOptions, GradientDescent, GradientDescentOptions, Lbfgs, LbfgsOptions,
    NonlinearCg, NonlinearCgOptions, ObjectiveFn, OptimizeDiagnostics, OptimizeResult,
    OptimizeTermination,
};

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
// f(x) = ½ Σ λᵢ xᵢ², with eigenvalues λᵢ = κ^{i/(n−1)} arranged geometrically from 1 to κ.
let n = 20_usize;
let kappa = condition_number;
let lambda: Vec<f64> = (0..n)
    .map(|i| RealScalar::powf(kappa, i as f64 / (n - 1) as f64))
    .collect();
let (lv, lg) = (lambda.clone(), lambda.clone());
let objective = ObjectiveFn::new(n, move |x: &[f64]| {
    Ok(0.5 * x.iter().zip(&lv).map(|(v, l)| l * v * v).sum::<f64>())
})
.with_gradient(move |x: &[f64], g: &mut [f64]| {
    for ((gi, v), l) in g.iter_mut().zip(x).zip(&lg) {
        *gi = l * v;
    }
    Ok(())
});
let start = vec![1.0_f64; n];
let initial = 0.5 * lambda.iter().sum::<f64>();
// Solve with method and iteration limit k. A run that reaches the limit returns the last accepted point.
let run = |method: usize, k: usize| -> Result<OptimizeResult<f64>, String> {
    let budget = Budget::try_from(k).map_err(|e| e.to_string())?;
    match method {
        0 => {
            GradientDescent::new(GradientDescentOptions::default().with_max_iterations(budget))
                .minimize(&objective, &start)
        }
        1 => NonlinearCg::new(NonlinearCgOptions::default().with_max_iterations(budget))
            .minimize(&objective, &start),
        2 => Bfgs::new(BfgsOptions::default().with_max_iterations(budget))
            .minimize(&objective, &start),
        _ => Lbfgs::new(LbfgsOptions::default().with_max_iterations(budget))
            .minimize(&objective, &start),
    }
    .map_err(|e| e.to_string())
};
let mut limits: Vec<usize> = (1..=10).collect();
while *limits.last().unwrap_or(&1) < 400 {
    let last = *limits.last().unwrap_or(&1);
    limits.push((last + (last / 8).max(1)).min(400));
}
let names = ["GradientDescent", "NonlinearCg", "Bfgs", "Lbfgs"];
let mut series = Vec::new();
let mut rows = Vec::new();
let mut bfgs = None;
for (method, name) in names.iter().enumerate() {
    let mut points = vec![[0.0, initial]];
    let mut dropped = 0_usize;
    let mut last = None;
    for &k in &limits {
        let result = run(method, k)?;
        // Omit zero-objective points, which cannot appear on a logarithmic axis, and report their count in the table.
        if result.fun() > 0.0 {
            points.push([k as f64, result.fun()]);
        } else {
            dropped += 1;
        }
        let success = result.is_success();
        last = Some(result);
        // Once a run succeeds before its limit, increasing the limit does not change its result.
        if success {
            break;
        }
    }
    series.push(serde_json::json!({ "name": name, "points": points }));
    // The table shows results for an iteration limit of 1000. Reuse runs that have already succeeded.
    let result = match last {
        Some(result) if result.is_success() => result,
        _ => run(method, 1000)?,
    };
    let distance = RealScalar::sqrt(result.x().iter().map(|v| v * v).sum::<f64>());
    // Counts of damped and skipped curvature updates (quasi-Newton methods), or restarts (conjugate gradients).
    let (curvature, restarts) = match result.method_diagnostics() {
        OptimizeDiagnostics::FirstOrder(d) if method >= 2 => {
            (Some(d.damped_updates() + d.skipped_updates()), None)
        }
        OptimizeDiagnostics::FirstOrder(d) if method == 1 => (None, Some(d.restarts())),
        _ => (None, None),
    };
    rows.push((
        name.to_string(),
        result.termination().to_string(),
        result.iterations(),
        result.fun_evals(),
        result.grad_evals(),
        result.fun(),
        distance,
        curvature,
        restarts,
        dropped,
    ));
    if method == 2 {
        bfgs = Some(result);
    }
}
// Formula for comparison: Kantorovich's worst-case bound f_k ≤ r^k f_0 for steepest descent with an exact line search.
let rate = RealScalar::powi((kappa - 1.0) / (kappa + 1.0), 2);
let bound: Vec<[f64; 2]> = (0..=400)
    .step_by(4)
    .map(|k| [k as f64, initial * RealScalar::powi(rate, k)])
    .filter(|p| p[1] > 0.0)
    .collect();
series.push(serde_json::json!({
    "name": "Worst-case bound for steepest descent (exact line search)",
    "points": bound,
    "style": { "lineType": "dashed" }
}));
emit_line_chart!(
    &series,
    options = &serde_json::json!({
        "xLabel": "Iteration limit k [iterations]",
        "yLabel": "Objective f(x_k) after k iterations [-]",
        "yType": "log",
        "xMin": 0.0,
        "xMax": 400.0,
        "yMin": 1.0e-30
    })
);
let columns = serde_json::json!([
    { "key": "0", "label": "Method" },
    { "key": "1", "label": "Termination reason" },
    { "key": "2", "label": "Iterations [count]", "type": "integer" },
    { "key": "3", "label": "Objective evaluations [count]", "type": "integer" },
    { "key": "4", "label": "Gradient evaluations [count]", "type": "integer" },
    { "key": "5", "label": "Final objective [-]", "type": "number", "format": sci3 },
    { "key": "6", "label": "Distance from origin [-]", "type": "number", "format": sci3 },
    { "key": "7", "label": "Damped or skipped updates [count]", "type": "integer", "nullText": "—" },
    { "key": "8", "label": "Restarts [count]", "type": "integer", "nullText": "—" },
    { "key": "9", "label": "Points omitted from chart [count]", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "methods" })
);
// Use BFGS's termination reason as the cell conclusion.
let result = bfgs.ok_or("No BFGS result")?;
let outcome = if result.is_success() {
    Outcome::satisfied("The BFGS gradient norm fell below the tolerance")
} else if matches!(
    result.termination(),
    OptimizeTermination::LineSearchFailed(_)
) {
    Outcome::failed("The BFGS line search did not accept a step length")
} else {
    Outcome::partial("BFGS reached its limit and returned the last accepted point")
};
emit_outcome!(
    outcome
        .status(result.termination().to_string())
        .diagnostic("Iterations", result.iterations() as f64, None)
        .diagnostic("Final objective", result.fun(), None)
);
```

At the default $\kappa = 400$, all four methods terminate with `GradientSmall`: `GradientDescent` takes 275 iterations, `NonlinearCg` 64, `Bfgs` 94 and `Lbfgs` 157.
The evaluation counts are 330 objective and 276 gradient evaluations for `GradientDescent`, 272 of each for `NonlinearCg`, 101 of each for `Bfgs`, and 173 of each for `Lbfgs`.
Using the strong Wolfe conditions of $c_2 = 0.1$, `NonlinearCg` requires about four evaluations per iteration.
The objective for `GradientDescent` decreases faster than the dashed worst-case bound (approximately 13.5 even at $k = 400$).
The dashed line bounds steepest descent with an exact line search; it does not bound `GradientDescent`, which uses BB initial trial steps.
Neither `Bfgs` nor `Lbfgs` damps or skips any curvature update, while `NonlinearCg` restarts three times.
At $\kappa = 2$, all four methods stop after 11–12 iterations, with little difference.

At $\kappa = 10^4$, `GradientDescent` stops at the 1000-iteration limit with `IterationLimit` (objective $8.9\times10^{-11}$ and distance $1.3\times10^{-5}$ from the origin); this is not convergence.
At the same $\kappa$, `NonlinearCg` reaches `GradientSmall` in 247 iterations (1915 evaluations and 12 restarts), `Bfgs` in 139 iterations (151 evaluations), and `Lbfgs` in 758 iterations (831 evaluations and no damped or skipped updates).
Because `Lbfgs` stores only the latest 10 pairs, it uses about 5.5 times as many iterations as dense `Bfgs` on this problem, where 20 eigenvalues span a factor of $10^4$.
BFGS with an exact line search terminates within $n$ iterations on a quadratic function, but this property does not hold with the inexact line search of $c_2 = 0.9$, so even `Bfgs` uses more than $n = 20$ iterations.
No zero-objective points are omitted from the logarithmic axis at the default input or either endpoint of the input range.

## Summary

On quadratic functions that differ only in eigenvalue spread, steepest descent iteration counts grow rapidly with $\kappa$, and at $\kappa = 10^4$ even 1000 iterations do not reach the tolerance.
Nonlinear conjugate gradients uses fewer iterations but more evaluations per iteration because of the strong Wolfe conditions of $c_2 = 0.1$, reducing its advantage when compared by evaluation count.
Dense BFGS learns curvature and uses the fewest evaluations; at $\kappa = 10^4$ it also uses the fewest iterations (at $\kappa = 400$, `NonlinearCg` has the minimum of 64 iterations).
Because L-BFGS stores fewer pairs, it uses more iterations than BFGS when $\kappa$ is large.
Choose `Bfgs` for few variables, or `Lbfgs` if memory usage $O(n^2)$ is unacceptable; in either case, interpret results through the termination reason and iteration count relative to the limit.
