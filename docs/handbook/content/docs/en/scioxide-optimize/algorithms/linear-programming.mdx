Linear programming (LP) minimizes a linear objective under linear equality and inequality constraints.
An optimum is attained at a vertex of the feasible region, so simplex follows successive vertices while interior-point methods approach an optimal face from within the region.
This page derives the two methods, explains termination tests and complexity, and describes SciOxide's `SimplexSolver` and `InteriorPointLp` implementations.
Checking solver points and multipliers against original equations is covered in [Certificates and verification for linear and quadratic programming](../programming-certificates/).

## Standard form and basic solutions

A standard-form linear program is

$$
\min_{\mathbf{x} \in \mathbb{R}^n} \mathbf{c}^\mathsf{T}\mathbf{x} \quad \text{subject to} \quad \mathbf{A}\mathbf{x} = \mathbf{b}, \quad \mathbf{x} \ge \mathbf{0}
$$

with $\mathbf{A}\in\mathbb{R}^{m\times n}$, $\mathbf{b}\in\mathbb{R}^m$ and $\mathbf{c}\in\mathbb{R}^n$.
The feasible region is a convex polyhedron, and objective level sets are hyperplanes.
If the feasible region is nonempty and the objective is bounded below, a minimum is attained at one of the polyhedron's vertices.
Any LP can be converted to this form by adding nonnegative slack variables to inequalities $\mathbf{a}_i^\mathsf{T}\mathbf{x}\le b_i$ and splitting unrestricted variables into differences of two nonnegative variables.

Assume $\operatorname{rank}(\mathbf{A}) = m < n$ and partition column indices into $m$ basic indices $\mathcal{B}$ and $n-m$ nonbasic indices $\mathcal{N}$.
If basis matrix $\mathbf{B} = \mathbf{A}_{:, \mathcal{B}}$ is nonsingular, setting nonbasic variables to $\mathbf{x}_{\mathcal{N}} = \mathbf{0}$ determines

$$
\mathbf{x}_{\mathcal{B}} = \mathbf{B}^{-1}\mathbf{b}
$$

.
When this satisfies $\mathbf{x}_{\mathcal{B}} \ge \mathbf{0}$, it is a basic feasible solution.
Basic feasible solutions correspond to polyhedron vertices and have at most $m$ positive components.
A vertex with a zero basic variable is degenerate, and multiple bases can correspond to a degenerate vertex.

## Reduced costs and the ratio test

Rewriting the objective in nonbasic variables gives

$$
\mathbf{c}^\mathsf{T}\mathbf{x} = \mathbf{c}_{\mathcal{B}}^\mathsf{T}\mathbf{B}^{-1}\mathbf{b} + \bar{\mathbf{c}}_{\mathcal{N}}^\mathsf{T}\mathbf{x}_{\mathcal{N}},\qquad
\bar{\mathbf{c}}_{\mathcal{N}}^\mathsf{T} = \mathbf{c}_{\mathcal{N}}^\mathsf{T} - \mathbf{c}_{\mathcal{B}}^\mathsf{T}\mathbf{B}^{-1}\mathbf{A}_{:,\mathcal{N}}
$$

where $\bar{\mathbf{c}}_{\mathcal{N}}$ is the reduced cost.

- If $\bar{\mathbf{c}}_{\mathcal{N}} \ge \mathbf{0}$, increasing any nonnegative $\mathbf{x}_{\mathcal{N}}$ cannot decrease the objective, so the current basic solution is optimal.
  Convexity of LP makes this local test establish global optimality.
- A negative component $\bar{c}_j < 0$ allows objective decrease by bringing $x_j$ into the basis (pivoting).

Increasing $x_j$ by $\theta\ge0$ requires basic variables to move as $\mathbf{x}_{\mathcal{B}}-\theta\mathbf{d}$ ($\mathbf{d}=\mathbf{B}^{-1}\mathbf{A}_{:,j}$) to preserve equality.
The largest step preserving nonnegativity is determined by the ratio test:

$$
\theta^*=\min_{i:\,d_i>0}\frac{(\mathbf{x}_{\mathcal{B}})_i}{d_i}
$$

The minimizing basic variable becomes zero and leaves the basis.
If no component satisfies $d_i>0$, $\theta$ can grow arbitrarily and the objective is unbounded below.
One pivot decreases the objective by $\theta^*|\bar{c}_j|$.

In a degenerate basis, a row with $(\mathbf{x}_{\mathcal{B}})_i=0$ gives $\theta^*=0$, changing only the basis while leaving the point fixed.
A sequence of such pivots can cycle through the same bases.
Bland's rule prevents cycling by choosing the smallest-index entering variable among negative reduced costs and the smallest-index leaving variable among minimum-ratio rows (Bland, 1977).
Since finitely many bases exist, avoiding cycling makes simplex terminate finitely.
Worst-case pivot counts grow exponentially with variable count (the Klee–Minty example for Dantzig's rule), while practical problems often finish within a few multiples of the row count (Chvátal, 1983, Chapter 4).

## SimplexSolver implementation

The `SimplexSolver` solver implements two-phase bounded-variable revised simplex.
Phase I constructs a feasible basis; phase II decreases the original objective.
Finite variable upper bounds are retained directly rather than expanded into rows; iterations that merely move a nonbasic variable from one bound to the other (bound flips) count as iterations just like pivots.
Rows and columns are equilibrated by powers of two; entering-variable selection (pricing) and ratio tests use these coordinates.

- Select entering variables by Dantzig's rule (most negative reduced cost).
- Select leaving variables by the two-pass Harris ratio test.
  The first pass finds the minimum ratio with feasibility relaxed by tolerance; the second selects the row with the largest $|d_i|$ among rows in that range.
  Avoiding small pivots limits rounding-error amplification (Harris, 1973).
- After eight consecutive pivots whose step or objective improvement is at or below tolerance, use Bland's rule for the rest of that phase.

Solve with the basis matrix using LU factorization.
Use sparse LU when row constraints were supplied as sparse matrices or `with_sparse_limits` is configured; otherwise use dense LU.
Between factorizations, represent basis changes by eta updates and refactor every `with_basis_update_limit` (default 32 updates).
For a dense basis, one pivot costs $O(m^2)$ and refactorization costs $O(m^3)$.
The default iteration limit is $\max(1000,\,10(n+m))$ from original variable count $n$ and row count $m$; override it with `with_max_iterations`.
Default absolute and relative tolerances are $10^{-8}$ for every role ($10^{-6}$ for scalars whose machine epsilon exceeds $10^{-8}$); change them with `with_tolerances`.

The `BasisMatrix` type borrows the current basis matrix; read entries through `order()`, `column_entries(column)` and `get(row, col)`.
Basis columns are standard-form columns; artificial-variable unit columns are not stored, and removed redundant rows are excluded.
The `BasisProvider` trait supplies this matrix's factorization (`factor`) and solves with $\mathbf{B}\mathbf{y}=\mathbf{r}$ or $\mathbf{B}^\mathsf{T}\mathbf{y}=\mathbf{r}$.
Built-in choices are `DenseBasisProvider` (dense LU with partial pivoting) and `SparseBasisProvider` (sparse LU reusing symbolic analysis while the pattern is unchanged); replace the built-in factorization with `SimplexWorkspace::with_basis_provider`.

## Reusing a basis

The `SimplexWorkspace` workspace retains the most recent attempt's basis and records.
Calling `SimplexWorkspace::warm_start()` after `SimplexSolver::solve_into` yields a `SimplexWarmStart` owning the basis and bound states of nonbasic variables.
The one-shot `solve` call does not record a basis, so use workspace for reuse.
Passing this snapshot and a modified problem to `SimplexSolver::resume_into` behaves as follows.

- If only the objective or right-hand side changed, or inequality rows were added, start from the recorded basis.
  If it is not primal feasible, restore feasibility with dual simplex or return a Farkas infeasibility certificate.
- If coefficients, row senses, variable bounds or shape changed, restart from scratch.
  An old snapshot does not cause an error.

Read which path was used from `reused_basis()` in the new snapshot.
Child nodes of branch and bound change only variable bounds, so this rule restarts them from scratch.
The `BranchAndBound` solver in [Mixed-integer programming and branch and cut](../mixed-integer-programming/) uses a dedicated `MipSimplexWorkspace` to reoptimize bound changes.

## Duality and shadow prices

The dual problem corresponding to the standard-form primal is

$$
\max_{\mathbf{y} \in \mathbb{R}^m} \mathbf{b}^\mathsf{T}\mathbf{y} \quad \text{subject to} \quad \mathbf{A}^\mathsf{T}\mathbf{y} \le \mathbf{c}
$$

.
For primal feasible $\mathbf{x}$ and dual feasible $\mathbf{y}$,

$$
\mathbf{c}^\mathsf{T}\mathbf{x}-\mathbf{b}^\mathsf{T}\mathbf{y}=(\mathbf{c}-\mathbf{A}^\mathsf{T}\mathbf{y})^\mathsf{T}\mathbf{x}\ge0
$$

holds (weak duality).
A dual feasible solution therefore gives a lower bound on the primal optimal value.
Equality holds only when complementarity $x_j(\mathbf{c}-\mathbf{A}^\mathsf{T}\mathbf{y})_j=0$ ($j=1,\dots,n$) holds.
If either problem has a finite optimum, so does the other, with equal optimal values (strong duality).

At an optimal simplex basis, $\mathbf{y}^{*\mathsf{T}}=\mathbf{c}_{\mathcal{B}}^\mathsf{T}\mathbf{B}^{-1}$ is a dual optimum.
The nonbasic components of $\mathbf{c}-\mathbf{A}^\mathsf{T}\mathbf{y}^*$ are then reduced costs, and $\bar{\mathbf{c}}_{\mathcal{N}}\ge\mathbf{0}$ is equivalent to dual feasibility.
While the optimal basis remains unchanged, changing right-hand side $b_i$ changes the optimal value at rate $y_i^*$.
This rate is the shadow price.

Primal infeasibility can be established by Farkas multipliers, and unboundedness by a feasible point and an objective-decreasing recession direction ([Infeasibility and unboundedness certificates and verification of external results](../infeasibility-certificates/)).

SciOxide results retain these multipliers in the original problem form ($\le$, $=$ and $\ge$ rows and variable bounds).
Their sign convention reverses the textbook form above: $\le$ row multipliers are nonnegative and represent the decrease in optimal value when the right-hand side increases by 1.
See [Certificates and verification for linear and quadratic programming](../programming-certificates/) for detailed conventions and verification.

## Homogeneous self-dual interior-point method

Where simplex moves between vertices, primal-dual interior-point methods approach an optimum while preserving $\mathbf{x} > \mathbf{0}$ and dual slack $\mathbf{s}=\mathbf{c}-\mathbf{A}^\mathsf{T}\mathbf{y} > \mathbf{0}$.
Relaxing complementarity $x_j s_j = 0$ by $\mu > 0$ gives the equations

$$
\mathbf{A}\mathbf{x} = \mathbf{b}, \quad \mathbf{A}^\mathsf{T}\mathbf{y} + \mathbf{s} = \mathbf{c}, \quad \mathbf{X}\mathbf{S}\mathbf{e} = \mu \mathbf{e}
$$

with $\mathbf{X} = \operatorname{diag}(\mathbf{x})$, $\mathbf{S} = \operatorname{diag}(\mathbf{s})$ and all-ones $\mathbf{e}$; their solutions form a central path toward an optimum as $\mu\to0$.
Eliminating $\Delta\mathbf{x}$ and $\Delta\mathbf{s}$ from the Newton equations leaves the normal equations in $\Delta\mathbf{y}$:

$$
\mathbf{A}\mathbf{D}\mathbf{A}^\mathsf{T}\Delta\mathbf{y}=\mathbf{r},\qquad \mathbf{D}=\mathbf{X}\mathbf{S}^{-1}
$$

where $\mathbf{r}$ is a right-hand side determined by residuals.

Mehrotra's predictor–corrector method first computes the affine direction for $\mu = 0$ (predictor), estimating average complementarity $\mu_{\mathrm{aff}}$ after advancing to the boundary along it.
It then uses the same factorization for a direction adding centering with coefficient $\sigma=(\mu_{\mathrm{aff}}/\mu)^3$ and a second-order correction (corrector) (Mehrotra, 1992).
The step length is 0.995 times the distance until a positive component reaches its boundary.

The `InteriorPointLp` solver applies this method to a homogeneous self-dual embedding (Ye, Todd and Mizuno, 1994; Xu, Hung and Ye, 1996).
The embedding is the homogeneous system with added nonnegative scalars $\tau,\kappa$:

$$
\mathbf{A}\mathbf{x}-\mathbf{b}\tau=\mathbf{0},\qquad -\mathbf{A}^\mathsf{T}\mathbf{y}+\mathbf{c}\tau-\mathbf{s}=\mathbf{0},\qquad \mathbf{b}^\mathsf{T}\mathbf{y}-\mathbf{c}^\mathsf{T}\mathbf{x}-\kappa=0
$$

At the limit of a nontrivial solution, $\tau>0$ makes $(\mathbf{x}/\tau,\mathbf{y}/\tau)$ primal and dual optima; if $\kappa>0$, $\mathbf{b}^\mathsf{T}\mathbf{y}>\mathbf{c}^\mathsf{T}\mathbf{x}$ establishes primal or dual infeasibility.
A feasible initial point is therefore unnecessary.
Solving the embedding by the path-following method of Ye, Todd and Mizuno (1994) bounds iteration count by $O(\sqrt{n}\log(1/\varepsilon))$.
This bound is unproved for Mehrotra's predictor–corrector method, but practical iteration counts often depend little on problem size.

The main cost per iteration is factoring the order-$m$ normal matrix $\mathbf{A}\mathbf{D}\mathbf{A}^\mathsf{T}$ ($O(m^3)$ if dense).
Near an optimum, components of $\mathbf{D}$ separate toward zero and $\infty$, making the normal matrix ill-conditioned.
The `InteriorPointLp` solver shares one factorization between predictor and corrector and compensates for this ill-conditioning by correcting the original Newton residuals up to three times using the same factorization.
Add scale-proportional diagonal regularization to the normal matrix and solve by dense $\mathrm{LDL}^\mathsf{T}$ factorization by default.
Correct the final iterate on its active face before constructing an optimality certificate.
The default iteration limit is 1000 and tolerances match simplex: $10^{-8}$ ($10^{-6}$ for lower-precision scalars).
Return `Unbounded` only if a feasible base point and unbounded direction pass checks against the original problem; small $\tau$ alone is insufficient.
Obtaining a base point may use one simplex solve, whose iterations also count toward the limit.

## Problem input and workspace

Create the objective with `LpProblem::new(c)`, add row constraints with `with_constraints` and variable bounds with `with_bounds`.
Variables without explicit bounds are treated as $x\ge0$.
The `LinearConstraints::new(a, b, senses)` type combines a coefficient matrix, right-hand side and each row's `LinearConstraintSense` (`Equal`, `LessEqual` or `GreaterEqual`); use `less_equal(a, b)`, `equal` or `greater_equal` when all rows have the same sense.
Match column count to the variable count and right-hand side and sense counts to the row count.
Coefficients are accepted as `CoefficientMatrix` in dense or sparse (CSR) form.
Sparse input storage and sparse factorization are separate properties; each solver chooses its factorization as described above.

The `LpProblem::solve()` method is a one-shot call using default `SimplexSolver`.
It returns unsuccessful termination in `Err`: verified infeasibility or unboundedness yields `DomainError`, and iteration-limit termination yields `ConvergenceFailure`.
Solving with a method object, as in `SimplexSolver::default().solve(&lp)`, returns the same termination as result `termination()` and allows inspection of a limit-stopped point.

The `SimplexWorkspace` type accepts any LP and sizes factorization memory on each call.
In contrast, `InteriorPointLpWorkspace` is fixed to the standard-form shape at construction by `InteriorPointLp::workspace(&problem)` (column and row counts, `shape()`) and rejects differently shaped problems with `DimensionMismatch` before factorization.
Pass `InteriorPointLpWorkspace::with_kkt_provider` a `KktProvider` accepting the symmetric order-$m$ normal matrix including scale-proportional diagonal regularization.
The `embedding_scalars()` method returns $(\tau,\kappa)$ from the most recently accepted iteration.

## Problem size and iteration counts

Examine how simplex pivot counts and interior-point iteration counts depend on problem size.
Use production planning with $n$ products and $n$ resources: one unit of product $j$ consumes $A_{ij}$ units of resource $i$ and earns profit $p_j$.
The values $A_{ij}$ and $p_j$ are seeded random integers from 1 to 9; each resource has 100 units.
Maximize profit $\mathbf{p}^\mathsf{T}\mathbf{x}$ subject to $\mathbf{A}\mathbf{x}\le\mathbf{b}$ and $\mathbf{x}\ge\mathbf{0}$ (by minimizing $-\mathbf{p}$).
Solve problems of size $n=10,20,40,80,120$ with default `SimplexSolver` and `InteriorPointLp` settings; use the relative difference in objectives as an independent check.
The only input is the random seed.
The table also gives pivots divided by row count $m=n$ and the number of positive variables in the simplex solution (at most $m$ because it is a vertex).

```rust
//| id: optimize-lp-iteration-growth
//| ref: optimize-lp-iteration-growth
//| title: "Compare simplex pivots and interior-point iterations versus problem size"
//| run: button
//| timeoutMs: 120000
//| crates: [scioxide-linalg, scioxide-optimize, scioxide-random]
//| inputs:
//|   seed: {"type":"range","label":"Random seed [-]","description":"Seed generating resource coefficients and profits.","min":1,"max":20,"step":1,"value":3}
//| cases:
//|   - {"id":"long-run","label":"Seed 1","description":"At n = 120, simplex exceeds 700 pivots, six times the row count; interior-point iterations remain at 11.","inputs":{"seed":1}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"iterations","path":"/rows/0/0","equals":10}
//|       - {"artifact":"iterations","path":"/rows/3/1","range":{"min":20,"max":200}}
//|       - {"artifact":"iterations","path":"/rows/3/3","range":{"min":5,"max":20}}
//|       - {"artifact":"iterations","path":"/rows/4/4","range":{"min":0,"max":1e-6}}
//|       - {"artifact":"iterations","path":"/rows/4/6","equals":"Converged"}
//|       - {"artifact":"iterations","path":"/rows/4/7","equals":"Converged"}
//|   - case: long-run
//|     expect:
//|       - {"artifact":"iterations","path":"/rows/4/1","range":{"min":300}}
//|       - {"artifact":"iterations","path":"/rows/4/3","range":{"min":5,"max":20}}
//|       - {"artifact":"iterations","path":"/rows/4/4","range":{"min":0,"max":1e-6}}
use scioxide_linalg::Matrix;
use scioxide_optimize::{InteriorPointLp, LinearConstraints, LpProblem, SimplexSolver};
use scioxide_random::{SeedableRng, Xoshiro256StarStar, uniform_index};

let fixed2 = serde_json::json!({ "fractionDigits": 2 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let mut rows = Vec::new();
let mut simplex_points = Vec::new();
let mut interior_points = Vec::new();
let mut reference = Vec::new();
for n in [10_usize, 20, 40, 80, 120] {
    // Create each problem size from the same seed. A_ij and p_j are integers from 1 to 9; resource quantities are 100.
    let mut rng = Xoshiro256StarStar::from_seed(seed.round() as u64);
    let mut a = Vec::with_capacity(n * n);
    for _ in 0..n * n {
        a.push(1.0 + uniform_index(9, &mut rng).map_err(|e| e.to_string())? as f64);
    }
    // Use objective −p to convert profit maximization to minimization.
    let mut cost = Vec::with_capacity(n);
    for _ in 0..n {
        cost.push(-(1.0 + uniform_index(9, &mut rng).map_err(|e| e.to_string())? as f64));
    }
    let matrix = Matrix::from_vec(n, n, a).map_err(|e| e.to_string())?;
    let resources =
        LinearConstraints::less_equal(matrix, vec![100.0; n]).map_err(|e| e.to_string())?;
    let lp = LpProblem::new(cost)
        .and_then(|p| p.with_constraints(resources))
        .map_err(|e| e.to_string())?;
    let simplex = SimplexSolver::default()
        .solve(&lp)
        .map_err(|e| e.to_string())?;
    let interior = InteriorPointLp::default()
        .solve(&lp)
        .map_err(|e| e.to_string())?;
    // Independent check: relative difference between the two objective values.
    let difference = (simplex.fun() - interior.fun()).abs() / simplex.fun().abs().max(1.0);
    let positive = simplex.x().iter().filter(|&&v| v > 0.0).count();
    let size = n as f64;
    simplex_points.push([size, simplex.iterations() as f64]);
    interior_points.push([size, interior.iterations() as f64]);
    reference.push([size, size]);
    rows.push((
        n,
        simplex.iterations(),
        simplex.iterations() as f64 / size,
        interior.iterations(),
        difference,
        positive,
        simplex.termination().to_string(),
        interior.termination().to_string(),
    ));
}
emit_line_chart!(
    &vec![
        serde_json::json!({
            "name": "Simplex pivots",
            "points": simplex_points,
            "style": {"showSymbol": true}
        }),
        serde_json::json!({
            "name": "Interior-point iterations",
            "points": interior_points,
            "style": {"showSymbol": true}
        }),
        serde_json::json!({
            "name": "Reference: row count m",
            "points": reference,
            "style": {"lineType": "dashed"}
        }),
    ],
    options = &serde_json::json!({
        "xLabel": "Product count n = resource count m [-]",
        "yLabel": "Iterations [count]",
        "xType": "log",
        "yType": "log"
    })
);
let columns = serde_json::json!([
    { "key": "0", "label": "n = m [-]", "type": "integer" },
    { "key": "1", "label": "Simplex pivots [count]", "type": "integer" },
    { "key": "2", "label": "Pivots / m [-]", "type": "number", "format": fixed2 },
    { "key": "3", "label": "Interior-point iterations [count]", "type": "integer" },
    { "key": "4", "label": "Relative objective difference [-]", "type": "number", "format": sci2 },
    { "key": "5", "label": "Positive components of simplex solution [count]", "type": "integer" },
    { "key": "6", "label": "Simplex termination" },
    { "key": "7", "label": "Interior-point termination" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "iterations" })
);
```

With default seed 3, simplex pivots rise from six at $n=10$ to 78 at $n=120$, with pivot-to-row ratios only 0.53–0.65.
Interior-point iterations rise only from eight to eleven.
On the log-log plot, pivot points are approximately parallel to the slope-1 reference line, while interior-point points are nearly horizontal.
Relative objective differences are below $2\times10^{-9}$ at every size; the simplex solution has 5–24 positive components, fewer than the row count.
A dense-basis pivot costs $O(m^2)$ and an interior-point iteration $O(m^3)$, so iteration counts alone do not compare runtime.

With seed 1, $n=120$ needs 739 pivots (6.2 times the row count), far above 78 with seed 3 or 110 with seed 20.
Interior-point iterations remain eleven even for this problem.
Simplex pivot counts can vary by orders of magnitude with coefficients even at the same problem size.

## Summary

A basis with nonnegative reduced costs is optimal; ratio tests determine step lengths, and Bland's rule prevents cycling of degenerate pivots.
Weak duality makes dual feasible solutions lower bounds on primal objectives, and the optimal basis dual solution gives right-hand side shadow prices.
Choose `SimplexSolver` for basis reuse, shadow prices and reoptimization with few pivots; choose `InteriorPointLp` when no feasible initial point is available or iteration counts should depend little on size.
The `LpProblem::solve()` call uses simplex with iteration limit $\max(1000,10(n+m))$; solve with a `SimplexSolver` value to inspect limit-stopped points.
Both methods' results can be checked independently of their solvers against the original equations.
