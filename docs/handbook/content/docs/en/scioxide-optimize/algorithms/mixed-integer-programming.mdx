Integrality conditions turn a continuous feasible region into a discrete set of points.
Simply rounding a continuous optimum yields neither a feasible integer solution nor the optimal value.
This page derives branch and cut, which obtains lower bounds from LP relaxation and narrows the gap to integer solutions through branching and cutting planes, and explains the `BranchAndBound` implementation and its results.

## LP relaxation and branch and bound

A linear program with integrality conditions $x_j \in \mathbb{Z}$ ($j\in\mathcal{I}$) on some variables is a mixed-integer linear program (MILP, hereafter MIP).
MIP is NP-hard in general.
Removing integrality conditions gives the LP relaxation.
The relaxed feasible region contains the original region, so for minimization its optimum $z_{\mathrm{LP}}$ is a lower bound on the integer optimum $z_{\mathrm{IP}}$ ($z_{\mathrm{LP}}\le z_{\mathrm{IP}}$).
Conversely, any feasible integer solution's objective is an upper bound on $z_{\mathrm{IP}}$.
Branch and bound narrows this difference between lower and upper bounds by subdividing the region (Land and Doig, 1960).

When integer variable $x_i$ takes fractional value $v$ in the relaxation, split the problem into child problems (child nodes) $x_i \le \lfloor v \rfloor$ and $x_i \ge \lceil v \rceil$.
The children exclude only the strip $\lfloor v\rfloor<x_i<\lceil v\rceil$, eliminating the parent's LP solution without losing any integer solution.
A child's feasible region is contained in its parent's, so relaxed values cannot decrease down the tree.
If a node's relaxed value is at least the value of the best integer solution so far (the incumbent), its subtree has no better integer solution and can be pruned.

With incumbent objective $U$ (upper bound) and minimum unprocessed-node relaxation value $L$ (lower bound), the absolute optimality gap is

$$
\mathrm{Gap} = U - L
$$

.
Both good integer solutions lowering $U$ and strong relaxations raising $L$ shorten the search.

## BranchAndBound procedure

The `BranchAndBound` method solves an LP relaxation at each node; because it adds cutting planes, it is also called branch and cut.
At each node it performs the following steps.

1. Solve the node's LP relaxation by revised simplex.
   Only variable bounds differ from the parent, so reoptimize from the retained matrix and most recent basis, obtaining the node lower bound from verified dual information.
2. Prune the node if the relaxation is infeasible or the lower bound is not below the incumbent within tolerance.
3. If the relaxed solution is nearly integral, independently check the rounded point against original constraints, variable bounds and objective, and accept it as incumbent only if it passes.
   Also try a round-and-fix repair once per node.
4. Find valid cutting planes violated by the current relaxed solution, add those passing checks, and reoptimize (see below).
5. Select a fractional variable by the `MipBranching` rule and create two children.

Process unhandled nodes in increasing lower-bound order (best-bound search).
Tied nodes follow creation order and tied branching variables use the smallest index, producing the same search tree for the same input.
Tree search is sequential even if the execution context has a parallel executor.

## Branching rules

The `MipBranching` type chooses the branching variable and is configured with `with_branching`.

- `MostFractional`: select the variable whose fractional part is closest to $1/2$.
- `Pseudocost`: select the variable with the largest pseudocost score.
- `Reliability` (default): use strong-branching trial solves for candidates with insufficient pseudocost history, then select by pseudocost score.

For branching variable $x_j$ down (up), pseudocost $\psi_j^-$ ($\psi_j^+$) is the average of the relaxed-value increase divided by displacement $f_j^-=v-\lfloor v\rfloor$ ($f_j^+=\lceil v\rceil-v$).
The score is $\min(\psi_j^-f_j^-,\ \psi_j^+f_j^+)$, with an unrecorded directional average treated as 1.
Variables without records therefore score $\min(f_j^-,f_j^+)$, selecting the variable whose fractional part is nearest $1/2$.
Selecting variables with large degradation in both directions tends to allow early pruning of both children (Achterberg, Koch and Martin, 2005).
The `Reliability` rule considers up to four candidates in order of proximity of their fractional parts to $1/2$; if either direction has fewer than two records, trial-solve child LPs with at most 32 pivots (strong branching), supplementing records before applying the same score.
Change candidate count, pivot limit and record count with `strong_candidates`, `strong_iterations` and `reliability` in `MipLimits`; a zero pivot limit disables trial solves.

## Cutting planes

A cutting plane is a linear inequality satisfied by all feasible integer solutions but violated by the current LP relaxation solution.
Tightening the relaxation raises the lower bound and can reduce node counts compared with branching alone.
The `MipCutKind` type describes the cutting plane kinds generated by `BranchAndBound`.

- `MipCutKind::IntegerRow` rounds the right-hand side of a row $\sum_ja_jx_j\le b$ containing only integer variables with integer coefficients to $\lfloor b\rfloor$ (reverse the sign of $\ge$ rows before rounding).
  Since integer solutions have integral left-hand sides, rounding excludes none of them (Chvátal–Gomory rounding).
- `MipCutKind::BinaryCover` uses a row $\sum_ja_jx_j\le b$ with all binary variables and positive coefficients (sign-reversed for $\ge$ rows) to construct $\sum_{j\in C}x_j\le|C|-1$ from a cover $C$ satisfying $\sum_{j\in C}a_j>b$.
  Setting all of $C$ to 1 violates the row, so an integer solution must set at least one of $C$ to zero.
  Build the cover greedily from variables with large relaxed values, then remove redundant variables to make it minimal.

Retain only candidates violating the relaxed solution by more than tolerance and independently check derivation assumptions against original rows before addition.
Limits are two rounds per node (`cut_rounds`), 128 cuts per solve (`max_cuts`) and 8192 nonzero coefficients in total (`max_cut_nonzeros`).
Cuts remain only at the node where they were added and its descendants.
Add only inequalities whose derivation establishes validity for every integer solution, rather than inequalities convenient for a found candidate.

## Presolve and implied bounds

Perform conservative presolve at the root.
Convert singleton rows to variable bounds, round integer-variable bounds to integers, and eliminate fixed variables.
Every step is an exact transformation; `MipPresolveMap` retains the map to original coordinates (`reconstruct`, `active_variables`, `original_rows` and `objective_offset`).
Disable presolve with `with_presolve(false)`.

Before searching, also add outward-rounded implied bounds on unbounded columns from rows where the other terms have finite ranges.
Node lower bounds come from verified dual certificates, requiring finite bounds on the side determined by reduced-cost signs.
If a column has no obtainable implied bound, its node lower bound cannot be verified and search may stop with `Stagnation`.
Supply bounds for variables with known physical limits.

## Interpreting gaps and termination

The `MipResult` result returns `absolute_gap()`, `relative_gap()` and `global_lower_bound()`, plus integrality and feasibility violations (`integrality_violation()`, `primal_feasibility()` and `bound_violation()`).
The relative gap is $\mathrm{Gap}/\max(1,|U|,|L|)$.
Node pruning and overall termination use absolute gap tolerance $a$ and relative part $r$ in the test

$$
U-L\le a+r\max(1,|U|,|L|)
$$

with `with_relaxation_tolerances`, defaulting to $a=r=10^{-8}$.
Bounds of nodes pruned by tolerance remain in the global lower bound, so a successful result need not report an exactly zero gap.
Node bounds are estimates from floating-point-verified dual information, not interval-arithmetic enclosures.
The `certified_optimality_gap()` field denotes exact-arithmetic proof, so floating-point branch and bound always returns `None`.

Read success using `is_success()`.
Searches stopped by node, depth or memory limits (`NodeLimit`, `DepthLimit` and `MemoryLimit`), or by `Stagnation`, are unsuccessful.
In such cases, inspect incumbent availability (`has_incumbent()`) and the gap, then decide whether that gap is acceptable for the application.
Do not use `x()` as an integer solution when no incumbent exists.

## Controlling the search

The `MipProblem::new(relaxation, integer_variables)` type combines an LP relaxation and integer-variable indices.
The one-shot `MipProblem::solve()` method uses default `BranchAndBound` (1000 processed nodes, 1000 pivots per relaxation, `Reliability` and presolve enabled); limit-stopped searches return `ConvergenceFailure` errors even if an incumbent exists.
To inspect incumbent and lower bound after a limit stop, solve with a method object as in `BranchAndBound::default().solve(&problem)`.
Search limits, workspace, unprocessed nodes, computation counts and replacement relaxation solvers are covered in [Branch-and-cut search state and limits](../branch-and-cut-search/).

## Integrality gap experiment for a knapsack problem

Maximize profit $11 x_A + 18 x_B$ under weight constraint $7 x_A + 11 x_B \le C$ and integer $x_A, x_B \ge 0$ by reversing the objective sign for minimization.
Weight is measured in kg and profit in points.
For each capacity $C$, solve the LP relaxation with `SimplexSolver` and the integer problem with `BranchAndBound`, comparing the integer result with an independent exhaustive optimum.
Profit per weight is $18/11\approx1.636$ for $B$ and $11/7\approx1.571$ for $A$, so the relaxed optimum is $18C/11$, filling only with $B$.
No variable upper bounds are supplied, but `BranchAndBound` adds implied bounds $x_A\le C/7$ and $x_B\le C/11$ from the weight constraint before search.
The input is capacity $C$ shown in the detailed table; the plot solves all capacities from $C=0$ to 70.
The cell stops with an error if any of these 71 cases terminates unsuccessfully.

At the default $C = 35$ kg, the LP relaxation upper bound is 57.27 and the integer optimum is 55 ($x_A = 5, x_B = 0$), giving integrality gap 2.27.
The `BranchAndBound` method processes 13 nodes before `Converged`, reports zero absolute gap, and matches the exhaustive optimum.
It solves 25 LP relaxations, including six strong-branching trials and six round-and-fix repairs.
No cutting planes are added for this problem.
At $C = 60$, it reaches 95 ($x_A = 7, x_B = 1$) in 17 nodes, with integrality gap 3.18.
At $C = 5$, no item fits; the integer optimum is 0 while the LP upper bound is 8.18.
Implied upper bounds $x_A\le5/7$ and $x_B\le5/11$ round to zero in presolve, fixing both variables, so no nodes are processed.
For all 71 capacities from $C = 0$ to 70, the `BranchAndBound` optimum matches exhaustive enumeration.

The dashed LP relaxation is linear, the integer optimum is a staircase as capacity increases, and their difference varies in a sawtooth pattern.
Rounding an LP value does not produce the integer optimum.
For example, rounding down LP solution $x_B=35/11\approx3.18$ at $C=35$ to $x_B=3$ gives profit 54; the integer optimum 55 instead chooses item $A$.

## Summary

Branch and cut obtains lower bounds from LP relaxation and upper bounds from checked integer solutions, narrowing their difference through branching and cutting planes.
The default branching rule `Reliability` supplements pseudocosts with strong branching; `MostFractional` and `Pseudocost` perform no trial solves.
Inspect `is_success()`, `has_incumbent()`, `absolute_gap()` and `relative_gap()` separately; after stops such as `NodeLimit`, judge whether the gap meets application needs.
Reported gaps are floating-point estimates, and `certified_optimality_gap()` is always `None`.
Unbounded integer variables may yield `Stagnation` if implied bounds cannot be derived, so provide known physical upper bounds.
