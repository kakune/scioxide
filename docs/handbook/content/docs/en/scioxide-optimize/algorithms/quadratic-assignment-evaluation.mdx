FAQ and 2-opt for the quadratic assignment problem (QAP) are heuristics; stopping with `Converged` does not establish global optimality.
This page computes the exact optimum of a small problem by enumerating every permutation and compares three method objects with it.
The problem definition, FAQ derivation, and 2-opt difference formula are in [quadratic assignment and permutation search](../quadratic-assignment/).

## Exhaustive search on a small problem

A problem with $n$ facilities has $n!$ permutations; $n=8$ gives 40 320.
At this size, directly summing every permutation's objective

$$
F(\pi)=\sum_{i=1}^n\sum_{j=1}^n A_{ij}B_{\pi(i),\pi(j)}
$$

gives the exact optimum and objective distribution.
Generate permutations one at a time with Heap's algorithm.
Heap's algorithm generates each next permutation by swapping two elements of the preceding one, enumerating all $n!$ without duplication.

The example places facilities with integer flows $A_{ij}$ from 0 to 9 (zero diagonal, asymmetric), random locations on a $10\times10$ grid, and distances $B_{kl}$ equal to their Manhattan distances.
Generate flows and locations from the random seed.
Objective units are flow times distance; minimization represents transport cost and maximization represents overlap (graph matching).
The next cell generates a problem, enumerates all permutations, and passes the problem and every objective value to the following cell.
Inputs are facility count $n$, random seed, and optimization direction; the table gives permutation count, optimum, worst value, mean, and number of optimal permutations.

```rust
//| id: optimize-qap-exhaustive
//| ref: optimize-qap-exhaustive
//| title: "Compute all permutation objectives for a seed-generated QAP"
//| run: reactive
//| crates: [scioxide-random]
//| exports: [size, maximize, flow, distance, optimum, values]
//| inputs:
//|   size: {"type":"range","label":"Facilities n [count]","min":5,"max":8,"step":1,"value":8}
//|   seed: {"type":"range","label":"Random seed [-]","min":1,"max":100,"step":1,"value":3}
//|   direction: {"type":"select","label":"Optimization direction","options":["Minimize (transport cost)","Maximize (overlap)"],"value":"Minimize (transport cost)"}
//| cases:
//|   - {"id":"maximize","label":"Maximize (overlap)","description":"The maximum of the same problem is 2182.","inputs":{"direction":"Maximize (overlap)"}}
//|   - {"id":"five-facilities","label":"Facilities n = 5","description":"The minimum over 120 permutations is 508.","inputs":{"size":5}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"instance","path":"/rows/0/1","equals":40320}
//|       - {"artifact":"instance","path":"/rows/0/2","approx":{"value":1560,"atol":0.5}}
//|   - case: maximize
//|     expect:
//|       - {"artifact":"instance","path":"/rows/0/2","approx":{"value":2182,"atol":0.5}}
//|   - case: five-facilities
//|     expect:
//|       - {"artifact":"instance","path":"/rows/0/1","equals":120}
//|       - {"artifact":"instance","path":"/rows/0/2","approx":{"value":508,"atol":0.5}}
use scioxide_random::{SeedableRng, Xoshiro256StarStar, uniform_index};

let fixed1 = serde_json::json!({ "fractionDigits": 1 });
let n = size.round() as usize;
let maximize = direction.starts_with("Maximize");
let mut rng = Xoshiro256StarStar::from_seed(seed.round() as u64);
// Flow A has integer entries 0–9 and zero diagonal; locations are on a 10×10 grid and B contains their Manhattan distances.
let mut flow = vec![0.0; n * n];
for i in 0..n {
    for j in 0..n {
        if i != j {
            flow[i * n + j] = uniform_index(10, &mut rng).map_err(|e| e.to_string())? as f64;
        }
    }
}
let mut sites = Vec::with_capacity(n);
for _ in 0..n {
    let x = uniform_index(10, &mut rng).map_err(|e| e.to_string())?;
    let y = uniform_index(10, &mut rng).map_err(|e| e.to_string())?;
    sites.push((x, y));
}
let distance: Vec<f64> = (0..n * n)
    .map(|k| {
        let ((ax, ay), (bx, by)) = (sites[k / n], sites[k % n]);
        (ax.abs_diff(bx) + ay.abs_diff(by)) as f64
    })
    .collect();
// Double sum from the original definition.
let double_sum = |p: &[usize]| -> f64 {
    (0..n)
        .map(|i| {
            (0..n)
                .map(|j| flow[i * n + j] * distance[p[i] * n + p[j]])
                .sum::<f64>()
        })
        .sum()
};
// Generate all n! permutations one at a time with Heap's algorithm and record their objectives.
let mut perm: Vec<usize> = (0..n).collect();
let mut counter = vec![0_usize; n];
let mut values = vec![double_sum(&perm)];
let mut level = 1;
while level < n {
    if counter[level] < level {
        let other = if level % 2 == 0 { 0 } else { counter[level] };
        perm.swap(other, level);
        values.push(double_sum(&perm));
        counter[level] += 1;
        level = 1;
    } else {
        counter[level] = 0;
        level += 1;
    }
}
let (low, high) = values
    .iter()
    .fold((f64::INFINITY, f64::NEG_INFINITY), |(l, h), &v| {
        (l.min(v), h.max(v))
    });
let (optimum, worst) = if maximize { (high, low) } else { (low, high) };
let mean = values.iter().sum::<f64>() / values.len() as f64;
let ties = values.iter().filter(|&&v| v == optimum).count();
let columns = serde_json::json!([
    { "key": "0", "label": "Facilities n [count]", "type": "integer" },
    { "key": "1", "label": "Permutations [count]", "type": "integer" },
    { "key": "2", "label": "Optimum [flow×distance]", "type": "number", "format": fixed1 },
    { "key": "3", "label": "Worst value [flow×distance]", "type": "number", "format": fixed1 },
    { "key": "4", "label": "Mean [flow×distance]", "type": "number", "format": fixed1 },
    { "key": "5", "label": "Optimal permutations [count]", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    vec![(n, values.len(), optimum, worst, mean, ties)],
    metadata = serde_json::json!({ "id": "instance" })
);
export!(size, &n);
export!(maximize, &maximize);
export!(flow, &flow);
export!(distance, &distance);
export!(optimum, &optimum);
export!(values, &values);
```

At the default $n=8$ and seed 3, the 40 320 permutations have minimum 1560, maximum 2182, and mean 1827.5; only one permutation attains the minimum.
Selecting maximization makes 2182 the optimum of the same problem.
Among the 120 permutations for $n=5$, the minimum is 508 and two permutations attain it.

## Three methods and the exact optimum

The next cell solves the preceding problem with `QapMethod::Faq`, `TwoOpt`, and `FaqThenTwoOpt` and compares them with the exhaustive optimum.
Each method solves from the same `QapPlan` using `solve_with_options`, without a supplied initial permutation.
The only input is the number of additional restarts; the problem changes through the preceding cell's inputs.
“Recomputed double sum” in the table is an independent check substituting the reported permutation into the original definition and summing within the cell.
Define rank as one plus the number of all permutations whose objectives are better than the reported value.
The histogram shows the objective distribution of every permutation, with vertical lines for the optimum and each method object.

```rust
//| id: optimize-qap-faq-two-opt
//| ref: optimize-qap-faq-two-opt
//| title: "Compare FAQ and 2-opt permutations with the exhaustive optimum"
//| run: reactive
//| crates: [scioxide-linalg, scioxide-optimize]
//| dependsOn:
//|   instance: optimize-qap-exhaustive
//| inputs:
//|   restarts: {"type":"range","label":"Additional restarts [count]","description":"Add trials starting from permutations generated by the random seed.","min":0,"max":5,"step":1,"value":0}
//| cases:
//|   - {"id":"restarts-3","label":"3 additional restarts","description":"Restarts from random permutations let TwoOpt reach the optimum 1560, while FaqThenTwoOpt remains at 1574 (gap 14) and Faq at 1620 (gap 60).","inputs":{"restarts":3}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"methods","path":"/rows/0/1","approx":{"value":1620,"atol":0.5}}
//|       - {"artifact":"methods","path":"/rows/0/2","approx":{"value":1620,"atol":0.5}}
//|       - {"artifact":"methods","path":"/rows/1/1","approx":{"value":1575,"atol":0.5}}
//|       - {"artifact":"methods","path":"/rows/2/1","approx":{"value":1574,"atol":0.5}}
//|       - {"artifact":"methods","path":"/rows/2/2","approx":{"value":1574,"atol":0.5}}
//|       - {"artifact":"methods","path":"/rows/2/3","approx":{"value":14,"atol":0.5}}
//|       - {"artifact":"methods","path":"/rows/0/4","equals":253}
//|       - {"artifact":"methods","path":"/rows/0/5","range":{"min":0}}
//|       - {"artifact":"methods","path":"/rows/1/5","equals":null}
//|       - {"artifact":"methods","path":"/rows/1/6","equals":"Converged"}
//|   - case: restarts-3
//|     expect:
//|       - {"artifact":"methods","path":"/rows/1/1","approx":{"value":1560,"atol":0.5}}
//|       - {"artifact":"methods","path":"/rows/1/3","approx":{"value":0,"atol":0.5}}
//|       - {"artifact":"methods","path":"/rows/1/4","equals":1}
//|       - {"artifact":"methods","path":"/rows/2/1","approx":{"value":1574,"atol":0.5}}
use scioxide_linalg::Matrix;
use scioxide_optimize::{QapDirection, QapMethod, QapOptions, QapProblemView};

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let fixed1 = serde_json::json!({ "fractionDigits": 1 });
let n = instance["size"].as_u64().ok_or("Missing facility count")? as usize;
let maximize = instance["maximize"].as_bool().ok_or("Missing direction")?;
let optimum = instance["optimum"].as_f64().ok_or("Missing optimum")?;
let flow: Vec<f64> =
    serde_json::from_value(instance["flow"].clone()).map_err(|e| e.to_string())?;
let distance: Vec<f64> =
    serde_json::from_value(instance["distance"].clone()).map_err(|e| e.to_string())?;
let values: Vec<f64> =
    serde_json::from_value(instance["values"].clone()).map_err(|e| e.to_string())?;
// Independent check: directly sum the original double-sum definition.
let double_sum = |p: &[usize]| -> f64 {
    (0..n)
        .map(|i| {
            (0..n)
                .map(|j| flow[i * n + j] * distance[p[i] * n + p[j]])
                .sum::<f64>()
        })
        .sum()
};
let better = |a: f64, b: f64| if maximize { a > b } else { a < b };
let a = Matrix::from_vec(n, n, flow.clone()).map_err(|e| e.to_string())?;
let b = Matrix::from_vec(n, n, distance.clone()).map_err(|e| e.to_string())?;
let plan = QapProblemView::new(a.view(), b.view(), &[])
    .map_err(|e| e.to_string())?
    .prepare()
    .map_err(|e| e.to_string())?;
let sense = if maximize {
    QapDirection::Maximize
} else {
    QapDirection::Minimize
};
let mut rows = Vec::new();
let mut marks =
    vec![serde_json::json!({"kind": "line", "axis": "x", "value": optimum, "label": "Optimum"})];
for (name, method) in [
    ("Faq", QapMethod::Faq),
    ("TwoOpt", QapMethod::TwoOpt),
    ("FaqThenTwoOpt", QapMethod::FaqThenTwoOpt),
] {
    let options = QapOptions::default()
        .with_method(method)
        .with_max_workspace_bytes(1_000_000)
        .with_restarts(restarts.round() as usize);
    let result = plan
        .solve_with_options(sense, None, &options)
        .map_err(|e| e.to_string())?;
    let (Some(p), Some(reported)) = (result.permutation(), result.objective()) else {
        return Err(format!("{name}: no candidate ({})", result.termination()));
    };
    let rank = 1 + values.iter().filter(|&&v| better(v, reported)).count();
    marks.push(
        serde_json::json!({"kind": "line", "axis": "x", "value": reported, "label": name}),
    );
    rows.push((
        name,
        reported,
        double_sum(p),
        (reported - optimum).abs(),
        rank,
        result.fw_gap(),
        result.termination().to_string(),
    ));
}
// Bin all permutation objectives into 24 histogram intervals.
let (low, high) = values
    .iter()
    .fold((f64::INFINITY, f64::NEG_INFINITY), |(l, h), &v| {
        (l.min(v), h.max(v))
    });
let width = (high - low) / 24.0;
let mut counts = vec![0_usize; 24];
for &v in &values {
    counts[(((v - low) / width) as usize).min(23)] += 1;
}
let histogram: Vec<[f64; 3]> = counts
    .iter()
    .enumerate()
    .map(|(i, &c)| {
        [
            low + i as f64 * width,
            low + (i + 1) as f64 * width,
            c as f64,
        ]
    })
    .collect();
emit_histogram!(
    &histogram,
    options = &serde_json::json!({
        "xLabel": "Objective F(π) [flow×distance]",
        "yLabel": "Permutations [count]",
        "annotations": marks
    })
);
let columns = serde_json::json!([
    { "key": "0", "label": "Method" },
    { "key": "1", "label": "Reported objective [flow×distance]", "type": "number", "format": fixed1 },
    { "key": "2", "label": "Recomputed double sum [flow×distance]", "type": "number", "format": fixed1 },
    { "key": "3", "label": "Difference from optimum [flow×distance]", "type": "number", "format": fixed1 },
    { "key": "4", "label": "Rank among all permutations [rank]", "type": "integer" },
    { "key": "5", "label": "fw_gap [flow×distance]", "type": "number", "format": sci3, "nullText": "None" },
    { "key": "6", "label": "Termination reason" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "methods" })
);
```

On the default problem, Faq gives 1620 (gap 60, rank 253), TwoOpt from the identity gives 1575 (gap 15, rank 10), and FaqThenTwoOpt gives 1574 (gap 14, rank 8); all three terminate with `Converged`.
`Converged` means the FAQ step criterion and 2-opt local optimality condition were met; it does not mean the optimum was reached.
Faq's `fw_gap` is 12.6 rather than 0, but it stops because the step size falls below its threshold.
Reported objectives match recomputed double sums; the three values cluster at the lower end of the histogram.

With 3 additional restarts, TwoOpt starting from a random permutation reaches the optimum 1560, while FaqThenTwoOpt remains at 1574.
With 5 restarts, FaqThenTwoOpt also falls to 1564 (gap 4, rank 2).
Selecting maximization in the preceding cell leaves Faq at 2130 (rank 32), 52 below the optimum 2182, despite stopping at an endpoint with `fw_gap` = 0; TwoOpt and FaqThenTwoOpt reach 2182.
A zero gap still does not establish permutation optimality.
At $n=5$, FaqThenTwoOpt reaches the optimum 508, Faq gives 527 (rank 7), and TwoOpt gives 517 (rank 3).
Other seeds can produce problems where FAQ outperforms 2-opt; at seed 1, Faq gives 1607, TwoOpt 1617, and the optimum is 1601.
At seed 1, Faq reaches the 30-iteration FAQ limit and stops with `IterationLimit`.

## Checking reported values

When a completed trial exists, `QapResult` returns a checked permutation in `permutation()` and its objective recomputed from the original matrices in `objective()`.
Even so, substituting the permutation into the original definition yourself can detect confusion about matrix orientation (`permutation[i]` is the `b` index assigned to index $i$ of `a`).
`QapPlan::objective(permutation)` also substitutes a permutation into the original problem to return its objective; a wrong length or a permutation violating a fixed pair gives `InvalidInput`.

`fw_gap()` is the Frank–Wolfe gap from the selected trial's last FAQ iteration, indicating first-order stationarity of the relaxation.
It is neither an upper bound on the gap to the permutation optimum nor a lower bound on the relaxation.
`relaxation_objective()` is the relaxed objective at the point after that iteration's update; the relaxation is generally nonconvex, so this value cannot be used as a lower bound on the original minimum.
Without a completed trial, `permutation()` and `objective()` are `None`; do not interpret this as a zero-cost solution.
`TwoOpt` does not use FAQ, so `fw_gap()` and `relaxation_objective()` are `None`.

## Evaluating larger problems

For problems too large for exhaustive search, assess results against sourced known optima (such as QAPLIB), improvements from restarts, and comparisons of different method objects.
Several permutations can have the same objective, so different permutations found from different seeds need not indicate an error.
Symmetric location layouts give symmetric permutations the same objective.
Check fixed matches, objectives, and differences from known values rather than relying only on exact permutation equality.

## Summary

Small problems permitting exhaustive search directly measure FAQ and 2-opt optimality gaps and ranks among all permutations.
In this example, all three methods stop with `Converged` without reaching the optimum; termination reasons and `fw_gap` = 0 do not establish global optimality.
Check whether additional restarts or method combinations improve the objective; cessation of improvement is not evidence of optimality either.
Recompute reported objectives from the original double sum or `QapPlan::objective`; do not read `fw_gap` or `relaxation_objective` as bounds on the permutation optimum.
For larger problems, assess results using sourced known values and improvement from restarts.
