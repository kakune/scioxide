This page summarizes heuristic global search methods over finite search boxes.
Pass the problem as `BoundedObjective`, which bundles an objective with scioxide-core `Bounds` ([Shared contracts for objectives, constraints and results](../problems-and-results/)); both endpoints of every variable must be finite, with the lower endpoint strictly smaller than the upper.
An infinite endpoint on either side gives `InvalidInput` (`UnsupportedConfiguration`); equal endpoints give `InvalidInput` (`OutOfRange`).
On every call, search copies the box into a checked `FiniteBounds` and passes it to the start design and proposal generator.
Multistart, basin hopping and dual annealing share start design `StartDesign`, injected local solver `LocalSolverFactory` and random source `SearchRandom` recording generated sample counts; `GlobalSearchResult` retains the history of all trials.
Differential evolution manages its own population and returns results as `OptimizeResult`.
None of these methods returns a proof of global optimality.

## Shared conventions

- Termination: exhausting trials or generations gives `SearchBudgetCompleted`; a differential-evolution population objective spread below tolerance gives `PopulationStagnation`.
  Both are unsuccessful, with `is_success()` false, and retain the best finite point observed.
  Stops at limits, cancellation or deadlines also return observations so far with termination reasons such as `IterationLimit`, `EvaluationLimit`, `SampleLimit`, `TimeLimit` or `Cancelled`.
- Randomness: multistart, basin hopping and dual annealing derive trial seeds from the parent seed using `scioxide_random::seed_sequence` (the SplitMix64 output sequence); each trial draws uniform 64-bit words (`next_uniform_u64`) from `Xoshiro256**` initialized with its seed and decodes them to $[0, 1)$.
  Differential evolution uses one `Xoshiro256**` sequence initialized with the configured seed.
  The same seed and objective reproduce the same trial sequence.
- Memory: prepare storage matching the requirements with the method's `workspace(dimension)`.
  Workspace owns local solver state, keeping trial records and accepted state separately.
  Errors leave the caller's output unchanged.
- Local failures: `ConvergenceFailure`, `NumericalInstability` and `Singular` returned by a local solver, and local execution stops (`ExecutionStopped`), remain in trial reports and are not converted to success.
  Other errors (inconsistent input, provider failures and so on) stop the entire search.
- Time: `with_time_limit` limits are available only when the supplied context has clock capability.
  Solving with such a limit in a context without a clock (such as a Wasm cell) returns a `CapabilityUnavailable` error.

## Summary

Choose `MultiStart` to optimize starts independently, `BasinHopping` to propose from accepted points and explore different basins of local minima, `DualAnnealing` for temperature-dependent visiting distributions and reheating, or `DifferentialEvolution` to evolve a population without a local solver.
For a single finite-box search without selecting settings, use differential-evolution `minimize_global`, which takes a seed argument.
The first three allow replacement of the local factory (multistart also allows a different start design, and basin hopping a different proposal generator); distinguish `best()` and `best_successful()` in `GlobalSearchResult`.
Recording seeds and trial counts makes results reproducible; repetitions with different seeds estimate how often basins are missed.
`SearchBudgetCompleted` and `PopulationStagnation` are not success, so refine returned points with a local solver and reevaluate gradients or constraints in the original problem before using them.
