`scioxide-optimize` provides unconstrained and bounded local optimization, nonlinear constrained optimization, nonlinear and linear least squares, linear programming (LP), quadratic programming (QP), mixed-integer linear programming (MIP), quadratic assignment, proximal methods and ADMM, stochastic first-order methods for sampled objectives, multiobjective optimization, and global search.
This guide identifies items by task and lists all 334 public items in tables across 10 purpose-grouped pages.
Item-name links point to the version 0.1.0 API reference on docs.rs.

## Type relationships

- Problems: supply objectives through `ObjectiveFunction` (returns values, writes gradients and Hessians to outputs, and uses `Ok(false)` for “not provided”) or the closure wrapper `ObjectiveFn`.
  Derivative closures of `ObjectiveFn` write every component into solver-supplied output storage.
  Nonlinear constraints use immutable `Constraints` collecting `ConstraintFunction`; residuals use `LeastSquaresProblem` or `LeastSquaresFn`.
  LP, QP, and MIP validate and store owned coefficients in `LpProblem`, `QpProblem`, and `MipProblem`.
- Call forms: three levels support different configuration needs, named according to the [call forms](oxref:optimize-call-forms) table.
  - One-shot functions: `minimize` (BFGS), `minimize_bounded` (L-BFGS-B), `minimize_constrained` (SQP), `minimize_scalar` (Brent), `minimize_global` (differential evolution), `least_squares` and `curve_fit` (Levenberg–Marquardt), `nnls`, `bvls`, and `quadratic_assignment` (FAQ and 2-opt), plus `LpProblem::solve` (revised simplex), `QpProblem::solve` (automatic convex QP selection), and `MipProblem::solve` (branch and bound), accept only problem data and solve with defaults.
    Unsuccessful solves return structured errors.
    However, `minimize_global` returns `PopulationStagnation` and `SearchBudgetCompleted` after completing the differential evolution schedule as results.
  - Method objects: solver types (such as `Bfgs`, `Sqp`, and `QpSolver`) retain validated settings (such as `BfgsOptions` and `SqpOptions`) immutably and can be called repeatedly with the same settings.
    Inherent `minimize` / `solve` methods allocate workspace and results internally and return complete results in `Ok` even for unsuccessful termination; call the result's `require_success()` to require success.
    Local methods, `LbfgsB`, nonlinear constrained methods, `DifferentialEvolution`, and `CmaEs` also implement common trait `Optimizer` for runtime solver selection; `problem` of `Optimizer::minimize(&problem, x0)` is an objective, `BoundedObjective`, or `ConstrainedProblem`.
    The only plan with precomputation is `QapPlan`, preparing copies of both matrices and free-node blocks in $O(n^2)$ work and memory.
  - Output-supplying API: use `minimize_into` / `solve_into` with prepared outputs, workspace, and execution scope.
    Scalar `ScalarMinimizer` has no workspace; its scope-accepting `minimize_scoped` also returns a newly allocated result.
    BFGS, NSGA-II, and stochastic first-order methods resume interrupted accepted states using workspace `checkpoint()` and solver `resume_into`.
- Derivatives: choose a derivative source, such as differences when derivatives are absent, through configuration `DerivativeStrategy`.
  Line-search BFGS, L-BFGS, steepest descent, nonlinear conjugate gradients, and Newton default to `AnalyticOrCentral` (central differences without analytic derivatives); other solvers supplying derivatives by differences default to `AnalyticOrForward` (forward differences).
- Workspace: each solver has its own workspace type (such as `BfgsWorkspace`, `LeastSquaresWorkspace`, or `GlobalSearchWorkspace`); another solver's workspace cannot be supplied.
  Callbacks write values and derivatives directly into output storage (trait `gradient_into` or closures of `ObjectiveFn`), so steady-state iteration allocates no new heap storage after dimension-specific preparation.
- Global search solvers: method objects (such as `MultiStart` and `Direct`) retain numerical and execution policies; finite boxes belong to `BoundedObjective`.
  Workspace owns providers such as local solvers and surrogate models.
  Options select random seeds (`minimize_global` takes a seed argument); parallel sample evaluation uses option policies and execution context capabilities.
- Results and evidence: local methods, constrained local methods, `DifferentialEvolution`, and `CmaEs` return `OptimizeResult`; nonlinear least squares returns `LeastSquaresResult`; LP, QP, and MIP return `ProgrammingResult` and `MipResult`; multistart, basin hopping, and dual annealing return `GlobalSearchResult`; DIRECT, SHGO, surrogate search, proximal methods, ADMM, quadratic assignment, stochastic first-order methods, and NSGA-II return their own result types (such as `DirectResult`, `ShgoResult`, `ProximalResult`, `StochasticResult`, and `Nsga2Result`).
  Each has one authoritative `OptimizeTermination` termination reason; feasibility, stationarity, complementarity, and other residuals are stored separately in `OptimalityDiagnostics`.
  Verify LP and QP solutions and certificates independently of solver state by passing `LpProblem` and `QpProblem` themselves (or borrowed `LpVerificationProblem` and `QpVerificationProblem`) to `ProgrammingVerifier::verify`.

## Workspace, cancellation, and resumption example

For a single solve without choosing settings, pass a value-returning closure `f` and initial point to `minimize(f, &x0)`; unsuccessful solves return errors.
The next cell demonstrates repeated same-size problems and externally interrupted solves continued later.

The Rosenbrock function $f(x) = (1 - x_1)^2 + 100\,(x_2 - x_1^2)^2$ has minimizer $(1, 1)$ and minimum 0.
The next cell allocates dense BFGS workspace and result storage once, then requests cancellation through `CancellationToken` after a specified number of objective evaluations.
The cancelled call returns `Ok` with unsuccessful termination `Cancelled` and retains accepted iterates in the result.
It then creates an owned `BfgsCheckpoint` from workspace, clears cancellation, and continues with `resume_into`.
The table lists each call's termination reason, attempt outcome recorded by workspace (`AttemptOutcome` of `last_attempt()`), objective evaluations counted by `counts()`, and callback-counted evaluations.
The last two columns check against the known minimizer; the cell's conclusion uses the last call's termination reason.

```rust
//| id: optimize-api-bfgs-lifecycle
//| ref: optimize-api-bfgs-lifecycle
//| title: "Solve BFGS with workspace and resume from a cancelled point"
//| run: reactive
//| crates: [scioxide-core, scioxide-optimize]
//| inputs:
//|   cancel_after: {"type":"range","label":"Objective evaluation count requesting cancellation [count]","description":"Request cancellation after this many objective evaluations, then continue by resumption.","min":1,"max":80,"step":1,"value":12}
//|   start_x1: {"type":"range","label":"Initial point x₁ [-]","description":"Change x₁ of initial point (x₁, 1).","min":-2,"max":2,"step":0.1,"value":-1.2}
//| cases:
//|   - {"id":"cancel-at-first-evaluation","label":"Cancel at the first evaluation","description":"Stopping before accepting a gradient makes checkpoint return InvalidInput, so no resumption occurs. Only one objective evaluation occurs.","inputs":{"cancel_after":1}}
//|   - {"id":"no-cancellation","label":"No cancellation (80 evaluations)","description":"Cancellation never occurs; one call reaches GradientSmall after 37 iterations and 66 evaluations.","inputs":{"cancel_after":80}}
//|   - {"id":"start-left-edge","label":"Initial point (−2, 1)","description":"Cancellation follows the initial-point evaluation (0 accepted iterations, f = 909); resumption succeeds in 26 iterations.","inputs":{"start_x1":-2}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"calls","path":"/rows/0/1","equals":"Cancelled"}
//|       - {"artifact":"calls","path":"/rows/0/2","equals":false}
//|       - {"artifact":"calls","path":"/rows/0/3","equals":"Stopped"}
//|       - {"artifact":"calls","path":"/rows/0/6","equals":12}
//|       - {"artifact":"calls","path":"/rows/1/0","equals":"resume_into"}
//|       - {"artifact":"calls","path":"/rows/1/1","equals":"GradientSmall"}
//|       - {"artifact":"calls","path":"/rows/1/2","equals":true}
//|       - {"artifact":"calls","path":"/rows/1/4","range":{"min":35,"max":39}}
//|       - {"artifact":"calls","path":"/rows/1/7","range":{"min":0,"max":1e-12}}
//|       - {"artifact":"calls","path":"/rows/1/8","range":{"min":0,"max":1e-6}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: cancel-at-first-evaluation
//|     expect:
//|       - {"artifact":"calls","path":"/rows/0/1","equals":"Cancelled"}
//|       - {"artifact":"calls","path":"/rows/0/4","equals":0}
//|       - {"artifact":"calls","path":"/rows/0/6","equals":1}
//|       - {"artifact":"calls","path":"/rows/1/0","equals":"checkpoint"}
//|       - {"artifact":"calls","path":"/rows/1/1","equals":"Err(InvalidInput)"}
//|       - {"artifact":"calls","path":"/rows/1/4","equals":null}
//|       - {"path":"/outputs/1/state","equals":"partial"}
//|   - case: no-cancellation
//|     expect:
//|       - {"artifact":"calls","path":"/rows/0/1","equals":"GradientSmall"}
//|       - {"artifact":"calls","path":"/rows/0/4","range":{"min":35,"max":39}}
//|       - {"artifact":"calls","path":"/rows/0/6","equals":66}
//|       - {"artifact":"calls","path":"/rows/0/8","range":{"min":0,"max":1e-6}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: start-left-edge
//|     expect:
//|       - {"artifact":"calls","path":"/rows/0/4","equals":0}
//|       - {"artifact":"calls","path":"/rows/0/7","approx":{"value":909,"rtol":1e-9}}
//|       - {"artifact":"calls","path":"/rows/1/1","equals":"GradientSmall"}
//|       - {"artifact":"calls","path":"/rows/1/4","range":{"min":24,"max":28}}
use core::sync::atomic::{AtomicUsize, Ordering};
use scioxide_core::{
    CancellationToken, EvaluationRole, ExecutionContext, SciOxideError, RealScalar,
};
use scioxide_optimize::{
    Bfgs, BfgsWorkspace, ObjectiveFunction, OptimizeResult, OptimizeTermination,
};

// Rosenbrock f(x) = (1 - x₁)² + 100 (x₂ - x₁²)². Known minimizer (1, 1), minimum 0.
// Count objective evaluations and request cancellation at the specified count (standing in for external interruption).
struct Rosenbrock<'a> {
    token: &'a CancellationToken,
    calls: AtomicUsize,
    cancel_after: usize,
}
impl ObjectiveFunction<f64> for Rosenbrock<'_> {
    fn dim(&self) -> usize {
        2
    }
    fn eval(&self, x: &[f64]) -> Result<f64, SciOxideError> {
        if self.calls.fetch_add(1, Ordering::Relaxed) + 1 == self.cancel_after {
            self.token.cancel();
        }
        let a = 1.0 - x[0];
        let b = x[1] - x[0] * x[0];
        Ok(a * a + 100.0 * b * b)
    }
    // Write the analytic gradient to output and return true to signal availability.
    fn gradient_into(&self, x: &[f64], g: &mut [f64]) -> Result<bool, SciOxideError> {
        let r = x[1] - x[0] * x[0];
        g[0] = -2.0 * (1.0 - x[0]) - 400.0 * x[0] * r;
        g[1] = 200.0 * r;
        Ok(true)
    }
}

let token = CancellationToken::new();
let problem = Rosenbrock {
    token: &token,
    calls: AtomicUsize::new(0),
    cancel_after: cancel_after as usize,
};
let solver = Bfgs::<f64>::default();
// Allocate workspace and result storage once and reuse them for two calls.
let mut workspace = solver.workspace(2).map_err(|e| e.to_string())?;
let mut result = OptimizeResult::<f64>::empty();
let context = ExecutionContext::sequential().with_cancellation(&token);
solver
    .minimize_into(
        &problem,
        &[start_x1, 1.0],
        &mut result,
        &mut workspace,
        context,
    )
    .map_err(|e| e.to_string())?;
// Columns: call, termination reason, success, attempt outcome, accepted iterations, counts() objective evaluations,
// callback-counted evaluations, f(x), distance to known minimizer (1, 1) (independent check).
let row = |label: &'static str, r: &OptimizeResult<f64>, ws: &BfgsWorkspace<f64>, calls| {
    let attempt = ws.last_attempt().map(|a| format!("{:?}", a.outcome()));
    (
        label,
        r.termination().to_string(),
        Some(r.is_success()),
        attempt.unwrap_or_default(),
        Some(r.iterations()),
        Some(r.counts().own().provider(EvaluationRole::Objective)),
        calls,
        Some(r.fun()),
        Some(RealScalar::hypot(r.x()[0] - 1.0, r.x()[1] - 1.0)),
    )
};
let first_calls = problem.calls.load(Ordering::Relaxed);
let mut rows = vec![row("minimize_into", &result, &workspace, first_calls)];
if !result.is_success() {
    // Copy accepted point, gradient, and inverse Hessian approximation into an owned checkpoint, clear cancellation, and continue.
    match workspace.checkpoint() {
        Ok(checkpoint) => {
            token.reset();
            solver
                .resume_into(&problem, &checkpoint, &mut result, &mut workspace, context)
                .map_err(|e| e.to_string())?;
            let calls = problem.calls.load(Ordering::Relaxed) - first_calls;
            rows.push(row("resume_into", &result, &workspace, calls));
        }
        Err(e) => rows.push((
            "checkpoint",
            format!("Err({:?})", e.kind()),
            None,
            "No accepted state".to_string(),
            None,
            None,
            0,
            None,
            None,
        )),
    }
}
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let fixed3 = serde_json::json!({ "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "Call" },
    { "key": "1", "label": "Termination reason" },
    { "key": "2", "label": "Success", "type": "boolean", "nullText": "-" },
    { "key": "3", "label": "Attempt outcome" },
    { "key": "4", "label": "Accepted iterations [count]", "type": "integer", "nullText": "-" },
    { "key": "5", "label": "counts() objective [count]", "type": "integer", "nullText": "-" },
    { "key": "6", "label": "Callback objective [count]", "type": "integer" },
    { "key": "7", "label": "f(x) [-]", "type": "number", "format": fixed3, "nullText": "-" },
    { "key": "8", "label": "‖x − (1, 1)‖₂ [-]", "type": "number", "format": sci2, "nullText": "-" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "calls" })
);

let termination = result.termination();
let outcome = match termination {
    _ if termination.is_success() => {
        Outcome::satisfied("The last call met the gradient stopping criterion")
    }
    OptimizeTermination::LineSearchFailed(_) => {
        Outcome::failed("Line search could not find an acceptable step length")
    }
    _ => Outcome::partial("Stopped by cancellation without an accepted state to resume")
        .explanation("The result contains the point accepted at cancellation."),
};
emit_outcome!(
    outcome
        .status(termination.to_string())
        .diagnostic("Accepted iterations", result.iterations() as f64, None)
        .diagnostic(
            "Objective evaluations",
            problem.calls.load(Ordering::Relaxed) as f64,
            None
        )
);
```

At default inputs (cancellation at objective evaluation 12, initial point $(-1.2, 1)$), the first call has 2 accepted iterations and $f = 4.60$, terminates with `Cancelled`, and records attempt outcome `Stopped`.
The resumed call reaches `GradientSmall` (success) at 37 cumulative accepted iterations, with $f = 8.3 \times 10^{-20}$ and distance $5.2 \times 10^{-10}$ from the known minimizer.
Without cancellation (80 evaluations), the same 37 iterations and objective give `GradientSmall`, using 66 objective evaluations.
Interruption and resumption use $12 + 55 = 67$ evaluations, adding only 1.

Resumption continues the solve recorded in the checkpoint rather than starting a new solve.
Resumed `iterations()` and `counts()` therefore inherit counts through the checkpoint; 67 objective evaluations in `counts()` match the callback's $12 + 55$ evaluations across both calls.
The iteration limit also counts cumulatively, so resuming a state stopped with `IterationLimit` under the same options adds no iterations.
Resuming with a differently configured solver gives `InvalidInput` because the checkpoint identifier does not match.

Cancellation at the first evaluation stops before accepting the gradient, leaving no resumable state; `checkpoint` returns `InvalidInput`.
The result is then `Cancelled` with the initial-point value ($f = 24.2$), and the cell's conclusion is `partial`.
With initial point $x_1 = -2$, cancellation follows initial evaluation (0 accepted iterations, $f = 909$), but its value and gradient were accepted, so resumption succeeds after 26 iterations.

## Reading results, errors, and diagnostics

- Errors: invalid input and execution failure return scioxide-core `SciOxideError`, classified by `kind()`.
  An initial-point dimension differing from `dim()` gives `DimensionMismatch`, nonfinite initial components give `NonFinite`, and malformed configuration or input gives `InvalidInput`; callback errors propagate to the caller.
  Workspace size limits give `ResourceLimit` and `SizeOverflow`; allocation failure gives `AllocationFailure`.
  Configuring a time limit without a clock in the execution context returns `CapabilityUnavailable` before invoking callbacks.
  Bind clocks through `ExecutionContext::with_clock` and supply cancellation through `with_cancellation`.
  One-shot functions and result `require_success()` convert unsuccessful termination into `ConvergenceFailure` carrying the reason and work counts, `ExecutionStopped` for cancellation or deadlines, and `DomainError` for verified infeasibility or unboundedness (full mappings in [termination classification](oxref:optimize-termination-classes)).
  Errors retain no caller identifier.
- Termination reasons: method-object calls that do not error report success or failure through one authoritative `OptimizeTermination`.
  `is_success()` is true only for `Converged` and `GradientSmall`.
  Unsuccessful termination includes lack of progress; iteration, time, and cancellation limits; completion of global or sampled-objective search; and infeasible or unbounded plan problems.
  The [termination classification](oxref:optimize-termination-classes) table lists retained results (last accepted point, best observed point, certificates) and converted errors for each category.
  Failure to find an acceptable line-search step gives `LineSearchFailed` with a cause (`IterationLimit`, `EvaluationLimit`, `StepSizeLimit`, or `Stagnation`).
  Stopping before accepting the first point leaves no result and gives a structured error.
  Gradient-based unconstrained local methods compare Euclidean gradient norm $\lVert\nabla f\rVert_2$ with tolerance; `LbfgsB` compares the $\infty$ norm of the projected gradient with active-bound components zeroed.
  Nonlinearly constrained local methods normalize the objective and constraint rows at the first derivative-evaluated point by their gradient $\infty$ norms (value magnitude or 1 if zero), and succeed only when normalized KKT residuals are within `OptimalityTolerances`.
  Returned diagnostics and multipliers are converted back to original units.
  LP, QP, and MIP succeed only when original-problem residuals meet these tolerances.
  Nonlinear least squares defaults to `LeastSquaresStopping::OriginalGradient`, tests the objective gradient norm, and returns `GradientSmall`; explicit `LeastSquaresStopping::Minpack` (dense Jacobians only) replaces this with Moré's criteria and can also return `Converged`.
- Global search and heuristics: global search claims neither convergence nor global optimality.
  A finite search limit gives `SearchBudgetCompleted`, while population contraction in differential evolution or CMA-ES gives `PopulationStagnation`; neither is success, and both return the best finite candidate found.
  DIRECT can also give `MemoryLimit` at a rectangle memory limit, and SHGO `NodeLimit` at a simplicial-complex limit.
  Global problems use `BoundedObjective` with a box whose endpoints are all finite; only surrogate search instead receives observation history `SurrogateHistory` and the objective.
- Sampled objectives: when a stochastic first-order method meets the gradient criterion, noiseless samples (`NoiseModel::Deterministic`) give `GradientSmall` (success), while independent noisy samples give estimated `EstimatedStationarity` (not success).
  Inability to resolve noise within the replication limit stops with `NoiseLimit`, also not success.
  Multistart results distinguish best candidate `best()` regardless of local success from `best_successful()`, the best locally successful candidate.
- Mathematical programming: read primal feasibility, stationarity, dual feasibility, complementarity, integrality, variable bounds, and optimality gaps separately from `OptimalityDiagnostics` in LP, QP, and MIP results.
  Before returning `Converged`, `Infeasible`, or `Unbounded`, LP and QP solvers independently check dual variables, Farkas multipliers, or recession-direction evidence in original coordinates; failed verification downgrades them to `Stagnation`, `SuspectedInfeasible`, or `SuspectedUnbounded`.
  Reports from `ProgrammingVerifier::verify` distinguish `Accepted`, `Rejected`, `KktOnly` (KKT passed but QP global convexity was not established), and `Incomplete` (interrupted by resource limits) through `VerificationStatus`.
  This is floating-point numerical evidence under tolerances, not a certified enclosure.
  `MipResult::absolute_gap` is the actual numerical gap, not an exact-arithmetic certificate.
- Work counts: result `counts()` returns scioxide-core `SolveCounts`, counting actually called providers (objective, gradient, Hessian, constraints, and so on) by role (`EvaluationRole`), including failed derivative attempts.
  Nested solves (such as global search with inner local solvers) expose own work in `own()` and descendant work in `nested()`; obtain totals through checked `total()`.
  Resumed solve `counts()` includes work through the checkpoint, as in the cell above.
- Method-specific diagnostics: `OptimizeResult::method_diagnostics()` uses `OptimizeDiagnostics` variants (`FirstOrder`, `Newton`, `NelderMead`, `Powell`, `Sqp`, `InteriorPoint`, `Cobyla`, `Cobyqa`, `Unavailable`) to report observations of line-search globalization, trust regions, simplex geometry, subproblems, and related quantities.

## Summary

Choose methods by problem structure and supply objectives and constraints through traits such as `ObjectiveFunction` or closure adapters.
For a single default solve, use functions such as `minimize` or `LpProblem::solve`, receiving unsuccessful solves as errors.
For repeated solves, allocate each solver's workspace once; BFGS handles interruption and resumption with `minimize_into` output storage and checkpoints.
Method-object calls use errors for invalid inputs or execution failure and report unsuccessful termination through `OptimizeTermination` in an `Ok` result; inspect `is_success()` and residual diagnostics or convert to an error with `require_success()`.
Interpret global search and mathematical programming results through retained candidates, residuals, and gap evidence rather than a convergence claim.
