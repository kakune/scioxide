These tables summarize branch and bound for linear programs containing integer-restricted variables (mixed-integer linear programming, MILP), and heuristics for choosing a permutation in the quadratic assignment problem (QAP).
Both accept configurable search and memory limits.
When a configured method stops at a search limit, it returns the best candidate checked so far with a termination reason in the `Ok` result, rather than returning `Err`.
The single-solve default entry points `MipProblem::solve()` and `quadratic_assignment` return structured errors unless successful.
QAP memory limits are checked before solving; exceeding them produces a `ResourceLimit` error.
The gap in a MILP result is a numerically checked floating-point quantity, rather than an exact-arithmetic proof of optimality.
A QAP result checks that the permutation is bijective and checks its objective, without claiming global optimality.

## Quadratic assignment

For $n \times n$ matrices $A$ and $B$, the quadratic assignment problem chooses a permutation $p$ to minimize (or maximize) $\sum_{i,j} A_{ij} B_{p(i)\,p(j)}$.
FAQ (Fast Approximate QAP) solves a relaxation over doubly stochastic matrices by Frank–Wolfe, then projects to a permutation by linear assignment.
2-opt improves the objective by swapping two assignments.

## Summary

Write MILPs as `MipProblem`, adding integer-variable indices to `LpProblem`; use `MipProblem::solve()` for defaults, or choose node and pivot counts and `MipLimits` for `BranchAndBound` to suit the application.
Read `termination` together with `has_incumbent`, `absolute_gap` and `global_lower_bound`; after a limit stop, decide whether the gap is acceptable for the application.
To inspect the frontier after interrupting search, read `MipSearchState` from `BranchAndBoundWorkspace::state()`; to use another LP solver, implement `MipRelaxationSolver` and pass it to `BranchAndBoundWorkspace::new`.
Use `quadratic_assignment` to solve a QAP once with default settings.
For partial results or configurable settings, create `QapPlan` from `QapProblemView`, explicitly set `QapOptions` limits and restart seed, solve, and check the returned permutation's objective with `QapPlan::objective`.
`fw_gap` and `relaxation_objective` describe the relaxation; do not read them as proofs of permutation optimality.
