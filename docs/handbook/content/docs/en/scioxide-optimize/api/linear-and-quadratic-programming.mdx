These tables summarize LP and convex QP inputs, solvers and results, and verifiers that check the evidence attached to results in the original coordinates.
Failed input checks (shape, non-finite values, symmetry or convexity) return `Err`; when computation ends at a limit or stop request, the `Ok` result contains the termination reason `OptimizeTermination`.
Before assigning termination reasons `Converged`, `Infeasible` or `Unbounded`, LP and QP solvers independently check evidence for the original problem (dual variables, Farkas multipliers or a recession direction); failed checks downgrade the reason to `Stagnation`, `SuspectedInfeasible` or `SuspectedUnbounded`.
Verification reports provide numerical evidence under floating-point tolerances, rather than interval-arithmetic enclosures with guaranteed containment.
The LP and QP result type `ProgrammingResult` appears in the tables in [Shared contracts for objectives, constraints and results](../problems-and-results/).
Use `LpProblem::solve()` and `QpProblem::solve()` for a single solve with default settings; verified infeasibility or unboundedness returns `DomainError`, and other unsuccessful terminations return the same errors as `ProgrammingResult::require_success`.

## Evidence and independent verification

The verifier checks only the supplied evidence in the original coordinates; it does not solve again for replacement multipliers.
The caller supplies the primal point and dual variables; the verifier measures primal feasibility, variable bounds, multiplier signs, stationarity (the Lagrangian gradient), complementarity and objective gap separately.

## Summary

Write LPs with `LinearConstraints` and `LpProblem` (variables without bounds become nonnegative); use `LpProblem::solve()` for a single default-simplex solve, or `SimplexSolver` or `InteriorPointLp` to choose settings.
For QP, explicitly choose the interpretation of Hessian symmetry with `QpProblem` and solve with `QpProblem::solve()` or `QpSolver`.
Both reject nonconvex problems with `Err` and treat variables without bounds as free.
Read `is_success` and whether the termination reason is `Suspected…` or `Stagnation`, then inspect residuals in original coordinates and the evidence in `certificate()`.
To check a claim independently of the solver, pass the original problem (`LpProblem` or `QpProblem` itself) to `ProgrammingVerifier::verify` or `ProgrammingVerifier::verify_into` and read `VerificationStatus` together with `objective_gap` and `dual_bound`.
These provide numerical evidence under floating-point tolerances; `KktOnly` means convexity has not been confirmed.
