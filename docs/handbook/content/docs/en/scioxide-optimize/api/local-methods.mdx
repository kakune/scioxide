This table collects solvers seeking a local minimizer near a starting point and their option, workspace, and diagnostic types.
All are local methods; only `Converged` and `GradientSmall` indicate successful termination.
A small gradient is a first-order stopping criterion, not a proof of a local minimum.
Iteration or evaluation limits, line-search failure, stagnation, cancellation, and deadlines return the last accepted point in `Ok` with an unsuccessful termination reason.
Stopping before the first observation, invalid inputs, callback failures, and numerical failures give `SciOxideError`.
Build settings by value and pass them to solvers; solver `new` validates Nelder–Mead and Powell settings.
Workspace types are solver-specific; another solver's workspace cannot be supplied.

## Call forms

For a single default solve, `minimize(f, x0)` (BFGS) and `minimize_bounded(f, x0, &bounds)` (L-BFGS-B) accept only a value-returning closure and initial point, returning structured errors without success.
To choose options, construct a solver value (such as `Bfgs`) and use its inherent `minimize(problem, x0)` method.
This owning API allocates workspace and results internally and returns unsuccessful termination in an `Ok` result; call result `require_success()` to require success.
The same call is available through `Optimizer` for runtime solver selection.
For repeated solves, prepare memory with `workspace_requirements(n)` and `workspace(n)` (`TrustRegionWorkspaceRequest` for trust regions), then use `minimize_into(problem, x0, output, workspace, scope)`.
Supply the final scope from a root `ExecutionContext` or a child `SolveContext` charging work to a parent solve.
No separate caller-identity argument is needed.

Workspace stores attempt records separately from accepted points.
Interpret method diagnostics as `OptimizeDiagnostics` variants returned by `OptimizeResult::method_diagnostics()`.
Obtain an owned BFGS resumption snapshot through `checkpoint()` and pass it to `resume_into`.
For L-BFGS-B or bounded Powell, pass `BoundedObjective` combining the objective and box.

## Summary

For smooth gradient-available problems, choose `Bfgs` for few variables, `Lbfgs` or `NonlinearCg` for many, or `LbfgsB` for box bounds; use `NewtonOptimizer` or `TrustRegionOptimizer` when accurate Hessians are inexpensive.
For many variables with only HVP available, use `TrustRegionOptimizer` with `TrustRegionSubproblem::SteihaugCg`.
For a few variables without derivatives, use `NelderMead` or `Powell`, which also handles bounds and fixed variables.
For every solver, determine success through `termination()`; results from `IterationLimit`, `LineSearchFailed`, `Stagnation`, or `EvaluationLimit` are only the best accepted points.
For a single default solve, use `minimize` or `minimize_bounded` and receive unsuccessful termination as an error.
For repeated same-size problems, allocate workspace once; BFGS handles interruption and resumption through `minimize_into` attempt records and `BfgsCheckpoint`.
