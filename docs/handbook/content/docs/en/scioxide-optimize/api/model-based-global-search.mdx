This page summarizes global searches that build models or partitions of the objective landscape during search.
CMA-ES adapts a normal distribution's mean and covariance; DIRECT partitions the box into rectangles and deterministically selects samples; SHGO selects local-minimum candidates from the samples' Delaunay simplicial complex; surrogate search fits models to observations of expensive objectives to propose the next evaluation point.
The searches themselves use only objective values (injected local solvers may use derivatives), and none returns a proof of global optimality.

## Shared conventions

- Termination: reaching computation-count or other limits produces unsuccessful termination such as `SearchBudgetCompleted`, retaining the best finite point observed.
  CMA-ES stagnation gives `PopulationStagnation`; DIRECT exhaustion of selectable rectangles gives `Stagnation`.
- Finite boxes: CMA-ES, DIRECT and SHGO accept `&BoundedObjective`, bundling an objective with scioxide-core `Bounds` ([Shared contracts for objectives, constraints and results](../problems-and-results/)); an infinite endpoint on either side gives `InvalidInput` (`UnsupportedConfiguration`).
  CMA-ES and SHGO also require lower endpoints strictly below upper endpoints; DIRECT treats equal endpoints as fixed coordinates.
  For surrogate search, the problem is `SurrogateHistory`, holding finite box `FiniteBounds` and observations.
  An initial point or design-generated point outside the box gives `InvalidInput`.
- Randomness and reproducibility: CMA-ES and SHGO default to seed 42.
  CMA-ES uses one seeded `Xoshiro256**` sequence; SHGO derives a seed per sample and initializes each `Xoshiro256**` separately.
  DIRECT is deterministic and uses no randomness.
  Surrogate search generates acquisition-function starts from a seed.
- Memory: prepare matching storage with the method's `workspace(dimension)` for CMA-ES, DIRECT and SHGO, or `workspace()` for surrogate search.
  Methods using local solvers also keep their state in workspace.
  CMA-ES, DIRECT and SHGO workspaces expose latest-trial records `last_attempt()` and accepted best points `last_accepted()`; surrogate-search workspace exposes only `last_attempt()`.
  Errors leave the caller's output unchanged.
  In surrogate search, however, observations appended to history before an error remain.
- Local solvers: optional final local optimization in CMA-ES and local optimization in SHGO use the same `SearchLocalSolver` and `LocalSolverFactory` as [Multistart, basin hopping, dual annealing and differential evolution](../global-search/).
  Local `ConvergenceFailure`, `NumericalInstability` and `Singular` are recorded and search continues.

## Surrogate search

Surrogate search fits a model to observation history $\{(x_i, y_i, \sigma_i^2)\}$ for an expensive objective, then proposes and evaluates points maximizing an acquisition function (a function measuring the value of the next evaluation).
Model fitting and prediction use scioxide-interp types; `MultiStart` searches for proposal points.

## Summary

Choose `CmaEs` for continuous smooth but ill-conditioned, nonseparable landscapes, `Direct` for low-dimensional boxes needing reproducible evaluation points without randomness, `Shgo` for low-dimensional problems where sampled landscapes supply local-minimum candidates to enumerate and refine, or `SurrogateSearch` for expensive objectives requiring only tens to hundreds of evaluations.
DIRECT and SHGO declare storage and geometry limits in settings, rejecting oversized problems before computation.
Every method returns only the best observed point and search diagnostics, without proving global optimality.
Refine returned points with a local solver and compare different seeds, other methods or known lower bounds before accepting them.
