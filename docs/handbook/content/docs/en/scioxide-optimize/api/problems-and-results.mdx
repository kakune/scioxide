This table collects input and output types shared by the solvers.
Supply objective $f:\mathbb R^n\to\mathbb R$, residual vector $r(x)$, and constraints $h(x)=0$ / $g(x)\le 0$ through traits or closure adapters; read output through the point, objective value, authoritative termination reason, and optimality diagnostics of `OptimizeResult`.
Closure adapters check only input and output lengths; mismatches give `DimensionMismatch` before the closure is called.
Derivative closures write all components directly into solver-supplied outputs, so adapters allocate nothing per call.
Solvers rather than adapters check nonfinite objective values, constraint values, residuals, and derivatives: errors at the starting point and rejection at trial points.
Iteration limits, stagnation, and other stops give an `Ok` result with unsuccessful termination; inspect `is_success()` and diagnostics.
To require success, use result `require_success()` to convert unsuccessful termination into structured errors.

The variants of `OptimizeTermination` have the following meanings.
Only the first row's two variants indicate success; receiving results from other variants does not establish an optimum.
The last column gives errors from `require_success()` and one-shot functions; `ConvergenceFailure` carries a reason (`ConvergenceReason`) and work counts.
However, `minimize_global` returns differential evolution termination `PopulationStagnation` or `SearchBudgetCompleted` as a result rather than an error.

| Termination reason | Meaning | Success? | `require_success()` error |
|---|---|---|---|
| `Converged`, `GradientSmall` | Met all method-specific stopping checks (such as gradient or KKT residuals) | Yes | None |
| `LineSearchFailed(LineSearchFailure)` | Local line search could not accept a trial (causes `IterationLimit`, `EvaluationLimit`, `StepSizeLimit`, or `Stagnation` in `LineSearchFailure`). Reaching the solver's overall evaluation limit instead gives a resource termination such as `EvaluationLimit` | No | `ConvergenceFailure` (`NestedSolver`) |
| `NotStarted` | Output storage was created with `empty()` but no solve has run | No | `InvalidInput` (`Inconsistent`) |
| `IterationLimit`, `EvaluationLimit`, `TimeLimit`, `NodeLimit`, `DepthLimit`, `MemoryLimit`, `ProposalLimit`, `SampleLimit` | Reached limits on iterations, evaluations, time, branch-and-bound nodes, search depth, caller-specified memory, shared proposals, or random samples | No | `IterationLimit` and `EvaluationLimit` use same-named reasons; nodes, depth, and memory use `ResourceLimit(Node)`, proposals `ResourceLimit(Proposal)`, and samples `ResourceLimit(Sample)` in `ConvergenceFailure`. `TimeLimit` gives `ExecutionStopped` (`DeadlineReached`) |
| `Cancelled` | Stopped after observing an execution-context cancellation request | No | `ExecutionStopped` (`Cancelled`) |
| `StepSmall`, `FunctionChangeSmall`, `Stagnation` | Small steps, small objective changes, or lack of progress without meeting convergence criteria | No | `StepSmall` uses `StepSizeLimit`; others use `Stagnation` in `ConvergenceFailure` |
| `SearchBudgetCompleted`, `PopulationStagnation` | Global search completed its prescribed work or its population concentrated; no global optimality claim | No | `SearchBudgetCompleted` uses `IterationLimit`; `PopulationStagnation` uses `Stagnation` in `ConvergenceFailure` |
| `EstimatedStationarity`, `NoiseLimit` | Sample-estimated gradient and error margin are small (not a proof), or replication could not resolve noise | No | `ConvergenceFailure` (`Stagnation`) |
| `SuspectedInfeasible`, `SuspectedUnbounded` | Suspected infeasibility or unboundedness without accepted evidence | No | `SuspectedInfeasible` uses `Stagnation`; `SuspectedUnbounded` uses `Divergence` in `ConvergenceFailure` |
| `Infeasible`, `Unbounded` | Detected infeasibility or unboundedness | No | `DomainError` (`Undefined`) |

## Summary

Supply problems by implementing `ObjectiveFunction`, `LeastSquaresProblem`, or `ConstraintFunction` or wrapping closures in `ObjectiveFn`, `LeastSquaresFn`, or `ConstraintFn`; register constraints in `Constraints` as equalities or inequalities.
Adapter and trait `*_into` methods write directly to outputs without per-call allocation; reuse `ConstraintsWorkspace` for repeated constraint evaluation.
Determine success through `termination()`, treating only `Converged` and `GradientSmall` as success; require success by converting other termination to errors with `require_success()`.
When line search stops without accepting a trial, `LineSearchFailed` returns with its reason.
Even after success, compare `OptimalityDiagnostics` residuals with tolerances and do not read `None` as 0.
Read work counts in `own()` and `nested()` of `counts()`, separating own work from nested solves.
