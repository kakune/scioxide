Consider placing factory equipment or hospital departments one each at a fixed number of sites.
Let $A_{ij}$ be flow (transport counts or people moving) from facility $i$ to facility $j$, and $B_{kl}$ the distance from site $k$ to site $l$.
Choose permutation $\pi$ placing facility $i$ at site $\pi(i)$ to minimize total transport

$$
F(\pi)=\sum_{i,j}A_{ij}B_{\pi(i),\pi(j)}
$$


This is the Koopmans–Beckmann quadratic assignment problem (QAP).
The double sum counts both directions $i\to j$ and $j\to i$, so symmetric matrices count transport for each facility pair twice.
This page uses the full double sum and does not halve it.
Costs depend on where pairs of facilities are placed, making QAP harder than independent linear assignment per facility; QAP is NP-hard.

## Permutation direction and plots

The objective of `QapProblemView::new(a, b, fixed)` is $\sum_{i,j}a_{ij}b_{p(i),p(j)}$; `permutation[i]` denotes the second-matrix index assigned to first-matrix index $i$.
Passing flow first and distance second makes `permutation[i]` the site holding facility $i$.
Both problems' cells on this page use this order.

Swapping matrices leaves the optimum unchanged.
Setting $\sigma=\pi^{-1}$ and relabeling indices gives $\sum_{i,j}B_{ij}A_{\pi(i),\pi(j)}=\sum_{k,l}A_{kl}B_{\sigma(k),\sigma(l)}$, merely reversing the permutation direction.
The returned permutation's interpretation reverses, however, so match table headings to matrix roles.

## Roles of FAQ and 2-opt

Default method `QapMethod::FaqThenTwoOpt` first runs FAQ (fast approximate QAP).
FAQ improves a relaxation from permutation matrices to doubly stochastic matrices (nonnegative matrices whose row and column sums are 1) using Frank–Wolfe.
Linear assignment selects the permutation nearest FAQ's final matrix; 2-opt then improves it locally by swapping two facilities' sites.
One FAQ iteration and one 2-opt sweep both cost $O(n^3)$.
Because the relaxed problem is nonconvex, FAQ's relaxed objective need not lower-bound the best permutation value.
The Frank–Wolfe gap also indicates only local stationarity on the relaxation, not distance to the optimum.
See [Quadratic assignment and permutation search](../../algorithms/quadratic-assignment/) for derivation and stopping conditions.

Cells change the FAQ iteration limit (`with_max_fw_iterations`), restarts, seed and workspace limit from `QapOptions::default()`, minimizing with `QapPlan::solve_with_options`.
`with_restarts(3)` adds 3 restarts from seeded initial permutations to the first trial and returns the best permutation.
`QapResult::termination` summarizes stopping across selected stages; if any trial reaches the FAQ iteration limit it becomes `IterationLimit`, and no status proves global optimality.
A permutation is returned even at `IterationLimit`, so this page's outcomes map `Converged` to satisfied and `IterationLimit` to partial.

The following definition block is shared by both cells on this page.
`objective` independently checks the returned permutation by substituting it into the original double sum; `solve` builds a Plan for $n$ facilities with flow first and distance second, then solves with 3 restarts.

```rust
//| id: optimize-qap-layout-model
//| kind: definitions
//| title: "Check the double sum and solve QAP with flow followed by distance"
//| crates: [scioxide-core, scioxide-linalg, scioxide-optimize]
use scioxide_core::{Budget, SciOxideError};
use scioxide_linalg::Matrix;
use scioxide_optimize::{QapDirection, QapOptions, QapProblemView, QapResult};

/// Double sum Σᵢⱼ flowᵢⱼ distance_{p(i), p(j)} when facility i is at site p[i].
pub(crate) fn objective(flow: &[f64], distance: &[f64], p: &[usize]) -> f64 {
    let n = p.len();
    let pairs = (0..n).flat_map(|i| (0..n).map(move |j| (i, j)));
    pairs
        .map(|(i, j)| flow[i * n + j] * distance[p[i] * n + p[j]])
        .sum()
}

/// Flow is the first matrix and distance the second, so permutation[i] is facility i's site.
pub(crate) fn solve(
    n: usize,
    flow: &[f64],
    distance: &[f64],
    iterations: usize,
    seed: u64,
) -> Result<QapResult<f64>, SciOxideError> {
    let flow = Matrix::from_vec(n, n, flow.to_vec())?;
    let distance = Matrix::from_vec(n, n, distance.to_vec())?;
    let plan = QapProblemView::new(flow.view(), distance.view(), &[])?.prepare()?;
    let options = QapOptions::default()
        .with_max_workspace_bytes(8_000_000)
        .with_max_fw_iterations(Budget::try_from(iterations)?)
        .with_restarts(3)
        .with_seed(seed);
    plan.solve_with_options(QapDirection::Minimize, None, &options)
}
```

## Synthetic problem checked by exhaustive search

For the synthetic $n$-facility problem, flows are daily transport counts $A_{ij}=1+(7(i+j)\bmod5)$ [trips/day] ($i\ne j$, symmetric values from 1 to 5).
Sites are equally spaced along a straight corridor; one adjacent spacing is one block, giving distance $B_{kl}=|k-l|$ [blocks].
Total transport $F$ therefore has units [trip·blocks/day].
Find the optimum by examining all $n!$ permutations, using it as an independent reference.
Evaluating one permutation costs $O(n^2)$, so exhaustive search costs $O(n!\,n^2)$; at $n=8$, $8!=40320$ permutations times 64 summed terms gives about 2.6 million multiply-adds.
Relabeling sites as $k\mapsto n-1-k$ preserves distance $|k-l|$, so relabeling an optimal permutation gives another optimum; there are at least 2 optimal permutations.

The following cell takes facility count $n$ (5–8), the FAQ iteration limit per trial and seed.
The plot has facility index on the horizontal axis and assigned site index on the vertical axis, showing that every site is used once.
The first table gives cost recomputed from the original double sum, reported `QapResult::objective` value, exhaustive-search optimum, gap and optimal-permutation count.
The second table gives termination, relaxed objective and Frank–Wolfe gap of the selected trial, total FAQ iterations and swap checks across all trials, and selected trial index.

```rust
//| id: optimize-facility-layout-qap
//| ref: optimize-facility-layout-qap
//| title: "Check FAQ and 2-opt assignments against the exhaustive-search optimum"
//| run: button
//| uses: [optimize-qap-layout-model]
//| crates: [scioxide-optimize]
//| inputs:
//|   facilities: {"type":"range","label":"Facility count n [count]","min":5,"max":8,"step":1,"value":6}
//|   iterations: {"type":"range","label":"FAQ iteration limit [count]","min":10,"max":100,"step":10,"value":30}
//|   seed: {"type":"range","label":"Random seed [-]","min":1,"max":100,"step":1,"value":7}
//| cases:
//|   - {"id":"eight","label":"8 facilities","description":"Cost matches the exhaustive optimum 438 over 8! = 40320 permutations, but some FAQ trials reach the iteration limit, giving IterationLimit.","inputs":{"facilities":8}}
//|   - {"id":"short-faq","label":"FAQ iteration limit 10","description":"FAQ reaches its iteration limit, giving IterationLimit and a partial outcome.","inputs":{"iterations":10}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"costs","path":"/rows/0/0","approx":{"value":184,"atol":1e-9}}
//|       - {"artifact":"costs","path":"/rows/0/1","approx":{"value":184,"atol":1e-9}}
//|       - {"artifact":"costs","path":"/rows/0/2","approx":{"value":184,"atol":1e-9}}
//|       - {"artifact":"faq","path":"/rows/0/0","equals":"Converged"}
//|       - {"artifact":"faq","path":"/rows/0/1","approx":{"value":171.393,"atol":0.5}}
//|       - {"path":"/outputs/3/state","equals":"satisfied"}
//|   - case: eight
//|     expect:
//|       - {"artifact":"costs","path":"/rows/0/0","approx":{"value":438,"atol":1e-9}}
//|       - {"artifact":"costs","path":"/rows/0/2","approx":{"value":438,"atol":1e-9}}
//|       - {"artifact":"costs","path":"/rows/0/4","equals":64}
//|   - case: short-faq
//|     expect:
//|       - {"artifact":"faq","path":"/rows/0/0","equals":"IterationLimit"}
//|       - {"path":"/outputs/3/state","equals":"partial"}
let n = facilities as usize;
// Facility flows are symmetric values from 1 to 5; sites are equally spaced on a straight line.
let flow: Vec<f64> = (0..n * n)
    .map(|k| match (k / n, k % n) {
        (i, j) if i == j => 0.0,
        (i, j) => 1.0 + ((i + j) * 7 % 5) as f64,
    })
    .collect();
let distance: Vec<f64> = (0..n * n).map(|k| (k / n).abs_diff(k % n) as f64).collect();
// Independent check: generate all n! permutations with Heap's algorithm and find the minimum double sum and optimal-permutation count.
let mut p: Vec<usize> = (0..n).collect();
let mut counters = vec![0; n];
let (mut exact, mut optimal) = (objective(&flow, &distance, &p), 1_usize);
let mut i = 0;
while i < n {
    if counters[i] < i {
        p.swap(if i % 2 == 0 { 0 } else { counters[i] }, i);
        let value = objective(&flow, &distance, &p);
        if value < exact {
            (exact, optimal) = (value, 1);
        } else if value == exact {
            optimal += 1;
        }
        counters[i] += 1;
        i = 0;
    } else {
        counters[i] = 0;
        i += 1;
    }
}
let result =
    solve(n, &flow, &distance, iterations as usize, seed as u64).map_err(|e| e.to_string())?;
let permutation = result
    .permutation()
    .ok_or(format!("No assignment candidate: {}", result.termination()))?;
let value = objective(&flow, &distance, permutation);
let points: Vec<_> = permutation
    .iter()
    .enumerate()
    .map(|(i, &j)| [i as f64, j as f64])
    .collect();
emit_scatter_chart!(
    &vec![serde_json::json!({ "name": "Assignment", "points": points })],
    options = &serde_json::json!({ "xLabel": "Facility index [-]", "yLabel": "Site index [-]" })
);
let cost = serde_json::json!({ "fractionDigits": 0 });
let fixed1 = serde_json::json!({ "fractionDigits": 1 });
emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "Recomputed cost [trip·blocks/day]", "type": "number", "format": cost },
        {
            "key": "1",
            "label": "Reported cost [trip·blocks/day]",
            "type": "number",
            "format": cost,
            "nullText": "None"
        },
        { "key": "2", "label": "Exhaustive-search optimum [trip·blocks/day]", "type": "number", "format": cost },
        { "key": "3", "label": "Gap [trip·blocks/day]", "type": "number", "format": cost },
        { "key": "4", "label": "Optimal permutations [count]", "type": "integer" }
    ]),
    vec![(value, result.objective(), exact, value - exact, optimal)],
    metadata = serde_json::json!({ "id": "costs" })
);
emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "Termination reason" },
        {
            "key": "1",
            "label": "Relaxed objective [trip·blocks/day]",
            "type": "number",
            "format": fixed1,
            "nullText": "None"
        },
        {
            "key": "2",
            "label": "Frank–Wolfe gap [trip·blocks/day]",
            "type": "number",
            "format": fixed1,
            "nullText": "None"
        },
        { "key": "3", "label": "Total FAQ iterations [count]", "type": "integer" },
        { "key": "4", "label": "Total swap checks [count]", "type": "integer" },
        { "key": "5", "label": "Selected trial [-]", "type": "integer" }
    ]),
    vec![(
        result.termination().to_string(),
        result.relaxation_objective(),
        result.fw_gap(),
        result.fw_iterations(),
        result.swap_checks(),
        result.selected_restart()
    )],
    metadata = serde_json::json!({ "id": "faq" })
);
let outcome = if result.termination().is_success() {
    Outcome::satisfied("All FAQ and 2-opt stages satisfy their stopping conditions")
} else {
    Outcome::partial("FAQ or 2-opt stopped at a limit")
};
emit_outcome!(
    outcome
        .explanation("No termination reason proves global optimality. Compare with exhaustive search in the gap column.")
        .status(result.termination().to_string())
        .diagnostic("Gap to exhaustive-search optimum", value - exact, Some("trip·blocks/day"))
        .diagnostic("Total FAQ iterations", result.fw_iterations() as f64, None)
);
```

For the default six-facility problem, recomputed and reported costs are both 184 trip·blocks/day, matching exhaustive search, with termination `Converged`.
Of 720 permutations, 8 attain optimum 184, so matching the permutation itself is not required for correctness.
The selected trial's relaxed objective is 171.4, below the permutation optimum, but cannot serve as a lower bound because it is a local relaxation solution.
For 8 facilities, cost 438 matches exhaustive search over $8!=40320$ permutations, with 64 optimal permutations.
However, some of the four trials reach the 30-iteration FAQ limit, so termination is `IterationLimit` and the outcome partial.
At FAQ limit 10, even six facilities give `IterationLimit`, but cost after 2-opt remains 184.

## A constructed 12-site reference problem

For 12 sites, exhaustive enumeration would examine $12!\approx4.8\times10^8$ permutations.
Instead, construct a reference problem whose optimum follows from the rearrangement inequality.
Choose two shuffled copies of the integers 1 through 12, $a$ and $b$, and set $A_{ij}=a_i a_j$ and $B_{st}=b_s b_t$.
Then the QAP double sum is $(\sum_i a_i b_{p(i)})^2$.
All weights are positive, so opposite sorting minimizes both the inner sum and its square.
The minimum is $(\sum_{k=1}^{12} k(13-k))^2=364^2=132496$.
These matrices include their diagonal entries and are algebraic costs, not geographic distances.
No external instance matrix or solution file is used.
The cell constructs an optimal permutation directly and verifies its cost with the same original double sum used to assess the heuristic.
The grid row and column in the display merely label the twelve sites.

```rust
//| id: optimize-facility-layout-nug12
//| ref: optimize-facility-layout-nug12
//| title: "Compare a 12-site assignment with its exact optimum"
//| run: button
//| uses: [optimize-qap-layout-model]
//| crates: [scioxide-optimize]
//| inputs:
//|   iterations: {"type":"range","label":"FAQ iteration limit [count]","min":10,"max":100,"step":10,"value":30}
//|   seed: {"type":"range","label":"Random seed [-]","min":1,"max":100,"step":1,"value":7}
//| cases:
//|   - {"id":"seed4","label":"Seed 4","inputs":{"seed":4}}
//|   - {"id":"short-faq","label":"10 FAQ iterations","inputs":{"iterations":10}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"costs","path":"/rows/0/0","approx":{"value":132496,"atol":1e-9}}
//|       - {"artifact":"costs","path":"/rows/0/2","approx":{"value":132496,"atol":1e-9}}
//|       - {"artifact":"costs","path":"/rows/0/3","approx":{"value":132496,"atol":1e-9}}
//|   - case: seed4
//|     expect:
//|       - {"artifact":"costs","path":"/rows/0/0","approx":{"value":132496,"atol":1e-9}}
//|       - {"artifact":"costs","path":"/rows/0/2","approx":{"value":132496,"atol":1e-9}}
//|   - case: short-faq
//|     expect:
//|       - {"artifact":"costs","path":"/rows/0/0","approx":{"value":132496,"atol":1e-9}}
//|       - {"artifact":"costs","path":"/rows/0/3","approx":{"value":132496,"atol":1e-9}}
// Construct rank-one matrices from weights; no downloaded instance or solution data.
let weights = [2.0, 5.0, 1.0, 8.0, 3.0, 12.0, 4.0, 10.0, 6.0, 11.0, 7.0, 9.0];
let site_weights = [7.0, 2.0, 11.0, 4.0, 9.0, 1.0, 12.0, 5.0, 3.0, 10.0, 6.0, 8.0];
let flow: Vec<f64> = (0..144)
    .map(|k| weights[k / 12] * weights[k % 12])
    .collect();
let distance: Vec<f64> = (0..144)
    .map(|k| site_weights[k / 12] * site_weights[k % 12])
    .collect();
// Rearrangement: pair ascending facility weights with descending site weights.
let inverse: Vec<usize> = weights
    .iter()
    .map(|&w| {
        site_weights
            .iter()
            .position(|&v| v == 13.0 - w)
            .ok_or("Missing site weight")
    })
    .collect::<Result<_, _>>()?;
let analytic_cost = objective(&flow, &distance, &inverse);
let result =
    solve(12, &flow, &distance, iterations as usize, seed as u64).map_err(|e| e.to_string())?;
let permutation = result
    .permutation()
    .ok_or(format!("No assignment candidate: {}", result.termination()))?;
let value = objective(&flow, &distance, permutation);
if analytic_cost != 132496.0 || value < analytic_cost {
    Err("Assignment cost contradicts the rearrangement bound".to_string())?;
}
emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "Facility", "type": "integer" },
        { "key": "1", "label": "Site", "type": "integer" },
        { "key": "2", "label": "Grid row", "type": "integer" },
        { "key": "3", "label": "Grid column", "type": "integer" }
    ]),
    permutation
        .iter()
        .enumerate()
        .map(|(i, &k)| (i, k, k / 4, k % 4))
        .collect::<Vec<_>>(),
    metadata = serde_json::json!({ "id": "layout" })
);
let cost = serde_json::json!({ "fractionDigits": 0 });
let fixed1 = serde_json::json!({ "fractionDigits": 1 });
emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "Recomputed cost [-]", "type": "number", "format": cost },
        { "key": "1", "label": "Reported cost [-]", "type": "number", "format": cost, "nullText": "None" },
        { "key": "2", "label": "Known optimum [-]", "type": "number", "format": cost },
        { "key": "3", "label": "Recomputed analytic-solution cost [-]", "type": "number", "format": cost },
        { "key": "4", "label": "Gap [-]", "type": "number", "format": cost },
        { "key": "5", "label": "Termination reason" },
        { "key": "6", "label": "Total FAQ iterations [count]", "type": "integer" },
        { "key": "7", "label": "Relaxed objective [-]", "type": "number", "format": fixed1, "nullText": "None" },
        { "key": "8", "label": "Frank–Wolfe gap [-]", "type": "number", "format": fixed1, "nullText": "None" }
    ]),
    vec![(
        value,
        result.objective(),
        132496.0,
        analytic_cost,
        value - 132496.0,
        result.termination().to_string(),
        result.fw_iterations(),
        result.relaxation_objective(),
        result.fw_gap()
    )],
    metadata = serde_json::json!({ "id": "costs" })
);
let outcome = if result.termination().is_success() {
    Outcome::satisfied("All FAQ and 2-opt stages satisfy their stopping conditions")
} else {
    Outcome::partial("FAQ or 2-opt stopped at a limit")
};
emit_outcome!(
    outcome
        .explanation("No termination reason proves global optimality. Compare with the known optimum in the gap column.")
        .status(result.termination().to_string())
        .diagnostic("Gap to known optimum", value - 132496.0, None)
        .diagnostic("Total FAQ iterations", result.fw_iterations() as f64, None)
);
```

The exact optimum and the recomputed analytic permutation both give 132496, independently of the seed or iteration limit.
The heuristic's recomputed cost must be at least this value; its difference from the exact optimum is the reported gap.
A zero gap verifies the objective value for this constructed instance, while the solver's termination still describes its own stopping conditions.
Vary the seed and FAQ limit to compare search behavior without treating the relaxed objective or a small Frank–Wolfe gap as a global certificate.

## Summary

Layouts involving facility-pair flows are quadratic assignment problems, harder than independent linear assignment per facility.
Pass flow first and distance second to `QapProblemView::new`, interpreting `permutation[i]` as the site of facility $i$.
If published data use reverse matrix order, swap matrices before passing them or interpret the returned permutation inversely.
Check up to about 8 facilities by exhaustive search and larger problems against known optima of published instances; in both cases substitute returned permutations into the original double sum.
Termination, relaxed objectives and Frank–Wolfe gaps provide no global-optimality evidence, so read reference gaps alongside differences across seeds.
