Mathematical optimization seeks decision variables $\mathbf{x}^* \in \Omega$ minimizing the objective function $f: \mathbb{R}^n \to \mathbb{R}$ within the feasible region $\Omega \subseteq \mathbb{R}^n$.
Writing $\Omega$ using equality constraints $c_i$, inequality constraints $g_j$, and variable bounds $\mathbf{l}, \mathbf{u}$ gives the following form.

$$
\min_{\mathbf{x} \in \mathbb{R}^n} f(\mathbf{x}) \quad \text{subject to} \quad \begin{cases} c_i(\mathbf{x}) = 0 & (i \in \mathcal{E}) \\ g_j(\mathbf{x}) \le 0 & (j \in \mathcal{I}) \\ \mathbf{l} \le \mathbf{x} \le \mathbf{u} \end{cases}
$$

Parameter estimation, loss minimization, searches for minimum-energy states, trajectory design, and asset allocation take this form.
The solution method depends on objective smoothness, availability of derivatives (gradient and Hessian), linear or nonlinear constraints, continuous or integer variables, and whether there is one local minimum or many (unimodality or multimodality).
`scioxide-optimize` provides unconstrained and box-constrained local methods, nonlinear constrained methods, nonlinear and linear least squares, linear, quadratic, and mixed-integer programming, quadratic assignment, composite objectives and splitting methods, sampled objectives, multiobjective optimization, and global search.
Solve maximization as minimization by negating the objective.

## First computation

The Rosenbrock function $f(x_1, x_2) = (1 - x_1)^2 + 100 (x_2 - x_1^2)^2$ has a curved narrow valley leading to minimizer $(1, 1)$ (minimum value 0).
The following cell minimizes from an initial point with `Bfgs` and an analytical gradient, tabulating termination reason, iteration and evaluation counts, gradient norm and stopping threshold, and distance to the known minimizer.
The threshold is recomputed from the gradient-tolerance formula $\tau = a + r \cdot \max\bigl(1, |f(\mathbf{x})| / \max(1, \lVert\mathbf{x}\rVert_\infty)\bigr)$; its default is $a = r = \sqrt{\varepsilon} \approx 1.49 \times 10^{-8}$ ($\varepsilon$ is machine epsilon for `f64`).
`Bfgs` stops with `GradientSmall` when $\lVert\nabla f(\mathbf{x})\rVert_2 \le \tau$ holds.

```rust
//| ref: optimize-overview-first-bfgs

//| run: reactive
//| crates: [scioxide-core, scioxide-optimize]
//| inputs:
//|   start_x1: {"type":"range","label":"Initial point x₁ [-]","description":"Starting from the opposite side of the valley increases iterations.","min":-2,"max":2,"step":0.1,"value":-1.2}

//|       - {"artifact":"bfgs","path":"/rows/0/8","range":{"min":0,"max":1e-6}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: far-above-valley

//|       - {"artifact":"bfgs","path":"/rows/0/8","range":{"min":0,"max":1e-6}}
//|   - case: left-edge
//|     expect:
//|       - {"artifact":"bfgs","path":"/rows/0/0","equals":"GradientSmall"}
//|       - {"artifact":"bfgs","path":"/rows/0/2","range":{"min":24,"max":28}}
//|       - {"artifact":"bfgs","path":"/rows/0/8","range":{"min":0,"max":1e-6}}
use scioxide_core::{GradientTolerance, RealScalar};
use scioxide_optimize::{Bfgs, ObjectiveFn, OptimizeTermination};

// Objective and analytical gradient. ObjectiveFn checks return values for finiteness.
let rosenbrock = ObjectiveFn::new(2, |x: &[f64]| {
    let a = 1.0 - x[0];
    let b = x[1] - x[0] * x[0];
    Ok(a * a + 100.0 * b * b)
})
.with_gradient(|x: &[f64], g: &mut [f64]| {
    let b = x[1] - x[0] * x[0];
    g[0] = -2.0 * (1.0 - x[0]) - 400.0 * x[0] * b;
    g[1] = 200.0 * b;
    Ok(())
});
let result = Bfgs::<f64>::default()
    .minimize(&rosenbrock, &[start_x1, start_x2])
    .map_err(|e| e.to_string())?;
let x = result.x();
let gradient_norm = result.grad().map(|g| RealScalar::hypot(g[0], g[1]));
// Recompute stopping threshold τ = a + r·max(1, |f|/max(1, ‖x‖∞)) from default tolerances.
let coordinate = RealScalar::max(1.0, RealScalar::max(x[0].abs(), x[1].abs()));
let scale = RealScalar::max(1.0, result.fun().abs() / coordinate);
let threshold = GradientTolerance::<f64>::default()
    .threshold(scale)
    .map_err(|e| e.to_string())?;
// Distance to known minimizer (1, 1) is an independent check.
let distance = RealScalar::hypot(x[0] - 1.0, x[1] - 1.0);
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "Termination reason" },
    { "key": "1", "label": "Success", "type": "boolean" },
    { "key": "2", "label": "Iterations [count]", "type": "integer" },
    { "key": "3", "label": "Objective evaluations [count]", "type": "integer" },
    { "key": "4", "label": "Gradient evaluations [count]", "type": "integer" },
    { "key": "5", "label": "f(x) [-]", "type": "number", "format": sci2 },
    { "key": "6", "label": "‖∇f(x)‖₂ [-]", "type": "number", "format": sci2, "nullText": "None" },
    { "key": "7", "label": "Threshold τ [-]", "type": "number", "format": sci2 },
    { "key": "8", "label": "‖x − (1, 1)‖₂ [-]", "type": "number", "format": sci2 }
]);
emit_table_with_columns!(
    columns,
    vec![(
        result.termination().to_string(),
        result.is_success(),
        result.iterations(),
        result.fun_evals(),
        result.grad_evals(),
        result.fun(),
        gradient_norm,
        threshold,
        distance,
    )],
    metadata = serde_json::json!({ "id": "bfgs" })
);

let termination = result.termination();
let outcome = match termination {
    _ if termination.is_success() => Outcome::satisfied("Gradient norm fell below the stopping threshold")
        .explanation("A first-order stopping criterion, not a certificate of a local or global minimum."),
    OptimizeTermination::LineSearchFailed(_) => {
        Outcome::failed("Line search could not find an acceptable step length")
    }
    _ => Outcome::partial("Stopped before satisfying the stopping criterion")
        .explanation("Returns the last point accepted during iteration. Treat it as an estimate because it need not be optimal."),
};
emit_outcome!(
    outcome
        .status(termination.to_string())
        .diagnostic("Iterations", result.iterations() as f64, None)
        .diagnostic("Distance to known minimizer", distance, None)
);
```

From the default initial point $(-1.2, 1)$, `GradientSmall` is reached in 37 iterations (66 objective and 66 gradient evaluations), and `is_success()` is true.
The final gradient norm is $7.7 \times 10^{-9}$, below threshold $\tau = 2\sqrt{\varepsilon} \approx 3.0 \times 10^{-8}$.
Near the minimizer, $|f| < 1$, so the scale is 1 and the threshold equals $a + r$.
Distance to the known minimizer is $5.2 \times 10^{-10}$ and the objective value is $8.3 \times 10^{-20}$.
Changing the initial point to $(-1.2, 3)$ takes 48 iterations, while $(-2, 1)$ takes 26; the count depends on where the valley is entered.
All tried initial points, including both ends of the input range, reach the same minimizer.
`GradientSmall` is a first-order stopping criterion for a small gradient, not proof of a local minimum, so check against a known solution or other initial points.

For a single solve without writing a gradient, pass an objective closure and initial point to one-shot function `minimize`.
`minimize` uses default `Bfgs`, approximates gradients by central differences ($2n$ objective evaluations per gradient), and returns unsuccessful terminations as `Err`.
With box constraints, `minimize_bounded` uses default `LbfgsB` and forward-difference gradients ($n$ objective evaluations).
The following cell solves the same Rosenbrock function with `minimize`, then calls `minimize_bounded` on box $x_1 \le 0.5$.
The box minimizer is $(0.5, 0.25)$, the intersection of valley floor $x_2 = x_1^2$ and boundary $x_1 = 0.5$, with minimum $(1 - 0.5)^2 = 0.25$.
Here $\partial f / \partial x_1 = -1 < 0$, so the objective decreases toward the upper bound and that bound is active.

```rust
//| id: optimize-overview-one-shot
//| ref: optimize-overview-one-shot
//| title: "Solve with one-shot minimize and minimize_bounded"
//| run: reactive
//| crates: [scioxide-core, scioxide-optimize]
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"one-shot","path":"/rows/0/1","equals":"GradientSmall"}
//|       - {"artifact":"one-shot","path":"/rows/0/3","equals":325}
//|       - {"artifact":"one-shot","path":"/rows/0/6","range":{"min":0,"max":1e-6}}
//|       - {"artifact":"one-shot","path":"/rows/1/1","equals":"GradientSmall"}
//|       - {"artifact":"one-shot","path":"/rows/1/5","approx":{"value":0.25,"atol":1e-8}}
//|       - {"artifact":"one-shot","path":"/rows/1/6","range":{"min":0,"max":1e-6}}
use scioxide_core::{Bounds, RealScalar};
use scioxide_optimize::{minimize, minimize_bounded};

let rosenbrock = |x: &[f64]| {
    let a = 1.0 - x[0];
    let b = x[1] - x[0] * x[0];
    Ok(a * a + 100.0 * b * b)
};
let start = [-1.2, 1.0];
// Without a supplied gradient, minimize uses central differences and minimize_bounded uses forward differences.
let free = minimize(rosenbrock, &start).map_err(|e| e.to_string())?;
let bounds = Bounds::new(vec![(Some(-2.0), Some(0.5)), (Some(-1.0), Some(3.0))])
    .map_err(|e| e.to_string())?;
let boxed = minimize_bounded(rosenbrock, &start, &bounds).map_err(|e| e.to_string())?;
// Independent check: distance to unconstrained minimizer (1, 1) and box minimizer (0.5, 0.25).
let rows = [
    ("minimize", &free, [1.0, 1.0]),
    ("minimize_bounded", &boxed, [0.5, 0.25]),
]
.into_iter()
.map(|(name, r, exact)| {
    (
        name,
        r.termination().to_string(),
        r.iterations(),
        r.fun_evals(),
        r.grad_evals(),
        r.fun(),
        RealScalar::hypot(r.x()[0] - exact[0], r.x()[1] - exact[1]),
    )
})
.collect::<Vec<_>>();
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "Call" },
    { "key": "1", "label": "Termination reason" },
    { "key": "2", "label": "Iterations [count]", "type": "integer" },
    { "key": "3", "label": "Objective evaluations [count]", "type": "integer" },
    { "key": "4", "label": "Approximated gradients [count]", "type": "integer" },
    { "key": "5", "label": "f(x) [-]", "type": "number", "format": sci2 },
    { "key": "6", "label": "Distance to known minimizer [-]", "type": "number", "format": sci2 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "one-shot" })
);
```

`minimize` reaches `GradientSmall` in 36 iterations, at distance $1.7 \times 10^{-8}$ from the known minimizer.
It uses 325 objective evaluations, about 5 times the analytical-gradient cell above (66).
Of these, 260 compute 65 finite-difference gradients ($2n = 4$ evaluations each).
The distance also exceeds the $5.2 \times 10^{-10}$ obtained with an analytical gradient, with finite-difference error remaining at the stopping point.
`minimize_bounded` reaches `GradientSmall` in 67 iterations and returns $f = 0.25$ and distance $7.4 \times 10^{-9}$ to box minimizer $(0.5, 0.25)$.
One-shot functions return only successful results as `Ok`, so this table shows only success categories of termination reasons.
For repeated solves, changing stopping tolerances or iteration limits, or receiving partial results, use a method object (such as `Bfgs`) as in the first cell ([Call forms](oxref:optimize-call-forms)).

## Reading results

- Termination reason: `OptimizeTermination` is the sole termination status.
  Only `Converged` and `GradientSmall` are successful (`is_success()` true).
  `StepSmall`, `FunctionChangeSmall`, and `Stagnation` return the last accepted point but are not successful, nor is `LineSearchFailed`, where line search could not accept a step length.
  Stops due to limits on iterations, evaluations, search trees, time, or cancellation, and termination of global search or sampled objectives, are also unsuccessful.
  See [Termination reason classification](oxref:optimize-termination-classes) for the full classification.
- Errors: invalid input shapes, nonfinite values, callback failures, and stops before accepting the first point return `SciOxideError` rather than `Ok`.
  One-shot functions also turn unsuccessful termination into errors such as `ConvergenceFailure`; method-object results can be converted to the same errors with `require_success()`.
  Read classification with `kind()` and `view()`; errors carry no caller identifier.
- Optimality evidence: `OptimalityDiagnostics` separately returns primal-feasibility, stationarity, dual-feasibility, and complementarity residuals, integrality and bound violations, and optimality gaps to the extent computed by the method.
  Uncomputed quantities are `None`, which does not mean zero residual.
  LP/QP results can be checked independently of the solver with `ProgrammingVerifier::verify`.
- Method-specific diagnostics: `method_diagnostics()` returns observations for each method class (one variant of `OptimizeDiagnostics`).
  BFGS above includes counts of undamped and damped curvature updates, but only the termination reason determines success.
- Computational work: besides `iterations()`, `fun_evals()`, and `grad_evals()`, `counts()` returns role-specific call counts as `SolveCounts`.
  Failed differentiation attempts also count; nested solves separate their own work (`own()`) from descendant work (`nested()`).

Detailed interpretation is in the [API guide](api/) and [Optimization problems and interpreting results](algorithms/).

## Local stationarity and Karush–Kuhn–Tucker conditions

A first-order necessary condition for $\mathbf{x}^*$ to be a local minimizer of an unconstrained problem is a zero gradient ($\nabla f(\mathbf{x}^*) = \mathbf{0}$).
A zero gradient and positive definite Hessian ($\nabla^2 f(\mathbf{x}^*) \succ 0$) satisfy a second-order sufficient condition, making $\mathbf{x}^*$ a strict local minimizer.

For constrained problems, use the Lagrangian with multipliers $\boldsymbol{\lambda}, \boldsymbol{\mu}$,

$$
\mathcal{L}(\mathbf{x}, \boldsymbol{\lambda}, \boldsymbol{\mu}) = f(\mathbf{x}) + \sum_{i \in \mathcal{E}} \lambda_i c_i(\mathbf{x}) + \sum_{j \in \mathcal{I}} \mu_j g_j(\mathbf{x})
$$

Under a constraint qualification (such as LICQ, linear independence of active-constraint gradients), a local optimum $\mathbf{x}^*$ has multipliers $(\boldsymbol{\lambda}^*, \boldsymbol{\mu}^*)$ satisfying the following Karush–Kuhn–Tucker (KKT) conditions.

$$
\begin{aligned}
\nabla_{\mathbf{x}} \mathcal{L}(\mathbf{x}^*, \boldsymbol{\lambda}^*, \boldsymbol{\mu}^*) = \mathbf{0} & \quad (\text{stationarity}) \\
c_i(\mathbf{x}^*) = 0 \; (\forall i \in \mathcal{E}), \quad g_j(\mathbf{x}^*) \le 0 \; (\forall j \in \mathcal{I}) & \quad (\text{primal feasibility}) \\
\mu_j^* \ge 0 \; (\forall j \in \mathcal{I}) & \quad (\text{dual feasibility}) \\
\mu_j^* g_j(\mathbf{x}^*) = 0 \; (\forall j \in \mathcal{I}) & \quad (\text{complementarity})
\end{aligned}
$$

Constrained solvers and `OptimalityDiagnostics` return these residuals separately.
Do not accept a point solely because its objective decreased; check constraint satisfaction and multiplier consistency through numerical residuals.
These residuals express first-order conditions within tolerances, not a rigorous certificate of local optimality.
The derivation is in [Nonlinear constraints and KKT conditions](algorithms/nonlinear-constraints/).

## Coordinate scaling and numerical stability

Variable scales affect convergence speed and the meaning of stopping criteria.
If one variable varies over $10^{-6}$ and another over $10^6$, objective contours become extremely elongated and the Hessian condition number can reach $10^{24}$.
Gradient methods then make little progress, and gradient tolerances are dominated by one variable's units.

Using dimensionless variables $\tilde{x}_i = x_i / s_i$ with representative scales $s_i > 0$ often makes contours more circular and reduces conditioning.
Local methods accepting general objectives do not choose variable scales automatically, so nondimensionalize when constructing the model.
Exceptions are dense nonlinear least-squares solvers, which derive scales from Jacobian column norms unless `parameter_scale` is supplied, and LP solvers, which internally scale standard-form rows and columns.
BFGS curvature learning and trust-radius adaptation absorb some distortion but do not correct poor scaling.

## Workspace reuse and allocation

For repeated problems of the same shape (each time-evolution step, model predictive control, parameter sweeps), per-iteration allocation increases computation time.
Each solver has reusable workspace (such as `BfgsWorkspace`, `LbfgsWorkspace`, `SqpWorkspace`, `LeastSquaresWorkspace`), prepared once and passed to `minimize_into` or `solve_into`.
For `Bfgs`, query memory requirements with `workspace_requirements`, allocate with `workspace`, and write into caller-owned results with `minimize_into`.
Workspace records the last attempt and accepted iterate (`last_attempt`, `last_accepted`).
BFGS, NSGA-II, and stochastic first-order methods can continue interrupted computations using workspace `checkpoint` and solver `resume_into`.

Prepared workspace and output-buffer callbacks make steady-state iteration heap-allocation-free.
Derivative closures attached to `ObjectiveFn`, `ConstraintFn`, and `LeastSquaresFn` also write directly into solver memory.
Gradients, constraint Jacobian rows, and residuals receive `(&[S], &mut [S])`; Hessians and residual Jacobians receive `(&[S], &mut Matrix<S>)`; Hessian-vector products receive `(&[S], &[S], &mut [S])`; write every component and return `Ok(())`.
LP, QP, and MIP APIs explicitly allocate memory for standard forms, factorizations, certificates, and search trees.
Pass cancellation through `ExecutionContext::with_cancellation`; solvers check it at computation boundaries and stop with `Cancelled`.
Time limits require a clock; setting one in a context without a clock registered through `ExecutionContext::with_clock` makes the solver return `CapabilityUnavailable` before calling callbacks.

## Summary

`scioxide-optimize` has dedicated solvers for each problem structure and result types carrying evidence.
For one solve, one-shot functions such as `minimize` return only successful results; use method objects to choose settings, read partial results, or reuse workspace.
Read the termination reason first: only `Converged` and `GradientSmall` count as success; `LineSearchFailed` and limit stops do not.
Then examine gradients and stopping thresholds, KKT residuals, LP/QP verification, and MIP gaps; objective values alone do not determine solution quality.
Align variable scales and reuse workspace for repeated problems of the same shape.
