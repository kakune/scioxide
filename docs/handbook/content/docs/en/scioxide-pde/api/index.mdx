`scioxide-pde` publishes plans that discretize partial differential equations in space, together with adapters that pass their results to steady and time-dependent solves and existing linear, nonlinear, and time-integration solvers.
Finite difference (FDM), finite volume (FVM), and P1/P2 finite element (FEM) plans handle one to three dimensions with a single type and implement the shared contract `SpatialDiscretization`.
`EllipticProblem` solves steady problems, `ParabolicProblem` solves heat equations, and `HyperbolicProblem` solves wave equations in the same way for every plan.
Elasticity, incompressible flow, hyperbolic conservation laws, adaptive mesh refinement (AMR), and discrete adjoints are provided by passing residuals, tangents, and operators to solvers from `scioxide-linalg`, `scioxide-sparse`, `scioxide-rootfind`, and `scioxide-ode`.

Every operation proceeds through configuration, preparation, and execution.
Prepared plans are immutable and `Send + Sync + Clone`; the caller owns the workspace, which records the last attempt.
No function accepts a caller identifier.
This guide identifies API items by purpose and collects all 163 rustdoc items in purpose-grouped tables.
Item-name links point to the version 0.1.0 API reference on docs.rs.

`scioxide-spatial` owns meshes, boundary sets, field locations (vertices, edges, faces, and cells), and mesh revisions (`MeshToken`).
`scioxide-sparse` provides sparse matrices through `CsrMatrix`; `scioxide-linalg` handles iterative solvers and augmented systems with nullspaces, `scioxide-rootfind` handles Newton–Krylov, and `scioxide-ode` handles time integration and the temporal sweep of adjoints.

## Type relationships

- **Boundary conditions**: `BoundaryCondition` groups a region, components (all components when omitted), `BoundaryKind` (`Dirichlet`, `Natural`, `Robin`), and `BoundaryData` with declared time dependence.
  `BoundaryConditions` binds the complete list of conditions to one mesh revision.
  Use `StructuredBoundaries` for structured grids (regions are `BoundarySet`) and `TaggedBoundaries` for simplex and adaptive meshes (regions are `u32` tags).
  Natural-boundary data are the outward conormal flux $n\cdot K\nabla u$ for every discretization.
- **Spatial discretization**: `StructuredFdmPlan`, `SimplexFemPlan`, `StructuredFvmPlan`, and `SimplexFvmPlan` sample coefficients during preparation.
  As `SpatialDiscretization`, they return a time-independent eliminated operator $A$, positive lumped mass, structural constant modes, and a load $b(t)$ evaluated at any time.
  Pass the source as `FieldData` when evaluating the load.
  Apply the operator only through `apply_into` (sequential) and `apply_into_scoped` (the caller's execution context) of `scioxide_core::LinearOperator`.
- **Steady solves**: `EllipticProblem` borrows the plan and source (and a nullspace basis if needed); settings are separated into `EllipticOptions` and passed on each call.
  `solve_into(options, out, workspace, scope)` writes into the caller's array and `EllipticWorkspace`.
  For owned results, `solve_with_options(options)` returns `EllipticSolution`, while `solve()` returns only the value array using default settings.
- **Time-evolution solves**: `ParabolicProblem::new(plan, source, end)` and `HyperbolicProblem::new(plan, source, end)` prepare the semidiscrete system of free unknowns `SemidiscreteSystem` once.
  `initial_state` creates caller-owned `PdeState`, which `advance(options, state, sink, workspace, scope)` advances to the final time.
  `resume` checks `PdeCheckpoint` before restoring and advancing it.
  In the owned-result API, `solve_with_options` returns `PdeSolution`, while `solve` returns only the final field.
  Both return `PartialFailure<PdeProgress>` on failure.
- **Physical models**: elasticity and incompressible flow share `SimplexFemOptions` and `TaggedBoundaries`.
  Linear plans provide operators and loads; nonlinear plans provide residuals and tangents (`ResidualOperator` and `JacobianOperator`).
  For every residual, `PdeTangent` represents a fixed-state tangent by borrowing provider products.
  Hyperelasticity and Navier–Stokes also support `SimplexLinearization`, which `linearize` evaluates once and stores in CSR form.
  Matrices of simplex-mesh plans can be rewritten into existing CSR with the same structure without allocation using `SimplexCsrWorkspace`.
- **Time, nonlinearity, and adjoints**: `MethodOfLinesPlan` handles only diagonal mass and scale normalization; `scioxide-ode` performs time integration.
  `NonlinearPdeProblem` passes the right-hand side of `OdeSystem` to `scioxide-rootfind` as a steady residual.
  `DifferentiableDiscretization::parameterize` creates derivatives `PdeParameterization` of plan data, which `PdeEllipticAdjointPlan` and `PdeTransientAdjointPlan` use to compute gradients.

## Minimal executable example: a one-dimensional Dirichlet problem

Impose $u(0)=2$ and $u(1)=5$ on $-u''=0$ over the interval $[0,1]$, discretize with `StructuredFdmPlan`, and solve with `EllipticProblem`.
The exact solution $u=2+3x$ is linear, so the three-point difference reproduces it without truncation error; error is determined only by rounding and termination of the inner linear solver.
Inputs are the vertex count, inner solver, and iteration limit.
By default the plan selects a tridiagonal direct method; selecting “CG” injects the conjugate gradient method (CG) into the workspace.
The iteration limit is supplied through `EllipticOptions::with_max_linear_iterations`; injected CG stops at the smaller of its own limit (200 iterations) and this limit.
The iteration limit has no effect on the direct method.
The table lists maximum error, solver name, iteration count, final residual, termination reason, and trust; the final outcome classifies the termination reason.

```rust
//| id: pde-api-affine-field
//| ref: pde-api-affine-field
//| title: "Solve a one-dimensional Dirichlet problem with FDM and read the diagnostics"
//| run: reactive
//| crates: [scioxide-pde, scioxide-spatial, scioxide-core, scioxide-linalg]
//| inputs:
//|   vertex_count: {"type":"range","label":"Vertex count N+1 [-]","min":3,"max":33,"step":2,"value":5}
//|   inner_solver: {"type":"select","label":"Inner solver","options":["Tridiagonal direct method (default)","CG (injected into workspace)"],"value":"Tridiagonal direct method (default)"}
//|   iteration_cap: {"type":"range","label":"Iteration limit [iterations]","description":"Applies only to injected CG.","min":1,"max":64,"step":1,"value":64}
//| cases:
//|   - {"id":"cg-coarse","label":"Inject CG (5 vertices)","description":"Solves the same eliminated matrix with CG and reaches Completed in 4 iterations.","inputs":{"inner_solver":"CG (injected into workspace)"}}
//|   - {"id":"cg-fine","label":"Inject CG (33 vertices)","description":"Iterations increase to 32, while maximum error stays at the rounding level.","inputs":{"inner_solver":"CG (injected into workspace)","vertex_count":33}}
//|   - {"id":"cg-capped","label":"Stop CG after 8 iterations (33 vertices)","description":"Stops with LinearIterationLimit; the unconverged iterate returned by CG is written with DiagnosticOnly trust.","inputs":{"inner_solver":"CG (injected into workspace)","vertex_count":33,"iteration_cap":8}}
//|   - {"id":"direct-fine","label":"Direct method (33 vertices)","description":"The direct method uses no iterations; maximum error and residual are at the rounding level.","inputs":{"vertex_count":33}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"solve","path":"/rows/0/1","range":{"min":0,"max":1e-14}}
//|       - {"artifact":"solve","path":"/rows/0/2","equals":"tridiagonal-direct"}
//|       - {"artifact":"solve","path":"/rows/0/3","equals":0}
//|       - {"artifact":"solve","path":"/rows/0/5","equals":"Completed"}
//|       - {"artifact":"solve","path":"/rows/0/6","equals":"ResidualChecked"}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: cg-coarse
//|     expect:
//|       - {"artifact":"solve","path":"/rows/0/2","equals":"CG"}
//|       - {"artifact":"solve","path":"/rows/0/3","range":{"min":3,"max":5}}
//|       - {"artifact":"solve","path":"/rows/0/5","equals":"Completed"}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: cg-fine
//|     expect:
//|       - {"artifact":"solve","path":"/rows/0/1","range":{"min":0,"max":1e-12}}
//|       - {"artifact":"solve","path":"/rows/0/3","range":{"min":30,"max":34}}
//|       - {"artifact":"solve","path":"/rows/0/5","equals":"Completed"}
//|   - case: cg-capped
//|     expect:
//|       - {"artifact":"solve","path":"/rows/0/1","approx":{"value":4.15625,"rtol":1e-9}}
//|       - {"artifact":"solve","path":"/rows/0/3","equals":8}
//|       - {"artifact":"solve","path":"/rows/0/5","equals":"LinearIterationLimit"}
//|       - {"artifact":"solve","path":"/rows/0/6","equals":"DiagnosticOnly"}
//|       - {"path":"/outputs/1/state","equals":"partial"}
//|   - case: direct-fine
//|     expect:
//|       - {"artifact":"solve","path":"/rows/0/0","equals":33}
//|       - {"artifact":"solve","path":"/rows/0/1","range":{"min":0,"max":1e-13}}
//|       - {"artifact":"solve","path":"/rows/0/3","equals":0}
//|       - {"artifact":"solve","path":"/rows/0/5","equals":"Completed"}
use scioxide_core::{Budget, ExecutionContext, SciOxideError, ResidualTolerance};
use scioxide_linalg::CgSolver;
use scioxide_pde::{
    BoundaryCondition, BoundaryData, BoundaryPoint, ConstantDiffusion, EllipticOptions,
    EllipticProblem, EllipticWorkspace, FieldData, PdeTermination, SpatialDiscretization,
    SpatialLimits, StructuredBoundaries, StructuredFdmPlan,
};
use scioxide_spatial::{
    AxisSide, AxisTopology, BoundarySet, CoordinateAxis, Grid1d, SegmentMesh,
};

let vertices = vertex_count as usize;
let axis = CoordinateAxis::uniform(0.0, 1.0, vertices).map_err(|e| e.to_string())?;
let grid = Grid1d::new([axis], [AxisTopology::Bounded]).map_err(|e| e.to_string())?;
let mesh = SegmentMesh::new(grid).map_err(|e| e.to_string())?;
// Dirichlet values at both ends come from the exact solution 2 + 3x.
let exact = BoundaryData::time_invariant(|p: BoundaryPoint<f64, 1>| Ok(2.0 + 3.0 * p.point[0]));
let conditions = [AxisSide::Start, AxisSide::End]
    .into_iter()
    .map(|side| {
        let region = BoundarySet::axis_side(&mesh, 0, side)?;
        Ok(BoundaryCondition::dirichlet(region, exact.clone()))
    })
    .collect::<Result<Vec<_>, SciOxideError>>()
    .map_err(|e| e.to_string())?;
let boundaries = StructuredBoundaries::new(&mesh, 1, conditions).map_err(|e| e.to_string())?;
let limits = SpatialLimits::new(64, 1024, 1 << 20);
// -u'' = 0: constant coefficients with diffusion 1 (reaction is 0).
let coefficients = ConstantDiffusion::new(1.0);
let plan = StructuredFdmPlan::with_options(mesh, &coefficients, &boundaries, limits)
    .map_err(|e| e.to_string())?;
let source = FieldData::zero();
let problem = EllipticProblem::new(&plan, &source);
let cap = Budget::try_from(iteration_cap as usize).map_err(|e| e.to_string())?;
let options = EllipticOptions::new().with_max_linear_iterations(cap);
let mut workspace = EllipticWorkspace::new();
if inner_solver == "CG (injected into workspace)" {
    let tolerance = ResidualTolerance::new(1e-12, 1e-12).map_err(|e| e.to_string())?;
    let limit = Budget::try_from(200).map_err(|e| e.to_string())?;
    workspace = workspace.with_linear_solver(Box::new(CgSolver::new(tolerance, limit)));
}
let mut values = vec![0.0; plan.unknowns()];
let report = problem
    .solve_into(
        &options,
        &mut values,
        &mut workspace,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;
// Read the physical coordinates of unknowns from the plan's dof_point and compare with the exact solution (independent check).
let mut error = 0.0_f64;
for (unknown, u) in values.iter().enumerate() {
    let x = plan.dof_point(unknown).map_err(|e| e.to_string())?.point[0];
    error = error.max((u - (2.0 + 3.0 * x)).abs());
}
let d = report.diagnostics();
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "Vertex count [-]", "type": "integer" },
    { "key": "1", "label": "Maximum error [-]", "type": "number", "format": sci3 },
    { "key": "2", "label": "Inner solver" },
    { "key": "3", "label": "Iterations [count]", "type": "integer" },
    { "key": "4", "label": "Final residual [-]", "type": "number", "format": sci3, "nullText": "None" },
    { "key": "5", "label": "Termination reason" },
    { "key": "6", "label": "Trust" }
]);
let row = (
    vertices,
    error,
    d.method().unwrap_or("None").to_owned(),
    d.num_linear_iterations(),
    d.residual_norm(),
    report.termination().to_string(),
    format!("{:?}", report.trust()),
);
emit_table_with_columns!(
    columns,
    vec![row],
    metadata = serde_json::json!({ "id": "solve" })
);

let termination = report.termination();
let outcome = match termination {
    _ if termination.is_success() => Outcome::satisfied("Solved the eliminated linear system to tolerance")
        .explanation("This is a residual criterion for the linear system and makes no claim about spatial discretization error."),
    PdeTermination::LinearBreakdown(_) => Outcome::failed("The inner iterative method broke down"),
    _ => Outcome::partial("The inner iterative method stopped at its limit")
        .explanation("The written values are an unconverged iterate, with DiagnosticOnly trust."),
};
emit_outcome!(
    outcome
        .status(termination.to_string())
        .diagnostic("Maximum error", error, None)
        .diagnostic("Iteration count", d.num_linear_iterations() as f64, None)
);
```

With the default 5 vertices, the tridiagonal direct method `tridiagonal-direct` solves the problem with 0 iterations.
Maximum error and residual are 0 in this example, and trust is `ResidualChecked` after an independent residual check.
Injecting CG solves the same eliminated matrix iteratively, reaching `Completed` in 4 iterations for 5 vertices and 32 iterations for 33 vertices.
With 33 vertices and an iteration limit of 8, CG stops with `LinearIterationLimit`.
Here `solve_into` returns no error; it writes the iterate returned by the injected solver to `values` and returns a report with `DiagnosticOnly` trust in `Ok`.
When CG from `scioxide-linalg` stops at its limit, it checks the true residual of the current iterate and returns the checked iterate with the smallest residual.
The final residual in this example is $2.13\times10^{1}$, smaller than the residual $\lVert b\rVert_2\approx1.72\times10^{2}$ at the initial zero vector, but the maximum error is 4.16, far from the solution.
The outcome is `partial`.
Do not use `DiagnosticOnly` values as a solution; change the limit or solver and solve again.
Because spatial discretization reproduces this linear solution exactly, this example does not measure grid error for general problems.
If only owned results are needed, call `EllipticProblem::solve_with_options` without creating a workspace to receive `EllipticSolution`.

## Reading results, errors, and diagnostics

- **Termination reason**: `PdeTermination` is the sole authority.
  Every reason other than `Completed` (`LinearIterationLimit`, `LinearStagnation`, `LinearConditionLimit`, `LinearBreakdown`, `LinearLeastSquaresConverged`, `TimeStepLimit`, `TimeStepSizeLimit`, `EvaluationLimit`, `ExecutionStopped`) means the requirements are not satisfied, even when returned in `Ok`.
  Decide with `report.is_success()`.
  `LinearLeastSquaresConverged` means only the normal equations have converged; it does not show that the physical equations have been solved.
- **Trust**: `PdeSolveReport::trust` indicates trust in the state published to output.
  In steady solves where an injected iterative method stops at an iteration limit, stagnation, or condition-number limit, the unconverged iterate is written with `DiagnosticOnly` trust.
- **Errors**: inconsistent inputs, boundaries, or mesh revisions produce `InvalidInput`; array length mismatches produce `DimensionMismatch`; non-finite callback values produce `NonFinite`.
  Read the classification through `e.kind()` and `e.view()`.
  `EllipticProblem::solve_into` leaves `out` unchanged on error.
  On error, `ParabolicProblem::advance` leaves the last accepted point in the state and records attempted progress in `PdeWorkspace::last_attempt`.
  The owned time-evolution APIs `solve` and `solve_with_options` return the last accepted progress in `PartialFailure<PdeProgress>` on error.
  In the owned-result API, `solve` turns unsuccessful termination reasons into errors for both steady and time-dependent solves.
  `solve_with_options` retains the termination reason in its report and returns it in `Ok`.
- **Diagnostics**: `PdeDiagnostics` records inner linear iteration counts and residuals; attempted, accepted, rejected, and failed time steps; and counts of right-hand-side evaluations, Jacobian evaluations, assemblies, and factorizations.
  For problems with a nullspace, read `nullspace()` (augmented-system diagnostics) and `nullspace_gauge_defect()` (the requested gauge defect) separately.
  See [Compatibility conditions, gauges, and conservative fluxes for elliptic problems](../algorithms/compatibility-gauges-and-fluxes/) for details.
- **Using only a plan**: a plan only constructs an operator and load, so check termination in the report of the solver you choose.
  Checks such as `check_constant_mode_compatibility` are algebraic conditions and do not certify uniqueness or accuracy of the solution.

## Summary

Prepare a spatial discretization plan once from the boundary-condition list and coefficients, then pass it to `EllipticProblem` for a steady problem or `ParabolicProblem` and `HyperbolicProblem` for time evolution.
The same plan works in one to three dimensions for every solve under the same contract `SpatialDiscretization`.
Judge results with `is_success()` of `PdeTermination`; after stopping at a limit, use `PdeSolveReport::trust` and the iteration counts and residuals of `PdeDiagnostics` to decide how to treat the values.
The caller owns and reuses workspaces and states; what remains after an error is defined for each kind of solve.
Use elasticity, incompressible flow, conservation laws, adjoints, and adaptive refinement by passing residuals, tangents, and operators to existing solvers.
