This page collects steady and time-evolution solves using spatial discretization plans, time-evolution output and resumption, and result types.
Problems (`EllipticProblem`, `ParabolicProblem`, `HyperbolicProblem`) borrow plans and sources; settings (`EllipticOptions`, `ParabolicOptions`, `HyperbolicOptions`) are immutable values passed on each call.
The caller owns workspaces and time-evolution states.
APIs with caller-specified outputs (`solve_into`, `advance`, `resume`) use the caller's execution context as one solve epoch; owned-result APIs (`solve`, `solve_with_options`) allocate and return results using sequential native execution.
Unsuccessful termination reasons are recorded in reports returned in `Ok` and are distinguished from errors.
However, `solve` in the owned-result API also turns unsuccessful termination reasons into errors.

## Summary

Construct steady solves with `EllipticProblem`, and time evolution with `ParabolicProblem` and `HyperbolicProblem`, `PdeState`, and `PdeWorkspace`.
APIs with specified outputs update the caller's arrays and states; owned-result APIs allocate and return results.
On failure, owned time-evolution APIs return the last accepted progress in `PartialFailure`.
Select intermediate fields with `PdeOutputSchedule`, receive them sequentially through `PdeOutputSink`, save with `PdeCheckpoint`, and continue with `resume`.
Judge results with `is_success()` of `PdeTermination`; for elliptic problems with nullspaces, check augmented-system diagnostics separately from requested gauge defects.
