In floating-point [partial-fraction decomposition](../partial-fractions/), approaching poles increase coefficient error to roughly unit roundoff divided by reciprocal conditioning; poles that are too close cause Plan preparation to be rejected.
Exactly representable coefficients such as rationals allow decomposition using field operations without rounding, making the resulting terms an exact equality.
This page covers the algorithm and contract of `ExactPartialFractionPlan` and use of a user-implemented rational coefficient type.
Existence, uniqueness, and residue formulas appear in [Partial-fraction decomposition](oxref:poly-partial-fraction-form).

## Cofactor inverses and F-adic expansions

`ExactPartialFractionPlan::new(&denominator, &[(&factor, multiplicity), ...])` checks a monic denominator with `ExactField` coefficients, monic nonconstant factors, and positive multiplicities.
A nonmonic denominator, constant or nonmonic factors, zero multiplicity, mismatched degree sums, factor-power products not exactly matching the denominator, or noncoprime factors give `InvalidInput` (`Inconsistent`).
Factors need not be irreducible; the Plan does not search for irreducible factors.
Preparation computes each cofactor $C_i = D / F_i^{m_i}$ inverse modulo $F_i^{m_i}$ once using extended Euclid.
Absence of an inverse also detects noncoprime factors.
Preparation uses $O(r n^2)$ field operations for $r$ factors and $n = \deg D$; the Plan retains $O(n)$ coefficients.
Coefficient-type division violating $(a/b) \cdot b = a$ gives `NumericalInstability` (`Breakdown`).

`decompose(&numerator)` divides numerator by denominator to obtain the polynomial part and remainder $R$, then computes $A_i = R\, C_i^{-1} \bmod F_i^{m_i}$ with one product and one remainder per factor.
Repeated division of $A_i$ by $F_i$ extracts power terms through an $F_i$-adic expansion (J. von zur Gathen and J. Gerhard, *Modern Computer Algebra*, 3rd ed., Cambridge University Press, 2013, §5.11).
Numerator degree is unrestricted.
The resulting `ExactPartialFractions` contains polynomial part `polynomial()` and a sequence `terms()` of `ExactPartialFractionTerm` in factor input order then ascending power order; `reconstruct()` converts their sum back to reduced `ExactRationalFunction`.
Each term contains factor `factor()`, power `power()`, and numerator `numerator()`; for a linear factor at power 1, the numerator is a constant residue.
There is no floating-point rounding, so the resulting terms form an equality without reports or tolerances.

## Decomposition with rational coefficients

SciOxide provides no rational coefficient type.
The following definitions block implements `ExactCoefficient` and `ExactField` for reduced fractions `Q` over `i128`, with display helper `show` listing polynomial coefficients as “numerator/denominator”.
`Q` arithmetic does not check overflow; use only inputs whose intermediates stay within `i128`.

```rust
//| id: poly-partial-fraction-rational-type
//| kind: definitions
//| title: "Rational coefficient type using reduced i128 fractions"
//| crates: [scioxide-poly]
use scioxide_poly::{ExactCoefficient, ExactField, ExactPolynomial};
use std::ops::{Add, Div, Mul, Neg, Sub};

/// Rationals as reduced p/q (q > 0). Cancel before products and sums to reduce i128 overflow risk
#[derive(Clone, Copy, Debug, PartialEq)]
pub(crate) struct Q(pub(crate) i128, pub(crate) i128);

fn gcd(x: i128, y: i128) -> i128 {
    let (mut x, mut y) = (x.abs(), y.abs());
    while y != 0 {
        (x, y) = (y, x % y);
    }
    x
}

impl Q {
    pub(crate) fn new(a: i128, b: i128) -> Self {
        let g = gcd(a, b) * b.signum();
        Self(a / g, b / g)
    }
}

impl Add for Q {
    type Output = Self;
    fn add(self, b: Self) -> Self {
        let g = gcd(self.1, b.1);
        Self::new(self.0 * (b.1 / g) + b.0 * (self.1 / g), self.1 / g * b.1)
    }
}

impl Neg for Q {
    type Output = Self;
    fn neg(self) -> Self {
        Self(-self.0, self.1)
    }
}

impl Sub for Q {
    type Output = Self;
    fn sub(self, b: Self) -> Self {
        self + -b
    }
}

impl Mul for Q {
    type Output = Self;
    fn mul(self, b: Self) -> Self {
        let (g, h) = (gcd(self.0, b.1), gcd(b.0, self.1));
        Self::new((self.0 / g) * (b.0 / h), (self.1 / h) * (b.1 / g))
    }
}

impl Div for Q {
    type Output = Self;
    fn div(self, b: Self) -> Self {
        self * Q::new(b.1, b.0)
    }
}

impl ExactCoefficient for Q {
    fn zero() -> Self {
        Q(0, 1)
    }
    fn one() -> Self {
        Q(1, 1)
    }
    fn from_usize(n: usize) -> Self {
        Q(n as i128, 1)
    }
}

impl ExactField for Q {}

/// String of ascending-power coefficients as “numerator/denominator”
pub(crate) fn show(p: &ExactPolynomial<Q>) -> String {
    let terms: Vec<String> = p
        .coefficients()
        .iter()
        .map(|q| {
            if q.1 == 1 {
                q.0.to_string()
            } else {
                format!("{}/{}", q.0, q.1)
            }
        })
        .collect();
    terms.join(", ")
}
```

The next cell decomposes the same rational function as the [floating-point decomposition cell](oxref:poly-partial-fraction-repeated-poles), using rational coefficients.
The denominator is $D = (x - 1)^2 F_1$ ($F_1 = (x - 1)^2 + s^2$); the numerator combines partial fractions $a/(x-1) + 2/(x-1)^2 + (3 + 4x)/F_1$ over a common denominator, with factor $x - 1$ at multiplicity 2 and $F_1$ at multiplicity 1.
Inputs are simple-pole coefficient $a$ and a choice of pole-pair distance $s$.
At $s = 0$, $F_1 = (x - 1)^2$, so the two factors are not coprime.
The first table compares each term's factor and numerator with the numerator used to construct it.
The second compares the rational function from `reconstruct()` with reduced $N/D$ by equality (independent check).

```rust
//| id: poly-exact-partial-fractions
//| ref: poly-exact-partial-fractions
//| title: "Exact partial fractions with rational coefficients"
//| run: reactive
//| uses: [poly-partial-fraction-rational-type]
//| crates: [scioxide-poly]
//| inputs:
//|   residue: {"type":"range","label":"Simple-pole coefficient a [-]","min":-2,"max":3,"step":1,"value":1}
//|   spacing: {"type":"select","label":"Pole-pair distance s","description":"At s = 0, F₁ = (x − 1)², making the factors noncoprime.","options":["1","1/16","1/256","0"],"value":"1/256"}
//| cases:
//|   - {"id":"unit-spacing","label":"s = 1","description":"Even for separated poles, coefficients exactly match construction values.","inputs":{"spacing":"1"}}
//|   - {"id":"coincident","label":"s = 0","description":"Noncoprime factors are rejected as InvalidInput during Plan preparation.","inputs":{"spacing":"0"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"terms","path":"/rows/0/2","equals":"1"}
//|       - {"artifact":"terms","path":"/rows/2/2","equals":"3, 4"}
//|       - {"artifact":"terms","path":"/rows/2/4","equals":"Equal"}
//|       - {"artifact":"check","path":"/rows/0/0","equals":"Equal"}
//|   - case: unit-spacing
//|     expect:
//|       - {"artifact":"terms","path":"/rows/1/2","equals":"2"}
//|       - {"artifact":"check","path":"/rows/0/0","equals":"Equal"}
//|   - case: coincident
//|     expect:
//|       - {"artifact":"rejection","path":"/rows/0/0","equals":"InvalidInput"}
use scioxide_poly::{ExactPartialFractionPlan, ExactPolynomial, ExactRationalFunction};

let s = match spacing.as_str() {
    "1" => Q(1, 1),
    "1/16" => Q(1, 16),
    "1/256" => Q(1, 256),
    _ => Q(0, 1),
};
let poly = |c: Vec<Q>| ExactPolynomial::new(c).map_err(|e| e.to_string());
let a = Q(residue as i128, 1);
let linear = poly(vec![Q(-1, 1), Q(1, 1)])?;
let square = linear.try_mul(&linear).map_err(|e| e.to_string())?;
// F₁ = (x − 1)² + s². The numerator combines a/(x − 1) + 2/(x − 1)² + (3 + 4x)/F₁ over a common denominator
let pair = poly(vec![Q(1, 1) + s * s, Q(-2, 1), Q(1, 1)])?;
let denominator = square.try_mul(&pair).map_err(|e| e.to_string())?;
let head = poly(vec![Q(2, 1) - a, a])?;
let tail = poly(vec![Q(3, 1), Q(4, 1)])?;
let numerator = head
    .try_mul(&pair)
    .and_then(|p| p.try_add(&tail.try_mul(&square)?))
    .map_err(|e| e.to_string())?;
match ExactPartialFractionPlan::new(&denominator, &[(&linear, 2), (&pair, 1)]) {
    Err(error) => {
        emit_table_with_columns!(
            ["Error classification", "Detail"],
            vec![(format!("{:?}", error.kind()), format!("{:?}", error.view()))],
            metadata = serde_json::json!({ "id": "rejection" })
        );
    }
    Ok(plan) => {
        let fractions = plan.decompose(&numerator).map_err(|e| e.to_string())?;
        // Independent check 1: compare exactly with construction numerators a, 2, and 3 + 4x
        let expected = [vec![a], vec![Q(2, 1)], vec![Q(3, 1), Q(4, 1)]];
        let mut rows = Vec::new();
        for (term, reference) in fractions.terms().iter().zip(expected) {
            let reference = poly(reference)?;
            let verdict = if term.numerator() == &reference {
                "Equal"
            } else {
                "Unequal"
            };
            rows.push((
                show(term.factor()),
                term.power(),
                show(term.numerator()),
                show(&reference),
                verdict,
            ));
        }
        emit_table_with_columns!(
            [
                "Factor (ascending powers)",
                "Denominator power",
                "Numerator (ascending powers)",
                "Construction numerator",
                "Comparison"
            ],
            rows,
            metadata = serde_json::json!({ "id": "terms" })
        );
        // Independent check 2: reconstruct the term sum as a reduced rational function and compare with reduced N/D
        let rebuilt = fractions.reconstruct().map_err(|e| e.to_string())?;
        let original = ExactRationalFunction::new(numerator.clone(), denominator.clone())
            .map_err(|e| e.to_string())?;
        let verdict = if rebuilt == original {
            "Equal"
        } else {
            "Unequal"
        };
        emit_table_with_columns!(
            ["reconstruct versus N/D", "Polynomial part"],
            vec![(verdict, show(fractions.polynomial()))],
            metadata = serde_json::json!({ "id": "check" })
        );
    }
}
```

At the default $s = 1/256$, the constant coefficient of $F_1$ is $65537/65536$; the three numerators exactly match construction values $1$, $2$, and $3 + 4x$, and `reconstruct()` agrees with the original rational function.
Even nearby poles rejected by the floating-point Plan with $s = 2^{-24}$ ([Coefficient errors and reconstruction at nearby poles](oxref:poly-partial-fraction-near-poles-error)) can be decomposed by the exact Plan while the coefficient type represents the values.
At $s = 0$, preparation is rejected with `InvalidInput` (`Inconsistent`, detail "factors must be pairwise coprime").
The floating-point Plan rejects through numerical rank; the exact Plan rejects through absence of an inverse.
Exact-operation error is 0, but intermediate rational digit counts grow as $s$ decreases.
For this cell's `Q`, intermediate products exceed `i128` at $s = 1/4096$, so that value is excluded from the options.
Exact-operation costs count coefficient operations; the user's coefficient type determines coefficient digit growth.

## Summary

For a field with exactly representable coefficients, `ExactPartialFractionPlan` prepares cofactor inverses once, and decomposition holds as an equality without rounding.
Exact Plans decompose even nearby poles rejected by floating-point numerical rank while the factors remain coprime.
Noncoprime factors are detected by missing inverses, giving `InvalidInput` (`Inconsistent`).
SciOxide supplies no rational type; provide a type implementing `ExactCoefficient` and `ExactField`, managing coefficient digit growth and limits in that type.
