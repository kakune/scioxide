In polynomial computation, error propagation depends on the storage basis and coefficient type even for the same expression.
Function approximation, coefficient operations, and root diagnostics serve different purposes, so interpret them using error measures appropriate to the desired result.
This page collects error distinctions, notation, and conventions shared by the algorithm pages, followed by a page map.

## Three kinds of error

Suppose function $f$ is approximated by degree-$n$ polynomial $p_n$, whose value at point $x$ is computed in floating-point arithmetic as $\widehat p_n(x)$.
The total error splits into two terms.

$$
f(x)-\widehat p_n(x)=\underbrace{f(x)-p_n(x)}_{\text{approximation error}}+\underbrace{p_n(x)-\widehat p_n(x)}_{\text{computational error}} .
$$

The first term, approximation error (representation error), depends on degree, node placement, sample noise, and function smoothness, and remains however accurately the computation is performed.
The second term arises from rounding stored coefficients and arithmetic operations.
The standard numerical-analysis approach estimates this term as the product of backward error and condition number.

Backward error is the smallest input perturbation for which computed $\widehat p_n(x)$ can be viewed as the exact value for a slightly perturbed input.
For polynomial evaluation, view it as the exact value of a polynomial with coefficients changed to $a_k(1+\theta_k)$ and use $\eta=\max_k|\theta_k|$ as componentwise backward error.
The condition number is a property of the problem itself, measuring amplification from relative input perturbations to relative output changes.
Together, they give the following first-order relation.

$$
\frac{|p_n(x)-\widehat p_n(x)|}{|p_n(x)|}\lesssim\kappa(p_n,x)\,\eta .
$$

An algorithm with small backward error is called backward stable.
Even a backward-stable algorithm can have large forward error (error in the value itself) for an ill-conditioned problem.

| Error or sensitivity | Quantity examined | Main checks |
|---|---|---|
| Approximation error | $f-p_n$; depends on degree, nodes, samples, and function analyticity | Known functions, changes as degree increases, and evaluation on independent grids |
| Rounding and backward errors | Difference between the stored polynomial's exact and computed values, expressed as coefficient perturbations | Closed forms, other evaluation methods, and error analysis with satisfied assumptions |
| Condition number | Amplification of coefficient, node, or sample-value perturbations into changes in values or roots | Coefficient perturbation experiments, condition estimates, and repeated/clustered-root diagnostics |

A small residual does not directly imply small approximation error against the original function or small root forward error.
Exact coefficient types preserve equalities in algebraic operations but do not remove input-model errors.
Backward errors, forward errors, condition numbers, and residuals returned by APIs are estimates, not certified enclosures.
Definitions of shared concepts appear in [Floating point and conditioning](../../concepts/floating-point-and-conditioning/) and [Tolerances and residuals](../../concepts/tolerances-and-residuals/).

## Notation

| Symbol | Meaning |
|---|---|
| $n$, $N$ | Polynomial degree and stored-coordinate count ($N=n+1$ for monomials) |
| $m$ | Number of samples or evaluation points, as specified in the text |
| $a_k$ | Monomial coefficients in ascending powers |
| $c_k$, $\phi_k$ | Coefficients and basis functions of the specified basis |
| $x$, $t$ | Physical and reference coordinates; $t=(x-\mathrm{shift})/\mathrm{scale}$ for orthogonal bases |
| $u$, $\varepsilon$ | Unit roundoff and machine epsilon (`EPSILON`); $u=\varepsilon/2=2^{-53}$ for binary64 round-to-nearest |
| $\gamma_j(u)$, $\gamma_j(\varepsilon)$ | $ju/(1-ju)$ and $j\varepsilon/(1-j\varepsilon)$; error-analysis theorems use the former and the API rounding model the latter |
| $\kappa$, $\eta$ | Condition number under the specified perturbation model, and normalized backward error |

Because $\gamma_j(\varepsilon)=\gamma_{2j}(u)$, values based on $\varepsilon$ are approximately twice those based on $u$ even with identical indices.
Before comparing theorem bounds and API estimates, check which $\gamma$ is used.

## Shared conventions

Stored coordinates are the sequence of numbers a type retains to represent a polynomial: coefficients, nodal values, or control points depending on the basis.
`PolynomialBasis::coefficients` borrows stored coordinates without implicit monomial conversion.
Monomial constructors remove only exact trailing zeros and do not automatically discard small coefficients.
Approximate polynomials retain `PolynomialApproximationPolicy` (coefficient tolerances and numerical-rank rules), and binary operations require both policies to match.
Data-only constructors use the default policy; `_with_options` forms accept alternatives.

Caller-supplied scratch space is an `&mut [..]` slice that functions do not grow.
`workspace_requirements` returns the required length; shorter slices yield `DimensionMismatch` before numerical computation, while longer slices are accepted.
Output slices must have exactly the required length.
Scratch contents may change on either success or failure; outputs are written only on success.
For reusable workspace, obtain requirements with `workspace_requirements`, create it with `workspace` or grow existing storage with `try_reserve`, and check capacity with `check`.
Reservations grow without shrinking, so workspace reserved for the largest requirement also serves smaller ones.
Except in `backend`, `_into` functions take `ExecutionContext` last and either commit the entire output or leave it unchanged on failure.
Exceptions are `LinearOperator::apply_into` implemented by `OrthogonalTransform` and `OrthogonalDerivative`: they take no `ExecutionContext` but still preserve output on failure.
Low-level `_into` functions in `backend` take no `ExecutionContext` and may partly modify output on failure; each page explains these individually.

## Summary

Split total error into approximation and computational errors, estimating computational error through backward error times condition number.
Even small backward errors can accompany large relative value errors when the condition number is large.
Before comparing theorem bounds with API estimates, check whether $\gamma_j$ uses unit roundoff $u$ or machine epsilon $\varepsilon$.
The caller queries and supplies scratch lengths; outputs are written only on success.
