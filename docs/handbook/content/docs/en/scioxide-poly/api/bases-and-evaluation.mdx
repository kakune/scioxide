This table collects public items for floating-point polynomial representation, evaluation, and basis conversion.
`ApproxPolynomial<C, B>` encodes coefficient scalar type `C` (real or complex) and prepared basis `B` in its type, retaining immutable approximation policy `PolynomialApproximationPolicy`.
The meaning of stored coordinates (coefficients, sample values, control points, or other basis-specific numerical sequences) depends on the basis.
Monomial coefficients and Newton coefficients constructed by interpolation or conversion have exact trailing zeros removed.
Newton coefficients supplied through `newton`, barycentric sample values, Bernstein control points, and orthogonal expansion coefficients retain trailing zeros.
Single-point evaluation takes no scratch-space argument.
Query scratch lengths for allocation-free multipoint methods such as `evaluate_batch_into` through `workspace_requirements(m)` ($m$ is the point count).

## Basis kernels (backend)

`scioxide_poly::backend` contains low-level functions and types shared by scioxide-poly, scioxide-interp, and others.
Input slices are unchanged.
Many functions taking output or working arrays can leave output unspecified on failure.
For ordinary use, prefer `ApproxPolynomial` constructors and evaluation.

## Summary

Construct floating-point polynomials with `ApproxPolynomial` and an explicit basis type; convert explicitly through `to_*` and read `PolynomialConversion` diagnostics.
`evaluate` returns values and `evaluate_with_derivative` adds derivatives and conditioning reports; query scratch lengths for batch `_into` forms through `workspace_requirements(m)`.
For complex points and root iterations, specify the basis through `PolynomialRootBasisRef` and use `checked_basis_evaluation`.
Create matrices with roots as eigenvalues using `root_matrix` or `polynomial_root_matrix_into` and compute eigenvalues through `scioxide-linalg`.
