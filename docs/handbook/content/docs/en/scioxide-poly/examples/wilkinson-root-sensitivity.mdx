Separated roots do not imply a well-conditioned coefficient-to-root problem.
Wilkinson polynomial $W_n(x)=\prod_{j=1}^n(x-j)$ has integer roots spaced by 1, yet small coefficient errors move them substantially (J. H. Wilkinson, 1959).
This page separates three sources of root-position error.
They are binary64 coefficient storage rounding, intentional coefficient perturbations, and root-computation error from matrix eigenvalues.
Coefficients, roots, and perturbations are all dimensionless.

## Closed-form conditioning at simple roots

Coefficients of $W_n(x)=\sum_ja_jx^j$ alternate in sign; their magnitudes equal coefficients of $\prod_{j=1}^n(x+j)$.
Thus at root $k$,

$$
|W_n'(k)|=\prod_{j\ne k}|k-j|=(k-1)!\,(n-k)!,\qquad
\sum_j|a_j|k^j=\prod_{j=1}^n(k+j)=\frac{(k+n)!}{k!}
$$

and substitution into [simple-root sensitivity](oxref:poly-simple-root-sensitivity) gives

$$
\kappa_{\rm abs}(k)=\frac{(k+n)!}{k!\,(k-1)!\,(n-k)!}
$$


$\kappa_{\rm abs}$ is the first-order coefficient of root movement $|\Delta r_k|\lesssim\eta\,\kappa_{\rm abs}(k)$ under coefficient changes bounded by $|\Delta a_j|\le\eta|a_j|$.
The derivative itself is $W_n'(k)=(-1)^{n-k}(k-1)!\,(n-k)!$, alternating signs at adjacent roots.

The following definitions implement integer coefficients and both closed forms as Rust functions.
`wilkinson_coefficients` successively multiplies $(x-k)$ to construct exact coefficients in `i128`; `derivative_at_root` returns $W_n'(k)$ and `closed_condition` returns $\kappa_{\rm abs}(k)$.
Factorials use `f64` products, exact through $22!$; larger arguments add relative rounding at most $u$ per multiplication.

```rust
//| id: poly-wilkinson-model
//| kind: definitions
//| title: "Wilkinson integer coefficients and closed-form conditioning"
//| crates: []
/// Ascending integer coefficients a_0, …, a_n of W_n(x) = (x − 1)(x − 2)…(x − n).
/// For n ≤ 20, |a_j| < 2⁶⁴, permitting exact i128 construction.
pub(crate) fn wilkinson_coefficients(n: usize) -> Vec<i128> {
    let mut coefficients = vec![1_i128];
    for k in 1..=n {
        // Multiply the current polynomial by (x − k).
        coefficients.push(0);
        for j in (1..coefficients.len()).rev() {
            coefficients[j] = coefficients[j - 1] - k as i128 * coefficients[j];
        }
        coefficients[0] *= -(k as i128);
    }
    coefficients
}

/// Return m! using f64 products; exact through 22!.
pub(crate) fn factorial(m: usize) -> f64 {
    (1..=m).map(|j| j as f64).product()
}

/// Derivative at root k: W_n′(k) = (−1)^(n−k) (k−1)! (n−k)!.
pub(crate) fn derivative_at_root(n: usize, k: usize) -> f64 {
    let sign = if (n - k) % 2 == 0 { 1.0 } else { -1.0 };
    sign * factorial(k - 1) * factorial(n - k)
}

/// Absolute condition number at k: κ_abs(k) = (k+n)! / (k! (k−1)! (n−k)!).
pub(crate) fn closed_condition(n: usize, k: usize) -> f64 {
    factorial(k + n) / (factorial(k) * factorial(k - 1) * factorial(n - k))
}
```

## Coefficient rounding

Coefficients of $W_{20}$ include integers above $2^{53}$, some unrepresentable exactly in binary64.
Rounding errors $\Delta a_j$ can be computed exactly by converting stored values back to integers and subtracting originals.
Simple-root sensitivity gives first-order shifts of stored-polynomial roots,

$$
\Delta r_k\approx-\frac{\sum_j\Delta a_jk^j}{W_n'(k)}
$$


With unit roundoff $u=2^{-53}\approx1.1\times10^{-16}$, relative coefficient errors are at most $u$, so first-order $|\Delta r_k|$ does not exceed $\kappa_{\rm abs}(k)\,u$.
$\kappa_{\rm abs}u$ assumes all coefficients move by worst-directed $u$; actual rounding affects only some coefficients, allowing much smaller first-order predictions.

The next cell takes degree $n$, rounds integer coefficients to binary64 once, and emits three tables.
The first lists stored coefficients, rounding errors $\Delta a_j$, and relative-error-to-$u$ ratios.
The second lists each integer root $k$, closed conditioning, relative discrepancies of SciOxide estimates (`RootConditionReport::absolute` from `root_condition`), predicted rounding shifts, and $\kappa_{\rm abs}u$.
The third summarizes changed coefficient count, maximum first-order prediction and its root, and maximum condition-estimate discrepancy.
Closed forms are independent checks; SciOxide uses stored coefficients to evaluate $\sum_j|a_j||z|^j/|p'(z)|$ at $z=k$ in floating point.

//| tests:
//|   - case: default
//|     expect:

//|       - {"artifact":"roots","path":"/rows/13/1","approx":{"value":7.5528e14,"rtol":1e-4}}

let n = degree as usize;
let unit_roundoff = f64::EPSILON / 2.0;
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let sci6 = serde_json::json!({ "notation": "scientific", "significantDigits": 6 });

// Construct exact integer coefficients, then round once to binary64.
let integers = wilkinson_coefficients(n);
let stored: Vec<f64> = integers.iter().map(|&a| a as f64).collect();
// Δa_j = stored value − integer value. Stored values are integers, allowing exact i128 subtraction.
let rounding: Vec<f64> = integers
    .iter()
    .zip(&stored)
    .map(|(&exact, &value)| (value as i128 - exact) as f64)
    .collect();
let coefficient_rows: Vec<(usize, f64, f64, f64)> = stored
    .iter()
    .zip(&rounding)
    .enumerate()
    .map(|(j, (&a, &d))| (j, a, d, (d / a).abs() / unit_roundoff))
    .collect();

        { "key": "1", "label": "Stored coefficient a_j [-]", "type": "number", "format": sci6 },

);

    let x = k as f64;
    let condition = closed_condition(n, k);
    // SciOxide estimate: RootConditionReport::absolute at z = k using stored coefficients
    let estimate = polynomial
        .root_condition(x)
        .map_err(|e| e.to_string())?
        .absolute()
        .value()
        .ok_or("No condition estimate")?;
    // Independent check: Horner sum Σ Δa_j k^j. Δa_j and k^j are integers and the sum is below 2⁵³, making it exact.
    let shift = rounding.iter().rev().fold(0.0, |sum, &d| sum * x + d);
    let predicted = -shift / derivative_at_root(n, k);

        condition,
        estimate / condition - 1.0,
        predicted,
        condition * unit_roundoff,

);

let largest = rows
    .iter()
    .max_by(|a, b| a.3.abs().total_cmp(&b.3.abs()))
    .ok_or("No root")?;
let gap = rows.iter().map(|row| row.2.abs()).fold(0.0_f64, f64::max);
let changed = rounding.iter().filter(|&&d| d != 0.0).count();
emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "Coefficients changed by rounding", "type": "integer" },
        { "key": "1", "label": "Maximum first-order |Δr_k| [-]", "type": "number", "format": sci3 },
        { "key": "2", "label": "Maximizing root k", "type": "integer" },
        { "key": "3", "label": "Maximum relative condition discrepancy [-]", "type": "number", "format": sci3 }
    ]),
    vec![(changed, largest.3.abs(), largest.0, gap)],
    metadata = serde_json::json!({ "id": "summary" })
);

Default $n=20$ rounds five coefficients $a_3,\dots,a_7$; other coefficients and all coefficients of $n\le18$ are stored exactly.
At $n=19$, only $a_4,a_5$ are rounded.
Every coefficient has $|\Delta a_j|/(|a_j|u)$ at most 1, confirming binary64 storage rounding within relative error $u$.
The largest coefficient is not constant term $20!\approx2.43\times10^{18}$ but $1.38\times10^{19}$ of $x^2$.

Conditioning exceeds $10^{14}$ for $k=11$ through 18, peaking at $7.55\times10^{14}$ for $k=14,15$.
Thus $\kappa_{\rm abs}u$ reaches maximum $0.084$.
Actual rounding's first-order shift peaks at $-6.19\times10^{-4}$ for $k=13$, only about one hundredth of $\kappa_{\rm abs}u$.
This is far below root spacing 1; still smaller quadratic terms let first-order predictions closely approximate stored-polynomial roots.
Simple real roots stay real under small real perturbations, suggesting all stored-polynomial roots remain real and within $10^{-3}$ of integers.
Larger discrepancies or computed complex roots then reflect root-computation error, not coefficient rounding.

SciOxide condition estimates differ from closed forms by at most $7.5\times10^{-3}$ relatively.
Stored rounding changes $p'(k)$ by only about $3\times10^{-4}$, so discrepancies mostly reflect floating-point evaluation of $p'(z)$ at $z=k$.
Condition numbers are first-order estimates; these relative discrepancies do not change their interpretation.

## One-coefficient perturbation and linearization

Subtracting $\delta$ from the $x^{n-1}$ coefficient (changing $a_{n-1}=-n(n+1)/2$ to $a_{n-1}-\delta$) gives the first-order shifts of the roots of $p(x)=W_n(x)-\delta x^{n-1}$ as

$$
\Delta r_k\approx\frac{\delta\,k^{n-1}}{W_n'(k)}
$$


For Wilkinson's classical $n=20$ and $\delta=2^{-23}\approx1.19\times10^{-7}$, predicted magnitudes exceed $0.9$ at $k\ge10$ and reach 287 at $k=16$.
Predictions approaching root spacing cannot be interpreted as actual shifts.
Adjacent roots instead collide and split into conjugate pairs: five pairs $10.10\pm0.64i$, $11.79\pm1.65i$, $13.99\pm2.52i$, $16.73\pm2.81i$, and $19.50\pm1.94i$, with real roots such as $8.007$, $8.92$, and $20.85$.
Real coefficients require complex roots to appear in conjugate pairs.

Small $\delta$ may leave the stored coefficient unchanged after subtraction.
$a_{19}=-210$ has ULP $2^{-45}$; for $p\ge47$ with $\delta=2^{-p}$ below half-ULP $2^{-46}$, rounding erases the difference.
At exact half-ULP $p=46$, ties-to-even returns $-210$, so $p\ge46$ gives stored change 0.
Inspect both requested perturbation and stored change.

## Bases and input-error models

Besides monomial companion matrices, orthogonal colleague matrices are available ([Matrices with roots as eigenvalues and root sensitivity](oxref:poly-orthogonal-root-matrix)).
Convert stored monomial coefficients to Chebyshev through `to_orthogonal` before constructing the colleague matrix.
Basis coordinates $t=(x-(n+1)/2)/((n-1)/2)$ map root interval $[1,n]$ to $[-1,1]$.
Conversion starts from rounded monomials, cannot recover lost input information, and adds its own rounding.

Eigensolvers are matrix-backward-stable: computed eigenvalues are exact for matrices perturbed slightly relative to their norm.
For companion matrices, this maps to first-order coefficient perturbations governed by overall coefficient magnitudes rather than individual $|a_j|$ (Edelman–Murakami, 1995).
Small coefficients can thus receive relative componentwise perturbations far larger than $u$.
The bases give different forms of coefficient backward error from eigenvalue computation.
The next comparison solves the same stored polynomial through different matrices; it does not apply equal-size coefficient perturbations to both bases.

## Comparing rounding, perturbation, and algorithm errors

Inputs are degree $n$, exponent $p$ in perturbation $\delta=2^{-p}$, and matrix type.

use scioxide_core::Complex;
use scioxide_linalg::GeneralEigenvaluesResult;
use scioxide_poly::{
    ApproxPolynomial, BasisNormalization, OrthogonalBasisSpec, OrthogonalFamily,
};

let n = degree as usize;
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let base: Vec<f64> = wilkinson_coefficients(n)
    .iter()
    .map(|&a| a as f64)
    .collect();
// Subtract δ = 2^(−p) from the x^(n−1) coefficient. Rounding can make the stored change differ from δ.

    OrthogonalFamily::ChebyshevT,
    BasisNormalization::Classical,
    (n + 1) as f64 / 2.0,
    (n - 1) as f64 / 2.0,

        .iter()

        .fold(f64::INFINITY, f64::min)

        let predicted = stored_delta * x.powi(n as i32 - 1) / derivative_at_root(n, k);
        let unit = closed_condition(n, k) * f64::EPSILON / 2.0;

            k,
            predicted,
            nearest(&spectra[0], x),
            nearest(&spectra[1], x),
            unit,
        )
    })
    .collect();
emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "Integer root k", "type": "integer" },
        { "key": "1", "label": "Predicted first-order perturbation shift [-]", "type": "number", "format": sci3 },
        { "key": "2", "label": "Rounded coefficients: nearest-candidate distance [-]", "type": "number", "format": sci3 },
        { "key": "3", "label": "Perturbed coefficients: nearest-candidate distance [-]", "type": "number", "format": sci3 },
        { "key": "4", "label": "κ_abs·u [-]", "type": "number", "format": sci3 }

    rows,
    metadata = serde_json::json!({ "id": "roots" })
);

emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "Requested δ [-]", "type": "number", "format": sci3 },
        { "key": "1", "label": "Stored δ [-]", "type": "number", "format": sci3 },
        { "key": "2", "label": "Nonreal candidates (rounded coefficients)", "type": "integer" },
        { "key": "3", "label": "Nonreal candidates (perturbed)", "type": "integer" }

        requested,
        stored_delta,
        nonreal(&spectra[0]),
        nonreal(&spectra[1])
    )],
    metadata = serde_json::json!({ "id": "summary" })
);
// Pass candidates as (real part, imaginary part) pairs to the next cell.

    .iter()
    .map(|roots| roots.iter().map(|z| [z.re, z.im]).collect())
    .collect();
export!(coefficients, &vec![base, changed]);

## A posteriori candidate diagnostics

Use `polynomial_root_diagnostics` to assess candidate accuracy without knowing true roots.
It builds Weierstrass disks from all candidates, clustering connected components of overlapping disks ([Candidate roots and estimated disks](oxref:poly-root-candidate-disks)).
In exact arithmetic, an isolated union of $k$ disks contains exactly $k$ roots.
The floating-point implementation adds a radius term from the rounding model for evaluating $p(z_i)$.
These disks are estimates, not guaranteed enclosures.

Diagnostics also give each candidate $z$ the componentwise backward error

$$
\eta(z)=\frac{|p(z)|}{\sum_j|a_j||z|^j}
$$

(`RootConditionReport::coefficient` returns its reciprocal).
$\eta(z)$ is the smallest $\eta$ such that coefficient changes bounded by $|\Delta a_j|\le\eta|a_j|$ (allowing complex perturbations) make $z$ an exact root (Mosier, 1986; Toh–Trefethen, 1994).
To first order, candidate-to-root distance is at most $\eta\,\kappa_{\rm abs}$; $\eta\le u$ puts it within $\kappa_{\rm abs}u$, whereas $\eta$ far above $u$ indicates algorithm error larger than coefficient rounding.
$\eta$ also evaluates $p(z)$ in floating point; interpret values around $u$ as rounding-level indicators.

Status is `RootDiagnosticsStatus`; both sets `Estimated` give satisfied, while either `Inconclusive` gives partial.

use scioxide_core::Complex;
use scioxide_poly::{RootDiagnosticsStatus, RootEstimate, polynomial_root_diagnostics};

let unit_roundoff = f64::EPSILON / 2.0;
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let fixed1 = serde_json::json!({ "fractionDigits": 1 });
let coefficients: Vec<Vec<f64>> =
    serde_json::from_value(roots["coefficients"].clone()).map_err(|e| e.to_string())?;
let candidates: Vec<Vec<[f64; 2]>> =
    serde_json::from_value(roots["candidates"].clone()).map_err(|e| e.to_string())?;
let mut reports = Vec::new();
for (values, points) in coefficients.iter().zip(&candidates) {
    let roots: Vec<_> = points
        .iter()
        .map(|&[re, im]| Complex::new(re, im))
        .collect();
    // Estimate Weierstrass disks from monomial coefficients and all candidates.
    reports.push(polynomial_root_diagnostics(values, &roots).map_err(|e| e.to_string())?);
}
let rows: Vec<_> = ["Rounded coefficients", "Perturbed coefficients"]
    .iter()
    .zip(&reports)
    .map(|(name, report)| {
        let radius = report
            .roots()
            .iter()
            .filter_map(|root| root.disk().map(|disk| disk.radius().value()))
            .reduce(f64::max);
        // Componentwise η = |p(z)| / Σ|a_j||z|^j is the reciprocal of B/|p(z)|; it is 0 when p(z) = 0.
        let backward = report
            .roots()
            .iter()
            .filter_map(|root| match root.condition().coefficient() {
                RootEstimate::Singular => Some(0.0),
                estimate => estimate.value().map(|c| 1.0 / c),
            })
            .reduce(f64::max);
        (
            *name,
            backward.map(|eta| eta / unit_roundoff),
            report.clusters().len(),
            radius,
            format!("{:?}", report.status()),
        )
    })
    .collect();
let n = candidates[0].len();
let integers_on_axis: Vec<_> = (1..=n).map(|k| [k as f64, 0.0]).collect();
emit_scatter_chart!(
    &vec![
        serde_json::json!({
            "name": "Integer roots k (exact roots)",
            "points": integers_on_axis,
            "style": { "symbol": "diamond" }
        }),
        serde_json::json!({ "name": "Rounded-coefficient candidates", "points": candidates[0] }),
        serde_json::json!({ "name": "Perturbed-coefficient candidates", "points": candidates[1] })
    ],
    options = &serde_json::json!({
        "xLabel": "Root real part [-]",
        "yLabel": "Root imaginary part [-]",
        "xMin": 0.0,
        "xMax": 24.0,
        "yMin": -8.0,
        "yMax": 8.0
    })
);
emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "Coefficients" },
        { "key": "1", "label": "Maximum backward error η/u [-]", "type": "number", "format": fixed1, "nullText": "None" },
        { "key": "2", "label": "Clusters", "type": "integer" },
        { "key": "3", "label": "Maximum disk radius [-]", "type": "number", "format": sci3, "nullText": "None" },
        { "key": "4", "label": "Diagnostic status" }
    ]),
    rows,
    metadata = serde_json::json!({ "id": "clusters" })
);

let estimated = reports
    .iter()
    .all(|report| report.status() == RootDiagnosticsStatus::Estimated);
let outcome = if estimated {
    Outcome::satisfied("Estimated disks and clusters for both candidate sets")
        .explanation("Disks are rounding-model estimates, not proofs of root positions or counts.")
} else {
    Outcome::partial("Some candidate disks unavailable; used a Cauchy disk instead")
};
let status = format!("{:?} / {:?}", reports[0].status(), reports[1].status());
emit_outcome!(
    outcome
        .status(status)
        .diagnostic(
            "Clusters (perturbed)",
            reports[1].clusters().len() as f64,
            None
        )
        .diagnostic("Candidates", candidates[1].len() as f64, None)
);

With defaults, both sets are `Estimated`, yet all 20 candidates form one cluster.

Radii include term $n\cdot8(n+1)\varepsilon\sum_j|a_j||z_i|^j/(|a_n|\prod_{j\ne i}|z_i-z_j|)$ ($\varepsilon=2^{-52}=2u$).
Near integer candidates, the denominator is near $|W_n'(k)|$, making this term $16n(n+1)\,\kappa_{\rm abs}u\approx6700\,\kappa_{\rm abs}u$, about 560 at $k=14,15$.

## Summary

Separated roots need not be well-conditioned in coefficients; Wilkinson $W_{20}$ reaches conditioning $7.6\times10^{14}$.
Separate coefficient rounding, intentional perturbations, and eigensolver errors using first-order rounding predictions and $\kappa_{\rm abs}u$.
First-order sensitivity models small local perturbations and fails once predictions approach root spacing or roots collide.
Companion eigenvalues are not componentwise-coefficient-backward-stable; compare candidate backward error $\eta$ with $u$ and consider colleague matrices or final refinement for ill-conditioned polynomials.
Disks from `polynomial_root_diagnostics` are estimates; when central roots merge into one cluster, verify counts with proved methods.
Check requested perturbations against stored changes.
