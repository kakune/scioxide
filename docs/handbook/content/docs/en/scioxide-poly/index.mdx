`scioxide-poly` handles univariate polynomial representations and operations, interpolation, least-squares approximation, orthogonal expansions, rational functions, partial fraction decomposition, resultant-based elimination, root-sensitivity diagnostics, and sparse multivariate polynomials.
There are two coefficient types.
`ApproxPolynomial` stores real or complex floating-point coefficients in an explicit basis.
`ExactPolynomial` computes without rounding using coefficients from an exact ring or field supplied by the user.
Even for the same polynomial, the propagation of rounding error depends on what is stored: coefficients, values at nodes, or control points.
This page evaluates a low-degree polynomial to examine how to interpret values and diagnostics, then presents representation choices and the chapter structure.

## First computation

The coefficients $[a_0,a_1,a_2]=[2,-3,1]$ in ascending powers represent $p(x)=2-3x+x^2=(x-1)(x-2)$.
The following cell constructs this polynomial with `ApproxPolynomial::monomial` and uses `evaluate_with_derivative` to compute its value, derivative, and error estimates at the evaluation point $x$ together.
The input is the evaluation point $x$; both input and output are dimensionless.
As independent checks, it computes the factored form $(x-1)(x-2)$, analytic derivative $2x-3$, and diagnostic formulas (next section) by hand and displays them alongside the results.

```rust
//| id: poly-first-evaluation
//| ref: poly-first-evaluation
//| title: "Compute a value, derivative, and error estimates from coefficients"
//| run: reactive
//| crates: [scioxide-poly]
//| inputs:
//|   point: {"type":"range","label":"Evaluation point x [-]","description":"x = 1, 2 are roots, where relative diagnostics become unbounded.","min":-2,"max":4,"step":0.25,"value":1.5}
//| cases:
//|   - {"id":"at-root","label":"Root x = 1","description":"The value is 0, and the condition-number and forward-error estimates are +∞.","inputs":{"point":1}}
//|   - {"id":"far-point","label":"x = 4","description":"There is less cancellation between terms, and the condition-number estimate falls to 5.","inputs":{"point":4}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"values","path":"/rows/0/1","approx":{"value":-0.25,"atol":1e-15}}
//|       - {"artifact":"values","path":"/rows/1/1","approx":{"value":0,"atol":1e-15}}
//|       - {"artifact":"diagnostics","path":"/rows/0/1","approx":{"value":6.661338147750939e-16,"rtol":1e-12}}
//|       - {"artifact":"diagnostics","path":"/rows/1/1","approx":{"value":35,"rtol":1e-12}}
//|       - {"artifact":"diagnostics","path":"/rows/2/1","approx":{"value":2.3314683517128287e-14,"rtol":1e-12}}
//|   - case: at-root
//|     expect:
//|       - {"artifact":"values","path":"/rows/0/1","approx":{"value":0,"atol":1e-15}}
//|       - {"artifact":"values","path":"/rows/1/1","approx":{"value":-1,"atol":1e-15}}
//|       - {"artifact":"diagnostics","path":"/rows/1/1","equals":null}
//|       - {"artifact":"diagnostics","path":"/rows/2/1","equals":null}
//|   - case: far-point
//|     expect:
//|       - {"artifact":"values","path":"/rows/0/1","approx":{"value":6,"atol":1e-14}}
//|       - {"artifact":"values","path":"/rows/1/1","approx":{"value":5,"atol":1e-14}}
//|       - {"artifact":"diagnostics","path":"/rows/1/1","approx":{"value":5,"rtol":1e-12}}
//|       - {"artifact":"diagnostics","path":"/rows/1/2","approx":{"value":5,"rtol":1e-12}}
use scioxide_poly::ApproxPolynomial;

let polynomial =
    ApproxPolynomial::monomial(vec![2.0_f64, -3.0, 1.0]).map_err(|e| e.to_string())?;
let result = polynomial
    .evaluate_with_derivative(point)
    .map_err(|e| e.to_string())?;
let report = result.condition();
// Independent check: factored form (x − 1)(x − 2) and analytic derivative 2x − 3.
let expected = (point - 1.0) * (point - 2.0);
let slope = 2.0 * point - 3.0;
// Independent check: envelope Σ|a_k||x|^k, γ_3(ε) = 3ε/(1 − 3ε), condition number = envelope / |p(x)|.
let envelope = 2.0 + 3.0 * point.abs() + point * point;
let gamma = 3.0 * f64::EPSILON / (1.0 - 3.0 * f64::EPSILON);
let condition = (expected != 0.0).then(|| envelope / expected.abs());
// Because +∞ diagnoses an unbounded quantity, show a blank (None) in the table.
let finite = |value: f64| Some(value).filter(|v| v.is_finite());
let digits = serde_json::json!({ "significantDigits": 15 });
let sci4 = serde_json::json!({ "notation": "scientific", "significantDigits": 4 });
let value_columns = serde_json::json!([
    { "key": "0", "label": "Quantity" },
    { "key": "1", "label": "SciOxide [-]", "type": "number", "format": digits },
    { "key": "2", "label": "Independent check [-]", "type": "number", "format": digits }
]);
emit_table_with_columns!(
    value_columns,
    vec![
        ("Value p(x)", result.value(), expected),
        ("Derivative p′(x)", result.derivative(), slope),
    ],
    metadata = serde_json::json!({ "id": "values" })
);
let diagnostic_columns = serde_json::json!([
    { "key": "0", "label": "Diagnostic" },
    { "key": "1", "label": "SciOxide [-]", "type": "number", "format": sci4, "nullText": "+∞" },
    { "key": "2", "label": "Independent formula [-]", "type": "number", "format": sci4, "nullText": "+∞" }
]);
emit_table_with_columns!(
    diagnostic_columns,
    vec![
        (
            "backward_error()",
            Some(report.backward_error()),
            Some(gamma)
        ),
        (
            "condition_estimate()",
            finite(report.condition_estimate()),
            condition
        ),
        (
            "forward_error_estimate()",
            finite(report.forward_error_estimate()),
            condition.map(|kappa| gamma * kappa),
        ),
    ],
    metadata = serde_json::json!({ "id": "diagnostics" })
);
```

At the default $x=1.5$, the value is $-0.25$ and the derivative is $0$, agreeing with the factored form and analytic derivative ($x=1.5$ is the parabola's vertex).
At $x=4$, the value is $6$ and the derivative is $5$.
When only the value is needed, `evaluate` returns just the value from the same computation, bit-for-bit identical to the value from `evaluate_with_derivative`.

## Interpreting results

All three quantities in the `PolynomialConditionReport` returned by `condition()` are estimates derived from a rounding model.
`backward_error()` is $\gamma_3(\varepsilon)=3\varepsilon/(1-3\varepsilon)\approx6.661\times10^{-16}$, based on the number of coefficients $N=3$ and machine epsilon $\varepsilon=2^{-52}$, and is independent of the evaluation point.
This is a backward-error model: the computed value can be interpreted as the exact value of a polynomial whose coefficients have each changed by roughly this relative amount.
`condition_estimate()` estimates the relative condition number of evaluation,

$$
\kappa(p,x)=\frac{\sum_k|a_k||x|^k}{|p(x)|}
$$

which is $(2+4.5+2.25)/0.25=35$ at the default $x=1.5$.
The numerator $\sum_k|a_k||x|^k$ is called the evaluation envelope.
`forward_error_estimate()` is their product $\gamma_3(\varepsilon)\,\kappa\approx2.33\times10^{-14}$, indicating the relative error in the value.

At roots $x=1,2$, $p(x)=0$ removes the scale for relative error, and the condition-number and forward-error estimates become $+\infty$ (shown as blanks in the table).
This is not an error; it indicates that the relative diagnostics are unbounded.
These three quantities are not certified upper bounds and are distinct from the differences observed in the table.
A large condition number indicates a problem sensitive to input perturbations; it does not mean this particular input necessarily produces a large error.
See [Rounding error and diagnostics for Horner evaluation](algorithms/horner-rounding-error/) to derive the bounds and verify that SciOxide's arithmetic path satisfies their assumptions.

## Choosing a representation from the input

| Available data | Main entry points | Reason to choose | Mathematics |
|---|---|---|---|
| Low-degree coefficients with physical meaning | `ApproxPolynomial::monomial`, `from_roots` | Store coefficients in ascending powers directly | [Representations and Horner's method](algorithms/representation-and-horner/) |
| Distinct nodes and values to interpolate exactly | `interpolate_barycentric`, `interpolate_newton` | Store nodal values or divided differences, avoiding monomial expansion | [Interpolation and Chebyshev nodes](algorithms/interpolation-and-chebyshev/) |
| Expansion of a smooth function on an interval | `OrthogonalBasisSpec`, `ApproxPolynomial::orthogonal` | Retain the family, normalization, center, and scale | [Preparing, evaluating, and converting orthogonal bases](algorithms/orthogonal-bases-and-calculus/) |
| Noisy samples | `fit_monomial`, `fit_orthogonal`, `PolynomialFitPlan` | Choose the degree by checking weighted residuals and numerical rank | [Sample matrices and least squares](algorithms/least-squares-and-vandermonde/) |
| Control points of curves or surfaces | `ApproxPolynomial::bernstein`, `TensorBernstein` | Use the convex-hull property within the interval and subdivision | [Bernstein representation and de Casteljau's algorithm](algorithms/multivariate-and-bernstein/), [Tensor-product Bernstein polynomials and range estimation](algorithms/tensor-bernstein-bounds/) |
| Sparse multivariate terms | `ApproxSparsePolynomial`, `SparseEvaluationPlan` | Store only exponents and coefficients of nonzero terms | [Sparse multivariate polynomials](algorithms/sparse-multivariate/) |
| Coefficients in an exact ring or field | `ExactPolynomial`, `ExactRationalFunction` | Perform algebra with an exact coefficient type implemented by the caller | [Exact coefficient operations and product trees](algorithms/exact-arithmetic-and-product-trees/) |
| Numerator and denominator | `ApproxRationalFunction` | Distinguish evaluation near poles from explicit approximate cancellation | [Evaluating and reducing rational functions](algorithms/rational-functions/) |

Choosing barycentric form alone does not eliminate the Runge phenomenon.
Node placement determines the conditioning of the interpolation problem itself, while the representation determines how rounding error propagates when evaluating the same polynomial.
See the [selection guide](choosing/) for a detailed comparison.

## Unavailable features and the roles of other chapters

`scioxide-poly` provides root matrices (companion and comrade matrices) that turn root finding into eigenvalue problems, and diagnostics for previously computed root candidates (disks from Weierstrass corrections, clusters, and condition numbers).
It does not provide a solver that computes all roots themselves.
Use scioxide-rootfind's `polynomial_roots` for solving, and scioxide-linalg for eigenvalues of root matrices.
This chapter's disks and clusters are estimates; to certify the number of roots in a disk, use scioxide-validated's `polynomial_roots` (disks based on Rouché's theorem).

This chapter's `OrthogonalFamily` returns orthogonal-polynomial zeros (Golub–Welsch nodes computed as eigenvalues of the Jacobi matrix), and the Jacobi matrix itself.
This chapter does not provide Gaussian quadrature weights or rules; scioxide-integrate's `GaussianRulePlan` provides them.
It also does not construct AAA rational approximations from samples or Padé approximations from Taylor coefficients; use scioxide-interp's `aaa` and `PadeApproximant`.
This chapter's `ApproxRationalFunction` handles evaluation, reduction, and partial fraction decomposition of rational functions with a supplied numerator and denominator.

No crate provides best polynomial approximation (minimax approximation) of general functions using the Remez exchange algorithm.
The Remez exchange algorithm is used only for equiripple FIR filter design by scioxide-signal's `design_fir_remez` (the Parks–McClellan algorithm).
As alternatives to best approximation, use interpolation at Chebyshev nodes or least-squares approximation in a Chebyshev basis.
Factorization that searches for all polynomial factors is also unavailable.
The `gcd` of exact polynomials and partial fraction decomposition with supplied factors do not search for factors.

## Summary

In addition to the value and derivative, `evaluate_with_derivative` returns the backward-error model $\gamma_N(\varepsilon)$, a condition-number estimate, and their product, a forward-error estimate.
All three diagnostics are estimates; at roots, the condition-number and forward-error estimates become $+\infty$.
Choose whether to store coefficients, nodal values, control points, or orthogonal-expansion coefficients from the available data and your goal.
Use scioxide-rootfind to solve for all roots, scioxide-integrate for Gaussian quadrature weights, and scioxide-interp to construct AAA and Padé approximations; no crate provides best approximation using the Remez algorithm.
