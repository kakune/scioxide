Computation in `scioxide-random` has two stages: convert generator integer words to uniform randomness, then map it to probability laws or sequence coordinates.
Each chapter page covers an individual algorithm; this page collects their shared conventions.
Child pages refer here rather than repeating these terms and contracts.

## Notation and terminology

| Symbol or term | Meaning |
|---|---|
| Engine | Deterministic machine advancing finite state $s_n$ by $s_{n+1} = T(s_n)$ and returning output $G(s_n)$, such as `Pcg64`, `Xoshiro256StarStar`, or `Philox4x64`. No cryptographic security |
| Native word | Integer returned by a generator using the reference implementation's rules (`next_u32`, `next_u64`). Its range need not cover all of $2^{32}$ or $2^{64}$ |
| Uniform word | 32- or 64-bit integer with all bits uniform (`next_uniform_u32`, `next_uniform_u64`), used by index sampling, integer laws, and fast Ziggurat paths |
| $U$ | Uniform value on $[0, 1)$. An open interval $(0, 1)$ is stated explicitly when required |
| $F(x)$, $S(x)$ | CDF $P(X \le x)$ and survival probability $P(X > x)$. $S$ is not computed by subtraction $1 - F$ |
| $Q(p)$ | Quantile $\inf\{x : F(x) \ge p\}$. Inverse survival solves $S(x) = p$ directly |
| Position | Number of native-word transitions consumed since the generator started. `None` if untrackable |
| Seed | `u64` determining initial state, passed to `SeedableRng::from_seed` |
| Plan | Immutable value with completed validation and preprocessing, shared across repeated calls: `QmcPlan`, `QmcReplicatePlan`, `BrownianBridgePlan`, `MultivariateProbabilityPlan` |
| Sampling policy | Pair of output and state policies for batch generation into caller output: `SamplingPolicy` |
| Workspace | Caller-owned storage reused across repeated batches |

A probability law exposes capabilities such as sampling, density, CDF, quantiles, and moments through separate traits.
[Distribution capabilities, tail probabilities, and numerical inversion](laws-tails-and-multivariate-models/) describes capabilities and treatment of nonexistent quantities.

## Conversion to uniform words and floating-point values

`BitGenerator` distinguishes two kinds of output.
Native words reproduce each engine's reference sequence directly: `Mrg` and `Cmrg` return residues in $[0, 2^{31} - 1)$; `Mrg32k3a` returns integers in $[1, m_1]$ ($m_1 = 2^{32} - 209$); the `Ranlux` family returns 24- or 48-bit values.
Uniform words have all bits uniform even for limited-range engines; integer rejection normalizes native words, without retaining intermediate randomness.
Normalization concatenates as many native words as necessary as base-$m$ digits; for example, `Mrg32k3a` uses two native words for a 32-bit uniform word and three for 64 bits, repeating upon rejection.
The sampling path determines whether native or uniform words are used.
Uniform words are used by index sampling (`uniform_index` and permutations, sampling without replacement, and `WeightedSampler` column selection using it), integer laws (`CountDistribution`), the first Ziggurat word, Latin hypercubes and Poisson disks, and randomized-QMC preparation.
Multivariate, matrix, group, spherical-direction, and some test-statistic laws use an internal wrapper counting words per sample and construct floating-point uniforms from uniform words too.
In contrast, inversion for `Uniform`, `Cauchy`, and `Logistic`, Ziggurat wedges and tails, $U$ in gamma acceptance, and `WeightedSampler` acceptance use floating-point uniforms such as `Rng::next_float`; built-in generators construct these from one native word.
Consequently, for `Ranlux`, `Ranlxs`, `Ranlxd`, `Mrg`, `Cmrg`, and `Mrg32k3a`, sample sequences on uniform-word paths differ from values constructed directly from native-word sequences.
On floating-point paths, value spacing depends on native-word width.

Every built-in generator implements `Rng` for `f32` and `f64`, constructing floating-point uniforms from native words.
One floating-point value consumes one native word, with no values retained between calls.
Engines with 64-bit native words use `decode_u64` with the top 53 bits (`f64`) or top 24 bits (`f32`).

$$
u = \left\lfloor W / 2^{11} \right\rfloor \cdot 2^{-53} \in \left[0,\ 1 - 2^{-53}\right]
$$

`decode_u32` uses all 32 bits for `f64` and the top 24 for `f32`.
For engines with narrow native words, floating-point spacing is likewise determined by native width.
`f64` for `Ranlux` and `Ranlxs` packs 24-bit native words into the high bits, giving spacing $2^{-24}$; `Ranlxd` has spacing $2^{-48}$.
`f64` for `Mrg` and `Cmrg` divides residues by $2^{31} - 1$.
`f64` for `Mrg32k3a` preserves RngStreams normalization (word $\times 1/4\,294\,967\,088$), giving values in open interval $(0, 1)$.
No conversion rounds up to $1$.
`next_open_float` rejects $u = 0$ to return values in $(0, 1)$; 1,024 consecutive $0$ values give an iteration-limit error.
For direct user implementations of `Rng`, distribution APIs check each value for finiteness and membership in $[0, 1)$.
Values from overridden `next_open_float` implementations are also checked before sampling for finiteness and membership in $0 < u < 1$; zero or out-of-range values give `InvalidInput`, nonfinite values `NonFinite`.
Built-in conversions already guarantee the range, so this repeated check is skipped.
`fill_uniforms` fills caller storage with the same checks, without allocating, and adds provider-call counts to `attempts`.

## Scope of reproducibility

A named engine with explicit seed and identical call sequence produces identical results when its algorithm version and the version of word-to-uniform-word or floating-point conversion conventions (decoder conventions) match.
Fixed results include raw integers, floating-point values, bytes, `skip_ahead` and `jump` results, and streams selected by `split`.
`seed_sequence` and built-in QMC sequences follow the same rule.
Serialized states reject incompatible convention versions.
Distribution sampling algorithms and rounding, and runs seeded from entropy, lie outside this guarantee and can change between releases.
For example, changing normal Ziggurat tables or uniform-word usage changes normal samples from the same seed.
Sample values displayed by handbook cells are those at the commit described by this handbook.

Use `SerializableState` to save state.
The versioned `GRN2` envelope contains algorithm identity, endianness, stream identity (`StreamIdentity`), position, and CRC-32C, independent of platform and pointer width.
Restoration validates contents and identity before replacing state.
SciOxide reads no process or OS entropy.
`SeedableRng::seed_from_entropy` uses only the caller-supplied `scioxide_core::EntropySource`.

## Batch sampling and state handling

Sample generation has three forms.

| Form | Call | Output | On failure |
|---|---|---|---|
| One sample | `law.sample(rng)` | Returns a value | Consumed words remain consumed |
| Owned output | `law.sample_n(rng, n)` | Returns `Vec` | No output returned; generator remains advanced by consumed words |
| Caller-provided output | `law.sample_n_into(rng, policy, output, workspace)` | Writes `output` | Follows the two policies in `policy` |

Owned forms take neither policies nor workspace.
Quasi-random `points`, `sample_indices`, `latin_hypercube`, `poisson_disk`, and `BrownianBridgePlan::apply` are also owned forms; in-place array shuffling `shuffle` likewise takes neither policies nor workspace.
On failure, these leave the generator advanced by consumed words.
To restore the generator after failure, capture `SnapshotGenerator::snapshot` before calling or pass a rollback policy to a caller-output form.

Caller-output forms (`sample_n_into`, `shuffle_in_place`, `QuasiRng::points_into`) take `SamplingPolicy`, immediately after the generator when one is passed.
`SamplingPolicy` combines two independent policies, constructed as in `SamplingPolicy::rollback(OutputPolicy::Atomic)`.
Output policy `OutputPolicy::Atomic` publishes the whole output only on success; `Incremental` publishes completed samples (rows for vector values) in order.
State policy `Rollback` restores the generator on failure and requires `SnapshotGenerator`; `AdvanceOnError` retains consumption.
`SamplingPolicy::rollback` and `SamplingPolicy::advance_on_error` select these respectively.
There are no policy defaults; callers explicitly specify both.
Rejected proposals consume words too, so a successful batch produces the same sequence as individual `sample` calls with the same boundaries.
Empty batches neither capture snapshots nor consume words.

Vector laws (such as `MultivariateNormal`, `Dirichlet`, and `Multinomial`) provide `sample` and row-based `sample_n` and `sample_n_into`.
Vector and matrix laws, circular and directional laws, and generic samplers also provide `sample_indexed_into(root, output, workspace, cx)`, writing from sample-specific streams without advancing the root generator.
This form's results are independent of `ExecutionContext` execution order.

## Querying workspace and requirements

Caller-output forms take reusable `SamplingWorkspace`.
Determine its size as follows.

```text
let requirements = policy.workspace_requirements(SamplingRequest::scalars(n))?; // Requirements
workspace.try_reserve(&requirements)?;                                         // Reserve
workspace.check(&requirements)?;                                               // Sufficient or NeedsGrowth
let workspace = policy.workspace(SamplingRequest::rows(n, width))?;            // Both steps at once
```

`Atomic` temporarily stores the whole batch ($n \times$ the width in elements).
For width at least two, `Incremental` stores one row to avoid exposing incomplete rows; for scalars it stores nothing.
`SamplingRequirements` contains the output-type element count, binary64 auxiliary storage (`Dirichlet` computes in binary64 even for `f32` output), and a byte limit.
Policy requirements are unlimited; the law's `LawOptions::max_bytes` applies to retained capacity at runtime.
Owned `sample_n` likewise gives `ResourceLimit` before drawing when output bytes exceed the law's limit, or `SizeOverflow` if byte-count arithmetic overflows.
Batches grow insufficient workspace before generating samples.
With workspace reserved according to requirements, successful batches allocate no storage.

Workspace whose size is fixed during preparation is constructed only through `workspace()`.
`PoissonDisk`, joint-probability Plans, and adaptive-rejection samplers use this form.
The request for `BrownianBridgePlan` is `()`.
`latin_hypercube_into` grows workspace to output length itself, avoiding allocation from the second call onward when reused.
QMC transport adapters' `workspace()` prepares coordinate storage; temporary output grows according to `SamplingPolicy` requirements.
The finite-sample two-sided KS law checks `KolmogorovWorkspace` through `KolmogorovRequirements` for each point $x$ and uses workspace without growing it.

## Rejection and work limits

All laws stop sampling rejection loops and staged searches after 1,024 candidates, returning `ConvergenceFailure`.
This is an upper limit, ordinarily not reached at normal acceptance rates.
Counting, circular, directional, multivariate, matrix, and test-statistic laws, plus `Rice`, `IrwinHall`, and `Mixture`, count uniform words requested per sample (including nested sampling and failed requests) through `LawOptions::sample_word_budget`.
Angle laws (such as `VonMises`) count floating-point uniform requests instead of words; prepared count samplers (such as `BinomialSampler`) use the originating law's limits.
Deterministic searches within sampling and nested iterative special functions share `work_budget` and never start evaluations exceeding remaining work.
Random words use a separate per-sample limit.
Generic rejection also allows at most 1,024 candidates; its `UniversalSamplingOptions` settings limit density evaluations, floating-point random calls (`rng_calls`), envelope nodes, and bytes.

`LawOptions` collects accuracy and resource limits for laws involving numerical computation.

| Setting | Default | Meaning |
|---|---|---|
| `tolerance` | $\sqrt{\varepsilon}$ absolute and relative | Requested quadrature, series, and numerical-inversion accuracy. Relative component must lie in $[64\varepsilon, 0.1)$; violations give `InvalidInput` at construction |
| `work_budget` | 65,536 | Work per preparation, query, or moment computation (recurrence updates, integrand evaluations) |
| `sample_word_budget` | 65,536 | Words requested by one sample |
| `max_bytes` | 64 MiB | Limit applied separately to each law allocation: retained parameters, returned `Vec`, internal storage, and workspace capacity. Caller-provided output is excluded. Excess gives `ResourceLimit` |
| `execution_policy` | Sequential | Scheduling rows of `sample_indexed_into`. Each row uses its own stream, leaving results unchanged |

Errors here are estimates rather than certified bounds.
Computations reaching work, word, or candidate limits return no value and give `ConvergenceFailure`.

## Error classification

| Kind (`kind()`) | Main causes |
|---|---|
| `InvalidInput` | Out-of-range `LawOptions` tolerance, $k > n$ for `sample_indices`, zero-limit `uniform_index`, user generators returning out-of-range values, invalid state bytes (reasons `Malformed`, `UnsupportedConfiguration`, `Inconsistent`) |
| `NonFinite` | NaN or infinite coordinates or parameters |
| `DomainError` | Parameter-domain violations and probabilities outside $[0, 1]$ (reason `OutsideDomain`), nonexistent moments (`Undefined`) |
| `ConvergenceFailure` | 1,024-candidate limit, word or work limit, numerical-inversion nonconvergence |
| `NotImplemented` | $Q(1)$ for integer laws unbounded above, counts beyond exact integer arithmetic |
| `OutOfBounds` | Out-of-range forward or backward moves, reads outside `BoundedSubstream` |
| `ResourceLimit`, `AllocationFailure`, `SizeOverflow` | Byte limit, allocation failure, size-arithmetic overflow |
| `DimensionMismatch` | Output/workspace lengths mismatching the design or law (`latin_hypercube_into`, `PoissonDisk::generate_into`, QMC transports, vector-law `sample_n_into` and `sample_indexed_into`). Checked before randomness is used or state/output changes |
| `NumericalInstability` | Unrepresentable results ($\mu + \sigma z$ overflow; `Underflow` and `Overflow` for positive samples rounding to zero or out of range), breakdown of computed constants or matrices (`Breakdown`), variance accuracy unverifiable due to cancellation (`Cancellation`). Mathematical parameter violations remain `DomainError` |

Errors carry no caller identity.
Read classifications through `e.kind()` and arguments and reasons through `e.view()`.

## Summary

Index sampling, integer laws, and fast Ziggurat paths in `scioxide-random` use uniform words; floating-point uniforms used by inversion and related methods are constructed from one native word without including endpoint 1.
Engine integer and QMC sequences are reproduced from seeds and call sequences while algorithm and decoder-convention versions match; distribution sampling algorithms lie outside this guarantee.
Failed owned batches leave generators advanced; caller-output forms independently select output and state policies through `SamplingPolicy` and reserve workspace once from requirements for reuse.
Rejection stops after 1,024 candidates and law numerical computation at `LawOptions` limits; both report `ConvergenceFailure`.
