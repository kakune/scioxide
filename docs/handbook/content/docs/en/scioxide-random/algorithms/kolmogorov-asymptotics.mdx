For large sample size $n$, KS statistic $p$-values are often approximated using the limiting Kolmogorov law of $\sqrt{n}\,D_n$.
This page explains evaluation of that limiting law and measures differences from exact finite-sample values using distinct comparison settings.
Algorithms and evaluation regions for finite-sample laws are in [Test-statistic laws and the finite-sample KS distribution](../test-statistic-laws/).
It also covers workspace reuse for matrix methods under repeated queries and how KS tests in `scioxide-stats` choose exact or asymptotic values.

## The asymptotic Kolmogorov law

As $n \to \infty$, $\sqrt{n}\,D_n$ converges to the Kolmogorov distribution

$$
P(K \le x) = 1 - 2\sum_{j=1}^{\infty} (-1)^{j-1} e^{-2j^2x^2}
= \frac{\sqrt{2\pi}}{x} \sum_{j=1}^{\infty} e^{-(2j-1)^2\pi^2/(8x^2)}
$$


The two series represent the same function, related by a Jacobi theta-function transformation.
`Kolmogorov` directly computes the lower tail from the right series for $x < 0.82$ and the upper tail from the left alternating series for $x \ge 0.82$.
Both factor out the leading exponential so the sum starts at 1 and stop when a term falls below $1/100$ times the tolerance in relative magnitude.
The boundary 0.82 is where the two series require approximately equal numbers of terms.
Mean $\sqrt{\pi/2}\,\ln 2 \approx 0.8687$ and variance $\pi^2/12 - (\pi/2)\ln^2 2 \approx 0.0678$ are returned in closed form; samples are quantiles of open-interval uniforms.

## Size of asymptotic approximation errors

For finite $n$, approximating the tail of $D_n$ by $P(K > \sqrt{n}\,d)$ gives a leading error of order $1/\sqrt{n}$, decreasing slowly.
However, the apparent quality of the approximation can reverse with the comparison setting.

Holding $d$ fixed while increasing $n$ makes the tail probability itself smaller, and the asymptotic approximation's relative error increases deeper into the tail.
In the [cell comparing the exact two-sided KS tail with twice the one-sided tail and the asymptotic approximation](oxref:random-ks-tail-regions), $n = 20$ and $d = 0.3$ give exact tail 0.04307 versus asymptotic 0.05465, 26.9% above the exact value.
Relative error grows with $d$; at $d = 0.6$ the asymptotic approximation $1.11 \times 10^{-6}$ is 5.4 times the exact $2.05 \times 10^{-7}$.
At the same $d = 0.3$, relative errors are 14.3% for $n = 5$ and 47.7% for $n = 60$, increasing with $n$ when $d$ is fixed.

For testing, the meaningful error compares the same significance level.
Starting with the asymptotic critical value $c$ at level $\alpha$ ($P(K > c) = \alpha$), form $d = c/\sqrt{n}$ and compare the finite-sample tail probability; the discrepancy decreases proportionally to $1/\sqrt{n}$.
The next two sections show workspace reuse for this comparison and the computation itself.

## Tail evaluation with reusable workspaces

Trait queries (`sf` or `cdf`) allocate a workspace whenever the matrix method is needed.
For repeated evaluation of the same law or similar $d$, the caller retains the workspace.

- `workspace_requirements(x)` returns the matrix order needed for a query at $x$ and the law's `max_bytes` in `KolmogorovRequirements`.
  An `dimension()` of 0 means no matrix is used.
- `KolmogorovWorkspace::new()` creates an empty workspace without allocation; `try_reserve(&requirements)` grows it after checking the storage limit.
  `check(&requirements)` returns `Capacity::Sufficient` or `Capacity::NeedsGrowth` without allocating.
  `law.workspace(x)` is a shortcut combining these two operations.
- `evaluate_tail(x, upper, &mut workspace)` does not grow the workspace.
  It returns `DimensionMismatch` if capacity is insufficient, `ResourceLimit` if retained storage exceeds the limit, and `ConvergenceFailure` (iteration limit) if work is exhausted.

A matrix-method tail evaluation takes roughly one third of $m^3 \log_2 n$ evaluations (33,164 for $n = 80$ and $m = 25$ in the next cell, and 103,935 for $n = 160$ and $m = 35$); the default 65,536 may be insufficient once $m$ exceeds 25.
Quantiles and inverse-transform sampling repeat tail evaluations, requiring still larger limits.
Density queries use matrices of dual numbers and allocate on every call without accepting a workspace.

## Finite-sample tails at asymptotic critical values

The following cell forms $d = c/\sqrt{n}$ from the asymptotic critical value $c$ at level $\alpha$ (computed by `Kolmogorov::isf`) and computes finite-sample tails $P(D_n > d)$ using `evaluate_tail` for $n = 5$ through 320.
If the asymptotic approximation were exact, every $n$ would give tail probability $\alpha$.
The input is level $\alpha$ (dimensionless, 0.01 through 0.2).
A single `KolmogorovWorkspace` is reused across all $n$, growing with `try_reserve` to the order returned by `workspace_requirements`.
The table reports $n$, $d$, matrix order $m$ (0 means no matrix), tail probability, estimated absolute error, evaluations, ratio $P/\alpha$, and $\sqrt{n}\,(\alpha - P)$.
If the final column is approximately constant across $n$, the discrepancy decreases proportionally to $1/\sqrt{n}$.

```rust
//| id: random-ks-asymptotic-level
//| ref: random-ks-asymptotic-level
//| title: "Compute finite-sample two-sided KS tails at asymptotic critical values across n"
//| run: reactive
//| crates: [scioxide-core, scioxide-random]
//| inputs:
//|   level: {"type":"range","label":"Asymptotic level α [-]","description":"Constructs critical value c satisfying P(K > c) = α.","min":0.01,"max":0.2,"step":0.01,"value":0.05}
//| cases:
//|   - {"id":"strict-level","label":"α = 0.01","description":"The critical value is large; for n = 5 and 10, d exceeds 1/2 and twice the one-sided tail is used.","inputs":{"level":0.01}}
//|   - {"id":"loose-level","label":"α = 0.2","description":"The critical value is small; the matrix method is used even at n = 5.","inputs":{"level":0.2}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"levels","path":"/rows/0/2","equals":0}
//|       - {"artifact":"levels","path":"/rows/2/3","approx":{"value":0.03919,"rtol":0.001}}
//|       - {"artifact":"levels","path":"/rows/6/3","approx":{"value":0.04743,"rtol":0.001}}
//|       - {"artifact":"levels","path":"/rows/6/4","range":{"min":0,"max":1e-10}}
//|   - case: strict-level
//|     expect:
//|       - {"artifact":"levels","path":"/rows/0/2","equals":0}
//|       - {"artifact":"levels","path":"/rows/6/3","range":{"min":0.008,"max":0.01}}
//|   - case: loose-level
//|     expect:
//|       - {"artifact":"levels","path":"/rows/0/2","range":{"min":1,"max":20}}
//|       - {"artifact":"levels","path":"/rows/6/3","range":{"min":0.18,"max":0.2}}
use scioxide_core::{Budget, RealScalar};
use scioxide_random::{
    InverseSurvival, Kolmogorov, KolmogorovSmirnovTwoSided, KolmogorovWorkspace, LawOptions,
};

let sig4 = serde_json::json!({ "significantDigits": 4 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let fixed3 = serde_json::json!({ "fractionDigits": 3 });
// Matrix-method evaluations are roughly one third of m³ log₂ n and exceed the default 65,536, so increase the limit.
let work = Budget::try_from(1_usize << 22).map_err(|e| e.to_string())?;
let options = LawOptions::default().with_work_budget(work);
let limit = Kolmogorov::with_options(options).map_err(|e| e.to_string())?;
// Asymptotic critical value c: P(K > c) = α.
let critical = limit.isf(level).map_err(|e| e.to_string())?;
// Reuse one workspace across all n, growing only when the order increases.
let mut workspace = KolmogorovWorkspace::new();
let mut rows = Vec::new();
let mut points = Vec::new();
for n in [5_usize, 10, 20, 40, 80, 160, 320] {
    let law = KolmogorovSmirnovTwoSided::with_options(n, options).map_err(|e| e.to_string())?;
    let root_n = RealScalar::sqrt(n as f64);
    let d = critical / root_n;
    let requirements = law.workspace_requirements(d).map_err(|e| e.to_string())?;
    workspace
        .try_reserve(&requirements)
        .map_err(|e| e.to_string())?;
    let tail = law
        .evaluate_tail(d, true, &mut workspace)
        .map_err(|e| e.to_string())?;
    let p = RealScalar::exp(tail.log_probability);
    points.push([n as f64, p]);
    rows.push((
        n,
        d,
        requirements.dimension(),
        p,
        tail.absolute_error,
        tail.evaluations,
        p / level,
        root_n * (level - p),
    ));
}
emit_line_chart!(
    &vec![serde_json::json!({
        "name": "Finite-sample P(D_n > c/√n)",
        "points": points,
        "style": {"symbol": "circle", "lineType": "dotted"}
    })],
    options = &serde_json::json!({
        "xLabel": "Sample size n [count]",
        "yLabel": "Tail probability [-]",
        "xType": "log",
        "yMin": 0.0,
        "yMax": 0.22,
        "annotations": [{"kind": "line", "axis": "y", "value": level, "label": "Asymptotic level α"}]
    })
);
let columns = serde_json::json!([
    { "key": "0", "label": "Sample count n", "type": "integer" },
    { "key": "1", "label": "d = c/√n [-]", "type": "number", "format": sig4 },
    { "key": "2", "label": "Matrix order m", "type": "integer" },
    { "key": "3", "label": "P(D_n > d) [-]", "type": "number", "format": sig4 },
    { "key": "4", "label": "Estimated absolute error [-]", "type": "number", "format": sci2 },
    { "key": "5", "label": "Evaluations", "type": "integer" },
    { "key": "6", "label": "P/α [-]", "type": "number", "format": fixed3 },
    { "key": "7", "label": "√n (α − P) [-]", "type": "number", "format": fixed3 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "levels" })
);
```

Plot points give finite-sample tail probabilities; the horizontal line gives asymptotic level $\alpha$.
At default $\alpha = 0.05$, the tail probability of $d = c/\sqrt{n}$ approaches $\alpha$ from below, rising from 0.0270 at $n = 5$ through 0.0392 at $n = 20$ to 0.0474 at $n = 320$.
The ratios $P/\alpha$ are 0.54, 0.78, and 0.95; asymptotic critical values are conservative in small samples (the actual type I error probability is below $\alpha$).
$\sqrt{n}\,(\alpha - P)$ changes slowly from 0.051 to 0.046, indicating a discrepancy decreasing approximately in proportion to $1/\sqrt{n}$.
For $n = 5$, $d = 0.607 \ge 1/2$, so the order is 0 and twice the one-sided Smirnov sum gives the exact value.
For $n \ge 10$, matrix orders range from 9 to 49, with 320,130 evaluations at $n = 320$ and estimated absolute error at most $9.1 \times 10^{-12}$.

At $\alpha = 0.01$, $d$ exceeds 1/2 for $n = 5$ and 10, requiring no matrix; the ratio varies from 0.32 at $n = 5$ to 0.94 at $n = 320$.
At $\alpha = 0.2$, even $n = 5$ uses a matrix of order 5, with ratios from 0.71 to 0.96.
At every level, asymptotic $p$-values overestimate $p$-values for small samples.
As an independent comparison, exact rational computation of Durbin's matrix power $(n!/n^n)(H^n)_{kk}$ agrees with tails in the rows $n = 10$ through 320 at default $\alpha$ to relative difference at most $3 \times 10^{-12}$; actual errors are below the table's estimated absolute errors.

## KS tests in scioxide-stats

`scioxide-random` provides only laws that take statistic values and return probabilities; it neither computes statistics from data nor returns test conclusions.
`scioxide-stats` performs KS tests on data, using the laws above as follows.

- `ks_one_sample_test` is a one-sample KS test against a specified continuous CDF.
  Under `TestCalibration::Auto`, if $n^2$ is within the test's work limit, it uses `sf` of finite-sample `KolmogorovSmirnovTwoSided` (`KolmogorovSmirnovOneSided` for a one-sided alternative); otherwise it uses the limit `Kolmogorov` ($e^{-2nd^2}$ one-sided).
  If finite-sample evaluation reaches its work or storage limit, `Auto` also switches to the limiting distribution, while `TestCalibration::Exact` returns an error.
  Data with ties returns `InvalidInput`.
  The null assumes a continuous distribution with specified parameters, so use `goodness_of_fit_test_into` for parameters fitted from data or discrete distributions ([Distribution goodness-of-fit and variance homogeneity tests](oxref:stats-dist-tests-kolmogorov-smirnov)).
- `ks_two_sample_test` uses its own lattice-path counting for exact cases and `Kolmogorov` for asymptotic cases.

## Summary

The asymptotic Kolmogorov law switches between two series at $x = 0.82$, directly evaluating the smaller tail on each side.
Asymptotic $p$-value errors increase relatively with $n$ at fixed $d$, but decrease proportionally to $1/\sqrt{n}$ when compared at a fixed level, so establish the comparison setting first.
Asymptotic critical values are conservative for small samples; at $n = 20$ the actual type I error probability is about 0.78 times nominal.
For repeated queries, reserve `KolmogorovWorkspace` once and pass it to `evaluate_tail`, checking estimated absolute errors and evaluation counts in `TestStatisticResult`.
For matrix-method queries with order above 25, increase the work limit in `LawOptions` beyond its default.
