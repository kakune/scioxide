Independent uniform points often contain close pairs, and Latin hypercubes guarantee only axis-wise stratification.
Use Poisson disk sampling when the minimum interpoint distance itself is a design constraint, such as keeping sampling locations or image samples at least a specified distance apart.
This page explains Bridson's method in `scioxide-random`, its work limits and termination reasons, and how to inspect how densely the resulting point set is packed.

## Poisson disk sampling

A Poisson disk sample is a random point set inside box $B = [\mathbf{l}, \mathbf{u}] \subset \mathbb{R}^d$ with every pair at least radius $r$ apart.
A set is maximal if no further point can be placed anywhere.
The naive dart-throwing method draws uniform candidates and compares each with every existing point, rejecting it if too close.
As points accumulate, most candidates are rejected; near maximality, placing one point requires many candidates.

Bridson's (2007) method reduces this waste by drawing candidates near existing points.

1. Draw the first point uniformly in the box and add it to the active list.
2. Choose an active point $\mathbf{p}$ uniformly and draw at most $k$ candidates from annulus $r \le \|\mathbf{x} - \mathbf{p}\| < 2r$.
3. Accept a candidate inside the box and at least $r$ from every accepted point, adding it to the active list.
4. If all $k$ attempts fail, remove $\mathbf{p}$ from the active list and return to step 2.

Candidates are uniform with respect to annular volume.
Their direction is $\mathbf{z}/\|\mathbf{z}\|$, a normalized standard normal vector $\mathbf{z}$; normal rotational invariance makes it uniform on the sphere.
Radius $\rho$ has CDF $(\rho^d - r^d)/((2r)^d - r^d)$, so inverse-transform sampling from uniform $u$ gives $\rho = r\,(1 + u(2^d - 1))^{1/d}$.

Neighbor checks use a background grid with cell side $r/\sqrt{d}$.
The cell diagonal is $r$, so each cell holds at most one accepted point and needs only one point index.
Points at distance less than $r$ from a candidate can occur only in cells within $\pm r$ along each axis from its coordinates (expanded by one cell on each side for rounding).
The implementation compares this cell count with the accepted point count and scans the smaller set.
Expected cost for placing $N$ points is $O(kN)$.

`PoissonDisk::new(lower, upper, r, capacity)` prepares a design in a box of 1–6 dimensions with point limit `capacity` and checks background cell count $\prod_j \lceil (u_j - l_j)\sqrt{d}/r \rceil$.
`PoissonDisk::with_options(lower, upper, r, capacity, options)` changes work limits through `PoissonDiskOptions`.

| `PoissonDiskOptions` field | Default | Meaning |
|---|---|---|
| `candidates_per_point` | 30 | Candidate count $k$ tried per active point (positive) |
| `max_proposals` | $2^{20}$ | Total candidate limit (including the first point and out-of-box candidates) |
| `max_grid_cells` | $2^{20}$ | Background cell limit (positive) |
| `max_distance_checks` | $2^{24}$ | Neighbor-work limit |

Neighbor work counts each visited grid cell (including empty cells) and each compared point as one, so it exceeds the distance-evaluation count.
Construction gives `InvalidInput` for dimensions outside 1–6, differing `upper` lengths, $r$ not positive and finite, nonfinite bounds or $l_j \ge u_j$, zero `capacity` or $k$, or a grid exceeding `max_grid_cells`.

## Generation and workspaces

`generate(rng)` returns a row-major `Vec` of accepted points paired with report `PoissonDiskReport`, allocating output and workspace per call.
`generate_into(rng, state, out, work, cx)` accepts `PoissonDiskWorkspace` created by `design.workspace()` and writes accepted points to the leading rows of `out`.
The workspace holds `capacity` points, the active list, and background grid; repeated generation with the same workspace allocates no storage.
If output length (`output_elements()` $= \texttt{capacity} \times d$) or workspace size mismatches the design, it returns `DimensionMismatch` before changing state or output.
Points depend on one another, so the design is built in the workspace and copied to `out` only on success.
Rows after accepted points are left unwritten.

`cx` checks cancellation and deadlines before initial sampling and each candidate; before initial sampling this gives an error `ExecutionStopped`, while before a candidate it gives termination `Stopped`.
If `generate_into` ends with an error, output remains unchanged and the generator follows `state` (`AdvanceOnError` or `Rollback`).
On failure, `generate` leaves the generator advanced.
`poisson_disk(lower, upper, r, capacity, rng)` is a one-shot form using default settings for `generate` and returning only accepted points.
Exhausting active points before reaching `capacity` is success; stopping at a limit (`BudgetExhausted`) gives an error `ConvergenceFailure`.

`PoissonDiskReport` returns termination reason `termination()`, accepted count `points()`, candidate count `proposals()`, and neighbor work `distance_checks()`; the first `points()` output rows contain accepted points.
The four `PoissonDiskTermination` termination reasons are below; outcomes map `Complete` to satisfied and the rest to partial.

| Termination reason | Meaning |
|---|---|
| `Complete` | Accepted `capacity` points |
| `ActiveListExhausted` | No active points remain. This does not prove maximality (that no further point fits) |
| `BudgetExhausted` | Total candidate or neighbor-work limit reached. If `max_proposals` is 0, no points are placed |
| `Stopped` | `ExecutionContext` supplied to `generate_into` reported cancellation or a deadline before a candidate |

Every termination preserves minimum separation $r$ among accepted points; a design stopped by limits remains usable up to that point.

## Point-count bounds and maximality checks

Point count $N$ has lower and upper bounds determined by box volume.
Consider unit square $[0, 1]^2$.
Disks of radius $r/2$ centered at points are disjoint and fit inside a square of side $1 + r$, so every $r$-separated set satisfies $N \le 4(1+r)^2/(\pi r^2)$.
If the set is maximal, disks of radius $r$ cover the square (an uncovered point could be added), giving $N \ge 1/(\pi r^2)$.
Thus $N$ below the lower bound establishes that the set is not maximal.

Coverage is measured by the largest distance from any square point to its nearest sample point (the covering radius).
A maximal set has covering radius below $r$.
Taking the maximum nearest distance over grid points approximates the covering radius from below.

The following cell generates a Poisson disk sample on the unit square using `generate_into` and tabulates termination reason and report counts.
Inputs are radius $r$, candidate count $k$, point limit `capacity`, total candidate limit, and seed.
Independent checks are minimum distance computed in `geometric_discrepancy` divided by $r$, grid-based covering radius at spacing $1/128$ divided by $r$, and bounds on $N$.
The plot shows accepted points and the grid point giving the covering radius (the largest gap's center).

```rust
//| id: random-poisson-disk-termination
//| ref: random-poisson-disk-termination
//| title: "Check Poisson disk termination reasons and point-count bounds"
//| run: reactive
//| crates: [scioxide-core, scioxide-random]
//| inputs:
//|   radius: {"type":"range","label":"Radius r [-]","min":0.04,"max":0.2,"step":0.01,"value":0.08}
//|   candidates: {"type":"range","label":"Candidate count k [count]","description":"Candidates tried per active point. Bridson's default is 30.","min":1,"max":60,"step":1,"value":30}
//|   capacity: {"type":"range","label":"Point limit capacity [points]","min":20,"max":1000,"step":20,"value":1000}
//|   budget: {"type":"select","label":"Total candidate limit","options":["2²⁰ (default)","2,000","500"],"value":"2²⁰ (default)"}
//|   seed: {"type":"range","label":"Random seed [-]","min":1,"max":1000,"step":1,"value":7}
//| cases:
//|   - {"id":"few-candidates","label":"k = 3","description":"Trying few candidates exhausts active points early and leaves large gaps.","inputs":{"candidates":3}}
//|   - {"id":"small-capacity","label":"capacity = 40","description":"Reaching capacity stops with Complete.","inputs":{"capacity":40}}
//|   - {"id":"small-budget","label":"500 candidates","description":"Exhausting the total candidate count stops with BudgetExhausted.","inputs":{"budget":"500"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"report","path":"/rows/0/0","equals":"ActiveListExhausted"}
//|       - {"artifact":"report","path":"/rows/0/1","range":{"min":50,"max":232}}
//|       - {"artifact":"checks","path":"/rows/0/0","range":{"min":1}}
//|       - {"artifact":"checks","path":"/rows/0/1","range":{"min":1,"max":1.5}}
//|       - {"path":"/outputs/3/state","equals":"partial"}
//|   - case: few-candidates
//|     expect:
//|       - {"artifact":"report","path":"/rows/0/0","equals":"ActiveListExhausted"}
//|       - {"artifact":"checks","path":"/rows/0/0","range":{"min":1}}
//|       - {"artifact":"checks","path":"/rows/0/1","range":{"min":2}}
//|   - case: small-capacity
//|     expect:
//|       - {"artifact":"report","path":"/rows/0/0","equals":"Complete"}
//|       - {"artifact":"report","path":"/rows/0/1","range":{"min":40,"max":40}}
//|       - {"path":"/outputs/3/state","equals":"satisfied"}
//|   - case: small-budget
//|     expect:
//|       - {"artifact":"report","path":"/rows/0/0","equals":"BudgetExhausted"}
//|       - {"artifact":"report","path":"/rows/0/2","range":{"min":500,"max":500}}
use scioxide_core::{ExecutionContext, RealScalar};
use scioxide_random::{
    AdvanceOnError, GeometricDiscrepancy, PoissonDisk, PoissonDiskOptions, PoissonDiskTermination,
    SeedableRng, SplitMix64, geometric_discrepancy,
};

let fixed3 = serde_json::json!({ "fractionDigits": 3 });
let fixed1 = serde_json::json!({ "fractionDigits": 1 });
let max_proposals = match budget.as_str() {
    "2,000" => 2_000,
    "500" => 500,
    _ => 1 << 20,
};
let options = PoissonDiskOptions::default()
    .with_candidates_per_point(candidates.round() as usize)
    .with_max_proposals(max_proposals);
let design = PoissonDisk::with_options(
    &[0.0_f64; 2],
    &[1.0; 2],
    radius,
    capacity.round() as usize,
    options,
)
.map_err(|e| e.to_string())?;
// Create workspace and output from the design once and reuse them for generation with the same design.
let mut work = design.workspace().map_err(|e| e.to_string())?;
let mut out = vec![0.0_f64; design.output_elements()];
let mut rng = SplitMix64::from_seed(seed.round() as u64);
let report = design
    .generate_into(
        &mut rng,
        AdvanceOnError,
        &mut out,
        &mut work,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;
let n = report.points();
let points = &out[..2 * n];
// Independent check 1: minimum distance divided by r (at least 1 by definition).
let separation = if n >= 2 {
    let minimum = geometric_discrepancy(points, 2, GeometricDiscrepancy::MinimumDistance)
        .map_err(|e| e.to_string())?;
    Some(minimum / radius)
} else {
    None
};
// Independent check 2: largest nearest-sample distance from grid points at spacing 1/128 (covering-radius approximation).
let (mut hole, mut center) = (0.0_f64, [0.0_f64; 2]);
for a in 0..=128 {
    for b in 0..=128 {
        let (x, y) = (f64::from(a) / 128.0, f64::from(b) / 128.0);
        let nearest = points
            .chunks_exact(2)
            .map(|p| (p[0] - x) * (p[0] - x) + (p[1] - y) * (p[1] - y))
            .fold(f64::INFINITY, f64::min);
        if nearest > hole {
            (hole, center) = (nearest, [x, y]);
        }
    }
}
let hole = RealScalar::sqrt(hole);
// Independent check 3: covering lower bound 1/(πr²) and radius-r/2 packing upper bound 4(1 + r)²/(πr²).
let area = std::f64::consts::PI * radius * radius;
let (lower, upper) = (1.0 / area, 4.0 * (1.0 + radius) * (1.0 + radius) / area);
let accepted: Vec<[f64; 2]> = points.chunks_exact(2).map(|p| [p[0], p[1]]).collect();
emit_chart!(
    serde_json::json!({
        "kind": "scatter",
        "xLabel": "x [-]",
        "yLabel": "y [-]",
        "xMin": 0.0,
        "xMax": 1.0,
        "yMin": 0.0,
        "yMax": 1.0,
        "dataZoom": true,
        "tooltip": true,
        "series": [
            { "name": "Accepted points", "points": accepted },
            { "name": "Center of largest gap", "points": [center], "style": { "symbol": "diamond" } }
        ]
    }),
    metadata = serde_json::json!({ "id": "points" })
);
let report_columns = serde_json::json!([
    { "key": "0", "label": "Termination reason" },
    { "key": "1", "label": "Accepted points N [points]", "type": "integer" },
    { "key": "2", "label": "Candidate count [count]", "type": "integer" },
    { "key": "3", "label": "Neighbor work [operations]", "type": "integer" }
]);
let termination = report.termination();
emit_table_with_columns!(
    report_columns,
    vec![(
        format!("{termination:?}"),
        n,
        report.proposals(),
        report.distance_checks(),
    )],
    metadata = serde_json::json!({ "id": "report" })
);
let check_columns = serde_json::json!([
    { "key": "0", "label": "Minimum distance / r [-]", "type": "number", "format": fixed3, "nullText": "Fewer than 2 points" },
    { "key": "1", "label": "Covering radius / r [-]", "type": "number", "format": fixed3 },
    { "key": "2", "label": "If maximal, N ≥ [points]", "type": "number", "format": fixed1 },
    { "key": "3", "label": "Always N ≤ [points]", "type": "number", "format": fixed1 }
]);
emit_table_with_columns!(
    check_columns,
    vec![(separation, hole / radius, lower, upper)],
    metadata = serde_json::json!({ "id": "checks" })
);
let outcome = if termination == PoissonDiskTermination::Complete {
    Outcome::satisfied("Accepted capacity points")
} else {
    Outcome::partial("Generation stopped before reaching capacity")
        .explanation("Accepted points are at least r apart. Check maximality through the covering radius.")
};
emit_outcome!(
    outcome
        .status(format!("{termination:?}"))
        .diagnostic("Accepted points", n as f64, None)
        .diagnostic("Candidate count", report.proposals() as f64, None)
        .diagnostic("Covering radius / r", hole / radius, None)
);
```

With the defaults ($r = 0.08$, $k = 30$, `capacity` 1,000, seed 7), active points are exhausted after 99 accepted points, stopping with `ActiveListExhausted`.
There are 3,578 candidates and 50,221 neighbor-work operations, with minimum distance 1.001 times $r$.
The 99 points lie between upper bound 232.0 and maximal-set lower bound 49.7.
However, the grid covering radius is 1.187 times $r$, so another point fits at the diamond marker ($x = 0$, $y = 0.859$).
Large gaps tend to remain near box edges and corners.
Near an edge, part of the annulus lies outside the box and those candidates are rejected, making narrow empty regions along the edge difficult to reach.
These values confirm that `ActiveListExhausted` does not prove maximality.

Setting $k = 3$ places only 60 points with 278 candidates and expands the covering radius to 3.03 times $r$.
Setting `capacity` to 40 reaches 40 points with 486 candidates and gives `Complete` (satisfied); setting total candidates to 500 gives `BudgetExhausted` after 40 points.
Both terminations retain minimum separation at least $r$, and placed points remain usable.
`scioxide-random` provides no postprocessing to fill gaps; increase $k$ or measure the covering radius and add points on the caller's side when smaller gaps are needed.

## Summary

Poisson disk sampling enforces minimum distance $r$; Bridson's method uses a background grid and annular candidates to place $N$ points with expected $O(kN)$ work.
Total candidates and neighbor work in `PoissonDiskOptions` bound generation work; exhaustion returns accepted points so far with `BudgetExhausted`.
Only `Complete` establishes that `capacity` was reached; `ActiveListExhausted` does not establish maximality, so check density using the covering radius or point-count lower bound.
For repeated generation with one design, create `workspace()` once and pass it to `generate_into`; use `poisson_disk` for one-shot generation.
