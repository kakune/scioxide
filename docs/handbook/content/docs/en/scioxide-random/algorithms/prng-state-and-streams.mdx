A pseudorandom number generator (PRNG) advances a finite state through a deterministic map and extracts integers from that state.
The same generator, initial state, and sequence of calls produce bit-for-bit identical integer sequences.
This page explains the recurrences, periods, and output functions of generators in `scioxide-random` to support generator selection.
Every generator is intended for statistical simulation and lacks the unpredictability required for cryptography.

Converting generator integers (native words) to words uniform in every bit is covered in [Native and uniform words](../native-and-uniform-words/), seed and state storage in [Seeds, state storage, and state after failure](../seeding-and-state/), and parallel streams in [Stream advancement, jumps, and splits](../advance-jump-split/).

## Finite-state generators and periods

With state space $\mathcal{S}$, transition $T : \mathcal{S} \to \mathcal{S}$, and output $G : \mathcal{S} \to \mathcal{W}$, a generator follows

$$
s_{n+1} = T(s_n), \qquad w_n = G(s_n)
$$

to produce word $w_n$.
Since $\mathcal{S}$ is finite, some $\mu \ge 0$ and $\rho \ge 1$ satisfy $s_{n+\rho} = s_n$ for $n \ge \mu$.
The smallest such $\rho$ is called the period.
If $T$ is bijective, $\mu = 0$ and the state space partitions into disjoint cycles.

A long period is only a necessary condition.
Whether tuples of successive words are uniformly distributed in multiple dimensions depends separately on the recurrence structure and output function.
The lattice structure of linear congruential methods discussed later is a representative example.

## Generator families

`scioxide-random` exposes 17 generators.
Table tags are discriminants of enum `GeneratorAlgorithm`, also identifying algorithms in serialized state bytes.
Native words are the reference-implementation integers returned by `next_u32` and `next_u64`.

| Generator | Tag | State | Transition and output | Period | Native word | Advancement, jumps, and splits |
|---|---|---|---|---|---|---|
| `SplitMix64` | 1 | 64 bits | $s \leftarrow s + \gamma \bmod 2^{64}$, bijective mixing with two xorshift/multiplication pairs followed by another xorshift | $2^{64}$ | 64 bits | `SkipAhead` ($O(1)$) |
| `Xoshiro256StarStar` | 2 | $4 \times 64$ bits | Linear transition over $\mathbb{F}_2$, output function `**` | $2^{256} - 1$ | 64 bits | `JumpableRng` ($2^{128}$, $2^{192}$ transitions) |
| `Xoshiro128StarStar` | 3 | $4 \times 32$ bits | Same as above | $2^{128} - 1$ | 32 bits | `JumpableRng` ($2^{64}$, $2^{96}$ transitions) |
| `Pcg64` | 4 | 128 bits + increment | Linear congruential modulo $2^{128}$, XSL-RR output function | $2^{128}$ per stream | 64 bits | `SkipAhead` ($O(\log k)$), `SplittableRng` |
| `Lcg64` | 5 | 64 bits | $s \leftarrow a s + c \bmod 2^{64}$, output is the updated state | $2^{64}$ | 64 bits | `SkipAhead` ($O(\log k)$) |
| `Mrg32k3a` | 6 | $2 \times 3$ words | Difference of two order-3 multiple recurrences | About $2^{191}$ | From $1$ through $2^{32} - 209$ | `SkipAhead` ($O(\log k)$), `SplittableRng` |
| `Mt19937` | 7 | 624 words | Mersenne Twister (tempering mixes output) | $2^{19937} - 1$ | 32 bits | None |
| `Ranlux` | 8 | $24 \times 24$ bits + borrow | $x_n = x_{n-10} - x_{n-24} - c_{n-1} \bmod 2^{24}$ and decimation | About $10^{171}$ | 24 bits | None |
| `Ranlxs`, `Ranlxd` | 9, 10 | $12 \times 48$ bits + borrow | $x_n = x_{n-5} - x_{n-12} - c_{n-1} \bmod 2^{48}$ and decimation | About $10^{171}$ | 24 bits, 48 bits | None |
| `Taus2`, `Taus113` | 11, 12 | 3 words, 4 words | Combined Tausworthe generators (exclusive OR) | About $2^{88}$, about $2^{113}$ | 32 bits | None |
| `Gfsr4` | 13 | Ring of 9,689 words | Four-tap GFSR (lags 471, 1586, 6988, 9689) | $2^{9689} - 1$ | 32 bits | None |
| `Mrg`, `Cmrg` | 14, 15 | 5 words, 6 words | `Mrg`: order-5 multiple recurrence modulo $2^{31} - 1$; `Cmrg`: combined order-3 multiple recurrences modulo $2^{31} - 1$ and $2\,145\,483\,479$ | About $2^{155}$, about $2^{185}$ | Residues below $2^{31} - 1$ | None |
| `Philox4x64`, `Threefry4x64` | 16, 17 | Key and counter | 10-round Philox, 20-round Threefry | $2^{66}$ words per stream | 64 bits | `SkipAhead`, `JumpableRng` ($2^{32}$, $2^{48}$ words), `SplittableRng`. All $O(1)$ |

`GeneratorAlgorithm` fixes algorithm names to numeric values, with 17 values from `SplitMix64 = 1` through `Threefry4x64 = 17`.
Read this value through `algorithm()` of `StreamIdentity` returned by `stream_identity()`.
Tags form part of the state-byte format, allowing the algorithm of saved state to be identified later.

All 17 generators implement `BitGenerator`, `SeedableRng`, `SerializableState`, and `SnapshotGenerator` for in-memory snapshots.
Only generators listed in the table's final column support advancement, jumps, or splits; classical generators from `Mt19937` through `Cmrg` do not.
The crate documentation recommends `Xoshiro256StarStar` for a single stream, `Pcg64` or `Philox4x64` for numbered streams, and `Mt19937` for reproducing published streams.

The input is the seed.
The table shows tags read from `stream_identity()`, state-byte length `STATE_BYTES`, bit length of the maximum over 4,096 `next_u32` calls, and the position advance (transition count) of one `next_u64` call.
The maximum's bit length is a lower bound on native-word width; 24-bit native words never exceed 24.

fn describe<R>(name: &str, seed: u64) -> Result<Row, String>
where
    R: SeedableRng + BitGenerator + SerializableState,
{
    let mut rng = R::from_seed(seed);
    let tag = rng
        .stream_identity()
        .map(|identity| identity.algorithm() as u8)
        .ok_or("Missing identity")?;
    let mut maximum = 0_u32;
    for _ in 0..4096 {

    // Read native words consumed by next_u64 from the difference between positions before and after the call.

    let after = rng.position().ok_or("Position is untracked")?;
    let used = u64::try_from(after - before).map_err(|e| e.to_string())?;
    let bits = u32::BITS - maximum.leading_zeros();
    Ok((name.to_string(), tag, R::STATE_BYTES, bits, used))
}

Tags run from 1 through 17 in table order, independently of seed.
Maximum bit lengths are 24 for `Ranlux` and `Ranlxs`, and 31 for `Mrg` and `Cmrg`; for these generators, the highest bit of `next_u32` is always 0.
The value 32 for `Ranlxd` results from `next_u32` returning the high 32 bits of a 48-bit native word.
`next_u64` advances once for generators with 64-bit native words and for `Ranlxd`, and twice for generators with native words of 32 bits or fewer.
For the latter, `next_u64` simply concatenates two native words from low to high, so generators such as `Ranlux` do not give 64 bits uniform in every bit.
`STATE_BYTES` ranges from 52 bytes for `SplitMix64` and `Lcg64` to 77,556 bytes for `Gfsr4`, which keeps root and current copies of a 9,690-word ring and index.

### RANLUX luxury levels

`Ranlux`, `Ranlxs`, and `Ranlxd` are Lüscher subtract-with-borrow generators.
Borrow $c_n$ is 1 when subtraction falls below 0 and otherwise 0.
The undecimated recurrence has long-range correlations between successive values.
The luxury level determines how many recurrence values are discarded rather than output.
Discarding more values weakens correlations and proportionally increases computation per output.

First-generation `Ranlux` outputs the first 24 values in each block of $p$ recurrence steps and discards the remaining $p - 24$.
Second-generation `Ranlxs` and `Ranlxd` have registers of twelve 48-bit words, advance the recurrence $p$ times per refill, and use the final 12 words for output.
`Ranlxs` splits each 48-bit word into two 24-bit outputs from low to high; `Ranlxd` outputs the 48-bit word directly.

| Generator | Enum | Level and $p$ | `from_seed` level | Recurrence updates per output |
|---|---|---|---|---|
| `Ranlux` | `RanluxLuxury` | `Level0`〜`Level4`：24, 48, 97, 223, 389 | `Level3`（$p = 223$） | $p/24$ |
| `Ranlxs` | `RanlxsLuxury` | `Level0`〜`Level2`：109, 202, 397 | `Level1`（$p = 202$） | $p/24$ |
| `Ranlxd` | `RanlxdLuxury` | `Level1`〜`Level2`：202, 397 | `Level1`（$p = 202$） | $p/12$ |

At `from_seed` levels, `Ranlux` uses $223/24 \approx 9.3$ updates per output, `Ranlxs` uses $202/24 \approx 8.4$, and `Ranlxd` uses $202/12 \approx 16.8$.
Select the level through `with_luxury(seed, level)` or construct it from a number with `TryFrom<u8>`.
Out-of-range levels (such as 0 for `RanlxdLuxury`) give `InvalidInput` (reason `OutOfRange`).
Discarded values do not count toward position (`position()`), so position measures output count independently of level.
The level is stored as part of root state and preserved by state-byte restoration.

## Linear congruential methods and lattice structure

A linear congruential generator (LCG) is $s_{n+1} = (a s_n + c) \bmod m$.
The Hull–Dobell theorem gives period $m$ when the following three conditions hold.

- $c$ and $m$ are relatively prime.
- $a \equiv 1 \pmod p$ for every prime factor $p$ of $m$.
- If $4 \mid m$, then $a \equiv 1 \pmod 4$.

`Lcg64` uses $m = 2^{64}$, $a = 6\,364\,136\,223\,846\,793\,005$, and $c = 1\,442\,695\,040\,888\,963\,407$ (Knuth's constants), satisfying these conditions.

Even with maximal period, LCG output retains two structures.
The first is lattice structure.
Points $(u_n, \dots, u_{n+d-1})$ formed by mapping $d$ consecutive outputs to $[0, 1)$ lie on at most $(d!\, m)^{1/d}$ parallel hyperplanes (Marsaglia's theorem).
For $m = 2^{32}$ and $d = 3$, this bound is about 2,953 hyperplanes.

The second is the short period of low bits.
For $m = 2^{64}$, $s_n \bmod 2^k$ is itself an LCG modulo $2^k$, so the low $k$ state bits have period only $2^k$.
Therefore `next_u32` of `Lcg64` returns the high 32 state bits rather than the low bits.
When using output directly in multidimensional computations, choose a generator such as `Pcg64` whose output function mixes state.

The following cell generates $N$ words of `next_u64` from each of `Lcg64` and `Pcg64` and checks periodicity in the low $k$ bits ($k = 1, \dots, 12$).
Inputs are seed and word count $N$ (256–8,192).
The period is the smallest $p$ at most $N/2$ satisfying $w_{n+p} \equiv w_n \pmod{2^k}$ throughout the sequence, so periods $2^k > N/2$ cannot be found.
The theoretical value $2^k$ is calculated by hand from the argument above as an independent check.

```rust
//| id: random-lcg-low-bits
//| ref: random-lcg-low-bits
//| title: "Compare low-k-bit periods of Lcg64 and Pcg64 output"
//| run: reactive
//| crates: [scioxide-random]
//| inputs:
//|   seed: {"type":"range","label":"Random seed [-]","min":1,"max":1000,"step":1,"value":42}
//|   words: {"type":"range","label":"Word count N [words]","description":"Search only for periods at most N/2.","min":256,"max":8192,"step":256,"value":1024}
//| cases:
//|   - {"id":"long-run","label":"N = 8192","description":"Increasing word count verifies periods 2^k through k = 12.","inputs":{"words":8192}}
//|   - {"id":"short-run","label":"N = 256, seed 7","description":"With few words, periods for k = 8 and higher exceed the search range.","inputs":{"seed":7,"words":256}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"periods","path":"/rows/0/1","equals":2}
//|       - {"artifact":"periods","path":"/rows/8/1","equals":512}
//|       - {"artifact":"periods","path":"/rows/9/1","equals":null}
//|       - {"artifact":"periods","path":"/rows/0/3","equals":null}
//|       - {"artifact":"periods","path":"/rows/11/3","equals":null}
//|   - case: long-run
//|     expect:
//|       - {"artifact":"periods","path":"/rows/11/1","equals":4096}
//|       - {"artifact":"periods","path":"/rows/0/3","equals":null}
//|   - case: short-run
//|     expect:
//|       - {"artifact":"periods","path":"/rows/6/1","equals":128}
//|       - {"artifact":"periods","path":"/rows/7/1","equals":null}
use scioxide_random::{BitGenerator, Lcg64, Pcg64, SeedableRng};

// Find the smallest period p of the low-k-bit sequence in 1 ≤ p ≤ N/2.
fn low_bit_period(words: &[u64], k: u32) -> Option<u64> {
    let mask = (1_u64 << k) - 1;
    (1..=words.len() / 2)
        .find(|&p| {
            words
                .iter()
                .zip(&words[p..])
                .all(|(a, b)| (a ^ b) & mask == 0)
        })
        .map(|p| p as u64)
}

fn draw<R: BitGenerator>(mut rng: R, n: usize) -> Result<Vec<u64>, String> {
    (0..n)
        .map(|_| rng.next_u64().map_err(|e| e.to_string()))
        .collect()
}

let n = words.round() as usize;
let seed = seed.round() as u64;
let lcg = draw(Lcg64::from_seed(seed), n)?;
let pcg = draw(Pcg64::from_seed(seed), n)?;
// (k, Lcg64 period, theoretical 2^k, Pcg64 period)
let rows: Vec<(u32, Option<u64>, u64, Option<u64>)> = (1..=12)
    .map(|k| {
        let lcg_period = low_bit_period(&lcg, k);
        let pcg_period = low_bit_period(&pcg, k);
        (k, lcg_period, 1_u64 << k, pcg_period)
    })
    .collect();
let columns = serde_json::json!([
    { "key": "0", "label": "Low bit count k", "type": "integer" },
    { "key": "1", "label": "Lcg64 period [words]", "type": "integer", "nullText": "None at or below N/2" },
    { "key": "2", "label": "Theoretical 2^k [words]", "type": "integer" },
    { "key": "3", "label": "Pcg64 period [words]", "type": "integer", "nullText": "None at or below N/2" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "periods" })
);
```

With the defaults (seed 42, $N = 1\,024$), periods of `Lcg64` agree with $2^k$ from $k = 1$ through $9$; at $k \ge 10$, period $2^k$ exceeds search range $N/2 = 512$ and is not found.
Setting $N = 8\,192$ verifies through the $k = 12$ period of 4,096.
For `Pcg64`, no period at most $N/2$ is found for any $k$.
This is because XSL-RR mixes high bits into low bits, although the state of `Pcg64` itself advances with the same recurrence type as `Lcg64`.

## PCG and xoshiro output functions

`Pcg64` advances state with an LCG modulo $2^{128}$ and compresses it to 64 bits using XSL-RR (xorshift low, random rotation).

$$
w_n = \operatorname{rotr}_{64}\!\left( \mathrm{hi}_{64}(s_n) \oplus \mathrm{lo}_{64}(s_n),\ \left\lfloor s_n / 2^{122} \right\rfloor \right)
$$

Here $\mathrm{hi}_{64}$ and $\mathrm{lo}_{64}$ are the high and low 64 bits of the 128-bit state; $\operatorname{rotr}_{64}(x, r)$ is a 64-bit right rotation.
The rotation amount is determined by the highest 6 state bits; exclusive OR of upper and lower halves mixes the LCG's weak low bits with high bits.
`Pcg64` advances state once before producing output, so $s_n$ is the state after $n$ transitions.
`next_u32` returns the low 32 bits of the 64-bit output.
Every odd increment $c$ gives period $2^{128}$, so changing increments gives different streams.
Stream selection using this property is explained in [Stream advancement, jumps, and splits](oxref:random-prng-advance-jump-split).

The transition of `Xoshiro256StarStar` applies assignments to state $(s_0, s_1, s_2, s_3)$ in the following order.

$$
t = s_1 \ll 17,\quad s_2 \mathrel{\oplus}= s_0,\quad s_3 \mathrel{\oplus}= s_1,\quad s_1 \mathrel{\oplus}= s_2,\quad s_0 \mathrel{\oplus}= s_3,\quad s_2 \mathrel{\oplus}= t,\quad s_3 \leftarrow \operatorname{rotl}_{64}(s_3, 45)
$$

Output is $\operatorname{rotl}_{64}(5 s_1, 7) \times 9$ from the state before the update (products modulo $2^{64}$).
`Xoshiro128StarStar` uses the same transition and output forms with 32-bit words, differing only in transition constants (left shift 9, rotation 11).
The transition is a linear map $M$ over $\mathbb{F}_2^{256}$; the all-zero state is a fixed point.
Since the characteristic polynomial of $M$ is primitive, all $2^{256} - 1$ nonzero states form one cycle, giving period $2^{256} - 1$.
Words from a linear transition exhibit regularity in tests such as linear complexity, so multiplication in `**` makes output nonlinear (Blackman–Vigna 2021).

## Summary

Choose generators by output function, native-word width, and advancement, jump, and split capabilities as well as period.
Following the crate documentation, choose `Xoshiro256StarStar` for a single stream, `Pcg64` or `Philox4x64` for numbered parallel streams, and `Mt19937` for reproducing published streams.
The low $k$ output bits of `Lcg64` have period only $2^k$, so use a generator with an output function for computations consuming output directly.
With the `Ranlux` family, luxury levels trade weaker correlation for greater per-output computation (8.4–16.8 updates at `from_seed` levels).
Native words of `Ranlux`, `Ranlxs`, `Mrg`, and `Cmrg` have fewer than 32 bits, so do not assume uniformity of their highest bits.
