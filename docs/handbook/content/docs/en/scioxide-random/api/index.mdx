`scioxide-random` exposes pseudorandom generators and stream partitioning, probability laws with capability-specific traits, law composition and generic samplers, index and permutation sampling, quasi-random sequences, designs such as Latin hypercubes, and Brownian bridges.
This guide identifies entry points by purpose and organizes all 260 public items in purpose-grouped tables.
Item-name links point to the version 0.1.0 API reference on docs.rs.

## Type relationships

- **Generators**: `BitGenerator` returns native and uniform words; every built-in generator also implements `Rng` (`f32` and `f64`), converting native words to floating-point values in $[0, 1)$.
  Sampling for `Distribution` and `WeightedSampler` takes `Rng`; sampling for `CountDistribution`, vector and matrix laws, and index sampling such as `uniform_index`, `shuffle`, and `sample_indices` take `BitGenerator`.
- **Streams**: `SkipAhead`, `JumpableRng`, and `SplittableRng` provide advancement and partitioning; `BoundedSubstream` and `StreamPartitioner` construct bounded streams.
  Storage uses separate `SerializableState` (bytes) and `SnapshotGenerator` (in-memory) capabilities.
- **Laws**: capabilities are independent traits such as `Distribution`, `CountDistribution`, `Density`, `Cdf`, `Survival`, `Quantile`, and `Mean`; laws implement only supported capabilities.
  Laws involving numerical computation use default `LawOptions` with `new(parameters…)` and accept settings through `with_options(parameters…, options)`.
- **Batch generation**: owned forms such as `sample_n` take no policies.
  Caller-output forms such as `sample_n_into` take `SamplingPolicy`, combining output policy `OutputPolicy` with state policy `Rollback` or `AdvanceOnError`; obtain `SamplingWorkspace` requirements `SamplingRequirements` from `SamplingRequest`.
- **Plans**: `QmcPlan`, `QmcReplicatePlan`, `BrownianBridgePlan`, `MultivariateProbabilityPlan`, and design `PoissonDisk` are immutable and `Send + Sync + Clone`.
  Callers own cursors (`QmcSequence`) and workspace.

## Minimal example: three forms and state policies

Generate samples in three forms: individual `sample`, owned-output `sample_n`, and caller-output `sample_n_into` ([Batch sampling and state handling](oxref:random-algorithms-batches-and-state)).
The next cell uses a generator whose readable word count is limited by `BoundedSubstream`, repeatedly generating batches `sample_n_into` of $\mathrm{Uniform}(1, 2)$ until words run out.
Inputs are available words, samples per batch, and random seed; `SplitMix64` uses one word per sample.
For each of four output/state-policy combinations, the first table shows successful batch count, failure kind, elements changed in the failed batch, final position, and workspace element count determined by `SamplingPolicy::workspace_requirements`.
The last row of that table requests twice a batch's sample count from owned `sample_n`.
The second table independently checks individual `sample` values against $1 + u$ from the first word $w$ under the same seed ($u$ is $w$ mapped to $[0, 1)$ with `decode_u64`).

```rust
//|       - {"artifact":"batch-forms","path":"/rows/0/1","equals":4}
//|       - {"artifact":"batch-forms","path":"/rows/2/3","equals":0}

//|       - {"artifact":"batch-forms","path":"/rows/3/4","equals":12}
//|       - {"artifact":"batch-forms","path":"/rows/4/1","equals":1}
//|       - {"artifact":"batch-forms","path":"/rows/4/4","equals":6}
//|   - case: batch-exceeds
//|     expect:
//|       - {"artifact":"batch-forms","path":"/rows/0/1","equals":0}
//|       - {"artifact":"batch-forms","path":"/rows/0/3","equals":0}

//|       - {"artifact":"single-draw","path":"/rows/0/3","range":{"min":0,"max":1e-15}}
use scioxide_core::NumericScalar;
use scioxide_random::{
    BitGenerator, BoundedSubstream, Distribution, OutputPolicy, SamplingPolicy, SamplingRequest,
    SeedableRng, SplitMix64, StatePolicy, Uniform, decode_u64,
};

type Source = BoundedSubstream<SplitMix64>;
// (form and policies, successful batches, failure kind, changed elements in failed batch, final position, workspace elements)
type Row = (
    String,
    usize,
    Option<String>,
    Option<usize>,
    Option<u64>,
    Option<usize>,
);

// Construct a generator limited to available readable words.
fn bounded(seed: u64, available: u64) -> Result<Source, String> {
    BoundedSubstream::for_chunk(&SplitMix64::from_seed(seed), 0, available)
        .map_err(|e| e.to_string())
}

// The bounded-stream position is at most available and fits in u64.
fn position(rng: &Source) -> Result<Option<u64>, String> {
    rng.position()
        .map(u64::try_from)
        .transpose()
        .map_err(|e| e.to_string())
}

// Repeat sample_n_into until words run out, then inspect output and position from the failed batch.
fn run<P: StatePolicy<Source>>(
    name: &str,
    policy: SamplingPolicy<P>,
    seed: u64,
    available: u64,
    n: usize,
) -> Result<Row, String> {
    let law = Uniform::new(1.0_f64, 2.0).map_err(|e| e.to_string())?;
    let mut rng = bounded(seed, available)?;
    let request = SamplingRequest::scalars(n);
    let staged = policy
        .workspace_requirements(request)
        .map_err(|e| e.to_string())?
        .elements();
    let mut workspace = policy.workspace(request).map_err(|e| e.to_string())?;
    let mut output = vec![0.0_f64; n];
    let mut successes = 0;
    loop {
        let before = output.clone();
        match law.sample_n_into(&mut rng, policy, &mut output, &mut workspace) {
            Ok(()) => successes += 1,
            Err(error) => {
                let written = output.iter().zip(&before).filter(|(a, b)| a != b).count();
                return Ok((
                    name.to_string(),
                    successes,
                    Some(format!("{:?}", error.kind())),
                    Some(written),
                    position(&rng)?,
                    Some(staged),
                ));
            }
        }
    }
}

// Call owned sample_n once and inspect success and final position. It takes no policies.
fn owned(name: &str, seed: u64, available: u64, n: usize) -> Result<Row, String> {
    let law = Uniform::new(1.0_f64, 2.0).map_err(|e| e.to_string())?;
    let mut rng = bounded(seed, available)?;
    let (successes, kind) = match law.sample_n(&mut rng, n) {
        Ok(_) => (1, None),
        Err(error) => (0, Some(format!("{:?}", error.kind()))),
    };
    Ok((
        name.to_string(),
        successes,
        kind,
        None,
        position(&rng)?,
        None,
    ))
}

let (seed, available, n) = (seed as u64, available as u64, batch as usize);
let mut rows = vec![
    run(
        "sample_n_into: Atomic + Rollback",
        SamplingPolicy::rollback(OutputPolicy::Atomic),
        seed,
        available,
        n,
    )?,
    run(
        "sample_n_into: Atomic + AdvanceOnError",

    )?,
    run(
        "sample_n_into: Incremental + Rollback",

        seed,
        available,
        n,
    )?,
    run(
        "sample_n_into: Incremental + AdvanceOnError",
        SamplingPolicy::advance_on_error(OutputPolicy::Incremental),
        seed,
        available,
        n,
    )?,
];
// Owned sample_n: request twice the batch sample count at once. Returns a Vec only on success.
rows.push(owned("sample_n (no policies)", seed, available, 2 * n)?);
let columns = serde_json::json!([
    { "key": "0", "label": "Form and policies" },
    { "key": "1", "label": "Successful batches [count]", "type": "integer" },
    { "key": "2", "label": "Failure kind", "nullText": "No failure" },
    { "key": "3", "label": "Elements changed in failed batch [count]", "type": "integer", "nullText": "—" },
    { "key": "4", "label": "Final position [words]", "type": "integer" },

// Independent check of individual sample against 1 + u from the first word under the same seed.
let law = Uniform::new(1.0_f64, 2.0).map_err(|e| e.to_string())?;
let x = law
    .sample(&mut SplitMix64::from_seed(seed))
    .map_err(|e| e.to_string())?;
let word = SplitMix64::from_seed(seed)
    .next_u64()
    .map_err(|e| e.to_string())?;
let reference = 1.0 + decode_u64::<f64>(word);
let digits = serde_json::json!({ "significantDigits": 17 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "Seed", "type": "integer" },
    { "key": "1", "label": "sample value [-]", "type": "number", "format": digits },
    { "key": "2", "label": "Independent check 1 + u [-]", "type": "number", "format": digits },
    { "key": "3", "label": "Absolute difference [-]", "type": "number", "format": sci3 }

    metadata = serde_json::json!({ "id": "single-draw" })

```

With default inputs (6 words, batches of 4, seed 42), every combination succeeds on the first batch and fails with `OutOfBounds` after producing two samples in the second.
`Atomic` changes none of the failed batch's output; `Incremental` publishes the two completed samples.
`Rollback` restores position 4 at the second batch's start; `AdvanceOnError` retains the six consumed words.
Workspace contains four elements for the entire batch with `Atomic` and zero elements for scalar `Incremental`.
Requesting eight samples through owned `sample_n` fails with only six words, returning no values and leaving the generator at position six.
Owned forms have no state policy; to restore the generator on failure, pass `SamplingPolicy::rollback` to `sample_n_into`.
The `sample` value 1.7415648787718232 equals independent check $1 + u$ with zero difference.

Nondefault inputs change boundary behavior.
Reading 12 words in batches of three succeeds four times and fails on the fifth before producing any sample, so even `Incremental` changes zero elements.
The six samples from `sample_n` then fit within 12 words and succeed, leaving final position six.
Requesting eight samples from four words fails on the first batch; `Incremental` publishes four completed samples, and `Rollback` restores position zero.

## Block functions and generator word order

Counter-based generators produce words through pure functions `philox4x64_block` and `threefry4x64_block` mapping a key and counter to four words.
Word $n$ of a stream is word $n \bmod 4$ of the block for counter `[⌊n/4⌋, tree_path, stream, subsequence]`.
The root stream starts at counter `[block, tree_path, stream, subsequence]` = `[0, 1, 0, 0]` (its tree path contains only sentinel 1).
The next cell takes the low key word; Philox uses key `[key_low, 17]` and Threefry key `[key_low, 17, 0, 0]`.
It compares the four words in this counter's block with the first four words from a generator constructed through `from_key` at matching positions and counts equal words.
After returning to the start with `seek(0)`, it also counts reread words matching the first four.
The first-word columns map each 64-bit word with `decode_u64` to value $u$ in $[0, 1)$.

```rust
//| id: random-api-counter-replay
//| ref: random-api-counter-replay
//| title: "Check counter-based block functions and word order"
//| run: reactive
//| crates: [scioxide-random]
//| inputs:
//|   key_low: {"type":"range","label":"Low key word","description":"Philox uses key [key_low, 17]; Threefry uses [key_low, 17, 0, 0].","min":0,"max":1000,"step":1,"value":42}
//| cases:
//|   - {"id":"zero-key","label":"Low key word 0","description":"Even with low key word zero, four-word order and seek(0) reproduction are unchanged.","inputs":{"key_low":0}}
//|   - {"id":"key-1000","label":"Low key word 1000","description":"A different key changes block words but still gives four matches with the generator.","inputs":{"key_low":1000}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"counter-words","path":"/rows/0/1","approx":{"value":0.9187004133956886,"atol":1e-15}}
//|       - {"artifact":"counter-words","path":"/rows/0/3","equals":4}
//|       - {"artifact":"counter-words","path":"/rows/0/4","equals":4}
//|       - {"artifact":"counter-words","path":"/rows/1/3","equals":4}
//|       - {"artifact":"counter-words","path":"/rows/1/4","equals":4}
//|   - case: zero-key
//|     expect:
//|       - {"artifact":"counter-words","path":"/rows/0/3","equals":4}
//|       - {"artifact":"counter-words","path":"/rows/1/4","equals":4}
//|   - case: key-1000
//|     expect:
//|       - {"artifact":"counter-words","path":"/rows/0/4","equals":4}
//|       - {"artifact":"counter-words","path":"/rows/1/3","equals":4}
use scioxide_random::{
    BitGenerator, Philox4x64, Threefry4x64, decode_u64, philox4x64_block, threefry4x64_block,
};

// Read four generator words, propagating read failures unchanged.
fn four_words(rng: &mut impl BitGenerator) -> Result<[u64; 4], String> {
    let mut words = [0_u64; 4];
    for word in &mut words {
        *word = rng.next_u64().map_err(|e| e.to_string())?;
    }
    Ok(words)
}

// Count equal words at matching positions in two four-word sequences.
fn matches(a: &[u64; 4], b: &[u64; 4]) -> usize {
    a.iter().zip(b).filter(|(x, y)| x == y).count()
}

let key = [key_low as u64, 17];
let mut rows = Vec::new();
// Philox: two key words. The root stream's first four words are the block for counter [0, 1, 0, 0].
let mut philox = Philox4x64::from_key(key);
let words = four_words(&mut philox)?;
let block = philox4x64_block([0, 1, 0, 0], key);
philox.seek(0).map_err(|e| e.to_string())?;
let replay = four_words(&mut philox)?;
rows.push((
    "Philox4x64",
    decode_u64::<f64>(block[0]),
    decode_u64::<f64>(words[0]),
    matches(&block, &words),
    matches(&replay, &words),
));
// Threefry: four key words.
let key4 = [key[0], key[1], 0, 0];
let mut threefry = Threefry4x64::from_key(key4);
let words = four_words(&mut threefry)?;
let block = threefry4x64_block([0, 1, 0, 0], key4);
threefry.seek(0).map_err(|e| e.to_string())?;
let replay = four_words(&mut threefry)?;
rows.push((
    "Threefry4x64",
    decode_u64::<f64>(block[0]),
    decode_u64::<f64>(words[0]),
    matches(&block, &words),
    matches(&replay, &words),
));
// Show the first word mapped by decode_u64 to u in [0, 1) (equal top 53 bits give equal values).
let digits = serde_json::json!({ "significantDigits": 17 });
let columns = serde_json::json!([
    { "key": "0", "label": "Generator" },
    { "key": "1", "label": "u of first block word [-]", "type": "number", "format": digits },
    { "key": "2", "label": "u of first generator word [-]", "type": "number", "format": digits },
    { "key": "3", "label": "Words matching block [words] (of 4)", "type": "integer" },
    { "key": "4", "label": "Words matching after seek(0) [words] (of 4)", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "counter-words" })
);
```

For both generators, all four words match block outputs in the same order; all four reread after `seek(0)` also match.
With default keys, Philox's first word is hexadecimal `eb2ff3465b2d8355` ($u = 0.9187004133956886$), and Threefry's is `9d98d4300189d615` ($u = 0.6156132332994624$).
Changing the low key word to zero or 1000 changes word values but retains four matching words.
Counter-based generators evaluate this function at counters determined by sample indices, so seeking needs no earlier words.

## Reading results, errors, and diagnostics

- **Errors**: failures return `SciOxideError` and are classified with `kind()`.
  Parameter- and probability-domain violations give `DomainError`; nonfinite values give `NonFinite`; invalid tolerances in `LawOptions` or out-of-range settings and arguments such as $k > n$ give `InvalidInput`.
  Rejection and numerical inversion reaching 1,024 candidates or word/work limits give `ConvergenceFailure`; out-of-range advancement or bounded-stream reads give `OutOfBounds`; output/workspace length mismatches give `DimensionMismatch`.
  Samples rounding to zero or out of range and variances whose accuracy cannot be verified due to cancellation give `NumericalInstability`; exceeding storage limits gives `ResourceLimit` ([Error classification](oxref:random-algorithms-errors)).
- **Nonexistent quantities**: quantities lacking a capability (the mean of `Cauchy`) have no trait implementation; quantities absent for some parameters (Student t mean at $\nu \le 1$) return `DomainError` with reason `Undefined`.
- **Batch generation**: the two policies in `SamplingPolicy` determine output and generator state after a caller-output failure.
  Owned forms return values only on success; failures leave the generator advanced by consumed words.
- **Reports**: `MultivariateProbabilityReport`, `QmcReplicateEstimate`, and `TestStatisticResult` return values and error estimates; these errors are statistical or numerical estimates rather than certified bounds.
  `InversionReport` returns numerical-inversion brackets, residuals, and termination status; `LatinHypercubeReport` and `PoissonDiskReport` return termination status and work counts; `SamplingDiagnostics` returns generic-sampler work counts.
  `MultivariateProbabilityTermination::AccuracyNotMet` and `PoissonDiskTermination::BudgetExhausted` return as termination statuses rather than errors; inspect status before using results.
  One-shot forms (`poisson_disk` and laws' `rectangle`) return these terminations as errors.
- **Reproducibility**: for explicit seeds and identical call sequences, generator integer and floating-point outputs, `seed_sequence`, and built-in QMC sequences are reproduced while algorithm and decoder-convention versions match.
  Distribution sampling algorithms and their rounding, and seeds obtained from entropy, lie outside this guarantee ([Scope of reproducibility](oxref:random-algorithms-reproducibility)).
