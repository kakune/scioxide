When examining soil properties in a field, spread sampling points evenly across the plot and avoid pairs that are too close together.
Nearby points return similar values, reducing the information obtained from the same number of samples.
This example uses `PoissonDisk` to place sampling points at least radius $r$ apart.
Check the design's promised minimum distance by an exhaustive calculation independent of its construction, and compare the point count with a theoretical upper bound.
Bridson's method, the background grid, and maximality checks are explained in [Poisson disk sampling](../../algorithms/poisson-disk-sampling/).
[Design inputs for computer experiments with Latin hypercubes](../space-filling-designs/) covers another space-filling design that uses each coordinate stratum once.

## Field sampling points and Poisson disk sampling

Place sampling points in a 1 m square plot $[0, 1]^2$ [m], keeping every pair at least $r$ apart.
Such a point set is called a Poisson disk sample.
`PoissonDisk::with_options(&[0, 0], &[1, 1], r, capacity, options)` places points with Bridson's method.

1. Choose the first point uniformly in the plot and add it to the active list.
2. Choose an active point uniformly and draw up to $k$ candidates uniformly by area in the surrounding annulus $r \le \rho < 2r$.
   $k$ is `candidates_per_point` (default 30).
3. Accept candidates inside the plot and at least $r$ from every accepted point, adding them to the list.
4. Remove a point from the list when all $k$ candidates are rejected, and return to step 2 until the list is empty.

Search for neighboring points in background grid cells of side length $r/\sqrt{2}$.
Each cell has diagonal $r$ and therefore contains at most one point, limiting distance calculations for each candidate to nearby cells.
For $N$ points, the expected computational cost is $O(kN)$.
`PoissonDisk` handles boxes in 1–6 dimensions; in $d$ dimensions the cell side length is $r/\sqrt{d}$, and candidates are uniform by volume in the spherical shell $r \le \rho < 2r$.

## Limits and termination statuses

The point count limit `capacity` is a constructor argument.
`PoissonDiskOptions` bounds candidates per active point, total candidates (`max_proposals`), grid cells (`max_grid_cells`), and neighborhood work (`max_distance_checks`).
Neighborhood work counts both each visited cell and each compared point as one unit.
The constructor rejects plots and radii exceeding the cell count limit with `InvalidInput`.

| Termination status | Stopping condition | Cell conclusion |
|---|---|---|
| `Complete` | Point count reaches `capacity` | satisfied |
| `ActiveListExhausted` | No active points remain | partial |
| `BudgetExhausted` | Total candidates or neighborhood work reaches its limit | partial |
| `Stopped` | Cancellation or a deadline in `ExecutionContext` is detected before a candidate | partial |

Under every termination status, accepted points remain at least $r$ apart.
`ActiveListExhausted` is the normal end of Bridson's method, but it does not guarantee maximality: gaps that can hold another point may remain.
For this reason, statuses other than `Complete` are treated as partial results returning the design so far.

`PoissonDiskReport` returns termination status `termination()`, accepted point count `points()`, proposal count `proposals()`, and neighborhood work `distance_checks()`.
The proposal count includes the initial point and candidates outside the plot.
`generate_into` writes accepted points into the first `points()` rows of caller-provided output, leaving subsequent output unchanged.
The owning form `generate` returns only accepted points as a `Vec`; `poisson_disk` is a one-shot form that returns only points with default settings.
Only `poisson_disk` converts `BudgetExhausted` to a `ConvergenceFailure` error.

## An upper bound on point count and independent uniform points

Circles of diameter $r$ centered at each point do not overlap.
Each circle lies in the square of area $(1 + r)^2$ formed by expanding the plot by $r/2$ on each side.
When congruent circles are packed without overlap into a convex polygon with at most six sides, their total area cannot exceed $\pi/(2\sqrt{3})$ times the polygon's area, the hexagonal close-packing density (L. Fejes Tóth's theorem).
The square satisfies this condition, giving

$$
N \cdot \frac{\pi r^2}{4} \le \frac{\pi}{2\sqrt{3}}(1 + r)^2, \qquad\text{that is}\qquad N \le \frac{2(1 + r)^2}{\sqrt{3}\, r^2}
$$


For comparison, consider placing the same number of points independently and uniformly.
The distance $D$ between two independent uniform points in the unit square satisfies, for $0 \le r \le 1$,

$$
P(D < r) = \pi r^2 - \tfrac{8}{3} r^3 + \tfrac{1}{2} r^4
$$


Among the $N(N-1)/2$ pairs of $N$ points, the expected number with distance below $r$ is $\binom{N}{2} P(D < r)$.
This number is 0 for a Poisson disk sample, so the expectation indicates how much the minimum-distance constraint changes the configuration.

## Generate and inspect sampling points

The following cell places sampling points from inputs of minimum interpoint distance $r$ [m], candidates per active point $k$, total candidate limit, and random seed.
The point count limit is 400, exceeding the upper bound for every input.
Compute every pairwise distance exhaustively, find the minimum, and compare it with `MinimumDistance` from `geometric_discrepancy`.
Also count coordinates outside the plot and overwritten unused output entries, which were filled with $-1$ before passing them to `generate_into`.
Finally, show the termination status as an outcome.

```rust
//| id: random-poisson-disk-separation
//| ref: random-poisson-disk-separation
//| title: "Check all pairwise distances and the output range of accepted sampling points"
//| run: reactive
//| crates: [scioxide-core, scioxide-random]
//| inputs:
//|   minimum_radius: {"type":"range","label":"Minimum interpoint distance r [m]","min":0.06,"max":0.2,"step":0.02,"value":0.1}
//|   candidates: {"type":"range","label":"Candidates per active point k [candidates]","description":"Fewer candidates remove active points earlier and reduce the number of points placed.","min":5,"max":40,"step":5,"value":30}
//|   proposal_budget: {"type":"range","label":"Total candidate limit [candidates]","description":"A small limit returns a partial design with BudgetExhausted.","min":500,"max":20000,"step":500,"value":20000}
//|   seed: {"type":"range","label":"Random seed","min":1,"max":1000,"step":1,"value":42}
//| cases:
//|   - {"id":"dense","label":"r = 0.06 m","description":"A smaller radius increases both the point count and the packing upper bound.","inputs":{"minimum_radius":0.06}}
//|   - {"id":"few-candidates","label":"5 candidates","description":"Fewer candidates reduce the point count, while the minimum distance remains at least r.","inputs":{"candidates":5}}
//|   - {"id":"short-budget","label":"Up to 1000 candidates","description":"Stop with BudgetExhausted when the total candidate limit is reached, returning the points placed so far.","inputs":{"proposal_budget":1000}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"design","path":"/rows/0/0","equals":68}
//|       - {"artifact":"design","path":"/rows/0/1","approx":{"value":139.72,"atol":0.01}}
//|       - {"artifact":"design","path":"/rows/0/2","equals":2485}
//|       - {"artifact":"separation","path":"/rows/0/0","range":{"min":0.1,"max":0.2}}
//|       - {"artifact":"separation","path":"/rows/0/1","equals":0}
//|       - {"artifact":"separation","path":"/rows/0/2","equals":0}
//|       - {"artifact":"separation","path":"/rows/0/3","equals":0}
//|       - {"artifact":"separation","path":"/rows/0/4","equals":0}
//|       - {"path":"/outputs/3/state","equals":"partial"}
//|   - case: dense
//|     expect:
//|       - {"artifact":"separation","path":"/rows/0/0","range":{"min":0.06,"max":0.12}}
//|       - {"artifact":"separation","path":"/rows/0/4","equals":0}
//|   - case: few-candidates
//|     expect:
//|       - {"artifact":"separation","path":"/rows/0/0","range":{"min":0.1,"max":0.2}}
//|       - {"artifact":"separation","path":"/rows/0/3","equals":0}
//|   - case: short-budget
//|     expect:
//|       - {"artifact":"design","path":"/rows/0/2","equals":1000}
//|       - {"artifact":"separation","path":"/rows/0/0","range":{"min":0.1,"max":0.2}}
//|       - {"path":"/outputs/3/state","equals":"partial"}
use scioxide_core::{ExecutionContext, RealScalar};
use scioxide_random::{
    GeometricDiscrepancy, PoissonDisk, PoissonDiskOptions, PoissonDiskTermination, Rollback,
    SeedableRng, SplitMix64, geometric_discrepancy,
};

let options = PoissonDiskOptions::default()
    .with_candidates_per_point(candidates.round() as usize)
    .with_max_proposals(proposal_budget.round() as usize)
    .with_max_grid_cells(10_000)
    .with_max_distance_checks(5_000_000);
// Point count limit capacity = 400.
let design =
    PoissonDisk::with_options(&[0.0_f64, 0.0], &[1.0, 1.0], minimum_radius, 400, options)
        .map_err(|e| e.to_string())?;
let mut work = design.workspace().map_err(|e| e.to_string())?;
let mut out = vec![-1.0; design.output_elements()]; // Unused output should remain -1
let report = design
    .generate_into(
        &mut SplitMix64::from_seed(seed.round() as u64),
        Rollback,
        &mut out,
        &mut work,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;
let m = report.points();
if m < 2 {
    return Err(format!("Cannot obtain two points for a distance comparison (point count {m})"));
}
let r = minimum_radius;
// Minimum of all pairwise distances and count of pairs closer than r (independent check).
let mut brute = f64::INFINITY;
let mut close_pairs = 0_usize;
for i in 0..m {
    for j in 0..i {
        let distance =
            RealScalar::hypot(out[2 * i] - out[2 * j], out[2 * i + 1] - out[2 * j + 1]);
        brute = brute.min(distance);
        if distance < r {
            close_pairs += 1;
        }
    }
}
let separation = geometric_discrepancy(&out[..2 * m], 2, GeometricDiscrepancy::MinimumDistance)
    .map_err(|e| e.to_string())?;
let outside_box = out[..2 * m]
    .iter()
    .filter(|x| !(0.0..=1.0).contains(*x))
    .count();
let overwritten = out[2 * m..].iter().filter(|&&x| x != -1.0).count();
// Circle-packing upper bound and expected number of pairs closer than r for independent uniform points (comparison references).
let bound = 2.0 * (1.0 + r) * (1.0 + r) / (RealScalar::sqrt(3.0_f64) * r * r);
let close_probability =
    std::f64::consts::PI * r * r - 8.0 / 3.0 * r * r * r + 0.5 * r * r * r * r;
let pairs = (m * (m - 1) / 2) as f64;
let points: Vec<[f64; 2]> = out[..2 * m].chunks_exact(2).map(|p| [p[0], p[1]]).collect();
emit_scatter_chart!(
    &points,
    options = &serde_json::json!({
        "xLabel": "East–west position [m]",
        "yLabel": "North–south position [m]",
        "xMin": 0.0,
        "xMax": 1.0,
        "yMin": 0.0,
        "yMax": 1.0
    })
);
let digits4 = serde_json::json!({ "significantDigits": 4 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let design_columns = serde_json::json!([
    { "key": "0", "label": "Accepted points points() [points]", "type": "integer" },
    { "key": "1", "label": "Packing upper bound [points]", "type": "number", "format": digits4 },
    { "key": "2", "label": "Proposals proposals() [proposals]", "type": "integer" },
    { "key": "3", "label": "Neighborhood work distance_checks() [operations]", "type": "integer" },
    { "key": "4", "label": "Expected uniform-point pairs closer than r [pairs]", "type": "number", "format": digits4 }
]);
emit_table_with_columns!(
    design_columns,
    vec![(
        m,
        bound,
        report.proposals(),
        report.distance_checks(),
        pairs * close_probability,
    )],
    metadata = serde_json::json!({ "id": "design" })
);
let separation_columns = serde_json::json!([
    { "key": "0", "label": "Exhaustive minimum distance [m]", "type": "number", "format": digits4 },
    { "key": "1", "label": "Difference from geometric_discrepancy [m]", "type": "number", "format": sci2 },
    { "key": "2", "label": "Pairs closer than r [pairs]", "type": "integer" },
    { "key": "3", "label": "Coordinates outside the plot [coordinates]", "type": "integer" },
    { "key": "4", "label": "Overwritten unused output [entries]", "type": "integer" }
]);
emit_table_with_columns!(
    separation_columns,
    vec![(
        brute,
        (brute - separation).abs(),
        close_pairs,
        outside_box,
        overwritten,
    )],
    metadata = serde_json::json!({ "id": "separation" })
);
let termination = report.termination();
let outcome = if termination == PoissonDiskTermination::Complete {
    Outcome::satisfied("Point count reached capacity")
} else {
    Outcome::partial("Stopped before capacity, returning the design so far").explanation(
        "Every pair of accepted points is at least r apart, but absence of gaps that can hold another point is not guaranteed.",
    )
};
emit_outcome!(
    outcome
        .status(format!("{termination:?}"))
        .diagnostic("Accepted points", m as f64, None)
        .diagnostic("Minimum distance", brute, Some("m"))
);
```

In the scatter plot, points have roughly uniform spacing and no pair is closer than $r$.
Unlike independent uniform points, they do not form tightly spaced clusters.
If two points are closer than $r$, the distance invariant has been violated.

With the default inputs ($r = 0.1$ m, $k = 30$, seed 42), generation ends with `ActiveListExhausted` when no active points remain, placing 68 points from 2,485 proposals.
The cell concludes partial, and the design returns all points placed so far.
The exhaustive minimum distance is $0.1007$ m, at least $r$, and matches `geometric_discrepancy`.
Pairs closer than $r$, coordinates outside the plot, and overwritten unused output entries all number 0.
The point count is about 49% of the packing upper bound of 139.7 points.
Placing the same 68 points independently and uniformly produces an average of 65.6 pairs closer than $r$ among 2,278 pairs.

With $r = 0.06$ m, 6,596 proposals place 181 points (about 50% of the 360.4-point upper bound); using 5 candidates places 54 points from 412 proposals, and both retain a minimum distance of at least $r$.
Fewer candidates remove active points from the list earlier, stopping with gaps still present and reducing the point count.
Setting the total candidate limit to 1,000 stops with `BudgetExhausted` and returns 49 points.
This design also retains a minimum distance of $0.1007$ m, but large regions of the plot can still hold more points.
Both `ActiveListExhausted` and `BudgetExhausted` are partial, but the former exhausts candidates while the latter stops at a work limit, so compare their point and proposal counts together.

## Summary

Exhaustive pairwise distances confirm that the Poisson disk sample's minimum distance is at least $r$, matching `geometric_discrepancy`.
The point count does not exceed the circle-packing upper bound and is about half that bound with this example's default candidate count.
The same number of independent uniform points gives about $\binom{N}{2}(\pi r^2 - \tfrac{8}{3}r^3 + \tfrac12 r^4)$ pairs closer than $r$, showing how substantially the minimum-distance constraint changes the configuration.
`generate_into` writes accepted points only at the start of the output and leaves the remainder unchanged, so read only `points()` rows.
Read termination statuses other than `Complete` as partial designs; if there are too few points, increase the candidate count or limits.
