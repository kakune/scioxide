When random seeds are assigned to workers in parallel computations, two workers can draw the same seed.
Their collision probability is $P(k, D) = 1 - \prod_{i<k}(1 - i/D)$, derived in [The birthday problem and random seed collisions](../birthday-collisions/), with day count $D$ replaced by the number of seeds and person count $k$ by the worker count.
This page estimates 64-bit seed collision probabilities and checks the same formula with simulations in a small seed space.
It then examines the guarantees and limitations of selecting streams by index instead of assigning seeds at random.

## 64-bit seed collisions

When $W$ workers independently choose uniformly from $2^b$ seeds, the probability of at least one pair choosing the same seed is $P(W, 2^b)$.
For $W \ll 2^{b/2}$, this is small at $P \approx W^2/2^{b+1}$, but it increases sharply as $W$ approaches $2^{b/2}$.
For 64-bit seeds, $P \approx W(W-1)/2^{65}$, and the worker count giving $P = 1/2$ is $\sqrt{2\ln 2 \cdot 2^{64}} \approx 5.06 \times 10^9$.
Two workers drawing the same seed use the same random sequence, counting the same sample twice while treating it as two independent samples.

Counting collisions in a 64-bit space is impractical, so the following cell checks the same formula in a small $b = 12$–$24$-bit space.
Inputs are seed bit count $b$, the worker count divided by $2^{b/2}$, and a random seed; the trial count is fixed at 400.
Each trial draws $W$ seeds with `uniform_index(2^b)` from a `root.split(trial_index)` stream, sorts them, and searches for adjacent equal values.
For comparison, also count duplicates among $W$ 64-bit seeds generated by `seed_sequence(seed, W)`.
The second table gives closed-form collision probabilities for 64-bit seeds at each $W$.

```rust
//| id: random-birthday-seeds
//| ref: random-birthday-seeds
//| title: "Count randomly assigned seed collisions and apply the result to 64 bits"
//| run: reactive
//| crates: [scioxide-core, scioxide-random]
//| inputs:
//|   seed_bits: {"type":"range","label":"Seed bit count b [bit]","description":"Seed-space size 2^b.","min":12,"max":24,"step":2,"value":20}
//|   worker_load: {"type":"range","label":"Worker count ratio W/2^{b/2} [-]","description":"At 1, collision probability is 1 − e^{−1/2} ≈ 0.39.","min":0.25,"max":3,"step":0.25,"value":1}
//|   seeds_seed: {"type":"range","label":"Random seed [-]","description":"Pcg64 seed. Each trial uses a split stream.","min":1,"max":1000,"step":1,"value":5}
//| cases:
//|   - {"id":"few-workers","label":"W/2^{b/2} = 0.25","description":"At W = 256, exact P is 0.0307, close to the W²/2^{b+1} estimate 0.031.","inputs":{"worker_load":0.25}}
//|   - {"id":"large-space","label":"b = 24, ratio 3","description":"At W = 12288, exact P is 0.989.","inputs":{"seed_bits":24,"worker_load":3}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"simulation","path":"/rows/0/1","equals":1024}
//|       - {"artifact":"simulation","path":"/rows/0/2","approx":{"value":0.3932718,"atol":1e-6}}
//|       - {"artifact":"simulation","path":"/rows/0/4","range":{"min":0.32,"max":0.47}}
//|       - {"artifact":"simulation","path":"/rows/0/7","equals":0}
//|       - {"artifact":"sixty-four","path":"/rows/3/2","approx":{"value":0.026741,"atol":1e-6}}
//|       - {"artifact":"sixty-four","path":"/rows/4/2","approx":{"value":0.5,"atol":1e-9}}
//|   - case: few-workers
//|     expect:
//|       - {"artifact":"simulation","path":"/rows/0/2","approx":{"value":0.0306509,"atol":1e-6}}
//|       - {"artifact":"simulation","path":"/rows/0/4","range":{"min":0.005,"max":0.06}}
//|   - case: large-space
//|     expect:
//|       - {"artifact":"simulation","path":"/rows/0/2","approx":{"value":0.9888991,"atol":1e-6}}
//|       - {"artifact":"simulation","path":"/rows/0/4","range":{"min":0.97,"max":1.0}}
use scioxide_core::RealScalar;
use scioxide_random::{Pcg64, SeedableRng, SplittableRng, seed_sequence, uniform_index};

let bits = seed_bits.round() as u32;
let space = 1_usize << bits;
let workers = (worker_load * RealScalar::sqrt(space as f64)).round() as usize;
let r = 400_usize;
let master = seeds_seed.round() as u64;
let root = Pcg64::from_seed(master);
let mut seeds = vec![0_usize; workers];
let mut collisions = 0;
for trial in 0..r {
    let mut rng = root.split(trial as u64).map_err(|e| e.to_string())?;
    for seed in seeds.iter_mut() {
        *seed = uniform_index(space, &mut rng).map_err(|e| e.to_string())?;
    }
    seeds.sort_unstable();
    collisions += usize::from(seeds.windows(2).any(|w| w[0] == w[1]));
}
// Count duplicates among W seed_sequence seeds (the SplitMix64 output sequence).
let mut derived = seed_sequence(master, workers).map_err(|e| e.to_string())?;
derived.sort_unstable();
let derived_duplicates = derived.windows(2).filter(|w| w[0] == w[1]).count();
// Independent check: exact product and exponential approximation.
let log_q: f64 = (0..workers)
    .map(|i| RealScalar::ln_1p(-(i as f64) / space as f64))
    .sum();
let p = -RealScalar::exp_m1(log_q);
let pairs = (workers * (workers - 1)) as f64 / 2.0;
let p_approx = -RealScalar::exp_m1(-pairs / space as f64);
let p_hat = collisions as f64 / r as f64;
let se = RealScalar::sqrt(p * (1.0 - p) / r as f64);
let fixed4 = serde_json::json!({ "fractionDigits": 4 });
let fixed2 = serde_json::json!({ "fractionDigits": 2 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "b [bit]", "type": "integer" },
    { "key": "1", "label": "Worker count W [workers]", "type": "integer" },
    { "key": "2", "label": "Exact P [-]", "type": "number", "format": fixed4 },
    { "key": "3", "label": "Approximate P [-]", "type": "number", "format": fixed4 },
    { "key": "4", "label": "P̂ (400 trials) [-]", "type": "number", "format": fixed4 },
    { "key": "5", "label": "SE [-]", "type": "number", "format": fixed4 },
    { "key": "6", "label": "z = (P̂ − P)/SE [-]", "type": "number", "format": fixed2 },
    { "key": "7", "label": "seed_sequence duplicates [pairs]", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    vec![(
        bits,
        workers,
        p,
        p_approx,
        p_hat,
        se,
        (p_hat - p) / se,
        derived_duplicates
    )],
    metadata = serde_json::json!({ "id": "simulation" })
);
// 64-bit seeds: P = 1 − exp(−W(W − 1)/2^65).
let two_65 = RealScalar::powi(2.0_f64, 65);
let half_point =
    RealScalar::sqrt(2.0 * RealScalar::ln(2.0_f64) * RealScalar::powi(2.0_f64, 64));
let rows: Vec<(f64, f64, f64)> = [1e3, 1e6, 1e8, 1e9, half_point, 1e10]
    .iter()
    .map(|&w| {
        (
            w,
            w * (w - 1.0) / two_65,
            -RealScalar::exp_m1(-w * (w - 1.0) / two_65),
        )
    })
    .collect();
let wide = serde_json::json!([
    { "key": "0", "label": "Worker count W [workers]", "type": "number", "format": sci3 },
    { "key": "1", "label": "W(W − 1)/2⁶⁵ [-]", "type": "number", "format": sci3 },
    { "key": "2", "label": "Collision probability [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    wide,
    rows,
    metadata = serde_json::json!({ "id": "sixty-four" })
);
```

With default $b = 20$ and $W = 1024$, the exact probability is $0.39327$ and the proportion over 400 trials is $0.3675$ (difference $-1.06\,\mathrm{SE}$).
The exponential approximation is $0.39317$; in this setting with $W \ll 2^b$, its difference from the exact value stays within $10^{-4}$.
A ratio of 0.25 gives $W = 256$ and $P = 0.0307$; a ratio of 3 with $b = 24$ gives $W = 12288$ and $P = 0.989$.
The probability depends mainly on ratio $W/2^{b/2}$ rather than $W$ itself; increasing the ratio twelvefold moves it from near 0 to near 1.
Duplicate counts among $W$ seeds from `seed_sequence` are 0 for every input.

For 64-bit seeds, $10^6$ workers give collision probability $2.7 \times 10^{-8}$, while $10^9$ workers give $0.0267$ and $5.06 \times 10^9$ workers give $0.5$.
$W(W-1)/2^{65}$ is an approximation for small $P$; when $P$ exceeds 0.1, its difference from $1 - \exp(-W(W-1)/2^{65})$ becomes noticeable.

## Guarantees of stream splitting

Selecting streams from one generator by worker index instead of random seeds gives distinct selectors $0, 1, \dots, W-1$, removing selector collisions.
Selectors of `SplittableRng` are absolute selections from the root even when called on a derived generator, and do not consume the parent.
However, the `SplittableRng` contract states only that different selectors refer to different streams.
Overlap within the ranges read depends on generator period, stream spacing, and words consumed per stream; each generator provides different guarantees.

- `split` and `substream` of `Philox4x64` and `Threefry4x64` change the counter's stream and substream words while retaining the same key.
  One stream has $2^{66}$ words; streams with distinct selectors never evaluate the same counter block, so overlap is excluded by construction while each stream reads at most $2^{66}$ words.
- `Pcg64::split(id)` selects an LCG with additive constant $2\,\mathrm{id} + 1$, allowing selection among $2^{64}$ streams.
  Each stream is a different congruential sequence with period $2^{128}$; `substream(id, j)` selects block $j$ of that stream divided into blocks of $2^{64}$ transitions.
  Blocks in the same stream do not overlap if each reads at most $2^{64}$ transitions.
- `Xoshiro256StarStar` has no `SplittableRng`; it separates intervals by advancing $2^{128}$ transitions with `JumpableRng::jump` or $2^{192}$ transitions with `long_jump`.
  Jumps for `Xoshiro128StarStar` are $2^{64}$ and $2^{96}$ transitions.
- `StreamPartitioner::for_partition` constructs a 128-bit key from a `ExecutionPlan` partition identifier and domain index, using its lower 64 bits as the stream selector and upper 64 bits as the substream selector, and returns a length-limited `BoundedSubstream`.
  Reads past the range fail with `OutOfBounds` without changing state.
  The key is mixed, so substream indices can be large.
  For example, `Mrg32k3a` specifies nonoverlapping substreams only over $j < 2^{51}$, while a key-derived $j$ usually falls outside that range.
  Only counter-based generators exclude overlap between partitions by construction; for other generators, check their individual spacing conditions.

`seed_sequence(seed, n)` is the output sequence of `SplitMix64` itself, applying a bijective mixing function to a Weyl sequence, so up to $2^{64}$ indices give distinct seeds.
This property explains the zeros in the cell's duplicate column.
Distinct seeds, however, do not guarantee nonoverlapping streams.
`Pcg64::from_seed` uses the same additive constant for every seed; a seed only selects a starting point on one congruential sequence with period $2^{128}$.
For $W$ random starting points and $L$ words used per stream, the probability of overlapping intervals is approximately $W(W-1)L/2^{128}$, giving $3.2 \times 10^{-15}$ for $W = 10^6$ and $L = 2^{40}$.
To avoid overlap by construction rather than probability, select streams with `split` or `substream` of a counter-based generator.
Stream spacing and overlap conditions are explained in [Stream spacing and overlap](oxref:random-prng-stream-spacing), and partition assignment in [Assignment to execution Plan partitions](oxref:random-prng-plan-partitions).

## Summary

Collision probabilities for randomly assigned $b$-bit seeds follow the birthday formula and depend mainly on the ratio between worker count $W$ and $2^{b/2}$.
For 64-bit seeds, the probability is about 2.7% at $W = 10^9$ and reaches 1/2 at $W \approx 5.06 \times 10^9$, so large parallel computations should not rely on random seeds.
`seed_sequence` returns distinct seeds, but for generators such as `Pcg64` whose seeds only choose starting points on one congruential sequence, stream overlap is controlled only probabilistically.
To avoid overlap by construction, use `split` or `substream` of a counter-based generator; for other generators, check each generator's stream spacing and per-stream word limit.
