[Bracketing root-finding methods](../bracketing-methods/) assume that a sign-changing interval $[a, b]$ is supplied.
For physical equilibria and distribution quantiles, the approximate root location is often known, but an interval with opposite endpoint signs cannot be specified in advance.
In that case, expand an interval from a guess to find a sign change, and reevaluate endpoints when reusing the resulting interval later.

## Search inputs and directions

When no sign-changing interval is known, expand from a guess to search for a sign change.
`find_bracket(f, guess)` accepts a closure `f` and one guess, searching within $[-\mathrm{MAX}, \mathrm{MAX}]$ (where `MAX` is the largest finite floating-point value) with defaults of automatic direction, additive expansion, growth factor 2, and at most 2048 expansions.
`find_bracket_with_options(&f, input, direction, &options)` accepts a function implementing `ScalarFunction`, a guess or two seeds, a search direction, and `BracketSearchOptions`.
Use `BracketSearchInput::Guess` for one guess and `Pair` for two seeds ordered as $a \le b$ ($a = b$ is also allowed).
With `Pair`, $a$ is evaluated first; if $f(a) = 0$, the search ends there.
Each expansion step moves one endpoint and evaluates the function once.
`BracketSearchDirection` distinguishes automatic search without a declared function direction (`Automatic`), monotonically increasing (`Increasing`), and monotonically decreasing (`Decreasing`).
Automatic search expands the endpoint with smaller $\lvert f \rvert$ and tries the other endpoint if it cannot advance.
Declaring monotonicity expands only toward the root based on the function-value sign and returns the first consecutive pair of points with a sign change.
Monotonicity is the caller's promise; the search does not verify it.

The search returns only intervals whose endpoint function values have opposite signs or include a zero.
It cannot distinguish roots without sign changes, such as even-multiplicity roots, or sign changes caused by poles.

## Expansion schemes and domains

`BracketSearchOptions` configures the expansion-count limit (`with_max_expansions`, default 2048), growth factor $r$ (`with_expansion_factor`, default 2, greater than 1), expansion scheme (`with_expansion`), domain (`with_domain`), and iteration and evaluation limits (`with_budgets`).
There is no option for setting the initial width.
Additive search from one guess $x_0$ begins with half-width $h = \max(\lvert x_0 \rvert, 1)$; automatic direction evaluates both endpoints of $[x_0 - h, x_0 + h]$, while declared monotonicity evaluates $x_0$ and $x_0 \pm h$.
To specify an initial interval, supply it through `Pair`.

`BracketExpansion::Additive` moves an endpoint by $b \leftarrow b + (r - 1)(b - a)$ (symmetrically for the lower endpoint), multiplying interval width by $r$; `Multiplicative` multiplies or divides the endpoint coordinate by $r$.
Multiplicative search never crosses 0, so a strictly positive or negative domain must be set with `with_domain`; a domain containing 0 returns `InvalidInput` before calling the function.
An `Excluded` endpoint in `with_domain` is replaced by its adjacent floating-point value inside the domain, and `Unbounded` by $\pm\mathrm{MAX}$, keeping every evaluation point within the domain.
Reversed seeds or seeds outside the domain also return `InvalidInput` before calling the function.
Reaching the expansion limit returns `ConvergenceFailure` (`IterationLimit`); inability to move either endpoint at the domain boundaries returns `ConvergenceFailure` (`Stagnation`).

With the default growth factor 2, a search from one guess expands its width approximately $2^k$-fold after $k$ expansions.
If the distance to the root is $d$, approximately $\log_2\bigl(d / \max(\lvert x_0 \rvert, 1)\bigr)$ expansions are needed, with evaluation counts growing at the same rate.

## Searching a positive domain

The following cell searches for a zero of $f(x) = \ln x - q$ in the positive domain $(0, \infty)$ from guess $x_0 = 1$, declaring monotonic increase.
Inputs are target $q$ and expansion scheme; outputs are interval endpoints, endpoint function values stored in `Bracket`, whether the interval contains independent reference $e^q$, and endpoint reevaluation results.

```rust
//| id: rootfind-positive-bracket-search
//| ref: rootfind-positive-bracket-search
//| title: "Find a sign change of a monotone logarithm on a positive domain"
//| run: reactive
//| crates: [scioxide-core, scioxide-rootfind]
//| inputs:
//|   level: {"type":"range","label":"Logarithm target q [-]","description":"The root is e^q. Negative values place it between 0 and 1.","min":-4,"max":4,"step":0.5,"value":2}
//|   expansion: {"type":"select","label":"Interval expansion scheme","options":["additive","multiplicative"],"value":"multiplicative"}
//| cases:
//|   - {"id":"additive","label":"q = 2, additive search","description":"Doubling the width visits 1, 2, 3, 5, 9 and returns [5, 9].","inputs":{"expansion":"additive"}}
//|   - {"id":"below-one","label":"q = −3, multiplicative search (root between 0 and 1)","description":"Halving coordinates returns [0.03125, 0.0625].","inputs":{"level":-3}}
//|   - {"id":"below-one-additive","label":"q = −3, additive search (root between 0 and 1)","description":"The first step reaches the domain boundary and returns [5 × 10⁻³²⁴, 1], spanning more than 300 orders of magnitude.","inputs":{"level":-3,"expansion":"additive"}}
//|   - {"id":"exact-guess","label":"q = 0 (guess is an exact root)","description":"Because f(1) = 0, the singleton interval [1, 1] is returned.","inputs":{"level":0}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"bracket","path":"/rows/0/0","approx":{"value":4,"atol":1e-12}}
//|       - {"artifact":"bracket","path":"/rows/0/1","approx":{"value":8,"atol":1e-12}}
//|       - {"artifact":"bracket","path":"/rows/0/2","range":{"max":0}}
//|       - {"artifact":"bracket","path":"/rows/0/3","range":{"min":0}}
//|       - {"artifact":"bracket","path":"/rows/0/4","approx":{"value":7.389,"atol":5e-4}}
//|       - {"artifact":"bracket","path":"/rows/0/5","equals":"Contains"}
//|       - {"artifact":"bracket","path":"/rows/0/6","equals":"Verified"}
//|   - case: additive
//|     expect:
//|       - {"artifact":"bracket","path":"/rows/0/0","approx":{"value":5,"atol":1e-12}}
//|       - {"artifact":"bracket","path":"/rows/0/1","approx":{"value":9,"atol":1e-12}}
//|       - {"artifact":"bracket","path":"/rows/0/5","equals":"Contains"}
//|       - {"artifact":"bracket","path":"/rows/0/6","equals":"Verified"}
//|   - case: below-one
//|     expect:
//|       - {"artifact":"bracket","path":"/rows/0/0","approx":{"value":0.03125,"atol":1e-15}}
//|       - {"artifact":"bracket","path":"/rows/0/1","approx":{"value":0.0625,"atol":1e-15}}
//|       - {"artifact":"bracket","path":"/rows/0/5","equals":"Contains"}
//|   - case: below-one-additive
//|     expect:
//|       - {"artifact":"bracket","path":"/rows/0/0","range":{"min":0,"max":1e-300}}
//|       - {"artifact":"bracket","path":"/rows/0/1","approx":{"value":1,"atol":1e-12}}
//|       - {"artifact":"bracket","path":"/rows/0/5","equals":"Contains"}
//|       - {"artifact":"bracket","path":"/rows/0/6","equals":"Verified"}
//|   - case: exact-guess
//|     expect:
//|       - {"artifact":"bracket","path":"/rows/0/0","approx":{"value":1,"atol":1e-15}}
//|       - {"artifact":"bracket","path":"/rows/0/1","approx":{"value":1,"atol":1e-15}}
//|       - {"artifact":"bracket","path":"/rows/0/2","equals":0}
use core::ops::Bound::{Excluded, Unbounded};
use scioxide_core::RealScalar;
use scioxide_rootfind::{
    BracketExpansion, BracketSearchDirection, BracketSearchInput, BracketSearchOptions,
    BracketVerification, ScalarFn, find_bracket_with_options,
};

let geometry = if expansion == "multiplicative" {
    BracketExpansion::Multiplicative
} else {
    BracketExpansion::Additive
};
// Logarithm domain x > 0. Excluded(0) becomes the positive floating-point neighbor of 0.
let options = BracketSearchOptions::default()
    .with_domain(Excluded(0.0_f64), Unbounded)
    .with_expansion(geometry);
let f = ScalarFn::new(|x: f64| Ok(RealScalar::ln(x) - level));
let bracket = find_bracket_with_options(
    &f,
    BracketSearchInput::Guess(1.0),
    BracketSearchDirection::Increasing,
    &options,
)
.map_err(|e| e.to_string())?;
// Reevaluate endpoints and check agreement with stored values.
let verification = match bracket.verify(&f).map_err(|e| e.to_string())? {
    BracketVerification::Verified => "Verified",
    BracketVerification::Rejected => "Rejected",
};
// Use f64's inherent exponential function as an independent reference.
let exact = level.exp();
let contains = if bracket.interval().contains(exact) {
    "Contains"
} else {
    "Does not contain"
};
let sci4 = serde_json::json!({ "notation": "scientific", "significantDigits": 4 });
let columns = serde_json::json!([
    { "key": "0", "label": "Lower endpoint [-]", "type": "number", "format": sci4 },
    { "key": "1", "label": "Upper endpoint [-]", "type": "number", "format": sci4 },
    { "key": "2", "label": "f(lower endpoint) [-]", "type": "number", "format": sci4 },
    { "key": "3", "label": "f(upper endpoint) [-]", "type": "number", "format": sci4 },
    { "key": "4", "label": "Reference exp(q) [-]", "type": "number", "format": sci4 },
    { "key": "5", "label": "Contains reference" },
    { "key": "6", "label": "Endpoint revalidation" }
]);
let row = (
    bracket.lower(),
    bracket.upper(),
    bracket.lower_value(),
    bracket.upper_value(),
    exact,
    contains,
    verification,
);
emit_table_with_columns!(
    columns,
    vec![row],
    metadata = serde_json::json!({ "id": "bracket" })
);
```

At $q = 2$, multiplicative search doubles coordinates as $1, 2, 4, 8$ and returns $[4, 8]$, while additive search doubles widths, visiting $1, 2, 3, 5, 9$ and returning $[5, 9]$.
Both contain reference $e^2 \approx 7.389$ and have opposite endpoint function signs.
For roots above 1, both schemes expand geometrically; even at $q = 4$, multiplicative search gives $[32, 64]$ and additive search $[33, 65]$ with little difference in evaluation counts.
The difference appears for $q < 0$ when the root lies between 0 and 1.
At $q = -3$, multiplicative search halves coordinates to return $[0.03125, 0.0625]$, while additive search reaches the domain boundary on the first step (the positive floating-point neighbor of 0, $5 \times 10^{-324}$) and returns $[5 \times 10^{-324}, 1]$, spanning more than 300 orders of magnitude.
Both correctly bracket the root, but the widths to reduce in the subsequent solve differ greatly.
At $q = 0$, guess 1 is an exact root, so singleton interval $[1, 1]$ is returned.

The interval establishes a sign change at finite endpoints; continuity and monotonicity remain mathematical assumptions about the input function.
To improve accuracy, pass `Bracket::interval()` to a bracketing method's `ScalarRootSolver::solve`, such as Brent's method.
If Brent's defaults suffice, `find_root(f, bracket.lower(), bracket.upper())` returns only the root, converting unsuccessful termination into errors such as `ConvergenceFailure`.
The solve reevaluates endpoints, adding those two evaluations to the search's evaluations.

## Revalidating intervals

`Bracket::verify` reevaluates endpoints and returns `BracketVerification::Verified` if they match the stored values or `Rejected` otherwise.
It performs one evaluation for a singleton interval and two otherwise.
This checks whether endpoint observations can be reproduced; it does not prove continuity between them.
For example, the intermediate value theorem does not apply to a sign change across a pole of $1/(x - c)$.
Take care when reusing intervals for functions whose values change with measurement noise or external state.

## Sharing execution and reuse

`find_bracket` and `find_bracket_with_options` search in a new sequential execution.
`find_bracket_scoped` shares the caller's execution scope, so inner searches obey the overall evaluation limit and cancellation.
Scalar bracketing methods have no external workspace and use only fixed-size state.
The same method, settings, and function can be reused, but no API resumes an earlier solve mid-computation.

## Summary

When no sign-changing interval is known, use `find_bracket` or `find_bracket_with_options` to expand from one guess or two seeds, then pass the resulting `Bracket` to a bracketing method.
For functions with declared monotonicity, specifying `Increasing` or `Decreasing` expands only toward the root.
For one-sided domains such as positive quantities, combine `with_domain` with `BracketExpansion::Multiplicative` to avoid intervals spanning many orders of magnitude.
Returned intervals and `Bracket::verify` results record evaluated endpoint signs; continuity between endpoints is the caller's assumption.
