Safety-limit analysis, distribution quantiles, and equilibrium temperatures often require evidence that a root lies within a specified interval as well as a small residual.
Bracketing methods shrink an interval $[a, b]$ ($f(a) f(b) < 0$) each iteration while preserving the property that it brackets a root (the containment invariant).
This property assumes continuity of $f$ and correctness of signs evaluated in floating-point arithmetic.
Bracketing methods from bisection to Brent differ only in their choice of evaluation points; these choices determine convergence speed and evaluations per iteration.
Searches without known brackets are covered in [Finding and revalidating a bracket](../bracket-search/).

## Intermediate value theorem and containment invariant

The mathematical basis of bracketing methods is Bolzano's intermediate value theorem.

If a continuous function $f$ on bounded closed interval $[a, b]$ has opposite endpoint signs,

$$
f(a) f(b) < 0
$$

then open interval $(a, b)$ contains at least one zero $x^*$ ($f(x^*) = 0$).

Bracketing methods evaluate $f$ at an interior point $c$ and choose $[a, c]$ as the next interval if $f(a)$ and $f(c)$ have opposite signs, or $[c, b]$ otherwise.
Either choice has opposite endpoint signs, preserving the theorem's assumptions and keeping a root inside the interval.
Methods differ only in how they choose evaluation point $c$.

The argument requires the following conditions.

1. Continuity: $f(x) = 1/x$ has opposite endpoint signs on $[-1, 1]$ ($f(-1) = -1$, $f(1) = 1$), but no zero; the interval crosses singularity $x = 0$.
   A sign change alone does not establish a root; continuity is necessary.
2. Sign change: at even-multiplicity roots (for example, $f(x) = (x - c)^2$), the curve merely touches the horizontal axis without changing sign.
   Searches for sign changes cannot detect such roots.
   Observing an exact endpoint zero accepts that point as a root even without a sign change.
3. Correct signs: near a root, error $\delta$ in computed $f$ can exceed the value itself, making its sign unreliable.
   Root position therefore cannot be determined more finely than approximately width $2\delta / \lvert f'(x^*) \rvert$ ([Residual and position error](oxref:rootfind-residual-and-position-error)).

scioxide-rootfind bracketing methods first evaluate supplied endpoints; without an exact endpoint zero or opposite signs, they return `InvalidInput` before iteration (argument `init`; `lower` for one-call `find_root`).
An exactly zero endpoint returns immediately with `ResidualTolerance` without iteration.
A function returning NaN or infinity produces a `NonFinite` error.

## Bisection convergence

Bisection (`Bisection`) evaluates the midpoint of current interval $[a_k, b_k]$:

$$
m_k = a_k + \frac{b_k - a_k}{2}
$$

After iteration $k$, interval width $w_k = b_k - a_k$ satisfies, independently of the function:

$$
w_k = \frac{w_0}{2^k} \qquad (w_0 = b_0 - a_0)
$$

scioxide-rootfind returns the endpoint with smaller $\lvert f \rvert$ as its root approximation, so position error is bounded by $w_k$.
The iterations required for position tolerance $\delta_x$ are therefore

$$
k_{\text{req}} = \max\left(0,\left\lceil \log_2 \frac{w_0}{\delta_x} \right\rceil\right)
$$

determined before computation, independently of curvature or higher derivatives.
Each iteration costs one function evaluation; continuity suffices without smoothness.
Knowing iteration counts beforehand helps applications such as control with bounded execution times.

The default stopping criterion is `BracketTolerance` when interval width is at most $4\varepsilon + 4\varepsilon \max(\lvert a_k \rvert, \lvert b_k \rvert)$; both $4\varepsilon$ values can be changed through `with_step_tolerance` ($\varepsilon$ is machine epsilon, $2^{-52} \approx 2.2 \times 10^{-16}$ for `f64`).
This criterion uses only interval width and is independent of function-value scale.
Starting from $[0, 1]$ stops after 50 iterations at width $2^{-50} \approx 8.9 \times 10^{-16}$ unless a midpoint is an exact root.
Once a floating-point interval shrinks to 1 ulp, no representable interior point remains; zero tolerances therefore stop with `Stagnation`.

## False position and one-sided stagnation

False position (`RegulaFalsi`) evaluates the intersection of the endpoint secant with the horizontal axis,

$$
c_k = a_k - f(a_k) \frac{b_k - a_k}{f(b_k) - f(a_k)} = \frac{a_k f(b_k) - b_k f(a_k)}{f(b_k) - f(a_k)}
$$

rather than the midpoint.
Since $f(a_k)$ and $f(b_k)$ have opposite signs, exact arithmetic always places $c_k$ inside open interval $(a_k, b_k)$.
scioxide-rootfind normalizes by endpoint function magnitudes when computing $c_k$, replacing $c_k$ by the midpoint only if rounding places it outside the interval interior.

If the function is nearly linear near a root, false position approaches it with fewer evaluations than bisection.
However, if $f''$ retains one sign on the interval (convex or concave), $c_k$ always falls on the same side of the root, leaving the opposite endpoint unchanged indefinitely.
If right endpoint $b$ stays fixed, iteration takes the form $x_{k+1} = g(x_k)$, $g(x) = x - f(x)\,(x - b)/(f(x) - f(b))$, and

$$
g'(x^*) = 1 - \frac{f'(x^*)\,(b - x^*)}{f(b)} = 1 - \frac{f'(x^*)}{f'(\eta)} \qquad (x^* < \eta < b)
$$

gives linear convergence, with errors multiplied by approximately $C = \lvert g'(x^*) \rvert$ per iteration.
For convex increasing $f$, $f'(\eta) > f'(x^*)$ gives $0 < C < 1$; stronger curvature moves $C$ closer to 1.
Even as the approximation converges to the root, interval width approaches $b - x^*$ rather than zero.
The interval still contains a root, but the width-based position-error bound does not improve.

## Resolving stagnation with the Illinois method

Illinois (`Illinois`) halves the function value used in interpolation at an endpoint retained for two consecutive iterations ($f(b) \leftarrow f(b)/2$).
Reducing its weight moves the next interpolated point toward the fixed endpoint, allowing it to fall across the root and replace that endpoint.
If that endpoint persists again, its function value is halved again.
Local order near simple roots is approximately $\sqrt[3]{3} \approx 1.442$ with one evaluation per iteration (Dowell and Jarratt's analysis).

scioxide-rootfind's `Illinois` additionally checks width every four iterations; if it has not at least halved since the previous check, it takes one bisection step and resets weight history.
This check approximately halves interval width at least every four iterations even when interpolation works poorly.
An interpolated point outside the interval interior is also replaced by one bisection step.
Weights change only the interpolation model; resulting `Bracket` retains actually evaluated endpoint values.

## Exponential linearization in Ridder's method

Ridder (`Ridder`) evaluates midpoint $m = (a + b)/2$ as well as endpoints $a$ and $b$, choosing $\lambda$ so the three values of $h(x) = f(x) e^{\lambda x}$, the function multiplied by exponential $e^{\lambda x}$, lie on a line.
Collinearity of three equally spaced points requires

$$
f(a) e^{\lambda a} + f(b) e^{\lambda b} = 2 f(m) e^{\lambda m}
$$

which gives the quadratic equation $f(b) Q^2 - 2 f(m) Q + f(a) = 0$ in $Q = e^{\lambda (m - a)}$.
Expressing this line's zero in original coordinates gives the next candidate explicitly.

$$
x_{\text{new}} = m + (m - a)\, \operatorname{sgn}\bigl(f(a) - f(b)\bigr) \frac{f(m)}{\sqrt{f(m)^2 - f(a) f(b)}}
$$

Since $f(a) f(b) < 0$, the radicand exceeds $f(m)^2$ and the fraction has magnitude below 1.
Thus $x_{\text{new}}$ lies less than $m - a$ from the midpoint, inside open interval $(a, b)$.

Each iteration evaluates the midpoint and new point, converging quadratically near smooth simple roots (Ridders, 1979).
Order per evaluation is $\sqrt 2 \approx 1.414$.
scioxide-rootfind updates the interval after midpoint evaluation and evaluates the new point only if inside that updated interval; iterations with unusable rounded candidates therefore use one evaluation.

## Brent–Dekker interpolation and safeguards

Brent–Dekker (`Brent`) switches among inverse quadratic interpolation, secant, and bisection using the same decisions as Brent's zeroin.
Each iteration maintains three points.

- $b$: current approximation, chosen so $\lvert f(b) \rvert \le \lvert f(c) \rvert$.
- $c$: opposite point with sign opposite to $f(b)$; the root lies between $b$ and $c$.
- $a$: approximation $b$ from the previous iteration.

### Interpolation candidate

If $a$ and $c$ differ, interpolate $x$ as a quadratic in $f$ through points $(f_a, a)$, $(f_b, b)$, and $(f_c, c)$ (inverse quadratic interpolation), taking its value at $f = 0$ as candidate.

$$
x_{\mathrm{IQI}} = \frac{f_b f_c}{(f_a - f_b)(f_a - f_c)} a + \frac{f_a f_c}{(f_b - f_a)(f_b - f_c)} b + \frac{f_a f_b}{(f_c - f_a)(f_c - f_b)} c
$$

If $a$ and $c$ coincide, construct the candidate from the secant through $b$ and $c$.
Inverse interpolation requires distinct function values; small denominators make candidates unstable.

### Conditions for accepting interpolation

Let $m = (c - b)/2$ be the bisection step and $\delta = \tfrac{1}{2}\varepsilon \lvert b \rvert$ the minimum step.
Accept interpolation step $s = x_{\mathrm{IQI}} - b$ only if both conditions below hold; otherwise use bisection step $m$.

1. $\lvert s \rvert < \tfrac{1}{2} \lvert e \rvert$: $e$ is the step two iterations earlier.
   Failure to halve step length over two iterations indicates interpolation stagnation.
2. $\lvert s \rvert < \tfrac{1}{2}(3 \lvert m \rvert - \delta)$: the candidate lies before three quarters of the interval from $b$ toward $c$.

For $\lvert e \rvert \le \delta$, or when $\lvert f(b) \rvert$ is no smaller than $\lvert f(a) \rvert$, use bisection without trying interpolation.
If the accepted step is at most $\delta$, move by $\delta$ toward $c$.
The minimum step safeguards rounding and is separate from caller tolerances.

Condition 1 ensures steps at least halve every two iterations even with consecutive interpolation.
Under these safeguards, Brent bounded evaluations by approximately $k^2$, where $k$ is the number needed for bisection.
Near simple roots with consecutive inverse quadratic interpolation, order is approximately 1.839, the real root of $x^3 = x^2 + x + 1$; consecutive secant steps give approximately 1.618.
Each iteration uses one evaluation.

### Variants

| Method | Candidates and safeguards |
|---|---|
| `Brent` | Switches inverse quadratic interpolation/secants with bisection using both conditions above |
| `Brenth` | A Brent-type method using Bus–Dekker hyperbolic interpolation instead of inverse quadratic interpolation |
| `Chandrupatla` | Accepts inverse quadratic interpolation only when position ratio $\xi$ and function ratio $\Phi$ of three points satisfy $1 - \sqrt{1 - \xi} < \Phi < \sqrt{\xi}$; otherwise bisection |
| `Toms748` | Alefeld–Potra–Shi Algorithm 748 ($k = 1$). Each cycle uses inverse cubic interpolation (quadratic Newton interpolation or secants if unavailable), a double-length secant, and bisection if the interval did not halve |

The `Chandrupatla` condition characterizes where three-point inverse quadratic interpolation is monotone over the interval with its zero inside.
`Chandrupatla` and `Toms748` move candidates into $[a + d, b - d]$ to avoid wasted evaluations near endpoints.
The margin is $d = c\,\bigl(\tau_a + \tau_r \max(\lvert a \rvert, \lvert b \rvert)\bigr)$; $\tau_a$ and $\tau_r$ are absolute/relative parts of `StepTolerance` (both default $4\varepsilon$); coefficient $c$ is 1/2 for `Chandrupatla` and 2 for `Toms748`.
If opposing margins overlap in a narrow interval, use its midpoint.
The first `Toms748` cycle uses only one endpoint secant; subsequent cycles use two or three evaluations.
Alefeld, Potra, and Shi showed the interval width itself approaches zero superlinearly near simple roots, estimating $k = 1$'s efficiency index per evaluation at approximately 1.65.
Brent's opposite point $c$ can remain fixed temporarily, allowing interval shrinkage to lag approximation convergence.
The original algorithm paper is [Alefeld–Potra–Shi Algorithm 748](https://na.math.kit.edu/alefeld/download/1995_Algorithm_748_Enclosing_Zeros_of_Continuous_Functions.pdf).

## Curvature and interval shrinkage

Solve function $f(x) = x^p - 0.2$ on interval $[0, 1]$.
Increasing exponent $p$ moves root $x^* = 0.2^{1/p}$ toward right endpoint $x = 1$, making the function flatter on the left and more sharply curved near the right endpoint.
Since $f'' > 0$, false position fixes the right endpoint.

The following cell resolves with zero tolerances and increasing iteration limits $k = 1, 2, \dots$, reading widths of `Bracket` returned by `Bisection`, `RegulaFalsi`, and `Illinois` at each iteration.
The input is exponent $p$ (2–16); outputs plot widths and tabulate widths after iteration 24.
Methods stopping before 24 iterations display their final width.

```rust
//| id: rootfind-bracket-curvature
//| ref: rootfind-bracket-curvature
//| title: "Vary curvature and compare interval shrinkage of bisection, false position, and Illinois"
//| run: reactive
//| crates: [scioxide-core, scioxide-rootfind]
//| inputs:
//|   exponent: {"type":"range","label":"Exponent p [-]","description":"Changes curvature of x^p near the right endpoint.","min":2,"max":16,"step":1,"value":6}
//| cases:
//|   - {"id":"gentle","label":"p = 2 (weak curvature)","description":"False position fixes the right endpoint, retaining width 1 − x* ≈ 0.553 after 24 iterations.","inputs":{"exponent":2}}
//|   - {"id":"steep","label":"p = 16 (sharp curvature near the right endpoint)","description":"The root approaches the right endpoint; false-position width after 24 iterations is 1 − x* ≈ 0.0957.","inputs":{"exponent":16}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"widths","path":"/rows/0/1","approx":{"value":5.96e-8,"rtol":1e-3}}
//|       - {"artifact":"widths","path":"/rows/1/1","approx":{"value":0.235,"atol":5e-4}}
//|       - {"artifact":"widths","path":"/rows/2/1","range":{"max":2.3e-16}}
//|   - case: gentle
//|     expect:
//|       - {"artifact":"widths","path":"/rows/0/1","approx":{"value":5.96e-8,"rtol":1e-3}}
//|       - {"artifact":"widths","path":"/rows/1/1","approx":{"value":0.553,"atol":5e-4}}
//|   - case: steep
//|     expect:
//|       - {"artifact":"widths","path":"/rows/1/1","approx":{"value":0.0957,"atol":5e-5}}
//|       - {"artifact":"widths","path":"/rows/2/1","range":{"max":2.3e-16}}
use scioxide_core::{Budget, Interval, RealScalar, ResidualTolerance, StepTolerance};
use scioxide_rootfind::{
    RootResult, RootTermination, ScalarFn, ScalarRootInput, ScalarRootMethod,
    ScalarRootOptions, ScalarRootSolver,
};

// Solve f(x) = x^p − 0.2 on [0, 1]. Root 0.2^{1/p} approaches right endpoint 1 as p increases.
let p = exponent.round() as i32;
let function = ScalarFn::new(|x: f64| Ok(RealScalar::powi(x, p) - 0.2));
let input = ScalarRootInput::Bracket(Interval::new(0.0_f64, 1.0).map_err(|e| e.to_string())?);
// With zero tolerances, inspect returned Bracket width at iteration limit k.
let exhaustive = ScalarRootOptions::default()
    .with_residual_tolerance(ResidualTolerance::new(0.0, 0.0).map_err(|e| e.to_string())?)
    .with_step_tolerance(StepTolerance::new(0.0, 0.0).map_err(|e| e.to_string())?);
let width = |result: &RootResult<f64>| -> Result<f64, String> {
    let bracket = result.bracket().ok_or("Bracketing results include an interval")?;
    Ok(bracket.upper() - bracket.lower())
};
let (mut series, mut rows) = (Vec::new(), Vec::new());
for (name, method) in [
    ("Bisection", ScalarRootMethod::Bisection),
    ("False position", ScalarRootMethod::RegulaFalsi),
    ("Illinois", ScalarRootMethod::Illinois),
] {
    let (mut points, mut omitted, mut after_24) = (vec![[0.0, 1.0]], 0_usize, 1.0);
    for k in 1..=80_usize {
        let options = exhaustive
            .clone()
            .with_max_iterations(Budget::try_from(k).map_err(|e| e.to_string())?);
        let result = method
            .solve(&function, input, &options)
            .map_err(|e| e.to_string())?;
        let w = width(&result)?;
        // Count and omit zero widths (observed exact zeros), which cannot appear on logarithmic axes.
        if w > 0.0 {
            points.push([result.iterations() as f64, w]);
        } else {
            omitted += 1;
        }
        if result.iterations() <= 24 {
            after_24 = w;
        }
        // At 1 ulp, intervals stop with Stagnation and cannot shrink further.
        if result.termination() != RootTermination::IterationLimit {
            break;
        }
    }
    series.push(
        serde_json::json!({"name": name, "points": points, "style": {"showSymbol": false}}),
    );
    rows.push((name, after_24, omitted));
}
emit_line_chart!(
    &series,
    options = &serde_json::json!({
        "xLabel": "Iteration k [count]",
        "yLabel": "Bracketing interval width [-]",
        "yType": "log",
        "xMin": 0.0,
        "xMax": 80.0,
        "yMin": 1e-17,
        "yMax": 1.0
    })
);
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "Method" },
    { "key": "1", "label": "Interval width after 24 iterations [-]", "type": "number", "format": sci3 },
    { "key": "2", "label": "Omitted zero-width points [count]", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "widths" })
);
```

Bisection widths halve every iteration independently of $p$, reaching $2^{-24} \approx 5.96 \times 10^{-8}$ after 24 iterations.
False position leaves right endpoint $x = 1$ ($f(1) = 0.8$) unchanged; widths after 24 iterations are 0.553 at $p = 2$, 0.235 at $p = 6$, and 0.0957 at $p = 16$, staying near $1 - x^*$.
Widths remain unchanged until the left endpoint approaches the root to rounding accuracy; an interpolated point then falls right of the root, updating the right endpoint for the first time and abruptly reducing width to 1–2 ulp.
If interpolation coincides with the left endpoint, midpoint replacement halves the interval once for $p = 6$ and twice for $p = 16$ before the drop.
These drops occur at iteration 40 for $p = 2$, 65 for $p = 6$, and 74 for $p = 16$.
The analysis's $C$ is approximately 0.38, 0.54, and 0.58 for $p = 2$, 6, and 16, consistent with slower linear convergence as curvature increases.
Illinois reduces the right endpoint's weight and replaces endpoints, shrinking widths to 1–2 ulp within 18 iterations for every $p = 2$–16.
Zero-width points from exact observed zeros are omitted from logarithmic plots and counted in the table.

## Evaluations with default stopping criteria

The following cell solves the same $f(x) = x^p - 0.2$ using eight bracketing methods, tabulating termination, iterations, function evaluations, discrepancies from closed-form root $0.2^{1/p}$, and final widths.
Methods switch at runtime through `ScalarRootMethod`.
Inputs are exponent $p$ and acceptance mode: `width` uses `ScalarRootOptions::default()` (width acceptance), while `residual` adds `with_residual_scale(1.0)`.
The latter accepts $\lvert f \rvert \le \sqrt{\varepsilon} \times 1$ as `ResidualTolerance` in addition to width-based acceptance.
Evaluation counts include the two initial endpoints.
The final outcome is satisfied if all eight methods terminate successfully (true `is_success()`), or partial if any stops before acceptance, with Brent termination and evaluation counts.

```rust
    outcome
        .status(brent.termination().to_string())
        .diagnostic("Brent function evaluations", brent_evaluations, None)
        .diagnostic("Maximum discrepancy from closed-form root", largest_error, None)
);
```

With defaults ($p = 6$, `width`), all methods terminate with `BracketTolerance`, differing from the closed-form root by at most $1.2 \times 10^{-16}$.
Bisection uses 52 function evaluations, false position 67, Illinois/Brent/Brenth/Ridder 12 each, Chandrupatla 11, and TOMS 748 15.
Ridder uses 12 evaluations in five iterations and TOMS 748 15 in seven; comparing iterations alone undervalues methods using more evaluations per iteration.
Varying $p$ over 2–16 gives 10–13 evaluations for Brent/Brenth/Chandrupatla and 12–17 for TOMS 748, versus 42–76 for false position.
Every method returns the endpoint with smaller $\lvert f \rvert$, so position error does not exceed final interval width.

Ridder uses 49 iterations/57 evaluations at $p = 4$ and 39/46 at $p = 13$, close to bisection.
Candidates mainly fall left of the root: the left endpoint reaches rounding agreement in five or six iterations, but midpoint evaluations account for most right-endpoint movement.
Once the left endpoint matches the root, candidates coincide with it outside the interior, leaving one midpoint evaluation per iteration and only bisection-rate halving.
Quadratic convergence of approximate points cannot accelerate the width-based criterion.

Selecting `residual` reduces evaluations at $p = 6$ to 9–10 for Brent-type methods, 24 for bisection, and 34 for false position.
However, closed-form discrepancies grow to $1.7 \times 10^{-9}$ for bisection and $7.6 \times 10^{-9}$ for false position, whose width remains 0.24.
Dividing residual criterion $\sqrt{\varepsilon} \approx 1.5 \times 10^{-8}$ by root slope $f'(x^*) = p\,x^{*\,p-1} \approx 1.57$ estimates position errors up to order $10^{-8}$, agreeing with observations.
For residual acceptance, specify a suitable criterion through `with_residual_tolerance` and independently assess position accuracy with $\lvert f \rvert / \lvert f' \rvert$ and interval width.

## Summary

Under continuity, bracketing methods preserve intervals containing roots; bisection reduces position error to at most $\delta_x$ in $\lceil \log_2(w_0/\delta_x) \rceil$ iterations.
False position fixes an endpoint and converges linearly without shrinking intervals when $f''$ has fixed sign; use Illinois, Ridder, Brent, or variants in practice.
Compare function evaluations rather than iterations: for $x^p - 0.2$, Brent-type methods used 10–13 evaluations versus 52 for bisection.
Default acceptance uses interval width; returned `Bracket` records evaluated signs rather than an interval-arithmetic proof.
Without a known bracket, construct one first with `find_bracket` in [Finding and revalidating a bracket](../bracket-search/).
