The mathematical pages in this chapter cover iterative methods for equations $f(x) = 0$ ($x \in \mathbb{R}$ or $\mathbb{C}$), $\mathbf{F}(\mathbf{x}) = \mathbf{0}$ ($\mathbf{x} \in \mathbb{R}^n$), and polynomials $p(z) = 0$.
Many methods combine a mechanism preserving the existence of a root (a sign-changing interval) with a local model that converges rapidly near a root (Taylor expansion or interpolation).
Notation, convergence order, residual and position error, and stopping criteria have the same meaning on every page.

## Notation

| Symbol | Meaning |
|---|---|
| $x^*$, $\hat x$ | True root and computed approximation |
| $e_k = x_k - x^*$ | Error at iteration $k$ |
| $[a_k, b_k]$, $w_k = b_k - a_k$ | Bracketing interval and its width |
| $J(\mathbf{x}) = \partial \mathbf{F}/\partial \mathbf{x}$ | Jacobian matrix |
| $p$ | Convergence order (defined below) |
| $\varepsilon$ | Machine epsilon ($2^{-52}$ for binary64), the same quantity as $\epsilon_{\mathrm{mach}}$ in [Numerical notation and terminology](../../reference/) |
| $\varepsilon_{\mathrm{res}}$, $\varepsilon_{\mathrm{step}}$ | Tolerances on residuals (function units) and coordinate changes (variable units) |

## Convergence order and evaluation efficiency

An iteration $x_k \to x^*$ converges with order $p \ge 1$ if, for some constant $C > 0$ ($C < 1$ when $p = 1$), sufficiently large $k$ satisfy:

$$
\lvert e_{k+1} \rvert \le C \lvert e_k \rvert^p
$$

$p = 1$ is called linear convergence, $p = 2$ quadratic convergence, and convergence for which $\lvert e_{k+1} \rvert / \lvert e_k \rvert \to 0$ is called superlinear.
For $p > 1$, the number of correct digits grows approximately $p$-fold per iteration.
This is a local property near a root; behavior for distant initial guesses must be examined separately.

Comparing methods also requires considering the cost of one iteration.
A method using $w$ function (or derivative) evaluations per iteration has an order per evaluation of $p^{1/w}$ (Ostrowski's efficiency index).
If a derivative evaluation costs the same as a function evaluation, Newton's method ($p = 2$, $w = 2$) has $\sqrt 2 \approx 1.414$, while the secant method ($p \approx 1.618$, $w = 1$) has $1.618$, making the secant method faster per evaluation.
scioxide-rootfind results count function, first-derivative, and second-derivative evaluations separately, allowing this comparison to be checked empirically.

## Residual and position error

The residual $f(\hat x)$ can be computed, but the desired quantity is the position error $\hat x - x^*$.
By the mean value theorem, for some $\xi$ between $\hat x$ and $x^*$,

$$
f(\hat x) = f(\hat x) - f(x^*) = f'(\xi)\,(\hat x - x^*)
$$

so near a simple root ($f'(x^*) \ne 0$), $\lvert \hat x - x^* \rvert \approx \lvert f(\hat x) \rvert / \lvert f'(x^*) \rvert$.
$1/\lvert f'(x^*) \rvert$ is the amplification factor from function-value errors to root position, called the root's (absolute) condition number.

Floating-point evaluation has an error of order $\delta$ even near a root.
Consequently, within a region of width approximately $2\delta / \lvert f'(x^*) \rvert$ where $\lvert f \rvert \le \delta$, the sign of computed $f$ is largely indeterminate, and no root-finding method can determine the root position more finely.
At a root of multiplicity $m$, $f(x) \approx f^{(m)}(x^*)(x - x^*)^m / m!$, so this region widens to order $(m!\,\delta / \lvert f^{(m)}(x^*) \rvert)^{1/m}$.
For example, when $\delta \approx 10^{-16}$ and $m = 4$, the position can be determined only to order $10^{-4}$.
Conversely, at roots with large $\lvert f'(x^*) \rvert$, the residual can look large even when the position is correct to rounding error.

`ScalarRootOptions` configures `ResidualTolerance` in function units separately from `StepTolerance` in coordinate units.
The scale for the relative residual criterion can be specified as a positive value in function units with `with_residual_scale`.
The general distinctions among errors, tolerances, and residuals are covered in [Scaling theory for tolerances and residuals](../../concepts/tolerances-and-residuals/) and [Floating-point numbers and condition numbers](../../concepts/floating-point-and-conditioning/).

## Default stopping criteria for methods in one variable

`ScalarRootOptions::default()` applies the following criteria by method type.

| Method type | Default success criterion | Termination reason |
|---|---|---|
| All methods | Evaluated function value is exactly 0 | `ResidualTolerance` |
| Bracketing and safeguarded methods | Interval width $b - a \le 4\varepsilon + 4\varepsilon \max(\lvert a \rvert, \lvert b \rvert)$ | `BracketTolerance` |
| Methods without a bracket (real or complex) | Step $\lvert x_{k+1} - x_k \rvert$ meets the same coordinate tolerance, and $\lvert f(x_{k+1}) \rvert \le \sqrt{\varepsilon}\, r_0$ | `StepTolerance` |

$r_0$ is the maximum $\lvert f \rvert$ at the initial points (interval endpoints for bracketing methods) and remains fixed during the solve.
By default, bracketing methods accept based only on interval width without checking the residual.
Changing the settings changes acceptance as follows.

- Explicitly setting `with_residual_tolerance` makes methods without brackets accept based only on the residual, regardless of step size (`ResidualTolerance`).
  For bracketing methods, residual-based acceptance is added to interval-width acceptance.
  Both are also checked at the initial points.
  The absolute criterion uses function units; the relative criterion multiplies the `with_residual_scale` scale or, if absent, $r_0$.
- For bracketing methods, supplying only `with_residual_scale` also enables residual acceptance with relative $\sqrt{\varepsilon}$ and absolute 0.
  For methods without brackets, this scale replaces $r_0$ in the residual condition for `StepTolerance`.
- `with_step_tolerance` changes both the interval-width and step-size criteria.

Unsuccessful termination reasons are as follows.

- `IterationLimit`: the iteration limit was reached (default 100, changed with `with_max_iterations`).
- `Stagnation`: for bracketing methods, no representable point remains inside the interval.
  For methods without brackets, a point recurred, a small step failed to reduce the residual, or a zero derivative or interpolation denominator prevented constructing a step.
- `ComplexStepRequired`: parabolic interpolation in real `Muller` requested a complex point.
- `WorkLimit`, `Cancelled`, `TimeLimit`: stopped at a `SolveBudgets` limit, cancellation, or deadline.

These cases also return results in `Ok`, but the values are unconverged candidates.
The point returned at an iteration limit or stagnation is the best observation so far (the endpoint with smaller $\lvert f \rvert$ for bracketing and safeguarded methods).
Systems, Newton–Krylov methods, fixed points, polynomials, continuation, and special-function zeros each have their own authoritative termination reason, explained on their respective pages.

## Bracket records

Bracketing and safeguarded methods return `Bracket` through `RootResult::bracket()`.
This records the last evaluated interval endpoints and function values, constructed only from an endpoint that is exactly zero or endpoints with strictly opposite signs.
It is returned at iteration limits, stagnation, and budget limits as well as on success.
Assuming continuity, it supports the existence of a root in the interval, but records floating-point evaluated signs rather than a proof using interval arithmetic.
The chapter [scioxide-validated: interval arithmetic with guaranteed containment](../../scioxide-validated/) covers proofs of existence and uniqueness using outward rounding.

## Evaluation counts and workspaces

Function and derivative evaluations and iterations are counted in the result's `counts()`; scioxide-core's `SolveBudgets` and execution contexts provide limits and cancellation.
Numerical-difference probe points also count as function evaluations.
Function evaluations are counted under role `EvaluationRole::Function` by default; `ScalarRootOptions::with_evaluation_role` can change this to another role (for example, `Event` for an inner root solve locating an event).
Analytic derivatives are counted as `Jacobian` and `Hessian` even if the role changes, and evaluations in all roles share the same limit.
Scalar methods use only fixed-size state and accept no external workspace.
For systems and fixed-point methods, reusing a prepared workspace (such as `SystemWorkspace` or `FixedPointWorkspace`) avoids reallocating memory across repeated solves.
Workspaces do not retain a solution continuation; every call starts a new solve.

## Summary

Convergence order is a local property near a root, so include the evaluations per iteration when comparing methods.
Convert residual to position error with $\lvert f \rvert / \lvert f' \rvert$; with evaluation rounding error $\delta$, the root cannot be determined more finely than width $2\delta / \lvert f' \rvert$.
By default, bracketing methods accept by interval width, while methods without brackets require both a small step and residual reduction; `with_residual_tolerance` and `with_residual_scale` change this behavior.
Determine success solely from the termination reason and treat bracket records as evidence under a continuity assumption.
