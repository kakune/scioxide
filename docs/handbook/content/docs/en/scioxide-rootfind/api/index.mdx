`scioxide-rootfind` finds real/complex one-variable roots, nonlinear-system solutions, fixed points, and all polynomial roots.
It also traces parameterized solution branches by continuation, finds additional solutions by deflation, and computes indexed special-function zeros.
This guide selects items by purpose and groups all 128 public items into tables.
Item-name links point to the version 0.1.0 API reference on docs.rs.

scioxide-differentiate provides derivative-source policies (`DerivativeStrategy`), scioxide-linalg vectors/matrices/iterative linear solvers (such as `GmresSolver`), and scioxide-poly basis-aware polynomials (`ApproxPolynomial`).
Look these up in their chapters' API guides.

## Type relationships

- Problems: supply real one-variable functions through `ScalarFunction` (closures through `ScalarFn` and others), complex functions through `ComplexScalarFunction`.
  Dense-system methods accept `DenseJacobian`, adding optional dense Jacobians to scioxide-core's `ResidualOperator` (closures use `ResidualFn`).
  Fixed-point methods accept `ResidualOperator`.
  Newton–Krylov uses `ResidualOperator` (finite-difference $Jv$ actions) or `JacobianOperator` (supplied actions); continuation/deflation uses `JacobianOperator` (closures `ResidualFn::with_jvp`, maps with final parameter input `ResidualFn::with_parameter`).
- Methods and initialization: one-variable methods implement `ScalarRootSolver` (`ComplexRootSolver` for complex numbers), with associated `Initialization` distinguishing inputs (`Interval`, guesses, two/three points, `SafeguardedInitialGuess`).
  Errors such as passing a guess to bracketing methods are rejected at compile time.
  Runtime-selected `ScalarRootMethod` rejects initialization mismatches at runtime with `InvalidInput`.
- One-call functions: `find_root`, `find_bracket`, `solve_system`, `fixed_point`, `polynomial_roots`, and `special_zeros` accept problems (closures or coefficients) and solve with defaults.
  Answers return only on success; other termination gives `ConvergenceFailure` (limit-specific kinds for limits, otherwise `Stagnation`), `ExecutionStopped`, or `NumericalInstability` errors.
- Method objects: systems, Newton–Krylov, fixed points, and continuation first create immutable validated settings values (such as `NewtonSystem`, `NewtonKrylovSolver`, `FixedPointSolver`, `Continuation`), reusable across solves.
  Polynomial and special-zero methods have no such objects; `polynomial_roots_with_options` and `special_zeros_with_options` take settings per call.
- Workspaces: one-variable methods and bracket searches take no external workspace and allocate nothing during solving.
  Method objects provide owned-result `solve` (`follow` for continuation), which allocates, and output-writing `solve_into` using prepared outputs/workspaces.
  For writing APIs, query capacity through `workspace_requirements`, reserve with `try_reserve`, then reuse outputs/workspaces.
  Polynomial/special-zero writing APIs are `polynomial_roots_into` and `special_zeros_into`, with workspace construction through `PolynomialRootWorkspace::workspace(degree, &options)` and `SpecialZeroWorkspace::workspace(count, &options)`.
  Workspaces retain solve-epoch state and last attempt records (`last_attempt()`), so callers create no solution identifiers.
  Continuation progress (accepted points, tangents, history) resides separately in caller-owned `ContinuationState`.
- Results: scalar `RootResult` (complex `ComplexRootResult`), systems `SystemRootResult`, Newton–Krylov `NewtonKrylovResult`, and fixed points `FixedPointResult`.
  Polynomials use `PolynomialRoots`/`PolynomialRootReport`; continuation per-advance `ContinuationReport` and `ContinuationState` history; deflation `DeflatedRootResult`; special zeros `SpecialZeros`/`SpecialZeroReport`.

## Minimal example: a bracketed square root

Find positive root $\sqrt{2}$ of $f(x) = x^2 - 2$ from interval $[1, 2]$ using `Brent` and compare analytic values.
Input $q$ sets the tolerance $10^q$ for both the residual $\lvert f(x) \rvert$ and the coordinate step (both absolute).
`with_residual_tolerance` enables residual acceptance, stopping once residual is at most $10^q$.
The table gives termination, roots, analytic discrepancies, residuals, iterations, function counts, and returned `Bracket` endpoints (absent for methods without brackets).
The final outcome is satisfied for true `termination().is_success()` and partial otherwise.

```rust
//| id: rootfind-api-brent-square-root
//| ref: rootfind-api-brent-square-root
//| title: "Bracketed square-root solving and termination"
//| run: reactive
//| crates: [scioxide-core, scioxide-rootfind]
//| inputs:
//|   tolerance_exponent: {"type":"range","label":"Exponent q in tolerance 10^q","description":"Residual and coordinate-step tolerances.","min":-15,"max":-3,"step":1,"value":-12}
//| cases:
//|   - {"id":"tight","label":"q = −15 (rounding level)","description":"Stops in six iterations with √2 discrepancy 2.2 × 10⁻¹⁶.","inputs":{"tolerance_exponent":-15}}
//|   - {"id":"loose","label":"q = −3 (coarse tolerance)","description":"Stops in three iterations with √2 discrepancy 1.4 × 10⁻⁴.","inputs":{"tolerance_exponent":-3}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":"ResidualTolerance"}
//|       - {"artifact":"summary","path":"/rows/0/2","approx":{"value":4.1e-14,"rtol":0.05}}
//|       - {"artifact":"summary","path":"/rows/0/3","approx":{"value":1.2e-13,"rtol":0.05}}
//|       - {"artifact":"summary","path":"/rows/0/4","equals":5}
//|       - {"artifact":"summary","path":"/rows/0/5","equals":7}
//|       - {"artifact":"summary","path":"/rows/0/6","approx":{"value":1.414213319995502,"atol":1e-15}}
//|       - {"artifact":"summary","path":"/rows/0/7","approx":{"value":1.414213562373136,"atol":1e-15}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: tight
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":"ResidualTolerance"}
//|       - {"artifact":"summary","path":"/rows/0/2","range":{"max":2.3e-16}}
//|       - {"artifact":"summary","path":"/rows/0/4","equals":6}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: loose
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":"ResidualTolerance"}
//|       - {"artifact":"summary","path":"/rows/0/2","approx":{"value":1.4e-4,"rtol":0.05}}
//|       - {"artifact":"summary","path":"/rows/0/4","equals":3}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
use scioxide_core::{EvaluationRole, Interval, RealScalar, ResidualTolerance, StepTolerance};
use scioxide_rootfind::{Brent, ScalarFn, ScalarRootOptions, ScalarRootSolver};

// Configure residual (function units) and coordinate-step (variable units) tolerances separately.
let tolerance = RealScalar::powf(10.0_f64, tolerance_exponent);
let options = ScalarRootOptions::default()
    .with_residual_tolerance(ResidualTolerance::new(tolerance, 0.0).map_err(|e| e.to_string())?)
    .with_step_tolerance(StepTolerance::new(tolerance, 0.0).map_err(|e| e.to_string())?);
let function = ScalarFn::new(|x: f64| Ok(x * x - 2.0));
let bracket = Interval::new(1.0, 2.0).map_err(|e| e.to_string())?;
let result = Brent
    .solve(&function, bracket, &options)
    .map_err(|e| e.to_string())?;
let termination = result.termination();
// Independent check: analytic √2 (f64 reference).
let x = result.point();
let error = (x - 2.0_f64.sqrt()).abs();
let evaluations = result.counts().provider(EvaluationRole::Function);
// Bracketing returns the last evaluated interval; unbracketed methods use None.
let (lower, upper) = result
    .bracket()
    .map_or((None, None), |b| (Some(b.lower()), Some(b.upper())));

let full = serde_json::json!({ "significantDigits": 16 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "Termination reason" },
    { "key": "1", "label": "Root x [-]", "type": "number", "format": full },
    { "key": "2", "label": "|x − √2| [-]", "type": "number", "format": sci2 },
    { "key": "3", "label": "Residual |f(x)| [-]", "type": "number", "format": sci2 },
    { "key": "4", "label": "Iterations [count]", "type": "integer" },
    { "key": "5", "label": "Function evaluations [count]", "type": "integer" },
    { "key": "6", "label": "Lower endpoint [-]", "type": "number", "format": full, "nullText": "None" },
    { "key": "7", "label": "Upper endpoint [-]", "type": "number", "format": full, "nullText": "None" }
]);
emit_table_with_columns!(
    columns,
    vec![(
        termination.to_string(),
        x,
        error,
        result.residual().abs(),
        result.counts().iterations(),
        evaluations,
        lower,
        upper,
    )],
    metadata = serde_json::json!({ "id": "summary" })
);

let outcome = if termination.is_success() {
    Outcome::satisfied("√2 approximation met termination criteria")
} else {
    Outcome::partial("Stopped before meeting termination criteria")
        .explanation("Interpret returned points as unconverged candidates.")
};
emit_outcome!(
    outcome
        .status(termination.to_string())
        .diagnostic("Residual |f(x)|", result.residual().abs(), None)
        .diagnostic("√2 discrepancy", error, None)
        .diagnostic("Function evaluations", evaluations as f64, None)
);
```

At default $q = -12$, five iterations (seven function evaluations including two initial endpoints) give residual $1.2 \times 10^{-13}$ and termination `ResidualTolerance`.
Root discrepancy from $\sqrt{2}$ is $4.1 \times 10^{-14}$; returned `Bracket` is $[1.414213319995502, 1.414213562373136]$ with width $2.4 \times 10^{-7}$.
Residual-based stopping leaves interval widths far greater than position error.
At $q = -15$, six iterations give discrepancy $2.2 \times 10^{-16}$; at $q = -3$, three give $1.4 \times 10^{-4}$.

With `ScalarRootOptions::default()` without `with_residual_tolerance`, bracketing stops only at interval widths (default $4\varepsilon + 4\varepsilon \max(\lvert a \rvert, \lvert b \rvert)$) or exact zeros.
Here seven iterations (nine evaluations) give `BracketTolerance` and width $2.2 \times 10^{-16}$.
To bound root position through width, leave residual tolerance unset (continuity between endpoints remains the user's assumption).

## Reading results, errors, and diagnostics

Determine success solely from `RootTermination` returned by `termination()`.
`is_success()` is true only for `ResidualTolerance`, `StepTolerance`, `BracketTolerance`, `Complete`, or `NoZeros` (a requested special-zero sequence known to be empty).
`NotStarted` (prepared output only) and `Advanced` (continuation accepted one point with more path remaining) are intermediate states, not failures.
For these termination reasons, values returned in `Ok` are unconverged or unverified candidates.

| Termination reason | Meaning |
|---|---|
| `IterationLimit`, `WorkLimit(kind)` | Reached iterations or local/outer computation limits (evaluation/iteration kind `kind`) |
| `HistoryLimit`, `StepLimit` | Continuation exhausted prepared history or retries/minimum steps |
| `Stagnation` | No progress at a finite point without success |
| `GlobalizationFailure` | Exhausted system line search, returning the last accepted point |
| `LinearFailure(_)` | Inner solver failed accuracy or recurrence checks |
| `TangentFailure` | Continuation cannot verify tangents even at minimum steps, or natural continuation reaches folds |
| `Unverified` | Finite candidates fail original-equation, separation, index, or branch checks |
| `NumericalFailure(issue)` | Polynomial all-root computation cannot finish because of breakdown or value ranges |
| `ComplexStepRequired` | Real Muller requires a complex next point |
| `Cancelled`, `TimeLimit` | Caller cancellation or injected deadline |

Errors return `Err(SciOxideError)` and classify through `kind()`.
Invalid input shapes/values, nonfinite inputs/evaluations, allocation failures, and callback errors yield `Err` for every method.
Numerical-breakdown handling differs by method.
Scalar breakdown and singular Jacobians of `NewtonSystem` without line search yield `Err`.
Polynomial all-root `polynomial_roots_with_options`/`polynomial_roots_into` return `NumericalFailure(issue)` reports inside `Ok` even after breakdown, exposing finite candidates.
Computation limits/cancellation/deadlines return unsuccessful results in `Ok` when checked points exist.
Bracket searches `find_bracket`/`find_bracket_with_options` are exceptions, always returning `Err` without obtained brackets.
One-call functions also return every unsuccessful termination through `Err`.
Errors describe failures (classification, `Argument` or `Quantity`, details) without caller identities.
Output-writing APIs such as `solve_into` preserve outputs on errors.

Distinguish estimates from guarantees.
`Bracket` records evaluated endpoint signs; continuity between endpoints remains the user's assumption.
Polynomial backward errors/conditioning, special-zero estimated errors/sign brackets, and continuation bifurcation diagnostics are numerical estimates, not interval proofs.

Inspect computational work through two accessors.
`counts()` returns direct evaluation/iteration/proposal counts through `EvaluationCounts`.
`accounting()` returns `SolveCounts` separating nested work such as inner linear solves and special evaluations; inspect totals through `accounting().total()`.

Full conventions appear in [Methods for finding roots of equations](../algorithms/).

## Summary

Problem structure determines the API.
Use `ScalarRootSolver` methods or `ScalarRootMethod` for scalar problems; `NewtonSystem`, `Broyden`, `TrustRegionSystem`, or `NewtonKrylovSolver` for systems; `FixedPointSolver` for fixed points; `polynomial_roots_with_options` for polynomials; `Continuation` for parameterized equations; `special_zeros_with_options` for special zeros.
For answers alone with defaults, use one-call `find_root`, `solve_system`, `fixed_point`, `polynomial_roots`, and `special_zeros`.
For every API, determine success from `is_success()` of `RootTermination`; even values in `Ok` remain candidates if termination is unsuccessful.
Read residuals, intervals, backward errors, and conditioning as estimates; check accuracy against analytic solutions or other methods.
Inspect arguments/defaults/errors in purpose-grouped tables and select methods through [Choosing a root-finding method](../choosing/), based on brackets, derivatives, and unknown counts.
