This table collects items solving one-variable equations $f(x) = 0$.
Methods implement `ScalarRootSolver` (`ComplexRootSolver` for complex numbers); associated `Initialization` determines initialization: brackets, single guesses, two/three points, or bracket-plus-guess.
`solve` returns `Ok(RootResult)` even at limits or stagnation; determine success through `RootTermination`.
Default one-call `find_root` and `find_bracket` return answers only on success and other termination as errors.
`Err` covers invalid inputs, nonfinite inputs/evaluations, unavailable requested derivatives, callback errors, numerical breakdown, and stopping before a checked point exists.

## Scalar execution without workspace allocation

Real/complex one-variable methods accept no external workspace.
Solves allocate nothing, including finite-difference derivative evaluations.
Owned-value API `solve` uses sequential execution contexts; `solve_scoped` runs under supplied `ExecutionContext` or parent `SolveContext`.
Configure iteration, evaluation, proposal, and nested-work limits in `ScalarRootOptions::with_budgets`.
Iterations are also limited by `with_max_iterations` (default 100).

## Runtime selection and bracket search

`ScalarRootMethod` selects methods as runtime values; `find_bracket` and `find_bracket_with_options` find sign-changing brackets for bracketing methods.
`find_bracket_with_options` takes search initialization (`BracketSearchInput`) and function direction (`BracketSearchDirection`) separately.
Monotonicity is the user's guarantee, not inferred from samples.
Additive search expands widths; multiplicative search multiplies or divides coordinates by growth factors.
Multiplicative search requires a domain excluding zero, specified through `with_domain`.
Open domain endpoints become their adjacent interior representable numbers; callbacks never run outside the domain.
Automatic additive search from one point starts with half-width $\max(\lvert x_0 \rvert, 1)$.

## Summary

One-variable methods separate bracketing, open, and safeguarded forms by initialization, preventing mismatches through types.
With known brackets, use bracketing/safeguarded methods and inspect positional ranges through returned `Bracket`.
Otherwise search with `find_bracket` before passing brackets to `find_root` or another bracketing method.
For every method, determine success with `RootTermination`, inspect iteration/evaluation details through `counts()`, and nested-inclusive counts through `accounting().total()`.
For two or more unknowns, inspect methods and workspaces in [Systems, Newton–Krylov methods, and fixed points](../systems/).
