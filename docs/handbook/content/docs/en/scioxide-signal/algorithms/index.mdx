The mathematics pages in this chapter handle uniformly sampled finite records $x[0], \dots, x[N-1]$.
All pages use the same meanings for notation, DFT normalization, frequency units, extension beyond the record, and workspace management.
This page collects these shared conventions, test signal generation, and working-precision error evaluation, then lists the questions answered by each page.

## Notation and DFT normalization

| Symbol | Meaning |
|---|---|
| $x[n]$ | Sample $n$ of a length-$N$ record ($n = 0, \dots, N-1$) |
| $h[n]$, $b_k$ | Filter impulse response, FIR coefficients |
| $T_s$, $f_s$ | Sampling period and sampling rate ($f_s = 1/T_s$) |
| $f_{\mathrm{Nyq}}$ | Nyquist frequency $f_s/2$ |
| $\omega$ | Digital angular frequency $2\pi f / f_s$ [rad/sample], or continuous-time angular frequency [rad/time] |
| $X[k]$ | Unnormalized DFT $X[k] = \sum_{n=0}^{N-1} x[n]\, e^{-2\pi i k n / N}$ |
| $\overline{z}$ | Conjugate of the complex number $z$ |
| $u$ | Unit roundoff $\varepsilon/2$ ($2^{-53}$ for `f64`) |

The forward transform is unnormalized, and the inverse transform divides by the transform length $N$.
Thus $x[n] = \frac{1}{N} \sum_{k} X[k]\, e^{2\pi i k n / N}$, and Parseval's relation is $\sum_n |x[n]|^2 = \frac{1}{N} \sum_k |X[k]|^2$.
The discrete power spectrum `power_spectrum` is $|X[k]|^2 / N$, and the cross-spectrum `cross_spectrum` is $A[k]\,\overline{B[k]} / N$; neither includes the sampling rate (they are not densities).
[Spectral estimation](spectral-estimation/) covers density and unit conversions.

## Frequency units

Frequency units differ by API.
Use the following table to align units before passing the same value to another API.

| Unit | APIs that use it | Conversion |
|---|---|---|
| Ratio to the Nyquist frequency $f \in [0, 1]$ | FIR and IIR design (`IirDomain::Digital`), frequency response of discrete-time LTI systems | $f = 1$ corresponds to $f_s/2$. The physical quantity is $f \cdot f_s / 2$ [Hz]. Evaluation point: $z = e^{i\pi f}$ |
| Angular frequency [rad/time] | Analog prototypes (`IirDomain::Analog`), continuous-time LTI systems, `lomb_scargle`, `LombScargle` | Evaluation point: $s = i\omega$. $2\pi$ times the value in cycles per time |
| Cycles per unit time | Frequencies in `welch`, `SpectralEstimatePlan`, `StftPlan`, `Waveform` | Hz when $f_s$ is given per second |
| DFT bin index $k$ | `power_spectrum`, `cross_spectrum` | Bin $k$ is $k f_s / N$ [Hz] |

Filters, zero-pole-gain representations, second-order sections, FIR designs, and state-space responses all follow these conventions and therefore return the same values at the same frequencies.
The fact that only the Lomb–Scargle method accepts angular frequency is a common source of errors when comparing its results with uniformly sampled estimates.

## Extension beyond the record

Operations that slide a window across a finite record need assumptions about values outside the record.
`SignalBoundary` represents the following three extensions and is accepted by `ConvolutionOptions`, `WaveletOptions`, and `StftOptions`.

| `SignalBoundary` | Extension | $x[-1]$ and $x[N]$ | Uses |
|---|---|---|---|
| `Zero` | Zero outside | $0$ and $0$ | Linear convolution, transient responses |
| `Periodic` | Repeats with period $N$ | $x[N-1]$ and $x[0]$ | Circular convolution, periodic signals, the same assumption as the DFT |
| `Reflect` | Reflects without repeating endpoints | $x[1]$ and $x[N-2]$ | Extension with continuous values and slopes at the endpoints, wavelet boundaries |

Defaults differ by plan.
Convolution and STFT default to `Zero`, while wavelets default to `Periodic`.
Convolution accepts `ConvolutionExtent::Circular` only in combination with `Periodic`.

APIs that do not use this type have their own extensions.
Local filters (median, Hampel, Wiener) repeat endpoint values; Savitzky–Golay selects extension with `SavitzkyGolayBoundary`, and forward–backward IIR filtering uses `IirPadding`.
Every extension only creates values beyond the record; output near the endpoints depends on the extension assumption.

## Workspace and execution contexts

One-shot functions (such as `convolve` and `welch`) allocate a plan, workspace, and output on the spot, return the result as a `Vec`, and execute sequentially with `ExecutionContext::sequential_native()`.
For repeated computations, create a plan or method object once and use the output-destination API `verb_into(inputs, output, workspace, cx)`, with caller-owned workspace and output.

`SignalRequirements` expresses the workspace size needed for one operation as element counts of three types: the sample type `T`, real `T::Real`, and complex `Complex<T::Real>`.
The plan's `workspace_requirements(request)` returns it; the request `request` is `()`, a record length, a lane count, `SignalLayout`, or a plan-specific value (`StftRequest`, `IirRequest`, `SplineRequest`).
`SignalLayout::Contiguous(n)` represents one length-$n$ record, while `SignalLayout::Axis { shape, axis }` represents all lanes along one axis of an array.
The `max` of two requirements returns the maximum of each element count and the smaller byte limit, so one allocation for the largest operation can also serve smaller operations.
Allocating or checking against requirements with `with_max_bytes(limit)` produces `ResourceLimit` if the workspace exceeds the limit.
The limit applies only during allocation and checking; execution does not inspect it.

`SignalWorkspace` holds one buffer for each of the three element types and can serve any number of plans and calls.
`SignalWorkspace::new()` creates empty workspace without allocation, `try_reserve(&requirements)` grows it only as needed, and `check(&requirements)` reports whether it is sufficient without growing it.
Workspace only grows and never shrinks; operations use only the required prefix, and its contents after a call are unspecified.
It does not grow during execution, so a call with insufficient workspace returns `DimensionMismatch`.
Peaks, ridges, Whittaker smoothing, and LTI responses use dedicated workspace types with the same `try_reserve` and `check`.

`SignalExecutionOptions` is accepted by plans whose only execution setting is the policy (`ExecutionPolicy`); the default is sequential (`Sequential`).
The policy limits the number of parallel workers, while the `ExecutionContext` passed to the call determines the actual executor.
The cells in this handbook execute sequentially on wasm32, so they pass `ExecutionContext::sequential()`.

Output-destination APIs write to output only after all validation, transforms, and scaling are complete.
A failed call leaves the caller's output unchanged and, for streams, also leaves state unchanged.

## Streaming conventions

`OverlapStream`, `PolyphaseStream`, `LocalFilterStream`, `StftAnalysisStream`, and `StftSynthesisStream` process a single record in chunks.
Each call accepts `StreamChunk`: `Partial` means more input follows, while `Final` means the record ends with that chunk.
A `Partial` call writes only output determined by the input received so far.
A `Final` call flushes pending output and closes the stream until `reset`.
Calling a closed stream produces `InvalidInput`.

Each call returns `StreamProgress`.
`consumed()` is the number of input samples consumed, `produced()` the number of output samples written, and `first_output_index()` the index in the output record of the first sample written.
`replacements()` is the number of replacement indices written by a Hampel filter stream and is 0 for other streams.
Because output lags behind input, count output positions with `first_output_index()` to avoid confusing chunk boundaries with the end of the signal.

Streams are values: save their state with `clone` and restore it without allocation with `clone_from`.
Workspace sized with `workspace_requirements(max)` serves all subsequent calls with at most `max` input samples.
IIR filters have no stream type; instead, caller-owned `IirState` holds delay values ([IIR filtering and zero phase](iir-filtering-and-zero-phase/)).

## Generating test signals

Test signals with closed-form values are useful for checking algorithms.
`Waveform` represents the following analytic waveforms, with frequency in cycles per unit time and phase $\varphi$ in radians.
For periodic waveforms, $u(t) = \operatorname{frac}(f t + \varphi / 2\pi)$ is the position within a period ($\operatorname{frac}$ denotes the fractional part).

| `Waveform` | Value |
|---|---|
| `Sine`, `Cosine` | $\sin(2\pi f t + \varphi)$, $\cos(2\pi f t + \varphi)$ |
| `Square { duty }` | $+1$ when $u < d$, otherwise $-1$ ($d \in [0, 1]$; $d = 1$ is the constant $+1$) |
| `Sawtooth { width }` | $2u/w - 1$ when $u < w$, otherwise $1 - 2(u - w)/(1 - w)$ ($w = 1/2$ gives a triangle wave) |
| `GaussianPulse { sigma }` | $e^{-(t/\sigma)^2/2} \cos(2\pi f t + \varphi)$ (exactly 0 when $\lvert t/\sigma \rvert > 64$) |
| `Chirp { initial, final_frequency, duration, law }` | $\cos\!\left(2\pi \int_0^t f(s)\, ds + \varphi\right)$ |
| `PolynomialSweep { coefficients }` | $\cos\!\left(2\pi \sum_k a_k t^{k+1}/(k+1) + \varphi\right)$ when $f(t) = \sum_k a_k t^k$ |

Choose the instantaneous frequency $f(t)$ of a swept wave (chirp) with `ChirpLaw`.
Let $f_0$ be the initial frequency and $f_1$ the frequency at time $T$ (`duration`), giving $f(0) = f_0$ and $f(T) = f_1$.
The phase is the integral of instantaneous frequency, $\Phi(t) = \int_0^t f(s)\, ds$ [cycles], and is computed in closed form.

| `ChirpLaw` | Instantaneous frequency $f(t)$ | Phase $\Phi(t)$ [cycles] |
|---|---|---|
| `Linear` | $f_0 + (f_1 - f_0)\, t/T$ | $f_0 t + (f_1 - f_0)\, t^2 / (2T)$ |
| `Quadratic { vertex_at_end: false }` | $f_0 + (f_1 - f_0)(t/T)^2$ | $f_0 t + (f_1 - f_0)\, t^3 / (3T^2)$ |
| `Quadratic { vertex_at_end: true }` | $f_0 + (f_1 - f_0)\left(1 - (1 - t/T)^2\right)$ | $f_0 t + (f_1 - f_0)\left(t^2/T - t^3/(3T^2)\right)$ |
| `Logarithmic` | $f_0 (f_1/f_0)^{t/T}$ | $f_0 T \left((f_1/f_0)^{t/T} - 1\right) / \ln(f_1/f_0)$ |
| `Hyperbolic` | $f_0 / \left(1 + (f_0/f_1 - 1)\, t/T\right)$ | $f_0 T \ln\!\left(1 + (f_0/f_1 - 1)\, t/T\right) / (f_0/f_1 - 1)$ |

The logarithmic and hyperbolic laws require nonzero $f_0$ and $f_1$ of the same sign; otherwise they produce `DomainError`.
Under the hyperbolic law the frequency diverges at times where the denominator becomes nonpositive; passing such a time returns `DomainError` (`Pole`).
Times outside $[0, T]$ are evaluated with the same law.

`waveform(w, &times)` evaluates a waveform at an arbitrary sequence of times and returns a `Vec`; times need not be increasing or uniformly spaced.
The output-destination API `waveform_into(w, &times, &mut output, cx)` writes to the first `times.len()` output elements.
Both evaluate all samples once for validation, then evaluate them again to write, so an error at any intermediate time leaves output unchanged.
`waveform_grid_into(w, origin, step, start_index, &mut output, cx)` writes values on the uniform grid $t_i = t_0 + (s + i)\,\Delta t$.
The grid constructs times from absolute indices $s + i$, so generating a long signal in chunks produces the same values as generating it all at once.
`unit_impulse_into(m, start_index, &mut output, cx)` writes a portion of a unit impulse that is 1 only at index $m$ (`output.len()` elements starting at index `start_index`), filling portions that do not contain the impulse with zeros.

The next cell generates 400 samples at $f_s = 400$ Hz of a chirp sweeping from $f_0 = 5$ Hz to $f_1 = 40$ Hz over $T = 1$ s.
It compares a sequence generated in chunks of the selected length with `waveform_grid_into` against a sequence generated all at once with `waveform`, then compares them with values computed by hand from the phase formulas above (reference values using `f64` intrinsic methods).
Inputs are the sweep law and chunk length; outputs are a table of the two differences and linked plots of the waveform and instantaneous frequency.

```rust
//| id: signal-chirp-waveform-chunks
//| ref: signal-chirp-waveform-chunks
//| title: "Generate a chirp in chunks and compare with closed-form phase"
//| run: reactive
//| crates: [scioxide-core, scioxide-signal]
//| inputs:
//|   law: {"type":"select","label":"Sweep law","description":"Choose the shape of instantaneous frequency f(t).","options":["Linear","Quadratic (vertex at start)","Quadratic (vertex at end)","Logarithmic","Hyperbolic"],"value":"Linear"}
//|   chunk: {"type":"range","label":"Chunk length [samples]","description":"Number of samples passed to waveform_grid_into at once.","min":1,"max":128,"step":1,"value":37}
//| cases:
//|   - {"id":"logarithmic","label":"Logarithmic law, one-sample chunks","description":"Generating one sample at a time still agrees with the batch sequence.","inputs":{"law":"Logarithmic","chunk":1}}
//|   - {"id":"hyperbolic","label":"Hyperbolic law","description":"Frequency rises sharply near the endpoint.","inputs":{"law":"Hyperbolic"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"agreement","path":"/rows/0/1","equals":0}
//|       - {"artifact":"agreement","path":"/rows/0/2","range":{"max":1e-11}}
//|       - {"artifact":"agreement","path":"/rows/0/3","approx":{"value":5,"atol":1e-12}}
//|       - {"artifact":"agreement","path":"/rows/0/4","approx":{"value":40,"atol":1e-12}}
//|   - case: logarithmic
//|     expect:
//|       - {"artifact":"agreement","path":"/rows/0/1","equals":0}
//|       - {"artifact":"agreement","path":"/rows/0/2","range":{"max":1e-11}}
//|   - case: hyperbolic
//|     expect:
//|       - {"artifact":"agreement","path":"/rows/0/1","equals":0}
//|       - {"artifact":"agreement","path":"/rows/0/2","range":{"max":1e-11}}
use scioxide_core::ExecutionContext;
use scioxide_signal::{ChirpLaw, Waveform, waveform, waveform_grid_into};

let (f0, f1, duration, rate) = (5.0_f64, 40.0_f64, 1.0_f64, 400.0_f64);
let n = 400_usize;
let chirp_law = match law.as_str() {
    "Quadratic (vertex at start)" => ChirpLaw::Quadratic {
        vertex_at_end: false,
    },
    "Quadratic (vertex at end)" => ChirpLaw::Quadratic {
        vertex_at_end: true,
    },
    "Logarithmic" => ChirpLaw::Logarithmic,
    "Hyperbolic" => ChirpLaw::Hyperbolic,
    _ => ChirpLaw::Linear,
};
let chirp = Waveform::Chirp {
    initial: f0,
    final_frequency: f1,
    duration,
    phase: 0.0,
    law: chirp_law,
};

// Batch generation: pass times t_n = n Δt (Δt = 1/f_s)
let step = 1.0 / rate;
let times: Vec<f64> = (0..n).map(|i| i as f64 * step).collect();
let whole = waveform(chirp, &times).map_err(|e| e.to_string())?;

// Chunked generation: write chunk elements at a time starting from absolute index start
let size = chunk.round() as usize;
let mut pieces = vec![0.0; n];
for (k, block) in pieces.chunks_mut(size).enumerate() {
    waveform_grid_into(
        chirp,
        0.0,
        step,
        k * size,
        block,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;
}

// Independent check: compute phase Φ(t) [cycles] and instantaneous frequency f(t) by hand from the table formulas
let (delta, ratio, b) = (f1 - f0, f1 / f0, f0 / f1 - 1.0);
let phase = |t: f64| match chirp_law {
    ChirpLaw::Quadratic {
        vertex_at_end: false,
    } => f0 * t + delta * t.powi(3) / (3.0 * duration * duration),
    ChirpLaw::Quadratic {
        vertex_at_end: true,
    } => f0 * t + delta * (t * t / duration - t.powi(3) / (3.0 * duration * duration)),
    ChirpLaw::Logarithmic => f0 * duration * (ratio.powf(t / duration) - 1.0) / ratio.ln(),
    ChirpLaw::Hyperbolic => f0 * duration * (b * t / duration).ln_1p() / b,
    ChirpLaw::Linear => f0 * t + delta * t * t / (2.0 * duration),
};
let frequency = |t: f64| {
    let u = t / duration;
    match chirp_law {
        ChirpLaw::Quadratic {
            vertex_at_end: false,
        } => f0 + delta * u * u,
        ChirpLaw::Quadratic {
            vertex_at_end: true,
        } => f0 + delta * (1.0 - (1.0 - u) * (1.0 - u)),
        ChirpLaw::Logarithmic => f0 * ratio.powf(u),
        ChirpLaw::Hyperbolic => f0 / (1.0 + b * u),
        ChirpLaw::Linear => f0 + delta * u,
    }
};
let chunk_gap = whole
    .iter()
    .zip(&pieces)
    .map(|(a, c)| (a - c).abs())
    .fold(0.0_f64, f64::max);
let formula_gap = whole
    .iter()
    .zip(&times)
    .map(|(a, &t)| (a - (std::f64::consts::TAU * phase(t)).cos()).abs())
    .fold(0.0_f64, f64::max);

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let fixed3 = serde_json::json!({ "fractionDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "Sweep law", "type": "string" },
    { "key": "1", "label": "Maximum batch–chunked difference [-]", "type": "number", "format": sci3 },
    { "key": "2", "label": "Maximum difference from closed form [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "f(0) [Hz]", "type": "number", "format": fixed3 },
    { "key": "4", "label": "f(T) [Hz]", "type": "number", "format": fixed3 }
]);
let rows = vec![(
    law.clone(),
    chunk_gap,
    formula_gap,
    frequency(0.0),
    frequency(duration),
)];
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "agreement" })
);

let signal: Vec<[f64; 2]> = times.iter().zip(&whole).map(|(&t, &y)| [t, y]).collect();
let law_curve: Vec<[f64; 2]> = times.iter().map(|&t| [t, frequency(t)]).collect();
emit_line_chart!(
    &vec![serde_json::json!({ "name": "Chirp x(t)", "points": signal })],
    options = &serde_json::json!({
        "xLabel": "Time t [s]",
        "yLabel": "Amplitude [-]",
        "yMin": -1.1,
        "yMax": 1.1,
        "link": { "group": "chirp-time" }
    })
);
emit_line_chart!(
    &vec![serde_json::json!({
        "name": "Instantaneous frequency f(t)",
        "points": law_curve,
        "style": { "lineType": "dashed" }
    })],
    options = &serde_json::json!({
        "xLabel": "Time t [s]",
        "yLabel": "Instantaneous frequency [Hz]",
        "yMin": 0.0,
        "yMax": 45.0,
        "link": { "group": "chirp-time" }
    })
);
```

With the default linear law, the sequence generated in chunks of 37 samples differs from the batch sequence by exactly 0 and from the values computed using closed-form phase by $2.7 \times 10^{-14}$.
For every law, the chunked–batch difference remains 0 as the chunk length varies from 1 to 128.
The difference from closed form ranges from $2.5 \times 10^{-14}$ to $4.9 \times 10^{-14}$ for the quadratic and logarithmic laws; it is 0 for the hyperbolic law because its computation order matches the hand calculation.
The linear law's phase reaches 22.5 cycles at the endpoint, so differences of about $10^{-14}$ are consistent with phase roundoff (of order $22 \times 2\pi \times u$).
The instantaneous frequency (dashed) in the lower plot passes through $f(0) = 5$ Hz and $f(T) = 40$ Hz for every law, and the oscillation rate of the waveform above follows that curve.
The time axes of the two plots are linked, allowing comparison of waveform periods and instantaneous frequency within a zoomed interval.

## Working-precision errors

Direct convolution and correlation, FIR filters, polyphase resampling, Savitzky–Golay filters, and wavelet filters compute sums of products in working precision.
For a sum of $m$ products, the absolute error in each of the real and imaginary parts of the result is bounded by

$$
\gamma_{2m+8}\, M + (2m + 8)\, \eta, \qquad \gamma_k = \frac{k u}{1 - k u}
$$


Here $M$ is the sum of absolute products, $\eta$ is the smallest positive subnormal number, and $k u < 1$ is assumed.
This bound applies to the stored coefficients and excludes errors in filter design itself.
In multilevel wavelet transforms, each level's error propagates through the absolute coefficients to the next level.

Errors in FFT-based convolution, analytic signals, Riesz transforms, and Fourier resampling are measured in norm.
They are proportional to $\varepsilon$, the operand norms, and the logarithm of the transform length, plus an underflow contribution.
As a result, components much smaller than the largest component can lose all relative accuracy or round to 0.
Inputs are scaled by powers of two only when needed, so finite results do not overflow or underflow at intermediate steps.
An error occurs if the result itself overflows.
Direct sums and FFTs need not return identical bit patterns, and accuracy must not be judged solely by the relative error of outputs with strong cancellation.

Filter and system design errors depend on the conditioning of poles and zeros.
Iterative designs (order selection, Remez exchange, pole placement, DPSS) return termination status and residuals; read them before using the result.
Each page explains the meaning of its diagnostics.

## Summary

The DFT leaves the forward transform unnormalized and divides the inverse by its length, so `power_spectrum` values are $|X[k]|^2/N$ and exclude the sampling rate.
Frequencies are passed as Nyquist ratios for FIR and IIR design and discrete-time systems, angular frequencies for continuous-time systems and the Lomb–Scargle method, and cycles per unit time for Welch, STFT, and waveforms.
Specify extension beyond the record explicitly with `SignalBoundary` or similar settings, and interpret results knowing that output near the endpoints depends on that assumption.
For repeated computations, reuse a single `SignalWorkspace` sized by the `max` of `SignalRequirements` across multiple plans, and close streaming records with `StreamChunk::Final`.
Generate test signals with the absolute indices of `waveform_grid_into` to obtain the same sequence in chunks as in a single batch.
Choose a page matching your question from the index above to examine each method's derivation and experiments.
