These tables summarize public items for time-domain convolution and correlation, streaming based on them, and resampling.
One-shot functions such as `convolve`, `correlate`, `resample`, and `resample_periodic` accept real or complex records, create plans and workspace on each call, and return results.
Plans (`ConvolutionNdPlan`, `OverlapPlan`, `PolyphasePlan`, `FourierResamplePlan`) validate shapes and transforms during preparation; their `_into` APIs use caller-owned output and workspace.
Plan execution leaves output unchanged on failure.

## Execution policies and workspace

Plans and method objects return required sizes through `workspace_requirements(request)`.
Requests are `()`, record length, lane count, `SignalLayout`, or plan-specific values.
Allocate storage before execution with `workspace(request)` or with `SignalWorkspace::default()` and `try_reserve`.
The final argument to caller-provided-output APIs `_into` is `ExecutionContext`; storage does not grow during execution.
Peaks, ridges, Whittaker smoothing, and LTI responses use dedicated workspace types.

## Summary

Use `convolve`, `convolve_circular`, or `correlate` for one-off convolution, and `resample` (rational ratios) or `resample_periodic` (periodic records) for sample-rate conversion.
Reuse a kernel-owning `ConvolutionNdPlan` for repeated kernels, multidimensional grids, cropping, or boundary settings.
For unbounded input sequences, use `OverlapPlan` and `PolyphasePlan` streams and pass `StreamChunk::Final` for the final chunk.
Spectral estimation items are in [Spectra, time–frequency analysis, and analytic signals](../spectra-and-time-frequency/), and filter design in [Filter design, minimum phase, and LTI systems](../filter-design-and-systems/).
