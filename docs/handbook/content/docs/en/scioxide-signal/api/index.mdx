`scioxide-signal` provides outputs for convolution and correlation, FIR and IIR filter design and application, resampling, windows and spectral estimation, STFT, analytic signals and Riesz transforms, minimum-phase conversion, wavelets, smoothing, feature extraction such as peaks, and state-space models.
This guide maps tasks to API items and groups all 192 public items into four tables by purpose.
Item-name links point to the version 0.1.0 API reference on docs.rs.

## APIs by purpose

| Estimate time differences | `correlate` | Signal $a$ (length $N$), reference $b$ (length $M$) | Ascending lags $-(M-1), \dots, N-1$ | [Convolution, correlation, and resampling](convolution-and-resampling/) |

## Call forms

Choose among the following forms according to the control needed over the same computation.

| Form | Examples | Accepts | Returns | Execution context |
|---|---|---|---|---|
| One-shot function | `convolve(&a, &b)`, `welch(&x, fs, m)`, `lomb_scargle(&t, &x, &omega)`, `resample(&x, up, down)`, `find_peaks(&x)`, `savitzky_golay(&x, w, p)`, `minimum_phase(&h)` | Data and a few required values | Newly allocated result | `sequential_native()` |
| Standard form | `design_iir(order, family, band, domain)`, `sos.filter(&x)`, `sos.forward_backward(&x)`, `plan.analyze(&x)`, `design_fir_remez(n, symmetry, &bands)` | Prepared values and inputs | Newly allocated result | `sequential_native()`; a new root scope for iterative design |
| Options form | `find_peaks_with_options(&x, options)`, `minimum_phase_with_options(&h, options)`, `design_fir_remez_with_options(…, options)`, `select_iir_order_with_options(…, options)`, `place_poles_with_options(&poles, options)` | Inputs, then options last | Newly allocated result | `sequential_native()` |
| Caller-provided-output API | `plan.power_into(&x, &mut out, &mut ws, cx)`, `filter.filter_into(&x, &mut y, &mut state, &mut ws, cx)`, `plan.analyze_axis_into(view, axis, out, &mut ws, cx)` | Input, output, workspace, then context last | Writes to output | Supplied context |
| Scoped API | `design_iir_scoped(…, scope)`, `select_iir_order_scoped(…, scope)`, `design_fir_remez_scoped(…, scope)`, `sos.to_zpk_scoped(scope)`, `place_poles_scoped(…, scope)` | Options-form arguments, then execution context or `SolveContext` last | Value | One epoch of the supplied scope |

- One-shot functions: use for one-off calculations needing only a result.
  Conventional settings are fixed per function and documented in rustdoc and the tables.
  For example, `welch` uses a periodic Hann window with half overlap, `resample` uses centered alignment, and `savitzky_golay` uses polynomial endpoint handling from complete endpoint windows.
- Plans and method objects: retain values that perform preparation once for repeated computations.
  Plans such as `ConvolutionNdPlan`, `SpectralEstimatePlan`, `StftPlan`, and `WaveletPlan` compute FFTs or coefficients during preparation.
  Method objects (`IirFilter`, `SymmetricFilter`, `SplineFilter`, `LombScargle`) retain only validated coefficients or settings, performing no computation at construction while sharing the same execution forms as plans.
  `Window` and `DpssTapers` hold computed samples.
  All are immutable; callers own state, outputs, and workspace.
  There is no global cache.
- Workspace queries: plans and method objects return required sizes through `workspace_requirements(request)`.
  Requests are `()`, record length, lane count, `SignalLayout`, or plan-specific values (`StftRequest`, `IirRequest`, `SplineRequest`).
  Allocate before execution with `workspace(request)` or `SignalWorkspace::try_reserve`; workspace does not grow during execution.
  Peaks, ridges, Whittaker, and LTI responses use dedicated workspace types.
  Insufficiency gives `DimensionMismatch`.
- Array-axis processing: a single-record plan's `verb_axis_into(input, axis, output, workspace, cx)` methods treat each lane of one array axis as a record.
  Shape and lane count come from the input view on each call; pass `SignalLayout::Axis` or lane count in workspace requests.
- Atomic writes: output is written only after all validation, transformation, and scaling succeed, leaving caller output unchanged on failure.
  Streams also retain their state on failure.
- Streaming: `LocalFilterStream`, `OverlapStream`, `PolyphaseStream`, `StftAnalysisStream`, and `StftSynthesisStream` borrow plans and own state.
  `IirFilter` stores delays in the caller's `IirState`.
  `clone` creates a snapshot; `clone_from` restores state without allocation.
  `StreamChunk::Final` marks the end.
- Frequency units: `power_spectrum` and `cross_spectrum` use DFT bins; `welch`, `SpectralEstimatePlan`, `StftPlan`, and waveforms use cycles per unit time; `lomb_scargle`, `LombScargle`, and continuous LTI systems use radians per unit time; discrete LTI systems and digital FIR and IIR filters use ratios to Nyquist frequency.
- Execution contexts: caller-provided-output and scoped APIs accept `ExecutionContext` (executor, cancellation, deadline) last; scoped APIs also accept an outer solver's `SolveContext`.
  Only sequential execution is available in wasm.

## Minimal runnable example

Linear convolution of the three-point input $x = [1, 2, 3]$ and two-point kernel $h = [1, 1]$ is $[1, 3, 5, 3]$ of length $3 + 2 - 1 = 4$.
The following cell compares `convolve` with these values.

```rust
//| id: signal-api-linear-convolution
//| title: "Linear convolution with a two-point kernel and full output length"
//| run: button
//| crates: [scioxide-signal]
use scioxide_signal::convolve;

let signal = [1.0_f64, 2.0, 3.0];
let kernel = [1.0_f64, 1.0];
let output = convolve(&signal, &kernel).map_err(|e| e.to_string())?;

// Compare each sample with the manually computed [1, 3, 5, 3]
let expected = [1.0, 3.0, 5.0, 3.0];
let rows: Vec<(usize, f64, f64, f64)> = output
    .iter()
    .zip(expected)
    .enumerate()
    .map(|(n, (&y, e))| (n, y, e, (y - e).abs()))
    .collect();
emit_table_with_columns!(["Index n", "convolve", "Manual computation", "Absolute error"], rows);
```

Output has 4 samples, all agreeing with the manual computation (zero error).
`convolve` is a one-shot function creating a `ConvolutionNdPlan` and workspace internally.
Longer inputs may make the plan switch from direct summation to a real FFT, while output length and value conventions remain the same.

## Interpreting results, errors, and diagnostics

Failures return `SciOxideError`; read classification through `e.kind()` (`SciOxideErrorKind`) and details through `e.view()`.
Common classifications in this chapter follow.

| Classification | Main causes |
|---|---|
| `InvalidInput` | Empty records, out-of-range parameters (window parameters, band edges, thresholds), input length differing from the plan, stream calls after the final chunk |
| `DimensionMismatch` | Insufficient output, workspace, or state; input length or shape mismatches (`convolve_circular`, `cross_spectrum`) |
| `NonFinite` | NaN or infinity in inputs or coefficients |
| `DomainError` | Normalization with zero sum or energy, coherence with zero autospectrum, minimum phase of a zero signal, Lomb–Scargle with constant input |
| `NumericalInstability` | Unrepresentable results (overflow), numerical rank loss in least squares, failed self-checks (dual windows or zero-pole conversions) |
| `SizeOverflow`, `AllocationFailure`, `ResourceLimit` | Overflow in workspace size calculation, allocation failure, exceeding `SignalRequirements::with_max_bytes` limits |
| `ConvergenceFailure` | Standard `select_iir_order` requires a degree beyond `usize`; `design_fir_remez` exchanges reach a limit or stagnate; `place_poles` poles fail tolerance. Scoped APIs also return this at scope limits |
| `ExecutionStopped` | Cancellation or deadline stops in scoped design APIs |

Even an `Ok` result needs diagnostic checks for quality.

- `FirDesign::termination()` is the sole termination status for FIR design.
  Options and scoped Remez forms return finite coefficients with `IterationLimit` or `ExchangeStalled` even without convergence.
  `condition_estimate()` estimates the 1-norm condition number of the normal equations in least-squares design and is `None` for other designs.
- `IirOrderReport::termination()` is degree-selection termination; options and scoped forms may return `OrderLimit` stopped at maximum degree.
- `IirDesign::stability_margin()` and `PoleZeroGain::stability_margin()` measure pole distance from the stability boundary; positive values mean strict stability.
- `MinimumPhaseDiagnostics`, `SmoothingDiagnostics`, `OverlapDiagnostics`, and `ConvolutionSelection` are estimates or decision diagnostics, not error guarantees.
- `PolePlacementReport` independently computes achieved poles and returns residuals against requested poles.

## Summary

Select items for your task from the API tables and begin with a one-shot function.
Use options forms to change settings; for repeated computation, retain plans or method objects and workspace, then use caller-provided-output APIs to eliminate allocations.
Use scoped APIs to apply outer-solver limits or cancellation to iterative designs.
Result conventions (correlation lag ordering, spectral normalization, frequency units) are item-specific; check the specification columns.
Classify errors with `kind()` and read termination and diagnostics before using `Ok` results.
See [Mathematics and algorithms](../algorithms/) for mathematical foundations and [Examples](../examples/) for use with independent checks.
