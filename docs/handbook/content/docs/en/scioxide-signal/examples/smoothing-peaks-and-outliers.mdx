Checking results through an independent computational path before applying signal-processing functions to measured data helps reveal convention mismatches early.
Independent paths include direct summation from the definition, conservation of energy, and geometric hand calculations.
This page compares Gaussian-kernel smoothing, the geometry of flat-topped peaks (plateaus), and streaming Hampel filtering with closed-form values or separate calculations.

## Gaussian-kernel smoothing and Parseval's relation

A basic operation for reducing high-frequency noise is linear convolution with the normalized Gaussian kernel

$$
h[j] = \frac{1}{Z} \exp\left( -\frac{j^2}{2\sigma^2} \right), \qquad j = -K, \dots, K
$$


The normalization constant $Z = \sum_{j=-K}^{K} \exp(-j^2/(2\sigma^2))$ makes the DC gain 1 ($\sum_j h[j] = 1$).

The linear convolution $y = x * h$ of a signal $x$ of length $N$ and a kernel $h$ of length $M = 2K + 1$ has length $N + M - 1$ and satisfies the following two relations.

1. Preservation of the output sum.
   Because the kernel sums to 1, the sum over the full output, including the zero extension at both ends, equals the input sum.

   $$
   \sum_{n=0}^{N+M-2} y[n] = \sum_{n=0}^{N-1} x[n] \sum_{j=-K}^{K} h[j] = \sum_{n=0}^{N-1} x[n]
   $$

2. Parseval's relation.
   The sum of $P_k = |X_k|^2 / N$ over all $N$ bins returned by `power_spectrum` equals the sum of squares in the time domain.

   $$
   E_x = \sum_{n=0}^{N-1} x[n]^2 = \sum_{k=0}^{N-1} P_k
   $$

Because the magnitude of the kernel's frequency response satisfies $|H(\omega)| \le \sum_j |h[j]| = 1$, the smoothed output energy $E_y = \sum_n y[n]^2$ does not exceed $E_x$.

The next cell smooths a Gaussian pulse of width 4 samples and length 64 with a 17-point ($K = 8$) kernel.
Because `convolve` chooses the less expensive of direct summation and the FFT, compare its result with a double-loop sum from the definition.
The table pairs SciOxide's values with independent calculations for output length, preservation of the sum, and Parseval's relation, and adds the maximum difference from direct summation and the energy ratio.
The chart plots the input (dashed) and the output, shifted by the kernel center of 8 samples to share the same time axis.

```rust
//| id: signal-convolution-energy
//| ref: signal-convolution-energy
//| title: "Check Gaussian-kernel smoothing against direct summation and Parseval's relation"
//| run: reactive
//| crates: [scioxide-signal]
//| inputs:
//|   filter_width: {"type":"range","label":"Kernel width σ [samples]","description":"Standard deviation of the Gaussian kernel (smoothing strength).","min":0.5,"max":4,"step":0.25,"value":1.5}
//|   pulse_position: {"type":"range","label":"Input center position [samples]","description":"Index of the Gaussian pulse peak.","min":16,"max":48,"step":2,"value":28}
//| cases:
//|   - {"id":"wide-kernel","label":"σ = 4","description":"The peak falls and the tails broaden, while the sum is preserved.","inputs":{"filter_width":4}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"checks","path":"/rows/0/1","equals":80}
//|       - {"artifact":"checks","path":"/rows/1/3","range":{"max":1e-12}}
//|       - {"artifact":"checks","path":"/rows/2/3","range":{"max":1e-12}}
//|       - {"artifact":"checks","path":"/rows/3/3","range":{"max":1e-14}}
//|       - {"artifact":"checks","path":"/rows/4/1","range":{"max":1.0}}
//|   - case: wide-kernel
//|     expect:
//|       - {"artifact":"checks","path":"/rows/1/3","range":{"max":1e-12}}
//|       - {"artifact":"checks","path":"/rows/4/1","range":{"max":1.0}}
use scioxide_signal::{convolve, power_spectrum};

let sig12 = serde_json::json!({ "significantDigits": 12 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
// Gaussian pulse of length 64 and width 4 samples (reference values using f64 standard functions).
let n = 64_usize;
let signal: Vec<f64> = (0..n)
    .map(|i| (-0.5 * ((i as f64 - pulse_position) / 4.0).powi(2)).exp())
    .collect();
// 17-point Gaussian kernel (radius 8), normalized to sum to 1.
let mut kernel: Vec<f64> = (-8..=8)
    .map(|j| (-0.5 * (j as f64 / filter_width).powi(2)).exp())
    .collect();
let mass: f64 = kernel.iter().sum();
kernel.iter_mut().for_each(|v| *v /= mass);

// Linear convolution (chooses the less expensive of direct summation and the FFT).
let output = convolve(&signal, &kernel).map_err(|e| e.to_string())?;
let spectrum = power_spectrum(&signal).map_err(|e| e.to_string())?;

// Independent check: direct summation from the definition, and the time-domain sum and sum of squares.
let mut reference = vec![0.0; signal.len() + kernel.len() - 1];
for (i, &a) in signal.iter().enumerate() {
    for (j, &b) in kernel.iter().enumerate() {
        reference[i + j] += a * b;
    }
}
let direct_error = output
    .iter()
    .zip(&reference)
    .map(|(a, b)| (a - b).abs())
    .fold(0.0_f64, f64::max);
let energy = |v: &[f64]| v.iter().map(|x| x * x).sum::<f64>();
let (input_sum, output_sum) = (signal.iter().sum::<f64>(), output.iter().sum::<f64>());
let spectral_energy: f64 = spectrum.iter().sum();
let expected_len = (signal.len() + kernel.len() - 1) as f64;

let rows = vec![
    (
        "Output length and N + M − 1 [samples]",
        Some(output.len() as f64),
        Some(expected_len),
        Some(0.0),
    ),
    (
        "Output sum Σy and input sum Σx",
        Some(output_sum),
        Some(input_sum),
        Some((output_sum - input_sum).abs()),
    ),
    (
        "Spectrum sum ΣP_k and E_x",
        Some(spectral_energy),
        Some(energy(&signal)),
        Some((spectral_energy - energy(&signal)).abs()),
    ),
    ("Maximum difference between convolve and direct summation", None, None, Some(direct_error)),
    (
        "Energy ratio E_y / E_x",
        Some(energy(&output) / energy(&signal)),
        None,
        None,
    ),
];
let columns = serde_json::json!([
    { "key": "0", "label": "Check" },
    { "key": "1", "label": "SciOxide value", "type": "number", "format": sig12, "nullText": "—" },
    { "key": "2", "label": "Independent calculation", "type": "number", "format": sig12, "nullText": "—" },
    { "key": "3", "label": "Absolute difference", "type": "number", "format": sci3, "nullText": "—" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "checks" })
);

// Shift by the kernel center (8 samples) to overlay on the input time axis.
let input_curve: Vec<[f64; 2]> = signal
    .iter()
    .enumerate()
    .map(|(i, &x)| [i as f64, x])
    .collect();
let output_curve: Vec<[f64; 2]> = output
    .iter()
    .enumerate()
    .map(|(i, &y)| [i as f64 - 8.0, y])
    .collect();
emit_line_chart!(
    &vec![
        serde_json::json!({
            "name": "Input x[n]",
            "points": input_curve,
            "style": { "lineType": "dashed" }
        }),
        serde_json::json!({ "name": "Smoothed y[n + 8]", "points": output_curve }),
    ],
    options = &serde_json::json!({
        "xLabel": "Input sample position n [-]",
        "yLabel": "Amplitude [-]",
        "xMin": -8.0,
        "xMax": 72.0,
        "yMin": 0.0,
        "yMax": 1.05
    })
);
```

At the default $\sigma = 1.5$, the output length is 80, matching $N + M - 1$.
The maximum difference from direct summation is $2.2 \times 10^{-16}$, the Parseval difference is $7.1 \times 10^{-15}$, and the difference between the sums is 0.
All are at the level of rounding error.
The energy ratio is 0.936, so the output has less energy than the input.
In the “σ = 4” case, the peak falls and the tails broaden, and the energy ratio drops to 0.736, while the difference between the sums remains only $3.6 \times 10^{-15}$.
Even when the pulse is moved toward an edge, the sum is preserved because the full output includes the zero extension.

## Geometry of flat-topped peaks

Quantization or saturation can give ECG R waves or saturated absorbance peaks flat tops with consecutive equal values.
`find_peaks` and `find_peaks_with_options` measure peaks using the following conventions ([Peak geometry and prominence](oxref:signal-peak-geometry)).

1. The representative index of a plateau $[s, e]$ is $s + \lfloor (e - s)/2 \rfloor$, the midpoint rounded down.
2. Prominence is the peak height minus the higher of the valleys on either side.
3. Width is the difference between the left and right intersections of the waveform with the contour at height $h - \rho P$, using linear interpolation between samples; $\rho$ is the relative depth and $P$ is the prominence.

For input $[0, 1, 1, 0, H, 0, 0]$, the plateau at indices 1–2 has representative point 1 and prominence 1.
Its width is $1 + 2\rho$: the plateau length of 1 plus a total of $2\rho$ from interpolation on both sides.
The sharp peak at index 4 has prominence $H$ and width $2\rho$.
The next cell passes `PeakOptions` with only the relative depth $\rho$ changed to the options-based form `find_peaks_with_options`, and places each detected peak's values beside these hand calculations.
The table has one row per detected peak; if a peak occurs at an index absent from the hand calculation, its hand-calculation columns remain empty.

```rust
//| id: signal-plateau-peak-geometry
//| ref: signal-plateau-peak-geometry
//| title: "Compare the representative point, prominence, and width of a flat-topped peak with hand calculations"
//| run: reactive
//| crates: [scioxide-signal]
//| inputs:
//|   peak_height: {"type":"range","label":"Sharp peak height H [-]","description":"Height of the peak at index 4 (determines its prominence).","min":2,"max":8,"step":1,"value":5}
//|   relative_depth: {"type":"range","label":"Relative depth for measuring width ρ [-]","description":"Depth of the width-measurement level as a fraction of prominence.","min":0,"max":1,"step":0.1,"value":0.5}
//| cases:
//|   - {"id":"top-contour","label":"ρ = 0","description":"Measure width at the peak height.","inputs":{"relative_depth":0}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"geometry","path":"/rows/0/0","equals":1}
//|       - {"artifact":"geometry","path":"/rows/1/0","equals":4}
//|       - {"artifact":"geometry","path":"/rows/0/4","approx":{"value":2.0,"atol":1e-12}}
//|       - {"artifact":"geometry","path":"/rows/1/2","approx":{"value":5.0,"atol":1e-12}}
//|       - {"artifact":"geometry","path":"/rows/1/6","range":{"max":1e-12}}
//|   - case: top-contour
//|     expect:
//|       - {"artifact":"geometry","path":"/rows/0/4","approx":{"value":1.0,"atol":1e-12}}
//|       - {"artifact":"geometry","path":"/rows/1/4","approx":{"value":0.0,"atol":1e-12}}
use scioxide_signal::{PeakOptions, find_peaks_with_options};

let fixed3 = serde_json::json!({ "fractionDigits": 3 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
// Plateau at indices 1–2 and sharp peak at index 4.
let input = [0.0_f64, 1.0, 1.0, 0.0, peak_height, 0.0, 0.0];
// Options-based form: change only the relative depth for measuring width; selection criteria remain at their defaults (accept all peaks).
let options = PeakOptions::default().with_relative_height(relative_depth);
let peaks = find_peaks_with_options(&input, options).map_err(|e| e.to_string())?;

// Hand calculation: representative point → (prominence, width).
let expected = |index: usize| match index {
    1 => Some((1.0, 1.0 + 2.0 * relative_depth)),
    4 => Some((peak_height, 2.0 * relative_depth)),
    _ => None,
};
let rows: Vec<_> = peaks
    .iter()
    .map(|p| {
        let hand = expected(p.index());
        (
            p.index(),
            hand.map(|_| p.index()),
            p.prominence(),
            hand.map(|(prominence, _)| prominence),
            p.width(),
            hand.map(|(_, width)| width),
            hand.map(|(_, width)| (p.width() - width).abs()),
        )
    })
    .collect();
let columns = serde_json::json!([
    { "key": "0", "label": "Representative point [-]", "type": "integer" },
    { "key": "1", "label": "Hand-calculated representative point [-]", "type": "integer", "nullText": "None" },
    { "key": "2", "label": "Prominence [-]", "type": "number", "format": fixed3 },
    { "key": "3", "label": "Hand-calculated prominence [-]", "type": "number", "format": fixed3, "nullText": "None" },
    { "key": "4", "label": "Width [samples]", "type": "number", "format": fixed3 },
    { "key": "5", "label": "Hand-calculated width [samples]", "type": "number", "format": fixed3, "nullText": "None" },
    { "key": "6", "label": "Width difference [samples]", "type": "number", "format": sci3, "nullText": "—" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "geometry" })
);
```

At the defaults $H = 5$ and $\rho = 0.5$, two peaks are detected with representative points 1 and 4.
Their widths are 2 and 1, matching the hand calculations with a difference of 0.
In the “ρ = 0” case, width is measured at the peak height, so the plateau has width $e - s = 1$, its top length, while the sharp peak has width 0.
Changing $H$ leaves the plateau's prominence at 1, showing that prominence depends only on the peak and valley heights.

## Streaming and finalization of a Hampel filter

For a sensor sequence processed as it arrives, future samples are not yet known, so calculating the local median and MAD incurs a delay of $r$ samples, the window radius.
At the end of the stream, the remaining output is flushed using an extension that repeats the endpoint value ([Plans and streaming](oxref:signal-local-filter-stream)).

The next cell applies batch processing (`filter_into`) and streaming split into two chunks at an arbitrary position (`LocalFilterStream::process_into`) to a 7-sample sequence containing an isolated spike, and compares their outputs and replaced indices.
The radius is $r = 1$ and the threshold is $\tau = 3$.
Near the spike, two of the window's three samples are 0, giving a MAD of 0, so a nonzero center sample is replaced.
The first table shows per-sample output, the second shows `StreamProgress` for each chunk, and the third shows replaced indices and total output.

```rust
//| id: signal-hampel-stream-finish
//| ref: signal-hampel-stream-finish
//| title: "Compare batch Hampel filtering with streaming in separate chunks"
//| run: reactive
//| crates: [scioxide-core, scioxide-signal]
//| inputs:
//|   spike_amplitude: {"type":"range","label":"Spike amplitude [-]","description":"Magnitude of the isolated outlier at index 3.","min":2,"max":10,"step":1,"value":8}
//|   chunk_split: {"type":"range","label":"First chunk length [samples]","description":"Position at which to split the 7-sample sequence into two chunks.","min":1,"max":6,"step":1,"value":3}
//| cases:
//|   - {"id":"late-split","label":"Split position 6","description":"The first chunk also completes the spike replacement.","inputs":{"chunk_split":6}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"samples","path":"/rows/3/2","equals":0}
//|       - {"artifact":"samples","path":"/rows/3/3","equals":0}
//|       - {"artifact":"progress","path":"/rows/0/3","equals":2}
//|       - {"artifact":"progress","path":"/rows/1/3","equals":5}
//|       - {"artifact":"summary","path":"/rows/1/1","equals":"[3]"}
//|   - case: late-split
//|     expect:
//|       - {"artifact":"progress","path":"/rows/0/3","equals":5}
//|       - {"artifact":"summary","path":"/rows/1/1","equals":"[3]"}
use scioxide_core::ExecutionContext;
use scioxide_signal::{LocalFilter, LocalFilterPlan, StreamChunk};

let input = [0.0_f64, 0.0, 0.0, spike_amplitude, 0.0, 0.0, 0.0];
let filter = LocalFilterPlan::new(1, LocalFilter::Hampel { threshold: 3.0 })
    .map_err(|e| e.to_string())?;

// Batch processing.
let mut batch = [0.0; 7];
let mut batch_indices = [0; 7];
let mut scratch = filter.workspace(input.len()).map_err(|e| e.to_string())?;
let batch_count = filter
    .filter_into(
        &input,
        &mut batch,
        &mut batch_indices,
        &mut scratch,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;

// The stream owns its state. The later chunk flushes the remaining output.
let mut stream = filter.stream().map_err(|e| e.to_string())?;
let mut work = stream.workspace(input.len()).map_err(|e| e.to_string())?;
let (mut streamed, mut stream_indices) = ([0.0; 7], [0; 7]);
let split = chunk_split.round() as usize;
let (mut emitted, mut replaced, mut progress_rows) = (0, Vec::new(), Vec::new());
for (chunk, finish) in [
    (&input[..split], StreamChunk::Partial),
    (&input[split..], StreamChunk::Final),
] {
    let progress = stream
        .process_into(
            chunk,
            finish,
            &mut streamed[emitted..],
            &mut stream_indices,
            &mut work,
            ExecutionContext::sequential(),
        )
        .map_err(|e| e.to_string())?;
    emitted += progress.produced();
    replaced.extend_from_slice(&stream_indices[..progress.replacements()]);
    progress_rows.push((
        chunk.len(),
        format!("{finish:?}"),
        progress.consumed(),
        progress.produced(),
        progress.first_output_index(),
    ));
}

let rows: Vec<(usize, f64, f64, f64)> = (0..7)
    .map(|i| (i, input[i], batch[i], streamed[i]))
    .collect();
let sample_columns = serde_json::json!([
    { "key": "0", "label": "Index [-]", "type": "integer" },
    { "key": "1", "label": "Input [-]", "type": "number" },
    { "key": "2", "label": "Batch processing [-]", "type": "number" },
    { "key": "3", "label": "Streaming [-]", "type": "number" }
]);
emit_table_with_columns!(
    sample_columns,
    rows,
    metadata = serde_json::json!({ "id": "samples" })
);
let progress_columns = serde_json::json!([
    { "key": "0", "label": "Chunk length [samples]", "type": "integer" },
    { "key": "1", "label": "Finalization type" },
    { "key": "2", "label": "Samples consumed [samples]", "type": "integer" },
    { "key": "3", "label": "Samples produced [samples]", "type": "integer" },
    { "key": "4", "label": "First output index [-]", "type": "integer" }
]);
emit_table_with_columns!(
    progress_columns,
    progress_rows,
    metadata = serde_json::json!({ "id": "progress" })
);
let summary_columns = serde_json::json!([
    { "key": "0", "label": "Processing" },
    { "key": "1", "label": "Replaced indices" },
    { "key": "2", "label": "Total output [samples]", "type": "integer" },
    { "key": "3", "label": "Delay [samples]", "type": "integer" }
]);
emit_table_with_columns!(
    summary_columns,
    vec![
        (
            "Batch",
            format!("{:?}", &batch_indices[..batch_count]),
            input.len(),
            0
        ),
        ("Streaming", format!("{replaced:?}"), emitted, filter.delay()),
    ],
    metadata = serde_json::json!({ "id": "summary" })
);
```

At the default amplitude 8 and split position 3, both batch and streaming outputs are all 0, and both replace index 3.
The first chunk (3 samples) produces only 2 samples because of the 1-sample delay; the later chunk, passed `StreamChunk::Final`, flushes the remaining 5 samples.
In the “Split position 6” case, the first chunk produces 5 samples and reports the spike replacement in that call.
Moving the split position from 1 to 6 changes only the number of samples produced per chunk; the output and replaced indices remain the same.

## Summary

The output of `convolve` agrees with direct summation from the definition, and the sum returned by `power_spectrum` agrees with the time-domain sum of squares, to the level of rounding error.
A normalized nonnegative kernel preserves the output sum and does not increase energy.
Knowing the conventions lets you predict the representative point, prominence, and width of a plateau returned by `find_peaks_with_options` by hand.
`LocalFilterStream` owns its state and returns the same output and replaced indices as batch processing regardless of how the chunks are split.
See [Local filters and peak detection](../../algorithms/local-filters-and-features/) for each function's conventions and derivation, and [Smoothing and detrending](../../algorithms/smoothing-and-detrending/) to compare smoothing methods.
