Many combinatorial optimization problems on graphs, such as transport-network capacities and worker–job assignments, can be solved on sparse structures.
Both problems on this page can be written as linear programs, whose dual solutions provide **certificates** of optimality.
The certificate is a minimum cut for maximum flow and a minimum vertex cover for bipartite matching; both use integers and allow exact comparisons.
Comparing the computed solution with its certificate verifies optimality independently of the algorithm that found the solution.
Assignments with a cost for each pair are covered in the [linear assignment problem](../linear-assignment/), where certificates are read as floating-point residuals.
The terms for the calling forms—one-shot functions, standard forms, detailed forms, and scoped forms—are defined in [shared contracts and organization](oxref:sparse-execution-forms).

## Maximum flow and minimum cut

Suppose that each edge $e$ of a directed graph $G = (V, E)$ has a nonnegative integer capacity $c(e)$.
A **flow** $f$ from a source $s$ to a sink $t$ assigns edge values satisfying the capacity constraints $0 \le f(e) \le c(e)$ and conservation (equal inflow and outflow) at every vertex other than $s$ and $t$.
The net amount leaving $s$ is called the flow value $\lvert f \rvert$.
A partition $(S, V \setminus S)$ defined by a vertex set $S$ with $s \in S$ and $t \notin S$ is called a **cut**, and the sum of the capacities of edges leaving $S$ is its capacity $\mathrm{cap}(S)$.

Summing the conservation equations over vertices in $S$ cancels flows on edges within $S$, leaving

$$
\lvert f \rvert = \sum_{e:\, S \to V \setminus S} f(e) - \sum_{e:\, V \setminus S \to S} f(e) \le \mathrm{cap}(S)
$$

as the resulting relation.
Thus every flow value is bounded above by the capacity of every cut.
The max-flow min-cut theorem states that this inequality becomes equality at the maximum and minimum.

$$
\max_f \lvert f \rvert = \min_S \mathrm{cap}(S)
$$

The proof uses augmenting paths.
For each edge, the residual graph has a forward arc carrying the remaining capacity $c(e) - f(e)$ and a reverse arc carrying the amount $f(e)$ that can be sent back.
If the residual graph contains a path from $s$ to $t$ (an augmenting path), the flow can be increased along that path.
If there is no augmenting path, let $S$ be the set of vertices reachable from $s$ in the residual graph; every edge leaving $S$ is saturated (its flow equals its capacity), and every edge entering $S$ from outside has zero flow.
The inequality above becomes equality, giving $\lvert f \rvert = \mathrm{cap}(S)$.
For integer capacities, the amount sent along each augmenting path is always an integer, so an integer maximum flow exists (integrality).

### Dinic's algorithm

Dinic's algorithm performs breadth-first search from $s$ in the residual graph, assigning each vertex its minimum number of arcs from $s$ (its level).
It retains only arcs whose level increases by 1 to form a level graph, then sends flow by depth-first search until no augmenting path remains there.
This flow is called a blocking flow.
Augmenting paths using arcs outside the level graph may remain after a blocking flow is sent, so the level graph is rebuilt and the process repeats.
Remembering the next arc to try at each vertex computes one blocking flow in $O(VE)$.
Each repetition increases the shortest number of residual arcs from $s$ to $t$, so there are at most $V - 1$ repetitions and the total complexity is $O(V^2 E)$.

`MaxFlowPlan::new(vertices, edges)` builds a Plan with forward and reverse arcs for each edge from a sequence of capacity edges `CapacityEdge { source, target, capacity }` (with `u64` capacities) in $O(V + E)$.
Out-of-range endpoints are rejected with `OutOfBounds`.
Zero-capacity edges, self-loops, and parallel edges are allowed; parallel edges are treated separately.
Outgoing arcs at each vertex are tried in input order, making the result deterministic for the same input.
`vertex_count()` returns the number of vertices, and `edges()` returns the edges in input order.
The standard form `maximum_flow(source, sink)` returns the maximum flow and minimum cut as `MaximumFlow`.
It rejects a source or sink outside the vertex set with `OutOfBounds` and equal source and sink with `InvalidInput`, and fails with `SizeOverflow` if the flow value or a residual capacity exceeds `u64::MAX`.
The one-shot function `maximum_flow(vertices, edges, source, sink)` builds the Plan and solves the problem in one call.
Retain and reuse the Plan when solving for other source–sink pairs on the same network.

The `FlowView` returned by `MaximumFlow::as_view()` has public fields for the source `source`, sink `sink`, flow value `value`, flows in input-edge order `edge_flows`, and `source_side`, which marks vertices on the source side of the cut with `true`.
For the computed flow, `source_side` is the set of vertices reachable from the source in the final residual graph.
`FlowView::verify(&plan)` checks all of the following with integer arithmetic, returning `Ok(true)` if all hold and `Ok(false)` if any fails.

- The source and sink are distinct vertices, and array lengths match the Plan.
- No edge flow exceeds its capacity.
- Flow conservation holds at every vertex other than the source and sink.
- The net outflow from the source and net inflow to the sink both equal `value`.
- `source_side` contains the source and excludes the sink.
- The capacity of that cut equals `value`.

Sums use 128-bit integers; overflow even in 128 bits fails with `SizeOverflow`, and failure to allocate arrays of per-vertex sums fails with `AllocationFailure`.
If the flow value and cut capacity are exactly equal, the inequality above proves that the flow is maximum and the cut is minimum.
Thus a true result from `verify` proves optimality.
Because the fields are public, flows computed by other methods can be checked in the same way.

### Checking maximum flow and minimum cut

The following cell finds a maximum flow on a six-vertex network ($s = 0$, $t = 5$).
The edges are $0 \to 1$: 10, $0 \to 2$: 8, $1 \to 2$: 2, $1 \to 3$: 5, $2 \to 4$: $c$, $3 \to 5$: 7, $4 \to 3$: 4, and $4 \to 5$: 6; the input is the capacity $c$ (0–12) of edge $2 \to 4$.
The first table shows each edge's flow and its direction across the cut $S$ indicated by `source_side`.
The second table shows the flow value, cut capacity, and result of `verify`.
As an independent check, it enumerates all 16 cuts formed by including or excluding the four vertices other than $s$ and $t$ in $S$ and finds the minimum capacity from the edge list.

```rust
//| id: sparse-flow-matching-certificates
//| ref: sparse-flow-matching-certificates
//| title: "Maximum-flow and minimum-cut certificates"
//| run: reactive
//| crates: [scioxide-core, scioxide-sparse]
//| inputs:
//|   capacity: {"type":"range","label":"Capacity c of edge 2→4","description":"The minimum cut shifts at c = 8.","min":0,"max":12,"step":1,"value":5}
//| cases:
//|   - {"id":"closed","label":"c = 0","description":"Edge 2→4 is unavailable, leaving only a flow of 5 through edge 1→3.","inputs":{"capacity":0}}
//|   - {"id":"wide","label":"c = 12","description":"The minimum cut shifts to edges 3→5 and 4→5 immediately before the sink.","inputs":{"capacity":12}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":10}
//|       - {"artifact":"summary","path":"/rows/0/1","equals":"{0, 1, 2}"}
//|       - {"artifact":"summary","path":"/rows/0/2","equals":10}
//|       - {"artifact":"summary","path":"/rows/0/3","equals":10}
//|       - {"artifact":"summary","path":"/rows/0/4","equals":true}
//|       - {"artifact":"edges","path":"/rows/3/2","equals":5}
//|       - {"artifact":"edges","path":"/rows/4/2","equals":5}
//|   - case: closed
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":5}
//|       - {"artifact":"summary","path":"/rows/0/3","equals":5}
//|       - {"artifact":"summary","path":"/rows/0/4","equals":true}
//|   - case: wide
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":13}
//|       - {"artifact":"summary","path":"/rows/0/1","equals":"{0, 1, 2, 3, 4}"}
//|       - {"artifact":"summary","path":"/rows/0/3","equals":13}
//|       - {"artifact":"edges","path":"/rows/5/2","equals":7}
//|       - {"artifact":"edges","path":"/rows/7/2","equals":6}
use scioxide_sparse::{CapacityEdge, MaxFlowPlan};

// Edge list (source, target, capacity). s = 0, t = 5.
let network = |c: u64| {
    [
        (0, 1, 10),
        (0, 2, 8),
        (1, 2, 2),
        (1, 3, 5),
        (2, 4, c),
        (3, 5, 7),
        (4, 3, 4),
        (4, 5, 6),
    ]
};
let edges_of = |c: u64| -> Vec<CapacityEdge> {
    network(c)
        .iter()
        .map(|&(source, target, capacity)| CapacityEdge {
            source,
            target,
            capacity,
        })
        .collect()
};
// Independent check: find the minimum capacity of all 16 cuts containing s and excluding t from the edge list.
let min_cut = |c: u64| -> u64 {
    (0..16_usize)
        .map(|mask| {
            let inside = |v: usize| v == 0 || (v != 5 && mask >> (v - 1) & 1 == 1);
            network(c)
                .iter()
                .filter(|e| inside(e.0) && !inside(e.1))
                .map(|e| e.2)
                .sum::<u64>()
        })
        .min()
        .unwrap_or(0)
};

let c = capacity.round() as u64;
let list = network(c);
let plan = MaxFlowPlan::new(6, &edges_of(c)).map_err(|e| e.to_string())?;
let flow = plan.maximum_flow(0, 5).map_err(|e| e.to_string())?;
let view = flow.as_view();
let side = view.source_side;
let rows: Vec<_> = list
    .iter()
    .zip(view.edge_flows)
    .map(|(&(u, v, cap), &f)| {
        let crossing = match (side[u], side[v]) {
            (true, false) => "Leaving S",
            (false, true) => "Entering S",
            _ => "Does not cross",
        };
        (format!("{u} → {v}"), cap, f, crossing)
    })
    .collect();
let columns = serde_json::json!([
    { "key": "0", "label": "Edge", "type": "string" },
    { "key": "1", "label": "Capacity", "type": "integer" },
    { "key": "2", "label": "Flow", "type": "integer" },
    { "key": "3", "label": "Relation to cut S", "type": "string" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "edges" })
);

let members: Vec<String> = (0..6).filter(|&v| side[v]).map(|v| v.to_string()).collect();
let cut: u64 = list
    .iter()
    .filter(|e| side[e.0] && !side[e.1])
    .map(|e| e.2)
    .sum();
let verified = view.verify(&plan).map_err(|e| e.to_string())?;
let columns = serde_json::json!([
    { "key": "0", "label": "Flow value |f|", "type": "integer" },
    { "key": "1", "label": "Source side S of the cut", "type": "string" },
    { "key": "2", "label": "cap(S) (from edge list)", "type": "integer" },
    { "key": "3", "label": "Exhaustive minimum-cut capacity", "type": "integer" },
    { "key": "4", "label": "FlowView::verify", "type": "boolean" }
]);
emit_table_with_columns!(
    columns,
    vec![(
        view.value,
        format!("{{{}}}", members.join(", ")),
        cut,
        min_cut(c),
        verified
    )],
    metadata = serde_json::json!({ "id": "summary" })
);
```

At the default $c = 5$, the maximum flow value is 10 and the source side of the minimum cut is $S = \{0, 1, 2\}$.
The edges leaving $S$ are $1 \to 3$ (capacity 5) and $2 \to 4$ (capacity 5); both are saturated, with flow equal to capacity.
The cut capacity of 10 summed from the edge list equals the flow value, `verify` returns true, and exhaustive enumeration also gives a minimum-cut capacity of 10.
At $c = 0$, edge $2 \to 4$ is unavailable, leaving only a flow of 5 through $1 \to 3$.
At $c = 12$, the flow increases to 13 and the minimum cut shifts to $S = \{0, 1, 2, 3, 4\}$ immediately before the sink.
The edges leaving $S$ are then $3 \to 5$ (capacity 7) and $4 \to 5$ (capacity 6).
Since $S = \{0, 1, 2\}$ has capacity $5 + c$ and $S = \{0, 1, 2, 3, 4\}$ has capacity 13, the maximum flow value is $\min(5 + c, 13)$ and the minimum cut shifts at $c = 8$.

## Bipartite matching and König's theorem

A bipartite graph divides its vertices into two sets $U$ (rows) and $W$ (columns), with edges only between $U$ and $W$.
A set of edges sharing no endpoints is called a **matching** $M$, and a vertex set containing at least one endpoint of every edge is a **vertex cover** $C$.
Since matching edges share no endpoints, covering them requires distinct vertices, so $\lvert M \rvert \le \lvert C \rvert$ always holds.
For bipartite graphs, König's theorem states that equality holds at the maximum and minimum.

$$
\max_M \lvert M \rvert = \min_C \lvert C \rvert
$$

Thus a matching and vertex cover of equal size establish that both are optimal.

A cover of equal size can be constructed from a maximum matching $M$ as follows.
A path alternating between matching and nonmatching edges is an alternating path; let $Z$ be the vertices reachable along alternating paths from unmatched rows, including the starting rows.
Set $C = (U \setminus Z) \cup (W \cap Z)$.
Consider an edge $(u, w)$.
If $u \notin Z$, then $u \in C$.
If $u \in Z$ and the edge is not in the matching, the alternating path can extend to $w$, giving $w \in Z$.
If it is a matching edge, a matched row $u$ can only be reached through its matched column $w$, so $w \in Z$ again.
In either case $w \in C$, so $C$ covers every edge.
Next, every vertex in $C$ is matched.
If a column in $W \cap Z$ were unmatched, that alternating path could increase the matching by one edge, contradicting the assumption that $M$ is maximum.
Also, all unmatched rows belong to $Z$, so every row in $U \setminus Z$ is matched.
Furthermore, if a column belongs to $Z$, its matched row also belongs to $Z$ through the matching edge; thus exactly one endpoint of each matching edge belongs to $C$.
Therefore $\lvert C \rvert = \lvert M \rvert$.

The Hopcroft–Karp algorithm flips the matching along alternating paths (augmenting paths) connecting unmatched rows and columns, adding one edge per path.
Each phase uses breadth-first search from unmatched rows to find the shortest augmenting-path length, then depth-first search to flip a collection of vertex-disjoint augmenting paths of that length.
There are $O(\sqrt{V})$ phases, so the total complexity is $O((V + E)\sqrt{V})$.

The one-shot function `maximum_bipartite_matching(pattern)` finds a maximum matching and minimum vertex cover of the bipartite graph whose rows are $U$, columns are $W$, and edges are stored entries (including zeros), returning `BipartiteMatching`.
Matching has no Plan.
The structure may be rectangular.
The `MatchingView` from `as_view()` has public fields for each row's matched column `left`, each column's matched row `right`, and `left_cover` and `right_cover` indicating the rows and columns in the cover.
`cardinality()` returns the number of matching edges.
`MatchingView::verify(pattern)` returns `bool`, which is true exactly when all of the following hold.
Array lengths match the structure, every matched pair is a stored entry, `left` and `right` agree, at least one endpoint of every entry belongs to the cover, and the number of cover vertices equals the number of matching edges.
These are all integer comparisons, so a true result proves by König's theorem that the matching is maximum and the cover is minimum.
The detailed form `maximum_bipartite_matching_with_options(pattern, options)` accepts an iteration limit.

The maximum matching size equals the greatest rank attainable by choosing entry values (the structural rank).
A perfect matching in a square structure means that some choice of values can make it nonsingular (structural nonsingularity).

### Eligibility table for the experiments

The next two cells use a $5 \times 5$ structure representing eligibility between five workers (rows) and five jobs (columns).
Worker 0 can do jobs 0 and 1; worker 1, job 0; worker 2, job 1; worker 3, jobs 2, 3, and 4; and worker 4, job 2.
In the definitions block, `allowed(extra_pair)` returns the list of eligible jobs for each worker; when `extra_pair` is true, worker 2 can also do job 3.
`workers_matrix` assembles a CSR matrix with value-1 entries for these eligible pairs.

```rust
//| id: sparse-matching-workers
//| kind: definitions
//| title: "Eligibility of five workers for five jobs"
//| crates: [scioxide-core, scioxide-sparse]
use scioxide_core::SciOxideError;
use scioxide_sparse::{CsrMatrix, DuplicatePolicy, ExplicitZeroPolicy, SparseBuilder};

/// List of jobs (columns) eligible for worker i (row). With extra_pair, worker 2 can also do job 3.
pub(crate) fn allowed(extra_pair: bool) -> [Vec<usize>; 5] {
    let worker2 = if extra_pair { vec![1, 3] } else { vec![1] };
    [vec![0, 1], vec![0], worker2, vec![2, 3, 4], vec![2]]
}

/// A 5 × 5 CSR matrix whose entry (i, j) is 1 when worker i can do job j.
pub(crate) fn workers_matrix(jobs: &[Vec<usize>; 5]) -> Result<CsrMatrix<f64>, SciOxideError> {
    let mut builder = SparseBuilder::new(5, 5);
    for (i, row) in jobs.iter().enumerate() {
        for &j in row {
            builder.push(i, j, 1.0)?;
        }
    }
    builder.finish_csr(DuplicatePolicy::Reject, ExplicitZeroPolicy::Preserve)
}
```

### Bipartite matching and vertex cover

The following cell uses the one-shot function `maximum_bipartite_matching` to find a maximum matching and vertex cover.
The input specifies whether worker 2 can also do job 3.
The first table shows each index's match and cover membership; the second shows matching and cover sizes and the result of `verify`.
As an independent check, it counts uncovered entries from the eligibility list and exhaustively searches all $5! = 120$ assignments for the maximum number of eligible pairs.
For a square structure, every matching extends to a permutation, so this maximum equals the maximum matching size.

```rust
//| id: sparse-bipartite-matching-cover
//| ref: sparse-bipartite-matching-cover
//| title: "Bipartite matching and König's vertex cover"
//| run: reactive
//| uses: [sparse-matching-workers]
//| crates: [scioxide-core, scioxide-sparse]
//| inputs:
//|   extra_pair: {"type":"checkbox","label":"Worker 2 can also do job 3","value":false}
//| cases:
//|   - {"id":"perfect","label":"Worker 2 can also do job 3","description":"A perfect matching becomes possible, making the structure structurally nonsingular.","inputs":{"extra_pair":true}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"matching","path":"/rows/1/1","equals":null}
//|       - {"artifact":"matching","path":"/rows/3/2","equals":true}
//|       - {"artifact":"summary","path":"/rows/0/0","equals":4}
//|       - {"artifact":"summary","path":"/rows/0/1","equals":4}
//|       - {"artifact":"summary","path":"/rows/0/2","equals":0}
//|       - {"artifact":"summary","path":"/rows/0/3","equals":4}
//|       - {"artifact":"summary","path":"/rows/0/4","equals":true}
//|   - case: perfect
//|     expect:
//|       - {"artifact":"matching","path":"/rows/2/1","equals":3}
//|       - {"artifact":"summary","path":"/rows/0/0","equals":5}
//|       - {"artifact":"summary","path":"/rows/0/3","equals":5}
//|       - {"artifact":"summary","path":"/rows/0/4","equals":true}
use scioxide_sparse::maximum_bipartite_matching;

let n = 5;
let jobs = allowed(extra_pair);
let matrix = workers_matrix(&jobs).map_err(|e| e.to_string())?;
let pattern = matrix.structural_pattern();
let matching = maximum_bipartite_matching(pattern).map_err(|e| e.to_string())?;
let m = matching.as_view();
let rows: Vec<_> = (0..n)
    .map(|k| (k, m.left[k], m.left_cover[k], m.right[k], m.right_cover[k]))
    .collect();
let columns = serde_json::json!([
    { "key": "0", "label": "Index k", "type": "integer" },
    { "key": "1", "label": "Job for worker k", "type": "integer", "nullText": "None" },
    { "key": "2", "label": "Worker k is in the cover", "type": "boolean" },
    { "key": "3", "label": "Worker for job k", "type": "integer", "nullText": "None" },
    { "key": "4", "label": "Job k is in the cover", "type": "boolean" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "matching" })
);

let cover = m
    .left_cover
    .iter()
    .chain(m.right_cover)
    .filter(|&&c| c)
    .count();
// Independent check: count uncovered entries and maximize the number of eligible pairs over all 120 permutations.
let uncovered: usize = (0..n)
    .map(|i| {
        let open = |&&j: &&usize| !m.left_cover[i] && !m.right_cover[j];
        jobs[i].iter().filter(open).count()
    })
    .sum();
let best = (0..n.pow(5))
    .map(|code| {
        (0..n)
            .map(|i| code / n.pow(i as u32) % n)
            .collect::<Vec<_>>()
    })
    .filter(|p| (0..n).all(|j| p.contains(&j)))
    .map(|p| (0..n).filter(|&i| jobs[i].contains(&p[i])).count())
    .max()
    .unwrap_or(0);
let columns = serde_json::json!([
    { "key": "0", "label": "|M|", "type": "integer" },
    { "key": "1", "label": "|C|", "type": "integer" },
    { "key": "2", "label": "Uncovered entries (from list)", "type": "integer" },
    { "key": "3", "label": "Exhaustive maximum size", "type": "integer" },
    { "key": "4", "label": "MatchingView::verify", "type": "boolean" }
]);
emit_table_with_columns!(
    columns,
    vec![(m.cardinality(), cover, uncovered, best, m.verify(pattern))],
    metadata = serde_json::json!({ "id": "summary" })
);
```

By default, workers 0, 1, and 2 have only jobs 0 and 1 available, so one of the three cannot be assigned and the maximum matching size is 4.
In the computed matching, worker 1 is unmatched, and the cover consists of four vertices: workers 3 and 4 and jobs 0 and 1.
Alternating paths from worker 1 reach jobs 0 and 1 and workers 0 and 2, so the cover agrees with the construction $C = (U \setminus Z) \cup (W \cap Z)$ above.
There are 0 uncovered entries, $\lvert M \rvert = \lvert C \rvert = 4$ agrees with the exhaustive maximum of 4, and `verify` returns true.
Allowing worker 2 to do job 3 produces a perfect matching.
The cover then consists of all five workers, and the structure is structurally nonsingular.

## Scoped forms and workspaces

In addition to forms that allocate a workspace internally (the maximum-flow one-shot function and standard form `maximum_flow`, and the matching one-shot function and detailed form), both problems provide scoped forms `maximum_flow_scoped` and `maximum_bipartite_matching_scoped` that use only reserved workspace.
Scoped forms accept options `GraphExecutionOptions`, a workspace, and a root or enclosing-solver context `scope`, returning results that borrow the workspace (`FlowView`, `MatchingView`).

Create a maximum-flow workspace with the Plan's `workspace(())`, or reserve it with `FlowWorkspace::try_reserve` for the `FlowWorkspaceRequirements` returned by `workspace_requirements(())`.
Because matching has no Plan, create its workspace with `MatchingWorkspace::workspace(pattern)`, or reserve it for the `MatchingWorkspaceRequirements` returned by `MatchingWorkspace::workspace_requirements(pattern)`.
The requirement's `bytes()` returns logical bytes, and the workspace's `check` checks whether it is sufficient.
Create an empty workspace with each type's `new()` and reserve it with `try_reserve`.
Insufficient workspace is rejected with `DimensionMismatch` without expansion.
Workspaces never shrink, allowing one workspace to be reused across multiple Plans or structures.

When `GraphExecutionOptions::with_budgets` specifies an iteration limit, iterations use the following units (see [iteration limits and execution contexts](oxref:sparse-iteration-limits) for the chapter-wide rules).

- Maximum flow: one per breadth-first search that builds a level graph and per depth-first search that finds an augmenting path within a blocking flow.
  Both include the final search that ends without finding anything.
- Matching: one per Hopcroft–Karp phase.
  The final breadth-first search confirming that no augmenting path exists also counts as one.

Reaching the limit returns `ConvergenceFailure`; cancellation or a deadline returns `ExecutionStopped`.
The maximum-flow one-shot function and standard form and the matching one-shot function have no limit and do not return these two errors.
The detailed matching form returns `ConvergenceFailure` when the supplied limit is reached.
Both problems execute sequentially under every execution policy.
On failure, no partial result is exposed, and the workspace's `last_accepted()` returns `None`.
`last_attempt()` returns the record of the last attempt, including calls rejected before they begin.

### Iteration limits and attempt records

The following cell calls the scoped form `maximum_bipartite_matching_scoped` on the same eligibility table.
The inputs are whether worker 2 can also do job 3 and the iteration limit.

```rust
//|   - {"id":"perfect-limit-three","label":"Add job 3 and limit to 3","description":"A perfect matching is found in three phases, but the limit is reached on the fourth search confirming that no augmenting path remains.","inputs":{"extra_pair":true,"phase_limit":"3"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"attempt","path":"/rows/0/0","equals":"Success"}
//|       - {"artifact":"attempt","path":"/rows/0/1","equals":3}
//|       - {"artifact":"attempt","path":"/rows/0/2","equals":4}
//|   - case: limit-two
//|     expect:
//|       - {"artifact":"attempt","path":"/rows/0/0","equals":"ConvergenceFailure"}
//|       - {"artifact":"attempt","path":"/rows/0/1","equals":2}
//|       - {"artifact":"attempt","path":"/rows/0/2","equals":null}
//|   - case: perfect-limit-three
//|     expect:
//|       - {"artifact":"attempt","path":"/rows/0/0","equals":"ConvergenceFailure"}
//|       - {"artifact":"attempt","path":"/rows/0/1","equals":3}
use scioxide_core::{Budget, BudgetKind, ExecutionContext, SolveBudgets};
use scioxide_sparse::{
    GraphExecutionOptions, MatchingWorkspace, maximum_bipartite_matching_scoped,
};

let jobs = allowed(extra_pair);
let matrix = workers_matrix(&jobs).map_err(|e| e.to_string())?;
let pattern = matrix.structural_pattern();
let mut budgets = SolveBudgets::unbounded();
if phase_limit != "none" {
    let limit: usize = phase_limit
        .parse()
        .map_err(|_| "The limit is not an integer".to_string())?;
    let limit = Budget::try_from(limit).map_err(|e| e.to_string())?;
    budgets = budgets.with_limit(BudgetKind::Iteration, limit);
}
let options = GraphExecutionOptions::new().with_budgets(budgets);
let mut workspace = MatchingWorkspace::workspace(pattern).map_err(|e| e.to_string())?;
let failure = maximum_bipartite_matching_scoped(
    pattern,
    options,
    &mut workspace,
    ExecutionContext::sequential(),
)
.err()
.map(|e| format!("{:?}", e.kind()));
// The attempt record retains the iterations counted so far even when a call fails.
let iterations = workspace
    .last_attempt()
    .map(|record| record.counts().own().iterations());
// The result can be read from the workspace only when the last call succeeded.
let accepted = workspace.last_accepted().map(|m| m.cardinality());
let result = failure.unwrap_or_else(|| "Success".to_string());
let columns = serde_json::json!([
    { "key": "0", "label": "Call result", "type": "string" },
    { "key": "1", "label": "Counted iterations [count]", "type": "integer", "nullText": "-" },
    { "key": "2", "label": "|M| from last_accepted", "type": "integer", "nullText": "None" }
]);
emit_table_with_columns!(
    columns,
    vec![(result, iterations, accepted)],
    metadata = serde_json::json!({ "id": "attempt" })
);
```

By default, three iterations are counted: two phases flipping augmenting paths and the final search confirming that no augmenting path remains.
With a limit of 2, the third search reaches the limit and returns `ConvergenceFailure`, and `last_accepted()` becomes `None`.
If worker 2 can also do job 3, a perfect matching is found in three phases, but the fourth search confirming that no augmenting path remains also counts, so a limit of 3 likewise gives `ConvergenceFailure`.
Even for failed calls, the `last_attempt()` record retains the iterations counted before reaching the limit.

## Summary

Maximum flow and bipartite matching both have linear-programming duals, and minimum cuts and minimum vertex covers provide optimality certificates.
Dinic's algorithm finds a maximum flow in $O(V^2 E)$, and Hopcroft–Karp finds a maximum matching in $O((V + E)\sqrt{V})$.
`FlowView::verify` and `MatchingView::verify` verify optimality exactly with integer comparisons; their public fields also allow them to check solutions found by other methods.
For square structures, the existence of a perfect matching determines structural nonsingularity.
Iteration counts include the final search that finds nothing, so for matching, set the limit one higher than the number of phases that flip augmenting paths.
