Treating the stored entries $(u, v)$ of a square sparse matrix $\mathbf{W}$ as edges and their values as weights makes the matrix a weighted graph.
Road networks, circuit-node connections, probability transitions, and finite-element mesh connectivity can all be represented this way.
`scioxide-sparse` builds adjacency lists from a sparse matrix once and reuses them for traversal, connected components, minimum spanning forests, shortest paths, and Laplacians.
This page explains conventions for reading a matrix as a graph, traversal and connected components, minimum spanning forests, and graph Laplacians.
Shortest paths and negative cycles using the same Plan are covered in [shortest paths and negative cycles](../shortest-paths/).
Terms for calling forms such as one-shot functions, standard forms, and scoped forms are defined in [shared contracts and organization](oxref:sparse-execution-forms).

## Reading a matrix as a graph

`GraphPlan::new(view, direction)` reads a square real sparse-matrix view as a weighted graph and builds a Plan `GraphPlan` with forward and reverse adjacency lists.
Vertex $i$ corresponds to row $i$ and column $i$.
For an unweighted structure, `GraphPlan::from_pattern(pattern, direction)` builds a Plan with all edge weights equal to 1.
Its weight type is `f64` regardless of the matrix type from which the structure was extracted.
With $V$ vertices and $E$ stored entries, preparation costs $O(V + E \log E)$ time and $O(V + E)$ storage.
Both constructors reject nonsquare matrices with `DimensionMismatch`.
Sparse storage contains only finite values, so weights are always finite.

- With `GraphDirection::Directed`, a stored entry $(u, v)$ becomes an edge from $u$ to $v$.
- With `GraphDirection::Undirected`, either $(u, v)$ or $(v, u)$ creates edge $\{u, v\}$.
  If both are stored with different weights, the smaller is used.

`vertex_count()` returns the vertex count including isolated vertices, and `direction()` returns the interpretation.
`edge_count()` counts directed arcs: in an undirected graph, an edge between two distinct vertices counts twice and a self-loop once.
Adjacency lists are sorted by vertex index, and all algorithms visit neighboring vertices in ascending index order, making results deterministic for the same matrix and interpretation.

### Edge weights and matrix values

Every algorithm uses stored values directly as edge weights.
However, the meaning of larger and smaller values reverses between algorithms.
For minimum spanning forests and shortest paths, weights are edge lengths: smaller means closer.
For Laplacians, weights measure connection strength, corresponding to conductance in an electrical circuit: larger means more strongly connected.
Keep this distinction in mind when using the same matrix for both purposes.
For example, to find shortest paths with resistance $1/g_{ij}$ as length in a circuit of conductance $g_{ij}$, assemble a separate matrix of reciprocal values.

### Zero-weight edges

A stored zero is also an edge.
A zero-weight edge represents connectivity for traversal and connected components, and a zero-length edge for minimum spanning forests and shortest paths.
Its Laplacian contribution is zero, however, so for the Laplacian it is equivalent to an absent edge ([graph Laplacians](#graph-laplacians)).
Choosing `ExplicitZeroPolicy::Drop` during assembly removes zero-valued entries from the structure and also removes their graph edges.
The same rule applies to entries that become zero through cancellation ([implicit and explicitly stored zero entries](oxref:sparse-explicit-zeros)).
The two cells on this page and the cell in [shortest paths and negative cycles](oxref:sparse-zero-edge-dijkstra-experiment) show how the zero policy changes results.

## Traversal and connected components

`breadth_first(source)` performs breadth-first search and `depth_first(source)` depth-first search; both return `GraphTraversal` in $O(V + E)$ time.
A source outside the vertex set is rejected with `OutOfBounds`.
`order()` lists vertices reachable from the source in discovery order, `predecessors()` gives their parents in the search tree (`None` for the source and unreachable vertices), and `depths()` gives search-tree depths (`None` for unreachable vertices).
Breadth-first search depth equals the smallest number of edges from the source, ignoring weights.
Depth-first search depth is depth within the search tree and need not be the smallest number of edges.
Depth-first search uses an explicit stack, so even deep graphs do not overflow the call stack.
It does not return topological orderings or cycle-detection results.

`weak_components()` finds connected components ignoring edge directions (weakly connected components).
`strong_components()` uses Kosaraju's algorithm to find strongly connected components: maximal sets of mutually reachable vertices.
Kosaraju's algorithm first performs depth-first search on the original graph and orders vertices by decreasing finishing time.
It then searches the graph with all edges reversed, choosing starting vertices in that order.
The component containing the last vertex to finish has no incoming edge from another component in the original graph.
In the reversed graph, that component therefore has no outgoing edge to another component, and a search starting there reaches exactly that strongly connected component.
Removing the reached vertices leaves the same argument applicable to the remaining vertices.
Both return `GraphComponents` in $O(V + E)$ time, with `labels()` giving each vertex's component index and `count()` the component count.
Components are numbered from 0 in ascending order of their smallest vertex index.

The one-shot function `connected_components(pattern)` builds a Plan from a square structure using `from_pattern` and `GraphDirection::Directed` and returns weakly connected components.
Including Plan preparation, the complexity is $O(V + E \log E)$.
Traversal, connected components, and the next section's minimum spanning forest take no options, workspace, or execution context and return newly allocated results.
Iteration limits, cancellation, and parallel execution are unavailable.

## Minimum spanning forests

In an undirected graph, a **minimum spanning tree** is a tree connecting all vertices with the smallest sum of edge weights.
For a disconnected graph, a collection of minimum spanning trees, one per connected component, is a **minimum spanning forest**.
A spanning forest of a graph with $V$ vertices and $c$ connected components has exactly $V - c$ edges.

Minimum spanning trees have the following **cut property**.
For a partition of vertices into two sets (a cut), a minimum-weight edge crossing the cut belongs to some minimum spanning tree.
If a minimum spanning tree $T$ does not contain that edge $e$, adding $e$ to $T$ creates a cycle containing another edge $f$ across the cut, and exchanging $e$ and $f$ cannot increase the total weight.

Kruskal's algorithm examines edges in ascending weight order and adds only edges joining different components to the forest.
When adding edge $e$, every edge examined before $e$, whether accepted or discarded, has both endpoints in one component.
Thus every edge crossing the cut between the component containing one endpoint of $e$ and the outside is examined after $e$, and $e$ has minimum weight among them.
Applying the cut-property argument to a minimum spanning forest containing the previously selected edges shows that a minimum spanning forest containing $e$ also exists.
Continuing through the last edge makes the selected edges a minimum spanning forest.
Component membership uses a disjoint-set forest (union–find), and sorting the edges dominates the complexity at $O(E \log E)$.
Since edge selection depends only on weight ordering, the argument also holds for negative weights.

`minimum_spanning_forest()` accepts only undirected graphs and rejects directed graphs with `InvalidInput`.
Negative weights are allowed, and self-loops never enter the forest.
The result's `MinimumSpanningForest` lists `ForestEdge { u, v, weight }` ($u < v$) in `edges()` in Kruskal selection order (by weight, then by $(u, v)$ for ties).
`total_weight()` is the exact sum of the selected edge weights rounded once.
Even if an intermediate partial sum exceeds the floating-point range, a finite value is returned when the final sum is representable.
Failure occurs only if the final sum is unrepresentable, with `NumericalInstability` (`Overflow`).
`components()` returns connected components including isolated vertices as `GraphComponents`.

### Minimum spanning forests and zero-weight edges

The following cell uses Kruskal's algorithm to find the minimum spanning forest of a six-vertex undirected graph.
The edges are $\{0, 1\}$: 0, $\{0, 2\}$: 4, $\{1, 2\}$: $d$, $\{1, 3\}$: 3, $\{2, 3\}$: 2, $\{2, 4\}$: 5, and $\{3, 4\}$: 6; vertex 5 has no edges.
Each edge is stored once as entry $(u, v)$ with $u < v$ and read using `GraphDirection::Undirected`.
The inputs are the weight $d$ ($-2$–8) of edge $\{1, 2\}$ and whether to retain the zero-weight edge $\{0, 1\}$ in the structure.
The first table lists forest edges in Kruskal selection order; the second shows the connected-component count, forest-edge count, and total weight.
As an independent check, it examines all subsets of retained edges and finds the smallest total weight among acyclic subsets with the maximum edge count.
An acyclic edge subset is a spanning forest exactly when its edge count is maximum, namely $V - c$.

```rust
//| id: sparse-minimum-spanning-forest
//| ref: sparse-minimum-spanning-forest
//| title: "Kruskal's minimum spanning forest checked by exhaustive enumeration"
//| run: reactive
//| crates: [scioxide-core, scioxide-sparse]
//| inputs:
//|   edge_weight: {"type":"range","label":"Weight d of edge {1, 2}","description":"Negative weights are also supported.","min":-2.0,"max":8.0,"step":1.0,"value":1.0}
//|   keep_zero: {"type":"checkbox","label":"Retain zero-weight edge {0, 1} in the structure (Preserve)","description":"Disabling this removes zero-valued entries during assembly (Drop).","value":true}
//| cases:
//|   - {"id":"negative-edge","label":"d = −2","description":"The negative-weight edge is selected first, lowering the total weight to 5.","inputs":{"edge_weight":-2}}
//|   - {"id":"heavy-edge","label":"d = 8","description":"Edge {1, 2} would create a cycle and is skipped; {1, 3} is included instead.","inputs":{"edge_weight":8}}
//|   - {"id":"drop-zero","label":"Remove zero-weight edges","description":"Vertex 0 connects through edge {0, 2} of weight 4, increasing the total weight to 12.","inputs":{"keep_zero":false}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"forest","path":"/rows/0/1","equals":0}
//|       - {"artifact":"forest","path":"/rows/0/2","equals":1}
//|       - {"artifact":"summary","path":"/rows/0/0","equals":2}
//|       - {"artifact":"summary","path":"/rows/0/1","equals":4}
//|       - {"artifact":"summary","path":"/rows/0/3","equals":4}
//|       - {"artifact":"summary","path":"/rows/0/2","approx":{"value":8,"atol":1e-15}}
//|       - {"artifact":"summary","path":"/rows/0/4","approx":{"value":8,"atol":1e-15}}
//|   - case: negative-edge
//|     expect:
//|       - {"artifact":"forest","path":"/rows/0/3","approx":{"value":-2,"atol":1e-15}}
//|       - {"artifact":"summary","path":"/rows/0/2","approx":{"value":5,"atol":1e-15}}
//|       - {"artifact":"summary","path":"/rows/0/4","approx":{"value":5,"atol":1e-15}}
//|   - case: heavy-edge
//|     expect:
//|       - {"artifact":"forest","path":"/rows/2/2","equals":3}
//|       - {"artifact":"summary","path":"/rows/0/2","approx":{"value":10,"atol":1e-15}}
//|       - {"artifact":"summary","path":"/rows/0/4","approx":{"value":10,"atol":1e-15}}
//|   - case: drop-zero
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":2}
//|       - {"artifact":"summary","path":"/rows/0/2","approx":{"value":12,"atol":1e-15}}
//|       - {"artifact":"summary","path":"/rows/0/4","approx":{"value":12,"atol":1e-15}}
use scioxide_sparse::{
    DuplicatePolicy, ExplicitZeroPolicy, GraphDirection, GraphPlan, SparseBuilder,
};

let n = 6;
let edges = [
    (0, 1, 0.0_f64),
    (0, 2, 4.0),
    (1, 2, edge_weight),
    (1, 3, 3.0),
    (2, 3, 2.0),
    (2, 4, 5.0),
    (3, 4, 6.0),
];
let zeros = if keep_zero {
    ExplicitZeroPolicy::Preserve
} else {
    ExplicitZeroPolicy::Drop
};
let mut builder = SparseBuilder::new(n, n);
for &(u, v, w) in &edges {
    builder.push(u, v, w).map_err(|e| e.to_string())?;
}
let matrix = builder
    .finish_csr(DuplicatePolicy::Reject, zeros)
    .map_err(|e| e.to_string())?;
let graph =
    GraphPlan::new(matrix.view(), GraphDirection::Undirected).map_err(|e| e.to_string())?;
let forest = graph.minimum_spanning_forest().map_err(|e| e.to_string())?;
let chosen: Vec<_> = forest
    .edges()
    .iter()
    .enumerate()
    .map(|(k, e)| (k + 1, e.u, e.v, e.weight))
    .collect();
let columns = serde_json::json!([
    { "key": "0", "label": "Selection order", "type": "integer" },
    { "key": "1", "label": "Endpoint u", "type": "integer" },
    { "key": "2", "label": "Endpoint v", "type": "integer" },
    { "key": "3", "label": "Weight", "type": "number" }
]);
emit_table_with_columns!(
    columns,
    chosen,
    metadata = serde_json::json!({ "id": "forest" })
);

// Independent check: Drop removes entries whose value is exactly 0, so select retained edges by the same rule.
let kept: Vec<_> = edges
    .iter()
    .copied()
    .filter(|e| keep_zero || e.2 != 0.0)
    .collect();
// Disjoint-set forest root (without path compression).
let root = |parent: &[usize], mut u: usize| {
    while parent[u] != u {
        u = parent[u];
    }
    u
};
// Minimum total weight among acyclic edge subsets with the maximum edge count (spanning forests).
let mut best: Option<(usize, f64)> = None;
for mask in 0..1_usize << kept.len() {
    let mut parent: Vec<usize> = (0..n).collect();
    let mut acyclic = true;
    let mut total = 0.0;
    for (k, &(u, v, w)) in kept.iter().enumerate() {
        if mask >> k & 1 == 1 {
            let (a, b) = (root(&parent, u), root(&parent, v));
            acyclic &= a != b;
            parent[a] = b;
            total += w;
        }
    }
    let count = mask.count_ones() as usize;
    let better = best.is_none_or(|(m, t)| count > m || (count == m && total < t));
    if acyclic && better {
        best = Some((count, total));
    }
}
let columns = serde_json::json!([
    { "key": "0", "label": "Connected-component count c", "type": "integer" },
    { "key": "1", "label": "Forest-edge count", "type": "integer" },
    { "key": "2", "label": "Total weight total_weight", "type": "number" },
    { "key": "3", "label": "Exhaustive edge count", "type": "integer", "nullText": "None" },
    { "key": "4", "label": "Exhaustive minimum", "type": "number", "nullText": "None" }
]);
let summary = (
    forest.components().count(),
    forest.edges().len(),
    forest.total_weight(),
    best.map(|b| b.0),
    best.map(|b| b.1),
);
emit_table_with_columns!(
    columns,
    vec![summary],
    metadata = serde_json::json!({ "id": "summary" })
);
```

At the default $d = 1$, Kruskal's algorithm selects $\{0, 1\}$ (weight 0), $\{1, 2\}$ (1), and $\{2, 3\}$ (2).
It skips $\{1, 3\}$ and $\{0, 2\}$ because they create cycles, then selects $\{2, 4\}$ (5).
The two connected components are $\{0, 1, 2, 3, 4\}$ and $\{5\}$; the forest has $V - c = 6 - 2 = 4$ edges and total weight 8, matching the exhaustive edge count and minimum total weight.
At $d = -2$, the negative-weight edge $\{1, 2\}$ is selected first and the sum decreases to 5.
At $d = 8$, $\{1, 2\}$ creates a cycle and is skipped; $\{1, 3\}$ is included instead, giving a sum of 10.
Removing zero-weight edges connects vertex 0 through edge $\{0, 2\}$ of weight 4, increasing the sum to 12.
Retaining or removing zero-weight edges changes the forest edges and total weight even when the connected-component count stays the same.

## Graph Laplacians

For an undirected graph with nonnegative weights, let $\mathbf{W}$ be its weight matrix ($w_{ij} = w_{ji} \ge 0$, with zero diagonal), $d_i = \sum_j w_{ij}$ the degree of vertex $i$, and $\mathbf{D} = \mathrm{diag}(d_i)$; the graph Laplacian is $\mathbf{L} = \mathbf{D} - \mathbf{W}$.
Using symmetry of $\mathbf{W}$ to rewrite the quadratic form gives

$$
\mathbf{x}^{\mathsf{T}}\mathbf{L}\mathbf{x}
= \sum_i d_i x_i^2 - \sum_{i, j} w_{ij} x_i x_j
= \frac{1}{2}\sum_{i, j} w_{ij}\,(x_i - x_j)^2
= \sum_{\{i, j\} \in E} w_{ij}\,(x_i - x_j)^2
$$

The right-hand side is nonnegative, so $\mathbf{L}$ is positive semidefinite.
For a positive semidefinite matrix, $\mathbf{L}\mathbf{x} = \mathbf{0}$ and $\mathbf{x}^{\mathsf{T}}\mathbf{L}\mathbf{x} = 0$ are equivalent; the latter means $x_i = x_j$ on every edge with $w_{ij} > 0$.
Thus the nullspace of $\mathbf{L}$ consists of vectors constant on each connected component of the graph containing only positive-weight edges, and the multiplicity of eigenvalue 0 equals the number of those components.
Zero-weight edges do not appear in the quadratic form, so these components remain separate even when connected structurally.

Ordering the eigenvalues as $0 = \lambda_1 \le \lambda_2 \le \cdots \le \lambda_V$, the second eigenvalue $\lambda_2$ is called the **algebraic connectivity**.
Since an eigenvector for $\lambda_1$ is $\mathbf{1}$, the Courant–Fischer theorem gives

$$
\lambda_2 = \min_{\mathbf{x} \ne \mathbf{0},\ \mathbf{x} \perp \mathbf{1}} \frac{\mathbf{x}^{\mathsf{T}}\mathbf{L}\mathbf{x}}{\mathbf{x}^{\mathsf{T}}\mathbf{x}}
$$

the relation above holds.
The ratio $\mathbf{x}^{\mathsf{T}}\mathbf{L}\mathbf{x} / \mathbf{x}^{\mathsf{T}}\mathbf{x}$ minimized on the right is called the **Rayleigh quotient**.
The Rayleigh quotient of any vector orthogonal to $\mathbf{1}$ bounds $\lambda_2$ from above.
For a graph separable into two parts by cutting a few light edges, the corresponding vector orthogonal to $\mathbf{1}$ has a small Rayleigh quotient, so $\lambda_2$ is also small ([graph partitioning with the Fiedler vector](../../examples/spectral-bisection/)).
In electrical circuits, with $w_{ij}$ as conductance, $\mathbf{L}$ is the nodal-analysis matrix ([nodal analysis of resistor networks and Foster's theorem](../../examples/resistor-network/)).

When all degrees are positive, the symmetrically normalized Laplacian is

$$
\mathbf{L}_{\mathrm{sym}} = \mathbf{D}^{-1/2}(\mathbf{D} - \mathbf{W})\mathbf{D}^{-1/2}
$$

the expression above.
Setting $\mathbf{x} = \mathbf{D}^{1/2}\mathbf{y}$ gives $\mathbf{x}^{\mathsf{T}}\mathbf{L}_{\mathrm{sym}}\mathbf{x} = \mathbf{y}^{\mathsf{T}}\mathbf{L}\mathbf{y}$, so the nullspace contains $\mathbf{D}^{1/2}\mathbf{1}$ and the Rayleigh quotient is

$$
\frac{\mathbf{x}^{\mathsf{T}}\mathbf{L}_{\mathrm{sym}}\mathbf{x}}{\mathbf{x}^{\mathsf{T}}\mathbf{x}}
= \frac{\sum_{\{i, j\} \in E} w_{ij}\,(y_i - y_j)^2}{\sum_i d_i\,y_i^2}
$$

the expression above.
By $(y_i - y_j)^2 \le 2(y_i^2 + y_j^2)$ and $\sum_{\{i, j\} \in E} w_{ij}(y_i^2 + y_j^2) = \sum_i d_i y_i^2$, this ratio is at most 2.
Thus the eigenvalues of $\mathbf{L}_{\mathrm{sym}}$ lie in $[0, 2]$.

`GraphPlan::laplacian::<T>(degree, normalization)` builds a `LaplacianPlan` storing the Laplacian as a CSR matrix.
`T` is either the weight type `S` or a complex type with real component `S`, allowing application to complex vectors.
Writing matrix entry $(u, v)$ as $w_{uv}$, `LaplacianDegree::Out` uses the row sum $d_u = \sum_v w_{uv}$ as degree, and `In` uses the column sum $d_v = \sum_u w_{uv}$.
For undirected graphs, both give the same degrees.
For an unnormalized directed graph, `Out` gives $\mathbf{L}\mathbf{1} = \mathbf{0}$, and `In` gives $\mathbf{1}^{\mathsf{T}}\mathbf{L} = \mathbf{0}^{\mathsf{T}}$.
`LaplacianNormalization::Unnormalized` is $\mathbf{D} - \mathbf{W}$, and `Symmetric` is $\mathbf{D}^{-1/2}(\mathbf{D} - \mathbf{W})\mathbf{D}^{-1/2}$; for a zero-degree vertex a scale of 1 replaces $d^{-1/2}$, leaving its diagonal entry at 0.
Self-loops are included in neither $\mathbf{D}$ nor $\mathbf{W}$.
The matrix contains every diagonal entry, including zero-degree vertices, and entry $(u, v)$ for every directed edge $(u, v)$ in $u \ne v$, retaining zero-weight edges as explicitly stored zeros.

Negative weights, including self-loop weights, are rejected with `DomainError`.
An unrepresentable degree sum fails with `NumericalInstability` (`Overflow`); a positive weight rounded to zero during symmetric normalization fails with `NumericalInstability` (`Underflow`).
`degrees()` returns degrees excluding self-loops, while `matrix()` and `into_matrix()` return the CSR matrix.
`LaplacianPlan` implements `LinearOperator`, `AdjointOperator`, and `BlockOperator` and can be passed directly to scioxide-linalg iterative solvers and eigenvalue computations.
The one-shot function `laplacian(matrix)` reads the matrix as a directed graph and returns the unnormalized $\mathbf{D} - \mathbf{W}$ with `Out` degrees as a CSR matrix.
Including Plan preparation, the complexity is $O(V + E \log E)$.
A symmetric input matrix gives an undirected graph Laplacian.

### A zero-weight bridge and the Laplacian nullspace

The following cell builds the Laplacian of an undirected graph consisting of weight-1 triangles $C = \{0, 1, 2\}$ and $\{3, 4, 5\}$ joined by bridge $\{2, 3\}$ of weight $b$.
The inputs are $b$ (0–2) and whether to normalize.
It tests three vectors $\mathbf{y}$, multiplying the `LaplacianPlan` matrix by $\mathbf{x} = \mathbf{y}$ without normalization and by $\mathbf{x} = \mathbf{D}^{1/2}\mathbf{y}$ with symmetric normalization.
$\mathbf{y} = \mathbf{1}$ should belong to the nullspace, $\mathbf{1}_C$ is the indicator vector of triangle $C$, and $\mathbf{1}_C - \tfrac{1}{2}\mathbf{1}$ is orthogonal to the nullspace.
The last vector also satisfies $\sum_i d_i y_i = 0$, so for either normalization its Rayleigh quotient bounds the matrix's $\lambda_2$ from above.
As a check, $\mathbf{x}^{\mathsf{T}}\mathbf{L}\mathbf{x}$ is computed independently from the edge list using $\sum w_{ij}(y_i - y_j)^2$.
The second table counts the connected components of the structure retaining zero-weight entries and of the graph containing only positive-weight edges, using `connected_components`.

```rust

//| inputs:
//|   bridge: {"type":"range","label":"Weight b of bridge {2, 3}","description":"At 0, the bridge remains in the structure but contributes zero to the Laplacian.","min":0.0,"max":2.0,"step":0.25,"value":1.0}
//|   scaling: {"type":"select","label":"Normalization","options":[{"label":"None (D − W)","value":"none"},{"label":"Symmetric (D^(−1/2)(D − W)D^(−1/2))","value":"symmetric"}],"value":"none"}

//|   - {"id":"zero-bridge","label":"b = 0","description":"The structure remains connected, but 1_C also enters the nullspace and eigenvalue 0 has multiplicity two.","inputs":{"bridge":0}}

//|       - {"artifact":"components","path":"/rows/0/1","equals":1}
//|   - case: zero-bridge
//|     expect:
//|       - {"artifact":"quadratic","path":"/rows/1/1","range":{"max":1e-15}}
//|       - {"artifact":"quadratic","path":"/rows/2/4","range":{"max":1e-15}}
//|       - {"artifact":"components","path":"/rows/0/0","equals":1}
//|       - {"artifact":"components","path":"/rows/0/1","equals":2}
//|   - case: symmetric
//|     expect:
//|       - {"artifact":"quadratic","path":"/rows/0/1","range":{"max":1e-14}}
//|       - {"artifact":"quadratic","path":"/rows/1/2","approx":{"value":1,"rtol":1e-12}}
//|       - {"artifact":"quadratic","path":"/rows/2/4","approx":{"value":0.2857142857142857,"rtol":1e-12}}
use scioxide_core::RealScalar;
use scioxide_sparse::{
    DuplicatePolicy, ExplicitZeroPolicy, GraphDirection, GraphPlan, LaplacianDegree,
    LaplacianNormalization, SparseBuilder, connected_components,
};

// Join triangles C = {0, 1, 2} and {3, 4, 5} (weight 1) with bridge {2, 3} of weight b.
let edges = [
    (0, 1, 1.0_f64),
    (0, 2, 1.0),
    (1, 2, 1.0),
    (3, 4, 1.0),
    (3, 5, 1.0),
    (4, 5, 1.0),
    (2, 3, bridge),
];
let n = 6;
let assemble = |zeros| {
    let mut builder = SparseBuilder::new(n, n);
    for &(u, v, w) in &edges {
        builder.push(u, v, w).map_err(|e| e.to_string())?;
    }
    builder
        .finish_csr(DuplicatePolicy::Reject, zeros)
        .map_err(|e| e.to_string())
};
let kept = assemble(ExplicitZeroPolicy::Preserve)?;
// Also build a matrix with zero-valued entries removed to count components using only positive-weight edges.
let positive = assemble(ExplicitZeroPolicy::Drop)?;
let structural = connected_components(kept.structural_pattern()).map_err(|e| e.to_string())?;
let weighted =
    connected_components(positive.structural_pattern()).map_err(|e| e.to_string())?;

let graph =
    GraphPlan::new(kept.view(), GraphDirection::Undirected).map_err(|e| e.to_string())?;
let symmetric = scaling == "symmetric";
let normalization = if symmetric {
    LaplacianNormalization::Symmetric
} else {
    LaplacianNormalization::Unnormalized
};
let plan = graph
    .laplacian::<f64>(LaplacianDegree::Out, normalization)
    .map_err(|e| e.to_string())?;
let degrees = plan.degrees();
let candidates: [(&str, fn(usize) -> f64); 3] = [
    ("1", |_| 1.0),
    ("1_C", |i| if i < 3 { 1.0 } else { 0.0 }),
    ("1_C − 1/2", |i| if i < 3 { 0.5 } else { -0.5 }),
];
let mut rows = Vec::new();
for (name, y) in candidates {
    // Multiply the symmetrically normalized L by x = D^{1/2} y.
    let x: Vec<f64> = (0..n)
        .map(|i| {
            if symmetric {
                RealScalar::sqrt(degrees[i]) * y(i)
            } else {
                y(i)
            }
        })
        .collect();
    let lx = plan.matrix().apply(&x).map_err(|e| e.to_string())?;
    let residual = lx.iter().map(|v| v * v).sum::<f64>().sqrt();
    let form: f64 = x.iter().zip(&lx).map(|(a, b)| a * b).sum();
    // Independent check: compute the quadratic form from the edge list as Σ w_ij (y_i − y_j)².
    let by_edges: f64 = edges
        .iter()
        .map(|&(i, j, w)| w * (y(i) - y(j)).powi(2))
        .sum();
    let rayleigh = form / x.iter().map(|v| v * v).sum::<f64>();
    rows.push((name, residual, form, by_edges, rayleigh));
}
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let fixed6 = serde_json::json!({ "significantDigits": 6 });
let columns = serde_json::json!([
    { "key": "0", "label": "y", "type": "string" },
    { "key": "1", "label": "‖Lx‖₂", "type": "number", "format": sci3 },
    { "key": "2", "label": "xᵀLx", "type": "number", "format": fixed6 },
    { "key": "3", "label": "Σ w(yᵢ − yⱼ)²", "type": "number", "format": fixed6 },
    { "key": "4", "label": "Rayleigh quotient xᵀLx / xᵀx", "type": "number", "format": fixed6 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "quadratic" })
);
let columns = serde_json::json!([
    { "key": "0", "label": "Structural connected-component count", "type": "integer" },
    { "key": "1", "label": "Connected-component count using only positive-weight edges", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    vec![(structural.count(), weighted.count())],
    metadata = serde_json::json!({ "id": "components" })
);
```

At the default $b = 1$ without normalization, $\mathbf{y} = \mathbf{1}$ gives $\lVert \mathbf{L}\mathbf{x} \rVert_2 = 0$, so the constant vector belongs to the nullspace.
For $\mathbf{1}_C$, the entries of $\mathbf{L}\mathbf{1}_C$ are $b$ at vertex 2 and $-b$ at vertex 3, giving $\lVert \mathbf{L}\mathbf{x} \rVert_2 = \sqrt{2}\,b \approx 1.414$.
The quadratic form consists solely of the bridge contribution $b = 1$ and agrees with the edge-list calculation in every row.
The Rayleigh quotient of $\mathbf{1}_C - \tfrac{1}{2}\mathbf{1}$ is $b/(6/4) = 2b/3 \approx 0.667$, establishing $\lambda_2 \le 0.667$.
At $b = 0$, the bridge entry remains in the structure, leaving one structural component, but $\mathbf{1}_C$ also satisfies $\mathbf{L}\mathbf{x} = \mathbf{0}$.
There are two components using only positive-weight edges, eigenvalue 0 has multiplicity two, and $\lambda_2 = 0$.
With symmetric normalization, $\lVert \mathbf{L}\mathbf{x} \rVert_2$ for $\mathbf{x} = \mathbf{D}^{1/2}\mathbf{1}$ is $5.4 \times 10^{-16}$, differing from zero only by square-root rounding.
The last vector's Rayleigh quotient becomes $b/\sum_i d_i y_i^2 = 2b/(6 + b) \approx 0.286$.

## Summary

Stored sparse entries become edges under the direction convention, and stored zeros are zero-weight edges, so the assembly zero policy determines graph connectivity.
Weights are lengths for minimum spanning forests and shortest paths, but connection strengths for Laplacians; transform values for the intended purpose before building a Plan.
Traversal and connected components cost $O(V + E)$, with Kosaraju's algorithm used for strongly connected components.
Kruskal's algorithm finds a minimum spanning forest in $O(E \log E)$ with $V - c$ edges, and its total weight is the exact sum rounded once.
The multiplicity of Laplacian eigenvalue 0 equals the number of connected components using only positive-weight edges, and `LaplacianPlan` can be used directly as an operator for eigenvalue computations and linear systems.
