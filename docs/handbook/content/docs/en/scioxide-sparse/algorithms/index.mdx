Storage, products, direct factorizations, preconditioners, orderings, and graph algorithms in this chapter all rely on several shared contracts.
They separate structure from values and structural phases from numerical phases, let the caller set storage limits, and preserve output on failure.
This page collects these contracts, notation, and names for calling forms assumed by each algorithm page and provides the page map.
[Error contracts and partial results](../../concepts/errors-and-partial-results/) and [Execution modes, workspaces, and reproducibility](../../concepts/workspaces-and-reproducibility/) cover shared cross-crate ideas for errors, workspaces, and tolerances.

## Notation

| Symbol | Meaning |
|---|---|
| $\mathbf{A} \in \mathbb{R}^{m \times n}$ (or $\mathbb{C}^{m \times n}$) | Sparse matrix |
| $\mathcal{S}(\mathbf{A})$ | Set of stored positions (nonzero pattern, structure) |
| $\mathrm{nnz}(\mathbf{A}) = \lvert \mathcal{S}(\mathbf{A}) \rvert$ | Stored entry count |
| $G(\mathbf{A})$ | Graph with edges given by square $\mathbf{A}$'s structure |
| $p[\text{new}] = \text{old}$ | Permutation `Permutation` orientation (`new_to_old()`). Gathers original indices as in $\mathbf{B}_{ij} = \mathbf{A}_{p[i], p[j]}$ |
| $\varepsilon = 2^{-52}$ | Double-precision machine epsilon |
| $u = \varepsilon/2 = 2^{-53}$ | Double-precision unit roundoff |
| $\gamma_k = ku/(1 - ku)$ | Error-bound factor for $k$ successive roundings (Higham notation) |
| $\kappa_2(\mathbf{A})$ | 2-norm condition number |

## Structure and values

All `scioxide-sparse` storage formats are canonical: each position appears once in fixed order, and every stored value is finite ([Sparse-matrix storage and assembly](storage-and-assembly/)).
There is no method to insert or delete entries in a finalized matrix.
Values can be changed through `set_value`, `copy_values_from`, and `update_values` on `CooMatrix`, `CsrMatrix`, and `CscMatrix` after finite-value validation.
`BsrMatrix` and `DiaMatrix` have no value-update methods; update a canonical format and convert again.
`CsrMatrix::try_assign_pattern` replaces the entire shape and structure and zeroes all values, reusing only storage.
Analyses, factors, and plans built from the previous structure cannot be used with the replacement matrix.

If structure is unchanged, everything computed from it (orderings, elimination trees, product structure, workspace sizes) remains reusable.
For time evolution or Newton methods changing only coefficients, compute structure once and repeat numerical work.

## Implicit and explicitly stored zeros

An **implicit zero** is a position outside $\mathcal{S}(\mathbf{A})$; it consumes no storage and algorithms do not visit it.
An **explicitly stored zero** is a position in $\mathcal{S}(\mathbf{A})$ whose value is exactly 0.
Explicitly stored zeros are structural: symbolic analysis includes them in fill calculations, graphs treat them as zero-weight edges, and structure comparison includes them in equality checks.
Choose treatment with assembly `ExplicitZeroPolicy::Preserve` and `Drop`; cancellation-created zeros follow the same rule.
Choose `Preserve` to keep coefficient values from changing structure.

## Symbolic and numerical phases

Many algorithms split into a structure-only symbolic phase and a value-dependent numerical phase.
The symbolic phase is value-independent and need run only once for a fixed structure.
What it can determine varies by algorithm.

| Algorithm | Determined symbolically | Determined numerically |
|---|---|---|
| Sparse product (`SparseProductPlan`) | Output structure, ignoring cancellation | Values |
| Cholesky (`SparseSymmetricSymbolic`) | Ordering, elimination tree, structural fill | Values |
| LDL (same) | Ordering and Cholesky structure | 1×1/2×2 pivot selection and resulting additional fill |
| LU (`SparseLuSymbolic`) | Column order | Row pivots and fill |
| QR (`SparseQrSymbolic`) | Column order | Householder vectors, structure and values of $\mathbf{R}$, and rank in minimum-norm plans |
| Incomplete factorization (`IncompleteSymbolic`) | Copy of input structure and block size | Fill positions and values determined by level or threshold |
| AMG (`AmgHierarchy`) | None (aggregation is value-dependent) | Entire hierarchy |

For products and Cholesky, the symbolic phase determines numerical-phase storage size.
LU/LDL factor sizes depend on pivoting; QR and incomplete factorizations determine factor structures numerically, so factor sizes remain unknown until the numerical phase finishes.
These factorizations bound storage with caller-supplied limits ([Limits and workspaces](#limits-and-workspaces)).
`refactor` repeats numerical factorization only for matrices whose structure exactly matches the symbolic analysis, rejecting other structures with `InvalidInput`.

## Calling forms

The same computation has several calling forms depending on the control required.
This chapter names argument/result forms as follows.

| Form | Examples | Accepts | Returns | Execution context |
|---|---|---|---|---|
| Single-call function | `solve(&a, &b)`, `least_squares`, `shortest_paths`, `connected_components`, `maximum_flow`, `maximum_bipartite_matching`, `minimum_cost_assignment`, `laplacian` | Problem data only | Answer | `sequential_native()` |
| Single-call constructor | `SparseLu::new(&a)`, `SparseCholesky::new`, `SparseLdl::new`, `SparseQrMinimumNormPlan::new`, `IncompleteFactor::ilu0`/`ic0`, `AmgPreconditioner::new`, `JacobiPreconditioner::new` | Matrix only | Factors, plan, or preconditioner | `sequential_native()` |
| Ordinary | `SparseLu::factor(symbolic, a.view())`, `lu.solve(&b)`, `solve_transpose`, `solve_adjoint`, preconditioner `apply(&r)`, `graph.shortest_paths(method)` | Prepared value and input only | Newly allocated result | `sequential_native()` |
| Detailed | `maximum_bipartite_matching_with_options(pattern, options)`, `a.add_with_options(&b, options)`, `SparseProductPlan::with_options(&a, &b, options)` | Input, then options last | Newly allocated result | `sequential_native()` |
| Borrowed | `lu.solve_into(&b, operation, options, &mut x, &mut ws, scope)`, `plan.evaluate_into(&a, &b, options, &mut c, &mut ws, context)` | Input, options, output, workspace, context, in that order | Writes output | Supplied context |
| Scoped | `SparseLu::factor_scoped(symbolic, a.view(), options, scope)`, `graph.shortest_paths_scoped(method, options, &mut ws, scope)` | Input, options, workspace if any, context last | Value | Supplied context |

A single-call function is a free function solving a problem once and returning only the answer.
Internal analyses, factorizations, and plans use settings defined by the function.
For example, `solve(&a, &b)` calls `SparseLu::new` followed by `solve`.
`least_squares` determines numerical rank at threshold $\tau = \min(\max(m, n)\,\varepsilon,\ 1/2) \max_j \lVert \mathbf{A}_{:,j} \rVert_2$ and returns a minimum-norm solution.
`shortest_paths` uses Dijkstra without negative weights and Bellman–Ford otherwise, returning `DomainError` for a negative cycle reachable from the source.
The graph plan's ordinary `GraphPlan::shortest_paths` returns the same negative cycle as a result value rather than an error.

Single-call constructors, such as `new`, perform analysis through factorization or construction without taking limits.
Direct-factorization `new` selects its own factor-entry limit.
`SparseCholesky::new` uses exactly the factor-entry count predicted by symbolic analysis as the limit.
`SparseLu::new`, `SparseLdl::new`, and `SparseQrMinimumNormPlan::new` start from estimated limits and double after each `ResourceLimit` failure, stopping at a size no factor of that matrix can exceed.
Estimates and stopping sizes are $\mathrm{nnz}(\mathbf{A}) + n$ and $n^2$ for LU, the Cholesky entry count and $n(n-1)/2$ for LDL, and $\mathrm{nnz}(\mathbf{A}) + \max(m, n)$ and $\min(m, n)\,(m + n)$ for $m \times n$ QR (QR also doubles the intermediate nonzero limit, stopping at $mn$).
Since limits are used only for capacities and comparisons, either rule returns the same factors as analysis and factorization with sufficient limits.
Failed attempts only repeat computation and do not change results.
`IncompleteFactor::ilu0` and `ic0` analyze with natural ordering, block size 1, limit $\mathrm{nnz}(\mathbf{A}) + n$ blocks, and no byte limit.
`AmgPreconditioner::new` builds a hierarchy with default settings and the constant vector as near-nullspace.

Ordinary forms are methods on prepared analyses, factors, preconditioners, or graph plans, taking no options, workspace, or context.
They return the same numbers as corresponding scoped or borrowed forms with default options (`SparseSolveOptions::new()` or `GraphExecutionOptions::new()`), newly allocated workspace, and `ExecutionContext::sequential_native()`.
`sequential_native()` runs sequentially on the calling thread, dispatches to CPU-specific kernels when `std` is present, and has no clock, cancellation, or random source.

Detailed forms have names ending in `_with_options` and take options last.
Here these include `maximum_bipartite_matching_with_options` taking iteration limits and `add_with_options`/`subtract_with_options`/`hadamard_with_options` and `SparseView::scaled_with_options` on `CsrMatrix` taking accuracy and zero policies.
Constructors `SparseProductPlan::with_options` (output-entry limit) and `SchwarzPlan::with_options` (storage limits and weight tolerances) follow the same form.
As with ordinary forms, results are newly allocated.

Borrowed forms have names ending in `_into` and write caller-provided output and workspace.
`solve_into`, `solve_block_into`, preconditioner `apply_into`/`apply_block_into`, `SparseProductPlan::evaluate_into`, and `sparse_dense_into` also take options and contexts.
The scioxide-core operator-trait methods `LinearOperator::apply_into(x, y, workspace)` and `Preconditioner::precondition_into` take no options or context and compute sequentially with defaults.
Accuracy is `Standard`, except `SparseOperator` returned by `SparseView::with_accuracy` uses its attached accuracy setting.
Despite its different name, numerical refactorization `refactor(matrix, options, workspace, scope)` updates factors as output under the same rules as borrowed forms.
Borrowed forms and `refactor` with reserved workspace do not allocate.

Scoped forms have names ending in `_scoped`, take options and contexts, and return values rather than writing arrays.
`factor_scoped` returns factors.
Graph `shortest_paths_scoped`, `maximum_flow_scoped`, `AssignmentPlan::solve_scoped`, and `maximum_bipartite_matching_scoped` also take workspace and return result views borrowing it.
Such views remain usable until the workspace is passed to another call.
`AmgHierarchy::build`, `AmgPreconditioner::build`, and `SparseQrMinimumNormPlan::build` likewise take options and context last and return values.

Pass borrowed/scoped factorization, solve, preconditioner, and graph methods either a root context such as `ExecutionContext::sequential()` or an enclosing solver's `SolveContext`.
With an enclosing solver context, the call's iterations also count against that solver's limit.
Borrowed products `evaluate_into` and `sparse_dense_into` take only `ExecutionContext` and count no iterations.
Contexts lend parallel executors, cancellation, and deadlines, so only borrowed and scoped forms can use them.

Use single-call functions for one-off answers, and single-call constructors or ordinary factorization for repeated solves with the same matrix.
Use borrowed/scoped forms to remove allocations inside iterations, use parallelism or cancellation, or share iteration limits with an enclosing solver.

## Limits and workspaces

With a poor ordering, sparse direct-factorization fill can grow to an $O(n^2)$ dense matrix.
Forms building factorizations or preconditioners from symbolic analyses or constructors with limits therefore require an allowed-storage limit and stop with `ResourceLimit` on excess.
Limit types differ by algorithm.

| Type | Constructor | Limits |
|---|---|---|
| `SparseLuLimits` | `new(max_factor_entries, max_workspace_bytes)` | Factor entries and logical bytes |
| `SparseSymmetricLimits` | `new(max_factor_entries, max_active_entries, max_workspace_bytes)` | Factors, intermediate Schur-complement nonzeros, bytes |
| `SparseQrLimits` | `new(max_factor_entries, max_active_entries, max_workspace_bytes)` | Householder vectors and $\mathbf{R}$, uneliminated submatrix, bytes |
| `IncompleteLimits` | `new(max_factor_blocks, max_workspace_bytes)` | Stored block count and bytes |
| `AmgLimits` | `new(max_levels, max_entries, max_setup_bytes)` | Hierarchy depth, entries in each matrix/product, construction bytes |
| `SchwarzOptions` | `new().with_max_plan_bytes(…).with_max_workspace_bytes(…)` | Plan and workspace bytes (unlimited by default) |

`JacobiPreconditioner::new` uses storage only proportional to dimension, and `IdentityPreconditioner::new` allocates no storage, so neither takes limits.
Single-call functions and constructors also take no limits; direct factorizations choose factor-entry limits using the rules in [Calling forms](#calling-forms).
Byte counts are logical quantities excluding allocator overhead and depend on `usize` width, so the same limit may pass in 32-bit environments and fail in 64-bit environments or vice versa.

Required amounts can be queried before allocation.
Each algorithm's `workspace_requirements(...)` returns `*Requirements` (bytes or entries); workspace types such as `SparseLuWorkspace` check sufficiency with `check` and reserve with `try_reserve`.
`workspace(...)` combines querying and reservation.
Numerical phases with reserved workspace do not allocate.
In contrast, `SparseBuilder::push`, ordinary `solve` or `multiply`, and format conversions allocate as needed.
Direct/incomplete factorizations, triangular solves, and preconditioner solves share `SparseSolveWorkspace`; `SparseSolveWorkspace::borrowed(&mut scratch)` can also borrow caller-owned arrays.
Borrowed arrays are checked only for length; when longer than required, only the required prefix is used.

## Output on failure

Output-writing operations (borrowed forms, `refactor`, value updates) complete every check and computation in workspace before updating output or factors all at once.
Thus failure leaves caller output, previously successful factors, and matrix values unchanged.
Workspace contents may be unspecified after failure, but the workspace remains reusable in the next call.
Workspace `last_attempt()` returns the last attempt's record.
No partial results are exposed.

### Values before and after failed operations

The following cell tries 4 operations in sequence on LU factors of the $3 \times 3$ upper-triangular matrix $\mathbf{A}$ and on $\mathbf{A}$ itself.
First solve with a length-2 right side; second solve with borrowed workspace of length equal to the required size $+\,d$.
The third solves $\mathbf{b} = (1, 1, 1)$ again, reusing the first failure's factors and workspace unchanged.
The fourth is `update_values` writing NaN to one candidate value.
Inputs are the prefilled output value $c$ and workspace-length difference $d$.
For each operation the table reports result classification, number of changed destination entries, and residual $\lVert \mathbf{b} - \mathbf{A}\hat{\mathbf{x}} \rVert_\infty$ for successful solves.
Compute residuals with a `apply` product separately from the solve.

```rust
//| id: sparse-transactional-failure
//| ref: sparse-transactional-failure
//| title: "Output and values before and after failed operations"
//| run: reactive
//| crates: [scioxide-core, scioxide-sparse]
//| inputs:
//|   initial_value: {"type":"range","label":"Initial output value c","description":"Value used to prefill solve output.","min":1.0,"max":10.0,"step":1.0,"value":7.0}
//|   scratch_offset: {"type":"range","label":"Workspace length minus requirement d","description":"Offset the second solve's borrowed-workspace length from the requirement.","min":-2,"max":2,"step":1,"value":-1}
//| cases:
//|   - {"id":"long-scratch","label":"d = 1","description":"Workspace longer than required is accepted; the second solve also succeeds and replaces output with the solution.","inputs":{"scratch_offset":1}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"attempts","path":"/rows/0/1","equals":"DimensionMismatch"}
//|       - {"artifact":"attempts","path":"/rows/0/3","equals":0}
//|       - {"artifact":"attempts","path":"/rows/1/1","equals":"DimensionMismatch"}
//|       - {"artifact":"attempts","path":"/rows/1/3","equals":0}
//|       - {"artifact":"attempts","path":"/rows/2/1","equals":"Success"}
//|       - {"artifact":"attempts","path":"/rows/2/3","equals":3}
//|       - {"artifact":"attempts","path":"/rows/2/5","range":{"max":1e-15}}
//|       - {"artifact":"attempts","path":"/rows/3/1","equals":"NonFinite"}
//|       - {"artifact":"attempts","path":"/rows/3/3","equals":0}
//|   - case: long-scratch
//|     expect:
//|       - {"artifact":"attempts","path":"/rows/1/1","equals":"Success"}
//|       - {"artifact":"attempts","path":"/rows/1/3","equals":3}
//|       - {"artifact":"attempts","path":"/rows/1/5","range":{"max":1e-15}}
use scioxide_core::{ExecutionContext, SciOxideError};
use scioxide_sparse::{
    CsrMatrix, DuplicatePolicy, ExplicitZeroPolicy, SparseBuilder, SparseLu, SparseLuLimits,
    SparseLuSymbolic, SparseOperation, SparseOrdering, SparseSolveOptions,
    SparseSolveWorkspace,
};

// Try one solve and return (result classification, changed-entry count, residual).
fn solve_attempt(
    lu: &SparseLu<f64>,
    a: &CsrMatrix<f64>,
    rhs: &[f64],
    start: [f64; 3],
    workspace: &mut SparseSolveWorkspace<'_, f64>,
) -> Result<(String, usize, Option<f64>), String> {
    let (options, scope) = (SparseSolveOptions::new(), ExecutionContext::sequential());
    let mut x = start;
    let result = lu.solve_into(
        rhs,
        SparseOperation::Normal,
        options,
        &mut x,
        workspace,
        scope,
    );
    let changed = x.iter().zip(&start).filter(|(u, v)| u != v).count();
    match result {
        Ok(()) => {
            // Independent check: form A x̂ separately from the solve and compute ‖b − A x̂‖∞.
            let ax = a.apply(&x).map_err(|e| e.to_string())?;
            let r = rhs
                .iter()
                .zip(&ax)
                .fold(0.0_f64, |m, (u, v)| m.max((u - v).abs()));
            Ok(("Success".to_string(), changed, Some(r)))
        }
        Err(e) => Ok((format!("{:?}", e.kind()), changed, None)),
    }
}

// Build LU factors of A = [[2, 0, 0], [0, 3, 1], [0, 0, 4]] with natural ordering.
let mut builder = SparseBuilder::new(3, 3);
builder
    .extend(&[0, 1, 1, 2], &[0, 1, 2, 2], &[2.0_f64, 3.0, 1.0, 4.0])
    .map_err(|e| e.to_string())?;
let mut a = builder
    .finish_csr(DuplicatePolicy::Reject, ExplicitZeroPolicy::Drop)
    .map_err(|e| e.to_string())?;
let symbolic = SparseLuSymbolic::analyze(
    a.structural_pattern(),
    SparseOrdering::Natural,
    SparseLuLimits::new(16, 1 << 16),
)
.map_err(|e| e.to_string())?;
let lu = SparseLu::factor(symbolic, a.view()).map_err(|e| e.to_string())?;
let (b, start) = ([1.0_f64, 1.0, 1.0], [initial_value; 3]);
let needed = lu
    .workspace_requirements(1)
    .map_err(|e| e.to_string())?
    .scalar_len();
let mut scratch = vec![0.0_f64; needed];
let mut workspace = SparseSolveWorkspace::borrowed(&mut scratch);
let mut rows = Vec::new();

// 1. Length-2 right side.
let (kind, changed, r) = solve_attempt(&lu, &a, &b[..2], start, &mut workspace)?;
rows.push(("Solve with length-2 right side", kind, "Output x", changed, 3, r));
// 2. Borrowed workspace of length required + d.
let mut other = vec![0.0_f64; (needed as f64 + scratch_offset) as usize];
let mut short = SparseSolveWorkspace::borrowed(&mut other);
let (kind, changed, r) = solve_attempt(&lu, &a, &b, start, &mut short)?;
rows.push(("Solve with workspace of length required + d", kind, "Output x", changed, 3, r));
// 3. Solve again with the correct right side and the first failure's factors and workspace.
let (kind, changed, r) = solve_attempt(&lu, &a, &b, start, &mut workspace)?;
rows.push((
    "Solve again with the same factors and workspace",
    kind,
    "Output x",
    changed,
    3,
    r,
));
// 4. Value update writing NaN to one candidate.
let before = a.values().to_vec();
let mut values = a.workspace(()).map_err(|e| e.to_string())?;
let result = a.update_values(
    |old, next| {
        next.copy_from_slice(old);
        next[1] = f64::NAN;
        Ok::<_, SciOxideError>(())
    },
    &mut values,
);
let kind = result.map_or_else(|e| format!("{:?}", e.kind()), |()| "Success".to_string());
let changed = a
    .values()
    .iter()
    .zip(&before)
    .filter(|(u, v)| u != v)
    .count();
rows.push((
    "update_values writing NaN",
    kind,
    "Matrix values",
    changed,
    4,
    None,
));

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "Operation" },
    { "key": "1", "label": "Result e.kind()" },
    { "key": "2", "label": "Destination" },
    { "key": "3", "label": "Changed entries [count]", "type": "integer" },
    { "key": "4", "label": "Entries [count]", "type": "integer" },
    { "key": "5", "label": "Residual ‖b − Ax̂‖∞ [-]", "type": "number", "format": sci3, "nullText": "No solution" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "attempts" })
);
```

At the defaults $c = 7$, $d = -1$, both first and second solves are rejected with `DimensionMismatch`; all 3 output entries remain $c$.
For the second, insufficient workspace is detected in checks before output is written.
The third solve succeeds, changing all 3 output entries to the solution and giving residual 0.
After a failed call, factors `lu` and workspace remain usable unchanged for the next computation.
The fourth, a value update, is rejected with `NonFinite`, leaving all 4 matrix values as before.
Setting $d = 1$ supplies longer-than-required workspace, which is accepted and lets the second solve succeed.
The borrowed array's excess beyond the requirement is unused.

## Iteration limits and execution contexts

Borrowed/scoped factorization, solve, preconditioner, and graph forms obey the `SolveBudgets` iteration limit supplied through `SparseSolveOptions::with_budgets` (`GraphExecutionOptions::with_budgets` for graphs).
Each algorithm counts iterations in a defined unit.

| Algorithm | One counted iteration |
|---|---|
| LU/QR numerical factorization | One column |
| QR minimum-norm plan construction (`build`) | One column examined in either factorization |
| Cholesky/LDL numerical factorization | One factor row (2 rows for an LDL 2×2 pivot) |
| Incomplete factorization | One block row |
| AMG hierarchy construction (`AmgHierarchy::build`) | One row, one aggregate, or one product output row at each level (details in [Algebraic multigrid preconditioning](oxref:sparse-amg-smoothed-aggregation)) |
| Solve or preconditioner application | One right side |
| Bellman–Ford | One relaxation pass over all edges, including the initial negative-cycle search in all-pairs methods |
| Dijkstra | One vertex removed from the heap |
| Floyd–Warshall | One pivot |
| Dinic (maximum flow) | One breadth-first level-graph search or one depth-first augmenting-path search, including each final unsuccessful search |
| Hopcroft–Karp (matching) | One phase, including the final search confirming no augmenting path |
| Assignment | Add one vertex from the smaller side to the search tree |

Schwarz counts one iteration per right side and additionally one evaluation for each local solve and each multiplicative-Schwarz residual update.

Reaching the limit returns `ConvergenceFailure` (reason `IterationLimit`); cancellation or deadlines return `ExecutionStopped`.
In either case, borrowed output and `refactor` factors remain unchanged under the rules above; graph scoped forms have workspace `last_accepted()` return `None`.
Johnson charges Bellman–Ford potential-computation iterations to the call limit and applies that same limit independently to Dijkstra from each source.
Each source search runs in a nested context, so its iterations do not count against the enclosing call limit.
Searches, connected components, spanning forests, and Laplacians have fixed work and take no context.

## Error classification

Errors use scioxide-core `SciOxideError`; read classification with `e.kind()` (`SciOxideErrorKind`) and details with `e.view()`.
Errors carry no caller-identifying information.
Common classifications in this chapter are as follows.

| Classification | Main causes |
|---|---|
| `DimensionMismatch` | Nonsquare matrices, incompatible vector lengths, insufficient workspace, or workspace reserved for another analysis |
| `InvalidInput` | Malformed storage arrays, duplicate rejection, entries outside the selected triangle, out-of-range options, `refactor` with structure differing from analysis, or Dijkstra on graphs with negative weights |
| `OutOfBounds` | Out-of-range triplet indices, `get` indices, source/target vertices, or stored positions in `set_value` |
| `NonFinite` | NaN/infinite input or update candidates |
| `Singular` | LU column without a nonzero pivot candidate, missing/zero triangular or Jacobi diagonal, incomplete-factorization pivot breakdown under `Strict`, zero-determinant LDL 2×2 pivot, or solve with singular LDL factors |
| `NumericalInstability` | Nonpositive Cholesky pivot (`Breakdown`), unrepresentable product/sum/reciprocal (`Overflow`), nonzero multiplier underflowing to 0 (`Underflow`), or Johnson weight made negative by rounding (`LossOfSignificance`) |
| `ResourceLimit` | Fill, intermediate nonzeros, or reservations exceeding limits |
| `SizeOverflow`, `AllocationFailure` | Unrepresentable size or allocation failure |
| `ConvergenceFailure` | Iteration limit reached |
| `ExecutionStopped` | Context cancellation or deadline |
| `DomainError` | Negative-weight Laplacian, source-reachable negative cycle in single-call `shortest_paths`, or `minimum_cost_assignment` for a cost matrix without a complete assignment |

Diagnostic values (such as `IncompleteDiagnostics`, `AmgDiagnostics`, and `AssignmentResiduals`) are observations, not proofs of accuracy or optimality.
Only `FlowView::verify` and `MatchingView::verify` support exact optimality checks using integer comparisons.

## Summary

Sparse algorithms assume values can be updated without changing finalized structure and that structural computations are reused.
What symbolic phases determine varies by algorithm; LU and LDL numerical fill depends on pivoting, which must be allowed for in limits.
Choose single-call functions for answers alone, and borrowed/scoped forms to remove allocations or share iteration limits with enclosing solvers.
Limit types differ by algorithm and bytes depend on `usize` width; query requirements with `workspace_requirements` before choosing limits.
Failed operations preserve output and previous factors, so interpret `e.kind()` classifications and continue from the preceding state.
