The linear assignment problem pairs elements of two sets one to one, such as workers and jobs, senders and recipients, or measurements and candidates, to minimize total cost.
It attaches a cost to every pair in bipartite matching ([maximum flow and bipartite matching](oxref:sparse-bipartite-matching-konig)) and can be written as a linear program.
Dual solutions called potentials certify assignment optimality and also keep shortest-path edge lengths nonnegative within the algorithm.
This page explains the formulation and dual, the potential-based shortest augmenting path method, and how to read results and residuals.
Terms for calling forms such as one-shot functions, standard forms, and scoped forms are defined in [shared contracts and organization](oxref:sparse-execution-forms).

## Primal and dual problems

The linear assignment problem assigns $k$ workers to $l$ jobs ($k \le l$), one job per worker, minimizing the sum of costs $c_{ij}$ over allowed pairs $(i, j) \in E$.
The worker side, with fewer vertices, is called the smaller side; the job side is the larger side.
Using variables $x_{ij} \in \{0, 1\}$, write

$$
\min \sum_{(i, j) \in E} c_{ij} x_{ij}
\quad \text{subject to} \quad
\sum_j x_{ij} = 1 \ (\text{each } i),
\quad \sum_i x_{ij} \le 1 \ (\text{each } j),
\quad x_{ij} \ge 0
$$

the expression above.
The constraint matrix is a bipartite incidence matrix whose every square submatrix has determinant 0, 1, or −1 (total unimodularity); thus even after relaxing the 0–1 restriction, every feasible-region vertex is integral and an integer optimum exists.
Its dual, in worker potentials $u_i$ and job potentials $v_j$, is

$$
\max \sum_i u_i + \sum_j v_j
\quad \text{subject to} \quad
u_i + v_j \le c_{ij} \ \ ((i, j) \in E),
\quad v_j \le 0
$$

the expression above.
$v_j \le 0$ follows from the inequality $\le 1$ on the job side.
In the square case $k = l$, job-side constraints are equalities for every feasible solution, so this sign restriction can be omitted.

$c_{ij} - u_i - v_j$ is called the **reduced cost** of pair $(i, j)$.
For any assignment $x$ and dual-feasible solution $(u, v)$,

$$
\sum_{(i, j)} c_{ij} x_{ij}
= \sum_{(i, j)} (c_{ij} - u_i - v_j)\,x_{ij} + \sum_i u_i + \sum_j v_j \sum_i x_{ij}
\ge \sum_i u_i + \sum_j v_j
$$

the relation above holds.
The first term is nonnegative because reduced costs are nonnegative, and $v_j \le 0$ together with $\sum_i x_{ij} \le 1$ implies $v_j \sum_i x_{ij} \ge v_j$.
Thus an assignment and $(u, v)$ satisfying the following two conditions are both optimal.

1. Dual feasibility: reduced costs are nonnegative for every allowed pair, and $v_j \le 0$.
2. Complementarity: assigned pairs have zero reduced cost, and $v_j = 0$ for unassigned jobs.

Condition 1 ensures the inequality above; condition 2 ensures equality.
Complementarity alone does not imply optimality; only together with dual feasibility does it provide an optimality certificate.

## Shortest augmenting path method

`AssignmentPlan` uses the shortest augmenting path method.
Below, vertices on the smaller side are called rows and those on the larger side columns.
Initially set each row potential to its minimum allowed-pair cost $u_i = \min_j c_{ij}$ and every column potential to $v_j = 0$, making all reduced costs nonnegative.
If a row has no allowed pair, no complete assignment exists at this stage.
An alternating path alternates between unassigned and assigned pairs.
Next, select unmatched rows $i$ in index order, using reduced costs as edge lengths and Dijkstra's algorithm to find a shortest alternating path (augmenting path) from $i$ to an unmatched column.
Reduced costs are nonnegative, so Dijkstra's algorithm from [shortest paths and negative cycles](oxref:sparse-path-methods) applies directly.
If no unmatched column is reachable, no matching covers the smaller side and the algorithm stops.
Flipping assignments along the path found adds one assigned row.
Finally, decrease potentials of columns whose distances were finalized by the augmenting-path length minus their distance, and recompute potentials of rows in the search tree (the source row and rows matched to finalized columns) from assigned-pair costs using $u_i = c_{i\sigma(i)} - v_{\sigma(i)}$.
Here $\sigma(i)$ is the column assigned to row $i$.
This update keeps reduced costs nonnegative and assigned-pair reduced costs zero; since $v_j$ only decreases, $v_j \le 0$ also remains true.
Every finalized column is matched after flipping, so unmatched column potentials remain $v_j = 0$, preserving the complementarity condition that unassigned jobs have $v_j = 0$.
With $k$ vertices on the smaller side, $l$ on the larger side, and $E$ allowed pairs, complexity is $O(kE\log(l + 1) + k + l)$.

Floating-point reduced costs and potential updates incur rounding.
Row potentials in the search tree are recomputed from assigned-pair costs each time, keeping assigned-pair reduced costs within one rounding step of zero.
Rounding in unassigned-pair reduced costs accumulates with each update.
Therefore a computed negative reduced cost is treated as zero if it is at least

$$
-\bigl(8\varepsilon \cdot \max(\lvert c_{ij} \rvert, \lvert u_i \rvert, \lvert v_j \rvert) + \Delta\bigr)
$$

the bound above.
$\varepsilon$ is machine epsilon; allowance $\Delta$ starts at zero and increases by $64\varepsilon(D + M)$ for every added assignment.
$D$ is that augmenting path's reduced-cost length, and $M$ is the largest absolute potential read or written in that update.
This is a worst-case estimate; typical deviations are much smaller.
A more negative reduced cost indicates dual inconsistency and fails with `NumericalInstability` (`Breakdown`).
Exactly representable costs such as small integers introduce no rounding.

## Plans, results, and residuals

`AssignmentPlan::new(pattern)` treats stored sparse entries, including zeros, as allowed pairs; `from_dense(n)` builds a square-problem Plan allowing every pair.
A sparse structure may have more rows than columns; then the matrix's column side is the smaller side, corresponding to the previous section's “rows.”
A Plan contains only structure and can be reused for many cost sets on that structure.
In the standard form `solve(costs, objective)`, `costs` follows structural storage order for sparse Plans and row-major $n \times n$ values for dense Plans.
A length mismatch is rejected with `DimensionMismatch`, and NaN or infinity with `NonFinite`.
The result is `AssignmentOutcome::Full(FullAssignment)` if a complete assignment exists, or `AssignmentOutcome::Infeasible` if the structure has no matching covering the smaller side.
Absence of an assignment is returned as an outcome rather than an error.
An unrepresentable reduced cost, distance, potential, or total cost fails with `NumericalInstability` (`Overflow`).

`AssignmentObjective::Maximize` solves minimization after negating costs.
The `AssignmentView` from `FullAssignment::as_view()` has public fields for row matches `left`, column matches `right`, total cost with its original sign `objective`, smaller-side potentials `small_potentials`, and nonpositive larger-side potentials `large_potentials`.
Potentials belong to the sign-reversed problem, so optimal maximization assignments satisfy $\sum_i u_i + \sum_j v_j = -\texttt{objective}$.
The one-shot function `minimum_cost_assignment(&costs)` minimizes using stored CSR entries as allowed pairs and costs, returning `FullAssignment`.
It reports absence of an assignment with `DomainError` (argument `costs`).

`AssignmentPlan::verify(costs, objective, view)` checks assignment shape, recomputes reduced costs for every allowed pair in floating point, and returns `AssignmentResiduals`.
Costs are checked with `DimensionMismatch` and `NonFinite` as in `solve`; lengths of `left`, `right`, and both potential arrays must match the Plan or are rejected with `DimensionMismatch`.
An unmatched smaller-side vertex, forbidden matched pair, disagreement between `left` and `right`, or nonfinite potentials or `objective` fails with `InvalidInput` rather than producing residuals.
An unrepresentable recomputed sum fails with `NumericalInstability` (`Overflow`).
There are three residuals.

- `dual_violation`: the greater of the maximum absolute negative reduced cost and the maximum positive larger-side potential.
  It measures dual-feasibility violation.
- `complementary_slackness`: the greater of the maximum absolute reduced cost of assigned pairs and the maximum absolute potential of unmatched larger-side vertices.
- `objective_gap`: the greater of the absolute primal–dual objective gap (negating costs for maximization) and the absolute difference between recomputed total cost and `objective`.

All three are zero for an exact optimal assignment and potentials.
In floating point, they are approximate rounding diagnostics, not proofs of optimality.
The integer comparisons in `FlowView::verify` and `MatchingView::verify` provide exact certificates.
Public fields also allow checking assignments computed by other methods.

### Assignment dual residuals and exhaustive search

The following cell solves assignment with a $4 \times 4$ cost table.
Worker 3 cannot do job 0, so that pair is absent from the structure.
The inputs are worker 0's cost $b$ (1–10) for job 2, minimization or maximization, and whether to forbid job 0 for everyone.
Selecting the last input leaves only three jobs for four people, making a complete assignment impossible.
The first table shows each worker's assignment and potentials; the second shows the objective, dual objective $\sum_i u_i + \sum_j v_j$, and the three residuals from `verify`.
As an independent check, it exhaustively searches the $4^4 = 256$ index tuples for permutations containing only allowed pairs and finds the minimum total cost (maximum for maximization).

```rust
//| id: sparse-assignment-duality
//| ref: sparse-assignment-duality
//| title: "Linear assignment dual residuals checked by exhaustive search"
//| run: reactive
//| crates: [scioxide-sparse]
//| inputs:
//|   bonus_task2: {"type":"range","label":"Cost b for worker 0 to do job 2","min":1.0,"max":10.0,"step":1.0,"value":3.0}
//|   direction: {"type":"select","label":"Objective","options":[{"label":"Minimize","value":"minimize"},{"label":"Maximize","value":"maximize"}],"value":"minimize"}
//|   close_job: {"type":"checkbox","label":"Forbid job 0 for everyone","value":false}
//| cases:
//|   - {"id":"expensive","label":"b = 10","description":"The assignment switches to give job 2 to worker 1 (cost 13).","inputs":{"bonus_task2":10}}
//|   - {"id":"maximize","label":"Maximize","description":"Potentials belong to the sign-reversed problem, so Σu + Σv equals the negated total cost.","inputs":{"direction":"maximize"}}
//|   - {"id":"infeasible","label":"Close job 0","description":"Only three jobs remain for four workers, returning AssignmentOutcome::Infeasible.","inputs":{"close_job":true}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"assignment","path":"/rows/0/1","equals":2}
//|       - {"artifact":"summary","path":"/rows/0/1","approx":{"value":12,"atol":1e-12}}
//|       - {"artifact":"summary","path":"/rows/0/2","approx":{"value":12,"atol":1e-12}}
//|       - {"artifact":"summary","path":"/rows/0/3","approx":{"value":12,"atol":1e-12}}
//|       - {"artifact":"summary","path":"/rows/0/4","range":{"max":1e-12}}
//|       - {"artifact":"summary","path":"/rows/0/5","range":{"max":1e-12}}
//|       - {"artifact":"summary","path":"/rows/0/6","range":{"max":1e-12}}
//|   - case: expensive
//|     expect:
//|       - {"artifact":"assignment","path":"/rows/1/1","equals":2}
//|       - {"artifact":"summary","path":"/rows/0/1","approx":{"value":13,"atol":1e-12}}
//|       - {"artifact":"summary","path":"/rows/0/2","approx":{"value":13,"atol":1e-12}}
//|   - case: maximize
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/1","approx":{"value":21,"atol":1e-12}}
//|       - {"artifact":"summary","path":"/rows/0/2","approx":{"value":21,"atol":1e-12}}
//|       - {"artifact":"summary","path":"/rows/0/3","approx":{"value":-21,"atol":1e-12}}
//|       - {"artifact":"summary","path":"/rows/0/6","range":{"max":1e-12}}
//|   - case: infeasible
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":"No assignment"}
//|       - {"artifact":"summary","path":"/rows/0/1","equals":null}
//|       - {"artifact":"summary","path":"/rows/0/2","equals":null}
use scioxide_sparse::{
    AssignmentObjective, AssignmentOutcome, AssignmentPlan, DuplicatePolicy,
    ExplicitZeroPolicy, SparseBuilder,
};

let n = 4;
// Closing job 0 removes every pair in that column from the structure.
let job0 = |c: f64| if close_job { None } else { Some(c) };
// Cost table. Pairs with None are absent from the structure (worker 3 cannot do job 0).
let table = [
    [job0(4.0), Some(2.0), Some(bonus_task2), Some(7.0)],
    [job0(3.0), Some(3.0), Some(5.0), Some(6.0)],
    [job0(2.0), Some(4.0), Some(6.0), Some(3.0)],
    [None, Some(5.0), Some(6.0), Some(4.0)],
];
// sign puts costs into minimization orientation (negating costs for maximization).
let (objective, sign) = if direction == "maximize" {
    (AssignmentObjective::Maximize, -1.0)
} else {
    (AssignmentObjective::Minimize, 1.0)
};
let mut builder = SparseBuilder::new(n, n);
for (i, row) in table.iter().enumerate() {
    for (j, cost) in row.iter().enumerate() {
        if let Some(c) = cost {
            builder.push(i, j, *c).map_err(|e| e.to_string())?;
        }
    }
}
let costs = builder
    .finish_csr(DuplicatePolicy::Reject, ExplicitZeroPolicy::Preserve)
    .map_err(|e| e.to_string())?;
let plan = AssignmentPlan::new(costs.structural_pattern()).map_err(|e| e.to_string())?;
let outcome = plan
    .solve(costs.values(), objective)
    .map_err(|e| e.to_string())?;

// Independent check: minimum (maximum) sum over the 4^4 index tuples that are permutations of allowed pairs.
let mut best: Option<f64> = None;
for code in 0..n.pow(4) {
    let p: Vec<usize> = (0..n).map(|i| code / n.pow(i as u32) % n).collect();
    let total: Option<f64> = (0..n).map(|i| table[i][p[i]]).sum();
    if let (true, Some(t)) = ((0..n).all(|j| p.contains(&j)), total) {
        let better = best.is_none_or(|b| sign * t < sign * b);
        best = if better { Some(t) } else { best };
    }
}

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let summary = serde_json::json!([
    { "key": "0", "label": "Result", "type": "string" },
    { "key": "1", "label": "Total cost objective", "type": "number", "nullText": "None" },
    { "key": "2", "label": "Exhaustive optimum", "type": "number", "nullText": "None" },
    { "key": "3", "label": "Σu + Σv", "type": "number", "nullText": "None" },
    { "key": "4", "label": "Dual violation", "type": "number", "format": sci3, "nullText": "None" },
    { "key": "5", "label": "Complementarity residual", "type": "number", "format": sci3, "nullText": "None" },
    { "key": "6", "label": "Objective gap", "type": "number", "format": sci3, "nullText": "None" }
]);
let mut report = ("No assignment", None, best, None, None, None, None);
if let AssignmentOutcome::Full(result) = outcome {
    let view = result.as_view();
    let residuals = plan
        .verify(costs.values(), objective, view)
        .map_err(|e| e.to_string())?;
    // Reduced costs with costs oriented for minimization.
    let mut rows = Vec::new();
    for (i, partner) in view.left.iter().enumerate() {
        let j = partner.ok_or("A worker is unmatched")?;
        let c = table[i][j].ok_or("A forbidden pair was selected")?;
        let (u, v) = (view.small_potentials[i], view.large_potentials[j]);
        rows.push((i, j, c, u, v, sign * c - u - v));
    }
    let columns = serde_json::json!([
        { "key": "0", "label": "Worker i", "type": "integer" },
        { "key": "1", "label": "Job σ(i)", "type": "integer" },
        { "key": "2", "label": "Cost c", "type": "number" },
        { "key": "3", "label": "u_i", "type": "number" },
        { "key": "4", "label": "v_σ(i)", "type": "number" },
        { "key": "5", "label": "Reduced cost", "type": "number" }
    ]);
    emit_table_with_columns!(
        columns,
        rows,
        metadata = serde_json::json!({ "id": "assignment" })
    );
    let dual: f64 = view
        .small_potentials
        .iter()
        .chain(view.large_potentials)
        .sum();
    report = (
        "Complete assignment",
        Some(view.objective),
        best,
        Some(dual),
        Some(residuals.dual_violation),
        Some(residuals.complementary_slackness),
        Some(residuals.objective_gap),
    );
}
emit_table_with_columns!(
    summary,
    vec![report],
    metadata = serde_json::json!({ "id": "summary" })
);
```

The best cost with worker 0 assigned to job 2 is $b + 9$ (the remaining pairs are $1 \to 1$, $2 \to 0$, and $3 \to 3$, with $3 + 2 + 4$).
Without that pair, the best is 13 ($0 \to 1$, $1 \to 2$, $2 \to 0$, and $3 \to 3$, with $2 + 5 + 2 + 4$), so the minimum is $\min(b + 9, 13)$.
At the default $b = 3$, the assignment $0 \to 2$, $1 \to 1$, $2 \to 0$, and $3 \to 3$ has cost 12, matching the exhaustive minimum.
The dual objective is also 12, every assigned pair has reduced cost 0, and all three residuals are 0.
All costs are small integers, so no rounding occurs and residuals are exactly zero.
At $b = 10$, the assignment switches to give job 2 to worker 1 (cost 13).
Maximization selects the assignment $0 \to 3$, $1 \to 0$, $2 \to 2$, and $3 \to 1$, with total cost 21.
$0 \to 0$, $1 \to 3$, $2 \to 2$, and $3 \to 1$ also sum to 21, so the optimum is not unique; the algorithm returns one of them and agrees with the exhaustive maximum.
Potentials use sign-reversed costs, giving $\sum_i u_i + \sum_j v_j = -21$.
Forbidding job 0 for everyone leaves only three jobs for four workers, returning `AssignmentOutcome::Infeasible`, and exhaustive search also finds no allowed permutation.

## Scoped forms and workspaces

Besides the standard form `solve`, the scoped form `solve_scoped(costs, objective, options, workspace, scope)` uses only reserved `AssignmentWorkspace` and returns a `AssignmentOutcome<AssignmentView>` borrowing the workspace.
Options are `GraphExecutionOptions`, and `scope` is a root or enclosing-solver context.
Create workspace with the Plan's `workspace(())`, or create it empty with `AssignmentWorkspace::new()` and reserve it with `try_reserve` for the `AssignmentWorkspaceRequirements` returned by `workspace_requirements(())`.
The requirement's `bytes::<S>()` returns logical bytes for cost type `S`; the workspace's `check` checks sufficiency.
Insufficient workspace is rejected with `DimensionMismatch` without expansion.
Workspaces never shrink, so one workspace can be reused across multiple Plans.

When `GraphExecutionOptions::with_budgets` sets an iteration limit, each smaller-side vertex added to the shortest-path search tree counts as one iteration (see the chapter-wide rules in [iteration limits and execution contexts](oxref:sparse-iteration-limits)).
Reaching the limit returns `ConvergenceFailure`; cancellation or a deadline returns `ExecutionStopped`.
The standard form and one-shot function have no limit and do not return these two errors.
Every execution policy runs sequentially.
After a failure or an infeasible outcome, the workspace's `last_accepted()` returns `None`.
`last_attempt()` returns the record of the last attempt, including calls rejected before they begin.

## Summary

Linear assignment is a linear program attaching costs to bipartite matching, and dual potentials certify optimality.
`AssignmentPlan` contains only structure and can be reused for many cost sets on the same structure; `solve` returns infeasibility as `AssignmentOutcome::Infeasible`, which callers handle by branching.
Read the three `AssignmentPlan::verify` residuals by checking whether they are consistent with rounding at the cost scale, rather than as exact optimality proofs.
Complementarity alone does not establish optimality; check it together with dual-feasibility violation.
For maximization, potentials belong to the sign-reversed problem, so compare the dual objective with the negated total cost.
