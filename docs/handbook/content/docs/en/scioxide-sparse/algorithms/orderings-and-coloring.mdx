Storage and work for direct methods are largely determined by fill created during elimination.
The elimination order of unknowns can change fill by orders of magnitude.
For an order-$n$ arrowhead matrix, eliminating the central vertex first fills the entire lower triangle of the factor, while eliminating it last creates no fill.
Finding a minimum-fill ordering is NP-hard (Yannakakis, 1981), so practical methods use heuristics to find good orderings quickly.
This page explains elimination graphs describing fill, approximate minimum degree (AMD), and bandwidth- and envelope-reducing Reverse Cuthill–McKee (RCM), then covers matrix coloring using the same structural ideas.

## Elimination graphs and fill

Represent an $n \times n$ matrix $\mathbf{A}$ with symmetric nonzero pattern by an undirected graph $G(\mathbf{A})$ with vertices $\{0, \dots, n-1\}$ and edges $\{i, j\}$ whenever $a_{ij} \ne 0$ ($i \ne j$).
Eliminating vertex $v$ (one Gaussian-elimination step using row $v$ and column $v$) can make Schur-complement entry $a_{ij} - a_{iv} a_{vj}/a_{vv}$ nonzero if both $a_{iv}$ and $a_{vj}$ are nonzero.
In the graph, this removes $v$ and connects every pair of neighbors of $v$.

$$
G \to G', \qquad V' = V \setminus \{v\}, \qquad E' = \bigl(E \cup \{\{i, j\} : i, j \in \mathrm{Adj}(v),\ i \ne j\}\bigr) \cap \binom{V'}{2}
$$

New edges are fill, and the neighbors of $v$ become a clique (complete subgraph) after elimination.
The sequence of graphs obtained by repeating this is called the **elimination graph** sequence.
The elimination order corresponds to permutation $\mathbf{P}$, and the nonzero pattern of the Cholesky factor $\mathbf{L}$ of $\mathbf{P}\mathbf{A}\mathbf{P}^{\mathsf{T}}$ is the union of original and fill edges.

The fill-path theorem of Rose, Tarjan, and Lueker (1976) characterizes fill using only the original graph.
With reordered indices satisfying $i > j$ and structural nonzeros counted without numerical cancellation,

$$
l_{ij} \ne 0 \iff G(\mathbf{A}) \text{ contains a path connecting } i \text{ and } j \text{ whose intermediate vertex indices are all less than } j \text{}
$$

the relation above holds.
More paths through lower-indexed vertices create more fill, so vertices connected to many others should be eliminated late where possible.

### Minimum degree and quotient graphs

If vertex $v$ has degree (neighbor count) $d$, eliminating $v$ adds at most $d(d-1)/2$ fill edges.
Minimum degree eliminates a vertex of smallest current elimination-graph degree at each step.
Rather than choosing a vertex minimizing fill itself (minimum deficiency), this heuristic minimizes its upper bound, computing quickly and substantially reducing fill in many problems.

An explicit elimination graph grows in storage with every fill edge, and updating degrees becomes expensive.
A **quotient graph** consists of **elements** grouping eliminated vertices and **variables** not yet eliminated.
If $L_e$ is the set of variables adjacent to element $e$, variables in $L_e$ are considered mutually adjacent through element $e$.
Eliminating variable $v$ absorbs elements adjacent to $v$ into a new element $v$; $L_v$ becomes the union of variables adjacent to $v$ and to the absorbed elements, excluding $v$ itself.
Adjacency can be represented without creating elimination-graph edges, bounding storage by the original graph size.

The approximate minimum degree (AMD) algorithm of Amestoy, Davis, and Duff replaces exact degrees with an inexpensive upper bound, the **approximate external degree**.
Let $A_i$ be the variables adjacent to variable $i$ and $E_i$ its adjacent elements; set size $|\cdot|$ counts the original vertices represented.
After eliminating $v$, update the approximate degree $\bar d_i$ of $i \in L_v$ by

$$
\bar d_i \leftarrow \min\Bigl(n_{\mathrm{rest}},\ \bar d_i + |L_v \setminus \{i\}|,\ |A_i \setminus L_v| + |L_v \setminus \{i\}| + \sum_{e \in E_i,\ e \ne v} |L_e \setminus L_v|\Bigr)
$$

using this rule ($n_{\mathrm{rest}}$ counts uneliminated vertices outside the supervariable $i$, excluding the dense vertices described below).
$|L_e \setminus L_v|$ can be obtained for all affected elements with a single scan of variables in $L_v$.
AMD additionally combines merging indistinguishable variables with identical adjacent-variable and element sets into supervariables, aggressive absorption of elements with $L_e \subseteq L_v$ into $v$, and mass elimination of variables with no neighbors outside $L_v$ together with $v$.

SciOxide's implementation traverses adjacent elements, counts each reachable active supervariable once, and updates external degrees by summing their weights.
Each update's complexity depends on the elements traversed and the sizes of their adjacency sets.

`approximate_minimum_degree(pattern)` applies AMD to the $\mathbf{A} + \mathbf{A}^{\mathsf{T}}$ graph formed by symmetrizing a square structure and returns `Permutation` ($p[\text{new}] = \text{old}$).
Diagonals are ignored; stored positions are edges even when their values are zero.
Dense vertices with original-graph degree above $\max(16, 10\lfloor\sqrt{n}\rfloor)$ are excluded from elimination and placed last in index order.
For equal approximate degrees, the supervariable containing the smallest original vertex index is eliminated first.
Finally, indices are reassigned by a postorder traversal of the assembly tree, which records absorption of elements and supervariables into elements.
Ties in approximate degrees are also broken by index, so the same structure always produces the same permutation.
Graph preparation costs $O(n + \mathrm{nnz})$, and quotient-graph storage is proportional to graph size, independent of fill.
Ordering work depends on the graph, and AMD does not generally guarantee minimum fill.
A nonsquare structure returns `DimensionMismatch`; this function accepts no storage limit.

### Graphs ordered for each factorization

| Factorization | Graph to order | How to specify it |
|---|---|---|
| Cholesky/LDL (`SparseSymmetricSymbolic`) | Symmetric structure of $\mathbf{A}$ represented by the selected triangle ($\mathbf{A} + \mathbf{A}^{\mathsf{T}}$ if none is selected) | `SparseOrdering` |
| LU (`SparseLuSymbolic`) | Structure of $\mathbf{A} + \mathbf{A}^{\mathsf{T}}$ (column order) | `SparseOrdering` |
| QR (`SparseQrSymbolic`) | Column-intersection graph structure $\mathbf{A}^{\mathsf{T}}\mathbf{A}$ (without forming the product) | `SparseOrdering` |

Symbolic analysis for direct factorizations accepts an ordering through `SparseOrdering`.
The default `FillReducing` uses AMD on the graph above, `Natural` uses original indices, and `Supplied(&permutation)` uses a supplied permutation; a permutation length differing from the column count gives `DimensionMismatch`.
`FillReducing` estimates temporary ordering storage and returns `ResourceLimit` if it exceeds the symbolic-analysis limit `max_workspace_bytes`.
For LU and $\mathbf{L}\mathbf{D}\mathbf{L}^{\mathsf{H}}$, numerical pivoting can further change this ordering.
Pass orderings computed by `reverse_cuthill_mckee` and similar functions through `Supplied`.

QR's `FillReducing` starts AMD from a quotient graph with each row of $\mathbf{A}$ containing at least two nonzeros as an initial element and columns as variables.
Thus it never creates edges of $\mathbf{A}^{\mathsf{T}}\mathbf{A}$.
Computing QR's column order yourself with `approximate_minimum_degree` requires the structure of $\mathbf{A}^{\mathsf{T}}\mathbf{A}$, so `FillReducing` uses less storage and work.

## Reverse Cuthill–McKee and envelopes

For a symmetric matrix with nonzero diagonal, define **bandwidth** as $\beta = \max\{\lvert i - j \rvert : a_{ij} \ne 0\}$ and **envelope** (profile) size as $\sum_i (i - f_i)$, where $f_i = \min\{j : a_{ij} \ne 0\}$ is the first nonzero column in row $i$.
Elimination creates no nonzero left of a row's first nonzero, so Cholesky nonzeros in row $i$ can occur only between columns $f_i$ and $i$ (the envelope theorem).
Thus the strictly lower-triangular factor has at most the envelope size in nonzeros, and envelope-reducing orderings lower the fill bound.

Cuthill–McKee performs breadth-first search from a starting vertex and numbers vertices in visitation order.
Each vertex's unvisited neighbors enter the queue in increasing degree order, breaking ties by index.
Adjacent vertices receive nearby indices, reducing bandwidth and envelope.
The start is a **pseudoperipheral vertex** with large breadth-first search depth (eccentricity).
`reverse_cuthill_mckee` starts from the unnumbered vertex with smallest (degree, index), then moves to the vertex of smallest (degree, index) in the deepest layer.
It repeats while eccentricity increases, approximating an endpoint of the graph diameter.
Reversing this order gives RCM; George's observation and the proof of Liu and Sherman show that reversal preserves bandwidth and never enlarges the envelope.
For multiple connected components, compute and reverse the ordering independently for each component.
One breadth-first search costs $O(n + \mathrm{nnz})$, plus neighbor sorting.
Minimum bandwidth is also NP-hard; RCM heuristically reduces bandwidth and envelope.

Because RCM produces banded structure, it is also useful for banded solvers and improving matrix–vector memory locality.
However, when bandwidth cannot be reduced below about $\sqrt{N}$, as for a two-dimensional grid with $N$ unknowns, the envelope fills and factors have $O(N^{3/2})$ nonzeros; AMD gives less fill.

scioxide-sparse provides no function to permute the matrix itself.
If a permuted matrix is needed, reassemble entries after relabeling row and column indices with `old_to_new()`.
Permute vectors with `Permutation::apply_into` ($y_{\text{new}} = x_{p[\text{new}]}$) and `inverse_into`.
For direct-factorization symbolic analysis alone, pass the permutation through `SparseOrdering::Supplied` without reassembly.

### Arrowhead fill and elimination graphs

An arrowhead matrix is an $n \times n$ matrix with nonzeros only on the diagonal and in row and column 0; its graph is a star centered at vertex 0.
The following cell symbolically analyzes an arrowhead matrix with diagonal 4 and row/column 0 entries 1 under four orders: natural, AMD (`FillReducing`), `reverse_cuthill_mckee`, and reversed indices.
The input is dimension $n$ (5–40).
The table shows when the center is eliminated and `cholesky_entries()` (the structural nonzero count in the factor's strictly lower triangle).
As a check, it constructs star elimination graphs for each order, counts fill edges added by successive eliminations, and compares the sum of the fill-edge count and the original strictly lower-triangular nonzero count $n - 1$ with `cholesky_entries()`.
Natural ordering eliminates the center first, making the rest a clique and filling all $n(n-1)/2$ factor entries.
Orders eliminating the center last should have zero fill and $n - 1$ factor entries.

```rust
//| id: sparse-arrow-fill
//| ref: sparse-arrow-fill
//| title: "Arrowhead elimination orders and fill"
//| run: reactive
//| crates: [scioxide-core, scioxide-sparse]
//| inputs:
//|   matrix_size: {"type":"range","label":"Matrix dimension n","description":"Number of vertices in a star with central vertex 0 and n − 1 leaves.","min":5,"max":40,"step":5,"value":10}
//| cases:
//|   - {"id":"large","label":"n = 40","description":"Only the natural-order factor grows to n(n − 1)/2 = 780 entries; the other three orders remain at n − 1 = 39.","inputs":{"matrix_size":40}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"orderings","path":"/rows/0/1","equals":1}
//|       - {"artifact":"orderings","path":"/rows/0/2","equals":45}
//|       - {"artifact":"orderings","path":"/rows/0/3","equals":36}
//|       - {"artifact":"orderings","path":"/rows/0/4","equals":45}
//|       - {"artifact":"orderings","path":"/rows/1/1","equals":10}
//|       - {"artifact":"orderings","path":"/rows/1/2","equals":9}
//|       - {"artifact":"orderings","path":"/rows/2/1","equals":9}
//|       - {"artifact":"orderings","path":"/rows/2/4","equals":9}
//|       - {"artifact":"orderings","path":"/rows/3/1","equals":10}
//|   - case: large
//|     expect:
//|       - {"artifact":"orderings","path":"/rows/0/2","equals":780}
//|       - {"artifact":"orderings","path":"/rows/0/4","equals":780}
//|       - {"artifact":"orderings","path":"/rows/1/2","equals":39}
//|       - {"artifact":"orderings","path":"/rows/2/1","equals":39}
//|       - {"artifact":"orderings","path":"/rows/2/2","equals":39}
//|       - {"artifact":"orderings","path":"/rows/3/3","equals":0}
use scioxide_core::{Permutation, Triangle};
use scioxide_sparse::{
    DuplicatePolicy, ExplicitZeroPolicy, SparseBuilder, SparseOrdering, SparseSymmetricLimits,
    SparseSymmetricSymbolic, reverse_cuthill_mckee,
};

let n = matrix_size as usize;
let mut builder = SparseBuilder::new(n, n);
for i in 0..n {
    builder.push(i, i, 4.0_f64).map_err(|e| e.to_string())?;
    if i > 0 {
        builder.push(i, 0, 1.0).map_err(|e| e.to_string())?;
        builder.push(0, i, 1.0).map_err(|e| e.to_string())?;
    }
}
let a = builder
    .finish_csr(DuplicatePolicy::Reject, ExplicitZeroPolicy::Drop)
    .map_err(|e| e.to_string())?;
let rcm = reverse_cuthill_mckee(a.structural_pattern()).map_err(|e| e.to_string())?;
let reversed = Permutation::new((0..n).rev().collect()).map_err(|e| e.to_string())?;
let limits = SparseSymmetricLimits::new(n * n, n * n, 1 << 20);
let mut rows = Vec::new();
for (name, ordering) in [
    ("Natural order", SparseOrdering::Natural),
    ("AMD（FillReducing）", SparseOrdering::FillReducing),
    ("RCM（Supplied）", SparseOrdering::Supplied(&rcm)),
    ("Reverse order (Supplied)", SparseOrdering::Supplied(&reversed)),
] {
    let symbolic = SparseSymmetricSymbolic::analyze(
        a.structural_pattern(),
        ordering,
        Some(Triangle::Lower),
        limits,
    )
    .map_err(|e| e.to_string())?;
    let p = symbolic.permutation().new_to_old().to_vec();
    // Independent check: construct the star's elimination graph and count added fill edges.
    let mut adjacent: Vec<Vec<bool>> = (0..n)
        .map(|i| (0..n).map(|j| i != j && (i == 0 || j == 0)).collect())
        .collect();
    let (mut eliminated, mut fill) = (vec![false; n], 0usize);
    for &v in &p {
        eliminated[v] = true;
        let neighbors: Vec<usize> = (0..n)
            .filter(|&u| !eliminated[u] && adjacent[v][u])
            .collect();
        for (k, &i) in neighbors.iter().enumerate() {
            for &j in &neighbors[k + 1..] {
                if !adjacent[i][j] {
                    adjacent[i][j] = true;
                    adjacent[j][i] = true;
                    fill += 1;
                }
            }
        }
    }
    let center = p
        .iter()
        .position(|&v| v == 0)
        .ok_or("The center vertex is absent from the ordering")?;
    rows.push((
        name,
        center + 1,
        symbolic.cholesky_entries(),
        fill,
        n - 1 + fill,
    ));
}
let columns = serde_json::json!([
    { "key": "0", "label": "Ordering" },
    { "key": "1", "label": "Center elimination position [ordinal]", "type": "integer" },
    { "key": "2", "label": "cholesky_entries() [count]", "type": "integer" },
    { "key": "3", "label": "Fill counted in elimination graph [count]", "type": "integer" },
    { "key": "4", "label": "Original edges + fill [count]", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "orderings" })
);
```

At the default $n = 10$, natural order eliminates the center first and `cholesky_entries()` is $n(n-1)/2 = 45$.
The elimination graph adds 36 fill edges, whose sum with the 9 original edges is 45, matching `cholesky_entries()`.
AMD postpones the degree-9 center until tenth, giving zero fill and 9 factor entries.
RCM starts at a leaf and visits the center second in breadth-first search.
Reversing that order eliminates the center ninth, again giving zero fill.
Reversing indices eliminates the center last and gives zero fill.
At $n = 40$, only natural-order factors grow to $780$ entries; the other three remain at $n - 1 = 39$.

## Coloring

Coloring is a structural computation grouping nonconflicting vertices or columns into colors for simultaneous processing by color.
Two kinds of coloring use different conflict definitions.
Both `distance_one_coloring` and `derivative_coloring` return scioxide-core's `ColoringSchedule`.
`kind()` returns the coloring kind (`ColoringKind::DistanceOne` or `DerivativeColumns`), `colors()` the color of each vertex or column (indices starting at 0), `color_count()` the color count, and `groups()` the vertices or columns in each color in ascending order.
`ColoringSchedule::new` checks for conflicts on construction and retains a copy of the colored structure.
`validate_pattern` checks whether another matrix has the same structure as the one colored.

### Distance-1 coloring

`distance_one_coloring(pattern)` colors the $\mathbf{A} + \mathbf{A}^{\mathsf{T}}$ graph formed by symmetrizing a square structure so adjacent vertices have different colors, ignoring the diagonal.
A greedy algorithm visits vertices in ascending index order and assigns the smallest color unused by lower-indexed neighbors; with maximum degree $\Delta$, at most $\Delta + 1$ colors are used.
It does not guarantee the minimum color count (finding that count is NP-hard).
A nonsquare structure returns `DimensionMismatch`.
Vertices of one color are mutually nonadjacent, allowing, for example, Gauss–Seidel updates in parallel by color (multicolor ordering).

### Derivative-column coloring

Two columns of the Jacobian $\mathbf{J}$ of $m \times n$ are structurally orthogonal if they share no row with nonzeros.
`derivative_coloring(pattern)` colors columns so that columns sharing a nonzero row have different colors.
The structure may be rectangular.
This is distance-1 coloring of the column-intersection graph (the structure of $\mathbf{J}^{\mathsf{T}}\mathbf{J}$); a greedy algorithm visits columns in ascending index order but follows row connectivity without constructing that graph.
It also does not guarantee the minimum color count.
For the column set $C_c$ of color $c$, compute the directional derivative $\mathbf{J}\mathbf{d}_c$ in direction $\mathbf{d}_c = \sum_{j \in C_c} \mathbf{e}_j$ with one finite difference or forward-mode automatic differentiation.
Each row $i$ has at most one nonzero among columns of $C_c$, so

$$
J_{ij} = (\mathbf{J}\mathbf{d}_c)_i \qquad (j \in C_c,\ J_{ij} \ne 0)
$$

recovers the columns of $\mathbf{J}$ together by color.
The required directional-derivative count falls from column count $n$ to color count.
Every nonzero in one row must have a different color, so the color count is at least the maximum row nonzero count.
Finite-difference recovery steps and errors are covered in [sparse Jacobian compression by coloring](../../../scioxide-differentiate/algorithms/sparse-coloring/).

### Color counts for banded matrices

For an $n \times n$ banded matrix with upper and lower bandwidth $\beta$ (nonzero when $\lvert i - j \rvert \le \beta$), columns $j$ and $k$ share a nonzero row when $\lvert j - k \rvert \le 2\beta$.
If $n \ge 2\beta + 1$, any consecutive $2\beta + 1$ columns conflict pairwise, requiring at least $2\beta + 1$ colors, and coloring by $j \bmod (2\beta + 1)$ uses exactly that many.
The index-ordered greedy algorithm assigns column $j$ the only color unused by the preceding $2\beta$ columns and therefore produces this coloring.
Color 0 then has the most columns, namely $\lceil n/(2\beta + 1) \rceil$.
For distance-1 coloring, adjacent vertices satisfy $\lvert i - j \rvert \le \beta$ and a clique of $\beta + 1$ vertices exists, so $\beta + 1$ colors are necessary and sufficient.
The following cell takes bandwidth $\beta$ (1–4) and dimension $n$ (10–60), computes both color counts and the maximum columns per color, and compares them with the theoretical values above.
As a check, it independently counts conflicts to verify distinct nonzero-column colors within each row.

```rust
//| id: sparse-derivative-coloring
//| ref: sparse-derivative-coloring
//| title: "Distance-1 and derivative-column color counts for banded matrices"
//| run: reactive
//| crates: [scioxide-sparse]
//| inputs:
//|   half_bandwidth: {"type":"range","label":"Bandwidth β","description":"Make entries with |i − j| ≤ β nonzero.","min":1,"max":4,"step":1,"value":1}
//|   grid_dimension: {"type":"range","label":"Dimension n","description":"Number of rows and columns.","min":10,"max":60,"step":10,"value":30}
//| cases:
//|   - {"id":"wide-band","label":"β = 4","description":"Column coloring uses 2β + 1 = 9 colors, confirming that color count depends only on bandwidth.","inputs":{"half_bandwidth":4}}
//|   - {"id":"long","label":"n = 60","description":"Doubling the dimension preserves color count and only increases the columns per color.","inputs":{"grid_dimension":60}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"colors","path":"/rows/0/1","equals":2}
//|       - {"artifact":"colors","path":"/rows/1/1","equals":3}
//|       - {"artifact":"colors","path":"/rows/3/1","equals":10}
//|       - {"artifact":"colors","path":"/rows/3/2","equals":10}
//|       - {"artifact":"colors","path":"/rows/4/1","equals":0}
//|   - case: wide-band
//|     expect:
//|       - {"artifact":"colors","path":"/rows/0/1","equals":5}
//|       - {"artifact":"colors","path":"/rows/1/1","equals":9}
//|       - {"artifact":"colors","path":"/rows/3/1","equals":4}
//|       - {"artifact":"colors","path":"/rows/4/1","equals":0}
//|   - case: long
//|     expect:
//|       - {"artifact":"colors","path":"/rows/1/1","equals":3}
//|       - {"artifact":"colors","path":"/rows/3/1","equals":20}
use scioxide_sparse::{
    DuplicatePolicy, ExplicitZeroPolicy, SparseBuilder, derivative_coloring,
    distance_one_coloring,
};

let (n, beta) = (grid_dimension as usize, half_bandwidth as usize);
let mut builder = SparseBuilder::new(n, n);
for i in 0..n {
    for j in i.saturating_sub(beta)..(i + beta + 1).min(n) {
        builder.push(i, j, 1.0_f64).map_err(|e| e.to_string())?;
    }
}
let a = builder
    .finish_csr(DuplicatePolicy::Reject, ExplicitZeroPolicy::Drop)
    .map_err(|e| e.to_string())?;
let vertex = distance_one_coloring(a.structural_pattern()).map_err(|e| e.to_string())?;
let columns = derivative_coloring(a.structural_pattern()).map_err(|e| e.to_string())?;

// Independent check: count same-color pairs among nonzero columns in each row.
let mut conflicts = 0usize;
for i in 0..n {
    let row = &a.col_indices()[a.row_ptr()[i]..a.row_ptr()[i + 1]];
    for (k, &j) in row.iter().enumerate() {
        conflicts += row[k + 1..]
            .iter()
            .filter(|&&l| columns.colors()[l] == columns.colors()[j])
            .count();
    }
}
let largest_group = columns.groups().map(<[usize]>::len).max().unwrap_or(0);
let rows: Vec<(&str, usize, Option<usize>)> = vec![
    ("Distance-1 color count", vertex.color_count(), Some(beta + 1)),
    (
        "Column color count (directional derivatives)",
        columns.color_count(),
        Some(2 * beta + 1),
    ),
    ("Column count n (without coloring)", n, None),
    (
        "Maximum columns per color",
        largest_group,
        Some(n.div_ceil(2 * beta + 1)),
    ),
    ("Same-color column pairs within a row", conflicts, Some(0)),
];
let table = serde_json::json!([
    { "key": "0", "label": "Quantity" },
    { "key": "1", "label": "Value [count]", "type": "integer" },
    { "key": "2", "label": "Theory [count]", "type": "integer", "nullText": "None" }
]);
emit_table_with_columns!(
    table,
    rows,
    metadata = serde_json::json!({ "id": "colors" })
);
```

At the defaults $\beta = 1$ (tridiagonal) and $n = 30$, distance-1 coloring uses 2 colors and column coloring 3, matching theoretical $\beta + 1$ and $2\beta + 1$, with 0 same-color column pairs within a row.
A finite-difference Jacobian therefore requires 3 directional derivatives instead of 30.
Increasing $n$ to 60 preserves color count; only the maximum columns per color grows from 10 to 20, as predicted by $\lceil n/3 \rceil$.
At $\beta = 4$, column coloring uses 9 colors and distance-1 coloring 5, with at most $\lceil 30/9 \rceil = 4$ columns per color.
Color count depends on bandwidth, not dimension.

## Summary

Fill arises when elimination makes neighboring vertices a clique; the fill-path theorem characterizes it using paths in the original graph alone.
Direct-factorization symbolic analysis uses AMD by default, eliminating small approximate-external-degree vertices while quotient graphs bound storage by original graph size.
AMD is a heuristic and does not guarantee minimum fill; supply known good orderings for specific structures through `SparseOrdering::Supplied`.
RCM reduces bandwidth and envelope; the envelope theorem bounds Cholesky fill by envelope size, making RCM suitable for banded solvers and product locality.
scioxide-sparse has no matrix-permutation function; for that purpose, relabel indices by the permutation and reassemble the matrix.
Sparse Jacobians can be recovered with as many directional derivatives as colors in `derivative_coloring`; for banded matrices, this is $2\beta + 1$ regardless of dimension.
