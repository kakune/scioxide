Travel times in road networks and delays in communication networks can be found as shortest paths in weighted directed graphs.
`scioxide-sparse` uses a Plan `GraphPlan` built from a sparse matrix to find single-source and all-pairs shortest paths with four algorithms.
Conventions for reading matrices as graphs and handling zero-weight edges are explained in [graph traversal, connected components, spanning forests, and Laplacians](oxref:sparse-graph-from-matrix).
This page explains shortest-path optimality conditions, negative cycles, the four algorithms, and how to read results and workspaces, verifying computed distances independently of the algorithm.
Terms for calling forms such as one-shot functions, standard forms, and scoped forms are defined in [shared contracts and organization](oxref:sparse-execution-forms).

## Shortest distances and negative cycles

In a weighted directed graph, find the shortest distance $d^\ast(v)$ from source $s$ to every vertex $v$.
Path length is the sum of edge weights; vertices unreachable from $s$ have $d^\ast(v) = +\infty$.
A cycle with negative total edge weight is a **negative cycle**.
If a negative cycle is reachable from $s$, traversing it repeatedly makes paths arbitrarily short, so no shortest distance exists.
Without a negative cycle, shortest distances exist even with negative-weight edges.

## Optimality conditions

Assign finite values $d(v)$ ($d(s) = 0$) to vertices reachable from $s$; if the following two conditions hold, then $d = d^\ast$.

1. Feasibility: $d(v) \le d(u) + w(u, v)$ on every edge $(u, v)$ whose endpoints both have values.
2. Tight tree: every reachable vertex $v$ other than $s$ has an edge $(u, v)$ satisfying $d(v) = d(u) + w(u, v)$.
   This $u$ is the **predecessor** of $v$, and following predecessors returns to $s$.

Summing condition 1 along any path $s = v_0 \to v_1 \to \cdots \to v_k = v$ from $s$ to $v$ gives $d(v) - d(s) \le \sum_{i=1}^{k} w(v_{i-1}, v_i)$.
Thus $d(v)$ exceeds no path length, giving $d(v) \le d^\ast(v)$.
Following condition-2 predecessors from $v$ to $s$ gives a path of equalities whose length is exactly $d(v)$, so $d^\ast(v) \le d(v)$.
Together these give $d(v) = d^\ast(v)$.
Condition 1 alone is insufficient.
If all weights are nonnegative, $d \equiv 0$ also satisfies condition 1.
The two conditions correspond to dual feasibility and complementarity in the shortest-path linear program.

If a negative cycle $C$ is reachable, summing condition 1 around it gives $0 \le w(C) < 0$, so no $d$ can satisfy condition 1.
A negative cycle therefore certifies that shortest distances do not exist.

## Four algorithms

| Algorithm | Scope | Complexity | Negative weights | Negative-cycle reporting |
|---|---|---|---|---|
| `GraphPathMethod::Dijkstra { source }` | Single-source | $O((V + E) \log V)$ | Rejected with `InvalidInput` | None |
| `GraphPathMethod::BellmanFord { source }` | Single-source | $O(VE)$ | Allowed | Cycles reachable from the source |
| `GraphPathMethod::FloydWarshall` | All-pairs | $O(V^3)$, output $O(V^2)$ | Allowed | Cycles anywhere in the graph |
| `GraphPathMethod::Johnson` | All-pairs | $O(VE + V(V + E) \log V)$, output $O(V^2)$ | Allowed | Cycles anywhere in the graph |

Plans do not select methods automatically (the one-shot function `shortest_paths` described later chooses Dijkstra or Bellman–Ford according to the presence of negative weights).
Single-source methods carry the source in the method value, as in `Dijkstra { source }`.

**Dijkstra's algorithm** grows the set of finalized vertices one at a time.
With nonnegative weights, the smallest tentative distance among unfinalized vertices cannot be shortened through other vertices, so it can be finalized.
Tentative distances use an indexed binary heap, repositioning a vertex whenever its distance decreases.
This argument fails with negative weights, so any negative edge, even unreachable from the source, is rejected with `InvalidInput`.
If rounding decreases a finalized distance, computation fails with `NumericalInstability` (`Breakdown`).

**Bellman–Ford** repeatedly relaxes every edge using $d(v) \leftarrow \min(d(v), d(u) + w(u, v))$.
Without negative cycles, a shortest path never visits the same vertex twice and has at most $V - 1$ edges.
After relaxation pass $k$, each vertex value is no greater than the minimum length among paths with at most $k$ edges.
Values are always lengths of actual paths and never fall below shortest distances, so after $V - 1$ passes they equal shortest distances.
If distances still change on pass $V$, a negative cycle exists.
It stops on the first pass with no change, finishing before $V$ passes on many graphs.
When a negative cycle is found, follow predecessors $V$ times from a vertex changed on pass $V$ to enter the cycle, then traverse it once to collect vertices.
The collected cycle weight is recomputed from edge weights; if rounding makes it nonnegative, no cycle is returned and computation fails with `NumericalInstability` (`LossOfSignificance`).
In an undirected graph, a negative edge $\{u, v\}$ alone forms cycle $u \to v \to u$, so reaching a negative edge reports a negative cycle.

Both all-pairs methods first run Bellman–Ford in $O(VE)$ from a virtual source with zero-weight edges to every vertex, searching for negative cycles anywhere in the graph.
Thus all-pairs methods also report cycles unreachable from a particular source.

**Floyd–Warshall** updates distances $d_k(i, j)$ allowing only intermediate vertices $0, 1, \ldots, k$ using

$$
d_k(i, j) = \min\bigl(d_{k-1}(i, j),\ d_{k-1}(i, k) + d_{k-1}(k, j)\bigr)
$$

for $k = 0, 1, \ldots, V - 1$.
Initially $d_{-1}(i, j)$ is edge $(i, j)$'s weight, 0 when $i = j$, and $+\infty$ when no edge exists.
Whenever an update lowers a value, it also sets the path-reconstruction predecessor to $p(i, j) \leftarrow p(k, j)$.
Each $k$ is a pivot; one update costs $O(V^2)$ and the total is $O(V^3)$.
It suits small dense graphs.

**Johnson's algorithm** uses distances from the virtual source as potentials $h$ and reweights edges as $w'(u, v) = w(u, v) + h(u) - h(v)$.
Since $h$ satisfies condition 1, $w' \ge 0$, allowing Dijkstra from every source.
Every path from $s$ to $t$ changes length by the same $h(s) - h(t)$, so shortest paths are preserved.
Restore computed distances $d'(s, t)$ using $d(s, t) = d'(s, t) - h(s) + h(t)$.
If rounding makes a reweighted edge negative, computation fails with `NumericalInstability` (`LossOfSignificance`).
It suits sparse graphs with $E$ much smaller than $V^2$.

Both all-pairs methods distribute sources (result rows) across workers according to execution policy.
Worker count never exceeds 64 or the vertex count.
Rows are computed independently, so results do not depend on worker count.
Single-source methods run sequentially.

## Results, workspaces, and iteration limits

The Plan's standard form `shortest_paths(method)` returns `PathOutcome::Paths(GraphPathResult)` or `PathOutcome::NegativeCycle(NegativeCycle)`.
A negative cycle is an outcome rather than an error.
`NegativeCycle::vertices()` lists cycle vertices with the first repeated at the end (`[v, v]` for a negative self-loop).
In the `GraphPathView` returned by `GraphPathResult::as_view()`, `distances()` and `predecessors()` are length-$V$ arrays for single-source results and row-major $V^2$ arrays for all-pairs results, with pair $(i, j)$ at index $iV + j$.
Unreachable distances and predecessors of the source and unreachable vertices are `None`.
`source()` returns the source for single-source results and `None` for all-pairs results.
`path(source, target)` follows predecessors in $O(V)$ to return a path, returning `None` if unreachable and `[source]` if source equals destination.
A different source for a single-source result gives `InvalidInput`; an invalid vertex index gives `OutOfBounds`.

The one-shot function `shortest_paths(matrix, source)` reads the matrix as a directed graph, computes distances with Dijkstra if there are no negative weights or Bellman–Ford otherwise, and returns `GraphPathResult`.
A reachable negative cycle means no distances exist and is reported with `DomainError` (argument `matrix`).

The scoped form `shortest_paths_scoped(method, options, workspace, scope)` writes results into reserved `GraphWorkspace` and returns them as a workspace-borrowing `PathOutcome<GraphPathView, &[usize]>`.
The borrow remains valid until the next call.
Create workspace by passing `GraphWorkspaceRequest::new(method, options)` to the Plan's `workspace(request)`, or reserve it with `GraphWorkspace::try_reserve` for the `GraphWorkspaceRequirements` returned by `workspace_requirements(request)`.
The requirement's `output_entries()` is $V$ for single-source and $V^2$ for all-pairs methods; `workers()` is the all-pairs worker count.
`bytes::<S>()` returns logical bytes, and `check` checks sufficiency.
Insufficient workspace is rejected with `DimensionMismatch` without expansion.

When `GraphExecutionOptions::with_budgets` supplies an iteration limit, scoped forms count one iteration in the following units (see chapter-wide rules in [iteration limits and execution contexts](oxref:sparse-iteration-limits)).

- Each Bellman–Ford relaxation pass.
  This includes the initial negative-cycle search for all-pairs methods.
- Each vertex removed from Dijkstra's heap.
- Each Floyd–Warshall pivot.
- Johnson's Dijkstra search for each source runs in a nested scope, applying the same limit separately to every source.
  Those iterations do not count toward the outer call.

Reaching the limit returns `ConvergenceFailure`; cancellation or a deadline returns `ExecutionStopped`.
The standard form and one-shot function have no limit and do not return these two errors.
On failure, no partial result is exposed, and the workspace's `last_accepted()` returns `None`.
`last_attempt()` returns the record of the last attempt, including calls rejected before they begin.
Every form fails with `NumericalInstability` (`Overflow`) if a distance sum is unrepresentable.

### Zero-weight edges and Dijkstra's algorithm

The following cell reads a $4 \times 4$ matrix with entries $(0, 1) = 0$, $(1, 2) = d$, and $(0, 2) = 5$ as a directed graph and finds shortest paths from vertex 0 with Dijkstra.
Vertex 3 has no edges.
Inputs are weight $d$ (1–8) and whether to retain zero-weight entries in the structure.
It places distances from the one-shot function `shortest_paths(matrix, source)` alongside distances and paths from the Plan's standard form `shortest_paths(method)`.
As a check, the final column contains distances obtained by hand from the edge list.

```rust
//| id: sparse-zero-edge-paths
//| ref: sparse-zero-edge-paths
//| title: "Zero-weight edges and Dijkstra's algorithm"
//| run: reactive
//| crates: [scioxide-core, scioxide-sparse]
//| inputs:
//|   edge_weight: {"type":"range","label":"Weight d of entry (1, 2)","description":"The shortest path changes according to whether it is shorter than direct edge 0→2 (weight 5).","min":1.0,"max":8.0,"step":1.0,"value":2.0}
//|   keep_zero: {"type":"checkbox","label":"Retain zero-weight entries in the structure (Preserve)","description":"Disabling this removes zero-valued entries during assembly (Drop).","value":true}
//| cases:
//|   - {"id":"long-detour","label":"d = 6","description":"Detour 0→1→2 becomes longer than the direct edge, changing the shortest path to 0→2.","inputs":{"edge_weight":6}}
//|   - {"id":"drop-zero","label":"Remove zero-weight entries","description":"Vertex 1 becomes unreachable and distance to vertex 2 becomes 5 through the direct edge.","inputs":{"keep_zero":false}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"paths","path":"/rows/1/1","approx":{"value":0,"atol":1e-15}}
//|       - {"artifact":"paths","path":"/rows/2/1","approx":{"value":2,"atol":1e-15}}
//|       - {"artifact":"paths","path":"/rows/2/2","equals":"0 → 1 → 2"}
//|       - {"artifact":"paths","path":"/rows/2/3","approx":{"value":2,"atol":1e-15}}
//|       - {"artifact":"paths","path":"/rows/3/1","equals":null}
//|       - {"artifact":"paths","path":"/rows/3/3","equals":null}
//|   - case: long-detour
//|     expect:
//|       - {"artifact":"paths","path":"/rows/2/1","approx":{"value":5,"atol":1e-15}}
//|       - {"artifact":"paths","path":"/rows/2/2","equals":"0 → 2"}
//|   - case: drop-zero
//|     expect:
//|       - {"artifact":"paths","path":"/rows/1/1","equals":null}
//|       - {"artifact":"paths","path":"/rows/1/3","equals":null}
//|       - {"artifact":"paths","path":"/rows/2/1","approx":{"value":5,"atol":1e-15}}
use scioxide_sparse::{
    DuplicatePolicy, ExplicitZeroPolicy, GraphDirection, GraphPathMethod, GraphPlan,
    PathOutcome, SparseBuilder, shortest_paths,
};

let d = edge_weight;
let zeros = if keep_zero {
    ExplicitZeroPolicy::Preserve
} else {
    ExplicitZeroPolicy::Drop
};
let mut builder = SparseBuilder::new(4, 4);
for (u, v, w) in [(0, 1, 0.0_f64), (1, 2, d), (0, 2, 5.0)] {
    builder.push(u, v, w).map_err(|e| e.to_string())?;
}
let matrix = builder
    .finish_csr(DuplicatePolicy::Reject, zeros)
    .map_err(|e| e.to_string())?;

// Plan standard form: specify the method and source explicitly.
let graph =
    GraphPlan::new(matrix.view(), GraphDirection::Directed).map_err(|e| e.to_string())?;
let outcome = graph
    .shortest_paths(GraphPathMethod::Dijkstra { source: 0 })
    .map_err(|e| e.to_string())?;
let PathOutcome::Paths(result) = outcome else {
    return Err("Dijkstra does not report negative cycles".to_string());
};
let paths = result.as_view();
// One-shot function: choose Dijkstra because no weights are negative.
let direct = shortest_paths(matrix.view(), 0).map_err(|e| e.to_string())?;
// Independent check: distances obtained by hand from the edge list.
let expected = if keep_zero {
    [Some(0.0), Some(0.0), Some(d.min(5.0)), None]
} else {
    [Some(0.0), None, Some(5.0), None]
};
let mut rows = Vec::new();
for v in 0..4 {
    let route = paths.path(0, v).map_err(|e| e.to_string())?.map(|p| {
        let names: Vec<String> = p.iter().map(|u| u.to_string()).collect();
        names.join(" → ")
    });
    let one_shot = direct.as_view().distances()[v];
    rows.push((v, paths.distances()[v], route, one_shot, expected[v]));
}
let columns = serde_json::json!([
    { "key": "0", "label": "Vertex v", "type": "integer" },
    { "key": "1", "label": "Distance d(v)", "type": "number", "nullText": "Unreachable" },
    { "key": "2", "label": "Shortest paths", "type": "string", "nullText": "None" },
    { "key": "3", "label": "One-shot function distance", "type": "number", "nullText": "Unreachable" },
    { "key": "4", "label": "Distance by hand", "type": "number", "nullText": "Unreachable" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "paths" })
);
```

At the default $d = 2$ with zero-weight entries retained, vertex 1 is reached at distance 0 and vertex 2 at distance 2 through $0 \to 1 \to 2$.
At $d = 6$, direct edge $0 \to 2$ (weight 5) is shorter and the shortest path changes to $0 \to 2$.
Removing zero-weight entries makes vertex 1 unreachable and gives distance 5 to vertex 2 through the direct edge.
Vertex 3 has no edges and is unreachable in every case; Plan, one-shot, and hand-computed distances agree.

### Experimental graph

The next two cells use the same six-vertex directed graph.
The edges are $0 \to 1$: 4, $0 \to 2$: 2, $2 \to 1$: 1, $1 \to 3$: 2, $2 \to 3$: 5, $3 \to 4$: 3, $4 \to 5$: 1, $3 \to 5$: 6, and $4 \to 1$: $w$.
Cycle $1 \to 3 \to 4 \to 1$ has weight $5 + w$, becoming negative when $w < -5$.
Vertex 5 has no outgoing edges, so choosing it as source cannot reach the cycle.
The definitions block provides edge list `network(w)`, a Plan `directed_plan` reading it as a directed graph, independent-check helpers `weight` to look up edge weights and `cycle_weight` to sum cycle weights, and `route` to format a vertex sequence.

```rust
//| id: sparse-shortest-path-network
//| kind: definitions
//| title: "Six-vertex directed graph with cycle 1→3→4→1"
//| crates: [scioxide-core, scioxide-sparse]
use scioxide_core::SciOxideError;
use scioxide_sparse::{
    DuplicatePolicy, ExplicitZeroPolicy, GraphDirection, GraphPlan, SparseBuilder,
};

/// Vertex count V.
pub(crate) const VERTICES: usize = 6;

/// Edge list (u, v, w(u, v)). Only the weight w of edge 4 → 1 changes with input.
pub(crate) fn network(back_weight: f64) -> [(usize, usize, f64); 9] {
    [
        (0, 1, 4.0),
        (0, 2, 2.0),
        (2, 1, 1.0),
        (1, 3, 2.0),
        (2, 3, 5.0),
        (3, 4, 3.0),
        (4, 5, 1.0),
        (3, 5, 6.0),
        (4, 1, back_weight),
    ]
}

/// Plan reading the edge list as a directed graph.
pub(crate) fn directed_plan(edges: &[(usize, usize, f64)]) -> Result<GraphPlan<f64>, SciOxideError> {
    let mut builder = SparseBuilder::new(VERTICES, VERTICES);
    for &(u, v, w) in edges {
        builder.push(u, v, w)?;
    }
    let matrix = builder.finish_csr(DuplicatePolicy::Reject, ExplicitZeroPolicy::Preserve)?;
    GraphPlan::new(matrix.view(), GraphDirection::Directed)
}

/// Look up edge (u, v)'s weight from the edge list (for independent checking).
pub(crate) fn weight(edges: &[(usize, usize, f64)], u: usize, v: usize) -> Option<f64> {
    edges.iter().find(|e| e.0 == u && e.1 == v).map(|e| e.2)
}

/// Sum edge weights of a closed vertex sequence from the edge list (for independent checking).
pub(crate) fn cycle_weight(edges: &[(usize, usize, f64)], cycle: &[usize]) -> Option<f64> {
    cycle.windows(2).map(|p| weight(edges, p[0], p[1])).sum()
}

/// Format a vertex sequence as a string such as “1 → 3 → 4 → 1.”
pub(crate) fn route(vertices: &[usize]) -> String {
    let names: Vec<String> = vertices.iter().map(|v| v.to_string()).collect();
    names.join(" → ")
}
```

### Shortest-path optimality certificates

The following cell applies Bellman–Ford from vertex 0.
The input is $w$ ($-8$–$4$).
When distances are returned, it shows two optimality-condition quantities for every vertex.
Condition 2 holds if $d(v) - d(u) - w(u, v)$ is zero on predecessor edges; condition 1 holds if the maximum of the same quantity over all edges entering $v$ is nonpositive.
When a negative cycle is reported, it independently sums its edge weights from the edge list to check negativity.

```rust
//| id: sparse-graph-certificates
//| ref: sparse-graph-certificates
//| title: "Bellman–Ford distance optimality certificates"
//| run: reactive
//| uses: [sparse-shortest-path-network]
//| crates: [scioxide-core, scioxide-sparse]
//| inputs:
//|   back_weight: {"type":"range","label":"Weight w of edge 4→1","description":"Cycle 1→3→4→1 has weight 5 + w, negative when w < −5.","min":-8.0,"max":4.0,"step":1.0,"value":-2.0}
//| cases:
//|   - {"id":"zero-cycle","label":"w = −5","description":"Making the cycle weight zero leaves shortest distances unchanged.","inputs":{"back_weight":-5}}
//|   - {"id":"negative-cycle","label":"w = −6","description":"The cycle weight becomes −1, and Bellman–Ford returns the cycle instead of distances.","inputs":{"back_weight":-6}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"certificate","path":"/rows/1/1","approx":{"value":3,"atol":1e-15}}
//|       - {"artifact":"certificate","path":"/rows/1/2","equals":2}
//|       - {"artifact":"certificate","path":"/rows/5/1","approx":{"value":9,"atol":1e-15}}
//|       - {"artifact":"certificate","path":"/rows/4/3","approx":{"value":0,"atol":1e-15}}
//|       - {"artifact":"certificate","path":"/rows/1/4","range":{"max":1e-15}}
//|       - {"artifact":"certificate","path":"/rows/0/2","equals":null}
//|   - case: zero-cycle
//|     expect:
//|       - {"artifact":"certificate","path":"/rows/1/1","approx":{"value":3,"atol":1e-15}}
//|       - {"artifact":"certificate","path":"/rows/1/4","range":{"max":1e-15}}
//|   - case: negative-cycle
//|     expect:
//|       - {"artifact":"cycle","path":"/rows/0/0","equals":"1 → 3 → 4 → 1"}
//|       - {"artifact":"cycle","path":"/rows/0/1","approx":{"value":-1,"atol":1e-15}}
use scioxide_sparse::{GraphPathMethod, PathOutcome};

let n = VERTICES;
let edges = network(back_weight);
let graph = directed_plan(&edges).map_err(|e| e.to_string())?;
let outcome = graph
    .shortest_paths(GraphPathMethod::BellmanFord { source: 0 })
    .map_err(|e| e.to_string())?;
match outcome {
    PathOutcome::Paths(result) => {
        let view = result.as_view();
        let (d, parent) = (view.distances(), view.predecessors());
        let mut rows = Vec::new();
        for v in 0..n {
            // Condition 2: d(v) − d(u) − w(u, v) on the edge from predecessor u.
            let tree = match (parent[v], d[v]) {
                (Some(u), Some(dv)) => {
                    let du = d[u].ok_or("The predecessor has no distance")?;
                    let w = weight(&edges, u, v).ok_or("The predecessor edge is absent from the list")?;
                    Some(dv - du - w)
                }
                _ => None,
            };
            // Condition 1: maximum of the same quantity over all edges (u, v) entering v.
            let worst = edges
                .iter()
                .filter(|e| e.1 == v)
                .filter_map(|&(u, _, w)| Some(d[v]? - d[u]? - w))
                .reduce(f64::max);
            rows.push((v, d[v], parent[v], tree, worst));
        }
        let columns = serde_json::json!([
            { "key": "0", "label": "Vertex v", "type": "integer" },
            { "key": "1", "label": "Distance d(v)", "type": "number", "nullText": "Unreachable" },
            { "key": "2", "label": "Predecessor u", "type": "integer", "nullText": "-" },
            { "key": "3", "label": "Difference on predecessor edge", "type": "number", "nullText": "-" },
            { "key": "4", "label": "Maximum difference on incoming edges", "type": "number", "nullText": "-" }
        ]);
        emit_table_with_columns!(
            columns,
            rows,
            metadata = serde_json::json!({ "id": "certificate" })
        );
    }
    PathOutcome::NegativeCycle(cycle) => {
        // Independent check: sum cycle-edge weights from the edge list. Negative weight means distances do not exist.
        let vertices = cycle.vertices();
        let total = cycle_weight(&edges, vertices).ok_or("A cycle edge is absent from the list")?;
        let columns = serde_json::json!([
            { "key": "0", "label": "Negative cycle", "type": "string" },
            { "key": "1", "label": "Cycle weight (from edge list)", "type": "number" }
        ]);
        emit_table_with_columns!(
            columns,
            vec![(route(vertices), total)],
            metadata = serde_json::json!({ "id": "cycle" })
        );
    }
}
```

At the default $w = -2$, cycle weight is 3 and distances are $(0, 3, 2, 5, 8, 9)$.
Vertex 1 is reached more cheaply by $0 \to 2 \to 1$ (weight 3) than by its direct edge (weight 4).
At every vertex other than the source, the predecessor-edge difference is 0 and the maximum incoming-edge difference is also 0, satisfying both conditions.
This table alone verifies shortest distances independently of the algorithm's internals.
At $w = -5$, the cycle weight is zero and edge $4 \to 1$ is also tight, but shortest distances are unchanged.
At $w = -6$, cycle weight becomes $-1$; Bellman–Ford returns cycle $1 \to 3 \to 4 \to 1$ instead of distances, and summing edge-list weights also gives $-1$.

### Negative cycles reported by single-source and all-pairs methods

The following cell compares Bellman–Ford from source $s$ with both all-pairs methods on the same graph.
Inputs are $w$ and source $s$ (0–5); defaults are $w = -6$ with a cycle and $s = 5$ unable to reach it.
When all-pairs methods return distances, it shows the maximum difference between row $s$ and Bellman–Ford distances.
When a negative cycle is reported, it independently sums its edge weights from the edge list.

```rust
//| id: sparse-negative-cycle-reports
//| ref: sparse-negative-cycle-reports
//| title: "Negative cycles reported by single-source and all-pairs methods"
//| run: reactive
//| uses: [sparse-shortest-path-network]
//| crates: [scioxide-core, scioxide-sparse]
//| inputs:
//|   back_weight: {"type":"range","label":"Weight w of edge 4→1","description":"Cycle 1→3→4→1 has weight 5 + w, negative when w < −5.","min":-8.0,"max":4.0,"step":1.0,"value":-6.0}
//|   source: {"type":"range","label":"Source s","description":"Vertex 5 has no outgoing edges and cannot reach the cycle.","min":0,"max":5,"step":1,"value":5}
//| cases:
//|   - {"id":"reachable","label":"s = 0","description":"The source can reach the cycle, so all three methods report the same cycle.","inputs":{"source":0}}
//|   - {"id":"no-cycle","label":"w = −2, s = 0","description":"The cycle weight becomes positive, and distances from all three methods agree.","inputs":{"back_weight":-2,"source":0}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"outcomes","path":"/rows/0/1","equals":"Shortest paths"}
//|       - {"artifact":"outcomes","path":"/rows/1/1","equals":"Negative cycle"}
//|       - {"artifact":"outcomes","path":"/rows/1/3","equals":"1 → 3 → 4 → 1"}
//|       - {"artifact":"outcomes","path":"/rows/2/4","approx":{"value":-1,"atol":1e-15}}
//|   - case: reachable
//|     expect:
//|       - {"artifact":"outcomes","path":"/rows/0/1","equals":"Negative cycle"}
//|       - {"artifact":"outcomes","path":"/rows/0/4","approx":{"value":-1,"atol":1e-15}}
//|   - case: no-cycle
//|     expect:
//|       - {"artifact":"outcomes","path":"/rows/1/1","equals":"Shortest paths"}
//|       - {"artifact":"outcomes","path":"/rows/1/2","range":{"max":1e-15}}
//|       - {"artifact":"outcomes","path":"/rows/2/2","range":{"max":1e-15}}
use scioxide_sparse::{GraphPathMethod, PathOutcome};

let s = source.round() as usize;
let n = VERTICES;
let edges = network(back_weight);
let graph = directed_plan(&edges).map_err(|e| e.to_string())?;
let methods = [
    (
        "Bellman–Ford (source s)",
        GraphPathMethod::BellmanFord { source: s },
    ),
    ("Floyd–Warshall", GraphPathMethod::FloydWarshall),
    ("Johnson", GraphPathMethod::Johnson),
];
// Bellman–Ford distances from source s (the reference for row s of all-pairs methods).
let mut reference: Option<Vec<Option<f64>>> = None;
let mut rows = Vec::new();
for (name, method) in methods {
    match graph.shortest_paths(method).map_err(|e| e.to_string())? {
        PathOutcome::Paths(result) => {
            let view = result.as_view();
            let mut gap = None;
            if view.source().is_some() {
                reference = Some(view.distances().to_vec());
            } else if let Some(base) = &reference {
                let row = &view.distances()[s * n..(s + 1) * n];
                let mut largest = 0.0_f64;
                for pair in base.iter().zip(row) {
                    match pair {
                        (Some(a), Some(b)) => largest = largest.max((a - b).abs()),
                        (None, None) => {}
                        _ => return Err("Reachability differs between methods".to_string()),
                    }
                }
                gap = Some(largest);
            }
            rows.push((name, "Shortest paths", gap, None, None));
        }
        PathOutcome::NegativeCycle(cycle) => {
            let vertices = cycle.vertices();
            // Independent check: sum cycle-edge weights from the edge list.
            let total = cycle_weight(&edges, vertices).ok_or("A cycle edge is absent from the list")?;
            rows.push((name, "Negative cycle", None, Some(route(vertices)), Some(total)));
        }
    }
}
let columns = serde_json::json!([
    { "key": "0", "label": "Method", "type": "string" },
    { "key": "1", "label": "Result", "type": "string" },
    { "key": "2", "label": "Maximum difference between row s and Bellman–Ford", "type": "number", "nullText": "-" },
    { "key": "3", "label": "Cycle vertex sequence", "type": "string", "nullText": "-" },
    { "key": "4", "label": "Cycle weight (from edge list)", "type": "number", "nullText": "-" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "outcomes" })
);
```

At the defaults $w = -6$ and $s = 5$, Bellman–Ford returns distances, reaching only vertex 5 itself at distance 0.
All-pairs methods examine the entire graph and report cycle $1 \to 3 \to 4 \to 1$ unreachable from this source; summing the edge-list weights gives $-1$.
At $s = 0$, the source reaches the cycle and all three methods report the same cycle.
At $w = -2$ and $s = 0$, the cycle weight is positive and all three methods return distances; row 0 of the all-pairs methods agrees with Bellman–Ford.

## Summary

Choose Dijkstra for nonnegative weights, Bellman–Ford when negative weights occur, Floyd–Warshall for all pairs on small dense graphs, and Johnson on sparse graphs.
Computed distances can be verified as shortest independently of the algorithm by feasibility on every edge and equality on predecessor edges.
Plan methods return negative cycles as closed vertex sequences in the outcome; the one-shot function `shortest_paths` reports `DomainError` instead.
Single-source methods report only reachable cycles, while all-pairs methods report cycles anywhere in the graph.
Use scoped forms for iteration limits; Johnson applies the same limit separately to each source's search.
