These tables collect preconditioners passed to iterative solvers such as Krylov methods.
`IdentityPreconditioner`, `JacobiPreconditioner`, `IncompleteFactor`, `AmgCycle`, `AmgPreconditioner`, and `SchwarzPlan` implement scioxide-core's `Preconditioner`.
This trait's `precondition_workspace_len` first returns the workspace length, and `precondition_into` applies it with default `SparseSolveOptions` (`Standard`, sequential).
`precondition_into_scoped` inherits the caller's execution context (cancellation and deadline) but does not count iterations.
The calling solver counts applications as preconditioner evaluations.

Each type's inherent methods include standard forms and output-buffer APIs.
Standard `apply(rhs)` (`solve` for `IncompleteFactor`) uses default `SparseSolveOptions`, new workspace, and `ExecutionContext::sequential_native()`, returning the result in a new array.
Output-buffer APIs `apply_into` and `apply_block_into` (`solve_into` and `solve_block_into` for `IncompleteFactor`) accept `SparseSolveOptions`, output, shared `SparseSolveWorkspace`, and a scope.
Query workspace with `workspace_requirements(rhs)` and construct it with `workspace(rhs)`; output-buffer APIs do not allocate when given preallocated workspace.
Output-buffer APIs count one iteration per right-hand side and return `ConvergenceFailure` (`IterationLimit`) on reaching the iteration limit in `SparseSolveOptions` or the scope.
Every form writes output only after checks and computation finish, leaving output unchanged on failure.
Successful construction and diagnostic values do not certify preconditioner quality or iterative convergence.

Size mismatch gives `DimensionMismatch`, nonfinite weights `NonFinite`. `plan_bytes()`, `preparation_peak_bytes()`, `kind()`. Counts one iteration per right-hand side, one evaluation per local solve, and in multiplicative one per residual update; reaching the evaluation limit gives `ConvergenceFailure` (`EvaluationLimit`). The two additive forms solve subdomains in parallel according to policy and sum corrections in subdomain order, making results independent of worker count. Multiplicative is always sequential.
