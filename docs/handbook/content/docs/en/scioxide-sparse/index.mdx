Finite-element and finite-difference stiffness matrices, circuit nodal equations, and network adjacency matrices are **sparse matrices**, with most entries zero.
Even with $n = 10^6$ unknowns, about a dozen nonzeros per row requires only $O(n)$ stored entries; the same matrix in dense double precision needs $8n^2$ bytes, or 8 TB.
Sparse computation stores only nonzero positions and values and computes only at those positions.

`scioxide-sparse` provides sparse storage and assembly, products, sparse direct factorization, iterative preconditioners, ordering and coloring, and graph algorithms.
Formats are COO, CSR, CSC, BSR, and DIA; assembly through `SparseBuilder` requires callers to specify duplicate-position and zero-value treatment.
Sparse LU, Cholesky, LDL, and QR separate structure-only symbolic analysis from value-based numerical factorization, allowing symbolic analysis reuse when structure matches.
Preconditioners include Jacobi, incomplete factorization, algebraic multigrid (AMG), and overlapping Schwarz, implementing scioxide-core's `Preconditioner`.
Triangular orientation `Triangle`, diagonal representation `DiagonalKind`, permutations `Permutation`, structures `StructuralPattern`, and operator traits come from scioxide-core.
scioxide-linalg provides iterative solvers such as conjugate gradients and GMRES, accepting this chapter's matrices and preconditioners directly.
Real and complex `f32` and `f64` scalars are supported.

## First computation: tridiagonal assembly and multiplication

The following cell assembles a three-unknown tridiagonal matrix $\mathbf{A} = \mathrm{tridiag}(-1, \alpha, -1)$ with `SparseBuilder` and finalizes it as CSR.
At $\alpha = 2$ this is a one-dimensional Poisson difference matrix; $\alpha > 2$ strengthens the diagonal.
It then computes $\mathbf{y} = \mathbf{A}\mathbf{x}$ for $\mathbf{x} = (1, 2, 1)^{\mathsf{T}}$ into a separate array with `apply_into` and uses the one-shot function ([calling forms](oxref:sparse-execution-forms)) `solve` to solve $\mathbf{A}\hat{\mathbf{x}} = \mathbf{y}$, checking recovery of $\mathbf{x}$.
The input is diagonal value $\alpha$ (2–6).
The first table lists stored CSR entries in storage order; the second compares the product to hand-computed $(\alpha - 2,\ 2\alpha - 2,\ \alpha - 2)$ and shows the error in recovered $\hat{\mathbf{x}}$.

```rust
//| id: sparse-intro-first-computation
//| ref: sparse-intro-first-computation
//| title: "Tridiagonal assembly, matrix–vector multiplication, and recovery by solving"
//| run: reactive
//| crates: [scioxide-core, scioxide-sparse]
//| inputs:
//|   diff_scale: {"type":"range","label":"Diagonal value α","description":"Main diagonal of the tridiagonal matrix. At 2 it is a one-dimensional difference Laplacian.","min":2.0,"max":6.0,"step":0.5,"value":2.0}
//| cases:
//|   - {"id":"stronger-diagonal","label":"α = 3","description":"Strengthening the diagonal increases every product entry, giving y = (1, 4, 1).","inputs":{"diff_scale":3.0}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"csr","path":"/rows/6/1","equals":2}
//|       - {"artifact":"csr","path":"/rows/6/2","equals":2}
//|       - {"artifact":"csr","path":"/rows/1/3","approx":{"value":-1.0,"atol":1e-15}}
//|       - {"artifact":"product","path":"/rows/0/2","approx":{"value":0.0,"atol":1e-15}}
//|       - {"artifact":"product","path":"/rows/1/2","approx":{"value":2.0,"atol":1e-15}}
//|       - {"artifact":"product","path":"/rows/1/5","range":{"max":1e-14}}
//|   - case: stronger-diagonal
//|     expect:
//|       - {"artifact":"product","path":"/rows/0/2","approx":{"value":1.0,"atol":1e-15}}
//|       - {"artifact":"product","path":"/rows/1/2","approx":{"value":4.0,"atol":1e-15}}
//|       - {"artifact":"product","path":"/rows/2/5","range":{"max":1e-14}}
use scioxide_core::LinearOperator;
use scioxide_sparse::{DuplicatePolicy, ExplicitZeroPolicy, SparseBuilder};

let n = 3;
let mut builder = SparseBuilder::new(n, n);
for i in 0..n {
    builder.push(i, i, diff_scale).map_err(|e| e.to_string())?;
    if i > 0 {
        builder.push(i, i - 1, -1.0).map_err(|e| e.to_string())?;
        builder.push(i - 1, i, -1.0).map_err(|e| e.to_string())?;
    }
}
// Duplicates should not occur, so check with Reject and remove zero-valued entries.
let a = builder
    .finish_csr(DuplicatePolicy::Reject, ExplicitZeroPolicy::Drop)
    .map_err(|e| e.to_string())?;
// (row, column, value) at storage position k. CSR sorts columns increasingly within each row.
let stored: Vec<(usize, usize, usize, f64)> = a
    .iter()
    .enumerate()
    .map(|(k, (i, j, v))| (k, i, j, v))
    .collect();

let x = [1.0_f64, 2.0, 1.0];
let mut y = [0.0; 3];
// apply_workspace_len() returns workspace length.
let mut work = vec![0.0; a.apply_workspace_len().map_err(|e| e.to_string())?];
a.apply_into(&x, &mut y, &mut work)
    .map_err(|e| e.to_string())?;
// Solve A x̂ = y with the one-shot solve function and check recovery of x.
let x_hat = scioxide_sparse::solve(&a, &y).map_err(|e| e.to_string())?;
// Independent check: product computed by hand.
let expected = [diff_scale - 2.0, 2.0 * diff_scale - 2.0, diff_scale - 2.0];
let rows: Vec<_> = (0..n)
    .map(|i| {
        (
            i,
            x[i],
            y[i],
            expected[i],
            x_hat[i],
            (x_hat[i] - x[i]).abs(),
        )
    })
    .collect();

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let plain = serde_json::json!({ "significantDigits": 6 });
let csr_columns = serde_json::json!([
    { "key": "0", "label": "Storage position k", "type": "integer" },
    { "key": "1", "label": "Row i", "type": "integer" },
    { "key": "2", "label": "Column j", "type": "integer" },
    { "key": "3", "label": "Value a_ij [-]", "type": "number", "format": plain }
]);
emit_table_with_columns!(
    csr_columns,
    stored,
    metadata = serde_json::json!({ "id": "csr" })
);
let product_columns = serde_json::json!([
    { "key": "0", "label": "Component i", "type": "integer" },
    { "key": "1", "label": "x_i [-]", "type": "number", "format": plain },
    { "key": "2", "label": "y_i（apply_into）[-]", "type": "number", "format": plain },
    { "key": "3", "label": "y_i (by hand) [-]", "type": "number", "format": plain },
    { "key": "4", "label": "x̂_i（solve）[-]", "type": "number", "format": plain },
    { "key": "5", "label": "|x̂_i − x_i| [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    product_columns,
    rows,
    metadata = serde_json::json!({ "id": "product" })
);
```

## Reading results

The first table lists seven entries: three diagonals and four neighbors; two of the $3 \times 3 = 9$ entries are zero and unstored.
Entries follow row order and ascending columns within each row.
This is CSR storage order; a separate `row_ptr()` array gives row boundaries ([sparse storage formats and assembly](algorithms/storage-and-assembly/)).

At the default $\alpha = 2$, $\mathbf{y} = (0, 2, 0)$ agrees with hand calculation.
Increasing $\alpha$ raises each entry of $\mathbf{y}$ by the extra diagonal contribution, giving $\mathbf{y} = (1, 4, 1)$ at $\alpha = 3$.
For every $\alpha$ in the input range, $\hat{\mathbf{x}}$ recovered with `solve` matches $\mathbf{x}$ bitwise, giving zero table differences.
For general matrices, recovery error depends on rounding and the condition number of $\mathbf{A}$ and need not be zero.
`solve` factorizes on every call; for repeated solves of the same matrix, retain factors built with `SparseLu::new` and repeat their `lu.solve` method.

`apply_into` checks lengths before computation and computes all results in workspace before copying to $\mathbf{y}$, leaving $\mathbf{y}$ unchanged on failure.
Product error bounds and once-rounded `Exact` arithmetic are covered in [matrix–vector and sparse matrix products](algorithms/kernels-and-products/).

## Summary

`scioxide-sparse` provides products, direct factorizations, preconditioners, and graph algorithms using canonical sparse formats with value updates preserving finalized structure.
Specify duplicate and zero-value policies in `SparseBuilder` and finalize once into CSR or CSC.
For a single solve, one-shot functions such as `solve` and `least_squares` suffice; for repeated solves of the same matrix, create and reuse factors with `SparseLu::new` or similar constructors.
For sequences of structurally identical matrices, retain symbolic analysis and workspace and repeat only numerical factorization with `refactor`; analysis forms with memory limits stop with `ResourceLimit` if memory exceeds them.
Output-writing operations preserve output and previous factors on failure, allowing error classification `e.kind()` to guide continuation from the previous state.
