Shape-approximation accuracy, remaining point-cloud registration error, and discrepancies between scanned data and a design shape can be measured by how far apart two point sets lie.
Use the Hausdorff distance to measure the worst local discrepancy rather than average separation.
This page explains directed and symmetric Hausdorff distances and their properties, an algorithm reducing all-pairs computation through early termination, distance-realizing pairs identifying the most separated locations, and an alternative using a KD tree.
[Distances and dissimilarities](../distances/) explains point sets and distance handling.

## Definition and properties

For two nonempty finite point sets $A$ ($m$ points) and $B$ ($n$ points), define the directed Hausdorff distance from $A$ to $B$ as:

$$
h(A, B) = \max_{a \in A} \min_{b \in B} \lVert a - b\rVert_2
$$

$\min_{b}$ is the distance from $a$ to the nearest point of $B$; $h(A, B)$ is its maximum, measuring how far the point in $A$ farthest from $B$ lies.
Equivalently, $h(A, B)$ is the smallest $\varepsilon$ such that the union of closed balls of radius $\varepsilon$ centered at points of $B$ covers $A$.

$h$ is asymmetric; in general, $h(A, B) \ne h(B, A)$.
For finite sets, $h(A, B) = 0$ is equivalent to $A \subseteq B$, so points in $B$ absent from $A$ do not appear in $h(A, B)$.
The directed distance satisfies the triangle inequality $h(A, C) \le h(A, B) + h(B, C)$.
The larger of the two directions,

$$
H(A, B) = \max\bigl(h(A, B),\; h(B, A)\bigr)
$$

is the symmetric Hausdorff distance, a metric on nonempty finite sets.
Since $H$ is determined by a maximum, one outlier makes it large even if other points agree closely.
For an outlier-resistant measure, use another quantity such as a mean or quantile of nearest-neighbor distances.

`directed_hausdorff(&source, &target)` computes $h(\mathrm{source}, \mathrm{target})$ using Euclidean distance and returns `HausdorffResult`.
Pass point sets as `PointSet` (one point per row), with arbitrary dimension and coordinates of type `f32` or `f64`.
`distance` is $h$, `source` is the farthest source point's index, and `target` is the index of the target point nearest to it.
These two points are called a distance-realizing pair.
To obtain symmetric $H$, call twice and take the larger value.
Only Euclidean distance is supported; other distances cannot be selected.

If either set is empty, $h$ is undefined and returns `DomainError`; mismatched set dimensions return `DimensionMismatch`.
An unrepresentable distance gives `NumericalInstability`, but overflow in pairs skipped by early termination is not reported.
It allocates $O(m + n)$ index storage for traversal order and returns `AllocationFailure` if allocation fails.

## Early-termination algorithm

Direct evaluation examines distances from every point of $A$ to every point of $B$, costing $O(mnd)$.
The Taha–Hanbury algorithm terminates the inner loop using the largest value $c_{\max}$ found so far.
For source point $a$, examine target points $b$ in order; once a $b$ satisfying $\lVert a - b\rVert_2 < c_{\max}$ is found, the nearest-point distance of $a$ is known to be below $c_{\max}$.
Such a $a$ cannot update the maximum, so remaining $b$ need not be examined before moving to the next $a$.
Only $a$ examined to completion without early termination have a fully determined nearest-point distance $\min_b \lVert a - b\rVert_2$.
If that distance exceeds $c_{\max}$, update the maximum and distance-realizing pair; if it equals $c_{\max}$, replace the pair only for a smaller index.
Terminated $a$ cannot attain the maximum, so early termination leaves the maximum unchanged and gives the value from the definition.

`directed_hausdorff` traverses source and target points in a randomized order (Fisher–Yates shuffle) with a fixed seed.
Some input orders would examine many points to completion while the maximum is still small; shuffling avoids that bias.
The fixed seed gives the same order on every run with identical input.
Target-point distances are computed in blocks of 32, terminating when a block minimum is below $c_{\max}$.
Distance comparisons use values rounded to the result scalar type (`f32` or `f64`).

Without early termination, the computational cost remains the direct-evaluation cost $O(mnd)$.
For example, with $h(A, B) = 0$, meaning $A \subseteq B$, $c_{\max}$ stays 0 and no $b$ satisfies $\lVert a - b\rVert_2 < 0$, so every $a$ examines all points of $B$.
The expected computational cost under randomized order is reported to be much smaller than the worst case (Taha–Hanbury), but the reduction depends on point configuration.

## Choosing a distance-realizing pair

If several target points share the nearest distance, `target` is the smallest-index point.
If several source points attain the maximum, `source` is the smallest-index point.
This rule is independent of traversal order, so the pair depends only on computed distances and point indices and matches an exhaustive search of the all-pairs distance matrix.
Points with equal closed-form distances can differ in their final computed digits through rounding; in that case, the largest computed distance selects the point.

The next cell compares $A$, with $n k$ equally spaced points on the unit circle, and $B$, formed by selecting every $k$th point as the vertices of a regular $n$-gon and shifting them by $\delta$ [m] along $x$.
At $\delta = 0$, $B \subset A$ implies $h(B, A) = 0$, and no early termination occurs in this direction.
If $k$ is even, $A$ includes points exactly midway between adjacent vertices, and their chord distance to the nearest vertex,

$$
h(A, B) = 2 \sin\frac{\pi}{2n}
$$

is maximal.
As an independent check, build the all-pairs distance matrix with `pairwise` and exhaustively find the maximum of row minima.
The table shows distances in both directions, distance-realizing pairs, exhaustive values, and closed forms (only at $\delta = 0$); the plot shows both sets and a segment joining the pair realizing $h(A, B)$.

```rust
//| id: spatial-hausdorff-witness
//| ref: spatial-hausdorff-witness
//| title: "Check directed Hausdorff distances between circle samples and regular-polygon vertices against exhaustive search and closed forms"
//| run: reactive
//| crates: [scioxide-core, scioxide-spatial]
//| inputs:
//|   vertices: {"type":"range","label":"Regular-polygon vertex count n","min":3,"max":24,"step":1,"value":6}
//|   samples_per_edge: {"type":"range","label":"Circle samples per edge k","min":2,"max":16,"step":2,"value":4}
//|   shift: {"type":"range","label":"B's x-direction shift δ [m]","min":0,"max":1,"step":0.1,"value":0}
//| cases:
//|   - {"id":"shifted","label":"δ = 0.5 m","description":"h(B, A) becomes positive too, changing both directed values. Agreement with exhaustive search is maintained.","inputs":{"shift":0.5}}
//|   - {"id":"fine-polygon","label":"n = 24","description":"h(A, B) = 2 sin(π/48) ≈ 0.1308 m, decreasing inversely with vertex count.","inputs":{"vertices":24}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"hausdorff","path":"/rows/0/1","approx":{"value":0.5176380902050415,"rtol":1e-14}}
//|       - {"artifact":"hausdorff","path":"/rows/0/4","approx":{"value":0.5176380902050415,"rtol":1e-14}}
//|       - {"artifact":"hausdorff","path":"/rows/0/2","equals":18}
//|       - {"artifact":"hausdorff","path":"/rows/0/5","equals":18}
//|       - {"artifact":"hausdorff","path":"/rows/1/1","equals":0}
//|   - case: shifted
//|     expect:
//|       - {"artifact":"hausdorff","path":"/rows/0/1","approx":{"value":0.7247448713915892,"rtol":1e-14}}
//|       - {"artifact":"hausdorff","path":"/rows/1/1","approx":{"value":0.5,"rtol":1e-14}}
//|       - {"artifact":"hausdorff","path":"/rows/1/4","approx":{"value":0.5,"rtol":1e-14}}
//|   - case: fine-polygon
//|     expect:
//|       - {"artifact":"hausdorff","path":"/rows/0/1","approx":{"value":0.13080625846028612,"rtol":1e-14}}
use scioxide_core::{NdView, RealScalar, StridedLayout};
use scioxide_spatial::{HausdorffResult, PointSet, directed_hausdorff, pairwise};

// A: m = n k points on the unit circle. B: every kth point (regular n-gon vertices), shifted by δ along x.
let (n, k) = (vertices as usize, samples_per_edge as usize);
let m = n * k;
let angle = |i: usize| 2.0 * core::f64::consts::PI * i as f64 / m as f64;
let circle: Vec<f64> = (0..m)
    .flat_map(|i| [RealScalar::cos(angle(i)), RealScalar::sin(angle(i))])
    .collect();
// B's vertices are exactly A's points j k (B ⊂ A when δ = 0).
let polygon: Vec<f64> = (0..n)
    .flat_map(|j| [circle[2 * j * k] + shift, circle[2 * j * k + 1]])
    .collect();
let (shape_a, shape_b, strides) = ([m, 2], [n, 2], [2, 1]);
let layout_a = StridedLayout::new(&shape_a, &strides).map_err(|e| e.to_string())?;
let layout_b = StridedLayout::new(&shape_b, &strides).map_err(|e| e.to_string())?;
let a = PointSet::new(NdView::new(&circle, layout_a).map_err(|e| e.to_string())?)
    .map_err(|e| e.to_string())?;
let b = PointSet::new(NdView::new(&polygon, layout_b).map_err(|e| e.to_string())?)
    .map_err(|e| e.to_string())?;
let ab = directed_hausdorff(&a, &b).map_err(|e| e.to_string())?;
let ba = directed_hausdorff(&b, &a).map_err(|e| e.to_string())?;

// Independent check: exhaustively find the maximum row minimum of the pairwise matrix (smaller indices break ties).
let brute = |left: &PointSet<f64>, right: &PointSet<f64>| {
    let table = pairwise(left, right)?;
    let mut best = (-1.0, 0, 0);
    for (row, distances) in table.as_slice().chunks(right.len()).enumerate() {
        let mut nearest = (f64::INFINITY, 0);
        for (column, &d) in distances.iter().enumerate() {
            if d < nearest.0 {
                nearest = (d, column);
            }
        }
        if nearest.0 > best.0 {
            best = (nearest.0, row, nearest.1);
        }
    }
    Ok::<_, scioxide_core::SciOxideError>(best)
};
let brute_ab = brute(&a, &b).map_err(|e| e.to_string())?;
let brute_ba = brute(&b, &a).map_err(|e| e.to_string())?;
// Closed form (only when δ = 0): reference value using standard f64 functions.
let chord = (shift == 0.0).then(|| 2.0 * (core::f64::consts::PI / (2.0 * n as f64)).sin());
let row = |label, h: &HausdorffResult<f64>, brute: (f64, usize, usize), exact: Option<f64>| {
    (
        label, h.distance, h.source, h.target, brute.0, brute.1, brute.2, exact,
    )
};
let rows = vec![
    row("h(A, B)", &ab, brute_ab, chord),
    row("h(B, A)", &ba, brute_ba, chord.map(|_| 0.0)),
];
let fixed6 = serde_json::json!({ "fractionDigits": 6 });
let columns = serde_json::json!([
    { "key": "0", "label": "Direction" },
    { "key": "1", "label": "Distance [m]", "type": "number", "format": fixed6 },
    { "key": "2", "label": "Realizing source point", "type": "integer" },
    { "key": "3", "label": "Realizing target point", "type": "integer" },
    { "key": "4", "label": "Exhaustive distance [m]", "type": "number", "format": fixed6 },
    { "key": "5", "label": "Exhaustive source point", "type": "integer" },
    { "key": "6", "label": "Exhaustive target point", "type": "integer" },
    { "key": "7", "label": "Closed form [m]", "type": "number", "format": fixed6, "nullText": "—" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "hausdorff" })
);

// A, B, and a segment connecting the pair realizing h(A, B).
let points_of = |coordinates: &[f64]| -> Vec<[f64; 2]> {
    coordinates.chunks(2).map(|p| [p[0], p[1]]).collect()
};
let witness = vec![
    [circle[2 * ab.source], circle[2 * ab.source + 1]],
    [polygon[2 * ab.target], polygon[2 * ab.target + 1]],
];
emit_chart!(serde_json::json!({
    "kind": "xy",
    "xLabel": "x [m]",
    "yLabel": "y [m]",
    "xMin": -1.2,
    "xMax": 2.2,
    "yMin": -1.2,
    "yMax": 1.2,
    "tooltip": true,
    "layers": [
        { "id": "a", "kind": "scatter", "name": "A (circle samples)", "points": points_of(&circle) },
        {
            "id": "b",
            "kind": "scatter",
            "name": "B (regular-polygon vertices)",
            "points": points_of(&polygon),
            "style": { "symbol": "diamond" }
        },
        { "id": "witness", "kind": "line", "name": "Pair realizing h(A, B)", "points": witness }
    ]
}));
```

With defaults ($n = 6$, $k = 4$, $\delta = 0$), $h(A, B)$ agrees with the closed form $2\sin(\pi/12) \approx 0.517638$ m, and $h(B, A) = 0$.
The six midpoint samples have identical closed-form distances, but rounded computations differ in their final digits, selecting midpoint 18 and vertex 4 as the distance-realizing pair.
Exhaustive search returns the same pair, so pair selection depends only on computed distances and indices, not traversal order.
At $\delta = 0.5$ m, $B$ moves off the circle, making $h(B, A)$ positive too and exposing the difference between directions.
For every input, the early-termination distance and pair agree with exhaustive search of the all-pairs distance matrix.
At $n = 24$, the distance is $h(A, B) = 2\sin(\pi/48) \approx 0.130806$ m; increasing polygon vertices shrinks the largest discrepancy from circle samples in proportion to $1/n$.

## Relationship to KD-tree computation

$h(A, B)$ is also the maximum nearest-neighbor distance in $B$ over points of $A$.
Thus it can also be computed by constructing a `KdTree` on $B$ and querying every point of $A$ with `nearest_batch_into` using $k = 1$.
Tree construction costs $O(d\,n\log n)$; for roughly uniform points in low dimensions, each query ends after examining few leaves ([Neighbor search with KD trees](../spatial-trees-and-distance/)).
When comparing many sets with the same $B$, the tree can be reused, supporting `CityBlock`, `Chebyshev`, and `Minkowski(p)` ($p \ge 1$) from `TreeMetric`, as well as periodic boxes.
`directed_hausdorff` performs a single comparison without preprocessing and supports only Euclidean distance.
KD-tree results sort by (distance, index), so nearest-neighbor ties select the smallest index.
Breaking maximum source-point ties by smaller index also gives the same distance-realizing pair as `directed_hausdorff`.

The next cell uses random seed $s$ to place $m$ points of $A$ in the unit square and $n$ points of $B$ in its central square $[0.25, 0.75]^2$.
$h(A, B)$ is large near the corners of $A$, while $h(B, A)$ is small.
Compute $h$ in both directions using both `directed_hausdorff` and batch KD-tree one-neighbor queries, and compare distances and distance-realizing pairs.

```rust
//| id: spatial-hausdorff-kdtree
//| ref: spatial-hausdorff-kdtree
//| title: "Recompute directed Hausdorff distances with KD-tree nearest-neighbor queries"
//| run: reactive
//| crates: [scioxide-core, scioxide-random, scioxide-spatial]
//| inputs:
//|   source_count: {"type":"range","label":"A point count m","min":10,"max":2000,"step":10,"value":400}
//|   target_count: {"type":"range","label":"B point count n","min":10,"max":2000,"step":10,"value":200}
//|   seed: {"type":"range","label":"Random seed s","min":1,"max":50,"step":1,"value":11}
//| cases:
//|   - {"id":"large","label":"m = n = 2000","description":"Increasing the point count still gives identical distances and distance-realizing pairs from both computations.","inputs":{"source_count":2000,"target_count":2000}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"comparison","path":"/rows/0/1","approx":{"value":0.3935228633647214,"rtol":1e-14}}
//|       - {"artifact":"comparison","path":"/rows/0/2","equals":35}
//|       - {"artifact":"comparison","path":"/rows/0/5","equals":35}
//|       - {"artifact":"comparison","path":"/rows/0/7","range":{"max":1e-15}}
//|       - {"artifact":"comparison","path":"/rows/1/2","equals":26}
//|       - {"artifact":"comparison","path":"/rows/1/5","equals":26}
//|       - {"artifact":"comparison","path":"/rows/1/7","range":{"max":1e-15}}
//|   - case: large
//|     expect:
//|       - {"artifact":"comparison","path":"/rows/0/1","approx":{"value":0.3651021533521946,"rtol":1e-14}}
//|       - {"artifact":"comparison","path":"/rows/0/7","range":{"max":1e-15}}
//|       - {"artifact":"comparison","path":"/rows/1/7","range":{"max":1e-15}}
use core::num::NonZeroUsize;
use scioxide_core::{ExecutionContext, NdView, StridedLayout};
use scioxide_random::{SeedableRng, SplitMix64, fill_uniforms};
use scioxide_spatial::{
    KdTree, Neighbor, PointSet, SearchOptions, SearchWorkspaceRequest, directed_hausdorff,
};

// A has uniform points in the unit square; B in the central square [0.25, 0.75]² (one point per row).
let (m, n) = (source_count as usize, target_count as usize);
let mut rng = SplitMix64::from_seed(seed as u64);
let (mut a, mut b) = (vec![0.0_f64; 2 * m], vec![0.0_f64; 2 * n]);
fill_uniforms(&mut rng, &mut a, &mut 0).map_err(|e| e.to_string())?;
fill_uniforms(&mut rng, &mut b, &mut 0).map_err(|e| e.to_string())?;
b.iter_mut().for_each(|x| *x = 0.25 + 0.5 * *x);
let (shape_a, shape_b, strides) = ([m, 2], [n, 2], [2, 1]);
let layout_a = StridedLayout::new(&shape_a, &strides).map_err(|e| e.to_string())?;
let layout_b = StridedLayout::new(&shape_b, &strides).map_err(|e| e.to_string())?;
let set_a = PointSet::new(NdView::new(&a, layout_a).map_err(|e| e.to_string())?)
    .map_err(|e| e.to_string())?;
let set_b = PointSet::new(NdView::new(&b, layout_b).map_err(|e| e.to_string())?)
    .map_err(|e| e.to_string())?;

// KD-tree h(source, target): build a tree on target and take the maximum one-neighbor distance for all source points.
let via_tree = |source: &PointSet<f64>, target: &PointSet<f64>| {
    let tree = KdTree::new(target)?;
    let options = SearchOptions::new();
    let count = source.len();
    let request =
        SearchWorkspaceRequest::new(1, options).with_batch(count, count, NonZeroUsize::MIN);
    let mut workspace = tree.workspace(request)?;
    let mut found = vec![Neighbor::default(); count];
    let context = ExecutionContext::sequential();
    tree.nearest_batch_into(source, 1, options, &mut found, &mut workspace, context)?;
    // For equal maxima, retain the smaller-index source point.
    let mut best = (-1.0, 0, 0);
    for (i, neighbor) in found.iter().enumerate() {
        if neighbor.distance > best.0 {
            best = (neighbor.distance, i, neighbor.index);
        }
    }
    Ok::<_, scioxide_core::SciOxideError>(best)
};
let mut rows = Vec::new();
for (label, source, target) in [("h(A, B)", &set_a, &set_b), ("h(B, A)", &set_b, &set_a)] {
    let direct = directed_hausdorff(source, target).map_err(|e| e.to_string())?;
    let tree = via_tree(source, target).map_err(|e| e.to_string())?;
    let gap = (direct.distance - tree.0).abs();
    rows.push((
        label,
        direct.distance,
        direct.source,
        direct.target,
        tree.0,
        tree.1,
        tree.2,
        gap,
    ));
}
let fixed6 = serde_json::json!({ "fractionDigits": 6 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "Direction" },
    { "key": "1", "label": "directed_hausdorff [-]", "type": "number", "format": fixed6 },
    { "key": "2", "label": "Source point", "type": "integer" },
    { "key": "3", "label": "Target point", "type": "integer" },
    { "key": "4", "label": "KD tree [-]", "type": "number", "format": fixed6 },
    { "key": "5", "label": "KD-tree source point", "type": "integer" },
    { "key": "6", "label": "KD-tree target point", "type": "integer" },
    { "key": "7", "label": "Distance difference [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "comparison" })
);
```

With defaults ($m = 400$, $n = 200$, $s = 11$), $h(A, B) = 0.393523$ and $h(B, A) = 0.074170$ agree bit for bit between computations, and the distance-realizing pairs agree as $(35, 12)$ and $(26, 312)$.
$h(A, B)$ is determined by the distance from a point near a corner of $A$ to $B$; increasing points in $B$ approaches the distance $\sqrt2/4 \approx 0.353553$ from a unit-square corner to a central-square corner ($0.365102$ at $m = n = 2000$).
$h(B, A)$ depends on how far points of $B$ lie in gaps between points of $A$ and decreases as $A$ increases ($0.035856$ at $m = n = 2000$).
The large difference between directions demonstrates the asymmetry of $h$.

## Summary

To measure the worst shape discrepancy, call `directed_hausdorff` in both directions and take their maximum as symmetric Hausdorff distance $H$.
Taha–Hanbury early termination preserves the defined result, and smallest-index tie breaking makes the distance-realizing pair reproducible for identifying the most separated location.
Configurations without early termination, such as $A \subseteq B$, retain all-pairs cost $O(mnd)$; account for this worst case with large sets.
A single outlier can make the value large; use mean or quantile nearest-neighbor distances to assess average agreement.
For repeated queries on the same set, non-Euclidean `TreeMetric` distances, or periodic boxes, compute the same quantity as the maximum KD-tree one-neighbor query distance.
