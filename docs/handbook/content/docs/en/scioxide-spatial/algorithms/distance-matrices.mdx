Linkage methods for hierarchical clustering and multidimensional scaling use distances between all pairs in a point set together.
There are $n^2$ pairs among $n$ points, raising the questions of array layout and required memory.
This page explains all-pairs distance array layouts, condensed storage for pairs within one set using half the memory and its indices, matrix conversions and validation, workspace size, and output handling on failure.
[Distances and dissimilarities](../distances/) covers distance definitions and domains.

## Pairwise distance matrices and condensed storage

The `pairwise_into(&left, &right, options, &mut output, &mut ws, cx)` method of `PreparedDistance` writes all pairwise distances between a left set ($n_\ell$ points) and a right set ($n_r$ points) to a row-major $n_\ell \times n_r$ array.
The distance between left point $i$ and right point $j$ is at `output[i * n_r + j]`.
The convenience method `pairwise(&left, &right)` returns the same values in a row-major `scioxide-linalg` matrix `Matrix`, using default options and sequential execution on the caller's thread.
The function `pairwise(&left, &right)` also computes a Euclidean distance matrix.

Within one set ($n$ points), the distance matrix is symmetric with zero diagonal; storing only pairs $i < j$ row by row as a condensed distance vector requires length $n(n - 1)/2$.
Pairs appear in order $(0, 1), (0, 2), \ldots, (0, n - 1), (1, 2), \ldots$; pair $(i, j)$ is at position:

$$
k(i, j) = \frac{n(n - 1)}{2} - \frac{(n - i)(n - i - 1)}{2} + (j - i - 1)
$$

The first term is the total length and the second counts pairs from row $i$ onward; their difference counts pairs before row $i$.
`condensed_len(n)` returns the length and `condensed_index(n, i, j)` the position; failure to satisfy $i < j < n$ returns `InvalidInput`, and a result exceeding `usize` returns `SizeOverflow`.
The `condensed_into(&points, options, &mut output, &mut ws, cx)` method of `PreparedDistance` writes condensed storage directly; method `condensed(&points)` and Euclidean-distance function `condensed(&points)` return condensed storage as a `Vec`.
`condensed_to_square_into` expands condensed storage to a row-major $n \times n$ array; `condensed_to_square(n, &values)` returns the same values as a `Matrix`.
`square_to_condensed_into` validates a matrix before copying its upper triangle to condensed storage; `square_to_condensed(matrix, tolerance)` returns the same values as a `Vec`.
Every allocating form executes sequentially with default options.

The following two functions validate externally supplied arrays.
`validate_condensed(n, values)` returns `InvalidInput` if the length is not $n(n - 1)/2$, and `DomainError` for negative or non-finite values.
`validate_distance_matrix(matrix, tolerance)` returns `DimensionMismatch` for a nonsquare matrix and `NonFinite` for non-finite values.
It also rejects negative values, asymmetry, or diagonal values exceeding absolute tolerance `tolerance` with `DomainError`.
Neither checks the triangle inequality.

Pairs are computed in blocks of 256.
For `Euclidean` (including `Minkowski` of $p = 2$), `SquaredEuclidean`, `CityBlock`, and `Chebyshev` with contiguous rows, each block computes without per-pair checks, then checks once at its end for overflow, subnormal sums of squares, and zero distances between different coordinates.
Blocks failing these checks are recomputed with full per-pair checks.
Other distances and strided layouts use per-pair checks from the start.
All paths use the same operation order, so the layout does not change result bits.

The next cell places $n$ points in the unit square using random seed $s$ and computes all-pairs distances in three ways with the selected distance.
These are the `PreparedDistance::pairwise` matrix, `PreparedDistance::condensed_into` condensed storage, and the matrix obtained by expanding it with `condensed_to_square_into`.
The first table compares `condensed_index` and closed-form positions, condensed values, and reference values computed separately with standard `f64` functions for representative pairs.
The second table shows, over all pairs, the largest differences among the three arrays, largest relative difference from reference values, and number of index mismatches.
For Mahalanobis distance ([Standardized Euclidean and Mahalanobis distances](oxref:spatial-standardized-mahalanobis)), use $V^{-1} = \begin{pmatrix} 4 & 1.2 \\ 1.2 & 1 \end{pmatrix}$ and compute reference values directly from $\sqrt{\delta^\mathsf{T} V^{-1} \delta}$ without Cholesky decomposition.
$\delta$ is the difference between the two points' coordinates.

```rust
//| ref: spatial-pairwise-condensed
//| title: "Check all-pairs condensed storage, indexing, and matrix expansion against reference values"
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg, scioxide-random, scioxide-spatial]
//| inputs:
//|   point_count: {"type":"range","label":"Point count n","min":2,"max":40,"step":1,"value":6}
//|   metric: {"type":"select","label":"Distance","options":[{"value":"euclidean","label":"Euclidean"},{"value":"cityblock","label":"CityBlock"},{"value":"chebyshev","label":"Chebyshev"},{"value":"minkowski3","label":"Minkowski(3)"},{"value":"mahalanobis","label":"Mahalanobis"}],"value":"euclidean"}
//|   seed: {"type":"range","label":"Random seed s","min":1,"max":50,"step":1,"value":7}
//| cases:
//|   - {"id":"mahalanobis","label":"Mahalanobis","description":"Evaluation with the Cholesky factor agrees with the inverse-covariance quadratic-form reference within rounding error.","inputs":{"metric":"mahalanobis"}}

//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"pairs","path":"/rows/1/2","equals":4}
//|       - {"artifact":"pairs","path":"/rows/2/2","equals":14}
//|       - {"artifact":"pairs","path":"/rows/2/6","range":{"max":1e-15}}
//|       - {"artifact":"summary","path":"/rows/0/0","equals":15}
//|       - {"artifact":"summary","path":"/rows/0/2","range":{"max":0}}
//|       - {"artifact":"summary","path":"/rows/0/3","range":{"max":1e-15}}
//|       - {"artifact":"summary","path":"/rows/0/4","equals":0}
//|   - case: mahalanobis
//|     expect:
//|       - {"artifact":"pairs","path":"/rows/0/4","approx":{"value":1.4349010886427962,"rtol":1e-14}}
//|       - {"artifact":"summary","path":"/rows/0/3","range":{"max":1e-15}}
//|   - case: many-points
//|     expect:
//|       - {"artifact":"pairs","path":"/rows/2/2","equals":779}
//|       - {"artifact":"summary","path":"/rows/0/0","equals":780}
//|       - {"artifact":"summary","path":"/rows/0/4","equals":0}
use scioxide_core::{ExecutionContext, NdView, StridedLayout};
use scioxide_linalg::Matrix;
use scioxide_random::{SeedableRng, SplitMix64, fill_uniforms};
use scioxide_spatial::{
    DistanceMetric, DistanceOptions, DistanceWorkspace, DistanceWorkspaceRequest, PointSet,
    PreparedDistance, condensed_index, condensed_len, condensed_to_square_into,
};

// n uniform points in the unit square (one per row).
let n = point_count as usize;
let mut coordinates = vec![0.0_f64; 2 * n];
let mut draws = 0;
let mut rng = SplitMix64::from_seed(seed as u64);
fill_uniforms(&mut rng, &mut coordinates, &mut draws).map_err(|e| e.to_string())?;
let (shape, strides) = ([n, 2], [2, 1]);
let layout = StridedLayout::new(&shape, &strides).map_err(|e| e.to_string())?;
let view = NdView::new(&coordinates, layout).map_err(|e| e.to_string())?;
let points = PointSet::new(view).map_err(|e| e.to_string())?;

// Inverse covariance V⁻¹ (used only for Mahalanobis distance).
let inverse = [[4.0, 1.2], [1.2, 1.0]];
let dist = match metric.as_str() {
    "cityblock" => PreparedDistance::new(DistanceMetric::CityBlock),
    "chebyshev" => PreparedDistance::new(DistanceMetric::Chebyshev),
    "minkowski3" => PreparedDistance::new(DistanceMetric::Minkowski(3.0)),
    "mahalanobis" => {
        let values = vec![inverse[0][0], inverse[0][1], inverse[1][0], inverse[1][1]];
        let matrix = Matrix::from_vec(2, 2, values).map_err(|e| e.to_string())?;
        PreparedDistance::mahalanobis(&matrix)
    }
    _ => PreparedDistance::new(DistanceMetric::Euclidean),
}
.map_err(|e| e.to_string())?;
// Reference values: evaluate the definition directly with standard f64 functions (without Cholesky decomposition).
let reference = |i: usize, j: usize| {
    let (dx, dy) = (
        coordinates[2 * i] - coordinates[2 * j],
        coordinates[2 * i + 1] - coordinates[2 * j + 1],
    );
    match metric.as_str() {
        "cityblock" => dx.abs() + dy.abs(),
        "chebyshev" => dx.abs().max(dy.abs()),
        "minkowski3" => (dx.abs().powi(3) + dy.abs().powi(3)).powf(1.0 / 3.0),
        "mahalanobis" => {
            (inverse[0][0] * dx * dx + 2.0 * inverse[0][1] * dx * dy + inverse[1][1] * dy * dy)
                .sqrt()
        }
        _ => dx.hypot(dy),
    }
};

// The pairwise matrix, condensed_into storage, and its expanded matrix.
let options = DistanceOptions::new();
let square = dist.pairwise(&points, &points).map_err(|e| e.to_string())?;
let square = square.as_slice();
let length = condensed_len(n).map_err(|e| e.to_string())?;
let mut condensed = vec![0.0_f64; length];
let request = DistanceWorkspaceRequest::condensed(n, options);
let mut ws = DistanceWorkspace::<f64>::workspace(request).map_err(|e| e.to_string())?;
let context = ExecutionContext::sequential();
dist.condensed_into(&points, options, &mut condensed, &mut ws, context)
    .map_err(|e| e.to_string())?;
let mut restored = vec![0.0_f64; n * n];
let request = DistanceWorkspaceRequest::square(n, options);
let mut ws = DistanceWorkspace::<f64>::workspace(request).map_err(|e| e.to_string())?;
condensed_to_square_into(n, &condensed, options, &mut restored, &mut ws, context)
    .map_err(|e| e.to_string())?;

// Check all pairs for agreement among the three arrays, closed-form positions, and relative differences from reference values.
let (mut layout_gap, mut reference_gap, mut misplaced) = (0.0_f64, 0.0_f64, 0_usize);
for i in 0..n {
    for j in i + 1..n {
        let k = condensed_index(n, i, j).map_err(|e| e.to_string())?;
        misplaced += usize::from(k != length - (n - i) * (n - i - 1) / 2 + (j - i - 1));
        let value = condensed[k];
        for other in [square[i * n + j], restored[i * n + j], restored[j * n + i]] {
            layout_gap = layout_gap.max((other - value).abs());
        }
        reference_gap = reference_gap.max((value - reference(i, j)).abs() / reference(i, j));
    }
}
let mut sample = vec![(0, 1), (0, n - 1), (n - 2, n - 1)];
sample.dedup();
let mut rows = Vec::new();
for (i, j) in sample {
    let k = condensed_index(n, i, j).map_err(|e| e.to_string())?;
    let closed = length - (n - i) * (n - i - 1) / 2 + (j - i - 1);
    let (value, exact) = (condensed[k], reference(i, j));
    rows.push((i, j, k, closed, value, exact, (value - exact).abs() / exact));
}
let fixed6 = serde_json::json!({ "fractionDigits": 6 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let pair_columns = serde_json::json!([
    { "key": "0", "label": "i", "type": "integer" },
    { "key": "1", "label": "j", "type": "integer" },
    { "key": "2", "label": "condensed_index", "type": "integer" },
    { "key": "3", "label": "Closed form k(i, j)", "type": "integer" },
    { "key": "4", "label": "Condensed value [-]", "type": "number", "format": fixed6 },
    { "key": "5", "label": "Reference [-]", "type": "number", "format": fixed6 },
    { "key": "6", "label": "Relative difference [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    pair_columns,
    rows,
    metadata = serde_json::json!({ "id": "pairs" })
);
let summary_columns = serde_json::json!([
    { "key": "0", "label": "Condensed length", "type": "integer" },
    { "key": "1", "label": "Closed form n(n − 1)/2", "type": "integer" },
    { "key": "2", "label": "Largest difference among three arrays [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "Maximum relative reference difference [-]", "type": "number", "format": sci3 },
    { "key": "4", "label": "Index mismatches [count]", "type": "integer" }
]);
let summary = vec![(
    length,
    n * (n - 1) / 2,
    layout_gap,
    reference_gap,
    misplaced,
)];
emit_table_with_columns!(
    summary_columns,
    summary,
    metadata = serde_json::json!({ "id": "summary" })
);
```

With defaults ($n = 6$, Euclidean distance, $s = 7$), condensed storage has length 15, pair $(0, 5)$ is at position 4, the final pair $(4, 5)$ is at position 14, and `condensed_index` agrees with the closed form for all pairs.
The three arrays agree bit for bit; the largest relative difference from references is $2.2 \times 10^{-16}$, about twice the unit roundoff $2^{-53} \approx 1.1 \times 10^{-16}$.
For Mahalanobis distance, the relative difference between Cholesky-factor values and quadratic-form references also remains around $3 \times 10^{-16}$.
At $n = 40$, condensed storage of length 780 uses less than half the memory of a 1600-element square matrix containing the same information.

## Workspaces and committing output

Pairwise distances and matrix conversions write results to workspace `DistanceWorkspace<S>` before copying to the output once all results are available.
Thus a failure during computation leaves the output unchanged (see [Error contracts and partial results](../../../concepts/errors-and-partial-results/) for output rules on failure).
If the output exceeds the required length, elements beyond that length remain unchanged.

Workspace size is determined by an `DistanceWorkspaceRequest` specifying computation kind and point counts.
`DistanceWorkspaceRequest::pairwise(n_l, n_r, options)` requests $n_\ell n_r$ values, `condensed(n, options)` requests $n(n - 1)/2$, and `square(n, options)` requests $n^2$.
Use a `condensed` request for `condensed_into` and `square_to_condensed_into`, and a `square` request for `condensed_to_square_into`.
`DistanceWorkspace::<S>::workspace_requirements(request)` returns `DistanceWorkspaceRequirements` from this request; `scalar_len()` gives the value count and `bytes::<S>()` the byte count.
`DistanceWorkspace::<S>::workspace(request)` returns a workspace allocated to that size; `new()` returns an empty workspace without allocating.
`check(&requirements)` reports sufficiency as `Capacity`; `try_reserve(&requirements)` grows storage while retaining existing capacity.
A failed `try_reserve` can leave some newly allocated capacity, so reserve again before use.
[Execution forms, workspaces, and reproducibility](../../../concepts/workspaces-and-reproducibility/) describes reservation steps and the meaning of `Capacity`.
Computation itself does not grow the workspace; insufficient capacity returns `DimensionMismatch`.

`DistanceOptions` holds an execution policy and byte limit; `DistanceOptions::new()` selects sequential execution without a limit.
`with_max_workspace_bytes(bytes)` limits bytes retained by the workspace, including capacity left from a previous larger reservation; exceeding it returns `ResourceLimit`.
Under `with_execution_policy(ExecutionPolicy::Auto)`, parallel execution occurs when at least 256 outputs are requested and estimated work per worker meets the executor's minimum work threshold.
Estimated work per pair in $d$ dimensions is $d$ ($d^2$ for Mahalanobis, $16d$ for Jensen–Shannon); matrix conversion costs one unit per element.
Cancellation and deadlines are checked at least every 256 pairs and immediately before writing output.
Cells running in wasm are sequential and remain so even with `Auto`.

The next cell uses the four-point square $(0, 0), (1, 0), (1, 1), (0, 1)$ to check workspace sizes and output on failure.
The first table compares value counts and byte counts (`f64`) for three request kinds with closed forms.
The second table tries failing operations in order and shows error classifications and whether output (prefilled with $-1$) remained unchanged.
Workspace-requirement and validation functions do not write output, so their final column shows “No output.”
The input adds an asymmetric perturbation $10^{a}$ to element $(0, 1)$ of the square's distance matrix and compares it with absolute tolerance $10^{-12}$ of `square_to_condensed_into`.

```rust
//|   - case: default
```

A request exceeding the byte limit is rejected with `ResourceLimit` before workspace allocation.

## Summary

Write all-pairs distances to a row-major $n_\ell \times n_r$ array with `pairwise_into`; for one point set, `condensed_into` writes condensed storage of length $n(n - 1)/2$, requiring less than half the memory of a square matrix.
The position of pair $(i, j)$ in condensed storage comes from `condensed_index` and agrees with the closed form $k(i, j)$.
Validate external arrays with `validate_condensed` and `validate_distance_matrix`; neither checks the triangle inequality, so callers must check it when later processing requires the metric axioms.
For repeated computations, determine workspace size from a request and reserve once; computation then performs no allocations and leaves output unchanged on failure.
