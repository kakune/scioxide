Cluster analysis, nearest-neighbor classification, and shape comparison begin by expressing separation between points numerically.
How separation is measured depends on the meaning of the data.
Choose Euclidean distance for coordinate differences, cosine for orientation alone, Jensen–Shannon distance for probability distributions, and contingency-table measures for 0/1 attributes.
This page explains distance and dissimilarity definitions and domains, distances accounting for component variation and correlation, and overflow and rounding in single-pair evaluation.
[Distance matrices and condensed storage](../distance-matrices/) covers arrays and workspaces for many point-pair distances; [Directed Hausdorff distance](../directed-hausdorff/) covers discrepancies between two point sets.

## Metric axioms and point sets

A function $d : X \times X \to [0, \infty)$ on a set $X$ satisfies the metric axioms if, for all $x, y, z \in X$, it obeys:

1. $d(x, y) = 0 \iff x = y$ (identity)
2. $d(x, y) = d(y, x)$ (symmetry)
3. $d(x, z) \le d(x, y) + d(y, z)$ (triangle inequality)

A function $d$ satisfying these conditions is called a distance (metric).
Measures of separation failing some conditions, such as the triangle inequality, are distinguished as dissimilarities.
With the triangle inequality, known distances give bounds on unknown ones, such as $\lvert d(x, z) - d(y, z)\rvert \le d(x, y)$.
This inference is unavailable for dissimilarities.

Pass point sets as `PointSet`; every constructor borrows coordinates without cloning them.
`PointSet::from_points(&points)` reads each element of `[[S; D]]` as one point; `PointSet::from_rows(&coordinates, d)` interprets each group of $d$ entries of a flat row-major array as one point.
`from_rows` rejects $d = 0$ with `InvalidInput` and array lengths not divisible by $d$ with `DimensionMismatch`.
`PointSet::new` borrows a rank-two view `NdView` from `scioxide_core`, interpreting each row as one point (shape $[n, d]$).
Strides are arbitrary; a zero stride can repeat the same row.
`new` rejects non-rank-two views with `InvalidInput`.
Every constructor checks all coordinates for finiteness once during construction (NaN or infinity gives `NonFinite`).

## Named distances and dissimilarities

`DistanceMetric` enumerates 17 functions, prepared for evaluation with `PreparedDistance::new(metric)`.
Let the two vectors be $u, v \in \mathbb{R}^d$.
Evaluating an undefined input returns `DomainError` rather than replacing the value with 0 or NaN.
Euclidean distance also has a preparation-free function `distance(&u, &v)` returning the same value as `distance` of `PreparedDistance::new(DistanceMetric::Euclidean)`.

| Variant | Definition | Undefined input | Properties |
|---|---|---|---|
| `Euclidean` | $\lVert u - v\rVert_2$ | None | Metric |
| `SquaredEuclidean` | $\lVert u - v\rVert_2^2$ | None | Dissimilarity (violates the triangle inequality) |
| `CityBlock` | $\sum_i \lvert u_i - v_i\rvert$ | None | Metric |
| `Chebyshev` | $\max_i \lvert u_i - v_i\rvert$ (0 for $d = 0$) | None | Metric |
| `Minkowski(p)` | $\bigl(\sum_i \lvert u_i - v_i\rvert^p\bigr)^{1/p}$, finite $p > 0$ | None | Metric for $p \ge 1$, dissimilarity for $p < 1$ |
| `Cosine` | $1 - u \cdot v / (\lVert u\rVert_2 \lVert v\rVert_2)$ | Either vector is zero | Dissimilarity, range $[0, 2]$ |
| `Correlation` | `Cosine` of mean-centered $u - \bar u$ and $v - \bar v$ | Either vector is constant | Dissimilarity, range $[0, 2]$ |
| `BrayCurtis` | $\sum_i \lvert u_i - v_i\rvert / \sum_i \lvert u_i + v_i\rvert$ | $\sum_i \lvert u_i + v_i\rvert = 0$ (equivalently $u = -v$) | Dissimilarity |
| `Canberra` | $\sum_i \lvert u_i - v_i\rvert / (\lvert u_i\rvert + \lvert v_i\rvert)$, with terms for $0/0$ set to 0 | None | Metric |
| `JensenShannon` | $\sqrt{\mathrm{JS}(p, q)}$ (defined below) | Negative coordinates or a zero-sum vector | Metric |
| `Hamming` | Fraction of differing coordinates $\#\{i : u_i \ne v_i\}/d$ | $d = 0$ | Metric |
| `Dice` | $(c_{10} + c_{01})/(2c_{11} + c_{10} + c_{01})$ | Both vectors all zero | Dissimilarity |
| `Jaccard` | $(c_{10} + c_{01})/(c_{11} + c_{10} + c_{01})$ (0 if both vectors are all zero) | None | Metric |
| `RogersTanimoto` | $2(c_{10} + c_{01})/(c_{11} + c_{00} + 2(c_{10} + c_{01}))$ | $d = 0$ | Metric |
| `RussellRao` | $(d - c_{11})/d$ | $d = 0$ | Dissimilarity (not necessarily 0 even for $u = v$) |
| `SokalSneath` | $2(c_{10} + c_{01})/(c_{11} + 2(c_{10} + c_{01}))$ | Both vectors all zero | Metric (excluding all-zero vectors) |
| `Yule` | $2c_{10}c_{01}/(c_{11}c_{00} + c_{10}c_{01})$ (0 if $c_{10}c_{01} = 0$) | None | Dissimilarity |

The 0/1 measures from `Dice` through `Yule` (excluding `Hamming`) require every coordinate to be 0 or 1; other values give `DomainError`.
$c_{ab}$ counts coordinates satisfying both $u_i = a$ and $v_i = b$; for example, $c_{10}$ counts coordinates where only $u$ is 1.
`Hamming` accepts arbitrary real coordinates, beyond 0/1, and compares only equality of values.
On 0/1 vectors, `Jaccard`, `RogersTanimoto`, and `SokalSneath` satisfy the triangle inequality and are metrics; `Dice` and `Yule` do not (Gower–Legendre).

`JensenShannon` measures separation between probability distributions.
Using vectors $p$ and $q$ normalized separately to sum to 1, and their mean $m = (p + q)/2$:

$$
\mathrm{JS}(p, q) = \tfrac{1}{2}\,\mathrm{KL}(p \,\Vert\, m) + \tfrac{1}{2}\,\mathrm{KL}(q \,\Vert\, m), \qquad
\mathrm{KL}(p \,\Vert\, m) = \sum_i p_i \ln\frac{p_i}{m_i}
$$

Logarithms are natural; $\mathrm{JS}$ lies in $[0, \ln 2]$ and its square root in $[0, \sqrt{\ln 2}]$.
Input sums need not be 1, but coordinates must be nonnegative and both vector sums positive.
$\mathrm{JS}$ itself violates the triangle inequality, but its square root is a metric (Endres–Schindelin).

`JensenShannon` rewrites each coordinate's contribution using $s_i = p_i + q_i$ and $t_i = \lvert p_i - q_i\rvert / s_i$ as

$$
\mathrm{JS}(p, q) = \sum_i \frac{s_i}{4}\, h(t_i), \qquad h(t) = (1 + t)\ln(1 + t) + (1 - t)\ln(1 - t)
$$

and computes this expression.
For small $t_i$, it uses the positive series $h(t) = \sum_{k \ge 1} t^{2k} / \bigl(k(2k - 1)\bigr)$, avoiding cancellation even for nearly equal distributions.
For a vector whose sum exceeds the range of `f64`, divide by its largest component before summing.
Normalized values remain in an extended-exponent representation through the square root, so normalization underflow cannot turn a small distance into 0.

For `Minkowski(p)`, a $p$ that is not finite and positive gives `InvalidInput` during preparation.
At $p < 1$ the triangle inequality fails; for example, at $p = 1/2$, $d\bigl((0, 0), (1, 1)\bigr) = 4$ exceeds $d\bigl((0, 0), (1, 0)\bigr) + d\bigl((1, 0), (1, 1)\bigr) = 2$.
At $p = 1$ it sums absolute differences directly; at $p = 2$ it computes as for Euclidean distance.
For other $p$, it divides differences by the largest component before summing their $p$th powers.
For components whose ratio to the largest component falls below the normal range at $p < 1$, it computes the $p$th power from logarithm differences without forming the ratio, preserving contributions that ratio underflow would lose.
At $p < 1$, if raising the sum to $1/p$ overflows, it obtains the root through logarithms, avoiding rejection of representable results, though error on this path grows with the result's exponent.

The input is exponent $p$ of `Minkowski(p)` in the final row, checking whether $d\bigl((0, 0), (1, 1)\bigr) = 2^{1/p}$ exceeds 2, the sum of two edges through $(1, 0)$.

`Canberra` treats terms for $0/0$ as 0, returning 0 even for two zero vectors.
`BrayCurtis` has zero denominator at $u = -v$; `Cosine` is undefined for zero vectors and `Correlation` for constant vectors, all returning `DomainError`.
`JensenShannon` returns the upper bound $\sqrt{\ln 2} \approx 0.832555$ for the pair $(1, 0)$ and $(0, 1)$ and for the unnormalized pair $(2, 0)$ and $(0, 3)$.
Even for $(10^{308}, 10^{308})$ and $(10^{308}, 0)$ where a sum exceeds the maximum `f64`, it returns $\sqrt{(3/4)\ln(4/3)} \approx 0.464502$ for normalized $p = (1/2, 1/2)$ and $q = (1, 0)$, while rejecting negative coordinates.
`Hamming` returns a differing-coordinate fraction of 0.5 even for non-0/1 coordinates; `Dice` rejects a coordinate of 0.5.
With the default $p = 1/2$, `Minkowski` equals 4, exceeding the two-edge sum 2 and violating the triangle inequality.
For $p \ge 1$, value $2^{1/p}$ is at most 2; at $p = 2$ it equals Euclidean distance $\sqrt 2$.

## Standardized Euclidean and Mahalanobis distances

When components have different units or variation, simply summing differences lets high-variance components dominate the distance.
`PreparedDistance::standardized(variances)` prepares standardized Euclidean distance, dividing each squared coordinate difference by its component's variance $\sigma_i^2 > 0$:

$$
d_\sigma(u, v) = \Bigl(\sum_i \frac{(u_i - v_i)^2}{\sigma_i^2}\Bigr)^{1/2}
$$

Variances are supplied by the caller, not estimated from data.
A variance that is not finite and positive gives `InvalidInput`.

With correlated components, use Mahalanobis distance with the inverse of covariance matrix $V$:

$$
d_M(u, v) = \sqrt{(u - v)^\mathsf{T} V^{-1} (u - v)} = \bigl\lVert L^\mathsf{T}(u - v)\bigr\rVert_2, \qquad V^{-1} = L L^\mathsf{T}
$$

$L$ is lower triangular with a positive diagonal.
`PreparedDistance::mahalanobis(inverse_covariance)` accepts $V^{-1}$ and computes $L$ once during preparation using unpivoted Cholesky decomposition.
$V^{-1}$ must be exactly symmetric; a nonsymmetric matrix gives `InvalidInput` (reason `Inconsistent`) during factorization.
A nonsquare matrix also returns `InvalidInput`; a matrix that is not positive definite returns `DomainError`.
Evaluation uses the triangular matrix-vector product $L^\mathsf{T}(u - v)$ and its norm, without substitution, costing about $d^2/2$ multiply-add operations per pair.
If $V$ is diagonal, Mahalanobis distance equals standardized Euclidean distance.
The cell in [Distance matrices and condensed storage](oxref:spatial-condensed-distance) compares Cholesky-factor values with quadratic-form references in all-pairs computation.

## Single-pair evaluation and floating-point handling

`PreparedDistance` is immutable; preparation may allocate, but evaluation does not.
Compute one pair's distance with `distance(&u, &v)` (slices) or `between(&left, i, &right, j)` (point-set rows).
Mismatched lengths or dimensions give `DimensionMismatch`, an out-of-range row index gives `OutOfBounds`, and NaN or infinity in slices gives `NonFinite`.
Intermediate calculations use `f64` for both `f32` and `f64` inputs.
Euclidean-type norms first sum squares without rescaling, recomputing after scaling by the largest component only if the sum overflows or falls below the normal range.
`Cosine` and `Correlation` also divide each vector by its largest component before dot products, preventing dot-product overflow for finite inputs.
If a difference, transformed component, or result is unrepresentable in `f64`, or the result exceeds the output scalar range (such as `f32`), it returns `NumericalInstability` (`Overflow`) instead of infinity.

## Summary

Choose a `DistanceMetric` appropriate for the data's meaning, and consult the table for its domain and whether it is a metric satisfying the triangle inequality or a dissimilarity.
`Cosine`, `Correlation`, `BrayCurtis`, `JensenShannon`, and the 0/1 measures return `DomainError` for undefined input; decide how to handle zero vectors and negative values in caller code.
`JensenShannon` normalizes each vector independently, so nonnegative vectors with unequal sums can be passed directly.
For data with differing component scales or correlations, use standardized Euclidean distance with supplied variances or Mahalanobis distance with supplied inverse covariance.
The latter uses Cholesky decomposition at preparation, reducing evaluation to a triangular matrix-vector product.
