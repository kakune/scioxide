Finite-difference, finite-volume, and finite-element methods divide a domain into grids or meshes and place unknowns at vertices, cells, faces, or edges.
Even for the same array, vertex values and cell values differ in both length and meaning; confusing them gives incorrect results or a length-mismatch failure.
Combining old-mesh values with a refined mesh causes the same kind of error.
This page explains point and index numbering, structured-grid coordinate and periodic axes, cell-mesh topology, fields with type-level locations, and mesh generations.
[Simplex meshes](../simplex-meshes/) covers interval, triangle, and tetrahedron meshes.
Every rule serves to determine array lengths and numbering, adjacency, and the mesh to which values belong unambiguously before computation.

## Points, ranges, and multi-indices

`Point<S, D>` is a point in $D = 1, 2, 3$ dimensions, storing coordinates in fixed-size array `[S; D]`.
Scalar type `S` is [`RealScalar`](../../../scioxide-core/api/scalars-and-values/) (`f32` or `f64`); aliases `Point1`, `Point2`, and `Point3` are provided.
`Point::new` checks that all coordinates are finite and returns `NonFinite` for NaN or infinity.
$D$ outside 1–3 gives `InvalidInput`.

`Extent<D>` holds index-space axis lengths $[n_0, \ldots, n_{D-1}]$; `Index<D>` holds a multi-index $[i_0, \ldots, i_{D-1}]$ within that space, with aliases `Extent1`–`Extent3` and `Index1`–`Index3`.
Zero-length axes are allowed and make the range empty.
Linear multi-index positions use axis 0 as the fastest-varying axis; in three dimensions:

$$
\ell(i_0, i_1, i_2) = i_0 + n_0\,\bigl(i_1 + n_1\, i_2\bigr)
$$

This is column-major (Fortran) order, with the first index varying fastest, opposite to row-major (C) order with the last index varying fastest.
`linearize` returns `OutOfBounds` for out-of-range components and `SizeOverflow` if the position does not fit in `usize`.
Only $\ell$ is checked for overflow; total element count $\prod_a n_a$ need not fit in `usize`.
The inverse map `delinearize` and element count `element_count` return `SizeOverflow` if the total element count does not fit.
Grid vertices, cells, faces, edges, and field values on them all follow this order.

## Coordinate axes and structured grids

`CoordinateAxis<S>` is a sequence of grid points on one axis, with all coordinates finite and strictly increasing or strictly decreasing.
`orientation()` returns the direction as `AxisOrientation::Increasing` or `Decreasing`.

`CoordinateAxis::uniform(start, end, count)` is a uniformly spaced axis, storing only endpoints and point count.
Point $i$ is the correctly rounded value of $x_i = \mathrm{start} + (\mathrm{end} - \mathrm{start})\, i/(\mathrm{count} - 1)$; endpoints equal the supplied values exactly.
To remain strictly monotone after rounding, endpoints must differ, the point count must be at least 2, and spacing must satisfy $|\mathrm{end} - \mathrm{start}| \ge (\mathrm{count} - 1)\,u$.
Here $u$ is the distance from the endpoint of larger magnitude to the adjacent floating-point number toward 0.
This condition is checked in $O(1)$ independently of point count; failure gives `InvalidInput`, while NaN or infinite endpoints give `NonFinite`.
`CoordinateAxis::explicit(coordinates)` is a nonuniform axis storing all coordinates.
Fewer than two points, equal points, or a direction reversal are rejected with `InvalidInput`; NaN or infinite coordinates with `NonFinite`.
Both axes return point $i$ through $O(1)$.

`locate(x)` uses binary search to find the interval containing $x$ in $O(\log n)$ and returns interval index $i$ and relative position

$$
\theta = \frac{x - x_i}{x_{i+1} - x_i}
$$

as `IntervalLocation`.
Intervals are half-open in grid-point order; a grid point belongs to the interval starting there, so $\theta$ usually lies in $[0, 1)$.
The final grid point instead belongs to the last interval, with $\theta$ exactly 1.
A $x$ outside the closed interval gives `DomainError`; NaN or infinite $x$ gives `NonFinite`.

`StructuredGrid<S, D>` (aliases `Grid1d`, `Grid2d`, `Grid3d`) is a Cartesian product of $D$ axes; vertices are tuples of axis grid points and cells are tuples of axis intervals.
Vertex extents use axis point counts, and cell extents use interval counts, each one smaller; both use column-major numbering as above.
Each axis receives one `AxisTopology`; with `Bounded`, its first and last grid points form separate boundaries.
With `Periodic`, first and last grid points are identified across a seam of period $|\mathrm{end} - \mathrm{start}|$, but remain distinct paired vertices.
Thus vertex, cell, face, and edge counts do not depend on axis periodicity.
`StructuredGrid::uniform(start, end, counts)` constructs a `Bounded` grid with every axis `CoordinateAxis::uniform(start[i], end[i], counts[i])`; `CellMesh::uniform` constructs that grid's cell mesh.
Specify boundary sides with `AxisSide::Start` (first grid point) or `End` (last grid point), independently of coordinate magnitude.

Grid `locate(point)` applies `CoordinateAxis::locate` on every axis and returns the cell multi-index and axis-relative positions as `CellLocation`.
Periodic-axis coordinates are not wrapped automatically.
`wrap_point` shifts periodic coordinates into the axis range by the period; `locate_wrapped` wraps before locating.
Coordinates outside a bounded axis give `DomainError` with either method.

`refined(factors)` returns a grid dividing each interval of axis $a$ into `factors[a]` equal parts.
Uniform axes remain uniform with more points; nonuniform axes retain original grid points and insert points between them.
A zero factor or inserted points that are not strictly monotone after rounding give `InvalidInput`.
`with_axis` returns a grid with one axis replaced.
Both advance the mesh generation described below by one; `refined` with all factors 1 leaves the grid and generation unchanged.

## Cell-mesh topology and boundaries

`CellMesh<S, D>` is a mesh of segments, quadrilaterals, or hexahedra on a structured grid, with aliases `SegmentMesh`, `QuadMesh`, and `HexMesh`.
`cell_kind()` returns the cell shape as `CellKind::Segment`, `Quadrilateral`, or `Hexahedron`.
The mesh stores no connectivity table, computing vertex, cell, and face incidence from index arithmetic as needed.
`cell_vertices`, `vertex_cells`, `cell_faces`, `face_cells`, `cell_neighbors`, and `axis_boundary_faces` return `impl Iterator`; iteration does not allocate.
Mesh storage consists only of the grid: independent of point count for uniform axes and proportional to coordinate count for nonuniform axes.

A face is represented by `FaceIndex<D>`, combining normal axis $a$ and position.
Let $n_b$ be the number of cells along axis $b$.
Position components are the vertex-plane index ($0, \ldots, n_a$) on the normal axis and cell indices on other axes.
`TopologySizes` returns the following element counts.

$$
N_{\mathrm{vertex}} = \prod_{b}(n_b + 1), \quad
N_{\mathrm{cell}} = \prod_{b} n_b, \quad
N_{\mathrm{face}}^{(a)} = (n_a + 1)\prod_{b \ne a} n_b, \quad
N_{\mathrm{edge}}^{(a)} = n_a \prod_{b \ne a}(n_b + 1)
$$

$N_{\mathrm{face}}^{(a)}$ counts faces perpendicular to axis $a$ (`faces_normal_to(a)`); $N_{\mathrm{edge}}^{(a)}$ counts edges parallel to axis $a$ (`edges_along(a)`).
It also returns total face and edge counts (`faces()`, `edges()`), cell-to-vertex incidence count $2^D N_{\mathrm{cell}}$ (`cell_vertex_incidences()`), and cell-to-face incidence count $2D\,N_{\mathrm{cell}}$ (`cell_face_incidences()`).
In two dimensions, faces perpendicular to x and edges parallel to y are the same set of segments.

`face_topology(face)` returns face topology as `FaceTopology`.
`Interior` is an internal face separating two cells; `Exterior { side }` is an end face of a bounded axis.
`Periodic { side, paired }` is an end face of a periodic axis; `paired` identifies its paired face across the seam.
For seam faces, `face_cells` returns cells on both sides; for seam vertices, `vertex_cells` also returns cells on both sides.
On a periodic axis, `cell_neighbors` treats the first and last cells as neighbors; if the axis has only one cell, that cell is not its own neighbor.

`BoundarySet<D>` is a set of faces for boundary conditions, containing only exterior and seam faces in increasing order without duplicates.
`BoundarySet::axis_side(&mesh, a, side)` collects all faces at one end of axis $a$.
Passing an internal or duplicate face to `BoundarySet::new` gives `InvalidInput`; an out-of-range face gives `OutOfBounds`.
The set holds its construction mesh's token (described below); `is_compatible_with` checks in $O(1)$ whether a supplied mesh is the same revision used at construction.

## Fields with type-checked locations

`Field<T, L, D>` is an immutable array placing one value on each mesh entity at location `L`; value type `T` is independent of coordinate type.
Location is part of the type, so passing vertex or face values to a function accepting `Field<T, Cell, D>` fails to compile.
Location types and aliases are as follows.

| Location `L` | Entity | Alias | Supported meshes |
|---|---|---|---|
| `Vertex` | Vertex | `VertexField<T, D>` | `CellMesh`, `SimplexMesh`, `AdaptiveMesh` |
| `Cell` | Cell | `CellField<T, D>` | `CellMesh`, `SimplexMesh`, `AdaptiveMesh` |
| `Face<A>` | Face perpendicular to axis $A$ | `FaceField<T, D, A>` | `CellMesh` |
| `Edge<A>` | Edge parallel to axis $A$ | `EdgeField<T, D, A>` | `CellMesh` |
| `UnstructuredFace` | All faces | `UnstructuredFaceField<T, D>` | `SimplexMesh`, `AdaptiveMesh` |
| `UnstructuredEdge` | All edges | `UnstructuredEdgeField<T, D>` | `SimplexMesh`, `AdaptiveMesh` |

`FieldLocation` is a trait representing locations on `CellMesh`; `MeshEntities` represents mesh/location combinations.
Neither permits external implementations, so users cannot add locations or combinations.
Meaningless combinations such as axis-perpendicular faces on a simplex mesh lack trait implementations, so such fields fail to compile.
Only the $A \ge D$ case for `Face<A>` and `Edge<A>` is checked at runtime, returning `OutOfBounds`.

Construct a field with `Field::new(&mesh, values)` or `Field::from_fn(&mesh, f)`; a value count differing from the entity count gives `DimensionMismatch`.
`from_fn` calls `f(i)` for each linear entity position $i$.
Obtain the value count in advance with `Field::required_len(&mesh)`.
`try_map` returns a new field on the same mesh and location; `try_zip_map` combines corresponding values of two fields.
`try_zip_map` returns `InvalidInput` unless both fields belong to the same revision of the same mesh (revisions are defined below).

`FieldView<'a, T, L, D>` is a field borrowing the caller's slice.
`FieldView::new` checks the value count and borrows the mesh token; `to_owned` clones values and token to construct `Field`.
`clone` on `Field` shares values and therefore costs $O(1)$.

## Checking periodic-grid fields and seams

The next cell constructs a two-dimensional grid of $[0, 1] \times [0, 1]$ m with $n_x$ cells along x and $n_y$ along y.
The y axis is bounded; the input selects periodic or bounded x.
The first table compares field lengths at each location with `TopologySizes` and closed-form counts, checking that periodicity does not change counts.
The second table shows `FaceTopology`, seam partners, and incident cells for faces at both x ends and a y end.
The third table shows neighbors of corner cell $[0, 0]$, cells containing the corner vertex, the result of locating point $(1.1, 0.5)$ m with `locate_wrapped`, and the initial-x boundary-set size; the first three depend on periodicity.

```rust
//| id: spatial-grid-field-topology
//| ref: spatial-grid-field-topology
//| title: "Field lengths, seams, and mesh checks on a two-dimensional grid with a periodic axis"
//| run: reactive
//| crates: [scioxide-core, scioxide-spatial]
//| inputs:
//|   cells_x: {"type":"range","label":"x-direction cell count nₓ","min":1,"max":8,"step":1,"value":4}
//|   cells_y: {"type":"range","label":"y-direction cell count n_y","min":1,"max":8,"step":1,"value":3}
//|   periodic_x: {"type":"checkbox","label":"Make the x axis periodic","value":true}
//| cases:
//|   - {"id":"bounded","label":"Bounded x axis too","description":"Element counts stay the same; x-end faces become Exterior and the corner cell has one fewer neighbor.","inputs":{"periodic_x":false}}
//|   - {"id":"single-cell","label":"nₓ = 1 (periodic)","description":"With only one cell on a periodic axis, that cell is not its own neighbor.","inputs":{"cells_x":1}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"counts","path":"/rows/0/1","equals":20}
//|       - {"artifact":"counts","path":"/rows/2/1","equals":15}
//|       - {"artifact":"counts","path":"/rows/2/3","equals":15}
//|       - {"artifact":"faces","path":"/rows/0/1","equals":"Periodic { side: Start }"}
//|       - {"artifact":"faces","path":"/rows/0/2","equals":"[4, 0]"}
//|       - {"artifact":"incidence","path":"/rows/0/1","equals":3}
//|       - {"artifact":"incidence","path":"/rows/2/2","equals":"[0, 1]"}
//|   - case: bounded
//|     expect:
//|       - {"artifact":"counts","path":"/rows/0/1","equals":20}
//|       - {"artifact":"faces","path":"/rows/0/1","equals":"Exterior { side: Start }"}
//|       - {"artifact":"faces","path":"/rows/0/2","equals":null}
//|       - {"artifact":"incidence","path":"/rows/0/1","equals":2}
//|       - {"artifact":"incidence","path":"/rows/2/2","equals":"DomainError"}
//|   - case: single-cell
//|     expect:
//|       - {"artifact":"incidence","path":"/rows/0/1","equals":1}
//|       - {"artifact":"faces","path":"/rows/0/3","equals":"[0, 0]"}
use scioxide_spatial::{
    AxisSide, AxisTopology, BoundarySet, CellField, CellMesh, CoordinateAxis, EdgeField,
    FaceField, FaceIndex, FaceTopology, Grid2d, Index, Point, VertexField,
};

let (nx, ny) = (cells_x as usize, cells_y as usize);
let axis_x = CoordinateAxis::uniform(0.0_f64, 1.0, nx + 1).map_err(|e| e.to_string())?;
let axis_y = CoordinateAxis::uniform(0.0_f64, 1.0, ny + 1).map_err(|e| e.to_string())?;
let topology_x = if periodic_x {
    AxisTopology::Periodic
} else {
    AxisTopology::Bounded
};
let topologies = [topology_x, AxisTopology::Bounded];
let grid = Grid2d::new([axis_x, axis_y], topologies).map_err(|e| e.to_string())?;
let mesh = CellMesh::new(grid).map_err(|e| e.to_string())?;
let sizes = mesh.topology_sizes();

// Field lengths at each location, TopologySizes values, and closed-form element counts.
let vertex = VertexField::<f64, 2>::from_fn(&mesh, |_| 0.0).map_err(|e| e.to_string())?;
let cell = CellField::<f64, 2>::from_fn(&mesh, |_| 0.0).map_err(|e| e.to_string())?;
let face_x = FaceField::<f64, 2, 0>::from_fn(&mesh, |_| 0.0).map_err(|e| e.to_string())?;
let face_y = FaceField::<f64, 2, 1>::from_fn(&mesh, |_| 0.0).map_err(|e| e.to_string())?;
let edge_x = EdgeField::<f64, 2, 0>::from_fn(&mesh, |_| 0.0).map_err(|e| e.to_string())?;
let faces_x = sizes.faces_normal_to(0).map_err(|e| e.to_string())?;
let faces_y = sizes.faces_normal_to(1).map_err(|e| e.to_string())?;
let edges_x = sizes.edges_along(0).map_err(|e| e.to_string())?;
let vertices = (nx + 1) * (ny + 1);
let counts = vec![
    ("Vertex", vertex.len(), sizes.vertices(), vertices),
    ("Cell", cell.len(), sizes.cells(), nx * ny),
    ("Face<0> (perpendicular to x)", face_x.len(), faces_x, (nx + 1) * ny),
    ("Face<1> (perpendicular to y)", face_y.len(), faces_y, nx * (ny + 1)),
    ("Edge<0> (parallel to x)", edge_x.len(), edges_x, nx * (ny + 1)),
];
let count_columns = serde_json::json!([
    { "key": "0", "label": "Position" },
    { "key": "1", "label": "Field length", "type": "integer" },
    { "key": "2", "label": "TopologySizes", "type": "integer" },
    { "key": "3", "label": "Closed form", "type": "integer" }
]);
emit_table_with_columns!(
    count_columns,
    counts,
    metadata = serde_json::json!({ "id": "counts" })
);

// Face topology, seam partners, and incident cells.
let show = |index: Index<2>| format!("{:?}", index.as_array());
let probes = [(0, [0, 0]), (0, [nx, 0]), (1, [0, 0]), (1, [0, ny])];
let mut face_rows = Vec::new();
for (normal, position) in probes {
    let face = FaceIndex::new(normal, Index::new(position).map_err(|e| e.to_string())?)
        .map_err(|e| e.to_string())?;
    let (kind, paired) = match mesh.face_topology(face).map_err(|e| e.to_string())? {
        FaceTopology::Interior => ("Interior".to_string(), None),
        FaceTopology::Exterior { side } => (format!("Exterior {{ side: {side:?} }}"), None),
        FaceTopology::Periodic { side, paired } => (
            format!("Periodic {{ side: {side:?} }}"),
            Some(show(paired.index())),
        ),
    };
    let cells = mesh.face_cells(face).map_err(|e| e.to_string())?;
    let cells: Vec<String> = cells.map(show).collect();
    let label = format!("Normal {}, position {}", ["x", "y"][normal], show(face.index()));
    face_rows.push((label, kind, paired, cells.join(", ")));
}
let face_columns = serde_json::json!([
    { "key": "0", "label": "Face" },
    { "key": "1", "label": "FaceTopology" },
    { "key": "2", "label": "Seam partner", "nullText": "None" },
    { "key": "3", "label": "Incident cells" }
]);
emit_table_with_columns!(
    face_columns,
    face_rows,
    metadata = serde_json::json!({ "id": "faces" })
);

// Corner-cell and corner-vertex incidence, location after periodic wrapping, and boundary-set size.
let listed = |items: Vec<String>| (Some(items.len()), items.join(", "));
let corner = Index::new([0, 0]).map_err(|e| e.to_string())?;
let neighbors = mesh.cell_neighbors(corner).map_err(|e| e.to_string())?;
let neighbors = listed(neighbors.map(show).collect());
let around = mesh.vertex_cells(corner).map_err(|e| e.to_string())?;
let around = listed(around.map(show).collect());
let probe = Point::new([1.1, 0.5]).map_err(|e| e.to_string())?;
let located = match mesh.grid().locate_wrapped(probe) {
    Ok(location) => (None, show(location.cell())),
    Err(error) => (None, format!("{:?}", error.kind())),
};
let boundary = BoundarySet::axis_side(&mesh, 0, AxisSide::Start).map_err(|e| e.to_string())?;
let boundary = listed(boundary.faces().iter().map(|f| show(f.index())).collect());
let incidence: Vec<(&str, Option<usize>, String)> = [
    ("Neighbors of cell [0, 0]", neighbors),
    ("Cells containing vertex [0, 0]", around),
    ("locate_wrapped of point (1.1, 0.5) m", located),
    ("BoundarySet at initial x", boundary),
]
.into_iter()
.map(|(label, (count, text))| (label, count, text))
.collect();
let incidence_columns = serde_json::json!([
    { "key": "0", "label": "Query" },
    { "key": "1", "label": "Count", "type": "integer", "nullText": "—" },
    { "key": "2", "label": "Result" }
]);
emit_table_with_columns!(
    incidence_columns,
    incidence,
    metadata = serde_json::json!({ "id": "incidence" })
);
```

With defaults ($n_x = 4$, $n_y = 3$, periodic x), the vertex field has $5 \times 4 = 20$ values and the x-perpendicular face field $5 \times 3 = 15$; field lengths, `TopologySizes`, and closed forms agree at every location.
The initial-x face $[0, 0]$ is `Periodic { side: Start }`, paired with terminal face $[4, 0]$; its incident cells are $[3, 0]$ and $[0, 0]$ across the seam.
Corner cell $[0, 0]$ has three neighbors, including $[3, 0]$ across the seam; two cells contain the corner vertex, and point $(1.1, 0.5)$ m wraps in x into cell $[0, 1]$.
Making x bounded leaves the count table unchanged, but x-end faces become `Exterior`, corner-cell neighbors decrease to two, corner-vertex incident cells to one, and $(1.1, 0.5)$ m gives `DomainError`.
On a periodic axis with $n_x = 1$, both sides of the seam are the same cell $[0, 0]$, so there is one incident cell, which is not its own neighbor.
In every case, the initial-x `BoundarySet` has $n_y = 3$ faces.

## Mesh identity and generation tokens

Each newly constructed mesh, and each new mesh produced by changing geometry or topology, is called a revision.
Each revision has a `MeshToken`; fields, boundary sets, boundary tags, and topological maps retain the token of their construction mesh.
A token consists of family `MeshId`, generation `MeshGeneration`, and a revision-specific identifier.
A family comprises a mesh and all revisions derived from it; two `MeshId` values are equal only when one is a clone of the other.
A newly constructed mesh has generation `MeshGeneration::INITIAL` (0), incremented whenever `refined`, `with_axis`, `with_points`, `with_cells`, `AdaptiveMesh::adapt`, or similar operations change geometry or topology.
Calls making no change (such as `refined` with all factors 1) return the same token.

Changing the same parent twice gives generation $g + 1$ for both results but different revision-specific identifiers.
Such sibling revisions are treated as distinct even when their generations agree.
`MeshToken::is_compatible_with` returns true only if family, generation, and revision identifier all agree: the tokens refer to the same revision.
`ensure_compatible` performs the same test, returning `InvalidInput` (reason `Inconsistent`) on mismatch.
`same_family` compares only families.
Comparison checks reference identity only, costing $O(1)$ without reading coordinates or connectivity.
Identifiers have meaning only within the running process and cannot be saved and compared in another process.
A `CellMesh::new(grid)` token is exactly the grid's token, so fields on meshes constructed from the same grid (or its clones) can be combined.

The next cell combines a field on a $4 \times 4$-cell grid (periodic x, bounded y) with four other fields using `try_zip_map`.
The counterparts use a mesh reconstructed from the same grid, a separately constructed grid with identical coordinates, a grid refined along x by factor $r$, and another grid refined from the same parent.
The table shows both generations, family equality (`same_family`), revision equality (`is_compatible_with`), and the combination result (accepted or error classification).
Only rows sharing a revision should be accepted.

```rust
//| id: spatial-mesh-token-check
//| ref: spatial-mesh-token-check
//| title: "Check mesh families, generations, and revisions when combining fields"
//| run: reactive
//| crates: [scioxide-core, scioxide-spatial]
//| inputs:
//|   refine_x: {"type":"range","label":"x-direction refinement factor r","min":1,"max":4,"step":1,"value":2}
//| cases:
//|   - {"id":"unchanged","label":"r = 1","description":"Refinement making no change returns the same token, allowing the combination.","inputs":{"refine_x":1}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"tokens","path":"/rows/0/4","equals":true}
//|       - {"artifact":"tokens","path":"/rows/0/5","equals":"Accepted"}
//|       - {"artifact":"tokens","path":"/rows/1/3","equals":false}
//|       - {"artifact":"tokens","path":"/rows/1/5","equals":"InvalidInput"}
//|       - {"artifact":"tokens","path":"/rows/2/2","equals":1}
//|       - {"artifact":"tokens","path":"/rows/2/5","equals":"InvalidInput"}
//|       - {"artifact":"tokens","path":"/rows/3/1","equals":1}
//|       - {"artifact":"tokens","path":"/rows/3/2","equals":1}
//|       - {"artifact":"tokens","path":"/rows/3/3","equals":true}
//|       - {"artifact":"tokens","path":"/rows/3/4","equals":false}
//|       - {"artifact":"tokens","path":"/rows/3/5","equals":"InvalidInput"}
//|   - case: unchanged
//|     expect:
//|       - {"artifact":"tokens","path":"/rows/2/2","equals":0}
//|       - {"artifact":"tokens","path":"/rows/2/4","equals":true}
//|       - {"artifact":"tokens","path":"/rows/2/5","equals":"Accepted"}
//|       - {"artifact":"tokens","path":"/rows/3/5","equals":"Accepted"}
use scioxide_spatial::{AxisTopology, CellField, CellMesh, CoordinateAxis, Grid2d};

let axis = CoordinateAxis::uniform(0.0_f64, 1.0, 5).map_err(|e| e.to_string())?;
let topologies = [AxisTopology::Periodic, AxisTopology::Bounded];
let grid = Grid2d::new([axis.clone(), axis.clone()], topologies).map_err(|e| e.to_string())?;
let mesh = CellMesh::new(grid.clone()).map_err(|e| e.to_string())?;
let rebuilt = CellMesh::new(grid.clone()).map_err(|e| e.to_string())?;
let separate_grid = Grid2d::new([axis.clone(), axis], topologies).map_err(|e| e.to_string())?;
let separate = CellMesh::new(separate_grid).map_err(|e| e.to_string())?;
let factors = [refine_x as usize, 1];
let refined = CellMesh::new(grid.refined(factors).map_err(|e| e.to_string())?)
    .map_err(|e| e.to_string())?;
let sibling = CellMesh::new(grid.refined(factors).map_err(|e| e.to_string())?)
    .map_err(|e| e.to_string())?;

// Construct cell fields on two meshes and combine them with try_zip_map.
let combine = |left: &CellMesh<f64, 2>, right: &CellMesh<f64, 2>| -> Result<String, String> {
    let a = CellField::<f64, 2>::from_fn(left, |i| i as f64).map_err(|e| e.to_string())?;
    let b = CellField::<f64, 2>::from_fn(right, |i| i as f64).map_err(|e| e.to_string())?;
    Ok(match a.try_zip_map(&b, |x, y| x + y) {
        Ok(_) => "Accepted".to_string(),
        Err(error) => format!("{:?}", error.kind()),
    })
};
let pairs = [
    (
        "Original grid and a mesh reconstructed from the same grid",
        &mesh,
        &rebuilt,
    ),
    ("Original grid and a separately constructed grid with identical coordinates", &mesh, &separate),
    ("Original grid and a refined grid", &mesh, &refined),
    (
        "Refined grid and another refinement from the same parent",
        &refined,
        &sibling,
    ),
];
let mut rows = Vec::new();
for (label, left, right) in pairs {
    let (l, r) = (left.mesh_token(), right.mesh_token());
    let result = combine(left, right)?;
    rows.push((
        label,
        l.generation().get(),
        r.generation().get(),
        l.same_family(r),
        l.is_compatible_with(r),
        result,
    ));
}
let columns = serde_json::json!([
    { "key": "0", "label": "Combination" },
    { "key": "1", "label": "Left generation", "type": "integer" },
    { "key": "2", "label": "Right generation", "type": "integer" },
    { "key": "3", "label": "Same family", "type": "boolean" },
    { "key": "4", "label": "Same revision", "type": "boolean" },
    { "key": "5", "label": "try_zip_map result" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "tokens" })
);
```

A mesh reconstructed from the same grid shares its token and revision, so field combination is accepted.
A separately constructed grid with identical coordinates has a different family; a refined grid shares its family but differs in generation, so both give `InvalidInput`.
Two grids refined separately from the same parent share family and generation 1 but differ in revision, again giving `InvalidInput`.
This rule prevents confusion between separately constructed revisions, even with identical coordinates.
At $r = 1$, refinement changes nothing and returns the original grid's token, so the bottom two rows are accepted too.
Even fields of different lengths (the refined grid has $4r \times 4$ cells) stop at the token check before length comparison.

## Summary

Arrange field values in column-major order with axis 0 varying fastest, matching grid and mesh entity numbering.
A periodic axis pairs seam endpoints while keeping distinct vertices and faces and unchanged counts; examine seams using `paired` of `FaceTopology::Periodic` and incidence queries.
Without a connectivity table, `CellMesh` computes adjacency and boundaries by index arithmetic; determine array sizes in advance with `TopologySizes`.
Select value locations through the type of `Field`, preventing meaningless mesh/location combinations at compile time.
Refinement or axis replacement changes the generation and revision of `MeshToken`; separately constructed grids also differ in family, so combining old-revision values gives `InvalidInput` through a $O(1)$ check.
Sibling revisions constructed separately from one parent cannot be combined merely because their generations agree; transfer fields to the target revision before combining them.
