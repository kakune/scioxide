## Coordinates and point sets

Coordinate scalars are `RealScalar` (`f32` or `f64`); complex numbers are unsupported.
Distances use `f64` intermediates regardless of coordinate type; if a Euclidean sum of squares overflows or falls below the normal range, it is rescaled and recomputed.

`PointSet` represents point collections of arbitrary dimension.
Each row is one point and columns are coordinates (shape $[n, d]$).
`PointSet::from_points` borrows a sequence of fixed-length arrays `[[S; D]]`, `PointSet::from_rows` a flat row-major array, and `PointSet::new` a rank-two `scioxide_core` view `NdView` with arbitrary strides.
Every constructor checks coordinate finiteness once; distances, KD trees, tessellations, and batch rigid transformations read coordinates without copying them.

Tessellations (`ConvexHull`, `Delaunay`, `Voronoi`, `SphericalVoronoi`) work differently.
They own coordinates sorted lexicographically, merging sites with equal coordinates.
Returned indices refer to these sorted sites (canonical sites).
Map to input rows using `input_mapping` (input row → canonical index) and `representatives` (canonical index → first input row) of `ConvexHull` and `Delaunay`.
`Voronoi` retrieves the same mappings through `delaunay()`; `SphericalVoronoi` holds only `input_mapping`.
Tessellation results therefore depend only on the site set, independently of input order.
`HalfspaceIntersection` keeps inequality rows in input order and uses their indices directly.

Structured grids and simplex meshes are limited to one through three dimensions and use fixed-size `Point<S, D>`, `Extent<D>`, and `Index<D>`.
Indices are ordered with axis 0 varying fastest; index $[x, y, z]$ in extent $[n_x, n_y, n_z]$ has linear position $x + n_x (y + n_y z)$.

Rotations are active, right-handed rotations with angles in radians.
Quaternions store the scalar component last, in order $[x, y, z, w]$; matrices are row-major and act on column vectors.

## Exact decisions and rounded constructions

Combinatorial decisions use exact signs of determinants of input coordinates.
These include orientation, circumcircle/circumsphere inclusion tests, convex-hull and Delaunay faces, point location, and simplex-mesh orientation checks.
Floating-point filters establish most signs; uncertain signs trigger exact determinant arithmetic, so results are correct for finite inputs, including degenerate inputs.
The signs are correct for the floating-point numbers representing the input, without accounting for measurement error.

Periodic-grid seam correspondence and mesh-face adjacency use integer indices instead of determinants.
These also involve no rounding.

Circumcenters, Voronoi vertices and ray directions, halfspace-intersection vertices, barycentric coordinates, lengths, areas and volumes, rotation composition, and rigid registration are rounded constructions.
Constructed values are not used for combinatorial decisions.
Only halfspace-intersection vertices have certified error bounds; for other constructions, we describe only the checks performed by each method.
For Delaunay tessellations and Voronoi diagrams, only queries for simplices or vertices whose constructions cannot be computed reliably return `NumericalInstability`; other items remain usable.
Halfspace intersection is an exception: failure to certify one vertex makes the entire construction return `NumericalInstability`.
Distances and rigid-registration residuals are computed values, not estimates of statistical uncertainty or certified enclosures.

## Preparation, workspaces, and execution

Batch computations have four stages.

| Stage | Form | Examples |
|---|---|---|
| Configuration | Settings values modified with `with_*` | `SearchOptions`, `DistanceOptions`, `TransformOptions`, `GeometryOptions`, `AdaptationLimits` |
| Preparation | `new(...)` with default options, `with_options(...)` accepting options, `build(..., cx)` accepting an execution context; produces an immutable plan | `KdTree::new`, `KdTree::with_options`, `PreparedDistance::new`, `Delaunay::build`, `RotationSpline::build` |
| Workspace | Query requirements (`workspace_requirements`) and reserve (`try_reserve`, `workspace`) | `SearchWorkspace`, `DistanceWorkspace`, `TransformWorkspace`, `GeometryWorkspace` |
| Execution | `*_into(..., out, workspace, cx)` and `*_scoped(..., cx)` with caller arrays and workspace, or forms running sequentially with defaults and returning owned results | `nearest_into`, `pairwise_into`, `apply_batch_into`, `find_simplex_scoped`, `nearest`, `pairwise`, `find_simplex` |

`*_into` forms update outputs only after the entire computation succeeds, preserving outputs on failure.
Reserved workspace does not grow during execution, so SciOxide numerical computations allocate no memory for calls within reserved sizes.
Allocations by injected executors follow their own contracts.
If `try_reserve` fails, some capacity already grown may remain; reserve again before use.

Batch distances, searches, and transformations receive executors, cancellation, and deadlines through `SpatialExecutionContext`.
This can be converted from `ExecutionContext`, `SolveScope`, or `&mut SolveContext`; even when constructed from a solve context, it does not count iterations.

Tessellation construction (`build`), Delaunay point location (`find_simplex_scoped`), convex-hull inclusion (`contains_scoped`), rotation-spline preparation (`RotationSpline::build`), rigid registration (`estimate_rigid_transform_scoped`), and adaptive refinement (`adapt_scoped`) accept `impl Into<SolveScope>`.
They run as nested solves in the supplied context, obeying the caller's cancellation and deadline.
Predicate and combinatorial work (tessellation, point location, inclusion) and adaptive-refinement work count toward the caller's node limit; adaptive cell splits also count toward the refinement limit.
Iterations (site insertion in tessellation, spline fixed-point iteration, rigid-registration fitting) appear in caller counts but consume only the nested solve's own limit, without reducing the caller's iteration limit.
Counting rules are covered in [Per-solve limits and limits shared between solves](oxref:core-local-and-shared-budgets).
Forms without contexts (such as `new`, `with_options`, `find_simplex`, `contains`, `estimate_rigid_transform`, `adapt`) perform the same work sequentially without cancellation or deadlines.

Batch distances, searches, and transformations under `ExecutionPolicy::Auto` consider parallel execution at 256 or more outputs or queries.
The chapter's cells run sequentially in wasm, so specifying `Auto` does not enable parallelism.

## Resource limits and errors

Constructions and workspaces have limits on bytes, point counts, work, and other resources.
Exceeding limits returns `ResourceLimit` without exposing intermediate results.
Tessellation limits use `GeometryLimits`, defaulting to 8 dimensions, one million each of sites and faces, $10^9$ each for predicate and combinatorial work, and 512 MiB memory.

Classify errors with `e.kind()` (`SciOxideErrorKind`).

| Classification | Conditions |
|---|---|
| `NonFinite` | NaN or infinity in coordinates, weights, or queries |
| `DimensionMismatch` | Point-set or array dimension/length mismatches, insufficient workspace or outputs (including batch radius queries that do not fit) |
| `OutOfBounds` | Indices outside mesh, tessellation, or point-set bounds |
| `DomainError` | Points outside grid coordinate bounds or distances undefined for the inputs (such as cosine distance for zero vectors) |
| `Singular` | Tessellation sites failing to span the space |
| `InvalidInput` | Invalid settings, connectivity failing validation, fields from another mesh revision, nonorthogonal rotation matrices, interpolation times outside knot bounds, sites rejected by `Strict`, noninterior points, or rigid registration with nonunique rotation |
| `NumericalInstability` | Ill-conditioned or unrepresentable constructions, measures, or distances |
| `ResourceLimit` | Exceeded limits or `KdTree::radius_into` queries exceeding output capacity |
| `SizeOverflow`, `AllocationFailure` | Size-computation overflow or allocation failure |
| `ExecutionStopped`, `ConvergenceFailure` | Cancellation, deadlines, or exhausted solve computation limits (such as iterations) |

Rank-deficient inputs receive different classifications in different contexts.
Tessellation sites on a hyperplane yield `Singular`; collinear rigid-registration points yield `InvalidInput`.
Errors carry failure kinds, arguments or quantities, and details, without caller identities.

## Notation

| Symbol | Meaning |
|---|---|
| $n$, $d$ | Point count and coordinate dimension |
| $d(x, y)$, $\Vert \cdot \Vert_p$ | Distance and $p$ norm |
| $k$, $r$, $\varepsilon$ | Neighbor count, search radius, and approximation tolerance (distance ratio $1 + \varepsilon$) |
| $\varepsilon_{\text{mach}}$ | Machine epsilon ($2^{-52}$ for `f64`, $2^{-23}$ for `f32`) |
| $R$, $q = (x, y, z, w)$ | Rotation matrix and scalar-last unit quaternion |
| $\omega$, $\alpha$ | Body-frame angular velocity [rad/s] and angular acceleration [rad/s²] |
| $a \cdot x + b \le 0$ | Halfspace (coefficient $a \in \mathbb{R}^d$, constant $b$) |

## Summary

Combinatorial decisions use exact signs, while constructions such as circumcenters and areas include rounding; do not repeat decisions using constructed values.
Tessellation indices are canonical indices of sorted sites; map back to input rows with `input_mapping` and `representatives` (`Voronoi` uses `delaunay()`).
Batch computation separates configuration, preparation, workspace, and execution; reserving workspace once avoids allocation for calls up to the same size.
Classify errors with `e.kind()`; outputs remain unchanged on failure.
Reading in the listed order requires only preceding pages, so begin with [Foundations of points, bounds, grids, and meshes](geometry-grids-and-meshes/) to examine grid and mesh representations.
