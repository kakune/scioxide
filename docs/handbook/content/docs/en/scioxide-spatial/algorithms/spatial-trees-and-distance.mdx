Finding the $k$ points nearest a query or all points within radius $r$ among $n$ points appears in cluster analysis, particle interactions, and nearest-neighbor interpolation or classification.
Exhaustive search computes distances to every point, costing $O(nd)$ per query in $d$ dimensions.
A KD tree recursively bisects space with axis-aligned hyperplanes, skipping whole regions far from the query.
This page explains tree construction, lower bounds supporting pruning, approximate-search meaning, and periodic boundaries, then compares results with exhaustive search.
[KD-tree queries and workspaces](../kdtree-queries-and-workspaces/) covers query forms and workspaces; [Distances and dissimilarities](../distances/) covers distance definitions.

## KD-tree construction

`KdTree::with_options(&points, metric, options)` constructs a binary tree over a borrowed `PointSet`.
`KdTree::new(&points)` constructs the same way with defaults: Euclidean distance, leaf size 16, and no periodic box.
Each node chooses the axis with greatest coordinate spread (maximum minus minimum) and splits points at its median coordinate.
Medians use (coordinate, original row index) order, making tree structure depend only on input even with equal coordinates.
Splitting stops when leaf point count is at most the `KdTreeOptions::with_leaf_size` value (default 16).
A region whose points all coincide cannot be split and remains one leaf even above the leaf-size limit.

Median splits bound tree depth by $\lceil \log_2 n \rceil$; construction costs $O(d\,n \log n)$ and uses $O(n + d)$ memory.
The tree stores only point indices and borrows coordinates without cloning; coordinates cannot be modified while the tree exists (such code fails to compile).
`node_count()` returns node count; `storage_bytes()` returns tree bytes excluding borrowed coordinates.
Zero leaf size or an exponent of `Minkowski` below 1 or non-finite gives `InvalidInput`.

## Distance lower bounds and pruning

Each node has an axis-aligned box $B = \prod_i [a_i, b_i]$ containing its subtree's points (the root box is stored; child boxes follow from splitting coordinates).
Define query point $q$'s excess along each axis as

$$
\delta_i = \max(a_i - q_i,\; 0,\; q_i - b_i)
$$

then every point $x$ in the box satisfies $\lvert q_i - x_i\rvert \ge \delta_i$ on each axis.
The $p$ norm increases monotonically with each component's magnitude, giving

$$
\lVert q - x\rVert_p \ge \lVert \delta\rVert_p \qquad (x \in B)
$$

follows.
This lower bound applies to all points in the box; if it exceeds current $k$th-neighbor distance $r_k$, discard the whole subtree without examining it.
Until $k$ candidates are available, use $r_k = \infty$; radius queries compare with $r$ instead of $r_k$.
This argument requires componentwise monotonicity, not the triangle inequality.
`TreeMetric` accepts four kinds supporting this lower bound: `Euclidean`, `CityBlock`, `Chebyshev` ($p = \infty$), and `Minkowski(p)` of $p \ge 1$.
Distances without box-distance lower bounds, such as Mahalanobis or cosine, are unsupported by the tree; compute all pairs with `PreparedDistance::pairwise`.

Floating-point computation of $\lVert \delta\rVert_p$ can slightly exceed the true lower bound through rounding, risking erroneous pruning of a subtree containing true neighbors.
`KdTree` multiplies a depth-$\ell$ node's lower bound by safety factor

$$
1 - 64\,(d + \ell + 1)\,\varepsilon_{\mathrm{mach}}
$$

then subtracts twice the scalar type's smallest subnormal before comparison.
$\varepsilon_{\mathrm{mach}}$ is the scalar type's machine epsilon.
This underestimates the lower bound, preventing incorrect pruning through rounding.
Candidate comparisons retain ties that become equal after rounding.

Results are sequences of `Neighbor` (point index `index` and distance `distance`), sorted by increasing distance, then increasing index for ties.
Ties use rounded distances; if several points share the $k$th-neighbor distance, smaller indices remain regardless of visitation order.
Points with unrepresentable distances (overflow) are skipped; only a nearest-neighbor query left with fewer than $k$ points gives `NumericalInstability`.
Radius queries exclude points with unrepresentable distances.
For roughly uniform points in low dimensions, queries end after examining few leaves.
In higher dimensions, many box lower bounds fall below $r_k$ and all points may be visited; results still match exhaustive search, with cost merely approaching exhaustive search.

## Meaning of approximate search

`SearchOptions::with_epsilon(ε)` permits approximate search with $\varepsilon \ge 0$.
Default $\varepsilon = 0$ performs exact search; negative or non-finite $\varepsilon$ gives `InvalidInput`.
Approximation guarantees differ for nearest-neighbor and radius queries.

- Nearest-neighbor queries lower the pruning threshold from $r_k$ to $r_k/(1 + \varepsilon)$.
  The returned $i$th-neighbor distance is at most $1 + \varepsilon$ times the true $i$th-neighbor distance.
  The returned count stays $\min(k, n)$; only point selection changes.
- Radius queries lower the pruning threshold to $r/(1 + \varepsilon)$ and accept candidates at distance at most $r$.
  Every point within $r/(1 + \varepsilon)$ is returned and no point beyond $r$ is returned.
  Points in the intervening band may be returned or omitted.

Both reduce examined subtrees by allowing answers to change within their guarantees.

## Periodic boxes and minimum images

`KdTreeOptions::with_periodic_box(Some(&lengths))` supplies axis periods $L_i$, measuring tree distances on a periodic box.
All indexed point coordinates must lie in $[0, L_i)$.
Out-of-range points, wrong array lengths, or periods that are not finite and positive give `InvalidInput` during construction.
Query coordinates wrap into $[0, L_i)$ on each axis before search (values rounding exactly to $L_i$ move to seam coordinate 0).
Coordinate differences use the minimum image

$$
\Delta_i = \min\bigl(\lvert q_i - x_i\rvert,\; L_i - \lvert q_i - x_i\rvert\bigr)
$$

so each point counts only through its image nearest the query.
The implementation evaluates $L_i - \lvert q_i - x_i\rvert$ in order $(L_i - \max(q_i, x_i)) + \min(q_i, x_i)$ to avoid cancellation when the across-seam image is closer.
This periodicity affects only tree distances and is unrelated to structured-grid periodic axes ([Foundations of points, ranges, grids, and meshes](../geometry-grids-and-meshes/)).

## Comparison with exhaustive search

The next cell uses random seed $s$ to place $n$ points and 32 queries in unit cube $[0, 1)^3$, then batch-computes KD-tree $k$ neighbors with `nearest_batch_into`.
As an independent check, construct the query-to-all-points distance matrix with `pairwise`, sort each row by (distance, index), and compare its $j$th neighbor.
The first table compares tree and exhaustive $k$th-neighbor distances, ratios, and neighbor indices for the first four queries.
The second table shows index matches across all queries, largest distance ratio and guarantee $1 + \varepsilon$, tree node count, and memory.
Check all indices agree at $\varepsilon = 0$ and ratios stay at most $1 + \varepsilon$ at $\varepsilon > 0$.

```rust
//| id: spatial-kdtree-brute-force-check
//| ref: spatial-kdtree-brute-force-check
//| title: "Compare KD-tree k neighbors with an all-pairs distance matrix"
//| run: reactive
//| crates: [scioxide-core, scioxide-random, scioxide-spatial]
//| inputs:
//|   point_count: {"type":"range","label":"Point count n","min":50,"max":2000,"step":50,"value":400}
//|   neighbor_count: {"type":"range","label":"Neighbor count k","min":1,"max":8,"step":1,"value":4}
//|   epsilon: {"type":"range","label":"Approximation allowance ε [-]","min":0,"max":1,"step":0.25,"value":0}
//|   seed: {"type":"range","label":"Random seed s","min":1,"max":50,"step":1,"value":3}
//| cases:
//|   - {"id":"approximate","label":"ε = 1","description":"Some neighbor indices differ from exhaustive search, but distance ratios remain at most 2.","inputs":{"epsilon":1}}
//|   - {"id":"many-points","label":"n = 2000, k = 8","description":"Even with more points and neighbors, exact search agrees with exhaustive search.","inputs":{"point_count":2000,"neighbor_count":8}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":128}
//|       - {"artifact":"summary","path":"/rows/0/1","equals":128}
//|       - {"artifact":"summary","path":"/rows/0/2","equals":1}
//|       - {"artifact":"queries","path":"/rows/0/3","equals":1}
//|   - case: approximate
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":128}
//|       - {"artifact":"summary","path":"/rows/0/2","range":{"min":1,"max":2}}
//|   - case: many-points
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":256}
//|       - {"artifact":"summary","path":"/rows/0/1","equals":256}
//|       - {"artifact":"summary","path":"/rows/0/2","equals":1}
use core::num::NonZeroUsize;
use scioxide_core::{ExecutionContext, NdView, StridedLayout};
use scioxide_random::{SeedableRng, SplitMix64, fill_uniforms};
use scioxide_spatial::{
    KdTree, Neighbor, PointSet, SearchOptions, SearchWorkspaceRequest, pairwise,
};

// n uniform points and 32 queries in the unit cube (one per row).
let (n, k, q, d) = (
    point_count as usize,
    neighbor_count as usize,
    32_usize,
    3_usize,
);
let mut rng = SplitMix64::from_seed(seed as u64);
let (mut coordinates, mut query_coordinates) = (vec![0.0_f64; n * d], vec![0.0_f64; q * d]);
let mut draws = 0;
fill_uniforms(&mut rng, &mut coordinates, &mut draws).map_err(|e| e.to_string())?;
fill_uniforms(&mut rng, &mut query_coordinates, &mut draws).map_err(|e| e.to_string())?;
let (shape_points, shape_queries, strides) = ([n, d], [q, d], [d, 1]);
let layout = StridedLayout::new(&shape_points, &strides).map_err(|e| e.to_string())?;
let points = PointSet::new(NdView::new(&coordinates, layout).map_err(|e| e.to_string())?)
    .map_err(|e| e.to_string())?;
let layout = StridedLayout::new(&shape_queries, &strides).map_err(|e| e.to_string())?;
let queries =
    PointSet::new(NdView::new(&query_coordinates, layout).map_err(|e| e.to_string())?)
        .map_err(|e| e.to_string())?;

// Construct the tree, reserve batch-query workspace, and find k neighbors.
let tree = KdTree::new(&points).map_err(|e| e.to_string())?;
let options = SearchOptions::new().with_epsilon(epsilon);
let request = SearchWorkspaceRequest::new(k, options).with_batch(q, q * k, NonZeroUsize::MIN);
let mut workspace = tree.workspace(request).map_err(|e| e.to_string())?;
let mut found = vec![Neighbor::default(); q * k];
let context = ExecutionContext::sequential();
let total = tree
    .nearest_batch_into(&queries, k, options, &mut found, &mut workspace, context)
    .map_err(|e| e.to_string())?;

// Independent check: sort each row of the query × all-points distance matrix by (distance, index).
let table = pairwise(&queries, &points).map_err(|e| e.to_string())?;
let (mut same_index, mut worst_ratio) = (0_usize, 1.0_f64);
let mut rows = Vec::new();
for (row, distances) in table.as_slice().chunks(n).enumerate() {
    let mut order: Vec<usize> = (0..n).collect();
    order.sort_by(|&a, &b| distances[a].total_cmp(&distances[b]).then(a.cmp(&b)));
    // Since n ≥ 50 > k, each query row has exactly k neighbors.
    let tree_row = &found[row * k..(row + 1) * k];
    for (rank, neighbor) in tree_row.iter().enumerate() {
        same_index += usize::from(neighbor.index == order[rank]);
        worst_ratio = worst_ratio.max(neighbor.distance / distances[order[rank]]);
    }
    if row < 4 {
        let (tree_kth, brute_kth) = (tree_row[k - 1].distance, distances[order[k - 1]]);
        let tree_indices: Vec<usize> = tree_row.iter().map(|v| v.index).collect();
        let brute_indices = format!("{:?}", &order[..k]);
        let tree_indices = format!("{tree_indices:?}");
        rows.push((
            row,
            tree_kth,
            brute_kth,
            tree_kth / brute_kth,
            tree_indices,
            brute_indices,
        ));
    }
}
let fixed6 = serde_json::json!({ "fractionDigits": 6 });
let query_columns = serde_json::json!([
    { "key": "0", "label": "Query", "type": "integer" },
    { "key": "1", "label": "Tree kth-neighbor distance [-]", "type": "number", "format": fixed6 },
    { "key": "2", "label": "Exhaustive kth-neighbor distance [-]", "type": "number", "format": fixed6 },
    { "key": "3", "label": "Ratio [-]", "type": "number", "format": fixed6 },
    { "key": "4", "label": "Tree neighbor indices" },
    { "key": "5", "label": "Exhaustive neighbor indices" }
]);
emit_table_with_columns!(
    query_columns,
    rows,
    metadata = serde_json::json!({ "id": "queries" })
);
let summary_columns = serde_json::json!([
    { "key": "0", "label": "Returned neighbor count", "type": "integer" },
    { "key": "1", "label": "Index matches", "type": "integer" },
    { "key": "2", "label": "Largest distance ratio [-]", "type": "number", "format": fixed6 },
    { "key": "3", "label": "Guarantee 1 + ε [-]", "type": "number", "format": fixed6 },
    { "key": "4", "label": "Node count", "type": "integer" },
    { "key": "5", "label": "Tree memory [B]", "type": "integer" }
]);
let summary = (total, same_index, worst_ratio, 1.0 + epsilon);
let (nodes, bytes) = (tree.node_count(), tree.storage_bytes());
emit_table_with_columns!(
    summary_columns,
    vec![(summary.0, summary.1, summary.2, summary.3, nodes, bytes)],
    metadata = serde_json::json!({ "id": "summary" })
);
```

With defaults ($n = 400$, $k = 4$, $\varepsilon = 0$, $s = 3$), all 128 neighbors of 32 queries have the same indices as exhaustive search and distance ratio 1.
The tree has 63 nodes.
Five levels of median bisection of 400 points produce $2^5 = 32$ leaves of 12–13 points (four leave 25 points, exceeding leaf size 16), giving $2 \cdot 32 - 1 = 63$ nodes.
At $\varepsilon = 1$, only 110 of 128 neighbors match exhaustive search; the largest distance ratio is 1.357, below the guaranteed 2.
Approximation changes neighbor indices but preserves the distance-ratio guarantee; actual ratios in this example are smaller than the bound.
Even at $n = 2000$ and $k = 8$, all 256 exact-search neighbors match exhaustive search.

## Radius-query band points and periodic-box effects

The next cell uses seed $s$ to place 500 points in unit square $[0, 1)^2$ and performs batch radius-$r$ queries from five corner, edge, and central points.
Inputs choose whether to use a periodic box (period 1) and permit approximation through $\varepsilon$.
As an independent check, compute all distances directly with standard `f64` functions (minimum images for periodic boxes), classifying points as inside $r/(1 + \varepsilon)$, in the band between $r/(1 + \varepsilon)$ and $r$, or outside $r$.
For each query, the table shows returned count, inner and band counts, omitted inner points, returned band points, returned points beyond $r$, and largest distance difference.
The guarantee requires zero omitted inner points and zero returned points beyond $r$.

```rust
//| id: spatial-kdtree-radius-periodic
//| ref: spatial-kdtree-radius-periodic
//| title: "Check radius-query approximation bands and periodic-box minimum images against exhaustive search"
//| run: reactive
//| crates: [scioxide-core, scioxide-random, scioxide-spatial]
//| inputs:
//|   radius: {"type":"range","label":"Radius r [-]","min":0.02,"max":0.3,"step":0.02,"value":0.1}
//|   epsilon: {"type":"range","label":"Approximation allowance ε [-]","min":0,"max":1,"step":0.25,"value":0.5}
//|   periodic: {"type":"checkbox","label":"Use a periodic box (period 1)","value":true}
//|   seed: {"type":"range","label":"Random seed s","min":1,"max":50,"step":1,"value":5}
//| cases:
//|   - {"id":"exact","label":"ε = 0","description":"The band is empty and the returned count equals the inner-point count.","inputs":{"epsilon":0}}
//|   - {"id":"bounded","label":"No periodic box","description":"Corner and edge queries return fewer points because regions outside the box contribute no points.","inputs":{"periodic":false}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"radius","path":"/rows/0/1","equals":16}
//|       - {"artifact":"radius","path":"/rows/0/4","equals":0}
//|       - {"artifact":"radius","path":"/rows/0/6","equals":0}
//|       - {"artifact":"radius","path":"/rows/3/4","equals":0}
//|       - {"artifact":"radius","path":"/rows/3/5","equals":11}
//|       - {"artifact":"radius","path":"/rows/3/7","range":{"max":1e-15}}
//|   - case: exact
//|     expect:
//|       - {"artifact":"radius","path":"/rows/3/1","equals":18}
//|       - {"artifact":"radius","path":"/rows/3/3","equals":0}
//|       - {"artifact":"radius","path":"/rows/3/4","equals":0}
//|   - case: bounded
//|     expect:
//|       - {"artifact":"radius","path":"/rows/0/1","equals":3}
//|       - {"artifact":"radius","path":"/rows/0/4","equals":0}
//|       - {"artifact":"radius","path":"/rows/4/6","equals":0}
use core::num::NonZeroUsize;
use scioxide_core::{ExecutionContext, NdView, StridedLayout};
use scioxide_random::{SeedableRng, SplitMix64, fill_uniforms};
use scioxide_spatial::{
    KdTree, KdTreeOptions, Neighbor, PointSet, SearchOptions, SearchWorkspaceRequest,
    TreeMetric,
};

let n = 500;
let mut coordinates = vec![0.0_f64; 2 * n];
let mut rng = SplitMix64::from_seed(seed as u64);
fill_uniforms(&mut rng, &mut coordinates, &mut 0).map_err(|e| e.to_string())?;
let probes = [
    [0.01, 0.01],
    [0.99, 0.5],
    [0.5, 0.995],
    [0.5, 0.5],
    [0.995, 0.995],
];
let query_coordinates: Vec<f64> = probes.iter().flatten().copied().collect();
let (shape_points, shape_queries, strides) = ([n, 2], [probes.len(), 2], [2, 1]);
let layout = StridedLayout::new(&shape_points, &strides).map_err(|e| e.to_string())?;
let points = PointSet::new(NdView::new(&coordinates, layout).map_err(|e| e.to_string())?)
    .map_err(|e| e.to_string())?;
let layout = StridedLayout::new(&shape_queries, &strides).map_err(|e| e.to_string())?;
let queries =
    PointSet::new(NdView::new(&query_coordinates, layout).map_err(|e| e.to_string())?)
        .map_err(|e| e.to_string())?;
let period = [1.0, 1.0];
let tree_options = KdTreeOptions::default().with_periodic_box(periodic.then_some(&period[..]));
let tree = KdTree::with_options(&points, TreeMetric::Euclidean, tree_options)
    .map_err(|e| e.to_string())?;

// Batch radius queries. Output holds all points × query count, enough for every result.
let options = SearchOptions::new().with_epsilon(epsilon);
let capacity = n * probes.len();
let request = SearchWorkspaceRequest::new(0, options).with_batch(
    probes.len(),
    capacity,
    NonZeroUsize::MIN,
);
let mut workspace = tree.workspace(request).map_err(|e| e.to_string())?;
let (mut found, mut counts) = (vec![Neighbor::default(); capacity], vec![0; probes.len()]);
let context = ExecutionContext::sequential();
tree.radius_batch_into(
    &queries,
    radius,
    options,
    &mut found,
    &mut counts,
    &mut workspace,
    context,
)
.map_err(|e| e.to_string())?;

// References: compute every point's distance with standard f64 functions (componentwise minimum images for periodic boxes).
let reference = |q: [f64; 2], i: usize| {
    let image = |delta: f64| {
        if periodic {
            delta.min(1.0 - delta)
        } else {
            delta
        }
    };
    let dx = image((q[0] - coordinates[2 * i]).abs());
    let dy = image((q[1] - coordinates[2 * i + 1]).abs());
    dx.hypot(dy)
};
let inner_radius = radius / (1.0 + epsilon);
let mut rows = Vec::new();
let mut start = 0;
for (row, &q) in probes.iter().enumerate() {
    let returned = &found[start..start + counts[row]];
    start += counts[row];
    let distances: Vec<f64> = (0..n).map(|i| reference(q, i)).collect();
    let inner = distances.iter().filter(|&&d| d <= inner_radius).count();
    let band = distances
        .iter()
        .filter(|&&d| d > inner_radius && d <= radius)
        .count();
    let band_returned = returned
        .iter()
        .filter(|v| distances[v.index] > inner_radius)
        .count();
    let inner_returned = returned.len() - band_returned;
    let beyond = returned
        .iter()
        .filter(|v| distances[v.index] > radius)
        .count();
    let gap = returned
        .iter()
        .map(|v| (v.distance - distances[v.index]).abs())
        .fold(0.0, f64::max);
    let label = format!("{q:?}");
    rows.push((
        label,
        returned.len(),
        inner,
        band,
        inner - inner_returned,
        band_returned,
        beyond,
        gap,
    ));
}
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "Query point" },
    { "key": "1", "label": "Returned points", "type": "integer" },
    { "key": "2", "label": "Inner points", "type": "integer" },
    { "key": "3", "label": "Band points", "type": "integer" },
    { "key": "4", "label": "Omitted inner points", "type": "integer" },
    { "key": "5", "label": "Returned band points", "type": "integer" },
    { "key": "6", "label": "Returned points beyond r", "type": "integer" },
    { "key": "7", "label": "Largest distance difference [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "radius" })
);
```

With defaults ($r = 0.1$, $\varepsilon = 0.5$, periodic box), every query has zero omitted inner points and zero returned points beyond $r$, as guaranteed.
At central query $(0.5, 0.5)$, only 11 of 12 band points are returned, omitting one.
At $\varepsilon = 0$, the band is empty and the central query returns all 18 inner points.
Removing the periodic box reduces corner query $(0.01, 0.01)$'s result from 16 points to 3, as points near opposite edges no longer count as neighbors.
Returned distances agree with minimum-image references within $3 \times 10^{-17}$.

## Summary

KD trees support componentwise-monotone distances `Euclidean`, `CityBlock`, `Chebyshev`, and `Minkowski(p ≥ 1)`; use exhaustive `PreparedDistance::pairwise` for Mahalanobis or cosine.
The tree splits points at medians along their widest axis, constructing in $O(d\,n\log n)$ without cloning coordinates and supporting reuse for many queries on one point set.
Pruning underestimates lower bounds to account for rounding, so exact-search results match exhaustive search down to point indices.
When selecting $\varepsilon > 0$, distinguish guarantees: nearest-neighbor distance ratios at most $1 + \varepsilon$; radius queries return every point within $r/(1 + \varepsilon)$ and none beyond $r$.
For periodic systems, place coordinates in $[0, L_i)$ before constructing with `with_periodic_box`, using minimum-image distances.
