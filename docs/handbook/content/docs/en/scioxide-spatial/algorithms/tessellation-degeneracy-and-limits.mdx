When constructing triangulations from cocircular survey grids or point clouds with millions of points, we need to know resource usage and degeneracy resolution as well as result structure.
Triangulation construction in `scioxide-spatial` accepts resource limits through `GeometryLimits` and returns usage and symbolic-perturbation information through `GeometryProvenance`.
This page explains limits, workspaces, and each construction-information quantity, then compares the two degeneracy policies on a cocircular lattice.
[Site canonicalization and degeneracy handling](oxref:spatial-tessellation-sites) explains canonicalization, definitions of `Deterministic` and `Strict`, and symbolic perturbation.

## Resource limits, workspaces, and construction information

Construction options `GeometryOptions` hold resource limits `GeometryLimits` and a degeneracy policy.
Constructed triangulations retain options and use the same limits for queries.
The following table shows defaults for `GeometryLimits::new()`.
Each limit is checked separately; exceeding one makes construction return `ResourceLimit`.
Setting a large limit does not reserve memory in advance.

| Limit | Default | Quantity counted |
|---|---|---|
| `max_dimension` | 8 | Coordinate dimension |
| `max_points` | 1,000,000 | Input sites (rows before deduplication) or halfspaces |
| `max_facets` | 1,000,000 | Convex-hull facets simultaneously present during construction (lifted hull for Delaunay) |
| `max_predicate_terms` | $10^9$ | Predicate work per construction or query |
| `max_canonical_work` | $10^9$ | Combinatorial work grouping and triangulating coplanar facets |
| `max_storage_bytes` | 512 MiB | Construction memory or workspace memory |

Predicate work counts one unit per sign evaluation.
If a floating-point filter cannot determine the sign and exact evaluation is needed, the determinant's Leibniz term count is added.
Term counts are $(d+1)!$ for $d$-dimensional orientation, $d\,(d+2)!$ for inside/outside tests, and $m!$ for a homogeneous determinant of order $m$.
In the plane, orientation has six terms and `incircle` 48; in space, orientation has 24 and `insphere` 360.
Counting is deterministic, giving the same quantities for identical inputs.
Combinatorial work counts adjacency visits, vertex scans, and sorting comparisons when grouping facets on the same supporting hyperplane.

`new(&points)` constructs with default options and `with_options(&points, options)` with supplied options, both without cancellation.
`build(&points, options, cx)` accepts an execution context or `SolveScope`, returning `ExecutionStopped` for cancellation or deadlines and `ConvergenceFailure` when the solve-context node limit is reached.
Predicate and combinatorial work also count toward solve-context node counts.

The `GeometryConstructionRequirements` returned by `construction_requirements()` is peak memory used during construction.
It includes temporary memory freed during construction and excludes input points and allocator overhead.
It applies only to that input; other inputs may require more memory.

Temporary storage for `ConvexHull` and `Delaunay` queries (`contains_scoped`, `find_simplex_scoped`) is represented by `GeometryWorkspaceRequirements` from `workspace_requirements(())` and allocated with `GeometryWorkspace::try_reserve`.
`workspace(())` constructs a workspace meeting requirements in one step.
Queries using reserved workspace allocate nothing further.
One workspace can serve any triangulation whose requirements it meets.
`GeometryWorkspace::predicate_terms()` returns predicate work from the most recent query using that workspace.

The `GeometryProvenance` returned by `provenance()` contains five construction-information quantities.

- `input_points` counts input sites (inequalities for halfspace intersection); `unique_points` counts sites after deduplication.
- `predicate_terms` is predicate work and `canonical_work` combinatorial work.
- `resolved_ties` is true when symbolic perturbation resolved at least one exactly zero sign.
  This includes ties that do not affect output simplices, and is independent of input-row order.
  `ConvexHull` and `SphericalVoronoi` use no lifting or symbolic perturbation, so it is always false for them.

`Voronoi::provenance` covers the entire construction including dual assembly; `delaunay().provenance()` covers triangulation alone.

## Degeneracy policies and construction information

The next cell constructs `Voronoi` on a $4 \times 4$ lattice (16 points) with both `Deterministic` and `Strict`, comparing results and construction information.
The lattice and “Perturb coordinates” match [Checking duality on lattice points](oxref:spatial-delaunay-voronoi-duality): input row $p$ is $(p \bmod 4,\ \lfloor p/4 \rfloor)$, with shifts below 1/256 determined from the fractional part of $(p+1)^2$ times a constant close to an irrational number.
“Add duplicate row” appends a row with the same coordinates as input row 0.
The table shows each policy's construction result, input-row and site counts, triangle and Voronoi-vertex counts, symbolic-perturbation use, and predicate and combinatorial work.
It also shows the largest difference between each simplex's circumcenter and its group's Voronoi vertex, checking agreement within rounding error.
Rows rejected by `Strict` show the failure classification under construction result and leave other entries empty.

```rust
//| id: spatial-delaunay-degeneracy-policy
//| ref: spatial-delaunay-degeneracy-policy
//| title: "Construct lattice Voronoi diagrams with Deterministic and Strict policies and compare construction information"
//| run: reactive
//| crates: [scioxide-spatial]
//| inputs:
//|   perturb: {"type":"checkbox","label":"Perturb coordinates to remove cocircularity","value":false}
//|   duplicate: {"type":"checkbox","label":"Add a row with input row 0's coordinates","value":false}
//| cases:
//|   - {"id":"perturbed","label":"Perturbed lattice","description":"Cocircularity disappears and Strict accepts too.","inputs":{"perturb":true}}
//|   - {"id":"perturbed-duplicate","label":"Perturbed lattice with duplicate row","description":"Strict rejects duplicate rows even without cocircularity.","inputs":{"perturb":true,"duplicate":true}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"policies","path":"/rows/0/4","equals":18}
//|       - {"artifact":"policies","path":"/rows/0/5","equals":9}
//|       - {"artifact":"policies","path":"/rows/0/6","equals":true}
//|       - {"artifact":"policies","path":"/rows/0/8","equals":2229}
//|       - {"artifact":"policies","path":"/rows/1/1","equals":"InvalidInput"}
//|   - case: perturbed
//|     expect:
//|       - {"artifact":"policies","path":"/rows/0/6","equals":false}
//|       - {"artifact":"policies","path":"/rows/0/8","equals":229}
//|       - {"artifact":"policies","path":"/rows/1/1","equals":"Success"}
//|       - {"artifact":"policies","path":"/rows/1/4","equals":21}
//|       - {"artifact":"policies","path":"/rows/1/8","equals":256}
//|   - case: perturbed-duplicate
//|     expect:
//|       - {"artifact":"policies","path":"/rows/0/2","equals":17}
//|       - {"artifact":"policies","path":"/rows/0/3","equals":16}
//|       - {"artifact":"policies","path":"/rows/0/4","equals":21}
//|       - {"artifact":"policies","path":"/rows/1/1","equals":"InvalidInput"}
use scioxide_spatial::{GeometryDegeneracy, GeometryOptions, PointSet, Voronoi};

// 4 × 4 lattice. Perturbations match the lattice-duality check cell.
let mut sites = Vec::with_capacity(17);
for p in 0..16_usize {
    let (mut dx, mut dy) = (0.0, 0.0);
    if perturb {
        let k = (p as f64 + 1.0) * (p as f64 + 1.0);
        dx = ((k * 0.754_877_666_246_692_7).fract() - 0.5) / 128.0;
        dy = ((k * 0.569_840_290_998_053_3).fract() - 0.5) / 128.0;
    }
    sites.push([(p % 4) as f64 + dx, (p / 4) as f64 + dy]);
}
if duplicate {
    sites.push(sites[0]);
}
let points = PointSet::from_points(&sites).map_err(|e| e.to_string())?;

let policies = [
    ("Deterministic", GeometryDegeneracy::Deterministic),
    ("Strict", GeometryDegeneracy::Strict),
];
let mut rows = Vec::new();
for (name, policy) in policies {
    let options = GeometryOptions::new().with_degeneracy(policy);
    let diagram = match Voronoi::with_options(&points, options) {
        Ok(diagram) => diagram,
        Err(e) => {
            let kind = format!("{:?}", e.kind());
            rows.push((
                name,
                kind,
                sites.len(),
                None,
                None,
                None,
                None,
                None,
                None,
                None,
            ));
            continue;
        }
    };
    let mesh = diagram.delaunay();
    // The group's Voronoi vertex is its lowest-index simplex's circumcenter, agreeing with other circumcenters within rounding error.
    let (mut gap, mut center) = (0.0_f64, [0.0; 2]);
    for s in 0..mesh.simplex_count() {
        mesh.circumcenter_into(s, &mut center)
            .map_err(|e| e.to_string())?;
        let vertex = diagram
            .vertex(diagram.simplex_vertices()[s])
            .map_err(|e| e.to_string())?;
        gap = gap.max(
            (vertex[0] - center[0])
                .abs()
                .max((vertex[1] - center[1]).abs()),
        );
    }
    let p = diagram.provenance();
    rows.push((
        name,
        "Success".to_string(),
        p.input_points,
        Some(p.unique_points),
        Some(mesh.simplex_count()),
        Some(diagram.vertex_count()),
        Some(p.resolved_ties),
        Some(gap),
        Some(p.predicate_terms),
        Some(p.canonical_work),
    ));
}
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "Policy" },
    { "key": "1", "label": "Construction result" },
    { "key": "2", "label": "Input rows [count]", "type": "integer" },
    { "key": "3", "label": "Sites [count]", "type": "integer", "nullText": "—" },
    { "key": "4", "label": "Triangles [count]", "type": "integer", "nullText": "—" },
    { "key": "5", "label": "Voronoi vertices [count]", "type": "integer", "nullText": "—" },
    { "key": "6", "label": "Ties resolved by symbolic perturbation", "type": "boolean", "nullText": "—" },
    { "key": "7", "label": "Largest circumcenter–vertex difference [-]", "type": "number", "format": sci2, "nullText": "—" },
    { "key": "8", "label": "Predicate work [work units]", "type": "integer", "nullText": "—" },
    { "key": "9", "label": "Combinatorial work [work units]", "type": "integer", "nullText": "—" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "policies" })
);
```

With defaults (unperturbed lattice), `Deterministic` produces 18 triangles and nine Voronoi vertices from 16 sites, resolving ties by symbolic perturbation (tie resolution true).
`Strict` returns `InvalidInput` because each square's two triangles share an empty circumcircle.
Predicate work is 2229 work units on the unperturbed lattice and 229 on the perturbed lattice, a roughly tenfold difference.
Exactly zero predicates cannot be resolved by floating-point filters and proceed to exact evaluation (48 terms per `incircle`) and symbolic perturbation.

For “Perturbed lattice,” both policies produce the same 21 triangles and tie resolution is false.
`Strict` uses more predicate work (256 units) than `Deterministic` (229) because it checks triangulation uniqueness.
For “Perturbed lattice with duplicate row,” `Deterministic` merges 17 rows into 16 sites and produces the same 21 triangles as without duplication.
`Strict` returns `InvalidInput` for duplicate rows even without four cocircular points.
Circumcenter–Voronoi-vertex differences are zero in every case: other triangles in each lattice group also round to the same circumcenter.

## Summary

For unavoidable cocircular or cospherical inputs such as lattices or survey points, use `Deterministic` to obtain one triangulation; choose `Strict` to treat nonuniqueness or duplicate sites as errors.
For large inputs, use `GeometryLimits` to limit dimensions, site and facet counts, predicate and combinatorial work, and memory; construction stops with `ResourceLimit` on excess.
For repeated queries, reuse a `GeometryWorkspace` allocated with `workspace_requirements(())` to avoid per-query allocation.
After construction, `predicate_terms` and `resolved_ties` in `GeometryProvenance` reveal how much degeneracy required exact evaluation and symbolic perturbation.
