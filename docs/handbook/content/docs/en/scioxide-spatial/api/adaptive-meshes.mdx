This table collects meshes that locally refine or coarsen structured-grid and simplex-mesh cells, together with their partitioning items.
Cell and face identities use exact binary reference coordinates rather than rounded coordinates.
One call to `AdaptiveMesh::adapt` refines or coarsens marked cells by one level and returns a new revision preserving face 2:1 balance.
`TopologyMap` returns cell and face correspondence between old and new revisions as topological relationships, without weights for transferring field values.
Users of the mesh construct field-value transfers, such as conservative transfers.

## Adaptive meshes and interfaces

| [`MeshPartition`](https://docs.rs/scioxide-spatial/0.1.0/scioxide_spatial/struct.MeshPartition.html) | Struct | Partition of active cells | Assigns every active cell to one part and uses face-sharing cells from other parts as one ghost layer. `balanced` splits `active_cells` order into equal-length contiguous intervals (one remainder cell each to lower-numbered parts); `new` uses the caller's `owners`. The smallest-index part owns shared vertices, faces, and edges (including those connected by interface fragments or periodic seams). Zero parts, `owners` length differing from the active-cell count, or out-of-range owners yield `InvalidInput`; construction exceeding the mesh's `AdaptationLimits` yields `ResourceLimit`. Construction costs $O(N \log N)$ | [Partitions and ghost cells](oxref:spatial-adaptive-partition) | [Partition a refined mesh equally and count owned cells, ghost cells, interfaces, and owned vertices](oxref:spatial-mesh-partition), [Reorder cell values into a partition with reassigned owners and examine permutations and migrating cells](oxref:spatial-mesh-repartition) |

Defaults to `Sequential`, used by `RepartitionMap::new` | [Partitions and ghost cells](oxref:spatial-adaptive-partition), [Repartitioning and cell-value reordering](oxref:spatial-adaptive-repartition) | - |
| [`RepartitionMap`](https://docs.rs/scioxide-spatial/0.1.0/scioxide_spatial/struct.RepartitionMap.html) | Struct | Repartitioning permutation | Transfers cell values between two partitions of the same revision. Values use per-part `cell_order` order; `permutation()` returns the source position for each destination position. Construct with default settings through `new(&source, &destination)` or with `RepartitionOptions` through `with_options`; different revisions yield `InvalidInput` and construction beyond limits yields `ResourceLimit`. `migration_cells(source, destination)` returns migrating cells for each part pair. `gather_into(&input, &mut output, &mut staging, cx)` performs `output[i] = input[permutation()[i]]` without allocation or partition arguments; `input` or `output` lengths differing from the active-cell count, or shorter `staging`, yield `DimensionMismatch`; cancellation and deadlines yield `ExecutionStopped`. Use `validate(&source, &destination)` to check whether the value ordering matches the partitions used at construction. ## Summary

One `adapt` changes an adaptive mesh by one level, adding refinement as needed to preserve face 2:1 balance.
Fine vertices, edges, and faces inside coarse-cell faces or edges are enumerated as hanging entities; interfaces represent all interior, exterior, and periodic fragments.
Correspondence between revisions uses five `EntityRelation` kinds; users construct weights for field-value transfer.
`MeshPartition` holds cell owners and one ghost-cell layer; `RepartitionMap` reorders cell fields on the same topology.
See [Adaptive mesh refinement and topology maps](../../algorithms/adaptive-mesh-and-shared-tessellation/) and [Adaptive mesh partitioning and repartitioning](../../algorithms/mesh-partition/) for mathematics, and [Geometry, grids, and meshes API](../geometry-and-meshes/) for mesh revisions.
