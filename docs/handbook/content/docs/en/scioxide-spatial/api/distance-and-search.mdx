This table collects distance and neighbor-search items for arbitrary-dimensional point sets.
`PointSet` represents borrowed fixed-array sequences, flat row-major arrays, or rank-two `NdView`, checking all coordinates for finiteness once during construction.
Distances use `f64` intermediates regardless of coordinate type.
Functions `distance`, `pairwise`, and `condensed` provide Euclidean distances without preparation; other metrics use `PreparedDistance` methods.
Batch computations stage results in workspace before committing outputs, preserving outputs on errors.
Query distance requirements through associated `DistanceWorkspace::workspace_requirements(request)` and search requirements through method `KdTree::workspace_requirements(request)`.

## Summary

Use `distance`, `pairwise`, and `condensed` for Euclidean distances; prepare 17 named metrics, standardized Euclidean, and Mahalanobis with `PreparedDistance`.
Condensed all-pairs storage ($n(n-1)/2$ entries) approximately halves memory; `condensed_index` retrieves pair positions.
Worst-case directed Hausdorff cost is $O(mnd)$; early termination only reduces comparisons for typical inputs.
KD trees support four metrics (Euclidean, CityBlock, Chebyshev, and Minkowski with $p \ge 1$), sorting results by distance and ascending indices on ties.
See [Distances and dissimilarities](../../algorithms/distances/) for domains, [Distance matrices and condensed representations](../../algorithms/distance-matrices/) for storage, and [Neighbor search with KD trees](../../algorithms/spatial-trees-and-distance/) for pruning/approximation.
