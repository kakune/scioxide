`scioxide-spatial` is a computational-geometry crate.
It places typed fields on structured grids and simplex meshes and supports local refinement and domain partitioning.
It determines orientations and circumsphere tests exactly, constructs convex hulls, Delaunay triangulations, Voronoi diagrams, and halfspace intersections, and locates points within them.
It represents and interpolates three-dimensional rotations and rigid transformations, constructs distance matrices, and answers nearest-neighbor and radius queries with KD trees.
Coordinate types are `f32` and `f64`; disabling default `std` enables the same API in `no_std` using only `alloc`.

This page identifies main items by task and explains type relationships and result and error interpretation.
Item specifications appear in five purpose-grouped table pages, accessible from [Tables by purpose](#purpose-specific-tables) at the end.

## Type relationships

### Settings, prepared plans, and workspaces

Batch computations distinguish four inputs: settings, prepared plans, workspaces, and execution contexts.

- Settings are value types.
  `DistanceOptions`, `SearchOptions`, and `TransformOptions` hold execution policy and workspace byte limits (`SearchOptions` also holds relative approximation error $\varepsilon$); `GeometryOptions` holds construction limits (`GeometryLimits`) and degeneracy handling (`GeometryDegeneracy`).
- Prepared plans (`PreparedDistance`, `KdTree`, `ConvexHull`, `Delaunay`, `Voronoi`, `HalfspaceIntersection`, `SphericalVoronoi`, `Slerp`, `RotationSpline`) are immutable and reusable.
  `KdTree`, convex hulls, Delaunay triangulations, Voronoi diagrams, spherical Voronoi diagrams, halfspace intersections, `RotationSpline`, and `RepartitionMap` have `new` for defaults and `with_options` accepting settings.
- Workspaces (`DistanceWorkspace`, `SearchWorkspace`, `TransformWorkspace`, `GeometryWorkspace`) require no further allocation for calls up to their reserved size once requirements are determined and storage reserved.
  `GeometryWorkspace` supports convex-hull containment (`contains_scoped`) and Delaunay point location (`find_simplex_scoped`).
- Execution contexts supply parallel execution, cancellation, and deadlines.
  Distance, search, and transformation batches and repartitioned-value transfer (`*_into`) accept `impl Into<SpatialExecutionContext>`; tessellation construction (`build`) and queries (`find_simplex_scoped`, `contains_scoped`), rotation-spline preparation (`RotationSpline::build`), rigid estimation (`estimate_rigid_transform_scoped`), and adaptive refinement (`adapt_scoped`) accept `impl Into<SolveScope>`; both accept a sequential `ExecutionContext::sequential()`.
- Forms accepting neither contexts nor workspaces (such as `KdTree::nearest`, `pairwise`, `condensed`, `Delaunay::find_simplex`, `apply_batch`, `evaluate_rotations`, `estimate_rigid_transform`, `AdaptiveMesh::adapt`) execute sequentially with defaults and allocate required workspace and returned results on every call.

Requirement calculation differs by family.

| Family | Request description | Requirement function | Reservation |
|---|---|---|---|
| Distance | `DistanceWorkspaceRequest::pairwise(m, n, options)`, `condensed(n, options)`, `square(n, options)` | `DistanceWorkspace::<S>::workspace_requirements(request)` (associated function) | `DistanceWorkspace::try_reserve` or `DistanceWorkspace::workspace(request)` |
| Search | `SearchWorkspaceRequest::new(k, options)` and `with_batch(queries, neighbors, workers)` | `tree.workspace_requirements(request)` (method of `KdTree`) | `SearchWorkspace::try_reserve` or `tree.workspace(request)` |
| Transformation | `apply`, `euler`, `rotations` of `TransformWorkspaceRequest` (each estimates one buffer kind) | `TransformWorkspace::<S>::workspace_requirements(request)` (associated function) | `TransformWorkspace::try_reserve` or `TransformWorkspace::workspace(request)` |
| Point location | No arguments (`()`) | `workspace_requirements(())` of `ConvexHull` and `Delaunay` | `GeometryWorkspace::try_reserve` or `workspace(())` |

`max_workspace_bytes` limits all retained workspace capacity, including capacity from previous larger reservations.
A failed `try_reserve` may leave some capacity allocated; reserve again before use.

### Borrowing and ownership

`PointSet` and `KdTree` borrow input coordinates without cloning.
Convex hulls, Delaunay triangulations, Voronoi diagrams, and spherical Voronoi diagrams sort sites lexicographically, merge equal coordinates, and own the resulting coordinates.
Their returned indices are therefore canonical indices after sorting.
`ConvexHull` and `Delaunay` have `input_mapping` (input row → canonical index) and `representatives` (canonical index → first input row).
`Voronoi` accesses the same mappings through `delaunay()`; `SphericalVoronoi` has only `input_mapping`.
`HalfspaceIntersection` neither sorts nor merges inequalities.
Structured grids, simplex meshes, and fields own coordinates and connectivity; reference-counted sharing makes clone cost independent of array length.

### Mesh revisions and fields

This guide calls each new mesh produced by modification a revision.
Every mesh has a `MeshToken` representing its family (revisions derived from the same mesh), generation number, and revision-specific identity.
Methods returning modified meshes, such as `StructuredGrid::refined`, `SimplexMesh::with_points`, and `AdaptiveMesh::adapt`, preserve the family and advance the generation.
Fields (`Field`), boundary sets (`BoundarySet`), boundary tags (`SimplexBoundaryTags`), and topological correspondences (`TopologyMap`) retain their construction revision; operations combining them check it in $O(1)$.
Different revisions of the same generation (constructed separately from one parent) are incompatible and return `InvalidInput`.

## Minimal executable example

For three planar points, check `orient2d` sign changes under reordering, zero for collinearity, and errors for non-finite input.
There are no inputs.
The output is a four-row table comparing expected signs with actual results.

```rust
//| id: spatial-api-orient2d-minimal
//| ref: spatial-api-orient2d-minimal
//| title: "Check orientation signs and errors for non-finite input"
//| run: reactive
//| crates: [scioxide-spatial]
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"signs","path":"/rows/0/1","equals":"Positive"}
//|       - {"artifact":"signs","path":"/rows/1/1","equals":"Negative"}
//|       - {"artifact":"signs","path":"/rows/2/1","equals":"Zero"}
//|       - {"artifact":"signs","path":"/rows/3/1","equals":"NonFinite"}
use scioxide_spatial::orient2d;

let a = [0.0_f64, 0.0];
let b = [1.0_f64, 0.0];
let c = [0.0_f64, 1.0];
let cases = [
    ("a → b → c (counterclockwise)", a, b, c, "Positive"),
    ("a → c → b (clockwise)", a, c, b, "Negative"),
    ("a → b → (2, 0) (collinear)", a, b, [2.0, 0.0], "Zero"),
    ("a → b → (NaN, 1)", a, b, [f64::NAN, 1.0], "NonFinite"),
];
let mut rows = Vec::new();
for (label, p, q, r, expected) in cases {
    // Signs use PredicateSign names; failures use error classification (SciOxideErrorKind) names.
    let result = match orient2d(&p, &q, &r) {
        Ok(sign) => format!("{sign:?}"),
        Err(e) => format!("{:?}", e.kind()),
    };
    rows.push((label, result, expected));
}
let columns = serde_json::json!([
    { "key": "0", "label": "Point order" },
    { "key": "1", "label": "orient2d result" },
    { "key": "2", "label": "Expected result" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "signs" })
);
```

`Positive` means counterclockwise, `Negative` clockwise, and `Zero` collinear points.
`Zero` means an exactly zero determinant, not a tolerance-based test.
Input containing NaN returns no sign and gives a `NonFinite` error.

## Reading results, errors, and diagnostics

### Written counts

Functions with variable result counts, such as `nearest_into`, `radius_into`, `nearest_batch_into`, and `radius_batch_into`, return the written count and modify only that many leading output elements.
They do not fill remaining elements with sentinel values.
`Neighbor` holds input-row indices and distances, sorted by increasing distance and then increasing index for ties.

### Exact decisions and rounded constructions

All combinatorial decisions use exact signs of determinants of input coordinates.
This includes predicates, convex-hull and Delaunay faces, point location, and simplex orientation checks; results are correct for finite input, including degeneracies.
Circumcenters, Voronoi vertices and ray directions, halfspace-intersection vertices, barycentric coordinates, volumes, and areas are constructed values involving rounding.
Only halfspace-intersection vertices have certified error bounds: a dimension-$d$ vertex $x$ violates each inequality $a\cdot x + b \le 0$ by at most $128\,\varepsilon\,(d+1)\,(|b| + \sum_i |a_i x_i|)$ ($\varepsilon$ is the coordinate type's machine epsilon).
For Delaunay and Voronoi structures, only queries on simplices or vertices whose constructed values cannot be computed reliably return `NumericalInstability`; other items remain usable.
Halfspace intersections and spherical Voronoi diagrams are exceptions: inability to certify one vertex's error or compute a spherical region or area makes the entire construction give `NumericalInstability`.
Distances use `f64` intermediates regardless of coordinate type.
Euclidean-type norms first sum squares without scaling, recomputing with scaling only on overflow or values below the normal range.

### Termination status and construction records

Unbounded halfspace intersections return `IntersectionKind` without an error.
Rotation-spline `with_options` and `build` return nonconvergence as `RotationSplineTermination` rather than an error; results contain a spline only for `Converged`.
`RotationSpline::new` reports the same nonconvergence as a `ConvergenceFailure` error.
`GeometryProvenance` records site counts used in tessellation construction, accepted predicate work, canonicalization work, and whether symbolic perturbation resolved a zero sign.
Rigid-estimation (`RigidEstimationResult`) residuals diagnose fit quality and are not statistical uncertainty intervals.
`HausdorffResult` holds the computed distance and the point pair realizing it (a distance-realizing pair).

### Error classifications

Classify errors with `e.kind()` (`SciOxideErrorKind`).

| Classification | Situations in this crate |
|---|---|
| `InvalidInput` | Invalid settings, rejected mesh connectivity, fields or maps for another revision, nonorthogonal rotation matrices, interpolation times outside knot ranges, sites rejected by `GeometryDegeneracy::Strict`, an interior point not strictly inside every halfspace, or rigid-estimation configurations without a unique rotation |
| `DimensionMismatch` | Point-set or array dimension/length mismatches, insufficient output, scratch arrays, or workspaces (including `KdTree::radius_batch_into` results exceeding output capacity) |
| `OutOfBounds` | Out-of-range mesh, tessellation, or point-set indices |
| `NonFinite` | NaN or infinity in coordinates, weights, or queries |
| `DomainError` | Points outside grid coordinate ranges or undefined distances (such as zero-vector cosine distance) |
| `Singular` | Tessellation sites not spanning space (sites in a hyperplane) |
| `NumericalInstability` | Ill-conditioned or unrepresentable constructed values (coordinates, measures, distances) |
| `ResourceLimit` | Construction exceeding `GeometryLimits` or `AdaptationLimits`, workspace byte-limit excess, or `KdTree::radius_into` queries exceeding output capacity |
| `SizeOverflow`, `AllocationFailure` | Size-computation overflow or allocation failure |
| `ExecutionStopped`, `ConvergenceFailure` | Cancellation, deadlines, or exhausted solve computation limits (such as iteration limits) in context-accepting operations. `RotationSpline::new` nonconvergence also gives `ConvergenceFailure` |

Errors leave output unchanged.
Variable-count functions modify only the returned count of leading elements.

## Summary

Proceed from task-based main items to purpose-grouped tables to inspect each item's specification.
Batch computations distinguish settings, immutable plans, workspaces, and execution contexts; reserving workspace once avoids allocations for calls up to that size.
Tessellation indices are canonical indices of sorted sites; return to input rows through `input_mapping` and `representatives` (`Voronoi` accesses them through `delaunay()`).
Exact signs determine combinatorial results, while constructed values involve rounding; compare values requiring verification with independent computations.
Classify errors with `e.kind()`; outputs remain unchanged on failure.
