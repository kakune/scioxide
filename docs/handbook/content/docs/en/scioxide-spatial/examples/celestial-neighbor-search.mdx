A star tracker determines spacecraft orientation by matching photographed star patterns against a catalog.
Matching repeatedly retrieves catalog stars within angular distance $\theta_0$ of a direction.
Stellar positions lie on the celestial sphere, so proximity uses angular distance along great circles rather than planar distances.
This example represents the celestial sphere as a three-dimensional unit sphere and replaces angular-distance searches with radius searches on a three-dimensional KD tree.
The second half constructs a spherical Voronoi diagram partitioning the sky by nearest star and examines region areas (solid angles).

## Equatorial coordinates and unit vectors

Stellar positions use right ascension $\alpha$ and declination $\delta$.
$\alpha$ measures eastward from the vernal equinox; $\delta$ measures northward from the celestial equator.
On a celestial sphere of radius 1, each star corresponds to the following unit vector.

$$
\boldsymbol{u}(\alpha, \delta) =
\begin{pmatrix} \cos\delta\cos\alpha \\ \cos\delta\sin\alpha \\ \sin\delta \end{pmatrix}
$$

The $x$ axis points toward the vernal equinox and $z$ toward the north celestial pole.
All three axes use celestial-sphere radius as the unit of length.

## Chord length and angular distance

Let $\theta \in [0, \pi]$ be the angular distance between stars $\boldsymbol{u}_1$ and $\boldsymbol{u}_2$.
Half the isosceles triangle’s apex angle gives chord length $c = \|\boldsymbol{u}_1 - \boldsymbol{u}_2\|$:

$$
c = 2\sin\frac{\theta}{2}, \qquad \theta = 2\arcsin\frac{c}{2}
$$


Since $c$ increases strictly with $\theta$, angular distance at most $\theta_0$ is equivalent to chord length at most $c_0 = 2\sin(\theta_0/2)$.
Thus an angular-distance search requires one Euclidean radius-$c_0$ query (`KdTree::radius_into`) on a KD tree of unit vectors.
Trigonometric functions are needed only to construct $c_0$ and convert found stars' $c$ back to angles.

The angle-conversion formula affects accuracy.
$\theta = 2\arcsin(c/2)$ remains well-conditioned for small $\theta$, transferring relative errors in $c$ almost directly to relative errors in $\theta$.
By contrast, computing $\theta = \arccos(\boldsymbol{u}_1\cdot\boldsymbol{u}_2)$ from dot products converts rounding error $\varepsilon \approx 1.1\times10^{-16}$ in $\boldsymbol{u}_1\cdot\boldsymbol{u}_2 = 1 - \theta^2/2 + \cdots$ to angular error around $\sqrt{2\varepsilon} \approx 1.5\times10^{-8}$ rad in $\theta$.
Using $\arccos$ for nearly coincident stars or the central star itself reveals differences on this scale.

## Checking with the haversine formula

Check search results with an independent formula using neither unit vectors nor KD trees.
Using the haversine function $\operatorname{hav}\theta = \sin^2(\theta/2)$, the spherical cosine law becomes the haversine formula:

$$
\operatorname{hav}\theta = \operatorname{hav}(\delta_2 - \delta_1) + \cos\delta_1\cos\delta_2\,\operatorname{hav}(\alpha_2 - \alpha_1), \qquad
\theta = 2\arcsin\sqrt{\operatorname{hav}\theta}
$$

The right side uses differences $\delta_2 - \delta_1$ and $\alpha_2 - \alpha_1$ directly, avoiding cancellation even at small angular distances.
Near antipodes where $\sqrt{\operatorname{hav}\theta}$ approaches 1, $\arcsin$ becomes ill-conditioned, but this example's radii (at most 60°) avoid that issue.

## Star catalog

The catalog contains 29 stars brighter than V magnitude 1.7 plus Polaris, totaling 30.
Coordinates are ICRS values at epoch J2000.0 from SIMBAD (mainly the Hipparcos new reduction, van Leeuwen 2007), rounded to three decimal places in degrees.
Rounding errors in right ascension and declination each lie within $\pm 0.0005°$ (about 1.8″).
This greatly exceeds the angular-distance differences compared in the check (around $10^{-16}$ rad), but both formulas use the same rounded coordinates, leaving the check unaffected.
Stars are ordered by increasing V magnitude (brightest first); later cells use the first $N$.
Alpha Centauri's position in the list uses combined A+B magnitude (−0.27), while coordinates use the brighter component A.
It therefore precedes Arcturus (−0.05), which is brighter than A alone (0.01).

The following block defines quantities shared by two cells.
`CATALOG` is the catalog, `unit_vector` gives $\boldsymbol{u}(\alpha, \delta)$, `catalog_coordinates` arranges unit-vector coordinates for the first $N$ stars, and `haversine_angle` implements the haversine formula.
`haversine_angle` supplies verification references computed with standard `f64` functions.

/// Construct unit vector u = (cos δ cos α, cos δ sin α, sin δ) from right ascension and declination [deg].
pub(crate) fn unit_vector(ra_deg: f64, dec_deg: f64) -> [f64; 3] {
    let (sin_a, cos_a) = RealScalar::sin_cos(RealScalar::to_radians(ra_deg));
    let (sin_d, cos_d) = RealScalar::sin_cos(RealScalar::to_radians(dec_deg));
    [cos_d * cos_a, cos_d * sin_a, sin_d]
}

/// Arrange the first n unit vectors in row-major order, one (x, y, z) per row.
pub(crate) fn catalog_coordinates(n: usize) -> Vec<f64> {
    CATALOG[..n]
        .iter()
        .flat_map(|&(_, ra, dec)| unit_vector(ra, dec))
        .collect()
}

/// Haversine angular distance [rad]. Verification reference (standard f64 functions).
pub(crate) fn haversine_angle(a: (f64, f64), b: (f64, f64)) -> f64 {
    let (ra1, dec1) = (a.0.to_radians(), a.1.to_radians());
    let (ra2, dec2) = (b.0.to_radians(), b.1.to_radians());
    let hav_dec = (0.5 * (dec2 - dec1)).sin().powi(2);
    let hav_ra = (0.5 * (ra2 - ra1)).sin().powi(2);
    let hav = hav_dec + dec1.cos() * dec2.cos() * hav_ra;
    2.0 * hav.sqrt().min(1.0).asin()
}
```

## Angular-distance radius search

The next cell selects a central star and angular radius $\theta_0$ [deg], finding stars within angular distance $\theta_0$ among all 30.
Construct the KD tree on 30 unit vectors and call `radius_into` with radius $c_0 = 2\sin(\theta_0/2)$.
`radius_into` writes found stars by increasing distance and returns their count.
Output `Neighbor::index` is the row index in the point set supplied to the KD tree, hence the catalog index.
`radius_into` gives `ResourceLimit` if more stars are found than output or workspace can hold; size both for all 30 stars.

The central star is found at distance 0 and omitted from tables and checks.
The first table shows each found star's angle recovered from its chord, haversine angle, difference, and chord length.
The second table compares the search count with an exhaustive haversine count among all 29 other stars satisfying $\theta \le \theta_0$.
Equal counts show that no qualifying star is omitted and no extra star included.

    .iter()
    .position(|&(name, _, _)| name == center_star)
    .ok_or("Central star absent from catalog")?;

    .workspace(SearchWorkspaceRequest::new(n, options))
    .map_err(|e| e.to_string())?;

    .radius_into(
        query,
        chord_radius,
        options,
        &mut found,
        &mut workspace,
        ExecutionContext::sequential(),

    .iter()
    .filter(|item| item.index != center)
    .map(|item| {

            name,
            RealScalar::to_degrees(from_chord),

    })

    { "key": "3", "label": "Difference [rad]", "type": "number", "format": sci2 },

]);
emit_table_with_columns!(
    neighbor_columns,
    rows.clone(),
    metadata = serde_json::json!({ "id": "neighbors" })
);
let summary_columns = serde_json::json!([
    { "key": "0", "label": "Chord radius c₀ [celestial-sphere radius]", "type": "number", "format": deg4 },
    { "key": "1", "label": "Stars found by search [count]", "type": "integer" },
    { "key": "2", "label": "Exhaustive stars with θ ≤ θ₀ [count]", "type": "integer" },

emit_table_with_columns!(

    .map(|item| item.index)

## Celestial spherical Voronoi diagram

For sites $\boldsymbol{u}_1, \ldots, \boldsymbol{u}_N$ on the unit sphere, define site $i$'s region by

$$
R_i = \{\boldsymbol{x} \in S^2 : \boldsymbol{x}\cdot\boldsymbol{u}_i \ge \boldsymbol{x}\cdot\boldsymbol{u}_j \ \text{for all}\ j\}
$$


Larger dot products mean smaller angular distances, so $R_i$ comprises points nearest to $\boldsymbol{u}_i$ in angular distance.
This spherical Voronoi diagram has spherical-polygon regions bounded by great-circle arcs.
Since the sky’s total area is $4\pi$ sr, region areas $A_i$ [sr] satisfy

$$
\sum_{i=1}^N A_i = 4\pi
$$


A region's area is the solid angle of directions in which that star is nearest; sparsely populated directions give larger regions.

`SphericalVoronoi::new` uses the fact that the convex hull of spherical sites is a spherical Delaunay triangulation.
Sphere points in the directions of outward hull-face normals are Voronoi vertices; region areas sum spherical-triangle solid angles formed by the site and consecutive vertices (Van Oosterom–Strackee formula).
Sites must lie on the sphere; if their center distance differs from radius $r$ by more than tolerance `Tolerance`'s threshold $\tau = \mathrm{atol} + \mathrm{rtol}\cdot r$, the result is `InvalidInput`.
Unit-vector length rounding errors are around $10^{-16}$, so the cell uses $\mathrm{atol} = 10^{-12}$ and $\mathrm{rtol} = 0$.

Like tessellations such as `Delaunay`, `SphericalVoronoi` sorts sites lexicographically and merges duplicates.
Indices of `areas()`, `region(site)`, and `neighbors(site)` are sorted-site canonical indices, not catalog indices.
Obtain input row $i$'s site index through `input_mapping()[i]`.
`SphericalVoronoi` has no `representatives()` mapping sites back to rows, so the cell maps each catalog row $i$ to its site through `input_mapping()[i]` before querying areas and regions.
Indexing `areas()` directly by catalog index reads another star's area.

## Region areas and largest and smallest regions

The next cell constructs a spherical Voronoi diagram from the first $N$ brightest catalog stars.
The first table sorts by decreasing area and shows each star's region area, fraction of sky, vertex count, and neighboring-region count.
The second table shows total area and relative error from $4\pi$, mean area $4\pi/N$, and stars with largest and smallest regions.

The last column independently checks index correspondence.
For each vertex $\boldsymbol{v}$ of star $i$'s region, compare its chord length to star $i$ with the smallest chord length to any of the $N$ stars, and show the largest difference.
The nearest stars to a Voronoi vertex (including ties) own regions containing it, so correct mappings give rounding-scale differences; wrong mappings produce much larger differences, as shown below.

let points = PointSet::from_rows(&coordinates, 3).map_err(|e| e.to_string())?;

    SphericalVoronoi::new(&points, [0.0; 3], 1.0, tolerance).map_err(|e| e.to_string())?;

// Map input row i (catalog index) to its canonical index before querying areas and regions.
let chord = |a: &[f64], b: &[f64]| -> f64 {
    let squared: f64 = a.iter().zip(b).map(|(x, y)| (x - y) * (x - y)).sum();
    RealScalar::sqrt(squared)
};
let mut rows = Vec::with_capacity(n);
let mut worst_violation = 0.0_f64;
for i in 0..n {
    let site = diagram.input_mapping()[i];
    let region = diagram.region(site).map_err(|e| e.to_string())?;
    let neighbors = diagram.neighbors(site).map_err(|e| e.to_string())?.count();
    // Mapping check: from region vertex v, star i is a nearest star (including ties).
    for &vertex in region {
        let v = &diagram.vertices()[3 * vertex..3 * vertex + 3];
        let own = chord(v, &coordinates[3 * i..3 * i + 3]);
        let nearest = coordinates
            .chunks_exact(3)
            .map(|u| chord(v, u))
            .fold(f64::INFINITY, f64::min);
        worst_violation = worst_violation.max(own - nearest);
    }
    let area = diagram.areas()[site];
    let share = 100.0 * area / (4.0 * core::f64::consts::PI);
    rows.push((CATALOG[i].0, area, share, region.len(), neighbors));
}
rows.sort_by(|a, b| b.1.total_cmp(&a.1));
let total: f64 = diagram.areas().iter().sum();
let four_pi = 4.0 * core::f64::consts::PI;

let fixed4 = serde_json::json!({ "fractionDigits": 4 });
let fixed2 = serde_json::json!({ "fractionDigits": 2 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let region_columns = serde_json::json!([
    { "key": "0", "label": "Star" },
    { "key": "1", "label": "Area A [sr]", "type": "number", "format": fixed4 },
    { "key": "2", "label": "Fraction of sky [%]", "type": "number", "format": fixed2 },
    { "key": "3", "label": "Vertices [count]", "type": "integer" },
    { "key": "4", "label": "Neighboring regions [count]", "type": "integer" }
]);
emit_table_with_columns!(
    region_columns,
    rows.clone(),
    metadata = serde_json::json!({ "id": "regions" })
);
let summary_columns = serde_json::json!([
    { "key": "0", "label": "Star count N [count]", "type": "integer" },
    { "key": "1", "label": "ΣA [sr]", "type": "number", "format": { "significantDigits": 15 } },
    { "key": "2", "label": "|ΣA − 4π| / 4π [-]", "type": "number", "format": sci2 },
    { "key": "3", "label": "Mean 4π/N [sr]", "type": "number", "format": fixed4 },
    { "key": "4", "label": "Largest region" },
    { "key": "5", "label": "Smallest region" },
    { "key": "6", "label": "Largest vertex-distance difference [celestial-sphere radius]", "type": "number", "format": sci2 }
]);
let summary = (
    n,
    total,
    (total - four_pi).abs() / four_pi,
    four_pi / n as f64,
    rows[0].0,
    rows[n - 1].0,
    worst_violation,
);
emit_table_with_columns!(
    summary_columns,
    vec![summary],
    metadata = serde_json::json!({ "id": "areas" })
);
```

With default $N = 30$, total area differs from $4\pi$ by relative error $2.8\times10^{-16}$, showing no systematic gaps or overlaps in area computation.
Against mean area $4\pi/30 = 0.4189$ sr, Fomalhaut has the largest region, 1.1350 sr (9.03% of the sky), and Mimosa the smallest, 0.0158 sr (0.13%), a ratio around 72.
Fomalhaut's nearest catalog star is Achernar, 39.1° away.
Within 10° of Mimosa are Gacrux (3.37°), Acrux (4.24°), and Hadar (9.50°).
Both angular-distance observations can be checked by choosing the central star in the search cell.
The largest vertex-distance difference is $1.5\times10^{-15}$, confirming correct index correspondence.
Querying `region(i)` and `areas()[i]` directly with catalog index $i$ without `input_mapping()` instead gives difference 1.83, falsely labeling Polaris largest and Vega smallest.

At “N = 4,” Sirius, Canopus, Alpha Centauri A, and Arcturus form a tetrahedron, and every region is a three-vertex spherical triangle.
Areas range from 2.06 to 4.41 sr, but their sum agrees with $4\pi$ to relative error $7.1\times10^{-16}$.

## Summary

Stars within celestial angular distance $\theta_0$ can be retrieved without omissions or extras by a KD-tree query on unit vectors with chord radius $c_0 = 2\sin(\theta_0/2)$.
Recover found stars' angular distances using $2\arcsin(c/2)$, avoiding $\arccos$, which loses accuracy for small angles.
Compare both counts and angular distances with exhaustive haversine evaluation independent of unit vectors; differences were on the double-precision rounding scale.
Areas from `SphericalVoronoi` sum to $4\pi$ at the $10^{-16}$ scale, with larger regions in sparsely populated sky directions.
Indices of `areas()` and `region()` are canonical, so map input rows through `input_mapping()` before access.
