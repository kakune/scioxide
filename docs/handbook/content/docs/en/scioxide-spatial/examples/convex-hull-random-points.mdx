How many vertices does the convex hull of $n$ uniform planar points have?
The answer depends strongly on boundary shape, growing proportionally to $\ln n$ for polygons and $n^{1/3}$ for smooth convex regions.
Vertex count is the hull algorithm's output-point count and affects the complexity of output-sensitive algorithms.
This example constructs hulls of uniform square and disk points with `ConvexHull` and compares mean vertex counts with Rényi–Sulanke formulas.

## Expected convex-hull vertex count

Place $n$ independent uniform points in convex region $K$ (area $A(K)$) and let $V_n$ be the vertex count of their hull $P_n$.
Rényi and Sulanke (1963, 1964) derived asymptotic forms of expectation $E[V_n]$ by boundary shape.

For a convex polygon $K$ with $r$ vertices,

$$
E[V_n] = \frac{2r}{3}\left(\ln n + \gamma\right) + \frac{2}{3}\sum_{i=1}^{r} \ln\frac{A(T_i)}{A(K)} + o(1)
$$

the expectation satisfies this formula.
$\gamma = 0.5772\ldots$ is Euler's constant; $T_i$ is the triangle joining three consecutive polygon vertices $v_{i-1}, v_i, v_{i+1}$.
Hull vertices cluster near polygon corners, increasing by $\tfrac{2}{3}\ln n$ per corner.
For the unit square, $r = 4$ and $A(T_i)/A(K) = 1/2$ give

$$
E[V_n] = \frac{8}{3}\left(\ln n + \gamma - \ln 2\right) + o(1)
$$

which yields $14.90$ at $n = 300$.

For $K$ with smooth boundary of curvature $\kappa > 0$,

$$
E[V_n] \sim \left(\frac{2}{3A(K)}\right)^{1/3} \Gamma\!\left(\tfrac{5}{3}\right) \left(\int_{\partial K} \kappa^{1/3}\,ds\right) n^{1/3}
$$

the expectation satisfies this asymptotic formula.
$s$ is arc length along boundary $\partial K$.
For the unit disk, $\kappa = 1$, $\int ds = 2\pi$, and $A(K) = \pi$ give coefficient $2\pi^{2/3}(2/3)^{1/3}\Gamma(5/3) = 3.3832$.
This formula gives only the leading term.
The next term becomes relatively smaller as $n$ grows, but decreases slowly.
With cell defaults below, measured means fall below the leading term for every $n$ through $n = 2000$.
The square formula also contains an $o(1)$ error, slightly differing from measurements at small $n$.

The following block defines formulas shared by the two comparison cells.
`square_formula` returns unit-square $\tfrac83(\ln n + \gamma - \ln 2)$, and `disk_leading_term` returns unit-disk leading term $3.3832\,n^{1/3}$.
$\Gamma(5/3)$ and $\gamma$ use 16-digit constants.

```rust
//| id: spatial-convex-hull-formulas
//| kind: definitions
//| title: "Rényi–Sulanke formulas"
//| crates: [scioxide-core]
use scioxide_core::RealScalar;

/// Euler's constant γ.
pub(crate) const EULER_GAMMA: f64 = 0.577_215_664_901_532_9;

/// Γ(5/3).
pub(crate) const GAMMA_FIVE_THIRDS: f64 = 0.902_745_292_950_933_6;

/// Unit-disk leading coefficient 2π^(2/3) (2/3)^(1/3) Γ(5/3).
pub(crate) fn disk_coefficient() -> f64 {
    let pi = core::f64::consts::PI;
    2.0 * RealScalar::powf(pi, 2.0 / 3.0) * RealScalar::cbrt(2.0 / 3.0) * GAMMA_FIVE_THIRDS
}

/// Unit-square E[V_n] ≈ (8/3)(ln n + γ − ln 2).
pub(crate) fn square_formula(n: f64) -> f64 {
    8.0 / 3.0 * (RealScalar::ln(n) + EULER_GAMMA - RealScalar::ln(2.0))
}

/// Unit-disk leading term for E[V_n]: 3.3832 n^(1/3).
pub(crate) fn disk_leading_term(n: f64) -> f64 {
    disk_coefficient() * RealScalar::cbrt(n)
}
```

## Counting vertices and construction work

`ConvexHull::new` constructs hulls by randomized incremental construction.
A hull's boundary edges (faces in three or more dimensions) are called facets.
Each point insertion finds and removes visible facets using exact orientation tests as in `orient2d`, then rebuilds the boundary.
Insertion order uses fixed pseudorandom values derived from point indices after lexicographic coordinate sorting.
Results therefore remain identical across runs and independent of input-row order.
Clarkson and Shor's (1989) analysis gives planar expected complexity $O(n\log n)$.

In two dimensions, facet (edge) count equals vertex count, so count vertices with `facet_count()`.
`provenance().predicate_terms` returns predicate work evaluated during construction.
Each sign evaluation counts one work unit; exact evaluation after an inconclusive floating-point filter adds determinant-expansion terms.
[Recovering a convex hull's boundary and missing area](../convex-hull-perimeter/) covers boundary ordering and point-index/input-row mappings.

## Mean vertex counts and sample size

The next cell increases point count $n$ from 10 to its limit in 1–2–5 steps, constructing $M$ hulls per $n$ and region and counting vertices.
For square $[0, 1)^2$, use uniform coordinates $u, v$ on $[0, 1)$ directly.
For the unit disk, radius $\sqrt{u}$ and angle $2\pi v$ give density proportional to area.
Draw random values directly from generator `SplitMix64` through `Rng::next_float`; changing the seed gives independent samples.
For each $n$, the table shows mean and standard error of vertex counts in both regions (sample standard deviation $/\sqrt{M}$ over $M$ replicates), and predicate work per point.
Even defaults construct tens of thousands of hulls, so execution uses a button and caches results for identical inputs.
Means and standard errors are passed to the two later cells.

```rust
//| id: spatial-convex-hull-renyi-sulanke
//| ref: spatial-convex-hull-renyi-sulanke
//| title: "Count hull vertices for each point count"
//| run: button
//| cache: inputs
//| crates: [scioxide-core, scioxide-random, scioxide-spatial]
//| exports: [square, disk]
//| inputs:
//|   largest: {"type":"range","label":"Maximum point count [count]","min":1000,"max":10000,"step":1000,"value":5000}
//|   replicates: {"type":"range","label":"Replicate count M per n","min":10,"max":200,"step":10,"value":100}
//|   seed: {"type":"range","label":"Random seed","min":1,"max":100,"step":1,"value":1}
//| cases:
//|   - {"id":"largest-1000","label":"Limit 1000 points","description":"Seven rows through n = 1000 use the same seeded random sequence, preserving each row's default-table values.","inputs":{"largest":1000}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"sweep","path":"/rows/8/0","equals":5000}
//|       - {"artifact":"sweep","path":"/rows/4/1","approx":{"value":13.91,"atol":1e-9}}
//|       - {"artifact":"sweep","path":"/rows/8/3","approx":{"value":57.88,"atol":1e-9}}
//|       - {"artifact":"sweep","path":"/rows/8/5","range":{"min":5,"max":12}}
//|   - case: largest-1000
//|     expect:
//|       - {"artifact":"sweep","path":"/rowCount","equals":7}
//|       - {"artifact":"sweep","path":"/rows/6/1","approx":{"value":18.33,"atol":1e-9}}
use scioxide_core::{SciOxideError, RealScalar};
use scioxide_random::{Rng, SeedableRng, SplitMix64};
use scioxide_spatial::{ConvexHull, PointSet};

// Write n uniform points in (x, y) order in the unit disk if region is "disk", otherwise in the unit square.
fn region_points(
    region: &str,
    n: usize,
    rng: &mut SplitMix64,
    coordinates: &mut Vec<f64>,
) -> Result<(), SciOxideError> {
    coordinates.clear();
    for _ in 0..n {
        let (u, v): (f64, f64) = (rng.next_float()?, rng.next_float()?);
        if region == "disk" {
            let (radius, angle) = (RealScalar::sqrt(u), 2.0 * core::f64::consts::PI * v);
            coordinates.push(radius * RealScalar::cos(angle));
            coordinates.push(radius * RealScalar::sin(angle));
        } else {
            coordinates.push(u);
            coordinates.push(v);
        }
    }
    Ok(())
}

let m = replicates as usize;
let sizes = [10, 20, 50, 100, 200, 500, 1000, 2000, 5000, 10000];
let mut rng = SplitMix64::from_seed(seed as u64);
let mut coordinates = Vec::new();
// Collect [n, mean, standard error, predicate work per point] for each region.
let (mut square, mut disk) = (Vec::new(), Vec::new());
for n in sizes.into_iter().filter(|&n| n as f64 <= largest) {
    for (region, summary) in [("square", &mut square), ("disk", &mut disk)] {
        let (mut counts, mut work) = (Vec::with_capacity(m), 0.0);
        for _ in 0..m {
            region_points(region, n, &mut rng, &mut coordinates).map_err(|e| e.to_string())?;
            let points = PointSet::from_rows(&coordinates, 2).map_err(|e| e.to_string())?;
            let hull = ConvexHull::new(&points).map_err(|e| e.to_string())?;
            // In two dimensions, facet (edge) count equals vertex count.
            counts.push(hull.facet_count() as f64);
            work += hull.provenance().predicate_terms as f64 / n as f64;
        }
        let mean = counts.iter().sum::<f64>() / m as f64;
        let variance =
            counts.iter().map(|v| (v - mean) * (v - mean)).sum::<f64>() / (m - 1) as f64;
        let se = RealScalar::sqrt(variance / m as f64);
        summary.push([n as f64, mean, se, work / m as f64]);
    }
}

let fixed1 = serde_json::json!({ "fractionDigits": 1 });
let fixed2 = serde_json::json!({ "fractionDigits": 2 });
let fixed3 = serde_json::json!({ "fractionDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "Point count n [count]", "type": "integer" },
    { "key": "1", "label": "Square mean vertices [count]", "type": "number", "format": fixed2 },
    { "key": "2", "label": "Square standard error [count]", "type": "number", "format": fixed3 },
    { "key": "3", "label": "Disk mean vertices [count]", "type": "number", "format": fixed2 },
    { "key": "4", "label": "Disk standard error [count]", "type": "number", "format": fixed3 },
    { "key": "5", "label": "Square work / point [work units]", "type": "number", "format": fixed1 },
    { "key": "6", "label": "Disk work / point [work units]", "type": "number", "format": fixed1 }
]);
let rows: Vec<(usize, f64, f64, f64, f64, f64, f64)> = square
    .iter()
    .zip(&disk)
    .map(|(s, d)| (s[0] as usize, s[1], s[2], d[1], d[2], s[3], d[3]))
    .collect();
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "sweep" })
);
export!(square, &square);
export!(disk, &disk);
```

With defaults (limit 5000 points, $M = 100$, seed 1), square mean vertex count increases from $5.92$ at $n = 10$ to $22.70$ at $n = 5000$.
Each tenfold increase in $n$ adds about six vertices, close to $\tfrac83\ln 10 = 6.14$.
The disk increases from $6.13$ to $57.88$, reaching 2.5 times the square's count at $n = 5000$.
Predicate work per point stays at 5–9 units independently of $n$, so construction work on uniform points is nearly proportional to $n$.

## Comparison with Rényi–Sulanke formulas

The next cell receives means and standard errors and compares them with Rényi–Sulanke formulas.
The horizontal axis is logarithmic point count $n$; measured means use symbols and formulas dashed lines.
The square formula is linear in $\ln n$ and thus straight on the logarithmic axis, while the disk leading term $3.3832\,n^{1/3}$ curves upward.
For each $n$, the table shows square $z = (\bar V - E[V_n])/\mathrm{SE}$ and the ratio of disk mean to leading term.
$\bar V$ is the mean over $M$ replicates; SE is its standard error.
Persistently large $|z|$ well above 2 across $n$ suggests a problem with the formula or counting.

//| title: "Compare mean vertex counts with Rényi–Sulanke formulas"

## Growth slopes

Besides pointwise comparisons, check growth coefficients themselves.
The next cell least-squares fits square means against $x = \ln n$ and disk means against $x = n^{1/3}$, comparing slopes with theoretical coefficients $8/3$ and $3.3832$.
Use only $n \ge 100$ to avoid $o(1)$ errors at small $n$.
Since slope $\hat\beta = \sum_k (x_k - \bar x)(\bar V_k - \overline{V}) / \sum_k (x_k - \bar x)^2$ is linear in means $\bar V_k$, propagate standard errors $\mathrm{SE}_k$ of each mean using $\bigl(\sum_k w_k^2\,\mathrm{SE}_k^2\bigr)^{1/2}$ and $w_k = (x_k - \bar x)/\sum_j (x_j - \bar x)^2$.
Do not report a slope with fewer than three $n \ge 100$ points.

```rust
//| id: spatial-convex-hull-slopes
//| ref: spatial-convex-hull-slopes
//| title: "Compare vertex-count growth slopes with theoretical coefficients"
//| run: reactive
//| uses: [spatial-convex-hull-formulas]
//| crates: [scioxide-core]
//| dependsOn:
//|   sweep: spatial-convex-hull-renyi-sulanke
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"slopes","path":"/rows/0/1","range":{"min":2.4,"max":2.95}}
//|       - {"artifact":"slopes","path":"/rows/0/3","approx":{"value":2.666666666667,"rtol":1e-10}}
//|       - {"artifact":"slopes","path":"/rows/1/1","range":{"min":3.38,"max":3.5}}
//|       - {"artifact":"slopes","path":"/rows/1/3","approx":{"value":3.383228965797,"rtol":1e-10}}
use scioxide_core::RealScalar;

let square: Vec<[f64; 4]> =
    serde_json::from_value(sweep["square"].clone()).map_err(|e| e.to_string())?;
let disk: Vec<[f64; 4]> =
    serde_json::from_value(sweep["disk"].clone()).map_err(|e| e.to_string())?;

// Least-squares slope fitting n ≥ 100 means against x, and slope standard error propagated from mean standard errors.
let slope = |rows: &[[f64; 4]], x: fn(f64) -> f64| -> (Option<f64>, Option<f64>) {
    let used: Vec<[f64; 3]> = rows
        .iter()
        .filter(|r| r[0] >= 100.0)
        .map(|r| [x(r[0]), r[1], r[2]])
        .collect();
    if used.len() < 3 {
        return (None, None);
    }
    let k = used.len() as f64;
    let (mx, my) = used
        .iter()
        .fold((0.0, 0.0), |(a, b), r| (a + r[0] / k, b + r[1] / k));
    let sxx: f64 = used.iter().map(|r| (r[0] - mx) * (r[0] - mx)).sum();
    let sxy: f64 = used.iter().map(|r| (r[0] - mx) * (r[1] - my)).sum();
    let variance: f64 = used
        .iter()
        .map(|r| ((r[0] - mx) / sxx) * ((r[0] - mx) / sxx) * r[2] * r[2])
        .sum();
    (Some(sxy / sxx), Some(RealScalar::sqrt(variance)))
};
let (square_slope, square_se) = slope(&square, RealScalar::ln);
let (disk_slope, disk_se) = slope(&disk, RealScalar::cbrt);
let fits = vec![
    (
        "Square: slope against ln n",
        square_slope,
        square_se,
        8.0 / 3.0,
    ),
    (
        "Disk: slope against n^(1/3)",
        disk_slope,
        disk_se,
        disk_coefficient(),
    ),
];
let fixed4 = serde_json::json!({ "fractionDigits": 4 });
let fit_columns = serde_json::json!([
    { "key": "0", "label": "Fit" },
    { "key": "1", "label": "Measured slope [count]", "type": "number", "format": fixed4, "nullText": "Insufficient points" },
    { "key": "2", "label": "Slope standard error [count]", "type": "number", "format": fixed4, "nullText": "—" },
    { "key": "3", "label": "Theoretical coefficient [count]", "type": "number", "format": fixed4 }
]);
emit_table_with_columns!(
    fit_columns,
    fits,
    metadata = serde_json::json!({ "id": "slopes" })
);
```

The square slope is $2.72 \pm 0.08$, agreeing with theoretical $8/3$ within standard error.
The disk slope $3.437 \pm 0.029$ exceeds coefficient $3.3832$ by 1.8 standard errors.
Disk means are below the leading term, with the gap shrinking from 0.87 at $n = 200$ to −0.03 at $n = 5000$ as $n$ increases, making the slope against $n^{1/3}$ larger than the coefficient.
Account for bias from this next term when checking coefficients through slopes.

## Summary

Uniform-square hull vertex counts grow as $\tfrac83(\ln n + \gamma - \ln 2)$, averaging only about 23 even at $n = 5000$.
For the disk, counts grow as $3.3832\,n^{1/3}$; this leading term exceeds measured means over $n = 100$–$2000$ by 0.8–4.6%.
Before estimating vertex-proportional postprocessing costs (boundary traversal or containment tests), determine whether the region's boundary is polygonal or smooth.
Assess expected-value comparisons with replicated means' standard errors and $z$; slope comparisons must also account for next-term bias.
Count two-dimensional hull vertices with `facet_count()`; `provenance().predicate_terms` shows that construction work on uniform points is nearly proportional to $n$.
