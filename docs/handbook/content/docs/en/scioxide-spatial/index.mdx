`scioxide-spatial` is a computational geometry crate for points and shapes in space.
Its problems fall into the following five categories.

| Area | Questions answered | Main types and functions |
|---|---|---|
| Grids, meshes, and fields | How are structured grids and simplex meshes connected, and to which mesh revision (a new mesh created by each change) does a field belong? | `StructuredGrid`, `CellMesh`, `TriangleMesh`, `Field`, `MeshToken` |
| Distances and neighbor search | What is the distance between points, which points are close to a query point, and how far apart are two point sets? | `PointSet`, `distance`, `pairwise`, `PreparedDistance`, `directed_hausdorff`, `KdTree` |
| Geometric predicates and tessellation | What is the orientation of three points, is a point inside or outside a circle, and what are the convex hull, Delaunay tessellation, Voronoi diagram, or halfspace intersection? | `orient2d`, `incircle`, `ConvexHull`, `Delaunay`, `Voronoi`, `SphericalVoronoi`, `HalfspaceIntersection` |
| Rotations and rigid transformations | How can orientations be represented and interpolated, and which rigid transformation can be estimated from corresponding points? | `Rotation`, `Slerp`, `RotationSpline`, `RigidTransform`, `estimate_rigid_transform` |
| Adaptive meshes | Which cells should be refined or coarsened, and how do cells correspond before and after refinement? | `AdaptiveMesh`, `TopologyMap`, `MeshPartition` |

Grid, mesh, and field types also provide geometric representations for partial differential equations (`scioxide-pde`), while point sets, KD trees, Delaunay tessellations, and predicates are also used for scattered-data interpolation (`scioxide-interp`).
This crate handles coordinates and topology; users perform computations such as field-transfer formulas and weak forms.

## First computation

Find the two water stations nearest a location among five stations in a plane [km].
Place one point per row in a rank-two view `PointSet` and build a Euclidean-distance KD-tree index with `KdTree::new`.
Reserve the search workspace in advance; `nearest_into` writes results to the caller's array.
The input is the location's coordinates $(x, y)$ [km]; the output gives the indices, coordinates, and distances of the two stations in order of proximity.

```rust
//| id: spatial-first-nearest
//| ref: spatial-first-nearest
//| title: "Find the nearest water stations with a KD tree"
//| run: reactive
//| crates: [scioxide-core, scioxide-spatial]
//| inputs:
//|   query_x: {"type":"range","label":"Location x [km]","min":0,"max":10,"step":0.5,"value":4}
//|   query_y: {"type":"range","label":"Location y [km]","min":0,"max":10,"step":0.5,"value":6}
//| cases:
//|   - {"id":"corner","label":"Location (10, 0) km","description":"At the lower-right corner, station 1 at (8, 2) is nearest.","inputs":{"query_x":10,"query_y":0}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"nearest","path":"/rows/0/1","equals":2}
//|       - {"artifact":"nearest","path":"/rows/1/1","equals":4}
//|       - {"artifact":"nearest","path":"/rows/0/4","approx":{"value":1.4142135623730951,"rtol":1e-15}}
//|       - {"artifact":"nearest","path":"/rows/1/4","approx":{"value":1.4142135623730951,"rtol":1e-15}}
//|   - case: corner
//|     expect:
//|       - {"artifact":"nearest","path":"/rows/0/1","equals":1}
//|       - {"artifact":"nearest","path":"/rows/0/4","approx":{"value":2.8284271247461903,"rtol":1e-15}}
use scioxide_core::{ExecutionContext, NdView, StridedLayout};
use scioxide_spatial::{KdTree, Neighbor, PointSet, SearchOptions, SearchWorkspaceRequest};

// Water station coordinates [km]. Each row is one station; columns are (x, y).
let sites = [1.0, 1.0, 8.0, 2.0, 3.0, 7.0, 9.0, 9.0, 5.0, 5.0];
let layout = StridedLayout::new(&[5, 2], &[2, 1]).map_err(|e| e.to_string())?;
let points = PointSet::new(NdView::new(&sites, layout).map_err(|e| e.to_string())?)
    .map_err(|e| e.to_string())?;
let tree = KdTree::new(&points).map_err(|e| e.to_string())?;

// Preparation: workspace for two neighbor candidates. Execution: write results to out.
let options = SearchOptions::new();
let mut workspace = tree
    .workspace(SearchWorkspaceRequest::new(2, options))
    .map_err(|e| e.to_string())?;
let mut out = [Neighbor::default(); 2];
let found = tree
    .nearest_into(
        &[query_x, query_y],
        2,
        options,
        &mut out,
        &mut workspace,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;
let rows: Vec<(usize, usize, f64, f64, f64)> = out[..found]
    .iter()
    .enumerate()
    .map(|(rank, v)| {
        let (x, y) = (sites[2 * v.index], sites[2 * v.index + 1]);
        (rank + 1, v.index, x, y, v.distance)
    })
    .collect();
let fixed1 = serde_json::json!({ "fractionDigits": 1 });
let fixed4 = serde_json::json!({ "fractionDigits": 4 });
let columns = serde_json::json!([
    { "key": "0", "label": "Rank", "type": "integer" },
    { "key": "1", "label": "Water station index", "type": "integer" },
    { "key": "2", "label": "x [km]", "type": "number", "format": fixed1 },
    { "key": "3", "label": "y [km]", "type": "number", "format": fixed1 },
    { "key": "4", "label": "Distance [km]", "type": "number", "format": fixed4 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "nearest" })
);
```

## Interpreting results

Each table row is a `Neighbor` value.
`index` is the input row index (starting at 0), rather than the tree's internal order.
`distance` is the tree's distance, here the Euclidean distance [km].
Results are ordered by increasing distance, with smaller indices first when rounded distances are equal.

The return value `found` is the number written, which is smaller than $k$ if fewer than $k$ points exist.
Missing entries are not filled with sentinel values.
At the default location $(4, 6)$ km, station 2 at $(3, 7)$ and station 4 at $(5, 5)$ are both $\sqrt{2} \approx 1.414$ km away, so the smaller index, 2, comes first.

If a coordinate is NaN or infinite, `PointSet::new` returns a `NonFinite` error.
A query dimension different from the tree's, a short output array, or insufficient reserved workspace produces `DimensionMismatch`; NaN or infinity in the query point produces `NonFinite`; neither case changes the output array.

## Summary

`scioxide-spatial` handles grids, meshes and fields, distances and neighbor searches, geometric predicates and tessellation, rotations and rigid transformations, and adaptive meshes.
A point cloud can be checked for finite coordinates once with `PointSet`, then the same view can be passed to distances, searches, tessellations, and batch rigid transformations.
Neighbor-search results return input row indices and distances, with smaller indices first for equal distances.
Combinatorial decisions use exact signs, while constructed quantities such as circumcenters and areas include rounding.
Go to [Choosing a method](choosing/) to select a method for a task, or read from item 1 in the chapter structure to examine each method's assumptions and errors.
