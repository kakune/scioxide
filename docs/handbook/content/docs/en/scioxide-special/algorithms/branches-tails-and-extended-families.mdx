For special functions, mathematically equivalent formulas need not have the same floating-point accuracy.
Computing $1 - F(x)$ after $F(x)$ has rounded to 1 makes a small tail probability zero.
In analytic continuation to complex arguments, the same formula can give different values on opposite sides of a branch cut.

This page explains four conventions shared by all function families: real and complex APIs, branch cuts and the choice of side, value representations and termination status in detailed results, and tail-probability representations.
It ends with a table of each family's APIs and representations, linking to the corresponding mathematical pages.

## Real and complex APIs

Functions use two kinds of type parameters.
Functions taking `RealScalar` accept only `f32` and `f64`; functions taking `NumericScalar` also accept `Complex<f32>` and `Complex<f64>` to evaluate analytic continuations.
In both cases, the argument type determines the result type.
Kelvin functions, Fermi–Dirac integrals, normal-distribution functions, and angular momentum coefficients accept only real numbers; Bessel, gamma, error, hypergeometric, and polylogarithm functions also accept complex numbers.
`faddeeva`, `lambert_w_complex`, and `parabolic_d_complex` accept only complex arguments, while `spherical_harmonic` and `voigt_complex` return complex values from real arguments.

Quantities whose roles differ from the argument, such as orders, shapes, and parameters, are accepted through `Parameter`.
`Parameter<T>` is implemented for the argument type `T` itself, and for the real type `R` when `T` is `Complex<R>`.
A real parameter is treated as a complex number with imaginary part $+0$ and gives a result bitwise identical to passing that complex number.
For example, `bessel_j(2.5, z)` evaluates $J_{2.5}(z)$ at complex `z`.
Conversely, complex parameters require a complex argument, so `bessel_j(Complex::new(0.5, 0.25), 1.0)` does not compile.
`Parameter` is a sealed trait with no public methods.

Real APIs retain their real domains and conventions.
Passing a negative real argument to `bessel_j` of noninteger order gives `DomainError` (`OutsideDomain`); for integer order it returns the value determined by the parity relation $J_n(-x) = (-1)^n J_n(x)$.
At $x < 0$, `expint_e1` returns the principal value $-\operatorname{Ei}(-x)$, the real part on either side of the cut, rather than a complex number.
`dilog` returns the real part of the principal value for real $x > 1$; `polylog` accepts real $z > 1$ only for order $s = 2$ and nonpositive integer orders.
To obtain a complex value on a cut, switch to the complex API and choose a side.

Scalar functions have no form that accepts an entire array.
Evaluate multiple points using an expression such as `iter().map(|&x| erf(x)).collect::<Result<Vec<_>, _>>()`.
Only a few forms return sequences of consecutive orders, such as `coulomb_wave_sequence` for Coulomb wave functions.

### Exact integers and generalized binomial coefficients

Two functions provide exact integers or rational numbers instead of floating-point values.
`checked_bernoulli(n)` returns the Bernoulli number $B_n$ as the reduced fraction `(numerator, denominator)`.
Its convention is $t/(e^t - 1) = \sum_n B_n t^n/n!$, giving $B_1 = -1/2$; it returns tabulated values for even $n \le 34$ and $n = 38$.
The numerator of $B_{36}$ does not fit in 64 bits, so $n = 36$ and even $n > 38$ give `SizeOverflow`.
`checked_euler(n)` returns the Euler number $E_n$ in the convention $\operatorname{sech} t = \sum_n E_n t^n/n!$ as an integer and accepts even $n \le 22$.
For odd orders, `checked_euler` returns `0`, and `checked_bernoulli` returns `(0, 1)` except for `(-1, 2)` at $B_1$.
`bernoulli` and `euler` return floating-point values for arbitrary orders.
`checked_factorial` and `checked_binomial` in `scioxide-core` return exact integer factorials and binomial coefficients.

`generalized_binomial(z, k)` returns the binomial coefficient $C(z, k) = z(z-1)\cdots(z-k+1)/k!$ for real or complex $z$ and integer $k \ge 0$.
$C(z, k)$ is a polynomial of degree $k$ in $z$, so it has neither poles nor branch cuts.
The numerator product tracks its power-of-two exponent separately, avoiding overflow before the single division by $k!$.
Its work is proportional to $k$, so it has an options form `generalized_binomial_with_options` and a scoped API `generalized_binomial_scoped`; $k$ exceeding the work budget gives `ConvergenceFailure`.
There is no uniform ULP target; inspect the estimated error in the options form.

## Branch cuts and signed zero

Functions involving logarithms, square roots, or noninteger powers are multivalued in the complex plane.
To obtain a single-valued function, introduce a cut in the plane (a branch cut) and choose a continuous branch (the principal branch) on the plane with the cut removed.
In `scioxide-special`, functions derived from logarithms have their cut on the negative real axis $(-\infty, 0]$; other functions follow the conventional DLMF cuts.

At points on a cut, the signed zero of the imaginary part selects the side.
An imaginary part of $+0$ returns the value on the upper side, and $-0$ returns the value on the lower side.
For real coefficients, the values on the two sides are complex conjugates.

| Function | Cut |
|---|---|
| `bessel_y`, `bessel_k`, `hankel_1`, `hankel_2`, `ln_gamma`, `hyperu` | $(-\infty, 0]$ |
| `bessel_j`, `bessel_i` (noninteger orders; entire for integer orders) | $(-\infty, 0]$ |
| `gamma_p`, `gamma_q` (principal powers of $z^a$) | $(-\infty, 0]$ |
| `beta_inc` | $(-\infty, 0]$ and $[1, \infty)$ |
| `hyp2f1`, `polylog`, `dilog`, `lerch_phi` | $[1, \infty)$ |
| `lambert_w_complex` | $(-\infty, -1/e]$ for branch 0; $(-\infty, 0]$ for other branches |
| `wright_omega` | Two rays $\operatorname{Im} z = \pm\pi$, $\operatorname{Re} z \le -1$ |
| `log_erfc` | Points where $\operatorname{erfc}(z)$ lies on the negative real axis |
| `gamma`, `riemann_zeta`, `hyp1f1`, `faddeeva`, `generalized_binomial` | None (meromorphic or entire) |

Lambert W selects the branch of the multivalued function itself by number.
Real `lambert_w0` ($W \ge -1$, $x \ge -1/e$) and `lambert_wm1` ($W \le -1$, $-1/e \le x < 0$) are separate functions; complex `lambert_w_complex(z, branch)` takes a branch number using the convention of Corless et al.
At rounded $-1/e$, both real branches return exact $-1$, while the immediately smaller representable number gives `DomainError` (`OutsideDomain`).
See [Lambert W and Wright omega functions](../lambert-w-and-wright-omega/) for details.

The next cell uses noninteger order $\nu$ to compare $J_\nu$ at the point $z = -x \pm 0\mathrm{i}$ on the cut with the connection formula $J_\nu(x e^{\pm\mathrm{i}\pi}) = e^{\pm\mathrm{i}\pi\nu} J_\nu(x)$.
Evaluate $J_\nu(x)$ on the right using the real API and multiply by the phase $e^{\pm\mathrm{i}\pi\nu}$.
It also checks $H_\nu^{(1)} = J_\nu + \mathrm{i}Y_\nu$ at $z = x + \mathrm{i}$ away from the cut.
The second table shows the result of passing $\pm x$ to the real API at the same $x$.

For the defaults $\nu = 1/2$ and $x = 3$, $J_{1/2}(z) = \sqrt{2/(\pi z)}\sin z$ gives the two side values $\pm\mathrm{i}\sqrt{2/(3\pi)}\sin 3 \approx \pm 0.0650\mathrm{i}$, which are complex conjugates.
The real part of the value from `scioxide-special` is exactly 0; the comparison real part $4 \times 10^{-18}$ is phase error from rounding $\cos(\pi/2)$.
Passing $-x$ to the real API gives `DomainError`.
For integer $\nu$, $e^{\pm\mathrm{i}\pi\nu} = (-1)^\nu$ makes the two sides agree, and the real API also returns the value given by $J_n(-x) = (-1)^n J_n(x)$.
Varying the order in steps of 0.25 and the distance in steps of 0.5 over their full ranges gives differences of at most $6 \times 10^{-16}$ from the connection formula and $2 \times 10^{-15}$ from the Hankel identity.
Complex Bessel functions have no uniform ULP target, so these differences show consistency between two paths, rather than bounds on error from the true value.

## Value representations and termination status

Options forms `*_with_options` and scoped APIs `*_scoped` return `SpecialFunctionResult`.
This type separates the results of a single evaluation through the following accessors.

| Accessor | Quantity returned |
|---|---|
| `value()` | Ordinary value and estimated error. `None` on overflow; $\pm\infty$ for documented limits |
| `scaled()` | Each component separated into a significand and a power-of-two exponent. Retained even on overflow |
| `logarithmic()` | Phase (sign for real numbers) and natural logarithm of the magnitude. Omitted when relative error reaches $1/2$ |
| `derivative()` | Derivative with respect to the argument. `None` when the function does not compute it |
| `scalar_representation()` | Status of projection to the ordinary value, `ScalarRepresentation` |
| `termination()` | Termination status `SpecialFunctionTermination` |
| `algorithm()`, `counts()` | Algorithm identifier and work counts, including failed attempts |
| `try_value()`, `try_derivative()` | Ordinary value and derivative without estimated errors. Error if evaluation is incomplete or the value is absent |

Each representation is an `ValueWithError` with `value()` (or the ownership-transferring `into_value()`), `absolute_error()`, `relative_error()`, and the estimation basis `reliability()`.
The estimated error is not an interval enclosure; the three categories of estimation basis are explained in [Algorithms](oxref:special-algorithms-error-estimates).
The ordinary value in an options form is bitwise identical to the standard-form value.
`SpecialFunctionResult::zero()` constructs a result with exact zero and zero counts without computation, for initializing output arrays.

`ScalarRepresentation` describes projection to an ordinary value and has three variants: `Finite`, `Overflow`, and `InfiniteLimit`.
For `Overflow`, `value()` is `None`, but `scaled()` and `logarithmic()` retain values within their representable ranges.
When a true value is so small that it rounds to zero, the status is `Finite` and the standard form returns `Ok(±0)`.

`SpecialFunctionTermination` has four variants, `Exact`, `Converged`, `Limit`, and `IterationLimit`; `is_success()` is true for the first three.
`IterationLimit` indicates that the work budget was reached; the result contains the estimate obtained so far.
In this case, `try_value()` and the standard form return `ConvergenceFailure`.
If the budget is reached before a useful estimate is obtained, the options form also returns `ConvergenceFailure`, and the error contains the number of attempted iterations.
Termination status does not indicate whether the estimated error meets a requirement; assess accuracy from the estimated error.

Options contain a work budget `Budget`, changed with `with_iteration_budget`.
This budget does not specify the requested number of digits.
A scoped API `*_scoped(.., options, scope)` accepts `impl Into<SolveScope>`; passing `ExecutionContext` starts a new evaluation, while passing a parent's `&mut SolveContext` starts an evaluation within the parent solve.
The work is reported to the parent solve as nested counts, and the parent's cancellation and deadline also apply to the evaluation.

The next cell varies the work budget from 1 to 24 and evaluates three quantities with known values using the options forms.
The references are $\operatorname{Cl}_2(\pi/2) = G$ (Catalan's constant $0.9159655941772190\ldots$) for the Clausen function and $F_{1/2}(0) = (1 - 2^{-1/2})\,\zeta(3/2) = 0.7651470246254079\ldots$ for the Fermi–Dirac integral.
The reference for the Faddeeva function $w(1 + \mathrm{i}/2)$ is a manual sum of the Taylor series $w(z) = \sum_{n \ge 0} (\mathrm{i}z)^n/\Gamma(n/2 + 1)$ through 80 terms.
The table shows termination status, iteration count, estimation basis, estimated absolute error, and actual error against the reference for each budget; the outcome shows the termination status at the selected budget.

```rust
//| id: special-result-budget-termination
//| ref: special-result-budget-termination
//| title: "Vary the work budget and read termination status and estimated error"
//| run: reactive
//| crates: [scioxide-core, scioxide-special]
//| inputs:
//|   function: {"type":"select","label":"Quantity to evaluate","options":["Clausen Cl₂(π/2)","Fermi–Dirac F₁/₂(0)","Faddeeva w(1 + i/2)"],"value":"Clausen Cl₂(π/2)"}
//|   budget: {"type":"integer","label":"Budget used for the outcome","description":"Work budget (number of iterations). The table lists budgets from 1 to 24.","min":1,"max":24,"value":6}
//| cases:
//|   - {"id":"fermi","label":"Fermi–Dirac","description":"Insufficient Chebyshev terms give IterationLimit, and the estimated error includes truncation.","inputs":{"function":"Fermi–Dirac F₁/₂(0)","budget":24}}
//|   - {"id":"faddeeva","label":"Faddeeva","description":"The estimated error of a continued fraction stopped at the budget is Heuristic and excludes truncation error.","inputs":{"function":"Faddeeva w(1 + i/2)","budget":4}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"sweep","path":"/rows/0/1","equals":"IterationLimit"}
//|       - {"artifact":"sweep","path":"/rows/8/1","equals":"Converged"}
//|       - {"artifact":"sweep","path":"/rows/8/5","range":{"max":1e-15}}
//|       - {"artifact":"sweep","path":"/rows/3/5","range":{"min":1e-7,"max":1e-5}}
//|       - {"path":"/outputs/1/state","equals":"partial"}
//|   - case: fermi
//|     expect:
//|       - {"artifact":"sweep","path":"/rows/8/1","equals":"Converged"}
//|       - {"artifact":"sweep","path":"/rows/8/5","range":{"max":1e-15}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: faddeeva
//|     expect:
//|       - {"artifact":"sweep","path":"/rows/0/3","equals":"Heuristic"}
//|       - {"artifact":"sweep","path":"/rows/0/5","range":{"min":0.01}}
//|       - {"artifact":"sweep","path":"/rows/8/5","range":{"max":1e-15}}
//|       - {"path":"/outputs/1/state","equals":"partial"}
use scioxide_core::{Budget, Complex, NumericScalar};
use scioxide_special::{
    ClausenOptions, FermiDiracOptions, ProbabilityOptions, SpecialFunctionResult,
    clausen_with_options, faddeeva_with_options, fermi_dirac_half_with_options,
};

// Extract (termination status, iteration count, estimation basis, estimated absolute error, value) from the result.
type Summary = (
    String,
    usize,
    Option<String>,
    Option<f64>,
    Option<Complex<f64>>,
);
fn summarize<V: NumericScalar<Real = f64>>(r: SpecialFunctionResult<V>) -> Summary {
    let value = r.value();
    (
        format!("{:?}", r.termination()),
        r.counts().iterations(),
        value.map(|v| format!("{:?}", v.reliability())),
        value.map(|v| v.absolute_error()),
        value
            .map(|v| Complex::new(v.value().real_component(), v.value().imaginary_component())),
    )
}

let z = Complex::new(1.0, 0.5);
// Evaluate with budget n. If no estimate is available by the budget, the options form also returns an error.
let evaluate = |n: usize| -> Result<Summary, String> {
    let limit = Budget::try_from(n).map_err(|e| e.to_string())?;
    let result = match function.as_str() {
        "Clausen Cl₂(π/2)" => {
            let options = ClausenOptions::default().with_iteration_budget(limit);
            clausen_with_options(std::f64::consts::FRAC_PI_2, options).map(summarize)
        }
        "Fermi–Dirac F₁/₂(0)" => {
            let options = FermiDiracOptions::default().with_iteration_budget(limit);
            fermi_dirac_half_with_options(0.0, options).map(summarize)
        }
        _ => {
            let options = ProbabilityOptions::default().with_iteration_budget(limit);
            faddeeva_with_options(z, options).map(summarize)
        }
    };
    Ok(result.unwrap_or_else(|e| (format!("{:?} (error)", e.kind()), n, None, None, None)))
};
// Reference values. Faddeeva uses an independent manual Taylor-series check (Γ(n/2 + 1) is formed by recurrence).
let reference = match function.as_str() {
    "Clausen Cl₂(π/2)" => Complex::new(0.9159655941772190150546035149, 0.0),
    "Fermi–Dirac F₁/₂(0)" => Complex::new(0.7651470246254079453672687586, 0.0),
    _ => {
        let iz = Complex::new(0.0, 1.0) * z;
        let mut gammas = [1.0, 0.5 * std::f64::consts::PI.sqrt()];
        let (mut power, mut sum) = (Complex::new(1.0, 0.0), Complex::new(1.0, 0.0));
        for n in 1..80 {
            power = power * iz;
            if n >= 2 {
                gammas[n % 2] *= n as f64 / 2.0;
            }
            sum = sum + power * (1.0 / gammas[n % 2]);
        }
        sum
    }
};

let mut rows = Vec::new();
for n in [1, 2, 3, 4, 6, 8, 12, 16, 24] {
    let (termination, iterations, reliability, estimate, value) = evaluate(n)?;
    let actual = value.map(|v| (v - reference).norm());
    rows.push((n, termination, iterations, reliability, estimate, actual));
}
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "Budget [iterations]", "type": "integer" },
    { "key": "1", "label": "Termination status" },
    { "key": "2", "label": "Iterations [count]", "type": "integer" },
    { "key": "3", "label": "Estimate basis", "nullText": "None" },
    { "key": "4", "label": "Estimated absolute error [-]", "type": "number", "format": sci2, "nullText": "None" },
    { "key": "5", "label": "Actual error [-]", "type": "number", "format": sci2, "nullText": "None" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "sweep" })
);

// Use the selected budget's termination status for the outcome (IterationLimit is partial).
let (termination, iterations, _, estimate, value) = evaluate(budget as usize)?;
let outcome = match (termination.as_str(), value) {
    ("Exact" | "Converged" | "Limit", Some(_)) => {
        Outcome::satisfied("Evaluation completed within the budget")
    }
    (_, Some(_)) => Outcome::partial("Budget reached; the value is an intermediate estimate")
        .explanation("try_value and the standard form return ConvergenceFailure for this result."),
    _ => Outcome::failed("No estimate was obtained within the budget, and the options form also returned an error"),
};
let mut outcome = outcome
    .status(termination)
    .diagnostic("Iteration count", iterations as f64, None);
if let (Some(estimate), Some(value)) = (estimate, value) {
    outcome = outcome
        .diagnostic("Estimated absolute error", estimate, None)
        .diagnostic("Actual error", (value - reference).norm(), None);
}
emit_outcome!(outcome);
```

For the default Clausen function, budgets below 15 give termination status `IterationLimit` and estimation basis `Heuristic`.
Even then, the estimated absolute error is 1–2.4 times the actual error (except at budget 12, where the actual error is 0); at budget 6 the estimate is $5.2 \times 10^{-9}$ versus an actual error of $4.8 \times 10^{-9}$.
With budget 16 it reaches `Converged` after 15 iterations, and the basis changes to `ModelBased`.
The outcome describes the state at the selected budget and is partial for `IterationLimit`.

For the Fermi–Dirac integral, the basis remains `ModelBased` even when stopped at the budget; the estimate includes omitted Chebyshev terms and covers the actual error.
It reaches `Converged` after 23 iterations and agrees bitwise with the reference.

The Faddeeva function behaves differently.
A continued fraction stopped at the budget receives the completed-evaluation envelope $64\varepsilon|w|$ unchanged, labeled `Heuristic`, without truncation error.
At this point, the estimate ranges only from $4.1 \times 10^{-15}$ at budget 1 to $7.0 \times 10^{-15}$ at budget 12.
The actual error is much larger, 0.26 at budget 1 and $5.6 \times 10^{-3}$ at budget 4, and is not covered by the estimate.
When it reaches `Converged` after 14 iterations, the basis changes to `StatisticallyCalibrated`, and the estimate $7.0 \times 10^{-15}$ covers the actual error $3.7 \times 10^{-16}$.
Therefore, for a value with `IterationLimit` and basis `Heuristic`, do not rely on the estimated error; increase the budget and evaluate again.

## Representing tail probabilities

Evaluate upper-tail probabilities directly using complementary forms.
`normal_sf`, `gamma_q`, `beta_inc_q`, and `erfc` form the smaller tail without subtraction, retaining relative accuracy even where the lower probability rounds to 1.
For tails whose complementary forms themselves fall below the scalar range ($x > 38.5$ for binary64 `normal_sf`), use logarithmic forms.
`normal_log_sf`, `gamma_log_q`, and `beta_inc_log_q` return logarithms without forming the probabilities.
To find quantiles from probabilities, use `normal_isf`, `gamma_q_inv`, and `beta_inc_q_inv` to invert the tail probability directly; for logarithmic probabilities, use `normal_inv_log_sf`, `gamma_q_inv_log`, and `beta_inc_q_inv_log`.

The function `log_erfc(z)` returns $\ln\operatorname{erfc}(z)$.
For real $x < 1/2$, $\ln(1 - \operatorname{erf}(x))$ is formed with `ln1p`, and elsewhere as $\ln\operatorname{erfcx}(x) - x^2$, retaining accuracy even where $\operatorname{erfc}(x)$ falls below the range.
Real arguments target 4 ULP in binary64 and 1 ULP in binary32; at $x > 1.3 \times 10^{154}$, where $x^2$ overflows, the result is `NumericalInstability` (`Overflow`).
For complex $z$, this is the principal logarithm of $\operatorname{erfc}(z)$, with no uniform target.
The options form is `log_erfc_with_options`; the scoped API `log_erfc_scoped` accepts only complex arguments.
Real evaluation has fixed work, so sharing counts with a parent solve serves no purpose.

The next cell evaluates three tails at a common argument $x$ using subtraction, complementary forms, and logarithmic forms.
They are the normal upper probability $1 - \Phi(x)$, the shape-3 gamma upper probability $Q(3, x)$, and the complementary error function $\operatorname{erfc}(x)$.
The normal and $\operatorname{erfc}$ references use a logarithm obtained by evaluating 500 levels of Laplace's continued fraction $1 - \Phi(t) = \varphi(t)/(t + 1/(t + 2/(t + 3/(t + \cdots))))$ backward, with the conversion $\operatorname{erfc}(x) = 2(1 - \Phi(\sqrt2 x))$.
The gamma reference is the finite sum $\ln Q(3, x) = -x + \ln(1 + x + x^2/2)$ for integer shape.
The implementation uses the same finite sum for integer shapes, so this row checks logarithmic assembly rather than comparing independent methods.

```rust
//| id: special-tail-representations
//| ref: special-tail-representations
//| title: "Compare tail probabilities from subtraction, complementary forms, and logarithmic forms"
//| run: reactive
//| crates: [scioxide-special]
//| inputs:
//|   x: {"type":"range","label":"Argument x","description":"Argument shared by the three distributions.","min":2,"max":800,"step":2,"value":10}
//| cases:
//|   - {"id":"deep","label":"x = 40","description":"Even the complementary normal form rounds to 0; only the logarithmic form retains a value.","inputs":{"x":40}}
//|   - {"id":"far","label":"x = 800","description":"All three complementary forms round to 0.","inputs":{"x":800}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"tails","path":"/rows/0/1","equals":0}
//|       - {"artifact":"tails","path":"/rows/0/2","approx":{"value":7.619853024e-24,"rtol":1e-9}}
//|       - {"artifact":"tails","path":"/rows/0/5","range":{"max":1e-14}}
//|       - {"artifact":"tails","path":"/rows/1/5","range":{"max":1e-14}}
//|       - {"artifact":"tails","path":"/rows/2/5","range":{"max":1e-14}}
//|   - case: deep
//|     expect:
//|       - {"artifact":"tails","path":"/rows/0/2","equals":0}
//|       - {"artifact":"tails","path":"/rows/0/5","range":{"max":1e-14}}
//|       - {"artifact":"tails","path":"/rows/2/5","range":{"max":1e-14}}
//|   - case: far
//|     expect:
//|       - {"artifact":"tails","path":"/rows/1/2","equals":0}
//|       - {"artifact":"tails","path":"/rows/0/3","approx":{"value":-320007.6,"rtol":1e-6}}
//|       - {"artifact":"tails","path":"/rows/0/5","range":{"max":1e-14}}
//|       - {"artifact":"tails","path":"/rows/1/5","range":{"max":1e-14}}
//|       - {"artifact":"tails","path":"/rows/2/5","range":{"max":1e-14}}
use scioxide_special::{
    erf, erfc, gamma_log_q, gamma_p, gamma_q, log_erfc, normal_cdf, normal_log_sf, normal_sf,
};

// Independent reference: ln(1 − Φ(t)) using Laplace's continued fraction (f64 intrinsic methods).
let normal_log_tail = |t: f64| {
    let mut fraction = t;
    for k in (1..=500).rev() {
        fraction = t + k as f64 / fraction;
    }
    -0.5 * t * t - (2.0 * std::f64::consts::PI).sqrt().ln() - fraction.ln()
};
let normal = (
    "Normal 1 − Φ(x)",
    1.0 - normal_cdf(x).map_err(|e| e.to_string())?,
    normal_sf(x).map_err(|e| e.to_string())?,
    normal_log_sf(x).map_err(|e| e.to_string())?,
    normal_log_tail(x),
);
// Finite sum for integer shape (the same formula as the implementation, so this checks logarithmic assembly).
let gamma = (
    "Gamma Q(3, x)",
    1.0 - gamma_p(3.0, x).map_err(|e| e.to_string())?,
    gamma_q(3.0, x).map_err(|e| e.to_string())?,
    gamma_log_q(3.0, x).map_err(|e| e.to_string())?,
    -x + (1.0 + x + 0.5 * x * x).ln(),
);
// erfc(x) = 2 (1 − Φ(√2 x)).
let error_function = (
    "Complementary error function erfc(x)",
    1.0 - erf(x).map_err(|e| e.to_string())?,
    erfc(x).map_err(|e| e.to_string())?,
    log_erfc(x).map_err(|e| e.to_string())?,
    std::f64::consts::LN_2 + normal_log_tail(std::f64::consts::SQRT_2 * x),
);
let rows = [normal, gamma, error_function].map(|(name, subtracted, direct, log, reference)| {
    let difference = ((log - reference) / reference).abs();
    (name, subtracted, direct, log, reference, difference)
});
let sci6 = serde_json::json!({ "notation": "scientific", "significantDigits": 6 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let fixed6 = serde_json::json!({ "fractionDigits": 6 });
let columns = serde_json::json!([
    { "key": "0", "label": "Tail" },
    { "key": "1", "label": "Subtraction 1 − F [-]", "type": "number", "format": sci6 },
    { "key": "2", "label": "Complementary form [-]", "type": "number", "format": sci6 },
    { "key": "3", "label": "Logarithmic form [-]", "type": "number", "format": fixed6 },
    { "key": "4", "label": "Reference logarithm [-]", "type": "number", "format": fixed6 },
    { "key": "5", "label": "Relative difference between logarithmic form and reference [-]", "type": "number", "format": sci2 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "tails" })
);
```

For the default $x = 10$, $\Phi(10)$ and $\operatorname{erf}(10)$ round to 1, so subtraction gives 0.
The complementary forms return $1 - \Phi(10) \approx 7.62 \times 10^{-24}$ and $\operatorname{erfc}(10) \approx 2.09 \times 10^{-45}$.
For $Q(3, 10) \approx 2.77 \times 10^{-3}$, subtraction retains a value, but the last two digits or so differ.
At $x = 40$, subtraction gives $3.55 \times 10^{-15}$ versus $Q(3, 40) \approx 3.57 \times 10^{-15}$, a relative error of 0.6%; for the normal distribution and $\operatorname{erfc}$, even the complementary forms round to 0.
At $x = 800$, all three complementary forms become 0.
Logarithmic forms retain finite values for every $x$; varying $x$ from 2 to 800 in steps of 2 keeps the relative difference from the reference at most $6 \times 10^{-16}$.
The normal logarithmic form is $-320007.6$ at $x = 800$, and $\ln\operatorname{erfc}(800)$ is $-640007.3$.

## Summary and further reading

The argument type determines the result type; a real order can be passed directly with a complex argument, but a complex order requires a complex argument.
On a cut, the imaginary part's $+0$ and $-0$ select the side; real APIs accept only their real domains.
Options results contain ordinary, scaled, logarithmic, and derivative values with estimated errors; termination status `IterationLimit` means an intermediate estimate, and basis `Heuristic` may exclude truncation error.
Evaluate tail probabilities directly with complementary forms and tails below the range with logarithmic forms, avoiding the subtraction $1 - F$.
The mathematical pages in the table explain each family's methods and accuracy targets; [Choosing a method](../../choosing/) explains how to select a representation.
