Evaluating a special function throughout its domain with a single series or integral representation encounters cancellation at large arguments, stalled convergence, and exponential overflow or underflow.
`scioxide-special` selects methods by argument region: defining series or rational approximations near the origin, continued fractions, recurrences, or Chebyshev expansions in intermediate regions, and asymptotic expansions at large arguments.
This page explains notation and shared contracts assumed by the 35 mathematical pages, then provides a page map.
Each family's mathematical page gives its definitions, method selection, and accuracy details.

## Notation

| Symbol | Meaning |
|---|---|
| $\varepsilon$ | Scalar-type machine epsilon; $2^{-52} \approx 2.22 \times 10^{-16}$ for binary64 |
| ULP | Floating-point spacing at the true value, used as a unit for counting error in ULP |
| $\eta$ | Smallest positive subnormal; approximately $4.9 \times 10^{-324}$ for binary64 |
| $P, Q$ | Regularized lower and upper probabilities; $P + Q = 1$, with $Q$ called the complementary form |
| $m = k^2$ | Parameter of elliptic integrals and Jacobi elliptic functions; $k$ is the modulus |
| $\nu$, $n$, $l$ | Orders; $\nu$ is real or complex, $n$ and $l$ are integers |
| $z$, $x$ | Arguments; $z$ includes complex values, $x$ is real only |

Pass all angles in radians.
Definitions and numbering follow NIST's DLMF.

## Shared contracts

### Value representations

The `SpecialFunctionResult` returned by detailed form `*_with_options` holds the same value in up to four forms.
These are ordinary value `value()`, a value splitting each component into a significand and power-of-two exponent `scaled()`, logarithmic form `logarithmic()` separating phase (sign for real numbers) and natural logarithm of magnitude, and argument derivative `derivative()`.
Even when the ordinary value overflows, scaled and logarithmic forms remain when representable.
`scalar_representation()` indicates ordinary-value projection status: `Finite`, `Overflow`, or `InfiniteLimit` (a documented $\pm\infty$ limit).
A true value too small to represent that rounds to zero retains status `Finite`; the ordinary form returns signed zero.

Functions with `_scaled` in their names return a different quantity multiplied by an exponential factor.
For example, `bessel_k_scaled` returns $e^{z}K_\nu(z)$; `airy_ai_scaled` returns $e^{\frac23 x^{3/2}}\operatorname{Ai}(x)$ for real $x > 0$ and applies no factor for $x \le 0$.
Detailed-form `scaled()` merely reexpresses the same value with powers of two and differs from named scaled functions.

Logarithmic functions use `ln_*` for Gamma, Beta, factorials, and binomial coefficients (such as `ln_gamma`); others include `log` in their names (`log_erfc`, `gamma_log_q`, `normal_log_sf`, `bessel_k_log`, `hurwitz_zeta_log`).
Inverse functions for logarithmic probabilities are named `*_inv_log*` (such as `gamma_p_inv_log`).
Complementary forms evaluate upper probabilities without subtraction: `erfc`, `gamma_q`, `beta_inc_q`, and `normal_sf`.

### Estimated errors

Each form carries an error estimate as `ValueWithError`.
`absolute_error()` is absolute error in that form's units; `relative_error()` is relative error when the value is nonzero; logarithmic-form error uses natural-logarithm units.
Logarithmic forms are omitted when relative error reaches $1/2$.

`reliability()` distinguishes three bases for estimates.
`ModelBased` derives from models of truncation and rounding errors in evaluation.
`StatisticallyCalibrated` is an envelope measured against high-precision references, using a function-specific constant $k$ in the form $k \max(\varepsilon|v|, \eta)$ ($v$ is the value).
`Heuristic` makes no coverage claim.
No estimate is a guaranteed enclosure; use `scioxide-validated` for certified lower and upper bounds.
Large estimated errors are reported directly rather than treated as errors.

### Termination status and work limits

`termination()` reports how evaluation ended through `SpecialFunctionTermination`.
`Exact` denotes an identity or exact tabulated value, `Converged` a value meeting the method's convergence criterion, and `Limit` a documented mathematical limit (such as $\Gamma(0^+) = +\infty$).
`IterationLimit` means a work limit was reached and retains the estimate available at that point.
`is_success()` is true for the first three statuses.
Projecting a `IterationLimit` result to an ordinary value with `try_value()` yields `ConvergenceFailure`; ordinary forms return the same error.
If no useful estimate is available before the limit, the detailed form also returns `ConvergenceFailure` rather than a result.

Option types (such as `GammaOptions` and `BesselOptions`) carry work limit `Budget`, counted in work units such as series terms or recurrence stages.
A limit is not an accuracy request: the method determines accuracy, and increasing the limit merely lets slowly converging cases finish.
Only `SpectralOptions` (truncation for Mathieu and spheroidal functions) and `EllipsoidalOptions` (adaptive quadrature for second-kind ellipsoidal harmonics and normalization constants) also carry tolerances.
`algorithm()` returns the selected method's identifier; `counts()` returns work counts including unsuccessful attempts.

### Accuracy targets

Accuracy targets express ULP distances from true values over ranges verified by crate tests against comparison data (independently generated high-precision references).
Near function zeros, targets use absolute error; small absolute errors can still accompany large relative errors.

| Functions with real arguments | binary64 | binary32 |
|---|---|---|
| `gamma`, `ln_gamma`, `digamma`, `polygamma`, `beta`, `ln_beta`, `factorial`, `ln_factorial`, `binomial` | 4 ULP | 1 ULP |
| Incomplete Gamma and Beta functions and their inverses | 32 ULP | 1 ULP |
| `erfinv`, `erfcinv`, `normal_quantile`, `normal_isf`, `erfcx`, `log_erfc`, `dawson` | 4 ULP | 1 ULP |
| `normal_cdf`, `normal_sf`, `normal_log_cdf`, `normal_log_sf`（$[-38, 38]$） | 8 ULP | 1 ULP |
| `expint_e1`, `expint_ei`, `expint_en`, `expint_3`, `si`, `ci` (away from zeros) | 8 ULP | None |
| `elliptic_k`, `elliptic_e`（$0 \le m < 1$） | 2 ULP | 1 ULP |
| Carlson integrals, incomplete elliptic integrals, Jacobi elliptic functions | 64 ULP | 64 ULP |
| `bessel_j`, `bessel_y`, `bessel_i`, `bessel_k`, Hankel functions, Airy functions | 64 ULP | 64 ULP |
| `struve`, `modstruve` ($-5 \le \nu \le 10$, $10^{-3} \le x \le 100$) | 64 ULP | None |
| `legendre_p`, `legendre_q`, `legendre_p_assoc` | 64 ULP | 64 ULP |
| `hyp0f1`, `hyp1f1`, `hyp2f1`, `hyperu` | 64 ULP | 64 ULP |
| `lambert_w0`, `lambert_wm1`, `wright_omega`, `dilog`, `spence` | 64 ULP | 64 ULP |
| `coulomb_f`, `coulomb_g` and their derivatives | 64 ULP | 64 ULP |

In a binary64 sample of 4160 points spanning more than the tested range, maximum errors were 3.7 ULP for `gamma`, 1.9 ULP for `ln_gamma`, 2.1 ULP for `digamma`, and 1.0 ULP for `beta`.
In the same sample, `gamma_p` and `gamma_q` reach 90 ULP and `beta_inc` 12 ULP, so the incomplete forms' 32 ULP target applies only to the tested ranges.
For real arguments, `riemann_zeta` and `dirichlet_eta`, together with `hurwitz_zeta` restricted to $s > 1$, have no ULP target and report estimated errors at most $64\varepsilon|v|$.
Complex arguments and unlisted functions (such as Kelvin, parabolic cylinder, angular-momentum and spectral functions, and Fermi–Dirac integrals) have no uniform targets; detailed error estimates provide guidance.

The following cell compares detailed estimated errors with actual errors at points whose values are known from closed forms or known constants.
References are decimal constants of at least 20 digits, correctly rounded when read as f64, allowing actual errors to be measured accurately within $0.5$ ULP.
There are no inputs; the table shows estimate bases, estimated relative errors, actual errors, and ULP targets.

```rust
//| id: special-index-estimate-and-ulp
//| ref: special-index-estimate-and-ulp
//| title: "Compare estimated and actual errors at known values"
//| run: reactive
//| crates: [scioxide-special]
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"estimates","path":"/rows/0/4","range":{"max":4}}
//|       - {"artifact":"estimates","path":"/rows/1/4","range":{"max":2}}
//|       - {"artifact":"estimates","path":"/rows/3/4","range":{"max":64}}
//|       - {"artifact":"estimates","path":"/rows/5/4","range":{"max":64}}
//|       - {"artifact":"estimates","path":"/rows/6/4","range":{"max":8}}
//|       - {"artifact":"estimates","path":"/rows/0/5","equals":"Yes"}
//|       - {"artifact":"estimates","path":"/rows/8/5","equals":"Yes"}
use scioxide_special::{
    SpecialFunctionResult, clausen_with_options, digamma_with_options, elliptic_k_with_options,
    expint_e1_with_options, fermi_dirac_half_with_options, gamma_with_options,
    hyp2f1_with_options, lambert_w0_with_options, riemann_zeta_with_options,
};

// Construct default options for each type.
fn d<T: Default>() -> T {
    T::default()
}
// References are decimal constants with at least 20 digits (DLMF closed forms and known constants).
let cases: Vec<(&str, Option<u32>, f64, SpecialFunctionResult<f64>)> = vec![
    (
        "Γ(1/2) = √π",
        Some(4),
        1.7724538509055160272981674833,
        gamma_with_options(0.5, d()),
    ),
    (
        "K(1/2) = Γ(1/4)²/(4√π)",
        Some(2),
        1.8540746773013719184338503472,
        elliptic_k_with_options(0.5, d()),
    ),
    (
        "ψ(1) = −γ",
        Some(4),
        -0.5772156649015328606065120901,
        digamma_with_options(1.0, d()),
    ),
    (
        "W₀(1) = Ω",
        Some(64),
        0.5671432904097838729999686622,
        lambert_w0_with_options(1.0, d()),
    ),
    (
        "ζ(2) = π²/6",
        None,
        1.6449340668482264364724151666,
        riemann_zeta_with_options(2.0, d()),
    ),
    (
        "₂F₁(1, 1; 2; 1/2) = 2 ln 2",
        Some(64),
        1.3862943611198906188344642429,
        hyp2f1_with_options(1.0, 1.0, 2.0, 0.5, d()),
    ),
    (
        "E₁(1)",
        Some(8),
        0.2193839343955202736771637755,
        expint_e1_with_options(1.0, d()),
    ),
    (
        "Cl₂(π/2) = G（Catalan）",
        None,
        0.9159655941772190150546035149,
        clausen_with_options(std::f64::consts::FRAC_PI_2, d()),
    ),
    (
        "F₁/₂(0) = (1 − 2^(−1/2)) ζ(3/2)",
        None,
        0.7651470246254079453672687586,
        fermi_dirac_half_with_options(0.0, d()),
    ),
]
.into_iter()
.map(|(name, target, reference, result)| result.map(|r| (name, target, reference, r)))
.collect::<Result<_, _>>()
.map_err(|e| e.to_string())?;

let mut rows = Vec::new();
for (name, target, reference, result) in cases {
    let value = result.value().ok_or("No ordinary value")?;
    // ULP at the reference value: 2^(⌊log₂|r|⌋ − 52).
    let ulp = 2f64.powi(reference.abs().log2().floor() as i32 - 52);
    let actual = (*value.value() - reference).abs();
    let covered = if actual <= value.absolute_error() {
        "Yes"
    } else {
        "No"
    };
    rows.push((
        name,
        format!("{:?}", value.reliability()),
        value.relative_error(),
        target,
        actual / ulp,
        covered,
    ));
}
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let fixed1 = serde_json::json!({ "fractionDigits": 1 });
let columns = serde_json::json!([
    { "key": "0", "label": "Function and point" },
    { "key": "1", "label": "Estimate basis" },
    { "key": "2", "label": "Estimated relative error [-]", "type": "number", "format": sci2, "nullText": "None" },
    { "key": "3", "label": "Target [ULP]", "type": "integer", "nullText": "No uniform target" },
    { "key": "4", "label": "Actual error [ULP]", "type": "number", "format": fixed1 },
    { "key": "5", "label": "Estimate covers actual error" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "estimates" })
);
```

At all nine points, actual errors are 0 ULP: the values match correctly rounded results.
These are browser wasm results; native execution gives 2 ULP for `expint_e1` because of mathematical-library differences.
Targets (2–64 ULP) bound the full tested range; individual-point errors are often much smaller.
Estimated relative errors range from $4.4 \times 10^{-16}$ (`elliptic_k`) to $1.5 \times 10^{-14}$ (`clausen`), covering actual errors at every point.
`StatisticallyCalibrated` estimates have form $k\varepsilon|v|$, making them small multiples of $\varepsilon$.
`ModelBased` estimates accumulate truncation and rounding assessments, giving relative errors from $5.5 \times 10^{-15}$ to $1.5 \times 10^{-14}$ in this table.
`hyp2f1` has an absolute-error estimate but reports no relative-error estimate at this point.
Zero error at one point does not guarantee a function's accuracy.

## Summary and further reading

Detailed results hold ordinary values, scaled values, logarithmic forms, and derivatives with their respective error estimates; when ordinary values overflow, other forms can retain them.
Error estimates use `ModelBased`, `StatisticallyCalibrated`, or `Heuristic` as their basis; none is a certified enclosure.
With termination `IterationLimit`, values are intermediate estimates and projection to ordinary values yields an error.
Accuracy targets are ULP values over tested ranges; inspect error estimates for unlisted functions and complex arguments.
First examine argument types and result interpretation in [Entry points, branches, and value representations](branches-tails-and-extended-families/), then proceed to the required family.
