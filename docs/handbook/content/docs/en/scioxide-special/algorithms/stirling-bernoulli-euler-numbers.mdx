Stirling, Bernoulli, and Euler numbers are integer and rational sequences appearing in enumeration and series coefficients.
Stirling numbers transform between power and falling-factorial bases; Bernoulli numbers appear as coefficients in Euler–Maclaurin summation and the Gamma function's Stirling series.
All grow factorially with degree and soon exceed the exact-integer range of binary64 (at most $2^{53} \approx 9.0 \times 10^{15}$).
This page explains sequence definitions, evaluation in `scioxide-special` (triangular recurrences, exact tables, and zeta/beta identities), exact-valued `checked_bernoulli` and `checked_euler`, accuracy guarantees, and API selection.
[Factorials and binomial coefficients](../combinatorial-numbers/) covers factorials, binomial coefficients, logarithmic forms, and method selection.

## Stirling numbers

Stirling numbers transform between the bases of powers $x^n$ and falling factorial powers $(x)_n^{\downarrow} = x(x-1)\cdots(x-n+1)$ (DLMF §26.8).
Signed Stirling numbers of the first kind $s(n, k)$ and Stirling numbers of the second kind $S(n, k)$ are defined by

$$
x(x-1)\cdots(x-n+1) = \sum_{k=0}^n s(n, k)\, x^k, \qquad x^n = \sum_{k=0}^n S(n, k)\, x(x-1)\cdots(x-k+1)
$$


$S(n, k)$ counts partitions of $n$ distinct elements into $k$ nonempty subsets, and $|s(n, k)|$ counts permutations of $n$ elements with $k$ cycles.
The sign of $s(n, k)$ is $(-1)^{n-k}$.
The transforms are inverse to each other, so the product of lower-triangular matrices $[s(n, j)]$ and $[S(j, m)]$ is the identity (DLMF §26.8).

$$
\sum_{j=m}^{n} s(n, j)\, S(j, m) = \delta_{nm}
$$

`stirling_first_kind` and `stirling_second_kind` advance the triangular recurrences

$$
|s(n+1, k)| = |s(n, k-1)| + n\,|s(n, k)|, \qquad S(n+1, k) = S(n, k-1) + k\,S(n, k)
$$

using one column ($k+1$ entries) of workspace, applying the sign of $s$ at the end.
The unsigned recurrences sum positive terms and have no cancellation.
Each column value is stored as a binary64 significand and integer exponent, avoiding intermediate overflow.
Work is $O(k(n-k))$ operations, allocating the column on every call.
$s(n, n) = S(n, n) = 1$, zero for $k > n$ and $k = 0 < n$, and $S(n, 1) = 1$ are returned without recurrence.

Since the significand is binary64, values above $2^{53}$ cease to be exact integers, and relative errors accumulate proportionally to recurrence length.
The form with options returns this as a relative error estimate of $8n\varepsilon$.
Recurrence work counts against `CombinatorialOptions`; if $O(k(n-k))$ exceeds the limit, it gives `ConvergenceFailure`.
For $0 < k < n$, if $n$ is at least the limit (65 536 by default), evaluation returns `InvalidInput` (`OutOfRange`) without starting the recurrence.
Failure to allocate the column gives `SizeOverflow` or `AllocationFailure`; values beyond the range give `NumericalInstability` (`Overflow`).
Work for both grows with the arguments, so they have scoped APIs `stirling_first_kind_scoped` and `stirling_second_kind_scoped`.

The next cell computes $s(n, k)$ and $S(n, k)$ in floating point up to maximum degree $N$ and performs two independent checks.
One is relative differences from exact values computed manually by the same recurrence in `i128` integers.
`i128` represents values through $33! \approx 8.7 \times 10^{36}$ exactly, allowing exact comparison for $N \le 30$.
The other is the inverse-matrix identity residual; since its sum cancels large alternating terms, it also reports the residual divided by term magnitude $\sum_j |s(n, j)|\,S(j, m)$.

```rust
//| id: special-combinatorial-stirling-orthogonality
//| ref: special-combinatorial-stirling-orthogonality
//| title: "Check Stirling numbers against exact integers and the inverse-matrix identity"
//| run: reactive
//| crates: [scioxide-special]
//| inputs:
//|   max_n: {"type":"range","label":"Maximum degree N [-]","description":"Extend comparison to degrees where values exceed 2^53.","min":4,"max":30,"step":1,"value":12}
//| cases:
//|   - {"id":"large","label":"N = 30","description":"Include the range where values cease to be exact integers, through |s(30, 1)| = 29! ≈ 8.8 × 10³⁰.","inputs":{"max_n":30}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"stirling","path":"/rows/11/1","equals":0}
//|       - {"artifact":"stirling","path":"/rows/11/2","equals":0}
//|       - {"artifact":"stirling","path":"/rows/11/5","range":{"max":1e-15}}
//|   - case: large
//|     expect:
//|       - {"artifact":"stirling","path":"/rows/29/1","range":{"max":1e-15}}
//|       - {"artifact":"stirling","path":"/rows/29/2","range":{"max":1e-15}}
//|       - {"artifact":"stirling","path":"/rows/29/4","range":{"min":1e18}}
//|       - {"artifact":"stirling","path":"/rows/29/5","range":{"max":1e-15}}
use scioxide_special::{stirling_first_kind, stirling_second_kind};

let size = max_n as usize + 1;
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
// Independent check: advance recurrences for |s(n, k)| and S(n, k) exactly in i128.
let mut first_exact = vec![vec![0_i128; size]; size];
let mut second_exact = vec![vec![0_i128; size]; size];
first_exact[0][0] = 1;
second_exact[0][0] = 1;
for n in 1..size {
    for k in 1..=n {
        first_exact[n][k] = first_exact[n - 1][k - 1] + (n as i128 - 1) * first_exact[n - 1][k];
        second_exact[n][k] = second_exact[n - 1][k - 1] + k as i128 * second_exact[n - 1][k];
    }
}

// Floating-point values (SciOxide).
let mut first = vec![vec![0.0_f64; size]; size];
let mut second = vec![vec![0.0_f64; size]; size];
for n in 0..size {
    for k in 0..=n {
        first[n][k] = stirling_first_kind::<f64>(n, k).map_err(|e| e.to_string())?;
        second[n][k] = stirling_second_kind::<f64>(n, k).map_err(|e| e.to_string())?;
    }
}

let mut rows = Vec::new();
for n in 1..size {
    let mut first_error = 0.0_f64;
    let mut second_error = 0.0_f64;
    for k in 1..=n {
        let sign = if (n - k) % 2 == 0 { 1.0 } else { -1.0 };
        let exact_first = sign * first_exact[n][k] as f64;
        let exact_second = second_exact[n][k] as f64;
        first_error = first_error.max((first[n][k] - exact_first).abs() / exact_first.abs());
        second_error = second_error.max((second[n][k] - exact_second).abs() / exact_second);
    }
    // Inverse-matrix identity residuals and magnitudes of cancelling terms.
    let mut residual = 0.0_f64;
    let mut relative = 0.0_f64;
    for m in 0..=n {
        let sum: f64 = (m..=n).map(|j| first[n][j] * second[j][m]).sum();
        let scale: f64 = (m..=n).map(|j| (first[n][j] * second[j][m]).abs()).sum();
        let delta = if m == n { 1.0 } else { 0.0 };
        residual = residual.max((sum - delta).abs());
        relative = relative.max((sum - delta).abs() / scale);
    }
    let largest = (1..=n)
        .map(|k| first_exact[n][k].max(second_exact[n][k]))
        .max()
        .unwrap_or(1);
    rows.push((
        n,
        first_error,
        second_error,
        largest as f64,
        residual,
        relative,
    ));
}
let columns = serde_json::json!([
    { "key": "0", "label": "n", "type": "integer" },
    { "key": "1", "label": "Maximum relative difference in s(n, ·) [-]", "type": "number", "format": sci3 },
    { "key": "2", "label": "Maximum relative difference in S(n, ·) [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "Maximum row magnitude [-]", "type": "number", "format": sci3 },
    { "key": "4", "label": "Inverse-matrix identity residual [-]", "type": "number", "format": sci3 },
    { "key": "5", "label": "Residual / term magnitude [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "stirling" })
);
```

At the default $N = 12$, every value equals the exact integer, and inverse-matrix residuals are zero.
At $N = 30$, $s(n, \cdot)$ starts differing slightly from exact integers at $n = 21$ and $S(n, \cdot)$ at $n = 24$, but the maximum relative difference is $3.2 \times 10^{-16}$.
This is much smaller than the estimated error $8n\varepsilon = 5.3 \times 10^{-14}$.

Inverse-matrix residuals become nonzero from $n = 18$ and reach $1.7 \times 10^{18}$ at $n = 30$.
Dividing by the magnitude of cancelling terms gives $1.5 \times 10^{-16}$, remaining at binary64 rounding level.
The large residual comes from cancellation of alternating terms exceeding $10^{30}$, rather than incorrect values.
If relative differences or residuals divided by term magnitudes exceed several tens of $\varepsilon$, suspect the values or the checking formula.

## Bernoulli and Euler numbers

Bernoulli numbers $B_n$ and Euler numbers $E_n$ are defined by exponential generating functions (DLMF 24.2.1, 24.2.6).

$$
\frac{t}{e^t - 1} = \sum_{n=0}^\infty B_n \frac{t^n}{n!}, \qquad \operatorname{sech} t = \frac{2}{e^t + e^{-t}} = \sum_{n=0}^\infty E_n \frac{t^n}{n!}
$$

$B_0 = 1$, $B_1 = -1/2$, $B_2 = 1/6$, and $B_4 = -1/30$; for odd $n \ge 3$, $B_n = 0$.
The sign of $B_1$ follows the generating-function convention $t/(e^t - 1)$; references using $t/(1 - e^{-t})$ have $+1/2$.
$E_0 = 1$, $E_2 = -1$, $E_4 = 5$, and $E_6 = -61$; odd $n$ gives $E_n = 0$, and even-indexed $E_n$ are integers with alternating signs.

Even-degree values can be expressed with zeta and the Dirichlet beta function $\beta(s) = \sum_{j \ge 0} (-1)^j (2j+1)^{-s}$ (including DLMF 25.6.2).

$$
B_{2m} = (-1)^{m+1}\frac{2\,(2m)!}{(2\pi)^{2m}}\,\zeta(2m), \qquad E_{2m} = (-1)^m \frac{2^{2m+2}\,(2m)!}{\pi^{2m+1}}\,\beta(2m+1)
$$

Since $\zeta(2m) \to 1$, $|B_{2m}|$ grows on the scale of $2(2m)!/(2\pi)^{2m}$, factorially for large $m$.

`bernoulli` rounds values at even degrees $n \le 34$ from an exact rational table; values at larger even degrees are evaluated logarithmically by directly summing the $\zeta(2m)$ and $\beta(2m+1)$ series in the identities above and combining with $\ln(2m)!$.
`euler` rounds values at even degrees $n \le 22$ from an exact integer table and evaluates values at larger even degrees similarly.
The series converge faster for larger $2m$ and stop when the omitted-term bound falls below $\varepsilon/4$.
Values exceeding the range give `NumericalInstability` (`Overflow`), while the form with options retains a logarithmic form.

Obtain exact values with `checked_bernoulli(n)` and `checked_euler(n)`.
`checked_bernoulli` returns a reduced fraction (numerator `isize`, denominator `usize`), supporting tabulated even $n \le 34$ and $n = 38$.
The numerator of $B_{36}$ does not fit in 64 bits, but that of $B_{38}$ does, so only $n = 36$ and $n > 38$ give `SizeOverflow`.
`checked_euler` returns values at even degrees $n \le 22$ as `isize` integers; larger even degrees give `SizeOverflow`.
The width of `isize` depends on the environment; on 32-bit environments (including wasm32), $B_{28}$ onward, with numerators exceeding $2^{31}$, and $E_{16}$ onward also give `SizeOverflow`.

The next cell compares even-indexed $B_n$ up to the maximum degree with exact rationals and an identity using `riemann_zeta`.
The identity side obtains $\zeta(2m)$ from `riemann_zeta` and manually combines $(2m)!$ and $(2\pi)^{2m}$ logarithmically.
Within the table range ($n \le 34$), this is independent of `bernoulli`; for $n \ge 36$, `bernoulli` uses the same identity, but $\zeta(2m)$ evaluation (`bernoulli` sums its series directly) and assembly rounding differ.
For $E_n$, the generating-function relation $\operatorname{sech} t \cdot \cosh t = 1$ gives the identity

$$
\sum_{j=0}^{m} \binom{2m}{2j} E_{2j} = 0 \qquad (m \ge 1)
$$

whose residual is reported divided by term magnitude $\sum_j \binom{2m}{2j}\lvert E_{2j}\rvert$.
On 32-bit environments, rows where `checked_bernoulli` returns `SizeOverflow` leave the exact-value column blank.

```rust
//| id: special-combinatorial-bernoulli-zeta
//| ref: special-combinatorial-bernoulli-zeta
//| title: "Check Bernoulli and Euler numbers with exact values and identities"
//| run: reactive
//| crates: [scioxide-core, scioxide-special]
//| inputs:
//|   max_order: {"type":"range","label":"Maximum degree n [-]","description":"Compare beyond the degree where evaluation switches from the table to identities.","min":4,"max":80,"step":2,"value":40}
//| cases:
//|   - {"id":"table-only","label":"n ≤ 12","description":"Compare only the exact table's range.","inputs":{"max_order":12}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"bernoulli","path":"/rows/5/1","approx":{"value":-0.25311355311355315,"rtol":1e-15}}
//|       - {"artifact":"bernoulli","path":"/rows/19/4","range":{"max":3e-14}}
//|       - {"artifact":"bernoulli","path":"/rows/19/5","equals":"combinatorial/bernoulli_zeta_identity@1"}
//|       - {"artifact":"euler","path":"/rows/19/2","range":{"max":1e-15}}
//|   - case: table-only
//|     expect:
//|       - {"artifact":"bernoulli","path":"/rows/5/3","equals":0}
//|       - {"artifact":"bernoulli","path":"/rows/5/4","range":{"max":1e-14}}
//|       - {"artifact":"euler","path":"/rows/5/2","range":{"max":1e-15}}
use scioxide_core::RealScalar;
use scioxide_special::{
    CombinatorialOptions, bernoulli, bernoulli_with_options, binomial, checked_bernoulli,
    euler, euler_with_options, ln_factorial, riemann_zeta,
};

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let sig12 = serde_json::json!({ "notation": "scientific", "significantDigits": 12 });
let options = CombinatorialOptions::default();
let half = max_order as usize / 2;
let log_two_pi = RealScalar::ln(2.0 * std::f64::consts::PI);

let mut rows = Vec::new();
for m in 1..=half {
    let n = 2 * m;
    let value = bernoulli::<f64>(n).map_err(|e| e.to_string())?;
    let method = bernoulli_with_options::<f64>(n, options)
        .map_err(|e| e.to_string())?
        .algorithm()
        .to_string();
    // Exact rational (None if it does not fit in isize).
    let exact = checked_bernoulli(n).ok().map(|(p, q)| p as f64 / q as f64);
    let exact_error = exact.map(|e| (value - e).abs() / e.abs());
    // Manually assemble B₂ₘ = (−1)^(m+1) 2 (2m)! ζ(2m) / (2π)^(2m) logarithmically.
    let sign = if m % 2 == 1 { 1.0 } else { -1.0 };
    let zeta = riemann_zeta(n as f64).map_err(|e| e.to_string())?;
    let log_magnitude = RealScalar::ln(2.0 * zeta)
        + ln_factorial::<f64>(n).map_err(|e| e.to_string())?
        - n as f64 * log_two_pi;
    let identity = sign * RealScalar::exp(log_magnitude);
    rows.push((
        n,
        value,
        exact,
        exact_error,
        (value - identity).abs() / value.abs(),
        method,
    ));
}
let columns = serde_json::json!([
    { "key": "0", "label": "n", "type": "integer" },
    { "key": "1", "label": "bernoulli(n)", "type": "number", "format": sig12 },
    { "key": "2", "label": "Exact rational", "type": "number", "format": sig12, "nullText": "Does not fit in isize" },
    { "key": "3", "label": "Relative difference from rational [-]", "type": "number", "format": sci3, "nullText": "—" },
    { "key": "4", "label": "Relative difference from ζ identity [-]", "type": "number", "format": sci3 },
    { "key": "5", "label": "Method" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "bernoulli" })
);

let values: Vec<f64> = (0..=half)
    .map(|m| euler::<f64>(2 * m))
    .collect::<Result<_, _>>()
    .map_err(|e| e.to_string())?;
let mut euler_rows = Vec::new();
for m in 1..=half {
    let n = 2 * m;
    // Residual of Σ_j C(2m, 2j) E₂ⱼ = 0 and term magnitude.
    let mut sum = 0.0;
    let mut scale = 0.0;
    for j in 0..=m {
        let weight = binomial::<f64>(n, 2 * j).map_err(|e| e.to_string())?;
        sum += weight * values[j];
        scale += weight * values[j].abs();
    }
    let method = euler_with_options::<f64>(n, options)
        .map_err(|e| e.to_string())?
        .algorithm()
        .to_string();
    euler_rows.push((n, values[m], sum.abs() / scale, method));
}
let columns = serde_json::json!([
    { "key": "0", "label": "n", "type": "integer" },
    { "key": "1", "label": "euler(n)", "type": "number", "format": sig12 },
    { "key": "2", "label": "Identity residual / term magnitude [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "Method" }
]);
emit_table_with_columns!(
    columns,
    euler_rows,
    metadata = serde_json::json!({ "id": "euler" })
);
```

At the default maximum degree 40, $n \le 34$ uses the table (`bernoulli_rational_table`) and $n \ge 36$ the identity (`bernoulli_zeta_identity`).
On 64-bit environments, relative differences from exact rationals are zero within the table range.
On wasm32, `checked_bernoulli` returns `SizeOverflow` for $n \ge 28$, leaving the exact-value column blank in those rows.
Unlike $B_{36}$, the numerator of $B_{38}$ fits in 64 bits, so its exact value also appears on 64-bit environments.

The maximum relative difference from the ζ identity is $1.2 \times 10^{-14}$.
In the manually assembled exponent for $\exp(\ln 2\zeta(2m) + \ln(2m)! - 2m\ln 2\pi)$, $\ln 40! \approx 110$ and $40\ln 2\pi \approx 74$ cancel, so differences remain at their rounding level $110\,\varepsilon \approx 2.4 \times 10^{-14}$ and do not indicate error in `bernoulli`.
Euler numbers use the table for $n \le 22$ and the β identity for $n \ge 24$; generating-function identity residuals are at most $1.1 \times 10^{-16}$ times the term magnitude.
Values grow factorially with degree, reaching $B_{40} \approx -1.93 \times 10^{16}$ and $E_{40} \approx 1.49 \times 10^{40}$.

## Accuracy guarantees

Functions in this section have no uniform ULP target checked on reference data (independent high-precision values).
Tests use independent references and exact identities; the forms with options return estimated errors.

| Function | binary64 | binary32 | Notes |
|---|---|---|---|
| `stirling_first_kind`, `stirling_second_kind` | No uniform specification | No uniform specification | Estimated relative error $8n\varepsilon$ |
| `bernoulli`, `euler` | No uniform specification | No uniform specification | Exact rounding within table range; estimated errors in identity range |
| `checked_bernoulli`, `checked_euler` | Exact | Exact | Untabulated degrees and values outside the type give `SizeOverflow` |

Estimated errors in the forms with options (the error in `ValueWithError`, not an enclosing interval) can be checked over the range used with independent checks such as the cells above.

## API

| Function | Standard-form arguments | Options form | Scoped API | Value |
|---|---|---|---|---|
| `stirling_first_kind` | `n, k` | `stirling_first_kind_with_options` | `stirling_first_kind_scoped` | $s(n, k)$ |
| `stirling_second_kind` | `n, k` | `stirling_second_kind_with_options` | `stirling_second_kind_scoped` | $S(n, k)$ |
| `bernoulli` | `n` | `bernoulli_with_options` | None | $B_n$ |
| `euler` | `n` | `euler_with_options` | None | $E_n$ |
| `checked_bernoulli` | `n` | None | None | Reduced fraction `(isize, usize)` of $B_n$ |
| `checked_euler` | `n` | None | None | Integer `isize` of $E_n$ |

Arguments `n` and `k` are `usize`; for floating-point functions, select result type `S: RealScalar` with a type argument such as `bernoulli::<f64>(n)`.
Options forms accept `CombinatorialOptions` and return `SpecialFunctionResult` containing the ordinary value and estimated error, scaled value, logarithmic form, termination status, algorithm identifier, and work counts.
Even on overflow, options forms do not return an error; projection to an ordinary value has status `ScalarRepresentation::Overflow`, and the logarithmic form remains available.
`CombinatorialOptions` contains only a work budget (`Budget`), defaulting to 65 536 units and changed with `CombinatorialOptions::new(budget)` or `with_iteration_budget`.
Only Stirling numbers, whose work grows with the arguments, have scoped APIs; these return the same results as the forms with options and pass work counts to the parent's execution context.
`bernoulli` and `euler` use tables or series that converge faster at higher degree, keeping work bounded independently of arguments, so they have no scoped APIs.

## Summary and further reading

Stirling numbers use unsigned triangular recurrences without cancellation, but values exceeding $2^{53}$ are rounded; work grows as $O(k(n-k))$, and $n$ at least the work limit returns `InvalidInput` before evaluation begins.
For residuals of alternating sums such as the inverse-matrix identity, divide by term magnitudes before comparing with rounding level.
Bernoulli and Euler numbers use exact tables for small degrees and zeta/beta identities for large degrees; use logarithmic forms in the forms with options for degrees exceeding binary64.
Use `checked_bernoulli` and `checked_euler` when exact rationals or integers are needed, remembering the narrower `isize` range in 32-bit environments.
See [Factorials and binomial coefficients](../combinatorial-numbers/) for factorials and binomials, [Gamma functions, polygamma functions, and Pochhammer symbols](oxref:special-gamma-stirling-series) for Stirling series with Bernoulli coefficients, and [Riemann and Hurwitz zeta functions and the Dirichlet eta function](../zeta-functions/) for zeta evaluation.
