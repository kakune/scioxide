`scioxide-special` provides Gamma and Beta functions and probability tails, error functions, Airy and Bessel functions, elliptic integrals, hypergeometric functions, zeta functions, Coulomb wave functions, angular momentum coupling coefficients, Mathieu, spheroidal and ellipsoidal harmonic functions, thermal integrals, and more.
This guide maps tasks to API items and groups the 705 rustdoc items by function family into 13 tables.
Item-name links point to the version 0.1.0 API reference on docs.rs.

---

Batch functions that evaluate many arguments together are not provided.
For evaluation at many points, call the standard form through an iterator and collect the results.
Only Coulomb functions `coulomb_sequence`, `coulomb_wave_sequence`, and `coulomb_normalization_sequence` return sequences of orders together, reusing recurrences between adjacent orders.
They accept a count `count` and return a `Vec` of values; their `*_into` forms write detailed results to caller-provided memory.

## Type relationships

Real-only functions accept `RealScalar` (`f32`, `f64`).
Functions supporting both real and complex arguments have `NumericScalar` signatures and accept `Complex<f32>` and `Complex<f64>` under the same names (for example, `bessel_j`, `gamma_p`, `polylog`, `wright_omega`).
Complex arguments evaluate analytic continuations; cut locations are stated in each function's table.
The argument type determines the result type.
Parameters such as orders and shapes use the same type as the argument; when the argument is complex, real parameters are also accepted (`Parameter`).
For example, with complex $z$, `bessel_j(2.5, z)` returns $J_{2.5}(z)$.
Complex parameters require complex arguments.

Functions have three calling forms: standard, with options, and scoped APIs.
Standard forms `f(..)` return only values.
The form with options `f_with_options(.., options)` returns `SpecialFunctionResult` from the same evaluation; its ordinary value agrees bit for bit with the standard form.
The scoped API `f_scoped(.., options, scope)` performs the same evaluation within a solve scope and returns the same result as the form with options.
Argument `scope` is either `ExecutionContext` (a new root evaluation) or `&mut SolveContext` (a child evaluation inside a parent solve).
Child evaluations pass work to the parent as nested counts and respect the parent's cancellation and deadline.

Functions whose computational work is bounded independently of both arguments and convergence have no scoped APIs.
This includes functions evaluated with fixed tables, rational or Chebyshev approximations, or fixed quadrature nodes.
Examples are Γ, $\ln\Gamma$, $\psi$, Beta, `erfinv`, normal probabilities, log probabilities, and quantiles (excluding inverses from log probabilities `normal_inv_log_cdf` and `normal_inv_log_sf`), `owens_t`, factorials and binomial coefficients, Bernoulli and Euler numbers, `clausen`, `dilog`, and synchrotron functions.
Real error functions and Dawson's integral also use kernels with fixed computational cost, so scoped APIs such as `erf_scoped` accept only complex arguments at the type level.

Each function family has an immutable options type with a work limit `Budget`.
The default for most families is 65536 units; a unit is an operation such as one series term or recurrence step.
Options do not specify an accuracy requirement.
Accuracy is fixed by the kernel; increasing the limit only allows slowly converging cases to complete.
Only `SpectralOptions` (determining truncation) and `EllipsoidalOptions` (determining quadrature) have tolerances.
`AngularOptions` also has a memory limit in addition to the work limit.

`MathieuPlan`, `SpheroidalPlan`, `EllipsoidalHarmonicPlan`, and `AngularPlan` are plans storing precomputations reused across many evaluations.
The first three solve truncated eigenvalue problems and store expansion coefficients; `AngularPlan` stores a prime table for factoring the factorials in Racah's formula.
Plans are immutable and retain the options used at construction.
They provide `new` for preparation with default execution and `build(.., scope)` for preparation within a scope; evaluation methods have `*_scoped` versions.
For a single evaluation, use a one-shot function that creates one plan internally and evaluates it once (such as `mathieu_a`, `spheroidal_angular`, `ellipsoidal_harmonic`, or `wigner_3j`).

`HypergeometricFunction` validates and stores parameters for ${}_pF_q$ or Tricomi's $U$ and evaluates at many arguments.
Construct it with `pfq` or `u`; it adds regularized ${}_pF_q$ and first derivatives with respect to the argument or one parameter, which `hyp_pfq` and `hyperu` do not provide.
Evaluation methods returning owned values in `AngularPlan` and `HypergeometricFunction` allocate workspace on every call.
Their respective `*_scoped` methods use the supplied `AngularWorkspace` and `HypergeometricWorkspace` without allocating.

The detailed result `SpecialFunctionResult<T>` may hold four forms: an ordinary value, a scaled value, a logarithmic form, and a derivative with respect to the argument.
Each form is a `ValueWithError` (value and estimated error); a form for which no meaningful estimate can be made is `None`.
It also contains the algorithm identifier `algorithm()`, work counts `counts()`, termination status `termination()` (`SpecialFunctionTermination`), and the status of projection to an ordinary value `scalar_representation()` (`ScalarRepresentation`).

## Minimal example: three calling forms

The following cell evaluates the regularized upper incomplete Gamma function $Q(3, x)$ in three forms.
For integer shape, integration by parts gives $Q(3, x) = e^{-x}(1 + x + x^2/2)$, which serves as an independent check.
For $x < 3$, the implementation computes $P$ with a compensated lower series and returns its complement; for $x \ge 3$, it sums the same finite sum in 3 terms.
Agreement with the finite sum therefore provides an independent check only for $x < 3$.

Input `budget` is the work limit in `GammaOptions` passed to the form with options and scoped API.
The standard form always uses the default limit (65536).
For each form, the table shows the value, estimated absolute error and its basis, termination status (or error kind on failure), iteration count, difference from the finite sum, algorithm identifier, and agreement with the result of the form with options.
The final outcome is determined by the termination status of the form with options.

```rust
//| id: special-api-forms
//| ref: special-api-forms
//| title: "Evaluate upper incomplete Gamma in three forms"
//| run: reactive
//| crates: [scioxide-core, scioxide-special]
//| inputs:
//|   x: {"type":"range","label":"Argument x","description":"Uses the lower series for x < 3 and an integer-shape finite sum for x ≥ 3.","min":0.5,"max":30,"step":0.5,"value":2}
//|   budget: {"type":"range","label":"Work limit [units]","description":"Passed to GammaOptions for the form with options and scoped API. The standard form uses the default 65536.","min":1,"max":64,"step":1,"value":64}
//| cases:
//|   - {"id":"small-budget","label":"Limit 10","description":"The series needs 20 iterations, so the form with options and scoped API return ConvergenceFailure without an estimate.","inputs":{"budget":10}}
//|   - {"id":"finite-sum","label":"x = 10, limit 10","description":"For x ≥ 3, the 3-term finite sum completes even with a small limit.","inputs":{"x":10,"budget":10}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"forms","path":"/rows/0/1","approx":{"value":0.6766764161830634,"rtol":1e-14}}
//|       - {"artifact":"forms","path":"/rows/0/6","range":{"max":1e-15}}
//|       - {"artifact":"forms","path":"/rows/1/4","equals":"Converged"}
//|       - {"artifact":"forms","path":"/rows/1/5","equals":20}
//|       - {"artifact":"forms","path":"/rows/1/7","equals":"gamma/lower_compensated_series@1"}
//|       - {"artifact":"forms","path":"/rows/0/8","equals":true}
//|       - {"artifact":"forms","path":"/rows/2/8","equals":true}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: small-budget
//|     expect:
//|       - {"artifact":"forms","path":"/rows/0/6","range":{"max":1e-15}}
//|       - {"artifact":"forms","path":"/rows/1/1","equals":null}
//|       - {"artifact":"forms","path":"/rows/1/4","equals":"ConvergenceFailure"}
//|       - {"artifact":"forms","path":"/rows/2/4","equals":"ConvergenceFailure"}
//|       - {"path":"/outputs/1/state","equals":"partial"}
//|   - case: finite-sum
//|     expect:
//|       - {"artifact":"forms","path":"/rows/1/1","approx":{"value":2.769395715511576e-3,"rtol":1e-13}}
//|       - {"artifact":"forms","path":"/rows/1/5","equals":3}
//|       - {"artifact":"forms","path":"/rows/1/7","equals":"gamma/integer_upper_finite@1"}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
use scioxide_core::{Budget, ExecutionContext, SciOxideError};
use scioxide_special::{
    GammaOptions, SpecialFunctionResult, gamma_q, gamma_q_scoped, gamma_q_with_options,
};

// (form, value, estimated absolute error, estimate basis, termination status or error, iterations, difference from finite sum,
//  algorithm, agreement with the form with options)
type Row = (
    &'static str,
    Option<f64>,
    Option<f64>,
    Option<String>,
    Option<String>,
    Option<usize>,
    Option<f64>,
    Option<String>,
    Option<bool>,
);
/// Turn a result from the form with options or scoped API into one table row.
fn row(
    form: &'static str,
    outcome: &Result<SpecialFunctionResult<f64>, SciOxideError>,
    exact: f64,
    same: Option<bool>,
) -> Row {
    match outcome {
        Ok(result) => {
            let estimate = result.value();
            let value = estimate.map(|v| *v.value());
            (
                form,
                value,
                estimate.map(|v| v.absolute_error()),
                estimate.map(|v| format!("{:?}", v.reliability())),
                Some(format!("{:?}", result.termination())),
                Some(result.counts().iterations()),
                value.map(|v| (v - exact).abs()),
                Some(result.algorithm().to_string()),
                same,
            )
        }
        // If no estimate is obtained within the limit, the form with options also returns an error without a result.
        Err(e) => {
            let kind = Some(format!("{:?}", e.kind()));
            (form, None, None, None, kind, None, None, None, same)
        }
    }
}

let a = 3.0_f64;
// Independent check: finite sum for integer shape (reference value using f64 inherent methods).
let exact = (-x).exp() * (1.0 + x + 0.5 * x * x);
// Standard form: returns only the value with the default limit.
let plain = gamma_q(a, x).map_err(|e| e.to_string())?;
let limit = Budget::try_from(budget as usize).map_err(|e| e.to_string())?;
let options = GammaOptions::default().with_iteration_budget(limit);
// Form with options: returns value, estimated error, termination status, and counts from the same evaluation.
let detailed = gamma_q_with_options(a, x, options);
// Scoped API: runs as a root evaluation and returns the same result as the form with options.
let scoped = gamma_q_scoped(a, x, options, ExecutionContext::sequential());

// Agreement check: compare the standard form bit for bit with the ordinary value from the form with options, and compare the entire scoped API result.
let reference = detailed.as_ref().ok().and_then(|r| r.try_value().ok());
let plain_same = reference.map(|v| v.to_bits() == plain.to_bits());
let scoped_same = match (&detailed, &scoped) {
    (Ok(d), Ok(s)) => Some(d == s),
    _ => None,
};
let plain_row: Row = (
    "Standard form",
    Some(plain),
    None,
    None,
    None,
    None,
    Some((plain - exact).abs()),
    None,
    plain_same,
);
let rows = vec![
    plain_row,
    row("With options", &detailed, exact, None),
    row("Scoped API", &scoped, exact, scoped_same),
];
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let digits16 = serde_json::json!({ "significantDigits": 16 });
let columns = serde_json::json!([
    { "key": "0", "label": "Form" },
    { "key": "1", "label": "Q(3, x)", "type": "number", "format": digits16, "nullText": "—" },
    { "key": "2", "label": "Estimated absolute error", "type": "number", "format": sci3, "nullText": "—" },
    { "key": "3", "label": "Estimate basis", "nullText": "—" },
    { "key": "4", "label": "Termination or error", "nullText": "(not returned)" },
    { "key": "5", "label": "Iterations [count]", "type": "integer", "nullText": "—" },
    { "key": "6", "label": "|value − finite sum|", "type": "number", "format": sci3, "nullText": "—" },
    { "key": "7", "label": "Algorithm", "nullText": "—" },
    { "key": "8", "label": "Agreement with the form with options", "type": "boolean", "nullText": "—" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "forms" })
);

// Outcome: determined by the termination status of the form with options. Stops due to the limit are partial.
let outcome = match &detailed {
    Ok(result) => {
        let termination = result.termination();
        let outcome = if termination.is_success() {
            Outcome::satisfied("The form with options completed evaluation within the limit")
        } else {
            Outcome::partial("The limit was reached; the form with options retained only an intermediate estimate")
                .explanation("The standard form and try_value() return ConvergenceFailure.")
        };
        let mut outcome = outcome.status(format!("{termination:?}")).diagnostic(
            "Iteration count",
            result.counts().iterations() as f64,
            None,
        );
        if let Some(v) = result.value() {
            outcome = outcome.diagnostic("Difference from finite sum", (*v.value() - exact).abs(), None);
        }
        outcome
    }
    Err(e) => Outcome::partial("The limit was reached; the form with options returned no estimate")
        .explanation("The form with options also returns a value when the limit is at least the series iteration count.")
        .status(format!("{:?}", e.kind())),
};
emit_outcome!(outcome);
```

With the default inputs ($x = 2$, limit 64), the compensated lower series converges in 20 iterations, and the three forms agree bit for bit.
The difference from the finite sum is of the order of rounding error and smaller than the estimated absolute error.
The algorithm identifier names the selected method: `gamma/lower_compensated_series@1` for the series and `gamma/integer_upper_finite@1` for the finite sum.
If the limit is smaller than the series iteration count (case “Limit 10”), the form with options and scoped API return `ConvergenceFailure` without a value, and the outcome is partial.
The standard form uses the default limit and returns a value for the same input.
For $x \ge 3$, the 3-term finite sum is used (case “x = 10, limit 10”), so the iteration count is 3 and evaluation completes even with a small limit.

This function leaves no estimate when the limit is reached; for functions that obtain useful estimates before reaching the limit, the form with options returns that estimate with termination status `IterationLimit`.
Even then, the standard form and `try_value()` return `ConvergenceFailure`.
The estimated absolute error is not an interval enclosure; the “Estimate basis” column indicates its type.

## Reading results, errors, and diagnostics

Failures return `SciOxideError`.
Read the kind with `kind()` and the failed argument and details with `view()`.
Errors describe only what failed and carry no caller identifier.

- NaN and infinite arguments produce `NonFinite`.
  Limits at infinity are not evaluated.
- Poles produce `DomainError` (detail `Pole`); arguments outside the real domain produce `DomainError` (`OutsideDomain`).
  Points whose limits depend on the direction of approach produce `DomainError` (`Undefined`), such as $(a, x) = (0, 0)$ for regularized incomplete Gamma functions.
- Out-of-range integer parameters such as orders produce `InvalidInput` (`OutOfRange`).
- Values outside the scalar type's range produce `NumericalInstability` (`Overflow`); cancellation that the method cannot resolve, leaving no correct digits, produces `NumericalInstability` (`LossOfSignificance`).
  Underflowing values return signed 0 or subnormals without an error.
- Reaching the work limit produces `ConvergenceFailure` (`IterationLimit`); the error carries the attempted counts.
- Cancellation or reaching a deadline in a scoped API produces `ExecutionStopped`.

Only documented endpoint limits produce non-finite successful values such as `Ok(±∞)`.
In that case, the form with options has termination status `Limit` and ordinary-value projection status `InfiniteLimit`.
Values rounded to 0 and subnormals are valid values.

Termination statuses `Exact`, `Converged`, and `Limit` describe completed evaluations and make `is_success()` true.
`IterationLimit` indicates that the work limit was reached.
Termination status does not indicate whether the estimated error meets the accuracy target.

Estimated errors `ValueWithError::absolute_error()` have three possible bases (`EstimateReliability`).
`ModelBased` is an estimate derived from evaluation truncation and rounding errors.
`StatisticallyCalibrated` is an envelope measured against high-precision reference values, taking the form $k\max(\varepsilon\lvert v\rvert, \eta)$ for value $v$.
Here $\varepsilon$ is the scalar type's machine epsilon, $\eta$ the smallest positive subnormal, and $k$ a function-specific constant.
`Heuristic` makes no coverage claim.
None is an interval enclosure (proven lower and upper bounds); use `scioxide-validated` when an enclosure is needed.
Large estimated errors are returned as they are rather than converted into errors.
Errors in logarithmic forms are in natural-log units; the logarithmic form is omitted when the relative error reaches 1/2.

ULP targets checked against comparison data (independently generated high-precision reference values) differ by function family.
For example, real Γ, $\ln\Gamma$, $\psi$, and Beta target 4 ULP for binary64 and 1 ULP for binary32; real Bessel and Airy functions target 64 ULP in both precisions.
These targets apply over the checked ranges.
Complex arguments and functions without stated targets have no uniform ULP specification; use estimated errors from forms with options.
The “Specification highlights” column in each table states the target for each function.

Ordinary-value projection status `ScalarRepresentation` is one of `Finite`, `Overflow`, or `InfiniteLimit`.
Results rounded to 0 are also `Finite`, and the standard form returns `Ok(±0)`.
Even when the ordinary value overflows (`Overflow`), the form with options can retain the value in `scaled()` (a significand and a power-of-two exponent) and `logarithmic()`.
Named scaled forms such as `bessel_k_scaled` return a different function multiplied by the documented exponential factor.
