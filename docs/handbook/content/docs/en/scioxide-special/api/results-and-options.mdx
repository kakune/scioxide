These tables cover result types and argument-type rules shared by all function families, and the option types for each family.
The form with options `*_with_options` and scoped API `*_scoped` return `SpecialFunctionResult`; the standard form returns only its ordinary value ([three calling forms](oxref:special-api-call-forms)).
Option types specify computational limits rather than accuracy requirements.
`SpectralOptions` and `EllipsoidalOptions`, which control truncation and quadrature through tolerances, and `AngularOptions`, which also has memory limits, are listed with their plan types in [Legendre functions, angular momentum, and spectral functions](../legendre-angular-spectral/).

## Detailed results and estimated errors

`SpecialFunctionResult` and `ValueWithError` are read-only; users construct only `SpecialFunctionResult::zero()` to initialize memory.
None of the estimated errors is an interval enclosure (proven lower and upper bounds); `EstimateReliability` (scioxide-core) indicates the basis.

## Iteration limits by function family

Every option type is an immutable value providing `new(budget)`, `iteration_budget()`, `with_iteration_budget(budget)`, and `Default` and retaining only a `Budget` limit on iterations or coefficient evaluations.
Units are operations counted by each family's kernel (series terms, continued-fraction levels, recurrence steps, and so on) and cannot be compared across families.
Nested evaluations (forward evaluations inside inverses, Coulomb recurrences, and so on) share the same limit.
In scoped APIs, this limit becomes the evaluation's local iteration limit, and consumption is passed to the outer solve as nested counts.

## Argument and parameter types

Parameters such as orders and shapes accept the same type as the argument, and also real values when the argument is complex.
For example, with complex $z$, `bessel_j(2.5, z)` returns $J_{2.5}(z)$.

| Item | Kind | Role | Specification essentials | Explanation | Executable example |
|---|---|---|---|---|---|
| [`Parameter`](https://docs.rs/scioxide-special/0.1.0/scioxide_special/trait.Parameter.html) | Trait | Types accepted as parameters such as orders and shapes alongside argument type `T` | Implemented for `T` itself and for `R` when `T` is `Complex<R>`. Real parameters are treated as complex numbers with imaginary part $+0$ and return values agreeing bit for bit with calls passing those complex numbers. The argument type determines `T` and the result type; complex parameters require complex arguments (passing a complex parameter with a real argument does not compile). Accepted for orders of Bessel and Hankel functions such as `bessel_j` and their derivatives and scaled forms; shapes of `gamma_p`, `gamma_q`, `gamma_lower`, `gamma_upper`, and `beta_inc`; parameters of `hyp0f1`, `hyp1f1`, `hyp2f1`, `hyp2f0`, `hyperu`, and `hyp2f1_regularized`; $q$ in `hurwitz_zeta`; the order in `polylog`; $s$ and $a$ in `lerch_phi`; and $m$ in `elliptic_f`, `elliptic_e_inc`, and Jacobi elliptic functions. A sealed trait with no public methods | [Real and complex APIs](oxref:special-entry-real-complex) | - |
