Separating variables in partial differential equations yields Bessel functions in cylindrical coordinates, Airy functions at turning points in linear potentials, and elliptic integrals for large-amplitude pendulums.
Normalization constants and cumulative probabilities of probability distributions can be written using Gamma and Beta functions and their incomplete forms, while normal-distribution tails can be written using error functions.
These functions, which cannot be expressed by finitely composing elementary functions, are collectively called special functions.

`scioxide-special` evaluates Gamma and Beta functions and probability tails; error and Faddeeva functions; Airy, Bessel, Hankel, Kelvin, Struve, and parabolic cylinder functions; special integrals such as exponential integrals; elliptic integrals and Jacobi elliptic functions; hypergeometric functions; zeta functions, polylogarithms, and Lambert W; Coulomb wave functions; combinatorial numbers; Legendre functions and angular-momentum coupling coefficients; Mathieu, spheroidal, and ellipsoidal harmonic functions; and Debye, Fermi–Dirac, and transport integrals.
Definitions and notation follow NIST's DLMF, and each function's rustdoc cites the formula numbers implemented.
Real-only functions accept `f32` and `f64`; functions supporting complex numbers also accept `Complex<f32>` and `Complex<f64>` under the same names.
`faddeeva`, `lambert_w_complex`, and `parabolic_d_complex` accept only complex arguments, while `spherical_harmonic` and `voigt_complex` return complex values from real arguments.

## First computation: overflow of Γ(x) and logarithmic form

Special-function values can exceed the floating-point range after only a small change in their arguments.
The largest binary64 value is approximately $1.8 \times 10^{308}$, which $\Gamma(x)$ exceeds at $x \approx 171.62$.

The following cell evaluates the Gamma function in three forms at the selected $x$ and at the negative argument $t = -(x + 1/4)$.
They are the ordinary form `gamma`, which returns only a value; the detailed form `gamma_with_options`, which returns a result with error estimates and alternative representations; and `ln_gamma`, which discards the sign and returns $\ln|\Gamma|$.
The first table shows ordinary-form values and errors, the detailed form's projection status for ordinary values, and the sign of $\Gamma$.
The second table compares the detailed logarithmic form and `ln_gamma` against independently computed reference values.
The references use Stirling's series $\ln\Gamma(t) \approx (t - \tfrac12)\ln t - t + \tfrac12\ln(2\pi) + \tfrac{1}{12t} - \tfrac{1}{360t^3} + \tfrac{1}{1260t^5}$ on the positive side and the reflection formula $\Gamma(-s)\,\Gamma(1+s) = -\pi/\sin(\pi s)$ on the negative side.
For $t \ge 160$, the truncation error of Stirling's series is smaller than $10^{-18}$.

//| ref: special-first-gamma-overflow
//| title: "Compare ordinary values and logarithmic forms across overflow of Γ(x)"
//| run: reactive
//| crates: [scioxide-special]
//| inputs:
//|   x: {"type":"range","label":"Argument x","description":"In binary64, Γ(x) overflows above x ≈ 171.62. On the negative side, evaluate −(x + 1/4).","min":160,"max":200,"step":0.5,"value":172}
//| cases:
//|   - {"id":"finite","label":"x = 171.5","description":"Γ(171.5) fits in the binary64 range, so an ordinary value is returned.","inputs":{"x":171.5}}
//|   - {"id":"far","label":"x = 200","description":"Γ(−200.25) falls below even the subnormal range, so the ordinary value becomes signed zero.","inputs":{"x":200}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"plain","path":"/rows/0/1","equals":null}
//|       - {"artifact":"plain","path":"/rows/0/2","equals":"NumericalInstability"}
//|       - {"artifact":"plain","path":"/rows/0/3","equals":"Overflow"}
//|       - {"artifact":"log","path":"/rows/0/1","approx":{"value":711.71472580229,"rtol":1e-12}}
//|       - {"artifact":"log","path":"/rows/0/4","range":{"max":1e-12}}
//|       - {"artifact":"log","path":"/rows/1/4","range":{"max":1e-12}}
//|   - case: finite
//|     expect:
//|       - {"artifact":"plain","path":"/rows/0/3","equals":"Finite"}
//|       - {"artifact":"log","path":"/rows/0/4","range":{"max":1e-12}}
//|   - case: far
//|     expect:
//|       - {"artifact":"plain","path":"/rows/1/1","equals":0}
//|       - {"artifact":"plain","path":"/rows/1/4","equals":-1}
//|       - {"artifact":"log","path":"/rows/1/4","range":{"max":1e-12}}
use scioxide_special::{GammaOptions, gamma, gamma_with_options, ln_gamma};

// Independent reference: ln|Γ(t)| and sign from Stirling's series and the reflection formula (f64 inherent methods).
let stirling = |t: f64| {
    let (t2, ln_2pi) = (t * t, (2.0 * std::f64::consts::PI).ln());
    (t - 0.5) * t.ln() - t + 0.5 * ln_2pi + 1.0 / (12.0 * t) - 1.0 / (360.0 * t * t2)
        + 1.0 / (1260.0 * t * t2 * t2)
};
let reference = |t: f64| {
    if t > 0.0 {
        return (stirling(t), 1.0);
    }
    // Γ(−s) = −π / (sin(πs) Γ(1 + s)). Reduce s modulo 2 before taking sin.
    let s = -t;
    let sine = (std::f64::consts::PI * (s - 2.0 * (s / 2.0).floor())).sin();
    let ln_abs = std::f64::consts::PI.ln() - sine.abs().ln() - stirling(1.0 + s);
    (ln_abs, -sine.signum())
};

let mut plain_rows = Vec::new();
let mut log_rows = Vec::new();
for t in [x, -(x + 0.25)] {
    // Ordinary form: display the error classification when out of range.
    let plain = gamma(t);
    let failure = match &plain {
        Ok(_) => "None".to_string(),
        Err(e) => format!("{:?}", e.kind()),
    };
    // Detailed form: inspect the ordinary-value projection status and signed logarithmic form.
    let detailed = gamma_with_options(t, GammaOptions::default()).map_err(|e| e.to_string())?;
    let log = detailed.logarithmic().map(|l| *l.value());
    let log_magnitude = log.and_then(|l| l.log_magnitude());
    let ln_abs = ln_gamma(t).map_err(|e| e.to_string())?;
    let (expected, expected_sign) = reference(t);
    plain_rows.push((
        t,
        plain.ok(),
        failure,
        format!("{:?}", detailed.scalar_representation()),
        log.map(|l| l.sign()),
        expected_sign,
    ));
    let difference = log_magnitude.map(|l| (l - expected).abs() / expected.abs());
    log_rows.push((t, log_magnitude, ln_abs, expected, difference));
}

At the default $x = 172$, the ordinary form returns `NumericalInstability`, and the detailed form's ordinary-value status is `Overflow`.
Even then, the detailed logarithmic form retains $\ln|\Gamma(172)| \approx 711.714726$ and sign $+1$, agreeing with both `ln_gamma` and the reference.
When the input is varied from 160 to 200 in steps of 0.5, the relative difference between the logarithmic form and reference remains at most $3 \times 10^{-16}$.
Setting $x$ to 171.5 or less yields an ordinary value with status `Finite`.

On the negative side, $\Gamma(-172.25)$ is very small by the reflection formula, with its sign alternating between intervals of $(-n-1, -n)$.
At the default, $\Gamma(-172.25) \approx -5.74 \times 10^{-312}$ is returned as a subnormal number.
This is a valid rounded value, not an error.
At $x = 200$, $\Gamma(-200.25)$ falls below even the subnormal range, so the ordinary form returns signed zero $-0$ (displayed as 0 in the table), while the status remains `Finite`.
The logarithmic form still retains $\ln|\Gamma(-200.25)| \approx -863.07$ and sign $-1$.
Because `ln_gamma` returns only $\ln|\Gamma|$ with the sign discarded, use the detailed logarithmic form when the sign is needed.

## Interpreting results and errors

This computation illustrates three ways of reading results throughout the chapter.

The first is error classification.
Failures return `SciOxideError`; `kind()` distinguishes the following classifications.
`NonFinite` indicates NaN or infinite input; no function evaluates limits at infinity.
`DomainError` indicates a pole (`Pole`, such as $\Gamma(0)$), an argument outside the real domain (`OutsideDomain`), or a point with a direction-dependent limit (`Undefined`).
`InvalidInput` is returned when an integer argument such as a degree or order is out of range (`OutOfRange`).
`SizeOverflow` is returned when an exact integer result (such as `checked_bernoulli`) or an array size determined by the degree cannot be represented.
`NumericalInstability` indicates value overflow (`Overflow`) or cancellation that the method cannot resolve (`LossOfSignificance`).
`ConvergenceFailure` indicates that a work limit (`Budget`) was reached and carries counts of the work attempted.
For Mathieu and spheroidal function plans, failure of an expansion to converge before the truncation limit is also indicated by `ConvergenceFailure` (`TruncationLimit`).
A scoped evaluation that is canceled or passes its deadline produces `ExecutionStopped`.
A value too small to represent does not produce an error; signed zero or a subnormal number is returned.

The second is the detailed result.
The detailed form `*_with_options` returns `SpecialFunctionResult`, with error estimates for ordinary values, scaled values, logarithmic forms, and derivatives, together with termination status, work counts, and an algorithm identifier.
Error estimates are not interval enclosures; use `scioxide-validated` when certified lower and upper bounds are needed.
The detailed form's ordinary value is bit-for-bit identical to the ordinary form's value.

The third is the choice of representation.
Even for the same mathematical quantity, evaluating logarithmic, complementary, or scaled forms can avoid range errors and cancellation.

## Alternative representations of the same quantity

| Representation | Representative functions | Problems avoided |
|---|---|---|
| Logarithmic | `ln_gamma`, `ln_beta`, `ln_factorial`, `gamma_log_q`, `normal_log_sf`, `log_erfc` | Range errors for large factorials or small probabilities |
| Complementary | `erfc`, `gamma_q`, `beta_inc_q`, `normal_sf` | Cancellation in $1 - F(x)$ (the tail becomes 0 when $F(x)$ rounds to 1) |
| Scaled | `bessel_k_scaled`, `airy_ai_scaled`, `erfcx`, `expint_e1_scaled` | Range errors from exponential factors; the returned value is a different quantity multiplied by an exponential factor |
| Inverse | `gamma_p_inv`, `beta_inc_inv`, `erfcinv`, `normal_quantile` | Implementing your own root finder to obtain quantiles from probabilities |

[Choosing a function](choosing/) discusses which representation to select for each problem.

## Evaluation methods and scope of accuracy

Using a single series or integral representation throughout the domain encounters cancellation or slow convergence at large arguments.
The implementation therefore selects methods by argument region.
It uses defining series or rational approximations near the origin, continued fractions or recurrences in intermediate regions, and asymptotic expansions for large arguments; the selected method is recorded as an algorithm identifier in the detailed result.

Functions whose work is independent of both arguments and convergence use fixed tables, rational or Chebyshev approximations, or fixed quadrature nodes.
These include `gamma`, `ln_gamma`, `digamma`, `beta`, `ln_beta`, `erfinv`, `erfcinv`, `normal_cdf`, `normal_sf`, `normal_quantile`, integer factorials, and `binomial`; they have no scoped form.
Functions evaluated through series, continued fractions, order recurrences, or root iterations iterate within the optional work limit and have scoped forms.

Accuracy targets are defined over the ranges checked by the crate's tests against comparison data (independently generated high-precision reference values).
For real binary64 arguments, targets are 4 ULP for complete Gamma and Beta functions and `digamma` and `polygamma`; 32 ULP for incomplete Gamma and Beta functions and their inverses; and 64 ULP for real Bessel and Airy functions, hypergeometric functions ${}_0F_1$, ${}_1F_1$, ${}_2F_1$, and $U$, Legendre functions, and Lambert W.
The 32 ULP for incomplete Gamma applies to the tested range; a wider sample of 4160 points has shown a maximum of 90 ULP.
For real `riemann_zeta` and `dirichlet_eta`, and for `hurwitz_zeta` with $s > 1$, there is no ULP target; they report an estimated error at most $64\varepsilon|\text{value}|$.
Complex arguments and functions absent from the accuracy table (including Kelvin, parabolic cylinder, angular-momentum, and spectral functions) have no uniform ULP contract; the detailed error estimate provides guidance.
Near zeros, poles, and branch points, a small absolute error can still correspond to a large relative error.

## Summary and further reading

Functions in `scioxide-special` have an ordinary form returning only the value and a detailed form returning error estimates, termination status, and alternative representations.
Even when an ordinary value exceeds the range, a detailed logarithmic or scaled form can retain the value, so inspect the error classification before choosing a different representation.
Very small values return as signed zero or subnormal numbers without an error.
Accuracy targets are defined for each function family over tested ranges and are not uniform guarantees throughout the domain.
See [Choosing a function](choosing/) for a suitable representation, [Algorithms](algorithms/) for result types and shared contracts, and the [API guide](api/) for item-specific contracts.
