`scioxide-stats` estimates statistics from samples and reports their uncertainty.
Its public procedures cover streaming moments and covariance without retaining samples; quantiles and tail means by sorting and selection; binning, kernel density estimation, and isotonic regression; descriptive statistics and distribution distances; classical and distribution tests; contingency tables and multiple testing; regression and generalized linear models; distribution fitting; resampling and power; parameter inversion from probabilities and conjugate posteriors; survival analysis and time series; and multivariate estimation.
This guide identifies entry points by purpose and collects all 635 public items in tables organized by use.
Item-name links point to the version 0.1.0 API reference on docs.rs.

## Type relationships

### Accumulators and summaries

Accumulators such as `OnlineMoments` add observations individually with `observe` and combine another accumulator's state with `merge`.
`snapshot` returns an immutable copy of the state as a summary and cannot fail.
A summary rounds means, variances, and standard errors on each query and returns them in `Result<Option<S>, SciOxideError>`.
To read quantities outside the range of `S` without rounding, use `MomentsSnapshot::scaled_variance_of_sample_mean` to obtain the mean's variance $s^2/n$ as an extended-exponent `Scaled<S>`.

### Borrowed views and policies

Batch functions accept a borrowed view (`BatchView`) describing the data layout and policies for missing values, non-finite values, and execution (`StatisticsOptions`).
A view selects the sample axis through an axis specification (`Axis`); the remaining axes index independent batches.
Missingness markers and weights use observation order, with batch indices outermost and sample indices innermost, regardless of physical strides.

### Calling forms

Many procedures provide the following forms, ordered from least to most configurable.

- A one-shot function `f(data)` accepts only problem data, allocates workspace and output, and computes through sequential native execution (`mean`, `t_test_one_sample`, `kaplan_meier`, `bootstrap`).
  Settings are fixed to the defaults in the table below.
- A detailed form `f_with_options(data, …, options)` accepts settings implementing `Default` (such as `ClassicalOptions`, `StatisticsOptions`, or `MultivariateOptions`) and convention arguments.
  For prepared types, `new(data)` is the one-shot constructor and `with_options` is the detailed form (`PreparedPca`, `PreparedCca`, `GaussianKde`).
- Prepared types (`Prepared…`, `…Plan`) validate and preprocess once.
  Owned forms `fit`, `evaluate`, and `test` allocate and return results.
- Scoped forms `f_scoped(…, scope)` and `fit_scoped` on prepared types accept a root execution context (`ExecutionContext`) or a parent solve's `SolveContext`, sharing evaluation limits and cancellation with the parent.
- Borrowed forms `f_into(…, output, workspace, context)` use workspace reserved after querying requirements (`…Workspace`, `…Requirements`) and caller-owned output, allocating nothing after reservation.

One-shot functions fix the following settings.

| Choice | One-shot value |
|---|---|
| Weights | Unweighted (except functions focused on a weight model) |
| Sample-spread divisor | $n-1$ |
| Quantiles | Hyndman–Fan type 7 (linear interpolation) |
| Mean interval | Two-sided 95% Student t interval with $n-1$ degrees of freedom |
| Test alternative | Two-sided (`Greater` for Chatterjee and Page) |
| Test calibration | `Auto` |
| Continuity correction | Half a unit (Yates' correction for Pearson statistics in 2×2 tables) |
| Independent two-sample t test | Welch (does not assume equal variances) |
| Zero differences in signed-rank tests | Omit (`Discard`) |
| Brunner–Munzel reference distribution | Student's t |
| Center for variance tests | Median |
| k-sample Anderson–Darling ties | Midranks |
| Observations equal to the pooled median in median tests | Count below the median (`Below`) |
| Isotonic regression direction | Increasing |
| Robust-slope intercept | Median of the residual intercepts $y_i - \hat\beta_1 x_i$ (`Joint`) |
| Kernel-density bandwidth | Scott's rule, full covariance |
| Missing and nonfinite values | Reject |
| Bootstrap | Independent BCa, 9999 repetitions, 95% |
| Permutations | Independent randomized assignments, 9999 repetitions |

One-shot functions using randomness also accept a generator argument and do not choose a seed internally.
Jackknife does not use a generator.
Settings types keep fields private, provide infallible configuration methods and `Default`, and validate values during preparation or execution.

### Injected solvers and generators

Distribution fitting, Cox regression, ARIMA, nonlinear orthogonal distance regression, and optimal transport do not embed an optimizer.
scioxide-stats prepares the objective, and the caller-supplied `FitSolver` or `TransportSolver` solves it.
GLMs use built-in iteratively reweighted least squares; selecting `GlmSolver::Injected` replaces the built-in iteration with a supplied `FitSolver` that minimizes the objective.
Procedures using randomness accept scioxide-random generators as arguments and use no implicit environmental randomness.
Cancellation and deadlines are conveyed through scioxide-core's `ExecutionContext` or a parent `SolveContext`.
Iteration limits for injected solvers, resampling, and σ-clipping follow per-call settings (solver limits, replicate counts, and pass limits) and are not constrained by the parent's iteration limit.
Child evaluations and generator calls count toward every computation-count limit shared by the parent.

### Results carrying conventions

Results for quantiles, tail means, confidence intervals, and tests return the conventions used (such as `QuantileConvention`, `TailMeanConvention`, `MeanIntervalMethod`, or `ClassicalMethod`) and assumptions with the values.

## Minimal example: merging split summaries and checking with two passes

Split 8 observations into the first $k$ and the remainder, summarize them in separate `OnlineMoments` accumulators, and combine them with `merge`.
The first table shows summaries of the two parts before merging; changing $k$ changes their counts and values.
The mean of a part with no observations and sample variance of a part with at most one observation are undefined, so they become `None` and display as “undefined.”
The second table compares the merged summary's mean, variance, skewness, and excess kurtosis with a two-pass calculation that first computes the mean and then sums powers of deviations.
The two-pass calculation is an independent reference using f64's inherent methods.
Then read a two-sided 95% interval for the mean with `confidence_interval_of_mean()` and check the error classification for NaN and that the accumulator is unchanged after the error.

```rust
//| id: stats-api-split-moments
//| ref: stats-api-split-moments
//| title: "Merge moments accumulated separately and compare with a two-pass calculation"
//| run: reactive
//| crates: [scioxide-stats]
//| inputs:
//|   split: {"type":"range","label":"Number k of observations in the first part [count]","description":"Split point for separately accumulating the first and second parts. At 0 and 8, one part is empty.","min":0,"max":8,"step":1,"value":3}
//| cases:
//|   - {"id":"empty-left","label":"k = 0","description":"The first part is empty, so its mean and sample variance are undefined; merging gives the second part's summary itself.","inputs":{"split":0}}
//|   - {"id":"singleton-left","label":"k = 1","description":"The first part contains one observation, so its mean is defined but its sample variance is undefined.","inputs":{"split":1}}
//|   - {"id":"empty-right","label":"k = 8","description":"The second part is empty, so merging with the empty accumulator is the identity operation.","inputs":{"split":8}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"parts","path":"/rows/0/1","equals":3}
//|       - {"artifact":"parts","path":"/rows/0/2","approx":{"value":3.3333333333333335,"rtol":1e-14}}
//|       - {"artifact":"parts","path":"/rows/1/2","approx":{"value":12.4,"rtol":1e-14}}
//|       - {"artifact":"moments","path":"/rows/0/1","approx":{"value":9,"rtol":1e-15}}
//|       - {"artifact":"moments","path":"/rows/2/1","approx":{"value":80.57142857142857,"rtol":1e-14}}
//|       - {"artifact":"moments","path":"/rows/3/3","range":{"max":1e-14}}
//|       - {"artifact":"moments","path":"/rows/4/3","range":{"max":1e-14}}
//|       - {"artifact":"interval","path":"/rows/0/2","equals":7}
//|       - {"artifact":"interval","path":"/rows/0/3","approx":{"value":1.4958,"atol":1e-3}}
//|       - {"artifact":"interval","path":"/rows/0/4","approx":{"value":16.5042,"atol":1e-3}}
//|       - {"artifact":"interval","path":"/rows/0/5","equals":"StudentT"}
//|       - {"artifact":"error","path":"/rows/0/1","equals":"NonFinite"}
//|       - {"artifact":"error","path":"/rows/0/2","equals":1}
//|   - case: empty-left
//|     expect:
//|       - {"artifact":"parts","path":"/rows/0/1","equals":0}
//|       - {"artifact":"parts","path":"/rows/0/2","equals":null}
//|       - {"artifact":"parts","path":"/rows/0/3","equals":null}
//|       - {"artifact":"moments","path":"/rows/0/1","approx":{"value":9,"rtol":1e-15}}
//|       - {"artifact":"moments","path":"/rows/4/3","range":{"max":1e-14}}
//|   - case: singleton-left
//|     expect:
//|       - {"artifact":"parts","path":"/rows/0/2","approx":{"value":2,"rtol":1e-15}}
//|       - {"artifact":"parts","path":"/rows/0/3","equals":null}
//|       - {"artifact":"moments","path":"/rows/2/1","approx":{"value":80.57142857142857,"rtol":1e-14}}
//|       - {"artifact":"moments","path":"/rows/2/3","range":{"max":1e-13}}
//|   - case: empty-right
//|     expect:
//|       - {"artifact":"parts","path":"/rows/1/1","equals":0}
//|       - {"artifact":"parts","path":"/rows/1/2","equals":null}
//|       - {"artifact":"moments","path":"/rows/3/1","approx":{"value":1.8169,"atol":1e-4}}
use scioxide_stats::{BiasCorrection, KurtosisConvention, MomentOrder, OnlineMoments};

// Eight dimensionless observations. The final value 30 creates a right tail.
let data = [2.0_f64, 4.0, 4.0, 5.0, 7.0, 9.0, 11.0, 30.0];
let k = split as usize;
// Accumulate the first and second parts separately, retaining central moments through order 4.
let mut left = OnlineMoments::new(MomentOrder::Fourth);
let mut right = OnlineMoments::new(MomentOrder::Fourth);
for &x in &data[..k] {
    left.observe(x).map_err(|e| e.to_string())?;
}
for &x in &data[k..] {
    right.observe(x).map_err(|e| e.to_string())?;
}

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let digits = serde_json::json!({ "significantDigits": 15 });
let fixed4 = serde_json::json!({ "fractionDigits": 4 });

// Summaries of parts before merging. A mean with zero observations and sample variance with at most one observation become None.
let mut parts = Vec::new();
for (name, part) in [("First part", &left), ("Second part", &right)] {
    let s = part.snapshot();
    let mean = s.mean().map_err(|e| e.to_string())?;
    let variance = s.sample_variance().map_err(|e| e.to_string())?;
    parts.push((name, s.count(), mean, variance));
}
emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "Part" },
        { "key": "1", "label": "Count [observations]", "type": "integer" },
        { "key": "2", "label": "Mean [-]", "type": "number", "format": digits, "nullText": "Undefined" },
        { "key": "3", "label": "Sample variance [-]", "type": "number", "format": digits, "nullText": "Undefined" }
    ]),
    parts,
    metadata = serde_json::json!({ "id": "parts" })
);

left.merge(&right).map_err(|e| e.to_string())?;
let s = left.snapshot();

// Independent check: a two-pass calculation that first computes the mean, then sums powers of deviations (a reference using f64's inherent methods).
let n = data.len() as f64;
let mean = data.iter().sum::<f64>() / n;
let central = |p: i32| data.iter().map(|x| (x - mean).powi(p)).sum::<f64>() / n;
let (m2, m3, m4) = (central(2), central(3), central(4));

// Every quantity is defined for 8 observations, so convert None to an error explaining the failure.
let undefined = || "A quantity expected to be defined for 8 observations was undefined".to_string();
let rows = [
    ("Mean", s.mean(), mean),
    ("Population variance (divisor n)", s.population_variance(), m2),
    ("Sample variance (divisor n-1)", s.sample_variance(), m2 * n / (n - 1.0)),
    ("Skewness (uncorrected)", s.skewness(BiasCorrection::None), m3 / m2.powf(1.5)),
    (
        "Excess kurtosis (uncorrected)",
        s.kurtosis(BiasCorrection::None, KurtosisConvention::Fisher),
        m4 / (m2 * m2) - 3.0,
    ),
];
let mut checks = Vec::new();
for (name, computed, reference) in rows {
    let c = computed.map_err(|e| e.to_string())?.ok_or_else(undefined)?;
    checks.push((name, c, reference, (c - reference).abs()));
}
emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "Quantity" },
        { "key": "1", "label": "Merged summary [-]", "type": "number", "format": digits },
        { "key": "2", "label": "Two-pass check [-]", "type": "number", "format": digits },
        { "key": "3", "label": "Absolute difference [-]", "type": "number", "format": sci3 }
    ]),
    checks,
    metadata = serde_json::json!({ "id": "moments" })
);

// Two-sided 95% Student t interval. Undefined sample variance gives Ok(None).
let interval = s
    .confidence_interval_of_mean()
    .map_err(|e| e.to_string())?
    .ok_or_else(undefined)?;
let method = format!("{:?}", interval.method());
let assumptions = format!("{:?}", interval.assumptions());
let bounds = interval.bounds();
emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "Estimate [-]", "type": "number", "format": fixed4 },
        { "key": "1", "label": "Standard error [-]", "type": "number", "format": fixed4 },
        { "key": "2", "label": "Degrees of freedom [-]", "type": "number", "format": fixed4, "nullText": "None" },
        { "key": "3", "label": "Lower endpoint [-]", "type": "number", "format": fixed4 },
        { "key": "4", "label": "Upper endpoint [-]", "type": "number", "format": fixed4 },
        { "key": "5", "label": "Method" },
        { "key": "6", "label": "Assumptions" }
    ]),
    vec![(
        interval.estimate(),
        interval.standard_error(),
        interval.degrees_of_freedom(),
        bounds.lower(),
        bounds.upper(),
        method,
        assumptions,
    )],
    metadata = serde_json::json!({ "id": "interval" })
);

// NaN produces an error, and the accumulator count remains unchanged after the error.
let mut probe = OnlineMoments::<f64>::new(MomentOrder::Second);
probe.observe(1.0).map_err(|e| e.to_string())?;
let kind = match probe.observe(f64::NAN) {
    Ok(()) => return Err("NaN was accepted".to_string()),
    Err(error) => format!("{:?}", error.kind()),
};
emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "Supplied value" },
        { "key": "1", "label": "Error kind" },
        { "key": "2", "label": "Count after the error [count]", "type": "integer" }
    ]),
    vec![("NaN", kind, probe.count())],
    metadata = serde_json::json!({ "id": "error" })
);
```

At default $k = 3$, the first part's mean is $10/3 \approx 3.333$ and the second part's mean is $62/5 = 12.4$.
At $k = 0$ the first part's mean and sample variance are undefined; at $k = 1$ its sample variance is undefined; at $k = 8$ the second part is empty.

The merged summary has mean 9, population variance $564/8 = 70.5$, sample variance $564/7 \approx 80.571$, uncorrected skewness 1.8169, and excess kurtosis 1.9902.
At default $k = 3$, the difference is $2.2 \times 10^{-16}$ for skewness and $8.9 \times 10^{-16}$ for excess kurtosis; the other quantities agree.
The largest differences are $1.4 \times 10^{-14}$ for population and sample variances at $k = 1$, with relative differences of about $2 \times 10^{-16}$.
Changing $k$ keeps differences at rounding scale; merge order affects only rounding.
Merging an empty part leaves values unchanged, and the merges at $k = 0$ and $k = 8$ give the nonempty summary itself.

The 95% interval is $[1.496, 16.504]$; its recorded method is `StudentT` with 7 degrees of freedom, and its assumption is `IndependentNormal`.
This is a nominal interval assuming independent normal observations.
This calculation does not establish that this assumption holds for the 8 observations including the outlying value 30.
Supplying NaN gives classification `NonFinite`, and the count remains 1 after the error.

## Reading results, errors, and diagnostics

### Undefined quantities and failures

Mathematically undefined quantities, such as the mean of an empty sample or sample variance of a single point in a streaming summary, or the correlation of a constant sequence, return `None` within `Option`.
Test results always contain a numerical p-value.
Invalid input, unrepresentable results, and computational breakdown return `Err` rather than being replaced with zero or NaN.
Summary queries return `Result<Option<S>, SciOxideError>` per quantity, so even if one quantity overflows to `Err`, other quantities in the same summary remain readable.

### Error classification

Failures return scioxide-core's `SciOxideError`; read the classification with `kind()`.
The main classifications in this crate are listed below.

| Kind | Main causes |
|---|---|
| `InvalidInput` | Too few observations for the statistic, probabilities or confidence levels outside their ranges, negative or noninteger weights disallowed by the model, missing values under `MissingPolicy::Reject`, or settings unsuitable for the method |
| `NonFinite` | NaN or infinite observations under `NonFinitePolicy::Reject`, non-finite weights or parameters, or non-finite values returned by caller-supplied functions |
| `DimensionMismatch` | Missing-value masks, weights, output, or workspace with lengths inconsistent with the data |
| `NumericalInstability` | Degenerate samples, such as zero variance in a test dividing by standard error, or results outside the output type's range |
| `ConvergenceFailure` | Exact tests, permutation enumeration, or iterations exceeding a configured work limit (such as `ClassicalOptions::max_work`); incomplete termination of a one-shot function (table below) |
| `ResourceLimit`, `SizeOverflow`, `AllocationFailure` | Workspace exceeding a byte limit such as `StatisticsOptions::max_bytes` or allocation failure |
| `Singular` | Rank-deficient design matrix in iteratively reweighted least squares within a one-shot function |
| `ExecutionStopped` | A one-shot function stopped by cancellation or deadline |
| `NotImplemented` | A solver requests a derivative not provided by `FitDerivatives` |
| `DomainError` | For example, an observation with zero probability during distribution fitting (`PreparedFit`) |

Each function's rustdoc lists its conditions.
Errors from caller-supplied functions and samplers propagate unchanged.
Errors describe what failed (classification, `Argument` or `Quantity`, and detail) and carry no caller identity.

### Committing output

Every function validates input before writing output.
Accumulator updates and borrowed functions leave state or output unchanged on `Err`.
Workspace may change on error but remains reusable.
Caller-supplied functions and random generators may have been called and advanced their state before an error.
The `_in_place` functions leave arrays unchanged when validation fails and change their ordering on success.

### Termination reasons

Detailed, scoped, and borrowed forms of procedures with iteration or limits (GLMs, Huber regression, distribution fitting, Cox regression, resampling, simulated power, parameter inversion, and others) report success or failure through one `StatsTermination`.
They return a report in `Ok` even when stopped by a limit, cancellation, or deadline.
`StatsTermination::is_success()` is true for `Completed`, `Converged`, and `ExactFit`.
When it is false, do not treat the report's values as converged estimates or completed calculations.

One-shot functions do not return incomplete estimates.
Successful termination returns the answer; other termination reasons map to the following errors.

| Termination reason | One-shot function error |
|---|---|
| `BudgetExhausted` | `ConvergenceFailure`. The reason is `IterationLimit` for GLMs and Huber regression, `NestedSolver` for injected solvers (distribution fitting, `ppcc_max`, `power_transform_normmax`, Cox regression), and the sample-count resource limit for resampling |
| `Stopped` | `ExecutionStopped` |
| `NotConverged` | `ConvergenceFailure` (`NestedSolver`) |
| `NoProgress` | `ConvergenceFailure` (`Stagnation`) |
| `Separated` | `ConvergenceFailure` (`Divergence`) |
| `RankDeficient` | `Singular` |

### Three kinds of uncertainty

Distinguish floating-point rounding error, statistical uncertainty (standard errors, confidence intervals, and p-values), and Monte Carlo error (from the number of resampling or simulation replicates).
Confidence intervals, credible intervals, and test p-values are estimates under the recorded assumptions, not numerical enclosures or coverage guarantees.

### Recording conventions

Results include the quantile definition, tail-mean boundary handling, interval method and degrees of freedom, and calibration actually used for tests.
Record conventions with values when comparing results that use different conventions.
