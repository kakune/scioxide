Distributed collection systems and parallel processing combine statistics accumulated separately in partitions.
Simply averaging partition means and variances omits variation from differences between partition means, giving incorrect overall variance or covariance.
This page partitions observations of temperature $T$ and power $P$, aggregates them with `OnlineCovariance`, merges with `merge`, and compares the result with whole-sample aggregation.
The merge formulas are derived in [Online means, variances, higher moments, and covariance](oxref:stats-online-merging-partials).

## Merging covariance and computing a regression slope

Let two partitions $A$ and $B$ have sizes $n_A$ and $n_B$ ($n = n_A + n_B$) and means $(\bar T_A, \bar P_A)$ and $(\bar T_B, \bar P_B)$.
The sum of cross-deviation products $C = \sum_i (T_i - \bar T)(P_i - \bar P)$ merges as

$$
C_{AB} = C_A + C_B + \frac{n_A n_B}{n}\,(\bar T_B - \bar T_A)(\bar P_B - \bar P_A)
$$


The final term is covariation from differences between partition means; a weighted average of partition covariances omits it.
When a series with increasing temperature is partitioned by time, the partition mean temperatures and powers rise together, so this term accounts for most of the covariance.

`OnlineCovariance` contains the same state as `OnlineMoments` for each of $T$ and $P$, together with the co-moment $C/n$.
`observe(x, y)` merges one pair as a size-1 partition; `merge` merges another partition's accumulator.
Both cost $O(1)$ and do not retain the sample.
Merging accumulators with different retained orders (`MomentOrder`) returns `InvalidInput`; merging an empty accumulator changes nothing.
The `CovarianceSnapshot` returned by `snapshot` contains `sample_covariance` ($C/(n-1)$), `population_covariance` ($C/n$), `correlation`, `mean_x`, `mean_y`, and a `MomentsSnapshot` for each coordinate (`marginal_x`, `marginal_y`); with fewer than two pairs, sample covariance is `None`.

The least-squares line $P = \alpha + \beta T$ has slope and intercept computed from the aggregated statistics as

$$
\hat\beta = \frac{C}{\sum_i (T_i - \bar T)^2} = \frac{s_{TP}}{s_T^2}, \qquad \hat\alpha = \bar P - \hat\beta\,\bar T
$$


Covariance has units °C·W, slope has units W/°C, and correlation is dimensionless.
scioxide-stats has no public function returning a slope from `CovarianceSnapshot`, so this page divides `sample_covariance` by `marginal_x().sample_variance()`.
Use `linear_regression` when you need regression estimates and intervals.

## Observation model and analytical slope

For $N = 240$ observations, temperature increases uniformly from 12 °C to 30 °C, and power is

$$
P_i = O + 38 + \beta\,T_i + 3\sin\!\left(\frac{2\pi i}{24}\right)\ \text{W}, \qquad T_i = 12 + \frac{18\,i}{N-1}\ \text{°C}
$$


$O = 10^p$ W is a common offset unrelated to covariance, representing a large constant component such as a building's base load.
$\beta$ is the specified temperature coefficient; the ±3 W sinusoid is deterministic variation with a period of 24 samples.

The periodic component appears uncorrelated with temperature, but in a finite sample its sample covariance with temperature is not exactly 0.
When $N$ is a multiple of 24, $\sum_i (i - (N-1)/2)\sin(2\pi i/24) = -(N/2)\cot(\pi/24)$ and $\sum_i (i - (N-1)/2)^2 = N(N^2-1)/12$, so the least-squares slope is

$$
\hat\beta = \beta - \frac{\cot(\pi/24)}{N+1}
$$


For $N = 240$, $\cot(\pi/24)/241 \approx 0.0315$ W/°C; this shift does not depend on $\beta$.
This is a property of the sample rather than a computational error.
The cell uses this analytical value as an independent check.

The following definitions block generates observations for the page's two cells.
`observations` returns offset-free pairs $(T_i, P_i - O)$ and observed pairs $(T_i, P_i)$ after adding $O$ and rounding to `f64`.

```rust
//| id: stats-merge-covariance-model
//| kind: definitions
//| title: "Observation model for temperature and power"
//| crates: [scioxide-core]
use scioxide_core::RealScalar;

/// Number of observation pairs N.
pub(crate) const PAIRS: usize = 240;

/// Offset O [W], offset-free pairs (T [°C], P − O [W]), and observed pairs (T [°C], P [W]).
pub(crate) struct PowerData {
    pub(crate) offset: f64,
    pub(crate) model: Vec<(f64, f64)>,
    pub(crate) observed: Vec<(f64, f64)>,
}

/// Tᵢ = 12 + 18 i/(N − 1), Pᵢ = O + 38 + β Tᵢ + 3 sin(2πi/24), O = 10ᵖ.
pub(crate) fn observations(offset_exponent: f64, coefficient: f64) -> PowerData {
    let offset = RealScalar::powf(10.0_f64, offset_exponent);
    let last = (PAIRS - 1) as f64;
    let model: Vec<(f64, f64)> = (0..PAIRS)
        .map(|i| {
            let t = 12.0 + 18.0 * i as f64 / last;
            let phase = 2.0 * std::f64::consts::PI * i as f64 / 24.0;
            (t, 38.0 + coefficient * t + 3.0 * RealScalar::sin(phase))
        })
        .collect();
    let observed = model.iter().map(|&(t, p)| (t, offset + p)).collect();
    PowerData {
        offset,
        model,
        observed,
    }
}
```

## Partition aggregation and merging experiment

The following cell divides observations into the specified number of partitions, aggregates each partition, and compares forward and reverse merges with whole-sample aggregation.
Partition size is $\lceil N/k \rceil$; only the final partition may be smaller.
Each row shows one path's mean power excluding the offset, sample covariance, slope, difference from the analytical slope, and correlation.

With the defaults of four partitions, offset $10^6$ W, and $\beta = 2.4$ W/°C, all three paths give mean power excluding the offset 88.400000 W, sample covariance 64.753970 °C·W, slope 2.368482 W/°C, and correlation 0.985671, agreeing in every displayed digit.
All three slopes differ from the analytical value 2.3684823 W/°C by about $3 \times 10^{-14}$ W/°C.
The two-pass calculation on deviations before adding the offset agrees with the analytical value to about $10^{-15}$ W/°C; the remaining difference comes from rounding measurements to spacing $1.2 \times 10^{-10}$ W near the offset $10^6$ W.
Setting the partition count to 2 or 16 leaves the displayed digits unchanged.

The aggregated slope 2.3685 W/°C is 0.0315 below the specified 2.4 W/°C; at $\beta = 5$ it becomes 4.9685 W/°C, lower by the same amount.
This finite-sample shift comes from the nonzero sample covariance between the periodic component and temperature, and agrees with the analytical value $\beta - \cot(\pi/24)/(N+1)$.
The plotted regression line has a slightly smaller slope than the specified dashed line.

With offset $10^0$, the difference from the analytical value falls to at most $10^{-15}$ W/°C.
At $10^{13}$ W, the measurements themselves round to spacing $2^{-9} \approx 0.002$ W; offset-subtracted mean power is 88.400391 W, the multiple of $2^{-9}$ nearest 88.4 W, and every path's slope difference is $7.8 \times 10^{-6}$ W/°C.
This is the difference between the least-squares slopes of the rounded measurements and the original values, independent of the aggregation path.
`OnlineCovariance` stores means with compensated sums and cancels common offsets before computing differences between partition means, so rounding accumulation from either online updates or partition merges does not affect the displayed digits.

## Merge order and reproducibility

Floating-point addition is not associative, so changing partitions or merge order can change the last digits of mathematically identical statistics.
In parallel aggregation, each worker aggregates a partition, and partial results are merged in a binary tree or in completion order.
Merging in completion order can change the last digits between runs on the same input, preventing bitwise reproducibility.

The scioxide-stats bulk reductions `reduce_covariance` and `reduce_moments` treat each batch of `BatchView` as one sample and return `CovarianceSnapshot` or `MomentsSnapshot` per batch.
Choose the merge policy with `StatisticsOptions::with_merge_policy`.
`MergePolicy::InputOrder` (the default) traverses observations in each batch once in input order; `MergePolicy::StablePartitions` aggregates partitions chosen by the execution plan and merges partial results in partition-index order.
The latter result does not depend on thread completion order, but the partition count depends on the `StatisticsOptions` execution policy and the workers available to the execution context, so environments with different worker counts need not agree bit for bit.
`reduce_covariance_with_options` and `reduce_covariance` use a current-thread context (`ExecutionContext::sequential_native`), resulting in one partition.
To partition across multiple workers, use `reduce_covariance_into` with workspace and an execution context.
If the entire sample is available at once, `OnlineCovariance::from_slices` aggregates it with a compensated two-pass calculation.
Its last digits can also differ from calling `observe` one pair at a time.

The following cell receives offset exponent $p$ and slope $\beta$, generates the same observations with offset included in power, varies partition count from 1 to $k_{\max}$, and compares merged sample covariances with whole-sample aggregation using `observe` one pair at a time.

//| uses: [stats-merge-covariance-model]

//|   data: stats-merge-covariance

//|     expect:
//|       - {"artifact":"drift","path":"/spec/series/0/points/7/0","equals":8}

use scioxide_stats::{
    Axis, BatchView, MergePolicy, MomentOrder, OnlineCovariance, StatisticsOptions,
    reduce_covariance_with_options,
};

// Receive the preceding cell's inputs and generate the same observations.

    .as_f64()
    .ok_or("Missing baseline exponent")?;
let coefficient = data["temperature_coefficient"]
    .as_f64()
    .ok_or("Missing slope")?;

let pairs = PAIRS;

    let value = acc
        .snapshot()
        .sample_covariance()
        .map_err(|e| e.to_string())?;
    value.ok_or_else(|| "Undefined sample covariance".to_string())
};

let summarize = |ts: &[f64], ps: &[f64]| -> Result<OnlineCovariance<f64>, String> {
    let mut acc = OnlineCovariance::new(MomentOrder::Second);
    for (&t, &p) in ts.iter().zip(ps) {
        acc.observe(t, p).map_err(|e| e.to_string())?;
    }
    Ok(acc)

        level.push(summarize(ts, ps)?);

        let width = if merge_shape == "tree" {
            2
        } else {
            level.len()
        };
        let mut next = Vec::new();
        for group in level.chunks(width) {
            let mut acc = group[0];
            for part in &group[1..] {
                acc.merge(part).map_err(|e| e.to_string())?;
            }
            next.push(acc);
        }
        level = next;
    }
    drift.push([k as f64, (covariance(&level[0])? - reference) / ulp]);
}

    columns,

With the default inputs ($p = 6$, $\beta = 2.4$ W/°C, $k_{\max} = 32$, sequential merging), partitioned and merged sample covariances differ from whole-sample aggregation by $-2$ to 0 ulp (1 ulp is $1.4 \times 10^{-14}$ °C·W).
As partition count changes, the difference moves irregularly among $-2$, $-1$, and 0 ulp; even extending to $k_{\max} = 60$ keeps it within 3 ulp.
Binary-tree merging also gives $-2$ to 0 ulp, but changing the merge shape changes which partition counts produce differences.
The statistic is mathematically identical, so the difference arises solely from rounding order.

`from_slices` differs from whole-sample aggregation by 1 ulp, while `reduce_covariance_with_options` with both merge policies agrees bit for bit.
Because this cell runs only on the current thread, `StablePartitions` also uses one partition and performs the same calculation as the path using `observe` one pair at a time.
These differences are relative errors of about $10^{-16}$, invisible in the six displayed digits but distinguishable in uses that compare results bit for bit.

## Independence assumptions and intervals

This measurement sequence has monotonically increasing temperature and a deterministic periodic power component; the observations are not an independent sample.
Applying mean intervals such as `MomentsSnapshot::confidence_interval_of_mean`, which assume independent normal samples, overstates estimation precision for this series.
[Checking confidence interval coverage with repeated experiments](../confidence-coverage/) examines how much autocorrelation reduces coverage.

## Summary

Partitioned aggregation computes the same statistic as whole-sample aggregation through merge formulas that include differences between partition means, retaining covariance and regression slope even with a large common offset.
The aggregated slope differs from the specified slope because of the finite-sample periodic component; agreement with the analytical value $\beta - \cot(\pi/24)/(N+1)$ and the two-pass deviation calculation shows this is not algorithmic error.
Partition count and merge shape can change the last digits; for bitwise reproducibility, fix merge order, select `MergePolicy::StablePartitions` for bulk reductions, and also fix worker count.
For series with dependent observations, mean standard errors and intervals constructed from the aggregated variance overstate precision.
