The correctness of interval arithmetic rests on the Fundamental Theorem of Interval Arithmetic: even with rounding error, the true real value remains inside the computed interval.
`scioxide-validated` obtains directed outward-rounded endpoints without modifying rounding-control registers, combining a round-to-nearest, ties-to-even candidate with the sign of its residual, determined through error-free transformations and exact comparisons at the limits of the exponent range.
Each endpoint of a basic operation lies at most 1 ulp outward from the nearest candidate, and computation takes $O(1)$ time with no heap allocation.

## Mathematical definition of outward directed rounding and the inclusion theorem

For a binary operation $\odot \in \{+, -, \times, /\}$ over the real field $\mathbb{R}$, the exact image set of intervals $X = [a, b]$ and $Y = [c, d]$ is defined as

$$
X \odot Y = \{ x \odot y \in \mathbb{R} \mid x \in X, \, y \in Y \}
$$


For division, exclude $y=0$.
Let $\mathbb{F}$ denote floating-point numbers together with boundary symbols $-\infty,+\infty$; downward and upward rounding are defined as follows.

$$
\operatorname{down}(x) = \max \{ f \in \mathbb{F} \mid f \le x \}, \quad \operatorname{up}(x) = \min \{ f \in \mathbb{F} \mid f \ge x \}
$$

The inclusion theorem for interval addition is then formulated as

$$
X + Y = [a + c, \, b + d] \subseteq [\operatorname{down}(a + c), \, \operatorname{up}(b + d)]
$$

For multiplication $X \times Y$, round the endpoints outward from the minimum and maximum of the four corner-product candidates $\{ac, ad, bc, bd\}$ so that

$$
X \times Y \subseteq \left[ \operatorname{down}\left(\min_{x \in \{a, b\}, y \in \{c, d\}} xy\right), \, \operatorname{up}\left(\max_{x \in \{a, b\}, y \in \{c, d\}} xy\right) \right]
$$

holds.
Provided that the rounding-environment assumptions hold, the resulting closed interval therefore contains the true image set.

## Directed rounding through exact residual tests

Switching rounding directions affects hardware state and optimization.
In supported environments, SciOxide constructs outward endpoints from nearest candidates and exact residual tests without changing the control state.
Simply adding or subtracting machine epsilon cannot guarantee inclusion across different scales or the subnormal range.

`scioxide-validated` uses an algorithm that does not change the hardware control state.


1. **Compute the nearest candidate**: First compute candidate $q = \operatorname{fl}(a \odot b)$ using the hardware's standard round-to-nearest, ties-to-even mode.
2. **Determine the exact residual sign**: Addition preserves the rounding residual with TwoSum, and multiplication uses FMA or a split product.
   Division and square root also determine the sign from the residual of a product involving the candidate.
   The residual expressions are as follows.
   - Addition: $r = a + b - q$
   - Multiplication: $r = a \cdot b - q$
   - Division: $r = a - q \cdot b$
   - Square root: $r = a - q^2$
3. **Apply a 1 ulp correction from the exact sign**: Division also accounts for the denominator's sign when ordering the true value and candidate.
   When a product has a residual smaller than a subnormal number or involves overflow, computation switches to exact comparison of fixed-length integer significands.
   Both paths produce bitwise-identical endpoints.
   Exact reductions of multiple terms use a wide integer accumulator, retaining even extreme products until final outward rounding.
   - Move the upper endpoint to the next representable number only when the true value exceeds $q$.
     For division, the sign of the difference between the true value and $q$ is determined by $r/b$ and is opposite to the sign of $r$ for a negative denominator.
   - Move the lower endpoint to the preceding representable number only when the true value is less than $q$.
   - For exact agreement ($r = 0$), both endpoints equal $q$ and the interval does not widen.
4. **Overflow**: If finite inputs produce an infinite candidate, the true value exceeds the largest finite value `MAX`.
   Set the upward endpoint to $+\infty$ (unbounded) and the downward endpoint to `MAX`, handling negative values symmetrically.

This design obtains outward endpoints for basic operations without modifying control registers.
Since $q$ is the nearest value, the corrected endpoints are the nearest downward and upward representable numbers to the true value.
Enclosures of elementary functions and widths of entire compound expressions need not be 1 ulp.

## Real-set conventions for singularities, unbounded endpoints, and signed zero

IEEE 754 floating-point operations differ in several respects from operations on real sets $\mathcal{P}(\mathbb{R})$.
`scioxide-validated` follows real-set conventions.

### Multiplication of zero and an unbounded set

IEEE 754 returns `NaN` for the invalid operation $0.0 \times (+\infty)$, but in real-set theory multiplication of any nonempty real set $S \subseteq \mathbb{R}$ by zero is exactly the singleton $\{0\}$:

$$
\{ 0 \cdot x \mid x \in [1, +\infty) \} = \{ 0 \}
$$

Thus, in `scioxide-validated`, $[0, 0] \cdot [1, +\infty)$ returns exactly $[0, 0]$ rather than `NaN`.
An unbounded endpoint (`None`) of `ExtendedInterval` is a boundary symbol indicating that the set extends to infinity; it does not mean that an infinite real number belongs to the set.

### Normalization of signed zero

Floating point has two zeros, $+0.0$ and $-0.0$, but real numbers have one zero.
`scioxide-validated` stores a zero lower endpoint normalized to $-0.0$ and a zero upper endpoint to $+0.0$.
IEEE numerical comparisons regard positive and negative zero as equal.
This normalization is a convention for consistent endpoint representation, not a consequence of different ordering between zeros.

### Separating one-sided limits in division

When denominator interval $Y = [c, d]$ contains 0 in its interior ($c < 0 < d$), the quotient set splits into negative and positive parts.
`scioxide-validated` splits $Y$ into negative region $[c, -0.0]$ and positive region $[+0.0, d]$, represents one-sided limits with signed zero, computes the four corner quotients, and returns the convex hull of the two quotient intervals.
Quotients are computed directly because rounding the reciprocal before multiplication widens the result.
A denominator containing zero, including at an endpoint, gives decoration `Trv`; a denominator consisting only of $\{0\}$ returns the empty set.

## Decoration lattice and propagation rules

The logical evidence [`Decoration`](https://docs.rs/scioxide-validated/0.1.0/scioxide_validated/enum.Decoration.html) attached during operations forms a totally ordered lattice:

$$
\operatorname{Trv} < \operatorname{Def} < \operatorname{Dac} < \operatorname{Com}
$$

When the compound operation $h(x) = (f \odot g)(x)$ is performed, the result decoration $\operatorname{dec}(h)$ follows this lattice rule:

$$
\operatorname{dec}(h) = \min\big( \operatorname{dec}(f), \, \operatorname{dec}(g), \, \operatorname{prop}(\odot, X, Y) \big)
$$

Here, $\operatorname{prop}(\odot, X, Y)$ represents properties specific to the operation.
A denominator containing 0 in division, or exclusion of a negative part in square root, gives $\operatorname{Trv}$ and hence result decoration $\operatorname{Trv}$.
The decoration is also capped by what the resulting set permits: the empty set cannot exceed $\operatorname{Trv}$, and an unbounded set cannot exceed $\operatorname{Dac}$.
Set operations `hull`, `intersection`, and `restrict` always yield $\operatorname{Trv}$.
Operations never strengthen decorations.
The constructor `DecoratedInterval::with_decoration` allows the caller to specify a decoration within what the set permits, and the caller is responsible for its justification.

## Complexity and runtime invariants

Operations and elementary functions of `DecoratedInterval` (those returning `ElementaryEnclosure`) satisfy the following conditions.

1. **Complexity**: The four arithmetic operations, square, square root, and set operations take $O(1)$ time.
   Their iteration counts do not depend on interval width or value magnitude.
2. **Storage**: Successful operations allocate no heap memory and use only fixed-size stack storage.
   `ElementaryEnclosure` also stores at most two interval pieces by value.
3. **Execution-environment checks**: Operations using outward rounding read, without modifying, the rounding-control registers at public arithmetic boundaries and after returning from user callbacks (MXCSR and the x87 control word on x86 (SSE2) and x86_64; FPCR on AArch64).
   Internal processing does not repeat the checks, and check results are not retained across calls.
   The following three conditions are checked.
   - The rounding mode is Round to Nearest, Ties to Even.
   - Flush-to-Zero (FTZ) and Denormals-are-Zero (DAZ) are disabled, enabling gradual underflow.
   - Floating-point exception traps are disabled (masked).

   If these conditions fail, or on other architectures including wasm32, `kind()` returns an error of `SciOxideErrorKind::InvalidInput` (with `InvalidInputReason::UnsupportedConfiguration` as the reason in `view()`) without an enclosure.
   Construction, membership tests, `set`, `decoration`, and set operations do not use rounding and do not perform this check.

Verification of linear systems, roots, and integrals recomputes bounds from the original problem on every verification and does not reuse proofs from previous calls.
Verifiers and Plans own execution policies, computation limits, and byte limits as `ValidatedOptions`; reserving a workspace according to the verifier's requirements avoids allocation in subsequent calls.
A verifier call reaching its computation limit returns an inconclusive decision rather than an error.
The one-shot functions `solve`, `roots`, `polynomial_roots`, and `integrate` perform the same verification with default settings and convert inconclusive decisions to errors.
These contracts appear in [Proofs with one-shot functions](oxref:validated-api-index-one-shot), [Verifier configuration and invocation](oxref:validated-api-index-configuration), and [Workspace requirements](oxref:validated-api-index-workspace) in the API guide.
