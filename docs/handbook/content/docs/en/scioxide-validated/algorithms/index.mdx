Verified computation encloses output sets from input sets and uses those enclosures to establish mathematical claims.
Inclusion of a range, existence of a solution to an equation, and uniqueness of that solution are separate claims.
A narrow interval need not contain a root.

## Conditions for interval extensions

An interval extension $F$ of a real function $f$ satisfies $f(X)\subseteq F(X)$ for an input interval $X$.
A closure implementing `IntervalScalarFunction` must enclose the function values at every input point, including rounding errors.
Simply substituting point evaluations at the two endpoints can miss extrema inside the interval.
The user must satisfy this condition because the verifier cannot detect an interval extension that is too narrow.

`IntervalBox<R>`, which handles both real and complex values, is a rectangle with intervals for its real and imaginary parts.
For real problems, set the imaginary part to an exact zero interval.
Use `IntervalLinearOperator`, `IntervalResidualOperator`, and `IntervalJacobianOperator` for linear actions, residuals, and Jacobian actions, respectively.
Use `QuadratureOracle` to enclose the integrand range and remainder.

## Proposals and proofs

A certificate is storage for candidate centers, radii, search regions, panels, and similar data.
Constructing a certificate alone establishes no mathematical claim.
The verifier recomputes the required bounds from the original problem and returns a report status.
In particular, success of `QuadratureVerifier::generate` means a proposal has been generated and differs from success of `verify`.

| Operation | Success | Meaning when unsuccessful |
|---|---|---|
| Verification of linear systems or quadrature | `Verified` | `Rejected` cannot accept the proposal; `Inconclusive` is inconclusive |
| Verification of a root claim | `Proved` | `Refuted` is a refutation; `Inconclusive` establishes neither the claim nor its opposite |
| Root isolation or polynomial covering | `Complete` | Undecided regions or capacity or resolution limits remain |
| Quadrature generation | `ToleranceReached` | A proposal may remain that fails to meet the requested accuracy; reverification is required |

The one-shot functions `solve`, `roots`, `polynomial_roots`, and `integrate` return `Ok` only for verified or complete results.
Configurable verifiers also return inconclusive reports in `Ok`, so always read the status after `?`.
`ProofInconclusive` distinguishes evaluation or iteration limits, cancellation, unbounded bounds, and method-specific reasons for inconclusiveness.
`RefinementLimit` distinguishes insufficient output capacity from resolution limits such as an unrepresentable subdivision point.

## Execution environment and storage

Outward rounding assumes round-to-nearest, ties-to-even, gradual underflow, and disabled exception traps.
Outside x86 (SSE2), x86_64, and AArch64, these assumptions cannot be checked, and `UnsupportedConfiguration` with argument `rounding_environment` is returned.
The wasm cells in this handbook mark proofs as not executed only in this case and place ordinary approximate computations in separate columns.
Operations without rounding, such as set construction and intersection, also run in wasm.

`ValidatedOptions` stores evaluation, iteration, and memory limits and the execution policy.
Reserve `LinearWorkspace`, `RootWorkspace`, and `QuadratureWorkspace` according to `LinearRequirements`, `RootRequirements`, and `QuadratureRequirements`, respectively.
For roots and quadrature, `ProofRequest::proofs(k)` specifies the batch verification count, and `ProofRequest::refinement(c)` specifies node, disk, or panel capacity.
When capacity suffices, subsequent calls do not reallocate the workspace, but the proof bounds themselves are recomputed on every call.
See the [API guide](../api/) for details of ownership and borrowing.

## Summary

An interval extension must include values over the entire input.
Distinguish the contents of a certificate from claims established through reverification.
One-shot functions return only successful results, while verifiers also report reasons for inconclusiveness.
The [examples](../examples/) compare these distinctions against known solutions and values.
