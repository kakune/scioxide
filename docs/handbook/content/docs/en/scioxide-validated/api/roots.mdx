Root APIs separate verification of claims about one region from construction of isolations or coverings of all roots.
Univariate real-function problems, nonlinear systems, and polynomials have different input representations.

## Pairing problems and claims

| Problem | Problem input | Proposal | Main entry point |
|---|---|---|---|
| Real-function roots | Value and derivative interval extensions | Interval, center, and `RootClaim` | `ScalarRootVerifier::verify` |
| System roots | Interval residual and Jacobian actions and a fixed preconditioner | Box per unknown, center, and `RootClaim` | `SystemRootVerifier::verify` |
| Polynomial counts | Coefficients ascending from the constant term | Complex disk and count including multiplicity | `PolynomialRootPlan::verify` |

Scalar interval extensions can be passed as closures of `Fn(DecoratedInterval) -> Result<DecoratedInterval, SciOxideError>`.
Systems require ordinary and interval actions; the [circle–line example](oxref:validated-system-provider) demonstrates four traits.
Polynomial Plans copy coefficients during preparation; rebuild the Plan when coefficients change.

## Ownership, borrowing, and reverification

A univariate certificate is a small value; a system's `SystemRootCertificate` owns arrays for the domain and center.
If arrays already exist, directly assemble and pass `SystemRootCertificateView`.
After changing the domain or claim with `view_mut()`, the previous report does not prove the modified claim.
`RootVerificationReport::evidence()` records the fact actually established, which need not match the requested claim.

`RootWorkspace` is shared across scalar, system, and polynomial problems, but reserve capacity for the intended call.
`ProofRequest::proofs(k)` gives the batch-verification count; `refinement(c)` gives node or disk capacity.
`NotRun` marks an unused batch-verification entry; do not treat it as a completed proof status.

## Reading isolation results

Check completeness of the reports before interpreting trees from `RootIsolation` or disks from `PolynomialRootCover`.
Individually proved roots do not enumerate all roots while undecided regions remain.
The one-shot `roots` merges duplicates from shared endpoints in a univariate tree.
Verify polynomial coverings, including count sums and disk separation, with `verify_cover`.

The [claim and binary-tree experiment](oxref:validated-root-claims-and-tree) and [disk radius and count experiment](oxref:validated-pellet-multiplicity) compare success, refutation, and undetermined results.
In the following index, examine both each type's contract and the scope proved by its results.
