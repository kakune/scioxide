The error function is defined by $\operatorname{erf}(x)=2\pi^{-1/2}\int_0^x e^{-t^2}\,dt$.
Enclosing only the integral and multiplying by an ordinary f64 normalization constant $2/\sqrt{\pi}$ does not guarantee inclusion of the full result.
Here, interval elementary functions enclose $\pi=4\arctan 1$, and square root and division also use outward rounding.

The second derivative of integrand $f(t)=e^{-t^2}$ is $f''(t)=(4t^2-2)e^{-t^2}$.
Pass these two interval extensions to `integrate`.
Cell input $x$ is dimensionless with $0\le x\le2$, defaulting to 1.
The independent reference evaluates alternating series $2\pi^{-1/2}\sum_{k\ge0}(-1)^k x^{2k+1}/(k!(2k+1))$ in f64 and is not used in the proof.

## Constructing the derivative enclosure

The chain rule gives $f'(t)=-2te^{-t^2}$; differentiating again gives $f''(t)=-2e^{-t^2}+4t^2e^{-t^2}$.
Thus, `d2f` can be constructed as the interval product of $4t^2-2$ and $e^{-t^2}$.
Repeated occurrences of $t$ mean this enclosure need not be minimal, but it satisfies the required inclusion.
The quadrature algorithm uses the supplied second-derivative enclosure in the trapezoidal remainder rather than estimating it with numerical differences.

If $[L,U]$ encloses $J=\int_0^x e^{-t^2}\,dt$ and $[c_-,c_+]$ encloses the positive normalization factor, then for $x\ge0$ their product is enclosed by $[c_-L,c_+U]$.
The actual code uses interval multiplication that also handles signs, including rounding of endpoint products.
Even a singleton interval for $f64::consts::PI$ need not contain mathematical $\pi$ itself.
Instead, construct $\pi$ from a certified enclosure of $\arctan(1)$.

## Independent check with a series

Integrating $e^{-t^2}=\sum_{k\ge0}(-1)^kt^{2k}/k!$ gives the reference series.
The cell updates $t_k=(-1)^kx^{2k+1}/k!$ by $t_{k+1}=-t_kx^2/(k+1)$ and adds $t_k/(2k+1)$.
This recurrence avoids recomputing factorials or large powers at every step.
It computes 80 terms for $0\le x\le2$, but because rounding of the sum and constants is not enclosed, this remains only an independent numerical comparison.
A reference value inside an enclosure is not a substitute for the integral proof.

```rust
//| id: validated-erf-certified-quadrature
//| ref: validated-erf-certified-quadrature
//| title: "Enclosing the error-function integral and normalization constant"
//| run: button
//| crates: [scioxide-core, scioxide-validated, scioxide-linalg]
//| inputs:
//|   x: {"type":"range","label":"Upper integration limit x","min":0,"max":2,"step":0.25,"value":1}
//| cases:
//|   - {"id":"zero","label":"x = 0","inputs":{"x":0}}
//|   - {"id":"two","label":"x = 2","inputs":{"x":2}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","approx":{"value":0.8427007929497149,"atol":1e-13}}
//|   - case: zero
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","approx":{"value":0,"atol":1e-13}}
//|   - case: two
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","approx":{"value":0.9953222650189527,"atol":1e-13}}
use scioxide_core::{SciOxideError, SciOxideErrorView, InvalidInputReason};
use scioxide_validated::DecoratedInterval as D;
use serde_json::json;
let unsupported = |error: &SciOxideError| {
    matches!(error.view(),
SciOxideErrorView::InvalidInput { argument,
reason: InvalidInputReason::UnsupportedConfiguration, .. }
if argument == scioxide_core::argument!("rounding_environment"))
};
let mut term = x;
let mut sum = x;
for k in 1..80 {
    term *= -x * x / (k as f64);
    sum += term / ((2 * k + 1) as f64);
}
let reference = 2.0 / std::f64::consts::PI.sqrt() * sum;
emit_table_with_columns!(
    ["x", "Series reference (f64, uncertified)"],
    vec![(x, reference)],
    metadata = json!({"id":"reference"})
);
let result = (|| -> Result<_, SciOxideError> {
    let f = |t: D<f64>| -> Result<D<f64>, SciOxideError> { Ok(t.square()?.neg()?.exp()?.hull()) };
    let d2f = |t: D<f64>| {
        D::point(4.0)?
            .mul(&t.square()?)?
            .sub(&D::point(2.0)?)?
            .mul(&f(t)?)
    };
    let integral = scioxide_validated::integrate(f, d2f, 0.0, x)?;
    let pi = D::point(1.0)?.atan()?.hull().mul(&D::point(4.0)?)?;
    let answer = D::from(integral).mul(&D::point(2.0)?.div(&pi.sqrt()?)?)?;
    let (lo, hi) = answer.set().bounds().unwrap();
    let rows = vec![(
        lo,
        hi,
        hi.unwrap() - lo.unwrap(),
        answer.contains(reference),
    )];
    Ok(rows)
})();
let outcome = match result {
    Ok(rows) => {
        let fmt = json!({"notation":"scientific","significantDigits":10});
        emit_table_with_columns!(
            json!([
                {"key":"0","label":"Lower endpoint","type":"number","format":fmt},
                {"key":"1","label":"Upper endpoint","type":"number","format":fmt},
                {"key":"2","label":"Width","type":"number","format":fmt},
                {"key":"3","label":"Contains reference"}
            ]),
            rows,
            metadata = json!({"id":"integral"})
        );
        Outcome::satisfied("Enclosure computation completed")
    }
    Err(error) if unsupported(&error) => Outcome::unavailable("Proof computation not executed in this environment")
        .explanation("Run the proof in a supported native environment."),
    Err(error) => return Err(error.to_string()),
};
emit_outcome!(outcome);
```

## Result width and tolerances

At $x=0$, the integration interval has zero width, so both the integral and its product with the normalization constant are exactly zero.
The reference is approximately $0.84270079295$ at $x=1$ and approximately $0.99532226502$ at $x=2$; it increases with the upper limit because the integrand is positive.
The computed width includes the trapezoidal remainder, interval-extension overestimation, and rounding of endpoints and the normalization constant.
Retain the returned numbers instead of using displayed decimal digits as exact endpoints of a new interval.

The default radius condition of `integrate` is $\sqrt\varepsilon(1+|m|)$ for midpoint $m$ of the integral before normalization.
The same value does not directly apply to the final error-function width; account for multiplication by the normalization factor.
For a specified tolerance on the final value, also use an upper bound on that factor to allocate the integral tolerance, then generate and reverify with `QuadratureVerifier`.
The [quadrature-rule comparison](oxref:validated-quadrature-assumptions) distinguishes capacity-limited termination from successful reverification of a wide enclosure.

## Summary

Compute constants multiplying an integral enclosure with their errors included as well.
The second-derivative enclosure supports the trapezoidal remainder.
Use [QuadratureVerifier](../../algorithms/certified-quadrature/) to specify tolerances or panel counts.
