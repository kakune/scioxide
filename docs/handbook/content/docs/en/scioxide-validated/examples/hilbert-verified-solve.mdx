The Hilbert matrix is defined by $H_{ij}=1/(i+j+1)$ ($i,j=0,\ldots,n-1$).
Its inverse has integer entries, so with the first unit vector as the right-hand side, the rational matrix's exact solution is the inverse's first column.
However, passing f64 coefficients to `solve` makes the rounded matrix the object of the proof.
Failure of that enclosure to contain the rational exact solution does not by itself indicate a verifier error.

The cell varies the order and compares each certified component's width with the exact solution of the rational matrix.
All quantities are dimensionless.
If nonsingularity cannot be proved, it shows the error classification rather than values.
The [mathematics of linear systems](../../algorithms/verified-linear-systems/) explains why error bounds grow as the contraction factor approaches 1.

## Exact solution of the rational matrix

For right-hand side $e_0=(1,0,\ldots,0)^T$, the solution is column 0 of the inverse.
The formula for the inverse Hilbert matrix gives its entries as

$$
x_i=(-1)^i(i+1){n+i\choose n-1}{n\choose n-i-1},\qquad i=0,\ldots,n-1
$$


The cell computes binomial coefficients with i128 integer arithmetic before displaying them, so references in this range do not undergo f64 coefficient rounding.
For $n=2$, $x=(4,-6)^T$; the first row $4-3=1$ and second row $2-2=0$ can be checked by hand.
As $n$ increases, large entries of opposite signs cancel, and small coefficient changes strongly affect the solution.

Let the stored matrix be $\widehat H=H+\Delta H$ and its solution $\widehat x$.
Then

$$
H(\widehat x-x)=-\Delta H\,\widehat x
$$


Thus $\|\widehat x-x\|\le\|H^{-1}\|\,\|\Delta H\|\,\|\widehat x\|$, showing that ill-conditioning amplifies input rounding.
This difference is separate from computational error in solving for the exact solution of $\widehat H$.
Even a narrow enclosure of the latter by `solve` does not eliminate the former.

```rust
//| id: validated-hilbert-exact-column
//| kind: definitions
//| title: "Exact solution of the rational Hilbert matrix"
//| crates: []
pub(crate) fn exact_column(n: usize) -> Vec<i128> {
    let choose =
        |a: usize, b: usize| (0..b).fold(1_i128, |v, k| v * (a - k) as i128 / (k + 1) as i128);
    (0..n)
        .map(|i| {
            let sign = if i % 2 == 0 { 1 } else { -1 };
            sign * (i + 1) as i128 * choose(n + i, n - 1) * choose(n, n - i - 1)
        })
        .collect()
}
```

## The system stored with point coefficients

```rust
//| id: validated-hilbert-verified-solve
//| uses: [validated-hilbert-exact-column]
//| ref: validated-hilbert-verified-solve
//| title: "Hilbert-matrix solutions and input rounding"
//| run: button
//| crates: [scioxide-core, scioxide-validated, scioxide-linalg]
//| inputs:
//|   order: {"type":"range","label":"Order n","min":2,"max":12,"step":1,"value":4}
//| cases:
//|   - {"id":"large","label":"n = 12","inputs":{"order":12}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","approx":{"value":16,"atol":1e-13}}
//|   - case: large
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","approx":{"value":144,"atol":1e-13}}
use scioxide_core::{SciOxideError, SciOxideErrorView, InvalidInputReason};
use serde_json::json;
let unsupported = |error: &SciOxideError| {
    matches!(error.view(),
SciOxideErrorView::InvalidInput { argument,
reason: InvalidInputReason::UnsupportedConfiguration, .. }
if argument == scioxide_core::argument!("rounding_environment"))
};
use scioxide_linalg::Matrix;
let n = order.round() as usize;
let exact = exact_column(n);
emit_table_with_columns!(
    ["Order", "Rational matrix exact solution x₀"],
    vec![(n, exact[0])],
    metadata = json!({"id":"reference"})
);
let result = (|| -> Result<_, SciOxideError> {
    let entries = (0..n)
        .flat_map(|i| (0..n).map(move |j| 1.0 / ((i + j + 1) as f64)))
        .collect();
    let a = Matrix::from_vec(n, n, entries)?;
    let mut b = vec![0.0; n];
    b[0] = 1.0;
    let certificate = scioxide_validated::solve(&a, &b)?;
    let enclosure = certificate.enclosure()?;
    let rows: Vec<_> = enclosure
        .iter()
        .enumerate()
        .map(|(i, x)| {
            let (lo, hi) = x.re.bounds().unwrap();
            (i, exact[i] as f64, lo, hi, hi.unwrap() - lo.unwrap())
        })
        .collect();
    Ok(rows)
})();
let outcome = match result {
    Ok(rows) => {
        let fmt = json!({"notation":"scientific","significantDigits":8});
        emit_table_with_columns!(
            json!([
                {"key":"0","label":"Component","type":"integer"},
                {"key":"1","label":"Rational matrix exact solution","type":"number","format":fmt},
                {"key":"2","label":"Rounded-matrix lower endpoint","type":"number","format":fmt},
                {"key":"3","label":"Rounded-matrix upper endpoint","type":"number","format":fmt},
                {"key":"4","label":"Width","type":"number","format":fmt}
            ]),
            rows,
            metadata = json!({"id":"solution"})
        );
        Outcome::satisfied("Enclosure computation completed")
    }
    Err(error) if unsupported(&error) => Outcome::unavailable("Proof computation not executed in this environment")
        .explanation("Run the proof in a supported native environment."),
    Err(error) => {
        Outcome::failed("Could not prove a solution enclosure").status(format!("{:?}", error.kind()))
    }
};
emit_outcome!(outcome);
```

## Interpreting outputs and proof limits

For example, the order-4 rational exact solution is $(16,-120,240,-140)^T$.
For point f64 coefficients, the certified interval of the first component may lie slightly below 16 and exclude 16 itself.
The “Rounded matrix” column labels make this distinction explicit.
Interval widths bound computational errors, but do not include input errors relative to the true rational coefficients.

If increasing the order prevents a proof, `NumericalInstability` indicates failure to satisfy proof conditions such as the contraction bound.
Hilbert matrices are mathematically nonsingular for every positive order, so do not interpret this as a singularity proof.
A returned `Singular` likewise represents a zero pivot in ordinary-precision LU factorization.
[Mixed-precision iterative refinement](../../../scioxide-linalg/algorithms/iterative-refinement/) improves approximate solutions and serves a different role from the proof on this page.

## Verification with interval coefficients containing the rational system

To target rational $1/(i+j+1)$ itself, create singleton intervals for the integer numerator and denominator and divide them with interval arithmetic.
Arrange their lower and upper endpoints in two matrices and pass them to `DenseIntervalOperator::new`.
Preconditioning uses an ordinary-precision LU factorization, but verification covers every matrix between the lower and upper bounds.
The original rational Hilbert matrix belongs to this set, so successful verification encloses its integer exact solution as well.

The next cell solves a different problem from the preceding point-coefficient system.
Set both cells to the same order to compare certified widths when input rounding is included.
Computation of the known integer solution shares page-local definitions.
Orders range from 2 to 8, testing membership where the rational system's integer solution is also exactly representable in f64.

```rust
//| id: validated-hilbert-rational-system
//| ref: validated-hilbert-rational-system
//| title: "Enclosing rational coefficients with intervals"
//| run: button
//| crates: [scioxide-core, scioxide-linalg, scioxide-validated]
//| uses: [validated-hilbert-exact-column]
//| inputs:
//|   exact_order: {"type":"range","label":"Interval-coefficient order n","min":2,"max":8,"step":1,"value":4}
//| cases:
//|   - {"id":"larger","label":"n = 8","inputs":{"exact_order":8}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","equals":16}
//|   - case: larger
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","equals":64}
use scioxide_core::{SciOxideError, SciOxideErrorView, InvalidInputReason};
use serde_json::json;
let unsupported = |error: &SciOxideError| {
    matches!(error.view(),
SciOxideErrorView::InvalidInput { argument, reason: InvalidInputReason::UnsupportedConfiguration, .. }
    if argument == scioxide_core::argument!("rounding_environment"))
};
use scioxide_linalg::{LuDecomposition, Matrix};
use scioxide_validated::{
    DecoratedInterval as D, DenseIntervalOperator, LinearVerifier, LuIntervalInverse,
    ValidatedOptions, point_enclosure,
};
let n = exact_order.round() as usize;
let exact = exact_column(n);
emit_table_with_columns!(
    ["Order", "Rational exact solution x₀"],
    vec![(n, exact[0])],
    metadata = json!({"id":"reference"})
);
let proof = (|| -> Result<_, SciOxideError> {
    let mut lower = Vec::new();
    let mut upper = Vec::new();
    let mut midpoint = Vec::new();
    for i in 0..n {
        for j in 0..n {
            let denominator = (i + j + 1) as f64;
            let bound = D::point(1.0)?.div(&D::point(denominator)?)?;
            let (lo, hi) = bound.set().bounds().unwrap();
            lower.push(lo.unwrap());
            upper.push(hi.unwrap());
            midpoint.push(1.0 / denominator);
        }
    }
    let lo = Matrix::from_vec(n, n, lower)?;
    let hi = Matrix::from_vec(n, n, upper)?;
    let mid = Matrix::from_vec(n, n, midpoint)?;
    let system = DenseIntervalOperator::new(lo.view(), hi.view())?;
    let factor = LuDecomposition::factor(&mid)?;
    let options = ValidatedOptions::new();
    let inverse = LuIntervalInverse::from_dense(&factor, options)?;
    let verifier = LinearVerifier::new(&system, &inverse, options)?;
    let mut rhs = vec![point_enclosure(0.0)?; n];
    rhs[0] = point_enclosure(1.0)?;
    let (report, certificate) = verifier.solve(&rhs)?;
    let bounds = certificate.map(|c| c.enclosure()).transpose()?;
    Ok((report, bounds))
})();
let outcome = match proof {
    Ok((report, bounds)) => {
        let rows: Vec<_> = (0..n)
            .map(|i| {
                let x = bounds.as_ref().map(|b| b[i].re);
                let ends = x.and_then(|x| x.bounds());
                (
                    i,
                    exact[i],
                    ends.and_then(|b| b.0),
                    ends.and_then(|b| b.1),
                    x.map(|x| x.contains(exact[i] as f64)),
                )
            })
            .collect();
        let fmt = json!({"significantDigits":12});
        emit_table_with_columns!(
            json!([
                {"key":"0","label":"Component","type":"integer"},
                {"key":"1","label":"Rational exact solution","type":"integer"},
                {"key":"2","label":"Lower endpoint","type":"number","format":fmt,"nullText":"No proof"},
                {"key":"3","label":"Upper endpoint","type":"number","format":fmt,"nullText":"No proof"},
                {"key":"4","label":"Contains exact solution","nullText":"No proof"}
            ]),
            rows,
            metadata = json!({"id":"solution"})
        );
        let result = if report.is_verified() {
            Outcome::satisfied("Enclosed solutions of all systems containing the rational Hilbert matrix")
        } else {
            Outcome::failed("Could not prove nonsingularity for all systems with the interval coefficients")
        };
        result.status(format!("{:?}", report.status()))
    }
    Err(e) if unsupported(&e) => Outcome::unavailable("Proof computation not executed in this environment"),
    Err(e) => return Err(e.to_string()),
};
emit_outcome!(outcome);
```


Interval coefficients widen the solution set itself, so a larger width than for point coefficients need not mean a worse accuracy guarantee.
The sets of problems under consideration differ.
Very ill-conditioned members within the input intervals make proof difficult; nonsingularity of the original rational matrix alone does not guarantee success for the entire set.

## Summary

Distinguish exact solutions of the stored coefficients from exact solutions of the rationally defined matrix.
Under ill-conditioning, input rounding strongly affects the solution.
To certify the rational matrix itself, enclose each coefficient in an interval and use `LinearVerifier`.
