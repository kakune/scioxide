Interpreting interval results requires separating correct inclusion from tight enclosures.
Here, comparisons with known intervals check endpoints and decorations, and the chaotic logistic map illustrates how expression form changes interval-width growth.

## Comparison with known intervals

First compare analytically known intervals to distinguish squares of the same variable from products of independent variables, and to check exclusions and decoration downgrading in division by denominators containing zero.

There are four inputs and expected results.
1. The image of square $X^2$ on interval $X = [-1.0, 1.0]$ is $[0.0, 1.0]$.
2. The enclosure of independent product $X \cdot X$ is $[-1.0, 1.0]$.
3. Dividing numerator $[1.0, 2.0]$ by denominator $[0.0, 4.0]$ gives the half-infinite interval $[0.25, +\infty)$.
4. Excluding the zero denominator gives result decoration `Decoration::Trv`.

All endpoints are exactly representable as floating-point numbers, so outward rounding does not widen them.
The cell tabulates expected set endpoints, computed endpoints and decorations, and equality with the expected set.
Expected sets are constructed without rounding and appear in every environment; computed endpoint columns are populated only in native environments.

```rust
//| id: validated-enclosures
//| ref: validated-enclosures
//| title: "Verify interval square, multiplication, division, and the arithmetic environment"
//| run: button
//| crates: [scioxide-core, scioxide-validated]
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"table-0","path":"/rows/0/0","equals":"x.square()"}
//|       - {"artifact":"table-0","path":"/rows/0/1","equals":0}
//|       - {"artifact":"table-0","path":"/rows/0/2","equals":1}
//|       - {"artifact":"table-0","path":"/rows/1/1","equals":-1}
//|       - {"artifact":"table-0","path":"/rows/1/2","equals":1}
//|       - {"artifact":"table-0","path":"/rows/2/1","approx":{"value":0.25,"atol":1e-14}}
//|       - {"artifact":"table-0","path":"/rows/2/2","equals":null}
use scioxide_core::{ExtendedInterval, SciOxideError, SciOxideErrorView, InvalidInputReason};
use scioxide_validated::DecoratedInterval as D;

// 1. Analytically known image sets. Construction uses no rounding and works in every environment.
let expected = [
    ("x.square()", ExtendedInterval::new(Some(0.0), Some(1.0))),
    ("x.mul(&x)", ExtendedInterval::new(Some(-1.0), Some(1.0))),
    ("[1, 2] / [0, 4]", ExtendedInterval::new(Some(0.25), None)),
];
let mut sets = Vec::new();
for (name, set) in expected {
    sets.push((name, set.map_err(|e| e.to_string())?));
}
// 2. Outward-rounded enclosures for X = [-1, 1], numerator [1, 2], and denominator [0, 4] with zero at an endpoint
let calculation = || -> Result<_, SciOxideError> {
    let x = D::new(-1.0_f64, 1.0)?;
    let numerator = D::new(1.0, 2.0)?;
    let denominator = D::new(0.0, 4.0)?;
    Ok([x.square()?, x.mul(&x)?, numerator.div(&denominator)?])
};
let unsupported = |error: &SciOxideError| {
    matches!(
        error.view(),
        SciOxideErrorView::InvalidInput {
            argument,
            reason: InvalidInputReason::UnsupportedConfiguration,
            ..
        } if argument == scioxide_core::argument!("rounding_environment")
    )
};
let enclosures = match calculation() {
    Ok(results) => Some(results),
    Err(error) if unsupported(&error) => None,
    Err(error) => return Err(error.to_string()),
};
use serde_json::json;
let rows: Vec<_> = sets
    .iter()
    .enumerate()
    .map(|(i, (name, set))| {
        let (elo, ehi) = set.bounds().unwrap();
        let y = enclosures.as_ref().map(|v| v[i]);
        let bounds = y.and_then(|v| v.set().bounds());
        (
            *name,
            elo,
            ehi,
            bounds.and_then(|b| b.0),
            bounds.and_then(|b| b.1),
            y.map(|v| format!("{:?}", v.decoration())),
            y.map(|v| v.set() == *set),
        )
    })
    .collect();
let missing = if enclosures.is_none() {
    "Not executed"
} else {
    "Unbounded"
};
emit_table_with_columns!(
    json!([
        {"key":"0","label":"Expression"},
        {"key":"1","label":"Expected lower endpoint","type":"number","nullText":"−∞"},
        {"key":"2","label":"Expected upper endpoint","type":"number","nullText":"+∞"},
        {"key":"3","label":"Lower endpoint","type":"number","nullText":missing},
        {"key":"4","label":"Upper endpoint","type":"number","nullText":missing},
        {"key":"5","label":"Decoration","nullText":"Not executed"},
        {"key":"6","label":"Equal sets","nullText":"Not executed"}
    ]),
    rows,
    metadata = json!({"id":"table-0"})
);
emit_outcome!(if enclosures.is_some() {
    Outcome::satisfied("Enclosed the known images")
} else {
    Outcome::unavailable("Proof computation not executed in this environment")
});
```

In a native environment (x86_64), all three expressions show true for “Equal to expected set”; `x.square()` and `x.mul(&x)` have decoration `Com`, and division has decoration `Trv`.
The lower endpoint of `x.square()` displays as `-0` under the convention normalizing a zero lower endpoint to $-0.0$; its value is 0.
Since the input endpoints are exactly representable, outward rounding introduces no widening.
In wasm32, enclosure columns display “Not executed”.

## Separating width growth: rounding, sensitivity, and dependency

When width $w(X) = U - L$ of a computed interval grows, distinguish its causes.
Width growth has three origins.

1. **Rounding width**: When the true result cannot be represented as a floating-point number, endpoints move to the neighboring outward floating-point numbers to preserve inclusion.
   One basic operation moves an endpoint at most 1 ulp from the nearest value.
2. **Propagation of input uncertainty (input sensitivity)**: The input interval's original width $w(X_{\text{in}}) > 0$ grows according to the map's derivative $|f'(x)|$.
   This is a property of the problem itself, not a defect of interval arithmetic.
3. **Dependency overestimation**: Repeated occurrences of the same variable are evaluated as independently varying values despite their actual correlation.
   Factorization, use of `square`, reformulation with a single variable occurrence, and affine arithmetic with shared noise symbols (`AffineForm`) can reduce this effect.

## Interval-width growth in the logistic map

In chaotic dynamical systems, rounding-generated widths grow each iteration through the second cause, and expression form can add the third.
Iterate the one-dimensional logistic map

$$
x_{n+1} = 4 x_n (1 - x_n) = 1 - (1 - 2x_n)^2
$$

from $x_0 = \operatorname{fl}(0.1)$ represented in binary64.
Interval arithmetic encloses the trajectory taking this binary number as the exact initial value.

Typical trajectories have Lyapunov exponent $\lambda=\ln 2$, giving a long-time average amplification of small initial errors of about 2 per iteration.
This average suggests that binary64 rounding errors become large after about 50 iterations, but guarantees neither the error for a specific initial value nor a limiting iteration count.
The cell computes actual interval widths to examine how far the position can be localized.

The two expressions are equal over the reals but have different interval-width growth.
For $X = [a, b] \subseteq [0, 1]$, the naive expression $4 \cdot X \cdot (1 - X)$ treats both factors independently, giving width $4\{b(1-a) - a(1-b)\} = 4 w(X)$ and fourfold growth per iteration.
The reformulated expression $1 - (1 - 2X)^2$ contains $X$ only once, and `square` preserves square dependency, so its width grows approximately as $|f'(x)| w(X) = 4|1 - 2x|\, w(X)$, with average growth per iteration approaching $e^{\lambda} = 2$.

The next cell iterates a floating-point trajectory and intervals from both expressions simultaneously, plotting widths on a logarithmic axis.
Dashed reference lines extend the first-iteration widths by $4^n$ and $2^n$; the expected shapes follow $4^n$ for the naive expression and, on average, $2^n$ for the reformulation.
The table displays values every 5 iterations.
Increasing iteration count $N$ reveals when the naive interval becomes unbounded and the reformulated interval width reaches $O(1)$.
Point values are uncertified approximations, as indicated by their column labels.
Point updates use only basic arithmetic, so the point column gives identical values in every environment.
Interval columns and charts are produced only in native environments.

```rust
//| id: validated-logistic-chaos
//| ref: validated-logistic-chaos
//| title: "Logistic-map point trajectory and interval enclosures from two expressions"
//| run: button
//| crates: [scioxide-core, scioxide-validated]
//| inputs:
//|   steps: {"type":"range","label":"Iteration count N [iterations]","description":"The naive expression becomes unbounded in the thirties; the reformulation reaches width O(1) around iteration 50.","min":10,"max":60,"step":5,"value":30}
//| cases:
//|   - {"id":"naive-unbounded","label":"N = 40 (naive expression becomes unbounded)","description":"The naive interval becomes unbounded at iteration 37, so its table entry at iteration 40 is “Unbounded”. The reformulated width at iteration 40 is approximately 1.9×10⁻⁴.","inputs":{"steps":40}}
//|   - {"id":"rewritten-saturates","label":"N = 60 (reformulation also loses trajectory information)","description":"The reformulated width is approximately 0.32 at iteration 50 and about 1 from iteration 55 onward, with the interval widening to about [0, 1].","inputs":{"steps":60}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"table-0","path":"/rows/0/1","approx":{"value":0.100000000000000,"atol":1e-14}}
//|       - {"artifact":"table-0","path":"/rows/1/1","approx":{"value":0.585420538734197,"atol":1e-14}}
//|       - {"artifact":"table-0","path":"/rows/6/0","equals":30}
//|       - {"artifact":"table-0","path":"/rows/6/1","approx":{"value":0.320342475185814,"atol":1e-14}}
//|   - case: naive-unbounded
//|     expect:
//|       - {"artifact":"table-0","path":"/rows/7/1","approx":{"value":0.153548305897691,"atol":1e-14}}
//|       - {"artifact":"table-0","path":"/rows/8/0","equals":40}
//|       - {"artifact":"table-0","path":"/rows/8/1","approx":{"value":0.097904876416033,"atol":1e-14}}
//|   - case: rewritten-saturates
//|     expect:
//|       - {"artifact":"table-0","path":"/rows/10/1","approx":{"value":0.560036763222377,"atol":1e-14}}
//|       - {"artifact":"table-0","path":"/rows/12/0","equals":60}
//|       - {"artifact":"table-0","path":"/rows/12/1","approx":{"value":0.872398576618023,"atol":1e-14}}
use scioxide_core::{SciOxideError, SciOxideErrorView, InvalidInputReason};
use scioxide_validated::DecoratedInterval as D;
use serde_json::json;

let n_max = steps.round() as usize;
let x0 = 0.1_f64;
// 1. Point trajectory (f64, uncertified): x ← 4x(1 − x). Basic operations give identical values across environments.
let mut points = vec![x0];
for _ in 0..n_max {
    let x = points[points.len() - 1];
    points.push(4.0 * x * (1.0 - x));
}
// 2. Interval iterations of two expressions, with fl(0.1) as the exact initial value
let calculation = || -> Result<_, SciOxideError> {
    let (one, two, four) = (D::point(1.0)?, D::point(2.0)?, D::point(4.0)?);
    let (mut naive, mut rewritten) = (D::point(x0)?, D::point(x0)?);
    let mut history = vec![(naive, rewritten)];
    for _ in 0..n_max {
        // Naive expression 4·(x·(1 − x)): x occurs twice and is treated independently
        naive = four.mul(&naive.mul(&one.sub(&naive)?)?)?;
        // Reformulation 1 − (1 − 2x)²: x occurs once and squaring uses square
        rewritten = one.sub(&one.sub(&two.mul(&rewritten)?)?.square()?)?;
        history.push((naive, rewritten));
    }
    Ok(history)
};
let unsupported = |error: &SciOxideError| {
    matches!(
        error.view(),
        SciOxideErrorView::InvalidInput {
            argument,
            reason: InvalidInputReason::UnsupportedConfiguration,
            ..
        } if argument == scioxide_core::argument!("rounding_environment")
    )
};
let history = match calculation() {
    Ok(history) => Some(history),
    Err(error) if unsupported(&error) => None,
    Err(error) => return Err(error.to_string()),
};
// Widths of bounded intervals (None when unbounded)
let width = |y: &D<f64>| y.set().bounds().and_then(|(lo, hi)| Some(hi? - lo?));
let rows: Vec<_> = (0..=n_max)
    .step_by(5)
    .map(|n| {
        let pair = history.as_ref().map(|h| &h[n]);
        (
            n,
            points[n],
            pair.and_then(|p| width(&p.0)),
            pair.and_then(|p| width(&p.1)),
            pair.map(|p| p.1.contains(points[n])),
        )
    })
    .collect();
let fmt = json!({"notation":"scientific","significantDigits":8});
let missing = if history.is_none() {
    "Not executed"
} else {
    "Unbounded"
};
emit_table_with_columns!(
    json!([
        {"key":"0","label":"Iteration count","type":"integer"},
        {"key":"1","label":"Point value (uncertified)","type":"number","format":fmt},
        {"key":"2","label":"Naive width","type":"number","format":fmt,"nullText":missing},
        {"key":"3","label":"Reformulated width","type":"number","format":fmt,"nullText":missing},
        {"key":"4","label":"Contains point","nullText":"Not executed"}
    ]),
    rows,
    metadata = json!({"id":"table-0"})
);
match &history {
    None => emit_text!(
        "Outward-rounded trajectory enclosure not executed in this environment (a supported native environment is required)"
    ),
    Some(history) => {
        // 4. Plot only positive, bounded widths on the logarithmic axis (width at n = 0 is 0)
        let series = |pick: fn(&(D<f64>, D<f64>)) -> &D<f64>| -> Vec<[f64; 2]> {
            history
                .iter()
                .enumerate()
                .filter_map(|(n, pair)| {
                    Some([n as f64, width(pick(pair)).filter(|&w| w > 0.0)?])
                })
                .collect()
        };
        let naive_points = series(|pair| &pair.0);
        let rewritten_points = series(|pair| &pair.1);
        // Reference line extending the first plotted width by rateⁿ
        let reference = |first: Option<&[f64; 2]>, rate: f64| -> Vec<[f64; 2]> {
            first.map_or(Vec::new(), |&[n0, w0]| {
                (n0 as usize..=n_max)
                    .map(|n| [n as f64, w0 * rate.powf(n as f64 - n0)])
                    .collect()
            })
        };
        let dashed = json!({"lineType": "dashed"});
        emit_line_chart!(
            &vec![
                json!({"name": "Naive expression 4·x·(1 − x)", "points": naive_points}),
                json!({"name": "Reformulation 1 − (1 − 2x)²", "points": rewritten_points}),
                json!({
                    "name": "Reference 4ⁿ",
                    "points": reference(naive_points.first(), 4.0),
                    "style": dashed
                }),
                json!({
                    "name": "Reference 2ⁿ",
                    "points": reference(rewritten_points.first(), 2.0),
                    "style": dashed
                }),
            ],
            options = &json!({
                "xLabel": "Iteration count n [iterations]",
                "yLabel": "Interval width w [-]",
                "yType": "log",
                "xMin": 0,
                "xMax": n_max
            })
        );
    }
}
emit_outcome!(if history.is_some() {
    Outcome::satisfied("Enclosed the trajectory with intervals")
} else {
    Outcome::unavailable("Proof computation not executed in this environment")
});
```

Running the same cell in an x86_64 native environment gives first-iteration widths $1.1 \times 10^{-16}$ for the naive expression and $3.3 \times 10^{-16}$ for the reformulation.
The naive width follows reference $4^n$, reaching $4.9 \times 10^{-2}$ at iteration 25.
Once its width exceeds 1, the interval extends beyond $[0, 1]$, and widths grow approximately quadratically, reaching $4.95 \times 10^{3}$ at iteration 30 and becoming unbounded at iteration 37.
The reformulated width grows by a factor of about 2 per iteration on average, reaching $2.9 \times 10^{-7}$ at iteration 30 and $3.2 \times 10^{-1}$ at iteration 50, then remaining at 1 (an interval of about $[0,1]$) from iteration 55 onward, losing trajectory-location information.
Points excluded from the chart are $n = 0$, with zero width, and iterations where the naive interval is unbounded.
Within the tabulated range, the point value always lies in the reformulated interval, but this does not prove that point value correct.
The interval guarantees inclusion of the true trajectory; the point is an approximation with accumulated rounding error.
In wasm32, this enclosure is not computed; interval table columns display “Not executed”, and a message replaces the chart.
Approximate intervals are not substituted.

## Summary and further reading

Comparison with known intervals checked results and decorations for squares, independent products, and division by denominators containing zero, using exactly representable endpoints.
Interpret interval-width growth in terms of rounding, propagation of input uncertainty, and expression dependency.
In the logistic map, two expressions equal over the reals grow in width by 4 per iteration with two variable occurrences and by 2 on average with one occurrence.
Inclusion of a floating-point point in an interval does not prove the trajectory; the outward-rounded enclosure itself provides the proof.
In wasm32 this enclosure is not computed, and no approximate interval replaces it.
