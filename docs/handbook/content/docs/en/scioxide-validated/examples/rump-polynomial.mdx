In an expression subtracting large terms, even small relative errors in each term can destroy the final result.
Evaluate the following expression at $a=77617$ and $b=33096$.

$$
f(a,b)=333.75b^6+a^2(11a^2b^2-b^6-121b^4-2)+5.5b^8+\frac{a}{2b}.
$$

Multiplying the polynomial part by 4 permits integer arithmetic and gives exactly $-8$ for these inputs.
Thus the full value is $-2+a/(2b)=-54767/66192$, approximately $-0.827396$.
The cell checks this cancellation independently with i128 integer arithmetic and compares interval enclosures of the original and simplified expressions.
All quantities are dimensionless, with inputs fixed to this integer pair.
The reference obtained by converting the rational number to f64 is rounded, while the interval evaluation of the simplified expression contains the exact rational value.

## Cancellation of large terms and an integer check

For these inputs, terms in $b^8$ have magnitude about $10^{36}$, while the full result is of order 1.
Absolute rounding errors in the large f64 terms can greatly exceed the final result.
Small relative errors in individual operations do not imply a small relative error after cancellation.

Writing the polynomial part as $P$, $333.75=1335/4$ and $5.5=11/2$ give

$$
4P=1335b^6+4a^2(11a^2b^2-b^6-121b^4-2)+22b^8
$$

this expression, whose terms can all be evaluated as integers for integer inputs.
The cell evaluates this expression at fixed inputs with i128, obtaining $4P=-8$.
Intermediate values also fit i128 here, but this method cannot be extended unconditionally to arbitrary integer inputs.
The final rational number $-2+77617/66192=-54767/66192$ has no finite binary representation, so its displayed f64 value is rounded too.

## Interval evaluation of two expressions

Interval evaluation of the original expression preserves true-value inclusion even through cancellation.
However, rounding widths of large intermediate values remain and may produce a huge interval.
Interval evaluation of the simplified expression justified by integer arithmetic needs to enclose only rounding in the final small division and addition.
This reformulation is valid because exact cancellation of the polynomial part was checked independently for these inputs.

```rust
//| id: validated-rump-polynomial
//| ref: validated-rump-polynomial
//| title: "Rump's expression and cancellation"
//| run: button
//| crates: [scioxide-core, scioxide-validated, scioxide-linalg]
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/0","approx":{"value":-8,"atol":1e-13}}
use scioxide_core::{SciOxideError, SciOxideErrorView, InvalidInputReason};
use scioxide_validated::DecoratedInterval as D;
use serde_json::json;
let unsupported = |error: &SciOxideError| {
    matches!(error.view(),
SciOxideErrorView::InvalidInput { argument,
reason: InvalidInputReason::UnsupportedConfiguration, .. }
if argument == scioxide_core::argument!("rounding_environment"))
};
let (a, b) = (77617_i128, 33096_i128);
let integer = 1335 * b.pow(6)
    + 4 * a * a * (11 * a * a * b * b - b.pow(6) - 121 * b.pow(4) - 2)
    + 22 * b.pow(8);
let (a, b) = (a as f64, b as f64);
let naive = 333.75 * b.powi(6)
    + a * a * (11.0 * a * a * b * b - b.powi(6) - 121.0 * b.powi(4) - 2.0)
    + 5.5 * b.powi(8)
    + a / (2.0 * b);
emit_table_with_columns!(
    [
        "Four times polynomial part (exact)",
        "Naive f64 value (uncertified)",
        "Rational reference (uncertified)"
    ],
    vec![(integer, naive, -54767.0 / 66192.0)],
    metadata = json!({"id":"reference"})
);
let result = (|| -> Result<_, SciOxideError> {
    let (a, b) = (D::point(a)?, D::point(b)?);
    let b2 = b.square()?;
    let b4 = b2.square()?;
    let b6 = b4.mul(&b2)?;
    let b8 = b4.square()?;
    let a2 = a.square()?;
    let inner = D::point(11.0)?
        .mul(&a2.mul(&b2)?)?
        .sub(&b6)?
        .sub(&D::point(121.0)?.mul(&b4)?)?
        .sub(&D::point(2.0)?)?;
    let ratio = a.div(&D::point(2.0)?.mul(&b)?)?;
    let original = D::point(333.75)?
        .mul(&b6)?
        .add(&a2.mul(&inner)?)?
        .add(&D::point(5.5)?.mul(&b8)?)?
        .add(&ratio)?;
    let simplified = D::point(-2.0)?.add(&ratio)?;
    let rows = [("Original expression", original), ("Simplified expression", simplified)].map(|(name, x)| {
        let (lo, hi) = x.set().bounds().unwrap();
        (name, lo, hi, hi.unwrap() - lo.unwrap())
    });
    Ok(rows)
})();
let outcome = match result {
    Ok(rows) => {
        let fmt = json!({"notation":"scientific","significantDigits":8});
        emit_table_with_columns!(
            json!([
                {"key":"0","label":"Expression"},
                {"key":"1","label":"Lower endpoint","type":"number","format":fmt},
                {"key":"2","label":"Upper endpoint","type":"number","format":fmt},
                {"key":"3","label":"Width","type":"number","format":fmt}
            ]),
            rows,
            metadata = json!({"id":"enclosures"})
        );
        Outcome::satisfied("Enclosure computation completed")
    }
    Err(error) if unsupported(&error) => Outcome::unavailable("Proof computation not executed in this environment")
        .explanation("Run the proof in a supported native environment."),
    Err(error) => return Err(error.to_string()),
};
emit_outcome!(outcome);
```

## Reading the table

First confirm that the integer column is $-8$, then inspect whether both intervals include the neighborhood of the rational reference.
Even a large difference between the original f64 value and the reference is consistent with inclusion if the original interval enclosure is wide.
The simplified enclosure has width of only a few ulps because the large cancelling terms were removed without error.

When applying this reasoning to measured data, remember input uncertainty.
The simplification shown is an identity for this particular integer pair, not a claim that the polynomial part equals $-2$ throughout neighboring inputs.
For interval inputs, construct a new reformulation preserving dependencies of the original function or an appropriate affine-arithmetic model.

## Summary

Outward rounding preserves inclusion through cancellation but does not guarantee narrow enclosures.
For these fixed inputs, integer arithmetic cancels large terms before division.
[Affine arithmetic](../../algorithms/affine-arithmetic/) addresses a different overestimation caused by variable correlations.

For details on verification methods and floating-point arithmetic, see Rump's [Verification methods (2010)](https://www.tuhh.de/ti3/rump/intlab/ActaNumerica2010.pdf).
