The Wilkinson polynomial $W(z)=\prod_{j=1}^{20}(z-j)$ illustrates root sensitivity to small coefficient changes.
Integer coefficients can be generated exactly in i128, but some are rounded when converted to f64.
`PolynomialRootPlan` proves claims about the polynomial with stored coefficients, so even without perturbation, integers are not assumed to remain exact roots.

The cell adds $\delta$ to the coefficient of $z^{19}$ and verifies “one root” claims for disks with centers $1,\ldots,20$ and radius $r$.
$\delta=-2^{-23}$ is a commonly used perturbation.
All quantities are dimensionless; $r<1/2$ makes the disks pairwise disjoint.
`Inconclusive` proves neither zero roots nor the emergence of complex roots.
Claiming coverage of all roots requires separate verification of disks and counts covering every root.

## Coefficient perturbation and approximate-root sensitivity

Differentiating a simple root $z(\delta)$ of $W(z)+\delta z^{19}=0$ at $\delta=0$ gives

$$
\frac{dz}{d\delta}\bigg|_{z=j}=-\frac{j^{19}}{W'(j)},\qquad
W'(j)=(-1)^{20-j}(j-1)!(20-j)!
$$


The large power in the numerator shows how a small coefficient change strongly affects root location.
This is a local sensitivity formula, not a guarantee of which disk a root enters under a finite perturbation.
Ill-conditioning is treated in detail in [Sensitivity of the Wilkinson polynomial](../../../scioxide-poly/examples/wilkinson-root-sensitivity/).

The cell successively multiplies integer coefficients by $(z-j)$, then converts to f64.
Five coefficients require rounding in this conversion; claims target the resulting rounded polynomial.
Even with zero perturbation, do not assume identity with the polynomial preserving the original integer coefficients exactly.
The degree and coefficient order are explicit: the array passed to `PolynomialRootPlan` starts with the constant term.

## Comparing disk counts

Fix the radius and compare $\delta=0$ with $\delta=-2^{-23}$, then vary the radius under the same perturbation.
This order distinguishes effects of coefficient changes from those of region changes.
Since the radius is below $1/2$, disks centered at neighboring integers are disjoint.
Known integer locations are initial reference points, not assumptions that perturbed roots remain inside the disks.

```rust
//| id: validated-wilkinson-root-counts
//| ref: validated-wilkinson-root-counts
//| title: "Wilkinson polynomial coefficients and root counts"
//| run: button
//| crates: [scioxide-core, scioxide-validated, scioxide-linalg]
//| inputs:
//|   perturbation: {"type":"range","label":"Coefficient perturbation δ","min":-0.00000011920928955078125,"max":0,"step":0.00000011920928955078125,"value":0}
//|   radius: {"type":"range","label":"Disk radius r","min":0.01,"max":0.4,"step":0.01,"value":0.1}
//| cases:
//|   - {"id":"perturbed","label":"δ = −2⁻²³","inputs":{"perturbation":-0.00000011920928955078125}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","approx":{"value":5,"atol":1e-13}}
//|   - case: perturbed
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/2","approx":{"value":-1.1920928955078125e-07,"atol":1e-13}}
use scioxide_core::{SciOxideError, SciOxideErrorView, InvalidInputReason};
use serde_json::json;
let unsupported = |error: &SciOxideError| {
    matches!(error.view(),
SciOxideErrorView::InvalidInput { argument,
reason: InvalidInputReason::UnsupportedConfiguration, .. }
if argument == scioxide_core::argument!("rounding_environment"))
};
use scioxide_core::Complex;
use scioxide_validated::{
    PolynomialRootCertificate, PolynomialRootPlan, RootDisk, ValidatedOptions,
};
let mut exact = vec![1_i128];
for j in 1..=20 {
    let mut next = vec![0_i128; exact.len() + 1];
    for (k, &c) in exact.iter().enumerate() {
        next[k] -= j * c;
        next[k + 1] += c;
    }
    exact = next;
}
let mut coefficients: Vec<f64> = exact.iter().map(|&c| c as f64).collect();
coefficients[19] += perturbation;
let rounded = exact.iter().filter(|&&c| (c as f64) as i128 != c).count();
emit_table_with_columns!(
    ["Order", "Coefficients rounded in f64 conversion", "z¹⁹ perturbation"],
    vec![(20, rounded, perturbation)],
    metadata = json!({"id":"reference"})
);
let result = (|| -> Result<_, SciOxideError> {
    let plan = PolynomialRootPlan::new(&coefficients, ValidatedOptions::new())?;
    let mut rows = Vec::new();
    for j in 1..=20 {
        let certificate = PolynomialRootCertificate {
            disk: RootDisk {
                center: Complex::new(j as f64, 0.0),
                radius,
            },
            count: 1,
        };
        let report = plan.verify(certificate)?;
        rows.push((j, radius, report.count(), format!("{:?}", report.status())));
    }
    Ok(rows)
})();
let outcome = match result {
    Ok(rows) => {
        emit_table_with_columns!(
            json!([
                {"key":"0","label":"Center real part","type":"integer"},
                {"key":"1","label":"Radius","type":"number"},
                {"key":"2","label":"Proved count","type":"integer","nullText":"Undetermined"},
                {"key":"3","label":"Verification status"}
            ]),
            rows,
            metadata = json!({"id":"counts"})
        );
        Outcome::partial("Per-disk decisions shown in the table; coverage of all roots remains unproved")
    }
    Err(error) if unsupported(&error) => Outcome::unavailable("Proof computation not executed in this environment")
        .explanation("Run the proof in a supported native environment."),
    Err(error) => return Err(error.to_string()),
};
emit_outcome!(outcome);
```

## Undetermined counts and coverage decisions

A row with `Proved` has 1 root in its disk, counting multiplicity.
A row with `Refuted` has a different proved count; read `count()`.
A blank in a row with `Inconclusive` indicates that the computation could not determine the count.
An undetermined label alone cannot distinguish a root that actually left the disk from failure to prove the inequality near a boundary.

If every disk is proved to have one root, the disks are disjoint, and their counts sum to 20, they mathematically cover all roots.
This cell compares individual proposals only; to receive success through the covering API, pass the same certificates to `verify_cover`.
When undecided disks remain, another option uses `isolate` to expand and merge disks from approximate roots.
Counting a cluster within one disk does not mean each root has been individually isolated.
The [boundary-root experiment](oxref:validated-pellet-multiplicity) gives an example where the cause of inconclusiveness can be identified analytically.

## Summary

Exact coefficient generation differs from exact f64 storage.
An undetermined count does not establish absence of roots.
See [Root counts in disks](../../algorithms/polynomial-root-counts/) for the strict Rouché and Pellet inequalities.
