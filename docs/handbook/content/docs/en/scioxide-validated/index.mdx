`scioxide-validated` provides outward-rounded interval arithmetic and verification of linear systems, roots, and integrals.
An approximation returns a single number, whereas a certified enclosure returns a set containing the true value.
Interval arithmetic can propagate input uncertainty and provide a posteriori error bounds for an already computed approximate solution.
The distinction between a priori and a posteriori bounds is separate from the distinction between an error estimate and a proven upper bound.

## Approximations and certified enclosures

First compare the product and square of $X=[-1,1]$.
The range of the product of independently varying $x,y\in X$ is $[-1,1]$, but the range of the square of the same variable is $[0,1]$.
`x.mul(&x)` treats the two occurrences independently, while `x.square()` evaluates the square of the same variable.

The cell compares samples at grid points $k/10$ with interval enclosures.
The sample minimum and maximum are uncertified reference values; samples alone generally cannot prove inclusion of the range.
In wasm, the outward-rounding environment cannot be checked, so only samples are displayed and the proof is marked as not executed.

```rust
//| id: validated-square-dependency
//| ref: validated-square-dependency
//| title: "Interval dependency and squaring"
//| run: button
//| crates: [scioxide-validated, scioxide-core]
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"table-0","path":"/rows/0/0","equals":"x.mul(&x)"}
//|       - {"artifact":"table-0","path":"/rows/0/1","approx":{"value":-1,"atol":1e-15}}
//|       - {"artifact":"table-0","path":"/rows/0/2","approx":{"value":1,"atol":1e-15}}
//|       - {"artifact":"table-0","path":"/rows/1/0","equals":"x.square()"}
//|       - {"artifact":"table-0","path":"/rows/1/1","approx":{"value":0,"atol":1e-15}}
//|       - {"artifact":"table-0","path":"/rows/1/2","approx":{"value":1,"atol":1e-15}}
use scioxide_core::{SciOxideError, SciOxideErrorView, InvalidInputReason};
use scioxide_validated::DecoratedInterval;
use serde_json::json;

// 1. Independent reference: f64 samples at grid points k/10 in X = [-1, 1] (uncertified values)
let grid: Vec<f64> = (-10..=10).map(|k| f64::from(k) / 10.0).collect();
let products: Vec<f64> = grid
    .iter()
    .flat_map(|&x| grid.iter().map(move |&y| x * y))
    .collect();
let squares: Vec<f64> = grid.iter().map(|&x| x * x).collect();
let range = |values: &[f64]| {
    let lo = values.iter().copied().fold(f64::INFINITY, f64::min);
    let hi = values.iter().copied().fold(f64::NEG_INFINITY, f64::max);
    (lo, hi)
};
// 2. Outward-rounded enclosure: general multiplication treats the operands independently; squaring uses their identity as the same variable
let calculation = || -> Result<_, SciOxideError> {
    let x = DecoratedInterval::new(-1.0_f64, 1.0)?;
    Ok([x.mul(&x)?, x.square()?])
};
let unsupported = |error: &SciOxideError| {
    matches!(
        error.view(),
        SciOxideErrorView::InvalidInput {
            argument,
            reason: InvalidInputReason::UnsupportedConfiguration,
            ..
        } if argument == scioxide_core::argument!("rounding_environment")
    )
};
let enclosures = match calculation() {
    Ok(results) => Some(results),
    Err(error) if unsupported(&error) => None,
    Err(error) => return Err(error.to_string()),
};
let samples = [
    ("x.mul(&x)", range(&products)),
    ("x.square()", range(&squares)),
];
let rows: Vec<_> = samples
    .iter()
    .enumerate()
    .map(|(i, &(name, (lo, hi)))| {
        let y = enclosures.as_ref().map(|v| v[i]);
        let bounds = y.and_then(|v| v.set().bounds());
        (
            name,
            lo,
            hi,
            bounds.and_then(|b| b.0),
            bounds.and_then(|b| b.1),
            y.map(|v| format!("{:?}", v.decoration())),
        )
    })
    .collect();
let fmt = json!({"significantDigits":8});
let missing = if enclosures.is_none() {
    "Not executed"
} else {
    "Unbounded"
};
emit_table_with_columns!(
    json!([
        {"key":"0","label":"Expression"},
        {"key":"1","label":"Sample minimum (uncertified)","type":"number","format":fmt},
        {"key":"2","label":"Sample maximum (uncertified)","type":"number","format":fmt},
        {"key":"3","label":"Lower endpoint","type":"number","format":fmt,"nullText":missing},
        {"key":"4","label":"Upper endpoint","type":"number","format":fmt,"nullText":missing},
        {"key":"5","label":"Decoration","nullText":"Not executed"}
    ]),
    rows,
    metadata = json!({"id":"table-0"})
);
emit_outcome!(if enclosures.is_some() {
    Outcome::satisfied("Computed image enclosures")
} else {
    Outcome::unavailable("Proof computation not executed in this environment")
});
```

In a supported native environment, the product enclosure is $[-1,1]$ and the square enclosure is $[0,1]$; both have decoration `Com`.
The endpoints in this example are exactly representable, so rounding introduces no widening.
The product enclosure is wide because it does not use the correlation between the two occurrences in the expression.
This overestimation is called the interval dependency problem.

## Three levels of set representation and guarantees

SciOxide interval types differ in the sets they represent and their arithmetic guarantees.

| Type | Crate | Set and use |
|---|---|---|
| `Interval<S>` | `scioxide-core` | Bounded, nonempty closed intervals, used for search domains and similar purposes |
| `ExtendedInterval<S>` | `scioxide-core` | Also represents the empty set and unbounded intervals; supports set intersection and convex hull |
| `DecoratedInterval<S>` | `scioxide-validated` | Attaches `Decoration` to sets and performs outward-rounded arithmetic |

The endpoint type is `f32` or `f64`.
`Decoration` conservatively records whether the function is defined and continuous throughout the input.
A stronger decoration does not imply a narrower interval.
The elementary-function result `ElementaryEnclosure` returns at most two interval pieces, for example when the range crosses a pole.

## Expression dependency and geometric overestimation

An expression with repeated occurrences of the same variable can overestimate even without rounding error.
For example, for $X-X=[-2,2]$, the difference $x-x$ of the same real number is zero.
Algebraic reformulation, `square`, and `AffineForm`, which preserves shared noise symbols, can reduce this overestimation.
Distinguish it from the width of the input interval itself, problem sensitivity, and widening due to rounding.

## Scope and assumptions

| Purpose | Initial API | When configuration or reuse is needed |
|---|---|---|
| Range of an arithmetic expression | `DecoratedInterval` | `AffineContext` and `AffineForm` to preserve correlations |
| Solution of a dense point matrix | `solve` | `LinearVerifier` for interval coefficients, sparse matrices, or multiple right-hand sides |
| Isolation of all roots of a real function | `roots` | `ScalarRootVerifier` to verify a claim; `SystemRootVerifier` for systems |
| Number of polynomial roots | `polynomial_roots` | `PolynomialRootPlan` to specify a disk and count |
| Integral over a finite interval | `integrate` | `QuadratureVerifier` for tolerances, singularities, or infinite intervals |

One-shot functions return `Ok` only for results for which the proof succeeds.
Verifiers also return reports with no conclusion, so read the status instead of treating `Ok` alone as success.
Constructing certificate storage alone does not prove the recorded claim.

Zero denominators in division and negative inputs to square roots are excluded from the domain, and the image of the defined part is enclosed.
This exclusion is indicated by the decoration of `Trv`, rather than an error.
An unsupported rounding environment, however, returns no enclosure and produces `UnsupportedConfiguration` of `InvalidInput`.
Outward rounding requires round-to-nearest, ties-to-even, gradual underflow, and disabled exception traps; these are checked on x86 (SSE2), x86_64, and AArch64.
Construction, membership tests, intersection, and convex hull do not use rounding and also run in wasm.

## Summary and further reading

Assess correctness of inclusion separately from enclosure width.
Use `square` for the square of the same variable, and consider reformulation or affine arithmetic for general correlations.
Read the verifier's termination status, and do not confuse an inconclusive result with a refutation.
