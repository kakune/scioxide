許容誤差は計算をどの尺度で受理し、いつ止めるかを決める基準である。
設定した値がそのまま真の解との誤差上限になるとは限らない。
絶対誤差と相対誤差の役割を分け、残差や誤差推定値に合う尺度を選ぶ。

---

## 絶対許容誤差と相対許容誤差の数学的役割

成分 $i$ に対する誤差推定値または残差を $e_i$ とするとき、反復の終了判定には以下の正規化された尺度比 $\eta_i$ が広く用いられる。

$$
\eta_i = \frac{|e_i|}{\tau_{\mathrm{abs}, i} + \tau_{\mathrm{rel}} |y_i|}.
$$

分母は誤差を比較する許容幅であり、2 つの項を足して決める。

- 絶対許容誤差 $\tau_{\mathrm{abs}, i}$ は、比較する誤差 $e_i$ と同じ単位を持つ。
  状態量の誤差なら m、s、K、mol/L などが対応し、値がゼロに近い領域の許容幅を決める。
- 相対許容誤差 $\tau_{\mathrm{rel}}$ は無次元量であり、代表値 $|y_i|$ に比例する許容幅を決める。
  残差を判定するときは、状態量ではなく残差と同じ単位の代表値を使う。

| 計算状況 | 絶対許容誤差 $\tau_{\mathrm{abs}}$ の役割 | 相対許容誤差 $\tau_{\mathrm{rel}}$ の役割 |
|---|---|---|
| **状態値がゼロを通過する** | ゼロ近傍での発散を防ぎ、停止判定を成立させる | 分母がゼロに近づくため、単独では機能しない |
| **状態値が数桁以上変動する** | 微小領域における過小評価への安全網 | 値の大きさに比例して許容幅を自動調整する |
| **測定器の分解能が既知である** | 物理的に意味のない末尾桁の過剰探索を抑制する | 代表値に応じた有効数字を指定する |
| **次元の異なる連立系** | 成分ごとの物理スケールを個別に規定する | 無次元化後の共通精度基準を規定する |

絶対許容誤差がゼロなら、代表値がゼロのときに分母もゼロになる。
`ErrorTolerance::normalized_norm` は、このとき誤差もゼロなら寄与をゼロとし、誤差が非ゼロなら `NumericalInstability` を返す。
受理だけを調べる `is_satisfied` は、ゼロの許容幅に対する非ゼロ誤差を `Ok(false)` とする。
正の絶対許容誤差を設定すると、ゼロ近傍でも有限の許容幅を保てる。
逆に絶対許容誤差だけを使うと、同じ許容幅でも小さい値に対する相対的な要求は緩く、大きい値に対する要求は厳しくなる。

## 交点スケール $s_{\times}$ と支配領域の遷移

相対許容誤差が正のとき、2つの許容項が釣り合う状態スケールは両者の比で定まる。

$$
s_{\times} = \frac{\tau_{\mathrm{abs}}}{\tau_{\mathrm{rel}}}.
$$

$|y| \ll s_{\times}$ では絶対項が、$|y| \gg s_{\times}$ では相対項が支配的になる。
許容誤差を選ぶときは、必要な絶対精度と相対精度の両方を決め、その切り替わりが対象の値域に合うかを確認する。
測定器の分解能は判断材料になるが、測定誤差と数値誤差は別の寄与として扱う。
両項の関係は [`scioxide-core` 許容誤差の役割と判定条件](../../scioxide-core/algorithms/error-and-tolerance-contracts/)のセルで確認できる。

## ベクトルノルムの選定とスケーリング

多変数の連立方程式や時間積分では、成分ごとの正規化比 $\eta_i$ を 1 つの数にまとめて判定する。
代表的な選択肢が最大ノルムと二乗平均平方根ノルム（RMS ノルム）である。

$$
\|\boldsymbol{\eta}\|_\infty = \max_{1 \le i \le n} |\eta_i|,
\qquad
\|\boldsymbol{\eta}\|_{\mathrm{RMS}} = \sqrt{\frac{1}{n} \sum_{i=1}^n \eta_i^2}.
$$

最大ノルムが 1 以下という条件は、全成分がそれぞれの許容幅以下であることを意味する。
RMS ノルムは同じ誤差分布を複製しても値が変わらないが、少数の大きな成分が平均に埋もれることがある。
特に、非ゼロの成分が 1 つだけなら RMS はその大きさの $1/\sqrt{n}$ 倍になる。
成分ごとの違反を検出したい場合は最大ノルムを選ぶ。
どちらの判定も、入力した誤差推定値を評価するものであり、真の誤差や物理的な安全性を証明するものではない。

物理単位が異なる成分（例えば位置 $\mathrm{m}$、速度 $\mathrm{m/s}$、温度 $\mathrm{K}$）を未処理のままユークリッドノルム $\sqrt{\sum y_i^2}$ へ投入してはならない。
必ず成分ごとの代表スケールによって無次元化し、正規化比 $\eta_i$ を構成した上でノルムを集約する。

次のセルでは、背景誤差が一様な格子の中央1点だけをスパイク値に置き換える。
入力は正規化済みの誤差なので、いずれも無次元である。
`ErrorTolerance` で4種類のノルムを求め、定義式から求めた値と照合する。
グラフは格子点数に対する変化を示し、局所スパイクがRMSでは薄まり、最大ノルムでは保たれることを確認する。

```rust
//| id: concept-norm-selection-spike
//| title: 格子上の局所スパイク誤差と各ノルムによる集約挙動の比較
//| run: reactive
//| crates: [scioxide-core]
//| inputs:
//|   spike_magnitude: {"type":"range","label":"局所スパイク誤差 S [-]","description":"中央の1格子点に加える局所誤差の大きさ。","min":0.1,"max":10.0,"step":0.1,"value":2.0}
//|   baseline_error: {"type":"range","label":"背景誤差 ε_base [-]","description":"全格子点に均一に乗る背景の平滑誤差。","min":0.001,"max":0.1,"step":0.001,"value":0.01}
//|   grid_size: {"type":"range","label":"観察する格子点数 n [点]","description":"一次元格子の分割数。","min":10,"max":500,"step":10,"value":100}
use scioxide_core::{ErrorTolerance, NormSelection};

let n = grid_size.round() as usize;
// 定義式による独立検算値を、それぞれの API の結果と比較する。
let squared = spike_magnitude.powi(2) + (n - 1) as f64 * baseline_error.powi(2);
let norms = [
    (
        "L₁",
        NormSelection::L1,
        spike_magnitude + (n - 1) as f64 * baseline_error,
    ),
    ("L₂", NormSelection::L2, squared.sqrt()),
    (
        "最大",
        NormSelection::Infinity,
        spike_magnitude.max(baseline_error),
    ),
    (
        "RMS",
        NormSelection::RootMeanSquare,
        (squared / n as f64).sqrt(),
    ),
];
let mut series = Vec::new();
let mut rows = Vec::new();
for (name, norm, reference) in norms {
    // 絶対許容誤差1、相対許容誤差0なので、入力はそのまま正規化誤差になる。
    let tolerance = ErrorTolerance::scalar(1.0, 0.0, norm).map_err(|e| e.to_string())?;
    let evaluate = |count: usize| -> Result<f64, String> {
        let mut errors = vec![baseline_error; count];
        errors[count / 2] = spike_magnitude;
        tolerance
            .normalized_norm(&errors, &vec![1.0; count])
            .map_err(|e| e.to_string())
    };
    let value = evaluate(n)?;
    rows.push((name, value, reference, (value - reference).abs()));
    let points = (10..=500)
        .step_by(10)
        .map(|k| Ok([k as f64, evaluate(k)?]))
        .collect::<Result<Vec<_>, String>>()?;
    series.push(serde_json::json!({"name":name, "points":points}));
}
// 正規化ノルムが横線 1 以下なら許容誤差を満たす。縦線は表で比べる n。
emit_line_chart!(
    &series,
    options = &serde_json::json!({"xLabel": "格子点数 n [点]", "yLabel": "正規化ノルム [-]", "yType": "log",
"annotations": [{"kind": "line", "axis": "y", "value": 1.0, "label": "許容誤差の境界"},
{"kind": "line", "axis": "x", "value": n as f64, "label": "選んだ n"}]})
);
emit_table_with_columns!(
    serde_json::json!([
    {"key":"0","label":"ノルム","type":"string","nullText":"未定義"},
    {"key":"1","label":"API の値","type":"number","format":{"significantDigits":6},"nullText":"未定義"},
    {"key":"2","label":"定義式の値","type":"number","format":{"significantDigits":6},"nullText":"未定義"},
    {"key":"3","label":"絶対差","type":"number","format":{"significantDigits":6},"nullText":"未定義"}
    ]),
    rows
);
```

## 停止判定条件の多面的設計

残差、反復点の変化、目的関数の変化、計算回数の上限は、それぞれ異なる停止理由を表す。
次は判定式の例であり、すべての SciOxide ソルバーが同じ式や組み合わせを使うわけではない。

1. **残差判定**: $\|\mathbf{f}(\mathbf{x}_k)\| \le \tau_{\mathrm{abs}} + \tau_{\mathrm{rel}} \|\mathbf{f}(\mathbf{x}_0)\|$（方程式がどの程度満たされているか）。
2. **ステップ幅判定**: $\|\mathbf{x}_{k+1} - \mathbf{x}_k\| \le \tau_{\mathrm{step}} (1 + \|\mathbf{x}_k\|)$（反復点が実質的に移動を停止したか）。
3. **目的関数変化量判定**: $|f(\mathbf{x}_{k+1}) - f(\mathbf{x}_k)| \le \tau_{\mathrm{obj}}$（最適化における改善幅が頭打ちになったか）。
4. **上限ガード**: 最大反復回数や最大関数評価回数への到達（無限ループの防止）。

反復点の変化が小さくても、停滞によって方程式を満たさないまま止まることがある。
逆に残差が小さくても、悪条件の問題では解の誤差が大きいことがある。
終了理由を読み、実際に満たした条件を確認してから結果を使う。

## まとめと次に読むページ

絶対許容誤差は値が小さい領域を支え、相対許容誤差は値の大きさに応じて許容幅を変える。
複数成分の誤差は、単位をそろえてからノルムで集約する。
局所的な違反を見逃したくない場合は、RMSと最大ノルムの違いが重要になる。
