SciOxide は19のクレートからなる Rust 向けの数値計算ライブラリである。
必要な機能を持つクレートを依存関係に追加して使う。

本節では、自身の Rust プロジェクトへ SciOxide を導入するための Cargo 設定、MSRV（Minimum Supported Rust Version）、`no_std` 環境への対応、Nix による開発環境、および本書の対話型セルの実行モデルについて解説する。

---

## Cargo への依存関係の追加

このページで使うソースのワークスペースバージョンは0.1.0である。
[0.1.0 の API リファレンス](https://docs.rs/scioxide-core/0.1.0/scioxide_core/)に対応するバージョンを Cargo.toml に指定する。

```toml
[dependencies]
# 共通基盤（スカラー型、許容誤差、範囲安全算術）
scioxide-core = "=0.1.0"

# 必要に応じたクレートの追加
scioxide-linalg = "=0.1.0"        # 密行列・行列分解・Krylov 法
scioxide-rootfind = "=0.1.0"      # 非線形方程式の求根
scioxide-ode = "=0.1.0"           # 常微分方程式ソルバー
```

### エディションと MSRV

- **Rust エディション**: Rust 2024
- **MSRV（最低サポート Rust バージョン）**: `1.93.0`

SciOxide は安定版 Rust の最新機能を活用しており、MSRV 以降のコンパイラを前提としている。

### 依存性ポリシー

SciOxide の公開ライブラリクレート（`crates/scioxide-*`）は、**通常依存とビルド依存にサードパーティのクレートを含まない**。
これらの依存関係は SciOxide のクレート間で完結する。
導入時には、利用するバージョンの API と対応する実行環境を確認する。

### `std` と `no_std` + `alloc` の切り替え

SciOxide の全クレートは、標準で `std` 機能を有効化している。
組み込みシステムや OS のないベアメタル環境では、`default-features = false` とし、ヒープアロケーターを用意して `no_std` + `alloc` 環境で利用する。
`alloc` という Cargo フィーチャーの指定は不要である。

```toml
[dependencies]
scioxide-core = { version = "=0.1.0", default-features = false }
scioxide-linalg = { version = "=0.1.0", default-features = false }
```

依存グラフ全体で `std` フィーチャーが無効な場合、OS スレッド並列実行（`ThreadExecutor`）や標準クロック（`StdClock`）などの OS 依存機能は無効化され、決定論的な逐次エグゼキューター（`SequentialExecutor`）が利用される。

## 開発環境の構築（Nix）

SciOxide のリポジトリのルートで Nix を使うと、バージョンを固定したツールチェーンをそろえた開発環境に入れる。
初回は必要なパッケージの取得に時間がかかる。

```bash
# SciOxideのソースディレクトリで実行
nix develop
```

この開発シェルには次のものが入る。
- MSRV と同じ Rust 1.95.0（`rustfmt`、`clippy`、`rust-analyzer` と、`wasm32-unknown-unknown`・i686・AArch64 のターゲットを含む）
- Node.js 24

ハンドブックを手元で動かす場合は `nix develop .#handbook` を使う。
このシェルも同じ Rust 1.95.0 を使い、Wasm ターゲット、Node.js 24、pnpm、Wasm を最適化する Binaryen を備える。

## ハンドブックセルの Wasm 実行モデルと制約

本書に埋め込まれている対話型コードセルは、Oxiquill エンジンにより `wasm32-unknown-unknown` ターゲットへコンパイルされ、ブラウザの Wasm ランタイム上で動作している。
この実行環境には、ネイティブ環境と異なる以下の特性と制約が存在する。

1. **シングルスレッド逐次実行**: ブラウザ環境ではスレッド生成を行わない。
   並列ポリシー（`ExecutionPolicy::Parallel`）や `ThreadExecutor` による並列ディスパッチは利用できず、すべて逐次実行される。
2. **時刻と時間制限**: `std::time::Instant` に依存する `StdClock` や実行期限 `Deadline::after` は Wasm 上では使用できない。
3. **ポインタ幅（usize）**: Wasm32 環境では `usize` が 32 ビット（最大約 $4.29 \times 10^9$）である。
   そのため、`usize` を返す整数の組合せ関数（`scioxide-core` の `checked_factorial`、`checked_binomial` など）がオーバーフローを返す境界が 64 ビットネイティブ環境（最大 $1.84 \times 10^{19}$）より低くなる（例: $13! \approx 6.22 \times 10^9 > 2^{32}$ のため 32 ビットでは表現不能）。
4. **精度保証計算の制限**: `scioxide-validated` の包含が保証された区間計算は、端点を誤差のない変換で外側へ丸めるので、浮動小数点の制御レジスタを変更しない。
   その代わり、最近接偶数への丸め、段階的アンダーフロー（flush-to-zero なし）、マスクされた浮動小数点例外を要し、各演算の前とコールバックの後に制御レジスタを読んで確かめる。
   対象は x86（SSE2）、x86_64、AArch64 だけで、Wasm 上では `kind()` が `InvalidInput`（`InvalidInputReason::UnsupportedConfiguration`）のエラーになる。
   そのため、ブラウザでは証明部分を「未実行」と表示する。
   参考計算を併記する場合も、その値に証明は付かない。

## 対話型セルをローカル環境で試す方法

本書に記載されたコード例を自身のローカルマシンで実行・改変するには、通常の Rust アプリケーションとして記述する。

### 1. プロジェクトの作成と依存関係の追加

```bash
cargo new scioxide-sandbox --bin
cd scioxide-sandbox
cargo add scioxide-core --path ../scioxide/crates/scioxide-core
cargo add scioxide-linalg --path ../scioxide/crates/scioxide-linalg
```

### 2. コードの移植

次のセルは解と後退誤差を表に表示する。
ブラウザと手元の実行結果がともに $x=(2,3)$ に近いことを確認する。
後退誤差の診断を読むので、`LuDecomposition::factor(&matrix)` で作った因子を `solve_with_options` で解く。
手元で試す場合はコードを `fn main() -> Result<(), String> { ...; Ok(()) }` の中に置く。
`emit_*` はハンドブック用の出力マクロなので、通常の Rust プロジェクトでは `println!` などに置き換える。

```rust
//| id: installation-linear-system
//| title: 手元でも再現できる連立方程式の例
//| run: button
//| crates: [scioxide-linalg]
use scioxide_linalg::{
    DirectSolveOptions, Estimation, LuDecomposition, Matrix, RankPolicy, Vector,
};

let matrix = Matrix::from_vec(2, 2, vec![3.0_f64, 1.0, 1.0, 2.0]).map_err(|e| e.to_string())?;
let rhs = Vector::from_vec(vec![9.0_f64, 8.0]);
let lu = LuDecomposition::factor(&matrix).map_err(|e| e.to_string())?;
// 後退誤差の診断は既定では計算しないので、solve_with_options で明示的に要求する。
let options = DirectSolveOptions::new(RankPolicy::Exact).with_residual(Estimation::Estimate);
let result = lu
    .solve_with_options(&rhs, &options)
    .map_err(|e| e.to_string())?;
let solution = result.solution().ok_or("解が受理されなかった")?;
let residual = result.report().residual().ok_or("要求した残差診断がない")?;
emit_table_with_columns!(
    serde_json::json!([
    {"key":"0","label":"x₁","type":"number","format":{"significantDigits":6},"nullText":"未定義"},
    {"key":"1","label":"x₂","type":"number","format":{"significantDigits":6},"nullText":"未定義"},
    {"key":"2","label":"元の行列に対する後退誤差 [-]","type":"number","format":{"significantDigits":6},"nullText":"未定義"}
    ]),
    vec![(
        solution.as_slice()[0],
        solution.as_slice()[1],
        residual.scaled_norm()
    )],
    metadata = serde_json::json!({"id":"solution"})
);
emit_outcome!(
    Outcome::satisfied("直接法の解が受理された")
        .status(format!("{:?}", result.report().termination()))
);
```

```bash
cargo run
```
