このページは、`scioxide-ad` のアルゴリズムページが共通に前提にすることをまとめる。
計算を文の列としてどう表すか、どの記号を使うか、微分の量ごとに何回の走査と何のメモリが要るか、どの仕様がすべての数値型に共通するかである。
最後に、各ページがどの問いに答えるかを示す。

## 計算グラフと文の列

`scioxide-ad` で微分する関数は `R: Real` に対して書いたふつうの Rust のコードである（[数値型・lane・汎用コード](number-types-and-lanes/)）。
評価点を決めて実行すると、コードは四則演算や初等関数のような演算を決まった順序で並べた列になる。
入力を $v_1 = x_1, \dots, v_n = x_n$ とし、続く値を

$$
v_i = \varphi_i\bigl(v_j\bigr)_{j \in P(i)}, \qquad P(i) \subset \{1, \dots, i - 1\}, \qquad i = n + 1, \dots, N
$$

で作る。
$\varphi_i$ は 1 つの演算、$P(i)$ はその引数の添字の集合で、出力はこの列の中から選んだ値の組 $\mathbf{y} = F(\mathbf{x})$ である。
各値はちょうど一度だけ、それより前の値から定義されるので、値の依存関係は閉路を持たない有向グラフ（計算グラフ）になる。
この列を Wengert の表（Wengert list）と呼び、テープに記録される 1 つの演算を文（statement）と呼ぶ。

自動微分は評価点で局所の偏導関数

$$
c_{ij} = \frac{\partial \varphi_i}{\partial v_j}, \qquad j \in P(i)
$$

を計算し、連鎖律で合成する。
前進モード（forward mode）は入力側の接ベクトル（tangent）$\dot{\mathbf{x}}$ をシード（seed）として、列の順に $\dot v_i = \sum_{j \in P(i)} c_{ij}\,\dot v_j$ を計算する。
逆モード（reverse mode）は出力側の余接ベクトル（cotangent）$\bar{\mathbf{y}}$ をシードとして、列の逆順に $\bar v_j = \sum_{i : j \in P(i)} \bar v_i\,c_{ij}$ を累積する。
$\bar v_j$ を $v_j$ の随伴（adjoint）と呼ぶ。
列を一度たどる計算を走査（sweep）と呼ぶ。

例えば $f(x_1, x_2) = x_1 x_2 + \sin x_1$ の表と局所の偏導関数は次のとおりである。

| $i$ | 文 | 局所の偏導関数 |
|---|---|---|
| 1 | $v_1 = x_1$ | なし |
| 2 | $v_2 = x_2$ | なし |
| 3 | $v_3 = v_1 v_2$ | $c_{31} = v_2$、$c_{32} = v_1$ |
| 4 | $v_4 = \sin v_1$ | $c_{41} = \cos v_1$ |
| 5 | $v_5 = v_3 + v_4$ | $c_{53} = c_{54} = 1$ |

前進モードでシードを $\dot{\mathbf{x}} = (1, 0)$ にすると、$\dot v_3 = v_2$、$\dot v_4 = \cos v_1$、$\dot v_5 = v_2 + \cos v_1 = \partial f / \partial x_1$ が 1 回の走査で求まる。
$\partial f / \partial x_2$ にはシードを $(0, 1)$ にしたもう 1 回の走査が要る。
逆モードで $\bar v_5 = 1$ から逆にたどると、$\bar v_3 = \bar v_4 = 1$、$\bar v_2 = \bar v_3 v_1 = x_1$、$\bar v_1 = \bar v_3 v_2 + \bar v_4 \cos v_1 = x_2 + \cos x_1$ となり、勾配の 2 成分が 1 回の走査で求まる。

前進モードの数値型（`Dual`、`MultiDual`、`Jet`）は、この列を実行しながら接成分を運び、列を記録しない。
逆モードの `Var` は、入力に依存する（能動的な）引数を持つ演算を文としてテープに記録し、評価のあとで逆にたどる。
定数の加算や `floor` のように、能動的な引数を持っても文を記録しない演算もある。
`dot`（`gemv_into` と `gemm_into` の各成分も）はスカラーの積和に展開せずに 1 つの文として、`solve_into`、`checkpointed_loop`、`Var::external` は 1 つの呼び出し文として記録する。
`cholesky_into` や `qr_into` は分解のアルゴリズムをスカラーの演算の文として記録する。
記録の規則は[逆モードとテープ](reverse-mode-and-replay/)にある。

## 記号

章の記号は[数値計算の記号と用語](../../reference/)に合わせる。

| 記号 | 意味 | 対応する API |
|---|---|---|
| $n$、$m$ | 入力のスカラーの数、出力のスカラーの数 | `Linearization::inputs`、`outputs` |
| $\mathbf{x} \in \mathbb{R}^n$、$\mathbf{y} = F(\mathbf{x}) \in \mathbb{R}^m$ | 評価点と出力の primal 値（primal） | 引数 `point`、`Linearization::values` |
| $v_i$、$\varphi_i$、$P(i)$ | $i$ 番目の値、それを作る演算、引数の添字の集合 | テープの文 |
| $c_{ij}$ | 局所の偏導関数 $\partial\varphi_i / \partial v_j$ | 各演算の規則 |
| $\dot v$、$\dot{\mathbf{x}}$ | 接成分、入力側の接ベクトル（シード） | `Dual::derivative`、`MultiDual::gradient` |
| $\bar v$、$\bar{\mathbf{y}}$ | 随伴、出力側の余接ベクトル（シード） | `Linearization::vjp_into` の引数 |
| $\mathbf{J} \in \mathbb{R}^{m \times n}$ | ヤコビ行列 $J_{ij} = \partial F_i / \partial x_j$。行が出力、列が入力 | `jacobian`、`Linearization::jacobian_into` |
| $\mathbf{J}\dot{\mathbf{x}}$、$\mathbf{J}^\mathsf{T}\bar{\mathbf{y}}$ | ヤコビ行列・ベクトル積（JVP）、ベクトル・ヤコビ行列積（VJP） | `jvp`、`vjp` |
| $\nabla f$、$\mathbf{H}$ | スカラー関数の勾配とヘッセ行列 | `grad`、`hessian` |
| $\mathbf{H}\mathbf{v}$ | ヘッセ行列・ベクトル積（HVP） | `hvp`、`Tape::hvp_into` |
| $c_k = \dfrac{1}{k!}\dfrac{d^k}{dt^k} f(\mathbf{x} + t\mathbf{d})\Big\vert_{t=0}$ | 正規化 Taylor 係数 | `Jet::coefficients`、`jet` |
| $\varepsilon$ | 二重数の無限小（$\varepsilon^2 = 0$） | `Dual` |
| $N$ | `MultiDual` の方向の数、`Jet` の係数の数 | `MultiDual<V, N>`、`Jet<V, N>` |
| $W$ | lane の幅（1 つの値が持つ独立な値の数） | `Lanes<S, W>`、`BatchPlan<W>` |
| $\chi$ | 疎な行列の彩色の色の数 | `ColoringSchedule` |
| $C_F$ | $F$ を 1 回評価する演算の数 | なし |
| $\varepsilon_{\mathrm{mach}}$、ulp | 機械イプシロン（`f64` で $2^{-52}$、`f32` で $2^{-23}$）、最後の桁の単位 | `RealScalar::EPSILON` |

記号 $\varepsilon$ は二重数の無限小に使い、機械イプシロンは添字を付けて $\varepsilon_{\mathrm{mach}}$ や $\varepsilon_{32}$（`f32` の値）と書く。

## 計算コストのモデル

計算コストは関数を 1 回評価する演算の数 $C_F$ に対する倍率と、走査の回数で数える。
1 回の前進走査（JVP）も、1 回の記録と逆走査（VJP、スカラー関数の勾配）も、計算コストは $C_F$ の小さな定数倍で、その定数は $n$ と $m$ によらない（Griewank と Walther の計算量のモデル。
[参考文献案内](../../reference/bibliography/)）。
これが、入力の多いスカラー関数の勾配を逆モードで求める理由である。
前進モードで勾配を求めると、入力の方向ごとに 1 回、合計 $n$ 回の走査が要る。

メモリは 2 つのモードで性質が違う。
前進モードの値は記録を残さず、値ごとに primal 値と接成分（`MultiDual` では $N$ 個）だけを持つ。
逆モードのテープは文の情報を表す `u64` のワード（単項と 2 項の文は 1 ワード）、偏導関数の列、ワードごとの随伴を持つので、メモリは記録の長さに比例して増える。
長いループでメモリを抑える方法は[ループとチェックポイント](checkpointing/)にある。

求める量ごとの走査の回数は次のとおりである。

| 求める量 | 主な API | 走査の回数 |
|---|---|---|
| JVP $\mathbf{J}\dot{\mathbf{x}}$ | `Dual`、`jvp`、`Linearization::jvp_into` | 前進 1 回 |
| $N$ 方向の JVP、$N$ 入力の勾配 | `MultiDual<V, N>` | 前進 1 回（微分の部分の演算は約 $N$ 倍） |
| VJP $\mathbf{J}^\mathsf{T}\bar{\mathbf{y}}$、勾配 $\nabla f$ | `vjp`、`grad`、`Tape::gradient_into`、`Linearization::vjp_into` | 記録 1 回と逆走査 1 回 |
| 密なヤコビ行列 $\mathbf{J}$ | `jacobian`、`Linearization::jacobian_into` | 記録 1 回と、前進 $n$ 回か逆 $m$ 回（`JacobianMode::Auto` は $m < n$ なら逆） |
| 疎なヤコビ行列 | `Linearization::sparse_jacobian_into` | 記録 1 回と、色ごとに前進 1 回（$\chi$ 回） |
| HVP $\mathbf{H}\mathbf{v}$ | `hvp`、`Tape::hvp_into` | 二重数の記録 1 回と逆走査 1 回（勾配の小さな定数倍） |
| 密なヘッセ行列 $\mathbf{H}$ | `hessian` | 方向ごとに記録と逆走査（$n$ 回） |
| 疎なヘッセ行列 | `Tape::sparse_hessian_into` | 色ごとに記録と逆走査（$\chi$ 回） |
| Taylor 係数 $c_0, \dots, c_{N-1}$ | `Jet`、`jet` | 前進 1 回（非線形の演算は 1 回あたり $O(N^2)$） |

表の回数は記録と走査の回数である。
テープの容量が足りない変換は文を数えるために関数をもう 1 回実行するので、関数の実行回数は記録の回数より多くなることがある。
毎回新しいテープを作るワンショット呼び出しでは、`grad`、`value_and_grad`、`vjp`、`jacobian`、`hvp` が関数を 2 回、`hessian` が $n + 1$ 回実行し、新しいテープでの `Tape::sparse_hessian_into` は $\chi + 1$ 回実行する（[テープのライフサイクルと再利用](tape-lifecycle/)）。

ヘッセ行列・ベクトル積はテープに二重数 `Dual<f64>` を記録する前進・逆の組み合わせ（forward-over-reverse）で求める。
入力に $\mathbf{x} + \mathbf{v}\,\varepsilon$ を入れて記録し、逆走査すると、随伴の値の成分に勾配、接成分に $\mathbf{H}\mathbf{v}$ が現れる。

### 設計に由来する計算コスト

上のモデルの定数は実装と実行環境で決まる。
`scioxide-ad` の設計に由来する計算コストとして、次のことが分かっている。

- `Lanes` の SIMD 命令はコンパイル時に決まるビルドの target feature で決まる。
  x86-64 で AVX2 を使うには `-C target-cpu=x86-64-v3`（または `native`）が要り、既定の SSE2 のビルドは lane の演算が中心のコードで約 1.2〜1.7 倍遅い。
- スカラーのテープで大きな要素ごとの計算を記録すると、要素あたり数十ナノ秒かかる。
  そのような計算は `Lanes` で一括して評価するか、前進モードで微分する。
- ヘッセ行列は方向ごとに（疎なヘッセ行列は色ごとに）関数を記録し直す。
- どの数値型も範囲の調整（スケーリング）をしない通常の IEEE の算術で評価するので、精度の保証の範囲の外では、範囲に配慮した式ならあふれない中間値があふれるか、アンダーフローしうる。

## 全ページに共通の仕様

次の仕様はすべての数値型と変換に共通する。
各ページはここに書いたことを前提にして、その項目に固有の規則だけを書く。

- 値は IEEE 754 に従い、演算の順序は固定されている。
  数値型の演算は引数を検査せず、エラーを返さず、NaN と無限大はそのまま伝わる。
  失敗を `Result` で返すのは、テープや一括評価の変換の境界、構造化演算、引数の長さや番号を検査する少数のメソッドと、規則のエラーを返す `try_map_scalar` である。
- 値は微分の方式によらない。
  ラッパー型は値の成分を一つ下の型（`Primal`）の算術で計算するので、`Dual`、`MultiDual`、`Var` で求めた関数値は、同じ関数を内側の型（`Dual<f64>` なら `f64`）で評価した値とビットで一致する。
  `Lanes` の結果は lane の幅によらず同じで、8 つの lane カーネル（`exp`、`exp_m1`、`ln`、`ln_1p`、`sin`、`cos`、`tanh`、`powf`）とそれを使う演算だけが、スカラーの結果と最後の数桁で違いうる。
- `Dual`、`MultiDual`、`Var` は、各関数の偏導関数を `Primal` の算術で評価し、連鎖律で合成する。
  入れ子の型は評価した式をもう一度微分する。
  引数の範囲で式を切り替える関数（`atan`、`tanh`、`asinh`、`acosh`、`hypot`、`atan2`）は、両方の式を計算して base の値の比較による `select` で選ぶ。
- テープの逆走査と前進走査はすべての更新に `azmul`（ちょうど 0 の因子があれば $+0$ を返す積）を使う。
  `Dual` と `MultiDual` は、`×`、スカラーによる乗除、`fract` と、`exp`・`sin`・`cos`・`tanh` などの滑らかな関数の族を除く偏導関数に `azmul` を使い、`Jet` はすべて IEEE の積を使う。
  連鎖律の積和と Taylor 係数の漸化式は乗算と加算を別々に行い、融合積和（FMA）に置き換えない。
  `sinc` と `sincpi` のスカラーの導関数カーネルだけは丸めの残差を求めるために明示的な融合積和を使うが、その演算はハードウェアの FMA の有無によらず同じ値を返すので、結果は FMA の有無によらない。
  使い分けの一覧と、それによって結果が分かれる例は[前進モードと二重数](forward-mode/)にある。
- どの数値型も折れ点では片側導関数の中点を使う。
  テープは能動的な引数が折れ点に当たった回数を数え、`KinkPolicy::Error` ならそれを変換の境界で `DomainError` にする。
  非有限値は数値型の中では IEEE に従って伝わり、`NonFinitePolicy` が変換の境界での扱いを決める（[折れ点と非有限値の扱い](nonsmooth-and-nonfinite-policies/)）。
- 変換が失敗したとき、呼び出し側の出力は書き換えられない。
  テープの容量が足りないと、変換はテープを広げて関数をもう一度実行するので、関数は 1 回の変換で最大 2 回実行され、決定論的でなければならない。
  同じ関数を記録したことのあるテープでの変換は、作業用の領域を確保する構造化演算と、受動的な入力の `Var::external` を除いて確保をしない（[テープのライフサイクルと再利用](tape-lifecycle/)）。

### 精度の保証

試験で確かめている精度は次のとおりである。
どれも 1 回の演算の局所の量か、Taylor 係数についての仕様で、合成した関数の導関数全体が正しく丸められることは約束しない。

- 値は scioxide-core の初等関数の精度を保つ。
  lane カーネルは厳密な値から 4 ulp 以内で、ほかの lane の演算はスカラーの関数とビットで一致する。
- 単項関数の 1 階の偏導関数は高精度の参照値から 64 ulp 以内（式を切り替える点や結果が非正規化数になる点の近くの `log10` と `tanh` は 4 ulp、定数倍だけの `log2`、`log10`、`exp2` は 1 ulp）、安定変換の 1 階と 2 階の導関数は 64 ulp 以内である。
- 二項関数の 1 階の偏導関数は 64 ulp 以内、入れ子で求めた 2 階の偏導関数は 256 ulp 以内である。
  これは引数、値、偏導関数がどれも 0 か、大きさが $[\sqrt{\texttt{MIN\_POSITIVE}}, \sqrt{\texttt{MAX}}]$ に入る点での仕様である。
- Taylor 係数 $c_k$ の絶対誤差は、同じ制限の点で、8 次までについて $64\,\varepsilon_{\mathrm{mach}}(k + 1)\,g$ に最小の正の非正規化数を加えた値以下である。
  $g$ は厳密な合成の各項の絶対値の和である。

浮動小数点の丸め、条件数、精度の保証の種類の一般論は[浮動小数点と条件数](../../concepts/floating-point-and-conditioning/)にある。

## まとめ

関数は文の列として評価され、前進モードは列の順に接ベクトルを、逆モードは列の逆順に随伴を伝播させる。
JVP と、勾配や VJP は、どちらも関数の評価の小さな定数倍の計算コストで 1 回の走査になり、密なヤコビ行列は前進 $n$ 回か逆 $m$ 回、ヘッセ行列は方向ごとの記録と逆走査になる。
入力が少なければ前進モード、入力の多いスカラー関数の勾配なら逆モードを選び、逆モードのメモリが文の数に比例して増えることを考慮する。
値は微分の方式によらず内側の型での評価とビットで一致し、精度の保証は局所の偏導関数についての ulp で与えられるので、合成した導関数の誤差は primal 値の丸めの伝わり方から見積もる。
