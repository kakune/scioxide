`abs`、`max`、`floor` のような関数は特定の点で古典的な導関数を持たない。
自動微分は各演算の局所的な導関数を連鎖律でつなぐので、そのような点で何を局所的な導関数とするかを決めておく必要がある。
primal 値や導関数が NaN や無限大になったときに、それを値として流すか、計算を止めるかも決めておく必要がある。

`scioxide-ad` はこの 2 つを次のように扱う。
すべての数値型は導関数を持たない点で原則として片側導関数の中点を使う。
テープはその点に当たった回数を数え、`KinkPolicy` で数を返すかエラーにするかを選ぶ。
数値型の演算は IEEE 754 に従って NaN と無限大を伝え、変換の境界で `NonFinitePolicy` が点と結果を検査する。
どちらの方針も `TapeOptions` と `BatchOptions` に持たせる値で、スレッドやプロセス全体の状態ではない。

## 折れ点の規約

関数が導関数を持たない点、または値が跳ぶ点を折れ点（kink）と呼ぶ。
`scioxide-ad` の折れ点と、そこで使う導関数は次の表のとおりである。

| 関数 | 導関数 | 折れ点 |
|---|---|---|
| `abs` | $\operatorname{sign} x$、$x = 0$ で 0 | $x = 0$ |
| `min`、`max` | 返した側に 1、同点では $\tfrac12$ ずつ、NaN の側に 0 | $a = b$ |
| `floor`、`ceil`、`round`、`trunc`、`signum` | 0 | 整数（`floor`、`ceil`）、半整数（`round`）、0 以外の整数（`trunc`）、0（`signum`） |
| `fract`、`a % b` | 1、$(1,\ -n)$（$n$ は剰余の商）、折れ点では $(1,\ -(n - \tfrac12 \operatorname{sign} n))$ | $x$ が 0 以外の整数、`a % b` は剰余が 0 で $a \ne 0$ |
| `hypot`、`atan2` | 原点で $(0, 0)$ | 原点。`atan2(a, b)` は $a = 0$、$b < 0$ も |

`abs` の 0 での 0 は片側導関数 $-1$ と $+1$ の中点、`max` の同点での $(\tfrac12, \tfrac12)$ は $(1, 0)$ と $(0, 1)$ の中点である。
丸めの関数と `signum` は両側の導関数が 0 なので 0 を返し、値の跳びは導関数に現れない。
テープでは、丸めの関数と `signum` の結果は微分対象外の値になり、文を記録しない（折れ点は数える）。
整数の折れ点は有限の整数だけで、$\pm\infty$ での `floor`、`ceil`、`trunc`、`fract` は折れ点として数えない。
`fract` は両側の導関数が 1 で、同じく跳びを無視する。
`atan2` の分枝切断 $a = 0$、$b < 0$ では値が $\pm\pi$ の間で跳ぶが、両側の偏導関数は等しいので、その値を使う。
`hypot` と `atan2` の原点では偏導関数を $(0, 0)$ にする。

`a % b` の $b$ についての偏導関数 $-n$ の $n$ は、剰余 $r = a \bmod b$ を作った商 $n = (a - r)/b$ で、基底の値から作る整数である。
浮動小数点の $a/b$ は次の整数に丸まることがあるので（`1.0 % 0.1` は $0.0999\ldots$ で商は 9 だが、$\mathrm{fl}(1.0/0.1) = 10$）、商は $a/b$ からは作らない。
$a/b$ が 0 以外の整数 $n$ に等しい点（剰余が 0 で $a \ne 0$）では、両側の偏導関数は $-n$ と $-(n - \operatorname{sign} n)$ で、規則はその中点 $-(n - \tfrac12 \operatorname{sign} n)$ を返す。

`min` と `max` は IEEE 754 の規則に従い、一方だけが NaN なら他方を返す。
そのとき返した側の偏導関数は 1、NaN の側は 0 で、両方が NaN なら偏導関数も NaN になる。
`clamp(x, lo, hi)` は `min(max(x, lo), hi)` として微分し、値は 1 つ下の数値型の `clamp` から取る。
そのため NaN の $x$ は NaN のまま、区間の中の $-0$ は符号を保ち、どの数値型でも値は `f64` の `clamp` と同じである。
$lo > hi$ の点と、どちらかの境界が NaN の点では NaN を返す。

折れ点の規則は偏導関数を比較と `select` で選び、$x/|x|$ のような算術では作らない。
`Jet` も係数ごとに同じ規約を使い、`abs` は $c_1$ 以上のすべての係数に $\operatorname{sign} x_0$（$x_0 = 0$ で 0）を掛ける（[Taylor ジェットと高階の係数](../taylor-jets/)）。

`select` と比較は折れ点ではない。
比較は base の値（最も内側の `f64` などの値）で行い、`select` は選んだ側の導関数をそのまま返す。
したがって `R::select(x.lt(zero), -x, x)` と書いた $|x|$ は、$x = 0$ で選んだ側 $x$ の導関数 1 を返し、テープはこれを数えない。
[初等関数の微分と精度](../elementary-functions/)の領域による式の切り替えも `select` なので、折れ点として数えない。

## Clarke の一般化勾配との関係

中点の規約が数学的に何を返すのかは、Clarke の一般化勾配で説明できる。
関数 $f: \mathbb{R}^n \to \mathbb{R}$ が点 $x$ の近傍で $|f(y) - f(z)| \le K \|y - z\|$ を満たすとき、$f$ はその点で局所 Lipschitz であるという。
Rademacher の定理により、局所 Lipschitz な関数は測度 0 の集合 $\Omega_f$ を除いて微分可能である。
Clarke の一般化勾配は微分可能な点での勾配の極限を集めた集合の凸包

$$
\partial_{\mathrm{C}} f(x) = \operatorname{conv} \Bigl\{ \lim_{k \to \infty} \nabla f(x_k) \;:\; x_k \to x,\ x_k \notin \Omega_f \Bigr\}
$$

である（F. H. Clarke, *Optimization and Nonsmooth Analysis*, Wiley, 1983）。
$\partial_{\mathrm{C}} f(x)$ は空でない有界閉凸集合で、$f$ が $x$ の近傍で連続微分可能なら $\{\nabla f(x)\}$ に、$f$ が凸なら凸解析の劣微分に一致する。
1 変数の区分的に滑らかな連続関数では、片側導関数 $f'(x_0^-)$ と $f'(x_0^+)$ を両端とする区間になる。
$|x|$ の原点では $[-1, 1]$、$\max(x, 0)$ の原点では $[0, 1]$、$\operatorname{hypot}(a, b)$ の原点では単位円板である。

1 つの演算では、表の Lipschitz な関数（`abs`、`min`、`max`、`hypot`）の規約の値は、その演算の Clarke の一般化勾配に入る。
`abs` と `max` では一般化勾配の線分の中点、`hypot` では円板の中心である。
値が跳ぶ関数（丸めの関数、`signum`、`fract`、`%`、`atan2` の分枝切断）は、跳ぶ点で局所 Lipschitz でないので、Clarke の一般化勾配は定義されない。

合成では、Clarke の一般化勾配の連鎖律は一般に包含関係

$$
\partial_{\mathrm{C}} (g \circ h)(x) \subseteq \operatorname{conv}\bigl\{ \xi^{\mathsf T} \zeta : \xi \in \partial_{\mathrm{C}} g(h(x)),\ \zeta \in \partial_{\mathrm{C}} h(x) \bigr\}
$$

としてしか成り立たない（$\partial_{\mathrm{C}} h(x)$ は $h$ の一般化ヤコビ行列）。
中点の規約は演算ごとに適用されるので、合成した関数での値は、合成した関数の片側導関数の中点と一般には一致しない。
$g(x) = \max(\max(x, 0), 0)$ は $\max(x, 0)$ に等しく、$x = 0$ での片側導関数は 0 と 1、その中点は $\tfrac12$ である。
規約は内側の `max` の $\tfrac12$ に外側の `max` の $\tfrac12$ を掛けて $\tfrac14$ を返し、これは $g$ の一般化勾配 $[0, 1]$ には入る。
各演算で一般化勾配の元を選んで連鎖律でつないだ値は右辺に入るが、左辺に入るとは限らない。
たとえば $f(x) = \max(\max(x, 0), 0) - \max(x, 0)$ はすべての $x$ で 0 なので $\partial_{\mathrm{C}} f(0) = \{0\}$ だが、中点の規約では外側の `max` が内側の傾き $\tfrac12$ にさらに $\tfrac12$ を掛け、$\tfrac14 - \tfrac12 = -\tfrac14$ を返す。
一方 $\max(x, 0) - \max(-x, 0) = x$ では $\tfrac12 - \tfrac12 \cdot (-1) = 1$ となり、正しい値に一致する。
合成した関数が折れ点で滑らかでも、自動微分の値がその導関数になる保証はない。

折れ点に当たる点は多くの計算で測度 0 の集合にあり、連続分布から選んだ点が当たることはまれである。
しかし 0 に初期化した重み、整数の入力、ReLU の境界のように、構造を持つ点はちょうど折れ点に当たる。
途中の値が区間で一定になる計算では、折れ点に当たる点が区間全体に広がる。
$g(x) = \max(\max(x, 0), 0)$ は $x < 0$ のすべての点で外側の `max` が 0 と 0 の同点になり、導関数 0 は正しいが、テープは毎回 1 回数える。
テープの数え方はこうした場合を検出するために使う。

## 折れ点の数え方と KinkPolicy

テープは、能動的な（入力に依存する）引数が折れ点にある演算を、演算とレーン（lane、SIMD の 1 要素）ごとに 1 回数える。
二項の演算（`min`、`max`、`hypot`、`%`、`atan2`）は、少なくとも一方の引数が能動的なら、両方が能動的でも 1 回だけ数える。
引数がすべて受動的な演算は記録されないので数えない。
`Dual`、`MultiDual`、`Jet` は規約を適用するだけで、数えない。

最後の記録の数は `TapeReport::kinks()` で読める。
`BatchEstimate::kinks()` は逆モードの一括評価で、項目の lane ごとの数と、ブロックごとに 1 回の `prepare` の数の和を返し、値だけの評価と前進モードでは `None` を返す（[多数の項目の一括評価](../batches/)）。

`KinkPolicy` は `TapeOptions::with_kink_policy` と `BatchOptions::with_kink_policy` で選ぶ。

| 方針 | 動作 |
|---|---|
| `Midpoint`（既定） | 中点の導関数を使い、数を返す |
| `Error` | 数が 0 でなければ、変換の境界で `DomainError`（引数 `point`、理由 `Undefined`）を返す |

`Error` の判定は記録の直後、勾配や積を書く前に行われるので、失敗した変換は出力を書き換えない。
`Tape::linearize` では記録の時点で失敗し、`Linearization` の積には進まない。
途中の値が区間で一定になる計算では、`Error` はその区間のすべての点を拒む（$\max(\max(x, 0), 0)$ なら $x \le 0$ のすべての点）。
折れ点に当たったかどうかを確かめたい検証では `Error` を使い、当たっても続けたい計算では `Midpoint` のまま `kinks()` を読んで、結果の扱いを決める。

一括評価では、`BatchOptions::with_kink_policy(KinkPolicy::Error)` は逆モードを選ばせ、評価する Plan が各ワーカーのテープにこの方針を渡す。
項目のどれかの能動的な引数が折れ点にあると、`evaluate_into` と `hvp_into` は出力を書かずに `DomainError` を返す。
二重数で進む `jvp_into` は折れ点を数えないので、この方針は効かない。

次のセルは、表の関数、上で扱った 3 つの合成、`select` で書いた $|x|$ を折れ点で評価し、`Dual::variable` の導関数と、`Tape::gradient_into` の勾配と折れ点の数を比べる。
入力はテープの `KinkPolicy` である。
1 つ目の表の「Clarke の一般化勾配」の列は関数全体の一般化勾配（1 変数なので区間）を手で求めた値で、値が跳ぶ関数では「不連続」と表示する。
テープの勾配の出力は事前に 9 で埋めてあり、失敗した変換が出力を書き換えないことを確かめる。
2 つ目の表は `Midpoint` の別のテープで数え方の規則を確かめる。

```rust
// 各行の関数。どれも数値型 R について一度だけ書く。
fn row<R: Real>(index: usize, x: R) -> R {
    let zero = R::zero();
    match index {
        0 | 1 => x.abs(),
        2 => x.max(zero),
        3 => x.max(x),
        4 => x.max(zero) - (-x).max(zero),
        5 => x.max(zero).max(zero),
        6 => x.max(zero).max(zero) - x.max(zero),
        7 => x.hypot(zero),
        8 => R::select(x.lt(zero), -x, x),
        9 => x.floor(),
        10 => x.fract(),
        _ => x.atan2(R::constant(-1.0)),
    }
}

    { "key": "3", "label": "Dual の導関数 [-]", "type": "number", "format": fixed2 },
    { "key": "4", "label": "テープの勾配の出力 [-]", "type": "number", "format": fixed2 },
    { "key": "5", "label": "折れ点の数 [回]", "type": "integer" },
    { "key": "6", "label": "Dual の値は Clarke に", "nullText": "—" },
    { "key": "7", "label": "テープの結果" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "kinks" })
);
emit_table_with_columns!(
    ["記録", "折れ点の数 [回]"],
    counts,
    metadata = serde_json::json!({ "id": "counting" })
);
```

既定の `Midpoint` では、`Dual` とテープがすべての行で同じ値を返す。
関数全体の Clarke の一般化勾配が定義される 9 行のうち 8 行で、その値は一般化勾配に入る。
$\max(\max(x, 0), 0)$ の行は $\tfrac14$ を返し、テープは 2 回数える。
この値は関数の片側導関数 0 と 1 の中点 $\tfrac12$ とは違うが、一般化勾配 $[0, 1]$ には入る。
$\max(\max(x, 0), 0) - \max(x, 0)$ の行だけが $-\tfrac14$ を返して外れ、テープはこの行で 3 回の折れ点を数える（$\max(x, 0)$ が 2 回、外側の `max` が 1 回）。
$\max(x, 0) - \max(-x, 0)$ の行は 2 回数えられるが、値は正しい 1 である。
`select` で書いた $|x|$ は選んだ側の導関数 1 を返し、折れ点として数えられない。
値が跳ぶ `floor`、`fract`、`atan2` の分枝切断は、それぞれ両側で等しい導関数 0、1、$-1$ を返し、1 回ずつ数えられる。
$x = -2$ の $|x|$ は折れ点ではないので、数は 0 で、導関数は古典的な $-1$ である。

`KinkPolicy::Error` にすると、数が 1 以上の 10 行が `DomainError`（引数 `point`、理由 `Undefined`）になり、勾配の出力は事前に入れた 9 のまま残る。
$x = -2$ の $|x|$ と、`select` で書いた $|x|$ は成功する。
`select` で書いた分岐は `Error` でも検出されないので、境界の扱いは書いた側で確かめる必要がある。

2 つ目の表では、$|x| + \max(x, x)$ が 2 つの演算でそれぞれ 1 回、受動的な $|0|$ は 0 回、片方の引数だけが能動的な $\max(x, 1)$ は 1 回である。
$\max(\max(x, 0), 0)$ は、関数が滑らかな点 $x = -1$ でも外側の `max` が同点になるので、1 回数えられる。
4 lane の $|x|$ は、値が 0 の 2 つの lane で 2 回である。

## 絶対零の積 azmul

`Real::azmul(a, b)` は、積 $a \cdot b$ を返すが、どちらかの因子が厳密に 0 なら、相手が無限大や NaN でも $+0$ を返す。
これを絶対零の積（absolute-zero product）と呼ぶ（B. M. Bell, CppAD）。
IEEE 754 の積では $0 \cdot \infty$ と $0 \cdot \text{NaN}$ は NaN になる。

連鎖律の各項は（偏導関数）×（接ベクトルまたは随伴）の形をしている。
接ベクトルが厳密に 0 の経路は導関数に寄与しないはずだが、偏導関数が無限大（$x = 0$ での $\sqrt{x}$ や $\ln x$ の偏導関数）だと、IEEE の積では NaN になり、導関数全体を NaN にする。
`azmul` はこの項を 0 にする。

`scioxide-ad` の積の使い分けは次のとおりである。

| 場所 | 積 |
|---|---|
| テープの逆走査と接ベクトルの走査 | すべての更新に `azmul` |
| `Dual`、`MultiDual` | `×`、スカラー倍、`to_degrees`、`to_radians`、`fract`、`exp`、`exp2`、`exp_m1`、`sin`、`cos`、`sinh`、`cosh`、`tanh`、`atan`、`asinh` の偏導関数は IEEE 積、ほかの偏導関数は `azmul` |
| `Jet` | 折れ点の規則（`abs`、`min`、`max`、`%`）は `azmul`、ほかの係数の漸化式は IEEE 積 |

この使い分けから、次の 2 つの帰結が出る。
1 つ目に、$\sqrt{\max(v, 0)}$ の $v < 0$ での導関数は、`Dual`、`MultiDual` と逆モードで $+0$ になる。
`max` が定数 0 を返すので接ベクトルは 0 で、$\sqrt{\cdot}$ の 0 での偏導関数 $+\infty$ との積が `azmul` で $+0$ になるからである。
`Jet` では $\sqrt{\cdot}$ の係数の漸化式で同じ積が IEEE 積になるので、$c_1$ は NaN になる。
2 つ目に、IEEE 積を使う規則では、無限大（または NaN）の偏導関数と厳密に 0 の接ベクトルの積が、前進モードでは NaN、テープの走査では 0 になる。
$x \cdot y$ を $(x, y) = (+\infty, 2)$ で方向 $(1, 0)$ に微分すると、`Dual` は $2 \cdot 1 + \infty \cdot 0 = \text{NaN}$ を、テープの `jvp_into` は $2$ を返す。

2 つ目の場合を除くと、1 つの演算についてテープの勾配と `Dual` の導関数はビットで一致し、違いは厳密に 0 の導関数がテープでは $+0$ になることだけである。

次のブロックは、このページの残りの 2 つのセルが使う定義である。
`clipped_root` は $\sqrt{\max(v, 0)}$ を数値型 `R` の演算で書いた関数である。
`class` は表に値の種類を示すための分類で、非有限の値を `NaN`、`+∞`、`−∞`、0 を符号つきで `+0`、`−0` と示す。

```rust
//| id: ad-non-finite-helpers
//| kind: definitions
//| title: √max(v, 0) と値の分類
//| crates: [scioxide-ad]
use scioxide_ad::Real;

/// √max(v, 0)。数値型 R の演算で書く。
pub(crate) fn clipped_root<R: Real>(v: R) -> R {
    v.max(R::zero()).sqrt()
}

/// 非有限の値は数値の列に入れず、この分類の文字列で示す。0 は符号を区別する。
pub(crate) fn class(v: f64) -> &'static str {
    if v.is_nan() {
        "NaN"
    } else if v.is_infinite() {
        if v > 0.0 { "+∞" } else { "−∞" }
    } else if v == 0.0 {
        if v.is_sign_negative() { "−0" } else { "+0" }
    } else {
        "有限"
    }
}
```

次のセルは上の 2 つの帰結を確かめる。
$\sqrt{\max(v, 0)}$ の $v = -1$ での導関数を `Dual`、テープ、`Jet` の $c_1$ で求め、$x \cdot y$ の $(+\infty, 2)$ での方向 $(1, 0)$ の微分を `Dual` とテープの `jvp_into` で求める。
比較のため、`azmul(+∞, 0)` と f64 の IEEE の積 $+\infty \times 0$ も示す。
表の数値の列は有限の値だけを表示し、値の種類は分類の列に示す。

```rust
//| id: ad-azmul-products
//| ref: ad-azmul-products
//| title: 絶対零の積と IEEE 積による導関数の違い
//| run: reactive
//| crates: [scioxide-ad, scioxide-core]
//| uses: [ad-non-finite-helpers]
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"products","path":"/rows/0/2","equals":"+0"}
//|       - {"artifact":"products","path":"/rows/1/2","equals":"NaN"}
//|       - {"artifact":"products","path":"/rows/2/2","equals":"+0"}
//|       - {"artifact":"products","path":"/rows/3/2","equals":"+0"}
//|       - {"artifact":"products","path":"/rows/4/2","equals":"NaN"}
//|       - {"artifact":"products","path":"/rows/5/2","equals":"NaN"}
//|       - {"artifact":"products","path":"/rows/6/1","approx":{"value":2,"atol":1e-15}}
//|       - {"artifact":"products","path":"/rows/7/2","equals":"+∞"}
use scioxide_ad::{Dual, Jet, Real, Tape, TapeOptions};
use scioxide_core::ExecutionContext;

let cx = ExecutionContext::sequential();
// √max(v, 0) の v = −1 での導関数。
let root_dual = clipped_root(Dual::variable(-1.0)).derivative();
let root_jet = clipped_root(Jet::<f64, 2>::variable(-1.0)).coefficients()[1];
let mut tape = Tape::<f64>::new(TapeOptions::new());
let mut root_tape = [0.0];
tape.gradient_into(|x| Ok(clipped_root(x[0])), &[-1.0], &mut root_tape, cx)
    .map_err(|e| e.to_string())?;
// x·y の (+∞, 2) での方向 (1, 0) の微分。
let product_dual = (Dual::new(f64::INFINITY, 1.0) * Dual::new(2.0, 0.0)).derivative();
let (mut product_jvp, mut product_vjp) = ([0.0], [0.0; 2]);
{
    let mut linear = tape
        .linearize(
            |x, y| {
                y.push(x[0] * x[1]);
                Ok(())
            },
            &[f64::INFINITY, 2.0],
            cx,
        )
        .map_err(|e| e.to_string())?;
    linear
        .jvp_into(&[1.0, 0.0], &mut product_jvp, cx)
        .map_err(|e| e.to_string())?;
    linear
        .vjp_into(&[1.0], &mut product_vjp, cx)
        .map_err(|e| e.to_string())?;
}
// 2 行目は比較のための f64 の IEEE の積で、SciOxide の規則ではない。
let products: Vec<_> = [
    ("azmul(+∞, 0)", <f64 as Real>::azmul(f64::INFINITY, 0.0)),
    ("+∞ × 0（IEEE の積）", f64::INFINITY * 0.0),
    ("√max(v, 0)、v = −1：Dual の導関数", root_dual),
    ("同上：テープの勾配", root_tape[0]),
    ("同上：Jet の c₁", root_jet),
    ("x·y、(+∞, 2)、方向 (1, 0)：Dual の導関数", product_dual),
    ("同上：テープの jvp_into", product_jvp[0]),
    ("同上：テープの vjp_into の ∂/∂y", product_vjp[1]),
]
.iter()
.map(|&(name, v)| (name, v.is_finite().then_some(v), class(v)))
.collect();

let general = serde_json::json!({ "significantDigits": 6 });
let product_columns = serde_json::json!([
    { "key": "0", "label": "式と方式" },
    { "key": "1", "label": "結果 [-]", "type": "number", "format": general, "nullText": "非有限" },
    { "key": "2", "label": "分類" }
]);
emit_table_with_columns!(
    product_columns,
    products,
    metadata = serde_json::json!({ "id": "products" })
);
```

`azmul(+∞, 0)` は $+0$、IEEE の積 $+\infty \times 0$ は NaN を返す。
$\sqrt{\max(v, 0)}$ の $v = -1$ での導関数は、`Dual` とテープでは `azmul` によって $+0$ になり、IEEE 積を使う `Jet` の $c_1$ は NaN になる。
$x \cdot y$ を $(+\infty, 2)$ で方向 $(1, 0)$ に微分すると、`×` に IEEE 積を使う `Dual` は NaN、`azmul` を使うテープの `jvp_into` は 2 を返す。
`vjp_into` の $\partial/\partial y$ は偏導関数 $x = +\infty$ そのものなので、$+\infty$ である。

## 非有限値と NonFinitePolicy

IEEE 754 の非有限値（NaN と $\pm\infty$）は、数学的な特異点（$\sqrt{x}$ の原点での導関数 $+\infty$、$\ln 0 = -\infty$）、あふれ（$e^{710}$）、不定形（$0/0$）から生じる（[浮動小数点数と条件数](../../../concepts/floating-point-and-conditioning/)）。
数値型の演算は引数を検査せず、NaN と無限大をそのまま伝える。
検査は点を受け取って結果を書く変換の境界で `NonFinitePolicy` に従って行う。

| 方針 | 動作 |
|---|---|
| `Propagate`（既定） | 計算した値を、NaN や無限大も含めてそのまま書く |
| `Error` | 関数を実行する前に点を検査し、非有限なら `NonFinite`（発生源 `Input`）を返す。値や導関数が非有限なら、何も書く前に `NonFinite`（発生源 `Output`）を返す |

`Tape` では `TapeOptions::with_non_finite_policy` で、一括評価では `BatchOptions::with_non_finite_policy` で選ぶ。
点の検査は、`Tape<Dual<f64>>` のように包んだ値では値と導関数のすべての成分に及ぶ。
`Error` のもとでは、記録の直後に出力の値を、`gradient_into` と `Linearization` の各積（`vjp_into`、`jvp_into` など）では書く前に結果を検査する。
エラーの発生源は `e.view()` の `SciOxideErrorView::NonFinite { origin, .. }` で読める。
`grad` などのワンショット関数は既定の `Propagate` を使う。
`Dual` や `Jet` を直接使う前進モードと、`jvp`、`jet` には方針がないので、必要なら結果を `is_finite()` で調べる。

次のセルは非有限値を生む 6 つの式を `Tape::gradient_into` で評価する。
入力はテープの `NonFinitePolicy` である。
値と勾配の種類は前のセルと同じ分類で示し、勾配の出力は事前に 7 で埋めて、失敗した変換が出力を書き換えないことを確かめる。

```rust
//| id: ad-non-finite-checks
//| ref: ad-non-finite-checks
//| title: NonFinitePolicy による点と結果の検査
//| run: reactive
//| crates: [scioxide-ad, scioxide-core]
//| uses: [ad-non-finite-helpers]
//| inputs:
//|   policy: {"type":"select","label":"テープの NonFinitePolicy","description":"Error では非有限な点と結果がエラーになる。","options":["Propagate","Error"],"value":"Propagate"}
//| cases:
//|   - {"id":"error-policy","label":"NonFinitePolicy::Error","description":"非有限な点は Input、非有限な値や勾配は Output のエラーになる。","inputs":{"policy":"Error"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"policy","path":"/rows/0/3","equals":"+∞"}
//|       - {"artifact":"policy","path":"/rows/2/1","equals":"NaN"}
//|       - {"artifact":"policy","path":"/rows/3/2","approx":{"value":2e200,"rtol":1e-15}}
//|       - {"artifact":"policy","path":"/rows/5/4","equals":"成功"}
//|   - case: error-policy
//|     expect:
//|       - {"artifact":"policy","path":"/rows/0/4","equals":"NonFinite（発生源 Output）"}
//|       - {"artifact":"policy","path":"/rows/0/2","equals":7}
//|       - {"artifact":"policy","path":"/rows/0/3","equals":"書き込まれない"}
//|       - {"artifact":"policy","path":"/rows/2/4","equals":"NonFinite（発生源 Input）"}
//|       - {"artifact":"policy","path":"/rows/3/4","equals":"NonFinite（発生源 Output）"}
//|       - {"artifact":"policy","path":"/rows/5/4","equals":"成功"}
use scioxide_ad::{NonFinitePolicy, Real, Tape, TapeOptions, Var};
use scioxide_core::{ExecutionContext, SciOxideErrorKind, SciOxideErrorView, NonFiniteOrigin};

let cx = ExecutionContext::sequential();
let non_finite = match policy.as_str() {
    "Error" => NonFinitePolicy::Error,
    _ => NonFinitePolicy::Propagate,
};
let mut strict = Tape::<f64>::new(TapeOptions::new().with_non_finite_policy(non_finite));
let specs: [(&str, f64, for<'t> fn(Var<'t, f64>) -> Var<'t, f64>); 6] = [
    ("√x、x = 0", 0.0, |x| x.sqrt()),
    ("1/x、x = 0", 0.0, |x| x.recip()),
    ("2x、x = NaN", f64::NAN, |x| x * 2.0),
    ("x·x、x = 10²⁰⁰", 1e200, |x| x * x),
    ("ln x、x = −1", -1.0, |x| x.ln()),
    ("√max(x, 0)、x = −1", -1.0, |x| clipped_root(x)),
];
let mut rows = Vec::new();
for &(name, point, f) in &specs {
    let mut gradient = [7.0];
    let outcome = strict.gradient_into(|x| Ok(f(x[0])), &[point], &mut gradient, cx);
    let (value_class, status) = match outcome {
        Ok(value) => (class(value), "成功".to_string()),
        Err(error) => {
            let status = match (error.kind(), error.view()) {
                (SciOxideErrorKind::NonFinite, SciOxideErrorView::NonFinite { origin, .. }) => {
                    let origin = match origin {
                        NonFiniteOrigin::Input => "Input",
                        NonFiniteOrigin::Output => "Output",
                        _ => "その他",
                    };
                    format!("NonFinite（発生源 {origin}）")
                }
                _ => error.to_string(),
            };
            ("返らない", status)
        }
    };
    // 失敗した変換は出力を書き換えないので、勾配の出力は 7 のまま残る。
    let g = gradient[0];
    let gradient_class = if value_class == "返らない" {
        "書き込まれない"
    } else {
        class(g)
    };
    rows.push((
        name,
        value_class,
        g.is_finite().then_some(g),
        gradient_class,
        status,
    ));
}

let general = serde_json::json!({ "significantDigits": 6 });
let policy_columns = serde_json::json!([
    { "key": "0", "label": "式と点" },
    { "key": "1", "label": "値の分類" },
    { "key": "2", "label": "勾配の出力 [-]", "type": "number", "format": general, "nullText": "非有限" },
    { "key": "3", "label": "勾配の分類" },
    { "key": "4", "label": "結果" }
]);
emit_table_with_columns!(
    policy_columns,
    rows,
    metadata = serde_json::json!({ "id": "policy" })
);
```

既定の `Propagate` では、6 つの式がすべて成功し、非有限の値と勾配がそのまま書かれる。
$\sqrt{x}$ の 0 での勾配は $+\infty$、$1/x$ は値 $+\infty$ と勾配 $-\infty$ になる。
NaN の点での $2x$ は値が NaN で勾配は 2、$10^{200}$ での $x \cdot x$ は値が $+\infty$ にあふれるが勾配 $2 \times 10^{200}$ は有限、$\ln(-1)$ は値が NaN で勾配 $-1$ になる。
この 3 行は勾配だけを見ると有限なので、値も検査しないと異常を見落とす。

`Error` にすると、NaN の点は関数を実行する前に発生源 `Input` で失敗し、ほかの 4 つは値か勾配の検査で発生源 `Output` で失敗する。
失敗した行の勾配の出力は 7 のまま残る。
$\sqrt{\max(x, 0)}$ は値も勾配も有限なので、どちらの方針でも成功する。

## まとめ

`scioxide-ad` のすべての数値型は折れ点で原則として片側導関数の中点を使い、1 つの Lipschitz な演算ではその値が Clarke の一般化勾配に入るが、合成した関数では外れることがある。
テープは能動的な引数が折れ点にある演算を演算と lane ごとに数えるので、`TapeReport::kinks()` が 0 でない結果は規約で選んだ導関数として扱い、必要なら点をずらすか滑らかな近似と比べて確かめる。
折れ点に当たった計算を止めたいときはテープを `KinkPolicy::Error` にして `DomainError`（引数 `point`）を受け取り、`select` で書いた分岐の境界は数えられないことを前提にする。
一括評価も `Error` の下では折れ点で `DomainError` を返し、`Midpoint` の下では数を `BatchEstimate::kinks()` に返す。
テープの走査と多くの前進の規則は `azmul` を使うので、接ベクトルが厳密に 0 の経路の無限大の偏導関数から NaN は生じないが、IEEE 積を使う規則（`Jet` の係数の漸化式を含む）では NaN になりうる。
非有限値を早く止めたいときは `NonFinitePolicy::Error` にし、発生源 `Input` と `Output` で点の異常と結果の異常を区別する。
