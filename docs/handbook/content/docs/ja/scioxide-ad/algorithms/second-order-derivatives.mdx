Newton 法、信頼領域法、平衡点の安定性の解析では、スカラー関数 $f: \mathbb{R}^n \to \mathbb{R}$ のヘッセ行列 $H = \nabla^2 f$ が要る。
密な $H$ は $n^2$ 個の成分を持ち、勾配の方向微分を $n$ 回行って求める。
Krylov 部分空間法のような反復解法が使うのは、積 $Hv$ や、写像 $F: \mathbb{R}^n \to \mathbb{R}^m$ のヤコビ行列 $J$ との積 $Jv$、$J^{\mathsf T} w$ だけであることが多い。
このページはヘッセ行列とベクトルの積を勾配の方向微分として導き、`scioxide-ad` でそれを求める関数と、行列を組み立てずに積だけを計算する作用素を説明する。
テープの記録、逆走査、前進走査（記録を先頭から末尾へたどって接ベクトルを書く走査）の規則は[逆モードとテープ](../reverse-mode-and-replay/)、二重数は[前進モードと二重数](../forward-mode/)で説明する。
疎な $H$ や $J$ を少ない回数の方向微分から復元する方法は[構造パターンと疎な微分の復元](../sparse-derivatives/)で扱う。

導出では、$f$ が評価点の近くで 2 回連続微分可能であることを仮定する。
このとき $H$ は対称である。
折れ点（kink、片側導関数が一致しない点）での規約は[折れ点と非有限値の扱い](../nonsmooth-and-nonfinite-policies/)にある。

## ヘッセ行列とベクトルの積の導出

勾配を $g(x) = \nabla f(x)$ と書くと、ヘッセ行列とベクトルの積（HVP、Hessian-vector product）は勾配の方向微分である。

$$
H(x)\,v = \left.\frac{d}{dt}\, g(x + t v)\right|_{t=0}
$$

逆モードの勾配は関数をテープに記録して逆走査（reverse sweep）を 1 回行う計算で、$g$ を $x$ の関数として与える。
二重数 $a + \dot a\,\varepsilon$（$\varepsilon^2 = 0$）の算術で、微分可能な写像 $G$ を $x + v\,\varepsilon$ において評価すると、$G(x) + G'(x)\,v\,\varepsilon$ が得られる。
記録と逆走査をまとめて $G = g$ とみなし、入力を二重数 $x_i + v_i\,\varepsilon$ にして同じ計算を二重数の算術で行えば、値の部分に $\nabla f(x)$、導関数の部分に $H(x)\,v$ が出る。
前進モードを逆モードの外側に重ねるこの方法を forward-over-reverse と呼ぶ。

文（statement、テープの 1 記録）ごとに見ると次のようになる。
文 $u_i = \phi_i(u_j, \dots)$ の偏導関数 $\partial\phi_i/\partial u_j$ は二重数として記録され、その導関数の部分は方向 $v$ に沿った変化 $\sum_k (\partial^2\phi_i/\partial u_j\,\partial u_k)\,\dot u_k$ である。
ここで $\dot u_k$ は $u_k$ の接ベクトル（tangent）の成分で、入力では $\dot x = v$ である。
逆走査は随伴（adjoint）$\bar u$ を二重数 $\bar u + \dot{\bar u}\,\varepsilon$ として運び、出力の $\bar u_L = 1$、$\dot{\bar u}_L = 0$ から始めて、各文で

$$
\bar u_j \mathrel{+}= \bar u_i\,\frac{\partial \phi_i}{\partial u_j}, \qquad
\dot{\bar u}_j \mathrel{+}= \dot{\bar u}_i\,\frac{\partial \phi_i}{\partial u_j} + \bar u_i \sum_k \frac{\partial^2 \phi_i}{\partial u_j\,\partial u_k}\,\dot u_k
$$

と更新する。
2 つ目の式は 1 つ目の式を二重数の積で計算したときの $\varepsilon$ の係数である。
入力に戻ったとき $\bar x = \nabla f(x)$、$\dot{\bar x} = H(x)\,v$ になる。
各文に要るのは局所的な 1 階と 2 階の偏導関数だけで、$n \times n$ の行列は作らない。

計算コストは二重数での記録 1 回と逆走査 1 回で、勾配 1 回の小さな定数倍である。
定数は演算の種類で決まり、$n$ によらない。
記録される偏導関数（定数の偏導関数を除く）と随伴が二重数なので、テープは同じ関数の `Tape<f64>` より多くのメモリ領域を使う。
比較は入れ子の最も内側の値で行うので、分岐は点 $x$ で選ばれ、$Hv$ は選ばれた分岐の式の微分になる。
差分の打ち切り誤差はなく、誤差は各文の偏導関数の丸めと足し込みの丸めである。

## hvp_into とワンショット呼び出しの hvp・hessian

`Tape<Dual<S>>` の `hvp_into(function, point, direction, product, context)` は、関数をシード `Dual::new(xᵢ, vᵢ)` で記録して逆走査を 1 回行い、$Hv$ を `product` に書いて値 $f(x)$ を返す。
`function` はスカラーを 1 つ返す関数で、その引数は `&[Var<'_, Dual<f64>>]` である。
クロージャを渡すときは `|x: &[Var<'_, Dual<f64>>]|` と引数の型を書き、モデルは `R: Real` の汎用関数にしてクロージャの中で呼ぶ。
`direction` か `product` の長さが `point` と違えば `DimensionMismatch` を返す。
ほかの失敗は `Tape::gradient_into` の記録の失敗と同じである。
たとえば `NonFinitePolicy::Error` の下では、二重数の値の部分と導関数の部分のどちらかが非有限なら `NonFinite` になり、`KinkPolicy::Error` の下では折れ点に当たると `DomainError` になる。
失敗したとき `product` は書き換えられない。
シードの配列はテープが持ち、同じテープで同じ関数を 2 回目以降に呼ぶときは確保しない。

ワンショット呼び出しの `hvp(function, point, direction)` と `hessian(function, point)` は、新しいテープと `ExecutionContext::sequential_native()` を使い、結果を確保して返す。
`hvp` は `scioxide_linalg::Vector`、`hessian` は行優先の $n \times n$ の `scioxide_linalg::Matrix` を返す。
`hessian` は単位方向 $e_j$ ごとに 1 回記録し、$H e_j$ を第 $j$ 列に書くので、記録は $n$ 回である。
新しいテープでは最初の実行が文の数を数えるだけで終わり、テープを広げて関数をもう一度実行して記録する（[テープのライフサイクルと再利用](../tape-lifecycle/)）。
そのため関数の実行は `hvp` で 2 回、`hessian` で $n + 1$ 回になる。
入力がない（$n = 0$）ときも、`hessian` は関数を 2 回実行して関数のエラーを確かめてから、$0 \times 0$ の行列を返す。
$n \times n$ が `usize` に収まらなければ、関数を実行する前に `SizeOverflow` を返し、結果を確保できなければ `AllocationFailure` を返す。
$H_{ij}$ と $H_{ji}$ は別々の記録から読むので、`hessian` の結果は丸めの範囲で対称であり、対称化はしない。
同じ点で多くの方向に掛けるときは、1 つのテープで `hvp_into` を繰り返すほうが、確保も文の数を数えるための実行もない。
密な $H$ は $n$ が小さいときか検算に使う。

## 前進モードを重ねる方法

テープを使わずに、前進モードの数値型を入れ子にしても 2 階の量が求まる。
`Dual<Dual<f64>>` の入力を $x_i = (p_i + v_i\,\varepsilon_1) + (u_i + 0\,\varepsilon_1)\,\varepsilon_2$ とすると、出力の $\varepsilon_1\varepsilon_2$ の係数、つまり `f.derivative().derivative()` は $u^{\mathsf T} H v$ である。
1 回の評価で得られるのは 2 方向の 2 階微分の数 1 つである。

`Dual<MultiDual<f64, n>>` の入力を `Dual::new(MultiDual::variable(pᵢ, i)?, MultiDual::constant(vᵢ))` とすると、`f.value().gradient()` が $\nabla f$、`f.derivative().gradient()` が $\nabla(\nabla f \cdot v) = Hv$ になる。
得られるのは 1 本の $Hv$ の $n$ 個の成分である。
各演算が $2(n + 1)$ 個の値を保持するので、計算コストは評価 1 回の $n$ に比例する倍数で、入力が少ないときに向く。
演算の順序が forward-over-reverse と違うので、結果は `hvp_into` と丸めの範囲で一致し、ビット単位で一致するとは限らない。

方向が $K$ 本あるときは、逆モードの外側に `MultiDual<f64, K>` を重ねる。
`Tape<MultiDual<f64, K>>` の `gradient_into` にシード `MultiDual::new(pᵢ, [v₁ᵢ, …, v_Kᵢ])` を渡すと、勾配の第 $i$ 成分は値の部分が $\partial f/\partial x_i$、導関数の部分が $((Hv_1)_i, \dots, (Hv_K)_i)$ の `MultiDual` になる。
記録 1 回と逆走査 1 回で $K$ 本の HVP が得られ、各演算の導関数の部分が $K$ 個の値を保持する。
`MultiDual` の各成分は `Dual` と同じ規則で計算されるので、後のセルの関数では、各方向の結果が `hvp_into` とビット単位で一致する。

## 非線形ばねの鎖

このページのセルは直線上に並んだ $n$ 個の変数 $x_0, \dots, x_{n-1}$ を非線形のばねでつないだ鎖を使う。
到達距離 $b$ までの組 $(i, i + d)$（$1 \le d \le b$）をばねでつなぎ、伸び $u = x_{i+d} - x_i$ のばねのエネルギーを $\varphi(u) = u^2 + u^4$ とする。
全エネルギーと、ばねの張力を並べた写像は

$$
E(x) = \sum_{d=1}^{b} \sum_{i=0}^{n-1-d} \varphi(x_{i+d} - x_i), \qquad
F_k(x) = \varphi'(u_k) = 2u_k + 4u_k^3
$$

である。
ばねの番号 $k$ は $d$ の昇順、同じ $d$ の中で $i$ の昇順に付け、ばねの数は $m = \sum_{d=1}^{b}(n - d)$ である。
各ばねの伸びを並べる $m \times n$ の差分行列を $D$（ばね $k = (i, i + d)$ の行は第 $i$ 列が $-1$、第 $i + d$ 列が $+1$）とすると、$u = Dx$ であり、

$$
\nabla E = D^{\mathsf T} F(x), \qquad
J_F = \operatorname{diag}(\varphi''(u))\,D, \qquad
H_E = D^{\mathsf T} \operatorname{diag}(\varphi''(u))\,D = D^{\mathsf T} J_F
$$

が成り立つ（$\varphi''(u) = 2 + 12u^2$）。
評価点は $x_i = 0.3 \sin(1.7\,i)$ とする。

次の定義のブロックは $E$ を `chain_energy`、$F$ を `bond_tensions`、評価点を `chain_point` として、どの数値型でも動く汎用関数で書く。

```rust
//| id: ad-spring-chain-model
//| kind: definitions
//| title: 非線形ばねの鎖のエネルギーと張力
//| crates: [scioxide-ad, scioxide-core]
use scioxide_ad::Real;
use scioxide_core::RealScalar;

/// 評価点 xᵢ = 0.3 sin(1.7 i)（入力データ）。
pub(crate) fn chain_point(n: usize) -> Vec<f64> {
    (0..n)
        .map(|i| 0.3 * RealScalar::sin(1.7 * i as f64))
        .collect()
}

/// E(x) = Σ_{d=1}^{b} Σ_i φ(x_{i+d} − x_i)、φ(u) = u² + u⁴。
pub(crate) fn chain_energy<R: Real>(x: &[R], reach: usize) -> R {
    let n = x.len();
    let mut total = R::zero();
    for d in 1..=reach {
        for i in 0..n.saturating_sub(d) {
            let u = x[i + d] - x[i];
            let u2 = u * u;
            total = total + u2 + u2 * u2;
        }
    }
    total
}

/// 張力 F_k = φ′(u_k) = 2u_k + 4u_k³ を、d の昇順、同じ d の中で i の昇順に積む。
pub(crate) fn bond_tensions<R: Real>(x: &[R], reach: usize, out: &mut Vec<R>) {
    let n = x.len();
    for d in 1..=reach {
        for i in 0..n.saturating_sub(d) {
            let u = x[i + d] - x[i];
            out.push(u * 2.0 + u * u * u * 4.0);
        }
    }
}
```

## 行列を作らない作用素

反復解法に $H$ や $J$ を渡すときは、行列を組み立てずに積だけを計算する作用素を使う。
`scioxide-core` は、大きさ `rows() × cols()` の作用素を `output = A · input` として適用する `LinearOperator` と、さらに $A^{\mathsf T}$（複素数では $A^{\mathsf H}$）を適用する `AdjointOperator` を定める（[作用素プロトコルとクロージャ作用素](../../../scioxide-core/algorithms/operator-protocols-and-structure/)）。
どちらも作業領域を呼び出し側が渡し、その長さを `apply_workspace_len()` と `apply_adjoint_workspace_len()` で返す。
`scioxide-ad` の 2 つの作用素はこれらのトレイトを実装するので、`&dyn LinearOperator<f64>` を受け取る解法にそのまま渡せる。

| 作用素 | 作り方 | 実装するトレイト | 大きさ | 1 回の適用 | 作業領域の長さ |
|---|---|---|---|---|---|
| `HessianOperator` | `Tape<Dual<S>>` の `hessian_operator` | `LinearOperator` | $n \times n$ | 関数の記録 1 回と逆走査 1 回で $Hv$ | 0 |
| `JacobianOperator` | `Linearization` の `jacobian_operator` | `LinearOperator`、`AdjointOperator` | $m \times n$ | 記録を使い回す前進走査 1 回で $Jv$、逆走査 1 回で $J^{\mathsf T} w$ | 文の数と、呼び出し文の一時領域の 2 倍の和 |

`scioxide-core` には、点を変えながら非線形写像の $J(x)\,v$ を求めるトレイト `scioxide_core::JacobianOperator` もあるが、これは別の項目で、`scioxide_ad::JacobianOperator` はそれを実装しない。
`scioxide_ad::JacobianOperator` は 1 つの点の記録に固定された線形作用素である。

### HessianOperator

`hessian_operator` は、関数と点と実行コンテキスト（`ExecutionContext`）を受け取り、点 $x$ でのヘッセ行列の作用素を返す。
作用素はテープを可変に借用してセル（`Cell`）に入れ、各適用でテープを取り出して、方向をシードにした記録と逆走査を 1 回ずつ行い、テープを戻す。
$Hv$ の記録では偏導関数の二重数が方向 $v$ を含むので、記録は方向ごとに作り直す必要がある。
構築時に方向 0 で 1 回記録してテープの容量を決めるので、新しいテープでは構築で関数を 2 回実行し、その後は適用 1 回につき 1 回実行する。
分岐は点だけで決まり方向によらないので、その容量で以後の記録が足り、適用は確保しない。
各適用は構築時に渡したコンテキストで逆走査を行う。

作業領域は使わないので、`apply_workspace_len()` は 0 で、`apply_into` には空のスライスを渡す。
入力に非有限の値があれば `NonFinite`（発生元 `Input`）、結果が非有限なら `NonFinite`（発生元 `Output`）を返し、どちらの場合も出力を書き換えない。
これはテープの `NonFinitePolicy` によらない、作用素のプロトコルの要求である。
$H$ は対称だが `AdjointOperator` は実装しないので、随伴の適用を要求する解法には渡せない。
構築の失敗は方向 0 での `hvp_into` の記録の失敗と同じである。

### JacobianOperator

`Tape<S>::linearize` が返す `Linearization` の `jacobian_operator()` は、その記録の上の $J$ を作用素として返す。
`apply_into` は前進走査 1 回で $Jv$ を、`apply_adjoint_into` は逆走査 1 回で $J^{\mathsf T} w$ を求め、関数は実行し直さない。
作用素はテープを不変に借用し、走査の作業値は呼び出し側の作業領域に置く。
作業領域の長さは記録の文の数に、呼び出し文（`solve_into` などが記録する 1 文）の一時領域の 2 倍を足した値で、適用は確保しない。
適用はコンテキストを受け取らないので、走査は中断の確認を伴わずに最後まで進む。

入力と結果は有限でなければならず、そうでなければ `NonFinite` を返して出力を書き換えない。
記録が `checkpointed_loop` を含むときは、その積にテープが要るので、`jacobian_operator()` は `CapabilityUnavailable` を返す（[ループとチェックポイント](../checkpointing/)）。
作用素が生きている間は `Linearization` を可変に借用できないので、`vjp_into` などの積は作用素を手放してから呼ぶ。

### 対称性と随伴の検査

次のセルはばねの鎖の $H_E$ と $J_F$ を作用素として適用し、次の 4 つの関係を確かめる。

- 対称性 $\langle u, H v\rangle = \langle H u, v\rangle$。
- 随伴の関係 $\langle J v, w\rangle = \langle v, J^{\mathsf T} w\rangle$。
- $H_E = D^{\mathsf T} J_F$ から来る $Hv = D^{\mathsf T}(Jv)$。
  $D^{\mathsf T}$ はセルの中で差分の転置として手で掛ける独立な検算である。
- `HessianOperator` の $Hv$ と、`Tape<MultiDual<f64, 2>>` で 2 方向 $(u, v)$ を同時に求めた HVP の 2 本目の一致。

入力は変数の数 $n$（4 から 40）とばねの到達距離 $b$（1 から 3）である。
方向は $u_i = \sin(0.9 i + 0.3)$、$v_i = \cos(0.4 i)$、$w_k = \cos(0.7 k + 0.2)$ と決める。
1 つ目の表は 4 つの関係の両辺と差を、2 つ目の表は作用素の大きさと作業領域の長さを示す。

```rust
//| id: ad-derivative-operators
//| ref: ad-derivative-operators
//| title: ヘッセ行列とヤコビ行列の作用素の対称性と随伴の検査
//| run: reactive
//| uses: [ad-spring-chain-model]
//| crates: [scioxide-ad, scioxide-core]
//| inputs:
//|   masses: {"type":"range","label":"変数の数 n","min":4,"max":40,"step":1,"value":12}
//|   reach: {"type":"range","label":"ばねの到達距離 b","description":"x_i と x_{i+d}（1 ≤ d ≤ b）をばねでつなぐ。","min":1,"max":3,"step":1,"value":2}
//| cases:
//|   - {"id":"long-chain","label":"n = 40、b = 3","description":"ばねが 114 本の長い鎖。","inputs":{"masses":40,"reach":3}}
//|   - {"id":"shortest","label":"n = 4、b = 1","description":"ばね 3 本の最小の鎖。","inputs":{"masses":4,"reach":1}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"checks","path":"/rows/0/3","approx":{"value":0,"atol":1e-12}}
//|       - {"artifact":"checks","path":"/rows/1/3","approx":{"value":0,"atol":1e-12}}
//|       - {"artifact":"checks","path":"/rows/2/3","approx":{"value":0,"atol":1e-12}}
//|       - {"artifact":"checks","path":"/rows/3/3","equals":0}
//|       - {"artifact":"shapes","path":"/rows/0/1","equals":21}
//|       - {"artifact":"shapes","path":"/rows/1/1","equals":12}
//|       - {"artifact":"shapes","path":"/rows/4/1","equals":0}
//|   - case: long-chain
//|     expect:
//|       - {"artifact":"checks","path":"/rows/0/3","approx":{"value":0,"atol":1e-11}}
//|       - {"artifact":"checks","path":"/rows/1/3","approx":{"value":0,"atol":1e-11}}
//|       - {"artifact":"checks","path":"/rows/2/3","approx":{"value":0,"atol":1e-11}}
//|       - {"artifact":"shapes","path":"/rows/0/1","equals":114}
//|   - case: shortest
//|     expect:
//|       - {"artifact":"checks","path":"/rows/0/3","approx":{"value":0,"atol":1e-13}}
//|       - {"artifact":"checks","path":"/rows/1/3","approx":{"value":0,"atol":1e-13}}
//|       - {"artifact":"shapes","path":"/rows/0/1","equals":3}
use scioxide_ad::{Dual, MultiDual, Tape, TapeOptions, Var};
use scioxide_core::{AdjointOperator, ExecutionContext, LinearOperator, RealScalar};

let (n, b) = (masses as usize, reach as usize);
let cx = ExecutionContext::sequential();
let point = chain_point(n);
// 作用素に掛ける方向（入力データ）。
let u: Vec<f64> = (0..n)
    .map(|i| RealScalar::sin(0.9 * i as f64 + 0.3))
    .collect();
let v: Vec<f64> = (0..n).map(|i| RealScalar::cos(0.4 * i as f64)).collect();
let dot = |a: &[f64], c: &[f64]| a.iter().zip(c).map(|(x, y)| x * y).sum::<f64>();
let norm = |a: &[f64]| a.iter().fold(0.0_f64, |m, x| m.max(x.abs()));
let gap = |a: &[f64], c: &[f64]| {
    a.iter()
        .zip(c)
        .fold(0.0_f64, |m, (x, y)| m.max((x - y).abs()))
};

// H_E の作用素。適用ごとに Tape<Dual<f64>> へ記録し直し、作業領域は空。
let mut second = Tape::<Dual<f64>>::new(TapeOptions::new());
let hessian = second
    .hessian_operator(
        |x: &[Var<'_, Dual<f64>>]| Ok(chain_energy(x, b)),
        &point,
        cx,
    )
    .map_err(|e| e.to_string())?;
let (mut hu, mut hv) = (vec![0.0; n], vec![0.0; n]);
hessian
    .apply_into(&u, &mut hu, &mut [])
    .map_err(|e| e.to_string())?;
hessian
    .apply_into(&v, &mut hv, &mut [])
    .map_err(|e| e.to_string())?;
let h_workspace = hessian.apply_workspace_len().map_err(|e| e.to_string())?;

// 2 方向を 1 回の記録で: シード MultiDual(xᵢ, [uᵢ, vᵢ]) の勾配の導関数部分が [Hu, Hv]。
let seeds: Vec<MultiDual<f64, 2>> = (0..n)
    .map(|i| MultiDual::new(point[i], [u[i], v[i]]))
    .collect();
let mut pair = Tape::<MultiDual<f64, 2>>::new(TapeOptions::new());
let mut both = vec![MultiDual::new(0.0, [0.0; 2]); n];
pair.gradient_into(|x| Ok(chain_energy(x, b)), &seeds, &mut both, cx)
    .map_err(|e| e.to_string())?;
let hv_pair: Vec<f64> = both.iter().map(|g| g.gradient()[1]).collect();

// J_F の作用素。記録 1 回の上で前進走査と逆走査を行う。
let mut tape = Tape::<f64>::new(TapeOptions::new());
let linear = tape
    .linearize(
        |x, y| {
            bond_tensions(x, b, y);
            Ok(())
        },
        &point,
        cx,
    )
    .map_err(|e| e.to_string())?;
let jacobian = linear.jacobian_operator().map_err(|e| e.to_string())?;
let (m, cols) = (jacobian.rows(), jacobian.cols());
let j_workspace = jacobian.apply_workspace_len().map_err(|e| e.to_string())?;
let w: Vec<f64> = (0..m)
    .map(|k| RealScalar::cos(0.7 * k as f64 + 0.2))
    .collect();
let (mut work, mut jv, mut jtw) = (vec![0.0; j_workspace], vec![0.0; m], vec![0.0; n]);
jacobian
    .apply_into(&v, &mut jv, &mut work)
    .map_err(|e| e.to_string())?;
jacobian
    .apply_adjoint_into(&w, &mut jtw, &mut work)
    .map_err(|e| e.to_string())?;
let words = tape.report().words();

// 独立検算: H_E = Dᵀ J_F なので Hv = Dᵀ(Jv)。Dᵀ はばね (i, i + d) ごとに手で掛ける。
let mut dt_jv = vec![0.0; n];
let mut k = 0;
for d in 1..=b {
    for i in 0..n - d {
        dt_jv[i + d] += jv[k];
        dt_jv[i] -= jv[k];
        k += 1;
    }
}
let sig6 = serde_json::json!({ "significantDigits": 6 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let check_columns = serde_json::json!([
    { "key": "0", "label": "関係" },
    { "key": "1", "label": "左辺 A [-]", "type": "number", "format": sig6 },
    { "key": "2", "label": "右辺 B [-]", "type": "number", "format": sig6 },
    { "key": "3", "label": "差の最大値 [-]", "type": "number", "format": sci3 }
]);
let checks = vec![
    (
        "⟨u, Hv⟩ = ⟨Hu, v⟩",
        dot(&u, &hv),
        dot(&hu, &v),
        (dot(&u, &hv) - dot(&hu, &v)).abs(),
    ),
    (
        "⟨Jv, w⟩ = ⟨v, Jᵀw⟩",
        dot(&jv, &w),
        dot(&v, &jtw),
        (dot(&jv, &w) - dot(&v, &jtw)).abs(),
    ),
    (
        "Hv = Dᵀ(Jv)（両辺は最大値ノルム）",
        norm(&hv),
        norm(&dt_jv),
        gap(&hv, &dt_jv),
    ),
    (
        "作用素の Hv = MultiDual の 2 本目",
        norm(&hv),
        norm(&hv_pair),
        gap(&hv, &hv_pair),
    ),
];
emit_table_with_columns!(
    check_columns,
    checks,
    metadata = serde_json::json!({ "id": "checks" })
);
let shape_columns = serde_json::json!([
    { "key": "0", "label": "量" },
    { "key": "1", "label": "値", "type": "integer" }
]);
let shapes = vec![
    ("J の rows()（ばねの数 m）", m),
    ("J の cols()（変数の数 n）", cols),
    ("J の apply_workspace_len()", j_workspace),
    ("記録の文の数 TapeReport::words()", words),
    ("H の apply_workspace_len()", h_workspace),
];
emit_table_with_columns!(
    shape_columns,
    shapes,
    metadata = serde_json::json!({ "id": "shapes" })
);
```

既定の $n = 12$、$b = 2$ では、ばねは $m = 21$ 本である。
対称性の差は $2.4 \times 10^{-15}$ で、内積 $\langle u, Hv\rangle \approx 0.676$ に対する相対差 $3.6 \times 10^{-15}$ は丸めの水準である。
随伴の関係は両辺がビット単位で一致する。
$Hv$ と $D^{\mathsf T}(Jv)$ の差は $6.7 \times 10^{-16}$ である。
この 2 つは $H_E = D^{\mathsf T} J_F$ を別の経路（forward-over-reverse と、記録の前進走査に手で $D^{\mathsf T}$ を掛ける計算）で評価した値で、2 つの作用素が同じ関数の微分を与えていることを示す。
`Tape<MultiDual<f64, 2>>` で 2 方向を同時に求めた $Hv$ は作用素の $Hv$ とビット単位で一致する。
$J$ の作業領域の長さは記録の文の数 139 に等しく、この記録に呼び出し文がないことと合う。
$H$ の作業領域の長さは 0 である。

$n = 40$、$b = 3$（ばね 114 本）では対称性の差が $9.3 \times 10^{-15}$ に増えるが、内積 2.33 に対する相対差は $4 \times 10^{-15}$ で、足し込む項が増えたぶんの丸めの水準である。
$n = 4$、$b = 1$ ではどの差も $1.1 \times 10^{-16}$ 以下である。
既定値、2 つのケース、入力の両端のどれでも、内積の差は丸めの水準にとどまり、$J$ の作業領域の長さは記録の文の数に等しい。

## まとめ

同じ点で $H$ を多くの方向に掛けるなら、1 つの `Tape<Dual<f64>>` で `hvp_into` を繰り返すか、`hessian_operator` を反復解法に渡せば、1 回あたり勾配の定数倍の計算コストで、$n^2$ のメモリ領域を使わずに $Hv$ が得られる。
ワンショット呼び出しの `hvp` は関数を 2 回、`hessian` は $n + 1$ 回実行するので、関数の評価コストが大きいなら同じテープを使い回す。
$K$ 本の方向をまとめるなら `Tape<MultiDual<f64, K>>` の `gradient_into` を、入力が少なければ `Dual<MultiDual<f64, n>>` の前進モードを使える。
$J$ を何度も掛けるなら `Linearization::jacobian_operator()` を使い、作業領域を `apply_workspace_len()` の長さで 1 度用意すれば、適用は記録を走査するだけで確保しない。
随伴の適用を要求する解法には `JacobianOperator` を渡せるが、`HessianOperator` は `AdjointOperator` を実装しないので渡せない。
