前進モード（forward mode）は、入力側のベクトル $\mathbf{v}$ とヤコビ行列 $\mathbf{J}$ の積 $\mathbf{J}\mathbf{v}$（ヤコビ行列・ベクトル積、JVP）を返す。
逆モード（reverse mode）は、出力側のベクトル $\mathbf{w}$ との積 $\mathbf{J}^\mathsf{T}\mathbf{w}$（ベクトル・ヤコビ行列積、VJP）を返す。
どちらも $\mathbf{J}$ を作らずに計算する。
二つは同じ線形写像を両側から見たもので、任意の $\mathbf{v}$、$\mathbf{w}$ について $\langle \mathbf{w}, \mathbf{J}\mathbf{v} \rangle = \langle \mathbf{J}^\mathsf{T}\mathbf{w}, \mathbf{v} \rangle$ が成り立つ。

ロボットのアームでは、$\mathbf{J}$ が関節の角速度を手先の速度に写し、$\mathbf{J}^\mathsf{T}$ が手先にかかる力を関節のトルクに写す。
このとき上の恒等式は、荷重がする仕事率を手先の側と関節の側で計算したものが等しいという仮想仕事の原理になる。
この例題では平面上の多関節アームの順運動学を題材に、JVP と VJP の双対性を丸め誤差の尺度で確かめ、手先の速度と関節のトルクを閉形式と照合する。
後半では入力と出力の数を変えて、ヤコビ行列全体を組むのに要る走査の回数を `JacobianMode` ごとに比べる。

## 平面多関節アームの順運動学

全長 $L = 1$ m のアームを長さ $\ell = L/n$ [m] の $n$ 本のリンクに分け、回転関節でつないで根元を原点に固定する。
関節 $j$（$j = 0, \dots, n-1$）の角度 $\theta_j$ [rad] は一つ前のリンクに対する相対角で、関節 0 の角度は $x$ 軸から測る。
リンク $i$ の向きは $\varphi_i = \sum_{j \le i} \theta_j$ で、リンク $i$ の先端の位置は

$$
\mathbf{p}_i = \sum_{j=0}^{i} \ell\,(\cos\varphi_j, \sin\varphi_j), \qquad i = 0, \dots, n - 1
$$

である。
根元を $\mathbf{p}_{-1} = \mathbf{0}$ とおく。
出力には後ろの $k$ 本のリンクの先端 $\mathbf{p}_{n-k}, \dots, \mathbf{p}_{n-1}$ の座標を $(x_{n-k}, y_{n-k}, \dots, x_{n-1}, y_{n-1})$ の順に並べ、写像 $\mathbf{F}: \mathbb{R}^n \to \mathbb{R}^m$（$m = 2k$）とする。
$k = 1$ なら手先の位置だけである。
姿勢は各関節を同じ角度 $\theta_j = \Theta/n$ だけ曲げたものとする。
$\Theta = 0$ では $x$ 軸に沿ってまっすぐ伸び、$\Theta > 0$ では関節の位置が正多角形の頂点として 1 つの円の上に並び、$\Theta$ が大きいほど強く巻く（$\Theta = 360°$ で手先が根元に戻る）。

関節 $j$ を回すと、それより先のリンクは $\mathbf{p}_{j-1}$ を中心に一体で回る。
そのためヤコビ行列は

$$
\frac{\partial \mathbf{p}_i}{\partial \theta_j} =
\begin{cases}
\hat{\mathbf{z}} \times (\mathbf{p}_i - \mathbf{p}_{j-1}) = \bigl(-(y_i - y_{j-1}),\ x_i - x_{j-1}\bigr) & (j \le i) \\
\mathbf{0} & (j > i)
\end{cases}
$$

と書ける [m/rad]。
$\hat{\mathbf{z}} \times (\Delta x, \Delta y) = (-\Delta y, \Delta x)$ は平面内の 90° の回転である。
この閉形式を独立な検算に使う。

次のブロックは二つのセルが共有する定義である。
`arm` が $\mathbf{F}$ に対応する汎用関数で、出力を受け取ったベクトルに積む。
`joints` は根元と各リンクの先端の位置、`arm_jacobian` は上の閉形式の $\mathbf{J}$（行優先）を、`f64` の固有メソッドで計算する参照値である。

```rust
//| id: ad-arm-model
//| kind: definitions
//| title: 平面多関節アームの順運動学と閉形式のヤコビ行列
//| crates: [scioxide-ad]
use scioxide_ad::Real;

/// 関節角 θ [rad] から、後ろの tracked 個のリンクの先端位置 (x, y) [m] を out に積む。
pub(crate) fn arm<R: Real>(theta: &[R], link: f64, tracked: usize, out: &mut Vec<R>) {
    let n = theta.len();
    let mut angle = R::zero();
    let (mut x, mut y) = (R::zero(), R::zero());
    for (i, &joint) in theta.iter().enumerate() {
        angle += joint;
        let (sin, cos) = angle.sin_cos();
        x += cos * link;
        y += sin * link;
        if i + tracked >= n {
            out.push(x);
            out.push(y);
        }
    }
}

/// 根元 p₋₁ = 0 と各リンクの先端 p₀, …, pₙ₋₁ [m]。参照値（f64 の固有メソッド）。
pub(crate) fn joints(theta: &[f64], link: f64) -> Vec<[f64; 2]> {
    let mut angle = 0.0;
    let mut points = vec![[0.0, 0.0]];
    for &joint in theta {
        angle += joint;
        let [x, y] = points[points.len() - 1];
        points.push([x + link * angle.cos(), y + link * angle.sin()]);
    }
    points
}

/// 閉形式のヤコビ行列（行優先、2k × n）: ∂pᵢ/∂θⱼ = ẑ × (pᵢ − pⱼ₋₁)（j ≤ i）、j > i では 0。
pub(crate) fn arm_jacobian(theta: &[f64], link: f64, tracked: usize) -> Vec<f64> {
    let n = theta.len();
    let points = joints(theta, link);
    let mut jacobian = vec![0.0; 2 * tracked * n];
    for (row, i) in (n - tracked..n).enumerate() {
        for j in 0..=i {
            // points[i + 1] = pᵢ、points[j] = pⱼ₋₁（関節 j の回転中心）。
            let dx = points[i + 1][0] - points[j][0];
            let dy = points[i + 1][1] - points[j][1];
            jacobian[2 * row * n + j] = -dy;
            jacobian[(2 * row + 1) * n + j] = dx;
        }
    }
    jacobian
}
```

## 速度と力の双対性

$\mathbf{v} \in \mathbb{R}^n$ を関節の角速度 $\dot\theta_j$ [rad/s] とすると、$\mathbf{J}\mathbf{v}$ は出力にした点の速度 $\dot{\mathbf{p}}_i$ [m/s] である。
$\mathbf{w} \in \mathbb{R}^m$ を出力にした点にかかる力 $\mathbf{f}_i$ [N] とすると、$\mathbf{J}^\mathsf{T}\mathbf{w}$ の第 $j$ 成分は

$$
\tau_j = \sum_{i \ge j} (\mathbf{p}_i - \mathbf{p}_{j-1}) \times \mathbf{f}_i \quad [\mathrm{N\,m}]
$$

で、荷重が関節 $j$ のまわりに作るトルクである（和は出力にした点 $i$ について取り、$\mathbf{a} \times \mathbf{b} = a_x b_y - a_y b_x$）。
内積の両辺は

$$
\langle \mathbf{w}, \mathbf{J}\mathbf{v} \rangle = \sum_i \mathbf{f}_i \cdot \dot{\mathbf{p}}_i, \qquad
\langle \mathbf{J}^\mathsf{T}\mathbf{w}, \mathbf{v} \rangle = \sum_j \tau_j\,\dot\theta_j
$$

で、どちらも荷重がする仕事率 [W] である。

数学的には、この等式は転置の定義 $\sum_{i,j} w_i J_{ij} v_j$ を二通りの順序で足したものにすぎない。
自動微分では $\mathbf{J}\mathbf{v}$ を記録の順の前進走査で、$\mathbf{J}^\mathsf{T}\mathbf{w}$ を記録の逆順の逆走査で計算し、局所的な偏微分を逆向きに組み合わせる。
両辺が丸め誤差の範囲で一致すれば、局所規則の転置、符号、走査の順序に誤りがないことの裏付けになる。
ただし一致は 1 点と 1 組のベクトルでの確認で、ほかの点や向きでの正しさは示さない。

両辺は積 $w_i J_{ij} v_j$ の和を異なる順序と異なる丸めで計算したものとみなせる。
内積の誤差評価（Higham, *Accuracy and Stability of Numerical Algorithms*, 第 3 章）にならうと、差の目安は単位丸め $u = 2^{-53}$ と

$$
S = \sum_{i,j} \lvert w_i J_{ij} v_j \rvert
$$

の積で、これに項の数と演算の段数で決まる係数が掛かる。
打ち消しで $\lvert\langle \mathbf{w}, \mathbf{J}\mathbf{v} \rangle\rvert \ll S$ のとき、差を仕事率そのものと比べると誤差を過大に見積もるので、$uS$ と比べる。

この例題では、隣り合う関節が逆向きに回る $\dot\theta_j = (-1)^j$ rad/s を $\mathbf{v}$ とし、出力にした各点に下向き 1 N の重り $\mathbf{f}_i = (0, -1)$ N をかけたものを $\mathbf{w}$ とする。
このとき $\tau_j = -\sum_{i \ge j} (x_i - x_{j-1})$ N·m で、関節 $j$ から各重りまでの水平距離の和に符号を付けたものになる。
$\mathbf{v}$ の符号が交互なので仕事率の和には打ち消しが起き、$\lvert\langle \mathbf{w}, \mathbf{J}\mathbf{v} \rangle\rvert$ は $S$ より小さくなる。

## 前進と逆の積を求める API

`jvp(function, point, direction)` は前進モードのワンショット呼び出しである。
入力を二重数 `Dual` の $x_j = p_j + d_j\,\varepsilon$ にして関数を 1 回評価し、出力の微分係数を `scioxide_linalg::Vector` で返す。
関数は `&[Dual<f64>]` と空のベクトルを受け取り、出力をベクトルに積む。
計算コストは評価 1 回の小さな定数倍で、入力と出力を確保する。
`direction.len() != point.len()` は `DimensionMismatch` で、関数が返したエラーはそのまま返る。

`vjp(function, point, cotangent)` は逆モードのワンショット呼び出しで、新しいテープに関数を記録し、逆走査を 1 回行って $\mathbf{J}^\mathsf{T}\mathbf{w}$ を `Vector` で返す。
関数は `jvp` と同じく出力をベクトルに積むが、受け取る入力はテープ上の `Var` である。
新しいテープは空なので、関数は 1 回目の実行で文を数え、テープを広げた 2 回目の実行で記録される（呼び出しのたびに 2 回実行する）。
`cotangent` の長さが出力の数と違えば `DimensionMismatch` になる。

`Tape::linearize(function, point, cx)` は、ベクトル値の関数をテープに 1 回記録して、その点の線形化 `Linearization` を返す。
`Linearization` はテープを可変で借用し、同じ記録で何回でも積を計算する。
`inputs()` は入力の数 $n$、`outputs()` は出力の数 $m$、`values()` は出力の値 $\mathbf{F}(\mathbf{x})$ を返す。
`jvp_into(direction, out, cx)` は記録の順に接ベクトルを伝播させる走査（tangent sweep）で $\mathbf{J}\mathbf{v}$ を、`vjp_into(cotangent, out, cx)` は記録の逆順の逆走査で $\mathbf{J}^\mathsf{T}\mathbf{w}$ を書く。
`jacobian_into(out, cx)` は密な $\mathbf{J}$ を行優先（出力 × 入力）で書く。
積はそれぞれ評価の小さな定数倍の走査で、同じテープで 2 回目以降に使うときはメモリを確保しない（`jacobian_into` は初回だけ作業用の領域を確保する）。
配列の長さが合わなければ `DimensionMismatch` で、失敗したときは出力を書き換えない。

`jvp` と `jvp_into` はどちらも前進モードだが、前者はテープを使わずに `Dual` で関数を評価し、後者は記録を走査する。
逆モードは記録を保持するメモリ領域を使い、その大きさは記録した文の数に比例する。
随伴の導出とテープの記録規則は[逆モードとテープ](../../algorithms/reverse-mode-and-replay/)、接ベクトルの規則は[前進モードと二重数](../../algorithms/forward-mode/)で扱う。

次のセルはリンクの数 $n$（2〜40）、出力にする点（手先だけ、後半のリンクの先端、すべてのリンクの先端）、曲げ角の合計 $\Theta$（0〜360°）を選び、`jvp` で $\mathbf{J}\mathbf{v}$ を、同じ点の線形化の `vjp_into` で $\mathbf{J}^\mathsf{T}\mathbf{w}$ を求めて双対性を確かめる。
$\mathbf{J}^\mathsf{T}\mathbf{w}$ はワンショット呼び出しの `vjp` でも求めて、`vjp_into` と比べる。
1 つ目のグラフはアームの形と出力にした点、2 つ目のグラフは関節トルク $\tau_j$ を `vjp_into`（記号）と閉形式（破線）で示す。
1 つ目の表は二つの内積、丸めの尺度 $S$、差と $uS$ の比を示す。
2 つ目の表は `values()` の位置、`jvp` と `jvp_into` の $\mathbf{J}\mathbf{v}$、`vjp` と `vjp_into` の $\mathbf{J}^\mathsf{T}\mathbf{w}$、`jacobian_into` の $\mathbf{J}$ を、閉形式または別の方式と比べた最大の差である。
差は、位置では全長 $L = 1$ m、$\mathbf{J}\mathbf{v}$ では項の絶対値の和の最大値 $\max_i \sum_j \lvert J_{ij} v_j \rvert$、$\mathbf{J}^\mathsf{T}\mathbf{w}$ では $\max_j \sum_i \lvert J_{ij} w_i \rvert$、$\mathbf{J}$ では最大成分で割る。
積の基準を項の大きさで決めるので、打ち消しで積が 0 に近い姿勢（$\Theta = 360°$ など）でも比は意味を保つ。
検証するのは、差と $uS$ の比が 1 程度に収まること、各量が閉形式と丸め誤差の水準で一致することである。

//| ref: ad-arm-duality
//| title: 手先の速度と関節トルクの双対性

//| uses: [ad-arm-model]
//| crates: [scioxide-ad, scioxide-core]
//| inputs:
//|   links: {"type":"range","label":"リンクの数 n","description":"入力（関節角）の個数。全長は 1 m に保つ。","min":2,"max":40,"step":1,"value":6}
//|   tracked: {"type":"select","label":"出力にする点","description":"出力の個数 m = 2k を決める。","options":[{"label":"先端だけ（k = 1）","value":"tip"},{"label":"後半のリンクの先端（k = ⌈n/2⌉）","value":"half"},{"label":"すべてのリンクの先端（k = n）","value":"all"}],"value":"tip"}
//|   bend: {"type":"range","label":"曲げ角の合計 Θ [deg]","description":"各関節を Θ/n ずつ曲げる。","min":0,"max":360,"step":5,"value":90}
//| cases:
//|   - {"id":"all-points","label":"すべてのリンクの先端（m = 12）","description":"出力が入力より多くなり、jacobian_into の Auto は接ベクトルの走査を選ぶ。","inputs":{"tracked":"all"}}

//|   - {"id":"closed-arm","label":"Θ = 360°","description":"手先が根元に戻り、仕事率は打ち消しで厳密に 0 になる。","inputs":{"bend":360}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"duality","path":"/rows/0/0","equals":2}
//|       - {"artifact":"duality","path":"/rows/0/2","approx":{"value":-0.3219752754296894,"rtol":1e-14}}
//|       - {"artifact":"duality","path":"/rows/0/3","approx":{"value":-0.3219752754296894,"rtol":1e-14}}
//|       - {"artifact":"duality","path":"/rows/0/5","range":{"max":8}}
//|       - {"artifact":"checks","path":"/rows/1/1","range":{"max":1e-15}}
//|       - {"artifact":"checks","path":"/rows/3/1","equals":0}
//|       - {"artifact":"checks","path":"/rows/4/1","range":{"max":1e-15}}
//|       - {"artifact":"checks","path":"/rows/5/1","range":{"max":1e-15}}
//|   - case: all-points
//|     expect:
//|       - {"artifact":"duality","path":"/rows/0/0","equals":12}
//|       - {"artifact":"duality","path":"/rows/0/5","range":{"max":8}}
//|       - {"artifact":"checks","path":"/rows/5/1","range":{"max":1e-15}}
//|   - case: straight-arm
//|     expect:
//|       - {"artifact":"duality","path":"/rows/0/2","approx":{"value":-0.5,"rtol":1e-14}}
//|       - {"artifact":"duality","path":"/rows/0/4","approx":{"value":20.5,"rtol":1e-14}}
//|       - {"artifact":"duality","path":"/rows/0/5","range":{"max":8}}
//|       - {"artifact":"checks","path":"/rows/4/1","range":{"max":1e-15}}
//|   - case: closed-arm
//|     expect:
//|       - {"artifact":"duality","path":"/rows/0/2","range":{"min":-1e-15,"max":1e-15}}
//|       - {"artifact":"duality","path":"/rows/0/4","approx":{"value":0.6666666666666666,"rtol":1e-14}}
//|       - {"artifact":"duality","path":"/rows/0/5","range":{"max":8}}
//|       - {"artifact":"checks","path":"/rows/2/1","range":{"max":1e-15}}
use scioxide_ad::{Tape, TapeOptions, jvp, vjp};
use scioxide_core::ExecutionContext;

let n = links as usize;
let k = match tracked.as_str() {
    "tip" => 1,
    "half" => n.div_ceil(2),
    _ => n,
};
let m = 2 * k;
// 全長 1 m、各関節を Θ/n だけ曲げた円弧の形。
let link = 1.0 / n as f64;
let theta = vec![bend * std::f64::consts::PI / 180.0 / n as f64; n];
// v: 隣り合う関節が逆向きに回る角速度 ±1 rad/s。w: 出力にする各点に下向き 1 N の荷重。
let v: Vec<f64> = (0..n)
    .map(|j| if j % 2 == 0 { 1.0 } else { -1.0 })
    .collect();
let w: Vec<f64> = (0..m)
    .map(|r| if r % 2 == 0 { 0.0 } else { -1.0 })
    .collect();

// 前進モードのワンショット呼び出し: Dual で 1 回評価して J v を得る。
let forward = jvp(
    |x, out| {
        arm(x, link, k, out);
        Ok(())
    },
    &theta,
    &v,
)
.map_err(|e| e.to_string())?;
// 逆モードのワンショット呼び出し: 新しいテープに記録し、逆走査を 1 回行って Jᵀ w を得る。
let pulled = vjp(
    |x, out| {
        arm(x, link, k, out);
        Ok(())
    },
    &theta,
    &w,
)
.map_err(|e| e.to_string())?;

// テープに 1 回記録し、同じ線形化で接ベクトルの走査と逆走査を行う。
let cx = ExecutionContext::sequential();
let mut tape = Tape::<f64>::new(TapeOptions::new());
let mut linear = tape
    .linearize(
        |x, out| {
            arm(x, link, k, out);
            Ok(())
        },
        &theta,
        cx,
    )
    .map_err(|e| e.to_string())?;
let mut tangent = vec![0.0; m];
linear
    .jvp_into(&v, &mut tangent, cx)
    .map_err(|e| e.to_string())?;
let mut torque = vec![0.0; n];
linear
    .vjp_into(&w, &mut torque, cx)
    .map_err(|e| e.to_string())?;
let mut jacobian = vec![0.0; m * n];
linear
    .jacobian_into(&mut jacobian, cx)
    .map_err(|e| e.to_string())?;
let shape = (linear.outputs(), linear.inputs());
let positions: Vec<f64> = linear.values().to_vec();

// 双対性: ⟨w, J v⟩ と ⟨Jᵀ w, v⟩。丸めの尺度 S = Σ |wᵢ Jᵢⱼ vⱼ|。
let power_forward: f64 = w.iter().zip(forward.as_slice()).map(|(a, b)| a * b).sum();
let power_reverse: f64 = torque.iter().zip(&v).map(|(a, b)| a * b).sum();
let scale: f64 = (0..m)
    .flat_map(|i| (0..n).map(move |j| (i, j)))
    .map(|(i, j)| (w[i] * jacobian[i * n + j] * v[j]).abs())
    .sum();
let unit_roundoff = f64::EPSILON / 2.0;
let ratio = (power_forward - power_reverse).abs() / (unit_roundoff * scale);

// 独立検算: 閉形式のヤコビ行列から J v と Jᵀ w を作る（f64 の演算）。
let exact = arm_jacobian(&theta, link, k);
let exact_tangent: Vec<f64> = (0..m)
    .map(|i| (0..n).map(|j| exact[i * n + j] * v[j]).sum())
    .collect();

    .map(|j| (0..m).map(|i| exact[i * n + j] * w[i]).sum())

        .zip(b)
        .fold(0.0_f64, |g, (x, y)| g.max((x - y).abs()))

    .map(|i| (0..n).map(|j| (exact[i * n + j] * v[j]).abs()).sum::<f64>())

    .map(|j| (0..m).map(|i| (exact[i * n + j] * w[i]).abs()).sum::<f64>())
    .fold(0.0_f64, f64::max);
let entry_scale = exact.iter().fold(0.0_f64, |s, x| s.max(x.abs()));

## ヤコビ行列を組む走査の回数

$\mathbf{v} = \mathbf{e}_j$ とすると JVP は $\mathbf{J}$ の第 $j$ 列を、$\mathbf{w} = \mathbf{e}_i$ とすると VJP は第 $i$ 行を返す。
そのため密な $\mathbf{J}$ は、接ベクトルの走査 $n$ 回でも逆走査 $m$ 回でも組み立てられる。
1 回の走査の計算コストはどちらの向きも評価の小さな定数倍なので、少ないほうの向きを選べば $\min(m, n)$ 回で済む。

`TapeOptions::with_jacobian_mode` で選ぶ `JacobianMode` は `jacobian_into` の向きを決める。
`Forward` は入力ごとに接ベクトルの走査を 1 回（計 $n$ 回）、`Reverse` は出力ごとに逆走査を 1 回（計 $m$ 回）行う。
既定の `Auto` は $m < n$ なら逆走査、そうでなければ接ベクトルの走査を選ぶ。
$m = n$ では接ベクトルの走査になる。
ワンショット呼び出しの `jacobian(function, point)` は新しいテープで `Auto` を使い、`vjp` と同じく関数を 2 回実行する。

次のセルは入力をとらず、$\Theta = 90°$ の姿勢で $(n, k)$ の 8 通りの組み合わせについて、3 つのモードのテープで同じ関数を線形化して `jacobian_into` で $\mathbf{J}$ を組み、閉形式と比べる。
走査の回数はモードの規則から決まるもので、セルの中で数えたものではない。
`Forward` と `Reverse` の結果は和の順序が違うので最後の桁で異なることがあり、そのとき `Auto` の結果がどちらとビット単位で一致したかを見れば、`Auto` が実際に選んだ向きが分かる。
表の「Auto の結果と一致した向き」はその比較で、差の列はどれも $\mathbf{J}$ の最大成分に対する相対差である。

```rust
//| id: ad-arm-jacobian-modes
//| ref: ad-arm-jacobian-modes
//| title: 入出力の次元と JacobianMode ごとの走査の回数
//| run: reactive
//| uses: [ad-arm-model]
//| crates: [scioxide-ad, scioxide-core]
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"modes","path":"/rows/0/6","equals":"逆"}
//|       - {"artifact":"modes","path":"/rows/1/6","equals":"前進"}
//|       - {"artifact":"modes","path":"/rows/3/6","equals":"逆"}
//|       - {"artifact":"modes","path":"/rows/4/6","equals":"前進"}
//|       - {"artifact":"modes","path":"/rows/6/6","equals":"逆"}
//|       - {"artifact":"modes","path":"/rows/7/6","equals":"前進"}
//|       - {"artifact":"modes","path":"/rows/6/5","equals":32}
//|       - {"artifact":"modes","path":"/rows/7/7","range":{"max":1e-14}}
//|       - {"artifact":"modes","path":"/rows/7/8","range":{"max":1e-14}}
use scioxide_ad::{JacobianMode, Tape, TapeOptions};
use scioxide_core::ExecutionContext;

let cx = ExecutionContext::sequential();
let mut rows = Vec::new();
for (n, k) in [
    (4, 1),
    (4, 4),
    (16, 1),
    (16, 4),
    (16, 16),
    (64, 1),
    (64, 16),
    (64, 64),
] {
    let m = 2 * k;
    let link = 1.0 / n as f64;
    let theta = vec![std::f64::consts::FRAC_PI_2 / n as f64; n];
    let exact = arm_jacobian(&theta, link, k);
    // 同じ関数を 3 つの JacobianMode のテープで線形化し、密なヤコビ行列を組む。
    let mut assembled = Vec::new();
    for mode in [
        JacobianMode::Auto,
        JacobianMode::Forward,
        JacobianMode::Reverse,
    ] {
        let mut tape = Tape::<f64>::new(TapeOptions::new().with_jacobian_mode(mode));
        let mut linear = tape
            .linearize(
                |x, out| {
                    arm(x, link, k, out);
                    Ok(())
                },
                &theta,
                cx,
            )
            .map_err(|e| e.to_string())?;
        let mut jacobian = vec![0.0; m * n];
        linear
            .jacobian_into(&mut jacobian, cx)
            .map_err(|e| e.to_string())?;
        assembled.push(jacobian);
    }
    let size = exact.iter().fold(0.0_f64, |s, x| s.max(x.abs()));
    let gap = |a: &[f64], b: &[f64]| {
        a.iter()
            .zip(b)
            .fold(0.0_f64, |g, (x, y)| g.max((x - y).abs()))
            / size
    };
    let worst = assembled
        .iter()
        .map(|j| gap(j, &exact))
        .fold(0.0_f64, f64::max);
    // Auto の規則: m < n なら逆走査を m 回、そうでなければ接ベクトルの走査を n 回。
    let rule = if m < n { "逆" } else { "前進" };
    let matched = match (assembled[0] == assembled[1], assembled[0] == assembled[2]) {
        (true, true) => "両方（ビット単位で同じ）",
        (true, false) => "前進",
        (false, true) => "逆",
        (false, false) => "どちらでもない",
    };
    rows.push((
        n,
        m,
        n,
        m,
        rule,
        m.min(n),
        matched,
        gap(&assembled[1], &assembled[2]),
        worst,
    ));
}
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "入力 n", "type": "integer" },
    { "key": "1", "label": "出力 m", "type": "integer" },
    { "key": "2", "label": "Forward の走査 [回]", "type": "integer" },
    { "key": "3", "label": "Reverse の走査 [回]", "type": "integer" },
    { "key": "4", "label": "Auto の向き" },
    { "key": "5", "label": "Auto の走査 [回]", "type": "integer" },
    { "key": "6", "label": "Auto の結果と一致した向き" },
    { "key": "7", "label": "Forward と Reverse の差 [-]", "type": "number", "format": sci3 },
    { "key": "8", "label": "閉形式との最大の差 [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "modes" })
);
```

8 通りすべてで、`Forward` と `Reverse` の結果は最後の桁で異なり、`Auto` の結果は規則どおりの向きの結果とビット単位で一致した。
$n = 64$ では手先だけ（$m = 2$）なら逆走査 2 回、16 本の先端（$m = 32$）なら逆走査 32 回、すべての先端（$m = 128$）なら接ベクトルの走査 64 回で、どれも $\min(m, n)$ 回である。
$n = 16$、$k = 4$ では $m = 8 < 16$ なので逆走査 8 回、$k = 16$ では $m = 32$ なので接ベクトルの走査 16 回になる。
`Forward` と `Reverse` の差、閉形式との差はどれも $7 \times 10^{-16}$ 以下で、向きの選び方は計算コストを変えるが、精度の水準は変えない。

## まとめ

`jvp` は前進評価 1 回で、`Linearization::jvp_into` は接ベクトルの走査 1 回で $\mathbf{J}\mathbf{v}$ を返し、`vjp` と `vjp_into` は逆走査 1 回で $\mathbf{J}^\mathsf{T}\mathbf{w}$ を返す。
どれも $\mathbf{J}$ を作らないが、ワンショット呼び出しの `vjp` は呼ぶたびに新しいテープで関数を 2 回実行するので、同じ点で多くの積を求めるなら `linearize` の記録を使い回す。
$\langle \mathbf{w}, \mathbf{J}\mathbf{v} \rangle$ と $\langle \mathbf{J}^\mathsf{T}\mathbf{w}, \mathbf{v} \rangle$ の差を $uS = u\sum\lvert w_i J_{ij} v_j \rvert$ と比べれば、閉形式がなくても記録した関数の微分を点検でき、比が 1 程度なら丸め誤差の範囲である。
アームでは $\mathbf{J}^\mathsf{T}\mathbf{w}$ が荷重の関節トルクになり、双対性は仮想仕事の原理として読める。
密なヤコビ行列が要るときは `jacobian_into` が $\min(m, n)$ 回の走査で組み、向きは `TapeOptions::with_jacobian_mode` で固定できる。
手先の位置だけのように出力が少なければ逆走査、操作量が少なく出力が多ければ接ベクトルの走査が少ない回数で済む。
