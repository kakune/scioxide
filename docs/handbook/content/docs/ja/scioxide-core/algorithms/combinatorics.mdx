疎行列の並べ替え、格子の数え上げ、標本の一様抽出では、階乗や二項係数の正確な値、組合せの辞書式の列挙、組合せと通し番号（順位）の相互変換が必要になる。
`scioxide-core` の組合せ関数は `usize` の整数で厳密に計算し、結果が `usize` に収まらない場合は `SizeOverflow` を返す。
桁あふれで折り返した値や、丸めた値を返すことはない。
添字と順位は 0 から数え、列挙と順位は辞書式順序に従う。

## 厳密な計数関数

| 関数 | 値 | 計算量 | 備考 |
|---|---|---|---|
| `checked_factorial(n)` | $n!$ | $O(n)$ | $0! = 1$ |
| `checked_double_factorial(n)` | $n!! = n(n-2)(n-4)\cdots$ | $O(n)$ | $0!! = 1!! = 1$ |
| `checked_multifactorial(n, step)` | $n(n - s)(n - 2s)\cdots$（2 未満の因子の手前まで） | $O(\lceil n/s \rceil)$ | `step` が 0 なら `InvalidInput` |
| `checked_rising_factorial(a, n)` | $a(a+1)\cdots(a+n-1)$ | $O(n)$ | 空の積（$n = 0$）は 1 |
| `checked_binomial(n, k)` | $C(n, k) = n!/(k!\,(n-k)!)$ | $O(\min(k, n-k))$ | $k > n$ なら 0 |
| `checked_permutation_count(n, k)` | $n!/(n-k)!$ | $O(k)$ | $k > n$ なら 0 |
| `checked_multiset_count(n, k)` | $C(n + k - 1, k)$ | $O(\min(k, n-1))$ | $n$ 種類から重複を許して $k$ 個 |
| `checked_stirling_first_kind(n, k)` | 符号付き第 1 種 $s(n, k)$ | $k\,(n - k + 1)$ セル | 結果は `isize` |
| `checked_stirling_second_kind(n, k)` | 第 2 種 $S(n, k)$ | $k\,(n - k + 1)$ セル | 結果は `usize` |

二項係数は $C(n, k) = C(n, n - k)$ で $k$ を小さい側に取り替えてから、$i = 1, \ldots, k$ の順に $C(n - k + i,\, i) = C(n - k + i - 1,\, i - 1)\,(n - k + i) / i$ で更新する。
掛ける前に $n - k + i$ と $i$ の最大公約数で約分するので、途中の値は最終結果を超えない。
そのため `SizeOverflow` になるのは、$C(n, k)$ そのものが `usize` に収まらないときだけである。

### Stirling 数

第 2 種 Stirling 数 $S(n, k)$ は、$n$ 個の要素を空でない $k$ 個の組に分ける方法の数である。
符号なしの第 1 種 Stirling 数 $c(n, k)$ は、$n$ 個の要素の置換のうち巡回がちょうど $k$ 個のものの数で、符号付きの値は $s(n, k) = (-1)^{n-k}\, c(n, k)$ である。
どちらも $S(0, 0) = s(0, 0) = 1$ で、$k > n$ か $k = 0 < n$ なら 0 になる。
値は漸化式

$$
S(n, k) = k\,S(n-1, k) + S(n-1, k-1), \qquad c(n, k) = (n-1)\,c(n-1, k) + c(n-1, k-1)
$$

で $n$ について 1 行ずつ更新して求める。
第 1 種は絶対値 $c(n, k)$ を計算し、最後に符号 $(-1)^{n-k}$ を付ける。

関数は長さ $k + 1$ の行を 1 本だけ確保し、求めるセル $(n, k)$ に寄与するセルだけを更新する。
更新するセルは $k\,(n - k + 1)$ 個で、1 個につき検査付きの乗算と加算を 1 回ずつ行う。
寄与しない列を計算しないので、ほかの列の桁あふれが原因で、表せる答えが拒否されることはない。
作業量に上限を設けたい呼び出し側は、呼ぶ前に $k\,(n - k + 1)$ を自分の上限と比べる。
結果か途中の値が収まらなければ `SizeOverflow`、行を確保できなければ `AllocationFailure` を返す。

### `usize` の幅による限界

結果の上限は `usize` のビット幅で決まる。

- 64 ビット環境では $20! \approx 2.43 \times 10^{18} < 2^{64} - 1 < 21!$ なので、$20!$ まで計算できる。
- wasm32 では `usize` が 32 ビットで、$12! = 479{,}001{,}600 < 2^{32} - 1 = 4{,}294{,}967{,}295 < 13! = 6{,}227{,}020{,}800$ である。
  このハンドブックのセルはブラウザの wasm32 で動くので、$13!$ 以上が `SizeOverflow` になる。

次のセルは $n$（0 から 14 の整数）について 4 つの量を SciOxide の関数で計算し、独立に求めた参照値と並べる。

- $n!$。
  参照値は `u64` の積である。
- 二項係数の行和 $\sum_k C(n, k)$。
  参照値は $2^n$ である。
- 第 2 種 Stirling 数の行和 $\sum_k S(n, k)$。
  これは $n$ 個の要素を分割する方法の総数、つまり Bell 数 $B_n$ に等しい。
  参照値は Stirling 数を使わない Bell の三角形で求める。
- 第 1 種 Stirling 数の絶対値の行和 $\sum_k c(n, k)$。
  どの置換も巡回の数が 1 つに決まるので、これは置換の総数 $n!$ に等しい。

和の途中も検査付きで足し、`usize` を超えた量は「usize を超える」と表示する。
2 つ目の表は実行した環境の `usize` のビット幅と、`checked_factorial(n)` が成功する最大の $n$ を示す。

```rust
//| id: core-combinatorial-identities
//| ref: core-combinatorial-identities
//| title: 計数関数と恒等式
//| run: reactive
//| crates: [scioxide-core]
//| inputs:
//|   n_val: {"type":"range","label":"n","description":"階乗、二項係数、Stirling 数の n。","min":0,"max":14,"step":1,"value":5}
//| cases:
//|   - {"id":"empty","label":"n = 0","description":"空の積と空集合の分割で、4 つの量がすべて 1 になる。","inputs":{"n_val":0}}
//|   - {"id":"wasm-limit","label":"n = 12","description":"32 ビットの usize に収まる最大の階乗。","inputs":{"n_val":12}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"identities","path":"/rows/0/1","equals":120}
//|       - {"artifact":"identities","path":"/rows/1/1","equals":32}
//|       - {"artifact":"identities","path":"/rows/2/1","equals":52}
//|       - {"artifact":"identities","path":"/rows/2/2","equals":52}
//|       - {"artifact":"identities","path":"/rows/3/1","equals":120}
//|   - case: empty
//|     expect:
//|       - {"artifact":"identities","path":"/rows/0/1","equals":1}
//|       - {"artifact":"identities","path":"/rows/1/1","equals":1}
//|       - {"artifact":"identities","path":"/rows/2/1","equals":1}
//|       - {"artifact":"identities","path":"/rows/3/1","equals":1}
//|   - case: wasm-limit
//|     expect:
//|       - {"artifact":"identities","path":"/rows/0/1","equals":479001600}
//|       - {"artifact":"identities","path":"/rows/1/1","equals":4096}
//|       - {"artifact":"identities","path":"/rows/2/1","equals":4213597}
//|       - {"artifact":"identities","path":"/rows/2/2","equals":4213597}
//|       - {"artifact":"identities","path":"/rows/3/1","equals":479001600}
use scioxide_core::{
    SciOxideError, SciOxideErrorKind, checked_binomial, checked_factorial,
    checked_stirling_first_kind, checked_stirling_second_kind,
};

let n = n_val as usize;
// SizeOverflow は「usize で表せない」として None にし、ほかのエラーは実行の失敗として返す。
let representable = |value: Result<usize, SciOxideError>| match value {
    Ok(count) => Ok(Some(count)),
    Err(error) if matches!(error.kind(), SciOxideErrorKind::SizeOverflow) => Ok(None),
    Err(error) => Err(error.to_string()),
};
// 和の途中も checked_add で桁あふれを検査する。
let add = |sum: Option<usize>, term: Option<usize>| {
    sum.zip(term)
        .and_then(|(total, count)| total.checked_add(count))
};
let factorial = representable(checked_factorial(n))?;
let mut binomial_sum = Some(0_usize);
let mut bell = Some(0_usize);
let mut cycles = Some(0_usize);
for k in 0..=n {
    binomial_sum = add(binomial_sum, representable(checked_binomial(n, k))?);
    bell = add(bell, representable(checked_stirling_second_kind(n, k))?);
    // 符号付きの s(n, k) の絶対値 c(n, k) を足す。
    let signed = checked_stirling_first_kind(n, k).map(isize::unsigned_abs);
    cycles = add(cycles, representable(signed)?);
}

// 独立な参照値。n ≤ 14 では u64 に収まる。
let factorial_reference: u64 = (1..=n as u64).product();
// Bell の三角形: 各行は前の行の末尾から始まり、左隣と前の行の値の和を並べる。
let mut row = vec![1_u64];
for _ in 0..n {
    let mut next = vec![row[row.len() - 1]];
    for &value in &row {
        next.push(next[next.len() - 1] + value);
    }
    row = next;
}
let bell_reference = row[0];

let widen = |count: Option<usize>| count.map(|value| value as u64);
let identity_columns = serde_json::json!([
    { "key": "0", "label": "量" },
    { "key": "1", "label": "SciOxide の値", "type": "integer", "nullText": "usize を超える" },
    { "key": "2", "label": "独立な参照値", "type": "integer" }
]);
emit_table_with_columns!(
    identity_columns,
    vec![
        ("n!", widen(factorial), factorial_reference),
        ("Σ C(n, k)（参照値は 2^n）", widen(binomial_sum), 1_u64 << n),
        ("Σ S(n, k)（参照値は Bell 数）", widen(bell), bell_reference),
        (
            "Σ c(n, k)（参照値は n!）",
            widen(cycles),
            factorial_reference
        ),
    ],
    metadata = serde_json::json!({ "id": "identities" })
);

// この環境の usize で checked_factorial が成功する最大の n。
let largest = (0..=25_usize)
    .take_while(|&m| checked_factorial(m).is_ok())
    .last();
let width_columns = serde_json::json!([
    { "key": "0", "label": "usize のビット幅 [bit]", "type": "integer" },
    { "key": "1", "label": "n! が usize に収まる最大の n", "type": "integer" }
]);
emit_table_with_columns!(
    width_columns,
    vec![(usize::BITS, largest)],
    metadata = serde_json::json!({ "id": "width" })
);
```

既定値 $n = 5$ では $5! = 120$、$\sum_k C(5, k) = 2^5 = 32$、$B_5 = 52$、$\sum_k c(5, k) = 120$ で、4 つとも参照値と一致する。
$n = 0$ では空の積と空集合の分割がどちらも 1 通りなので、4 つの量はすべて 1 になる。
$n = 12$ では $12! = 479{,}001{,}600$、$B_{12} = 4{,}213{,}597$ で、ここまでは 32 ビットの `usize` に収まる。

ブラウザで $n$ を 13 以上にすると、$n!$ と $\sum_k c(n, k)$ が「usize を超える」になる。
後者は個々の $c(13, k)$ が 32 ビットに収まっていても、和が $13!$ に達する途中で `checked_add` があふれを検出する。
$2^n$ と Bell 数は $n = 14$ でも 32 ビットに収まる（$B_{14} = 190{,}899{,}322$）。
2 つ目の表の最大の $n$ はブラウザでは 12、64 ビットのネイティブ環境では 20 になる。

## 辞書式の列挙と順位

$\{0, \ldots, n-1\}$ から $k$ 個を選ぶ組合せを昇順の添字 $c_0 < c_1 < \cdots < c_{k-1}$ で表すと、辞書式の順序で $C(n, k)$ 個が並ぶ。

### 列挙器

`CombinationEnumerator::first_into(n, storage)` は、呼び出し側のメモリ領域に最初の組合せ $(0, 1, \ldots, k-1)$ を書く（$k$ はメモリ領域の長さ）。
`first(n, k)` は同じことを、メモリ領域を確保して行う。
どちらも $k > n$ なら `InvalidInput` を返す。
`advance()` は次の組合せへ進む。
右端から、上限 $n - k + i$ に達していない位置 $i$ を探して 1 増やし、その右を連続した値に戻すので、1 歩は $O(k)$ である。
最後の組合せに達していれば `false` を返して状態を変えない。
`indices()` は現在の組合せを返し、`reset()` は最初の組合せに戻し、`into_inner()` はメモリ領域を返す。

`MultisetEnumerator` は非減少の添字 $c_0 \le c_1 \le \cdots \le c_{k-1}$ で重複組合せを同じ形で列挙する。
`PermutationEnumerator` は $0, \ldots, n-1$ の順列を列挙し、`identity(n)`（メモリ領域を確保する）か `identity_into(storage)` で恒等置換から始める。
順列の次の要素は Narayana のアルゴリズムで求める。
右端の昇順の対 $p_i < p_{i+1}$ を探し、$p_i$ を、その右にある $p_i$ より大きい要素のうち最も右のものと入れ替え、位置 $i$ より右を反転する。
この 1 歩は全体を列挙したときの平均で $O(1)$、最悪で $O(n)$ である。
既存の状態から再開する `new` は、渡された状態が正しくなければ変更せずに `InvalidInput` で拒否する。
`PermutationEnumerator::new` は検査用に $\lceil n/8 \rceil$ バイトの `scratch` も受け取り、短ければ `DimensionMismatch` を返す。

### 順位と復元

組合せの順位は 0 から数えた辞書式の通し番号である。
位置 $i$ より前の添字を固定し、位置 $i$ に $c_i$ より小さい値 $v$（$s_i \le v < c_i$）を選んだ組合せは、すべて $\mathbf{c}$ より前に並ぶ。
ここで $s_i$ は位置 $i$ に置ける最小の値で、$s_0 = 0$、$s_{i+1} = c_i + 1$ である。
残りの $k - i - 1$ 個は $v$ より大きい $n - v - 1$ 個から選ぶので、その数は $C(n - v - 1, k - i - 1)$ である。
これを $v$ について足すと、二項係数の和の公式（ホッケースティック恒等式）$\sum_{v=s}^{c-1} C(n - v - 1,\, r - 1) = C(n - s,\, r) - C(n - c,\, r)$ から

$$
\mathrm{rank}(\mathbf{c}) = \sum_{i=0}^{k-1} \left[ C(n - s_i,\, k - i) - C(n - c_i,\, k - i) \right]
$$

を得る。
順位を二項係数の和で表すこの方法は、組合せ数系（combinatorial number system）と同じ数え方を辞書式順序に当てはめたものである。

`combination_rank(n, &c)` はこの和を $O(k^2)$ の整数演算で計算する。
範囲外の添字や昇順でない添字は `InvalidInput`、$C(n, k)$ が `usize` を超える場合は `SizeOverflow` で拒否する。
逆向きの `combination_unrank_into(n, rank, &mut out)` は位置ごとに、飛ばす組合せの数 $C(n - s_i, k - i) - C(n - v, k - i)$ が残りの順位を超えない最大の $v$ を二分探索で求め、その数を順位から引いて次の位置へ進む。
計算量は $O(k^2 \log(n+1))$ で、範囲外の順位は出力を変える前に `OutOfBounds` として拒否する。

重複組合せ（`multiset_rank`、`multiset_unrank_into`）は、非減少の添字 $c_i$ を $c_i + i$ と置き直した $n + k - 1$ 個からの組合せとして同じ式で扱う。
順列（`permutation_rank`、`permutation_unrank_into`）は Lehmer 符号を使う。
位置 $i$ の桁は $i$ より後ろにある $c_i$ より小さい要素の数で、重み $(n - 1 - i)!$ を掛けて足すと順位になる。
計算量は $O(n^2)$ で、$n!$ が `usize` を超える長さは `SizeOverflow` になる。
どの関数もヒープを確保しない。

順位と組合せは一対一に対応する。
そのため、組合せの表を作らずに、一様乱数の順位から組合せを一様に抽出したり、順位の区間で処理を分割したりできる。

次のセルは `CombinationEnumerator` で全組合せを列挙する。
入力は全体の大きさ $n$（4 から 10）と選ぶ個数 $k$（1 から 4）である。
列挙の位置 $r$ ごとに、`combination_rank` が $r$ を返すことと、`combination_unrank_into` が同じ組合せを返すことを確かめる。
1 つ目の表は先頭と末尾の 3 個ずつについて、組合せの添字 $c_0, \ldots, c_{k-1}$ と順位を示す。
2 つ目の表は、$C(n, k)$、列挙した個数、順位か復元が一致しなかった位置の数を示す。

```rust
//| id: core-rank-unrank-roundtrip
//| ref: core-rank-unrank-roundtrip
//| title: 列挙の順序と順位の一致
//| run: reactive
//| crates: [scioxide-core]
//| inputs:
//|   universe_n: {"type":"range","label":"全体の大きさ n","description":"{0, …, n-1} から選ぶ。","min":4,"max":10,"step":1,"value":6}
//|   subset_k: {"type":"range","label":"選ぶ個数 k","description":"k ≤ n。","min":1,"max":4,"step":1,"value":3}
//| cases:
//|   - {"id":"largest","label":"n = 10、k = 4","description":"C(10, 4) = 210 個を列挙する。","inputs":{"universe_n":10,"subset_k":4}}
//|   - {"id":"all-selected","label":"n = 4、k = 4","description":"全部を選ぶ組合せは 1 個だけである。","inputs":{"universe_n":4,"subset_k":4}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":20}
//|       - {"artifact":"summary","path":"/rows/0/1","equals":20}
//|       - {"artifact":"summary","path":"/rows/0/2","equals":0}
//|       - {"artifact":"summary","path":"/rows/0/3","equals":0}
//|       - {"artifact":"combinations","path":"/rows/5/0","equals":19}
//|       - {"artifact":"combinations","path":"/rows/5/1","equals":3}
//|       - {"artifact":"combinations","path":"/rows/5/3","equals":5}
//|       - {"artifact":"combinations","path":"/rows/5/5","equals":19}
//|   - case: largest
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":210}
//|       - {"artifact":"summary","path":"/rows/0/1","equals":210}
//|       - {"artifact":"summary","path":"/rows/0/2","equals":0}
//|       - {"artifact":"summary","path":"/rows/0/3","equals":0}
//|   - case: all-selected
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":1}
//|       - {"artifact":"summary","path":"/rows/0/1","equals":1}
//|       - {"artifact":"summary","path":"/rows/0/3","equals":0}
//|       - {"artifact":"combinations","path":"/rows/0/4","equals":3}
use scioxide_core::{
    CombinationEnumerator, checked_binomial, combination_rank, combination_unrank_into,
};

let (n, k) = (universe_n as usize, subset_k as usize);
let total = checked_binomial(n, k).map_err(|e| e.to_string())?;
let mut storage = vec![0_usize; k];
let mut enumerator =
    CombinationEnumerator::first_into(n, &mut storage[..]).map_err(|e| e.to_string())?;
let mut unranked = vec![0_usize; k];

let mut position = 0_usize;
let mut rank_mismatches = 0_usize;
let mut unrank_mismatches = 0_usize;
let mut rows = Vec::new();
loop {
    let current = enumerator.indices();
    let rank = combination_rank(n, current).map_err(|e| e.to_string())?;
    combination_unrank_into(n, position, &mut unranked).map_err(|e| e.to_string())?;
    rank_mismatches += usize::from(rank != position);
    unrank_mismatches += usize::from(unranked.as_slice() != current);
    // 先頭と末尾の 3 個だけ表に出す。k 個より後ろの添字の欄は空欄にする。
    if position < 3 || position + 3 >= total {
        let index = |i: usize| current.get(i).copied();
        rows.push((position, index(0), index(1), index(2), index(3), rank));
    }
    position += 1;
    if !enumerator.advance() {
        break;
    }
}
let combination_columns = serde_json::json!([
    { "key": "0", "label": "列挙の位置 r", "type": "integer" },
    { "key": "1", "label": "c₀", "type": "integer", "nullText": "-" },
    { "key": "2", "label": "c₁", "type": "integer", "nullText": "-" },
    { "key": "3", "label": "c₂", "type": "integer", "nullText": "-" },
    { "key": "4", "label": "c₃", "type": "integer", "nullText": "-" },
    { "key": "5", "label": "combination_rank(n, c)", "type": "integer" }
]);
emit_table_with_columns!(
    combination_columns,
    rows,
    metadata = serde_json::json!({ "id": "combinations" })
);
let summary_columns = serde_json::json!([
    { "key": "0", "label": "C(n, k)", "type": "integer" },
    { "key": "1", "label": "列挙した個数", "type": "integer" },
    { "key": "2", "label": "順位が位置と違った個数", "type": "integer" },
    { "key": "3", "label": "復元が組合せと違った個数", "type": "integer" }
]);
emit_table_with_columns!(
    summary_columns,
    vec![(total, position, rank_mismatches, unrank_mismatches)],
    metadata = serde_json::json!({ "id": "summary" })
);
```

既定値 $n = 6$、$k = 3$ では $C(6, 3) = 20$ 個が並び、先頭は $(0, 1, 2)$、末尾の順位 19 は $(3, 4, 5)$ である。
例えば $(0, 2, 3)$ の順位は式で $[C(6,3) - C(6,3)] + [C(5,2) - C(4,2)] + [C(3,1) - C(3,1)] = 0 + 4 + 0 = 4$ となり、$(0,1,2)$、$(0,1,3)$、$(0,1,4)$、$(0,1,5)$ の 4 個が前に並ぶことと一致する。
$n = 10$、$k = 4$ では 210 個を列挙し、一致しなかった位置の数は順位も復元も 0 である。
$n = k = 4$ では組合せは $(0, 1, 2, 3)$ の 1 個だけで、最初の `advance()` が `false` を返して列挙が終わる。

## 検査済みの置換

疎行列の並べ替えなどで使う置換は、`Permutation`（所有）と `PermutationView`（借用）で表す。
`Permutation` は `new_to_old[new] = old` と `old_to_new[old] = new` の 2 つの写像を持ち、$0, \ldots, n-1$ のすべての番号がちょうど 1 回ずつ現れることを構築時に検査する。

`Permutation::new(new_to_old)` は重複や範囲外の番号を `InvalidInput` で拒否し、逆写像を作る。
`identity(n)`、`inverse()`、`compose(&other)` は $O(n)$ の時間とメモリ領域を使う。
`compose` の結果は `new_to_old[i] = other.new_to_old[self.new_to_old[i]]` で、ベクトルに `other` を先に、`self` を後に適用した並べ替えに等しい。
`PermutationView::new(map, scratch)` は借用した写像を $O(n)$ で検査する。
各番号を見たかどうかを 1 ビットで記録するので、`scratch` は $\lceil n/8 \rceil$ バイト（`permutation_validation_scratch_bytes(n)`）あればよく、検査のあとは保持しない。
`scratch` が短ければ `DimensionMismatch` を返す。
`apply_into(input, output)` は $\mathrm{output}_i = \mathrm{input}_{\mathrm{new\_to\_old}[i]}$ を、`inverse_into` はその逆 $\mathrm{output}_{\mathrm{new\_to\_old}[i]} = \mathrm{input}_i$ を計算する。
長さが合わなければ、出力を変えずに `DimensionMismatch` で拒否する。
借用のビューには確保をしない `inverse_map_into` と `compose_into` もある。

次のセルは 4 個の要素の順列を順位 $\rho$（0 から 23 の整数）から `permutation_unrank_into` で作り、`Permutation` にする。
表は位置 $i$ ごとに 2 つの写像、$x = (10, 20, 30, 40)$ に `apply_into` を適用した値、それを `inverse_into` で戻した値を示す。
2 つ目の表は、`permutation_rank` が $\rho$ に戻ること、戻した値と $x$ の差、置換とその逆の合成が動かす位置の数を示す。

```rust
//| id: core-permutation-roundtrip
//| ref: core-permutation-roundtrip
//| title: 順位から作った置換の適用と逆
//| run: reactive
//| crates: [scioxide-core]
//| inputs:
//|   permutation_index: {"type":"range","label":"順列の順位 ρ","description":"4 個の要素の順列 24 個の辞書式の通し番号。","min":0,"max":23,"step":1,"value":9}
//| cases:
//|   - {"id":"identity","label":"ρ = 0","description":"恒等置換。","inputs":{"permutation_index":0}}
//|   - {"id":"reversal","label":"ρ = 23","description":"逆順の置換。","inputs":{"permutation_index":23}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"maps","path":"/rows/0/1","equals":1}
//|       - {"artifact":"maps","path":"/rows/3/1","equals":0}
//|       - {"artifact":"maps","path":"/rows/0/2","equals":3}
//|       - {"artifact":"maps","path":"/rows/0/3","approx":{"value":20,"atol":1e-12}}
//|       - {"artifact":"maps","path":"/rows/3/3","approx":{"value":10,"atol":1e-12}}
//|       - {"artifact":"maps","path":"/rows/2/4","approx":{"value":30,"atol":1e-12}}
//|       - {"artifact":"summary","path":"/rows/0/0","equals":9}
//|       - {"artifact":"summary","path":"/rows/0/1","approx":{"value":0,"atol":1e-12}}
//|       - {"artifact":"summary","path":"/rows/0/2","equals":0}
//|   - case: identity
//|     expect:
//|       - {"artifact":"maps","path":"/rows/2/1","equals":2}
//|       - {"artifact":"maps","path":"/rows/2/3","approx":{"value":30,"atol":1e-12}}
//|       - {"artifact":"summary","path":"/rows/0/0","equals":0}
//|   - case: reversal
//|     expect:
//|       - {"artifact":"maps","path":"/rows/0/1","equals":3}
//|       - {"artifact":"maps","path":"/rows/0/3","approx":{"value":40,"atol":1e-12}}
//|       - {"artifact":"summary","path":"/rows/0/0","equals":23}
//|       - {"artifact":"summary","path":"/rows/0/2","equals":0}
use scioxide_core::{Permutation, permutation_rank, permutation_unrank_into};

let mut map = vec![0_usize; 4];
permutation_unrank_into(permutation_index as usize, &mut map).map_err(|e| e.to_string())?;
// new は全単射であることを検査し、逆写像 old_to_new を作る。
let permutation = Permutation::new(map).map_err(|e| e.to_string())?;
let rank = permutation_rank(permutation.as_view()).map_err(|e| e.to_string())?;

let x = [10.0_f64, 20.0, 30.0, 40.0];
let mut permuted = [0.0_f64; 4];
let mut restored = [0.0_f64; 4];
// permuted[i] = x[new_to_old[i]]、restored[new_to_old[i]] = permuted[i]。
permutation
    .apply_into(&x, &mut permuted)
    .map_err(|e| e.to_string())?;
permutation
    .inverse_into(&permuted, &mut restored)
    .map_err(|e| e.to_string())?;
let change = (0..4).fold(0.0_f64, |worst, i| worst.max((restored[i] - x[i]).abs()));
// 置換と逆置換の合成は恒等置換になる。動く位置の数を数える。
let inverse = permutation.inverse().map_err(|e| e.to_string())?;
let composed = permutation.compose(&inverse).map_err(|e| e.to_string())?;
let moved = composed
    .new_to_old()
    .iter()
    .enumerate()
    .filter(|&(i, &old)| i != old)
    .count();

let rows: Vec<(usize, usize, usize, f64, f64)> = (0..4)
    .map(|i| {
        let new_to_old = permutation.new_to_old()[i];
        let old_to_new = permutation.old_to_new()[i];
        (i, new_to_old, old_to_new, permuted[i], restored[i])
    })
    .collect();
let fixed0 = serde_json::json!({ "fractionDigits": 0 });
let map_columns = serde_json::json!([
    { "key": "0", "label": "位置 i", "type": "integer" },
    { "key": "1", "label": "new_to_old[i]", "type": "integer" },
    { "key": "2", "label": "old_to_new[i]", "type": "integer" },
    { "key": "3", "label": "apply_into の出力 [-]", "type": "number", "format": fixed0 },
    { "key": "4", "label": "inverse_into で戻した値 [-]", "type": "number", "format": fixed0 }
]);
emit_table_with_columns!(
    map_columns,
    rows,
    metadata = serde_json::json!({ "id": "maps" })
);
let summary_columns = serde_json::json!([
    { "key": "0", "label": "permutation_rank", "type": "integer" },
    { "key": "1", "label": "戻した値と x の差の最大値 [-]", "type": "number", "format": fixed0 },
    { "key": "2", "label": "置換と逆の合成が動かす位置の数", "type": "integer" }
]);
emit_table_with_columns!(
    summary_columns,
    vec![(rank, change, moved)],
    metadata = serde_json::json!({ "id": "summary" })
);
```

既定値 $\rho = 9$ の Lehmer 符号は $9 = 1 \cdot 3! + 1 \cdot 2! + 1 \cdot 1!$ から $(1, 1, 1, 0)$ で、順列は `new_to_old` $= (1, 2, 3, 0)$ である。
`apply_into` の出力は $(20, 30, 40, 10)$ で、位置 $i$ に元の位置 `new_to_old[i]` の値が集まる。
逆写像は `old_to_new` $= (3, 0, 1, 2)$ で、`inverse_into` は $(10, 20, 30, 40)$ を復元する。
`permutation_rank` は 9 に戻り、置換と逆の合成が動かす位置は 0 個である。
$\rho = 0$ は恒等置換、$\rho = 23 = 4! - 1$ は逆順の置換 $(3, 2, 1, 0)$ で、どちらも順位が元の値に戻る。

## まとめ

階乗・二項係数・Stirling 数などは `checked_*` 関数で `usize` の範囲内で厳密に計算し、範囲を超えれば `SizeOverflow` を受け取る。
wasm32 では `usize` が 32 ビットなので、$12!$ を超える値や大きな $C(n, k)$ はネイティブ環境より早く範囲を超える。
Stirling 数の作業量を抑えたいときは、呼ぶ前に $k\,(n - k + 1)$ を自分の上限と比べる。
組合せ・重複組合せ・順列は呼び出し側のメモリ領域で辞書式に列挙できる。
組合せの順位は二項係数の和の式により $O(k^2)$ で求まり、順位からの復元は位置ごとの二分探索で $O(k^2 \log(n+1))$ で済むので、列挙表なしに一様抽出や作業の分割ができる。
置換は構築時に全単射であることを検査し、借用した写像の検査には $\lceil n/8 \rceil$ バイトの作業領域を呼び出し側が渡す。
