反復をいつ止めるか、計算結果をいつ受理するかは、許容誤差の置き方で決まる。
絶対許容誤差だけでは値の桁が大きく変わる問題に合わず、相対許容誤差だけでは値が 0 を通るときに判定できない。
`scioxide-core` は両者を結合したしきい値を `Tolerance` として定め、判定の役割ごとに別の型を用意する。
概念の一般論は[許容誤差と残差の尺度化理論](../../../concepts/tolerances-and-residuals/)にまとめてあり、このページは `scioxide-core` の型と判定規則を扱う。

## 絶対項と相対項を結合したしきい値

真値を $y^*$、計算値を $\hat{y}$、前進誤差を $e = \hat{y} - y^*$ とする。
絶対誤差 $|e|$ は $y$ と同じ単位を持ち、相対誤差 $|e| / |y^*|$ は無次元である。
`Tolerance` は二つを次の和で結合する。

$$
|e| \le \tau(s) = \tau_{\mathrm{abs}} + \tau_{\mathrm{rel}}\, s, \qquad s \ge 0.
$$

$s$ は判定に使う代表スケールで、何を代表スケールに選ぶかは呼び出し側またはソルバーが決める。
`Tolerance::threshold(scale)` は $\tau(s)$ を返す。
`Tolerance::is_converged(current, previous)` は続く二つの反復値を比べる判定で、$s = \max(|y_{\mathrm{current}}|, |y_{\mathrm{previous}}|)$ として $|y_{\mathrm{current}} - y_{\mathrm{previous}}| \le \tau(s)$ を調べる。
この判定は差 $y_{\mathrm{current}} - y_{\mathrm{previous}}$ を作らずに比較するので、符号の異なる大きな有限値どうしでも差がオーバーフローしない。

二つの項が等しくなるスケールを**交点スケール**と呼ぶ。

$$
s_\times = \frac{\tau_{\mathrm{abs}}}{\tau_{\mathrm{rel}}} \qquad (\tau_{\mathrm{rel}} > 0).
$$

$s \ll s_\times$ では絶対項が、$s \gg s_\times$ では相対項がしきい値を決める。
許容誤差を選ぶときは、$s_\times$ が問題の中で意味を持つ大きさ（測定器の分解能や無視してよい物理量の大きさ）に来るように二つの値を決める。
和の代わりに $\max(\tau_{\mathrm{abs}}, \tau_{\mathrm{rel}} s)$ で結合する流儀もある。
$\max(a, b) \le a + b \le 2 \max(a, b)$ なので、和のしきい値は $\max$ のしきい値の 1 倍以上 2 倍以下で、2 倍になるのは $s = s_\times$ のときである。

構築と判定の失敗は `Result` で区別される。

- `Tolerance::new(absolute, relative)` は負の値を `InvalidInput`（`InvalidInputReason::OutOfRange`）、NaN と無限大を `NonFinite` として拒否する。
- `threshold` は負のスケールを `InvalidInput`、非有限のスケールを `NonFinite` として拒否する。
  有限な入力から表現できないしきい値ができた場合は `NumericalInstability`（`NumericalIssue::Overflow`）を返す。
- `is_residual_ok(residual_norm, problem_scale)` は大きいが正当な残差に対して `Ok(false)` を返す。
  負や非有限の残差・スケールは未収束ではなく入力の誤りなので `Err` になる。

次のセルは温度 [K] を想定し、絶対許容誤差 $\tau_{\mathrm{abs}}$ [K] と相対許容誤差の指数 $\log_{10} \tau_{\mathrm{rel}}$ を入力とする。
グラフは `threshold` が返す $\tau(s)$（実線）と二つの項（破線）を、$s = 10^{-2}$ K から $10^{6}$ K までの両対数軸に描き、交点 $s_\times$ を縦線で示す。
表は $s = 10\ \mathrm{K}$、$s_\times$、$300\ \mathrm{K}$ の 3 点で、しきい値、二つの項、大きい方の項を示す。
確かめるのは、しきい値が二つの項の和に一致することと、$s_\times$ でしきい値が $2\tau_{\mathrm{abs}}$ になることである。

```rust

既定値（$\tau_{\mathrm{abs}} = 0.02$ K、$\tau_{\mathrm{rel}} = 10^{-4}$）では交点は $s_\times = 200$ K である。
$10$ K ではしきい値 $0.021$ K のうち相対項は $0.001$ K だけで、$300$ K では相対項 $0.03$ K が絶対項を上回ってしきい値は $0.05$ K になる。
交点ではしきい値が $2\tau_{\mathrm{abs}} = 0.04$ K になる。
$\tau_{\mathrm{rel}}$ を $10^{-5}$ に下げると交点が $2000$ K へ動き、$300$ K のしきい値 $0.023$ K はほとんど絶対項で決まる。
逆に $\tau_{\mathrm{abs}} = 0.005$ K、$\tau_{\mathrm{rel}} = 10^{-2}$ では交点が $0.5$ K まで下がり、$10$ K のしきい値 $0.105$ K の大半を相対項が占める。
グラフでは、実線が交点の左で絶対項の水平線に、右で相対項の傾き 1 の直線に近づく。

## 役割別の許容誤差型

同じ `1e-6` でも、状態の変化量、方程式の残差、勾配のどれに課すかで単位と意味が異なる。
`scioxide-core` は判定の役割ごとに `Tolerance` をラップする型を定義し、取り違えを型で防ぐ。

| 型 | 判定対象 | 判定メソッド | `Default` |
|---|---|---|---|
| `StepTolerance` | 状態の変化量（ステップ長） | `is_satisfied(magnitude, scale)` | $\tau_{\mathrm{abs}} = \tau_{\mathrm{rel}} = \sqrt{\varepsilon}$ |
| `ResidualTolerance` | 方程式の残差ノルム | `is_satisfied(magnitude, scale)` | 同上 |
| `GradientTolerance` | 目的関数の勾配ノルム | `is_satisfied(magnitude, scale)` | 同上 |
| `RankThreshold` | 数値階数を決める特異値やピボット | `is_satisfied(magnitude, scale)` | 同上 |
| `FeasibilityTolerance` | 制約違反量 | `is_satisfied(magnitude, scale)` | 同上 |
| `IntegralityTolerance` | 最も近い整数までの距離 | `is_satisfied(distance)` | $\sqrt{\varepsilon}$ |

$\varepsilon$ は機械イプシロンで、倍精度では $\sqrt{\varepsilon} \approx 1.5 \times 10^{-8}$ である。
最初の 5 型は `new(absolute, relative)`、`from_tolerance`、`tolerance()`、`threshold(scale)` を共有し、検証規則は `Tolerance::new` と同じである。
`is_satisfied(magnitude, scale)` は $\text{magnitude} \le \tau(\text{scale})$ を判定し、エラーの条件は `is_residual_ok` と同じである。

`IntegralityTolerance` は絶対値だけを持ち、$[0, 0.5)$ の範囲に制限される。
$0.5$ 未満なら許容幅に入る整数は高々一つなので、「ほぼ整数」と判定した値の丸め先が一意に決まる。
$0.5$ 以上の値は `InvalidInput`（`OutOfRange`）として拒否され、半整数は整数とみなされない。

`Tolerance` の既定値は定義されていない。
`Tolerance::from_sqrt_epsilon()`（$\tau_{\mathrm{abs}} = \tau_{\mathrm{rel}} = \sqrt{\varepsilon}$）と `Tolerance::from_machine_epsilon()`（$\tau_{\mathrm{abs}} = \tau_{\mathrm{rel}} = \varepsilon$）は名前付きの方針であり、ソルバーがどれを採用するかは各ソルバーのオプション型が文書化する。
`Tolerance::from_decimal_places(p, q)` は $\tau_{\mathrm{abs}} = 10^{-p}$、$\tau_{\mathrm{rel}} = 10^{-q}$ を作る。

絶対項を持たない収束判定には `RelativeTolerance` を使う。
`RelativeTolerance::new(relative)` は有限で非負の相対しきい値だけを受け付け、負の値を `InvalidInput`、NaN と無限大を `NonFinite` として拒否する。
0 は手法が達成できる最良の精度の要求を意味し、精度の下限がある手法はそれを文書化する。
`Default` は機械イプシロン $\varepsilon$ である。
この型は判定メソッドを持たず、`relative()` で値を読み出すか、`Tolerance::from` で $\tau_{\mathrm{abs}} = 0$ の `Tolerance` に変換して使う。

どの許容誤差の型も反復回数や評価回数の上限を含まない。
上限は別の型 `Budget` で与える（[求解のライフサイクルと計算回数の管理](../solve-lifecycle-and-accounting/)）。

## 成分ごとに正規化した誤差と `ErrorTolerance` の 4 ノルム

ベクトル量の誤差 $\mathbf{e} \in \mathbb{R}^n$ では、成分ごとに尺度と許容幅が異なる。
常微分方程式の刻み幅制御や適応求積の局所誤差の判定がこの形である。
`ErrorTolerance` は成分 $i$ のしきい値 $\tau_i = \tau_{\mathrm{abs}, i} + \tau_{\mathrm{rel}} s_i$ で各成分を割った無次元量

$$
w_i = \frac{|e_i|}{\tau_{\mathrm{abs}, i} + \tau_{\mathrm{rel}}\, s_i}
$$

を作り、`NormSelection` で選んだノルムを $\mathbf{w}$ に適用する。
`is_satisfied(errors, scales)` はノルムが 1 以下かを判定し、`normalized_norm(errors, scales)` はノルムの値を返す。
絶対項は `AbsoluteTolerance` として全成分共通（`ErrorTolerance::scalar`）か成分別（`ErrorTolerance::try_vector`）に与え、相対項は共通の一つの値である。
`try_vector` は成分別の値を複製するのでヒープを確保し、`normalized_norm` と `is_satisfied` は確保せずに $O(n)$ の時間で計算する。

| `NormSelection` | 値 | 計算方法 |
|---|---|---|
| `L1` | $\sum_i w_i$ | 浮動小数点数として求めた各 $w_i$ を `RangeAccumulator` で厳密に合計し、最後に一度丸める |
| `L2` | $\sqrt{\sum_i w_i^2}$ | `ScaledNorm`（LASSQ 型の尺度化）で二乗のオーバーフローを避ける |
| `RootMeanSquare` | $\sqrt{\sum_i w_i^2 / n}$ | `ScaledNorm` の尺度化した二乗和を $n$ で割って平方根を取り、尺度を掛け戻す |
| `Infinity` | $\max_i w_i$ | 最大成分 |

空のベクトルのノルムはどの選択でも 0 である。
RMS は同じ誤差分布を複製しても値が変わらないが、少数の成分だけが大きい場合は $n$ が大きいほど薄まる。
`Infinity` は一つの成分でも許容幅を超えれば受理しない。
`ErrorTolerance` の既定値は $\sqrt{\varepsilon}$ の絶対・相対項と `RootMeanSquare` である。

しきい値が 0 の成分には次の規則がある。

- $\tau_i = 0$ の成分は誤差が厳密に 0 のときだけ受理される。
  誤差が 0 でなければ $w_i$ は有限値で表せない。
- このとき `is_satisfied` は `Ok(false)` を返し、`normalized_norm` は `NumericalInstability`（`Overflow`）を返す。
- 成分別の絶対許容誤差の長さが誤差ベクトルと異なると `DimensionMismatch` になる。
  誤差とスケールの長さが異なる場合も同じである。

同じ成分尺度で複数の誤差を判定するときは、`ErrorTolerance::prepare_norm(scales, storage)` でしきい値 $\tau_i$ を一度だけ計算できる。
返される `PreparedErrorNorm` は許容誤差と呼び出し側のしきい値の領域 `storage` を借用するので、再利用中はどちらも変更できない。
`PreparedErrorNorm::normalized_norm_by` は添字から誤差の成分を返すクロージャを受け取って正規化ノルムを返し、`is_satisfied_by` は受理の可否を返す。
どちらもクロージャを成分ごとに 1 回、添字の順に呼ぶ。
`storage` の長さは尺度の成分数と一致させ、異なる場合は `DimensionMismatch` になる。
しきい値が 0 の成分は、ここでも誤差が 0 の場合だけ受理される。
`threshold` と `prepare_norm` は、しきい値を積 $\tau_{\mathrm{rel}} s_i$ と和の 2 回の丸めで作る。
成分が 2 つ以上の `normalized_norm` と `is_satisfied` は、融合積和を 1 命令で実行できるターゲット（`HARDWARE_FMA` が真）では積和を 1 回の丸めで作るので、二つの経路のしきい値は最後のビットで異なることがある。
スライスを作らずに誤差と尺度の組を渡す形は `ErrorTolerance::normalized_norm_by(dimension, component)` である。

次のセルは 4 成分の誤差のうち一つを大きくし、4 種類のノルムで判定を比べる。
入力は大きな誤差を置く成分の添字（0 から 3）とその誤差の大きさで、他の 3 成分の誤差は 0.01 に固定する。
尺度は全成分 1、しきい値は全成分で $0.05 + 0.05 \times 1 = 0.1$ とした（すべて無次元）。
最初の表はノルムごとの正規化ノルム、`prepare_norm` を経由して求めた同じノルム、`is_satisfied` の結果を示す。
2 番目の表はしきい値 0 の成分の扱いと、2 成分の絶対許容誤差を 4 成分の誤差へ当てたときの `DimensionMismatch` を示す。
次元の不一致では、`e.view()` の `SciOxideErrorView::DimensionMismatch` から期待した長さと実際の長さを読み出す。
確かめるのは、二つの経路のノルムが一致することと、手計算した $\mathbf{w}$ のノルムと表の値が一致することである。

//|       - {"artifact":"norms","path":"/rows/0/1","approx":{"value":1.3,"rtol":1e-12}}
//|       - {"artifact":"norms","path":"/rows/0/3","equals":"false"}
//|       - {"artifact":"norms","path":"/rows/1/1","approx":{"value":1.014889156509,"rtol":1e-10}}
//|       - {"artifact":"norms","path":"/rows/2/1","approx":{"value":0.507444578255,"rtol":1e-10}}
//|       - {"artifact":"norms","path":"/rows/2/3","equals":"true"}
//|       - {"artifact":"norms","path":"/rows/3/3","equals":"true"}
//|   - case: last-component
//|     expect:
//|       - {"artifact":"norms","path":"/rows/0/1","approx":{"value":50.3,"rtol":1e-12}}
//|       - {"artifact":"norms","path":"/rows/3/1","approx":{"value":50,"rtol":1e-12}}
use scioxide_core::{ErrorTolerance, SciOxideErrorKind, SciOxideErrorView, NormSelection};

let mut errors = [0.01; 4];
errors[spike_index as usize] = spike_magnitude;
let scales = [1.0; 4];

let mut rows = Vec::new();
for (name, norm) in [
    ("L1", NormSelection::L1),
    ("L2", NormSelection::L2),
    ("RMS", NormSelection::RootMeanSquare),
    ("L∞", NormSelection::Infinity),
] {
    let tolerance = ErrorTolerance::scalar(0.05, 0.05, norm).map_err(|e| e.to_string())?;
    let value = tolerance
        .normalized_norm(&errors, &scales)
        .map_err(|e| e.to_string())?;
    let accepted = tolerance
        .is_satisfied(&errors, &scales)
        .map_err(|e| e.to_string())?;
    // 同じ尺度で繰り返し判定する形: しきい値を thresholds に一度だけ計算する。
    let mut thresholds = [0.0; 4];
    let prepared = tolerance
        .prepare_norm(&scales, &mut thresholds)
        .map_err(|e| e.to_string())?;
    let prepared_value = prepared
        .normalized_norm_by(|i| errors[i])
        .map_err(|e| e.to_string())?;
    rows.push((name, value, prepared_value, accepted.to_string()));
}
let digits6 = serde_json::json!({ "significantDigits": 6 });
let norm_columns = serde_json::json!([
    { "key": "0", "label": "ノルム" },
    { "key": "1", "label": "normalized_norm [-]", "type": "number", "format": digits6 },
    { "key": "2", "label": "prepare_norm 経由のノルム [-]", "type": "number", "format": digits6 },
    { "key": "3", "label": "is_satisfied" }
]);
emit_table_with_columns!(
    norm_columns,
    rows,
    metadata = serde_json::json!({ "id": "norms" })
);

// 分類 kind() を列挙子の名前で表示する。この表で起こるのは次の 2 分類である。
let kind_name = |kind: SciOxideErrorKind| match kind {
    SciOxideErrorKind::NumericalInstability => "NumericalInstability",
    SciOxideErrorKind::DimensionMismatch => "DimensionMismatch",
    _ => "その他の分類",
};
// 判定とノルムを別々に呼び、エラーなら分類と、次元の不一致なら二つの長さを読む。
let observe = |tolerance: &ErrorTolerance<f64>, errors: &[f64], scales: &[f64]| {
    let accepted = tolerance
        .is_satisfied(errors, scales)
        .ok()
        .map(|ok| ok.to_string());
    match tolerance.normalized_norm(errors, scales) {
        Ok(value) => (accepted, Some(value), None, None, None),
        Err(error) => {
            // 形は軸の長さの並び（ここでは 1 軸）で返る。
            let (expected, actual) = match error.view() {
                SciOxideErrorView::DimensionMismatch { expected, actual } => {
                    (expected.first().copied(), actual.first().copied())
                }
                _ => (None, None),
            };
            (
                accepted,
                None,
                Some(kind_name(error.kind())),
                expected,
                actual,
            )
        }
    }
};
// しきい値 0 の成分と、2 成分の絶対許容誤差を 4 成分の誤差に当てた場合。
let zero =
    ErrorTolerance::scalar(0.0, 0.0, NormSelection::Infinity).map_err(|e| e.to_string())?;
let vector = ErrorTolerance::try_vector(&[0.01, 0.02], 0.05, NormSelection::Infinity)
    .map_err(|e| e.to_string())?;
let edge_rows: Vec<_> = [
    ("τ_i = 0, e_i = 0", observe(&zero, &[0.0], &[1.0])),
    ("τ_i = 0, e_i = 0.01", observe(&zero, &[0.01], &[1.0])),
    (
        "2 成分の τ_abs と 4 成分の誤差",
        observe(&vector, &errors, &scales),
    ),
]
.into_iter()
.map(|(label, (accepted, norm, kind, expected, actual))| {
    (label, accepted, norm, kind, expected, actual)
})
.collect();
let edge_columns = serde_json::json!([
    { "key": "0", "label": "条件" },
    { "key": "1", "label": "is_satisfied", "nullText": "エラー" },
    { "key": "2", "label": "normalized_norm [-]", "type": "number", "nullText": "エラー" },
    { "key": "3", "label": "エラーの kind()", "nullText": "—" },
    { "key": "4", "label": "期待した長さ", "type": "integer", "nullText": "—" },
    { "key": "5", "label": "実際の長さ", "type": "integer", "nullText": "—" }
]);
emit_table_with_columns!(
    edge_columns,
    edge_rows,
    metadata = serde_json::json!({ "id": "edges" })
);
```

既定の入力では正規化誤差は $\mathbf{w} = (0.1, 20, 0.1, 0.1)$ となり、L1 は $20.3$、L2 は $\sqrt{400.03} \approx 20.0007$、RMS はその半分の約 $10.0004$、L∞ は $20$ である。
どのノルムでも 1 を超えるので受理されない。
`prepare_norm` を経由した値は 4 種類とも `normalized_norm` の値と一致する。
大きな誤差を 0.1 まで下げると $\mathbf{w} = (0.1, 1, 0.1, 0.1)$ となり、L∞ は 1、RMS は約 $0.507$ で受理される。
一方 L1 は $1.3$、L2 は約 $1.015$ で受理されず、小さな成分の寄与も足し合わされることが分かる。
添字を 3、誤差を 5 にすると L1 は $50.3$、L∞ は $50$ で、ノルムは大きな成分の位置によらない。

2 番目の表では、しきい値 0 で誤差 0 の成分は受理され、ノルムは 0 である。
誤差が $0.01$ になると `is_satisfied` は `false` を返し、`normalized_norm` は `NumericalInstability` のエラーになる。
長さの合わない許容誤差では両方の関数が `DimensionMismatch` を返し、期待した長さは誤差ベクトルの 4、実際の長さは成分別の絶対許容誤差の 2 である。

## 残差レポートと `ResidualReport`

ソルバーが終了時に残差を返すとき、生の残差ノルムだけでは問題の尺度によって大小を比べられない。
`ResidualReport` は生の残差とその尺度化の規則を一組で保持する。

- `raw_norm()`：問題の単位での残差ノルム $\|F(\mathbf{x})\|$。
- `norm()`：残差を縮約したノルム（`NormSelection`）。
- `scaling()`：尺度化の規則 `ResidualScalingRule` と正の分母 $D$ を持つ `ResidualScaling`。
- `scaled_norm()`：`raw_norm / D` を範囲安全な除算（`checked_float_quotient`）で求めた無次元の値。

`ResidualScalingRule` は `Unscaled`（分母 1）、`Reference`（参照値で割る）、`ToleranceThreshold`（しきい値で割る）、`ComponentwiseTolerance`（成分ごとに正規化してから縮約）、`BackwardError`（ノルムの後退誤差の分母）のどれを使ったかを記録する。
`ResidualScaling::new(rule, denominator)` は 0 以下の分母を `InvalidInput`、非有限の分母を `NonFinite` として拒否する。
`ResidualReport::new(raw_norm, norm, scaling)` は負の残差ノルムを `InvalidInput`、非有限の残差ノルムを `NonFinite`、商のオーバーフローを `NumericalInstability` として返す。
分母にしきい値 $\tau(s)$ を使う `ToleranceThreshold` では、`scaled_norm()` が 1 以下であることと、同じ許容誤差で残差が受理されることが対応する。

レポートは失敗時の診断にも付く。
`ConvergenceDiagnostics::with_residual` で付けたレポートは、`SciOxideErrorView::ConvergenceFailure` の `diagnostics`（借用ビュー `ConvergenceDiagnosticsView`）の `residual()` で読み出せる。
反復上限による失敗で、詳細が静的な文字列、診断が自分と入れ子の求解の反復回数だけの場合は、エラーはヒープを使わずにその回数だけを保持する。
このとき `residual()`、`budget()`、`algorithm()` は `None` を返し、`counts()` は二つの反復回数を返す。

次のセルは残差の許容誤差を $\tau_{\mathrm{abs}} = 10^{-10}$、$\tau_{\mathrm{rel}} = 10^{-8}$ に固定し、残差ノルムの指数 $\log_{10}\|r\|$ と代表スケール $s$（右辺のノルムなど）を入力とする。
量はすべて無次元の例として扱う。
最初の表は分母 $D = \tau(s)$ の `ToleranceThreshold` で作ったレポートの生の残差、分母、尺度化した残差と、`ResidualTolerance::is_satisfied` の結果を示す。
2 番目の表は回数だけの診断と、残差とアルゴリズムの識別子を付けた診断の二つで反復上限の失敗を作り、`view()` から読み出した内容を比べる。
確かめるのは、尺度化した残差が `raw_norm / D` に一致することと、それが 1 以下かどうかが `is_satisfied` と一致することである。

既定値（$\|r\| = 10^{-9}$、$s = 1$）では分母は $D = 10^{-10} + 10^{-8} = 1.01 \times 10^{-8}$ で、尺度化した残差は約 $0.099$ となり、許容誤差を満たす。
残差を $10^{-7}$ に上げると尺度化した残差は約 $9.9$ になり、`is_satisfied` は `false` を返す。
$s = 0$ では分母が $\tau_{\mathrm{abs}} = 10^{-10}$ になり、同じ残差 $10^{-9}$ の尺度化した値は $10$ で、許容誤差を満たさない。
生の残差が同じでも、分母の選び方で尺度化した値は 2 桁変わる。

2 番目の表では、回数だけの診断から作ったエラーの `residual()` と `algorithm()` は `None` で、残差と識別子を付けた診断からは同じ尺度化した残差と識別子 `handbook/residual-report@1` が読める。

小さい残差は前進誤差が小さいことを意味しない。
残差と後退誤差・前進誤差の関係は[浮動小数点と条件数](../../../concepts/floating-point-and-conditioning/)で扱う。

## まとめ

`Tolerance` のしきい値は $\tau_{\mathrm{abs}} + \tau_{\mathrm{rel}} s$ であり、交点スケール $s_\times$ を問題の意味のある大きさに置くように二つの値を選ぶ。
判定の対象が変化量・残差・勾配・階数・制約・整数性のどれかに応じて役割別の型を使い、既定値に頼る場合は $\sqrt{\varepsilon}$ が選ばれることを確認する。
ベクトルの誤差は `ErrorTolerance` で成分ごとに正規化し、局所的な誤差を見逃したくないときは `Infinity`、成分数に依存しない平均的な水準を見たいときは `RootMeanSquare` を選ぶ。
しきい値 0 の成分は誤差 0 だけを受理し、判定は `Ok(false)` で返ることを前提に呼び出し側の分岐を書く。
残差のレポートを読むときは、`scaled_norm()` だけでなく `scaling()` の規則と分母を確かめ、何で割った値かを把握する。
