SciOxide の関数は入力の誤りから数値計算の破綻、実行環境の不足までを一つの型 `SciOxideError` で返す。
呼び出し側は分類で処理を分け、詳細ビューで何がどう失敗したかを確かめる。
このページはその読み方を扱う。
`Err` と未収束などの結果を含む `Ok` の区別と部分結果の扱いは[エラー仕様と部分結果](../../../concepts/errors-and-partial-results/)にあり、許容誤差による判定は[許容誤差の役割と判定条件](../error-and-tolerance-contracts/)にある。
成功した結果に付く推定値の根拠の読み方は[推定値の信頼性の区分](../estimate-reliability/)で扱う。

## 分類 `kind()` と詳細ビュー `view()`

`SciOxideError` は中身を出力に反映しない構造体で、内部の列挙子に直接照合することはできない。
`kind()` は安定した分類 `SciOxideErrorKind` を値で返し、`view()` は分類ごとの欄を借用した `SciOxideErrorView<'_>` を返す。
二つの列挙型の列挙子は同じ名前の 20 個で、一対一に対応する。
処理を分けるだけなら `kind()` で足り、引数の名前や形、理由まで読むときは `view()` を照合する。
`to_string()` が返す文は人が読むための英語の説明で、プログラムで解析する対象ではない。

| 分類 | 失敗の内容 | `view()` の欄 |
|---|---|---|
| `InvalidInput` | 入力や設定が構造的に不正 | `argument`、`reason`（`InvalidInputReason`）、`detail` |
| `DimensionMismatch` | 形が合わない | `expected`、`actual`（軸の長さの並び） |
| `SizeOverflow` | 大きさや容量の計算が表せない | `context`（`Quantity`） |
| `AccountingInvariant` | 回数の集計の記録が整合しない | `detail`、`partition` |
| `ResourceLimit` | 設定したリソースの上限を超えた | `resource`（`Quantity`）、`required`、`limit` |
| `AllocationFailure` | メモリを確保できなかった | `context`（`Quantity`）、`requested` |
| `ExecutionFailure` | 注入したエグゼキューターが失敗した | `partition`、`reason`（`ExecutionFailureReason`）、`detail` |
| `CapabilityUnavailable` | 要求した機能が与えられていない | `capability`（`Capability`） |
| `CapabilityFailure` | 与えた機能のプロバイダーが失敗した | `capability`、`detail` |
| `ExecutionStopped` | 取り消しか期限で止まった | `reason`（`ExecutionStopReason`） |
| `OutOfBounds` | 添字が範囲の外にある | `collection`（`Quantity`）、`index`、`size` |
| `DomainError` | 有限な引数が定義域の外にある | `argument`、`reason`（`DomainReason`）、`detail` |
| `NonFinite` | NaN か無限大を観測した | `origin`（`NonFiniteOrigin`）、`detail` |
| `ScalarConversion` | 検査付きのスカラー変換に失敗した | `from_type`、`to_type`（`ConversionType`）、`reason` |
| `ConvergenceFailure` | 有効な有限の反復が収束しなかった | `reason`（`ConvergenceReason`）、`diagnostics`、`detail` |
| `Singular` | 行列が特異 | `pivot`（検証したピボットの位置。分かる場合だけ） |
| `NumericalInstability` | 有限精度の計算が破綻した | `issue`（`NumericalIssue`）、`detail` |
| `DifferentiationFailure` | 微分のコールバックが失敗した | `frames`（`DifferentiationFrame` の並び）、`cause` |
| `NotImplemented` | 意図して提供しない操作 | `detail` |
| `External` | コールバックや利用側のコードが返した失敗 | `detail` |

数値に関わる 5 分類は重ならないように定めてある。
`InvalidInput` は構造の誤りで、`DomainError` は有限な引数が数学的な定義域の外にある場合に限る。
`NonFinite` は NaN か無限大、`NumericalInstability` は有限精度による破綻、`ConvergenceFailure` は有効な有限の入力に対する反復が収束しなかった場合である。
たとえば `logit` に $0 < x < 1$ の外にある有限の $x$ を渡すと `DomainError`、NaN を渡すと `NonFinite` になる。
有限の被演算子から無限大ができた場合は `NonFinite` ではなく、`NumericalInstability`（`Overflow`）として示される。

リソースに関わる 3 分類も区別される。
`SizeOverflow` は必要な大きさの計算が整数型で表せない場合、`ResourceLimit` は表せるが呼び出し側の設定した上限を超える場合、`AllocationFailure` は確保そのものが失敗した場合である。
分類の `ResourceLimit` と収束の理由 `ConvergenceReason::ResourceLimit` は別のもので、後者は反復回数と評価回数以外の求解の計算回数の上限に達して反復が止まったことを表す。

`DifferentiationFailure` は元の失敗を包む分類である。
包んだエラーの `kind()` は `DifferentiationFailure` を返し、元の失敗は `view()` の `cause` か `Error::source()` で読める。

SciOxide の外のコードは `SciOxideError::external(detail)` で `External` のエラーを作る。
利用側のコールバックが返したエラーは、変更されずに呼び出し元へ返る。
数値微分の中でコールバックが失敗した場合は、上のとおり `DifferentiationFailure` に包まれ、返したエラーは `cause` に変更されずに残る。

詳細が静的な文字列のエラーと、二つの形がどちらも階数 2 以下の `DimensionMismatch` はヒープを確保しない。
反復上限の失敗も、詳細が静的な文字列で診断が反復回数だけなら確保しない。
所有する文字列の詳細、分割の番号を持つ `ExecutionFailure`、機能 `Operation` の `CapabilityFailure`、反復回数以外の診断を持つ `ConvergenceFailure`、`DifferentiationFailure` は、ヒープに確保して保持する。

次のブロックは、このページのセルが共有する定義である。
`kind_name` は分類 `SciOxideErrorKind` を列挙子の名前の文字列にする。
`SciOxideErrorKind` は網羅的に照合できるので、20 個の列挙子をすべて並べる。
`describe` は `view()` を照合し、失敗箇所（引数・量・機能・変換の向き）、理由の列挙子の名前、詳細文の三つを読み出す。
理由の列挙型は外部のクレートから網羅的に照合できないので、挙げていない列挙子は「その他」とする。

```rust
//| id: core-error-kind-names
//| kind: definitions
//| title: 分類と理由の列挙子の名前
//| crates: [scioxide-core]
use scioxide_core::{
    Capability, DomainReason, SciOxideError, SciOxideErrorKind, SciOxideErrorView, InvalidInputReason,
    NonFiniteOrigin, NumericalIssue, ScalarConversionReason,
};

/// 分類の列挙子の名前を返す。
pub(crate) fn kind_name(kind: SciOxideErrorKind) -> &'static str {
    match kind {
        SciOxideErrorKind::InvalidInput => "InvalidInput",
        SciOxideErrorKind::DimensionMismatch => "DimensionMismatch",
        SciOxideErrorKind::SizeOverflow => "SizeOverflow",
        SciOxideErrorKind::AccountingInvariant => "AccountingInvariant",
        SciOxideErrorKind::ResourceLimit => "ResourceLimit",
        SciOxideErrorKind::AllocationFailure => "AllocationFailure",
        SciOxideErrorKind::ExecutionFailure => "ExecutionFailure",
        SciOxideErrorKind::CapabilityUnavailable => "CapabilityUnavailable",
        SciOxideErrorKind::CapabilityFailure => "CapabilityFailure",
        SciOxideErrorKind::ExecutionStopped => "ExecutionStopped",
        SciOxideErrorKind::OutOfBounds => "OutOfBounds",
        SciOxideErrorKind::DomainError => "DomainError",
        SciOxideErrorKind::NonFinite => "NonFinite",
        SciOxideErrorKind::ScalarConversion => "ScalarConversion",
        SciOxideErrorKind::ConvergenceFailure => "ConvergenceFailure",
        SciOxideErrorKind::Singular => "Singular",
        SciOxideErrorKind::NumericalInstability => "NumericalInstability",
        SciOxideErrorKind::DifferentiationFailure => "DifferentiationFailure",
        SciOxideErrorKind::NotImplemented => "NotImplemented",
        SciOxideErrorKind::External => "External",
    }
}

// 列挙子の名前を文字列にする。挙げていない列挙子は「その他」とする。
macro_rules! variant_name {
    ($value:expr; $ty:ident => $($variant:ident)|+) => {
        match $value {
            $($ty::$variant => stringify!($variant),)+
            _ => "その他",
        }
    };
}

/// 失敗箇所、理由の列挙子の名前、詳細文。その分類が持たない欄は `None`。
pub(crate) type ErrorDetail = (Option<String>, Option<&'static str>, Option<String>);

/// `view()` から失敗箇所（引数・量・機能・変換の向き）、理由、詳細文を読む。
pub(crate) fn describe(error: &SciOxideError) -> ErrorDetail {
    match error.view() {
        SciOxideErrorView::InvalidInput {
            argument,
            reason,
            detail,
        } => {
            let reason = variant_name!(reason; InvalidInputReason =>
                Empty | OutOfRange | Inconsistent | Malformed | UnsupportedConfiguration);
            (
                Some(format!("引数 {argument}")),
                Some(reason),
                Some(detail.to_string()),
            )
        }
        SciOxideErrorView::DomainError {
            argument,
            reason,
            detail,
        } => {
            let reason = variant_name!(reason; DomainReason => OutsideDomain | Pole | Undefined);
            (
                Some(format!("引数 {argument}")),
                Some(reason),
                Some(detail.to_string()),
            )
        }
        SciOxideErrorView::NonFinite { origin, detail } => {
            let origin =
                variant_name!(origin; NonFiniteOrigin => Input | Callback | Intermediate | Output);
            (None, Some(origin), Some(detail.to_string()))
        }
        SciOxideErrorView::ScalarConversion {
            from_type,
            to_type,
            reason,
        } => {
            let reason = variant_name!(reason; ScalarConversionReason =>
                NonFiniteInput | OutOfRange | Inexact | Unsupported);
            (Some(format!("{from_type} → {to_type}")), Some(reason), None)
        }
        SciOxideErrorView::NumericalInstability { issue, detail } => {
            let issue = variant_name!(issue; NumericalIssue =>
                ExponentOutOfRange | Overflow | Underflow | Cancellation | LossOfSignificance
                | IllConditioned | DefectiveEigenbasis | Breakdown);
            (None, Some(issue), Some(detail.to_string()))
        }
        SciOxideErrorView::SizeOverflow { context } => (Some(format!("量 {context}")), None, None),
        SciOxideErrorView::CapabilityUnavailable { capability } => {
            let name =
                variant_name!(capability; Capability => Clock | Entropy | Blas | ProcessorFeatures);
            (Some(format!("機能 {name}")), None, None)
        }
        SciOxideErrorView::CapabilityFailure { capability, detail } => {
            let name =
                variant_name!(capability; Capability => Clock | Entropy | Blas | ProcessorFeatures);
            (Some(format!("機能 {name}")), None, Some(detail.to_string()))
        }
        // このページの表に現れない分類は、Display の文だけを詳細に出す。
        _ => (None, None, Some(error.to_string())),
    }
}
```

## 引数と量による失敗箇所

エラーは失敗した関数のどの入力か、どのリソースかを識別子で示し、呼び出し元が誰かは持たない。
入力の引数は `Argument` で表し、`InvalidInput` と `DomainError` が持つ。
大きさ・容量・計数・集まりのようなリソースは `Quantity` で表し、`SizeOverflow`、`ResourceLimit`、`AllocationFailure`、`OutOfBounds` が持つ。

二つの文法は同じで、小文字の英字か下線で始まり小文字・数字・下線が続く区切りを `.` でつなぐ（`options.max_steps`、`workspace.capacity`）。
型は分けてあるので、リソースの名前を引数の欄に入れることはできない。
識別子は失敗した関数の仮引数の名前で、たとえば `Interval::new` は端点の逆転を `lower` に、`checked_float_quotient` は 0 の分母を `denominator` に帰す。

`argument!` と `quantity!` はリテラルをコンパイル時に検査して識別子を作り、文法に合わない綴りはコンパイルエラーになる。
綴りは確保せずに保持され、`as_str()` か `Display` で読める。

## 理由の列挙型

多くの分類は機械が読める理由を列挙型で持つ。
次の表の列挙型はどれも `#[non_exhaustive]` なので、外部のクレートからの `match` には `_` の腕が要る。
`SciOxideErrorKind` と `ConversionType` は網羅的に照合できる。

| 列挙型 | 現れる分類 | 列挙子 |
|---|---|---|
| `InvalidInputReason` | `InvalidInput` | `Empty`（必要な値がない）、`OutOfRange`（許される範囲の外）、`Inconsistent`（個々には正しい入力どうしが矛盾する）、`Malformed`（形式の誤り）、`UnsupportedConfiguration`（この構成では扱わない組合せ） |
| `DomainReason` | `DomainError` | `OutsideDomain`（定義域の外）、`Pole`（関数の極）、`Undefined`（数学的に定義されない。0 での除算など） |
| `NonFiniteOrigin` | `NonFinite` | 非有限値を観測した場所。`Input`、`Callback`、`Intermediate`、`Output` |
| `NumericalIssue` | `NumericalInstability` | `Overflow`、`Underflow`、`Cancellation`、`IllConditioned`、`Breakdown` など 8 種類（[射影と範囲のエラー](oxref:core-projection-errors)） |
| `ConvergenceReason` | `ConvergenceFailure` | `IterationLimit`、`EvaluationLimit`、`ResourceLimit(BudgetKind)`、`TruncationLimit`、`Stagnation`、`StepSizeLimit`、`ReplayMismatch`、`Divergence`、`NestedSolver`、`NoSuccessfulCandidate` |
| `ScalarConversionReason` | `ScalarConversion` | `NonFiniteInput`、`OutOfRange`、`Inexact`、`Unsupported` |
| `ExecutionFailureReason` | `ExecutionFailure` | `WorkerCreation { os_error }`、`CallbackPanicked`、`ProviderFailure`、`UnknownPartition`、`DuplicatePartition`、`MissingPartition`、`ProtocolViolation` |
| `ExecutionStopReason` | `ExecutionStopped` | `Cancelled`、`DeadlineReached` |

スカラー変換の失敗は変換元と変換先の表現を `ConversionType`（`F32`、`F64`、`Complex32`、`Complex64`、`I64`、`Isize`、`U128`、`Usize`）で示す。
`RealScalar::try_from_f64_exact` は値が変わる変換を `Inexact` として拒む（倍精度の 0.1 は単精度で厳密に表せない）。
`try_from_f64_lossy` は最近接への丸めを許し、非有限値と範囲の外だけを拒む。

`ConvergenceFailure` の `diagnostics` は、アルゴリズムの識別子、反復と評価の回数、止めた計算回数の上限、最後の残差、最後に受理した状態、入れ子の求解ごとの同じ記録を持つ。
読み方は[残差レポートと `ResidualReport`](oxref:core-residual-report-section)と[入れ子の上限と診断](oxref:core-nested-diagnostics)にある。

## 機能の不足

クロック、外部のエントロピー源、BLAS のプロバイダーは、呼び出し側が注入する機能である。
`Capability` は実行環境の機能を `Clock`（単調なクロックと期限）、`Entropy`（外部のエントロピー源）、`Blas`（BLAS のプロバイダー）、`ProcessorFeatures`（プロセッサの機能の観測）で表し、数値演算そのものの機能は `Operation(&'static str)` に名前を入れて表す。
機能が与えられていなければ `CapabilityUnavailable`、与えたプロバイダーが失敗すれば `CapabilityFailure` になる。
クロックを結び付けていない `ExecutionContext` に `with_time_limit` で時間の上限を付けると、機能 `Clock` の `CapabilityUnavailable` が返る。
scioxide-linalg は、BLAS が使えないときに参照実装への切り替えを禁じた設定では、機能 `Blas` の `CapabilityUnavailable` を返す。

プロバイダーが実装するトレイト（`Clock::now`、`EntropySource::fill_bytes`）は、失敗を詳細文だけを持つ `CapabilityError` で返す。
`CapabilityError` は `new(detail)` で作り、`detail()` で読む。
SciOxide は `into_detail()` でその文を複製せずに `CapabilityFailure` の `detail` へ移す。
wasm には標準のクロック `StdClock` がないので、時間の上限は使えない（[wasm 環境でのクロックと時間上限](oxref:core-wasm-clocks)）。

## 識別子の検証

`Argument::new`、`Quantity::new`、`AlgorithmComponent::new` は綴りを文法で検査する `const fn` で、違反は `IdentifierError` になる。
`IdentifierError::position()` は最初の不正なバイトの位置を 0 始まりで返す。
区切りが空のまま綴りが終わる場合は、入力の長さを返す。
`into_scioxide()` はこのエラーを確保なしで `InvalidInput`（引数 `identifier`、理由 `Malformed`）に変える。

`AlgorithmComponent` はアルゴリズムの識別子 `AlgorithmId` を作る族と手法の名前で、文法は `[A-Za-z0-9_][A-Za-z0-9_.-]*`（大文字と小文字を区別する）である。
`algorithm_component!` はリテラル、`concat!`、`stringify!` の式をコンパイル時に検査する。
検査済みの部品は `AlgorithmId::from_components(family, method, version)` で検査し直さずに組み合わせられる。
`AlgorithmId` は求解の識別と収束の失敗の診断に記録される（[求解の同一性とエポック](oxref:core-solve-identity)）。

次のセルは入力を持たず、三つの型に正しい綴りと誤った綴りを渡して、受理の可否と `position()` を表にする。
拒否された行では、`into_scioxide()` で変換したエラーの分類と理由も示す。
確かめるのは、`position()` が最初の不正なバイトの位置（`options.maxSteps` では大文字 `S` の 11）と一致することである。

```rust
//| id: core-identifier-validation
//| ref: core-identifier-validation
//| title: 識別子の文法の検査と不正なバイトの位置
//| run: reactive
//| uses: [core-error-kind-names]
//| crates: [scioxide-core]
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"identifiers","path":"/rows/0/2","equals":"受理"}
//|       - {"artifact":"identifiers","path":"/rows/0/3","equals":null}
//|       - {"artifact":"identifiers","path":"/rows/1/3","equals":11}
//|       - {"artifact":"identifiers","path":"/rows/1/4","equals":"InvalidInput"}
//|       - {"artifact":"identifiers","path":"/rows/1/5","equals":"Malformed"}
//|       - {"artifact":"identifiers","path":"/rows/2/3","equals":8}
//|       - {"artifact":"identifiers","path":"/rows/3/3","equals":0}
//|       - {"artifact":"identifiers","path":"/rows/4/2","equals":"受理"}
//|       - {"artifact":"identifiers","path":"/rows/5/3","equals":3}
use scioxide_core::{
    AlgorithmComponent, Argument, SciOxideErrorView, IdentifierError, InvalidInputReason,
    Quantity,
};

// 検査の結果を、受理の可否、不正なバイトの位置、into_scioxide() の分類と理由にする。
let row = |kind: &'static str, spelling: &'static str, checked: Result<(), IdentifierError>| {
    match checked {
        Ok(()) => (kind, spelling, "受理", None, None, None),
        Err(error) => {
            let converted = error.into_scioxide();
            let malformed = matches!(
                converted.view(),
                SciOxideErrorView::InvalidInput {
                    reason: InvalidInputReason::Malformed,
                    ..
                }
            );
            (
                kind,
                spelling,
                "拒否",
                Some(error.position()),
                Some(kind_name(converted.kind())),
                malformed.then_some("Malformed"),
            )
        }
    }
};
let argument = |spelling| row("Argument", spelling, Argument::new(spelling).map(|_| ()));
let quantity = |spelling| row("Quantity", spelling, Quantity::new(spelling).map(|_| ()));
let component = |spelling| {
    row(
        "AlgorithmComponent",
        spelling,
        AlgorithmComponent::new(spelling).map(|_| ()),
    )
};
let rows = vec![
    argument("options.max_steps"),
    // 大文字は引数の文法に含まれない。
    argument("options.maxSteps"),
    // 最後の区切りが空。
    argument("options."),
    // 区切りの先頭に数字は置けない。
    quantity("9lives"),
    // アルゴリズムの部品は数字で始まってよく、`.` と `-` を含められる。
    component("2-norm.v2"),
    component("bad method"),
];
let columns = serde_json::json!([
    { "key": "0", "label": "型" },
    { "key": "1", "label": "綴り" },
    { "key": "2", "label": "検査" },
    { "key": "3", "label": "position() [バイト]", "type": "integer", "nullText": "—" },
    { "key": "4", "label": "into_scioxide() の kind()", "nullText": "—" },
    { "key": "5", "label": "理由", "nullText": "—" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "identifiers" })
);
```

`options.max_steps` は受理され、`options.maxSteps` は大文字 `S` の位置 11 で拒否される。
`options.` は最後の区切りが空なので、入力の長さ 8 が返る。
`9lives` は区切りの先頭が数字なので位置 0 で拒否される。
`AlgorithmComponent` は `2-norm.v2` を受理し、空白を含む `bad method` を位置 3 で拒否する。
拒否された 4 行はどれも `into_scioxide()` で `InvalidInput` の `Malformed` になる。

## 次元の不一致

`DimensionMismatch` の `view()` は期待した形 `expected` と実際の形 `actual` を軸の長さの並び `&[usize]` で返す。
形を作る側は `Dimensions` を `Dimensions::scalar()`（階数 0）、`one(n)`、`two(m, n)` で作るか、`usize`、長さ 1 と 2 の配列、スライス、配列への参照、`Vec<usize>`、`Box<[usize]>` から変換して作る。
`rank()` は軸の数を、`axes()` は軸の長さを元の順に返す。
`SciOxideError::dimension_mismatch(expected, actual)` は `impl Into<Dimensions>` を受け取り、二つの形がどちらも階数 2 以下ならヒープを使わずに保持する。

どちらを期待した形とするかは関数ごとに決まる。
`ErrorTolerance::normalized_norm` は誤差ベクトルの長さを期待した形、成分別の絶対許容誤差の長さを実際の形として返す。
この例は[成分ごとに正規化した誤差のセル](oxref:core-error-tolerance-norms)で実行できる。

## 微分の失敗位置

数値微分がコールバックを呼んで失敗すると、その失敗は `DifferentiationFailure` に包まれ、どこで何回呼んだかが外側の境界から順に `DifferentiationFrame` の並びとして残る。
各フレームは公開フィールド `location`（`DifferentiationLocation`）と `evaluations`（失敗した呼び出しを含む呼び出しの回数）を持つ。
微分を入れ子にすると、`SciOxideError::differentiation_failure` は新しいフレームを先頭に足し、エラーを一つにまとめる。

`DifferentiationLocation::site()` が返す `DifferentiationSite` は次のどれかである。

- `BasePoint`：摂動しない関数値の検査。
- `Direction`：方向微分（基点の検査を含む）。
- `Variable(i)`：1 座標の導関数。
- `Variables(i, j)`：2 座標の導関数（ヘッセ行列の対角を含む）。

`component_index()` は出力の成分番号が分かる場合にそれを返す。
`scioxide-core` 自身はこの分類のエラーを作らず、実例は [数値微分のアルゴリズムの共通仕様と構成](oxref:differentiate-failure-outputs) にある。

## 不正な入力に対する分類の実例

次のセルは `scioxide-core` の公開関数に不正な入力を与え、返ったエラーを `kind()` と `view()` で読んで二つの表にする。
操作入力は関数に渡す無次元の値 $x$ で、有限の値 6 個と `NaN`、`inf` から選ぶ。

最初の表は $x$ を受け取る 6 個の呼び出しである。
`Interval::new(0.25, x)` は $x < 0.25$ で端点が逆順になり、`logit(x)` の定義域は $0 < x < 1$、`Tolerance::new(x, 1e-8)` は負の絶対許容誤差を拒否する。
残りは単精度への厳密な変換、$1/x$ の検査付き除算、有限の値だけを受け付ける `ReliableEstimate::new`（[推定値の信頼性の区分](../estimate-reliability/)）である。
成功した行は値を示し、区間では上端、許容誤差では $\tau_{\mathrm{abs}}$、推定値ではその値を出す。

2 番目の表は $x$ によらず失敗する 4 個の呼び出しである。
0 の計算回数の上限、二項係数 $\binom{100}{50} \approx 1.0 \times 10^{29}$（wasm の 32 ビットでも 64 ビットでも `usize` に収まらない）、クロックのないコンテキストでの時間の上限、失敗するクロックのプロバイダーを試す。

列挙子の名前は識別子のまま、詳細は SciOxide が返す英語の文のまま示す。
確かめるのは、各行の分類と理由が上の表の定義どおりになることである。

既定の $x = -1$ では、`Interval::new` が `InvalidInput`（`Inconsistent`、引数 `lower`）、`logit` が `DomainError`（`OutsideDomain`、引数 `x`）、`Tolerance::new` が `InvalidInput`（`OutOfRange`、引数 `absolute`）を返す。
単精度への変換、除算、`ReliableEstimate::new` は成功して $-1$ を返す。

$x$ を `NaN` か `inf` にすると、単精度への変換を除く 5 行がそろって `NonFinite`（`Input`）に変わり、単精度への変換は `ScalarConversion`（`NonFiniteInput`）になる。
$x = 0$ では除算が `DomainError`（`Undefined`、引数 `denominator`）になる。
$x = 10^{-310}$ では商 $10^{310}$ が倍精度の範囲を超え、除算は `NumericalInstability`（`Overflow`）になる。
単精度への変換は $x = 0.1$ と $10^{-310}$ で `Inexact`、$x = 10^{300}$ で `OutOfRange` を返す。
$x = 0.5$ では 6 行とも成功し、`logit(0.5) = 0` と $1/x = 2$ が返る。

2 番目の表では、0 の計算回数の上限が `InvalidInput`（`OutOfRange`、引数 `value`）、二項係数が量 `binomial_coefficient` の `SizeOverflow` を返す。
クロックの 2 行は機能 `Clock` の `CapabilityUnavailable` と `CapabilityFailure` で、後者の詳細はプロバイダーが `CapabilityError` に入れた文のままである。

## まとめ

`SciOxideError` は `kind()` で 20 分類のどれかを確かめて処理を分け、引数・量・形・理由が必要なときだけ `view()` を照合して読む。
`InvalidInput`、`DomainError`、`NonFinite`、`NumericalInstability`、`ConvergenceFailure` は重ならないので、入力の直し方を分類だけで選べる。
失敗箇所は `Argument` と `Quantity` の識別子で示され、理由の列挙型は `#[non_exhaustive]` なので `match` に `_` の腕を置く。
クロックや BLAS が必要な処理では、`CapabilityUnavailable` なら機能を注入し、`CapabilityFailure` ならプロバイダーの詳細文を確かめる。
詳細文 `detail` と `to_string()` は人が読むための英語の説明なので、処理の分岐には使わない。
