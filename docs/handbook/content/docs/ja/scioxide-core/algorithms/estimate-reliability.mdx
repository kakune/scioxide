条件数や誤差の推定値は、エラーではなく成功した結果の一部として返る。
失敗の原因を読むのとは別に、返った数値がどの根拠で求めた値かを確かめる必要がある。
`scioxide-core` は、証明のない推定値の根拠を示す区分 `EstimateReliability` と、値と区分を組にした型 `ReliableEstimate` を定める。
`scioxide-core` 自身にこの型を返す関数はなく、区分を返すのは後の章の解法である。
このページは区分の読み方を先に示し、実測には scioxide-linalg の逆条件数の推定を使う。
失敗したときの分類と詳細の読み方は[エラーの分類と詳細ビュー](../errors-and-diagnostic-views/)にある。

## 3 つの区分と `ReliableEstimate`

`EstimateReliability` は、証明された限界ではない推定値を次の 3 つに分ける。

| 区分 | 根拠 |
|---|---|
| `Heuristic` | 較正された被覆の主張を持たない目安 |
| `ModelBased` | 文書化した数値モデルで裏付けた推定 |
| `StatisticallyCalibrated` | 文書化した統計的な手順で較正した推定 |

区分は推定の根拠を示すもので、精度の大小も、真の値を含むことの保証も示さない。
真の値を確実に含む区間が必要なら、[scioxide-validated](../../../scioxide-validated/) の包含が保証された区間を使う。
`EstimateReliability` は `#[non_exhaustive]` なので、照合には `_` の腕が要る。

`ReliableEstimate<S>` は有限の値と区分を組にした型である。
`ReliableEstimate::new(value, reliability)` は NaN と無限大を `NonFinite`（`NonFiniteOrigin::Input`）として拒み、値を `value()`、区分を `reliability()` で返す。
検査するのは有限性だけで、値の符号や大きさは制限しない。
この検査は[不正な入力に対する分類のセル](oxref:core-error-view-gallery)の最後の行で実行できる。

区分を付けて値を返すのは、次のような後の章の解法である。

- scioxide-linalg の `ConditionEstimate::reciprocal()` は逆条件数の推定を `ReliableEstimate` で返す。
  Schur 形の並べ替えのレポート `SchurReorderReport::separation()` も、推定を求めた場合に同じ型で分離の推定を返す。
- scioxide-poly の根の診断は、根の条件数と包含円板の半径の推定を `ReliableEstimate` で持つ。
- scioxide-special の誤差の推定値を持つ結果は、同じ区分を `reliability()` で返す。

最後に受理した状態に付く `PartialResultTrust` は、その状態がどの検査を通ったかを示す別の区分である（[エラー仕様と部分結果](../../../concepts/errors-and-partial-results/)）。

## 逆条件数の二つの推定とその根拠

区分の違いを、scioxide-linalg が返す逆条件数の二つの推定で見る。
逆条件数を $\mathrm{rcond}_p(A) = 1/(\lVert A \rVert_p \lVert A^{-1} \rVert_p)$ とする。
二つの関数の使い方は scioxide-linalg の[分解と解の受理を分ける](oxref:linalg-factorization-acceptance)と[特異値分解の計アルゴリズム](oxref:linalg-svd-method)にある。

`LuDecomposition::condition_estimate` は、LU 因子による $A$ と $A^{\mathsf H}$ の求解を数回だけ使う Hager–Higham の方法で $\lVert A^{-1} \rVert_1$ を推定し、求解 1 回あたり $O(n^2)$ の手間で $\mathrm{rcond}_1$ を返す（区分 `Heuristic`）。
$n \le 4$ では $\lVert A^{-1} \rVert_1$ を推定せずに厳密に計算する。
厳密な算術では、推定した値はある単位ベクトルへの $A^{-1}$ の作用の大きさなので $\lVert A^{-1} \rVert_1$ を超えず、$\mathrm{rcond}_1$ を過大に見積もる向きにだけずれる。
浮動小数点では因子の丸めが入るので、この向きも保証されない。

`SvdValues::condition_estimate` は計算した特異値の比 $\sigma_{\min}/\sigma_{\max}$ を $\mathrm{rcond}_2$ として返す（区分 `ModelBased`）。
後退安定な SVD は $\lVert E \rVert_2 \le c(n)\,u\,\lVert A \rVert_2$ を満たす $A + E$ の特異値を返すので、Weyl の不等式から $\lvert \hat\sigma_i - \sigma_i \rvert \le c(n)\,u\,\sigma_{\max}$ となる。
ここで $u = 2^{-53}$ は倍精度の単位丸め、$c(n)$ は次数とともにゆるやかに増える定数である。
したがって $\mathrm{rcond}_2$ の相対誤差はおよそ $c(n)\,u/\mathrm{rcond}_2$ で抑えられ、$\mathrm{rcond}_2$ が $u$ に近づくと推定は意味を失う。

## Hilbert 行列での実測

次のセルは $n$ 次の Hilbert 行列 $(H_n)_{ij} = 1/(i + j - 1)$（1 始まり）で二つの推定を求め、区分と推定値を厳密値と並べる。
入力は次数 $n$（2 から 12）である。
厳密値は、成分が整数になる逆行列の閉じた形から独立に計算する。
1 ノルムは列の絶対値和の最大で、2 ノルムは対称正定値行列の最大固有値をべき乗法で求めた値である。
確かめるのは、推定値と厳密値の比が 1 に近いことと、区分が上の説明どおりであることである。
Hilbert 行列の条件数と前進誤差の詳しい観察は scioxide-linalg の例題 [Hilbert 行列で見る条件数・前進誤差・混合精度反復改良](../../../scioxide-linalg/examples/hilbert-conditioning/)にある。

```rust
//| id: core-estimate-reliability
//| ref: core-estimate-reliability
//| title: 逆条件数の推定値と信頼性の区分を Hilbert 行列の厳密値と比べる
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg]
//| inputs:
//|   order: {"type":"range","label":"Hilbert 行列の次数 n [-]","description":"H_ij = 1/(i + j − 1)。n を上げると条件数が急に大きくなる。","min":2,"max":12,"step":1,"value":6}
//| cases:
//|   - {"id":"order-3","label":"n = 3","description":"κ₁(H₃) = 748 が厳密に求まり、LU の推定も厳密になる。","inputs":{"order":3}}
//|   - {"id":"order-12","label":"n = 12","description":"rcond₂ が単位丸めを下回り、推定と厳密値の比が 1 からずれる。","inputs":{"order":12}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"estimates","path":"/rows/0/2","equals":"Heuristic"}
//|       - {"artifact":"estimates","path":"/rows/0/4","approx":{"value":3.43994e-8,"rtol":1e-5}}
//|       - {"artifact":"estimates","path":"/rows/0/5","approx":{"value":1,"atol":1e-3}}
//|       - {"artifact":"estimates","path":"/rows/1/2","equals":"ModelBased"}
//|       - {"artifact":"estimates","path":"/rows/1/5","approx":{"value":1,"atol":1e-3}}
//|   - case: order-3
//|     expect:
//|       - {"artifact":"estimates","path":"/rows/0/4","approx":{"value":1.3368983957219251e-3,"rtol":1e-12}}
//|       - {"artifact":"estimates","path":"/rows/0/5","approx":{"value":1,"atol":1e-9}}
//|       - {"artifact":"estimates","path":"/rows/1/4","approx":{"value":1.90819e-3,"rtol":1e-5}}
//|       - {"artifact":"estimates","path":"/rows/1/5","approx":{"value":1,"atol":1e-9}}
//|   - case: order-12
//|     expect:
//|       - {"artifact":"estimates","path":"/rows/0/5","range":{"min":0.5,"max":1.5}}
//|       - {"artifact":"estimates","path":"/rows/1/5","range":{"min":0.5,"max":1.5}}
//|       - {"artifact":"estimates","path":"/rows/1/4","range":{"min":0,"max":1.1e-16}}
use scioxide_core::EstimateReliability;
use scioxide_linalg::{LuDecomposition, Matrix, SvdValues};

let n = order as usize;
// Hilbert 行列を行優先で並べる。0 始まりの添字では H_ij = 1/(i + j + 1)。
let entries = (0..n * n)
    .map(|k| 1.0 / (k / n + k % n + 1) as f64)
    .collect();
let a = Matrix::from_vec(n, n, entries).map_err(|e| e.to_string())?;
// 1 ノルムの逆条件数は LU 分解から、2 ノルムの逆条件数は特異値から推定する。
let lu = LuDecomposition::factor(&a)
    .and_then(|factor| factor.condition_estimate())
    .map_err(|e| e.to_string())?
    .reciprocal();
let sv = SvdValues::compute(&a)
    .and_then(|values| values.condition_estimate())
    .map_err(|e| e.to_string())?
    .reciprocal();

// 独立検算: 逆行列の整数の公式（添字は 1 始まり）
// (H⁻¹)_ij = (−1)^(i+j) (i+j−1) C(n+i−1, n−j) C(n+j−1, n−i) C(i+j−2, i−1)²。
// 二項係数は u64 で厳密に作る。
let binom = |p: u64, q: u64| (0..q).fold(1_u64, |c, t| c * (p - t) / (t + 1));
let m = n as u64;
let inverse = |i: usize, j: usize| {
    let (i, j) = (i as u64 + 1, j as u64 + 1);
    let sign = if (i + j) % 2 == 0 { 1.0 } else { -1.0 };
    let first = binom(m + i - 1, m - j) as f64;
    let second = binom(m + j - 1, m - i) as f64;
    let third = binom(i + j - 2, i - 1) as f64;
    sign * (i + j - 1) as f64 * first * second * third * third
};
let hilbert = |i: usize, j: usize| 1.0 / (i + j + 1) as f64;
// 1 ノルムは列の絶対値和の最大。
let norm1 = |f: &dyn Fn(usize, usize) -> f64| {
    (0..n)
        .map(|j| (0..n).map(|i| f(i, j).abs()).sum::<f64>())
        .fold(0.0, f64::max)
};
// 対称正定値なので 2 ノルムは最大固有値。べき乗法を 200 回反復する。
// 参照値の計算なので、平方根は f64 の標準関数を使う。
let norm2 = |f: &dyn Fn(usize, usize) -> f64| {
    let mut v = vec![1.0 / (n as f64).sqrt(); n];
    let mut lambda = 0.0;
    for _ in 0..200 {
        let w: Vec<f64> = (0..n)
            .map(|i| (0..n).map(|j| f(i, j) * v[j]).sum())
            .collect();
        lambda = w.iter().map(|x| x * x).sum::<f64>().sqrt();
        v = w.iter().map(|x| x / lambda).collect();
    }
    lambda
};
let exact1 = 1.0 / (norm1(&hilbert) * norm1(&inverse));
let exact2 = 1.0 / (norm2(&hilbert) * norm2(&inverse));

// 区分を列挙子の名前で表示する。列挙型は非網羅的なので `_` の腕を置く。
let class = |reliability: EstimateReliability| match reliability {
    EstimateReliability::Heuristic => "Heuristic",
    EstimateReliability::ModelBased => "ModelBased",
    EstimateReliability::StatisticallyCalibrated => "StatisticallyCalibrated",
    _ => "その他の区分",
};
let rows: Vec<_> = [
    ("LuDecomposition::condition_estimate", "1", lu, exact1),
    ("SvdValues::condition_estimate", "2", sv, exact2),
]
.into_iter()
.map(|(method, norm, estimate, exact)| {
    (
        method,
        norm,
        class(estimate.reliability()),
        estimate.value(),
        exact,
        estimate.value() / exact,
    )
})
.collect();
let sci5 = serde_json::json!({ "notation": "scientific", "significantDigits": 5 });
let fixed3 = serde_json::json!({ "fractionDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "推定した関数" },
    { "key": "1", "label": "ノルム p" },
    { "key": "2", "label": "区分" },
    { "key": "3", "label": "rcond の推定値 [-]", "type": "number", "format": sci5 },
    { "key": "4", "label": "rcond の厳密値（独立検算） [-]", "type": "number", "format": sci5 },
    { "key": "5", "label": "推定値 / 厳密値 [-]", "type": "number", "format": fixed3 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "estimates" })
);
```

既定の $n = 6$ ではLU の推定値 $3.4399 \times 10^{-8}$ と特異値の比 $6.6885 \times 10^{-8}$ が厳密値と 10 桁まで一致する（$\kappa_1 = 1/\mathrm{rcond}_1 \approx 2.91 \times 10^{7}$）。
$n = 3$ では厳密値が $\mathrm{rcond}_1 = 1/748$ で、LU の値は丸めの範囲でこれに一致する。
次数を上げると比は 1 から離れ、ずれは $n = 10$ で $10^{-4}$ 程度、$n = 11$ で $10^{-3}$ 程度になる。
$n = 12$ では $\mathrm{rcond}_2 \approx 5.8 \times 10^{-17}$ が $u \approx 1.1 \times 10^{-16}$ を下回り、特異値の比は厳密値より数 % 小さくなる（ブラウザでの実行では約 2 %）。
このとき LU の推定値と厳密値の差は 1 % 未満である。

ここでの厳密値は丸める前の Hilbert 行列の値である。
成分 $1/(i+j-1)$ を倍精度で格納しただけでも相対 $u$ の摂動が入るので、$\mathrm{rcond}$ が $u$ に近い次数では、このずれを推定のずれと区別できない。
`Heuristic` の推定がこの例で `ModelBased` より厳密値に近いことは区分の定義と矛盾しない。
区分は精度の順位ではなく、根拠の種類を表す。

## まとめ

推定値を受け取ったら、`value()` の数値と合わせて `reliability()` で根拠の区分を読む。
`Heuristic` は目安、`ModelBased` は文書化した数値モデル、`StatisticallyCalibrated` は文書化した統計的な手順に基づく推定で、どれも証明された限界ではない。
区分は精度の順位ではないので、推定がどこで意味を失うかは区分ではなく手法の誤差のモデルで判断する（特異値の比なら $\mathrm{rcond}_2$ が $u$ に近づくところ）。
真の値を含むことの保証が要る判断には scioxide-validated の包含区間を使う。
`EstimateReliability` は `#[non_exhaustive]` なので、`match` には `_` の腕を置く。
