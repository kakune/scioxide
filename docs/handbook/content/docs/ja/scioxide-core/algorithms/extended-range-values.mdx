倍精度の正の正規化数は約 $2.2 \times 10^{-308}$ から $1.8 \times 10^{308}$ まで、非正規化数を含めても最小は約 $4.9 \times 10^{-324}$ である。
大きな階乗、分配関数、確率の積のように、最終結果や途中の値がこの範囲を出る計算は珍しくない。
`scioxide-core` は指数を 64 ビット整数で別に持つ値の型を用意し、IEEE 型へ戻す（射影する）ときの規則を型ごとに定めている。
IEEE 754 の表現範囲と非正規化数は[浮動小数点と条件数](../../../concepts/floating-point-and-conditioning/)で説明している。

## 二進正規化数 `Scaled`

`Scaled<S>`（`S` は `f32` または `f64`）は、0 でない値を

$$
x = m \cdot 2^{e}, \qquad 1 \le |m| < 2, \quad e \in \mathbb{Z},\ -2^{63} \le e < 2^{63}
$$

で表す。
仮数 $m$ は `S` の精度を持ち、指数 $e$ は `i64` である。
符号付きゼロは符号を保ち、指数 0 を持つ。

この表現では、乗除算は仮数と指数を分けて計算できる。

$$
(m_1 2^{e_1})(m_2 2^{e_2}) = (m_1 m_2)\, 2^{e_1 + e_2}, \qquad 1 \le |m_1 m_2| < 4
$$

仮数の積は 1 ビットずらせば $[1, 2)$ に戻るので、正規化は一度の桁移動で済む。
加減算では指数の小さい側の仮数を $e_1 - e_2$ ビット右へずらしてから足す。
指数の差が仮数の桁数より 2 以上大きいと、小さい項は丸めで失われる（大きい項に吸収される）。
どの演算でも丸めは仮数の精度で起き、指数の大きさとは関係しない。
射影するまで IEEE のオーバーフローやアンダーフローは起きず、範囲に関する失敗は指数が `i64` を出る場合だけである。

値は三通りに作る。

- `from_value(x)` は有限な IEEE 値を、非正規化数や符号付きゼロも含めて厳密に分解する。
- `from_parts(x, e)` は $x \cdot 2^e$ を作る。
- `from_log(sign, ℓ)` は符号 $\pm 1$ と対数 $\ell$ から $\mathrm{sign} \cdot e^{\ell}$ を作る。
  結果が `S` の正規化数の範囲にあれば、誤差は 4 ULP 以内である。

`add`、`sub`、`mul`、`div`、`square`、`sqrt` は拡張範囲で計算し、結果の仮数を `S` の精度に一度丸める。
`shifted(k)` は $2^k$ 倍を厳密に返す。
`difference_of_products(b, c, d)` は $x b - c d$ の厳密な値を一度丸める。
打ち消しを先に計算してから指数の範囲を検査するので、途中の積だけが `i64` の範囲を出る場合も失敗しない。
`ln_abs()` は射影せずに $\ln |x|$ を `S` の値で返し、その絶対誤差は $16\,\varepsilon\,(1 + |\ln |x||)$ 以下である（1 の近くでの相対誤差の保証ではない）。
0 による除算、0 の `ln_abs`、負の値の `sqrt` は `DomainError` になる。

すべての演算は固定長のスタック領域で行い、失敗時も含めてヒープを確保しない。
`Scaled` の加減算は仮数の精度で丸めるので、`RangeAccumulator` のような厳密な和の仕様はない。

### 射影と範囲のエラー

拡張範囲の値を IEEE 型に戻す方法は二つある。
`round()` と `round_to::<R>()` は一度の最近接偶数丸めで射影し、段階的アンダーフローで非正規化数や符号付きゼロになることを許す。
`try_value()` と `try_value_to::<R>()` は、0 でない値が 0 に丸められる場合をエラーにする。
非正規化数に丸められるだけなら、どちらもエラーにしない。
範囲に関するエラーは `kind()` が `NumericalInstability` になり、詳細ビュー `view()` の `NumericalIssue` で三つに分かれる。

| `NumericalIssue` | 起きる場面 |
|---|---|
| `Overflow` | 射影した値が有限の最大値を超える |
| `Underflow` | `try_value` で 0 でない値が 0 に丸められる |
| `ExponentOutOfRange` | 正規化した指数が `i64` に収まらない（IEEE への射影とは別） |

次のセルは $n!$ を `Scaled::mul` で計算し、`ln_abs()` で得た $\ln n!$ を Stirling 級数

$$
\ln n! \approx n \ln n - n + \tfrac{1}{2}\ln(2\pi n) + \frac{1}{12 n} - \frac{1}{360 n^3}
$$

と比べる。
級数の打ち切り誤差は次の項 $1/(1260\, n^5)$ 程度で、$n \ge 10$ では $10^{-8}$ 以下である。
入力は $n$（10 から 500、10 刻み）である。
1 つ目の表は $n! = m \cdot 2^e$ の仮数と指数、二つの $\ln n!$、その差、`ln_abs` の誤差の限界を示す。
2 つ目の表は $n!$ と $1/n!$ を `round()` と `try_value()` で射影し、失敗した場合の `NumericalIssue` を列挙子の名前で示す。
$n > 170$ では $n!$ が倍精度の最大値を超え、$n \ge 178$ では $1/n!$ が最小の非正規化数の半分より小さくなる。

```rust
//| id: core-scaled-factorial
//| ref: core-scaled-factorial
//| title: n! を拡張範囲で計算して Stirling 級数と比べる
//| run: reactive
//| crates: [scioxide-core]
//| inputs:
//|   n_eval: {"type":"range","label":"階乗の n [-]","description":"n > 170 で n! は倍精度の範囲を超える。","min":10,"max":500,"step":10,"value":200}
//| cases:
//|   - {"id":"small","label":"n = 10","description":"n! も 1/n! も倍精度で表せる。Stirling 級数の打ち切り誤差が見える。","inputs":{"n_eval":10}}
//|   - {"id":"largest-finite","label":"n = 170","description":"n! が倍精度に収まる最大の n。","inputs":{"n_eval":170}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"factorial","path":"/rows/0/2","equals":1245}
//|       - {"artifact":"factorial","path":"/rows/0/3","approx":{"value":863.2319871924054,"rtol":1e-13}}
//|       - {"artifact":"factorial","path":"/rows/0/5","range":{"min":0,"max":1e-11}}
//|       - {"artifact":"projection","path":"/rows/0/1","equals":null}
//|       - {"artifact":"projection","path":"/rows/0/2","equals":"Overflow"}
//|       - {"artifact":"projection","path":"/rows/1/1","equals":0}
//|       - {"artifact":"projection","path":"/rows/1/3","equals":"Underflow"}
//|   - case: small
//|     expect:
//|       - {"artifact":"factorial","path":"/rows/0/3","approx":{"value":15.104412573075516,"rtol":1e-14}}
//|       - {"artifact":"factorial","path":"/rows/0/5","range":{"min":1e-9,"max":1e-8}}
//|       - {"artifact":"projection","path":"/rows/0/1","equals":3628800}
//|       - {"artifact":"projection","path":"/rows/1/3","equals":"なし"}
//|   - case: largest-finite
//|     expect:
//|       - {"artifact":"projection","path":"/rows/0/1","approx":{"value":7.257415615307994e306,"rtol":1e-13}}
//|       - {"artifact":"projection","path":"/rows/0/2","equals":"なし"}
//|       - {"artifact":"projection","path":"/rows/1/3","equals":"なし"}
use scioxide_core::{SciOxideError, SciOxideErrorView, NumericalIssue, Scaled};

let n = n_eval as usize;
let mut factorial = Scaled::ONE;
for k in 1..=n {
    let factor = Scaled::from_value(k as f64).map_err(|e| e.to_string())?;
    factorial = factorial.mul(factor).map_err(|e| e.to_string())?;
}
let ln_factorial = factorial.ln_abs().map_err(|e| e.to_string())?;

// 独立な参照値: Stirling 級数（f64 の固有メソッドで計算）。
let x = n as f64;
let stirling = x * x.ln() - x + 0.5 * (2.0 * core::f64::consts::PI * x).ln() + 1.0 / (12.0 * x)
    - 1.0 / (360.0 * x.powi(3));
// ln_abs の絶対誤差の限界 16 ε (1 + |ln n!|)。
let ln_bound = 16.0 * f64::EPSILON * (1.0 + ln_factorial.abs());
let digits = serde_json::json!({ "significantDigits": 15 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let factorial_columns = serde_json::json!([
    { "key": "0", "label": "n [-]", "type": "integer" },
    { "key": "1", "label": "仮数 m [-]", "type": "number", "format": digits },
    { "key": "2", "label": "二進指数 e [-]", "type": "integer" },
    { "key": "3", "label": "ln n!（ln_abs）[-]", "type": "number", "format": digits },
    { "key": "4", "label": "ln n!（Stirling 級数）[-]", "type": "number", "format": digits },
    { "key": "5", "label": "差の絶対値 [-]", "type": "number", "format": sci3 },
    { "key": "6", "label": "ln_abs の誤差の限界 [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    factorial_columns,
    vec![(
        n as u32,
        factorial.significand(),
        factorial.exponent(),
        ln_factorial,
        stirling,
        (ln_factorial - stirling).abs(),
        ln_bound,
    )],
    metadata = serde_json::json!({ "id": "factorial" })
);

// 射影の失敗を view() の NumericalIssue で分類し、列挙子の名前で示す。
let issue_name = |error: SciOxideError| match error.view() {
    SciOxideErrorView::NumericalInstability {
        issue: NumericalIssue::Overflow,
        ..
    } => Ok("Overflow"),
    SciOxideErrorView::NumericalInstability {
        issue: NumericalIssue::Underflow,
        ..
    } => Ok("Underflow"),
    _ => Err(error.to_string()),
};
let inverse = Scaled::ONE.div(factorial).map_err(|e| e.to_string())?;
let mut projections = Vec::new();
for (name, value) in [("n!", factorial), ("1/n!", inverse)] {
    // round() は段階的アンダーフローを許し、try_value() は 0 への丸めを拒否する。
    let (rounded, round_issue) = match value.round() {
        Ok(rounded) => (Some(rounded), "なし"),
        Err(error) => (None, issue_name(error)?),
    };
    let try_issue = match value.try_value() {
        Ok(_) => "なし",
        Err(error) => issue_name(error)?,
    };
    projections.push((name, rounded, round_issue, try_issue));
}
let sci7 = serde_json::json!({ "notation": "scientific", "significantDigits": 7 });
let projection_columns = serde_json::json!([
    { "key": "0", "label": "量" },
    {
        "key": "1",
        "label": "round() の値 [-]",
        "type": "number",
        "format": sci7,
        "nullText": "失敗"
    },
    { "key": "2", "label": "round() の NumericalIssue" },
    { "key": "3", "label": "try_value() の NumericalIssue" }
]);
emit_table_with_columns!(
    projection_columns,
    projections,
    metadata = serde_json::json!({ "id": "projection" })
);
```

既定の $n = 200$ では $200! \approx 1.3018 \times 2^{1245}$ で、`ln_abs` の $\ln 200! = 863.2319871924$ は Stirling 級数と 13 桁一致する。
級数の打ち切り誤差は $1/(1260 \cdot 200^5) \approx 2.5 \times 10^{-15}$ で、この値の近くの倍精度数の間隔 $1.1 \times 10^{-13}$ より小さい。
射影では$n!$ は `round()` も `try_value()` も `Overflow` で失敗する。
$1/n!$ は `round()` が 0 を返し、`try_value()` は `Underflow` で失敗する。

$n = 10$ に下げると $n!$ の `round()` は 3628800 を返し、Stirling 級数との差 $7.9 \times 10^{-9}$ は級数の打ち切り誤差 $1/(1260 \cdot 10^5)$ にあたる。
$n = 170$ では $170! \approx 7.257416 \times 10^{306}$ も $1/170! \approx 1.38 \times 10^{-307}$ も倍精度に収まり、どの射影も成功する。

## 補償付きの和 `ScaledAccumulator`

`Scaled` 同士の加減算では、大きな項に加えた小さな項は仮数の精度で丸められて失われうる。
`ScaledAccumulator<S>` は和と補正項の二つの `Scaled` を持ち、Neumaier の補償和で丸めで失われた下位の値を補正項に残す。
後の項が和を打ち消すと、補正項に残った値が結果に現れる。
`add_scaled`、`sub_scaled`、`add_value` は、失敗すると和も補正項も変えない。
`total()` は和と補正項を足して一度丸めた `Scaled` を返し、`round()` はそれを `S` へ射影する。

積の `add_product` は丸めた積を加え、補正項も `S` の精度しか持たない。
そのため和は厳密ではなく、符号や正しい丸めは保証されない。
厳密な和が必要なら `RangeAccumulator` を使う。
`ScaledAccumulator` は、倍精度の範囲を超える値の和を少ないメモリ領域で補償したいときに使う。

`absorbs(exponent)` は、正規化した指数が `exponent` 以下の項をいくら加えても、和と補正項のビットが変わらないかを判定する。
和と補正項がともに 0 でなく、どちらの指数も `exponent` を仮数の桁数 $+ 2$ より大きく上回るときだけ `true` を返す。
上で見た吸収の条件を、和と補正項の両方について余裕を持たせて検査するので、級数の残りの項をまとめて省くときの判定に使える。
`false` は吸収されないことを意味しない。

次のセルは $2^{e} + 1 - 2^{e}$ を三通りに計算する。
入力は二進指数 $e$（50 から 2000、50 刻み）で、数学的な値は $e$ によらず 1 である。
表は倍精度のままの計算、`Scaled` の加減算、`ScaledAccumulator` の結果と、`ScaledAccumulator` が最後に持つ和と補正項を示す。
$e > 1023$ では $2^{e}$ 自体が倍精度で表せないので、倍精度の計算は $\infty - \infty$ になり、表では値のない欄になる。

```rust
//| id: core-scaled-accumulator-vs-exact
//| ref: core-scaled-accumulator-vs-exact
//| title: 大きな項に埋もれた 1 を補償和で取り戻す
//| run: reactive
//| crates: [scioxide-core]
//| inputs:
//|   large_exponent: {"type":"range","label":"大きな項の二進指数 e [-]","description":"大きな項を 2^e とする。","min":50,"max":2000,"step":50,"value":500}
//| cases:
//|   - {"id":"representable","label":"e = 50","description":"2^50 + 1 が 53 ビットに収まり、どの方法も 1 を返す。","inputs":{"large_exponent":50}}
//|   - {"id":"beyond-f64","label":"e = 1100","description":"2^e が倍精度で表せず、f64 の計算は ∞ − ∞ になる。","inputs":{"large_exponent":1100}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"sums","path":"/rows/0/0","equals":0}
//|       - {"artifact":"sums","path":"/rows/0/1","equals":0}
//|       - {"artifact":"sums","path":"/rows/0/2","equals":1}
//|       - {"artifact":"sums","path":"/rows/0/4","equals":1}
//|   - case: representable
//|     expect:
//|       - {"artifact":"sums","path":"/rows/0/0","equals":1}
//|       - {"artifact":"sums","path":"/rows/0/1","equals":1}
//|       - {"artifact":"sums","path":"/rows/0/2","equals":1}
//|   - case: beyond-f64
//|     expect:
//|       - {"artifact":"sums","path":"/rows/0/0","equals":null}
//|       - {"artifact":"sums","path":"/rows/0/1","equals":0}
//|       - {"artifact":"sums","path":"/rows/0/2","equals":1}
use scioxide_core::{RealScalar, Scaled, ScaledAccumulator};

let exponent = large_exponent as i64;
let big = Scaled::from_parts(1.0_f64, exponent).map_err(|e| e.to_string())?;

// 比較用: f64 のまま計算する（e > 1023 では 2^e が inf になり、差は NaN になる）。
let big_f64 = RealScalar::powi(2.0_f64, large_exponent as i32);
let naive = (big_f64 + 1.0) - big_f64;
let naive = naive.is_finite().then_some(naive);

// Scaled の加減算: 1 は 2^e の仮数の精度で丸められる。
let direct = big
    .add(Scaled::ONE)
    .map_err(|e| e.to_string())?
    .sub(big)
    .map_err(|e| e.to_string())?
    .round()
    .map_err(|e| e.to_string())?;

// 補償和: 失われた 1 が補正項に残る。
let mut compensated = ScaledAccumulator::ZERO;
compensated.add_scaled(big).map_err(|e| e.to_string())?;
compensated
    .add_scaled(Scaled::ONE)
    .map_err(|e| e.to_string())?;
compensated.sub_scaled(big).map_err(|e| e.to_string())?;
let [sum, correction] = compensated.parts();

let digits = serde_json::json!({ "significantDigits": 6 });
let columns = serde_json::json!([
    {
        "key": "0",
        "label": "f64 [-]",
        "type": "number",
        "format": digits,
        "nullText": "NaN（∞ − ∞）"
    },
    { "key": "1", "label": "Scaled の加減算 [-]", "type": "number", "format": digits },
    { "key": "2", "label": "ScaledAccumulator の round() [-]", "type": "number", "format": digits },
    { "key": "3", "label": "最後の和 [-]", "type": "number", "format": digits },
    { "key": "4", "label": "最後の補正項 [-]", "type": "number", "format": digits }
]);
emit_table_with_columns!(
    columns,
    vec![(
        naive,
        direct,
        compensated.round().map_err(|e| e.to_string())?,
        sum.round().map_err(|e| e.to_string())?,
        correction.round().map_err(|e| e.to_string())?,
    )],
    metadata = serde_json::json!({ "id": "sums" })
);
```

既定の $e = 500$ では f64 と `Scaled` の加減算はどちらも 0 を返す。
`ScaledAccumulator` は 1 を返し、最後の和は 0、補正項は 1 である。
$2^{500}$ に 1 を足したときに丸めで失われた 1 が補正項に残り、$2^{500}$ を引いた後に結果として現れる。

$e = 50$ では $2^{50} + 1$ が 53 ビットの仮数に収まるので、三つの方法がすべて 1 を返し、補正項は 0 のままである。
$e = 1100$ にすると f64 の計算は $\infty - \infty$ で `NaN` になるが、`Scaled` と `ScaledAccumulator` の結果は $e = 500$ と同じである。

## 成分ごとの尺度 `ScaledValue` と共有指数 `ProjectiveValue`

複素数の実部と虚部の大きさが大きく異なると、一つの指数で両方を表すことはできない。

- `ScaledValue<V>`（`V` は実数または複素数）は成分ごとに独立した `Scaled` を持つ。
  `from_value` は有限な IEEE 値の全ビットを保ち、`try_value` で元のビットに戻せる。
  実数の場合、虚部は $+0$ に固定される。
  複素数の商は射影前に成分ごとの相対誤差 $\gamma_3 = 3u/(1-3u)$ 以内である（$u = \varepsilon/2$ は単位丸め）。
- `ProjectiveValue<V>` は全成分が一つの二進指数を共有する座標 $\mathbf{s} \cdot 2^{k}$ で、最大成分の大きさが $[1, 2)$ に入る。
  `ScaledValue::try_projective()` でだけ作られ、共有指数に合わせたときに 0 でない仮数のビットが一つでも失われる場合は変換を拒否する。
  この表現で算術は行わない。
- `ScaledValue::scale_exponent()` は 0 でない成分の指数の最大を返し、`scaled_magnitude()` はその指数 $k$ に対する $2^{k}$ を単位としたノルムを返す。
  ノルムに基づく誤差見積りに使う。

`try_projective()` の拒否は `kind()` が `NumericalInstability` で、`NumericalIssue` は二つに分かれる。
0 でない成分の下位のビットが落ちる場合は `LossOfSignificance`、0 でない成分が 0 になる場合は `Underflow` である。

次のセルは実部 $2^{d}$、虚部 $1/3$（倍精度に丸めた値）の複素数を `ScaledValue` で作り、`try_projective()` を試す。
入力は実部と虚部の指数の差 $d$（0 から 1100、50 刻み）である。
共有指数は $d$ になり、虚部の仮数は $2^{-d}/3$ に縮む。
$1/3 \approx 1.33 \times 2^{-2}$ なので、$d \le 1020$ なら虚部の 53 ビットは倍精度の正規化数に収まり、往復しても同じ値に戻る。
$d > 1020$ では非正規化数になって下位のビットが失われるので、変換は拒否される。
1 つ目の表は成分ごとの仮数と指数、2 つ目の表は変換の結果で、拒否された場合は共有指数と仮数の欄が空になり、`NumericalIssue` の名前が入る。

```rust
//| id: core-projective-frame
//| ref: core-projective-frame
//| title: 成分の尺度差と共有指数への変換
//| run: reactive
//| crates: [scioxide-core]
//| inputs:
//|   exponent_gap: {"type":"range","label":"実部と虚部の指数の差 d [-]","description":"実部を 2^d、虚部を 1/3 とする。","min":0,"max":1100,"step":50,"value":1000}
//| cases:
//|   - {"id":"lost-bits","label":"d = 1050","description":"虚部の仮数が非正規化数になり、下位のビットが落ちる。","inputs":{"exponent_gap":1050}}
//|   - {"id":"vanished","label":"d = 1100","description":"虚部の仮数が 0 に丸められる。","inputs":{"exponent_gap":1100}}
//|   - {"id":"same-scale","label":"d = 0","description":"実部 1 と虚部 1/3 は同じ尺度にある。","inputs":{"exponent_gap":0}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"components","path":"/rows/0/3","equals":-2}
//|       - {"artifact":"components","path":"/rows/0/4","equals":1000}
//|       - {"artifact":"projective","path":"/rows/0/0","equals":1000}
//|       - {"artifact":"projective","path":"/rows/0/1","approx":{"value":3.110878728344063e-302,"rtol":1e-14}}
//|       - {"artifact":"projective","path":"/rows/0/2","equals":"一致"}
//|       - {"artifact":"projective","path":"/rows/0/3","equals":"なし"}
//|   - case: lost-bits
//|     expect:
//|       - {"artifact":"projective","path":"/rows/0/0","equals":null}
//|       - {"artifact":"projective","path":"/rows/0/3","equals":"LossOfSignificance"}
//|   - case: vanished
//|     expect:
//|       - {"artifact":"projective","path":"/rows/0/0","equals":null}
//|       - {"artifact":"projective","path":"/rows/0/3","equals":"Underflow"}
//|   - case: same-scale
//|     expect:
//|       - {"artifact":"projective","path":"/rows/0/0","equals":0}
//|       - {"artifact":"projective","path":"/rows/0/1","approx":{"value":0.3333333333333333,"rtol":1e-15}}
//|       - {"artifact":"projective","path":"/rows/0/2","equals":"一致"}
use scioxide_core::{Complex64, SciOxideErrorView, NumericalIssue, ScaledValue};

let d = exponent_gap as i64;
let third = 1.0_f64 / 3.0;
// 実部 1·2^d と虚部 (1/3)·2^0 を独立した指数で保持する。
let value = ScaledValue::from_component_parts(Complex64::new(1.0, third), [d, 0])
    .map_err(|e| e.to_string())?;
let [re_exp, im_exp] = value.component_exponents();
let significands = value.component_significands();
let digits = serde_json::json!({ "significantDigits": 17 });
let component_columns = serde_json::json!([
    { "key": "0", "label": "実部の仮数 [-]", "type": "number", "format": digits },
    { "key": "1", "label": "実部の指数 [-]", "type": "integer" },
    { "key": "2", "label": "虚部の仮数 [-]", "type": "number", "format": digits },
    { "key": "3", "label": "虚部の指数 [-]", "type": "integer" },
    { "key": "4", "label": "scale_exponent() [-]", "type": "integer" }
]);
emit_table_with_columns!(
    component_columns,
    vec![(
        significands.re,
        re_exp,
        significands.im,
        im_exp,
        value.scale_exponent(),
    )],
    metadata = serde_json::json!({ "id": "components" })
);

let projective = match value.try_projective() {
    Ok(frame) => {
        // 共有指数から元の成分へ戻し、虚部のビットが保たれたか確かめる。
        let back = frame.into_scaled().map_err(|e| e.to_string())?;
        let same = back.imaginary().significand() == value.imaginary().significand()
            && back.imaginary().exponent() == value.imaginary().exponent();
        let round_trip = if same { "一致" } else { "不一致" };
        (
            Some(frame.exponent()),
            Some(frame.significand().im),
            round_trip,
            "なし",
        )
    }
    Err(error) => match error.view() {
        SciOxideErrorView::NumericalInstability {
            issue: NumericalIssue::LossOfSignificance,
            ..
        } => (None, None, "変換なし", "LossOfSignificance"),
        SciOxideErrorView::NumericalInstability {
            issue: NumericalIssue::Underflow,
            ..
        } => (None, None, "変換なし", "Underflow"),
        _ => return Err(error.to_string()),
    },
};
let sci17 = serde_json::json!({ "notation": "scientific", "significantDigits": 17 });
let projective_columns = serde_json::json!([
    { "key": "0", "label": "共有指数 k [-]", "type": "integer", "nullText": "拒否" },
    {
        "key": "1",
        "label": "共有指数での虚部の仮数 [-]",
        "type": "number",
        "format": sci17,
        "nullText": "拒否"
    },
    { "key": "2", "label": "往復した虚部" },
    { "key": "3", "label": "拒否の NumericalIssue" }
]);
emit_table_with_columns!(
    projective_columns,
    vec![projective],
    metadata = serde_json::json!({ "id": "projective" })
);
```

既定の $d = 1000$ では共有指数 1000 の座標が作られ、虚部の仮数は $3.11 \times 10^{-302}$ になる。
往復した虚部は元の仮数と指数に一致する。
$d = 1050$ に上げると虚部の仮数が非正規化数の範囲に入り、`try_projective()` は `LossOfSignificance` で変換を拒否する。
$d = 1100$ では虚部の仮数が 0 に丸められるので、拒否の理由は `Underflow` に変わる。
$d = 0$ では共有指数は 0 で、虚部の仮数は $1/3$ を丸めた倍精度数そのものである。
どの $d$ でも、成分ごとの指数を持つ `ScaledValue` は実部と虚部を厳密に保持している。

## 対数表現 `LogValue`

`LogValue<V, R>` は 0 でない値を、大きさ 1 の位相 $p$（実数なら符号 $\pm 1$、複素数なら単位複素数）と有限な自然対数 $\ell = \ln |x|$ の組で $x = p\,e^{\ell}$ と表し、0 は別の状態として持つ。
位相は成分ごとに指数を持つので、0 でない小さな成分も失われない。

- `from_log(phase, log_magnitude)` は、実数の位相が $\pm 1$ でない場合と、複素数の位相の絶対値が 1 から $16\varepsilon$ を超えて離れている場合を `InvalidInput` として拒否する。
- `from_value(x)` は有限な IEEE 値から必ず作れるが、対数は丸めた近似値になる。
  `ScaledValue::from_value` のような厳密な変換ではない。
- `log_magnitude()` は 0 のときだけ `None` を返す。
  `LogValue::ZERO` は空の和や厳密に打ち消し合った和を表し、無限大の対数を保存しない。
- `round()` は $e^{\ell}$ を単独では作らず、成分ごとに一度の尺度調整で IEEE 値へ射影する。
  そのため $\ell$ が倍精度の最大値の対数を少し超えていても、各成分が表せれば射影できる。
  `try_value()` は 0 でない成分が 0 に丸められる場合を拒否する。

`LogValue` は `logsumexp_value` と `weighted_logsumexp` の戻り値で、符号付きの重みで打ち消し合った和を厳密な 0 として返すために使われる。
詳しくは[対数和・重み付き和・正規化](../logarithmic-reductions/)で扱う。

## 値と導関数の組 `ValueAndDerivative`

`ValueAndDerivative<V, D>` は、関数値 $f(x)$ と導関数 $f'(x)$ を組にして持つ型である。
`new(value, derivative)` で作り、`value()` と `derivative()` で参照を、`into_parts()` で `(V, D)` の組を取り出す。
値と導関数の型は別々に選べるので、例えば値を `Scaled<f64>`、導関数を `f64` で持てる。
組を作るときに値の検証は行わず、型自体は数値の仕様を持たない。
値と導関数の精度は、この型を返す関数の仕様による。

## まとめ

倍精度の範囲を超える途中の値や結果は `Scaled` で計算し、`ln_abs()` で対数として取り出すか、`round()` / `try_value()` で射影するかを用途で選ぶ。
射影の失敗は `kind()` が `NumericalInstability` で、`view()` の `Overflow`、`Underflow`、`ExponentOutOfRange` からどの段階で範囲を超えたかを読み分ける。
大きさの異なる値の和は、厳密さが必要なら `RangeAccumulator`、範囲の広い値の補償和で足りるなら `ScaledAccumulator` を使う。
成分の尺度が大きく異なる複素数は `ScaledValue` で保持し、共有指数の `ProjectiveValue` へは情報が失われない場合だけ変換できる。
