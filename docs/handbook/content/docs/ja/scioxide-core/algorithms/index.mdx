`scioxide-core` のアルゴリズムは方程式を解くためのものではなく、他のクレートの解法が共通に使う表現・累積・変換・仕様の部品である。
このページは各ページで共通に使う記号と規則をまとめ、どのページで何を扱うかを示す。

## 記号

| 記号 | 意味 |
|---|---|
| $\varepsilon$ | 機械イプシロン（`RealScalar::EPSILON`）。1 とその次に大きい浮動小数点数の間隔で、倍精度で $2^{-52}$、単精度で $2^{-23}$ |
| $u = \varepsilon / 2$ | 単位丸め。最近接偶数丸め一回の相対誤差の上限 |
| $\gamma_k = k u / (1 - k u)$ | $k$ 回の丸めが積み重なった相対誤差の上限（$k u < 1$） |
| $\eta$ | 最小の正の非正規化数（`RealScalar::MIN_SUBNORMAL`）。倍精度で $2^{-1074}$、単精度で $2^{-149}$ |
| ulp | 厳密な値での隣接する浮動小数点数の間隔。非正規化数の範囲では $\eta$ |
| $\tau_{\mathrm{abs}}, \tau_{\mathrm{rel}}$ | 絶対許容誤差と相対許容誤差 |

$\gamma_k$ は、相対誤差が $u$ 以下の丸めを $k$ 回重ねたときの $(1 + u)^k - 1 \le \gamma_k$ という評価から現れる（Higham, *Accuracy and Stability of Numerical Algorithms*, 第 3 章）。
浮動小数点数の構造と条件数の一般論は[浮動小数点と条件数](../../concepts/floating-point-and-conditioning/)を参照する。

## 精度の保証の種類

`scioxide-core` の関数は結果の精度を次のどれかの形で約束する。
同じ「誤差が小さい」でも意味が異なるので、区別する。

| 種類 | 意味 | 例 |
|---|---|---|
| 一回の丸め（0 ULP） | 数学的な値を一度だけ最近接偶数丸めした結果 | `checked_sum`、`checked_difference_of_products`、`RealScalar::sqrt` |
| $N$ ULP | 試験で確かめた精度の保証。$\lvert \text{計算値} - \text{真値} \rvert \le N \cdot \mathrm{ulp}$ | 超越関数 4 ULP、実数の安定変換と実数の `logsumexp` 16 ULP |
| 演算回数による限界 | $\gamma_k$ と $\eta$ で書いた相対誤差の上限 | `checked_scaled_norm`、`checked_float_product_factors` |
| 残差の限界 | 結果を方程式に代入した残差の上限。前進誤差の保証ではない | `checked_quadratic_roots` |
| 条件数や増大因子に比例する限界 | 問題の条件数 $\kappa$ や関数ごとの増大因子に比例して広がる上限 | 符号付き・複素の重みの `weighted_logsumexp`、複素数の安定変換 |

区間演算による真の値を含む区間は `scioxide-core` では扱わず、[scioxide-validated](../../scioxide-validated/) が提供する。

## 失敗と出力の規則

- 非有限な入力は `NonFinite`、有限な引数が数学的な定義域の外にある場合は `DomainError`、構造的に不正な入力は `InvalidInput` で返る。
  有限な入力から表現できない結果ができた場合は `NumericalInstability`（`Overflow` など）である。
- 成功した結果は NaN にならない。
  無限大になるのは、空の入力に対する `logsumexp` の $-\infty$ のように、文書化した数学的な極限だけである。
- 判定関数（許容誤差の比較など）は正当な入力に対する「満たさない」を `Ok(false)` で返し、エラーにしない。
- 借用した出力に書く関数（`*_into`）は、すべての入力を検査してから書き込み、完全な結果を書くか、失敗して出力を変えないかのどちらかになる。
  作業用のバッファーは失敗時に内容が変わることがあるが、そのまま再利用できる。
- スカラーを返す関数（`checked_sum`、`logsumexp`、`sin_pi` など）と、十分な大きさの作業領域を受け取る関数はヒープを確保しない。
  `Vec` を返す関数（`softmax` など）や、表・置換・彩色を所有する型の構築は確保を行い、その失敗を `AllocationFailure` で返す。

エラーと部分結果の考え方は[エラー仕様と部分結果](../../concepts/errors-and-partial-results/)にまとめてある。
`SciOxideErrorKind` の各分類と、`view()` で読める詳細は[エラーの分類と詳細ビュー](errors-and-diagnostic-views/)で扱う。

## まとめ

アルゴリズムページを読むときは、まず結果の精度がどの種類の仕様（一回の丸め、$N$ ULP、演算回数による限界、残差の限界、条件数や増大因子に比例する限界）で示されているかを確かめる。
失敗は `kind()` の分類で区別される。
借用した出力に書く関数は失敗時に出力を変えないので、出力が新しい値かどうかは `Result` で判断する。
ほかの章の解法を使うだけなら、許容誤差の判定と求解の回数の集計の 2 ページを先に読み、必要に応じて算術・拡張範囲値・対数和のページへ進む。
自分で作用素や解法を実装するなら、借用レイアウト、作用素プロトコル、実行方針、入れ子の求解のページで、作業領域と出力と回数の集計の仕様を確かめる。
エラーを受け取って原因を調べるときは、エラーの分類と詳細ビューのページから読み始める。
