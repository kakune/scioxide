疎行列を扱うアルゴリズムは値より先に、どの位置に要素があるかという構造を必要とする。
並べ替えや、疎なヤコビ行列を求める評価の Plan は、値を読まずに構造だけから決められる。
`scioxide-core` は、非零構造 `StructuralPattern`、三角格納の向き `Triangle` と対角の表し方 `DiagonalKind`、検証済みの彩色 `ColoringSchedule` を、複数のクレートが共有する型として提供する。
彩色を求めるアルゴリズムは scioxide-sparse にあり、`scioxide-core` は渡された彩色が衝突しないことを検証して保持する。
行列を持たずに積だけを使う作用素のプロトコルは[作用素プロトコルとクロージャ作用素](../operator-protocols-and-structure/)で扱う。

## 正準 CSR の疎構造

`StructuralPatternView`（借用）と `StructuralPattern`（所有）は、圧縮行格納（CSR）の非零構造を表す。
行 $i$ の列番号は `col_indices[row_ptr[i] .. row_ptr[i + 1]]` に並ぶ。
保存された位置は、値が 0 でも構造の一部とみなす。
構築時に次を検査し、満たさなければ `InvalidInput`（理由は `InvalidInputReason::Malformed`）を返す。

- 行の開始位置の配列 `pointers` の長さが行数 $+ 1$ で、先頭が 0、末尾が列番号の配列 `indices` の長さに等しい。
- `pointers` が非減少である。
- 各行の列番号が列数未満で、重複なく昇順に並ぶ。

行数 $+ 1$ が `usize` に収まらなければ `SizeOverflow` を返す。
列番号が各行で昇順に 1 通りに並ぶので、同じ構造は同じ配列で表される。
`StructuralPattern` の等値比較では、形とすべての番号を厳密に比べる。
`view()` は借用のビューを、`StructuralPatternView::to_owned()` は所有する複製を返す。
`try_reserve` と `try_assign` は確保済みのメモリ領域を再利用して別の構造を写し取るために使う。

三角行列を格納する側は、どちらの半分を格納したかを `Triangle`（`Lower` は対角とその下、`Upper` は対角とその上）で、対角の表し方を `DiagonalKind` で示す。
`Triangle` は転置や随伴を適用する前の格納された半分を指す。
`DiagonalKind::Explicit` は対角の値を格納し、三角系の求解は対角要素が 0 でないことを要求する。
`DiagonalKind::Unit` は対角を 1 とみなし、値を読まない。
このとき疎な三角格納は対角の要素を持ってはならず、密な格納と圧縮（packed）格納は対角の位置を残すがその値を読まない。
2 つの列挙型はscioxide-sparse の `SparseTriangular` や疎な対称分解と、scioxide-linalg の三角・対称の格納が共有する。

## ヤコビ行列の列彩色

$m \times n$ の疎なヤコビ行列 $J$ を有限差分や前進モードの自動微分で求めるとき、素朴には単位ベクトル $e_0, \ldots, e_{n-1}$ の方向に $n$ 回評価する。
同じ行に非零を持たない列どうしは、方向をまとめて 1 回で評価しても、各非零要素の寄与が混ざらない。
列を色 $0, \ldots, p - 1$ に分け、同じ色の列がどの行でも非零を共有しないようにすれば、色 $k$ の列の集合 $C_k$ についての和

$$
d_k = \sum_{j \in C_k} e_j
$$

の方向の評価 $J d_k$ から、色 $k$ のすべての列の非零要素を取り出せる。
行 $i$ で構造上の非零を持つ $C_k$ の列は高々 1 つなので、その列を $j$ とすれば $(J d_k)_i = J_{ij}$ である。
評価は $p$ 回で済む。
この方法は Curtis–Powell–Reid の列圧縮と呼ばれ、列を頂点とするグラフの彩色（二部グラフの部分的な距離 2 彩色）にあたる。
1 つの行の非零の列はすべて異なる色が必要なので、色の数 $p$ は行あたりの非零の最大数以上になる。

`ColoringSchedule::new(pattern, kind, colors)` は、列ごとに 1 つの色番号を受け取り、その彩色が衝突しないことを検証して、色ごとの列を昇順に並べたグループを作る。
彩色そのものを求めるアルゴリズムは持たず、呼び出し側が渡した彩色を検査する。
彩色は scioxide-sparse の `derivative_coloring` と `distance_one_coloring` で求められる（[並べ替えと彩色](oxref:sparse-coloring)）。
衝突の関係は `ColoringKind` で選ぶ。

- `ColoringKind::DerivativeColumns` は、同じ行に保存された位置を持つ列どうしが異なる色であることを要求する。
  ヤコビ行列の列圧縮に使う。
- `ColoringKind::DistanceOne` は、正方の構造を無向グラフとみなし、隣接する頂点どうしが異なる色であることを要求する。
  $(i, j)$ か $(j, i)$ が保存されていて $i \ne j$ なら、頂点 $i$ と $j$ は隣接する（対角要素は無視する）。

`DistanceOne` は隣接だけを見るので、隣接しない 2 つの列が同じ行に位置を持っていても、同じ色を許す。
そのため `DistanceOne` の彩色は列圧縮の条件を満たすとは限らない。
scioxide-differentiate の `ColoredJacobianPlan` は、`DerivativeColumns` 以外のスケジュールを拒否する。

色の番号は 0 から連続していなければならない。
彩色の長さと列数の不一致、列数以上の色番号、衝突、使われない色番号、正方でない構造への `DistanceOne` は `InvalidInput`（`Malformed`）、確保の失敗は `AllocationFailure` になる。
検証は非零の数、行数、列数の和に比例する時間で済み、作業用に色の数に比例するメモリ領域を使う。
`groups()` は色の順に列のグループを、`colors()` は列ごとの色を、`color_count()` は色の数を返す。
列のない構造では色の数は 0 である。
スケジュールは渡された構造を所有して保持し、`pattern()` がそのビューを、`kind()` が衝突の関係を返す。
`validate_pattern(view)` は、あとで渡された構造がそれと厳密に一致するかを確かめ、違えば `InvalidInput`（`Malformed`）を返す。

次のセルは $n \times n$ の三重対角構造を作り、列番号を 3 で割った余りで彩色して検証する。
入力は次数 $n$（4 から 12 の整数）である。
三重対角では、行 $i$ に列 $i - 1$、$i$、$i + 1$ が現れる。
行 1 は列 0、1、2 を含むので 3 色が必要で、3 で割った余りの彩色はどの行でも 3 つの列に異なる色を与えるので 3 色で十分である。
比較として 2 で割った余りの彩色を検証すると、列 0 と列 2 が行 1 で同じ色になるため、`DerivativeColumns` では拒否される。
三重対角のグラフで隣接するのは番号が 1 だけ違う頂点どうしなので、同じ 2 色の彩色は `DistanceOne` では受理される。

セルはさらに、彩色を使ってヤコビ行列を復元する。
要素を $J_{ij} = 10\,(i + 1) + (j + 1)$ と決め、色ごとの積 $J d_k$ を 3 本計算し、行 $i$ と列 $j$ の要素を $(J d_{c_j})_i$ から読み出す（$c_j$ は列 $j$ の色）。
1 つ目の表は構造と彩色の要約、復元した要素と元の要素の差の最大値、2 色の彩色を 2 つの関係で検証した結果を示す。
2 つ目の表は `groups()` が返す色ごとの列を並べる。

```rust
//| id: core-coloring-schedule
//| ref: core-coloring-schedule
//| title: 三重対角構造の列彩色とヤコビ行列の復元
//| run: reactive
//| crates: [scioxide-core]
//| inputs:
//|   matrix_size: {"type":"range","label":"行列の次数 n","description":"n × n の三重対角構造。","min":4,"max":12,"step":1,"value":6}
//| cases:
//|   - {"id":"smallest","label":"n = 4","description":"色ごとの列の数が 2、1、1 になる。","inputs":{"matrix_size":4}}
//|   - {"id":"largest","label":"n = 12","description":"列が 4 倍になっても色の数は 3 のままである。","inputs":{"matrix_size":12}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":16}
//|       - {"artifact":"summary","path":"/rows/0/1","equals":3}
//|       - {"artifact":"summary","path":"/rows/0/2","equals":3}
//|       - {"artifact":"summary","path":"/rows/0/3","equals":6}
//|       - {"artifact":"summary","path":"/rows/0/4","approx":{"value":0,"atol":1e-12}}
//|       - {"artifact":"summary","path":"/rows/0/5","equals":"InvalidInput"}
//|       - {"artifact":"summary","path":"/rows/0/6","equals":"受理"}
//|       - {"artifact":"groups","path":"/rows/1/1","equals":3}
//|       - {"artifact":"groups","path":"/rows/2/0","equals":1}
//|   - case: smallest
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":10}
//|       - {"artifact":"summary","path":"/rows/0/2","equals":3}
//|       - {"artifact":"summary","path":"/rows/0/4","approx":{"value":0,"atol":1e-12}}
//|       - {"artifact":"groups","path":"/rows/2/0","equals":1}
//|   - case: largest
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":34}
//|       - {"artifact":"summary","path":"/rows/0/2","equals":3}
//|       - {"artifact":"summary","path":"/rows/0/4","approx":{"value":0,"atol":1e-12}}
//|       - {"artifact":"summary","path":"/rows/0/5","equals":"InvalidInput"}
//|       - {"artifact":"summary","path":"/rows/0/6","equals":"受理"}
//|       - {"artifact":"groups","path":"/rows/11/1","equals":11}
use scioxide_core::{ColoringKind, ColoringSchedule, SciOxideErrorKind, StructuralPattern};

let n = matrix_size as usize;
let mut pointers = vec![0];
let mut indices = Vec::new();
for i in 0..n {
    // 行 i の非零列: i-1, i, i+1（範囲内のもの）を昇順に。
    indices.extend(i.saturating_sub(1)..=(i + 1).min(n - 1));
    pointers.push(indices.len());
}
let nnz = indices.len();
// 色の数の下限: 行あたりの非零の最大数。
let max_row = pointers.windows(2).map(|w| w[1] - w[0]).max().unwrap_or(0);
let pattern = StructuralPattern::new(n, n, pointers, indices).map_err(|e| e.to_string())?;

let modulo3: Vec<usize> = (0..n).map(|j| j % 3).collect();
let schedule = ColoringSchedule::new(pattern.clone(), ColoringKind::DerivativeColumns, modulo3)
    .map_err(|e| e.to_string())?;
let colors = schedule.colors();
let view = schedule.pattern();
let (row_ptr, col_indices) = (view.row_ptr(), view.col_indices());

// ヤコビ行列の要素 J_ij = 10 (i + 1) + (j + 1)。構造上の位置だけで使う。
let entry = |i: usize, j: usize| (10 * (i + 1) + j + 1) as f64;
// 色 k の方向 d_k = Σ_{j ∈ C_k} e_j への積 (J d_k)_i を compressed[k][i] に作る。
let mut compressed = vec![vec![0.0_f64; n]; schedule.color_count()];
for i in 0..n {
    for &j in &col_indices[row_ptr[i]..row_ptr[i + 1]] {
        compressed[colors[j]][i] += entry(i, j);
    }
}
// 復元: J_ij = (J d_{c_j})_i。元の要素との差の最大値を取る。
let mut worst = 0.0_f64;
for i in 0..n {
    for &j in &col_indices[row_ptr[i]..row_ptr[i + 1]] {
        worst = worst.max((compressed[colors[j]][i] - entry(i, j)).abs());
    }
}

// 2 色（j mod 2）の彩色を、2 つの衝突の関係で検証する。
let two_colors = |kind: ColoringKind| {
    let modulo2: Vec<usize> = (0..n).map(|j| j % 2).collect();
    match ColoringSchedule::new(pattern.clone(), kind, modulo2) {
        Ok(_) => "受理",
        Err(error) => match error.kind() {
            SciOxideErrorKind::InvalidInput => "InvalidInput",
            _ => "その他の分類",
        },
    }
};
let two_columns = two_colors(ColoringKind::DerivativeColumns);
let two_adjacent = two_colors(ColoringKind::DistanceOne);
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let summary_columns = serde_json::json!([
    { "key": "0", "label": "非零の数", "type": "integer" },
    { "key": "1", "label": "行あたりの非零の最大数", "type": "integer" },
    { "key": "2", "label": "色の数 color_count() [回]", "type": "integer" },
    { "key": "3", "label": "単位ベクトルでの評価 [回]", "type": "integer" },
    { "key": "4", "label": "復元した要素の差の最大値 [-]", "type": "number", "format": sci3 },
    { "key": "5", "label": "2 色（j mod 2）を DerivativeColumns で検証" },
    { "key": "6", "label": "2 色（j mod 2）を DistanceOne で検証" }
]);
emit_table_with_columns!(
    summary_columns,
    vec![(
        nnz,
        max_row,
        schedule.color_count(),
        n,
        worst,
        two_columns,
        two_adjacent,
    )],
    metadata = serde_json::json!({ "id": "summary" })
);

// groups() は色の順に、色ごとの列を昇順で返す。
let members: Vec<(usize, usize)> = schedule
    .groups()
    .enumerate()
    .flat_map(|(k, group)| group.iter().map(move |&j| (k, j)))
    .collect();
let group_columns = serde_json::json!([
    { "key": "0", "label": "色 k", "type": "integer" },
    { "key": "1", "label": "列 j", "type": "integer" }
]);
emit_table_with_columns!(
    group_columns,
    members,
    metadata = serde_json::json!({ "id": "groups" })
);
```

既定値 $n = 6$ では非零は 16 個で、色の数は下限の 3 に一致する。
色 0 は列 0 と 3、色 1 は列 1 と 4、色 2 は列 2 と 5 で、6 回の評価が 3 回になる。
復元した要素と元の要素の差の最大値は 0 である。
1 つの行で同じ色の列は 1 本だけなので、積の成分は 1 つの要素そのもので、加算の丸めも入らない。
2 色の彩色は `DerivativeColumns` では `InvalidInput` で拒否され、`DistanceOne` では受理される。
距離 1 の彩色として正しい 2 色でも、列圧縮に使うと行 1 で列 0 と列 2 の要素が混ざる。

$n = 12$ でも色の数は 3 のままで、評価回数の比 $n / 3$ は $n$ に比例して大きくなる。
$n = 4$ では色ごとの列の数が 2、1、1 になり、$n$ が 3 の倍数でないときは、色によって列の数が 1 だけ異なる。
実際の有限差分では、各評価に打ち切り誤差と丸め誤差が加わるので、復元した要素の誤差は差分の公式と刻み幅に依存する。
彩色が減らすのは評価の回数であり、差分の誤差ではない。

## まとめ

疎行列の構造は各行の列番号を重複なく昇順に並べた正準 CSR の `StructuralPattern` で渡し、検査を満たさない配列は構築時に `InvalidInput` で拒否される。
三角格納は `Triangle` で格納した半分を、`DiagonalKind` で対角を格納したかどうかを示す。
疎なヤコビ行列は、同じ行に位置を持つ列が異なる色になる彩色を `ColoringSchedule`（`DerivativeColumns`）で検証すれば、列の数ではなく色の数だけの評価で求められる。
色の数は行あたりの非零の最大数を下回らない。
距離 1 の彩色は列圧縮の条件を満たすとは限らないので、用途に合った `ColoringKind` を選ぶ。
彩色したあとで構造が変わった可能性があるときは、`validate_pattern` で一致を確かめてからスケジュールを使う。
