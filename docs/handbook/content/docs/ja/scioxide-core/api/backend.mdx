`scioxide_core::backend` は、他の SciOxide クレートが自分のカーネルを実装するときに共有する低水準の仕様を出力に反映する。
利用者のコードが直接使うことは少ないが、他の章の API が返すエラーや保証の多くはこれらの関数に由来する。
大きさと確保の関数は、`Quantity` で数量を名付けて `SizeOverflow` や `AllocationFailure` を返し、パニックしない。

## 実数核と範囲を保つ累積

この節の関数は検査付き算術と安定変換の実数版を、他のクレートのカーネルから直接呼べる形で出力に反映する。
利用者の計算では先に上位の検査付き算術や安定変換を選ぶ。

`real_*` は対応する安定変換の実数版を `f64` で評価して `S` へ丸め、失敗を `SciOxideError` ではなく `ScalarKernelError` で返す。
`real_*` に共通のエラーは次の 3 つである。

## レーンごとの初等関数

`lanes_*` は、`[f64; W]` の配列の各レーンで binary64 の初等関数を一つ評価する。
核は分岐のない計算で、`IEEE` の算術とビット演算だけを使い、特殊値は選択で処理する。
表引き、分岐、融合積和は使わない。
どのレーンも同じ演算を行うので、ループはビルドの対象機能（既定は SSE2、最近の x86-64 で `-C target-cpu=native` なら AVX2）に合わせてベクトル化される。
あるレーンの結果はそのレーンの引数だけで決まり、`W`、レーンの位置、対象環境、FMA の有無によらず同じである。

結果は厳密な値から 4 ULP 以内である。
スカラーの `RealScalar` のメソッドの結果とは、末尾の数 ULP が違うことがある。
MPFR と照合した試験では、`lanes_tanh` は正しく丸めた値から 2 ULP 以内、ほかの関数は 1 ULP 以内である。

核の定義域は表の各行に示す。
定義域の外のレーンはスカラーのメソッドの結果を返す（0、無限大、`NaN` に対する `IEEE` の結果を含む）。
定義域の検査は呼び出し 1 回につき分岐 1 回で、レーンごとには分岐しない。
これらの関数は失敗せず、引数を検査しない。

## Standard の積と尺度化

これらの補助関数は有限な入力や成分の上限を準備する側と、結果を検査する側に役割を分ける。

## 実数の積和の因子と累積

以下の二つの型は実数の積和を丸めずに蓄積するカーネルのための型である。
因子は `ProductFactor` で一度だけ検査して分解し、積は `RealProductSum` に蓄積して `finish` で丸める。

| 項目 | 種別 | 役割 | 仕様の要点 | 解説節 | 実行例 |
|---|---|---|---|---|---|
| [`ProductFactor`](https://docs.rs/scioxide-core/0.1.0/scioxide_core/backend/struct.ProductFactor.html) | 構造体 | 検査済みで分解済みの実数の因子 | 有限な実数を仮数と指数へ一度だけ分解して持つ `Copy` の値。`new` は `NaN` と無限大を `NonFinite` で拒否する。`normalized` は値を変えずに仮数の末尾の 0 のビットを除く。確保しない | - | - |
| [`RealProductSum`](https://docs.rs/scioxide-core/0.1.0/scioxide_core/backend/struct.RealProductSum.html) | 構造体 | 実数の積の厳密な累積和 | `add_value`、`add_product`、`add_weighted_pair` などで積を丸めずに蓄積し、`finish` は現在の和を一回丸める。丸めた結果は `RangeAccumulator` とビット単位で一致する。項の指数の幅が小さい間は符号付き 192 ビット整数 1 個で持ち、幅が広がると丸めずに `RangeAccumulator` へ移る。`sign` は厳密な和の符号を丸めずに返し、最小の非正規化数より小さい和や、丸めるとあふれる和でも正しい。非有限な入力は `NonFinite` で、和を変えない。`finish` のあふれは `NumericalInstability`（`Overflow`）で、厳密な和は残る。確保しない | - | - |

## まとめ

この名前空間の項目は、SciOxide のクレートがカーネルを実装するときの部品である。
利用者のコードではルートの `checked_*` 関数や安定変換を先に検討し、同じ仕様を自分のカーネルで保つ必要があるときにここを引く。
大きさと確保の関数は、桁あふれと確保の失敗を `SizeOverflow` と `AllocationFailure` で返す。
`lanes_*` は引数を検査せず失敗もしないので、定義域と 4 ULP の誤差を各行で確かめてから使う。
