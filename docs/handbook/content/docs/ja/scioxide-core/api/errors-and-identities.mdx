`scioxide-core` の失敗は一つの内部構造を公開しない型 `SciOxideError` で返る。
分類は `kind()` の `SciOxideErrorKind` で、詳細は `view()` の `SciOxideErrorView` で読む。
内部表現や `Display` の文字列には依存しない。
エラーは何が失敗したか（分類、`Argument` / `Quantity`、詳細）だけを持ち、呼び出し元の識別子は持たない。
分類ごとの詳細の読み方と実例は[エラーの分類と詳細ビュー](../../algorithms/errors-and-diagnostic-views/)にある。
`Err` と未収束などの結果を含む `Ok` の考え方は[エラー仕様と部分結果](../../../concepts/errors-and-partial-results/)にある。

## まとめ

失敗を受け取ったら、`kind()` で分類を確かめ、`view()` で引数、数量、理由を読む。
分岐は `SciOxideErrorKind` と理由の列挙型で書き、`Display` の文字列には依存しない。
反復の失敗は `ConvergenceDiagnostics` から反復回数、止めた計算回数の上限、入れ子の記録を読める。
自分の解法で引数や数量に名前を付けるときは、`argument!` と `quantity!` でコンパイル時に検査する。
