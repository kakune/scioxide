`scioxide-core` は、他のクレートが共有するスカラー型の要件、許容誤差、定義域、範囲安全な算術、拡張範囲値、求解の回数の集計、実行の方針と機能、作用素のプロトコルを出力に反映する。
このガイドは目的ごとに API となる項目を示す。
公開されている 335 項目（ルートの 227 項目と `backend` 名前空間の 108 項目）は、用途別の表にまとめてある。
表の項目名のリンクは、docs.rs の 0.1.0 の API リファレンスを指す。

## 目的別の API

| したいこと | API となる項目 | 表 |

| 収束や受理を判定する | `Tolerance`、`ResidualTolerance` などの役割別の型、`RelativeTolerance`、`ErrorTolerance` | [定義域・許容誤差・上限](domains-tolerances-budgets/) |
| 変数の範囲を表す | `Interval`、`ExtendedInterval`、`Bounds` | [定義域・許容誤差・上限](domains-tolerances-budgets/) |
| 反復や評価の回数を制限・計数する | `Budget`、`budget!`、`SolveBudgets`、`SolveState`、`SolveContext`、`SolveScope` | [定義域・許容誤差・上限](domains-tolerances-budgets/)、[求解の回数の集計と実行](solve-and-execution/) |
| 和・積和・ノルムを丸めや桁あふれなしに計算する | `checked_sum`、`RangeAccumulator`、`checked_scaled_norm` | [算術・安定変換・対数和](arithmetic-and-reductions/) |
| 倍精度の範囲外の値を扱う | `Scaled`、`ScaledValue`、`LogValue` | [スカラー・複素数・値の表現](scalars-and-values/) |
| 指数の和や確率を計算する | `logsumexp`、`weighted_logsumexp`、`softmax_into`、`softmax_axis_into` | [算術・安定変換・対数和](arithmetic-and-reductions/) |
| 0 の近くの打ち消しを避ける | `cosm1`、`exprel`、`sin_pi` など | [算術・安定変換・対数和](arithmetic-and-reductions/) |
| 失敗の分類と詳細を読む | `SciOxideError`、`SciOxideErrorKind`、`SciOxideErrorView`、`EstimateReliability` | [エラー分類と識別子](errors-and-identities/) |
| 並列化・取り消し・期限を指定する | `ExecutionPolicy`、`ExecutionContext`、`ThreadExecutor`、`CancellationToken`、`Deadline` | [求解の回数の集計と実行](solve-and-execution/) |
| 多次元配列を借用する | `StridedLayout`、`NdView`、`NdViewMut` | [レイアウト・作用素・組合せ](layouts-operators-combinatorics/) |

| 組合せを数える・列挙する | `checked_binomial`、`CombinationEnumerator`、`Permutation` | [レイアウト・作用素・組合せ](layouts-operators-combinatorics/) |

三角格納の向き `Triangle` と対角の表し方 `DiagonalKind` は scioxide-core にある。
疎行列の格納と Hermitian 構造は scioxide-sparse が、数値微分は scioxide-differentiate が提供する。

## 型の関係

- `RealScalar` は `f32` と `f64` だけが実装する sealed トレイトである。
  `NumericScalar` も外部からの実装を許可していないため、`Complex<f32>` と `Complex<f64>` を加えた 4 つの型が実装する。
  `AlgebraicScalar` は体の演算だけを要求する境界で、他のクレートも実装できる。
- しきい値は `Tolerance`（とそれを包む役割別の型）で、回数の上限は `Budget` と `SolveBudgets` で表す。
  両者は別の型である。
- 所有する `SolveState` から `begin_solve` で借用の `SolveContext` を得る。
  子の求解は `SolveScope` で始める。
  回数の集計は `SolveCounts` の `own()` と `nested()` に分かれる。
- 名前が `_scoped` で終わる関数は、呼び出し側のスコープかコンテキストを最後の引数に取り、その中で動く。
  呼び出し側の取り消しと期限に従い、入れ子の求解は呼び出し側の上限に計上される。
  `LinearOperator`、`AdjointOperator`、`Preconditioner` の `_scoped` 版のメソッドは `OperatorContext` を受け取る。
  `OperatorContext` は `SolveContext` を借用し、呼び出し側が解決した `DenseOperatorKernel` を添えることもできる。
- `ExecutionPolicy` は並列化の意図を表す。
  エグゼキューターと機能を持つ `ExecutionContext` が、この方針を `PlanLimits` のもとで `ExecutionPlan` に解決する。
  コンテキストの引数を持たない関数は `ExecutionContext::sequential_native()` で動く。
- `StridedLayout` は形とストライドを借用し、`NdView` / `NdViewMut` がそれをメモリ領域と結び付ける。
  行優先の配置は `row_major` で形だけから作れる。
  軸に沿う正規化と対数和（`softmax_axis_into`、`logsumexp_axis_into` など）はこのビューを受け取る。
- `Scaled`（一成分）、`ScaledValue`（成分ごとの尺度）、`ProjectiveValue`（共有指数）、`LogValue`（位相と対数）は、IEEE 型への射影規則を共有する。

## 最小の実行例：三つの呼び出し形

同じ計算に三つの呼び出し形がある。
所有値を返す API は結果を確保して返す。
出力先を指定する API（名前が `_into` で終わる）は、呼び出し側が用意した出力と作業領域に書く。
軸に沿う形（`_axis_into`）は多次元のビューを受け取り、実行方針 `ExecutionPolicy` と実行コンテキスト `ExecutionContext` を引数に取る。

次のセルは二つの対数 $c + \Delta$ と $c$ のソフトマックスを三つの形で計算する。
入力は共通の移動 $c$ と対数の差 $\Delta$ で、どちらも無次元である。
出力は形ごとの確率 $p_0$、$p_1$ と、解析値 $p_0 = 1/(1 + e^{-\Delta})$ との差である。
三つの形の結果が解析値と一致することと、$c \ge 710$ で $e^{c}$ が倍精度の範囲を超えても確率が有限に求まることを確かめる。
軸に沿う形には `ExecutionContext::sequential_native()` を渡し、コンテキストの引数を持たない二つの形と同じコンテキストで動かす。

```rust
//| id: core-api-normalization-forms
//| ref: core-api-normalization-forms
//| title: ソフトマックスを所有値を返す API・出力先を指定する API・軸に沿う形で計算する
//| run: reactive
//| crates: [scioxide-core]
//| inputs:
//|   shift: {"type":"range","label":"共通の移動 c [-]","description":"c ≥ 710 では e^c がオーバーフローする。","min":500,"max":1000,"step":50,"value":1000}
//|   logit_diff: {"type":"range","label":"対数の差 Δ [-]","description":"二つ目の対数は c、一つ目は c + Δ。","min":0,"max":5,"step":0.5,"value":2}
//| cases:
//|   - {"id":"equal-logits","label":"Δ = 0","description":"二つの対数が等しく、確率は 1/2 ずつになる。","inputs":{"logit_diff":0}}
//|   - {"id":"small-shift","label":"c = 500、Δ = 5","description":"e^c が有限な範囲でも同じ式で求まる。","inputs":{"shift":500,"logit_diff":5}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"forms","path":"/rows/0/1","approx":{"value":0.8807970779778823,"atol":1e-12}}
//|       - {"artifact":"forms","path":"/rows/1/1","approx":{"value":0.8807970779778823,"atol":1e-12}}
//|       - {"artifact":"forms","path":"/rows/2/1","approx":{"value":0.8807970779778823,"atol":1e-12}}
//|       - {"artifact":"forms","path":"/rows/2/2","approx":{"value":0.11920292202211755,"atol":1e-12}}
//|       - {"artifact":"forms","path":"/rows/0/3","range":{"min":0,"max":1e-12}}
//|   - case: equal-logits
//|     expect:
//|       - {"artifact":"forms","path":"/rows/0/1","approx":{"value":0.5,"atol":1e-12}}
//|       - {"artifact":"forms","path":"/rows/1/2","approx":{"value":0.5,"atol":1e-12}}
//|       - {"artifact":"forms","path":"/rows/2/1","approx":{"value":0.5,"atol":1e-12}}
//|   - case: small-shift
//|     expect:
//|       - {"artifact":"forms","path":"/rows/0/1","approx":{"value":0.9933071490757153,"atol":1e-12}}
//|       - {"artifact":"forms","path":"/rows/1/1","approx":{"value":0.9933071490757153,"atol":1e-12}}
//|       - {"artifact":"forms","path":"/rows/2/1","approx":{"value":0.9933071490757153,"atol":1e-12}}
use scioxide_core::{
    ExecutionContext, ExecutionPolicy, NdView, NdViewMut, softmax, softmax_axis_into,
    softmax_into,
};

let logits = [shift + logit_diff, shift];
// 所有値を返す API: 結果の Vec を確保して返す。
let owned = softmax(&logits).map_err(|e| e.to_string())?;
// 出力先を指定する API: 出力と作業領域を呼び出し側が用意する。
let mut borrowed = [0.0; 2];
let mut scratch = [0.0; 2];
softmax_into(&logits, &mut borrowed, &mut scratch).map_err(|e| e.to_string())?;
// 軸に沿う形: 行優先のビュー、軸、実行方針、出力、作業領域、実行コンテキストを渡す。
let shape = [2];
let mut along_axis = [0.0; 2];
softmax_axis_into(
    NdView::row_major(&logits, &shape).map_err(|e| e.to_string())?,
    0,
    ExecutionPolicy::Sequential,
    NdViewMut::row_major(&mut along_axis, &shape).map_err(|e| e.to_string())?,
    &mut scratch,
    ExecutionContext::sequential_native(),
)
.map_err(|e| e.to_string())?;

// 解析値（参照値なので f64 の固有メソッドで計算する）。
let expected = 1.0 / (1.0 + (-logit_diff).exp());
let digits = serde_json::json!({ "significantDigits": 15 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "形" },
    { "key": "1", "label": "p₀ [-]", "type": "number", "format": digits },
    { "key": "2", "label": "p₁ [-]", "type": "number", "format": digits },
    { "key": "3", "label": "|p₀ − 解析値| [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    vec![
        (
            "softmax（所有値を返す API）",
            owned[0],
            owned[1],
            (owned[0] - expected).abs(),
        ),
        (
            "softmax_into（出力先を指定する API）",
            borrowed[0],
            borrowed[1],
            (borrowed[0] - expected).abs(),
        ),
        (
            "softmax_axis_into（軸に沿う形）",
            along_axis[0],
            along_axis[1],
            (along_axis[0] - expected).abs(),
        ),
    ],
    metadata = serde_json::json!({ "id": "forms" })
);
```

表の各行が一つの形で、右端の列が解析値との差である。
既定値（$c = 1000$、$\Delta = 2$）では、三つの形とも $p_0 \approx 0.8808$、$p_1 \approx 0.1192$ になり、解析値との差は $10^{-12}$ より小さい。
$e^{1000}$ は倍精度で表せないが、どの形も最大の対数を引いてから指数を取るので、確率は $\Delta$ だけで決まる。
$\Delta = 0$ では確率は $0.5$ ずつになり、$c = 500$、$\Delta = 5$ では $p_0 \approx 0.9933$ になる。

## 結果・エラー・診断の読み方

- 失敗は内部構造を公開しない `SciOxideError` で返る。
  `kind()` の `SciOxideErrorKind`（20 種類）で分類し、`view()` の `SciOxideErrorView` で引数（`Argument`）、数量（`Quantity`）、理由、詳細を読む。
  `ConvergenceFailure` の診断（回数、計算回数の上限、残差など）は借用ビュー `ConvergenceDiagnosticsView` で読む。
  エラーは呼び出し元の識別子を持たない。
  分類ごとの読み方は[エラーの分類と詳細ビュー](../algorithms/errors-and-diagnostic-views/)にある。
- 許容誤差の比較などで正当な入力が条件を満たさない場合は、エラーではなく `Ok(false)` が返る。
- 上限による拒否は `Admission::Denied` や `Invocation::BudgetExhausted` として値で返る。
  取り消しと期限による停止は `Invocation::ExecutionStopped` として値で返る。
  これらは `require()` を呼んだ境界でだけ、それぞれ `ConvergenceFailure` と `ExecutionStopped` のエラーになる。
- 出力先を指定する API の関数はすべての入力を検査してから出力に書く。
  結果をすべて書き込むか、失敗して出力を変えないかのどちらかになる。
  作業領域の内容は失敗時に変わることがある。
- 各関数の仕様は「一回の丸め」「$N$ ULP」「$\gamma_k$ の限界」「残差の限界」などで示される。
  種類の違いは[共通基盤の数理](oxref:core-accuracy-contracts)にある。
