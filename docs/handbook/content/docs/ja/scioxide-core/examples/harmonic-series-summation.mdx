調和級数 $H_n = \sum_{k=1}^{n} 1/k$ は $n \to \infty$ で発散する。
ところが単精度（`f32`）で $k = 1, 2, \ldots$ の順に足すと、和はある項数から先まったく増えなくなる。
この例題ではその原因を浮動小数点の間隔から説明し、足す順序を変えた和、`ScaledAccumulator` による補償和、`RangeAccumulator` による厳密な和を比べる。

## Euler–Maclaurin 展開による参照値

$H_n$ は Euler の定数 $\gamma \approx 0.5772156649015329$ を使って

$$
H_n = \ln n + \gamma + \frac{1}{2n} - \frac{1}{12 n^2} + \frac{1}{120 n^4} - \frac{1}{252 n^6} + \cdots
$$

と展開できる。
$1/(120 n^4)$ の項まで取ると、打ち切り誤差は次の項 $1/(252 n^6)$ 程度で、$n \ge 10$ では $4 \times 10^{-9}$ 以下である。
倍精度で計算したこの値の誤差は、単精度の間隔（$H_n \approx 14$ の近くで約 $9.5 \times 10^{-7}$）よりずっと小さいので、参照値として使う。
$H_{10^6} \approx 14.3927267$、$H_{3 \times 10^6} \approx 15.49134$ である。

## 前から足した和が止まる理由

`f32` の仮数は 24 ビット（暗黙の先頭ビットを含む）で、$8 \le S < 16$ の数の間隔は $\mathrm{ulp}(S) = 2^{3-23} = 2^{-20}$ である。
最近接偶数丸めでは、$x < \mathrm{ulp}(S)/2 = 2^{-21}$ のとき $S + x$ は $S$ に丸められる。
前から足していくと、`f32` の和は $k \approx 2 \times 10^{6}$ で約 15.40 に達する。
この値は数学的な $H_{2^{21}} \approx 15.133$ より大きい（理由は[項数を増やしたときの誤差](#項数を増やしたときの誤差)で確かめる）。
$1/k < 2^{-21}$、すなわち $k > 2^{21} = 2{,}097{,}152$ の項はどれも和を変えない。
$k = 2^{21}$ の項はちょうど間隔の半分で、偶数丸めで切り上がるか元に戻るかは和の最下位ビットで決まる。
そのため、前から足した `f32` の和は $k = 2^{21}$ のあたりで $15.403683$ になったまま止まる。

和を止めないための方法は三つある。

- **後ろから足す**：$k = n, n-1, \ldots, 1$ の順に足す。
  部分和が小さいうちに小さな項が足されるので、和が止まらず、丸め誤差も前からの和よりずっと小さい。
- **補償和**（`ScaledAccumulator`）：和と補正項の二つを持つ Neumaier の方法。
  足すたびに失われた下位の値を補正項に残す。
  補正項も有限の精度を持つので、厳密な和ではない。
- **厳密な和**（`RangeAccumulator`）：各項を整数の桁として丸めずに累積し、最後に一度だけ丸める。

ただし、どの方法でも各項 $1/k$ はまず `f32` に丸められる。
`RangeAccumulator` が厳密に足すのはこの丸めた項なので、結果と $H_n$ の差には、項の丸め誤差の和（大きさは最大で $u H_n$ 程度、$u = 2^{-24}$）が残る。
$H_n \approx 15.5$ では $u H_n \approx 9.2 \times 10^{-7}$ で、ほぼ 1 ulp にあたる。

次のブロックは二つのセルが共有する定義である。
`term` は `f32` に丸めた項 $1/k$、`harmonic_reference` は上の展開を $1/(120 n^4)$ の項まで取った参照値、`ulp_at` は `f32` の値の位置での間隔を返す。

```rust
//| id: core-harmonic-series-model
//| kind: definitions
//| title: 調和級数の項と参照値
//| crates: [scioxide-core]
use scioxide_core::RealScalar;

/// f32 に丸めた項 1/k（k < 2²⁴ は f32 で厳密に表せる）。
pub(crate) fn term(k: usize) -> f32 {
    1.0_f32 / k as f32
}

/// 参照値: Euler–Maclaurin 展開を倍精度で計算する（f64 の固有メソッド）。
pub(crate) fn harmonic_reference(n: usize) -> f64 {
    let x = n as f64;
    x.ln() + 0.577_215_664_901_532_9 + 0.5 / x - 1.0 / (12.0 * x * x) + 1.0 / (120.0 * x.powi(4))
}

/// f32 の値 value の位置での間隔（上側の隣接数との差）。
pub(crate) fn ulp_at(value: f32) -> f64 {
    f64::from(RealScalar::next_after(value, f32::INFINITY) - value)
}
```

## 一つの項数での比較

次のセルは選んだ $n$ について四つの和を `f32` で計算し、参照値との差を和の位置での `f32` の間隔（ulp）で示す。
入力は $\log_{10} n$（1 から 6.5、0.5 刻み）で、$n$ は $10^{\log_{10} n}$ を整数に丸めた値である。
1 つ目の表は $n$、参照値、ulp の大きさを、2 つ目の表は方法ごとの和と参照値との差を示す。
$n = 10^{6.5} \approx 3.16 \times 10^{6}$ の計算には時間がかかるので、ボタンで実行する。

```rust
//| id: core-harmonic-series-summation
//| ref: core-harmonic-series-summation
//| title: 単精度の調和級数を四通りに足す
//| run: button
//| crates: [scioxide-core]
//| uses: [core-harmonic-series-model]
//| inputs:
//|   log_n: {"type":"range","label":"項数の指数 log₁₀ n [-]","description":"1 は 10 項、6 は 10⁶ 項、6.5 は約 3.16 × 10⁶ 項。","min":1,"max":6.5,"step":0.5,"value":6.5}
//| cases:
//|   - {"id":"million","label":"n = 10⁶","description":"前からの和はまだ止まっていないが、すでに大きくずれている。","inputs":{"log_n":6}}
//|   - {"id":"ten","label":"n = 10","description":"項が少なく、どの方法も 1 ulp 以内で一致する。","inputs":{"log_n":1}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/0","equals":3162278}
//|       - {"artifact":"reference","path":"/rows/0/1","approx":{"value":15.5440194,"atol":1e-6}}
//|       - {"artifact":"sums","path":"/rows/0/1","approx":{"value":15.403683,"atol":1e-6}}
//|       - {"artifact":"sums","path":"/rows/0/2","range":{"min":-160000,"max":-140000}}
//|       - {"artifact":"sums","path":"/rows/3/2","range":{"min":-1,"max":1}}
//|   - case: million
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","approx":{"value":14.392726722865724,"atol":1e-9}}
//|       - {"artifact":"sums","path":"/rows/2/2","range":{"min":-3,"max":3}}
//|       - {"artifact":"sums","path":"/rows/3/2","range":{"min":-1,"max":1}}
//|   - case: ten
//|     expect:
//|       - {"artifact":"sums","path":"/rows/3/1","approx":{"value":2.9289682539682538,"atol":3e-7}}
//|       - {"artifact":"sums","path":"/rows/0/2","range":{"min":-1,"max":1}}
use scioxide_core::{RangeAccumulator, RealScalar, ScaledAccumulator};

let n = RealScalar::round(RealScalar::powf(10.0_f64, log_n)) as usize;
let forward = (1..=n).fold(0.0_f32, |sum, k| sum + term(k));
let backward = (1..=n).rev().fold(0.0_f32, |sum, k| sum + term(k));
let mut compensated = ScaledAccumulator::<f32>::ZERO;
let mut exact = RangeAccumulator::<f32>::new();
for k in 1..=n {
    compensated.add_value(term(k)).map_err(|e| e.to_string())?;
    exact.add(term(k)).map_err(|e| e.to_string())?;
}
let compensated = compensated.round().map_err(|e| e.to_string())?;
let exact = exact.finish().map_err(|e| e.to_string())?;

let reference = harmonic_reference(n);
// 和の位置での f32 の間隔。差はこの単位で表す。
let ulp = ulp_at(exact);
let fixed7 = serde_json::json!({ "fractionDigits": 7 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let reference_columns = serde_json::json!([
    { "key": "0", "label": "項数 n [項]", "type": "integer" },
    { "key": "1", "label": "参照値 H_n [-]", "type": "number", "format": fixed7 },
    { "key": "2", "label": "和の位置での f32 の間隔 [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    reference_columns,
    vec![(n as u32, reference, ulp)],
    metadata = serde_json::json!({ "id": "reference" })
);

let fixed2 = serde_json::json!({ "fractionDigits": 2 });
let sum_columns = serde_json::json!([
    { "key": "0", "label": "方法" },
    { "key": "1", "label": "f32 の和 [-]", "type": "number", "format": fixed7 },
    { "key": "2", "label": "和 − 参照値 [ulp]", "type": "number", "format": fixed2 }
]);
let row = |name: &'static str, value: f32| {
    let value = f64::from(value);
    (name, value, (value - reference) / ulp)
};
emit_table_with_columns!(
    sum_columns,
    vec![
        row("前から足す", forward),
        row("後ろから足す", backward),
        row("ScaledAccumulator", compensated),
        row("RangeAccumulator", exact),
    ],
    metadata = serde_json::json!({ "id": "sums" })
);
```

既定の $n = 3{,}162{,}278$ では前からの和は $15.403683$ で止まっていて、参照値 $15.544019$ より約 0.14 小さい（約 15 万 ulp）。
後ろからの和の差は約 1300 ulp、`RangeAccumulator` は 0.3 ulp である。
`ScaledAccumulator` は約 180 ulp ずれる。
丸めで失われた下位の値は補正項に入るが、補正項自身も `f32` の精度で足されていくので、その丸め誤差が残るためである。

$n = 10^{6}$ では、前からの和はまだ止まっていないが、すでに約 3.7 万 ulp ずれている。
後ろからの和の差は約 80 ulp、`ScaledAccumulator` は約 1 ulp、`RangeAccumulator` は 0.2 ulp である。
$n = 10$ では四つの和がどれも参照値から 1 ulp 以内にある。

## 項数を増やしたときの誤差

次のセルは $n = 10, 10^{1.5}, \ldots, 10^{6.5}$ の 12 点と $n = 2^{21}$ で、前からの和、後ろからの和、`RangeAccumulator` の和を参照値と比べる。
前からの和と `RangeAccumulator` は一回の走査の途中の値を記録し、後ろからの和は $n$ ごとに計算し直す。
入力はない。
グラフは差の絶対値を ulp で表して両対数軸に描き、前からの和が止まる $n = 2^{21}$ を縦線で示す。
差が厳密に 0 の点は対数軸に描けないので系列から除く。
表は $k = 2^{21}$ の直前の 2 項、$k = 2^{21}$、最後の項数での前から足した和と、同じ項数での `RangeAccumulator` の差を示す。

```rust
//| id: core-harmonic-series-growth
//| ref: core-harmonic-series-growth
//| title: 項数と各方法の誤差
//| run: button
//| crates: [scioxide-core]
//| uses: [core-harmonic-series-model]
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"frozen","path":"/rows/0/0","equals":2097150}
//|       - {"artifact":"frozen","path":"/rows/0/1","approx":{"value":15.4036818,"atol":3e-7}}
//|       - {"artifact":"frozen","path":"/rows/2/1","approx":{"value":15.403683,"atol":1e-6}}
//|       - {"artifact":"frozen","path":"/rows/3/0","equals":3162278}
//|       - {"artifact":"frozen","path":"/rows/3/1","approx":{"value":15.403683,"atol":1e-6}}
//|       - {"artifact":"frozen","path":"/rows/3/2","range":{"min":0,"max":1}}
use scioxide_core::{RangeAccumulator, RealScalar};

let mut checkpoints: Vec<usize> = (2..=13)
    .map(|i| RealScalar::round(RealScalar::powf(10.0_f64, 0.5 * i as f64)) as usize)
    .collect();
let last = *checkpoints.last().ok_or("項数の列が空")?;
// 前からの和が止まる n = 2²¹ も記録する。
checkpoints.push(2_097_152);
let ulps =
    |value: f32, n: usize| (f64::from(value) - harmonic_reference(n)).abs() / ulp_at(value);

let mut forward = 0.0_f32;
let mut exact = RangeAccumulator::<f32>::new();
// 0 番目が前からの和、1 番目が後ろからの和、2 番目が RangeAccumulator。
let mut curves = [Vec::new(), Vec::new(), Vec::new()];
let mut frozen = Vec::new();
for k in 1..=last {
    forward += term(k);
    exact.add(term(k)).map_err(|e| e.to_string())?;
    let exact_sum = exact.finish().map_err(|e| e.to_string())?;
    if [2_097_150, 2_097_151, 2_097_152, last].contains(&k) {
        frozen.push((k as u32, f64::from(forward), ulps(exact_sum, k)));
    }
    if checkpoints.contains(&k) {
        let backward = (1..=k).rev().fold(0.0_f32, |sum, j| sum + term(j));
        for (curve, value) in curves.iter_mut().zip([forward, backward, exact_sum]) {
            let error = ulps(value, k);
            if error > 0.0 {
                curve.push([k as f64, error]);
            }
        }
    }
}
emit_line_chart!(
    &vec![
        serde_json::json!({ "name": "前から足す", "points": curves[0] }),
        serde_json::json!({ "name": "後ろから足す", "points": curves[1] }),
        serde_json::json!({ "name": "RangeAccumulator", "points": curves[2] }),
    ],
    options = &serde_json::json!({
        "xLabel": "項数 n [項]",
        "yLabel": "|和 − 参照値| [ulp]",
        "xType": "log",
        "yType": "log",
        "annotations": [{ "kind": "line", "axis": "x", "value": 2_097_152.0, "label": "n = 2²¹" }]
    })
);
let fixed7 = serde_json::json!({ "fractionDigits": 7 });
let fixed2 = serde_json::json!({ "fractionDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "項数 k [項]", "type": "integer" },
    { "key": "1", "label": "前から足した和 [-]", "type": "number", "format": fixed7 },
    {
        "key": "2",
        "label": "RangeAccumulator の |和 − 参照値| [ulp]",
        "type": "number",
        "format": fixed2
    }
]);
emit_table_with_columns!(
    columns,
    frozen,
    metadata = serde_json::json!({ "id": "frozen" })
);
```

前からの和の誤差は全体として $n$ とともに増えるが、単調ではなく、$n = 2^{21}$ で約 28 万 ulp の山を作る。
項が和の間隔と同じ程度の大きさになると、各項は間隔の整数倍に丸められて足されるからである。
$2^{20} < k < 2^{21}$ の項は間隔 $2^{-20}$ の半分より大きく間隔より小さいので、どれもちょうど 1 間隔として足される。
この区間の項の和は数学的には約 $\ln 2 \approx 0.693$ だが、`f32` の和は約 1 増える。
そのため和が止まる $n = 2^{21}$ では、前からの和 $15.403683$ は $H_n \approx 15.133$ より約 0.27 大きい。
その後は和が変わらず $H_n$ だけが増えるので、差は $n \approx 2.75 \times 10^{6}$ で符号を変え、最後の $n \approx 3.16 \times 10^{6}$ では和が約 0.14（約 15 万 ulp）小さい。
この先は $\ln n$ の増加分だけ差が広がり続ける。

後ろからの和の誤差はゆっくり増え、$n \approx 3.16 \times 10^{6}$ で約 1300 ulp である。
`RangeAccumulator` の誤差は項の丸め誤差だけで、記録したどの $n$ でも 1 ulp 以下にとどまる。

表では、前からの和は $k = 2{,}097{,}151$ の項で最後に 1 ulp 増えて $15.4036827$ になる。
$k = 2^{21} = 2{,}097{,}152$ の項はちょうど間隔の半分で、偶数丸めで元の値に戻る。
それ以降の約 106 万項は和を変えず、最後の $k = 3{,}162{,}278$ でも同じ値である。
同じ行の `RangeAccumulator` の差は 0.2〜0.3 ulp で、前からの和が止まる前後でも変わらない。

## まとめ

前から足した `f32` の和は、和の間隔の半分より小さな項を足しても変わらないので、調和級数では $k > 2^{21}$ で増えなくなる。
$n \approx 3.16 \times 10^{6}$ では、足す順序を逆にすると誤差は約 15 万 ulp から約 1300 ulp に減る。
`ScaledAccumulator` の補償和は誤差をさらに小さくするが、補正項も単精度なので、同じ $n$ で約 180 ulp の誤差が残る。
`RangeAccumulator` は与えられた項を厳密に足して一度だけ丸めるので、残る誤差は各項を `f32` に丸めたときの誤差だけになる。
厳密な結果が必要な和や、分割して計算した和をマージしる場合は `RangeAccumulator`、範囲の広い値を少ないメモリ領域で補償したい場合は `ScaledAccumulator` を使う。
