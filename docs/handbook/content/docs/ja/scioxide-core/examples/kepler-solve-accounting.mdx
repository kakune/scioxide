実際の数値計算では大域的だが収束の遅い方法で解の近くまで進み、局所的に速く収束する方法で仕上げる二段の解法がよく使われる。
二段目を入れ子の求解として呼ぶと、親と子のどちらが反復や関数評価をいくつ使ったかを区別して数える必要がある。
この例題ではKepler 方程式を題材に、`scioxide-core` の `SolveState`、`SolveContext`、`SolveScope` で親子の回数の集計を分ける。
Kepler 方程式のモデルと解法の比較は scioxide-rootfind の[Kepler 方程式と離心率](../../../scioxide-rootfind/examples/kepler-equation/)が扱い、ここでは求解の回数の集計に話を限る。
パラメータの既定値（$e = 0.6$、$M = 1.2$ rad）はそのページにそろえてある。

## Kepler 方程式

楕円軌道を運動する天体の位置は、平均近点角 $M$ [rad]（時間に比例して進む角度）から離心近点角 $E$ [rad] を求めて決まる。
離心率を $e$（$0 \le e < 1$、無次元）とすると、$E$ は

$$
R(E) = E - e \sin E - M = 0
$$

の解である。
$R'(E) = 1 - e\cos E \ge 1 - e > 0$ なので $R$ は狭義単調増加で、解 $E^*$ はただ一つである。
$R(0) = -M \le 0$、$R(2\pi) = 2\pi - M \ge 0$ なので、$M \in [0, 2\pi]$ なら解は $[0, 2\pi]$ にある。

残差から誤差の上界も得られる。
平均値の定理から、ある $\xi$ について $R(E) = R(E) - R(E^*) = R'(\xi)(E - E^*)$ であり、$R' \ge 1 - e$ なので

$$
|E - E^*| \le \frac{|R(E)|}{1 - e}
$$

が成り立つ。
残差を許容誤差 $\tau$ 以下にすれば、誤差は $\tau/(1 - e)$ 以下になる。
これは厳密な $R$ についての上界で、浮動小数点で計算した残差には丸め誤差が含まれるので、計算した残差に当てはめた値は証明付きの誤差限界ではない（[根の一意性と誤差の上界](oxref:rootfind-kepler-uniqueness)）。
$e$ が 1 に近いほど、同じ残差に対する誤差の上界は大きい。

## 二段の解法

1. **不動点反復（親）**：$E_{k+1} = g(E_k)$、$g(E) = M + e\sin E$、$E_0 = M$。
   $|g'(E)| = e|\cos E| \le e < 1$ なので $g$ は縮小写像で、どの初期値からも解に収束する。
   誤差は $|E_k - E^*| \le e^k |E_0 - E^*|$ を満たす。
   解の近くでの縮小率は $|g'(E^*)| = e|\cos E^*|$ で、$e$ が 1 に近く $|\cos E^*|$ も 1 に近い位置では収束が遅い。
2. **Newton 法（子）**：$E_{n+1} = E_n - R(E_n)/R'(E_n)$。
   解の近くでは $E_{n+1} - E^* \approx \dfrac{R''(E^*)}{2R'(E^*)}(E_n - E^*)^2$、$R''(E) = e\sin E$ で、誤差は一回ごとにおよそ二乗で減る。

不動点反復では反復値の残差を追加の評価なしで読める。
$R(E_k) = E_k - g(E_k) = E_k - E_{k+1}$ なので、$|R(E_k)|$ は続く二つの反復値の差の大きさに等しい。
$|g'| \le e$ から $|E_{k+1} - E_k| \le e\,|E_k - E_{k-1}|$ が成り立つので、不動点反復の間、残差は一回ごとに $e$ 倍以下になる。

## 親子の回数の集計

親は `SolveState::begin_solve` で求解を始め、子は `SolveScope` を通して親のコンテキストから始める。
求解の同一性 `SolveIdentity` は問題の識別子、アルゴリズムの識別子（`algorithm_id!` で定数として作る）、形と設定の識別子からなり、親子でアルゴリズムの識別子が異なる。
計算回数の上限と許可の規則は[求解のライフサイクルと計算回数の管理](../../algorithms/solve-lifecycle-and-accounting/)、親子の回数の集計の規則は[入れ子の求解・回数の集計・診断](../../algorithms/nested-solves-and-diagnostics/)のとおりで、この例題では次のように使う。

- 反復の上限は、親が $K_{\mathrm{outer}}$、子が自分の $K_{\mathrm{inner}}$ を持つ。
  子の反復は親自身の反復回数には加算せず、親の `counts().nested()` に記録される。
- 評価は $g(E)$、$R(E)$、$R'(E)$ の呼び出しを `invoke_provider` で数える（$g$ と $R$ は `EvaluationRole::Function`、$R'$ は `Jacobian`）。
  評価の上限は親に設定した一つの共有の上限で、子の評価も親の残り回数から差し引かれる。
- 途中で止められない作業の前には、必要な評価の回数を `can_consume` で確かめる。
  不動点反復の 1 回は $g$ の評価 1 回、Newton 法の 1 回は $R'$ と更新後の $R$ の評価 2 回を必要とする。
  足りなければ反復を数えずに止まるので、数えた反復はすべて最後まで実行される。
- 子は Newton 法の反復値を自分の `SolveState` に `commit_accepted(PartialResultTrust::DiagnosticOnly)` で受理する。
  残差 $|R(E)|$ が `ResidualTolerance`（絶対許容誤差 $\tau = 10^{-14}$ rad）を満たしたら、`assess_accepted(PartialResultTrust::ResidualChecked)` で信頼区分を上げて終わる。
  子の受理は親の受理状態を進めない。
- 親は子が返した $E$ を 1 回だけ受理する。
  信頼区分は、子が収束していれば `ResidualChecked`、上限で止まっていれば `DiagnosticOnly` にする。

子の Newton 法は呼び出し側のスコープを最後の引数に取る `_scoped` の形の関数 `newton_scoped` として書く。
親が `&mut SolveContext` を渡すので、子は親の共有の評価の上限のもとで動く。

試行の結果は `AttemptRecord` に記録する。
残差が許容誤差を満たしたら `AttemptOutcome::Succeeded`、上限で止まったら `AttemptOutcome::Stopped` とし、どちらの場合も最後の $E$ を進捗として持たせる。
判定に使う残差はすべて回数の集計に含めた評価から得る。
独立な参照値は $[0, 2\pi]$ での二分法を 80 回行って得る（$2\pi / 2^{80}$ は倍精度の間隔より十分小さい）。
二分法の評価は検算のためのもので、回数の集計には含めない。

```rust
use scioxide_core::{
    Admission, AlgorithmId, AttemptKind, AttemptOutcome, AttemptRecord, Budget, BudgetKind,
    EvaluationCounts, EvaluationRole, ExecutionContext, SciOxideError, PartialResultTrust,
    ProblemToken, RealScalar, ResidualTolerance, SolveBudgets, SolveIdentity, SolveScope,
    SolveState, algorithm_id,
};

const FIXED_POINT: AlgorithmId = algorithm_id!("handbook", "kepler_fixed_point", 1);
const NEWTON: AlgorithmId = algorithm_id!("handbook", "kepler_newton", 1);

/// 残差 R(E) = E − e sin E − M。
fn residual(e: f64, m: f64, x: f64) -> f64 {
    x - e * RealScalar::sin(x) - m
}

/// Newton 法（子）。呼び出し側のスコープを最後の引数に取る `_scoped` の形。
/// 評価した残差の大きさを `history` に足し、(E, 止めた計算回数の上限の種類) を返す。
/// 止めた計算回数の上限が `None` なら、残差が許容誤差を満たしている。
fn newton_scoped<'scope, 'capability>(
    (e, m, start): (f64, f64, f64),
    tolerance: ResidualTolerance<f64>,
    max_iterations: Budget,
    history: &mut Vec<f64>,
    scope: impl Into<SolveScope<'scope, 'capability>>,
) -> Result<(f64, Option<BudgetKind>), SciOxideError> {
    let identity = SolveIdentity::new(ProblemToken::new(1), NEWTON, 0, 0);
    let allowance = SolveBudgets::unbounded().with_limit(BudgetKind::Iteration, max_iterations);
    let mut state = SolveState::new();
    scope.into().run(&mut state, identity, allowance, |child| {
        let mut x = start;
        // 出発点の残差に評価を 1 回使う。許可されなければ何もせずに返す。
        if let Admission::Denied(report) = child.can_consume(BudgetKind::Evaluation, 1)? {
            return Ok((x, Some(report.kind())));
        }
        let mut f = child
            .invoke_provider(EvaluationRole::Function, || Ok(residual(e, m, x)))?
            .require()?;
        loop {
            history.push(f.abs());
            if tolerance.is_satisfied(f.abs(), 1.0)? {
                child.assess_accepted(PartialResultTrust::ResidualChecked)?;
                return Ok((x, None));
            }
            // 1 反復は R′ と更新後の R を使う。2 回の評価が許可されるときだけ反復を数える。
            let admission = match child.can_consume(BudgetKind::Evaluation, 2)? {
                Admission::Granted(()) => child.record_iteration()?,
                denied => denied,
            };
            if let Admission::Denied(report) = admission {
                return Ok((x, Some(report.kind())));
            }
            let slope = child
                .invoke_provider(
                    EvaluationRole::Jacobian,
                    || Ok(1.0 - e * RealScalar::cos(x)),
                )?
                .require()?;
            x -= f / slope;
            f = child
                .invoke_provider(EvaluationRole::Function, || Ok(residual(e, m, x)))?
                .require()?;
            child.commit_accepted(PartialResultTrust::DiagnosticOnly)?;
        }
    })
}

    ],
    metadata = serde_json::json!({ "id": "budgets", "title": "実行済みの計算回数" })
);
export!(eccentricity, e);
export!(tolerance, tau);
export!(residual_history, history);
export!(parent_steps, parent_steps);
let mut outcome = outcome
    .status(attempt_name)
    .diagnostic("評価の合計", evaluation_budget.consumed() as f64, None)
    .diagnostic("二分法との差", (x - reference).abs(), Some("rad"));
if let Some(value) = last_residual {
    outcome = outcome.diagnostic("最後の残差", value, Some("rad"));
}
emit_outcome!(outcome);
```

既定の $e = 0.6$、$M = 1.2$ rad では、親が 4 回の不動点反復を行い、子の Newton 法が 2 回の反復で残差を $10^{-14}$ rad 以下にして、試行の結果は `Succeeded` になる。
解は $E = 1.78614$ rad で、二分法との差は誤差の上界 $\tau/(1 - e) = 2.5 \times 10^{-14}$ rad より小さい。
親の `own` は反復 4 回と `Function` の評価 4 回である。
`nested` は子の反復 2 回、`Function` の評価 3 回（出発点の残差と、更新後の残差 2 回）、`Jacobian` の評価 2 回で、`total` は `own` と `nested` の和になる。
評価の消費は親子を合わせた 9 回で、共有の上限 30 回のうち 21 回が残る。
`accepted()` は `own` が 1 回（親が最後の $E$ を受理した回数）、`nested` が 2 回（Newton 法の更新の回数）で、子の受理が親の受理を進めていないことが分かる。

評価の上限を 6 回に下げると、親が 4 回、子が出発点の残差に 1 回使った後、残りは 1 回になる。
Newton 法の 1 反復に必要な 2 回に足りないので、子は反復を数えずに `evaluation` で止まり、`nested` の反復は 0 回、評価の消費は 5 回で残りが 1 回になる。
試行の結果は `Stopped`、親の信頼区分は `diagnostic-only` で、$E$ は不動点反復の結果のままである。
最後の残差は $6.0 \times 10^{-5}$ rad、二分法との差は $5.4 \times 10^{-5}$ rad で、差は上界 $|R(E)|/(1 - e) = 1.5 \times 10^{-4}$ rad の内側にある。

$e = 0.95$ にすると不動点反復の収束が遅くなり、4 回の反復の後の残差は $4.9 \times 10^{-3}$ rad にとどまる。
子の Newton 法の反復は 3 回に増え、評価の消費は 11 回になる。
誤差の上界は $\tau/(1 - e) = 2 \times 10^{-13}$ rad に広がる。
さらに $K_{\mathrm{inner}} = 1$ にすると、子は 1 回の更新の後に自分の反復の上限 `iteration` で止まり、結果は `Stopped` になる。
このとき親の評価回数の上限は 30 回のうち 23 回が残っており、止めたのが子の求解ごとの上限であることを 3 つ目の表で確かめられる。

## 残差の履歴

次のセルは、前のセルが渡した残差の履歴を対数軸のグラフと表で示す。
横軸は反復値の番号 $k$ で、網掛けの範囲は親が自分の評価から残差を得た反復値 $E_0, \ldots, E_{K-1}$（$K$ は親が行った反復の回数）である。
その右は子の Newton 法が評価した残差で、最初の点は親の最後の反復値 $E_K$ の残差にあたる。
横線は許容誤差 $\tau$ を表す。
表は各反復値の残差、それを評価した階層、直前の反復値の残差に対する比を示す。
検証するのは、不動点反復で作った反復値（番号 1 から $K$）の比が $e$ 以下であることである。
残差が厳密に 0 になった点は対数軸に描けないので、グラフから除き、その数を 2 つ目の表に示す。

既定値では、番号 1 から 4 の比は 0.054、0.12、0.13、0.13 で、どれも $e = 0.6$ より小さい。
不動点反復の漸近的な縮小率は $|g'(E^*)| = e|\cos E^*|$ で、$E^* = 1.78614$ rad では $0.6 \times 0.214 = 0.13$ になり、表の比と合う。
Newton 法に移ると残差は $6.0 \times 10^{-5}$、$8.4 \times 10^{-10}$、$2 \times 10^{-16}$ rad と減る。
1 回目の更新で残差がほぼ二乗の大きさになり、2 回目で倍精度の丸めの水準に達して許容誤差の横線を下回る。
前のセルで評価の上限を下げると、子が残差を評価できた分だけ履歴が短くなる。

## まとめ

二段の解法を入れ子の求解として書くと、親の反復と子の反復は別々の上限で管理され、`counts()` の `own()` と `nested()` で区別して読める。
評価は親の一つの共有の上限から親子ともに消費されるので、問題全体の評価回数を一か所で制限できる。
途中で止められない作業の前に `can_consume` で必要な評価の回数を確かめれば、数えた反復がすべて実行された記録になる。
試行の結果は `AttemptOutcome` の `Succeeded` と `Stopped` で分け、`Stopped` のときは信頼区分と止めた計算回数の上限の種類を見て結果を扱う。
誤差の上界は残差の $1/(1 - e)$ 倍なので、$e$ が 1 に近い軌道では許容誤差をそれだけ小さく取る。
