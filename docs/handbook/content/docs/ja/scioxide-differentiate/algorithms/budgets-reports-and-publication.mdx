最適化や時間発展の内側で導関数を求めるときは、1 回の評価が関数を呼ぶ回数に上限を付けたり、外側の求解の上限と共有したりしたいことがある。
上限で止まった評価や外挿が途中で止まった評価が出力を書くかどうかは、終了理由とレポートで決まる。
このページでは評価回数と反復回数に上限を付ける方法、上限に達した評価のレポート、結果を出力に反映する規則、関数の受け渡しの形を説明する。
評価回数、反復回数、終了理由、出力への反映の定義は [呼び出しの形](oxref:differentiate-call-forms-terms) に、作業領域と出力先を指定する API の使い方は [Plan・要件・作業領域の再利用](../plans-workspaces-and-reports/) にある。
上限で止まった計算の部分結果についてクレートに共通の考え方は [エラー仕様と部分結果](../../../concepts/errors-and-partial-results/) にある。

## 評価回数・反復回数の上限と求解の回数の集計

関数の呼び出しはすべて、scioxide-core の求解の回数の集計に関数の評価（`EvaluationRole::Function`）として計上される。
エラーを返した呼び出しも 1 回と数える。
レポートの `evaluations()` はその評価が関数を呼んだ回数で、関数の中で行った入れ子の求解の評価は含まない。
上限は手法オブジェクトと節点差分の選択肢 `NodeDifferenceOptions` の `with_budgets(SolveBudgets)` で、たとえば `SolveBudgets::unbounded().with_limit(BudgetKind::Evaluation, Budget::try_from(n)?)` のように指定する。
Plan は作成時に渡した手法オブジェクトか選択肢の上限を使う。
既定では上限はない。

反復 1 回にあたる処理は種類によって違い、[呼び出しの形](oxref:differentiate-call-forms-terms) の表で定めてある。
固定刻みでは座標 1 つ（ヘッセ行列では対角か上三角の要素 1 つ）、適応差分では座標ごとの準位 1 つ、彩色では列ごとの準位 1 つである。
固定刻み、複素ステップ法、適応差分、彩色は、評価点での値 $f(\mathbf{x})$ を最初の反復の前に評価し、評価回数にだけ数える（固定刻みで `base` を渡したときは評価しない）。
節点差分は変位 0 の節点の評価も反復の中で行う。

出力先を指定する API に実行中の求解の `&mut SolveContext` を渡すと、差分の評価は入れ子の求解になる。
このとき評価回数は親の求解の評価回数の上限にも数え、反復回数はその評価の中だけで数える（[入れ子の求解・回数の集計・診断](../../../scioxide-core/algorithms/nested-solves-and-diagnostics/)）。
上限に達した評価はエラーを返さず、終了理由 `EvaluationLimit` か `IterationLimit` を持つ `Ok` のレポートを返し、出力に何も書かない。
ワンショット関数は上限を取らない。

## レポートと出力への反映の規則

[`DifferentiationReport`](https://docs.rs/scioxide-differentiate/0.1.0/scioxide_differentiate/struct.DifferentiationReport.html) は、`source()`、`termination()`、`is_success()`、`evaluations()`、`iterations()`、`completed_entries()`、`output_available()`、`require_success()` を持つ。
[`DerivativeSource`](https://docs.rs/scioxide-differentiate/0.1.0/scioxide_differentiate/enum.DerivativeSource.html) は値を作った方法で、`FiniteDifference(scheme)`（固定刻み）、`AdaptiveDifference`、`ColoredDifference`、`NodeDifference`（節点差分）、`ComplexStep` のどれかである。
`completed_entries()` は有限の推定が求まった要素の数、`iterations()` は試みた反復の数である。

終了理由 [`DifferentiationTermination`](https://docs.rs/scioxide-differentiate/0.1.0/scioxide_differentiate/enum.DifferentiationTermination.html) の意味と `require_success()` が返すエラーは [結果の読み方](oxref:differentiate-reading-results) の表にある。
`is_success()` は `Completed` と `Converged` のときだけ真になる。
終了理由は `Display` を実装し、`to_string()` は列挙子の名前（`"Converged"` など）を返すので、そのまま表や記録に書ける。
終了理由ごとに、それを返す種類と出力への反映は次のとおりである。

| 終了理由 | 返す種類 | 出力への反映 |
|---|---|---|
| `Completed` | 固定刻み、節点差分、複素ステップ法 | 出力に反映する |
| `Converged` | 適応差分、彩色 | 出力に反映する |
| `RoundoffLimit`、`RefinementLimit`、`StepSizeLimit` | 適応差分、彩色 | すべての要素に推定があれば出力に反映する |
| `EvaluationLimit`、`IterationLimit` | すべて | 出力に反映しない |
| `Cancelled`、`DeadlineReached` | すべて | 出力に反映しない |

固定刻み、節点差分、複素ステップ法の `Completed` は、予定した差分の公式をすべて評価し終えたことだけを表し、精度については何も主張しない。
適応差分と彩色の `Converged` は、すべての要素で連続する 2 つの準位の推定誤差と最良の推定値の推定誤差が許容誤差を満たしたことを表すが、推定誤差は上界ではない（[Richardson 外挿と Ridders の方法](../richardson-and-ridders/)）。

結果を出力に反映するかどうかは `output_available()` だけで決まる。
出力に反映されるのは、終了理由が `Completed` のときと、すべての要素に推定が求まり（`completed_entries()` が出力の長さに等しい）、上限、取り消し、期限による停止がないときである。
適応差分は座標ごとに外挿を進め、推定を持たないまま止まった座標があれば残りの座標を評価しない。
推定を持って止まった座標（`RoundoffLimit` など）のあとは、残りの座標の評価を続ける。
出力に反映されないときとエラーのときは、出力先を指定する API の出力の配列は書き換えられない。
所有値を返す API の結果では、出力に反映されないとき `values()` と `errors()` が `None` になる。

関数のエラーは `DifferentiationFailure` に包まれて返る。
`DifferentiationFailure` は標本の位置と評価回数を記録し、原因の `source()` に関数が返したエラーをそのまま保つ。
関数が有限でない値を書き込むか、出力の一部を書き込まなければ、原因が `NonFinite`（`Callback`）の `DifferentiationFailure` になる。
標本点や差分の和が有限の範囲を超えたときは、原因が `NumericalInstability` になる。

## 上限に達した評価と出力

次の二つのセルは $f(\mathbf{x}) = \sum_i e^{x_i}$ の $\mathbf{x} = (0.1, 0.2, 0.3, 0.4)$ での勾配を、評価回数か反復回数の上限 $L$ を付けて `gradient_into` で求める。
勾配の厳密値は $\partial f / \partial x_i = e^{x_i}$ である。
出力の配列には評価の前に NaN を入れておき、出力に反映されなかったときに配列が書き換えられないことを確かめる。

最初のセルは方法（固定刻みの中心差分か、適応差分の Ridders 法）と上限の種類を入力として、$L = 1, \ldots, 60$ のそれぞれで 1 回ずつ評価する。
表は、推定が求まった要素が $k$ 個になる最小の $L$ と、出力が出力に反映される最小の $L$ を、その $L$ での終了理由とともに示す。
各 $L$ のレポートと出力の第 1 成分は次のセルに渡す。

中心差分の勾配は $f(\mathbf{x})$ の 1 回と座標ごとの 2 回で評価し、反復は座標ごとに 1 回なので、要素 $k$ 個の推定がそろう最小の $L$ は評価回数で $1 + 2k$、反復回数で $k$ と予想できる。
適応差分は座標ごとに準位を進め、2 準位目から推定を持つ。
この関数では各座標が 6 準位で収束するので、要素 $k$ 個の推定がそろうのは反復回数で $6(k - 1) + 2$、評価回数で $1 + 2\{6(k - 1) + 2\}$ のときである。

```rust
//| id: differentiate-budget-sweep
//| ref: differentiate-budget-sweep
//| title: 上限 L ごとの評価と推定がそろう最小の上限
//| run: reactive
//| crates: [scioxide-core, scioxide-differentiate]
//| exports: [method, records]
//| inputs:
//|   method: {"type":"select","label":"方法","options":["固定刻み（中心差分）","適応差分（Ridders）"],"value":"固定刻み（中心差分）"}
//|   budget: {"type":"select","label":"上限の種類","options":["評価回数","反復回数"],"value":"評価回数"}
//| cases:
//|   - {"id":"fixed-iterations","label":"固定刻み、反復回数","description":"反復 1 回が座標 1 つなので、要素 k 個の推定は L = k でそろい、L = 4 から出力に反映される。","inputs":{"budget":"反復回数"}}
//|   - {"id":"adaptive-evaluations","label":"適応差分、評価回数","description":"推定は L = 5、17、29、41 で 1 個ずつ増えるが、出力への反映はすべての要素が収束する L = 49 からである。","inputs":{"method":"適応差分（Ridders）"}}
//|   - {"id":"adaptive-iterations","label":"適応差分、反復回数","description":"推定は L = 2、8、14、20 で 1 個ずつ増え、すべての要素が収束する L = 24 から出力に反映される。","inputs":{"method":"適応差分（Ridders）","budget":"反復回数"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"thresholds","path":"/rows/0/1","equals":3}
//|       - {"artifact":"thresholds","path":"/rows/1/1","equals":5}
//|       - {"artifact":"thresholds","path":"/rows/3/1","equals":9}
//|       - {"artifact":"thresholds","path":"/rows/3/2","equals":"Completed"}
//|       - {"artifact":"thresholds","path":"/rows/2/2","equals":"EvaluationLimit"}
//|       - {"artifact":"thresholds","path":"/rows/4/1","equals":9}
//|   - case: fixed-iterations
//|     expect:
//|       - {"artifact":"thresholds","path":"/rows/0/1","equals":1}
//|       - {"artifact":"thresholds","path":"/rows/2/2","equals":"IterationLimit"}
//|       - {"artifact":"thresholds","path":"/rows/4/1","equals":4}
//|   - case: adaptive-evaluations
//|     expect:
//|       - {"artifact":"thresholds","path":"/rows/0/1","equals":5}
//|       - {"artifact":"thresholds","path":"/rows/3/1","equals":41}
//|       - {"artifact":"thresholds","path":"/rows/3/2","equals":"EvaluationLimit"}
//|       - {"artifact":"thresholds","path":"/rows/4/1","equals":49}
//|       - {"artifact":"thresholds","path":"/rows/4/2","equals":"Converged"}
//|   - case: adaptive-iterations
//|     expect:
//|       - {"artifact":"thresholds","path":"/rows/1/1","equals":8}
//|       - {"artifact":"thresholds","path":"/rows/3/1","equals":20}
//|       - {"artifact":"thresholds","path":"/rows/4/1","equals":24}
use scioxide_core::{
    Budget, BudgetKind, ExecutionContext, SciOxideError, RealScalar, SolveBudgets,
};
use scioxide_differentiate::{
    AdaptiveDifference, AdaptiveDifferenceWorkspace, DerivativeRequest, DerivativeShape,
    FiniteDifference, FiniteDifferenceWorkspace,
};

let x = [0.1_f64, 0.2, 0.3, 0.4];
// f(x) = Σ e^{xᵢ}。
let f = |p: &[f64], y: &mut [f64]| {
    y[0] = p.iter().map(|&v| RealScalar::exp(v)).sum();
    Ok::<(), SciOxideError>(())
};
let kind = match budget.as_str() {
    "評価回数" => BudgetKind::Evaluation,
    _ => BudgetKind::Iteration,
};
let adaptive_method = method != "固定刻み（中心差分）";
let shape = DerivativeShape::gradient(4);
let (fixed, adaptive) = (FiniteDifference::default(), AdaptiveDifference::default());
let s = |e: SciOxideError| e.to_string();
let mut fixed_ws =
    FiniteDifferenceWorkspace::workspace(DerivativeRequest::new(&fixed, shape)).map_err(s)?;
let request = DerivativeRequest::new(&adaptive, shape);
let mut adaptive_ws = AdaptiveDifferenceWorkspace::<f64>::workspace(request).map_err(s)?;
// L = 1, …, 60 で 1 回ずつ評価する。出力は NaN で埋め、書き換えられたかを調べる。
let mut records = Vec::new();
for l in 1..=60_usize {
    let budgets = SolveBudgets::unbounded().with_limit(kind, Budget::try_from(l).map_err(s)?);
    let (mut out, mut errors) = ([f64::NAN; 4], [f64::NAN; 4]);
    let scope = ExecutionContext::sequential();
    let report = if adaptive_method {
        let method = adaptive.clone().with_budgets(budgets);
        method.gradient_into(f, &x, None, &mut out, &mut errors, &mut adaptive_ws, scope)
    } else {
        let method = fixed.clone().with_budgets(budgets);
        method.gradient_into(f, &x, None, None, &mut out, &mut fixed_ws, scope)
    };
    let report = report.map_err(s)?;
    // 書き換えられていない出力（NaN のまま）は値なし（null）として渡す。
    let first = (!out[0].is_nan()).then_some(out[0]);
    records.push((
        report.termination().to_string(),
        report.is_success(),
        report.output_available(),
        report.evaluations(),
        report.iterations(),
        report.completed_entries(),
        first,
    ));
}
// 推定が k 個そろう最小の L と、出力が出力に反映される最小の L。
let mut rows = Vec::new();
for k in 1..=4 {
    let found = records.iter().position(|r| r.5 >= k);
    let termination = found.map(|i| records[i].0.clone());
    rows.push((
        format!("要素 {k} 個の推定"),
        found.map(|i| i + 1),
        termination,
    ));
}
let found = records.iter().position(|r| r.2);
let termination = found.map(|i| records[i].0.clone());
rows.push(("出力への反映".to_string(), found.map(|i| i + 1), termination));
let columns = serde_json::json!([
    { "key": "0", "label": "事象" },
    { "key": "1", "label": "最小の上限 L [回]", "type": "integer", "nullText": "60 以下にない" },
    { "key": "2", "label": "その L での終了理由", "nullText": "—" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "thresholds" })
);
export!(method, method);
export!(records, records);
```

既定の固定刻み、評価回数の上限では、要素 1、2、3、4 個の推定は $L = 3, 5, 7, 9$ でそろい、予想の $1 + 2k$ に一致する。
要素が 3 個までそろった $L$ でも終了理由は `EvaluationLimit` で、4 個すべてがそろう $L = 9$ で初めて `Completed` になって出力が出力に反映される。
反復回数を上限にすると、推定は $L = 1, 2, 3, 4$ でそろい、$L = 4$ から出力に反映される。

適応差分では、評価回数の上限で推定が $L = 5, 17, 29, 41$ で 1 個ずつ増え、予想の $1 + 2\{6(k - 1) + 2\}$ に一致する。
$L = 41$ から $48$ では 4 要素すべてに推定があるが、終了理由は `EvaluationLimit` で出力に反映されない。
すべての要素が収束する $1 + 4 \cdot 6 \cdot 2 = 49$ 回の評価に届いた $L = 49$ から、`Converged` で出力に反映される。
反復回数を上限にすると、推定は $L = 2, 8, 14, 20$ で増え、24 回の反復に届く $L = 24$ から出力に反映される。

```rust
let outcome = if !success {
    Outcome::partial("上限で止まり、勾配は出力に反映されなかった").explanation(
        "出力の配列は書き換えられていない。上限を増やすか、レポートの評価回数を見て選び直す。",
    )
} else if termination == "Completed" {
    Outcome::satisfied("差分の公式をすべて評価し、勾配を出力に反映した")
        .explanation("Completed は評価を終えたことだけを表し、精度の主張はない。")
} else {
    Outcome::satisfied("すべての要素の推定誤差が許容誤差を満たし、勾配を出力に反映した")
};
emit_outcome!(
    outcome
        .status(termination.as_str())
        .diagnostic("評価回数", evaluations as f64, None)
        .diagnostic("求まった要素", completed as f64, None)
);
```

既定の設定（固定刻みの中心差分、評価回数の上限 6）では、$f(\mathbf{x})$ の 1 回と第 1・第 2 座標の 2 回ずつで 5 回、第 3 座標の 1 回目で 6 回を使い、第 3 座標の 2 回目の評価が上限で拒まれる。
終了理由は `EvaluationLimit`、反復回数は 3、求まった要素は 2 つだが、出力は出力に反映されず、配列は NaN のまま残る。
上限を 9 以上にすると `Completed` で出力に反映され、第 1 成分は厳密値 $e^{0.1}$ と $8.6 \times 10^{-11}$ の差で一致する。
適応差分を選んだときも、上限で止まった評価は推定が求まった要素を一つも出力に反映しない。
上限に達したことはエラーではなくレポートで伝わるので、終了理由と `output_available()` を見て次の行動を決める。

## 関数の受け渡し

関数の渡し方は呼び出す関数とメソッドによって決まっている。

| 呼び出すもの | 受け取る関数 |
|---|---|
| 手法オブジェクトの `derivative`、`second_derivative`（`FiniteDifference`、`AdaptiveDifference`）、`FiniteDifference::derivative_into` | `x` を受け取って `Ok(f(x))` を返すクロージャ（`FnMut(S) -> Result<T, SciOxideError>`、固定刻みでは `T = S`） |
| `ComplexStep::derivative` | 複素数の `z` を受け取って `Ok(f(z))` を返すクロージャ |
| ワンショット呼び出しの `derivative`、`second_derivative`、`physical_difference_derivative`、`complex_step_derivative` | 同じ形の `Fn` のクロージャ（`complex_step_derivative` は複素数の引数と値） |
| ワンショット呼び出しの `gradient`、`hessian` | 点を受け取って値を返す `Fn(&[S]) -> Result<S, SciOxideError>` |
| ワンショット呼び出しの `jacobian`、`jvp`、`sparse_jacobian` | 出力の配列に書く `Fn(&[S], &mut [T]) -> Result<(), SciOxideError>`（`Contextual` と `Parallel` は渡せない） |
| それ以外の手法オブジェクトの演算と、Plan・節点を指定する差分法オブジェクトの評価 | sealed トレイト [`SampleFunction`](https://docs.rs/scioxide-differentiate/0.1.0/scioxide_differentiate/trait.SampleFunction.html) を実装する次の三つの形 |

`SampleFunction` を実装するのは次の三つの形だけで、ほかの型では実装できない。
どの形でも、関数は点の配列を受け取り、出力の配列の $m$ 個の要素をすべて有限な値で書き換える。

| 形 | 関数の型 | 動作 |
|---|---|---|
| クロージャ | `FnMut(&[S], &mut [T]) -> Result<(), SciOxideError>` | 呼び出し側のスレッドで逐次に呼ばれ、最初のエラーで止まる |
| [`Contextual`](https://docs.rs/scioxide-differentiate/0.1.0/scioxide_differentiate/struct.Contextual.html)`(f)` | `FnMut(&[S], &mut [T], &mut SolveContext) -> Result<(), SciOxideError>` | 実行中の求解コンテキストを受け取り、中で行う入れ子の求解を同じ回数の集計に含める。逐次に呼ばれる |
| [`Parallel`](https://docs.rs/scioxide-differentiate/0.1.0/scioxide_differentiate/struct.Parallel.html)`(f)` | `Fn(&[S], &mut [T]) -> Result<(), SciOxideError> + Sync` | 独立な標本を実行コンテキストのエグゼキューターで並列に評価できる |

`Contextual` の関数は受け取った `&mut SolveContext` を内側の出力先を指定する API の `scope` に渡せる。
そうすると内側で関数を呼んだ回数は外側の評価回数の上限にも数えられ、外側の取り消しと期限が内側にも届く。
関数の中で `record_iteration()` を呼ぶと、その反復は差分の評価と同じ反復回数の上限に数えられるが、レポートの `iterations()` には入らない（[最小の実行例](oxref:differentiate-api-minimal-example)）。

`Parallel` の標本をエグゼキューターに配るかどうかは、手法オブジェクトか選択肢の `with_execution` で決める実行の方針 `ExecutionPolicy` で決まる。
既定の `Sequential` と、ワーカーが 1 つで足りる `Auto` では、その場で逐次に評価する。
`Auto` は標本 1 つを処理の 1 単位と数えてワーカーを最大 16 個使い、`Parallel(n)` は標本が 1 つでもエグゼキューターに渡す。
どちらの場合も、1 つの標本でエラーが出ても、まとめて出した残りの標本を評価してから、標本の順で最初のエラーを返す。
複数の標本をまとめて評価に出すのは、適応差分（1 準位で最大 8 標本）と彩色（1 色の 1 準位で最大 3 標本）だけで、固定刻み、複素ステップ法、節点差分は標本を 1 つずつ評価する。
結果は完了の順ではなく標本の順に組み合わせるので、決定論的な関数ならワーカーの数によらず同じ値になる。
所有値を返す API は常に `sequential_native()` のコンテキストで評価し、ブラウザで動くこの本のセルも逐次に実行される。

## まとめ

評価回数と反復回数の上限は手法オブジェクトか `NodeDifferenceOptions` の `with_budgets` で決め、出力先を指定する API に `&mut SolveContext` を渡せば評価回数を外側の求解の上限と共有できる。
上限に達した評価はエラーを返さず、終了理由 `EvaluationLimit` か `IterationLimit` のレポートを返し、推定が求まった要素があっても出力に何も書かない。
出力は `output_available()` が真のときだけ出力に反映され、適応差分と彩色は `Converged` でなくても、すべての要素に推定があれば出力に反映する。
`Completed` は精度を主張しないので、精度は推定誤差か独立な検算で確かめる。
関数の中で行う入れ子の求解や反復を同じ上限で制御するときは `Contextual` を使い、並列に評価するときは `Parallel` と実行の方針を使う。
