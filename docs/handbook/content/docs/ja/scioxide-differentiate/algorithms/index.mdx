`scioxide-differentiate` の方法は固定刻みの差分、節点を指定する差分、適応差分、彩色ヤコビ行列、複素ステップ法の五つの種類に分かれる。
アルゴリズムは種類ごとに違うが、呼び出しの形、評価回数と反復回数の数え方、入力と関数の値の検査、エラーと結果の出力への反映の規則は共通である。
このページでは、各アルゴリズムのページが前提とする記号、用語、約束をまとめ、ページ一覧を示す。
誤差と浮動小数点数の一般的な説明は [浮動小数点数と条件数](../../concepts/floating-point-and-conditioning/)、エラーと部分結果は [エラー仕様と部分結果](../../concepts/errors-and-partial-results/)、作業領域は [実行形式・作業領域・再現性](../../concepts/workspaces-and-reproducibility/) にある。

## 記号

| 記号 | 意味 |
|---|---|
| $\mathbf{x} \in \mathbb{R}^n$、$\mathbf{F}(\mathbf{x}) \in \mathbb{R}^m$ | 評価点と関数の値（スカラー関数では $m = 1$ で、関数を $f$ と書く） |
| $h$、$h_i$ | 刻み幅、座標 $i$ の刻み幅 |
| $\varepsilon = 2^{-52}$ | 倍精度の計算機イプシロン（1 と次の浮動小数点数の差） |
| $u = \varepsilon / 2 = 2^{-53}$ | 丸めの単位（正しく丸めた演算の相対誤差の上界） |
| $\varepsilon_f$ | 関数値の相対誤差の大きさ |
| $p$、$m$ | 打ち切り誤差の次数、微分の階数（多変数と彩色のページでは $m$ は出力の次元） |
| $\Delta_j = x_j - x$ | 節点 $x_j$ の評価点 $x$ からの変位 |
| $w_j$、$s$、$A_w$ | 差分の重み、変位の尺度 $\max_j \lvert \Delta_j \rvert$、正規化した重みの絶対値の和 |
| $\mathbf{J}$、$\mathbf{H}$、$\mathbf{v}$ | ヤコビ行列、ヘッセ行列、方向微分 $\mathbf{J}\mathbf{v}$ の方向 |
| $r$ | 適応差分で刻みを縮める比（Ridders の方法で 1.4、Richardson 外挿で 2） |
| $L$ | 準位（適応差分で刻みを 1 段縮めた差分）の数の上限（`with_max_levels`、既定 16） |

## 手法の分類

| 種類 | 手法オブジェクトと Plan | 推定誤差 | 既知の基準値 `base` | 関数の値 |
|---|---|---|---|---|
| 固定刻みの差分 | `FiniteDifference` | なし | あり | 実数 |
| 節点を指定する差分 | `PhysicalDifferencePlan`、`RelativeDifference`、`FiniteDifferenceStencil` | なし | なし | 実数・複素数 |
| 適応差分 | `AdaptiveDifference` | あり | なし | 実数・複素数 |
| 彩色ヤコビ行列 | `ColoredJacobianPlan` | あり | なし | 実数・複素数 |
| 複素ステップ法 | `ComplexStep`、`ComplexStepPlan`、`RelativeComplexStep` | なし | なし | 実数（関数は複素数で評価） |

座標はどの種類でも実数（`f32` か `f64`）である。
節点を指定する差分、適応差分、彩色は複素数の値を返す関数も受け取り、実部と虚部を実数の座標で別々に微分する。
複素ステップ法は実数の関数を解析的に複素数へ拡張した関数を受け取り、実数の導関数を返す。
`FiniteDifferenceStencil` は関数を呼ばず、呼び出し側が持つ値に掛ける重みだけを作る。
推定誤差を返すのは適応差分と彩色だけで、ほかの種類の完了 `Completed` は予定した評価を終えたことだけを表し、精度を主張しない。

## 呼び出しの形

同じ導関数を、必要な制御の量に応じていくつかの形で求められる。
この章では値と型を役割で次のように呼ぶ。

| 用語 | 型・関数 | 持つもの・役割 |
|---|---|---|
| ワンショット関数 | `derivative`、`second_derivative`、`gradient`、`jacobian`、`hessian`、`jvp`、`sparse_jacobian`、`physical_difference_derivative`、`complex_step_derivative` | 関数と評価点を受け取り、導関数の値だけを返す自由関数 |
| 手法オブジェクト | `FiniteDifference`、`AdaptiveDifference`、`ComplexStep` | 設定（差分公式、刻み、許容誤差、準位の数、上限）だけを持つ。演算はメソッドで選ぶ |
| 節点を指定する差分法オブジェクト | `RelativeDifference`、`RelativeComplexStep` | 座標ごとの変位の並びを持ち、評価点は評価のたびに受け取る |
| Plan | `ColoredJacobianPlan`、`PhysicalDifferencePlan`、`ComplexStepPlan` | 前計算したデータ（彩色の列ごとの行と許容誤差、固定した評価点での節点の重み）を持つ |
| 要件 | `FiniteDifferenceRequirements` など `*Requirements` | 1 回の評価に要る作業領域の大きさ（`bytes()`） |
| 作業領域 | `FiniteDifferenceWorkspace` など `*Workspace` | 評価の途中の値を置くメモリで、事前確保したあとは同じ種類の評価に使い回せる |
| レポート | `DifferentiationReport` | 使った方法（`source()`）、終了理由、評価回数、反復回数、求まった要素の数、出力への反映の有無 |
| 結果 | `DifferentiationResult` | レポート、出力に反映された値、推定誤差 |

手法オブジェクトは `default()` と `with_…` で作り、評価点の長さから入力の次元 $n$ を、ヤコビ行列と方向微分では引数から出力の次元 $m$ を受け取って、設定と次元を評価のたびに検査する。
Plan と節点を指定する差分法オブジェクトは `new` で作り、それぞれが受け取る演算、次元、節点、設定を作成時に検査する。
評価点、区間 `bounds`、方向微分の方向、既知の基準値は評価の引数で、評価点を作成時に固定する `PhysicalDifferencePlan` と `ComplexStepPlan` だけは評価点を受け取らない。
どれも関数に依存しないので、一度作れば多くの評価に使える。

評価の形は三つある。

| 形 | 例 | 返すもの | 作業領域と出力 | 実行コンテキスト |
|---|---|---|---|---|
| ワンショット関数 | `gradient(f, &x)` | 導関数の値（スカラーか `Vec`） | 内部で確保する（`derivative` は確保しない） | `sequential_native()` |
| 所有値を返す API | `method.gradient(f, &x, bounds, base)`、`plan.evaluate(f, bounds)` | `DifferentiationResult` | 呼ぶたびに確保する | `sequential_native()` |
| 出力先を指定する API | `method.gradient_into(f, &x, bounds, base, &mut out, &mut workspace, scope)`、`plan.evaluate_into(…)` | `DifferentiationReport` | 呼び出し側が渡す | 渡した `scope` |

`derivative` 以外のワンショット関数は既定の設定で手法オブジェクトか Plan を作って所有値を返す API を呼び、`into_values()` で値を取り出す。
`derivative` は出力先を指定する API `FiniteDifference::derivative_into` をスタックのメモリだけで呼び、`require_success()` で終了理由を確かめるので、確保をしない。
`derivative`、`second_derivative`、`gradient`、`jacobian`、`hessian`、`jvp` は既定の刻みの中心差分、`sparse_jacobian` は適応差分（既定の設定）による彩色、`physical_difference_derivative` は渡した節点の差分、`complex_step_derivative` は刻み $h = \varepsilon$ の複素ステップ法を使う。
成功でない終了理由はエラーになるので、返る値はいつも成功した評価の値である。
区間、刻み、許容誤差、上限を変えるときと、レポートや推定誤差を読むときは、手法オブジェクトか Plan を使う。

所有値を返す API は名前に `_into` が付かないメソッドで、作業領域と結果の配列を呼ぶたびに確保する。
手法オブジェクトの所有値を返す API は `derivative`、`second_derivative`、`gradient`、`jacobian`、`hessian`、`jvp` で、`ComplexStep` は `derivative`、`gradient`、`jacobian`、`jvp` だけを持つ。
Plan と節点を指定する差分法オブジェクトでは、所有値を返す API は `evaluate` である。
所有値を返す API とワンショット関数は、呼び出したスレッドで逐次に動き、クロックと取り消しを持たないコンテキスト `ExecutionContext::sequential_native()` で評価する。

出力先を指定する API は名前が `_into` で終わり、呼び出し側が用意した出力の配列（適応差分と彩色では推定誤差の配列も）と作業領域に書き、最後の引数に実行コンテキストを受け取る。
コンテキストには最上位の計算なら `ExecutionContext::sequential()` などを、別の求解の中から呼ぶならその求解の `&mut SolveContext` を渡す。
並列のエグゼキューター、取り消し通知、期限はコンテキストを通じて参照するので、これらを使えるのは出力先を指定する API だけである。
十分な作業領域を渡した出力先を指定する API は、数値計算のための確保をしない。
`FiniteDifference::derivative_into` は 1 変数の一階導関数を作業領域なしにスタックのメモリだけで求める出力先を指定する API で、区間を `ExtendedInterval` で受け取る。
要件の求め方、作業領域の事前確保と使い回しは [Plan・要件・作業領域の再利用](plans-workspaces-and-reports/) で扱う。

評価が止まった理由を**終了理由**（`DifferentiationTermination` の値）と呼び、結果の値を書き込むことを**出力への反映**と呼ぶ。
出力に反映したかどうかはレポートの `output_available()` が示し、出力に反映しない評価は出力先を指定する API に渡した出力の配列を変えない。
終了理由ごとの出力への反映の規則は [結果の読み方](oxref:differentiate-reading-results) にまとめてある。
**推定誤差**は、適応差分と彩色が要素ごとに返す絶対誤差の見積もりで、外挿の表の差に、伝播した丸め誤差の上界を加えたものである。
推定誤差は上界ではない。
要素 $D$ は、連続する 2 つの準位で推定誤差が $\mathrm{atol} + \mathrm{rtol}\,\lvert D \rvert$ 以下になり、そのとき採る最良の推定値もこの許容誤差を満たせば、収束したとみなされる（判定の詳細は [Richardson 外挿と Ridders の方法](richardson-and-ridders/)）。

**評価回数**は関数を呼んだ回数で、エラーを返した呼び出しも数える。
関数が実行コンテキストを受け取って中で別の求解を呼んでも、その求解の評価はレポートの評価回数に含めない（scioxide-core の規則により、評価回数の上限には数える）。
**反復回数**は種類ごとに次の単位で数える。

| 種類 | 1 回の反復として数えるもの |
|---|---|
| 固定刻みの差分、節点を指定する差分 | 座標 1 つ（勾配とヤコビ行列の 1 列）、ヘッセ行列の対角要素 1 つと上三角の混合要素 1 つ、固定刻みの方向微分 1 回（節点を指定する差分は方向微分を持たない） |
| 複素ステップ法 | 座標 1 つ、`ComplexStepPlan` と `RelativeComplexStep` のヘッセ行列では座標の順序対 1 つ、方向微分 1 回 |
| 適応差分 | 座標（ヘッセ行列では座標の組）ごとの準位 1 つ、方向微分では準位 1 つ |
| 彩色 | 列ごとの準位 1 つ |

**評価回数の上限**と**反復回数の上限**は scioxide-core の `SolveBudgets` で、手法オブジェクトと節点差分の選択肢 `NodeDifferenceOptions` の `with_budgets` に `SolveBudgets::unbounded().with_limit(BudgetKind::Evaluation, Budget::try_from(k)?)` のように渡す。
Plan は作成時に渡した手法オブジェクトか選択肢の上限を使う。
評価回数の上限は外側の求解と共有され、反復回数の上限はその評価の中だけで数える。
上限に達した評価はエラーではなく、終了理由 `EvaluationLimit` か `IterationLimit` のレポートを返し、値を出力に反映しない。
ワンショット関数は上限を取らない。

同じ関数の勾配を三つの形と四つの種類で求め、ここで定めた評価回数と反復回数の数え方と上限での停止を確かめる実験は、[呼び出しの形と評価回数の実測](call-forms-and-evaluation-counts/) にある。

## 入力と関数の値の検査

入力は 1 回の評価の初めに一度だけ検査し、そのあとアルゴリズムに渡す。
生成した節点と関数の出力は、作るたびに検査する。
主なエラーの分類は次のとおりで、分類は `e.kind()`（`SciOxideErrorKind`）、詳細は `e.view()` で読む。

| 分類 | 主な原因 |
|---|---|
| `InvalidInput` | 範囲外の設定（準位の数が 3 から 64 の外、最小の正規化数より小さい複素ステップの刻み）、演算と次元の不一致、空の区間、区間の外の評価点（`OutOfRange`）、置けない差分公式、足りない節点と重なった節点、演算に合わない方針（`Inconsistent`）、解析的拡張の検査の失敗 |
| `DimensionMismatch` | 評価点・区間・方向・`base`・出力・座標ごとの刻みの長さの不一致、容量の足りない作業領域 |
| `NonFinite` | 有限でない評価点・方向・`base`・節点・複素ステップの刻み（原因 `Input`）、固定刻みの差分の有限でない最終結果（`Output`） |
| `DifferentiationFailure` | 関数のエラー、関数が書いた有限でない値、有限の範囲を出た標本点や差分の和、固定刻みの方向微分で異なる点を置けないとき |
| `NumericalInstability` | 重みの漸化式の破綻、複素ステップ法で 0 でない $\operatorname{Im} f$ が非正規化数になるか、$h$ で割った商が 0 にアンダーフローしたとき |
| `ResourceLimit`、`SizeOverflow`、`AllocationFailure` | 作業領域の上限の超過、表せない大きさ、確保の失敗 |
| `ConvergenceFailure`、`ExecutionStopped` | ワンショット関数と `into_values()` で、成功でない終了理由を変換したもの |

`DifferentiationFailure` は、失敗した場所（基準点、座標、方向など）、それまでの評価回数、原因のエラーを持ち、関数が返したエラーは原因として変えずに保たれる。
評価回数や反復回数の上限に達したことは、所有値を返す API と出力先を指定する API ではレポートの終了理由で、ワンショット関数では `ConvergenceFailure` で伝わる。
複素ステップ法で $\operatorname{Im} f(x + ih)$ がちょうど 0 のときは、真の導関数 0 と区別できないのでエラーにならず、導関数 0 を返す（[複素ステップ微分と解析的拡張](complex-step/)）。

## 基準値の扱い

導関数の重みの和は 0 なので、標本から定数を引いても結果は数学的に変わらない。
丸めの漏れを減らすために引く値は、種類によって違う。

- 固定刻み、適応差分、彩色は評価点での値 $f(\mathbf{x})$ を引く。
  そのため中心差分でも $f(\mathbf{x})$ を評価する（固定刻みでは `base` で省ける）。
- 節点を指定する差分は評価点に最も近い標本とその鏡像の標本の中点（鏡像がなければ最も近い標本）を引き、評価点を別に評価しない。
- 複素ステップ法の一階は引き算を使わない。
  基準点での評価は、値が実数であることの検査にだけ使う。

## 失敗したときの出力

出力先を指定する API は結果を出力に反映するときだけ呼び出し側の配列に書き込み、エラーのときと出力に反映しないときは配列を変えない。
次のセルは 3 変数の関数 $f(\mathbf{x}) = \lVert \mathbf{x} \rVert_2^2$ の勾配を、区間 $x_i \ge 0$ のもとで $\mathbf{x} = (1, 2, 3)$ で求める。
方法は固定刻みの中心差分で、出力先を指定する API `gradient_into` で呼ぶ。
関数は入力で選んだ回の呼び出しでエラーを返すか、有限でない値を書く。
あわせて、NaN を含む評価点、区間の外の評価点、長さの違う評価点、失敗しない関数の場合も試す。
中心差分は評価点を 1 回、各座標で 2 回評価するので、呼び出しの順は基準点、座標 0、座標 0、座標 1、座標 1、座標 2、座標 2 である。
表は結果の分類（成功なら終了理由）、`DifferentiationFailure` の原因の分類、失敗した場所、エラーに記録された評価回数、関数を呼んだ回数、値が変わった出力の成分の数を示す。

```rust
//|       - {"artifact":"failures","path":"/rows/1/6","equals":0}
//|       - {"artifact":"failures","path":"/rows/2/1","equals":"NonFinite"}

};
use scioxide_differentiate::{
    DerivativeRequest, DerivativeShape, FiniteDifference, FiniteDifferenceWorkspace,
};

let failing = failing as usize;
let method = FiniteDifference::<f64>::default();
let request = DerivativeRequest::new(&method, DerivativeShape::gradient(3));
let mut workspace = FiniteDifferenceWorkspace::workspace(request).map_err(|e| e.to_string())?;
let bounds = Bounds::new(vec![(Some(0.0), None); 3]).map_err(|e| e.to_string())?;
let mut rows = Vec::new();
for case in [

    "有限でない値",

    "区間の外の評価点",
    "長さの違う評価点",
    "失敗しない関数",
] {
    let x: Vec<f64> = match case {
        "NaN を含む評価点" => vec![1.0, f64::NAN, 3.0],
        "区間の外の評価点" => vec![1.0, -2.0, 3.0],
        "長さの違う評価点" => vec![1.0, 2.0],
        _ => vec![1.0, 2.0, 3.0],
    };
    let mut count = 0;
    let initial = [7.0; 3];
    let mut out = initial;
    let result = method.gradient_into(
        |p: &[f64], y: &mut [f64]| {
            count += 1;
            if count == failing && case == "関数のエラー" {
                return Err(SciOxideError::external("モデルの評価に失敗"));
            }
            y[0] = if count == failing && case == "有限でない値" {
                f64::NAN
            } else {
                p.iter().map(|v| v * v).sum()
            };
            Ok(())
        },
        &x,
        Some(&bounds),
        None,
        &mut out,
        &mut workspace,
        ExecutionContext::sequential(),
    );
    // (分類か終了理由, 原因の分類, 失敗した場所, 記録された評価回数)
    let (kind, cause, site, recorded) = match result {
        Ok(report) => (report.termination().to_string(), None, None, None),
        Err(e) => match e.view() {
            SciOxideErrorView::DifferentiationFailure { frames, cause } => {
                let place = match frames[0].location.site() {
                    DifferentiationSite::BasePoint => "基準点".to_string(),
                    DifferentiationSite::Variable(i) => format!("座標 {i}"),
                    other => format!("{other:?}"),
                };
                let kind = format!("{:?}", e.kind());
                (
                    kind,
                    Some(format!("{:?}", cause.kind())),
                    Some(place),
                    Some(frames[0].evaluations),
                )
            }
            _ => (format!("{:?}", e.kind()), None, None, None),
        },
    };
    let changed = out.iter().zip(&initial).filter(|(a, b)| a != b).count();
    rows.push((case, kind, cause, site, recorded, count, changed));
}
let columns = serde_json::json!([
    { "key": "0", "label": "場合" },
    { "key": "1", "label": "結果 e.kind() か終了理由" },
    { "key": "2", "label": "原因の分類", "nullText": "－" },
    { "key": "3", "label": "失敗した場所", "nullText": "－" },
    { "key": "4", "label": "記録された評価回数 [回]", "type": "integer", "nullText": "－" },
    { "key": "5", "label": "関数を呼んだ回数 [回]", "type": "integer" },
    { "key": "6", "label": "値が変わった出力の成分 [個]", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "failures" })
);
```

既定の $k = 4$ では、4 回目の呼び出し（座標 1 の 1 回目の標本）で関数がエラーを返し、結果は原因 `External` の `DifferentiationFailure` になる。
エラーには失敗した場所「座標 1」と評価回数 4 が記録され、出力の配列は初期値の 7 のまま変わらない。
有限でない値を書いた場合も `DifferentiationFailure`（原因 `NonFinite`）で、出力は変わらない。
NaN を含む評価点は `NonFinite`、区間の外の評価点は `InvalidInput`、長さの違う評価点は `DimensionMismatch` で、いずれも関数を一度も呼ばずに拒まれる。
失敗しない関数では 7 回の評価で `Completed` になり、出力の 3 成分がすべて書き換わる。
$k = 1$ にすると、最初の呼び出しが基準点の評価なので、失敗した場所は基準点になり、記録された評価回数は 1 になる。

## まとめ

`scioxide-differentiate` の方法は五つの種類に分かれ、どの種類も所有値を返す API と出力先を指定する API で呼べ、よく使う計算にはワンショット関数がある。
値だけが要るならワンショット関数を、終了理由や推定誤差を読むなら所有値を返す API を、確保をなくすときや上限・取り消しを外側の求解と共有するときは出力先を指定する API を選ぶ。
評価回数は関数を呼んだ回数で、反復回数は種類ごとに座標、要素、準位の単位で数え、上限に達した評価は値を出力に反映しない。
入力は評価の初めに一度検査され、関数のエラーや有限でない値は `DifferentiationFailure` として場所、評価回数、原因つきで返る。
エラーのときと出力に反映しないときは借用した出力の配列が変わらないので、エラーの分類と終了理由を読んでから次の行動を決められる。
