`scioxide-differentiate` は、固定刻みの差分、適応差分、複素ステップ法の手法オブジェクトとワンショット関数、節点を指定する差分と彩色ヤコビ行列の Plan、結果、関数の受け渡し、導関数のプロバイダーの選択の型を提供する。
このガイドは目的から適した項目を示し、公開されている 48 項目を用途別の三つの表のページにまとめる。
表の項目名のリンクは、docs.rs の 0.1.0 の API リファレンスを指す。

## 目的別の API

| したいこと | API となる項目 | 表 |
|---|---|---|
| 導関数・勾配・ヤコビ行列・ヘッセ行列を既定の設定で一行で求める | `derivative`、`second_derivative`、`gradient`、`jacobian`、`hessian`、`jvp` | [ワンショット呼び出し・結果・選択](oxref:differentiate-api-one-shots) |
| 区間、差分公式、刻み、既知の基準値を指定して固定刻みで求める | `FiniteDifference`、`DifferenceScheme`、`DifferenceStep` | [固定刻みと節点の差分](oxref:differentiate-api-fixed) |
| ヤコビ行列とベクトルの積を求める | `jvp`、`FiniteDifference::jvp`、`AdaptiveDifference::jvp`、`ComplexStep::jvp` | [固定刻みと節点の差分](fixed-and-node-differences/)、[適応差分・彩色・複素ステップ](adaptive-colored-and-complex/) |
| 推定誤差とともに導関数を求める | `AdaptiveDifference`、`AdaptiveDifferenceMethod` | [適応差分・彩色・複素ステップ](oxref:differentiate-api-adaptive-colored) |
| 疎なヤコビ行列を少ない評価で求める | `sparse_jacobian`、`ColoredJacobianPlan`（彩色は scioxide-sparse の `derivative_coloring`） | [適応差分・彩色・複素ステップ](oxref:differentiate-api-adaptive-colored) |
| 引き算なしで一階導関数を求める | `complex_step_derivative`、`ComplexStep` | [適応差分・彩色・複素ステップ](oxref:differentiate-api-complex-step) |
| 複素ステップの勾配からヘッセ行列を求める | `ComplexStepPlan`、`RelativeComplexStep` | [適応差分・彩色・複素ステップ](oxref:differentiate-api-complex-step) |
| 表の値や選んだ節点で微分する | `FiniteDifferenceStencil`、`physical_difference_derivative`、`PhysicalDifferencePlan`、`RelativeDifference` | [固定刻みと節点の差分](oxref:differentiate-api-nodes) |
| 反復の中で作業領域を使い回す | `DerivativeRequest`、`DerivativeShape`、出力先を指定する API `_into`、各種類の要件と作業領域 | [ワンショット呼び出し・結果・選択](oxref:differentiate-api-workspace-shapes)、各種類の表、[Plan・要件・作業領域の再利用](../algorithms/plans-workspaces-and-reports/) |
| 結果を読み、出力への反映の有無を判断する | `DifferentiationResult`、`DifferentiationReport`、`DifferentiationTermination`、`DerivativeSource` | [ワンショット呼び出し・結果・選択](oxref:differentiate-api-results)、[評価回数の上限・レポート・結果の出力への反映](../algorithms/budgets-reports-and-publication/) |
| 関数の中の処理を上限で制御する、標本を並列に評価する | `Contextual`、`Parallel`、`SampleFunction` | [ワンショット呼び出し・結果・選択](oxref:differentiate-api-sample-functions) |
| 導関数のプロバイダーを方針で選ぶ | `DerivativeStrategy`、`DerivativeCandidate` | [ワンショット呼び出し・結果・選択](oxref:differentiate-api-strategy) |

このクレートが使う scioxide-core の型は、scioxide-core の API ガイドで引く。
区間の制約 `Bounds` と 1 変数の区間 `ExtendedInterval`、評価回数・反復回数の上限 `Budget` と `SolveBudgets`、許容誤差 `ErrorTolerance` は[定義域・許容誤差・上限](../../scioxide-core/api/domains-tolerances-budgets/)に、実行コンテキスト `ExecutionContext`・`SolveContext`・`SolveScope`、実行の方針 `ExecutionPolicy`、`check` が返す容量の判定 `Capacity` は[求解の回数の集計と実行](../../scioxide-core/api/solve-and-execution/)にある。
複素数 `Complex` は[スカラー・複素数・値の表現](../../scioxide-core/api/scalars-and-values/)に、構造 `StructuralPattern` と彩色 `ColoringSchedule` は[レイアウト・作用素・組合せ](../../scioxide-core/api/layouts-operators-combinatorics/)にある。

## 型の関係

手法オブジェクト `FiniteDifference`、`AdaptiveDifference`、`ComplexStep` は設定だけを持つ値で、`with_scheme`、`with_tolerance`、`with_step` などで設定を変えた新しい値を作る。
演算はメソッド（`derivative`、`second_derivative`、`gradient`、`jacobian`、`hessian`、`jvp`）で選び、入力の次元 $n$ は評価点の長さから、関数の出力の数 $m$ は `jacobian` と `jvp` の引数から決まる。
設定はそれを使う演算を呼ぶたびに検査される。
手法オブジェクトは Plan を持たないので、作業領域は手法オブジェクトと演算の形の組 `DerivativeRequest::new(&method, DerivativeShape::gradient(n))` から、作業領域の型の関連関数 `workspace_requirements(request)` と `workspace(request)` で用意する。
`FixedCoordinatePolicy`（上下限が等しい座標の扱い）と `ZeroDirectionPolicy`（方向が 0 のときの `jvp` の扱い）は手法オブジェクトの設定である。

Plan `ColoredJacobianPlan`、`PhysicalDifferencePlan`、`ComplexStepPlan` と、節点の変位を持つ節点を指定する差分法オブジェクト `RelativeDifference`、`RelativeComplexStep` は `new` で作り、作成時に次元、節点、設定を検査する。
`PhysicalDifferencePlan` と `RelativeDifference` は演算を `DerivativeOperation` で、設定を `NodeDifferenceOptions` で受け取る。
これらは `plan.workspace_requirements(())` と `plan.workspace(())` で要件と作業領域を用意し、`evaluate` と `evaluate_into` で評価する。
要件（`FiniteDifferenceRequirements` など）は確保せずに必要な大きさを返し、作業領域（`FiniteDifferenceWorkspace` など）は `check` で容量を確かめ、`try_reserve` で要件まで広げる。

評価点と方向微分の方向は評価のたびに渡す。
ただし `PhysicalDifferencePlan` と `ComplexStepPlan` は評価点を作成時に固定し、`evaluate` は関数と区間だけを受け取る。
区間 `bounds` は `FiniteDifference` と `AdaptiveDifference` の多変数の演算と、Plan と節点を指定する差分法オブジェクトの評価が受け取り、`ComplexStep` の演算は受け取らない。
既知の基準値 $f(x)$ を `base` で渡せるのは `FiniteDifference` だけである。

関数の受け渡しには二つの系統がある。
スカラーの `derivative`、`second_derivative` と `FiniteDifference::derivative_into` は $x$ を受け取って $f(x)$ を返すクロージャを受け取る（`ComplexStep::derivative` は複素数の引数と値）。
それ以外の演算と Plan は sealed トレイト `SampleFunction` を実装する三つの形のどれかを受け取る。
クロージャ `FnMut(&[S], &mut [T])` は呼び出したスレッドで逐次に呼ばれ、`Contextual(f)` は評価の求解コンテキスト `&mut SolveContext` も受け取り、`Parallel(f)`（`Fn + Sync`）は独立な標本を手法オブジェクトか Plan の `ExecutionPolicy` に従ってエグゼキューターで評価する。
どの形も点を受け取って出力の配列のすべての要素を有限な値で書き換える。
複素ステップ法の関数は実関数の解析的拡張として複素数の点を受け取り、複素数の値を返す。

結果では、所有値を返す API が `DifferentiationResult`（値、推定誤差、レポート）を返し、出力先を指定する API が `DifferentiationReport` だけを返す。
レポートはどの方法で作ったか（`DerivativeSource`）、終了理由（`DifferentiationTermination`）、評価回数、反復回数、求まった要素の数、結果を出力に反映したかを持つ。

`DerivativeStrategy` と `DerivativeCandidate` は Plan ではなく、ソルバーが導関数のプロバイダー（解析式、自動微分、差分）を順に試すための方針と候補である。

## 呼び出しの形

一つの演算は次の三つの形で呼べる。
形の定義は[呼び出しの形](oxref:differentiate-call-forms-terms)に、形の使い分けと作業領域の扱いは[所有値を返す API と出力先を指定する API](oxref:differentiate-owned-borrowed)にある。

| 形 | 例 | 受け取るもの | 返すもの | 実行コンテキスト |
|---|---|---|---|---|
| ワンショット関数 | `derivative(f, x)`、`gradient(f, &x)`、`jacobian(f, &x, m)`、`sparse_jacobian(f, &x, &schedule)` | 関数と点（と出力の数、方向、彩色、節点） | 値だけ。成功でない終了はエラー | `sequential_native()` |
| 所有値を返す API | `method.gradient(f, &x, bounds, base)`、`plan.evaluate(f, &x, bounds)` | 関数、点、区間など | 新しく確保した `DifferentiationResult` | `sequential_native()` |
| 出力先を指定する API `*_into` | `method.gradient_into(f, &x, bounds, base, &mut out, &mut workspace, scope)`、`plan.evaluate_into(…)` | 所有値を返す API の引数に加えて、出力、作業領域、コンテキスト | `DifferentiationReport` | 渡したコンテキスト |

ワンショット関数は既定の設定で一度だけ評価し、値だけを返す。
これらの関数は `Fn` のクロージャを受け取り、`gradient` と `hessian` の関数は点から値を返し、`jacobian`、`jvp`、`sparse_jacobian` の関数は出力の配列に書くので、`Contextual` と `Parallel` は渡せない。
成功でない終了は `require_success` と同じ写像でエラーになる。

所有値を返す API は作業領域と結果を毎回確保し、`ExecutionContext::sequential_native()`（呼び出したスレッドで逐次に動くコンテキスト）で評価する。
出力先を指定する API は呼び出し側の出力の配列、作業領域、コンテキストを借り、十分な作業領域を渡せば数値計算のための確保をしない。
コンテキストに外側の解法の `&mut SolveContext` を渡すと、差分の評価は入れ子の求解になり、関数の評価回数は外側の解法の評価回数の上限にも数えられる（[評価回数・反復回数の上限と求解の回数の集計](oxref:differentiate-budgets)）。

## 最小の実行例：関数の受け渡しの三つの形

次のセルは $f(\mathbf{x}) = \sum_i x_i^2 \sin x_i$ の勾配を、既定の中心差分の `FiniteDifference` で求める。
手法オブジェクトと作業領域（`DerivativeRequest` で大きさを決める）を一度だけ作り、同じ作業領域で、クロージャ、`Contextual`、`Parallel` の三つの形の関数を `gradient_into` に渡す。
三つの形は型が違うので、セルの中の関数 `evaluate` は関数をトレイト境界 `impl SampleFunction<f64, f64>` で受け取る。
点は $x_i = 0.4 + 0.3 i$ で、厳密な勾配 $\partial f / \partial x_i = 2 x_i \sin x_i + x_i^2 \cos x_i$ と比べる。
`Contextual` の関数は受け取ったコンテキストに呼ばれるたびに反復を 1 回計上する。
入力で手法オブジェクトの反復回数の上限を $n$ にすると、この計上が差分の評価と同じ上限に数えられることを確かめられる。

```rust
//| id: differentiate-api-minimal
//| ref: differentiate-api-minimal
//| title: 関数の受け渡しの三つの形とレポートの読み方
//| run: reactive
//| crates: [scioxide-core, scioxide-differentiate]
//| inputs:
//|   n: {"type":"range","label":"変数の数 n [-]","min":1,"max":6,"step":1,"value":3}
//|   limited: {"type":"checkbox","label":"反復回数の上限を n にする","value":false}
//| cases:
//|   - {"id":"iteration-limit","label":"反復回数の上限 n","description":"差分の反復は n 回で上限に収まるが、Contextual の関数が計上した反復で上限を超え、関数がエラーを返す。","inputs":{"limited":true}}
//|   - {"id":"one-variable-limit","label":"n = 1、上限 1","description":"基準点の評価で上限に達し、差分の側が IterationLimit で止まって結果を出力に反映しない。","inputs":{"n":1,"limited":true}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"forms","path":"/rows/0/1","equals":"Completed"}
//|       - {"artifact":"forms","path":"/rows/0/3","equals":"FiniteDifference(Central)"}
//|       - {"artifact":"forms","path":"/rows/0/4","equals":7}
//|       - {"artifact":"forms","path":"/rows/0/5","equals":3}
//|       - {"artifact":"forms","path":"/rows/0/6","equals":3}
//|       - {"artifact":"forms","path":"/rows/0/7","equals":true}
//|       - {"artifact":"forms","path":"/rows/0/8","range":{"max":1e-10}}
//|       - {"artifact":"forms","path":"/rows/1/4","equals":7}
//|       - {"artifact":"forms","path":"/rows/1/5","equals":3}
//|       - {"artifact":"forms","path":"/rows/2/4","equals":7}
//|       - {"artifact":"forms","path":"/rows/2/8","range":{"max":1e-10}}
//|   - case: iteration-limit
//|     expect:
//|       - {"artifact":"forms","path":"/rows/0/1","equals":"Completed"}
//|       - {"artifact":"forms","path":"/rows/0/5","equals":3}
//|       - {"artifact":"forms","path":"/rows/1/1","equals":null}
//|       - {"artifact":"forms","path":"/rows/1/2","equals":"DifferentiationFailure"}
//|       - {"artifact":"forms","path":"/rows/2/1","equals":"Completed"}
//|   - case: one-variable-limit
//|     expect:
//|       - {"artifact":"forms","path":"/rows/0/4","equals":3}
//|       - {"artifact":"forms","path":"/rows/1/1","equals":"IterationLimit"}
//|       - {"artifact":"forms","path":"/rows/1/4","equals":1}
//|       - {"artifact":"forms","path":"/rows/1/7","equals":false}
//|       - {"artifact":"forms","path":"/rows/1/8","equals":null}
use scioxide_core::{
    Budget, BudgetKind, ExecutionContext, SciOxideError, RealScalar, SolveBudgets, SolveContext,
};
use scioxide_differentiate::{
    Contextual, DerivativeRequest, DerivativeShape, FiniteDifference,
    FiniteDifferenceWorkspace, Parallel, SampleFunction,
};

// (形, 終了理由, エラーの分類, source(), 評価回数, 反復回数, 求まった要素, 出力への反映, 最大誤差)
type Row = (
    &'static str,
    Option<String>,
    Option<String>,
    Option<String>,
    Option<usize>,
    Option<usize>,
    Option<usize>,
    Option<bool>,
    Option<f64>,
);
/// 三つの形のどれでも受け取れるように、関数を SampleFunction で受けて gradient_into に渡す。
fn evaluate(
    form: &'static str,
    f: impl SampleFunction<f64, f64>,
    method: &FiniteDifference<f64>,
    x: &[f64],
    workspace: &mut FiniteDifferenceWorkspace<f64>,
    exact: &[f64],
) -> Row {
    let mut gradient = vec![0.0; x.len()];
    let context = ExecutionContext::sequential();
    match method.gradient_into(f, x, None, None, &mut gradient, workspace, context) {
        Ok(report) => {
            let error = report.output_available().then(|| {
                let gaps = gradient.iter().zip(exact).map(|(g, e)| (g - e).abs());
                gaps.fold(0.0, f64::max)
            });
            (
                form,
                Some(report.termination().to_string()),
                None,
                Some(format!("{:?}", report.source())),
                Some(report.evaluations()),
                Some(report.iterations()),
                Some(report.completed_entries()),
                Some(report.output_available()),
                error,
            )
        }
        Err(e) => {
            let kind = format!("{:?}", e.kind());
            (form, None, Some(kind), None, None, None, None, None, None)
        }
    }
}

let n = n as usize;
let x: Vec<f64> = (0..n).map(|i| 0.4 + 0.3 * i as f64).collect();
let value = |p: &[f64]| p.iter().map(|&v| v * v * RealScalar::sin(v)).sum::<f64>();
let budgets = if limited {
    let limit = Budget::try_from(n).map_err(|e| e.to_string())?;
    SolveBudgets::unbounded().with_limit(BudgetKind::Iteration, limit)
} else {
    SolveBudgets::unbounded()
};
let method = FiniteDifference::default().with_budgets(budgets);
let request = DerivativeRequest::new(&method, DerivativeShape::gradient(n));
let mut workspace = FiniteDifferenceWorkspace::workspace(request).map_err(|e| e.to_string())?;
// 参照値: ∂f/∂x_i = 2 x_i sin x_i + x_i² cos x_i（f64 の固有メソッド）。
let exact: Vec<f64> = x
    .iter()
    .map(|v| 2.0 * v * v.sin() + v * v * v.cos())
    .collect();
let closure = |p: &[f64], y: &mut [f64]| {
    y[0] = value(p);
    Ok::<(), SciOxideError>(())
};
// 関数の中の作業を、差分の評価のコンテキストに反復として計上する。
let contextual = Contextual(
    |p: &[f64], y: &mut [f64], context: &mut SolveContext<'_, '_>| {
        context.record_iteration()?.require()?;
        y[0] = value(p);
        Ok::<(), SciOxideError>(())
    },
);
let mut rows = Vec::new();
rows.push(evaluate(
    "クロージャ",
    closure,
    &method,
    &x,
    &mut workspace,
    &exact,
));
rows.push(evaluate(
    "Contextual",
    contextual,
    &method,
    &x,
    &mut workspace,
    &exact,
));
rows.push(evaluate(
    "Parallel",
    Parallel(closure),
    &method,
    &x,
    &mut workspace,
    &exact,
));
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "関数の形" },
    { "key": "1", "label": "termination()", "nullText": "—" },
    { "key": "2", "label": "エラーの分類", "nullText": "なし" },
    { "key": "3", "label": "source()", "nullText": "—" },
    { "key": "4", "label": "evaluations() [回]", "type": "integer", "nullText": "—" },
    { "key": "5", "label": "iterations() [回]", "type": "integer", "nullText": "—" },
    { "key": "6", "label": "completed_entries() [個]", "type": "integer", "nullText": "—" },
    { "key": "7", "label": "output_available()", "type": "boolean", "nullText": "—" },
    { "key": "8", "label": "勾配の最大誤差 [-]", "type": "number", "format": sci3, "nullText": "—" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "forms" })
);
```

既定の $n = 3$ では、三つの形のどれでも `source()` は `FiniteDifference(Central)`、終了理由は `Completed`、評価回数は $2n + 1 = 7$、反復回数と求まった要素の数は $n = 3$ である。
評価回数の 7 は基準点 $f(\mathbf{x})$ の 1 回と、座標ごとの $f(\mathbf{x} \pm h \mathbf{e}_i)$ の 2 回ずつで、反復回数は座標ごとに 1 回である。
勾配の最大誤差は $3.5 \times 10^{-11}$ で、中心差分の誤差の目安 $\varepsilon^{2/3} \approx 4 \times 10^{-11}$ と同じ大きさになる。
`Contextual` の関数が計上した 7 回の反復は差分の評価のコンテキストに数えられるが、レポートの `iterations()` には入らない。
手法オブジェクトの実行の方針は既定の `Sequential` なので、`Parallel` の関数は呼び出したスレッドで実行され、結果はクロージャと同じになる。
三つの形は同じ作業領域を使い回し、評価ごとに作業領域を確保し直さない。

反復回数の上限を $n$ にすると、クロージャと `Parallel` は座標ごとの $n$ 回の反復で上限に収まり、`Completed` になる。
`Contextual` では、関数が計上した反復と差分の座標ごとの反復が同じ上限を使うので、途中で上限を超える。
$n \ge 2$ では関数の中の計上が先に拒まれ、`require()` が返す `ConvergenceFailure` が `DifferentiationFailure` に包まれて呼び出し元に返る。
$n = 1$ では基準点の評価で 1 回を使い切り、差分の側の計上が拒まれて、`Ok` のレポートに終了理由 `IterationLimit` が入り、出力は出力に反映されない。
どちらの場合も出力の配列は書き換えられない。
関数の中で入れ子の求解を行うときは、`Contextual` で受け取ったコンテキストをその求解に渡すと、入れ子の求解の評価回数が差分の評価の評価回数の上限にも数えられる。

## 結果・エラー・診断の読み方

出力を使ってよいかは `output_available()` だけで決まる。
固定刻み、節点、複素ステップの評価は `Completed` で終わったときに出力を書く。
適応差分と彩色は、すべての要素に推定値があり、評価回数・反復回数の上限、取り消し、期限で止まっていないときに書くので、`Converged` のほか `RoundoffLimit`、`RefinementLimit`、`StepSizeLimit` でも値は出力に反映される。
`Completed` は差分公式の評価を終えたことだけを表し、精度は主張しない。
推定誤差を返すのは適応差分と彩色だけで、その推定誤差も上界ではない。
レポートの各値の意味は[レポートと出力への反映の規則](oxref:differentiate-report-rules)にある。
`require_success()` は成功でない終了を `ConvergenceFailure` か `ExecutionStopped` のエラーに写し、`into_values()` とワンショット関数はこのエラーを返す。
途中で止まった適応差分の最良の推定値を使うときは、`values()` か `into_parts()` で読む。

入力の誤り、関数のエラー、作業領域の不足はエラーで返り、分類は `e.kind()`、詳細は `e.view()` で読む。
節点が置けないことは、固定刻みの座標ごとの差分と節点の差分ではエラー（`InvalidInput`）、固定刻みの方向微分では原因が `ConvergenceFailure`（`StepSizeLimit`）の `DifferentiationFailure`、適応差分と彩色では終了理由 `StepSizeLimit` で伝わる。
関数のエラーと有限でない関数の値は `DifferentiationFailure` に包まれ、標本の位置と評価回数を持ち、元のエラーは `source()` で読める。
エラーのときと出力に反映しないとき、出力先を指定する API の出力の配列は書き換えられない（[数値微分のアルゴリズムの共通仕様と構成](oxref:differentiate-input-checks)）。

## まとめ

既定の設定で値だけが要るならワンショット関数を使い、設定を変えるなら手法オブジェクトか Plan を作り、反復の中では要件から作った作業領域を出力先を指定する API で使い回す。
関数はクロージャ、`Contextual`、`Parallel` のどれかで渡し、決定論的な関数ならどの形でも同じ結果と評価回数になる。
関数の中で反復を数えたり入れ子の求解を行ったりするなら、`Contextual` でコンテキストを受け取り、その作業を差分の評価の上限で制御する。
結果は `output_available()` で出力への反映の有無を、`termination()` と推定誤差で信頼性を判断する。
各項目の仕様、エラーの分類、作業領域は、三つの用途別の表で引く。
