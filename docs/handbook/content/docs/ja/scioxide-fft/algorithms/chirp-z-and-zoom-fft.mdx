長さ $N$ の DFT は有限列の $z$ 変換 $X(z)=\sum_{j=0}^{N-1}x_jz^{-j}$ を単位円上の等間隔な $N$ 点で評価する。
チャープ Z 変換（CZT）は評価点を $z$ 平面の円弧か対数螺旋の上に $M$ 個並べ、$M$ を $N$ とは別に選べるようにした変換である。
単位円上の狭い周波数帯だけを細かく評価するものを zoom FFT と呼ぶ。
`scioxide-fft` は 1 回だけ評価する関数 `czt` と `zoom_fft`、輪郭を表す `CztContour`、繰り返し使う Plan `CztPlan` を提供する。
このページでは定義と輪郭の作り方、Plan の使い方、zoom FFT の周波数帯の指定を説明し、減衰振動の極を輪郭の半径で調べる。
CZT を計算する 2 つのアルゴリズムと誤差の上界は [CZT のアルゴリズムの選択と誤差](../czt-algorithms-and-accuracy/)で扱う。

## z 平面の輪郭と CZT の定義

始点 $A$ と隣接点の比 $W$ を与え、評価点を $z_k=AW^{-k}$（$k=0,\ldots,M-1$）とする。
CZT は

$$
X_k = s\sum_{j=0}^{N-1}x_j z_k^{-j} = s\sum_{j=0}^{N-1}x_jA^{-j}W^{jk}
$$

を計算する。
$s$ は `Normalization` が決める係数で、入力長 $N$ を基準に、`Forward` なら $1/N$、`Orthonormal` なら $1/\sqrt N$、`Inverse` と `Unscaled` なら 1 である。
CZT は常に順方向の和なので、`Inverse` を選んでも $1/N$ は掛からない。
出力点数 $M$ は係数に入らない。

`CztContour` は輪郭を対数で保持する。

$$
z_k = \exp\bigl(\rho_0 + k\rho + 2\pi i\,(t_0 + k t)\bigr)
$$

$\rho_0=\ln\lvert A\rvert$ は始点の対数半径、$\rho=-\ln\lvert W\rvert$ は 1 点ごとの対数半径の増分である。
$t_0=\arg A/2\pi$ は始点の位相、$t=-\arg W/2\pi$ は位相の増分で、位相の単位は回転数（1 回転が $2\pi$ rad）である。
$\rho=0$ なら半径 $e^{\rho_0}$ の円弧、$\rho\ne0$ なら対数螺旋になる。
対数で持つので、$e^{\rho_0}$ がスカラー型で表せないほど大きいか小さい輪郭も扱える。
輪郭 `CztContour::dft(n)` の上で $M=N=n$ とすると、CZT は順方向の DFT に一致する。

## 輪郭の作り方

輪郭の作り方は 4 通りある。

- `CztContour::new(log_radius, log_radius_step, start_turns, step_turns)` は $\rho_0,\rho,t_0,t$ をそのまま受け取る。
  どれかが NaN か無限大なら `NonFinite` になる。
- `CztContour::from_wa(w, a)` と関数 `czt(input, m, w, a, normalization)` は、$W$、$A$ の順に複素数で受け取る。
  計算した $\ln\lvert W\rvert$ や $\ln\lvert A\rvert$ の絶対値が $2\varepsilon$（$\varepsilon$ はスカラー型の機械イプシロン）以下なら 0 に丸めるので、丸めた $e^{-2\pi i/N}$ も単位円上の輪郭になる。
  それほど小さい半径の変化を意図して与えるときは `new` を使う。
  $W$ か $A$ が 0 なら `InvalidInput`（`OutOfRange`）、成分が NaN か無限大なら `NonFinite` になる。
- `CztContour::dft(n)` は長さ $n$ の DFT の輪郭 $z_k=e^{2\pi ik/n}$ で、位相 $k/n$ を整数演算で約分する。
  $n=0$ なら `InvalidInput`（`Empty`）になる。
- `CztContour::zoom(start, end, m, fs, endpoint)` は単位円上の周波数帯で、[zoom FFT](#zoom-fft) の節で説明する。

`CztContour::point(k)` は $z_k$ を返す。
Plan は $z_k$ を作らずに対数のまま計算するので、輪郭にスカラー型で表せない点があってもよい。
一方 `point` は、$z_k$ がスカラー型で表せないと `NumericalInstability` を返す。

## Plan、作業領域、リソースの上限

`CztPlanSpec::new(n, m, contour, normalization)` が変換を指定する。
既定は逐次実行、FFT の実装の自動選択、上限なしで、`with_execution_policy`、`with_backend_strategy`、`with_limits` で変える。
`input_len()`、`output_len()`、`contour()`、`normalization()`、`limits()` などで指定を読み返せる。
$N$ か $M$ が 0 なら、準備が `InvalidInput`（`Empty`）を返す。

`CztPlan::new(spec)` が準備し、`CztPlan::build(spec, context)` は `FftPlanningContext` の FFT の実装と実行コンテキストを使う（[外部 FFT 実装の注入](oxref:fft-providers)）。
準備は輪郭と大きさから Bluestein 法か直接和を選び、`algorithm()` が `CztAlgorithm::Bluestein` か `CztAlgorithm::ScaledDirect` を返す。
選択の規則は [アルゴリズムの選択](oxref:fft-czt-algorithm) にある。
`plan_bytes()` は FFT の表を含む Plan のメモリ使用量を返す。

`plan.workspace(())` で作業領域を確保し、`execute_into(input, output, &mut workspace, cx)` で 1 本の列を変換する。
入力は実数か複素数の列（間隔付きや共役のビューも可）で、出力は長さ $M$ の複素数の列に限る。
長さが合わなければ `DimensionMismatch`、入力に NaN か無限大があれば `NonFinite` になる。
結果は作業領域の中で組み立て、成功したときだけ出力へ写すので、失敗した呼び出しは出力を変えない。
`execute_axis_into` は多次元配列の 1 つの軸に沿った全列を変換し、すべての列を書くか、失敗したらどれも書かない。

`CztLimits` はバイト数の上限で、2 つの欄を持つ。

| 欄 | 制限する量 |
|---|---|
| `preparation_bytes` | 準備中に CZT の Plan 自身が同時に保持するメモリ使用量。内部の FFT の Plan と割り当ての付加分は含まない |
| `workspace_bytes` | 実行の作業領域全体。軸ごとの変換の一時領域を含む |

どちらも既定は `usize::MAX` で、超えると `ResourceLimit` になる。
直接和の演算回数には専用の上限がない。

関数 `czt` と `zoom_fft` は呼び出しごとに Plan を準備して捨て、結果を長さ $M$ の新しい `Vec` で返す。
Bluestein 法の準備はチャープ核の FFT を 1 回計算するので、関数の 1 回の呼び出しは長さ $L$ の FFT 3 回になり、Plan を再利用すれば 2 回で済む。
同じ輪郭で多くの列を変換するときは、Plan と作業領域を作って使い回す。

`execute_axis_into` の作業領域は `plan.workspace(AxisWorkspaceRequest::Axis { shape, axis })` で配列の形状 `shape` と変換する軸 `axis` を渡して確保する。
`()` は `AxisWorkspaceRequest::Plain` と同じで、1 本の列の `execute_into` 用である。
軸の作業領域は全列の出力をまとめて持つので、1 本の列の作業領域より大きい。
`workspace_requirements` は確保せずに同じ大きさを返し、`bytes()` でそのバイト数を読める。

次のセルは形状 $[N, 3]$ の行優先の実数の配列の 3 本の列を、$W=\lvert W\rvert e^{-2\pi i/24}$、$A=1$ の輪郭の $M=24$ 点で変換する。
入力は列の長さ $N$ と、$\lvert W\rvert=0.99$ の外向きの螺旋にするか（偽なら $\lvert W\rvert=1$ の単位円）である。
確かめることは 3 つある。
1 本めの列について、関数 `czt` の結果と Plan の `execute_into` の結果を比べる。
軸 0 に沿った `execute_axis_into` の結果を、列ごとの `execute_into` の結果と比べる。
`CztLimits` の `workspace_bytes` を、`workspace_requirements` が返すバイト数ちょうどと 1 バイト少ない値にして準備し、1 本の列と軸 0 の作業領域を確保する。
差は Plan の出力の大きさの最大で割った値で示す。

```rust
//| id: fft-czt-function-axis-limits
//| ref: fft-czt-function-axis-limits
//| title: 関数 czt と Plan、軸に沿った実行、バイト数の上限
//| run: reactive
//| crates: [scioxide-core, scioxide-fft]
//| inputs:
//|   samples: {"type":"integer","label":"列の長さ N","description":"各列の標本数。配列の形状は [N, 3]。","min":4,"max":256,"value":16}
//|   spiral: {"type":"checkbox","label":"|W| = 0.99 の外向きの螺旋にする（外すと単位円）","value":true}
//| cases:
//|   - {"id":"unit-circle","label":"単位円","description":"ρ = 0 なので N によらず Bluestein 法になる。","inputs":{"spiral":false}}
//|   - {"id":"long-spiral","label":"N = 256 の螺旋","description":"NM = 6144 > 4096 だが χ が 0.5 を超え、係数を保持しない直接和になる。","inputs":{"samples":256}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"agreement","path":"/rows/0/0","equals":"ScaledDirect"}
//|       - {"artifact":"agreement","path":"/rows/0/4","range":{"max":1e-14}}
//|       - {"artifact":"agreement","path":"/rows/0/5","range":{"max":1e-14}}
//|       - {"artifact":"limits","path":"/rows/0/2","equals":"成功"}
//|       - {"artifact":"limits","path":"/rows/1/2","equals":"ResourceLimit"}
//|       - {"artifact":"limits","path":"/rows/2/2","equals":"ResourceLimit"}
//|       - {"artifact":"limits","path":"/rows/3/2","equals":"成功"}
//|   - case: unit-circle
//|     expect:
//|       - {"artifact":"agreement","path":"/rows/0/0","equals":"Bluestein"}
//|       - {"artifact":"agreement","path":"/rows/0/4","range":{"max":1e-14}}
//|       - {"artifact":"agreement","path":"/rows/0/5","range":{"max":1e-14}}
//|       - {"artifact":"limits","path":"/rows/1/2","equals":"ResourceLimit"}
//|   - case: long-spiral
//|     expect:
//|       - {"artifact":"agreement","path":"/rows/0/0","equals":"ScaledDirect"}
//|       - {"artifact":"agreement","path":"/rows/0/5","range":{"max":1e-14}}
//|       - {"artifact":"limits","path":"/rows/2/2","equals":"ResourceLimit"}
use scioxide_core::{Complex, ExecutionContext, NdView, NdViewMut};
use scioxide_fft::{
    AxisWorkspaceRequest, CztContour, CztLimits, CztPlan, CztPlanSpec, Normalization, czt,
};

let (n, m, lanes) = (samples as usize, 24_usize, 3_usize);
let tau = 2.0 * std::f64::consts::PI;
// W = |W| e^{−2πi/M}、A = 1（f64 の from_polar と三角関数は入力の生成だけに使う）
let w = Complex::from_polar(if spiral { 0.99 } else { 1.0 }, -tau / m as f64);
let a = Complex::new(1.0, 0.0);
// 形状 [N, 3] の行優先の配列。列 c が軸 0 に沿った 1 本の列
let data: Vec<f64> = (0..n * lanes)
    .map(|i| {
        let (j, c) = ((i / lanes) as f64, (i % lanes) as f64);
        (0.3 * j + c).cos() + 0.5 * (1.1 * j * (c + 1.0)).sin()
    })
    .collect();
let column = |c: usize| -> Vec<f64> { (0..n).map(|j| data[j * lanes + c]).collect() };

let contour = CztContour::from_wa(w, a).map_err(|e| e.to_string())?;
let spec = CztPlanSpec::new(n, m, contour, Normalization::Unscaled);
let plan = CztPlan::new(spec).map_err(|e| e.to_string())?;
let cx = ExecutionContext::sequential();
let mut workspace = plan.workspace(()).map_err(|e| e.to_string())?;
let mut lanes_out = vec![vec![Complex::new(0.0, 0.0); m]; lanes];
for (c, out) in lanes_out.iter_mut().enumerate() {
    plan.execute_into(&column(c)[..], &mut out[..], &mut workspace, cx)
        .map_err(|e| e.to_string())?;
}
let scale = lanes_out
    .iter()
    .flatten()
    .map(|v| v.norm())
    .fold(0.0_f64, f64::max);

// 検算 1: 関数 czt は呼び出しごとに同じ W、A の Plan を作って捨てる
let once = czt(&column(0)[..], m, w, a, Normalization::Unscaled).map_err(|e| e.to_string())?;
let function_gap = once
    .iter()
    .zip(&lanes_out[0])
    .map(|(p, q)| (*p - *q).norm())
    .fold(0.0_f64, f64::max);

// 検算 2: 軸 0 に沿った 3 本の列を 1 回で変換し、出力は形状 [M, 3]
let shape = [n, lanes];
let out_shape = [m, lanes];
let request = AxisWorkspaceRequest::Axis {
    shape: &shape,
    axis: 0,
};
let mut axis_workspace = plan.workspace(request).map_err(|e| e.to_string())?;
let mut stacked = vec![Complex::new(0.0, 0.0); m * lanes];
let x = NdView::row_major(&data, &shape).map_err(|e| e.to_string())?;
let y = NdViewMut::row_major(&mut stacked, &out_shape).map_err(|e| e.to_string())?;
plan.execute_axis_into(x, 0, y, &mut axis_workspace, cx)
    .map_err(|e| e.to_string())?;
let mut axis_gap = 0.0_f64;
for (c, out) in lanes_out.iter().enumerate() {
    for (k, value) in out.iter().enumerate() {
        axis_gap = axis_gap.max((stacked[k * lanes + c] - *value).norm());
    }
}

// workspace_bytes の上限を課して準備し、要求した作業領域を確保する
let plain_bytes = plan
    .workspace_requirements(())
    .map_err(|e| e.to_string())?
    .bytes();
let axis_bytes = plan
    .workspace_requirements(request)
    .map_err(|e| e.to_string())?
    .bytes();
let attempt = |limits: CztLimits, request: AxisWorkspaceRequest| {
    CztPlan::new(spec.with_limits(limits)).and_then(|p| p.workspace(request).map(|_| ()))
};
let label = |outcome: Result<(), scioxide_core::SciOxideError>| match outcome {
    Ok(()) => "成功".to_string(),
    Err(e) => format!("{:?}", e.kind()),
};
let workspace_limit = |bytes: usize| CztLimits {
    workspace_bytes: bytes,
    ..CztLimits::default()
};
let mut rows = Vec::new();
for (limit, request, name) in [
    (plain_bytes, AxisWorkspaceRequest::Plain, "1 本の列"),
    (plain_bytes - 1, AxisWorkspaceRequest::Plain, "1 本の列"),
    (plain_bytes, request, "軸 0"),
    (axis_bytes, request, "軸 0"),
] {
    let outcome = label(attempt(workspace_limit(limit), request));
    rows.push((name, limit, outcome));
}
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let agreement_columns = serde_json::json!([
    { "key": "0", "label": "アルゴリズム" },
    { "key": "1", "label": "plan_bytes() [B]", "type": "integer" },
    { "key": "2", "label": "1 本の列の作業領域 [B]", "type": "integer" },
    { "key": "3", "label": "軸 0 の作業領域 [B]", "type": "integer" },
    { "key": "4", "label": "czt と Plan の差 / 出力の最大 [-]", "type": "number", "format": sci2 },
    { "key": "5", "label": "軸と列ごとの差 / 出力の最大 [-]", "type": "number", "format": sci2 }
]);
let agreement = (
    format!("{:?}", plan.algorithm()),
    plan.plan_bytes(),
    plain_bytes,
    axis_bytes,
    function_gap / scale,
    axis_gap / scale,
);
emit_table_with_columns!(
    agreement_columns,
    vec![agreement],
    metadata = serde_json::json!({ "id": "agreement" })
);
let limit_columns = serde_json::json!([
    { "key": "0", "label": "作業領域の要求" },
    { "key": "1", "label": "workspace_bytes の上限 [B]", "type": "integer" },
    { "key": "2", "label": "結果" }
]);
emit_table_with_columns!(
    limit_columns,
    rows,
    metadata = serde_json::json!({ "id": "limits" })
);
```

既定の $N=16$ の螺旋では $NM=384\le4096$ なので直接和が選ばれ、1 本の列の作業領域は 640 B、軸 0 の作業領域は 2048 B である。
単位円では Bluestein 法になり、1 本の列の作業領域は 1664 B、軸 0 の作業領域は 3072 B になる。
どの場合も、関数 `czt` と Plan の差、軸に沿った実行と列ごとの実行の差はちょうど 0 である。
関数 `czt` は同じ $W$、$A$ から同じ Plan を作り、軸に沿った実行は各列を同じ手順で変換するからである。

`workspace_bytes` を必要なバイト数ちょうどにすると準備と確保が通り、1 バイト少なくすると `ResourceLimit` になる。
準備は 1 本の列の作業領域を上限と比べ、要求ごとの大きさは `workspace` が上限と比べる。
そのため、1 本の列の大きさちょうどの上限では、準備は通るが、軸 0 の作業領域の確保が `ResourceLimit` になる。
$N=256$ の螺旋では $NM=6144>4096$ で、$\chi=\lvert\rho\rvert\max(N,M)^2\approx659>0.5$ なので直接和のままである。
この大きさでは係数を保持しないので、1 本の列の作業領域は複素数 $M+N$ 個ではなく $M+2N$ 個分の 8576 B になる。

## zoom FFT

`CztContour::zoom(start, end, m, fs, endpoint)` と `zoom_fft(input, start, end, m, fs, endpoint, normalization)` は、単位円上の周波数

$$
f_k = \mathrm{start} + k\Delta, \qquad z_k = e^{2\pi i f_k/f_s}, \qquad k=0,\ldots,m-1
$$

で評価する。
`endpoint` が真なら $\Delta=(\mathrm{end}-\mathrm{start})/(m-1)$ で終点を含み、偽なら $\Delta=(\mathrm{end}-\mathrm{start})/m$ で終点を含まない。
$m=1$ なら start だけを評価する。
負の周波数や start > end の降順の帯域も指定できる。
$f_s$ で割った帯域の幅がちょうど 1 回転（end − start = $f_s$）なら、位相を `dft` と同じく整数演算で約分する。
$m=0$ は `InvalidInput`（`Empty`）、$f_s\le0$ は `InvalidInput`（`OutOfRange`）、start、end、$f_s$ が有限でなければ `NonFinite` である。
start$/f_s$ か刻み $\Delta/f_s$ が `f64` の範囲を超えると `NumericalInstability`（`Overflow`）になる。

$z_k^{-j}=e^{-2\pi i jf_k/f_s}$ なので、zoom FFT は有限列の離散時間 Fourier 変換（DTFT）$X(f)=\sum_jx_je^{-2\pi ijf/f_s}$ を $f_k$ で評価する。
これは長いゼロパディングの FFT の一部を取り出すのと同じ値である。
評価点を細かくしても、周波数分解能は観測時間 $T=N/f_s$ で決まる約 $1/T$ のままである。
観測時間と評価点数の違いは例題 [zoom FFT による狭帯域の精密スペクトル](../../examples/zoom-fft-tone-resolution/)で比べる。

## 減衰振動の極と輪郭の半径

標本間隔 $\Delta t=1/f_s$ の減衰振動 $x_j=\rho_s^j\cos(\omega_0 j)$、$\rho_s=e^{-\sigma\Delta t}$、$\omega_0=2\pi f_0\Delta t$ を考える。
$\sigma$ [1/s] は減衰率、$f_0$ [Hz] は振動数である。
無限に続く列なら、$z$ 変換は $z=\rho_s e^{\pm i\omega_0}$ に極を持つ。
半径 $r$ の円弧 $z=re^{i\omega}$ の上で見ると、$\lvert X\rvert$ は $\omega=\omega_0$ の近くで Lorentz 形の山になり、パワーの半値全幅は周波数で約 $\lvert\ln(r/\rho_s)\rvert f_s/\pi$ である。
輪郭が極を通る $r=\rho_s$ で山は最も鋭くなり、山の幅から減衰率を読み取れる。

標本が $N$ 個で終わる有限列では、$z$ 変換は多項式なので極はない。
$q_\pm=\rho_se^{\pm i\omega_0}/z$ とおくと、等比級数の和から

$$
X(z) = \frac12\left(\frac{1-q_+^N}{1-q_+}+\frac{1-q_-^N}{1-q_-}\right)
$$

で、$q_+=1$ の点でも $N/2$ という有限の値になる。
そのため $r=\rho_s$ の山の幅は、観測時間 $T=N\Delta t$ の矩形ウインドウで決まる約 $0.886/T$ にとどまる。
$r<\rho_s$ では重み $r^{-j}$ が後半の標本を増幅し、山はふたたび広がる。

次のセルは $f_s=64$ Hz、$N=256$（$T=4$ s）、$f_0=10$ Hz の減衰振動を、半径 $r=e^{-\sigma_c\Delta t}$ の円弧上の 8〜12 Hz（201 点、0.02 Hz 刻み）で評価する。
輪郭は `CztContour::new` に $\rho_0=-\sigma_c\Delta t$、$\rho=0$、$t_0=8/64$、$t=0.02/64$ を渡して作る。
入力は信号の減衰率 $\sigma$ と輪郭の減衰率 $\sigma_c$ [1/s] で、$\sigma_c=\sigma$ のとき輪郭が極の半径を通る。
独立な検算として、上の等比級数の閉形式を `f64` の固有メソッドで計算する。
差は半径の重みを付けた入力の大きさ $B_k=\sum_j\lvert x_j\rvert r^{-j}$ で割った最大値で示す。
図は山の高さで割った振幅で、半値（パワーが半分）の線との交点の間隔を半値全幅として表に出す。

```rust
//| id: fft-czt-damped-mode
//| ref: fft-czt-damped-mode
//| title: 輪郭の半径を変えて減衰振動の山の幅を測る
//| run: reactive
//| crates: [scioxide-core, scioxide-fft]
//| inputs:
//|   damping: {"type":"range","label":"信号の減衰率 σ [1/s]","description":"x_j = exp(−σ j Δt) cos(2π f0 j Δt) の減衰率。","min":0.5,"max":4,"step":0.5,"value":2}
//|   contour_damping: {"type":"range","label":"輪郭の減衰率 σ_c [1/s]","description":"輪郭の半径 r = exp(−σ_c Δt)。σ_c = σ で極の半径を通る。","min":-1,"max":6,"step":0.25,"value":0}
//| cases:
//|   - {"id":"through-pole","label":"σ_c = σ = 2","description":"輪郭が極の半径を通り、山の幅が観測区間の幅まで狭まる。","inputs":{"contour_damping":2}}
//|   - {"id":"inside-pole","label":"σ_c = 4","description":"r < ρ_s で後半の標本が増幅され、山がふたたび広がる。","inputs":{"contour_damping":4}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"peak","path":"/rows/0/2","approx":{"value":10,"atol":0.011}}
//|       - {"artifact":"peak","path":"/rows/0/4","approx":{"value":0.638,"atol":0.005}}
//|       - {"artifact":"peak","path":"/rows/0/6","range":{"max":1e-13}}
//|   - case: through-pole
//|     expect:
//|       - {"artifact":"peak","path":"/rows/0/3","approx":{"value":128,"rtol":0.01}}
//|       - {"artifact":"peak","path":"/rows/0/4","approx":{"value":0.221,"atol":0.003}}
//|       - {"artifact":"peak","path":"/rows/0/6","range":{"max":1e-13}}
//|   - case: inside-pole
//|     expect:
//|       - {"artifact":"peak","path":"/rows/0/4","approx":{"value":0.638,"atol":0.005}}
//|       - {"artifact":"peak","path":"/rows/0/6","range":{"max":1e-13}}
use scioxide_core::{Complex, ExecutionContext};
use scioxide_fft::{CztContour, CztPlan, CztPlanSpec, Normalization};

let (fs, n, f0) = (64.0_f64, 256_usize, 10.0_f64);
let (f_start, f_step, m) = (8.0_f64, 0.02_f64, 201_usize);
let tau = 2.0 * std::f64::consts::PI;
// 減衰振動 x_j（f64 の exp と cos は入力の生成だけに使う）
let x: Vec<f64> = (0..n)
    .map(|j| (-damping * j as f64 / fs).exp() * (tau * f0 * j as f64 / fs).cos())
    .collect();

// 半径 r = exp(−σ_c Δt) の円弧: ρ0 = −σ_c Δt、ρ = 0、位相は回転数で与える
let log_radius = -contour_damping / fs;
let contour =
    CztContour::new(log_radius, 0.0, f_start / fs, f_step / fs).map_err(|e| e.to_string())?;
let spec = CztPlanSpec::new(n, m, contour, Normalization::Unscaled);
let plan = CztPlan::new(spec).map_err(|e| e.to_string())?;
let mut workspace = plan.workspace(()).map_err(|e| e.to_string())?;
let mut output = vec![Complex::new(0.0, 0.0); m];
plan.execute_into(
    &x[..],
    &mut output[..],
    &mut workspace,
    ExecutionContext::sequential(),
)
.map_err(|e| e.to_string())?;

// 独立な検算: e^u − 1 を打ち消しなしで求め、等比級数の閉形式 (e^{Nu} − 1)/(e^u − 1) を作る
let expm1 = |re: f64, im: f64| {
    let half = (0.5 * im).sin();
    Complex::new(
        re.exp_m1() * im.cos() - 2.0 * half * half,
        re.exp() * im.sin(),
    )
};
let geometric = |re: f64, im: f64| {
    if re == 0.0 && im == 0.0 {
        Complex::new(n as f64, 0.0)
    } else {
        expm1(n as f64 * re, n as f64 * im) / expm1(re, im)
    }
};
// 円弧では重み付きの入力の大きさ B_k = Σ |x_j| r^{−j} が k によらない
let mass: f64 = x
    .iter()
    .enumerate()
    .map(|(j, v)| v.abs() * (-(j as f64) * log_radius).exp())
    .sum();
// u = ln(ρ_s / r) + i(±ω0 − ω_k)
let decay = (contour_damping - damping) / fs;
let omega0 = tau * f0 / fs;
let mut relative_error = 0.0_f64;
let mut magnitudes = Vec::with_capacity(m);
for (k, value) in output.iter().enumerate() {
    let omega = tau * (f_start + k as f64 * f_step) / fs;
    let exact = (geometric(decay, omega0 - omega) + geometric(decay, -omega0 - omega)) * 0.5;
    relative_error = relative_error.max((*value - exact).norm() / mass);
    magnitudes.push(value.norm());
}

// 山の位置と、パワーが半分になる点の線形補間による半値全幅
let peak_index = (0..m)
    .max_by(|&i, &j| magnitudes[i].total_cmp(&magnitudes[j]))
    .unwrap_or(0);
let peak = magnitudes[peak_index];
let level = peak / 2.0_f64.sqrt();
let frequency = |k: usize| f_start + k as f64 * f_step;
let crossing = |inner: usize, outer: usize| {
    let t = (magnitudes[inner] - level) / (magnitudes[inner] - magnitudes[outer]);
    frequency(inner) + t * (frequency(outer) - frequency(inner))
};
let left = (1..=peak_index)
    .rev()
    .find(|&k| magnitudes[k - 1] < level)
    .map(|k| crossing(k, k - 1));
let right = (peak_index..m - 1)
    .find(|&k| magnitudes[k + 1] < level)
    .map(|k| crossing(k, k + 1));
let width = left.zip(right).map(|(a, b)| b - a);

let curve: Vec<[f64; 2]> = magnitudes
    .iter()
    .enumerate()
    .map(|(k, v)| [frequency(k), v / peak])
    .collect();
emit_line_chart!(
    &vec![serde_json::json!({ "name": "|X(r e^{iω})| / 山の高さ", "points": curve })],
    options = &serde_json::json!({
        "xLabel": "周波数 f [Hz]",
        "yLabel": "山の高さで割った振幅 [-]",
        "xMin": 8.0,
        "xMax": 12.0,
        "yMin": 0.0,
        "yMax": 1.05,
        "annotations": [
            { "kind": "line", "axis": "y", "value": 0.7071067811865476, "label": "半値（パワー）" },
            { "kind": "line", "axis": "x", "value": f0, "label": "f0 = 10 Hz" }
        ]
    })
);
let fixed3 = serde_json::json!({ "fractionDigits": 3 });
let sig4 = serde_json::json!({ "significantDigits": 4 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "輪郭の半径 r [-]", "type": "number", "format": sig4 },
    { "key": "1", "label": "極の半径 ρ_s [-]", "type": "number", "format": sig4 },
    { "key": "2", "label": "山の位置 [Hz]", "type": "number", "format": fixed3 },
    { "key": "3", "label": "山の高さ [-]", "type": "number", "format": sig4 },
    { "key": "4", "label": "半値全幅 [Hz]", "type": "number", "format": fixed3, "nullText": "帯域外" },
    { "key": "5", "label": "|σ − σ_c|/π [Hz]", "type": "number", "format": fixed3 },
    { "key": "6", "label": "閉形式との差 / B_k [-]", "type": "number", "format": sci2 },
    { "key": "7", "label": "アルゴリズム" }
]);
let row = (
    log_radius.exp(),
    (-damping / fs).exp(),
    frequency(peak_index),
    peak,
    width,
    (damping - contour_damping).abs() / std::f64::consts::PI,
    relative_error,
    format!("{:?}", plan.algorithm()),
);
emit_table_with_columns!(
    columns,
    vec![row],
    metadata = serde_json::json!({ "id": "peak" })
);
```

既定の $\sigma=2$、$\sigma_c=0$ は単位円上の評価、すなわち DTFT である。
山の半値全幅は 0.638 Hz で、無限列の Lorentz 形の幅 $\sigma/\pi\approx0.637$ Hz に近い。
$\sigma_c=\sigma=2$ にすると、輪郭が極の半径 $\rho_s=e^{-2/64}\approx0.9692$ を通る。
山の高さは $N/2$ に等しい 128.0 になり、幅は 0.221 Hz まで狭まる。
これは $T=4$ s の矩形ウインドウの幅 $0.886/T\approx0.22$ Hz であり、有限列の山の幅はここより狭くならない。
$\sigma_c=4$ では $r<\rho_s$ となり、幅は 0.638 Hz にふたたび広がる。
幅が最小になる $\sigma_c$ を探せば減衰率を推定できるが、ウインドウの幅より細かい差は読み取れない。

どの場合も $NM=51456>4096$、$\rho=0$ なので Bluestein 法が選ばれる。
閉形式との差は既定で $B_k$ の $4.6\times10^{-15}$ 倍、$\sigma_c=2$ と $4$ で $1.7\times10^{-14}$ 倍と $3.1\times10^{-14}$ 倍である。
$\sigma_c=6$ では $r^{-j}$ が最大 $e^{6\cdot255/64}\approx2.4\times10^{10}$ の重みになり、山の高さは $6.7\times10^7$ まで大きくなるが、$B_k$ で割った差は $3.5\times10^{-14}$ にとどまる。
始点の半径は入力の重みとして別の 2 進指数で扱われ、[誤差の上界](oxref:fft-czt-error)の螺旋による拡大 $e^{2\chi}$ に入らないからである。

## まとめ

CZT は $z_k=AW^{-k}$、すなわち対数半径と回転数が等差に並ぶ輪郭の上で有限列の $z$ 変換を評価し、係数 $s$ は入力長 $N$ だけで決まる。
輪郭は `CztContour` の `new`（対数と回転数）、`from_wa`（$W$、$A$）、`dft`、`zoom` で作り、Plan はスカラー型で表せない半径も対数のまま扱う。
多くの列を同じ輪郭で変換するときは `CztPlan` と作業領域を使い回し、関数 `czt` と `zoom_fft` は 1 回きりの評価に使う。
多次元配列の軸に沿って変換するときは `AxisWorkspaceRequest::Axis` で全列の出力を持つ作業領域を確保し、`CztLimits` のバイト数の上限を超えた準備や確保は `ResourceLimit` になる。
zoom FFT は単位円上の等間隔な周波数で DTFT を評価し、`endpoint` で終点を含めるかを選ぶが、分解能は観測時間で決まる。
輪郭の半径を極の半径に合わせると減衰振動の山がウインドウの幅まで狭まり、その位置から減衰率を読み取れる。
