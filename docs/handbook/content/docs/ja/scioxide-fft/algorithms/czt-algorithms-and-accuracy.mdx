[チャープ Z 変換と zoom FFT](../chirp-z-and-zoom-fft/)で定義した CZT

$$
X_k = s\sum_{j=0}^{N-1}x_jA^{-j}W^{jk},\qquad z_k=AW^{-k}=\exp\bigl(\rho_0+k\rho+2\pi i(t_0+kt)\bigr)
$$

を、`CztPlan` は 2 つのアルゴリズムのどちらかで計算する。
1 つは Bluestein の恒等式で和を畳み込みに直し、FFT で $O(L\log L)$ の演算で求める方法である。
もう 1 つは $O(NM)$ の直接和である。
このページでは恒等式を導き、螺旋の輪郭で畳み込みの丸め誤差が拡大される理由、準備がアルゴリズムを選ぶ規則、Bluestein 法の誤差の上界を説明する。

## Bluestein の恒等式

$2jk = j^2 + k^2 - (k-j)^2$ を使い、半整数べき $W^{j^2/2}$ に同じ複素対数の枝を使うと

$$
X_k = s\,W^{k^2/2}\sum_{j=0}^{N-1}\left(x_jA^{-j}W^{j^2/2}\right)W^{-(k-j)^2/2}
$$

になる（Rabiner, Schafer & Rader 1969；Bluestein 1970）。
右辺の和は括弧内の長さ $N$ の列とチャープ核 $W^{-m^2/2}$（$m=-(N-1),\ldots,M-1$）の線形畳み込みである。
これを長さ $L$ = `next_fast_len(N + M − 1)` の巡回畳み込みとして FFT で計算すると、[ゼロパディングの長さ](oxref:fft-zero-padding)と同じ理由で折り返しが起きない。
`next_fast_len` は素因数が 2、3、5、7 だけの長さを返すので、FFT は混合基数のアルゴリズムで計算できる。
Plan は核の変換を準備のときに保持するので、1 回の評価は長さ $L$ の FFT 2 回と $O(N+M)$ の位相の乗算になる。
DFT の輪郭で同じ恒等式を素数長の FFT に使う方法は [Bluestein のアルゴリズム](oxref:fft-bluestein)にある。

単位円上では $\lvert W^{j^2/2}\rvert=1$ で、チャープは位相だけを回す。
螺旋（$\rho\ne0$）では $\lvert W^{j^2/2}\rvert = e^{-\rho j^2/2}$ と $\lvert W^{-(k-j)^2/2}\rvert=e^{\rho(k-j)^2/2}$ が添字の 2 乗で増減する。
畳み込みの途中の項は最終的な項 $x_jz_k^{-j}$ よりずっと大きくなりうるので、足し合わせで打ち消しが起き、FFT の丸め誤差が拡大される。
下の上界では、この拡大が因子 $e^{2\chi}$（$\chi$ は次の節で定義する）で表される。
一方、始点の半径の因子 $e^{-j\rho_0}$ は入力の重みにすぎず、別の 2 進指数で掛けるので、畳み込みの打ち消しを増やさない。

## アルゴリズムの選択

`CztPlan::algorithm()` は、準備で選んだアルゴリズムを `CztAlgorithm::Bluestein` か `CztAlgorithm::ScaledDirect`（指数の範囲を広げた直接和）で返す。
螺旋の広がりを $\chi = \lvert\rho\rvert\max(N,M)^2$ とすると、選択は次の順に決まる。

| 輪郭と大きさ | 選ばれるアルゴリズム |
|---|---|
| 単位円上（$\rho_0=\rho=0$） | `Bluestein` |
| 単位円以外で $NM\le4096$ | `ScaledDirect` |
| 単位円以外で $NM>4096$、$\chi\le0.5$ | `Bluestein` |
| 単位円以外で $NM>4096$、$\chi>0.5$ | `ScaledDirect` |

半径が 1 でない円弧（$\rho_0\ne0$、$\rho=0$）は $\chi=0$ なので、$NM>4096$ なら Bluestein 法になる。
単位円以外の小さい問題では、成分ごとの誤差が小さい直接和を使う。

`ScaledDirect` は 1 回の評価に $O(NM)$ の演算を要し、$NM\le4096$ なら係数を準備で保存する。
各出力は、誤差の評価が許す限り作業精度の補償和で、許さなければ指数の範囲を広げた演算で足す。
足す順序は固定で、スレッド数によらない。
少なくとも 256 項ごとに中止の要求と期限を確かめる。
直接和は FFT を使わないので、`resolved_backends()` は空になる。

## 誤差の上界

Bluestein 法のときの誤差の上界は、組み込みの FFT を使う場合、各出力成分について

$$
\lvert X_k-\hat X_k\rvert \le \lvert s\rvert\, e^{2\chi}\bigl(128\,\varepsilon\, h\, B + 32\,\varepsilon_{64}(D+\chi B)\bigr) + U
$$

である。
$\hat X_k$ は計算値、$\varepsilon$ はスカラー型の、$\varepsilon_{64}$ は `f64` の機械イプシロン、$h=\max(1,\log_2L)$ である。
$B=\sum_j(\lvert\operatorname{Re}x_j\rvert+\lvert\operatorname{Im}x_j\rvert)e^{-j\rho_0}$ は、始点の半径で重みを付けた入力の大きさを表す。
$D=\sum_j(\lvert\operatorname{Re}x_j\rvert+\lvert\operatorname{Im}x_j\rvert)e^{-j\rho_0}(1+\lvert j\rho_0\rvert)$ は $B$ の各項に $1+\lvert j\rho_0\rvert$ を掛けた和で、`f64` で計算する位相と半径の因子の誤差の項に入る。
$U$ は漸次アンダーフローの寄与で、通常の大きさの入力では無視できる。

上界は絶対誤差なので、$B$ よりずっと小さい出力値の相対誤差は大きくなりうる。
$\chi\le0.5$ の制限で、螺旋による拡大 $e^{2\chi}$ は $e\approx2.7$ 以下に抑えられる。
`f64` で $L=480$ なら主要項は $128\,\varepsilon\,h\,B\approx2.5\times10^{-13}B$ である。
注入した FFT の実装を使う場合は、その実装の精度が別に効く。

次のセルは輪郭と大きさを変えて選択規則と誤差を確かめる。
入力は固定で、$x_j=\cos(0.3j)+0.5\sin(0.71j)$ を 6 通りの輪郭で変換し、`algorithm()`、$\chi$、`f64` の直接和との差を $B_k=\sum_j\lvert x_j\rvert\,\lvert z_k\rvert^{-j}$ で割った最大値を並べる。
直接和は $z_k^{-j}=e^{-j(\rho_0+k\rho)}e^{-2\pi ij(t_0+kt)}$ を `f64` の固有メソッドで作る独立な参照計算で、それ自身も $10^{-15}$ 程度の丸め誤差を持つ。

```rust
//| id: fft-czt-algorithm-choice
//| ref: fft-czt-algorithm-choice
//| title: 輪郭と大きさによるアルゴリズムの選択と誤差
//| run: reactive
//| crates: [scioxide-core, scioxide-fft]
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"choice","path":"/rows/0/5","equals":"Bluestein"}
//|       - {"artifact":"choice","path":"/rows/1/5","equals":"Bluestein"}
//|       - {"artifact":"choice","path":"/rows/2/5","equals":"ScaledDirect"}
//|       - {"artifact":"choice","path":"/rows/3/5","equals":"Bluestein"}
//|       - {"artifact":"choice","path":"/rows/4/5","equals":"ScaledDirect"}
//|       - {"artifact":"choice","path":"/rows/5/5","equals":"ScaledDirect"}
//|       - {"artifact":"choice","path":"/rows/3/3","approx":{"value":0.459,"atol":0.001}}
//|       - {"artifact":"choice","path":"/rows/0/6","range":{"max":1e-13}}
//|       - {"artifact":"choice","path":"/rows/3/6","range":{"max":1e-13}}
//|       - {"artifact":"choice","path":"/rows/5/6","range":{"max":1e-13}}
use scioxide_core::{Complex, ExecutionContext};
use scioxide_fft::{CztContour, CztPlan, CztPlanSpec, Normalization};

// (輪郭の説明, N, M, ρ0, ρ): 位相は始点 0.125 回転、刻み 1/(4M) 回転にそろえる
let cases = [
    ("単位円", 256_usize, 201_usize, 0.0_f64, 0.0_f64),
    ("半径 0.97 の円弧", 256, 201, 0.97_f64.ln(), 0.0),
    ("半径 0.97 の円弧（小）", 32, 64, 0.97_f64.ln(), 0.0),
    ("螺旋 ρ = 7e−6", 256, 201, 0.0, 7e-6),
    ("螺旋 ρ = 1e−5", 256, 201, 0.0, 1e-5),
    ("螺旋 ρ = 1e−4", 256, 201, 0.0, 1e-4),
];
let tau = 2.0 * std::f64::consts::PI;
let mut rows = Vec::new();
for (label, n, m, rho0, rho) in cases {
    // 入力の生成と参照の直接和には f64 の固有メソッドを使う
    let x: Vec<f64> = (0..n)
        .map(|j| (0.3 * j as f64).cos() + 0.5 * (0.71 * j as f64).sin())
        .collect();
    let (t0, t) = (0.125_f64, 0.25 / m as f64);
    let contour = CztContour::new(rho0, rho, t0, t).map_err(|e| e.to_string())?;
    let plan = CztPlan::new(CztPlanSpec::new(n, m, contour, Normalization::Unscaled))
        .map_err(|e| e.to_string())?;
    let mut workspace = plan.workspace(()).map_err(|e| e.to_string())?;
    let mut output = vec![Complex::new(0.0, 0.0); m];
    plan.execute_into(
        &x[..],
        &mut output[..],
        &mut workspace,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;
    let mut worst = 0.0_f64;
    for (k, value) in output.iter().enumerate() {
        let (log_r, turns) = (rho0 + k as f64 * rho, t0 + k as f64 * t);
        let mut sum = Complex::new(0.0, 0.0);
        let mut mass = 0.0;
        for (j, &v) in x.iter().enumerate() {
            let weight = (-(j as f64) * log_r).exp();
            sum += Complex::from_polar(v * weight, -tau * j as f64 * turns);
            mass += v.abs() * weight;
        }
        worst = worst.max((*value - sum).norm() / mass);
    }
    let chi = rho.abs() * (n.max(m) as f64).powi(2);
    rows.push((
        label,
        n,
        m,
        chi,
        n * m,
        format!("{:?}", plan.algorithm()),
        worst,
    ));
}
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let sig3 = serde_json::json!({ "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "輪郭" },
    { "key": "1", "label": "N", "type": "integer" },
    { "key": "2", "label": "M", "type": "integer" },
    { "key": "3", "label": "χ = |ρ| max(N, M)² [-]", "type": "number", "format": sig3 },
    { "key": "4", "label": "NM", "type": "integer" },
    { "key": "5", "label": "アルゴリズム" },
    { "key": "6", "label": "直接和との差 / B_k の最大 [-]", "type": "number", "format": sci2 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "choice" })
);
```

表の選択は規則の表と一致する。
半径 0.97 の円弧は $NM=51456$ なら Bluestein 法、$NM=2048$ なら直接和になる。
螺旋は $\chi=0.459$ で Bluestein 法、$\chi=0.655$ と $6.55$ で直接和になる。
差の最大はどの行も $1.3\times10^{-15}$〜$1.1\times10^{-14}$ で、参照の直接和自身の丸め誤差と区別できない。
$L=480$ の上界の主要項 $2.5\times10^{-13}$ より 1 桁以上小さい。
この大きさは選んだ入力と輪郭での値で、一般の輪郭の精度は上の上界で評価する。

## まとめ

CZT は単位円上の輪郭と $\chi=\lvert\rho\rvert\max(N,M)^2\le0.5$ の大きな問題では Bluestein 法（長さ `next_fast_len(N + M − 1)` の FFT 2 回）で計算する。
単位円以外の $NM\le4096$ と $\chi>0.5$ では直接和で計算し、選ばれたアルゴリズムは `algorithm()` で読める。
Bluestein 法の誤差の上界は $B$ に比例する絶対誤差で、螺旋による拡大は $e^{2\chi}\le e$ に抑えられ、始点の半径は拡大に入らない。
出力が $B$ よりずっと小さい成分では相対誤差が大きくなりうるので、そうした成分を使うときは上界と出力の大きさを比べる。
