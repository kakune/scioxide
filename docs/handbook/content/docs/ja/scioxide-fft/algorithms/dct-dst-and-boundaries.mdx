有限区間のデータに DFT を使うと、データを周期的に延長したことになり、両端の値が合わなければ継ぎ目に段差ができる。
段差は高い周波数の成分を生み、係数の減衰を遅くする。
離散コサイン変換（DCT）と離散サイン変換（DST）は、データを端で鏡映（偶対称）または符号反転（奇対称）に延長してから Fourier 変換することに当たり、延長の仕方で端の扱いを選ぶ。
このページは延長と境界条件の対応、`scioxide-fft` が計算する 4 つの型の定義の和と尺度、計アルゴリズムと API を説明する。
各型の核が境界条件で閉じた 2 階差分の固有ベクトルになることは、[差分ラプラシアンの対角化](../laplacian-diagonalization/)で導いて確かめる。

## 対称な延長と境界条件

区間 $[0,L]$ の関数を $x(-t)=x(t)$ と偶に延長すると、Fourier 級数の正弦の項が消え、$\cos(k\pi t/L)$ だけの和になる。
余弦は端で導関数が 0 なので、この展開は Neumann 条件（端での法線方向の導関数が 0）に合う。
$x(-t)=-x(t)$ と奇に延長すると余弦の項が消えて $\sin(k\pi t/L)$ だけの和になり、正弦は端で 0 なので Dirichlet 条件（端の値が 0）に合う。
偶に延長すれば値の段差はなくなるが、導関数まで滑らかにつながるかは元の関数による。

離散の場合は、対称の中心を標本の上（格子点）に置くか、隣り合う標本の中間（半格子点）に置くかも選べる。
左右の端で偶・奇と中心の位置を選ぶ組み合わせが、DCT と DST の I〜IV 型になる。
次の表は各型の核 $c_k[j]$ を標本の添字 $j=0,\ldots,n-1$ の関数として見たときの対称性である。
「格子点 $-1$」は最初の標本の 1 つ外側の格子点、「半格子点 $-\tfrac12$」は外側との中間を指す。

| 型 | 核 $c_k[j]$ | 左端の対称と境界条件 | 右端の対称と境界条件 |
|---|---|---|---|
| DCT-I | $\cos\frac{\pi jk}{n-1}$ | 格子点 0 で偶（Neumann） | 格子点 $n-1$ で偶（Neumann） |
| DCT-II | $\cos\frac{\pi(j+\frac12)k}{n}$ | 半格子点 $-\tfrac12$ で偶（Neumann） | 半格子点 $n-\tfrac12$ で偶（Neumann） |
| DCT-III | $\cos\frac{\pi j(k+\frac12)}{n}$ | 格子点 0 で偶（Neumann） | 格子点 $n$ で奇（Dirichlet） |
| DCT-IV | $\cos\frac{\pi(j+\frac12)(k+\frac12)}{n}$ | 半格子点 $-\tfrac12$ で偶（Neumann） | 半格子点 $n-\tfrac12$ で奇（Dirichlet） |
| DST-I | $\sin\frac{\pi(j+1)(k+1)}{n+1}$ | 格子点 $-1$ で奇（Dirichlet） | 格子点 $n$ で奇（Dirichlet） |
| DST-II | $\sin\frac{\pi(j+\frac12)(k+1)}{n}$ | 半格子点 $-\tfrac12$ で奇（Dirichlet） | 半格子点 $n-\tfrac12$ で奇（Dirichlet） |
| DST-III | $\sin\frac{\pi(j+1)(k+\frac12)}{n}$ | 格子点 $-1$ で奇（Dirichlet） | 格子点 $n-1$ で偶（Neumann） |
| DST-IV | $\sin\frac{\pi(j+\frac12)(k+\frac12)}{n}$ | 半格子点 $-\tfrac12$ で奇（Dirichlet） | 半格子点 $n-\tfrac12$ で偶（Neumann） |

各 $k$ について $j$ を動かしたベクトル $(c_k[j])_j$ は、表の境界条件で閉じた 2 階差分 $u_{j-1}-2u_j+u_{j+1}$ の固有ベクトルになる（G. Strang, "The discrete cosine transform", *SIAM Review* 41(1), 1999）。
例えば DST-I の核は両端の外側の格子点で 0 になる列で、格子点に置いた Dirichlet 条件の差分行列の固有ベクトルである。
DCT-II の核は半格子点で鏡映した列で、セル中心の格子で流束 0 の Neumann 条件を課した差分行列の固有ベクトルである。
8 つの型すべての外側の値の決め方と固有値は、[差分ラプラシアンの対角化](oxref:fft-laplacian-diagonalization)で導き、数値で確かめる。

## 4 つの型の定義と尺度

長さを $n$、出力の添字を $0\le k<n$ とする。
`scioxide-fft` は `Normalization::Unscaled` のとき、端点の重みを含む次の和を計算する（空の和は 0）。

| 型 | DCT の $y_k$ | DST の $y_k$ |
|---|---|---|
| I | $x_0+(-1)^kx_{n-1}+2\sum_{j=1}^{n-2}x_j\cos\frac{\pi jk}{n-1}$ | $\sum_{j=0}^{n-1}x_j\sin\frac{\pi(j+1)(k+1)}{n+1}$ |
| II | $\sum_{j=0}^{n-1}x_j\cos\frac{\pi(j+\frac12)k}{n}$ | $\sum_{j=0}^{n-1}x_j\sin\frac{\pi(j+\frac12)(k+1)}{n}$ |
| III | $x_0+2\sum_{j=1}^{n-1}x_j\cos\frac{\pi j(k+\frac12)}{n}$ | $(-1)^kx_{n-1}+2\sum_{j=0}^{n-2}x_j\sin\frac{\pi(j+1)(k+\frac12)}{n}$ |
| IV | $\sum_{j=0}^{n-1}x_j\cos\frac{\pi(j+\frac12)(k+\frac12)}{n}$ | $\sum_{j=0}^{n-1}x_j\sin\frac{\pi(j+\frac12)(k+\frac12)}{n}$ |

逆変換は双対の型を計算する。
I と IV は自分自身、II と III は互いの双対である。
`idct`、`idst` と逆方向の Plan には、逆にしたい順変換の型を渡す。
例えば `idct(…, DctType::II, …)` は DCT-III を計算する。

無尺度の順変換と逆変換を続けると、入力は次の往復の係数 $R$ 倍になる。

| 型 | DCT の $R$ | DST の $R$ | 最小の長さ |
|---|---|---|---|
| I | $2(n-1)$ | $(n+1)/2$ | DCT-I は 2、DST-I は 1 |
| II | $n$ | $n$ | 1 |
| III | $n$ | $n$ | 1 |
| IV | $n/2$ | $n/2$ | 1 |

`Normalization::Forward` は順変換の出力を $R$ で割り、`Normalization::Inverse` は逆変換の出力を $R$ で割る。
どちらも同じ正規化を両方向に使えば往復で入力に戻る。
`Normalization::Orthonormal` は変換の行列を直交行列にする。
実際に計算する型（逆方向の Plan では双対の型）について、入力の端点に重みを掛け、全体の係数を掛け、指定の出力を $\sqrt2$ で割る。

| 計算する型 | 入力の重み | 全体の係数 | $\sqrt2$ で割る出力 |
|---|---|---|---|
| DCT-I | $x_0$、$x_{n-1}$ に $\sqrt2$ | $1/\sqrt{2(n-1)}$ | $y_0$、$y_{n-1}$ |
| DCT-II | なし | $\sqrt{2/n}$ | $y_0$ |
| DCT-III | $x_0$ に $\sqrt2$ | $1/\sqrt{2n}$ | なし |
| DCT-IV | なし | $\sqrt{2/n}$ | なし |
| DST-I | なし | $\sqrt{2/(n+1)}$ | なし |
| DST-II | なし | $\sqrt{2/n}$ | $y_{n-1}$ |
| DST-III | $x_{n-1}$ に $\sqrt2$ | $1/\sqrt{2n}$ | なし |
| DST-IV | なし | $\sqrt{2/n}$ | なし |

$n=1$ で同じ端点が表に 2 回現れるときは、1 回だけ調整する。


### 定義と尺度の照合

次のセルは非対称な入力 $x_j=1/(1+j)+0.5\,(j\bmod2)$ について 8 つの型を `RealTransformPlan` で計算し、上の表の和と比べる。
和は `f64` の `cos` と `sin` で直接計算した独立な参照値である。
無尺度の順方向と逆方向の Plan を続けて実測した往復の係数 $R$ と、往復の結果と $Rx$ の差、`Orthonormal` での $\lVert y\rVert/\lVert x\rVert$ の 1 からのずれも測る。
長さが足りない型は、Plan の準備で返るエラーの分類を表に示す。
2 つ目の表は一括関数 `idct`・`idst` を同じ $y$ にかけた結果と、逆方向の Plan の結果との相対差を示す。
さらに `Normalization::Inverse` で `dct`・`dst` の後に `idct`・`idst` をかけた結果を $z$ とし、$x$ に戻るかを $\max_j\lvert z_j-x_j\rvert/\max_j\lvert x_j\rvert$ で測る。

//|       - {"artifact":"conventions","path":"/rows/0/1","equals":"InvalidInput"}
//|       - {"artifact":"conventions","path":"/rows/0/3","equals":null}
//|       - {"artifact":"conventions","path":"/rows/3/3","approx":{"value":0.5,"rtol":1e-12}}
//|       - {"artifact":"conventions","path":"/rows/4/3","approx":{"value":1,"rtol":1e-12}}
//|       - {"artifact":"inverse-functions","path":"/rows/0/1","equals":"InvalidInput"}
//|       - {"artifact":"inverse-functions","path":"/rows/0/3","equals":null}
//|       - {"artifact":"inverse-functions","path":"/rows/3/3","range":{"max":1e-14}}
//|   - case: odd
//|     expect:
//|       - {"artifact":"conventions","path":"/rows/1/2","range":{"max":1e-14}}
//|       - {"artifact":"conventions","path":"/rows/3/3","approx":{"value":3.5,"rtol":1e-12}}

use scioxide_core::{ExecutionContext, SciOxideError};
use scioxide_fft::{DctType, DstType, FftDirection, Normalization, dct, dst, idct, idst};
use scioxide_fft::{RealTransformKind, RealTransformPlan, RealTransformPlanSpec};

let n = length.round() as usize;
let nf = n as f64;
let pi = std::f64::consts::PI;
let x: Vec<f64> = (0..n)
    .map(|j| 1.0 / (1.0 + j as f64) + 0.5 * (j % 2) as f64)
    .collect();
// Plan を準備して 1 回実行する。逆方向の Plan には順変換の型を渡す。
let run = |kind: RealTransformKind,
           direction: FftDirection,
           normalization: Normalization,
           input: &[f64]|
 -> Result<Vec<f64>, SciOxideError> {
    let spec = RealTransformPlanSpec::new(input.len(), kind, direction, normalization);
    let plan = RealTransformPlan::<f64>::new(spec)?;
    let mut workspace = plan.workspace(())?;
    let mut output = vec![0.0; input.len()];
    plan.execute_into(
        input,
        &mut output,
        &mut workspace,
        ExecutionContext::sequential(),
    )?;
    Ok(output)
};
// 独立検算: 表の定義の和（f64 の cos と sin による参照値）。添字 0..3 が DCT、4..7 が DST。
let reference = |index: usize, k: usize| {
    let kf = k as f64;
    let kernel = |j: usize| {
        let jf = j as f64;
        match index {
            0 => (pi * jf * kf / (nf - 1.0)).cos(),
            1 => (pi * (jf + 0.5) * kf / nf).cos(),
            2 => (pi * jf * (kf + 0.5) / nf).cos(),
            3 => (pi * (jf + 0.5) * (kf + 0.5) / nf).cos(),
            4 => (pi * (jf + 1.0) * (kf + 1.0) / (nf + 1.0)).sin(),
            5 => (pi * (jf + 0.5) * (kf + 1.0) / nf).sin(),
            6 => (pi * (jf + 1.0) * (kf + 0.5) / nf).sin(),
            _ => (pi * (jf + 0.5) * (kf + 0.5) / nf).sin(),
        }
    };
    let inner = |range: std::ops::Range<usize>| range.map(|j| x[j] * kernel(j)).sum::<f64>();
    // 端点の項 (−1)ᵏ x[n−1]。
    let alternating = if k % 2 == 0 { x[n - 1] } else { -x[n - 1] };
    match index {
        0 => x[0] + alternating + 2.0 * inner(1..n - 1),
        2 => x[0] + 2.0 * inner(1..n),
        6 => alternating + 2.0 * inner(0..n - 1),
        _ => inner(0..n),
    }
};
// 一括関数: inverse が true なら idct・idst（順変換の型を渡す）、false なら dct・dst。
let convenience = |kind: RealTransformKind,
                   inverse: bool,
                   normalization: Normalization,
                   input: &[f64]| match (kind, inverse) {
    (RealTransformKind::Dct(ty), false) => dct(input, ty, normalization),
    (RealTransformKind::Dct(ty), true) => idct(input, ty, normalization),
    (RealTransformKind::Dst(ty), false) => dst(input, ty, normalization),
    (RealTransformKind::Dst(ty), true) => idst(input, ty, normalization),
};
let kinds: [(&str, RealTransformKind, f64); 8] = [
    ("DCT-I", DctType::I.into(), 2.0 * (nf - 1.0)),
    ("DCT-II", DctType::II.into(), nf),
    ("DCT-III", DctType::III.into(), nf),
    ("DCT-IV", DctType::IV.into(), nf / 2.0),
    ("DST-I", DstType::I.into(), (nf + 1.0) / 2.0),
    ("DST-II", DstType::II.into(), nf),
    ("DST-III", DstType::III.into(), nf),
    ("DST-IV", DstType::IV.into(), nf / 2.0),
];
let max_abs = |v: &[f64]| v.iter().fold(0.0_f64, |m, a| m.max(a.abs()));
let norm2 = |v: &[f64]| v.iter().map(|a| a * a).sum::<f64>().sqrt();
let mut rows = Vec::new();
let mut inverse_rows = Vec::new();
for (index, &(label, kind, factor)) in kinds.iter().enumerate() {
    let forward = run(kind, FftDirection::Forward, Normalization::Unscaled, &x);
    let y = match forward {
        Ok(y) => y,
        Err(e) => {
            rows.push((
                label,
                format!("{:?}", e.kind()),
                None,
                None,
                None,
                None,
                None,
            ));
            let status = match convenience(kind, true, Normalization::Unscaled, &x) {
                Ok(_) => "計算".to_string(),
                Err(e) => format!("{:?}", e.kind()),
            };
            inverse_rows.push((label, status, None, None));
            continue;
        }
    };
    let expected: Vec<f64> = (0..n).map(|k| reference(index, k)).collect();
    let gaps: Vec<f64> = y.iter().zip(&expected).map(|(a, b)| a - b).collect();
    let back = run(kind, FftDirection::Inverse, Normalization::Unscaled, &y)
        .map_err(|e| e.to_string())?;
    // 実測の R は ⟨z, x⟩ / ⟨x, x⟩。残差は z − R x を max|x| で割る。
    let measured = back.iter().zip(&x).map(|(a, b)| a * b).sum::<f64>() / norm2(&x).powi(2);
    let residual: Vec<f64> = back.iter().zip(&x).map(|(a, b)| a - factor * b).collect();
    let ortho = run(kind, FftDirection::Forward, Normalization::Orthonormal, &x)
        .map_err(|e| e.to_string())?;
    rows.push((
        label,
        "計算".to_string(),
        Some(max_abs(&gaps) / max_abs(&expected)),
        Some(measured),
        Some(factor),
        Some(max_abs(&residual) / (factor * max_abs(&x))),
        Some((norm2(&ortho) / norm2(&x) - 1.0).abs()),
    ));
    // idct・idst を同じ y に適用し、逆方向の Plan の結果 back と比べる。
    let inverse =
        convenience(kind, true, Normalization::Unscaled, &y).map_err(|e| e.to_string())?;
    let plan_gaps: Vec<f64> = inverse.iter().zip(&back).map(|(a, b)| a - b).collect();
    // Inverse 正規化では順変換が無尺度、逆変換が 1/R 倍なので、往復で x に戻る。
    let coefficients =
        convenience(kind, false, Normalization::Inverse, &x).map_err(|e| e.to_string())?;
    let restored = convenience(kind, true, Normalization::Inverse, &coefficients)
        .map_err(|e| e.to_string())?;
    let restore_gaps: Vec<f64> = restored.iter().zip(&x).map(|(a, b)| a - b).collect();
    inverse_rows.push((
        label,
        "計算".to_string(),
        Some(max_abs(&plan_gaps) / max_abs(&back)),
        Some(max_abs(&restore_gaps) / max_abs(&x)),
    ));
}

既定の $n=8$ では、8 つの型のどれも定義の和との相対差が $8.2\times10^{-16}$ 以下で、表の和がそのまま SciOxide の規約である。
実測の $R$ は表の $14,8,8,4,4.5,8,8,4$ と相対 $3\times10^{-16}$ 以内で一致し、往復の結果と $Rx$ の差も $3\times10^{-16}$ 以下である。
逆方向の Plan に順変換の型を渡して往復が $R$ 倍になることは、II と III が互いの双対として計算されていることを示す。
`Orthonormal` では $\lVert y\rVert/\lVert x\rVert$ の 1 からのずれが $2.2\times10^{-16}$ 以下で、変換が直交であることと合う。
$n=1$ では DCT-I の Plan が `InvalidInput` を返し、ほかの型は計算されて、IV 型の $R$ は $1/2$ になる。
$n=24$ でも定義の和との相対差は $2.4\times10^{-15}$ 以下である。

2 つ目の表では、`idct`・`idst` の結果が逆方向の Plan の結果とどの型でも一致し、差は 0 である。
一括関数は呼び出しごとに同じ型・方向・正規化の `RealTransformPlan` を準備して実行するので、双対の型の選び方も Plan と同じになる。
`Normalization::Inverse` での往復の相対残差は既定の $n=8$ で $3.3\times10^{-16}$ 以下、$n=7$ で $3.9\times10^{-16}$ 以下である。
$n=1$ では `idct(…, DctType::I, …)` も Plan と同じく `InvalidInput` を返す。


## 計アルゴリズムと API

どの型も FFT 1 回に帰着し、計算量は $O(n\log n)$ である。

- DCT-I は長さ $2(n-1)$、DST-I は長さ $2(n+1)$ の対称な延長を実数 FFT で変換する。
- II 型と III 型は偶数長なら長さ $n/2$ の複素 FFT（Makhoul, 1980）、奇数長なら長さ $n$ の実数 FFT を使う。
- IV 型は偶数長なら長さ $n/2$ の複素 FFT、奇数長なら長さ $n$ の実数 FFT を使う。
- DST の II〜IV 型は標本の順序を反転して符号を交互に変え、同じ型の DCT から求める。

一括関数 `dct(input, ty, normalization)`、`idct`、`dst`、`idst` は 1 次元の入力から新しい `Vec` を返す。
同じ長さを繰り返すときは、`RealTransformPlanSpec::new(length, kind, direction, normalization)` から `RealTransformPlan` を準備する。
`RealTransformKind` は `Dct(DctType)` か `Dst(DstType)` で、`DctType::II.into()` のように型から変換できる。
`kind` は常に順変換の型で、逆方向の Plan はその双対を計算する。
Plan は方向と正規化を固定するので、往復には 2 つの Plan を準備する。
`workspace(())` が返す `FftWorkspace` を `execute_into(input, output, scratch, context)` に渡し、入出力は長さ $n$ の実数のスライスである。

エラーは次のとおりである。

- 長さ 0 の入力と長さ 1 の DCT-I は Plan の準備（一括関数では呼び出し）で `InvalidInput` になる。
- 入力の NaN と無限大は `NonFinite`、係数や結果が表せなければ `NumericalInstability`（`Overflow`）になる。
- 入出力の長さが Plan と違うか、作業領域が足りなければ `DimensionMismatch` になる。

多次元の `dctn`、`idctn`、`dstn`、`idstn` と `RealTransformNdPlan` は、選んだ軸ごとに型を指定する。
作業領域と軸の扱いは[多次元の DCT・DST と作業領域](oxref:fft-real-transform-nd-workspace)にある。

## 型の用途

| 型 | 主な用途 |
|---|---|
| DCT-I | 端点を含む Chebyshev–Gauss–Lobatto 点での値から Chebyshev 係数を求める。格子点の Neumann 境界のスペクトル法 |
| DCT-II | JPEG などのブロック変換。Chebyshev 点 $\cos\frac{(2j+1)\pi}{2n}$ での値から Chebyshev 係数を求める。セル中心の Neumann 境界 |
| DCT-III | DCT-II の係数からの復元 |
| DCT-IV、DST-IV | 重なりのある変換（MDCT、MDST）の内部 |
| DST-I | 格子点の Dirichlet 境界の 2 階差分（[高速 Poisson 解法](oxref:fft-fast-poisson)） |
| DST-II | セル中心の格子の Dirichlet 境界（両端の半格子点で奇） |
| DST-III | DST-II の係数からの復元 |

第一種 Chebyshev 多項式 $T_k(\cos\theta)=\cos k\theta$ による展開は、$t=\cos\theta$ と置くと余弦級数になる。
Chebyshev 点での関数値には DCT-II、端点を含む点では DCT-I を使い、和に正規化と端点の重みを合わせて Chebyshev 係数に換算する。

## まとめ

DCT と DST の 8 つの型は両端で偶・奇のどちらに延長するかと、対称の中心を格子点と半格子点のどちらに置くかで決まる。
`scioxide-fft` の型は上の定義の和で、無尺度の往復は入力を $R$ 倍し、`Forward` と `Inverse` は $R$ で割る方向を、`Orthonormal` は直交行列を選ぶ。
逆変換の関数と逆方向の Plan には順変換の型を渡し、II と III は互いの双対として計算される。
DCT-I だけは長さ 2 以上が必要で、ほかの型は長さ 1 から使える。
