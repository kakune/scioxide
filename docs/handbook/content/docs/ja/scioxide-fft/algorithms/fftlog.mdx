[動径方向の変換と離散 Hankel 変換](../radial-transforms/)の離散 Hankel 変換は、等間隔に近い格子を使い、計算量は $O(n^2)$ である。
パワースペクトルと相関関数のように、半径と波数が何桁にも広がる関数では、等間隔の格子は標本数が多くなりすぎる。
FFTLog（Talman 1978、Hamilton 2000）は $\ln r$ の等間隔格子を使い、Hankel 変換を FFT 2 回の $O(n\log n)$ で計算する。
`scioxide-fft` は `FftLogPlan` と簡易 API `fht`、`ifht` を提供する。

## 対数格子と offset

FFTLog の順変換は

$$
A(k) = \int_0^\infty a(r)\, J_\mu(kr)\, k\,dr
$$

を近似する（$J_\mu$ は実数の次数 $\mu$ の第一種 Bessel 関数）。
積分の重みが $r\,dr$ ではなく $k\,dr$ である点が離散 Hankel 変換と違う。

入力と出力は、どちらも刻み $\Delta$ の $n$ 点の対数格子に置く。

$$
\ln r_j = \ln r_c + (j - j_c)\Delta, \qquad
\ln k_j = L - \ln r_c + (j - j_c)\Delta, \qquad
j_c = \frac{n-1}{2}
$$

$r_c$ は入力の中心の半径で、既定は 1 である。
$L = \ln(r_c k_c)$ を offset と呼び、出力の中心 $k_c$ を決める。
2 つの格子は $\ln r_j + \ln k_{n-1-j} = L$ を満たし、入力の範囲 $[r_0, r_{n-1}]$ と出力の範囲はおよそ逆数の関係になる。
$r$ と $k$ の単位は互いに逆数であればよく、$L$ は無次元である。

## Mellin 乗数による導出

バイアスの指数 $q$ を 1 つ選び、$b(r) = a(r)\,(r/r_c)^{-q}$ を考える。
$b$ の $n$ 個の標本を $\ln r$ の周期関数として補間すると、

$$
b(r) = \sum_m c_m \left(\frac{r}{r_c}\right)^{i\omega_m}, \qquad
\omega_m = \frac{2\pi m}{n\Delta}
$$

になる。
係数 $c_m$ は標本 $b(r_j)$ の DFT である。
したがって $a(r)$ はべき関数 $r^{x_m}$（$x_m = q + i\omega_m$）の和で表される。

べき関数の Hankel 変換は閉形式を持つ。

$$
\int_0^\infty r^{x} J_\mu(kr)\, k\,dr = k^{-x}\, U_\mu(x), \qquad
U_\mu(x) = 2^x\,\frac{\Gamma\!\left(\frac{\mu+1+x}{2}\right)}{\Gamma\!\left(\frac{\mu+1-x}{2}\right)}
$$

この積分は $-\mu - 1 < \operatorname{Re} x < 1/2$ で収束し（DLMF 10.22.43）、その外では右辺を Γ の比の解析接続として使う。
各項を変換して出力の格子に代入すると、

$$
A(k_j)\,(k_j r_c)^{q} = \sum_m c_m\, u_m\, e^{-i\omega_m (j - j_c)\Delta}, \qquad
u_m = U_\mu(q + i\omega_m)\, e^{-i\omega_m L}
$$

となる。
右辺も DFT なので、FFTLog は次の 4 段で計算できる。

1. 入力にバイアスの重み $(r_j/r_c)^{-q}$ を掛ける。
2. FFT で $c_m$ を求める。
3. Mellin 乗数 $u_m$ を掛ける。
4. 右辺の和を、逆向きの FFT と添字の反転で求める（$e^{-i\omega_m (j - j_c)\Delta}$ は添字を反転した逆 DFT の核である）。
   出力にはバイアスの重み $(k_j r_c)^{-q}$ を掛ける。

逆方向の Plan は $1/u_m$ と逆数のべき関数を使うので、乗数に零がなければ、順方向の離散の写像を丸めを除いて厳密に戻す。

## バイアスと周期化

FFTLog は $b(r) = a(r)(r/r_c)^{-q}$ を $\ln r$ の周期 $n\Delta$ の周期関数として扱う。
ゼロパディングやウインドウは掛けない。
両端の値 $b(r_0)$ と $b(r_{n-1})$ が大きく違うと、周期延長に段差ができ、その段差が出力に振動（リンギング）として現れる。
出力の側でも、$A(k)\,(k r_c)^{q}$ が周期関数として扱われる。

バイアス $q$ は両端の段差を小さくするために選ぶ。
入力が小さい $r$ で $a(r) \sim r^{s}$ と振る舞うなら、入力の左端の値は $b(r_0) \sim r_0^{s-q}$ である。
右端の値が十分小さい関数では、$q$ を小さくするほど入力の段差が減る。
出力が小さい $k$ で $A(k) \sim k^{t}$ と振る舞うなら、出力の左端の値は $A(k_0)(k_0 r_c)^{q} \sim k_0^{t+q}$ の程度で、逆に $q$ を大きくするほど減る。
さらに、出力は最後に重み $(k r_c)^{-q}$ を掛けて戻すので、周期化による誤差もこの重みで拡大される。
重みは $q > 0$ なら小さい $k$ の側で、$q < 0$ なら大きい $k$ の側で大きくなる。
$q$ は入力と出力の段差と、この重みによる拡大の釣り合いで選ぶ。
入力がべき関数 $a(r) = r^{q}$ そのものなら、$b$ は定数で段差がなく、FFTLog の結果は丸め誤差の範囲で閉形式と一致する。
この性質は[べき乗則の閉形式](oxref:fft-fftlog-power-law-check)で、相関関数への換算の検算に使う。

格子の範囲の外にある関数の値は、周期延長によって反対側から折り返される。
標本数を増やしても範囲 $[r_0, r_{n-1}]$ が同じなら、この折り返しは減らない。
範囲を広げるには $\Delta$ か $n$ を大きくする。

## 低リンギングの offset

$n$ が偶数のとき、DFT の Nyquist 成分 $m = n/2$ は $\pm\omega_{n/2}$ の 2 つの周波数を 1 つの係数で表す。
バイアスが実数なら、Plan は Nyquist の乗数 $u_{n/2}$ をその実部に置き換える。
$u_{n/2}$ の位相 $\varphi$ が $\pi$ の整数倍でないと、この成分の大きさは $\lvert\cos\varphi\rvert$ 倍に縮む。
Hamilton（2000）は、この位相を $\pi$ の整数倍にする offset で出力の振動（リンギング）が小さくなることを示した。
$\lvert\cos\varphi\rvert \le 64\varepsilon$ のときは乗数を 0 とみなす。

乗数の位相は $-\omega_{n/2} L = -\pi L / \Delta$ を含むので、$L$ を $\Delta$ だけ動かすと位相が $\pi$ だけ変わる。
`fftlog_low_ringing_offset(log_spacing, order, initial, bias)` は、位相が $\pi$ の整数倍になる offset のうち `initial` に最も近いものを返す。
戻り値と `initial` の差は $\Delta/2$ 以下である。
この選択は Nyquist 成分の扱いだけを整えるもので、端の段差による誤差や連続の積分との差を消すものではない。

## 乗数の零と極

$U_\mu(x)$ は、分母の Γ が極を持つ点で 0 になり、分子の Γ が極を持つ点で無限大になる。
実数のバイアスでは、$\omega_0 = 0$ の成分で次が起こる。

- $(\mu + 1 - q)/2$ が 0 以下の整数（$q = \mu + 1, \mu + 3, \dots$）なら $u_0 = 0$ である。
  順方向の Plan はその成分を消すだけで実行でき、逆方向の Plan は実行時に `Singular` を返す。
- $(\mu + 1 + q)/2$ が 0 以下の整数（$q = -\mu - 1, -\mu - 3, \dots$）なら $u_0$ は極である。
  順方向の Plan は実行時に `Singular` を返し、逆方向の Plan はその成分を消す。
- 両方が極なら、比の有限な極限（Pochhammer 記号による極限）を使う。
- 前の節の規則で Nyquist の乗数を 0 とみなした場合も、順方向はその成分を消し、逆方向は `Singular` を返す。

零や極を含む仕様でも、Plan の準備は成功する。
随伴は同じ乗数を使うので、同じ場合に失敗する。

## 計算量と精度

準備は $n$ 個の Mellin 乗数を複素数の対数 Γ 関数で f64 で評価する。
$\lvert\omega_m\rvert$ が大きくても Γ の値そのものは作らず、対数のまま差を取るので、Γ の値の桁あふれは起こらない。
実行は選んだスカラー型の長さ $n$ の複素 FFT 2 回と $O(n)$ の掛け算で、作業領域は複素数 $n$ 個と FFT の作業領域である。
乗数とバイアスの重みは仮数と 2 進の指数を別に持つので、途中の値がスカラー型の範囲を超えても、結果が範囲内なら計算できる。

`FftLogDiagnostics::log_multiplier_condition` は、乗数の大きさの最大と最小の比 $\max_m\lvert u_m\rvert / \min_m\lvert u_m\rvert$ の自然対数である。
$q = 0$ では、離散の写像の特異値が $\lvert u_m\rvert$ なので、この値は 2 ノルムの条件数の対数になる。
さらに実数の $\mu$ と $q = 0$ では $\lvert U_\mu(i\omega)\rvert = 1$ なので、$n$ が奇数か、Nyquist の乗数が実数になる低リンギングの offset なら、条件数は 1（対数は 0）である。
偶数の $n$ でそれ以外の offset なら、Nyquist の乗数が $\lvert\cos\varphi\rvert$ 倍に縮むので、対数は $-\ln\lvert\cos\varphi\rvert$ になる。
バイアスを 0 から離すと乗数の大きさが広がり、条件数が大きくなる。
どちらかの方向に零か極があると、値は無限大になる。

rustdoc は FFTLog の精度について数値の上界を示していない。
離散の写像の丸め誤差は、FFT の丸め誤差が乗数の大きさの広がり（条件数）で拡大された程度と見積もれる。
これは見積もりで、試験で確かめた上界ではない。
連続の積分との差は上で述べた周期化、範囲の外への折り返し、$\Delta$ の粗さで決まり、関数ごとに違う。
次のセルのように、解析解か範囲を広げた計算と比べて確かめる。

## Plan と簡易 API

- 仕様 `FftLogPlanSpec::new(length, log_spacing, order, offset, bias, direction)` は、標本数 $n$、刻み $\Delta$、次数 $\mu$、offset $L$、複素数のバイアス $q$、方向を受け取る。
  `with_log_radius_center` は $\ln r_c$ を設定し、両方の格子を動かす（変換の値は $L$ だけで決まる）。
  `with_limits`、`with_iteration_budget`（1 本の変換で $n$ 回）、`with_execution_policy`、`with_backend_strategy` で上限、反復の上限、FFT の実行方針と実装の選び方を設定する。
- 上限 [`FftLogLimits`](https://docs.rs/scioxide-fft/0.1.0/scioxide_fft/struct.FftLogLimits.html) は準備のメモリ使用量 `preparation_bytes`、作業領域のメモリ使用量 `workspace_bytes`、準備の計算量 `preparation_work`（関数の呼び出しと対数 Γ 関数の反復の総数）を持つ。
  既定はすべて上限なしである。
  メモリ使用量の上限を超えると `ResourceLimit`、計算量を使い切ると `ConvergenceFailure` を返す。
- Plan `FftLogPlan::new(spec)` は乗数、重み、FFT の Plan を自分で持つ。
  `build(spec, planning, scope)` は FFT の実装やプロバイダーを選び、準備処理の計算回数を親の求解にも加算する。
- 格子の座標は `log_radius(j)` と `log_frequency(j)` が $\ln r_j$ と $\ln k_j$ を `Result` で返す。
  $j \ge n$ なら `OutOfBounds` である。
- 実行 `execute_into(input, output, workspace, scope)` は長さ $n$ の複素数の列を受け取る。
  作業領域は `workspace(())` で一度確保し、同じ Plan の実行で使い回す。
  `execute_axis_into` は多次元配列の 1 つの軸に沿って各列を変換する。
  実行時の失敗は乗数の極（順方向）か零（逆方向）による `Singular`、結果の桁あふれによる `NumericalInstability`、反復の上限による `ConvergenceFailure` などである。
- 診断 [`FftLogDiagnostics`](https://docs.rs/scioxide-fft/0.1.0/scioxide_fft/struct.FftLogDiagnostics.html) は `diagnostics()` で得る。
  `log_multiplier_condition` と、準備で使った計算量 `preparation_work` を持つ。
- Plan は `LinearOperator` と `AdjointOperator` を実装する。
  随伴は Plan の写像の共役転置を掛ける。
- 簡易 API `fht(a, dln, mu, offset, bias)` は実数の標本と実数のバイアスで順変換を 1 回行い、実数の列を返す（虚部の丸め誤差は捨てる）。
  入力の中心の半径は $r_c = 1$ に固定される。
  `ifht` は `fht` の離散の写像の逆を作用させ、乗数に零がなければ `ifht(fht(a))` は丸めを除いて `a` に戻る。

準備の失敗は次のとおりである。
長さが 0 か $\Delta \le 0$ なら `InvalidInput`、次数、刻み、offset、中心、バイアスに NaN か無限大があれば `NonFinite` になる。
零でない乗数が 0 に丸まるときは `NumericalInstability`（`Underflow`）、重みや 2 進の指数が範囲を超えるときは `NumericalInstability`（`Overflow`）になる。

次のセルは $\Delta=0.1$、$\mu=1/2$、$L=0$ の $n$ 点の格子で $a(r)=r^{3/2}/(1+r^2)^2$ を変換し、簡易 API と Plan、上限の働きを確かめる。
入力は標本数 $n$ とバイアス $q$ である。
確かめることは 2 つある。
1 つめは `fht` の結果を順方向の Plan の `execute_into` の結果の実部と、その実部に `ifht` を掛けたものを逆方向の Plan の結果の実部と比べることである。
差は Plan の出力の大きさの最大で割った値で示し、順方向の Plan の `FftLogDiagnostics` の 2 つの値も並べる。
2 つめは `FftLogLimits` の `preparation_work` と `workspace_bytes` である。
基準の値は、診断が返す準備の計算量と、`workspace_requirements(())` が返す作業領域のバイト数にする。
どちらもその値ちょうどの上限と 1 だけ小さい上限で準備と作業領域の確保を試す。

```rust
//|       - {"artifact":"agreement","path":"/rows/0/3","approx":{"value":2.391,"atol":0.001}}

    a.push(r.powf(1.5) / (1.0 + r * r).powi(2));
}

    .iter()
    .map(|&v| Complex::new(v, 0.0))
    .collect();

inverse
    .execute_into(&real_input, &mut back, &mut workspace, cx)
    .map_err(|e| e.to_string())?;

    let scale = q.iter().map(|z| z.re.abs()).fold(0.0_f64, f64::max);
    p.iter()
        .zip(q)
        .map(|(x, z)| (*x - z.re).abs())
        .fold(0.0_f64, f64::max)
        / scale
};

    Ok(()) => "成功".to_string(),

    let budget = Budget::try_from(work).map_err(|e| e.to_string())?;
    Ok(FftLogLimits {
        preparation_work: budget,
        ..FftLogLimits::default()
    })

let bytes_limit = |bytes: usize| FftLogLimits {
    workspace_bytes: bytes,
    ..FftLogLimits::default()

let mut rows = Vec::new();
for work in [d.preparation_work, d.preparation_work - 1] {
    rows.push(("preparation_work", work, label(attempt(work_limit(work)?))));
}
for bytes in [plain_bytes, plain_bytes - 1] {
    rows.push(("workspace_bytes", bytes, label(attempt(bytes_limit(bytes)))));

    { "key": "1", "label": "fht と Plan の差 / 出力の最大 [-]", "type": "number", "format": sci2 },
    { "key": "2", "label": "ifht と Plan の差 / 出力の最大 [-]", "type": "number", "format": sci2 },
    { "key": "3", "label": "乗数の条件数の対数 [-]", "type": "number", "format": fixed3, "nullText": "∞" },
    { "key": "4", "label": "準備の計算量 [回]", "type": "integer" },
    { "key": "5", "label": "plan_bytes() [B]", "type": "integer" }
]);
let agreement = (
    n,
    gap(&once, &transform),
    gap(&once_back, &back),
    Some(d.log_multiplier_condition).filter(|c| c.is_finite()),
    d.preparation_work,
    forward.plan_bytes(),
);
emit_table_with_columns!(
    agreement_columns,
    vec![agreement],
    metadata = serde_json::json!({ "id": "agreement" })
);
let limit_columns = serde_json::json!([
    { "key": "0", "label": "FftLogLimits の欄" },
    { "key": "1", "label": "上限 [回か B]", "type": "integer" },
    { "key": "2", "label": "結果" }
]);
emit_table_with_columns!(
    limit_columns,
    rows,
    metadata = serde_json::json!({ "id": "limits" })
);
```

どの場合も、`fht` と `ifht` は Plan の結果の実部とちょうど一致する。
簡易 API は同じ引数から $r_c=1$ の同じ Plan を作り、複素数の結果の実部を返すからである。
既定の $n=64$、$q=0$ では、乗数の条件数の対数が 0 ではなく 0.437 になる。
$L=0$ は低リンギングの offset ではないので、偶数の $n$ では Nyquist の乗数が $\lvert\cos\varphi\rvert=e^{-0.437}\approx0.65$ 倍に縮むからである（[計算量と精度](#計算量と精度)）。
$q=-0.5$ では対数が 2.391 に上がり、両方の格子のバイアスの重みを保持するので `plan_bytes()` も 2944 B から 4992 B に増える。

準備の計算量は $n=64$ で 1665 で、$q$ によらない。
`preparation_work` を 1665 にすると準備が通り、1664 にすると `ConvergenceFailure` になる。
作業領域は 2048 B で、`workspace_bytes` を 2047 にすると `ResourceLimit` になる。
$n=256$ では計算量が 6657、作業領域が 8192 B に増える。

## Gauss 型の関数での確認

$a(r) = r^{\mu+1} e^{-r^2/2}$ の変換は $A(k) = k^{\mu+1} e^{-k^2/2}$ である（Weber の積分、DLMF 10.22.51）。
入力は小さい $r$ で $r^{\mu+1}$ のように減り、出力は小さい $k$ で $k^{\mu+1}$ のように減る。
そのため、周期化した関数の段差は入力の左端で $r_0^{\mu+1-q}$、出力の左端で $k_0^{\mu+1+q}$ の程度になる。
右端はどちらも Gauss 関数で十分小さい。
段差による誤差は出力の重み $k^{-q}$ の最大値の倍まで拡大されうる。

次のセルは $n = 128$ 点、$r_c = 1$ の格子で $a$ を変換し、解析解と比べる。
入力は次数 $\mu$、刻み $\Delta$（範囲は $e^{\pm 63.5\Delta}$）、バイアス $q$ である。
offset は `fftlog_low_ringing_offset` で 0 の近くから選ぶので、出力の格子もおよそ $e^{\pm 63.5\Delta}$ になる。
1 つめの図は $A(k)$ と解析解、2 つめの図は各点の差の絶対値を対数軸で描き、2 つの図の波数の軸を連動させる。
表には 2 つの段差の目安、出力の重みの最大値、$A$ の最大値で割った差の最大、`ifht` で戻したときの差の最大、乗数の条件数の対数、準備の計算量を出す。

```rust
//| id: fft-fftlog-gaussian
//| ref: fft-fftlog-gaussian
//| title: FFTLog で Gauss 型の関数の Hankel 変換を対数格子で求める
//| run: reactive
//| crates: [scioxide-core, scioxide-fft]
//| inputs:
//|   order: {"type":"range","label":"Bessel 関数の次数 μ","description":"核 J_μ の次数。入力と出力の左端の減り方 r^{μ+1} が変わる。","min":0,"max":2,"step":0.5,"value":0}
//|   log_step: {"type":"range","label":"対数格子の刻み Δ","description":"標本数 128 のまま、範囲 e^{±63.5Δ} を変える。","min":0.05,"max":0.15,"step":0.025,"value":0.1}
//|   bias: {"type":"range","label":"バイアス q","description":"入力の左端の段差 r₀^{μ+1−q} と出力の左端の段差 k₀^{μ+1+q} の釣り合いを変える。","min":-0.75,"max":0.25,"step":0.25,"value":0}
//| cases:
//|   - {"id":"wide-grid","label":"Δ = 0.15","description":"範囲が e^{±9.5} に広がり、段差と誤差が小さくなる。","inputs":{"log_step":0.15}}
//|   - {"id":"order-two","label":"μ = 2","description":"両端が r³ で減り、段差が 10⁻⁹ の程度に下がる。","inputs":{"order":2}}
//|   - {"id":"negative-bias","label":"q = −0.5","description":"出力の段差が 0.04 に増え、右端で 24 倍になる出力の重み k^{0.5} がその振動を拡大する。","inputs":{"bias":-0.5}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","approx":{"value":0.047483887457456936,"atol":1e-12}}
//|       - {"artifact":"summary","path":"/rows/0/4","approx":{"value":1.59e-3,"rtol":0.01}}
//|       - {"artifact":"summary","path":"/rows/0/5","range":{"max":1e-14}}
//|       - {"artifact":"summary","path":"/rows/0/6","range":{"max":1e-12}}
//|   - case: wide-grid
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/1","approx":{"value":7.300373162293296e-5,"rtol":1e-9}}
//|       - {"artifact":"summary","path":"/rows/0/4","approx":{"value":6.51e-5,"rtol":0.01}}
//|   - case: order-two
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/4","approx":{"value":3.85e-9,"rtol":0.02}}
//|   - case: negative-bias
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/3","approx":{"value":24.500134301992844,"rtol":1e-9}}
//|       - {"artifact":"summary","path":"/rows/0/4","approx":{"value":1.65,"rtol":0.01}}
//|       - {"artifact":"summary","path":"/rows/0/6","approx":{"value":2.46,"atol":0.01}}

use scioxide_fft::{FftDirection, FftLogPlan, FftLogPlanSpec, fftlog_low_ringing_offset, ifht};

let (n, dln) = (128_usize, log_step); // 標本数と ln r の刻み Δ
// 0 の近くで低リンギングの offset を選ぶ
let offset = fftlog_low_ringing_offset(dln, order, 0.0, bias).map_err(|e| e.to_string())?;
let spec = FftLogPlanSpec::new(
    n,
    dln,
    order,
    offset,
    Complex::new(bias, 0.0),
    FftDirection::Forward,
);
let plan = FftLogPlan::new(spec).map_err(|e| e.to_string())?;

// 入力 a(r) = r^{μ+1} e^{−r²/2}。解析解 A(k) も同じ形（どちらも f64 の関数で評価）
let profile = |x: f64| x.powf(order + 1.0) * (-0.5 * x * x).exp();
let mut input = Vec::with_capacity(n);
for j in 0..n {
    let r = plan.log_radius(j).map_err(|e| e.to_string())?.exp();
    input.push(Complex::new(profile(r), 0.0));
}
let mut output = vec![Complex::new(0.0, 0.0); n];
let mut workspace = plan.workspace(()).map_err(|e| e.to_string())?;
plan.execute_into(
    &input,
    &mut output,
    &mut workspace,
    ExecutionContext::sequential(),
)
.map_err(|e| e.to_string())?;

// 独立検算: k_j = exp(log_frequency(j)) で解析解と比べる
let (mut computed, mut exact, mut errors) = (Vec::new(), Vec::new(), Vec::new());
let (mut largest, mut peak) = (0.0_f64, 0.0_f64);
for (j, value) in output.iter().enumerate() {
    let k = plan.log_frequency(j).map_err(|e| e.to_string())?.exp();
    let reference = profile(k);
    let error = (value.re - reference).abs();
    largest = largest.max(error);
    peak = peak.max(reference);
    computed.push([k, value.re]);
    exact.push([k, reference]);
    // 差がちょうど 0 の点は対数軸に描けないので除く
    if error > 0.0 {
        errors.push([k, error]);
    }
}
// 実数の簡易 API ifht で入力の格子へ戻し、元の標本と比べる
let real_output: Vec<f64> = output.iter().map(|z| z.re).collect();
let back = ifht(&real_output, dln, order, offset, bias).map_err(|e| e.to_string())?;
let roundtrip = input
    .iter()
    .zip(&back)
    .map(|(a, b)| (a.re - b).abs())
    .fold(0.0_f64, f64::max);
// 周期化した関数の左端の段差の目安（入力 r₀^{μ+1−q}、出力 k₀^{μ+1+q}）と出力の重み k^{−q}
let r0 = plan.log_radius(0).map_err(|e| e.to_string())?.exp();

let k_last = plan.log_frequency(n - 1).map_err(|e| e.to_string())?.exp();
let diagnostics = plan.diagnostics();
let condition = Some(diagnostics.log_multiplier_condition).filter(|c| c.is_finite());

emit_line_chart!(
```

既定の $\mu = 0$、$\Delta = 0.1$、$q = 0$ では、範囲は $r_0 = 1.7\times 10^{-3}$ から 573 で、offset は 0.0475 になる。
入力と出力の段差は $1.7\times 10^{-3}$ と $1.8\times 10^{-3}$ で、差の最大は $A$ の最大値の $1.6\times 10^{-3}$ 倍とほぼ同じ大きさである。
$\Delta = 0.15$ にすると範囲が $e^{\pm 9.5}$ に広がって段差が $7.3\times 10^{-5}$ に下がり、差も $6.5\times 10^{-5}$ 倍になる。
$\Delta = 0.05$ では段差が $4.2\times 10^{-2}$ に上がり、差も $3.9\times 10^{-2}$ 倍になる。
$\mu = 2$ では段差が $r_0^3 \approx 5.3\times 10^{-9}$ に下がり、差は $3.9\times 10^{-9}$ 倍になる。
どの場合も差の最大は大きい方の段差と同じ桁で、段差とともに変わる。
このことから、この入力では誤差の主な源が周期化した関数の端の段差であると分かる。

$q = -0.5$ にすると、入力の段差は $7.3\times 10^{-5}$ に下がるが、出力の段差が $k_0^{0.5} = 4.3\times 10^{-2}$ に上がる。
出力の重み $k^{0.5}$ は右端で 24.5 になるので、振動が拡大されて差の最大は $A$ の最大値の 1.6 倍に達する。
$q = 0.25$ では入力の段差 $8.5\times 10^{-3}$ が、左端で 4.8 になる重み $k^{-0.25}$ で拡大され、差は $3.9\times 10^{-2}$ 倍になる。
Gauss 型のように入力と出力の両端が同じ速さで減る関数では、$q = 0$ がよい。

`ifht` で戻した差の最大は、$q = 0$ では $1.7\times 10^{-16}$ で、乗数の条件数の対数は 0 である。
$q = -0.5$ では条件数の対数が 2.46（条件数 12）に上がり、往復の差も $1.3\times 10^{-14}$ に増える。
往復の差は離散の写像が逆になることを示すだけで、連続の Hankel 変換への近さは格子の範囲とバイアスで決まる。

## まとめ

FFTLog はバイアスを掛けた入力を $\ln r$ の周期関数として DFT し、Mellin 乗数 $u_m$ を掛けて戻すことで、Hankel 変換を $O(n\log n)$ で計算する。
変換の規約は $\int a(r) J_\mu(kr)\,k\,dr$ で、`fht` と `ifht` は $r_c = 1$ の実数の簡易 API である。
誤差の主な源は入力と出力の両端の段差による振動と範囲の外からの折り返しで、標本数を増やすだけでは減らない。
範囲は $\Delta$ と $n$ で広げ、バイアス $q$ は入力と出力の端の段差の釣り合いで選び、offset は `fftlog_low_ringing_offset` で選ぶ。
`ifht` で戻せることは離散の写像が逆になることだけを示すので、連続の積分への近さは解析解か範囲を広げた計算で確かめる。
`fht` と `ifht` は Plan と同じ結果を返し、`FftLogLimits` の上限を超える準備は、メモリ使用量なら `ResourceLimit`、計算量なら `ConvergenceFailure` で止まる。
