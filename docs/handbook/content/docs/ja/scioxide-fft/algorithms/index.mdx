この部では、`scioxide-fft` が計算する変換の定義、それを速く計算するアルゴリズム、誤差と失敗の扱いを説明する。
各ページは一つの問いを扱い、このページにはすべてのページが前提にする記法と規約を置く。

## 離散 Fourier 変換の記法

長さ $n$ の複素数列 $x_0,\dots,x_{n-1}$ に対し、正規化の前の順変換と逆変換を

$$
X_k = \sum_{j=0}^{n-1} x_j\, e^{-2\pi i jk/n}, \qquad
x_j = \sum_{k=0}^{n-1} X_k\, e^{+2\pi i jk/n}
$$

と書く（$k, j = 0,\dots,n-1$）。
`FftDirection::Forward` は指数の符号が負の和を、`FftDirection::Inverse` は正の和を選ぶ。
二つを続けると列は $n$ 倍になり（導出は [DFT の定義と逆変換](oxref:fft-dft-definition)）、係数 $1/n$ の置き場所を次節の `Normalization` で選ぶ。
定義どおりの和は $n^2$ 回の複素乗算を要し、高速 Fourier 変換（FFT）は $n$ の因数分解を使って同じ値を $O(n\log n)$ 回の演算で求めるアルゴリズムの総称である。

ビン $k$ の周波数は $k < n/2$ なら $k/n$、$k \ge n/2$ なら $(k-n)/n$ [サイクル/標本] である。
偶数長では Nyquist のビン $k = n/2$ を $-1/2$ として数える。
標本の間隔を $\Delta t$ とすると、物理的な周波数はこの値を $\Delta t$ で割ったものになる。
`fftfreq(n, Δt)` はその列を（実数変換の非負のビンは `rfftfreq` が）返し、`fftshift` はビン 0 を中央へ移す（[周波数軸とビンの並び](oxref:fft-frequency-axis)）。

多次元の配列は行優先（最後の軸が最も速く変わる）で詰め、`shape` と変換する軸の列 `axes` で表す。
選ばなかった軸は独立な列（バッチ）として扱う。

### 正規化

`Normalization` の 4 つの列挙子は往復の係数 $n$（多次元では選んだ軸の長さの積）を、逆変換に $1/n$（`Inverse`）、順変換に $1/n$（`Forward`）、両方向に $1/\sqrt n$（`Orthonormal`）と割り振るか、割り振らない（`Unscaled`）。
`Unscaled` 以外は両方向に同じ値を渡せば往復で元に戻り、実数変換のパックした表現は係数を変えない。
各列挙子の Parseval の等式は [正規化と Parseval の等式](oxref:fft-normalization-conventions) で導く。

Fourier 変換以外では $n$ の読み方が変わる。

- DCT・DST は型ごとの往復係数（DCT-II なら $n$、DCT-I なら $2(n-1)$）を使い、`Orthonormal` は端点の重みも変えて変換行列を直交にする（[DCT・DST と境界条件](dct-dst-and-boundaries/)）。
- チャープ Z 変換は方向を持たず、入力の長さ $n$ について `Forward` は $1/n$、`Orthonormal` は $1/\sqrt n$ を掛け、`Inverse` と `Unscaled` は係数を掛けない。
- 非一様 Fourier 変換は和の項の数（型 1・3 は点の数、型 2 はモードの数の積）を使う。
  `Forward` と `Inverse` は Plan の方向と名前が一致するときだけその数で割り、`Orthonormal` は方向によらずその平方根で割る。
- 離散 Hankel 変換と FFTLog は固有の積分の規約を持ち、`Normalization` を取らない（[動径方向の変換と離散 Hankel 変換](radial-transforms/)、[FFTLog と対数格子](fftlog/)）。

## 実数入力とパックしたスペクトル

実数列の DFT は $X_{n-k} = \overline{X_k}$（Hermite 対称性）を満たすので、独立な値は $k = 0,\dots,\lfloor n/2\rfloor$ の $\lfloor n/2\rfloor + 1$ 個である。
`rfft` はこの非負周波数のビンだけを返す。
長さ $2m$ と $2m+1$ の列はどちらも $m+1$ 個のビンになるので、`HermitianSpectrum` はビンと一緒に元の長さ（論理長）を持ち、逆変換の長さを決める。
多次元の `HermitianSpectrumNd` は選んだ軸の最後の一つだけを詰め、形状と軸の列を持つ。

Plan では `FftLayout`（`Complex`、`Real`、`Hermitian`）が入出力の表現を選び、方向と組み合わせて `rfft`・`irfft`・`hfft`・`ihfft` のどれに当たるかが決まる（[Plan での格納形式](oxref:fft-real-plan-layout)）。
`execute_into` に渡す `FftInput` と `FftOutput` の種類が配置と合わないと、`InvalidInput`（`UnsupportedConfiguration`）になる。

## 入力の検査と失敗の扱い

### 長さと定義域

一次元の変換は空の入力を `InvalidInput` で拒み、DCT-I は 2 点未満も拒む。
多次元の変換では、変換する軸の長さが 0 なら `InvalidInput`、軸が重複していれば `InvalidInput`、軸の番号が次元数以上なら `OutOfBounds` になる。
選ばなかった軸の長さが 0 の配列（空のバッチ）は有効で、何も書かずに成功する。
NUFFT の空の和は 0 である。

変換の長さは渡した配列の長さそのものであり、ゼロパディングや切り詰めを暗黙には行わない。
ゼロパディングが必要なら、呼び出し側が配列を伸ばす。

入力の値かパラメータに NaN か無限大があると、計算の前に `NonFinite`（由来は `Input`）を返す。
注入した外部実装（`FftProvider`）が NaN か無限大を返したときも `NonFinite` で、由来は `Callback` になる。

### Hermite 対称性の検査

パックしたスペクトルから実数を復元する変換（`irfft`、`irfftn`、`hfft`、`hfftn` と、パックした入力を取る Plan）は、入力が丸め誤差の範囲で Hermite 対称かを調べる。
独立なスペクトルごとに、成分の実部と虚部の絶対値の最大を $M$、機械イプシロンを $\varepsilon$、最小の正の非正規化数を $\eta$ として、

$$
\tau = \max(8\varepsilon M,\ \eta)
$$

とおく。

- 自己共役なビン（DC と、偶数長の Nyquist）は、虚部の絶対値が $\tau$ 以下でなければならない。
- 多次元の変換では、パックした軸の DC と Nyquist の面に共役な対の両方が入る。
  その実部の差と虚部の和は、絶対値が $2\tau$ 以下でなければならない。

範囲内のずれは作業領域の中で厳密な Hermite 対称に射影し、呼び出し側の入力は変えない。
範囲を超える入力は黙って射影せず、`InvalidInput` を返す。
射影の規則と、それによる変換の変化の上界は [Hermite 対称性の検査](oxref:fft-hermitian-check) で導く。

### 値の範囲と桁あふれ

核は変換の前に入力を 2 のべきで縮め、最後に正規化と一緒に一度の丸めで戻す。
そのため、オーバーフローの閾値に近い入力も途中で桁あふれせずに変換できる。
多次元の変換ではバッチごとに別々に縮めるので、大きな値のバッチが小さな値のバッチの成分を 0 に落とすことはない。
有限の入力から表現できない出力が生じたときは `NumericalInstability`（`Overflow`）になり、出力が 0 にアンダーフローすることはエラーではない。

### 出力の扱い

失敗したときは、呼び出し側の出力を変えない。
ストライド付きの出力の隙間と、軸に沿った変換のすべての列もこれに含まれる。
作業領域の中身は失敗で変わることがあるが、そのまま次の呼び出しに使える。

### エラーの分類

| `kind()` | 主な原因 |
|---|---|
| `InvalidInput` | 空の入力、短すぎる DCT-I、Hermite 対称性の検査の失敗、重複した軸、仕様の不正なパラメータ、Plan の配置と合わない入出力の種類、Plan のコンテキストが提供しない CPU 命令セットの要求 |
| `OutOfBounds` | 次元数以上の軸の番号 |
| `NonFinite` | NaN か無限大の入力・パラメータ（`Input`）、外部実装の非有限な出力（`Callback`） |
| `NumericalInstability` | 有限の入力からの出力の桁あふれ（`Overflow`）、パックした実数変換の内部の丸め検査の失敗（`Breakdown`）、準備で求めた非零の係数のアンダーフロー（`Underflow`） |
| `DimensionMismatch` | 出力・ビュー・作業領域の形が違うか短い |
| `Singular` | FFTLog の乗数が 0 になり逆数が要るとき、または Γ 関数の極に当たるとき |
| `ResourceLimit`、`AllocationFailure`、`SizeOverflow` | 設定した上限の超過、確保の失敗、大きさの桁あふれ |
| `ConvergenceFailure` | 離散 Hankel 変換か FFTLog の準備が計算量の上限を超えた |
| `ExecutionStopped` | 中止の要求か期限による停止 |

分類は `e.kind()` で調べ、詳細は `e.view()` で読む。
エラーの分類と部分結果の一般論は [エラー仕様と部分結果](../../concepts/errors-and-partial-results/) にある。

## 精度の範囲

複素 FFT とパック形式の実数 FFT の順変換（SciOxide の CPU カーネル）は、高精度で計算した参照の DFT と比べる試験で、相対 $L^2$ 誤差が $2\varepsilon\max(1, \log_2 n)$ 以下であることを確かめている（$\varepsilon$ は機械イプシロン、試験した長さは [計算コストと丸め誤差](oxref:fft-cost-and-accuracy)）。
これは試験で確かめたノルムの範囲であり、証明した上界でも成分ごとの相対誤差の保証でもない。
最大のビンよりずっと小さいビンは、相対誤差が大きくなりうる。
DC ビンも他のビンと同じ FFT の丸めで求めるので、打ち消し合う入力の総和を正しく丸めた値にはならない。
注入した外部実装はこの範囲に含まれず、それ自身の精度に従う。

他の変換は精度を別の形で述べる。

| 変換 | 精度の述べ方 |
|---|---|
| チャープ Z 変換、`zoom_fft` | Bluestein のアルゴリズムで、成分ごとの絶対誤差の上界（重み付きの入力の和に比例） |
| 非一様 Fourier 変換 | 入力の $\ell^1$ ノルムに対する誤差の推定値が要求精度を満たす。推定値は上界ではない |
| 離散 Hankel 変換 | 行列とベクトルの積の成分ごとの上界。求積の誤差は関数による |
| FFTLog | 数値の上界を述べない。連続積分の誤差は格子、バイアス、関数による |

各ページで、上界、推定値、試験で確かめた範囲を区別して述べる。

## Plan と作業領域

同じ形の変換を繰り返すときは Plan（plan）を作る。
Plan は仕様（`FftPlanSpec` など）から準備し、長さ、方向、正規化、配置、実行方針、CPU の命令セットを準備のときに固定する。
準備した Plan は変更できないので、逆方向には別の Plan を用意する。

準備（`new`、`build`）は Plan のメモリ領域を確保する。
Plan の `execute_into` は呼び出し側が渡した出力と作業領域だけを使い、作業領域が十分ならヒープを確保しない。
`fft`、`rfft`、`dct` などの関数は呼び出しのたびに Plan を作って捨て、結果を新しいメモリ領域に入れて返す。

作業領域の大きさは Plan の `workspace_requirements(request)` で問い合わせ、`workspace(request)` で確保する。
大きさが Plan だけで決まる変換の `request` は `()` である。
チャープ Z 変換、非一様 Fourier 変換、離散 Hankel 変換、FFTLog を多次元配列の一つの軸に沿って行う `execute_axis_into` には、`AxisWorkspaceRequest::Axis { shape, axis }` を渡す。
この作業領域は出力全体も持ち、すべての列が成功してから出力に書く。

非一様 Fourier 変換、離散 Hankel 変換、FFTLog の Plan は `LinearOperator` と `AdjointOperator` を実装する。
1 回の適用（と、少なくとも 1 列を持つ軸に沿った呼び出し）を 1 回の演算子の評価として数え、内部の FFT は数えない。

Plan の所有、作業領域の使い回しと上限、`FftPlanCache` は [FFT の Plan・作業領域・キャッシュ](plans-workspaces-and-providers/) で、CPU 命令セットの選択と外部実装（`FftProvider`）の注入は [外部 FFT 実装と CPU 命令セット](providers-and-cpu-backends/) で説明する。
作業領域と再現性の一般論は [実行形式・作業領域・再現性](../../concepts/workspaces-and-reproducibility/) にある。
本書のセルは wasm32 の上で逐次に動くので、結果は可搬なスカラーの核による。

## まとめ

`scioxide-fft` の変換は、順方向の指数の符号が負で、往復の係数を `Normalization` の `Forward`、`Inverse`、`Orthonormal`、`Unscaled` で割り振る。
DCT・DST、チャープ Z 変換、非一様 Fourier 変換は係数の数え方が違い、離散 Hankel 変換と FFTLog は `Normalization` を取らない。
実数のスペクトルは論理長とパックした軸を持ち、パックした入力は Hermite 対称性を検査して、範囲を超えれば `InvalidInput` を返す。
失敗した呼び出しは出力を変えないので、エラーの分類を見て入力を直してから呼び直せる。
FFT の精度は試験で確かめたノルムの範囲、チャープ Z 変換と離散 Hankel 変換は上界、非一様 Fourier 変換は推定値で述べるので、それぞれの意味で読む。
