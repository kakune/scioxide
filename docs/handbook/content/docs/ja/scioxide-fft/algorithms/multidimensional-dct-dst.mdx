偏微分方程式の格子や画像では、軸ごとに違う境界条件を持つ配列を変換したいことが多い。
多次元の DCT・DST は選んだ軸ごとに 1 次元の DCT か DST を順にかけた変換で、多次元 DFT と同じく軸ごとに分離できる（[軸ごとの分離と計算量](oxref:fft-multidimensional)）。
このページは一括関数と軸ごとに型を混ぜる Plan の使い方、作業領域の要件と確保を説明し、直接和と照合する。

## 一括関数と Plan

`dctn`、`idctn`、`dstn`、`idstn` は、行優先のスライスと形状、軸の列、軸ごとの型の列を受け取る一括関数である。
型の列の `i` 番目が `axes` の `i` 番目の軸の型で、`dctn` は `DctType`、`dstn` は `DstType` の列を取る。
DCT と DST を軸ごとに混ぜるときは、`RealTransformNdPlanSpec::new(shape, axes, types, direction, normalization)` に `RealTransformKind` の列を渡して `RealTransformNdPlan` を準備する。
各型の定義と尺度は [DCT・DST と境界条件](../dct-dst-and-boundaries/) にある。
無尺度の往復の係数は選んだ軸の係数の積になる。

`RealTransformNdPlan` は実数と複素数の 2 つの作業領域を持つ `RealTransformNdWorkspace` を使い、複素 FFT の `FftWorkspace` とは型が違う。
`RealTransformNdWorkspaceRequirements` は、実数の領域の要素数 `real_len()`、バイト数 `real_bytes()`、整列 `real_alignment()`、複素の領域の要件 `complex()`、合計のバイト数 `bytes()`、受け付ける容量の上限 `byte_limit()` を返す。
実数の領域は結果を組み立てる $V$ 個の値と、ストライドのある列を連続に並べ直す一時領域を合わせた長さを持つ。
一時領域の長さは最も長い列と 1 次元の Plan の要求で決まり、$V$ より大きくなることもある。
複素の領域は、軸ごとの 1 次元の Plan が順に使うので、そのうち最大の要求の長さを持つ。

作業領域は `plan.workspace(())` で確保するか、`RealTransformNdWorkspace::new()` で空のものを作って `try_reserve(&requirements)` で広げる。
`check(&requirements)` は二つの領域の長さが足りるかを `Capacity` で返す。
作業領域は大きくなるだけで縮まず、複数の Plan で使い回せる。
ただし二つの領域の容量の合計が Plan の上限を超えると `ResourceLimit`、実行のときに長さが足りなければ `DimensionMismatch` になる。

## DCT と DST を混ぜた Plan と作業領域の照合

次のセルは $M\times N$ の非対称な実数配列に、軸 0 で DCT-II、軸 1 で DST-II をかける無尺度の `RealTransformNdPlan` を準備する。
`RealTransformNdWorkspace::new()` で作った空の作業領域を、Plan の要件 `RealTransformNdWorkspaceRequirements` で `check` し、`try_reserve` で広げてもう一度 `check` する。
広げた作業領域で実行した結果を、2 つの軸の定義の和を重ねた $O(M^2N^2)$ の直接和と比べる。
直接和は `f64` の `cos` と `sin` で計算した独立な参照値である。
同じ配列に `dctn` で軸 0、続いて `dstn` で軸 1 をかけた結果とも比べる。
さらに軸ごとに DST-I と DST-IV を指定した `Orthonormal` の `dstn` の後に `idstn` をかけ、元の配列に戻るかを測る。
差はどれも直接和（往復では元の配列）の最大絶対値で割った相対値で示す。
要件の表は要素数とバイト数を示し、要素の大きさ（`f64` は 8 バイト、`Complex<f64>` は 16 バイト）から計算した合計バイト数も並べる。

```rust
//| id: fft-nd-mixed-real-transforms
//| ref: fft-nd-mixed-real-transforms
//| title: 軸ごとに DCT と DST を混ぜる Plan と作業領域の要件
//| run: reactive
//| crates: [scioxide-core, scioxide-fft]
//| inputs:
//|   rows_count: {"type":"range","label":"行数 M","description":"軸 0 の長さ。軸 0 は DCT-II で変換する。","min":1,"max":16,"step":1,"value":6}
//|   cols_count: {"type":"range","label":"列数 N","description":"軸 1 の長さ。軸 1 は DST-II で変換する。","min":1,"max":16,"step":1,"value":8}
//| cases:
//|   - {"id":"odd-sizes","label":"M = 5, N = 9","description":"奇数長。II 型は同じ長さの実数 FFT で計算される。","inputs":{"rows_count":5,"cols_count":9}}
//|   - {"id":"single-row","label":"M = 1, N = 7","description":"軸 0 の長さが 1。長さ 1 の DCT-II は値を変えないので、各行の DST-II だけが残る。","inputs":{"rows_count":1,"cols_count":7}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"capacity","path":"/rows/0/1","equals":"NeedsGrowth"}
//|       - {"artifact":"capacity","path":"/rows/1/1","equals":"Sufficient"}
//|       - {"artifact":"nd-errors","path":"/rows/0/1","range":{"max":1e-14}}
//|       - {"artifact":"nd-errors","path":"/rows/1/1","range":{"max":1e-14}}
//|       - {"artifact":"nd-errors","path":"/rows/2/1","range":{"max":1e-14}}
//|       - {"artifact":"requirements","path":"/rows/0/1","approx":{"value":160,"atol":0.5}}
//|       - {"artifact":"requirements","path":"/rows/2/1","approx":{"value":8,"atol":0.5}}
//|       - {"artifact":"requirements","path":"/rows/4/1","approx":{"value":1408,"atol":0.5}}
//|       - {"artifact":"requirements","path":"/rows/5/1","approx":{"value":1408,"atol":0.5}}
//|   - case: odd-sizes
//|     expect:
//|       - {"artifact":"capacity","path":"/rows/1/1","equals":"Sufficient"}
//|       - {"artifact":"nd-errors","path":"/rows/0/1","range":{"max":1e-14}}
//|       - {"artifact":"nd-errors","path":"/rows/2/1","range":{"max":1e-14}}
//|       - {"artifact":"requirements","path":"/rows/2/1","approx":{"value":26,"atol":0.5}}
//|       - {"artifact":"requirements","path":"/rows/4/1","approx":{"value":1712,"atol":0.5}}
//|       - {"artifact":"requirements","path":"/rows/5/1","approx":{"value":1712,"atol":0.5}}
//|   - case: single-row
//|     expect:
//|       - {"artifact":"nd-errors","path":"/rows/0/1","range":{"max":1e-14}}
//|       - {"artifact":"nd-errors","path":"/rows/1/1","range":{"max":1e-14}}
//|       - {"artifact":"nd-errors","path":"/rows/2/1","range":{"max":1e-14}}
//|       - {"artifact":"capacity","path":"/rows/1/1","equals":"Sufficient"}
//|       - {"artifact":"requirements","path":"/rows/4/1","approx":{"value":896,"atol":0.5}}
use scioxide_core::{ExecutionContext, NdView, NdViewMut};
use scioxide_fft::{DctType, DstType, FftDirection, Normalization, RealTransformKind};
use scioxide_fft::{RealTransformNdPlan, RealTransformNdPlanSpec, RealTransformNdWorkspace};
use scioxide_fft::{RealTransformNdWorkspaceRequirements, dctn, dstn, idstn};

let (m, n) = (rows_count.round() as usize, cols_count.round() as usize);
let shape = [m, n];
let pi = std::f64::consts::PI;
// 非対称な実数配列（四則演算だけで作る）。行優先なので要素 (j, k) は位置 j·N + k。
let x: Vec<f64> = (0..m * n)
    .map(|i| 1.0 / (1.0 + i as f64) + 0.5 * ((i * 7) % 5) as f64)
    .collect();
// types[i] が axes[i] の型: 軸 0 は DCT-II、軸 1 は DST-II。
let kinds: [RealTransformKind; 2] = [DctType::II.into(), DstType::II.into()];
let spec = RealTransformNdPlanSpec::new(
    &shape,
    &[0, 1],
    &kinds,
    FftDirection::Forward,
    Normalization::Unscaled,
)
.map_err(|e| e.to_string())?;
let plan = RealTransformNdPlan::<f64>::new(spec).map_err(|e| e.to_string())?;
let requirements: RealTransformNdWorkspaceRequirements =
    plan.workspace_requirements(()).map_err(|e| e.to_string())?;
// 空の作業領域は確保せずに作られ、try_reserve で要件まで広がる。
let mut workspace = RealTransformNdWorkspace::<f64>::new();
let before = workspace.check(&requirements).map_err(|e| e.to_string())?;
workspace
    .try_reserve(&requirements)
    .map_err(|e| e.to_string())?;
let after = workspace.check(&requirements).map_err(|e| e.to_string())?;
let mut mixed = vec![0.0; m * n];
plan.execute_into(
    NdView::row_major(&x, &shape).map_err(|e| e.to_string())?,
    NdViewMut::row_major(&mut mixed, &shape).map_err(|e| e.to_string())?,
    &mut workspace,
    ExecutionContext::sequential(),
)
.map_err(|e| e.to_string())?;
// 独立検算: Σ_j Σ_k x_jk cos(π(j+½)p/M) sin(π(k+½)(q+1)/N)（f64 の cos と sin による参照値）。
let mut direct = vec![0.0; m * n];
for p in 0..m {
    for q in 0..n {
        let mut sum = 0.0;
        for j in 0..m {
            let cosine = (pi * (j as f64 + 0.5) * p as f64 / m as f64).cos();
            for k in 0..n {
                let sine = (pi * (k as f64 + 0.5) * (q as f64 + 1.0) / n as f64).sin();
                sum += x[j * n + k] * cosine * sine;
            }
        }
        direct[p * n + q] = sum;
    }
}
let norm = Normalization::Unscaled;
let along_rows = dctn(&x, &shape, &[0], &[DctType::II], norm).map_err(|e| e.to_string())?;
let composed =
    dstn(&along_rows, &shape, &[1], &[DstType::II], norm).map_err(|e| e.to_string())?;
// 直交の DST-I（軸 0）と DST-IV（軸 1）の往復。
let sine_types = [DstType::I, DstType::IV];
let ortho = Normalization::Orthonormal;
let coefficients = dstn(&x, &shape, &[0, 1], &sine_types, ortho).map_err(|e| e.to_string())?;
let restored =
    idstn(&coefficients, &shape, &[0, 1], &sine_types, ortho).map_err(|e| e.to_string())?;
let max_abs = |v: &[f64]| v.iter().fold(0.0_f64, |a, b| a.max(b.abs()));
let relative_gap = |a: &[f64], b: &[f64]| {
    let gap = a
        .iter()
        .zip(b)
        .fold(0.0_f64, |g, (p, q)| g.max((p - q).abs()));
    gap / max_abs(b)
};

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let error_columns = serde_json::json!([
    { "key": "0", "label": "比較" },
    { "key": "1", "label": "最大絶対値で割った差 [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    error_columns,
    vec![
        (
            "RealTransformNdPlan と直接和",
            relative_gap(&mixed, &direct)
        ),
        (
            "dctn（軸 0）→ dstn（軸 1）と直接和",
            relative_gap(&composed, &direct)
        ),
        ("直交の idstn(dstn(x)) と x", relative_gap(&restored, &x)),
    ],
    metadata = serde_json::json!({ "id": "nd-errors" })
);
// 要素の大きさから合計バイト数を独立に計算する（f64 は 8、Complex<f64> は 16 バイト）。
let complex_len = requirements.complex().complex_len();
let expected_bytes = 8 * requirements.real_len() + 16 * complex_len;
let requirement_columns = serde_json::json!([
    { "key": "0", "label": "量" },
    { "key": "1", "label": "値", "type": "integer" }
]);
emit_table_with_columns!(
    requirement_columns,
    vec![
        ("実数の領域 real_len() [要素]", requirements.real_len()),
        ("総要素数 V = MN [要素]", m * n),
        ("複素の領域 complex().complex_len() [要素]", complex_len),
        (
            "実数の領域 real_bytes() [バイト]",
            requirements.real_bytes()
        ),
        ("合計 bytes() [バイト]", requirements.bytes()),
        ("8·real_len + 16·complex_len [バイト]", expected_bytes),
    ],
    metadata = serde_json::json!({ "id": "requirements" })
);
let capacity_columns = serde_json::json!([
    { "key": "0", "label": "時点" },
    { "key": "1", "label": "check の結果" }
]);
emit_table_with_columns!(
    capacity_columns,
    vec![
        ("new() の直後", format!("{before:?}")),
        ("try_reserve の後", format!("{after:?}")),
    ],
    metadata = serde_json::json!({ "id": "capacity" })
);
```

既定の 6×8 では、Plan の結果と直接和の差は直接和の最大絶対値で割って $7.9\times10^{-16}$ である。
`dctn` と `dstn` を軸ごとに続けた結果も同じ $7.9\times10^{-16}$ で、型の列の $i$ 番目が `axes` の $i$ 番目の軸にかかることと合う。
直交の DST-I と DST-IV の `dstn` の後に `idstn` をかけた往復の差は $5.7\times10^{-16}$ で、往復の係数が 1 になる。
5×9 の奇数長でも Plan と直接和の差は $1.3\times10^{-15}$ にとどまる。

`new()` の直後の `check` は `NeedsGrowth`、`try_reserve` の後は `Sufficient` を返し、広げた作業領域でそのまま実行できる。
6×8 の要件は実数の領域が 160 個、複素の領域が 8 個で、実数の領域は $V=48$ 個より大きい。
合計 `bytes()` の 1408 バイトは $8\cdot160+16\cdot8$ と一致し、`real_bytes()` と複素の領域のバイト数の和である。
5×9 では複素の領域が 26 個、合計が 1712 バイトになり、要件は形状ごとに変わる。

## まとめ

`dctn`、`idctn`、`dstn`、`idstn` は行優先のスライスに軸ごとの型の列をかける一括関数で、型の列の $i$ 番目が `axes` の $i$ 番目の軸にかかる。
軸ごとに DCT と DST を混ぜるときは `RealTransformNdPlanSpec` に `RealTransformKind` の列を渡して `RealTransformNdPlan` を準備する。
Plan は実数と複素数の二つの領域を持つ `RealTransformNdWorkspace` を使い、要件は `RealTransformNdWorkspaceRequirements` で問い合わせて `try_reserve` で確保する。
実数の領域は $V$ 個の値に列の一時領域を加えた長さで、$V$ より大きくなりうるので、要件を見ずに大きさを決めない。
直接和との差は丸め誤差の程度で、無尺度の往復の係数は選んだ軸の係数の積になる。
