非一様高速 Fourier 変換（NUFFT）は、等間隔でない位置や周波数での指数和を、直接和の $O(MK)$ より少ない演算で近似する。
$M$ は非一様な点の数、$K$ は出力の数である。
不規則な時刻の観測、極座標や放射状の格子で測った MRI のデータ、粒子の配置からの構造因子などに使う。
観測値を等間隔の格子へ補間してから FFT を掛ける前処理とは違い、指数和そのものを要求精度まで近似する。
`scioxide-fft` は 1 回だけ計算する関数 `nufft_type1`、`nufft_type2`、`nufft_type3` と、繰り返し使う Plan `NufftPlan` を提供する。
このページでは 3 つの型の規約、座標とモードの並び、Plan とリソースの上限を説明し、直接和と随伴の恒等式で確かめる。
型 3 も直接和と比べ、関数と Plan の結果の一致と、診断の値を使った上限の働きを確かめる。
核と過標本格子による近似と、要求精度と誤差の推定は [NUFFT の核と要求精度](../nufft-kernel-and-accuracy/)で扱う。

## 3 つの型と符号・尺度

非一様な点を $\mathbf x_j\in\mathbb R^d$（$j=0,\ldots,M-1$）とし、`FftDirection::Forward` なら $\sigma=-1$、`FftDirection::Inverse` なら $\sigma=+1$ とする。
3 つの型は次の和を計算する。

| 型 | 計算する和 | 入力 | 出力 | 関数 |
|---|---|---|---|---|
| 型 1 | $f_{\mathbf k}=s\sum_j c_j e^{\sigma i\mathbf k\cdot\mathbf x_j}$、$\mathbf k\in K$ | 点ごとの値 $c_j$ | 整数モードの格子 $K$ 上の値 | `nufft_type1` |
| 型 2 | $c_j=s\sum_{\mathbf k\in K}f_{\mathbf k}e^{\sigma i\mathbf k\cdot\mathbf x_j}$ | モードの係数 $f_{\mathbf k}$ | 点ごとの値 | `nufft_type2` |
| 型 3 | $f_\ell=s\sum_j c_j e^{\sigma i\boldsymbol\omega_\ell\cdot\mathbf x_j}$ | 点ごとの値 $c_j$ | 任意の角周波数 $\boldsymbol\omega_\ell$ での値 | `nufft_type3` |

$s$ は `Normalization` が決める係数で、基準の数は和を取る項の数、すなわち型 1 と型 3 では点の数 $M$、型 2 ではモードの数 $N_1\cdots N_d$ である。
`Forward` は方向が `Forward` のときだけ、`Inverse` は方向が `Inverse` のときだけ、その数で割る。
`Orthonormal` は方向によらず平方根で割り、`Unscaled` は割らない。
出力の数は基準にならず、空の和は 0 である。

Plan に渡すときは、`NufftTransform` の列挙子 `Type1 { points, modes }`、`Type2 { points, modes }`、`Type3 { points, frequencies }` で型と幾何を選ぶ。
符号、正規化、要求精度は `NufftPlanSpec::new(direction, normalization, accuracy)` で別に与える。

型 2 は型 1 の逆変換ではない。
型 1 と方向を反転した型 2 は、同じ点とモードについて互いの随伴（共役転置）になる。
`NufftPlan` は `scioxide_core::LinearOperator` と `AdjointOperator` を実装し、随伴は同じ係数 $s$ を持つ共役転置である。
不規則な観測から係数を推定する逆問題は、この随伴を使った最小二乗や正則化として別に組み立てる。

## 座標の単位とモードの並び

点と周波数は、形状 `[点の数, d]` の `NdView`（行が 1 つの点）で渡す。
型 1・2 のモード $K$ は各軸 $a$ で $-\lfloor N_a/2\rfloor,\ldots,\lceil N_a/2\rceil-1$ の昇順で、多次元では行優先（最後の軸が最も速く変わる）に並ぶ。
通常の FFT の、零周波数を先頭に置く並びとは異なる。
`modes` は各軸のモード数 $N_a$ で、0 なら `InvalidInput`（`Empty`）、長さが $d$ と違えば `DimensionMismatch` になる。

型 1・2 の座標は角度 [rad] で、各座標について周期 $2\pi$ である。
時刻 $t_j$ [s] と時間尺度 $T_0$ [s] から $x_j=2\pi t_j/T_0$ と無次元化すれば、モード $k$ は周波数 $k/T_0$ [Hz] に当たる。
$[-\pi,\pi]$ の外の座標も受け付け、正弦と余弦を通して $[-\pi,\pi]$ に戻す。
ただし、大きな座標は渡す前の浮動小数点数の段階で桁を失っている。
たとえば $x=2\pi\cdot1000+0.5$ を `f64` で表すと最大 $4.5\times10^{-13}$ rad 丸められ、モード $k$ の位相 $kx$ はその $\lvert k\rvert$ 倍ずれる。
そのため座標は $[-\pi,\pi]$ に置いて渡す。

型 3 の点と周波数は任意の実数で、内積 $\boldsymbol\omega_\ell\cdot\mathbf x_j$ が無次元 [rad] になるように単位を選ぶ。
時刻を日で与えるなら周波数は角周波数 [rad/日] で渡し、周波数 [日⁻¹] との間には $2\pi$ の換算がある。
Plan は点の箱と周波数の箱をそれぞれの中心へ平行移動してから格子に載せるので、時刻の原点が遠くても格子は大きくならない。
周波数の次元が点の次元と違えば `DimensionMismatch` になる。

## Plan、診断、リソースの上限

`NufftPlan::new(transform, spec)` が準備し、点と周波数を読み終えると借用を手放す。
`NufftPlan::build(transform, spec, context)` は `FftPlanningContext` の FFT の実装を使う（[外部 FFT 実装の注入](oxref:fft-providers)）。
`NufftPlanSpec` の既定は過標本率 2、上限なし、逐次実行、FFT の実装の自動選択で、`with_oversampling`、`with_limits`、`with_execution_policy`、`with_backend_strategy` で変える。
要求精度が $(0,1)$ の外か過標本率が 2 未満なら `InvalidInput`（`OutOfRange`）、要求精度や座標が NaN か無限大なら `NonFinite` になる。
関数 `nufft_type1` などは既定の指定で Plan を作り、1 回使って捨てる。

`plan.diagnostics()` は `NufftDiagnostics` を返す。
`approximation_error` と `roundoff_error` は折り返しと丸めの誤差の推定 $E_a$ と $E_r$、`kernel_support` は核の幅 $w$、`grid_points` は過標本格子の点数 $G$ である（定義は [要求精度と誤差の推定](oxref:fft-nufft-accuracy)）。
`stencil_visits` は 1 回の変換か随伴での格子点の延べ訪問数、`preparation_bytes` と `workspace_bytes` は準備中の最大メモリ使用量と 1 回分の作業領域のバイト数である。
要求精度と過標本率は `plan.spec()` で読み返す。
`grid_shape()` は軸ごとの格子点数、`input_len()` と `output_len()` は入出力の長さ、`dimension()` は $d$、`plan_bytes()` は FFT の Plan を含む Plan のメモリ使用量を返す。

`NufftLimits` は次の欄を持ち、どれも既定は `usize::MAX` である。

| 欄 | 制限する量 |
|---|---|
| `preparation_bytes` | 準備中に同時に保持するメモリ使用量。FFT の Plan を含む |
| `workspace_bytes` | 実行の作業領域。出力の一時領域を含む |
| `grid_points` | どちらかの過標本格子の点数 |
| `stencil_visits` | 1 回の変換か随伴での、拡散と補間による格子点の延べ訪問数 |
| `kernel_support` | 核の幅 $w$（軸ごとの格子点数） |

準備は確保の前にすべての上限を確かめ、超えれば `ResourceLimit` を返す。
上限を満たすように核を狭めたり要求精度を緩めたりはしない。

`plan.workspace(())` で作業領域を確保し、`execute_into(input, output, &mut workspace, scope)` で変換する。
入力は実数か複素数の列で、出力は複素数の列に限る。
1 回の呼び出しは `scope` の線形作用素の評価回数を 1 つ数える。
結果は作業領域の中で組み立て、成功したときだけ出力へ写すので、失敗した呼び出しは出力を変えない。
`execute_axis_into` は多次元配列の 1 つの軸に沿った全列を変換し、すべてを書くか、どれも書かない。
NaN や無限大の入力は `NonFinite`、長さの不一致は `DimensionMismatch` になる。

## 直接和と随伴の恒等式による確認

次のセルは $[-\pi,\pi)$ に散らした $M=12$ 点の 1 次元の型 1 を Plan で、方向を反転した型 2 を関数 `nufft_type2` で計算する。
入力はモード数 $N$、要求精度の指数、全座標に $2\pi$ の何倍を足すかである。
独立な検算は 2 つある。
型 1 の各モードを直接和 $\sum_jc_je^{-ikx_j}$ と比べ、随伴の恒等式 $\langle T_1c,f\rangle=\langle c,T_2f\rangle$ の相対差を求める。
直接和はずらす前の座標と `f64` の固有メソッドで計算する。

```rust
//| id: fft-nufft-type1-type2-adjoint
//| ref: fft-nufft-type1-type2-adjoint
//| title: 型 1 のモードの並びと直接和、型 2 との随伴の恒等式
//| run: reactive
//| crates: [scioxide-core, scioxide-fft]
//| inputs:
//|   mode_count: {"type":"integer","label":"モード数 N","description":"モードは −⌊N/2⌋, …, ⌈N/2⌉ − 1 の昇順に並ぶ。","min":4,"max":12,"value":8}
//|   accuracy_exponent: {"type":"integer","label":"要求精度の指数 p（ε_r = 10^p）","description":"入力の 1 ノルムに対する最大誤差の要求。","min":-13,"max":-3,"value":-10}
//|   wraps: {"type":"integer","label":"座標に足す 2π の倍数","description":"値は変わらないはずだが、座標の丸めで位相がずれる。","min":0,"max":1000,"value":0}
//| cases:
//|   - {"id":"odd-modes","label":"N = 7","description":"奇数のモード数では −3, …, 3 と対称に並ぶ。","inputs":{"mode_count":7}}
//|   - {"id":"strict","label":"ε_r = 10⁻¹³","description":"核の幅が広がり、直接和との差が要求の範囲に収まる。","inputs":{"accuracy_exponent":-13}}
//|   - {"id":"far-coordinates","label":"ε_r = 10⁻¹³、2π × 1000 をずらす","description":"座標の丸めによる位相のずれが要求精度を上回る。","inputs":{"wraps":1000,"accuracy_exponent":-13}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"modes","path":"/rows/0/0","equals":-4}
//|       - {"artifact":"modes","path":"/rows/7/0","equals":3}
//|       - {"artifact":"checks","path":"/rows/0/0","approx":{"value":12,"atol":0.5}}
//|       - {"artifact":"checks","path":"/rows/0/4","range":{"max":1e-10}}
//|       - {"artifact":"checks","path":"/rows/0/5","range":{"max":1e-10}}
//|   - case: odd-modes
//|     expect:
//|       - {"artifact":"modes","path":"/rows/0/0","equals":-3}
//|       - {"artifact":"modes","path":"/rows/6/0","equals":3}
//|       - {"artifact":"checks","path":"/rows/0/4","range":{"max":1e-10}}
//|   - case: strict
//|     expect:
//|       - {"artifact":"checks","path":"/rows/0/4","range":{"max":1e-13}}
//|   - case: far-coordinates
//|     expect:
//|       - {"artifact":"checks","path":"/rows/0/3","range":{"min":5e-15}}
//|       - {"artifact":"checks","path":"/rows/0/4","range":{"min":1e-13}}
use scioxide_core::{Complex, ExecutionContext, NdView, StridedLayout};
use scioxide_fft::{
    FftDirection, Normalization, NufftPlan, NufftPlanSpec, NufftTransform, nufft_type2,
};

let (count, modes) = (12_usize, [mode_count as usize]);
let accuracy = 10f64.powi(accuracy_exponent);
let tau = 2.0 * std::f64::consts::PI;
// [−π, π) に散らした点、点ごとの値 c_j、モードの係数 f_k（f64 の三角関数は入力の生成だけ）
let x: Vec<f64> = (0..count)
    .map(|j| -std::f64::consts::PI + tau * (0.1 + 0.618_033_988_749_895 * j as f64).fract())
    .collect();
let shifted: Vec<f64> = x.iter().map(|v| v + tau * wraps as f64).collect();
let c: Vec<Complex<f64>> = (0..count)
    .map(|j| Complex::new((1.3 * j as f64).cos(), (0.7 * j as f64).sin()))
    .collect();
let first = -((modes[0] / 2) as i64);
let ks: Vec<i64> = (0..modes[0] as i64).map(|i| first + i).collect();
let f: Vec<Complex<f64>> = ks
    .iter()
    .map(|&k| Complex::new(1.0 / (1.0 + k.abs() as f64), 0.1 * k as f64))
    .collect();

// 型 1（Forward、σ = −1）を Plan で求める。座標は形状 [M, 1] のビュー
let shape = [count, 1];
let layout = StridedLayout::new(&shape, &[1, 1]).map_err(|e| e.to_string())?;
let points = NdView::new(&shifted, layout).map_err(|e| e.to_string())?;
let spec = NufftPlanSpec::new(FftDirection::Forward, Normalization::Unscaled, accuracy);
let transform = NufftTransform::Type1 {
    points,
    modes: &modes,
};
let plan = NufftPlan::new(transform, spec).map_err(|e| e.to_string())?;
let mut workspace = plan.workspace(()).map_err(|e| e.to_string())?;
let mut type1 = vec![Complex::new(0.0, 0.0); modes[0]];
plan.execute_into(
    &c[..],
    &mut type1[..],
    &mut workspace,
    ExecutionContext::sequential(),
)
.map_err(|e| e.to_string())?;
// 方向を反転した型 2（Inverse、σ = +1）は型 1 の随伴
let points = NdView::new(&shifted, layout).map_err(|e| e.to_string())?;
let type2 = nufft_type2(
    points,
    &f,
    &modes,
    FftDirection::Inverse,
    Normalization::Unscaled,
    accuracy,
)
.map_err(|e| e.to_string())?;

// 独立な検算 1: ずらす前の座標での直接和 Σ_j c_j exp(−i k x_j)
let l1: f64 = c.iter().map(|v| v.norm()).sum();
let mut rows = Vec::new();
let mut worst = 0.0_f64;
for (&k, value) in ks.iter().zip(&type1) {
    let direct: Complex<f64> = c
        .iter()
        .zip(&x)
        .map(|(cj, xj)| *cj * Complex::from_polar(1.0, -(k as f64) * xj))
        .sum();
    let error = (*value - direct).norm() / l1;
    worst = worst.max(error);
    rows.push((k, value.re, value.im, error));
}
// 独立な検算 2: 随伴の恒等式 ⟨T1 c, f⟩ = ⟨c, T2 f⟩
let left: Complex<f64> = type1.iter().zip(&f).map(|(a, b)| *a * b.conj()).sum();
let right: Complex<f64> = c.iter().zip(&type2).map(|(a, b)| *a * b.conj()).sum();
let adjoint = (left - right).norm() / left.norm().max(right.norm());

let fixed6 = serde_json::json!({ "fractionDigits": 6 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let mode_columns = serde_json::json!([
    { "key": "0", "label": "モード k", "type": "integer" },
    { "key": "1", "label": "Re f_k [-]", "type": "number", "format": fixed6 },
    { "key": "2", "label": "Im f_k [-]", "type": "number", "format": fixed6 },
    { "key": "3", "label": "直接和との差 / Σ|c_j| [-]", "type": "number", "format": sci2 }
]);
emit_table_with_columns!(
    mode_columns,
    rows,
    metadata = serde_json::json!({ "id": "modes" })
);
let d = plan.diagnostics();
let check_columns = serde_json::json!([
    { "key": "0", "label": "核の幅 w", "type": "integer" },
    { "key": "1", "label": "格子点数 G", "type": "integer" },
    { "key": "2", "label": "推定 E_a [-]", "type": "number", "format": sci2 },
    { "key": "3", "label": "推定 E_r [-]", "type": "number", "format": sci2 },
    { "key": "4", "label": "実測誤差の最大 [-]", "type": "number", "format": sci2 },
    { "key": "5", "label": "随伴の恒等式の相対差 [-]", "type": "number", "format": sci2 }
]);
let check = (
    d.kernel_support,
    d.grid_points,
    d.approximation_error,
    d.roundoff_error,
    worst,
    adjoint,
);
emit_table_with_columns!(
    check_columns,
    vec![check],
    metadata = serde_json::json!({ "id": "checks" })
);
```

既定の $N=8$ では、モードが $k=-4,\ldots,3$ の順に並ぶ。
要求 $10^{-10}$ に対して核の幅は 12、格子は 16 点で、推定は $E_a=7.3\times10^{-11}$、$E_r=3.6\times10^{-15}$ である。
直接和との差は入力の 1 ノルムの $1.7\times10^{-12}$ 倍で、要求の範囲に入る。
随伴の恒等式の相対差は $6.9\times10^{-16}$ で、型 1 と方向を反転した型 2 が同じ規約の共役転置であることを確かめられる。
$N=7$ ではモードが $-3,\ldots,3$ と対称に並ぶ。

要求を $10^{-13}$ にすると核の幅は 15 に広がり、直接和との差は $1.4\times10^{-15}$ まで下がる。
同じ要求で座標を $2\pi\times1000$ ずらすと、$E_r$ の座標の項（$\lvert x\rvert>\pi$ の軸のモード数の和 $P=N$）が加わって $E_r$ は $7.3\times10^{-15}$ に増え、核の幅は 16 になる。
それでも直接和との差は $1.2\times10^{-12}$ で、要求を上回る。
差の大部分は計算の誤差ではなく、ずらした座標を浮動小数点数で表した段階の丸めで、推定 $E_r$ もこれを含まない。
差が $k=0$ で最も小さく、$\lvert k\rvert$ とともにおおむね大きくなることも、位相 $kx_j$ のずれが原因であることを示す。
要求精度の推定は渡された座標を正確な値とみなすので、座標は $[-\pi,\pi]$ に置いて渡す。

## 型 3 とリソースの上限の確認

次のセルは $[0, 40]$ 日に不規則に置いた $M=40$ 個の時刻 $t_j$ [日] の値 $c_j$ を、$[0,\omega_{\max}]$ に等間隔に並べた $L=16$ 個の角周波数 $\omega_\ell$ [rad/日] で型 3（`Forward`、$\sigma=-1$）に変換する。
入力は要求精度の指数と $\omega_{\max}$ である。
$\omega_{\max}$ を大きくすると、点の広がりと周波数の広がりの積が大きくなり、過標本格子が大きくなる。
確かめることは 3 つある。
型 3 の Plan の結果を、`f64` の固有メソッドで計算した直接和 $\sum_jc_je^{-i\omega_\ell t_j}$ と比べる。
関数 `nufft_type3` の結果を Plan の結果と比べ、同じ時刻を $x_j=2\pi t_j/40-\pi$ と角度に直した型 1（モード数 16）でも、関数 `nufft_type1` と Plan を比べる。
型 3 の Plan の `NufftDiagnostics` が返す値をそのまま `NufftLimits` の各欄の上限にして準備し、さらに 1 欄ずつ 1 だけ小さくして準備する。
差はどれも入力の 1 ノルム $\sum_j\lvert c_j\rvert$ で割った値で示す。

```rust
//| id: fft-nufft-type3-limits
//| ref: fft-nufft-type3-limits
//| title: 型 3 の直接和との比較、関数と Plan の一致、診断値と上限
//| run: reactive
//| crates: [scioxide-core, scioxide-fft]
//| inputs:
//|   accuracy_exponent: {"type":"integer","label":"要求精度の指数 p（ε_r = 10^p）","description":"入力の 1 ノルムに対する最大誤差の要求。","min":-12,"max":-3,"value":-9}
//|   max_frequency: {"type":"range","label":"最大の角周波数 ω_max [rad/日]","description":"周波数は [0, ω_max] に 16 個並ぶ。大きいほど格子が大きい。","min":2,"max":50,"step":2,"value":10}
//| cases:
//|   - {"id":"strict","label":"ε_r = 10⁻¹²","description":"核の幅が広がり、直接和との差が要求の範囲に下がる。","inputs":{"accuracy_exponent":-12}}
//|   - {"id":"wide-band","label":"ω_max = 50 rad/日","description":"格子点数と作業領域が増え、核の幅と延べ訪問数は変わらない。","inputs":{"max_frequency":50}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"type3","path":"/rows/0/4","range":{"max":1e-9}}
//|       - {"artifact":"type3","path":"/rows/0/5","range":{"max":1e-14}}
//|       - {"artifact":"type3","path":"/rows/0/6","range":{"max":1e-14}}
//|       - {"artifact":"limits","path":"/rows/0/2","equals":"成功"}
//|       - {"artifact":"limits","path":"/rows/0/3","equals":"ResourceLimit"}
//|       - {"artifact":"limits","path":"/rows/4/3","equals":"ResourceLimit"}
//|   - case: strict
//|     expect:
//|       - {"artifact":"type3","path":"/rows/0/4","range":{"max":1e-12}}
//|       - {"artifact":"limits","path":"/rows/2/3","equals":"ResourceLimit"}
//|   - case: wide-band
//|     expect:
//|       - {"artifact":"type3","path":"/rows/0/4","range":{"max":1e-9}}
//|       - {"artifact":"limits","path":"/rows/1/3","equals":"ResourceLimit"}
use scioxide_core::{Complex, ExecutionContext, SciOxideError, NdView};
use scioxide_fft::{
    FftDirection, Normalization, NufftDiagnostics, NufftLimits, NufftPlan, NufftPlanSpec,
    NufftTransform, nufft_type1, nufft_type3,
};

let (count, bins, span) = (40_usize, 16_usize, 40.0_f64);
let accuracy = 10f64.powi(accuracy_exponent);
let pi = std::f64::consts::PI;
// 不規則な時刻 t_j [日]、値 c_j、角周波数 ω_ℓ [rad/日]（f64 の三角関数は入力の生成だけ）
let t: Vec<f64> = (0..count)
    .map(|j| {
        span * (j as f64 + 0.8 * (0.618_033_988_749_895 * j as f64).fract()) / count as f64
    })
    .collect();
let c: Vec<Complex<f64>> = (0..count)
    .map(|j| Complex::new((0.9 * t[j]).cos(), 0.3 * (2.1 * t[j]).sin()))
    .collect();
let omega: Vec<f64> = (0..bins)
    .map(|l| max_frequency * l as f64 / (bins - 1) as f64)
    .collect();
let x: Vec<f64> = t.iter().map(|v| 2.0 * pi * v / span - pi).collect();
// 座標は形状 [点の数, 1] と [周波数の数, 1] のビュー
let (point_shape, frequency_shape) = ([count, 1], [bins, 1]);
let points = NdView::row_major(&t, &point_shape).map_err(|e| e.to_string())?;
let frequencies = NdView::row_major(&omega, &frequency_shape).map_err(|e| e.to_string())?;
let angles = NdView::row_major(&x, &point_shape).map_err(|e| e.to_string())?;
let type3 = || NufftTransform::Type3 {
    points,
    frequencies,
};
let spec = NufftPlanSpec::new(FftDirection::Forward, Normalization::Unscaled, accuracy);
let cx = ExecutionContext::sequential();
let l1: f64 = c.iter().map(|v| v.norm()).sum();
let gap = |p: &[Complex<f64>], q: &[Complex<f64>]| {
    p.iter()
        .zip(q)
        .map(|(a, b)| (*a - *b).norm())
        .fold(0.0_f64, f64::max)
        / l1
};

// 型 3 を Plan で求め、関数 nufft_type3 と比べる
let plan = NufftPlan::new(type3(), spec).map_err(|e| e.to_string())?;
let mut workspace = plan.workspace(()).map_err(|e| e.to_string())?;
let mut planned = vec![Complex::new(0.0, 0.0); bins];
plan.execute_into(&c[..], &mut planned[..], &mut workspace, cx)
    .map_err(|e| e.to_string())?;
let once = nufft_type3(
    points,
    &c[..],
    frequencies,
    FftDirection::Forward,
    Normalization::Unscaled,
    accuracy,
)
.map_err(|e| e.to_string())?;
// 独立な検算: 直接和 Σ_j c_j exp(−i ω_ℓ t_j)
let direct: Vec<Complex<f64>> = omega
    .iter()
    .map(|w| {
        c.iter()
            .zip(&t)
            .map(|(cj, tj)| *cj * Complex::from_polar(1.0, -w * tj))
            .sum()
    })
    .collect();

// 型 1（モード数 16）も関数 nufft_type1 と Plan で求めて比べる
let modes = [bins];
let type1 = NufftTransform::Type1 {
    points: angles,
    modes: &modes,
};
let plan1 = NufftPlan::new(type1, spec).map_err(|e| e.to_string())?;
let mut workspace1 = plan1.workspace(()).map_err(|e| e.to_string())?;
let mut planned1 = vec![Complex::new(0.0, 0.0); bins];
plan1
    .execute_into(&c[..], &mut planned1[..], &mut workspace1, cx)
    .map_err(|e| e.to_string())?;
let once1 = nufft_type1(
    angles,
    &c[..],
    &modes,
    FftDirection::Forward,
    Normalization::Unscaled,
    accuracy,
)
.map_err(|e| e.to_string())?;

// 診断値ちょうどの上限と、1 欄だけ 1 小さい上限で型 3 を準備する
let d: NufftDiagnostics = plan.diagnostics();
let exact = NufftLimits {
    preparation_bytes: d.preparation_bytes,
    workspace_bytes: d.workspace_bytes,
    grid_points: d.grid_points,
    stencil_visits: d.stencil_visits,
    kernel_support: d.kernel_support,
};
let label = |outcome: Result<NufftPlan<f64>, SciOxideError>| match outcome {
    Ok(_) => "成功".to_string(),
    Err(e) => format!("{:?}", e.kind()),
};
let fields = [
    ("kernel_support", d.kernel_support),
    ("grid_points", d.grid_points),
    ("stencil_visits", d.stencil_visits),
    ("workspace_bytes", d.workspace_bytes),
    ("preparation_bytes", d.preparation_bytes),
];
let mut rows = Vec::new();
for (index, (name, value)) in fields.into_iter().enumerate() {
    let mut tight = exact;
    match index {
        0 => tight.kernel_support -= 1,
        1 => tight.grid_points -= 1,
        2 => tight.stencil_visits -= 1,
        3 => tight.workspace_bytes -= 1,
        _ => tight.preparation_bytes -= 1,
    }
    let at = label(NufftPlan::new(type3(), spec.with_limits(exact)));
    let below = label(NufftPlan::new(type3(), spec.with_limits(tight)));
    rows.push((name, value, at, below));
}

let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let type3_columns = serde_json::json!([
    { "key": "0", "label": "核の幅 w", "type": "integer" },
    { "key": "1", "label": "格子点数 G", "type": "integer" },
    { "key": "2", "label": "推定 E_a [-]", "type": "number", "format": sci2 },
    { "key": "3", "label": "推定 E_r [-]", "type": "number", "format": sci2 },
    { "key": "4", "label": "直接和との差 / Σ|c_j| [-]", "type": "number", "format": sci2 },
    { "key": "5", "label": "nufft_type3 と Plan の差 / Σ|c_j| [-]", "type": "number", "format": sci2 },
    { "key": "6", "label": "nufft_type1 と Plan の差 / Σ|c_j| [-]", "type": "number", "format": sci2 }
]);
let summary = (
    d.kernel_support,
    d.grid_points,
    d.approximation_error,
    d.roundoff_error,
    gap(&planned, &direct),
    gap(&once, &planned),
    gap(&once1, &planned1),
);
emit_table_with_columns!(
    type3_columns,
    vec![summary],
    metadata = serde_json::json!({ "id": "type3" })
);
let limit_columns = serde_json::json!([
    { "key": "0", "label": "NufftLimits の欄" },
    { "key": "1", "label": "診断の値", "type": "integer" },
    { "key": "2", "label": "上限 = 診断の値" },
    { "key": "3", "label": "その欄だけ 1 小さい上限" }
]);
emit_table_with_columns!(
    limit_columns,
    rows,
    metadata = serde_json::json!({ "id": "limits" })
);
```

既定の要求 $10^{-9}$、$\omega_{\max}=10$ rad/日では、核の幅は 12、格子は 512 点で、推定は $E_a=1.5\times10^{-10}$、$E_r=4.7\times10^{-15}$ である。
直接和との差は入力の 1 ノルムの $3.0\times10^{-12}$ 倍で、要求の範囲に入る。
要求を $10^{-12}$ にすると核の幅は 15 に広がり、差は $7.6\times10^{-15}$ 倍に下がる。
$\omega_{\max}=50$ rad/日では格子が 2048 点に、作業領域が 38048 B から 152288 B に増えるが、核の幅と延べ訪問数 672 は変わらない。
延べ訪問数は点と周波数の数の和 56 と核の幅の積（$56\times12=672$）で、格子の大きさにはよらないからである。
関数 `nufft_type3` と `nufft_type1` はどの場合も Plan の結果とちょうど一致する。

上限の表では、どの欄も診断の値ちょうどなら準備が通り、その欄だけ 1 小さくすると `ResourceLimit` になる。
この Plan では、`NufftDiagnostics` の値が準備の上限の判定に使う量と一致する。
Plan は上限に合わせて核を狭めたり格子を小さくしたりしないので、上限を下げても精度を落とした Plan にはならず、準備が失敗する。

## まとめ

型 1 は非一様な点の値から整数モードへ、型 2 は整数モードから非一様な点へ、型 3 は非一様な点から任意の角周波数への指数和である。
符号は `FftDirection` で、係数 $s$ は `Normalization` と和を取る項の数で決まる。
型 1・2 の座標は周期 $2\pi$ の角度で、モードは $-\lfloor N/2\rfloor$ から昇順に並び、座標は $[-\pi,\pi]$ に置いて渡す。
Plan は借用を残さず、`diagnostics()` で選ばれた核の幅、格子、誤差の推定を読み、`NufftLimits` でメモリ使用量と演算量に上限を課せる。
上限を下回る準備は `ResourceLimit` になり、核や格子を小さくした Plan には切り替わらない。
型 2 は型 1 の逆変換ではなく、方向を反転すれば随伴になるので、逆問題はその随伴を使って別に解く。
