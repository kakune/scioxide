DFT を定義どおりに計算すると $N^2$ 回の複素乗算が要る。
高速 Fourier 変換（FFT）は、回転因子 $W_N = e^{-2\pi i/N}$ の周期性 $W_N^{k+N} = W_N^k$ と、偶数長での対称性 $W_N^{k+N/2} = -W_N^k$ を使い、長さ $N$ の変換を短い変換の組合せに分けて $O(N\log N)$ 回の演算で計算する。
このページでは分割の式、素数長を畳み込みに帰着する二つの方法、`scioxide-fft` が長さからアルゴリズムを選ぶ規則、計算コストと丸め誤差を説明する。
選ばれた Plan を再利用する方法、作業領域、キャッシュは[FFT の Plan・作業領域・キャッシュ](../plans-workspaces-and-providers/)で、外部実装の注入は[外部 FFT 実装と CPU 命令セット](../providers-and-cpu-backends/)で扱う。

## Cooley–Tukey 分割

### 基数 2 の時間間引き

$N = 2M$ のとき、入力を偶数番目 $x_{2m}$ と奇数番目 $x_{2m+1}$ に分ける。

$$
X_k = \sum_{m=0}^{M-1} x_{2m}\, W_M^{km} + W_N^k \sum_{m=0}^{M-1} x_{2m+1}\, W_M^{km} = E_k + W_N^k O_k
$$

$E_k$ と $O_k$ は長さ $M$ の DFT で、周期 $M$ を持つ。
$W_N^{k+M} = -W_N^k$ から、後半のビンは追加の乗算なしに

$$
X_k = E_k + W_N^k O_k, \qquad X_{k+M} = E_k - W_N^k O_k \qquad (0 \le k < M)
$$

と求まる。
この加減算の対をバタフライ演算と呼ぶ。
回転因子との乗算を自明な場合も含めて数えると $C(N) = 2C(N/2) + N/2$ であり、$N = 2^p$ では $C(N) = \frac{N}{2}\log_2 N$ 回になる。

### 混合基数

$N = N_1 N_2$ のとき、添字を $n = n_1 N_2 + n_2$、$k = k_2 N_1 + k_1$（$0 \le n_1, k_1 < N_1$、$0 \le n_2, k_2 < N_2$）と分けると

$$
W_N^{nk} = W_{N_1}^{n_1 k_1}\, W_N^{n_2 k_1}\, W_{N_2}^{n_2 k_2}
$$

となる（$W_N^{n_1 k_2 N_1 N_2} = 1$ の項が消える）。
長さ $N$ の変換は長さ $N_1$ の変換 $N_2$ 個、回転因子 $W_N^{n_2 k_1}$ の乗算、長さ $N_2$ の変換 $N_1$ 個の 3 段に分かれる。
これを繰り返すと、$N = r_1 r_2 \cdots r_s$ の各因子 $r_i$ が 1 つの段になる。

`scioxide-fft` は基数 2・3・4・5・7 の小さな DFT を段として持つ。
$N = 2^a 3^b 5^c 7^d$（2・3・5・7 の積の長さ）でだけ混合基数を使い、11 以上の素因数の段は持たない。
2 のべきでは基数 4 の段を並べ、因子 2 が奇数個なら基数 2 の段を 1 つ加える。
それ以外の長さでは、段の並びの候補を計算コストのモデル（要素あたりの演算量、回転因子の表の読み出し、小さなブロックの数）で比べる動的計画法で、最も計算コストが小さい並びを決定論的に選ぶ。
計算コストが等しいときは基数 4 を優先する。
このモデルは候補の順位を決めるための相対的な目安で、演算回数そのものを表さない。

## 素数長の変換

素数長 $p$ は段に分けられない。
次の二つの方法はどちらも長さ $p$ の DFT を、別の長さの FFT で計算できる畳み込みに書き換える。

### Rader のアルゴリズム

素数 $p$ の非零の剰余 $(\mathbb{Z}/p\mathbb{Z})^\times$ は位数 $p-1$ の巡回群であり、原始根 $g$ を使って $n = g^{-q}$、$k = g^{r}$（$q, r = 0,\dots,p-2$）と表せる。
代入すると $nk = g^{r-q}$ なので

$$
X_{g^{r}} = x_0 + \sum_{q=0}^{p-2} x_{g^{-q}}\, W_p^{g^{r-q}}
$$

となり、$a_q = x_{g^{-q}}$ と $b_m = W_p^{g^m}$ の長さ $p-1$ の巡回畳み込みに帰着する。
$X_0 = \sum_n x_n$ は別に足す。
`scioxide-fft` は準備のときに添字の置換と $b$ の FFT を作って保持し、実行では長さ $p-1$ の FFT を 2 回（$a$ の変換と、積の逆変換）と要素ごとの積で畳み込みを計算する。

### Bluestein のアルゴリズム

恒等式 $jk = \frac{1}{2}\left[j^2 + k^2 - (k-j)^2\right]$ を使い、チャープ $c_j = e^{-\pi i j^2/N}$ をおくと

$$
X_k = c_k \sum_{j=0}^{N-1}\left(x_j c_j\right) \overline{c_{k-j}}
$$

となる。
こうして任意の長さの DFT がチャープを掛けた列と $\overline{c_m}$（$-N < m < N$）の線形畳み込みになる。
巡回畳み込みで線形畳み込みを折り返しなく計算するには、長さ $L \ge 2N-1$ が要る。
`scioxide-fft` は $L$ を $2N-1$ 以上で最小の 2・3・5・7 の積に選び、$\overline{c}$ の FFT を準備のときに保持する。
実行では長さ $L$ の FFT を 2 回使い、逆変換は $\mathrm{IDFT}(x) = \overline{\mathrm{DFT}(\overline{x})}$ で同じチャープを使い回す。

チャープの位相 $\pi j^2/N$ を浮動小数点数でそのまま計算すると、$j^2$ が $N^2$ の大きさになるので、位相の絶対誤差が $\varepsilon N$ の程度まで育つ（$\varepsilon$ は機械イプシロン）。
`scioxide-fft` は $j^2 \bmod 2N$ を整数で求めてから角度に直すので、各チャープは丸めの程度の誤差で求まる。
チャープ Z 変換は同じ恒等式を単位円の外の輪郭に広げたもので、[チャープ Z 変換と zoom FFT](../chirp-z-and-zoom-fft/)で扱う。

## アルゴリズムの選択規則

`FftPlan` は長さから次の規則でアルゴリズムを決め、`diagnostics().algorithm()` で `FftAlgorithmKind` として返す。

| 長さ $N$ | アルゴリズム | `FftAlgorithmKind` |
|---|---|---|
| $N = 1$ | 恒等写像 | `Identity` |
| 2・3・5・7 の積（$N > 1$） | 混合基数の Cooley–Tukey | `MixedRadix` |
| $2^{20}$ 以下の素数で、$p-1$ が 2・3・5・7 の積であり、計算コストのモデルで Bluestein より計算コストが小さいもの | Rader | `Rader` |
| それ以外（11 以上の素因数を含む合成数も含む） | Bluestein | `Bluestein` |
| 外部から注入した実装が引き受けた長さ | プロバイダーの実装 | `Provider` |

Rader と Bluestein の比較では、長さ $p-1$ の FFT 2 回と長さ $L$ の FFT 2 回の計算コストを、混合基数と同じモデルで比べる。
$p-1$ が 2・3・5・7 の積でない素数に Rader を使うと、内側の畳み込みにもう一度 Rader か Bluestein が要る。
`scioxide-fft` はこの入れ子を作らず、その場合は Bluestein を使う。
11 以上の素因数を持つ合成数（例えば $22 = 2\cdot 11$）も、因数 11 の段を作らず全体を Bluestein で計算する。
$2^{20}$ の上限は準備のときの素数判定（試し割り）と原始根の探索の手間を抑えるためのものである。

`diagnostics().stage_count()` は、実行経路の FFT の段数の最大を返す。
混合基数では段の数、Rader と Bluestein では内側の畳み込みの FFT の段数に、前後の位相の積の 2 段を足した値である。
実数の配置（`FftLayout::Real`、`Hermitian`）の Plan は内側の複素 FFT のアルゴリズムを返す。
偶数長では内側は長さ $N/2$ の複素 FFT で、段数には実数のスペクトルへ組み立てる 1 段を足す。
3、5、7 のどれかで割り切れ、その数より長い奇数長（9、15、21 など）は、実数データをその基数で分解し、やはり組み立ての 1 段を足す。
それ以外の奇数長は長さ $N$ の複素 FFT をそのまま使い、段数もその複素 FFT の値になる。

## 計算コストと丸め誤差

演算量はどの長さでも $O(N\log N)$ だが、定数はアルゴリズムで異なる。

- 混合基数の段は、要素あたりの演算が基数ごとに決まった小さな DFT と回転因子の積である。
  基数 2 の FFT の実数演算は約 $5N\log_2 N$ 回で、基数 4・5・7 の段は 1 段で複数の因子を処理して段の数を減らす。
- Rader は長さ $p-1$ の FFT を 2 回使うので、演算量は近い長さの混合基数の変換の約 2 倍と見積もれる。
- Bluestein は長さ $L \ge 2N-1$ の FFT 2 回とチャープの積 $2N$ 回を使う。
  長さ約 $2N$ の FFT 2 回は長さ $N$ の FFT の 4 倍強の演算量なので、近い長さの混合基数の変換の 4 倍以上と見積もれる。
  $L$ は $2N-1$ 以上で最小の 2・3・5・7 の積なので、$L/(2N-1)$ は 1 に近い。

準備（`FftPlan::new`、`build`）では、段の並びの選択、回転因子の表、Rader の置換と核の FFT、Bluestein のチャープと核の FFT を一度だけ計算する。
Bluestein の準備は核の FFT を 1 回含むので、実行 1 回より重い。
Plan を使い回す理由はここにある。

丸め誤差について、基数 2 の Cooley–Tukey は回転因子の誤差を $\mu$ として、正規化した 2 ノルムの相対誤差が $\log_2 N$ 倍の $\mu + O(\varepsilon)$ で抑えられることが知られている（Higham 2002, §24.1）。
総和を 1 つずつ足す直接の DFT では、誤差の上限が $N$ に比例して育つ。
SciOxide の CPU 実装の複素と実数の順変換は、100 桁と 160 桁の精度で計算した参照の DFT と比べる試験で、相対 L2 誤差が

$$
\frac{\lVert \hat X - X\rVert_2}{\lVert X\rVert_2} \le 2\varepsilon\max(1, \log_2 N)
$$

以下であることを確かめている。
試験の範囲は 6720 までの 2・3・5・7 の積の長さ、奇数長 3375、65537 までの Rader の素数長、10007 までの Bluestein の素数長で、`f32` と `f64`、すべての CPU 実装である。
これは試験で確認したノルムでの範囲で、証明した上限ではない。
最大のビンよりずっと小さいビンの相対誤差は大きくなりうる。
外部から注入した実装の精度はこの範囲に含まれない。

## 速い長さの選択

長さを自由に選べるとき（畳み込みのゼロパディングなど）は、`next_fast_len(n)` が $n$ 以上で最小の 2・3・5・7 の積を返す。
`prev_fast_len(n)` は $n$ 以下で最大の 2・3・5・7 の積を返し、列を切り詰めるときに使う。
どちらも $n = 0$ では `InvalidInput`、`next_fast_len` は結果が `usize` に収まらないとき `SizeOverflow` を返す。
結果は実数と複素数の変換で共通である。
混合基数の段だけで計算できる長さを返すが、どのプロセッサでも最速の長さであるとは限らない。
DFT は入力の長さそのもので計算するので、ゼロパディングはスペクトルの格子を変える。
ゼロパディングの長さを選ぶ実例は[畳み込みと相関](../convolution-correlation-and-analytic-signals/)にある。

## 長さごとのアルゴリズムと誤差の実験

次のセルは入力した長さ $N$ から $N+11$ までの 12 通りについて `f32` の `FftPlan` を作り、選ばれたアルゴリズム、段数、作業領域の要素数、Bluestein の畳み込み長 $L$ を表にする。
各長さで決定論的な入力を変換し、同じ入力の $O(N^2)$ の直接和を `f64` で計算した独立な参照と比べる。
参照の誤差は `f32` の FFT の誤差より 6 桁以上小さいので、相対 L2 差は `f32` の FFT の誤差とみなせる。
最後の列はその差を試験で確認した範囲 $2\varepsilon_{32}\max(1,\log_2 N)$（$\varepsilon_{32} = 2^{-23}$）で割った比である。
入力と参照の回転因子の生成には f64 の `cos`・`sin` を使う。
2 つ目の表は同じ 12 通りの $N$ について `prev_fast_len` と `next_fast_len` の結果を、$N$ から 1 ずつ下と上へ動かして最初の 2・3・5・7 の積を探す独立な探索の結果と並べる。
返った長さで作った Plan のアルゴリズムも示し、その長さが混合基数の段だけで計算されることを確かめる。

```rust
//| id: fft-planner-algorithm-choice
//| ref: fft-planner-algorithm-choice
//| title: 変換長ごとのアルゴリズムの選択と f32 の誤差を Plan の診断で確かめる
//| run: reactive
//| crates: [scioxide-core, scioxide-fft]
//| inputs:
//|   start_length: {"type":"range","label":"最初の変換長 N","description":"N から N+11 までの 12 通りの長さで Plan を作る。","min":1,"max":1000,"step":1,"value":96}
//| cases:
//|   - {"id":"short-lengths","label":"N = 1〜12","description":"長さ 1 の恒等写像と、素数 11 の Rader が現れる。","inputs":{"start_length":1}}
//|   - {"id":"near-thousand","label":"N = 1000〜1011","description":"大きな素因数を持つ長さで Bluestein が多くなり、畳み込み長 L が 2N − 1 をわずかに超える。","inputs":{"start_length":1000}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"algorithms","path":"/rows/0/2","equals":"MixedRadix"}
//|       - {"artifact":"algorithms","path":"/rows/1/2","equals":"Rader"}
//|       - {"artifact":"algorithms","path":"/rows/7/2","equals":"Bluestein"}
//|       - {"artifact":"algorithms","path":"/rows/0/4","approx":{"value":192,"atol":0.5}}
//|       - {"artifact":"algorithms","path":"/rows/7/5","approx":{"value":210,"atol":0.5}}
//|       - {"artifact":"algorithms","path":"/rows/0/7","range":{"max":1}}
//|       - {"artifact":"fast-lengths","path":"/rows/1/1","approx":{"value":96,"atol":0.5}}
//|       - {"artifact":"fast-lengths","path":"/rows/1/2","approx":{"value":96,"atol":0.5}}
//|       - {"artifact":"fast-lengths","path":"/rows/1/4","approx":{"value":98,"atol":0.5}}
//|       - {"artifact":"fast-lengths","path":"/rows/7/1","approx":{"value":100,"atol":0.5}}
//|       - {"artifact":"fast-lengths","path":"/rows/7/3","equals":"MixedRadix"}
//|       - {"artifact":"fast-lengths","path":"/rows/10/4","approx":{"value":108,"atol":0.5}}
//|       - {"artifact":"fast-lengths","path":"/rows/10/5","approx":{"value":108,"atol":0.5}}
//|   - case: short-lengths
//|     expect:
//|       - {"artifact":"algorithms","path":"/rows/0/2","equals":"Identity"}
//|       - {"artifact":"algorithms","path":"/rows/0/4","approx":{"value":0,"atol":0.5}}
//|       - {"artifact":"algorithms","path":"/rows/10/2","equals":"Rader"}
//|       - {"artifact":"fast-lengths","path":"/rows/0/3","equals":"Identity"}
//|       - {"artifact":"fast-lengths","path":"/rows/10/1","approx":{"value":10,"atol":0.5}}
//|       - {"artifact":"fast-lengths","path":"/rows/10/4","approx":{"value":12,"atol":0.5}}
//|   - case: near-thousand
//|     expect:
//|       - {"artifact":"algorithms","path":"/rows/0/2","equals":"MixedRadix"}
//|       - {"artifact":"algorithms","path":"/rows/1/2","equals":"Bluestein"}
//|       - {"artifact":"fast-lengths","path":"/rows/1/4","approx":{"value":1008,"atol":0.5}}
//|       - {"artifact":"fast-lengths","path":"/rows/11/1","approx":{"value":1008,"atol":0.5}}
//|       - {"artifact":"fast-lengths","path":"/rows/11/4","approx":{"value":1024,"atol":0.5}}
//|       - {"artifact":"fast-lengths","path":"/rows/11/6","equals":"MixedRadix"}
use scioxide_core::{Complex, ExecutionContext};
use scioxide_fft::{
    FftAlgorithmKind, FftDirection, FftLayout, FftPlan, FftPlanSpec, Normalization,
    next_fast_len, prev_fast_len,
};

let first = start_length.round() as usize;
let cx = ExecutionContext::sequential();
// 素因数分解を文字列にする（表示用）
let factor = |mut n: usize| {
    let mut parts = Vec::new();
    let mut d = 2;
    while d * d <= n {
        while n % d == 0 {
            parts.push(d.to_string());
            n /= d;
        }
        d += 1;
    }
    if n > 1 || parts.is_empty() {
        parts.push(n.to_string());
    }
    parts.join("·")
};
let spec_of = |n: usize| {
    FftPlanSpec::new(
        n,
        FftDirection::Forward,
        Normalization::Unscaled,
        FftLayout::Complex,
    )
};
// 独立検算用: 2・3・5・7 で割れるだけ割って 1 になるか（速い長さの判定）
let smooth = |mut m: usize| {
    for p in [2, 3, 5, 7] {
        while m % p == 0 {
            m /= p;
        }
    }
    m == 1
};
// 長さ length の Plan が選ぶアルゴリズムの名前
let algorithm_of = |length: usize| {
    FftPlan::<f32>::build(spec_of(length), cx)
        .map(|plan| format!("{:?}", plan.diagnostics().algorithm()))
        .map_err(|e| e.to_string())
};
let mut rows = Vec::new();
let mut fast_rows = Vec::new();
for n in first..first + 12 {
    let plan = FftPlan::<f32>::build(spec_of(n), cx).map_err(|e| e.to_string())?;
    let diagnostics = plan.diagnostics();
    let scratch = plan
        .workspace_requirements(())
        .map_err(|e| e.to_string())?
        .complex_len();
    // 決定論的な入力 x_j = cos(0.7 j) + i sin(1.3 j²/N)（生成は f64 の関数）
    let input: Vec<Complex<f32>> = (0..n)
        .map(|j| {
            let t = j as f64;
            Complex::new(
                (0.7 * t).cos() as f32,
                (1.3 * t * t / n as f64).sin() as f32,
            )
        })
        .collect();
    let mut output = vec![Complex::new(0.0_f32, 0.0); n];
    let mut workspace = plan.workspace(()).map_err(|e| e.to_string())?;
    plan.execute_into(&input, &mut output, &mut workspace, cx)
        .map_err(|e| e.to_string())?;
    // 独立な参照: 同じ f32 の入力の定義どおりの和を f64 でとる（回転因子は f64 の cos・sin）
    let twiddle: Vec<Complex<f64>> = (0..n)
        .map(|m| {
            let a = -2.0 * std::f64::consts::PI * m as f64 / n as f64;
            Complex::new(a.cos(), a.sin())
        })
        .collect();
    let (mut difference, mut reference) = (0.0_f64, 0.0_f64);
    for (k, y) in output.iter().enumerate() {
        let mut direct = Complex::new(0.0_f64, 0.0);
        for (j, x) in input.iter().enumerate() {
            direct += Complex::new(x.re as f64, x.im as f64) * twiddle[(j * k) % n];
        }
        difference += (Complex::new(y.re as f64, y.im as f64) - direct).norm_sqr();
        reference += direct.norm_sqr();
    }
    let error = (difference / reference).sqrt();
    let bound = 2.0 * f32::EPSILON as f64 * (n as f64).log2().max(1.0);
    // Bluestein の作業領域は N + 2L なので、そこから L を読む
    let bluestein = diagnostics.algorithm() == FftAlgorithmKind::Bluestein;
    let convolution = bluestein.then(|| (scratch - n) / 2);
    rows.push((
        n,
        factor(n),
        format!("{:?}", diagnostics.algorithm()),
        diagnostics.stage_count(),
        scratch,
        convolution,
        error,
        error / bound,
    ));
    // 速い長さを、1 ずつ動かす独立な探索の結果と、その長さの Plan が選ぶアルゴリズムと並べる
    let prev = prev_fast_len(n).map_err(|e| e.to_string())?;
    let next = next_fast_len(n).map_err(|e| e.to_string())?;
    let prev_search = (1..=n).rev().find(|&m| smooth(m));
    let next_search = (n..).find(|&m| smooth(m));
    fast_rows.push((
        n,
        prev,
        prev_search,
        algorithm_of(prev)?,
        next,
        next_search,
        algorithm_of(next)?,
    ));
}
```

既定の $N = 96$〜$107$ では、96・98・100・105 が `MixedRadix`、97 と 101 が `Rader`（$97-1 = 96$ と $101-1 = 100$ が 2・3・5・7 の積）、残りの 6 つが `Bluestein` になる。
$99 = 3^2\cdot 11$ や $104 = 2^3\cdot 13$ のように 11 以上の素因数を 1 つでも含むと、合成数でも Bluestein になる。
Bluestein の作業領域は $N + 2L$ 個で、$N = 103$ では $L = 210$（$2N-1 = 205$ 以上で最小の 2・3・5・7 の積）、作業領域は 523 個と、混合基数の $2N$ 個の約 2.5 倍になる。
相対 L2 差は混合基数で $1\times10^{-7}$ 前後、Rader と Bluestein で $2\times10^{-7}$ 前後で、どれも試験で確認した範囲の 0.15 倍以下に収まる。
Rader と Bluestein の差が混合基数の約 2 倍になるのは、畳み込みの FFT 2 回と位相の積を通るためと考えられる。
これはこの入力での観測で、一般の比を示すものではない。

$N = 1$〜$12$ では、長さ 1 が `Identity`（作業領域 0 個）、11 が `Rader` になる。
$N = 1000$〜$1011$ では 1009 が `Rader`（$1008 = 2^4\cdot3^2\cdot7$）、1000 と 1008 が混合基数で、残りは $L = 2016$ か $2025$ の Bluestein になる。
段数、作業領域、誤差の比からはメモリ使用量と精度を比べられるが、実行時間は決まらない。

`prev_fast_len` と `next_fast_len` はどの $N$ でも独立な探索と同じ長さを返し、その長さの Plan はすべて `MixedRadix`（長さ 1 では `Identity`）を選ぶ。
既定の範囲では、例えば $N = 103$ が下へ 100、上へ 105 に移り、$N = 106$ と $107$ の次の速い長さは 108 である。
$N = 1009$〜$1011$ では下の速い長さが 1008、上が 1024 と離れており、切り詰めとゼロパディングで変わる標本数が大きく違う。

## まとめ

`scioxide-fft` はどの長さも $O(N\log N)$ で変換し、2・3・5・7 の積の長さには混合基数、条件を満たす素数には Rader、それ以外には Bluestein を選ぶ。
選ばれたアルゴリズムと段数は `diagnostics()` で読める。
Bluestein は長さ $2N-1$ 以上の FFT を 2 回使うので、長さを自由に選べるときは `next_fast_len` で 2・3・5・7 の積にゼロパディングする方が計算コストが小さい。
丸め誤差は試験の範囲で $2\varepsilon\max(1,\log_2 N)$ 以下で、Rader と Bluestein の長さも同じ範囲に入る。
これはノルムでの範囲で、小さなビンの相対誤差や外部の実装の精度は別に確かめる。
