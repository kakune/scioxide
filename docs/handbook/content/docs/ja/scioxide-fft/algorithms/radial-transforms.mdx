円や球の対称性を持つ関数の Fourier 変換は、動径方向だけの 1 次元の積分になる。
この積分を Hankel 変換と呼ぶ。
`scioxide-fft` は Hankel 変換を 2 つの方法で計算する。
このページでは区間 $[0, R]$ の Bessel 関数の零点に節点を置く離散 Hankel 変換（`DiscreteHankelPlan`、`dht`、`idht`）を説明する。
半径と波数が何桁にも広がる場合に使う対数格子の FFTLog は、[FFTLog と対数格子](../fftlog/)で説明する。

## 軸対称な関数の Fourier 変換

$d$ 次元の関数 $f(\mathbf{x})$ が半径 $r = \lvert\mathbf{x}\rvert$ だけで決まるとする。
Fourier 変換 $\hat f(\mathbf{k}) = \int f(\mathbf{x})\, e^{-i\mathbf{k}\cdot\mathbf{x}}\, d\mathbf{x}$ も波数の大きさ $k = \lvert\mathbf{k}\rvert$ だけで決まり、角度について積分すると

$$
\hat f(k) = (2\pi)^{d/2}\, k^{1-d/2} \int_0^\infty f(r)\, r^{d/2-1}\, J_{d/2-1}(kr)\, r\,dr
$$

になる（$J_\nu$ は第一種 Bessel 関数）。
そこで、次数 $\nu$ の Hankel 変換を

$$
F(k) = \int_0^\infty g(r)\, J_\nu(kr)\, r\,dr
$$

と定める。
$d$ 次元の Fourier 変換は $\nu = d/2 - 1$、$g(r) = r^{d/2-1} f(r)$ とした Hankel 変換に係数 $(2\pi)^{d/2} k^{1-d/2}$ を掛けたものである。
2 次元では $\nu = 0$、$g = f$ で $\hat f(k) = 2\pi F(k)$ になる。
3 次元では $\nu = 1/2$、$g(r) = r^{1/2} f(r)$ で $\hat f(k) = (2\pi)^{3/2} k^{-1/2} F(k)$ になる。
光学の円形開口、軸対称な拡散、宇宙論のパワースペクトルと相関関数がこの形の変換を使う。

`scioxide-fft` の Hankel 変換は $\nu > -1/2$ を受け付ける。
1 次元（$\nu = -1/2$）では Hankel 変換が余弦変換になるので、離散の計算には [DCT・DST と境界条件](../dct-dst-and-boundaries/)を使う。

## Fourier–Bessel 級数と零点の格子

$J_\nu$ の正の零点を $j_1 < j_2 < \cdots$ とする。
$g$ が $r \ge R$ で 0 なら、$[0, R]$ の Fourier–Bessel 級数

$$
g(r) = \sum_{m=1}^{\infty} c_m\, J_\nu\!\left(\frac{j_m r}{R}\right), \qquad
c_m = \frac{2}{R^2 J_{\nu+1}(j_m)^2} \int_0^R g(r)\, J_\nu\!\left(\frac{j_m r}{R}\right) r\,dr
$$

が成り立つ（Bessel 関数の直交性、DLMF 10.22.37）。
係数の積分は波数 $\kappa_m = j_m / R$ での Hankel 変換そのものなので、$c_m = 2F(\kappa_m) / (R^2 J_{\nu+1}(j_m)^2)$ である。

さらに $F$ が $\kappa \ge j_{n+1}/R$ で無視できるとして、級数を $n$ 項で打ち切る。
打ち切った級数を動径の節点

$$
r_k = R\,\frac{j_k}{j_{n+1}} \qquad (k = 1, \dots, n)
$$

で評価すると、$F(\kappa_m)$ から $g(r_k)$ を求める式が得られる。
役割を入れ替えて、$F$ を $[0, j_{n+1}/R]$ の Fourier–Bessel 級数に展開すると、逆に $g(r_k)$ から $F(\kappa_m)$ を求める式が得られる。
2 つの式は次のとおりである。

$$
F(\kappa_m) \approx \left(\frac{R}{j_{n+1}}\right)^2 \sum_{k=1}^{n} \frac{2\, J_\nu(j_m j_k / j_{n+1})}{J_{\nu+1}(j_k)^2}\, g(r_k),
\qquad
g(r_k) \approx \frac{1}{R^2} \sum_{m=1}^{n} \frac{2\, J_\nu(j_k j_m / j_{n+1})}{J_{\nu+1}(j_m)^2}\, F(\kappa_m)
$$

左の式が順方向、右の式が逆方向の求積である。
この形は Johnson（1987）の離散 Hankel 変換である。

仮定は 2 つある。
$g$ が $r > R$ で十分小さいこと、$F$ が $\kappa > j_{n+1}/R$ で十分小さいことである。
零でない関数が両方の範囲で厳密に 0 になることはないので、離散 Hankel 変換は近似になる。
誤差は主に、範囲の外に残る $g$ の裾と $F$ の裾から生じる。
McMahon の漸近形 $j_m \approx (m + \nu/2 - 1/4)\pi$ から、周波数の上限は $j_{n+1}/R \approx n\pi/R$ になる。
必要な波数の範囲を $\kappa_{\max}$ とすると、標本数は $n \gtrsim R\,\kappa_{\max}/\pi$ が目安になる。

順方向と逆方向の行列は、どちらも同じ対称な核 $J_\nu(j_k j_m / j_{n+1})$ と重み $2/J_{\nu+1}(j_k)^2$ からなり、係数だけが違う。
2 つの求積は互いの厳密な逆ではなく、続けて掛けた行列は一般には単位行列にならない。
ただし $\nu = 1/2$ では零点が $j_k = k\pi$ で、核は $\sin(\pi km/(n+1))/\sqrt{km}$ に、重みは $\pi^2 k$ に比例する。
このとき DST-I の直交性 $\sum_{m=1}^{n} \sin(\pi km/(n+1))\sin(\pi ml/(n+1)) = \frac{n+1}{2}\delta_{kl}$ から、続けて掛けた行列は丸めを除いて単位行列になる。
どちらの場合も、往復で元に戻ることは連続の変換への近さを示さない。

## 零点の検査

零点は呼び出し側が渡す。
$\nu = 1/2$ では $J_{1/2}(x) = \sqrt{2/(\pi x)}\,\sin x$ なので、零点は $k\pi$ である。
他の次数の零点は[scioxide-rootfind の特殊関数の零点](../../../scioxide-rootfind/algorithms/special-function-zeros/)で求められる。

準備は渡された $n+1$ 個の零点 $z_k$ を次の 3 つで検査し、満たさなければ `InvalidInput` を返す。

1. Newton 法の補正量 $c_k = \lvert J_\nu(z_k) / J_\nu'(z_k)\rvert$ が $\max(a, r z_k)$ 以下である。
   $a$ と $r$ は `Tolerance` の絶対許容と相対許容で、既定は `Tolerance::from_sqrt_epsilon()`（$a = r = \sqrt{\varepsilon}$）である。
2. $J_\nu'(z_k)$ の符号が、$k$ 番目の正の零点の符号 $(-1)^k$ と一致する。
3. $z_k$ が、準備が自分で求めた $k$ 番目の零点の区間から $\max(a, r z_k)$ 以内にある。
   これで、途中の零点を偶数個飛ばした列も拒否する。

受け入れた零点は丸めずにそのまま使う。
既定の許容は作業精度に丸めた零点（補正量は約 $\varepsilon z_k/2$）を受け入れる。
完全な精度の零点を要求するときは、`DiscreteHankelPlanSpec::with_tolerance` で許容を狭める。
零点の区間を求める Bessel 関数の評価も、準備の計算量に数える。

## 計算量と丸め誤差

準備は対称な核の異なる値 $n(n+1)/2$ 個と重み $n$ 個を Bessel 関数で評価し、$n \times n$ の行列を保持する。
準備の評価回数とメモリ使用量はどちらも $O(n^2)$ である。
実行は 1 回の行列とベクトルの積で、$O(n^2)$ 回の積和である。
FFT は使わない（`resolved_backends()` は空の列を返す）。

行列の各行と入力は、仮数と 2 進の指数を別に持つ。
そのため、係数 $(R/j_{n+1})^2$ や $1/R^2$ がスカラー型の範囲を超えても、結果が範囲内なら計算できる。
積和は補償付きの総和を決まった順で行うので、実行方針（スレッド数）によらず同じビット列になる。

rustdoc は丸め誤差の範囲を精度の保証として示す。
出力の各成分は、指数の範囲を広げた補償付きの内積との差が

$$
8\varepsilon\,(n+2) \sum_k \lvert m_{ik}\rvert\,\lvert x_k\rvert
$$

と最小の非正規化数 2 個分の和以下である。
$m_{ik}$ は Plan の方向の行列の成分、$x_k$ は入力の実部または虚部である。
この上界は丸めの範囲だけを表し、連続の積分との差（求積の誤差）は含まない。
求積の誤差は $g$ と $F$ の裾で決まるので、解析解や範囲を広げた計算と比べて確かめる。

## Plan と簡易 API

- 仕様 `DiscreteHankelPlanSpec::new(order, extent, direction)` は次数 $\nu$、範囲 $R$、方向を受け取る。
  `FftDirection::Forward` は $g(r_k)$ から $F(\kappa_m)$ への順方向の求積、`Inverse` は逆方向の求積である。
  `with_tolerance` は零点の許容、`with_limits` は上限、`with_iteration_budget` は実行ごとの反復の上限（1 本の変換で $n$ 回）、`with_execution_policy` は行列とベクトルの積の実行方針を設定する。
- 上限 [`HankelLimits`](https://docs.rs/scioxide-fft/0.1.0/scioxide_fft/struct.HankelLimits.html) は準備のメモリ使用量 `preparation_bytes`、作業領域のメモリ使用量 `workspace_bytes`、準備の計算量 `preparation_work`（関数の呼び出しと Bessel 関数の反復の総数）を持つ。
  既定はすべて上限なしである。
  メモリ使用量の上限を超えると `ResourceLimit`、計算量を使い切ると `ConvergenceFailure` を返す。
- Plan `DiscreteHankelPlan::new(zeros, spec)` は最初の $n+1$ 個の正の零点を借用して検査し、節点、周波数、行列を自分で持つ。
  零点の列は Plan に残らない。
  `build(zeros, spec, scope)` は準備処理の計算回数を親の求解にも加算する。
- 節点 $r_k$ は `nodes()`、周波数 $\kappa_m$ は `frequencies()` が昇順で返す。
  $r_k$ は $R$ と同じ長さの単位、$\kappa_m$ はその逆数の単位である。
- 実行 `execute_into(input, output, workspace, scope)` は長さ $n$ の複素数の列を受け取る。
  行列は実数なので、実部と虚部は別々に変換される。
  作業領域は `workspace(())` で一度確保し、同じ Plan の実行で使い回す。
  `execute_axis_into` は多次元配列の 1 つの軸に沿って、各列をまとめて変換する。
- 診断 [`DiscreteHankelDiagnostics`](https://docs.rs/scioxide-fft/0.1.0/scioxide_fft/struct.DiscreteHankelDiagnostics.html) は `diagnostics()` で得る。
  `maximum_zero_residual` は零点での $\lvert J_\nu(z_k)\rvert$ の最大、`maximum_zero_correction` は Newton 法の補正量の最大、`preparation_work` は準備で使った計算量である。
  どれも零点と準備の診断で、求積の誤差の推定ではない。
- Plan は `LinearOperator` と `AdjointOperator` を実装する。
  随伴は Plan の方向の行列の転置を掛ける。
- 簡易 API `dht(input, zeros, order, extent)` と `idht` は、実数の標本に順方向と逆方向の求積を 1 回だけ行い、実数の列を返す。
  零点の許容は既定の値に固定される。
  `input` の長さが `zeros.len() − 1` でなければ `DimensionMismatch` を返す。

失敗の分類は次のとおりである。
零点が 2 個未満、正でない、増加しない、許容を満たさない、連続しない場合と、$\nu \le -1/2$ または $R \le 0$ の場合は `InvalidInput` になる。
零点、次数、範囲、標本に NaN か無限大があれば `NonFinite` になる。
節点や周波数が表せない場合と、重みが 0 に丸まる場合は `NumericalInstability` になる。

次のセルは $\nu=1/2$、$R=6$ の格子で $g(r)=r^{1/2}e^{-r}$ の $n$ 個の標本を変換し、簡易 API と Plan、上限の働きを確かめる。
入力は標本数 $n$ で、零点 $k\pi$（$k=1,\ldots,n+1$）を渡す。
確かめることは 2 つある。
1 つめは `dht` の結果を順方向の Plan の `execute_into` の結果と、その結果の実部に `idht` を掛けたものを逆方向の Plan の結果と比べることである。
差は Plan の出力の大きさの最大で割った値で示す。
2 つめは `HankelLimits` の `preparation_work` と `workspace_bytes` である。
基準の値は、順方向の Plan の `DiscreteHankelDiagnostics` が返す準備の計算量と、`workspace_requirements(())` が返す作業領域のバイト数にする。
どちらもその値ちょうどの上限と 1 だけ小さい上限で準備と作業領域の確保を試す。

```rust
//| id: fft-hankel-function-limits
//| ref: fft-hankel-function-limits
//| title: dht・idht と Plan の一致、HankelLimits の各欄
//| run: reactive
//| crates: [scioxide-core, scioxide-fft]
//| inputs:
//|   samples: {"type":"integer","label":"標本数 n","description":"零点を n+1 個使う。準備の計算量とメモリ使用量が n² で増える。","min":4,"max":48,"value":16}
//| cases:
//|   - {"id":"many-samples","label":"n = 48","description":"行列が 9 倍になり、準備の計算量と plan_bytes() が増える。","inputs":{"samples":48}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"agreement","path":"/rows/0/0","equals":16}
//|       - {"artifact":"agreement","path":"/rows/0/1","range":{"max":1e-14}}
//|       - {"artifact":"agreement","path":"/rows/0/2","range":{"max":1e-14}}
//|       - {"artifact":"limits","path":"/rows/0/2","equals":"成功"}
//|       - {"artifact":"limits","path":"/rows/1/2","equals":"ConvergenceFailure"}
//|       - {"artifact":"limits","path":"/rows/2/1","approx":{"value":512,"atol":0.5}}
//|       - {"artifact":"limits","path":"/rows/3/2","equals":"ResourceLimit"}
//|   - case: many-samples
//|     expect:
//|       - {"artifact":"agreement","path":"/rows/0/1","range":{"max":1e-14}}
//|       - {"artifact":"limits","path":"/rows/1/2","equals":"ConvergenceFailure"}
//|       - {"artifact":"limits","path":"/rows/2/1","approx":{"value":1536,"atol":0.5}}
use scioxide_core::{Budget, Complex, ExecutionContext, SciOxideError};
use scioxide_fft::{
    DiscreteHankelDiagnostics, DiscreteHankelPlan, DiscreteHankelPlanSpec, FftDirection,
    HankelLimits, dht, idht,
};

let n = samples as usize;
let (order, extent) = (0.5_f64, 6.0_f64);
let pi = std::f64::consts::PI;
// J_{1/2} の正の零点 kπ（k = 1, …, n+1）
let zeros: Vec<f64> = (1..=n + 1).map(|k| k as f64 * pi).collect();
let spec = |direction| DiscreteHankelPlanSpec::new(order, extent, direction);
let forward =
    DiscreteHankelPlan::new(&zeros, spec(FftDirection::Forward)).map_err(|e| e.to_string())?;
let inverse =
    DiscreteHankelPlan::new(&zeros, spec(FftDirection::Inverse)).map_err(|e| e.to_string())?;
// 標本 g(r_k) = r_k^{1/2} e^{−r_k}（f64 の関数は入力の生成だけに使う）
let g: Vec<f64> = forward
    .nodes()
    .iter()
    .map(|r| r.sqrt() * (-r).exp())
    .collect();
let input: Vec<Complex<f64>> = g.iter().map(|&v| Complex::new(v, 0.0)).collect();
let cx = ExecutionContext::sequential();
let mut workspace = forward.workspace(()).map_err(|e| e.to_string())?;
let mut transform = vec![Complex::new(0.0, 0.0); n];
forward
    .execute_into(&input, &mut transform, &mut workspace, cx)
    .map_err(|e| e.to_string())?;
let mut back = vec![Complex::new(0.0, 0.0); n];
inverse
    .execute_into(&transform, &mut back, &mut workspace, cx)
    .map_err(|e| e.to_string())?;

// 簡易 API は実数の列を受け取り、既定の零点の許容で Plan を作って捨てる
let once = dht(&g, &zeros, order, extent).map_err(|e| e.to_string())?;
let real_transform: Vec<f64> = transform.iter().map(|z| z.re).collect();
let once_back = idht(&real_transform, &zeros, order, extent).map_err(|e| e.to_string())?;
let gap = |p: &[f64], q: &[Complex<f64>]| {
    let scale = q.iter().map(|z| z.norm()).fold(0.0_f64, f64::max);
    p.iter()
        .zip(q)
        .map(|(a, b)| (*a - b.re).abs().max(b.im.abs()))
        .fold(0.0_f64, f64::max)
        / scale
};

// 上限ちょうどと 1 小さい上限で、順方向の準備と作業領域の確保を試す
let d: DiscreteHankelDiagnostics = forward.diagnostics();
let plain_bytes = forward
    .workspace_requirements(())
    .map_err(|e| e.to_string())?
    .bytes();
let attempt = |limits: HankelLimits| {
    DiscreteHankelPlan::new(&zeros, spec(FftDirection::Forward).with_limits(limits))
        .and_then(|plan| plan.workspace(()).map(|_| ()))
};
let label = |outcome: Result<(), SciOxideError>| match outcome {
    Ok(()) => "成功".to_string(),
    Err(e) => format!("{:?}", e.kind()),
};
let work_limit = |work: usize| -> Result<HankelLimits, String> {
    let budget = Budget::try_from(work).map_err(|e| e.to_string())?;
    Ok(HankelLimits {
        preparation_work: budget,
        ..HankelLimits::default()
    })
};
let bytes_limit = |bytes: usize| HankelLimits {
    workspace_bytes: bytes,
    ..HankelLimits::default()
};
let mut rows = Vec::new();
for work in [d.preparation_work, d.preparation_work - 1] {
    rows.push(("preparation_work", work, label(attempt(work_limit(work)?))));
}
for bytes in [plain_bytes, plain_bytes - 1] {
    rows.push(("workspace_bytes", bytes, label(attempt(bytes_limit(bytes)))));
}

let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let agreement_columns = serde_json::json!([
    { "key": "0", "label": "標本数 n", "type": "integer" },
    { "key": "1", "label": "dht と Plan の差 / 出力の最大 [-]", "type": "number", "format": sci2 },
    { "key": "2", "label": "idht と Plan の差 / 出力の最大 [-]", "type": "number", "format": sci2 },
    { "key": "3", "label": "零点での |J_ν| の最大 [-]", "type": "number", "format": sci2 },
    { "key": "4", "label": "plan_bytes() [B]", "type": "integer" }
]);
let agreement = (
    n,
    gap(&once, &transform),
    gap(&once_back, &back),
    d.maximum_zero_residual,
    forward.plan_bytes(),
);
emit_table_with_columns!(
    agreement_columns,
    vec![agreement],
    metadata = serde_json::json!({ "id": "agreement" })
);
let limit_columns = serde_json::json!([
    { "key": "0", "label": "HankelLimits の欄" },
    { "key": "1", "label": "上限 [回か B]", "type": "integer" },
    { "key": "2", "label": "結果" }
]);
emit_table_with_columns!(
    limit_columns,
    rows,
    metadata = serde_json::json!({ "id": "limits" })
);
```

既定の $n=16$ でも $n=48$ でも、`dht` と `idht` は Plan の結果とちょうど一致する。
簡易 API は同じ零点、次数、範囲から、既定の零点の許容で同じ Plan を作って 1 回使うからである。
$n=16$ では準備の計算量が 7051 で、`preparation_work` を 7051 にすると準備が通り、7050 にすると `ConvergenceFailure` になる。
作業領域は複素数 $2n$ 個の 512 B で、`workspace_bytes` を 511 にすると `ResourceLimit` になる。
計算量の上限は使い切った時点で止まる反復の上限なので、メモリ使用量の上限とは失敗の分類が違う。
$n=48$ では計算量が 31502、作業領域が 1536 B、`plan_bytes()` が 2664 B から 19944 B に増える。

## 3 次元 Gauss 関数での確認

3 次元の Gauss 関数 $f(r) = e^{-r^2/2}$ を変換する。
長さの単位を 1 とする無次元量で計算する。
$\nu = 1/2$、$g(r) = r^{1/2} e^{-r^2/2}$ とすると、Hankel 変換の解析解は $F(\kappa) = \kappa^{1/2} e^{-\kappa^2/2}$ である（Weber の積分 DLMF 10.22.51 で $\nu = 1/2$ とした式）。
Fourier 変換に直すと $\hat f(k) = (2\pi)^{3/2} e^{-k^2/2}$ になる。

次のセルは標本数 $n$ と範囲 $R$ を変えて順方向の Plan で $F(\kappa_m)$ を求め、解析解と比べる。
逆方向の Plan で $g(r_k)$ に戻したときの差も求める。
零点の許容は `with_tolerance` で $10^{-13}$ に狭める。
1 つめの図は $F$ と解析解、2 つめの図は各周波数での差の絶対値を対数軸で描く。
2 つの図は波数の軸を連動させてある。
表には 2 つの裾 $g(R)$ と $F(\kappa_n)$、差の最大、往復の差の最大、零点の残差、準備の計算量を出す。

```rust
//| id: fft-hankel-gaussian
//| ref: fft-hankel-gaussian
//| title: Bessel 零点の格子で 3 次元 Gauss 関数の動径変換を求める
//| run: reactive
//| crates: [scioxide-core, scioxide-fft]
//| inputs:
//|   samples: {"type":"range","label":"標本数 n","description":"零点を n+1 個使う。周波数の上限 κₙ ≈ nπ/R が伸びる。","min":4,"max":64,"step":4,"value":24}
//|   extent: {"type":"range","label":"動径の範囲 R [-]","description":"g を r = R で打ち切る。小さいと g の裾、大きいと F の裾が残る。","min":3,"max":12,"step":1,"value":8}
//| cases:
//|   - {"id":"few-samples","label":"n = 8","description":"周波数の上限が 3.1 で、F の裾が格子の外に残る。","inputs":{"samples":8}}
//|   - {"id":"short-extent","label":"R = 4","description":"g を r = 4 で打ち切るので、標本を増やしても g の裾の誤差が残る。","inputs":{"extent":4}}
//|   - {"id":"long-extent","label":"R = 12","description":"同じ n で周波数の上限が 6.3 に下がり、F の裾が誤差を決める。","inputs":{"extent":12}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":24}
//|       - {"artifact":"summary","path":"/rows/0/1","approx":{"value":9.42477796076938,"rtol":1e-12}}
//|       - {"artifact":"summary","path":"/rows/0/4","range":{"max":1e-14}}
//|       - {"artifact":"summary","path":"/rows/0/5","range":{"max":1e-14}}
//|   - case: few-samples
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/1","approx":{"value":3.141592653589793,"rtol":1e-12}}
//|       - {"artifact":"summary","path":"/rows/0/4","approx":{"value":9.93e-4,"rtol":0.01}}
//|       - {"artifact":"summary","path":"/rows/0/5","range":{"max":1e-14}}
//|   - case: short-extent
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/2","approx":{"value":6.709252558050237e-4,"rtol":1e-10}}
//|       - {"artifact":"summary","path":"/rows/0/4","approx":{"value":7.25e-5,"rtol":0.01}}
//|   - case: long-extent
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/3","approx":{"value":6.7059525e-9,"rtol":1e-6}}
//|       - {"artifact":"summary","path":"/rows/0/4","approx":{"value":2.36e-10,"rtol":0.02}}
use scioxide_core::{Complex, ExecutionContext, Tolerance};
use scioxide_fft::{DiscreteHankelPlan, DiscreteHankelPlanSpec, FftDirection};

let n = samples.round() as usize;
let order = 0.5_f64; // 次数 ν = 1/2（3 次元の動径変換）
let pi = std::f64::consts::PI;
// J_{1/2}(x) = √(2/(πx)) sin x の正の零点は kπ（k = 1, …, n+1）
let zeros: Vec<f64> = (1..=n + 1).map(|k| k as f64 * pi).collect();
let tolerance = Tolerance::new(1e-13, 1e-13).map_err(|e| e.to_string())?;
let spec =
    |direction| DiscreteHankelPlanSpec::new(order, extent, direction).with_tolerance(tolerance);
let forward =
    DiscreteHankelPlan::new(&zeros, spec(FftDirection::Forward)).map_err(|e| e.to_string())?;
let inverse =
    DiscreteHankelPlan::new(&zeros, spec(FftDirection::Inverse)).map_err(|e| e.to_string())?;

// g(r) = r^{1/2} e^{−r²/2}。解析解 F(κ) = κ^{1/2} e^{−κ²/2} も同じ形（どちらも f64 の関数で評価）
let profile = |x: f64| x.sqrt() * (-0.5 * x * x).exp();
let input: Vec<Complex<f64>> = forward
    .nodes()
    .iter()
    .map(|&r| Complex::new(profile(r), 0.0))
    .collect();
let cx = ExecutionContext::sequential();
let mut output = vec![Complex::new(0.0, 0.0); n];
let mut workspace = forward.workspace(()).map_err(|e| e.to_string())?;
forward
    .execute_into(&input, &mut output, &mut workspace, cx)
    .map_err(|e| e.to_string())?;
// 逆方向の求積で動径の節点へ戻す（作業領域は Plan ごとに確保する）
let mut recovered = vec![Complex::new(0.0, 0.0); n];
let mut back_workspace = inverse.workspace(()).map_err(|e| e.to_string())?;
inverse
    .execute_into(&output, &mut recovered, &mut back_workspace, cx)
    .map_err(|e| e.to_string())?;

// 独立検算: 解析解との差を周波数の節点 κ_m = j_m / R ごとに求める
let (mut computed, mut exact, mut errors) = (Vec::new(), Vec::new(), Vec::new());
let mut largest = 0.0_f64;
for (value, &kappa) in output.iter().zip(forward.frequencies()) {
    let reference = profile(kappa);
    let error = (*value - Complex::new(reference, 0.0)).norm();
    largest = largest.max(error);
    computed.push([kappa, value.re]);
    exact.push([kappa, reference]);
    // 差がちょうど 0 の点は対数軸に描けないので除く
    if error > 0.0 {
        errors.push([kappa, error]);
    }
}
let roundtrip = input
    .iter()
    .zip(&recovered)
    .map(|(a, b)| (*a - *b).norm())
    .fold(0.0_f64, f64::max);
let kappa_top = forward.frequencies()[n - 1];
let d = forward.diagnostics();

emit_line_chart!(
    &vec![
        serde_json::json!({
            "name": "離散 Hankel 変換",
            "points": computed,
            "style": { "showSymbol": true, "lineType": "dotted" }
        }),
        serde_json::json!({
            "name": "解析解 κ^{1/2} e^{−κ²/2}",
            "points": exact,
            "style": { "lineType": "dashed" }
        }),
    ],
    options = &serde_json::json!({
        "xLabel": "波数 κ [-]",
        "yLabel": "F(κ) [-]",
        "xMin": 0.0,
        "xMax": 16.0,
        "yMin": 0.0,
        "yMax": 0.7,
        "link": { "group": "hankel-kappa" }
    })
);
emit_line_chart!(
    &vec![serde_json::json!({
        "name": "解析解との差の絶対値",
        "points": errors,
        "style": { "showSymbol": true }
    })],
    options = &serde_json::json!({
        "xLabel": "波数 κ [-]",
        "yLabel": "|F − 解析解| [-]",
        "xMin": 0.0,
        "xMax": 16.0,
        "yType": "log",
        "yMin": 1e-18,
        "yMax": 1.0,
        "link": { "group": "hankel-kappa" }
    })
);
let fixed2 = serde_json::json!({ "fractionDigits": 2 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "標本数 n", "type": "integer" },
    { "key": "1", "label": "周波数の上限 κₙ [-]", "type": "number", "format": fixed2 },
    { "key": "2", "label": "g の裾 g(R) [-]", "type": "number", "format": sci2 },
    { "key": "3", "label": "F の裾 F(κₙ) [-]", "type": "number", "format": sci2 },
    { "key": "4", "label": "解析解との差の最大 [-]", "type": "number", "format": sci2 },
    { "key": "5", "label": "往復の差の最大 [-]", "type": "number", "format": sci2 },
    { "key": "6", "label": "零点での |J_ν| の最大 [-]", "type": "number", "format": sci2 },
    { "key": "7", "label": "準備の計算量 [回]", "type": "integer" }
]);
let row = (
    n,
    kappa_top,
    profile(extent),
    profile(kappa_top),
    largest,
    roundtrip,
    d.maximum_zero_residual,
    d.preparation_work,
);
emit_table_with_columns!(
    columns,
    vec![row],
    metadata = serde_json::json!({ "id": "summary" })
);
```

既定の $n = 24$、$R = 8$ では、周波数の上限が $\kappa_{24} = 9.42$ で、2 つの裾は $g(8) = 3.6\times 10^{-14}$ と $F(9.42) = 1.6\times 10^{-19}$ である。
解析解との差の最大は $1.1\times 10^{-15}$ で、丸め誤差の程度になる。
$n = 8$ にすると上限が $\kappa_8 = 3.14$ に下がり、$F(3.14) = 1.3\times 10^{-2}$ の裾が格子の外に残って、差の最大は $9.9\times 10^{-4}$ になる。
$R = 4$ では上限は 18.8 に伸びるが、$g(4) = 6.7\times 10^{-4}$ の裾を打ち切るので、差の最大は $7.3\times 10^{-5}$ になる。
$R = 12$ では $g$ の裾は $10^{-31}$ まで下がるが、上限が 6.28 に下がり、$F(6.28) = 6.7\times 10^{-9}$ の裾で差の最大が $2.4\times 10^{-10}$ になる。
どの場合も差の最大は 2 つの裾の大きい方を超えず、$R$ を大きくすると $g$ の裾が、小さくすると $F$ の裾が減る。

往復の差の最大はどの場合も $10^{-16}$ から $10^{-15}$ の程度である。
$\nu = 1/2$ では丸めがなければ往復が恒等写像になるので、この値は丸め誤差だけを表す。
$n = 8$ で解析解との差が $10^{-3}$ のときも往復の差は $3.3\times 10^{-16}$ なので、往復の一致は解析解への近さを示さない。
零点での $\lvert J_\nu\rvert$ の最大は $9.4\times 10^{-16}$ で、f64 に丸めた零点 $k\pi$ は許容 $10^{-13}$ の検査を通る。
準備の計算量（関数の呼び出しと反復の総数）は $n = 24$ で 11951、$n = 64$ で 47870 である。
核の評価の回数 $n(n+1)/2$ は 300 から 2080 へ 6.9 倍になるが、計算量は 4.0 倍にとどまる。
計算量は Bessel 関数 1 回の評価に使った反復の数も数え、その数は引数によって変わるので、評価の回数に比例しない。

## まとめ

軸対称な関数の $d$ 次元 Fourier 変換は、次数 $\nu = d/2 - 1$ の Hankel 変換に係数を掛けたものになる。
`DiscreteHankelPlan` は、呼び出し側が渡した最初の $n+1$ 個の Bessel 零点で $[0, R]$ の積分を求積し、零点の精度と順番を準備で検査する。
準備と実行はどちらも $O(n^2)$ で、丸め誤差には上界があるが、求積の誤差は $g$ の $r = R$ での裾と $F$ の $\kappa \approx n\pi/R$ での裾で決まる。
$R$ は $g$ が十分小さくなる位置に、$n$ は $R\,\kappa_{\max}/\pi$ 以上に選び、解析解か範囲を広げた計算と比べて確かめる。
順方向と逆方向の往復の一致は、連続の変換への近さを示さない。
`dht` と `idht` は Plan と同じ結果を返す 1 回きりの関数で、`HankelLimits` の上限を超える準備は、メモリ使用量なら `ResourceLimit`、計算量なら `ConvergenceFailure` で止まる。
