`scioxide-fft` は、一次元と多次元の複素数・実数の離散 Fourier 変換（DFT）を高速 Fourier 変換（FFT）で計算する関数と Plan を提供する。
ほかに、Hermite 対称な標本の変換、I〜IV 型の離散コサイン変換（DCT）と離散サイン変換（DST）、チャープ Z 変換（CZT）、非一様 FFT（NUFFT）、Bessel 関数の零点の格子による離散 Hankel 変換、対数格子の FFTLog、周波数軸と変換長の補助関数、外部の FFT 実装を準備に渡す仕組みを持つ。
このガイドは目的ごとの API と型の関係を示し、公開されている 93 項目を用途別の表にまとめる。
表の項目名のリンクは、docs.rs の 0.1.0 の API リファレンスを指す。

## 目的別の API

| ビンの周波数を求め、ゼロパディングの長さを選ぶ | `rfftfreq`、`fftfreq`、`next_fast_len` | [周波数軸と変換長](oxref:fft-api-frequency) |
| 同じ長さの変換を確保なしで繰り返す | `FftPlanSpec`、`FftPlan`、`FftWorkspace` | [FFT Plan・キャッシュ・入出力](oxref:fft-api-plans)、[作業領域と軸単位の実行](oxref:fft-api-workspaces) |
| 多次元配列の選んだ軸を変換する | `fftn`、`rfftn`、`irfftn`、`FftNdPlan` | [多次元 FFT と形状](oxref:fft-api-multidimensional) |
| 境界条件に合う余弦・正弦の変換を使う | `dct`、`dst`、`dctn`、`RealTransformPlan` | [離散コサイン変換](oxref:fft-api-dct)、[離散サイン変換](oxref:fft-api-dst)、[DCT・DST の Plan](oxref:fft-api-dct-dst-plans)、[多次元 DCT・DST](oxref:fft-api-dct-dst-nd) |

| 不規則な位置の Fourier 和を求める | `NufftPlan`、`NufftPlanSpec`、`nufft_type1` | [非一様 Fourier 変換](oxref:fft-api-nufft) |

これらはそれぞれの章の API ガイドで引く。

## 型の関係

ワンショット関数（`fft`、`rfft`、`dct`、`czt`、`nufft_type1`、`dht`、`fht` など）は、呼び出しのたびに Plan を準備して一度だけ実行し、結果を新しい `Vec` で返す。
実数 FFT の結果はパックしたビンと元の長さを持つ `HermitianSpectrum`（多次元では `HermitianSpectrumNd`）で返る。
これらの関数は連続したスライスを受け取り、多次元の関数は行優先（最後の軸が最も速く変わる順）にパックしたスライスと形状を受け取る。

同じ大きさの変換を繰り返すとき、ストライド付きの配列を扱うとき、既定以外の設定を使うときは、仕様（`FftPlanSpec` などの `…Spec`）から Plan を準備する。
Plan は `FftPlan`、`FftNdPlan`、`RealTransformPlan`、`RealTransformNdPlan`、`CztPlan`、`NufftPlan`、`DiscreteHankelPlan`、`FftLogPlan` の 8 種類で、結果を呼び出し側が渡す出力に書く（`execute_into`、`execute_in_place`、`execute_axis_into`）。
方向（`FftDirection`）、正規化（`Normalization`）、配置（`FftLayout`）は仕様の値で、準備のときに Plan に固定されるので、逆変換には別の Plan を準備する。
実行方針と CPU の命令セットは仕様の `with_execution_policy` と `with_backend_strategy` で選ぶ。
FFT を使わない `DiscreteHankelPlanSpec` は命令セットの選択を持たない。

入力と出力の受け取り方は Plan によって違う。
`FftPlan` と `CztPlan`・`NufftPlan` は入力を `FftInput`、出力を `FftOutput` で受け取り、実数・複素数のスライス、配列、`Vec`、`VectorView` と `&HermitianSpectrum` はこれらに変換されるので、そのまま渡せる。
CZT と NUFFT はパックしたビンを受け付けず、出力は複素数に限る。
`FftNdPlan` は `NdView`・`NdViewMut` を `FftNdInput`・`FftNdOutput` に変換して受け取り、ストライド付きの配列もそのまま扱う。
`RealTransformPlan` は実数のスライス、`RealTransformNdPlan` は実数の `NdView`・`NdViewMut`、`DiscreteHankelPlan` と `FftLogPlan` は複素数のスライスを受け取る。

作業領域の渡し方は二通りある。
`FftPlan`、`FftNdPlan`、`RealTransformPlan`、`CztPlan` の `execute_into` は複素数の一時領域を `&mut [Complex<S>]` で受け取り、`FftWorkspace` はスライスに参照外しされるのでそのまま渡せる。
`NufftPlan`・`DiscreteHankelPlan`・`FftLogPlan` の `execute_into` と、CZT・NUFFT・Hankel・FFTLog の Plan の `execute_axis_into` は `&mut FftWorkspace` を受け取る。
この作業領域は作用素の評価回数を数える求解の状態も持つ。
`RealTransformNdPlan` は実数と複素数の二つの領域を持つ `RealTransformNdWorkspace` を使う。
必要な大きさは `workspace_requirements(request)` が返し、Plan の `workspace(request)` か作業領域の `try_reserve` で確保する。
要求 `request` は一回の変換では `()` で、CZT・NUFFT・Hankel・FFTLog の軸単位の実行では `AxisWorkspaceRequest::Axis { shape, axis }` である。

所有と再利用の規則は次のとおりである。
Plan は準備に使ったコンテキストを保持しない。
`FftPlanningContext` は実行コンテキストと外部の FFT 実装（`FftProvider`）を準備の間だけ借用する。
`FftPlan` の複製は準備した表を共有し、呼び出し側が所有する `FftPlanCache` は長さ、配置の種類（複素かパックしたか）、実行方針、命令セットが同じ Plan の表を共有する。
準備済みの Plan は十分な大きさの作業領域を渡せば実行中にメモリ領域を確保しない。

成分の順と単位は変換ごとに決まっている。
`fft` の結果は `fftfreq` と同じ順（非負の周波数のあとに負の周波数）に並び、`fftshift` が零周波数を中央へ移す。
`fftfreq` と `rfftfreq` の周波数の単位は標本間隔 $d$ の単位の逆数あたりのサイクル数である。
NUFFT のモードは各軸で $-\lfloor N/2\rfloor$ から昇順に並び、多次元では行優先に並ぶ。
NUFFT の型 3 の周波数は座標の単位あたりのラジアンで表した角周波数である。

## 実数 FFT の往復と対称性の検査

長さ 4 の余弦 $x = (1, 0, -1, 0)$ の DFT は $X = (0, 2, 0, 2)$ で、`rfft` は非負の周波数の 3 個のビン $(0, 2, 0)$ と論理長 4 を返す。
論理長は詰める前の列の長さで、長さ 4 と 5 はどちらも 3 個のビンに詰まるので、逆変換はこの値で出力の長さを決める。

次のセルは `rfft` と `irfft` で往復し、ビンを解析値と、往復の結果を元の列と比べる。
続けて、DC のビンに入力で選んだ虚部を加えたスペクトルを `HermitianSpectrum::from_vec` で作り、`irfft` に渡す。
Hermite 対称性 $X_{n-k} = \overline{X_k}$ で $k = 0$ とすると $X_0 = \overline{X_0}$ なので、DC のビンは実数でなければならず、虚部は丸め誤差の大きさまでしか許されない。
許容は $\tau = \max(8\varepsilon M, \eta)$ で、$M$ はスペクトルの実部・虚部の絶対値の最大、$\varepsilon = 2^{-52}$ は機械イプシロン、$\eta$ は最小の正の非正規化数である。
セルはこの $\tau$ を手で計算し、`irfft` の判定と並べる。
許容を超えると `irfft` はエラーを返し、セルは分類を `e.kind()` で読む。
許容内なら `irfft` は作業領域の写しの虚部を 0 にしてから変換するので、結果は摂動のない往復と一致するはずである。

```rust
//| id: fft-api-real-roundtrip
//| ref: fft-api-real-roundtrip
//| title: 実数 FFT の往復と DC のビンの対称性の検査
//| run: reactive
//| crates: [scioxide-core, scioxide-fft]
//| inputs:
//|   dc_imag: {"type":"select","label":"DC のビンに加える虚部 [-]","description":"許容 τ = 8εM ≈ 3.55e-15 を超えると irfft は InvalidInput を返す。","options":["1e-3","1e-14","1e-16"],"value":"1e-3"}
//| cases:
//|   - {"id":"just-above","label":"虚部 1e-14","description":"許容 τ の約 3 倍で、わずかな超過でも拒まれる。","inputs":{"dc_imag":"1e-14"}}
//|   - {"id":"within","label":"虚部 1e-16","description":"許容 τ より小さいので虚部を 0 にしてから変換し、結果は摂動のない往復と一致する。","inputs":{"dc_imag":"1e-16"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"bins","path":"/rows/1/1","approx":{"value":2,"atol":1e-15}}
//|       - {"artifact":"bins","path":"/rows/1/4","range":{"max":1e-15}}
//|       - {"artifact":"summary","path":"/rows/0/0","approx":{"value":4,"atol":0.5}}
//|       - {"artifact":"summary","path":"/rows/0/1","approx":{"value":3,"atol":0.5}}
//|       - {"artifact":"summary","path":"/rows/0/3","range":{"max":1e-15}}
//|       - {"artifact":"perturbed","path":"/rows/0/1","approx":{"value":3.552713678800501e-15,"rtol":1e-12}}
//|       - {"artifact":"perturbed","path":"/rows/0/2","equals":"InvalidInput"}
//|       - {"artifact":"perturbed","path":"/rows/0/3","equals":null}
//|   - case: just-above
//|     expect:
//|       - {"artifact":"perturbed","path":"/rows/0/0","approx":{"value":1e-14,"rtol":1e-12}}
//|       - {"artifact":"perturbed","path":"/rows/0/2","equals":"InvalidInput"}
//|   - case: within
//|     expect:
//|       - {"artifact":"perturbed","path":"/rows/0/2","equals":"受理"}
//|       - {"artifact":"perturbed","path":"/rows/0/3","range":{"max":0}}
use scioxide_core::Complex;
use scioxide_fft::{HermitianSpectrum, Normalization, irfft, rfft};

let dc_imag: f64 = dc_imag
    .parse()
    .map_err(|e: std::num::ParseFloatError| e.to_string())?;
// 周期 4 の余弦 x = (1, 0, −1, 0)。Inverse 正規化では順変換に係数を掛けない。
let input = [1.0_f64, 0.0, -1.0, 0.0];
let spectrum = rfft(&input, Normalization::Inverse).map_err(|e| e.to_string())?;
// 論理長 4 のビンから実数列へ戻す。逆変換が 1/4 を掛ける。
let output = irfft(&spectrum, Normalization::Inverse).map_err(|e| e.to_string())?;
// 独立な検算: 解析的な DFT X = (0, 2, 0, 2) のうち非負の周波数の 3 個。
let expected = [0.0, 2.0, 0.0];
let bins: Vec<(usize, f64, f64, f64, f64)> = spectrum
    .bins()
    .iter()
    .zip(expected)
    .enumerate()
    .map(|(k, (z, x))| (k, z.re, z.im, x, (*z - Complex::new(x, 0.0)).norm()))
    .collect();
let bin_error = bins.iter().map(|row| row.4).fold(0.0_f64, f64::max);
// 往復の差の最大。f64 の abs と max は参照値の計算に限って使う。
let max_difference = |a: &[f64], b: &[f64]| {
    a.iter()
        .zip(b)
        .map(|(x, y)| (x - y).abs())
        .fold(0.0_f64, f64::max)
};
let roundtrip = max_difference(&input, &output);

// DC のビンに虚部を加える。from_vec はビンの数だけを検査し、対称性は irfft が検査する。
let mut perturbed = spectrum.clone().into_vec();
perturbed[0].im += dc_imag;
// 独立な検算: 許容 τ = max(8εM, η) を手で計算する（M は実部・虚部の絶対値の最大）。
let mass = perturbed
    .iter()
    .map(|z| z.re.abs().max(z.im.abs()))
    .fold(0.0_f64, f64::max);
let tau = (8.0 * f64::EPSILON * mass).max(f64::from_bits(1));
let perturbed = HermitianSpectrum::from_vec(4, perturbed).map_err(|e| e.to_string())?;
// 拒まれたら分類を、受理されたら摂動のない往復との差を出す。
let (verdict, deviation) = match irfft(&perturbed, Normalization::Inverse) {
    Ok(values) => ("受理".to_string(), Some(max_difference(&values, &output))),
    Err(e) => (format!("{:?}", e.kind()), None),
};

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let fixed2 = serde_json::json!({ "fractionDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "ビン k", "type": "integer" },
    { "key": "1", "label": "Re X_k [-]", "type": "number", "format": fixed2 },
    { "key": "2", "label": "Im X_k [-]", "type": "number", "format": fixed2 },
    { "key": "3", "label": "解析値 [-]", "type": "number", "format": fixed2 },
    { "key": "4", "label": "解析値との差 [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    bins,
    metadata = serde_json::json!({ "id": "bins" })
);
let columns = serde_json::json!([
    { "key": "0", "label": "論理長 n", "type": "integer" },
    { "key": "1", "label": "ビンの数", "type": "integer" },
    { "key": "2", "label": "ビンと解析値の差の最大 [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "往復の差の最大 [-]", "type": "number", "format": sci3 }
]);
let summary = vec![(spectrum.logical_len(), spectrum.len(), bin_error, roundtrip)];
emit_table_with_columns!(
    columns,
    summary,
    metadata = serde_json::json!({ "id": "summary" })
);
let columns = serde_json::json!([
    { "key": "0", "label": "DC の虚部 [-]", "type": "number", "format": sci3 },
    { "key": "1", "label": "許容 τ [-]", "type": "number", "format": sci3 },
    { "key": "2", "label": "irfft の結果" },
    { "key": "3", "label": "摂動のない往復との差 [-]", "type": "number", "format": sci3, "nullText": "拒否" }
]);
let rows = vec![(dc_imag, tau, verdict, deviation)];
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "perturbed" })
);
```

最初の表は、`rfft` のビンが解析値 $(0, 2, 0)$ と一致することを示す。
2 つ目の表では論理長が 4、ビンの数が $\lfloor 4/2\rfloor + 1 = 3$ で、往復の差も 0 である（この入力では丸め誤差が生じない）。
3 つ目の表の許容は $M = 2$ に対する $\tau = 16\varepsilon \approx 3.55\times 10^{-15}$ である。
既定の虚部 $10^{-3}$ と $10^{-14}$ は $\tau$ を超えるので、`irfft` は `InvalidInput` を返す。
$10^{-16}$ は許容内なので受理され、摂動のない往復との差は 0 になる。
許容を超えた虚部は丸め誤差では説明できないので、`scioxide-fft` はこれを 0 に直さず、入力の誤りとして返す。

## 結果・エラー・診断の読み方

失敗は `scioxide_core::SciOxideError` で返る。
分類は `kind()`、引数や詳細は `view()` で読む。
この章で現れる主な分類は次のとおりである。

| 分類 | 主な原因 |
|---|---|
| `InvalidInput` | 一次元の変換長や選んだ軸の長さが 0、長さ 1 の DCT-I、許容を超える Hermite 対称性の破れ、重複した軸、実数・Hermite の配置で選んだ軸の列が空、Plan の配置と合わない `FftInput`・`FftOutput` の変種、仕様の値の範囲外（NUFFT の精度、Hankel の次数、正でない刻みなど）、コンテキストが提供しない命令セットの要求、外部の実装が断った長さ（`FftProviderPolicy::Required`） |
| `OutOfBounds` | 配列の階数以上の軸 |
| `DimensionMismatch` | 入力・出力・ビューの形や長さ、論理長、作業領域の不足、Hankel の零点の数と標本数の不一致 |
| `NonFinite` | 入力や仕様の NaN・無限大（起源 `Input`）、外部の実装が返した NaN・無限大（起源 `Callback`） |
| `NumericalInstability` | 有限の入力からの出力の桁あふれ（`Overflow`）、パックした実数変換の内部の丸めの検査の失敗（`Breakdown`）、準備で計算した 0 でない係数が 0 に丸められた（`Underflow`）、NUFFT の丸めの推定より厳しい精度の要求 |
| `Singular` | FFTLog の実行で、方向に応じて乗数の極（順方向）か零（逆方向）に当たった |
| `ConvergenceFailure` | Hankel・FFTLog の準備の計算量の上限や、実行の反復回数の上限に達した |
| `ScalarConversion` | `fftfreq`・`rfftfreq` で長さや添字がスカラー型で正確に表せない、または隣り合う周波数を区別できない |
| `ResourceLimit`、`AllocationFailure`、`SizeOverflow` | 設定したバイト数などの上限の超過、確保の失敗、大きさの計算の桁あふれ |
| `ExecutionStopped` | 実行コンテキストによる取り消しや期限 |

長さ 0 が許される場面と拒まれる場面は区別されている。
一次元の変換長と、多次元で選んだ軸の長さが 0 なら `InvalidInput` である。
一方、選んでいない軸の長さ 0（空のバッチ）、`fftshift_nd` の長さ 0 の軸、空の入力に対する `fftshift`、点の数 0 の NUFFT（空の和は 0）は受け付ける。

Plan は検査と計算がすべて成功してから出力に書く。
失敗したときは出力を変えず、成功したときもストライドの隙間など、ビューが指さない要素は変えない。
軸単位の実行は、すべての列が成功したときだけまとめて書く。
ワンショット関数は Plan の準備と結果の確保を呼び出しの中で行う。

精度の情報は変換ごとに性質が違う。
内蔵の実装による順方向の複素 FFT とパック形式の実数 FFT の 2 ノルムの相対誤差 $2\varepsilon\max(1, \log_2 n)$ は、高精度で計算した参照 DFT と比べる試験で確かめた精度で、証明した上界ではない。
これはノルムで測った値なので、最大のビンよりずっと小さいビンの相対誤差は大きくなりうる。
外部の実装にはこの精度は当てはまらない。
`CztPlan`（Bluestein のアルゴリズムを内蔵の FFT で実行する場合）と `DiscreteHankelPlan` は出力の成分ごとの丸めの上界を定めている。
NUFFT の `NufftDiagnostics` の誤差は推定値で、証明付きの誤差の包含区間ではない。
FFTLog の `FftLogDiagnostics` は乗数の大きさの広がりと準備の計算量を返し、誤差の評価は含まない。
往復の一致は離散の写像の逆を確かめるだけで、連続な積分の近似精度は別に調べる。

`FftPlan::diagnostics()` は選んだアルゴリズムと段数を、`CztPlan::algorithm()` は CZT のアルゴリズムを返す。
`plan_bytes()` は Plan が保持するバイト数、`resolved_backends()` は実際に使う子の FFT の実装を返す。
直接和を選んだ CZT や離散 Hankel 変換のように子の FFT を持たない Plan では、このイテレータは空である。
NUFFT・離散 Hankel・FFTLog の `execute_into` と、少なくとも一つの列を持つそれらの `execute_axis_into` は、`SolveScope` で作用素の評価を 1 回と数える。
離散 Hankel と FFTLog はさらに列ごとに $n$ 回の反復を数え、仕様の `with_iteration_budget` がその上限を決める。
CZT の `execute_axis_into` は評価も反復も数えない。

表の「解説節」はその項目を説明する節、「実行例」はその項目を実際に使うセルを指す。
「-」は該当するセルがないことを示す。
共通の規約は[アルゴリズムの API](../algorithms/)にある。

## まとめ

変換の種類と正規化を選び、一度だけならワンショット関数を、繰り返すなら仕様から Plan を準備して作業領域と一緒に使う。
実数 FFT のパックしたビンは論理長（多次元では形と軸）とともに `HermitianSpectrum`・`HermitianSpectrumNd` で持ち運び、逆変換は DC と Nyquist のビンの対称性を許容 $\max(8\varepsilon M, \eta)$ で検査する。
失敗は `kind()` で分類する。
Plan は失敗したとき出力を変えないので、失敗のあとも出力には前の値が残る。
FFT の誤差は試験で確かめた精度、CZT（Bluestein のアルゴリズム）と離散 Hankel 変換は成分ごとの丸めの上界、NUFFT の診断は推定値であり、これらを区別して結果の信頼性を判断する。
