JPEG などの画像圧縮の中心にある離散コサイン変換（DCT）は、隣り合う画素の値が近いブロックを少数の低周波の係数で表しやすくする。
周期境界を仮定する DFT は、ブロックの左端と右端の値の差を段差として扱い、高い周波数の成分を生む。
偶対称の延長に対応する DCT-II は端で値が連続につながるので、そのような段差が生じない。

この例では $8\times8$ 画素のブロックを `dctn` で変換し、低い周波数から $K$ 個の係数だけを残して `idctn` で戻す。
Parseval の等式から、復元の二乗誤差の総和が捨てた係数のエネルギーに等しいことを確かめ、係数そのものを定義の和と比べる。

## 偶対称の延長とエネルギーの集中

長さ $N$ の直交正規化した一次元の DCT-II は

$$
C_k = \alpha_k\sum_{n=0}^{N-1} x_n\cos\left[\frac{\pi}{N}\left(n + \frac{1}{2}\right)k\right], \qquad
\alpha_0 = \sqrt{\frac{1}{N}},\quad \alpha_k = \sqrt{\frac{2}{N}}\ (k \ge 1)
$$

である。
`scioxide-fft` では `Normalization::Orthonormal` を指定した DCT-II がこれに一致する（[4 つの型の定義と尺度](oxref:fft-dct-types)）。
DCT-II の基底は列を半画素ずらした位置で鏡映して長さ $2N$ に延長した列の Fourier 級数にあたる。
鏡映した延長は端で値が連続なので、周期延長で値の段差が生じる場合の DFT と比べて、高い周波数の係数が小さくなりやすい。
ただし係数の減り方は値や導関数の滑らかさに依存し、任意の画像で一律には決まらない。

DC 係数 $C_0=\sqrt{1/N}\sum_nx_n=\sqrt N\,\bar x$ はブロックの平均の明るさに比例する。
$k\ge1$ の係数は $k$ とともに零交差の増える明暗の縞を表す。
滑らかな明るさのブロックでは、定数とゆっくり変わる基底が大半のエネルギーを受け持ち、一定のブロックでは DC 係数だけが零でない。
段差や細かい模様を含むブロックでは、高い周波数の係数も必要になる。

## 二次元変換の分離可能性

$N\times N$ のブロック $X$ の二次元 DCT-II は一次元の基底の積で

$$
C_{vu} = \alpha_u\alpha_v\sum_{y=0}^{N-1}\sum_{x=0}^{N-1} X_{yx}\cos\left[\frac{\pi}{N}\left(x + \frac{1}{2}\right)u\right]\cos\left[\frac{\pi}{N}\left(y + \frac{1}{2}\right)v\right]
$$

と書ける（$u$ が横、$v$ が縦の周波数）。
一次元の直交 DCT-II の行列を $A$ とすると $C=AXA^\mathsf{T}$ であり、各行の一次元変換のあとに各列の一次元変換を行えばよい。
`dctn` は行優先のスライスと形状を受け取り、選んだ軸ごとに指定した型の変換を行って、同じ形状の新しい `Vec` を返す。
行優先の $8\times8$ 配列では軸 0 が縦、軸 1 が横で、形状 `&[8, 8]`、軸 `&[0, 1]`、型 `&[DctType::II, DctType::II]` を渡す。
`idctn` には逆にしたい順変換の型（ここでは II）を渡し、内部では DCT-III が実行される。
同じ形状のブロックを多数変換するなら、`RealTransformNdPlan` を一度作って作業領域を再利用する。

## Parseval の等式と打切りの誤差

$A$ は直交行列なので、$C=AXA^\mathsf{T}$ は Frobenius ノルム（成分の二乗和の平方根）を保つ。

$$
\lVert X\rVert_F^2 = \sum_{y,x} X_{yx}^2 = \sum_{v,u} C_{vu}^2 = \lVert C\rVert_F^2
$$

周波数の添字の集合 $S$ の係数だけを残して他を 0 にした $\hat C$ から $\hat X=A^\mathsf{T}\hat CA$ を作ると、二乗誤差の総和は捨てた係数のエネルギーに等しい。

$$
\lVert X - \hat X\rVert_F^2 = \lVert C - \hat C\rVert_F^2 = \sum_{(u, v)\notin S} C_{vu}^2
$$

画素の平均二乗誤差は $\mathrm{MSE}=\frac{1}{N^2}\sum_{(u,v)\notin S}C_{vu}^2$ で、画素値の範囲を $[0,1]$ としたピーク信号対雑音比は $\mathrm{PSNR}=-10\log_{10}\mathrm{MSE}$ [dB] である。
残す係数の数 $K$ を決めたとき、MSE を最小にするのは絶対値の大きい $K$ 個を残すことである。
圧縮では残した係数の位置を符号化する手間を省くため、$u+v$ の小さい順に並べる走査（JPEG のジグザグ走査に近い低周波優先の順）を使う。

## 打切りの実験

次のセルは横の線形の勾配、縦の緩い余弦、$x+y\ge8$ の斜めの段差（高さ $0.25c$）を重ねた $8\times8$ の合成画像を変換し、$(u+v,v,u)$ の順に $K$ 個の係数を残して戻す。
元の画像と復元した画像を同じ色の範囲で描き、符号付き誤差のヒートマップと、$K$ に対する捨てた係数のエネルギーの比を対数の縦軸で描く。
1 つ目の表は MSE、PSNR、画素の最大誤差を示す。
2 つ目の表は捨てた係数のエネルギー（Parseval の等式による予測）と実際の二乗誤差の総和、画像と係数の二乗和の相対差、係数を定義の二重和で計算した値との最大差を示す。
定義の和は `f64` の余弦を使う独立な参照計算である。
$K=64$ では捨てた係数がないので、比の曲線は $K\le63$ だけを描く。

```rust
//| id: fft-dct-image-compression
//| ref: fft-dct-image-compression
//| title: DCT 係数の打切りと画像の復元
//| run: reactive
//| crates: [scioxide-fft]
//| inputs:
//|   retained_coefficients: {"type":"range","label":"保持する DCT 係数の数 K [個]","description":"低周波側（u + v の小さい順）から残す係数の数（最大 64 個）。","min":1,"max":64,"step":1,"value":12}
//|   edge_contrast: {"type":"range","label":"斜めの段差の明暗差 c [-]","description":"段差の高さ 0.25c を変える。","min":0,"max":1,"step":0.05,"value":0.55}
//| cases:
//|   - {"id":"dc-only","label":"K = 1","description":"DC 係数だけを残し、ブロックが平均の明るさ一色になる。","inputs":{"retained_coefficients":1}}
//|   - {"id":"all-coefficients","label":"K = 64","description":"すべての係数を残し、誤差が丸めの水準になる。","inputs":{"retained_coefficients":64}}
//|   - {"id":"no-edge","label":"c = 0","description":"段差のない滑らかなブロック。同じ K で誤差が 1 桁以上小さい。","inputs":{"edge_contrast":0}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":12}
//|       - {"artifact":"summary","path":"/rows/0/1","approx":{"value":0.9963,"atol":5e-4}}
//|       - {"artifact":"summary","path":"/rows/0/3","approx":{"value":30.6,"atol":0.1}}
//|       - {"artifact":"checks","path":"/rows/0/0","approx":{"value":0.05555,"rtol":1e-3}}
//|       - {"artifact":"checks","path":"/rows/0/2","range":{"max":1e-14}}
//|       - {"artifact":"checks","path":"/rows/0/3","range":{"max":1e-13}}
//|   - case: dc-only
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/3","approx":{"value":14.7,"atol":0.1}}
//|   - case: all-coefficients
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/4","range":{"max":1e-14}}
//|       - {"artifact":"checks","path":"/rows/0/0","equals":0}
//|   - case: no-edge
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/3","approx":{"value":47.0,"atol":0.1}}
use scioxide_fft::{DctType, Normalization, dctn, idctn};

let side = 8_usize;
let keep = retained_coefficients as usize;
let pi = std::f64::consts::PI;
// 8×8 の合成画像（行優先 [y, x]）: 横の勾配 + 縦の緩い余弦 + x + y ≥ 8 の斜めの段差。
let mut image = Vec::with_capacity(side * side);
for y in 0..side {
    for x in 0..side {
        let smooth = 0.18 + 0.42 * x as f64 / 7.0 + 0.10 * (pi * y as f64 / 7.0).cos();
        let edge = if x + y >= side {
            0.25 * edge_contrast
        } else {
            0.0
        };
        image.push(smooth + edge);
    }
}
let (shape, axes, types) = ([side, side], [0, 1], [DctType::II, DctType::II]);
// 二次元の直交 DCT-II（軸 0 = 縦 v、軸 1 = 横 u）。
let coefficients = dctn(&image, &shape, &axes, &types, Normalization::Orthonormal)
    .map_err(|e| e.to_string())?;
// 独立検算: 定義の二重和 C_vu = α_u α_v Σ X_yx cos(π(x+½)u/N) cos(π(y+½)v/N)。
let alpha = |k: usize| if k == 0 { (1.0 / 8.0_f64).sqrt() } else { 0.5 };
let basis = |k: usize, n: usize| (pi * (n as f64 + 0.5) * k as f64 / side as f64).cos();
let mut direct_difference = 0.0_f64;
for v in 0..side {
    for u in 0..side {
        let sum: f64 = (0..side * side)
            .map(|i| image[i] * basis(u, i % side) * basis(v, i / side))
            .sum();
        let difference = (alpha(u) * alpha(v) * sum - coefficients[v * side + u]).abs();
        direct_difference = direct_difference.max(difference);
    }
}
// (u + v, v, u) の順に並べ、低い周波数から K 個を残す。
let mut order: Vec<(usize, usize)> = (0..side)
    .flat_map(|v| (0..side).map(move |u| (u, v)))
    .collect();
order.sort_by_key(|&(u, v)| (u + v, v, u));
let energies: Vec<f64> = order
    .iter()
    .map(|&(u, v)| coefficients[v * side + u].powi(2))
    .collect();
let total: f64 = energies.iter().sum();
let mut truncated = vec![0.0; side * side];
for &(u, v) in order.iter().take(keep) {
    truncated[v * side + u] = coefficients[v * side + u];
}
// 逆変換には順変換の型 II を渡す（実行されるのは DCT-III）。
let reconstructed = idctn(
    &truncated,
    &shape,
    &axes,
    &types,
    Normalization::Orthonormal,
)
.map_err(|e| e.to_string())?;
let differences: Vec<f64> = reconstructed
    .iter()
    .zip(&image)
    .map(|(r, o)| r - o)
    .collect();
let squared_error: f64 = differences.iter().map(|d| d * d).sum();
let maximum_error = differences.iter().fold(0.0_f64, |m, d| m.max(d.abs()));
let image_energy: f64 = image.iter().map(|x| x * x).sum();
let mse = squared_error / (side * side) as f64;
// 捨てた係数のエネルギー（後ろからの和で、1 − 累積比の打ち消しを避ける）。
let tails: Vec<f64> = (0..=side * side)
    .map(|k| energies[k..].iter().sum())
    .collect();
let discarded = tails[keep];
let psnr = (mse > 0.0).then(|| -10.0 * mse.log10());
let fraction: Vec<[f64; 2]> = (1..side * side)
    .filter(|&k| tails[k] > 0.0)
    .map(|k| [k as f64, tails[k] / total])
    .collect();

let map = |values: &[f64]| {
    (0..side * side)
        .map(|i| [(i % side) as f64, (i / side) as f64, values[i]])
        .collect::<Vec<_>>()
};
// 元の画像と復元した画像は同じ色の範囲 [0, 1] で描き、色の差を明るさの差として比べる。
let picture = |values: &[f64], title: &str| {
    serde_json::json!({
        "kind": "heatmap",
        "data": map(values),
        "xLabel": "列 x [画素]",
        "yLabel": "行 y [画素]",
        "colorMin": 0.0,
        "colorMax": 1.0,
        "tooltip": true,
        "style": { "animation": false, "showGrid": false },
        "title": title
    })
};
emit_chart!(picture(&image, "元の画像"));
emit_chart!(picture(&reconstructed, "復元した画像"));
// 誤差は符号付きなので、0 を中間色とする発散型の色で描く。
emit_chart!(serde_json::json!({
    "kind": "heatmap",
    "data": map(&differences),
    "xLabel": "列 x [画素]",
    "yLabel": "行 y [画素]",
    "title": "符号付きの誤差（復元 − 元）",
    "colorScale": "diverging",
    "center": 0.0,
    "colorMin": -0.5,
    "colorMax": 0.5,
    "tooltip": true,
    "style": { "animation": false, "showGrid": false }
}));
emit_line_chart!(
    &vec![serde_json::json!({
        "name": "捨てた係数のエネルギーの比",
        "points": fraction,
        "style": { "symbol": "circle", "showSymbol": true }
    })],
    options = &serde_json::json!({
        "xLabel": "残した係数の数 K [個]",
        "yLabel": "捨てた係数のエネルギー / 全エネルギー [-]",
        "yType": "log",
        "xMin": 1.0,
        "xMax": 64.0,
        "annotations": [{ "kind": "line", "axis": "x", "value": keep as f64, "label": "選んだ K" }]
    })
);
let fixed4 = serde_json::json!({ "significantDigits": 4 });
let fixed3 = serde_json::json!({ "significantDigits": 3 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let summary_columns = serde_json::json!([
    { "key": "0", "label": "K [個]", "type": "integer" },
    { "key": "1", "label": "残したエネルギーの比 [-]", "type": "number", "format": fixed4 },
    { "key": "2", "label": "MSE [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "PSNR [dB]", "type": "number", "format": fixed3, "nullText": "∞（誤差 0）" },
    { "key": "4", "label": "画素の最大誤差 [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    summary_columns,
    vec![(keep, 1.0 - discarded / total, mse, psnr, maximum_error)],
    metadata = serde_json::json!({ "id": "summary" })
);
let check_columns = serde_json::json!([
    { "key": "0", "label": "捨てた係数のエネルギー [-]", "type": "number", "format": sci3 },
    { "key": "1", "label": "二乗誤差の総和 [-]", "type": "number", "format": sci3 },
    { "key": "2", "label": "Parseval の相対差 [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "定義の和との最大差 [-]", "type": "number", "format": sci3 }
]);
let parseval = ((image_energy - total) / total).abs();
emit_table_with_columns!(
    check_columns,
    vec![(discarded, squared_error, parseval, direct_difference)],
    metadata = serde_json::json!({ "id": "checks" })
);
```

既定の $K=12$、$c=0.55$ では、残した係数が全エネルギーの 99.63% を持ち、MSE は $8.68\times10^{-4}$（PSNR 30.6 dB）、画素の最大誤差は 0.070 である。
捨てた係数のエネルギーと二乗誤差の総和はどちらも $5.555\times10^{-2}$ で、表示した桁で一致する。
画像と係数の二乗和の相対差は $8\times10^{-16}$、定義の和との差は $6\times10^{-15}$ で、どちらも丸めの水準である。

段差をなくす（$c=0$）と、同じ $K=12$ で残したエネルギーの比は 0.99989、PSNR は 47.0 dB に上がる。
$c=1$ では PSNR が 25.5 dB に下がる。
$K=1$ では DC だけが残り、残したエネルギーの比は 0.856、PSNR は 14.7 dB である。
$K=64$ ではすべての係数を残すので、画素の最大誤差は $3.3\times10^{-16}$ と丸め誤差だけになり、PSNR の 318 dB は丸め誤差の大きさを表すにすぎない。

捨てた係数のエネルギーの比は $K$ とともに下がるが、段差があると下がり方が遅い。
段差を表すには $u+v$ の大きい係数も要るので、低周波優先の走査では $K$ を大きくするまでそれらが捨てられる。

## 誤差の形とブロック歪み

$K=1$ では、ブロックは平均の明るさ一色になる。
$K$ を 3〜6 程度に増やすと大きな勾配は戻るが、斜めの段差の近くには Gibbs 現象に似たさざ波が残る。
段差の明暗差を上げると、段差を表すのに高い周波数の係数が必要になり、同じ $K$ での MSE と画素の最大誤差が増える。

画像全体を $8\times8$ のブロックに分けて独立に打ち切ると、隣り合うブロックで平均や勾配が食い違い、ブロックの境界に段差が見える。
これをブロック歪みと呼ぶ。
画像や動画の符号化では、ブロックの境界を平滑化する処理や、隣のブロックと重なる基底を使う変換で、この歪みを抑える。

## 打切りと量子化

この例の打切りは残す係数を倍精度のまま保持して他を 0 にする理想化である。
実際の符号化では、周波数ごとの刻み幅 $Q_{vu}$ で係数を量子化する。

$$
\tilde{C}_{vu} = \mathrm{round}\left(\frac{C_{vu}}{Q_{vu}}\right), \qquad \hat{C}_{vu} = \tilde{C}_{vu}\,Q_{vu}
$$

人の視覚は高い空間周波数の明るさの変化に対する感度が低いので、JPEG の標準の量子化表は低い周波数に小さな $Q_{vu}$、高い周波数に大きな $Q_{vu}$ を割り当てる。
その結果、多くの高い周波数の係数が 0 になり、後段の Huffman 符号化や算術符号化で短く表せる。
量子化の誤差についても、直交性から画素の二乗誤差の総和は係数の誤差の二乗和に等しく、MSE は係数の側で計算できる。

## まとめ

二次元の DCT-II は行と列の一次元変換の積であり、`dctn` に形状、軸、型を渡せば一度の呼び出しで計算できる。
逆変換の `idctn` には順変換の型を渡す。
直交正規化した DCT は Frobenius ノルムを保つので、係数を捨てたときの二乗誤差の総和は捨てた係数のエネルギーに等しく、この例では丸めの水準で一致した。
滑らかなブロックではエネルギーが少数の低周波の係数に集まり、段差のあるブロックでは高い周波数の係数が必要になる。
