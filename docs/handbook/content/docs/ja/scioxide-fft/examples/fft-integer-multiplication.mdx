位取り記数法で書いた整数の乗算は、桁を係数とする多項式の乗算に帰着する。
係数列の畳み込みを FFT で計算すれば、長さ $L$ の変換で $O(L\log L)$ の演算で積の係数が求まる。
ただし浮動小数点の FFT の結果には丸め誤差があり、整数へ戻すには誤差が十分小さい必要がある。

このページでは `rfft` と `irfft` で係数の線形畳み込みを計算し、最近接整数への丸めと桁上がりで積の桁を作る。
検算には浮動小数点を使わない整数の畳み込みを使い、真の係数誤差と誤った桁の数を数える。
基数 $B$ と桁数 $d$ を変え、誤差が $1/2$ に近づいて整数へ戻せなくなる範囲を調べる。
任意の大きさの整数を扱うライブラリではなく、FFT による整数復元の条件を調べる例題である。

## 基数と多項式の積

基数 $B\ge2$、桁数 $d$ の二つの整数を、下位の桁から並べて

$$
u=\sum_{j=0}^{d-1}u_j B^j,\qquad
v=\sum_{j=0}^{d-1}v_j B^j,\qquad 0\le u_j,v_j<B
$$

と書く。
多項式 $U(z)=\sum_j u_jz^j$ と $V(z)=\sum_jv_jz^j$ の積の係数は

$$
w_\ell=\sum_j u_jv_{\ell-j},\qquad 0\le\ell<2d-1
$$

で、範囲外の桁を 0 とみなした線形畳み込みである。
長さ $L$ の DFT の積は巡回畳み込みを与えるので、$L\ge2d-1$ まで零を詰めれば折り返しが起きず、巡回畳み込みが線形畳み込みに一致する。
`next_fast_len` はこの下限以上で素因数が 2、3、5、7 だけの長さを返す。
零を詰める処理は呼び出し側で行う。

## 実数 FFT による畳み込み

係数列は実数なので、`rfft` で非負の周波数のビン $X_0,\ldots,X_{\lfloor L/2\rfloor}$ だけを求める。
返る `HermitianSpectrum` はビンの列と論理長 $L$ を所有する。
二つのスペクトルのビンを成分ごとに掛けた列を `HermitianSpectrum::from_vec(L, bins)` で包み直し、`irfft` に渡すと長さ $L$ の実数列が返る。
正変換を `Normalization::Unscaled`、逆変換を `Normalization::Inverse` にすると、逆変換の $1/L$ だけが掛かり、結果が畳み込みの係数そのものになる。
実数列の積は Hermite 対称性を保つので、パックしたビンの積をそのまま逆変換してよい。

## 整数復元の条件

FFT で得た係数を $\widetilde w_\ell$ とする。
真の整数係数に対して

$$
|\widetilde w_\ell-w_\ell|<\frac12
$$

なら、最近接整数への丸めで $w_\ell$ が復元できる。
これに対して、最近接整数との距離 $|\widetilde w_\ell-\operatorname{round}(\widetilde w_\ell)|$ は、誤差が $1/2$ 未満のときだけ真の誤差に一致する。
誤差が $1/2$ を超えると計算値は別の整数の近くに来るので、距離が小さくても正しいとは言えない。

係数の大きさの上限は $d(B-1)^2$ である。
`f64` は絶対値が $2^{53}\approx9.0\times10^{15}$ 以下の整数をすべて正確に表せるが、それより大きい整数は一部しか表せない。
上限が $2^{53}$ を超えると、入力によっては真の係数を `f64` で表すことさえできない。
上限が $2^{53}$ 未満でも、FFT の途中の丸めによる誤差が $1/2$ 未満になるとは限らない。

Percival（"Rapid multiplication modulo the sum and difference of highly composite numbers", *Math. Comp.* 72 (2003), 387–395）の定理 5.1 は、長さ $L=2^n$ の基数 2 の FFT で計算した巡回畳み込みについて、最大誤差の上界

$$
\max_\ell\lvert\widetilde w_\ell-w_\ell\rvert<\lVert u\rVert_2\lVert v\rVert_2\left[(1+\varepsilon)^{3n}(1+\sqrt5\,\varepsilon)^{3n+1}(1+\beta)^{3n}-1\right]
$$

を与える。
ここで $\varepsilon$ は加減算と乗算の相対誤差の上界（倍精度では $2^{-53}$）、$\beta$ は回転因子 $e^{2\pi ik/L}$ の計算値の絶対誤差の上界である。
$\varepsilon$ と $\beta$ について 1 次の項だけを残すと $3(1+\sqrt5)\varepsilon n+3\beta n$ 倍になり、正しく丸めた回転因子（$\beta=\varepsilon/\sqrt2$）ではおよそ $12\,\varepsilon\lVert u\rVert_2\lVert v\rVert_2\log_2L$ である。
これは最悪の入力に対する上界で、乱数の入力では誤差が打ち消し合ってずっと小さくなることも同じ論文で述べられている。
`scioxide-fft` は混合基数、Bluestein のアルゴリズム、実数 FFT のパッキングも使い、回転因子の誤差も公表していないので、この定理を保証として当てはめることはできない。
以下では定数を除いた $\varepsilon\lVert u\rVert_2\lVert v\rVert_2\log_2L$ を誤差の大きさの目安として描き、上界としては使わない。

## 桁上がり

丸めた係数 $w_\ell$ は $B$ 以上になりうる。
下位の桁から、前の桁の繰り上がり $q_\ell$ を加えて

$$
s_\ell=w_\ell+q_\ell,\qquad
a_\ell=s_\ell\bmod B,\qquad
q_{\ell+1}=\left\lfloor s_\ell/B\right\rfloor,\qquad q_0=0
$$

とすれば、$0\le a_\ell<B$ の桁列が得られる。
最後に繰り上がりが残れば、その分だけ桁を追加する。
桁上がりは整数演算なので誤差を生まないが、丸めで誤った係数はそのまま誤った桁になる。

## 基数・桁数と誤差の実験

次のセルは基数 $B=10^k$ と最大桁数 $2^m$ を入力に取り、$d=1,2,4,\ldots,2^m$ の各桁数で乱数の桁を持つ二つの整数を掛ける。
桁は splitmix64 の擬似乱数で $[0,B)$ から一様に選ぶ。
独立な検算として、整数だけで係数 $w_\ell$ を直接の二重和（$O(d^2)$）で求め、真の係数誤差を測る。
さらに、FFT の係数と整数の係数のそれぞれから桁上がりで積の桁を作り、一致しない桁を数える。
入力の範囲では $d(B-1)^2\le2^{12}\cdot10^{14}<2^{63}$ なので、係数と桁上がりは `i64` で正確に計算できる。

表は桁数ごとの係数の上限、真の最大係数誤差、最近接整数との最大距離、丸めを誤った係数の数、積の誤った桁の数を示す。
グラフは両対数で、真の最大係数誤差を記号、最近接整数との距離を点線、目安 $\varepsilon\lVert u\rVert_2\lVert v\rVert_2\log_2L$ を破線で描き、$1/2$ を横線で示す。
誤差が 0 の点は対数軸に描けないので除き、その数を表の下に示す。

```rust
//| id: fft-integer-multiplication
//| ref: fft-integer-multiplication
//| title: 基数と桁数を変えた FFT 乗算の係数誤差
//| run: reactive
//| crates: [scioxide-core, scioxide-fft]
//| inputs:
//|   radix_exponent: {"type":"range","label":"基数の指数 k（B = 10^k）","description":"係数の上限 d(B−1)² と誤差が B² に比例して増える。","min":1,"max":7,"step":1,"value":5}
//|   digits_exponent: {"type":"range","label":"最大桁数の指数 m（d ≤ 2^m）","description":"d = 1, 2, 4, …, 2^m を調べる。","min":2,"max":12,"step":1,"value":12}
//|   seed: {"type":"range","label":"乱数のシード","description":"桁の擬似乱数の系列を変える。","min":1,"max":1000,"step":1,"value":1}
//| cases:
//|   - {"id":"decimal","label":"B = 10","description":"係数が小さく、誤差は 1/2 より 10 桁以上小さい。","inputs":{"radix_exponent":1}}
//|   - {"id":"radix-1e7","label":"B = 10^7","description":"d が大きいと誤差が 1/2 を超え、積の桁が誤る。","inputs":{"radix_exponent":7}}
//|   - {"id":"radix-1e6","label":"B = 10^6","description":"d = 4096 で誤差が 1/2 の手前まで増える。","inputs":{"radix_exponent":6}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"errors","path":"/rows/12/0","equals":4096}
//|       - {"artifact":"errors","path":"/rows/12/1","equals":8192}
//|       - {"artifact":"errors","path":"/rows/12/3","approx":{"value":0.0039,"rtol":0.5}}
//|       - {"artifact":"errors","path":"/rows/12/6","equals":0}
//|   - case: decimal
//|     expect:
//|       - {"artifact":"errors","path":"/rows/12/3","range":{"max":1e-9}}
//|       - {"artifact":"errors","path":"/rows/12/6","equals":0}
//|   - case: radix-1e7
//|     expect:
//|       - {"artifact":"errors","path":"/rows/12/3","range":{"min":0.5}}
//|       - {"artifact":"errors","path":"/rows/12/5","range":{"min":1}}
//|   - case: radix-1e6
//|     expect:
//|       - {"artifact":"errors","path":"/rows/12/3","approx":{"value":0.375,"atol":0.2}}
//|       - {"artifact":"errors","path":"/rows/12/6","equals":0}
use scioxide_core::Complex;
use scioxide_fft::{HermitianSpectrum, Normalization, irfft, next_fast_len, rfft};

let base = 10_i64.pow(radix_exponent as u32);
let max_digits = 1_usize << (digits_exponent as u32);
// 入力の生成: splitmix64 による [0, B) の一様な桁（FFT とは独立）。
let mut state = seed as u64;
let mut next_digit = || {
    state = state.wrapping_add(0x9E37_79B9_7F4A_7C15);
    let mut z = state;
    z = (z ^ (z >> 30)).wrapping_mul(0xBF58_476D_1CE4_E5B9);
    z = (z ^ (z >> 27)).wrapping_mul(0x94D0_49BB_1331_11EB);
    ((z ^ (z >> 31)) % base as u64) as i64
};
// 桁上がり: s = w + q、a = s mod B、q ← ⌊s/B⌋。負の繰り上がりは誤りとしてそのまま残す。
let carry_digits = |coefficients: &[i64]| {
    let (mut digits, mut carry) = (Vec::with_capacity(coefficients.len() + 4), 0_i64);
    for &w in coefficients {
        let total = w + carry;
        digits.push(total.rem_euclid(base));
        carry = total.div_euclid(base);
    }
    while carry > 0 {
        digits.push(carry % base);
        carry /= base;
    }
    if carry < 0 {
        digits.push(carry);
    }
    digits
};
let (mut rows, mut zero_points) = (Vec::new(), 0_usize);
let (mut true_curve, mut nearest_curve, mut scale_curve) = (Vec::new(), Vec::new(), Vec::new());
let mut d = 1_usize;
while d <= max_digits {
    let u: Vec<i64> = (0..d).map(|_| next_digit()).collect();
    let v: Vec<i64> = (0..d).map(|_| next_digit()).collect();
    // 長さ L ≥ 2d − 1 まで零を詰め、巡回畳み込みを線形畳み込みに一致させる。
    let needed = 2 * d - 1;
    let length = next_fast_len(needed).map_err(|e| e.to_string())?;
    let (mut a, mut b) = (vec![0.0; length], vec![0.0; length]);
    for j in 0..d {
        a[j] = u[j] as f64;
        b[j] = v[j] as f64;
    }
    let fa = rfft(&a, Normalization::Unscaled).map_err(|e| e.to_string())?;
    let fb = rfft(&b, Normalization::Unscaled).map_err(|e| e.to_string())?;
    let bins: Vec<Complex<f64>> = fa
        .bins()
        .iter()
        .zip(fb.bins())
        .map(|(&x, &y)| x * y)
        .collect();
    let spectrum = HermitianSpectrum::from_vec(length, bins).map_err(|e| e.to_string())?;
    let conv = irfft(&spectrum, Normalization::Inverse).map_err(|e| e.to_string())?;
    // 独立検算: 浮動小数点を使わない係数の二重和。
    let mut exact = vec![0_i64; needed];
    for (i, &x) in u.iter().enumerate() {
        for (j, &y) in v.iter().enumerate() {
            exact[i + j] += x * y;
        }
    }
    // w を f64 の上位部と整数の残りに分け、2^53 を超える係数でも誤差を正しく測る。
    let error = |(&x, &w): (&f64, &i64)| {
        let high = w as f64;
        ((x - high) - (w - high as i64) as f64).abs()
    };
    let true_error = conv.iter().zip(&exact).map(error).fold(0.0_f64, f64::max);
    let nearest = conv[..needed]
        .iter()
        .map(|&x| (x - x.round()).abs())
        .fold(0.0_f64, f64::max);
    let rounded: Vec<i64> = conv[..needed].iter().map(|&x| x.round() as i64).collect();
    let wrong_coefficients = rounded.iter().zip(&exact).filter(|(r, w)| r != w).count();
    let (fft_digits, exact_digits) = (carry_digits(&rounded), carry_digits(&exact));
    let digit_count = fft_digits.len().max(exact_digits.len());
    let digit_at = |digits: &[i64], i: usize| digits.get(i).copied().unwrap_or(0);
    let wrong_digits = (0..digit_count)
        .filter(|&i| digit_at(&fft_digits, i) != digit_at(&exact_digits, i))
        .count();
    let norm = |x: &[i64]| x.iter().map(|&c| (c as f64).powi(2)).sum::<f64>().sqrt();
    let scale = f64::EPSILON / 2.0 * norm(&u) * norm(&v) * (length as f64).log2().max(1.0);
    let bound = d as f64 * ((base - 1) as f64).powi(2);
    rows.push((
        d,
        length,
        bound,
        true_error,
        nearest,
        wrong_coefficients,
        wrong_digits,
    ));
    if true_error > 0.0 {
        true_curve.push([d as f64, true_error]);
    } else {
        zero_points += 1;
    }
    if nearest > 0.0 {
        nearest_curve.push([d as f64, nearest]);
    }
    if scale > 0.0 {
        scale_curve.push([d as f64, scale]);
    }
    d *= 2;
}
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "桁数 d", "type": "integer" },
    { "key": "1", "label": "FFT 長 L", "type": "integer" },
    { "key": "2", "label": "係数の上限 d(B−1)² [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "真の最大係数誤差 [-]", "type": "number", "format": sci3 },
    { "key": "4", "label": "最近接整数との最大距離 [-]", "type": "number", "format": sci3 },
    { "key": "5", "label": "丸めを誤った係数 [個]", "type": "integer" },
    { "key": "6", "label": "積の誤った桁 [桁]", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "errors" })
);
emit_text!(format!(
    "真の誤差が 0 でグラフから除いた桁数: {zero_points} 個"
));
emit_line_chart!(
    &vec![
        serde_json::json!({
            "name": "真の最大係数誤差",
            "points": true_curve,
            "style": { "symbol": "circle", "showSymbol": true }
        }),
        serde_json::json!({
            "name": "最近接整数との最大距離",
            "points": nearest_curve,
            "style": { "lineType": "dotted" }
        }),
        serde_json::json!({
            "name": "目安 ε‖u‖₂‖v‖₂log₂L",
            "points": scale_curve,
            "style": { "lineType": "dashed", "showSymbol": false }
        })
    ],
    options = &serde_json::json!({
        "xLabel": "桁数 d [桁]",
        "yLabel": "係数の絶対誤差 [-]",
        "xType": "log",
        "yType": "log",
        "annotations": [{ "kind": "line", "axis": "y", "value": 0.5, "label": "復元の条件 1/2" }]
    })
);
```

既定の $B=10^5$ では、真の最大係数誤差は $d=4096$（$L=8192$）でも $3.9\times10^{-3}$ で、誤った桁はない。
$B=10$ では同じ桁数で $2.9\times10^{-11}$ である。
誤差は基数を 10 倍にすると約 100 倍、桁数を 2 倍にすると約 2 倍になる。
$\lVert u\rVert_2\lVert v\rVert_2$ はおよそ $dB^2/3$ で、最大の係数（およそ $dB^2/4$）と同じ大きさなので、誤差は係数の大きさにほぼ比例する。
破線の目安 $\varepsilon\lVert u\rVert_2\lVert v\rVert_2\log_2L$ は、$B=10$、$10^5$、$10^6$、$10^7$ のどの点でも実測の 1.4〜10 倍の位置にある。
実測の誤差は最大の係数の数 ulp（隣り合う `f64` の間隔）の大きさで、表の値が $2^{-k}$ の小さな整数倍になるのはそのためである。

$B=10^6$ では $d=4096$ で誤差が 0.375 まで増え、$1/2$ の手前にある。
このときの最大の係数はおよそ $1.0\times10^{15}\approx2^{50}$ で、$2^{53}$ の $1/8$ にすぎない。
$B=10^7$ では $d=32$ で 0.375、$d=64$ でちょうど 0.5 に達し、$d=128$ では 51 個の係数の丸めが誤って、積の 51 桁が正しくない。
$d=128$ の最大の係数はおよそ $3.2\times10^{15}$ で $2^{52}$ に届かず、真の係数は `f64` で正確に表せる。
桁を誤らせたのは格納の誤差ではなく FFT の途中の丸めで、目安 $\varepsilon\lVert u\rVert_2\lVert v\rVert_2\log_2L$ はこの点で 3.6 に達している。
すべての入力で整数へ戻すには $d(B-1)^2\le2^{53}$ が必要だが、それだけでは足りず、目安が $1/2$ より十分小さくなるように基数と桁数を選ぶ必要がある。

誤差が $1/2$ を超えた行でも、最近接整数との距離は 0.5 以下にとどまり、$d\ge1024$ では 0 になる。
$2^{53}$ 以上の `f64` はすべて整数なので、大きい係数では FFT が返す値自体が整数になるが、それが正しい整数とは限らない。
真の誤差を測れない大きな計算では、最近接整数との距離が小さいことを正しさの根拠にできない。

表の値は表示した乱数の桁についての結果で、シードを変えると最大誤差は同じ程度の範囲で変わる。
FFT の演算回数は $O(L\log L)$ だが、このセルの検算の二重和は $O(d^2)$ で、$d=4096$ では FFT よりずっと重い。

## まとめ

FFT で整数を掛けるには、桁の列を $L\ge2d-1$ まで零で詰め、正変換を無尺度、逆変換を $1/L$ にして線形畳み込みの係数を求める。
最近接整数への丸めが正しい十分条件は、真の係数に対する誤差が $1/2$ 未満であることで、最近接整数との距離はその代わりにならない。
実測の誤差は目安 $\varepsilon\lVert u\rVert_2\lVert v\rVert_2\log_2L$ の 1/10〜1/1.4 で、基数を 10 倍にすると約 100 倍、桁数を 2 倍にすると約 2 倍になる。
`f64` では $B=10^5$ なら 4096 桁でも誤差は $3.9\times10^{-3}$ だが、$B=10^7$ では係数が $2^{52}$ 未満の 128 桁でも FFT の丸めで桁が誤る。
本例の一致は選んだ入力についての確認で、保証には Percival の定理のような誤差の上界を満たすアルゴリズムか、剰余による照合が別に要る。
