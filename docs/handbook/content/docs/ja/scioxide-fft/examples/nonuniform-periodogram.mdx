夜間だけの観測では、標本の時刻が等間隔にならない。
このような時刻 $t_j$ から Fourier 和 $\sum_jc_je^{-2\pi ift_j}$ を多くの周波数で求めると、直接和は観測数と周波数の数の積に比例する演算を要する。
非一様高速 Fourier 変換（NUFFT）は、各標本の実際の時刻を使ったまま、この和を要求精度まで近似する。

題材は scioxide-signal の[変光星の周期推定](../../../scioxide-signal/examples/variable-star-period/)と同じ合成データ（周期 $P=0.567$ 日、40 夜・一晩 6 回の観測）である。
周期の推定、日周エイリアス、誤警報確率はそのページが主に扱う。
このページは NUFFT の精度と計算コストに限り、直接和との誤差が要求精度を下回るか、核幅と格子と演算量が要求精度でどう変わるかを調べる。

## 合成光度曲線

観測時刻 [日] と光度 [等] は signal 章と同じく

$$
t_j=\lfloor j/6\rfloor+0.05+0.25\{0.6180339887498949\,j\},\qquad
y_j=0.3\sin\frac{2\pi t_j}{P}+0.1\sin\Bigl(\frac{4\pi t_j}{P}+0.7\Bigr)+\sigma g_j
$$

とする（$j=0,\ldots,239$）。
$\{\cdot\}$ は小数部分、$g_j$ は標準正規乱数で、signal 章と同じ splitmix64 と Box–Muller 法でシードから作る。
既定の $\sigma=0.3$ 等、シード 2024 は signal 章の既定値と同じで、観測数 $M$ を減らすときは 240 点の先頭から取る。

## 型 1 への換算

型 1 の NUFFT は非一様な座標 $x_j$ から等間隔の整数モード $k$ への和

$$
F_k=\sum_{j=0}^{M-1}c_j e^{-ikx_j},\qquad k=-N/2,\ldots,N/2-1
$$

を計算する（`FftDirection::Forward`、`Normalization::Unscaled`）。
時間尺度 $T_0$ を決めて $x_j=2\pi t_j/T_0$ とすると、$e^{-ikx_j}=e^{-2\pi i(k/T_0)t_j}$ なので、モード $k$ は周波数 $f_k=k/T_0$ [日⁻¹] にあたる。
ここでは $T_0=500$ 日、$N=4096$ とする。
周波数の刻みは 0.002 日⁻¹ で signal 章の周波数格子と同じになり、$k=100,\ldots,2000$ が 0.2〜4 日⁻¹ を覆う。
座標は $0\le x_j<2\pi\cdot40/500\approx0.50$ rad で、[座標の単位とモードの並び](oxref:fft-nufft-coordinates)が勧める $[-\pi,\pi]$ の中にある。
重み $c_j=y_j-\bar y$ は平均を引いた光度で、零周波数の大きな値が周りへ漏れるのを防ぐ。

出力は $k=-2048$ から昇順に並び、通常の FFT の零周波数を先頭に置く並びとは異なる。
任意の周波数の列で評価したいときは[型 3](oxref:fft-nufft-type3-observations)を使う。
$\lvert F_k\rvert^2/M$ は古典的なペリオドグラム（Schuster）で、signal 章の Lomb–Scargle 法の正規化パワーとは別の量である。

## 要求精度と誤差の測り方

`NufftPlanSpec::new(direction, normalization, accuracy)` の要求精度 $\epsilon$ は出力の最大誤差を入力の 1 ノルム $\lVert c\rVert_1=\sum_j\lvert c_j\rvert$ に対する比で表す。
そこで直接和 $F_k^{\mathrm{direct}}$ との差を

$$
E=\frac{\max_k\lvert F_k^{\mathrm{NUFFT}}-F_k^{\mathrm{direct}}\rvert}{\lVert c\rVert_1}
$$

で測り、最大は 4096 個のすべてのモードについて取る。
$\lvert F_k\rvert\le\lVert c\rVert_1$ なので、$E$ は各出力の大きさに対する相対誤差ではなく、出力の取りうる最大値に対する比である。

参照の直接和は要求精度より十分正確でなければならない。
位相 $kx_j$ は 1000 rad を超えるので、`f64` の積をそのまま正弦・余弦に渡すと、位相の丸め $10^{-13}$ rad 程度が誤差に加わる。
以下の参照計算では、$x_j$ を上位 26 ビットと残りに分けて $\lvert k\rvert\le2^{11}$ との積を正確に作り、$2\pi$ の倍数を 3 つの定数に分けて引いてから（Cody–Waite の縮約）、`f64` の `sin_cos` を使う。
こうすると参照値の誤差は $10^{-15}$ の桁に収まり、$10^{-13}$ までの要求精度を確かめられる。

Plan の準備は、エイリアシングの推定 $E_a$ と丸めの推定 $E_r$ の和が要求精度以下になる最小の核幅 $w$ を選び、`NufftDiagnostics` で返す。
二つの推定の式は[要求精度と誤差の推定](oxref:fft-nufft-accuracy)にある。
どちらも推定値で、上界の証明ではない。
要求精度が $E_r$ を下回ると準備は `NumericalInstability` で失敗する。

次の定義のブロックは合成データの生成、型 1 の重みと座標、参照の直接和を二つのセルで共有する。
定数 `TIME_SCALE` が $T_0$、`MODES` が $N$ である。

```rust
//| id: fft-nonuniform-light-curve
//| kind: definitions
//| title: 合成光度曲線と型 1 の参照和
//| crates: [scioxide-core]
use scioxide_core::Complex;
use std::f64::consts::TAU;

/// 周期 P [日]。
pub(crate) const PERIOD: f64 = 0.567;
/// 座標の時間尺度 T₀ [日]。モード k は周波数 k/T₀ [日⁻¹] にあたる。
pub(crate) const TIME_SCALE: f64 = 500.0;
/// 整数モードの数 N。k = −N/2, …, N/2 − 1。
pub(crate) const MODES: usize = 4096;

/// 観測時刻 t_j [日] と光度 y_j [等]。ノイズは splitmix64 と Box–Muller（f64 の固有メソッド）。
pub(crate) fn light_curve(count: usize, sigma: f64, seed: u64) -> (Vec<f64>, Vec<f64>) {
    let times: Vec<f64> = (0..count)
        .map(|j| (j / 6) as f64 + 0.05 + 0.25 * (j as f64 * 0.618_033_988_749_894_9).fract())
        .collect();
    let mut state = seed;
    let mut uniform = || -> f64 {
        state = state.wrapping_add(0x9E37_79B9_7F4A_7C15);
        let mut z = state;
        z = (z ^ (z >> 30)).wrapping_mul(0xBF58_476D_1CE4_E5B9);
        z = (z ^ (z >> 27)).wrapping_mul(0x94D0_49BB_1331_11EB);
        ((z ^ (z >> 31)) >> 11) as f64 / (1u64 << 53) as f64 + 0.5 / (1u64 << 53) as f64
    };
    let values = times
        .iter()
        .map(|&t| {
            let phase = TAU * t / PERIOD;
            let gauss = (-2.0 * uniform().ln()).sqrt() * (TAU * uniform()).cos();
            0.3 * phase.sin() + 0.1 * (2.0 * phase + 0.7).sin() + sigma * gauss
        })
        .collect();
    (times, values)
}

/// 型 1 の重み c_j = y_j − ȳ と座標 x_j = 2π t_j / T₀ [rad]。
pub(crate) fn type1_data(times: &[f64], values: &[f64]) -> (Vec<Complex<f64>>, Vec<f64>) {
    let mean = values.iter().sum::<f64>() / values.len() as f64;
    let weights = values
        .iter()
        .map(|&y| Complex::new(y - mean, 0.0))
        .collect();
    let positions = times.iter().map(|&t| TAU * t / TIME_SCALE).collect();
    (weights, positions)
}

/// 独立検算: F_k = Σ_j c_j exp(−i k x_j) の直接和（f64 の sin_cos による参照値）。
/// 位相 k x_j を丸めずに作り、2π = C1 + C2 + C3 の倍数を引いてから評価する。
pub(crate) fn direct_type1(weights: &[Complex<f64>], positions: &[f64]) -> Vec<Complex<f64>> {
    // C1 は下位 28 ビットを 0 にした 2π、C3 は f64 の TAU と 2π の差。
    let c1 = f64::from_bits(TAU.to_bits() & !((1_u64 << 28) - 1));
    let (c2, c3) = (TAU - c1, 2.449_293_598_294_706_4e-16);
    // x = 上位 26 ビット + 残り。|k| ≤ 2^11 との積はどちらも正確に表せる。
    let split: Vec<(f64, f64)> = positions
        .iter()
        .map(|&x| {
            let high = f64::from_bits(x.to_bits() & !((1_u64 << 27) - 1));
            (high, x - high)
        })
        .collect();
    let half = (MODES / 2) as i64;
    (-half..half)
        .map(|k| {
            let k = k as f64;
            weights
                .iter()
                .zip(&split)
                .map(|(&c, &(high, low))| {
                    let n = (k * high / TAU).round();
                    let reduced = ((k * high - n * c1) - n * c2 - n * c3) + k * low;
                    let (s, co) = reduced.sin_cos();
                    c * Complex::new(co, -s)
                })
                .sum()
        })
        .collect()
}
```

## 周波数と計算コストの実験

次のセルは要求精度 $\epsilon=10^{-9}$ の型 1 Plan を作り、0.2〜4 日⁻¹ の $\lvert F_k\rvert^2/M$ を描く。
グラフには入力の基本周波数 $f_0=1/P\approx1.764$ 日⁻¹ と日周エイリアス $f_0\pm1$ 日⁻¹ を縦線で示す。
表は NUFFT と直接和のそれぞれで最大の山の周波数、全モードでの誤差 $E$、核幅と格子の大きさ、演算量の目安を並べる。
演算量は、NUFFT が拡散で訪れる格子点の数 `stencil_visits` と格子の FFT、直接和が複素指数関数の評価 $MN$ 回である。

```rust
//| id: fft-nonuniform-periodogram
//| ref: fft-nonuniform-periodogram
//| title: 型 1 NUFFT による不規則観測の Fourier 和と直接和の比較
//| run: reactive
//| uses: [fft-nonuniform-light-curve]
//| crates: [scioxide-core, scioxide-fft]
//| inputs:
//|   observations: {"type":"range","label":"観測数 M","description":"240 点の先頭から取る。","min":60,"max":240,"step":60,"value":240}
//|   noise_sigma: {"type":"range","label":"ノイズの標準偏差 σ [等]","min":0,"max":1.5,"step":0.1,"value":0.3}
//|   seed: {"type":"range","label":"乱数のシード","min":1,"max":9999,"step":1,"value":2024}
//| cases:
//|   - {"id":"ten-nights","label":"M = 60","description":"10 夜だけの観測。最大の山が日周エイリアス f₀ − 1 に移る。","inputs":{"observations":60}}
//|   - {"id":"noisy","label":"σ = 1.5 等","description":"ノイズが大きく、最大の山が別の周波数に移る。","inputs":{"noise_sigma":1.5}}
//|   - {"id":"noise-free","label":"σ = 0","description":"ノイズなし。最大の山は f₀ に最も近い格子点に来る。","inputs":{"noise_sigma":0}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/1","approx":{"value":1.762,"atol":0.0011}}
//|       - {"artifact":"summary","path":"/rows/0/2","approx":{"value":1.762,"atol":0.0011}}
//|       - {"artifact":"summary","path":"/rows/0/3","range":{"max":1e-9}}
//|       - {"artifact":"summary","path":"/rows/0/7","equals":983040}
//|   - case: ten-nights
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/1","approx":{"value":0.764,"atol":0.0011}}
//|       - {"artifact":"summary","path":"/rows/0/3","range":{"max":1e-9}}
//|   - case: noisy
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/3","range":{"max":1e-9}}
//|   - case: noise-free
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/1","approx":{"value":1.764,"atol":0.0011}}
use scioxide_core::{Complex, ExecutionContext, NdView, StridedLayout};
use scioxide_fft::{FftDirection, Normalization, NufftPlan, NufftPlanSpec, NufftTransform};

let count = observations as usize;
let (times, values) = light_curve(count, noise_sigma, seed as u64);
let (weights, positions) = type1_data(&times, &values);
// 座標は形状 [M, 1] の行（1 次元）、モードは N 個。
let (shape, strides, modes) = ([count, 1], [1, 1], [MODES]);
let layout = StridedLayout::new(&shape, &strides).map_err(|e| e.to_string())?;
let points = NdView::new(&positions, layout).map_err(|e| e.to_string())?;
let transform = NufftTransform::Type1 {
    points,
    modes: &modes,
};
let spec = NufftPlanSpec::new(FftDirection::Forward, Normalization::Unscaled, 1e-9);
let plan = NufftPlan::new(transform, spec).map_err(|e| e.to_string())?;
let diagnostics = plan.diagnostics();
let mut workspace = plan.workspace(()).map_err(|e| e.to_string())?;
let mut output = vec![Complex::new(0.0, 0.0); MODES];
plan.execute_into(
    &weights,
    &mut output,
    &mut workspace,
    ExecutionContext::sequential(),
)
.map_err(|e| e.to_string())?;
let direct = direct_type1(&weights, &positions);
let norm1: f64 = weights.iter().map(|c| c.norm()).sum();
let error = output
    .iter()
    .zip(&direct)
    .map(|(&a, &b)| (a - b).norm())
    .fold(0.0_f64, f64::max)
    / norm1;
// 0.2〜4 日⁻¹ のモード k = 100, …, 2000 の |F_k|²/M と最大の山。
let band = |spectrum: &[Complex<f64>]| -> Vec<[f64; 2]> {
    (100..=2000)
        .map(|k| {
            let power = spectrum[k + MODES / 2].norm_sqr() / count as f64;
            [k as f64 / TIME_SCALE, power]
        })
        .collect()
};
let peak = |curve: &[[f64; 2]]| {
    curve
        .iter()
        .fold([0.0, 0.0], |b, &p| if p[1] > b[1] { p } else { b })
};
let (curve, reference) = (band(&output), band(&direct));
let (nufft_peak, direct_peak) = (peak(&curve), peak(&reference));
let f0 = 1.0 / PERIOD;
emit_line_chart!(
    &vec![serde_json::json!({ "name": "|F_k|²/M（NUFFT）", "points": curve })],
    options = &serde_json::json!({
        "xLabel": "周波数 f [日⁻¹]",
        "yLabel": "|F|²/M [等²]",
        "xMin": 0.2,
        "xMax": 4.0,
        "annotations": [
            { "kind": "line", "axis": "x", "value": f0, "label": "f₀ = 1/P" },
            { "kind": "line", "axis": "x", "value": f0 - 1.0, "label": "f₀ − 1" },
            { "kind": "line", "axis": "x", "value": f0 + 1.0, "label": "f₀ + 1" }
        ]
    })
);
let fixed4 = serde_json::json!({ "significantDigits": 4 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "観測数 M", "type": "integer" },
    { "key": "1", "label": "最大の山（NUFFT）[日⁻¹]", "type": "number", "format": fixed4 },
    { "key": "2", "label": "最大の山（直接和）[日⁻¹]", "type": "number", "format": fixed4 },
    { "key": "3", "label": "誤差 E [-]", "type": "number", "format": sci2 },
    { "key": "4", "label": "核幅 w [点]", "type": "integer" },
    { "key": "5", "label": "格子点数 G", "type": "integer" },
    { "key": "6", "label": "拡散の訪問 [回]", "type": "integer" },
    { "key": "7", "label": "直接和の項 MN [回]", "type": "integer" }
]);
let row = (
    count,
    nufft_peak[0],
    direct_peak[0],
    error,
    diagnostics.kernel_support,
    diagnostics.grid_points,
    diagnostics.stencil_visits,
    count * MODES,
);
emit_table_with_columns!(
    columns,
    vec![row],
    metadata = serde_json::json!({ "id": "summary" })
);
```

既定の $M=240$、$\sigma=0.3$ 等、シード 2024 では、最大の山は NUFFT でも直接和でも 1.762 日⁻¹ にあり、signal 章の Lomb–Scargle 法の最大の山と同じ周波数である。
全 4096 モードでの誤差は $E=2.0\times10^{-11}$ で、要求精度 $10^{-9}$ を 50 倍下回る。
グラフでは $f_0\pm1$ 日⁻¹ の日周エイリアスにも山が立ち、主な山の幅はおよそ $1/(40\ \text{日})=0.025$ 日⁻¹ である。

$M=60$（10 夜）では最大の山が 0.764 日⁻¹、すなわち $f_0-1$ のエイリアスに移り、$\sigma=1.5$ 等では 2.680 日⁻¹ に移る。
どちらでも NUFFT と直接和の最大の山は一致し、誤差 $E$ は $3\times10^{-11}$ 程度にとどまる。
山の位置が真の周波数からずれるのは観測区間とノイズのためで、NUFFT の計算誤差のためではない。
ノイズがない $\sigma=0$ では、最大の山は $f_0=1.7637$ 日⁻¹ に最も近い格子点 1.764 日⁻¹ に来る。

演算量は、NUFFT の拡散が $Mw=240\times11=2640$ 回の格子点の訪問と、$G=8192$ 点の FFT 1 回である。
直接和は $MN=983040$ 回の複素指数関数の評価を要する。
直接和の演算量は $MN$ に比例し、NUFFT の演算量はおよそ $Mw+G\log G$ に比例するので、$M$ と $N$ がともに大きいほど差が開く。

## 要求精度と核幅の実験

次のセルは同じデータ（$\sigma=0.3$ 等、シード 2024）について要求精度を $\epsilon=10^{-2},\ldots,10^{-13}$ と変え、Plan ごとに誤差 $E$ と診断を表にする。
入力は観測数と過標本率の下限 $\sigma_o$（`with_oversampling`）である。
格子は $\max(\lceil\sigma_oN\rceil,w+2)$ 以上で最小の 2 のべきの点数を持つので、$N=4096$ では $\sigma_o=2$ で $G=8192$、$2<\sigma_o\le4$ で $G=16384$ になる。
一方、核幅を選ぶ推定 $E_a$ と核の形状 $\beta$ には、実際の格子の比ではなく指定した $\sigma_o$ が使われる。

上のグラフは $\epsilon$ に対する $E$ と推定 $E_a+E_r$ を両対数で描き、$E=\epsilon$ の線を破線で示す。
下のグラフは選ばれた核幅 $w$ を階段で描く。
二つのグラフは横軸の $\epsilon$ を共有して連動する。

```rust
//| id: fft-nonuniform-accuracy
//| ref: fft-nonuniform-accuracy
//| title: 要求精度に対する NUFFT の誤差・核幅・作業領域
//| run: reactive
//| uses: [fft-nonuniform-light-curve]
//| crates: [scioxide-core, scioxide-fft]
//| inputs:
//|   observations: {"type":"range","label":"観測数 M","min":60,"max":240,"step":60,"value":240}
//|   oversampling: {"type":"range","label":"過標本率の下限 σ_o","description":"2 より大きいと格子が 2 倍になり、必要な核幅が減る。","min":2,"max":4,"step":0.5,"value":2}
//| cases:
//|   - {"id":"oversampling-3","label":"σ_o = 3","description":"格子が 16384 点に倍増し、同じ要求精度での核幅は同じか 1 点小さい。","inputs":{"oversampling":3}}
//|   - {"id":"few-points","label":"M = 60","description":"観測が少なくても、誤差の比 E は要求精度を下回る。","inputs":{"observations":60}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"sweep","path":"/rows/0/0","approx":{"value":0.01,"rtol":1e-12}}
//|       - {"artifact":"sweep","path":"/rows/0/1","range":{"max":0.01}}
//|       - {"artifact":"sweep","path":"/rows/6/1","range":{"max":1e-8}}
//|       - {"artifact":"sweep","path":"/rows/11/1","range":{"max":1e-13}}
//|       - {"artifact":"sweep","path":"/rows/11/5","equals":8192}
//|   - case: oversampling-3
//|     expect:
//|       - {"artifact":"sweep","path":"/rows/11/1","range":{"max":1e-13}}
//|       - {"artifact":"sweep","path":"/rows/11/5","equals":16384}
//|   - case: few-points
//|     expect:
//|       - {"artifact":"sweep","path":"/rows/11/1","range":{"max":1e-13}}
use scioxide_core::{Complex, ExecutionContext, NdView, StridedLayout};
use scioxide_fft::{FftDirection, Normalization, NufftPlan, NufftPlanSpec, NufftTransform};

let count = observations as usize;
let (times, values) = light_curve(count, 0.3, 2024);
let (weights, positions) = type1_data(&times, &values);
let direct = direct_type1(&weights, &positions);
let norm1: f64 = weights.iter().map(|c| c.norm()).sum();
let (shape, strides, modes) = ([count, 1], [1, 1], [MODES]);
let layout = StridedLayout::new(&shape, &strides).map_err(|e| e.to_string())?;
let mut output = vec![Complex::new(0.0, 0.0); MODES];
let mut rows = Vec::new();
```

既定の $\sigma_o=2$ では、要求精度を 1 桁厳しくするごとに核幅 $w$ が 1 点ずつ増え、$\epsilon=10^{-2}$ で $w=4$、$10^{-13}$ で $w=15$ になる。
誤差 $E$ はすべての要求で要求精度を下回り、その比はおよそ 1/25 から 1/90 である（$10^{-9}$ で $2.0\times10^{-11}$、$10^{-13}$ で $4.1\times10^{-15}$）。
推定 $E_a$ は実際の誤差の 20〜40 倍で、核幅の選択は安全側に寄っている。
推定 $E_r=5.6\times10^{-15}$ は核幅によらず、これを下回る要求は準備の段階で `NumericalInstability` になる。

$\sigma_o=3$ では格子が $G=16384$ 点に倍増し、同じ要求精度での核幅は同じか 1 点小さくなる（$10^{-13}$ で $w=14$）。
拡散の訪問は核幅に比例して少し減るが、作業領域は 0.59 MB から 1.1 MB に増え、格子の FFT も 2 倍の長さになる。
$\sigma_o=4$ では $\epsilon=10^{-2}$ と $10^{-3}$ がともに最小の核幅 $w=4$ になり、誤差はどちらも $3.7\times10^{-5}$ 程度で、要求より 1.4〜2.4 桁小さい。
この例では $\sigma_o$ を上げても核幅は高々 2 点しか減らず、格子と作業領域は 2 倍になる。
観測数がモード数より少ない 1 次元の問題では、拡散の訪問 $Mw$ は格子の大きさ $G$ より小さいので、過標本率を上げて核幅を減らす利点は小さい。

$M=60$ でも誤差の比 $E$ は要求精度を下回る。
$E$ は入力の 1 ノルムに対する比なので、観測数が変わっても同じ要求精度で比べられる。
個々の出力 $F_k$ の相対誤差は、$\lvert F_k\rvert$ が $\lVert c\rVert_1$ よりずっと小さいモードでは $E$ よりずっと大きくなりうる。

## まとめ

型 1 の NUFFT は不規則な時刻 $t_j$ の重み付き指数和を等間隔の整数モードで求め、時間尺度 $T_0$ を決めればモード $k$ を周波数 $k/T_0$ に換算できる。
要求精度は入力の 1 ノルムに対する最大誤差の比で、直接和との比較はこの尺度で行う。
参照の直接和は位相の丸めが誤差を支配しないように作る必要があり、そうした参照と比べると、この例では $10^{-2}$ から $10^{-13}$ までのすべての要求で実際の誤差が要求を下回った。
要求精度を 1 桁厳しくすると核幅がおよそ 1 点増え、拡散の演算量はそれに比例して増えるが、格子の大きさはモード数と過標本率だけで決まる。
周期を検出したかどうかの統計的な判断は、Fourier 和の計算精度とは別の問題で、signal 章の誤警報確率で扱う。
