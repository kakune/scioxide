項が滑らかな関数の標本 $a_n = f(n)$ で、$f$ の積分と導関数を解析的に与えられるなら、級数の剰余を経験的に推定せずに上から評価できる。
このページは Euler–Maclaurin 公式による尾部の評価と、`SeriesSummation` の `SeriesMethod::EulerMaclaurin` が返す条件付きの上界を説明する。
Plan・状態・作業領域・レポートの仕様は 3 つの方法に共通で、[無限級数の加速（Levin u・Wynn ε）](oxref:integrate-series-plan-state)にまとめた。

---

## 尾部の Euler–Maclaurin 公式

$f$ が $[n, N]$ で $2p$ 回連続微分可能なら、周期的な Bernoulli 関数 $\tilde B_m(x)$（Bernoulli 多項式 $B_m(x - \lfloor x\rfloor)$）を使った部分積分の繰り返しから

$$
\sum_{k=n}^{N} f(k) = \int_n^N f(x)\,dx + \frac{f(n) + f(N)}{2} + \sum_{j=1}^{p} \frac{B_{2j}}{(2j)!}\Bigl(f^{(2j-1)}(N) - f^{(2j-1)}(n)\Bigr) - \int_n^N \frac{\tilde B_{2p}(x)}{(2p)!} f^{(2p)}(x)\,dx
$$

が成り立つ。
$B_{2j}$ は Bernoulli 数で、この式は[Euler–Maclaurin 展開と Romberg 外挿](../romberg-extrapolation/)の台形則の誤差展開と同じものである。
$N \to \infty$ で $f$ と奇数階導関数が 0 に近づき、$f^{(2p)}$ が絶対可積分なら、$n$ 以降の和は

$$
\sum_{k=n}^{\infty} f(k) = \int_n^{\infty} f(x)\,dx + \frac{f(n)}{2} - \sum_{j=1}^{p} \frac{B_{2j}}{(2j)!} f^{(2j-1)}(n) + R_p, \qquad
|R_p| \le \frac{|B_{2p}|}{(2p)!} \int_n^{\infty} \bigl|f^{(2p)}(x)\bigr|\,dx
$$

となる。
剰余の上界は周期的な Bernoulli 関数の性質 $|\tilde B_{2p}(x)| \le |B_{2p}|$ から出る。
推定値は $n$ 未満の部分和にこの右辺を加えたもので、剰余の上界は解析的に評価できる。

Euler–Maclaurin 展開は収束級数ではなく漸近級数である。
$B_{2j}/(2j)! \approx 2(-1)^{j+1}/(2\pi)^{2j}$ なので、たとえば $f(x) = x^{-s}$ の補正項は $2n^{1-s}(s)_{2j-1}/(2\pi n)^{2j}$ 程度の大きさである（$(s)_m = s(s+1)\cdots(s+m-1)$ は上昇階乗）。
隣り合う補正項の比は $(s + 2j - 1)(s + 2j)/(2\pi n)^2$ 程度なので、$j$ を増やすと補正項は $j$ がおよそ $\pi n - s/2$ を超えたところから大きくなる。
固定した $n$ で補正次数 $p$ を上げても誤差は際限なく小さくはならず、高い $p$ を使うには明示的に足す項数 $n$ を大きくとる。

## プロバイダーと仮定

`EulerMaclaurinProvider` は項 `term`（`SeriesTerms`）に加え、尾部の積分 `tail_integral`、奇数階の導関数 `odd_derivative`（それぞれ値と絶対誤差の上界）、偶数階導関数の $L^1$ ノルムの上界 `even_derivative_l1_bound` を提供する。
1 項あたりのプロバイダーの呼び出しは項、尾部の積分、$p$ 個の奇数階導関数、1 つの上界の $p + 3$ 回である。
補正次数 $p$ は `SeriesOptions::with_order` で 1〜12 の範囲で指定する。
利用者は、$f$ が $[n, \infty)$ で滑らかに延長でき、奇数階導関数が無限遠で 0 に近づき、$f^{(2p)}$ が絶対可積分であることに責任を持つ。
SciOxide はこの仮定を確かめない。
返した誤差の上界が負や非有限なら `InvalidInput` になる。

## 誤差の内訳と停止

`SeriesError` は、提示した誤差を Bernoulli の係数で重みづけた `provider`、剰余の上界 `tail_bound`、浮動小数点演算による誤差の下限 `roundoff` を分けて返す。
その和が許容誤差以下なら `BoundedTailReached` で止まる。
`is_success()` が真を返す状態のうち、剰余の上界が付くのはこの状態だけである（ほかは成分を持たない項の `ExactEmpty` と、加速の `HeuristicToleranceReached`）。
この上界は、利用者が与えた滑らかさ・減衰・導関数の値が正しいという条件のもとでだけ成り立つ。
浮動小数点演算による誤差の下限は推定値を作る各加数（丸めた部分和、尾部の積分、項の半分、各補正項）の絶対値の $64\varepsilon$ 倍の和で、許容誤差がこの誤差の下限より小さいと到達できない。
項数の上限に達すると `TermLimit` で終わり、最後の推定値と上界を返す。
Euler–Maclaurin のプロバイダーは常に逐次に評価される。

## ζ(s) の Euler–Maclaurin 和

$\zeta(s) = \sum_{n\ge1} n^{-s}$ を、$f(x) = x^{-s}$ の導関数 $f^{(m)}(x) = (-1)^m (s)_m\,x^{-s-m}$（$(s)_m$ は上昇階乗）を解析式で与えて計算する。
$f^{(2p)} > 0$ なので $\int_n^\infty |f^{(2p)}|\,dx = (s)_{2p}\,n^{1-s-2p}/(s + 2p - 1)$ である。
プロバイダーの値は `RealScalar::powf` で計算し、提示内容誤差は丸めの尺度 $64\varepsilon|\text{値}|$ とした。
`scioxide_special::riemann_zeta` を独立な参照値とする。

次の定義のブロックは、このページの 2 つのセルが使うプロバイダーである。
`rising` が上昇階乗 $(s)_m$、`PowerLaw` が項 $n^{-s}$（`SeriesTerms`）と、尾部の積分、奇数階の導関数、$L^1$ ノルムの上界（`EulerMaclaurinProvider`）に対応する。

```rust
//| id: integrate-euler-maclaurin-power-law
//| kind: definitions
//| title: f(x) = x^(−s) の Euler–Maclaurin プロバイダー
//| crates: [scioxide-core, scioxide-integrate]
use scioxide_core::{SciOxideError, RealScalar};
use scioxide_integrate::{EulerMaclaurinProvider, SeriesTerms};

/// 上昇階乗 (s)_m = s (s + 1) ⋯ (s + m − 1)。
pub(crate) fn rising(s: f64, m: usize) -> f64 {
    (0..m).fold(1.0, |acc, k| acc * (s + k as f64))
}

/// f(x) = x^(−s)。導関数と積分は解析式で、提示内容誤差は丸めの尺度 64ε|値|。
pub(crate) struct PowerLaw(pub(crate) f64);
impl SeriesTerms<f64> for PowerLaw {
    fn term(&self, n: usize, out: &mut [f64]) -> Result<(), SciOxideError> {
        out[0] = RealScalar::powf(n as f64, -self.0);
        Ok(())
    }
}
impl EulerMaclaurinProvider<f64> for PowerLaw {
    fn tail_integral(
        &self,
        at: usize,
        value: &mut [f64],
        error: &mut [f64],
    ) -> Result<(), SciOxideError> {
        // ∫_n^∞ x^(−s) dx = n^(1−s) / (s − 1)
        value[0] = RealScalar::powf(at as f64, 1.0 - self.0) / (self.0 - 1.0);
        error[0] = 64.0 * f64::EPSILON * value[0];
        Ok(())
    }
    fn odd_derivative(
        &self,
        at: usize,
        order: usize,
        value: &mut [f64],
        error: &mut [f64],
    ) -> Result<(), SciOxideError> {
        // f^(m)(n) = (−1)^m (s)_m n^(−s−m)。m は奇数なので符号は負。
        value[0] = -rising(self.0, order) * RealScalar::powf(at as f64, -self.0 - order as f64);
        error[0] = 64.0 * f64::EPSILON * value[0].abs();
        Ok(())
    }
    fn even_derivative_l1_bound(
        &self,
        at: usize,
        order: usize,
        bound: &mut [f64],
    ) -> Result<(), SciOxideError> {
        // f^(2p) > 0 なので ∫_n^∞ |f^(2p)| = (s)_{2p} n^(1−s−2p) / (s+2p−1)。丸め分を上乗せする。
        let (s, m) = (self.0, order as f64);
        let exact = rising(s, order) * RealScalar::powf(at as f64, 1.0 - s - m) / (s + m - 1.0);
        bound[0] = exact * (1.0 + 64.0 * f64::EPSILON);
        Ok(())
    }
}
```

## 項数を増やしたときの上界と実誤差

最初のセルは状態と作業領域を保ったまま `advance` を呼び（[再開の仕様](oxref:integrate-series-plan-state)）、1 回の呼び出しで 1 項ずつ進めて（`with_terms_per_advance(Budget::ONE)`）、各段の推定値と示された上界を記録する。
項数の上限は 40 で、`CallLimit` 以外の終了状態が出たところで止める。
実誤差が上界以下であることを図で確かめる。
入力は指数 $s$、補正次数 $p$、絶対許容誤差の指数である。
実誤差が厳密に 0 の段は対数軸に描けないので除き、その数を表に示す。
表の「最後の advance のプロバイダー呼び出し」は、1 項を足すのに使った呼び出しの回数で、$p + 3$ になる。

```rust
//| id: integrate-series-euler-maclaurin-zeta
//| ref: integrate-series-euler-maclaurin-zeta
//| title: 指数と補正次数を動かして ζ(s) の Euler–Maclaurin 上界を実誤差と比べる
//| run: reactive
//| uses: [integrate-euler-maclaurin-power-law]
//| crates: [scioxide-core, scioxide-integrate, scioxide-special]
//| inputs:
//|   exponent: {"type":"range","label":"指数 s [-]","description":"Σ n^(−s) の減衰の速さを変える（s > 1）。","min":1.25,"max":6,"step":0.25,"value":2}
//|   correction_order: {"type":"range","label":"補正次数 p [-]","description":"Bernoulli 数による端点補正の項数を変える。","min":1,"max":12,"step":1,"value":3}
//|   tolerance_exponent: {"type":"range","label":"絶対許容誤差の指数 q [-]","description":"条件付きの上界と比べる許容誤差を 10^q とする。","min":-14,"max":-4,"step":1,"value":-12}
//| cases:
//|   - {"id":"order-12","label":"補正次数 p = 12","description":"5 項で BoundedTailReached となり、上界 3.2×10⁻¹³ に対して実誤差は 1.1×10⁻¹³ になる。","inputs":{"correction_order":12}}
//|   - {"id":"order-1","label":"補正次数 p = 1","description":"40 項でも上界が 2.6×10⁻⁶ までしか下がらず TermLimit で終わる。","inputs":{"correction_order":1}}
//|   - {"id":"below-floor","label":"許容誤差 10⁻¹⁴","description":"浮動小数点演算による誤差の下限が許容誤差を上回るので到達できず、40 項で TermLimit になる。","inputs":{"tolerance_exponent":-14}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/1","range":{"min":30,"max":32}}
//|       - {"artifact":"summary","path":"/rows/0/4","range":{"min":0,"max":1e-14}}
//|       - {"artifact":"summary","path":"/rows/0/5","approx":{"value":8.89e-13,"atol":5e-15}}
//|       - {"artifact":"summary","path":"/rows/0/6","equals":"BoundedTailReached"}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: order-12
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/1","equals":5}
//|       - {"artifact":"summary","path":"/rows/0/4","approx":{"value":1.11e-13,"atol":5e-15}}
//|       - {"artifact":"summary","path":"/rows/0/5","approx":{"value":3.17e-13,"atol":5e-15}}
//|       - {"artifact":"summary","path":"/rows/0/6","equals":"BoundedTailReached"}
//|   - case: order-1
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/1","equals":40}
//|       - {"artifact":"summary","path":"/rows/0/5","approx":{"value":2.604e-6,"atol":5e-10}}
//|       - {"artifact":"summary","path":"/rows/0/6","equals":"TermLimit"}
//|       - {"path":"/outputs/2/state","equals":"partial"}
//|   - case: below-floor
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/1","equals":40}
//|       - {"artifact":"summary","path":"/rows/0/5","approx":{"value":1.69e-13,"atol":5e-15}}
//|       - {"artifact":"summary","path":"/rows/0/6","equals":"TermLimit"}
use scioxide_core::{Budget, ErrorTolerance, ExecutionContext, NormSelection};
use scioxide_integrate::{
    SeriesMethod, SeriesOptions, SeriesProblem, SeriesSummation, SeriesTermination,
};
use scioxide_special::riemann_zeta;

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let digits15 = serde_json::json!({ "significantDigits": 15 });
let tolerance = 10.0_f64.powf(tolerance_exponent);
let options = SeriesOptions::default()
    .with_max_terms(Budget::try_from(40).map_err(|e| e.to_string())?)
    .with_order(Budget::try_from(correction_order as usize).map_err(|e| e.to_string())?)
    .with_tolerance(
        ErrorTolerance::scalar(tolerance, 0.0, NormSelection::Infinity)
            .map_err(|e| e.to_string())?,
    )
    .with_terms_per_advance(Budget::ONE);
let plan = SeriesSummation::<f64>::new(SeriesMethod::EulerMaclaurin, 1, options)
    .map_err(|e| e.to_string())?;
let mut state = plan.state(1).map_err(|e| e.to_string())?;
let mut workspace = plan.workspace(1).map_err(|e| e.to_string())?;
let exact = riemann_zeta(exponent).map_err(|e| e.to_string())?; // 独立な参照値
let provider = PowerLaw(exponent);

// 1 項ずつ進め、同じ状態と作業領域で再開しながら各段の推定値と上界を記録する。
let (mut actual, mut bound) = (Vec::new(), Vec::new());
let mut zero_errors = 0_usize;
let report = loop {
    let report = plan
        .advance(
            SeriesProblem::EulerMaclaurin(&provider),
            &mut state,
            |_| Ok(()),
            &mut workspace,
            ExecutionContext::sequential(),
        )
        .map_err(|e| e.to_string())?;
    let error = state.errors().ok_or("誤差の推定がない")?[0];
    let gap = (state.value().ok_or("推定値がない")?[0] - exact).abs();
    let reported = error.provider().ok_or("プロバイダーの誤差がない")?
        + error.tail_bound().ok_or("剰余の上界がない")?
        + error.roundoff();
    let n = report.terms() as f64;
    // 実誤差が厳密に 0 の段は対数軸に描けないので除く。
    if gap > 0.0 {
        actual.push([n, gap]);
    } else {
        zero_errors += 1;
    }
    bound.push([n, reported]);
    if report.termination() != SeriesTermination::CallLimit {
        break report;
    }

    serde_json::json!({ "kind": "line", "axis": "y", "value": tolerance, "label": "許容誤差" });

    serde_json::json!({ "showSymbol": true }),
    serde_json::json!({ "lineType": "dashed" }),
);

    &vec![
        serde_json::json!({ "name": "|推定値 − ζ(s)|", "points": actual, "style": marker }),
        serde_json::json!({ "name": "示された条件付きの上界", "points": bound, "style": dashed }),
    ],
    options = &serde_json::json!({
        "xLabel": "明示的に加えた項数 n [項]",
        "yLabel": "誤差 [-]",
        "yType": "log",
        "xMin": 0,
        "xMax": 40,
        "annotations": [tolerance_line]
    })
);

let gap = (value - exact).abs();
let last_bound = bound.last().map(|point| point[1]);
let termination = report.termination();
let status = format!("{termination:?}");
let columns = serde_json::json!([
    { "key": "0", "label": "s [-]", "type": "number", "format": { "fractionDigits": 2 } },
    { "key": "1", "label": "使用項数 [項]", "type": "integer" },
    { "key": "2", "label": "推定値 [-]", "type": "number", "format": digits15 },
    { "key": "3", "label": "ζ(s) [-]", "type": "number", "format": digits15 },
    { "key": "4", "label": "実誤差 [-]", "type": "number", "format": sci3 },
    { "key": "5", "label": "条件付きの上界 [-]", "type": "number", "format": sci3, "nullText": "未計算" },
    { "key": "6", "label": "終了状態" },
    { "key": "7", "label": "最後の advance のプロバイダー呼び出し [回]", "type": "integer" },
    { "key": "8", "label": "図で除いた段 [段]", "type": "integer" }
]);
let row = (
    exponent,
    state.terms(),
    value,
    exact,
    gap,
    last_bound,
    status.clone(),
    report.provider_calls(),
    zero_errors,
);
emit_table_with_columns!(
    columns,
    vec![row],
    metadata = serde_json::json!({ "id": "summary" })
);

let outcome = if termination.is_success() {
    Outcome::satisfied("条件付きの上界が許容誤差を満たした")
        .explanation("上界はプロバイダーの導関数と尾部の情報が正しいという条件のもとで成り立つ。")
} else {
    Outcome::partial("上界が許容誤差を満たす前に項数の上限に達した")
        .explanation("推定値と上界は最後に加えた項の段のものである。")
};
let outcome = outcome
    .status(status)
    .diagnostic("使用項数", state.terms() as f64, None)
    .diagnostic("実誤差", gap, None);
emit_outcome!(match last_bound {
    Some(bound) => outcome.diagnostic("条件付きの上界", bound, None),
    None => outcome,
});
```

既定値（$s = 2$、$p = 3$、許容誤差 $10^{-12}$）では 31 項で `BoundedTailReached` となり、上界 $8.9 \times 10^{-13}$ に対して実誤差は $10^{-15}$ の程度だった。
$p = 12$ では 5 項で止まる（上界 $3.2 \times 10^{-13}$、実誤差 $1.1 \times 10^{-13}$）が、$n = 1$ の段の推定値は $\zeta(2)$ から $8 \times 10^4$ もずれる。
Euler–Maclaurin 展開は漸近級数なので、補正次数を上げるほど $n$ を大きくとる必要がある。
$p = 1$ では 40 項でも上界が $2.6 \times 10^{-6}$ までしか下がらず、`TermLimit` で終わって outcome は `partial` になった。
許容誤差を $10^{-14}$ にすると、浮動小数点演算による誤差の下限（約 $64\varepsilon\,\zeta(2) \approx 2.3 \times 10^{-14}$）が許容誤差を上回るので到達できず、40 項で上界 $1.7 \times 10^{-13}$ の `TermLimit` になる。

## 補正次数と漸近級数

2 つ目のセルは明示的に足す項数 $n$ を固定し、補正次数 $p$ を 1 から 12 まで変えて、$n$ 項を足した段の推定値と上界を比べる。
許容誤差を浮動小数点演算による誤差の下限より小さい $10^{-20}$ にすると到達できないので、各 Plan は `sum` でちょうど $n$ 項まで進んで `TermLimit` で止まり、その推定値と上界を読める。
補正項の大きさは $j \approx \pi n - s/2$ で最小になるので、誤差と上界はこの次数の近くで最小になり、それより高い次数では増えると予想される。
図の縦線は $p = \pi n - s/2$ である。
入力は項数 $n$ と指数 $s$ である。

```rust
//| id: integrate-euler-maclaurin-asymptotic
//| ref: integrate-euler-maclaurin-asymptotic
//| title: 項数を固定して補正次数を上げ、漸近級数の誤差の最小を見る
//| run: reactive
//| uses: [integrate-euler-maclaurin-power-law]
//| crates: [scioxide-core, scioxide-integrate, scioxide-special]
//| inputs:
//|   explicit_terms: {"type":"range","label":"項数 n [項]","description":"明示的に足す項の数。補正を評価する点も決まる。","min":1,"max":4,"step":1,"value":1}
//|   fixed_exponent: {"type":"range","label":"指数 s [-]","description":"Σ n^(−s) の減衰の速さを変える（s > 1）。","min":1.5,"max":6,"step":0.5,"value":2}
//| cases:
//|   - {"id":"two-terms","label":"n = 2","description":"実誤差と上界が p = 6 で最小になる。","inputs":{"explicit_terms":2}}
//|   - {"id":"four-terms","label":"n = 4","description":"最小の位置が p = 12 より先に移り、誤差は p = 12 まで減り続ける。","inputs":{"explicit_terms":4}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"orders","path":"/rows/0/3","equals":"TermLimit"}
//|       - {"artifact":"orders","path":"/rows/1/1","approx":{"value":1.160e-2,"rtol":1e-3}}
//|       - {"artifact":"orders","path":"/rows/2/2","approx":{"value":2.381e-2,"rtol":1e-3}}
//|       - {"artifact":"orders","path":"/rows/11/1","approx":{"value":8.087e4,"rtol":1e-3}}
//|   - case: two-terms
//|     expect:
//|       - {"artifact":"orders","path":"/rows/5/1","approx":{"value":1.540e-5,"rtol":1e-3}}
//|       - {"artifact":"orders","path":"/rows/5/2","approx":{"value":3.090e-5,"rtol":1e-3}}
//|   - case: four-terms
//|     expect:
//|       - {"artifact":"orders","path":"/rows/11/1","approx":{"value":3.753e-11,"rtol":1e-2}}
//|       - {"artifact":"orders","path":"/rows/11/2","approx":{"value":7.693e-11,"rtol":1e-3}}
use scioxide_core::{Budget, ErrorTolerance, NormSelection};
use scioxide_integrate::{SeriesMethod, SeriesOptions, SeriesProblem, SeriesSummation};
use scioxide_special::riemann_zeta;

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let exact = riemann_zeta(fixed_exponent).map_err(|e| e.to_string())?; // 独立な参照値
let provider = PowerLaw(fixed_exponent);
// 浮動小数点演算による誤差の下限より小さい許容誤差は到達できないので、ちょうど n 項を足した段の値を読める。
let unreachable = ErrorTolerance::scalar(1.0e-20, 0.0, NormSelection::Infinity)
    .map_err(|e| e.to_string())?;
let terms = Budget::try_from(explicit_terms as usize).map_err(|e| e.to_string())?;
let (mut rows, mut actual, mut bound) = (Vec::new(), Vec::new(), Vec::new());
for p in 1..=12_usize {
    let options = SeriesOptions::default()
        .with_max_terms(terms)
        .with_order(Budget::try_from(p).map_err(|e| e.to_string())?)
        .with_tolerance(unreachable.clone());
    let plan = SeriesSummation::<f64>::new(SeriesMethod::EulerMaclaurin, 1, options)
        .map_err(|e| e.to_string())?;
    let result = plan
        .sum(SeriesProblem::EulerMaclaurin(&provider))
        .map_err(|e| e.to_string())?;
    let error = result.error();
    let reported = error.provider().ok_or("プロバイダーの誤差がない")?
        + error.tail_bound().ok_or("剰余の上界がない")?
        + error.roundoff();
    let gap = (result.value() - exact).abs();
    // 実誤差が厳密に 0 の次数は対数軸に描けないので、図からだけ除く。
    if gap > 0.0 {
        actual.push([p as f64, gap]);
    }
    bound.push([p as f64, reported]);
    rows.push((
        p,
        gap,
        reported,
        result.report().termination().to_string(),
    ));
}
let (marker, dashed) = (
    serde_json::json!({ "showSymbol": true }),
    serde_json::json!({ "lineType": "dashed" }),
);
let optimum = std::f64::consts::PI * explicit_terms - 0.5 * fixed_exponent;
emit_line_chart!(
    &vec![
        serde_json::json!({ "name": "|推定値 − ζ(s)|", "points": actual, "style": marker }),
        serde_json::json!({ "name": "示された条件付きの上界", "points": bound, "style": dashed }),
    ],
    options = &serde_json::json!({
        "xLabel": "補正次数 p [-]",
        "yLabel": "誤差 [-]",
        "yType": "log",
        "xMin": 1,
        "xMax": 12,
        "annotations": [{ "kind": "line", "axis": "x", "value": optimum, "label": "p = πn − s/2" }]
    })
);
let columns = serde_json::json!([
    { "key": "0", "label": "補正次数 p [-]", "type": "integer" },
    { "key": "1", "label": "実誤差 [-]", "type": "number", "format": sci3 },
    { "key": "2", "label": "条件付きの上界 [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "終了状態" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "orders" })
);
```

既定値（$n = 1$、$s = 2$）では、実誤差は $p = 2$ の $1.16 \times 10^{-2}$、上界は $p = 3$ の $2.38 \times 10^{-2}$ で最小になり、$p = 12$ では実誤差が $8.1 \times 10^4$ まで増える。
最初のセルで $p = 12$ のとき 1 項目の段が $\zeta(2)$ から大きくずれたのは、この増え方による。
$n = 2$ では実誤差と上界がどちらも $p = 6$ で最小（$1.54 \times 10^{-5}$ と $3.09 \times 10^{-5}$）になり、$\pi n - s/2 \approx 5.3$ に近い。
$n = 4$ では最小の位置が $p = 12$ より先にあり、実誤差は $p = 12$ の $3.8 \times 10^{-11}$ まで減り続ける。
どの次数でも上界は実誤差を上回り、示された上界は漸近級数の発散も含めて誤差を押さえている。
$s = 6$ では上昇階乗 $(s)_{2j-1}$ が大きいので、$n = 1$ の実誤差は $p = 1$ で最小になる。

## まとめ

項が滑らかな関数の標本で、尾部の積分と奇数階の導関数を解析的に与えられるなら、Euler–Maclaurin 和が剰余の上界を返し、`BoundedTailReached` で止まる。
この上界は、利用者が `EulerMaclaurinProvider` で与えた値と誤差の上界、滑らかさと減衰の仮定が正しいときだけ成り立つ。
Euler–Maclaurin 展開は漸近級数なので、明示的に足す項数 $n$ を固定して補正次数 $p$ を上げても誤差はある次数（$x^{-s}$ では $\pi n - s/2$ 程度）から増え、高い $p$ を使うには $n$ を大きくとる。
許容誤差は浮動小数点演算による誤差の下限（各加数の $64\varepsilon$ 倍の和）より大きく選び、到達できないときの `TermLimit` は推定値として扱う。
