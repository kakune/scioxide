端点で発散する被積分関数と無限区間の積分は、Gauss 型求積や等間隔の Newton–Cotes 公式の収束を遅くする。
このページは変数変換で端点の特異性と無限区間を急減衰に変える二重指数変換と、内部の既知の特異点の扱いを説明する。

| 問題 | Plan | 方法 |
|---|---|---|
| 端点の代数的・対数的特異性、半無限区間、全実数直線 | `DoubleExponentialIntegrator` | tanh–sinh、exp–sinh、sinh–sinh 変換と入れ子の台形和 |
| 位置の分かっている内部特異点 | `DoubleExponentialDomain::Finite` の `singular_points` | 区分ごとの tanh–sinh |
| 跳びや折れなど滑らかでない内部の点 | `WeightedQuadraturePlan::breakpoints` | 分割点つきの適応 G7K15 |

振動する被積分関数と半直線の Fourier 積分は[振動積分の相殺と Fourier 積分の尾部](../fourier-integrals-and-tails/)、端点重みと Cauchy 主値は[端点重み・主値・複素経路の重み付き求積](../weighted-rules-and-sensitivities/)で扱う。
手法の選び方は[数値積分の選び方](../../choosing/)にまとめた。

## 二重指数変換の考え方

積分 $I = \int_a^b f(x)\,dx$ に変数変換 $x = \phi(t)$ を施し、実数直線全体の積分

$$
I = \int_{-\infty}^{\infty} f(\phi(t))\,\phi'(t)\,dt = \int_{-\infty}^{\infty} g(t)\,dt
$$

に書き換える。
二重指数（double exponential, DE）変換は、$g(t)$ が $|t| \to \infty$ で

$$
|g(t)| = O\bigl(\exp(-c\,e^{|t|})\bigr) \qquad (c > 0)
$$

のように指数関数の指数関数の速さで減衰するように $\phi$ を選ぶ。
この性質を二重指数的な減衰と呼ぶ。

減衰した $g$ には刻み $h$ の台形則

$$
I_h = h \sum_{k=-\infty}^{\infty} g(kh)
$$

を使う。
$g$ が帯状領域 $|\operatorname{Im} t| < d$ で正則で、その領域で可積分であると仮定すると、台形則の離散化誤差は

$$
|I - I_h| = O\bigl(\exp(-2\pi d / h)\bigr)
$$

となる。
実際には無限和を $|t| \le T$ で打ち切るので、打ち切り誤差 $|g(T)|$ も加わる。
二重指数的な減衰では $T$ は $\log(1/h)$ 程度で足り、標本数を $N$ とすると誤差は $\exp(-cN/\log N)$ の速さで減る。
この収束は、$f$ が開区間の近傍で解析的であれば、端点に代数的・対数的な特異性があっても成り立つ。
端点の特異性は $\phi'(t)$ の二重指数的な減衰に吸収されるからである。

| 積分領域 | 変換 $x = \phi(t)$ | Jacobian $\phi'(t)$ | 主な対象 |
|---|---|---|---|
| 有限区間 $[a, b]$（tanh–sinh） | $\frac{a+b}{2} + \frac{b-a}{2}\tanh\bigl(\frac{\pi}{2}\sinh t\bigr)$ | $\frac{b-a}{2}\cdot\frac{\frac{\pi}{2}\cosh t}{\cosh^2(\frac{\pi}{2}\sinh t)}$ | 端点の $(x-a)^{-\alpha}$、$\log(b-x)$ など |
| 半直線 $[a, \infty)$（exp–sinh） | $a + \exp\bigl(\frac{\pi}{2}\sinh t\bigr)$ | $\frac{\pi}{2}\cosh t\,\exp\bigl(\frac{\pi}{2}\sinh t\bigr)$ | 代数的・指数的に減衰する関数 |
| 実数直線（sinh–sinh） | $\sinh\bigl(\frac{\pi}{2}\sinh t\bigr)$ | $\frac{\pi}{2}\cosh t\,\cosh\bigl(\frac{\pi}{2}\sinh t\bigr)$ | 両側で減衰する関数 |

DE 変換は被積分関数が振動しながらゆっくり減衰する場合には向かない。
exp–sinh の節点は遠方で疎になり、振動の符号を追えないからである。
その場合は[振動積分の相殺と Fourier 積分の尾部](../fourier-integrals-and-tails/)の方法を使う。

## 入れ子の台形和と尾部の打ち切り

`DoubleExponentialIntegrator::new(domain, LevelOptions)` は節点と重みを一度だけ準備する。
最初の段は $t$ の刻み $h = 1$ で、段ごとに $h$ を半分にし、新しく加わる奇数番目の点だけを評価する。
段数 $L$ は `LevelOptions` の `with_max_levels` で 4〜15 の範囲で指定し、既定は 15（最も細かい刻みは $2^{-14}$）である。
許容誤差の既定は絶対・相対とも $\sqrt{\varepsilon}$（`f64` で約 $1.49 \times 10^{-8}$）、最大値ノルムである。

和は $|t| \le 8$ まで、または変換が飽和する位置で打ち切る。
両側の尾部は $t$ の幅 1 の追加区間（shell）$k \le |t| < k+1$ ごとに外へ広げ、直近 3 つの追加区間の寄与が減少するまで続ける。
尾部の推定は最後の追加区間の寄与を $1 - r$ で割った値で、$r$ は直近 2 つの追加区間の比の大きい方である。
これは観測した減衰を幾何級数として延長した経験的な推定であり、未標本の位置にある峰は検出できない。

準備する節点は高々 $8 \cdot 2^{L-1} + 1$ 個で、`f64` と 15 段では約 4 MiB になる。
呼び出しのたびに $t$ の超越関数を評価することはなく、複製した Plan は節点の表を共有する。

ワンショット関数 `integrate_unbounded(f, domain)` は scioxide-core の `ExtendedInterval` で無限区間を受け取り、既定の `LevelOptions` で一度だけ積分する。
$[a,\infty)$ は exp–sinh 変換、$(-\infty,b]$ は $x=-t$ と反転した $[-b,\infty)$ の exp–sinh 変換、実数直線は sinh–sinh 変換を使い、被積分関数は座標 $x$ だけを受け取る。
許容誤差は絶対・相対とも $\sqrt{\varepsilon}$、段数は 15 で、どちらも変えられない。
成功したときだけ値と誤差の推定を `Integral` で返し、成功しなかった終了状態はエラーに変える（`Stagnation` なら `ConvergenceFailure` の `Stagnation`）。
呼び出しごとに節点の表を作るので、何度も積分する場合は `DoubleExponentialIntegrator` を作り置く。
有限区間と空の区間は評価の前に `InvalidInput` で拒み、有限区間は `integrate` に渡す。

次のセルは Lorentz 型の関数 $f(x)=1/(1+x^2)$ を 3 種類の無限区間で積分する。
閉じた形は $\int_a^\infty f\,dx=\pi/2-\arctan a$、$\int_{-\infty}^a f\,dx=\pi/2+\arctan a$、$\int_{-\infty}^{\infty} f\,dx=\pi$ である。
$f$ は $x^{-2}$ でしか減衰しないが、exp–sinh 変換の Jacobian が二重指数的に減衰する。
入力は有限の端点 $a$ で、$x$ と積分値は無次元である。
各行で `integrate_unbounded` と、同じ変換と既定の `LevelOptions` で作った Plan の値を並べ、両者の差、閉じた形との差、誤差推定、Plan の評価回数と終了状態を示す。
$(-\infty,a]$ の Plan は、ワンショット関数と同じく $x=-t$ で反転した $[-a,\infty)$ の半直線で作る。
参照値の $\arctan$ は f64 の標準関数で計算する。

```rust
//| id: integrate-unbounded-one-shot
//| ref: integrate-unbounded-one-shot
//| title: ワンショット呼び出しの integrate_unbounded と DE の Plan を 3 種類の無限区間で比べる
//| run: reactive
//| crates: [scioxide-core, scioxide-integrate]
//| inputs:
//|   endpoint: {"type":"range","label":"有限の端点 a [-]","description":"半直線 [a, ∞) と (−∞, a] の端点を動かす。","min":-5,"max":5,"step":0.5,"value":1}
//| cases:
//|   - {"id":"far-left","label":"a = −5","description":"[a, ∞) が質量のほとんどを含み、(−∞, a] は小さな裾だけになる。","inputs":{"endpoint":-5}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"domains","path":"/rows/0/3","range":{"min":0,"max":1e-15}}
//|       - {"artifact":"domains","path":"/rows/0/4","range":{"min":0,"max":1e-12}}
//|       - {"artifact":"domains","path":"/rows/2/4","range":{"min":0,"max":1e-12}}
//|       - {"artifact":"domains","path":"/rows/2/7","equals":"HeuristicToleranceReached"}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: far-left
//|     expect:
//|       - {"artifact":"domains","path":"/rows/1/4","range":{"min":0,"max":1e-12}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
use core::f64::consts::{FRAC_PI_2, PI};
use scioxide_core::{ExtendedInterval, RealScalar};
use scioxide_integrate::DoubleExponentialDomain::{HalfLine, RealLine};
use scioxide_integrate::{
    DoubleExponentialIntegrator, DoubleExponentialPoint, LevelOptions, integrate_unbounded,
};

let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let digits15 = serde_json::json!({ "significantDigits": 15 });
let a = endpoint;
let lorentz = |x: f64| Ok(1.0 / (1.0 + RealScalar::powi(x, 2)));
let mut rows = Vec::new();
let mut unsuccessful = Vec::new();
let mut last_status = String::new();
for name in ["[a, ∞)", "(−∞, a]", "(−∞, ∞)"] {
    // (ワンショット呼び出しの端点, Plan の領域, x = −t で反転するか)。
    let (ends, domain, reflect) = match name {
        "[a, ∞)" => ((Some(a), None), HalfLine { lower: a }, false),
        "(−∞, a]" => ((None, Some(a)), HalfLine { lower: -a }, true),
        _ => ((None, None), RealLine, false),
    };
    // 閉じた形（参照値の atan は f64 の標準関数）。
    let exact = match name {
        "[a, ∞)" => FRAC_PI_2 - a.atan(),
        "(−∞, a]" => FRAC_PI_2 + a.atan(),
        _ => PI,
    };
    // 既定値（許容誤差 √ε、15 段）だけを使うワンショット呼び出し。
    let set = ExtendedInterval::new(ends.0, ends.1).map_err(|e| e.to_string())?;
    let one_shot = integrate_unbounded(lorentz, set).map_err(|e| e.to_string())?;
    // 同じ変換と既定の LevelOptions で作り置く Plan。被積分関数は DoubleExponentialPoint を受け取る。
    let plan = DoubleExponentialIntegrator::new(domain, LevelOptions::default())
        .map_err(|e| e.to_string())?;
    let point = |p: DoubleExponentialPoint<f64>| {
        let t = p.coordinate();
        lorentz(if reflect { -t } else { t })
    };
    let (value, report) = plan.integrate(&point).map_err(|e| e.to_string())?;
    last_status = report.termination().to_string();
    if !report.is_success() {
        unsuccessful.push(last_status.clone());
    }
    rows.push((
        name,
        one_shot.value(),
        value,
        (one_shot.value() - value).abs(),
        (one_shot.value() - exact).abs(),
        one_shot.error_estimate(),
        report.evaluations(),
        report.termination().to_string(),
    ));
}
let columns = serde_json::json!([
    { "key": "0", "label": "積分区間" },
    { "key": "1", "label": "integrate_unbounded の値 [-]", "type": "number", "format": digits15 },
    { "key": "2", "label": "Plan の値 [-]", "type": "number", "format": digits15 },
    { "key": "3", "label": "両者の差 [-]", "type": "number", "format": sci2 },
    { "key": "4", "label": "閉じた形との差 [-]", "type": "number", "format": sci2 },
    { "key": "5", "label": "ワンショット呼び出しの誤差推定 [-]", "type": "number", "format": sci2 },
    { "key": "6", "label": "Plan の評価回数 [回]", "type": "integer" },
    { "key": "7", "label": "Plan の終了状態" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "domains" })
);

// 結論: 3 つの区間の Plan がすべて成功したか。ワンショット呼び出しは成功しなければエラーを返す。
let outcome = match unsuccessful.first() {
    None => Outcome::satisfied("3 つの区間で Plan が成功し、ワンショット呼び出しも値を返した")
        .status(last_status)
        .explanation("誤差推定は観測した減衰に基づく経験的な値で、上界ではない。"),
    Some(status) => {
        Outcome::partial("許容誤差を満たす前に止まった Plan がある").status(status.clone())
    }
};
emit_outcome!(outcome.diagnostic("成功しなかった Plan", unsuccessful.len() as f64, None));
```

既定値 $a=1$ では、3 つの区間すべてで `integrate_unbounded` と Plan の値がビット単位で一致し、閉じた形との差は $5 \times 10^{-16}$ 以下だった。
Plan の評価回数は $[1,\infty)$ と実数直線で 81 回、$(-\infty,1]$ で 145 回である。
$a=-5$ にすると、$[a,\infty)$ の評価回数は 1041 回に増えた。
exp–sinh 変換では $dx/dt=\frac{\pi}{2}\cosh t\,(x-a)$ なので、端点から 5 離れた $x=0$ の付近では $t$ の幅 1 が $x$ の幅およそ 11 に当たり、幅 1 程度の山を解像するには細かい段まで進む必要がある。
ワンショット呼び出しは評価回数を返さないので、この計算コストの差は Plan でしか確かめられない。

## 浮動小数点での端点の飽和

標準区間 $[-1, 1]$ の tanh–sinh 変換では、端点までの距離は

$$
1 - \tanh\bigl(\tfrac{\pi}{2}\sinh t\bigr) = \frac{2e^{-\pi\sinh t}}{1 + e^{-\pi\sinh t}}
$$

である。
これは `f64` の 1 の近くの間隔 $2^{-53}$ を $t \approx 3.2$ で下回り、座標 $x$ は端点そのものに丸められる。
一方、区間幅に対する距離の比 $e^{-\pi\sinh t}/(1+e^{-\pi\sinh t})$ 自体は正規化数の範囲に入る限り表せる。
`f64` では $e^{-\pi\sinh t}$ が最小の正規化数を下回る $t \approx 6.1$ まで距離が表せ、Plan はそこで変換が飽和したとみなして節点の表を終える。
飽和は $|t| = 8$ より前に起こるので、`f64` の有限区間では飽和が打ち切りを決める。

そのため被積分関数は `DoubleExponentialPoint` を受け取る。
`coordinate()` は丸めた座標 $x$ を返し、端点と等しくなることがある。
`nearest_endpoint()` は最も近い有限の端点と、丸めた座標を引かずに計算した正の距離の組を返す。
有限区間では、端点はいま評価している区分の両端（内部の特異点を含む）で、区分の中点では下端を返す。
半直線では下端、実数直線では `None` を返す。

端点の特異因子はこの距離で評価する。
丸めた座標から `1.0 - x` を作ると、$t \approx 3.2$ より外側で 0 になり、距離の情報が失われる。

## 誤差推定と終了状態

成分ごとの誤差推定は

$$
E = \max\bigl(4\,|Q_h - Q_{2h}|,\; 50\,\varepsilon A\bigr) + T
$$

である。
$Q_h$ は刻み $h$ の和、$A$ は $|f|$ の標本から作った和（絶対質量）、$T$ は尾部の推定である。
最初の項は段間の差を、2 番目の項は丸め誤差の下限を表す。
どちらも上界ではなく、$T$ は観測した減衰に基づく経験的な値である。

終了状態は次のとおりである。

- `HeuristicToleranceReached` は第 3 段以降で $E$ が許容誤差を満たし、すべての尾部が打ち切られ、0 でない標本があり、$4\,|Q_h - Q_{2h}|$ が $A$ の 4 分の 1 以下のときに返る。
  DE 積分が `ToleranceReached` を返すことはなく、収束したときの状態はこれだけである。
- `Stagnation` は第 3 段以降で丸め誤差による精度の限界を超える段間の差が 3 回続けて 4 倍未満しか縮まない場合、値が変わらなくなった場合、差が誤差の下限に達した場合に返る。
  格子をそれ以上細かくできない場合と、尾部が減衰しない場合もこの状態になる。
- `RefinementLimit` はすべての段を使い切ったときに返る。
- `BudgetLimit` と `ExecutionStopped` は評価回数の上限、取り消し、期限で次の段や尾部の延長を止めたときに返る。
- `DegenerateDomain` は幅 0 の有限区間で、値は厳密に 0 で被積分関数は呼ばれない。

すべての標本で 0 になる被積分関数は成功しない。
格子の外に質量がある関数と区別できないからである。
4 番目の条件は格子より狭い山の裾だけを標本にした場合に、絶対許容誤差だけで成功とするのを防ぐ。

誤差の内訳は `DoubleExponentialWorkspace::component_errors()` が成分ごとの `IntegrationErrorComponents` で返す。
`discretization` は段間の差の 4 倍、`roundoff` は丸め誤差による精度の限界、`tail` は尾部の推定（`ErrorReliability::Heuristic`）である。
`tail_diagnostics()` は `TailDiagnostics` を返し、`extent()` は評価した最大の $|t|$、`shells()` は完了した追加区間の数、`status()` は `TailStatus` である。
`FourierTailPlan` も同じ型で尾部の診断を返すが、`extent()` と `shells()` の意味は異なる（[終了状態と尾部の診断](oxref:integrate-fourier-tail-diagnostics)）。

| `TailStatus` | DE 積分での意味 |
|---|---|
| `HeuristicallyTruncated` | 連続する追加区間の寄与が無視できるほど小さく、和を打ち切った |
| `Open` | 打ち切りに必要な数の追加区間を完了していない |
| `Saturated` | 表せる節点がもうない、または追加区間の上限まで調べた |
| `Stagnated` | 許容誤差を超える追加区間の寄与が減らず、丸めた和も変わらない |

1 つの成分に複数の区分がある場合は、最も信頼できない区分の状態を `Stagnated`、`Saturated`、`Open`、`HeuristicallyTruncated` の優先順で返す。
値の成分が複数ある場合、`IntegrationReport::error_components()` は成分ごとの診断をまとめ、`Open`、`Stagnated`、`Saturated`、`HeuristicallyTruncated` の順に弱いとみなして最も弱い状態を残す。
`Stagnated` のときは尾部の推定が `None` になり、`total()` と `error_estimate()` も `None` になる。

## 端点特異性と tanh–sinh の変換座標

ベータ関数型の端点特異性を持つ積分

$$
I(\alpha) = \int_0^1 x^{-\alpha}\,(1 - x)^{-0.35}\,dx = B(1 - \alpha,\, 0.65)
$$

を tanh–sinh 変換で計算する。
入力は左端の特異指数 $\alpha$ で、$x$ と積分値は無次元である。
被積分関数は `nearest_endpoint()` の距離で特異因子を評価し、`integrate_into` の後に作業領域から尾部の診断を読む。
検算は `scioxide_special::beta` による Beta 関数の値である。

図は変換後の被積分関数 $g(t) = f(x(t))\,x'(t)$ である。
$f$ は $x \to 0$ で発散するが、$g$ は両側で急速に減衰する山になる。
図示用の $g(t)$ は f64 の標準関数（`sinh`、`tanh`、`cosh`、`powf`）で計算し、座標が端点に丸められる点は除いてその数を表に示す。

```rust
//| id: integrate-tanh-sinh-singularity
//| ref: integrate-tanh-sinh-singularity
//| title: 端点特異性の強さを動かして tanh–sinh 後の形を見る
//| run: reactive
//| crates: [scioxide-core, scioxide-integrate, scioxide-special]
//| inputs:
//|   singularity_power: {"type":"range","label":"左端の特異指数 α [-]","description":"x^(−α) の発散の強さを変える。","min":0.05,"max":0.95,"step":0.05,"value":0.55}
//| cases:
//|   - {"id":"strong-singularity","label":"α = 0.95","description":"g(t) の左の裾が広がって尾部を打ち切れず、Stagnation で止まる。","inputs":{"singularity_power":0.95}}
//|   - {"id":"weak-singularity","label":"α = 0.05","description":"弱い特異性では少ない段で成功する。","inputs":{"singularity_power":0.05}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/2","range":{"min":0,"max":1e-12}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: strong-singularity
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/2","range":{"min":0,"max":1e-9}}
//|       - {"artifact":"summary","path":"/rows/0/7","equals":"Stagnation"}
//|       - {"path":"/outputs/2/state","equals":"partial"}
//|   - case: weak-singularity
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/2","range":{"min":0,"max":1e-12}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
use scioxide_core::{ExecutionContext, Interval, RealScalar};
use scioxide_integrate::{
    DoubleExponentialDomain, DoubleExponentialIntegrator, DoubleExponentialPoint, LevelOptions,
};
use scioxide_special::beta;

let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let digits15 = serde_json::json!({ "significantDigits": 15 });
let fixed0 = serde_json::json!({ "fractionDigits": 0 });
let alpha = singularity_power;
let right_power = 0.35_f64;
// f(x) = x^(−α) (1 − x)^(−0.35)。端点に近い標本は、丸めた座標ではなく保持された端点距離を使う。
let function = |point: DoubleExponentialPoint<f64>| {
    let x = point.coordinate();
    let (left, right) = match point.nearest_endpoint() {
        Some((0.0, distance)) => (distance, 1.0 - x),
        Some((_, distance)) => (x, distance),
        None => (x, 1.0 - x),
    };
    Ok(RealScalar::powf(left, -alpha) * RealScalar::powf(right, -right_power))
};

let domain = DoubleExponentialDomain::Finite {
    interval: Interval::new(0.0_f64, 1.0).map_err(|e| e.to_string())?,
    singular_points: &[],
};
let integrator = DoubleExponentialIntegrator::new(domain, LevelOptions::default())
    .map_err(|e| e.to_string())?;
let mut workspace = integrator.workspace(1).map_err(|e| e.to_string())?;
let mut value = 0.0_f64;
let report = integrator
    .integrate_into(
        &function,
        &mut value,
        &mut workspace,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;
// 独立な参照値: B(1 − α, 0.65)。
let reference = beta(1.0 - alpha, 1.0 - right_power).map_err(|e| e.to_string())?;
let tail = workspace
    .component_errors()
    .and_then(|errors| errors[0].tail_diagnostics());

// 図示用の g(t) = f(x(t)) x'(t)（f64 の標準関数による参照計算）。
// x(t) が端点に丸められる点は描かず、その数を数える。
let mut curve = Vec::new();
let mut collapsed = 0_usize;
for index in 0..=160 {
    let t = -3.5 + 7.0 * index as f64 / 160.0;
    let u = std::f64::consts::FRAC_PI_2 * t.sinh();
    let x = 0.5 * (1.0 + u.tanh());
    let jacobian = 0.5 * std::f64::consts::FRAC_PI_2 * t.cosh() / u.cosh().powi(2);
    if x > 0.0 && x < 1.0 {
        curve.push([t, x.powf(-alpha) * (1.0 - x).powf(-right_power) * jacobian]);
    } else {
        collapsed += 1;
    }
}
emit_line_chart!(
    &vec![serde_json::json!({"name": "g(t) = f(x(t)) x′(t)", "points": curve})],
    options = &serde_json::json!({
        "xLabel": "変換座標 t [-]",
        "yLabel": "変換後の被積分関数 g(t) [-]",
        "xMin": -3.5,
        "xMax": 3.5
    })
);

let columns = serde_json::json!([
    { "key": "0", "label": "積分値 [-]", "type": "number", "format": digits15 },
    { "key": "1", "label": "B(1−α, 0.65) [-]", "type": "number", "format": digits15 },
    { "key": "2", "label": "実誤差 [-]", "type": "number", "format": sci2 },
    { "key": "3", "label": "誤差推定 [-]", "type": "number", "format": sci2, "nullText": "推定なし" },
    { "key": "4", "label": "尾部の到達 |t| [-]", "type": "number", "format": fixed0, "nullText": "なし" },
    { "key": "5", "label": "尾部の状態" },
    { "key": "6", "label": "評価回数 [回]", "type": "integer" },
    { "key": "7", "label": "終了状態" },
    { "key": "8", "label": "端点に丸めた描画点 [点]", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    vec![(
        value,
        reference,
        (value - reference).abs(),
        report.error_estimate(),
        tail.map(|t| t.extent()),
        tail.map_or("なし".to_string(), |t| format!("{:?}", t.status())),
        report.evaluations(),
        report.termination().to_string(),
        collapsed,
    )],
    metadata = serde_json::json!({ "id": "summary" })
);

let outcome = if report.is_success() {
    Outcome::satisfied("誤差推定が許容誤差を満たした")
} else {
    Outcome::partial("許容誤差を満たす前に止まった")
        .explanation("表の積分値は最後の段の推定値として扱う。")
};
let outcome = outcome
    .status(report.termination().to_string())
    .diagnostic("評価回数", report.evaluations() as f64, None)
    .diagnostic("実誤差", (value - reference).abs(), None);
emit_outcome!(match report.error_estimate() {
    Some(estimate) => outcome.diagnostic("誤差推定", estimate, None),
    None => outcome,
});
```

既定値（$\alpha = 0.55$）では 73 回の評価で `HeuristicToleranceReached` となり、Beta 関数との差は丸め誤差の程度だった。
誤差推定は $4 \times 10^{-14}$ 程度で、既定の許容誤差 $\sqrt{\varepsilon}$ を大きく下回る。
尾部は $|t| = 5$ までの追加区間で打ち切られ、状態は `HeuristicallyTruncated` である。
$\alpha = 0.05$ では 65 回の評価で成功し、尾部は $|t| = 4$ で打ち切られた。

$\alpha = 0.95$ では $x \to 0$ の近くで $g(t) \approx \exp\bigl(-(1-\alpha)\frac{\pi}{2}e^{|t|}\bigr)$ となり、左の裾の減衰が遅い。
尾部は $|t| < 7$ の 7 個の追加区間まで広げても打ち切りの条件を満たさず（`extent()` は 7、状態は `Open`）、Plan は 97 回の評価で `Stagnation` を返した。
`f64` で表せる節点は $|t| \approx 6.1$ までなので、最後の追加区間には途中までしか標本がない。
有限区間の細分した段では表せない節点を標本のない節点として扱うので、状態は `Saturated` ではなく `Open` になる。
値そのものは参照値と $2 \times 10^{-14}$ 程度で一致するが、誤差推定は $8 \times 10^{-5}$ で、Plan はこの精度を確かめられなかった。
outcome は `partial` になり、値は推定値として扱う。
特異指数が 1 に近い端点では、DE 変換でも特異性が十分に吸収されないので、[端点重み・主値・複素経路の重み付き求積](../weighted-rules-and-sensitivities/)の端点重みで特異因子を解析的に扱うほうがよい。

描画で除いた点は通常の tanh の式で座標を作ったときに端点へ丸められた点である。
求積は保持した距離で評価するので、この件数を求積の打ち切りと解釈しない。

## 内部の特異点と分割点

積分区間の内部 $c \in (a, b)$ に特異点や導関数の不連続点があると、全区間への tanh–sinh 変換では $c$ が変換座標の中ほどに残る。
そこで $g(t)$ の帯状領域での正則性が失われ、指数的な収束が成り立たなくなる。
位置の分かっている点は区間を分けてそれぞれの区分の端点にする。

`DoubleExponentialDomain::Finite { interval, singular_points }` は、特異点で分けた区分ごとに別の tanh–sinh 変換を使う。
節点は各区分の両端に集まり、`nearest_endpoint()` は区分の端点としての特異点までの距離を返す。
特異点は任意の順で与えてよく、重複と区間の端点に等しい点は区分を増やさない。
区間の外の点は `InvalidInput`、NaN や無限大は `NonFinite` になる。
許容誤差は区分の間で等分する。
$f$ が各区分の内部で解析的で、端点に代数的・対数的な特異性を持つ場合に向く。

`WeightedQuadraturePlan::breakpoints(interval, points, options)` は指定した分割点から適応求積を始める。
分割点で区切った区分を初期領域とし、誤差推定の最も大きい領域を二分しながら、各領域に 15 点の Gauss–Kronrod 則（G7K15）を使う。
Kronrod の節点は領域の内部にあるので、分割点と区間の端点で $f$ を評価することはない。
`with_extrapolation(true)` は二分の列を Wynn ε アルゴリズムで外挿し、区分の端点にある特異性の収束を速める。
外挿は既定で無効である。
収束したときの終了状態は `ToleranceReached` で、適応求積の誤差推定と終了状態は[埋め込み対と大域適応求積](../adaptive-quadrature/)と同じ規則に従う。
被積分関数の跳びや折れのように、特異性はないが滑らかでない点に向く。

ワンショット関数 `integrate_piecewise(f, a, b, &points)` は `breakpoints` の Plan を既定の `WeightedQuadratureOptions`（許容誤差 $\sqrt{\varepsilon}$、二分 50 回、外挿なし）で作り、1 回だけ積分する。
成功したときだけ値と誤差の推定を `Integral` で返し、評価回数と終了状態は返さない。
上限で止まると推定値の代わりにエラーを返すので、上限を変えたい場合や、`BudgetLimit` の推定値を受け取りたい場合は Plan を使う。

次のセルは、内部の点 $c$ で値が半分に跳ぶ関数 $f(x)=e^x$（$x<c$）、$f(x)=e^x/2$（$x\ge c$）を $[0,1]$ で積分する。
閉じた形は $(e^c-1)+(e-e^c)/2$ である。
`integrate_piecewise`、同じ分割の `breakpoints` の Plan、分割点を与えない `AdaptiveIntegrator`（G7K15、既定の設定）、`singular_points` に $c$ を与えた tanh–sinh 変換の 4 つを比べる。
入力は跳びの位置 $c$ で、$x$ と積分値は無次元である。
参照値の指数関数は f64 の標準関数で計算する。
ワンショット呼び出しの行は評価回数と終了状態を持たないので、空欄にする。
outcome は `breakpoints` の Plan の終了状態を示す。

```rust
//| id: integrate-piecewise-one-shot
//| ref: integrate-piecewise-one-shot
//| title: 内部の跳びを分割点で渡す 4 つの方法を比べる
//| run: reactive
//| crates: [scioxide-core, scioxide-integrate]
//| inputs:
//|   jump_point: {"type":"range","label":"跳びの位置 c [-]","description":"f が e^x から e^x/2 へ跳ぶ点を動かす。","min":0.1,"max":0.9,"step":0.05,"value":0.3}
//| cases:
//|   - {"id":"dyadic","label":"c = 0.5","description":"最初の二分の中点が跳びに一致し、分割点がなくても跳びが区間の端になる。","inputs":{"jump_point":0.5}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"methods","path":"/rows/0/2","range":{"min":0,"max":1e-8}}
//|       - {"artifact":"methods","path":"/rows/1/2","range":{"min":0,"max":1e-8}}
//|       - {"artifact":"methods","path":"/rows/1/5","equals":"ToleranceReached"}
//|       - {"artifact":"methods","path":"/rows/3/2","range":{"min":0,"max":1e-8}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: dyadic
//|     expect:
//|       - {"artifact":"methods","path":"/rows/2/2","range":{"min":0,"max":1e-8}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
use scioxide_core::{Interval, RealScalar};
use scioxide_integrate::{
    AdaptiveIntegrator, AdaptiveRule, DoubleExponentialDomain, DoubleExponentialIntegrator,
    DoubleExponentialPoint, LevelOptions, SubdivisionOptions, WeightedQuadratureOptions,
    WeightedQuadraturePlan, integrate_piecewise,
};

let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let digits15 = serde_json::json!({ "significantDigits": 15 });
let c = jump_point;
let interval = Interval::new(0.0_f64, 1.0).map_err(|e| e.to_string())?;
let f = |x: f64| Ok(RealScalar::exp(x) * if x < c { 1.0 } else { 0.5 });
// 閉じた形: (e^c − 1) + (e − e^c)/2（f64 の標準関数による参照値）。
let exact = (c.exp() - 1.0) + (1.0_f64.exp() - c.exp()) / 2.0;

// ワンショット呼び出し: breakpoints の Plan を既定の設定で 1 回だけ使う。
let one_shot = integrate_piecewise(f, 0.0, 1.0, &[c]).map_err(|e| e.to_string())?;
let options = WeightedQuadratureOptions::default();
let plan =
    WeightedQuadraturePlan::breakpoints(interval, &[c], options).map_err(|e| e.to_string())?;
let (piecewise, piecewise_report) = plan.integrate(f).map_err(|e| e.to_string())?;
let adaptive =
    AdaptiveIntegrator::new(AdaptiveRule::GaussKronrod, SubdivisionOptions::default())
        .map_err(|e| e.to_string())?;
let (plain, plain_report) = adaptive.integrate(f, interval).map_err(|e| e.to_string())?;
// DE は c を区分の端点にし、跳びの両側を別々の tanh–sinh 変換で積分する。
let domain = DoubleExponentialDomain::Finite {
    interval,
    singular_points: &[c],
};
let de = DoubleExponentialIntegrator::new(domain, LevelOptions::default())
    .map_err(|e| e.to_string())?;
let point = |p: DoubleExponentialPoint<f64>| f(p.coordinate());
let (de_value, de_report) = de.integrate(&point).map_err(|e| e.to_string())?;

let mut rows = vec![(
    "integrate_piecewise".to_string(),
    one_shot.value(),
    (one_shot.value() - exact).abs(),
    Some(one_shot.error_estimate()),
    None,
    None,
)];
for (name, value, report) in [
    ("breakpoints の Plan", piecewise, &piecewise_report),
    ("分割点なしの適応 G7K15", plain, &plain_report),
    ("tanh–sinh（singular_points）", de_value, &de_report),
] {
    rows.push((
        name.to_string(),
        value,
        (value - exact).abs(),
        report.error_estimate(),
        Some(report.evaluations()),
        Some(report.termination().to_string()),
    ));
}
let columns = serde_json::json!([
    { "key": "0", "label": "方法" },
    { "key": "1", "label": "積分値 [-]", "type": "number", "format": digits15 },
    { "key": "2", "label": "閉じた形との差 [-]", "type": "number", "format": sci2 },
    { "key": "3", "label": "誤差推定 [-]", "type": "number", "format": sci2, "nullText": "推定なし" },
    { "key": "4", "label": "評価回数 [回]", "type": "integer", "nullText": "返さない" },
    { "key": "5", "label": "終了状態", "nullText": "返さない" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "methods" })
);

let outcome = if piecewise_report.is_success() {
    Outcome::satisfied("分割点つきの Plan が許容誤差を満たした")
} else {
    Outcome::partial("分割点つきの Plan が許容誤差を満たす前に止まった")
};
emit_outcome!(
    outcome
        .status(piecewise_report.termination().to_string())
        .diagnostic("評価回数", piecewise_report.evaluations() as f64, None)
);
```

既定値 $c=0.3$ では、`integrate_piecewise` と `breakpoints` の Plan は同じ値を返し、Plan は 2 つの区分に G7K15 を 1 回ずつ当てた 30 回の評価で `ToleranceReached` になった。
閉じた形との差は $2 \times 10^{-16}$ である。
分割点を与えない `AdaptiveIntegrator` は、跳びを含む区間を二分し続けて 735 回の評価を使い、差は $1.4 \times 10^{-9}$ にとどまった。
tanh–sinh 変換は 106 回の評価で差 $3 \times 10^{-15}$ だった。
$c=0.5$ では最初の二分の中点が跳びに一致するので、分割点がなくても 45 回で同じ値になる。

## まとめ

端点の特異性と無限区間には `DoubleExponentialIntegrator` を使い、特異因子は `nearest_endpoint()` の距離で評価する。
丸めた座標から端点までの差を作り直すと、$t \approx 3.2$ より外側で距離の情報が失われる。
DE 積分の収束は `HeuristicToleranceReached` だけで、尾部の推定は経験的なので、`TailDiagnostics` の状態と独立な参照値で確かめる。
特異指数 $\alpha$ が 1 に近い端点では `Stagnation` になりやすく、そのときは端点重みで特異因子を解析的に扱う。
内部の既知の特異点は `singular_points` で区分の端点にし、跳びや折れには `WeightedQuadraturePlan::breakpoints` を使う。
既定の設定で 1 回だけ積分するなら `integrate_unbounded` と `integrate_piecewise` で足り、許容誤差を変える場合や、評価回数、終了状態、上限で止まったときの推定値が要る場合は Plan を使う。
