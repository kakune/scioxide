数値求積は関数空間上の定積分汎関数

$$
I[f] = \int_\Omega f(\boldsymbol{x})\,w(\boldsymbol{x})\,d\boldsymbol{x}
$$

を、有限個の節点 $\boldsymbol{x}_i \in \Omega$ と重み $w_i$ による有限和

$$
Q_n[f] = \sum_{i=1}^n w_i\,f(\boldsymbol{x}_i)
$$

で近似する。
$I$ と $Q_n$ はどちらも $f$ について線形なので、求積の誤差 $I[f]-Q_n[f]$ も線形汎関数になる。
節点と重みの決め方、厳密に積分できる多項式の次数、剰余の漸近的な振る舞い、評価点を局所的に増やす規則が手法の性質を決める。
このページは各アルゴリズムページに共通する記号と仕様をまとめる。

## 記号

| 記号 | 意味 |
|---|---|
| $f$ | 被積分関数。実数、複素数、またはそれらのベクトルを返す |
| $w(\boldsymbol x)$ | 被積分関数から分離した既知の重み関数（古典直交多項式の重み、端点特異性、振動因子など）。分離しない場合は $w\equiv1$ |
| $\boldsymbol x_i,\ w_i$ | 求積則の節点と重み |
| $n$ | 節点の数。1 回の適用での評価回数 |
| $\mu_0 = \int_\Omega w\,d\boldsymbol x$ | 重み関数の 0 次モーメント。$w\equiv1$ なら領域の測度 |
| $\Lambda_n = \sum_i \lvert w_i\rvert$ | 重みの絶対値和。関数値の誤差の増幅率 |
| $d$ | 積分の次元 |
| $\varepsilon$ | 計算に使うスカラー型の機械イプシロン（`f64` で $2^{-52}\approx2.2\times10^{-16}$） |
| $\varepsilon_{\mathrm{abs}},\ \varepsilon_{\mathrm{rel}}$ | 絶対許容誤差と相対許容誤差 |
| $E$ | 誤差推定。真の誤差 $\lvert I-Q\rvert$ の推定値で、上界ではない |

## 厳密次数と安定性

求積則の厳密次数は次数 $m$ 以下のすべての多項式 $p$ で $Q_n[p]=I[p]$ となる最大の $m$ である。
これは厳密な算術での性質で、浮動小数点では丸め誤差が加わる。
単体では全次数、球面では球面調和関数の次数で数える。
$f$ が次数 $m$ の多項式でよく近似できるほど、厳密次数 $m$ の則の誤差は小さい。

関数値に絶対誤差 $\delta_i$ があると、和の誤差は

$$
\Bigl|\sum_i w_i\,\delta_i\Bigr| \le \Lambda_n \max_i \lvert\delta_i\rvert
$$

で抑えられる。
すべての重みが正なら、定数関数 $1$ を厳密に積分する則では $\Lambda_n = \sum_i w_i = \mu_0$ になる。
$\mu_0$ が領域の測度に等しいのは $w\equiv1$ の場合だけで、たとえば重み $e^{-x^2}$ の Gauss–Hermite 則では $\mu_0=\sqrt\pi$ である。
`GaussianRulePlan::zeroth_moment()` はこの $\mu_0$ を返す。
負の重みを持つ則（高次の Newton–Cotes 則、Grundmann–Möller 則）では $\Lambda_n$ が $\mu_0$ を超え、関数値の誤差が増幅される。

## 4 種類の不確かさ

このクレートの結果に付く不確かさは、次の 4 種類を区別する。

- 誤差推定（`ErrorReliability::Estimated`）は、2 つの則の差（埋め込み対）、2 つの段の差（外挿）、丸め誤差のモデルから求めた推定である。
- 経験的な推定（`ErrorReliability::Heuristic`）は、観測した寄与の減り方（二重指数変換の尾部、Fourier 尾部の周期ごとの寄与など）から推した推定で、観測範囲の外の構造は分からない。
- 包含が保証された区間は積分値を確実に含む区間で、`scioxide-integrate` は返さない。
  `scioxide-validated` のワンショット関数 `scioxide_validated::integrate` と検証器 `QuadratureVerifier` が利用者の与えた区間拡張から作る。
- 統計的な不確かさは、Monte Carlo 法の標本の標準誤差と信頼区間で、被積分関数の分散が有限であることを仮定する。

無限級数の Euler–Maclaurin 和は、利用者が与えた尾部の積分と導関数の上界を仮定した剰余の上界を持つ。
これは仮定が正しい場合に限る上界で、仮定そのものは検証しない。

## 結果のレポート `IntegrationReport`

保存標本の Plan、級数、感度、VEGAS と MISER の学習を除く Plan は、値とともに `IntegrationReport` を返す。
Monte Carlo 法もこのレポートを返し、標準誤差は作業領域の `statistics()` で読む。
値は呼び出し側が渡した出力に書かれるか、所有値を返す API の `integrate` が値とレポートの組で返す。

| メソッド | 返す値 |
|---|---|
| `termination()` | 唯一の終了理由 `IntegrationTermination` |
| `is_success()` | `termination().is_success()` |
| `evaluations()` | 被積分関数の評価回数。反復積分では内側の積分の評価も含む |
| `subdivisions()` | 二分の回数。細分しない手法では 0 |
| `error_components()` | 誤差推定の内訳 `IntegrationErrorComponents`。埋め込み対のない固定則と Monte Carlo 法では `None` |
| `error_estimate()` | 内訳の合計 `total()` |

複素数やベクトルの値では、レポートに入る誤差の内訳は実成分ごとの最大値（包絡）である。
成分ごとの内訳はそのレポートを作った作業領域の `component_errors()` で読む。

## 終了理由 `IntegrationTermination`

終了理由は次の 11 種類で、`is_success()` が真になるのは最初の 5 種類である。
`Ok` の結果は必ず全領域を覆う推定値を持つ。
全領域の推定ができる前に止まった場合は、値の代わりに右端の列のエラーが返る。

| 終了理由 | 成功 | 意味 | 全領域の推定がない場合のエラー |
|---|---|---|---|
| `FixedRuleCompleted` | 成功 | 固定次数の則を 1 回適用した。許容誤差は調べていない | — |
| `ToleranceReached` | 成功 | 誤差推定が許容誤差を満たした | — |
| `HeuristicToleranceReached` | 成功 | 経験的な誤差推定（観測した尾部の減衰など）が許容誤差を満たした | — |
| `SampleBudgetCompleted` | 成功 | Monte Carlo 法が指定の数の標本を使い切った | — |
| `DegenerateDomain` | 成功 | 領域の測度が 0 で、結果は厳密に 0 | — |
| `BudgetLimit(kind)` | — | 次の作業単位が評価回数・二分の回数などの上限を超える | `ConvergenceFailure`（`Evaluation` なら `EvaluationLimit`、`Iteration` なら `IterationLimit`、他は `ResourceLimit(kind)`） |
| `ExecutionStopped(reason)` | — | 取り消しまたは期限 | `ExecutionStopped` |
| `RefinementLimit` | — | 最大の段数・項数に達した | `ConvergenceFailure`（`TruncationLimit`） |
| `Stagnation` | — | 浮動小数点で推定がこれ以上変わらない | `ConvergenceFailure`（`Stagnation`） |
| `ProbablyDivergent` | — | 外挿が発散か非常に遅い収束を示す | `ConvergenceFailure`（`Divergence`） |
| `GeometryFailure` | — | 次の細分に表現できる評価点がない | `NumericalInstability`（`Breakdown`） |

成功は手法が設定どおりに終わったことを意味し、真の誤差を抑えない。
他のレポート型の成功は別に定まる。

- `SeriesTermination::is_success()` は `BoundedTailReached`（Euler–Maclaurin の剰余の上界が許容誤差を満たした）、`ExactEmpty`、`HeuristicToleranceReached`（Levin u と Wynn ε の加速値が連続して一致した）で真になる。
  上界が付くのは `BoundedTailReached` だけである。
- `TrainingReport::is_success()`（VEGAS と MISER の学習）は、学習を最後まで実行したときに真になる。
- `SensitivityReport` は `is_success()` を持たないので、`report.termination().is_success()` で読む。

## 誤差推定の内訳

`ErrorEstimate` は非負の大きさ `magnitude()` と種類 `reliability()`（`ErrorReliability::Estimated` か `Heuristic`）の組である。
`IntegrationErrorComponents` は、各手法が推定した成分だけを埋め、推定しなかった成分を `None` にする。
`None` は「0 と分かった」ではなく「推定していない」を意味する。

| 成分 | 内容 | 主に埋める手法 |
|---|---|---|
| `discretization()` | 2 つの埋め込み則や 2 つの段の差 | 埋め込み対、適応法、外挿 |
| `roundoff()` | 和の丸め誤差の推定。これより小さい離散化誤差の推定は意味を持たない | 同上 |
| `inner()` | 反復積分の内側の積分の誤差を外側の則で重み付けしたもの | `IteratedDomainPlan` |
| `moments()` | 重み付き則の修正モーメントの誤差 | `WeightedQuadraturePlan`、`FourierTailPlan` |
| `extrapolation()` | 列の外挿の誤差 | `with_extrapolation`、`FourierTailPlan` |
| `tail()` | 打ち切った尾部の寄与の推定 | `DoubleExponentialIntegrator`、`FourierTailPlan` |
| `tail_diagnostics()` | 尾部の探索範囲と状態 `TailDiagnostics` | 同上 |

合計 `total()` は

$$
E = \max(\text{discretization},\ \text{roundoff}) + \text{inner} + \text{moments} + \text{extrapolation} + \text{tail}
$$

で、`discretization` 以外の欠けた成分は 0 として数える。
丸め誤差より小さい離散化誤差の推定は意味を持たないので、丸めの推定は足さずに最大をとる。
`discretization` がない場合、尾部の診断があるのに尾部の大きさがない場合、和が桁あふれする場合、`total()` は `None` を返す。
`TailDiagnostics` と `TailStatus` の詳細は、二重指数変換の尾部を[広義積分と端点特異性の二重指数変換](improper-singular-and-oscillatory/)で、Fourier 尾部を[振動積分の相殺と Fourier 積分の尾部](fourier-integrals-and-tails/)で扱う。

## Plan・作業領域・実行コンテキスト

Plan（`AdaptiveIntegrator`、`CubaturePlan` など）は、作成時に選択肢を一度だけ検査し、何度でも使える不変の値である。
作業領域は呼び出し側が所有するメモリで、同じ種類の Plan の呼び出しで再利用できる。
実行の手順は次のとおりである。

1. `plan.workspace_requirements(..)` で必要な大きさ `IntegrationRequirements` を得る。
2. `plan.workspace(..)` で作業領域を作るか、既存の作業領域に `check(&requirements)` と `try_reserve(&requirements)` を使う。
3. `plan.integrate_into(f, .., &mut out, &mut workspace, scope)` で計算する。
   `scope` には `ExecutionContext::sequential()` などの実行コンテキストか、計算回数の上限を持つ solve scope を渡す。

所有値を返す API の `integrate(f, ..)` は呼び出しごとに作業領域を作り、逐次に実行して値とレポートを返す。
被積分関数は値として渡し、同じクロージャを続けて使うときは `&f` を渡す。
既定の設定で一度だけ積分するワンショット関数（`integrate`、`integrate_box` など）は、Plan と作業領域をその場で作り、成功したときだけ値と誤差の推定を `Integral` で返す（[ワンショット関数と設定した Plan](oxref:integrate-choosing-one-shot)）。
十分な大きさの作業領域を使う `integrate_into` はメモリを確保しない。
エラーが返った場合、出力は変わらない。

`IntegrationRequirements::components()` は値の実成分の数（実数で 1、複素数で 2、ベクトルでは長さ）を返す。
作業領域は 1 つの成分数と、多次元の Plan では 1 つの次元に対応し、どちらかが違えば `check` は `Capacity::NeedsGrowth` を返す。
`try_reserve` は今の容量と要求の大きい方を保つので、1 つの作業領域で同じ種類の複数の Plan に使える。
別の種類の Plan の要求を渡すと `InvalidInput` になる。
`last_attempt()` は直前の呼び出しの記録（結果の分類、評価回数、レポート）を返す。

次の表は全作業領域の一覧である。
「検査と記録」は `check`・`try_reserve`・`last_attempt` を持つかを示す。

| 作業領域 | 作るメソッド | 大きさを決める量 | 検査と記録 | 成分ごとの結果 |
|---|---|---|---|---|
| `FixedRuleWorkspace` | `FixedRule::workspace(components)`（`GaussianRulePlan` の重み付き則も含む） | 節点数 $n$ と成分数 | あり | `component_errors()`（埋め込み対のある則だけ） |
| `RombergWorkspace` | `Romberg::workspace(components)` | 評価点のブロックと成分数。段数によらない | あり | `component_errors()` |
| `AdaptiveWorkspace` | `AdaptiveIntegrator::workspace(components)` | 二分の上限 $+1$ 個の領域と成分数。Simpson では領域ごとに 9 標本 | あり | `component_errors()` |
| `DoubleExponentialWorkspace` | `DoubleExponentialIntegrator::workspace(components)` | 特異点で分けた区間の数、評価点のブロック、成分数 | あり | `component_errors()`（`TailDiagnostics` を含む） |
| `WeightedQuadratureWorkspace` | `WeightedQuadraturePlan::workspace(components)`、`ContourPlan::workspace()`（2 成分） | 初期区間の数と二分の上限から決まる領域数、成分数 | あり | `component_errors()` |
| `FourierTailWorkspace` | `FourierTailPlan::workspace(components)` | 1 周期分の領域、周期数の上限、成分数 | あり | `component_errors()` |
| `OscillatoryWorkspace` | `OscillatoryQuadraturePlan::workspace(components)` | 宣言した領域の数と二分の上限、成分数。Levin では $25\times25$ の選点系 | あり | `component_errors()` |
| `SampledWorkspace` | 標本の Plan の `workspace(components)`、`cumulative_workspace(components)` | 出力の数 × 成分数 | なし | なし |
| `SampledAxisWorkspace` | 標本の Plan の `axis_workspace(shape, axis, components)`、`cumulative_axis_workspace(shape, axis, components)` | 軸方向の標本数、出力配列の値の数 × 成分数、配列の階数 | なし | なし |
| `SeriesWorkspace` | `SeriesSummation::workspace(width)` | 項の幅 × （次数 + 32）。最大項数によらない | あり（`SeriesRequirements`） | `component_errors()`（`SeriesError` の列） |
| `QuadratureSensitivityWorkspace` | `QuadratureSensitivityPlan::workspace()` | Plan の区間、方式、則の大きさ、次元（`SensitivityRequirements`） | あり | `value_errors()`、`derivative_errors()` |
| `ProductWorkspace` | `ProductRule::workspace((d, c))` | 節点数 $n$ と次元 $d$ と成分数 $c$ | あり | `component_errors()`（埋め込み対のある則だけ） |
| `CubatureWorkspace` | `CubaturePlan::workspace(components)` | 初期の領域数 + 二分の上限、次元、成分数 | あり | `component_errors()` |
| `IteratedWorkspace` | `IteratedDomainPlan::workspace(components)` | 軸ごとの領域数（分割片の数 + 二分の上限）× 次元 × 成分数 | あり | `component_errors()` |
| `GeometricWorkspace` | `SimplexRule`・`LebedevRule`・`SphereProductRule` の `workspace(components)` | 節点数、次元、成分数。単体では正確な向きの判定の項数 | あり | なし（`mapped_points()`、`mapped_weights()`） |
| `SparseGridWorkspace` | `SparseGridPlan::workspace(components)` | 指数集合の上限と評価回数の上限 × （次元 + 成分数） | あり | `component_errors()` |
| `MonteCarloWorkspace` | `MonteCarloIntegrator::workspace(components, execution)` | 複製または層の数、並列のワーカーの数、成分数 | あり | `statistics()`、`children()` |
| `VegasWorkspace` | `VegasTrainer::workspace(execution)` | 次元 × ビン数、ワーカーの数 | `last_attempt` だけ（`TrainingReport`） | なし |
| `MiserWorkspace` | `MiserTrainer::workspace(components, execution)` | 層の上限、次元、成分数、ワーカーの数 | `last_attempt` だけ（`TrainingReport`） | なし |

`component_errors()` は、直前の呼び出しが失敗した場合や、0 幅の区間などで推定がない場合に `None` を返す（`SeriesWorkspace` は常に列を返す）。

## ベクトル値と複素値の求積

求積則の重み $w_i$ は実数なので、$f$ が複素数やベクトルを返しても、各成分に同じ節点と重みを使える。

$$
Q_n[\boldsymbol f] = \Bigl(\sum_i w_i f_1(x_i),\ \dots,\ \sum_i w_i f_m(x_i)\Bigr).
$$

被積分関数の値には `scioxide-core` の `AffineValue` を実装する型（実数、`Complex<S>`、`Vec<V>`、`[V; N]`）を使え、`integrate_into` の出力にはスライス `[V]` も使える。
所有値を返す API の `integrate` とワンショット関数は `Copy` な値（実数、複素数、固定長の配列）に限るので、長さが実行時に決まるベクトル値は `integrate_into` に `Vec` かスライスの出力を渡す。
複素数は実部と虚部の 2 つの実成分として扱い、作業領域は実成分の数で作る（複素数なら `workspace(2)`）。
許容誤差は成分ごとに正規化した誤差を `ErrorTolerance` のノルムで束ねて判定する。
被積分関数が NaN や無限大を返すと、`NonFinite`（発生元はコールバック）のエラーになる。

固定則は `FixedRule` トレイトで表す。
`map_nodes_into(interval, &mut nodes)` は区間に写した節点と重みを `FixedRuleNode` の列に書き、被積分関数は評価しない。
`FixedRuleNode` は節点 `point()`、主の則の重み `primary_weight()`、埋め込み則の重み `embedded_weight()`（埋め込み対のない則では `None`）を持ち、`FixedRuleNode::new(point, primary_weight, embedded_weight)` で作れる。
`integrate_into` は全節点を写して検査してから被積分関数を呼び、重み付き和を補償加算（丸め誤差を別に保持して足し戻す加算）で求める。
途中の積や和がスカラー型の範囲を超える場合は、指数の範囲を広げた表現に移して計算を続ける。
補償加算は丸め誤差を大きく減らすが、厳密な和や 1 回だけの丸めを保証するものではない。

次のセルは複素数値の被積分関数 $f(x)=e^{i\kappa x}$ を $[0,1]$ で Gauss–Kronrod 則により積分する。
厳密値は

$$
\int_0^1 e^{i\kappa x}\,dx = \frac{\sin\kappa}{\kappa} + i\,\frac{1-\cos\kappa}{\kappa}
$$

である。
入力は波数 $\kappa$ と Gauss–Kronrod 対の種類で、作業領域は G7K15 用に作ってから選んだ対の要求で `check` と `try_reserve` を行う。
出力は成分ごとの誤差推定と実際の誤差の表、レポートと重みの絶対値和 $\Lambda_n$ の表、終了理由の判定である。
確かめる点は、成分ごとの推定が実際の誤差を上回るか、レポートの推定が成分の最大になっているか、$\Lambda_n$ が区間の長さ 1 に等しいかである。

```rust
//| id: integrate-affine-complex-moments
//| ref: integrate-affine-complex-moments
//| title: 複素数値の被積分関数を Gauss–Kronrod 則で成分ごとに積分する
//| run: reactive
//| crates: [scioxide-core, scioxide-integrate]
//| inputs:
//|   wave_number: {"type":"range","label":"波数 κ [-]","description":"[0, 1] での振動の回数 κ/(2π) を変える。","min":1,"max":60,"step":1,"value":20}
//|   pair: {"type":"select","label":"Gauss–Kronrod 対","description":"点数が多いほど厳密次数が上がる。","options":["G7K15","G10K21","G15K31","G20K41","G25K51"],"value":"G7K15"}
//| cases:
//|   - {"id":"larger-pair","label":"G15K31","description":"31 点の対では κ = 20 の振動を解像し、誤差が丸めの水準まで下がる。","inputs":{"pair":"G15K31"}}
//|   - {"id":"fast-oscillation","label":"κ = 60","description":"15 点では振動を解像できず、推定と実際の誤差がともに大きい。","inputs":{"wave_number":60}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"components","path":"/rows/0/2","range":{"min":1e-10,"max":1e-8}}
//|       - {"artifact":"components","path":"/rows/0/3","range":{"min":0.1,"max":1}}
//|       - {"artifact":"report","path":"/rows/0/3","approx":{"value":1.0,"rtol":1e-14}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: larger-pair
//|     expect:
//|       - {"artifact":"components","path":"/rows/0/2","range":{"min":0,"max":1e-14}}
//|       - {"artifact":"report","path":"/rows/0/1","equals":31}
//|   - case: fast-oscillation
//|     expect:
//|       - {"artifact":"components","path":"/rows/0/2","range":{"min":1e-3,"max":1}}
//|       - {"artifact":"components","path":"/rows/1/2","range":{"min":1e-3,"max":1}}
use scioxide_core::{Complex, ExecutionContext, Interval, RealScalar};
use scioxide_integrate::{FixedRule, FixedRuleNode, GaussKronrod, GaussKronrodRule};

let kappa = wave_number;
let selected = match pair.as_str() {
    "G10K21" => GaussKronrodRule::G10K21,
    "G15K31" => GaussKronrodRule::G15K31,
    "G20K41" => GaussKronrodRule::G20K41,
    "G25K51" => GaussKronrodRule::G25K51,
    _ => GaussKronrodRule::G7K15,
};
let interval = Interval::new(0.0, 1.0).map_err(|e| e.to_string())?;

// 作業領域は 15 点・2 実成分（複素数）で作り、選んだ対の要求に合わせて広げる。
let mut workspace = GaussKronrod::<f64>::new(GaussKronrodRule::G7K15)
    .map_err(|e| e.to_string())?
    .workspace(2)
    .map_err(|e| e.to_string())?;
let rule = GaussKronrod::new(selected).map_err(|e| e.to_string())?;
let requirements = rule.workspace_requirements(2).map_err(|e| e.to_string())?;
let capacity = workspace.check(&requirements).map_err(|e| e.to_string())?;
workspace
    .try_reserve(&requirements)
    .map_err(|e| e.to_string())?;

// f(x) = e^{iκx} = cos κx + i sin κx。SciOxide の関数は RealScalar 経由で呼ぶ。
let integrand = |x: f64| {
    Ok(Complex::new(
        RealScalar::cos(kappa * x),
        RealScalar::sin(kappa * x),
    ))
};
let mut output = Complex::new(0.0_f64, 0.0);
let report = rule
    .integrate_into(
        &integrand,
        interval,
        &mut output,
        &mut workspace,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;

// 参照値（f64 の標準関数による閉形式）。
let exact = [kappa.sin() / kappa, (1.0 - kappa.cos()) / kappa];
let computed = [output.re, output.im];
let errors = workspace
    .component_errors()
    .ok_or("成分ごとの誤差推定がない")?;
let sig15 = serde_json::json!({ "significantDigits": 15 });
let sig16 = serde_json::json!({ "significantDigits": 16 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let component_columns = serde_json::json!([
    { "key": "0", "label": "成分" },
    { "key": "1", "label": "積分値 [-]", "type": "number", "format": sig15 },
    { "key": "2", "label": "実際の誤差 [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "離散化の推定 [-]", "type": "number", "format": sci3, "nullText": "未推定" },
    { "key": "4", "label": "丸め誤差による精度の限界 [-]", "type": "number", "format": sci3, "nullText": "未推定" },
    { "key": "5", "label": "合計 total() [-]", "type": "number", "format": sci3, "nullText": "未定義" }
]);
let rows: Vec<_> = ["実部", "虚部"]
    .into_iter()
    .zip(computed.iter().zip(&exact))
    .zip(errors)
    .map(|((name, (&value, &reference)), parts)| {
        (
            name,
            value,
            (value - reference).abs(),
            parts.discretization().map(|estimate| estimate.magnitude()),
            parts.roundoff(),
            parts.total(),
        )
    })
    .collect();
emit_table_with_columns!(
    component_columns,
    rows,
    metadata = serde_json::json!({ "id": "components" })
);

// 区間に写した節点と重みから Λ = Σ|w_i| を求める。重みは正なので区間の長さ 1 に等しい。
let mut nodes = vec![FixedRuleNode::new(0.0, 0.0, None); rule.node_count()];
rule.map_nodes_into(interval, &mut nodes)
    .map_err(|e| e.to_string())?;
let lebesgue: f64 = nodes.iter().map(|node| node.primary_weight().abs()).sum();
let report_columns = serde_json::json!([
    { "key": "0", "label": "広げる前の容量" },
    { "key": "1", "label": "評価回数 [回]", "type": "integer" },
    { "key": "2", "label": "レポートの誤差推定 [-]", "type": "number", "format": sci3, "nullText": "未定義" },
    { "key": "3", "label": "Λ = Σ|w_i| [-]", "type": "number", "format": sig16 },
    { "key": "4", "label": "終了理由" }
]);
emit_table_with_columns!(
    report_columns,
    vec![(
        format!("{capacity:?}"),
        report.evaluations(),
        report.error_estimate(),
        lebesgue,
        report.termination().to_string(),
    )],
    metadata = serde_json::json!({ "id": "report" })
);

// 固定則の適用は FixedRuleCompleted で終わる。許容誤差は調べていない。
let mut outcome = Outcome::satisfied("固定則を 1 回適用した")
    .explanation("精度の主張はないので、表の誤差推定と閉形式との差で読む。")
    .status(report.termination().to_string())
    .diagnostic("評価回数", report.evaluations() as f64, None);
if let Some(estimate) = report.error_estimate() {
    outcome = outcome.diagnostic("誤差推定", estimate, None);
}
emit_outcome!(outcome);
```

既定値（$\kappa=20$、G7K15）では、15 回の評価で実部・虚部の実際の誤差はそれぞれ $1.3\times10^{-9}$ と $8.3\times10^{-10}$ だったが、離散化の推定は $0.61$ と $0.64$ だった。
G7K15 の推定は 7 点 Gauss 値と 15 点 Kronrod 値の差から作るので、7 点では解像できない振動があると、15 点の値がずっと正確でも推定は大きく出る（この式は[埋め込み対と大域適応求積](adaptive-quadrature/)で扱う）。
レポートの誤差推定 $0.64$ は 2 成分の大きい方で、成分ごとの内訳は作業領域から読む必要がある。
G15K31 を選ぶと作業領域の容量は `NeedsGrowth` と判定されて広がり、31 回の評価で実際の誤差は $2\times10^{-16}$ 以下、推定は $10^{-14}$ 程度になった。
このとき虚部の合計 $7.1\times10^{-15}$ は離散化の推定 $5.5\times10^{-15}$ ではなく丸め誤差による精度の限界に等しく、`total()` が両者の最大をとることが分かる。
$\kappa=60$ では 15 点の則は振動を解像できず、実際の誤差は $0.07$ と $0.43$、推定は $0.41$ と $0.62$ だった。
どの場合も $\Lambda_n$ は 1 で、正の重みの則では関数値の誤差が増幅されないことを確かめられる。

## まとめ

求積の結果は値、唯一の終了理由、誤差推定の内訳の組として解釈する。
成功は手法が設定どおりに終わったことを意味し、積分と級数のどちらでも `HeuristicToleranceReached` を含む。
誤差推定の合計は $\max(\text{discretization},\text{roundoff})$ に他の成分を足したもので、どの成分も上界ではない。
Plan は不変で、作業領域は呼び出し側が所有し、`check` と `try_reserve` で別の Plan にも使える。
複素数やベクトルの値は実成分ごとに同じ則で積分され、成分ごとの推定は作業領域の `component_errors()` で読む。
