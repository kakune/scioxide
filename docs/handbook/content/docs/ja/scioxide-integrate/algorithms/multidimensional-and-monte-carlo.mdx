熱源の全出力、確率の期待値、波動関数の行列要素のように、多くの量は直方体上の多重積分

$$
I[f] = \int_B f(\boldsymbol x)\,d\boldsymbol x, \qquad B = [a_1, b_1] \times \cdots \times [a_d, b_d]
$$

で表される。
1 次元の求積則は各軸に拡張できるが、決定論的な規則の評価回数は次元 $d$ とともに急に増える。
一方、乱数で点を置く Monte Carlo 法の標準誤差は次元によらず $N^{-1/2}$ で減る。
どの次元から Monte Carlo 法が有利になるかは、被積分関数の滑らかさと求める精度で決まり、一つの閾値はない。
滑らかな関数を高い精度で求めるなら決定論的な規則が 5〜10 次元程度まで有利なことが多く、不連続な関数や 2〜3 桁の精度で足りる場合は低い次元でも Monte Carlo 法が有利になる。

このページは直方体上の決定論的な二つの方法、すなわち各軸に同じ固定則を使うテンソル積則と、誤差の大きい部分直方体を細分する Genz–Malik の適応 cubature を扱う。
一様 Monte Carlo 法の推定量と統計は[Monte Carlo 積分の推定量と統計](../monte-carlo-integration/)、直方体でない領域は[可変端点の反復積分と座標写像](../domains-and-geometric-rules/)と[単体と球面の求積則](../simplex-and-sphere-rules/)、滑らかで中程度の次元の積分は[疎格子と乱択準 Monte Carlo](../sparse-grids-and-qmc/)で扱う。
方法の選び方は[数値積分の選び方](../../choosing/)にまとめた。

## テンソル積則と評価回数

1 次元の固定則（節点 $x_i$ と重み $w_i$、$i = 1, \dots, n$）を各軸 $[a_k, b_k]$ へ写したものを $x_{k,i}$、$w_{k,i}$ と書く。
Fubini の定理で多重積分を軸ごとの積分の繰り返しに直し、各軸を同じ則で近似すると、テンソル積則

$$
Q[f] = \sum_{i_1=1}^{n} \cdots \sum_{i_d=1}^{n} w_{1,i_1} \cdots w_{d,i_d}\, f(x_{1,i_1}, \dots, x_{d,i_d})
$$

を得る。
1 次元則が次数 $p$ までの多項式を厳密に積分するなら、テンソル積則は各変数の次数が $p$ 以下の単項式 $x_1^{k_1} \cdots x_d^{k_d}$（$k_j \le p$）を厳密に積分する。

評価回数は $N = n^d$ である。
$n = 10$ なら $d = 3$ で 1000 点だが、$d = 6$ で $10^6$ 点、$d = 8$ で $10^8$ 点になる。
誤差を評価回数で書くと、この増え方の意味が分かる。
各軸で $r$ 階の導関数が有界な関数に $n$ 点の Gauss 型則を使うと、各軸の誤差は $O(n^{-r})$ 程度で、合計の誤差も同じ大きさである。
$n = N^{1/d}$ を代入すると誤差は $O(N^{-r/d})$ となり、同じ評価回数で得られる精度が次元とともに下がる。
これを次元の呪いと呼ぶ。

`ProductRule::new(rule, ProductOptions)` は、一つの固定則 `rule`（[`FixedRule`](oxref:integrate-vector-valued-quadrature) を実装する Gauss–Legendre 則や Gauss–Kronrod 対など）をすべての軸に使うテンソル積則である。
軸ごとに別の則を選ぶ機能はない。
節点は行優先の順、すなわち最後の軸が最も速く変わる順に評価する。
則が Gauss–Kronrod 対のように埋め込み重みを持つなら、主の重みと埋め込み重みによる二つのテンソル和の差を誤差推定とし、丸め誤差による精度の限界 $50\varepsilon\sum|w f|$ を下限に置く。
埋め込み重みがなければ誤差推定はない。
終了状態は `FixedRuleCompleted` で、幅 0 の軸があれば評価なしで 0 と `DegenerateDomain` を返す。

`ProductOptions` は 1 回の呼び出しの評価回数の上限（既定はなし）と実行方針を持つ。
$n^d$ が上限を超える呼び出しは、評価の前に `ConvergenceFailure` で失敗する。
`plan.workspace((d, c))` は次元 $d$ と実数成分数 $c$ の `ProductWorkspace` を作り、写した節点と 64 点分の評価点を $O(nd + 64(d+c))$ のメモリに持つ。
同じ次元・成分数で節点数がそれ以下の則なら同じ作業領域を使え、`integrate_into` は確保を行わない。
`component_errors()` は埋め込み重みを持つ則の最後の成功した呼び出しの成分ごとの誤差を返す。

## Genz–Malik 適応 cubature

全域に一様な格子を敷く代わりに、誤差の大きい部分直方体だけを細分すれば、局所的なピークや境界層に評価を集められる。
`CubaturePlan::new(&bounds, SubdivisionOptions)` は、$d = 1$ では [G7K15 の大域適応求積](../adaptive-quadrature/)（分割点がなければ `AdaptiveIntegrator` と同じ値・誤差・評価回数）を使い、$d \ge 2$ では Genz–Malik の 7 次則と埋め込みの 5 次則の対を同じ優先度付きの細分で使う。

### 節点の配置と評価回数

Genz–Malik 則は、中心 $\boldsymbol c$、各軸の半幅 $h_j$ の部分直方体を参照立方体 $[-1, 1]^d$ に写し、対称な 4 種類の点で評価する。
生成元は $\lambda_2 = \sqrt{9/70}$、$\lambda_3 = \sqrt{9/10}$、$\lambda_5 = \sqrt{9/19}$ である。

- 中心 1 点。
- 各軸上の $\pm\lambda_2$ と $\pm\lambda_3$ の $4d$ 点。
- 2 軸の座標が $\pm\lambda_3$ の $2d(d-1)$ 点。
- すべての座標が $\pm\lambda_5$ の頂点方向の $2^d$ 点。

1 領域の評価回数は

$$
n(d) = 2^d + 2d(d-1) + 4d + 1
$$

で、$d = 2, 3, 4, 5$ で 17、33、57、93 点になる。
7 次則はこのすべての点を使い、5 次則は頂点方向を除いた点を使う。
二つの則は同じ評価値を共有するので、誤差推定のための追加の評価はない。
1 回の分割は二つの子を最初から評価し、$2n(d)$ 回かかる。
$2^d$ の項が大きい次元で支配するので、この方法は $d \lesssim 10$ が実用の範囲である。

### 分割軸を選ぶ 4 階差分

分割する軸は各軸に沿った 4 階差分

$$
D_j = \Bigl| f(\boldsymbol c + \lambda_2 h_j \boldsymbol e_j) + f(\boldsymbol c - \lambda_2 h_j \boldsymbol e_j) - 2f(\boldsymbol c)
- \frac{\lambda_2^2}{\lambda_3^2}\bigl(f(\boldsymbol c + \lambda_3 h_j \boldsymbol e_j) + f(\boldsymbol c - \lambda_3 h_j \boldsymbol e_j) - 2f(\boldsymbol c)\bigr) \Bigr|
$$

で選ぶ（$\boldsymbol e_j$ は軸 $j$ の単位ベクトル）。
$g(t) = f(\boldsymbol c + t h_j \boldsymbol e_j)$ と置くと、Taylor 展開から

$$
g(\lambda) + g(-\lambda) - 2g(0) = \lambda^2 g''(0) + \frac{\lambda^4}{12} g^{(4)}(0) + O(\lambda^6)
$$

である。
係数 $\lambda_2^2/\lambda_3^2 = 1/7$ を掛けた差をとると 2 階導関数の項が消え、

$$
D_j \approx \frac{\lambda_2^2(\lambda_3^2 - \lambda_2^2)}{12}\,\bigl|g^{(4)}(0)\bigr|
$$

が残る。
5 次則は 5 次以下の多項式を厳密に積分するので、7 次則と 5 次則の差は Taylor 展開の 6 次以上の項から生じる。
2 階の項を消した $D_j$ は、軸 $j$ に沿った高次の変化の大きさを測り、その変化の大きい軸を示す。
$D_j$ が最大の軸で、領域を中点で二つの合同な部分直方体に分ける。
差が埋め込み誤差の $10^{-d}$ 倍や丸めの大きさより小さい同点の軸では、幅の最も広い軸を選び、領域の形が細長くなりすぎないようにする。
軸の評価は誤差推定に使った点の値の再利用で、追加の評価はない。

### 誤差推定と終了

体積 $V$ の領域の誤差推定は 7 次則と 5 次則の推定値の差の 4 倍

$$
E = 4\,|Q_7 - Q_5|
$$

である。
分割の後は、各子の誤差推定を、自身の $4|Q_7 - Q_5|$ と、分割による値の変化の 4 倍 $4|Q_{\text{左}} + Q_{\text{右}} - Q_{\text{親}}|$ の半分のうち大きい方にする。
二つの子を合わせると、分割で値が動いた量の 4 倍以上の誤差が残る。
どちらの推定も丸め誤差による精度の限界 $50\varepsilon V \sum|w_7| \max|f|$ を下回らない（$w_7$ は体積 1 の領域での 7 次則の重み、$\max|f|$ はその領域で評価した値の最大の大きさ）。

全体の誤差推定は領域の誤差推定の和で、[`SubdivisionOptions`](oxref:integrate-adaptive-options-workspace) の許容誤差 $E \le \varepsilon_{\mathrm{abs}} + \varepsilon_{\mathrm{rel}}|Q|$ を満たすまで、誤差の最も大きい領域を分割する。
4 倍の係数は 1 次元の適応求積と同じ経験的な安全率で、誤差の上界を証明しない。
そのため $d \ge 2$ の誤差推定は `ErrorReliability::Heuristic` として示され、許容誤差に達した終了は `ToleranceReached` ではなく `HeuristicToleranceReached` になる。
$d = 1$ の G7K15 は `ToleranceReached` を返す。

丸め誤差による精度の限界は各領域の 7 次則の値の大きさの $50\varepsilon\sum|w_7|$ 倍以上である。
そのため全体の誤差推定は積分の推定値の大きさの $50\varepsilon\sum|w_7|$ 倍を下回らない。
許容誤差がこの下限より小さいと、細分を続けても達成できない。
この場合、誤差の最も大きい領域の分割が 2 回続けて値を子の領域の誤差の下限以内でしか変えなかった時点で、細分をやめて `Stagnation` を返す。
節点が区別できないほど細い領域を分割しようとしたときも `Stagnation` で止まる。

評価回数と分割回数の上限は呼び出しごとに数える。
初期領域（分割点で切った部分直方体）をすべて測る前に上限、取り消し、期限で止まると、全体の推定値がないので `ConvergenceFailure` または `ExecutionStopped` のエラーを返す。
その後に止まった場合は、全体の推定値と誤差推定を `BudgetLimit` または `ExecutionStopped` の終了状態とともに返す。
1 回の分割は二つの子を合わせた一つの単位として評価の前に許可されるので、分割の途中で止まることはない。
幅 0 の軸を持つ直方体は評価なしで厳密な 0 と `DegenerateDomain` を返す。

`plan.workspace(components)` が返す `CubatureWorkspace` は、初期領域数 $k$ と分割回数の上限 $m$ から最大 $r = k + m$ 個の領域を、成分数を $c$ として $O(r(d + c))$ のメモリに持ち、`integrate_into` は確保を行わない。
`component_errors()` は最後の成功した呼び出しの成分ごとの誤差を返す。
`plan.integrate(f)` は作業領域を確保して逐次に実行する簡易形である。
既定の設定で一度だけ積分するワンショット関数 `integrate_box` は、[ワンショット呼び出しの integrate_box](#ワンショット呼び出しの-integrate_box)で扱う。
既知の折れ目や不連続の位置で初期領域を区切る `with_breakpoints` は、[直方体内の特徴位置の事前分割](oxref:integrate-box-breakpoints)で扱う。

## ピークの cubature とテンソル積則

単位立方体 $[0,1]^d$ の中の点 $\boldsymbol u$ に中心を持つ二種類のピーク

$$
f_{\mathrm G}(\boldsymbol x) = \exp\Bigl(-a^2 \sum_{j=1}^d (x_j - u_j)^2\Bigr), \qquad
f_{\mathrm K}(\boldsymbol x) = \exp\Bigl(-a \sum_{j=1}^d |x_j - u_j|\Bigr)
$$

を積分する。
$f_{\mathrm G}$ は解析的な Gauss 型のピーク、$f_{\mathrm K}$ は各座標面 $x_j = u_j$ に折れ目を持つピークで、$a$ はピークの鋭さ（幅はおよそ $1/a$）である。
厳密値は軸ごとの 1 次元積分の積

$$
I_{\mathrm G} = \prod_{j=1}^d \frac{\sqrt\pi}{2a}\bigl[\operatorname{erf}(a(1 - u_j)) + \operatorname{erf}(a u_j)\bigr], \qquad
I_{\mathrm K} = \prod_{j=1}^d \frac{2 - e^{-a u_j} - e^{-a(1-u_j)}}{a}
$$

である。
次の定義のブロックは、二つのセルが使う被積分関数 `peak` と厳密値 `exact_peak` を置く。
中心 $\boldsymbol u$ は `CENTERS` の先頭 $d$ 個で、対称性を避けるため軸ごとにずらしてある。
厳密値は SciOxide の `erf` と `exp` で求め、独立な参照値にする。

```rust
//| id: integrate-peak-integrands
//| kind: definitions
//| title: Gauss 型と折れ目のあるピークとその厳密値
//| crates: [scioxide-core, scioxide-special]
use scioxide_core::RealScalar;
use scioxide_special::erf;

// ピークの中心 u_j（d ≤ 5）。
pub(crate) const CENTERS: [f64; 5] = [0.37, 0.52, 0.61, 0.45, 0.29];

// Gauss 型は exp(−a² Σ (x_j − u_j)²)、折れ目のあるピークは exp(−a Σ |x_j − u_j|)。
pub(crate) fn peak(x: &[f64], a: f64, smooth: bool) -> f64 {
    let exponent: f64 = x
        .iter()
        .zip(CENTERS)
        .map(|(x, c)| {
            if smooth {
                a * a * (x - c) * (x - c)
            } else {
                a * (x - c).abs()
            }
        })
        .sum();
    RealScalar::exp(-exponent)
}

// 厳密値: 軸ごとの 1 次元積分の積。
pub(crate) fn exact_peak(d: usize, a: f64, smooth: bool) -> Result<f64, String> {
    let mut exact = 1.0;
    for &c in &CENTERS[..d] {
        exact *= if smooth {
            let sum = erf(a * (1.0 - c)).map_err(|e| e.to_string())?
                + erf(a * c).map_err(|e| e.to_string())?;
            RealScalar::sqrt(std::f64::consts::PI) / (2.0 * a) * sum
        } else {
            (2.0 - RealScalar::exp(-a * c) - RealScalar::exp(-a * (1.0 - c))) / a
        };
    }
    Ok(exact)
}
```

最初のセルは相対許容誤差 $10^{-2}$ から $10^{-6}$ までの `CubaturePlan` で積分する。
1 回の積分の評価回数の上限は $10^q$ 回（$q \le 5$）で、上限で止まった許容誤差より厳しい許容誤差は計算しない。

outcome は最も厳しい許容誤差での終了状態で、上限に達すると `BudgetLimit` の部分結果になる。

```rust
    let estimate = report.error_estimate();
    // 両対数のグラフには正の値だけを描く。
    estimated.extend(estimate.filter(|e| *e > 0.0).map(|e| [n as f64, e]));
    actual.extend(Some([n as f64, error]).filter(|_| error > 0.0));
    let status = report.termination().to_string();
    rows.push((tol, n, report.subdivisions(), estimate, error, status));
    let stopped = !report.is_success();
    last = Some((report, estimate));
    // 上限で止まったら、より厳しい許容誤差も同じ上限で止まるので計算しない。
    if stopped {
        break;
    }
}
let series = vec![
    serde_json::json!({ "name": "誤差推定", "points": estimated, "style": { "lineType": "dashed" } }),
    serde_json::json!({ "name": "厳密値との差", "points": actual, "style": { "showSymbol": true } }),
];
emit_line_chart!(
    &series,
    options = &serde_json::json!({
        "xLabel": "被積分関数の評価回数 [回]",
        "yLabel": "積分の誤差 [-]",
        "xType": "log",
        "yType": "log"
    })
);
let columns = serde_json::json!([
    { "key": "0", "label": "相対許容誤差 [-]", "type": "number", "format": sci3 },
    { "key": "1", "label": "評価回数 [回]", "type": "integer" },
    { "key": "2", "label": "分割回数 [回]", "type": "integer" },
    { "key": "3", "label": "誤差推定 [-]", "type": "number", "format": sci3, "nullText": "なし" },
    { "key": "4", "label": "厳密値との差 [-]", "type": "number", "format": sci3 },
    { "key": "5", "label": "終了状態" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "tolerances" })
);
let (report, estimate) = last.ok_or("許容誤差の列が空である")?;
let outcome = if report.is_success() {
    Outcome::satisfied("最も厳しい許容誤差に推定上で到達した")
        .explanation("誤差推定は経験的な安全率による推定で、上界ではない。")
} else {
    Outcome::partial("最も厳しい許容誤差に達する前に止まった")
        .explanation("表の最後の行の値は、その時点の推定値である。")
};
let evaluations = report.evaluations() as f64;
let mut outcome =
    outcome
        .status(report.termination().to_string())
        .diagnostic("評価回数", evaluations, None);
if let Some(estimate) = estimate {
    outcome = outcome.diagnostic("誤差推定", estimate, None);
}
emit_outcome!(outcome);
```

既定値（$d = 2$、$a = 10$、Gauss 型）では、許容誤差を $10^{-2}$ から $10^{-6}$ まで下げると、評価回数は約 1000 回から約 14000 回に増え、すべて `HeuristicToleranceReached` で終わる。
評価回数は初期領域の 17 回に分割 1 回あたり 34 回を足した値で、分割が二つの子を合わせた単位で数えられることを確かめられる。
誤差推定は実際の誤差より 2〜4 桁大きく、許容誤差を厳しくするたびに約 1 桁ずつ下がる。
推定が悲観的なのは、4 倍の安全率に加え、7 次則と 5 次則の差が主に 5 次則の誤差を表し、7 次則自身の誤差より大きいためである。
被積分関数を「折れ目のあるピーク」に替えると、折れ目の近くを細分して、24599 回で差 $2.5\times10^{-10}$ に達する。

$d = 3$ では許容誤差 $10^{-4}$ までに約 56000 回を使い、$10^{-5}$ の途中で上限 $10^5$ 回に達して `BudgetLimit(Evaluation)` で止まり、outcome は partial になる。
$d = 5$ では 1 領域が 93 点、1 回の分割が 186 回になり、最初の許容誤差 $10^{-2}$ の前に上限に達する。
どちらの場合も表の最後の行の値は全体の推定値で、誤差推定が付いている。

2 つ目のセルは同じピークを `ProductRule` のテンソル積則で積分する。
Gauss–Legendre 則（`GaussianRulePlan`、各軸 $n$ 点、$n^d$ 回）は埋め込み重みを持たないので誤差推定がなく、Gauss–Kronrod 対 G7K15（各軸 15 点）は主の和と埋め込みの和の差を誤差推定として返す。
G7K15 は `workspace((d, 1))` の `ProductWorkspace` を使って `integrate_into` で実行し、`component_errors()` で成分ごとの誤差を読む。
評価回数が $10^5$ を超える則は使わない。
グラフは Gauss–Legendre 則の誤差を評価回数に対して描き、表は則ごとの評価回数、厳密値との差、誤差推定を示す。

```rust
//| id: integrate-product-rule-peak
//| ref: integrate-product-rule-peak
//| title: 次元とピークの形を動かしてテンソル積則の誤差を各軸の点数で見る
//| run: reactive
//| uses: [integrate-peak-integrands]
//| crates: [scioxide-core, scioxide-integrate, scioxide-special]
//| inputs:
//|   dimension: {"type":"range","label":"次元 d [-]","description":"積分する立方体の次元。評価回数は n^d。","min":2,"max":5,"step":1,"value":2}
//|   sharpness: {"type":"range","label":"ピークの鋭さ a [-]","description":"ピークの幅はおよそ 1/a。","min":2,"max":20,"step":2,"value":10}
//|   integrand: {"type":"select","label":"被積分関数","description":"解析的な Gauss 型ピークか、各座標面に折れ目を持つピークかを選ぶ。","options":["Gauss 型ピーク","折れ目のあるピーク"],"value":"Gauss 型ピーク"}
//| cases:
//|   - {"id":"kink","label":"折れ目のあるピーク","description":"折れ目があると Gauss 則の誤差は点数を増やしても 10⁻⁴ 程度にとどまる。","inputs":{"integrand":"折れ目のあるピーク"}}
//|   - {"id":"four-dimensions","label":"d = 4","description":"同じ評価回数の上限で使える各軸の点数が 17 点以下に減る。","inputs":{"dimension":4}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"rules","path":"/rows/7/3","range":{"min":0,"max":1e-14}}
//|       - {"artifact":"rules","path":"/rows/8/2","equals":225}
//|       - {"artifact":"rules","path":"/rows/8/4","range":{"min":1e-6,"max":1}}
//|   - case: kink
//|     expect:
//|       - {"artifact":"rules","path":"/rows/7/3","range":{"min":1e-6,"max":1e-2}}
//|   - case: four-dimensions
//|     expect:
//|       - {"artifact":"rules","path":"/rows/6/2","equals":50625}
use scioxide_core::{ExecutionContext, Interval};
use scioxide_integrate::{
    GaussKronrod, GaussKronrodRule, GaussianRulePlan, ProductOptions, ProductRule,
};

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let (d, a) = (dimension.round() as usize, sharpness);
let smooth = integrand == "Gauss 型ピーク";
let f = |x: &[f64]| Ok(peak(x, a, smooth));
let exact = exact_peak(d, a, smooth)?;
let bounds = vec![Interval::new(0.0_f64, 1.0).map_err(|e| e.to_string())?; d];
let limit = 100_000_usize;
let (mut rows, mut curve) = (Vec::new(), Vec::new());
// Gauss–Legendre 則: 埋め込み重みがないので誤差推定は None。
for n in [2_usize, 4, 6, 8, 12, 16, 24, 32] {
    if n.pow(d as u32) > limit {
        break;
    }
    let rule = GaussianRulePlan::gauss_legendre(n).map_err(|e| e.to_string())?;
    let (value, report) = ProductRule::new(rule, ProductOptions::default())
        .integrate(&f, &bounds)
        .map_err(|e| e.to_string())?;
    let (evaluations, error) = (report.evaluations(), (value - exact).abs());
    curve.extend(Some([evaluations as f64, error]).filter(|_| error > 0.0));
    rows.push((
        "Gauss–Legendre",
        n,
        evaluations,
        error,
        report.error_estimate(),
    ));
}
// G7K15 の積: 15^d ≤ 10^5 のときだけ、作業領域を使って実行し誤差推定を読む。
if 15_usize.pow(d as u32) <= limit {
    let rule = GaussKronrod::new(GaussKronrodRule::G7K15).map_err(|e| e.to_string())?;
    let plan = ProductRule::new(rule, ProductOptions::default());
    let mut workspace = plan.workspace((d, 1)).map_err(|e| e.to_string())?;
    let (mut value, context) = (0.0_f64, ExecutionContext::sequential());
    let report = plan
        .integrate_into(&f, &bounds, &mut value, &mut workspace, context)
        .map_err(|e| e.to_string())?;
    let component = workspace
        .component_errors()
        .and_then(|e| e[0].discretization());
    let estimate = component.map(|e| e.magnitude());
    let error = (value - exact).abs();
    rows.push((
        "G7K15（Kronrod 15 点）",
        15,
        report.evaluations(),
        error,
        estimate,
    ));
}
let series = serde_json::json!({
    "name": "Gauss–Legendre テンソル積則",
    "points": curve,
    "style": { "showSymbol": true }
});
emit_line_chart!(
    &vec![series],
    options = &serde_json::json!({
        "xLabel": "被積分関数の評価回数 n^d [回]",
        "yLabel": "厳密値との差 [-]",
        "xType": "log",
        "yType": "log"
    })
);
let columns = serde_json::json!([
    { "key": "0", "label": "1 次元の則" },
    { "key": "1", "label": "各軸の点数 n", "type": "integer" },
    { "key": "2", "label": "評価回数 [回]", "type": "integer" },
    { "key": "3", "label": "厳密値との差 [-]", "type": "number", "format": sci3 },
    { "key": "4", "label": "誤差推定 [-]", "type": "number", "format": sci3, "nullText": "なし" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "rules" })
);
```

既定値（$d = 2$、Gauss 型）では、Gauss–Legendre テンソル積則の誤差は $n$ とともに指数的に減り、各軸 32 点（1024 回）で丸めの水準 $10^{-16}$ に達する。
同じ被積分関数で Genz–Malik 則が $6\times10^{-12}$ に約 14000 回を要したのと比べると、解析的な被積分関数の低い次元ではテンソル積の Gauss 則のほうが少ない評価で正確である。
G7K15 の積（225 回）の誤差推定 $1.3\times10^{-4}$ は実際の差 $1.8\times10^{-5}$ より大きく、埋め込みの Gauss 7 点則の積の誤差を表している。

「折れ目のあるピーク」では、Gauss–Legendre 則の誤差は 1024 回でも $4\times10^{-4}$ 程度にとどまり、点数とともに単調にも減らない。
折れ目は各軸の多項式近似の収束を遅くし、その位置に節点を集める仕組みがテンソル積則にはないからである。
同じ関数で Genz–Malik 則は 24599 回で $2.5\times10^{-10}$ に達しており、滑らかさの失われた位置に細分を集めることが適応 cubature の利点である。
$d = 4$ では評価回数 $10^5$ 以下で使える点数が各軸 16 点までになり、誤差は $5\times10^{-8}$ 程度にとどまる。

## ワンショット呼び出しの integrate_box

ワンショット関数 `integrate_box(f, &lower, &upper)` は、下端と上端の角の座標から直方体を作り、既定の `SubdivisionOptions` の `CubaturePlan` で積分する。
既定は絶対・相対とも $\sqrt\varepsilon \approx 1.5\times10^{-8}$ の許容誤差、分割 50 回、評価回数の上限なしで、作業領域を内部で確保し、`ExecutionContext::sequential_native()` で逐次に実行する。
戻り値は値と結合した誤差推定を持つ `Integral` で、レポートは返さない。
成功しなかった終了はエラーに変わるので、分割の上限で止まると、途中の推定値は得られない。
ほかのワンショット関数との対応は[ワンショット関数と設定した Plan](oxref:integrate-choosing-one-shot)にまとめてある。

次のセルは Gauss 型ピークを `integrate_box` と、同じ既定値の `CubaturePlan`、分割の上限を $10^4$ 回に上げた `CubaturePlan` で積分する。
Plan の行は `plan.integrate(f)` のレポートから評価回数と終了状態を示し、`integrate_box` の行は成功なら値と誤差推定、失敗ならエラーの分類を示す。

```rust
//| id: integrate-box-one-shot
//| ref: integrate-box-one-shot
//| title: ピークの鋭さを動かしてワンショット呼び出しの integrate_box と Plan を比べる
//| run: reactive
//| uses: [integrate-peak-integrands]
//| crates: [scioxide-core, scioxide-integrate, scioxide-special]
//| inputs:
//|   dimension: {"type":"range","label":"次元 d [-]","description":"積分する立方体の次元。","min":2,"max":3,"step":1,"value":2}
//|   sharpness: {"type":"range","label":"ピークの鋭さ a [-]","description":"Gauss 型ピークの幅はおよそ 1/a。","min":1,"max":10,"step":1,"value":1}
//| cases:
//|   - {"id":"sharper-peak","label":"a = 4","description":"既定の分割 50 回では許容誤差に届かず、integrate_box はエラーを返す。","inputs":{"sharpness":4}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"one-shot","path":"/rows/0/5","equals":"成功"}
//|       - {"artifact":"one-shot","path":"/rows/0/2","range":{"min":0,"max":1e-12}}
//|       - {"artifact":"one-shot","path":"/rows/1/4","equals":1377}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: sharper-peak
//|     expect:
//|       - {"artifact":"one-shot","path":"/rows/0/5","equals":"ConvergenceFailure"}
//|       - {"artifact":"one-shot","path":"/rows/1/5","equals":"BudgetLimit(Subdivision)"}
//|       - {"artifact":"one-shot","path":"/rows/2/5","equals":"HeuristicToleranceReached"}
//|       - {"path":"/outputs/1/state","equals":"failed"}
use scioxide_core::{Budget, Interval};
use scioxide_integrate::{CubaturePlan, SubdivisionOptions, integrate_box};

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let sig12 = serde_json::json!({ "significantDigits": 12 });
let (d, a) = (dimension.round() as usize, sharpness);
let f = |x: &[f64]| Ok(peak(x, a, true));
let exact = exact_peak(d, a, true)?;
let (lower, upper) = (vec![0.0_f64; d], vec![1.0_f64; d]);
// ワンショット呼び出し: 既定の SubdivisionOptions。成功しない終了はエラーになる。
let mut rows = vec![match integrate_box(&f, &lower, &upper) {
    Ok(r) => {
        let error = Some((r.value() - exact).abs());
        (
            "integrate_box",
            Some(r.value()),
            error,
            Some(r.error_estimate()),
            None,
            "成功".into(),
        )
    }
    Err(e) => (
        "integrate_box",
        None,
        None,
        None,
        None,
        format!("{:?}", e.kind()),
    ),
}];
// 同じ既定値の Plan と、分割の上限だけを上げた Plan。止まってもレポートと推定値が返る。
let bounds = vec![Interval::new(0.0_f64, 1.0).map_err(|e| e.to_string())?; d];
for (name, limit) in [
    ("CubaturePlan（分割 50 回）", 50),
    ("CubaturePlan（分割 10⁴ 回）", 10_000),
] {
    let budget = Budget::try_from(limit).map_err(|e| e.to_string())?;
    let options = SubdivisionOptions::default().with_max_subdivisions(budget);
    let plan = CubaturePlan::new(&bounds, options).map_err(|e| e.to_string())?;
    let (value, report) = plan.integrate(&f).map_err(|e| e.to_string())?;
    let error = Some((value - exact).abs());
    let status = report.termination().to_string();
    let evaluations = Some(report.evaluations());
    rows.push((
        name,
        Some(value),
        error,
        report.error_estimate(),
        evaluations,
        status,
    ));
}
let columns = serde_json::json!([
    { "key": "0", "label": "呼び出し" },
    { "key": "1", "label": "積分値 [-]", "type": "number", "format": sig12, "nullText": "なし" },
    { "key": "2", "label": "厳密値との差 [-]", "type": "number", "format": sci3, "nullText": "なし" },
    { "key": "3", "label": "誤差推定 [-]", "type": "number", "format": sci3, "nullText": "なし" },
    { "key": "4", "label": "評価回数 [回]", "type": "integer", "nullText": "レポートなし" },
    { "key": "5", "label": "終了状態またはエラー" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "one-shot" })
);
// ワンショット呼び出しの成否を結論にし、同じ既定値の Plan の終了状態を添える。
let (status, evaluations) = (rows[1].5.clone(), rows[1].4.unwrap_or(0) as f64);
let outcome = if rows[0].1.is_some() {
    Outcome::satisfied("integrate_box が既定の設定で成功した")
        .explanation("誤差推定は経験的な推定で、上界ではない。")
} else {
    Outcome::failed("integrate_box は推定値を返さなかった")
        .explanation("同じ既定値の Plan は分割の上限で止まり、その時点の推定値を返す。")
};
emit_outcome!(
    outcome
        .status(status)
        .diagnostic("既定の Plan の評価回数", evaluations, None)
);
```

既定値（$d = 2$、$a = 1$）では、`integrate_box` が成功し、厳密値との差は $4\times10^{-16}$、誤差推定は $2.7\times10^{-8}$ である。
同じ既定値の Plan は同じ値を 1377 回の評価（分割 40 回）と `HeuristicToleranceReached` で返し、分割の上限を上げても変わらない。
ピークを $a = 4$ に鋭くすると、既定の Plan は 1717 回（分割 50 回）で `BudgetLimit(Subdivision)` に止まり、`integrate_box` は `ConvergenceFailure` のエラーを返す。
止まった Plan の推定値は厳密値との差 $8.1\times10^{-9}$ で十分正確だが、誤差推定 $7.2\times10^{-6}$ が許容誤差 $\sqrt\varepsilon\,(1 + |Q|) \approx 1.8\times10^{-8}$ を上回るので、成功と判定されない。
分割の上限を $10^4$ 回に上げた Plan は 12665 回で許容誤差に達する。
既定の許容誤差と分割 50 回で足りる低い次元の滑らかな積分ならワンショット呼び出しで十分で、上限で止まった推定値を使いたいとき、許容誤差や上限を変えたいとき、評価回数を読みたいときは `CubaturePlan` を使う。

## まとめ

直方体上の滑らかな積分では、各軸に同じ固定則を使う `ProductRule` の評価回数が $n^d$、誤差が $O(N^{-r/d})$ となり、次元とともに効率が下がるが、解析的な被積分関数の低い次元では Gauss 型の則の指数的な収束が最も効率がよい。
`CubaturePlan` は $d \ge 2$ で 1 領域 $2^d + 2d(d-1) + 4d + 1$ 点の Genz–Malik 7/5 次則を使い、4 階差分の大きい軸で領域を二分して、折れ目やピークのような局所的な変化に評価を集める。
その誤差推定は 7 次と 5 次の差の 4 倍による経験的な推定で、成功は `HeuristicToleranceReached` と示されるので、実際の誤差は既知の値や許容誤差を変えた比較で確かめる。
評価回数の上限で止まった場合も全体の推定値と誤差推定が返るので、終了状態を読んで部分結果として扱う。
ワンショット呼び出しの `integrate_box` は既定の許容誤差 $\sqrt\varepsilon$ と分割 50 回で積分し、届かなければ推定値を返さずにエラーにするので、上限を変えるときや途中の推定値が要るときは `CubaturePlan` を使う。
