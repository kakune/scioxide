`scioxide-integrate` は 1 次元の固定則・適応則・変数変換、重み付きの積分と振動積分、標本データの積分、無限級数の和、多次元の決定論的な求積、Monte Carlo 法、積分のパラメータ感度を `f32` と `f64` で提供する。
被積分関数の値は実数、複素数、ベクトルのどれでもよい。
このガイドは目的から API の項目を示し、公開されている 133 項目を用途別の表にまとめる。
このページの表はすべての手法に共通する結果の型と設定の 10 項目を載せ、手法ごとの 123 項目は子ページの表に分けた。
表の項目名のリンクは、docs.rs の 0.1.0 の API リファレンスを指す。

## 用途別の API

既定の設定で値だけが必要なら、ワンショット関数 `scioxide_integrate::integrate`、`integrate_piecewise`、`integrate_fourier`、`integrate_unbounded`、`integrate_box`、`integrate_iterated`、`integrate_monte_carlo`、`trapezoid`、`simpson`、`cumulative_trapezoid`、`sum_series` から始める。
問題ごとの対応と既定の手法は[ワンショット関数と設定した Plan](oxref:integrate-choosing-one-shot)にまとめた。
次の表は、手法と設定を選んで呼ぶときに使う型と関数である。

原始関数を式で求める記号積分はどのクレートも提供しない。

## 型の関係

ワンショット関数は既定の設定の Plan と作業領域をその場で作って逐次に実行し、成功したときだけ答えを返す。
`integrate`、`integrate_piecewise`、`integrate_fourier`、`integrate_unbounded`、`integrate_box`、`integrate_iterated` の答えは値と誤差の推定の組 `Integral` である。
`integrate_monte_carlo` は `MonteCarloStatistics`、`sum_series` は `SeriesResult` を返し、`trapezoid`・`simpson` は値、`cumulative_trapezoid` は値の `Vec` だけを返す。

Plan（`AdaptiveIntegrator`、`CubaturePlan` など）は節点、幾何、許容誤差、上限、実行の方針を作成時に一度だけ検査して保持する不変の値で、何度でも使える。
被積分関数は `Fn(S) -> Result<V, SciOxideError>`（1 次元）か `Fn(&[S]) -> Result<V, SciOxideError>`（多次元）のクロージャで、値として渡す。
同じクロージャを続けて使うときは `&f` を渡す（クロージャの参照も同じトレイトを実装する）。
被積分関数は端点や領域などのほかの引数より前に置く。
値の型 `V` は scioxide-core の `AffineValue` を実装する型（実数、`Complex<S>`、`Vec<V>`、`[V; N]`）で、各実成分を同じ節点と重みで積分する。
所有値を返す API の `integrate` とワンショット関数は `Copy` な値（実数、複素数、固定長の配列）だけを返すので、長さが実行時に決まるベクトル値は `integrate_into` に `Vec` かスライス `[V]` の出力を渡す。
複素数は実部と虚部の 2 成分として数える。

作業領域は呼び出し側が所有するメモリである。
Plan の `workspace_requirements(..)` が返す要件（多くの Plan で `IntegrationRequirements`）は実成分の数と、多次元の Plan では次元を記録し、`workspace(..)` がそれに合う作業領域を作る。
`integrate_into(f, .., &mut out, &mut workspace, scope)` は出力と作業領域を借用して計算し、レポートを返す。
`scope` には `ExecutionContext::sequential()` などの実行コンテキストか、上限を持つ solve scope を渡す。
所有値を返す API の `integrate` は呼び出しごとに作業領域を作り、逐次に実行して `(値, レポート)` を返す。
Monte Carlo 法の積分器 `MonteCarloIntegrator` は統計を作業領域に残すので所有値を返す API を持たず、級数は `sum`、感度は `jvp_into`・`vjp_into` という別の API を持つ。

固定則は `FixedRule` トレイトで表し、`GaussianRulePlan`、`GaussKronrod`、`ClenshawCurtis`、`NewtonCotes` が実装する。
同じトレイトを満たす則は `ProductRule` の 1 次元の則としても使える。
適応二分を使う手法は `SubdivisionOptions`、刻みを半減する `Romberg` と `DoubleExponentialIntegrator` は `LevelOptions` で許容誤差と上限を受け取る。
重み付き求積、Fourier 尾部、振動積分、反復積分、感度の設定は `SubdivisionOptions` を包み、手法に固有の値を加える。

## 最小の実行例

次のセルは 2 点の Gauss–Legendre 則の Plan を一度だけ作り、1 つの作業領域を使い回して $\int_{-1}^1 x^2\,dx = 2/3$ と $\int_{-1}^1 x^4\,dx = 2/5$ を `integrate_into` で計算する。
2 点の Gauss 則は 3 次までの多項式を厳密に積分するので、$x^2$ は丸めの範囲で一致し、$x^4$ では $2/9$ を返して $8/45 \approx 0.178$ ずれるはずである。
表は値、解析解との差、評価回数、レポートの誤差推定、終了理由を示す。
固定則は誤差推定を持たないので、誤差推定の列は未推定になる。

```rust
//| id: integrate-api-gaussian-moment
//| ref: integrate-api-gaussian-moment
//| title: 二点 Gauss–Legendre 則の厳密次数と作業領域の再利用
//| run: reactive
//| crates: [scioxide-core, scioxide-integrate]
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/2","range":{"min":0,"max":1e-15}}
//|       - {"artifact":"summary","path":"/rows/1/2","approx":{"value":0.17777777777777778,"rtol":1e-12}}
//|       - {"artifact":"summary","path":"/rows/1/3","equals":2}
//|       - {"artifact":"summary","path":"/rows/1/4","equals":null}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
use scioxide_core::{ExecutionContext, Interval};
use scioxide_integrate::{FixedRule, GaussianRulePlan};

// 1. 2 点の Gauss–Legendre 則の Plan を一度だけ準備する。
let plan = GaussianRulePlan::gauss_legendre(2).map_err(|e| e.to_string())?;

// 2. 実数 1 成分の作業領域を一度だけ作り、2 つの被積分関数で使い回す。
let mut workspace = plan.workspace(1).map_err(|e| e.to_string())?;
let interval = Interval::new(-1.0, 1.0).map_err(|e| e.to_string())?;
let integrands: [(&str, fn(f64) -> f64, f64); 2] = [
    ("x²", |x| x * x, 2.0 / 3.0),
    ("x⁴", |x| x * x * x * x, 2.0 / 5.0),
];
let mut rows = Vec::new();
let mut evaluations = 0;
for (name, f, exact) in integrands {
    // 3. 出力・作業領域・実行コンテキストを渡して積分し、レポートを読む。
    let mut value = 0.0_f64;
    let report = plan
        .integrate_into(
            |x: f64| Ok(f(x)),
            interval,
            &mut value,
            &mut workspace,
            ExecutionContext::sequential(),
        )
        .map_err(|e| e.to_string())?;
    evaluations += report.evaluations();
    rows.push((
        name,
        value,
        (value - exact).abs(),
        report.evaluations(),
        report.error_estimate(),
        report.termination().to_string(),
    ));
}
let termination = rows.last().map(|row| row.5.clone()).unwrap_or_default();

let sig15 = serde_json::json!({ "significantDigits": 15 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "被積分関数" },
    { "key": "1", "label": "積分値 [-]", "type": "number", "format": sig15 },
    { "key": "2", "label": "解析解との差 [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "評価回数 [回]", "type": "integer" },
    { "key": "4", "label": "誤差推定 [-]", "type": "number", "format": sci3, "nullText": "未推定" },
    { "key": "5", "label": "終了理由" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "summary" })
);

// 固定則の適用は FixedRuleCompleted で終わり、精度は主張しない。
emit_outcome!(
    Outcome::satisfied("固定則を 2 回適用した")
        .explanation("成功は則を設定どおりに適用したことだけを表す。精度は解析解との差で読む。")
        .status(termination)
        .diagnostic("評価回数", evaluations as f64, None)
);
```

$x^2$ では差が丸めの範囲に収まり、$x^4$ では $8/45$ ずれる。
どちらの呼び出しも評価は 2 回で、終了理由は `FixedRuleCompleted`、誤差推定は `None` である。
成功は則を設定どおりに適用したことだけを表し、$x^4$ の大きな誤差はレポートに現れない。
精度の判断には点数を変えた比較や、[埋め込み対と大域適応求積](../algorithms/adaptive-quadrature/)のように誤差推定を持つ則を使う。
2 回目の呼び出しは 1 回目の作業領域をそのまま使い、新たな確保をしない。

## 結果・誤差・終了状態の読み方

ワンショット関数が返す `Integral` は値 `value()` と誤差の推定 `error_estimate()` だけを持つ。
誤差の推定はレポートの `error_estimate()` と同じ値である。
レポートに推定がない場合は、領域の測度が 0 なら 0、それ以外の成功ではスカラーの最大の有限値になる。
ワンショット関数は成功でない終了をエラーに変え、上限で止まった推定値は返さない。
エラーの分類は次の表の右の列と同じで、全体の推定ができた後に止まった場合も同じ分類になる。

所有値を返す API の `integrate` は `(値, IntegrationReport)` を返し、`integrate_into` は出力に値を書いて `IntegrationReport` を返す。
レポートの `termination()` が唯一の終了理由で、`is_success()` は `termination().is_success()` と同じである。
`evaluations()` は被積分関数の評価回数（反復積分では内側の積分の評価も含む）、`subdivisions()` は二分の回数である。

`Ok` の結果は必ず領域全体を覆う推定値を持つ。
全体の推定ができた後に評価回数の上限、取り消し、期限で止まると、その推定値を成功でない終了理由（`BudgetLimit`、`RefinementLimit`、`Stagnation` など）とともに返す。
全体の推定ができる前に止まると、値の代わりにエラーを返し、出力を書き換えない。
その分類は次のとおりで、`e.kind()` で読む。

| 止まった理由 | 全体の推定がないときのエラー |
|---|---|
| 評価回数・反復回数・その他の上限（`BudgetLimit`） | `ConvergenceFailure`（`EvaluationLimit`、`IterationLimit`、`ResourceLimit`） |
| 段数や項数の上限（`RefinementLimit`） | `ConvergenceFailure`（`TruncationLimit`） |
| 推定の停滞（`Stagnation`） | `ConvergenceFailure`（`Stagnation`） |
| 外挿が示す発散（`ProbablyDivergent`） | `ConvergenceFailure`（`Divergence`） |
| 次の細分に表せる評価点がない（`GeometryFailure`） | `NumericalInstability`（`Breakdown`） |
| 取り消し・期限（`ExecutionStopped`） | `ExecutionStopped` |

入力の誤りは評価の前に返る。
範囲外の選択肢や分割点、別の種類の Plan の要件は `InvalidInput`、NaN や無限大の端点や引数は `NonFinite`（発生元は入力）、出力・ベクトルの許容誤差・作業領域の成分数の不一致は `DimensionMismatch` である。
被積分関数が NaN や無限大を返すと `NonFinite`（発生元はコールバック）になり、被積分関数が返したエラーはそのまま返る。
作業領域が小さすぎる場合は Plan によって `DimensionMismatch` か `InvalidInput` で、各 Plan の表に書いた。

`IntegrationTermination::is_success()` は `FixedRuleCompleted`、`ToleranceReached`、`HeuristicToleranceReached`、`SampleBudgetCompleted`、`DegenerateDomain` で真になる。
成功は手法が設定どおりに終わったことを意味し、真の誤差を抑えない。
`HeuristicToleranceReached` は二重指数変換、Fourier 尾部、2 次元以上の `CubaturePlan`、疎格子が収束したときの終了理由で、成功に数える。
級数の `SeriesTermination::is_success()` も同じ考え方で、`BoundedTailReached`、`ExactEmpty`、`HeuristicToleranceReached` で真になる。
Levin u と Wynn ε の `HeuristicToleranceReached` は連続する加速値の一致による停止で、収束を証明せず、無限の尾部を抑えない。
感度の `SensitivityReport` は `is_success()` を持たないので `report.termination().is_success()` で読み、VEGAS と MISER の `TrainingReport::is_success()` は学習を最後まで終えたときに真になる。

決定論的な誤差推定は `error_components()` が返す `IntegrationErrorComponents` で読む。
離散化、丸め、内側の積分、モーメント、外挿、尾部の成分に分かれ、推定しなかった成分は `None` で、0 とは限らない。
合計 `error_estimate()`（`total()`）は

$$
E = \max(\text{discretization},\ \text{roundoff}) + \text{inner} + \text{moments} + \text{extrapolation} + \text{tail}
$$

で、離散化の推定がない場合、尾部の診断があるのに尾部の大きさがない場合、和が桁あふれする場合は `None` になる。
どの成分も推定値で、上界ではない。
標本から求める丸め誤差による精度の限界 $50\varepsilon\sum_i\lvert w_i f(x_i)\rvert$ を含むのは Gauss–Kronrod、Simpson、Romberg、二重指数変換の推定で、疎格子の剰余による推定は丸め誤差による精度の限界を別に持たない。
観測した減衰から推した成分は `ErrorReliability::Heuristic` を持つ。
複素数やベクトルの値ではレポートの成分は実成分ごとの最大で、成分ごとの内訳は作業領域の `component_errors()` で読む。
Monte Carlo 法のレポートは誤差推定を持たず、標準誤差と信頼区間は作業領域の `statistics()` が返す統計的な不確かさである。

## 作業領域の再利用と確保

作業領域は 1 つの実成分の数と、多次元の Plan では 1 つの次元に対応する。
`check(&requirements)` は大きさが足りるかを `Capacity` で返し、成分数か次元が違うかメモリが足りなければ `Capacity::NeedsGrowth` になる。
`try_reserve(&requirements)` は今の容量と要求の大きい方を保つので、同じ種類の複数の Plan に 1 つの作業領域を使える。
別の種類の Plan の要件を渡すと `InvalidInput` になり、確保に失敗すると作業領域は変わらない。
`last_attempt()` は直前の呼び出しの記録（結果の分類、評価回数、レポート）を、失敗した呼び出しも含めて返す。
`component_errors()` は直前の呼び出しが返した成分ごとの誤差推定で、呼び出しの前、エラーを返した呼び出しの後、推定のない呼び出し（幅 0 の区間など）の後は `None` である。

十分な大きさの作業領域を渡した `integrate_into` はメモリを確保しない。
標本データの Plan は自分の `workspace`、`cumulative_workspace`、`axis_workspace`、`cumulative_axis_workspace` で作る作業領域を使い、レポートも誤差推定も返さない。
級数、感度、VEGAS・MISER の作業領域は専用の要件型とレポート型を持ち、子ページの表にまとめた。
作業領域の一覧と大きさを決める量は[Plan・作業領域・実行コンテキスト](oxref:integrate-plans-and-workspaces)にある。
