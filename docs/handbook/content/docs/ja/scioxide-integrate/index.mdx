定積分

$$
I[f] = \int_\Omega f(\boldsymbol{x})\,w(\boldsymbol{x})\,d\boldsymbol{x}
$$

を有限回の関数評価から近似する問題は、偏微分方程式の弱形式、統計力学の分配関数、ベイズ推論の周辺化、不確かさの伝播などに現れる。
ここで $f$ は被積分関数、$w$ は既知の重み関数（不要なら $w \equiv 1$）、$\Omega$ は積分領域である。
原始関数を初等関数で書ける被積分関数は限られるので、一般には節点 $\boldsymbol{x}_i$ と重み $w_i$ による重み付き和

$$
Q_n[f] = \sum_{i=1}^n w_i\,f(\boldsymbol{x}_i)
$$

で近似する。
この近似を求積（quadrature）と呼び、多次元の場合は cubature とも呼ぶ。

## クレートの役割

`scioxide-integrate` は、実数値・複素数値・ベクトル値の被積分関数の定積分と無限級数の和を、`f32` と `f64` で計算する。
扱う問題と主な API は次のとおりである。

- 1 次元の固定則：等間隔節点の `NewtonCotes`、古典重みの Gauss 型則 `GaussianRulePlan`、Chebyshev 極値点の `ClenshawCurtis`、埋め込み対 `GaussKronrod`、台形則の外挿 `Romberg`。
- 1 次元の適応求積：大域適応の `AdaptiveIntegrator`、端点特異性と無限区間の `DoubleExponentialIntegrator`。
- 重み付き求積と振動積分：端点重み・主値・Fourier 重みの `WeightedQuadraturePlan`、半無限区間の Fourier 積分の `FourierTailPlan`、非線形位相の `OscillatoryQuadraturePlan`、複素経路の `ContourPlan`。
- 標本データと級数：保存した標本の `SampledTrapezoidPlan`・`SampledSimpsonPlan`・`SampledRombergPlan`、級数の加速と Euler–Maclaurin 和の `SeriesSummation`。
- 多次元の求積：直積則 `ProductRule`、適応 cubature `CubaturePlan`、端点が外側の座標に依存する領域の `IteratedDomainPlan`、単体と球面の `SimplexRule`・`LebedevRule`・`SphereProductRule`、疎格子 `SparseGridPlan`。
- Monte Carlo 法：一様・重点・層別の `MonteCarloIntegrator`、学習した写像と層別化の `VegasTrainer`・`MiserTrainer`。
- パラメータ感度：積分のパラメータに関する JVP と VJP の `QuadratureSensitivityPlan`。

既定の設定で答えだけが必要なら、ワンショット関数を使う。
`scioxide_integrate::integrate`（有限区間）、`integrate_piecewise`（既知の折れ目）、`integrate_fourier`（Fourier 重み）、`integrate_unbounded`（無限区間）、`integrate_box`（直方体）、`integrate_iterated`（可変端点）、`integrate_monte_carlo`（Monte Carlo 法）、`trapezoid`・`simpson`・`cumulative_trapezoid`（標本データ）、`sum_series`（無限級数）の 11 個である。
どれも既定の設定の Plan と作業領域をその場で作って逐次に実行し、成功しない終了をエラーにする。
`integrate` から `integrate_iterated` までの 6 個は値と誤差の推定を `Integral` で返す。
`integrate_monte_carlo` は統計量 `MonteCarloStatistics`、`sum_series` は `SeriesResult` を返し、標本データの 3 個は値（累積積分では `Vec`）だけを返す。
手法や許容誤差、上限を変える場合や、終了理由と評価回数を読む場合は、上の Plan や積分器を設定して使う。

このクレートが返す誤差は推定値であり、真の誤差の上界を証明しない。
積分値を確実に含む区間（包含が保証された区間）が必要な場合は、`scioxide-validated` のワンショット関数 `scioxide_validated::integrate` か検証器 `QuadratureVerifier` を使う。
そこでは利用者が被積分関数の区間拡張（値や高階導関数を区間で囲む関数）を与え、台形則と 4 点 Gauss–Legendre 則の剰余項を区間演算で囲む。
原始関数を式として求める記号積分は、どのクレートも提供しない。

## 最初の計算：Bessel 関数の積分表示

第 1 種 Bessel 関数 $J_0$ は、円形開口の回折や周波数変調の側帯波の振幅に現れ、次の積分表示を持つ。

$$
J_0(x) = \frac{1}{\pi}\int_0^\pi \cos(x\sin\theta)\,d\theta .
$$

被積分関数は滑らかだが、$x$ が大きいと $[0,\pi]$ の中で約 $x/\pi$ 回振動する。
次のセルはこの積分をワンショット関数 `integrate(f, a, b)` で計算し、`scioxide-special` の `bessel_j` の値と比べる。
`integrate` は大域適応の Gauss–Kronrod 則（G7K15）に Wynn の ε アルゴリズムによる外挿を組み合わせ、絶対・相対とも $\sqrt\varepsilon \approx 1.5\times10^{-8}$ の許容誤差と二分 50 回の上限を使う。
戻り値の `Integral` は値 `value()` と誤差の推定 `error_estimate()` を持つ。
入力は引数 $x$ で、出力は積分値、参照値、実際の誤差、誤差の推定の表である。

```rust
//| id: integrate-first-one-shot
//| ref: integrate-first-one-shot
//| title: Bessel 関数 J₀ の積分表示をワンショット関数で求める
//| run: reactive
//| crates: [scioxide-core, scioxide-integrate, scioxide-special]
//| inputs:
//|   argument: {"type":"range","label":"引数 x [-]","description":"大きいほど被積分関数の振動が増える。","min":0,"max":80,"step":1,"value":10}
//| cases:
//|   - {"id":"many-oscillations","label":"x = 80","description":"振動が増えても既定の上限の中で許容誤差を満たす。","inputs":{"argument":80}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"one-shot","path":"/rows/0/0","approx":{"value":-0.245935764451348,"atol":1e-9}}
//|       - {"artifact":"one-shot","path":"/rows/0/2","range":{"min":0,"max":1e-8}}
//|   - case: many-oscillations
//|     expect:
//|       - {"artifact":"one-shot","path":"/rows/0/2","range":{"min":0,"max":1e-8}}
use scioxide_core::RealScalar;
use scioxide_integrate::integrate;

let x = argument;
// 被積分関数 cos(x sin θ)/π。SciOxide の関数は RealScalar 経由で呼ぶ。
let integrand =
    |theta: f64| Ok(RealScalar::cos(x * RealScalar::sin(theta)) / std::f64::consts::PI);
let result = integrate(integrand, 0.0, std::f64::consts::PI).map_err(|e| e.to_string())?;
// 独立な参照値: scioxide-special の級数・漸近展開による J₀(x)。
let reference = scioxide_special::bessel_j(0.0, x).map_err(|e| e.to_string())?;
let sig15 = serde_json::json!({ "significantDigits": 15 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "積分値 Q [-]", "type": "number", "format": sig15 },
    { "key": "1", "label": "参照値 J₀(x) [-]", "type": "number", "format": sig15 },
    { "key": "2", "label": "実際の誤差 |Q − J₀| [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "誤差の推定 [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    vec![(
        result.value(),
        reference,
        (result.value() - reference).abs(),
        result.error_estimate(),
    )],
    metadata = serde_json::json!({ "id": "one-shot" })
);
```

既定値の $x = 10$ では、積分値 $-0.245935764451349$ と参照値の差は $2\times10^{-16}$ 程度で、誤差の推定は $7.7\times10^{-9}$ だった。
推定は実際の誤差より 7 桁ほど大きく、許容誤差 $\sqrt\varepsilon$ を満たしたところで止まったことを表すだけで、上界ではない。
$x = 80$ でも差は $10^{-16}$ 程度で、推定は $1.5\times10^{-8}$ だった。
`integrate` は成功しなければエラーを返すので、値が返ったこと自体が成功の印である。

許容誤差と上限を自分で決める場合や、終了理由、評価回数、誤差推定の内訳を読む場合は、設定した積分器を使う。
次のセルは同じ積分を `AdaptiveIntegrator` の Gauss–Kronrod 則（G7K15）で外挿なしに計算する。
入力は引数 $x$、許容誤差の指数 $q$、二分の上限である。
許容誤差は絶対許容誤差 $\varepsilon_{\mathrm{abs}} = 10^q$ と相対許容誤差 $\varepsilon_{\mathrm{rel}} = 10^q$ の両方に使い、全体の誤差推定 $E$ が $\varepsilon_{\mathrm{abs}} + \varepsilon_{\mathrm{rel}}|Q|$ 以下になれば止まる。
$J_0$ は $x$ とともに 0 の近くを振動するので、相対許容誤差だけでは判定が厳しくなりすぎる。
出力は値と評価回数の表、誤差推定の内訳の表、終了理由の判定である。
内訳の表の $E$ は `error_estimate()` で、離散化の推定と丸め誤差による精度の限界の和ではなく、$E = \max(\text{離散化}, \text{丸め}) + \text{inner} + \text{moments} + \text{extrapolation} + \text{tail}$ である（この例では後ろの 4 項は推定されず、0 として足される）。

```rust
//| id: integrate-first-bessel-j0
//| ref: integrate-first-bessel-j0
//| title: Bessel 関数 J₀ の積分表示を適応 Gauss–Kronrod 則で求める
//| run: reactive
//| crates: [scioxide-core, scioxide-integrate, scioxide-special]
//| inputs:
//|   argument: {"type":"range","label":"引数 x [-]","description":"大きいほど被積分関数の振動が増える。","min":0,"max":80,"step":1,"value":10}
//|   tolerance_exponent: {"type":"range","label":"許容誤差の指数 q [-]","description":"絶対・相対許容誤差をともに 10^q とする。","min":-14,"max":-4,"step":1,"value":-10}
//|   max_subdivisions: {"type":"range","label":"二分の上限 [回]","description":"上限に達すると BudgetLimit で止まる。","min":1,"max":50,"step":1,"value":50}
//| cases:
//|   - {"id":"many-oscillations","label":"x = 80","description":"振動が増え、評価回数と二分の回数が増える。","inputs":{"argument":80}}
//|   - {"id":"subdivision-limit","label":"二分 2 回まで","description":"x = 80 で二分を 2 回に制限すると、許容誤差の前に BudgetLimit で止まる。","inputs":{"argument":80,"max_subdivisions":2}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","approx":{"value":-0.245935764451348,"atol":1e-9}}
//|       - {"artifact":"summary","path":"/rows/0/2","range":{"min":0,"max":1e-10}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: many-oscillations
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/2","range":{"min":0,"max":1e-10}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: subdivision-limit
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/6","equals":"BudgetLimit(Subdivision)"}
//|       - {"path":"/outputs/2/state","equals":"partial"}
use scioxide_core::{Budget, ErrorTolerance, Interval, NormSelection, RealScalar};
use scioxide_integrate::{AdaptiveIntegrator, AdaptiveRule, SubdivisionOptions};

let x = argument;
let requested = 10.0_f64.powf(tolerance_exponent);
let options = SubdivisionOptions::default()
    .with_tolerance(
        ErrorTolerance::scalar(requested, requested, NormSelection::Infinity)
            .map_err(|e| e.to_string())?,
    )
    .with_max_subdivisions(
        Budget::try_from(max_subdivisions as usize).map_err(|e| e.to_string())?,
    );
let plan =
    AdaptiveIntegrator::new(AdaptiveRule::GaussKronrod, options).map_err(|e| e.to_string())?;

// 被積分関数 cos(x sin θ)/π。SciOxide の関数は RealScalar 経由で呼ぶ。
let integrand =
    |theta: f64| Ok(RealScalar::cos(x * RealScalar::sin(theta)) / std::f64::consts::PI);
let domain = Interval::new(0.0, std::f64::consts::PI).map_err(|e| e.to_string())?;
let (value, report) = plan
    .integrate(integrand, domain)
    .map_err(|e| e.to_string())?;

// 独立な参照値: scioxide-special の級数・漸近展開による J₀(x)。
let reference = scioxide_special::bessel_j(0.0, x).map_err(|e| e.to_string())?;
let threshold = requested + requested * value.abs();
let termination = report.termination();
let sig15 = serde_json::json!({ "significantDigits": 15 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let value_columns = serde_json::json!([
    { "key": "0", "label": "積分値 Q [-]", "type": "number", "format": sig15 },
    { "key": "1", "label": "参照値 J₀(x) [-]", "type": "number", "format": sig15 },
    { "key": "2", "label": "実際の誤差 |Q − J₀| [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "しきい値 ε_abs + ε_rel|Q| [-]", "type": "number", "format": sci3 },
    { "key": "4", "label": "評価回数 [回]", "type": "integer" },
    { "key": "5", "label": "二分の回数 [回]", "type": "integer" },
    { "key": "6", "label": "終了理由" }
]);
emit_table_with_columns!(
    value_columns,
    vec![(
        value,
        reference,
        (value - reference).abs(),
        threshold,
        report.evaluations(),
        report.subdivisions(),
        termination.to_string(),
    )],
    metadata = serde_json::json!({ "id": "summary" })
);

// 誤差推定の内訳。適応 Gauss–Kronrod は離散化と丸めの 2 成分を埋める。
let components = report.error_components();
let discretization = components.and_then(|parts| parts.discretization());
let reliability = discretization.map(|estimate| format!("{:?}", estimate.reliability()));
let error_columns = serde_json::json!([
    { "key": "0", "label": "離散化誤差の推定 [-]", "type": "number", "format": sci3, "nullText": "未推定" },
    { "key": "1", "label": "推定の種類", "nullText": "なし" },
    { "key": "2", "label": "丸め誤差の下限 [-]", "type": "number", "format": sci3, "nullText": "未推定" },
    { "key": "3", "label": "全体の誤差推定 E [-]", "type": "number", "format": sci3, "nullText": "未定義" }
]);
emit_table_with_columns!(
    error_columns,
    vec![(
        discretization.map(|estimate| estimate.magnitude()),
        reliability,
        components.and_then(|parts| parts.roundoff()),
        report.error_estimate(),
    )],
    metadata = serde_json::json!({ "id": "error-parts" })
);

let outcome = if termination.is_success() {
    Outcome::satisfied("推定誤差が許容誤差を満たした")
        .explanation("推定は上界ではないので、参照値との差で確かめる。")
} else {
    Outcome::partial("許容誤差を満たす前に止まった")
        .explanation("表の積分値は全区間を覆う推定値として読み、上限を増やして計算し直す。")
};
let mut outcome = outcome
    .status(termination.to_string())
    .diagnostic("評価回数", report.evaluations() as f64, None)
    .diagnostic("実際の誤差", (value - reference).abs(), None);
if let Some(estimate) = report.error_estimate() {
    outcome = outcome.diagnostic("誤差推定", estimate, None);
}
emit_outcome!(outcome);
```

既定値（$x = 10$、$q = -10$）では、7 回の二分と 225 回（$15 + 30 \times 7$）の評価で `ToleranceReached` になった。
積分値 $-0.245935764451349$ と参照値の差は $4\times10^{-16}$ 程度で、誤差推定 $E \approx 8\times10^{-13}$ はしきい値 $1.2\times10^{-10}$ を満たし、実際の誤差より 3 桁ほど大きい。
滑らかな被積分関数を解像できた場合、Gauss–Kronrod 則の誤差推定はこのように控えめ（悲観的）になることが多い。
$x = 80$ では振動が増え、41 回の二分と 1245 回の評価が必要になった。
二分を 2 回に制限すると、75 回の評価で `BudgetLimit(Subdivision)` になり、積分値は参照値から $4.7\times10^{-3}$ ずれ、誤差推定は $0.62$ だった。
このとき判定は `partial` で、表の積分値は全区間を覆う推定値ではあるが、許容誤差を満たしていない。

## 結果の読み方

ワンショット関数は成功でない終了をエラー（上限なら `ConvergenceFailure` の `EvaluationLimit` や `ResourceLimit`、停滞なら `Stagnation` など）に変える。
そのため読むのは `Integral` の値と誤差の推定か、エラーの分類である。
設定した積分器は値と `IntegrationReport` を返す。
レポートは唯一の終了理由 `termination()`、評価回数 `evaluations()`、二分の回数 `subdivisions()`、誤差推定 `error_estimate()` とその内訳 `error_components()` を持つ。
読む順序は次のとおりである。

1. `is_success()` で成功かどうかを見る。
   成功は `ToleranceReached`（誤差推定が許容誤差を満たした）、`HeuristicToleranceReached`（観測した減衰など経験的な推定が許容誤差を満たした）、`FixedRuleCompleted`（固定則を 1 回適用した。
   許容誤差は調べていない）、`SampleBudgetCompleted`（Monte Carlo 法が指定の標本数を使い切った）、`DegenerateDomain`（領域の測度が 0 で結果は厳密に 0）の 5 つである。
2. 成功でなければ、`BudgetLimit`・`RefinementLimit`・`Stagnation` などの理由を見て、上限を増やす、領域を事前に分割する、手法を変えるのどれかを選ぶ。
   このとき返る値は全領域を覆う推定値で、許容誤差の達成は意味しない。
   全領域の推定ができる前に止まった場合は、値の代わりにエラー（`ConvergenceFailure` など）が返る。
3. 誤差推定の種類を見る。
   `ErrorReliability::Estimated` は 2 つの則や 2 つの段の差から求めた推定、`ErrorReliability::Heuristic` は寄与の減衰の観測から推した推定で、どちらも上界ではない。
   節点の間に隠れた細いピークのように、標本に現れない構造があれば推定はいくらでも外れうる。
4. 独立な方法で確かめる。
   既知の値、別の手法、許容誤差や次数を変えた比較のどれかで、推定の妥当性を確認する。

Monte Carlo 法は決定論的な誤差推定の代わりに標本の標準誤差と信頼区間を返し、これは統計的な不確かさの推定である。
終了理由と誤差の各成分の詳細は[数値積分の数理とアルゴリズム体系](algorithms/)にまとめてある。

## まとめ

既定の設定で値だけが必要ならワンショット関数を使い、成功しなかった場合はエラーの分類を読む。
手法や上限を選ぶ場合は、設定した Plan と再利用できる作業領域で計算し、値とレポートの組を受け取る。
結果はまず `is_success()` と終了理由で読み、`FixedRuleCompleted` や `BudgetLimit` を許容誤差の達成と取り違えない。
誤差推定は `Estimated` でも `Heuristic` でも上界ではないので、既知の値や別の手法、条件を変えた比較で確かめる。
上界の証明が必要な場合は `scioxide-validated` の `scioxide_validated::integrate` か `QuadratureVerifier` を使う。
