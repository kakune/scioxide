B スプラインでは曲線を局所的な基底関数の和として表す。
制御値を変えた影響は限られた範囲にとどまり、次数とノットの多重度から滑らかさを設計できる。
制御点は一般には曲線上の標本点ではない。
そのため、与えた係数から曲線を評価する処理と、標本を通す係数を求める処理を分けて考える。

## 基底の漸化式と連続性

非減少のノット列 $t_0 \le t_1 \le \dots \le t_{K-1}$ と次数 $p$ を与える。
基底関数の数（制御値の数）は $n = K - p - 1$ で、基底の評価域は $[t_p, t_n]$ である。
0 次の基底 $B_{i,0}$ を区間 $[t_i, t_{i+1})$ の指示関数とし、Cox–de Boor の漸化式で次数を上げる。

$$
B_{i,p}(x)=\frac{x-t_i}{t_{i+p}-t_i}B_{i,p-1}(x)
+\frac{t_{i+p+1}-x}{t_{i+p+1}-t_{i+1}}B_{i+1,p-1}(x)
$$

分母が 0 になる項は 0 とする。
帰納法から次の性質が出る。

- 局所台：$B_{i,p}$ は $[t_i, t_{i+p+1})$ の外で 0 になり、一点で 0 でない基底は高々 $p+1$ 個である。
- 非負性と 1 の分解：$B_{i,p} \ge 0$ で、評価域では $\sum_i B_{i,p}(x) = 1$ である。
  したがって曲線 $s(x) = \sum_i c_i B_{i,p}(x)$ の値は、その点で 0 でない基底の制御値の凸結合になる。
- 連続性：多重度 $k$ の内部ノットでは、一般の係数で接続は $C^{p-k}$ までになる。
  係数どうしの打ち消しによって、実際の曲線がそれより滑らかになることもある。
- 端点：両端のノットを $p+1$ 回繰り返す（開いたノット列）と、端の制御値がそのまま端点の値になる。

微分は次数を一つ下げた基底で書ける。

$$
B_{i,p}'(x) = p\left(\frac{B_{i,p-1}(x)}{t_{i+p}-t_i} - \frac{B_{i+1,p-1}(x)}{t_{i+p+1}-t_{i+1}}\right)
$$

[`BSplineBasis::new(knots, degree)`](https://docs.rs/scioxide-interp/0.1.0/scioxide_interp/struct.BSplineBasis.html#method.new) は、ノットが $2(p+1)$ 個以上あること、非減少であること、多重度が $p+1$ 以下であること、評価域が空でないことを検査する。
違反は `InvalidInput`（`Inconsistent`）、有限でないノットは `NonFinite` になる。
よく使うノット列には名前付きの構築関数がある。
`BSplineBasis::clamped(breakpoints, degree)` は両端の区切り点を $p+1$ 回繰り返して内部の区切り点を一度ずつ置き、`BSplineBasis::not_a_knot(nodes, degree)` は奇数次 $p = 2k+1$ について、両端の節点を $p+1$ 回繰り返し、内部のノットに $x_{k+1}, \dots, x_{n-k-2}$ を置く。
後者は節点で Schoenberg–Whitney 条件を満たし、$p = 3$ では not-a-knot の 3 次スプラインの空間になる。
一点の評価では点を含むノット区間を二分探索で見つけ、0 でない $p+1$ 個の基底を三角形の漸化式で計算するので、計算量は $O(p^2 + \log n)$ である。
`evaluate_into(x, order, side, policy, out, workspace)` は全 $n$ 個の基底の値か `order` 階導関数を出力に書き（0 の部分を埋める $O(n)$ を含む）、`integrals_into(lower, upper, policy, out, workspace)` は各基底の定積分を書く。
次数より高い階数の導関数は 0 になり、`Clamp` で領域の外を問い合わせた導関数も 0 になる。
作業領域 `SplineBasisWorkspace` は `basis.workspace()` から作り、大きさは次数だけで決まるので、同じかそれより低い次数の基底にも使える。

ノットの上では既定で右側の多項式片を使う。
`KnotSide::Left` と `KnotSide::Right` はノットでどちらの片の極限をとるかを指定する。
`BSpline::derivative(point, orders, sides, policy)` に `sides = None` を渡すと通常の導関数を求め、多重度 $k$ のノットでは $p - k$ を超える各階数の導関数を両側の片で厳密に比べる。
一致しなければ通常の導関数は存在しないので、`DomainError`（`Undefined`）を返す。
片側を明示すれば、その片の極限を比較なしで返す。
領域の端で外を向く側を指定すると、`Reject` では拒否され、`Clamp` では一定の延長（導関数 0）として扱われる。
通常の導関数が存在することと、指定した側の導関数を計算できることは別である。

[`cardinal_bspline(degree, x)`](https://docs.rs/scioxide-interp/0.1.0/scioxide_interp/fn.cardinal_bspline.html) は、間隔 1 の一様なノット $-(p+1)/2, -(p-1)/2, \dots, (p+1)/2$ 上で中心を 0 にそろえた基数 B スプライン $B_p$ を、次数 0〜3 について閉じた形の多項式片で評価する。
台は半開区間 $[-(p+1)/2, (p+1)/2)$ で、外では 0 を返し、積分は 1 である（例えば $B_1(x) = 1 - |x|$、$B_3(0) = 2/3$）。
計算量は $O(1)$ で、確保を行わない。
次数 4 以上は `InvalidInput`（`OutOfRange`）になる。

## ノットの挿入と導関数のスプライン

1 次元の `BSpline` には、同じ関数を別の表現に移す操作がある。

`insert_knot(t)` は Boehm のアルゴリズムでノット $t \in [t_k, t_{k+1})$ を一つ加える。
新しい制御値は $k - p + 1 \le i \le k$ について

$$
Q_i = (1 - \alpha_i)\, c_{i-1} + \alpha_i\, c_i, \qquad \alpha_i = \frac{t - t_i}{t_{i+p} - t_i}
$$

で、それより前の制御値はそのまま、後ろの制御値は番号が一つずれる。
結果は元と同じ関数を表し、元のモデルは変更しない。
$t$ が評価域の外なら `DomainError`、多重度が $p+1$ を超えるなら `InvalidInput` になる。
ノットを細かくすると制御多角形が曲線に近づくので、曲線の分割や形状の調整の前処理に使える。

`derivative_spline()` は導関数を次数 $p-1$ のスプライン

$$
s'(x) = \sum_{i=0}^{n-2} q_i B_{i,p-1}(x), \qquad q_i = p\,\frac{c_{i+1} - c_i}{t_{i+p+1} - t_{i+1}}
$$

として返す（ノット列は両端を一つずつ除いたもの）。
ノットでは右側の片の値をとるので、通常の導関数が存在しない点の情報は失われる。
存在を確かめるには `derivative_into` を使う。
0 次のスプラインからは 0 のスプラインが返る。

`BSpline::linear(x, y)` は、ノット $[x_0, x_0, x_1, \dots, x_{n-1}, x_{n-1}]$ の 1 次のスプラインで標本を折れ線補間し、係数は標本値そのものになる。
1 次元の `BSpline` は `prepare_antiderivative()` で、定積分を繰り返すための原始関数も準備できる。

## テンソル積と格子補間

$D$ 次元の曲面や場を、軸ごとの基底の積で

$$
s(x_1,\ldots,x_D)=\sum_{i_1,\ldots,i_D}
 c_{i_1\cdots i_D}\prod_{a=1}^D B^{(a)}_{i_a}(x_a)
$$

と表す。
[`BSpline<S, V, D>`](https://docs.rs/scioxide-interp/0.1.0/scioxide_interp/struct.BSpline.html) は軸ごとの `BSplineBasis` とアフィン値の制御値を所有し、$D = 1$ が通常の曲線である。
`BSpline::new(bases, coefficients)` の制御値は多重添字の行優先（最後の軸が最速）で並べ、値の実数成分は各制御値の内側に並ぶ。
制御値の数が軸の制御値数の積と合わなければ `DimensionMismatch` になる。
複素数の値も実部と虚部を持つ値として扱い、座標は実数のままである。

評価では各軸で 0 でない $p_a + 1$ 個の基底を求め、対応する制御値のブロックだけを縮約する。
全基底の直積を並べた大きな行列を問い合わせのたびに作ることはない。
一点の処理は値の成分数を $d$ として $O\bigl(\sum_a (p_a^2 + \log n_a) + d\prod_a (p_a + 1)\bigr)$ である。
訪れる制御値の数 $\prod_a (p_a + 1)$ は次元とともに指数的に増えるので、局所台だけで次元への依存がなくなるわけではない。
`BSpline` は `Differentiable`、`TwiceDifferentiable`、`Integrable`（箱の上の積分）を実装し、高階の混合偏導関数は `derivative_into` で求める。

標本を通す係数は `TensorSplineInterpolationPlan` で求める。
各軸に `BSplineBasis::not_a_knot` の基底を使うなら、ワンショット関数 `BSpline::interpolate(nodes, values, degree)` が Plan を作って一度だけ解く。
奇数次 $p$ の各軸に $p+1$ 個以上の節点が要り、$p = 1$ は多重線形補間、$p = 3$ は各軸が not-a-knot の 3 次スプラインになる。
軸 $a$ の節点 $x^{(a)}_j$ での選点行列 $A_a[j][i] = B^{(a)}_i(x^{(a)}_j)$ は正方行列で、節点の数は制御値の数と等しくなければならない。
格子上の標本 $Y$ に対する方程式 $(A_1 \otimes \dots \otimes A_D)\,\mathrm{vec}(C) = \mathrm{vec}(Y)$ は、Kronecker 積を作らずに、各軸の $A_a$ をその軸に沿った列（レーン）へ順に当てて解ける。
1 次元の選点行列が正則になる条件は Schoenberg–Whitney の定理が与え、各 $i$ で $B_i(x_i) \ne 0$、つまり $t_i < x_i < t_{i+p+1}$（開いたノット列の端点では等号も可）が必要十分である。
`TensorSplineInterpolationPlan::new(bases, nodes)` は、節点の数が制御値の数と等しいこと（違えば `DimensionMismatch`）と、節点が基底の評価域にあること（外なら `DomainError`）を確かめ、対角の基底値 $B_i(x_i)$ が正でなければ `Singular` を返す。
選点行列を帯行列として LU 分解し、準備の計算量は $O(\sum_a n_a (p_a+1)^2)$、メモリは $O(\sum_a n_a (p_a+1))$ である。
節点は軸ごとに増加でも減少でもよく、減少の軸は内部で反転し、標本の並びは呼び出し側の向きのまま受け取る。

### `TensorSplineInterpolationPlan` と作業領域の要件

`fit(samples)` は行優先（最後の軸が最速）の格子の標本から `BSpline` を返し、呼び出しごとに作業領域と係数の配列を確保する。
同じ節点で値だけを変えて何度も解くときは、作業領域を一度だけ用意し、`fit_into(values, out, workspace, cx)` で制御値の配列に直接書く。
`out` には、制御値の総数 $\prod_a n_a$ と値の実数成分の数 $m$ の積の長さで、`BSpline::coefficients` と同じ行優先の順に係数を書く（各制御値の内側に $m$ 個の成分が並ぶ）。
`cx` は `ExecutionContext` で、取り消しと期限を帯行列の求解に伝える。
逐次で取り消しも期限も要らなければ `ExecutionContext::sequential_native()` を渡す。

`fit_into` に要る作業領域の大きさは、値の実数成分の数 $m$ で変わる。
`TensorSplineInterpolationRequirements` はこの大きさを表す値で、Plan の `workspace_requirements(m)` が返し、`dimension()` で対象の成分数 $m$ を確かめられる。
要求量は係数と同じ長さ $m\prod_a n_a$ の作業用の配列 2 本と、最も制御値の多い軸の帯行列の求解に要る領域からなる。
軸ごとの解を 2 本の配列の間で交互に書き、Kronecker 積の行列を作らずに 1 軸ずつ解くためである。
$m = 0$ は `InvalidInput`（`OutOfRange`）、大きさを計算できなければ `SizeOverflow` か `ResourceLimit` になる。

`TensorSplineInterpolationWorkspace` は `workspace(m)` で作り、作った時点で `workspace_requirements(m)` を満たす。
`check(&requirements)` は、作業領域がその要求量を満たせば `Capacity::Sufficient`、足りなければ `Capacity::NeedsGrowth` を返し、確保は行わない。
`try_reserve(&requirements)` は作業領域をその場で広げ、確保に失敗すると `AllocationFailure` を返して、それまでの容量を保つ。
成分の多い要求量に合わせた作業領域は、成分の少ない求解にもそのまま使える。
足りない作業領域を `fit_into` に渡すと `DimensionMismatch` になる。
したがって、値の成分数が変わりうる処理では、最大の成分数の要求量で一度 `try_reserve` しておけば、その後の `fit_into` は確保を行わない。

`preparation_bytes(bases)` は、構築の前に準備で必要なメモリの上界を確保せずに返す。
準備の帯行列のメモリ、`fit_into` の作業領域、評価の局所的な作業領域は、それぞれ別の計算コストである。

節点の位置は選点行列の条件を左右する。
よく使われる選び方は Greville 点 $\xi_i = (t_{i+1} + \dots + t_{i+p})/p$ で、scioxide-interp は Greville 点を計算する関数を提供しないので、この式で作って渡す。
十分滑らかな $f$ に対して、スプライン空間での最良近似の誤差はノット間隔 $h$ について $O(h^{p+1})$ である。
補間がこの精度に近づくのは、選点行列の条件がよい場合である。

## テンソル格子の係数の求解

次のセルは両軸に 3 次の基底（ノット $[0,0,0,0,\,0.5,\,1,1,1,1]$、制御値 5 個）を使い、Greville 点 $0, 1/6, 1/2, 5/6, 1$ の $5 \times 5$ 格子で $f(x, y) = x^3 - 2xy^2 + y$ を補間する。
$f$ は各変数について 3 次以下の多項式なので、3 次のテンソルスプラインはこれを丸め誤差の範囲で再現する。
入力は $x$ 座標で、$y = 0.4$ に固定する。
値、勾配 $(3x^2 - 2y^2,\ -4xy + 1)$、単位正方形の積分 $5/12$ を解析式と比べる。

値は 2 成分にし、成分 0 には正しい順序（最後の軸 $y$ が最速）、成分 1 には最初の軸 $x$ が最速という誤った順序で同じ $f$ の標本を並べる。
1 回の `fit_into` で、同じ帯行列の分解から 2 つの成分の係数を求める。
作業領域は 1 成分用に作り、2 成分の要求量に対する `check` の結果を `try_reserve` の前後で表に出す。
1 つ目の表は値、勾配、積分と、誤った順序の成分の値を解析式と比べ、2 つ目の表は作業領域の確認の結果である。

```rust
//| id: interp-tensor-affine-recovery
//| ref: interp-tensor-affine-recovery
//| title: テンソル補間の成分順と微積分を検算する
//| run: reactive
//| crates: [scioxide-core, scioxide-interp]
//| inputs:
//|   position: {"type":"range","label":"x 座標 [-]","min":0,"max":1,"step":0.05,"value":0.25}
//| cases:
//|   - {"id":"diagonal","label":"x = 0.4","description":"x = y の対角線上の点では、誤った順序の成分でも値が一致し、順序の誤りが見えない。","inputs":{"position":0.4}}
//|   - {"id":"right-edge","label":"x = 1","description":"評価域の端でも、値・勾配・積分は解析式と一致する。","inputs":{"position":1}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"recovery","path":"/rows/0/1","approx":{"value":0.335625,"atol":1e-14}}
//|       - {"artifact":"recovery","path":"/rows/1/3","range":{"max":1e-14}}
//|       - {"artifact":"recovery","path":"/rows/3/1","approx":{"value":0.4166666666666667,"atol":1e-14}}
//|       - {"artifact":"recovery","path":"/rows/4/3","approx":{"value":0.071625,"atol":1e-12}}
//|       - {"artifact":"workspace","path":"/rows/0/2","equals":"NeedsGrowth"}
//|       - {"artifact":"workspace","path":"/rows/1/2","equals":"Sufficient"}
//|       - {"artifact":"workspace","path":"/rows/2/2","equals":"Sufficient"}
//|   - case: diagonal
//|     expect:
//|       - {"artifact":"recovery","path":"/rows/0/1","approx":{"value":0.336,"atol":1e-14}}
//|       - {"artifact":"recovery","path":"/rows/4/3","range":{"max":1e-14}}
//|   - case: right-edge
//|     expect:
//|       - {"artifact":"recovery","path":"/rows/0/1","approx":{"value":1.08,"atol":1e-14}}
//|       - {"artifact":"recovery","path":"/rows/1/1","approx":{"value":2.68,"atol":1e-13}}
//|       - {"artifact":"recovery","path":"/rows/4/3","approx":{"value":0.816,"atol":1e-12}}
use scioxide_core::ExecutionContext;
use scioxide_interp::{
    BSpline, BSplineBasis, Differentiable, ExtrapolationPolicy, Integrable, Interpolant,
    TensorSplineInterpolationPlan,
};

let f = |x: f64, y: f64| x * x * x - 2.0 * x * y * y + y;
let knots = vec![0.0_f64, 0.0, 0.0, 0.0, 0.5, 1.0, 1.0, 1.0, 1.0];
let basis = BSplineBasis::new(knots.clone(), 3).map_err(|e| e.to_string())?;
// Greville 点 ξ_i = (t_{i+1} + t_{i+2} + t_{i+3}) / 3
let nodes: Vec<f64> = (0..basis.control_count())
    .map(|i| (knots[i + 1] + knots[i + 2] + knots[i + 3]) / 3.0)
    .collect();
let bases = [basis.clone(), basis];
let plan = TensorSplineInterpolationPlan::new(bases.clone(), [nodes.clone(), nodes.clone()])
    .map_err(|e| e.to_string())?;
// 外側の添字が x、内側の添字が y。成分 0 は f(x, y)（正しい順序）、
// 成分 1 は x を内側の添字に取った f（誤った順序）
let samples: Vec<[f64; 2]> = nodes
    .iter()
    .flat_map(|&a| nodes.iter().map(move |&b| [f(a, b), f(b, a)]))
    .collect();

// 1 成分用の作業領域を、2 成分の要求量に合わせて広げる
let one = plan.workspace_requirements(1).map_err(|e| e.to_string())?;
let two = plan.workspace_requirements(2).map_err(|e| e.to_string())?;
let mut workspace = plan.workspace(1).map_err(|e| e.to_string())?;
let before = workspace.check(&two).map_err(|e| e.to_string())?;
workspace.try_reserve(&two).map_err(|e| e.to_string())?;
let after = workspace.check(&two).map_err(|e| e.to_string())?;
let smaller = workspace.check(&one).map_err(|e| e.to_string())?;
// 係数は制御値 25 個 × 2 成分。行優先で、各制御値の内側に 2 成分が並ぶ
let mut coefficients = vec![0.0; samples.len() * two.dimension()];
plan.fit_into(
    &samples,
    coefficients.as_mut_slice(),
    &mut workspace,
    ExecutionContext::sequential_native(),
)
.map_err(|e| e.to_string())?;
let controls: Vec<[f64; 2]> = coefficients.chunks_exact(2).map(|c| [c[0], c[1]]).collect();
let model = BSpline::new(bases, controls).map_err(|e| e.to_string())?;

let policy = ExtrapolationPolicy::Reject;
let (x, y) = (position, 0.4);
let [value, wrong_value] = model.evaluate([x, y], policy).map_err(|e| e.to_string())?;
let [[dx, _], [dy, _]] = model.gradient([x, y], policy).map_err(|e| e.to_string())?;
let [integral, _] = model
    .integral([0.0, 0.0], [1.0, 1.0], policy)
    .map_err(|e| e.to_string())?;
// 独立な検算: f の解析的な値・勾配・積分
let exact = [f(x, y), 3.0 * x * x - 2.0 * y * y, 1.0 - 4.0 * x * y, 5.0 / 12.0, f(x, y)];
let computed = [value, dx, dy, integral, wrong_value];
let names = ["値 f", "∂f/∂x", "∂f/∂y", "積分 [0,1]²", "誤った順序の成分の値"];
let rows: Vec<(&str, f64, f64, f64)> = names
    .iter()
    .zip(computed.iter().zip(exact))
    .map(|(name, (&c, e))| (*name, c, e, (c - e).abs()))
    .collect();
let digits = serde_json::json!({ "significantDigits": 10 });
let columns = serde_json::json!([
    { "key": "0", "label": "量" },
    { "key": "1", "label": "スプライン [-]", "type": "number", "format": digits },
    { "key": "2", "label": "解析値 [-]", "type": "number", "format": digits },
    {
        "key": "3",
        "label": "誤差 [-]",
        "type": "number",
        "format": { "notation": "scientific", "significantDigits": 2 }
    }
]);
emit_table_with_columns!(columns, rows, metadata = serde_json::json!({ "id": "recovery" }));
let checks = vec![
    ("try_reserve の前", two.dimension(), format!("{before:?}")),
    ("try_reserve の後", two.dimension(), format!("{after:?}")),
    ("try_reserve の後", one.dimension(), format!("{smaller:?}")),
];
emit_table_with_columns!(
    ["作業領域の状態", "要求量の成分数 dimension()", "check の結果"],
    checks,
    metadata = serde_json::json!({ "id": "workspace" })
);
```

既定の $x = 0.25$ では、値、二つの偏導関数、積分の誤差はどれも $10^{-16}$ の程度で、3 次のテンソルスプラインが $f$ を丸め誤差の範囲で再現している。
$x$ を 0 から 1 まで動かしても誤差は $10^{-15}$ 程度にとどまり、積分は入力によらず $5/12$ と一致する。
誤った順序の成分は転置した関数 $f(y, x)$ を補間するので、同じ点で $7.2 \times 10^{-2}$ の誤差が出る。
$x = 0.4$ では $x = y$ なので、誤った順序の成分でも値が一致して誤りが見えない。
対称な関数や対角線上の点だけで検算すると順序の誤りを見落とすので、非対称な関数で確かめる。
1 成分用に作った作業領域は 2 成分の要求量に対して `NeedsGrowth` で、`try_reserve` のあとは `Sufficient` になり、1 成分の要求量にもそのまま `Sufficient` である。

## 有理曲線と正の重み

[`Nurbs`](https://docs.rs/scioxide-interp/0.1.0/scioxide_interp/struct.Nurbs.html) は正の重み $w_i$ を持つ非一様有理 B スプライン（NURBS）で、

$$
R(t)=\frac{N(t)}{W(t)}, \qquad N(t) = \sum_i w_i c_i B_i(t), \qquad W(t) = \sum_i w_i B_i(t)
$$

と定める。
同次座標 $(w_i c_i, w_i)$ を制御点とする 1 次元高い空間の多項式 B スプラインを、最後の成分で割って射影したものと見ることもできる。
多項式だけでは円弧を有限次数で正確に表せないが、この商なら 2 次で円弧を表せる。
中心角 $\theta < \pi$ の円弧は、両端の点と両端の接線の交点を制御点にし、重みを $1, \cos(\theta/2), 1$ とすれば正確に表せる。
四分円（$\theta = \pi/2$）では中央の重みが $1/\sqrt{2}$ になる。
全重みを同じ定数倍しても、丸め誤差を除いて曲線は変わらない。
重みがすべて 1 なら多項式の B スプラインに一致する。

`Nurbs::new(bases, controls, weights)` は、制御値と重みの数がテンソルの制御値数と合うこと（違えば `DimensionMismatch`）と、重みが正であること（0 以下は `InvalidInput`（`OutOfRange`））を検査する。
重みは最大値で割って拡張指数の範囲で保持する。
評価は `BSpline` と同じく 0 でない基底のブロック（$\prod_a (p_a + 1)$ 個）だけを訪れ、作業領域を渡す `evaluate_into` などの形は確保を行わない。
`Nurbs` は `Differentiable` と `TwiceDifferentiable` を実装するが、`Integrable` は実装しない。

商の導関数は分母の変化も含む。
$N = RW$ を微分すると、

$$
R'=\frac{N'-RW'}{W},\qquad
R''=\frac{N''-2R'W'-RW''}{W}
$$

を得る（多変数では $R_{ab} = (N_{ab} - R_a W_b - R_b W_a - R W_{ab})/W$）。
$N$ と $W$ が区分 1 次式でも $R$ は一般に 1 次式ではないので、2 階導関数は 0 とは限らない。
内部のノットで通常の導関数を求めるには、接するすべての片で、有理関数としての値と要求した階数までの導関数が一致していなければならない。
scioxide-interp は、両側の片の値と導関数の各成分の差が、両側の 1 次の丸め誤差の上界の和に $64(2 + \sum_a p_a)\varepsilon$ を掛けた値以下なら一致とみなし、超えれば `DomainError`（`Undefined`）を返す。
同次座標の跳びが商で打ち消し合う場合は、通常の導関数が存在する。
重みの正規化と拡張指数の計算は中間値の範囲を広げるが、仮数の精度は増やさない。
表せない最終値は構造化されたエラーになる。

## 四分円の半径と曲率による検算

次のセルは制御点 $(r, 0), (r, r), (0, r)$ と重み $1, m/\sqrt{2}, 1$ の 2 次の NURBS を作る。
入力は半径 $r$ [m] と中央の重みの倍率 $m$ で、$m = 1$ のときだけ半径 $r$ の四分円になる。
101 点で、原点からの距離 $|R(t)|$、`TwiceDifferentiable::hessian` から求めた曲率 $\kappa = |x'y'' - y'x''|/(x'^2 + y'^2)^{3/2}$、媒介変数に対する速さ $|R'(t)|$ を求める。
表はそれぞれの最小と最大、円の値（半径 $r$ と曲率 $1/r$）、円の値からの最大のずれを示す。
円なら $|R(t)| = r$、$\kappa = 1/r$ で一定になる。
図は曲線と参照の円弧で、参照の円弧は `RealScalar::cos`、`RealScalar::sin` で計算し、破線で描く。

```rust
//| id: interp-nurbs-circle
//| ref: interp-nurbs-circle
//| title: NURBS の四分円と中央重みの効果を確認する
//| run: reactive
//| crates: [scioxide-core, scioxide-interp]
//| inputs:
//|   radius: {"type":"range","label":"半径 r [m]","min":0.5,"max":3.0,"step":0.1,"value":1.0}
//|   weight: {"type":"range","label":"中央重みの倍率 m [-]","min":0.5,"max":1.5,"step":0.05,"value":1.0}
//| cases:
//|   - {"id":"large-radius","label":"r = 3 m","description":"半径を変えても円のままで、曲率は 1/r = 0.333 [1/m] になる。","inputs":{"radius":3}}
//|   - {"id":"ellipse","label":"m = 0.5","description":"中央の重みが 1/√2 より小さいと楕円の弧になり、曲率が 0.5 から 4 [1/m] に広がる。","inputs":{"weight":0.5}}
//|   - {"id":"hyperbola","label":"m = 1.5","description":"中央の重みが 1 を超えると双曲線の弧になる。","inputs":{"weight":1.5}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"circle","path":"/rows/0/4","range":{"max":1e-15}}
//|       - {"artifact":"circle","path":"/rows/1/4","range":{"max":1e-13}}
//|       - {"artifact":"circle","path":"/rows/2/1","approx":{"value":1.4142135623730951,"rtol":1e-12}}
//|       - {"artifact":"circle","path":"/rows/2/4","equals":null}
//|   - case: large-radius
//|     expect:
//|       - {"artifact":"circle","path":"/rows/1/1","approx":{"value":0.3333333333333333,"rtol":1e-12}}
//|       - {"artifact":"circle","path":"/rows/0/4","range":{"max":1e-14}}
//|   - case: ellipse
//|     expect:
//|       - {"artifact":"circle","path":"/rows/0/4","approx":{"value":0.1082,"atol":1e-3}}
//|       - {"artifact":"circle","path":"/rows/1/1","approx":{"value":0.5,"rtol":1e-9}}
//|       - {"artifact":"circle","path":"/rows/1/2","approx":{"value":4,"rtol":1e-9}}
//|   - case: hyperbola
//|     expect:
//|       - {"artifact":"circle","path":"/rows/1/1","approx":{"value":0.4444444444444444,"rtol":1e-9}}
//|       - {"artifact":"circle","path":"/rows/1/2","approx":{"value":1.5,"rtol":1e-9}}
use scioxide_core::RealScalar;
use scioxide_interp::{
    BSplineBasis, Differentiable, ExtrapolationPolicy, Interpolant, Nurbs, TwiceDifferentiable,
};

let basis =
    BSplineBasis::new(vec![0.0_f64, 0.0, 0.0, 1.0, 1.0, 1.0], 2).map_err(|e| e.to_string())?;
let middle = RealScalar::sqrt(0.5_f64) * weight;
let curve = Nurbs::new(
    [basis],
    vec![[radius, 0.0], [radius, radius], [0.0, radius]],
    vec![1.0, middle, 1.0],
)
.map_err(|e| e.to_string())?;
let policy = ExtrapolationPolicy::Reject;
let (mut points, mut reference) = (Vec::new(), Vec::new());
// 各量の [最小, 最大]：原点からの距離、曲率、速さ
let mut ranges = [[f64::INFINITY, f64::NEG_INFINITY]; 3];
for i in 0..=100 {
    let t = f64::from(i) / 100.0;
    let [x, y] = curve.evaluate([t], policy).map_err(|e| e.to_string())?;
    let [[dx, dy]] = curve.gradient([t], policy).map_err(|e| e.to_string())?;
    let [[[ddx, ddy]]] = curve.hessian([t], policy).map_err(|e| e.to_string())?;
    // 媒介変数 t に対する速さと、速さで正規化した曲率
    let v = RealScalar::hypot(dx, dy);
    let kappa = (dx * ddy - dy * ddx).abs() / (v * v * v);
    for (range, q) in ranges.iter_mut().zip([RealScalar::hypot(x, y), kappa, v]) {
        *range = [range[0].min(q), range[1].max(q)];
    }
    points.push([x, y]);
    // 参照の円弧（角度で等分した点）
    let angle = std::f64::consts::FRAC_PI_2 * t;
    reference.push([
        radius * RealScalar::cos(angle),
        radius * RealScalar::sin(angle),
    ]);
}
// 円の値と、その値からの最大のずれ（速さには円の基準値がない）
let circle = [Some(radius), Some(1.0 / radius), None];
let names = ["原点からの距離 |R(t)| [m]", "曲率 κ [1/m]", "速さ |R'(t)| [m]"];
let rows: Vec<(&str, f64, f64, Option<f64>, Option<f64>)> = names
    .iter()
    .zip(ranges.iter().zip(circle))
    .map(|(name, (r, c))| {
        let deviation = c.map(|c| (r[0] - c).abs().max((r[1] - c).abs()));
        (*name, r[0], r[1], c, deviation)
    })
    .collect();
let digits = serde_json::json!({ "significantDigits": 7 });
let columns = serde_json::json!([
    { "key": "0", "label": "量" },
    { "key": "1", "label": "最小", "type": "number", "format": digits },
    { "key": "2", "label": "最大", "type": "number", "format": digits },
    { "key": "3", "label": "円の値", "type": "number", "format": digits, "nullText": "なし" },
    {
        "key": "4",
        "label": "円の値からの最大のずれ",
        "type": "number",
        "format": { "notation": "scientific", "significantDigits": 3 },
        "nullText": "なし"
    }
]);
emit_table_with_columns!(columns, rows, metadata = serde_json::json!({ "id": "circle" }));
emit_line_chart!(
    &vec![
        serde_json::json!({ "name": "NURBS", "points": points }),
        serde_json::json!({
            "name": "半径 r の円弧（参照）",
            "points": reference,
            "style": { "lineType": "dashed" }
        }),
    ],
    options = &serde_json::json!({
        "xLabel": "x [m]",
        "yLabel": "y [m]",
        "xMin": 0,
        "xMax": 3,
        "yMin": 0,
        "yMax": 3
    })
);
```

既定の $r = 1$、$m = 1$ では、原点からの距離の最大のずれは $1.1 \times 10^{-16}$ m で、曲率は 101 点すべてで $1/r = 1$ と丸め誤差の範囲で一致し、曲線は参照の円弧に重なる。
一方、速さ $|R'(t)|$ は $\sqrt{2} = 1.414$ から $1.657$ まで変わり、$t$ は弧長に比例しない。
同じ $t$ で描いた参照の円弧の点とは位置がずれるので、円かどうかは点の対応ではなく距離と曲率で判断する。
半径を 0.5 m や 3 m にしても、距離のずれは $10^{-16}$ m の程度で、曲率は $1/r$（2 と 0.333 [1/m]）に一致する。
倍率を $m = 0.5$ にすると距離のずれは 0.108 m、曲率は 0.5 から 4 [1/m] に広がり、$m = 1.5$ ではずれ 0.071 m、曲率 0.444 から 1.5 [1/m] になる。
中央の重みを $1/\sqrt{2}$ からずらすと、曲線は同じ制御点を持つ別の円錐曲線になる。
端の重みが 1 の 2 次の有理 Bézier 曲線は、中央の重み $w$ が $w < 1$ なら楕円（$w = 1/\sqrt{2}$ で円）、$w = 1$ なら放物線、$w > 1$ なら双曲線の一部である。
NURBS の媒介変数は弧長とは限らないので、曲率は速さを含む上の式で求める。

## まとめ

B スプラインの滑らかさは次数とノットの多重度で決まり、多重度 $k$ のノットでの接続は $C^{p-k}$ までである。
ノットの上で導関数を求めるときは `derivative` に `KnotSide` を明示するか、`None` で通常の導関数の存在を確かめる。
制御値を直接与える `BSpline::new` と、標本を通す係数を求める `TensorSplineInterpolationPlan` を区別し、補間の節点は Schoenberg–Whitney 条件を満たすように（例えば Greville 点に）置く。
格子の標本は最後の軸が最速の順に並べ、値だけを変えて繰り返すなら、`workspace_requirements` が返す要求量で作業領域を `try_reserve` しておき、`fit_into` で確保なしに解く。
円弧や円錐曲線には正の重みの `Nurbs` を使い、媒介変数は弧長ではないので、曲率は速さを含む式で求める。
