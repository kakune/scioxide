補間では標本 $(x_i, y_i)$ に対して $s(x_i) = y_i$ を課す。
近似や平滑化では残差と複雑さの釣り合いから $s$ を選び、標本での一致を必須にしない。
どちらでも、標本の間の真の誤差は標本での残差だけからは分からない。
各ページでは仮定を明示し、数学的な導出と API の約束事を分けて説明する。

## 記号と入力の形

| 記号 | 意味 |
|---|---|
| $x$、$\boldsymbol{x}$ | 実数の座標（1 次元、多次元） |
| $y_i$、$f_i$ | 標本値（実数、複素数、配列、ベクトル） |
| $n$ | 標本数、節点数または制御値の数（各ページで定める） |
| $p$ | 多項式・スプラインの次数 |
| $D$ | 座標の次元 |
| $d$ | 値の実数成分の数（複素数の値は 2）。Floater–Hormann 補間では混合の次数 |
| $h$ | 節点の間隔の最大値 |

座標はつねに実数である。
複素数の値は実部と虚部の 2 成分として扱い、座標の次元は増えない。
例外は複素平面の有理関数で、`[実部, 虚部]` の 2 座標で問い合わせる形も持つ。
配列やベクトルの値の成分順、テンソルの軸順、格子の標本の並びは、各方式の入力の約束事で固定する。

節点が相異なること、順序、有限性、重みの正負、数値ランクは別々の条件である。
`NodeSeparation` は節点の分離を判定する方針であり、許容誤差を使った重複の判定と近似誤差を混同しない。
1 次元と格子の補間器では、この方針を `SampleOptions` に入れてオプション付き形式 `with_options` に渡す。
重複点を統合する散在点の分割では、統合後の点と標本値の対応も必要になる。

## 構築の形

補間器は標本から次のどれかの形で作る。

- 標準形式 `new(data)` は標本だけを受け取り、設定を rustdoc に書かれた既定値に固定する。
  例えば `CubicSpline::new` は not-a-knot の端、`AkimaInterpolator::new` は Akima の元の重みを使う。
- オプション付き形式 `with_options(data, options)` は設定を値で受け取る。
  設定の型は `Default` を実装し、1 次元と格子の補間器では節点の分離だけを持つ `SampleOptions` である。
- 実行スコープを受け取る `build(data, options, scope)` は、呼び出し側の求解の中で構築を数える。
  スコープは最上位の求解の `ExecutionContext` か、外側の求解の `&mut SolveContext` で、後者では数えた量が外側の上限に入る。
  `RbfInterpolator`、`GaussianProcessModel`、`LocalRbfModel` は構築を 1 回の提案、`LocalPolynomialModel` は試した近傍と次数ごとに 1 回の提案、`PadeApproximant` は 1 回の反復、`CloughTocherInterpolator` は 1 回の提案と掃引ごとに 1 回の反復として数える。
  `PenalizedSplinePlan` と `SphericalSplinePlan` は分解を子のスコープで行う。
  反復で当てはめる関数では `aaa_into`、`fit_parametric_spline_scoped`、`fit_spherical_spline_scoped` が同じ役割を持つ。
- 名前付きの構築関数は別の種類の準備を選ぶ。
  `CubicSpline::with_boundary`、`AkimaInterpolator::with_method`、`BicubicInterpolator::monotone`、`BarycentricInterpolator::from_chebyshev_lobatto`、`BSpline::linear` がこれに当たる。
- ワンショット関数は準備から結果までを一度に行う。
  `BSpline::interpolate` はテンソル格子の標本を各軸で同じ奇数次 $p$ の not-a-knot の基底で補間し（$p = 3$ なら各軸が not-a-knot の 3 次スプライン）、`interpolate_scattered` は散在点の Delaunay 分割を作って問い合わせの組を単体線形補間で評価する。

結果を決める量で中立な既定値を持たないもの（RBF の核、Floater–Hormann の混合の次数、Hermite 補間の導関数の標本）は、設定ではなく標本と並ぶ引数である。
局所モデルの設定は例外で、`LocalPolynomialOptions::new` は次数と近傍の数、`LocalRbfOptions::new` は近傍の数と核というモデルを決める量を受け取り、どちらも `Default` を持たない。
反復で当てはめる `aaa`、`fit_parametric_spline`、`fit_spherical_spline` と `CloughTocherInterpolator::new` は、反復が目標に達したときだけモデルを返し、それ以外は `ConvergenceFailure` を返す。
これらのオプション付き形式はモデルをレポート（`RationalReport`、`AdaptiveSplineReport`、`CloughTocherReport`）とともに返し、未達の終了状態はレポートの `termination()` で示す。
終了状態の型 `RationalTermination`、`AdaptiveSplineTermination`、`CloughTocherTermination` は `is_success()` で目標に達したかを返す。

## 領域と外挿

1 次元の区間、直交格子の箱、散在点の凸包、球面の角度の領域は異なる。
`RbfInterpolator` の領域は点の凸包ではなく、点を囲む長方形である。
`ExtrapolationPolicy` はそれぞれの方式の領域に対して適用され、暗黙の既定値はない。
1 変数の補間器のスカラー形 `value_at`・`values_at`・`derivative_at`・`integrate`（トレイト `Univariate`）は方針を取らず、`Reject` と同じく定義域の外を拒否する。
`Clamp` の微分は射影との合成の微分であり、境界での式を単に延長したものではない。
`BoundedContinue` と `MethodDefined` を指定しても、方式が対応しない外挿や数値的な破綻はエラーになる。
たとえば自然近傍補間は凸包の外で `Clamp` だけを受け付け、球面スプラインは余緯度を $[0, \pi]$ の外へ延長しない。
各方針の動作は[外挿と座標のレポート](oxref:interp-extrapolation-report)、微積分での扱いは[補間の導関数と積分](./derivatives-integrals-and-workspaces/)にまとめてある。

## 誤差と計算コスト

補間誤差、丸め誤差、推定した条件数、統計的な予測分散は異なる量である。
理論の誤差式に未知の高階導関数が含まれるとき、その式だけでは計算後の誤差の上界は得られない。
反復の終了状態も標本での残差や勾配の変化に対する判定として解釈する。
1 次元の各手法の連続性と誤差の次数は、[1 次元手法の性質](oxref:interp-choosing-one-dimensional)の表で比べる。

構築・当てはめ・問い合わせの計算コストは分けて比べる。
分解を保持する Plan は同じ標本位置での再計算を速めるが、保持する分のメモリを要する。
事前確保した作業領域を使う問い合わせと、所有する出力を作る便利な形も区別する。
共通の考え方は[作業領域と再現性](../../concepts/workspaces-and-reproducibility/)にある。

## まとめ

標本への一致と、未知の関数への近さを分けて考え、標本での残差を標本の間の誤差の上界として読まない。
領域（区間・箱・長方形・凸包・球面）、値の形、必要な導関数を決めてから方式を選び、外挿方針は評価のたびに渡す。
反復で当てはめる準備では、オプション付き形式のレポートの `termination()` と `is_success()` で目標に達したかを確かめる。
計算量は準備と繰り返しの問い合わせに分けて比べ、求解の中で数える必要があれば `build` や `*_scoped` の形を使う。
