この表は補間器の種類によらない共通の仕様をまとめる。
評価の機能は四つのトレイトに分かれる。
`Interpolant` が値、`Differentiable` が勾配、`TwiceDifferentiable` が Hessian、`Integrable` が箱領域の定積分を表す。
補間器は実際に持つ対応機能を表すトレイトだけを実装するので、機能のない組み合わせはコンパイル時に拒否される。

勾配は重心形式・Newton・Hermite、Akima・PCHIP・3 次スプライン、B スプライン・NURBS、双 3 次、単体線形、Clough–Tocher、球面スプラインが返す。
Hessian は B スプライン・NURBS・双 3 次・球面スプラインが返し、定積分は Akima・PCHIP・3 次スプライン・B スプライン・球面スプラインが返す。
Neville、Bulirsch–Stoer、Floater–Hormann、`BarycentricRational`、Padé、双線形、RBF、最近傍、自然近傍、局所モデル、Gauss 過程の予測は値だけを返す。
大域多項式（重心形式・Newton・Hermite）の定積分は `Integrable` ではなく、`prepare_antiderivative` で準備した原始関数から求める。
1 変数の補間器にはどれも、外挿の方針を `Reject` に固定したスカラー形のトレイト `Univariate` が実装されている。

外挿の方針に既定値はなく、方針を取る呼び出しごとに指定する。
境界上の点は定義域の内側として扱い、定義域は区間・箱・凸包など手法ごとに決まる。

作業領域は二層ある。
一点の評価では補間器の `workspace()` で作った作業領域を `evaluate_into` などへ渡す。
バッチ評価では、`BatchEvaluator::workspace(request)` がワーカーごとのモデル用作業領域と全結果の一時格納をまとめて事前確保する。
どちらも事前確保後は確保せず、失敗した呼び出しは呼び出し側の出力を変えない。
作業領域を持たない所有値を返す API の `evaluate_many` は、呼び出しのたびに一つの作業領域と値の配列を確保する。
作業領域と部分結果の一般的な扱いは[作業領域と再現性](../../../concepts/workspaces-and-reproducibility/)と[エラーと部分結果](../../../concepts/errors-and-partial-results/)にまとめてある。

## 一点の評価と座標のレポート

次のセルは $p(x) = (x, x^2)$ を 3 点 $x = 0, 1, 2$ で通る Newton 補間を、一点だけ評価する。
値は 2 成分のベクトルで、成分順は $x$、$x^2$ である。
補間器の `workspace()` で作った作業領域と呼び出し側の配列 `[f64; 2]` を `evaluate_into_with_report` に渡し、値と座標のレポートを同時に受け取る。
操作入力は評価位置 $x$（無次元、$-0.5$ から $2.5$）と外挿の方針である。
`BoundedContinue` の上限は $0.25$ に固定した。
3 点の 2 次補間は 2 次式を厳密に再現し、Newton 形式の延長も同じ 2 次式なので、レポートの座標 $t$ を使った $(t, t^2)$ を独立な検算値にする。

```rust
//|       - {"artifact":"point","path":"/rows/0/1","equals":0}
//|       - {"artifact":"point","path":"/rows/0/2","approx":{"value":0.5,"atol":1e-15}}
//|       - {"artifact":"point","path":"/rows/0/4","approx":{"value":0,"atol":1e-15}}
//|   - case: method-defined
//|     expect:
//|       - {"artifact":"point","path":"/rows/0/1","approx":{"value":2.3,"atol":1e-15}}
//|       - {"artifact":"point","path":"/rows/0/2","approx":{"value":0.3,"atol":1e-12}}
//|       - {"artifact":"point","path":"/rows/0/4","approx":{"value":5.29,"rtol":1e-14}}
//|       - {"artifact":"point","path":"/rows/0/5","range":{"max":1e-14}}
//|   - case: bounded-too-far
//|     expect:
//|       - {"artifact":"point","path":"/rows/0/1","equals":null}
//|       - {"artifact":"point","path":"/rows/0/3","equals":null}
//|       - {"artifact":"point","path":"/rows/0/6","equals":"DomainError"}
use scioxide_interp::{ExtrapolationPolicy, Interpolant, NewtonInterpolator};

// p(x) = (x, x²) を 3 点で通る Newton 補間。成分順は (x, x²)、定義域は [0, 2]
let model = NewtonInterpolator::new(
    vec![0.0_f64, 1.0, 2.0],
    vec![[0.0, 0.0], [1.0, 1.0], [2.0, 4.0]],
)
.map_err(|e| e.to_string())?;
let extrapolation = match policy.as_str() {
    "bounded" => ExtrapolationPolicy::BoundedContinue { max_distance: 0.25 },
    "method" => ExtrapolationPolicy::MethodDefined,
    _ => ExtrapolationPolicy::Clamp,
};
// 一点用の作業領域を一度作り、呼び出し側の配列へ書く。失敗したら value は変わらない
let mut workspace = model.workspace().map_err(|e| e.to_string())?;
let mut value = [0.0; 2];
let evaluated =
    model.evaluate_into_with_report([query_x], extrapolation, &mut value, &mut workspace);
let row = match evaluated {
    Ok(report) => {
        let [effective] = report.effective();
        let [distance] = report.outside_distance();
        // 独立検算: 使った座標 t での厳密値は (t, t²)
        let check = (value[1] - effective * effective).abs();
        (
            query_x,
            Some(effective),
            Some(distance),
            Some(value[0]),
            Some(value[1]),
            Some(check),
            None,
        )
    }
    Err(e) => (
        query_x,
        None,
        None,
        None,
        None,
        None,
        Some(format!("{:?}", e.kind())),
    ),
};
let fixed3 = serde_json::json!({ "fractionDigits": 3 });
let sig = serde_json::json!({ "significantDigits": 15 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "x [-]", "type": "number", "format": fixed3 },
    { "key": "1", "label": "使った座標 t [-]", "type": "number", "format": sig, "nullText": "—" },
    { "key": "2", "label": "定義域外の距離 [-]", "type": "number", "format": sig, "nullText": "—" },
    { "key": "3", "label": "第一成分 [-]", "type": "number", "format": sig, "nullText": "—" },
    { "key": "4", "label": "第二成分 [-]", "type": "number", "format": sig, "nullText": "—" },
    { "key": "5", "label": "第二成分と t² の差 [-]", "type": "number", "format": sci3, "nullText": "—" },
    { "key": "6", "label": "エラーの分類", "nullText": "—" }
]);
emit_table_with_columns!(
    columns,
    vec![row],
    metadata = serde_json::json!({ "id": "point" })
);
```

既定値の $x = 2.3$ と `Clamp` では、使った座標は $t = 2$、距離は約 $0.3$（$2.3$ の 2 進表現の丸めを含み、$0.2999999999999998$）になる。
値は境界での値 $(2, 4)$ で、`Clamp` が問い合わせを境界へ射影したことがレポートから読める。
`MethodDefined` に切り替えると射影は起こらず、$t = 2.3$、値は $(2.3, 5.29)$ になり、距離の列は同じ $0.3$ を示す。
`BoundedContinue`（上限 $0.25$）では距離 $0.3$ が上限を超えるので `DomainError` になり、値もレポートも返らない。
レポートの座標を作る段階で距離を上限と比べるので、上限を超えた問い合わせは評価の前に拒否される。
$x$ を $[0, 2]$ の中へ動かすと、どの方針でも $t = x$、距離 0 になり、二つの成分は $x$ と $x^2$ に丸めの程度で一致する。

## バッチ評価の全件成功と失敗

次のセルは同じモデルを `BatchEvaluator::new(&model, ExecutionPolicy::Sequential)` で 3 点ずつ 2 回評価し、失敗したバッチが出力を変えないことを確かめる。
問い合わせは `[問い合わせ, 座標]` = `[3, 1]`、出力は `[問い合わせ, 成分]` = `[3, 2]` の行優先の配列である。
作業領域は `BatchRequest::values(3)` で一度だけ事前確保し、2 回の評価で使い回す。
1 回目は定義域内の $x = 0, 0.5, 2$ を評価する。
2 回目は $x = 1, 1.5$ と、操作入力の第 3 点（無次元、$1.5$ から $3$）を `Reject` で評価する。
第 3 点が $[0, 2]$ の外なら 2 回目は `DomainError` になり、出力は 1 回目の値のまま残るはずである。

```rust
//| id: interp-affine-batch-transaction
//| ref: interp-affine-batch-transaction
//| title: 失敗したバッチが呼び出し側の出力を保つことを確かめる
//| run: reactive
//| crates: [scioxide-core, scioxide-interp]
//| inputs:
//|   third_x: {"type":"range","label":"2 回目の第 3 点 x [-]","min":1.5,"max":3,"step":0.25,"value":2.5}
//| cases:
//|   - {"id":"boundary","label":"第 3 点 x = 2（境界）","description":"境界上の点は定義域の内側なので、2 回目も成功して出力が更新される。","inputs":{"third_x":2}}
//|   - {"id":"inside","label":"第 3 点 x = 1.5","description":"全件が定義域内なので、出力は 2 回目の (x, x²) に更新される。","inputs":{"third_x":1.5}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"status","path":"/rows/0/0","equals":"失敗"}
//|       - {"artifact":"status","path":"/rows/0/1","equals":"DomainError"}
//|       - {"artifact":"batch","path":"/rows/0/4","equals":0}
//|       - {"artifact":"batch","path":"/rows/1/5","approx":{"value":0.25,"atol":1e-15}}
//|       - {"artifact":"batch","path":"/rows/2/5","approx":{"value":4,"atol":1e-14}}
//|   - case: boundary
//|     expect:
//|       - {"artifact":"status","path":"/rows/0/0","equals":"成功"}
//|       - {"artifact":"batch","path":"/rows/0/5","approx":{"value":1,"atol":1e-14}}
//|       - {"artifact":"batch","path":"/rows/2/5","approx":{"value":4,"atol":1e-14}}
//|   - case: inside
//|     expect:
//|       - {"artifact":"status","path":"/rows/0/0","equals":"成功"}
//|       - {"artifact":"batch","path":"/rows/1/5","approx":{"value":2.25,"atol":1e-14}}
//|       - {"artifact":"batch","path":"/rows/2/4","approx":{"value":1.5,"atol":1e-15}}
use scioxide_core::{ExecutionContext, ExecutionPolicy, NdView, NdViewMut, StridedLayout};
use scioxide_interp::{BatchEvaluator, BatchRequest, ExtrapolationPolicy, NewtonInterpolator};

// p(x) = (x, x²) を 3 点で通る Newton 補間。定義域は [0, 2]
let model = NewtonInterpolator::new(
    vec![0.0_f64, 1.0, 2.0],
    vec![[0.0, 0.0], [1.0, 1.0], [2.0, 4.0]],
)
.map_err(|e| e.to_string())?;
let policy = ExtrapolationPolicy::Reject;
// 補間器を借用して逐次実行（1 ワーカー）の評価器に結び付ける
let evaluator = BatchEvaluator::new(&model, ExecutionPolicy::Sequential);
// 3 点の値のバッチに合わせて作業領域を一度だけ事前確保し、2 回の評価で使い回す
let mut workspace = evaluator
    .workspace(BatchRequest::values(3))
    .map_err(|e| e.to_string())?;
// 問い合わせは [3, 1]、出力は [3, 2] の行優先
let query_layout = StridedLayout::new(&[3, 1], &[1, 1]).map_err(|e| e.to_string())?;
let output_layout = StridedLayout::new(&[3, 2], &[2, 1]).map_err(|e| e.to_string())?;
let mut values = [0.0; 6];

// 1 回目: 定義域内の 3 点
let first_points = [0.0, 0.5, 2.0];
let first = NdView::new(&first_points, query_layout).map_err(|e| e.to_string())?;
{
    let mut out = NdViewMut::new(&mut values, output_layout).map_err(|e| e.to_string())?;
    evaluator
        .evaluate_into(
            &first,
            policy,
            &mut out,
            None,
            &mut workspace,
            ExecutionContext::sequential_native(),
        )
        .map_err(|e| e.to_string())?;
}
let after_first = values;

// 2 回目: 第 3 点だけを操作入力にする。[0, 2] の外なら Reject でバッチ全体が失敗する
let second_points = [1.0, 1.5, third_x];
let second = NdView::new(&second_points, query_layout).map_err(|e| e.to_string())?;
let outcome = {
    let mut out = NdViewMut::new(&mut values, output_layout).map_err(|e| e.to_string())?;
    evaluator.evaluate_into(
        &second,
        policy,
        &mut out,
        None,
        &mut workspace,
        ExecutionContext::sequential_native(),
    )
};
let status = match outcome {
    Ok(()) => ("成功", None),
    Err(e) => ("失敗", Some(format!("{:?}", e.kind()))),
};
emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "2 回目のバッチ" },
        { "key": "1", "label": "エラーの分類", "nullText": "—" }
    ]),
    vec![status],
    metadata = serde_json::json!({ "id": "status" })
);

// 独立検算: 各行の第二成分は、その行の値を書いた評価の x の 2 乗に等しい
let rows: Vec<_> = (0..3)
    .map(|row| {
        (
            row + 1,
            first_points[row],
            after_first[2 * row + 1],
            second_points[row],
            values[2 * row],
            values[2 * row + 1],
        )
    })
    .collect();
let digits = serde_json::json!({ "significantDigits": 15 });
let columns = serde_json::json!([
    { "key": "0", "label": "行", "type": "integer" },
    { "key": "1", "label": "1 回目の x [-]", "type": "number", "format": digits },
    { "key": "2", "label": "1 回目の後の第二成分 [-]", "type": "number", "format": digits },
    { "key": "3", "label": "2 回目の x [-]", "type": "number", "format": digits },
    { "key": "4", "label": "2 回目の後の第一成分 [-]", "type": "number", "format": digits },
    { "key": "5", "label": "2 回目の後の第二成分 [-]", "type": "number", "format": digits }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "batch" })
);
```

既定値の第 3 点 $x = 2.5$ では 2 回目が `DomainError` になり、2 回目の後の列は 1 回目の値 $(0, 0)$、$(0.5, 0.25)$、$(2, 4)$ のままである。
第 1・第 2 点は定義域内でも書き込まれず、失敗したバッチの一部だけが出力に残ることはない。
第 3 点を $2$ 以下にすると 2 回目は成功し、各行は $(x, x^2)$ に更新される。
$x = 2$ は定義域の境界上にあり、閉じた定義域の内側として扱われるので、`Reject` でも評価できる。
この仕様があるので、呼び出し側は失敗したバッチの結果を部分的に採用せずに済む。

## まとめ

勾配・Hessian・定積分が要るときは、補間器が `Differentiable`・`TwiceDifferentiable`・`Integrable` を実装しているかを最初に確かめる。
外挿の方針は呼び出しごとに渡し、`Clamp` などで延長した値を使うときは `report` か `evaluate_into_with_report` で使った座標と定義域の外の距離を確かめる。
一点の評価を繰り返すなら補間器の `workspace()` を一度作って `evaluate_into` に渡し、多数の点は `evaluate_many` で値の配列を受け取るか、`BatchWorkspace` を事前確保して `BatchEvaluator::evaluate_into` で呼び出し側の配列へ書く。
どちらも失敗時は出力を変えないので、エラーのときは出力を使わずに分類 `e.kind()` を読めばよい。
