`scioxide-linalg` のアルゴリズムは連立一次方程式、最小二乗問題、固有値問題、行列関数と行列方程式の四つの問題を、直接法と反復法の両方で扱う。
このページには各ページで共通に使う記号と誤差の測り方、呼び出しの形と実行の制御、分解と解の受理を分ける規約、失敗したときの出力の規則をまとめ、どのページで何を扱うかを示す。

## 記号

本書全体の記号と用語は[数値計算の記号と用語](../../reference/)に従う。
この章では行列を $A, B$、ベクトルを $x, b$ のように細字で書き、これは記号の一覧の $\mathbf{A}$、$\mathbf{x}$ と同じものである。

| 記号 | 意味 |
|---|---|
| $\mathbb{K}$ | スカラーの体。$\mathbb{R}$（`f32`、`f64`）か $\mathbb{C}$（`Complex<f32>`、`Complex<f64>`） |
| $A^{\mathsf T}, A^{\mathsf H}$ | 転置と共役転置（随伴） |
| $\hat x$ | 計算で得た近似解。$x$ は格納された $A$、$b$ についての厳密解 |
| $\varepsilon$、$u = \varepsilon/2$ | 機械イプシロン（記号の一覧の $\epsilon_{\mathrm{mach}}$）と単位丸め。倍精度で $u = 2^{-53} \approx 1.1 \times 10^{-16}$、単精度で $2^{-24} \approx 6.0 \times 10^{-8}$ |
| $\gamma_k = k u / (1 - k u)$ | $k$ 回の丸めが積み重なった相対誤差の上限（$k u < 1$ のとき） |
| $\lVert \cdot \rVert_1$、$\lVert \cdot \rVert_2$、$\lVert \cdot \rVert_\infty$、$\lVert \cdot \rVert_F$ | 1 ノルム（行列では列の絶対値の和の最大）、2 ノルム、$\infty$ ノルム（行列では行の絶対値の和の最大）、Frobenius ノルム |
| $\sigma_1 \ge \dots \ge \sigma_n$ | 特異値 |
| $\kappa(A) = \lVert A \rVert \lVert A^{-1} \rVert$ | 条件数。ノルムを $\kappa_1$、$\kappa_2 = \sigma_1 / \sigma_n$、$\kappa_\infty$ のように添字で示す |
| $\mathrm{rcond}_1 = 1/\kappa_1(A)$ | 逆条件数。直接法の `condition_estimate` が推定する量 |
| $\lvert A \rvert$ | 成分ごとの絶対値をとった行列 |

浮動小数点数と条件数の一般論は[浮動小数点数と条件数](../../concepts/floating-point-and-conditioning/)にある。

## 誤差の測り方

$Ax = b$ の近似解 $\hat x$ の良さは、次の三つの量で測り分ける。

| 量 | 定義 | 何が分かるか |
|---|---|---|
| 残差 | $r = b - A\hat x$ | $\hat x$ から直接計算できる。$A$ と $b$ の尺度に依存する |
| 後退誤差 | $\eta = \lVert r \rVert / (\lVert A \rVert \lVert \hat x \rVert + \lVert b \rVert)$ | $\hat x$ がどれだけ近い問題の厳密解か。アルゴリズムの安定性を表す |
| 前進誤差 | $\lVert \hat x - x \rVert / \lVert x \rVert$ | 厳密解からの相対的なずれ。$\kappa(A)\,\eta < 1$ のとき $2\kappa(A)\,\eta / (1 - \kappa(A)\,\eta)$ 以下 |

後退誤差が $u$ の程度に小さいアルゴリズムを後退安定という。
後退安定なアルゴリズムでも、前進誤差は条件数の分だけ大きくなりうるので、残差が小さいことだけでは解が正確だとは言えない。
上の前進誤差の上界は格納された $A$ と $b$ を基準にした相対誤差の上界である。
入力そのものに丸めや測定の誤差があれば、その分は別に加わる。
成分ごとの後退誤差（Oettli–Prager）は[混合精度の反復改良と後退誤差](iterative-refinement/)で扱う。

## 呼び出しの形と実行の制御

各アルゴリズムページは一つの計算をいくつかの形で呼ぶ API を説明し、形は名前の末尾で区別する。
問題のデータだけを取る標準形式（`factor(&a)`、`solve(&b)`、`norm2()`）、設定を最後の引数に取るオプション付き形式（`*_with_options`）、呼び出し側の出力・作業領域・コンテキストを取る出力先を指定する API（`*_into`）、値を返す演算がコンテキストを取るスコープ付き API（`*_scoped`）がある。
このほかに、答えだけを返すワンショット関数（`solve`、`least_squares` など）、作るときに再利用するデータを計算する Plan（`…Plan`）、設定だけを持つ手法オブジェクト（`ExponentialAction`、`CgSolver` など）がある。
定義と使い分けは[作業領域・実行コンテキスト・試行記録](oxref:linalg-execution-forms)にある。

標準形式とオプション付き形式（まとめて所有値を返す API）とワンショット関数は、クロックも取り消しも持たない `ExecutionContext::sequential_native()` で逐次に実行する。
そのため、所有値を返す API に時間上限を設定すると `CapabilityUnavailable` になり、並列実行、取り消し、期限、外部 BLAS プロバイダーは出力先を指定する API とスコープ付き API でだけ使える。
実行の制御は `LinalgExecutionOptions` の一つの値にまとまり、実行方針、積の精度階層、経過時間とバイト数の上限、反復の上限を持つ。
各手法のオプションは `with_execution_options` でこれを一度だけ合成し、残りの欄には数学的な設定だけを持つ。

## 分解と受理を分ける規約

分解の構築は構造上の判断だけを行い、数値ランクのしきい値を暗黙に使わない。
構築が拒否するのは、形状の誤り、非有限な成分、明示された構造（Hermitian など）の違反、厳密に 0 のピボットのような代数的な破綻と、因子の成分のあふれだけである。
Cholesky・LDL・Hermitian 固有値問題では、入力を Hermitian 行列とみなす方法を `HermitianInput` で必ず指定する。
選べるのは、厳密な対称性を要求する `Exact`、片方の三角だけを読む `Triangle`、$(A + A^{\mathsf H})/2$ へ明示的に射影する `Projected` の三つである。
得られた結果を数値的にどう解釈するかは、呼び出し側が渡す次の値で決まる。

- `RankPolicy`：特異値や因子の対角をランクとして数える規則。
  `Exact`（厳密に 0 の値だけを除く）、`DimensionScaledEpsilon`（$\min(\max(m, n)\,\varepsilon,\ 1/2) \times$ 最大値をしきい値にする）、`Threshold`（core の `RankThreshold` による絶対・相対しきい値）がある。
  結果は `RankReport`（ランク、最大ランク、しきい値、尺度）で返る。
- `ConditionEstimate`：しきい値によらない逆条件数の推定値と、その信頼度（`EstimateReliability` の `Heuristic` など）の組。
  LU や Cholesky の `condition_estimate` は元の座標の $1/\kappa_1(A)$ を推定し、次数 4 以下では $\lVert A^{-1} \rVert_1$ を逆行列の各列から計算し、それより大きい次数では Hager の方法を Higham が改良した方法で推定する。
  この推定値は正確な算術では $\lVert A^{-1} \rVert_1$ の下界で、多くの場合は真の値の 10 分の 1 以上になるが、そのことは保証されない。
- `DirectSolveOptions`：分解から解くときの受理の条件。
  ランクの方針、任意の逆条件数の下限 `ReciprocalConditionThreshold`、後退誤差の診断を計算するか（`with_residual`、既定は `Estimation::Skip`。
  返すだけで解を拒否しない）、実行の制御（`with_execution_options`）を持つ。
  条件数の推定は下限を指定したときだけ行う。
  `DirectSolveOptions::default()` は `RankPolicy::Exact` で、条件数の下限を持たず、後退誤差も計算しない。
- `DirectSolveResult` と `DirectSolveTermination`：オプション付き形式の `solve_with_options(&b, &options)` は方針による拒否をエラーにせず、`Ok` の結果で返す。
  レポート `DirectSolveReport` の終了理由が `Accepted` のときだけ、`solution()` が `Some` を返す。
  ほかの終了理由は `RankDeficient`（ランクの方針で不足と判定）、`IllConditioned`（逆条件数の推定値が下限未満）、`ResidualRejected`（元の方程式の残差が許容誤差を満たさない）、`StabilityRejected`（Riccati 方程式の解が閉ループの安定性の検証に失敗）である。
  `ResidualRejected` は Toeplitz などの構造行列、合成作用素、行列方程式の求解が使い、`StabilityRejected` は Riccati 方程式だけが使う。
  標準形式の `solve(&b)` とワンショット関数は `DirectSolveTermination::require_accepted` で拒否をエラーに変え、`RankDeficient` は `Singular`、ほかは `NumericalInstability` になる。
  `into_accepted()` はオプション付き形式の結果を同じ規則で変換する。
- `EquilibrationMetadata`：LU が分解の前に適用する、行と列の 2 の冪の尺度（`equilibration()`）。
  Cholesky も対称な 2 の冪の尺度 $DAD$ を内部で使う。
  どちらも、因子・解・診断は元の行列についての値で返す。

この分離により、方針を変えても分解の結果は変わらず、特異値などの生の値はいつでも読める。

## 失敗と出力の規則

失敗は `SciOxideError` で返り、`kind()` で分類を読む。
この章の機能が返す主な分類は次のとおりである。

| `kind()` | 起こる状況 |
|---|---|
| `DimensionMismatch` | 形状の不一致、正方であるべき行列が正方でない、出力や参照を渡した作業領域が小さい |
| `InvalidInput` | 範囲外の設定値、`HermitianInput::Exact` での厳密に Hermitian でない入力、求解の種類に合わない構造の行列 |
| `NonFinite` | 非有限な入力、作用素や前処理のコールバックが返した非有限値 |
| `Singular` | 厳密に 0 のピボット、標準形式の求解での `RankDeficient` |
| `DomainError` | 数値的に正定値でない入力の Cholesky、定義されない点（分岐の切断上など）に固有値を持つ行列の行列関数、空の行列への条件数の下限 |
| `NumericalInstability` | 結果（行列式、解、固有値）や因子の成分がスカラー型で表せない、固有ベクトルの残差や一次独立性の検査、Schur 形の並べ替えでの交換の失敗、標準形式の求解での `IllConditioned`・`ResidualRejected`・`StabilityRejected` |
| `ConvergenceFailure` | 固有値分解や SVD の内部反復が上限に達した、反復法の標準形式が許容誤差を満たさずに止まった、使える反復解がないまま反復法が止まった |
| `ExecutionStopped` | 出力先を指定する API とスコープ付き API での取り消しや期限 |
| `ResourceLimit`、`AllocationFailure` | 作業領域がバイト上限を超える、メモリ領域を確保できない |
| `CapabilityUnavailable` | 実行コンテキストが持たない機能の要求（所有値を返す API での時間上限、`BlasFallbackPolicy::Error` のもとでプロバイダーが受けられない呼び出しなど） |
| `CapabilityFailure` | 外部 BLAS プロバイダーがエラーを返したか、不正な値（負のノルム、範囲外の添字など）を書いた |

出力の扱いは次の規則に従う。

- 出力先を指定する API は、すべての検査と計算が成功してから出力を書き換え、失敗時や方針による拒否では出力を変えない。
- 反復解法のオプション付き形式と出力先を指定する API、作用素の作用と部分スペクトルの手法オブジェクト、反復改良は、上限・取り消し・漸化式の破綻・停滞で止まっても、意味のある途中結果があれば `Ok` で返す（反復解法では、真の残差を確かめた反復のうち最良のもの）。
  成否はレポートの終了理由で示すので、`Ok` を収束とみなさず、終了理由を読む。
  一つの右辺を解く反復解法の標準形式 `solve(a, b)` だけは、同じ停止を `ConvergenceFailure` のエラーにする。
- 要件を満たした作業領域と出力を渡せば、SciOxide の数値処理は確保を行わない（[作業領域・実行コンテキスト・試行記録](workspaces-and-execution/)）。

エラーの分類と部分結果の一般論は[エラー仕様と部分結果](../../concepts/errors-and-partial-results/)にある。

## まとめ

この章のアルゴリズムページは上の記号、残差・後退誤差・前進誤差の三つの量、分解と受理を分ける規約を前提にしている。
解の精度はレポートの後退誤差と逆条件数の推定値を組み合わせて見積もり、残差が小さいことだけで正確とはみなさない。
受理の条件を変えたり終了理由を読んだりするときはオプション付き形式を使い、標準形式とワンショット関数では拒否と非収束をエラーとして受け取る。
並列実行、取り消し、期限、外部 BLAS、確保のない繰り返しが必要なときは、出力先を指定する API とスコープ付き API に作業領域と実行コンテキストを渡す。
オプション付き形式・出力先を指定する API と反復法の結果は、`Ok` であることだけで成功とみなさず、終了理由の `is_success()` で成否を判定する。
