単精度（`f32`）の LU 分解は倍精度の半分のメモリ使用量で済み、多くの環境で速いが、解の精度は単精度の単位丸め $u_f = 2^{-24} \approx 6 \times 10^{-8}$ に制限される。
反復改良は低い精度の分解を補正の計算にだけ使い、残差と解の更新を高い精度で行うことで、条件が許す範囲で倍精度の後退誤差を回復する。
このページはその収束の条件と限界、誤差の測り方、`IterativeRefinement` の使い方を説明する。

---

## 反復改良の手順と収束条件

近似解 $x_k$ から次を繰り返す。

1. 残差 $r_k = b - A x_k$ を作業精度（倍精度、単位丸め $u$）で計算する。
2. 補正方程式 $A d_k = r_k$ を低い精度の分解で近似的に解く。
3. $x_{k+1} = x_k + d_k$ を作業精度で更新する。

ある $E_k$ について、計算した補正が $(A + E_k)\, d_k = r_k$ を満たし、$\lVert A^{-1} E_k \rVert \le \theta$ とする。
残差を厳密に計算した場合、$r_k = A(x - x_k)$ から

$$
x_{k+1} - x = -A^{-1} E_k (A + E_k)^{-1} r_k \quad\Rightarrow\quad
\lVert x_{k+1} - x \rVert \le \frac{\theta}{1 - \theta}\, \lVert x_k - x \rVert
$$

となるので、$\theta < 1/2$ なら誤差は一回ごとに縮む（残差の丸めの分は後で述べる限界に現れる）。
単精度の LU では $\theta$ はおよそ $c\,\kappa(A)\, u_f$（$c$ は $n$ と成長因子に依存する定数）なので、$\kappa(A) u_f$ が 1 より十分小さいこと、つまり $\kappa(A) \ll 1/u_f \approx 1.7 \times 10^{7}$ が収束の目安になる。
条件数がこれを超えると補正が誤差を減らさなくなり、改良は停滞する。

収束したときの限界は二つある。
後退誤差は作業精度の単位丸め $u$ の程度（倍精度で $10^{-16}$ 程度）まで下がる。
前進誤差の限界は残差をどれだけ正確に計算するかで決まる。
残差を作業精度の通常の演算で計算する改良では、前進誤差は後退誤差に条件数を掛けた $\kappa(A) u$ の程度で止まる。
`scioxide-linalg` は明示的な行列（下の `Dense` と `Sparse`）の残差を、各行の積和 $b_i - \sum_j a_{ij} x_j$ を丸めずに累積し、最後に一度だけ作業精度へ丸めて作る。
これは残差を作業精度より高い精度で計算する古典的な改良に当たり、$\kappa(A) u_f$ が 1 より十分小さい範囲では、格納された $A$ と $b$ の厳密解に対する前進誤差も理論上 $u$ の程度まで下がる。
ただし、$A$ と $b$ そのものに含まれる誤差（測定や丸め）が $\kappa(A)$ 倍に拡大される分は、改良では消せない。
行列を持たない作用素の系では残差を作業精度の作用から作るので、この利点はない。
解の更新はどちらの場合も作業精度で行う。

## ノルムごとと成分ごとの後退誤差

改良が目標にするのは、元の系についての後退誤差である。

$$
\eta_N = \frac{\lVert r \rVert_\infty}{\lVert A \rVert_\infty \lVert x \rVert_\infty + \lVert b \rVert_\infty}, \qquad
\eta_C = \max_i \frac{\lvert r_i \rvert}{(\lvert A \rvert \lvert x \rvert + \lvert b \rvert)_i}
$$

$\eta_N$（Rigal–Gaches）は $x$ を厳密解にする摂動を $A$ と $b$ のノルムに対する比で測った最小値、$\eta_C$（Oettli–Prager）は各成分に比例する摂動で測った最小値で、$\eta_N \le \eta_C$ が成り立つ。
成分の大きさが極端に異なる系や疎な系では、成分ごとの後退誤差が小さいことのほうが強い主張になる。
成分ごとの値は行列の成分が分かる場合だけ計算でき、行列を持たない作用素では計算しない。
どちらも浮動小数点で計算した推定値で、前進誤差の限界や区間による保証ではなく、前進誤差は条件数と組み合わせて初めて抑えられる。

## IterativeRefinement の入力と結果

改良の設定と、改良する系は別の値で渡す。
`IterativeRefinement::new(options)` は設定 `RefinementOptions` だけを持つ手法オブジェクトで、行列も因子も前もって計算しないので、同じ値を多くの問題に使える。
作るときに、因子の精度 `L` と残差の精度 `H` の組が `f32/f32`、`f64/f64`、`f32/f64` かその複素数版であることを検査し、それ以外は `InvalidInput`（`UnsupportedConfiguration`）にする。
系と逆作用素は `RefinementProblem::new(system, inverse, scaling, fallback)` にまとめ、呼び出しのたびに手法オブジェクトへ渡す。
`RefinementProblem::new` はそれらを借用し、形と有限性を検査する。
どちらも分解や行列の変換を暗黙には行わず、低い精度の分解は呼び出し側が作る。
以下では、低い精度の補正が失敗したときや改良が進まなくなったときに、作業精度の逆作用素へ一度だけ切り替えることを退避（fallback）と呼ぶ。

| 入力 | 型 | 役割 |
|---|---|---|
| `system` | `RefinementSystem` | 元の系（作業精度）。密行列 `Dense`、CSR 行列 `Sparse`、作用素と $\lVert A \rVert_\infty$ の正の上界の組 `Operator` |
| `inverse` | `&(dyn LinearOperator<L> + Sync)` | 補正に使う低い精度の逆作用素（例: `f32` の `LuDecomposition` の `inverse_operator()`） |
| `scaling` | `Option<&EquilibrationMetadata>` | 逆作用素が平衡化した系 $D_r A D_c$ を解く場合の 2 の冪の尺度 |
| `fallback` | `Option<&(dyn LinearOperator<H> + Sync)>` | 退避先。作業精度で平衡化しない元の系 $A^{-1}$ を作用させる逆作用素 |
| `options`（手法オブジェクト） | `RefinementOptions` | 許容誤差 `ResidualTolerance`、`with_criterion`（`RefinementCriterion::Normwise` が既定、`Componentwise`）、`with_fallback`（`RefinementFallback::Disabled` が既定、`OnFailure`）、`with_execution_options` |

収束の判定は、選んだ後退誤差が `ResidualTolerance` の $\tau_{\mathrm{abs}} + \tau_{\mathrm{rel}}$ 以下になることである（後退誤差はもともと相対量なので、尺度は 1 とする）。
補正回数の上限は `with_execution_options` に渡す `LinalgExecutionOptions` の反復上限 `with_iteration_budget` で決まり、右辺ごとに数え、退避後の補正も含めて既定は 10 回である。
同じ値のバイト上限が作業領域を制限し、実行方針・積の精度・時間上限がすべての改良に適用される。
所有値を返す API の `refine` は `ExecutionContext::sequential_native()` で動いてクロックを持たないので、時間上限を設定すると `CapabilityUnavailable` になる（所有値を返す API と出力先を指定する API は[呼び出しの形](oxref:linalg-execution-forms)で定義している）。

`EquilibrationMetadata::prepare(system)` は密行列か CSR 行列から、絶対値が最大の成分が $[1, 2)$ に入るように各行の 2 の冪を選び、続けて列の 2 の冪を選ぶ（作用素の系は拒否する）。
`scale_matrix_into(a, &mut low)` は尺度を掛けながら低い精度の行列へ書き込むので、単精度の範囲を超える大きな成分も変換であふれない（0 になってしまう成分があれば `NumericalInstability` で失敗する）。
各補正では平衡化した残差 $D_r r$ をその $\infty$ ノルムに近い 2 の冪で割ってから低い精度に丸め、補正を作業精度に戻してから尺度を掛け直す。
低い精度で表せずに消える成分は $\varepsilon_L \lVert D_r r \rVert_\infty$（$\varepsilon_L$ は低い精度の機械イプシロン）より小さいものに限り、それより大きな成分が表せない場合は変換の失敗として扱う。

`refine(&problem, rhs, initial)` は初期値を受け取り、改良した解と `RefinementReport` の組を返す。
出力先を指定する API の `refine_into(&problem, rhs, solution, &mut ws, cx)` は `solution` の各列を初期値として独立に改良し、列ごとのレポートを返す。
作業領域 `RefinementWorkspace` は `RefinementWorkspaceRequest::new(&problem).with_right_hand_sides(m)` を `workspace_requirements` に渡して得る `RefinementRequirements` で事前確保するか、`workspace(&request)` で作る。
`OnFailure` を選んで退避先を渡さない場合は `InvalidInput`（`Inconsistent`）、作用素の系で成分ごとの判定を選んだ場合は `InvalidInput`（`UnsupportedConfiguration`）で、どちらも要件を求める段階で拒否される。

各補正は選んだ後退誤差を厳密に下げた場合か許容誤差を満たした場合だけ採用する。
例外は成分ごとの判定で、低い精度で表せずに落とした残差の成分があり、後退誤差が横ばいでも残差のノルムが下がった補正も採用する。
後退誤差が下がらなかった補正は捨てて停滞とみなし、`OnFailure` なら一度だけ退避先に切り替え、そうでなければ `Stagnation` で止まる。
残差の変換に失敗した場合と、低い精度の逆作用素が `NumericalInstability` か `Singular` を返した場合も、`OnFailure` なら退避し、そうでなければ `CorrectionFailed` で止まる。

成否はレポートの `termination()` か `is_success()` で判定する。
終了理由 `RefinementTermination` の値と、セルの outcome への対応は次のとおりである。

| 終了理由 | 意味 | outcome |
|---|---|---|
| `Converged` | 選んだ後退誤差が許容誤差を満たした（`is_success()` が真になる唯一の値） | satisfied |
| `Stagnation` | 補正が後退誤差を下げなかった | partial |
| `IterationLimit` | 右辺あたりの補正回数の上限に達した | partial |
| `EvaluationLimit` | 評価の上限で残差か逆作用素を計算できなかった | partial |
| `ExecutionStopped(reason)` | 取り消しか期限で止まった | partial |
| `CorrectionFailed` | 低い精度への変換か補正の計算が失敗し、退避も許されていなかった | failed |

成功しなかった場合も、それまでに採用した最良の反復解を出力に反映して `Ok` を返す。
取り消しや期限で止まった場合も、エラーではなく `ExecutionStopped` のレポートになる。
レポートは試みた補正の回数 `iterations()`（採用しなかった補正を含む）、初期値と返した解の後退誤差 `initial_error()` と `final_error()`、退避の理由 `fallback_reason()`、退避先の呼び出し回数 `fallback_iterations()`、使った精度 `factor_precision()` と `residual_precision()` も持つ。
後退誤差の値 `BackwardError` は `normwise()`、`componentwise()`（作用素の系では `None`）、作用素の系で $\lVert A \rVert_\infty$ の代わりに上界を使ったかどうかの `uses_operator_bound()` を持つ。
退避の理由 `RefinementFallbackReason` は `Conversion`（変換に失敗した）、`NumericalFailure`（低い精度の逆作用素が数値的に失敗した）、`Stagnation`（停滞した）のどれかである。

## 条件数を変えた実験

次のセルは特異値を 1 から $10^{-t}$ まで等比に並べた $40 \times 40$ 行列 $A = H_u \Sigma H_v$（$H_u, H_v$ は Householder 鏡映）で $Ax = b$、$x^{\star} = (1, \dots, 1)$ を解く。
鏡映は直交行列なので、$\kappa_2(A) = 10^{t}$ が厳密に決まる。
平衡化した $A$ を `f32` に変換して LU 分解し、初期値 0 から `IterativeRefinement` で改良する。
入力はグラフと outcome に使う条件数の指数 $t$、停止の判定（許容誤差 $10^{-15}$ と比べる後退誤差の種類）、`f64` の LU への退避を許すかどうかである。
表は $t = 0, \dots, 10$ について最大 10 回まで改良した結果で、前進誤差は $x^{\star}$ との差、$\kappa_2 u$ はその参照値である。
グラフは選んだ $t$ で最大補正回数 $k$ を $1, \dots, 10$ と変えたときの後退誤差を示し、横線は許容誤差を表す。
outcome は選んだ $t$ を最大 10 回まで改良した終了理由を上の表の対応で示す。

```rust
//| id: linalg-mixed-precision-refinement
//| ref: linalg-mixed-precision-refinement
//| title: f32 の LU と f64 の残差による反復改良
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg]
//| inputs:
//|   condition_exponent: {"type":"range","label":"条件数 κ₂ = 10^t の t","description":"グラフと outcome に使う行列の条件数。","min":0,"max":10,"step":1,"value":8}
//|   criterion: {"type":"select","label":"停止の判定","description":"許容誤差 10^−15 と比べる後退誤差。","options":["Normwise","Componentwise"],"value":"Normwise"}
//|   use_fallback: {"type":"checkbox","label":"f64 の LU に退避する","description":"改良が止まったときに一度だけ f64 の逆作用素へ切り替える。","value":false}
//| cases:
//|   - {"id":"stagnation","label":"t = 10","description":"単精度の分解では補正が後退誤差を下げなくなり、Stagnation で止まる。","inputs":{"condition_exponent":10}}
//|   - {"id":"fallback","label":"t = 10、退避あり","description":"停滞した時点で f64 の LU に切り替わり、収束する。","inputs":{"condition_exponent":10,"use_fallback":true}}
//|   - {"id":"componentwise","label":"t = 9、成分ごと","description":"成分ごとの判定では補正回数の上限で止まる。","inputs":{"condition_exponent":9,"criterion":"Componentwise"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/1","equals":"Converged"}
//|       - {"artifact":"summary","path":"/rows/8/1","equals":"Converged"}
//|       - {"artifact":"summary","path":"/rows/8/3","range":{"max":1e-15}}
//|       - {"artifact":"summary","path":"/rows/9/3","range":{"min":1e-14}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: stagnation
//|     expect:
//|       - {"path":"/outputs/2/state","equals":"partial"}
//|   - case: fallback
//|     expect:
//|       - {"artifact":"summary","path":"/rows/10/1","equals":"Converged"}
//|       - {"artifact":"summary","path":"/rows/10/7","equals":"Stagnation"}
//|       - {"artifact":"summary","path":"/rows/10/8","range":{"min":1}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: componentwise
//|     expect:
//|       - {"artifact":"summary","path":"/rows/9/1","equals":"IterationLimit"}
//|       - {"artifact":"summary","path":"/rows/9/2","equals":10}
//|       - {"path":"/outputs/2/state","equals":"partial"}
use scioxide_core::{Budget, LinearOperator, ResidualTolerance};
use scioxide_linalg::{
    EquilibrationMetadata, IterativeRefinement, LinalgExecutionOptions, LuDecomposition,
    Matrix, RefinementCriterion, RefinementFallback, RefinementFallbackReason,
    RefinementOptions, RefinementProblem, RefinementReport, RefinementSystem,
    RefinementTermination,
};

let n = 40_usize;
let u: Vec<f64> = (0..n).map(|i| ((i + 1) as f64).sqrt()).collect();
let v: Vec<f64> = (0..n).map(|i| 1.0 + (i % 5) as f64).collect();
let (uu, vv) = (
    u.iter().map(|x| x * x).sum::<f64>(),
    v.iter().map(|x| x * x).sum::<f64>(),
);
// 鏡映 H = I − 2 w wᵀ / (wᵀ w) の (i, k) 成分。
let reflect = |w: &[f64], ww: f64, i: usize, k: usize| {
    (if i == k { 1.0 } else { 0.0 }) - 2.0 * w[i] * w[k] / ww
};
let rule = if criterion == "Componentwise" {
    RefinementCriterion::Componentwise
} else {
    RefinementCriterion::Normwise
};
let fallback_policy = if use_fallback {
    RefinementFallback::OnFailure
} else {
    RefinementFallback::Disabled
};
let tolerance = ResidualTolerance::new(0.0, 1e-15).map_err(|e| e.to_string())?;
let name = |t: RefinementTermination| match t {
    RefinementTermination::Converged => "Converged",
    RefinementTermination::Stagnation => "Stagnation",
    RefinementTermination::IterationLimit => "IterationLimit",
    RefinementTermination::EvaluationLimit => "EvaluationLimit",
    RefinementTermination::ExecutionStopped(_) => "ExecutionStopped",
    RefinementTermination::CorrectionFailed => "CorrectionFailed",
};
let reason = |r: RefinementFallbackReason| match r {
    RefinementFallbackReason::Conversion => "Conversion",
    RefinementFallbackReason::NumericalFailure => "NumericalFailure",
    RefinementFallbackReason::Stagnation => "Stagnation",
};
// A = H_u Σ H_v（σ_j = 10^(−t j/(n−1))）を作り、最大 k 回の補正で改良する。
let run = |t: f64, k: usize| -> Result<(RefinementReport<f64>, f64), String> {
    let s: Vec<f64> = (0..n)
        .map(|j| 10.0_f64.powf(-t * j as f64 / (n - 1) as f64))
        .collect();
    let entry = |i: usize, j: usize| -> f64 {
        (0..n)
            .map(|m| reflect(&u, uu, i, m) * s[m] * reflect(&v, vv, m, j))
            .sum()
    };
    let data: Vec<f64> = (0..n * n).map(|idx| entry(idx / n, idx % n)).collect();
    let a = Matrix::from_vec(n, n, data).map_err(|e| e.to_string())?;
    let b: Vec<f64> = (0..n)
        .map(|i| a.as_slice()[i * n..(i + 1) * n].iter().sum())
        .collect();
    // 平衡化した A を f32 に変換して分解し、その逆作用素を補正に使う。
    let meta = EquilibrationMetadata::prepare(RefinementSystem::Dense(a.view()))
        .map_err(|e| e.to_string())?;
    let mut low = Matrix::<f32>::zeros(n, n).map_err(|e| e.to_string())?;
    meta.scale_matrix_into(a.view(), &mut low.view_mut())
        .map_err(|e| e.to_string())?;
    let lu32 = LuDecomposition::factor(&low).map_err(|e| e.to_string())?;
    let lu64 = LuDecomposition::factor(&a).map_err(|e| e.to_string())?;
    let (inverse, fallback_inverse) = (lu32.inverse_operator(), lu64.inverse_operator());
    let fallback: Option<&(dyn LinearOperator<f64> + Sync)> = if use_fallback {
        Some(&fallback_inverse)
    } else {
        None
    };
    // 補正回数の上限は実行オプションの反復上限（退避後の補正も数える）。
    let budget = Budget::try_from(k).map_err(|e| e.to_string())?;
    let options = RefinementOptions::new(tolerance)
        .with_criterion(rule)
        .with_fallback(fallback_policy)
        .with_execution_options(LinalgExecutionOptions::new().with_iteration_budget(budget));
    // 手法オブジェクトには設定だけを入れ、系と逆作用素は呼び出しごとに問題として借用する。
    let problem = RefinementProblem::new(
        RefinementSystem::Dense(a.view()),
        &inverse,
        Some(&meta),
        fallback,
    )
    .map_err(|e| e.to_string())?;
    let refinement = IterativeRefinement::new(options).map_err(|e| e.to_string())?;
    let zero = vec![0.0_f64; n];
    let (x, report) = refinement
        .refine(&problem, &b[..], &zero[..])
        .map_err(|e| e.to_string())?;
    let forward = x
        .as_slice()
        .iter()
        .fold(0.0_f64, |m, &xi| m.max((xi - 1.0).abs()));
    Ok((report, forward))
};

    { "key": "6", "label": "κ₂ u [-]", "type": "number", "format": sci2 },
    { "key": "7", "label": "退避の理由" },
    { "key": "8", "label": "退避先の呼び出し [回]", "type": "integer" }
]);
let mut rows = Vec::new();
for t in 0..=10 {
    let (report, forward) = run(t as f64, 10)?;
    let error = report.final_error();
    rows.push((
        10.0_f64.powi(t),
        name(report.termination()),
        report.iterations(),
        error.map(|e| e.normwise()),
        error.and_then(|e| e.componentwise()),
        forward,
        10.0_f64.powi(t) * f64::EPSILON / 2.0,
        report.fallback_reason().map_or("—", reason),
        report.fallback_iterations(),
    ));
}
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "summary" })
);
let mut history = Vec::new();
for k in 1..=10 {
    let (report, _) = run(condition_exponent, k)?;
    // 後退誤差が厳密に 0 の点は対数軸に描けないので除く。
    if let Some(e) = report.final_error().filter(|e| e.normwise() > 0.0) {
        history.push([k as f64, e.normwise()]);
    }
}
let label = format!("κ₂ = 1e{condition_exponent}");
emit_line_chart!(
    &vec![
        serde_json::json!({ "name": label, "points": history, "style": { "showSymbol": true } })
    ],
    options = &serde_json::json!({
        "xLabel": "最大補正回数 k [回]",
        "yLabel": "ノルムごとの後退誤差 [-]",
        "yType": "log",
        "annotations": [{ "kind": "line", "axis": "y", "value": 1e-15, "label": "許容誤差 1e-15" }]
    })
);
// outcome は選んだ t を最大 10 回まで改良した結果で決める。
let (report, forward) = run(condition_exponent, 10)?;
let termination = report.termination();
let outcome = match termination {
    RefinementTermination::Converged => {
        Outcome::satisfied("選んだ後退誤差が許容誤差 1e-15 を満たした")
    }
    RefinementTermination::CorrectionFailed => Outcome::failed("補正の計算が失敗した"),
    _ => Outcome::partial("許容誤差を満たす前に止まった")
        .explanation("返された解は採用した最良の反復解で、後退誤差は許容誤差を超えている。"),
};
let mut outcome = outcome
    .status(name(termination))
    .diagnostic("補正回数", report.iterations() as f64, None)
    .diagnostic("前進誤差", forward, None);
if let Some(e) = report.final_error() {
    outcome = outcome.diagnostic("ノルムごとの後退誤差", e.normwise(), None);
}
emit_outcome!(outcome);
```

$\kappa_2 \le 10^{8}$ では 3〜6 回の補正で `Converged` になり、ノルムごとの後退誤差は $1.7 \times 10^{-17}$〜$4.2 \times 10^{-16}$ になる。
$b$ を `f64` で作るときの丸め（相対 $u$ 程度）だけで、格納された系の厳密解は $x^{\star}$ から $\kappa_2 u$ の程度ずれうるので、表の前進誤差はデータの丸めの影響を含む。
収束した行の前進誤差は $\kappa_2 \ge 10^{3}$ では $\kappa_2 u$ の 0.07〜0.16 倍（$\kappa_2 = 1$ では $u$ の 8 倍）で、条件数に比例して増える。
$\kappa_2 \ge 10^{9}$ では補正が後退誤差を下げなくなって `Stagnation` で止まり、後退誤差は単精度の水準の $10^{-9}$ 程度にとどまり、前進誤差は $10^{9}$ で 0.18、$10^{10}$ で 130 と解として意味を持たない。
先に述べた目安 $\kappa \ll 1/u_f \approx 1.7 \times 10^{7}$ は大まかな見積もりで、この行列は $10^{8}$ まで収束し、$10^{9}$ で収束しなくなる。

グラフの $\kappa_2 = 10^{8}$ では、補正一回あたり後退誤差が約 2 桁ずつ下がり、6 回目で許容誤差 $10^{-15}$ を下回って $3.2 \times 10^{-17}$ になる。
$t = 10$ を選ぶと outcome は `Stagnation` の partial になり、返される解は採用した最良の反復解で、前進誤差は 130 である。
退避を有効にすると、停滞した時点で一度だけ `f64` の LU に切り替わり（理由 `Stagnation`、退避先の呼び出し 1 回）、$10^{9}$ は 5 回、$10^{10}$ は 4 回の補正で収束し、後退誤差はそれぞれ $1.3 \times 10^{-17}$、$7.5 \times 10^{-16}$ になる。
成分ごとの判定では、$\kappa_2 \le 10^{8}$ の行は同じ回数で収束し、$10^{9}$ では補正のたびに成分ごとの後退誤差が少しずつ下がり続けて `IterationLimit`（10 回、ノルムごとの後退誤差 $6.2 \times 10^{-14}$）で止まる。
表の数値はこのページの Wasm での実行結果で、ネイティブでは libm の違いで行列の丸めが変わり、補正回数や、境目の $10^{9}$ の行の終了理由が変わることがある。

## まとめ

反復改良は低い精度の分解で補正を求め、残差と更新を作業精度で行う方法で、$\kappa(A) u_f$ が 1 より十分小さければ数回の補正で作業精度の後退誤差に達する。
明示的な行列では残差を丸めずに累積するので、格納された系に対する前進誤差も下げられるが、入力の $A$ と $b$ に含まれる誤差が $\kappa(A)$ 倍に拡大される分は改良で消えない。
`IterativeRefinement` は設定だけを持つ手法オブジェクトで、元の系・低い精度の逆作用素・平衡化の尺度・退避先は `RefinementProblem` として呼び出しごとに借用し、成否はレポートの `termination()` か `is_success()` で判定する。
補正回数の上限は `LinalgExecutionOptions` の反復上限（既定 10 回）で決まり、上限や停滞で止まった場合も最良の反復解が返るので、終了理由を見てから解を使う。
条件数が大きく停滞する場合は、`RefinementFallback::OnFailure` と作業精度の逆作用素を渡すと、一度だけ切り替えて収束させられる。
