観測の数 $m$ が未知数の数 $n$ より多い過剰決定系 $Ax \approx b$（$A \in \mathbb{K}^{m \times n}$、$\mathbb{K}$ は $\mathbb{R}$ か $\mathbb{C}$）では、残差の 2 ノルム $\lVert b - Ax \rVert_2$ を最小にする $x$ を求める。
このページはこの最小二乗問題を直交変換で解く QR 分解と、その誤差と感度、ランク落ちへの対処、信頼領域の部分問題、行列が少しずつ変わる場合の QR の更新を説明する。
記号 $u$（単位丸め）と $\kappa_2$ は[線形代数の数理と共通の規約](../)の定義に従い、後退誤差と条件数の一般論は[浮動小数点と条件数](../../../concepts/floating-point-and-conditioning/)にある。
標準形式・オプション付き形式・出力先を指定する API・ワンショット関数という呼び出しの形の名前は[呼び出しの形](oxref:linalg-execution-forms)で、解の受理の仕様は[分解と解の受理を分ける](oxref:linalg-factorization-acceptance)で定義している。

## Householder 鏡映

0 でないベクトル $v \in \mathbb{R}^m$ に対する鏡映 $H = I - 2 v v^{\mathsf T} / (v^{\mathsf T} v)$ は対称な直交行列で、$v$ に直交する超平面についての折り返しである。
与えられた $x$ の 2 番目以降の成分を 0 にする、つまり $Hx = \beta e_1$ とするには、$\lvert \beta \rvert = \lVert x \rVert_2$ として $v = x - \beta e_1$ を選ぶ。
実際、$v^{\mathsf T} x = \beta^2 - \beta x_1$、$v^{\mathsf T} v = 2(\beta^2 - \beta x_1)$ なので $Hx = x - v = \beta e_1$ になる。

$\beta$ の符号は自由に選べるが、数値的には $\beta = -\operatorname{sign}(x_1) \lVert x \rVert_2$ と選ぶ。
このとき $v_1 = x_1 + \operatorname{sign}(x_1) \lVert x \rVert_2$ は同じ符号の数の和になる。
逆の符号では $v_1 = x_1 - \operatorname{sign}(x_1) \lVert x \rVert_2$ となり、$x$ が $e_1$ にほぼ平行なときに桁落ちで $v_1$ の相対誤差が大きくなり、計算した $H$ が直交から外れる。
`scioxide-linalg` は鏡映を $H = I - \tau v v^{\mathsf H}$ の形（$v_1 = 1$）で保持し、ノルムを求める前に成分を 2 の冪で尺度変換してオーバーフローとアンダーフローを避ける。
複素数では $\tau$ を複素数にして $\beta$ を実数にとる（このとき $H$ はユニタリだが Hermitian ではない）。

## QR 分解と最小二乗解

第 $k$ 列の対角から下に鏡映 $H_k$ を作って左から掛けることを $k = 1, \dots, n$ と繰り返すと、$A$ は上三角になり、

$$
A = Q R = \begin{bmatrix} Q_1 & Q_2 \end{bmatrix} \begin{bmatrix} R_1 \\ 0 \end{bmatrix}, \qquad Q = H_1 \cdots H_n,\ Q^{\mathsf H} Q = I
$$

が得られる（$Q_1 \in \mathbb{K}^{m \times n}$、$R_1$ は $n \times n$ の上三角）。
直交変換は 2 ノルムを変えないので

$$
\lVert b - Ax \rVert_2^2 = \lVert Q_1^{\mathsf H} b - R_1 x \rVert_2^2 + \lVert Q_2^{\mathsf H} b \rVert_2^2
$$

となり、最小二乗解は $R_1 x = Q_1^{\mathsf H} b$ の後退代入で求まり、残差のノルムは $\lVert Q_2^{\mathsf H} b \rVert_2$ である。

実数の場合の演算量は次のように数える。
第 $k$ 段では長さ $m - k + 1$ の $v$ を残りの $n - k$ 列に作用させ、$w^{\mathsf T} = v^{\mathsf T} A_{k:m,\,k+1:n}$ と更新 $A_{k:m,\,k+1:n} - \tau v w^{\mathsf T}$ がそれぞれ約 $2(m-k)(n-k)$ 回の演算になる。
合計は $\sum_{k=1}^{n} 4(m-k)(n-k) \approx 4 \int_0^n (m-t)(n-t)\,dt = 2mn^2 - \tfrac{2}{3} n^3$ である。
$Q$ を作らずに $Q^{\mathsf H} b$ を求めるには鏡映を順に作用させればよく、追加は $O(mn)$ にとどまる。

`HouseholderDecomposition::factor(&a, orientation, pivoting)` は、複数の鏡映を compact-WY 形式 $I - VTV^{\mathsf H}$ にまとめ、残りの列の更新と $Q$ の作用を行列積で行う。
$Q$ は鏡映のまま保持し、必要なときだけ `to_q_matrix()` で作る（`apply_q` は作らずに作用させる）。
因子は残差を測るために元の行列の写しも保持する。
分解はランク落ちの行列でも失敗せず、ランクは求解のときに判定する。

Householder QR は後退安定である。
標準の丸めのモデルのもとで、計算した $\hat R$ に対して、厳密に直交な $Q$ と、$A + \Delta A = Q \hat R$、$\lVert \Delta a_j \rVert_2 \le \tilde\gamma_{mn} \lVert a_j \rVert_2$（$j = 1, \dots, n$）を満たす $\Delta A$ が存在する（Higham, *Accuracy and Stability of Numerical Algorithms*, 定理 19.4）。
$\tilde\gamma_{k} = cku/(1 - cku)$ は小さな定数 $c$ を含む量で、$cku < 1$ を仮定する。
この評価は列ごとの相対誤差で、計算した $\hat Q$ も直交行列から $\tilde\gamma_{mn}$ の程度しか離れない。
最小二乗解についても、計算した $\hat x$ は列ごとに同じ大きさの摂動を加えた問題 $\min \lVert (A + \Delta A) x - (b + \Delta b) \rVert_2$（$\lVert \Delta b \rVert_2 \le \tilde\gamma_{mn} \lVert b \rVert_2$）の厳密解である（同書の定理 20.3）。
これらはアルゴリズムの性質を述べる事前の評価で、`scioxide-linalg` が実行ごとに返す推定値ではない。

## 最小二乗問題の感度と正規方程式

後退誤差を前進誤差に直すには、最小二乗解の摂動に対する感度が要る。
残差を $r = b - Ax$、$b$ と $A$ の値域のなす角を $\theta$（$\sin\theta = \lVert r \rVert_2 / \lVert b \rVert_2$）とする。
$A$ が列フルランクで $\sin\theta < 1$、摂動が $\lVert \Delta A \rVert_2 \le \epsilon \lVert A \rVert_2$、$\lVert \Delta b \rVert_2 \le \epsilon \lVert b \rVert_2$ を満たし $\epsilon\,\kappa_2(A) < 1$ なら、摂動した問題の解 $x + \Delta x$ について

$$
\frac{\lVert \Delta x \rVert_2}{\lVert x \rVert_2} \le \epsilon \left( \frac{2\kappa_2(A)}{\cos\theta} + \kappa_2(A)^2 \tan\theta \right) + O(\epsilon^2)
$$

が成り立つ（Wedin の評価。
Golub–Van Loan, *Matrix Computations*, 定理 5.3.1）。
導出では正規方程式を摂動の大きさで微分すると、一次の項は $\Delta x \approx A^{+}(\Delta b - \Delta A\, x) + (A^{\mathsf H} A)^{-1} \Delta A^{\mathsf H} r$ になる。
$\lVert A^{+} \rVert_2 = 1/\sigma_n$、$\lVert (A^{\mathsf H} A)^{-1} \rVert_2 = 1/\sigma_n^2$ と $\lVert Ax \rVert_2 = \lVert b \rVert_2 \cos\theta$ を使うと、第 1 項が $2\kappa_2/\cos\theta$ を、残差に比例する第 2 項が $\kappa_2^2 \tan\theta$ を与える。
相対誤差で測った評価で、残差が 0 なら条件数は $\kappa_2$、残差が大きいと $\kappa_2^2$ に比例する。

この評価に $\epsilon \approx u$ の後退誤差を入れると、QR の前進誤差はおおよそ $u(\kappa_2 + \kappa_2^2 \tan\theta)$ である。
正規方程式 $A^{\mathsf H} A x = A^{\mathsf H} b$ を Cholesky 分解で解くと演算量は約半分になるが、$A^{\mathsf H} A$ を作る段階で $\kappa_2(A^{\mathsf H} A) = \kappa_2(A)^2$ の問題に変わるので、誤差は残差によらず $u\kappa_2^2$ の程度になる。
二つの差が大きいのは、残差が小さく $\tan\theta$ が小さい問題である。

QR の因子の標準形式 `qr.solve(&b)` は、$m \ge n$ の QR 分解から最小二乗解 $x = P R_1^{-1} (Q^{\mathsf H} b)_1$ を返す。
既定の選択肢（`RankPolicy::Exact`）を使うので、$R$ の対角に厳密に 0 がある場合だけ `Singular` のエラーになり、LQ の因子や $m < n$ の QR では `InvalidInput`（`UnsupportedConfiguration`）になる。
オプション付き形式の `solve_with_options(&b, &options)` は数値ランクのしきい値や逆条件数の下限で受理を判定し、列フルランクでなければ `Ok` のレポートの `termination()` を `RankDeficient` にして解を出力に反映しない。

ワンショット関数 `least_squares(&a, &b)` は、列ピボット付き QR と次節の最小ノルム解の準備をまとめた関数で、縦長・正方・横長のどの $A$ でも最小ノルムの最小二乗解を返す。
数値ランクは $R$ の対角のうち $\tau = \min(\max(m, n)\,\varepsilon,\ 1/2) \cdot \max_i \lvert r_{ii} \rvert$（`RankPolicy::DimensionScaledEpsilon`）を超えるものの数で、ランク落ちの $R$ は完全直交分解で処理するので、ランク落ちはエラーにならない。
$m \ge n$ での演算量は約 $2mn^2 - \tfrac{2}{3}n^3$ で、逐次のコンテキスト `ExecutionContext::sequential_native()` で動く。
失敗は `DimensionMismatch`、`NonFinite`、解のあふれの `NumericalInstability`（`Overflow`）、確保の失敗の `AllocationFailure` である。
別のランクの方針や逆条件数の下限が必要な場合は、`HouseholderDecomposition::into_minimum_norm` を使う。

この節と信頼領域の節の三つのセルは、同じ当てはめの問題を使う。
区間 $[0, 1]$ の $m$ 点 $t_i = i/(m-1)$ で $a_{ij} = t_i^{\,j}$ とした $m \times n$ の行列 $A$ を `monomial_matrix` が作る。
真の係数を $c = (1, \dots, 1)$ とし、`fitting_rhs` は右辺 $b = Ac + s\,w/\lVert w \rVert_2$ を作る。
$w = g - A x_g$ はある $g$ の最小二乗残差なので $A$ の値域に直交し、最小二乗解はどの $s$ でも $c$ で、残差のノルムは $s$ である。

```rust
//| id: linalg-polynomial-fit-model
//| kind: definitions
//| title: 単項式の基底による多項式の当てはめ
//| crates: [scioxide-linalg]
use scioxide_linalg::{
    HouseholderDecomposition, HouseholderOrientation, HouseholderPivoting, Matrix,
};

/// 区間 [0, 1] の m 点 t_i = i/(m − 1) で a_ij = t_i^j とした m × n 行列。
pub(crate) fn monomial_matrix(m: usize, n: usize) -> Result<Matrix<f64>, String> {
    let entries = (0..m * n).map(|k| ((k / n) as f64 / (m - 1) as f64).powi((k % n) as i32));
    Matrix::from_vec(m, n, entries.collect()).map_err(|e| e.to_string())
}

/// b = A c + s w / ‖w‖₂（c = (1, …, 1)、w は A の値域に直交）。
pub(crate) fn fitting_rhs(a: &Matrix<f64>, s: f64) -> Result<Vec<f64>, String> {
    let (m, n) = (a.rows(), a.cols());
    // w = g − A x_g は g の最小二乗残差なので A の値域に直交する。
    let g: Vec<f64> = (0..m).map(|i| ((i * 37 % 11) as f64 - 5.0) / 5.0).collect();
    let qr =
        HouseholderDecomposition::factor(a, HouseholderOrientation::Qr, HouseholderPivoting::None)
            .map_err(|e| e.to_string())?;
    let xg = qr.solve(&g[..]).map_err(|e| e.to_string())?;
    let ag = a.view().mul_vec(&xg).map_err(|e| e.to_string())?;
    let w: Vec<f64> = g.iter().zip(ag.as_slice()).map(|(p, q)| p - q).collect();
    let w_norm = w.iter().map(|v| v * v).sum::<f64>().sqrt();
    let ac = a
        .view()
        .mul_vec(&vec![1.0_f64; n][..])
        .map_err(|e| e.to_string())?;
    Ok(ac
        .as_slice()
        .iter()
        .zip(&w)
        .map(|(p, q)| p + s * q / w_norm)
        .collect())
}
```

次のセルは $m = 40$ 点で $d$ 次の多項式を当てはめる（$n = d + 1$）。
入力は次数 $d$ と残差の大きさ $s = 10^{s'}$ の指数 $s'$ で、出力は問題の量の表と、三つの方法の前進誤差（最大値ノルム）の表である。
方法は QR の標準形式 `solve`、ワンショット呼び出しの `least_squares`、$A^{\mathsf T}A$ を作って Cholesky 分解で解いた正規方程式で、参照値 $u\kappa_2$ と $u\kappa_2^2$ と比べる。

```rust
//| id: linalg-qr-vs-normal-equations
//| ref: linalg-qr-vs-normal-equations
//| title: QR と正規方程式の最小二乗解の誤差
//| run: reactive
//| uses: [linalg-polynomial-fit-model]
//| crates: [scioxide-core, scioxide-linalg]
//| inputs:
//|   degree: {"type":"range","label":"多項式の次数 d","description":"単項式 1, t, …, t^d で当てはめる。次数とともに κ₂ が増える。","min":1,"max":12,"step":1,"value":8}
//|   residual_exponent: {"type":"range","label":"残差の大きさ 10^s の s","description":"値域に直交する成分 w の大きさ。","min":-16,"max":0,"step":1,"value":-12}
//| cases:
//|   - {"id":"large-residual","label":"s = 0","description":"残差が大きいと QR の誤差も κ₂² tan θ の項で増える。","inputs":{"residual_exponent":0}}
//|   - {"id":"degree-twelve","label":"d = 12","description":"丸めた AᵀA が正定値でなくなり、Cholesky 分解が失敗する。","inputs":{"degree":12}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"problem","path":"/rows/0/0","range":{"min":1e5,"max":1e6}}
//|       - {"artifact":"errors","path":"/rows/0/1","range":{"max":1e-10}}
//|       - {"artifact":"errors","path":"/rows/1/1","range":{"max":1e-10}}
//|       - {"artifact":"errors","path":"/rows/2/1","range":{"min":1e-7,"max":1e-4}}
//|   - case: large-residual
//|     expect:
//|       - {"artifact":"errors","path":"/rows/0/1","range":{"min":1e-10,"max":1e-7}}
//|   - case: degree-twelve
//|     expect:
//|       - {"artifact":"errors","path":"/rows/2/1","equals":null}
//|       - {"artifact":"errors","path":"/rows/2/2","equals":"DomainError"}
use scioxide_core::SciOxideErrorKind;
use scioxide_linalg::{
    CholeskyDecomposition, CholeskyPivoting, HermitianInput, HouseholderDecomposition,
    HouseholderOrientation, HouseholderPivoting, SvdValues, least_squares,
};

let (m, n) = (40_usize, degree.round() as usize + 1);
let a = monomial_matrix(m, n)?;
let s = 10.0_f64.powf(residual_exponent);
let b = fitting_rhs(&a, s)?;
let qr =
    HouseholderDecomposition::factor(&a, HouseholderOrientation::Qr, HouseholderPivoting::None)
        .map_err(|e| e.to_string())?;
let error = |x: &[f64]| x.iter().fold(0.0_f64, |e, v| e.max((v - 1.0).abs()));
let qr_error = error(qr.solve(&b[..]).map_err(|e| e.to_string())?.as_slice());
let lsq_error = error(
    least_squares(&a, &b[..])
        .map_err(|e| e.to_string())?
        .as_slice(),
);
// 正規方程式: AᵀA と Aᵀb を作って Cholesky 分解で解く。
let ata = a
    .view()
    .transpose()
    .mul_mat(&a)
    .map_err(|e| e.to_string())?;
let atb = a
    .view()
    .transpose()
    .mul_vec(&b[..])
    .map_err(|e| e.to_string())?;
let normal = CholeskyDecomposition::factor(&ata, HermitianInput::Exact, CholeskyPivoting::None)
    .and_then(|f| f.solve(&atb));
// 丸めた AᵀA が正定値でなければ Cholesky 分解は DomainError で失敗する。
let (normal_error, normal_status) = match normal {
    Ok(x) => (Some(error(x.as_slice())), "解を返す"),
    Err(e) if e.kind() == SciOxideErrorKind::DomainError => (None, "DomainError"),
    Err(e) => return Err(e.to_string()),
};
let sigma = SvdValues::compute(&a).map_err(|e| e.to_string())?;
let kappa = sigma.singular_values()[0] / sigma.singular_values()[n - 1];
let u = f64::EPSILON / 2.0;
// 残差のノルムは s なので tan θ = s / ‖A c‖₂。
let ac = a
    .view()
    .mul_vec(&vec![1.0_f64; n][..])
    .map_err(|e| e.to_string())?;
let tan_theta = s / ac.as_slice().iter().map(|v| v * v).sum::<f64>().sqrt();
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let problem = serde_json::json!([
    { "key": "0", "label": "κ₂(A) [-]", "type": "number", "format": sci2 },
    { "key": "1", "label": "tan θ [-]", "type": "number", "format": sci2 },
    { "key": "2", "label": "u κ₂ [-]", "type": "number", "format": sci2 },
    { "key": "3", "label": "u κ₂² [-]", "type": "number", "format": sci2 }
]);
emit_table_with_columns!(
    problem,
    vec![(kappa, tan_theta, u * kappa, u * kappa * kappa)],
    metadata = serde_json::json!({ "id": "problem" })
);
let errors = serde_json::json!([
    { "key": "0", "label": "方法" },
    { "key": "1", "label": "前進誤差 [-]", "type": "number", "format": sci2, "nullText": "なし" },
    { "key": "2", "label": "結果" }
]);
emit_table_with_columns!(
    errors,
    vec![
        ("QR の solve", Some(qr_error), "解を返す"),
        ("least_squares", Some(lsq_error), "解を返す"),
        ("正規方程式（Cholesky）", normal_error, normal_status),
    ],
    metadata = serde_json::json!({ "id": "errors" })
);
```

既定の $d = 8$（$\kappa_2 \approx 6.2 \times 10^{5}$）、$s = 10^{-12}$ では、QR の `solve` の誤差 $9.3 \times 10^{-12}$ は $u\kappa_2 = 6.8 \times 10^{-11}$ 以下で、正規方程式の誤差 $7.2 \times 10^{-6}$ は $u\kappa_2^2 = 4.2 \times 10^{-5}$ と同じ桁であり、二つの差は約 6 桁ある。
`least_squares` の誤差 $4.1 \times 10^{-11}$ も $u\kappa_2$ 以下である。
`least_squares` は列ピボットと最小ノルム解の準備を通るので、誤差は QR の `solve` と同じ値にはならない。
$s = 1$ にすると $\tan\theta \approx 0.044$ になり、QR の誤差も $\kappa_2^2 \tan\theta$ の項で $6.9 \times 10^{-9}$（`least_squares` は $1.5 \times 10^{-7}$）まで増え、正規方程式の $1.7 \times 10^{-5}$ との差は QR の `solve` で約 3 桁、`least_squares` で約 2 桁に縮む。
どちらの QR の誤差も一次の評価 $u(\kappa_2 + \kappa_2^2 \tan\theta) \approx 1.9 \times 10^{-6}$ を下回る。
$d = 12$ では $u\kappa_2^2$ が 1 を超え、丸めた $A^{\mathsf T} A$ が正定値でなくなって Cholesky 分解が `DomainError` で失敗するが、QR の二つの方法は $2 \times 10^{-8}$ 程度の誤差で解く。

## 列ピボット・最小ノルム解・LQ・RQ

列の一次従属が疑われる場合は、列ピボット付き QR（`HouseholderPivoting::Column`、既定）を使う。
各段で残りの列のうち 2 ノルムが最大の列を先頭に移すので、$R$ の対角の絶対値が降順に並び、小さい対角の個数が数値ランクの目安になる。
ただしこの並びはランクを確定するものではなく、Kahan 行列のように、対角がどれも小さくないのに特異値が非常に小さい例があるので、確実な判定には [SVD](../svd-and-rank/) を使う。
列ノルムは各段で引き算によって更新し、桁落ちで信頼できなくなったときだけ計算し直す（Drmač–Bujanović）。

QR の `solve` は列フルランクを要求するので、ランク落ちを許す場合は、列ピボット付きの因子を `into_minimum_norm(&options)` で `HouseholderMinimumNormPlan` に変える（列ピボットのない因子は `InvalidInput` で拒否する）。
この準備では `options` のランクの方針で決めたランク $r$ に対して、$R$ の先頭 $r$ 行の台形をさらに $\begin{bmatrix} T & 0 \end{bmatrix} Z$（$T$ は上三角、$Z$ はユニタリ）と分解する。
これは打ち切った行列 $A_r$ の完全直交分解 $AP = Q \begin{bmatrix} T & 0 \\ 0 & 0 \end{bmatrix} Z$ で、$O(r^2 n)$ の演算で一度だけ行う。
以後の `solve(&b)` は、$A_r$ についての最小二乗解のうち 2 ノルムが最小のもの $x = P Z^{\mathsf H} [T^{-1}(Q^{\mathsf H} b)_1;\ 0]$ を、右辺あたり $O(mn + rn + r^2)$ で返す。
ランクの判定は準備のときに一度だけ行い、`rank()` で読める。
`solve` の戻り値は `DirectSolveResult` で、ランク落ちは拒否の理由にならない。
ランク落ちの Plan では逆条件数の推定値が 0 になるので、正の逆条件数の下限を設定した `options` では `IllConditioned` で拒否される。
`options` は後退誤差の診断と、各求解の実行上限も決める。

`HouseholderOrientation::Lq` は $A$ の行に対する LQ 分解 $A[p, :] = LQ$（$L$ は下台形、$Q$ は $n \times n$ のユニタリ）で、$A^{\mathsf H}$ の QR 分解として計算し、未知数の方が多い劣決定系に使う。
行ピボット付きの LQ も `into_minimum_norm` で最小ノルム解の準備に変えられる。
`RqDecomposition::factor(&a)` は $A = RQ$（$Q$ は $n \times n$ のユニタリ、$R$ は対角が右下の角で終わる $m \times n$ の上台形）を与え、二つの因子を明示的に持つので、`r_matrix()` と `q_matrix()` で読む。
計算は反転の置換 $J$ を使って、ピボットのない $J_n A^{\mathsf H} J_m$ の Householder QR から行う。

減衰付きの問題 $\min \lVert Ax - b \rVert_2^2 + \lambda \lVert x \rVert_2^2$ は、実数の $m \ge n$ の QR から `qr.solve_damped(&b, λ)`（標準形式）か `solve_damped_with_options(&b, λ, &options)`（オプション付き形式）で解く。
これは拡大した系 $\begin{bmatrix} A \\ \sqrt\lambda I \end{bmatrix} x \approx \begin{bmatrix} b \\ 0 \end{bmatrix}$ の最小二乗問題で、$Q^{\mathsf H}b$ を求めてから $\sqrt\lambda I$ の行を次節の Givens 回転で $R$ に組み込み、演算量は $O(mn + n^3)$ である。
条件数が $A$ の 2 乗になる正規方程式 $(A^{\mathsf H}A + \lambda I)x = A^{\mathsf H}b$ も、二つ目の分解も作らない。
$\lambda = 0$ は通常の最小二乗解になる。

## Givens 回転

Householder 鏡映が列の多くの成分を一度に消すのに対し、Givens 回転は平面内の回転で成分を一つずつ消す。
実数 $(a, b)$ に対して $\lvert r \rvert = \sqrt{a^2 + b^2}$、$c = a/r$、$s = b/r$ として $G = \begin{bmatrix} c & s \\ -s & c \end{bmatrix}$ とすると $G (a, b)^{\mathsf T} = (r, 0)^{\mathsf T}$ で、$c^2 + s^2 = 1$ から $G$ は直交行列である。
二つのベクトルの組に作用させる計算コストは成分あたり乗算 4 回と加算 2 回で、変更が局所的なので、Hessenberg 行列や三角行列にできた少数の非零成分を消す用途に向く。
$a^2 + b^2$ をそのまま計算するとオーバーフローやアンダーフローが起きうるので、`scioxide-linalg` は極端な大きさの入力を 2 の冪で尺度変換してから $r$ を求め、$r$ があふれるのは $\sqrt{a^2 + b^2}$ そのものがあふれる場合だけである。

`givens_rotation(a, b)` は実数の BLAS xROTG と同じ規約で回転を作り、`GivensRotationResult` を返す（取り消しや BLAS プロバイダーを使うコンテキストを渡すスコープ付き API は `givens_rotation_scoped(a, b, &options, context)`）。
`r()` は回転後の第 1 成分で、その符号は $\lvert a \rvert > \lvert b \rvert$ なら $a$ の、そうでなければ $b$ の符号に従う。
`z()` は回転を一つの数に符号化した BLAS の再構成用の値で、$\lvert a \rvert > \lvert b \rvert$ なら $s$、そうでなければ $c \ne 0$ のとき $1/c$、$c = 0$ のとき 1 である。
`rotation()` が返す `GivensRotation` は係数 $c$（`cosine()`）と $s$（`sine()`）を持つ値の型である。
$a = b = 0$ では単位行列の回転と $r = z = 0$ を返す。

`GivensRotation::new(c, s)` は有限であることだけを検査し、$c^2 + s^2 = 1$ への正規化はしないので、手で作る場合は単位の回転を渡す。
二つのベクトルへの作用は `VectorViewMut::rotate_in_place(rotation, &options, x, y, &mut workspace, context)` で、各組を $x_i \leftarrow c x_i + s y_i$、$y_i \leftarrow c y_i - s x_i$ と置き換え（BLAS xROT）、作業領域は `DenseWorkspaceRequest::vector_pair` で事前確保する。
失敗したときはどちらのベクトルも変えない。
この節の型と関数は実数だけを扱い、複素数の平面回転は QR の更新が内部で使う。

## 信頼領域の部分問題

非線形最小二乗の Levenberg–Marquardt 法は、各反復でヤコビ行列 $A$、残差 $b$、尺度の対角行列 $D$、信頼領域の半径 $\Delta$ について部分問題

$$
\min_p \lVert Ap - b \rVert_2 \quad \text{subject to} \quad \lVert Dp \rVert_2 \le \Delta
$$

を解く（scioxide-optimize の非線形最小二乗も、この節で説明する `solve_trust_region_into` を呼ぶ）。
最適性の条件から、解は $\lambda \ge 0$ をパラメータとする

$$
p(\lambda) = (A^{\mathsf T} A + \lambda D^{\mathsf T} D)^{-1} A^{\mathsf T} b, \qquad \lambda \bigl(\lVert D p(\lambda) \rVert_2 - \Delta\bigr) = 0
$$

の形になる。
制約のない解 $p(0)$ が $\lVert Dp(0) \rVert_2 \le \Delta$ を満たせば $\lambda = 0$ で、そうでなければ $\lVert D p(\lambda) \rVert_2 = \Delta$ となる $\lambda > 0$（Levenberg–Marquardt パラメータ）を求める。
$\phi(\lambda) = \lVert Dp(\lambda) \rVert_2 - \Delta$ は $\lambda$ について単調に減少するが、極に近い形をしているので、$\phi$ そのものに Newton 法を使うと収束が遅い。
Moré の方法はほぼ線形な $1/\lVert Dp(\lambda) \rVert_2 - 1/\Delta$ に Newton 法を使った更新

$$
\lambda^{+} = \lambda - \frac{\phi(\lambda)}{\phi'(\lambda)} \cdot \frac{\lVert D p(\lambda) \rVert_2}{\Delta}
$$

を、区間 $[\ell, \upsilon]$ で保護して繰り返す。
上限は $\upsilon = \lVert D^{-1} A^{\mathsf T} b \rVert_2 / \Delta$、下限は $\lambda = 0$ での Newton の値（求まらなければ 0）である。
各反復では $\phi$ の符号に応じて $\ell$ か $\upsilon$ を今の $\lambda$ に置き換え、次の値を $\max(\ell, \lambda^{+})$ とする。
更新が有限な値にならない場合は、Moré の保護の値 $\max(\upsilon/1000, \sqrt{\ell\upsilon})$ に移る。

`HouseholderDecomposition::solve_trust_region_into(&b, &diagonal, radius, hint, &options, x, &mut ws, cx)` は、実数の $m \ge n$ の QR から $D = \operatorname{diag}(\mathrm{diagonal})$ の部分問題を解く出力先を指定する API である。
$\lVert Dp(0) \rVert_2 \le 1.1\Delta$ なら $\lambda = 0$ とし、そうでなければ `hint`（たとえば前の反復の $\lambda$）を区間 $[\ell, \upsilon]$ に収めた値から始めた Moré の反復を、$\lVert Dp(\lambda) \rVert_2$ が $\Delta$ の 10 % 以内に入るか、それ以上改善できなくなるか、10 回の反復に達するまで続ける。
各 $p(\lambda)$ は $R$ と $Q^{\mathsf T}b$ を使い回し、$\sqrt\lambda D$ の行を Givens 回転で消去して求めるので、正規方程式は作らず、1 回の反復は $O(n^2)$ である。
$Q^{\mathsf T}b$ か $\lambda > 0$ のステップ幅 $p(\lambda)$ の成分があふれると `NumericalInstability`（`Overflow`）になる。
`options` のランクと条件数の検査に通らない因子は、その終了理由のレポートを返して解を書かず、出力は変わらない。
作業領域に `HouseholderWorkspaceRequest::damped_solve` を事前確保しておけば確保しない。

`ThinSvdDecomposition::solve_trust_region_into(&b, radius, hint, rank, &options, x, &mut ws, cx)` は、薄い特異値分解 $A = U\Sigma V^{\mathsf T}$ から $D = I$ の部分問題を解く。
ランクの方針 `rank` のしきい値以下の特異値を捨て、$p(\lambda) = \sum_i \sigma_i (u_i^{\mathsf T} b) / (\sigma_i^2 + \lambda)\, v_i$ について同じ保護付きの反復で $\lambda$ を選ぶ。
この求解は常に受理され、レポートはランクを持つが、条件数の推定と後退誤差は持たない。

どちらも `LeastSquaresTrustRegionReport` を返す。
`termination()` は `DirectSolveTermination`、`solve_report()` はランク・条件数・後退誤差の診断を持つ `DirectSolveReport`、`damping()` は選んだ $\lambda \ge 0$、`step_norm()` は信頼領域のノルムで測ったステップ幅（QR では $\lVert Dp \rVert_2$、SVD では $\lVert p \rVert_2$）で、拒否された場合はどちらも `None` である。
$\lambda = 0$ のステップ幅のノルムは $1.1\Delta$ 以下である。
半径が有限で正でない場合、`hint` が有限で非負でない場合、`diagonal` の成分が有限で正でない場合は `InvalidInput`（`OutOfRange`）、LQ の因子や $m < n$ の QR は `InvalidInput`（`UnsupportedConfiguration`）になる。

次のセルは前のセルの既定と同じ当てはめの問題（$d = 8$、$s = 10^{-12}$）を定義のブロックから取り込み、半径 $\Delta$ の部分問題を QR（$D = I$）と薄い SVD の二つで解く。
制約のない解は $p(0) = c$ で、$\lVert p(0) \rVert_2 = 3$ である。
入力は半径 $\Delta$ の指数で、表は二つの方法の終了理由、$\lambda$、ステップ幅、$\lVert p \rVert_2 / \Delta$ と、独立な検算として返された $\lambda$ と $p$ で計算した正規方程式の相対残差 $\lVert A^{\mathsf T}(Ap - b) + \lambda p \rVert_2 / \lVert A^{\mathsf T} b \rVert_2$ を示す。
outcome は QR の求解の終了理由を示し、選んだ $\Delta$ は次のセルのグラフにも渡す。

```rust
//| ref: linalg-trust-region-step

//| run: reactive
//| uses: [linalg-polynomial-fit-model]
//| crates: [scioxide-core, scioxide-linalg]
//| exports: [radius]
//| inputs:
//|   radius_exponent: {"type":"range","label":"半径 Δ = 10^r の r","description":"信頼領域の半径。制約のない解のノルムは 3。","min":-2,"max":1,"step":0.1,"value":0}

//|   - {"id":"inactive","label":"Δ = 10","description":"制約のない解が信頼領域の内側にあり、λ = 0 になる。","inputs":{"radius_exponent":1}}
//|   - {"id":"small-radius","label":"Δ = 0.01","description":"半径が小さいと λ が大きくなり、ステップ幅は最急降下方向 Aᵀb に近づく。","inputs":{"radius_exponent":-2}}

//|   - case: default
//|     expect:
//|       - {"artifact":"steps","path":"/rows/0/1","equals":"Accepted"}
//|       - {"artifact":"steps","path":"/rows/0/4","range":{"min":0.9,"max":1.1}}
//|       - {"artifact":"steps","path":"/rows/1/4","range":{"min":0.9,"max":1.1}}
//|       - {"artifact":"steps","path":"/rows/0/5","range":{"max":1e-8}}
//|       - {"artifact":"steps","path":"/rows/1/5","range":{"max":1e-8}}

//|       - {"artifact":"steps","path":"/rows/0/4","range":{"min":0.9,"max":1.1}}

use scioxide_linalg::{
    DirectSolveOptions, DirectSolveTermination, HouseholderDecomposition,
    HouseholderOrientation, HouseholderPivoting, LinalgExecutionOptions, LinalgWorkspace,
    RankPolicy, ThinSvdDecomposition, VectorViewMut,
};

let (m, n) = (40_usize, 9_usize);

// 前のセルの既定と同じ問題（d = 8、s = 10⁻¹²）。
let b = fitting_rhs(&a, 1e-12)?;
let qr = HouseholderDecomposition::factor(
    &a,
    HouseholderOrientation::Qr,
    HouseholderPivoting::Column,
)
.map_err(|e| e.to_string())?;
let svd = ThinSvdDecomposition::compute(&a).map_err(|e| e.to_string())?;
let (options, accept) = (LinalgExecutionOptions::new(), DirectSolveOptions::default());
let cx = ExecutionContext::sequential_native();
// QR では D = I（対角の成分をすべて 1 にする）。
let unit = vec![1.0_f64; n];
let atb = a
    .view()
    .transpose()
    .mul_vec(&b[..])
    .map_err(|e| e.to_string())?;
let norm = |v: &[f64]| v.iter().map(|x| x * x).sum::<f64>().sqrt();
// 独立な検算: ‖Aᵀ(A p − b) + λ p‖ / ‖Aᵀ b‖（正規方程式の相対残差）。
let check = |p: &[f64], lambda: f64| -> Result<f64, String> {
    let ap = a.view().mul_vec(p).map_err(|e| e.to_string())?;
    let r: Vec<f64> = ap.as_slice().iter().zip(&b).map(|(x, y)| x - y).collect();
    let atr = a
        .view()
        .transpose()
        .mul_vec(&r[..])
        .map_err(|e| e.to_string())?;
    let g: Vec<f64> = atr
        .as_slice()
        .iter()
        .zip(p)
        .map(|(x, y)| x + lambda * y)
        .collect();
    Ok(norm(&g) / norm(atb.as_slice()))
};

    .solve_trust_region_into(
        &b[..],
        &unit,
        radius,
        0.0,
        &accept,
        VectorViewMut::from_slice(&mut p_qr),
        &mut LinalgWorkspace::new(),
        cx,
    )
    .map_err(|e| e.to_string())?;
let svd_report = svd
    .solve_trust_region_into(
        &b[..],
        radius,
        0.0,
        RankPolicy::Exact,
        &options,
        VectorViewMut::from_slice(&mut p_svd),
        &mut LinalgWorkspace::new(),
        cx,
    )
    .map_err(|e| e.to_string())?;
let name = |t: DirectSolveTermination| match t {
    DirectSolveTermination::Accepted => "Accepted",
    DirectSolveTermination::RankDeficient => "RankDeficient",
    DirectSolveTermination::IllConditioned => "IllConditioned",
    _ => "その他",
};
let mut rows = Vec::new();
for (method, report, p) in [
    ("QR（D = I）", qr_report, &p_qr),
    ("薄い SVD", svd_report, &p_svd),
] {
    let lambda = report.damping();
    let residual = lambda.map(|l| check(p, l)).transpose()?;
    let ratio = report.step_norm().map(|s| s / radius);
    rows.push((
        method,
        name(report.termination()),
        lambda,
        report.step_norm(),
        ratio,
        residual,
    ));
}
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "方法" },
    { "key": "1", "label": "終了理由" },
    { "key": "2", "label": "λ [-]", "type": "number", "format": sci3, "nullText": "なし" },
    { "key": "3", "label": "ステップ幅 ‖p‖ [-]", "type": "number", "format": sci3, "nullText": "なし" },
    { "key": "4", "label": "‖p‖/Δ [-]", "type": "number", "format": sci3, "nullText": "なし" },
    { "key": "5", "label": "正規方程式の相対残差 [-]", "type": "number", "format": sci3, "nullText": "なし" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "steps" })
);
export!(radius, radius);
let termination = qr_report.termination();
let outcome = if termination.is_success() {
    Outcome::satisfied("QR の信頼領域の部分問題が受理された")
} else {
    Outcome::failed("QR の因子が受理の検査に通らず、ステップ幅を出力に反映しなかった")
};
let mut outcome = outcome.status(name(termination));
if let (Some(l), Some(s)) = (qr_report.damping(), qr_report.step_norm()) {
    outcome = outcome
        .diagnostic("λ", l, None)
        .diagnostic("‖p‖/Δ", s / radius, None);
}
emit_outcome!(outcome);
```

既定の $\Delta = 1$ では、QR と SVD はどちらも `Accepted` で、$\lambda \approx 110.18$ を相対差 $10^{-6}$ 以下で一致して選び、ステップ幅は $\lVert p \rVert_2 / \Delta = 1.033$ と 10 % の範囲に入る。
返された $\lambda$ と $p$ での正規方程式の相対残差は QR で $1.8 \times 10^{-16}$、SVD で $6.5 \times 10^{-16}$ で、$p = p(\lambda)$ が成り立っている。
停止の判定は $\lVert p \rVert_2$ が半径の 10 % 以内に入ることなので、$\lambda$ そのものは方程式 $\lVert p(\lambda) \rVert_2 = \Delta$ の根の近似にとどまる。
$\Delta = 10$ では制約のない解 $p(0) = c$ が内側にあり、$\lambda = 0$、$\lVert p \rVert_2 = 3$ になる。
$\Delta = 0.01$ では $\lambda \approx 1.85 \times 10^{4}$ で、$\lambda$ が大きいほどステップ幅は短くなり、向きは最急降下方向 $A^{\mathsf T} b$ に近づく。

次のセルは同じ問題で $\Delta$ を $10^{-2}$ から $10$ まで対数等間隔に 31 点動かし、QR と薄い SVD の二つの方法が選ぶ $\lambda(\Delta)$ を描く。
入力はなく、縦線の「選んだ Δ」は前のセルの半径を受け取って描く。
表は $\lambda = 0$ になった点の数と、両方が $\lambda > 0$ を選んだ点での二つの $\lambda$ の相対差の最大を示す。
二つの方法は同じ保護付きの反復で $\lambda$ を選ぶが、$p(\lambda)$ を別の分解から計算するので、$\lambda$ の一致は QR の Givens 回転による $p(\lambda)$ を SVD の閉じた形で検算することになる。

```rust

// 前のセルで選んだ半径は縦線にだけ使う。
let selected = step["radius"].as_f64().ok_or("半径がない")?;
let (m, n) = (40_usize, 9_usize);
let a = monomial_matrix(m, n)?;
let b = fitting_rhs(&a, 1e-12)?;
let qr = HouseholderDecomposition::factor(
    &a,
    HouseholderOrientation::Qr,
    HouseholderPivoting::Column,

.map_err(|e| e.to_string())?;
let svd = ThinSvdDecomposition::compute(&a).map_err(|e| e.to_string())?;
let (options, accept) = (LinalgExecutionOptions::new(), DirectSolveOptions::default());
let cx = ExecutionContext::sequential_native();
let unit = vec![1.0_f64; n];
let mut workspace = LinalgWorkspace::new();
let mut p = vec![0.0_f64; n];
let (mut qr_curve, mut svd_curve) = (Vec::new(), Vec::new());
let (mut qr_zero, mut svd_zero, mut largest) = (0_usize, 0_usize, 0.0_f64);
for i in 0..=30 {
    let delta = 10.0_f64.powf(-2.0 + 0.1 * i as f64);
    let from_qr = qr
        .solve_trust_region_into(
            &b[..],
            &unit,
            delta,
            0.0,
            &accept,
            VectorViewMut::from_slice(&mut p),
            &mut workspace,
            cx,
        )
        .map_err(|e| e.to_string())?
        .damping()
        .ok_or("QR の求解が拒否された")?;
    let from_svd = svd
        .solve_trust_region_into(
            &b[..],
            delta,
            0.0,
            RankPolicy::Exact,
            &options,
            VectorViewMut::from_slice(&mut p),
            &mut workspace,
            cx,
        )
        .map_err(|e| e.to_string())?
        .damping()
        .ok_or("SVD の求解が拒否された")?;
    // λ = 0 の点は対数軸に描けないので、数だけを数える。
    if from_qr > 0.0 {
        qr_curve.push([delta, from_qr]);
    } else {
        qr_zero += 1;
    }
    if from_svd > 0.0 {
        svd_curve.push([delta, from_svd]);
    } else {
        svd_zero += 1;
    }
    if from_qr > 0.0 && from_svd > 0.0 {
        largest = largest.max((from_qr - from_svd).abs() / from_svd);
    }
}
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([

    { "key": "1", "label": "SVD で λ = 0 の点 [個]", "type": "integer" },
    { "key": "2", "label": "λ の相対差の最大 [-]", "type": "number", "format": sci2 }
]);
emit_table_with_columns!(

);
emit_line_chart!(

        }),
    ],
    options = &serde_json::json!({

        "yLabel": "Levenberg–Marquardt パラメータ λ [-]",
        "xType": "log",
        "yType": "log",
        "annotations": [
            { "kind": "line", "axis": "x", "value": selected, "label": "選んだ Δ" },
            { "kind": "line", "axis": "x", "value": 3.0 / 1.1, "label": "‖p(0)‖/1.1" }
        ]
    })
```

グラフの $\lambda(\Delta)$ は二つの方法とも $\Delta$ の増加とともに単調に減り、二つの曲線の相対差は 25 点で最大 $9.6 \times 10^{-7}$ にとどまる。
$\lVert p(0) \rVert_2 / 1.1 \approx 2.7$ を超える 6 点では $\lambda = 0$ になるので、対数軸から除いている。
前のセルで $\Delta$ を変えると、縦線の位置だけが動く。

## QR の更新

移動ウインドウの回帰や逐次的な観測のように、行や列を一つずつ足したり除いたりする場合、毎回 $O(mn^2)$ の分解をやり直す必要はない。
`QrUpdateDecomposition` は列ピボット付きの完全な QR 分解 $A\Pi = QR$ を、$m \times m$ の $Q$ と $m \times n$ の $R$ を明示的に持つ形で保持する。
`modify(edit)` とオプション付き形式の `modify_with_options(edit, &options)` は一回の変更を反映した新しい因子とレポートを返し、出力先を指定する API の `modify_in_place` は因子をその場で書き換える。
新しい分解（`factor(&a)`、`factor_with_options(&a, &options)`、既存の `HouseholderDecomposition` からの `from_householder`）は $O(m^2 n)$ の演算で、メモリ使用量は $O(m^2 + mn)$ である。
変更で $R$ に生じた非零成分は、隣り合う行の間の平面回転（複素数も扱う）で消し、使った回転を $Q$ にもまとめて作用させるので、基本の変更一回あたりの演算量は $O(m^2 + mn)$ である。
変更 `QrModification` は行の挿入 `InsertRows`、削除 `DeleteRows`、列の挿入 `InsertColumns`、削除 `DeleteColumns`、低ランクの加減 `RankUpdate`（$A + UV^{\mathsf H}$）と `RankDowndate`（$A - UV^{\mathsf H}$）で、ブロックの変更は行・列・$U$ の列ごとの基本の変更の列として反映する。
列の添字は $A$ の列を指し、$R$ のピボット後の順ではない。
変更は列の置換を保ち、ピボットを選び直さない。

`QrUpdateOptions::new(policy)` はランクの方針と列ピボットの有無（`with_pivoting`、既定は列ピボット）と実行上限を持ち、`QrUpdateOptions::default()` は `RankPolicy::Exact` と列ピボットである。
分解と変更のたびに、そのランクの方針で $R$ のランクを判定し、変更前後の判定を `QrUpdateReport`（`before()`、`after()`、ランクが下がったかの `rank_lost()`）で返す。
判定は因子を打ち切らない。
判定には $R$ に対する増分的な条件数推定（Bischof の方法）を $O(mn)$ の演算で使う。
推定がしきい値から 16 倍以上離れていればその推定で決め、近ければ $R$ の特異値を計算して決める。
推定で決めた場合、しきい値を超える特異値が $r$ 個より多くないことは Frobenius ノルムによる上界 $\sigma_{r+1} \le \lVert R_{22} \rVert_F$ で示されるが、$r$ 個がしきい値を超えることは最小特異値の推定に基づく経験的な判定である。
どちらで決めたかは `QrRankDecision::source()` が返す `QrRankSource` の `Estimator`（推定）か `SingularValues`（特異値）で分かる。
呼び出し側が持つ三角の因子に同じ推定を使うには、[構造付き線形方程式](oxref:linalg-triangular-systems)の `TriangularRankWorkspace` を使う。

次のセルは $y_t = 1 + 0.5\,t + 0.1 \sin t$ の観測に直線を当てはめる幅 $w$ の移動ウインドウを、毎回の行の追加と最古の行の削除で $k$ 回ずらす。
入力はウインドウの幅 $w$ とずらす回数 $k$ である。
更新した因子の係数を、その時点のウインドウを最初から QR 分解して解いた係数と比べ、更新後のランクとその判定の根拠を表に示す。
係数は更新した $Q$ と $R$ から $R_{1:2,1:2}\, z = (Q^{\mathsf T} y)_{1:2}$ を `TriangularPlan::from_dense` の三角系で解き、列の置換を戻して求める。

```rust
//| id: linalg-qr-update-window
//| ref: linalg-qr-update-window
//| title: 移動ウインドウの直線回帰を QR の更新で追跡する
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg]
//| inputs:
//|   window: {"type":"range","label":"ウインドウの幅 w","description":"同時に使う観測の数。","min":3,"max":60,"step":1,"value":12}
//|   shifts: {"type":"range","label":"ずらす回数 k","description":"行の追加と削除を繰り返す回数。","min":1,"max":200,"step":1,"value":100}
//| cases:
//|   - {"id":"narrow-window","label":"w = 3","description":"ウインドウが狭いと列が平行に近づくのが早く、κ₂ が大きくなる。","inputs":{"window":3}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"window","path":"/rows/4/5","equals":2}
//|       - {"artifact":"window","path":"/rows/4/6","equals":"Estimator"}
//|       - {"artifact":"window","path":"/rows/4/2","approx":{"value":0.5,"atol":0.01}}
//|       - {"artifact":"worst","path":"/rows/0/0","range":{"max":1e-11}}
//|   - case: narrow-window
//|     expect:
//|       - {"artifact":"window","path":"/rows/4/5","equals":2}
//|       - {"artifact":"worst","path":"/rows/0/0","range":{"max":1e-9}}
use scioxide_core::{DiagonalKind, Triangle};
use scioxide_linalg::{
    HouseholderDecomposition, HouseholderOrientation, HouseholderPivoting, Matrix, MatrixView,
    QrModification, QrRankSource, QrUpdateDecomposition, QrUpdateOptions, RankPolicy,
    StructuredOperation, SvdValues, TriangularPlan,
};

let (w, k) = (window.round() as usize, shifts.round() as usize);
let observe = |t: f64| 1.0 + 0.5 * t + 0.1 * t.sin();
let rows_of =
    |start: usize| -> Vec<f64> { (start..start + w).flat_map(|t| [1.0, t as f64]).collect() };
let update = QrUpdateOptions::new(RankPolicy::DimensionScaledEpsilon);
let first = Matrix::from_vec(w, 2, rows_of(0)).map_err(|e| e.to_string())?;
let mut factor = QrUpdateDecomposition::factor_with_options(first.view(), &update)
    .map_err(|e| e.to_string())?;
// 更新した Q, R から係数を求める: R x = (Qᵀ y) の先頭 2 成分（列の置換を戻す）。
let coefficients = |f: &QrUpdateDecomposition<f64>, y: &[f64]| -> Result<[f64; 2], String> {
    let qty = f
        .q_matrix()
        .view()
        .transpose()
        .mul_vec(y)
        .map_err(|e| e.to_string())?;
    let r = f
        .r_matrix()
        .view()
        .block(0, 0, 2, 2)
        .map_err(|e| e.to_string())?;
    let z = TriangularPlan::from_dense(r, Triangle::Upper, DiagonalKind::Explicit)
        .and_then(|p| p.solve(StructuredOperation::Normal, &qty.as_slice()[..2]))
        .map_err(|e| e.to_string())?;
    let mut x = [0.0; 2];
    for (j, &p) in f.permutation().iter().enumerate() {
        x[p] = z.as_slice()[j];
    }
    Ok(x)
};
let mut rows = Vec::new();
let mut worst = 0.0_f64;
for step in 1..=k {
    let new_row = [1.0, (step + w - 1) as f64];
    let values = MatrixView::from_slice(1, 2, &new_row).map_err(|e| e.to_string())?;
    let insert = QrModification::InsertRows { index: w, values };
    let (grown, _) = factor
        .modify_with_options(insert, &update)
        .map_err(|e| e.to_string())?;
    let delete = QrModification::DeleteRows { index: 0, count: 1 };
    let (shrunk, report) = grown
        .modify_with_options(delete, &update)
        .map_err(|e| e.to_string())?;
    factor = shrunk;
    let y: Vec<f64> = (step..step + w).map(|t| observe(t as f64)).collect();
    let x = coefficients(&factor, &y)?;
    // 独立な参照: 同じウインドウを最初から Householder QR で解く。
    let window_matrix = Matrix::from_vec(w, 2, rows_of(step)).map_err(|e| e.to_string())?;
    let x_ref = HouseholderDecomposition::factor(
        &window_matrix,
        HouseholderOrientation::Qr,
        HouseholderPivoting::Column,
    )
    .and_then(|f| f.solve(&y[..]))
    .map_err(|e| e.to_string())?;
    let diff = (x[0] - x_ref.as_slice()[0])
        .abs()
        .max((x[1] - x_ref.as_slice()[1]).abs());
    worst = worst.max(diff);
    if step == 1 || step == k || step % (k / 4).max(1) == 0 {
        let s = SvdValues::compute(&window_matrix).map_err(|e| e.to_string())?;
        let s = s.singular_values();
        let source = match report.after().source() {
            QrRankSource::Estimator => "Estimator",
            QrRankSource::SingularValues => "SingularValues",
        };
        rows.push((
            step,
            x[0],
            x[1],
            diff,
            s[0] / s[1],
            report.after().report().rank(),
            source,
        ));
    }
}
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let fixed6 = serde_json::json!({ "fractionDigits": 6 });
let columns = serde_json::json!([
    { "key": "0", "label": "ずらした回数", "type": "integer" },
    { "key": "1", "label": "切片 [-]", "type": "number", "format": fixed6 },
    { "key": "2", "label": "傾き [-]", "type": "number", "format": fixed6 },
    { "key": "3", "label": "最初から解いた係数との差 [-]", "type": "number", "format": sci2 },
    { "key": "4", "label": "ウインドウの κ₂ [-]", "type": "number", "format": sci2 },
    { "key": "5", "label": "ランク", "type": "integer" },
    { "key": "6", "label": "判定の根拠" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "window" })
);
let summary = serde_json::json!([
    { "key": "0", "label": "全更新を通した係数の差の最大 [-]", "type": "number", "format": sci2 }
]);
emit_table_with_columns!(
    summary,
    vec![(worst,)],
    metadata = serde_json::json!({ "id": "worst" })
);
```

既定の $w = 12$ で 100 回ずらしても、更新した係数と最初から解いた係数の差は最大 $5.2 \times 10^{-13}$ にとどまる。
差はウインドウの条件数 $\kappa_2$（100 回後に $3.2 \times 10^{3}$）とともに増えるが、$\kappa_2 u \approx 3.6 \times 10^{-13}$ と同じ程度にとどまる。
時刻 $t$ が大きくなると列 $(1, t)$ が平行に近づいて $\kappa_2$ が増えるので、差の増加は、更新で誤差がたまったためではなく問題の条件で説明できる。
表に示した時点のランクはすべて 2 と判定され、その根拠には条件数推定（`Estimator`）が記録される。
$w = 3$ では 100 回後の $\kappa_2$ が $1.2 \times 10^{4}$ まで増え、差の最大は $1.7 \times 10^{-12}$ になるが、ランクは 2 のままである。

## まとめ

最小二乗問題は Householder QR で後退安定に解け、列フルランクで $\epsilon\kappa_2 < 1$ なら前進誤差はおおよそ $u(\kappa_2 + \kappa_2^2 \tan\theta)$ である。
正規方程式は残差によらず $u\kappa_2^2$ の程度の誤差を持つので、残差の小さい悪条件の問題では QR を使う。
ワンショット呼び出しの `least_squares` は列ピボット付き QR と完全直交分解でランク落ちも含めて最小ノルム解を返し、別のランクの方針が必要なら `into_minimum_norm` の `HouseholderMinimumNormPlan` を使う。
Levenberg–Marquardt 法の部分問題は `solve_trust_region_into` で QR か SVD から解け、レポートの `damping()` と `step_norm()` で選ばれた $\lambda$ とステップ幅を確かめられる。
行や列を少しずつ変える問題では、`QrUpdateDecomposition` が一回の変更を平面回転で $O(m^2 + mn)$ で反映し、変更前後のランクの判定とその根拠を返す。
