この表は連立方程式を一度だけ解く関数、密行列の直接分解、分解から得た解を受理するかどうかを決める型、反復改良の型をまとめる。
分解は形の不一致、非有限値、厳密に 0 のピボットのような構造上の破綻だけを `Err` にし、解を受理するかどうかは解くときに `DirectSolveOptions` で決める。
標準形式の `solve(&b)` は既定の条件（`RankPolicy::Exact`）で判定して解の `Vector` を返し、拒否をエラーにする（ランク不足は `Singular`、それ以外は `NumericalInstability`）。
オプション付き形式の `solve_with_options(&b, &options)` は、受理しない場合も `Ok` で `DirectSolveResult` を返し、その `solution()` は `None` になる。
出力先を指定する API の `solve_into` はレポートを返し、拒否すると出力を書き換えない。
出力先を指定する API とスコープ付き API（`factor_into`、`solve_into`、`inverse_into`、`condition_estimate_scoped` など）は、空の求解や拒否した求解も含めて呼ぶたびに作業領域の `last_attempt()` を置き換え、上限や取り消しによる停止（`Stopped`）、数値的な失敗（`Failed`）、検査での拒否（`PreflightRejected`）を区別して記録する。
Plan を持たない `inverse_into` と `condition_estimate_scoped` は `LinalgExecutionOptions` を明示して受け取り、作業領域が保持する容量全体をそのバイト上限で検査する。
呼び出しの形の定義は [呼び出しの形](oxref:linalg-api-forms)にある。

## ワンショット関数

次の 4 個の関数は分解や Plan を既定の設定で作って一度だけ解き、解の `Vector` だけを返す。
拒否はエラーになり、レポートは返らない。
行列関数と行列方程式のワンショット関数（`matrix_function`、`solve_sylvester`、`solve_lyapunov`、`solve_riccati`）は[行列関数と行列方程式](../functions-and-equations/)にある。

## まとめ

一度だけ解くなら `solve`・`least_squares`・`solve_triangular`・`solve_structured` を使い、拒否をエラーとして受け取る。
同じ行列で何度も解くなら、行列の性質に合わせて LU・Cholesky・LDL・Householder QR の分解を一度だけ作り、標準形式の `solve` で解く。
数値ランク・条件数・後退誤差で受理を決めたいときは `DirectSolveOptions` をオプション付き形式に渡し、`Ok` でも `solution()` が `None` になりうることを前提に終了理由を確かめる。
ランクが落ちうる最小二乗問題は `HouseholderMinimumNormPlan` で最小ノルム解を求め、行や列の追加・削除が続くなら `QrUpdateDecomposition` で分解を更新する。
低い精度の分解で高い精度の後退誤差が要るなら、`IterativeRefinement` に `RefinementProblem` を渡して `RefinementTermination` で成否を判定する。
