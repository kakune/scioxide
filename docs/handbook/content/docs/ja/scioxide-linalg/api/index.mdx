`scioxide-linalg` は、密行列と構造を持つ行列の格納と積、直接分解と解の受理、固有値と特異値、反復法、行列関数と行列方程式、行列関数のベクトルへの適用と部分スペクトルを出力に反映する。
このガイドでは目的ごとに最初に使う項目を示し、公開されている 342 項目を用途別の表にまとめる。
342 項目のうち 324 項目は既定の機能で出力に反映され、残りの 18 項目は `blas` 機能を有効にしたときだけ出力に反映される。
`backend` モジュールの 8 項目は、ほかの SciOxide クレートが使う下位の部品である。
これらは失敗したときに作業用のメモリを書き換えることがあり、ランクの方針も診断も持たない。
表の項目名のリンクは、docs.rs の 0.1.0 の API リファレンスを指す。

ワンショット関数は 8 個ある。
連立方程式の `solve`、`least_squares`、`solve_triangular`、`solve_structured` は[ワンショット関数](oxref:linalg-api-one-shot)の表に、行列関数と行列方程式の `matrix_function`、`solve_sylvester`、`solve_lyapunov`、`solve_riccati` は[行列関数と行列方程式](functions-and-equations/)の各節の表に載せる。

疎行列の格納（`CsrMatrix` など）と前処理（`JacobiPreconditioner`、`IncompleteFactor`、`AmgPreconditioner`）は scioxide-sparse が提供する。
作用素のトレイト（`LinearOperator`、`AdjointOperator`、`Preconditioner`）、許容誤差、上限、実行コンテキストは scioxide-core が提供する。
これらの型はこのガイドの表には含めず、それぞれの章の API ガイドで引く。

## 型の関係

格納の基本は所有の `Matrix`（行優先）と `Vector` である。
`view()` はストライド付きの `MatrixView` と `VectorView` を借用し、行列とベクトルを受け取る関数は `impl Into<MatrixView>` と `impl Into<VectorView>` の形なので、`&Matrix` や `&[S]` をそのまま渡せる。
`try_finite()` で非有限値がないと検査した `FiniteMatrixView` は `LinearOperator` を実装し、反復法と作用素の作用に作用素として渡せる。

分解型（`LuDecomposition` など）は、形の不一致、非有限値、厳密に 0 のピボットのような構造上の破綻だけをエラーにする。
解を受理するかどうかは解くときに `DirectSolveOptions` で決める。
この値は数値ランクの方針 `RankPolicy`、必要なときだけ与える逆条件数の下限 `ReciprocalConditionThreshold`、後退誤差を求めるかどうか（`Estimation`）を持つ。
既定値は `RankPolicy::Exact` で、因子が厳密に特異なときだけ解を拒否し、条件数も後退誤差も求めない。
帯・三重対角・三角の分解と Plan の `solve` は、係数行列を $A$、$A^{\mathsf T}$、$A^{\mathsf H}$ のどれにするかを選ぶ `StructuredOperation` を最初の引数に取る。

並列化の方針、積の精度 `Accuracy`、時間とバイト数の上限、反復の許容回数は、一つの `LinalgExecutionOptions` にまとめる。
密行列の操作と分解のうち設定を受け取る形（次の節のオプション付き形式・出力先を指定する API・スコープ付き API）はこの値を直接受け取り、各機能の設定（`DirectSolveOptions`、`StructuredSolveOptions`、反復法のソルバーなど）は `with_execution_options` で一度だけ取り込む。
そのため、機能の設定には数学的な選択だけが残る。

Plan（`…Plan`）は分解、係数、Schur 形のような再利用できるデータを構築のときに一度だけ計算して保持する。
手法オブジェクト（`ExponentialAction`、`LobpcgSolver`、`IterativeRefinement`、`CgSolver` など）は設定だけを持ち、作用素と次元を呼び出しのたびに受け取る。
Plan と違って事前に計算したデータを持たないので、一つの値を大きさの異なる問題に使い回せる。

## 呼び出しの形

一つの操作は名前の末尾で区別する次の形を持つ。
形の定義と使い分けは[呼び出しの形](oxref:linalg-execution-forms)にある。

| 形 | 名前 | 例 |
|---|---|---|
| ワンショット関数 | 自由関数 | `solve(&a, &b)`、`least_squares(&a, &b)` |
| 標準形式 | 接尾辞なし | `LuDecomposition::factor(&a)`、`lu.solve(&b)`、`x.norm2()` |
| オプション付き形式 | `*_with_options` | `LuDecomposition::factor_with_options(&a, &options)`、`lu.solve_with_options(&b, &accept)` |
| 出力先を指定する API | `*_into`、`*_in_place` | `lu.solve_into(&b, &accept, out, &mut ws, cx)` |
| スコープ付き API | `*_scoped` | `x.norm2_scoped(&options, cx)`、`lu.condition_estimate_scoped(&options, &mut ws, cx)` |

標準形式とオプション付き形式をあわせて所有値を返す API と呼ぶ。
所有値を返す API はクロックを持たない逐次のコンテキストで実行するので、時間の上限を設定すると計算を始める前に `CapabilityUnavailable` になる。
出力先を指定する API とスコープ付き API は、`ExecutionContext`（新しい操作の根）か `&mut SolveContext`（呼び出し元の操作の子として、使用量を上位の操作の上限にも数える）を受け取り、内部で `LinalgExecutionContext` に変換する。
並列実行、取り消し、期限、外部 BLAS のプロバイダーは、このコンテキストを通じて使う。

作業領域の大きさは一つの要求の値（`LuWorkspaceRequest` など）から `workspace_requirements` で問い合わせ、作業領域の `check` で足りるかを確かめ、`try_reserve` で事前確保する。
事前確保した後で同じ大きさの出力先を指定する API を繰り返し呼ぶと、新しいメモリを確保しない。

反復法のソルバーは前処理を持たず、呼び出しごとに `Preconditioning`（`None`、`Inverse`、`InverseAdjoint`）で前処理を借用する。
右辺が 1 本の 16 個のソルバーの標準形式 `solve(a, b)` は、0 から前処理なしで始め、許容誤差に達しなければ `ConvergenceFailure` を返す。
オプション付き形式 `solve_with_options(a, b, preconditioning, x0)` と出力先を指定する API `solve_into` は終了理由を返す。
どのソルバーも一つの `IterativeWorkspace` を使い、試行記録 `last_attempt()` と、成功したか使える反復解を残して止まった求解の結果 `last_accepted()` を残す。

## 最小の実行例：ピボットと呼び出しの形

$\varepsilon$ が小さい行列 $A = \begin{bmatrix} \varepsilon & 1 \\ 1 & 1 \end{bmatrix}$ と $b = (1, 2)$ の厳密解は、$x_1 = 1/(1-\varepsilon)$、$x_2 = (1-2\varepsilon)/(1-\varepsilon)$ である。
ピボットなしで $a_{11} = \varepsilon$ を軸に消去すると、$1/\varepsilon$ の大きな乗数が $a_{22}$ の情報を消し、$x_1$ が大きく狂う。
部分ピボット付きの LU 分解は、各段で絶対値が最大の成分を軸に選ぶので、乗数の絶対値は 1 以下に収まる。

次のセルは同じ系を、ワンショット関数 `solve`、分解の標準形式 `lu.solve`、オプション付き形式 `lu.solve_with_options`、出力先を指定する API `lu.solve_into` で解き、ピボットなしの消去を式で直接計算した値と並べる。
入力は左上の成分を $\varepsilon = 10^{t}$ と表す指数 $t$（$-20 \le t \le -1$）と、受理する逆条件数の下限を $\tau = 10^{s}$ と表す指数 $s$（$-6 \le s \le 0$）である。
オプション付き形式と出力先を指定する API は、ランクの方針 `DimensionScaledEpsilon`、下限 $\tau$、後退誤差の推定を指定した同じ `DirectSolveOptions` を受け取る。
1 つ目の表は経路ごとの終了理由、解、厳密解との相対差の最大を示し、受理されなかった経路の解を「出力の変更なし」と表示する。
2 つ目の表は分解が最初の軸に選んだ行、オプション付き形式のレポートの数値ランク、逆条件数 $\mathrm{rcond}_1$ の推定値、後退誤差を示す。
テストは解と厳密解の差、$\mathrm{rcond}_1$ の推定値と手計算の値 $1/4$、ピボットなしの消去の誤差を確かめる。

```rust
//| id: linalg-api-pivoted-solve
//| ref: linalg-api-pivoted-solve
//| title: 部分ピボット付き LU 分解を呼び出しの形ごとに比べる
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg]
//| inputs:
//|   epsilon_exponent: {"type":"range","label":"左上の成分 ε = 10^t の t","description":"小さいほどピボットなしの消去が不安定になる。","min":-20,"max":-1,"step":1,"value":-12}
//|   rcond_floor_exponent: {"type":"range","label":"受理する逆条件数の下限 τ = 10^s の s","description":"オプション付き形式と出力先を指定する API の受理の条件。s = 0 では τ = 1 となり、rcond₁ ≈ 0.25 のこの行列の解は拒否される。","min":-6,"max":0,"step":1,"value":-3}
//| cases:
//|   - {"id":"strict-floor","label":"τ = 1","description":"rcond₁ ≈ 0.25 が下限を下回り、オプション付き形式と出力先を指定する API は解を出力に反映しない。","inputs":{"rcond_floor_exponent":0}}
//|   - {"id":"mild-pivot","label":"ε = 0.1","description":"乗数が小さく、ピボットなしの消去でも誤差は丸めの程度に収まる。","inputs":{"epsilon_exponent":-1}}
//|   - {"id":"tiny-pivot","label":"ε = 10⁻¹⁷","description":"ピボットなしの消去では x₁ が 0 になる。","inputs":{"epsilon_exponent":-17}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"paths","path":"/rows/0/2","approx":{"value":1.000000000001,"rtol":1e-14}}
//|       - {"artifact":"paths","path":"/rows/2/4","range":{"max":1e-15}}
//|       - {"artifact":"paths","path":"/rows/3/1","equals":"Accepted"}
//|       - {"artifact":"paths","path":"/rows/4/4","approx":{"value":2.2e-5,"rtol":0.05}}
//|       - {"artifact":"diagnostics","path":"/rows/0/1","equals":2}
//|       - {"artifact":"diagnostics","path":"/rows/0/2","approx":{"value":0.25,"rtol":1e-6}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: strict-floor
//|     expect:
//|       - {"artifact":"paths","path":"/rows/1/4","range":{"max":1e-15}}
//|       - {"artifact":"paths","path":"/rows/2/1","equals":"IllConditioned"}
//|       - {"artifact":"paths","path":"/rows/2/2","equals":null}
//|       - {"artifact":"paths","path":"/rows/3/2","equals":null}
//|       - {"artifact":"diagnostics","path":"/rows/0/3","equals":null}
//|       - {"path":"/outputs/2/state","equals":"failed"}
//|   - case: mild-pivot
//|     expect:
//|       - {"artifact":"paths","path":"/rows/4/4","range":{"max":1e-15}}
//|       - {"artifact":"diagnostics","path":"/rows/0/2","approx":{"value":0.225,"rtol":1e-6}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: tiny-pivot
//|     expect:
//|       - {"artifact":"paths","path":"/rows/1/4","range":{"max":1e-15}}
//|       - {"artifact":"paths","path":"/rows/4/2","approx":{"value":0.0,"atol":1e-12}}
//|       - {"artifact":"paths","path":"/rows/4/4","approx":{"value":1.0,"atol":1e-12}}
use scioxide_core::ExecutionContext;
use scioxide_linalg::{
    DirectSolveOptions, DirectSolveTermination as T, Estimation, LinalgExecutionOptions,
    LuDecomposition, LuWorkspaceRequest, Matrix, RankPolicy, ReciprocalConditionThreshold,
    Vector, solve,
};

let eps = 10.0_f64.powf(epsilon_exponent);
let tau = 10.0_f64.powf(rcond_floor_exponent);
let a = Matrix::from_rows(&[[eps, 1.0], [1.0, 1.0]]).map_err(|e| e.to_string())?;
let b = Vector::from_vec(vec![1.0, 2.0]);
// 厳密解（独立な比較用）。
let exact = [1.0 / (1.0 - eps), (1.0 - 2.0 * eps) / (1.0 - eps)];

// ワンショット関数: 分解と求解を一度に行い、解だけを返す。
let x_once = solve(&a, &b).map_err(|e| e.to_string())?;
// 標準形式: 分解を残して再利用する。拒否はエラーになる。
let lu = LuDecomposition::factor(&a).map_err(|e| e.to_string())?;
let x_plain = lu.solve(&b).map_err(|e| e.to_string())?;
// オプション付き形式: 受理の条件を渡し、解とレポートを受け取る。拒否しても Ok を返す。
let floor = ReciprocalConditionThreshold::new(tau).map_err(|e| e.to_string())?;
let accept = DirectSolveOptions::new(RankPolicy::DimensionScaledEpsilon)
    .with_minimum_reciprocal_condition(floor)
    .with_residual(Estimation::Estimate);
let detailed = lu
    .solve_with_options(&b, &accept)
    .map_err(|e| e.to_string())?;
// 出力先を指定する API: 出力・作業領域・コンテキストを渡す。拒否すると出力を書き換えない。
let request = LuWorkspaceRequest::solve(2, &LinalgExecutionOptions::new());
let mut workspace = LuDecomposition::<f64>::workspace(&request).map_err(|e| e.to_string())?;
let mut borrowed = Vector::zeros(2).map_err(|e| e.to_string())?;
let report = lu
    .solve_into(
        &b,
        &accept,
        borrowed.view_mut(),
        &mut workspace,
        ExecutionContext::sequential_native(),
    )
    .map_err(|e| e.to_string())?;

// ピボットなしの消去を式で直接計算する（独立な比較用）。
let x2 = (2.0 - 1.0 / eps) / (1.0 - 1.0 / eps);
let naive = [(1.0 - x2) / eps, x2];

// 終了理由は列挙子の名前で示す。
let name = |t: T| match t {
    T::Accepted => "Accepted",
    T::RankDeficient => "RankDeficient",
    T::IllConditioned => "IllConditioned",
    T::ResidualRejected => "ResidualRejected",
    T::StabilityRejected => "StabilityRejected",
};
let diff = |x: &[f64]| {
    (0..2).fold(0.0_f64, |m, i| {
        m.max((x[i] - exact[i]).abs() / exact[i].abs())
    })
};
let row = |path: &'static str, status: Option<&'static str>, x: Option<&[f64]>| {
    (path, status, x.map(|x| x[0]), x.map(|x| x[1]), x.map(diff))
};
let accepted = report.termination() == T::Accepted;
let rows = vec![
    row("solve（ワンショット呼び出し）", None, Some(x_once.as_slice())),
    row("lu.solve（標準形式）", None, Some(x_plain.as_slice())),
    row(
        "lu.solve_with_options（オプション付き形式）",
        Some(name(detailed.report().termination())),
        detailed.solution().map(|x| x.as_slice()),
    ),
    row(
        "lu.solve_into（出力先を指定する API）",
        Some(name(report.termination())),
        accepted.then_some(borrowed.as_slice()),
    ),
    row("ピボットなしの消去（式）", None, Some(&naive[..])),
];
let full = serde_json::json!({ "significantDigits": 16 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "経路" },
    { "key": "1", "label": "終了理由", "nullText": "なし" },
    { "key": "2", "label": "x₁", "type": "number", "format": full, "nullText": "出力の変更なし" },
    { "key": "3", "label": "x₂", "type": "number", "format": full, "nullText": "出力の変更なし" },
    { "key": "4", "label": "厳密解との相対差の最大", "type": "number", "format": sci2, "nullText": "-" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "paths" })
);

let diagnostics = detailed.report();
let rcond = diagnostics.condition().map(|c| c.reciprocal().value());
let backward = diagnostics.residual().map(|r| r.scaled_norm());
let columns = serde_json::json!([
    { "key": "0", "label": "最初の軸の行（0 始まり）", "type": "integer" },
    { "key": "1", "label": "数値ランク", "type": "integer" },
    { "key": "2", "label": "rcond₁ の推定値", "type": "number", "format": sci3, "nullText": "未推定" },
    { "key": "3", "label": "後退誤差 η", "type": "number", "format": sci2, "nullText": "未計算" }
]);
emit_table_with_columns!(
    columns,
    vec![(
        lu.permutation()[0],
        diagnostics.rank().rank(),
        rcond,
        backward
    )],
    metadata = serde_json::json!({ "id": "diagnostics" })
);

let termination = diagnostics.termination();
let outcome = if termination.is_success() {
    Outcome::satisfied("オプション付き形式の解は受理の条件を満たした")
} else {
    Outcome::failed("オプション付き形式と出力先を指定する API は解を出力に反映しなかった").explanation(
        "標準形式とワンショット関数は既定の条件で受理する。下限 τ を下げると出力に反映される。",
    )
};
let mut outcome = outcome.status(name(termination));
if let Some(value) = rcond {
    outcome = outcome.diagnostic("rcond₁ の推定値", value, None);
}
if let Some(value) = backward {
    outcome = outcome.diagnostic("後退誤差 η", value, None);
}
emit_outcome!(outcome);
```

既定の $\varepsilon = 10^{-12}$ では、分解は 2 行目（添字 1）を最初の軸に選ぶ。
四つの経路はどれも同じ解を返し、式で求めた厳密解との相対差は 0 になる。
オプション付き形式と出力先を指定する API の終了理由は `Accepted`、数値ランクは 2、後退誤差 $\eta$ は 0 である。
$\lVert A \rVert_1 = 2$、$\lVert A^{-1} \rVert_1 = 2/(1-\varepsilon)$ から $\mathrm{rcond}_1 = (1-\varepsilon)/4$ と求まる。
$n \le 4$ の LU は $\lVert A^{-1} \rVert_1$ を推定せず逆行列の各列から計算するので、推定値 0.25 は丸め誤差の範囲でこの値と一致する。
ピボットなしの消去では、$x_1$ の相対差が $2.2 \times 10^{-5}$ になる。

$s = 0$ にすると下限 $\tau = 1$ が推定値 0.25 を上回り、オプション付き形式と出力先を指定する API の終了理由は `IllConditioned` になる。
オプション付き形式は `Ok` のまま解を出力に反映せず、出力先を指定する API は出力を書き換えないので、表の解の欄は「出力の変更なし」になる。
解を計算しないので後退誤差も求めず、2 つ目の表では「未計算」になる。
既定の条件で受理するワンショット関数と標準形式は、同じ解を返す。
$\varepsilon = 10^{-1}$ では消去の乗数が小さいので、ピボットなしでも相対差は $4.0 \times 10^{-16}$ で丸めの程度に収まり、$\mathrm{rcond}_1$ の推定値は 0.225 になる。
$\varepsilon = 10^{-17}$ では、ピボットなしの消去の $x_1$ が 0 になり、正しい値 1 とまったく合わない。
この行列の条件数 $\kappa_1(A) = 4/(1-\varepsilon)$ は 4 程度なので、ピボットなしの誤差は問題の悪条件ではなくアルゴリズムの不安定さによるものである。

## 結果・エラー・診断の読み方

- 失敗は scioxide-core の `SciOxideError` で返り、`kind()` で `DimensionMismatch`、`NonFinite`、`Singular`、`DomainError`、`NumericalInstability`、`ConvergenceFailure`、`ResourceLimit`、`AllocationFailure`、`ExecutionStopped`、`CapabilityUnavailable` などに分類する。
  エラーは何が失敗したかを表し、呼び出し元の識別子を持たない。
- 直接法の標準形式とワンショット関数は、解だけを返す。
  拒否は `DirectSolveTermination::require_accepted` によってエラーになり、ランク不足は `Singular`、それ以外は `NumericalInstability` になる。
- 直接法のオプション付き形式と出力先を指定する API、構造を持つ行列の求解、行列方程式は、受理しない場合も `Ok` を返す。
  結果は共通の終了理由 `DirectSolveTermination`（`Accepted`、`RankDeficient`、`IllConditioned`、`ResidualRejected`、`StabilityRejected`）と `solution()` の有無で伝わり、`into_accepted()` で標準形式と同じエラーに変換できる。
  拒否した候補のランクと条件数の診断（残差の検査で拒否したときは残差も）はレポートに残り、出力先を指定する API の出力は `Accepted` のときだけ書き換わる。
- 反復法のオプション付き形式と出力先を指定する API、作用素の作用、部分スペクトル、反復改良は、上限・取り消し・期限・停滞で止まった場合も、受理した最良の結果を `Ok` で返す。
  成否は `LinearSolveTermination`、`SpectralTermination`、`RefinementTermination` の終了理由だけで判定する。
  反復法のレポートでは、返した反復解の信頼区分は成功したときだけ `ResidualChecked` で、止まったときは `Admissible` になる。
  取り消しや期限による停止は `ExecutionStopped(reason)` で表し、評価回数と反復回数の上限は `EvaluationLimit` と `IterationLimit` で区別する。
- 出力先を指定する API は検査と計算が成功してから出力を書き換え、`Err` のときは出力を変えない。
  作業領域の `last_attempt()` は結果を `Succeeded`、`Stopped`、`Failed`、`PreflightRejected` に分けて記録する。
- 分解の後退誤差の上界（$c\,n\,\varepsilon$ の形）、`Accuracy` の内積の誤差限界、レポートの残差と後退誤差は、どれも前進誤差を保証しない。
  前進誤差は条件数の推定と合わせて読む。
  規約の全体は[線形代数の数理と共通の規約](../algorithms/)にある。

## まとめ

目的が決まっていれば、目的別の API の表から API の項目を選び、用途別の表でその仕様と解説節を確かめる。
一度だけ解くならワンショット関数か標準形式を使い、拒否をエラーとして受け取る。
受理の条件を選んでレポートを読むならオプション付き形式を使い、`Ok` でも `solution()` が `None` になりうることを前提に終了理由を確かめる。
同じ大きさの計算を繰り返すなら、要求の値から作業領域を一度だけ事前確保し、出力先を指定する API で呼んで確保を避ける。
反復法と作用素の作用の成否は、`Ok` かどうかではなくレポートの終了理由で判定する。
