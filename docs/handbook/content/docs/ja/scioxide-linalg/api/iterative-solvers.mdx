この表は正方の作用素の方程式 $Ax = b$ と長方形の最小二乗問題を解く反復法と、それらが共有する作業領域・レポート・終了理由の型をまとめる。
ソルバーの型（`…Solver`）は許容誤差、反復の上限、実行の設定などの設定だけを持つ手法オブジェクトで、作用素も前処理も保持しない。
前処理は呼び出しごとに `Preconditioning` で借用する。

単一の右辺のソルバーは三つの形で呼び出せる。
形の定義は[呼び出しの形](oxref:linalg-api-forms)にある。
標準形式 `solve(a, b)` は零ベクトルから前処理なしで解き、解の `Vector` を返す。
許容誤差を満たさずに終わると `ConvergenceFailure`（`NestedSolver`）になる。
オプション付き形式 `solve_with_options(a, b, preconditioning, x0)` は前処理と初期値（`None` なら零）を受け取り、終了理由を含む `IterativeSolveResult` を返す。
出力先を指定する API `solve_into(a, b, preconditioning, x, workspace, context)` は `x` の値から始め、`IterativeWorkspace` とコンテキストを使って `IterativeSolveReport` を返す。
LSQR・LSMR と行列分割の定常反復は前処理の引数を持たない。
ブロック法の `solve(a, b, preconditioning, x0)` は終了理由を含む `BlockKrylovResult` を返す。

反復回数は `new` に渡す上限と、`with_execution_options` で合成した反復の許容回数の小さい方で制限される。
オプション付き形式と出力先を指定する API は、反復と評価の上限、停滞、破綻、取り消し、期限で止まっても `Ok` を返し、検証済みの反復解のうち真の残差が最小のものを解とする。
成否は終了理由 `LinearSolveTermination` で判定する。
レポートの信頼区分は成功したときだけ `ResidualChecked` で、止まったときは `Admissible` である。
停滞（`Stagnation`）は、更新で反復解が変わらなかったときと、検証した真の残差がそれまでの最小を下回らず、その最小が丸め誤差の下限 $\varepsilon c(\lVert b \rVert_2 + \lVert A(s \circ x) \rVert_2)$ 以下のときに判定する。
ここで $x$ は残差が最小の検証済みの反復解、$s$ は固定の $\pm 1$ の符号の列、$c$ は実数で 16、複素数で 32 である。
$A(s \circ x)$ の積も評価の上限に数える。
毎反復に真の残差を計算する定常反復（Richardson と行列分割の反復）は 50 回ごとの検査点でだけ下限を判定し、GMRES 系（LGMRES、GCROT、ブロック法を含む）は周期の終わりと、射影した残差が許容誤差を満たした検証でだけ判定する。
下限は許容誤差を変えない。
`Err` になる主な場合は、形の不一致（数値計算の前に拒否する）、非有限値、漸化式の桁あふれ、作用素や前処理のプロバイダーのエラー、リソースの確保の失敗、初期残差を計算する前に評価の上限に達した場合と、各行に書いた解法ごとの拒否（MINRES の非 Hermitian、定常反復の対角の 0 など）で、そのとき出力は変わらない。

## まとめ

Hermitian 正定値なら `CgSolver`、Hermitian 不定値なら `MinresSolver`、非対称なら `GmresSolver` か `BicgstabSolver`、長方形の最小二乗なら `LsqrSolver` か `LsmrSolver` を選ぶ。
解だけが要るなら標準形式 `solve(a, b)` を使い、収束しなければエラーとして受け取る。
前処理、初期値、停止したときの反復解と残差が要るならオプション付き形式を使い、`IterativeSolveResult` の終了理由で成否を判定する。
同じ形の求解を繰り返すときは `IterativeWorkspaceRequest` から作業領域を事前確保して出力先を指定する API を使い、試行記録と受理状態を `IterativeWorkspace` から読む。
同じ作用素で右辺だけを変えて繰り返すなら、LGMRES・GCROT の `solve_recycled_into` で再利用空間を持ち越せる。
