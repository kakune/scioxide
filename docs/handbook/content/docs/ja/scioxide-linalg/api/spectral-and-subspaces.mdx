この表は特異値と固有値を求める分解、その結果から作る部分空間、一般化した分解、零空間を宣言した境界付きの系の型をまとめる。
固有値と特異値の型は、値だけを求める型（`SvdValues`、`…ValuesResult`、`…ValuesBuffer`）と、ベクトルも求める型（`…Decomposition`）に分かれる。

分解は三つの形で呼び出せる。
形の定義は[呼び出しの形](oxref:linalg-api-forms)にある。
標準形式（`compute(a)`、`decompose(a)`、`factor(a)`）は既定の設定を使い、オプション付き形式（`compute_with_options` など）は設定を最後の引数に取る。
この二つは結果を確保して `ExecutionContext::sequential_native()` で逐次に実行する所有値を返す API であり、時間の上限を設定すると `CapabilityUnavailable` になる。
出力先を指定する API（`compute_into`、`decompose_into`、`factor_into`）は設定と呼び出し側の出力、作業領域、コンテキストを受け取って出力に書く。
作業領域の要件は結果の型の `workspace_requirements` に要求（`…WorkspaceRequest`）を渡して求める。

形の不一致、非有限な入力、反復の上限による `ConvergenceFailure` などの分解の失敗は `Err` で返り、出力先を指定する API の出力は変わらない。
所有値を返す API の `…ValuesResult` は値と作業のレポート `EigenReport` を持つが、出力先を指定する API の出力 `…ValuesBuffer` はレポートを持たない。
条件数や分離の欄は推定であり、上界ではない。

## まとめ

特異値や固有値を求めるときは、値だけで足りるなら `SvdValues` や `…ValuesResult`、ベクトルも要るなら `…Decomposition` の標準形式（`compute(a)`、`decompose(a)`）から始める。
許容誤差、順序、平衡化、反復の上限を変えるときはオプション付き形式に設定の値を渡し、同じ大きさの問題を繰り返すときは要求から作業領域を事前確保して出力先を指定する API を使う。
数値ランク、部分空間、Procrustes 問題の一意性の分類は、どれも `RankPolicy` のしきい値で決まり、レポートの `rank` と `condition` で確かめられる。
GSVD、CS 分解、極分解は、再構成の残差（CS 分解と極分解では直交性の誤差も）が許容値を超える因子を `NumericalInstability` で拒否する。
零空間が分かっている特異な系は `BorderedSystem` で正則な拡大系にして、直接法か反復法で解き、`diagnose` で元の系の残差を確かめる。
