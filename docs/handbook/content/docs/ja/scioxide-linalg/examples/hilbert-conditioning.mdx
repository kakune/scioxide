連立一次方程式の解の誤差は解法の安定性と問題の条件数の二つで決まる。
後退安定な解法は「少しだけ違う問題の厳密解」を返すが、条件の悪い問題ではその少しの違いが解を大きく変える。
この例題では条件数が次数とともに急速に増える Hilbert 行列を使い、二つの要因を分けて観察する。
真の解を $x^\ast = (1, \dots, 1)$ と決め、次数 $n = 2, \dots, 13$ の系 $H_n x = b$ を倍精度（`f64`）で解く。
さらに、単精度（`f32`）の分解と倍精度の残差を組み合わせる反復改良が、どの次数まで倍精度の LU 分解と同じ精度に達するかを確かめる。
誤差と条件数の一般論は[浮動小数点と条件数](../../../concepts/floating-point-and-conditioning/)にまとめてある。

## Hilbert 行列と条件数

$n$ 次の Hilbert 行列は、成分が（0 始まりの添字で）

$$
(H_n)_{ij} = \frac{1}{i + j + 1}, \qquad 0 \le i, j < n
$$

の対称正定値行列である。
これは区間 $[0, 1]$ の単項式 $1, x, \dots, x^{n-1}$ の $L^2$ 内積を並べた Gram 行列で、$[0, 1]$ 上の関数を $n-1$ 次の多項式で最小二乗近似するときの正規方程式の係数行列に当たる。
高次の単項式は区間の上でたがいに似た形になるので、列はほぼ線形従属になる。
2 ノルムの条件数 $\kappa_2(H_n) = \sigma_{\max}/\sigma_{\min}$ は、定数倍を除いて

$$
\kappa_2(H_n) \propto \frac{(1+\sqrt2)^{4n}}{\sqrt{n}} \approx \frac{e^{3.5 n}}{\sqrt n}
$$

の速さで増え、次数を一つ上げるごとにおよそ $(1+\sqrt2)^4 \approx 34$ 倍になる（$n = 5$ で $4.8 \times 10^{5}$、$n = 10$ で $1.6 \times 10^{13}$）。
逆行列は成分がすべて整数になる閉じた形を持ち、`StructuredMatrixView::hilbert(n, MatrixForm::Inverse)` で得られる（[構造を持つ行列](../../algorithms/structured-systems/)）。
`materialize()` を呼ぶと、どちらの形も密な `Matrix` になる。
逆行列で絶対値が最大の成分は $n = 12$ で $3.7 \times 10^{15}$ と $2^{53} \approx 9.0 \times 10^{15}$ 未満なので丸めなしに表せるが、$n = 13$ では $1.1 \times 10^{17}$ になり、一部の成分に相対 $u$ の丸めが入る。

## 前進誤差と後退誤差

計算した解 $\hat x$ の後退誤差は、$\hat x$ を厳密解とする近くの問題までの相対的な距離

$$
\eta(\hat x) = \frac{\lVert b - H\hat x \rVert_\infty}{\lVert H \rVert_\infty \lVert \hat x \rVert_\infty + \lVert b \rVert_\infty}
$$

である。
部分ピボット付き LU 分解では、増大因子が小さい限り $\eta$ は単位丸め $u = 2^{-53} \approx 1.1 \times 10^{-16}$ の小さな倍数になる。
前進誤差は解そのものの相対的な差で、$H$ と $b$ の両方の摂動を測るこの $\eta$ について、$\kappa_\infty(H)\,\eta < 1$ なら

$$
\frac{\lVert \hat x - x \rVert_\infty}{\lVert x \rVert_\infty} \le \frac{2\,\kappa_\infty(H)\,\eta}{1 - \kappa_\infty(H)\,\eta}
$$

が成り立つ（$x$ は格納した系の厳密解）。
$H$ は対称なので $\kappa_\infty(H) = \kappa_1(H)$ である。
$\kappa_\infty \eta \ge 1$ ではこの上界は意味を持たず、解が 1 桁も合わないこともある。
$H_n$ の成分 $1/(i+j+1)$ はほとんどが二進数の有限桁で表せないので、行列を格納しただけで成分ごとに相対 $u$ の摂動が入る。
格納した系の厳密解はそのぶん $x^\ast$ から $\kappa u$ の程度ずれうるので、どんな解法を使っても $x^\ast$ に対する前進誤差は $\kappa u$ の程度になりうる。

`LuDecomposition::factor(&h)` は部分ピボット付き LU 分解で、数値の性質で分解が失敗するのは厳密に 0 のピボットに出会ったとき（`Singular`）だけである。
解を受理するかどうかは求解のときに `DirectSolveOptions` の条件で別に判定する（[解の受理](oxref:linalg-factorization-acceptance)）。
レポートを読むために、このページでは求解に[オプション付き形式](oxref:linalg-execution-forms) `solve_with_options(&b, &options)` を使う。
オプション付き形式は解とレポートをまとめた `DirectSolveResult` を返し、受理されなかった解は `Ok` のまま出力に反映せず、`solution()` が `None` になる。
`with_residual(Estimation::Estimate)` を付けると、レポートの `residual()` が上の $\eta$ を元の行列について返す。
`with_minimum_reciprocal_condition` で逆条件数の下限を与えると、求解の前に下の節の方法で逆条件数を推定し、推定値が下限を下回れば終了理由を `DirectSolveTermination::IllConditioned` にして解を出力に反映しない。
ランクの方針は `RankPolicy::Exact`（厳密な 0 のピボットだけを不足とみなす）で、下限を与えなければ悪条件の次数でも解は受理される。

次のセルは右辺を $b = Hx^\ast$ とし、次数 2 から $n_{\max}$（4〜13）までの LU 分解の解を調べる。
条件数は三つの方法で求める。
`SvdValues::compute` の特異値の比による $\kappa_2$、閉じた形の逆行列による $\kappa_1 = \lVert H \rVert_1 \lVert H^{-1} \rVert_1$（`MatrixView::norm(MatrixNorm::One)` で計算する独立な検算）、LU 因子の `condition_estimate()` が返す $\mathrm{rcond}_1 = 1/\kappa_1$ の推定値の逆数である。
入力の「逆条件数の下限」は「なし」、$10^{-14}$、$10^{-10}$ から選ぶ。
表は次数ごとに三つの条件数、終了理由、後退誤差 $\eta$、$x^\ast$ に対する前進誤差、目安 $\kappa_2 u$ を示し、出力に反映されなかった解の誤差は「出力の変更なし」と示す。
グラフは $\kappa_2$、前進誤差、$\kappa_2 u$（破線）を対数軸で描く。

```rust
//| ref: linalg-hilbert-conditioning
//| title: Hilbert 行列の条件数と LU 分解の前進誤差・後退誤差

//|   rcond_floor: {"type":"select","label":"逆条件数の下限","description":"推定した rcond₁ がこれを下回る次数では解を出力に反映しない。","options":["なし","1e-14","1e-10"],"value":"なし"}

//|   - {"id":"order-13","label":"n_max = 13","description":"κ₂ u が 1 を大きく超え、前進誤差が 1 を超える。","inputs":{"max_order":13}}

//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"orders","path":"/rows/8/2","approx":{"value":3.5357e13,"rtol":1e-4}}
//|       - {"artifact":"orders","path":"/rows/8/3","approx":{"value":3.5357e13,"rtol":0.05}}
//|       - {"artifact":"orders","path":"/rows/8/1","approx":{"value":1.6025e13,"rtol":1e-3}}
//|       - {"artifact":"orders","path":"/rows/10/4","equals":"Accepted"}
//|       - {"artifact":"orders","path":"/rows/10/5","range":{"max":1e-15}}
//|       - {"artifact":"orders","path":"/rows/3/6","range":{"max":1e-10}}
//|   - case: order-13
//|     expect:
//|       - {"artifact":"orders","path":"/rows/11/2","approx":{"value":1.3244e18,"rtol":0.05}}
//|       - {"artifact":"orders","path":"/rows/11/6","range":{"min":1.0}}
//|   - case: floor-1e-10
//|     expect:
//|       - {"artifact":"orders","path":"/rows/5/4","equals":"Accepted"}
//|       - {"artifact":"orders","path":"/rows/6/4","equals":"IllConditioned"}
//|       - {"artifact":"orders","path":"/rows/6/6","equals":null}
//|       - {"artifact":"orders","path":"/rows/6/2","approx":{"value":3.3873e10,"rtol":1e-4}}
use scioxide_linalg::{
    DirectSolveOptions, DirectSolveTermination, Estimation, LuDecomposition, MatrixForm,
    MatrixNorm, RankPolicy, ReciprocalConditionThreshold, StructuredMatrixView, SvdValues,
};

// 後退誤差 η の診断を要求し、下限を選んだときは推定した逆条件数で受理を判定する。
let mut accept = DirectSolveOptions::new(RankPolicy::Exact).with_residual(Estimation::Estimate);
if rcond_floor != "なし" {
    let floor: f64 = rcond_floor.parse().map_err(|_| "下限を読めない")?;
    let threshold = ReciprocalConditionThreshold::new(floor).map_err(|e| e.to_string())?;
    accept = accept.with_minimum_reciprocal_condition(threshold);
}
let unit = f64::EPSILON / 2.0;
let mut rows = Vec::new();
let (mut kappa_line, mut forward_line, mut bound_line) = (Vec::new(), Vec::new(), Vec::new());
for n in 2..=max_order.round() as usize {
    let dense = |form: MatrixForm| {
        StructuredMatrixView::<f64>::hilbert(n, form).and_then(|view| view.materialize())
    };
    let h = dense(MatrixForm::Direct).map_err(|e| e.to_string())?;
    let sigma = SvdValues::compute(&h).map_err(|e| e.to_string())?;
    let kappa2 = sigma.singular_values()[0] / sigma.singular_values()[n - 1];
    // 閉じた形の逆行列（整数）による κ₁ = ‖H‖₁ ‖H⁻¹‖₁（独立な検算）。
    let inverse = dense(MatrixForm::Inverse).map_err(|e| e.to_string())?;
    let h_norm = h.view().norm(MatrixNorm::One).map_err(|e| e.to_string())?;
    let kappa1 = h_norm
        * inverse
            .view()
            .norm(MatrixNorm::One)
            .map_err(|e| e.to_string())?;
    let lu = LuDecomposition::factor(&h).map_err(|e| e.to_string())?;
    let rcond = lu.condition_estimate().map_err(|e| e.to_string())?;
    // 真の解 x* = (1, …, 1) から右辺 b = H x* を作り、オプション付き形式で解いてレポートを読む。
    let ones = vec![1.0_f64; n];
    let b = h.view().mul_vec(&ones[..]).map_err(|e| e.to_string())?;
    let result = lu
        .solve_with_options(&b, &accept)
        .map_err(|e| e.to_string())?;
    let name = match result.report().termination() {
        DirectSolveTermination::Accepted => "Accepted",
        DirectSolveTermination::RankDeficient => "RankDeficient",
        DirectSolveTermination::IllConditioned => "IllConditioned",
        DirectSolveTermination::ResidualRejected => "ResidualRejected",
        DirectSolveTermination::StabilityRejected => "StabilityRejected",
    };
    let backward = result.report().residual().map(|r| r.scaled_norm());
    let forward = result.solution().map(|x| {
        x.as_slice()
            .iter()
            .fold(0.0_f64, |m, &v| m.max((v - 1.0).abs()))
    });
    let estimate = 1.0 / rcond.reciprocal().value();
    rows.push((
        n,
        kappa2,
        kappa1,
        estimate,
        name,
        backward,
        forward,
        kappa2 * unit,
    ));
    kappa_line.push([n as f64, kappa2]);
    bound_line.push([n as f64, kappa2 * unit]);
    // 対数軸に描けない 0 の誤差と、出力に反映されなかった解は除く。
    if let Some(error) = forward.filter(|&e| e > 0.0) {
        forward_line.push([n as f64, error]);
    }
}
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "次数 n [-]", "type": "integer" },
    { "key": "1", "label": "κ₂（SVD）[-]", "type": "number", "format": sci3 },
    { "key": "2", "label": "κ₁（厳密な逆行列）[-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "1/rcond₁ の推定 [-]", "type": "number", "format": sci3 },
    { "key": "4", "label": "終了理由" },
    { "key": "5", "label": "後退誤差 η [-]", "type": "number", "format": sci2, "nullText": "出力の変更なし" },
    { "key": "6", "label": "前進誤差 [-]", "type": "number", "format": sci2, "nullText": "出力の変更なし" },
    { "key": "7", "label": "κ₂ u [-]", "type": "number", "format": sci2 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "orders" })
);
emit_line_chart!(
    &vec![
        serde_json::json!({ "name": "κ₂", "points": kappa_line }),
        serde_json::json!({ "name": "前進誤差 ‖x̂ − x*‖∞", "points": forward_line }),
        serde_json::json!({
            "name": "κ₂ u",
            "points": bound_line,
            "style": { "lineType": "dashed" }
        })
    ],
    options = &serde_json::json!({
        "xLabel": "次数 n [-]",
        "yLabel": "条件数・誤差 [-]",
        "yType": "log",

    })

```

既定値（$n_{\max} = 12$、下限なし）では、表の後退誤差 $\eta$ はどの次数でも $1.6 \times 10^{-16}$ 以下で、LU 分解は後退安定に計算している。
一方、前進誤差は $n = 5$ で $2.1 \times 10^{-11}$、$n = 10$ で $3.6 \times 10^{-4}$、$n = 12$ で $0.52$ と増え、どの次数でも破線の $\kappa_2 u$ の下にある。
上界の条件 $\kappa_1 \eta < 1$ は $n \le 11$ で成り立ち、たとえば $n = 10$ では $\kappa_1 \eta = 5.4 \times 10^{-3}$ から上界は $1.1 \times 10^{-2}$ になる。
$n = 12$ では $\kappa_1 \eta \approx 4.8$ で上界は使えず、$\kappa_2 u$ も 1 を超える（1.9）。
$n_{\max} = 13$ にすると $n = 13$ の前進誤差は 12 になり、計算した解は真の解と 1 桁も合わない。
それでも終了理由は `Accepted` で $\eta$ は $2.9 \times 10^{-17}$ なので、レポートの後退誤差だけでは解の精度を判断できない。
前進誤差は丸めの順序にも敏感で、ネイティブ環境の積のカーネルで実行すると、同じ次数でも数倍から 10 倍違う値になる（本文の数値はブラウザでの実行の値）。
グラフは対数軸なので、前進誤差が厳密に 0 になる次数があればその点を除いて描く。

SVD による $\kappa_2$ は、$n \le 12$ では $\kappa_1$ の 0.42〜0.71 倍で、両者はそろって増える。
$n = 13$ では比が 1.1 に跳ね、この関係から外れる。
後退安定な SVD が求める特異値には、$u\,\sigma_{\max}$ の程度の絶対誤差が入る。
$\sigma_{\min}$ がこれより小さくなる $\kappa_2 > 1/u$ の行列では、計算した $\sigma_{\min}$ は相対的に 1 桁も合わない。
格納の丸めも行列を相対 $u$ だけ動かすので、$\sigma_{\min}$ を同じ大きさで変える。
したがって $1/u \approx 9 \times 10^{15}$ を超える条件数は、SVD でも大きさの目安にしかならない。

## 条件数の推定値の読み方

`condition_estimate()` は $\lVert A^{-1} \rVert_1$ を Hager の方法と Higham による改良で推定し、元の行列の座標での $\mathrm{rcond}_1 = 1/(\lVert A \rVert_1 \lVert A^{-1} \rVert_1)$ を `ConditionEstimate` として返す。
$\lVert A \rVert_1$ は分解のときに厳密に計算してある。
推定は $A^{-1}$ を作らず、保持した LU 因子で $A^{-1}v$ と $A^{-\mathsf T}v$ を数回だけ解き、試したベクトルの比 $\lVert A^{-1}v \rVert_1 / \lVert v \rVert_1$ の最大値をとる。
1 回の求解は $O(n^2)$ で、分解の $O(n^3)$ より小さい。
4 次以下では $\lVert A^{-1} \rVert_1$ を厳密に計算する。
どの試行ベクトルでも比は $\lVert A^{-1} \rVert_1$ を超えないので、厳密な算術では推定値は $\lVert A^{-1} \rVert_1$ の下界で、表の「1/rcond₁ の推定」は $\kappa_1$ の下界になる。
多くの場合は真の値の 10 倍以内に入るが、保証はない。
浮動小数点では $A^{-1}v$ を LU 因子で解く誤差が入るので下界とも限らず、`reciprocal()` が返す `ReliableEstimate` の信頼性は `Heuristic`（上界でも下界でも保証のない推定）である。

表の「1/rcond₁ の推定」は $n \le 12$ では厳密な $\kappa_1$ と有効数字 2〜3 桁で一致する（$n = 10$ でどちらも $3.54 \times 10^{13}$）。
$n = 13$ では $\kappa_1 u > 1$ なので、格納した $H$ の逆行列は閉じた形の逆行列から大きく離れうるうえ、LU 因子による作用にも同じ大きさの誤差が入る。
推定値の逆数が $\kappa_1$ の 1.7 倍になって下界の性質が崩れているのは、このためである。
この例では $n \le 12$ で有効数字 2〜3 桁まで合ったが、一般には桁の目安として解釈する。
条件数そのものを確かめたい場合は特異値（$\kappa_2$）や、構造が分かっていれば閉じた形の逆行列を使う。

逆条件数の下限を $10^{-10}$ にすると、推定した $\mathrm{rcond}_1$ が $2.95 \times 10^{-11}$ の $n = 8$ から先で終了理由が `IllConditioned` になり、解と $\eta$ は出力に反映されない（表の「出力の変更なし」）。
下限を $10^{-14}$ にすると、拒否されるのは $\mathrm{rcond}_1$ が $8.1 \times 10^{-16}$ の $n = 11$ からになる。
この拒否は `Ok` で返る結果で、分解はそのまま残るので、下限を変えて同じ因子で解き直せる。
拒否を誤りとして扱いたいときは、結果の `into_accepted()` で `NumericalInstability`（`IllConditioned`）の誤りに変える。
標準形式の `solve(&b)` は既定の条件（`RankPolicy::Exact`、下限なし）で判定する。
厳密に 0 のピボットは分解の段階で `Singular` の誤りになるので、`factor` が返した LU の因子なら、標準形式の `solve` は必ず解を受理する。

## 混合精度の反復改良

混合精度の反復改良では LU 分解の $\tfrac23 n^3$ 回の演算を単精度（`f32`、単位丸め $u_f = 2^{-24} \approx 6 \times 10^{-8}$）で行う（[反復改良](../../algorithms/iterative-refinement/)）。
残差 $r_k = b - H x_k$ だけを倍精度で計算し、単精度の因子で解いた補正 $d_k$ を $x_{k+1} = x_k + d_k$ と足す。
補正の方程式を後退安定な単精度の LU で解くと、補正はある $E_k$ について $(H + E_k)\,d_k = r_k$ を満たす。
$\lVert E_k \rVert_\infty \le c_n \rho_n u_f \lVert H \rVert_\infty$（$c_n$ は $n$ の小さな多項式、$\rho_n$ は LU の増大因子）とし、$\theta = \lVert H^{-1} E_k \rVert_\infty < 1$ とすると、残差の丸めを無視した誤差は一回ごとに

$$
\lVert x_{k+1} - x \rVert_\infty \lesssim \frac{\theta}{1 - \theta}\, \lVert x_k - x \rVert_\infty, \qquad \theta \le c_n \rho_n\, \kappa_\infty(H)\, u_f
$$

を満たす。
縮小率 $\theta/(1-\theta)$ が 1 未満になるのは $\theta < 1/2$ のときで、$\theta$ が $1/2$ に近づくほど補正の回数が増え、それを超えるとこの評価は誤差の減少を示さない。
したがって $\kappa_\infty(H) u_f$ が 1 より十分小さいことが収束の目安になる。
Hilbert 行列で $\kappa_2 u_f$ が 1 を超えるのは $n = 7$ である。
収束した解の $x^\ast$ に対する前進誤差は、`f64` の LU 分解と同じく $\kappa u$ の程度にとどまる。
改良が解くのは $H$ と $b$ を `f64` で格納した系で、その格納の丸めが解を $\kappa u$ の程度動かすからである。

`IterativeRefinement<L, H>` は、因子の精度 `L` と残差の精度 `H` の組（`f32`/`f32`、`f64`/`f64`、`f32`/`f64` と、その複素数版）で改良する[手法オブジェクト](oxref:linalg-execution-forms)である（入力と結果の全体は [IterativeRefinement の入力と結果](oxref:linalg-refinement-inputs)）。
値は `RefinementOptions` の設定だけを持ち、元の系と逆作用素は呼び出しのたびに `RefinementProblem::new(system, inverse, scaling, fallback)` として借用する。
このセルの `system` は `f64` の元の行列 `RefinementSystem::Dense`、`inverse` は `f32` の LU 因子の `inverse_operator()` で、改良は分解を自分では行わない。
後退誤差が `atol + rtol` 以下になれば `Converged` で止まり、後退誤差を厳密に減らさない補正は捨てて `Stagnation` で止まる。
補正回数の上限は `LinalgExecutionOptions::with_iteration_budget` で与え、既定は右辺ごとに 10 回である。
`RefinementFallback::OnFailure` を選ぶと、残差を因子の精度へ変換できないとき、低い精度の逆作用素が数値的に失敗したとき、改良が停滞したときに、`fallback` に渡した `f64` の逆作用素へ一度だけ切り替える（退避）。
補正回数は捨てた補正と退避した後の補正も数える。
`refine(&problem, &b, &x0)` は改良した解と `RefinementReport` を返し、成功しなかった改良でも、採用した反復のうち最良のものを `Ok` で返す。
終了理由 `RefinementTermination` は `Converged` だけが成功で、`Stagnation`、`IterationLimit`、`EvaluationLimit`、`ExecutionStopped` は停滞や上限で止まったこと、`CorrectionFailed` は退避のない補正の失敗を表す。

次のセルは次数 $n = 3, \dots, 10$ ごとに `f32` の Hilbert 行列を分解し、`IterativeRefinement::<f32, f64>` で初期値 $x_0 = 0$ から倍精度の解へ改良する。
入力は最大補正回数（1〜20 回）と退避の有無である。
表は終了理由、補正回数、後退誤差、改良した解の前進誤差を、`f32` の LU だけで解いた場合と `f64` の LU 分解（どちらも標準形式の `solve`）と並べる。
許容誤差は $\mathrm{atol} = 0$、$\mathrm{rtol} = 10^{-15}$ で、ノルムごとの後退誤差 $\eta$ で判定する。
outcome は全次数をまとめた結論で、すべての次数が `Converged` なら `satisfied`、止まった次数があれば `partial`、`CorrectionFailed` があれば `failed` にする。

```rust
//| id: linalg-hilbert-refinement
//| ref: linalg-hilbert-refinement
//| title: 単精度の LU と倍精度の残差による Hilbert 系の反復改良
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg]
//| inputs:
//|   max_iterations: {"type":"range","label":"最大補正回数 [回]","description":"一つの次数で行う補正の上限。","min":1,"max":20,"step":1,"value":10}
//|   use_fallback: {"type":"checkbox","label":"f64 の LU に退避する","description":"改良が止まったときに一度だけ f64 の逆作用素へ切り替える。","value":false}
//| cases:
//|   - {"id":"fallback","label":"退避あり","description":"停滞した次数も f64 の逆作用素に切り替えて Converged になる。","inputs":{"use_fallback":true}}
//|   - {"id":"one-correction","label":"最大補正回数 1","description":"f32 の分解で一度解いただけで IterationLimit になる。","inputs":{"max_iterations":1}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"refinement","path":"/rows/0/3","equals":"Converged"}
//|       - {"artifact":"refinement","path":"/rows/3/3","equals":"Converged"}
//|       - {"artifact":"refinement","path":"/rows/3/1","approx":{"value":0.89,"rtol":0.01}}
//|       - {"artifact":"refinement","path":"/rows/4/3","equals":"Stagnation"}
//|       - {"artifact":"refinement","path":"/rows/2/6","range":{"max":1e-9}}
//|       - {"path":"/outputs/1/state","equals":"partial"}
//|   - case: fallback
//|     expect:
//|       - {"artifact":"refinement","path":"/rows/7/3","equals":"Converged"}
//|       - {"artifact":"refinement","path":"/rows/7/8","equals":"Stagnation"}
//|       - {"artifact":"refinement","path":"/rows/7/6","range":{"max":1e-2}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: one-correction
//|     expect:
//|       - {"artifact":"refinement","path":"/rows/0/3","equals":"IterationLimit"}
//|       - {"artifact":"refinement","path":"/rows/0/6","range":{"min":1e-7,"max":1e-4}}
//|       - {"path":"/outputs/1/state","equals":"partial"}
use scioxide_core::{Budget, LinearOperator, ResidualTolerance};
use scioxide_linalg::{
    IterativeRefinement, LinalgExecutionOptions, LuDecomposition, MatrixForm,
    RefinementFallback, RefinementFallbackReason, RefinementOptions, RefinementProblem,
    RefinementSystem, RefinementTermination, StructuredMatrixView, SvdValues,
};

let tolerance = ResidualTolerance::new(0.0, 1e-15).map_err(|e| e.to_string())?;
// 補正回数の上限は、合成する実行の設定の反復の上限として与える。
let budget = Budget::try_from(max_iterations.round() as usize).map_err(|e| e.to_string())?;
let policy = if use_fallback {
    RefinementFallback::OnFailure
} else {
    RefinementFallback::Disabled
};
let options = RefinementOptions::new(tolerance)
    .with_execution_options(LinalgExecutionOptions::new().with_iteration_budget(budget))
    .with_fallback(policy);
// 手法オブジェクトは設定だけを持ち、問題（元の系と逆作用素）は呼び出しごとに借用する。
let refinement = IterativeRefinement::<f32, f64>::new(options).map_err(|e| e.to_string())?;
let error = |v: &[f64]| v.iter().fold(0.0_f64, |m, &xi| m.max((xi - 1.0).abs()));
let single_unit = f64::from(f32::EPSILON) / 2.0;
let (mut rows, mut stopped, mut failed, mut hardest) = (Vec::new(), 0, 0, "");
for n in 3..=10_usize {
    let h = StructuredMatrixView::<f64>::hilbert(n, MatrixForm::Direct)
        .and_then(|view| view.materialize())
        .map_err(|e| e.to_string())?;
    let h32 = StructuredMatrixView::<f32>::hilbert(n, MatrixForm::Direct)
        .and_then(|view| view.materialize())
        .map_err(|e| e.to_string())?;
    let sigma = SvdValues::compute(&h).map_err(|e| e.to_string())?;
    let kappa2 = sigma.singular_values()[0] / sigma.singular_values()[n - 1];
    let ones = vec![1.0_f64; n];
    let b = h.view().mul_vec(&ones[..]).map_err(|e| e.to_string())?;
    let lu32 = LuDecomposition::factor(&h32).map_err(|e| e.to_string())?;
    let lu64 = LuDecomposition::factor(&h).map_err(|e| e.to_string())?;
    let (inverse, fallback_inverse) = (lu32.inverse_operator(), lu64.inverse_operator());
    let fallback: Option<&(dyn LinearOperator<f64> + Sync)> = if use_fallback {
        Some(&fallback_inverse)
    } else {
        None
    };
    let system = RefinementSystem::Dense(h.view());
    let problem =
        RefinementProblem::new(system, &inverse, None, fallback).map_err(|e| e.to_string())?;
    let zero = vec![0.0_f64; n];
    let (x, report) = refinement
        .refine(&problem, &b, &zero[..])
        .map_err(|e| e.to_string())?;
    // 比べる直接解: f64 の LU と、f32 の LU だけで解いた解（標準形式の solve）。
    let direct = lu64.solve(&b).map_err(|e| e.to_string())?;
    let b32: Vec<f32> = b.as_slice().iter().map(|&v| v as f32).collect();
    let single = lu32.solve(&b32[..]).map_err(|e| e.to_string())?;
    let single: Vec<f64> = single.as_slice().iter().map(|&v| f64::from(v)).collect();
    let name = match report.termination() {
        RefinementTermination::Converged => "Converged",
        RefinementTermination::Stagnation => "Stagnation",
        RefinementTermination::IterationLimit => "IterationLimit",
        RefinementTermination::EvaluationLimit => "EvaluationLimit",
        RefinementTermination::ExecutionStopped(_) => "ExecutionStopped",
        RefinementTermination::CorrectionFailed => "CorrectionFailed",
    };
    let reason = report.fallback_reason().map(|r| match r {
        RefinementFallbackReason::Conversion => "Conversion",
        RefinementFallbackReason::NumericalFailure => "NumericalFailure",
        RefinementFallbackReason::Stagnation => "Stagnation",
    });
    stopped += usize::from(!report.is_success());
    failed += usize::from(report.termination() == RefinementTermination::CorrectionFailed);
    hardest = name;
    rows.push((
        n,
        kappa2 * single_unit,
        error(&single),
        name,
        report.iterations(),
        report.final_error().map(|e| e.normwise()),
        error(x.as_slice()),
        error(direct.as_slice()),
        reason,
    ));
}
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "次数 n [-]", "type": "integer" },
    { "key": "1", "label": "κ₂ u_f [-]", "type": "number", "format": sci2 },
    { "key": "2", "label": "f32 の LU だけの前進誤差 [-]", "type": "number", "format": sci2 },
    { "key": "3", "label": "終了理由" },
    { "key": "4", "label": "補正回数 [回]", "type": "integer" },
    { "key": "5", "label": "後退誤差 η [-]", "type": "number", "format": sci2, "nullText": "なし" },
    { "key": "6", "label": "改良した解の前進誤差 [-]", "type": "number", "format": sci2 },
    { "key": "7", "label": "f64 の LU の前進誤差 [-]", "type": "number", "format": sci2 },
    { "key": "8", "label": "退避の理由", "nullText": "退避なし" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "refinement" })
);
let outcome = if failed > 0 {
    Outcome::failed("退避のない補正が失敗した次数がある")
} else if stopped > 0 {
    Outcome::partial("一部の次数で改良が許容誤差に達する前に止まった").explanation(
        "止まった次数の解は受理した反復のうち最良のもので、前進誤差は表で確かめる。",
    )
} else {
    Outcome::satisfied("すべての次数で後退誤差が許容誤差 10⁻¹⁵ を下回った")
};
emit_outcome!(
    outcome
        .status(hardest)
        .diagnostic("止まった次数の数", stopped as f64, None)
        .diagnostic("最大補正回数", max_iterations, None)
);
```

既定値（最大補正回数 10、退避なし）では、$n \le 6$（$\kappa_2 u_f < 1$）で 3〜7 回の補正で `Converged` になり、改良した解の前進誤差は `f64` の LU 分解と同じ $\kappa u$ の程度になる。
補正の回数は $\kappa_2 u_f$ が 1 に近づくほど増え、$n = 6$（$\kappa_2 u_f = 0.89$）では 7 回かかる。
$n = 6$ の $\kappa_1 u_f$ は 1.7 と 1 を超えているのに収束しており、$\kappa u_f < 1$ は定数 $c_n \rho_n$ を含まない大まかな目安である。
$n \ge 7$ では補正が後退誤差を減らさなくなって `Stagnation` で止まり、後退誤差は単精度の水準 $10^{-10}$〜$10^{-8}$ にとどまる。
改良した解の前進誤差は $n = 7$ で 0.21、$n \ge 8$ では 1 を超え、`f32` の LU だけで解いた解と同じく正しい桁がほとんど残らない。
$n = 9$ と $10$ では 2 回目の補正が捨てられ、最初の補正のあとの値がそのまま返っている。
outcome は `partial` で、状態の名前は $n = 10$ の終了理由 `Stagnation` である。
最大補正回数を 20 にしても、停滞は 6 回以内に起こるので、$n \le 6$ の収束と $n \ge 7$ の停滞は変わらない。
最大補正回数を 1 にすると、`f32` の分解で一度解いただけの値が返り、すべての次数で終了理由は `IterationLimit` になる。

退避を有効にすると、停滞した時点で `f64` の逆作用素に切り替わり（退避の理由 `Stagnation`）、$n = 7$〜$10$ は切り替えの前後を合わせて 4〜7 回の補正で `Converged` になる。
outcome は `satisfied` になる。
前進誤差は $n = 7$ から 10 で $2.1 \times 10^{-8}$、$3.7 \times 10^{-7}$、$9.9 \times 10^{-6}$、$6.5 \times 10^{-4}$ で、`f64` の LU 分解と同じ桁に収まる。
改良は後退誤差が許容誤差 $10^{-15}$ を下回った時点で止まるので、一般には前進誤差が上の上界のとおり $2\kappa_1 \times 10^{-15}$ の程度（$n = 10$ では 0.07）まで残りうる。
この例では切り替えた後の後退誤差が $10^{-17}$ の程度まで下がったので、`f64` の LU 分解と同じ水準になった。
前進誤差の上界を LU 分解と同じ水準まで下げたい場合は、許容誤差を $u$ の数倍まで小さくする。
区間演算で解を包む方法は [Hilbert 行列の検証付き計算](../../../scioxide-validated/examples/hilbert-verified-solve/) で扱う。
丸めた係数の行列に対する証明と、有理数の Hilbert 行列の厳密解を区別して比較できる。

## まとめ

Hilbert 行列の条件数は次数を一つ上げるごとにおよそ 34 倍になり、$n = 12$ では倍精度の単位丸めの逆数 $1/u \approx 9 \times 10^{15}$ を超える。
部分ピボット付き LU 分解の後退誤差はどの次数でも単位丸めの程度にとどまるが、前進誤差は $\kappa u$ に沿って増え、$\kappa_1 \eta < 1$ の範囲では上界 $2\kappa_1\eta/(1-\kappa_1\eta)$ の内側にある。
したがって、`residual()` の $\eta$ が小さいことだけで解を正確とみなさない。
LU 因子による $O(n^2)$ の Hager–Higham 推定は、この例では $n \le 12$ で厳密な $\kappa_1$ とよく一致するが、保証のない目安として解釈する。
解を出力に反映する前に条件数で止めたいときは、`with_minimum_reciprocal_condition` で下限を与え、オプション付き形式の終了理由 `IllConditioned` で拒否を受け取る。
単精度の分解による反復改良は $\kappa u_f$ がおよそ 1 未満の範囲で倍精度の LU 分解と同じ精度に達し、それを超えると `Stagnation` で止まるので、終了理由を確かめ、退避を有効にするか倍精度の分解で解く。
