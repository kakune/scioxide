電気回路の節点方程式、化学反応の速い平衡、拘束された機械系では、微分方程式と一緒に、時間微分を含まない代数方程式が成り立つ。
このような方程式は微分代数方程式（differential-algebraic equation、DAE）と呼ばれ、初期値を勝手に選べず、ODE の解法をそのまま当てはめられない。
このページでは残差形式の DAE と指数 1 の条件、整合初期値、`DaeBdf` が使う可変刻み・可変次数の後退差分公式（BDF）を説明する。
ODE の BDF の係数と次数の選択は[線形多段階法](../multistep-methods/)、陰的な段の Newton 法と線形解法の選び方は[ヤコビ行列と各ステージの線形方程式の解法](../jacobians-and-linear-stages/)で扱う。

## 残差形式と変数の分割

`scioxide-ode` の DAE は時刻 $t$、状態 $y \in \mathbb K^n$、その時間微分 $\dot y$ に対する $n$ 本の方程式

$$
F(t, y, \dot y) = 0, \qquad F(t, y, \dot y) \in \mathbb K^n
$$

である。
$\mathbb K$ は状態のスカラー型 `T` が表す実数か複素数で、時刻は実数である。
`DaeSystem` は残差 $F$ を `residual` で書き込み、方程式の数を `dimension` で返す。
クロージャで残差だけを与える場合は `DaeFn::new(dimension, residual)` を使う。

`DaePartition::new(variables, equations)` は各変数と各方程式が微分か代数かを `bool` の列で指定する。
$\dot y_i$ が $F$ に現れる変数 $y_i$ を微分変数 $x$、現れない変数を代数変数 $z$ と呼ぶ。
方程式も同様に、微分変数の導関数を含む微分方程式と、どの導関数も含まない代数方程式に分ける。
二つの列は同じ長さで、`true` の個数（微分の数）が等しくなければならないが、並び順は違ってよい。
長さが違う、空である、微分の数が合わない場合は `InvalidInput` になる。

複素数の状態では、$F$ は $y$ と $\dot y$ について正則でなければならない。
正則でない式（共役や絶対値を含む式）は実部と虚部の実座標に書き直す。

特異な質量行列 $M$ を持つ $M\dot y = f(t, y)$ は、$F = M\dot y - f$ として残差形式に書ける。
`DaeBdf` は $M$ の逆行列を作らないので、$M$ が特異な指数 1 の系も扱える。
このとき $M$ の零の行に当たる方程式を代数方程式として `DaePartition` に指定する。
質量行列を `OdeSystem` に持たせて陰的 Runge–Kutta 法で解く方法は[陰的 Runge–Kutta 法と質量行列](../implicit-runge-kutta-and-mass-matrices/)にある。

## 指数 1 の条件

分割した変数で書くと、DAE は

$$
\begin{aligned}
f(t, x, z, \dot x) &= 0 && (\text{微分方程式}), \\
g(t, x, z) &= 0 && (\text{代数方程式})
\end{aligned}
$$

となる。
`DaeSystem` が求める条件は二つある。
一つは構造の条件で、微分方程式は微分変数の導関数だけを含み、代数方程式はどの導関数も含まない。
もう一つは指数 1 の条件で、整合化のヤコビ行列

$$
J_{\mathrm c} = \begin{bmatrix} f_{\dot x} & f_z \\ 0 & g_z \end{bmatrix}
$$

が正則であることである。
$J_{\mathrm c}$ の列には、微分変数では $F_{\dot y}$ の列を、代数変数では $F_y$ の列を取る。
構造の条件から左下のブロックは 0 なので、$J_{\mathrm c}$ は $f_{\dot x}$ と $g_z$ がともに正則なときに限り正則になる。

$g_z$ が正則なら、陰関数定理により代数方程式を $z = \zeta(t, x)$ と局所的に解ける。
代数方程式を時間で 1 回微分すると $g_t + g_x \dot x + g_z \dot z = 0$ から $\dot z$ が決まり、全体が ODE になる。
ODE にするのに必要な微分の回数を（微分）指数と呼び、指数 1 の DAE は 1 回の微分で ODE になる。
拘束された振り子のように $g_z$ が特異な系は指数 2 以上で、BDF をそのまま当てると精度が落ち、Newton 法が収束しないことがある。
`DaeBdf` は指数の判定、指数の低減、変数の分割の自動的な発見を行わない。
高指数の系は呼び出し側で拘束を微分して指数 1 に書き直すか、ホロノミック拘束を持つ力学系なら[幾何積分](../geometric-integrators/)の RATTLE 法を使う。

`DaeBdf` は呼び出しのたびに初期値で $J_{\mathrm c}$ を 1 回分解するので、初期時刻で特異な系は最初の刻みの前に示される。
積分の途中で $g_z$ が特異に近づく場合（指数が変わる点や特異点）は、Newton 法の収束の失敗と刻みの縮小として現れる。

## 整合初期値

ODE と違い、DAE の初期値 $(y_0, \dot y_0)$ は自由に選べない。
代数方程式 $g(t_0, x_0, z_0) = 0$ が $z_0$ を決め、微分方程式 $f = 0$ が $\dot x_0$ を決める。
残差 $F(t_0, y_0, \dot y_0)$ の微分と代数のブロックがそれぞれ許容誤差を満たす組を整合した（consistent）初期値と呼ぶ。
代数変数の導関数 $\dot z_0$ は $F$ に現れないので、整合の判定には入らない。

`DaeInitialization` は与えた組の扱いを選び、`DaeNumericalOptions::with_initialization` で設定する。

- `Check`（既定）は与えた組を変えずに残差を検査する。
  整合していなければ `InvalidInput`（理由は `Inconsistent`）のエラーになる。
- `Project` は微分状態 $x_0$ を固定し、$J_{\mathrm c}$ を使う Newton 法で $z_0$ と $\dot x_0$ を求める。
  収束しなければ `ConvergenceFailure` のエラーになり、エラーは Newton 法の停止理由と反復回数を持つ。

`Project` は $x_0$ を変えないので、射影後の組が物理的に意図した初期値であるかは呼び出し側が確かめる。
射影した $\dot z_0$ は与えた値のままで、連続な解の接線である保証はない。
`DaeReport::consistency` が返す `DaeConsistencyReport` には、与えた組の微分・代数の残差（`initial_differential_residual`、`initial_algebraic_residual`）、受理した組の残差（`differential_residual`、`algebraic_residual`）、代数状態の変化（`state_correction`）、微分変数の導関数の変化（`derivative_correction`）が無限大ノルムで入る。

`DaeProblem::new(system, end)` の終端 `end` が状態の時刻と等しいと、`advance` は初期値の検査か射影だけを行って `ReachedEnd` を返す。
この呼び出しで整合化した組を `DaeState` に受け取り、積分の前に確かめられる。

## 可変刻み・可変次数の残差 BDF

$q$ 次の BDF は受理した時刻 $t_{n+1}, t_n, \dots, t_{n+1-q}$ の状態を補間する多項式の $t_{n+1}$ での微分で $\dot y_{n+1}$ を近似する。

$$
\dot y_{n+1} \approx \frac{1}{h_n}\sum_{j=0}^{q} \alpha_j\, y_{n+1-j}, \qquad h_n = t_{n+1} - t_n
$$

係数 $\alpha_j$ は実際の刻みの時刻から毎回作るので、刻み幅を変えても次数は保たれる。
これを残差に代入した

$$
F\!\left(t_{n+1},\; y_{n+1},\; \frac{1}{h_n}\sum_{j=0}^{q} \alpha_j\, y_{n+1-j}\right) = 0
$$

を $y_{n+1}$ について Newton 法で解く。
Newton 法の行列は

$$
A = F_y + \frac{\alpha_0}{h_n} F_{\dot y}
$$

で、初期値は過去の状態を補間する多項式の外挿から作る。
密と疎の線形解法では、段が収束しないとき、現在の刻み幅での分解、新しく評価した導関数のブロックの順に 2 回まで再試行する。
Newton 法の反復が受理されるのは、残差そのものが微分と代数の残差の許容誤差を満たしたときだけである。
したがって近似的なヤコビ行列は反復回数を変えるが、受理する解は変えない。

次数は 1〜5 で、BDF の 1 次と 2 次は A 安定、3〜5 次は負の実軸全体で安定だが A 安定ではない。
局所誤差は新しい値と過去の値を通る $q + 2$ 点の $(q+1)$ 階の差商に、時刻の配置で決まる係数を掛けて推定する。
$q - 1$、$q$、$q + 1$ 次の推定を比べて次の次数を選ぶ。
刻み幅は、正規化した誤差の推定 $E$ から $h_{\mathrm{new}} = 0.9\,h\,E^{-1/(q+1)}$ とする I 制御で決める。
1 次では刻み幅の増加を 5 倍、それ以外では 2 倍までに抑え、棄却の直後は増やさない。

最初の刻みには過去の値がない。
微分変数の誤差は予測子 $x_0 + h\dot x_0$ との差 $e_x = (h/2)(\dot x_1 - \dot x_0)$ で推定し、代数変数の誤差は線形化した代数方程式の $e_x$ への応答 $g_z^{-1} g_x e_x$ で推定する。
呼び出しのたびに 1 次から履歴なしで始めるので、続けて `advance` を呼ぶと、そのつど最初の刻みからやり直す。

微分変数と代数変数の局所誤差は、それぞれ `with_differential_error` と `with_algebraic_error` の許容誤差の 4 分の 1 を基準に正規化する。
二つの正規化した推定の大きい方が 1 以下なら刻みを受理する。
許容誤差の 4 分の 3 は誤差の伝播と非線形方程式の誤差に残してある。
これらは局所誤差の推定であり、大域誤差の上界ではない。
連続して棄却できる回数は `with_rejection_limit`（既定 12 回）で、使い切ると `RejectionLimit` で止まる。

初期刻みを `DaeOptions::with_initial_step` で与えないと、

$$
h_0 = \min\!\left(\frac{|t_{\mathrm{end}} - t_0|}{1000},\; \frac{0.5}{\lVert \dot x_0 \rVert}\right)
$$

を使う（DASSL と同じ規則）。
$\lVert \dot x_0 \rVert$ は微分変数の導関数に、尺度 $|x_0|$ で `with_differential_error` のノルムを当てた値で、最初の増分 $h_0 \lVert \dot x_0 \rVert$ は微分の許容誤差の半分以下になる。

## 導関数の取り方

Newton 法の行列には $F_y$ と $F_{\dot y}$ が要る。
`DaeSystem` は三つの任意のコールバックで導関数を受け付ける。

| コールバック | 使う線形解法（`OdeStageBackend`） | 書き込むもの |
|---|---|---|
| `derivatives` | `Dense`（密 LU） | $F_y$ と $F_{\dot y}$ の密なブロック |
| `sparse_derivatives` | `Sparse`（疎 LU） | 共通の非零構造の上の $F_y$ と $F_{\dot y}$ の値 |
| `derivative_product` | `Krylov`（GMRES） | 方向の積 $F_y u + F_{\dot y} v$ |

どのコールバックも、書き込んだときは `Ok(Some(()))`、与えないときは `Ok(None)` を返し、既定の実装は `Ok(None)` を返す。
導関数の取り方は `DaeNumericalOptions::with_derivative_strategy` の `DerivativeStrategy` に従い、既定ではコールバックを先に試し、`Ok(None)` なら残差の前進差分で作る。
DAE の残差には自動微分の源がないので、その候補は飛ばされる。
次の候補へ進むのは `Ok(None)` のときだけで、コールバックのエラーはそのまま返る。
差分の刻みは座標の大きさの $\sqrt{\varepsilon}$ 倍（中心差分では $\varepsilon^{1/3}$ 倍）で、座標の大きさの下限には、状態では分割ごとの状態の絶対許容誤差、微分変数の導関数では初期化の導関数の絶対許容誤差を使い、絶対許容誤差が 0 の成分では 1 を使う。
$F_{\dot y}$ の、分割が禁じる位置（代数方程式の行か代数変数の列）に 0 でない値を書くと `InvalidInput` になる。
Krylov の線形解法では、`preconditioner` で右前処理を与えられる。

## 設定・状態・作業領域

`DaeNumericalOptions` は誤差の制御、残差の許容誤差、初期化、反復の上限をまとめ、`DaeOptions::with_numerics` で `DaeOptions` に渡す。
既定は、微分・代数の状態と初期化の導関数に絶対・相対とも $\sqrt{\varepsilon}$ の許容誤差（無限大ノルム）、微分・代数の残差に絶対 $\sqrt{\varepsilon}$・相対 0、残差の基準の尺度 1、`Check` の初期化、試行ごとの Newton 反復 12 回、連続棄却 12 回である。
$\varepsilon$ はスカラー型の計算機イプシロンである。
成分ごとの許容誤差は分割の中での番号で指定し、$k$ 番目の値は $k$ 番目の微分（または代数）変数に対応する。
DAE の随伴（`DaeAdjointOptions`）も同じ `DaeNumericalOptions` を受け取る（[随伴法による勾配](../adjoint-gradients/)）。

`DaeOptions` は数値の設定に初期刻み、試行した刻みの上限（`with_max_steps`）、コールバックの評価回数の上限（`with_max_evaluations`）を加える。
設定関数は失敗せず、分割との整合は `advance` が積分の前に検査する。

`DaeState` は時刻、状態、導関数の組で、`advance` は初期値をここから読み、受理した最後の組をここに残す。
初期値が受理される前に失敗した場合、状態は変わらない。
`DaeOutputSink` は受理した刻みごとに `emit(t, y, ẏ)` を受け取り、初期の組は送られない。
`()` は出力を捨て、クロージャ `FnMut(t, y, ẏ) -> Result<(), SciOxideError>` も出力先になる。

`DaeBdf::workspace` か `DaeWorkspace::try_reserve` は、`DaeRequirements`（次元と線形解法）に合う BDF の履歴、Newton 法、線形解法のメモリを確保する。
次元や線形解法の違う作業領域は `advance` が確保し直す。
作業領域が十分に大きく、コールバックと出力の出力先が確保しなければ、`advance` はメモリを確保しない。
`DaeWorkspace::last_attempt` は直前の呼び出しの結果、作業量、進捗の `DaeReport` を記録する。
`DaeBdf::solve` は作業領域を作って逐次に実行し、`DaeSolution`（最終の組とレポート）を返す。
失敗すると、エラーと進捗を `PartialFailure` で返す。

## 終了状態とレポート

`DaeTermination` の `ReachedEnd` だけが成功である。
`BudgetLimit(kind)` は計算回数の上限への到達（`Proposal` は刻み、`Evaluation` は評価、`Iteration` は Newton 反復）、`StepSizeLimit` は終端へ進める刻みがないこと、`ExecutionStopped` は取り消しか期限、`RejectionLimit` は連続棄却の上限を表す。
`TerminalEvent` は DAE に事象がないので生じない。
これらの停止は初期の組を受理した後に起こり、`advance` は `Ok` と成功でないレポートを返し、状態は最後に受理した組を持つ。
整合しない初期値、射影の失敗、初期値を受理する前の停止はエラーになる。

`DaeReport` は終了状態（`termination`、`is_success`）、最後の受理時刻（`final_time`）、受理と棄却の刻みの数、評価と反復の回数（`counts`、`accounting`）、最後の組の微分と代数の残差、最後に受理した刻みの正規化した局所誤差の推定（`differential_error`、`algebraic_error`）、最後に試行した刻みの推定（`last_step_error_estimate`）を持つ。
`trust` は組を受理した後は `ResidualChecked`、それまでは `DiagnosticOnly` で、精度の証明ではない。

## 整合化と積分の実験

モデルは微分変数 $x$ と代数変数 $z$ の

$$
F(t, y, \dot y) = \begin{bmatrix} \dot x + z - t \\ z - x^2 - t \end{bmatrix} = 0, \qquad x(0) = 1
$$

である。
代数方程式から $z = x^2 + t$ で、微分方程式に代入すると $\dot x = -x^2$ になるので、解析解は

$$
x(t) = \frac{1}{1 + t}, \qquad z(t) = \frac{1}{(1 + t)^2} + t
$$

である。
整合化のヤコビ行列は $J_{\mathrm c} = \begin{bmatrix} 1 & 1 \\ 0 & 1 \end{bmatrix}$ で、どこでも正則である。
$x(0) = 1$ に整合する値は $z(0) = 1$、$\dot x(0) = -1$ になる。

次のブロックは三つのセルが使うモデルと設定である。
`DecayConstraint` の `residual` が $F$、`derivatives` が $F_y$ と $F_{\dot y}$ の密なブロック（行優先）、`exact` が解析解に対応する。
`bdf_plan` は分割と密 LU の Plan を、`bdf_options` は微分・代数の状態に同じ許容誤差 $\varepsilon$ を与える設定を作り、`accepted_state` は整合化のセルが渡した組を読む。

```rust
//| id: ode-dae-index-one-model
//| kind: definitions
//| title: 代数拘束を持つモデルの残差と解析解
//| crates: [scioxide-core, scioxide-differentiate, scioxide-linalg, scioxide-ode]
use scioxide_core::{ErrorTolerance, SciOxideError, NormSelection, SolveContext, Tolerance};
use scioxide_differentiate::DerivativeStrategy;
use scioxide_linalg::MatrixViewMut;
use scioxide_ode::{
    DaeBdf, DaeInitialization, DaeNumericalOptions, DaeOptions, DaePartition, DaeState, DaeSystem,
    OdeStageBackend,
};

/// F(t, y, y') = (x' + z − t, z − x² − t)。y = (x, z) で、x が微分変数、z が代数変数。
pub(crate) struct DecayConstraint;

impl DaeSystem<f64> for DecayConstraint {
    fn dimension(&self) -> usize {
        2
    }

    fn residual(
        &self,
        t: f64,
        y: &[f64],
        dy: &[f64],
        out: &mut [f64],
        _: &mut SolveContext<'_, '_>,
    ) -> Result<(), SciOxideError> {
        out[0] = dy[0] + y[1] - t;
        out[1] = y[1] - y[0] * y[0] - t;
        Ok(())
    }

    // state_block = ∂F/∂y = [[0, 1], [−2x, 1]]、derivative_block = ∂F/∂y' = [[1, 0], [0, 0]]。
    fn derivatives(
        &self,
        _: f64,
        y: &[f64],
        _: &[f64],
        state_block: &mut MatrixViewMut<'_, f64>,
        derivative_block: &mut MatrixViewMut<'_, f64>,
        _: &mut SolveContext<'_, '_>,
    ) -> Result<Option<()>, SciOxideError> {
        let state = [0.0, 1.0, -2.0 * y[0], 1.0];
        let derivative = [1.0, 0.0, 0.0, 0.0];
        for k in 0..4 {
            state_block.set(k / 2, k % 2, state[k])?;
            derivative_block.set(k / 2, k % 2, derivative[k])?;
        }
        // Some は解析的なブロックを書いたことを表す。None なら残差の差分に切り替わる。
        Ok(Some(()))
    }
}

/// 変数・方程式とも 1 番目が微分、2 番目が代数の分割と、密 LU の残差 BDF。
pub(crate) fn bdf_plan() -> Result<DaeBdf, SciOxideError> {
    let partition = DaePartition::new(&[true, false], &[true, false])?;
    DaeBdf::new(partition, OdeStageBackend::Dense)
}

/// 微分・代数の状態の許容誤差をともに ε（絶対・相対、無限大ノルム）にした設定。
pub(crate) fn bdf_options(
    epsilon: f64,
    initialization: DaeInitialization,
    strategy: DerivativeStrategy,
) -> Result<DaeOptions<f64>, SciOxideError> {
    let tolerance =
        ErrorTolerance::from_tolerance(Tolerance::new(epsilon, epsilon)?, NormSelection::Infinity);
    let numerics = DaeNumericalOptions::new()
        .with_differential_error(tolerance.clone())
        .with_algebraic_error(tolerance)
        .with_initialization(initialization)
        .with_derivative_strategy(strategy);
    Ok(DaeOptions::new().with_numerics(numerics))
}

/// 整合化のセルが渡した組を読む。受理しなかった場合（Check）は null が渡り、エラーにする。
pub(crate) fn accepted_state(exports: &serde_json::Value) -> Result<DaeState<f64>, String> {
    let read = |key: &str| {
        serde_json::from_value::<Option<Vec<f64>>>(exports[key].clone())
            .map_err(|e| e.to_string())?
            .ok_or_else(|| "初期値が整合していない（前のセルを Project にする）".to_string())
    };
    DaeState::from_slices(0.0, &read("initial_values")?, &read("initial_derivative")?)
        .map_err(|e| e.to_string())
}

/// 解析解 (x, z) = (1/(1 + t), 1/(1 + t)² + t)。検算用の参照値。
pub(crate) fn exact(t: f64) -> (f64, f64) {
    let x = 1.0 / (1.0 + t);
    (x, x * x + t)
}
```

次のセルは整合しない初期値の推定 $z(0) = z_0$、$\dot x(0) = 0$ を、終端を初期時刻と同じにした `advance` で検査か射影する。
表は与えた組と受理した組の値と残差を示す。
`Check` にすると、整合しない初期値はエラーになり、エラーの分類を outcome に示す。
受理した組は後の二つのセルの初期値として渡す。

```rust
//| id: ode-index-one-consistency
//| ref: ode-index-one-consistency
//| title: 整合しない初期値を検査し、射影する
//| run: reactive
//| uses: [ode-dae-index-one-model]
//| crates: [scioxide-core, scioxide-differentiate, scioxide-ode]
//| exports: [initial_values, initial_derivative]
//| inputs:
//|   initial_guess: {"type":"range","label":"代数変数の初期推定 z₀ [-]","description":"整合した値は z(0) = 1。","min":-1,"max":3,"step":0.25,"value":0}

//|   - {"id":"check","label":"Check","description":"整合しない初期値は InvalidInput のエラーになる。","inputs":{"mode":"Check"}}

//|   - case: default

//|       - {"artifact":"initialization","path":"/rows/1/2","equals":null}
//|       - {"path":"/outputs/1/state","equals":"failed"}
//|   - case: consistent-check
//|     expect:
//|       - {"path":"/outputs/1/state","equals":"failed"}

use scioxide_differentiate::DerivativeStrategy;
use scioxide_ode::{DaeInitialization, DaeProblem, DaeState};

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let fixed6 = serde_json::json!({ "fractionDigits": 6 });
let initialization = if mode == "Check" {
    DaeInitialization::Check
} else {
    DaeInitialization::Project
};
// 既定と同じ許容誤差 √ε（絶対・相対）。
let strategy = DerivativeStrategy::AnalyticOrForward;
let options =
    bdf_options(f64::EPSILON.sqrt(), initialization, strategy).map_err(|e| e.to_string())?;
let plan = bdf_plan().map_err(|e| e.to_string())?;
let mut workspace = plan.workspace().map_err(|e| e.to_string())?;
let mut state = DaeState::from_slices(0.0, &[1.0, initial_guess], &[0.0, 0.0])
    .map_err(|e| e.to_string())?;
// 終端 = 初期時刻: 初期値の検査か射影だけを行う。
let initialized = plan.advance(
    &DaeProblem::new(&DecayConstraint, 0.0),
    &options,
    &mut state,
    &mut (),
    &mut workspace,
    ExecutionContext::sequential(),
);
// 失敗しても、作業領域の記録に与えた組の残差が残る。
let progress = workspace.last_attempt().and_then(|a| a.progress().copied());
let given = progress.and_then(|p| p.consistency());
let accepted = initialized.as_ref().ok().and_then(|r| r.consistency());
let rows = vec![
    (
        "与えた組",
        Some(1.0),
        Some(initial_guess),
        Some(0.0),
        given.map(|c| c.initial_differential_residual()),
        given.map(|c| c.initial_algebraic_residual()),

    (

        accepted.map(|_| state.values()[0]),
        accepted.map(|_| state.values()[1]),
        accepted.map(|_| state.derivative()[0]),
        accepted.map(|c| c.differential_residual()),
        accepted.map(|c| c.algebraic_residual()),
    ),
];
let columns = serde_json::json!([
    { "key": "0", "label": "組" },
    { "key": "1", "label": "x(0) [-]", "type": "number", "format": fixed6, "nullText": "なし" },
    { "key": "2", "label": "z(0) [-]", "type": "number", "format": fixed6, "nullText": "なし" },
    { "key": "3", "label": "x'(0) [-]", "type": "number", "format": fixed6, "nullText": "なし" },
    { "key": "4", "label": "微分方程式の残差 [-]", "type": "number", "format": sci3, "nullText": "なし" },
    { "key": "5", "label": "代数方程式の残差 [-]", "type": "number", "format": sci3, "nullText": "なし" }

emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "initialization" })
);
let pair = accepted.map(|_| (state.values().to_vec(), state.derivative().to_vec()));
export!(initial_values, &pair.as_ref().map(|p| p.0.clone()));
export!(initial_derivative, &pair.as_ref().map(|p| p.1.clone()));
let outcome = match (&initialized, accepted) {
    (Ok(_), Some(report)) => Outcome::satisfied("整合した初期値を受理した")
        .status(mode.to_string())
        .diagnostic("代数状態の補正", report.state_correction(), None)
        .diagnostic("導関数の補正", report.derivative_correction(), None),
    (Ok(_), None) => Outcome::failed("整合化の記録がない"),
    (Err(error), _) => Outcome::failed("初期値を受理できなかった")
        .status(format!("{:?}", error.kind()))
        .explanation(error.to_string()),
};
emit_outcome!(outcome);
```

既定値（$z_0 = 0$、`Project`）では、与えた組の代数方程式の残差は 1、微分方程式の残差は 0 である。
射影は $x(0) = 1$ を固定したまま $z(0) = 1$、$\dot x(0) = -1$ に直し、二つの残差はどちらも 0 になる。
`Check` では代数方程式の残差 1 が許容誤差 $\sqrt{\varepsilon} \approx 1.5 \times 10^{-8}$ を超えるので、`InvalidInput` のエラーになる。
$z_0 = 1$ でも、$\dot x(0) = 0$ が微分方程式の残差 1 を残すので、`Check` は同じエラーを返す。
整合した組を手で作るには、代数方程式と微分方程式の両方を満たす $z_0$ と $\dot x_0$ が要る。

次のセルは受理した組から状態の許容誤差 $\varepsilon$ で $t = T$ まで積分する。
初期値はすでに整合しているので、`Check` で始める。
受理した刻みは出力の出力先のクロージャで記録する。
上のグラフは数値解（記号）と解析解（破線）、下のグラフは受理した刻み幅で、横軸の時刻は連動する。
表は終端での解析解との差、残差、作業量、終了状態を示す。

## 許容誤差と大域誤差

局所誤差の推定で刻み幅を決めても、大域誤差は許容誤差の定数倍とは限らない。
次のセルは同じ整合した初期値から許容誤差 $\varepsilon = 10^{-3}, 10^{-4}, \dots, 10^{-11}$ で $T = 4$ まで積分し、終端での解析解との差と作業量を比べる。
導関数の取り方を選ぶ入力で、解析的なブロック（`AnalyticOrForward`、既定）と残差の前進差分だけ（`Forward`）を切り替えられる。
Newton 法の反復は残差の許容誤差を満たすまで続くので、前進差分のヤコビ行列でも誤差の列はほぼ同じで、評価の回数だけが変わると予想できる。
グラフは誤差と許容誤差を両対数で描き、破線は誤差 = 許容誤差の参照線である。

```rust
//| id: ode-dae-tolerance-sweep
//| ref: ode-dae-tolerance-sweep
//| title: 許容誤差を変えて大域誤差と作業量を比べる
//| run: reactive
//| uses: [ode-dae-index-one-model]
//| crates: [scioxide-core, scioxide-differentiate, scioxide-ode]
//| dependsOn:
//|   initialization: ode-index-one-consistency
//| inputs:
//|   strategy: {"type":"select","label":"導関数の取り方","description":"解析的なブロックか、残差の前進差分だけか。","options":["AnalyticOrForward","Forward"],"value":"AnalyticOrForward"}
//| cases:
//|   - {"id":"forward","label":"Forward","description":"ヤコビ行列を差分で作る。誤差はほぼ同じで、残差の評価が増える。","inputs":{"strategy":"Forward"}}

//|   - case: default
//|     expect:
//|       - {"artifact":"sweep","path":"/rows/0/0","approx":{"value":1e-3,"rtol":1e-12}}
//|       - {"artifact":"sweep","path":"/rows/8/3","range":{"max":1e-9}}
//|       - {"artifact":"sweep","path":"/rows/8/6","equals":0}
//|   - case: forward
//|     expect:
//|       - {"artifact":"sweep","path":"/rows/8/3","range":{"max":1e-9}}
//|       - {"artifact":"sweep","path":"/rows/8/6","equals":0}
use scioxide_core::{EvaluationRole, ExecutionContext};
use scioxide_differentiate::DerivativeStrategy;
use scioxide_ode::{DaeInitialization, DaeProblem};

let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let initial = accepted_state(initialization)?;
let strategy = if strategy == "Forward" {
    DerivativeStrategy::Forward
} else {
    DerivativeStrategy::AnalyticOrForward
};
let end_time = 4.0;
let (x_exact, z_exact) = exact(end_time);
let plan = bdf_plan().map_err(|e| e.to_string())?;
// 作業領域は全ての許容誤差で使い回す。
let mut workspace = plan.workspace().map_err(|e| e.to_string())?;
let mut rows = Vec::new();
for k in 3..=11 {
    let epsilon = 10.0_f64.powi(-k);
    let options =
        bdf_options(epsilon, DaeInitialization::Check, strategy).map_err(|e| e.to_string())?;
    let mut state = initial.clone();
    let report = plan
        .advance(
            &DaeProblem::new(&DecayConstraint, end_time),
            &options,
            &mut state,
            &mut (),
            &mut workspace,
            ExecutionContext::sequential(),
        )
        .map_err(|e| e.to_string())?;
    let counts = report.counts();
    rows.push((
        epsilon,
        report.accepted_steps(),
        (state.values()[0] - x_exact).abs(),
        (state.values()[1] - z_exact).abs(),
        counts.provider(EvaluationRole::Residual),
        counts.provider(EvaluationRole::Jacobian),
        usize::from(!report.is_success()),
    ));
}
let errors: Vec<[f64; 2]> = rows.iter().map(|r| [r.0, r.2]).collect();
let diagonal: Vec<[f64; 2]> = rows.iter().map(|r| [r.0, r.0]).collect();
emit_line_chart!(
    &vec![
        serde_json::json!({ "name": "|x(4) − x*(4)|", "points": errors }),
        serde_json::json!({
            "name": "誤差 = 許容誤差",
            "points": diagonal,
            "style": { "lineType": "dashed" }
        })
    ],
    options = &serde_json::json!({
        "xLabel": "許容誤差 ε [-]",
        "yLabel": "終端の誤差 [-]",
        "xType": "log",
        "yType": "log"
    })
);
let columns = serde_json::json!([
    { "key": "0", "label": "許容誤差 ε [-]", "type": "number", "format": sci2 },
    { "key": "1", "label": "受理した刻み [回]", "type": "integer" },
    { "key": "2", "label": "|x(4) − x*(4)| [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "|z(4) − z*(4)| [-]", "type": "number", "format": sci3 },
    { "key": "4", "label": "残差の評価 [回]", "type": "integer" },
    { "key": "5", "label": "ヤコビ行列の評価 [回]", "type": "integer" },
    { "key": "6", "label": "未完了の数 [-]", "type": "integer" }
]);

    columns,
    rows,
    metadata = serde_json::json!({ "id": "sweep" })
);
```

解析的なブロックでは、$\varepsilon$ を $10^{-3}$ から $10^{-11}$ まで下げると、受理した刻みは 28 から 345 に、$x(4)$ の差は $5.2 \times 10^{-4}$ から $1.1 \times 10^{-10}$ に変わる。
差と許容誤差の比は $\varepsilon = 10^{-3}$ で 0.52、$10^{-8}$ で 2.9、$10^{-11}$ で 11 で、許容誤差を厳しくするほど誤差は許容誤差の割合ほどには減らない。
このように、局所誤差を許容誤差以下に保っても、終端の大域誤差は許容誤差より大きくなりうる。
`Forward` にすると、ヤコビ行列の評価は 0 回になり、残差の評価は前進差分の分だけ 34〜43 回増える。
誤差は有効数字 3 桁で一致し、受理する解が残差の許容誤差で決まることと合う。

## まとめ

`DaeBdf` は残差形式 $F(t, y, \dot y) = 0$ の指数 1 の DAE を、`DaePartition` で微分変数と代数変数を明示して積分する。
初期値は `Check` で検査するか `Project` で代数状態と導関数を求め直し、`DaeConsistencyReport` で補正の大きさを確かめる。
刻みは実際の時刻から係数を作る次数 1〜5 の残差 BDF で、微分変数と代数変数の局所誤差を別々に許容誤差の 4 分の 1 と比べる。
局所誤差の制御は大域誤差を保証しないので、許容誤差を変えた解か既知の解で確かめる。
導関数のブロックは解析的に与えるか `Ok(None)` で差分に任せ、受理する解は残差の許容誤差で決まる。
