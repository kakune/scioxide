個体群の増殖、生理系の制御、伝染病の潜伏期間のように、変化の速さが少し前の状態で決まる現象は遅延微分方程式（delay differential equation、DDE）で表される。
DDE の初期条件は 1 点の値ではなく、遅延の長さの区間にわたる関数（履歴）である。
このページでは一定遅延の DDE、段階法、導関数の不連続が解に伝わる仕組みと刻みの予定、`DdePlan` と `solve_dde` の使い方を説明し、遅延ロジスティック方程式の平衡が遅延の長さで振動に変わることを確かめる。
陽的 Runge–Kutta 法の誤差制御と連続出力は[陽的 Runge–Kutta 法と刻み幅の制御](../explicit-runge-kutta-and-control/)と[連続出力と事象](../dense-output-and-events/)にそろえる。

## 一定遅延の遅延微分方程式

`scioxide-ode` が扱うのは、遅延 $\tau_1, \dots, \tau_k > 0$ が定数の遅れ型（retarded）の方程式

$$
\begin{aligned}
y'(t) &= f\bigl(t,\, y(t),\, y(t - \tau_1),\, \dots,\, y(t - \tau_k)\bigr), && t_0 \le t \le t_{\mathrm{end}}, \\
y(t) &= \varphi(t), && t_0 - \tau_{\max} \le t \le t_0
\end{aligned}
$$

である。
$y(t) \in \mathbb R^n$ は状態、$\varphi$ は初期の履歴、$\tau_{\max}$ は最大の遅延である。
右辺は過去の状態の値だけを使うので、過去の導関数を含む中立型（neutral）、未来の値を含む進み型、状態に依存する遅延は扱わない。
状態は実数に限る。

`DdeRhs` は右辺を表し、`evaluate(t, y, delayed, out)` の `delayed` は行 $j$ が $y(t - \tau_j)$、列が状態の成分の行列である。
行の順序は `DdePlan::new` に渡した遅延の順序で、同じ遅延が重複しても位置を保つ。
`DdeHistory` は履歴 $\varphi(t)$ を書き込む。
どちらもクロージャ（`Fn(t, y, delayed, out)` と `Fn(t, out)`）で実装でき、`DdeProblem::new(&rhs, &history)` で組にする。
履歴は連続でなければならず、同じ時刻には呼び出しの順序によらず同じ値を返さなければならない。
履歴の呼び出しは `Function`、右辺の呼び出しは `RightHandSide` の評価として数える。

## 段階法

刻み幅 $h$ が最小の遅延 $\tau_{\min}$ 以下なら、区間 $[t, t + h]$ の中のどの時刻 $t'$ でも $t' - \tau_j \le t$ なので、遅延した値はすでに分かっている。
したがって各刻みは既知の関数を右辺に持つ通常の ODE の 1 刻みになる。
この考え方を段階法（method of steps）と呼ぶ。
最初の区間 $[t_0, t_0 + \tau_{\min}]$ では過去の値は履歴 $\varphi$ から、それより後では受理した刻みの連続拡張から取る。

`DdePlan` は適応刻みの Dormand–Prince 5(4) 対（`DormandPrince5`）で刻み、刻みの長さを最小の遅延以下に抑える。
そのため遅延した値はいつも既知の値から得られ、刻みの中で反復を必要としない。
受理した刻みの間の値は Shampine の 4 次の連続拡張で補間する。
誤差の制御、刻み幅の上下限、出力の時刻、事象、計算回数の上限は `OdeOptions` で与え、`DdeOptions::with_ode_options` で渡す。
局所誤差の推定には補間した履歴の誤差が入らないので、許容誤差は補間の精度も考えて選ぶ。

## 導関数の不連続の伝播

初期時刻 $t_0$ では、履歴の右側の導関数 $\varphi'(t_0^-)$ と方程式が与える $y'(t_0^+) = f(t_0, \varphi(t_0), \dots)$ は一般に一致しない。
このとき $y'$ は $t_0$ で跳び、右辺が $y(t - \tau_j)$ を通して跳びを受け取る時刻 $t_0 + \tau_j$ では、$y''$ が跳ぶ。
一般に、時刻 $s$ で $m$ 階の導関数が跳ぶと、各遅延 $\tau_j$ について時刻 $s + \tau_j$ で $m + 1$ 階の導関数が跳ぶ。
跳びは階数を上げながら広がるので、解は時間とともに滑らかになる。

Runge–Kutta 法の誤差の評価は解が刻みの中で滑らかであることを前提にするので、低い階数の跳びを刻みの内部に含むと局所誤差の推定が狂い、刻みの棄却が続く。
`DdePlan::new` は不連続の時刻をあらかじめ計算し、刻みがその時刻でちょうど終わるようにする。
$t_0$ は常に 1 階の跳びとして予定に入り、宣言した履歴の不連続点も起点になる。
跳びは 5 階まで伝え、それより高い階数の跳びは 5 次の方法の精度を落とさないので予定しない。
互いに $8\varepsilon\max(|a|, |b|)$ 以内の時刻はまとめる。
$b$ 個の起点と $d$ 個の遅延に対して、予定の計算は $O(bd)$ 回の挿入で済む。
`DdePlan::discontinuities` は $t_0$ より後の予定の時刻を返す。

履歴そのものに導関数の跳びがある場合（区分的な関数の履歴など）は、`DdeHistoryBreak::new(time, derivative_order)` で時刻と最初に跳ぶ導関数の階数を宣言する。
`DdeHistoryBreak::first_derivative(time)` は 1 階の跳びの省略形である。
履歴は連続でなければならないので、階数 0 は `InvalidInput` になる。
宣言の時刻は $[t_0 - \tau_{\max}, t_0]$ になければならない。
5 階より高い階数の宣言は刻みを強制しない。

## 履歴のメモリと上限

段階法は時刻 $t$ で $[t - \tau_{\max}, t]$ の連続拡張を保持し、それより古い刻みを捨てる。
保持する刻みの数は $\tau_{\max}$ を刻み幅で割った数程度で、遅延が長いほど、許容誤差が厳しいほど増える。
`DdeOptions::with_history_capacity` は保持する刻みの数の上限、`with_schedule_capacity` は不連続の予定の数の上限で、既定ではどちらも上限がない。
上限は比較に使うだけで、確保はしない。
予定の数が上限を超えると `DdePlan::new` が `ResourceLimit` を返す。
次の刻みに上限より多い履歴が要ると、積分は `HistoryCapacity` で止まる。

`DdeWorkspaceRequest::new(events)` は監視する事象関数の数を、`with_history_segments(count)` は前もって確保する履歴の刻みの数を指定する。
`DdePlan::workspace_requirements` が返す `DdeRequirements` は、状態の成分あたり 6 個のスカラー（4 個の補間係数と両端の値）を、要求した刻みと進行中の刻みの分だけ数えたバイト数を `required_bytes` で返す。
積分は不足した履歴のメモリを上限まで倍々に増やし、作業領域に残す。
同じ次元の次の積分ではメモリを使い回すので、十分な履歴を持つ作業領域とコールバックが確保をしなければ、`advance` はメモリを確保しない。

## Plan・レポート・終了状態

`DdePlan::new(dimension, span, delays, history_breaks, options)` は区間 $(t_0, t_{\mathrm{end}})$、遅延、履歴の不連続点から予定を作る。
$t_0 \ge t_{\mathrm{end}}$、遅延がない、正でない遅延、浮動小数点で時刻を動かせないほど小さい遅延は `InvalidInput`、有限でない値は `NonFinite` になる。
`advance(problem, state, sink, workspace, scope)` は呼び出しのたびに履歴から始め直し、状態を $\varphi(t_0)$ にしてから積分する。
止まった積分を続きから再開することはできない。
`solve(problem)` は作業領域を作り、`DdeSolution`（最終の状態、レポート、出力の `OdeTrajectory`）を返す。
事象は `DdeProblem::with_events` で与えられるが、事象関数は $(t, y(t))$ だけに依存し、遅延した値を使えず、事象で状態を変えることもできない。

`solve_dde(rhs, history, delays, t0, t1, dimension)` は、既定の `DdeOptions`（絶対許容誤差 $10^{-6}$、相対許容誤差 $10^{-3}$、上限なし）で積分して $y(t_1)$ だけを返すワンショット関数である。
成功でない終了はすべてエラーになり、エラーは最後に受理した進捗を `DdeProgress` で持つ。

`DdeTermination` の `ReachedEnd` と `TerminalEvent` が成功で、`BudgetLimit`、`StepSizeLimit`、`ExecutionStopped` は他の時間発展と同じ意味を持つ。
`HistoryCapacity` は履歴の上限による停止である。
これらの停止では `advance` は `Ok` と成功でないレポートを返し、状態は最後に受理した点を持つ。
`DdeReport` は受理・棄却した刻みの数、評価回数、最後の刻みの局所誤差の推定、事象の数、同時に保持した履歴の刻みの最大数（`peak_history_segments`）を持つ。
`DdeWorkspace::last_attempt` は直前の呼び出しの進捗を `DdeProgress` で記録する。

## 区分多項式の解析解との比較

一定の遅延 $\tau = 1$ を持つ線形の遅延方程式

$$
y'(t) = y(t - 1) \quad (t \ge 0), \qquad y(t) = 1 \quad (t \le 0)
$$

を考える。
$[0, 1]$ では $y(t - 1) = 1$ なので $y = 1 + t$、$[1, 2]$ では $y' = 1 + (t - 1)$ を積分して $y = 1 + t + (t - 1)^2/2$ となる。
これを繰り返すと、解は次の区分多項式になる。

$$
y(t) = 1 + \sum_{k = 1}^{\infty} \frac{(t - k + 1)_+^k}{k!}, \qquad (x)_+ = \max(x, 0)
$$

区間 $[k - 1, k]$ の解は $k$ 次の多項式である。
$t = 0$ で $y'$ が 0 から 1 に跳ぶので、$t = k$ では $k + 1$ 階の導関数が跳ぶ。
予定に入るのは $t = 1, 2, 3, 4$（2〜5 階の跳び）までである。

次のセルは終端時刻 $T$ までを許容誤差 $10^{-10}$（絶対・相対とも）、最大刻み 0.125 で解き、101 点の出力を解析解と比べる。
グラフの縦の点線は予定した不連続の時刻である。
表には区間ごとの最大誤差と、`solve_dde`（既定の許容誤差）の $y(T)$ を含む要約を出す。
履歴の上限を小さくすると、`HistoryCapacity` で止まる。

```rust
//| id: ode-dde-method-of-steps
//| ref: ode-dde-method-of-steps
//| title: 遅延方程式の数値解を区分多項式の解析解と比べる
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg, scioxide-ode]
//| inputs:
//|   final_time: {"type":"range","label":"終端時刻 T [-]","min":1,"max":5,"step":0.5,"value":3}
//|   history_capacity: {"type":"range","label":"履歴の上限 [刻み]","description":"保持できる受理した刻みの数。","min":4,"max":64,"step":1,"value":64}
//| cases:
//|   - {"id":"degree-five","label":"T = 5","description":"区間 [4, 5] の解は 5 次で、誤差が丸めの水準を超える。","inputs":{"final_time":5}}
//|   - {"id":"small-history","label":"履歴の上限 8","description":"遅延 1 の間の 9 刻みを保持できず、HistoryCapacity で止まる。","inputs":{"history_capacity":8}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"intervals","path":"/rows/2/3","range":{"max":1e-13}}
//|       - {"artifact":"summary","path":"/rows/0/1","approx":{"value":6.166666666666667,"rtol":1e-12}}
//|       - {"artifact":"summary","path":"/rows/0/2","approx":{"value":6.166666666666667,"rtol":1e-4}}
//|       - {"path":"/outputs/3/state","equals":"satisfied"}
//|   - case: degree-five
//|     expect:
//|       - {"artifact":"intervals","path":"/rows/4/3","range":{"min":1e-12,"max":1e-7}}
//|       - {"path":"/outputs/3/state","equals":"satisfied"}
//|   - case: small-history
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/6","equals":"Some(HistoryCapacity)"}
//|       - {"path":"/outputs/3/state","equals":"partial"}
use scioxide_core::{
    Budget, ErrorTolerance, EvaluationRole, ExecutionContext, SciOxideError, NormSelection,
    Tolerance,
};
use scioxide_linalg::{MatrixView, Vector};
use scioxide_ode::{
    DdeOptions, DdePlan, DdeProblem, DdeWorkspaceRequest, OdeOptions, OdeOutputSchedule,
    OdeState, OdeTrajectory, solve_dde,
};

let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let digits12 = serde_json::json!({ "significantDigits": 12 });
// 履歴 y(t) = 1（t ≤ 0）と、遅延した状態を受け取る右辺 y'(t) = y(t − 1)。
let history = |_: f64, out: &mut [f64]| {
    out.fill(1.0);
    Ok(())
};
let rhs = |_: f64, _: &[f64], delayed: MatrixView<'_, f64>, out: &mut [f64]| {
    out[0] = delayed.get(0, 0)?; // 行 j が y(t − τ_j)
    Ok::<(), SciOxideError>(())
};
let tolerance = ErrorTolerance::from_tolerance(
    Tolerance::new(1e-10, 1e-10).map_err(|e| e.to_string())?,
    NormSelection::RootMeanSquare,
);
let ode_options = OdeOptions::new()
    .with_error_tolerance(tolerance)
    .with_maximum_step(0.125)
    .with_output_schedule(OdeOutputSchedule::times(
        (0..=100)
            .map(|i| final_time * f64::from(i) / 100.0)
            .collect(),
    ));
let capacity =
    Budget::try_from(history_capacity.round() as usize).map_err(|e| e.to_string())?;
let options = DdeOptions::new()
    .with_history_capacity(capacity)
    .with_ode_options(ode_options);
// 次元 1、遅延 [1.0]、履歴の不連続点なし。
let plan =
    DdePlan::new(1, (0.0, final_time), &[1.0], &[], options).map_err(|e| e.to_string())?;
let mut workspace = plan
    .workspace(DdeWorkspaceRequest::new(0))
    .map_err(|e| e.to_string())?;
let mut state = OdeState::new(0.0, Vector::from_vec(vec![0.0]));
let mut path = OdeTrajectory::new();
let report = plan
    .advance(
        &DdeProblem::new(&rhs, &history),
        &mut state,
        &mut path,
        &mut workspace,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;
// 独立な検算: 区分多項式の解析解 1 + Σ (t − k + 1)₊^k / k!（t ≤ 5 なので k ≤ 6 で足りる）。
let exact = |t: f64| {
    (1..=6)
        .fold((1.0, 1.0), |(sum, factorial), k| {
            let factorial = factorial * f64::from(k);
            (
                sum + (t - f64::from(k) + 1.0).max(0.0).powi(k) / factorial,
                factorial,
            )
        })
        .0
};
let computed: Vec<[f64; 2]> = path
    .times()
    .iter()
    .zip(path.states())
    .map(|(&t, y)| [t, y.as_slice()[0]])
    .collect();
let reference: Vec<[f64; 2]> = (0..=200)
    .map(|i| final_time * f64::from(i) / 200.0)
    .map(|t| [t, exact(t)])
    .collect();
let dotted = serde_json::json!({ "lineType": "dotted" });
let breaks: Vec<serde_json::Value> = plan
    .discontinuities()
    .iter()
    .map(|&t| serde_json::json!({ "kind": "line", "axis": "x", "value": t, "style": dotted }))
    .collect();
emit_line_chart!(
    &vec![
        serde_json::json!({ "name": "DdePlan の数値解", "points": computed }),
        serde_json::json!({
            "name": "区分多項式の解析解",
            "points": reference,
            "style": { "lineType": "dashed" }
        })
    ],
    options = &serde_json::json!({
        "xLabel": "時刻 t [-]",
        "yLabel": "状態 y [-]",
        "annotations": breaks
    })
);
// 区間 (k, k + 1] ごとの最大誤差。出力が届かなかった区間は None。
let intervals = final_time.ceil() as usize;
let mut worst = vec![None::<f64>; intervals];
for (&t, y) in path.times().iter().zip(path.states()) {
    let k = (t.ceil() as usize).clamp(1, intervals) - 1;
    let error = (y.as_slice()[0] - exact(t)).abs();
    worst[k] = Some(worst[k].map_or(error, |w: f64| w.max(error)));
}
let rows: Vec<(usize, f64, usize, Option<f64>)> = worst
    .iter()
    .enumerate()
    .map(|(k, &w)| (k, ((k + 1) as f64).min(final_time), k + 1, w))
    .collect();
let columns = serde_json::json!([
    { "key": "0", "label": "区間の始点 [-]", "type": "integer" },
    { "key": "1", "label": "区間の終点 [-]", "type": "number", "format": { "fractionDigits": 1 } },
    { "key": "2", "label": "解析解の次数 [-]", "type": "integer" },
    { "key": "3", "label": "最大の |y − y*| [-]", "type": "number", "format": sci2, "nullText": "未到達" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "intervals" })
);
// ワンショット関数は既定の許容誤差（絶対 1e-6、相対 1e-3）で y(T) だけを返す。
let one_shot = solve_dde(rhs, history, &[1.0], 0.0, final_time, 1)
    .map_err(|e| e.error().to_string())?
    .as_slice()[0];
let columns = serde_json::json!([
    { "key": "0", "label": "最後の y（DdePlan）[-]", "type": "number", "format": digits12 },
    { "key": "1", "label": "同じ時刻の解析解 [-]", "type": "number", "format": digits12 },
    { "key": "2", "label": "solve_dde の y(T) [-]", "type": "number", "format": digits12 },
    { "key": "3", "label": "受理した刻み [回]", "type": "integer" },
    { "key": "4", "label": "履歴の最大保持数 [刻み]", "type": "integer" },
    { "key": "5", "label": "履歴の評価 [回]", "type": "integer" },
    { "key": "6", "label": "終了状態" }
]);
emit_table_with_columns!(
    columns,
    vec![(
        state.values()[0],
        exact(report.final_time()),
        one_shot,
        report.accepted_steps(),
        report.peak_history_segments(),
        report.counts().provider(EvaluationRole::Function),
        format!("{:?}", report.termination()),
    )],
    metadata = serde_json::json!({ "id": "summary" })
);
let outcome = if report.is_success() {
    Outcome::satisfied("終端まで積分した（精度は解析解との比較で読む）")
} else {
    Outcome::partial("終端の前で止まった").explanation("状態は最後に受理した点を持つ。")
};
emit_outcome!(
    outcome
        .status(format!("{:?}", report.termination()))
        .diagnostic("終端の時刻", report.final_time(), None)
        .diagnostic(
            "履歴の最大保持数",
            report.peak_history_segments() as f64,
            None
        )
);
```

既定の $T = 3$ では、どの区間でも最大誤差は $1.8 \times 10^{-15}$ 以下で、$y(3) = 37/6$ を丸め誤差の範囲で再現する。
$t \le 3$ の解は 3 次以下の区分多項式で、境目 $t = 1, 2$ を刻みの境目にそろえた 5 次の方法は、各刻みで多項式を丸め誤差の範囲で積分する。
受理した刻みは 24、同時に保持した履歴は最大 9 刻みで、最大刻み 0.125 で遅延 1 を覆う 8 刻みと進行中の 1 刻みに当たる。
$T = 5$ では区間 $[4, 5]$ の最大誤差だけが $2.2 \times 10^{-9}$ に増え、$[3, 4]$ までは $3.6 \times 10^{-15}$ 以下にとどまる。
$[4, 5]$ の解は 5 次で、出力の時刻の値は 4 次の連続拡張で補間するので、その補間誤差が現れる。
刻みの終点の $y(5) = 19.175$ は表示した桁で解析解と一致する。
既定の許容誤差の `solve_dde` も、表示した桁で同じ $y(T)$ を返す。
履歴の上限を 8 にすると、$t = 1$ で遅延 1 の区間を覆う 9 刻み目を保持できず、`HistoryCapacity` で止まって outcome は partial になる。

## 遅延ロジスティック方程式と Hopf 分岐

Hutchinson（1948）の遅延ロジスティック方程式

$$
y'(t) = r\, y(t)\left(1 - \frac{y(t - \tau)}{K}\right)
$$

は、個体群の増殖率が時間 $\tau$ 前の個体数で決まるモデルである。
$r > 0$ は内的増加率、$K > 0$ は環境収容力である。
$s = t/\tau$、$u = y/K - 1$ と置くと $\dot u(s) = -r\tau\, u(s - 1)\bigl(1 + u(s)\bigr)$ になり、解の振る舞いは積 $r\tau$ だけで決まる（Wright の方程式）。
平衡 $u = 0$ のまわりで線形化した $\dot u(s) = -r\tau\, u(s - 1)$ に $u = e^{\lambda s}$ を代入すると、特性方程式

$$
\lambda + r\tau\, e^{-\lambda} = 0
$$

を得る。
平衡が漸近安定であるのは、すべての特性根の実部が負のときである。
$\lambda = i\omega$ を代入すると $\cos\omega = 0$、$\omega = r\tau\sin\omega$ から $\omega = \pi/2$、$r\tau = \pi/2$ を得るので、$r\tau < \pi/2$ では平衡は安定で、$r\tau = \pi/2$ で特性根の組が虚軸を横切る。
$r\tau > 1/e$ では実部が最大の根は複素数なので、平衡への近づき方は減衰振動になる。
$r\tau$ が $\pi/2$ を超えると平衡は不安定になり、周期解（リミットサイクル）が生まれる（Hopf 分岐）。
分岐の直後の周期は $2\pi/\omega = 4\tau$ で、振幅は Hopf 分岐の標準形から

$$
A \approx \sqrt{\frac{40\,(r\tau - \pi/2)}{3\pi - 2}}
$$

と近似できる（$A$ は $y/K$ の振動の半振幅）。

次のブロックは二つのセルが使う計算である。
`hutchinson_path` は $\tau = 1$、$K = 1$、履歴 $y(t) = 1 + \delta$（$t \le 0$）として $t \in [0, T]$ を `DdePlan` で解き、0.05 おきの $(t, y)$ を返す。
`characteristic_root` は実部が最大の特性根 $\lambda = \mu + i\omega$ を $\lambda_0 = 1.5i$ からの複素数の Newton 法で求める独立な計算で、`half_range` は値の列の半振幅 $(\max - \min)/2$ を返す。

```rust
//| id: ode-hutchinson-model
//| kind: definitions
//| title: 遅延ロジスティック方程式の数値解と特性根
//| crates: [scioxide-core, scioxide-linalg, scioxide-ode]
use scioxide_core::{ErrorTolerance, ExecutionContext, SciOxideError, NormSelection, Tolerance};
use scioxide_linalg::{MatrixView, Vector};
use scioxide_ode::{
    DdeOptions, DdePlan, DdeProblem, DdeReport, DdeWorkspaceRequest, OdeOptions, OdeOutputSchedule,
    OdeState, OdeTrajectory,
};

/// y'(t) = rτ y(t)(1 − y(t − 1))、履歴 y = 1 + δ を t ∈ [0, horizon] で解き、
/// start 以降 0.05 おきの (t, y) とレポートを返す。許容誤差は絶対・相対とも 10⁻⁹。
pub(crate) fn hutchinson_path(
    rate_delay: f64,
    perturbation: f64,
    start: f64,
    horizon: f64,
) -> Result<(Vec<(f64, f64)>, DdeReport<f64>), SciOxideError> {
    let rhs = |_: f64, y: &[f64], delayed: MatrixView<'_, f64>, out: &mut [f64]| {
        out[0] = rate_delay * y[0] * (1.0 - delayed.get(0, 0)?);
        Ok::<(), SciOxideError>(())
    };
    let history = |_: f64, out: &mut [f64]| {
        out[0] = 1.0 + perturbation;
        Ok(())
    };
    let count = ((horizon - start) / 0.05).round() as usize;
    let times = (0..=count).map(|i| start + 0.05 * i as f64).collect();
    let tolerance =
        ErrorTolerance::from_tolerance(Tolerance::new(1e-9, 1e-9)?, NormSelection::RootMeanSquare);
    let ode = OdeOptions::new()
        .with_error_tolerance(tolerance)
        .with_output_schedule(OdeOutputSchedule::times(times));
    let options = DdeOptions::new().with_ode_options(ode);
    let plan = DdePlan::new(1, (0.0, horizon), &[1.0], &[], options)?;
    let mut workspace = plan.workspace(DdeWorkspaceRequest::new(0))?;
    let mut state = OdeState::new(0.0, Vector::from_vec(vec![0.0]));
    let mut path = OdeTrajectory::new();
    let problem = DdeProblem::new(&rhs, &history);
    let cx = ExecutionContext::sequential();
    let report = plan.advance(&problem, &mut state, &mut path, &mut workspace, cx)?;
    let samples = path.times().iter().zip(path.states());
    Ok((
        samples.map(|(&t, y)| (t, y.as_slice()[0])).collect(),
        report,
    ))
}

/// λ + rτ e^{−λ} = 0 の実部最大の根 (μ, ω)。λ₀ = 1.5i からの Newton 法（f64 の標準関数）。
pub(crate) fn characteristic_root(rate_delay: f64) -> (f64, f64) {
    let (mut mu, mut omega) = (0.0_f64, 1.5_f64);
    for _ in 0..100 {
        // e = rτ e^{−λ}、g = λ + e、g' = 1 − e。
        let scale = rate_delay * (-mu).exp();
        let (er, ei) = (scale * omega.cos(), -scale * omega.sin());
        let (gr, gi, dr, di) = (mu + er, omega + ei, 1.0 - er, -ei);
        let norm = dr * dr + di * di;
        mu -= (gr * dr + gi * di) / norm;
        omega -= (gi * dr - gr * di) / norm;
    }
    (mu, omega)
}

/// 値の列の半振幅 (max − min)/2。
pub(crate) fn half_range(values: &[f64]) -> f64 {
    let max = values.iter().copied().fold(f64::MIN, f64::max);
    let min = values.iter().copied().fold(f64::MAX, f64::min);
    (max - min) / 2.0
}
```

次のセルは選んだ $r\tau$ と $\delta$ で $t = 200$ まで積分し、特性根と数値解から測った量を比べる。
観測した減衰率は区間 $[20, 40]$ と $[60, 80]$ の $|y - 1|$ の最大値の比から、周期は $t \ge 100$ で $y = 1$ を上向きに横切る時刻の間隔の平均から求める。
減衰率は、二つの最大値がどちらも線形化が成り立つ 0.05 未満で、積分の誤差の水準（$10^{-6}$）より大きいときだけ求める。

```rust
//| id: ode-hutchinson-hopf
//| ref: ode-hutchinson-hopf
//| title: 遅延ロジスティック方程式の平衡の安定性を特性根と比べる
//| run: reactive
//| uses: [ode-hutchinson-model]
//| crates: [scioxide-core, scioxide-linalg, scioxide-ode]
//| inputs:
//|   rate_delay: {"type":"range","label":"積 rτ [-]","description":"π/2 ≈ 1.571 を超えると平衡が不安定になる。","min":0.5,"max":2.5,"step":0.05,"value":1.4}
//|   perturbation: {"type":"range","label":"履歴のずれ δ [-]","description":"履歴 y = 1 + δ の平衡からのずれ。","min":0.01,"max":0.5,"step":0.01,"value":0.05}
//| cases:
//|   - {"id":"oscillating","label":"rτ = 1.8","description":"平衡が不安定になり、周期 4 より長い周期解に落ち着く。","inputs":{"rate_delay":1.8}}
//|   - {"id":"overdamped","label":"rτ = 0.5","description":"速い減衰振動で平衡に戻り、減衰率は誤差の水準より下で測れない。","inputs":{"rate_delay":0.5}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"stability","path":"/rows/0/1","approx":{"value":-0.0817037,"atol":1e-6}}
//|       - {"artifact":"stability","path":"/rows/0/2","approx":{"value":-0.0817,"atol":3e-3}}
//|       - {"artifact":"stability","path":"/rows/0/4","approx":{"value":4.1419,"atol":2e-2}}
//|       - {"artifact":"stability","path":"/rows/0/5","range":{"max":1e-4}}
//|   - case: oscillating
//|     expect:
//|       - {"artifact":"stability","path":"/rows/0/2","equals":null}
//|       - {"artifact":"stability","path":"/rows/0/5","range":{"min":0.9,"max":1.2}}
let fixed4 = serde_json::json!({ "fractionDigits": 4 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let (path, report) =
    hutchinson_path(rate_delay, perturbation, 0.0, 200.0).map_err(|e| e.to_string())?;
if !report.is_success() {
    return Err(format!("終端に達しなかった: {:?}", report.termination()));
}
let (mu, omega) = characteristic_root(rate_delay);
let deviation = |a: f64, b: f64| {
    path.iter()
        .filter(|p| p.0 >= a && p.0 <= b)
        .fold(0.0_f64, |m, p| m.max((p.1 - 1.0).abs()))
};
let (early, late) = (deviation(20.0, 40.0), deviation(60.0, 80.0));
let measurable = |d: f64| d < 0.05 && d > 1e-6;
let rate = (measurable(early) && measurable(late)).then(|| (late / early).ln() / 40.0);
// y = 1 を上向きに横切る時刻（線形補間）。
let crossings: Vec<f64> = path
    .windows(2)
    .filter(|w| w[0].0 >= 100.0 && w[0].1 < 1.0 && w[1].1 >= 1.0)
    .map(|w| w[0].0 + (1.0 - w[0].1) * (w[1].0 - w[0].0) / (w[1].1 - w[0].1))
    .collect();
let count = crossings.len();
let period = (count >= 2).then(|| (crossings[count - 1] - crossings[0]) / (count - 1) as f64);
let tail: Vec<f64> = path.iter().filter(|p| p.0 >= 180.0).map(|p| p.1).collect();
let linear_period = 2.0 * std::f64::consts::PI / omega;
let columns = serde_json::json!([
    { "key": "0", "label": "rτ [-]", "type": "number", "format": { "fractionDigits": 2 } },
    { "key": "1", "label": "特性根の実部 μ [1/τ]", "type": "number", "format": sci3 },
    { "key": "2", "label": "観測の減衰率 [1/τ]", "type": "number", "format": sci3, "nullText": "範囲外" },
    { "key": "3", "label": "線形化の周期 2π/ω [τ]", "type": "number", "format": fixed4 },
    { "key": "4", "label": "観測の周期 [τ]", "type": "number", "format": fixed4, "nullText": "なし" },
    { "key": "5", "label": "t ≥ 180 の半振幅 [K]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    vec![(
        rate_delay,
        mu,
        rate,
        linear_period,
        period,
        half_range(&tail)
    )],
    metadata = serde_json::json!({ "id": "stability" })
);
let series: Vec<[f64; 2]> = path.iter().map(|p| [p.0, p.1]).collect();
emit_line_chart!(
    &vec![
        serde_json::json!({ "name": format!("y(t)（rτ = {rate_delay:.2}）"), "points": series })
    ],
    options = &serde_json::json!({
        "xLabel": "時刻 t [τ]",
        "yLabel": "個体数 y [K]",
        "annotations": [{ "kind": "line", "axis": "y", "value": 1.0, "label": "平衡 y = K" }]
    })
);
```

既定の $r\tau = 1.4$ では、特性根は $\mu = -0.0817$、$2\pi/\omega = 4.1419$ で、数値解の減衰率 $-0.0832$ と周期 $4.1420$ はそれぞれ 2% と $10^{-4}$ 以内で一致する。
$t \ge 180$ の半振幅は $1.9 \times 10^{-8}$ まで減り、平衡は安定である。
$r\tau = 0.5$ では減衰が速く、$t = 20$ より前に平衡からのずれが積分の誤差の水準より小さくなるので、減衰率は範囲外として表示しない。
$r\tau = 1.8$ では $\mu = 0.097 > 0$ で平衡は不安定になり、解は半振幅 1.05 の周期解に落ち着く。
その周期 4.18 は線形化の周期 3.85 とも、分岐の直後の周期 4 とも異なり、非線形の効果を含む。

次のセルは $r\tau = 1.0, 1.1, \dots, 2.5$ の 16 通りを $\delta = 0.05$ で終端 $T$ まで解き、最後の 20 の時間の半振幅を分岐図に描く。

既定の $T = 200$ では、$r\tau \le 1.4$ の半振幅は $2 \times 10^{-8}$ 以下、$r\tau = 1.5$ では $1.4 \times 10^{-4}$ で、$\pi/2$ を超えると急に大きくなる。
$r\tau = 1.7$ と $1.8$ の半振幅 0.80 と 1.05 は標準形の近似 0.83 と 1.11 に近く、近似は $r\tau$ が $\pi/2$ から離れるほど外れる。
$r\tau = 1.6$ の 0.35 は近似の 0.40 より小さいが、これは成長率 $\mu = 0.013$ が小さく、$t = 200$ でもまだ周期解に近づく途中であるためである。

## まとめ

`DdePlan` は一定遅延の遅れ型 DDE を、最小の遅延以下の刻みで DP5(4) の段階法により積分し、過去の値を 4 次の連続拡張から取る。
初期時刻と宣言した履歴の不連続点から跳びを 5 階まで伝えて刻みの境目に予定するので、区分的に滑らかな解でも刻みの内部に低い階数の跳びを含まない。
保持する履歴は最大の遅延と刻み幅で決まり、`with_history_capacity` を超えると `HistoryCapacity` で止まる。
局所誤差の推定は履歴の補間誤差を含まないので、精度は既知の解か許容誤差を変えた解で確かめる。
遅延の長さは安定性を変え、遅延ロジスティック方程式では $r\tau = \pi/2$ で平衡が周期解に変わる。
