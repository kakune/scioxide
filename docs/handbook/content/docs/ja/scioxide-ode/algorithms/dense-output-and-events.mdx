適応刻みの方式では、局所誤差の制御で刻み幅 $h_n = t_{n+1} - t_n$ が刻みごとに変わる。
一方、応用では等間隔の時刻の値（図や FFT のための標本）や、地面への衝突、弁の開放、臨界温度への到達のような事象の時刻が必要になる。

観測の時刻に合わせて刻みを縮めると、誤差の制御が選んだ刻みより細かく積分することになり、右辺の評価が増える。
`scioxide-ode` は、受理した刻みの中を多項式で表す連続拡張（continuous extension、dense output）と、その多項式の上で事象関数の零点を探す事象検出を提供する。
このページでは連続拡張の構成と方式ごとの次数、出力の方針と受け取り先、事象の検出・局所化・見逃しを扱う。
刻みの受理と試行の区別、失敗したときに残る状態と出力は[解く手順と仕様](../solve-lifecycle-and-contracts/)で説明する。

## 連続拡張

受理した刻み $[t_n, t_{n+1}]$（幅 $h$）の中の位置を $\theta = (t - t_n)/h \in [0, 1]$ で表す。

### 連続拡張の構成

Runge–Kutta 法の連続拡張は、その刻みで計算した段の傾き $k_1, \dots, k_{s^*}$（連続出力のためだけに評価する段を含む）に $\theta$ の多項式の重みを掛けて

$$
\tilde{y}(t_n + \theta h) = y_n + h \sum_{i=1}^{s^*} b_i(\theta)\, k_i
$$

と作る。
重みは $b_i(0) = 0$（始点で $\tilde{y}(t_n) = y_n$）と $b_i(1) = b_i$（終点で $\tilde{y}(t_{n+1}) = y_{n+1}$）を満たす。
刻みの始点が厳密なとき、区間の中の値の誤差が $O(h^{p^*+1})$ となる $p^*$ を連続拡張の次数という。

段の傾きを使わない簡単な連続拡張に、端点の値と傾きによる 3 次 Hermite 補間

$$
\tilde{y}(t_n + \theta h) = (1-\theta)\, y_n + \theta\, y_{n+1} + \theta(\theta - 1)\Bigl[(1 - 2\theta)(y_{n+1} - y_n) + (\theta - 1)\, h f_n + \theta\, h f_{n+1}\Bigr]
$$

がある。
$f_n = f(t_n, y_n)$、$f_{n+1} = f(t_{n+1}, y_{n+1})$ で、連続拡張の次数は 3 である。

### 方式ごとの連続拡張の次数

| 方式 | 進める解の次数 | 連続拡張 | 次数 $p^*$ | 追加の右辺の評価 |
|---|---|---|---|---|
| `DormandPrince5` | 5 | Shampine の 4 次多項式 | 4 | なし |
| `DormandPrince853` | 8 | 3 段を足した 7 次多項式 | 7 | 連続出力を読む刻みで 3 回 |
| `Rkf45`、`Verner65` | 5、6 | 3 次 Hermite 補間 | 3 | 終点の $f_{n+1}$（次の刻みの第 1 段に使い回す） |
| `RadauIia` | 5 | 選点多項式（3 次） | 3 | なし |
| `RosenbrockW` | 2 か 3 | 3 次 Hermite 補間 | 3 | 終点の $f_{n+1}$（次の刻みの始点の微分に使い回す） |
| `AdamsBashforth`、`AdamsMoulton`、`Bdf` | 1〜5 | 履歴の補間多項式 | 現在の次数 | なし |
| `AutoStiff`、`AdamsBdf` | 使用中の方式 | 使用中の方式のもの | 使用中の方式のもの | 使用中の方式のもの |
| 固定刻みの Runge–Kutta 法と `StormerVerlet`、`Rattle` | — | なし | — | — |

`DormandPrince853` は、要求時刻の出力、事象、遅延方程式の履歴のいずれかがその刻みの連続出力を読むときだけ、3 段を追加で評価する。
`Rkf45` と `Verner65` の連続出力は主解の次数より低い。
連続拡張を持たない方式は、事象と要求時刻の出力に対応しない。
その方式に事象のある問題や `OdeOutputSchedule::Times` を渡すと、`InvalidInput`（`UnsupportedConfiguration`）を返す。
表の次数は、刻みの始点が厳密なときの区間の中の値の誤差の次数であり、それまでに積み重なった軌道の誤差の上限ではない。
連続出力の値の誤差はその刻みの始点の大域誤差と、連続拡張の誤差の和になる。

次のセルは調和振動子 $y_1' = y_2$、$y_2' = -y_1$、$y(0) = (1, 0)$（厳密解 $(\cos t, -\sin t)$）を、5 つの方式で刻み $h$ の 1 刻みだけ進める。
始点が厳密なので、時刻 $\theta h$ の連続出力と厳密解との差（最大値ノルム）は、連続拡張そのものの誤差である。
刻みは $h = 1.6, 0.8, 0.4, 0.2, 0.1$ で、許容誤差を緩くして刻みを棄却させない。
入力は刻みの中の位置 $\theta$ である。
出力の受け取り先には時刻と状態を受け取るクロージャを渡す。
表の右の 2 列は $h = 0.4$ の 1 刻みの右辺の評価回数を、終端だけを出力したときと連続出力を求めたときで比べる。

```rust
// 刻み h の 1 刻みを進め、時刻 θh の連続出力の誤差（θ が None なら終端だけを出力）と
// 右辺の評価回数を返す。
fn one_step<M: OdeMethod<f64> + Clone, Sys: OdeSystem<f64>>(
    method: &M,
    system: &Sys,
    h: f64,
    theta: Option<f64>,
) -> Result<(f64, usize), String> {
    let tolerance = ErrorTolerance::scalar(1.0, 1.0, NormSelection::RootMeanSquare)
        .map_err(|e| e.to_string())?;
    let schedule = match theta {
        Some(theta) => OdeOutputSchedule::times(vec![theta * h]),
        None => OdeOutputSchedule::FinalOnly,
    };
    let options = OdeOptions::new()
        .with_error_tolerance(tolerance)
        .with_initial_step(h)
        .with_output_schedule(schedule);
    let problem = OdeProblem::new(system, h);
    let mut workspace = method
        .workspace(&problem, &options)
        .map_err(|e| e.to_string())?;
    let mut state = OdeState::new(0.0, Vector::from_vec(vec![1.0, 0.0]));
    // 受け取り先のクロージャで、厳密解 (cos t, −sin t) との差を記録する（f64 の標準関数）。
    let mut error = 0.0;
    let mut sink = |t: f64, y: &[f64]| -> Result<(), SciOxideError> {
        error = (y[0] - t.cos()).abs().max((y[1] + t.sin()).abs());
        Ok(())
    };
    let report = method
        .advance(
            &problem,
            &options,
            &mut state,
            &mut sink,
            &mut workspace,
            ExecutionContext::sequential(),
        )
        .map_err(|e| e.to_string())?;
    if report.accepted_steps() != 1 || report.rejected_steps() != 0 {
        return Err("刻みが 1 回で受理されなかった".to_string());
    }
    Ok((
        error,
        report.counts().provider(EvaluationRole::RightHandSide),
    ))
}

// h = 1.6, 0.8, …, 0.1 の誤差と、h = 0.4 の評価回数（終端だけ、連続出力あり）。
fn measure<M: OdeMethod<f64> + Clone, Sys: OdeSystem<f64>>(
    method: M,
    system: &Sys,
    theta: f64,
) -> Result<(Vec<f64>, usize, usize), String> {
    let errors = (0..5)
        .map(|k| one_step(&method, system, 1.6 / f64::from(1 << k), Some(theta)).map(|r| r.0))
        .collect::<Result<Vec<f64>, String>>()?;
    let (_, endpoint_only) = one_step(&method, system, 0.4, None)?;
    let (_, dense) = one_step(&method, system, 0.4, Some(theta))?;
    Ok((errors, endpoint_only, dense))
}
```

既定の $\theta = 0.5$ では、観測次数は `DormandPrince5` で 4.99、`DormandPrince853` で 8.01、`Rkf45`、`Verner65`、`RadauIia` で 3.99、3.99、4.01 で、どれも表の次数 $p^*$ に 1 を足した値に近い。
`DormandPrince853` の誤差は $h = 0.1$ で $7.7 \times 10^{-15}$ まで下がり、丸め誤差の程度に近づく。
$\theta = 0.9$ の `DormandPrince5` の観測次数は 6.00 で、この問題とこの位置では $h^5$ の項の係数がほぼ 0 になる。
観測次数は位置と問題によって変わるので、連続拡張の次数を確かめるときは複数の $\theta$ で測る。

評価回数は、`DormandPrince853` が終端だけなら 13 回、連続出力を求めると 16 回で、追加の 3 段の分だけ増える。
`Rkf45` と `Verner65` は連続出力のために終点の $f_{n+1}$ を評価し、6 回が 7 回に、8 回が 9 回になる。
この $f_{n+1}$ は次の刻みの第 1 段に使い回されるが、1 刻みだけの積分ではその効果は現れない。
`DormandPrince5` と `RadauIia` は、連続出力を求めても評価が増えない。

## 出力の方針と受け取り先

`OdeOptions::with_output_schedule` に渡す `OdeOutputSchedule` で、受け取り先に送る状態を選ぶ。

| `OdeOutputSchedule` | 送る状態 |
|---|---|
| `FinalOnly`（既定） | 最後に受理した状態だけ |
| `AcceptedSteps` | 初期状態と、受理したすべての刻みの終点 |
| `Times { times, initial, final_state }` | `times` の各時刻の連続出力。`initial`、`final_state` が真なら初期状態と最後の状態も送る |

`OdeOutputSchedule::times(times)` は、初期状態と最後の状態を含めない `Times` を作る。
`times` は有限で、積分の区間の中にあり、積分の向きに単調でなければならない（同じ時刻の重複は許され、そのまま送られる）。
`Times` は連続拡張を持つ方式でだけ使える。
要求時刻は刻み幅に影響しないので、出力を細かくしても誤差の制御が選ぶ刻みは変わらない。

受け取り先は `OdeOutputSink` を実装した値で、`advance` の `sink` 引数に `&mut` で渡す。
`emit(time, state)` が状態を、`emit_requested(index, time, state)` が要求時刻の位置 `index` 付きの状態を、`event(event)` が事象を受け取る。
`emit_requested` の既定は `emit` を呼び、`event` の既定は事象を捨てる。
標準で使える受け取り先は次の 3 つである。

- `()`：すべての出力を捨てる。
  終端の状態だけが要るときは、`advance` の `state` を読めば足りる。
- `FnMut(S, &[T]) -> Result<(), SciOxideError>` のクロージャ：状態を受け取る（事象は捨てる）。
- `OdeTrajectory`：状態と事象をすべてメモリに保存する。
  `times()`、`states()`、`events()` で読み、`into_parts()` で取り出す。

受け取り先は各刻みの出力を刻みを受理した時点で受け取る。
同じ刻みの中では状態が先、事象がその後に、積分の順（同じ時刻では事象の番号の順）に送られる。
送った出力は、後の刻みで積分が失敗しても取り消されない。
受け取り先が返したエラーは積分を止め、そのまま `advance` から返る。
十分な大きさの作業領域と、確保をしない系と受け取り先を使えば、`advance` は積分の途中で確保をしない。
`OdeTrajectory` は状態と事象ごとに確保するので、確保を避けたいときは、あらかじめ確保した配列に書くクロージャか独自の受け取り先を使う。

## 事象の検出

### 事象関数と向き

事象は状態に依存するスカラーの事象関数 $g(t, y(t))$ の零点として定める。
`EventFunction` を実装した値が事象関数で、`eval` が $g(t, y)$ を、`direction` が数える符号の変化の向き（`EventDirection`）を、`is_terminal` が事象で積分を止めるかを返す。
`EventFn::new(closure)` は、クロージャ `Fn(S, &[T]) -> Result<S, SciOxideError>` から全微分を持たない事象関数を作り、`with_direction` と `with_terminal` で向きと終端の指定を変える（既定は両方向、終端でない）。
事象関数の配列は `OdeProblem::with_events` で問題に渡す。

| `EventDirection` | 数える変化 |
|---|---|
| `Rising` | 負から 0 以上へ |
| `Falling` | 正から 0 以下へ |
| `Either` | 両方 |

向きは刻みの始点から終点への順で測るので、時間を逆向きに積分するときも積分の順に従う。
ちょうど 0 になった標本は符号の変化を始めず、次の 0 でない標本が以後の判定の基準の符号になる。
そのため積分の開始時刻での零点は事象にならず、事象の時刻から積分を再開しても同じ事象を数え直さない。

見つかった事象は受け取り先の `event` に `OdeEvent` として渡される。
`OdeEvent` は事象関数の番号 `index()`、時刻 `time()`、その時刻の連続出力の状態 `state()`、起こり方 `occurrence()`（`EventOccurrence::Rising`、`Falling`、`Tangency`）、終端かどうか `is_terminal()`、局所化の根拠 `evidence()` を持つ。
`state()` は積分器の領域を借りているので、呼び出しの後まで残すには `EventInfo::from_event` で複製する（`OdeTrajectory` はそうして `EventInfo` を保存する）。
`EventEvidence` は、標本がちょうど 0 だった `SampledZero`、符号の変化を挟んで絞った `Crossing { bracket, residual }`、停留点で接触とみなした `Contact { bracket, residual }` のどれかで、`bracket` は最後の区間、`residual` はその時刻の $|g|$ である。
根拠は求根の過程だけを表し、ODE の解の精度は表さない。

終端の事象が見つかると、積分はその時刻で止まり、状態はその時刻の連続出力になり、レポートは `OdeTermination::TerminalEvent` と `terminal_event()`（事象の番号）を返す。
1 刻みに複数の事象があるときは、積分の順で最初の終端の事象までを送る。
終端の事象と時刻の許容誤差の範囲で同時に起きた事象も送り、その組は事象の番号の順に並べる。

### 検出の手順

刻みを受理するたびに、事象ごとに次の手順で調べる。

1. 刻みの終点で $g$ を評価し、始点の値と比べる。
   `EventSearchPolicy::Endpoints` では、向きに合う符号の変化がなければ、その刻みの連続出力を読まずに次へ進む。
2. `Subdivide(n)` と `DerivativeAssisted(n)` では刻みを $n$ 等分した各点で連続出力から $g$ を評価し、小区間ごとに符号の変化を調べる。
3. 符号の変化を挟む小区間があれば、連続出力 $\tilde{y}(t)$ の上で TOMS 748 の求根で区間を絞り、事象の時刻と状態を記録する。
4. `DerivativeAssisted(n)` では、各点で全微分 $dg/dt$ も評価し、その符号が変わる小区間では停留点を同じ求根で絞る。
   停留点で $g$ の符号が両端と違えば、同じ符号の両端の間の 2 回の交差として、停留点の両側をそれぞれ絞る。
   符号が変わらず $|g|$ が接触の許容誤差以下なら、接触（`EventOccurrence::Tangency`、`EventEvidence::Contact`）として記録する。
   接触を記録するのは、向きが `EventDirection::Either` の事象だけである。

どの方針も有限個の標本を調べるだけなので、標本の間の零点を見逃していないことは示せない。

### 連続拡張の上での求根

刻みの中の小区間 $[t_a, t_b]$ で $g(t_a)\, g(t_b) < 0$（または一端で 0）なら、$g$ が連続である限り区間に零点がある。
`scioxide-ode` は、連続拡張の上の関数

$$
\psi(t) = g\bigl(t,\, \tilde{y}(t)\bigr)
$$

の零点を、Alefeld–Potra–Shi の囲い込み法（Algorithm 748、TOMS 748）で求める。
TOMS 748 は逆 3 次補間（使えなければ 2 次の Newton 補間と割線）と倍幅の割線で区間を縮め、区間が十分に縮まなかった周期には二分法を行い、符号の変化を挟む区間を常に保つ（[区間を保つ求根法](../../../scioxide-rootfind/algorithms/bracketing-methods/)）。
滑らかな $\psi$ では二分法より少ない評価で収束し、区間の幅は 1 回の反復で大きく縮むことが多い。
この求根は多項式と事象関数を評価するだけで、微分方程式を積分し直さない。

区間は、幅が `OdeEventOptions` の時刻の許容誤差（`localization()`）以下になるか、$\psi$ がちょうど 0 になるか、区間の内側に表せる浮動小数点数がなくなるまで絞る。
時刻の許容誤差の既定は絶対・相対とも $4\varepsilon$（区間の幅が $4\varepsilon + 4\varepsilon \max(|t_a|, |t_b|)$ 以下）で、反復は事象ごとに 64 回までである。
$\varepsilon$ は時刻の型の機械イプシロンである。
これは積分の許容誤差とも接触の許容誤差とも独立で、`OdeEventOptions::with_localization(tolerance, max_iterations)` で変えられる。
反復の上限までに区間が許容誤差に達しなければ、積分は `ConvergenceFailure` のエラーで止まる。
求めた時刻の精度は連続拡張の精度を超えないので、事象の時刻の誤差は局所化で残る区間の幅と、その時刻の連続出力の誤差の大きい方で決まる。
局所化での $g$ の評価も事象関数の評価（`EvaluationRole::Event`）として数え、レポートの `event_search().evaluations()` は探索と局所化を合わせた事象関数とその全微分の評価回数になる。

### 探索の方針と零点の見逃し

端点の符号だけを調べる既定の `EventSearchPolicy::Endpoints` は、1 刻みの中で偶数回交差した零点の組と、軌道が事象の面に接して戻る接触（$g(t^*) = 0$、$dg/dt(t^*) = 0$）を見逃す。
`Subdivide(n)` は各刻みを $n$ 等分した点でも符号を調べ、`DerivativeAssisted(n)` はさらに全微分

$$
\frac{dg}{dt} = \frac{\partial g}{\partial t} + \nabla_y g \cdot \tilde{y}'(t)
$$

の符号の変化から停留点を挟み、同じ符号の 2 回の交差や接触を探す。
全微分は `EventFunction::total_derivative(t, y, slope)` で与え、`slope` には連続拡張の時間微分 $\tilde{y}'(t)$ が渡される（右辺を評価し直さない）。
`DerivativeAssisted` を選ぶには、すべての事象関数が `has_total_derivative()` で `true` を返さなければならず、そうでなければ `InvalidInput` になる。
`EventFn` は全微分を持たないので、`DerivativeAssisted` には `EventFunction` を自分で実装した値を使う。
レポートの `event_search()` が返す `EventSearchEvidence` は、使った方針（`policy()`）と評価回数（`evaluations()`）を記録する。

次のセルは時刻そのものを状態とする $y' = 1$、$y(0) = 0$ を一定の刻み $h$ で解き、事象関数 $g = \sin(\omega y + 0.3)$ の零点を 3 つの方針で数える。
右辺が定数なので、`DormandPrince5` の刻みは最大の刻み $h$ にそろう。
$(0, 10]$ にある真の零点 $t = (k\pi - 0.3)/\omega$ の数と比べ、見逃した数と事象関数の評価回数を表にする。
入力は事象の角周波数 $\omega$ と刻み $h$ である。

```rust
// 事象 g = sin(ω y + 0.3)。全微分 dg/dt = ω cos(ω y + 0.3) y' も与える。

impl EventFunction<f64> for Wave {

    fn has_total_derivative(&self) -> bool {
        true
    }
    fn total_derivative(&self, _: f64, y: &[f64], slope: &[f64]) -> Result<f64, SciOxideError> {
        Ok(self.0 * (self.0 * y[0] + 0.3).cos() * slope[0])

    }
}

// y' = 1、y(0) = 0 なので y = t。

    .map(|k| (f64::from(k) * std::f64::consts::PI - 0.3) / omega)

    ),
];

let (mut rows, mut nodes) = (Vec::new(), Vec::new());
for (name, policy) in policies {
    let options = OdeOptions::new()
        .with_initial_step(h)
        .with_maximum_step(h)
        .with_event_options(OdeEventOptions::new().with_search(policy))
        .with_output_schedule(OdeOutputSchedule::AcceptedSteps);
    let mut path = OdeTrajectory::new();
    let mut workspace = method
        .workspace(&problem, &options)
        .map_err(|e| e.to_string())?;
    let mut state = OdeState::new(0.0, Vector::from_vec(vec![0.0]));
    let report = method
        .advance(
            &problem,
            &options,
            &mut state,
            &mut path,
            &mut workspace,
            scioxide_core::ExecutionContext::sequential(),
        )
        .map_err(|e| e.to_string())?;
    if !report.is_success() {
        return Err(format!("積分が途中で終了した: {:?}", report.termination()));
    }
    let search = report.event_search().ok_or("探索の記録がない")?;
    let found = path.events().len();
    rows.push((
        name,
        found,
        exact,
        exact.saturating_sub(found),
        search.evaluations(),
    ));
    // 刻みの端点はどの方針でも同じ。
    nodes = path.times().to_vec();
}
// 参照の曲線と刻みの端点の値（f64 の標準関数による）。
```

既定値（$\omega = 6$ rad/s、$h = 0.8$ s）では、零点の間隔 $\pi/\omega \approx 0.52$ s が刻みより短い。
端点だけを調べる `Endpoints` は 19 個の零点のうち 7 個しか見つけず、12 個を見逃す。
各刻みを 4 等分する `Subdivide(4)` と `DerivativeAssisted(4)` は 19 個すべてを見つけるが、事象関数の評価は 105 回から 244 回、523 回に増える。
$h = 2$ s では `Endpoints` は 1 個しか見つけず、$\omega = 14$ rad/s では 44 個のうち 6 個しか見つけない。
$h = 0.05$ s では刻みが零点の間隔より十分短く、`Endpoints` も 360 回の評価で 19 個すべてを見つける。
零点の間隔より刻みが長くなりうる問題では、刻みを細かくするか、探索の方針で標本を増やす。
どちらの場合も、有限回の探索はすべての零点を見つけたことの証明にはならない。

### 符号が変わらない接触の検出

軌道が事象の面に接して戻る場合、たとえば $g(t, y) = (y - a)^2$ は常に 0 以上で、どの標本でも符号は変わらない。
`EventSearchPolicy::DerivativeAssisted` は、全微分 $dg/dt = 2(y - a)\, y'$ の符号の変化から停留点を挟み、そこで $|g|$ が接触の許容誤差以下なら接触として記録する。
接触の許容誤差は `OdeEventOptions::with_contact_tolerance(tolerance, scale)` で与え、$|g| \le \mathrm{atol} + \mathrm{rtol} \cdot \mathrm{scale}$ を接触の条件とする（既定は $\mathrm{atol} = \mathrm{rtol} = \sqrt{\varepsilon}$、$\mathrm{scale} = 1$）。
接触は有限の許容誤差による推定であり、軌道が面に触れたことの証明ではない。

次のセルは $y' = 1$、$y(0) = 0$ を 1 刻みで $[0, 1]$ について解き、接触の時刻 $a$ を `Endpoints` と `DerivativeAssisted(1)` で探す。
接触の許容誤差は $|g| \le 10^{-12}$ とする。
入力は接触の時刻 $a$ で、検出した時刻と解析的な時刻 $a$ の差を表にする。

```rust

//|   contact_time: {"type":"range","label":"接触の時刻 a [-]","description":"g = (y − a)² が 0 に触れる時刻。","min":0.31,"max":0.71,"step":0.1,"value":0.41}

//|   - {"id":"late-contact","label":"a = 0.71","description":"接触の位置を変えても、時刻の差は時刻の許容誤差の程度に収まる。","inputs":{"contact_time":0.71}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"contact","path":"/rows/0/1","equals":0}

//|   - case: late-contact
//|     expect:
//|       - {"artifact":"contact","path":"/rows/1/5","range":{"max":1e-15}}

        EventDirection::Either

        false

}
```

`DerivativeAssisted(1)` は接触を `Contact` として記録し、その時刻と $a$ の差は $5.6 \times 10^{-17}$、$|g|$ は $3.1 \times 10^{-33}$ で、事象関数とその全微分の評価は合わせて 11 回である。

この問題は解が $y = t$ で連続出力が厳密なので、時刻の差は局所化だけで決まる。
有限回の探索は、ほかに事象がないことを示さない。

## まとめ

連続拡張は受理した刻みの中を多項式で表し、積分し直さずに任意の時刻の値と事象の時刻を与える。
その誤差は方式ごとの連続拡張の次数で決まり、`Rkf45`、`Verner65`、`RadauIia`、`RosenbrockW` の 3 次は主解の次数より低い。
`DormandPrince853` の 7 次の連続拡張は連続出力を読む刻みで 3 回の評価を追加する。
出力は `OdeOutputSchedule` で選んで `OdeOutputSink` に送り、要求時刻は刻み幅を変えない。
事象の時刻は連続拡張の上で TOMS 748 によって既定 $4\varepsilon$ の時刻の許容誤差まで絞るが、その精度は連続拡張の精度を超えない。
事象の探索は既定では刻みの端点だけを調べるので、零点の間隔より刻みが長い問題や接触が起こる問題では `Subdivide` か `DerivativeAssisted` を選び、`EventSearchEvidence` の評価回数と合わせて見逃しの可能性を判断する。

事象の実例は[空気抵抗のある落体の接地事象](../../examples/ground-event/)にある。
積分が途中で止まったときに残る状態と出力の扱いは[解く手順と仕様](../solve-lifecycle-and-contracts/)で確かめられる。
