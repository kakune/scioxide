この章の数理のページは初期値問題

$$
M\,\frac{dy}{dt} = f(t, y), \qquad y(t_0) = y_0 \in \mathbb{C}^d
$$

を離散的な時刻 $t_0 < t_1 < \dots$ で近似する方式と、その仲間の問題（DAE、DDE、SDE、Hamilton 系、境界値問題）を扱う。
このページには全ページに共通する記号と仕様をまとめる。

## 記号

| 記号 | 意味 |
|---|---|
| $y_n$ | 時刻 $t_n$ での数値解 |
| $h_n = t_{n+1} - t_n$ | 刻み幅（負の向きの積分では負） |
| $p$ | 方式の次数（局所誤差が $O(h^{p+1})$、有限区間の大域誤差が $O(h^p)$） |
| $J = \partial f / \partial y$ | 右辺のヤコビ行列 |
| $z = h\lambda$ | 試験方程式 $y' = \lambda y$ での刻みと固有値の積 |
| $R(z)$ | 安定関数（1 刻みの増幅率 $y_{n+1} = R(z) y_n$） |
| $\varepsilon_{\mathrm{abs}}, \varepsilon_{\mathrm{rel}}$ | 局所誤差の絶対許容誤差と相対許容誤差 |
| $\varepsilon$ | 時間の型（`f64` か `f32`）の機械イプシロン |

## 共通の仕様

適応型の方式は埋め込み公式などで 1 刻みの局所誤差 $e_i$ を成分ごとに推定する。
それを $\varepsilon_{\mathrm{abs},i} + \varepsilon_{\mathrm{rel}}\max(|y_{i,n}|, |y_{i,n+1}|)$ で割ったノルム（既定は二乗平均）が 1 以下なら、刻みを受理する。
推定値は誤差の上限ではないので、大域誤差は許容誤差を変えた解や既知の解との比較で確かめる。

誤差の推定で刻みを変えない方式（古典的な陽的 Runge–Kutta 法、`RadauIia` 以外の陰的 Runge–Kutta 法、固定次数の多段法、Hamilton 系の分割法）は、与えた刻み幅で進む。
`OdeMethod` の固定刻みの方式は、`OdeOptions::with_initial_step` で刻み幅を与えなければ、適応型と同じ方法で推定した最初の刻み幅を使い続ける。

成否を決めるのは各問題の終了状態だけである。
初期値問題は `OdeTermination`、DAE は `DaeTermination`、DDE は `DdeTermination`、SDE は `SdeTermination`、Hamilton 系は `MechanicalTermination`、境界値問題は `BvpTermination`、随伴法は `AdjointTermination` を返す。
上限や取り消しで止まった結果も `Ok` で返ることがあるので、値を使う前にレポートの `is_success()` を確かめる。

コールバックのエラー、メモリ領域の確保の失敗、非有限値、数値計算の破綻は `SciOxideError` で返る。
このとき呼び出し側の状態には最後に受理した点が残り、作業領域の試行の記録（`last_attempt`）に進捗が残る。
受理する前の候補が、受理済みの状態を書き換えることはない。
詳しい手順は[解く手順と結果の仕様](solve-lifecycle-and-contracts/)で説明する。

右辺・ヤコビ行列・事象関数などの評価回数と、刻みの試行・受理・棄却の回数はレポートに記録される。
上限は `OdeOptions` の `with_max_steps`（試行の回数）と `with_max_evaluations`（評価の回数）か、scioxide-core の実行コンテキスト（取り消し・期限・計算回数の上限）で与える。
コールバックの中で別の求解を行うと、その処理も同じコンテキストの計算回数の上限に数えられる。

方式の係数は積分法オブジェクトに、次元に依存するメモリは呼び出し側が持つ作業領域にある。
作業領域は `check` と `try_reserve` で必要な容量を確かめてから再利用できる。
`advance` を呼ぶたびに、方式は前回の刻み幅や履歴を使わずに、渡した状態から新しく始める。
軌道の保存や事象の記録は、呼び出し側が選ぶ出力の出力先が確保する。

時間は実数で、状態は実数でも複素数でもよい。
陰的な方式、ヤコビ行列、随伴の積は正則な右辺を仮定するので、正則でないモデルは実部と虚部に分けて書く。

公開 API は呼び出し元の識別子や由来を表す引数を受け取らない。
エラーは、何が失敗したか（種類、`Argument` と `Quantity`、詳細）で表す。

## まとめ

この章の方式は、局所誤差の推定と許容誤差による刻みの受理、唯一の終了状態、失敗時の受理済み状態の保持、呼び出し側が持つ作業領域という共通の仕様に従う。
誤差の推定は上限ではないので、結果は既知の解や許容誤差を変えた解と比べる。
理論の基礎から読むなら[誤差・次数・安定性](error-order-and-stability/)へ、結果の受け取り方と失敗の扱いを先に確かめるなら[解く手順と結果の仕様](solve-lifecycle-and-contracts/)へ、型の一覧は [API ガイド](../api/)へ進む。
