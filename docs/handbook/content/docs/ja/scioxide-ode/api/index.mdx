`scioxide-ode` は常微分方程式の初期値問題、残差形式の指数 1 の微分代数方程式（DAE）、一定遅延の遅延微分方程式（DDE）、確率微分方程式（SDE）、分離可能な Hamilton 系とホロノミック拘束系、2 点境界値問題を解く。
解のパラメータと初期値に関する微分は、前進感度と随伴法で求める。
時刻は `f32` か `f64` の実数で、状態は実数か複素数である（DDE と RATTLE の状態は実数だけ）。
このガイドは目的ごとに最初に使う項目を示し、rustdoc の `all.html` に載る公開項目 177 個を 5 つの子ページの表にまとめる。
表の項目名のリンクは、docs.rs の 0.1.0 の API リファレンスを指す。

## 用途別の API

既定の設定で答えだけが必要なら、ワンショット関数から始める。
`solve_ivp` は終端時刻の状態を、`solve_ivp_at` は指定した時刻ごとの状態を行とする行列を返す。
どちらも Dormand–Prince 5(4) 法を、絶対許容誤差 $10^{-6}$、相対許容誤差 $10^{-3}$ の RMS ノルムの誤差制御で使う。
`solve_dde` は一定遅延の DDE を Dormand–Prince 5(4) 法の段階法で解き、終端時刻の状態を返す。
`solve_sde` は呼び出し側が与えた Wiener 増分で Euler–Maruyama 法の経路を求め、時刻の格子ごとの状態を返す。
`solve_hamiltonian` は分離可能な Hamilton 系を Störmer–Verlet 法の固定刻みで進め、最後の位置と運動量を返す。
`solve_bvp` は 2 点境界値問題を既定の選点法と残差の許容誤差 $10^{-3}$ で解き、区分 3 次の解を返す。
`solve_ensemble_into` は、パラメータだけが違う多数の問題を 1 回の実行で解き、メンバーごとの結果を呼び出し側の配列に書く。

ワンショット関数は成功しなかった終了をすべてエラーとして返す。
時間発展の関数（`solve_ivp`、`solve_ivp_at`、`solve_dde`、`solve_sde`、`solve_hamiltonian`）のエラーは `PartialFailure` で、最後に受理した点までの進捗を持つ。
`solve_bvp` のエラーは `SciOxideError` だけである。

方式と設定を選んで呼ぶときは、次の表の型から始める。

| 課題 | API となる項目 | 表 |

| 初期値問題の方式を選ぶ | `DormandPrince5`、`DormandPrince853`、`RadauIia`、`RosenbrockW`、`Bdf`、`AdamsBdf`、`BuiltinOdeMethod` | [方式と陰的な段の解法](steppers/) |
| 陰的な方式の線形方程式の解き方と Jacobian の取り方を指定する | `OdeStageBackend`、`NewtonMode`、`OdeStageSolver`、`DerivativeStrategy` | [方式と陰的な段の解法](steppers/) |
| 残差形式の DAE を解く | `DaeSystem`、`DaePartition`、`DaeBdf`、`DaeOptions` | [DAE・DDE・SDE・力学系](dae-dde-sde/) |
| 一定遅延の DDE を解く | `DdeRhs`、`DdeHistory`、`DdePlan` | [DAE・DDE・SDE・力学系](dae-dde-sde/) |

| 解のパラメータ・初期値に関する微分を求める | `ForwardSensitivitySystem`、`OdeAdjointSolver`、`DaeAdjointSolver` | [感度・随伴法・アンサンブル](sensitivities-and-adjoints/) |
| パラメータを変えた多数の問題を解く | `solve_ensemble_into`、`EnsembleParameters` | [感度・随伴法・アンサンブル](sensitivities-and-adjoints/) |
| 2 点境界値問題を解く | `BvpSystem`、`BvpProblem`、`BvpPlan`、`BvpOptions` | [境界値問題](boundary-value/) |

ほかのクレートの型も引数と結果に現れる。
許容誤差（`ErrorTolerance`、`ResidualTolerance`）、上限（`Budget`）、実行コンテキスト（`ExecutionContext`、`SolveContext`）、部分失敗（`PartialFailure`）、試行の記録（`AttemptRecord`）、疎な構造（`StructuralPattern`）は scioxide-core が提供する。
ベクトルと行列（`Vector`、`Matrix`、`MatrixView`）は scioxide-linalg、Jacobian の取り方（`DerivativeStrategy`）は scioxide-differentiate、疎 LU 分解の上限（`SparseLuLimits`）は scioxide-sparse、チェックポイントのスケジュール（`CheckpointSchedule`）は scioxide-ad が提供する。
境界値問題の Newton 法の設定は scioxide-rootfind の `NewtonKrylovOptions` と同じ既定値を使い、Newton 法の未収束は同じクレートの `RootTermination` で返す。
これらの型はそれぞれのクレートの API ガイドの表に載る。

## 型の関係

ワンショット関数は既定の設定の方式と作業領域をその場で作り、逐次に実行して答えを返す。

初期値問題では、系、問題、積分法オブジェクト、設定、状態、出力の出力先、作業領域がそれぞれ別の値である。
`OdeSystem` は次元と右辺 $f(t, y)$ を必須とするトレイトで、Jacobian、質量行列、時間の偏微分、刻み幅の上限、試行状態を拒む判定（`admits`）を任意で与える。
`OdeFn` はクロージャから作る `OdeSystem` の実装である。
`OdeProblem` は系、終端時刻、事象関数、陰的な段の解法を借用し、開始時刻と初期値は呼び出し側が所有する `OdeState` に置く。
積分法オブジェクト（`DormandPrince5::new()` など）は係数と方式に固有の設定だけを持ち、`OdeMethod` トレイトのメソッドで実行する。
`validate(options, dimension)` は設定を検査し、`workspace(problem, options)` は再利用する作業領域 `OdeWorkspace` を確保する。
`advance(problem, options, state, sink, workspace, scope)` は状態をその場で進め、受理した点を出力の出力先 `OdeOutputSink` に送り、`OdeSolveReport` を返す。
`solve(problem, options, initial)` は新しい作業領域と `OdeTrajectory` を用意して `advance` を逐次に呼び、`OdeSolution` を返す。
`OdeOptions` は許容誤差、初期刻み、刻み幅の上下限、制御器（`OdeStepControl`）、出力する時刻（`OdeOutputSchedule`）、事象の探索（`OdeEventOptions`）、試行と評価の上限をまとめた設定で、呼び出しごとに渡す。
実行時に方式を選ぶときは、積分法オブジェクトを `BuiltinOdeMethod` に変換する。

ほかの問題も同じ分け方をとる。
DAE は `DaeBdf`、SDE は `SdeMethod`、Hamilton 系は `StormerVerlet` と `Rattle` の積分法オブジェクトに、問題（または系）、設定、状態、出力の出力先、作業領域を渡す。
DDE の `DdePlan` は遅延と区間から導関数の不連続点のスケジュールを、境界値問題の `BvpPlan` は初期の節点の列と特異項の擬似逆行列を、作成時に一度だけ計算する。
どちらの Plan も系を借用せず、同じ次元の問題に何度でも使える。
随伴法の `OdeAdjointSolver` と `DaeAdjointSolver` も次元と設定だけを検査する Plan で、系、目的関数、初期値、積分区間を借用する `OdeAdjointProblem` と `DaeAdjointProblem` を受け取る。
前進感度は `ForwardSensitivitySystem::bind` が作る拡大系を通常の `OdeSystem` として扱い、初期値問題の方式で積分する。

## 最小の実行例

次のセルは $y' = -y$、$y(0) = 1$ を古典的 4 次 Runge–Kutta 法（`ClassicalRk4`）で $t = 1$ まで解き、解析解 $e^{-1}$ と比べる。
`ClassicalRk4` は固定刻みの方式なので、`OdeOptions::with_initial_step` の値がそのまま刻み幅 $h$ になり、終端を越える刻みだけが終端に合わせて短くなる。
刻み幅は $h = 2^{-k}$ とし、入力で指数 $k$ を変える。
2 の冪は 2 進の浮動小数点数で正確に表せるので、$h$ の倍数がちょうど $t = 1$ に達する。
$h = 0.1$ のように正確に表せない刻み幅では時刻の和に丸め誤差がたまるが、終端までの残りが丸め誤差の上界 $1024\,\varepsilon\max(|t|, |t_\text{end}|)$ 以下になった刻みは終端で終えるので、余分な短い刻みは入らない。
積分法オブジェクトと作業領域を一度だけ作り、刻み幅 $h$ と $h/2$ の 2 回の `advance` で使い回す。
大域誤差 $e_h$ が $h^4$ に比例するなら、2 回の誤差の比から求める観測次数 $\log_2(e_h / e_{h/2})$ は 4 に近づく。
表は刻み幅、終了状態、受理した刻みの数、出力の出力先に届いた点の数、数値解、解析解との差、観測次数を示す。
既定の出力 `FinalOnly` は終端の状態だけを送るので、届く点は 1 個である。

```rust
//| id: ode-api-exponential-decay
//| ref: ode-api-exponential-decay
//| title: 指数減衰を固定刻みの RK4 で解いてレポートと誤差を読む
//| run: reactive
//| crates: [scioxide-ode, scioxide-core, scioxide-linalg]
//| inputs:
//|   step_exponent: {"type":"range","label":"刻み幅の指数 k（h = 2⁻ᵏ）","description":"刻み幅を 2 の冪で変える。RK4 の大域誤差は h⁴ に比例して変わる。","min":2,"max":7,"step":1,"value":3}
//| cases:
//|   - {"id":"coarse","label":"h = 0.25","description":"4 刻みでも観測次数は 4 に近い。","inputs":{"step_exponent":2}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"runs","path":"/rows/0/1","equals":"ReachedEnd"}
//|       - {"artifact":"runs","path":"/rows/0/2","equals":8}
//|       - {"artifact":"runs","path":"/rows/0/3","equals":1}
//|       - {"artifact":"runs","path":"/rows/0/5","approx":{"value":8.3075e-7,"rtol":1e-3}}
//|       - {"artifact":"runs","path":"/rows/1/6","approx":{"value":4.075,"atol":0.01}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: coarse
//|     expect:
//|       - {"artifact":"runs","path":"/rows/0/2","equals":4}
//|       - {"artifact":"runs","path":"/rows/0/5","approx":{"value":1.4758e-5,"rtol":1e-3}}
//|       - {"artifact":"runs","path":"/rows/1/6","approx":{"value":4.151,"atol":0.01}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
use scioxide_core::ExecutionContext;
use scioxide_linalg::Vector;
use scioxide_ode::{
    ClassicalRk4, OdeFn, OdeMethod, OdeOptions, OdeProblem, OdeState, OdeTrajectory,
};

let sig12 = serde_json::json!({ "significantDigits": 12 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let sig4 = serde_json::json!({ "significantDigits": 4 });
let fixed2 = serde_json::json!({ "fractionDigits": 2 });

// y' = -y の 1 成分の系。
let system = OdeFn::new(1, |_t: f64, y: &[f64], dy: &mut [f64]| {
    dy[0] = -y[0];
    Ok(())
})
.map_err(|e| e.to_string())?;
let problem = OdeProblem::new(&system, 1.0);
let method = ClassicalRk4::new();
// 作業領域は一度だけ確保し、2 回の advance で使い回す。
let mut workspace = method
    .workspace(&problem, &OdeOptions::new())
    .map_err(|e| e.to_string())?;

let mut rows = Vec::new();
let mut errors = Vec::new();
let mut all_reached = true;
// 2 の冪の刻み幅は 2 進で正確に表せるので、h の倍数がちょうど t = 1 に達する。
let step_size = 0.5_f64.powi(step_exponent as i32);
for h in [step_size, step_size / 2.0] {
    // 固定刻みの方式では初期刻みがそのまま刻み幅になる。
    let options = OdeOptions::new().with_initial_step(h);
    let mut state = OdeState::new(0.0, Vector::from_vec(vec![1.0]));
    let mut output = OdeTrajectory::new();
    let report = method
        .advance(
            &problem,
            &options,
            &mut state,
            &mut output,
            &mut workspace,
            ExecutionContext::sequential(),
        )
        .map_err(|e| e.to_string())?;
    all_reached &= report.is_success();
    // 独立な検算: 到達した時刻 t の解析解 e^{-t}（f64 の参照値）。
    let value = state.values()[0];
    let error = (value - (-report.final_time()).exp()).abs();
    // 観測次数は 2 行目だけで定義する。
    let order = errors.last().map(|&coarse: &f64| (coarse / error).log2());
    errors.push(error);
    rows.push((
        h,
        report
            .termination()
            .map_or_else(String::new, |t| t.to_string()),
        report.accepted_steps(),
        output.times().len(),
        value,
        error,
        order,
    ));
}
let observed = rows[1].6.unwrap_or(f64::NAN);

let columns = serde_json::json!([
    { "key": "0", "label": "刻み幅 h [-]", "type": "number", "format": sig4 },
    { "key": "1", "label": "終了状態" },
    { "key": "2", "label": "受理した刻み [回]", "type": "integer" },
    { "key": "3", "label": "出力した点 [個]", "type": "integer" },
    { "key": "4", "label": "数値解 y(t) [-]", "type": "number", "format": sig12 },
    { "key": "5", "label": "解析解との差 [-]", "type": "number", "format": sci3 },
    { "key": "6", "label": "観測次数 [-]", "type": "number", "format": fixed2, "nullText": "-" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "runs" })
);

// 2 回とも終端に達したときだけ観測次数を結論に使う。
let outcome = if all_reached && observed.is_finite() {
    Outcome::satisfied("2 つの刻み幅で終端に達した")
        .explanation("固定刻みの方式は誤差を推定しない。精度は解析解との差と観測次数で読む。")
        .diagnostic("観測次数", observed, None)
} else {
    Outcome::partial("終端に達する前に止まった")
        .explanation("表の値は最後に受理した時刻の状態である。")
};
emit_outcome!(outcome.status(rows[1].1.clone()));
```

既定の $k = 3$（$h = 0.125$）では、どちらの刻み幅でも `ReachedEnd` で終わり、受理した刻みは 8 回と 16 回である。
解析解との差は $h = 0.125$ で $8.31 \times 10^{-7}$、$h = 0.0625$ で $4.93 \times 10^{-8}$ で、観測次数は 4.08 になる。
$k = 2$（$h = 0.25$）の 4 刻みでは差が $1.48 \times 10^{-5}$ まで増えるが、観測次数は 4.15 で、粗い刻みでも 4 次の収束が見える。
$k = 7$（$h = 2^{-7}$）では差が $1.15 \times 10^{-11}$ まで下がり、観測次数は 4.01 である。
固定刻みの方式は誤差の推定を持たないので、レポートの `last_step_error_estimate()` は `None` になる。
精度は解析解や刻み幅を変えた比較のような独立な基準で読む。

## 結果・エラー・診断の読み方

時間発展の解法はそれぞれ終了状態の列挙型を 1 つ持つ。
`OdeTermination`、`DaeTermination`、`DdeTermination`、`SdeTermination`、`MechanicalTermination`、`AdjointTermination` は、共通の列挙子 `ReachedEnd`、`TerminalEvent`、`BudgetLimit(kind)`、`StepSizeLimit`、`ExecutionStopped(reason)` に問題ごとの列挙子を加える。
問題ごとの列挙子は、DDE の `HistoryCapacity`（履歴の保持数の上限）、DAE の `RejectionLimit`（連続棄却の上限）、RATTLE の `ProjectionLimit`（拘束の許容誤差を満たせない刻み）、随伴法の `ReplayMismatch`（再計算の不一致）と `EventDerivativeUnavailable`（終端事象の微分がない）である。
レポートの `is_success()` が成否を判定し、成功は `ReachedEnd` と `TerminalEvent` である。
事象を持たない DAE、SDE、力学系は `TerminalEvent` を返さない。
境界値問題は別の列挙型 `BvpTermination` を持ち、成功は `Converged` だけである。

試行・評価の上限、最小の刻み幅、取り消し、期限で止まると、`advance` は成功でない終了状態のレポートを `Ok` で返し、状態には最後に受理した点が残る。
それ以外の失敗は `SciOxideError` で返る。
入力の検査はコールバックを呼ぶ前に行い、検査で拒んだ呼び出しは状態を変えない。
積分を始めた後の失敗でも状態には最後に受理した点が残り、作業領域の `last_attempt()` が試行の結果と進捗（初期値問題では `OdeProgress`）を記録する。
出力の出力先に送った点は後の失敗でも取り消されない。
所有値を返す API の `solve` は積分を始めた後の失敗の進捗を `PartialFailure` に入れて返す。
ワンショット関数は試行・評価の上限と最小の刻み幅による停止を `ConvergenceFailure` に、DDE の履歴の保持数の上限を `ResourceLimit` に、取り消しと期限を `ExecutionStopped` に変える。
随伴法は両方の勾配を成功したときだけ書き、境界値問題の `solve_into` はエラーのとき出力を変えない。

エラーの分類は `e.kind()` で読む。
`InvalidInput` は設定の誤り（正でない刻み幅の上限など）、方式が対応しない機能（連続出力のない方式での時刻指定の出力や事象、固定刻みの方式への制御器の指定）、等しい開始時刻と終端時刻である。
`NonFinite` は入力（発生元 `Input`）かコールバックの出力（発生元 `Callback`）の NaN や無限大、`DimensionMismatch` は系・状態・出力の配列の長さの不一致である。
`ConvergenceFailure`、`Singular`、`NumericalInstability` は、固定刻みの方式の段の解法の失敗や DAE の初期値の射影の失敗を表す。
適応刻みの方式は段の解法に失敗すると刻みを半分にしてやり直し、それ以上縮められないと `StepSizeLimit` で止まる。
`ResourceLimit`、`AllocationFailure`、`SizeOverflow` は、作業領域・履歴・チェックポイントのメモリが設定した上限を超えるか確保できないことを表す。
コールバックが返したエラーは変えずにそのまま返る。

`last_step_error_estimate()` は最後に試行した刻みの正規化した局所誤差の推定で、1 以下なら刻みを受理する。
大域誤差の上限ではない。
DDE の推定は履歴の補間の誤差を含まない。
SDE の推定は 1 刻みと半刻み 2 回の差で、細分化を設定したときだけ値を持つ。
力学系のレポートは推定を持たない。
境界値問題の区間の残差、DAE の残差、随伴法の `AdjointErrorReport` も診断の値で、誤差の上限ではない。
`trust()` は最後に受理した状態の信頼の段階（`PartialResultTrust`）で、精度の証明ではない。

`accepted_steps()` と `rejected_steps()` は時間方向の刻みの受理と棄却の回数で、随伴法では最初の前進の積分だけを数える。
`counts()` はその呼び出し自身の評価と反復の回数で、入れ子の解法を含まない。
`accounting()` は入れ子の解法を含む回数の集計である。

事象を設定した初期値問題と DDE では、レポートの `events()` が検出した事象の数、`terminal_event()` が積分を止めた事象の添字を返す。
`event_search()` は探索方針と、局所化を含む事象関数の評価回数を返す。
事象の時刻と状態は `OdeOutputSink::event` に渡り、`OdeTrajectory::events()` に `EventInfo` として残る。
有限個の標本で探すので、検出しなかったことは事象がないことを示さない。
