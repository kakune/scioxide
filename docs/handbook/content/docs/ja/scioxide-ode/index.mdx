状態 $y(t) \in \mathbb{R}^d$（または $\mathbb{C}^d$）の変化率がその時刻の状態で決まる常微分方程式（ordinary differential equation, ODE）の初期値問題（initial value problem, IVP）

$$
M\,\frac{dy}{dt} = f(t, y), \qquad y(t_0) = y_0
$$

は、天体の運動、化学反応の濃度変化、生態系の個体数、電気回路の過渡応答など多くのモデルに現れる。
$M$ は定数の質量行列で、既定は単位行列である。
数値積分を難しくするのは、時定数が大きく離れた成分による剛性（stiffness）、事象による不連続、過去の状態への依存、確率的な駆動などである。

`scioxide-ode` は次の問題を扱う。

| 問題 | 式 | ワンショット関数 | 設定して使う型 |
|---|---|---|---|
| 初期値問題（正則な質量行列を含む） | $M y' = f(t, y)$ | `solve_ivp`、`solve_ivp_at` | `OdeMethod` を実装する方式（`DormandPrince5`、`RadauIia`、`Bdf` など） |
| 指数 1 の微分代数方程式（DAE） | $F(t, y, y') = 0$ | なし | `DaeBdf` |
| 一定遅延の遅延微分方程式（DDE） | $y' = f(t, y(t), y(t - \tau_j))$ | `solve_dde` | `DdePlan` |
| 確率微分方程式（SDE） | $dY = a\,dt + B\,dW$ | `solve_sde` | `SdeMethod` |
| 分離可能な Hamilton 系とホロノミック拘束 | $q' = \partial H/\partial p$、$p' = -\partial H/\partial q$ | `solve_hamiltonian` | `StormerVerlet`、`Rattle` |
| 2 点境界値問題（BVP） | $y' = f(x, y, p)$、$g(y(a), y(b), p) = 0$ | `solve_bvp` | `BvpPlan` |
| 解のパラメータに関する微分 | 前進感度、随伴法 | なし | `ForwardSensitivitySystem`、`OdeAdjointSolver`、`DaeAdjointSolver` |
| 独立な多数の初期値問題 | パラメータごとの IVP | `solve_ensemble_into` | `EnsembleWorkspace` |

時間は `f32` か `f64` の実数で、状態は実数でも複素数でもよい。
陰的な方式で複素数の状態を使う場合、右辺は正則（holomorphic）でなければならない。
正則でないモデルは実部と虚部に分けた実数の系として書く。

## 最初の計算：ロジスティック成長

個体数 $y$ [匹] が増殖率 $r$ [1/日] と環境収容力 $K$ [匹] で $y' = r\,y(1 - y/K)$ に従うとき、解は

$$
y(t) = \frac{K}{1 + (K/y_0 - 1)e^{-rt}}
$$

である。
$K = 1000$、$y_0 = 10$ として 20 日後の値を三つの方法で求め、閉形式と比べる。

1. ワンショット関数 `solve_ivp` に右辺のクロージャ、始点と終点の時刻、初期値を渡す。
   方式は 5(4) 次の Dormand–Prince 法で、許容誤差は既定の $\varepsilon_\text{abs} = 10^{-6}$、$\varepsilon_\text{rel} = 10^{-3}$ に固定される。
   戻り値は終点の状態だけである。
2. 積分法オブジェクト `DormandPrince5` と 8(5,3) 次の `DormandPrince853` に `OdeOptions` で許容誤差と刻みの上限を与え、`solve` で解く。
   戻り値の `OdeSolution` は終点の状態のほかに、終了状態、刻みの数、評価回数を記録したレポート `OdeSolveReport` を持つ。

セルの入力は増殖率、積分法オブジェクトに与える許容誤差、試行する刻みの上限である。
出力は 3 行の表と、積分法オブジェクトの二つがともに成功したかを示す判定である。

```rust
//| id: ode-first-logistic
//| ref: ode-first-logistic
//| title: ロジスティック成長を solve_ivp と二つの積分法オブジェクトで解き、レポートを読む
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg, scioxide-ode]
//| inputs:
//|   growth_rate: {"type":"range","label":"増殖率 r [1/日]","description":"大きいほど 20 日の間に飽和へ速く近づく。","min":0.2,"max":2,"step":0.1,"value":0.5}
//|   tolerance_exponent: {"type":"range","label":"許容誤差 10^q の指数 q","description":"積分法オブジェクトに与える相対許容誤差と絶対許容誤差 [匹]。solve_ivp は既定値のまま。","min":-12,"max":-3,"step":1,"value":-6}
//|   max_steps: {"type":"range","label":"試行する刻みの上限 [回]","description":"棄却した刻みも数える。小さくすると途中で止まる。","min":5,"max":500,"step":5,"value":500}
//| cases:
//|   - id: step-limit
//|     label: 刻みの上限 10
//|     inputs: {"max_steps":10}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"methods","path":"/rows/0/4","range":{"max":1e-1}}
//|       - {"artifact":"methods","path":"/rows/1/1","equals":"ReachedEnd"}
//|       - {"artifact":"methods","path":"/rows/2/4","range":{"max":1e-4}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: step-limit
//|     expect:
//|       - {"artifact":"methods","path":"/rows/1/1","equals":"BudgetLimit(Proposal)"}
//|       - {"artifact":"methods","path":"/rows/1/2","range":{"max":10}}
//|       - {"path":"/outputs/1/state","equals":"partial"}
use scioxide_core::{Budget, ErrorTolerance, NormSelection};
use scioxide_linalg::Vector;
use scioxide_ode::{
    DormandPrince5, DormandPrince853, OdeFn, OdeMethod, OdeOptions, OdeProblem, OdeSolution,
    OdeState, solve_ivp,
};

let (capacity, initial, horizon) = (1000.0_f64, 10.0_f64, 20.0_f64);
// 右辺 y' = r y (1 − y/K)。状態は 1 成分。
let logistic = move |_t: f64, y: &[f64], dy: &mut [f64]| {
    dy[0] = growth_rate * y[0] * (1.0 - y[0] / capacity);
    Ok(())
};
// 独立な検算: 時刻 t の閉形式の解（指数関数は f64 の参照値）。
let exact = |t: f64| capacity / (1.0 + (capacity / initial - 1.0) * (-growth_rate * t).exp());

// 1. ワンショット呼び出し。既定の許容誤差で DormandPrince5 を使い、終点の状態を返す。
let one_shot = solve_ivp(logistic, 0.0, horizon, &[initial])
    .map_err(|e| e.error().to_string())?;
let one_shot_value = one_shot.as_slice()[0];

// 2. 積分法オブジェクト。許容誤差と刻みの上限を OdeOptions で与える。
let tol = 10.0_f64.powf(tolerance_exponent);
let budget = Budget::try_from(max_steps as usize).map_err(|e| e.to_string())?;
let options = OdeOptions::new()
    .with_error_tolerance(
        ErrorTolerance::scalar(tol, tol, NormSelection::RootMeanSquare)
            .map_err(|e| e.to_string())?,
    )
    .with_max_steps(budget);
let rhs = OdeFn::new(1, logistic).map_err(|e| e.to_string())?;
let problem = OdeProblem::new(&rhs, horizon);
let initial_state = || OdeState::new(0.0, Vector::from_vec(vec![initial]));
let solutions: [(&str, OdeSolution<f64>); 2] = [
    (
        "DormandPrince5",
        DormandPrince5::new()
            .solve(&problem, &options, initial_state())
            .map_err(|e| e.error().to_string())?,
    ),
    (
        "DormandPrince853",
        DormandPrince853::new()
            .solve(&problem, &options, initial_state())
            .map_err(|e| e.error().to_string())?,
    ),
];

let mut rows = vec![(
    "solve_ivp（既定の許容誤差）".to_string(),
    "ReachedEnd".to_string(),
    horizon,
    one_shot_value,
    (one_shot_value - exact(horizon)).abs(),
    None,
    None,
    None,
)];
for (name, solution) in &solutions {
    let report = solution.report();
    // 途中で止まった場合も、到達した時刻の閉形式と比べる。
    let time = solution.state().time();
    let value = solution.state().values()[0];
    let evaluations = report.counts().total_providers().map_err(|e| e.to_string())?;
    rows.push((
        name.to_string(),
        report.termination().map_or_else(String::new, |t| t.to_string()),
        time,
        value,
        (value - exact(time)).abs(),
        Some(report.accepted_steps()),
        Some(report.rejected_steps()),
        Some(evaluations),
    ));
}
let sig4 = serde_json::json!({ "significantDigits": 4 });
let sig10 = serde_json::json!({ "significantDigits": 10 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "方法" },
    { "key": "1", "label": "終了状態" },
    { "key": "2", "label": "到達時刻 t [日]", "type": "number", "format": sig4 },
    { "key": "3", "label": "y(t) [匹]", "type": "number", "format": sig10 },
    { "key": "4", "label": "閉形式との差 [匹]", "type": "number", "format": sci2 },
    { "key": "5", "label": "受理した刻み [回]", "type": "integer", "nullText": "レポートなし" },
    { "key": "6", "label": "棄却した刻み [回]", "type": "integer", "nullText": "レポートなし" },
    { "key": "7", "label": "右辺の評価 [回]", "type": "integer", "nullText": "レポートなし" }
]);
emit_table_with_columns!(columns, rows, metadata = serde_json::json!({ "id": "methods" }));

let all_success = solutions.iter().all(|(_, s)| s.report().is_success());
let first = solutions[0].1.report();
let outcome = if all_success {
    Outcome::satisfied("二つの積分法オブジェクトが終点に達した")
        .explanation("許容誤差は局所誤差の目標なので、精度は閉形式との差で確かめる。")
} else {
    Outcome::partial("刻みの上限で終点の前に止まった")
        .explanation("表の値は最後に受理した時刻の状態で、20 日の値ではない。")
};
emit_outcome!(
    outcome
        .status(first.termination().map_or_else(String::new, |t| t.to_string()))
        .diagnostic("DormandPrince5 の到達時刻", first.final_time(), Some("日"))
);
```

既定の $r = 0.5$、許容誤差 $10^{-6}$ では、表の 3 行がすべて `ReachedEnd` で終わる。
`solve_ivp` は既定の許容誤差（相対 $10^{-3}$）で解くので、閉形式との差は $6.6\times10^{-2}$ 匹と大きい。
積分法オブジェクトでは、`DormandPrince5` が受理 29 回・棄却 2 回・右辺 188 回の評価で差 $1.3\times10^{-4}$ 匹、`DormandPrince853` が受理 10 回・棄却 2 回・右辺 146 回の評価で差 $5.4\times10^{-6}$ 匹になる。
許容誤差を $10^{-12}$ まで厳しくすると、`DormandPrince5` は 2444 回の評価で差 $1.8\times10^{-10}$ 匹、`DormandPrince853` は 686 回の評価で差 $6.8\times10^{-11}$ 匹になる。
高次の方式が評価回数で有利になるのは、このように厳しい許容誤差で解くときである。

刻みの上限を 10 回にすると、二つの積分法オブジェクトは `BudgetLimit(Proposal)` で終点の前に止まり、判定は `partial` になる。
`DormandPrince5` は 4.38 日、`DormandPrince853` は 15.8 日で 10 回の試行を使い切る。
このとき `solve` はエラーを返さず、表の値は到達時刻の状態で、その時刻の閉形式との差はどちらも $4\times10^{-5}$ 匹以下である。
一方、ワンショット呼び出しの `solve_ivp` は成功でない終了をエラーとして返す。

## 結果の読み方

成否を決めるのはレポートの終了状態 `report.termination()`（`Option<OdeTermination>`）だけで、`report.is_success()` はその要約である。
成功は `ReachedEnd`（終点に到達）と `TerminalEvent`（終端の事象で停止）の二つに限る。
積分法オブジェクトの `solve` と `advance` は、試行の上限 `BudgetLimit(Proposal)`、評価回数の上限 `BudgetLimit(Evaluation)`、刻み幅の下限 `StepSizeLimit`、取り消し `ExecutionStopped` でも `Ok` を返す。
値を使う前に、必ず終了状態を確かめる。

コールバックのエラー、メモリ領域の確保の失敗、数値の破綻は `Err` で返る。
`solve` とワンショット関数は `PartialFailure` を返し、積分を始めた後のエラーなら、最後に受理した時刻と状態（`OdeProgress`）をその中に入れる。
`advance` では、呼び出し側の `OdeState` に最後の受理点が残り、作業領域の `last_attempt()` で試行の結果を読める。
詳しくは[解く手順と結果の仕様](algorithms/solve-lifecycle-and-contracts/)で説明する。

許容誤差は 1 刻みの局所誤差の推定に対する目標で、終点での大域誤差の上限ではない。
このセルのように閉形式、保存量、許容誤差を変えた解との比較で確かめる。
`accepted_steps()` と `rejected_steps()` は時間方向の刻みの受理と棄却の回数、`counts()` は右辺などのコールバックの評価回数である。

## まとめ

`scioxide-ode` は初期値問題を中心に、DAE、DDE、SDE、Hamilton 系、2 点境界値問題と、解の微分（前進感度と随伴法）を扱う。
既定の設定で終点の値だけが要るなら `solve_ivp` を使い、許容誤差、出力、上限、作業領域の再利用が要るなら積分法オブジェクトと `OdeOptions` を使う。
積分法オブジェクトの結果は、まず `report.is_success()` で成否を確かめ、値は誤差の推定に基づく近似として閉形式や別の計算と比べる。
方式を選ぶには[選び方](choosing/)へ進む。
許容誤差と大域誤差の関係を確かめるには[誤差・次数・安定性](algorithms/error-order-and-stability/)へ進む。
