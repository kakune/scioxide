[近接勾配法](../composite-and-splitting/)は非滑らかな項 $g$ の近接写像を閉形式で計算できることを前提にする。
$g(Dx)$ のように線形写像を挟むと、近接写像は一般に閉形式にならない。
交互方向乗数法（ADMM）は $z=Dx$ のような新しい変数で問題を二つのブロックに分け、それぞれの部分問題を交互に解く。
このページでは $f$ と $g$ を真閉凸関数とし、収束の議論はこの仮定の下で行う。

## ADMM の変数分割

$\min f(x)+g(z)$、$Ax+Bz=c$ の拡張 Lagrange 関数は

$$
L_\rho(x,z,y)=f(x)+g(z)+y^T(Ax+Bz-c)+\frac\rho2\|Ax+Bz-c\|^2
$$

である。
$y$ は等式制約の Lagrange 乗数、$\rho>0$ はペナルティの重みである。
尺度付き双対変数 $u=y/\rho$ を使って平方完成すると、一次と二次の項が $\frac\rho2\|Ax+Bz-c+u\|^2-\frac\rho2\|u\|^2$ にまとまる。
$x$ と $z$ を交互に最小化し、双対変数を刻み $\rho$ の上昇法で更新すると、反復は

$$
\begin{aligned}
x^{k+1}&=\arg\min_x f(x)+\tfrac\rho2\|Ax+Bz^k-c+u^k\|^2,\\
z^{k+1}&=\arg\min_z g(z)+\tfrac\rho2\|Ax^{k+1}+Bz-c+u^k\|^2,\\
u^{k+1}&=u^k+Ax^{k+1}+Bz^{k+1}-c
\end{aligned}
$$

となる。
主問題の残差 $r=Ax+Bz-c$ は結合条件の違反、双対残差 $s=\rho A^TB(z^{k+1}-z^k)$ は分割に伴う停留性の欠陥を測る。
$x$ の部分問題の最適性条件 $0\in\partial f(x^{k+1})+\rho A^T(Ax^{k+1}+Bz^k-c+u^k)$ に $u^{k+1}$ を代入すると、$0\in\partial f(x^{k+1})+A^Ty^{k+1}-\rho A^TB(z^{k+1}-z^k)$ となる。
最後の項が $-s$ で、$s=0$ なら $x^{k+1}$ について元の問題の最適性条件 $0\in\partial f(x)+A^Ty$ が成り立つ。
$z$ についての条件 $0\in\partial g(z^{k+1})+B^Ty^{k+1}$ は、$z$ の部分問題の最適性条件と $u^{k+1}$ の定義から毎回成り立つ。
残る条件は結合条件 $r=0$ である。
したがって、$r$ と $s$ の一方だけが小さくても十分ではない。
$f,g$ が真閉凸で $L_0$ に鞍点があれば、$r\to0$、目的値の収束、双対変数の収束が成り立つ（Boyd ほか, 2011, 第 3.2 節）。
収束の速さは多くの場合、良くても一次収束で、$\rho$ に強く依存する。
一般の非凸問題でこの反復の収束は保証されないので、凸性の仮定が自分のモデルで成り立つかを確かめる。

## ブロック更新の API

`AdmmProblem::new(a, b, c, x_update, z_update)` は作用素 $A$（随伴付きの `AdjointOperator`）、$B$（`LinearOperator`）、右辺 $c$ と二つの `AdmmBlockUpdate` を借用する。
$A$、$B$、$c$ の行数が違えば `DimensionMismatch`、$c$ が非有限なら `NonFinite` になる。
$f$ と $g$ は部分問題の解法を通してだけ現れるので、どちらも非滑らかでよい。
更新側は `AdmmUpdateInput` のアクセサ `block()`（`AdmmBlock::X` か `Z`）、`current()`、他方の変数の最新値 `other()`、`scaled_dual()`、`rhs()`、`operator()`、`other_operator()`、`rho()` を読み、出力へ部分問題の解を書く。
戻り値は `AdmmUpdateReport::new(converged, stationarity_norm)` で作り、部分問題の解法が終わったかと、その停留条件の違反の大きさを返す。
解法はこのレポートを信じて使い、違反を自分で計算し直さない。
レポートが未収束か、違反が部分問題の許容誤差（`with_subproblem_tolerance`、既定は絶対・相対とも $\sqrt{\varepsilon}$、尺度 1）を超えると、ADMM は終了理由ではなく `InvalidInput`（`Inconsistent`）のエラーで止まる。
更新には解法の `SolveContext` が渡され、その中で入れ子の求解を行うと、その処理は ADMM の上限に数えられる。

`AdmmStart::new(x, z, u)` は $x,z,u$ の初期値を借用し、形が問題と合わなければ `DimensionMismatch`、非有限なら `NonFinite` になる。
`AdmmOptions::new(rho)` は $\rho$ と残差・部分問題の許容誤差、反復の上限を持ち、`Admm::new` は $\rho$ が正の有限値でなければ `InvalidInput` を返す。
`solve(&problem, start)` は呼び出しごとに作業領域を確保し、`AdmmWorkspace` と `AdmmResult::empty()` を `solve_into` に渡すと再利用できる。
必要量は `workspace_requirements(&problem)` が `AdmmWorkspaceRequirements` で返し、$x$ と $z$ の次元、制約の数、作用素の作業領域を含むバイト数 `bytes()` を読める。
`AdmmResult` は `x()`、`z()`、`scaled_dual()` と、残差のベクトル `primal_residual()`、`dual_residual()` を返す。
一回の反復は二つの部分問題、$A$ の積 1 回、$B$ の積 2 回、随伴 $A^T$ の積 2 回を使う。

## ADMM の停止判定とペナルティの調整

各反復で $r$ と $s$ を元の単位で計算し、Euclid ノルムで

$$
\|r\|_2\le\epsilon_{\mathrm{abs}}+\epsilon_{\mathrm{rel}}\max(\|Ax\|_2,\|Bz\|_2,\|c\|_2),\qquad
\|s\|_2\le\epsilon_{\mathrm{abs}}+\epsilon_{\mathrm{rel}}\|\rho A^Tu\|_2
$$

の両方が成り立てば `Converged` で止まる。
$r$ の各成分は $Ax$、$Bz$、$-c$ を丸める前に足し合わせるので、打ち消し合う大きな項があっても途中で桁あふれしにくい。
`AdmmOptions::new(rho)` の既定は $\epsilon_{\mathrm{abs}}=\epsilon_{\mathrm{rel}}=\sqrt{\varepsilon}$（`with_residual_tolerance` で変更）、反復の上限 1000 回（`with_max_iterations`）である。
上限に達すると `IterationLimit` で止まり、最後に受理した $x,z,u$ を返す。
`AdmmResult` の `primal_norm()` と `dual_norm()` は最後の反復の $\|r\|_2$ と $\|s\|_2$ で、最初の反復が終わる前は `None` である。
`rho()` は最後の $\rho$、`iterations()` は反復数、`is_success()` は `Converged` のときだけ真である。

$\rho$ が大きいと結合条件が強く課されて $r$ は小さくなるが、$z$ の変化が $\rho$ 倍されて $s$ が大きくなりやすい。
$\rho$ が小さいと逆に $s$ は小さく、$r$ が残る。
既定では $\rho$ を固定し、残差の均衡化は行わない。
`with_residual_balancing(ratio, factor)` を指定すると、収束しなかった反復の後で、$\|r\|>\text{ratio}\cdot\|s\|$ なら $\rho$ を `factor` 倍、$\|s\|>\text{ratio}\cdot\|r\|$ なら `factor` で割る（両方とも 1 より大きい有限の値）。
$\rho$ を変えるときは $y=\rho u$ を保つように $u$ を $\rho_{\text{旧}}/\rho_{\text{新}}$ 倍するので、尺度付き双対変数の意味は保たれる。
Boyd ほかは ratio = 10、factor = 2 を典型値として挙げている。

## 箱への射影のモデル

点 $a\in\mathbb R^8$（$a_i=-1+3i/7$、$i=0,\dots,7$）を箱 $[0,1]^8$ に射影する問題を、$f(x)=\tfrac12\|x-a\|^2$、$g$ を箱の指示関数、$x-z=0$（$A=I$、$B=-I$、$c=0$）と分けて ADMM で解く。
解析解は成分ごとの切り詰め $\operatorname{clamp}(a_i,0,1)$ である。
$x$ の部分問題は $\tfrac12\|x-a\|^2+\tfrac\rho2\|x-z+u\|^2$ の最小化で、閉形式 $x=(a+\rho(z-u))/(1+\rho)$ を持つ。
$z$ の部分問題は $x+u$ の箱への射影である。
$f$ は強凸率 1 を持つので、凸性の仮定を満たし、最小点は一つに決まる。

次の定義のブロックは二つの部分問題、作用素、設定と検算の補助関数を、続く二つのセルで共有する。
`Fit` は $x$ の更新で、停留条件 $(x-a)+\rho(x-z+u)=0$ の違反を計算して返す。
`UnitBox` は $z$ の更新で、射影は厳密なので違反 0 を返す。
$A$ と $B$ は scioxide-core の `ClosureOperator` に関数 `identity` と `negation` を渡して作る。

```rust
//| id: optimize-admm-box-model
//| kind: definitions
//| title: 箱への射影の二つの部分問題と作用素
//| crates: [scioxide-core, scioxide-optimize]
use scioxide_core::{SciOxideError, SolveContext};
use scioxide_optimize::{AdmmBlockUpdate, AdmmOptions, AdmmUpdateInput, AdmmUpdateReport};

/// 射影する点 aᵢ = −1 + 3i/7（i = 0, …, 7）。
pub(crate) fn box_target() -> Vec<f64> {
    (0..8).map(|i| -1.0 + 3.0 * i as f64 / 7.0).collect()
}

/// A = I の積。随伴も同じ関数で表す。
pub(crate) fn identity(v: &[f64], out: &mut [f64]) -> Result<(), SciOxideError> {
    out.copy_from_slice(v);
    Ok(())
}

/// B = −I の積。
pub(crate) fn negation(v: &[f64], out: &mut [f64]) -> Result<(), SciOxideError> {
    for (o, &x) in out.iter_mut().zip(v) {
        *o = -x;
    }
    Ok(())
}

/// x の部分問題 argmin ½‖x − a‖² + (ρ/2)‖x − z + u‖² = (a + ρ(z − u)) / (1 + ρ)。
pub(crate) struct Fit(pub(crate) Vec<f64>);

impl AdmmBlockUpdate<f64> for Fit {
    fn update_into(
        &self,
        input: AdmmUpdateInput<'_, f64>,
        out: &mut [f64],
        _: &mut SolveContext<'_, '_>,
    ) -> Result<AdmmUpdateReport<f64>, SciOxideError> {
        let rho = input.rho();
        let mut defect = 0.0_f64;
        let pairs = input.other().iter().zip(input.scaled_dual());
        for ((x, &a), (&z, &u)) in out.iter_mut().zip(&self.0).zip(pairs) {
            *x = (a + rho * (z - u)) / (1.0 + rho);
            // 停留条件 (x − a) + ρ(x − z + u) = 0 の違反。
            defect = defect.max(((*x - a) + rho * (*x - z + u)).abs());
        }
        Ok(AdmmUpdateReport::new(true, defect))
    }
}

/// z の部分問題: x + u の箱 [0, 1]ⁿ への射影。
pub(crate) struct UnitBox;

impl AdmmBlockUpdate<f64> for UnitBox {
    fn update_into(
        &self,
        input: AdmmUpdateInput<'_, f64>,
        out: &mut [f64],
        _: &mut SolveContext<'_, '_>,
    ) -> Result<AdmmUpdateReport<f64>, SciOxideError> {
        let pairs = input.other().iter().zip(input.scaled_dual());
        for (z, (&x, &u)) in out.iter_mut().zip(pairs) {
            *z = (x + u).clamp(0.0, 1.0);
        }
        Ok(AdmmUpdateReport::new(true, 0.0))
    }
}

/// 初期のペナルティ ρ と、残差の均衡化（ratio = 10、factor = 2）の有無から設定を作る。
pub(crate) fn admm_options(rho: f64, balanced: bool) -> AdmmOptions<f64> {
    let options = AdmmOptions::new(rho);
    if balanced {
        options.with_residual_balancing(10.0, 2.0)
    } else {
        options
    }
}

/// 独立検算: f64 の clamp で書いた射影（参照値）との差の最大。
pub(crate) fn projection_error(z: &[f64], target: &[f64]) -> f64 {
    z.iter()
        .zip(target)
        .map(|(&z, &a)| (z - a.clamp(0.0, 1.0)).abs())
        .fold(0.0, f64::max)
}
```

## ペナルティと反復数

次のセルは $\rho\in\{0.01,0.1,1,10,100\}$ と均衡化の有無の 10 通りを、零から始めて解く。
表は初期の $\rho$、均衡化の有無、反復数、終了理由、最後の $\|r\|_2$ と $\|s\|_2$、最後の $\rho$、解析解との差 $\max_i|z_i-\operatorname{clamp}(a_i,0,1)|$ を並べる。
入力はない。

```rust
//| id: optimize-admm-rho-sweep
//| ref: optimize-admm-rho-sweep
//| title: ペナルティ ρ と残差の均衡化で ADMM の反復数を比べる
//| run: reactive
//| uses: [optimize-admm-box-model]
//| crates: [scioxide-core, scioxide-optimize]
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"rho-sweep","path":"/rows/2/2","range":{"min":1,"max":1000}}
//|       - {"artifact":"rho-sweep","path":"/rows/2/3","equals":"Converged"}
//|       - {"artifact":"rho-sweep","path":"/rows/2/7","range":{"min":0,"max":1e-7}}
use scioxide_core::ClosureOperator;
use scioxide_optimize::{Admm, AdmmProblem, AdmmStart};
let target = box_target();
let n = target.len();
let a = ClosureOperator::new(n, n, identity).with_adjoint(identity);
let b = ClosureOperator::new(n, n, negation);
let zero = vec![0.0; n];
let fit = Fit(target.clone());
let problem = AdmmProblem::new(&a, &b, &zero, &fit, &UnitBox).map_err(|e| e.to_string())?;
let mut rows = Vec::new();
for balanced in [false, true] {
    for exponent in -2..=2 {
        let rho = 10.0_f64.powi(exponent);
        let result = Admm::new(admm_options(rho, balanced))
            .map_err(|e| e.to_string())?
            .solve(&problem, AdmmStart::new(&zero, &zero, &zero))
            .map_err(|e| e.to_string())?;
        rows.push((
            rho,
            if balanced { "あり" } else { "なし" },
            result.iterations(),
            result.termination().to_string(),
            result.primal_norm(),
            result.dual_norm(),
            result.rho(),
            projection_error(result.z(), &target),
        ));
    }
}
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let general3 = serde_json::json!({ "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "初期の ρ [-]", "type": "number", "format": general3 },
    { "key": "1", "label": "均衡化" },
    { "key": "2", "label": "反復 [回]", "type": "integer" },
    { "key": "3", "label": "終了理由" },
    { "key": "4", "label": "主問題の残差 ‖r‖₂ [-]", "type": "number", "format": sci3, "nullText": "未計算" },
    { "key": "5", "label": "双対残差 ‖s‖₂ [-]", "type": "number", "format": sci3, "nullText": "未計算" },
    { "key": "6", "label": "最後の ρ [-]", "type": "number", "format": general3 },
    { "key": "7", "label": "解析解との差 [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "rho-sweep" })
);
```

$\rho$ を固定すると、$\rho=1$ が 27 回で最も少なく、$\rho=0.1$ と $\rho=10$ はそれぞれ 184 回と 177 回かかる。
$\rho=0.01$ と $\rho=100$ は 1000 回の上限で `IterationLimit` になる。
ただし、二つの止まり方は逆である。
$\rho=0.01$ では $z$ が 8 回の反復で解析解に一致して動かなくなり、$s=\rho(z^{k+1}-z^k)$ は 0 になるが、$x$ が $a$ に引かれて $\|r\|_2=7.8\times10^{-5}$ が残る。
$\rho=100$ では $x=z$ が成り立って $\|r\|_2=0$ になるが、$z$ の変化が 100 倍されて $\|s\|_2=3.7\times10^{-5}$ が残り、$z$ も解析解から $3.4\times10^{-5}$ ずれている。
$\rho=0.01$ の $z$ は `IterationLimit` でも解析解に一致しているので、終了理由だけでは解の精度は分からず、二つの残差と独立な検算を併せて読む。

均衡化を有効にすると、どの初期値でも 14〜32 回で `Converged` になる。
$\rho=0.01$ から始めると主問題の残差が双対残差の 10 倍を超えるたびに $\rho$ が 2 倍になり、最後の $\rho$ は $0.01\times2^{13}=81.92$ である。
$\rho=100$ から始めると $\rho$ が半分ずつ下がり、最後は 0.78 になる。
$\rho=1$ では二つの残差の比が 10 を超えないので $\rho$ は変わらず、固定の場合と同じ 27 回になる。

## 残差の履歴

次のセルは選んだ初期の $\rho$ と均衡化の有無で、$\|r_k\|_2$ と $\|s_k\|_2$ と、それぞれの停止の閾値（破線）を反復ごとに描く。
履歴は反復の上限を 1 にした `solve_into` を、前の結果の $x,z,u,\rho$ から始め直して一回ずつ進めて記録する。
作業領域 `AdmmWorkspace` と結果 `AdmmResult` は呼び出しの間で使い回す。
同じ設定を一度に解いた結果と反復数と $z$ を比べ、一回ずつ再開しても同じ反復になることを確かめる。
最後に、一度に解いた結果の終了状態を判定として示す。

```rust
//| id: optimize-admm-residual-history
//| ref: optimize-admm-residual-history
//| title: ADMM の主問題の残差と双対残差の履歴をペナルティ ρ ごとに描く
//| run: reactive
//| uses: [optimize-admm-box-model]
//| crates: [scioxide-core, scioxide-optimize]
//| inputs:
//|   log_rho: {"type":"range","label":"初期のペナルティ log₁₀ ρ [-]","min":-2,"max":2,"step":0.5,"value":0}
//|   balancing: {"type":"checkbox","label":"残差の均衡化（ratio = 10、factor = 2）","value":false}
//| cases:
//|   - {"id":"small-rho","label":"ρ = 0.01","description":"双対残差は小さいまま、主問題の残差がゆっくり減る。","inputs":{"log_rho":-2}}
//|   - {"id":"large-rho","label":"ρ = 100","description":"主問題の残差はすぐ小さくなるが、双対残差がゆっくり減る。","inputs":{"log_rho":2}}
//|   - {"id":"balanced-large-rho","label":"ρ = 100 と均衡化","description":"双対残差が主問題の残差の 10 倍を超えるたびに ρ を半分にする。","inputs":{"log_rho":2,"balancing":true}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|       - {"path":"/outputs/1/diagnostics/0/value","equals":27}
//|       - {"path":"/outputs/1/diagnostics/4/value","equals":0}
//|   - case: small-rho
//|     expect:
//|       - {"path":"/outputs/1/state","equals":"partial"}
//|   - case: large-rho
//|     expect:
//|       - {"path":"/outputs/1/state","equals":"partial"}
//|   - case: balanced-large-rho
//|     expect:
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
use scioxide_core::{Budget, ClosureOperator, ExecutionContext, RealScalar};
use scioxide_optimize::{Admm, AdmmProblem, AdmmResult, AdmmStart, AdmmWorkspace};
let target = box_target();
let n = target.len();
let a = ClosureOperator::new(n, n, identity).with_adjoint(identity);
let b = ClosureOperator::new(n, n, negation);
let zero = vec![0.0; n];
let fit = Fit(target.clone());
let problem = AdmmProblem::new(&a, &b, &zero, &fit, &UnitBox).map_err(|e| e.to_string())?;
let rho = RealScalar::powf(10.0, log_rho);
let full = Admm::new(admm_options(rho, balancing))
    .map_err(|e| e.to_string())?
    .solve(&problem, AdmmStart::new(&zero, &zero, &zero))
    .map_err(|e| e.to_string())?;
let mut workspace = AdmmWorkspace::new();
let mut step = AdmmResult::empty();
let (mut x, mut z, mut u, mut current) = (zero.clone(), zero.clone(), zero.clone(), rho);
let (mut primal, mut dual, mut primal_limit, mut dual_limit) =
    (Vec::new(), Vec::new(), Vec::new(), Vec::new());
let norm = |v: &[f64]| RealScalar::sqrt(v.iter().map(|t| t * t).sum::<f64>());
let tolerance = RealScalar::sqrt(f64::EPSILON);
for k in 1..=full.iterations() {
    // 反復の上限を 1 にして、前の結果の x, z, u, ρ から一回だけ進める。
    Admm::new(admm_options(current, balancing).with_max_iterations(Budget::ONE))
        .map_err(|e| e.to_string())?
        .solve_into(
            &problem,
            AdmmStart::new(&x, &z, &u),
            &mut step,
            &mut workspace,
            ExecutionContext::sequential_native(),
        )
        .map_err(|e| e.to_string())?;
    let k = k as f64;
    primal.push([k, step.primal_norm().ok_or("主問題の残差がない")?]);
    dual.push([k, step.dual_norm().ok_or("双対残差がない")?]);
    // 閾値 ε_abs + ε_rel·max(‖x‖, ‖z‖) と ε_abs + ε_rel·‖ρu‖（ρu は均衡化で変わらない）。
    primal_limit.push([
        k,
        tolerance + tolerance * norm(step.x()).max(norm(step.z())),
    ]);
    dual_limit.push([
        k,
        tolerance + tolerance * step.rho() * norm(step.scaled_dual()),
    ]);
    x.copy_from_slice(step.x());
    z.copy_from_slice(step.z());
    u.copy_from_slice(step.scaled_dual());
    current = step.rho();
}
// 0 の残差は対数軸に描けないので除き、件数を判定に示す。
let removed = primal.iter().chain(&dual).filter(|p| p[1] <= 0.0).count();
primal.retain(|p| p[1] > 0.0);
dual.retain(|p| p[1] > 0.0);
emit_line_chart!(
    &vec![
        serde_json::json!({ "name": "主問題の残差 ‖r‖₂", "points": primal, "style": { "showSymbol": true } }),
        serde_json::json!({ "name": "双対残差 ‖s‖₂", "points": dual, "style": { "showSymbol": true } }),
        serde_json::json!({
            "name": "主問題の残差の閾値",
            "points": primal_limit,
            "style": { "lineType": "dashed" }
        }),
        serde_json::json!({
            "name": "双対残差の閾値",
            "points": dual_limit,
            "style": { "lineType": "dashed" }
        })
    ],
    options = &serde_json::json!({
        "xLabel": "反復 k [回]",
        "yLabel": "残差のノルム [-]",
        "yType": "log"
    })
);
let chain_gap = z
    .iter()
    .zip(full.z())
    .map(|(a, b)| (a - b).abs())
    .fold(0.0_f64, f64::max);
let primal_norm = full.primal_norm().ok_or("主問題の残差がない")?;
let dual_norm = full.dual_norm().ok_or("双対残差がない")?;
let outcome = if full.is_success() {
    Outcome::satisfied("主問題の残差と双対残差の両方が閾値を下回った")
} else {
    Outcome::partial("残差が閾値を下回る前に反復の上限に達した")
        .explanation("返された x と z は最後に受理した反復で、射影の推定値として扱う。")
};
emit_outcome!(
    outcome
        .status(full.termination().to_string())
        .diagnostic("反復", full.iterations() as f64, None)
        .diagnostic("主問題の残差", primal_norm, None)
        .diagnostic("双対残差", dual_norm, None)
        .diagnostic("解析解との差", projection_error(full.z(), &target), None)
        .diagnostic("一回ずつ進めた z との差", chain_gap, None)
        .diagnostic("対数軸から除いた点", removed as f64, None)
);
```

既定の $\rho=1$ では、二つの残差がほぼ同じ速さで一次収束して 27 回で閾値を下回り、判定は satisfied になる。
一回ずつ再開した反復の $z$ は、一度に解いた $z$ と完全に一致する。
$\rho=0.01$ では双対残差が 9 回目から 0 になるので、対数軸には最初の 8 点しか描けず、主問題の残差は閾値の上でゆっくり下がる。
$\rho=100$ では逆に主問題の残差が 36 回目から 0 になり、双対残差が閾値の上に残る。
除いた点の数は判定の「対数軸から除いた点」に出る。
均衡化を有効にして $\rho=100$ から始めると、双対残差が主問題の残差の 10 倍を超えるたびに $\rho$ が半分になり、残差の釣り合いが取れたところで両方が閾値を下回る。

## まとめ

近接写像が閉形式にならない項は、$z=Dx$ のように変数を分けると、二つの部分問題を交互に最小化して扱える。
停止は主問題の残差と双対残差の両方で判定され、一方だけが小さい状態は収束ではない。
ペナルティ $\rho$ が小さすぎると主問題の残差が、大きすぎると双対残差が残るので、反復数が多いときは二つの残差の比を見て $\rho$ を変えるか `with_residual_balancing` を使う。
部分問題の解法は `AdmmUpdateReport` で停留条件の違反を正直に返し、許容誤差を超えると ADMM はエラーで止まる。
`IterationLimit` でも最後の $x,z,u$ は返るので、残差と独立な検算で精度を確かめてから使う。
