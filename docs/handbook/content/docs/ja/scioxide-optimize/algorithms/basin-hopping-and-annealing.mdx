basin hopping と dual annealing は、現在の点から次の候補を作り、確率的な規則で受理するかを決める連鎖（chain）で大域探索を行う。
どちらも悪化する候補をある確率で受理するので、浅い谷から抜け出せる。
受理の規則は統計力学の Metropolis 法に由来し、温度と呼ぶ母数が悪化の受理しやすさを決める。
このページでは二つの方法の手順と温度の意味を導き、SciOxide の `BasinHopping` と `DualAnnealing` の設定と結果を、二次元 Rastrigin 関数で確かめる。
どちらも大域最適性を主張せず、連鎖の段を使い切った終了は成功ではない `SearchBudgetCompleted` である。

## basin hopping

basin hopping（Wales と Doye, 1997）は、目的関数 $f$ の代わりに、各点を局所最小化した値

$$
\tilde f(\mathbf{x}) = f\bigl(\operatorname{LocalMin}(\mathbf{x})\bigr)
$$

の上で連鎖を進める。
$\tilde f$ は吸引域ごとに一定の値を取る階段状の関数になり、吸引域の中の細かい凹凸が消える。
一段の手順は次のとおりである。

1. 現在の局所解 $\mathbf{x}_k$ を変位させて候補の開始点 $\mathbf{y}$ を作る。
2. $\mathbf{y}$ から局所ソルバーで最小化し、局所解 $\mathbf{x}'$ とその値 $f' = f(\mathbf{x}')$ を得る。
3. $\Delta = f' - f(\mathbf{x}_k)$ として、確率 $\min(1, e^{-\Delta/T})$ で $\mathbf{x}_{k+1} = \mathbf{x}'$ とし、受理しなければ $\mathbf{x}_{k+1} = \mathbf{x}_k$ とする。

3 の受理規則が Metropolis 則で、温度 $T$ は目的値と同じ単位を持つ。
$\Delta \le 0$ の候補は常に受理し、悪化する候補は $\Delta$ が $T$ の数倍を超えるとほとんど受理しない。
$T = 0$ では悪化する候補を受理しない単調な basin hopping になる。
$T$ は局所解どうしの目的値の差の典型的な大きさに合わせて選ぶ。
小さすぎると最初の谷の近くから出られず、大きすぎると深い谷にとどまらずに無作為な探索に近づく。

SciOxide の `BasinHopping` は 0 段目で `x0` から局所最小化し、その結果を連鎖の最初の点にする。
1 段目以降は、`BasinProposal` が現在の点から変位させた開始点を作り、局所ソルバーで最小化して Metropolis 則で受理を決める。
局所求解がエラーで終わった段は候補を持たず、現在の点を置き換えない。
連鎖は逐次なので、`BasinHopping::new` は逐次でない実行方針を `InvalidInput` で拒む。
一段の計算コストは一回の局所求解である。

`UniformBasinProposal::new(step)` は、各座標を $[-\mathrm{step}, \mathrm{step}]$ の一様乱数に箱の幅を掛けた量だけ独立に動かし、箱の外へ出た分を端で折り返す。
`step` が NaN、無限大、0 以下なら `InvalidInput` である。
別の変位は `BasinProposal` を実装して与える。
実装は乱数を渡された `SearchRandom` からだけ引き、箱の中の点を書く必要があり、箱の外の点を返すと探索が `InvalidInput` で止まる。

## dual annealing

焼きなまし法（simulated annealing）は、温度を少しずつ下げながら Metropolis 則で候補を受理する。
温度が高いうちは悪化も受理して広く動き、低くなると谷の底にとどまる。
dual annealing（Xiang ら, 1997）は、Tsallis と Stariolo の一般化焼きなまし（generalized simulated annealing）に局所最適化を組み合わせた方法である。

### 訪問分布と冷却

座標を箱の中で $[0, 1)$ へ正規化し、変位を訪問分布（visiting distribution）から引く。
一般化焼きなましの訪問分布は、指数 $q_v \in (1, 3)$ の Tsallis の $q$-Gauss 分布で、一座標の密度は

$$
g(\Delta) \propto \left[1 + (q_v - 1)\frac{\Delta^2}{T^{2/(3-q_v)}}\right]^{-1/(q_v-1)}
$$

である。
これは自由度 $\nu = (3 - q_v)/(q_v - 1)$ の Student の $t$ 分布を、尺度 $T^{1/(3-q_v)}/\sqrt{3 - q_v}$ に伸ばしたものと同じで、SciOxide はこの $t$ 分布から変位を引く。
$\nu$ が小さいほど裾が重く、ときどき大きく跳ぶので、遠い谷へ移れる。
既定の $q_v = 2.62$ では $\nu \approx 0.23$ である。
変位を足した座標が $[0, 1)$ の外へ出ると、反対側から入る周期的な巻き戻しを行う。

訪問の温度は、掃引の番号 $k = 0, 1, 2, \dots$ に対して

$$
T(k) = T_0 \, \frac{2^{q_v - 1} - 1}{(k + 2)^{q_v - 1} - 1}
$$

で下がる。
$T(0) = T_0$ で、$k$ が大きいと $T(k) \approx T_0 (2^{q_v-1} - 1) k^{-(q_v-1)}$ のように冪で減る。
一つの掃引は $n$ 変数に対して $2n$ 段で、前半の $n$ 段は全座標を、後半の $n$ 段は 1 座標ずつを動かす。

### 一般化 Metropolis 則と再加熱

悪化する候補（$\Delta > 0$）は、受理の指数 $q_a < 1$ の一般化 Metropolis 則の確率

$$
p = \left[1 - (1 - q_a)\frac{\Delta}{T_a}\right]^{1/(1 - q_a)}, \qquad T_a = \frac{T(k)}{k + 1}
$$

で受理し、$1 - (1-q_a)\Delta/T_a \le 0$ なら受理しない。
$q_a \to 1$ の極限で通常の $e^{-\Delta/T_a}$ に戻る。
$q_a < 1$ では受理の確率が有限の $\Delta$ で 0 になるので、大きな悪化を確実に退ける。
受理の温度 $T_a$ は訪問の温度をさらに $k + 1$ で割ったもので、訪問より速く冷える。

$T(k)$ が $T_0$ に再加熱の比 $r$ を掛けた値以下になると、連鎖は箱の中の一様な点から温度 $T_0$ で再び始める（再加熱、reannealing）。
再加熱した段の点は受理の判定をせずに連鎖の現在の点にする。
既定の $q_v = 2.62$ と $r = 2 \times 10^{-5}$ では、$(k + 2)^{1.62} \ge (2^{1.62} - 1)/r$ から $k \approx 1245$ 掃引、2 変数なら約 5000 段で再加熱する。

### 局所最適化

局所最適化を有効にすると、最初の点、それまでの最良値を下回った点、再加熱した点を局所ソルバーで最小化する。
局所解の値が焼きなましの点の値以下なら、それを候補にする。
局所求解が失敗したか値が高かった場合は、焼きなましの点をそのまま候補に残す。
一段の計算コストは目的の評価 1 回と、局所最適化のための求解である。

## basin hopping・dual annealingの設定と結果

`BasinHoppingOptions::new(multistart, temperature)` は `GlobalSearchOptions` と Metropolis 温度を受け取り、温度が NaN、無限大、負なら `InvalidInput` を返す。
`DualAnnealingOptions::new(multistart)` と `default()`（`GlobalSearchOptions::default()` から作る）は、$T_0 = 5230$、$q_v = 2.62$、$q_a = -5$、$r = 2 \times 10^{-5}$、局所最適化ありである。
`with_schedule(T₀, q_v, q_a, r)` は値を検査せずに置き、`DualAnnealing::new(options, factory)` が非有限の値、$T_0 \le 0$、$(1, 3)$ の外の $q_v$、$q_a \ge 1$、$(0, 1)$ の外の $r$ を `InvalidInput` で拒む。
`with_local_search(false)` で局所最適化を止める。

どちらの方法でも、連鎖の段数は `GlobalSearchOptions::with_starts` で決まり、0 段目を含む。
既定は 10 段で、2 変数の dual annealing では 1 回の掃引が 4 段なので、0 段目のあとの 9 段は 2 回余りの掃引にしかならない。
そのため通常は段数を明示する。
`BasinHopping::new(options, proposal, factory)` と `DualAnnealing::new(options, factory)` は、`GlobalSearchOptions` の極小点をまとめる許容誤差が有限で正でない場合と、逐次でない実行方針を `InvalidInput` で拒む。
局所ソルバーの factory は [複数開始点法](oxref:optimize-local-solver-injection)と同じ `LocalSolverFactory` を使う。

`minimize_into(problem, x0, output, workspace, scope)` と `minimize(problem, x0)` が連鎖を `x0` から実行する。
`x0` が有限で箱の中になければ `InvalidInput` である。
dual annealing では、訪問した点で目的が NaN か無限大を返すと `NonFinite`、訪問の変位が桁あふれすると `NumericalInstability` になる。

結果は複数開始点法と同じ `GlobalSearchResult` で、各段の `SearchStartReport` を持つ。
`accepted()` はその段の候補が連鎖の現在の点になったか、`temperature()` はその段の温度（basin hopping では一定の $T$、dual annealing では訪問の温度 $T(k)$）、`reannealed()` はその段で再加熱したかを返す。
dual annealing の `candidate()` は焼きなましの点と局所解の低いほう、`local_result()` は局所求解の結果である。
`best()` は全段の候補の最良点で、連鎖の段を使い切った終了は `SearchBudgetCompleted` である。

## Rastrigin 関数と注入する局所ソルバー

二次元 Rastrigin 関数

$$
f(x, y) = 2A + \bigl(x^2 - A\cos 2\pi x\bigr) + \bigl(y^2 - A\cos 2\pi y\bigr), \qquad (x, y) \in [-5.12, 5.12]^2
$$

は、$A = 10$ のとき原点に大域的最小点 $f = 0$ を持ち、整数の格子点の近くに局所解が並ぶ。
格子点 $(i, j)$ の近くの局所解の値はおよそ $i^2 + j^2$ なので、隣り合う局所解の値の差は 1 から 9 程度である。
勾配は $\partial f/\partial x = 2x + 2\pi A \sin 2\pi x$ で、$y$ も同じ形である。

次の定義のブロックはこの関数を解析的な勾配付きで定義し、[複数開始点法](../multistart/)と同じ形で L-BFGS-B を局所ソルバーとして注入する factory を実装する。
二つのセルはどちらも格子点 $(4, -3)$ の近くの局所解 $\mathbf{x}_0 = (3.97978, -2.98486)$（$f = 24.87$）を `x0` にする。
この点は Newton 法で $\partial f/\partial x = \partial f/\partial y = 0$ を解いて求めた値で、局所ソルバーはここから動かないので、連鎖は変位や訪問で谷を移らなければ先へ進めない。
表の「最小値に初めて達した段」は、候補の目的値が初めて $10^{-8}$ を下回った段で、大域的最小点の谷に入ったことを既知の最小値 0 で確かめる。

```rust
//| id: optimize-chain-rastrigin-model
//| kind: definitions
//| title: 二次元 Rastrigin 関数と L-BFGS-B を注入する局所ソルバーの factory
//| crates: [scioxide-core, scioxide-optimize]
use scioxide_core::{SciOxideError, RealScalar, SolveContext};
use scioxide_optimize::{
    BoundedObjective, GlobalSearchResult, LbfgsB, LbfgsBWorkspace, LocalSolverFactory,
    ObjectiveFunction, OptimizeResult, SearchLocalSolver,
};

/// 凹凸の強さ A。
pub(crate) const AMPLITUDE: f64 = 10.0;

/// 格子点 (4, −3) の近くの局所解。Newton 法で勾配を 0 にした値で、f = 24.87。
pub(crate) const START: [f64; 2] = [3.9797838603007536, -2.984855701039481];

/// 候補の目的値が初めて 1e-8 を下回った段。大域的最小値 0 に達したかの検算に使う。
pub(crate) fn first_hit(result: &GlobalSearchResult<f64>) -> Option<usize> {
    result
        .starts()
        .iter()
        .position(|r| r.candidate().is_some_and(|c| c.fun() < 1e-8))
}

/// Rastrigin 関数 f = 2A + Σ (x_j² − A cos 2πx_j) と、その解析的な勾配。
pub(crate) struct Rastrigin;
impl ObjectiveFunction<f64> for Rastrigin {
    fn dim(&self) -> usize {
        2
    }
    fn eval(&self, x: &[f64]) -> Result<f64, SciOxideError> {
        let tau = std::f64::consts::TAU;
        Ok(x.iter()
            .map(|&v| AMPLITUDE + v * v - AMPLITUDE * RealScalar::cos(tau * v))
            .sum())
    }
    fn gradient_into(&self, x: &[f64], out: &mut [f64]) -> Result<bool, SciOxideError> {
        let tau = std::f64::consts::TAU;
        for (g, &v) in out.iter_mut().zip(x) {
            *g = 2.0 * v + tau * AMPLITUDE * RealScalar::sin(tau * v);
        }
        Ok(true)
    }
}

/// 注入する局所ソルバーの factory。探索は段ごとに用意したソルバーを使う。
#[derive(Debug)]
pub(crate) struct LbfgsBFactory;
pub(crate) struct LbfgsBLocal {
    solver: LbfgsB<f64>,
    work: LbfgsBWorkspace<f64>,
}
impl LocalSolverFactory<f64> for LbfgsBFactory {
    type Solver = LbfgsBLocal;
    fn prepare(&self, dimension: usize) -> Result<LbfgsBLocal, SciOxideError> {
        let solver = LbfgsB::default();
        let work = solver.workspace(dimension)?;
        Ok(LbfgsBLocal { solver, work })
    }
}
impl SearchLocalSolver<f64> for LbfgsBLocal {
    fn minimize_into(
        &mut self,
        problem: &BoundedObjective<'_, f64>,
        start: &[f64],
        _: u64,
        output: &mut OptimizeResult<f64>,
        context: &mut SolveContext<'_, '_>,
    ) -> Result<(), SciOxideError> {
        self.solver
            .minimize_into(problem, start, output, &mut self.work, context)
    }
}
```

### basin hopping の温度とステップ幅

このセルは `BasinHopping` を 60 段走らせ、Metropolis 温度 $T$、変位のステップ幅（箱の幅に対する割合）、シードを変える。
図は各段の局所解の値（記号）と連鎖の現在の値（階段）で、受理した悪化は現在の値が上がる段として見える。
表は受理した段の数、悪化を受理した段の数、最良の目的値、原点までの距離、目的の評価の回数である。
原点までの距離と既知の最小値 0 が独立な検算になる。

```rust
//|   step: {"type":"range","label":"ステップ幅 [箱の幅に対する割合]","description":"各座標の一様な変位の最大値。","min":0.02,"max":0.5,"step":0.02,"value":0.1}

//|   - case: default

let bounds = Bounds::new(vec![(Some(-5.12), Some(5.12)); 2]).map_err(|e| e.to_string())?;
let problem = BoundedObjective::new(&Rastrigin, &bounds).map_err(|e| e.to_string())?;
let hops = Budget::try_from(60).map_err(|e| e.to_string())?;
let search = GlobalSearchOptions::default()
    .with_starts(hops)
    .with_seed(hop_seed.round() as u64);
let options = BasinHoppingOptions::new(search, temperature).map_err(|e| e.to_string())?;
let proposal = UniformBasinProposal::new(step).map_err(|e| e.to_string())?;
let method = BasinHopping::new(options, proposal, LbfgsBFactory).map_err(|e| e.to_string())?;
```

既定の $T = 2$、ステップ幅 0.1（各座標 $\pm 1.02$）、シード 42 では、59 回の候補のうち 25 回を受理し、そのうち 7 回は悪化の受理だった。
17 段目で最小値 0 の谷に入り、最良点は原点から $9.3 \times 10^{-10}$ の距離にある。
$T = 0$ では悪化を受理せず、受理した段は 8 回に減るが、このシードでは同じ 17 段目で最小値に達する。
$T = 20$ では 51 回を受理し、そのうち 20 回が悪化の受理で、谷の間をさまよう。
60 段では最小値に達せず、最良値は原点の隣の局所解の 0.995 にとどまる。
局所解どうしの値の差が 1 から 9 程度の地形では、$T$ をこれより十分大きくすると受理が無差別になる。
ステップ幅を 0.02（$\pm 0.2$）に縮めると、変位は格子の間隔 1 より小さくなり、60 段の最良値は 0.995 で最小値に達しない。
シードを 100 にすると 6 段目で最小値に達し、1 にすると 60 段では達しない。
一本の連鎖の結果は乱数列に大きく依存する。

### dual annealing の温度の予定と再加熱

このセルは `DualAnnealing` を、段数、訪問の指数 $q_v$、再加熱の比 $r$、シードを変えて走らせる。
$T_0 = 5230$ と $q_a = -5$ は既定値のままにする。
上の図は各段で示された訪問の温度（記号）と、上の式から独立に計算した予定（破線）で、横線は再加熱のしきい値 $T_0 r$ である。
下の図はそれまでの最良の目的値で、二つの図の横軸は連動する。
表は再加熱の回数、局所最適化の回数、最良の目的値、原点までの距離、示された温度と式の最大の相対差である。

```rust
//| id: optimize-dual-annealing-schedule
//| ref: optimize-dual-annealing-schedule
//| title: 訪問の指数と再加熱の比を変えて dual annealing の温度の予定を見る
//| run: reactive
//| uses: [optimize-chain-rastrigin-model]
//| crates: [scioxide-core, scioxide-optimize]
//| inputs:
//|   anneal_steps: {"type":"range","label":"連鎖の段数 [段]","description":"0 段目を含む連鎖の長さ。2 変数では 4 段で 1 掃引。","min":40,"max":2000,"step":40,"value":400}
//|   visit: {"type":"range","label":"訪問の指数 q_v [-]","description":"大きいほど訪問分布の裾が重く、温度の下がり方も速い。","min":1.5,"max":2.9,"step":0.02,"value":2.62}
//|   restart: {"type":"select","label":"再加熱の比 r [-]","options":["2×10⁻⁵（既定）","10⁻³","10⁻²"],"value":"10⁻²"}
//|   anneal_seed: {"type":"range","label":"乱数のシード [-]","description":"訪問、受理判定、再加熱の点の乱数列を変える。","min":1,"max":100,"step":1,"value":42}
//| cases:
//|   - {"id":"default-restart","label":"r = 2×10⁻⁵","description":"既定の比では 400 段の間に再加熱せず、温度は冪で下がり続ける。","inputs":{"restart":"2×10⁻⁵（既定）"}}
//|   - {"id":"heavy-tail","label":"q_v = 2.9","description":"訪問分布の裾が重くなり、温度も速く下がって再加熱が増える。このシードでは 316 段で最小値に達する。","inputs":{"visit":2.9}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"anneal","path":"/rows/0/0","equals":"SearchBudgetCompleted"}
//|       - {"artifact":"anneal","path":"/rows/0/1","equals":3}
//|       - {"artifact":"anneal","path":"/rows/0/6","range":{"min":0,"max":1e-12}}
//|       - {"path":"/outputs/3/state","equals":"partial"}
//|   - case: default-restart
//|     expect:
//|       - {"artifact":"anneal","path":"/rows/0/1","equals":0}
//|   - case: heavy-tail
//|     expect:
//|       - {"artifact":"anneal","path":"/rows/0/3","range":{"min":1,"max":400}}
use scioxide_core::RealScalar;
use scioxide_core::{Bounds, Budget, EvaluationRole};
use scioxide_optimize::{
    BoundedObjective, DualAnnealing, DualAnnealingOptions, GlobalSearchOptions,
};

let ratio = match restart.as_str() {
    "10⁻³" => 1e-3,
    "10⁻²" => 1e-2,
    _ => 2e-5,
};
let initial = 5230.0;
let bounds = Bounds::new(vec![(Some(-5.12), Some(5.12)); 2]).map_err(|e| e.to_string())?;
let problem = BoundedObjective::new(&Rastrigin, &bounds).map_err(|e| e.to_string())?;
let steps = Budget::try_from(anneal_steps.round() as usize).map_err(|e| e.to_string())?;
let search = GlobalSearchOptions::default()
    .with_starts(steps)
    .with_seed(anneal_seed.round() as u64);
let options = DualAnnealingOptions::new(search).with_schedule(initial, visit, -5.0, ratio);
let method = DualAnnealing::new(options, LbfgsBFactory).map_err(|e| e.to_string())?;
let result = method
    .minimize(&problem, &START)
    .map_err(|e| e.to_string())?;

// 独立な検算: 掃引 k を 2n = 4 段ごとに進め、T(k) が T₀ r 以下なら k = 0 に戻して T₀ とする。
let schedule = |k: usize| {
    let power = visit - 1.0;
    initial * (RealScalar::powf(2.0, power) - 1.0)
        / (RealScalar::powf(k as f64 + 2.0, power) - 1.0)
};
let mut sweep = 0;
let mut deviation: f64 = 0.0;
let mut reported = Vec::new();
let mut expected = Vec::new();
let mut best_so_far = Vec::new();
let mut best = f64::INFINITY;
for (index, report) in result.starts().iter().enumerate() {
    if index > 0 && (index - 1) % 4 == 0 {
        sweep += 1;
    }
    let mut planned = schedule(sweep);
    if planned <= initial * ratio {
        sweep = 0;
        planned = initial;
    }
    let t = report.temperature().ok_or("温度が示されていない")?;
    deviation = deviation.max((t - planned).abs() / planned);
    reported.push([index as f64, t]);
    expected.push([index as f64, planned]);
    if let Some(candidate) = report.candidate() {
        best = best.min(candidate.fun());
    }
    best_so_far.push([index as f64, best]);
}
let last = anneal_steps.round();
emit_chart!(
    serde_json::json!({
        "kind": "xy",
        "dataZoom": true,
        "tooltip": true,
        "link": { "group": "anneal-step" },
        "xLabel": "段 [-]",
        "yLabel": "訪問の温度 T [-]",
        "yType": "log",
        "xMin": 0.0,
        "xMax": last,
        "layers": [
            {
                "id": "planned",
                "kind": "line",
                "name": "式の予定",
                "points": expected,
                "style": { "lineType": "dashed", "showSymbol": false }
            },
            {
                "id": "reported",
                "kind": "scatter",
                "name": "示された温度",
                "points": reported,
                "style": { "symbol": "circle" }
            }
        ],
        "annotations": [
            { "kind": "line", "axis": "y", "value": initial * ratio, "label": "再加熱のしきい値 T₀ r" }
        ]
    }),
    metadata = serde_json::json!({ "id": "temperature" })
);
emit_line_chart!(
    &vec![
        serde_json::json!({ "name": "それまでの最良値", "points": best_so_far, "style": { "step": "end" } })
    ],
    options = &serde_json::json!({
        "xLabel": "段 [-]",
        "yLabel": "最良の目的値 [-]",
        "xMin": 0.0,
        "xMax": last,
        "link": { "group": "anneal-step" }
    })
);
let reanneals = result.starts().iter().filter(|r| r.reannealed()).count();
let refinements = result
    .starts()
    .iter()
    .filter(|r| r.local_result().is_some())
    .count();
let point = result.best().ok_or("候補がない")?;
let distance = point.x()[0].hypot(point.x()[1]);
let evaluations = result
    .counts()
    .total()
    .map_err(|e| e.to_string())?
    .provider(EvaluationRole::Objective);
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "終了理由" },
        { "key": "1", "label": "再加熱 [回]", "type": "integer" },
        { "key": "2", "label": "局所最適化 [回]", "type": "integer" },
        { "key": "3", "label": "最小値に初めて達した段 [段]", "type": "integer", "nullText": "達していない" },
        { "key": "4", "label": "最良の目的値 [-]", "type": "number", "format": sci3 },
        { "key": "5", "label": "原点までの距離 [-]", "type": "number", "format": sci3 },
        { "key": "6", "label": "温度と式の最大の相対差 [-]", "type": "number", "format": sci3 },
        { "key": "7", "label": "目的の評価 [回]", "type": "integer" }
    ]),
    vec![(
        result.termination().to_string(),
        reanneals,
        refinements,
        first_hit(&result),
        point.fun(),
        distance,
        deviation,
        evaluations
    )],
    metadata = serde_json::json!({ "id": "anneal" })
);
emit_outcome!(
    Outcome::partial("連鎖の段を使い切った。最良点は大域的最小点の候補である")
        .status(result.termination().to_string())
        .diagnostic("最良の目的値", point.fun(), None)
        .diagnostic("再加熱", reanneals as f64, None)
        .diagnostic("温度と式の最大の相対差", deviation, None)
);
```

既定の入力（400 段、$q_v = 2.62$、$r = 10^{-2}$、シード 42）では、示された訪問の温度は式の予定と相対差 $8.4 \times 10^{-16}$ で一致し、3 回再加熱した。
温度は再加熱のたびに $T_0$ へ戻るので、図はのこぎりの歯の形になる。
局所最適化は最初の点、最良値の更新、再加熱で合わせて 6 回走り、最良値は隣の局所解の 0.995 で、400 段では最小値 0 に達しなかった。

訪問の尺度 $T^{1/(3-q_v)}/\sqrt{3 - q_v}$ は、$q_v = 2.62$ では $T \approx 0.8$ まで下がらないと 1（箱の幅）を下回らない。
$r = 10^{-2}$ のしきい値は $T_0 r = 52.3$ なので、この入力の訪問はずっと箱の中でほぼ一様であり、探索は一様な訪問と局所最適化の組み合わせに近い。
既定の $r = 2 \times 10^{-5}$ では 400 段の間に再加熱せず、温度は冪で下がり続ける。
$q_v = 2.9$ では温度が速く下がって 5 回再加熱し、このシードでは 316 段目で最小値に達する。
局所最適化の回数が少ないうちは、最小値の谷に入れるかどうかが訪問の乱数に左右される。

## まとめ

basin hopping は局所解を変位させて局所最小化し、目的値の差を温度 $T$ と比べる Metropolis 則で受理するので、$T$ は局所解どうしの値の差に合わせて選ぶ。
dual annealing は裾の重い訪問分布で遠くへ跳び、温度を冪で下げ、しきい値で再加熱し、最初の点と最良点を局所最適化する。
どちらも逐次の連鎖で、段数は `GlobalSearchOptions::with_starts` で決まり、既定の 10 段では足りないことが多い。
各段の `SearchStartReport` の `accepted()`、`temperature()`、`reannealed()` から、連鎖が谷を移ったかと温度の予定を確かめられる。
`SearchBudgetCompleted` は成功ではないので、最良点は既知の値、別のシード、別の方法で確かめる候補として扱う。
