分枝切除法の探索木は最悪の場合に指数的に大きくなるので、実用では節点数やメモリ使用量に上限を設け、上限で止まった探索からも使える情報を読み出す。
このページでは `BranchAndBound` の上限、探索の状態（`MipSearchState`、`MipNode`）、計算量の計数（`MipStatistics`）、緩和のソルバーの差し替え（`MipRelaxationSolver`）を説明する。
分枝規則、切除平面、ギャップの定義は[混合整数計画と分枝切除法](../mixed-integer-programming/)にある。

## 上限と任意の作業

`BranchAndBound` の既定は次のとおりで、どの設定メソッドも失敗しない。

| 設定 | 既定 | 意味 |
|---|---|---|
| `with_max_nodes` | 1000 | 処理する節点の数（根を含む） |
| `with_max_lp_iterations` | 1000 | 各緩和の求解のピボット数（修復を含む） |
| `with_integrality_tolerance` | $\sqrt{\epsilon}$ | 整数とみなす距離 |
| `with_relaxation_tolerances` | 各役割 $10^{-8}$ | 緩和の許容誤差とギャップの許容誤差 |
| `with_branching` | `Reliability` | 分枝規則 |
| `with_presolve` | `true` | 根の前処理 |
| `with_limits` | `MipLimits::default()` | メモリ使用量と任意の作業の上限 |

`MipLimits` は、未処理の節点 1000 個（処理中の節点は数えない）、深さ 1000（根は 0）、探索木と作業配列のメモリ使用量 64 MiB（`max_search_bytes`）、各緩和の求解のメモリ使用量 64 MiB（`max_relaxation_bytes`）を持つ。
任意の作業の上限として、加える切除平面 128 本と非零係数 8192 個、節点ごとの切除平面の回数 2 回、強分枝の候補 4 個とピボット 32 回、擬計算コストを信頼する記録の回数 2 回、修復の有無（既定で実行）も持つ。
任意の作業の上限を 0 にするとその作業を止める。
上限に達すると、節点数は `NodeLimit`、深さは `DepthLimit`、未処理の節点数とメモリ使用量は `MemoryLimit` で止まり、どれも成功ではない。

## 探索の状態と計算量

`BranchAndBound::workspace(&problem)` が作る `BranchAndBoundWorkspace` は、緩和のソルバーと探索の状態を持つ。
`solve_into` で解いたあと、`BranchAndBoundWorkspace::state()` が返す `MipSearchState` から、上限で止まった探索の状態も読める。

- `open_nodes()` は未処理の節点で、処理の順ではなく保存の順に並ぶ。
- `incumbent()` と `incumbent_objective()` は暫定解と、元の問題で計算し直したその目的値である。
- `active_node()` は上限で止まったときに処理中だった節点である。
- `presolve_map()` は前処理の写像で、前処理が終わっていれば `Some` になる。
- `cut_provenance(node)` は、未処理か処理中の節点に効いている切除平面の種類（`MipCutKind`）と、前処理後のモデルでの元の行の番号を返す。
  それ以外の節点を渡すと `InvalidInput` になり、行の番号は `MipPresolveMap::original_rows` で元の行に戻す。

`MipNode` は節点で、`id()` は作った順の番号、`depth()` は根を 0 とする深さ、`lower_bound()` は親か自身の緩和から得た下界である。
結果の `global_lower_bound()` は全体の下界で、未処理の節点（上限で止まったときは処理中の節点も）と許容誤差で刈った節点の下界、暫定解の目的値の最小である。
下界の分からない未処理の節点が残っていれば `None` になる。
探索が成功して止まっても、下界が暫定解の値に許容誤差の範囲で届いた節点は処理せずに残るので、`open_nodes()` が空になるとは限らない。

`MipStatistics` は探索の計算量の計数で、`MipResult::statistics()` か `MipSearchState::statistics()` から取り出す。
`nodes()` は処理した節点（強分枝の試し解きを除く）、`relaxations()` は試し解きと修復を含む LP 緩和の求解、`iterations()` は全ての緩和のピボットと上下端の切り替え、`probes()` は強分枝の試し解き（方向ごとに 1 回）である。
`cuts()` と `cut_nonzeros()` は加えた切除平面の本数と非零係数、`repairs()` は丸めと固定の修復の試行、`basis_reuses()` は直前の基底から始めた緩和の求解、`peak_search_bytes()` は `max_search_bytes` と比べる探索木のメモリ使用量の最大値である。

各求解は新しい探索として始まる。
前回の探索木や暫定解を次の求解の初期値として渡す API（MIP のウォームスタート）は提供しない。
整数解が一つ分かっていれば、目的がその値以下という行を問題に加えて、それより悪い領域を探索から除ける。

## 緩和のソルバーの差し替え

`BranchAndBound::workspace` は緩和に `SimplexSolver` を使う。
その作業メモリ `MipSimplexWorkspace` は目的と行を準備のときに固定し、節点ごとに変数の境界だけを変えて直前の基底から再最適化する。
基底は密な LU 分解で保持し、CSR で渡した制約の行は疎のまま扱う。

`BranchAndBoundWorkspace::new(relaxation)` は独自の `MipRelaxationSolver` を組み込む。
このトレイトは次の四つを持つ。

- `workspace_bytes(p)`：作業メモリと求解に必要なメモリ使用量の上界を返す。
- `workspace(p)`：目的と行を固定した作業メモリを作る。
- `reused_basis(w)`：直前の求解が記録した基底から始めたかを返す。
- `solve_into(p, w, output, iterations, max_workspace_bytes, context)`：境界だけが前回と違う LP を、ピボット数とメモリ使用量の上限の中で解く。

探索は緩和が返した点、目的値、証明用データを元の問題に対して検査するので、誤った緩和の結果から誤った最適性の主張は生まれない。
緩和のソルバーが返した点や目的値が有限でないか問題と合わない場合は、`BranchAndBound::solve_into` が `InvalidInput` を返す。
木の探索は、実行コンテキストに並列エグゼキューターがあっても逐次に行う。

## 節点の上限で止まった探索

$n=20$ 品目の 0-1 ナップサック問題を、節点の上限を変えて解く。
品目 $j$ の重さ $w_j$ は乱数のシードから作る 10〜60 kg の整数、価値は $v_j=w_j+10$ 点、容量は重さの合計の半分（切り捨て）で、$\sum_jw_jx_j\le C$、$x_j\in\{0,1\}$ の下で $\sum_jv_jx_j$ を最大にする（目的は $-\mathbf{v}$ の最小化に写す）。
価値が重さに定数を足した形のナップサック問題は強相関（strongly correlated）と呼ばれ、分枝限定法で解きにくい例として知られる（Kellerer, Pferschy and Pisinger, 2004）。
LP 緩和の上界は整数最適値に近いが、その差を閉じるまでに多くの節点を処理する。
独立な検算として、重さが整数であることを使う動的計画法で厳密な最適値を求める。
入力は処理する節点の上限と乱数のシードである。
表は終了理由、暫定解の価値、探索の上界（`global_lower_bound()` の符号を反転した値）、動的計画法の最適値と、未処理の節点と計算量の計数を示す。

```rust
//| id: optimize-mip-search-state
//| ref: optimize-mip-search-state
//| title: 節点の上限で止まった分枝切除法の暫定解と上界を厳密解と比べる
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg, scioxide-optimize, scioxide-random]
//| inputs:
//|   max_nodes: {"type":"range","label":"処理する節点の上限 [個]","min":5,"max":300,"step":5,"value":50}
//|   seed: {"type":"range","label":"乱数のシード [-]","min":1,"max":10,"step":1,"value":1}
//| cases:
//|   - {"id":"enough-nodes","label":"節点の上限 200","description":"探索が Converged で止まり、暫定解が動的計画法の最適値 487 に一致する。未処理の節点は残るが、その下界は暫定解に届いている。","inputs":{"max_nodes":200}}
//|   - {"id":"few-nodes","label":"節点の上限 5","description":"NodeLimit で止まり、暫定解と上界の差が大きく残る。上界は最適値を下回らない。","inputs":{"max_nodes":5}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"search","path":"/rows/0/0","equals":"NodeLimit"}
//|       - {"artifact":"search","path":"/rows/0/4","equals":487}
//|       - {"artifact":"search","path":"/rows/0/6","range":{"min":0}}
//|       - {"artifact":"search","path":"/rows/0/5","range":{"min":0}}
//|       - {"path":"/outputs/2/state","equals":"partial"}
//|   - case: enough-nodes
//|     expect:
//|       - {"artifact":"search","path":"/rows/0/0","equals":"Converged"}
//|       - {"artifact":"search","path":"/rows/0/1","approx":{"value":487,"atol":1e-9}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: few-nodes
//|     expect:
//|       - {"artifact":"search","path":"/rows/0/0","equals":"NodeLimit"}
//|       - {"artifact":"search","path":"/rows/0/6","range":{"min":0}}
use scioxide_core::{Bounds, Budget, ExecutionContext};
use scioxide_linalg::Matrix;
use scioxide_optimize::{BranchAndBound, LinearConstraints, LpProblem, MipProblem, MipResult};
use scioxide_random::{SeedableRng, Xoshiro256StarStar, uniform_index};

let fixed2 = serde_json::json!({ "fractionDigits": 2 });
let n = 20;
let mut rng = Xoshiro256StarStar::from_seed(seed.round() as u64);
let mut weight = Vec::with_capacity(n);
for _ in 0..n {
    weight.push(10 + uniform_index(51, &mut rng).map_err(|e| e.to_string())?);
}
let value: Vec<usize> = weight.iter().map(|&w| w + 10).collect();
let capacity = weight.iter().sum::<usize>() / 2;
// 独立な検算: 重さが整数なので、容量ごとの最大価値を動的計画法で求める。
let mut best = vec![0_usize; capacity + 1];
for (&w, &v) in weight.iter().zip(&value) {
    for c in (w..=capacity).rev() {
        best[c] = best[c].max(best[c - w] + v);
    }
}
let optimum = best[capacity];
let row = Matrix::from_vec(1, n, weight.iter().map(|&w| w as f64).collect())
    .map_err(|e| e.to_string())?;
let lp = LpProblem::new(value.iter().map(|&v| -(v as f64)).collect())
    .and_then(|p| {
        p.with_constraints(LinearConstraints::less_equal(row, vec![capacity as f64])?)
    })
    .and_then(|p| p.with_bounds(Bounds::new(vec![(Some(0.0), Some(1.0)); n])?))
    .map_err(|e| e.to_string())?;
let problem = MipProblem::new(lp, (0..n).collect()).map_err(|e| e.to_string())?;
let limit = Budget::try_from(max_nodes.round() as usize).map_err(|e| e.to_string())?;
let solver = BranchAndBound::default().with_max_nodes(limit);
let mut workspace = solver.workspace(&problem).map_err(|e| e.to_string())?;
let mut result = MipResult::empty();
solver
    .solve_into(
        &problem,
        &mut result,
        &mut workspace,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;
let state = workspace.state();
// 最小化の界を利益の向きに戻す。暫定解がなければ None。
let incumbent = state.incumbent_objective().map(|f| -f);
let upper = result.global_lower_bound().map(|b| -b);
let search = vec![(
    result.termination().to_string(),
    incumbent,
    upper,
    result.absolute_gap(),
    optimum,
    incumbent.map(|f| optimum as f64 - f),
    upper.map(|u| u - optimum as f64),
)];
let columns = serde_json::json!([
    { "key": "0", "label": "終了理由" },
    { "key": "1", "label": "暫定解の価値 [点]", "type": "number", "format": fixed2, "nullText": "なし" },
    { "key": "2", "label": "探索の上界 [点]", "type": "number", "format": fixed2, "nullText": "なし" },
    { "key": "3", "label": "レポートの絶対ギャップ [点]", "type": "number", "format": fixed2, "nullText": "なし" },
    { "key": "4", "label": "動的計画法の最適値 [点]", "type": "integer" },
    { "key": "5", "label": "最適値 − 暫定解 [点]", "type": "number", "format": fixed2, "nullText": "なし" },
    { "key": "6", "label": "上界 − 最適値 [点]", "type": "number", "format": fixed2, "nullText": "なし" }
]);
emit_table_with_columns!(
    columns,
    search,
    metadata = serde_json::json!({ "id": "search" })
);
let open = state.open_nodes();
let deepest = open.iter().map(|node| node.depth()).max();
let mut cuts_in_open_nodes = 0;
for node in open {
    cuts_in_open_nodes += state
        .cut_provenance(node)
        .map_err(|e| e.to_string())?
        .count();
}
let stats = result.statistics();
let work_columns = serde_json::json!([
    { "key": "0", "label": "処理した節点 [個]", "type": "integer" },
    { "key": "1", "label": "未処理の節点 [個]", "type": "integer" },
    { "key": "2", "label": "未処理の節点の最大深さ [-]", "type": "integer", "nullText": "なし" },
    { "key": "3", "label": "LP 緩和の求解 [回]", "type": "integer" },
    { "key": "4", "label": "強分枝の試し解き [回]", "type": "integer" },
    { "key": "5", "label": "加えた切除平面 [本]", "type": "integer" },
    { "key": "6", "label": "未処理の節点に効く切除平面の延べ数 [本]", "type": "integer" },
    { "key": "7", "label": "修復 [回]", "type": "integer" }
]);
emit_table_with_columns!(
    work_columns,
    vec![(
        stats.nodes(),
        open.len(),
        deepest,
        stats.relaxations(),
        stats.probes(),
        stats.cuts(),
        cuts_in_open_nodes,
        stats.repairs()
    )],
    metadata = serde_json::json!({ "id": "work" })
);
let outcome = if result.is_success() {
    Outcome::satisfied("ギャップが許容誤差内に入って探索が止まった")
} else if result.has_incumbent() {
    Outcome::partial("上限で止まった。暫定解と上界の差を用途の許容範囲と比べる")
} else {
    Outcome::failed("暫定解のないまま探索が止まった")
};
let mut outcome = outcome.status(result.termination().to_string()).diagnostic(
    "処理した節点",
    stats.nodes() as f64,
    None,
);
if let Some(gap) = result.absolute_gap() {
    outcome = outcome.diagnostic("絶対ギャップ", gap, None);
}
emit_outcome!(outcome);
```

既定の上限 50 節点では探索が `NodeLimit` で止まり、outcome は partial になる。
暫定解の価値は 485 点、探索の上界は 487.82 点で、レポートの絶対ギャップは 2.82 点である。
動的計画法の最適値 487 点は暫定解より 2 点大きく、上界より 0.82 点小さいので、最適値は返した二つの界の間に入っている。
このとき未処理の節点が 46 個（最大の深さ 9）残り、加えた切除平面は 61 本である。

上限を 200 にすると 113 節点で `Converged` になり、暫定解は最適値 487 に一致する。
このときも未処理の節点が 47 個残るが、その下界は暫定解の値に許容誤差の範囲で届いているので、処理する必要がない。
上限を 5 にすると暫定解は 483 点、上界は 488.30 点で、差 5.30 点のうち実際に改善できる余地は 4 点である。
探索は決定論的なので、節点の上限を増やしても途中までは同じ探索をたどり、暫定解は下がらず、上界は上がらない。
二つの界は最適値を両側から挟んだまま近づく。

## まとめ

`BranchAndBound` は節点数、深さ、未処理の節点数、メモリ使用量に上限を持ち、上限で止まった探索は成功ではないが、暫定解と全体の下界を読める。
上限で止まった結果では、暫定解の目的値と下界の差が、未処理の部分木から得られる改善の上限を与える。
`BranchAndBoundWorkspace::state()` から未処理の節点、処理中の節点、前処理の写像、節点ごとの切除平面の由来を読み、`MipStatistics` で計算量を確かめられる。
緩和を独自のソルバーで解くには `MipRelaxationSolver` を実装して組み込み、その結果も探索が元の問題で検査する。
前回の探索を引き継ぐウォームスタートはないので、各求解は新しい探索になる。
