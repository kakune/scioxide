大域探索の方法は有限の観測から次にどこを評価するかの選び方で分けられる。
このページの二つの方法は、どちらも観測の幾何を使う。
DIRECT は箱を長方形に分割し、長方形の大きさと中心の値から次に分割する長方形を決める。
SHGO は標本点を Delaunay 分割で単体に分け、隣り合う標本より値が低い点を極小の候補として局所ソルバーで精度を改善する。
DIRECT は乱数を使わず、SHGO は開始点の設計に乱数を使わない設計を選べるので、どちらも結果を再現しやすい。

二つの方法は `MultiStart` と同じく、呼び出しごとに `BoundedObjective` から箱を受け取り、全ての座標に有限な上下端を求める。
どちらも大域最適性の証明は返さず、計算回数の上限に達した終了を成功として返しない。
大域探索の一般的な限界は[大域探索の限界と吸引域の命中確率](../global-search/)で扱う。

## DIRECT の領域分割

DIRECT（dividing rectangles、Jones ほか 1993）は、箱を単位箱 $[0, 1]^d$ へ正規化し、長方形の中心で目的を評価する。
目的関数が未知の Lipschitz 定数 $K$ を持つとすると、中心値 $f_i$、中心から最も遠い点までの距離 $d_i$ の長方形の中では $f \ge f_i - K d_i$ が成り立つ。
$K$ が分かれば下界の最も低い長方形を分割すればよいが、$K$ は分からない。
DIRECT は、ある $K > 0$ で下界が最も低くなりうる長方形を全て分割し、小さい目的値の近くと、まだ粗い領域の両方を調べる。

### 潜在的最適な長方形

長方形 $j$ は、ある $K > 0$ について

$$
f_j - K d_j \le f_i - K d_i \quad (\text{全ての } i), \qquad
f_j - K d_j \le f_{\min} - \epsilon |f_{\min}|
$$

を満たすとき、潜在的最適（potentially optimal）と呼ぶ。
$f_{\min}$ は現在の最良値である。
一つ目の条件は、$(d, f)$ 平面で点 $(d_j, f_j)$ が全ての点の下側凸包の右下の部分にあることと同じである。
条件を満たす $K$ の範囲は $d_i < d_j$ の点からの傾き $(f_j - f_i)/(d_j - d_i)$ の最大値以上、$d_i > d_j$ の点への傾き $(f_i - f_j)/(d_i - d_j)$ の最小値以下である。
二つ目の条件は現在の最良値を相対的に $\epsilon$（既定 $10^{-4}$）以上改善できる見込みのない小さな長方形を除く。

大きさが最大の長方形のうち中心値が最も低いものは、右側に比べる点がないので、どの掃引でも選ばれる。
このため評価回数を増やせば、全ての長方形がいずれ分割され、標本は箱の中で稠密になる。
目的が連続なら最良値は大域的最小値に近づくが、有限回で打ち切ったときの差の上界は得られない。

`DirectVariant::Original` は大きさ $d_i$ を中心から頂点までの距離（正規化した半辺長の Euclid ノルム）とし、同じ大きさと値の長方形を全て選ぶ。
`DirectVariant::LocallyBiased`（DIRECT-L、Gablonsky と Kelley 2001）は大きさを最長の半辺長とし、大きさごとに一つだけを選び、$\epsilon = 0$ を使う。
大きさの種類が少なくなり、一回の掃引で分割する長方形が減るので、局所的な改善に評価が寄る。

### 長方形の三分割

選んだ長方形の中心を $c$、最長の半辺長を $h$ とする。
最長の辺の方向 $e_k$ ごとに $c \pm \frac{2h}{3} e_k$ の二点を評価し、$w_k = \min\bigl(f(c + \frac{2h}{3} e_k), f(c - \frac{2h}{3} e_k)\bigr)$ とする。
$w_k$ の小さい方向から順に三等分するので、最も良い値の方向の子が最も大きな長方形として残る。
一つの長方形の分割は最長の辺の数を $m$ として $2m$ 回の評価を使う。
以前に評価した点と同じ点は評価せず、記録した値を使う。
丸めで新しい点が作れない長方形は停滞した長方形として数え、それ以上分割しない。
上下端が等しい変数は固定され、分割しない。

### DIRECT の API と停止

`DirectOptions::new(max_evaluations, max_rectangles, max_storage_bytes)` は、目的の評価回数、同時に持つ長方形の数、作業領域が確保してよいバイト数の上限を受け取り、失敗しない。
既定は `Original`、掃引の上限は評価回数の上限と同じ、$\epsilon = 10^{-4}$、逐次実行で、`with_variant`、`with_max_sweeps`、`with_epsilon` で変える。
`Direct::new` は負か非有限の $\epsilon$ と逐次でない実行方針を `InvalidInput` で拒む。
各掃引が以前の全ての標本に依存するので、DIRECT は逐次にしか実行しない。
`Direct::workspace(dimension)` が作業領域 `DirectWorkspace` を用意し、必要なメモリが `max_storage_bytes` を超えると `ResourceLimit` を返す。
必要量は `workspace_requirements(dimension)` が返す `DirectWorkspaceRequirements` で分かる。
空の `DirectWorkspace::new()` を `minimize_into` に渡しても、最初の呼び出しで準備される。
`minimize(&problem)` は作業領域と結果を内部で用意して逐次に解く。
メモリは長方形の数を $r$ として $O(rd)$ である。

次の分割で評価回数の上限を超えるなら `EvaluationLimit`、長方形の数の上限を超えるなら `MemoryLimit`、掃引の上限に達すれば `SearchBudgetCompleted`、分割できる長方形がなくなれば `Stagnation` で止まり、どれも成功ではない。
評価回数の上限は分割の単位で守るので、実際の評価回数は上限より少し少ないことがある。
`DirectResult` は最良の標本 `best_sample()`、評価回数 `evaluations()`、掃引の数 `sweeps()`、長方形の数 `rectangles()`、停滞した長方形の数 `stalled_rectangles()`、最大の半辺長 `max_live_half_side()` を返す。
最大の半辺長は箱をどこまで細かく覆ったかの尺度であり、目的値の誤差の上界ではない。

## Branin 関数での分割

Branin 関数

$$
f(x, y) = \Bigl(y - \frac{5.1}{4\pi^2} x^2 + \frac{5}{\pi} x - 6\Bigr)^2 + 10\Bigl(1 - \frac{1}{8\pi}\Bigr)\cos x + 10
$$

は、箱 $x \in [-5, 10]$、$y \in [0, 15]$ に三つの大域的最小点 $(-\pi, 12.275)$、$(\pi, 2.275)$、$(3\pi, 2.475)$ を持つ標準的な試験問題である。
最小値は、二乗の項が 0 で $\cos x = -1$ になる点の値 $5/(4\pi) \approx 0.397887$ である。
このセルは評価回数の上限と選択の方式を入力にして、最良の標本、既知の最小値との差、最も近い最小点までの距離、実際の評価回数、掃引と長方形の数、最大の半辺長を出す。
三つの最小点のどれに近づいても同じ目的値になるので、距離は最も近い最小点で測る。

```rust

//| ref: optimize-direct-branin
//| title: DIRECT の評価回数と最良の標本の誤差を調べる

//| timeoutMs: 120000
//| crates: [scioxide-core, scioxide-optimize]

//| cases:
//|   - {"id":"locally-biased","label":"DIRECT-L（LocallyBiased）","description":"同じ 499 回の評価で最良の標本は (π, 2.275) の近くに寄り、既知の最小値との差は 2.1×10⁻¹¹、最小点までの距離は 4.8×10⁻⁶ に縮む。","inputs":{"variant":"LocallyBiased"}}

        { "key": "3", "label": "既知の最小値との差 [-]", "type": "number", "format": sci3 },
        { "key": "4", "label": "最小点までの距離 [-]", "type": "number", "format": sci3 },
        { "key": "5", "label": "評価 [回]", "type": "integer" },
        { "key": "6", "label": "掃引 [回]", "type": "integer" },
        { "key": "7", "label": "長方形 [個]", "type": "integer" },
        { "key": "8", "label": "最大の半辺長 [箱の幅]", "type": "number", "format": digits4 },
```

既定の 500 回の上限では、DIRECT は 27 回の掃引で 499 回評価して `EvaluationLimit` で止まる。
最良の標本は $(3\pi, 2.475)$ の近くの $(9.42501, 2.47485)$ で、既知の最小値との差は $3.8 \times 10^{-7}$、最小点までの距離は $2.8 \times 10^{-4}$ である。
最大の半辺長は $1/18 \approx 0.056$ で、どの長方形の辺も正規化した箱の幅の $1/9$ 以下まで分割されている。
`LocallyBiased` では同じ評価回数で差が $2.1 \times 10^{-11}$ まで下がり、大きさごとに一つだけ選ぶ規則が局所的な改善に評価を回すことが分かる。
上限を 2000 回にすると、Original の最良の標本は別の最小点 $(-\pi, 12.275)$ の近くへ移り、差は $2.9 \times 10^{-8}$ になる。
三つの最小点が同じ値を持つので、どの最小点の近くに最良の標本があるかは評価の進み方で変わる。
どの場合も終了理由は上限によるもので、最良の標本が大域的最小点の近くにあることは既知の値との比較で確かめている。

## SHGO の標本と局所最適化

SHGO（simplicial homology global optimization、Endres ほか 2018）は、標本の単体複体から局所的に低い点を選び、局所ソルバーで精度を改善する。
SciOxide の実装は箱の $2^d$ 個の頂点と、`StartDesign` が作る `samples` 個の点を順に評価する。
これらの点を [Delaunay 分割](../../../scioxide-spatial/algorithms/delaunay-voronoi-and-hulls/)で単体に分け、単体の辺で結ばれた点を隣接点とする。
全ての隣接点より値が低い点を、標本で見た極小の候補とする。
同じ値の隣接点は一つの平坦部としてまとめ、平坦部のどの点にもより低い隣接点がなければ、平坦部から一つを候補にする。
候補は値の小さい順に並べ、`LocalSolverFactory` が作る局所ソルバーで精度を改善する。

標本が十分に密なら、それぞれの極小点の吸引域に標本が入り、候補の一覧は極小点の一覧に近づく。
ただし有限の標本で見た低点は、未知の領域も含む全ての極小点ではない。
計算コストは $2^d$ と標本数の合計の評価、Delaunay 分割、候補ごとの局所求解である。
頂点の数 $2^d$ と Delaunay 分割の単体の数は次元とともに急に増えるので、SHGO は低次元向けである。

`Shgo::new(options, design, factory)` は失敗しない。
`ShgoOptions::new(samples, geometry)` も失敗せず、`geometry` は scioxide-spatial の `GeometryOptions` で、Delaunay 分割の点の数、次元（既定の上限 8）、メモリと計算量を制限する。
既定は全ての候補を局所最適化し、シード 42、各局所求解の上限なし、逐次実行である。
`with_max_refinements` は局所最適化する候補の数を、`with_seed` は設計と局所求解のシードを、`with_local_budgets` は各局所求解の上限を、`with_execution` は局所最適化の実行方針を決める。
標本と分割は常に逐次で、逐次でない実行方針では問題を `BoundedObjective::new_sync` で作る必要がある。

`Shgo::workspace(dimension)` か空の `ShgoWorkspace::new()` を用意する。
頂点と標本の合計が幾何の点の上限を超えるか、次元が次元の上限を超えると、`workspace_requirements(dimension)` が `ResourceLimit` を返す。
成功すると必要量 `ShgoWorkspaceRequirements` を返し、次元 `dimension()`、頂点と標本を合わせた点の数 `sites()`、用意する局所ソルバーの数 `refinements()` が読める。
`minimize_into(problem, output, workspace, scope)` か `minimize(problem)` で解き、標本の点が箱の外なら `InvalidInput`、目的が NaN か無限大を返せば `NonFinite` になる。
全ての候補を局所最適化した終了は `SearchBudgetCompleted` で、成功ではない。

`ShgoResult` は標本の点 `points()` と値 `values()`、候補の標本の番号 `candidates()`、局所最適化の記録 `refinements()`、単体の数 `simplex_count()` を返す。
`best_sample()` は標本の最良点、`best_observed()` は標本と局所解を合わせた最良点、`best_refined()` は局所求解が成功した局所最適化の最良点である。
`ShgoRefinement` は候補の標本の番号 `vertex()`、局所解 `result()`、エラー `error()`、評価回数 `counts()` を持つ。

## Himmelblau 関数の極小点の一覧

Himmelblau 関数 $f(x, y) = (x^2 + y - 11)^2 + (x + y^2 - 7)^2$ は、箱 $[-5, 5]^2$ に 4 つの極小点（どれも $f = 0$）を持つ（[複数開始点法](oxref:optimize-multistart-designs)と同じ関数）。
このセルは `Shgo` で、Sobol 列の標本の数を変え、極小の候補と局所最適化で求めた解の一覧を作る。
局所ソルバーは解析的な勾配で L-BFGS-B を走らせる factory を注入する（仕様は[局所ソルバーの差し替え](oxref:optimize-local-solver-injection)）。
出力は標本、候補、局所解の散布図、局所最適化ごとの表、要約と判定である。
既知の 4 つの極小点までの距離が独立な検算になる。

```rust
// Himmelblau 関数と解析的な勾配。
struct Himmelblau;
impl ObjectiveFunction<f64> for Himmelblau {
    fn dim(&self) -> usize {
        2
    }
    fn eval(&self, x: &[f64]) -> Result<f64, SciOxideError> {
        let (a, b) = (x[0] * x[0] + x[1] - 11.0, x[0] + x[1] * x[1] - 7.0);
        Ok(a * a + b * b)
    }
    fn gradient_into(&self, x: &[f64], out: &mut [f64]) -> Result<bool, SciOxideError> {
        let (a, b) = (x[0] * x[0] + x[1] - 11.0, x[0] + x[1] * x[1] - 7.0);
        out[0] = 4.0 * x[0] * a + 2.0 * b;
        out[1] = 2.0 * a + 4.0 * x[1] * b;
        Ok(true)
    }
}
// 候補ごとに L-BFGS-B と作業領域を用意する局所ソルバーの factory。
#[derive(Debug)]
struct LbfgsBFactory;
struct LbfgsBLocal(LbfgsB<f64>, LbfgsBWorkspace<f64>);
impl LocalSolverFactory<f64> for LbfgsBFactory {
    type Solver = LbfgsBLocal;
    fn prepare(&self, dimension: usize) -> Result<LbfgsBLocal, SciOxideError> {
        let solver = LbfgsB::default();
        let work = solver.workspace(dimension)?;
        Ok(LbfgsBLocal(solver, work))
    }
}
impl SearchLocalSolver<f64> for LbfgsBLocal {
    fn minimize_into(
        &mut self,
        problem: &BoundedObjective<'_, f64>,
        start: &[f64],
        _: u64,
        output: &mut OptimizeResult<f64>,
        context: &mut SolveContext<'_, '_>,
    ) -> Result<(), SciOxideError> {
        self.0
            .minimize_into(problem, start, output, &mut self.1, context)
    }
}
```

## まとめ

DIRECT は乱数を使わず、潜在的最適な長方形の規則で大域と局所の探索に評価を配分するので、低次元で再現性の高い探索に向く。
`Original` と `LocallyBiased` は選ぶ長方形の数が違い、後者は同じ評価回数で局所的な改善に評価を寄せる。
SHGO は $2^d$ 個の頂点と Delaunay 分割を使うので低次元に限られるが、極小の候補を一度に複数返し、局所最適化で極小点の一覧を作れる。
どちらも評価回数だけでなく、長方形の数、標本の数、幾何のメモリも制限して使う。
終了はどれも成功ではないので、最良の標本や局所解は既知の値、局所ソルバーの判定、別の方法で確かめる。
