[一階法・非線形共役勾配・準 Newton 法](../first-order-and-quasi-newton/)では、反復回数が最急降下法で条件数 $\kappa$ に比例し、共役勾配法で $\sqrt{\kappa}$ に比例し、準 Newton 法では曲率の学習でこの依存が弱まることを導いた。
このページでは、固有値の広がりだけを変えた二次関数で四つの方法を同じ設定で動かし、その違いを反復と評価の回数で確かめる。

## 理論の収束率

二次関数 $f(\mathbf{x}) = \tfrac12\mathbf{x}^\mathsf{T}\mathbf{A}\mathbf{x}$（$\mathbf{A}$ は正定値、条件数 $\kappa$）では、最小値は 0 で、目的値そのものが誤差のエネルギーノルムの二乗の半分になる。
厳密な直線探索の最急降下法は一反復で目的値を最悪で $r = ((\kappa - 1)/(\kappa + 1))^2$ 倍にする（Kantorovich の不等式）。
共役勾配法では誤差のエネルギーノルムが $2((\sqrt\kappa - 1)/(\sqrt\kappa + 1))^k$ 倍以下に縮み、厳密な算術なら $n$ 反復以内に終わる。
BFGS 法も厳密な直線探索なら二次関数で $n$ 反復以内に終わるが、SciOxide の既定の直線探索は不正確なので、この有限終了は成り立たない。
これらの評価はどれも厳密な直線探索を前提にしているので、SciOxide の既定の設定で解いたときの反復回数の上界ではない。

## 四つの方法の比較

$n=20$ 変数の二次関数 $f(\mathbf{x}) = \frac{1}{2}\sum_i \lambda_i x_i^2$ を考える。
固有値は $\lambda_i=\kappa^{i/(n-1)}$（$i=0,\dots,19$）と 1 から $\kappa$ まで等比に並べ、ヘッセ行列の条件数を入力の $\kappa$ に一致させる。
点 $(1,\dots,1)$ から既定の設定の `GradientDescent`、`NonlinearCg`、`Bfgs`、`Lbfgs`（$m = 10$）で最小化し、目的値の推移を比べる。
推移は反復上限を $k = 1, 2, \dots, 400$ と変えた独立な実行の最終値から作り、成功した時点でその方法の系列を打ち切る。
上限で止まった実行は `IterationLimit` で終わり、最後に受理した点を返すので、その目的値が $k$ 反復後の値になる。
破線は厳密な直線探索の最急降下法に対する最悪評価 $f_k\le r^k f_0$ で、比較用に式で描く。
表は反復上限 1000 での各方法の終了理由、反復と評価の回数、最終の目的値、原点からの距離、曲率更新の内訳（減衰と省略）または再開始の回数、対数軸から除いた目的値 0 の点の数である。
停止判定は四つとも勾配の 2 ノルムによる `GradientSmall` で、許容誤差は既定（絶対・相対とも $\sqrt{\varepsilon_{\mathrm{mach}}}$）である。
セルの最後の判定は `Bfgs` の終了理由から出す。

```rust
//| id: optimize-bfgs-condition
//| ref: optimize-bfgs-condition
//| title: 条件数を動かして最急降下・共役勾配・BFGS・L-BFGS の収束を比べる
//| run: reactive
//| crates: [scioxide-core, scioxide-optimize]
//| inputs:
//|   condition_number: {"type":"range","label":"ヘッセ行列の条件数 κ [-]","description":"二次関数の固有値の広がりを変える。","min":2,"max":10000,"step":2,"value":400}
//| cases:
//|   - {"id":"kappa-2","label":"κ = 2","description":"固有値がほぼそろい、四つの方法とも 11〜12 反復で GradientSmall になる。","inputs":{"condition_number":2}}
//|   - {"id":"kappa-10000","label":"κ = 10⁴","description":"GradientDescent は 1000 反復の上限で IterationLimit（目的値 8.9×10⁻¹¹）に止まり、Bfgs は 139 反復、NonlinearCg は 247 反復、Lbfgs は 758 反復で GradientSmall になる。","inputs":{"condition_number":10000}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"methods","path":"/rows/0/1","equals":"GradientSmall"}
//|       - {"artifact":"methods","path":"/rows/1/1","equals":"GradientSmall"}
//|       - {"artifact":"methods","path":"/rows/2/1","equals":"GradientSmall"}
//|       - {"artifact":"methods","path":"/rows/3/1","equals":"GradientSmall"}
//|       - {"artifact":"methods","path":"/rows/2/6","range":{"min":0,"max":1e-7}}
//|       - {"artifact":"methods","path":"/rows/0/9","equals":0}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: kappa-2
//|     expect:
//|       - {"artifact":"methods","path":"/rows/0/2","range":{"min":9,"max":15}}
//|       - {"artifact":"methods","path":"/rows/1/2","range":{"min":9,"max":15}}
//|       - {"artifact":"methods","path":"/rows/2/2","range":{"min":9,"max":15}}
//|       - {"artifact":"methods","path":"/rows/3/2","range":{"min":9,"max":15}}
//|   - case: kappa-10000
//|     expect:
//|       - {"artifact":"methods","path":"/rows/0/1","equals":"IterationLimit"}
//|       - {"artifact":"methods","path":"/rows/0/2","equals":1000}
//|       - {"artifact":"methods","path":"/rows/0/5","range":{"min":1e-12,"max":1e-7}}
//|       - {"artifact":"methods","path":"/rows/1/1","equals":"GradientSmall"}
//|       - {"artifact":"methods","path":"/rows/2/1","equals":"GradientSmall"}
//|       - {"artifact":"methods","path":"/rows/3/1","equals":"GradientSmall"}
use scioxide_core::{Budget, RealScalar};
use scioxide_optimize::{
    Bfgs, BfgsOptions, GradientDescent, GradientDescentOptions, Lbfgs, LbfgsOptions,
    NonlinearCg, NonlinearCgOptions, ObjectiveFn, OptimizeDiagnostics, OptimizeResult,
    OptimizeTermination,
};

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
// f(x) = ½ Σ λᵢ xᵢ²、固有値 λᵢ = κ^{i/(n−1)} を 1 から κ まで等比に並べる。
let n = 20_usize;
let kappa = condition_number;
let lambda: Vec<f64> = (0..n)
    .map(|i| RealScalar::powf(kappa, i as f64 / (n - 1) as f64))
    .collect();
let (lv, lg) = (lambda.clone(), lambda.clone());
let objective = ObjectiveFn::new(n, move |x: &[f64]| {
    Ok(0.5 * x.iter().zip(&lv).map(|(v, l)| l * v * v).sum::<f64>())
})
.with_gradient(move |x: &[f64], g: &mut [f64]| {
    for ((gi, v), l) in g.iter_mut().zip(x).zip(&lg) {
        *gi = l * v;
    }
    Ok(())
});
let start = vec![1.0_f64; n];
let initial = 0.5 * lambda.iter().sum::<f64>();
// 方法 method を反復上限 k で解く。上限で止まった実行は最後に受理した点を返す。
let run = |method: usize, k: usize| -> Result<OptimizeResult<f64>, String> {
    let budget = Budget::try_from(k).map_err(|e| e.to_string())?;
    match method {
        0 => {
            GradientDescent::new(GradientDescentOptions::default().with_max_iterations(budget))
                .minimize(&objective, &start)
        }
        1 => NonlinearCg::new(NonlinearCgOptions::default().with_max_iterations(budget))
            .minimize(&objective, &start),
        2 => Bfgs::new(BfgsOptions::default().with_max_iterations(budget))
            .minimize(&objective, &start),
        _ => Lbfgs::new(LbfgsOptions::default().with_max_iterations(budget))
            .minimize(&objective, &start),
    }
    .map_err(|e| e.to_string())
};
let mut limits: Vec<usize> = (1..=10).collect();
while *limits.last().unwrap_or(&1) < 400 {
    let last = *limits.last().unwrap_or(&1);
    limits.push((last + (last / 8).max(1)).min(400));
}
let names = ["GradientDescent", "NonlinearCg", "Bfgs", "Lbfgs"];
let mut series = Vec::new();
let mut rows = Vec::new();
let mut bfgs = None;
for (method, name) in names.iter().enumerate() {
    let mut points = vec![[0.0, initial]];
    let mut dropped = 0_usize;
    let mut last = None;
    for &k in &limits {
        let result = run(method, k)?;
        // 目的値 0 の点は対数軸に描けないので除き、件数を表に出す。
        if result.fun() > 0.0 {
            points.push([k as f64, result.fun()]);
        } else {
            dropped += 1;
        }
        let success = result.is_success();
        last = Some(result);
        // 上限より前に成功した後は、上限を増やしても結果は変わらない。
        if success {
            break;
        }
    }
    series.push(serde_json::json!({ "name": name, "points": points }));
    // 表は反復上限 1000 の結果。成功済みの実行はそのまま使う。
    let result = match last {
        Some(result) if result.is_success() => result,
        _ => run(method, 1000)?,
    };
    let distance = RealScalar::sqrt(result.x().iter().map(|v| v * v).sum::<f64>());
    // 曲率更新の減衰と省略（準 Newton 法）、再開始（共役勾配法）の回数。
    let (curvature, restarts) = match result.method_diagnostics() {
        OptimizeDiagnostics::FirstOrder(d) if method >= 2 => {
            (Some(d.damped_updates() + d.skipped_updates()), None)
        }
        OptimizeDiagnostics::FirstOrder(d) if method == 1 => (None, Some(d.restarts())),
        _ => (None, None),
    };
    rows.push((
        name.to_string(),
        result.termination().to_string(),
        result.iterations(),
        result.fun_evals(),
        result.grad_evals(),
        result.fun(),
        distance,
        curvature,
        restarts,
        dropped,
    ));
    if method == 2 {
        bfgs = Some(result);
    }
}
// 比較用（式）: 厳密な直線探索の最急降下法に対する Kantorovich の最悪評価 f_k ≤ r^k f_0。
let rate = RealScalar::powi((kappa - 1.0) / (kappa + 1.0), 2);
let bound: Vec<[f64; 2]> = (0..=400)
    .step_by(4)
    .map(|k| [k as f64, initial * RealScalar::powi(rate, k)])
    .filter(|p| p[1] > 0.0)
    .collect();
series.push(serde_json::json!({
    "name": "最急降下（厳密な直線探索）の最悪評価",
    "points": bound,
    "style": { "lineType": "dashed" }
}));
emit_line_chart!(
    &series,
    options = &serde_json::json!({
        "xLabel": "反復上限 k [回]",
        "yLabel": "k 反復後の目的値 f(x_k) [-]",
        "yType": "log",
        "xMin": 0.0,
        "xMax": 400.0,
        "yMin": 1.0e-30
    })
);
let columns = serde_json::json!([
    { "key": "0", "label": "方法" },
    { "key": "1", "label": "終了理由" },
    { "key": "2", "label": "反復 [回]", "type": "integer" },
    { "key": "3", "label": "目的の評価 [回]", "type": "integer" },
    { "key": "4", "label": "勾配の評価 [回]", "type": "integer" },
    { "key": "5", "label": "最終の目的値 [-]", "type": "number", "format": sci3 },
    { "key": "6", "label": "原点からの距離 [-]", "type": "number", "format": sci3 },
    { "key": "7", "label": "減衰・省略した更新 [回]", "type": "integer", "nullText": "—" },
    { "key": "8", "label": "再開始 [回]", "type": "integer", "nullText": "—" },
    { "key": "9", "label": "図から除いた点 [個]", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "methods" })
);
// BFGS の終了理由をセルの結論にする。
let result = bfgs.ok_or("BFGS の結果がない")?;
let outcome = if result.is_success() {
    Outcome::satisfied("BFGS の勾配ノルムが許容誤差を下回った")
} else if matches!(
    result.termination(),
    OptimizeTermination::LineSearchFailed(_)
) {
    Outcome::failed("BFGS の直線探索がステップ幅を受理しなかった")
} else {
    Outcome::partial("BFGS が上限で止まり、最後に受理した点を返した")
};
emit_outcome!(
    outcome
        .status(result.termination().to_string())
        .diagnostic("反復", result.iterations() as f64, None)
        .diagnostic("最終の目的値", result.fun(), None)
);
```

既定の $\kappa = 400$ では四つの方法とも `GradientSmall` で終わり、反復は `GradientDescent` が 275 回、`NonlinearCg` が 64 回、`Bfgs` が 94 回、`Lbfgs` が 157 回である。
評価回数は `GradientDescent` が目的 330 回・勾配 276 回、`NonlinearCg` が 272 回ずつ、`Bfgs` が 101 回ずつ、`Lbfgs` が 173 回ずつである。
$c_2 = 0.1$ の強 Wolfe 条件を使う `NonlinearCg` は、一反復あたり約 4 回と評価が多い。
`GradientDescent` の目的値は破線の最悪評価（$k = 400$ でも約 13.5）より速く減る。
破線は厳密な直線探索の最急降下法に対する評価で、BB の初期試行を使う `GradientDescent` の上界ではない。
`Bfgs` と `Lbfgs` はどちらも曲率の更新を一度も減衰も省略もせず、`NonlinearCg` は 3 回再開始した。
$\kappa = 2$ では四つの方法とも 11〜12 反復で止まり、差はほとんどない。

$\kappa = 10^4$ では `GradientDescent` が 1000 反復の上限で `IterationLimit` に止まり（目的値 $8.9\times10^{-11}$、原点からの距離 $1.3\times10^{-5}$）、これは収束ではない。
同じ $\kappa$ で `NonlinearCg` は 247 反復（評価 1915 回、再開始 12 回）、`Bfgs` は 139 反復（評価 151 回）、`Lbfgs` は 758 反復（評価 831 回、減衰と省略は 0 回）で `GradientSmall` になる。
`Lbfgs` は直近の 10 組しかメモリしないので、20 個の固有値が $10^4$ 倍に広がった問題では、密な `Bfgs` の約 5.5 倍の反復を使う。
厳密な直線探索なら BFGS は二次関数で $n$ 反復以内に終わるが、$c_2 = 0.9$ の不正確な直線探索ではこの性質が成り立たないので、`Bfgs` も $n = 20$ を超える反復を使う。
対数軸から除いた目的値 0 の点は、既定と入力範囲の両端のどれでも 0 個である。

## まとめ

固有値の広がりだけを変えた二次関数では、最急降下法の反復は $\kappa$ とともに急に増え、$\kappa = 10^4$ では 1000 反復でも許容誤差に届かない。
非線形共役勾配法は反復が少ない代わりに、$c_2 = 0.1$ の強 Wolfe 条件のため一反復の評価が多く、評価回数で比べると利点が小さくなる。
密な BFGS は曲率を学習して評価回数が最も少なく、$\kappa = 10^4$ では反復も最も少ない（$\kappa = 400$ では `NonlinearCg` の 64 反復が最少）。
L-BFGS はメモリする組数が少ないぶん、$\kappa$ が大きいと BFGS より多くの反復を使う。
変数が少なければ `Bfgs`、メモリ使用量 $O(n^2)$ が許せなければ `Lbfgs` を選び、どちらでも結果は終了理由と反復上限との比で読む。
