最適化は許された点の集合から目的関数を最小にする点を探す問題である。
目的の式、制約、微分の有無、必要な結果を先に整理すると、使う解法を絞れる。
この章では局所的な停止、凸問題の最適性、有限回の大域探索、統計的な推定を区別する。
このページは章の全体で共通する型、記号、終了理由、呼び出しの形をまとめ、各アルゴリズムのページへ案内する。

## 問題の型

`ObjectiveFunction` は実数値の目的、`LeastSquaresProblem` は残差ベクトルを返す。
`ObjectiveFn` と `LeastSquaresFn` はクロージャをこれらの仕様へ接続する。
ボックス制約は `BoundedObjective`、一般の等式・不等式は `ConstrainedProblem` にまとめる。
`ConstraintFunction` と `ConstraintFn` が制約値を与え、`Constraints` に等式か不等式かを登録する。
LP・QP・MIP は係数を所有する `LpProblem`、`QpProblem`、`MipProblem` で表す。

不等式は $g(x)\le0$ の向きである。
例えば $x\ge a$ は $a-x\le0$ と書く。
行列の行・列、母数の成分順、残差の単位を、式とコールバックでそろえる。
制約の値とヤコビ行列の評価には `ConstraintsWorkspace` を再利用できる。
`ConstraintProfile` は制約の構成、`ConstraintValues` と `ConstraintJacobianStats` は評価の結果と情報を表す。

## 記号

この章では反復点を $\mathbf{x}_k$、勾配を $\mathbf{g}_k=\nabla f(\mathbf{x}_k)$、ヘッセ行列を $\nabla^2 f(\mathbf{x}_k)$ と書く。
[Newton 法と信頼領域法](newton-and-trust-region/)では[記号と用語](../../reference/)に合わせてヘッセ行列を $\mathbf{H}_k=\nabla^2 f(\mathbf{x}_k)$ と書く。
準 Newton 法のページでは Nocedal–Wright の記法に従い、ヘッセ行列の近似を $\mathbf{B}_k$、逆ヘッセ行列の近似を $\mathbf{H}_k$ と書く。
この二つは `HessianForm::Hessian`（割線条件 $\mathbf{B}\mathbf{s}=\mathbf{y}$）と `HessianForm::Inverse`（$\mathbf{H}\mathbf{y}=\mathbf{s}$）に対応する。
最小二乗のページでは残差を $\mathbf{r}$、そのヤコビ行列を $\mathbf{J}$ と書く。
$\varepsilon$ はスカラー型の機械イプシロンで、`f64` では $2^{-52} \approx 2.2 \times 10^{-16}$ である。

## 微分の取得と尺度

解析式の勾配、自動微分、有限差分は、計算の負担と誤差の性質が異なる。
利用可能な導関数はトレイトのメソッドかアダプターのクロージャで渡し、渡さない導関数の扱いは設定の `DerivativeStrategy` で決める。
既定の方針は、直線探索を使う局所法（`Bfgs`、`Lbfgs`、`GradientDescent`、`NonlinearCg`、`NewtonOptimizer`）が `AnalyticOrCentral`（解析的な導関数がなければ中心差分）、差分で導関数を補うその他の方法が `AnalyticOrForward`（なければ前進差分）である。
中心差分は勾配一つに目的の評価を $2n$ 回使い、誤差は $O(\varepsilon^{2/3})$ 程度、前進差分は $n$ 回で誤差は $O(\sqrt{\varepsilon})$ 程度である。
`DerivativeWorkspace` は微分を取得するためのメモリを準備する。
`NelderMead`、`Powell`、`Cobyla`、`Cobyqa` は値だけを使うので、この設定を持たない。
[微分の章](../../scioxide-differentiate/)と[自動微分の章](../../scioxide-ad/)で取得方法を選べる。

変数を $\mathbf{x}=D\mathbf{z}$ と尺度変換すると、$\nabla_{\mathbf{z}} f=D^\mathsf{T}\nabla_{\mathbf{x}} f$ になる。
小さい勾配の意味は座標と目的の尺度に依存する。
停止のしきい値は `scioxide-core` の許容誤差の形 $a + r \cdot s$（$a$ は絶対、$r$ は相対の許容誤差、$s$ は問題の大きさ）で、滑らかな局所法は $s = \max\bigl(1, |f(\mathbf{x})| / \max(1, \lVert\mathbf{x}\rVert_\infty)\bigr)$ を使う。
`OptimalityTolerances` は実行可能性、勾配、相補性、数値階数、双対実行可能性、ピボット、被約費用、双対ギャップの役割を分けて設定し、制約付きの方法、数理計画、検証が使う。
刻みの大きさの許容誤差は `OptimalityTolerances` に含まれず、各方式の設定（`StepTolerance` など）で与える。
[座標スケーリング・降下方向・直線探索](line-search-and-scaling/)では探索方向への影響を扱う。

## 終了理由と診断

結果型の `termination()` が返す `OptimizeTermination` が終了理由の唯一の基準であり、成否は `is_success()` で判定する。
結果型が直接提供する `is_success()` も、この終了理由に基づく。
`Ok` は結果を受け取れたことを示すが、収束とは限らない。
小さい刻み、目的変化の小ささ、停滞、上限で止まった部分結果を成功へ読み替えない。
例外は直線探索の `LineSearchResult`（`LineSearchTermination`）と、LP・QP の検証の `VerificationReport`（`VerificationStatus` と `is_accepted()`）で、それぞれ自分の状態を持つ。

`OptimizeResult` は点、目的値、勾配、終了理由、計算量と、二種類の診断を持つ。
`OptimalityDiagnostics` は元の問題の残差（主実行可能性、停留性、双対実行可能性、相補性、整数性、境界の違反、最適性のギャップ）で、`OptimizeDiagnostics` は方式ごとの観測である。
計算していない診断の `None` は残差 0 ではない。
`trust()` は返された点をどこまで確かめたかを `PartialResultTrust` で示し、方法自身の受理規則だけの `Admissible`、残差を独立に検査した `ResidualChecked`、検証済みの証明用データを持つ `CertificateVerified` などを区別する。
LP・QP の `ProgrammingResult` と、整数解・下界・ギャップを持つ `MipResult` は用途に応じて読み分ける。

### 終了理由の分類

次の表は成功でない終了理由を意味ごとにまとめ、ワンショット関数と `require_success()` がどのエラーに変えるかを示す。
エラーの列の括弧内は `ConvergenceFailure` の理由（`ConvergenceReason`）である。

| 分類 | 終了理由 | 結果が持つ点 | ワンショット関数と `require_success()` |
|---|---|---|---|
| 成功 | `Converged`、`GradientSmall` | 停止判定を満たした点 | エラーにしない |
| 進まなくなった | `StepSmall`、`FunctionChangeSmall`、`Stagnation` | 最後に受理した点 | `ConvergenceFailure`（`StepSizeLimit`、`Stagnation`） |
| 直線探索の失敗 | `LineSearchFailed(_)` | 最後に受理した点 | `ConvergenceFailure`（`NestedSolver`） |
| 回数とメモリの上限 | `IterationLimit`、`EvaluationLimit`、`ProposalLimit`、`SampleLimit`、`NodeLimit`、`DepthLimit`、`MemoryLimit` | 最後に受理した点 | `ConvergenceFailure`（`IterationLimit`、`EvaluationLimit`、`ResourceLimit`） |
| 時間上限と取り消し | `TimeLimit`、`Cancelled` | 最後に受理した点 | `ExecutionStopped` |
| 大域探索の終わり | `SearchBudgetCompleted`、`PopulationStagnation` | 観測した最良点 | `ConvergenceFailure`（`IterationLimit`、`Stagnation`）。`minimize_global` は結果を返す |
| 標本化した目的 | `EstimatedStationarity`、`NoiseLimit` | 最後に受理した点 | `ConvergenceFailure`（`Stagnation`） |
| 証明用データのある実行不能・非有界 | `Infeasible`、`Unbounded` | 最適解はなく、証明用データを持つ | `DomainError` |
| 証明用データのない実行不能・非有界 | `SuspectedInfeasible`、`SuspectedUnbounded` | 最後の反復点 | `ConvergenceFailure`（`Stagnation`、`Divergence`） |

上限や取り消しで止まっても、最初の点を受理する前なら結果は返らず、エラーになる。
`NotStarted` は `OptimizeResult::empty()` などの空の結果が持つ初期値で、解いた後の終了理由ではない。
大域探索の方法は成功を示す終了状態を返さず、予定の探索を終えた終了も `SearchBudgetCompleted` である。
標本化した目的では、ノイズのない標本で勾配の判定を満たすと `GradientSmall`、ノイズのある標本では推定に基づく `EstimatedStationarity` になる。

| 結果で確かめる量 | 分かること | 別に必要な確認 |
|---|---|---|
| 勾配・射影勾配 | 一次の改善方向が残る程度 | 曲率、局所性、変数の尺度 |
| 制約違反 | 元の制約からの隔たり | 停留性、双対実行可能性、相補性 |
| 主双対の数値検証 | 渡した点と証明データの整合 | 凸性の仮定、丸めと許容誤差 |
| MIP の下界とギャップ | 暫定整数解と探索下界の隔たり | 整数性、元の制約、探索上限 |
| 大域探索の最良標本 | 観測した範囲での最良候補 | 未探索領域、シードによるばらつき |
| 標本平均と標準誤差 | 観測された推定値の不確かさ | 標本化の仮定、独立反復数 |

## 呼び出しの形

同じ最適化を、必要な制御の量に応じていくつかの形で呼べる。
この章では引数と戻り値の形を次の名前で呼ぶ。

| 形 | 例 | 受け取るもの | 返すもの | 実行コンテキスト |
|---|---|---|---|---|
| ワンショット関数 | `minimize(f, &x0)`、`minimize_bounded(f, &x0, &bounds)`、`minimize_constrained(f, &x0, &constraints)`、`minimize_global(f, &bounds, seed)`、`minimize_scalar(f, a, b)`、`least_squares(r, &x0, m)`、`curve_fit(model, &xdata, &ydata, &p0)`、`nnls(&a, &b)`、`bvls(&a, &b, &bounds)`、`quadratic_assignment(a, b, direction)`、`LpProblem::solve`、`QpProblem::solve`、`MipProblem::solve` | 問題のデータだけ | 成功した結果 | 逐次、クロックなし |
| 手法オブジェクトの標準形式 | `Bfgs::default().minimize(&f, &x0)`、`LeastSquares::new(options)?.solve(&problem, &x0)`、`DifferentialEvolution::new(options)?.minimize(&problem, &x0)`、`Direct::new(options)?.minimize(&problem)` | 検査済みの設定を持つ値と問題 | 新しく確保した結果（成功でなくても返る） | 逐次、クロックなし |
| Plan | `QapProblemView::prepare()` で作る `QapPlan` の `solve(direction, initial)`、オプション付き形式の `solve_with_options(direction, initial, &options)` | 前処理した問題 | 新しく確保した結果 | 逐次、クロックなし |
| 出力先を指定する API | `solver.minimize_into(&f, &x0, &mut result, &mut workspace, context)`、`solve_into`、`verify_into` | 入力、出力、作業領域、最後にコンテキスト | 出力に書く | 渡したコンテキスト |

ワンショット関数は決まった手法オブジェクトを既定の設定で作って一度だけ解く自由関数（線形・二次・整数計画では問題型のメソッド）である。
`minimize` は BFGS、`minimize_bounded` は L-BFGS-B、`minimize_constrained` は SQP、`minimize_global` は差分進化、`minimize_scalar` は区間上の Brent 法、`least_squares` と `curve_fit` は Levenberg–Marquardt 法を使う。
目的は値を返すクロージャ（多変数では `Fn(&[S]) -> Result<S, SciOxideError>`、`least_squares` では残差を出力へ書く `Fn(&[S], &mut [S])`）で渡し、導関数を使う方法では差分で近似する。
差分は `minimize` が中心差分、`minimize_bounded`、`minimize_constrained`、`least_squares`、`curve_fit` が前進差分である。
`minimize`、`minimize_bounded`、`minimize_constrained`、`minimize_scalar`、`least_squares`、`curve_fit` の反復の上限は 1000 回で、停止の許容誤差は $a = r = \sqrt{\varepsilon}$ である。
`LpProblem::solve` は改訂単体法、`QpProblem::solve` は問題の形に応じた自動選択、`MipProblem::solve` は分枝限定法（探索節点 1000 個）を使う。

ワンショット関数は成功しない終了を `Err` で返し、点を持つ部分結果を返さない。
エラーへの対応は[終了理由の分類](#終了理由の分類)の表のとおりである。
例外は `minimize_global` で、差分進化が予定の世代を使い切った `SearchBudgetCompleted` と集団の停滞 `PopulationStagnation` でも結果を返す。
これらは収束を主張しない終了なので、結果の終了理由を読む。

手法オブジェクト（`Bfgs`、`LeastSquares`、`Sqp`、`Direct`、`BasinHopping` など）は検査した設定を持ち、何度でも問題を解ける。
標準形式の `minimize`、`solve`、`verify` は作業領域と結果を確保して逐次に解き、成功でない終了でも受理した最良点を持つ結果を返す。
成功だけを受け付けるなら、結果の `require_success()` で終了理由をワンショット関数と同じエラーへ変える。
`Optimizer` トレイトは同じ問題型の局所法を `dyn Optimizer` として実行時に選ぶためのものである。
前処理を持つ Plan は二次割当ての `QapPlan` だけで、行列の複製と固定されない施設の区画を $O(n^2)$ の計算量とメモリで作る。

作業領域は最新の試行と、その試行で受理した状態を記録する。
`MinimizerProgress` と `MinimizerAccepted`、Plan 法の `ProgrammingProgress` と `ProgrammingAccepted` は、この対応を読む型である。
エラーのときに呼び出し側の出力を変えないことと、最新の試行が成功したことは別である。
再開用の所有スナップショットには、BFGS・NSGA-II・確率的一階法のチェックポイント（`BfgsCheckpoint`、`Nsga2Checkpoint`、`StochasticCheckpoint`）と、単体法の `SimplexWarmStart` がある。

## 評価回数と実行環境

目的値、残差、勾配、ヤコビ行列の一回の評価は、必要な計算量が異なる。
結果の `counts()` は `scioxide-core` の `SolveCounts` を返し、目的、勾配、ヘッセ行列、制約、残差などの役割（`EvaluationRole`）ごとに、実際に許可された呼び出しを数える。
自分の分は `own()`、入れ子の求解の分は `nested()` にあり、合計は桁あふれを検査する `total()` で得る。
数値微分では一つの勾配のために複数の目的評価が必要になり、失敗した微分の試行も計数に入る。
大域探索から呼ぶ局所求解は、探索全体の上限からも回数を引く。

ブラウザーのセルは Wasm 上で逐次に動く。
スレッド実行やクロックを必要とする時間上限をセルへ設定せず、反復・評価・標本の上限を使う。
確保しない実行には作業領域と出力の事前確保に加えて、コールバックと供給側も確保しないという条件が必要である。

## まとめ

目的が滑らかで微分が得られるか、制約が箱だけか一般の等式・不等式か、残差の構造があるかで、読む数理ページが決まる。
一度だけ解くならワンショット関数が成功しない終了をエラーで返し、設定や作業領域の再利用が要るなら手法オブジェクトと出力先を指定する API を使う。
手法オブジェクトの結果は `termination().is_success()` か `require_success()` で成否を判定し、`Ok` が返ったことや目的値が小さいことを収束とみなさず、成功でなければ返った点が最後に受理した点か観測した最良点かを終了理由の分類から読み分ける。
勾配・制約違反・相補性の許容誤差は `OptimalityTolerances` で役割ごとに分かれるので、どの残差がどの尺度で小さいかを点と目的値に添えて読む。
評価回数は `counts()` の役割ごとの数から読み、数値微分の試行や大域探索の局所求解も上限に数えられることを考慮する。
解析解、元の式への代入、精度改善、別手法のいずれかで用途上の妥当性を確かめる。
