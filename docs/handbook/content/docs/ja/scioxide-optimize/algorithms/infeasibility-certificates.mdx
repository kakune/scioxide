ソルバーが「実行不能」や「非有界」と答えたとき、その答えも最適解と同じく証明用データで確かめられる。
このページでは二つの証明用データの数学的な根拠、`ProgrammingVerifier` が行う検査、外部のソルバーの出力を SciOxide の結果の形にして検査する方法、繰り返す検査での作業領域の再利用を説明する。
乗数の符号の規約と最適性の証明用データは[線形・二次計画の証明用データと検証](../programming-certificates/)にある。

## Farkas の補題

標準形の制約 $\mathbf{A}\mathbf{x}=\mathbf{b}$、$\mathbf{x}\ge\mathbf{0}$ が解を持たないことと、

$$
\mathbf{A}^\mathsf{T}\mathbf{y}\le\mathbf{0},\qquad \mathbf{b}^\mathsf{T}\mathbf{y}>0
$$

を満たす $\mathbf{y}$ が存在することは同値である（Farkas の補題）。
一方の向きは一行で示せる。
実行可能な $\mathbf{x}$ があれば $0<\mathbf{b}^\mathsf{T}\mathbf{y}=\mathbf{x}^\mathsf{T}\mathbf{A}^\mathsf{T}\mathbf{y}\le0$ となって矛盾する。
逆向きは分離超平面定理から従い、実行不能な LP には必ずこのような $\mathbf{y}$ がある。
制約に $\mathbf{y}$ の重みを掛けて足すと、どの $\mathbf{x}$ でも満たせない不等式が得られる、というのが証明用データの意味である。

SciOxide は元の問題の形（$\le$・$=$・$\ge$ の行と変数の上下限）のまま、符号の規約を満たす乗数 $\mathbf{y},\boldsymbol{\alpha}_{\mathrm{lower}},\boldsymbol{\alpha}_{\mathrm{upper}}$ で同じことを表す。
目的を 0 とした停留性

$$
\mathbf{A}^\mathsf{T}\mathbf{y}-\boldsymbol{\alpha}_{\mathrm{lower}}+\boldsymbol{\alpha}_{\mathrm{upper}}=\mathbf{0}
$$

が成り立つと、[最適性の証明用データの下界](../programming-certificates/)は「目的 0 の問題の最適値は $-\mathbf{b}^\mathsf{T}\mathbf{y}+\mathbf{l}^\mathsf{T}\boldsymbol{\alpha}_{\mathrm{lower}}-\mathbf{u}^\mathsf{T}\boldsymbol{\alpha}_{\mathrm{upper}}$ 以上」になる。
目的 0 の問題の値は 0 なので、この値が正なら実行可能な点はない。
`ProgrammingCertificate::Infeasibility(dual)` の検査は、乗数の符号が許容誤差なしに規約を満たすこと、この停留性、この値（余裕、`witness_margin()`）がギャップの許容誤差を超える正の値であることを確かめる。
乗数は検査の前に、絶対値が最大の成分が $[1,2)$ に入るよう 2 のべき乗で割って尺度をそろえる。
そのため乗数の組を 2 のべき乗倍しても余裕は変わらないが、それ以外の定数倍では余裕が最大 2 倍未満の範囲で変わる。
別の乗数の組は別の余裕を持つ。

## 非有界の証明用データ

実行可能な点 $\mathbf{x}_0$ と、全ての $t\ge0$ で $\mathbf{x}_0+t\mathbf{d}$ が実行可能なままの方向 $\mathbf{d}$（回帰方向）があり、$\mathbf{c}^\mathsf{T}\mathbf{d}<0$ なら、目的は $t\to\infty$ で $-\infty$ へ下がる。
回帰方向の条件は、$\le$ 行で $\mathbf{a}_i^\mathsf{T}\mathbf{d}\le0$、$=$ 行で $\mathbf{a}_i^\mathsf{T}\mathbf{d}=0$、$\ge$ 行で $\mathbf{a}_i^\mathsf{T}\mathbf{d}\ge0$、有限の下限を持つ成分で $d_j\ge0$、有限の上限を持つ成分で $d_j\le0$ である。
`ProgrammingCertificate::Unboundedness { point, direction }` の検査は、点の実行可能性、方向の回帰条件、目的の降下 $-\mathbf{c}^\mathsf{T}\mathbf{d}>0$（`witness_margin()`）を確かめる。
方向は検査の前に尺度をそろえる。
点の実行可能性は許容誤差の範囲で判定するが、方向の回帰条件は許容誤差なしに厳密に（違反 0 で）判定する。
凸 QP では $\mathbf{d}$ に沿った目的は $\tfrac12t^2\mathbf{d}^\mathsf{T}\mathbf{Q}\mathbf{d}+t(\mathbf{Q}\mathbf{x}_0+\mathbf{c})^\mathsf{T}\mathbf{d}+f(\mathbf{x}_0)$ なので、$\mathbf{d}^\mathsf{T}\mathbf{Q}\mathbf{d}>0$ なら下に有界である。
そのため QP の非有界の証明用データには、$(\mathbf{Q}+\mathbf{Q}^\mathsf{T})\mathbf{d}/2$ が厳密に $\mathbf{0}$ であることも要求する。
凸 QP では $\mathbf{d}^\mathsf{T}\mathbf{Q}\mathbf{d}=0$ と $\mathbf{Q}\mathbf{d}=\mathbf{0}$ が同値なので、このとき目的は $t$ の一次式 $t\,\mathbf{c}^\mathsf{T}\mathbf{d}+f(\mathbf{x}_0)$ になる。

ソルバーが実行不能や非有界の兆候を見ても、証明用データが検査を通らなければ、終了理由は `SuspectedInfeasible` や `SuspectedUnbounded` のままで、`Infeasible` や `Unbounded` にはならない。

## 外部のソルバーの結果

他のソルバーが出した点、目的値、終了理由、証明用データは `ProgrammingResult::from_candidate(x, fun, termination, iterations, evidence)` で `ProgrammingResult` の形にできる。
`evidence` は `OwnedProgrammingCertificate`（`Optimality`、`Infeasibility`、`Unboundedness`）で、乗数は `OwnedDualCertificate::new(rows, lower, upper)` で作る。
`from_candidate` が確かめるのは点と目的値が有限で空でないことだけで、作った結果は検証されていない。
この結果を `ProgrammingVerifier::verify(&problem, &result)` に渡すと、証明用データの検査に加えて、終了理由が証明用データの種類と合うことと、返した目的値が再計算した値と一致することも確かめる。
証明用データを持たない結果は棄却される。

## 作業領域の再利用

`ProgrammingVerifier::workspace(&problem)` は一つの問題に合わせて `VerificationWorkspace` を確保し、QP の凸性の検査に使う密な Cholesky 分解と固有値のメモリも含める。
この作業領域で `verify_into(&problem, claim, &mut report, &mut workspace, scope)` を呼ぶと、最初の検査も含めて確保をしない。
大きさの合わない作業領域（別の大きさの問題で作ったもの）、長さの合わない証明用データ、有限でない成分を含む証明用データは、作用素を適用する前に `InvalidInput`、`DimensionMismatch`、`NonFinite` のエラーで拒否する。
`scope` には実行コンテキストを渡し、`VerificationOptions::with_max_evaluations` の上限、取り消し、期限で止まった検査は `Incomplete` になる。
`VerificationReport::empty()` は `verify_into` の出力に使う空のレポートである。
直近の検査の記録は `VerificationWorkspace::last_attempt()` で読める。

## 在庫と出荷の約束

原料の在庫が 1 t しかないのに、二つの製品 $x_1,x_2$ [t] の合計で $r$ t 以上の出荷を約束した場合を考える。
制約は $x_1+x_2\le1$、$x_1+x_2\ge r$、$x_1,x_2\ge0$、目的は計算コスト $x_1+2x_2$ の最小化で、$r>1$ なら実行不能である。
$\le$ 行に $y_1=1$、$\ge$ 行に $y_2=-1$ を掛けて $\le$ の向きにそろえて足すと、左辺は打ち消し合って $0\le1-r$ になり、$r>1$ では矛盾する。
Farkas の補題の節の式では、余裕が $-(1\cdot1+(-1)\cdot r)=r-1$ になる。
このセルは `SimplexSolver` と `InteriorPointLp` の結果を検証し、さらにこの手計算の乗数を外部のソルバーの主張として `ProgrammingResult::from_candidate` で作り、再利用する `VerificationWorkspace` で `verify_into` に渡す。
入力は約束した出荷量 $r$ で、表の「余裕の解析値」は $r-1$ である。
最後の outcome は、`SimplexSolver` の主張（最適か実行不能）が検証を通ったかを示す。

```rust
//| id: optimize-lp-farkas-certificate
//| ref: optimize-lp-farkas-certificate
//| title: 実行不能の証明用データをソルバーと手計算の乗数で検証する
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg, scioxide-optimize]
//| inputs:
//|   promised: {"type":"range","label":"約束した出荷量 r [t]","description":"在庫 1 t を超えると実行不能になる。","min":0,"max":4,"step":0.25,"value":2}
//| cases:
//|   - {"id":"feasible","label":"r = 0.5 t（実行可能）","description":"ソルバーは Converged で最適性の証明用データを返し、手計算の Farkas 乗数は余裕 −0.5 で Rejected になる。","inputs":{"promised":0.5}}
//|   - {"id":"boundary","label":"r = 1 t（境界）","description":"実行可能で、手計算の乗数の余裕は 0 になり、正でないので Rejected になる。","inputs":{"promised":1}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"claims","path":"/rows/0/1","equals":"Infeasible"}
//|       - {"artifact":"claims","path":"/rows/0/3","equals":"Accepted"}
//|       - {"artifact":"claims","path":"/rows/0/4","approx":{"value":1,"atol":1e-9}}
//|       - {"artifact":"claims","path":"/rows/1/1","equals":"Infeasible"}
//|       - {"artifact":"claims","path":"/rows/2/3","equals":"Accepted"}
//|       - {"artifact":"claims","path":"/rows/2/4","approx":{"value":1,"atol":1e-12}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: feasible
//|     expect:
//|       - {"artifact":"claims","path":"/rows/0/1","equals":"Converged"}
//|       - {"artifact":"claims","path":"/rows/0/2","equals":"最適性"}
//|       - {"artifact":"claims","path":"/rows/0/6","approx":{"value":0.5,"atol":1e-9}}
//|       - {"artifact":"claims","path":"/rows/2/3","equals":"Rejected"}
//|       - {"artifact":"claims","path":"/rows/2/4","approx":{"value":-0.5,"atol":1e-12}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: boundary
//|     expect:
//|       - {"artifact":"claims","path":"/rows/2/3","equals":"Rejected"}
use scioxide_core::ExecutionContext;
use scioxide_linalg::Matrix;
use scioxide_optimize::{
    InteriorPointLp, LinearConstraintSense, LinearConstraints, LpProblem, OptimizeTermination,
    OwnedDualCertificate, OwnedProgrammingCertificate, ProgrammingCertificate,
    ProgrammingResult, ProgrammingVerifier, SimplexSolver, VerificationReport,
};
let general = serde_json::json!({ "significantDigits": 6 });
// 行 0: 在庫 x₁ + x₂ ≤ 1、行 1: 出荷 x₁ + x₂ ≥ r。境界なしの LpProblem は x ≥ 0。
let rows = LinearConstraints::new(
    Matrix::from_vec(2, 2, vec![1.0_f64, 1.0, 1.0, 1.0]).map_err(|e| e.to_string())?,
    vec![1.0, promised],
    vec![
        LinearConstraintSense::LessEqual,
        LinearConstraintSense::GreaterEqual,
    ],
)
.map_err(|e| e.to_string())?;
let lp = LpProblem::new(vec![1.0, 2.0])
    .and_then(|p| p.with_constraints(rows))
    .map_err(|e| e.to_string())?;
let verifier = ProgrammingVerifier::default();
let simplex = SimplexSolver::default()
    .solve(&lp)
    .map_err(|e| e.to_string())?;
let interior = InteriorPointLp::default()
    .solve(&lp)
    .map_err(|e| e.to_string())?;
// 手計算の Farkas 乗数: ≤ 行に 1、≥ 行に −1。外部のソルバーの主張として結果の形にする。
let farkas = OwnedDualCertificate::new(vec![1.0, -1.0], vec![0.0; 2], vec![0.0; 2]);
let external = ProgrammingResult::from_candidate(
    vec![0.0, 0.0],
    0.0,
    OptimizeTermination::Infeasible,
    0,
    Some(OwnedProgrammingCertificate::Infeasibility(farkas)),
)
.map_err(|e| e.to_string())?;
// 作業領域を一度だけ確保し、三つの主張を同じ領域で検査する。
let mut workspace = verifier.workspace(&lp).map_err(|e| e.to_string())?;
let mut reports = Vec::new();
for result in [&simplex, &interior, &external] {
    let mut report = VerificationReport::empty();
    verifier
        .verify_into(
            &lp,
            result,
            &mut report,
            &mut workspace,
            ExecutionContext::sequential(),
        )
        .map_err(|e| e.to_string())?;
    reports.push(report);
}
let kind = |result: &ProgrammingResult<f64>| match result.certificate() {
    Some(ProgrammingCertificate::Optimality { .. }) => "最適性",
    Some(ProgrammingCertificate::Infeasibility(_)) => "実行不能",
    Some(ProgrammingCertificate::Unboundedness { .. }) => "非有界",
    None => "なし",
};
let table: Vec<_> = [
    ("SimplexSolver", &simplex),
    ("InteriorPointLp", &interior),
    ("手計算の乗数", &external),
]
.into_iter()
.zip(&reports)
.map(|((name, result), report)| {
    (
        name,
        result.termination().to_string(),
        kind(result),
        format!("{:?}", report.status()),
        report.witness_margin(),
        promised - 1.0,
        report
            .primal_objective()
            .filter(|_| result.termination() == OptimizeTermination::Converged),
    )
})
.collect();
let columns = serde_json::json!([
    { "key": "0", "label": "主張" },
    { "key": "1", "label": "終了理由" },
    { "key": "2", "label": "証明用データの種類" },
    { "key": "3", "label": "検証状態" },
    { "key": "4", "label": "余裕 [-]", "type": "number", "format": general, "nullText": "なし" },
    { "key": "5", "label": "余裕の解析値 r − 1 [-]", "type": "number", "format": general },
    { "key": "6", "label": "最適な計算コスト [-]", "type": "number", "format": general, "nullText": "なし" }
]);
emit_table_with_columns!(
    columns,
    table,
    metadata = serde_json::json!({ "id": "claims" })
);
// 結論: SimplexSolver の主張が元の問題での検査を通ったか。
let check = &reports[0];
let outcome = if check.is_accepted() {
    Outcome::satisfied("SimplexSolver の主張が元の問題での検査を通った")
} else {
    Outcome::failed("SimplexSolver の主張が元の問題での検査を通らなかった")
};
emit_outcome!(
    outcome
        .status(simplex.termination().to_string())
        .diagnostic("停留性の残差", check.stationarity(), None)
        .diagnostic("乗数の符号の違反", check.dual_violation(), None)
);
```

既定の $r=2$ t では、`SimplexSolver` と `InteriorPointLp` がどちらも `Infeasible` を返し、その実行不能の証明用データは `Accepted` になる。
`SimplexSolver` の乗数と手計算の乗数の余裕はどちらも 1 で、解析値 $r-1$ に一致する。
`InteriorPointLp` の証明用データは別の乗数の組で、余裕は 0.42 である。
証明に必要なのは余裕が許容誤差を超える正の値であることで、その大きさは乗数の組によって変わる。

$r=0.5$ t にすると、二つのソルバーは計算コスト 0.5 の最適解と最適性の証明用データを返し、手計算の乗数は余裕 $-0.5$ で `Rejected` になる。
境界の $r=1$ t では余裕がちょうど 0 になり、正でないので `Rejected` になる。
`from_candidate` で作った結果は、終了理由を `Infeasible` と主張していても、検査を通らなければ受理されない。

## まとめ

実行不能は符号の規約を満たし目的 0 の停留性を満たす乗数で、余裕が正になることで確かめられる。
非有界は実行可能な点と、全ての制約を保ったまま目的を下げる回帰方向の組で確かめられ、QP では $\mathbf{Q}\mathbf{d}=\mathbf{0}$ も必要である。
余裕の大きさは乗数の組ごとに違うので、正であることと許容誤差を超えることだけを読む。
外部のソルバーの出力は `from_candidate` で結果の形にしてから検証し、終了理由と証明用データの種類が合わない主張は受理されない。
繰り返す検査では `VerificationWorkspace` を一度確保し、`verify_into` で確保なしに検査できる。
