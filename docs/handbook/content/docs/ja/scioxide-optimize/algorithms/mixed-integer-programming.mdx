整数条件は連続な実行可能領域を離散的な点の集合に変える。
連続問題の最適点を丸めるだけでは、制約を満たす整数解も最適値も得られない。
このページでは LP 緩和から下界を作り、分枝と切除平面で整数解との隔たりを狭める分枝切除法を導き、`BranchAndBound` の実装と結果の読み方を説明する。

## LP 緩和と分枝限定法

決定変数の一部に整数条件 $x_j \in \mathbb{Z}$（$j\in\mathcal{I}$）を課した線形計画を混合整数線形計画（MILP、以下 MIP）と呼ぶ。
MIP は一般に NP 困難である。
整数条件を外した問題を LP 緩和と呼ぶ。
緩和の実行可能領域は元の問題の実行可能領域を含むので、最小化問題では緩和の最適値 $z_{\mathrm{LP}}$ が整数最適値 $z_{\mathrm{IP}}$ の下界になる（$z_{\mathrm{LP}}\le z_{\mathrm{IP}}$）。
逆に、整数条件を満たす実行可能解の目的値はどれも $z_{\mathrm{IP}}$ の上界である。
分枝限定法はこの下界と上界の差を領域の分割で狭める方法である（Land and Doig, 1960）。

緩和の解で整数変数 $x_i$ が小数値 $v$ をとるとき、$x_i \le \lfloor v \rfloor$ と $x_i \ge \lceil v \rceil$ の二つの子問題（子節点）に分ける。
二つの子節点は $\lfloor v\rfloor<x_i<\lceil v\rceil$ の帯だけを除くので、整数解を一つも失わずに親の LP 解を除く。
子節点の実行可能領域は親に含まれるので、緩和値は子節点で下がらない。
したがって、ある節点の緩和値が暫定最良整数解（暫定解）の値以上なら、その下の部分木に暫定解より良い整数解はなく、節点を刈れる。

暫定解の目的値を $U$（上界）、未処理の節点の緩和値の最小を $L$（下界）とすると、絶対最適性ギャップは

$$
\mathrm{Gap} = U - L
$$

である。
$U$ を小さくする良い整数解と、$L$ を大きくする強い緩和の両方が、探索を短くする。

## BranchAndBound の手順

`BranchAndBound` は節点ごとに LP 緩和を解く分枝限定法で、切除平面を加えるので分枝切除法とも呼ぶ。
各節点では次を行う。

1. 節点の LP 緩和を改訂単体法で解く。
   変数の上下限だけが親と違うので、保持した行列と直前の基底から再最適化し、検証した双対の情報から節点の下界を得る。
2. 緩和が実行不能か、下界が暫定解の値を許容誤差の範囲で下回らなければ、その節点を刈る。
3. 緩和の解が整数に近ければ、整数に丸めた点を元の制約・変数の境界・目的について独立に検査し、合格した場合だけ暫定解にする。
   丸めと固定による修復（round-and-fix）も節点ごとに 1 回試す。
4. 現在の緩和の解を破る妥当な切除平面を探し、検査を通ったものを加えて再最適化する（下の節）。
5. 小数値の変数を `MipBranching` の規則で選び、二つの子節点を作る。

未処理の節点は下界の小さい順に処理する（最良下界探索）。
同じ下界の節点は作った順に処理し、分枝規則の同点は添字の小さい変数を選ぶので、同じ入力からは同じ探索木ができる。
実行コンテキストに並列エグゼキューターがあっても、木の探索は逐次に行う。

## 分枝規則

`MipBranching` は分枝する変数の選び方で、`with_branching` で指定する。

- `MostFractional`：小数部が $1/2$ に最も近い変数を選ぶ。
- `Pseudocost`：擬計算コスト（pseudocost）による評点が最大の変数を選ぶ。
- `Reliability`（既定）：擬計算コストの記録が足りない候補を強分枝で試し解きしてから、擬計算コストの評点で選ぶ。

擬計算コストは変数 $x_j$ を下（上）へ分枝したときの緩和値の増加を、動かした距離 $f_j^-=v-\lfloor v\rfloor$（$f_j^+=\lceil v\rceil-v$）で割った値の平均 $\psi_j^-$（$\psi_j^+$）である。
評点は $\min(\psi_j^-f_j^-,\ \psi_j^+f_j^+)$ で、記録がない方向の平均は 1 とみなす。
記録がまだない変数どうしでは評点が $\min(f_j^-,f_j^+)$ になるので、最も $1/2$ に近い変数が選ばれる。
両方向の悪化が大きい変数を選ぶと、二つの子節点がどちらも早く刈られやすい（Achterberg, Koch and Martin, 2005）。
`Reliability` は、小数部が $1/2$ に近い順に最大 4 個の候補について、各方向の記録が 2 回に満たなければ子節点の LP を最大 32 回のピボットで試し解き（強分枝）して記録を補ってから、同じ評点で選ぶ。
候補の数、ピボットの上限、記録の回数は `MipLimits` の `strong_candidates`、`strong_iterations`、`reliability` で変えられ、ピボットの上限を 0 にすると試し解きをしない。

## 切除平面

切除平面は整数実行可能解をすべて満たしたまま現在の LP 緩和の解を破る線形不等式である。
緩和を狭めて下界を上げるので、分枝だけより少ない節点で済むことがある。
`MipCutKind` は `BranchAndBound` が作る切除平面の種類を表す。

- `MipCutKind::IntegerRow` は、整数変数だけを整数係数で含む行 $\sum_ja_jx_j\le b$ の右辺を $\lfloor b\rfloor$ に丸める（$\ge$ 行は符号を反転してから丸める）。
  整数解では左辺が整数値になるので、丸めても整数解は除かれない（Chvátal–Gomory の丸め）。
- `MipCutKind::BinaryCover` は、全ての変数が二値で係数が正の行 $\sum_ja_jx_j\le b$（$\ge$ 行は符号を反転した形）について、$\sum_{j\in C}a_j>b$ となる被覆 $C$ から $\sum_{j\in C}x_j\le|C|-1$ を作る。
  $C$ のすべてを 1 にすると行を破るので、整数解は $C$ の少なくとも一つを 0 にする。
  被覆は緩和の解の値が大きい変数から貪欲に集め、余分な変数を除いて極小にする。

候補は緩和の解を許容誤差より大きく破るものだけを残し、導出の条件を元の行に対して独立に検査してから加える。
加える回数は節点ごとに最大 2 回（`cut_rounds`）、求解全体で最大 128 本（`max_cuts`）、非零係数は合計 8192 個（`max_cut_nonzeros`）までである。
切除平面は加えた節点とその子孫だけに残る。
見つかった候補に都合のよい不等式を加えるのではなく、全ての整数解を満たすことが導出から分かる不等式だけを加える。

## 前処理と暗黙の境界

根では保守的な前処理（presolve）を行う。
一変数だけの行を変数の境界に移し、整数変数の境界を整数に丸め、固定された変数を消去する。
どの段階も厳密な変形で、`MipPresolveMap` が元の座標に戻す写像（`reconstruct`、`active_variables`、`original_rows`、`objective_offset`）を持つ。
`with_presolve(false)` で前処理を止められる。

探索の前には、ほかの項の値の範囲が有限な行から、境界のない列の暗黙の境界も外側へ丸めて加える。
節点の下界は双対の証明用データから検証して得るので、被約費用の符号に応じた側に有限の境界が必要である。
暗黙の境界も得られない列があると、その節点の下界を検証できず、探索は `Stagnation` で止まることがある。
物理的な上限が分かっている変数には、境界を与えておく。

## ギャップと終了の読み方

`MipResult` は `absolute_gap()`、`relative_gap()`、`global_lower_bound()` と、整数性・実行可能性の違反（`integrality_violation()`、`primal_feasibility()`、`bound_violation()`）を返す。
相対ギャップは $\mathrm{Gap}/\max(1,|U|,|L|)$ である。
節点を刈る判定と探索全体の停止は、ギャップの許容誤差の絶対部分 $a$ と相対部分 $r$ を使って

$$
U-L\le a+r\max(1,|U|,|L|)
$$

で行う（`with_relaxation_tolerances`、既定は $a=r=10^{-8}$）。
許容誤差によって刈った節点の下界も全体の下界に残すので、成功したときのレポートギャップが厳密に 0 とは限らない。
節点の下界は浮動小数点で検証した双対の情報から作る推定値で、区間演算による包含区間ではない。
`certified_optimality_gap()` は厳密な算術の証明を表すので、浮動小数点の分枝限定法では常に `None` を返す。

成功の判定は `is_success()` で読む。
節点数、深さ、メモリ使用量の上限で止まった探索（`NodeLimit`、`DepthLimit`、`MemoryLimit`）や `Stagnation` は成功ではない。
その場合は暫定解があるか（`has_incumbent()`）とギャップを読み、ギャップが用途の許容範囲に入っているかを利用者が判断する。
暫定解のない結果の `x()` を整数解として使わない。

## 探索の制御

`MipProblem::new(relaxation, integer_variables)` は LP 緩和と整数変数の添字をまとめる。
`MipProblem::solve()` は既定の `BranchAndBound`（処理する節点 1000 個、各緩和のピボット 1000 回、`Reliability`、前処理あり）で解くワンショット呼び出しのメソッドで、上限で止まった探索を、暫定解があっても `ConvergenceFailure` のエラーにする。
上限で止まった探索の暫定解と下界を読むには、`BranchAndBound::default().solve(&problem)` のように手法オブジェクトで解く。
探索の上限、作業領域、未処理の節点や計算量の読み方、緩和のソルバーの差し替えは[分枝切除法の探索状態と上限](../branch-and-cut-search/)で扱う。

## ナップサック問題における整数性ギャップの実験

重量制約 $7 x_A + 11 x_B \le C$、$x_A, x_B \ge 0$ の整数のもとで利益 $11 x_A + 18 x_B$ を最大化する問題を、符号を反転した最小化として解く。
重量の単位は kg、利益の単位は点である。
各容量 $C$ について LP 緩和を `SimplexSolver` で、整数問題を `BranchAndBound` で解き、整数解は全列挙による独立な最適値と比べる。
重量あたりの利益は $B$ が $18/11\approx1.636$、$A$ が $11/7\approx1.571$ なので、LP 緩和の最適値は $B$ だけを詰めた $18C/11$ になる。
変数に上限は与えないが、`BranchAndBound` は探索の前に重量制約から $x_A\le C/7$、$x_B\le C/11$ の暗黙の上限を加える。
入力は表に詳しく出す容量 $C$ で、図は $C=0$ から 70 までを全て解く。
セルはこの 71 通りのどれかで成功でない終了が出たら、エラーとして止まる。

use scioxide_linalg::Matrix;

let build = |limit: f64| -> Result<LpProblem<f64>, String> {
    let rows = LinearConstraints::new(
        Matrix::from_vec(1, 2, vec![7.0, 11.0]).map_err(|e| e.to_string())?,
        vec![limit],
        vec![LinearConstraintSense::LessEqual],
    )
    .map_err(|e| e.to_string())?;
    LpProblem::new(vec![-11.0, -18.0])
        .map_err(|e| e.to_string())?
        .with_constraints(rows)
        .map_err(|e| e.to_string())?
        .with_bounds(Bounds::new(vec![(Some(0.0), None); 2]).map_err(|e| e.to_string())?)
        .map_err(|e| e.to_string())

    (0..=limit / 7)
        .flat_map(|a| (0..=limit / 11).map(move |b| (a, b)))
        .filter(|&(a, b)| 7 * a + 11 * b <= limit)
        .map(|(a, b)| 11 * a + 18 * b)
        .max()
        .unwrap_or(0)
};
let solve = |limit: i32| -> Result<(f64, scioxide_optimize::MipResult<f64>), String> {

        .solve(&build(limit as f64)?)
        .map_err(|e| e.to_string())?;
    let mip = BranchAndBound::<f64>::default()
        .solve(&MipProblem::new(build(limit as f64)?, vec![0, 1]).map_err(|e| e.to_string())?)
        .map_err(|e| e.to_string())?;

    if !lp.is_success() || !mip.is_success() {
        return Err(format!(
            "C = {limit}: LP {}, MIP {}",
            lp.termination(),
            mip.termination()
        ));
    }
    Ok((-lp.fun(), mip))
};

    relaxation.push([limit as f64, bound]);
    integer.push([limit as f64, -mip.fun()]);
    if (-mip.fun() - enumerate(limit) as f64).abs() > 1.0e-9 {
        mismatches += 1;

`BranchAndBound` は 13 節点を処理して `Converged` になり、レポートの絶対ギャップは 0 で、全列挙の最適値とも一致する。
その間に LP 緩和を 25 回解き、そのうち 6 回は強分枝の試し解き、6 回は丸めと固定の修復である。
この問題では切除平面は一本も加わらない。
$C = 60$ では 95（$x_A = 7, x_B = 1$）に 17 節点で到達し、ギャップは 3.18 である。
$C = 5$ では荷物を一つも入れられず、整数最適値 0 に対して LP の上界は 8.18 になる。
このとき暗黙の上限 $x_A\le5/7$、$x_B\le5/11$ が前処理で 0 に丸められて両変数が固定されるので、処理する節点は 0 個である。
$C = 0$ から 70 までの 71 通りで、`BranchAndBound` の最適値は全列挙と一致する。

図の破線（LP 緩和）は直線、階段（整数最適値）は容量の増加に対して段差を持ち、二つの差は鋸歯状に変わる。
LP の値を丸めても整数最適値は得られない。
たとえば $C=35$ の LP 解 $x_B=35/11\approx3.18$ を切り下げた $x_B=3$ の利益は 54 で、整数最適値 55 は別の品 $A$ を選んだ点にある。

## まとめ

LP 緩和から下界、検査を通った整数解から上界を得て、その差を分枝と切除平面で狭めるのが分枝切除法である。
分枝規則は既定の `Reliability` が強分枝で擬計算コストを補い、`MostFractional` と `Pseudocost` は試し解きをしない。
結果は `is_success()`、`has_incumbent()`、`absolute_gap()` と `relative_gap()` を別々に読み、`NodeLimit` などの上限で止まった場合はギャップが用途に足りるかを判断する。
レポートのギャップは浮動小数点の推定値で、`certified_optimality_gap()` は常に `None` である。
境界のない整数変数は暗黙の境界が作れないと `Stagnation` になりうるので、物理的な上限が分かっていれば与える。
