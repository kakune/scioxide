線形計画（LP）と凸二次計画（QP）の解は、点だけでなく乗数を添えると、ソルバーを信頼せずに確かめられる。
乗数が双対実行可能なら弱双対定理から最適値の下界が得られ、相補性まで成り立てば下界と目的値が一致して最適性が分かる。
このページでは SciOxide が結果に付ける証明用データの形と符号の規約、`ProgrammingVerifier` が行う検査、検証状態の読み方を説明する。
双対定理そのものの導出は[線形計画と双対性](oxref:optimize-lp-duality)にある。

## 元の問題の形での乗数

SciOxide の LP と QP は標準形に直す前の形

$$
\min_{\mathbf{x}}\ f(\mathbf{x})\quad\text{subject to}\quad \mathbf{a}_i^\mathsf{T}\mathbf{x}\ (\le,\,=,\,\ge)\ b_i\ (i=1,\dots,m),\qquad \mathbf{l}\le\mathbf{x}\le\mathbf{u}
$$

で乗数を表す（LP では $f(\mathbf{x})=\mathbf{c}^\mathsf{T}\mathbf{x}$、QP では $f(\mathbf{x})=\tfrac12\mathbf{x}^\mathsf{T}\mathbf{Q}\mathbf{x}+\mathbf{c}^\mathsf{T}\mathbf{x}$）。
行の乗数を $\mathbf{y}\in\mathbb{R}^m$、下限と上限の乗数を $\boldsymbol{\alpha}_{\mathrm{lower}},\boldsymbol{\alpha}_{\mathrm{upper}}\in\mathbb{R}^n$ とすると、停留性は

$$
\nabla f(\mathbf{x})+\mathbf{A}^\mathsf{T}\mathbf{y}-\boldsymbol{\alpha}_{\mathrm{lower}}+\boldsymbol{\alpha}_{\mathrm{upper}}=\mathbf{0}
$$

である。
符号の規約は次のとおりである。

- 等式行の乗数は符号が自由である。
- $\le$ 行の乗数は非負、$\ge$ 行の乗数は非正である。
- 境界の乗数は非負で、境界のない成分では 0 でなければならない。

この規約では $\le$ 行の乗数 $y_i\ge0$ が、右辺 $b_i$ を増やしたときの最適値の減少率（右辺 1 単位あたりの減少量）になる。
[線形計画と双対性](oxref:optimize-lp-duality)の教科書の形（$\mathbf{A}^\mathsf{T}\mathbf{y}\le\mathbf{c}$ の双対）とは $\mathbf{y}$ の符号が逆である。

乗数の符号が規約を満たすとき、実行可能な任意の $\mathbf{x}$ について LP の目的は次の下界を持つ。
停留性の残差を $\mathbf{r}=\mathbf{c}+\mathbf{A}^\mathsf{T}\mathbf{y}-\boldsymbol{\alpha}_{\mathrm{lower}}+\boldsymbol{\alpha}_{\mathrm{upper}}$ と書くと、

$$
\mathbf{c}^\mathsf{T}\mathbf{x}\ \ge\ -\mathbf{b}^\mathsf{T}\mathbf{y}+\mathbf{l}^\mathsf{T}\boldsymbol{\alpha}_{\mathrm{lower}}-\mathbf{u}^\mathsf{T}\boldsymbol{\alpha}_{\mathrm{upper}}+\sum_{j}\ \min_{l_j\le x_j\le u_j} r_j x_j
$$

である。
$\mathbf{c}=\mathbf{r}-\mathbf{A}^\mathsf{T}\mathbf{y}+\boldsymbol{\alpha}_{\mathrm{lower}}-\boldsymbol{\alpha}_{\mathrm{upper}}$ を代入し、$-y_i\mathbf{a}_i^\mathsf{T}\mathbf{x}\ge-y_ib_i$、$\boldsymbol{\alpha}_{\mathrm{lower}}^\mathsf{T}\mathbf{x}\ge\boldsymbol{\alpha}_{\mathrm{lower}}^\mathsf{T}\mathbf{l}$、$-\boldsymbol{\alpha}_{\mathrm{upper}}^\mathsf{T}\mathbf{x}\ge-\boldsymbol{\alpha}_{\mathrm{upper}}^\mathsf{T}\mathbf{u}$ を使うと導ける。
最後の和は、$r_j>0$ なら下限 $l_j$、$r_j<0$ なら上限 $u_j$ で最小になり、必要な側の境界がなければ下界は得られない。
停留性が厳密に成り立てば最後の和は 0 で、下界は双対の目的値そのものになる。
凸 QP では $-\tfrac12\mathbf{x}^\mathsf{T}\mathbf{Q}\mathbf{x}$ を加えた Wolfe 双対の値が同じ役割を持つ。

## 最適性の証明用データ

`ProgrammingCertificate` はソルバーの主張を元の問題に結びつける証明用データで、次の三つの形を持つ。

- `Optimality { point, dual }`：点と乗数の組で、最適性を主張する。
- `Infeasibility(dual)`：Farkas の乗数で、実行不能を主張する。
- `Unboundedness { point, direction }`：実行可能な点と回帰方向の組で、非有界を主張する。

このページは最適性の証明用データを扱い、残りの二つは[実行不能・非有界の証明用データと外部の結果の検証](../infeasibility-certificates/)で扱う。
最適性の証明用データでは、主実行可能性（行と境界の違反）、乗数の符号、停留性、相補性 $y_i(\mathbf{a}_i^\mathsf{T}\mathbf{x}-b_i)=0$ と境界の相補性、主目的と双対の目的の差の五つを検査する。
停留性と相補性が厳密に成り立てば目的の差は 0 になり、下界が主目的と一致するので、点が最適であると分かる。
浮動小数点では五つの量をそれぞれ許容誤差と比べる。

`DualCertificate` は乗数を借用する構造体で、行の乗数 `rows`、下限の乗数 `lower`、上限の乗数 `upper` の三つのスライスを公開フィールドとして持ち、`ProgrammingCertificate` は点とともにこれを借用する。
`OwnedDualCertificate::new(rows, lower, upper)` と `OwnedProgrammingCertificate` は同じ内容を所有する型で、点を持たない。
`ProgrammingResult` はこの所有型で証明用データを保存し、`certificate()` は点と組にした借用を返す。
長さ、有限性、符号は作成時ではなく検証の時に確かめる。

## 検証器の判定

`ProgrammingVerifier::verify(&problem, claim)` は、元の問題のデータと証明用データから残差を計算し直す。
欠けた乗数を解いて補うことはしない。
`claim` には `ProgrammingCertificate` か `&ProgrammingResult` を渡し、どちらも `ProgrammingClaim` に変換される。
`&ProgrammingResult` を渡すと、証明用データの検査に加えて、終了理由が証明用データの種類と合うことと、示された目的値が再計算した値と許容誤差内で一致することも確かめる。
証明用データのない結果は棄却される。

`VerificationReport::status()` は `VerificationStatus` の次のどれかである。

| 状態 | 意味 |
|---|---|
| `Accepted` | 証明用データが要求する検査がすべて許容誤差内で通った |
| `Rejected` | 少なくとも一つの検査が通らなかった |
| `KktOnly` | QP の KKT 条件は通ったが凸性を確かめられず、大域最小とは言えない |
| `Incomplete` | 評価回数の上限、取り消し、期限で検査が途中で止まった |

成功の判定は `is_accepted()` で読み、状態を自分で並べ直さない。
`primal_violation()`、`bound_violation()`、`dual_violation()`、`stationarity()`、`complementarity()` は各検査の最大の残差、`primal_objective()` は渡した点で計算し直した目的、`objective_gap()` は主と双対の目的の差、`dual_bound()` は上の式による下界、`witness_margin()` は実行不能・非有界の証明用データの余裕である。
下界は乗数の符号が許容誤差なしに厳密に規約を満たし、凸性を確かめられ、必要な境界があるときだけ `Some` になる。
したがって `Rejected` のレポートでも下界を持つことがあり、下界の有無と状態は別々に読む。

各検査はそれぞれの役割の許容誤差を `VerificationOptions::with_tolerances` から使う。
行と境界の残差は実行可能性、乗数の符号は双対実行可能性、停留性と Farkas の組合せは勾配、乗数と余裕の積は相補性、目的の差と証明用データの余裕はギャップ、ヘッセ行列の凸性は階数の許容誤差を使う。
各許容誤差は絶対部分と相対部分を持ち、既定はすべての役割で両方とも $\sqrt{\epsilon}$（`f64` で約 $1.5\times10^{-8}$）である。
LP と QP のソルバーの既定（両方とも $10^{-8}$）とは別に決まっている。
`with_max_evaluations` は 1 回の検査で作用素を適用する回数の上限を設ける。
検査は浮動小数点で行うので、`Accepted` は残差が許容誤差内にあることを示し、区間演算による包含区間ではない。

## 検証する問題の型

`LpProblem`、`QpProblem`、`LpVerificationProblem`、`QpVerificationProblem` が、sealed トレイト `VerificationProblem` を実装する。
`LpVerificationProblem::from_problem(&lp)` は `LpProblem` を複製せずに借用し、境界のない `LpProblem` の $\mathbf{x}\ge\mathbf{0}$ も引き継ぐ。
`LpVerificationProblem::new(objective)` から組み立てる場合は、行の係数に任意の `AdjointOperator` を使え、境界を付けない変数は自由変数になる。
同じ問題でも組み立て方で非負条件の扱いが変わるので、境界は明示しておくと読み違えない。
`LpProblem::from_view(&view, maximum_entries)` は、作用素で与えた行を列ごとに適用して疎な `LpProblem` に変換し、ソルバーへ渡せる形にする。

`QpVerificationProblem` は勾配を $(\mathbf{Q}+\mathbf{Q}^\mathsf{T})\mathbf{x}/2+\mathbf{c}$ で計算するので、非対称な $\mathbf{Q}$ はその対称部分として解釈する。
係数が見える `from_dense`、`from_sparse`、`from_problem` で作った場合は、Gershgorin の円板、Cholesky 分解、固有値の順に半正定値性を確かめ、確かめられれば `Accepted` になりうる。
対称部分の最小固有値が $-(\tau_{\mathrm{abs}}+\tau_{\mathrm{rel}}\max_{ij}|Q_{ij}|)$（$\tau_{\mathrm{abs}}$、$\tau_{\mathrm{rel}}$ は階数の許容誤差の絶対部分と相対部分）より小さければ `Rejected`、それと 0 の間の負の値なら凸性を判定できずに `KktOnly` になる。
作用素として渡す `QpVerificationProblem::new` では凸性を確かめられないので、KKT 条件がすべて通っても `KktOnly` が上限である。
`convexity_checked()` は凸性を確かめたかを返し、LP では常に真である。

繰り返す検査で作業領域を再利用する方法は[実行不能・非有界の証明用データと外部の結果の検証](../infeasibility-certificates/)にある。

## 双対の証明用データの再構成と誤った乗数

$x_1+x_2\le3$、$x_1,x_2\ge0$ の下で $-x_1-2x_2$ を最小化する。
最適点は $(0,3)$、最適値は $-6$ である。
停留性 $(-1,-2)+y(1,1)-\boldsymbol{\alpha}_{\mathrm{lower}}=\mathbf{0}$ と相補性（$x_2>0$ なので $\alpha_{\mathrm{lower},2}=0$）から、行の乗数は $y=2$、下限の乗数は $\boldsymbol{\alpha}_{\mathrm{lower}}=(1,0)$ になる。
`SimplexSolver` の結果と、入力で選んだ乗数や点の組を `ProgrammingVerifier::verify` へ渡し、元の式で検査する。
入力は頂点 $(0,3)$ と組にする乗数 $y$ と、解析乗数と組にする制約の辺上の点 $(x_1,3-x_1)$ である。
表は検証状態、主目的、双対の下界、停留性と相補性の残差を示す。

```rust
//| id: optimize-lp-independent-evidence
//| ref: optimize-lp-independent-evidence
//| title: 正しい双対と変更した乗数を元座標で検査する
//| run: reactive
//| crates: [scioxide-optimize, scioxide-linalg]
//| inputs:
//|   trial_multiplier: {"type":"range","label":"試す行の乗数 y [-]","description":"頂点 (0, 3) と組にする行の乗数を変える。","min":0,"max":3,"step":0.25,"value":1}
//|   candidate_x: {"type":"range","label":"試す点の x₁ [-]","description":"制約の辺上の点 (x₁, 3 − x₁) を解析乗数と組にする。","min":0,"max":3,"step":0.5,"value":1}
//| cases:
//|   - {"id":"exact-multiplier","label":"乗数 y = 2 と頂点 (0, 3)","description":"入力の 2 行とも解析乗数と最適点の組になり、4 行すべてが Accepted、主目的と下界はともに −6 になる。","inputs":{"trial_multiplier":2,"candidate_x":0}}
//|   - {"id":"dual-feasible","label":"乗数 y = 3","description":"停留性の残差 1 で Rejected のままだが、符号が規約を満たす乗数なので下界 −9 が得られる。","inputs":{"trial_multiplier":3}}
//|   - {"id":"far-vertex","label":"点 (3, 0)","description":"停留性は満たすが相補性の残差が 3 になり、主目的 −3 と下界 −6 の差 3 が残って Rejected になる。","inputs":{"candidate_x":3}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"reports","path":"/rows/0/4","equals":"Accepted"}
//|       - {"artifact":"reports","path":"/rows/0/3","approx":{"value":2,"atol":1e-9}}
//|       - {"artifact":"reports","path":"/rows/0/5","approx":{"value":-6,"atol":1e-9}}
//|       - {"artifact":"reports","path":"/rows/1/4","equals":"Accepted"}
//|       - {"artifact":"reports","path":"/rows/1/6","approx":{"value":-6,"atol":1e-12}}
//|       - {"artifact":"reports","path":"/rows/2/4","equals":"Rejected"}
//|       - {"artifact":"reports","path":"/rows/2/6","equals":null}
//|       - {"artifact":"reports","path":"/rows/2/7","approx":{"value":1,"atol":1e-12}}
//|       - {"artifact":"reports","path":"/rows/3/4","equals":"Rejected"}
//|       - {"artifact":"reports","path":"/rows/3/5","approx":{"value":-5,"atol":1e-12}}
//|       - {"artifact":"reports","path":"/rows/3/8","approx":{"value":1,"atol":1e-12}}
//|   - case: exact-multiplier
//|     expect:
//|       - {"artifact":"reports","path":"/rows/2/4","equals":"Accepted"}
//|       - {"artifact":"reports","path":"/rows/3/4","equals":"Accepted"}
//|   - case: dual-feasible
//|     expect:
//|       - {"artifact":"reports","path":"/rows/2/4","equals":"Rejected"}
//|       - {"artifact":"reports","path":"/rows/2/6","approx":{"value":-9,"atol":1e-12}}
//|   - case: far-vertex
//|     expect:
//|       - {"artifact":"reports","path":"/rows/3/4","equals":"Rejected"}
//|       - {"artifact":"reports","path":"/rows/3/5","approx":{"value":-3,"atol":1e-12}}
//|       - {"artifact":"reports","path":"/rows/3/8","approx":{"value":3,"atol":1e-12}}
use scioxide_linalg::Matrix;
use scioxide_optimize::{
    DualCertificate, LinearConstraintSense, LinearConstraints, LpProblem,
    LpVerificationProblem, ProgrammingCertificate, ProgrammingVerifier, SimplexSolver,
    VerificationOptions, VerificationReport,
};
let general = serde_json::json!({ "significantDigits": 6 });
let rows = LinearConstraints::new(
    Matrix::from_vec(1, 2, vec![1.0_f64, 1.0]).map_err(|e| e.to_string())?,
    vec![3.0],
    vec![LinearConstraintSense::LessEqual],
)
.map_err(|e| e.to_string())?;
let lp = LpProblem::new(vec![-1.0, -2.0])
    .and_then(|p| p.with_constraints(rows))
    .map_err(|e| e.to_string())?;
// 境界のない LpProblem の x ≥ 0 も検証用の問題に引き継がれる。
let problem = LpVerificationProblem::from_problem(&lp);
let verifier = ProgrammingVerifier::new(VerificationOptions::default());
// ソルバーの結果は &ProgrammingResult を主張として渡し、終了理由と目的値も照合させる。
let solved = SimplexSolver::default()
    .solve(&lp)
    .map_err(|e| e.to_string())?;
let solver_multiplier = match solved.certificate() {
    Some(ProgrammingCertificate::Optimality { dual, .. }) => Some(dual.rows[0]),
    _ => None,
};
let solver_report = verifier
    .verify(&problem, &solved)
    .map_err(|e| e.to_string())?;
// c + Aᵀy − α_lower + α_upper = 0 となる解析乗数は y = 2、α_lower = (1, 0)。
let (lower, upper) = ([1.0, 0.0], [0.0, 0.0]);
let inspect = |point: &[f64], y: f64| {
    verifier
        .verify(
            &problem,
            ProgrammingCertificate::Optimality {
                point,
                dual: DualCertificate {
                    rows: &[y],
                    lower: &lower,
                    upper: &upper,
                },
            },
        )
        .map_err(|e| e.to_string())
};
let edge = [candidate_x, 3.0 - candidate_x];
let cases: [(&str, [f64; 2], Option<f64>, VerificationReport<f64>); 4] = [
    (
        "SimplexSolver の結果",
        [solved.x()[0], solved.x()[1]],
        solver_multiplier,
        solver_report,
    ),
    (
        "解析乗数と頂点",
        [0.0, 3.0],
        Some(2.0),
        inspect(&[0.0, 3.0], 2.0)?,
    ),
    (
        "試す乗数と頂点",
        [0.0, 3.0],
        Some(trial_multiplier),
        inspect(&[0.0, 3.0], trial_multiplier)?,
    ),
    ("解析乗数と試す点", edge, Some(2.0), inspect(&edge, 2.0)?),
];
let table: Vec<_> = cases
    .into_iter()
    .map(|(name, point, y, report)| {
        (
            name,
            point[0],
            point[1],
            y,
            format!("{:?}", report.status()),
            report.primal_objective(),
            report.dual_bound(),
            report.stationarity(),
            report.complementarity(),
        )
    })
    .collect();
let columns = serde_json::json!([
    { "key": "0", "label": "証明用データ" },
    { "key": "1", "label": "点 x₁ [-]", "type": "number", "format": general },
    { "key": "2", "label": "点 x₂ [-]", "type": "number", "format": general },
    { "key": "3", "label": "行の乗数 y [-]", "type": "number", "format": general },
    { "key": "4", "label": "検証状態" },
    { "key": "5", "label": "主目的 [-]", "type": "number", "format": general },
    { "key": "6", "label": "双対の下界 [-]", "type": "number", "format": general, "nullText": "なし" },
    { "key": "7", "label": "停留性の残差 [-]", "type": "number", "format": general },
    { "key": "8", "label": "相補性の残差 [-]", "type": "number", "format": general }
]);
emit_table_with_columns!(
    columns,
    table,
    metadata = serde_json::json!({ "id": "reports" })
);
```

`SimplexSolver` の結果と解析乗数の組では状態が `Accepted` になり、主目的と双対の下界はともに $-6$ である。
既定の乗数 $y=1$ では停留性の残差が 1 になって状態は `Rejected`、残差 $\mathbf{r}=(-1,-1)$ を吸収する上限がないので下界も得られない。
$y=3$ にすると停留性の残差は 1 のまま `Rejected` だが、残差 $\mathbf{r}=(1,1)$ は下限 0 で最小になるので、下界 $-9$ が得られる。
これは弱双対定理による正しい下界 $-9\le-6$ で、最適性の証明にはならない。
点を $(1,2)$ に変えると停留性は満たされるが、$x_1=1>0$ に正の下限の乗数 1 が付いて相補性の残差が 1 になり、主目的 $-5$ と下界 $-6$ の差 1 が残る。

## まとめ

LP と QP の結果は、点と乗数を元の問題の形のまま `ProgrammingVerifier` に渡せば、ソルバーの内部状態に頼らずに検算できる。
乗数の符号は $\le$ 行が非負、$\ge$ 行が非正、境界が非負で、教科書の双対とは $\mathbf{y}$ の符号が逆になる。
`Accepted` は実行可能性、符号、停留性、相補性、目的の差がすべて許容誤差 $\sqrt{\epsilon}$ 内に入った数値的な判定で、区間演算による包含区間ではない。
双対の下界は `Rejected` のレポートにも付くことがあるので、状態と下界を別々に読み、下界は乗数を変えても最適値を超えないことを使って候補の質を評価できる。
QP で `KktOnly` が出たら、係数の見える形で問題を渡して凸性を確かめる。
