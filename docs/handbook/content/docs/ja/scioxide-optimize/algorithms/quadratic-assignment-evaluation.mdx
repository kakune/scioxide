二次割当て問題（QAP）の FAQ と 2-opt はヒューリスティック解法で、`Converged` で止まっても大域最適を示さない。
このページでは、全ての置換を調べられる小さな問題で厳密な最適値を求め、三つの手法オブジェクトをそれと比べる。
問題の定義、FAQ の導出、2-opt の差分の式は[二次割当てと置換の探索](../quadratic-assignment/)にある。

## 小さな問題での全探索

$n$ 施設の問題では置換が $n!$ 通りあり、$n=8$ なら 40 320 通りである。
この程度なら全ての置換の目的値

$$
F(\pi)=\sum_{i=1}^n\sum_{j=1}^n A_{ij}B_{\pi(i),\pi(j)}
$$

を直接足して、厳密な最適値と目的値の分布を得られる。
置換は Heap の方法で一つずつ作る。
Heap の方法は直前の置換から 2 要素の交換だけで次の置換を作り、$n!$ 通りを重複なく列挙する。

題材は、流量 $A_{ij}$ を 0〜9 の整数（対角は 0、非対称）、地点を $10\times10$ の格子上の無作為な点、距離 $B_{kl}$ をその Manhattan 距離とした施設配置である。
流量と地点は乱数のシードから作る。
目的値の単位は流量と距離の積で、最小化は輸送費、最大化は重なり（グラフ照合）にあたる。
次のセルは問題を作って全ての置換を調べ、問題と全ての目的値を次のセルへ渡す。
入力は施設数 $n$、乱数のシード、最適化の向きで、表は置換の数、最適値、最悪値、平均値、最適値をとる置換の数を示す。

```rust
//| id: optimize-qap-exhaustive
//| ref: optimize-qap-exhaustive
//| title: シードから作った QAP の全ての置換の目的値を求める
//| run: reactive
//| crates: [scioxide-random]
//| exports: [size, maximize, flow, distance, optimum, values]
//| inputs:
//|   size: {"type":"range","label":"施設数 n [個]","min":5,"max":8,"step":1,"value":8}
//|   seed: {"type":"range","label":"乱数のシード [-]","min":1,"max":100,"step":1,"value":3}
//|   direction: {"type":"select","label":"最適化の向き","options":["最小化（輸送費）","最大化（重なり）"],"value":"最小化（輸送費）"}
//| cases:
//|   - {"id":"maximize","label":"最大化（重なり）","description":"同じ問題の最大値は 2182 である。","inputs":{"direction":"最大化（重なり）"}}
//|   - {"id":"five-facilities","label":"施設数 n = 5","description":"120 通りの最小値は 508 である。","inputs":{"size":5}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"instance","path":"/rows/0/1","equals":40320}
//|       - {"artifact":"instance","path":"/rows/0/2","approx":{"value":1560,"atol":0.5}}
//|   - case: maximize
//|     expect:
//|       - {"artifact":"instance","path":"/rows/0/2","approx":{"value":2182,"atol":0.5}}
//|   - case: five-facilities
//|     expect:
//|       - {"artifact":"instance","path":"/rows/0/1","equals":120}
//|       - {"artifact":"instance","path":"/rows/0/2","approx":{"value":508,"atol":0.5}}
use scioxide_random::{SeedableRng, Xoshiro256StarStar, uniform_index};

let fixed1 = serde_json::json!({ "fractionDigits": 1 });
let n = size.round() as usize;
let maximize = direction.starts_with("最大化");
let mut rng = Xoshiro256StarStar::from_seed(seed.round() as u64);
// 流量 A は 0〜9 の整数で対角が 0、地点は 10×10 の格子点、B はその Manhattan 距離。
let mut flow = vec![0.0; n * n];
for i in 0..n {
    for j in 0..n {
        if i != j {
            flow[i * n + j] = uniform_index(10, &mut rng).map_err(|e| e.to_string())? as f64;
        }
    }
}
let mut sites = Vec::with_capacity(n);
for _ in 0..n {
    let x = uniform_index(10, &mut rng).map_err(|e| e.to_string())?;
    let y = uniform_index(10, &mut rng).map_err(|e| e.to_string())?;
    sites.push((x, y));
}
let distance: Vec<f64> = (0..n * n)
    .map(|k| {
        let ((ax, ay), (bx, by)) = (sites[k / n], sites[k % n]);
        (ax.abs_diff(bx) + ay.abs_diff(by)) as f64
    })
    .collect();
// 元の定義の二重和。
let double_sum = |p: &[usize]| -> f64 {
    (0..n)
        .map(|i| {
            (0..n)
                .map(|j| flow[i * n + j] * distance[p[i] * n + p[j]])
                .sum::<f64>()
        })
        .sum()
};
// Heap の方法で n! 通りの置換を一つずつ作り、目的値を記録する。
let mut perm: Vec<usize> = (0..n).collect();
let mut counter = vec![0_usize; n];
let mut values = vec![double_sum(&perm)];
let mut level = 1;
while level < n {
    if counter[level] < level {
        let other = if level % 2 == 0 { 0 } else { counter[level] };
        perm.swap(other, level);
        values.push(double_sum(&perm));
        counter[level] += 1;
        level = 1;
    } else {
        counter[level] = 0;
        level += 1;
    }
}
let (low, high) = values
    .iter()
    .fold((f64::INFINITY, f64::NEG_INFINITY), |(l, h), &v| {
        (l.min(v), h.max(v))
    });
let (optimum, worst) = if maximize { (high, low) } else { (low, high) };
let mean = values.iter().sum::<f64>() / values.len() as f64;
let ties = values.iter().filter(|&&v| v == optimum).count();
let columns = serde_json::json!([
    { "key": "0", "label": "施設数 n [個]", "type": "integer" },
    { "key": "1", "label": "置換の数 [通り]", "type": "integer" },
    { "key": "2", "label": "最適値 [流量×距離]", "type": "number", "format": fixed1 },
    { "key": "3", "label": "最悪値 [流量×距離]", "type": "number", "format": fixed1 },
    { "key": "4", "label": "平均値 [流量×距離]", "type": "number", "format": fixed1 },
    { "key": "5", "label": "最適値をとる置換 [通り]", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    vec![(n, values.len(), optimum, worst, mean, ties)],
    metadata = serde_json::json!({ "id": "instance" })
);
export!(size, &n);
export!(maximize, &maximize);
export!(flow, &flow);
export!(distance, &distance);
export!(optimum, &optimum);
export!(values, &values);
```

既定の $n=8$、シード 3 では、40 320 通りの最小値は 1560、最大値は 2182、平均は 1827.5 で、最小値をとる置換は一つだけである。
最大化を選ぶと、同じ問題の最適値は 2182 になる。
$n=5$ の 120 通りでは最小値は 508 で、二つの置換がこの値をとる。

## 三つの方法と厳密な最適値

次のセルは前のセルの問題を `QapMethod::Faq`、`TwoOpt`、`FaqThenTwoOpt` で解き、全探索の最適値と比べる。
どの方法も同じ `QapPlan` から `solve_with_options` で解き、初期置換は与えない。
入力は追加の再開始の回数だけで、問題は前のセルの入力で変わる。
表の「二重和の再計算」は示された置換を元の定義に代入してセルの中で足した独立な検算である。
順位は全ての置換のうちレポート値より良いものの数に 1 を足した値とする。
ヒストグラムは全ての置換の目的値の分布で、最適値と各手法オブジェクトを縦線で示す。

```rust
//| id: optimize-qap-faq-two-opt
//| ref: optimize-qap-faq-two-opt
//| title: FAQ と 2-opt の置換を全探索の最適値と比べる
//| run: reactive
//| crates: [scioxide-linalg, scioxide-optimize]
//| dependsOn:
//|   instance: optimize-qap-exhaustive
//| inputs:
//|   restarts: {"type":"range","label":"追加の再開始 [回]","description":"乱数のシードから作る置換で始める試行を加える。","min":0,"max":5,"step":1,"value":0}
//| cases:
//|   - {"id":"restarts-3","label":"追加の再開始 3 回","description":"TwoOpt は無作為な置換からの再開始で最適値 1560 に達するが、FaqThenTwoOpt は 1574（差 14）のまま、Faq は 1620（差 60）のままである。","inputs":{"restarts":3}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"methods","path":"/rows/0/1","approx":{"value":1620,"atol":0.5}}
//|       - {"artifact":"methods","path":"/rows/0/2","approx":{"value":1620,"atol":0.5}}
//|       - {"artifact":"methods","path":"/rows/1/1","approx":{"value":1575,"atol":0.5}}
//|       - {"artifact":"methods","path":"/rows/2/1","approx":{"value":1574,"atol":0.5}}
//|       - {"artifact":"methods","path":"/rows/2/2","approx":{"value":1574,"atol":0.5}}
//|       - {"artifact":"methods","path":"/rows/2/3","approx":{"value":14,"atol":0.5}}
//|       - {"artifact":"methods","path":"/rows/0/4","equals":253}
//|       - {"artifact":"methods","path":"/rows/0/5","range":{"min":0}}
//|       - {"artifact":"methods","path":"/rows/1/5","equals":null}
//|       - {"artifact":"methods","path":"/rows/1/6","equals":"Converged"}
//|   - case: restarts-3
//|     expect:
//|       - {"artifact":"methods","path":"/rows/1/1","approx":{"value":1560,"atol":0.5}}
//|       - {"artifact":"methods","path":"/rows/1/3","approx":{"value":0,"atol":0.5}}
//|       - {"artifact":"methods","path":"/rows/1/4","equals":1}
//|       - {"artifact":"methods","path":"/rows/2/1","approx":{"value":1574,"atol":0.5}}
use scioxide_linalg::Matrix;
use scioxide_optimize::{QapDirection, QapMethod, QapOptions, QapProblemView};

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let fixed1 = serde_json::json!({ "fractionDigits": 1 });
let n = instance["size"].as_u64().ok_or("施設数がない")? as usize;
let maximize = instance["maximize"].as_bool().ok_or("向きがない")?;
let optimum = instance["optimum"].as_f64().ok_or("最適値がない")?;
let flow: Vec<f64> =
    serde_json::from_value(instance["flow"].clone()).map_err(|e| e.to_string())?;
let distance: Vec<f64> =
    serde_json::from_value(instance["distance"].clone()).map_err(|e| e.to_string())?;
let values: Vec<f64> =
    serde_json::from_value(instance["values"].clone()).map_err(|e| e.to_string())?;
// 独立な検算: 元の定義の二重和を直接足す。
let double_sum = |p: &[usize]| -> f64 {
    (0..n)
        .map(|i| {
            (0..n)
                .map(|j| flow[i * n + j] * distance[p[i] * n + p[j]])
                .sum::<f64>()
        })
        .sum()
};
let better = |a: f64, b: f64| if maximize { a > b } else { a < b };
let a = Matrix::from_vec(n, n, flow.clone()).map_err(|e| e.to_string())?;
let b = Matrix::from_vec(n, n, distance.clone()).map_err(|e| e.to_string())?;
let plan = QapProblemView::new(a.view(), b.view(), &[])
    .map_err(|e| e.to_string())?
    .prepare()
    .map_err(|e| e.to_string())?;
let sense = if maximize {
    QapDirection::Maximize
} else {
    QapDirection::Minimize
};
let mut rows = Vec::new();
let mut marks =
    vec![serde_json::json!({"kind": "line", "axis": "x", "value": optimum, "label": "最適値"})];
for (name, method) in [
    ("Faq", QapMethod::Faq),
    ("TwoOpt", QapMethod::TwoOpt),
    ("FaqThenTwoOpt", QapMethod::FaqThenTwoOpt),
] {
    let options = QapOptions::default()
        .with_method(method)
        .with_max_workspace_bytes(1_000_000)
        .with_restarts(restarts.round() as usize);
    let result = plan
        .solve_with_options(sense, None, &options)
        .map_err(|e| e.to_string())?;
    let (Some(p), Some(reported)) = (result.permutation(), result.objective()) else {
        return Err(format!("{name}: 候補なし（{}）", result.termination()));
    };
    let rank = 1 + values.iter().filter(|&&v| better(v, reported)).count();
    marks.push(
        serde_json::json!({"kind": "line", "axis": "x", "value": reported, "label": name}),
    );
    rows.push((
        name,
        reported,
        double_sum(p),
        (reported - optimum).abs(),
        rank,
        result.fw_gap(),
        result.termination().to_string(),
    ));
}
// 全ての置換の目的値を 24 区間の度数にする。
let (low, high) = values
    .iter()
    .fold((f64::INFINITY, f64::NEG_INFINITY), |(l, h), &v| {
        (l.min(v), h.max(v))
    });
let width = (high - low) / 24.0;
let mut counts = vec![0_usize; 24];
for &v in &values {
    counts[(((v - low) / width) as usize).min(23)] += 1;
}
let histogram: Vec<[f64; 3]> = counts
    .iter()
    .enumerate()
    .map(|(i, &c)| {
        [
            low + i as f64 * width,
            low + (i + 1) as f64 * width,
            c as f64,
        ]
    })
    .collect();
emit_histogram!(
    &histogram,
    options = &serde_json::json!({
        "xLabel": "目的値 F(π) [流量×距離]",
        "yLabel": "置換の数 [個]",
        "annotations": marks
    })
);
let columns = serde_json::json!([
    { "key": "0", "label": "手法" },
    { "key": "1", "label": "レポートの目的値 [流量×距離]", "type": "number", "format": fixed1 },
    { "key": "2", "label": "二重和の再計算 [流量×距離]", "type": "number", "format": fixed1 },
    { "key": "3", "label": "最適値との差 [流量×距離]", "type": "number", "format": fixed1 },
    { "key": "4", "label": "全置換中の順位 [位]", "type": "integer" },
    { "key": "5", "label": "fw_gap [流量×距離]", "type": "number", "format": sci3, "nullText": "なし" },
    { "key": "6", "label": "終了理由" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "methods" })
);
```

既定の問題では、Faq は 1620（差 60、順位 253）、TwoOpt は恒等置換から 1575（差 15、順位 10）、FaqThenTwoOpt は 1574（差 14、順位 8）で、三つとも終了理由は `Converged` である。
`Converged` は FAQ の刻みと 2-opt の局所最適の条件が満たされたことを表し、最適値に達したことは表さない。
Faq の `fw_gap` は 12.6 で 0 ではないが、刻みの大きさが閾値を下回ったので止まっている。
レポートの目的値と二重和の再計算は一致し、ヒストグラムでは三つの値が分布の下側の端に集まる。

追加の再開始を 3 回にすると、無作為な置換から始めた TwoOpt が最適値 1560 に達し、FaqThenTwoOpt は 1574 のまま変わらない。
再開始を 5 回にすると、FaqThenTwoOpt も 1564（差 4、順位 2）まで下がる。
前のセルで最大化を選ぶと、Faq は `fw_gap` = 0 の端点で止まりながら最適値 2182 より 52 小さい 2130（順位 32）にとどまり、TwoOpt と FaqThenTwoOpt は 2182 に達する。
ギャップが 0 でも、置換の最適性は示されない。
$n=5$ では FaqThenTwoOpt が最適値 508 に達し、Faq は 527（順位 7）、TwoOpt は 517（順位 3）である。
シードを変えると FAQ の方が 2-opt より良い問題も現れ、シード 1 では Faq が 1607、TwoOpt が 1617、最適値は 1601 である。
シード 1 の Faq は FAQ の反復上限 30 回に達して、`IterationLimit` で止まる。

## レポート値の検算

`QapResult` は、完了した試行があれば `permutation()` に検査済みの置換を、`objective()` に元の行列で計算し直したその目的値を返す。
それでも、利用者の側で置換を元の定義に代入した値と比べると、行列の向き（`permutation[i]` は `a` の番号 $i$ に割り当てた `b` の番号）の取り違えを見つけられる。
`QapPlan::objective(permutation)` も、置換を元の問題へ代入して目的値を返す API で、長さが違うか固定した組に反する置換は `InvalidInput` になる。

`fw_gap()` は選ばれた試行の最後の FAQ の反復での Frank–Wolfe ギャップで、緩和の上での一次の停留性の目安である。
置換の最適値との差の上界でも、緩和の下界でもない。
`relaxation_objective()` はその反復で更新した後の点での緩和の目的値で、一般に非凸な緩和の値なので、元の最小値の下界として使えない。
完了した試行がない結果の `permutation()` と `objective()` は `None` で、計算コスト 0 の解とは読まない。
`TwoOpt` は FAQ を使わないので、`fw_gap()` と `relaxation_objective()` は `None` になる。

## 大きな問題での評価

全探索ができない大きさでは、出典のある既知の最適値（QAPLIB など）との差、再開始による値の改善、異なる手法オブジェクトの比較で結果を評価する。
目的値が同じ置換は一つとは限らないので、異なるシードからの探索で置換が一致しなくても誤りとは限らない。
地点の配置に対称性があれば、対称な置換は同じ目的値になる。
置換の完全一致だけを検算にせず、固定した対応、目的値、既知値との差を確かめる。

## まとめ

全探索できる小さな問題では、FAQ と 2-opt の値の最適値との差と、全ての置換の中での順位を直接測れる。
この例では三つの方法がどれも `Converged` で止まりながら最適値に届かず、終了理由と `fw_gap` = 0 は大域最適性を示さない。
再開始の回数や方法の組み合わせで値が改善するかを確かめ、改善が止まったことも最適性の証拠にはしない。
レポートの目的値は元の二重和か `QapPlan::objective` で計算し直し、`fw_gap` と `relaxation_objective` を置換の最適値の界として読まない。
大きな問題では、出典のある既知値と再開始による改善で結果を評価する。
