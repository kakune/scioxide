$n$ 個の施設を $n$ 個の地点へ一つずつ置く。
施設 $i$ から施設 $j$ への流量を $A_{ij}$、地点 $k$ から地点 $l$ への距離を $B_{kl}$ とし、施設 $i$ を地点 $\pi(i)$ に置くときの輸送費を

$$
F(\pi)=\sum_{i=1}^n\sum_{j=1}^n A_{ij}B_{\pi(i),\pi(j)}
$$

と定める。
これが Koopmans–Beckmann 形の二次割当て問題（quadratic assignment problem: QAP）である。
$\pi$ は全単射なので、どの施設も別々の地点へ置く。
対称な行列でもこの式は往復の二項を数えるため、片方向の和で定義した計算コストと比較する場合は係数をそろえる。

各施設の計算コストが置いた地点だけで決まる線形割当て問題と違い、QAP の計算コストは二つの施設の組の置き場所で決まる。
QAP は NP 困難であり、定数倍の近似解を求めることも一般には NP 困難である（Sahni と Gonzalez, 1976）。
候補は $n!$ 通りあり、$n=12$ で約 $4.8\times10^8$、$n=20$ で約 $2.4\times10^{18}$ になる。
このページの方法はどれも良い置換を探すヒューリスティック解法で、大域最適を保証しない。

## 置換行列による表現

置換 $\pi$ を、$X_{ik}=1$（$\pi(i)=k$ のとき）、それ以外は $0$ の置換行列 $X$ で表す。
$(XBX^T)_{ij}=B_{\pi(i),\pi(j)}$ なので、目的は Frobenius 内積 $\langle U,V\rangle=\sum_{ij}U_{ij}V_{ij}$ を使って

$$
F(X)=\langle A,\,XBX^T\rangle=\operatorname{tr}(A^TXBX^T)
$$

と書ける。
`QapDirection::Minimize` はこの値を最小化し、輸送費のような計算コストに使う。
`QapDirection::Maximize` は最大化し、二つのグラフの隣接行列 $A,B$ の重なりを最大にするグラフ照合（graph matching）に使う。
施設 $i$ を地点 $k$ に固定する組を与えると、残りの $k_{\mathrm{free}}=n-|\text{固定}|$ 個の自由な施設と地点だけを探す。
グラフ照合では、このような既知の対応をシード（seed）と呼ぶ。

## FAQ の緩和

置換行列の各行各列の和は 1 で、成分は 0 または 1 である。
成分を非負実数まで緩めると二重確率行列の集合

$$
\mathcal D=\{P\in\mathbb R^{n\times n}: P\ge0,\ P\mathbf 1=\mathbf 1,\ P^T\mathbf 1=\mathbf 1\}
$$

になる。
Birkhoff–von Neumann の定理により、$\mathcal D$ の端点は置換行列に限られる。
FAQ（Fast Approximate QAP, Vogelstein ほか 2015）は $f(P)=\langle A,PBP^T\rangle$ を $\mathcal D$ の上で Frank–Wolfe 法により改善し、最後に置換へ戻す。

### 勾配と Frank–Wolfe 方向

$P$ に摂動 $E$ を加えると

$$
f(P+E)=f(P)+\langle A,EBP^T\rangle+\langle A,PBE^T\rangle+\langle A,EBE^T\rangle
$$

で、一次の二項はそれぞれ $\langle AP B^T,E\rangle$、$\langle A^TPB,E\rangle$ に等しい。
したがって勾配は

$$
\nabla f(P)=APB^T+A^TPB
$$

であり、$A,B$ が対称なら $2APB$ になる。
Frank–Wolfe 法は一次近似を $\mathcal D$ の上で最小化する点

$$
Q=\arg\min_{Q\in\mathcal D}\ \langle\nabla f(P),Q\rangle
$$

を方向の終点にする。
線形関数の最小値は多面体の端点で達成されるので、$Q$ は置換行列から選べ、この部分問題は費用行列 $\nabla f(P)$ の線形割当て問題になる。
最大化では $\langle\nabla f(P),Q\rangle$ を最大にする割当てを選ぶ。

### 厳密な直線探索

$f$ は $P$ の二次式なので、$D=Q-P$ に沿った値は $t$ の二次式

$$
f(P+tD)=f_0+g\,t+c\,t^2,\qquad g=\langle\nabla f(P),D\rangle,\quad c=f(Q)-f_0-g
$$

になる（$f_0=f(P)$）。
$c$ は $t=1$ の値 $f(Q)$ から求まり、$f(Q)$ は置換 $Q$ について $O(k_{\mathrm{free}}^2)$ で計算できる。
最小化で $c>0$ なら $t^*=\min(\max(-g/(2c),0),1)$、そうでなければ $f_0$ と $f(Q)$ の良い方の端点 $t\in\{0,1\}$ を選び、$P\leftarrow P+t^*D$ と更新する。

### Frank–Wolfe ギャップと停止

$\mathrm{gap}(P)=\max\bigl(0,\,-\langle\nabla f(P),Q-P\rangle\bigr)$ を Frank–Wolfe ギャップと呼ぶ（最大化では符号を反転する）。
$f$ が凸なら $f(P)-\min_{\mathcal D}f\le\mathrm{gap}(P)$ だが、$A,B$ が一般の行列では $f$ は凸でも凹でもない。
このため `fw_gap` は $\mathcal D$ の上での一次の停留性の目安であり、置換の最適値との差や緩和の下界ではない。
緩和後の目的も一般には非凸であるため、得られた緩和値は元の最小値の下界として保証されない。

反復は、更新量 $\|t^*D\|_F/\sqrt{k_{\mathrm{free}}}$ が刻みの閾値（既定 0.03）以下になれば止まり、反復の上限（既定 30 回）に達すれば `IterationLimit` で止まる。
初期点は、最初の試行で初期置換を与えなければ重心 $J/k_{\mathrm{free}}$（全成分 $1/k_{\mathrm{free}}$）である。
初期置換を与えた最初の試行と、追加の再開始では、重心と置換行列の平均を初期点にする。
再開始の置換は `with_seed` のシードに再開始の番号を足したシードから無作為に作る。

### 置換への射影

最後の $P$ に最も近い置換行列を Frobenius ノルムで選ぶ。
置換行列は $\|X\|_F^2=n$ を満たすので $\|P-X\|_F^2=\|P\|_F^2+n-2\langle P,X\rangle$ となり、最近点は $\langle P,X\rangle$ を最大にする線形割当てで求まる。
一回の反復の計算コストは勾配の二つの行列積の $O(k_{\mathrm{free}}^3)$ と、二分ヒープの Dijkstra 法を使う最短増加路法による密な線形割当ての $O(k_{\mathrm{free}}^3\log k_{\mathrm{free}})$ である。
メモリは行列と作業配列の $O(n^2)$ である。

## 2-opt と固定した対応

2-opt は二施設の地点を交換したときの目的の差を調べ、改善する交換を繰り返す。
施設 $i,j$ の地点 $u=\pi(i)$、$v=\pi(j)$ を入れ替えると、変わるのは $i$ か $j$ を含む項だけで、差は

$$
\Delta_{ij}=\sum_{m\ne i,j}\Bigl[(A_{im}-A_{jm})(B_{v\,\pi(m)}-B_{u\,\pi(m)})+(A_{mi}-A_{mj})(B_{\pi(m)\,v}-B_{\pi(m)\,u})\Bigr]+R_{ij}
$$

になる。
$R_{ij}=(A_{ii}-A_{jj})(B_{vv}-B_{uu})+(A_{ij}-A_{ji})(B_{vu}-B_{uv})$ は、二つの施設自身の対角項と互いの間の項である。
一回の交換の検査は $O(n)$、全ての組を調べる一巡は $O(n^3)$ である。

固定した組の施設は交換の対象にしない。
実装は自由な施設の組 $(i,j)$ を辞書式の順に調べ、改善する最初の交換を受け入れる（最初の改善）。
受け入れた交換では二重和を $O(n^2)$ で計算し直して改善を確かめ、先頭から調べ直す。
どの交換も改善しなくなれば 2-opt の局所最適で `Converged`、交換の検査の上限（既定 100 000 回）に達すれば `IterationLimit` で止まる。
交換による改善がなくても、三つ以上を同時に動かすと改善する場合がある。
全探索は $n!$ 通りになるため、小規模な検算と実用的なヒューリスティック解法を使い分ける。

## 二次割当ての API

`QapProblemView::new(a, b, fixed)` は同じ大きさの二つの正方行列と、固定した組 `(施設, 地点)` の列を借用する。
形が合わないか、固定した組が範囲外か同じ番号を繰り返すと `InvalidInput`、成分が NaN か無限大なら `NonFinite` になる。
結果の置換は `permutation[i]` が `a` の番号 $i$ に割り当てた `b` の番号を表す。
`prepare()` は二つの行列を複製し、固定されない施設と地点の区画を $O(n^2)$ の計算量とメモリで前処理した `QapPlan` を作る。
`prepare_with_limit(max_bytes)` は Plan と作業領域が `max_bytes` に収まらなければ、確保の前に `ResourceLimit` を返す。
疎な行列からは `QapPlan::from_sparse(a, b, fixed)`（欠けた成分は 0）と `from_sparse_with_limit` で作る。
`QapPlan::workspace_bytes()` は Plan と作業領域一つのメモリ使用量の上界を返す。

最適化の向き `QapDirection`（`Minimize` か `Maximize`）は求解のたびに引数で渡す。
`solve(direction, initial)` は既定の `QapOptions` で解き、作業領域と結果を内部で確保する。
`initial` は最初の試行の初期置換で、長さが違うか固定した組に反すると `InvalidInput` になる。
設定を変えるときは `solve_with_options(direction, initial, &options)` を使う。

`QapOptions::default()` は FAQ の後に 2-opt（`QapMethod::FaqThenTwoOpt`）、FAQ の反復 30 回、交換の検査 100 000 回、刻みの閾値 0.03、追加の再開始 0 回、シード 42、逐次実行、作業領域の上限なし（`usize::MAX` バイト）である。
`with_method`、`with_max_fw_iterations`、`with_max_swap_checks`、`with_step_tolerance`、`with_restarts`、`with_seed`、`with_execution`、`with_max_workspace_bytes` で変え、どの設定メソッドも失敗しない。
作業領域の上限は求解のたびに確かめ、0 バイトなら `InvalidInput`、必要量が上限を超えれば `ResourceLimit` になる。
`QapMethod` は `Faq`（FAQ と射影）、`TwoOpt`（初期置換からの交換探索だけ）、`FaqThenTwoOpt`（FAQ の射影から交換探索）の三つである。
`TwoOpt` の最初の試行は、初期置換を渡さなければ恒等置換（自由な施設を番号順に自由な地点へ置く置換）から始まる。

`QapPlan::workspace(&options)` で `QapWorkspace` を準備し、出力先を指定する API の `solve_into(direction, initial, &options, &mut result, &mut workspace, scope)` を呼ぶ。
`result` は `QapResult::empty(n)` で作る。
逐次実行（既定）では再開始を順に同じ作業領域で行い、最初の呼び出しも含めて確保をしない。
`with_execution` で並列の方針を選ぶと、再開始を実行コンテキストのエグゼキューターで並べて行い、再開始ごとの作業領域と結果がすべてメモリ使用量の上限に収まる必要がある。
結果は再開始の番号の順に比べて、最良のものを選ぶ。

`QapResult` は `permutation()`、`objective()`、選んだ試行の `relaxation_objective()` と `fw_gap()`、全試行の合計の `fw_iterations()` と `swap_checks()`、選んだ試行の番号 `selected_restart()`、`termination()` を返す。
`termination()` の `Converged` は、方式に含まれる各段階（FAQ の刻みの判定と 2-opt の局所最適）が全ての試行で停止条件を満たしたことを表し、大域最適の証明ではない。
選んだ試行が停止条件を満たしていても、ほかの試行が上限で止まれば `IterationLimit` になる。
`IterationLimit` は FAQ の反復か交換の検査の上限、または親のコンテキストの反復上限に達したことを表し、`ProposalLimit`、`Cancelled`、`TimeLimit` は親のコンテキストの上限や停止を表す。
`QapPlan::solve` 系は上限に達しても置換と目的値を持つ結果を返す。
ワンショット関数 `quadratic_assignment(a, b, direction)` は、固定した組のない問題を既定の設定で解き、上限による停止を `ConvergenceFailure` のエラーにする。
上限で止まった結果も読むには `QapPlan` を使う。

## 固定した組と作業領域の再利用

固定した組が最適値をどう変えるかと、作業領域を再利用する呼び出しの形を、7 施設の小さな問題で確かめる。
流量 $A_{ij}$ は 0〜9 の整数（対角は 0、非対称）、地点は $10\times10$ の格子上の無作為な点、距離 $B_{kl}$ はその Manhattan 距離で、どちらも乱数のシードから作る。
入力は施設 0 を固定する地点と乱数のシードである。
セルは Plan と作業領域を一度だけ作り、同じ作業領域で最小化と最大化を `solve_into` で解く。
レポート値は `QapPlan::objective` で計算し直し、固定した組を満たす全ての置換（固定なしで $7!=5040$ 通り、固定ありで $6!=720$ 通り）を調べた最適値と比べる。

```rust
//| id: optimize-qap-fixed-pairs
//| ref: optimize-qap-fixed-pairs
//| title: 固定した組を付けた QAP を同じ作業領域で最小化と最大化する
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg, scioxide-optimize, scioxide-random]
//| inputs:
//|   pinned: {"type":"select","label":"施設 0 を固定する地点","options":["固定しない","地点 0","地点 1","地点 2","地点 3","地点 4","地点 5","地点 6"],"value":"固定しない"}
//|   seed: {"type":"range","label":"乱数のシード [-]","min":1,"max":20,"step":1,"value":3}
//| cases:
//|   - {"id":"pin-site-3","label":"施設 0 を地点 3 に固定","description":"固定した組を満たす 720 通りの中で最適値を探し、示された置換の施設 0 は地点 3 になる。","inputs":{"pinned":"地点 3"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"directions","path":"/rows/0/2","range":{"min":0,"max":1e-9}}
//|       - {"artifact":"directions","path":"/rows/1/2","range":{"min":0,"max":1e-9}}
//|       - {"artifact":"directions","path":"/rows/0/4","range":{"min":0}}
//|       - {"artifact":"directions","path":"/rows/1/4","range":{"min":0}}
//|       - {"artifact":"directions","path":"/rows/0/6","equals":5040}
//|   - case: pin-site-3
//|     expect:
//|       - {"artifact":"directions","path":"/rows/0/5","equals":3}
//|       - {"artifact":"directions","path":"/rows/1/5","equals":3}
//|       - {"artifact":"directions","path":"/rows/0/6","equals":720}
use scioxide_core::{ExecutionContext, PermutationView, permutation_validation_scratch_bytes};
use scioxide_linalg::Matrix;
use scioxide_optimize::{QapDirection, QapOptions, QapProblemView, QapResult};
use scioxide_random::{SeedableRng, Xoshiro256StarStar, uniform_index};

let fixed1 = serde_json::json!({ "fractionDigits": 1 });
let n = 7;
let mut rng = Xoshiro256StarStar::from_seed(seed.round() as u64);
let mut flow = vec![0.0; n * n];
for i in 0..n {
    for j in 0..n {
        if i != j {
            flow[i * n + j] = uniform_index(10, &mut rng).map_err(|e| e.to_string())? as f64;
        }
    }
}
let mut sites = Vec::with_capacity(n);
for _ in 0..n {
    let x = uniform_index(10, &mut rng).map_err(|e| e.to_string())?;
    let y = uniform_index(10, &mut rng).map_err(|e| e.to_string())?;
    sites.push((x, y));
}
let distance: Vec<f64> = (0..n * n)
    .map(|k| {
        let ((ax, ay), (bx, by)) = (sites[k / n], sites[k % n]);
        (ax.abs_diff(bx) + ay.abs_diff(by)) as f64
    })
    .collect();
// 「地点 k」なら施設 0 を地点 k に固定する。
let fixed: Vec<(usize, usize)> = pinned
    .strip_prefix("地点 ")
    .and_then(|k| k.parse().ok())
    .map(|site| vec![(0, site)])
    .unwrap_or_default();
let a = Matrix::from_vec(n, n, flow.clone()).map_err(|e| e.to_string())?;
let b = Matrix::from_vec(n, n, distance.clone()).map_err(|e| e.to_string())?;
let plan = QapProblemView::new(a.view(), b.view(), &fixed)
    .map_err(|e| e.to_string())?
    .prepare_with_limit(1_000_000)
    .map_err(|e| e.to_string())?;
let options = QapOptions::default();
// Plan と作業領域を一度だけ作り、二つの向きで再利用する。
let mut workspace = plan.workspace(&options).map_err(|e| e.to_string())?;
let mut result = QapResult::empty(n).map_err(|e| e.to_string())?;
// 独立な検算: 固定した組を満たす全ての置換を Heap の方法で作り、二重和の最小と最大を求める。
let double_sum = |p: &[usize]| -> f64 {
    (0..n)
        .map(|i| {
            (0..n)
                .map(|j| flow[i * n + j] * distance[p[i] * n + p[j]])
                .sum::<f64>()
        })
        .sum()
};
let allowed = |p: &[usize]| fixed.iter().all(|&(i, k)| p[i] == k);
let mut perm: Vec<usize> = (0..n).collect();
let mut counter = vec![0_usize; n];
let mut values = Vec::new();
if allowed(&perm) {
    values.push(double_sum(&perm));
}
let mut level = 1;
while level < n {
    if counter[level] < level {
        let other = if level % 2 == 0 { 0 } else { counter[level] };
        perm.swap(other, level);
        if allowed(&perm) {
            values.push(double_sum(&perm));
        }
        counter[level] += 1;
        level = 1;
    } else {
        counter[level] = 0;
        level += 1;
    }
}
let low = values.iter().copied().fold(f64::INFINITY, f64::min);
let high = values.iter().copied().fold(f64::NEG_INFINITY, f64::max);
let count = values.len();
let mut scratch = vec![0_u8; permutation_validation_scratch_bytes(n)];
let mut rows = Vec::new();
for (name, direction, optimum) in [
    ("最小化", QapDirection::Minimize, low),
    ("最大化", QapDirection::Maximize, high),
] {
    plan.solve_into(
        direction,
        None,
        &options,
        &mut result,
        &mut workspace,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;
    let p = result.permutation().ok_or("置換がない")?;
    let reported = result.objective().ok_or("目的値がない")?;
    let view = PermutationView::new(p, &mut scratch).map_err(|e| e.to_string())?;
    let recomputed = plan.objective(view).map_err(|e| e.to_string())?;
    rows.push((
        name,
        reported,
        (reported - recomputed).abs(),
        optimum,
        (reported - optimum).abs(),
        p[0],
        count,
        result.fw_iterations(),
        result.swap_checks(),
        result.termination().to_string(),
    ));
}
let columns = serde_json::json!([
    { "key": "0", "label": "向き" },
    { "key": "1", "label": "レポートの目的値 [流量×距離]", "type": "number", "format": fixed1 },
    { "key": "2", "label": "objective との差 [流量×距離]", "type": "number", "format": fixed1 },
    { "key": "3", "label": "全探索の最適値 [流量×距離]", "type": "number", "format": fixed1 },
    { "key": "4", "label": "最適値との差 [流量×距離]", "type": "number", "format": fixed1 },
    { "key": "5", "label": "施設 0 の地点", "type": "integer" },
    { "key": "6", "label": "調べた置換 [通り]", "type": "integer" },
    { "key": "7", "label": "FAQ の反復 [回]", "type": "integer" },
    { "key": "8", "label": "交換の検査 [回]", "type": "integer" },
    { "key": "9", "label": "終了理由" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "directions" })
);
```

既定のシード 3 で施設 0 を固定しない場合、最小化は 5040 通りの最適値 1018 に一致し、施設 0 は地点 5 に置かれる。
最大化の値は 1275 で、最適値 1315 より 40 小さいが、終了理由は `Converged` である。
施設 0 を地点 3 に固定すると、調べる置換は 720 通りに減り、示された置換の施設 0 は地点 3 になる。
このときの最小化の最適値は 1043 で、固定しない場合の 1018 より大きく、レポート値 1050 はそれより 7 大きい。
地点 5 に固定すると、固定しない場合の最適な配置と同じなので、最小化の値は 1018 のままである。
どの入力でも、レポートの目的値と `QapPlan::objective` で計算し直した値の差は 0 である。
二つの向きは同じ作業領域で続けて解き、作業領域は作り直していない。

## まとめ

二次割当ては施設間の流量と地点間の距離を置換で結びつける問題で、候補は $n!$ 通りあり、定数倍の近似も一般には難しい。
FAQ は二重確率行列への緩和を Frank–Wolfe 法と線形割当てで解いて置換へ射影し、2-opt は $O(n)$ の差分で交換を調べて最初の改善を受け入れる。
どちらもヒューリスティック解法で、`Converged` や `fw_gap` = 0 は大域最適性を示さない。
既知の対応は固定した組として渡すと探索から外れ、向きは求解のたびに選べ、作業領域を再利用する逐次の求解は確保をしない。
レポートの目的値は元の二重和か `QapPlan::objective` で計算し直して確かめる。
