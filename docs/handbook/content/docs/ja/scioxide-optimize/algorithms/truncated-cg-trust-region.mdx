[ドッグレッグ信頼領域法](oxref:optimize-trust-region-dogleg)は密なヘッセ行列を Cholesky 分解するので、変数が多いとメモリが $O(n^2)$、一反復の計算量が $O(n^3)$ になる。
ヘッセ行列とベクトルの積（HVP）を $O(n)$ 程度で計算できる問題では、部分問題を共役勾配法で近似的に解けば、行列を作らずに済む。
`TrustRegionSubproblem::SteihaugCg` を選んだ `TrustRegionOptimizer` は、Steihaug の切断共役勾配法でこれを行う。
このページではその手順と停止、HVP だけを使う作業領域を説明する。
勾配が零の鞍点で止まらないための二次の停止は[二次の停止と鞍点](../second-order-stopping-saddle/)で扱う。
記号は[Newton 法と信頼領域法](../newton-and-trust-region/)と同じで、$\mathbf{B}_k$ はモデルの行列、$\Delta_k$ は信頼半径を表す。

## Steihaug の切断共役勾配法

部分問題 $\min_{\|\mathbf{p}\|\le\Delta_k}\ \mathbf{g}_k^\mathsf{T}\mathbf{p}+\tfrac12\mathbf{p}^\mathsf{T}\mathbf{B}_k\mathbf{p}$ に対し、$\mathbf{B}_k\mathbf{p}=-\mathbf{g}_k$ へ $\mathbf{p}_0=\mathbf{0}$ から共役勾配法を当てる。
残差 $\mathbf{r}_j=\mathbf{B}_k\mathbf{p}_j+\mathbf{g}_k$ と探索方向 $\mathbf{d}_j$（$\mathbf{d}_0=-\mathbf{r}_0=-\mathbf{g}_k$）を使い、各反復は次のように進む。

1. 曲率 $\kappa_j=\mathbf{d}_j^\mathsf{T}\mathbf{B}_k\mathbf{d}_j$ を一回の HVP で計算する。
   $\kappa_j\le0$ なら、$\mathbf{p}_j+t\,\mathbf{d}_j$（$t\ge0$）が球面と交わる点で止める（`NegativeCurvature`）。
2. $\alpha_j=\mathbf{r}_j^\mathsf{T}\mathbf{r}_j/\kappa_j$ とし、$\|\mathbf{p}_j+\alpha_j\mathbf{d}_j\|\ge\Delta_k$ なら、同じ直線と球面の交点で止める（`Boundary`）。
3. $\mathbf{p}_{j+1}=\mathbf{p}_j+\alpha_j\mathbf{d}_j$、$\mathbf{r}_{j+1}=\mathbf{r}_j+\alpha_j\mathbf{B}_k\mathbf{d}_j$ と更新し、$\|\mathbf{r}_{j+1}\|/\|\mathbf{g}_k\|\le\eta_k$ なら止める（`ResidualSmall`）。
4. $\beta_j=\|\mathbf{r}_{j+1}\|^2/\|\mathbf{r}_j\|^2$、$\mathbf{d}_{j+1}=-\mathbf{r}_{j+1}+\beta_j\mathbf{d}_j$ として 1 へ戻る。

許容誤差は $\eta_k=\max(\sqrt{\varepsilon_{\mathrm{mach}}},\min(0.1,\sqrt{\|\mathbf{g}_k\|}))$ である。
内側の反復が `max_inner_iterations` に達した場合は、そこまでの $\mathbf{p}_j$ をそのまま試行ステップにする（`IterationLimit`）。
この四つの止まり方は `NewtonCgTermination` の値で、最後の部分問題の止まり方は `NewtonDiagnostics::cg_termination()`、積の回数は `cg_iterations()` で読める。
ドッグレッグのように部分問題を共役勾配法で解かなかった実行では `NotRun` になる。
`NewtonCgTermination` は内側の解き方だけを表し、最小化全体の終了理由は `OptimizeTermination` で別に返る。

正の曲率が続く間、共役勾配法の反復点のノルム $\|\mathbf{p}_j\|$ は狭義に増え、モデルの値は単調に減る（Nocedal–Wright の定理 7.3）。
そのため、半径を超えた時点で境界に止めても、それまでの反復点よりモデルの値が大きくなることはない。
最初の反復は $-\mathbf{g}_k$ に沿った一次元の最小化なので、得られるステップはモデルをコーシー点と同じかそれ以上に減らす。
この性質から、外側の反復にはドッグレッグと同じ大域収束の結果（Nocedal–Wright の定理 4.5 と 4.6）が当てはまる。
解の近くでモデルが正定値になりステップが半径の内側に収まると、$\eta_k$ が $\sqrt{\|\mathbf{g}_k\|}$ とともに 0 に近づくので、外側の反復は超一次収束する（不正確 Newton 法の結果、Nocedal–Wright の第 7.1 節）。

一回の内側反復は HVP 一回と $O(n)$ のベクトル演算で済む。
外側の受理比、半径の更新、停止の規則は[受理比と半径の更新](oxref:optimize-trust-region-ratio)と同じである。

## ヘッセ行列とベクトルの積だけを使う場合

クロージャの目的では `ObjectiveFn::with_hessian_vector_product` に、方向 $\mathbf{d}$ を受け取って積 $\nabla^2 f(\mathbf{x})\,\mathbf{d}$ を出力へ書く `(&[S], &[S], &mut [S])` のクロージャを渡す。
`ObjectiveFunction` を自分で実装する場合は `hessian_vector_product_into` を実装し、`has_hessian_vector_product` が `true` を返すようにする。
目的が HVP を提供すると、`SteihaugCg` は密なヘッセ行列を作らず、受理比の予測減少も同じ HVP で計算する。
HVP がなければ、解析的なヘッセ行列か勾配の差分から密な行列を作り、その行列とベクトルの積を使う。

作業領域は `TrustRegionWorkspaceRequest::of(&f)` で目的に合わせて要求する。
`SteihaugCg` と HVP を持つ目的の組では、`TrustRegionOptimizerWorkspaceRequirements::dense()` が `false` になり、作業領域は密なヘッセ行列を持たない。
`TrustRegionWorkspaceRequest::dense(n)` は密なヘッセ行列を持つ作業領域を要求し、ドッグレッグは常にこちらを使う。
`TrustRegionOptimizer::workspace(request)` で作った `TrustRegionOptimizerWorkspace` を `minimize_into` に渡せば、同じ大きさの問題を解き直すときにメモリを確保し直さない。

次のセルは両端を固定した弦を硬化する基礎（変位の 3 乗に比例する復元力）で支え、一様な荷重を掛けたときの釣り合いを求める。
エネルギーは無次元化して

$$
f(\mathbf{x})=\frac12\sum_{i=0}^{n}(x_{i+1}-x_i)^2+\sum_{i=1}^{n}\frac{x_i^4}{4}-\sum_{i=1}^{n}x_i,\qquad x_0=x_{n+1}=0
$$

で、ヘッセ行列は三重対角の $\mathbf{L}+\operatorname{diag}(3x_i^2)$ である。
HVP $(\mathbf{L}+\operatorname{diag}(3x_i^2))\mathbf{d}$ は $O(n)$ で計算でき、ヘッセ行列はどこでも正定値なので、最小点は一つに決まる。
入力は節点の数 $n$ と内側反復の上限で、開始点は $\mathbf{x}=\mathbf{0}$ である。
`SteihaugCg`（HVP だけ）と、同じ問題に密なヘッセ行列を渡したドッグレッグを比べ、二つの解の差と、解で計算し直した勾配の最大成分を独立な検算にする。
最後に `SteihaugCg` の終了理由を計算の判定として示す。

```rust
//| id: optimize-trust-steihaug-matrix-free
//| ref: optimize-trust-steihaug-matrix-free
//| title: ヘッセ行列とベクトルの積だけで弦の釣り合いを解く
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg, scioxide-optimize]
//| inputs:
//|   nodes: {"type":"range","label":"節点の数 n [個]","description":"変数の数を変え、密なヘッセ行列のメモリと分解の計算量を変える。","min":10,"max":300,"step":10,"value":100}
//|   inner_limit: {"type":"range","label":"内側反復の上限 [回]","description":"部分問題ごとの HVP の回数の上限を変える。1 回ではコーシー点だけになる。","min":1,"max":40,"step":1,"value":40}
//| cases:
//|   - {"id":"cauchy-only","label":"内側 1 回","description":"各部分問題がコーシー点で止まり、外側の反復が増える。","inputs":{"inner_limit":1}}
//|   - {"id":"small","label":"n = 10","description":"変数が少なく、密なヘッセ行列でもメモリは 100 個の値で済む。","inputs":{"nodes":10}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"methods","path":"/rows/0/1","equals":"なし"}
//|       - {"artifact":"methods","path":"/rows/1/1","equals":"あり"}
//|       - {"artifact":"methods","path":"/rows/0/2","equals":"GradientSmall"}
//|       - {"artifact":"methods","path":"/rows/0/6","equals":"ResidualSmall"}
//|       - {"artifact":"methods","path":"/rows/0/7","range":{"min":0,"max":1e-6}}
//|       - {"artifact":"check","path":"/rows/0/0","range":{"min":0,"max":1e-6}}
//|       - {"artifact":"check","path":"/rows/0/1","approx":{"value":1.0,"atol":1e-6}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: cauchy-only
//|     expect:
//|       - {"artifact":"methods","path":"/rows/0/5","equals":1}
//|       - {"artifact":"methods","path":"/rows/0/6","equals":"IterationLimit"}
//|       - {"artifact":"methods","path":"/rows/0/3","range":{"min":10,"max":30}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
use scioxide_core::{Budget, ExecutionContext};
use scioxide_linalg::Matrix;
use scioxide_optimize::{
    ObjectiveFn, OptimizeDiagnostics, OptimizeResult, TrustRegionOptimizer, TrustRegionOptions,
    TrustRegionSubproblem, TrustRegionWorkspaceRequest,
};

let n = nodes as usize;
// エネルギー ½Σ(x_{i+1} − x_i)² + Σ x_i⁴/4 − Σ x_i（両端 x_0 = x_{n+1} = 0）。
let energy = |x: &[f64]| -> Result<f64, scioxide_core::SciOxideError> {
    let mut total = 0.0;
    for i in 0..=x.len() {
        let left = if i > 0 { x[i - 1] } else { 0.0 };
        let right = if i < x.len() { x[i] } else { 0.0 };
        total += 0.5 * (right - left) * (right - left);
    }
    Ok(total + x.iter().map(|&v| 0.25 * v * v * v * v - v).sum::<f64>())
};
// 勾配 (L x)_i + x_i³ − 1。
let gradient = |x: &[f64], g: &mut [f64]| -> Result<(), scioxide_core::SciOxideError> {
    for i in 0..x.len() {
        let left = if i > 0 { x[i - 1] } else { 0.0 };
        let right = if i + 1 < x.len() { x[i + 1] } else { 0.0 };
        g[i] = 2.0 * x[i] - left - right + x[i] * x[i] * x[i] - 1.0;
    }
    Ok(())
};
// HVP (L + diag(3x²)) d を O(n) で書く。
let product = |x: &[f64], d: &[f64], out: &mut [f64]| -> Result<(), scioxide_core::SciOxideError> {
    for i in 0..x.len() {
        let left = if i > 0 { d[i - 1] } else { 0.0 };
        let right = if i + 1 < x.len() { d[i + 1] } else { 0.0 };
        out[i] = 2.0 * d[i] - left - right + 3.0 * x[i] * x[i] * d[i];
    }
    Ok(())
};
let matrix_free = ObjectiveFn::new(n, energy)
    .with_gradient(gradient)
    .with_hessian_vector_product(product);
// 比較用: 同じヘッセ行列を n × n の密な行列として渡す。
let dense = ObjectiveFn::new(n, energy)
    .with_gradient(gradient)
    .with_hessian(|x: &[f64], h: &mut Matrix<f64>| {
        let n = x.len();
        let entries = h.as_mut_slice();
        entries.fill(0.0);
        for i in 0..n {
            entries[i * n + i] = 2.0 + 3.0 * x[i] * x[i];
            if i + 1 < n {
                entries[i * n + i + 1] = -1.0;
                entries[(i + 1) * n + i] = -1.0;
            }
        }
        Ok(())
    });
let inner = Budget::try_from(inner_limit as usize).map_err(|e| e.to_string())?;
let steihaug = TrustRegionOptimizer::new(TrustRegionOptions::default().with_subproblem(
    TrustRegionSubproblem::SteihaugCg {
        max_inner_iterations: inner,
        second_order_stopping: false,
    },
));
let request = TrustRegionWorkspaceRequest::of(&matrix_free);
let stores_dense = steihaug
    .workspace_requirements(request)
    .map_err(|e| e.to_string())?
    .dense();
let mut workspace = steihaug.workspace(request).map_err(|e| e.to_string())?;
let mut result = OptimizeResult::empty();
let start = vec![0.0; n];
steihaug
    .minimize_into(
        &matrix_free,
        &start,
        &mut result,
        &mut workspace,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;
let dogleg = TrustRegionOptimizer::<f64>::default();
let dogleg_dense = dogleg
    .workspace_requirements(TrustRegionWorkspaceRequest::of(&dense))
    .map_err(|e| e.to_string())?
    .dense();
let reference = dogleg.minimize(&dense, &start).map_err(|e| e.to_string())?;

// 独立検算: 返された点で勾配を計算し直し、最大成分を読む。
let residual = |x: &[f64]| -> Result<f64, String> {
    let mut g = vec![0.0; x.len()];
    gradient(x, &mut g).map_err(|e| e.to_string())?;
    Ok(g.iter().fold(0.0_f64, |m, v| m.max(v.abs())))
};
let mut rows = Vec::new();
for (name, stored, run) in [
    ("SteihaugCg（HVP だけ）", stores_dense, &result),
    ("Dogleg（密）", dogleg_dense, &reference),
] {
    let OptimizeDiagnostics::Newton(diag) = run.method_diagnostics() else {
        return Err("対応するアルゴリズムの診断がない".to_string());
    };
    rows.push((
        name,
        if stored { "あり" } else { "なし" },
        run.termination().to_string(),
        run.iterations(),
        run.fun_evals(),
        diag.cg_iterations(),
        format!("{:?}", diag.cg_termination()),
        residual(run.x())?,
    ));
}
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "方法" },
    { "key": "1", "label": "密なヘッセ行列" },
    { "key": "2", "label": "終了理由" },
    { "key": "3", "label": "外側の反復 [回]", "type": "integer" },
    { "key": "4", "label": "目的の評価 [回]", "type": "integer" },
    { "key": "5", "label": "最後の部分問題の HVP [回]", "type": "integer" },
    { "key": "6", "label": "最後の部分問題の終了" },
    { "key": "7", "label": "勾配の最大成分（再計算） [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "methods" })
);
let difference = result
    .x()
    .iter()
    .zip(reference.x())
    .fold(0.0_f64, |m, (a, b)| m.max((a - b).abs()));
let check_columns = serde_json::json!([
    { "key": "0", "label": "二つの解の差の最大 [-]", "type": "number", "format": sci3 },
    {
        "key": "1",
        "label": "中央の変位 x_{n/2} [-]",
        "type": "number",
        "format": { "significantDigits": 8 }
    }
]);
emit_table_with_columns!(
    check_columns,
    vec![(difference, result.x()[n / 2])],
    metadata = serde_json::json!({ "id": "check" })
);
let termination = result.termination();
let outcome = if termination.is_success() {
    Outcome::satisfied("勾配が停止の閾値を下回った")
} else {
    Outcome::partial("勾配の判定を満たす前に止まった")
};
emit_outcome!(
    outcome
        .status(termination.to_string())
        .diagnostic("外側の反復", result.iterations() as f64, None)
        .diagnostic("二つの解の差の最大", difference, None)
);
```

既定の $n=100$、内側の上限 40 回では、`SteihaugCg` は 6 回の外側の反復（目的の評価 7 回）で `GradientSmall` になり、最後の部分問題は 4 回の HVP で `ResidualSmall` として止まる。
その作業領域は密なヘッセ行列を持たず、ドッグレッグは $100\times100$ の行列を持って 5 回の反復で止まる。
二つの解の差の最大は $2.2\times10^{-9}$ で、`SteihaugCg` の解で計算し直した勾配の最大成分は $1.0\times10^{-8}$ である。
弦の中央付近では隣の節点との差がほぼ 0 になり、釣り合いの式は $x^3=1$ に近づくので、中央の変位 1 はこの見積もりとも合う。
内側の上限を 1 回にすると、各部分問題はコーシー点で止まり（`IterationLimit`、HVP 1 回）、外側の反復は 16 回に増える。
$n=300$ でも `SteihaugCg` の外側の反復は 6 回のままで、ドッグレッグは $300\times300$ の行列の Cholesky 分解を反復ごとに行う。

## まとめ

Steihaug の切断共役勾配法は、$\mathbf{B}_k\mathbf{p}=-\mathbf{g}_k$ への共役勾配法を、負の曲率か半径の境界か残差の判定で打ち切って試行ステップにする。
最初の内側反復がコーシー点に当たるので、打ち切ってもモデルはコーシー点と同じかそれ以上に減り、外側の受理と半径の規則はドッグレッグと同じである。
目的が HVP を提供すれば `SteihaugCg` は密なヘッセ行列を作らず、`TrustRegionWorkspaceRequest::of(&f)` で要求した作業領域の `dense()` が `false` になる。
内側反復の上限を小さくすると部分問題はコーシー点に近づき、外側の反復が増えるので、上限は HVP の計算量と外側の反復数の兼ね合いで決める。
解の検算には別の方式の解との差と、返された点で計算し直した勾配を使える。
