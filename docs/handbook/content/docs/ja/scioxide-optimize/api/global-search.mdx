このページは有限な探索箱の上で働く大域探索のヒューリスティック解法をまとめる。
問題は目的関数と scioxide-core の `Bounds` を束ねた `BoundedObjective`（[目的関数・制約・結果の共通仕様](../problems-and-results/)）で渡し、全変数の両端が有限で下端が上端より小さくなければならない。
片側でも無限の端があれば `InvalidInput`（`UnsupportedConfiguration`）、両端が等しければ `InvalidInput`（`OutOfRange`）になる。
探索は呼び出しごとに箱を検査済みの `FiniteBounds` に写し、開始点設計と提案器へ渡す。
複数開始点法、basin hopping、dual annealing は、開始点設計 `StartDesign`、注入する局所解法 `LocalSolverFactory`、生成した標本数を記録する乱数源 `SearchRandom` を共有し、全試行の履歴を `GlobalSearchResult` に残す。
差分進化は集団を自分で管理し、結果を `OptimizeResult` で返す。
どの方法も大域最適性の証明を返さない。

## 共通の規約

- 終了：試行数や世代数を使い切った終了は `SearchBudgetCompleted`、差分進化の集団の目的値幅が許容誤差を下回った終了は `PopulationStagnation` である。
  どちらも `is_success()` が偽の非成功で、観測した最良の有限な点を保持する。
  上限・取り消し・期限で止まった場合も、それまでの観測を `IterationLimit`、`EvaluationLimit`、`SampleLimit`、`TimeLimit`、`Cancelled` などの終了として返す。
- 乱数：複数開始点法とbasin hopping・dual annealingは、試行ごとのシードを派生元のシードから `scioxide_random::seed_sequence`（SplitMix64 の出力列）で導き、各試行は自分のシードで初期化した `Xoshiro256**` から一様な 64 ビットワード（`next_uniform_u64`）を引いて $[0, 1)$ へ復号する。
  差分進化は設定のシードで初期化した一つの `Xoshiro256**` の列を使う。
  同じシードと同じ目的関数なら同じ試行列を再現する。
- メモリ領域：解法の `workspace(dimension)` で要件に合うメモリを準備する。
  局所解法の状態は作業領域が所有し、試行の記録と受理状態を分けて保持する。
  エラーのとき呼び出し側の出力は変わらない。
- 局所の失敗：局所解法が返した `ConvergenceFailure`、`NumericalInstability`、`Singular` と、局所解法の実行停止（`ExecutionStopped`）は試行のレポートに残し、成功へは変えない。
  それ以外のエラー（入力の不整合、プロバイダーの失敗など）は探索全体を止める。
- 時間：`with_time_limit` の上限は、渡すコンテキストにクロックの機能がある場合だけ使える。
  クロックのないコンテキスト（wasm のセルなど）で上限を設定して解くと、`CapabilityUnavailable` のエラーになる。

## まとめ

開始点を独立に局所最適化するなら `MultiStart`、受理点から提案して異なる局所解の吸引域を探索するなら `BasinHopping`、温度に応じた分布からの探索点の生成と再加熱を使うなら `DualAnnealing`、局所解法を使わずに集団を進化させるなら `DifferentialEvolution` を選ぶ。
設定を選ばずに有限な箱を一回だけ探すなら、シードを引数に取る差分進化の `minimize_global` を使う。
前の三つは局所 factory を差し替えられ（複数開始点法は開始点設計、basin hopping は提案器も差し替えられる）、`GlobalSearchResult` の `best()` と `best_successful()` を区別する。
シードと試行数を記録すれば結果を再現でき、別のシードで繰り返せば吸引域を見落とす頻度を見積もれる。
`SearchBudgetCompleted` と `PopulationStagnation` は成功ではないので、得た点は局所解法で解の精度を改善し、勾配や制約を元の問題で再評価してから使う。
