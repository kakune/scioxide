`scioxide-optimize` は、無制約・境界付きの局所最適化、非線形制約付き最適化、非線形・線形最小二乗、線形計画（LP）・二次計画（QP）・混合整数線形計画（MIP）と二次割当、近接法と ADMM、標本化した目的の確率的一階法、多目的最適化、大域探索を出力に反映する。
このガイドは目的に応じて使う項目を示し、公開されている 334 項目を用途別の 10 ページの表にまとめる。
表の項目名のリンクは、docs.rs の 0.1.0 の API リファレンスを指す。

| 滑らかな項と近接写像を持つ項の和を最小化する | `ProximalGradient`、`Fista`、`Admm` | [近接法・ADMM・標本化した目的・多目的最適化](composite-stochastic-multiobjective/) |

これらの型はこのガイドの表には含めず、それぞれの章の API ガイドで引く。

## 型の関係

- 問題: 目的関数は `ObjectiveFunction`（値を返し、勾配・ヘッセ行列は出力先へ書いて `Ok(false)` で「提供しない」を表す）か、クロージャをラップする `ObjectiveFn` で渡す。
  `ObjectiveFn` の導関数のクロージャは、解法が渡す出力領域へ全成分を書く。
  非線形制約は `ConstraintFunction` を集めた不変の `Constraints`、残差は `LeastSquaresProblem` か `LeastSquaresFn` で表す。
  LP・QP・MIP は係数を所有する `LpProblem`、`QpProblem`、`MipProblem` に検査して格納する。
- 呼び出しの形: 設定を選ぶ必要に応じて三つの段階があり、名前は[呼び出しの形](oxref:optimize-call-forms)の表に合わせる。
  - ワンショット関数: `minimize`（BFGS）、`minimize_bounded`（L-BFGS-B）、`minimize_constrained`（SQP）、`minimize_scalar`（Brent 法）、`minimize_global`（差分進化）、`least_squares` と `curve_fit`（Levenberg–Marquardt 法）、`nnls`、`bvls`、`quadratic_assignment`（FAQ と 2-opt）の関数と、`LpProblem::solve`（改訂単体法）、`QpProblem::solve`（凸 QP の自動選択）、`MipProblem::solve`（分枝限定法）は、問題のデータだけを受け取って既定の設定で解く。
    成功しなかった場合は構造化エラーを返す。
    ただし `minimize_global` は差分進化の予定を終えた `PopulationStagnation` と `SearchBudgetCompleted` を結果として返す。
  - 手法オブジェクト: 解法の型（`Bfgs`、`Sqp`、`QpSolver` など）は検査済みの設定（`BfgsOptions`、`SqpOptions` など）を不変に保持し、同じ設定で何度でも呼べる。
    固有メソッドの `minimize` / `solve` は作業領域と結果を内部で確保し、成功でない終了も含む完全な結果を `Ok` で返すので、成功を必須とするなら結果の `require_success()` を呼ぶ。
    局所法、`LbfgsB`、非線形制約法、`DifferentialEvolution`、`CmaEs` は、実行時に解法を選ぶための共通トレイト `Optimizer` も実装し、`Optimizer::minimize(&problem, x0)` の `problem` は目的関数、`BoundedObjective`、`ConstrainedProblem` のどれかである。
    前計算を持つ Plan（plan）は `QapPlan` だけで、二つの行列の写しと自由な節点のブロックを $O(n^2)$ の処理とメモリで準備する。
  - 出力先を指定する API: 準備した出力・作業領域・実行範囲を渡す `minimize_into` / `solve_into` を使う。
    一変数の `ScalarMinimizer` は作業領域を持たず、実行範囲を受け取る `minimize_scoped` も新しく確保した結果を返す。
    BFGS、NSGA-II、確率的一階法は作業領域の `checkpoint()` と解法の `resume_into` で、中断した受理状態から再開する。
- 導関数: 導関数を与えない場合の差分などの微分源は設定の `DerivativeStrategy` で選ぶ。
  直線探索を使う BFGS、L-BFGS、最急降下、非線形共役勾配、Newton 法の既定は `AnalyticOrCentral`（解析的な導関数がなければ中心差分）、差分で導関数を補うそのほかの解法の既定は `AnalyticOrForward`（前進差分）である。
- 作業領域: 作業領域は解法ごとの型（`BfgsWorkspace`、`LeastSquaresWorkspace`、`GlobalSearchWorkspace` など）で、別の解法の作業領域は渡せない。
  コールバックは値と導関数を出力領域へ直接書く（トレイトの `gradient_into` や `ObjectiveFn` のクロージャ）ので、寸法に合わせて確保した後は、定常の反復で新たなヒープ確保をしない。
- 大域探索の解法: 大域探索の手法オブジェクト（`MultiStart`、`Direct` など）は数値・実行の方針を保持し、有限箱は `BoundedObjective` に所属する。
  局所解法やサロゲートモデルなどのプロバイダーは作業領域が所有する。
  乱数はオプションのシードから選び（`minimize_global` は引数のシード）、並列の標本評価はオプションの実行方針とコンテキストの機能で指定する。
- 結果と証拠: 局所法、制約付き局所法、`DifferentialEvolution`、`CmaEs` は `OptimizeResult`、非線形最小二乗は `LeastSquaresResult`、LP・QP・MIP は `ProgrammingResult`、`MipResult`、複数開始点・basin hopping・dual annealingは `GlobalSearchResult` を返し、DIRECT・SHGO・サロゲートモデル・近接法・ADMM・二次割当・確率的一階法・NSGA-II はそれぞれの結果型（`DirectResult`、`ShgoResult`、`ProximalResult`、`StochasticResult`、`Nsga2Result` など）を返す。
  終了理由はどれも唯一の `OptimizeTermination` で、実行可能性・停留性・相補性などの残差は `OptimalityDiagnostics` に分けて入る。
  LP・QP の解と証明用データは、`LpProblem`・`QpProblem` そのもの（または借用の `LpVerificationProblem`・`QpVerificationProblem`）を `ProgrammingVerifier::verify` に渡して、解法の内部状態から独立に検証できる。

## 作業領域・取り消し・再開の実行例

設定を選ばずに一回だけ解くなら、値を返すクロージャ `f` と開始点を `minimize(f, &x0)` に渡せばよく、成功しなければエラーが返る。
次のセルは同じ大きさの問題を繰り返し解く場合と、外から中断して後で続ける場合の形を示す。

Rosenbrock 関数 $f(x) = (1 - x_1)^2 + 100\,(x_2 - x_1^2)^2$ の最小点は $(1, 1)$、最小値は 0 である。
次のセルは密な BFGS の作業領域と結果の格納先を一度だけ確保し、指定した回数の目的評価の後で `CancellationToken` による取り消しを要求する。
取り消された呼び出しは `Ok` で戻り、終了理由は `Cancelled`（成功ではない）で、受理済みの反復点を結果に残す。
続いて作業領域から所有の `BfgsCheckpoint` を作り、取り消しを解除して `resume_into` で続きを解く。
表は呼び出しごとの終了理由、作業領域が記録した試行の結果（`last_attempt()` の `AttemptOutcome`）、`counts()` が数えた目的の評価と、コールバック自身が数えた評価を並べる。
最後の 2 列は既知の最小点による検算で、セルの結論には最後の呼び出しが返した終了理由を使う。

```rust
//| id: optimize-api-bfgs-lifecycle
//| ref: optimize-api-bfgs-lifecycle
//| title: BFGS を作業領域で解き、取り消した点から再開する
//| run: reactive
//| crates: [scioxide-core, scioxide-optimize]
//| inputs:
//|   cancel_after: {"type":"range","label":"取り消しを要求する目的評価の回数 [回]","description":"この回数の目的評価の後で取り消しを要求し、再開で続きを解く。","min":1,"max":80,"step":1,"value":12}
//|   start_x1: {"type":"range","label":"初期点の x₁ [-]","description":"初期点 (x₁, 1) の x₁ を変える。","min":-2,"max":2,"step":0.1,"value":-1.2}
//| cases:
//|   - {"id":"cancel-at-first-evaluation","label":"1 回目の評価で取り消し","description":"勾配を受理する前に止まるので checkpoint は InvalidInput を返し、再開しない。目的評価は 1 回だけである。","inputs":{"cancel_after":1}}
//|   - {"id":"no-cancellation","label":"取り消しなし（80 回）","description":"取り消しが起こらず、1 回の呼び出しが 37 反復・66 回の評価で GradientSmall になる。","inputs":{"cancel_after":80}}
//|   - {"id":"start-left-edge","label":"初期点 (−2, 1)","description":"初期点の評価の後（受理した反復 0 回、f = 909）で取り消され、再開は 26 反復で成功する。","inputs":{"start_x1":-2}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"calls","path":"/rows/0/1","equals":"Cancelled"}
//|       - {"artifact":"calls","path":"/rows/0/2","equals":false}
//|       - {"artifact":"calls","path":"/rows/0/3","equals":"Stopped"}
//|       - {"artifact":"calls","path":"/rows/0/6","equals":12}
//|       - {"artifact":"calls","path":"/rows/1/0","equals":"resume_into"}
//|       - {"artifact":"calls","path":"/rows/1/1","equals":"GradientSmall"}
//|       - {"artifact":"calls","path":"/rows/1/2","equals":true}
//|       - {"artifact":"calls","path":"/rows/1/4","range":{"min":35,"max":39}}
//|       - {"artifact":"calls","path":"/rows/1/7","range":{"min":0,"max":1e-12}}
//|       - {"artifact":"calls","path":"/rows/1/8","range":{"min":0,"max":1e-6}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: cancel-at-first-evaluation
//|     expect:
//|       - {"artifact":"calls","path":"/rows/0/1","equals":"Cancelled"}
//|       - {"artifact":"calls","path":"/rows/0/4","equals":0}
//|       - {"artifact":"calls","path":"/rows/0/6","equals":1}
//|       - {"artifact":"calls","path":"/rows/1/0","equals":"checkpoint"}
//|       - {"artifact":"calls","path":"/rows/1/1","equals":"Err(InvalidInput)"}
//|       - {"artifact":"calls","path":"/rows/1/4","equals":null}
//|       - {"path":"/outputs/1/state","equals":"partial"}
//|   - case: no-cancellation
//|     expect:
//|       - {"artifact":"calls","path":"/rows/0/1","equals":"GradientSmall"}
//|       - {"artifact":"calls","path":"/rows/0/4","range":{"min":35,"max":39}}
//|       - {"artifact":"calls","path":"/rows/0/6","equals":66}
//|       - {"artifact":"calls","path":"/rows/0/8","range":{"min":0,"max":1e-6}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: start-left-edge
//|     expect:
//|       - {"artifact":"calls","path":"/rows/0/4","equals":0}
//|       - {"artifact":"calls","path":"/rows/0/7","approx":{"value":909,"rtol":1e-9}}
//|       - {"artifact":"calls","path":"/rows/1/1","equals":"GradientSmall"}
//|       - {"artifact":"calls","path":"/rows/1/4","range":{"min":24,"max":28}}
use core::sync::atomic::{AtomicUsize, Ordering};
use scioxide_core::{
    CancellationToken, EvaluationRole, ExecutionContext, SciOxideError, RealScalar,
};
use scioxide_optimize::{
    Bfgs, BfgsWorkspace, ObjectiveFunction, OptimizeResult, OptimizeTermination,
};

// Rosenbrock 関数 f(x) = (1 - x₁)² + 100 (x₂ - x₁²)²。既知の最小点は (1, 1)、最小値は 0。
// 目的評価を数え、指定回数に達したら取り消しを要求する（外部からの中断の代わり）。
struct Rosenbrock<'a> {
    token: &'a CancellationToken,
    calls: AtomicUsize,
    cancel_after: usize,
}
impl ObjectiveFunction<f64> for Rosenbrock<'_> {
    fn dim(&self) -> usize {
        2
    }
    fn eval(&self, x: &[f64]) -> Result<f64, SciOxideError> {
        if self.calls.fetch_add(1, Ordering::Relaxed) + 1 == self.cancel_after {
            self.token.cancel();
        }
        let a = 1.0 - x[0];
        let b = x[1] - x[0] * x[0];
        Ok(a * a + 100.0 * b * b)
    }
    // 解析的な勾配を出力先へ書き、利用できたことを true で伝える。
    fn gradient_into(&self, x: &[f64], g: &mut [f64]) -> Result<bool, SciOxideError> {
        let r = x[1] - x[0] * x[0];
        g[0] = -2.0 * (1.0 - x[0]) - 400.0 * x[0] * r;
        g[1] = 200.0 * r;
        Ok(true)
    }
}

let token = CancellationToken::new();
let problem = Rosenbrock {
    token: &token,
    calls: AtomicUsize::new(0),
    cancel_after: cancel_after as usize,
};
let solver = Bfgs::<f64>::default();
// 作業領域と結果の格納先を一度だけ確保し、二つの呼び出しで再利用する。
let mut workspace = solver.workspace(2).map_err(|e| e.to_string())?;
let mut result = OptimizeResult::<f64>::empty();
let context = ExecutionContext::sequential().with_cancellation(&token);
solver
    .minimize_into(
        &problem,
        &[start_x1, 1.0],
        &mut result,
        &mut workspace,
        context,
    )
    .map_err(|e| e.to_string())?;
// 列: 呼び出し、終了理由、成功、試行の結果、受理した反復、counts() の目的の評価、
// コールバックが数えた評価、f(x)、既知の最小点 (1, 1) との距離（独立な検算）。
let row = |label: &'static str, r: &OptimizeResult<f64>, ws: &BfgsWorkspace<f64>, calls| {
    let attempt = ws.last_attempt().map(|a| format!("{:?}", a.outcome()));
    (
        label,
        r.termination().to_string(),
        Some(r.is_success()),
        attempt.unwrap_or_default(),
        Some(r.iterations()),
        Some(r.counts().own().provider(EvaluationRole::Objective)),
        calls,
        Some(r.fun()),
        Some(RealScalar::hypot(r.x()[0] - 1.0, r.x()[1] - 1.0)),
    )
};
let first_calls = problem.calls.load(Ordering::Relaxed);
let mut rows = vec![row("minimize_into", &result, &workspace, first_calls)];
if !result.is_success() {
    // 受理済みの点・勾配・逆ヘッセ近似を所有する checkpoint に写し、取り消しを解除して続ける。
    match workspace.checkpoint() {
        Ok(checkpoint) => {
            token.reset();
            solver
                .resume_into(&problem, &checkpoint, &mut result, &mut workspace, context)
                .map_err(|e| e.to_string())?;
            let calls = problem.calls.load(Ordering::Relaxed) - first_calls;
            rows.push(row("resume_into", &result, &workspace, calls));
        }
        Err(e) => rows.push((
            "checkpoint",
            format!("Err({:?})", e.kind()),
            None,
            "受理状態なし".to_string(),
            None,
            None,
            0,
            None,
            None,
        )),
    }
}
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let fixed3 = serde_json::json!({ "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "呼び出し" },
    { "key": "1", "label": "終了理由" },
    { "key": "2", "label": "成功", "type": "boolean", "nullText": "-" },
    { "key": "3", "label": "試行の結果" },
    { "key": "4", "label": "受理した反復 [回]", "type": "integer", "nullText": "-" },
    { "key": "5", "label": "counts() の目的 [回]", "type": "integer", "nullText": "-" },
    { "key": "6", "label": "コールバックの目的 [回]", "type": "integer" },
    { "key": "7", "label": "f(x) [-]", "type": "number", "format": fixed3, "nullText": "-" },
    { "key": "8", "label": "‖x − (1, 1)‖₂ [-]", "type": "number", "format": sci2, "nullText": "-" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "calls" })
);

let termination = result.termination();
let outcome = match termination {
    _ if termination.is_success() => {
        Outcome::satisfied("最後の呼び出しが勾配の停止判定を満たした")
    }
    OptimizeTermination::LineSearchFailed(_) => {
        Outcome::failed("直線探索が受理できるステップ幅を見つけられなかった")
    }
    _ => Outcome::partial("取り消しで止まり、再開できる受理状態がない")
        .explanation("結果は取り消しの時点で受理していた点を持つ。"),
};
emit_outcome!(
    outcome
        .status(termination.to_string())
        .diagnostic("受理した反復", result.iterations() as f64, None)
        .diagnostic(
            "目的の評価",
            problem.calls.load(Ordering::Relaxed) as f64,
            None
        )
);
```

既定の入力（12 回目の目的評価で取り消し、初期点 $(-1.2, 1)$）では、最初の呼び出しは受理した反復 2 回、$f = 4.60$ で `Cancelled` になり、試行の結果は `Stopped` と記録される。
再開した呼び出しは受理した反復の通算 37 回で `GradientSmall`（成功）になり、$f = 8.3 \times 10^{-20}$、既知の最小点との距離は $5.2 \times 10^{-10}$ である。
取り消しを要求しない場合（80 回）も同じ 37 回、同じ目的値で `GradientSmall` になり、目的評価は 66 回である。
中断と再開を挟むと評価は $12 + 55 = 67$ 回で、1 回だけ増える。

再開は新しい求解ではなく、checkpoint に記録した求解の続きである。
そのため再開した結果の `iterations()` と `counts()` は checkpoint までの分を引き継ぎ、`counts()` の目的の評価 67 回は、二つの呼び出しでコールバックが数えた $12 + 55$ 回に一致する。
反復上限も通算で数えるので、`IterationLimit` で止まった状態を同じ設定で再開しても反復は増えない。
設定の異なる解法で再開すると、checkpoint の識別子が合わず `InvalidInput` になる。

1 回目の評価で取り消すと、勾配を受理する前に止まるので再開できる状態がなく、`checkpoint` は `InvalidInput` を返す。
このとき結果は初期点の値（$f = 24.2$）を持つ `Cancelled` で、セルの結論は `partial` になる。
初期点を $x_1 = -2$ にすると、取り消しは初期点の評価の後（受理した反復 0 回、$f = 909$）で起こるが、初期点の値と勾配は受理済みなので、再開は 26 回で成功する。

## 結果・エラー・診断の読み方

- エラー: 入力の誤りと実行の失敗は scioxide-core の `SciOxideError` で返り、`kind()` で分類する。
  初期点の次元が `dim()` と合わなければ `DimensionMismatch`、初期点に非有限な成分があれば `NonFinite`、設定や入力の構造の誤りは `InvalidInput` になり、コールバックが返したエラーは呼び出し側へ伝わる。
  作業領域の大きさの上限は `ResourceLimit` と `SizeOverflow`、確保の失敗は `AllocationFailure` になる。
  設定で時間上限を与えたのに実行コンテキストにクロックがない場合は、コールバックを呼ぶ前に `CapabilityUnavailable` を返す。
  クロックは `ExecutionContext::with_clock` で束縛し、取り消しは `with_cancellation` で渡す。
  ワンショット関数と結果の `require_success()` は、成功でない終了を、理由と計算量を持つ `ConvergenceFailure`、取り消しと期限では `ExecutionStopped`、検証済みの実行不能と非有界では `DomainError` にする（対応の全体は[終了理由の分類](oxref:optimize-termination-classes)の表）。
  エラーは呼び出し元の識別子を持たない。
- 終了理由: 手法オブジェクトの呼び出しは、エラーにならなければ成否を唯一の `OptimizeTermination` で伝える。
  `is_success()` が真になるのは `Converged` と `GradientSmall` だけである。
  成功でない終了は、進まなくなった停止、上限・時間上限・取り消し、大域探索と標本化した目的の終わり、Plan 問題の実行不能・非有界に分かれる。
  分類ごとに結果が持つもの（最後に受理した点、観測した最良点、証明用データ）と、変換されるエラーは[終了理由の分類](oxref:optimize-termination-classes)の表にある。
  直線探索が受理できるステップ幅を見つけられなかった場合は、原因（`IterationLimit`、`EvaluationLimit`、`StepSizeLimit`、`Stagnation`）を持つ `LineSearchFailed` になる。
  最初の点を受理する前に止まった場合は、残す結果がないので構造化エラーになる。
  勾配を使う無制約の局所法は勾配のユークリッドノルム $\lVert\nabla f\rVert_2$ を許容誤差と比べ、`LbfgsB` は有効な境界の成分を 0 にした射影勾配の $\infty$ ノルムを比べる。
  非線形制約付きの局所法は最初に導関数を評価した点で目的と各制約の行をその勾配の $\infty$ ノルム（0 なら値の大きさか 1）で割って問題を正規化し、正規化した問題の KKT 残差が `OptimalityTolerances` 以内のときだけ成功とする。
  返す診断と乗数は元の問題の単位に戻す。
  LP・QP・MIP は元の問題の残差がこの許容誤差を満たしたときだけ成功とする。
  非線形最小二乗は既定（`LeastSquaresStopping::OriginalGradient`）で目的の勾配のノルムを判定して `GradientSmall` を返し、明示した `LeastSquaresStopping::Minpack`（密なヤコビ行列だけ）は勾配の判定を Moré の判定に置き換えて `Converged` も返す。
- 大域探索とヒューリスティクス: 大域探索は収束や大域最適性を主張しない。
  有限の探索回数の上限に達した終了は `SearchBudgetCompleted`、集団探索（差分進化・CMA-ES）の集団が縮んだ終了は `PopulationStagnation` で、どちらも成功ではなく、見つけた最良の有限な候補を返す。
  DIRECT は矩形のメモリの上限で `MemoryLimit`、SHGO は単体複体の上限で `NodeLimit` などにもなる。
  大域探索の問題は端点がすべて有限の箱を持つ `BoundedObjective` で渡し、サロゲートモデルによる探索だけは観測履歴 `SurrogateHistory` と目的を渡す。
- 標本化した目的: 確率的一階法が勾配の停止判定を満たしたとき、ノイズのない標本（`NoiseModel::Deterministic`）では `GradientSmall`（成功）、独立なノイズを持つ標本では推定に基づく `EstimatedStationarity`（成功ではない）になる。
  反復観測の上限の中でノイズを分離できなければ `NoiseLimit` で止まり、これも成功ではない。
  複数開始点の結果では、局所解法が成功したかによらない最良の候補 `best()` と、局所解法が成功した中で最良の `best_successful()` を区別する。
- 数理計画: LP・QP・MIP の結果は主実行可能性、停留性、双対実行可能性、相補性、整数性、変数境界、最適性の隔たりを `OptimalityDiagnostics` から別々に読む。
  LP・QP の解法は終了理由を `Converged`、`Infeasible`、`Unbounded` にする前に、双対変数・Farkas 乗数・後退方向の証拠を元の座標で独立に検査し、受理できなければ `Stagnation`、`SuspectedInfeasible`、`SuspectedUnbounded` に下げる。
  `ProgrammingVerifier::verify` のレポートは `VerificationStatus` で `Accepted`、`Rejected`、`KktOnly`（KKT 検査は通ったが QP の大域的な凸性を確かめていない）、`Incomplete`（リソースの上限で中断）を区別する。
  これは浮動小数点の許容誤差による数値的な証拠であって、包含が保証された区間ではない。
  `MipResult::absolute_gap` は実際の数値の隔たりで、厳密な算術による証明用データではない。
- 計算量: 結果の `counts()` は scioxide-core の `SolveCounts` を返し、失敗した導関数の試行を含め、実際に呼んだプロバイダー（目的・勾配・ヘッセ行列・制約など）の回数を役割（`EvaluationRole`）ごとに数える。
  入れ子の求解（局所解法を内側に持つ大域探索など）では、自分の分を `own()`、子孫の分を `nested()` で別々に読み、合計は検査付きの `total()` で得る。
  再開した求解の `counts()` は上のセルのように checkpoint までの分を含む。
- 方式別の診断: `OptimizeResult::method_diagnostics()` は `OptimizeDiagnostics` の列挙子（`FirstOrder`、`Newton`、`NelderMead`、`Powell`、`Sqp`、`InteriorPoint`、`Cobyla`、`Cobyqa`、`Unavailable`）で、直線探索の大域化・信頼領域・単体の形・部分問題などの観測を返す。

## まとめ

解法は問題の構造で選び、目的関数と制約は `ObjectiveFunction` などのトレイトかクロージャの適合で渡す。
既定の設定で一回だけ解くなら `minimize` などの関数や `LpProblem::solve` を使い、成功しなかった場合をエラーで受け取る。
繰り返し解く場合は解法ごとの作業領域を一度だけ確保し、BFGS では `minimize_into` の出力先と checkpoint で中断と再開を扱える。
手法オブジェクトの呼び出しでは、エラーは入力や実行の失敗を表し、成功でない終了は `Ok` の結果の `OptimizeTermination` で伝わるので、`is_success()` と残差の診断を読むか、`require_success()` でエラーに変える。
大域探索と数理計画の結果は、収束の主張ではなく、残した候補・残差・隔たりの証拠として解釈する。
