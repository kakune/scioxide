この表は開始点の近くの局所最小点を探す解法と、その設定・作業領域・診断の型をまとめる。
どれも局所法で、成功とみなす終了理由は `Converged` と `GradientSmall` だけである。
勾配が小さいことは一次の停止判定であり、極小点の証明ではない。
反復上限・評価上限・直線探索の失敗・停滞・取り消し・期限で止まった場合は、最後に受理した点を成功でない終了理由とともに `Ok` で返す。
最初の観測より前に止まった場合と、入力・コールバック・数値の失敗は `SciOxideError` になる。
設定は値として組み立てて解法に渡し、Nelder–Mead 法と Powell 法の設定は解法の `new` が検査する。
作業領域は解法ごとの型なので、別の解法の作業領域は渡せない。

## 呼び出しの形

既定の設定で一回だけ解くなら、`minimize(f, x0)`（BFGS）と `minimize_bounded(f, x0, &bounds)`（L-BFGS-B）が値を返すクロージャと開始点だけを受け取り、成功しなければ構造化エラーを返す。
設定を選ぶ場合は解法の値（`Bfgs` など）を作り、固有メソッド `minimize(problem, x0)` で解く。
これは作業領域と結果を内部で確保する所有値を返す API 式で、成功でない終了も `Ok` の結果で返すので、成功を必須とするなら結果の `require_success()` を呼ぶ。
同じ呼び出しは実行時に解法を選ぶための `Optimizer` トレイトからも使える。
繰り返す場合は `workspace_requirements(n)` と `workspace(n)`（信頼領域法は `TrustRegionWorkspaceRequest`）でメモリを準備し、`minimize_into(problem, x0, output, workspace, scope)` を使う。
最後の scope は根の `ExecutionContext` または親の求解へ処理を計上する子の `SolveContext` から渡す。
呼び出し側の識別子を別の引数に渡す必要はない。

作業領域は試行記録と受理した点を分けて保持する。
方式別の診断は `OptimizeResult::method_diagnostics()` が返す `OptimizeDiagnostics` の列挙子として解釈する。
BFGS の再開用の所有スナップショットは `checkpoint()` で取得し、`resume_into` に渡す。
L-BFGS-B や境界付きの Powell 法では、目的と箱をまとめた `BoundedObjective` を問題として渡す。

## まとめ

勾配が得られる滑らかな問題では、変数が少なければ `Bfgs`、多ければ `Lbfgs` か `NonlinearCg`、箱の境界だけがあれば `LbfgsB` を選び、正確なヘッセ行列が安く得られるなら `NewtonOptimizer` か `TrustRegionOptimizer` を使う。
変数が多く、ヘッセ行列とベクトルの積だけが得られるなら、`TrustRegionSubproblem::SteihaugCg` を選んだ `TrustRegionOptimizer` を使う。
導関数を使えない少数変数の問題には `NelderMead` か、境界と固定変数を扱える `Powell` を使う。
どの解法でも成否は `termination()` で判定し、`IterationLimit`・`LineSearchFailed`・`Stagnation`・`EvaluationLimit` の結果は受理済みの最良点にすぎない。
設定を変えずに一回だけ解くなら `minimize` か `minimize_bounded` を使い、成功しなかった場合をエラーとして受け取る。
同じ寸法の問題を繰り返すなら作業領域を一度だけ確保し、BFGS では `minimize_into` の試行の記録と `BfgsCheckpoint` で中断と再開を扱う。
