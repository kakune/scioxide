この表はどの解法にも共通する入力と出力の型をまとめる。
入力は目的関数 $f:\mathbb R^n\to\mathbb R$、残差ベクトル $r(x)$、制約 $h(x)=0$・$g(x)\le 0$ をトレイトかクロージャのアダプターで与え、出力は `OptimizeResult` の点・目的値・唯一の終了理由・最適性診断で読む。
クロージャのアダプターは入力と出力領域の長さだけを検査し、不一致はクロージャを呼ぶ前に `DimensionMismatch` のエラーにする。
導関数のクロージャは解法が渡す出力領域へ全成分を直接書くので、アダプターは呼び出しごとに確保しない。
目的値・制約値・残差・導関数の非有限な値はアダプターではなく解法が検査し、開始点ではエラー、試行点では棄却になる。
反復上限や停滞などで止まった場合は `Ok` の結果に成功でない終了理由が入るので、`is_success()` と診断を確かめる。
成功を必須とする場合は、結果の `require_success()` で成功でない終了を構造化エラーに変える。

`OptimizeTermination` の列挙子は次の意味を持つ。
成功は 1 行目の二つだけで、その他は結果を受け取っても最適点の根拠にはならない。
最後の列は `require_success()` と一回の呼び出しで解く関数が返すエラーで、`ConvergenceFailure` は理由（`ConvergenceReason`）と計算量を持つ。
ただし `minimize_global` は、差分進化が `PopulationStagnation` か `SearchBudgetCompleted` で止まった場合をエラーにせず、結果として返す。

| 終了理由 | 意味 | 成功か | `require_success()` のエラー |
|---|---|---|---|
| `Converged`、`GradientSmall` | 方式に固有の停止検査（勾配や KKT 残差など）をすべて満たした | 成功 | なし |
| `LineSearchFailed(LineSearchFailure)` | 局所法の直線探索が試行を受理できなかった（理由は `LineSearchFailure` の `IterationLimit`・`EvaluationLimit`・`StepSizeLimit`・`Stagnation`）。解法全体の評価回数の上限に達した場合は `EvaluationLimit` などのリソースの終了理由になる | いいえ | `ConvergenceFailure`（`NestedSolver`） |
| `NotStarted` | 出力領域を `empty()` で作っただけで、まだ解いていない | いいえ | `InvalidInput`（`Inconsistent`） |
| `IterationLimit`、`EvaluationLimit`、`TimeLimit`、`NodeLimit`、`DepthLimit`、`MemoryLimit`、`ProposalLimit`、`SampleLimit` | 反復・評価・時間・分枝限定法の節点・探索の深さ・呼び出し側が与えたメモリ使用量・共有の提案数・乱数標本数の上限に達した | いいえ | `IterationLimit` と `EvaluationLimit` は同名の理由、節点・深さ・メモリ使用量は `ResourceLimit(Node)`、提案数は `ResourceLimit(Proposal)`、標本数は `ResourceLimit(Sample)` の `ConvergenceFailure`。`TimeLimit` は `ExecutionStopped`（`DeadlineReached`） |
| `Cancelled` | 実行コンテキストから取り消し要求を確認して停止した | いいえ | `ExecutionStopped`（`Cancelled`） |
| `StepSmall`、`FunctionChangeSmall`、`Stagnation` | ステップ幅や目的値の変化が小さい、または進まなくなったが、収束判定は満たしていない | いいえ | `StepSmall` は `StepSizeLimit`、その他は `Stagnation` の `ConvergenceFailure` |
| `SearchBudgetCompleted`、`PopulationStagnation` | 大域探索が決めた計算回数の上限に達した、または集団が集まった。大域最適性は主張しない | いいえ | `SearchBudgetCompleted` は `IterationLimit`、`PopulationStagnation` は `Stagnation` の `ConvergenceFailure` |
| `EstimatedStationarity`、`NoiseLimit` | 標本から推定した勾配とその誤差幅が小さい（証明ではない）、または反復観測でノイズを分離できなかった | いいえ | `ConvergenceFailure`（`Stagnation`） |
| `SuspectedInfeasible`、`SuspectedUnbounded` | 実行不能・非有界の疑いがあるが、受理された証拠がない | いいえ | `SuspectedInfeasible` は `Stagnation`、`SuspectedUnbounded` は `Divergence` の `ConvergenceFailure` |
| `Infeasible`、`Unbounded` | 実行不能・非有界を検出した | いいえ | `DomainError`（`Undefined`） |

## まとめ

問題は `ObjectiveFunction`・`LeastSquaresProblem`・`ConstraintFunction` を実装するか、`ObjectiveFn`・`LeastSquaresFn`・`ConstraintFn` でクロージャを包んで与え、制約は等式か不等式かを決めて `Constraints` に登録する。
アダプターとトレイトの `*_into` メソッドは出力領域へ直接書くので呼び出しごとに確保せず、制約の評価を繰り返す場合は `ConstraintsWorkspace` を使い回す。
結果の成否は `termination()` で決め、成功とみなすのは `Converged` と `GradientSmall` だけで、成功を必須とする場合は `require_success()` で成功でない終了をエラーに変える。
直線探索が試行を受理できずに止まった場合は、`LineSearchFailed` が理由とともに返る。
成功した場合も `OptimalityDiagnostics` の残差を許容誤差と比べ、`None` を 0 と読まない。
計算量は `counts()` の `own()` と `nested()` で、自分の分と入れ子の解法の分に分けて読む。
