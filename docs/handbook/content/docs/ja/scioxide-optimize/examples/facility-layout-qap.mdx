工場の設備や病院の診療科を、決まった数の地点へ一つずつ配置する問題を考える。
施設 $i$ から施設 $j$ への流量（搬送の回数や人の移動量）を $A_{ij}$、地点 $k$ から地点 $l$ への距離を $B_{kl}$ とする。
施設 $i$ を地点 $\pi(i)$ に置く置換 $\pi$ を選び、総輸送量

$$
F(\pi)=\sum_{i,j}A_{ij}B_{\pi(i),\pi(j)}
$$

を最小にする。
これが Koopmans–Beckmann 形の二次割当て問題（quadratic assignment problem: QAP）である。
二重和は $i\to j$ と $j\to i$ の両方の向きを数えるので、対称な行列では各施設の組の輸送量を 2 回数える。
このページでは二重和の全体を使い、半分にはしない。
費用が施設の組の置き場所で決まるため、施設ごとに独立な線形割当て問題より難しく、QAP は NP 困難である。

## 置換の向きと図

`QapProblemView::new(a, b, fixed)` の目的は $\sum_{i,j}a_{ij}b_{p(i),p(j)}$ で、`permutation[i]` は第一行列の番号 $i$ に割り当てた第二行列の番号を表す。
第一行列に流量、第二行列に距離を渡すと、`permutation[i]` は施設 $i$ を置く地点になる。
このページのセルはどちらの問題でもこの順に渡す。

二つの行列を入れ替えても最適値は変わらない。
$\sigma=\pi^{-1}$ と置いて添字を付け替えると $\sum_{i,j}B_{ij}A_{\pi(i),\pi(j)}=\sum_{k,l}A_{kl}B_{\sigma(k),\sigma(l)}$ となり、置換が逆向きになるだけである。
ただし返る置換の読み方は逆になるので、表の見出しと行列の役割を一致させる。

## FAQ と 2-opt の役割

既定の方法 `QapMethod::FaqThenTwoOpt` はまず FAQ（fast approximate QAP）を走らせる。
FAQ は置換行列を二重確率行列（各行と各列の和が 1 の非負行列）まで緩めた問題を Frank–Wolfe 法で改善する。
FAQ の最後の行列に最も近い置換を線形割当てで選び、その置換から二施設の地点を交換する 2-opt で局所的に改善する。
FAQ の一反復と 2-opt の一巡はどちらも $O(n^3)$ の計算量である。
緩和した問題は非凸なので、FAQ が返す緩和の目的値は、置換で達成できる最適値の下界になるとは限らない。
Frank–Wolfe ギャップも緩和の上の局所的な停留性の目安であり、最適値への隔たりではない。
導出と停止条件は[二次割当てと置換の探索](../../algorithms/quadratic-assignment/)にある。

セルは `QapOptions::default()` から FAQ の反復上限（`with_max_fw_iterations`）、再開始、シード、作業領域の上限を変え、`QapPlan::solve_with_options` で最小化する。
`with_restarts(3)` は最初の試行に加えて、シードから作った初期置換で 3 回やり直し、最良の置換を返す。
`QapResult::termination` は選んだ段階の停止をまとめたもので、どれかの試行が FAQ の反復上限に達すると `IterationLimit` になり、どの状態も大域最適を証明しない。
`IterationLimit` で止まっても置換は返るので、このページの outcome では `Converged` を satisfied、`IterationLimit` を partial とする。

次の定義のブロックは、このページの二つのセルが共有する。
`objective` は返った置換を元の二重和に代入し直す独立な検算で、`solve` は $n$ 施設の流量を第一行列、距離を第二行列として Plan を作り、再開始 3 回で解く。

```rust
//| id: optimize-qap-layout-model
//| kind: definitions
//| title: 二重和の検算と、流量・距離の順に渡す QAP の求解
//| crates: [scioxide-core, scioxide-linalg, scioxide-optimize]
use scioxide_core::{Budget, SciOxideError};
use scioxide_linalg::Matrix;
use scioxide_optimize::{QapDirection, QapOptions, QapProblemView, QapResult};

/// 施設 i を地点 p[i] に置いたときの二重和 Σᵢⱼ flowᵢⱼ distance_{p(i), p(j)}。
pub(crate) fn objective(flow: &[f64], distance: &[f64], p: &[usize]) -> f64 {
    let n = p.len();
    let pairs = (0..n).flat_map(|i| (0..n).map(move |j| (i, j)));
    pairs
        .map(|(i, j)| flow[i * n + j] * distance[p[i] * n + p[j]])
        .sum()
}

/// 流量を第一行列、距離を第二行列として渡すので、permutation[i] は施設 i の地点になる。
pub(crate) fn solve(
    n: usize,
    flow: &[f64],
    distance: &[f64],
    iterations: usize,
    seed: u64,
) -> Result<QapResult<f64>, SciOxideError> {
    let flow = Matrix::from_vec(n, n, flow.to_vec())?;
    let distance = Matrix::from_vec(n, n, distance.to_vec())?;
    let plan = QapProblemView::new(flow.view(), distance.view(), &[])?.prepare()?;
    let options = QapOptions::default()
        .with_max_workspace_bytes(8_000_000)
        .with_max_fw_iterations(Budget::try_from(iterations)?)
        .with_restarts(3)
        .with_seed(seed);
    plan.solve_with_options(QapDirection::Minimize, None, &options)
}
```

## 全探索で検算できる合成問題

$n$ 施設の合成問題では、施設間の流量を 1 日あたりの搬送回数 $A_{ij}=1+(7(i+j)\bmod5)$ [回/日]（$i\ne j$、1〜5 の対称な値）とする。
地点は一直線の通路に沿って等間隔に並び、隣り合う地点の間隔を 1 区画として、距離を $B_{kl}=|k-l|$ [区画] とする。
したがって総輸送量 $F$ の単位は [回·区画/日] である。
$n!$ 通りの置換をすべて調べて最適値を求め、これを独立な参照値にする。
一つの置換の評価は $O(n^2)$ なので、全探索は $O(n!\,n^2)$ の計算量で、$n=8$ では $8!=40320$ 通りに 64 項の和を掛けた約 260 万回の積和になる。
地点の番号を $k\mapsto n-1-k$ と付け替えても距離 $|k-l|$ は変わらないので、最適な置換を付け替えた置換も最適で、最適な置換は少なくとも 2 個ある。

次のセルの入力は施設の数 $n$（5〜8）、一試行あたりの FAQ の反復上限、シードである。
図は横軸が施設番号、縦軸が割り当てた地点番号で、各地点が一度ずつ使われることを確認できる。
一つ目の表は元の二重和に代入し直した費用、`QapResult::objective` のレポート値、全探索の最適値、その隔たり、最適な置換の数である。
二つ目の表は終了理由、選んだ試行での緩和の目的値と Frank–Wolfe ギャップ、FAQ の反復と交換の検査の全試行での合計、選んだ試行の番号である。

```rust
//| id: optimize-facility-layout-qap
//| ref: optimize-facility-layout-qap
//| title: FAQ と 2-opt の割当てを全探索の最適値で確かめる
//| run: button
//| uses: [optimize-qap-layout-model]
//| crates: [scioxide-optimize]
//| inputs:
//|   facilities: {"type":"range","label":"施設の数 n [個]","min":5,"max":8,"step":1,"value":6}
//|   iterations: {"type":"range","label":"FAQ の反復上限 [回]","min":10,"max":100,"step":10,"value":30}
//|   seed: {"type":"range","label":"乱数のシード [-]","min":1,"max":100,"step":1,"value":7}
//| cases:
//|   - {"id":"eight","label":"8 施設","description":"費用は 8! = 40320 通りの全探索の最適値 438 と一致するが、FAQ の反復上限に達した試行があるので IterationLimit になる。","inputs":{"facilities":8}}
//|   - {"id":"short-faq","label":"FAQ の反復上限 10 回","description":"FAQ が反復上限に達して IterationLimit になり、outcome は partial になる。","inputs":{"iterations":10}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"costs","path":"/rows/0/0","approx":{"value":184,"atol":1e-9}}
//|       - {"artifact":"costs","path":"/rows/0/1","approx":{"value":184,"atol":1e-9}}
//|       - {"artifact":"costs","path":"/rows/0/2","approx":{"value":184,"atol":1e-9}}
//|       - {"artifact":"faq","path":"/rows/0/0","equals":"Converged"}
//|       - {"artifact":"faq","path":"/rows/0/1","approx":{"value":171.393,"atol":0.5}}
//|       - {"path":"/outputs/3/state","equals":"satisfied"}
//|   - case: eight
//|     expect:
//|       - {"artifact":"costs","path":"/rows/0/0","approx":{"value":438,"atol":1e-9}}
//|       - {"artifact":"costs","path":"/rows/0/2","approx":{"value":438,"atol":1e-9}}
//|       - {"artifact":"costs","path":"/rows/0/4","equals":64}
//|   - case: short-faq
//|     expect:
//|       - {"artifact":"faq","path":"/rows/0/0","equals":"IterationLimit"}
//|       - {"path":"/outputs/3/state","equals":"partial"}
let n = facilities as usize;
// 施設間の流量は対称な 1〜5、地点は一直線上に等間隔に並ぶ。
let flow: Vec<f64> = (0..n * n)
    .map(|k| match (k / n, k % n) {
        (i, j) if i == j => 0.0,
        (i, j) => 1.0 + ((i + j) * 7 % 5) as f64,
    })
    .collect();
let distance: Vec<f64> = (0..n * n).map(|k| (k / n).abs_diff(k % n) as f64).collect();
// 独立検算: Heap のアルゴリズムで n! 通りの置換を一つずつ作り、二重和の最小値と最適な置換の数を求める。
let mut p: Vec<usize> = (0..n).collect();
let mut counters = vec![0; n];
let (mut exact, mut optimal) = (objective(&flow, &distance, &p), 1_usize);
let mut i = 0;
while i < n {
    if counters[i] < i {
        p.swap(if i % 2 == 0 { 0 } else { counters[i] }, i);
        let value = objective(&flow, &distance, &p);
        if value < exact {
            (exact, optimal) = (value, 1);
        } else if value == exact {
            optimal += 1;
        }
        counters[i] += 1;
        i = 0;
    } else {
        counters[i] = 0;
        i += 1;
    }
}
let result =
    solve(n, &flow, &distance, iterations as usize, seed as u64).map_err(|e| e.to_string())?;
let permutation = result
    .permutation()
    .ok_or(format!("割当て候補なし: {}", result.termination()))?;
let value = objective(&flow, &distance, permutation);
let points: Vec<_> = permutation
    .iter()
    .enumerate()
    .map(|(i, &j)| [i as f64, j as f64])
    .collect();
emit_scatter_chart!(
    &vec![serde_json::json!({ "name": "割当て", "points": points })],
    options = &serde_json::json!({ "xLabel": "施設番号 [-]", "yLabel": "地点番号 [-]" })
);
let cost = serde_json::json!({ "fractionDigits": 0 });
let fixed1 = serde_json::json!({ "fractionDigits": 1 });
emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "再計算費用 [回·区画/日]", "type": "number", "format": cost },
        {
            "key": "1",
            "label": "レポート費用 [回·区画/日]",
            "type": "number",
            "format": cost,
            "nullText": "なし"
        },
        { "key": "2", "label": "全探索の最適値 [回·区画/日]", "type": "number", "format": cost },
        { "key": "3", "label": "隔たり [回·区画/日]", "type": "number", "format": cost },
        { "key": "4", "label": "最適な置換 [個]", "type": "integer" }
    ]),
    vec![(value, result.objective(), exact, value - exact, optimal)],
    metadata = serde_json::json!({ "id": "costs" })
);
emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "終了理由" },
        {
            "key": "1",
            "label": "緩和の目的値 [回·区画/日]",
            "type": "number",
            "format": fixed1,
            "nullText": "なし"
        },
        {
            "key": "2",
            "label": "Frank–Wolfe ギャップ [回·区画/日]",
            "type": "number",
            "format": fixed1,
            "nullText": "なし"
        },
        { "key": "3", "label": "FAQ 反復の合計 [回]", "type": "integer" },
        { "key": "4", "label": "交換の検査の合計 [回]", "type": "integer" },
        { "key": "5", "label": "選んだ試行 [-]", "type": "integer" }
    ]),
    vec![(
        result.termination().to_string(),
        result.relaxation_objective(),
        result.fw_gap(),
        result.fw_iterations(),
        result.swap_checks(),
        result.selected_restart()
    )],
    metadata = serde_json::json!({ "id": "faq" })
);
let outcome = if result.termination().is_success() {
    Outcome::satisfied("FAQ と 2-opt の全段階が停止条件を満たした")
} else {
    Outcome::partial("FAQ か 2-opt が上限で止まった")
};
emit_outcome!(
    outcome
        .explanation("どの終了理由も大域最適を証明しない。隔たりの列で全探索と比べる。")
        .status(result.termination().to_string())
        .diagnostic("全探索の最適値との隔たり", value - exact, Some("回·区画/日"))
        .diagnostic("FAQ 反復の合計", result.fw_iterations() as f64, None)
);
```

既定の六施設の問題では、再計算費用とレポート費用はともに 184 回·区画/日で、全探索の最適値と一致し、終了理由は `Converged` である。
720 通りのうち 8 個の置換が同じ最適値 184 を与えるので、置換そのものの一致は正解の条件にならない。
選んだ試行での緩和の目的値は 171.4 で、置換の最適値より小さいが、緩和の局所解の値なので下界としては使えない。
8 施設では、費用 438 が $8!=40320$ 通りの全探索の最適値と一致し、最適な置換は 64 個ある。
ただし四つの試行の中に FAQ の反復上限 30 回に達したものがあるので、終了理由は `IterationLimit`、outcome は partial になる。
FAQ の反復上限を 10 回にすると六施設でも `IterationLimit` になるが、2-opt の後の費用は 184 のままである。

## 12 地点の参照問題

12 地点の全列挙には $12!\approx4.8\times10^8$ 通りの置換を調べる必要がある。
ここでは、並べ替え不等式から最適値が分かる参照問題を構成する。
1 から 12 までの整数をそれぞれ並べ替えた $a$ と $b$ を用意し、$A_{ij}=a_i a_j$、$B_{st}=b_s b_t$ とする。
QAP の二重和は $(\sum_i a_i b_{p(i)})^2$ となる。
すべての重みが正なので、一方の昇順と他方の降順を組み合わせれば、内側の和もその平方も最小になる。
最小値は $(\sum_{k=1}^{12} k(13-k))^2=364^2=132496$ である。
対角成分も含む代数的な費用の行列であり、地理的な距離を表すものではない。
外部の問題行列や解のファイルは使わない。
セルは最適な置換を直接構成し、発見的解法の評価にも使う元の二重和で費用を検算する。
表示する格子の行と列は、12 地点の番号を整理するためだけのものである。

```rust
        .explanation("どの終了理由も大域最適を証明しない。隔たりの列で既知の最適値と比べる。")
        .status(result.termination().to_string())
        .diagnostic("既知の最適値との隔たり", value - 132496.0, None)
        .diagnostic("FAQ 反復の合計", result.fw_iterations() as f64, None)
);
```

厳密な最適値と、解析的に構成した置換から再計算した費用は、どちらもシードや反復上限によらず 132496 となる。
発見的解法で得た置換から再計算した費用はこの値以上であり、その差を表の「隔たり」列に示す。
差がゼロならこの参照問題で最適値が得られたことを確認できるが、ソルバーの終了理由が表すのは、その解法の停止条件である。
緩和の目的値や小さな Frank–Wolfe ギャップを大域最適性の証明として扱わず、シードと FAQ の反復上限を変えて探索の挙動を比較する。

## まとめ

施設間の流量を含む配置は、施設ごとに独立な線形割当てより難しい二次割当てになる。
`QapProblemView::new` には流量を第一行列、距離を第二行列として渡し、`permutation[i]` を施設 $i$ の地点として解釈する。
公開データの行列の順が逆なら、入れ替えて渡すか、返った置換を逆置換として解釈する。
8 施設程度までは全探索、それより大きな問題は公開されている問題の既知の最適値で検算し、どちらでも返った置換を元の二重和へ代入し直す。
終了理由、緩和の目的値、Frank–Wolfe ギャップはどれも大域最適の証拠ではないので、参照値への隔たりとシードによる違いを並べて読む。
