倉庫や配送拠点を候補地のどこに開くかを考える。
顧客への輸送費を減らすには施設を増やせばよいが、施設ごとに開設費がかかる。
容量に制約がない施設配置（uncapacitated facility location）では、どの施設を開くかと、各顧客をどこへ割り当てるかを同時に決める。

## 変数と制約

施設 $i$ の開設を $y_i\in\{0,1\}$、顧客 $j$ の需要のうち施設 $i$ へ割り当てる割合を $x_{ij}\ge0$ とする。
開設費 $f_i$、輸送費 $c_{ij}$ に対して

$$
\min\sum_i f_i y_i+\sum_{i,j}c_{ij}x_{ij},\qquad
\sum_i x_{ij}=1,\quad x_{ij}\le y_i
$$

を解く。
一つ目の制約は各顧客の需要を全て割り当てること、二つ目は閉じた施設へ割り当てないことを表す。
開設変数が整数なら、各顧客は開いた施設のうち最安のものへ割り当てられる。
輸送費が同じ施設があれば分割した解も同じ最適値を持つので、割当変数そのものの整数性は要求しない。
施設の候補数を $p$、顧客数を $q$ とすると、変数は $p+pq$ 個、制約は $q+pq$ 本である。

## 強い定式化と弱い定式化

二つ目の制約を施設ごとにまとめた $\sum_jx_{ij}\le q\,y_i$ も整数の $y$ に対しては同じ実行可能集合を表す。
制約は $p$ 本に減るが、$y$ の整数条件を外した LP 緩和では、一人の顧客を施設 $i$ に全て割り当てても $y_i=1/q$ でよく、開設費の $1/q$ しか数えない。
個別の $x_{ij}\le y_i$ では、顧客 $j$ を施設 $i$ に全て割り当てるには $y_i=1$ が要る。
$x_{ij}\le y_i$ を $j$ について足すと $\sum_jx_{ij}\le q\,y_i$ になるので、強い定式化の緩和の実行可能領域は弱い定式化の領域に含まれ、その下界は弱い定式化の下界以上になる。
整数計画は緩和の下界で枝を刈るので、下界が強いほど探索木は小さくなりやすい。
次のセルは強い定式化で MILP を解き、比較のために弱い定式化の LP 緩和の値も出す。

## 独立な全探索

施設数 $p$ が小さければ、空でない $2^p-1$ 個の開設集合を列挙できる。
集合を固定した費用は開設費の和と、顧客ごとに開いた施設への最小輸送費を足して求める。
一つの集合の評価は $O(pq)$ なので、全探索は $O(2^ppq)$ の計算量である。
これは MILP の探索木を使わない独立検算である。
LP 緩和は $y$ の整数条件だけを外し、最小費用の下界を与える。
緩和の解の $y$ がすべて 0 か 1 なら、その解は整数計画の最適解でもあり、分枝は要らない。

入力は施設の候補数、顧客数、開設費、乱数のシードである。
一辺 10 km の正方形の地域に施設の候補と顧客を一様に置き、輸送費 $c_{ij}$ はユークリッド距離に 0.1 万円/km を掛けた、1 か月に顧客 1 件の需要を運ぶ費用とする。
開設費 $f$ は全施設に共通で、同じ 1 か月に按分した施設 1 か所の費用 [万円] である。
出力は配置図、開設変数と強い定式化の緩和の $y$ の表、整数費用と全探索・二つの LP 緩和の比較の表、分枝限定法の統計の表、探索の判定である。
`BranchAndBound` の判定は、暫定解と下界の差がギャップの許容誤差以下になったかで、下界は浮動小数点の推定であり証明ではない。

```rust
use scioxide_core::Bounds;
use scioxide_linalg::Matrix;
use scioxide_optimize::{
    BranchAndBound, LinearConstraintSense, LinearConstraints, LpProblem, MipProblem,
    SimplexSolver,
};
use scioxide_random::{BitGenerator, SeedableRng, SplitMix64, decode_u64};
let (p, q) = (facilities as usize, customers as usize);
// 一辺 10 km の正方形に施設の候補と顧客を一様に置き、輸送費 cᵢⱼ [万円] を距離 [km] × 0.1 万円/km とする。
let (side, rate) = (10.0_f64, 0.1_f64);
let mut rng = SplitMix64::from_seed(seed as u64);
let mut points = Vec::new();
for _ in 0..p + q {
    let x: f64 = decode_u64(rng.next_uniform_u64().map_err(|e| e.to_string())?);
    let y: f64 = decode_u64(rng.next_uniform_u64().map_err(|e| e.to_string())?);
    points.push([side * x, side * y]);
}
let mut costs = vec![0.0; p * q];
for i in 0..p {
    for j in 0..q {
        costs[i * q + j] = rate
            * scioxide_core::RealScalar::hypot(
                points[i][0] - points[p + j][0],
                points[i][1] - points[p + j][1],
            );
    }
}
// 変数の順は (y₀, …, y_{p−1}, x₀₀, …, x_{p−1,q−1})、xᵢⱼ は列 p + iq + j。
let n = p + p * q;
let mut objective = vec![opening; p];
objective.extend_from_slice(&costs);
// 強い定式化: Σᵢ xᵢⱼ = 1（q 行）と xᵢⱼ ≤ yᵢ（pq 行）。
let rows = q + p * q;
let mut matrix = vec![0.0; rows * n];
let mut rhs = vec![0.0; rows];
let mut senses = vec![LinearConstraintSense::LessEqual; rows];
for j in 0..q {
    rhs[j] = 1.0;
    senses[j] = LinearConstraintSense::Equal;
    for i in 0..p {
        matrix[j * n + p + i * q + j] = 1.0;
    }
}
for i in 0..p {
    for j in 0..q {
        let row = q + i * q + j;
        matrix[row * n + p + i * q + j] = 1.0;
        matrix[row * n + i] = -1.0;
    }
}
let lp = LpProblem::new(objective.clone())
    .and_then(|v| {
        v.with_constraints(LinearConstraints::new(
            Matrix::from_vec(rows, n, matrix)?,
            rhs,
            senses,
        )?)
    })
    .and_then(|v| v.with_bounds(Bounds::new(vec![(Some(0.0), Some(1.0)); n])?))
    .map_err(|e| e.to_string())?;
// 比較用の弱い定式化: xᵢⱼ ≤ yᵢ を施設ごとに Σⱼ xᵢⱼ ≤ q yᵢ（p 行）へまとめる。
let weak_rows = q + p;
let mut weak = vec![0.0; weak_rows * n];
let mut weak_rhs = vec![0.0; weak_rows];
let mut weak_senses = vec![LinearConstraintSense::LessEqual; weak_rows];
for j in 0..q {
    weak_rhs[j] = 1.0;
    weak_senses[j] = LinearConstraintSense::Equal;
    for i in 0..p {
        weak[j * n + p + i * q + j] = 1.0;
    }
}
for i in 0..p {
    weak[(q + i) * n + i] = -(q as f64);
    for j in 0..q {
        weak[(q + i) * n + p + i * q + j] = 1.0;
    }
}
let weak_lp = LpProblem::new(objective)
    .and_then(|v| {
        v.with_constraints(LinearConstraints::new(
            Matrix::from_vec(weak_rows, n, weak)?,
            weak_rhs,
            weak_senses,
        )?)
    })
    .and_then(|v| v.with_bounds(Bounds::new(vec![(Some(0.0), Some(1.0)); n])?))
    .map_err(|e| e.to_string())?;
let relaxation = SimplexSolver::default()
    .solve(&lp)
    .map_err(|e| e.to_string())?;
let weak_relaxation = SimplexSolver::default()
    .solve(&weak_lp)
    .map_err(|e| e.to_string())?;
let mip = MipProblem::new(lp, (0..p).collect()).map_err(|e| e.to_string())?;
let result = BranchAndBound::default()
    .solve(&mip)
    .map_err(|e| e.to_string())?;
// 独立検算: 開設集合を列挙し、顧客ごとに開いた施設のうち最安のものを選ぶ。
let exact = (1_usize..1 << p)
    .map(|mask| {
        opening * mask.count_ones() as f64
            + (0..q)
                .map(|j| {
                    (0..p)
                        .filter(|&i| mask & (1 << i) != 0)
                        .map(|i| costs[i * q + j])
                        .fold(f64::INFINITY, f64::min)
                })
                .sum::<f64>()
    })
    .fold(f64::INFINITY, f64::min);
if !result.has_incumbent() {
    return Err(format!("整数候補なし: {}", result.termination()));
}
let open: Vec<_> = (0..p).map(|i| result.x()[i] > 0.5).collect();
let opened: Vec<_> = (0..p).filter(|&i| open[i]).map(|i| points[i]).collect();
let closed: Vec<_> = (0..p).filter(|&i| !open[i]).map(|i| points[i]).collect();
emit_scatter_chart!(
    &vec![
        serde_json::json!({"name":"開いた施設", "points":opened}),
        serde_json::json!({"name":"閉じた施設の候補", "points":closed}),
        serde_json::json!({"name":"顧客", "points":&points[p..]})
    ],
    options = &serde_json::json!({
        "xLabel": "東西の位置 [km]",
        "yLabel": "南北の位置 [km]",
        "xMin": 0,
        "xMax": 10,
        "yMin": 0,
        "yMax": 10
    })
);
let fixed4 = serde_json::json!({ "fractionDigits": 4 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let open_columns = serde_json::json!([
    { "key": "0", "label": "施設 i", "type": "integer" },
    { "key": "1", "label": "開設変数 yᵢ [-]", "type": "number", "format": { "fractionDigits": 0 } },
    { "key": "2", "label": "強い定式化の LP 緩和の yᵢ [-]", "type": "number", "format": fixed4 }
]);
let open_rows: Vec<_> = (0..p)
    .map(|i| (i, result.x()[i], relaxation.x()[i]))
    .collect();
emit_table_with_columns!(
    open_columns,
    open_rows,
    metadata = serde_json::json!({ "id": "opening" })
);
let cost_columns = serde_json::json!([
    { "key": "0", "label": "整数費用 [万円]", "type": "number", "format": fixed4 },
    { "key": "1", "label": "全探索 [万円]", "type": "number", "format": fixed4 },
    { "key": "2", "label": "差 [万円]", "type": "number", "format": sci2 },
    { "key": "3", "label": "強い定式化の LP 下界 [万円]", "type": "number", "format": fixed4 },
    { "key": "4", "label": "弱い定式化の LP 下界 [万円]", "type": "number", "format": fixed4 },
    { "key": "5", "label": "開設数 [施設]", "type": "integer" },
    { "key": "6", "label": "終了理由" }
]);
emit_table_with_columns!(
    cost_columns,
    vec![(
        result.fun(),
        exact,
        result.fun() - exact,
        relaxation.fun(),
        weak_relaxation.fun(),
        open.iter().filter(|&&o| o).count(),
        result.termination().to_string()
    )],
    metadata = serde_json::json!({ "id": "costs" })
);
let stats = result.statistics();
let search_columns = serde_json::json!([
    { "key": "0", "label": "処理節点 [個]", "type": "integer" },
    { "key": "1", "label": "LP 求解 [回]", "type": "integer" },
    { "key": "2", "label": "切除平面 [枚]", "type": "integer" },
    { "key": "3", "label": "基底再利用 [回]", "type": "integer" },
    { "key": "4", "label": "絶対ギャップ [万円]", "type": "number", "format": sci2, "nullText": "未計算" }
]);
emit_table_with_columns!(
    search_columns,
    vec![(
        stats.nodes(),
        stats.relaxations(),
        stats.cuts(),
        stats.basis_reuses(),
        result.absolute_gap()
    )],
    metadata = serde_json::json!({ "id": "search" })
);
let outcome = if result.is_success() {
    Outcome::satisfied("分枝限定法がギャップの判定を満たした")
        .explanation("下界は浮動小数点の推定で、証明ではない。")
} else {
    Outcome::partial("分枝限定法がギャップの判定を満たす前に止まった")
        .explanation("整数費用は暫定解の値で、最適性は示されていない。")
};
let mut outcome = outcome
    .status(result.termination().to_string())
    .diagnostic("処理節点", stats.nodes() as f64, None)
    .diagnostic("全探索との差", result.fun() - exact, Some("万円"));
if let Some(gap) = result.absolute_gap() {
    outcome = outcome.diagnostic("絶対ギャップ", gap, Some("万円"));
}
emit_outcome!(outcome);
```

既定の入力（4 施設、5 顧客、開設費 0.5 万円、シード 11）では施設 1 だけを開き、整数費用 2.9329 万円は全探索と一致する。
強い定式化の LP 下界も 2.9329 万円で緩和の解がすでに整数なので、分枝限定法は根の節点 1 個で終わり、絶対ギャップは 0 である。
弱い定式化の下界は 2.3059 万円で、整数費用との隔たりは 0.627 万円ある。

開設費を 0.1 万円に下げると 3 施設を開いて総費用は 2.106 万円に下がり、2 万円にすると 1 施設に戻って 4.433 万円になる。
開設費を大きくすると施設をまとめる利点が増えるが、最適な開設数は離散的に変わる。
6 施設、8 顧客、シード 3 でも整数費用は全探索の 3.212 万円と一致し、強い定式化の下界は整数費用に等しく、弱い定式化の下界は 2.174 万円にとどまる。
ここまでの例では強い定式化の緩和がすでに整数解を返したが、シードを 81 にすると緩和の解は $y=(0.5,0,0.5,0.5)$ と分数になる。
このとき強い定式化の下界 2.6525 万円は整数費用 2.6762 万円より低く、分枝限定法は 3 個の節点を処理し、試行と修復を含めて 10 回の LP を解く。
そのうち 9 回は前に解いた LP の基底から始める。
整数費用は全探索と一致し、弱い定式化の下界 1.9438 万円は強い定式化の下界よりさらに低い。
LP 下界と整数費用の差、探索器の返すギャップは、比較対象が異なるので別々に読む。

## まとめ

開設の二値変数と割当ての連続変数を組み合わせて、容量制約のない施設配置を MILP として表せる。
同じ整数解の集合を表す定式化でも、$x_{ij}\le y_i$ の強い定式化の LP 緩和の下界は $\sum_jx_{ij}\le qy_i$ の弱い定式化の下界以上で、探索を小さくできる。
強い定式化でも緩和の解が分数になる例があり、そのときは分枝の節点数と LP 求解の回数で探索の大きさを読む。
小規模な集合列挙は整数計画の出力を独立に確かめる基準になり、規模を増やすときは候補の有無、緩和の下界、レポートギャップ、探索上限を確認する。
