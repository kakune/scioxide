連続な線形計画ではリソースを一単位増やしたときの最適値の増加をシャドープライス（双対変数）で読める。
ロットが整数の生産計画では、リソースを一単位増やしても、次のロットを作れるようになるまで利益は増えない。
このページでは[完成品ロットを混合整数計画で選ぶ](../integer-production/)と同じ生産計画で電池セルの上限を一個ずつ動かし、LP 緩和の最適値と整数最適値をリソース量の関数として比べる。

## LP の価値関数とシャドープライス

問題は標準製品セット $x$ ロットと上位製品セット $y$ ロットの利益 $190x+p_yy$ [千円] を、電池セル $4x+7y\le C$、組立時間 $4x+3y\le H$、需要 $0\le x\le18$、$0\le y\le12$ のもとで最大にする。
電池セルの上限 $C$ の関数として見た最適値 $V_{\mathrm{LP}}(C)$ を価値関数と呼ぶ。
LP の最適値は右辺について凹な区分線形関数で、各区間の傾きはその区間での電池セルの制約のシャドープライスに等しい。

既定の $H=52$、$p_y=310$ で価値関数を導く。
$C\le52$ では電池セルだけが効き、電池セル 1 個あたりの利益は標準製品が $190/4=47.5$、上位製品が $310/7\approx44.3$ なので、標準製品だけを $x=C/4$ ロット作る。
$52\le C\le100$ では二つのリソースの制約がともに等号で効き、$y=(C-52)/4$、$x=(52-3y)/4$ から

$$
V_{\mathrm{LP}}(C)=2470+41.875\,(C-52)
$$

となる。
$C\ge100$ では $y$ が需要の上限 12 に達して $(x,y)=(4,12)$ に止まり、電池セルが余る。
傾き（シャドープライス）は $47.5$、$41.875$、$0$ 千円/個と減っていく。

## 整数最適値の階段

整数最適値 $V_{\mathrm{MIP}}(C)$ は $C$ について単調非減少だが、連続ではない。
電池セルを 1 個増やしても、整数点の集合が変わらなければ最適値は変わらない（水平な区間）。
最適値が段になって上がるのは、新しい整数点が実行可能になったときだけである。

段の高さは 1 ロットの利益とは限らない。
既定の入力では、$C=79$ で最適解が $(7,7)$ から $(4,9)$ に変わり、利益は $-3\times190+2\times310=50$ 千円増える。
$C=80$ では $(4,9)$ から $(6,8)$ に変わり、$2\times190-310=70$ 千円増える。
段はロットの組合せの入れ替えで生じ、その高さは組合せの差で決まる。

LP 緩和の解が整数点になる $C$ では、二つの価値関数は一致する。
$52\le C\le100$ では $C-52$ が 16 の倍数のとき、つまり $C=52,68,84,100$ で緩和解が $(13,0)$、$(10,4)$、$(7,8)$、$(4,12)$ になる。
$C=52$ から $C=100$ までに $V_{\mathrm{MIP}}$ が上がる量の平均は LP の傾き 41.875 千円/個に等しいが、電池セル 1 個ごとの増加は 0 か段の高さのどちらかである。
整数ロットの Plan では LP のシャドープライスを 1 個の電池セルの価値として使えない。

## 電池セルの上限を一個ずつ動かす

組立時間と上位製品の利益を固定し、電池セルの上限 $C=45,\dots,120$ の 76 通りで LP 緩和と MIP を解く。
1 つ目の図は LP 緩和の最適値（破線）と MIP の最適値（階段）、2 つ目の図は二つの差 $V_{\mathrm{LP}}-V_{\mathrm{MIP}}$ で、同じ $C$ の軸で連動する。
表は差が最大になる $C$、$C=80$ の前後の中心差分で測った LP の傾き、全整数点の列挙で求めた整数最適値と MIP の値の最大差である。
列挙は 247 個の整数点を元の不等式に代入する独立な検算である。
どれかの $C$ で LP か MIP が成功しなければ、その $C$ と終了状態を添えてエラーを返す。

```rust
//| id: optimize-integer-capacity-sweep
//| ref: optimize-integer-capacity-sweep
//| title: 電池セルリソースに対するLP上界と整数利益の段差
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg, scioxide-optimize]
//| inputs:
//|   sweep_labor_capacity: {"type":"range","label":"固定する組立時間 H [h]","description":"電池セル以外に効く制約を変える。","min":35,"max":80,"step":1,"value":52}
//|   sweep_premium_profit: {"type":"range","label":"上位製品セットの利益 pᵧ [千円/ロット]","description":"選ばれる整数の組合せを変える。","min":240,"max":420,"step":10,"value":310}
//| cases:
//|   - {"id":"premium-heavy","label":"上位製品セットの利益 pᵧ = 420","description":"上位製品だけを作る Plan が有利になり、差は走査の左端 C = 45 で最大の 180 千円になる。","inputs":{"sweep_premium_profit":420}}
//|   - {"id":"tight-labor","label":"組立時間 H = 35 h","description":"組立時間が先に効き、差は C = 82 で最大の 206.7 千円に広がる。","inputs":{"sweep_labor_capacity":35}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/1","equals":76}
//|       - {"artifact":"summary","path":"/rows/1/1","equals":99}
//|       - {"artifact":"summary","path":"/rows/2/1","approx":{"value":148.125,"atol":1e-6}}
//|       - {"artifact":"summary","path":"/rows/3/1","approx":{"value":41.875,"atol":1e-6}}
//|       - {"artifact":"summary","path":"/rows/4/1","range":{"min":0,"max":1e-6}}
//|   - case: premium-heavy
//|     expect:
//|       - {"artifact":"summary","path":"/rows/1/1","equals":45}
//|       - {"artifact":"summary","path":"/rows/2/1","approx":{"value":180,"atol":1e-6}}
//|       - {"artifact":"summary","path":"/rows/4/1","range":{"min":0,"max":1e-6}}
//|   - case: tight-labor
//|     expect:
//|       - {"artifact":"summary","path":"/rows/1/1","equals":82}
//|       - {"artifact":"summary","path":"/rows/2/1","approx":{"value":206.6667,"atol":1e-3}}
//|       - {"artifact":"summary","path":"/rows/4/1","range":{"min":0,"max":1e-6}}
use scioxide_core::{Bounds, SciOxideError};
use scioxide_linalg::Matrix;
use scioxide_optimize::{
    BranchAndBound, LinearConstraintSense, LinearConstraints, LpProblem, MipProblem,
    SimplexSolver,
};
use serde_json::json;

// 電池セルの上限 C だけを変えた LP 緩和を作る（利益は符号を反転して最小化）。
let relaxation = |cell: f64| -> Result<LpProblem<f64>, SciOxideError> {
    let rows = LinearConstraints::new(
        Matrix::from_vec(2, 2, vec![4.0_f64, 7.0, 4.0, 3.0])?,
        vec![cell, sweep_labor_capacity],
        vec![LinearConstraintSense::LessEqual; 2],
    )?;
    LpProblem::new(vec![-190.0_f64, -sweep_premium_profit])?
        .with_constraints(rows)?
        .with_bounds(Bounds::new(vec![
            (Some(0.0), Some(18.0)),
            (Some(0.0), Some(12.0)),
        ])?)
};
// 独立な検算: 全整数点を元の不等式に代入して整数最適値を求める。
let enumerate = |cell: f64| {
    let mut best = 0.0_f64;
    for x in 0..=18 {
        for y in 0..=12 {
            let (x, y) = (f64::from(x), f64::from(y));
            if 4.0 * x + 7.0 * y <= cell && 4.0 * x + 3.0 * y <= sweep_labor_capacity {
                best = best.max(190.0 * x + sweep_premium_profit * y);
            }
        }
    }
    best
};
let (mut lp_curve, mut mip_curve, mut gap_curve) = (Vec::new(), Vec::new(), Vec::new());
let (mut widest, mut enumeration_error) = ((0.0_f64, 0.0_f64), 0.0_f64);
for cell in 45..=120 {
    let c = f64::from(cell);
    let problem = relaxation(c).map_err(|e| e.to_string())?;
    let lp = SimplexSolver::<f64>::default()
        .solve(&problem)
        .map_err(|e| e.to_string())?;
    let mip = BranchAndBound::<f64>::default()
        .solve(&MipProblem::new(problem, vec![0, 1]).map_err(|e| e.to_string())?)
        .map_err(|e| e.to_string())?;
    if !lp.is_success() || !mip.is_success() {
        return Err(format!(
            "C = {c} で成功しなかった: LP {}、MIP {}",
            lp.termination(),
            mip.termination()
        ));
    }
    let (lp_value, mip_value) = (-lp.fun(), -mip.fun());
    let gap = lp_value - mip_value;
    if gap > widest.1 {
        widest = (c, gap);
    }
    enumeration_error = enumeration_error.max((mip_value - enumerate(c)).abs());
    lp_curve.push([c, lp_value]);
    mip_curve.push([c, mip_value]);
    gap_curve.push([c, gap]);
}
emit_line_chart!(
    &vec![
        json!({
            "name": "LP 緩和の最適値（上界）",
            "points": lp_curve,
            "style": {"lineType": "dashed"}
        }),
        json!({"name": "MIP の最適値", "points": mip_curve, "style": {"step": "end"}}),
    ],
    options = &json!({
        "link": {"group": "integer-capacity"},
        "xLabel": "電池セルの上限 C [個]",
        "yLabel": "最適な利益 [千円]"
    })
);
emit_line_chart!(
    &vec![json!({"name": "V_LP − V_MIP", "points": gap_curve, "style": {"step": "end"}})],
    options = &json!({
        "link": {"group": "integer-capacity"},
        "xLabel": "電池セルの上限 C [個]",
        "yLabel": "LP 上界との差 V_LP − V_MIP [千円]",
        "annotations": [{"kind": "line", "axis": "x", "value": widest.0, "label": "差が最大の C"}]
    })
);
// C = 80 の前後の中心差分。C = 79, 81 は走査の 35 番目と 37 番目。
let lp_slope = (lp_curve[36][1] - lp_curve[34][1]) / 2.0;
let columns = json!([
    { "key": "0", "label": "量" },
    { "key": "1", "label": "値", "type": "number", "format": { "significantDigits": 6 } }
]);
emit_table_with_columns!(
    columns,
    vec![
        ("解いた上限 C の数 [個]", lp_curve.len() as f64),
        ("差が最大の C [個]", widest.0),
        ("そのときの差 V_LP − V_MIP [千円]", widest.1),
        ("C = 80 の LP の傾き（中心差分） [千円/個]", lp_slope),
        ("MIP と全列挙の最大差 [千円]", enumeration_error),
    ],
    metadata = json!({ "id": "summary" })
);
```

既定の入力（$H=52$、$p_y=310$）では、76 通りの $C$ すべてで LP と MIP が成功し、MIP の値は全列挙と一致する。
LP の破線は $C=52$ と $C=100$ で折れ、その間の傾きは中心差分でも 41.875 千円/個で、上で導いたシャドープライスと一致する。
MIP の階段は $C\le100$ では幅 1〜4 個の水平な区間と高さ 50〜190 千円の段からなり、$C=48,52,68,84$ と $C\ge100$ で破線に接する。
差は $C=99$ で最大の 148.1 千円になる。
このとき LP の上界は 4438.1 千円だが、整数最適値は $(3,12)$ の 4290 千円で、電池セルをあと 1 個増やすと $(4,12)$ の 4480 千円に跳ぶ。

上位製品の利益を 420 千円にすると、上位製品だけを作る Plan が有利になり、差は走査の左端 $C=45$ で最大の 180 千円になる。
最大が走査範囲の端にあるときは、範囲を広げるとさらに大きな差が見つかる可能性がある。
組立時間を 35 h に絞ると、組立時間が先に効き、差は $C=82$ で最大の 206.7 千円に広がる。

差 $V_{\mathrm{LP}}-V_{\mathrm{MIP}}$ は絶対的な利益の差なので、事業の規模が違う問題を比べるには相対的な差も必要になる。
ただし利益が 0 に近いと相対的な差は不安定になるので、意思決定で許せる絶対的な差と併用する。

## まとめ

LP 緩和の価値関数は電池セルの上限について凹な区分線形関数で、既定の Plan では傾き（シャドープライス）が 47.5、41.875、0 千円/個と変わる。
整数最適値は単調非減少の階段で、電池セル 1 個の増加は利益を 0 か 50〜190 千円の段だけ変え、LP のシャドープライスはその平均の傾きにしか対応しない。
整数ロットの Plan でリソースの追加を判断するときは、シャドープライスではなく候補のリソース量ごとに MIP を解き直して比べる。
LP と MIP の差はリソース量によって 0 から 148.1 千円まで変わるので、一つのリソース量で測った差を他のリソース量へ持ち込まない。
