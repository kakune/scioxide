希ガス原子のように、近づくと強く反発し、少し離れると弱く引き合う原子の集まりを考える。
原子間距離 $r_{ij}$ の対ポテンシャルを足した Lennard-Jones（LJ）ポテンシャル

$$
E=4\varepsilon\sum_{i<j}\left[\left(\frac{\sigma}{r_{ij}}\right)^{12}-\left(\frac{\sigma}{r_{ij}}\right)^{6}\right]
$$

で全体のエネルギーを表す。
$\varepsilon$ は井戸の深さ、$\sigma$ は対ポテンシャルが 0 になる距離で、ここではエネルギーと長さの単位を $\varepsilon=\sigma=1$ とする。
一対の平衡距離は $2^{1/6}\sigma\approx1.1225\,\sigma$、そこでのエネルギーは $-\varepsilon$ である。
3 原子の正三角形と 4 原子の正四面体ではすべての対をこの距離にでき、最小エネルギーはそれぞれ $-3\varepsilon$、$-6\varepsilon$ になる。
5 原子以上ではすべての対を同時に平衡距離にできず、多くの局所最小配置が現れる。
局所最小の数は原子数とともに急速に増えるため、一つの開始点から局所法を走らせるだけでは最も低い配置に届かないことが多い。

## 局所勾配と構造の比較

差ベクトルを $d=r_i-r_j$、$s=\|d\|^2$ とすると、一対のエネルギーは $4(s^{-6}-s^{-3})$ である。
$\partial s/\partial r_i=2d$ から、粒子 $i$ の勾配への寄与は $24(s^{-4}-2s^{-7})d$ になり、粒子 $j$ には符号を変えた寄与が入る。
一回の評価は $N(N-1)/2$ 対を回るので $O(N^2)$ の計算量である。
変数は $n=3N$ 個の座標で、密な BFGS は $n\times n$ の逆ヘッセ近似を持ち、一反復に $O(n^2)$ の演算を使う。

並進と回転でエネルギーが変わらないため、局所最小は孤立点ではなく 6 次元の族をなし、ヘッセ行列には零固有値が 6 個残る。
同じ構造でも原子番号の入れ替えや回転で座標が変わるので、座標そのものではなく、エネルギー、力の大きさ $\|\nabla E\|$、原子間距離で構造を比べる。
ここでは距離が $1.35\,\sigma$ 未満の対を接触と呼び、その数を構造の指標にする。
このページで得られる構造では、最近接の対の距離は $1.08$〜$1.17\,\sigma$、それ以外の対は $1.77\,\sigma$ 以上なので、この閾値で最近接の対を数えられる。
$N=7$ の最小構造は五方両錐（点群 $D_{5h}$）で接触は 16 本、$N=13$ の最小構造は正二十面体（$I_h$）で、中心と表面の 12 本と表面どうしの 30 本を合わせて 42 本である。

## basin hopping の変換地形

basin hopping は配置 $x$ をそこから局所法で降りた先の値に置き換えた地形 $\tilde E(x)=E(\mathrm{loc}(x))$ の上を歩く。
$\tilde E$ は局所最小ごとに平らな段になり、段の間の障壁が消える。
一回の試行では現在の配置を乱数で変位させ、BFGS で緩和し、緩和後のエネルギーで受理を決める。
最初の試行だけは開始点そのものを緩和する。

受理は Metropolis 則で、緩和後のエネルギーの増加 $\Delta E>0$ を確率 $\exp(-\Delta E/T)$ で受け入れ、減少は常に受け入れる。
ここでの $T$ は目的と同じ単位を持つ量で、この例では $\varepsilon$ 単位である。
$T=0$ では上り坂を受け入れない単調な basin hopping になる。
変位は `UniformBasinProposal` で、各座標を箱の幅の $\pm8\%$（ここでは $\pm0.4\,\sigma$）以内の一様乱数で動かし、箱の端で反射させる。
一試行の計算コストは BFGS 一回分なので、試行数が同じでも目的の評価回数は局所法の反復に比例して増える。

$T$ は探索の設定であり、クラスタの熱平衡の温度を推定するものではない。
受理の判断は局所最小の値どうしで行うので、ここで生成される系列は振動する原子の熱分布とは別物である。

## 一般化焼きなましの温度

dual annealing は一般化焼きなまし（generalized simulated annealing）と局所最適化を組み合わせる。
座標を箱の幅で割った正規化座標 $u\in[0,1)$ の上で、裾の重い訪問分布（Tsallis の $q$ 分布、$q_v=2.62$）から変位を引き、箱を周期的につないで新しい点を作る。
訪問は一回ごとに目的を一回だけ評価し、局所法は初期点、生の評価値が最良値を下回った点、再加熱の点でだけ走る。

初期温度 $T_0$ からの温度は、掃引の番号 $k$ に対して

$$
T_k=T_0\,\frac{2^{q_v-1}-1}{(k+2)^{q_v-1}-1}
$$

で下がる。
一回の掃引は $2n$ 回の訪問で、前半の $n$ 回は全座標を、後半の $n$ 回は座標を一つずつ動かす。
訪問分布の尺度は $T_k^{1/(3-q_v)}/\sqrt{3-q_v}$（箱の幅を 1 とする単位）で、$T_k$ が 1 程度以上なら変位は箱全体に広がる。
上り坂の受理は $q_a=-5$ の一般化 Metropolis 則である。
受理の温度 $T_k/(k+1)$ に対して $(1-q_a)\Delta E\ge T_k/(k+1)$ なら拒否し、それ以外は確率 $[1-(1-q_a)\Delta E(k+1)/T_k]^{1/(1-q_a)}$ で受け入れる。
$T_k$ が $2\times10^{-5}T_0$ 以下になると、温度を $T_0$ に戻し、箱の中の一様乱数の点から再出発する（再加熱）。
$q_v=2.62$ ではこの比に達するのは $k\approx1250$ の掃引で、$N=7$ なら 5 万回を超える訪問のあとなので、このページの計算回数の上限では再加熱は起きない。

このように一つの数 $T_0$ が、訪問では正規化座標の尺度を、受理では目的と同じ $\varepsilon$ 単位の温度を決める。
`DualAnnealingOptions::new` の既定値は $T_0=5230$、$q_v=2.62$、$q_a=-5$、再加熱の比 $2\times10^{-5}$ である。
受理の温度 $T_k/(k+1)$ は掃引とともに下がるので、basin hopping の一定の $T$ とは役割が異なる。
そのため次のセルでは basin hopping の $T$ と dual annealing の $T_0$ を別の入力にしている。

## 探索箱と局所ソルバー

各座標を $[-2.5,2.5]$ に制限し、同じ有限箱で二方式を比較する。
大域探索の二方式はどちらも有限な箱を要求し、箱の外の開始点を拒否する。
BFGS は箱を持つ問題を受け取らないので、局所ソルバーのアダプターは箱を外した目的を渡し、箱の検査を定義域の検査 `is_in_domain` として残す。
直線探索は定義域の外の試行点を退けるので、BFGS の反復点は箱の中にとどまる。
この接続は、箱の境界に最適点がある問題を解く L-BFGS-B の代わりにはならない。
そこで、得られた構造の箱の端までの余裕も表に出す。

開始点は半径 $1\,\sigma$ の円周上に原子を等間隔に並べ、$z$ を少しずつずらした配置である。
どちらの方式も最初の試行でこの点を緩和するので、二方式の差はその後の探索から生じる。

次の定義のブロックは、このページの二つのセルが共有する。
`Cluster` がエネルギーと勾配、`Factory` と `Local` が探索に渡す局所 BFGS、`REFERENCES` が Cambridge Cluster Database の最低エネルギーと点群、`ring_start` が開始点、`search_box` が探索箱である。
参照値は [Cambridge Cluster Database の LJ クラスタの表](https://www-wales.ch.cam.ac.uk/~wales/CCD/jon/structures/LJ/tables.html)（$N=3$–$13$）の小数第 6 位までの値で、$N\ge5$ では数値探索で得られた値である。

```rust
//| id: optimize-lj-model
//| kind: definitions
//| title: LJ クラスタのエネルギー、局所 BFGS と既知の最低エネルギー
//| crates: [scioxide-core, scioxide-optimize]
use scioxide_core::{Bounds, SciOxideError, RealScalar, SolveContext};
use scioxide_optimize::{
    Bfgs, BfgsWorkspace, BoundedObjective, LocalSolverFactory, ObjectiveFunction, OptimizeResult,
    SearchLocalSolver,
};

/// N 原子の LJ クラスタ（ε = σ = 1）。座標は原子ごとの (x, y, z) を並べた 3N 成分。
pub(crate) struct Cluster(pub(crate) usize);

impl Cluster {
    /// E = Σ_{i<j} 4(s⁻⁶ − s⁻³) と勾配。s = |rᵢ − rⱼ|²。
    pub(crate) fn value_gradient(&self, x: &[f64]) -> (f64, Vec<f64>) {
        let mut value = 0.0;
        let mut gradient = vec![0.0; x.len()];
        for i in 0..self.0 {
            for j in 0..i {
                let d: [f64; 3] = std::array::from_fn(|k| x[3 * i + k] - x[3 * j + k]);
                let inverse = 1.0 / d.iter().map(|v| v * v).sum::<f64>();
                let sixth = inverse * inverse * inverse;
                value += 4.0 * (sixth * sixth - sixth);
                // ∂/∂rᵢ 4(s⁻⁶ − s⁻³) = 24(s⁻⁴ − 2s⁻⁷) d = 24 s⁻¹ s⁻³ (1 − 2 s⁻³) d。
                let coefficient = 24.0 * inverse * sixth * (1.0 - 2.0 * sixth);
                for k in 0..3 {
                    gradient[3 * i + k] += coefficient * d[k];
                    gradient[3 * j + k] -= coefficient * d[k];
                }
            }
        }
        (value, gradient)
    }
}

impl ObjectiveFunction<f64> for Cluster {
    fn dim(&self) -> usize {
        3 * self.0
    }
    fn eval(&self, x: &[f64]) -> Result<f64, SciOxideError> {
        Ok(self.value_gradient(x).0)
    }
    fn gradient_into(&self, x: &[f64], out: &mut [f64]) -> Result<bool, SciOxideError> {
        out.copy_from_slice(&self.value_gradient(x).1);
        Ok(true)
    }
    // 二つの原子が重なる点では E が定義されないので、定義域の外とする。
    fn is_in_domain(&self, x: &[f64]) -> Result<bool, SciOxideError> {
        Ok(x.iter().all(|v| v.is_finite()) && pairs(x).all(|(_, _, r)| r > 1e-6))
    }
}

/// 原子の対 (i, j) と距離 rᵢⱼ [σ]。
pub(crate) fn pairs(x: &[f64]) -> impl Iterator<Item = (usize, usize, f64)> + '_ {
    let n = x.len() / 3;
    (0..n).flat_map(move |i| {
        (0..i).map(move |j| {
            let d: [f64; 3] = std::array::from_fn(|k| x[3 * i + k] - x[3 * j + k]);
            let s = d.iter().map(|v| v * v).sum::<f64>();
            (i, j, RealScalar::sqrt(s))
        })
    })
}

/// BFGS は箱を持つ問題を受け取らないので、箱を外し、箱の検査を定義域の検査として残す。
struct Domain<'a, 'b>(&'a BoundedObjective<'b, f64>);

impl ObjectiveFunction<f64> for Domain<'_, '_> {
    fn dim(&self) -> usize {
        self.0.dim()
    }
    fn eval(&self, x: &[f64]) -> Result<f64, SciOxideError> {
        self.0.eval(x)
    }
    fn gradient_into(&self, x: &[f64], out: &mut [f64]) -> Result<bool, SciOxideError> {
        self.0.gradient_into(x, out)
    }
    fn is_in_domain(&self, x: &[f64]) -> Result<bool, SciOxideError> {
        self.0.is_in_domain(x)
    }
}

/// 探索の各試行に、作業領域を使い回す既定の BFGS を渡す。
#[derive(Debug)]
pub(crate) struct Factory;

pub(crate) struct Local {
    solver: Bfgs<f64>,
    work: BfgsWorkspace<f64>,
}

impl LocalSolverFactory<f64> for Factory {
    type Solver = Local;
    fn prepare(&self, n: usize) -> Result<Local, SciOxideError> {
        let solver = Bfgs::default();
        let work = solver.workspace(n)?;
        Ok(Local { solver, work })
    }
}

impl SearchLocalSolver<f64> for Local {
    fn minimize_into(
        &mut self,
        problem: &BoundedObjective<'_, f64>,
        start: &[f64],
        _: u64,
        out: &mut OptimizeResult<f64>,
        scope: &mut SolveContext<'_, '_>,
    ) -> Result<(), SciOxideError> {
        self.solver
            .minimize_into(&Domain(problem), start, out, &mut self.work, scope)
    }
}

/// Cambridge Cluster Database の最低エネルギー [ε] と点群（N = 3, …, 13）。
pub(crate) const REFERENCES: [(f64, &str); 11] = [
    (-3.0, "D3h"),
    (-6.0, "Td"),
    (-9.103852, "D3h"),
    (-12.712062, "Oh"),
    (-16.505384, "D5h"),
    (-19.821489, "Cs"),
    (-24.113360, "C2v"),
    (-28.422532, "C3v"),
    (-32.765970, "C2v"),
    (-37.967600, "C5v"),
    (-44.326801, "Ih"),
];

/// 半径 1σ の円周上に N 原子を等間隔に並べ、z を 0.2 i/N σ ずつずらした開始点。
pub(crate) fn ring_start(n: usize) -> Vec<f64> {
    (0..n)
        .flat_map(|i| {
            let angle = 2.0 * std::f64::consts::PI * i as f64 / n as f64;
            let height = 0.2 * i as f64 / n as f64;
            [RealScalar::cos(angle), RealScalar::sin(angle), height]
        })
        .collect()
}

/// 各座標を [−2.5σ, 2.5σ] に制限する探索箱。
pub(crate) fn search_box(n: usize) -> Result<Bounds<f64>, SciOxideError> {
    Bounds::new(vec![(Some(-2.5), Some(2.5)); 3 * n])
}
```

## 二方式の比較

3 次元の図は二方式の最良候補の構造で、どちらも重心を原点に移し、dual annealing の構造は $x$ 方向に $4\,\sigma$ ずらして並べる。
距離が $1.35\,\sigma$ 未満の対を線で結び、点を選ぶと原子間の距離を測れる。

```rust
        annealing.minimize(&problem, &start),
    ),
] {
    let report = report.map_err(|e| e.to_string())?;
    let best = report.best().ok_or(format!("{name}: 有限な候補がない"))?;
    // 独立な検算: 返った座標を元の対ポテンシャルに代入し、エネルギーと力を求め直す。
    let x = best.x();
    let (energy, gradient) = f.value_gradient(x);
    let force = RealScalar::sqrt(gradient.iter().map(|g| g * g).sum::<f64>());
    let closest = pairs(x).map(|(_, _, r)| r).fold(f64::INFINITY, f64::min);
    let contacts: Vec<_> = pairs(x).filter(|&(_, _, r)| r < 1.35).collect();
    let margin = 2.5 - x.iter().map(|v| v.abs()).fold(0.0, f64::max);
    energies.push((
        name,
        energy,
        reference,
        group,
        energy - reference,
        force,
        closest,
        contacts.len(),
        margin,
    ));
    let evaluations = report.counts().total().map_err(|e| e.to_string())?;
    work.push((
        name,
        report
            .starts()
            .iter()
            .filter(|s| s.local_result().is_some())
            .count(),
        report.starts().iter().filter(|s| s.accepted()).count(),
        evaluations.provider(EvaluationRole::Objective),
        report.termination().to_string(),
        best.termination().to_string(),
    ));
    // 図: 重心を原点に移し、dual annealing の構造は x 方向に shift [σ] ずらす。
    let centroid: [f64; 3] =
        std::array::from_fn(|k| x.iter().skip(k).step_by(3).sum::<f64>() / n as f64);
    for (i, p) in x.chunks_exact(3).enumerate() {
        let position = [
            p[0] - centroid[0] + shift,
            p[1] - centroid[1],
            p[2] - centroid[2],
        ];
        points.push(serde_json::json!({ "id": format!("{tag}-{i}"), "position": position, "group": tag }));
    }
    for (i, j, _) in contacts {
        edges.push(
            serde_json::json!({ "from": format!("{tag}-{i}"), "to": format!("{tag}-{j}") }),
        );
    }
    if tag == "bh" {
        basin_report = Some((report.termination(), energy - reference, force, evaluations));
    }
}
let axis = |label: &str| serde_json::json!({ "label": label, "unit": "σ" });
emit_scene3d!(
    serde_json::json!({
        "points": points,
        "edges": edges,
        "groups": [
            { "id": "bh", "label": "basin hopping の最良候補" },
            { "id": "da", "label": "dual annealing の最良候補（x を +4σ）" }
        ],
        "axes": { "x": axis("x"), "y": axis("y"), "z": axis("z") }
    }),
    metadata = serde_json::json!({ "id": "structures", "title": format!("LJ{n} の最良候補") })
);
let fixed6 = serde_json::json!({ "fractionDigits": 6 });
let fixed4 = serde_json::json!({ "fractionDigits": 4 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "方法" },
        { "key": "1", "label": "エネルギー [ε]", "type": "number", "format": fixed6 },
        { "key": "2", "label": "文献値 [ε]", "type": "number", "format": fixed6 },
        { "key": "3", "label": "文献の点群" },
        { "key": "4", "label": "差 [ε]", "type": "number", "format": sci2 },
        { "key": "5", "label": "‖∇E‖ [ε/σ]", "type": "number", "format": sci2 },
        { "key": "6", "label": "最短の原子間距離 [σ]", "type": "number", "format": fixed4 },
        { "key": "7", "label": "接触 r < 1.35σ [本]", "type": "integer" },
        { "key": "8", "label": "箱までの余裕 [σ]", "type": "number", "format": fixed4 }
    ]),
    energies,
    metadata = serde_json::json!({ "id": "energies" })
);
emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "方法" },
        { "key": "1", "label": "局所解のある試行 [回]", "type": "integer" },
        { "key": "2", "label": "受理 [回]", "type": "integer" },
        { "key": "3", "label": "目的の評価 [回]", "type": "integer" },
        { "key": "4", "label": "探索の終了理由" },
        { "key": "5", "label": "最良候補の終了理由" }
    ]),
    work,
    metadata = serde_json::json!({ "id": "work" })
);
let (termination, gap, force, evaluations) =
    basin_report.ok_or("basin hopping の結果がない")?;
emit_outcome!(
    Outcome::partial("basin hopping は予定した試行を終えた。最良候補は大域最小の証明ではない")
        .explanation("文献値との差と ‖∇E‖ で、最良候補が既知の最小構造かを判断する。")
        .status(termination.to_string())
        .diagnostic("文献値との差", gap, Some("ε"))
        .diagnostic("‖∇E‖", force, Some("ε/σ"))
        .diagnostic(
            "目的の評価",
            evaluations.provider(EvaluationRole::Objective) as f64,
            None
        )
);
```

既定の入力（$N=7$、basin hopping 10 試行、$T=0.5\,\varepsilon$、$T_0=5230$、訪問 1000 回、シード 7）では、basin hopping は 2707 回の目的の評価で $-16.505384\,\varepsilon$ に達し、文献値と表の 6 桁まで一致する。
返った座標の $\|\nabla E\|$ は $6.7\times10^{-8}\,\varepsilon/\sigma$ で、接触は五方両錐の 16 本、最短の原子間距離 $1.1152\,\sigma$ は対の平衡距離 $1.1225\,\sigma$ より少し短く、箱の端まで $1.25\,\sigma$ の余裕がある。
最短距離が対の平衡距離より短いのは、周りの原子からの引力が対を押し縮めるためである。
dual annealing は 1179 回の評価のあとも、開始点を緩和した $-14.568061\,\varepsilon$（接触 14 本）にとどまる。
局所解のある試行は初期点の 1 回だけで、残りの訪問では生のエネルギーが一度も最良値を下回らなかった。

この差は、二方式が何を比べているかから説明できる。
basin hopping は一試行ごとに局所最小まで降りてから比べるので、局所最小どうしの比較になる。
dual annealing の訪問は生のエネルギーで比べ、箱の中の任意の点では、どこかの対が近すぎて大きな正のエネルギーを持ちやすい。
$T_0=5230$ では訪問分布の尺度が箱の幅をはるかに超え、変位はほぼ一様乱数になる。
訪問数を 5000 回にして目的の評価回数を 5179 回と basin hopping の 2 倍近くにしても、結果は同じ $-14.568061\,\varepsilon$ である。

$T_0=1$ にすると、温度が下がるにつれて訪問が現在の点の近くに集まり、1000 回の訪問のうちに 2 回目の局所最適化が走って $-15.593211\,\varepsilon$ まで下がる。
$T_0=0.2$ 以下では、1000 回の訪問のあとも開始点を緩和した値のままである。
どの設定でも LJ7 の最低値には届かないので、この地形と計算回数の上限では、局所最小の上を歩く basin hopping のほうが効率がよい。
これはこの問題と計算回数の上限での観測であり、dual annealing が一般に劣ることを示すものではない。

basin hopping の試行を 5 回にすると、既定のシードでは別の局所最小 $-15.593211\,\varepsilon$（接触 15 本）で止まる。
$N=13$、試行 5 回では、シード 7 で正二十面体の $-44.326801\,\varepsilon$（接触 42 本）に達するが、シード 1 では $-41.471980\,\varepsilon$（接触 39 本）にとどまる。
温度 $T$ を 0 にすると上り坂を受け入れないので、既定の入力では受理が 10 試行中 9 回から 4 回に減る。
$T$ を大きくすると高い局所最小にも移りやすくなり、探索は広がるが、低い局所最小の近くにとどまりにくくなる。
$N=3$ では、どちらの方式も解析値 $-3\varepsilon$ の正三角形に達する。

## シードによる成功率

一回の探索で最低値に届くかどうかは、乱数のシードで変わる。
次のセルは basin hopping だけをシード $1,2,\dots,S$ で繰り返し、最良候補のエネルギーが文献値から $10^{-4}\,\varepsilon$ 以内に入った割合を成功率として数える。
成功率 $\hat p=k/S$ の 95% 信頼区間には、少ない回数や 0、1 に近い割合でも範囲が $[0,1]$ に収まる Wilson の区間

$$
\frac{\hat p+\dfrac{z^2}{2S}\pm z\sqrt{\dfrac{\hat p(1-\hat p)}{S}+\dfrac{z^2}{4S^2}}}{1+\dfrac{z^2}{S}},\qquad z=1.96
$$

を使う。
シードごとの探索を独立な試行とみなすと、成功の数は二項分布に従う。
入力は原子数、試行数、温度 $T$、シードの数 $S$ で、開始点と箱は前のセルと同じである。
グラフはシードごとの最良候補のエネルギーで、文献値を破線で示す。
表は成功の数、成功率と信頼区間、探索一回あたりの平均の目的の評価回数である。

```rust
//| id: optimize-lennard-jones-seeds
//| ref: optimize-lennard-jones-seeds
//| title: シードを変えて basin hopping の成功率を信頼区間で読む
//| run: button
//| timeoutMs: 120000
//| uses: [optimize-lj-model]
//| crates: [scioxide-core, scioxide-optimize]
//| inputs:
//|   atoms: {"type":"range","label":"原子数 N [個]","min":3,"max":13,"step":1,"value":13}
//|   attempts: {"type":"range","label":"試行数 [回]","min":5,"max":30,"step":5,"value":5}
//|   temperature: {"type":"range","label":"Metropolis 温度 T [ε]","min":0,"max":2,"step":0.1,"value":0.5}
//|   seeds: {"type":"range","label":"シードの数 S [個]","min":5,"max":40,"step":5,"value":20}
//| cases:
//|   - {"id":"more-hops","label":"試行 15 回","description":"成功は 20 個中 17 個に増え、95% 信頼区間は [0.64, 0.95] になる。","inputs":{"attempts":15}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"rate","path":"/rows/0/1","equals":9}
//|       - {"artifact":"rate","path":"/rows/0/3","approx":{"value":0.2582,"atol":1e-3}}
//|       - {"artifact":"rate","path":"/rows/0/4","approx":{"value":0.6579,"atol":1e-3}}
//|   - case: more-hops
//|     expect:
//|       - {"artifact":"rate","path":"/rows/0/1","equals":17}
use scioxide_core::{Budget, EvaluationRole, RealScalar};
use scioxide_optimize::{
    BasinHopping, BasinHoppingOptions, BoundedObjective, GlobalSearchOptions,
    UniformBasinProposal,
};
let n = atoms as usize;
let f = Cluster(n);
let bounds = search_box(n).map_err(|e| e.to_string())?;
let problem = BoundedObjective::new(&f, &bounds).map_err(|e| e.to_string())?;
let (reference, _) = REFERENCES[n - 3];
let start = ring_start(n);
let hops = Budget::try_from(attempts as usize).map_err(|e| e.to_string())?;
let proposal = UniformBasinProposal::new(0.08).map_err(|e| e.to_string())?;
let (mut found, mut successes, mut evaluations) = (vec![], 0_usize, 0_usize);
for seed in 1..=seeds as u64 {
    let options = GlobalSearchOptions::default()
        .with_seed(seed)
        .with_starts(hops);
    let search = BasinHopping::new(
        BasinHoppingOptions::new(options, temperature).map_err(|e| e.to_string())?,
        proposal.clone(),
        Factory,
    )
    .map_err(|e| e.to_string())?;
    let report = search
        .minimize(&problem, &start)
        .map_err(|e| e.to_string())?;
    let best = report
        .best()
        .ok_or(format!("シード {seed}: 有限な候補がない"))?;
    // 独立な検算: 成功の判定は、返った座標で計算し直したエネルギーで行う。
    let energy = f.value_gradient(best.x()).0;
    successes += usize::from((energy - reference).abs() < 1e-4);
    evaluations += report
        .counts()
        .total()
        .map_err(|e| e.to_string())?
        .provider(EvaluationRole::Objective);
    found.push([seed as f64, energy]);
}
// Wilson の 95% 信頼区間。
let s = seeds as f64;
let (p, z) = (successes as f64 / s, 1.96);
let center = (p + z * z / (2.0 * s)) / (1.0 + z * z / s);
let half = z * RealScalar::sqrt(p * (1.0 - p) / s + z * z / (4.0 * s * s)) / (1.0 + z * z / s);
// 成功が 0 回のとき下限は厳密に 0 なので、丸めで生じる負の微小値だけを 0 にそろえる。
let (lower, upper) = ((center - half).max(0.0), center + half);
emit_scatter_chart!(
    &vec![serde_json::json!({ "name": "最良候補", "points": found })],
    options = &serde_json::json!({
        "xLabel": "シード [-]",
        "yLabel": "最良候補のエネルギー [ε]",
        "annotations": [{
            "kind": "line",
            "axis": "y",
            "value": reference,
            "label": "文献値",
            "style": { "lineType": "dashed" }
        }]
    })
);
let fixed2 = serde_json::json!({ "fractionDigits": 2 });
emit_table_with_columns!(
    serde_json::json!([
        { "key": "0", "label": "シードの数 S [個]", "type": "integer" },
        { "key": "1", "label": "成功 [回]", "type": "integer" },
        { "key": "2", "label": "成功率 [-]", "type": "number", "format": fixed2 },
        { "key": "3", "label": "95% CI の下限 [-]", "type": "number", "format": fixed2 },
        { "key": "4", "label": "95% CI の上限 [-]", "type": "number", "format": fixed2 },
        { "key": "5", "label": "目的の評価の平均 [回]", "type": "number", "format": { "fractionDigits": 0 } }
    ]),
    vec![(
        seeds as usize,
        successes,
        p,
        lower,
        upper,
        evaluations as f64 / s
    )],
    metadata = serde_json::json!({ "id": "rate" })
);
```

既定の入力（$N=13$、試行 5 回、$T=0.5\,\varepsilon$、$S=20$）では、20 個のシードのうち 9 個で最低値に届き、成功率は 0.45、95% 信頼区間は $[0.26,0.66]$ である。
グラフでは、届かなかった 11 個のシードの最良候補がすべて $-41.471980\,\varepsilon$ に並ぶ。
これは開始点を緩和した局所最小で、5 回の試行ではその段から抜け出せなかったことを示す。
試行を 15 回に増やすと、成功は 20 個中 17 個、成功率は 0.85、信頼区間は $[0.64,0.95]$ になり、二つの区間は 0.64〜0.66 でわずかに重なる。
その代わり一回あたりの目的の評価は平均 2264 回から 5952 回に増えるので、成功率と評価回数を合わせて設定を選ぶ。
$S=20$ の区間の幅は 0.3〜0.4 あり、成功率の小さな差を比べるにはシードの数を増やす必要がある。

## 基準振動への接続

表示した座標は $\sigma=1$、エネルギーは $\varepsilon=1$ の単位系である。
[Lennard-Jones クラスタの力と基準振動](../../../scioxide-ad/examples/lennard-jones-normal-modes/)も同じポテンシャルと同じ単位を使う。
4 原子の参照構造と比較するときは、粒子番号や回転をそろえる代わりに、六つの対距離を $2^{1/6}$ と比較できる。
基準振動を調べる前に $\|\nabla E\|$ が十分小さいことを確認し、停留点でない配置のヘッセ行列を平衡構造の振動と解釈しない。
平衡構造のヘッセ行列には並進と回転の 6 個の零固有値が現れ、残りの $3N-6$ 個が正なら局所最小である。

## まとめ

basin hopping の $T$ は目的と同じ $\varepsilon$ 単位の Metropolis 温度で、dual annealing の $T_0$ は訪問の広さ（正規化座標）と受理の温度（$\varepsilon$ 単位）の両方を決める初期温度である。
二方式を比べるときは試行数ではなく目的の評価回数をそろえ、最良候補のエネルギー、$\|\nabla E\|$、接触の数、文献値との差を同じ表で読む。
終了理由 `SearchBudgetCompleted` は予定した試行を終えたことだけを表し、大域最小であることは示さない。
最低値に届いたかどうかはシードで変わるので、一回の成功ではなく、複数のシードでの成功率と信頼区間で探索の設定を評価する。
