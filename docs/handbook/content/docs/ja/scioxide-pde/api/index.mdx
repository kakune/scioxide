`scioxide-pde` は、偏微分方程式を空間について離散化する Plan と、その結果を定常・時間発展の求解や既存の線形・非線形・時間積分の解法へ渡す接続部を出力に反映する。
有限差分法（FDM）・有限体積法（FVM）・P1/P2 有限要素法（FEM）の Plan は、一つの型で一次元から三次元までを扱い、共通の約束 `SpatialDiscretization` を実装する。
定常問題は `EllipticProblem`、熱方程式は `ParabolicProblem`、波動方程式は `HyperbolicProblem` が、どの Plan に対しても同じ形で解く。
弾性体、非圧縮流れ、双曲型保存則、適応細分化（AMR）、離散随伴は、残差・接線・作用素を `scioxide-linalg`・`scioxide-sparse`・`scioxide-rootfind`・`scioxide-ode` の解法へ渡す形で提供する。

どの操作も設定、準備、実行の順に進む。
準備した Plan は不変で `Send + Sync + Clone` であり、作業領域は呼び出し側が所有して最後の試行を記録する。
どの関数も呼び出し元の識別子を受け取らない。
このガイドは目的から API の項目を示し、rustdoc の全 163 項目を用途別の表にまとめる。
表の項目名のリンクは、docs.rs の 0.1.0 の API リファレンスを指す。

## 目的別の API

疎行列は `scioxide-sparse` の `CsrMatrix`、反復解法と零空間を持つ拡大系は `scioxide-linalg`、Newton–Krylov 法は `scioxide-rootfind`、時間積分と随伴の時間方向の走査は `scioxide-ode` が担う。

## 型の関係

- **境界条件**：`BoundaryCondition` は領域、成分（省略時は全成分）、`BoundaryKind`（`Dirichlet`・`Natural`・`Robin`）、時間依存を提示した `BoundaryData` をまとめる。
  `BoundaryConditions` は条件の完全な一覧を一つのメッシュの revision に結び付ける。
  構造格子では `StructuredBoundaries`（領域は `BoundarySet`）、単体メッシュと適応メッシュでは `TaggedBoundaries`（領域は `u32` のタグ）を使う。
  自然境界のデータはどの離散化でも外向きの余法線流束 $n\cdot K\nabla u$ である。
- **空間離散化**：`StructuredFdmPlan`・`SimplexFemPlan`・`StructuredFvmPlan`・`SimplexFvmPlan` は係数を準備時に標本化する。
  `SpatialDiscretization` として、時刻に依存しない消去済みの作用素 $A$、正の集中質量、構造的な定数モード、任意の時刻で評価する荷重 $b(t)$ を返す。
  源項は `FieldData` として荷重の評価時に渡す。
  作用素の適用は `scioxide_core::LinearOperator` の `apply_into`（逐次）と `apply_into_scoped`（呼び出し側の実行コンテキスト）だけで行う。
- **定常の求解**：`EllipticProblem` は Plan と源項（必要なら零空間の基底）を借用し、設定は `EllipticOptions` に分けて呼び出しごとに渡す。
  `solve_into(options, out, workspace, scope)` は呼び出し側の配列と `EllipticWorkspace` に書く。
  所有する結果が欲しいときは、`solve_with_options(options)` が `EllipticSolution` を返し、`solve()` は既定の設定で値の配列だけを返す。
- **時間発展の求解**：`ParabolicProblem::new(plan, source, end)` と `HyperbolicProblem::new(plan, source, end)` は自由な未知数の半離散系 `SemidiscreteSystem` を一度だけ準備する。
  `initial_state` が呼び出し側の所有する `PdeState` を作り、`advance(options, state, sink, workspace, scope)` がそれを終端時刻まで進める。
  `resume` は `PdeCheckpoint` を検査してから復元して進める。
  所有値を返す API の `solve_with_options` は `PdeSolution` を返し、`solve` は最終の場だけを返す。
  どちらも失敗のときは `PartialFailure<PdeProgress>` を返す。
- **物理モデル**：弾性体と非圧縮流れは `SimplexFemOptions` と `TaggedBoundaries` を共有する。
  線形の Plan は作用素と荷重、非線形の Plan は残差と接線（`ResidualOperator`・`JacobianOperator`）を提供する。
  固定した状態の接線はどの残差でもプロバイダーの積を借用する `PdeTangent` で表す。
  超弾性と Navier–Stokes では、`linearize` が一度だけ評価して CSR に保つ `SimplexLinearization` も使える。
  単体メッシュの Plan の行列は `SimplexCsrWorkspace` を使って同じ構造の既存の CSR に確保なしで書き直せる。
- **時間・非線形・随伴**：`MethodOfLinesPlan` は対角の質量と尺度の正規化だけを担い、時間積分は `scioxide-ode` が行う。
  `NonlinearPdeProblem` は `OdeSystem` の右辺を定常残差として `scioxide-rootfind` に渡す。
  `DifferentiableDiscretization::parameterize` は Plan のデータの微分 `PdeParameterization` を作り、`PdeEllipticAdjointPlan`・`PdeTransientAdjointPlan` がそれを使って勾配を求める。

## 最小の実行例：一次元の Dirichlet 問題

区間 $[0,1]$ の $-u''=0$ に $u(0)=2$、$u(1)=5$ を課し、`StructuredFdmPlan` で離散化して `EllipticProblem` で解く。
厳密解 $u=2+3x$ は一次関数なので、三点差分は打切り誤差なしに再現し、誤差は丸めと内側の線形解法の止まり方だけで決まる。
入力は頂点数、内側の解法、反復の上限である。
既定では Plan が三重対角の直接法を選び、「CG」を選ぶと作業領域に共役勾配法（CG）を注入する。
反復の上限は `EllipticOptions::with_max_linear_iterations` で与え、注入した CG は自分の上限（200 回）とこの上限の小さい方で止まる。
直接法には反復の上限は効かない。
表には最大誤差、解法の名前、反復回数、最終残差、終了理由、信頼を並べ、最後の outcome で終了理由を判定する。

```rust
//| id: pde-api-affine-field
//| ref: pde-api-affine-field
//| title: 一次元の Dirichlet 問題を FDM で解き、診断を読む
//| run: reactive
//| crates: [scioxide-pde, scioxide-spatial, scioxide-core, scioxide-linalg]
//| inputs:
//|   vertex_count: {"type":"range","label":"頂点数 N+1 [-]","min":3,"max":33,"step":2,"value":5}
//|   inner_solver: {"type":"select","label":"内側の解法","options":["三重対角の直接法（既定）","CG（作業領域に注入）"],"value":"三重対角の直接法（既定）"}
//|   iteration_cap: {"type":"range","label":"反復の上限 [回]","description":"注入した CG だけに効く。","min":1,"max":64,"step":1,"value":64}
//| cases:
//|   - {"id":"cg-coarse","label":"CG を注入（5 頂点）","description":"同じ消去済みの行列を CG で解き、4 回の反復で Completed になる。","inputs":{"inner_solver":"CG（作業領域に注入）"}}
//|   - {"id":"cg-fine","label":"CG を注入（33 頂点）","description":"反復は 32 回に増え、最大誤差は丸めの水準にとどまる。","inputs":{"inner_solver":"CG（作業領域に注入）","vertex_count":33}}
//|   - {"id":"cg-capped","label":"CG を 8 回で打ち切る（33 頂点）","description":"LinearIterationLimit で止まり、CG が返した未収束の反復値が DiagnosticOnly の信頼で書かれる。","inputs":{"inner_solver":"CG（作業領域に注入）","vertex_count":33,"iteration_cap":8}}
//|   - {"id":"direct-fine","label":"直接法（33 頂点）","description":"直接法は反復を使わず、最大誤差と残差は丸めの水準になる。","inputs":{"vertex_count":33}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"solve","path":"/rows/0/1","range":{"min":0,"max":1e-14}}
//|       - {"artifact":"solve","path":"/rows/0/2","equals":"tridiagonal-direct"}
//|       - {"artifact":"solve","path":"/rows/0/3","equals":0}
//|       - {"artifact":"solve","path":"/rows/0/5","equals":"Completed"}
//|       - {"artifact":"solve","path":"/rows/0/6","equals":"ResidualChecked"}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: cg-coarse
//|     expect:
//|       - {"artifact":"solve","path":"/rows/0/2","equals":"CG"}
//|       - {"artifact":"solve","path":"/rows/0/3","range":{"min":3,"max":5}}
//|       - {"artifact":"solve","path":"/rows/0/5","equals":"Completed"}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: cg-fine
//|     expect:
//|       - {"artifact":"solve","path":"/rows/0/1","range":{"min":0,"max":1e-12}}
//|       - {"artifact":"solve","path":"/rows/0/3","range":{"min":30,"max":34}}
//|       - {"artifact":"solve","path":"/rows/0/5","equals":"Completed"}
//|   - case: cg-capped
//|     expect:
//|       - {"artifact":"solve","path":"/rows/0/1","approx":{"value":4.15625,"rtol":1e-9}}
//|       - {"artifact":"solve","path":"/rows/0/3","equals":8}
//|       - {"artifact":"solve","path":"/rows/0/5","equals":"LinearIterationLimit"}
//|       - {"artifact":"solve","path":"/rows/0/6","equals":"DiagnosticOnly"}
//|       - {"path":"/outputs/1/state","equals":"partial"}
//|   - case: direct-fine
//|     expect:
//|       - {"artifact":"solve","path":"/rows/0/0","equals":33}
//|       - {"artifact":"solve","path":"/rows/0/1","range":{"min":0,"max":1e-13}}
//|       - {"artifact":"solve","path":"/rows/0/3","equals":0}
//|       - {"artifact":"solve","path":"/rows/0/5","equals":"Completed"}
use scioxide_core::{Budget, ExecutionContext, SciOxideError, ResidualTolerance};
use scioxide_linalg::CgSolver;
use scioxide_pde::{
    BoundaryCondition, BoundaryData, BoundaryPoint, ConstantDiffusion, EllipticOptions,
    EllipticProblem, EllipticWorkspace, FieldData, PdeTermination, SpatialDiscretization,
    SpatialLimits, StructuredBoundaries, StructuredFdmPlan,
};
use scioxide_spatial::{
    AxisSide, AxisTopology, BoundarySet, CoordinateAxis, Grid1d, SegmentMesh,
};

let vertices = vertex_count as usize;
let axis = CoordinateAxis::uniform(0.0, 1.0, vertices).map_err(|e| e.to_string())?;
let grid = Grid1d::new([axis], [AxisTopology::Bounded]).map_err(|e| e.to_string())?;
let mesh = SegmentMesh::new(grid).map_err(|e| e.to_string())?;
// 両端の Dirichlet 値は厳密解 2 + 3x から与える。
let exact = BoundaryData::time_invariant(|p: BoundaryPoint<f64, 1>| Ok(2.0 + 3.0 * p.point[0]));
let conditions = [AxisSide::Start, AxisSide::End]
    .into_iter()
    .map(|side| {
        let region = BoundarySet::axis_side(&mesh, 0, side)?;
        Ok(BoundaryCondition::dirichlet(region, exact.clone()))
    })
    .collect::<Result<Vec<_>, SciOxideError>>()
    .map_err(|e| e.to_string())?;
let boundaries = StructuredBoundaries::new(&mesh, 1, conditions).map_err(|e| e.to_string())?;
let limits = SpatialLimits::new(64, 1024, 1 << 20);
// -u'' = 0: 拡散係数 1 の定数係数（反応は 0）。
let coefficients = ConstantDiffusion::new(1.0);
let plan = StructuredFdmPlan::with_options(mesh, &coefficients, &boundaries, limits)
    .map_err(|e| e.to_string())?;
let source = FieldData::zero();
let problem = EllipticProblem::new(&plan, &source);
let cap = Budget::try_from(iteration_cap as usize).map_err(|e| e.to_string())?;
let options = EllipticOptions::new().with_max_linear_iterations(cap);
let mut workspace = EllipticWorkspace::new();
if inner_solver == "CG（作業領域に注入）" {
    let tolerance = ResidualTolerance::new(1e-12, 1e-12).map_err(|e| e.to_string())?;
    let limit = Budget::try_from(200).map_err(|e| e.to_string())?;
    workspace = workspace.with_linear_solver(Box::new(CgSolver::new(tolerance, limit)));
}
let mut values = vec![0.0; plan.unknowns()];
let report = problem
    .solve_into(
        &options,
        &mut values,
        &mut workspace,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;
// 未知数の物理座標は Plan の dof_point から読み、厳密解と比べる（独立な検算）。
let mut error = 0.0_f64;
for (unknown, u) in values.iter().enumerate() {
    let x = plan.dof_point(unknown).map_err(|e| e.to_string())?.point[0];
    error = error.max((u - (2.0 + 3.0 * x)).abs());
}
let d = report.diagnostics();
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "頂点数 [-]", "type": "integer" },
    { "key": "1", "label": "最大誤差 [-]", "type": "number", "format": sci3 },
    { "key": "2", "label": "内側の解法" },
    { "key": "3", "label": "反復回数 [回]", "type": "integer" },
    { "key": "4", "label": "最終残差 [-]", "type": "number", "format": sci3, "nullText": "なし" },
    { "key": "5", "label": "終了理由" },
    { "key": "6", "label": "信頼" }
]);
let row = (
    vertices,
    error,
    d.method().unwrap_or("なし").to_owned(),
    d.num_linear_iterations(),
    d.residual_norm(),
    report.termination().to_string(),
    format!("{:?}", report.trust()),
);
emit_table_with_columns!(
    columns,
    vec![row],
    metadata = serde_json::json!({ "id": "solve" })
);

let termination = report.termination();
let outcome = match termination {
    _ if termination.is_success() => Outcome::satisfied("消去済みの線形系を許容誤差まで解いた")
        .explanation("線形系の残差の判定であり、空間離散化の誤差は主張しない。"),
    PdeTermination::LinearBreakdown(_) => Outcome::failed("内側の反復法が破綻した"),
    _ => Outcome::partial("内側の反復法が上限で止まった")
        .explanation("書かれた値は未収束の反復値で、信頼は DiagnosticOnly である。"),
};
emit_outcome!(
    outcome
        .status(termination.to_string())
        .diagnostic("最大誤差", error, None)
        .diagnostic("反復回数", d.num_linear_iterations() as f64, None)
);
```

既定の 5 頂点では三重対角の直接法 `tridiagonal-direct` が解き、反復回数は 0 である。
最大誤差と残差はこの例では 0 になり、信頼は残差を独立に検査した `ResidualChecked` である。
CG を注入すると同じ消去済みの行列を反復で解き、5 頂点では 4 回、33 頂点では 32 回の反復で `Completed` になる。
33 頂点で反復の上限を 8 回にすると、CG は `LinearIterationLimit` で止まる。
このとき `solve_into` はエラーを返さず、注入した解法が返した反復値を `values` に書き、信頼を `DiagnosticOnly` にしたレポートを `Ok` で返す。
`scioxide-linalg` の CG は上限で止まると、そのときの反復値の真の残差を確かめ、確かめた反復値のうち残差が最小のものを返す。
この例の最終残差は $2.13\times10^{1}$ で、初期値 0 での残差 $\lVert b\rVert_2\approx1.72\times10^{2}$ より小さいが、最大誤差は 4.16 で解からは遠い。
outcome は `partial` になる。
`DiagnosticOnly` の値は解として使わず、上限や解法を変えて解き直す。
この直線解は空間離散化で正確に再現できるため、この例は一般の問題の格子誤差を測っていない。
所有する結果だけが欲しい場合は、作業領域を作らずに `EllipticProblem::solve_with_options` を呼べば `EllipticSolution` が返る。

## 結果・エラー・診断の読み方

- **終了理由**：`PdeTermination` が唯一の権威である。
  `Completed` 以外（`LinearIterationLimit`・`LinearStagnation`・`LinearConditionLimit`・`LinearBreakdown`・`LinearLeastSquaresConverged`・`TimeStepLimit`・`TimeStepSizeLimit`・`EvaluationLimit`・`ExecutionStopped`）は、`Ok` で返っても要求を満たしていない。
  判定は `report.is_success()` で行う。
  `LinearLeastSquaresConverged` は正規方程式だけが収束した状態で、物理の方程式が解けたことは示さない。
- **信頼**：`PdeSolveReport::trust` は出力に反映した状態の信頼を示す。
  注入した反復法が上限・停滞・条件数の上限で止まった定常の求解は、未収束の反復値を `DiagnosticOnly` の信頼で書く。
- **エラー**：入力・境界・メッシュの revision の不整合は `InvalidInput`、配列の長さの不一致は `DimensionMismatch`、コールバックの非有限値は `NonFinite` になる。
  分類は `e.kind()` と `e.view()` で読む。
  `EllipticProblem::solve_into` はエラーのとき `out` を変えない。
  `ParabolicProblem::advance` はエラーのとき状態に最後に受理した点を残し、試行の進行を `PdeWorkspace::last_attempt` に記録する。
  時間発展の所有値を返す API `solve` と `solve_with_options` はエラーのとき最後に受理した進行を `PartialFailure<PdeProgress>` に入れて返す。
  所有値を返す API の `solve` は定常・時間発展とも成功でない終了理由をエラーにする。
  `solve_with_options` は終了理由をレポートに残して `Ok` で返す。
- **診断**：`PdeDiagnostics` は、内側の線形反復の回数と残差、時間刻みの試行・受理・棄却・失敗の回数、右辺・ヤコビアン・組立・因子分解の回数を記録する。
  零空間を持つ問題では、`nullspace()`（拡大系の診断）と `nullspace_gauge_defect()`（要求したゲージの欠陥）を別々に読む。
  詳しくは[楕円問題の適合条件・ゲージ・保存的流束](../algorithms/compatibility-gauges-and-fluxes/)で説明する。
- **Plan だけを使う場合**：Plan は作用素と荷重を作るだけなので、終了理由は利用者が選んだ解法のレポートで確かめる。
  `check_constant_mode_compatibility` などの検査は代数的な条件であり、解の一意性や精度の証明ではない。

## まとめ

境界条件の一覧と係数から空間離散化の Plan を一度準備し、定常なら `EllipticProblem`、時間発展なら `ParabolicProblem`・`HyperbolicProblem` に渡す。
同じ Plan は一次元から三次元まで、どの求解にも同じ約束 `SpatialDiscretization` で使える。
結果は `PdeTermination` の `is_success()` で判定し、上限で止まったときは `PdeSolveReport::trust` と `PdeDiagnostics` の反復回数・残差で値の扱いを決める。
作業領域と状態は呼び出し側が所有して再利用し、エラーのときに何が残るかは求解の種類ごとに決まっている。
弾性体、非圧縮流れ、保存則、随伴、適応細分化は、残差・接線・作用素を既存の解法へ渡す形で使う。
