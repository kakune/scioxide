有理数や有限体のように演算が厳密な係数型では丸め誤差が生じないので、アルゴリズムの選択は演算の回数と係数の大きさの増え方で決まる。
このページは厳密な環での Karatsuba 法による積と合成、節点の一次式の積を二分木にまとめる部分積の木（subproduct tree）による多点評価と補間を説明する。
浮動小数点の係数の積・合成・Taylor シフトと、その Plan と作業領域は[高速な積・合成・Taylor シフト](../fast-operations-and-product-trees/)で扱う。

係数は昇べき順に並べ、$a=(a_0,\ldots,a_{m-1})$ は $a(x)=\sum_ia_ix^i$ を表す。
係数の個数が $n$ の二つの多項式の積に要する係数の乗算回数を $M(n)$ と書く。
ほかの記号は[共通の規約](oxref:poly-notation)に従う。

## 厳密環の Karatsuba と体の演算

`ExactCoefficient` は、等号と `+`・`-`・`*`・符号反転が厳密な環の係数の規約である。
`ExactField` はこれに、零でない除数に対して $(a/b)b=a$ を満たす除算を加えた体の係数の規約である。
SciOxide はどの型にもこの二つを実装しないので、浮動小数点型を厳密な演算に渡すことはできない。

積を $a=a_0+x^ka_1$、$b=b_0+x^kb_1$ と分けると

$$
ab=a_0b_0+x^k\{(a_0+a_1)(b_0+b_1)-a_0b_0-a_1b_1\}+x^{2k}a_1b_1
$$

となり、半分の長さの積が四つから三つに減る。
漸化式 $T(n)=3T(n/2)+O(n)$ から、長さがそろった積では $O(n^{\log_23})\approx O(n^{1.585})$ 回の係数演算になる（Karatsuba と Ofman, 1962）。
加減算が増えるので浮動小数点では打ち消しによる誤差が増えうるが、厳密な係数では値は変わらない。
浮動小数点の Plan `PolynomialOperationPlan` の積は Karatsuba 法を使わず、直接の和か FFT のどちらかで計算する。

厳密な係数の積 `exact_multiply_into`、合成 `exact_compose_into`、Taylor シフト `exact_taylor_shift_into` は Plan を持たない関数で、浮動小数点の FFT を使わない。
短い側の係数が 32 個未満なら筆算、32 個以上なら Karatsuba 法で掛け、長い側の係数の個数の半分（切り上げ）で分ける。
短い側がその半分以下の積では、長い側を短い側と同じ長さの区画に分けて、区画ごとに掛ける。

厳密な合成は $p$ を $m=\lfloor(\text{係数の個数})/2\rfloor$ で $p=p_{\mathrm{low}}+x^mp_{\mathrm{high}}$ と分け、$p_{\mathrm{low}}(q)+q^m\,p_{\mathrm{high}}(q)$ を再帰的に計算する。
各節の $q^m$ は二乗の繰り返しで作り、浮動小数点の Plan と違って節の間で共有しない。
Taylor シフト $p(x+s)$ は $x+s$ との合成で、階乗や除算を使わないので、$k!$ が零になる正の標数の体でも使える。
`ExactPolynomial::compose` と `ExactPolynomial::taylor_shift` は同じ計算を、呼ぶたびに確保する作業領域で行う。

`ExactPolynomialWorkspace::workspace_requirements(capacity)` は、出力の係数が `capacity` 個までの演算の要件を `ExactPolynomialWorkspaceRequirements` で返し、0 は `InvalidInput`（`Inconsistent`）になる。
その `coefficient_len()` は、出力の一時的な保持と再帰の途中の係数を合わせた個数で、`capacity` の 7 倍以下である。
`ExactPolynomialWorkspace::workspace(capacity)` はこの要件を満たす作業領域を確保し、作業領域は近似の作業領域と同じ規約の `new`・`try_reserve`・`check` も持つ。
大きい容量の作業領域は、それより短い出力の演算にもそのまま使える。
三つの関数は空の入力を `InvalidInput`、長さの合わない出力と足りない作業領域を `DimensionMismatch`、取り消しと期限切れを `ExecutionStopped` として拒否し、失敗しても出力は変わらない。

SciOxide は作業領域を渡した演算でメモリを確保しない。
ただし、係数型の複製や演算が確保するメモリと、係数のビット長の増大は SciOxide の回数の集計の外にある。
有理数の係数では、乗算の回数が少なくても係数の桁数が増え、計算時間が延びうる。

## 部分積の木と剰余の木

節点 $x_0,\ldots,x_{n-1}$ に対して、葉を一次式 $x-x_j$、内部の節を二つの子の積とする二分木を部分積の木と呼ぶ。
根は $P(x)=\prod_j(x-x_j)$ である。
多項式 $f$ を根で割った剰余を子へ渡し、その剰余を子の節で割った剰余をさらに下へ渡す木を、剰余の木（remainder tree）と呼ぶ。
$f\equiv f(x_j)\pmod{x-x_j}$ であり、$x-x_j$ を因子に持つ節で割っても法 $x-x_j$ での値は変わらないので、葉での剰余は定数 $f(x_j)$ になる。

補間では Lagrange の公式

$$
p(x)=\sum_j\frac{y_j}{P'(x_j)}\prod_{k\ne j}(x-x_k),\qquad P'(x_j)=\prod_{k\ne j}(x_j-x_k)
$$

を木で組み立てる。
重み $P'(x_j)$ は根の導関数 $P'$ を剰余の木で評価して一度に求める。
葉に $y_j/P'(x_j)$ を置き、各節で左右の子の結果 $r_{\mathrm L},r_{\mathrm R}$ と子の部分積 $P_{\mathrm L},P_{\mathrm R}$ から $r_{\mathrm L}P_{\mathrm R}+r_{\mathrm R}P_{\mathrm L}$ を作って上へ進むと、根で $p$ が得られる。
$P'(x_j)=0$ は節点の重複を意味するので、補間には相異なる節点が要る。

剰余は除数 $b$ の係数を逆順に並べた $\operatorname{rev}(b)$ の逆数を $x^q$ を法として求めれば、積だけで計算できる（$q$ は商の係数の個数）。
逆数は Newton 法 $g\leftarrow g\,(2-\operatorname{rev}(b)\,g)$ で、反復ごとに正しい係数の個数を倍にして求める。
木の節はどれもモニックなので、初期値 $g=1$ は正確である。
商は $\operatorname{rev}(f)\,g \bmod x^q$ を逆順に戻したもので、剰余は $f-(\text{商})\,b$ の低次の係数である。

積に $M(n)$ 回の乗算を使うと、木の構築は $O(M(n)\log n)$ 回の乗算になる。
剰余を Newton 法で計算すると、評価と補間も $O(M(n)\log n)$ になる（von zur Gathen と Gerhard の *Modern Computer Algebra* 第 9 章と第 10 章）。
FFT による積 $M(n)=O(n\log n)$ を使えば全体で $O(n\log^2n)$ だが、厳密な係数の積は Karatsuba 法なので、ここでの $M(n)$ は $O(n^{1.585})$ である。

古典的なモニック除算では、係数の個数 $\ell$ の多項式を次数 $d$ のモニック多項式で割る剰余に $(\ell-d)\,d$ 回の乗算を要する。
次数 $n-1$ の $f$ を根で割る段は $f$ をそのまま渡し、第 $k$ 段（$k=1,\ldots,\log_2n$）の $2^k$ 個の剰余はそれぞれ $(n/2^k)^2$ 回の乗算を要する。
合計は $\sum_k2^k(n/2^k)^2=n^2-n$ 回で、次数 $n-1$ の多項式を $n$ 点で Horner 法により評価する $n^2$ 回とほぼ同じである。
したがって、高速な積を持たない係数型では、部分積の木が実用的な大きさで Horner 法より少ない乗算で済むとは限らない。
`ExactPolynomialProductTree` は、商の係数の個数と除数の係数の個数がどちらも 32 以上で、Newton 法の積の回数を Karatsuba 法の積の回数から見積もった値が古典的な除算の回数を下回る剰余だけを Newton 法で計算する。

`ExactPolynomialProductTree::new(&points)` は節点の順序を保ったまま木を作り、節点を並べ替えない。
点数を 2 の冪に切り上げ、余った葉は定数 1 で埋めるが、その葉では演算が生じない。
`product()` は根 $P$（点がなければ 1）、`points()` は節点を返す。
`evaluate(&f)` は各節点での値を節点の順に返し、同じ節点が重なっていてもよい。
`interpolate(&values)` は、値の個数が節点数と違うときと節点が重複するときに `InvalidInput`（`Inconsistent`）を返し、節点も値もないときは零多項式を返す。
問い合わせのたびに剰余の多項式と結果のメモリを確保する。

浮動小数点の部分積の木と剰余の木は提供しない。
浮動小数点の高速な多点評価では剰余の計算で丸め誤差が増幅され、点ごとの Horner 法より精度が落ちうる。
近似値の多点評価には点ごとの `ApproxPolynomial::evaluate` か `evaluate_batch`（単項式基底では Horner 法で点あたり $O(d)$）を使い、標本値からの補間には `ApproxPolynomial::interpolate_barycentric`（重心形式）を使う。

## 厳密な体での多点評価と補間

次のセルは素数 $P=2^{31}-1$ を法とする有限体 $\mathbb F_P$ を係数型として、係数の乗算の回数を数える。
有限体の元は常に 31 ビットに収まるので、係数の桁が増えず、乗算の回数がそのまま計算量の目安になる。
次の定義のブロックは元を $0\le x<P$ の `u64` で持つ型 `F`、乗算 `*` のたびに一つ増える計数、計数を読んで 0 に戻す `take_multiplications` を定める。
除算は Fermat の小定理による逆元 $a^{P-2}$ を計数しない `u64` の演算で求めるので、補間の $y_j/P'(x_j)$ は回数に入らない。

```rust
//| id: poly-finite-field-model
//| kind: definitions
//| title: 乗算を数える有限体 F_P（P = 2³¹ − 1）
//| crates: [scioxide-poly]
use scioxide_poly::{ExactCoefficient, ExactField};
use std::ops::{Add, Div, Mul, Neg, Sub};
use std::sync::atomic::{AtomicUsize, Ordering};

/// 法とする素数 P = 2³¹ − 1。二つの元の積は 2⁶² 未満で u64 に収まる。
pub(crate) const P: u64 = 2_147_483_647;

/// 係数の乗算 `*` の回数。
static MULTIPLICATIONS: AtomicUsize = AtomicUsize::new(0);

/// 直前の呼び出しからの乗算の回数を返し、計数を 0 に戻す。
pub(crate) fn take_multiplications() -> usize {
    MULTIPLICATIONS.swap(0, Ordering::Relaxed)
}

/// F_P の元 0 ≤ x < P。
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub(crate) struct F(pub(crate) u64);

impl Add for F {
    type Output = Self;
    fn add(self, other: Self) -> Self {
        Self((self.0 + other.0) % P)
    }
}

impl Sub for F {
    type Output = Self;
    fn sub(self, other: Self) -> Self {
        Self((self.0 + P - other.0) % P)
    }
}

impl Mul for F {
    type Output = Self;
    fn mul(self, other: Self) -> Self {
        MULTIPLICATIONS.fetch_add(1, Ordering::Relaxed);
        Self(self.0 * other.0 % P)
    }
}

impl Neg for F {
    type Output = Self;
    fn neg(self) -> Self {
        Self((P - self.0) % P)
    }
}

impl Div for F {
    type Output = Self;
    fn div(self, other: Self) -> Self {
        assert_ne!(other.0, 0, "有限体の零除算");
        // Fermat の小定理により、非零元 a の逆元は a^(P−2)。数えない u64 の演算で求める。
        let (mut base, mut exponent, mut inverse) = (other.0, P - 2, 1_u64);
        while exponent > 0 {
            if exponent & 1 == 1 {
                inverse = inverse * base % P;
            }
            base = base * base % P;
            exponent >>= 1;
        }
        Self(self.0 * inverse % P)
    }
}

impl ExactCoefficient for F {
    fn zero() -> Self {
        F(0)
    }
    fn one() -> Self {
        F(1)
    }
    fn from_usize(value: usize) -> Self {
        F(value as u64 % P)
    }
}

impl ExactField for F {}
```

セルは節点数 $n=4,8,\ldots$ ごとに、擬似乱数で作った次数 $n-1$ の多項式を節点 $1,2,\ldots,n$ で評価する。
同じ値を `ExactPolynomial::evaluate`（Horner 法で、乗算を数える）と、乗算を数えない `u64` の演算による直接の代入でも求め、部分積の木の値と照合する。
最後に、木で補間した多項式が元の多項式に一致するかを調べる。
操作入力で最後の節点を一つ前の節点に重ねると、評価は成功し補間が失敗することを確かめられる。

```rust
//| id: poly-product-tree-evaluation
//| ref: poly-product-tree-evaluation
//| title: 部分積の木による多点評価と乗算の回数
//| run: reactive
//| uses: [poly-finite-field-model]
//| crates: [scioxide-poly]
//| inputs:
//|   max_points: {"type":"select","label":"最大の節点数 n [-]","options":["16","64","256","1024"],"value":"64"}
//|   nodes: {"type":"select","label":"節点","options":["相異なる 1, 2, …, n","最後の節点を一つ前の節点に重ねる"],"value":"相異なる 1, 2, …, n"}
//| cases:
//|   - {"id":"newton-1024","label":"n ≤ 1024","description":"n = 1024 で上の段の剰余に Newton 法が使われ、評価の乗算が n² − n を下回る。","inputs":{"max_points":"1024"}}
//|   - {"id":"repeated-node","label":"節点を重ねる","description":"評価は重なった節点でも成功し、補間は重み P′(xⱼ) = 0 を検出して InvalidInput を返す。","inputs":{"nodes":"最後の節点を一つ前の節点に重ねる"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"counts","path":"/rows/1/2","equals":59}
//|       - {"artifact":"counts","path":"/rows/4/3","equals":4032}
//|       - {"artifact":"counts","path":"/rows/4/6","equals":0}
//|       - {"artifact":"counts","path":"/rows/4/7","equals":"元の多項式に一致"}
//|   - case: newton-1024
//|     expect:
//|       - {"artifact":"counts","path":"/rows/7/3","equals":261632}
//|       - {"artifact":"counts","path":"/rows/8/3","equals":1023144}
//|       - {"artifact":"counts","path":"/rows/8/6","equals":0}
//|   - case: repeated-node
//|     expect:
//|       - {"artifact":"counts","path":"/rows/4/6","equals":0}
//|       - {"artifact":"counts","path":"/rows/4/7","equals":"InvalidInput"}
use scioxide_poly::{ExactPolynomial, ExactPolynomialProductTree};

let max_points: usize = max_points
    .parse()
    .map_err(|e: std::num::ParseIntError| e.to_string())?;
let repeated = nodes.starts_with("最後");
let mut state = 1_u64;
let mut rows = Vec::new();
let mut n = 4;
while n <= max_points {
    // 次数 n − 1 の係数を乗算合同法で作る。
    let coefficients: Vec<F> = (0..n)
        .map(|_| {
            state = state * 48_271 % P;
            F(state)
        })
        .collect();
    let polynomial = ExactPolynomial::new(coefficients.clone()).map_err(|e| e.to_string())?;
    // 重ねる場合は節点 n を n − 1 に置き換える。評価は重なりを許し、補間は拒否する。
    let points: Vec<F> = (1..=n as u64)
        .map(|x| F(if repeated && x == n as u64 { x - 1 } else { x }))
        .collect();
    take_multiplications();
    let horner: Vec<F> = points.iter().map(|&x| polynomial.evaluate(x)).collect();
    let horner_count = take_multiplications();
    let tree = ExactPolynomialProductTree::new(&points).map_err(|e| e.to_string())?;
    let build_count = take_multiplications();
    let values = tree.evaluate(&polynomial).map_err(|e| e.to_string())?;
    let evaluation_count = take_multiplications();
    let interpolation = match tree.interpolate(&values) {
        Ok(recovered) if recovered == polynomial => "元の多項式に一致".to_string(),
        Ok(_) => "元の多項式と不一致".to_string(),
        Err(e) => format!("{:?}", e.kind()),
    };
    let interpolation_count = take_multiplications();
    // 独立検算: 係数から u64 の Horner 法で直接代入する（計数しない）。
    let mismatches = points
        .iter()
        .zip(values.iter().zip(&horner))
        .filter(|(x, (tree_value, horner_value))| {
            let direct = coefficients
                .iter()
                .rev()
                .fold(0, |v, c| (v * x.0 + c.0) % P);
            direct != tree_value.0 || tree_value != horner_value
        })
        .count();
    rows.push((
        n,
        horner_count,
        build_count,
        evaluation_count,
        evaluation_count as f64 / horner_count as f64,
        interpolation_count,
        mismatches,
        interpolation,
    ));
    n *= 2;
}
let fixed3 = serde_json::json!({ "fractionDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "節点数 n [-]", "type": "integer" },
    { "key": "1", "label": "Horner 法の乗算 [回]", "type": "integer" },
    { "key": "2", "label": "木の構築の乗算 [回]", "type": "integer" },
    { "key": "3", "label": "木による評価の乗算 [回]", "type": "integer" },
    { "key": "4", "label": "評価の乗算の比 木/Horner [-]", "type": "number", "format": fixed3 },
    { "key": "5", "label": "補間の乗算 [回]", "type": "integer" },
    { "key": "6", "label": "値の不一致 [点]", "type": "integer" },
    { "key": "7", "label": "補間の結果" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "counts" })
);
```

乗算の回数は係数の値によらず、点数と節点の配置だけで決まる。
$n=8$ の構築の 59 回は、一次式どうし、二次式どうし、四次式どうしの筆算の積 $4\cdot2^2+2\cdot3^2+5^2$ に一致する。
Horner 法は点あたり $n$ 回で、合計 $n^2$ 回である。
木による評価はNewton 法を使わない $n\le512$ では上で導いた $n^2-n$ 回にちょうど一致し、Horner 法との比は $1-1/n$ である。
$n=1024$ では上の段の剰余で Newton 法の見積もりが古典的な除算を下回り、評価の乗算は 1023144 回（Horner 法との比 0.976）に減る。
木の構築は Karatsuba 法により、$n=1024$ で 189312 回と $n^2$ の約 18% で済む。
補間は導関数の評価と組み立ての積を含み、$n=1024$ で 1401896 回で、評価だけの約 1.4 倍である。
節点を重ねると評価はそのまま成功し、補間は重み $P'(x_j)=0$ を検出して `InvalidInput` を返す。
このセルは有限体で演算の回数と恒等式を確かめる例であり、実数の丸め誤差や近い節点の条件数は調べない。

## まとめ

厳密な係数の積・合成・Taylor シフトは、短い側が 32 係数以上で Karatsuba 法（$O(n^{1.585})$ 回の環の演算）になり、`ExactPolynomialWorkspace` を渡せば SciOxide はメモリを確保しない。
係数のビット長の増大と係数型の確保は回数の集計の外にあるので、有理数の係数では演算の回数とは別に係数の桁数を見積もる。
`ExactPolynomialProductTree` の評価は、Newton 法が働かない大きさでは古典的な除算で $n^2-n$ 回の乗算になり、Horner 法の $n^2$ 回とほとんど変わらない。
部分積の木を選ぶかどうかは、表のように点数と次数から乗算の回数を数えて判断する。
補間は相異なる節点を要し、重なった節点は `InvalidInput` として検出される。
