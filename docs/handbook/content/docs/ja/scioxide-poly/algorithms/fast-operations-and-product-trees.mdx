多項式の係数に対する演算には、積、合成 $p(q(x))$、Taylor シフト $p(x+s)$、除算がある。
浮動小数点の係数では、同じ積でも直接の和と FFT とで丸め誤差の性質が異なり、合成と Taylor シフトでは係数の打ち消しが結果の精度を決める。
同じ形の演算を何度も行うときは、変換表と作業領域を一度だけ準備すれば、実行のたびにメモリを確保せずに済む。
このページはこれらのアルゴリズムの計算量と丸め誤差を導き、`scioxide-poly` がどの条件でどのアルゴリズムを選ぶかを説明する。
厳密な係数の Karatsuba 法と、部分積の木による多点評価と補間は[厳密な係数の演算と部分積の木](../exact-arithmetic-and-product-trees/)で扱う。

係数は昇べき順に並べ、$a=(a_0,\ldots,a_{m-1})$ は $a(x)=\sum_ia_ix^i$ を表す。
係数の個数が $n$ の二つの多項式の積に要する係数の乗算回数を $M(n)$ と書く。
$u$ は単位丸め、$\varepsilon=2u$ は機械イプシロン（`EPSILON`）で、ほかの記号は[共通の規約](oxref:poly-notation)に従う。

## 直接畳込みと FFT

係数の個数が $m$ と $n$ の多項式の積 $c=ab$ は、係数の畳込み

$$
c_k=\sum_{i+j=k}a_ib_j,\qquad k=0,\ldots,m+n-2
$$

で、係数は $m+n-1$ 個ある。
この和を直接計算する筆算（schoolbook）は $mn$ 回の乗算を要する。

離散 Fourier 変換は巡回畳込みを成分ごとの積に変える。
両方の係数列を長さ $N\ge m+n-1$ まで零で埋めてから変換すると、巡回畳込みが求めたい線形畳込みに一致し、計算量は $O(N\log N)$ になる。
ゼロパディングが足りないと高次の係数が低次へ折り返し、別の多項式の積になる。
`scioxide-poly` は $N$ を $m+n-1$ 以上の最小の 2 の冪に取り、実数の係数には実数用の変換、複素数の係数には複素変換を使う。

二つの方法は丸め誤差の性質が異なる。
直接の和では、各係数について

$$
|\hat c_k-c_k|\le\gamma_L\,(|a|*|b|)_k,\qquad \gamma_L=\frac{Lu}{1-Lu}
$$

が成り立つ（$L\le\min(m,n)$ は和の項数、$|a|*|b|$ は絶対値の係数の畳込み。
内積の誤差の上界で、Higham, *Accuracy and Stability of Numerical Algorithms*, 2nd ed., §3.1）。
SciOxide は和を四つの部分和に分けて足すが、加算の順序を変えても同じ上界が成り立つ。
誤差が係数ごとの和 $(|a|*|b|)_k$ に比例するので、小さい係数も相対的に正確に求まる。
FFT の誤差は変換全体のノルムで決まり、各係数の絶対誤差はおよそ $u\,\|a\|_2\|b\|_2$ に $\log_2N$ 程度の因子を掛けた大きさになる（同書 §24.1）。
そのため、ほかの係数より何桁も小さい係数は、同じ大きさの絶対誤差を受けて相対精度を失う。

`PolynomialOperationPlan` は、次の二つの条件をともに満たす積だけを FFT で計算し、それ以外は直接の和で計算する。

- 短い側の係数の個数が実数の係数で 32 以上、複素数の係数で 16 以上である。
- 各因子の零でない係数（複素数では零でない実部と虚部）の絶対値が、その因子の最大の絶対値の $\sqrt\varepsilon$ 倍以上である。

最初の条件は実装上の切替点で、数学的な閾値でも速度の保証でもない。
二つ目の条件は係数の値で決まるので、同じ形の積でも呼び出しごとに経路が変わりうる。
すべての係数が零の因子は二つ目の条件を満たさないので、直接の和になる。
FFT の前に各因子を 2 の冪で縮尺して結果を戻すので、表現範囲の内側では縮尺そのものは丸めを生じない。
直接の和は通常の浮動小数点演算で計算し、途中で表現範囲を外れた係数だけを拡張した指数の範囲で計算し直す。
実際に使った経路は `PolynomialProductAlgorithm` の `Schoolbook` または `Fft` として返る。

`polynomial_product_condition` は、計算済みの積から $\kappa=\max(1,\|a\|_1\|b\|_1/\|ab\|_1)$ を求めて打ち消しの程度を示す。
$\||a|*|b|\|_1=\|a\|_1\|b\|_1$ なので、$\kappa$ は直接の和の誤差上界と結果の大きさの比を 1 ノルムで測った値でもある。
レポートの後退誤差は上の $\gamma_L$ の $u$ を機械イプシロン $\varepsilon$ に、$L$ を積の係数の個数に置き換えた $\gamma_{m+n-1}=(m+n-1)\varepsilon/(1-(m+n-1)\varepsilon)$ で、前進誤差の推定はこれに $\kappa$ を掛けた値である。
すべての係数が打ち消し合って積が零になると、$\kappa$ は正の無限大になる（因子のどちらかが零なら積も零で、$\kappa=1$）。
因子が空なら `InvalidInput`（`Empty`）、積の長さが $m+n-1$ でなければ `InvalidInput`（`Inconsistent`）、非有限の係数は `NonFinite` になる。
計算量は係数の個数に比例し、メモリは確保しない。
どちらの推定も一次の丸めのモデルによる目安で、計算した積の前進誤差の上界ではない。

## 入力形状と領域

`PolynomialOperationRequest` は演算ごとの正確な入力長を宣言する。

- `Multiply { left_len, right_len }` は積で、左右を入れ替えた形も同じ形として扱う。
- `Compose { outer_len, inner_len }` は合成 $p(q(x))$ である。
- `TaylorShift { len }` は Taylor シフトである。
- `Divide { dividend_len, divisor_len }` は除算 `div_rem_into` で、商と剰余の規約は[長除法の後退誤差](oxref:poly-division-reconstruction-residual)にある。

長さはどれも正でなければならず、0 は準備のときに `InvalidInput`（`Empty`）になる。
大きい形を宣言しても小さい形は準備されないので、使う形はすべて宣言する。
`PolynomialOperationPlan::new(&requests)` は重複した形をまとめ、宣言した形から到達する長さの FFT 表だけを作る。
`build(&requests, options, context)` は、実行方針とワーカー数の上限を持つ `PolynomialExecutionOptions` を保持して準備する。
既定は逐次実行で上限は 64 であり、64 を超える上限は準備で `InvalidInput` になる。
準備に渡した `ExecutionContext` は保持されず、実行のたびに `ExecutionContext` を最後の引数として渡す。

`workspace_requirements(&requests)` は、宣言した形の部分集合に必要なメモリを `PolynomialWorkspaceRequirements` で返す。
係数 `coefficient_len()`、FFT の複素数 `fft_len()`、実数の標本 `real_len()`、拡張した指数の範囲の値 `scaled_len()` を数え、`required_bytes()` が合計のバイト数を返す。
`scaled_len()` は、除算では被除数と除数の長さの和、合成と Taylor シフトでは[後述の計算し直し](#合成と-taylor-シフト)に使う出力の 2 倍の長さ、積では 0 である。
演算は一つずつ実行されるので、複数の形の要件は和ではなく種類ごとの最大になる。
未宣言の形を問い合わせると `InvalidInput`（`Inconsistent`）になる。

作業領域 `PolynomialWorkspace` は呼び出し側が所有する。
`PolynomialWorkspace::new()` は何も確保せず、`try_reserve(&requirements)` が足りない分だけを伸ばし、`check(&requirements)` は確保せずに `Sufficient` か `NeedsGrowth` を返す。
事前確保は縮まないので、最も大きい Plan に合わせた作業領域は小さい Plan にもそのまま使える。
`plan.workspace(&requests)` は新しい作業領域を作って事前確保する。

実行の `multiply_into`、`compose_into`、`taylor_shift_into`、`div_rem_into` は作業領域を伸ばさない。
作業領域が足りないときと出力の長さが合わないときは `DimensionMismatch`、宣言していない形は `InvalidInput`（`Inconsistent`）、非有限の係数は `NonFinite`、結果の係数の桁あふれは `NumericalInstability`、取り消しと期限切れは `ExecutionStopped` になる。
結果は作業領域の中で作り、すべての検査が通ってから出力へ写すので、失敗しても出力は変わらない。
作業領域の中身は成功と失敗のどちらでも書き換わりうる。

## 積の経路と誤差の検算

次のセルは係数の個数 $n=16,31,32,64$ の二つの因子を一つの `PolynomialOperationPlan` で掛け、使った経路と係数ごとの誤差を表にする。
四つの形を一つの Plan に宣言し、要件の最大で事前確保した一つの作業領域を使い回す。
係数は $-8$ から $8$ の零でない整数で、整数の直接の畳込みを `i64` で計算すれば厳密な積が得られる。
操作入力で $a_0$ を $2^{-k}$ に置き換えると、$c_0=2^{-k}b_0$ は小さい積だけからなる係数になる。
$2^{-k}$ と整数の積は `f64` で厳密に表せるので、置き換えたあとも厳密な積を独立に計算できる。
表の係数ごとの相対誤差は $|\hat c_k-c_k|/(|a|*|b|)_k$ の最大で、直接の和の誤差上界 $\gamma_L$ と比べる量である。

```rust
//| id: poly-prepared-product-tree
//| ref: poly-prepared-product-tree
//| title: 積の経路の選択と係数ごとの誤差
//| run: reactive
//| crates: [scioxide-core, scioxide-poly]
//| inputs:
//|   tiny_exponent: {"type":"select","label":"a₀ = 2⁻ᵏ の指数 k","options":["置き換えない","20","30"],"value":"置き換えない"}
//| cases:
//|   - {"id":"tiny-20","label":"a₀ = 2⁻²⁰","description":"最大の係数との比 2⁻²³ は √ε 以上なので FFT のままで、c₀ の相対誤差が大きくなる。","inputs":{"tiny_exponent":"20"}}
//|   - {"id":"tiny-30","label":"a₀ = 2⁻³⁰","description":"比 2⁻³³ が √ε を下回るので、n ≥ 32 でも直接の和に戻る。","inputs":{"tiny_exponent":"30"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"paths","path":"/rows/1/1","equals":"Schoolbook"}
//|       - {"artifact":"paths","path":"/rows/2/1","equals":"Fft"}
//|       - {"artifact":"paths","path":"/rows/1/2","range":{"max":1e-16}}
//|       - {"artifact":"paths","path":"/rows/3/2","range":{"max":1e-13}}
//|       - {"artifact":"paths","path":"/rows/3/4","range":{"min":1,"max":2}}
//|   - case: tiny-20
//|     expect:
//|       - {"artifact":"paths","path":"/rows/2/1","equals":"Fft"}
//|       - {"artifact":"paths","path":"/rows/2/3","range":{"min":1e-10,"max":1e-6}}
//|   - case: tiny-30
//|     expect:
//|       - {"artifact":"paths","path":"/rows/3/1","equals":"Schoolbook"}
//|       - {"artifact":"paths","path":"/rows/3/3","range":{"max":1e-16}}
use scioxide_core::ExecutionContext;
use scioxide_poly::{
    PolynomialOperationPlan, PolynomialOperationRequest, PolynomialProductAlgorithm,
    PolynomialWorkspaceRequirements, polynomial_product_condition,
};

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let fixed3 = serde_json::json!({ "fractionDigits": 3 });

// FFT の切替（短い側 32）の前後の長さを一つの Plan で準備する。
let lengths = [16_usize, 31, 32, 64];
let requests = lengths.map(|n| PolynomialOperationRequest::Multiply {
    left_len: n,
    right_len: n,
});
let plan = PolynomialOperationPlan::<f64>::new(&requests).map_err(|e| e.to_string())?;
let requirements: PolynomialWorkspaceRequirements<f64> = plan
    .workspace_requirements(plan.requests())
    .map_err(|e| e.to_string())?;
// 一つの作業領域が四つの形の要件の最大を満たす。
let mut workspace = plan.workspace(plan.requests()).map_err(|e| e.to_string())?;
let tiny = match tiny_exponent.as_str() {
    "置き換えない" => None,
    k => Some(1.0 / (1_u64 << k.parse::<u32>().map_err(|e| e.to_string())?) as f64),
};
// -8..=8 の零でない整数係数を決定論的に作る。
let integer = |i: usize, salt: usize| {
    let value = ((i * 37 + salt * 11 + 5) % 16) as i64 - 8;
    if value == 0 { 1 } else { value }
};
let mut rows = Vec::new();
for n in lengths {
    let mut a_int: Vec<i64> = (0..n).map(|i| integer(i, 1)).collect();
    let b_int: Vec<i64> = (0..n).map(|i| integer(i, 2)).collect();
    let mut a: Vec<f64> = a_int.iter().map(|&v| v as f64).collect();
    let b: Vec<f64> = b_int.iter().map(|&v| v as f64).collect();
    if let Some(t) = tiny {
        // a₀ を 2⁻ᵏ に置き換え、整数部分の畳込みからは除く。
        a[0] = t;
        a_int[0] = 0;
    }
    let mut product = vec![0.0; 2 * n - 1];
    let algorithm: PolynomialProductAlgorithm = plan
        .multiply_into(
            &a,
            &b,
            &mut product,
            &mut workspace,
            ExecutionContext::sequential(),
        )
        .map_err(|e| e.to_string())?;
    // 独立検算: 整数部分は i64 の直接の畳込み、a₀ = 2⁻ᵏ の寄与は 2⁻ᵏ b_k（どちらも f64 で厳密）。
    let (mut worst, mut first) = (0.0_f64, 0.0_f64);
    for k in 0..2 * n - 1 {
        let (mut exact, mut magnitude) = (0_i64, 0_i64);
        for i in k.saturating_sub(n - 1)..=k.min(n - 1) {
            exact += a_int[i] * b_int[k - i];
            magnitude += (a_int[i] * b_int[k - i]).abs();
        }
        let small = tiny.map_or(0.0, |t| if k < n { t * b[k] } else { 0.0 });
        let error =
            (product[k] - (exact as f64 + small)).abs() / (magnitude as f64 + small.abs());
        worst = worst.max(error);
        if k == 0 {
            first = error;
        }
    }
    let report = polynomial_product_condition(&a, &b, &product).map_err(|e| e.to_string())?;
    rows.push((
        n,
        format!("{algorithm:?}"),
        worst,
        first,
        report.condition_estimate(),
    ));
}
let columns = serde_json::json!([
    { "key": "0", "label": "係数の個数 n [-]", "type": "integer" },
    { "key": "1", "label": "使った経路" },
    { "key": "2", "label": "係数ごとの最大相対誤差 [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "c₀ の相対誤差 [-]", "type": "number", "format": sci3 },
    { "key": "4", "label": "条件数の推定 κ [-]", "type": "number", "format": fixed3 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "paths" })
);
emit_text!(&format!(
    "作業領域の要件: 係数 {} 個、FFT の複素数 {} 個、実数 {} 個。",
    requirements.coefficient_len(),
    requirements.fft_len(),
    requirements.real_len()
));
```

既定の入力では、$n=16,31$ は直接の和で誤差が 0、$n=32,64$ は FFT で係数ごとの最大相対誤差が $1.4\times10^{-14}$ と $4.7\times10^{-15}$ になる。
直接の和の誤差が 0 なのは、整数の積と和がどれも `f64` で厳密に表せるからで、一般の係数では $\gamma_L$ 程度の誤差が残る。
$k=20$ では、最大の係数 8 との比 $2^{-23}$ が $\sqrt\varepsilon=2^{-26}$ 以上なので FFT が使われ、$c_0$ の相対誤差は $2.5\times10^{-9}$（$n=32$）と $1.5\times10^{-8}$（$n=64$）に増える。
$k=30$ では比が $2^{-33}$ で $\sqrt\varepsilon$ を下回るので、$n\ge32$ でも直接の和に戻り、誤差は再び 0 になる。
条件数の推定 $\kappa$ はどの場合も 2 未満で、打ち消しは小さい。
$k=20$ で誤差が増えたのは打ち消しのためではなく、ノルムで決まる FFT の誤差が小さい係数 $c_0$ に比べて大きいためである。
作業領域の要件は係数が最大の形の $2\cdot64-1=127$ 個と、長さ 128 の変換の分（複素数 259 個、実数 128 個）で、四つの形の和ではない。

## 合成と Taylor シフト

$p$ の次数を $d$、$q$ の次数を $e$ とすると、合成 $p(q(x))$ の次数は高々 $de$ で、出力は最高次の零を含めて $de+1$ 個の係数を持つ。
多項式の Horner 法 $p(q)=(\cdots(p_dq+p_{d-1})q+\cdots)q+p_0$ をそのまま使うと、長くなっていく多項式と $q$ の積を $d$ 回繰り返すので、乗算は $O(d^2e^2)$ 回になる。

分割統治では $p=p_{\mathrm{low}}+x^mp_{\mathrm{high}}$ と分け、

$$
p(q)=p_{\mathrm{low}}(q)+q^m\,p_{\mathrm{high}}(q)
$$

を再帰的に計算する。
近似の Plan は $m$ を $p$ の係数の個数より小さい最大の 2 の冪に取り、$q^2,q^4,q^8,\ldots$ を一度だけ作って再帰の全体で共有する。
高速な積を使えば、計算量は $O(M(de)\log d)$ になる。
`compose_into` は $q$ の冪と再帰の各節の積で、[上の積の経路](#直接畳込みと-fft)（直接の和か FFT）を選ぶ。

途中の積の係数が、積の台（0 でない係数が現れうる次数の範囲）の内側で 0、非正規化数、または表現範囲の外になると、`compose_into` は合成全体を計算し直す。
0 になった係数が構造上の 0 なのか、丸めで消えた項なのかを区別できず、後の積で消えた項が増幅されるおそれがあるからである。
$q=x^2+1$ のように $q^2$ の台の内側に 0 の係数が現れる内側の多項式では、常にこの計算し直しになる。
計算し直しでは、拡張した指数の範囲で係数の Horner 法 $c\leftarrow c\,q+p_i$ を実行し、最後の係数だけを一度丸める。
この経路は時間 $O(d\,N\,(e+1))$（$N=de+1$ は出力の係数の個数）と、出力の 2 倍の拡張指数の値を要する。
そのメモリは Plan の要件 `scaled_len()` に含まれるので、作業領域を伸ばす必要はない。
どちらの経路を通ったかは返り値に現れない。

Taylor シフト $p(x+s)$ は $q(x)=s+x$ との合成である。
教科書の式 $p(x+s)=\sum_kp^{(k)}(s)x^k/k!$ は、高次では階乗が桁あふれし（`f64` では $171!$ が範囲を超える）、導関数の和で打ち消しが起きる。
`taylor_shift_into` は階乗を使わずに合成として計算する。
Taylor シフトは基底の変換ではなく、同じ単項式基底のまま変数を平行移動する操作である。

`polynomial_composition_condition` は、絶対値の係数の Horner 法を $\|q\|_1$ で評価した $\sum_i|p_i|\,\|q\|_1^i$ と合成結果の 1 ノルムの比を $\kappa$（1 未満なら 1）として返す。
$\|q^i\|_1\le\|q\|_1^i$ なので、$\|q\|_1^i$ の和は打ち消しがない場合の結果の 1 ノルムの上界であり、比は打ち消しによる縮みの目安になる。
$p$ の係数に相対 $u$ 以内の摂動を加えると、結果の係数の変化は 1 ノルムで $u\sum_i|p_i|\,\|q\|_1^i$ 以下なので、$u\kappa$ は結果の相対変化の上界でもある。
Taylor シフトでは $\|q\|_1=1+|s|$ なので、目安は $\sum_i|p_i|(1+|s|)^i/\|p(x+s)\|_1$ で、$|s|$ とともに大きくなる。
前進誤差の推定は $\gamma_N\kappa$（$N$ は合成結果の係数の個数）である。
この比も一次の目安であり、誤差の保証ではない。
計算量は係数の個数に比例し、メモリは確保しない。

次のセルは $(x-3)^n/3$ と $(x+3)^n/3$ を $s=3$ で Taylor シフトし、結果の係数の誤差を $\kappa$ と比べる（$n=4,8,\ldots,24$）。
係数 $\binom{n}{i}(\mp3)^{n-i}/3$ を `f64` に丸めたものを入力とし、丸めた入力そのもののシフトを正解とする。
前者のシフトは $x^n/3$ に近く、大きさ $\binom{n}{i}3^{n-i}4^i/3$ 程度の項が打ち消し合って小さな結果になるので、$\kappa\approx\sum_i\binom{n}{i}3^{n-i}4^i=7^n$ である。
後者のシフトは $(x+6)^n/3$ に近く、打ち消しがないので $\kappa=1$ である。
独立検算では、入力の係数がどれも $1/3$ 以上で $2^{54}$ 倍すると整数になることを使う。
シフト後の係数 $c_k=\sum_{i\ge k}p_i\binom{i}{k}3^{i-k}$ を $2^{54}$ 倍した整数として `i128` で厳密に求め、最後に一度だけ `f64` に丸める。
表の観測誤差は $\|\hat c-c\|_1/\|c\|_1$ で、正解を一度丸めているので、$u$ 程度の差は検算の分解能の内側にある。
一つの Plan に六つの次数の形を宣言し、一つの作業領域で順に計算する。

```rust
//| id: poly-taylor-shift-condition
//| ref: poly-taylor-shift-condition
//| title: Taylor シフトの打ち消しと条件数の推定
//| run: reactive
//| crates: [scioxide-core, scioxide-poly]
//| inputs:
//|   polynomial: {"type":"select","label":"シフトする多項式（s = 3）","options":["(x − 3)ⁿ/3（結果 ≈ xⁿ/3）","(x + 3)ⁿ/3（結果 ≈ (x + 6)ⁿ/3）"],"value":"(x − 3)ⁿ/3（結果 ≈ xⁿ/3）"}
//| cases:
//|   - {"id":"no-cancellation","label":"(x + 3)ⁿ/3","description":"打ち消しがないので κ = 1 で、誤差は単位丸めの水準にとどまる。","inputs":{"polynomial":"(x + 3)ⁿ/3（結果 ≈ (x + 6)ⁿ/3）"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"shift","path":"/rows/0/1","approx":{"value":2401,"rtol":1e-6}}
//|       - {"artifact":"shift","path":"/rows/0/3","range":{"max":1e-13}}
//|       - {"artifact":"shift","path":"/rows/5/3","range":{"min":1e-12}}
//|   - case: no-cancellation
//|     expect:
//|       - {"artifact":"shift","path":"/rows/5/1","approx":{"value":1,"rtol":1e-12}}
//|       - {"artifact":"shift","path":"/rows/5/3","range":{"max":1e-15}}
use scioxide_core::ExecutionContext;
use scioxide_poly::{
    PolynomialOperationPlan, PolynomialOperationRequest, polynomial_composition_condition,
};

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let sign: i128 = if polynomial.starts_with("(x − 3)") {
    -1
} else {
    1
};
let degrees = [4_usize, 8, 12, 16, 20, 24];
let requests = degrees.map(|n| PolynomialOperationRequest::TaylorShift { len: n + 1 });
let plan = PolynomialOperationPlan::<f64>::new(&requests).map_err(|e| e.to_string())?;
let mut workspace = plan.workspace(plan.requests()).map_err(|e| e.to_string())?;
// Pascal の三角形 C(i, k)（i ≤ 24）を整数で作る。
let mut binomial: Vec<Vec<i128>> = vec![vec![1]];
for i in 1..=24 {
    let previous = &binomial[i - 1];
    let row = (0..=i)
        .map(|k| {
            if k == 0 || k == i {
                1
            } else {
                previous[k - 1] + previous[k]
            }
        })
        .collect();
    binomial.push(row);
}
// 2⁵⁴ 倍すると、絶対値が 1/4 以上の f64 はすべて整数になる。
let frame = (1_i128 << 54) as f64;
let mut rows = Vec::new();
for n in degrees {
    // xⁱ の係数 C(n, i)(∓3)ⁿ⁻ⁱ/3 を f64 に丸めたものを入力とする（どれも 1/3 以上）。
    let p: Vec<f64> = (0..=n)
        .map(|i| (binomial[n][i] * (3 * sign).pow((n - i) as u32)) as f64 / 3.0)
        .collect();
    let mut shifted = vec![0.0; n + 1];
    let context = ExecutionContext::sequential();
    plan.taylor_shift_into(&p, 3.0, &mut shifted, &mut workspace, context)
        .map_err(|e| e.to_string())?;
    let report = polynomial_composition_condition(&p, &[3.0, 1.0], &shifted)
        .map_err(|e| e.to_string())?;
    // 独立検算: 丸めた入力 pᵢ のシフト cₖ = Σᵢ pᵢ C(i, k) 3ⁱ⁻ᵏ を、
    // 2⁵⁴ 倍した整数として i128 で厳密に求め、最後に一度だけ f64 に丸める。
    let scaled: Vec<i128> = p.iter().map(|&c| (c * frame) as i128).collect();
    let exact: Vec<f64> = (0..=n)
        .map(|k| {
            let sum: i128 = (k..=n)
                .map(|i| scaled[i] * binomial[i][k] * 3_i128.pow((i - k) as u32))
                .sum();
            sum as f64 / frame
        })
        .collect();
    let error: f64 = shifted.iter().zip(&exact).map(|(c, e)| (c - e).abs()).sum();
    let norm: f64 = exact.iter().map(|e| e.abs()).sum();
    rows.push((
        n,
        report.condition_estimate(),
        report.forward_error_estimate(),
        error / norm,
    ));
}
let columns = serde_json::json!([
    { "key": "0", "label": "次数 n [-]", "type": "integer" },
    { "key": "1", "label": "条件数の推定 κ [-]", "type": "number", "format": sci3 },
    { "key": "2", "label": "前進誤差の推定 γκ [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "観測した相対誤差 [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "shift" })
);
```

既定の $(x-3)^n/3$ では $\kappa$ が $7^n$ に一致し（$n=4$ で 2401、$n=24$ で $1.9\times10^{20}$）、前進誤差の推定 $\gamma_{n+1}\kappa$ は $n=16$ で $0.13$、$n=24$ で $1.1\times10^{6}$ になる。
観測した相対誤差も $n$ とともに増え、$n=16$ で $2.4\times10^{-7}$、$n=24$ で $1.5\times10^{-2}$ になる。
観測値はどの $n$ でもおよそ $u\,4^n/2$ で、推定より何桁も小さい。
$u\kappa$ は入力の係数の摂動に対する最悪の場合の増幅であり、実際の丸め誤差がその最悪の向きにそろうとは限らないからである。
それでも $n=24$ では、結果の係数に有効数字が 2 桁ほどしか残らない。
$(x+3)^n/3$ では $\kappa=1$ で、観測誤差は $n\le20$ で 0、$n=24$ で $4\times10^{-18}$ にとどまる。
$\kappa u$ が 1 に近い場合は、シフトした係数を作らずに $p(x+s)$ を直接評価するか、はじめから $x-s$ の冪で表した係数を使う。

## まとめ

`PolynomialOperationPlan` は、短い側の係数が実数で 32 個以上（複素数で 16 個以上）あり、各因子で零でない係数がどれも最大の係数の $\sqrt\varepsilon$ 倍以上である積だけを FFT で計算し、使った経路を `PolynomialProductAlgorithm` で返す。
係数ごとの相対精度が要る積で小さい係数を含むときは直接の和に戻るので、経路と `polynomial_product_condition` の推定を合わせて読む。
合成と Taylor シフトの係数は `polynomial_composition_condition` の $\kappa$ で打ち消しを見積もり、$\kappa u$ が 1 に近ければ結果の係数を信用しない。
繰り返す演算は `PolynomialOperationRequest` で使う形をすべて宣言し、最大の要件で事前確保した `PolynomialWorkspace` を使い回せば、実行でメモリを確保しない（合成の拡張指数による計算し直しもこの要件に含まれる）。
