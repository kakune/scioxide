直交多項式一つの値と、その族による有限展開の値は異なる計算である。
展開 $p(x)=\sum_{k=0}^n\gamma_k\phi_k(x)$ を扱うには、係数 $\gamma_k$ だけでなく、族、規格化、座標の対応を一緒に保つ必要がある。
`scioxide-poly` では `OrthogonalBasisSpec` がこの三つを指定し、`prepare` で作る `OrthogonalBasisPlan` が漸化式を準備し、`ApproxPolynomial` の中の `OrthogonalBasis` が係数と Plan を所有する。
評価と直交基底どうしの変換は準備した漸化式を使い、単項式の係数を経由しない。
このページでは基底の指定と準備、Clenshaw 法による評価とその丸め誤差、基底変換の作用素を説明し、最後のセルで Chebyshev 基底を単項式に直したときの係数の増大を確かめる。
族ごとの区間・重み・漸化式は[直交多項式族](../orthogonal-families/)、同じ基底での微分と原始関数は[直交展開の微分と積分](../orthogonal-calculus/)で扱う。

## 物理座標と規格化

`OrthogonalBasisSpec::new(family, normalization, shift, scale)` は、物理座標 $x$ と族の基準座標 $t$ を

$$
t=\frac{x-\mathrm{shift}}{\mathrm{scale}},\qquad \mathrm{scale}>0
$$

で結ぶ。
有限区間 $[x_{\rm a},x_{\rm b}]$ を $[-1,1]$ に移すなら `shift` $=(x_{\rm a}+x_{\rm b})/2$、`scale` $=(x_{\rm b}-x_{\rm a})/2$ である。
最後の二つの引数を区間の両端と取り違えない。
`new` は族のパラメータも検査し、範囲外のパラメータや $\mathrm{scale}\le0$ を `DomainError`、有限でない値を `NonFinite` として返す。

区間の両端から作るときは `OrthogonalBasisSpec::on_interval(family, lower, upper)` を使う。
この関数は `shift` と `scale` を途中で桁あふれしない形で 1 回ずつ丸めて求め、`Classical` の仕様を作る。
両端が有限でなければ `NonFinite`、$\mathrm{lower}\ge\mathrm{upper}$ か半幅が零に丸まる場合は `InvalidInput`（`OutOfRange`）、台が $[-1,1]$ でない Laguerre・Hermite の族は `InvalidInput`（`Inconsistent`）になる。
`OrthogonalBasisSpec::classical(family)` は `shift` $=0$、`scale` $=1$ の古典的な仕様で、`with_normalization(normalization)` は規格化だけを替えた仕様を返す。
半無限・無限区間の族にも `new` で同じ変換を適用でき、たとえば `Laguerre` の台は $x\ge\mathrm{shift}$、`HermiteH` の重みは $e^{-((x-\mathrm{shift})/\mathrm{scale})^2}$ になる。
指定した値は `family()`、`normalization()`、`shift()`、`scale()` で読める。

`BasisNormalization` は基底の各要素の定数倍を選ぶ。
基準座標の古典族を $P_k(t)$、その最高次係数を $\ell_k$、二乗ノルムを $h_k=\int P_k(t)^2w(t)\,dt$、尺度を $s=\mathrm{scale}$ とすると、三つの規格化は次の基底を表す。

| 列挙子 | 基底 $\phi_k(x)$ | 性質 |
|---|---|---|
| `Classical` | $P_k(t)$ | 族の慣用の規格化（$T_k(1)=1$ など） |
| `Monic` | $s^kP_k(t)/\ell_k$ | 物理座標 $x$ で最高次係数が 1 |
| `Orthonormal` | $P_k(t)/\sqrt{s\,h_k}$ | $\int\phi_j\phi_k\,w(t)\,dx=\delta_{jk}$ |

`Orthonormal` は物理座標の測度 $w((x-\mathrm{shift})/\mathrm{scale})\,dx$ で二乗ノルムを 1 にし、$dx=s\,dt$ の因子 $s$ をノルムに含める。
各要素の符号は古典族と同じに保つので、Laguerre の奇数次のように最高次係数が負の要素もある。
モニック形は[Jacobi 行列と零点](oxref:poly-jacobi-matrix-reduction)の対称三重対角化で使う $d_k,e_k$ を使って

$$
\phi_{k+1}(x)=\bigl(x-\mathrm{shift}-s\,d_k\bigr)\phi_k(x)-s^2e_k^2\,\phi_{k-1}(x)
$$

を満たす。
準備ではこのように各規格化の漸化式を物理座標に直して保存する。
規格化を変えると、同じ関数を表す係数は基底の定数倍の逆数だけ変わり、係数のノルムや係数への摂動のモデルも変わる。

## 準備した展開の評価

`spec.prepare(degree, options)` は次数 `degree` までの漸化式の係数 `degree + 1` 組を確保して `OrthogonalBasisPlan` を返す。
準備は $O(n)$ の時間とメモリで、`Orthonormal` では最初の要素 $\phi_0=1/\sqrt{\mu_0s}$（$\mu_0=\int w(t)\,dt$）もここで決める。
係数や $\phi_0$ が表現できない場合や零に丸まる場合は `NumericalInstability`、`options` が 64 を超えるワーカーを許す場合は `InvalidInput` になる。
Plan は変更できず、`degree()`、`spec()`、`options()` で準備の内容を読める。

`ApproxPolynomial::orthogonal(coefficients, spec)` は、係数の個数から次数を決めて既定の実行設定で Plan を準備し、既定の方針で多項式を作る。
Plan の次数・実行設定や方針を選ぶときは `ApproxPolynomial::orthogonal_with_plan(coefficients, plan, policy)` を使う。
どちらの多項式も昇べき順の係数と Plan を所有する。
係数は空でなく有限で、`orthogonal_with_plan` では個数が Plan の `degree() + 1` 以下でなければならない。
空の係数は `InvalidInput`（`Empty`）、多すぎる係数は `InvalidInput`（`Inconsistent`）、有限でない係数は `NonFinite` になる。
短い展開を入れても、Plan の最大次数と実行の設定はそのまま保持される。
中の基底 `OrthogonalBasis` は `basis().plan()` で Plan を借用でき、係数は `PolynomialBasis::coefficients` で読める。
末尾の零も構造上の係数として残り、隠れた可変のキャッシュは持たない。

### Clenshaw 法

展開の値は Clenshaw 法で計算する。
基底が $\phi_{k+1}=(a_kx+b_k)\phi_k-c_k\phi_{k-1}$（$\phi_{-1}=0$）を満たすとき、$B_{n+1}=B_{n+2}=0$ から

$$
B_k=\gamma_k+(a_kx+b_k)B_{k+1}-c_{k+1}B_{k+2}\quad(k=n,\dots,0),\qquad p(x)=\phi_0B_0
$$

と逆向きに更新する。
この式は$\gamma_k=B_k-(a_kx+b_k)B_{k+1}+c_{k+1}B_{k+2}$ を $\sum_k\gamma_k\phi_k$ に代入し、$B_{k+1}$ の係数を $\phi_{k+1}-(a_kx+b_k)\phi_k+c_k\phi_{k-1}=0$ でまとめると、$\phi_0B_0$ だけが残ることから導ける。
基底の値 $\phi_k(x)$ を一つも作らないので、一点の評価は $O(n)$ の時間と一定の追加メモリで済む。
Chebyshev 第 1 種を基準座標 $t$ で書くと（$a_0=1$、$a_k=2$、$b_k=0$、$c_k=1$）、$p=\gamma_0+tB_1-B_2$ となる。
$\gamma_0$ に $1/2$ を掛ける流儀もあるが、SciOxide は全係数をそのまま掛ける。

丸め誤差は後退誤差として読める。
$B_k$ を計算するときに入る誤差 $\delta_k$ は、その後の更新が $B_k$ について線形なので、係数を $\gamma_k+\delta_k$ に替えた厳密な計算と同じ結果を与える。
したがって計算値は係数を $|\delta_k|\lesssim cu\bigl(|\gamma_k|+|a_kx+b_k||B_{k+1}|+|c_{k+1}||B_{k+2}|\bigr)$ だけ動かした展開の厳密な値であり（$u$ は単位丸め、$c$ は小さな定数）、誤差は $\bigl|\sum_k\delta_k\phi_k(x)\bigr|\le\max_k|\delta_k|\sum_k|\phi_k(x)|$ で抑えられる（A. Smoktunowicz, "Backward stability of Clenshaw's algorithm", *BIT* 42, 2002, 600–610）。
摂動の大きさは $|\gamma_k|$ ではなく途中の $|B_k|$ で決まる。
Chebyshev では $k\ge1$ で $B_k=\sum_{j\ge k}\gamma_jU_{j-k}(t)$（$U_m$ は第 2 種）であり、$|U_m(t)|\le m+1$ の上限は $t=\pm1$ で達する。
そのため端点の近くでは $|B_k|$ が $\sum_j|\gamma_j|$ の $O(n)$ 倍まで育つ。
$|T_k(t)|\le1$ なので誤差は $\sum_k|\delta_k|$ 以下で、この上界は $u\sum_j|\gamma_j|$ の $O(n^2)$ 倍になりうる。
区間の内部では $|U_m(t)|\le1/\sqrt{1-t^2}$ なので、この増幅は小さい。

SciOxide は同じ走査で導関数と包絡 $\sum_k|\gamma_k||\phi_k(x)|$ も求め、包絡と $|p(x)|$ の比を条件の推定として `PolynomialEvaluation::condition()` に入れる。
この推定は係数の大きさに比例する摂動のモデルに基づき、上の $|B_k|$ の増大を含まないので、誤差の上界ではない。
通常の浮動小数点で途中の値が範囲を外れそうなときは、指数の範囲を広げた算術で評価をやり直すので、最終の値が表現できる限り途中の桁あふれでは失敗しない。
区間外では基底自身が急増しうるので、直交基底を選んだだけで外挿の精度が保たれるとは限らない。

評価の API は次のとおりである。

- `polynomial.evaluate(point)` は所有した多項式の値を返し、`polynomial.evaluate_with_derivative(point)` は値・導関数・条件の推定を持つ `PolynomialEvaluation` を返す。
  直交基底ではどちらもメモリを確保しない。
- `plan.evaluate_with_derivative(&coefficients, point)` は係数を借用して同じ値・導関数・条件の推定を返すので、毎回多項式を所有し直す必要がない。
- `polynomial.evaluate_many_with_derivative(&points)` は各点の `evaluate_with_derivative` の結果を順に返す反復子で、メモリを確保しない。
  係数が 32 個以下なら 4 点ずつ、それより多ければ 8 点ずつ係数の読み込みを共有するので、点ごとに呼ぶより速い。
  ある点の失敗はその後の点の評価を妨げない。
- `plan.evaluate_batch_into(&coefficients, &points, &mut output, &mut scratch, context)` は値だけを `output` に書き、Plan の実行設定と `context` が許すワーカーに点を分ける。
  呼び出し側が渡す一時領域 `scratch` は `workspace_requirements(points.len())` の長さ（点の数）が必要で、足りなければ `DimensionMismatch` になる。
  `output` と `points` の長さが違う場合も `DimensionMismatch`、停止は `ExecutionStopped` になる。
  `output` は全点の成功後にだけ更新され、失敗時には `scratch` だけが変わりうる。

## 基底変換の作用素

`to_orthogonal(spec)` は単項式・Bernstein・直交基底の多項式を別の直交基底へ、`to_monomial()` は単項式へ変換する。
どちらも変換した多項式と条件のレポートを持つ `PolynomialConversion` を返し、係数の増大と後退誤差の推定を一緒に読める。
直交基底からの `to_orthogonal` は元の実行設定を引き継ぎ、単項式と Bernstein からは既定の設定で、展開の構造上の次数まで変換先の Plan を準備する。
直交基底どうしの変換では、変換元の展開に Clenshaw 法を係数の空間で適用し、$x$ を掛ける操作を変換先の三項漸化式（三重対角の作用素）で表すので、単項式を経由しない。
単項式からの変換は同じ作用素で Horner 法を係数の空間で行う。
どちらも時間は $O(n^2)$、メモリは $O(n)$ である。
Bernstein からの変換は単項式を経由するので、高い次数では単項式の係数の悪条件を引き継ぐ。
同じ仕様への変換は係数をそのまま写す。
`PolynomialConversion` の条件数の推定は変換後と変換前の係数の最大絶対値の比（1 未満なら 1）で、打ち消しを伴う変換の誤差を証明するものではない。

同じ変換を何度も使うなら、行列を準備した `OrthogonalTransform` を再利用する。
`plan.conversion_operator(&target)` は二つの直交基底の間、`from_monomial_operator()` は単項式から、`monomial_operator()` は単項式への変換を準備する。
第 $j$ 列は変換元の $j$ 次の要素を変換先で展開した係数で、変換元の三項漸化式を変換先の係数の空間で前進させて列を順に作る。
次数が上がらないので行列は上三角になる。
`conversion_operator` は変換先の最大次数が元の次数以上であることを要求し、満たさなければ `InvalidInput`（`Inconsistent`）になる。
準備と保存は密な $(n+1)\times(n+1)$ 行列の $O(n^2)$ で、`entries()` はその要素を列優先で借用する。
出力の係数は次数の昇順である。
`LinearOperator` の `rows`、`cols`、`apply_workspace_len` で出力と一時領域の長さを問い合わせ、`apply_into` は $O(n^2)$ の時間で、成功時にだけ出力を書く。
`apply` は出力と一時領域を確保する簡便な API である。
多項式に作用させる `to_orthogonal_with_operator` と `to_monomial_with_operator` は、作用素の変換元の仕様が多項式の基底と一致し、作用素の列数が係数の個数に等しいことを確かめてから、行列を作り直さずに `PolynomialConversion` を返す。
列数の不一致は `DimensionMismatch`、変換元や変換先の食い違いは `InvalidInput`（`Inconsistent`）になる。
評価と違い、短い展開を長い作用素にそのまま渡すことはできない。

## 単項式への変換と係数の増大

$T_m$ を単項式で書くと、係数 $c_k$ は 2 次おきに並び、符号が交互に変わる。
そのため $T_m(\mathrm{i}x)=\mathrm{i}^m\sum_k|c_k|x^k$ となり、$x=1$ とおくと係数の絶対値の和は

$$
\sum_k|c_k|=|T_m(\mathrm{i})|=\frac{(1+\sqrt2)^m+(1-\sqrt2)^m}{2}\approx\frac{(1+\sqrt2)^m}{2}
$$

になる。
区間 $[-1,1]$ で $|T_m|\le1$ の関数を、絶対値の和が $(1+\sqrt2)^m/2$ 程度になる係数の打ち消し合いで表すことになる。
各 $c_k$ を相対的に $u$ だけ動かすと、関数は $[-1,1]$ 上で最大 $u\sum_k|c_k|$ 程度変わり、この変化は打ち消し合わない。
そのため単項式の係数を丸めてから直交基底へ戻すと、誤差は $u\sum_k|c_k|$ 程度まで育ちうる。
この目安は次数 $m$ ごとに $\log_{10}(1+\sqrt2)\approx0.38$ 桁ずつ増える。

次のセルは最大次数 $n$ の Chebyshev 基底を準備し、`monomial_operator()` と `from_monomial_operator()` の行列を一度だけ作る。
$m=0,\dots,n$ について $\gamma T_m$（$\gamma=0.1$）の係数を単項式に変換し、係数の絶対値の和を $\gamma$ で割って上の閉形式と比べる。
$\gamma$ を 2 進で正確に表せない値にするのは、整数の係数だけでは積が丸めなしに表せて、丸め誤差の伝わり方が見えないからである。
閉形式は f64 の固有メソッド `powi` で計算した参照値である。
さらに単項式の係数を Chebyshev 基底へ戻し、元の係数との差の最大を $\gamma$ で割って往復の相対誤差とする。
表の条件数の推定は $\gamma T_n$ の多項式を `to_monomial_with_operator` で変換したときの `PolynomialConversion` の値で、変換後と変換前の係数の最大絶対値の比、つまり $T_n$ の単項式の係数の最大絶対値に等しい。
入力は最大次数 $n$ で、座標と係数は無次元である。

```rust
//| id: poly-chebyshev-monomial-growth
//| ref: poly-chebyshev-monomial-growth
//| title: Chebyshev 基底と単項式の往復で失う桁
//| run: reactive
//| crates: [scioxide-poly]
//| inputs:
//|   degree: {"type":"range","label":"最大次数 n","min":4,"max":48,"step":4,"value":24}
//| cases:
//|   - {"id":"low","label":"n = 8","description":"係数の絶対値の和は 577 で、往復の相対誤差は 10⁻¹⁴ 程度にとどまる。","inputs":{"degree":8}}
//|   - {"id":"high","label":"n = 48","description":"係数の絶対値の和が 10¹⁸ を超え、往復の相対誤差が 1 を超えて係数は一桁も残らない。","inputs":{"degree":48}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"growth","path":"/rows/0/1","approx":{"value":768398401,"rtol":1e-13}}
//|       - {"artifact":"growth","path":"/rows/0/2","range":{"max":1e-14}}
//|       - {"artifact":"growth","path":"/rows/0/3","range":{"min":1e-10,"max":1e-6}}
//|       - {"artifact":"growth","path":"/rows/0/4","approx":{"value":199229440,"rtol":1e-12}}
//|   - case: low
//|     expect:
//|       - {"artifact":"growth","path":"/rows/0/1","approx":{"value":577,"rtol":1e-14}}
//|       - {"artifact":"growth","path":"/rows/0/3","range":{"max":1e-13}}
//|   - case: high
//|     expect:
//|       - {"artifact":"growth","path":"/rows/0/1","approx":{"value":1.1808722053187136e18,"rtol":1e-13}}
//|       - {"artifact":"growth","path":"/rows/0/3","range":{"min":0.5}}
use scioxide_poly::{ApproxPolynomial, OrthogonalBasisSpec, OrthogonalFamily};

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let n = degree as usize;
let spec =
    OrthogonalBasisSpec::classical(OrthogonalFamily::ChebyshevT).map_err(|e| e.to_string())?;
let plan = spec
    .prepare(n, Default::default())
    .map_err(|e| e.to_string())?;
// 行列は一度だけ準備し、各次数の単位ベクトルに作用させる。
let to_power = plan.monomial_operator().map_err(|e| e.to_string())?;
let from_power = plan.from_monomial_operator().map_err(|e| e.to_string())?;
let (mut reference, mut errors, mut exact) = (Vec::new(), Vec::new(), 0_usize);
let (mut last_sum, mut worst_relative, mut worst_error) = (0.0_f64, 0.0_f64, 0.0_f64);
// T_m に 2 進で正確に表せない係数 γ を掛ける（整数の係数だけなら丸めが起こらない）。
let gamma = 0.1_f64;
let mut unit = vec![0.0_f64; n + 1];
for m in 0..=n {
    unit.fill(0.0);
    unit[m] = gamma;
    // γT_m の単項式の係数と、それを Chebyshev 基底へ戻した係数
    let power = to_power.apply(&unit).map_err(|e| e.to_string())?;
    let back = from_power.apply(&power).map_err(|e| e.to_string())?;
    last_sum = power.iter().map(|c| c.abs()).sum::<f64>() / gamma;
    // 独立検算: Σ|c_k| = |T_m(i)| = ((1 + √2)^m + (1 − √2)^m)/2（f64 の powi による参照値）
    let root = std::f64::consts::SQRT_2;
    let closed = ((1.0 + root).powi(m as i32) + (1.0 - root).powi(m as i32)) / 2.0;
    worst_relative = worst_relative.max((last_sum - closed).abs() / closed);
    reference.push([m as f64, f64::EPSILON * closed]);
    let error = back
        .iter()
        .zip(&unit)
        .map(|(b, u)| (b - u).abs() / gamma)
        .fold(0.0_f64, f64::max);
    worst_error = worst_error.max(error);
    // 対数軸に描けない誤差 0 の次数は数えて表に出す。
    if error > 0.0 {
        errors.push([m as f64, error]);
    } else {
        exact += 1;
    }
}
// T_n の多項式を準備した行列で単項式へ変換し、条件数の推定を読む。
```

既定の $n=24$ では、$T_{24}$ の係数の絶対値の和は $7.68\times10^8$ で、閉形式との相対差は $9.6\times10^{-16}$ である。
往復の相対誤差の最大は $6.7\times10^{-9}$ で、係数の 16 桁のうち 8 桁ほどを失っている。
図の観測点は破線 $\varepsilon\sum_k|c_k|$ と同じ傾きで増え、破線より 1〜2 桁下にある。
$n=8$ では和が 577 で、往復の相対誤差は $8.9\times10^{-15}$ にとどまる。
$n=48$ では和が $1.18\times10^{18}$ に達し、往復の相対誤差は 5 で、戻した係数は一桁も正しくない。
誤差が厳密に 0 になった次数は対数軸に描けないので図から除き、表に個数を示す。
条件数の推定は $n=24$ で $2.0\times10^8$ と係数の増大の向きを示すが、往復誤差そのものではない。
直交基底のまま評価・変換すればこの増大を経由しないので、高い次数の展開を単項式に直して保存しない。

## まとめ

直交展開は係数と準備済みの基底を一緒に保持し、族・規格化・アフィン座標は `OrthogonalBasisSpec` で一度だけ指定する。
`on_interval` は区間の両端から中心と尺度を作るので、`new` の最後の二つの引数に区間の両端を渡す取り違えを避けられる。
Clenshaw 法の丸め誤差は係数の摂動として読め、その大きさは途中の $|B_k|$ で決まるので、Chebyshev 展開の誤差の上界は端点の近くで $u\sum_j|\gamma_j|$ の $O(n^2)$ 倍まで育ちうる。
直交基底どうしの変換は単項式を経由しないが、単項式との変換では係数の絶対値の和が $(1+\sqrt2)^n$ の速さで増え、往復の誤差もそれに比例して育つ。
同じ変換を繰り返すなら `OrthogonalTransform` を一度準備して再利用し、一時領域の長さは `apply_workspace_len` で問い合わせる。
