同じ多項式でも、何を入力データとして保存するかによって丸め誤差の伝わり方が変わる。
係数を扱う計算では単項式、標本値を保つ補間では重心形式、区間上の近似では直交展開が候補になる。
このページでは保存座標の規約を定め、単項式の Horner 法を導き、基底の変換と評価に渡す一時領域の仕様を説明する。
評価の丸め誤差の上界と、示される推定値の意味は [Horner 評価の丸め誤差と診断](../horner-rounding-error/)で扱う。

## 保存する座標と次数

本章では、多項式を表すために型が保持する数の並びを保存座標と呼ぶ。
保存座標は基底によって係数・節点での値・制御点のいずれかになる。
単項式基底の保存座標は昇べき順の係数である。

$$
p(x)=\sum_{k=0}^{n}a_kx^k,\qquad [a_0,a_1,\ldots,a_n].
$$

`ApproxPolynomial::monomial` は係数を所有し、末尾の厳密な零だけを除く。
零多項式は係数一つ $[0]$ で表す。
空の係数列と非有限の係数はエラーになる。
有限な小さい係数を許容誤差で捨てる処理は行わない。
例えば $10^{-20}x^{10}+1$ の最高次の項は、$x=100$ では定数項と同じ大きさになる。
保存上の次数と、「この尺度では小さい」という判断は分けて扱う必要がある。

この判断の規則は `PolynomialApproximationPolicy` が持つ。
既定の方針では、保存座標の最大絶対値を $s$ として、絶対値が $\tau=\mathrm{atol}+\mathrm{rtol}\cdot s$（既定は $\mathrm{atol}=\mathrm{rtol}=\sqrt\varepsilon$）以下の係数を零とみなす。
`classify_coefficients` が返す `PolynomialCoefficientReport` の `effective_degree()` は、$\tau$ を超える最後の係数の添字である。
`effective_rank()` は、数値ランクの閾値（既定は $s\,N\varepsilon$、$N$ は保存座標の数）を超える保存座標の数で、次数でも行列のランクでもない。
どちらの分類も保存座標を変更しない。
構築と評価はこの分類を行わない。

Newton 形式は末尾の零係数とその節点を残す。
重心形式の保存座標は節点での値、Bernstein 形式では制御点であり、単項式係数ではない。
そのため有効次数の分類は、重心形式では節点での値の Newton 差商、Bernstein 形式では $t=(x-a)/(b-a)$ のべきの係数を作って判定し、$s$ もその係数の最大絶対値にする。
この二つは指数の範囲を広げた算術で $O(n^2)$ の演算と $O(n)$ の一時確保を行い、ほかの基底は保存座標をそのまま $O(n)$ で調べる。

`PolynomialBasis` はこれらの基底に共通する sealed トレイトで、外部の型は実装できない。
`ApproxPolynomial` の基底は `MonomialBasis`、`NewtonBasis`、`BarycentricBasis`、`BernsteinBasis`、`OrthogonalBasis` のどれかである。
このトレイトを `use` で取り込めば、どの基底でも `basis().coefficients()` で保存座標を借用できる。
この操作だけで基底が変換されることはない。

## Horner 法と微分

括弧を内側から計算すると、各べきを作らずに値を求められる。

$$
p(x)=a_0+x\bigl(a_1+x(\cdots+x\,a_n)\bigr).
$$

$b_n=a_n$、$c_n=0$ とおき、$k=n-1,\ldots,0$ について

$$
c_k=b_{k+1}+x\,c_{k+1},\qquad b_k=a_k+x\,b_{k+1}
$$

と更新すれば、$b_0=p(x)$、$c_0=p'(x)$ となる。
$b_k$ は $p$ を $t-x$ で割った商 $q(t)=\sum_{k\ge1}b_kt^{k-1}$ の係数でもあり（組立除法）、$p(t)=b_0+(t-x)q(t)$ である。
この式を $t$ で微分して $t=x$ とおくと $p'(x)=q(x)$ となる。
二つ目の漸化式はこの $q(x)$ を同じ Horner 法で求めている。
$c_k$ の更新には同じ段で更新する前の $b_{k+1}$ を使う。

値だけなら乗算と加算をそれぞれ $n$ 回行い、時間は $O(n)$、追加のメモリは $O(1)$ である。
導関数も求めると演算はおよそ 2 倍になる。
各べき $x^k$ を一から作る方法は $n(n+1)/2$ 回の乗算を要するが、べきを $x^k=x\cdot x^{k-1}$ と逐次に更新する直接和なら $O(n)$ で済む。
Horner 法の利点は演算回数だけではなく、後退誤差が小さいことが証明されている点にある（Higham, *Accuracy and Stability of Numerical Algorithms*, 第 5 章）。

`evaluate` は値だけを返し、`evaluate_with_derivative` は値、導関数、`PolynomialConditionReport` をまとめた `PolynomialEvaluation` を返す。
二つは同じ計算を共有するので、値は最後のビットまで一致する。
非有限の評価点、表現できない値・導関数・包絡はエラー（`NonFinite`、`NumericalInstability`）になる。
相対的な診断が有界でない場合は、エラーにせず正の無限大を返す。
`derivative` は微分した多項式を新しく所有する操作であり、一点で導関数を読むことと異なる。
単項式では $a_k$ を $ka_k$ に置き換え（$k\ge1$）、直交展開の微積分は[直交展開の微分と積分](../orthogonal-calculus/)の規約に従う。

## 基底の変換と一時領域

`PolynomialConversion` は変換後の多項式と、条件のレポート `PolynomialConditionReport` を所有する。
`to_monomial` はどの基底からも使え、`to_newton`、`to_barycentric`、`to_bernstein` は単項式から、`to_orthogonal` は単項式・Bernstein・直交展開から変換する。
Bernstein 形式の `to_orthogonal` は単項式を経由し、レポートは単項式から直交基底への段のものになる。
レポートの条件数の推定は変換先と変換元の保存座標の最大絶対値の比（1 未満なら 1）である。
後退誤差のモデルは両者の座標数の大きい方 $N$ による $\gamma_N(\varepsilon)$ である（記号は[示される推定値](oxref:poly-condition-report-estimates)を参照）。
変換の途中で打ち消しが起きると、この比が示す以上に桁を失うことがある。
`BasisNormalization` は直交基底の規格化（`Classical`・`Monic`・`Orthonormal`）を指定する。
変換しても、すでに丸められた入力の情報は回復しない。

一点の `evaluate` と `evaluate_with_derivative` は一時領域を引数に取らない。
Bernstein 形式は de Casteljau 法で $O(n^2)$ の演算を使い、制御点の数の一時ベクトルを呼び出しごとに確保する（確保に失敗すると `AllocationFailure`）。
ほかの基底は $O(n)$ の演算で、確保しない。
多くの点の値は `evaluate_batch(&points)` が新しいベクトルで返す。
確保を避けるときは、値を書く `evaluate_batch_into` と、導関数も書く `evaluate_batch_with_derivative_into` に一時領域を渡す。
その長さは `workspace_requirements(m)`（$m$ は点の数）が返す `PolynomialScratchRequirements` から問い合わせる。
値だけなら $m+s$ 個、導関数も求めるなら $2m+s$ 個が要り（$s$ は Bernstein 形式で制御点の数、ほかの基底で 0）、返る長さ $2m+s$ はどちらにも足りる。
一時領域が短いときや、出力の長さが点の数と違うときは、数値計算の前に `DimensionMismatch` になる。
`_into` の形は確保せず、値を一時領域に置いてから最後に出力へ写すので、失敗しても出力を変えない。
実行コンテキスト（`ExecutionContext`）も受け取り、各点の前と出力へ写す前に取り消しと期限を確かめ、止まれば `ExecutionStopped` を返す。
各点の値は一点の `evaluate` と最後のビットまで一致する。
係数の演算を繰り返す `PolynomialWorkspace` とその要件は[高速な積・合成・Taylor シフト](../fast-operations-and-product-trees/)で扱う。

## 評価と演算回数の比較

次のセルは指数関数の $n$ 次 Taylor 多項式 $p_n(x)=\sum_{k=0}^n x^k/k!$ を作り、SciOxide の評価で値・導関数・診断を求める。
入力は次数 $n$ と無次元の評価点 $x$ である。
独立な検算は三つある。
一つ目は各べきを一から作る素朴な直接和で、値の差と乗算の回数を比べる。
二つ目はTaylor 多項式の性質 $p_n'(x)=p_{n-1}(x)=p_n(x)-x^n/n!$ による導関数の検算で、$x^n$ には f64 の `powi`（SciOxide の関数ではない参照値）を使う。
三つ目は包絡 $\sum_k|a_kx^k|$ と $|p_n(x)|$ の比と、$\gamma_N(\varepsilon)$ の式である。
条件数と後退誤差のモデルの意味は [Horner 評価の丸め誤差と診断](../horner-rounding-error/)で導く。

```rust
//| id: poly-horner-operation-growth
//| ref: poly-horner-operation-growth
//| title: Taylor 多項式の Horner 評価を素朴な直接和と比べる
//| run: reactive
//| crates: [scioxide-poly]
//| inputs:
//|   degree: {"type":"range","label":"多項式の次数 n","description":"評価する Taylor 多項式の次数を変える。","min":2,"max":80,"step":1,"value":20}
//|   point: {"type":"range","label":"評価点 x [-]","description":"負にすると項の符号が交互になり、打ち消しが起きる。","min":-8,"max":8,"step":0.5,"value":-4}
//| cases:
//|   - {"id":"strong-cancellation","label":"n = 80、x = −8","description":"打ち消しが強く、条件数の推定が e^16 ≈ 8.9 × 10^6 に達する。","inputs":{"degree":80,"point":-8}}
//|   - {"id":"positive-point","label":"n = 20、x = 4","description":"すべての項が正で打ち消しがなく、条件数の推定は 1 になる。","inputs":{"degree":20,"point":4}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"comparison","path":"/rows/0/3","range":{"min":-1e-13,"max":1e-13}}
//|       - {"artifact":"comparison","path":"/rows/1/3","range":{"min":-1e-13,"max":1e-13}}
//|       - {"artifact":"comparison","path":"/rows/2/1","approx":{"value":2981.0,"rtol":1e-3}}
//|       - {"artifact":"comparison","path":"/rows/2/2","approx":{"value":2981.0,"rtol":1e-3}}
//|       - {"artifact":"comparison","path":"/rows/3/1","approx":{"value":4.6629367034256575e-15,"rtol":1e-12}}
//|       - {"artifact":"operations","path":"/rows/0/1","equals":210}
//|       - {"artifact":"operations","path":"/rows/0/2","equals":20}
//|   - case: strong-cancellation
//|     expect:
//|       - {"artifact":"comparison","path":"/rows/2/1","approx":{"value":8886110.52,"rtol":1e-3}}
//|       - {"artifact":"comparison","path":"/rows/0/3","range":{"min":-1e-12,"max":1e-12}}
//|       - {"artifact":"operations","path":"/rows/0/1","equals":3240}
//|   - case: positive-point
//|     expect:
//|       - {"artifact":"comparison","path":"/rows/2/1","approx":{"value":1,"atol":1e-12}}
//|       - {"artifact":"comparison","path":"/rows/0/1","approx":{"value":54.5981499281488,"rtol":1e-12}}
use scioxide_poly::ApproxPolynomial;

let n = degree.round() as usize;
// e^x の n 次 Taylor 多項式の係数 a_k = 1/k!（昇べき順）。
let mut coefficients = vec![1.0_f64];
for k in 1..=n {
    coefficients.push(coefficients[k - 1] / k as f64);
}
let polynomial = ApproxPolynomial::monomial(coefficients.clone()).map_err(|e| e.to_string())?;
// 主計算: SciOxide の Horner 法で値・導関数・診断を同時に得る。
let evaluation = polynomial
    .evaluate_with_derivative(point)
    .map_err(|e| e.to_string())?;
let condition = evaluation.condition();

// 独立検算: 各べき x^k を一から作る素朴な直接和（x^k に k − 1 回、係数との積に 1 回の乗算）。
let mut naive = coefficients[0];
let mut envelope = coefficients[0].abs();
let mut naive_multiplications = 0_u64;
for (k, &a) in coefficients.iter().enumerate().skip(1) {
    let mut power = point;
    for _ in 1..k {
        power *= point;
        naive_multiplications += 1;
    }
    naive += a * power;
    envelope += (a * power).abs();
    naive_multiplications += 1;
}
// 独立検算: Taylor 多項式では p′(x) = p(x) − x^n/n!（x^n は f64 の powi による参照値）。
let slope = evaluation.value() - coefficients[n] * point.powi(n as i32);
// 独立検算: 座標数 N = n + 1 と EPSILON による γ_N(ε)。
let count = (n + 1) as f64;
let gamma = count * f64::EPSILON / (1.0 - count * f64::EPSILON);
let ratio = (naive != 0.0).then(|| envelope / naive.abs());
let digits = serde_json::json!({ "significantDigits": 15 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "量" },
    { "key": "1", "label": "SciOxide [-]", "type": "number", "format": digits },
    { "key": "2", "label": "独立な検算 [-]", "type": "number", "format": digits, "nullText": "+∞" },
    { "key": "3", "label": "差 [-]", "type": "number", "format": sci3, "nullText": "-" }
]);
let row = |name: &'static str, scioxide: f64, check: Option<f64>| {
    (name, scioxide, check, check.map(|c| scioxide - c))
};
emit_table_with_columns!(
    columns,
    vec![
        row("値 p(x)", evaluation.value(), Some(naive)),
        row("導関数 p′(x)", evaluation.derivative(), Some(slope)),
        row("条件数の推定", condition.condition_estimate(), ratio),
        row(
            "後退誤差のモデル γ_N(ε)",
            condition.backward_error(),
            Some(gamma)
        ),
    ],
    metadata = serde_json::json!({ "id": "comparison" })
);
let operation_columns = serde_json::json!([
    { "key": "0", "label": "次数 n", "type": "integer" },
    { "key": "1", "label": "素朴な直接和の乗算 [回]", "type": "integer" },
    { "key": "2", "label": "Horner 法の乗算 [回]", "type": "integer" }
]);
emit_table_with_columns!(
    operation_columns,
    vec![(n as u64, naive_multiplications, n as u64)],
    metadata = serde_json::json!({ "id": "operations" })
);
// 乗算回数の理論値: 素朴な直接和 n(n + 1)/2、Horner 法 n。
let naive_curve: Vec<[f64; 2]> = (1..=80)
    .map(|d| [d as f64, (d * (d + 1) / 2) as f64])
    .collect();
let horner_curve: Vec<[f64; 2]> = (1..=80).map(|d| [d as f64, d as f64]).collect();
emit_line_chart!(
    &vec![
        serde_json::json!({
            "name": "各べきを一から作る直接和 n(n + 1)/2",
            "points": naive_curve,
            "style": { "lineType": "dashed" }
        }),
        serde_json::json!({
            "name": "Horner 法 n",
            "points": horner_curve,
            "style": { "lineType": "dashed" }
        }),
    ],
    options = &serde_json::json!({
        "xLabel": "次数 n [-]",
        "yLabel": "乗算回数 [回]",
        "yType": "log",
        "annotations": [
            { "kind": "line", "axis": "x", "value": n as f64, "label": "選んだ n" }
        ]
    })
);
```

一つ目の表の「差」は SciOxide の値から独立な検算を引いたもので、条件数の推定が空欄になるのは素朴な和がちょうど 0 になった場合だけである。
二つ目の表とグラフは理論上の乗算回数であり、実行時間の測定ではない。
SciOxide の実装は係数を二つずつまとめた漸化式なども使うが、値の乗算はおよそ $n$ 回で、Horner 法と同じ程度である（経路は [SciOxide の演算経路と定理の仮定](oxref:poly-horner-arithmetic-paths)を参照）。
SciOxide の評価は導関数と包絡も同時に計算するので、処理全体の演算数は値だけの $n$ 回より多い。

既定の $n=20$、$x=-4$ では、条件数の推定が $2.98\times10^3$ で、検算の $\sum_k|a_kx^k|/|p_n(x)|$ と一致する。
この値は $e^{|x|}/e^{x}=e^{8}\approx2981$ に近い。
包絡は $e^{|x|}$、値は $e^{x}$ に近いので、負の $x$ では打ち消しで約 $e^{2|x|}$ 倍の相対誤差の増幅が起こりうる。
$n=80$、$x=-8$ では条件数の推定が $8.9\times10^6\approx e^{16}$ まで増え、素朴な和との差も $1.6\times10^{-14}$（値に対して約 $5\times10^{-11}$）に広がる。
$x=4$ ではすべての項が正なので条件数の推定は 1 で、二つの和の差は丸めの数単位にとどまる。
有限次数の Taylor 多項式と指数関数との差は打ち切り誤差で、同じ多項式を二通りに評価した差とは別の量である。

## まとめ

保存座標は基底ごとに係数・節点での値・制御点のどれかで、有効次数の分類も基底の変換も保存座標を変えない明示的な操作である。
Horner 法は組立除法として値と導関数を $O(n)$ の演算と $O(1)$ の追加メモリで求め、各べきを一から作る方法の $n(n+1)/2$ 回の乗算を避ける。
基底の変換のレポートは保存座標の最大絶対値の増え方を条件数の推定とするが、すでに丸められた入力の情報は回復しない。
一点の評価は一時領域を取らず、多点を確保なしで評価する `evaluate_batch_into` の一時領域は `workspace_requirements(m)` で長さを問い合わせる。
交代級数のように項が打ち消し合う評価点では条件数の推定が大きくなるので、値と一緒に `condition()` を読む。
