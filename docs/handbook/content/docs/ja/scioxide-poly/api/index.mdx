`scioxide-poly` は、浮動小数点の近似多項式と基底の変換、直交多項式族、有理関数と近似 GCD、部分分数分解、終結式と判別式、根の感度の診断、厳密な係数の多項式、準備済みの係数の演算と部分積の木、疎な多変数多項式と Bernstein 表現を出力に反映する。
このガイドは目的ごとに使い始める項目と型の関係を示し、公開されている 124 項目を用途別の四つのページの表にまとめる。
表の項目名のリンクは、docs.rs の 0.1.0 の API リファレンスを指す。

## 型の関係

`ApproxPolynomial<C, B>` は、係数のスカラー型 `C` と準備済みの基底 `B`（`MonomialBasis`、`NewtonBasis`、`BarycentricBasis`、`OrthogonalBasis`、`BernsteinBasis`）を型で持つ。
基底の変換は `to_*` で明示的に行い、暗黙の変換はしない。
近似の多項式は `PolynomialApproximationPolicy`（係数の許容誤差と数値ランクの方針）を持ち、二項演算は同じ方針の多項式どうしに限られる。
データだけを取る構築関数は既定の方針を使い、`monomial_with_options` のような `_with_options` の形が別の方針を受け取る。
方針は次数とランクの判定に使い、係数を自動で削除しない。
`ExactPolynomial<C>` は `ExactCoefficient`（除算には `ExactField`）を実装する係数型だけを受け取り、近似の演算と厳密な演算は別の型と関数で提供する。

メモリの扱いは三種類に分かれる。
`PolynomialOperationPlan`、`OrthogonalBasisPlan`、`ApproxPartialFractionPlan`、`ExactPartialFractionPlan` などの Plan は準備で必要な表を確保し、実行は呼び出し側が所有する作業領域（`PolynomialWorkspace` など）を使ってメモリを確保しない。
`SylvesterElimination` と `SylvesterDiscriminant` は検査した次数と方針だけを持つ値で、固定の大きさの作業領域を `workspace()` で作り、`_scoped` の形が呼び出し側のスコープの中で確保せずに計算する。
作業領域は `workspace_requirements` で要件を問い合わせ、`try_reserve` で伸ばし、`check` で確保せずに足りるかを調べる。
一括評価などの `_into` の形に渡す `&mut [C]` は呼び出し側の一時領域で、伸ばされず、必要な長さは `PolynomialScratchRequirements` で問い合わせる。
一点の評価は一時領域を取らない。
`ExactPolynomialProductTree` の問い合わせや所有する多項式を返すワンショット関数（`div_rem`、`compose` など）は、結果のメモリを確保する。

準備済みの原子的な実行は最後の引数に `ExecutionContext` を受け取り、失敗したときは出力を変えない。
呼び出し側の識別子を引数に渡すことはない。

## 最小の実行例

昇べき順の係数 $[2, -3, 1]$ は $p(x) = 2 - 3x + x^2 = (x-1)(x-2)$ を表し、$p'(x) = 2x-3$ である。
次のセルは三つの点 $x=4,\ 2.5,\ 2$ で `evaluate_with_derivative` を呼び、値・導関数・条件のレポートを手計算と並べる。
2 つ目の表には非有限の点の評価と方針の異なる多項式どうしの和が返すエラーの分類を `kind()` で読んで出す。

```rust
//| id: poly-api-horner-derivative
//| ref: poly-api-horner-derivative
//| title: 値・導関数・診断・エラーの読み方
//| run: reactive
//| crates: [scioxide-core, scioxide-poly]
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"evaluations","path":"/rows/0/1","approx":{"value":6,"atol":1e-12}}
//|       - {"artifact":"evaluations","path":"/rows/0/3","approx":{"value":5,"atol":1e-12}}
//|       - {"artifact":"evaluations","path":"/rows/1/6","approx":{"value":6.661338147750944e-16,"rtol":1e-6}}
//|       - {"artifact":"evaluations","path":"/rows/1/7","approx":{"value":21,"rtol":1e-12}}
//|       - {"artifact":"evaluations","path":"/rows/2/7","equals":null}
//|       - {"artifact":"errors","path":"/rows/0/1","equals":"NonFinite"}
//|       - {"artifact":"errors","path":"/rows/1/1","equals":"InvalidInput"}
use scioxide_core::Tolerance;
use scioxide_poly::{ApproxPolynomial, PolynomialApproximationPolicy};

// 昇べき順の係数 [a0, a1, a2] による p(x) = 2 - 3x + x^2
let polynomial =
    ApproxPolynomial::monomial(vec![2.0_f64, -3.0, 1.0]).map_err(|e| e.to_string())?;
// 導関数の多項式 p'(x) = -3 + 2x も作り、evaluate_with_derivative の導関数と比べる。
let derivative = polynomial.derivative().map_err(|e| e.to_string())?;
// 有限でない推定値（根での +∞）は表で None として出す。
let finite = |value: f64| value.is_finite().then_some(value);
let mut rows = Vec::new();
for x in [4.0, 2.5, 2.0] {
    let evaluation = polynomial
        .evaluate_with_derivative(x)
        .map_err(|e| e.to_string())?;
    let slope = derivative.evaluate(x).map_err(|e| e.to_string())?;
    let report = evaluation.condition();
    // 独立な検算: 因数の形 (x - 1)(x - 2) と解析的な導関数 2x - 3 を手で計算する。
    rows.push((
        x,
        evaluation.value(),
        (x - 1.0) * (x - 2.0),
        evaluation.derivative(),
        slope,
        2.0 * x - 3.0,
        report.backward_error(),
        finite(report.condition_estimate()),
        finite(report.forward_error_estimate()),
    ));
}
let fixed2 = serde_json::json!({ "fractionDigits": 2 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "点 x [-]", "type": "number", "format": fixed2 },
    { "key": "1", "label": "p(x) [-]", "type": "number", "format": fixed2 },
    { "key": "2", "label": "手計算の p(x) [-]", "type": "number", "format": fixed2 },
    { "key": "3", "label": "p'(x) [-]", "type": "number", "format": fixed2 },
    { "key": "4", "label": "derivative() の p'(x) [-]", "type": "number", "format": fixed2 },
    { "key": "5", "label": "手計算の p'(x) [-]", "type": "number", "format": fixed2 },
    { "key": "6", "label": "後退誤差 [-]", "type": "number", "format": sci3 },
    { "key": "7", "label": "条件数の推定 [-]", "type": "number", "format": fixed2, "nullText": "+∞" },
    { "key": "8", "label": "前進誤差の推定 [-]", "type": "number", "format": sci3, "nullText": "+∞" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "evaluations" })
);
// 失敗は SciOxideError で返り、分類は kind() で読む。ここでは失敗を期待して分類を表に出す。
let nonfinite = polynomial
    .evaluate(f64::NAN)
    .map_or_else(|e| format!("{:?}", e.kind()), |_| "成功".to_string());
// 既定の方針の許容誤差だけを替えた方針で、もう一つの多項式を作る。
let tolerance = Tolerance::new(1e-12, 1e-12).map_err(|e| e.to_string())?;
let other_policy = PolynomialApproximationPolicy::default().with_tolerance(tolerance);
let other = ApproxPolynomial::monomial_with_options(vec![1.0_f64], other_policy)
    .map_err(|e| e.to_string())?;
let mismatch = polynomial
    .try_add(&other)
    .map_or_else(|e| format!("{:?}", e.kind()), |_| "成功".to_string());
emit_table_with_columns!(
    ["呼び出し", "エラーの分類"],
    vec![
        ("evaluate(NaN)", nonfinite),
        ("方針の異なる多項式の try_add", mismatch),
    ],
    metadata = serde_json::json!({ "id": "errors" })
);
```

値と導関数は因数の形と解析的な導関数による手計算と一致する。
`evaluate_with_derivative` は値と導関数を一度の Horner 法の走査で返すので、導関数の値だけが必要なときに `derivative` で多項式を作り直す必要はない。

後退誤差の列は $\gamma_3=3\varepsilon/(1-3\varepsilon)\approx6.66\times10^{-16}$ である（$\varepsilon=2^{-52}$ は機械イプシロン、3 は係数の個数）。
これは丸めのモデルから決まる目安で、実測した誤差ではない。
条件数の推定は $\kappa(x)=\max\{1,\ \sum_k|a_k||x|^k/|p(x)|\}$ で、$x=4$ では $30/6=5$、根に近い $x=2.5$ では $15.75/0.75=21$ になる。
根 $x=2$ では $p(x)=0$ なので相対的な条件数は有界でなく、レポートは正の無限大を返し、表は `+∞` と示す。
前進誤差の推定は $\gamma_3\kappa$ で、$x=2.5$ では $1.40\times10^{-14}$ と $x=4$ の 4.2 倍になり、根では無限大になる。
根の近くでは値の相対誤差の目安が意味を失うので、根の候補の信頼性は[根の診断の項目](oxref:poly-api-roots-sensitivity)で調べる。

エラーの表は非有限の点の評価が `NonFinite`、方針の異なる多項式どうしの和が `InvalidInput` になることを示す。

## 結果・エラー・診断の読み方

失敗は `SciOxideError` で返り、分類は `e.kind()`（`SciOxideErrorKind`）、詳細は `e.view()` で読む。
この章でよく現れる分類は次のとおりである。

| 分類 | 主な原因 |
|---|---|
| `InvalidInput` | 空の係数や空の要求、重複した節点、零の除数、範囲外の次数・添字、負または全て 0 の当てはめの重み、方針・単項式順序の異なる多項式どうしの演算、宣言していない演算の形、次数 0 か最高次の係数が 0 の根を固有値に持つ行列、厳密な部分分数の互いに素でない因子、一部の形の不一致（積・合成の条件の推定の長さ、テンソル Bernstein の制御点の数と一括評価の出力の長さ、一括評価の点の形） |
| `DimensionMismatch` | 出力・作業領域・一時領域の長さや形の不一致、変数の個数の違い |
| `NonFinite` | 係数・点・節点の NaN や無限大 |
| `NumericalInstability` | 表せない結果（桁あふれ・アンダーフロー）、数値的に分離できない部分分数の因子・許容誤差を満たさない約分・丸めのモデルが成り立たない検査付き評価（`IllConditioned`）、厳密な体の除アルゴリズム則の破れ（`Breakdown`） |
| `DomainError` | 直交族の不正なパラメータや正でない尺度、重み関数の台の外の点、有理関数の零または丸め誤差に埋もれた分母での評価 |
| `ResourceLimit` | 疎多項式の代入の途中の項数が `SparseExpansionLimits` を超えた |
| `OutOfBounds` | 疎多項式の範囲外の変数の軸 |
| `SizeOverflow`、`AllocationFailure` | 大きさの計算の桁あふれ、確保の失敗 |
| `ConvergenceFailure` | 直交多項式の零点の固有値計算、近似 GCD と当てはめの SVD が収束しない、Legendre 多項式の値の漸化式が計算量の上限を超える |
| `ExecutionStopped` | `ExecutionContext` による取り消し |

`Ok` で返っても、結果の質は診断で確かめる。
`PolynomialConditionReport`、`ApproximateGcdReport`、`EliminationReport`、`PartialFractionReport`、`RootConditionReport`、`RootDiagnostics` はどれも推定値と判定の根拠であり、誤差の上界や根の証明ではない。
`PolynomialConditionReport` の後退誤差は、座標の個数 $N$ に対する $\gamma_N=N\varepsilon/(1-N\varepsilon)$ の目安で、除算だけは計算した商と剰余の再構成残差である。
相対的な診断が有界でないときは正の無限大を返す。
`PartialFractionReport::reciprocal_condition()` は、分母が定数で方程式がないとき `None` を返し、近似 GCD のレポートは零の入力でランクと逆条件数を持たない。

## まとめ

API の表で目的に合う項目を選び、近似では方針を、厳密な演算では係数型を明示する。
基底の変換・積・補間はすべて明示的で、準備済みの Plan は作業領域を呼び出し側が持ち、一括評価の一時領域の長さは要件で問い合わせる。
エラーは `kind()` で分類し、`Ok` の結果も後退誤差と条件数の推定を読んでから使う。
