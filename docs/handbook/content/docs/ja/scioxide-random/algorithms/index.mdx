`scioxide-random` の計算は、生成器が出す整数ワードを一様乱数に直し、それを確率分布や点列の座標へ写す、という二段で進む。
この章の各ページは個別のアルゴリズムを扱い、このページはそれらが共有する約束をまとめる。
ここで定める用語と仕様は、子ページでは繰り返さずにこのページへ参照する。

## 記号と用語

| 記号・用語 | 意味 |
|---|---|
| 生成器（engine） | 有限の状態 $s_n$ を $s_{n+1} = T(s_n)$ で進め、出力 $G(s_n)$ を返す決定論的な機械。`Pcg64`、`Xoshiro256StarStar`、`Philox4x64` など。暗号用途の安全性は持たない |
| ネイティブ出力ワード（native word） | 生成器が参照実装と同じ規則で返す整数（`next_u32`、`next_u64`）。値域が $2^{32}$ や $2^{64}$ の全体とは限らない |
| 一様乱数ワード（uniform word） | 全ビットが一様な 32 ビットまたは 64 ビットの整数（`next_uniform_u32`、`next_uniform_u64`）。添字の抽出、整数の分布、Ziggurat 法の速い経路などが使う |
| $U$ | $[0, 1)$ 上の一様乱数。開区間 $(0, 1)$ が必要なときは明記する |
| $F(x)$、$S(x)$ | 分布関数 $P(X \le x)$ と上側確率 $P(X > x)$。$S$ は $1 - F$ の引き算では計算しない |
| $Q(p)$ | 分位点 $\inf\{x : F(x) \ge p\}$。逆上側確率は $S(x) = p$ を直接解く |
| 位置（position） | 生成器が開始から消費したネイティブ出力ワードの遷移数。追跡できない場合は `None` |
| シード（seed） | 初期状態を決める `u64`。`SeedableRng::from_seed` に渡す |
| Plan（plan） | 検査と前処理を済ませ、繰り返しの呼び出しで共有する不変な値。`QmcPlan`、`QmcReplicatePlan`、`BrownianBridgePlan`、`MultivariateProbabilityPlan` |
| 標本化の方針（sampling policy） | 呼び出し側の出力に書く一括生成の、出力方針と状態方針の組。`SamplingPolicy` |
| 作業領域（workspace） | 呼び出し側が所有し、繰り返しの一括生成で再利用するメモリ領域 |

確率分布（law）は標本化、密度、分布関数、分位点、モーメントといった機能を別々のトレイトとして持つ。
機能の一覧と、存在しない量の扱いは[分布の機能・裾確率・数値逆算](laws-tails-and-multivariate-models/)で説明する。

## 一様乱数ワードと浮動小数点への変換

`BitGenerator` は 2 種類の出力を区別する。
ネイティブ出力ワードは各エンジンの参照の数列をそのまま再現するためのもので、たとえば `Mrg` と `Cmrg` のネイティブ出力ワードは $[0, 2^{31} - 1)$ の剰余、`Mrg32k3a` のネイティブ出力ワードは $[1, m_1]$（$m_1 = 2^{32} - 209$）の整数、`Ranlux` 系は 24 ビットまたは 48 ビットの値である。
一様乱数ワードは、値域が限られたエンジンでも全ビットを一様にしたワードで、ネイティブ出力ワードを整数の棄却で正規化して作る（途中の乱数を保持しない）。
正規化はネイティブ出力ワードを基数 $m$ の桁として必要な数だけ並べるので、たとえば `Mrg32k3a` の一様乱数ワードは 32 ビットでネイティブ出力ワード 2 個、64 ビットでネイティブ出力ワード 3 個から作る（棄却されれば作り直す）。
ネイティブ出力ワードと一様乱数ワードのどちらを使うかは、標本化の経路で決まる。
添字の抽出（`uniform_index` と、それを使う置換、非復元抽出、`WeightedSampler` の列の選択）、整数の分布（`CountDistribution`）、Ziggurat 法の最初のワード、ラテンハイパーキューブと Poisson 円板標本、ランダム化 QMC の準備は一様乱数ワードを使う。
多変量・行列・群の分布、球面上の方向の分布、一部の検定統計量の分布は、一標本のワードを数える内部の包みを通し、浮動小数点の一様乱数も一様乱数ワードから作る。
一方、`Uniform`、`Cauchy`、`Logistic` などの逆関数法、Ziggurat 法のくさびと裾、ガンマ分布の受理判定の $U$、`WeightedSampler` の受理判定は `Rng::next_float` などの浮動小数点の一様乱数を使い、組み込みの生成器はそれをネイティブ出力ワード一つから作る。
そのため `Ranlux`、`Ranlxs`、`Ranlxd`、`Mrg`、`Cmrg`、`Mrg32k3a` では、一様乱数ワードを使う経路の標本の列はネイティブ出力ワードの列から直接作った値と一致しない。
浮動小数点の経路では、値の刻みがネイティブ出力ワードの幅で決まる。

組み込みの生成器はどれも `f32` と `f64` の `Rng` を実装し、浮動小数点の一様乱数をネイティブ出力ワードから作る。
一つの浮動小数点数はネイティブ出力ワードを一つ消費し、呼び出しの間に値を保持しない。
64 ビットのネイティブ出力ワードを持つエンジンは `decode_u64` で、上位 53 ビット（`f64`）または上位 24 ビット（`f32`）を使う。

$$
u = \left\lfloor W / 2^{11} \right\rfloor \cdot 2^{-53} \in \left[0,\ 1 - 2^{-53}\right]
$$

`decode_u32` は `f64` に 32 ビットすべてを、`f32` に上位 24 ビットを使う。
ネイティブ出力ワードの幅が狭いエンジンでは、浮動小数点数の刻みもネイティブ出力ワードの幅で決まる。
`Ranlux` と `Ranlxs` の `f64` は 24 ビットのネイティブ出力ワードを上に詰めた値なので $2^{-24}$ 刻みになり、`Ranlxd` は $2^{-48}$ 刻みになる。
`Mrg` と `Cmrg` の `f64` は剰余を $2^{31} - 1$ で割った値である。
`Mrg32k3a` の `f64` は RngStreams の正規化（ワード $\times 1/4\,294\,967\,088$）を保ち、値は開区間 $(0, 1)$ に入る。
どの変換も $1$ に丸め上がらない。
`next_open_float` は $u = 0$ を棄却して $(0, 1)$ の値を返し、1,024 回続けて $0$ が出ると反復上限のエラーを返す。
利用者が `Rng` を直接実装した場合、分布の API はその値が有限で $[0, 1)$ に入ることを毎回検査する。
`next_open_float` を上書きした実装の値も、標本化の前に有限で $0 < u < 1$ であることを確かめ、0 や範囲外の値は `InvalidInput`、非有限の値は `NonFinite` になる。
組み込みの生成器の値は変換の段階で範囲が保証されているので、この再検査を省く。
呼び出し側の領域をまとめて埋める `fill_uniforms` も同じ検査を行い、メモリ領域を確保せず、プロバイダーの呼び出し回数を `attempts` に加える。

## 再現性の範囲

名前の付いたエンジンに明示したシードと同じ呼び出しの列を与えたときの結果は、エンジンのアルゴリズムのバージョンと、ワードを一様乱数ワードや浮動小数点数に変換する規約（デコーダの規約）のバージョンが同じなら同じになる。
固定する結果は生の整数、浮動小数点数、バイト列、`skip_ahead` と `jump` の結果、`split` した系列である。
`seed_sequence` と組み込みの QMC 点列も同じ規則に従う。
状態のバイト列は対応しない規約のバージョンを拒否する。
一方、分布の標本化アルゴリズムとその丸め、エントロピーからシードを取った実行は、この保証の外にあり、リリースの間で変わりうる。
たとえば正規分布の Ziggurat 表や一様乱数ワードの使い方が変わると、同じシードから得る正規標本の列は変わる。
本書のセルが示す標本の値は、本書が説明するコミットでの値である。

状態の保存には `SerializableState` を使う。
形式はバージョン付きの `GRN2` 形式の状態データで、アルゴリズムの識別子、エンディアン、系列の識別（`StreamIdentity`）、位置、CRC-32C を含み、プラットフォームやポインタ幅に依存しない。
復元は検査と識別子の一致を確かめてから状態を置き換える。
SciOxide はプロセスや OS のエントロピーを読まない。
`SeedableRng::seed_from_entropy` は呼び出し側が渡した `scioxide_core::EntropySource` だけを使う。

## 標本の一括生成と状態の扱い

標本の生成には三つの形がある。

| 形 | 呼び出し | 出力 | 失敗時 |
|---|---|---|---|
| 一つの標本 | `law.sample(rng)` | 値を返す | 消費したワードは消費されたまま |
| 所有した出力を返す | `law.sample_n(rng, n)` | `Vec` を返す | 出力は返らない。生成器は消費したワードの分だけ進んだまま |
| 呼び出し側の出力に書く | `law.sample_n_into(rng, policy, output, workspace)` | `output` に書く | `policy` の二つの方針に従う |

所有値を返す API は方針も作業領域も取らない。
準乱数の `points`、`sample_indices`、`latin_hypercube`、`poisson_disk`、`BrownianBridgePlan::apply` も同じ所有値を返す API で、配列をその場で並べ替える `shuffle` も方針と作業領域を取らない。
これらが失敗すると、生成器は消費したワードの分だけ進んだまま残る。
失敗の後に生成器を戻したいときは、呼び出しの前に `SnapshotGenerator::snapshot` を取るか、呼び出し側の出力に書く形に巻き戻しの方針を渡す。

呼び出し側の出力に書く形（`sample_n_into`、`shuffle_in_place`、`QuasiRng::points_into`）は `SamplingPolicy` を取り、生成器を受け取る形では生成器の直後に置く。
`SamplingPolicy` は二つの独立な方針の組で、`SamplingPolicy::rollback(OutputPolicy::Atomic)` のように作る。
出力方針 `OutputPolicy::Atomic` は成功したときだけ全体を出力に反映し、`Incremental` は完了した標本（ベクトル値なら行）を順に出力に反映する。
状態方針は失敗したときに生成器を戻す `Rollback`（`SnapshotGenerator` を実装する生成器が必要）と、消費をそのまま残す `AdvanceOnError` で、`SamplingPolicy::rollback` と `SamplingPolicy::advance_on_error` がそれぞれを選ぶ。
方針には既定値がなく、呼び出し側が二つを明示する。
棄却された提案もワードを消費するので、成功した一括生成は同じ境界で一つずつ `sample` を呼んだ場合と同じ列を作る。
空の一括生成はスナップショットを取らず、ワードも消費しない。

ベクトル値の分布（`MultivariateNormal`、`Dirichlet`、`Multinomial` など）は `sample`、行単位の `sample_n` と `sample_n_into` を持つ。
ベクトル値・行列値の分布、円周・方向の分布、汎用標本化器は、ルート生成器を進めずに標本ごとの系列から書く `sample_indexed_into(root, output, workspace, cx)` も持つ。
この形の結果は `ExecutionContext` の実行順序に依存しない。

## 作業領域と要件の問い合わせ

呼び出し側の出力に書く形は、再利用できる `SamplingWorkspace` を受け取る。
大きさは次の手順で決める。

```text
let requirements = policy.workspace_requirements(SamplingRequest::scalars(n))?; // 必要量
workspace.try_reserve(&requirements)?;                                         // 確保
workspace.check(&requirements)?;                                               // Sufficient か NeedsGrowth
let workspace = policy.workspace(SamplingRequest::rows(n, width))?;            // 上の二つを一度に
```

`Atomic` は一括生成全体（$n \times$ 幅の要素）を一時的に置く。
`Incremental` は、幅が 2 以上なら書きかけの行を見せないために 1 行分を置き、スカラーなら何も置かない。
`SamplingRequirements` は出力型の要素数、binary64 の補助領域（`Dirichlet` は `f32` 出力でも binary64 で計算する）、バイト数の上限を持つ。
方針の要件には上限がなく、分布の `LawOptions::max_bytes` が実行時に保持容量へ適用される。
所有値を返す API の `sample_n` も、出力のバイト数が分布の上限を超えれば標本を作る前に `ResourceLimit` を返し、バイト数の計算があふれれば `SizeOverflow` を返す。
容量が足りない作業領域は、一括生成が標本を作る前に伸ばす。
要件どおりに確保した作業領域を使えば、成功した一括生成はメモリ領域を確保しない。

準備で大きさが決まる作業領域は `workspace()` だけで作る。
`PoissonDisk`、同時確率の Plan、適応棄却の標本化器がこの形である。
`BrownianBridgePlan` の要求は `()` である。
`latin_hypercube_into` は作業領域を出力の長さまで自分で伸ばすので、再利用した作業領域では 2 回目から確保しない。
QMC の輸送アダプターの `workspace()` は座標の領域を準備し、出力の一時領域は `SamplingPolicy` の要件に従って伸びる。
有限標本の両側 KS 分布は点 $x$ ごとの `KolmogorovRequirements` で `KolmogorovWorkspace` を確かめ、伸ばさずに使う。

## 棄却と作業量の上限

標本化の中の棄却ループと段階的な探索は、どの分布でも 1,024 候補で止まり、`ConvergenceFailure` を返す。
これは上限であり、通常の受理確率では到達しない。
計数、円周・方向、多変量、行列、検定統計量の分布と `Rice`、`IrwinHall`、`Mixture` は、一つの標本が要求した一様乱数ワード（入れ子の標本化と失敗した要求を含む）を `LawOptions::sample_word_budget` で数える。
角度の分布（`VonMises` など）はワードの代わりに浮動小数点の一様乱数の要求を数え、準備した計数の標本化器（`BinomialSampler` など）は準備元の分布の上限を使う。
標本化の中の決定論的な探索と入れ子の反復的な特殊関数は `work_budget` を共有し、残量を超える評価を始めない。
乱数のワードにはこれとは別に一標本あたりの上限を使う。
汎用棄却法も候補は 1,024 個までで、その設定 `UniversalSamplingOptions` は密度の評価回数、浮動小数点の乱数の呼び出し回数（`rng_calls`）、包絡の節点数、バイト数を制限する。

`LawOptions` は数値計算を伴う分布の精度とリソースの上限をまとめる。

| 設定 | 既定値 | 意味 |
|---|---|---|
| `tolerance` | 絶対・相対とも $\sqrt{\varepsilon}$ | 求積、級数、数値逆算の要求精度。相対成分は $[64\varepsilon, 0.1)$ でなければならず、外れると構築時に `InvalidInput` |
| `work_budget` | 65,536 | 一回の準備、問い合わせ、モーメント計算の作業量（漸化式の更新、被積分関数の評価） |
| `sample_word_budget` | 65,536 | 一つの標本が要求できるワードの数 |
| `max_bytes` | 64 MiB | 分布が確保するメモリ領域（保持する母数、返す `Vec`、内部の領域、作業領域の容量）の一つずつに掛かる上限。呼び出し側が渡す出力は数えない。超えると `ResourceLimit` |
| `execution_policy` | 逐次 | `sample_indexed_into` の行の並べ方。各行が自分の系列を使うので結果は変わらない |

ここでの誤差は推定値であり、証明付きの限界ではない。
作業量、ワード数、候補数の上限に達した計算は値を返さず、`ConvergenceFailure` になる。

## エラーの分類

| 分類（`kind()`） | 主な原因 |
|---|---|
| `InvalidInput` | `LawOptions` の許容誤差の範囲外、`sample_indices` の $k > n$、上限 0 の `uniform_index`、範囲外の値を返す利用者の生成器、状態のバイト列の不正（理由 `Malformed`、`UnsupportedConfiguration`、`Inconsistent`） |
| `NonFinite` | NaN や無限大の座標と母数 |
| `DomainError` | 母数の定義域の違反と $[0, 1]$ の外の確率（理由 `OutsideDomain`）、存在しないモーメント（`Undefined`） |
| `ConvergenceFailure` | 1,024 候補の上限、ワード・作業量の上限、数値逆算の未収束 |
| `NotImplemented` | 上に有界でない整数分布の $Q(1)$、正確な整数演算を超える計数 |
| `OutOfBounds` | 範囲を超える前進や後退、`BoundedSubstream` の範囲外の読み出し |
| `ResourceLimit`、`AllocationFailure`、`SizeOverflow` | バイト数の上限、確保の失敗、大きさの計算の桁あふれ |
| `DimensionMismatch` | 出力・作業領域の長さが設計や分布と合わない（`latin_hypercube_into`、`PoissonDisk::generate_into`、QMC の輸送、ベクトル値の分布の `sample_n_into` と `sample_indexed_into`）。乱数を使う前、状態や出力を変える前に検査する |
| `NumericalInstability` | 表せない結果（$\mu + \sigma z$ のオーバーフロー、0 や範囲外に丸められる正の標本の `Underflow`・`Overflow`）、計算した定数や行列の破綻（`Breakdown`）、打ち消しで精度を確かめられない分散（`Cancellation`）。母数の数学的な違反は `DomainError` のまま |

エラーは呼び出し元の識別子を持たない。
分類は `e.kind()` で、引数や理由は `e.view()` で読む。

## まとめ

`scioxide-random` の添字の抽出、整数の分布、Ziggurat 法の速い経路は一様乱数ワードを使い、逆関数法などが使う浮動小数点の一様乱数はネイティブ出力ワード一つから端点 1 を含まずに作られる。
エンジンの整数列と QMC 点列は、アルゴリズムとデコーダの規約のバージョンが同じならシードと呼び出し列で再現されるが、分布の標本化アルゴリズムはこの保証の外にある。
所有値を返す API の一括生成は失敗すると生成器を進めたまま残し、呼び出し側の出力に書く形は `SamplingPolicy` で出力方針と状態方針を別々に選び、作業領域を要件から一度確保して再利用する。
棄却は 1,024 候補、分布の数値計算は `LawOptions` の上限で止まり、どちらも `ConvergenceFailure` として示される。
