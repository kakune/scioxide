計算機実験や多次元の積分では、$d$ 個の入力を同時に変える $n$ 点の設計を作る。
独立な一様点は塊と隙間を作り、各軸を $m$ 分割した格子は点の数が $m^d$ に増える。
このページは点の数を次元と独立に選べる ラテンハイパーキューブ設計、点集合の一様さを測るディスクレパンシー、ディスクレパンシーを下げる交換の局所探索を説明する。
1 次元の層化抽出の分散は[一様な添字・置換・層化抽出](oxref:random-sampling-stratified-variance)で扱った。

## ラテンハイパーキューブ設計

ラテンハイパーキューブ（LHS、McKay–Beckman–Conover 1979）は、各軸を $n$ 個の等しい層 $[s/n, (s+1)/n)$ に分け、どの軸でもどの層にもちょうど一点が入るように $n$ 点を置く。
$j$ 番目の軸の値は、軸ごとに独立な一様置換 $\pi_j$ と層の中の位置 $U_{ij} \in [0, 1)$ で

$$
x_{ij} = \frac{\pi_j(i) + U_{ij}}{n}, \qquad i = 0, \dots, n-1,\quad j = 1, \dots, d
$$

と作る。
各点は単独では $[0, 1)^d$ 上で一様に分布するので、平均 $\hat{I} = \frac{1}{n}\sum_i f(\mathbf{x}_i)$ は $I = \int_{[0,1)^d} f$ の不偏推定量である。

関数を ANOVA 分解して $f(\mathbf{x}) = I + \sum_j f_j(x_j) + r(\mathbf{x})$ と書く。
$f_j$ は変数 $x_j$ だけによる主効果で、$r$ は交互作用の残りである。
Stein（1987）は、$f$ が二乗可積分なら

$$
\mathrm{Var}\,\hat{I}_{\mathrm{LHS}} = \frac{1}{n}\Bigl(\sigma_f^2 - \sum_{j=1}^d \sigma_j^2\Bigr) + o\!\left(\frac{1}{n}\right), \qquad \sigma_j^2 = \mathrm{Var}\,f_j(U)
$$

を示した。
単純な Monte Carlo 法の分散 $\sigma_f^2/n$ から主効果の分散が除かれ、関数が各変数の和に近いほど利得が大きい。
交互作用だけを持つ関数では、利得は $o(1/n)$ の項に限られる。

`latin_hypercube(n, d, rng)` は各軸の層に一点ずつ値を置き、軸ごとに Fisher–Yates で並べ替えた設計を、$n$ 行 $d$ 列の行優先の `Vec` で返す。
計算量は $O(nd)$ で、層の中の位置に $nd$ 個の一様乱数ワードを、並べ替えにおよそ $nd$ 個の一様乱数ワードを使う。
`latin_hypercube_with_options(n, d, rng, options)` は設定 `LatinHypercubeOptions` を取り、設計とレポート `LatinHypercubeReport` の組を返す。
`LatinHypercubeOptions::with_centered(true)` を渡すと $U_{ij} = 1/2$（層の中点）になり、層の中の位置にワードを使わない。
$n = 0$、$d = 0$、`stagnation_limit` が 0 のときは `InvalidInput` である。
`f32` の出力で $n > 2^{24}$ のときも隣り合う層の境界を区別できないので `InvalidInput` で、$nd$ が `usize` を超えると `SizeOverflow` である。
二つの所有値を返す API は失敗すると何も返さず、生成器は消費したワードの分だけ進んだまま残る。

`latin_hypercube_into(d, rng, state, options, out, workspace, cx)` は設計全体を作業領域に作り、成功したときだけ `out` に写す。
設計の行は置換で互いに結び付いており、途中まで書いた行は単独では使えないからである。
点の数は `out.len() / d` で、`out` の長さが $d$ の倍数でなければ、乱数を使う前に `DimensionMismatch` を返す。
作業領域が `out` より小さければ伸ばすので、使い回せば 2 回目からは確保しない。
`state` は `AdvanceOnError` か `Rollback` で、失敗したときに生成器を戻すかを決める。

## ディスクレパンシーの尺度

点集合の一様さはディスクレパンシーで測る。
スター・ディスクレパンシーは原点を角に持つ箱に入る点の割合と箱の体積の差の上限で、[Koksma–Hlawka の不等式](oxref:random-qmc-koksma-hlawka)で積分の誤差を抑える。
上限を正確に求めるのは高次元で難しいので、`discrepancy(points, d, method)` は箱についての差の二乗平均に当たる $L^2$ 型のディスクレパンシーを、Hickernell の閉形式

$$
D^2 = C^d - \frac{2}{n} \sum_{i} \prod_{k} g(x_{ik}) + \frac{1}{n^2} \sum_{i, j} \prod_{k} h(x_{ik}, x_{jk})
$$

で評価する。
点 $\mathbf{x}_i = (x_{i1}, \dots, x_{id})$ は行優先で $n$ 行 $d$ 列に並べ、$a = |x - 1/2|$、$b = |y - 1/2|$、$\delta = |x - y|$ とする。
評価は $O(n^2 d)$ の時間で、作業用のメモリ領域を確保しない。

| `DiscrepancyMethod` | $C$ | $g(x)$ | $h(x, y)$ | 返す値 |
|---|---|---|---|---|
| `Centered`（中心化 $L^2$） | $13/12$ | $1 + a/2 - a^2/2$ | $1 + a/2 + b/2 - \delta/2$ | $D^2$ |
| `WrapAround`（周期的） | $4/3$、定数項は $-(4/3)^d$ | $0$ | $3/2 - \delta + \delta^2$ | $D^2$ |
| `Mixture`（Zhou–Fang–Ning） | $19/12$ | $5/3 - a/4 - a^2/4$ | $15/8 - a/4 - b/4 - 3\delta/4 + \delta^2/2$ | $D^2$ |
| `L2Star`（Warnock） | $1/3$ | $(1 - x^2)/2$ | $1 - \max(x, y)$ | $D$（平方根） |

`Centered` は各座標を $1/2$ のまわりで反転しても変わらず、`WrapAround` は点を 1 を法としてずらしても変わらない。
`L2Star` は原点を角に持つ箱 $[0, \mathbf{t})$ についての二乗平均の平方根で、上限で定義するスター・ディスクレパンシーではない。
独立な一様点では $g$ の平均が $C$、$h(x, \cdot)$ の平均が $g(x)$ になるので、中心化の値の期待値は $\mathrm{E}[D^2] = \bigl((5/4)^d - (13/12)^d\bigr)/n$ である。

座標は閉区間 $[0, 1]$ に入らなければならず、外れた座標、空の点集合、行の途中で切れた配列は `InvalidInput`、NaN と無限大は `NonFinite` である。
$D^2$ は $C^d$ 程度の項の差なので、一様な設計では打ち消しが大きく、丸めで小さな負の値になりうる。
項の絶対値の和の $64\varepsilon(d + 1)$ 倍に収まる負の値は 0 に置き換え、それを超える負の値は `InvalidInput` にする。
和は正確に累積して最後に一度だけ丸めるので、誤差は $C^d$ と項の大きさの数 ulp に収まる。

`CenteredDiscrepancy` は点と和を保持し、`evaluate_append` で行を加えた場合の値を状態を変えずに $O(nd)$ で返し、`append` で確定する。
メモリ領域は構築時に `capacity` 点分を確保し、満杯の状態の `append` は `InvalidInput` である。
`geometric_discrepancy(points, d, method)` は点の間の最小距離（`MinimumDistance`）か、Prim 法で求めた最小全域木の辺の長さの平均（`MeanSpanningTreeEdge`、点の数だけの距離を内部で確保する）を返す。
値が大きいほど点は離れている。
`geometric_discrepancy` は 2 点以上を要求し、座標の範囲の規則は `discrepancy` と同じである。

## 交換による改善

LHS は一次元の射影しか層化しないので、すべての点が対角線の近くに並ぶような設計も起こりうる。
`with_max_proposals(M)` で $M$ を正にすると、生成した設計を貪欲な局所探索で改善する。
各提案は軸と二つの行を一様に選び、その軸の二つの値を交換する。
交換は各軸の値の集合を変えないので、Latin の性質を保つ。
中心化 $L^2$ ディスクレパンシーの二乗 $D^2$ が厳密に下がる提案だけを受理し、それ以外は元に戻す。

$D^2$ は点ごとの和 $\sum_i \prod_k g(x_{ik})$ と点の組の和 $\sum_{i,j} \prod_k h(x_{ik}, x_{jk})$ から決まる。
交換で変わるのは二つの行を含む項だけなので、提案ごとにその項を和から引き、交換後の項を足す。
一提案の計算量は $O(nd)$ で、全体の再計算の $O(n^2 d)$ を避ける。
和は正確に累積しているので、差分で更新した値は `discrepancy` で全体を計算し直した値とビット単位で一致する。

`stagnation_limit`（既定 100）回続けて改善しなければ `LatinHypercubeTermination::Stagnation`、$M$ 回の提案を使い切れば `BudgetExhausted`、提案を求めなければ（$M = 0$、既定）`Complete` で終わる。
同じ行を二度選んだ提案も改善しない提案として数える。
`latin_hypercube_into` は最初の抽出の前と各提案の前に `ExecutionContext` の取り消しと期限を確かめる。
最初の抽出の前に見つけたら `ExecutionStopped` のエラーを返し、提案の前に見つけたら `Stopped` で止まる。
どの終了でも設計は $n$ 点すべてを持ち、`Stopped`・`BudgetExhausted`・`Stagnation` はそこまでに受理した交換を含む設計を返す。
`LatinHypercubeReport` は終了の理由、提案数（棄却を含む）、交換の前と後の $D^2$ を返し、提案を求めなかった場合の $D^2$ は `None` である。
これは局所探索であり、最適な設計に達したことは示さない。

次のセルは同じシードから $n$ 点 $d$ 次元の設計を作り、提案の上限 $M$ を 0 から 3,000 まで変える。
入力は点数 $n$、次元 $d$、停滞の上限、シードである。
同じシードでは交換の前の設計と提案の列が共通なので、$M$ を増やしても $D^2$ は増えない。
表は終了の理由、提案数、レポートの $D^2$、`discrepancy` で計算し直した $D^2$ との差、各軸で一つの層に入った点の最大数を示す。
計算し直した値と層の数え上げはレポートと独立な検算で、図の破線は独立な一様点の期待値 $\bigl((5/4)^d - (13/12)^d\bigr)/n$ である。
セルの結論は最大の上限 $M = 3000$ の終了の理由で、局所探索は上限か停滞で止まるので outcome は partial になる。

```rust
//| id: random-lhs-swap-optimization
//| ref: random-lhs-swap-optimization
//| title: ラテンハイパーキューブの交換による改善を提案の上限ごとに比べる
//| run: reactive
//| crates: [scioxide-core, scioxide-random]
//| inputs:
//|   points: {"type":"range","label":"点数 n [点]","min":8,"max":64,"step":8,"value":32}
//|   dimension: {"type":"range","label":"次元 d [-]","min":2,"max":6,"step":1,"value":3}
//|   stagnation: {"type":"range","label":"停滞の上限 [回]","description":"続けて改善しない提案がこの回数に達すると止まる。","min":10,"max":400,"step":10,"value":100}
//|   seed: {"type":"range","label":"乱数のシード [-]","min":1,"max":1000,"step":1,"value":5}
//| cases:
//|   - {"id":"short-patience","label":"停滞の上限 10","description":"停滞の上限が短いと、少ない提案で Stagnation になる。","inputs":{"stagnation":10}}
//|   - {"id":"six-dimensions","label":"n = 64、d = 6","description":"次元を上げても Latin の性質と差分の一致は保たれる。","inputs":{"points":64,"dimension":6}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"budgets","path":"/rows/0/1","equals":"Complete"}
//|       - {"artifact":"budgets","path":"/rows/1/1","equals":"BudgetExhausted"}
//|       - {"artifact":"budgets","path":"/rows/1/2","range":{"min":10,"max":10}}
//|       - {"artifact":"budgets","path":"/rows/6/5","range":{"min":0,"max":0}}
//|       - {"artifact":"budgets","path":"/rows/6/6","range":{"min":1,"max":1}}
//|       - {"path":"/outputs/2/state","equals":"partial"}
//|   - case: short-patience
//|     expect:
//|       - {"artifact":"budgets","path":"/rows/6/1","equals":"Stagnation"}
//|       - {"artifact":"budgets","path":"/rows/6/5","range":{"min":0,"max":0}}
//|   - case: six-dimensions
//|     expect:
//|       - {"artifact":"budgets","path":"/rows/6/5","range":{"min":0,"max":0}}
//|       - {"artifact":"budgets","path":"/rows/6/6","range":{"min":1,"max":1}}
use scioxide_core::RealScalar;
use scioxide_random::{
    DiscrepancyMethod, LatinHypercubeOptions, LatinHypercubeTermination, SeedableRng, SplitMix64,
    discrepancy, latin_hypercube_with_options,
};

let sci4 = serde_json::json!({ "notation": "scientific", "significantDigits": 4 });
let (n, d) = (points.round() as usize, dimension.round() as usize);
let limit = stagnation.round() as usize;
// 独立な一様点の中心化 D² の期待値 ((5/4)^d − (13/12)^d)/n（解析値）。
let iid =
    (RealScalar::powi(1.25, d as i32) - RealScalar::powi(13.0 / 12.0, d as i32)) / n as f64;
let (mut rows, mut curve) = (Vec::new(), Vec::new());
let mut before = None;
let mut last = (LatinHypercubeTermination::Complete, 0, None);
for budget in [0_usize, 10, 30, 100, 300, 1000, 3000] {
    let options = LatinHypercubeOptions::default()
        .with_max_proposals(budget)
        .with_stagnation_limit(limit);
    let mut rng = SplitMix64::from_seed(seed.round() as u64);
    let (design, report) = latin_hypercube_with_options::<f64, _>(n, d, &mut rng, options)
        .map_err(|e| e.to_string())?;
    // 独立検算 1: 出力に反映された設計の D² を全体から計算し直す。
    let direct =
        discrepancy(&design, d, DiscrepancyMethod::Centered).map_err(|e| e.to_string())?;
    let gap = report
        .final_discrepancy()
        .map(|value| (value - direct).abs());
    // 独立検算 2: 各軸で一つの層 [s/n, (s+1)/n) に入った点の最大数（Latin なら 1）。
    let mut crowded = 0;
    for axis in 0..d {
        let mut counts = vec![0_usize; n];
        for row in design.chunks_exact(d) {
            counts[(row[axis] * n as f64) as usize] += 1;
        }
        crowded = counts.into_iter().fold(crowded, usize::max);
    }
    if let (Some(initial), Some(after)) =
        (report.initial_discrepancy(), report.final_discrepancy())
    {
        before = Some(initial);
        curve.push([budget as f64, after]);
    }
    last = (
        report.termination(),
        report.proposals(),
        report.final_discrepancy(),
    );
    rows.push((
        budget,
        format!("{:?}", report.termination()),
        report.proposals(),
        report.initial_discrepancy(),
        report.final_discrepancy(),
        gap,
        crowded,
    ));
}
let mut annotations = vec![serde_json::json!({
    "kind": "line",
    "axis": "y",
    "value": iid,
    "label": "独立な一様点の期待値",
    "style": { "lineType": "dashed" }
})];
if let Some(value) = before {
    annotations.push(serde_json::json!({
        "kind": "line",
        "axis": "y",
        "value": value,
        "label": "交換の前の D²"
    }));
}
emit_line_chart!(
    &vec![serde_json::json!({
        "name": "交換の後の D²",
        "points": curve,
        "style": { "showSymbol": true, "symbol": "circle" }
    })],
    options = &serde_json::json!({
        "xLabel": "提案の上限 M [回]",
        "yLabel": "中心化 L² ディスクレパンシーの二乗 D² [-]",
        "xType": "log",
        "yType": "log",
        "annotations": annotations
    })
);
let columns = serde_json::json!([
    { "key": "0", "label": "提案の上限 M [回]", "type": "integer" },
    { "key": "1", "label": "終了の理由" },
    { "key": "2", "label": "提案数 [回]", "type": "integer" },
    { "key": "3", "label": "交換の前の D² [-]", "type": "number", "format": sci4, "nullText": "なし" },
    { "key": "4", "label": "交換の後の D² [-]", "type": "number", "format": sci4, "nullText": "なし" },
    { "key": "5", "label": "|レポート − 再計算| [-]", "type": "number", "format": sci4, "nullText": "なし" },
    { "key": "6", "label": "一つの層の最大点数 [点]", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "budgets" })
);
// 結論: 最大の上限 M = 3000 の局所探索は上限か停滞で止まる（partial）。
let (termination, proposals, after) = last;
let mut outcome = Outcome::partial("交換による局所探索が提案の上限か停滞で止まった")
    .explanation("D² は局所探索の結果で、最適な設計であることは示さない。")
    .status(format!("{termination:?}"))
    .diagnostic("提案数", proposals as f64, None);
if let (Some(initial), Some(value)) = (before, after) {
    outcome = outcome
        .diagnostic("交換の前の D²", initial, None)
        .diagnostic("交換の後の D²", value, None);
}
emit_outcome!(outcome);
```

既定の入力（$n = 32$、$d = 3$、停滞の上限 100、シード 5）では、交換の前の $D^2 = 2.471 \times 10^{-3}$ が、$M = 100$ で $1.790 \times 10^{-3}$、$M = 1000$ で $1.347 \times 10^{-3}$ に下がる。
$M = 3000$ では 1,112 回の提案で `Stagnation` になり、$D^2 = 1.342 \times 10^{-3}$ は交換の前の 54% である。
交換の前の値でも、独立な一様点の期待値 $2.130 \times 10^{-2}$ の約 9 分の 1 で、層化だけでディスクレパンシーの大部分が除かれている。
どの行でもレポートの $D^2$ と `discrepancy` で計算し直した値の差は 0 で、各軸の一つの層に入る点は 1 個だけである。
停滞の上限を 10 にすると 40 回の提案で止まり、$D^2$ は $2.204 \times 10^{-3}$ に留まる。
$n = 64$、$d = 6$ では $1.001 \times 10^{-2}$ から 2,676 回の提案で $4.338 \times 10^{-3}$ まで下がる。
$D^2$ の減り方は提案の上限に対して次第に鈍り、停滞の上限が探索の打ち切りを決める。

## まとめ

ラテンハイパーキューブは点の数を次元と独立に選べる層化で、主効果の分散を除くので、関数が各変数の和に近いほど単純な Monte Carlo 法より誤差が小さい。
`discrepancy` は四種類の $L^2$ ディスクレパンシーを閉形式で正確に累積して評価し、`L2Star` 以外は二乗の値を返すので、比べるときは同じ尺度と同じ点数にそろえる。
`with_max_proposals` による交換は Latin の性質を保ったまま差分の更新で $D^2$ を下げ、レポートの値は全体を計算し直した値とビット単位で一致する。
終了の理由は `Stagnation` か `BudgetExhausted` が普通で、どちらも使える設計を返すが、最適な設計であることは示さない。
