生成器が返す整数には二種類ある。
ネイティブ出力ワード（native word）は `next_u32` と `next_u64` が返す参照実装どおりの整数で、値域が $2^{32}$ や $2^{64}$ の全体とは限らない。
一様乱数ワード（uniform word）は `next_uniform_u32` と `next_uniform_u64` が返す、全ビットが一様な整数である。
このページはネイティブ出力ワードの値域が狭い生成器で一様乱数ワードをどう作るか、それが正確に一様である理由、ネイティブ出力ワードを何個使うかを説明する。
生成器ごとの漸化式は[生成器の種類](oxref:random-prng-families)にある。

## ネイティブ出力ワードの値域

ネイティブ出力ワードの値域は生成器ごとに次のように決まる。

| 生成器 | ネイティブ出力ワードの値域 $r$ | `next_u32` | `next_u64` |
|---|---|---|---|
| `SplitMix64`、`Xoshiro256StarStar`、`Pcg64`、`Lcg64`、`Philox4x64`、`Threefry4x64` | $2^{64}$ | 64 ビットのネイティブ出力ワードの一部（`Lcg64`、`Philox4x64`、`Threefry4x64` は上位、ほかは下位の 32 ビット） | ネイティブ出力ワード一つ |
| `Xoshiro128StarStar`、`Mt19937`、`Taus2`、`Taus113`、`Gfsr4` | $2^{32}$ | ネイティブ出力ワード一つ | ネイティブ出力ワード二つを下位から並べる |
| `Mrg32k3a` | $2^{32} - 209$（ネイティブ出力ワードは $1$ 以上 $2^{32} - 209$ 以下） | ネイティブ出力ワード一つ | ネイティブ出力ワード二つを下位から並べる |
| `Mrg`、`Cmrg` | $2^{31} - 1$（ネイティブ出力ワードは $0$ 以上 $2^{31} - 1$ 未満） | ネイティブ出力ワード一つ | ネイティブ出力ワード二つを下位から並べる |
| `Ranlux`、`Ranlxs` | $2^{24}$ | ネイティブ出力ワード一つ | ネイティブ出力ワード二つを下位から並べる |
| `Ranlxd` | $2^{48}$ | ネイティブ出力ワードの上位 32 ビット | ネイティブ出力ワード一つ（48 ビット） |

値域が $2^{31}$ 以下の生成器（`Mrg`、`Cmrg`、`Ranlux`、`Ranlxs`）では、`next_u32` の最上位ビットはいつも 0 で、`next_u64` でも二つの 32 ビットの半分それぞれの最上位ビットが 0 になる。
`Mrg32k3a` のネイティブ出力ワードは最上位ビットも使うが、0 と $2^{32} - 208$ 以上の値の計 209 個を取らない。
値域の狭いワードを $2^{32}$ や $2^{64}$ で割って $[0, 1)$ に写すと、値は区間の一部にしか届かない。
添字の抽出、整数の分布、Ziggurat 法の速い経路など、整数のビットをそのまま使う標本化は、ネイティブ出力ワードではなく一様乱数ワードを読む。

## 一様乱数ワードの作り方

`next_uniform_u32` は、値域 $r$ が $2^{32}$ より狭いネイティブ出力ワードを $r$ 進法の桁として集める。
ネイティブ出力ワードの下限が 1 の `Mrg32k3a` は、ネイティブ出力ワードから 1 を引いて $0$ 以上 $r$ 未満の桁にする。
$r^k \ge 2^{32}$ となる最小の $k$ について、$k$ 個のネイティブ出力ワード $d_0, \dots, d_{k-1}$ から

$$
v = \sum_{j=0}^{k-1} d_j\, r^j \qquad (0 \le v < r^k)
$$

を作る（最初のネイティブ出力ワードが最下位の桁）。
$L = r^k - (r^k \bmod 2^{32})$ を $2^{32}$ の倍数のうち $r^k$ 以下で最大のものとし、$v \ge L$ なら $k$ 個すべてを捨てて引き直す。
受理した $v$ の下位 32 ビット $v \bmod 2^{32}$ を返す。

このワードが正確に一様である理由は次のとおりである。
桁 $d_j$ が独立に $\{0, \dots, r-1\}$ 上で一様なら、$v$ は $\{0, \dots, r^k - 1\}$ 上で一様である。
受理した $v$ は $\{0, \dots, L - 1\}$ 上で一様で、$L$ は $2^{32}$ の倍数なので、どの値 $w$ にも $v \equiv w \pmod{2^{32}}$ となる $v$ がちょうど $L / 2^{32}$ 個ずつある。
したがって返すワードは $\{0, \dots, 2^{32} - 1\}$ 上で一様である。

受理の確率は $a = L / r^k$ で、引き直しの回数は幾何分布に従う。
一様乱数ワード一つが使うネイティブ出力ワードの個数（遷移数）の期待値は $k/a$ である。
値域が $2^{32}$ のネイティブ出力ワードでは $k = 1$、$a = 1$ で、`next_u32` と同じ値を返す。
値域が $2^b$（$b > 32$）の `Ranlxd` は、48 ビットのネイティブ出力ワードの上位 32 ビットをそのまま一様乱数ワードにする。

64 ビットの一様乱数ワード `next_uniform_u64` は同じ規則を $2^{64}$ について使う。
値域 $2^{24}$、$2^{31} - 1$、$2^{32} - 209$ のネイティブ出力ワードでは $k = 3$ 個、`Ranlxd` の 48 ビットのネイティブ出力ワードでは $k = 2$ 個を一組にする。
値域 $2^{32}$ のネイティブ出力ワードは二つを並べるだけで、64 ビットのネイティブ出力ワードは一つをそのまま返す。

引き直しは 1,024 回で打ち切り、それを超えると `ConvergenceFailure`（理由 `IterationLimit`）を返す。
使ったネイティブ出力ワードは消費したまま残り、位置はそれも数える。
一様乱数ワードの途中の桁を次の呼び出しのために持ち越さないので、生成器の状態だけで、ネイティブ出力ワード・一様乱数ワード・浮動小数点数を混ぜた呼び出しの列を再現できる。

## 浮動小数点の一様乱数との関係

`Rng::next_float` が返す $[0, 1)$ の浮動小数点数は、一様乱数ワードではなくネイティブ出力ワード一つを写した値である。
たとえば `Mrg32k3a` の `f64` は $z_n / (m_1 + 1)$（$z_n$ はネイティブ出力ワード、$m_1 = 2^{32} - 209$）、`Ranlux` の値は 24 ビットのネイティブ出力ワードを左に詰めて写した値になる。
したがって値域の狭い生成器では、一様乱数ワードを使う標本化の列と、浮動小数点数を使う標本化（逆関数法など）の列は、同じシードからでも一標本が読むネイティブ出力ワードの個数が異なる。
浮動小数点への写し方と開区間 $(0, 1)$ の扱いは[一様乱数ワードと浮動小数点への変換](oxref:random-algorithms-uniform-conversion)にある。

次のセルは古典的な生成器と `Mrg32k3a`、`Ranlxd` でネイティブ出力ワードと一様乱数ワードを $N$ 個ずつ作る。
入力はシードとワード数 $N$（1,000〜20,000）である。
表はネイティブ出力ワードの値域 $r$、`next_u32` の最大値、ネイティブ出力ワードと一様乱数ワードの最上位ビットが 1 の割合、一様乱数ワードの割合を標準化した値 $z = (\hat{q} - 1/2)/\mathrm{SE}$、一様乱数ワード一つが使った遷移数とその理論値 $k/a$ を示す。
一様なワードでは最上位ビットが 1 の割合の期待値は $1/2$、標準誤差は $\mathrm{SE} = 1/(2\sqrt{N})$ である。
理論値 $k/a$ は $r$ から手で計算した独立検算である。

```rust
//| id: random-native-uniform-words
//| ref: random-native-uniform-words
//| title: ネイティブ出力ワードと一様乱数ワードの最上位ビットと消費遷移数を比べる
//| run: reactive
//| crates: [scioxide-core, scioxide-random]
//| inputs:
//|   seed: {"type":"range","label":"乱数のシード [-]","min":1,"max":1000,"step":1,"value":7}
//|   words: {"type":"range","label":"ワード数 N [ワード]","description":"ネイティブ出力ワードと一様乱数ワードをそれぞれ N 個作る。","min":1000,"max":20000,"step":1000,"value":10000}
//| cases:
//|   - {"id":"many-words","label":"N = 20000、シード 123","description":"ワード数を増やすと最上位ビットの割合の標準誤差は 0.0035 になる。","inputs":{"seed":123,"words":20000}}
//|   - {"id":"few-words","label":"N = 1000","description":"ワード数が少ないと割合のばらつきは標準誤差 0.0158 程度に広がる。","inputs":{"words":1000}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"words","path":"/rows/0/6","range":{"min":1,"max":1}}
//|       - {"artifact":"words","path":"/rows/3/6","range":{"min":2,"max":2.0001}}
//|       - {"artifact":"words","path":"/rows/4/3","range":{"min":0,"max":0}}
//|       - {"artifact":"words","path":"/rows/4/6","range":{"min":2,"max":2.0001}}
//|       - {"artifact":"words","path":"/rows/6/3","range":{"min":0,"max":0}}
//|       - {"artifact":"words","path":"/rows/8/6","range":{"min":1,"max":1}}
//|       - {"artifact":"words","path":"/rows/4/5","range":{"min":-4,"max":4}}
//|       - {"artifact":"words","path":"/rows/6/5","range":{"min":-4,"max":4}}
//|   - case: many-words
//|     expect:
//|       - {"artifact":"words","path":"/rows/5/3","range":{"min":0,"max":0}}
//|       - {"artifact":"words","path":"/rows/5/5","range":{"min":-4,"max":4}}
//|       - {"artifact":"words","path":"/rows/7/6","range":{"min":2,"max":2}}
//|   - case: few-words
//|     expect:
//|       - {"artifact":"words","path":"/rows/4/5","range":{"min":-4,"max":4}}
//|       - {"artifact":"words","path":"/rows/4/6","range":{"min":2,"max":2.01}}
use scioxide_core::RealScalar;
use scioxide_random::{
    BitGenerator, Cmrg, Gfsr4, Mrg, Mrg32k3a, Mt19937, Ranlux, Ranlxd, Ranlxs, SeedableRng, Taus2,
};

// (生成器, 値域 r, next_u32 の最大値, ネイティブ出力ワードと一様乱数ワードの上位ビット率, 一様乱数ワードの z, 遷移数/ワード, 理論値)
type Row = (String, u64, u32, f64, f64, f64, f64, f64);

// 独立検算: 値域 r のネイティブ出力ワードから 32 ビットの一様乱数ワードを作るときの遷移数の期待値 k / a。
fn expected_transitions(radix: u64) -> f64 {
    let (target, r) = (1_u128 << 32, u128::from(radix));
    let (mut range, mut digits) = (r, 1);
    while range < target {
        range *= r;
        digits += 1;
    }
    let accepted = range - range % target;
    digits as f64 * (range as f64 / accepted as f64)
}

fn measure<R>(name: &str, radix: u64, seed: u64, n: usize) -> Result<Row, String>
where
    R: SeedableRng + BitGenerator,
{
    let mut native = R::from_seed(seed);
    let mut uniform = R::from_seed(seed);
    let (mut maximum, mut native_top, mut uniform_top) = (0_u32, 0_usize, 0_usize);
    for _ in 0..n {
        let word = native.next_u32().map_err(|e| e.to_string())?;
        maximum = maximum.max(word);
        native_top += (word >> 31) as usize;
        let word = uniform.next_uniform_u32().map_err(|e| e.to_string())?;
        uniform_top += (word >> 31) as usize;
    }
    let consumed = uniform.position().ok_or("位置が追跡されていない")?;
    let rate = uniform_top as f64 / n as f64;
    let z = (rate - 0.5) / (0.5 / RealScalar::sqrt(n as f64));
    Ok((
        name.to_string(),
        radix,
        maximum,
        native_top as f64 / n as f64,
        rate,
        z,
        consumed as f64 / n as f64,
        expected_transitions(radix),
    ))
}

let seed = seed.round() as u64;
let n = words.round() as usize;
let full = 1_u64 << 32;
let rows = vec![
    measure::<Mt19937>("Mt19937", full, seed, n)?,
    measure::<Taus2>("Taus2", full, seed, n)?,
    measure::<Gfsr4>("Gfsr4", full, seed, n)?,
    measure::<Mrg32k3a>("Mrg32k3a", full - 209, seed, n)?,
    measure::<Mrg>("Mrg", (1 << 31) - 1, seed, n)?,
    measure::<Cmrg>("Cmrg", (1 << 31) - 1, seed, n)?,
    measure::<Ranlux>("Ranlux", 1 << 24, seed, n)?,
    measure::<Ranlxs>("Ranlxs", 1 << 24, seed, n)?,
    measure::<Ranlxd>("Ranlxd", 1 << 48, seed, n)?,
];
let rate4 = serde_json::json!({ "fractionDigits": 4 });
let z2 = serde_json::json!({ "fractionDigits": 2 });
let digits6 = serde_json::json!({ "significantDigits": 6 });
let columns = serde_json::json!([
    { "key": "0", "label": "生成器" },
    { "key": "1", "label": "ネイティブ出力ワードの値域 r", "type": "integer" },
    { "key": "2", "label": "next_u32 の最大値", "type": "integer" },
    { "key": "3", "label": "ネイティブ出力ワードの最上位ビット率 [-]", "type": "number", "format": rate4 },
    { "key": "4", "label": "一様乱数ワードの最上位ビット率 [-]", "type": "number", "format": rate4 },
    { "key": "5", "label": "一様乱数ワードの z [-]", "type": "number", "format": z2 },
    { "key": "6", "label": "一様乱数ワードあたりの遷移数 [遷移]", "type": "number", "format": digits6 },
    { "key": "7", "label": "理論値 k/a [遷移]", "type": "number", "format": digits6 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "words" })
);
```

既定の入力（シード 7、$N = 10\,000$）では、`Mrg`、`Cmrg`、`Ranlux`、`Ranlxs` のネイティブ出力ワードの最上位ビット率は 0 である。
同じ生成器の一様乱数ワードの最上位ビット率は SE $= 0.005$ の幅で $1/2$ のまわりに散らばり、9 行の $z$ は $-0.94$ から $2.00$ に入る。
9 行が独立なら、どれかの $|z|$ が 2 以上になる確率は $1 - 0.9545^9 \approx 0.34$ なので、`Cmrg` の $z = 2.00$ は統計的な揺らぎで説明できる。
`Mt19937`、`Taus2`、`Gfsr4` は値域が $2^{32}$ なので一様乱数ワード一つが 1 遷移を使い、`Ranlxd` も上位 32 ビットを使うので 1 遷移で済む。
`Mrg32k3a`、`Mrg`、`Cmrg`、`Ranlux`、`Ranlxs` は 2 遷移を使い、理論値 $k/a$ との差は $10^{-14}$ 未満である。
受理の確率 $a$ は $r = 2^{24}$ で 1、$r = 2^{31} - 1$ で $1 - r^{-2}$、$r = 2^{32} - 209$ で $1 - 43\,681/r^2$ なので、引き直しはほとんど起きない。
`Ranlxd` の `next_u32` の最大値 4,294,800,509 は 48 ビットのネイティブ出力ワードの上位 32 ビットで、ネイティブ出力ワードの最上位ビット率は 0.5047 である。

## まとめ

ネイティブ出力ワードは参照実装どおりの整数で、`Ranlux`、`Ranlxs`、`Mrg`、`Cmrg`、`Mrg32k3a` では値域が $2^{32}$ に満たない。
全ビット一様な整数が要るときは `next_uniform_u32` か `next_uniform_u64` を使えば、ネイティブ出力ワードの桁を集める棄却法により正確に一様なワードが得られる。
値域の狭い生成器の 32 ビットの一様乱数ワードはネイティブ出力ワードを約 2 個、64 ビットの一様乱数ワードは約 3 個使うので、位置から消費量を見積もるときはこの係数を掛ける。
一様乱数ワードを使う標本化と浮動小数点数を使う標本化では一標本が読むネイティブ出力ワードの個数が異なり、同じシードでも列は一致しない。
