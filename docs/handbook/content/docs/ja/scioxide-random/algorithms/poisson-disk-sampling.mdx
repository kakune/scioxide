独立な一様点は近接した組を含みやすく、ラテンハイパーキューブも軸ごとの層化しか保証しない。
点どうしの最小距離そのものを設計の条件にしたいとき、たとえば試料の採取点や画像の標本点を一定の間隔以上離したいときは、Poisson 円板標本を使う。
このページは `scioxide-random` の Bridson の方法、作業量の上限、終了の理由と、得られた点集合がどこまで詰まっているかの点検を説明する。

## Poisson 円板標本

Poisson 円板標本は箱 $B = [\mathbf{l}, \mathbf{u}] \subset \mathbb{R}^d$ の中で、どの二点も半径 $r$ 以上離れた無作為な点集合である。
それ以上どこにも点を置けない集合を極大と呼ぶ。
素朴な方法（dart throwing）は一様な候補を引いて既存のすべての点と比べ、近すぎれば捨てる。
点が増えるほど候補の大部分が捨てられ、極大に近づくと一点を置くのに多数の候補が要る。

Bridson（2007）の方法は、既存の点の近くから候補を引くことでこの無駄を減らす。

1. 最初の点を箱の中で一様に引き、活動中の点の一覧に入れる。
2. 活動中の点 $\mathbf{p}$ を一様に一つ選び、円環 $r \le \|\mathbf{x} - \mathbf{p}\| < 2r$ から候補を最大 $k$ 回引く。
3. 箱の中にあり、受理済みのどの点からも $r$ 以上離れた候補を受理し、活動中の一覧に加える。
4. $k$ 回とも失敗したら $\mathbf{p}$ を活動中の一覧から外し、2 に戻る。

候補は円環の体積について一様に引く。
方向は標準正規ベクトル $\mathbf{z}$ を正規化した $\mathbf{z}/\|\mathbf{z}\|$ で、正規分布の回転不変性から球面上で一様である。
半径 $\rho$ の分布関数は $(\rho^d - r^d)/((2r)^d - r^d)$ なので、一様乱数 $u$ から $\rho = r\,(1 + u(2^d - 1))^{1/d}$ と逆変換で作る。

近傍の検査には一辺 $r/\sqrt{d}$ の背景格子を使う。
升目の対角線の長さが $r$ なので、各升目には受理済みの点が高々一つしか入らず、升目ごとに点の番号を一つ持てば足りる。
候補から距離 $r$ 未満の点は、候補の座標から各軸に $\pm r$ の範囲の升目（丸めに備えて両側に 1 升目ずつ広げる）にしかない。
その升目の数と受理済みの点の数を比べ、少ない方を走査する。
$N$ 点を置く期待の計算量は $O(kN)$ である。

`PoissonDisk::new(lower, upper, r, capacity)` は 1〜6 次元の箱で、点の数の上限を `capacity` とする設計を準備し、背景格子の升目の数 $\prod_j \lceil (u_j - l_j)\sqrt{d}/r \rceil$ を検査する。
`PoissonDisk::with_options(lower, upper, r, capacity, options)` は作業量の上限を `PoissonDiskOptions` で変える。

| `PoissonDiskOptions` の項目 | 既定値 | 意味 |
|---|---|---|
| `candidates_per_point` | 30 | 活動中の点ごとに試す候補の数 $k$（正） |
| `max_proposals` | $2^{20}$ | 候補の総数の上限（最初の点と箱の外に出た候補を含む） |
| `max_grid_cells` | $2^{20}$ | 背景格子の升目の数の上限（正） |
| `max_distance_checks` | $2^{24}$ | 近傍の作業量の上限 |

近傍の作業量は訪ねた格子の升目（空の升目を含む）と比較した点をどちらも 1 として数えるので、距離を計算した回数より多い。
次元が 1〜6 でない、`upper` の長さが違う、$r$ が正の有限値でない、境界が有限でないか $l_j \ge u_j$、`capacity` か $k$ が 0、格子が `max_grid_cells` を超える、のどれかに当たる設計は構築時に `InvalidInput` になる。

## 生成と作業領域

`generate(rng)` は受理した点を行優先に並べた `Vec` とレポート `PoissonDiskReport` の組を返し、呼び出しのたびに出力と作業領域を確保する。
`generate_into(rng, state, out, work, cx)` は `design.workspace()` で作った `PoissonDiskWorkspace` を受け取り、受理した点を `out` の先頭の行に書く。
作業領域は `capacity` 点分の点、活動中の一覧、背景格子を持ち、同じ作業領域を繰り返し渡すと生成はメモリ領域を確保しない。
出力の長さ（`output_elements()` $= \texttt{capacity} \times d$）や作業領域の大きさが設計と合わなければ、状態と出力を変える前に `DimensionMismatch` を返す。
点は互いに依存するので、設計は作業領域の中で作り、成功したときだけ `out` に写す。
受理した点より後ろの行は書かない。

`cx` は最初の抽出の前と各候補の前に取り消しと期限を確かめ、最初の抽出の前なら `ExecutionStopped` のエラー、候補の前なら `Stopped` の終了になる。
`generate_into` がエラーで終わった場合は出力を変えず、生成器は `state`（`AdvanceOnError` か `Rollback`）に従う。
`generate` は失敗すると生成器を進めたまま残す。
`poisson_disk(lower, upper, r, capacity, rng)` は既定の設定で `generate` を行い、受理した点だけを返す一回きりの形である。
活動中の点が尽きて `capacity` に届かない終了は成功として扱い、上限による停止（`BudgetExhausted`）は `ConvergenceFailure` のエラーにする。

`PoissonDiskReport` は終了の理由 `termination()`、受理した点の数 `points()`、候補の数 `proposals()`、近傍の作業量 `distance_checks()` を返し、出力の先頭 `points()` 行が受理した点である。
終了の理由 `PoissonDiskTermination` は次の四つで、outcome では `Complete` を satisfied、残りを partial に対応させる。

| 終了の理由 | 意味 |
|---|---|
| `Complete` | `capacity` 個の点を受理した |
| `ActiveListExhausted` | 活動中の点がなくなった。これ以上置けないこと（極大性）の証明ではない |
| `BudgetExhausted` | 候補の総数か近傍の作業量の上限に達した。`max_proposals` が 0 なら点を一つも置かない |
| `Stopped` | `generate_into` に渡した `ExecutionContext` が候補の前に取り消しか期限を返した |

どの終了でも、受理した点は互いに $r$ 以上離れており、上限で止まった設計もそこまでの点として使える。

## 点の数の上下界と極大性の点検

点の数 $N$ には、箱の体積から決まる上下界がある。
単位正方形 $[0, 1]^2$ で考える。
点を中心とする半径 $r/2$ の円板は互いに重ならず、一辺 $1 + r$ の正方形に収まるので、どの $r$ 離れた集合でも $N \le 4(1+r)^2/(\pi r^2)$ である。
集合が極大なら、半径 $r$ の円板が正方形を覆う（覆われない点があれば、そこに新しい点を置ける）ので、$N \ge 1/(\pi r^2)$ である。
したがって $N$ が下界を下回れば、その集合は極大ではない。

被覆の度合いは正方形の中の点から最も近い標本点までの距離の最大値（被覆半径）で測れる。
極大な集合の被覆半径は $r$ 未満である。
格子点で最近接距離の最大値を求めると、被覆半径の近似（真の値以下）が得られる。

次のセルは単位正方形に Poisson 円板標本を `generate_into` で作り、終了の理由とレポートの数を表に示す。
入力は半径 $r$、候補の数 $k$、点の数の上限 `capacity`、候補の総数の上限、シードである。
独立な検算は `geometric_discrepancy` で計算した最小距離と $r$ の比、間隔 $1/128$ の格子で求めた被覆半径と $r$ の比、$N$ の上下界である。
図は受理した点と、被覆半径を与えた格子点（最も大きな空隙の中心）を示す。

```rust
//| id: random-poisson-disk-termination
//| ref: random-poisson-disk-termination
//| title: Poisson 円板標本の終了の理由と点の数の上下界を確かめる
//| run: reactive
//| crates: [scioxide-core, scioxide-random]
//| inputs:
//|   radius: {"type":"range","label":"半径 r [-]","min":0.04,"max":0.2,"step":0.01,"value":0.08}
//|   candidates: {"type":"range","label":"候補の数 k [個]","description":"活動中の点ごとに試す候補の数。Bridson の既定は 30。","min":1,"max":60,"step":1,"value":30}
//|   capacity: {"type":"range","label":"点の数の上限 capacity [点]","min":20,"max":1000,"step":20,"value":1000}
//|   budget: {"type":"select","label":"候補の総数の上限","options":["2²⁰（既定）","2,000","500"],"value":"2²⁰（既定）"}
//|   seed: {"type":"range","label":"乱数のシード [-]","min":1,"max":1000,"step":1,"value":7}
//| cases:
//|   - {"id":"few-candidates","label":"k = 3","description":"候補を少ししか試さないと活動中の点が早く尽き、大きな空隙が残る。","inputs":{"candidates":3}}
//|   - {"id":"small-capacity","label":"capacity = 40","description":"上限に届くと Complete で止まる。","inputs":{"capacity":40}}
//|   - {"id":"small-budget","label":"候補 500 個","description":"候補の総数が尽きると BudgetExhausted で止まる。","inputs":{"budget":"500"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"report","path":"/rows/0/0","equals":"ActiveListExhausted"}
//|       - {"artifact":"report","path":"/rows/0/1","range":{"min":50,"max":232}}
//|       - {"artifact":"checks","path":"/rows/0/0","range":{"min":1}}
//|       - {"artifact":"checks","path":"/rows/0/1","range":{"min":1,"max":1.5}}
//|       - {"path":"/outputs/3/state","equals":"partial"}
//|   - case: few-candidates
//|     expect:
//|       - {"artifact":"report","path":"/rows/0/0","equals":"ActiveListExhausted"}
//|       - {"artifact":"checks","path":"/rows/0/0","range":{"min":1}}
//|       - {"artifact":"checks","path":"/rows/0/1","range":{"min":2}}
//|   - case: small-capacity
//|     expect:
//|       - {"artifact":"report","path":"/rows/0/0","equals":"Complete"}
//|       - {"artifact":"report","path":"/rows/0/1","range":{"min":40,"max":40}}
//|       - {"path":"/outputs/3/state","equals":"satisfied"}
//|   - case: small-budget
//|     expect:
//|       - {"artifact":"report","path":"/rows/0/0","equals":"BudgetExhausted"}
//|       - {"artifact":"report","path":"/rows/0/2","range":{"min":500,"max":500}}
use scioxide_core::{ExecutionContext, RealScalar};
use scioxide_random::{
    AdvanceOnError, GeometricDiscrepancy, PoissonDisk, PoissonDiskOptions, PoissonDiskTermination,
    SeedableRng, SplitMix64, geometric_discrepancy,
};

let fixed3 = serde_json::json!({ "fractionDigits": 3 });
let fixed1 = serde_json::json!({ "fractionDigits": 1 });
let max_proposals = match budget.as_str() {
    "2,000" => 2_000,
    "500" => 500,
    _ => 1 << 20,
};
let options = PoissonDiskOptions::default()
    .with_candidates_per_point(candidates.round() as usize)
    .with_max_proposals(max_proposals);
let design = PoissonDisk::with_options(
    &[0.0_f64; 2],
    &[1.0; 2],
    radius,
    capacity.round() as usize,
    options,
)
.map_err(|e| e.to_string())?;
// 作業領域と出力は設計から一度だけ作り、同じ設計の生成で使い回せる。
let mut work = design.workspace().map_err(|e| e.to_string())?;
let mut out = vec![0.0_f64; design.output_elements()];
let mut rng = SplitMix64::from_seed(seed.round() as u64);
let report = design
    .generate_into(
        &mut rng,
        AdvanceOnError,
        &mut out,
        &mut work,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;
let n = report.points();
let points = &out[..2 * n];
// 独立検算 1: 最小距離と r の比（定義から 1 以上）。
let separation = if n >= 2 {
    let minimum = geometric_discrepancy(points, 2, GeometricDiscrepancy::MinimumDistance)
        .map_err(|e| e.to_string())?;
    Some(minimum / radius)
} else {
    None
};
// 独立検算 2: 間隔 1/128 の格子点から最も近い標本点までの距離の最大値（被覆半径の近似）。
let (mut hole, mut center) = (0.0_f64, [0.0_f64; 2]);
for a in 0..=128 {
    for b in 0..=128 {
        let (x, y) = (f64::from(a) / 128.0, f64::from(b) / 128.0);
        let nearest = points
            .chunks_exact(2)
            .map(|p| (p[0] - x) * (p[0] - x) + (p[1] - y) * (p[1] - y))
            .fold(f64::INFINITY, f64::min);
        if nearest > hole {
            (hole, center) = (nearest, [x, y]);
        }
    }
}
let hole = RealScalar::sqrt(hole);
// 独立検算 3: 被覆による下界 1/(πr²) と、半径 r/2 の円板の詰め込みによる上界 4(1 + r)²/(πr²)。
let area = std::f64::consts::PI * radius * radius;
let (lower, upper) = (1.0 / area, 4.0 * (1.0 + radius) * (1.0 + radius) / area);
let accepted: Vec<[f64; 2]> = points.chunks_exact(2).map(|p| [p[0], p[1]]).collect();
emit_chart!(
    serde_json::json!({
        "kind": "scatter",
        "xLabel": "x [-]",
        "yLabel": "y [-]",
        "xMin": 0.0,
        "xMax": 1.0,
        "yMin": 0.0,
        "yMax": 1.0,
        "dataZoom": true,
        "tooltip": true,
        "series": [
            { "name": "受理した点", "points": accepted },
            { "name": "最も大きな空隙の中心", "points": [center], "style": { "symbol": "diamond" } }
        ]
    }),
    metadata = serde_json::json!({ "id": "points" })
);
let report_columns = serde_json::json!([
    { "key": "0", "label": "終了の理由" },
    { "key": "1", "label": "受理した点 N [点]", "type": "integer" },
    { "key": "2", "label": "候補の数 [個]", "type": "integer" },
    { "key": "3", "label": "近傍の作業量 [回]", "type": "integer" }
]);
let termination = report.termination();
emit_table_with_columns!(
    report_columns,
    vec![(
        format!("{termination:?}"),
        n,
        report.proposals(),
        report.distance_checks(),
    )],
    metadata = serde_json::json!({ "id": "report" })
);
let check_columns = serde_json::json!([
    { "key": "0", "label": "最小距離 / r [-]", "type": "number", "format": fixed3, "nullText": "2 点未満" },
    { "key": "1", "label": "被覆半径 / r [-]", "type": "number", "format": fixed3 },
    { "key": "2", "label": "極大なら N ≥ [点]", "type": "number", "format": fixed1 },
    { "key": "3", "label": "常に N ≤ [点]", "type": "number", "format": fixed1 }
]);
emit_table_with_columns!(
    check_columns,
    vec![(separation, hole / radius, lower, upper)],
    metadata = serde_json::json!({ "id": "checks" })
);
let outcome = if termination == PoissonDiskTermination::Complete {
    Outcome::satisfied("capacity 個の点を受理した")
} else {
    Outcome::partial("capacity に届く前に生成が止まった")
        .explanation("受理した点は互いに r 以上離れている。極大かどうかは被覆半径で確かめる。")
};
emit_outcome!(
    outcome
        .status(format!("{termination:?}"))
        .diagnostic("受理した点", n as f64, None)
        .diagnostic("候補の数", report.proposals() as f64, None)
        .diagnostic("被覆半径 / r", hole / radius, None)
);
```

既定の入力（$r = 0.08$、$k = 30$、`capacity` 1,000、シード 7）では、99 点を受理したところで活動中の点が尽き、`ActiveListExhausted` で止まる。
候補は 3,578 個、近傍の作業量は 50,221 回で、最小距離は $r$ の 1.001 倍である。
点の数 99 は上界 232.0 と、極大な集合の下界 49.7 のあいだにある。
しかし格子で求めた被覆半径は $r$ の 1.187 倍で、図の菱形の位置（$x = 0$、$y = 0.859$）にはもう一点を置ける。
大きな空隙は箱の縁や角に残りやすい。
縁の近くでは円環の一部が箱の外にはみ出し、その候補は捨てられるので、縁に沿った狭い空き領域には候補が届きにくい。
`ActiveListExhausted` が極大性の証明でないことは、この数値で確かめられる。

$k = 3$ にすると 278 個の候補で 60 点しか置けず、被覆半径は $r$ の 3.03 倍に広がる。
`capacity` を 40 にすると 486 個の候補で 40 点に達して `Complete`（satisfied）になり、候補の総数を 500 にすると 40 点を置いたところで `BudgetExhausted` になる。
どちらの終了でも最小距離は $r$ 以上で、置いた点はそのまま使える。
`scioxide-random` は空隙に点を足す後処理を提供しないので、空隙を小さくしたいときは $k$ を増やすか、呼び出し側で被覆半径を測って点を足す。

## まとめ

Poisson 円板標本は最小距離 $r$ を設計の条件とし、Bridson の方法は背景格子と円環からの候補で、$N$ 点を期待 $O(kN)$ の作業で置く。
`PoissonDiskOptions` の候補の総数と近傍の作業量は生成の作業を上から抑え、尽きたときは `BudgetExhausted` でそこまでの点を返す。
`Complete` だけが `capacity` に達したことを示し、`ActiveListExhausted` は極大性を示さないので、被覆半径か点の数の下界で詰まり具合を確かめる。
同じ設計で何度も生成するときは `workspace()` を一度作って `generate_into` に渡し、一回きりの生成には `poisson_disk` を使う。
