`scioxide-random` は、擬似乱数生成器と系列の分割、機能ごとのトレイトを持つ確率分布、分布の合成と汎用標本化器、添字と置換の抽出、準乱数点列、ラテンハイパーキューブなどの設計、Brownian 橋を出力に反映する。
このガイドは目的から API となる項目を示し、公開されている 260 項目を用途別の表にまとめる。
表の項目名のリンクは、docs.rs の 0.1.0 の API リファレンスを指す。

---

## 目的別の API

| したいこと | API となる項目 | 表 |
|---|---|---|
| シードから再現できる乱数を作る | `Pcg64`、`SplitMix64`、`Rng`、`SeedableRng` | [生成器と系列](engines-and-streams/) |
| 並列のワーカーに重ならない系列を割り当てる | `SplittableRng`、`StreamPartitioner`、`BoundedSubstream`、`Philox4x64` | [生成器と系列](engines-and-streams/) |
| 生成器の状態を保存して再開する | `SerializableState`、`StreamIdentity`、`SnapshotGenerator` | [生成器と系列](engines-and-streams/)、[標本抽出と一括生成](sampling-and-batches/) |
| 配列を並べ替える、添字や要素を選ぶ | `shuffle`、`shuffle_in_place`、`choose`、`sample_indices`、`uniform_index`、`WeightedSampler` | [標本抽出と一括生成](sampling-and-batches/) |
| 一括生成の出力と状態の扱いを選ぶ | `SamplingPolicy`、`OutputPolicy`、`Rollback`、`AdvanceOnError`、`SamplingWorkspace` | [標本抽出と一括生成](sampling-and-batches/) |
| 確率分布の密度・裾・分位点を求める | `Density`、`Cdf`、`Survival`、`Quantile`、`InverseSurvival`、`log_interval_probability`、`invert_log_probability` | [分布の機能と合成](law-protocols-and-combinators/) |
| 分布を打ち切る、混ぜる、変換する | `Affine`、`Truncated`、`Mixture`、`Transformed`、`LogTransformed`、`Histogram`、`OrderStatistic` | [分布の機能と合成](law-protocols-and-combinators/) |
| 組込みにない密度から標本を作る | `UserDensity`、`ConcaveDensityFn`、`BoundedDensityFn`、`LogTailsFn`、`AdaptiveRejectionSampler`、`RatioUniformsSampler`、`InversionSampler` | [分布の機能と合成](law-protocols-and-combinators/) |
| 連続分布を使う | `Normal`、`Exponential`、`Gamma`、`Beta`、`StudentT` など、連続分布の表の 62 種類（F 分布・非心分布・円周の分布は別の表） | [連続分布](continuous-laws/) |
| 計数・角度・検定統計量の分布を使う | `Binomial`、`Poisson`、`CountDistribution`、`VonMises`、`FisherF` | [計数・円周・検定統計量の分布](count-circular-and-test-laws/) |
| 正規ベクトルや行列の分布と同時確率を使う | `MultivariateNormal`、`Dirichlet`、`Wishart`、`MultivariateProbabilityPlan` | [多変量・行列の分布](multivariate-and-matrix-laws/) |
| 低食い違い点列と設計を作る | `QmcPlan`、`QmcReplicatePlan`、`latin_hypercube`、`PoissonDisk`、`BrownianBridgePlan` | [準乱数と標本設計](quasi-random-and-designs/) |

暗号用途の乱数生成器、ハードウェアや OS のエントロピーの読み取り、乱数の統計的検定の一式（TestU01 のような検定群）は提供しない。
エントロピーが必要なら、呼び出し側が `scioxide_core::EntropySource` を実装して `SeedableRng::seed_from_entropy` に渡す。

## 型の関係

- **生成器**：`BitGenerator` がネイティブ出力ワードと一様乱数ワードを返し、組込みの生成器はどれも `Rng`（`f32` と `f64`）も実装して、ネイティブ出力ワードを $[0, 1)$ の浮動小数点数にする。
  `Distribution` の標本化と `WeightedSampler` は `Rng` を、`CountDistribution` の標本化、ベクトル・行列の分布、`uniform_index`・`shuffle`・`sample_indices` などの添字の抽出は `BitGenerator` を受け取る。
- **系列**：`SkipAhead`、`JumpableRng`、`SplittableRng` が前進と分割を、`BoundedSubstream` と `StreamPartitioner` が範囲付きの系列を作る。
  保存は `SerializableState`（バイト列）と `SnapshotGenerator`（メモリ上）で別々である。
- **分布**：機能は `Distribution`、`CountDistribution`、`Density`、`Cdf`、`Survival`、`Quantile`、`Mean` などの独立なトレイトで、分布は実装できるものだけを実装する。
  数値計算を伴う分布は `new(母数…)` で既定の `LawOptions` を使い、`with_options(母数…, options)` で設定を受け取る。
- **一括生成**：所有値を返す API（`sample_n` など）は方針を取らない。
  呼び出し側の出力に書く形（`sample_n_into` など）は `SamplingPolicy` を取り、これは出力方針 `OutputPolicy` と状態方針（`Rollback` か `AdvanceOnError`）の組で、`SamplingWorkspace` の要件 `SamplingRequirements` を `SamplingRequest` から求める。
- **Plan**：`QmcPlan`、`QmcReplicatePlan`、`BrownianBridgePlan`、`MultivariateProbabilityPlan` と設計 `PoissonDisk` は不変で、`Send + Sync + Clone` である。
  カーソル（`QmcSequence`）と作業領域は呼び出し側が持つ。

## 最小の実行例：三つの形と状態方針

標本は一つずつ作る `sample`、所有した出力を返す `sample_n`、呼び出し側の出力に書く `sample_n_into` の三つの形で作る（[標本の一括生成と状態の扱い](oxref:random-algorithms-batches-and-state)）。
次のセルは `BoundedSubstream` で読めるワード数を制限した生成器を使い、$\mathrm{Uniform}(1, 2)$ の一括生成 `sample_n_into` をワードが尽きるまで繰り返す。
入力は読めるワード数、一回の一括生成の標本数、乱数のシードで、`SplitMix64` は標本一つにワードを一つ使う。
一つ目の表は出力方針と状態方針の四つの組合せごとに、成功した回数、失敗の分類、失敗した回に書き換えた要素の数、終了後の位置、`SamplingPolicy::workspace_requirements` が求めた作業領域の要素数を示す。
同じ表の最後の行は所有値を返す API `sample_n` に一回分の 2 倍の標本を求めた結果である。
二つ目の表は一つずつ作る `sample` の値を、同じシードの最初のワード $w$ から作った $1 + u$（$u$ は `decode_u64` で $w$ を $[0, 1)$ に写した値）と比べる独立検算である。

use scioxide_core::NumericScalar;
use scioxide_random::{
    BitGenerator, BoundedSubstream, Distribution, OutputPolicy, SamplingPolicy, SamplingRequest,
    SeedableRng, SplitMix64, StatePolicy, Uniform, decode_u64,
};

type Source = BoundedSubstream<SplitMix64>;
// (形と方針, 成功した回数, 失敗の分類, 失敗した回に書き換えた要素, 終了後の位置, 作業領域の要素数)
type Row = (
    String,
    usize,
    Option<String>,
    Option<usize>,
    Option<u64>,
    Option<usize>,
);

// 読めるワード数を available に制限した生成器を作る。
fn bounded(seed: u64, available: u64) -> Result<Source, String> {
    BoundedSubstream::for_chunk(&SplitMix64::from_seed(seed), 0, available)
        .map_err(|e| e.to_string())
}

// 範囲付き系列の位置は available 以下なので u64 に収まる。
fn position(rng: &Source) -> Result<Option<u64>, String> {
    rng.position()
        .map(u64::try_from)
        .transpose()
        .map_err(|e| e.to_string())
}

// ワードが尽きるまで sample_n_into を繰り返し、失敗した回の出力と位置を調べる。
fn run<P: StatePolicy<Source>>(
    name: &str,
    policy: SamplingPolicy<P>,
    seed: u64,
    available: u64,
    n: usize,
) -> Result<Row, String> {
    let law = Uniform::new(1.0_f64, 2.0).map_err(|e| e.to_string())?;
    let mut rng = bounded(seed, available)?;
    let request = SamplingRequest::scalars(n);
    let staged = policy
        .workspace_requirements(request)
        .map_err(|e| e.to_string())?
        .elements();
    let mut workspace = policy.workspace(request).map_err(|e| e.to_string())?;
    let mut output = vec![0.0_f64; n];
    let mut successes = 0;
    loop {
        let before = output.clone();
        match law.sample_n_into(&mut rng, policy, &mut output, &mut workspace) {
            Ok(()) => successes += 1,
            Err(error) => {
                let written = output.iter().zip(&before).filter(|(a, b)| a != b).count();
                return Ok((
                    name.to_string(),
                    successes,
                    Some(format!("{:?}", error.kind())),
                    Some(written),
                    position(&rng)?,
                    Some(staged),
                ));
            }
        }
    }
}

// 所有値を返す API sample_n を一度呼び、成否と終了後の位置を調べる。方針は取らない。
fn owned(name: &str, seed: u64, available: u64, n: usize) -> Result<Row, String> {
    let law = Uniform::new(1.0_f64, 2.0).map_err(|e| e.to_string())?;
    let mut rng = bounded(seed, available)?;
    let (successes, kind) = match law.sample_n(&mut rng, n) {
        Ok(_) => (1, None),
        Err(error) => (0, Some(format!("{:?}", error.kind()))),
    };
    Ok((
        name.to_string(),
        successes,
        kind,
        None,
        position(&rng)?,
        None,
    ))
}

let (seed, available, n) = (seed as u64, available as u64, batch as usize);

既定の入力（読めるワード数 6、一回 4 個、シード 42）では、どの組合せも最初の一括生成は成功し、二回目は 2 個を作ったところで `OutOfBounds` で失敗する。
`Atomic` は失敗した回の出力を一つも書き換えず、`Incremental` は完了した 2 個を出力に反映する。
`Rollback` は位置を二回目の開始時の 4 に戻し、`AdvanceOnError` は消費した 6 を残す。
作業領域は `Atomic` で一括生成全体の 4 要素、スカラーの `Incremental` で 0 要素である。
所有値を返す API `sample_n` に 8 個を求めると 6 ワードでは足りずに失敗して値は返らず、生成器は消費した 6 ワードの位置に残る。
所有値を返す API には状態方針がないので、失敗の後に生成器を戻したいときは `sample_n_into` に `SamplingPolicy::rollback` を渡す。
`sample` の値 1.7415648787718232 は独立検算の $1 + u$ と一致し、差は 0 である。

非既定の入力では境界の振る舞いが変わる。
12 ワードを 3 個ずつ読むと 4 回成功し、5 回目は 1 個も作らずに失敗するので、`Incremental` でも書き換えた要素は 0 個になる。
このとき `sample_n` の 6 個は 12 ワードに収まって成功し、終了後の位置は 6 になる。
4 ワードに 8 個を求めると一回目から失敗し、`Incremental` は作れた 4 個を出力に反映し、`Rollback` は位置を 0 に戻す。

## ブロック関数と生成器のワードの順序

カウンター型生成器のワードは鍵とカウンターから 4 ワードを決める純粋な関数 `philox4x64_block` と `threefry4x64_block` の出力である。
系列の $n$ 番目のワードはカウンター `[⌊n/4⌋, tree_path, stream, subsequence]` のブロックの $n \bmod 4$ 番目のワードになる。
根の系列のカウンターは `[block, tree_path, stream, subsequence]` = `[0, 1, 0, 0]` から始まる（木の経路は番兵 1 だけ）。
次のセルの入力は鍵の下位語で、Philox は鍵 `[key_low, 17]`、Threefry は鍵 `[key_low, 17, 0, 0]` を使う。
セルはこのカウンターのブロックの 4 ワードと、`from_key` で作った生成器が最初に返す 4 ワードを同じ位置どうしで比べ、一致したワードの数を数える。
`seek(0)` で先頭に戻した後に読み直した 4 ワードについても、最初の 4 ワードと一致した数を数える。
表の第 1 ワードの列は64 ビットのワードを `decode_u64` で $[0, 1)$ の値 $u$ に写して示す。

```rust
//| id: random-api-counter-replay
//| ref: random-api-counter-replay
//| title: カウンター型生成器のブロック関数とワードの順序を照合する
//| run: reactive
//| crates: [scioxide-random]
//| inputs:
//|   key_low: {"type":"range","label":"鍵の下位語","description":"Philox は鍵 [key_low, 17]、Threefry は鍵 [key_low, 17, 0, 0] を使う。","min":0,"max":1000,"step":1,"value":42}
//| cases:
//|   - {"id":"zero-key","label":"鍵の下位語 0","description":"鍵の下位語が 0 でも、4 ワードの順序と seek(0) の再現は変わらない。","inputs":{"key_low":0}}
//|   - {"id":"key-1000","label":"鍵の下位語 1000","description":"別の鍵ではブロックのワードが変わるが、生成器との一致は同じ 4 ワードになる。","inputs":{"key_low":1000}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"counter-words","path":"/rows/0/1","approx":{"value":0.9187004133956886,"atol":1e-15}}
//|       - {"artifact":"counter-words","path":"/rows/0/3","equals":4}
//|       - {"artifact":"counter-words","path":"/rows/0/4","equals":4}
//|       - {"artifact":"counter-words","path":"/rows/1/3","equals":4}
//|       - {"artifact":"counter-words","path":"/rows/1/4","equals":4}
//|   - case: zero-key
//|     expect:
//|       - {"artifact":"counter-words","path":"/rows/0/3","equals":4}
//|       - {"artifact":"counter-words","path":"/rows/1/4","equals":4}
//|   - case: key-1000
//|     expect:
//|       - {"artifact":"counter-words","path":"/rows/0/4","equals":4}
//|       - {"artifact":"counter-words","path":"/rows/1/3","equals":4}
use scioxide_random::{
    BitGenerator, Philox4x64, Threefry4x64, decode_u64, philox4x64_block, threefry4x64_block,
};

// 生成器から 4 ワードを読み、読み出しの失敗はそのまま返す。
fn four_words(rng: &mut impl BitGenerator) -> Result<[u64; 4], String> {
    let mut words = [0_u64; 4];
    for word in &mut words {
        *word = rng.next_u64().map_err(|e| e.to_string())?;
    }
    Ok(words)
}

// 二つの 4 ワードの並びで、同じ位置のワードが一致する数を数える。
fn matches(a: &[u64; 4], b: &[u64; 4]) -> usize {
    a.iter().zip(b).filter(|(x, y)| x == y).count()
}

let key = [key_low as u64, 17];
let mut rows = Vec::new();
// Philox: 鍵は 2 ワード。根の系列の最初の 4 ワードはカウンター [0, 1, 0, 0] のブロック。
let mut philox = Philox4x64::from_key(key);
let words = four_words(&mut philox)?;
let block = philox4x64_block([0, 1, 0, 0], key);
philox.seek(0).map_err(|e| e.to_string())?;
let replay = four_words(&mut philox)?;
rows.push((
    "Philox4x64",
    decode_u64::<f64>(block[0]),
    decode_u64::<f64>(words[0]),
    matches(&block, &words),
    matches(&replay, &words),
));
// Threefry: 鍵は 4 ワード。
let key4 = [key[0], key[1], 0, 0];
let mut threefry = Threefry4x64::from_key(key4);
let words = four_words(&mut threefry)?;
let block = threefry4x64_block([0, 1, 0, 0], key4);
threefry.seek(0).map_err(|e| e.to_string())?;
let replay = four_words(&mut threefry)?;
rows.push((
    "Threefry4x64",
    decode_u64::<f64>(block[0]),
    decode_u64::<f64>(words[0]),
    matches(&block, &words),
    matches(&replay, &words),
));
// 第 1 ワードは decode_u64 で [0, 1) の値 u に写して示す（上位 53 ビットが一致すれば同じ値）。
let digits = serde_json::json!({ "significantDigits": 17 });
let columns = serde_json::json!([
    { "key": "0", "label": "生成器" },
    { "key": "1", "label": "ブロックの第 1 ワードの u [-]", "type": "number", "format": digits },
    { "key": "2", "label": "生成器の第 1 ワードの u [-]", "type": "number", "format": digits },
    { "key": "3", "label": "ブロックと一致したワード [ワード]（4 語中）", "type": "integer" },
    { "key": "4", "label": "seek(0) 後に一致したワード [ワード]（4 語中）", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "counter-words" })
);
```

どちらの生成器でも 4 ワードすべてがブロックの出力と同じ順序で一致し、`seek(0)` の後に読み直した 4 ワードもすべて一致する。
既定の鍵では Philox の第 1 ワードは 16 進で `eb2ff3465b2d8355`（$u = 0.9187004133956886$）、Threefry の第 1 ワードは `9d98d4300189d615`（$u = 0.6156132332994624$）である。
鍵の下位ワードを 0 や 1000 に変えるとワードの値は変わるが、一致するワードの数は 4 のままである。
カウンター型生成器はこの関数を標本の番号に応じたカウンターで評価するので、位置の移動に過去のワードを必要としない。

## 結果・エラー・診断の読み方

- **エラー**：失敗は `SciOxideError` で返り、`kind()` で分類する。
  母数と確率の定義域の違反は `DomainError`、非有限な値は `NonFinite`、`LawOptions` の許容誤差や $k > n$ のような設定と引数の範囲外は `InvalidInput` である。
  候補 1,024 個やワード数・作業量の上限に達した棄却と数値逆算は `ConvergenceFailure`、範囲外の前進や範囲付き系列の読み出しは `OutOfBounds`、出力や作業領域の長さの不一致は `DimensionMismatch` である。
  0 や範囲外に丸められる標本と、打ち消しで精度を確かめられない分散は `NumericalInstability`、メモリ領域の上限の超過は `ResourceLimit` である（[エラーの分類](oxref:random-algorithms-errors)）。
- **存在しない量**：機能がない量（`Cauchy` の平均）はトレイトを実装せず、母数によって存在しない量（$\nu \le 1$ の Student t の平均）は `DomainError` で理由 `Undefined` を返す。
- **一括生成**：呼び出し側の出力に書く形が失敗したときの出力と生成器の状態は `SamplingPolicy` の二つの方針で決まる。
  所有値を返す API は成功したときだけ値を返し、失敗すると生成器を消費したワードの分だけ進めたまま残す。
- **レポート**：`MultivariateProbabilityReport`、`QmcReplicateEstimate`、`TestStatisticResult` は値と誤差の推定を返し、その誤差は統計的な推定や推定値であって証明付きの限界ではない。
  `InversionReport` は数値逆算の区間、残差と終了状態を、`LatinHypercubeReport` と `PoissonDiskReport` は終了状態と作業量を、`SamplingDiagnostics` は汎用標本化器の作業量を返す。
  `MultivariateProbabilityTermination::AccuracyNotMet` や `PoissonDiskTermination::BudgetExhausted` はエラーではなく終了状態として返るので、結果を使う前に終了状態を読む。
  一回きりの形（`poisson_disk` と分布の `rectangle`）は、これらの終了をエラーとして返す。
- **再現性**：明示したシードと同じ呼び出し列なら、各生成器が返す整数列と浮動小数点数、`seed_sequence`、組込みの QMC 点列は、アルゴリズムとデコーダの規約のバージョンが同じ限り再現される。
  分布の標本化アルゴリズムとその丸め、エントロピーから作ったシードは、この保証の外にある（[再現性の範囲](oxref:random-algorithms-reproducibility)）。
