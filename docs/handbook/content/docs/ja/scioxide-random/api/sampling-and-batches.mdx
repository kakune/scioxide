この表は有限集合からの抽出と、標本の一括生成の失敗時の扱いを決める型をまとめる。
一括生成の出力方針と状態方針は[標本の一括生成と状態の扱い](oxref:random-algorithms-batches-and-state)、作業領域の手順は[作業領域と要件の問い合わせ](oxref:random-algorithms-workspaces)で説明した。

## 添字と置換の抽出

| 項目 | 種別 | 役割 | 仕様の要点 | 解説節 | 実行例 |
|---|---|---|---|---|---|
| [`uniform_index`](https://docs.rs/scioxide-random/0.1.0/scioxide_random/fn.uniform_index.html) | 関数 | $\{0, \dots, n-1\}$ の偏りのない添字 | `uniform_index(n, rng)`。Lemire の棄却で正確に一様。$n \le 2^{32}$ は 32 ビット、それより大きいと 64 ビットの一様乱数ワード。1,024 ワードで `ConvergenceFailure`、$n = 0$ は `InvalidInput`。確保しない。失敗の前に読んだワードは消費したまま残る | [剰余の偏りと Lemire の棄却](oxref:random-sampling-lemire)、[シミュレーションと Wilson 区間](oxref:random-birthday-wilson) | [衝突の確率を正確な式・近似・シミュレーションで比べる](oxref:random-birthday-probability)、[無作為に配ったシードの衝突を数え 64 ビットに当てはめる](oxref:random-birthday-seeds) |
| [`shuffle`](https://docs.rs/scioxide-random/0.1.0/scioxide_random/fn.shuffle.html) | 関数 | Fisher–Yates の置換 | `shuffle(slice, rng)`。どの置換も等確率。`uniform_index` を $n - 1$ 回使い、確保も要素の複製もしない。失敗すると生成器は消費したワードの分だけ進み、配列には入力を並べ替えた途中の状態が残る。全か無かの出力や生成器の巻き戻しには `shuffle_in_place` を使う | [置換と非復元抽出](oxref:random-sampling-permutation) | - |
| [`shuffle_in_place`](https://docs.rs/scioxide-random/0.1.0/scioxide_random/fn.shuffle_in_place.html) | 関数 | 方針の下の Fisher–Yates の置換 | `shuffle_in_place(slice, rng, policy, workspace)`。抽出の列と、成功したときの置換は `shuffle` と同じ。`Atomic` は配列と同じ長さ（2 未満なら 0）の作業領域に要素を複製して並べ替え、失敗しても配列を変えない。`Incremental` は作業領域を使わず、完了した交換を残す。生成器は `policy` の状態方針に従う。作業領域を伸ばせなければ `AllocationFailure` | [置換と非復元抽出](oxref:random-sampling-permutation) | - |
| [`choose`](https://docs.rs/scioxide-random/0.1.0/scioxide_random/fn.choose.html) | 関数 | 一つの要素を一様に選ぶ | `choose(slice, rng)`。空の配列はワードを使わずに `None`。生成器の失敗と棄却の上限を返す | [置換と非復元抽出](oxref:random-sampling-permutation) | [偏りのある壺の取り出しを Fisher と Wallenius の確率質量と比べる](oxref:random-noncentral-hypergeometric-urn) |
| [`sample_indices`](https://docs.rs/scioxide-random/0.1.0/scioxide_random/fn.sample_indices.html) | 関数 | $k$ 個の異なる添字の非復元抽出 | `sample_indices(n, k, rng)` は所有の `Vec` を返す。$k \ge \lfloor n/16 \rfloor$ では部分的な Fisher–Yates（$O(n)$ の作業とメモリ領域、一様に無作為な順序）、それ以外は最大 $4k$ 枠の集合を使う Floyd の方法（期待 $O(k)$、順序は規定しない）。$k > n$ は `InvalidInput`。メモリ領域は最初の抽出の前に確保し、確保できなければワードを使わずに `AllocationFailure`。抽出の途中で失敗すると何も返さず、生成器は進んだまま残る | [置換と非復元抽出](oxref:random-sampling-permutation) | - |
| [`WeightedSampler`](https://docs.rs/scioxide-random/0.1.0/scioxide_random/struct.WeightedSampler.html) | 構造体 | 重みに比例する添字の別名表 | `new(&weights)` は非負で有限な重み（正の重みが一つ以上）を最大値で割ってから補償和で正規化し、$O(n)$ の表を作る。一回の抽出は `uniform_index` と `next_float` を一回ずつ使う。`sample_index(rng)` と `sample(rng, &values)` は確保せず、`sample` は長さの不一致を生成器を進める前に `DimensionMismatch` にする。`sample_n(rng, n)` は所有の `Vec` を一度だけ確保し、`sample_n_into(rng, policy, output, workspace)` は `SamplingPolicy` に従って呼び出し側の出力に書く。重み 0 の添字は返らない。空・負・全零は `InvalidInput`、非有限は `NonFinite`、確保の失敗は `AllocationFailure` | [重み付きの添字とエイリアス法](oxref:random-discrete-alias-method)、[重みから確率へ](oxref:random-weighted-probabilities)、[エイリアス法が各カテゴリの確率を再現する理由](oxref:random-weighted-alias-reason) | [エイリアス法のまれな重み・抽出回数・乱数のシードを動かす](oxref:random-weighted-sampling) |

## 一括生成の方針

| 項目 | 種別 | 役割 | 仕様の要点 | 解説節 | 実行例 |
|---|---|---|---|---|---|
| [`SamplingPolicy`](https://docs.rs/scioxide-random/0.1.0/scioxide_random/struct.SamplingPolicy.html) | 構造体 | 呼び出し側の出力に書く一括生成の方針 | `SamplingPolicy::rollback(output)` と `advance_on_error(output)` で作る `Copy` の値で、既定値はない。出力方針と状態方針は独立。呼び出し側の出力に書く形（`sample_n_into`、`shuffle_in_place`、`points_into`）が取り（生成器を受け取る形では生成器の直後）、所有値を返す API は取らない。検査と作業領域の確保はスナップショットと標本化より前で、空の一括生成は保存も抽出もしない。成功した一括生成は同じ数の一つずつの標本と同じワードを同じ順に読む（棄却した候補も含む）。方針は返したエラーに適用し、panic には適用しない。`output_policy()`、`workspace_requirements(request)`、`workspace(request)` を持つ | [一括生成の状態方針](oxref:random-prng-batch-state-policy)、[標本の一括生成と状態の扱い](oxref:random-algorithms-batches-and-state)、[最小の実行例：三つの形と状態方針](oxref:random-api-minimal-examples) | [失敗した一括生成が出力と生成器に残すものを方針ごとに比べる](oxref:random-batch-state-policy)、[独立な反復で誤差の傾き −1/2 を測る](oxref:random-buffon-convergence)、[標本数を変えて π を推定し信頼区間を求める](oxref:random-buffon-estimate)、[Brownian 橋で軌跡を細分し分散を確かめる](oxref:random-colloid-bridge) |
| [`OutputPolicy`](https://docs.rs/scioxide-random/0.1.0/scioxide_random/enum.OutputPolicy.html) | 列挙型 | 出力への反映の単位 | `Atomic` は成功したときだけ全体を出力に反映する、`Incremental` は完了した標本（ベクトル値なら行、置換なら交換）を順に出力に反映し、後の失敗でも（`Rollback` でも）残る | [一括生成の状態方針](oxref:random-prng-batch-state-policy)、[標本の一括生成と状態の扱い](oxref:random-algorithms-batches-and-state)、[最小の実行例：三つの形と状態方針](oxref:random-api-minimal-examples) | [失敗した一括生成が出力と生成器に残すものを方針ごとに比べる](oxref:random-batch-state-policy)、[独立な反復で誤差の傾き −1/2 を測る](oxref:random-buffon-convergence)、[標本数を変えて π を推定し信頼区間を求める](oxref:random-buffon-estimate)、[Brownian 橋で軌跡を細分し分散を確かめる](oxref:random-colloid-bridge) |
| [`Rollback`](https://docs.rs/scioxide-random/0.1.0/scioxide_random/struct.Rollback.html) | 構造体 | 失敗したら生成器を戻す状態方針 | `SnapshotGenerator` を実装する生成器だけに使える。`SamplingPolicy::rollback` が選び、`latin_hypercube_into` と `PoissonDisk::generate_into` には値として渡す。所有値を返す API は状態方針を取らない | [一括生成の状態方針](oxref:random-prng-batch-state-policy)、[標本の一括生成と状態の扱い](oxref:random-algorithms-batches-and-state)、[標本の形と失敗時の状態](oxref:random-choosing-sample-shape)、[最小の実行例：三つの形と状態方針](oxref:random-api-minimal-examples) | [失敗した一括生成が出力と生成器に残すものを方針ごとに比べる](oxref:random-batch-state-policy)、[受理した採取点の全点対距離と出力範囲を確かめる](oxref:random-poisson-disk-separation)、[ラテンハイパーキューブの交換後も各層が一度ずつ使われるかを確かめる](oxref:random-lhs-marginal-invariants)、[三つの形と二つの状態方針で一様標本を作る](oxref:random-api-batch-forms) |
| [`AdvanceOnError`](https://docs.rs/scioxide-random/0.1.0/scioxide_random/struct.AdvanceOnError.html) | 構造体 | 失敗しても消費したワードを残す状態方針 | スナップショットの機能は要らない。`SamplingPolicy::advance_on_error` が選ぶ。失敗した所有値を返す API が生成器を残す位置と同じ扱い | [一括生成の状態方針](oxref:random-prng-batch-state-policy)、[標本の一括生成と状態の扱い](oxref:random-algorithms-batches-and-state)、[標本の形と失敗時の状態](oxref:random-choosing-sample-shape)、[最小の実行例：三つの形と状態方針](oxref:random-api-minimal-examples) | [Poisson 円板標本の終了の理由と点の数の上下界を確かめる](oxref:random-poisson-disk-termination)、[失敗した一括生成が出力と生成器に残すものを方針ごとに比べる](oxref:random-batch-state-policy)、[三つの形と二つの状態方針で一様標本を作る](oxref:random-api-batch-forms) |
| [`StatePolicy`](https://docs.rs/scioxide-random/0.1.0/scioxide_random/trait.StatePolicy.html) | トレイト | 状態方針の sealed トレイト | `Rollback` と `AdvanceOnError` だけが実装する。`Rollback` は `SnapshotGenerator` の生成器に限られる。`SamplingPolicy<P>` の型引数と、`latin_hypercube_into`、`PoissonDisk::generate_into` の状態方針の引数に使う | [一括生成の状態方針](oxref:random-prng-batch-state-policy) | [失敗した一括生成が出力と生成器に残すものを方針ごとに比べる](oxref:random-batch-state-policy)、[三つの形と二つの状態方針で一様標本を作る](oxref:random-api-batch-forms) |
| [`SnapshotGenerator`](https://docs.rs/scioxide-random/0.1.0/scioxide_random/trait.SnapshotGenerator.html) | トレイト | メモリ上の状態の取得と復元 | 取得は生成器を進めず、同じ生成器への復元は失敗せず確保もしない。組込みの生成器、`BoundedSubstream`、`QmcSequence`、`&mut G` が実装する。所有値を返す API の失敗の後に生成器を戻すには、呼び出し前に `snapshot` を取って `restore_snapshot` で戻す。移植可能な保存は `SerializableState` | [一括生成の状態方針](oxref:random-prng-batch-state-policy) | [失敗した一括生成が出力と生成器に残すものを方針ごとに比べる](oxref:random-batch-state-policy) |

## 作業領域

| 項目 | 種別 | 役割 | 仕様の要点 | 解説節 | 実行例 |
|---|---|---|---|---|---|
| [`SamplingRequest`](https://docs.rs/scioxide-random/0.1.0/scioxide_random/struct.SamplingRequest.html) | 構造体 | 一括生成の形 | `scalars(n)` は $n$ 個のスカラー、`rows(n, width)` は $n$ 行。幅 0 は要件の計算で `InvalidInput`、要素数があふれると `SizeOverflow` | [作業領域と要件の問い合わせ](oxref:random-algorithms-workspaces) | [失敗した一括生成が出力と生成器に残すものを方針ごとに比べる](oxref:random-batch-state-policy)、[独立な反復で誤差の傾き −1/2 を測る](oxref:random-buffon-convergence)、[標本数を変えて π を推定し信頼区間を求める](oxref:random-buffon-estimate)、[Brownian 橋で軌跡を細分し分散を確かめる](oxref:random-colloid-bridge) |
| [`SamplingRequirements`](https://docs.rs/scioxide-random/0.1.0/scioxide_random/struct.SamplingRequirements.html) | 構造体 | 一括生成に必要な一時領域 | `elements()`（`Atomic` は全体、`Incremental` は幅 2 以上で 1 行、スカラーは 0）、`f64_scratch_elements()`（`Dirichlet` の binary64 の補助）、`max_bytes()`（作業領域の容量全体の上限で、`usize::MAX` は上限なし。方針の要件は上限を持たず、分布が実行時に適用する） | [作業領域と要件の問い合わせ](oxref:random-algorithms-workspaces) | - |
| [`SamplingWorkspace`](https://docs.rs/scioxide-random/0.1.0/scioxide_random/struct.SamplingWorkspace.html) | 構造体 | 再利用する一時領域 | `new()` は確保しない。`try_reserve(&requirements)` は容量を伸ばし（上限超過は `ResourceLimit`、確保の失敗は `AllocationFailure`）、容量を手放さない。`check(&requirements)` は `Capacity::Sufficient` か `NeedsGrowth`。一括生成は足りなければ標本化の前に伸ばす。要件どおりなら成功した一括生成は確保しない。失敗後も中身は変わりうるが再利用できる | [作業領域と要件の問い合わせ](oxref:random-algorithms-workspaces) | [ラテンハイパーキューブの交換後も各層が一度ずつ使われるかを確かめる](oxref:random-lhs-marginal-invariants) |
