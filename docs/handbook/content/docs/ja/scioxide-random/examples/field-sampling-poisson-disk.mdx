圃場で土壌の性質を調べるときは、採取点を区画に偏りなく広げ、近すぎる点の組を作らないようにする。
近い二点は似た値を返すので、同じ数の採取で得られる情報が減るからである。
この例題は `PoissonDisk` で、どの二点も半径 $r$ 以上離れた採取点を置く。
設計が約束する最小距離を、設計を作る計算とは別の総当たりの計算で確かめ、点の数を理論の上界と比べる。
Bridson の方法、背景の格子、極大性の点検は[Poisson 円板標本](../../algorithms/poisson-disk-sampling/)で説明した。
各座標の層を一度ずつ使う別の空間充填設計は[ラテンハイパーキューブによる計算機実験の入力設計](../space-filling-designs/)で扱った。

## 圃場の採取点と Poisson 円板標本

1 m 四方の区画 $[0, 1]^2$ [m] に採取点を置き、どの二点も $r$ 以上離す。
このような点集合を Poisson 円板標本と呼ぶ。
`PoissonDisk::with_options(&[0, 0], &[1, 1], r, capacity, options)` は Bridson の方法で点を置く。

1. 最初の点を区画の中に一様に選び、活動中の点の一覧に入れる。
2. 活動中の点を一様に一つ選び、そのまわりの円環 $r \le \rho < 2r$ に面積で一様に分布する候補を最大 $k$ 個引く。
   $k$ は `candidates_per_point`（既定 30）である。
3. 区画の中にあり、受理済みのどの点からも $r$ 以上離れた候補を受理し、一覧に加える。
4. $k$ 個の候補がすべて退けられた点は一覧から外し、一覧が空になるまで 2 に戻る。

近傍の点は一辺 $r/\sqrt{2}$ の背景格子の升目で探す。
升目の対角線が $r$ なので一つの升目には高々一点しか入らず、候補ごとの距離の計算は近くの升目に限られる。
点の数を $N$ とすると、期待される計算量は $O(kN)$ である。
`PoissonDisk` は 1〜6 次元の箱を扱い、$d$ 次元では升目の一辺が $r/\sqrt{d}$、候補は球殻 $r \le \rho < 2r$ に体積で一様に分布する。

## 上限と終了状態

点の数の上限 `capacity` はコンストラクターの引数である。
`PoissonDiskOptions` は、活動点ごとの候補数、候補の総数（`max_proposals`）、格子の升目の数（`max_grid_cells`）、近傍の計算量（`max_distance_checks`）に上限を与える。
近傍の計算量は訪ねた升目と比較した点をどちらも 1 と数える。
升目の数が上限を超える区画と半径は、コンストラクターが `InvalidInput` で拒む。

| 終了状態 | 止まる条件 | セルの結論 |
|---|---|---|
| `Complete` | 点の数が `capacity` に達した | satisfied |
| `ActiveListExhausted` | 活動中の点がなくなった | partial |
| `BudgetExhausted` | 候補の総数か近傍の計算量が上限に達した | partial |
| `Stopped` | `ExecutionContext` の取り消しか期限を候補の前に見つけた | partial |

どの終了状態でも、受理した点はどの二点も $r$ 以上離れている。
`ActiveListExhausted` は Bridson の方法の通常の終わり方だが、まだ点を置ける隙間が残っていないこと（極大性）は保証しない。
そのため、`Complete` 以外はそれまでの設計を返す途中の結果として partial とする。

`PoissonDiskReport` は、終了状態 `termination()`、受理した点の数 `points()`、提案の数 `proposals()`、近傍の計算量 `distance_checks()` を返す。
提案の数は最初の点と区画の外に出た候補も含む。
呼び出し側の出力に書く `generate_into` は受理した点を出力の先頭 `points()` 行に書き、それより後ろの出力を書き換えない。
所有値を返す API の `generate` は受理した点だけを `Vec` で返し、`poisson_disk` は既定の設定で点だけを返す一回きりの形である。
`poisson_disk` だけは `BudgetExhausted` を `ConvergenceFailure` のエラーにする。

## 点の数の上界と独立な一様点

直径 $r$ の円を各点に置くと、円どうしは重ならない。
各円は区画を各辺 $r/2$ ずつ広げた面積 $(1 + r)^2$ の正方形に収まる。
辺が 6 本以下の凸多角形に合同な円を重ならずに詰めたとき、円の面積の合計は多角形の面積の $\pi/(2\sqrt{3})$ 倍（六方最密充填の密度）を超えない（L. Fejes Tóth の定理）。
正方形はこの条件を満たすので

$$
N \cdot \frac{\pi r^2}{4} \le \frac{\pi}{2\sqrt{3}}(1 + r)^2, \qquad\text{つまり}\qquad N \le \frac{2(1 + r)^2}{\sqrt{3}\, r^2}
$$

が成り立つ。

比較のため、同じ数の点を独立に一様に置いた場合を考える。
単位正方形の独立な一様点二つの距離 $D$ は、$0 \le r \le 1$ で

$$
P(D < r) = \pi r^2 - \tfrac{8}{3} r^3 + \tfrac{1}{2} r^4
$$

に従う。
$N$ 点の $N(N-1)/2$ 組の点対のうち、距離が $r$ 未満の組の数の期待値は $\binom{N}{2} P(D < r)$ である。
Poisson 円板標本ではこの数が 0 なので、この期待値は最小距離の制約がどれだけ配置を変えたかの目安になる。

## 採取点の生成と検査

次のセルは最小の点間距離 $r$ [m]、活動点ごとの候補数 $k$、候補総数の上限、乱数のシードを入力に採取点を置く。
点の数の上限は 400 点で、どの入力でも上界より大きい。
すべての点の組の距離を総当たりで計算して最小値を求め、`geometric_discrepancy` の `MinimumDistance` と比べる。
区画の外に出た座標の数と、`generate_into` に渡す前に $-1$ で埋めておいた未使用の出力のうち、書き換えられた数も数える。
最後に終了状態を outcome で示す。

```rust
//| id: random-poisson-disk-separation
//| ref: random-poisson-disk-separation
//| title: 受理した採取点の全点対距離と出力範囲を確かめる
//| run: reactive
//| crates: [scioxide-core, scioxide-random]
//| inputs:
//|   minimum_radius: {"type":"range","label":"最小の点間距離 r [m]","min":0.06,"max":0.2,"step":0.02,"value":0.1}
//|   candidates: {"type":"range","label":"活動点ごとの候補数 k [個]","description":"少ないと活動点が早く外れ、置ける点が減る。","min":5,"max":40,"step":5,"value":30}
//|   proposal_budget: {"type":"range","label":"候補総数の上限 [個]","description":"小さいと BudgetExhausted で途中の設計を返す。","min":500,"max":20000,"step":500,"value":20000}
//|   seed: {"type":"range","label":"乱数のシード","min":1,"max":1000,"step":1,"value":42}
//| cases:
//|   - {"id":"dense","label":"r = 0.06 m","description":"半径を小さくすると点が増え、充填の上界も増える。","inputs":{"minimum_radius":0.06}}
//|   - {"id":"few-candidates","label":"候補数 5","description":"候補が少ないと点の数が減るが、最小距離は r 以上のまま。","inputs":{"candidates":5}}
//|   - {"id":"short-budget","label":"候補 1000 個まで","description":"候補の総数が上限に達して BudgetExhausted で止まり、それまでの点を返す。","inputs":{"proposal_budget":1000}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"design","path":"/rows/0/0","equals":68}
//|       - {"artifact":"design","path":"/rows/0/1","approx":{"value":139.72,"atol":0.01}}
//|       - {"artifact":"design","path":"/rows/0/2","equals":2485}
//|       - {"artifact":"separation","path":"/rows/0/0","range":{"min":0.1,"max":0.2}}
//|       - {"artifact":"separation","path":"/rows/0/1","equals":0}
//|       - {"artifact":"separation","path":"/rows/0/2","equals":0}
//|       - {"artifact":"separation","path":"/rows/0/3","equals":0}
//|       - {"artifact":"separation","path":"/rows/0/4","equals":0}
//|       - {"path":"/outputs/3/state","equals":"partial"}
//|   - case: dense
//|     expect:
//|       - {"artifact":"separation","path":"/rows/0/0","range":{"min":0.06,"max":0.12}}
//|       - {"artifact":"separation","path":"/rows/0/4","equals":0}
//|   - case: few-candidates
//|     expect:
//|       - {"artifact":"separation","path":"/rows/0/0","range":{"min":0.1,"max":0.2}}
//|       - {"artifact":"separation","path":"/rows/0/3","equals":0}
//|   - case: short-budget
//|     expect:
//|       - {"artifact":"design","path":"/rows/0/2","equals":1000}
//|       - {"artifact":"separation","path":"/rows/0/0","range":{"min":0.1,"max":0.2}}
//|       - {"path":"/outputs/3/state","equals":"partial"}
use scioxide_core::{ExecutionContext, RealScalar};
use scioxide_random::{
    GeometricDiscrepancy, PoissonDisk, PoissonDiskOptions, PoissonDiskTermination, Rollback,
    SeedableRng, SplitMix64, geometric_discrepancy,
};

let options = PoissonDiskOptions::default()
    .with_candidates_per_point(candidates.round() as usize)
    .with_max_proposals(proposal_budget.round() as usize)
    .with_max_grid_cells(10_000)
    .with_max_distance_checks(5_000_000);
// 点の数の上限 capacity = 400。
let design =
    PoissonDisk::with_options(&[0.0_f64, 0.0], &[1.0, 1.0], minimum_radius, 400, options)
        .map_err(|e| e.to_string())?;
let mut work = design.workspace().map_err(|e| e.to_string())?;
let mut out = vec![-1.0; design.output_elements()]; // 未使用の出力は -1 のまま残るはず
let report = design
    .generate_into(
        &mut SplitMix64::from_seed(seed.round() as u64),
        Rollback,
        &mut out,
        &mut work,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;
let m = report.points();
if m < 2 {
    return Err(format!("距離を比べる二点が得られない（点の数 {m}）"));
}
let r = minimum_radius;
// 全点対の距離の最小値と、距離 r 未満の点対の数（独立な検算）。
let mut brute = f64::INFINITY;
let mut close_pairs = 0_usize;
for i in 0..m {
    for j in 0..i {
        let distance =
            RealScalar::hypot(out[2 * i] - out[2 * j], out[2 * i + 1] - out[2 * j + 1]);
        brute = brute.min(distance);
        if distance < r {
            close_pairs += 1;
        }
    }
}
let separation = geometric_discrepancy(&out[..2 * m], 2, GeometricDiscrepancy::MinimumDistance)
    .map_err(|e| e.to_string())?;
let outside_box = out[..2 * m]
    .iter()
    .filter(|x| !(0.0..=1.0).contains(*x))
    .count();
let overwritten = out[2 * m..].iter().filter(|&&x| x != -1.0).count();
// 円の充填の上界と、独立な一様点で距離 r 未満になる点対の期待数（比較の基準）。
let bound = 2.0 * (1.0 + r) * (1.0 + r) / (RealScalar::sqrt(3.0_f64) * r * r);
let close_probability =
    std::f64::consts::PI * r * r - 8.0 / 3.0 * r * r * r + 0.5 * r * r * r * r;
let pairs = (m * (m - 1) / 2) as f64;
let points: Vec<[f64; 2]> = out[..2 * m].chunks_exact(2).map(|p| [p[0], p[1]]).collect();
emit_scatter_chart!(
    &points,
    options = &serde_json::json!({
        "xLabel": "東西方向の位置 [m]",
        "yLabel": "南北方向の位置 [m]",
        "xMin": 0.0,
        "xMax": 1.0,
        "yMin": 0.0,
        "yMax": 1.0
    })
);
let digits4 = serde_json::json!({ "significantDigits": 4 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let design_columns = serde_json::json!([
    { "key": "0", "label": "受理した点 points() [点]", "type": "integer" },
    { "key": "1", "label": "充填の上界 [点]", "type": "number", "format": digits4 },
    { "key": "2", "label": "提案 proposals() [個]", "type": "integer" },
    { "key": "3", "label": "近傍の計算量 distance_checks() [回]", "type": "integer" },
    { "key": "4", "label": "一様点で r 未満の点対の期待数 [組]", "type": "number", "format": digits4 }
]);
emit_table_with_columns!(
    design_columns,
    vec![(
        m,
        bound,
        report.proposals(),
        report.distance_checks(),
        pairs * close_probability,
    )],
    metadata = serde_json::json!({ "id": "design" })
);
let separation_columns = serde_json::json!([
    { "key": "0", "label": "総当たりの最小距離 [m]", "type": "number", "format": digits4 },
    { "key": "1", "label": "geometric_discrepancy との差 [m]", "type": "number", "format": sci2 },
    { "key": "2", "label": "r 未満の点対 [組]", "type": "integer" },
    { "key": "3", "label": "区画の外の座標 [個]", "type": "integer" },
    { "key": "4", "label": "書き換えられた未使用の出力 [個]", "type": "integer" }
]);
emit_table_with_columns!(
    separation_columns,
    vec![(
        brute,
        (brute - separation).abs(),
        close_pairs,
        outside_box,
        overwritten,
    )],
    metadata = serde_json::json!({ "id": "separation" })
);
let termination = report.termination();
let outcome = if termination == PoissonDiskTermination::Complete {
    Outcome::satisfied("点の数が上限 capacity に達した")
} else {
    Outcome::partial("capacity に達する前に止まり、それまでの設計を返した").explanation(
        "受理した点はどの二点も r 以上離れているが、まだ点を置ける隙間がないことは保証されない。",
    )
};
emit_outcome!(
    outcome
        .status(format!("{termination:?}"))
        .diagnostic("受理した点", m as f64, None)
        .diagnostic("最小距離", brute, Some("m"))
);
```

散布図では点がほぼ一様な間隔で並び、どの二点も $r$ より近づかない。
独立な一様点と違って、点どうしが近づいた塊ができない。
二点が $r$ より近づいていれば、距離の不変量が破れている。

既定の入力（$r = 0.1$ m、$k = 30$、シード 42）では、活動中の点がなくなる `ActiveListExhausted` で終わり、2,485 個の提案で 68 点が置かれた。
セルの結論は partial で、設計はそれまでの点をすべて返している。
総当たりの最小距離は $0.1007$ m で $r$ 以上、`geometric_discrepancy` の値と一致した。
$r$ 未満の点対、区画の外の座標、書き換えられた未使用の出力は、どれも 0 個だった。
点の数は充填の上界 139.7 点の約 49% である。
同じ 68 点を独立に一様に置くと、2,278 組の点対のうち $r$ 未満の組は平均 65.6 組できる。

$r = 0.06$ m では 6,596 個の提案で 181 点（上界 360.4 点の約 50%）、候補数を 5 にすると 412 個の提案で 54 点になり、どちらも最小距離は $r$ 以上だった。
候補が少ないと活動点が早く一覧から外れるので、隙間が残ったまま止まり、点の数が減る。
候補総数の上限を 1,000 個にすると `BudgetExhausted` で止まり、49 点を返す。
この設計も最小距離 $0.1007$ m を保つが、区画にはまだ点を置ける領域が広く残る。
`ActiveListExhausted` と `BudgetExhausted` はどちらも partial だが、前者は候補を出し尽くした結果、後者は作業量の上限による打ち切りなので、点の数と提案の数を併せて比べる。

## まとめ

Poisson 円板標本の最小距離は、全点対の総当たりで $r$ 以上と確かめられ、`geometric_discrepancy` の値とも一致する。
点の数は円の充填の上界を超えず、この例の既定の候補数では上界の約半分だった。
同じ数の独立な一様点では $r$ 未満の点対が $\binom{N}{2}(\pi r^2 - \tfrac{8}{3}r^3 + \tfrac12 r^4)$ 組ほどできるので、最小距離の制約が配置を大きく変えることが分かる。
`generate_into` は受理した点だけを出力の先頭に書き、残りの出力を書き換えないので、`points()` 行だけを読む。
`Complete` 以外の終了状態は途中の設計として読み、点の数が足りなければ候補数か上限を増やす。
