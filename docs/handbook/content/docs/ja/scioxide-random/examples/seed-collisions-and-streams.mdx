並列計算のワーカーに乱数のシードを無作為に配ると、二つのワーカーが同じシードを引くことがある。
その確率は[誕生日問題と乱数のシードの衝突](../birthday-collisions/)で導いた $P(k, D) = 1 - \prod_{i<k}(1 - i/D)$ で、日数 $D$ をシードの数に、人数 $k$ をワーカー数に読み替えたものである。
このページは 64 ビットのシードの衝突の確率を見積もり、小さなシードの空間のシミュレーションで同じ式を確かめる。
そのうえで、シードを無作為に配る代わりに系列を番号で選ぶ方法が、何を保証し何を保証しないかを整理する。

## 64 ビットのシードの衝突

$W$ 個のワーカーが $2^b$ 通りのシードから無作為に一つずつ引くと、同じシードを引くワーカーの組が生じる確率は $P(W, 2^b)$ である。
$W \ll 2^{b/2}$ では $P \approx W^2/2^{b+1}$ と小さいが、$W$ が $2^{b/2}$ に近づくと急に増える。
64 ビットのシードでは $P \approx W(W-1)/2^{65}$ で、$P = 1/2$ になるワーカー数は $\sqrt{2\ln 2 \cdot 2^{64}} \approx 5.06 \times 10^9$ である。
同じシードを引いた二つのワーカーは同じ乱数列を使い、互いに独立な標本のつもりで同じ標本を二度数えることになる。

64 ビットの空間で衝突を数えるのは現実的でないので、次のセルは $b = 12$–$24$ ビットの小さな空間で同じ式を確かめる。
入力はシードのビット数 $b$、ワーカー数を $2^{b/2}$ で割った比、乱数のシードで、試行数は 400 に固定する。
各試行は `root.split(試行の番号)` の系列から `uniform_index(2^b)` で $W$ 個のシードを引き、並べ替えて隣り合う等しい値を探す。
比較のため、`seed_sequence(シード, W)` が作る $W$ 個の 64 ビットのシードに重複があるかも数える。
二つ目の表は 64 ビットのシードについて $W$ ごとの衝突の確率を閉形式で示す。

```rust
//| id: random-birthday-seeds
//| ref: random-birthday-seeds
//| title: 無作為に配ったシードの衝突を数え 64 ビットに当てはめる
//| run: reactive
//| crates: [scioxide-core, scioxide-random]
//| inputs:
//|   seed_bits: {"type":"range","label":"シードのビット数 b [bit]","description":"シードの空間の大きさ 2^b。","min":12,"max":24,"step":2,"value":20}
//|   worker_load: {"type":"range","label":"ワーカー数の比 W/2^{b/2} [-]","description":"1 で衝突の確率は 1 − e^{−1/2} ≈ 0.39 になる。","min":0.25,"max":3,"step":0.25,"value":1}
//|   seeds_seed: {"type":"range","label":"乱数のシード [-]","description":"Pcg64 のシード。試行ごとに split の系列を使う。","min":1,"max":1000,"step":1,"value":5}
//| cases:
//|   - {"id":"few-workers","label":"W/2^{b/2} = 0.25","description":"W = 256 で正確な P は 0.0307 になり、W²/2^{b+1} の見積もり 0.031 に近い。","inputs":{"worker_load":0.25}}
//|   - {"id":"large-space","label":"b = 24、比 3","description":"W = 12288 で正確な P は 0.989 になる。","inputs":{"seed_bits":24,"worker_load":3}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"simulation","path":"/rows/0/1","equals":1024}
//|       - {"artifact":"simulation","path":"/rows/0/2","approx":{"value":0.3932718,"atol":1e-6}}
//|       - {"artifact":"simulation","path":"/rows/0/4","range":{"min":0.32,"max":0.47}}
//|       - {"artifact":"simulation","path":"/rows/0/7","equals":0}
//|       - {"artifact":"sixty-four","path":"/rows/3/2","approx":{"value":0.026741,"atol":1e-6}}
//|       - {"artifact":"sixty-four","path":"/rows/4/2","approx":{"value":0.5,"atol":1e-9}}
//|   - case: few-workers
//|     expect:
//|       - {"artifact":"simulation","path":"/rows/0/2","approx":{"value":0.0306509,"atol":1e-6}}
//|       - {"artifact":"simulation","path":"/rows/0/4","range":{"min":0.005,"max":0.06}}
//|   - case: large-space
//|     expect:
//|       - {"artifact":"simulation","path":"/rows/0/2","approx":{"value":0.9888991,"atol":1e-6}}
//|       - {"artifact":"simulation","path":"/rows/0/4","range":{"min":0.97,"max":1.0}}
use scioxide_core::RealScalar;
use scioxide_random::{Pcg64, SeedableRng, SplittableRng, seed_sequence, uniform_index};

let bits = seed_bits.round() as u32;
let space = 1_usize << bits;
let workers = (worker_load * RealScalar::sqrt(space as f64)).round() as usize;
let r = 400_usize;
let master = seeds_seed.round() as u64;
let root = Pcg64::from_seed(master);
let mut seeds = vec![0_usize; workers];
let mut collisions = 0;
for trial in 0..r {
    let mut rng = root.split(trial as u64).map_err(|e| e.to_string())?;
    for seed in seeds.iter_mut() {
        *seed = uniform_index(space, &mut rng).map_err(|e| e.to_string())?;
    }
    seeds.sort_unstable();
    collisions += usize::from(seeds.windows(2).any(|w| w[0] == w[1]));
}
// seed_sequence の W 個のシード（SplitMix64 の出力列）の重複を数える。
let mut derived = seed_sequence(master, workers).map_err(|e| e.to_string())?;
derived.sort_unstable();
let derived_duplicates = derived.windows(2).filter(|w| w[0] == w[1]).count();
// 独立検算: 正確な積と指数近似。
let log_q: f64 = (0..workers)
    .map(|i| RealScalar::ln_1p(-(i as f64) / space as f64))
    .sum();
let p = -RealScalar::exp_m1(log_q);
let pairs = (workers * (workers - 1)) as f64 / 2.0;
let p_approx = -RealScalar::exp_m1(-pairs / space as f64);
let p_hat = collisions as f64 / r as f64;
let se = RealScalar::sqrt(p * (1.0 - p) / r as f64);
let fixed4 = serde_json::json!({ "fractionDigits": 4 });
let fixed2 = serde_json::json!({ "fractionDigits": 2 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "b [bit]", "type": "integer" },
    { "key": "1", "label": "ワーカー数 W [個]", "type": "integer" },
    { "key": "2", "label": "正確な P [-]", "type": "number", "format": fixed4 },
    { "key": "3", "label": "近似 P [-]", "type": "number", "format": fixed4 },
    { "key": "4", "label": "P̂（400 試行）[-]", "type": "number", "format": fixed4 },
    { "key": "5", "label": "SE [-]", "type": "number", "format": fixed4 },
    { "key": "6", "label": "z = (P̂ − P)/SE [-]", "type": "number", "format": fixed2 },
    { "key": "7", "label": "seed_sequence の重複 [組]", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    vec![(
        bits,
        workers,
        p,
        p_approx,
        p_hat,
        se,
        (p_hat - p) / se,
        derived_duplicates
    )],
    metadata = serde_json::json!({ "id": "simulation" })
);
// 64 ビットのシード: P = 1 − exp(−W(W − 1)/2^65)。
let two_65 = RealScalar::powi(2.0_f64, 65);
let half_point =
    RealScalar::sqrt(2.0 * RealScalar::ln(2.0_f64) * RealScalar::powi(2.0_f64, 64));
let rows: Vec<(f64, f64, f64)> = [1e3, 1e6, 1e8, 1e9, half_point, 1e10]
    .iter()
    .map(|&w| {
        (
            w,
            w * (w - 1.0) / two_65,
            -RealScalar::exp_m1(-w * (w - 1.0) / two_65),
        )
    })
    .collect();
let wide = serde_json::json!([
    { "key": "0", "label": "ワーカー数 W [個]", "type": "number", "format": sci3 },
    { "key": "1", "label": "W(W − 1)/2⁶⁵ [-]", "type": "number", "format": sci3 },
    { "key": "2", "label": "衝突の確率 [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    wide,
    rows,
    metadata = serde_json::json!({ "id": "sixty-four" })
);
```

既定の $b = 20$、$W = 1024$ では、正確な確率 $0.39327$ に対し 400 試行の割合は $0.3675$（差は $-1.06\,\mathrm{SE}$）だった。
指数近似は $0.39317$ で、$W \ll 2^b$ のこの場面では正確な値との差は $10^{-4}$ に収まる。
比を 0.25 にすると $W = 256$ で $P = 0.0307$、比を 3 にして $b = 24$ とすると $W = 12288$ で $P = 0.989$ になる。
確率を決めるのは $W$ そのものではなく比 $W/2^{b/2}$ で、比が 12 倍になると確率は 0 に近い値から 1 に近い値まで動く。
`seed_sequence` の $W$ 個のシードの重複はどの入力でも 0 である。

64 ビットのシードでは、ワーカーが $10^6$ 個なら衝突の確率は $2.7 \times 10^{-8}$ だが、$10^9$ 個では $0.0267$、$5.06 \times 10^9$ 個では $0.5$ になる。
$W(W-1)/2^{65}$ は $P$ が小さいときの近似で、$P$ が 0.1 を超えると $1 - \exp(-W(W-1)/2^{65})$ との差が目立つ。

## 系列の分割が保証すること

シードを無作為に配る代わりに、一つの生成器からワーカーの番号で系列を選べば、セレクターは $0, 1, \dots, W-1$ と互いに異なり、セレクターの衝突を考える必要はない。
`SplittableRng` のセレクターは派生した生成器から呼んでも根からの絶対的な選択で、親を消費しない。
ただし `SplittableRng` の仕様が述べるのは、異なるセレクターが異なる系列を指すことまでである。
読み出す範囲で系列が重ならないかは、各生成器の周期と系列の間隔、各系列で消費するワード数で決まり、生成器ごとに保証の中身が違う。

- `Philox4x64` と `Threefry4x64` の `split` と `substream` は同じ鍵のままカウンターの系列語と部分系列ワードを変える。
  一つの系列は $2^{66}$ ワードを持ち、異なるセレクターの系列は同じカウンターのブロックを評価しないので、1 系列で $2^{66}$ 語以下しか読まない限り、重なりは構成から起こらない。
- `Pcg64::split(id)` は加算定数を $2\,\mathrm{id} + 1$ にした LCG を選ぶので、$2^{64}$ 個の系列から選べる。
  各系列は周期 $2^{128}$ の別の合同列で、`substream(id, j)` はその系列を $2^{64}$ 遷移ずつの区画に分けた $j$ 番目を選ぶ。
  同じ系列の区画どうしはそれぞれ $2^{64}$ 遷移以下しか読まなければ重ならない。
- `Xoshiro256StarStar` は `SplittableRng` を持たず、`JumpableRng::jump` で $2^{128}$ 遷移、`long_jump` で $2^{192}$ 遷移進めて区間を分ける。
  `Xoshiro128StarStar` のジャンプは $2^{64}$ 遷移と $2^{96}$ 遷移である。
- `StreamPartitioner::for_partition` は、`ExecutionPlan` の分割の識別子と領域番号から 128 ビットの鍵を作り、下位 64 ビットを系列、上位 64 ビットを部分系列のセレクターにして、長さを限った `BoundedSubstream` を返す。
  範囲を越える読み出しは状態を変えずに `OutOfBounds` で失敗する。
  鍵は散らした値なので、部分系列の番号は大きな値になる。
  たとえば `Mrg32k3a` が重ならないと述べる部分系列の範囲は $j < 2^{51}$ だが、鍵から作る $j$ はふつうその外にある。
  分割どうしの重なりを構成から避けられるのはカウンター型の生成器だけで、他の生成器では生成器ごとの間隔の条件を確かめる。

`seed_sequence(seed, n)` は `SplitMix64` の出力列そのもので、Weyl 列に全単射の混合関数をかけるので、$2^{64}$ 個までの添字は互いに異なるシードを与える。
上のセルの重複の列が 0 なのはこの性質による。
ただしシードが異なっても系列が重ならないとは限らない。
`Pcg64::from_seed` はどのシードでも同じ加算定数を使い、シードは周期 $2^{128}$ の一つの合同列の上の出発点を決めるだけである。
$W$ 個の出発点が無作為なら、各系列で $L$ ワードを使うときに区間が重なる確率は約 $W(W-1)L/2^{128}$ で、$W = 10^6$、$L = 2^{40}$ では $3.2 \times 10^{-15}$ になる。
重なりを確率でなく構成で避けるには、カウンター型の生成器の `split` か `substream` で系列を選ぶ。
系列の間隔と重なりの条件は[系列の間隔と重なり](oxref:random-prng-stream-spacing)、分割への割り当ては[実行 Plan の分割への割り当て](oxref:random-prng-plan-partitions)で説明した。

## まとめ

無作為に配った $b$ ビットのシードの衝突の確率は誕生日問題の式で決まり、ワーカー数 $W$ と $2^{b/2}$ の比でほぼ決まる。
64 ビットのシードでは $W = 10^9$ で約 2.7%、$W \approx 5.06 \times 10^9$ で 1/2 に達するので、大規模な並列計算では無作為なシードに頼らない。
`seed_sequence` は互いに異なるシードを返すが、`Pcg64` のようにシードが一つの合同列の出発点を決めるだけの生成器では、系列の重なりを確率でしか抑えられない。
重なりを構成から避けるにはカウンター型の生成器の `split` か `substream` を使い、それ以外の生成器では、生成器ごとに系列の間隔と読むワード数の上限を確かめる。
