計算機実験では計算コストが大きいシミュレーションを少ない回数だけ回し、その結果から入力と出力の関係を調べる。
入力の組は空間に偏りなく広がり、各入力の範囲をむらなく調べられるように選びたい。
この例題は `latin_hypercube_into` で ラテンハイパーキューブ設計を作り、設計が約束する性質（不変量）を、設計を作る計算とは別のコードで確かめる。
確かめる不変量は、各入力の層が一度ずつ使われることと、交換による改善の後もその性質が保たれることである。
構成、分散の理論、ディスクレパンシーの閉形式は[ラテンハイパーキューブ設計とディスクレパンシー](../../algorithms/latin-hypercube-and-discrepancy/)で説明した。
点どうしの最小距離を保証する別の設計は[Poisson 円板標本による土壌採取点の配置](../field-sampling-poisson-disk/)で扱う。

## 計算機実験の入力と ラテンハイパーキューブ

熱交換器のシミュレーションで、次の 3 入力を $n = 32$ 組だけ選ぶとする。

| 入力 | 記号 | 範囲 |
|---|---|---|
| 流量 | $\dot{m}$ | 0.1〜0.5 kg/s |
| API 温度 | $T_{\mathrm{in}}$ | 20〜80 °C |
| 壁の熱伝導率 | $k$ | 15〜400 W/(m·K) |

設計は単位立方体 $[0, 1)^3$ で作り、各座標 $x$ を $\text{下限} + (\text{上限} - \text{下限})\,x$ で物理量に写す。
この写像は各軸の層を層に写すので、単位立方体での性質がそのまま物理の範囲に移る。

ラテンハイパーキューブ（LHS）は各入力を幅 $1/32$ の 32 の層に分け、どの入力についても各層にちょうど一つの点を置く。
`latin_hypercube` とその設定付きの形は入力ごとに層 $i$ の中に一点ずつ値を置き、その列を Fisher–Yates の方法で独立に並べ替える。
層の中の位置は既定では一様な乱数で、`LatinHypercubeOptions::with_centered(true)` なら層の中点である。
各入力の主効果を均等に調べられる一方、三つの入力の組合せの配置は保証されない。
すべての点が対角線の近くに並ぶような設計も、層の性質だけからは排除できない。

## ディスクレパンシーと交換による改善

組合せの偏りは中心化 $L^2$ ディスクレパンシー（Hickernell）の二乗

$$
\mathrm{CD}^2 = \Bigl(\tfrac{13}{12}\Bigr)^d - \frac{2}{n}\sum_{i}\prod_{k}\Bigl(1 + \tfrac12 a_{ik} - \tfrac12 a_{ik}^2\Bigr) + \frac{1}{n^2}\sum_{i}\sum_{j}\prod_{k}\Bigl(1 + \tfrac12 a_{ik} + \tfrac12 a_{jk} - \tfrac12|x_{ik} - x_{jk}|\Bigr)
$$

で測る。
ここで $x_{ik}$ は点 $i$ の座標 $k$、$a_{ik} = |x_{ik} - \tfrac12|$、$d = 3$ は入力の数である。
立方体の各点 $\mathbf{x}$ と、$\mathbf{x}$ に最も近い頂点が張る箱を考え、箱に入る点の割合と箱の体積の差を二乗して $\mathbf{x}$ について平均する。
この量を座標のすべての部分集合への射影について足し合わせたものが $\mathrm{CD}^2$ で、値が小さいほど点は一様に広がる。
独立な一様点の $\mathrm{CD}^2$ の期待値は $\bigl((5/4)^d - (13/12)^d\bigr)/n$ で、$d = 3$、$n = 32$ では $2.130 \times 10^{-2}$ である。

`LatinHypercubeOptions` の `max_proposals` を正にすると、関数は入力を一つ選び、その入力の中で二つの点の値を入れ替える提案を作る。
提案は $\mathrm{CD}^2$ が厳密に下がる場合だけ受理し、それ以外は元に戻す。
二つの点は独立に選ぶので同じ点になることがあり、その提案は何も変えずに改善なしと数える。
入れ替えは同じ列の中の値の並べ替えなので、各層を一度ずつ使う性質を保つ。
交換で変わる項だけを和から引いて足し直すので、一つの提案は $O(nd)$ で評価できる。
詳しくは[交換による改善](oxref:random-sampling-exchange)で説明した。

`LatinHypercubeReport` は、終了状態 `termination()`、試みた提案の数 `proposals()`、改善の前と後の $\mathrm{CD}^2$（`initial_discrepancy()`、`final_discrepancy()`）を返す。
提案を求めなければ二つの $\mathrm{CD}^2$ は `None` で、終了状態は `Complete` である。
提案の数が `max_proposals` に達すると `BudgetExhausted`、改善のない提案が `stagnation_limit`（既定 100）回続くと `Stagnation` で止まる。
`ExecutionContext` の取り消しか期限を提案の前に見つけたときは `Stopped` で止まる。
どの終了状態でも設計は 32 点すべてを持ち、それまでに受理した交換を含む。
交換は貪欲な局所探索なので、どの終了状態も最適な設計に達したことは示さない。
そのため、セルの結論は `Complete` なら satisfied、それ以外は partial とする。

## 設計の作成と不変量の検査

次のセルは設計を `latin_hypercube_into` で呼び出し側の出力に作り、`LatinHypercubeReport` を読む。
`latin_hypercube_into` は設計全体を作業領域に作り、成功したときだけ出力に写す。
`Rollback` は、失敗したときに生成器を呼び出し前の状態に戻す指定である。
入力は交換を提案する回数の上限、層の中点に置くかどうか、乱数のシードである。

セルは三つの独立な検算を行う。
各入力の層 $\lfloor 32 x \rfloor$ の度数を数え直し、1 でない層の数を合計する。
最後の $\mathrm{CD}^2$ を、`discrepancy` の `DiscrepancyMethod::Centered` と、セルの中で上の式から直接計算した値の二通りで計算し直す。
同じシードから所有値を返す API の `latin_hypercube_with_options(n, d, rng, options)` でも設計を作り、二つの形の設計の最大の差を求める。

散布図は流量と API 温度の射影を物理の単位で描く。
上の表は $\mathrm{CD}^2$ の推移と比較の基準、下の表は不変量の検査結果である。

```rust
//| id: random-lhs-marginal-invariants
//| ref: random-lhs-marginal-invariants
//| title: ラテンハイパーキューブの交換後も各層が一度ずつ使われるかを確かめる
//| run: reactive
//| crates: [scioxide-core, scioxide-random]
//| inputs:
//|   proposal_limit: {"type":"range","label":"交換の提案の上限 [回]","min":0,"max":512,"step":32,"value":128}
//|   centered: {"type":"checkbox","label":"層の中点に置く（centered）","value":false}
//|   seed: {"type":"range","label":"乱数のシード","min":1,"max":1000,"step":1,"value":42}
//| cases:
//|   - {"id":"no-optimization","label":"提案の上限 0","description":"交換を行わず、終了状態は Complete、レポートのディスクレパンシーは None になる。","inputs":{"proposal_limit":0}}
//|   - {"id":"long-optimization","label":"提案の上限 512","description":"提案を 4 倍にすると CD² がさらに下がり、上限に達して BudgetExhausted で止まる。","inputs":{"proposal_limit":512}}
//|   - {"id":"centered","label":"層の中点","description":"点を層の中点に置いても各層は一度ずつ使われる。","inputs":{"centered":true}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"discrepancy","path":"/rows/0/0","equals":128}
//|       - {"artifact":"discrepancy","path":"/rows/0/1","approx":{"value":3.503e-3,"atol":2e-6}}
//|       - {"artifact":"discrepancy","path":"/rows/0/2","approx":{"value":1.685e-3,"atol":2e-6}}
//|       - {"artifact":"discrepancy","path":"/rows/0/3","range":{"min":0,"max":0}}
//|       - {"artifact":"discrepancy","path":"/rows/0/4","approx":{"value":2.1304e-2,"atol":1e-6}}
//|       - {"artifact":"invariants","path":"/rows/0/0","equals":0}
//|       - {"artifact":"invariants","path":"/rows/0/1","range":{"min":0,"max":1e-14}}
//|       - {"artifact":"invariants","path":"/rows/0/2","equals":0}
//|       - {"path":"/outputs/3/state","equals":"partial"}
//|   - case: no-optimization
//|     expect:
//|       - {"artifact":"discrepancy","path":"/rows/0/1","equals":null}
//|       - {"artifact":"invariants","path":"/rows/0/0","equals":0}
//|       - {"path":"/outputs/3/state","equals":"satisfied"}
//|   - case: long-optimization
//|     expect:
//|       - {"artifact":"discrepancy","path":"/rows/0/2","range":{"min":1e-3,"max":1.685e-3}}
//|       - {"artifact":"invariants","path":"/rows/0/0","equals":0}
//|       - {"path":"/outputs/3/state","equals":"partial"}
//|   - case: centered
//|     expect:
//|       - {"artifact":"invariants","path":"/rows/0/0","equals":0}
//|       - {"artifact":"invariants","path":"/rows/0/1","range":{"min":0,"max":1e-14}}
use scioxide_core::{ExecutionContext, RealScalar};
use scioxide_random::{
    DiscrepancyMethod, LatinHypercubeOptions, LatinHypercubeTermination, Rollback,
    SamplingWorkspace, SeedableRng, SplitMix64, discrepancy, latin_hypercube_into,
    latin_hypercube_with_options,
};

let (n, d, seed) = (32_usize, 3_usize, seed.round() as u64);
let options = LatinHypercubeOptions::default()
    .with_centered(centered)
    .with_max_proposals(proposal_limit.round() as usize);
// 呼び出し側の出力に書く形。作業領域は必要な大きさまで伸びる。
let mut workspace = SamplingWorkspace::new();
let mut design = vec![0.0_f64; n * d];
let report = latin_hypercube_into(
    d,
    &mut SplitMix64::from_seed(seed),
    Rollback,
    options,
    &mut design,
    &mut workspace,
    ExecutionContext::sequential(),
)
.map_err(|e| e.to_string())?;
// 所有値を返す API は同じ設定と同じシードから同じ設計を返す。
let (owned, _) =
    latin_hypercube_with_options::<f64, _>(n, d, &mut SplitMix64::from_seed(seed), options)
        .map_err(|e| e.to_string())?;
let owned_difference = owned
    .iter()
    .zip(&design)
    .map(|(a, b)| (a - b).abs())
    .fold(0.0_f64, f64::max);
// 各入力について層 floor(32 x) の度数を数え直し、1 でない層の数を集計する（独立な検算）。
let mut violations = 0_usize;
for column in 0..d {
    let mut counts = vec![0_usize; n];
    for row in design.chunks_exact(d) {
        counts[(row[column] * n as f64).floor() as usize] += 1;
    }
    violations += counts.iter().filter(|&&c| c != 1).count();
}
// Hickernell の式で CD² を直接計算する（独立な検算）。
let half = |x: f64| (x - 0.5).abs();
let mut single = 0.0;
let mut pair = 0.0;
for a in design.chunks_exact(d) {
    single += a
        .iter()
        .map(|&x| 1.0 + 0.5 * half(x) - 0.5 * half(x) * half(x))
        .product::<f64>();
    for b in design.chunks_exact(d) {
        pair += a
            .iter()
            .zip(b)
            .map(|(&x, &y)| 1.0 + 0.5 * half(x) + 0.5 * half(y) - 0.5 * (x - y).abs())
            .product::<f64>();
    }
}
let nf = n as f64;
let constant = RealScalar::powi(13.0_f64 / 12.0, d as i32);
let hickernell = constant - 2.0 * single / nf + pair / (nf * nf);
let recomputed =
    discrepancy(&design, d, DiscrepancyMethod::Centered).map_err(|e| e.to_string())?;
// 独立な一様点の期待値 ((5/4)^d − (13/12)^d)/n（比較の基準）。
let iid_expected = (RealScalar::powi(1.25_f64, d as i32) - constant) / nf;
// 流量 0.1〜0.5 kg/s と API 温度 20〜80 °C へ写した射影。
let projection: Vec<[f64; 2]> = design
    .chunks_exact(d)
    .map(|row| [0.1 + 0.4 * row[0], 20.0 + 60.0 * row[1]])
    .collect();
emit_scatter_chart!(
    &projection,
    options = &serde_json::json!({
        "xLabel": "流量 ṁ [kg/s]",
        "yLabel": "API 温度 T_in [°C]",
        "xMin": 0.1,
        "xMax": 0.5,
        "yMin": 20.0,
        "yMax": 80.0
    })
);
let sci4 = serde_json::json!({ "notation": "scientific", "significantDigits": 4 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let none = "提案なし";
let columns = serde_json::json!([
    { "key": "0", "label": "試みた提案 [回]", "type": "integer" },
    { "key": "1", "label": "最初の CD² [-]", "type": "number", "format": sci4, "nullText": none },
    { "key": "2", "label": "最後の CD² [-]", "type": "number", "format": sci4, "nullText": none },
    { "key": "3", "label": "discrepancy との差 [-]", "type": "number", "format": sci2, "nullText": none },
    { "key": "4", "label": "独立な一様点の期待値 [-]", "type": "number", "format": sci4 }
]);
emit_table_with_columns!(
    columns,
    vec![(
        report.proposals(),
        report.initial_discrepancy(),
        report.final_discrepancy(),
        report
            .final_discrepancy()
            .map(|last| (last - recomputed).abs()),
        iid_expected,
    )],
    metadata = serde_json::json!({ "id": "discrepancy" })
);
let check_columns = serde_json::json!([
    { "key": "0", "label": "度数が 1 でない層（3 入力の合計）[個]", "type": "integer" },
    { "key": "1", "label": "Hickernell の式との差 [-]", "type": "number", "format": sci2 },
    { "key": "2", "label": "所有値を返す API との最大の差 [-]", "type": "number", "format": sci2 }
]);
emit_table_with_columns!(
    check_columns,
    vec![(
        violations,
        (recomputed - hickernell).abs(),
        owned_difference
    )],
    metadata = serde_json::json!({ "id": "invariants" })
);
let termination = report.termination();
let outcome = if termination == LatinHypercubeTermination::Complete {
    Outcome::satisfied("交換を求めない ラテンハイパーキューブが完成した")
        .explanation("層の性質だけを持つ設計で、ディスクレパンシーの改善は試みていない。")
} else {
    Outcome::partial("交換による改善が途中で止まった").explanation(
        "設計は 32 点すべてを持ち、各層を一度ずつ使う。CD² は局所探索の到達値である。",
    )
};
emit_outcome!(
    outcome
        .status(format!("{termination:?}"))
        .diagnostic("試みた提案", report.proposals() as f64, None)
        .diagnostic("CD²", recomputed, None)
);
```

散布図の各軸には 32 の層があり、どの列にもどの行にも一点ずつ並ぶ。
一つの列や行に二点が入っていれば、層の不変量が破れている。
提案の上限が 0 のとき、レポートの二つの $\mathrm{CD}^2$ は `None` なので、表には「提案なし」と出る。

既定の入力（提案の上限 128、シード 42）では、終了状態は `BudgetExhausted` で、セルの結論は partial である。
度数が 1 でない層は 0 個だった。
$\mathrm{CD}^2$ は $3.503 \times 10^{-3}$ から $1.685 \times 10^{-3}$ に下がり、`discrepancy` で計算し直した値はレポート値とビット単位で一致した。
Hickernell の式で直接計算した値との差は $1.6 \times 10^{-15}$ で、丸めの大きさである。
所有値を返す API と `latin_hypercube_into` の設計の最大の差は 0 である。
交換をする前の LHS でも、$\mathrm{CD}^2$ は独立な一様点の期待値 $2.130 \times 10^{-2}$ の約 6 分の 1 にとどまる。
$\mathrm{CD}^2$ は座標の部分集合 $u$ ごとの射影の項の和で、独立な一様点では $u$ の項の期待値が $\bigl((1/4)^{|u|} - (1/12)^{|u|}\bigr)/n$ になる。
$d = 3$ では一次元の射影の 3 項が期待値の約 73% を占め、射影を層化した LHS ではこの部分がほとんど残らない。

提案の上限を 512 にすると、改善のない提案が 100 回続くことはなく上限に達して `BudgetExhausted` で止まり、$\mathrm{CD}^2$ は $1.430 \times 10^{-3}$ まで下がる。
層の中点に置く（centered）と、最初の値は $2.485 \times 10^{-3}$、128 回の提案の後は $1.576 \times 10^{-3}$ になる。
提案の上限を 0 にすると交換は行われず、終了状態は `Complete`、セルの結論は satisfied になる。
提案を増やすほど $\mathrm{CD}^2$ は下がるが、partial の結論が示すとおり、到達した値が最小である保証はない。

## まとめ

ラテンハイパーキューブの交換は列の中の並べ替えなので層の性質を保ち、度数を数え直すと各入力の 32 の層がちょうど一度ずつ使われている。
層化だけで $\mathrm{CD}^2$ は独立な一様点の期待値の数分の 1 になり、交換による局所探索でさらに下げられる。
レポートの $\mathrm{CD}^2$ は `discrepancy` と Hickernell の式で再現でき、所有値を返す API と呼び出し側の出力に書く形は同じシードから同じ設計を返す。
交換を求めた設計は終了状態にかかわらず局所探索の到達点として読み、組合せの偏りは $\mathrm{CD}^2$ の値で判断する。
単位立方体で作った設計は、各軸の一次関数で物理の範囲に写せば層の性質を保ったまま使える。
