[区間を保つ求根法](../bracketing-methods/)は、符号の変わる区間 $[a, b]$ が与えられていることを前提にする。
物理量の平衡点や分布の分位点では、根のおおよその位置は分かっても、両端の符号が反対になる区間を事前に書けないことが多い。
その場合は推測値から区間を広げて符号の変化を探し、得た区間を後で再び使うときは端点を評価し直して確かめる。

## 探索の入力と方向

符号の変わる区間が分からないときは、推測値から区間を広げて符号の変化を探す。
`find_bracket(f, guess)` はクロージャ `f` と一つの推測値を受け取り、自動の向き、加法的な拡大、拡大率 2、拡大 2048 回までの既定の設定で、$[-\mathrm{MAX}, \mathrm{MAX}]$（`MAX` は最大の有限な浮動小数点数）の中を探す。
`find_bracket_with_options(&f, input, direction, &options)` は `ScalarFunction` を実装した関数、推測値または二つのシード、探索の向き、`BracketSearchOptions` を受け取る。
`BracketSearchInput::Guess` は一つの推測値、`Pair` は $a \le b$ の順の二つのシード（$a = b$ でもよい）を渡す。
`Pair` では $a$ を先に評価し、$f(a) = 0$ ならそこで探索を終える。
拡大の 1 歩は端点を一つ動かし、関数を 1 回評価する。
`BracketSearchDirection` は、関数の向きを宣言しない自動の探索（`Automatic`）、単調増加（`Increasing`）、単調減少（`Decreasing`）を区別する。
自動の探索では $\lvert f \rvert$ の小さい方の端を広げ、進めなければもう一方を広げる。
単調性を宣言すると、関数値の符号から根がある側へだけ広げ、最初に符号が変わった連続する 2 点を返す。
単調性は呼び出し側の約束で、探索はそれを確かめない。

探索が返すのは、両端の関数値が反対の符号を持つ（または一方が 0 の）区間だけである。
偶数重根のように符号が変わらない根や、符号の変化が極によって生じる場合は、探索では区別できない。

## 拡大の方式と定義域

`BracketSearchOptions` で設定できるのは、拡大の回数の上限（`with_max_expansions`、既定 2048 回）、拡大率 $r$（`with_expansion_factor`、既定 2、1 より大きい値）、拡大の方式（`with_expansion`）、定義域（`with_domain`）、反復や評価の回数の上限（`with_budgets`）である。
初期の幅を決めるオプションはない。
一つの推測値 $x_0$ からの加法的な探索は半幅 $h = \max(\lvert x_0 \rvert, 1)$ で始め、自動の向きでは $[x_0 - h, x_0 + h]$ の両端を、単調性を宣言した場合は $x_0$ と $x_0 \pm h$ を評価する。
始めの区間を指定したい場合は `Pair` で渡す。

`BracketExpansion::Additive` は端点を $b \leftarrow b + (r - 1)(b - a)$（下端なら対称に）と動かして区間の幅を $r$ 倍にし、`Multiplicative` は端点の座標を $r$ で掛けるか割る。
乗法的な探索は 0 をまたがないので、正または負の側だけの定義域を `with_domain` で指定する必要があり、0 を含む定義域では関数を呼ぶ前に `InvalidInput` を返す。
`with_domain` の `Excluded` の端は定義域の内側の隣の浮動小数点数に、`Unbounded` は $\pm\mathrm{MAX}$ に置き換わり、すべての評価点は定義域に収まる。
シードの順序が逆の場合やシードが定義域の外にある場合も、関数を呼ぶ前に `InvalidInput` を返す。
拡大の上限に達したときは `ConvergenceFailure`（`IterationLimit`）、定義域の端でどちらの端点も進めなくなったときは `ConvergenceFailure`（`Stagnation`）のエラーを返す。

既定の拡大率 2 では、一つの推測値から始める探索は $k$ 回の拡大で幅をおよそ $2^k$ 倍にする。
根までの距離が $d$ なら、必要な拡大の回数はおよそ $\log_2\bigl(d / \max(\lvert x_0 \rvert, 1)\bigr)$ 回で、評価回数も同じ程度に増える。

## 正の領域での探索

次のセルは $f(x) = \ln x - q$ の零点を正の領域 $(0, \infty)$ で、推測値 $x_0 = 1$ から単調増加として探す。
入力は目標 $q$ と拡大の方式で、出力は区間の両端、`Bracket` が持つ両端の関数値、独立な参照値 $e^q$ を区間が含むか、端点の再評価の結果である。

```rust
//| id: rootfind-positive-bracket-search
//| ref: rootfind-positive-bracket-search
//| title: 正の領域で単調な対数関数の符号変化を探す
//| run: reactive
//| crates: [scioxide-core, scioxide-rootfind]
//| inputs:
//|   level: {"type":"range","label":"対数の目標 q [-]","description":"根は e^q。負にすると根は 0 と 1 の間に入る。","min":-4,"max":4,"step":0.5,"value":2}
//|   expansion: {"type":"select","label":"区間の広げ方","options":["additive","multiplicative"],"value":"multiplicative"}
//| cases:
//|   - {"id":"additive","label":"q = 2、加法的な探索","description":"幅を倍にしながら 1, 2, 3, 5, 9 と進み、区間 [5, 9] を返す。","inputs":{"expansion":"additive"}}
//|   - {"id":"below-one","label":"q = −3、乗法的な探索（根が 0 と 1 の間）","description":"座標を半分ずつにして区間 [0.03125, 0.0625] を返す。","inputs":{"level":-3}}
//|   - {"id":"below-one-additive","label":"q = −3、加法的な探索（根が 0 と 1 の間）","description":"最初の一歩で定義域の端まで進み、[5 × 10⁻³²⁴, 1] という 300 桁以上にわたる区間を返す。","inputs":{"level":-3,"expansion":"additive"}}
//|   - {"id":"exact-guess","label":"q = 0（推測値が厳密な根）","description":"f(1) = 0 なので、一点の区間 [1, 1] を返す。","inputs":{"level":0}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"bracket","path":"/rows/0/0","approx":{"value":4,"atol":1e-12}}
//|       - {"artifact":"bracket","path":"/rows/0/1","approx":{"value":8,"atol":1e-12}}
//|       - {"artifact":"bracket","path":"/rows/0/2","range":{"max":0}}
//|       - {"artifact":"bracket","path":"/rows/0/3","range":{"min":0}}
//|       - {"artifact":"bracket","path":"/rows/0/4","approx":{"value":7.389,"atol":5e-4}}
//|       - {"artifact":"bracket","path":"/rows/0/5","equals":"含む"}
//|       - {"artifact":"bracket","path":"/rows/0/6","equals":"Verified"}
//|   - case: additive
//|     expect:
//|       - {"artifact":"bracket","path":"/rows/0/0","approx":{"value":5,"atol":1e-12}}
//|       - {"artifact":"bracket","path":"/rows/0/1","approx":{"value":9,"atol":1e-12}}
//|       - {"artifact":"bracket","path":"/rows/0/5","equals":"含む"}
//|       - {"artifact":"bracket","path":"/rows/0/6","equals":"Verified"}
//|   - case: below-one
//|     expect:
//|       - {"artifact":"bracket","path":"/rows/0/0","approx":{"value":0.03125,"atol":1e-15}}
//|       - {"artifact":"bracket","path":"/rows/0/1","approx":{"value":0.0625,"atol":1e-15}}
//|       - {"artifact":"bracket","path":"/rows/0/5","equals":"含む"}
//|   - case: below-one-additive
//|     expect:
//|       - {"artifact":"bracket","path":"/rows/0/0","range":{"min":0,"max":1e-300}}
//|       - {"artifact":"bracket","path":"/rows/0/1","approx":{"value":1,"atol":1e-12}}
//|       - {"artifact":"bracket","path":"/rows/0/5","equals":"含む"}
//|       - {"artifact":"bracket","path":"/rows/0/6","equals":"Verified"}
//|   - case: exact-guess
//|     expect:
//|       - {"artifact":"bracket","path":"/rows/0/0","approx":{"value":1,"atol":1e-15}}
//|       - {"artifact":"bracket","path":"/rows/0/1","approx":{"value":1,"atol":1e-15}}
//|       - {"artifact":"bracket","path":"/rows/0/2","equals":0}
use core::ops::Bound::{Excluded, Unbounded};
use scioxide_core::RealScalar;
use scioxide_rootfind::{
    BracketExpansion, BracketSearchDirection, BracketSearchInput, BracketSearchOptions,
    BracketVerification, ScalarFn, find_bracket_with_options,
};

let geometry = if expansion == "multiplicative" {
    BracketExpansion::Multiplicative
} else {
    BracketExpansion::Additive
};
// 対数の定義域 x > 0。Excluded(0) は 0 の隣の正の浮動小数点数に置き換わる。
let options = BracketSearchOptions::default()
    .with_domain(Excluded(0.0_f64), Unbounded)
    .with_expansion(geometry);
let f = ScalarFn::new(|x: f64| Ok(RealScalar::ln(x) - level));
let bracket = find_bracket_with_options(
    &f,
    BracketSearchInput::Guess(1.0),
    BracketSearchDirection::Increasing,
    &options,
)
.map_err(|e| e.to_string())?;
// 端点を再評価し、保存された値と一致するかを確かめる。
let verification = match bracket.verify(&f).map_err(|e| e.to_string())? {
    BracketVerification::Verified => "Verified",
    BracketVerification::Rejected => "Rejected",
};
// 独立な参照値として f64 固有の指数関数を使う。
let exact = level.exp();
let contains = if bracket.interval().contains(exact) {
    "含む"
} else {
    "含まない"
};
let sci4 = serde_json::json!({ "notation": "scientific", "significantDigits": 4 });
let columns = serde_json::json!([
    { "key": "0", "label": "下端 [-]", "type": "number", "format": sci4 },
    { "key": "1", "label": "上端 [-]", "type": "number", "format": sci4 },
    { "key": "2", "label": "f(下端) [-]", "type": "number", "format": sci4 },
    { "key": "3", "label": "f(上端) [-]", "type": "number", "format": sci4 },
    { "key": "4", "label": "参照値 exp(q) [-]", "type": "number", "format": sci4 },
    { "key": "5", "label": "参照値を含むか" },
    { "key": "6", "label": "端点の再検証" }
]);
let row = (
    bracket.lower(),
    bracket.upper(),
    bracket.lower_value(),
    bracket.upper_value(),
    exact,
    contains,
    verification,
);
emit_table_with_columns!(
    columns,
    vec![row],
    metadata = serde_json::json!({ "id": "bracket" })
);
```

$q = 2$ では、乗法的な探索が $1, 2, 4, 8$ と座標を倍にして $[4, 8]$ を返し、加法的な探索は幅を倍にしながら $1, 2, 3, 5, 9$ と進んで $[5, 9]$ を返す。
どちらも参照値 $e^2 \approx 7.389$ を含み、両端の関数値は反対の符号を持つ。
根が 1 より大きい側では、どちらの方式も幾何級数的に広がるので、$q = 4$ でも乗法的な探索で $[32, 64]$、加法的な探索で $[33, 65]$ と、評価回数はほとんど変わらない。
違いは $q < 0$ で根が 0 と 1 の間にあるときに現れる。
$q = -3$ の乗法的な探索は座標を半分ずつにして $[0.03125, 0.0625]$ を返すが、加法的な探索は最初の一歩で定義域の端（0 の隣の正の浮動小数点数 $5 \times 10^{-324}$）まで進み、$[5 \times 10^{-324}, 1]$ という 300 桁以上にわたる区間を返す。
どちらも正しく根を挟むが、後の求解で縮める幅が大きく異なる。
$q = 0$ では推測値 1 が厳密な根なので、一点の区間 $[1, 1]$ が返る。

得られる区間は、有限な両端で符号が変わることを確かめた結果であり、連続性と単調性は入力関数の数学的な仮定である。
精度を上げるには、`Bracket::interval()` を Brent 法などの `ScalarRootSolver::solve` に渡す。
既定の設定の Brent 法でよければ、`find_root(f, bracket.lower(), bracket.upper())` が根だけを返し、成功でない終了は `ConvergenceFailure` などのエラーにする。
求解では端点を改めて評価するので、その 2 回分の評価が探索の評価に加わる。

## 区間の再検証

`Bracket::verify` は端点を再評価し、保存された値と一致すれば `BracketVerification::Verified`、一致しなければ `Rejected` を返す。
一点に縮んだ区間は 1 回、それ以外は 2 回評価する。
これは端点の観測を再現できるかの検査であり、端点の間の連続性を証明するものではない。
例えば $1/(x - c)$ の極を挟む符号の変化には、中間値の定理を使えない。
観測のノイズや外部の状態で関数値が変わる問題では、同じ区間を再利用するときに注意する。

## 実行の共有と再利用

`find_bracket` と `find_bracket_with_options` は新しい逐次の実行で区間を探す。
`find_bracket_scoped` は呼び出し側の実行スコープを共有するので、内側の探索も全体の評価回数の上限と取り消しに従う。
スカラーの区間法には外部の作業領域はなく、固定の大きさの状態だけを使う。
同じ方法・設定・関数は繰り返し使えるが、前の求解の途中から再開する API はない。

## まとめ

符号の変わる区間が分からないときは、`find_bracket` か `find_bracket_with_options` で推測値か二つのシードから区間を広げ、得られた `Bracket` を区間法に渡す。
単調性を宣言できる関数では `Increasing` か `Decreasing` を指定すると、根のある側へだけ広げる。
正の量のように片側だけの定義域を持つ問題では、`with_domain` と `BracketExpansion::Multiplicative` を組み合わせ、桁にわたって広がる区間を避ける。
返る区間と `Bracket::verify` の結果は評価した端点の符号の記録であり、端点の間の連続性は呼び出し側の仮定である。
