[継続法による解の枝の追跡](../continuation-and-deflation/)は、一つの解の枝を予測子と修正子でたどる方法を扱った。
同じ継続の仕組みは次の三つの場面でも使える。
一つ目は良い初期値がない方程式を、解の分かっている方程式からの継続で解くホモトピーである。
二つ目は長い継続を途中で止めて再開するための状態の保存である。
三つ目はたどっている枝の上で分岐点の候補を見つける診断である。

## ホモトピー

解きたい方程式 $\mathbf{G}(\mathbf{x}) = \mathbf{0}$ の良い初期値がないとき、解が分かっている方程式 $\mathbf{S}(\mathbf{x}) = \mathbf{0}$ から

$$
\mathbf{H}(\mathbf{x}, \lambda) = (1 - \lambda)\,\mathbf{S}(\mathbf{x}) + \lambda\,\mathbf{G}(\mathbf{x})
$$

を $\lambda = 0$ から 1 まで継続する方法をホモトピー法という。
`LinearHomotopy::new(&start, &target)` は同じ次元 $n$ の二つの正方の写像 $\mathbf{S}$、$\mathbf{G}$ から、$\lambda$ を最後の入力に持つ $\mathbf{H}: \mathbb{R}^{n+1} \to \mathbb{R}^n$ を作り、`ContinuationProblem` に渡せる。
$\mathbf{H}$ の残差 1 回は $\mathbf{S}$ と $\mathbf{G}$ の残差を 1 回ずつ、方向微分 1 回は両方の方向微分と残差を 1 回ずつ使う。
途中で枝が折り返すと $\lambda$ が 1 に届く前に戻り、分岐点に当たると修正子が失敗することがある。
`ContinuationPath::Parameters(vec![1.0])` なら $\lambda = 1$ で正確に止まるが、折り返し点は越えられない。
擬弧長継続は折り返し点を越えられるが、$\lambda = 1$ で止まるとは限らないので、履歴の $\lambda$ が 1 をまたぐ点を探し、その近くの点を初期値にして元の $\mathbf{G}$ を解き直す。
Chow–Mallet-Paret–Yorke の確率 1 のホモトピー（写像の条件のもとで、ほとんどすべての始点から $\lambda = 1$ に届く）や、多項式系のすべての解を求める複素数のホモトピーは提供しない。

複素数の方程式は `RealifiedProblem` で実部と虚部を交互に並べた実座標の写像に変換してから使う。
`RealifiedProblem::square` は正方の写像（Newton 法やデフレーション用）、`RealifiedProblem::with_real_parameter` は最後の入力だけを実数のパラメータにした継続用である。
変換は写像が正則（複素微分可能）であることを仮定し、方向微分を複素数の積 $G'(\mathbf{z})\mathbf{v}$ として計算するので、正則でない写像は実数の写像として直接与える。
`with_real_parameter` は $\lambda$ を虚部 0 の複素数として写像に渡す。

## 状態の保存と再開

`Continuation` は経路と設定、`ContinuationState` は受理した点、接線、履歴、進んだ距離を持つ。
`ContinuationWorkspaceRequirements` に従って準備する `ContinuationWorkspace` は、補正や接線の計算に使う一時領域である。
作業領域は解の続きを持たないので、再開には状態から作ったチェックポイントを渡す。
`ContinuationState::history()` はシードを含む受理点ごとの `ContinuationObservation`（$\lambda$、擬弧長、元の残差ノルム、修正子の反復、退けた提案の数、折り返し点の候補、診断）を持ち、座標は `history_point(i)` で読む。

受理済みの状態から `checkpoint()` で作る `ContinuationCheckpoint` は、メモリ上の再開用の複製である。
永続化するファイルの形式は定めない。
`Continuation::resume` は経路と設定、問題の形、保存した状態の整合性を検査してから呼び出し側の状態を戻し、1 点だけ進める。
保存前に消費した局所の計算量は引き継ぎ、実行コンテキストと上限は再開のときに新しく渡す。
検査に失敗した場合は、チェックポイントと呼び出し側の状態を変更しない。

次のセルは円 $F(x, \lambda) = x^2 + \lambda^2 - 1$ をシード $(-1, 0)$ から擬弧長 $s$ だけたどる。
受理点 $k$ の時点でチェックポイントを取り、新しい状態と作業領域に `resume` で戻して終わりまで進め、中断しない経路と比べる。
表の「試行した刻みの数」は `ContinuationState::iterations()` の値で、退けた試行も含む。
受理した点の擬弧長の合計は $s$ だが、円周上の真の弧長 $\theta$（シードから反時計回りに測った角）は 1 歩ごとに $\arcsin\Delta s - \Delta s \approx \Delta s^3/6$ だけ長くなる。
この差 $\theta - s$ を独立な検算として出す。
最後の判定は、二つの経路がどちらも `Complete` なら satisfied にし、終点の差を添える。

```rust
//| id: rootfind-continuation-checkpoint
//| ref: rootfind-continuation-checkpoint
//| title: 円の解の枝を途中のチェックポイントから再開して比べる
//| run: reactive
//| crates: [scioxide-core, scioxide-rootfind]
//| inputs:
//|   arclength: {"type":"range","label":"たどる擬弧長 s [-]","description":"π/2 よりわずかに手前（真の弧長 θ = π/2）で折り返し点 (0, 1) に達する。","min":1,"max":3,"step":0.25,"value":2.5}
//|   saved: {"type":"range","label":"チェックポイントを取る受理点 k [-]","description":"補正したシードを k = 0 として数えた受理点の番号。","min":0,"max":6,"step":1,"value":3}
//| cases:
//|   - {"id":"before-turn","label":"s = 1.5（折り返し点の手前）","description":"終点は λ = 0.998033276 で、まだ折り返し点 (0, 1) の手前の x < 0 の側にある。","inputs":{"arclength":1.5}}
//|   - {"id":"past-turn","label":"s = 1.75（折り返し点の先）","description":"終点は x = 0.187869227 で、折り返し点を越えて λ が減る側に入っている。","inputs":{"arclength":1.75}}
//|   - {"id":"seed-checkpoint","label":"k = 0（補正したシードで保存）","description":"シードで取ったチェックポイントから再開しても、16 点・累積 15 回の反復を再現する。","inputs":{"saved":0}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"paths","path":"/rows/0/1","equals":"Complete"}
//|       - {"artifact":"paths","path":"/rows/1/1","equals":"Complete"}
//|       - {"artifact":"paths","path":"/rows/1/2","equals":16}
//|       - {"artifact":"paths","path":"/rows/0/3","approx":{"value":0.809947218,"atol":5e-10}}
//|       - {"artifact":"paths","path":"/rows/1/3","approx":{"value":0.809947218,"atol":5e-10}}
//|       - {"artifact":"paths","path":"/rows/1/4","approx":{"value":0.586502775,"atol":5e-10}}
//|       - {"artifact":"paths","path":"/rows/1/5","equals":15}
//|       - {"artifact":"paths","path":"/rows/1/6","range":{"max":1e-15}}
//|       - {"artifact":"paths","path":"/rows/1/7","approx":{"value":1.49e-2,"atol":5e-5}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: before-turn
//|     expect:
//|       - {"artifact":"paths","path":"/rows/1/3","approx":{"value":-0.062686362,"atol":5e-10}}
//|       - {"artifact":"paths","path":"/rows/1/4","approx":{"value":0.998033276,"atol":5e-10}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: past-turn
//|     expect:
//|       - {"artifact":"paths","path":"/rows/1/3","approx":{"value":0.187869227,"atol":5e-10}}
//|       - {"artifact":"paths","path":"/rows/1/4","approx":{"value":0.982194051,"atol":5e-10}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: seed-checkpoint
//|     expect:
//|       - {"artifact":"paths","path":"/rows/1/2","equals":16}
//|       - {"artifact":"paths","path":"/rows/1/5","equals":15}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
use scioxide_core::{Budget, ExecutionContext, RealScalar, ResidualTolerance};
use scioxide_rootfind::{
    Continuation, ContinuationCheckpoint, ContinuationOptions, ContinuationPath,
    ContinuationProblem, ContinuationState, ResidualFn, RootTermination,
};
// F(x, λ) = x² + λ² − 1 と方向微分 F_y v = 2(x v_x + λ v_λ)。y = (x, λ)。
let circle = ResidualFn::with_parameter(1, |y: &[f64], out: &mut [f64]| {
    out[0] = y[0] * y[0] + y[1] * y[1] - 1.0;
    Ok(())
})
.with_jvp(|y: &[f64], v: &[f64], out: &mut [f64]| {
    out[0] = 2.0 * (y[0] * v[0] + y[1] * v[1]);
    Ok(())
});
let problem = ContinuationProblem::new(&circle).map_err(|e| e.to_string())?;
let options = ContinuationOptions::new(
    0.05,
    1e-8,
    0.2,
    Budget::try_from(400).map_err(|e| e.to_string())?,
)
.map_err(|e| e.to_string())?
.with_residual_tolerance(ResidualTolerance::new(1e-12, 0.0).map_err(|e| e.to_string())?);
let continuation = Continuation::new(ContinuationPath::PseudoArclength(arclength), options)
    .map_err(|e| e.to_string())?;
// 新しい状態と作業領域で終わりまで進める。from があれば最初の 1 点を resume で進め、
// 受理点 k に達した時点のチェックポイントを返す。
let trace = |from: Option<&ContinuationCheckpoint<f64>>| {
    let mut state = continuation
        .state(&problem, &[-1.0, 0.0])
        .map_err(|e| e.to_string())?;
    let mut workspace = continuation
        .workspace(&problem)
        .map_err(|e| e.to_string())?;
    let (mut pending, mut kept) = (from, None);
    loop {
        let sequential = ExecutionContext::sequential();
        let report = match pending.take() {
            Some(c) => continuation.resume(
                &problem,
                c,
                &mut state,
                |_, _| Ok(()),
                &mut workspace,
                sequential,
            ),
            None => continuation.advance(
                &problem,
                &mut state,
                |_, _| Ok(()),
                &mut workspace,
                sequential,
            ),
        }
        .map_err(|e| e.to_string())?;
        if kept.is_none() && state.history().len() == saved as usize + 1 {
            kept = Some(state.checkpoint().map_err(|e| e.to_string())?);
        }
        if report.termination() != RootTermination::Advanced {
            return Ok::<_, String>((state, kept));
        }
    }
};
let (whole, checkpoint) = trace(None)?;
let checkpoint = checkpoint.ok_or("経路が受理点 k に届く前に終わった")?;
let (resumed, _) = trace(Some(&checkpoint))?;
// 独立な検算: シード (−1, 0) から反時計回りに測った真の弧長 θ と、要求した擬弧長 s の差。
let row = |name: &str, state: &ContinuationState<f64>| {
    let (x, lambda) = (state.point()[0], state.point()[1]);
    (
        name.to_string(),
        state.termination().to_string(),
        state.history().len(),
        x,
        lambda,
        state.iterations(),
        state.residual_norm(),
        RealScalar::atan2(lambda, -x) - arclength,
    )
};
let rows = vec![
    row("中断なし", &whole),
    row("チェックポイントから再開", &resumed),
];
let fixed9 = serde_json::json!({ "notation": "standard", "fractionDigits": 9 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "経路" },
    { "key": "1", "label": "終了状態" },
    { "key": "2", "label": "受理点の数 [点]", "type": "integer" },
    { "key": "3", "label": "終点の x [-]", "type": "number", "format": fixed9 },
    { "key": "4", "label": "終点の λ [-]", "type": "number", "format": fixed9 },
    { "key": "5", "label": "試行した刻みの数 [回]", "type": "integer" },
    { "key": "6", "label": "残差ノルム [-]", "type": "number", "format": sci2, "nullText": "未評価" },
    { "key": "7", "label": "真の弧長 θ − 擬弧長 s [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "paths" })
);

// 再開した経路の終点と中断しない経路の終点の差（最大成分）。
let gap = whole
    .point()
    .iter()
    .zip(resumed.point())
    .map(|(a, b)| (a - b).abs())
    .fold(0.0, f64::max);
let termination = resumed.termination();
let outcome = if termination.is_success() && whole.is_success() {
    Outcome::satisfied("再開した経路も要求した擬弧長を最後までたどった")
} else {
    Outcome::partial("経路が要求した擬弧長の途中で止まった")
};
emit_outcome!(
    outcome
        .status(termination.to_string())
        .diagnostic("終点の差", gap, None)
        .diagnostic("試行した刻みの数", resumed.iterations() as f64, None)
);
```

既定の $s = 2.5$、$k = 3$ では、中断しない経路と再開した経路はどちらも 16 点を受理して `Complete` で終わり、終点 $(0.809947218, 0.586502775)$ も試行した刻みの数 15 回も一致する。
試行の数が一致するのは、チェックポイントが保存前の計算量を引き継ぐからである。
終点の残差は $2.2 \times 10^{-16}$、$\theta - s = 1.49 \times 10^{-2}$ である。
刻みは 0.05 から 1.5 倍ずつ 0.075、0.1125、0.16875 と増えて上限 0.2 に達し、0.2 の 10 歩と最後の端数 0.09375 の 1 歩が続く（シードを含めて 16 点）。
1 歩あたり $\arcsin \Delta s - \Delta s$ の見積もりでは、0.2 の 10 歩で $1.36 \times 10^{-2}$、残りの 5 歩で $1.3 \times 10^{-3}$ が加わり、合計 $1.49 \times 10^{-2}$ になって実測と合う。
真の弧長 $\theta$ は $s$ より長いので、折り返し点 $(0, 1)$（$\theta = \pi/2$）には π/2 よりわずかに手前の $s \approx 1.56$ で達し、その先では $\lambda$ が減る側に入る。

## 分岐の診断

`ContinuationOptions::with_dense_diagnostics(threshold)` を指定すると、受理点ごとに $[F_{\mathbf{x}}\ F_\lambda]$ を $n + 1$ 回のヤコビ行列とベクトルの積から列ごとに組み立て、密な行列で診断を計算する（1 点あたりメモリ使用量 $O(n^2)$、計算量 $O(n^3)$）。
階数は特異値を相対の閾値 `threshold` と比べて推定し、縁付き行列 $B = \begin{bmatrix} F_{\mathbf{y}} \\ \mathbf{t}^{\mathsf T}M \end{bmatrix}$ の行列式の符号は LU 分解で求める。
`ContinuationDiagnostic` は推定の階数 `augmented_rank`、最小と最大の特異値の比 `reciprocal_condition`、行列式の符号 `bordered_sign`、分岐点の候補 `branch_point_candidate` を持つ。
密な診断は、階数が $n$ より小さいか LU 分解が $B$ を特異と判定したとき候補とする。
単純な分岐点の前後では $\det B$ の符号が変わるので、継続は前の受理点と `bordered_sign` が逆の符号になった点も候補にする。
折り返し点では $F_{\mathbf{y}}$ の階数が $n$ のままで $B$ も正則なので、この診断は折り返し点を候補にしない。
折り返し点は接線の $\lambda$ 成分の符号の変化（`turning_point_candidate`）で見つける。
大規模・疎な問題では `ContinuationDiagnosticProvider` を実装し、`ContinuationProblem::with_diagnostic` で密な診断の代わりに渡す。
どの値も数値的な推定で、分岐点の存在の証明ではない。
診断を指定しない場合の `diagnostic()` は `None` で、零とみなしてはいけない。

## まとめ

良い初期値がない方程式は、`LinearHomotopy` で解の分かっている方程式からつなぎ、継続の終わりの近くの点を初期値にして元の方程式を解き直す。
折り返し点や分岐点に当たると $\lambda = 1$ に届かないことがあり、すべての解を求める複素数のホモトピーは提供しない。
`ContinuationState` は解の続きを、`ContinuationWorkspace` は一時領域を持つので、再開には状態から作った `ContinuationCheckpoint` を使う。
再開は保存前の計算量を引き継ぎ、中断しない経路と同じ点と試行の数を再現する。
`with_dense_diagnostics` や `ContinuationDiagnosticProvider` の診断は分岐点の候補を示す推定であり、存在の証明ではない。
