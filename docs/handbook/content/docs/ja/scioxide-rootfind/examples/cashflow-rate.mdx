投資の採算を評価するとき、正味現在価値（NPV: Net Present Value）を 0 にする割引率を内部収益率（IRR: Internal Rate of Return）と呼ぶ。

初期投資額を $C_0 < 0$（資金の流出）、第 $t$ 期末のキャッシュフローを $C_t$（流入または流出）とすると、年利率 $r$ に対する NPV は次の式で定義される。

$$
\operatorname{NPV}(r) = \sum_{t=0}^m \frac{C_t}{(1 + r)^t} = C_0 + \frac{C_1}{1 + r} + \frac{C_2}{(1 + r)^2} + \dots + \frac{C_m}{(1 + r)^m} \qquad (r > -1)
$$

IRR の方程式 $\operatorname{NPV}(r) = 0$ に $q^m$（$q = 1 + r$）を掛けると、$q$ の $m$ 次の多項式の方程式になる。
$r = -1$（$q = 0$）は NPV の特異点で、キャッシュフローの符号の並びによっては $r > -1$ に実根が複数ある。

## 通常型と非通常型のキャッシュフロー

### 通常型：IRR が一つに決まる場合

初期投資の後に正の回収だけが続く並び（$C_0 < 0$、$t \ge 1$ で $C_t > 0$）を通常型と呼ぶ。
このとき導関数は

$$
\frac{d \operatorname{NPV}}{dr} = -\sum_{t=1}^m \frac{t C_t}{(1 + r)^{t+1}} < 0 \qquad (r > -1)
$$

で、NPV は $r > -1$ で狭義単調減少する。
さらに $r \to -1^+$ で $\operatorname{NPV} \to +\infty$、$r \to +\infty$ で $\operatorname{NPV} \to C_0 < 0$ なので、中間値の定理と単調性から IRR は $r > -1$ にちょうど一つある。
その IRR が正になるのは、$\operatorname{NPV}(0) = \sum_t C_t > 0$（回収の合計が投資を上回る）ときである。

### 非通常型：IRR が複数ありうる場合

設備の撤去費や環境の復元費のように、終わりに大きな支出 $C_m = -D < 0$ がある並び（例えば $(-, +, +, -)$）を非通常型と呼ぶ。

初期投資 100 万円、1 年後と 2 年後に各 $A$ 万円の回収、3 年後に撤去費 $D$ 万円を支払うモデルの NPV [万円] は次のとおりである。

$$
\operatorname{NPV}(r) = -100 + \frac{A}{1+r} + \frac{A}{(1+r)^2} - \frac{D}{(1+r)^3}
$$

$q = 1 + r > 0$ と置き、両辺に $q^3$ を掛けると次の 3 次方程式になる。

$$
P(q) = -100 q^3 + A q^2 + A q - D = 0
$$

撤去費 $D > 0$ のとき係数の符号は $-100 \to +A \to -D$ で 2 回変わるので、Descartes の符号則から、正の実根 $q > 0$ は重複度を数えて 2 個か 0 個である。
$D = 0$ では $P(q) = q(-100q^2 + Aq + A)$ となり、$q = 0$ を除くと正の根は一つで、通常型と同じく IRR は一つになる。

| 利率の範囲 | 撤去費 $D > 0$ がある場合の NPV |
|---|---|
| $r \to -1^+$ | 撤去の項 $-D/q^3$ が支配し、$-\infty$ に発散する |
| 中間の利率 | 回収額 $A$ が十分大きければ正になる |
| $r \to +\infty$ | 割り引いた項がすべて 0 に近づき、初期投資の $-100$ 万円に近づく |

回収額 $A$ が十分大きければ、NPV は負から正へ上がってから再び負へ下がり、二つの IRR $r_1 < r_2$ を持つ。

### 二つの IRR が重なる撤去費

$A$ を固定して $D$ を大きくすると $P$ のグラフは下へ平行移動し、二つの正の根は近づいて、ある撤去費 $D^*$ で重根になる。
重根では $P(q) = 0$ と $P'(q) = -300 q^2 + 2 A q + A = 0$ が同時に成り立つ。
$P'(q) = 0$ の正の根と、そこでの撤去費は

$$
q^* = \frac{A + \sqrt{A^2 + 300 A}}{300}, \qquad D^* = -100 (q^*)^3 + A (q^*)^2 + A q^*
$$

である。
$0 < D < D^*$ では IRR が二つ、$D > D^*$ では IRR がない。
$A = 70$ 万円では $D^* \approx 49.75$ 万円、$r^* = q^* - 1 \approx -23.0$ % で、$A = 100$ 万円では $q^* = 1$、$D^* = 100$ 万円（$r^* = 0$）になる。
$D$ が $D^*$ に近いと二つの根の間隔は $\sqrt{D^* - D}$ に比例して狭くなり、重根の近くでは NPV が符号を変えないので、符号の変化を探す方法では見つけにくい。

## 対数の座標での走査と Brent 法

利率 $r$ を等間隔に走査すると、特異点 $r = -1$ の近くの急な変化を粗くしか捉えられない。
そこで、無次元の対数成長率

$$
u = \ln(1 + r) \iff 1 + r = e^u
$$

を等間隔に分ける。
$r = -0.95$（$u \approx -3.0$）から $r = 4$（$u \approx 1.6$）までを、隣り合う走査点で複利の倍率 $1 + r$ の比が一定になるように調べる。

走査で両端の NPV の符号が変わった小区間ごとに Brent 法を適用し、それぞれの区間の根を求める。
走査点で NPV がちょうど 0 になった場合も、`Brent` は端点の根を受け付けるので、その小区間も解く。
Brent 法は逆 2 次補間と割線法の更新を、根を挟む区間を保つ二分法で守る方法で、詳しくは[区間を保つ求根法](../../algorithms/bracketing-methods/)にある。
走査の間隔より近い二つの根や、符号を変えない重根は見落としうるので、走査の細かさは根の間隔に合わせる。

次のブロックは、このページの二つのセルが共有する定義である。
`npv` が上の NPV の式、`log_grid` が $u$ を $n$ 等分した走査点 $r = e^u - 1$、`sign_change_intervals` が Brent 法に渡す小区間の選び方に対応する。
$\ln(1 + r)$ と $e^u - 1$ は、$r$ と $u$ が 0 に近いときに桁落ちしない `RealScalar::ln_1p` と `RealScalar::exp_m1` で計算する。

```rust
//| id: rootfind-cashflow-model
//| kind: definitions
//| title: NPV と対数の座標での走査
//| crates: [scioxide-core]
use scioxide_core::RealScalar;

/// NPV(r) = −100 + A/(1 + r) + A/(1 + r)² − D/(1 + r)³ [万円]。A は回収額、D は撤去費 [万円]。
pub(crate) fn npv(inflow: f64, cost: f64, rate: f64) -> f64 {
    let q = 1.0 + rate;
    -100.0 + inflow / q + inflow / (q * q) - cost / (q * q * q)
}

/// u = ln(1 + r) を [ln(1 + r_min), ln(1 + r_max)] で n 等分した走査点 r = e^u − 1。
pub(crate) fn log_grid(r_min: f64, r_max: f64, n: usize) -> Vec<f64> {
    let (u_min, u_max) = (RealScalar::ln_1p(r_min), RealScalar::ln_1p(r_max));
    (0..=n)
        .map(|i| RealScalar::exp_m1(u_min + (u_max - u_min) * i as f64 / n as f64))
        .collect()
}

/// Brent 法に渡す小区間の左端の番号。両端で符号が変わる小区間と、
/// 左端（最後の小区間は右端も）で値がちょうど 0 の小区間を選ぶ。
pub(crate) fn sign_change_intervals(values: &[f64]) -> Vec<usize> {
    let last = values.len() - 2;
    (0..=last)
        .filter(|&j| {
            let (left, right) = (values[j], values[j + 1]);
            left == 0.0
                || (left < 0.0 && right > 0.0)
                || (left > 0.0 && right < 0.0)
                || (j == last && right == 0.0)
        })
        .collect()
}
```

## 撤去費のあるキャッシュフローの IRR

次のセルは回収額 $A$、撤去費 $D$、走査の上限の利率を変え、$u$ を 640 等分した走査で符号の変わる小区間を集め、各区間を `Brent` で解く。
`with_residual_tolerance` で絶対の基準 $\lvert \operatorname{NPV} \rvert \le 10^{-11}$ 万円（$10^{-7}$ 円）を与える。
区間の幅が $4\varepsilon(1 + \max(\lvert a \rvert, \lvert b \rvert))$ 以下に縮むという既定の条件に加えて、金額の単位の残差でも受理するためである。
表は小区間の両端、`Brent` が返した点、その点での NPV、関数の評価回数、終了理由を示す。
終了理由が成功でない区間の点は IRR として数えず、すべての区間で成功したかをセルの最後の判定に示す。
走査の範囲に符号の変わる小区間がなければ Brent 法は実行せず、判定を `failed` にして $\lvert \operatorname{NPV} \rvert$ が最小の走査点を示す。

```rust
//| id: rootfind-cashflow-rate
//| ref: rootfind-cashflow-rate
//| title: 撤去費のあるキャッシュフローの IRR を符号の変わる区間ごとに求める
//| run: reactive
//| uses: [rootfind-cashflow-model]
//| crates: [scioxide-core, scioxide-rootfind]
//| inputs:
//|   annual_inflow: {"type":"range","label":"1・2 年後の各回収額 A [万円]","description":"正の中間キャッシュフローを変える。","min":45,"max":100,"step":1,"value":70}
//|   decommissioning_cost: {"type":"range","label":"3 年後の撤去費 D [万円]","description":"末尾の負のキャッシュフローと IRR の個数を変える。","min":0,"max":180,"step":5,"value":40}
//|   maximum_rate_percent: {"type":"range","label":"走査の上限の利率 [%/年]","description":"高い利率の側で走査・表示する範囲を変える。","min":100,"max":800,"step":25,"value":400}
//| cases:
//|   - {"id":"no-decommissioning","label":"D = 0（撤去費なし）","description":"通常型のキャッシュフローになり、IRR は 25.69 % の一つだけになる。","inputs":{"decommissioning_cost":0}}
//|   - {"id":"large-inflow","label":"A = 100（回収額が大きい）","description":"二つの IRR は −67.22 % と 49.08 % に離れる。","inputs":{"annual_inflow":100}}
//|   - {"id":"no-sign-change","label":"D = 180（撤去費が大きい）","description":"走査の範囲に符号の変化がなく、|NPV| が最小の走査点だけを示す。","inputs":{"decommissioning_cost":180}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"irr","path":"/rows/0/2","approx":{"value":-50.0,"atol":5e-11}}
//|       - {"artifact":"irr","path":"/rows/1/2","approx":{"value":0.0,"atol":5e-11}}
//|       - {"artifact":"irr","path":"/rows/0/3","range":{"min":-1e-11,"max":1e-11}}
//|       - {"artifact":"irr","path":"/rows/0/4","equals":2}
//|       - {"artifact":"irr","path":"/rows/1/4","equals":5}
//|       - {"artifact":"irr","path":"/rows/0/5","equals":"ResidualTolerance"}
//|       - {"artifact":"irr","path":"/rows/1/5","equals":"ResidualTolerance"}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: no-decommissioning
//|     expect:
//|       - {"artifact":"irr","path":"/rows/0/2","approx":{"value":25.69,"atol":5e-3}}
//|       - {"artifact":"irr","path":"/rows/0/5","equals":"ResidualTolerance"}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: large-inflow
//|     expect:
//|       - {"artifact":"irr","path":"/rows/0/2","approx":{"value":-67.22,"atol":5e-3}}
//|       - {"artifact":"irr","path":"/rows/1/2","approx":{"value":49.08,"atol":5e-3}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: no-sign-change
//|     expect:
//|       - {"path":"/outputs/1/state","equals":"failed"}
//|       - {"path":"/outputs/1/diagnostics/0/value","approx":{"value":94.80,"atol":5e-3}}
//|       - {"path":"/outputs/1/diagnostics/1/value","approx":{"value":-69.97,"atol":5e-3}}
use scioxide_core::{EvaluationRole, Interval, NumericScalar, ResidualTolerance};
use scioxide_rootfind::{Brent, ScalarFn, ScalarRootOptions, ScalarRootSolver};

let (a, d) = (annual_inflow, decommissioning_cost);
let function = ScalarFn::new(|r: f64| Ok(npv(a, d, r)));
// |NPV| ≤ 1e-11 万円でも受理する（相対の部分は 0）。
let options = ScalarRootOptions::default()
    .with_residual_tolerance(ResidualTolerance::new(1e-11, 0.0).map_err(|e| e.to_string())?);
let grid = log_grid(-0.95, maximum_rate_percent / 100.0, 640);
let values: Vec<f64> = grid.iter().map(|&r| npv(a, d, r)).collect();
let (mut rows, mut found, mut unsuccessful) = (Vec::new(), Vec::new(), 0_usize);
for j in sign_change_intervals(&values) {
    let interval = Interval::new(grid[j], grid[j + 1]).map_err(|e| e.to_string())?;
    let result = Brent
        .solve(&function, interval, &options)
        .map_err(|e| e.to_string())?;
    // 成功の終了理由でなければ IRR として数えない。
    if result.is_success() {
        found.push(result.point());
    } else {
        unsuccessful += 1;
    }
    rows.push((
        100.0 * grid[j],
        100.0 * grid[j + 1],
        100.0 * result.point(),
        result.residual(),
        result.counts().provider(EvaluationRole::Function),
        result.termination().to_string(),
    ));
}
// IRR は縦線、NPV = 0 は横線で示す。
let zero_line =
    serde_json::json!({ "kind": "line", "axis": "y", "value": 0.0, "label": "NPV = 0" });
let mut marks = vec![zero_line];
marks.extend(found.iter().map(|&r| {
    serde_json::json!({ "kind": "line", "axis": "x", "value": 100.0 * r, "label": "IRR" })
}));
let curve: Vec<[f64; 2]> = grid
    .iter()
    .zip(&values)
    .map(|(&r, &v)| [100.0 * r, v])
    .collect();
emit_line_chart!(
    &vec![serde_json::json!({ "name": "NPV(r)", "points": curve })],
    options = &serde_json::json!({
        "xLabel": "利率 r [%/年]",
        "yLabel": "正味現在価値 NPV [万円]",
        "yMin": -150.0,
        "yMax": 150.0,
        "annotations": marks
    })
);
if rows.is_empty() {
    // 符号の変化がなければ |NPV| が最小の走査点を示す（根がないことの証明ではない）。
    let (r, v) = grid
        .iter()
        .zip(&values)
        .fold((grid[0], values[0]), |best, (&r, &v)| {
            if NumericScalar::abs(v) < NumericScalar::abs(best.1) {
                (r, v)
            } else {
                best
            }
        });
    emit_outcome!(
        Outcome::failed("走査の範囲に符号の変わる小区間がなく、IRR を求めていない")
            .explanation("根がないことの証明ではない。3 次式のすべての根で確かめる。")
            .status("符号の変化なし")
            .diagnostic("|NPV| が最小の走査点の利率", 100.0 * r, Some("%"))
            .diagnostic("その点の NPV", v, Some("万円"))
    );
} else {
    let percent = serde_json::json!({ "fractionDigits": 4 });
    let fixed10 = serde_json::json!({ "fractionDigits": 10 });
    let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
    let columns = serde_json::json!([
        { "key": "0", "label": "小区間の左端 [%]", "type": "number", "format": percent },
        { "key": "1", "label": "小区間の右端 [%]", "type": "number", "format": percent },
        { "key": "2", "label": "Brent 法の点 [%]", "type": "number", "format": fixed10 },
        { "key": "3", "label": "NPV [万円]", "type": "number", "format": sci2 },
        { "key": "4", "label": "関数の評価 [回]", "type": "integer" },
        { "key": "5", "label": "終了理由" }
    ]);
    let intervals = rows.len();
    emit_table_with_columns!(
        columns,
        rows,
        metadata = serde_json::json!({ "id": "irr" })
    );
    let outcome = if unsuccessful == 0 {
        Outcome::satisfied("符号の変わるすべての小区間で Brent 法が IRR を受理した")
    } else {
        Outcome::partial("Brent 法が受理の条件を満たさずに止まった小区間がある")
            .explanation("表の終了理由が成功でない行の点は IRR として数えていない。")
    };
    emit_outcome!(
        outcome
            .status(format!("成功 {}/{intervals}", intervals - unsuccessful))
            .diagnostic("符号の変わる小区間", intervals as f64, None)
            .diagnostic("受理しなかった小区間", unsuccessful as f64, None)
    );
}
```

既定の $A = 70$、$D = 40$ 万円では $-100q^3 + 70q^2 + 70q - 40 = -10(q - 1)(2q - 1)(5q + 4)$ と因数分解でき、IRR は $r = -50$ % と 0 % の二つになる（$q = -0.8$ は $r > -1$ の外）。
`Brent` はこの二つを `ResidualTolerance` で受理し、点での NPV は $1.1 \times 10^{-13}$ 万円と $1.4 \times 10^{-14}$ 万円、閉形式の根との差は $1.4 \times 10^{-14}$ % と $1.6 \times 10^{-14}$ % である。
既定の上限 400 % では $-50$ % の根が走査の中央の点（$u = \ln 0.5$）と数学的には一致するので、両端の 2 回の評価だけで受理される。
$0$ % の根は 5 回の評価で求まる。
$D = 0$ では IRR は 25.69 % の一つだけで、$A = 100$ では $-67.22$ % と 49.08 % の二つになる。

図の縦軸は $\pm 150$ 万円に固定しているので、$r$ が $-95$ % に近い側の急な変化は図の外に出る。
二つの IRR の間（$-50$ % < $r$ < 0 %）では NPV が正になり、その外では負になる。
同じプロジェクトに IRR が二つあると、「IRR が資本コストを上回れば採用する」という規則は使えない。
資本コスト $r_c$ での $\operatorname{NPV}(r_c)$ の符号のような、別の基準で判断する。

$D = 180$ や $A = 45$ では走査の範囲に符号の変化がなく、判定は `failed` になる。
$D = 180$ では NPV の最大が負の値にとどまり、$\lvert \operatorname{NPV} \rvert$ が最小の走査点 $r = 94.80$ % でも NPV は $-69.97$ 万円である。
走査だけでは根がないことは示せないので、次の節で 3 次式のすべての根から IRR の有無を確かめる。

## 3 次式のすべての根による検算

NPV が多項式に直せるこの例では、$P(q) = 0$ のすべての根を `polynomial_roots_with_options` で求めれば、$q > 0$ の実根から IRR の候補を漏れなく得られる。
これは走査とは別の計算なので、走査が根を見落としていないかの独立な検算になる。
次のセルは回収額 $A$ を固定して撤去費 $D$ を 0 から 180 万円まで 0.5 万円刻みで変え、各 $D$ で 3 次式の IRR の個数と、前のセルと同じ走査で選ぶ小区間の個数を比べる。
走査の分割数 $N$ を操作入力にして、粗い走査が近い二つの根を見落とす範囲を見る。
比べるのは走査の範囲 $-95$ % $\le r \le 400$ % にある根だけである。

既定の `PolynomialRootMethod::Auto` は 3 次式の根の候補を伴行列の固有値から作り、Aberth–Ehrlich 反復で改良してから後退誤差で検証する。
3 次式の根は `PolynomialRootReport` の終了理由が成功の場合だけ使い、そうでなければその $D$ で計算を止める。
表の後退誤差は掃引したすべての $D$ での `PolynomialRootReport::backward_error` の最大である。
361 個の $D$ のすべてで根が検証されたことを、セルの最後の判定に示す。

```rust
//| id: rootfind-cashflow-polynomial-roots
//| ref: rootfind-cashflow-polynomial-roots
//| title: 撤去費を掃引して 3 次式のすべての根と走査で選ぶ区間を比べる
//| run: reactive
//| uses: [rootfind-cashflow-model]
//| crates: [scioxide-core, scioxide-rootfind]
//| inputs:
//|   sweep_inflow: {"type":"range","label":"1・2 年後の各回収額 A [万円]","description":"二つの IRR が重なる撤去費 D* を変える。","min":45,"max":100,"step":1,"value":70}

//| tests:

//|       - {"artifact":"summary","path":"/rows/0/0","approx":{"value":49.7497,"atol":5e-5}}
//|       - {"artifact":"summary","path":"/rows/0/1","approx":{"value":-23.0217,"atol":5e-5}}
//|       - {"artifact":"summary","path":"/rows/0/2","equals":0}

//|       - {"artifact":"summary","path":"/rows/0/3","equals":71}
//|       - {"artifact":"summary","path":"/rows/0/4","equals":72}
//|   - case: close-roots-fine

//|       - {"artifact":"summary","path":"/rows/0/2","equals":0}

use scioxide_rootfind::{PolynomialRootOptions, polynomial_roots_with_options};

let (a, n) = (sweep_inflow, scan_intervals as usize);
let (r_min, r_max) = (-0.95_f64, 4.0_f64);
let grid = log_grid(r_min, r_max, n);
// 既定の設定で、方法は Auto。
let options = PolynomialRootOptions::default();
// 閉形式: P′(q*) = 0 の正の根 q* で二つの IRR が重なり、そのときの撤去費が D*。
let q_star = (a + RealScalar::sqrt(a * a + 300.0 * a)) / 300.0;
let d_star = -100.0 * RealScalar::powi(q_star, 3) + a * q_star * q_star + a * q_star;
let (mut lower, mut upper, mut lost) = (Vec::new(), Vec::new(), Vec::new());
let (mut missed, mut backward) = (Vec::new(), 0.0_f64);
for k in 0..=360 {
    let d = 0.5 * f64::from(k);
    // P(q) = −100q³ + Aq² + Aq − D の係数（定数項から昇べき順）。
    let cubic = polynomial_roots_with_options(&[-d, a, a, -100.0], &options)
        .map_err(|e| e.to_string())?;
    let report = cubic.report();
    if !report.is_success() {
        return Err(format!(
            "D = {d} 万円で 3 次式の根が検証されていない: {}",
            report.termination()
        ));

    backward = report
        .backward_error()
        .map_or(backward, |e| backward.max(e));
    // q > 0 の実根のうち、走査の範囲にある r = q − 1 を IRR とする。

        .iter()
        .filter(|q| q.im == 0.0 && q.re > 0.0)
        .map(|q| q.re - 1.0)
        .filter(|&r| r_min <= r && r <= r_max)
        .collect();

        let branch = if r < q_star - 1.0 {
            &mut lower
        } else {
            &mut upper
        };
        branch.push([d, 100.0 * r]);

    // 前のセルと同じ規則で、走査が Brent 法に渡す小区間を数える。
```

図の実線は 3 次式の根から得た二つの IRR の枝、縦線は閉形式の $D^*$、記号は走査で選ぶ小区間の個数が 3 次式の IRR の個数と合わない $D$ での根である。
既定の $A = 70$ 万円、$N = 640$ では、$D^* = 49.7497$ 万円（$r^* = -23.02$ %）で二つの枝がつながり、それより右には IRR がない。
361 個のすべての $D$ で個数が一致し、後退誤差の最大は $2.6 \times 10^{-16}$ で、倍精度の丸めの程度である。
$D$ が小さいと小さい IRR は $r \to -100$ % に近づき、$0 < D \le 3.5$ 万円では走査の範囲 $r \ge -95$ % の外に出るので、図にも比較にも入らない。

$A = 85$ 万円では $D^* = 72.48$ 万円で、$N = 20$ にすると $D = 71$〜72 万円の 3 個の $D$ で走査が二つの IRR を見落とす。
二つの根が同じ小区間に入り、両端の NPV がどちらも負になるためである。
$N = 40$ に細かくすると、この見落としはなくなる。
$A = 100$ 万円では $D^* = 100$ 万円が掃引の刻みにちょうど乗り、$D = 100$ で $q = 1$ が重根になる。
NPV は $r = 0$ で 0 に接するだけで符号を変えないので、$N = 640$ でも走査はこの根を見つけない。
3 次式の根はこの重根を二つの実根として返すので、個数の不一致として表に現れる。
重根の位置は係数の摂動に対して $\sqrt{u}$ の程度（$u$ は単位丸め誤差）でしか決まらないので、重根の近くの IRR は桁数を割り引いて読む。

## まとめ

撤去費のように終わりに支出があるキャッシュフローでは、IRR は二つあることも、一つもないこともある。
対数の座標 $u = \ln(1 + r)$ で走査して符号の変わる小区間を集め、各区間を `Brent` で解けば区間ごとの IRR が求まるが、走査点の間隔より近い二つの根と重根は見落としうる。
NPV が多項式に直せる場合は、`polynomial_roots_with_options` ですべての根を求め、$q > 0$ の実根の個数と走査で見つけた個数を照らし合わせる。
個数が合わないときは走査を細かくするか、重根の条件 $P = P' = 0$ のような閉形式で境目を確かめる。
IRR が二つある案件は IRR だけで採否を決めず、資本コストでの NPV で判断する。
