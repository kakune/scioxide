FIR フィルタの適用、音響の伝搬の合成、画像の平滑化は、どれも有限の記録と係数の畳み込みである。
二つの記録の時間差の推定や、既知の波形の検出には相関を使う。
このページでは`scioxide-signal` の畳み込みと相関の定義、出力の範囲とラグの並び、直接和と FFT の選択と誤差、多次元の配列と逐次の入力への拡張、畳み込みの逆演算を説明する。
DFT による巡回畳み込みの定理とゼロパディングの長さの導出は、`scioxide-fft` の章の[線形畳み込みと巡回畳み込み](oxref:fft-convolution)を前提とし、ここでは繰り返さない。

## 線形畳み込みと出力の範囲

長さ $N$ の記録 $a$ と長さ $M$ の係数（核）$b$ の線形畳み込みを、区間外の標本を 0 とみなして

$$
y[n] = (a * b)[n] = \sum_{k=0}^{M-1} a[n-k]\, b[k], \qquad n = 0, \dots, N + M - 2
$$

と定義する。
$a[n-k]\,b[k]$ が 0 でないのは $0 \le k \le M-1$ かつ $0 \le n-k \le N-1$ のときだけなので、出力の長さは $N + M - 1$ である。
$A(z) = \sum_n a[n] z^{-n}$ のような $z^{-1}$ の多項式で書くと、$Y(z) = A(z)\,B(z)$ となり、線形畳み込みは多項式の積と同じ演算である。
直接和では乗算が $NM$ 回要る。

`convolve(a, b)` はこの全体（`ConvolutionExtent::Full`）を返す。
Plan `ConvolutionNdPlan` では`ConvolutionOptions::with_extent` で全体の一部を切り出せる。

| `ConvolutionExtent` | 出力の長さ | 全体の中の位置 | 主な用途 |
|---|---|---|---|
| `Full` | $N + M - 1$ | 添字 $0$ から | 系の応答の全体、多項式の積 |
| `Same` | $N$ | 添字 $\lfloor (M-1)/2 \rfloor$ から | 記録と同じ長さの平滑化（奇数長の対称核で遅れが 0） |
| `Valid` | $N - M + 1$（$N \ge M$ が必要） | 添字 $M-1$ から | 核全体が記録に重なる位置だけ |
| `Circular` | $N$ | 巡回畳み込み（下の節） | 周期的な記録 |

`Valid` で $N < M$ の場合は準備の時点で `InvalidInput` になる。
`convolve`、`correlate`、`convolve_circular` は、空の記録に `InvalidInput`、NaN と無限大に `NonFinite`、結果の桁あふれに `NumericalInstability` を返す。

## 巡回畳み込み

同じ長さ $N$ の二つの記録を周期 $N$ の列の一周期とみなすと、巡回畳み込みは

$$
y_\circ[n] = \sum_{k=0}^{N-1} a[(n-k) \bmod N]\, b[k], \qquad n = 0, \dots, N-1
$$

である。
長さ $N$ の DFT では、スペクトルの要素ごとの積がこの演算に対応する。
`convolve_circular(a, b)` は長さの異なる記録を受け取らず、ゼロパディングも切り詰めもせずに `DimensionMismatch` を返す。
線形畳み込みの結果を周期 $N$ で折り返して足すと、巡回畳み込みに一致する。

$$
y_\circ[n] = \sum_{q \ge 0} y[n + qN]
$$

この折り返し（巡回の折り返し）が、FFT で線形畳み込みを計算するときにゼロパディングが要る理由である。
`convolve` と `ConvolutionNdPlan` は FFT を使う場合も内部でゼロパディングするので、呼び出し側が長さを調整する必要はない。

## 相関のラグの並び

相互相関を

$$
c[\ell] = \sum_{k} a[k]\, \overline{b[k-\ell]}, \qquad \ell = -(M-1), \dots, N-1
$$

と定義する。
和は $0 \le k < N$ かつ $0 \le k-\ell < M$ の範囲を取り、実数の記録では共役は効かない。
`correlate(a, b)` はこの $N + M - 1$ 個の値をラグ $\ell$ の昇順に並べて返す。
配列の添字 $j$ とラグの関係は $\ell = j - (M-1)$ で、ラグ 0 は添字 $M-1$ にある。

ラグの符号は次のように読む。
$a$ が $b$ を $d$ 標本遅らせた波形 $a[n] = b[n-d]$ を含むとき、$c[\ell] = \sum_k b[k-d]\,b[k-\ell]$ は Cauchy–Schwarz の不等式から $\ell = d$ で最大になる。
したがって、最大のラグ $\ell^\ast$ が正なら、$a$ の中の $b$ に似た波形は $\ell^\ast$ 標本だけ後ろにある。
引数を入れ替えると $c_{ba}[\ell] = \overline{c_{ab}[-\ell]}$ となり、配列は逆順になって最大のラグの符号が変わる。
標本化周期が $T_s = 1/f_s$ なら、時間差は $\tau = \ell^\ast T_s$ である。

相関は$b$ の時間反転の共役 $\tilde b[m] = \overline{b[M-1-m]}$ との畳み込み $c[\ell] = (a * \tilde b)[\ell + M - 1]$ に等しい。
`correlate` は内積の和を返すだけで、平均を引くこともノルムで割ることもしない。
$[-1, 1]$ の相関係数が必要なら、両方の記録から平均を引き、$\lVert a \rVert_2 \lVert b \rVert_2$ で割る処理を呼び出し側で行う。
ラグ $\ell$ で重なる標本の数は $\ell$ によって変わるので、端のラグの値は少ない標本の和であることにも注意する。

次のセルは長さ $M = 7$ の型 $b$ を $d$ 標本遅らせて長さ $N = 32$ の記録 $a$ に埋め込み、弱い正弦波を加える。
`convolve`、`convolve_circular`、`correlate` の結果を、上の定義式の直接和（独立な検算）と比べる。
巡回畳み込みには$b$ を長さ $N$ まで零で伸ばした $b_0$ を渡し、線形畳み込みを折り返した列とも比べる。
二つ目の表は相関の最大の添字とラグで、`correlate(a, b)` が $+d$、`correlate(b, a)` が $-d$ を示すかを確かめる。

```rust
//| id: signal-convolution-conventions
//| ref: signal-convolution-conventions
//| title: 畳み込み・巡回畳み込み・相関を定義の直接和と照合する
//| run: reactive
//| crates: [scioxide-core, scioxide-signal]
//| inputs:
//|   delay: {"type":"range","label":"埋め込む遅延 d [標本]","description":"記録 a の中で型 b を置く位置。","min":0,"max":25,"step":1,"value":9}
//| cases:
//|   - {"id":"no-delay","label":"d = 0","description":"相関の最大がラグ 0（添字 M − 1 = 6）に来る。","inputs":{"delay":0}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"checks","path":"/rows/0/1","equals":38}
//|       - {"artifact":"checks","path":"/rows/0/2","range":{"max":1e-14}}
//|       - {"artifact":"checks","path":"/rows/1/2","range":{"max":1e-14}}
//|       - {"artifact":"checks","path":"/rows/2/2","range":{"max":1e-14}}
//|       - {"artifact":"checks","path":"/rows/3/2","range":{"max":1e-14}}
//|       - {"artifact":"checks","path":"/rows/4/2","range":{"max":1e-14}}
//|       - {"artifact":"lags","path":"/rows/0/2","equals":9}
//|       - {"artifact":"lags","path":"/rows/1/2","equals":-9}
//|   - case: no-delay
//|     expect:
//|       - {"artifact":"lags","path":"/rows/0/1","equals":6}
//|       - {"artifact":"lags","path":"/rows/0/2","equals":0}
use scioxide_core::RealScalar;
use scioxide_signal::{convolve, convolve_circular, correlate};

// 型 b（M = 7）と、b を d 標本遅らせて弱い正弦波を加えた記録 a（N = 32）
let template = [1.0_f64, -2.0, 3.0, 0.5, -1.0, 2.0, -0.5];
let (n, m) = (32_usize, template.len());
let d = delay.round() as i64;
// 区間外の添字を 0 とみなして値を読む
let at = |x: &[f64], i: i64| usize::try_from(i).ok().and_then(|i| x.get(i)).copied();
let record: Vec<f64> = (0..n as i64)
    .map(|i| at(&template, i - d).unwrap_or(0.0) + 0.2 * RealScalar::sin(1.7 * i as f64))
    .collect();
let padded: Vec<f64> = (0..n as i64)
    .map(|k| at(&template, k).unwrap_or(0.0))
    .collect();

let full = convolve(&record, &template).map_err(|e| e.to_string())?;
let circular = convolve_circular(&record, &padded).map_err(|e| e.to_string())?;
let forward = correlate(&record, &template).map_err(|e| e.to_string())?;
let backward = correlate(&template, &record).map_err(|e| e.to_string())?;
let unequal = convolve_circular(&record, &template).map_err(|e| format!("{:?}", e.kind()));

// 独立な検算: 定義式どおりの直接和
let linear: Vec<f64> = (0..(n + m - 1) as i64)
    .map(|j| {
        (0..m)
            .map(|k| at(&record, j - k as i64).unwrap_or(0.0) * template[k])
            .sum()
    })
    .collect();
let circular_sum: Vec<f64> = (0..n)
    .map(|j| (0..n).map(|k| record[(j + n - k) % n] * padded[k]).sum())
    .collect();
let lagged: Vec<f64> = (-(m as i64 - 1)..n as i64)
    .map(|l| {
        (0..n)
            .map(|k| record[k] * at(&template, k as i64 - l).unwrap_or(0.0))
            .sum()
    })
    .collect();
// 線形畳み込みを周期 N で折り返して足した列
let mut wrapped = vec![0.0_f64; n];
linear
    .iter()
    .enumerate()
    .for_each(|(j, v)| wrapped[j % n] += v);
let reversed: Vec<f64> = backward.iter().rev().copied().collect();

let largest = |x: &[f64], y: &[f64]| {
    x.iter()
        .zip(y)
        .map(|(p, q)| (p - q).abs())
        .fold(0.0_f64, f64::max)
};
let checks = vec![
    ("convolve(a, b)", full.len(), largest(&full, &linear)),
    (
        "convolve_circular(a, b₀)",
        circular.len(),
        largest(&circular, &circular_sum),
    ),
    (
        "周期 N の折り返し",
        wrapped.len(),
        largest(&circular, &wrapped),
    ),
    ("correlate(a, b)", forward.len(), largest(&forward, &lagged)),
    (
        "correlate(b, a) の逆順",
        backward.len(),
        largest(&reversed, &forward),
    ),
];
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "比べる量" },
    { "key": "1", "label": "出力長 [標本]", "type": "integer" },
    { "key": "2", "label": "直接和との最大差 [-]", "type": "number", "format": sci2 }
]);
emit_table_with_columns!(
    columns,
    checks,
    metadata = serde_json::json!({ "id": "checks" })
);

// 最大の添字 j とラグ ℓ = j − (第 2 引数の長さ − 1)
let peak = |c: &[f64]| (0..c.len()).fold(0, |best, j| if c[j] > c[best] { j } else { best });
let lags = vec![
    (
        "correlate(a, b)",
        peak(&forward),
        peak(&forward) as i64 - (m as i64 - 1),
    ),
    (
        "correlate(b, a)",
        peak(&backward),
        peak(&backward) as i64 - (n as i64 - 1),
    ),
];
let columns = serde_json::json!([
    { "key": "0", "label": "呼び出し" },
    { "key": "1", "label": "最大の添字 j [-]", "type": "integer" },
    { "key": "2", "label": "ラグ ℓ [標本]", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    lags,
    metadata = serde_json::json!({ "id": "lags" })
);
emit_text!(format!(
    "長さ 32 と 7 の convolve_circular: {}",
    unequal.err().unwrap_or_default()
));

let curve: Vec<[f64; 2]> = forward
    .iter()
    .enumerate()
    .map(|(j, &c)| [j as f64 - (m as f64 - 1.0), c])
    .collect();
emit_line_chart!(
    &vec![serde_json::json!({ "name": "c[ℓ] = correlate(a, b)", "points": curve })],
    options = &serde_json::json!({
        "xLabel": "ラグ ℓ [標本]",
        "yLabel": "相関 c[ℓ] [-]",
        "annotations": [{ "kind": "line", "axis": "x", "value": d as f64, "label": "埋め込んだ d" }]
    })
);
```

既定の $d = 9$ では、四つの演算と定義の直接和との差は $4.4 \times 10^{-15}$ 以下で、丸め誤差の範囲で一致する。
巡回畳み込みは線形畳み込みを周期 32 で折り返した列とも同じ差で一致する。
`correlate(b, a)` を逆順にした列は `correlate(a, b)` と差 0 で一致し、実数の記録で $c_{ba}[\ell] = c_{ab}[-\ell]$ が成り立つことを確かめられる。
二つ目の表では、`correlate(a, b)` の最大は添字 15 にあり、$15 - (7 - 1) = 9$ が埋め込んだ $d$ に一致する。
`correlate(b, a)` の最大は添字 22 にあり、第 2 引数の長さが 32 なのでラグは $22 - 31 = -9$ となり、符号が反転する。
$d = 0$ では最大が添字 6（ラグ 0）に移り、型の最後の標本が記録の末尾に重なる $d = 25$ でもラグ 25 が求まる。
長さの異なる記録を渡した `convolve_circular` は `DimensionMismatch` を返す。

## 直接和と FFT の選択

直接和は各出力を $m$ 個の積の和として作業精度で計算する。
単位丸め誤差を $u = \varepsilon/2$、$\gamma_k = ku/(1-ku)$、最小の正の非正規数を $\eta$ とすると、各成分の絶対誤差は

$$
\lvert \hat y[n] - y[n] \rvert \le \gamma_{2m+8}\, \sum_k \lvert a[n-k]\, b[k] \rvert + (2m+8)\,\eta
$$

以下である。
上界は各成分の絶対積の和に比例するので、すべての積が同じ符号なら、小さい出力値も相対的に正確に求まる。

FFT による方法は両方をゼロパディングして変換し、スペクトルの積を逆変換する。
`ConvolutionNdPlan` は、選んだ各軸の長さを $N + M - 1$（区間外を 0 以外で延長する場合は、さらに $2(M-1)$ を加えた長さ）以上の 2 のべきに切り上げる。
計算量は補零後の要素数 $P$ について $O(P \log P)$ である。
誤差はノルムに比例し、どの成分でも定数倍を除いて $\varepsilon \log_2 P\, \lVert a \rVert_2 \lVert b \rVert_2$ 程度になる。
最大値より何桁も小さい出力成分は、この誤差に埋もれて相対精度を失い、符号が反転することもある。
入力の最大値が指数の範囲の端に近い場合は、変換の前に 2 のべきで尺度を変えるので、有限な結果が途中で桁あふれや下位桁あふれを起こすことはない。
結果そのものが桁あふれする場合は `NumericalInstability` になる。

`ConvolutionMethod` は `Direct`、`Fft`、`Automatic`（既定）の三つである。
`Automatic` は準備の時点で二つの演算回数を見積もり、直接法の積の数が FFT の計算量以下なら `Direct`、そうでなければ `Fft` を選ぶ。

$$
\text{直接法の積の数} = \prod_{\text{選んだ軸}} N_i M_i \times (\text{バッチの数}), \qquad
\text{FFT の計算量} = P \sum_{\text{選んだ軸}} \log_2 p_i
$$

$p_i$ は軸 $i$ の補零後の長さである。
直接法の積の数は、`Full` で区間外を 0 とする場合は厳密な値で、他の切り出しでは出力ごとに $\min(N_i, M_i)$ 個の積を数える上界である。
`selection()` が返す `ConvolutionSelection` は、選んだ方法（`method()`）と二つの見積もり（`direct_products()`、`fft_work()`）を持つ。
見積もりは演算の回数であり、実行時間を測った値ではない。
二つの方法は同じ誤差の上界を満たすが、丸めの順序が違うので、結果は最後の数ビットで異なりうる。

次のセルは中心 128、標準偏差 16 標本の Gauss 形のパルス $a$（$N = 256$）を、減衰する指数 $b[k] = e^{-k/4}$（長さ $M$）と畳み込む。
同じ核で `Direct`、`Fft`、`Automatic` の三つの Plan を作り、`selection()` の見積もりと、直接法との差を表にする。
$a$ の端の値は $e^{-32} \approx 1.3 \times 10^{-14}$ なので、出力は 14 桁ほどの幅を持つ。
図は直接法の出力 $\lvert y[n] \rvert$ と FFT との差を対数軸で描き、ノルムによる誤差の目安 $\varepsilon \log_2 P\, \lVert a \rVert_2 \lVert b \rVert_2$ を破線で示す。
差が 0 の点は対数軸に描けないので除き、その数を表の下に示す。

```rust
//| id: signal-convolution-method-selection
//| ref: signal-convolution-method-selection
//| title: 直接和と FFT の見積もりと誤差を比べる
//| run: reactive
//| crates: [scioxide-core, scioxide-signal]
//| inputs:
//|   kernel_length: {"type":"range","label":"核の長さ M [標本]","description":"直接法の積の数 256 M と FFT の計算量の大小を変える。","min":4,"max":64,"step":2,"value":24}
//| cases:
//|   - {"id":"short-kernel","label":"M = 16","description":"積の数 4096 が FFT の計算量 4608 以下になり、Automatic は Direct を選ぶ。","inputs":{"kernel_length":16}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"methods","path":"/rows/2/1","equals":"Fft"}
//|       - {"artifact":"methods","path":"/rows/2/2","equals":6144}
//|       - {"artifact":"methods","path":"/rows/2/3","equals":4608}
//|       - {"artifact":"methods","path":"/rows/0/4","equals":0}
//|       - {"artifact":"methods","path":"/rows/1/4","range":{"max":1e-14}}
//|       - {"artifact":"methods","path":"/rows/1/5","range":{"max":1e-12}}
//|       - {"artifact":"methods","path":"/rows/1/6","range":{"min":0.1}}
//|   - case: short-kernel
//|     expect:
//|       - {"artifact":"methods","path":"/rows/2/1","equals":"Direct"}
//|       - {"artifact":"methods","path":"/rows/2/5","equals":0}
use scioxide_core::{NdView, RealScalar, StridedLayout};
use scioxide_signal::{ConvolutionMethod, ConvolutionNdPlan, ConvolutionOptions};

let (n, m) = (256_usize, kernel_length.round() as usize);
let signal: Vec<f64> = (0..n)
    .map(|i| RealScalar::exp(-0.5 * ((i as f64 - 128.0) / 16.0).powi(2)))
    .collect();
let kernel: Vec<f64> = (0..m).map(|k| RealScalar::exp(-(k as f64) / 4.0)).collect();
// 1 次元の記録の形と刻み（ビューはこれらを借用する）
let (signal_shape, kernel_shape, unit) = ([n], [m], [1_usize]);
let kernel_layout = StridedLayout::new(&kernel_shape, &unit).map_err(|e| e.to_string())?;
let signal_layout = StridedLayout::new(&signal_shape, &unit).map_err(|e| e.to_string())?;
let kernel_view = NdView::new(&kernel, kernel_layout).map_err(|e| e.to_string())?;
let signal_view = NdView::new(&signal, signal_layout).map_err(|e| e.to_string())?;

// 同じ核で三つの Plan を準備し、それぞれの選択と出力を得る
let mut runs = Vec::new();
for method in [
    ConvolutionMethod::Direct,
    ConvolutionMethod::Fft,
    ConvolutionMethod::Automatic,
] {
    let options = ConvolutionOptions::new().with_method(method);
    let plan =
        ConvolutionNdPlan::new(&[n], kernel_view, &[0], options).map_err(|e| e.to_string())?;
    let output = plan.convolve(signal_view).map_err(|e| e.to_string())?;
    runs.push((method, plan.selection(), output));
}
let direct = runs[0].2.clone();
let peak = direct.iter().fold(0.0_f64, |acc, y| acc.max(y.abs()));

let mut rows = Vec::new();
for (method, selection, output) in &runs {
    let differences: Vec<f64> = output
        .iter()
        .zip(&direct)

    };

        format!("{:?}", selection.method()),

        selection.fft_work(),
        differences.iter().fold(0.0_f64, |acc, &e| acc.max(e)),
        relative(1e-3),
        relative(0.0),
    ));
}

let columns = serde_json::json!([
    { "key": "0", "label": "要求した方法" },

let norm = |x: &[f64]| RealScalar::sqrt(x.iter().map(|v| v * v).sum::<f64>());
```

既定の $M = 24$ では、直接法の積の数 $256 \times 24 = 6144$ が FFT の計算量 $512 \times 9 = 4608$ を超えるので、`Automatic` は `Fft` を選ぶ。
FFT と直接法の差は最大で $1.8 \times 10^{-15}$ であり、誤差の目安 $1.7 \times 10^{-14}$ より小さい。
最大値の $10^{-3}$ 以上の成分に限ると相対差は $3.3 \times 10^{-14}$ にとどまるが、全成分では 4.3 になる。
図では、出力の両端で $\lvert y[n] \rvert$ が誤差の目安の線より下がり、そこで FFT の差が $\lvert y[n] \rvert$ と同程度になる。
$M = 16$ では積の数 4096 が 4608 以下なので `Automatic` は `Direct` を選び、結果は `Direct` と差 0 で一致する。
$M = 64$ では端の値がさらに小さくなり、全成分の相対差は $8.4 \times 10^4$ に増える。
出力の裾の値に意味がある場合（確率分布の畳み込みや、対数を取る量）は、`ConvolutionMethod::Direct` を指定する。

## N 次元の畳み込みと境界

`ConvolutionNdPlan::new(shape, kernel, axes, options)` は、形 `shape` の配列と核 `kernel`（`NdView`、同じ階数）を、`axes` で選んだ軸に沿って畳み込む Plan を作る。
選ばなかった軸はバッチの軸であり、その軸の核の長さは 1（すべてのバッチに同じ核）か配列と同じ長さ（バッチごとの核）でなければならず、そうでなければ `DimensionMismatch` になる。
入力と出力は行優先の配列で、`output_shape()` が出力の形を返す。
`convolve2d(a, b)` は `MatrixView` を受け取り、二つの軸で `Full` を計算した `Matrix` を返すワンショット関数である。

区間外の延長は `SignalBoundary` で選ぶ。

| `SignalBoundary` | 区間外の値（長さ $n$ の記録） | 主な用途 |
|---|---|---|
| `Zero`（既定） | $x[-1] = x[n] = 0$ | 線形畳み込み、系の応答 |
| `Periodic` | $x[-1] = x[n-1]$ | 周期的な記録。`Circular` には必須 |
| `Reflect` | $x[-1] = x[1]$、$x[n] = x[n-2]$（端点を繰り返さない鏡映） | 画像の平滑化で端の暗化を避ける |

`Zero` 以外では、Plan は記録の両側に $M-1$ 標本ずつの延長を足してから畳み込む。
直接法の積の数は出力 1 個あたり $M$ 個で数え、FFT の補零後の長さも延長の分だけ伸びる。
`SignalProduct::Correlation` を選ぶと、同じ Plan が核の時間反転の共役との畳み込み、すなわち相関を計算する。
`correlate` はこの指定と既定の切り出しで 1 次元の Plan を一度だけ実行する。

Plan は核を所有し、FFT を選んだ場合は準備の時点で核のスペクトルを一度だけ計算する。
所有値を返す API の `convolve(input)` は出力と作業領域を毎回確保し、出力先を指定する API の `convolve_into(input, output, workspace, cx)` は呼び出し側の出力と作業領域に書く。
作業領域の必要量は `workspace_requirements(kernel)` で問い合わせ、`ConvolutionKernel` で使う核を指定する。
`ConvolutionKernel::Prepared` は Plan が持つ核、`ConvolutionKernel::Supplied` は `convolve_pair_into(input, kernel, output, workspace, cx)` に毎回渡す同じ形の核で、FFT の場合は呼び出しごとに核も変換するので、必要量は `Prepared` 以上になる。
`workspace(kernel)` で確保した `SignalWorkspace` は、同じ Plan の何度目の呼び出しにも使え、実行中に領域を増やさない。
形の合わない入力・出力・作業領域は `DimensionMismatch`、非有限の入力は `NonFinite` になり、失敗した呼び出しは出力を変更しない。

## 分離可能な 2 次元 FIR

2 次元の核が二つの 1 次元の列の外積 $h[p, q] = r[p]\, c[q]$ で書けるとき、核は分離可能（階数 1）であるという。
Gauss 核 $e^{-(p^2 + q^2)/(2\sigma^2)} = e^{-p^2/(2\sigma^2)}\, e^{-q^2/(2\sigma^2)}$ や箱形の平均は分離可能で、円形の平均は分離可能でない。
分離可能な核との畳み込みは、軸 0 に沿って $r$ を、その結果に軸 1 に沿って $c$ を畳み込む二回の 1 次元の畳み込みに等しい。

$$
\sum_{p,q} x[i-p,\, j-q]\, r[p]\, c[q] = \sum_q c[q] \Big( \sum_p x[i-p,\, j-q]\, r[p] \Big)
$$

`SeparableFir2dPlan::new(shape, row_taps, column_taps, options)` はこの二回の Plan を保持する。
`row_taps` は軸 0（行の添字の方向）、`column_taps` は軸 1 に沿って掛かる。
二回とも同じ `ConvolutionOptions` を使うので、結果は外積の核を持つ `ConvolutionNdPlan` と丸めの違いを除いて一致する。
直接法の積の数は、$R \times C$ の配列と長さ $k_r$、$k_c$ の列について、外積の核の $RC\,k_r k_c$ に対して約 $RC\,(k_r + k_c)$ に減る。
中間結果は呼び出し側の作業領域（`workspace(())`）に置き、二回とも成功してから出力に書く。

次のセルは48 × 64 の試験画像（二つの円と斜めの縞）を、標準偏差 $\sigma$ の Gauss 核（半径 $3\sigma$ を切り上げた $k = 2\lceil 3\sigma \rceil + 1$ 個の係数、和を 1 に正規化）で平滑化する。
切り出しは `Same`、境界は `Reflect` とし、`SeparableFir2dPlan` と、外積の核を持つ `ConvolutionNdPlan` の結果を比べる。
表は二つの Plan の選んだ方法、直接法の積の数の見積もり、結果の最大差を示す。

```rust
//| id: signal-separable-gaussian-blur

//| crates: [scioxide-core, scioxide-signal]

//|   sigma: {"type":"range","label":"Gauss 核の標準偏差 σ [画素]","description":"係数の数 k = 2⌈3σ⌉ + 1 と平滑化の強さを変える。","min":0.5,"max":4,"step":0.5,"value":1.5}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"plans","path":"/rows/0/2","equals":67584}
//|       - {"artifact":"plans","path":"/rows/1/1","equals":"Fft"}
//|       - {"artifact":"plans","path":"/rows/1/2","equals":371712}
//|       - {"artifact":"plans","path":"/rows/1/3","range":{"max":1e-15}}

use scioxide_signal::{
    ConvolutionExtent, ConvolutionKernel, ConvolutionNdPlan, ConvolutionOptions,

};

    .map(|i| {
        let (y, x) = ((i / cols) as f64, (i % cols) as f64);

            |cy: f64, cx: f64, r: f64| f64::from((y - cy).powi(2) + (x - cx).powi(2) < r * r);

        (disc(16.0, 18.0, 10.0) + 0.5 * disc(30.0, 44.0, 12.0) + 0.25 * stripes).min(1.0)

    .collect();

    .map(|p| RealScalar::exp(-0.5 * (p as f64 / sigma).powi(2)))
    .collect();

let kernel_layout =
    StridedLayout::new(&kernel_shape, &kernel_strides).map_err(|e| e.to_string())?;
```

外積の核の Plan は FFT の計算量の方が小さいと見積もって `Fft` を選び、二つの結果の差は最大 $4.4 \times 10^{-16}$ である。
$\sigma = 0.5$（$k = 5$）では外積の核の Plan も `Direct` を選び、差は $3.3 \times 10^{-16}$ である。
$\sigma = 4$（$k = 25$）では積の数の比が $1920000 / 153600 = 12.5 = k/2$ まで開く。
分離形の積の数は二回の通過を直接法で計算した場合の値で、各通過の Plan も同じ規則で FFT を選ぶことがある。
`Reflect` の境界なので、平滑化した画像の縁は 0 で延長した場合のように暗くならない。

## オーバーラップ加算による逐次処理

終わりのない入力や長い記録を FIR で処理するときは、記録全体を一度に変換せず、長さ $B$ のブロックに分けて畳み込む。
ブロック $x_r[n] = x[n + rB]$（$0 \le n < B$）と核 $h$（長さ $K$）の線形畳み込みは長さ $B + K - 1$ で、線形性から全体の畳み込みは

$$
y[n] = \sum_r (x_r * h)[n - rB]
$$

となる。
隣り合うブロックの結果は $K - 1$ 標本だけ重なるので、重なりを足し合わせれば線形畳み込みの全体が得られる。
これがオーバーラップ加算（overlap-add）である。
入力を $K-1$ 標本ずつ重ねて切り出し、巡回畳み込みのうち折り返しの影響を受けない部分だけを残す方法は重畳保存（overlap-save）と呼ぶ。
`scioxide-signal` はオーバーラップ加算の Plan だけを提供し、重畳保存の Plan は提供しない。

`OverlapPlan::new(taps, block_size, SignalExecutionOptions::new())` は、ブロック長 $B$ の FFT と核のスペクトルを準備する。
FFT の長さは $B + K - 1$ 以上の 2 のべき $L$ で、ブロックあたりの計算量は $O(L \log L)$、出力 1 標本あたりでは $O((L/B) \log L)$ である。
$B$ を大きくすると 1 標本あたりの計算コストが下がり、小さくすると遅れと作業領域が減る。

`plan.stream()` が返す `OverlapStream` は、現在のブロックの入力と前のブロックの重なりを状態として所有し、Plan を借用する。
`process_into(input, chunk, output, workspace, cx)` は任意の長さのチャンクを受け取る。
`StreamChunk::Partial` の呼び出しは完全なブロックの出力だけを書き、最大 $B - 1$ 標本の入力は次の呼び出しまで待つ。
`StreamChunk::Final` の呼び出しは最後のブロックを零で埋めて処理し、核の末尾の $K - 1$ 標本を書いて、ストリームを `reset` まで閉じる。
閉じたストリームの呼び出しは `InvalidInput` になる。
すべての呼び出しの出力をつなぐと、記録全体の `convolve` の結果に一致する。

書き出す標本の数は `output_len(input_len, chunk)` で事前に分かり、戻り値の `StreamProgress` は消費した入力の数（`consumed()`）、書いた出力の数（`produced()`）、最初の出力の通し番号（`first_output_index()`）を返す。
作業領域は `stream.workspace(max_input_len)` で一度確保すれば、入力が `max_input_len` 標本以下のすべての呼び出しに使える。
呼び出しはチャンクを不可分に処理し、失敗した呼び出しは状態も出力も変えない。
`clone` で状態の写しを取り、`clone_from` で確保なしに戻せる。

次のセルは200 標本の記録を、シードから決めた長さ 1〜23 のチャンクに分けて `OverlapStream` に流す。
核は長さ 21 の指数減衰 $h[k] = 0.85^k$ である。
最後のチャンクだけを `Final` にし、各呼び出しの消費・出力・通し番号を表にして、つないだ出力をワンショット呼び出しの `convolve` と比べる。

```rust
//| id: signal-overlap-stream
//| ref: signal-overlap-stream
//| title: オーバーラップ加算のストリームをワンショット呼び出しの畳み込みと比べる
//| run: reactive
//| crates: [scioxide-core, scioxide-signal]
//| inputs:
//|   block_size: {"type":"range","label":"ブロック長 B [標本]","description":"Partial の呼び出しが書く単位と FFT の長さを変える。","min":4,"max":64,"step":4,"value":16}
//|   seed: {"type":"range","label":"チャンク長のシード [-]","description":"チャンクの長さの並びを決める。","min":1,"max":50,"step":1,"value":7}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"summary","path":"/rows/0/0","equals":220}
//|       - {"artifact":"summary","path":"/rows/0/1","equals":220}
//|       - {"artifact":"summary","path":"/rows/0/2","range":{"max":1e-13}}

use scioxide_signal::{OverlapPlan, SignalExecutionOptions, StreamChunk, convolve};

    .map(|i| RealScalar::sin(0.07 * i as f64) + 0.5 * RealScalar::sin(0.31 * i as f64))
    .collect();
let taps: Vec<f64> = (0..21).map(|k| 0.85_f64.powi(k)).collect();
let plan = OverlapPlan::new(
    &taps,
    block_size.round() as usize,
    SignalExecutionOptions::new(),
)
.map_err(|e| e.to_string())?;
let mut stream = plan.stream().map_err(|e| e.to_string())?;
// チャンクは最長 23 標本なので、23 標本までの呼び出しに足りる作業領域を一度だけ確保する
let mut workspace = stream.workspace(23).map_err(|e| e.to_string())?;

// シードから決まる線形合同法でチャンクの長さ 1〜23 を作る
let mut state = seed.round() as u64;
let mut start = 0;
let mut streamed = Vec::new();
let mut calls = Vec::new();
while start < record.len() {
    state = state
        .wrapping_mul(6364136223846793005)
        .wrapping_add(1442695040888963407);
    let end = (start + 1 + (state >> 33) as usize % 23).min(record.len());
    let chunk = if end == record.len() {
        StreamChunk::Final
    } else {
        StreamChunk::Partial
    };
    let mut output = vec![
        0.0_f64;
        stream
            .output_len(end - start, chunk)
            .map_err(|e| e.to_string())?
    ];
    let progress = stream
        .process_into(
            &record[start..end],
            chunk,
            &mut output,
            &mut workspace,
            ExecutionContext::sequential(),
        )
        .map_err(|e| e.to_string())?;
    calls.push((
        format!("{chunk:?}"),
        progress.consumed(),
        progress.produced(),
        progress.first_output_index(),
    ));
    streamed.extend_from_slice(&output[..progress.produced()]);
    start = end;
}
let closed = stream
    .output_len(1, StreamChunk::Partial)
    .map_err(|e| format!("{:?}", e.kind()))
    .err()
    .unwrap_or_default();

// 独立な検算: ワンショット呼び出しの線形畳み込み
let whole = convolve(&record, &taps).map_err(|e| e.to_string())?;
let difference = streamed
    .iter()
    .zip(&whole)
    .fold(0.0_f64, |acc, (a, b)| acc.max((a - b).abs()));
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "つないだ出力 [標本]", "type": "integer" },
    { "key": "1", "label": "N + K − 1 [標本]", "type": "integer" },
    { "key": "2", "label": "convolve との最大差 [-]", "type": "number", "format": sci2 }
]);
emit_table_with_columns!(
    columns,
    vec![(streamed.len(), whole.len(), difference)],
    metadata = serde_json::json!({ "id": "summary" })
);
let columns = serde_json::json!([
    { "key": "0", "label": "チャンクの種類" },
    { "key": "1", "label": "消費 [標本]", "type": "integer" },
    { "key": "2", "label": "出力 [標本]", "type": "integer" },
    { "key": "3", "label": "最初の出力の通し番号 [-]", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    calls,
    metadata = serde_json::json!({ "id": "calls" })
);
emit_text!(format!("Final の後の output_len: {closed}"));
```

既定の $B = 16$ では、最初の二回の呼び出し（7 標本と 4 標本）は完全なブロックがそろわないので何も書かない。
三回目に 19 標本を受け取ると、たまった 30 標本のうち 1 ブロック分の 16 標本の出力を書き、残りの 14 標本は次へ持ち越す。
`Partial` の出力はいつも 16 の倍数で、`Final` は残りの 44 標本（最後のブロックと核の末尾 20 標本）をまとめて書く。
つないだ出力は $200 + 21 - 1 = 220$ 標本で、`convolve` との差は最大 $3.6 \times 10^{-15}$ である。
$B = 64$ にすると出力は 64 標本ずつになり、`Final` が書く量は 92 標本に増える。
`Final` の後の `output_len` は `InvalidInput` を返し、ストリームが閉じたことを示す。

## 逆畳み込みと多項式の除算

線形畳み込みは多項式の積なので、その逆演算は多項式の除算である。
`deconvolve(signal, divisor)` は、二つの係数列を標本の順（先頭の係数を最高次とする降べきの順）の多項式とみなして長除法を行い、

$$
\text{signal} = \text{convolve}(\text{quotient}, \text{divisor}) + \text{remainder}
$$

を満たす商と剰余を返す。
長さ $L_s$ の signal と長さ $L_d$ の divisor について、商の長さは $L_s - L_d + 1$、剰余の長さは $L_s$ である。
剰余は先頭の $L_s - L_d + 1$ 個が 0 で、0 でない値は末尾の $L_d - 1$ 個に入る。
signal が divisor より短い場合は、商が空で剰余が signal に等しい。
divisor が空か `divisor[0]` が 0 の場合は `InvalidInput`、非有限の係数は `NonFinite`、商か剰余の桁あふれは `NumericalInstability` になる。

標本の順の長除法は、商を先頭から

$$
q[n] = \frac{1}{d[0]} \Big( s[n] - \sum_{k=1}^{L_d - 1} d[k]\, q[n-k] \Big)
$$

と順に決める再帰であり、伝達関数 $1/D(z)$（$D(z) = \sum_k d[k] z^{-k}$）の IIR フィルタを signal に掛けることと同じである。
ある段の丸め誤差はこのフィルタのインパルス応答に乗って後の商へ伝わる。
$D(z)$ の零点がすべて単位円の内側にある（divisor が最小位相である）とき、インパルス応答は減衰し、誤差は有界にとどまる。
単位円の外に半径 $\rho > 1$ の零点があると、誤差はおよそ $\rho^n$ で増える。
`divisor[0]` が他の係数に比べて小さいことは、この増幅が起こる典型的な場合である。
観測ノイズを含む記録の逆畳み込みでは、ノイズも同じ割合で増幅されるので、長除法の結果をそのまま信号の推定に使えない。

次のセルは零点 $\rho e^{\pm i\theta}$（$\theta = 1$ rad）を持つ 2 次の divisor $d = [1, -2\rho\cos\theta, \rho^2]$ と、長さ 60 の既知の商 $q$ から signal $s = q * d$ を `convolve` で作り、`deconvolve` で $q$ を取り戻す。
図は各添字の商の誤差 $\lvert \hat q[n] - q[n] \rvert$ を対数軸で描き、増幅率の目安 $\varepsilon \rho^n$ を破線で重ねる。
表は商の最大誤差、剰余の最大値、恒等式 $s = \hat q * d + r$ の残差（`convolve` による独立な検算）である。

```rust
//| id: signal-deconvolution-stability
//| ref: signal-deconvolution-stability
//| title: 長除法による逆畳み込みの誤差の増幅を零点の半径で比べる
//| run: reactive
//| crates: [scioxide-core, scioxide-signal]
//| inputs:
//|   radius: {"type":"range","label":"divisor の零点の半径 ρ [-]","description":"1 を超えると長除法の再帰が不安定になる。","min":0.5,"max":1.6,"step":0.05,"value":0.8}
//| cases:
//|   - {"id":"outside","label":"ρ = 1.5","description":"零点が単位円の外にあり、商の誤差が ρⁿ で増える。","inputs":{"radius":1.5}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"division","path":"/rows/0/0","range":{"max":1e-14}}
//|       - {"artifact":"division","path":"/rows/0/2","range":{"max":1e-14}}
//|   - case: outside
//|     expect:
//|       - {"artifact":"division","path":"/rows/0/0","range":{"min":1e-9}}
use scioxide_core::RealScalar;
use scioxide_signal::{convolve, deconvolve};

let theta = 1.0_f64;
let divisor = [1.0, -2.0 * radius * RealScalar::cos(theta), radius * radius];
let quotient: Vec<f64> = (0..60)
    .map(|n| 0.5 + RealScalar::cos(0.3 * n as f64))
    .collect();
let signal = convolve(&quotient, &divisor).map_err(|e| e.to_string())?;
let (estimate, remainder) = deconvolve(&signal, &divisor).map_err(|e| e.to_string())?;

// 独立な検算: 商と剰余から signal を組み立て直す
let rebuilt = convolve(&estimate, &divisor).map_err(|e| e.to_string())?;
let identity = signal
    .iter()
    .zip(&rebuilt)
    .zip(&remainder)
    .fold(0.0_f64, |acc, ((s, q), r)| acc.max((s - q - r).abs()));
let errors: Vec<f64> = estimate
    .iter()
    .zip(&quotient)
    .map(|(a, b)| (a - b).abs())
    .collect();
let rows = vec![(
    errors.iter().fold(0.0_f64, |acc, &e| acc.max(e)),
    remainder.iter().fold(0.0_f64, |acc, r| acc.max(r.abs())),
    identity,
    estimate.len(),
    remainder.len(),
)];
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "商の最大誤差 [-]", "type": "number", "format": sci2 },
    { "key": "1", "label": "剰余の最大値 [-]", "type": "number", "format": sci2 },
    { "key": "2", "label": "s − (q̂ * d + r) の最大値 [-]", "type": "number", "format": sci2 },
    { "key": "3", "label": "商の長さ [-]", "type": "integer" },
    { "key": "4", "label": "剰余の長さ [-]", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "division" })
);

let measured: Vec<[f64; 2]> = errors
    .iter()
    .enumerate()
    .filter(|(_, e)| **e > 0.0)
    .map(|(n, &e)| [n as f64, e])
    .collect();
let growth: Vec<[f64; 2]> = (0..60)
    .map(|n| [n as f64, f64::EPSILON * radius.powi(n)])
    .collect();
emit_text!(format!(
    "誤差が 0 で図から除いた添字: {} / 60",
    60 - measured.len()
));
emit_line_chart!(
    &vec![
        serde_json::json!({
            "name": "|q̂[n] − q[n]|",
            "points": measured,
            "style": { "symbol": "circle" }
        }),
        serde_json::json!({
            "name": "ε ρⁿ（目安）",
            "points": growth,
            "style": { "lineType": "dashed", "showSymbol": false }
        }),
    ],
    options = &serde_json::json!({
        "xLabel": "商の添字 n [-]",
        "yLabel": "誤差 [-]",
        "yType": "log"
    })
);
```

既定の $\rho = 0.8$ では、商の最大誤差は $2.2 \times 10^{-16}$ で、60 個のうち 53 個は誤差が 0 であり、剰余もちょうど 0 になる。
$\rho = 1.5$ では商の最大誤差が $6.6 \times 10^{-7}$ に増え、図の誤差は破線の $\varepsilon \rho^n$ と同じ傾きで伸びる。
商の誤差を打ち消すように剰余も $1.5 \times 10^{-6}$ になるので、恒等式の残差は $5.6 \times 10^{-17}$ のままである。
したがって、$s = \hat q * d + r$ の残差が小さいことは、商が正しいことを意味しない。
$\rho = 1.6$ では商の最大誤差は $2.0 \times 10^{-5}$ に達する。

## まとめ

区間外を 0 とみなす線形畳み込みは長さ $N + M - 1$ の多項式の積であり、`ConvolutionExtent` で `Same` や `Valid` の範囲を切り出せる。
`correlate(a, b)` はラグ $-(M-1)$ から $N-1$ の昇順に並ぶので、最大の添字から $M-1$ を引けばラグになり、正のラグは $a$ の中の波形が遅れていることを示す。
直接和は成分ごとに正確で、FFT はノルムに比例する誤差で速く、`Automatic` は演算回数の見積もりで方法を選ぶので、出力の小さい成分の相対精度が要るときは `Direct` を指定する。
同じ核を繰り返し使うときは `ConvolutionNdPlan` と作業領域を、分離可能な 2 次元の核には `SeparableFir2dPlan` を、長い入力には `OverlapStream` を使う。
`deconvolve` は長除法なので、divisor が最小位相でなければ誤差が指数的に増えることを確かめてから使う。

リサンプリングの多相フィルタは同じ FIR の積和を間引いた形で計算するので、続けて[リサンプリング](../resampling/)を読む。
相関による時間差の推定は[地震波の到達時刻差を相互相関で推定する](../../examples/seismic-delay-correlation/)で、FFT による畳み込みの組み立ては `scioxide-fft` の章の[相互相関とラグの並び](oxref:fft-correlation)で確かめられる。
