この章の数理ページは等間隔に標本化した有限長の記録 $x[0], \dots, x[N-1]$ を扱う。
どのページでも、記号、DFT の正規化、周波数の単位、記録の外側の延長、作業領域の扱いは同じ意味で使う。
このページはそれらの共通の規約と、試験信号の生成、作業精度の誤差の評価をまとめ、最後に各ページが答える問いを一覧にする。

## 記号と DFT の正規化

| 記号 | 意味 |
|---|---|
| $x[n]$ | 長さ $N$ の記録の第 $n$ 標本（$n = 0, \dots, N-1$） |
| $h[n]$, $b_k$ | フィルタのインパルス応答、FIR の係数 |
| $T_s$, $f_s$ | 標本化周期と標本化周波数（$f_s = 1/T_s$） |
| $f_{\mathrm{Nyq}}$ | Nyquist 周波数 $f_s/2$ |
| $\omega$ | デジタル角周波数 $2\pi f / f_s$ [rad/標本]、または連続系の角周波数 [rad/時間] |
| $X[k]$ | 正規化しない DFT $X[k] = \sum_{n=0}^{N-1} x[n]\, e^{-2\pi i k n / N}$ |
| $\overline{z}$ | 複素数 $z$ の共役 |
| $u$ | 単位丸め誤差 $\varepsilon/2$（`f64` では $2^{-53}$） |

順変換は正規化せず、逆変換は変換長 $N$ で割る。
したがって $x[n] = \frac{1}{N} \sum_{k} X[k]\, e^{2\pi i k n / N}$ であり、Parseval の関係は $\sum_n |x[n]|^2 = \frac{1}{N} \sum_k |X[k]|^2$ になる。
離散のパワースペクトル `power_spectrum` は $|X[k]|^2 / N$、相互スペクトル `cross_spectrum` は $A[k]\,\overline{B[k]} / N$ で、標本化周波数を含まない（密度ではない）。
密度と単位の換算は[スペクトル推定](spectral-estimation/)で扱う。

## 周波数の単位

API ごとに周波数の単位が違う。
同じ値を別の API に渡す前に、次の表で単位をそろえる。

| 単位 | 使う API | 換算 |
|---|---|---|
| Nyquist 周波数に対する比 $f \in [0, 1]$ | FIR・IIR の設計（`IirDomain::Digital`）、離散時間の LTI 系の周波数応答 | $f = 1$ が $f_s/2$。物理量は $f \cdot f_s / 2$ [Hz]。評価点は $z = e^{i\pi f}$ |
| 角周波数 [rad/時間] | アナログプロトタイプ（`IirDomain::Analog`）、連続時間の LTI 系、`lomb_scargle`、`LombScargle` | 評価点は $s = i\omega$。周期／時間の値の $2\pi$ 倍 |
| 時間単位あたりの周期 | `welch`、`SpectralEstimatePlan`、`StftPlan`、`Waveform` の周波数 | $f_s$ を秒あたりで与えれば Hz |
| DFT のビンの番号 $k$ | `power_spectrum`、`cross_spectrum` | ビン $k$ は $k f_s / N$ [Hz] |

フィルタ、零点・極・利得、二次節、FIR の設計、状態空間の応答はどれも上の規約に従うので、同じ周波数では同じ値を返す。
Lomb–Scargle 法だけが角周波数を受け取ることは、等間隔の推定と結果を比べるときの誤りの原因になりやすい。

## 記録の外側の延長

有限の記録にウインドウをずらして掛ける演算は、記録の外側の値を仮定する必要がある。
`SignalBoundary` は次の三つの延長を表し、`ConvolutionOptions`、`WaveletOptions`、`StftOptions` が受け取る。

| `SignalBoundary` | 延長 | $x[-1]$ と $x[N]$ | 使う場面 |
|---|---|---|---|
| `Zero` | 外側は 0 | $0$ と $0$ | 線形の畳み込み、過渡応答 |
| `Periodic` | 周期 $N$ で繰り返す | $x[N-1]$ と $x[0]$ | 巡回畳み込み、周期信号、DFT と同じ仮定 |
| `Reflect` | 端点を繰り返さずに折り返す | $x[1]$ と $x[N-2]$ | 端で値と傾きが連続な延長、ウェーブレットの端 |

既定は Plan によって違う。
畳み込みと STFT の既定は `Zero`、ウェーブレットの既定は `Periodic` である。
畳み込みの `ConvolutionExtent::Circular` は `Periodic` と組み合わせたときだけ受け付ける。

この型を使わない API はそれぞれの延長を持つ。
局所フィルタ（中央値、Hampel、Wiener）は端点の値を繰り返し、Savitzky–Golay は `SavitzkyGolayBoundary` で、IIR の前後方向の実行は `IirPadding` で延長を選ぶ。
どの延長も記録の外の値を作るだけで、端の近くの出力は延長の仮定に依存する。

## 作業領域と実行コンテキスト

ワンショット関数（`convolve`、`welch` など）は、Plan、作業領域、出力をその場で確保して結果を `Vec` で返し、`ExecutionContext::sequential_native()` で逐次に実行する。
繰り返す計算では、Plan や手法オブジェクトを一度だけ作り、作業領域と出力を呼び出し側が持つ出力先を指定する API `verb_into(inputs, output, workspace, cx)` を使う。

`SignalRequirements` は一回の演算に要る作業領域の大きさを、標本の型 `T`、実数 `T::Real`、複素数 `Complex<T::Real>` の三種類の要素数で表す。
Plan の `workspace_requirements(request)` が返し、要求 `request` は `()`、記録長、レーンの数、`SignalLayout`、または Plan に固有の値（`StftRequest`、`IirRequest`、`SplineRequest`）である。
`SignalLayout::Contiguous(n)` は長さ $n$ の一つの記録、`SignalLayout::Axis { shape, axis }` は配列の一つの軸に沿ったすべてのレーンを表す。
二つの要求の `max` は要素数ごとの最大と小さい方のバイト上限を返すので、最も大きい演算に合わせて一度確保すれば、小さい演算にも同じ領域を使える。
`with_max_bytes(limit)` を付けた要求で確保や照合をすると、上限を超える領域は `ResourceLimit` になる。
上限は確保と照合のときだけ効き、実行は上限を見ない。

`SignalWorkspace` は三種類の要素のバッファーを一つずつ持ち、何個の Plan と呼び出しにも使える。
`SignalWorkspace::new()` は確保せずに空の領域を作り、`try_reserve(&requirements)` が必要な分だけ広げ、`check(&requirements)` は広げずに足りるかを返す。
領域は広がるだけで縮まず、演算は要求の先頭部分だけを使い、呼び出しの後の中身は規定しない。
実行中には広げないので、足りない領域を渡した呼び出しは `DimensionMismatch` を返す。
ピーク、リッジ、Whittaker 平滑化、LTI 系の応答は、同じ `try_reserve` と `check` を持つ専用の領域型を使う。

`SignalExecutionOptions` は実行の方針（`ExecutionPolicy`）だけを設定に持つ Plan が受け取る設定で、既定は逐次（`Sequential`）である。
並列のワーカーの数を方針で限り、実際のエグゼキューターは呼び出しに渡す `ExecutionContext` が決める。
このハンドブックのセルは wasm32 の上で逐次に動くので、セルでは `ExecutionContext::sequential()` を渡す。

出力先を指定する API は検査、変換、尺度の調整がすべて終わってから出力に書く。
失敗した呼び出しは呼び出し側の出力を変えず、ストリームでは状態も変えない。

## 逐次処理の規約

`OverlapStream`、`PolyphaseStream`、`LocalFilterStream`、`StftAnalysisStream`、`StftSynthesisStream` は、一つの記録をチャンクに分けて処理する。
各呼び出しは `StreamChunk` を受け取り、`Partial` はまだ入力が続くこと、`Final` は記録がそのチャンクで終わることを表す。
`Partial` の呼び出しはそれまでの入力で決まる出力だけを書く。
`Final` の呼び出しは保留していた出力を書き出し、ストリームを `reset` まで閉じる。
閉じたストリームを呼ぶと `InvalidInput` になる。

各呼び出しは `StreamProgress` を返す。
`consumed()` は消費した入力の標本数、`produced()` は書いた出力の標本数、`first_output_index()` は書いた最初の標本の出力記録の中での添字である。
`replacements()` は Hampel フィルタのストリームが書いた置換の添字の数で、ほかのストリームでは 0 になる。
出力は入力より遅れて出るので、チャンクの境界を信号の終わりと取り違えないよう、出力の位置は `first_output_index()` で数える。

ストリームは値であり、`clone` で状態を保存し、`clone_from` で確保せずに戻せる。
`workspace_requirements(max)` で大きさを決めた作業領域は、`max` 標本以下の入力を渡すその後のすべての呼び出しに使える。
IIR フィルタはストリームの型を持たず、遅延の値を呼び出し側の `IirState` に持たせる（[IIR フィルタの実行とゼロ位相](iir-filtering-and-zero-phase/)）。

## 試験信号の生成

アルゴリズムの検証には、閉じた形で値が分かる試験信号が便利である。
`Waveform` は次の解析的な波形を表し、周波数は時間単位あたりの周期、位相 $\varphi$ はラジアンで与える。
周期的な波形では $u(t) = \operatorname{frac}(f t + \varphi / 2\pi)$ を周期の中の位置とする（$\operatorname{frac}$ は小数部分）。

| `Waveform` | 値 |
|---|---|
| `Sine`、`Cosine` | $\sin(2\pi f t + \varphi)$、$\cos(2\pi f t + \varphi)$ |
| `Square { duty }` | $u < d$ で $+1$、それ以外で $-1$（$d \in [0, 1]$。$d = 1$ は定数 $+1$） |
| `Sawtooth { width }` | $u < w$ で $2u/w - 1$、それ以外で $1 - 2(u - w)/(1 - w)$（$w = 1/2$ が三角波） |
| `GaussianPulse { sigma }` | $e^{-(t/\sigma)^2/2} \cos(2\pi f t + \varphi)$（$\lvert t/\sigma \rvert > 64$ では厳密に 0） |
| `Chirp { initial, final_frequency, duration, law }` | $\cos\!\left(2\pi \int_0^t f(s)\, ds + \varphi\right)$ |
| `PolynomialSweep { coefficients }` | $f(t) = \sum_k a_k t^k$ のとき $\cos\!\left(2\pi \sum_k a_k t^{k+1}/(k+1) + \varphi\right)$ |

掃引波（チャープ）の瞬時周波数 $f(t)$ は `ChirpLaw` で選ぶ。
$f_0$ を初めの周波数、$f_1$ を時刻 $T$（`duration`）の周波数とし、$f(0) = f_0$、$f(T) = f_1$ になる。
位相は瞬時周波数の積分 $\Phi(t) = \int_0^t f(s)\, ds$ [周期] で、閉じた形で計算する。

| `ChirpLaw` | 瞬時周波数 $f(t)$ | 位相 $\Phi(t)$ [周期] |
|---|---|---|
| `Linear` | $f_0 + (f_1 - f_0)\, t/T$ | $f_0 t + (f_1 - f_0)\, t^2 / (2T)$ |
| `Quadratic { vertex_at_end: false }` | $f_0 + (f_1 - f_0)(t/T)^2$ | $f_0 t + (f_1 - f_0)\, t^3 / (3T^2)$ |
| `Quadratic { vertex_at_end: true }` | $f_0 + (f_1 - f_0)\left(1 - (1 - t/T)^2\right)$ | $f_0 t + (f_1 - f_0)\left(t^2/T - t^3/(3T^2)\right)$ |
| `Logarithmic` | $f_0 (f_1/f_0)^{t/T}$ | $f_0 T \left((f_1/f_0)^{t/T} - 1\right) / \ln(f_1/f_0)$ |
| `Hyperbolic` | $f_0 / \left(1 + (f_0/f_1 - 1)\, t/T\right)$ | $f_0 T \ln\!\left(1 + (f_0/f_1 - 1)\, t/T\right) / (f_0/f_1 - 1)$ |

対数と双曲線の法則は $f_0$ と $f_1$ が 0 でなく同じ符号であることを要し、満たさなければ `DomainError` になる。
双曲線の法則は分母が 0 以下になる時刻で周波数が発散し、その時刻を渡すと `DomainError`（`Pole`）を返す。
区間 $[0, T]$ の外の時刻も同じ法則で評価する。

`waveform(w, &times)` は任意の時刻の列で波形を評価して `Vec` を返し、時刻は昇順や等間隔でなくてよい。
出力先を指定する API `waveform_into(w, &times, &mut output, cx)` は出力の先頭 `times.len()` 個に書く。
どちらも全標本を一度評価して検査してから、もう一度評価して書くので、途中の時刻でエラーになっても出力は変わらない。
`waveform_grid_into(w, origin, step, start_index, &mut output, cx)` は等間隔の格子 $t_i = t_0 + (s + i)\,\Delta t$ の値を書く。
格子は絶対の添字 $s + i$ で時刻を作るので、長い信号をチャンクに分けて作っても一度に作った信号と同じ値になる。
`unit_impulse_into(m, start_index, &mut output, cx)` は、添字 $m$ だけが 1 の単位インパルスの一部分（添字 `start_index` から `output.len()` 個）を書き、インパルスを含まない部分はすべて 0 にする。

次のセルは $f_0 = 5$ Hz から $f_1 = 40$ Hz へ $T = 1$ s で掃引するチャープを $f_s = 400$ Hz で 400 標本作る。
`waveform_grid_into` で選んだ長さのチャンクに分けて作った列と、`waveform` で一度に作った列を比べ、さらに上の表の位相の式から手で計算した値（`f64` の固有メソッドによる参照値）と比べる。
入力は掃引の法則とチャンクの長さで、出力は二つの差の表と、波形と瞬時周波数の連動した図である。

```rust
//| id: signal-chirp-waveform-chunks
//| ref: signal-chirp-waveform-chunks
//| title: チャープを分割して生成し、閉じた形の位相と比べる
//| run: reactive
//| crates: [scioxide-core, scioxide-signal]
//| inputs:
//|   law: {"type":"select","label":"掃引の法則","description":"瞬時周波数 f(t) の形を選ぶ。","options":["線形","二次（頂点が始点）","二次（頂点が終点）","対数","双曲線"],"value":"線形"}
//|   chunk: {"type":"range","label":"チャンクの長さ [標本]","description":"waveform_grid_into に一度に渡す標本数。","min":1,"max":128,"step":1,"value":37}
//| cases:
//|   - {"id":"logarithmic","label":"対数の法則、チャンク 1 標本","description":"一標本ずつ作っても一括の列と一致する。","inputs":{"law":"対数","chunk":1}}
//|   - {"id":"hyperbolic","label":"双曲線の法則","description":"周波数が終点の近くで急に上がる。","inputs":{"law":"双曲線"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"agreement","path":"/rows/0/1","equals":0}
//|       - {"artifact":"agreement","path":"/rows/0/2","range":{"max":1e-11}}
//|       - {"artifact":"agreement","path":"/rows/0/3","approx":{"value":5,"atol":1e-12}}
//|       - {"artifact":"agreement","path":"/rows/0/4","approx":{"value":40,"atol":1e-12}}
//|   - case: logarithmic
//|     expect:
//|       - {"artifact":"agreement","path":"/rows/0/1","equals":0}
//|       - {"artifact":"agreement","path":"/rows/0/2","range":{"max":1e-11}}
//|   - case: hyperbolic
//|     expect:
//|       - {"artifact":"agreement","path":"/rows/0/1","equals":0}
//|       - {"artifact":"agreement","path":"/rows/0/2","range":{"max":1e-11}}
use scioxide_core::ExecutionContext;
use scioxide_signal::{ChirpLaw, Waveform, waveform, waveform_grid_into};

let (f0, f1, duration, rate) = (5.0_f64, 40.0_f64, 1.0_f64, 400.0_f64);
let n = 400_usize;
let chirp_law = match law.as_str() {
    "二次（頂点が始点）" => ChirpLaw::Quadratic {
        vertex_at_end: false,
    },
    "二次（頂点が終点）" => ChirpLaw::Quadratic {
        vertex_at_end: true,
    },
    "対数" => ChirpLaw::Logarithmic,
    "双曲線" => ChirpLaw::Hyperbolic,
    _ => ChirpLaw::Linear,
};
let chirp = Waveform::Chirp {
    initial: f0,
    final_frequency: f1,
    duration,
    phase: 0.0,
    law: chirp_law,
};

// 一括の生成: 時刻の列 t_n = n Δt（Δt = 1/f_s）を渡す
let step = 1.0 / rate;
let times: Vec<f64> = (0..n).map(|i| i as f64 * step).collect();
let whole = waveform(chirp, &times).map_err(|e| e.to_string())?;

// 分割した生成: 絶対の添字 start から chunk 個ずつ書く
let size = chunk.round() as usize;
let mut pieces = vec![0.0; n];
for (k, block) in pieces.chunks_mut(size).enumerate() {
    waveform_grid_into(
        chirp,
        0.0,
        step,
        k * size,
        block,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;
}

// 独立な検算: 位相 Φ(t) [周期] と瞬時周波数 f(t) を表の式から手で計算する
let (delta, ratio, b) = (f1 - f0, f1 / f0, f0 / f1 - 1.0);
let phase = |t: f64| match chirp_law {
    ChirpLaw::Quadratic {
        vertex_at_end: false,
    } => f0 * t + delta * t.powi(3) / (3.0 * duration * duration),
    ChirpLaw::Quadratic {
        vertex_at_end: true,
    } => f0 * t + delta * (t * t / duration - t.powi(3) / (3.0 * duration * duration)),
    ChirpLaw::Logarithmic => f0 * duration * (ratio.powf(t / duration) - 1.0) / ratio.ln(),
    ChirpLaw::Hyperbolic => f0 * duration * (b * t / duration).ln_1p() / b,
    ChirpLaw::Linear => f0 * t + delta * t * t / (2.0 * duration),
};
let frequency = |t: f64| {
    let u = t / duration;
    match chirp_law {
        ChirpLaw::Quadratic {
            vertex_at_end: false,
        } => f0 + delta * u * u,
        ChirpLaw::Quadratic {
            vertex_at_end: true,
        } => f0 + delta * (1.0 - (1.0 - u) * (1.0 - u)),
        ChirpLaw::Logarithmic => f0 * ratio.powf(u),
        ChirpLaw::Hyperbolic => f0 / (1.0 + b * u),
        ChirpLaw::Linear => f0 + delta * u,
    }
};
let chunk_gap = whole
    .iter()
    .zip(&pieces)
    .map(|(a, c)| (a - c).abs())
    .fold(0.0_f64, f64::max);
let formula_gap = whole
    .iter()
    .zip(&times)
    .map(|(a, &t)| (a - (std::f64::consts::TAU * phase(t)).cos()).abs())
    .fold(0.0_f64, f64::max);

let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let fixed3 = serde_json::json!({ "fractionDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "掃引の法則", "type": "string" },
    { "key": "1", "label": "一括と分割の最大差 [-]", "type": "number", "format": sci3 },
    { "key": "2", "label": "閉じた形との最大差 [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "f(0) [Hz]", "type": "number", "format": fixed3 },
    { "key": "4", "label": "f(T) [Hz]", "type": "number", "format": fixed3 }
]);
let rows = vec![(
    law.clone(),
    chunk_gap,
    formula_gap,
    frequency(0.0),
    frequency(duration),
)];
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "agreement" })
);

let signal: Vec<[f64; 2]> = times.iter().zip(&whole).map(|(&t, &y)| [t, y]).collect();
let law_curve: Vec<[f64; 2]> = times.iter().map(|&t| [t, frequency(t)]).collect();
emit_line_chart!(
    &vec![serde_json::json!({ "name": "チャープ x(t)", "points": signal })],
    options = &serde_json::json!({
        "xLabel": "時刻 t [s]",
        "yLabel": "振幅 [-]",
        "yMin": -1.1,
        "yMax": 1.1,
        "link": { "group": "chirp-time" }
    })
);
```

既定の線形の法則では、37 標本ずつ分けて作った列と一括の列の差は厳密に 0 で、閉じた形の位相から計算した値との差は $2.7 \times 10^{-14}$ である。

閉じた形との差は二次と対数の法則で $2.5 \times 10^{-14}$ から $4.9 \times 10^{-14}$、双曲線の法則では計算の順序が手計算と同じなので 0 になる。

## 作業精度の誤差

直接の畳み込みと相関、FIR フィルタ、多相のリサンプリング、Savitzky–Golay フィルタ、ウェーブレットのフィルタは、積和を作業精度で計算する。
$m$ 個の積の和について、結果の実部と虚部のそれぞれの絶対誤差は

$$
\gamma_{2m+8}\, M + (2m + 8)\, \eta, \qquad \gamma_k = \frac{k u}{1 - k u}
$$

以下である。
$M$ は積の絶対値の和、$\eta$ は最小の正の非正規化数で、$k u < 1$ を仮定する。
この限界は保存した係数に対するもので、フィルタの設計そのものの誤差は含まない。
ウェーブレットの多段の変換では、各段の誤差が係数の絶対値を通して次の段へ伝わる。

FFT を使う畳み込み、解析信号、Riesz 変換、Fourier のリサンプリングの誤差はノルムで測る量である。
誤差は $\varepsilon$、オペランドのノルム、変換長の対数に比例し、これに下位桁あふれの寄与が加わる。
そのため、最大の成分よりずっと小さい成分は相対精度をすべて失うか、0 に丸められうる。
入力は必要なときだけ 2 の累乗で尺度を調整するので、有限の結果が途中で桁あふれや下位桁あふれを起こすことはない。
結果そのものが桁あふれするときはエラーになる。
直接和と FFT は同じビット列を返すとは限らず、打ち消しの大きい出力の相対誤差だけで精度を判断してはいけない。

フィルタや系の設計の誤差は、極と零点の条件に依存する。
反復で求める設計（次数の選択、Remez 交換、極配置、DPSS）は終了状態と残差を返すので、それを読んでから結果を使う。
各ページの診断の意味はそのページで説明する。

## まとめ

DFT は順変換を正規化せず逆変換を長さで割るので、`power_spectrum` の値は $|X[k]|^2/N$ で、標本化周波数を含まない。
周波数は、FIR・IIR の設計と離散系では Nyquist 比、連続系と Lomb–Scargle 法では角周波数、Welch・STFT・波形では時間単位あたりの周期で渡す。
記録の外側の延長は `SignalBoundary` などで明示し、端の近くの出力がその仮定に依存することを考えて結果を読む。
繰り返す計算では、`SignalRequirements` の `max` で決めた一つの `SignalWorkspace` を複数の Plan に使い回し、逐次処理では `StreamChunk::Final` で記録を閉じる。
試験信号は `waveform_grid_into` の絶対の添字で作れば、チャンクに分けても一度に作った列と一致する。
各手法の導出と実験は、上の一覧から問いに合うページを選んで確かめる。
