周波数が時間とともに変わる信号では、記録全体の DFT は「どの周波数があったか」を示すが、「いつあったか」を失う。
短時間 Fourier 変換（STFT）は、ウインドウを少しずつずらしながら区間ごとの DFT を並べ、時間と周波数の両方の情報を残す。
このページでは STFT の定義と規約を述べ、係数から元の信号を戻す合成の条件を導く。
ウインドウそのものの性質は[窓関数と DPSS](../windows-and-dpss/)、パワーの推定は[スペクトル推定](../spectral-estimation/)で扱う。

## STFT の定義とフレーム

長さ $m$ のウインドウ $w$、hop（隣り合うフレームの開始位置の差）$h$、FFT 長 $n \ge m$ を決める。
フレーム $p$ の係数は

$$
X[p, k] = c_k \sum_{j=0}^{m-1} x[ph - \lfloor m/2 \rfloor + j]\, \overline{w[j]}\, e^{-2\pi i jk/n}, \qquad k = 0, \dots, n - 1
$$

である。
$c_k$ は係数の尺度、$\overline{w}$ は複素共役で、実数のウインドウでは $w$ そのものである。
フレーム $p$ は標本 $ph - \lfloor m/2 \rfloor$ から $m$ 個を覆い、その中心は標本 $ph$ にある。
位相はフレームの先頭を基準にとる。
$n > m$ にすると各フレームを $n$ 点まで 0 で延長してから FFT をかけ、スペクトルを細かい格子で標本化する。
零詰めは周波数分解能を変えない。

記録の外側の値は `StftOptions::with_boundary` の `SignalBoundary` で決める。
`Zero`（既定）は 0、`Periodic` は周期 $N$ の繰り返し、`Reflect` は端点を繰り返さない鏡映である。
境界の延長は分析だけに使い、合成は元の長さ $N$ の記録だけを返す。

`StftPlan::frames(N)` は、ウインドウが長さ $N$ の記録に少しでも重なるフレームの範囲を `StftFrames` で返す。
最初のフレームの番号 `first()` は $\lfloor(\lfloor m/2 \rfloor - m)/h\rfloor + 1 \le 0$ で、記録の先頭より前から始まるフレームを含む。
`count()` がフレームの数、`signal_len()` が記録の長さである。
`frame_time(p)` はフレームの中心の時刻 $ph/f_s$、`frame_sample_range(p)` は覆う標本の半開区間を返す。
係数はフレームごとに `bins()` 個ずつ並び、総数は `output_len(N)` である。
計算量は 1 フレームあたり長さ $n$ の FFT が 1 回である。

## ビンの並びと係数の尺度

ビン $k$ の周波数は、標本化周波数 $f_s$ に対して $k < \lceil n/2 \rceil$ なら $k f_s/n$、それ以外なら $(k - n) f_s/n$ で、単位は時間単位あたりの周期である。
`StftPacking` は 1 フレーム内のビンの並びを選ぶ。

- `Full`: DFT の自然な順 $k = 0, \dots, n-1$。
  負の周波数は後半に並ぶ。
- `Centered`: 周波数の昇順。
  周波数 0 はビン $\lfloor n/2 \rfloor$ に来る。
- `OneSided`: 非負の周波数の $\lfloor n/2 \rfloor + 1$ 個のビン。
  実数の標本の型に限る。

`StftScaling` は尺度 $c_k$ を選び、合成はその尺度を戻す。

- `Raw`（既定）: $c_k = 1$。
  ウインドウを掛けたフレームの正規化しない DFT である。
- `Magnitude`: $c_k = 1/|\sum_j w[j]|$。
  ビンの周波数にある振幅 1 の複素指数関数の係数の絶対値が 1 になる。
  実数の正弦波 $A\cos(2\pi f t)$ は正と負の周波数に分かれるので、各ビンの絶対値は $A/2$ になる。
- `Psd`: $c_k = 1/\sqrt{f_s \sum_j |w[j]|^2}$。
  $|X|^2$ がパワースペクトル密度になる。
  片側の並びでは、DC と（$n$ が偶数なら）Nyquist 周波数以外のビンにさらに $\sqrt 2$ を掛ける。

`spectrogram` と `spectrogram_into` はこの尺度の付いた $|X[p, k]|^2$ を、`cross_spectrogram_into` は $X[p,k]\,\overline{Y[p,k]}$ を返す。
位相を捨てたスペクトログラムからは、一般に元の信号を戻せない。

## 双対ウインドウによる合成

合成は各フレームの逆 FFT をとり、尺度 $c_k$ を戻して、合成ウインドウ $d$ を掛けて足し合わせる（オーバーラップ加算）。
逆 FFT の先頭 $m$ 標本はフレーム $p$ の $x[ph - \lfloor m/2 \rfloor + j]\,\overline{w[j]}$ なので、標本 $t$ には $t$ を覆うすべてのフレームから

$$
\hat x[t] = \sum_p x[t]\, \overline{w[t - ph + \lfloor m/2 \rfloor]}\, d[t - ph + \lfloor m/2 \rfloor]
$$

が集まる。
ウインドウの中の位置 $j = t - ph + \lfloor m/2 \rfloor$ を $h$ で割った余り $r = j \bmod h$ は、$t$ を固定すると $p$ によらない。
したがって $\hat x = x$ となる条件は、各余り $r = 0, \dots, h-1$ について

$$
\sum_{q} \overline{w[r + qh]}\, d[r + qh] = 1
$$

が成り立つことである。
この条件を満たす $d$ を、ウインドウ $w$ と hop $h$ の双対ウインドウと呼ぶ。
条件は余りごとに独立な 1 本の一次方程式なので、合成は記録全体の連立方程式を解かずに済む（有限台の「painless」な双対、Daubechies–Grossmann–Meyer）。

## NOLA と COLA

余り $r$ のウインドウのエネルギーを $E_r = \sum_q |w[r + qh]|^2$ とする。
双対ウインドウが存在するのは、すべての $r$ で $E_r > 0$ のとき、かつそのときに限る。
この条件を NOLA（nonzero overlap-add）と呼ぶ。
$E_r = 0$ の余りでは、その位置の標本がどのフレームにも重みを持たず、係数から復元できない。

一方 COLA（constant overlap-add）は、余りごとの和 $S_r = \sum_q w[r + qh]$ が $r$ によらず一定という条件である。
COLA が成り立つと、合成ウインドウを使わずにウインドウを掛けたフレームを足すだけで、定数倍を除いて記録が戻る。
COLA は双対ウインドウによる合成に必要ではない。
たとえば対称な Hann ウインドウは COLA を満たさないが、NOLA を満たすので正準双対で正確に再構成できる。

`check_overlap(window, hop, tolerance)` はウインドウを絶対値の最大で割り、$S_r$ と $E_r$ から二つの条件を判定して `OverlapDiagnostics` を返す。
COLA は $\max_r |S_r - S_0| \le \mathrm{atol} + \mathrm{rtol} \cdot \max_r |S_r|$ で、NOLA は $\min_r E_r / \max_r E_r > \mathrm{atol} + \mathrm{rtol}$ で判定する。
`energy_ratio()` はこの比 $\min_r E_r / \max_r E_r$ を返し、小さいほど合成が係数の誤差を増幅する。
hop がウインドウ長より長い場合と、ウインドウがすべて 0 の場合は、両方の条件が成り立たない。
計算量は $O(m)$ で、判定はウインドウの尺度によらず、誤差の上界は持たない。

周期ウインドウの余弦和 $\sum_{j=0}^{J} (-1)^j a_j \cos(2\pi j i/m)$ は、$m$ が $h$ で割り切れ $m/h > J$ のとき COLA を満たす。
$q$ について足すと、$j \ge 1$ の項は 1 の $m/h$ 乗根の和になって消えるからである。
Hann ウインドウ（$J = 1$）は $h = m/2$ で、4 項の Blackman–Harris ウインドウ（$J = 3$）は $h = m/4$ で COLA を満たす。

次のセルは、ウインドウの種類と長さを選び、いくつかの hop について `check_overlap` の判定と $E_r$ の比を表にする。
比の列は $E_r$ を直接足して求めた値との差で独立に検算する。
図は選んだ hop での $S_r$ と $E_r$ を余り $r$ の関数として描き、COLA なら $S_r$ が水平になる。

```rust
//| id: signal-stft-overlap-conditions
//| ref: signal-stft-overlap-conditions
//| title: ウインドウと hop の重なりの和から NOLA と COLA を判定する
//| run: reactive
//| crates: [scioxide-core, scioxide-signal]
//| inputs:
//|   window_name: {"type":"select","label":"ウインドウ","options":["Hann（周期）","Hann（対称）","Hamming（周期）","Blackman–Harris（周期）","矩形"],"value":"Hann（周期）"}
//|   window_length: {"type":"range","label":"ウインドウ長 m [標本]","description":"hop の候補は m/8、m/4、m/3、m/2、3m/4、m。","min":24,"max":96,"step":24,"value":48}
//|   hop_choice: {"type":"range","label":"図に描く hop h [標本]","description":"余りごとの和とエネルギーを描く hop。","min":1,"max":96,"step":1,"value":24}
//| cases:
//|   - {"id":"symmetric-hann","label":"Hann（対称）","description":"COLA は成り立たないが NOLA は成り立つ。","inputs":{"window_name":"Hann（対称）"}}
//|   - {"id":"blackman-harris","label":"Blackman–Harris、h = 12","description":"4 項の余弦和は h = m/4 で COLA になる。","inputs":{"window_name":"Blackman–Harris（周期）","hop_choice":12}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"hops","path":"/rows/3/0","equals":24}
//|       - {"artifact":"hops","path":"/rows/3/2","equals":"成立"}
//|       - {"artifact":"hops","path":"/rows/3/4","approx":{"value":0.5,"atol":1e-12}}
//|       - {"artifact":"hops","path":"/rows/3/5","range":{"max":1e-15}}
//|   - case: symmetric-hann
//|     expect:
//|       - {"artifact":"hops","path":"/rows/3/2","equals":"不成立"}
//|       - {"artifact":"hops","path":"/rows/3/3","equals":"成立"}
//|   - case: blackman-harris
//|     expect:
//|       - {"artifact":"hops","path":"/rows/1/2","equals":"成立"}
//|       - {"artifact":"hops","path":"/rows/3/2","equals":"不成立"}
use scioxide_core::Tolerance;
use scioxide_signal::{WindowKind, WindowNormalization, WindowSymmetry, check_overlap, window};

let m = window_length.round() as usize;
let (kind, symmetry) = match window_name.as_str() {
    "Hann（対称）" => (WindowKind::Hann, WindowSymmetry::Symmetric),
    "Hamming（周期）" => (WindowKind::Hamming, WindowSymmetry::Periodic),
    "Blackman–Harris（周期）" => (WindowKind::BlackmanHarris, WindowSymmetry::Periodic),
    "矩形" => (WindowKind::Boxcar, WindowSymmetry::Periodic),
    _ => (WindowKind::Hann, WindowSymmetry::Periodic),
};
let w = window::<f64>(kind, m, symmetry, WindowNormalization::Native).map_err(|e| e.to_string())?;
let tolerance = Tolerance::from_sqrt_epsilon();
// 余り r ごとの和 S_r とエネルギー E_r（独立な検算と図に使う直接和）
let residues = |h: usize| -> Vec<(f64, f64)> {
    (0..h)
        .map(|r| {
            let terms = w.iter().skip(r).step_by(h);
            (terms.clone().sum::<f64>(), terms.map(|v| v * v).sum::<f64>())
        })
        .collect()
};
let verdict = |ok: bool| if ok { "成立" } else { "不成立" };
let hops = [m / 8, m / 4, m / 3, m / 2, 3 * m / 4, m];
let mut rows = Vec::new();
for h in hops {
    let diagnostics = check_overlap(&w, h, tolerance).map_err(|e| e.to_string())?;
    let sums = residues(h);
    let (low, high) = sums
        .iter()
        .fold((f64::INFINITY, 0.0_f64), |(a, b), s| (a.min(s.1), b.max(s.1)));
    rows.push((
        h,
        100.0 * (m - h) as f64 / m as f64,
        verdict(diagnostics.cola()),
        verdict(diagnostics.nola()),
        diagnostics.energy_ratio(),
        (diagnostics.energy_ratio() - low / high).abs(),
    ));
}
let fixed1 = serde_json::json!({ "fractionDigits": 1 });
let fixed6 = serde_json::json!({ "fractionDigits": 6 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "hop h [標本]", "type": "integer" },
    { "key": "1", "label": "重なり [%]", "type": "number", "format": fixed1 },
    { "key": "2", "label": "COLA" },
    { "key": "3", "label": "NOLA" },
    { "key": "4", "label": "min E_r / max E_r [-]", "type": "number", "format": fixed6 },
    { "key": "5", "label": "直接和との差 [-]", "type": "number", "format": sci2 }
]);
emit_table_with_columns!(columns, rows, metadata = serde_json::json!({ "id": "hops" }));

let chosen = residues((hop_choice.round() as usize).clamp(1, m));
let sum_points: Vec<[f64; 2]> = chosen.iter().enumerate().map(|(r, s)| [r as f64, s.0]).collect();
let energy_points: Vec<[f64; 2]> = chosen.iter().enumerate().map(|(r, s)| [r as f64, s.1]).collect();
emit_line_chart!(
    &vec![
        serde_json::json!({ "name": "S_r = Σ_q w[r + qh]", "points": sum_points }),
        serde_json::json!({ "name": "E_r = Σ_q w[r + qh]²", "points": energy_points })
    ],
    options = &serde_json::json!({
        "xLabel": "余り r [標本]",
        "yLabel": "余りごとの和 [-]",
        "yMin": 0.0
    })
);
```

既定の周期 Hann ウインドウ（$m = 48$）では、hop 6、12、16、24 で COLA と NOLA が成り立ち、$E_r$ の比は $h \le 16$ で 1、$h = 24$ で 0.5 である。
$h = 36$ では COLA が崩れ、比は 0.043 に下がる。
$h = 48$ では余り 0 に端の標本 $w[0] = 0$ だけが入るので $E_0 = 0$ となり、NOLA も成り立たない。
対称な Hann ウインドウでは 6 つの hop のどれでも COLA が成り立たないが、$h = 36$ までは NOLA が成り立つ。
4 項の Blackman–Harris ウインドウは $m/h \ge 4$ の $h = 6$、12 で COLA を満たし、$m/h = 3$ の $h = 16$ では満たさない。
これは上の条件 $m/h > J$ と一致する。
端点が 0 でない Hamming ウインドウは $h = 48$ でも NOLA を満たすが、比は 0.0064 と小さい。
比の列と直接和の差は、すべての入力で $2.3 \times 10^{-16}$ 以下である。

## 双対ウインドウの選び方

双対の条件は余りごとに 1 本の方程式なので、NOLA のもとで双対ウインドウは一般に無数にある。
scioxide-signal は次の三つを閉じた形で計算し、どれもウインドウ長 $m$ に対して $O(m)$ である。

- 正準双対 `canonical_stft_dual(window, hop, tolerance)` は、Euclid ノルムが最小の双対 $d[j] = w[j]/E_r$（$r = j \bmod h$）である。
  余りごとに Lagrange の乗数法で $\sum_q |d|^2$ を最小にすると得られる。
  この合成は、変更した係数 $Y$ に最も近い STFT を持つ信号（$\sum_{p,k} |X[p,k] - Y[p,k]|^2$ を最小にする $x$）を与える（Griffin–Lim の最小二乗推定）。
  `StftPlan::new` は NOLA が成り立てばこの双対を準備し、成り立たなければ分析専用の Plan を作って `dual_window()` が `None` を返す。
- 最も近い双対 `closest_stft_dual(window, hop, desired, scale, tolerance)` は、望む合成ウインドウ `desired` に Euclid ノルムで最も近い双対である。
  `DualScale::Fixed` では双対全体への直交射影で、`DualScale::Optimized` では分析ウインドウを定数倍する係数も選び、その係数を `ClosestStftDual::window_scale()` が返す。
  合成には `window_scale()` 倍した分析ウインドウと `dual()` を組にして使う。
- タイトウインドウ `tight_stft_window(window, hop, tolerance)` は $g[j] = w[j]/\sqrt{E_r}$ で、自分自身の双対になる。
  分析と合成に同じウインドウを使え、係数のエネルギーが信号のエネルギーに比例する。

自分で選んだ組は `StftPlan::from_windows(window, dual, hop, options)` に渡し、合成ウインドウだけを決めて分析ウインドウをその正準双対にするときは `StftPlan::from_dual` を使う。
どちらも組が双対の条件を許容誤差の範囲で満たすかを確かめ、満たさなければ `InvalidInput`（`Inconsistent`）を返す。
計算した双対が自分の条件を満たさない場合は、丸めによる桁落ちとして `NumericalInstability`（`LossOfSignificance`）になる。

次のセルは、長さ 64 の Hann ウインドウと hop を選んで長さ 1024 の乱数の記録を片側の並びで分析し、三通りの組で合成する。
正準双対、すべて 1 の合成ウインドウに最も近い双対（`DualScale::Fixed`）、タイトウインドウの三つである。
前の二つは同じ分析ウインドウを使うので、係数も同じになる。
係数をそのまま合成した誤差と、係数に標準偏差 $\delta$ の複素ノイズを加えてから合成した誤差を比べる。
ノイズを加えた誤差を $\delta$ で割った値は、合成が係数の誤差を何倍にするかを表す。
双対の条件の残差 $\max_r |\sum_q \overline{w} d - 1|$ は、表示の前に直接和で計算し直す。

```rust
//| id: signal-stft-dual-reconstruction
//| ref: signal-stft-dual-reconstruction
//| title: 正準双対・最も近い双対・タイトウインドウで STFT を合成する
//| run: reactive
//| crates: [scioxide-core, scioxide-signal]
//| inputs:
//|   hop: {"type":"range","label":"hop h [標本]","description":"ウインドウ長 64 に対するフレームの間隔。","min":4,"max":56,"step":4,"value":16}
//|   symmetric_window: {"type":"checkbox","label":"対称な Hann ウインドウを使う","description":"COLA を満たさないウインドウでも合成できることを確かめる。","value":true}
//|   noise_level: {"type":"range","label":"係数のノイズ δ [-]","description":"係数の実部と虚部に加えるノイズの標準偏差。","min":0.001,"max":0.1,"step":0.001,"value":0.01}
//|   seed: {"type":"integer","label":"乱数のシード","description":"記録とノイズの系列を変える。","min":1,"max":9999,"value":11}
//| cases:
//|   - {"id":"periodic-half","label":"周期ウインドウ、h = 32","description":"COLA を満たす周期 Hann ウインドウでは正準双対がウインドウの定数倍になる。","inputs":{"symmetric_window":false,"hop":32}}
//|   - {"id":"sparse-hop","label":"h = 56","description":"重なりが少なく E_r の比が小さいので、ノイズが大きく増幅される。","inputs":{"hop":56}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"duals","path":"/rows/0/2","range":{"max":1e-12}}
//|       - {"artifact":"duals","path":"/rows/1/2","range":{"max":1e-12}}
//|       - {"artifact":"duals","path":"/rows/2/2","range":{"max":1e-12}}
//|       - {"artifact":"duals","path":"/rows/0/3","range":{"max":1e-13}}
//|   - case: sparse-hop
//|     expect:
//|       - {"artifact":"duals","path":"/rows/0/2","range":{"max":1e-10}}
use scioxide_core::{Complex, Tolerance};
use scioxide_signal::{
    DualScale, StftOptions, StftPacking, StftPlan, WindowKind, WindowNormalization,
    WindowSymmetry, closest_stft_dual, tight_stft_window, window,
};

let (m, h, len) = (64_usize, hop.round() as usize, 1024_usize);
let symmetry = if symmetric_window {
    WindowSymmetry::Symmetric
} else {
    WindowSymmetry::Periodic
};
let w = window::<f64>(WindowKind::Hann, m, symmetry, WindowNormalization::Native)
    .map_err(|e| e.to_string())?;
// 記録とノイズ: splitmix64 による一様乱数（f64 の固有メソッドで変換）
let mut state = seed as u64;
let mut uniform = || -> f64 {
    state = state.wrapping_add(0x9E37_79B9_7F4A_7C15);
    let mut z = state;
    z = (z ^ (z >> 30)).wrapping_mul(0xBF58_476D_1CE4_E5B9);
    z = (z ^ (z >> 27)).wrapping_mul(0x94D0_49BB_1331_11EB);
    ((z ^ (z >> 31)) >> 11) as f64 / (1u64 << 53) as f64 - 0.5
};
let x: Vec<f64> = (0..len).map(|_| uniform()).collect();
let tolerance = Tolerance::from_sqrt_epsilon();
let options = StftOptions::new().with_packing(StftPacking::OneSided);
let ones = vec![1.0; m];
// 分析ウインドウを変えない（Fixed）ので、正準双対と同じ係数から合成を比べられる
let closest =
    closest_stft_dual(&w, h, &ones, DualScale::Fixed, tolerance).map_err(|e| e.to_string())?;
let tight = tight_stft_window(&w, h, tolerance).map_err(|e| e.to_string())?;
let plans = [
    ("正準双対", StftPlan::new(&w, h, options)),
    ("矩形に最も近い双対", StftPlan::from_windows(&w, closest.dual(), h, options)),
    ("タイトウインドウ", StftPlan::from_windows(&tight, &tight, h, options)),
];
// 三つの合成に同じノイズを加える。標準偏差 δ（一様乱数 [−1/2, 1/2) の分散は 1/12）
// 片側の並びの DC と Nyquist のビンは実数でなければならないので、実部だけにノイズを加える
let amplitude = noise_level * 12.0_f64.sqrt();
let bins = m / 2 + 1;
let count = StftPlan::new(&w, h, options)
    .and_then(|p| p.output_len(len))
    .map_err(|e| e.to_string())?;
let perturbation: Vec<Complex<f64>> = (0..count)
    .map(|i| {
        let real_bin = i % bins == 0 || i % bins == bins - 1;
        let imaginary = if real_bin { 0.0 } else { amplitude * uniform() };
        Complex::new(amplitude * uniform(), imaginary)
    })
    .collect();
let mut rows = Vec::new();
for (name, plan) in plans {
    let plan = plan.map_err(|e| e.to_string())?;
    let dual = plan.dual_window().ok_or("NOLA が成り立たない")?;
    let analysis = plan.window();
    let coefficients = plan.analyze(&x).map_err(|e| e.to_string())?;
    let restored = plan.synthesize(&coefficients, len).map_err(|e| e.to_string())?;
    let error = x.iter().zip(&restored).map(|(a, b)| (a - b).abs()).fold(0.0, f64::max);
    let noisy: Vec<Complex<f64>> = coefficients
        .iter()
        .zip(&perturbation)
        .map(|(c, e)| *c + *e)
        .collect();
    let perturbed = plan.synthesize(&noisy, len).map_err(|e| e.to_string())?;
    let rms = (x.iter().zip(&perturbed).map(|(a, b)| (a - b).powi(2)).sum::<f64>()
        / len as f64)
        .sqrt();
    // 独立な検算: 余りごとの Σ_q w d − 1 を直接和で求める
    let residual = (0..h)
        .map(|r| {
            let s: f64 = analysis.iter().zip(dual).skip(r).step_by(h).map(|(a, d)| a * d).sum();
            (s - 1.0).abs()
        })
        .fold(0.0, f64::max);
    let norm = dual.iter().map(|d| d * d).sum::<f64>().sqrt();
    rows.push((name, norm, error, residual, rms / noise_level));
}
let fixed4 = serde_json::json!({ "fractionDigits": 4 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "合成ウインドウ" },
    { "key": "1", "label": "合成ウインドウのノルム ‖d‖₂ [-]", "type": "number", "format": fixed4 },
    { "key": "2", "label": "再構成誤差の最大 [-]", "type": "number", "format": sci2 },
    { "key": "3", "label": "双対の条件の残差 [-]", "type": "number", "format": sci2 },
    { "key": "4", "label": "ノイズの増幅率 [-]", "type": "number", "format": fixed4 }
]);
emit_table_with_columns!(columns, rows, metadata = serde_json::json!({ "id": "duals" }));
```

既定の対称 Hann ウインドウと $h = 16$ では、三つの組の再構成誤差はどれも $3.4 \times 10^{-16}$ 以下で、双対の条件の残差も $2.3 \times 10^{-16}$ 以下である。
COLA を満たさない対称ウインドウでも、正準双対で丸め誤差の範囲まで戻る。
合成ウインドウのノルムは正準双対が 3.29 で最も小さく、すべて 1 に最も近い双対は 5.73 である。
$\delta = 0.01$ のノイズに対する増幅率は正準双対が 0.143、最も近い双対が 0.248 で、同じ係数から合成した二つのうち正準双対が小さい。
これは正準双対による合成が最小二乗の推定であることの表れである。
タイトウインドウは余りごとのエネルギーが 1 なので、ノルムは $\sqrt h = 4$ になる。
タイトウインドウは分析ウインドウそのものを変えるので、増幅率 0.174 は前の二つと直接は比べられない。

$h = 56$ では $E_r$ の小さい余りができ、正準双対のノルムは 47.3、増幅率は 1.10 に跳ね上がる。
周期ウインドウと $h = 32$ ではウインドウが COLA を満たし、すべて 1 の列がそのまま双対になるので、最も近い双対のノルムは $\sqrt{64} = 8$、残差は 0 になる。
ノイズの大きさ $\delta$ を変えても増幅率はほとんど変わらず、合成が係数について線形であることと合う。

## Plan と作業領域

`StftPlan::new(window, hop, options)` はウインドウと hop を検査し、順方向と逆方向の FFT の Plan と、NOLA のもとで正準双対を準備する。
`StftOptions` の既定は、FFT 長がウインドウ長、標本化周波数 1、`StftPacking::Full`、`SignalBoundary::Zero`、`StftScaling::Raw`、許容誤差 `Tolerance::from_sqrt_epsilon()`、逐次実行である。
設定の関数は値を検査せず、`StftPlan::new` がまとめて検査する。
Plan は不変で、`Send + Sync + Clone` を満たし、ウインドウと双対ウインドウの複製を所有する。
`StftPlan::build` は実行コンテキストを受け取って FFT の Plan を作るが、コンテキストを保持しない。

`StftPlan::new` の失敗は次のとおりである。

- 空のウインドウは `InvalidInput`（`Empty`）、0 の hop と正でない標本化周波数は `InvalidInput`（`OutOfRange`）になる。
- ウインドウより短い FFT 長は `InvalidInput`（`Inconsistent`）、複素数の型での片側の並びは `InvalidInput`（`UnsupportedConfiguration`）になる。
- NaN や無限大のウインドウと標本化周波数は `NonFinite` になる。
- `Magnitude` で和が 0 のウインドウ、`Psd` で全標本が 0 のウインドウは `DomainError` になる。

所有値を返す API の `analyze`、`synthesize`、`spectrogram` は結果を `Vec` で返し、内部で作業領域を確保する。
出力先を指定する API `analyze_into`、`synthesize_into`、`spectrogram_into`、`cross_spectrogram_into`、`analyze_detrended_into` は呼び出し側の出力と作業領域に書き込む。
作業領域の大きさは `workspace_requirements(request)` で問い合わせ、`workspace(request)` で確保する。
`StftRequest` は操作と記録の長さの組で、`Analysis(N)`、`Synthesis(N)`、`Spectrogram(N)`、`CrossSpectrogram(N)`、`DetrendedAnalysis(N)` と、配列の 1 つの軸に沿った `Axis { shape, axis }` がある。
大きさは記録の長さに比例する。
配列の軸に沿った変換 `analyze_axis_into` と `synthesize_axis_into` では、標本の軸がフレームとビンの 2 軸に置き換わる。

合成は複素数の出力を作ってから実数の型へ戻すので、実数の型では虚部が許容誤差を超えると `DomainError`（`OutsideDomain`）を返す。
許容誤差 $t = \mathrm{atol} + \mathrm{rtol}$ は、虚部をその標本に重なるフレームの寄与の大きさの和と比べる。
変更した係数（たとえば片側の並びで DC のビンに虚部を持たせたもの）を合成するときは、この検査に注意する。
`analyze_detrended_into` はフレームごとに傾向を除いてからウインドウを掛けるので、その係数を合成しても記録は戻らない。

係数の誤差は FFT の正規ノルム誤差（演算対象のノルムと機械イプシロンと変換長の対数に比例する誤差）である。
合成で $r$ 個のフレームの寄与を足すと、寄与の絶対値の和の $\gamma_r$ 倍と $r\eta$ だけ誤差が増える（$\gamma_r = ru/(1 - ru)$、$u$ は単位丸め誤差、$\eta$ は最小の正の非正規数）。

## チャンクごとの分析と合成

`StftPlan::analysis_stream()` が返す `StftAnalysisStream` は、記録をチャンクに分けて受け取り、覆う標本がそろったフレームの係数から順に書き出す。
係数はチャンクの分け方によらず、零延長の `analyze_into` の係数と同じである。
ストリームは最後のウインドウ長分の標本を保持し、`StreamChunk::Final` を受け取ると記録の末尾より後ろにはみ出すフレームを書き出して閉じる。
閉じたストリームは `reset` するまで `InvalidInput`（`Inconsistent`）を返す。

`StftPlan::synthesis_stream(N)` が返す `StftSynthesisStream` は、長さ $N$ の記録の係数をフレーム単位のチャンクで受け取り、重なるフレームがそろった標本から書き出す。
フレームの途中で切れるチャンクや、記録のフレーム数を超えるチャンクは `InvalidInput`（`Inconsistent`）になる。
どちらのストリームも境界が `SignalBoundary::Zero` の Plan にしか作れない。

`output_len(input_len, chunk)` は次の呼び出しが書く個数を返し、`workspace_requirements(max)` で確保した作業領域は、入力が `max` 個以下の以後のすべての呼び出しに使える。
`process_into` が返す `StreamProgress` は、`consumed`（読んだ個数）、`produced`（書いた個数）、`first_output_index`（最初に書いた値の記録全体での位置）を持つ。
分析では `consumed` が標本、`produced` が係数の個数で、合成ではその逆になる。
ストリームは値なので、`clone` で状態を保存し、`clone_from` で確保せずに戻せる。

次のセルは、標本化周波数 1000 Hz の記録（125 Hz の余弦波と乱数の和）を周期 Hann ウインドウ（$m = 64$、$h = 16$）、片側の並び、`Magnitude` の尺度で分析する。
分析のストリームに長さ $L$ のチャンクで渡した係数を、出力先を指定する API `analyze_into` の係数と比べる。
125 Hz はビン 8 の中心にあるので、記録の内側のフレームで $|X[p, 8]|$ は振幅の半分 0.5 に近い。
次に合成のストリームに $F$ フレームずつ係数を渡し、元の記録との差を測る。

```rust
//| id: signal-stft-streaming
//| ref: signal-stft-streaming
//| title: チャンクに分けた STFT の分析と合成を一括処理と比べる
//| run: reactive
//| crates: [scioxide-core, scioxide-signal]
//| inputs:
//|   chunk_len: {"type":"range","label":"分析のチャンク長 L [標本]","description":"1 回の呼び出しで渡す標本の数。","min":1,"max":400,"step":1,"value":100}
//|   frames_per_chunk: {"type":"range","label":"合成のチャンク F [フレーム]","description":"1 回の呼び出しで渡すフレームの数。","min":1,"max":20,"step":1,"value":3}
//|   seed: {"type":"integer","label":"乱数のシード","description":"余弦波に加える乱数を変える。","min":1,"max":9999,"value":5}
//| cases:
//|   - {"id":"single-samples","label":"L = 1、F = 1","description":"1 標本ずつ渡しても係数は一括処理と同じになる。","inputs":{"chunk_len":1,"frames_per_chunk":1}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"stream","path":"/rows/0/1","range":{"max":0}}
//|       - {"artifact":"stream","path":"/rows/1/1","range":{"max":1e-12}}
//|       - {"artifact":"stream","path":"/rows/2/1","approx":{"value":0.5,"atol":0.02}}
//|   - case: single-samples
//|     expect:
//|       - {"artifact":"stream","path":"/rows/0/1","range":{"max":0}}
//|       - {"artifact":"stream","path":"/rows/1/1","range":{"max":1e-12}}
use scioxide_core::{Complex, ExecutionContext, RealScalar};
use scioxide_signal::{
    StftOptions, StftPacking, StftPlan, StftRequest, StftScaling, StreamChunk, WindowKind,
    WindowNormalization, WindowSymmetry, window,
};

let (fs, len, m, hop) = (1000.0_f64, 1000_usize, 64_usize, 16_usize);
let w = window::<f64>(WindowKind::Hann, m, WindowSymmetry::Periodic, WindowNormalization::Native)
    .map_err(|e| e.to_string())?;
let options = StftOptions::new()
    .with_sample_rate(fs)
    .with_packing(StftPacking::OneSided)
    .with_scaling(StftScaling::Magnitude);
let plan = StftPlan::new(&w, hop, options).map_err(|e| e.to_string())?;
let mut state = seed as u64;
let mut uniform = || -> f64 {
    state = state.wrapping_add(0x9E37_79B9_7F4A_7C15);
    let mut z = state;
    z = (z ^ (z >> 30)).wrapping_mul(0xBF58_476D_1CE4_E5B9);
    z = (z ^ (z >> 27)).wrapping_mul(0x94D0_49BB_1331_11EB);
    ((z ^ (z >> 31)) >> 11) as f64 / (1u64 << 53) as f64 - 0.5
};
let x: Vec<f64> = (0..len)
    .map(|i| RealScalar::cos(2.0 * core::f64::consts::PI * 125.0 * i as f64 / fs) + 0.1 * uniform())
    .collect();

// 一括処理（出力先を指定する API）: 作業領域を StftRequest で確保する
let cx = ExecutionContext::sequential();
let mut ws = plan.workspace(StftRequest::Analysis(len)).map_err(|e| e.to_string())?;
let mut offline = vec![Complex::new(0.0, 0.0); plan.output_len(len).map_err(|e| e.to_string())?];
plan.analyze_into(&x, &mut offline, &mut ws, cx).map_err(|e| e.to_string())?;

// 分析のストリーム: 長さ L のチャンクで渡し、最後のチャンクを Final にする
let l = chunk_len.round() as usize;
let mut stream = plan.analysis_stream().map_err(|e| e.to_string())?;
let mut stream_ws = stream.workspace(l).map_err(|e| e.to_string())?;
let mut streamed = Vec::with_capacity(offline.len());
let mut calls = 0;
for (index, chunk) in x.chunks(l).enumerate() {
    let kind = if (index + 1) * l >= len { StreamChunk::Final } else { StreamChunk::Partial };
    let count = stream.output_len(chunk.len(), kind).map_err(|e| e.to_string())?;
    let mut out = vec![Complex::new(0.0, 0.0); count];
    stream.process_into(chunk, kind, &mut out, &mut stream_ws, cx).map_err(|e| e.to_string())?;
    streamed.extend_from_slice(&out);
    calls += 1;
}
let analysis_gap = offline
    .iter()
    .zip(&streamed)
    .map(|(a, b)| (*a - *b).norm())
    .fold(0.0, f64::max);

// 合成のストリーム: F フレームずつ渡す
let bins = plan.bins();
let block = frames_per_chunk.round() as usize * bins;
let mut synthesis = plan.synthesis_stream(len).map_err(|e| e.to_string())?;
let mut synth_ws = synthesis.workspace(block).map_err(|e| e.to_string())?;
let mut restored = Vec::with_capacity(len);
for (index, chunk) in streamed.chunks(block).enumerate() {
    let kind = if (index + 1) * block >= streamed.len() { StreamChunk::Final } else { StreamChunk::Partial };
    let count = synthesis.output_len(chunk.len(), kind).map_err(|e| e.to_string())?;
    let mut out = vec![0.0; count];
    synthesis.process_into(chunk, kind, &mut out, &mut synth_ws, cx).map_err(|e| e.to_string())?;
    restored.extend_from_slice(&out);
}
let synthesis_error = x.iter().zip(&restored).map(|(a, b)| (a - b).abs()).fold(0.0, f64::max);

// 内側のフレーム（記録にウインドウが収まるフレーム）での |X[p, 8]|
let frames = plan.frames(len).map_err(|e| e.to_string())?;
let inner: Vec<f64> = (0..frames.count())
    .filter(|&i| {
        let start = (frames.first() + i as i64) * hop as i64 - (m / 2) as i64;
        start >= 0 && start + m as i64 <= len as i64
    })
    .map(|i| offline[i * bins + 8].norm())
    .collect();
let tone = inner.iter().sum::<f64>() / inner.len() as f64;

let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "量" },
    { "key": "1", "label": "値", "type": "number", "format": sci2 }
]);
let rows = vec![
    ("ストリームと一括処理の係数の差の最大 [-]", analysis_gap),
    ("合成のストリームの再構成誤差の最大 [-]", synthesis_error),
    ("内側のフレームの |X[p, 8]| の平均 [-]", tone),
    ("フレーム数 [-]", frames.count() as f64),
    ("最初のフレームの番号 [-]", frames.first() as f64),
    ("分析の呼び出し回数 [-]", calls as f64),
];
emit_table_with_columns!(columns, rows, metadata = serde_json::json!({ "id": "stream" }));
```

既定の $L = 100$ では分析を 10 回に分けて呼び、係数は一括処理とビット単位で一致する（差は 0）。
$L = 1$ で 1000 回に分けても、$L = 400$ で 3 回に分けても同じである。
合成のストリームの再構成誤差は $4.4 \times 10^{-16}$ で、$F$ によらない。
長さ 1000 の記録は番号 −1 から始まる 66 個のフレームを持ち、フレーム −1 は標本 −48 から始まる。
内側のフレームの $|X[p, 8]|$ の平均は 0.4993 で、振幅の半分 0.5 から乱数の寄与の分だけずれる。

## まとめ

STFT はウインドウを hop ずつずらした DFT の並びで、フレーム $p$ は標本 $ph$ を中心にし、位相はフレームの先頭を基準にとる。
合成できるかどうかは NOLA（余りごとのウインドウのエネルギーが正）で決まり、COLA はウインドウを掛けたフレームを足すだけで戻すための条件にすぎない。
既定の正準双対は最小ノルムで、変更した係数からの合成を最小二乗の意味で最良にする。
`check_overlap` の `energy_ratio()` が小さいウインドウと hop の組は、係数の誤差を大きく増幅するので避ける。
チャンクで届く記録は `StftAnalysisStream` と `StftSynthesisStream` で処理でき、結果は一括処理と同じになる。
STFT の時間分解能と周波数分解能の交換は[チャープのスペクトログラムと時間周波数の不確定性](../../examples/chirp-spectrogram-uncertainty/)、フレームを平均してパワーを推定する方法は[スペクトル推定](../spectral-estimation/)で扱う。
