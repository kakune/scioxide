有限の長さで観測した信号の DFT は、真のスペクトルそのものではなく、観測区間の形（ウインドウ）のスペクトルでぼかしたものになる。
このページでは、そのぼけ（スペクトル漏れ）を式で表し、窓関数を選ぶための指標を導く。
ウインドウの標本を作る `window`、指標を測る `window_metrics`、帯域へのエネルギーの集中を最大にする DPSS（`DpssTapers`）を扱う。
STFT とスペクトル推定はここで決めたウインドウを使う（[STFT と再構成](../stft/)、[スペクトル推定](../spectral-estimation/)）。

## 有限長の観測とスペクトル漏れ

長さ $N$ の区間 $0 \le n \le N-1$ で観測した列は、無限に続く列 $x[n]$ にウインドウ $w[n]$（区間外では 0）を掛けた $x_w[n] = x[n]\,w[n]$ である。
離散時間 Fourier 変換（DTFT）$X(e^{j\omega}) = \sum_n x[n] e^{-j\omega n}$ では、時間領域の積は周波数領域の周期的な畳み込みになる。

$$
X_w(e^{j\omega}) = \frac{1}{2\pi} \int_{-\pi}^{\pi} X(e^{j\theta})\, W(e^{j(\omega - \theta)})\, d\theta
$$

ここで $\omega$ は 1 標本あたりのラジアンで表した角周波数である。
角周波数 $\omega_0$ の複素正弦波 $x[n] = e^{j\omega_0 n}$ では $X$ が $\omega_0$ のデルタ関数になるので、$X_w(e^{j\omega}) = W(e^{j(\omega - \omega_0)})$ となる。
つまり 1 本の線スペクトルはウインドウのスペクトルの形に広がり、他の周波数へ漏れる。

ウインドウを掛けない観測は矩形ウインドウ $w[n] = 1$ にあたり、そのスペクトルは Dirichlet 核

$$
W_{\mathrm{R}}(e^{j\omega}) = e^{-j\omega (N-1)/2}\, \frac{\sin(N\omega/2)}{\sin(\omega/2)}
$$

である。
長さ $N$ の DFT のビンの間隔は $2\pi/N$ なので、周波数を「ビン」$\nu = N\omega/(2\pi)$ で測ると、主ローブ（中央の山）の零点は $\nu = \pm 1$ にある。
主ローブの外の山をサイドローブと呼ぶ。
矩形ウインドウの最大サイドローブは $\nu \approx 1.43$ にあり、主ローブより 13.3 dB 低いだけで、高さは $1/\nu$ の速さでしか減らない。
そのため、強い成分の漏れが離れた周波数の弱い成分を覆い隠す。

ウインドウを使うと、主ローブを広げる代わりにサイドローブを下げられる。
ウインドウの端で値と低次の導関数が 0 に近づくほど、サイドローブは速く減衰する。
DTFT の端点の不連続は $1/\nu$ の減衰を生み、$p$ 階導関数まで連続にすると減衰は $1/\nu^{p+2}$ になるからである。
主ローブの幅（周波数分解能）とサイドローブの高さ（漏れの抑制）は同時には改善できず、ウインドウの選択はこの交換で決まる。

## ウインドウの種類とパラメータ

`WindowKind` はウインドウの種類とそのパラメータを表す列挙型で、24 種類の列挙子を持つ。
式は標本化する長さ $N_s$（要求した長さ、周期ウインドウではそれに 1 を足した長さ）、添字 $i = 0, \dots, N_s - 1$、中心 $c = (N_s - 1)/2$、中心からの座標 $z = 2i/(N_s - 1) - 1 \in [-1, 1]$ で書かれる。

余弦和のウインドウは

$$
w[i] = \sum_{j=0}^{m-1} (-1)^j a_j \cos\!\left( \frac{2\pi j i}{N_s - 1} \right)
$$

で、係数 $a_j$ が族を決める。
周期ウインドウでは、各項のスペクトルが矩形ウインドウの Dirichlet 核を $\pm j$ ビンずらした和になり、ずれた核のサイドローブが打ち消し合う。

| 分類 | 列挙子 | 定義の要点 |
|---|---|---|
| 余弦和 | `Hann`（$a = [0.5, 0.5]$）、`Hamming`（$[0.54, 0.46]$）、`Blackman`（$[0.42, 0.5, 0.08]$）、`Nuttall`、`BlackmanHarris`（4 項）、`FlatTop`（5 項）、`GeneralCosine(&[f64])`、`GeneralHamming { alpha }` | 係数は列挙子の rustdoc に書かれている。`GeneralCosine` は Hann を `[0.5, 0.5]` と書く正の符号の係数を取る |
| 区分的な多項式 | `Boxcar`、`Triang`、`Bartlett`、`Parzen`、`Bohman`、`Barthann` | `Triang` は端点が 0 にならない三角形、`Bartlett` は端点が 0 の三角形 |
| パラメータで形を変える族 | `Kaiser { beta }`、`KaiserBesselDerived { beta }`、`Gaussian { sigma }`、`GeneralGaussian { power, sigma }`、`Tukey { alpha }`、`Exponential { tau, center }` | Kaiser は $I_0(\beta\sqrt{1 - z^2}) / I_0(\beta)$（$I_0$ は 0 次の第 1 種変形 Bessel 関数）。$\beta$ を大きくすると主ローブが広がりサイドローブが下がる |
| サイドローブの高さを指定する族 | `Chebyshev { attenuation }`、`Taylor { nbar, sidelobe_level, normalize }` | Dolph–Chebyshev ウインドウはすべてのサイドローブを `attenuation` dB だけ主ローブより下げ、長さ $N_s$ の FFT で計算する。Taylor ウインドウは主ローブに近い `nbar` 個のサイドローブをほぼ一定の高さに保つ |
| その他 | `Cosine`（$\sin(\pi(i + 1/2)/N_s)$）、`Lanczos`（$\operatorname{sinc} z$） | |

パラメータは出力の型によらず `f64` で受け取り、標本も `f64` で評価してから出力の型へ変換する。
NaN や無限大のパラメータは `NonFinite`、範囲外の値（負の $\beta$、正でない $\sigma$・$\tau$・`attenuation`・`sidelobe_level`、0 の `nbar`、空の係数列）は `InvalidInput` になる。
Kaiser–Bessel 派生ウインドウは偶数長と対称ウインドウだけを受け付け、`Exponential` の中心を明示するのは周期ウインドウのときに限られる。
長さ 0 のウインドウは空の列、長さ 1 のウインドウは $[1]$ である。

関数 `window(kind, length, symmetry, normalization)` は標本を `Vec` で返す。
同じ引数の `Window::new` は標本を計算して値として保持し、`samples()` で借用し、`into_samples()` で取り出す。
標本を何度も使うときや、構造体のフィールドにウインドウを持たせるときは `Window` を使う。

計算量は多くの族で $O(N)$ で、対称ウインドウは半分だけ評価して折り返す。
Taylor ウインドウは $O(N \bar n + \bar n^2)$、Dolph–Chebyshev ウインドウは FFT を使うので $O(N \log N)$ である。
余弦和のウインドウの標本の絶対誤差は、$m$ 項の和で $A = \sum_j |a_j|$、$J = \sum_j j|a_j|$、$u = 2^{-53}$ とすると、余弦の評価の誤差を除いて約 $2muA + 10\pi u J$ 以下である。
ウインドウの零点の近くでは、この絶対誤差に対する相対精度はない。

## 対称ウインドウと周期ウインドウ

`WindowSymmetry` は標本化の規約を選ぶ。

- `Symmetric`（既定）は長さ $N$ の対称な列を作り、両端点を含む。
  $w[i] = w[N-1-i]$ を満たすので、線形位相の FIR フィルタの係数に使う（[FIR の設計と最小位相](../fir-design-and-minimum-phase/)）。
- `Periodic` は長さ $N + 1$ の対称な列を作って最後の標本を除く。
  残った $N$ 標本は周期 $N$ の関数の 1 周期になるので、DFT の解析に使う。

周期ウインドウでは余弦和の各項が長さ $N$ の DFT の基底と一致する。
そのため Hann ウインドウの和は $N/2$、二乗和は $3N/8$ となり、Hann ウインドウを $N/2$ ずつずらして足すと定数になる。
対称ウインドウは周期 $N - 1$ の Hann ウインドウに端点を 1 つ加えた列で、和は $(N-1)/2$、二乗和は $3(N-1)/8$ である。
二つの規約の差は $1/N$ の程度で、短いウインドウほど目立つ。

## ウインドウの尺度

`WindowNormalization` は、周期ウインドウが最後の標本を除いた後に適用する尺度を選ぶ。
`Native`（既定）は族の定義どおりの尺度、`UnitPeak` は絶対値の最大で割った尺度、`UnitEnergy` は Euclid ノルムで割った尺度である。
すべての標本が 0 のときに `UnitPeak` か `UnitEnergy` を求めると `DomainError` になる。

尺度は指標のうち ENBW を変えず、コヒーレント利得だけを定数倍する。
`StftPlan` と `SpectralEstimatePlan` はウインドウの和や二乗和で係数を割るので、尺度の選び方は結果の単位に影響しない。

## コヒーレント利得と等価雑音帯域幅

ウインドウの性能は正弦波に対する利得と白色雑音に対する利得の比で測る。

ビンの中心の周波数 $\nu = k$ にある振幅 $A$ の実正弦波 $A\cos(2\pi k n/N + \phi)$ を考える。
ウインドウを掛けた DFT のビン $k$ の値は、負の周波数の成分の漏れを無視すると $|X_k| = A\,|\sum_n w[n]|/2$ である。
そこで、コヒーレント利得を

$$
G_c = \frac{1}{N} \sum_{n=0}^{N-1} w[n]
$$

と定義すると、片側の振幅は $A = 2|X_k| / (N G_c)$ で求まる。
正弦波の周波数がビンの中心から半ビンずれると、ピークの高さは $|W(\nu = 1/2)|/|W(0)|$ 倍に下がる。
これをスカロップ損失と呼ぶ。

分散 $\sigma^2$ の白色雑音では $\mathrm{E}|X_k|^2 = \sigma^2 \sum_n w[n]^2$ である。
同じノイズの電力を、高さ $|W(0)|^2 = (\sum_n w[n])^2$ で幅 $B$ ビンの理想的な矩形の帯域が通したとして、$B$ を解くと等価雑音帯域幅（ENBW）

$$
\mathrm{ENBW} = N \frac{\sum_{n} w[n]^2}{\left( \sum_{n} w[n] \right)^2} \quad [\text{ビン}]
$$

が得られる。
片側の電力スペクトル密度 $S$ のノイズが 1 つのビンに与える電力は $S \cdot \mathrm{ENBW} \cdot f_s/N$ で、$f_s$ は標本化周波数である。
Cauchy–Schwarz の不等式から ENBW $\ge 1$ で、等号は矩形ウインドウのときに限る。

`window_metrics(samples)` は実際の標本から $G_c$ と ENBW を計算し、`WindowMetrics` の `coherent_gain()` と `equivalent_noise_bandwidth()` で返す。
和は最大の $|w[n]|$ で割ってから `f64` の補償和で求める。
空の標本は `InvalidInput`、NaN や無限大は `NonFinite`、和が 0 の標本は ENBW が定義されないので `DomainError` になる。
$G_c$ は符号を含む平均で、負の標本を持つウインドウ（Flat-top など）では和の打ち消しを含む。

次のセルは Hann ウインドウの対称ウインドウと周期ウインドウを作り、測った値を上の閉じた形と比べる。
周期ウインドウでは $G_c = 1/2$、ENBW $= 1.5$ ビンである。
対称ウインドウでは $G_c = (N-1)/(2N)$、ENBW $= 1.5N/(N-1)$ となる。
表の閉じた形の列はこの式による独立な検算である。

```rust
//| id: signal-hann-gain-bandwidth
//| ref: signal-hann-gain-bandwidth
//| title: 対称ウインドウと周期ウインドウの実標本から利得を読む
//| run: reactive
//| crates: [scioxide-signal]
//| inputs:
//|   window_length: {"type":"range","label":"ウインドウ長 N [標本]","description":"端点の影響と二つの規約の差を変える。","min":16,"max":64,"step":8,"value":32}
//|   periodic_window: {"type":"checkbox","label":"周期ウインドウを使う","description":"一つ長い対称列から最後の標本を除く標本化を選ぶ。","value":true}
//| cases:
//|   - {"id":"symmetric-16","label":"対称ウインドウ、N = 16","description":"両端が 0 になり、ENBW が 1.6 ビンに増える。","inputs":{"window_length":16,"periodic_window":false}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"metrics","path":"/rows/0/1","approx":{"value":0.5,"atol":1e-15}}
//|       - {"artifact":"metrics","path":"/rows/1/1","approx":{"value":1.5,"atol":1e-14}}
//|       - {"artifact":"metrics","path":"/rows/1/3","range":{"max":1e-14}}
//|   - case: symmetric-16
//|     expect:
//|       - {"artifact":"metrics","path":"/rows/0/1","approx":{"value":0.46875,"atol":1e-15}}
//|       - {"artifact":"metrics","path":"/rows/1/1","approx":{"value":1.6,"atol":1e-14}}
//|       - {"artifact":"metrics","path":"/rows/1/3","range":{"max":1e-14}}
use scioxide_signal::{WindowKind, WindowNormalization, WindowSymmetry, window, window_metrics};

let n = window_length.round() as usize;
let symmetry = if periodic_window {
    WindowSymmetry::Periodic
} else {
    WindowSymmetry::Symmetric
};

// Hann ウインドウの標本を定義どおりの尺度（Native）で作る
let samples = window::<f64>(WindowKind::Hann, n, symmetry, WindowNormalization::Native)
    .map_err(|e| e.to_string())?;
let metrics = window_metrics(&samples).map_err(|e| e.to_string())?;

// 独立な検算: 周期ウインドウは周期 N、対称ウインドウは周期 N − 1 の Hann ウインドウの 1 周期分の和を持つ
let period = if periodic_window { n } else { n - 1 } as f64;
let expected_gain = period / (2.0 * n as f64);
let expected_bandwidth = 1.5 * n as f64 / period;

let fixed6 = serde_json::json!({ "fractionDigits": 6 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "量" },
    { "key": "1", "label": "window_metrics の値", "type": "number", "format": fixed6 },
    { "key": "2", "label": "閉じた形", "type": "number", "format": fixed6 },
    { "key": "3", "label": "絶対誤差", "type": "number", "format": sci2 }
]);
let rows = vec![
    (
        "コヒーレント利得 G_c [-]",
        metrics.coherent_gain(),
        expected_gain,
        (metrics.coherent_gain() - expected_gain).abs(),
    ),
    (
        "ENBW [ビン]",
        metrics.equivalent_noise_bandwidth(),
        expected_bandwidth,
        (metrics.equivalent_noise_bandwidth() - expected_bandwidth).abs(),
    ),
];
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "metrics" })
);

let curve: Vec<[f64; 2]> = samples
    .iter()
    .enumerate()
    .map(|(j, &w)| [j as f64, w])
    .collect();
emit_line_chart!(
    &vec![serde_json::json!({ "name": "Hann ウインドウ", "points": curve })],
    options = &serde_json::json!({
        "xLabel": "標本の添字 j [-]",
        "yLabel": "ウインドウの係数 w[j] [-]",
        "yMin": 0.0,
        "yMax": 1.05
    })
);
```

既定の $N = 32$ の周期ウインドウでは、$G_c = 0.5$、ENBW $= 1.5$ ビンが閉じた形と一致し、表の差は 0 である。
周期ウインドウでは最後の標本が 0 にならず、図の右端は 0 に戻らない。
対称ウインドウに切り替えると両端が 0 になり、$N = 16$ では $G_c = 0.46875$、ENBW $= 1.6$ ビンになり、閉じた形との差は $2.2 \times 10^{-16}$ 以下である。
$N$ を大きくすると、二つの規約の差は $1/N$ に比例して小さくなる。

## ウインドウの性能の比較

ウインドウの周波数応答 $W(e^{j\omega})$ は、ウインドウの標本の後ろに 0 を足した長い列の DFT で、細かい格子の上で評価できる。
長さ $N$ のウインドウを $ZN$ 点に零詰めすると、DFT は $1/Z$ ビン間隔の格子で DTFT の値を与える。
零詰めは格子を細かくするだけで、周波数分解能は変えない。

次のセルは、長さ $N$ の周期ウインドウを `window` で作り、$Z = 32$ 倍に零詰めした列の `power_spectrum`（$|W_k|^2 / (ZN)$）から次の量を求める。

- 3 dB 幅: $|W|^2$ が中央の半分になる周波数の 2 倍。
  格子点の間は dB の値を線形補間する。
- 最初の零点: 主ローブの外側で $|W|^2$ が最初に極小になる位置。
- 最大サイドローブ: 最初の零点より外側の $|W|^2$ の最大値と中央の比。
  極大の格子点の前後 3 点に dB の放物線を当てはめて頂点を求める。
- スカロップ損失: 半ビンずれた位置の $|W|^2$ と中央の比。
- ENBW: `window_metrics` の値と、Parseval の関係から $\sum_k |W_k|^2 / (Z |W_0|^2)$ で求めた値の差。

ウインドウは矩形、Hann、Hamming、Blackman、4 項の Blackman–Harris、5 項の Flat-top と、入力で $\beta$ を選ぶ Kaiser ウインドウである。
図は正規化した電力 $|W(\nu)|^2 / |W(0)|^2$ を対数軸で描く。

```rust
//| id: signal-window-leakage-comparison
//| ref: signal-window-leakage-comparison
//| title: 零詰めの DFT でウインドウの主ローブとサイドローブを測る
//| run: reactive
//| crates: [scioxide-core, scioxide-signal]
//| inputs:
//|   window_length: {"type":"range","label":"ウインドウ長 N [標本]","description":"周期ウインドウの長さ。指標は N によらずほぼ一定になる。","min":64,"max":2048,"step":64,"value":1024}
//|   kaiser_beta: {"type":"range","label":"Kaiser ウインドウの β [-]","description":"大きいほど主ローブが広がり、サイドローブが下がる。","min":0,"max":14,"step":0.5,"value":8.5}
//| cases:
//|   - {"id":"short-window","label":"N = 64","description":"短い周期ウインドウでも指標は N = 1024 とほぼ同じになる。","inputs":{"window_length":64}}
//|   - {"id":"kaiser-zero","label":"β = 0","description":"Kaiser ウインドウが矩形ウインドウに一致する。","inputs":{"kaiser_beta":0}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"windows","path":"/rows/0/1","approx":{"value":0.886,"atol":0.001}}
//|       - {"artifact":"windows","path":"/rows/0/3","approx":{"value":-13.26,"atol":0.01}}
//|       - {"artifact":"windows","path":"/rows/1/2","approx":{"value":2.0,"atol":0.01}}
//|       - {"artifact":"windows","path":"/rows/1/5","approx":{"value":1.5,"atol":1e-12}}
//|       - {"artifact":"windows","path":"/rows/1/6","range":{"max":1e-12}}
//|   - case: kaiser-zero
//|     expect:
//|       - {"artifact":"windows","path":"/rows/6/1","approx":{"value":0.886,"atol":0.001}}
//|       - {"artifact":"windows","path":"/rows/6/5","approx":{"value":1.0,"atol":1e-12}}
use scioxide_core::RealScalar;
use scioxide_signal::{
    WindowKind, WindowNormalization, WindowSymmetry, power_spectrum, window, window_metrics,
};

let n = window_length.round() as usize;
let zoom = 32_usize;
let kinds = [
    ("矩形", WindowKind::Boxcar),
    ("Hann", WindowKind::Hann),
    ("Hamming", WindowKind::Hamming),
    ("Blackman", WindowKind::Blackman),
    ("Blackman–Harris（4 項）", WindowKind::BlackmanHarris),
    ("Flat-top（5 項）", WindowKind::FlatTop),
    ("Kaiser", WindowKind::Kaiser { beta: kaiser_beta }),
];
let decibel = |r: f64| 10.0 * RealScalar::log10(r);
let mut rows = Vec::new();
let mut curves = Vec::new();
for (name, kind) in kinds {
    let w = window::<f64>(kind, n, WindowSymmetry::Periodic, WindowNormalization::Native)
        .map_err(|e| e.to_string())?;
    let metrics = window_metrics(&w).map_err(|e| e.to_string())?;
    // ウインドウを Z 倍に零詰めし、|W_k|² を 1/Z ビンの格子で求める
    let mut padded = vec![0.0; zoom * n];
    padded[..n].copy_from_slice(&w);
    let power = power_spectrum(&padded).map_err(|e| e.to_string())?;
    let half: Vec<f64> = power[..=zoom * n / 2].iter().map(|p| p / power[0]).collect();
    // 3 dB 幅: 半値を下回る最初の格子点と一つ手前の間を dB で線形補間する
    let k3 = half.iter().position(|&r| r < 0.5).ok_or("3 dB 点がない")?;
    let (a, b) = (decibel(half[k3 - 1]), decibel(half[k3]));
    let crossing = (k3 - 1) as f64 + (a - decibel(0.5)) / (a - b);
    let width = 2.0 * crossing / zoom as f64;
    // 最初の零点: 半値より低い最初の極小
    let null = (1..half.len() - 1)
        .find(|&k| half[k] < 0.5 && half[k] <= half[k - 1] && half[k] <= half[k + 1])
        .ok_or("主ローブの外の極小がない")?;
    // 最大サイドローブ: 極大の格子点の前後で dB の放物線の頂点を求める
    let peak = (null..half.len() - 1)
        .max_by(|&i, &j| half[i].total_cmp(&half[j]))
        .ok_or("サイドローブがない")?;
    let (l, c, r) = (decibel(half[peak - 1]), decibel(half[peak]), decibel(half[peak + 1]));
    let curvature = l - 2.0 * c + r;
    let sidelobe = if curvature < 0.0 {
        c - (r - l).powi(2) / (8.0 * curvature)
    } else {
        c
    };
    let scallop = decibel(half[zoom / 2]);
    // 独立な検算: Parseval の関係による ENBW
    let spectral_enbw = power.iter().sum::<f64>() / power[0] / zoom as f64;
    let enbw = metrics.equivalent_noise_bandwidth();
    rows.push((
        name,
        width,
        null as f64 / zoom as f64,
        sidelobe,
        scallop,
        enbw,
        (spectral_enbw - enbw).abs(),
    ));
    if matches!(name, "矩形" | "Hann" | "Blackman–Harris（4 項）" | "Kaiser") {
        let points: Vec<[f64; 2]> = half[..=16 * zoom]
            .iter()
            .enumerate()
            .filter(|(_, r)| **r > 0.0)
            .map(|(k, &r)| [k as f64 / zoom as f64, r])
            .collect();
        curves.push(serde_json::json!({ "name": name, "points": points }));
    }
}

let fixed3 = serde_json::json!({ "fractionDigits": 3 });
let fixed2 = serde_json::json!({ "fractionDigits": 2 });
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "ウインドウ" },
    { "key": "1", "label": "3 dB 幅 [ビン]", "type": "number", "format": fixed3 },
    { "key": "2", "label": "最初の零点 [ビン]", "type": "number", "format": fixed3 },
    { "key": "3", "label": "最大サイドローブ [dB]", "type": "number", "format": fixed2 },
    { "key": "4", "label": "スカロップ損失 [dB]", "type": "number", "format": fixed2 },
    { "key": "5", "label": "ENBW [ビン]", "type": "number", "format": fixed3 },
    { "key": "6", "label": "ENBW の Parseval 検算との差 [ビン]", "type": "number", "format": sci2 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "windows" })
);
emit_line_chart!(
    &curves,
    options = &serde_json::json!({
        "xLabel": "主ローブの中心からの周波数 ν [ビン]",
        "yLabel": "正規化した電力 |W(ν)|²/|W(0)|² [-]",
        "yType": "log",
        "xMin": 0.0,
        "xMax": 16.0,
        "yMin": 1e-14,
        "yMax": 2.0
    })
);
```

既定の $N = 1024$、$\beta = 8.5$ では、表は次の値になる。
矩形ウインドウの 3 dB 幅は 0.885 ビン、最大サイドローブは −13.26 dB、スカロップ損失は −3.92 dB である。
これは Dirichlet 核の値（$N \to \infty$ で 0.886 ビン、−13.26 dB、$20\log_{10}(2/\pi) = -3.92$ dB）と一致する。
Hann ウインドウは 1.441 ビン、−31.47 dB、ENBW 1.500 ビン、Hamming ウインドウは 1.303 ビン、−42.67 dB、ENBW 1.363 ビンである。

Flat-top ウインドウは 3 dB 幅 3.724 ビン、ENBW 3.770 ビンと最も広いが、スカロップ損失は −0.0098 dB で、ビンの間にある正弦波の振幅をほぼそのまま読める。
余弦和のウインドウの最初の零点は項の数と同じ 1〜5 ビンにある。
各項が Dirichlet 核をずらして重ねたもので、ずらした核の零点が重なるからである。
`window_metrics` の ENBW と Parseval の関係による値の差は $10^{-13}$ 以下である。

$\beta = 0$ の Kaiser ウインドウは矩形ウインドウと同じ行になり、$\beta = 14$ では 3 dB 幅 2.045 ビン、最大サイドローブ −105.93 dB まで変わる。
$N = 64$ に短くしても、3 dB 幅、ENBW、スカロップ損失は小数第 3 位まで変わらない。
最大サイドローブは Hamming ウインドウで −42.45 dB、Flat-top ウインドウで −88.16 dB に上がり、サイドローブの低いウインドウほど短いウインドウで差が出る。

## 帯域に集中したウインドウ

ウインドウの主ローブの幅を決めたうえで、その帯域の外へ漏れるエネルギーを最小にするウインドウは、固有値問題として求まる。
1 標本あたりの周期で測った半帯域幅を $W$（$0 < W < 1/2$）とする。
長さ $N$ の列 $v$ の DTFT を $V(f)$ とし、全エネルギーのうち帯域 $|f| \le W$ に入る割合

$$
\lambda = \frac{\int_{-W}^{W} |V(f)|^2\, df}{\int_{-1/2}^{1/2} |V(f)|^2\, df} = \frac{v^{\mathsf T} C v}{v^{\mathsf T} v}, \qquad C_{mn} = \frac{\sin(2\pi W (m - n))}{\pi (m - n)}, \quad C_{nn} = 2W
$$

を集中度と呼ぶ。
2 番目の等式は Parseval の関係と $\int_{-W}^{W} e^{2\pi j f (m-n)} df = C_{mn}$ から従う。
集中度は Rayleigh 商なので、Toeplitz 行列 $C$ の固有値が大きい順の固有ベクトル $v_0, v_1, \dots$ が、それまでの列に直交する列の中で集中度を最大にする。
これが離散長球列（DPSS、Slepian のウインドウ）で、$\lambda_k$ はその固有値である。

$C$ の固有値は、およそ $2NW$ 個（Shannon 数）が 1 の近くに、残りが 0 の近くに集まる。
1 に近い固有値どうしの差は指数的に小さいので、$C$ を直接分解すると固有ベクトルの区別が丸め誤差に埋もれる。
Slepian は $C$ と可換な対称三重対角行列

$$
T_{ii} = \left( \frac{N - 1}{2} - i \right)^2 \cos(2\pi W), \qquad T_{i-1,i} = T_{i,i-1} = \frac{i (N - i)}{2}
$$

を示した。
可換な対称行列は固有ベクトルを共有し、$T$ の固有値はよく分離しているので、$T$ の固有ベクトルは安定に求まる。
`DpssTapers` は $T$ を $N^2$ で割って係数の大きさを $N$ によらずそろえ、大きい方から $K$ 個の固有対を二分法と逆反復で選ぶ。
メモリは $O(NK)$ である。
各ウインドウの集中度 $\lambda_k$ は、ウインドウの自己相関を FFT で求めて $C$ との内積をとり、計算し直す。

### DPSS の API

`DpssTapers::<S>::new(length, time_bandwidth, taper_count, options)` は時間帯域積 $NW$ を `time_bandwidth` で受け取り、$W = NW/N$ とする。
$N$ は標本化する長さで、周期ウインドウでは要求した長さに 1 を足す。
`DpssOptions` は標本化の規約（既定 `Symmetric`）、ウインドウの尺度（既定 `UnitEnergy`）、三重対角の固有値解法の設定（`scioxide_linalg::HermitianEigenOptions`）を持つ。
計算は出力の型によらず `f64` で行う。

ウインドウは連続した行として `samples()` に並び、`taper(k)` で $k$ 番目のウインドウを借用できる。
偶数次のウインドウは和が正、奇数次のウインドウは最初の有意な標本が正になるように符号をそろえる。
`concentration_ratios()` は、周期化と尺度の調整の前の、標本化した長さ $N$ の単位エネルギーのウインドウに対する $\lambda_k$ を返す。

`report()` が返す `DpssReport` は、固有値解法の作業回数（`counts()`）と尺度付き残差（`residual()`）を持つ。
固有対 $(\mu, v)$ の尺度付き残差は $\lVert (T - \mu I) v \rVert_\infty / ((\lVert T \rVert_\infty + |\mu|) \lVert v \rVert_\infty)$ で、全ウインドウの最大値を保持する。
終了状態 `DpssTermination` の列挙子は `Completed` だけで、計算に失敗した場合はエラーを返す。
`Completed` は精度を主張しないので、精度は残差と集中度から判断する。

失敗は次のとおりである。
長さ 0 は `InvalidInput`（`Empty`）、`taper_count` が 1 以上・要求した長さ `length` 以下でない場合と、`time_bandwidth` が $(0, \text{length}/2)$ の外にある場合は `InvalidInput`、NaN や無限大の `time_bandwidth` は `NonFinite` になる。
二つの範囲は、周期ウインドウでも 1 を足す前の要求した長さで判定する。
固有値解法の失敗は `ConvergenceFailure` か `NumericalInstability` になる。
計算した集中度が $[0, 1]$ から $64\varepsilon N$ を超えて外れた場合も `NumericalInstability`（`LossOfSignificance`）になる。
長さ 1 のウインドウは $[1]$ で、集中度は $2W$ である。

次のセルは DPSS を計算し、集中度を Toeplitz 行列 $C$ の二次形式 $v^{\mathsf T} C v / v^{\mathsf T} v$ の直接和（$O(N^2)$、FFT を使わない独立な検算）と比べる。
ウインドウどうしの内積の最大値で直交性も確かめる。
終了状態を outcome で示し、診断に残差と最小の集中度を出す。

```rust
//| id: signal-dpss-concentration
//| ref: signal-dpss-concentration
//| title: DPSS の集中度を Toeplitz 行列の二次形式で確かめる
//| run: reactive
//| crates: [scioxide-core, scioxide-signal]
//| inputs:
//|   length: {"type":"range","label":"ウインドウ長 N [標本]","description":"ウインドウの長さ。","min":16,"max":256,"step":16,"value":128}
//|   time_bandwidth: {"type":"range","label":"時間帯域積 NW [-]","description":"半帯域幅 W = NW/N を決める。","min":1,"max":6,"step":0.5,"value":4}
//|   taper_count: {"type":"range","label":"ウインドウの数 K","description":"Shannon 数 2NW を超えると集中度が急に下がる。","min":1,"max":12,"step":1,"value":8}
//| cases:
//|   - {"id":"beyond-shannon","label":"K = 12","description":"2NW = 8 を超える次数のウインドウは帯域の外にエネルギーを持つ。","inputs":{"taper_count":12}}
//|   - {"id":"narrow-band","label":"NW = 1.5、K = 3","description":"帯域が狭いと 1 に近い集中度のウインドウが少ない。","inputs":{"time_bandwidth":1.5,"taper_count":3}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"tapers","path":"/rows/0/1","approx":{"value":1.0,"atol":1e-9}}
//|       - {"artifact":"tapers","path":"/rows/0/3","range":{"max":1e-12}}
//|       - {"artifact":"tapers","path":"/rows/7/3","range":{"max":1e-12}}
//|       - {"artifact":"tapers","path":"/rows/7/4","range":{"max":1e-12}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
//|   - case: beyond-shannon
//|     expect:
//|       - {"artifact":"tapers","path":"/rows/11/1","range":{"max":0.1}}
//|       - {"artifact":"tapers","path":"/rows/11/3","range":{"max":1e-12}}
//|       - {"path":"/outputs/2/state","equals":"satisfied"}
use scioxide_core::RealScalar;
use scioxide_signal::{DpssOptions, DpssTapers, DpssTermination};

let n = length.round() as usize;
let count = taper_count.round() as usize;
let tapers = DpssTapers::<f64>::new(n, time_bandwidth, count, DpssOptions::default())
    .map_err(|e| e.to_string())?;
let bandwidth = time_bandwidth / n as f64;

// 独立な検算: C の 1 列目 c[ℓ] = sin(2πWℓ)/(πℓ)、c[0] = 2W を作り、vᵀCv を直接和で求める
let pi = core::f64::consts::PI;
let kernel: Vec<f64> = (0..n)
    .map(|lag| match lag {
        0 => 2.0 * bandwidth,
        _ => RealScalar::sin(2.0 * pi * bandwidth * lag as f64) / (pi * lag as f64),
    })
    .collect();
let mut rows = Vec::with_capacity(count);
for k in 0..count {
    let v = tapers.taper(k).map_err(|e| e.to_string())?;
    let mut quadratic = 0.0;
    for (m, &vm) in v.iter().enumerate() {
        for (l, &vl) in v.iter().enumerate() {
            quadratic += vm * vl * kernel[m.abs_diff(l)];
        }
    }
    let energy: f64 = v.iter().map(|x| x * x).sum();
    let direct = quadratic / energy;
    // 直交性: 前のウインドウとの内積の最大（単位エネルギーなので 0 が理想）
    let mut overlap = 0.0_f64;
    for j in 0..k {
        let u = tapers.taper(j).map_err(|e| e.to_string())?;
        let dot: f64 = u.iter().zip(v).map(|(a, b)| a * b).sum();
        overlap = overlap.max(dot.abs());
    }
    let lambda = tapers.concentration_ratios()[k];
    rows.push((k, lambda, 1.0 - lambda, (lambda - direct).abs(), overlap));
}

let fixed12 = serde_json::json!({ "fractionDigits": 12 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let columns = serde_json::json!([
    { "key": "0", "label": "次数 k", "type": "integer" },
    { "key": "1", "label": "集中度 λ_k [-]", "type": "number", "format": fixed12 },
    { "key": "2", "label": "帯域外の割合 1 − λ_k [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "直接和との差 [-]", "type": "number", "format": sci3 },
    { "key": "4", "label": "前のウインドウとの内積の最大 [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    columns,
    rows.clone(),
    metadata = serde_json::json!({ "id": "tapers" })
);

let series: Vec<serde_json::Value> = (0..count.min(4))
    .map(|k| {
        let v = tapers.samples()[k * n..(k + 1) * n].to_vec();
        let points: Vec<[f64; 2]> = v.iter().enumerate().map(|(i, &x)| [i as f64, x]).collect();
        serde_json::json!({ "name": format!("v_{k}"), "points": points })
    })
    .collect();
emit_line_chart!(
    &series,
    options = &serde_json::json!({
        "xLabel": "標本の添字 i [-]",
        "yLabel": "ウインドウの係数 v_k[i]（単位エネルギー） [-]"
    })
);

let report = tapers.report();
let minimum = rows.iter().map(|r| r.1).fold(1.0_f64, f64::min);
let outcome = match report.termination() {
    DpssTermination::Completed => {
        Outcome::satisfied("固有対と全てのウインドウを計算した（精度の主張はない）")
    }
};
emit_outcome!(
    outcome
        .status(format!("{:?}", report.termination()))
        .diagnostic("固有対の尺度付き残差", report.residual().scaled_norm(), None)
        .diagnostic("最小の集中度", minimum, None)
);
```

既定の $N = 128$、$NW = 4$、$K = 8$ では、$\lambda_0 = 1 - 2.8 \times 10^{-10}$ から $\lambda_5 = 0.9926$、$\lambda_6 = 0.937$、$\lambda_7 = 0.699$ と下がる。
Shannon 数 $2NW = 8$ に近い次数で、集中度が 1 から離れ始める。
$K = 12$ にすると $\lambda_8 = 0.299$、$\lambda_9 = 0.064$、$\lambda_{11} = 7.5 \times 10^{-4}$ となり、この次数のウインドウは帯域の外にエネルギーの大半を持つ。
$NW = 1.5$ では $\lambda_0 = 0.9989$、$\lambda_1 = 0.969$、$\lambda_2 = 0.733$ で、1 に近いウインドウは 2 つしかない。
すべての入力の両端で、`concentration_ratios()` と二次形式の直接和の差は $1.3 \times 10^{-14}$ 以下、ウインドウどうしの内積は $5 \times 10^{-16}$ 以下、固有対の尺度付き残差は $2.3 \times 10^{-16}$ 以下である。
$1 - \lambda_k$ の列は 1 に近い数の差なので、$10^{-15}$ の程度の値（$NW = 6$ の $\lambda_0$ など）は丸め誤差しか表さない。

DPSS は帯域 $[-W, W]$ の外への漏れをウインドウごとに最小にする。
Shannon 数より少ない $K$ 個のウインドウでそれぞれ periodogram を作って平均すると、帯域幅 $2W$ の分解能を保ったまま推定の分散を下げられる（マルチテーパー法）。
scioxide-signal はマルチテーパーの推定関数を持たないので、`DpssTapers` の各ウインドウを `SpectralEstimatePlan` に渡し、結果を呼び出し側で平均する。

## まとめ

有限長の観測はウインドウのスペクトルとの畳み込みを生むので、ウインドウは主ローブの幅（分解能）とサイドローブの高さ（漏れ）の交換で選ぶ。
DFT の解析には周期ウインドウを使い、線形位相の FIR 設計には対称ウインドウを使う。
正弦波の振幅はコヒーレント利得で、ノイズの電力は ENBW で換算する。
`window_metrics` と零詰めの `power_spectrum` で、実際に使う標本の利得、3 dB 幅、サイドローブを確かめられる。
決まった帯域へのエネルギーの集中が目的なら DPSS を使い、集中度と残差で品質を判断する。
ウインドウを時間方向にずらして並べる短時間 Fourier 変換は [STFT と再構成](../stft/)、ウインドウを使ったスペクトル密度の推定は[スペクトル推定](../spectral-estimation/)で扱う。
