`scioxide-signal` は、畳み込みと相関、FIR・IIR フィルタの設計と適用、リサンプリング、窓関数とスペクトル推定、STFT、解析信号と Riesz 変換、最小位相への変換、ウェーブレット、平滑化、ピークなどの特徴抽出、状態空間モデルを出力に反映する。
このガイドは、目的から API となる項目を示し、公開されている 192 項目を用途別の四つの表にまとめる。
表の項目名のリンクは、docs.rs の 0.1.0 の API リファレンスを指す。

## 目的別の API

| したいこと | API となる項目 | 入力と主な設定 | 出力と規約 | 表 |
|---|---|---|---|---|
| 有限長の応答との線形畳み込み | `convolve` | 実数か複素数のスライス二つ | 長さ $N+M-1$ の `Vec` | [畳み込み・相関・リサンプリング](convolution-and-resampling/) |
| 同じ形の畳み込みを繰り返す | `ConvolutionNdPlan` | `ConvolutionOptions`、準備した核 | 呼び出し側の出力と作業領域 | [畳み込み・相関・リサンプリング](convolution-and-resampling/) |
| 周期信号の巡回畳み込み | `convolve_circular` | 同じ長さのスライス | 長さ $N$ | [畳み込み・相関・リサンプリング](convolution-and-resampling/) |
| 画像や多次元の格子の畳み込み | `convolve2d`、`ConvolutionNdPlan` | `MatrixView` または多次元のビュー、`ConvolutionOptions` | `Matrix`、または切り出し（`Full`・`Same`・`Valid`）を指定した配列 | [畳み込み・相関・リサンプリング](convolution-and-resampling/) |
| 時間差の推定 | `correlate` | 信号 $a$（長さ $N$）、参照 $b$（長さ $M$） | ラグ $-(M-1), \dots, N-1$ の昇順 | [畳み込み・相関・リサンプリング](convolution-and-resampling/) |
| 標本化周波数の変換 | `resample`、`resample_periodic` | 有理比 $L/M$、または出力の長さ | 中心をそろえた $\lceil NL/M \rceil$ 標本、または周期的な補間 | [畳み込み・相関・リサンプリング](convolution-and-resampling/) |
| 終わりのない列の FIR・リサンプリング | `OverlapPlan`、`PolyphasePlan` | ブロック長、有理比 $L/M$ | ストリームが消費数・出力数を返し、`StreamChunk::Final` で末尾を出す | [畳み込み・相関・リサンプリング](convolution-and-resampling/) |
| ウインドウの係数と利得 | `window`、`window_metrics`、`DpssTapers` | `WindowKind`、長さ、対称性、正規化 | 係数、コヒーレント利得と ENBW | [スペクトル・時間周波数解析・解析信号](spectra-and-time-frequency/) |
| 等間隔標本のパワースペクトル | `power_spectrum`、`welch`、`SpectralEstimatePlan` | 標本化周波数、セグメント長、ウインドウと重なり | $\lvert X \rvert^2/n$、または密度（信号単位の二乗／周波数） | [スペクトル・時間周波数解析・解析信号](spectra-and-time-frequency/) |
| 不等間隔標本の周期探索 | `lomb_scargle`、`LombScargle` | 時刻、角周波数 [rad/時間]、重み | 正規化パワー（説明できた分散の割合） | [スペクトル・時間周波数解析・解析信号](spectra-and-time-frequency/) |
| 時間周波数解析と逆変換 | `StftPlan`、`check_overlap` | ウインドウ、hop、FFT 長 | フレームごとの係数。NOLA が成り立てば合成できる | [スペクトル・時間周波数解析・解析信号](spectra-and-time-frequency/) |
| 包絡線と瞬時位相 | `hilbert`、`envelope`、`AnalyticSignalNdPlan` | 実数のスライス | 周期的な解析信号、その絶対値 | [スペクトル・時間周波数解析・解析信号](spectra-and-time-frequency/) |
| 画像の局所振幅と方向 | `AnalyticSignalNdPlan`、`monogenic_nd`、`RieszPlan` | 多次元のビュー、軸、標本間隔 | 成分の軸を先頭に置いた配列 | [スペクトル・時間周波数解析・解析信号](spectra-and-time-frequency/) |
| FIR フィルタの設計 | `design_fir_window`、`design_fir_least_squares`、`design_fir_remez` | 係数の個数、`FirSymmetry`、`FirBand`（Nyquist 比） | `FirDesign`（係数、終了状態、条件数の推定値） | [フィルタ設計・最小位相・LTI 系](filter-design-and-systems/) |
| IIR フィルタの設計と適用 | `design_iir`、`select_iir_order`、`IirDesign::to_sos`、`SecondOrderSections::filter`・`forward_backward` | `IirFamily`、`IirBand`、`IirDomain` | 二次節の縦続、因果的な出力かゼロ位相の出力 | [フィルタ設計・最小位相・LTI 系](filter-design-and-systems/) |
| 状態を持つ IIR の逐次処理 | `IirFilter` | 二次節か伝達関数、`IirState` | チャンクごとの出力と更新した遅延 | [フィルタ設計・最小位相・LTI 系](filter-design-and-systems/) |

| 状態空間モデルの離散化と応答 | `StateSpace` | $A, B, C, D$、`LtiTime` | 離散化したモデル、時間応答、周波数応答 | [フィルタ設計・最小位相・LTI 系](filter-design-and-systems/) |

| 多重解像度の分解 | `WaveletPlan`、`Wavelet2dPlan` | `WaveletFamily`、段数、`WaveletOptions` | 詰めた係数の列 | [局所フィルタ・特徴・平滑化・ウェーブレット](features-and-smoothing/) |

## 呼び出しの形

同じ計算は、必要な制御の量に応じて次の形で呼び分ける。

| 形 | 例 | 受け取るもの | 返すもの | 実行コンテキスト |
|---|---|---|---|---|
| ワンショット関数 | `convolve(&a, &b)`、`welch(&x, fs, m)`、`lomb_scargle(&t, &x, &omega)`、`resample(&x, up, down)`、`find_peaks(&x)`、`savitzky_golay(&x, w, p)`、`minimum_phase(&h)` | データと少数の必須の値だけ | 新しく確保した結果 | `sequential_native()` |
| 標準形式 | `design_iir(order, family, band, domain)`、`sos.filter(&x)`、`sos.forward_backward(&x)`、`plan.analyze(&x)`、`design_fir_remez(n, symmetry, &bands)` | 準備した値と入力 | 新しく確保した結果 | `sequential_native()`、反復する設計は新しい根のスコープ |
| オプション付き形式 | `find_peaks_with_options(&x, options)`、`minimum_phase_with_options(&h, options)`、`design_fir_remez_with_options(…, options)`、`select_iir_order_with_options(…, options)`、`place_poles_with_options(&poles, options)` | 入力と、最後にオプション | 新しく確保した結果 | `sequential_native()` |
| 出力先を指定する API | `plan.power_into(&x, &mut out, &mut ws, cx)`、`filter.filter_into(&x, &mut y, &mut state, &mut ws, cx)`、`plan.analyze_axis_into(view, axis, out, &mut ws, cx)` | 入力、出力、作業領域、最後にコンテキスト | 出力に書く | 渡したコンテキスト |
| スコープ付き API | `design_iir_scoped(…, scope)`、`select_iir_order_scoped(…, scope)`、`design_fir_remez_scoped(…, scope)`、`sos.to_zpk_scoped(scope)`、`place_poles_scoped(…, scope)` | オプション付き形式の引数と、最後に実行コンテキストか `SolveContext` | 値 | 渡したスコープの一つのエポック |

- ワンショット関数: 結果だけが必要な一度きりの計算に使う。
  慣例の設定は関数ごとに固定され、rustdoc と表に書いてある。
  たとえば `welch` は周期 Hann ウインドウと半分の重なりを、`resample` は中心をそろえた位置合わせを、`savitzky_golay` は端の完全なウインドウの多項式による境界を使う。
- Plan と手法オブジェクト: 繰り返す計算では、準備を一度だけ行う値を保持する。
  Plan（`ConvolutionNdPlan`、`SpectralEstimatePlan`、`StftPlan`、`WaveletPlan` など）は FFT や係数を準備時に計算する。
  手法オブジェクト（`IirFilter`、`SymmetricFilter`、`SplineFilter`、`LombScargle`）は検査した係数や設定だけを保持し、構築時には計算しないが、Plan と同じ実行の形を持つ。
  `Window` と `DpssTapers` は計算した標本を保持する値である。
  どれも不変で、状態・出力・作業領域は呼び出し側が持つ。
  大域的なキャッシュはない。
- 作業領域の問い合わせ: Plan と手法オブジェクトは `workspace_requirements(request)` で必要量を返す。
  要求は `()`、記録長、レーンの数、`SignalLayout` または Plan に固有の値（`StftRequest`、`IirRequest`、`SplineRequest`）である。
  `workspace(request)` または `SignalWorkspace::try_reserve` で実行前に確保し、実行中に拡張しない。
  ピーク・リッジ・Whittaker・LTI 応答は用途別の領域型を使う。
  不足は `DimensionMismatch` である。
- 配列の軸に沿った処理: 一つの記録を扱う Plan のメソッド `verb_axis_into(input, axis, output, workspace, cx)` が配列の一つの軸の各レーンを記録として処理する。
  形とレーンの数は呼び出しごとに入力のビューから求め、作業領域の要求には `SignalLayout::Axis` かレーンの数を渡す。
- 不可分な書き込み: 検査・変換・尺度の調整がすべて終わってから出力に書くので、失敗したときは呼び出し側の出力が変わらない。
  ストリームでは状態も変わらない。
- 逐次処理: `LocalFilterStream`、`OverlapStream`、`PolyphaseStream`、`StftAnalysisStream`、`StftSynthesisStream` は Plan を借用し、状態を所有する。
  `IirFilter` は遅延を呼び出し側の `IirState` に持たせる。
  `clone` がスナップショットを作り、`clone_from` は確保せずに状態を戻す。
  `StreamChunk::Final` が終端を示す。
- 周波数の単位: `power_spectrum` と `cross_spectrum` は DFT のビン、`welch`・`SpectralEstimatePlan`・`StftPlan` と波形は時間単位あたりの周期、`lomb_scargle`・`LombScargle` と連続 LTI 系は時間単位あたりのラジアン、離散 LTI 系とデジタル FIR・IIR は Nyquist 周波数に対する比を使う。
- 実行コンテキスト: 出力先を指定する API とスコープ付き API は最後の引数に `ExecutionContext`（エグゼキューター、取り消し、期限）を受け取り、スコープ付き API は外側の解法の `SolveContext` も受け取る。
  wasm では逐次実行だけが使える。

## 最小の実行例

3 点の入力 $x = [1, 2, 3]$ と 2 点の核 $h = [1, 1]$ の線形畳み込みは、長さ $3 + 2 - 1 = 4$ の $[1, 3, 5, 3]$ である。
次のセルは `convolve` の結果をこの値と比べる。

```rust
//| id: signal-api-linear-convolution
//| title: 二点核の線形畳み込みと全長
//| run: button
//| crates: [scioxide-signal]
use scioxide_signal::convolve;

let signal = [1.0_f64, 2.0, 3.0];
let kernel = [1.0_f64, 1.0];
let output = convolve(&signal, &kernel).map_err(|e| e.to_string())?;

// 手計算の値 [1, 3, 5, 3] と標本ごとに比べる
let expected = [1.0, 3.0, 5.0, 3.0];
let rows: Vec<(usize, f64, f64, f64)> = output
    .iter()
    .zip(expected)
    .enumerate()
    .map(|(n, (&y, e))| (n, y, e, (y - e).abs()))
    .collect();
emit_table_with_columns!(["添字 n", "convolve", "手計算", "絶対誤差"], rows);
```

出力は 4 標本で、どの標本も手計算と一致する（誤差 0）。
`convolve` はワンショット関数で、内部で `ConvolutionNdPlan` と作業領域を作る。
入力を長くすると Plan は直接和から実 FFT に切り替わることがあるが、出力の長さと値の規約は変わらない。

## 結果・エラー・診断の読み方

失敗は `SciOxideError` で返り、分類は `e.kind()`（`SciOxideErrorKind`）、詳細は `e.view()` で読む。
この章でよく現れる分類は次のとおりである。

| 分類 | 主な原因 |
|---|---|
| `InvalidInput` | 空の記録、範囲外のパラメータ（ウインドウのパラメータ、帯域端、しきい値など）、Plan と異なる長さの入力、最後のチャンクの後のストリームの呼び出し |
| `DimensionMismatch` | 出力・作業領域・状態の不足、長さや形の異なる入力（`convolve_circular`、`cross_spectrum`） |
| `NonFinite` | 入力や係数の NaN・無限大 |
| `DomainError` | 和やエネルギーが 0 の正規化、自己スペクトルが 0 の coherence、0 の信号の最小位相、定数の入力の Lomb–Scargle |
| `NumericalInstability` | 結果が表せない（桁あふれ）、最小二乗の数値ランクの喪失、計算結果の自己検査（双対ウインドウ、零点・極の変換）の失敗 |
| `SizeOverflow`、`AllocationFailure`、`ResourceLimit` | 作業領域の大きさの計算の桁あふれ、確保の失敗、`SignalRequirements::with_max_bytes` の上限超過 |
| `ConvergenceFailure` | 標準形式の `select_iir_order` が `usize` に収まらない次数を要する、`design_fir_remez` の交換が上限に達するか停滞する、`place_poles` の極が許容誤差を満たさない。スコープ付き API ではスコープの上限に達したときにも返る |
| `ExecutionStopped` | スコープ付き API の設計に渡した取り消し・期限による停止 |

`Ok` で返っても、結果の質は診断で確かめる。

- `FirDesign::termination()` は FIR の設計の唯一の終了状態である。
  Remez 法のオプション付き形式とスコープ付き API は、未収束でも `IterationLimit` か `ExchangeStalled` の有限の係数を返す。
  `condition_estimate()` は最小二乗の設計の正規方程式の 1 ノルム条件数の推定値で、ほかの設計では `None` になる。
- `IirOrderReport::termination()` は次数の選択の終了状態で、オプション付き形式とスコープ付き API では最大次数で止まった `OrderLimit` を返しうる。
- `IirDesign::stability_margin()` と `PoleZeroGain::stability_margin()` は極と安定境界の距離で、正なら厳密に安定である。
- `MinimumPhaseDiagnostics`、`SmoothingDiagnostics`、`OverlapDiagnostics`、`ConvolutionSelection` は推定値や判定の根拠であり、誤差の保証ではない。
- `PolePlacementReport` は実現した極を独立に計算し、要求との残差を返す。

## まとめ

API の表で課題に合う項目を選び、まずワンショット関数で試す。
設定を変えるときはオプション付き形式、繰り返す計算では Plan や手法オブジェクトと作業領域を保持し、出力先を指定する API で確保をなくす。
外側の解法の上限や取り消しを反復する設計に効かせるときはスコープ付き API を使う。
結果の規約（相関のラグの並び、スペクトルの正規化、周波数の単位）は項目ごとに決まっているので、表の仕様の欄で確かめる。
エラーは `kind()` で分類し、`Ok` の結果は終了状態と診断を読んでから使う。
数式の根拠は[数理とアルゴリズム](../algorithms/)、検算付きの使い方は[実例](../examples/)で確認する。
