信号処理の関数を測定データに使う前に、独立な計算経路で結果を確かめておくと、規約の取り違えに早く気づける。
独立な経路には、定義どおりの直接和、エネルギーの保存、手計算の幾何などがある。
このページでは、Gauss 核による平滑化、平坦な頂部（プラトー）を持つピークの幾何、Hampel フィルタの逐次処理を、それぞれ閉じた形の値や別の計算と比べる。

## Gauss 核による平滑化と Parseval の関係

高い周波数のノイズを減らす基本的な操作は、正規化した Gauss 核

$$
h[j] = \frac{1}{Z} \exp\left( -\frac{j^2}{2\sigma^2} \right), \qquad j = -K, \dots, K
$$

との線形畳み込みである。
正規化定数 $Z = \sum_{j=-K}^{K} \exp(-j^2/(2\sigma^2))$ は直流利得を 1（$\sum_j h[j] = 1$）にする。

長さ $N$ の信号 $x$ と長さ $M = 2K + 1$ の核 $h$ の線形畳み込み $y = x * h$ は長さ $N + M - 1$ で、次の二つの関係を満たす。

1. 出力の和の保存。
   核の和が 1 なので、両端の 0 の延長を含む出力全体の和は入力の和に一致する。

   $$
   \sum_{n=0}^{N+M-2} y[n] = \sum_{n=0}^{N-1} x[n] \sum_{j=-K}^{K} h[j] = \sum_{n=0}^{N-1} x[n]
   $$

2. Parseval の関係。
   `power_spectrum` が返す全 $N$ ビンの $P_k = |X_k|^2 / N$ の総和は、時間領域の二乗和に等しい。

   $$
   E_x = \sum_{n=0}^{N-1} x[n]^2 = \sum_{k=0}^{N-1} P_k
   $$

核の周波数応答の大きさは $|H(\omega)| \le \sum_j |h[j]| = 1$ なので、平滑化した出力のエネルギー $E_y = \sum_n y[n]^2$ は $E_x$ を超えない。

次のセルは、幅 4 標本の Gauss パルス（長さ 64）を 17 点（$K = 8$）の核で平滑化する。
`convolve` は直接和と FFT のうち演算の少ない方を選ぶので、結果を定義どおりの二重ループの和と比べる。
表は出力長、和の保存、Parseval の関係を SciOxide の値と独立な計算の組で示し、直接和との最大差とエネルギーの比を加える。
図は入力（破線）と、核の中心の 8 標本だけずらして同じ時間軸に重ねた出力を描く。

```rust
//| id: signal-convolution-energy
//| ref: signal-convolution-energy
//| title: Gauss 核の平滑化を直接和と Parseval の関係で照合する
//| run: reactive
//| crates: [scioxide-signal]
//| inputs:
//|   filter_width: {"type":"range","label":"核の幅 σ [標本]","description":"Gauss 核の標準偏差（平滑化の強さ）。","min":0.5,"max":4,"step":0.25,"value":1.5}
//|   pulse_position: {"type":"range","label":"入力の中心位置 [標本]","description":"Gauss パルスの頂点の添字。","min":16,"max":48,"step":2,"value":28}
//| cases:
//|   - {"id":"wide-kernel","label":"σ = 4","description":"頂点が下がって裾が広がるが、和は保たれる。","inputs":{"filter_width":4}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"checks","path":"/rows/0/1","equals":80}
//|       - {"artifact":"checks","path":"/rows/1/3","range":{"max":1e-12}}
//|       - {"artifact":"checks","path":"/rows/2/3","range":{"max":1e-12}}
//|       - {"artifact":"checks","path":"/rows/3/3","range":{"max":1e-14}}
//|       - {"artifact":"checks","path":"/rows/4/1","range":{"max":1.0}}
//|   - case: wide-kernel
//|     expect:
//|       - {"artifact":"checks","path":"/rows/1/3","range":{"max":1e-12}}
//|       - {"artifact":"checks","path":"/rows/4/1","range":{"max":1.0}}
use scioxide_signal::{convolve, power_spectrum};

let sig12 = serde_json::json!({ "significantDigits": 12 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
// 長さ 64、幅 4 標本の Gauss パルス（参照値。f64 の標準関数）。
let n = 64_usize;
let signal: Vec<f64> = (0..n)
    .map(|i| (-0.5 * ((i as f64 - pulse_position) / 4.0).powi(2)).exp())
    .collect();
// 和を 1 に正規化した 17 点（半径 8）の Gauss 核。
let mut kernel: Vec<f64> = (-8..=8)
    .map(|j| (-0.5 * (j as f64 / filter_width).powi(2)).exp())
    .collect();
let mass: f64 = kernel.iter().sum();
kernel.iter_mut().for_each(|v| *v /= mass);

// 線形畳み込み（直接和と FFT のうち演算の少ない方を選ぶ）。
let output = convolve(&signal, &kernel).map_err(|e| e.to_string())?;
let spectrum = power_spectrum(&signal).map_err(|e| e.to_string())?;

// 独立な検算: 定義どおりの直接和と、時間領域の和・二乗和。
let mut reference = vec![0.0; signal.len() + kernel.len() - 1];
for (i, &a) in signal.iter().enumerate() {
    for (j, &b) in kernel.iter().enumerate() {
        reference[i + j] += a * b;
    }
}
let direct_error = output
    .iter()
    .zip(&reference)
    .map(|(a, b)| (a - b).abs())
    .fold(0.0_f64, f64::max);
let energy = |v: &[f64]| v.iter().map(|x| x * x).sum::<f64>();
let (input_sum, output_sum) = (signal.iter().sum::<f64>(), output.iter().sum::<f64>());
let spectral_energy: f64 = spectrum.iter().sum();
let expected_len = (signal.len() + kernel.len() - 1) as f64;

let rows = vec![
    (
        "出力長と N + M − 1 [標本]",
        Some(output.len() as f64),
        Some(expected_len),
        Some(0.0),
    ),
    (
        "出力の和 Σy と入力の和 Σx",
        Some(output_sum),
        Some(input_sum),
        Some((output_sum - input_sum).abs()),
    ),
    (
        "スペクトルの和 ΣP_k と E_x",
        Some(spectral_energy),
        Some(energy(&signal)),
        Some((spectral_energy - energy(&signal)).abs()),
    ),
    ("convolve と直接和の最大差", None, None, Some(direct_error)),
    (
        "エネルギーの比 E_y / E_x",
        Some(energy(&output) / energy(&signal)),
        None,
        None,
    ),
];
let columns = serde_json::json!([
    { "key": "0", "label": "検算" },
    { "key": "1", "label": "SciOxide の値", "type": "number", "format": sig12, "nullText": "—" },
    { "key": "2", "label": "独立な計算", "type": "number", "format": sig12, "nullText": "—" },
    { "key": "3", "label": "差の絶対値", "type": "number", "format": sci3, "nullText": "—" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "checks" })
);

// 核の中心（8 標本）だけずらして入力と同じ時間軸に重ねる。
let input_curve: Vec<[f64; 2]> = signal
    .iter()
    .enumerate()
    .map(|(i, &x)| [i as f64, x])
    .collect();
let output_curve: Vec<[f64; 2]> = output
    .iter()
    .enumerate()
    .map(|(i, &y)| [i as f64 - 8.0, y])
    .collect();
emit_line_chart!(
    &vec![
        serde_json::json!({
            "name": "入力 x[n]",
            "points": input_curve,
            "style": { "lineType": "dashed" }
        }),
        serde_json::json!({ "name": "平滑化した y[n + 8]", "points": output_curve }),
    ],
    options = &serde_json::json!({
        "xLabel": "入力の標本位置 n [-]",
        "yLabel": "振幅 [-]",
        "xMin": -8.0,
        "xMax": 72.0,
        "yMin": 0.0,
        "yMax": 1.05
    })
);
```

既定の $\sigma = 1.5$ では、出力長は 80 で $N + M - 1$ に一致する。
直接和との最大差は $2.2 \times 10^{-16}$、Parseval の差は $7.1 \times 10^{-15}$ で、和の差は 0 である。
いずれも丸め誤差の程度である。
エネルギーの比は 0.936 で、出力のエネルギーは入力より小さい。
ケース「σ = 4」では頂点が下がって裾が広がり、エネルギーの比は 0.736 まで下がるが、和の差は $3.6 \times 10^{-15}$ にとどまる。
パルスの位置を端に寄せても、0 の延長を含む全長の出力をとるので和は変わらない。

## 平坦な頂部を持つピークの幾何

心電図の R 波や飽和した吸光度のピークは、量子化や飽和によって同じ値が続く平坦な頂部を作ることがある。
`find_peaks` と `find_peaks_with_options` は、ピークを次の規約で測る（[ピークの幾何と突出度](oxref:signal-peak-geometry)）。

1. 平坦な頂部 $[s, e]$ の代表の添字は、中点を下に丸めた $s + \lfloor (e - s)/2 \rfloor$ である。
2. 突出度は、頂部の高さから両側の谷の高い方を引いた値である。
3. 幅は、高さ $h - \rho P$（$\rho$ は相対深さ、$P$ は突出度）の等高線と波形の交点を標本の間で線形補間し、左右の交点の差として測る。

入力 $[0, 1, 1, 0, H, 0, 0]$ では、平坦な山（添字 1〜2）の代表点は 1、突出度は 1 である。
幅は頂部の長さ 1 に両側の補間区間 $2\rho$ を加えた $1 + 2\rho$ になる。
鋭い山（添字 4）の突出度は $H$、幅は $2\rho$ である。
次のセルは、オプション付き形式 `find_peaks_with_options` に相対深さ $\rho$ だけを変えた `PeakOptions` を渡し、検出した各ピークの値をこの手計算と並べる。
表は検出したピークごとに 1 行で、手計算にない添字のピークが現れた場合は手計算の列を空にする。

```rust
//| id: signal-plateau-peak-geometry
//| ref: signal-plateau-peak-geometry
//| title: 平坦な頂部を持つピークの代表点・突出度・幅を手計算と比べる
//| run: reactive
//| crates: [scioxide-signal]
//| inputs:
//|   peak_height: {"type":"range","label":"鋭い山の高さ H [-]","description":"添字 4 の山の高さ（突出度を決める）。","min":2,"max":8,"step":1,"value":5}
//|   relative_depth: {"type":"range","label":"幅を測る相対深さ ρ [-]","description":"突出度に対する、幅を測る高さの深さの比。","min":0,"max":1,"step":0.1,"value":0.5}
//| cases:
//|   - {"id":"top-contour","label":"ρ = 0","description":"頂部の高さで幅を測る。","inputs":{"relative_depth":0}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"geometry","path":"/rows/0/0","equals":1}
//|       - {"artifact":"geometry","path":"/rows/1/0","equals":4}
//|       - {"artifact":"geometry","path":"/rows/0/4","approx":{"value":2.0,"atol":1e-12}}
//|       - {"artifact":"geometry","path":"/rows/1/2","approx":{"value":5.0,"atol":1e-12}}
//|       - {"artifact":"geometry","path":"/rows/1/6","range":{"max":1e-12}}
//|   - case: top-contour
//|     expect:
//|       - {"artifact":"geometry","path":"/rows/0/4","approx":{"value":1.0,"atol":1e-12}}
//|       - {"artifact":"geometry","path":"/rows/1/4","approx":{"value":0.0,"atol":1e-12}}
use scioxide_signal::{PeakOptions, find_peaks_with_options};

let fixed3 = serde_json::json!({ "fractionDigits": 3 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
// 添字 1〜2 に平坦な山、添字 4 に鋭い山。
let input = [0.0_f64, 1.0, 1.0, 0.0, peak_height, 0.0, 0.0];
// オプション付き形式: 幅を測る相対深さだけを変え、選別の条件は既定（すべてのピークを受け入れる）。
let options = PeakOptions::default().with_relative_height(relative_depth);
let peaks = find_peaks_with_options(&input, options).map_err(|e| e.to_string())?;

// 手計算: 代表点 → (突出度, 幅)。
let expected = |index: usize| match index {
    1 => Some((1.0, 1.0 + 2.0 * relative_depth)),
    4 => Some((peak_height, 2.0 * relative_depth)),
    _ => None,
};
let rows: Vec<_> = peaks
    .iter()
    .map(|p| {
        let hand = expected(p.index());
        (
            p.index(),
            hand.map(|_| p.index()),
            p.prominence(),
            hand.map(|(prominence, _)| prominence),
            p.width(),
            hand.map(|(_, width)| width),
            hand.map(|(_, width)| (p.width() - width).abs()),
        )
    })
    .collect();
let columns = serde_json::json!([
    { "key": "0", "label": "代表点 [-]", "type": "integer" },
    { "key": "1", "label": "手計算の代表点 [-]", "type": "integer", "nullText": "なし" },
    { "key": "2", "label": "突出度 [-]", "type": "number", "format": fixed3 },
    { "key": "3", "label": "手計算の突出度 [-]", "type": "number", "format": fixed3, "nullText": "なし" },
    { "key": "4", "label": "幅 [標本]", "type": "number", "format": fixed3 },
    { "key": "5", "label": "手計算の幅 [標本]", "type": "number", "format": fixed3, "nullText": "なし" },
    { "key": "6", "label": "幅の差 [標本]", "type": "number", "format": sci3, "nullText": "—" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "geometry" })
);
```

既定の $H = 5$、$\rho = 0.5$ では、二つのピークが代表点 1 と 4 で検出される。
幅は 2 と 1 で手計算と一致し、差は 0 である。
ケース「ρ = 0」では幅を頂部の高さで測るので、平坦な山の幅は頂部の長さ $e - s = 1$、鋭い山の幅は 0 になる。
$H$ を変えても平坦な山の突出度は 1 のままで、突出度が頂部の高さと谷の高さだけで決まることがわかる。

## Hampel フィルタの逐次処理と終端

受信しながら処理するセンサーの列では、将来の標本が未確定なので、局所中央値と MAD の計算に半径 $r$ 標本の遅延が生じる。
ストリームの最後では、端点の値を繰り返した延長で残りの出力を書き出す（[Plan と逐次処理](oxref:signal-local-filter-stream)）。

次のセルは、孤立したスパイクを含む 7 標本の列に、一括処理（`filter_into`）と、任意の位置で二つに分けた逐次処理（`LocalFilterStream::process_into`）を適用し、出力と置換した添字を比べる。
半径は $r = 1$、しきい値は $\tau = 3$ である。
スパイクの近くではウインドウの 3 標本のうち 2 標本が 0 なので MAD は 0 になり、0 と異なる中心の標本は置き換えられる。
1 つ目の表は標本ごとの出力、2 つ目の表はチャンクごとの `StreamProgress`、3 つ目の表は置換した添字と出力の合計である。

```rust
//| id: signal-hampel-stream-finish
//| ref: signal-hampel-stream-finish
//| title: Hampel フィルタの一括処理と分割した逐次処理を比べる
//| run: reactive
//| crates: [scioxide-core, scioxide-signal]
//| inputs:
//|   spike_amplitude: {"type":"range","label":"スパイクの振幅 [-]","description":"添字 3 の孤立した外れ値の大きさ。","min":2,"max":10,"step":1,"value":8}
//|   chunk_split: {"type":"range","label":"最初のチャンクの長さ [標本]","description":"7 標本の列を二つに分ける位置。","min":1,"max":6,"step":1,"value":3}
//| cases:
//|   - {"id":"late-split","label":"分割位置 6","description":"最初のチャンクでスパイクの置換まで終わる。","inputs":{"chunk_split":6}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"samples","path":"/rows/3/2","equals":0}
//|       - {"artifact":"samples","path":"/rows/3/3","equals":0}
//|       - {"artifact":"progress","path":"/rows/0/3","equals":2}
//|       - {"artifact":"progress","path":"/rows/1/3","equals":5}
//|       - {"artifact":"summary","path":"/rows/1/1","equals":"[3]"}
//|   - case: late-split
//|     expect:
//|       - {"artifact":"progress","path":"/rows/0/3","equals":5}
//|       - {"artifact":"summary","path":"/rows/1/1","equals":"[3]"}
use scioxide_core::ExecutionContext;
use scioxide_signal::{LocalFilter, LocalFilterPlan, StreamChunk};

let input = [0.0_f64, 0.0, 0.0, spike_amplitude, 0.0, 0.0, 0.0];
let filter = LocalFilterPlan::new(1, LocalFilter::Hampel { threshold: 3.0 })
    .map_err(|e| e.to_string())?;

// 一括処理。
let mut batch = [0.0; 7];
let mut batch_indices = [0; 7];
let mut scratch = filter.workspace(input.len()).map_err(|e| e.to_string())?;
let batch_count = filter
    .filter_into(
        &input,
        &mut batch,
        &mut batch_indices,
        &mut scratch,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;

// ストリームは状態を所有する。後のチャンクで残りを書き出す。
let mut stream = filter.stream().map_err(|e| e.to_string())?;
let mut work = stream.workspace(input.len()).map_err(|e| e.to_string())?;
let (mut streamed, mut stream_indices) = ([0.0; 7], [0; 7]);
let split = chunk_split.round() as usize;
let (mut emitted, mut replaced, mut progress_rows) = (0, Vec::new(), Vec::new());
for (chunk, finish) in [
    (&input[..split], StreamChunk::Partial),
    (&input[split..], StreamChunk::Final),
] {
    let progress = stream
        .process_into(
            chunk,
            finish,
            &mut streamed[emitted..],
            &mut stream_indices,
            &mut work,
            ExecutionContext::sequential(),
        )
        .map_err(|e| e.to_string())?;
    emitted += progress.produced();
    replaced.extend_from_slice(&stream_indices[..progress.replacements()]);
    progress_rows.push((
        chunk.len(),
        format!("{finish:?}"),
        progress.consumed(),
        progress.produced(),
        progress.first_output_index(),
    ));
}

let rows: Vec<(usize, f64, f64, f64)> = (0..7)
    .map(|i| (i, input[i], batch[i], streamed[i]))
    .collect();
let sample_columns = serde_json::json!([
    { "key": "0", "label": "添字 [-]", "type": "integer" },
    { "key": "1", "label": "入力 [-]", "type": "number" },
    { "key": "2", "label": "一括処理 [-]", "type": "number" },
    { "key": "3", "label": "逐次処理 [-]", "type": "number" }
]);
emit_table_with_columns!(
    sample_columns,
    rows,
    metadata = serde_json::json!({ "id": "samples" })
);
let progress_columns = serde_json::json!([
    { "key": "0", "label": "チャンクの長さ [標本]", "type": "integer" },
    { "key": "1", "label": "終端区分" },
    { "key": "2", "label": "消費した標本 [標本]", "type": "integer" },
    { "key": "3", "label": "出力した標本 [標本]", "type": "integer" },
    { "key": "4", "label": "最初の出力の添字 [-]", "type": "integer" }
]);
emit_table_with_columns!(
    progress_columns,
    progress_rows,
    metadata = serde_json::json!({ "id": "progress" })
);
let summary_columns = serde_json::json!([
    { "key": "0", "label": "処理" },
    { "key": "1", "label": "置換した添字" },
    { "key": "2", "label": "出力の合計 [標本]", "type": "integer" },
    { "key": "3", "label": "遅延 [標本]", "type": "integer" }
]);
emit_table_with_columns!(
    summary_columns,
    vec![
        (
            "一括",
            format!("{:?}", &batch_indices[..batch_count]),
            input.len(),
            0
        ),
        ("逐次", format!("{replaced:?}"), emitted, filter.delay()),
    ],
    metadata = serde_json::json!({ "id": "summary" })
);
```

既定の振幅 8、分割位置 3 では、一括処理と逐次処理の出力はどちらもすべて 0 で、置換した添字は両方とも 3 である。
最初のチャンク（3 標本）では遅延 1 標本のために 2 標本だけが出力され、`StreamChunk::Final` を渡した後のチャンクで残りの 5 標本が書き出される。
ケース「分割位置 6」では、最初のチャンクで 5 標本が出力され、スパイクの置換もこの呼び出しで示される。
分割位置を 1 から 6 まで動かしても、出力と置換した添字は変わらず、チャンクごとの出力数だけが変わる。

## まとめ

`convolve` の出力は定義どおりの直接和と、`power_spectrum` の総和は時間領域の二乗和と、丸め誤差の程度で一致する。
正規化した非負の核は出力の和を保ち、エネルギーを増やさない。
`find_peaks_with_options` の平坦な頂部の代表点・突出度・幅は、規約を知れば手計算で予測できる。
`LocalFilterStream` は状態を所有し、チャンクの分け方によらず一括処理と同じ出力と置換した添字を返す。
各関数の規約と導出は[局所フィルタとピークの検出](../../algorithms/local-filters-and-features/)、平滑化の方法の比較は[平滑化とトレンド除去](../../algorithms/smoothing-and-detrending/)で確かめる。
