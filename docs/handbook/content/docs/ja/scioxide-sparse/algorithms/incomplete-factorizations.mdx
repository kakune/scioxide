対称正定値な行列の共役勾配法（CG）では、反復回数はおよそ条件数 $\kappa$ の平方根に比例する。
差分や有限要素の行列は格子を細かくすると条件数が大きくなるので、そのままでは反復回数が増える。
**前処理**は $\mathbf{A}$ を近似し、逆の作用 $\mathbf{M}^{-1}\mathbf{r}$ を安く計算できる行列 $\mathbf{M}$ を選び、$\mathbf{M}^{-1}\mathbf{A}$ の固有値をまとめて反復回数を減らす方法である。
疎な LU 分解や Cholesky 分解は $\mathbf{M} = \mathbf{A}$ そのものだが、フィルのためにメモリと手間が大きい。
不完全分解はフィルの一部を規則に従って捨て、因子を小さく保ったまま $\mathbf{A} \approx \tilde{\mathbf{L}}\tilde{\mathbf{U}}$ を作る。
このページでは捨てる規則の二つの系統（構造で決めるレベルと、値で決める閾値）、ピボットの破綻と修復、単純な前処理、`IncompleteFactor` の使い方を説明する。

## 前処理の役割

前処理付きの反復法は $\mathbf{A}\mathbf{x} = \mathbf{b}$ の代わりに、左から $\mathbf{M}^{-1}$ を掛けた $\mathbf{M}^{-1}\mathbf{A}\mathbf{x} = \mathbf{M}^{-1}\mathbf{b}$ か、右から掛けた $\mathbf{A}\mathbf{M}^{-1}\mathbf{y} = \mathbf{b}$（$\mathbf{x} = \mathbf{M}^{-1}\mathbf{y}$）を解く。
scioxide-linalg の GMRES は右から掛ける形なので、前処理をしても元の残差 $\lVert \mathbf{b} - \mathbf{A}\mathbf{x} \rVert_2$ を最小にし、その大きさで収束を判定する。
各反復で $\mathbf{z} = \mathbf{M}^{-1}\mathbf{r}$ を一度計算するので、$\mathbf{M}^{-1}$ の作用は $\mathbf{A}$ との積と同じ程度の手間でなければ意味がない。
不完全分解では $\mathbf{M} = \tilde{\mathbf{L}}\tilde{\mathbf{U}}$ なので、$\mathbf{M}^{-1}\mathbf{r}$ は二つの疎な三角系の代入で計算でき、手間は因子の非零の数に比例する。
$\mathbf{M}$ が $\mathbf{A}$ に近いほど $\mathbf{M}^{-1}\mathbf{A}$ は単位行列に近づいて反復回数は減るが、因子は大きくなる。
前処理は因子の大きさ（分解と作用 1 回の手間）と反復回数の釣り合いで選ぶ。
CG に使う前処理は Hermitian 正定値でなければならない。
IC(0) と ICT は $\mathbf{M} = \tilde{\mathbf{L}}\tilde{\mathbf{L}}^{\mathsf{H}}$ の形なので、正のピボットで分解が終われば、この条件を満たす。

## レベルで捨てる IC(0) と ILU(k)

ガウス消去の第 $k$ 段の更新 $a_{ij} \leftarrow a_{ij} - a_{ik}a_{kj}/a_{kk}$ では、元は 0 だった位置にフィルが生じる。
**ILU(0)** はこのうち $\mathbf{A}$ の非零パターン $\mathcal{S}(\mathbf{A})$ の外に落ちる更新をすべて捨て、因子の構造を $\mathcal{S}(\mathbf{A})$ に限る。
その結果 $\tilde{\mathbf{L}}\tilde{\mathbf{U}} = \mathbf{A} + \mathbf{R}$ となり、誤差 $\mathbf{R}$ は $\mathcal{S}(\mathbf{A})$ の外にだけ成分を持つ。
scioxide-sparse は保存されていない対角も値 0 の成分として因子の構造に加える。
Hermitian 正定値な行列に対する、同じ構造の Cholesky 版が **IC(0)** である。
scioxide-sparse の IC(0) は下三角の部分（対角を含む）だけを保存するので、構造が対称で対角がすべて保存されていれば、因子は $(\mathrm{nnz}(\mathbf{A}) + n)/2$ 個の成分を持つ。

**ILU(k)** はフィルにレベルを付けて、レベル $k$ 以下のものだけを残す。
元の非零と対角のレベルを 0、それ以外を $\infty$ とし、第 $j$ 行を使って第 $i$ 行を消去するたびに

$$
\mathrm{lev}(i, m) \leftarrow \min\bigl(\mathrm{lev}(i, m),\ \mathrm{lev}(i, j) + \mathrm{lev}(j, m) + 1\bigr)
$$

と更新する。
$G(\mathbf{A})$ で $i$ と $m$ を結び、途中の頂点の番号がすべて $\min(i, m)$ より小さい道を、$i$ と $m$ の[フィル路](oxref:sparse-elimination-graph-fill)と呼ぶ。
位置 $(i, m)$ のレベルは最も短いフィル路の辺の数から 1 を引いた値に等しい（Hysom and Pothen, 2001）。
レベルは構造だけで決まる組合せの量で、値によらない。
したがって ILU(k) の構造は $\mathbf{A}$ の非零パターンだけで決まり、$k$ を上げるほど因子は大きく、$\mathbf{M}$ は $\mathbf{A}$ に近くなる。
scioxide-sparse はこの構造を記号解析では求めず、数値分解の中で行ごとにレベルを計算する。

$\mathbf{A}$ が M 行列（非対角が 0 以下で、逆行列の成分がすべて 0 以上の正則行列。
差分のラプラシアンなど）なら、対角以外の捨てる位置の集合を前もってどう選んでも、不完全分解はピボットが正のまま最後まで計算できる（Meijerink and van der Vorst, 1977）。
一般の Hermitian 正定値行列では、捨てた更新のために IC(0) の途中のピボットが正でなくなり、分解が破綻することがある。

## 閾値で捨てる ILUT と ICT

レベルは値を見ないので、大きさの小さなフィルを残し、大きなフィルを捨てることがある。
**ILUT** は値の大きさで捨てる（Saad の双閾値法）。
scioxide-sparse は元の行列の第 $i$ ブロック行のブロックの Frobenius ノルムの最大（対角と上三角も含む）を $s_i$ とし、捨てる基準を $\tau s_i$（$\tau$ は `with_drop_tolerance`）とする。
ブロックの大きさが 1 なら、$s_i$ は第 $i$ 行で絶対値が最も大きい成分の絶対値である。

- 下三角のブロックはそのブロックで消去を進める前、対角のピボットで割る前の値のノルムが $\tau s_i$ 未満なら捨てる。
  捨てたブロックはその行の以後の消去に使わない。
  Saad の ILUT は割ったあとの乗数で判定するので、この点が異なる。
- 上三角のブロックは、行の消去を終えた値のノルムが $\tau s_i$ 未満なら捨てる。
- そのあと `with_max_off_diagonal(p)` で、各行の下三角と上三角に残すブロックを、ノルムの大きい順に高々 $p$ 個に制限する。
  下三角は割ったあとの乗数で、上三角は最終の値で比べ、ノルムが等しければ列番号の小さい方を残す。
  この上限で捨てた乗数はその行の消去にすでに使われており、それによる更新は取り消されない。
  対角のブロックは捨てない。

値による判定は元の $\mathbf{A}$ の成分にも当てる。
ノルムがちょうど $\tau s_i$ のブロックは残すので、$\tau = 0$ なら値による捨て方は働かず、値が 0 のブロックも含めてすべてのフィルを残す。

**ICT** は同じ考え方の Cholesky 版である。
第 $i$ 行の下三角のブロック $l_{ij}$ を、その行にすでに残したブロックで更新し、対角のブロック $l_{jj}^{\mathsf{H}}$ による三角系の求解（Cholesky の割り算にあたる）の前に判定する。
残した $l_{ij}$ と、それより前の行で求めた $l_{kj}$（$j < k < i$）から、位置 $(i, k)$ にフィルの候補が生まれる。
行ごとの上限 $p$ は下三角にだけ当て、対角はその行に残した下三角のブロックだけから計算し直す。

どの方法でも、記号解析は $\mathbf{A}$ の非零パターンを保存するだけで、フィルの位置は数値分解の中で決まる。
因子の大きさは上限 `max_factor_blocks`（対角を含む $\tilde{\mathbf{L}}$ と $\tilde{\mathbf{U}}$ のブロックの数）で抑え、これを超えると `ResourceLimit` になる。

各行の上限 $p$ を使わなければ、捨てたブロックはその後の消去に使われないので、ILUT と ICT の因子は捨てた位置の集合を前もって与えた不完全分解と同じになる。
したがって M 行列では、閾値で捨てる場合も前の節の Meijerink–van der Vorst の結果が当てはまり、ピボットは正のまま終わる。

## ピボットの破綻と修復

不完全分解では捨てた更新のために、$\mathbf{A}$ が正則でも 0 や負のピボットが現れうる。
ブロックの大きさ $b > 1$ では、ピボットは対角のブロックの密な分解に現れるスカラーのピボットを指す。
扱いは `IncompletePivotPolicy` で選ぶ。

- `Strict`（既定）は LU 系で厳密に 0 のピボットを、Cholesky 系で正でないピボット（平方根を取る前の対角の値）を `Singular` として拒む。
  LU 系の負のピボットは受け入れる。
- `Repair { absolute, relative }` は、$t = \max(\text{absolute},\ \text{relative} \cdot s_i)$ として、大きさが $t$ より小さいピボットと `Strict` が拒むピボットを、大きさ $t$ のピボットで置き換える。
  LU 系の 0 でないピボットは符号（複素数では位相）を保ち、LU 系の 0 のピボットと Cholesky 系のピボットは $t$ になる。
  二つの下限は有限で 0 以上、少なくとも一方が正でなければならず、そうでなければ数値計算の前に `InvalidInput` を返す。
  修復したピボットの数は診断の `repaired_pivots()` で読める。

修復は前処理を変えるだけで、入力の行列は変えない。
修復は分解を最後まで進めるための手段で、修復した前処理が良い前処理になるとは限らない。
修復の数が多いなら、$\tau$ やレベルを変えるか、別の前処理を検討する。

## ブロック版

`IncompleteSymbolic::analyze(pattern, method, block_size, limits)` の `block_size` に $b > 1$ を与えると、行列を $b \times b$ のブロックに分け、ブロック単位で同じ規則を当てる。
保存された成分を一つでも含むブロックは密なブロックとして扱い、保存されていない位置は 0 とする。
ブロックの大きさは Frobenius ノルムで測る。
対角のブロックは LU 系では部分ピボット選択付きの密な LU 分解で、Cholesky 系では密な Cholesky 分解で分解する。
節点ごとに $b$ 個の自由度を持つ系では、同じ節点の自由度の結合をブロックの中で厳密に扱えるので、スカラーの不完全分解より安定なことが多い。
$b$ は次元を割り切らなければならない。
BSR の行列はスカラーの成分の構造で解析する。

`blocks()` は、保存したブロックを（ブロック行、ブロック列、行優先の値）の組で、行と列の順に返す。
LU 系では、非対角のブロックは単位下三角の $\tilde{\mathbf{L}}$ と $\tilde{\mathbf{U}}$ のもので、対角のブロックは自身の密な LU 因子を持つ。
`diagonal_pivots(row)` は、そのブロック行の対角のブロックの行の交換を返す（Cholesky 系では空）。

## Jacobi と恒等の前処理

最も単純な前処理は対角だけを使う Jacobi 前処理 $\mathbf{M} = \mathrm{diag}(\mathbf{A})$ である。
`JacobiPreconditioner::new(matrix)` は、正方な CSR 行列の保存された対角から逆数を作る。
正方でなければ `DimensionMismatch`、対角が欠けているか 0 なら `Singular`、逆数があふれれば `NumericalInstability` を返す。
構築は各行の対角を二分探索で探すので $O(n + \sum_i \log \mathrm{nnz}_i)$ で、作用は $O(n)$ である。
`inverse_diagonal()` は逆数の列を返す。
対角の尺度が行ごとに大きく違う問題では Jacobi だけでも反復回数が大きく減るが、格子を細かくしたときの条件数の増え方は変わらない。
`IdentityPreconditioner::new(n)` は $\mathbf{M} = \mathbf{I}$ で、前処理のない反復を、前処理を受け取る同じ呼び出しの形で書くために使う。

どの前処理も scioxide-core の `Preconditioner` を実装し、scioxide-linalg の反復法に `Preconditioning::Inverse(&preconditioner)` として渡せる。
`JacobiPreconditioner` と `IdentityPreconditioner` の標準形式 `apply(rhs)` は作用を新しい配列に返し、出力先を指定する API `apply_into(rhs, options, output, workspace, scope)` は根のコンテキストか外側の解法のコンテキストを受け取り、作用を `output` に書く（[呼び出しの形](oxref:sparse-execution-forms)）。
`IncompleteFactor` では、同じ役割を `solve(rhs)` と `solve_into(rhs, operation, options, output, workspace, scope)` が持ち、`solve_transpose` と `solve_adjoint` で $\mathbf{M}^{-\mathsf{T}}$ と $\mathbf{M}^{-\mathsf{H}}$ も作用させられる。

## 記号解析・分解・作業領域

1. `IncompleteSymbolic::analyze(pattern, method, block_size, limits)` は、正方な構造を解析する。
   `method` は `IncompleteMethod::Ilu { level }`、`Ilut`、`Ic0`、`Ict` で、`Ilu { level: usize::MAX }` や、$b$ が 0 か次元を割り切らない場合は `InvalidInput`、正方でなければ `DimensionMismatch` を返す。
2. `IncompleteFactor::factor(symbolic, matrix, options)` は、`IncompleteOptions`（捨て方と修復）を一度だけ検査し、作業領域を確保して最初の数値分解を行う。
   スコープ付き API `factor_scoped(symbolic, matrix, options, solve_options, scope)` は、同じ分解を、`SparseSolveOptions` と、根のコンテキストか外側の解法のコンテキストを受け取って行う。
   IC(0) と ICT は、行列が厳密に Hermitian でなければ `InvalidInput` を返す。
   準備を一括して行うコンストラクター `IncompleteFactor::ilu0(&a)` と `ic0(&a)` は、ILU(0) と IC(0) の記号解析と分解を、構造から決まる上限（$\mathrm{nnz}(\mathbf{A}) + n$ ブロック、バイト数の上限なし）と `IncompleteOptions::new()` で済ませる。
   `IncompleteOptions::new()` は、捨てない（$\tau = 0$）、各行の上限なし、`Strict` である。
   `diagnostics()` は最後に成功した分解の `IncompleteDiagnostics`（`factor_blocks()`、`dropped_blocks()`、`repaired_pivots()`）を返す。
   これは因子について観測した量で、前処理の精度を表すものではない。
3. `refactor(matrix, options, workspace, scope)` は、構造が一致する新しい値で分解をやり直し、確保をしない。
   作業領域がこの解析に合う大きさに事前確保されていなければ `DimensionMismatch` を返す。
   失敗したときは、どの失敗でも直前の因子と診断を保つ。
   作業領域 `IncompleteWorkspace` は、解析の `workspace(())` で作るか、`workspace_requirements(())` が返す `IncompleteRequirements`（`symbolic_bytes()`、`factor_bytes()`、`workspace_bytes()`、`total_bytes()`）に対して `try_reserve` で事前確保する。
   この作業領域は再分解だけに使い、前処理の作用や求解には共通の `SparseSolveWorkspace` を `factor.workspace(rhs)` で用意する。

必須の上限 `IncompleteLimits::new(max_factor_blocks, max_workspace_bytes)` は、保存するブロックの数と、解析・因子・作業領域を合わせた論理バイト数を制限する。
`factor_scoped` や `refactor` に `SparseSolveOptions::with_budgets` で反復回数の上限を与えると、分解はブロック行ごとに 1 回と数え、上限に達すると `ConvergenceFailure` を返す。

### 実験のモデル

以下の二つのセルは $k \times k$ 格子の 5 点差分の行列（$N = k^2$）で前処理を比べる。
拡散係数を $a_x$（$x$ 方向、番号が $\pm 1$ の隣接）と $a_y = 1$（$y$ 方向、番号が $\pm k$ の隣接）とし、対角は $2(a_x + a_y)$、隣接は $-a_x$ と $-a_y$ である。
どの $a_x > 0$ でも $\mathbf{A}$ は M 行列で、以下のセルは各行の上限 $p$ を使わないので、どの不完全分解もピボットが正のまま終わる。
ILU 系の $\mathbf{M} = \tilde{\mathbf{L}}\tilde{\mathbf{U}}$ は一般に Hermitian ではないので、どの前処理にも使える GMRES（再始動 50、反復回数の上限 1000）でそろえ、$\lVert \mathbf{b} - \mathbf{A}\mathbf{x} \rVert_2 \le 10^{-8}\lVert \mathbf{b} \rVert_2$ まで解く。
$\mathbf{x}^\ast = \mathbf{1}$ のように格子の対称性を持つ厳密解では、右辺が対称な固有ベクトルだけを含むので、前処理のない GMRES が一般の右辺より少ない反復で終わることがある。
そこで、対称性のない厳密解 $x^\ast_p = \sin(p + 1)$ から右辺 $\mathbf{b} = \mathbf{A}\mathbf{x}^\ast$ を作る。
因子の大きさは作用 1 回で使う $\tilde{\mathbf{L}}$ と $\tilde{\mathbf{U}}$ の非零の数を $\mathrm{nnz}(\mathbf{A})$ で割った値で比べる。
Cholesky 系は $\tilde{\mathbf{L}}$ だけを保存し、$\tilde{\mathbf{U}} = \tilde{\mathbf{L}}^{\mathsf{H}}$ と対角を共有するので、非零の数は $2 \times (\text{保存したブロック}) - N$ になる。

次のブロックは二つのセルが共有する定義である。
`diffusion` は `sparse_diagonals` で 5 本の対角から行列を作り、格子の行の端で切れる $x$ 方向の結合を明示的な 0 として落とす。
`gmres` は上の右辺で GMRES を解き、反復回数、終了理由、厳密解との差の最大を `Trial` で返す。
`incomplete` は記号解析と数値分解を行い、因子と $\tilde{\mathbf{L}}$ と $\tilde{\mathbf{U}}$ の非零の数を返す。
因子のブロックの上限は、自然順の 5 点差分のフィルが帯幅 $k$ の包絡に収まる（[包絡の定理](oxref:sparse-rcm-envelope)）ことから、$N(2k + 1)$ とする。

```rust
//| id: sparse-ilu-model
//| kind: definitions
//| title: 5 点差分の拡散行列、前処理付き GMRES、不完全分解
//| crates: [scioxide-core, scioxide-sparse, scioxide-linalg]
use scioxide_core::{Budget, LinearOperator, RealScalar, ResidualTolerance};
use scioxide_linalg::{GmresSolver, LinearSolveTermination, Preconditioning};
use scioxide_sparse::{
    CsrMatrix, ExplicitZeroPolicy, IncompleteFactor, IncompleteLimits, IncompleteMethod,
    IncompleteOptions, IncompleteSymbolic, sparse_diagonals,
};

/// k × k 格子の 5 点差分。x 方向（番号 ±1）の結合 a_x、y 方向（番号 ±k）の結合 1。
pub(crate) fn diffusion(k: usize, a_x: f64) -> Result<CsrMatrix<f64>, String> {
    let n = k * k;
    // 第 p 成分は頂点 p と p + 1 の結合。格子の行の端（p + 1 が k の倍数）では 0。
    let x: Vec<f64> = (1..n)
        .map(|p| if p % k == 0 { 0.0 } else { -a_x })
        .collect();
    let y = vec![-1.0_f64; n - k];
    let diagonal = vec![2.0 * (a_x + 1.0); n];
    let offsets = [-(k as isize), -1, 0, 1, k as isize];
    let stored = sparse_diagonals(n, n, &offsets, &[&y, &x, &diagonal, &x, &y])
        .map_err(|e| e.to_string())?;
    stored
        .view()
        .to_csr(ExplicitZeroPolicy::Drop)
        .map_err(|e| e.to_string())
}

/// 前処理付き GMRES の 1 回の結果。
pub(crate) struct Trial {
    pub(crate) iterations: usize,
    pub(crate) termination: LinearSolveTermination,
    pub(crate) error: f64,
}

/// b = A x*（x*_p = sin(p + 1)）を ‖b − Ax‖₂ ≤ 10⁻⁸‖b‖₂ まで解き、厳密解との差の最大を測る。
pub(crate) fn gmres(
    a: &CsrMatrix<f64>,
    preconditioning: Preconditioning<'_, f64>,
) -> Result<Trial, String> {
    let exact: Vec<f64> = (0..a.rows())
        .map(|p| RealScalar::sin((p + 1) as f64))
        .collect();
    let mut b = vec![0.0_f64; a.rows()];
    let mut scratch = vec![0.0_f64; a.apply_workspace_len().map_err(|e| e.to_string())?];
    a.apply_into(&exact, &mut b, &mut scratch)
        .map_err(|e| e.to_string())?;
    let tolerance = ResidualTolerance::new(0.0, 1e-8).map_err(|e| e.to_string())?;
    let limit = Budget::try_from(1000).map_err(|e| e.to_string())?;
    let restart = Budget::try_from(50).map_err(|e| e.to_string())?;
    let result = GmresSolver::new(tolerance, limit)
        .with_restart(restart)
        .solve_with_options(a, &b[..], preconditioning, None)
        .map_err(|e| e.to_string())?;
    let error = result
        .solution()
        .as_slice()
        .iter()
        .zip(&exact)
        .fold(0.0_f64, |m, (x, y)| m.max((x - y).abs()));
    Ok(Trial {
        iterations: result.report().iterations(),
        termination: result.report().termination(),
        error,
    })
}

/// k × k 格子の行列 a の閾値 tau の不完全分解と、作用 1 回で使う L̃ と Ũ の非零の数。
pub(crate) fn incomplete(
    a: &CsrMatrix<f64>,
    k: usize,
    method: IncompleteMethod,
    tau: f64,
) -> Result<(IncompleteFactor<f64>, usize), String> {
    let n = a.rows();
    // 自然順ではフィルは帯幅 k の包絡の中に収まるので、因子は高々 N(2k + 1) ブロック。
    let limits = IncompleteLimits::new(n * (2 * k + 1), 1 << 24);
    let symbolic = IncompleteSymbolic::analyze(a.structural_pattern(), method, 1, limits)
        .map_err(|e| e.to_string())?;
    let options = IncompleteOptions::new().with_drop_tolerance(tau);
    let factor =
        IncompleteFactor::factor(symbolic, a.view(), options).map_err(|e| e.to_string())?;
    let stored = factor.diagnostics().factor_blocks();
    // Cholesky 系は L̃ だけを保存し、L̃ᴴ と対角を共有する。
    let cholesky = matches!(method, IncompleteMethod::Ic0 | IncompleteMethod::Ict);
    Ok((factor, if cholesky { 2 * stored - n } else { stored }))
}
```

### レベルと閾値による因子の大きさと反復回数

次のセルは等方の $a_x = a_y = 1$（対角 4、隣接 $-1$ のラプラシアン）で、前処理なし、Jacobi、IC(0)、ILU(0)、ILU(1)、ILU(2)、ICT、ILUT を比べる。
前処理なしの行は `IdentityPreconditioner` を渡し、前処理を受け取る同じ呼び出しで解く。
入力は格子の辺の点の数 $k$（8〜24）と、ICT と ILUT の閾値 $\tau = 10^{-q}$ の指数 $q$（1〜4）である。
表は保存したブロック、$\tilde{\mathbf{L}}$ と $\tilde{\mathbf{U}}$ の非零の比、捨てたブロック、反復回数、終了理由、厳密解との差の最大を示す。
Jacobi は対角の $N$ 個を保存し、作用 1 回で $N$ 個を使うものとして数える。
最後の判定は、すべての行の GMRES が許容誤差を満たしたかを示す。

```rust
//| id: sparse-ilu-levels
//| ref: sparse-ilu-levels
//| title: 不完全分解のレベルと閾値による因子の大きさと GMRES の反復回数
//| run: reactive
//| uses: [sparse-ilu-model]
//| crates: [scioxide-core, scioxide-sparse, scioxide-linalg]
//| inputs:
//|   grid: {"type":"range","label":"格子の辺の点の数 k","description":"未知数は N = k² 個。","min":8,"max":24,"step":4,"value":16}
//|   drop_exponent: {"type":"range","label":"閾値 τ = 10^(−q) の q","description":"ICT と ILUT が捨てる基準 τ s_i を変える。","min":1,"max":4,"step":1,"value":2}
//| cases:
//|   - {"id":"loose-threshold","label":"τ = 10⁻¹","description":"閾値が大きいと ICT はフィルをすべて捨て、IC(0) と同じ因子と反復回数になる。","inputs":{"drop_exponent":1}}
//|   - {"id":"fine-grid","label":"k = 24","description":"格子を細かくすると、不完全分解でも反復回数が増える。","inputs":{"grid":24}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"preconditioners","path":"/rows/0/4","equals":44}
//|       - {"artifact":"preconditioners","path":"/rows/1/4","equals":44}
//|       - {"artifact":"preconditioners","path":"/rows/2/1","equals":736}
//|       - {"artifact":"preconditioners","path":"/rows/2/2","approx":{"value":1.0,"atol":1e-12}}
//|       - {"artifact":"preconditioners","path":"/rows/2/4","equals":15}
//|       - {"artifact":"preconditioners","path":"/rows/3/4","equals":15}
//|       - {"artifact":"preconditioners","path":"/rows/5/1","equals":2086}
//|       - {"artifact":"preconditioners","path":"/rows/5/4","equals":8}
//|       - {"artifact":"preconditioners","path":"/rows/6/2","approx":{"value":1.7154605263,"rtol":1e-9}}
//|       - {"artifact":"preconditioners","path":"/rows/6/3","equals":405}
//|       - {"artifact":"preconditioners","path":"/rows/7/1","equals":2086}
//|       - {"artifact":"preconditioners","path":"/rows/7/6","range":{"max":1e-6}}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|       - {"path":"/outputs/1/diagnostics/1/value","range":{"max":1e-6}}
//|   - case: loose-threshold
//|     expect:
//|       - {"artifact":"preconditioners","path":"/rows/6/1","equals":736}
//|       - {"artifact":"preconditioners","path":"/rows/6/4","equals":15}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|       - {"path":"/outputs/1/diagnostics/1/value","range":{"max":1e-6}}
//|   - case: fine-grid
//|     expect:
//|       - {"artifact":"preconditioners","path":"/rows/0/4","equals":55}
//|       - {"artifact":"preconditioners","path":"/rows/2/4","equals":20}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|       - {"path":"/outputs/1/diagnostics/1/value","range":{"max":1e-6}}
use scioxide_core::Preconditioner;
use scioxide_linalg::{LinearSolveTermination, Preconditioning};
use scioxide_sparse::{IdentityPreconditioner, IncompleteMethod, JacobiPreconditioner};

let k = grid as usize;
let n = k * k;
let a = diffusion(k, 1.0)?;
let nnz = a.nnz() as f64;
let tau = 10.0_f64.powi(-(drop_exponent as i32));
let identity = IdentityPreconditioner::<f64>::new(n);
let jacobi = JacobiPreconditioner::new(&a).map_err(|e| e.to_string())?;
let mut factors = Vec::new();
for (name, method, drop) in [
    ("IC(0)", IncompleteMethod::Ic0, 0.0),
    ("ILU(0)", IncompleteMethod::Ilu { level: 0 }, 0.0),
    ("ILU(1)", IncompleteMethod::Ilu { level: 1 }, 0.0),
    ("ILU(2)", IncompleteMethod::Ilu { level: 2 }, 0.0),
    ("ICT(τ)", IncompleteMethod::Ict, tau),
    ("ILUT(τ)", IncompleteMethod::Ilut, tau),
] {
    let (factor, entries) = incomplete(&a, k, method, drop)?;
    factors.push((name, factor, entries));
}
// (前処理, 保存したブロック, L̃ と Ũ の非零, 捨てたブロック)
let mut candidates: Vec<(
    &str,
    &dyn Preconditioner<f64>,
    Option<(usize, usize)>,
    Option<usize>,
)> = vec![
    ("前処理なし", &identity, None, None),
    ("Jacobi", &jacobi, Some((n, n)), None),
];
for (name, factor, entries) in &factors {
    let d = factor.diagnostics();
    candidates.push((
        name,
        factor,
        Some((d.factor_blocks(), *entries)),
        Some(d.dropped_blocks()),
    ));
}
let (mut rows, mut trials) = (Vec::new(), Vec::new());
for (name, preconditioner, sizes, dropped) in candidates {
    let trial = gmres(&a, Preconditioning::Inverse(preconditioner))?;
    rows.push((
        name,
        sizes.map(|(stored, _)| stored),
        sizes.map(|(_, entries)| entries as f64 / nnz),
        dropped,
        trial.iterations,
        format!("{:?}", trial.termination),
        trial.error,
    ));
    trials.push(trial);
}
let (fixed2, sci2) = (
    serde_json::json!({ "fractionDigits": 2 }),
    serde_json::json!({ "notation": "scientific", "significantDigits": 2 }),
);
let columns = serde_json::json!([
    { "key": "0", "label": "前処理" },
    { "key": "1", "label": "保存したブロック [個]", "type": "integer", "nullText": "なし" },
    { "key": "2", "label": "L̃ と Ũ の非零 / nnz(A) [-]", "type": "number", "format": fixed2, "nullText": "なし" },
    { "key": "3", "label": "捨てたブロック [個]", "type": "integer", "nullText": "なし" },
    { "key": "4", "label": "反復回数 [回]", "type": "integer" },
    { "key": "5", "label": "終了理由" },
    { "key": "6", "label": "厳密解との差の最大 [-]", "type": "number", "format": sci2 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "preconditioners" })
);
// 判定: 最初に許容誤差を満たさなかった行の終了理由で決める。
let failure = trials
    .iter()
    .map(|t| t.termination)
    .find(|t| !t.is_success());
let outcome = match failure {
    None => Outcome::satisfied("8 つの前処理のすべてで GMRES が許容誤差を満たした"),
    Some(LinearSolveTermination::Breakdown(_)) => {
        Outcome::failed("GMRES が破綻した前処理がある")
    }
    Some(_) => Outcome::partial("GMRES が許容誤差を満たす前に止まった前処理がある"),
};
let most = trials.iter().map(|t| t.iterations).max().unwrap_or(0);
let error = trials.iter().fold(0.0_f64, |m, t| m.max(t.error));
emit_outcome!(
    outcome
        .status(failure.map_or("Converged".to_string(), |t| format!("{t:?}")))
        .diagnostic("最大の反復回数", most as f64, None)
        .diagnostic("厳密解との差の最大", error, None)
);
```

既定の $k = 16$（$N = 256$）、$\tau = 10^{-2}$ では、前処理なしの GMRES は 44 回で収束する。
Jacobi も 44 回で、この行列は対角がすべて 4 なので、Jacobi 前処理は全体を定数倍するだけで反復を変えない。
IC(0) と ILU(0) はどちらも 15 回である。
対称な行列では二つは同じ $\mathbf{M}$ を表し、IC(0) が保存するのは下三角の 736 個だけだが、作用 1 回で使う非零はどちらも $\mathbf{A}$ と同じ 1.00 倍である。
ILU(1) は 1.37 倍で 10 回、ILU(2) は 1.72 倍で 8 回と、レベルを上げるほど因子が大きくなり、反復が減る。
ICT は 405 個のブロックを捨てて、作用 1 回の非零が ILU(2) と同じ 1.72 倍の因子を作り、同じ 8 回で収束する。
ILUT は ICT のちょうど 2 倍の 810 個を捨て、ILU(2) と同じ 2086 個のブロックを残す。
ILU(2)、ICT、ILUT の反復回数は 8 回で一致し、厳密解との差も表の桁で一致する。
等方のラプラシアンでは、閾値 $10^{-2}$ の因子がレベル 2 の因子と同じ大きさになる。
厳密解との差の最大はどれも $10^{-7}$ の程度である。
これは、相対残差の許容誤差 $10^{-8}$ と条件数 $\kappa(\mathbf{A}) = \cot^2(\pi/(2(k+1))) \approx 116$ から決まる上界 $\lVert \mathbf{x} - \mathbf{x}^\ast \rVert_2 \le 10^{-8}\,\kappa(\mathbf{A})\,\lVert \mathbf{x}^\ast \rVert_2$ に収まる。

$\tau = 10^{-1}$ にすると、ICT はフィルをすべて捨てて IC(0) と同じ 736 個のブロックを残し、反復も 15 回に戻る。
格子を細かくすると、前処理なしの反復は $k = 8, 16, 24$ で 25、44、55 回、IC(0) でも 11、15、20 回と増え続ける。
不完全分解は反復の回数を減らすが、格子の大きさへの依存はなくさない。

### 異方性のある拡散での閾値とレベル

レベルは値を見ないので、結合の強さが方向によって大きく違う問題では、弱い結合から生じた小さなフィルも強い結合のフィルと同じように残す。
次のセルは $k = 16$ に固定し、$x$ 方向の結合 $a_x$ を選んで、レベルの ILU(k)（$k = 0, 1, 2, 3$）と閾値の ICT（$\tau = 10^{-1}, \dots, 10^{-4}$）を比べる。
グラフは横軸に $\tilde{\mathbf{L}}$ と $\tilde{\mathbf{U}}$ の非零の比、縦軸に GMRES の反復回数を取り、二つの規則の因子の大きさと反復回数の釣り合いを示す。
左下にある点ほど、少ないメモリと手間で少ない反復に届く。

```rust
//| id: sparse-ilu-anisotropic
//| ref: sparse-ilu-anisotropic
//| title: 異方性のある拡散での閾値とレベルの因子の大きさと反復回数
//| run: reactive
//| uses: [sparse-ilu-model]
//| crates: [scioxide-core, scioxide-sparse, scioxide-linalg]
//| inputs:
//|   coupling: {"type":"select","label":"x 方向の結合 a_x","description":"y 方向の結合は a_y = 1。","options":[{"label":"a_x = 1（等方）","value":"1"},{"label":"a_x = 0.1","value":"0.1"},{"label":"a_x = 0.01","value":"0.01"},{"label":"a_x = 0.001","value":"0.001"}],"value":"0.01"}
//| cases:
//|   - {"id":"isotropic","label":"a_x = 1（等方）","description":"結合の強さがそろうと、閾値の方法はレベルの方法より有利にならない。","inputs":{"coupling":"1"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"tradeoff","path":"/rows/0/3","equals":6}

//|       - {"artifact":"tradeoff","path":"/rows/1/3","equals":3}
//|       - {"artifact":"tradeoff","path":"/rows/5/1","approx":{"value":0.6052631579,"rtol":1e-9}}
//|       - {"artifact":"tradeoff","path":"/rows/5/3","equals":6}
//|       - {"artifact":"tradeoff","path":"/rows/6/1","approx":{"value":1.3700657895,"rtol":1e-9}}
//|       - {"artifact":"tradeoff","path":"/rows/6/3","equals":3}
//|   - case: isotropic
//|     expect:
//|       - {"artifact":"tradeoff","path":"/rows/3/3","equals":7}
//|       - {"artifact":"tradeoff","path":"/rows/6/1","approx":{"value":4.1447368421,"rtol":1e-9}}
```

既定の $a_x = 0.01$ では、ILU(0) は作用 1 回の非零が $\mathbf{A}$ と同じ 1.00 倍で 6 回、ILU(1)〜ILU(3) は 1.37〜2.38 倍でどれも 3 回である。
ICT は $\tau = 10^{-1}$ と $10^{-2}$ で 0.61 倍の因子を作り、1.00 倍の ILU(0) と同じ 6 回で収束する。
$x$ 方向の隣接の大きさ 0.01 は、$s_i = 2.02$ なので $\tau \ge 10^{-2}$ では基準 $\tau s_i \ge 0.0202$ を下回り、ICT は元の $\mathbf{A}$ の弱い結合ごと捨てる。
$\tau = 10^{-3}$ では ILU(1) と同じ 1.37 倍で 3 回になる。
グラフでは、反復 6 回の閾値の点がレベルの点の左にあり、反復 3 回の最も小さい因子はどちらの規則でも 1.37 倍である。

等方の $a_x = 1$ では、同じ因子の大きさで反復回数がそろい（1.00 倍で 15 回、1.72 倍で 8 回）、閾値の点がレベルの点より左下に来ることはない。
$a_x = 0.1$ の $\tau = 10^{-1}$ のように閾値が大きすぎると、ICT は 0.61 倍の因子で 14 回かかり、ILU(0) の 11 回より多くなる。
閾値の方法は値を見て捨てるので、結合の強さがそろわない問題で因子を小さくできるが、$\tau$ は問題に合わせて選ぶ必要がある。

## まとめ

不完全分解はフィルを規則に従って捨てた因子 $\tilde{\mathbf{L}}\tilde{\mathbf{U}} \approx \mathbf{A}$ で、二つの三角系の代入で前処理の作用を計算する。
IC(0) と ILU(k) は構造だけで残す位置を決め、レベル $k$ を上げると因子が大きくなる代わりに反復回数が減る。
ILUT と ICT は値の大きさで捨て、閾値 $\tau$ と各行の上限 $p$ で因子の大きさと近さを調整でき、異方性のある問題では弱い結合を捨てて因子を小さくできる。
因子の大きさを比べるときは、Cholesky 系が $\tilde{\mathbf{L}}$ だけを保存することを考えに入れ、作用 1 回で使う非零の数で比べる。
捨てた更新のためにピボットが破綻したら `IncompletePivotPolicy::Repair` で修復して分解を進められるが、修復の数は前処理の質の目安として診断で確かめる。
格子を細かくすると不完全分解でも反復回数は増えるので、格子によらない収束が必要な楕円型の問題には多重格子の前処理を使う。
