直接法のメモリ使用量と手間は、消去の途中で生じるフィルの量でほぼ決まる。
フィルの量は未知数を消去する順番で桁違いに変わる。
$n$ 次の矢形行列では、中心の頂点を最初に消去すると因子の下三角がすべて埋まり、最後に消去するとフィルは 1 つも生じない。
フィルを最小にする順番を求める問題は NP 困難（Yannakakis, 1981）なので、実際には良い順番を速く見つける発見的な方法を使う。
このページではフィルをグラフの言葉で表す消去グラフ、近似最小次数法（AMD）、帯幅と包絡を縮める Reverse Cuthill–McKee 法（RCM）を説明し、最後に同じ構造の考え方を使う行列の彩色を扱う。

## 消去グラフとフィル

対称な非零パターンを持つ $n \times n$ 行列 $\mathbf{A}$ を、頂点 $\{0, \dots, n-1\}$ と、$a_{ij} \ne 0$（$i \ne j$）のときの辺 $\{i, j\}$ からなる無向グラフ $G(\mathbf{A})$ で表す。
頂点 $v$ を消去する（第 $v$ 行と第 $v$ 列でガウス消去を 1 段進める）と、Schur 補行列の成分 $a_{ij} - a_{iv} a_{vj}/a_{vv}$ は、$a_{iv}$ と $a_{vj}$ がともに 0 でなければ 0 でなくなりうる。
グラフでは $v$ を取り除き、$v$ に隣接していた頂点どうしをすべて辺で結ぶことにあたる。

$$
G \to G', \qquad V' = V \setminus \{v\}, \qquad E' = \bigl(E \cup \{\{i, j\} : i, j \in \mathrm{Adj}(v),\ i \ne j\}\bigr) \cap \binom{V'}{2}
$$

新しく加わった辺がフィルで、$v$ の隣接頂点は消去のあとクリーク（完全部分グラフ）になる。
これを順に繰り返したグラフの列を**消去グラフ**と呼ぶ。
頂点を消去する順番は並べ替え $\mathbf{P}$ にあたり、$\mathbf{P}\mathbf{A}\mathbf{P}^{\mathsf{T}}$ の Cholesky 因子 $\mathbf{L}$ の非零パターンは、元の辺とすべてのフィルの辺の和になる。

Rose、Tarjan、Lueker のフィル路の定理（1976）は、フィルを元のグラフだけで特徴づける。
並べ替えたあとの番号で $i > j$ とし、値の打ち消しを考えない構造上の非零で数えると、

$$
l_{ij} \ne 0 \iff G(\mathbf{A}) \text{ に } i \text{ と } j \text{ を結び、途中の頂点の番号がすべて } j \text{ より小さい道がある}
$$

が成り立つ。
番号の小さい頂点を経由する道が多いほどフィルが増えるので、多くの頂点とつながる頂点はなるべく後で消去する方がよい。

### 最小次数法と商グラフ

頂点 $v$ の次数（隣接頂点の数）を $d$ とすると、$v$ の消去で加わるフィルの辺は高々 $d(d-1)/2$ 本である。
最小次数法は、各段でその時点の消去グラフの次数が最小の頂点を消去する。
フィルそのものを最小にする頂点（最小欠損）を選ぶ代わりにその上界を最小にする発見的な方法で、計算が速く、多くの問題でフィルを大きく減らす。

消去グラフを明示的に作ると、フィルの辺を加えるたびにメモリが増え、次数の更新も重くなる。
**商グラフ**は消去した頂点をまとめた**要素**と、まだ消去していない**変数**からなる。
要素 $e$ に隣接する変数の集合を $L_e$ とすると、$L_e$ の変数どうしは要素 $e$ を通して互いに隣接するとみなす。
変数 $v$ を消去すると、$v$ に隣接していた要素は新しい要素 $v$ に吸収され、$L_v$ は $v$ に隣接していた変数と、吸収した要素に隣接する変数を合わせた集合（$v$ 自身を除く）になる。
消去グラフの辺を作らずに隣接関係を表せるので、メモリ使用量は元のグラフの大きさで抑えられる。

Amestoy、Davis、Duff の近似最小次数法（AMD）は、正確な次数の代わりに、計算量の少ない上界である**近似外部次数**を使う。
変数 $i$ に隣接する変数の集合を $A_i$、要素の集合を $E_i$ とし、集合の大きさ $|\cdot|$ は含まれる元の頂点の数で数える。
$v$ を消去したあと、$i \in L_v$ の近似次数 $\bar d_i$ を

$$
\bar d_i \leftarrow \min\Bigl(n_{\mathrm{rest}},\ \bar d_i + |L_v \setminus \{i\}|,\ |A_i \setminus L_v| + |L_v \setminus \{i\}| + \sum_{e \in E_i,\ e \ne v} |L_e \setminus L_v|\Bigr)
$$

で更新する（$n_{\mathrm{rest}}$ は、まだ消去していない頂点のうち $i$ の超変数に含まれないものの数で、後で述べる密な頂点は数えない）。
$|L_e \setminus L_v|$ は、$L_v$ の変数を 1 回走査するだけで、影響を受けるすべての要素について求まる。
AMD はさらに、隣接する変数と要素の集合が同じ（区別できない）変数を一つの超変数にまとめる統合、$L_e \subseteq L_v$ となった要素を $v$ に吸収する積極的吸収（aggressive absorption）、$L_v$ の外に隣接を持たない変数を $v$ と同時に消去する一括消去（mass elimination）を組み合わせる。

SciOxide の実装は、隣接する要素をたどって到達する生存超変数を重複なく数え、その重みの和で外部次数を更新する。
各更新の計算量は、たどる要素とその隣接集合の大きさに依存する。

`approximate_minimum_degree(pattern)` は、正方な構造を対称化した $\mathbf{A} + \mathbf{A}^{\mathsf{T}}$ のグラフに AMD を適用し、`Permutation`（$p[\text{新}] = \text{旧}$）を返す。
対角は無視し、値が 0 でも保存された位置は辺として扱う。
元のグラフでの次数が $\max(16, 10\lfloor\sqrt{n}\rfloor)$ を超える密な頂点は、消去の対象から外し、番号の順に最後に置く。
近似次数が等しい超変数の間では、元の番号が最も小さい頂点を含むものを先に消去する。
最後に、組立て木（要素と超変数がどの要素に吸収されたかを表す木）を後順にたどって番号を付け直す。
同じ近似次数の間の順序も番号で決めるので、同じ構造には常に同じ置換を返す。
グラフの準備は $O(n + \mathrm{nnz})$ で、商グラフのメモリ使用量はグラフの大きさに比例し、フィルの量にはよらない。
順序付けの手間はグラフに依存し、AMD は一般にはフィルの最小を保証しない。
構造が正方でなければ `DimensionMismatch` を返し、この関数はメモリ使用量の上限を取らない。

### 分解ごとに並べ替えるグラフ

| 分解 | 並べ替えるグラフ | 指定の方法 |
|---|---|---|
| Cholesky・LDL（`SparseSymmetricSymbolic`） | 選んだ三角が表す $\mathbf{A}$ の対称な構造（三角を選ばなければ $\mathbf{A} + \mathbf{A}^{\mathsf{T}}$） | `SparseOrdering` |
| LU（`SparseLuSymbolic`） | $\mathbf{A} + \mathbf{A}^{\mathsf{T}}$ の構造（列の順序） | `SparseOrdering` |
| QR（`SparseQrSymbolic`） | 列の交差グラフ $\mathbf{A}^{\mathsf{T}}\mathbf{A}$ の構造（積は作らない） | `SparseOrdering` |

直接分解の記号解析は `SparseOrdering` で順序を受け取る。
既定の `FillReducing` は上の表のグラフの AMD、`Natural` は元の番号、`Supplied(&permutation)` は与えた置換で、置換の長さが列の数と違えば `DimensionMismatch` になる。
`FillReducing` は順序付けに使う一時的なメモリを見積もり、記号解析の上限 `max_workspace_bytes` を超えれば `ResourceLimit` を返す。
LU と $\mathbf{L}\mathbf{D}\mathbf{L}^{\mathsf{H}}$ では、数値分解のピボット選択がこの順序をさらに変えることがある。
`reverse_cuthill_mckee` などで求めた順序は `Supplied` で渡す。

QR の `FillReducing` は 2 個以上の非零を持つ $\mathbf{A}$ の各行を初期の要素とし、列を変数とする商グラフから AMD を始める。
そのため $\mathbf{A}^{\mathsf{T}}\mathbf{A}$ の辺を一度も作らない。
QR の列順を `approximate_minimum_degree` で自分で求めるには $\mathbf{A}^{\mathsf{T}}\mathbf{A}$ の構造が必要になるので、`FillReducing` を使う方がメモリも手間も少ない。

## Reverse Cuthill–McKee 法と包絡

対角が非零の対称な行列について、**帯幅**を $\beta = \max\{\lvert i - j \rvert : a_{ij} \ne 0\}$、第 $i$ 行の最初の非零の列を $f_i = \min\{j : a_{ij} \ne 0\}$ とし、**包絡**（プロファイル）の大きさを $\sum_i (i - f_i)$ と定める。
消去は行の最初の非零より左に非零を作らないので、Cholesky 分解では第 $i$ 行の非零は列 $f_i$ から $i$ の間にしか生じない（包絡の定理）。
したがって狭義下三角の因子の非零の数は包絡の大きさ以下で、包絡を縮める並べ替えはフィルの上界を下げる。

Cuthill–McKee 法は始点から幅優先探索を行い、訪れた順に番号を付ける。
各頂点の未訪問の隣接頂点は次数の小さい順（同じなら番号の小さい順）に待ち行列に入れる。
隣接する頂点の番号が近くなるので、帯幅と包絡が小さくなる。
始点には、幅優先探索の深さ（離心数）が大きい**疑似周辺頂点**を選ぶ。
`reverse_cuthill_mckee` は、まだ番号を付けていない頂点のうち（次数、番号）が最小のものから探索を始め、最も深い層で（次数、番号）が最小の頂点へ移る。
離心数が増える限りこれを繰り返して始点を決めるので、得られる始点はグラフの直径の端点の近似である。
得られた順序を逆にしたものが RCM で、George の観察と Liu と Sherman の証明により、逆にしても帯幅は変わらず、包絡は大きくならない。
連結成分が複数あるときは、成分ごとに独立に順序を求めて逆にする。
1 回の幅優先探索は $O(n + \mathrm{nnz})$ で、これに隣接頂点の整列が加わる。
帯幅を最小にする問題も NP 困難で、RCM は帯幅と包絡を発見的に縮める方法である。

RCM は帯状の構造を作るので、帯行列の解法や、行列ベクトル積のメモリの局所性を高める目的にも使う。
一方、未知数 $N$ 個の 2 次元格子のように帯幅を $\sqrt{N}$ 程度より小さくできない問題では、包絡の中が埋まって因子の非零が $O(N^{3/2})$ になり、AMD の方がフィルは少ない。

scioxide-sparse は行列そのものを並べ替える関数を提供しない。
並べ替えた行列が必要なら、`old_to_new()` で行と列の番号を付け直した成分から行列を組み立て直す。
ベクトルは `Permutation::apply_into`（$y_{\text{新}} = x_{p[\text{新}]}$）と `inverse_into` で並べ替える。
直接分解の記号解析に使うだけなら、組み立て直さずに `SparseOrdering::Supplied` で置換を渡せばよい。

### 矢形行列のフィルと消去グラフ

矢形行列は、対角と第 0 行・第 0 列だけが非零の $n \times n$ 行列で、グラフは頂点 0 を中心とする星である。
次のセルは対角を 4、第 0 行と第 0 列を 1 とした矢形行列を、自然順、AMD（`FillReducing`）、`reverse_cuthill_mckee` の順序、番号を逆にした順序の四つで記号解析する。
入力は次元 $n$（5〜40）である。
表は中心を消去する順番と、`cholesky_entries()`（因子の狭義下三角にある構造上の非零の数）を示す。
検算として、各順序で星のグラフの消去グラフを作り、頂点を順に消去して加わるフィルの辺を数え、元の狭義下三角の非零の数 $n - 1$ との和を `cholesky_entries()` と比べる。
自然順では中心が最初に消去されて残りがクリークになるので、因子は $n(n-1)/2$ 個で全部埋まる。
中心を最後に消去する順序ではフィルは 0 で、因子は $n - 1$ 個になるはずである。

```rust
//| id: sparse-arrow-fill
//| ref: sparse-arrow-fill
//| title: 矢形行列の消去の順序とフィル
//| run: reactive
//| crates: [scioxide-core, scioxide-sparse]
//| inputs:
//|   matrix_size: {"type":"range","label":"行列の次元 n","description":"中心の頂点 0 と葉 n − 1 個からなる星のグラフの頂点の数。","min":5,"max":40,"step":5,"value":10}
//| cases:
//|   - {"id":"large","label":"n = 40","description":"自然順の因子だけが n(n − 1)/2 = 780 個まで増え、ほかの三つの順序は n − 1 = 39 個のまま変わらない。","inputs":{"matrix_size":40}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"orderings","path":"/rows/0/1","equals":1}
//|       - {"artifact":"orderings","path":"/rows/0/2","equals":45}
//|       - {"artifact":"orderings","path":"/rows/0/3","equals":36}
//|       - {"artifact":"orderings","path":"/rows/0/4","equals":45}
//|       - {"artifact":"orderings","path":"/rows/1/1","equals":10}
//|       - {"artifact":"orderings","path":"/rows/1/2","equals":9}
//|       - {"artifact":"orderings","path":"/rows/2/1","equals":9}
//|       - {"artifact":"orderings","path":"/rows/2/4","equals":9}
//|       - {"artifact":"orderings","path":"/rows/3/1","equals":10}
//|   - case: large
//|     expect:
//|       - {"artifact":"orderings","path":"/rows/0/2","equals":780}
//|       - {"artifact":"orderings","path":"/rows/0/4","equals":780}
//|       - {"artifact":"orderings","path":"/rows/1/2","equals":39}
//|       - {"artifact":"orderings","path":"/rows/2/1","equals":39}
//|       - {"artifact":"orderings","path":"/rows/2/2","equals":39}
//|       - {"artifact":"orderings","path":"/rows/3/3","equals":0}
use scioxide_core::{Permutation, Triangle};
use scioxide_sparse::{
    DuplicatePolicy, ExplicitZeroPolicy, SparseBuilder, SparseOrdering, SparseSymmetricLimits,
    SparseSymmetricSymbolic, reverse_cuthill_mckee,
};

let n = matrix_size as usize;
let mut builder = SparseBuilder::new(n, n);
for i in 0..n {
    builder.push(i, i, 4.0_f64).map_err(|e| e.to_string())?;
    if i > 0 {
        builder.push(i, 0, 1.0).map_err(|e| e.to_string())?;
        builder.push(0, i, 1.0).map_err(|e| e.to_string())?;
    }
}
let a = builder
    .finish_csr(DuplicatePolicy::Reject, ExplicitZeroPolicy::Drop)
    .map_err(|e| e.to_string())?;
let rcm = reverse_cuthill_mckee(a.structural_pattern()).map_err(|e| e.to_string())?;
let reversed = Permutation::new((0..n).rev().collect()).map_err(|e| e.to_string())?;
let limits = SparseSymmetricLimits::new(n * n, n * n, 1 << 20);
let mut rows = Vec::new();
for (name, ordering) in [
    ("自然順", SparseOrdering::Natural),
    ("AMD（FillReducing）", SparseOrdering::FillReducing),
    ("RCM（Supplied）", SparseOrdering::Supplied(&rcm)),
    ("逆順（Supplied）", SparseOrdering::Supplied(&reversed)),
] {
    let symbolic = SparseSymmetricSymbolic::analyze(
        a.structural_pattern(),
        ordering,
        Some(Triangle::Lower),
        limits,
    )
    .map_err(|e| e.to_string())?;
    let p = symbolic.permutation().new_to_old().to_vec();
    // 独立検算: 星のグラフの消去グラフを作り、加わるフィルの辺を数える。
    let mut adjacent: Vec<Vec<bool>> = (0..n)
        .map(|i| (0..n).map(|j| i != j && (i == 0 || j == 0)).collect())
        .collect();
    let (mut eliminated, mut fill) = (vec![false; n], 0usize);
    for &v in &p {
        eliminated[v] = true;
        let neighbors: Vec<usize> = (0..n)
            .filter(|&u| !eliminated[u] && adjacent[v][u])
            .collect();
        for (k, &i) in neighbors.iter().enumerate() {
            for &j in &neighbors[k + 1..] {
                if !adjacent[i][j] {
                    adjacent[i][j] = true;
                    adjacent[j][i] = true;
                    fill += 1;
                }
            }
        }
    }
    let center = p
        .iter()
        .position(|&v| v == 0)
        .ok_or("中心の頂点が順序にない")?;
    rows.push((
        name,
        center + 1,
        symbolic.cholesky_entries(),
        fill,
        n - 1 + fill,
    ));
}
let columns = serde_json::json!([
    { "key": "0", "label": "順序" },
    { "key": "1", "label": "中心を消去する順番 [番目]", "type": "integer" },
    { "key": "2", "label": "cholesky_entries() [個]", "type": "integer" },
    { "key": "3", "label": "消去グラフで数えたフィル [個]", "type": "integer" },
    { "key": "4", "label": "元の辺 + フィル [個]", "type": "integer" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "orderings" })
);
```

既定の $n = 10$ では、自然順は中心を 1 番目に消去し、`cholesky_entries()` は $n(n-1)/2 = 45$ になる。
消去グラフで数えたフィルは 36 個で、元の辺 9 本との和 45 が `cholesky_entries()` と一致する。
AMD は次数 9 の中心を後回しにして 10 番目に消去し、フィルは 0 で因子は 9 個である。
RCM は葉の一つを始点に選び、幅優先探索で中心を 2 番目に訪れる。
その順序を逆にするので、中心は 9 番目に消去され、やはりフィルは 0 になる。
番号を逆にした順序では中心が最後に消去され、フィルは 0 である。
$n = 40$ にすると、自然順の因子だけが $780$ 個まで増え、ほかの三つの順序は $n - 1 = 39$ 個のままである。

## 彩色

彩色は互いに衝突しない頂点や列を同じ色にまとめ、色ごとに一括して処理するための構造の計算である。
衝突の定義によって、二種類の彩色を使い分ける。
`distance_one_coloring` と `derivative_coloring` はどちらも scioxide-core の `ColoringSchedule` を返す。
`kind()` が彩色の種類（`ColoringKind::DistanceOne` か `DerivativeColumns`）、`colors()` が各頂点や列の色（0 から始まる番号）、`color_count()` が色の数、`groups()` が色ごとの頂点や列の集合（昇順）を返す。
`ColoringSchedule::new` は作るときに衝突がないことを検査し、彩色した構造の複製を持つ。
`validate_pattern` は、別の行列の構造が彩色したときと同じかを確かめる。

### 距離 1 彩色

`distance_one_coloring(pattern)` は、正方な構造を対称化した $\mathbf{A} + \mathbf{A}^{\mathsf{T}}$ のグラフで、隣接する頂点が異なる色になるように彩色する（対角は無視する）。
頂点を番号の小さい順に見て、番号の小さい隣接頂点が使っていない最小の色を割り当てる貪欲法で、最大次数を $\Delta$ とすると色の数は $\Delta + 1$ 以下である。
色の数の最小は保証しない（最小の色数を求める問題は NP 困難である）。
構造が正方でなければ `DimensionMismatch` を返す。
同じ色の頂点は互いに隣接しないので、たとえば Gauss–Seidel 法の更新を色ごとに並列に行える（多色順序）。

### 導関数の列の彩色

$m \times n$ のヤコビ行列 $\mathbf{J}$ の二つの列が同じ行に非零を持たないとき、その二つの列は構造的に直交するという。
`derivative_coloring(pattern)` は、同じ行に非零を持つ列が異なる色になるように列を彩色する。
構造は長方形でもよい。
これは列の交差グラフ（$\mathbf{J}^{\mathsf{T}}\mathbf{J}$ の構造）の距離 1 彩色にあたり、列を番号の小さい順に見る貪欲法で求めるが、交差グラフは作らずに行ごとの接続をたどる。
こちらも色の数の最小は保証しない。
色 $c$ の列の集合を $C_c$ とし、$\mathbf{d}_c = \sum_{j \in C_c} \mathbf{e}_j$ の方向微分 $\mathbf{J}\mathbf{d}_c$ を一回の差分や前進モードの自動微分で計算する。
各行 $i$ には $C_c$ の列のうち高々一つしか非零がないので、

$$
J_{ij} = (\mathbf{J}\mathbf{d}_c)_i \qquad (j \in C_c,\ J_{ij} \ne 0)
$$

として、色ごとに $\mathbf{J}$ の列をまとめて復元できる。
必要な方向微分の回数は列の数 $n$ から色の数に減る。
一つの行の非零はすべて異なる色でなければならないので、色の数は行ごとの非零の数の最大以上である。
差分による復元の誤差と手順は [疎ヤコビ行列の彩色による圧縮](../../../scioxide-differentiate/algorithms/sparse-coloring/) で扱う。

### 帯行列の色の数

上下の帯幅が $\beta$ の $n \times n$ の帯行列（$\lvert i - j \rvert \le \beta$ のとき非零）では、列 $j$ と列 $k$ は $\lvert j - k \rvert \le 2\beta$ のとき同じ行に非零を持つ。
$n \ge 2\beta + 1$ なら連続する $2\beta + 1$ 本の列は互いに衝突するので、色は少なくとも $2\beta + 1$ 個必要で、$j \bmod (2\beta + 1)$ による彩色でちょうど足りる。
列を番号の順に見る貪欲法は、列 $j$ に前の $2\beta$ 本が使っていない唯一の色を割り当てるので、この彩色に一致する。
このとき列の数が最も多い色は色 0 で、$\lceil n/(2\beta + 1) \rceil$ 本の列を持つ。
距離 1 彩色では隣接するのは $\lvert i - j \rvert \le \beta$ の頂点で、$\beta + 1$ 個の頂点のクリークがあるので、$\beta + 1$ 色が必要かつ十分である。
次のセルは帯幅 $\beta$（1〜4）と次元 $n$（10〜60）を入力として二つの彩色の色の数と、一つの色の列の最大数を求め、上の理論値と比べる。
検算として、各行の非零の列の色がすべて異なることを、彩色とは独立に数えて確かめる。

```rust
//| id: sparse-derivative-coloring
//| ref: sparse-derivative-coloring
//| title: 帯行列の距離 1 彩色と導関数の列の彩色の色の数
//| run: reactive
//| crates: [scioxide-sparse]
//| inputs:
//|   half_bandwidth: {"type":"range","label":"帯幅 β","description":"|i − j| ≤ β の成分を非零にする。","min":1,"max":4,"step":1,"value":1}
//|   grid_dimension: {"type":"range","label":"次元 n","description":"行と列の数。","min":10,"max":60,"step":10,"value":30}
//| cases:
//|   - {"id":"wide-band","label":"β = 4","description":"列の彩色は 2β + 1 = 9 色になり、色の数が帯幅だけで決まることを確かめる。","inputs":{"half_bandwidth":4}}
//|   - {"id":"long","label":"n = 60","description":"次元を倍にしても色の数は変わらず、一つの色の列の数だけが増える。","inputs":{"grid_dimension":60}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"colors","path":"/rows/0/1","equals":2}
//|       - {"artifact":"colors","path":"/rows/1/1","equals":3}
//|       - {"artifact":"colors","path":"/rows/3/1","equals":10}
//|       - {"artifact":"colors","path":"/rows/3/2","equals":10}
//|       - {"artifact":"colors","path":"/rows/4/1","equals":0}
//|   - case: wide-band
//|     expect:
//|       - {"artifact":"colors","path":"/rows/0/1","equals":5}
//|       - {"artifact":"colors","path":"/rows/1/1","equals":9}
//|       - {"artifact":"colors","path":"/rows/3/1","equals":4}
//|       - {"artifact":"colors","path":"/rows/4/1","equals":0}
//|   - case: long
//|     expect:
//|       - {"artifact":"colors","path":"/rows/1/1","equals":3}
//|       - {"artifact":"colors","path":"/rows/3/1","equals":20}
use scioxide_sparse::{
    DuplicatePolicy, ExplicitZeroPolicy, SparseBuilder, derivative_coloring,
    distance_one_coloring,
};

let (n, beta) = (grid_dimension as usize, half_bandwidth as usize);
let mut builder = SparseBuilder::new(n, n);
for i in 0..n {
    for j in i.saturating_sub(beta)..(i + beta + 1).min(n) {
        builder.push(i, j, 1.0_f64).map_err(|e| e.to_string())?;
    }
}
let a = builder
    .finish_csr(DuplicatePolicy::Reject, ExplicitZeroPolicy::Drop)
    .map_err(|e| e.to_string())?;
let vertex = distance_one_coloring(a.structural_pattern()).map_err(|e| e.to_string())?;
let columns = derivative_coloring(a.structural_pattern()).map_err(|e| e.to_string())?;

// 独立検算: 各行の非零の列の組のうち、同じ色の組を数える。
let mut conflicts = 0usize;
for i in 0..n {
    let row = &a.col_indices()[a.row_ptr()[i]..a.row_ptr()[i + 1]];
    for (k, &j) in row.iter().enumerate() {
        conflicts += row[k + 1..]
            .iter()
            .filter(|&&l| columns.colors()[l] == columns.colors()[j])
            .count();
    }
}
let largest_group = columns.groups().map(<[usize]>::len).max().unwrap_or(0);
let rows: Vec<(&str, usize, Option<usize>)> = vec![
    ("距離 1 彩色の色の数", vertex.color_count(), Some(beta + 1)),
    (
        "列の彩色の色の数（方向微分の回数）",
        columns.color_count(),
        Some(2 * beta + 1),
    ),
    ("列の数 n（彩色しない場合の回数）", n, None),
    (
        "一つの色の列の最大数",
        largest_group,
        Some(n.div_ceil(2 * beta + 1)),
    ),
    ("同じ行で色が重なる列の組の数", conflicts, Some(0)),
];
let table = serde_json::json!([
    { "key": "0", "label": "量" },
    { "key": "1", "label": "値 [個]", "type": "integer" },
    { "key": "2", "label": "理論値 [個]", "type": "integer", "nullText": "なし" }
]);
emit_table_with_columns!(
    table,
    rows,
    metadata = serde_json::json!({ "id": "colors" })
);
```

既定の $\beta = 1$（三重対角）、$n = 30$ では、距離 1 彩色は 2 色、列の彩色は 3 色で、理論値 $\beta + 1$ と $2\beta + 1$ に一致し、同じ行で色が重なる列の組は 0 である。
ヤコビ行列を差分で求めるなら、30 回の方向微分が 3 回で済む。
$n$ を 60 にしても色の数は変わらず、一つの色の列の最大数が理論値 $\lceil n/3 \rceil$ のとおり 10 から 20 に増えるだけである。
$\beta = 4$ では列の彩色は 9 色、距離 1 彩色は 5 色になり、一つの色の列は最大 $\lceil 30/9 \rceil = 4$ 本である。
色の数は次元によらず帯幅で決まる。

## まとめ

フィルは消去グラフで隣接頂点がクリークになることで生じ、フィル路の定理によって元のグラフの道だけで判定できる。
直接分解の記号解析は既定で AMD を使い、商グラフでメモリ使用量を元のグラフの大きさに抑えながら、近似外部次数が小さい頂点から消去する。
AMD は発見的な方法で最小のフィルを保証しないので、特定の構造で良い順序が分かっている場合は `SparseOrdering::Supplied` で与える。
RCM は帯幅と包絡を縮め、包絡の定理によって Cholesky のフィルを包絡の大きさ以下に抑えるので、帯行列の解法や積の局所性の改善に向く。
scioxide-sparse には行列を並べ替える関数がないので、その用途では置換で番号を付け直して行列を組み立て直す。
疎なヤコビ行列は `derivative_coloring` の色の数だけの方向微分で復元でき、帯行列では色の数が次元によらず $2\beta + 1$ になる。
