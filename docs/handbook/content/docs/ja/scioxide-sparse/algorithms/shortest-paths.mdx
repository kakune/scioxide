道路網の所要時間や通信網の遅延は、重み付きの有向グラフの最短路として求まる。
`scioxide-sparse` は、疎行列から作った Plan `GraphPlan` で、単一始点と全点対の最短路を四つのアルゴリズムで求める。
行列をグラフとして解釈する規約と重み 0 の辺の扱いは、[グラフの探索・連結成分・全域森・ラプラシアン](oxref:sparse-graph-from-matrix)で説明している。
このページでは最短路の最適性条件と負の閉路、四つのアルゴリズム、結果と作業領域の読み方を説明し、計算した距離が最短であることをアルゴリズムとは独立に確かめる。
ワンショット関数、標準形式、スコープ付き API といった呼び出しの形の呼び方は、[共通仕様と構成](oxref:sparse-execution-forms)で定義している。

## 最短距離と負の閉路

重み付きの有向グラフで、始点 $s$ から各頂点 $v$ への最短距離 $d^\ast(v)$ を求める。
道の長さは辺の重みの和で、$s$ から届かない頂点では $d^\ast(v) = +\infty$ とする。
辺の重みの和が負になる閉路を**負の閉路**という。
$s$ から負の閉路に届くと、その閉路を何度も回る道はいくらでも短くなるので、最短距離は定まらない。
負の閉路がなければ、負の重みの辺があっても最短距離は定まる。

## 最適性条件

$s$ から届く頂点に有限の値 $d(v)$（$d(s) = 0$）を置いたとき、次の二つが成り立てば $d = d^\ast$ である。

1. 実行可能性：両端に値があるすべての辺 $(u, v)$ で $d(v) \le d(u) + w(u, v)$。
2. 等号の木：$s$ 以外の届く頂点 $v$ ごとに、$d(v) = d(u) + w(u, v)$ を満たす辺 $(u, v)$ がある。
   この $u$ を $v$ の**先行頂点**と呼び、先行頂点をたどると $s$ に戻る。

$s$ から $v$ への任意の道 $s = v_0 \to v_1 \to \cdots \to v_k = v$ で条件 1 の不等式を足し合わせると、$d(v) - d(s) \le \sum_{i=1}^{k} w(v_{i-1}, v_i)$ になる。
したがって $d(v)$ はどの道の長さも超えず、$d(v) \le d^\ast(v)$ が成り立つ。
条件 2 の先行頂点を $v$ から $s$ までたどった道では等号が続くので、その道の長さはちょうど $d(v)$ で、$d^\ast(v) \le d(v)$ である。
合わせて $d(v) = d^\ast(v)$ となる。
条件 1 だけでは足りない。
重みがすべて非負なら、$d \equiv 0$ も条件 1 を満たすからである。
二つの条件は最短路を線形計画として書いたときの双対の実行可能性と相補性にあたる。

負の閉路 $C$ に届く場合は、閉路の各辺で条件 1 を足し合わせると $0 \le w(C) < 0$ となり、条件 1 を満たす $d$ は存在しない。
つまり、負の閉路は最短距離が存在しないことの証拠になる。

## 四つのアルゴリズム

| アルゴリズム | 対象 | 計算量 | 負の重み | 負の閉路のレポート |
|---|---|---|---|---|
| `GraphPathMethod::Dijkstra { source }` | 単一始点 | $O((V + E) \log V)$ | `InvalidInput` で拒む | なし |
| `GraphPathMethod::BellmanFord { source }` | 単一始点 | $O(VE)$ | 使える | 始点から届く閉路 |
| `GraphPathMethod::FloydWarshall` | 全点対 | $O(V^3)$、出力 $O(V^2)$ | 使える | グラフのどこかにある閉路 |
| `GraphPathMethod::Johnson` | 全点対 | $O(VE + V(V + E) \log V)$、出力 $O(V^2)$ | 使える | グラフのどこかにある閉路 |

Plan は方法を自動では選ばない（負の重みの有無で Dijkstra 法と Bellman–Ford 法を選ぶのは、後で述べるワンショット関数 `shortest_paths` である）。
単一始点の方法は `Dijkstra { source }` のように始点を手法オブジェクトに持つ。

**Dijkstra 法**は距離の確定した頂点の集合を一つずつ広げる。
非負の重みでは、未確定の頂点のうち仮の距離が最小のものは、他の頂点を経由してもそれ以上短くならないので確定してよい。
仮の距離は添字付きの二分ヒープに置き、距離が下がるたびにヒープの中で位置を直す。
負の重みがあるとこの議論が成り立たないので、始点から届かない辺も含めて、負の重みが一つでもあれば `InvalidInput` で拒む。
確定した頂点の距離が丸めのために下がった場合は、`NumericalInstability`（`Breakdown`）で失敗する。

**Bellman–Ford 法**はすべての辺で $d(v) \leftarrow \min(d(v), d(u) + w(u, v))$ とする緩和を繰り返す。
負の閉路がなければ最短路は同じ頂点を二度通らないので、高々 $V - 1$ 本の辺からなる。
$k$ 回目の緩和の後には、各頂点の値は、辺が $k$ 本以下の道の長さの最小を超えない。
値はいつも実際の道の長さなので最短距離を下回らず、$V - 1$ 回の後には最短距離に等しくなる。
$V$ 回目にも距離が変われば、負の閉路がある。
距離が変わらなくなった回で止めるので、多くのグラフでは $V$ 回より早く終わる。
負の閉路を見つけたときは、$V$ 回目に距離が変わった頂点から先行頂点を $V$ 回たどって閉路の上に移り、そこから閉路を一周して頂点を集める。
集めた閉路の重みは辺の重みから計算し直し、丸めのために負でなくなったときは閉路を返さずに `NumericalInstability`（`LossOfSignificance`）で失敗する。
無向のグラフでは、負の重みの辺 $\{u, v\}$ がそれだけで閉路 $u \to v \to u$ になるので、負の辺に届けば負の閉路が示される。

二つの全点対の方法はまず全頂点へ重み 0 の辺を張った仮の始点から Bellman–Ford 法を $O(VE)$ で行い、グラフのどこかにある負の閉路を探す。
そのため、全点対の方法は始点から届かない閉路も返す。

**Floyd–Warshall 法**は、経由してよい頂点を $0, 1, \ldots, k$ に限ったときの距離 $d_k(i, j)$ を

$$
d_k(i, j) = \min\bigl(d_{k-1}(i, j),\ d_{k-1}(i, k) + d_{k-1}(k, j)\bigr)
$$

で $k = 0, 1, \ldots, V - 1$ と更新する。
初めの $d_{-1}(i, j)$ は辺 $(i, j)$ の重みで、$i = j$ では 0、辺がなければ $+\infty$ とする。
更新で値が下がったときは、経路を復元するための先行頂点も $p(i, j) \leftarrow p(k, j)$ と書き換える。
各 $k$ をピボットと呼び、一回の更新は $O(V^2)$、全体で $O(V^3)$ である。
小さく密なグラフに向く。

**Johnson 法**は仮の始点からの距離をポテンシャル $h$ とし、重みを $w'(u, v) = w(u, v) + h(u) - h(v)$ に付け替える。
$h$ は条件 1 を満たすので $w' \ge 0$ になり、各始点で Dijkstra 法が使える。
$s$ から $t$ への道の長さは $h(s) - h(t)$ だけ変わり、どの道でも同じ量なので、最短路は変わらない。
求めた距離 $d'(s, t)$ は $d(s, t) = d'(s, t) - h(s) + h(t)$ で元に戻す。
付け替えた重みが丸めで負になったときは `NumericalInstability`（`LossOfSignificance`）で失敗する。
$E$ が $V^2$ よりずっと小さい疎なグラフに向く。

二つの全点対の方法は始点（結果の行）を実行方針に従って複数のワーカーに分ける。
ワーカーの数は 64 と頂点の数を超えない。
各行は独立に計算するので、結果はワーカーの数によらない。
単一始点の方法は逐次に実行する。

## 結果、作業領域、反復回数の上限

Plan の標準形式 `shortest_paths(method)` は、`PathOutcome::Paths(GraphPathResult)` か `PathOutcome::NegativeCycle(NegativeCycle)` を返す。
負の閉路はエラーではなく結果の一つである。
`NegativeCycle::vertices()` は閉路の頂点の列で、最初の頂点を最後にもう一度置く（負の自己ループなら `[v, v]`）。
`GraphPathResult::as_view()` が返す `GraphPathView` の `distances()` と `predecessors()` は、単一始点では長さ $V$、全点対では行優先の $V^2$ の配列で、組 $(i, j)$ は $iV + j$ 番目にある。
届かない頂点の距離と、始点と届かない頂点の先行頂点は `None` である。
`source()` は単一始点の結果なら始点、全点対なら `None` を返す。
`path(source, target)` は先行頂点を $O(V)$ でたどって経路を返し、届かなければ `None`、始点と終点が同じなら `[source]` を返す。
単一始点の結果に別の始点を渡すと `InvalidInput`、頂点でない番号は `OutOfBounds` である。

ワンショット関数 `shortest_paths(matrix, source)` は、行列を有向グラフとして読み、負の重みがなければ Dijkstra 法、あれば Bellman–Ford 法で距離を求めて `GraphPathResult` を返す。
始点から届く負の閉路は、距離が存在しないので `DomainError`（引数 `matrix`）で返す。

スコープ付き API `shortest_paths_scoped(method, options, workspace, scope)` は、事前確保した `GraphWorkspace` に結果を書き、`PathOutcome<GraphPathView, &[usize]>` として作業領域を借用して返す。
借用は次の呼び出しまで有効である。
作業領域は `GraphWorkspaceRequest::new(method, options)` を Plan の `workspace(request)` に渡して作るか、`workspace_requirements(request)` が返す `GraphWorkspaceRequirements` に対して `GraphWorkspace::try_reserve` で事前確保する。
要件の `output_entries()` は単一始点で $V$、全点対で $V^2$ で、`workers()` は全点対の方法のワーカーの数である。
`bytes::<S>()` は論理バイト数を返し、`check` で足りるかを確かめられる。
足りない作業領域は広げずに `DimensionMismatch` で拒む。

`GraphExecutionOptions::with_budgets` で反復回数の上限を与えると、スコープ付き API は次の単位で反復を 1 回と数える（章に共通の規則は[反復回数の上限と実行コンテキスト](oxref:sparse-iteration-limits)）。

- Bellman–Ford 法の各回の緩和。
  全点対の方法が最初に行う負の閉路の探索も含む。
- Dijkstra 法でヒープから取り出す各頂点。
- Floyd–Warshall 法の各ピボット。
- Johnson 法の各始点の Dijkstra 法は入れ子のスコープで実行し、同じ上限を始点ごとに別々に当てる。
  その反復は外側の呼び出しの回数に数えない。

上限に達すると `ConvergenceFailure`、取り消しや期限では `ExecutionStopped` を返す。
標準形式とワンショット関数は上限を持たないので、この二つのエラーを返さない。
失敗したときは部分的な結果を出力に反映せず、作業領域の `last_accepted()` は `None` を返す。
`last_attempt()` は、始まる前に拒まれた呼び出しを含めて、最後の試行の記録を返す。
距離の和が表せないときは、どの形も `NumericalInstability`（`Overflow`）で失敗する。

### 重み 0 の辺と Dijkstra 法

次のセルは成分 $(0, 1) = 0$、$(1, 2) = d$、$(0, 2) = 5$ を持つ $4 \times 4$ の行列を有向グラフとして読み、頂点 0 からの最短路を Dijkstra 法で求める。
頂点 3 は辺を持たない。
入力は重み $d$（1〜8）と、重み 0 の成分を構造に残すかどうかである。
Plan の標準形式 `shortest_paths(method)` の距離と経路に、ワンショット関数 `shortest_paths(matrix, source)` の距離を並べる。
検算として、辺の一覧から手で求めた距離を最後の列に置く。

```rust
//| id: sparse-zero-edge-paths
//| ref: sparse-zero-edge-paths
//| title: 重み 0 の辺と Dijkstra 法
//| run: reactive
//| crates: [scioxide-core, scioxide-sparse]
//| inputs:
//|   edge_weight: {"type":"range","label":"成分 (1, 2) の重み d","description":"直接の辺 0→2（重み 5）より短いかどうかで最短路が変わる。","min":1.0,"max":8.0,"step":1.0,"value":2.0}
//|   keep_zero: {"type":"checkbox","label":"重み 0 の成分を構造に残す（Preserve）","description":"外すと、組立てで値が 0 の成分を取り除く（Drop）。","value":true}
//| cases:
//|   - {"id":"long-detour","label":"d = 6","description":"回り道 0→1→2 が直接の辺より長くなり、最短路が 0→2 に変わる。","inputs":{"edge_weight":6}}
//|   - {"id":"drop-zero","label":"重み 0 の成分を取り除く","description":"頂点 1 に届かなくなり、頂点 2 への距離は直接の辺の 5 になる。","inputs":{"keep_zero":false}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"paths","path":"/rows/1/1","approx":{"value":0,"atol":1e-15}}
//|       - {"artifact":"paths","path":"/rows/2/1","approx":{"value":2,"atol":1e-15}}
//|       - {"artifact":"paths","path":"/rows/2/2","equals":"0 → 1 → 2"}
//|       - {"artifact":"paths","path":"/rows/2/3","approx":{"value":2,"atol":1e-15}}
//|       - {"artifact":"paths","path":"/rows/3/1","equals":null}
//|       - {"artifact":"paths","path":"/rows/3/3","equals":null}
//|   - case: long-detour
//|     expect:
//|       - {"artifact":"paths","path":"/rows/2/1","approx":{"value":5,"atol":1e-15}}
//|       - {"artifact":"paths","path":"/rows/2/2","equals":"0 → 2"}
//|   - case: drop-zero
//|     expect:
//|       - {"artifact":"paths","path":"/rows/1/1","equals":null}
//|       - {"artifact":"paths","path":"/rows/1/3","equals":null}
//|       - {"artifact":"paths","path":"/rows/2/1","approx":{"value":5,"atol":1e-15}}
use scioxide_sparse::{
    DuplicatePolicy, ExplicitZeroPolicy, GraphDirection, GraphPathMethod, GraphPlan,
    PathOutcome, SparseBuilder, shortest_paths,
};

let d = edge_weight;
let zeros = if keep_zero {
    ExplicitZeroPolicy::Preserve
} else {
    ExplicitZeroPolicy::Drop
};
let mut builder = SparseBuilder::new(4, 4);
for (u, v, w) in [(0, 1, 0.0_f64), (1, 2, d), (0, 2, 5.0)] {
    builder.push(u, v, w).map_err(|e| e.to_string())?;
}
let matrix = builder
    .finish_csr(DuplicatePolicy::Reject, zeros)
    .map_err(|e| e.to_string())?;

// Plan の標準形式: 方法と始点を明示する。
let graph =
    GraphPlan::new(matrix.view(), GraphDirection::Directed).map_err(|e| e.to_string())?;
let outcome = graph
    .shortest_paths(GraphPathMethod::Dijkstra { source: 0 })
    .map_err(|e| e.to_string())?;
let PathOutcome::Paths(result) = outcome else {
    return Err("Dijkstra 法は負の閉路を返しない".to_string());
};
let paths = result.as_view();
// ワンショット関数: 負の重みがないので Dijkstra 法を選ぶ。
let direct = shortest_paths(matrix.view(), 0).map_err(|e| e.to_string())?;
// 独立検算: 辺の一覧から手で求めた距離。
let expected = if keep_zero {
    [Some(0.0), Some(0.0), Some(d.min(5.0)), None]
} else {
    [Some(0.0), None, Some(5.0), None]
};
let mut rows = Vec::new();
for v in 0..4 {
    let route = paths.path(0, v).map_err(|e| e.to_string())?.map(|p| {
        let names: Vec<String> = p.iter().map(|u| u.to_string()).collect();
        names.join(" → ")
    });
    let one_shot = direct.as_view().distances()[v];
    rows.push((v, paths.distances()[v], route, one_shot, expected[v]));
}
let columns = serde_json::json!([
    { "key": "0", "label": "頂点 v", "type": "integer" },
    { "key": "1", "label": "距離 d(v)", "type": "number", "nullText": "未到達" },
    { "key": "2", "label": "最短路", "type": "string", "nullText": "なし" },
    { "key": "3", "label": "ワンショット関数の距離", "type": "number", "nullText": "未到達" },
    { "key": "4", "label": "手で求めた距離", "type": "number", "nullText": "未到達" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "paths" })
);
```

既定の $d = 2$ で重み 0 の成分を残すと、頂点 1 には距離 0 で、頂点 2 には $0 \to 1 \to 2$ を通って距離 2 で届く。
$d = 6$ にすると直接の辺 $0 \to 2$（重み 5）の方が短くなり、最短路は $0 \to 2$ に変わる。
重み 0 の成分を取り除くと頂点 1 には届かなくなり、頂点 2 への距離は直接の辺の 5 になる。
どの場合も頂点 3 は辺を持たないので届かず、Plan の距離、ワンショット関数の距離、手で求めた距離が一致する。

### 実験のグラフ

次の二つのセルは同じ 6 頂点の有向グラフを使う。
辺は $0 \to 1$: 4、$0 \to 2$: 2、$2 \to 1$: 1、$1 \to 3$: 2、$2 \to 3$: 5、$3 \to 4$: 3、$4 \to 5$: 1、$3 \to 5$: 6、$4 \to 1$: $w$ である。
閉路 $1 \to 3 \to 4 \to 1$ の重みは $5 + w$ なので、$w < -5$ で負の閉路ができる。
頂点 5 からは辺が出ていないので、頂点 5 を始点にすると閉路に届かない。
定義のブロックは辺の一覧 `network(w)`、それを有向グラフとして解釈する Plan `directed_plan`、検算のために辺の一覧から重みを引く `weight` と閉路の重みを足す `cycle_weight`、頂点の列を文字列にする `route` を置く。

```rust
//| id: sparse-shortest-path-network
//| kind: definitions
//| title: 閉路 1→3→4→1 を持つ 6 頂点の有向グラフ
//| crates: [scioxide-core, scioxide-sparse]
use scioxide_core::SciOxideError;
use scioxide_sparse::{
    DuplicatePolicy, ExplicitZeroPolicy, GraphDirection, GraphPlan, SparseBuilder,
};

/// 頂点の数 V。
pub(crate) const VERTICES: usize = 6;

/// 辺の一覧 (u, v, w(u, v))。入力で変えるのは辺 4 → 1 の重み w だけである。
pub(crate) fn network(back_weight: f64) -> [(usize, usize, f64); 9] {
    [
        (0, 1, 4.0),
        (0, 2, 2.0),
        (2, 1, 1.0),
        (1, 3, 2.0),
        (2, 3, 5.0),
        (3, 4, 3.0),
        (4, 5, 1.0),
        (3, 5, 6.0),
        (4, 1, back_weight),
    ]
}

/// 辺の一覧を有向グラフとして読んだ Plan。
pub(crate) fn directed_plan(edges: &[(usize, usize, f64)]) -> Result<GraphPlan<f64>, SciOxideError> {
    let mut builder = SparseBuilder::new(VERTICES, VERTICES);
    for &(u, v, w) in edges {
        builder.push(u, v, w)?;
    }
    let matrix = builder.finish_csr(DuplicatePolicy::Reject, ExplicitZeroPolicy::Preserve)?;
    GraphPlan::new(matrix.view(), GraphDirection::Directed)
}

/// 辺 (u, v) の重みを辺の一覧から引く（独立検算用）。
pub(crate) fn weight(edges: &[(usize, usize, f64)], u: usize, v: usize) -> Option<f64> {
    edges.iter().find(|e| e.0 == u && e.1 == v).map(|e| e.2)
}

/// 閉じた頂点の列の辺の重みを、辺の一覧から足す（独立検算用）。
pub(crate) fn cycle_weight(edges: &[(usize, usize, f64)], cycle: &[usize]) -> Option<f64> {
    cycle.windows(2).map(|p| weight(edges, p[0], p[1])).sum()
}

/// 頂点の列を「1 → 3 → 4 → 1」の形の文字列にする。
pub(crate) fn route(vertices: &[usize]) -> String {
    let names: Vec<String> = vertices.iter().map(|v| v.to_string()).collect();
    names.join(" → ")
}
```

### 最短路の最適性の証拠

次のセルは頂点 0 を始点として Bellman–Ford 法を当てる。
入力は $w$（$-8$〜$4$）である。
距離が返ったときは、最適性条件の二つの量を頂点ごとに示す。
先行頂点の辺での $d(v) - d(u) - w(u, v)$ が 0 なら条件 2、$v$ に入るすべての辺での同じ量の最大が 0 以下なら条件 1 が成り立つ。
負の閉路が示されたときは、閉路の辺の重みを辺の一覧から独立に足し、負であることを確かめる。

```rust
//| id: sparse-graph-certificates
//| ref: sparse-graph-certificates
//| title: Bellman–Ford 法の距離の最適性の証拠
//| run: reactive
//| uses: [sparse-shortest-path-network]
//| crates: [scioxide-core, scioxide-sparse]
//| inputs:
//|   back_weight: {"type":"range","label":"辺 4→1 の重み w","description":"閉路 1→3→4→1 の重みは 5 + w で、w < −5 で負になる。","min":-8.0,"max":4.0,"step":1.0,"value":-2.0}
//| cases:
//|   - {"id":"zero-cycle","label":"w = −5","description":"閉路の重みが 0 になっても、最短距離は変わらない。","inputs":{"back_weight":-5}}
//|   - {"id":"negative-cycle","label":"w = −6","description":"閉路の重みが −1 になり、Bellman–Ford 法は距離の代わりに閉路を返す。","inputs":{"back_weight":-6}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"certificate","path":"/rows/1/1","approx":{"value":3,"atol":1e-15}}
//|       - {"artifact":"certificate","path":"/rows/1/2","equals":2}
//|       - {"artifact":"certificate","path":"/rows/5/1","approx":{"value":9,"atol":1e-15}}
//|       - {"artifact":"certificate","path":"/rows/4/3","approx":{"value":0,"atol":1e-15}}
//|       - {"artifact":"certificate","path":"/rows/1/4","range":{"max":1e-15}}
//|       - {"artifact":"certificate","path":"/rows/0/2","equals":null}
//|   - case: zero-cycle
//|     expect:
//|       - {"artifact":"certificate","path":"/rows/1/1","approx":{"value":3,"atol":1e-15}}
//|       - {"artifact":"certificate","path":"/rows/1/4","range":{"max":1e-15}}
//|   - case: negative-cycle
//|     expect:
//|       - {"artifact":"cycle","path":"/rows/0/0","equals":"1 → 3 → 4 → 1"}
//|       - {"artifact":"cycle","path":"/rows/0/1","approx":{"value":-1,"atol":1e-15}}
use scioxide_sparse::{GraphPathMethod, PathOutcome};

let n = VERTICES;
let edges = network(back_weight);
let graph = directed_plan(&edges).map_err(|e| e.to_string())?;
let outcome = graph
    .shortest_paths(GraphPathMethod::BellmanFord { source: 0 })
    .map_err(|e| e.to_string())?;
match outcome {
    PathOutcome::Paths(result) => {
        let view = result.as_view();
        let (d, parent) = (view.distances(), view.predecessors());
        let mut rows = Vec::new();
        for v in 0..n {
            // 条件 2: 先行頂点 u からの辺での d(v) − d(u) − w(u, v)。
            let tree = match (parent[v], d[v]) {
                (Some(u), Some(dv)) => {
                    let du = d[u].ok_or("先行頂点に距離がない")?;
                    let w = weight(&edges, u, v).ok_or("先行頂点の辺が一覧にない")?;
                    Some(dv - du - w)
                }
                _ => None,
            };
            // 条件 1: v に入るすべての辺 (u, v) での同じ量の最大。
            let worst = edges
                .iter()
                .filter(|e| e.1 == v)
                .filter_map(|&(u, _, w)| Some(d[v]? - d[u]? - w))
                .reduce(f64::max);
            rows.push((v, d[v], parent[v], tree, worst));
        }
        let columns = serde_json::json!([
            { "key": "0", "label": "頂点 v", "type": "integer" },
            { "key": "1", "label": "距離 d(v)", "type": "number", "nullText": "未到達" },
            { "key": "2", "label": "先行頂点 u", "type": "integer", "nullText": "-" },
            { "key": "3", "label": "先行頂点の辺での差", "type": "number", "nullText": "-" },
            { "key": "4", "label": "入る辺での差の最大", "type": "number", "nullText": "-" }
        ]);
        emit_table_with_columns!(
            columns,
            rows,
            metadata = serde_json::json!({ "id": "certificate" })
        );
    }
    PathOutcome::NegativeCycle(cycle) => {
        // 独立検算: 閉路の辺の重みを辺の一覧から足す。負なら距離は存在しない。
        let vertices = cycle.vertices();
        let total = cycle_weight(&edges, vertices).ok_or("閉路の辺が一覧にない")?;
        let columns = serde_json::json!([
            { "key": "0", "label": "負の閉路", "type": "string" },
            { "key": "1", "label": "閉路の重み（辺の一覧から）", "type": "number" }
        ]);
        emit_table_with_columns!(
            columns,
            vec![(route(vertices), total)],
            metadata = serde_json::json!({ "id": "cycle" })
        );
    }
}
```

既定の $w = -2$ では閉路の重みは 3 で、距離は $(0, 3, 2, 5, 8, 9)$ になる。
頂点 1 へは直接の辺（重み 4）より $0 \to 2 \to 1$（重み 3）が短い。
始点以外の頂点で、先行頂点の辺での差はすべて 0 で、入る辺での差の最大も 0 なので、二つの条件が成り立つ。
アルゴリズムの中身によらず、この表だけで距離が最短であることを確かめられる。
$w = -5$ では閉路の重みが 0 になり、辺 $4 \to 1$ でも等号が成り立つが、最短距離は変わらない。
$w = -6$ にすると閉路の重みが $-1$ になり、Bellman–Ford 法は距離の代わりに閉路 $1 \to 3 \to 4 \to 1$ を返し、辺の一覧から足した重みも $-1$ になる。

### 単一始点と全点対の方法が返す負の閉路

次のセルは同じグラフに始点 $s$ からの Bellman–Ford 法と、二つの全点対の方法を当てて結果を並べる。
入力は $w$ と始点 $s$（0〜5）で、既定は閉路のある $w = -6$ と、閉路に届かない $s = 5$ である。
全点対の方法が距離を返したときは、行 $s$ と Bellman–Ford 法の距離の差の最大を示す。
負の閉路が示されたときは、閉路の辺の重みを辺の一覧から独立に足す。

```rust
//| id: sparse-negative-cycle-reports
//| ref: sparse-negative-cycle-reports
//| title: 単一始点と全点対の方法が返す負の閉路
//| run: reactive
//| uses: [sparse-shortest-path-network]
//| crates: [scioxide-core, scioxide-sparse]
//| inputs:
//|   back_weight: {"type":"range","label":"辺 4→1 の重み w","description":"閉路 1→3→4→1 の重みは 5 + w で、w < −5 で負になる。","min":-8.0,"max":4.0,"step":1.0,"value":-6.0}
//|   source: {"type":"range","label":"始点 s","description":"頂点 5 からは辺が出ていないので、閉路に届かない。","min":0,"max":5,"step":1,"value":5}
//| cases:
//|   - {"id":"reachable","label":"s = 0","description":"始点から閉路に届くので、三つの方法がどれも同じ閉路を返す。","inputs":{"source":0}}
//|   - {"id":"no-cycle","label":"w = −2、s = 0","description":"閉路の重みが正になり、三つの方法の距離が一致する。","inputs":{"back_weight":-2,"source":0}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"outcomes","path":"/rows/0/1","equals":"最短路"}
//|       - {"artifact":"outcomes","path":"/rows/1/1","equals":"負の閉路"}
//|       - {"artifact":"outcomes","path":"/rows/1/3","equals":"1 → 3 → 4 → 1"}
//|       - {"artifact":"outcomes","path":"/rows/2/4","approx":{"value":-1,"atol":1e-15}}
//|   - case: reachable
//|     expect:
//|       - {"artifact":"outcomes","path":"/rows/0/1","equals":"負の閉路"}
//|       - {"artifact":"outcomes","path":"/rows/0/4","approx":{"value":-1,"atol":1e-15}}
//|   - case: no-cycle
//|     expect:
//|       - {"artifact":"outcomes","path":"/rows/1/1","equals":"最短路"}
//|       - {"artifact":"outcomes","path":"/rows/1/2","range":{"max":1e-15}}
//|       - {"artifact":"outcomes","path":"/rows/2/2","range":{"max":1e-15}}
use scioxide_sparse::{GraphPathMethod, PathOutcome};

let s = source.round() as usize;
let n = VERTICES;
let edges = network(back_weight);
let graph = directed_plan(&edges).map_err(|e| e.to_string())?;
let methods = [
    (
        "Bellman–Ford（始点 s）",
        GraphPathMethod::BellmanFord { source: s },
    ),
    ("Floyd–Warshall", GraphPathMethod::FloydWarshall),
    ("Johnson", GraphPathMethod::Johnson),
];
// Bellman–Ford 法の始点 s からの距離（全点対の方法の行 s と比べる基準）。
let mut reference: Option<Vec<Option<f64>>> = None;
let mut rows = Vec::new();
for (name, method) in methods {
    match graph.shortest_paths(method).map_err(|e| e.to_string())? {
        PathOutcome::Paths(result) => {
            let view = result.as_view();
            let mut gap = None;
            if view.source().is_some() {
                reference = Some(view.distances().to_vec());
            } else if let Some(base) = &reference {
                let row = &view.distances()[s * n..(s + 1) * n];
                let mut largest = 0.0_f64;
                for pair in base.iter().zip(row) {
                    match pair {
                        (Some(a), Some(b)) => largest = largest.max((a - b).abs()),
                        (None, None) => {}
                        _ => return Err("到達の判定が方法によって違う".to_string()),
                    }
                }
                gap = Some(largest);
            }
            rows.push((name, "最短路", gap, None, None));
        }
        PathOutcome::NegativeCycle(cycle) => {
            let vertices = cycle.vertices();
            // 独立検算: 閉路の辺の重みを辺の一覧から足す。
            let total = cycle_weight(&edges, vertices).ok_or("閉路の辺が一覧にない")?;
            rows.push((name, "負の閉路", None, Some(route(vertices)), Some(total)));
        }
    }
}
let columns = serde_json::json!([
    { "key": "0", "label": "方法", "type": "string" },
    { "key": "1", "label": "結果", "type": "string" },
    { "key": "2", "label": "行 s と Bellman–Ford 法の差の最大", "type": "number", "nullText": "-" },
    { "key": "3", "label": "閉路の頂点の列", "type": "string", "nullText": "-" },
    { "key": "4", "label": "閉路の重み（辺の一覧から）", "type": "number", "nullText": "-" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "outcomes" })
);
```

既定の $w = -6$、$s = 5$ では、Bellman–Ford 法は距離を返すが、届くのは頂点 5 自身（距離 0）だけである。
一方、全点対の方法はグラフ全体を調べるので、始点から届かない閉路 $1 \to 3 \to 4 \to 1$ を返し、辺の一覧から足した重みは $-1$ になる。
$s = 0$ にすると始点から閉路に届くので、三つの方法がどれも同じ閉路を返す。
$w = -2$、$s = 0$ では閉路の重みが正になり、三つの方法はどれも距離を返し、全点対の方法の行 0 は Bellman–Ford 法の距離と一致する。

## まとめ

最短路は、非負の重みなら Dijkstra 法、負の重みがあれば Bellman–Ford 法、全点対なら小さく密なグラフで Floyd–Warshall 法、疎なグラフで Johnson 法を選ぶ。
求めた距離は全辺での実行可能性と先行頂点の辺での等号の二つで、アルゴリズムによらず最短であることを確かめられる。
負の閉路は、Plan のメソッドでは閉じた頂点の列として結果に返り、ワンショット関数 `shortest_paths` では `DomainError` になる。
単一始点の方法は始点から届く閉路だけを返し、全点対の方法はグラフのどこかにある閉路を返す。
反復回数の上限を与えるときはスコープ付き API を使い、Johnson 法では始点ごとの探索に同じ上限が別々に当たる。
