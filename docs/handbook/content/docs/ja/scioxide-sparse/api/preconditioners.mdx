この表は Krylov 法などの反復解法に渡す前処理の項目をまとめる。
`IdentityPreconditioner`、`JacobiPreconditioner`、`IncompleteFactor`、`AmgCycle`、`AmgPreconditioner`、`SchwarzPlan` は scioxide-core の `Preconditioner` を実装する。
このトレイトの `precondition_workspace_len` は作業領域の長さを先に返し、`precondition_into` は既定の `SparseSolveOptions`（`Standard`、逐次）で作用させる。
`precondition_into_scoped` は呼び出し側の実行コンテキスト（取り消しと期限）を引き継ぐが、反復回数は数えない。
作用の回数は、呼び出した解法が前処理の評価として数える。

各型の固有のメソッドには、標準形式と出力先を指定する API がある。
標準形式の `apply(rhs)`（`IncompleteFactor` では `solve`）は、既定の `SparseSolveOptions`、新しい作業領域、`ExecutionContext::sequential_native()` で実行し、結果を新しい配列で返す。
出力先を指定する API の `apply_into`・`apply_block_into`（`IncompleteFactor` では `solve_into`・`solve_block_into`）は、`SparseSolveOptions`、出力、共通の `SparseSolveWorkspace`、スコープを受け取る。
作業領域は `workspace_requirements(rhs)` で問い合わせて `workspace(rhs)` で作り、事前確保済みの作業領域を渡せば出力先を指定する API は自分では確保しない。
出力先を指定する API は右辺 1 本を反復 1 回と数え、`SparseSolveOptions` かスコープの反復回数の上限に達すると `ConvergenceFailure`（`IterationLimit`）を返す。
どの形も検査と計算を終えてから出力を書くので、失敗しても出力は変わらない。
構築の成功や診断の値は、前処理の質や反復の収束を証明しない。
