階層的クラスタリングの連結法や多次元尺度構成法は、点集合のすべての対の距離をまとめて使う。
$n$ 点の対は $n^2$ 個あるので、結果をどの形の配列に並べ、どれだけのメモリ領域を用意するかが問題になる。
このページは全点対の距離を並べる配列の形、同じ点集合の対を半分のメモリ領域で持つ圧縮表現とその添字、行列との相互変換と検証、作業領域の大きさと失敗したときの出力の扱いを説明する。
距離の定義と定義域は[距離と非類似度](../distances/)で扱う。

## 対ごとの距離行列と圧縮表現

左の点集合（$n_\ell$ 点）と右の点集合（$n_r$ 点）の全点対の距離は、`PreparedDistance` のメソッド `pairwise_into(&left, &right, options, &mut output, &mut ws, cx)` が行優先の $n_\ell \times n_r$ 配列に書く。
左の点 $i$ と右の点 $j$ の距離は `output[i * n_r + j]` にある。
メソッド `pairwise(&left, &right)` は同じ値を `scioxide-linalg` の行優先の行列 `Matrix` に入れて返す簡易 API で、既定の選択肢で呼び出し元のスレッドで逐次に動く。
Euclid 距離の行列は関数 `pairwise(&left, &right)` でも求まる。

同じ点集合（$n$ 点）の中の距離行列は対称で対角が 0 なので、$i < j$ の対だけを行ごとに並べた圧縮表現（condensed distance vector）で持てば、長さは $n(n - 1)/2$ で足りる。
対の順序は $(0, 1), (0, 2), \ldots, (0, n - 1), (1, 2), \ldots$ で、対 $(i, j)$ の位置は

$$
k(i, j) = \frac{n(n - 1)}{2} - \frac{(n - i)(n - i - 1)}{2} + (j - i - 1)
$$

である。
第 1 項は全長、第 2 項は行 $i$ から後ろの対の数で、その差が行 $i$ より前の対の数になる。
`condensed_len(n)` は長さを、`condensed_index(n, i, j)` は位置を返し、$i < j < n$ でなければ `InvalidInput`、`usize` に収まらなければ `SizeOverflow` を返す。
`PreparedDistance` のメソッド `condensed_into(&points, options, &mut output, &mut ws, cx)` は圧縮表現を直接書き、メソッド `condensed(&points)` と Euclid 距離の関数 `condensed(&points)` は圧縮表現を `Vec` で返す。
`condensed_to_square_into` は圧縮表現を $n \times n$ の行優先の配列に広げ、`condensed_to_square(n, &values)` は同じ値を `Matrix` で返す。
`square_to_condensed_into` は行列を検証してから上三角を圧縮表現に写し、`square_to_condensed(matrix, tolerance)` は同じ値を `Vec` で返す。
割り当てて返す形はどれも既定の選択肢で逐次に動く。

外から受け取った配列は次の 2 つの関数で検証できる。
`validate_condensed(n, values)` は長さが $n(n - 1)/2$ でなければ `InvalidInput`、負か非有限の値があれば `DomainError` を返す。
`validate_distance_matrix(matrix, tolerance)` は正方でなければ `DimensionMismatch`、非有限の値は `NonFinite` を返す。
さらに、負の値と、絶対許容誤差 `tolerance` を超える非対称や対角の値を `DomainError` で拒む。
どちらも三角不等式は調べない。

対の計算は 256 対ずつの塊で進む。
`Euclidean`（$p = 2$ の `Minkowski` を含む）、`SquaredEuclidean`、`CityBlock`、`Chebyshev` を行が連続した配置で計算するときは、塊の中を対ごとの検査なしで計算し、桁あふれ、非正規化数の 2 乗和、座標の異なる対の 0 がないかを塊の終わりで 1 回だけ調べる。
検査に通らない塊は対ごとに完全な検査をする計算でやり直す。
ほかの距離とストライドのある配置は、はじめから対ごとに検査して計算する。
どの経路でも演算の順序は同じなので、配置によって結果のビットは変わらない。

次のセルはシード $s$ の乱数で単位正方形に $n$ 点を置き、選んだ距離で全点対の距離を 3 通りに求める。
`PreparedDistance::pairwise` の行列、`PreparedDistance::condensed_into` の圧縮表現、それを `condensed_to_square_into` で広げた行列である。
1 つ目の表は代表的な対について、`condensed_index` と閉形式の位置、圧縮表現の値、`f64` の標準関数で別に計算した参照値を並べる。
2 つ目の表は全点対について、3 つの配列の差の最大値、参照値との相対差の最大値、位置の不一致の数を示す。
Mahalanobis 距離（[標準化 Euclid 距離と Mahalanobis 距離](oxref:spatial-standardized-mahalanobis)）では $V^{-1} = \begin{pmatrix} 4 & 1.2 \\ 1.2 & 1 \end{pmatrix}$ を使い、参照値は $\sqrt{\delta^\mathsf{T} V^{-1} \delta}$ を Cholesky 分解なしで直接求める。
$\delta$ は 2 点の座標の差である。

```rust
//| id: spatial-pairwise-condensed
//| ref: spatial-pairwise-condensed
//| title: 全点対の距離の圧縮表現、添字、行列への展開を参照値と照合する
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg, scioxide-random, scioxide-spatial]
//| inputs:
//|   point_count: {"type":"range","label":"点の数 n","min":2,"max":40,"step":1,"value":6}
//|   metric: {"type":"select","label":"距離","options":[{"value":"euclidean","label":"Euclidean"},{"value":"cityblock","label":"CityBlock"},{"value":"chebyshev","label":"Chebyshev"},{"value":"minkowski3","label":"Minkowski(3)"},{"value":"mahalanobis","label":"Mahalanobis"}],"value":"euclidean"}
//|   seed: {"type":"range","label":"乱数のシード s","min":1,"max":50,"step":1,"value":7}
//| cases:
//|   - {"id":"mahalanobis","label":"Mahalanobis","description":"Cholesky 因子による評価が、逆共分散の 2 次形式の参照値と丸めの範囲で一致する。","inputs":{"metric":"mahalanobis"}}
//|   - {"id":"many-points","label":"n = 40、Chebyshev","description":"圧縮表現の長さは 780 で、最後の対 (38, 39) の位置は 779 になる。","inputs":{"point_count":40,"metric":"chebyshev"}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"pairs","path":"/rows/1/2","equals":4}
//|       - {"artifact":"pairs","path":"/rows/2/2","equals":14}
//|       - {"artifact":"pairs","path":"/rows/2/6","range":{"max":1e-15}}
//|       - {"artifact":"summary","path":"/rows/0/0","equals":15}
//|       - {"artifact":"summary","path":"/rows/0/2","range":{"max":0}}
//|       - {"artifact":"summary","path":"/rows/0/3","range":{"max":1e-15}}
//|       - {"artifact":"summary","path":"/rows/0/4","equals":0}
//|   - case: mahalanobis
//|     expect:
//|       - {"artifact":"pairs","path":"/rows/0/4","approx":{"value":1.4349010886427962,"rtol":1e-14}}
//|       - {"artifact":"summary","path":"/rows/0/3","range":{"max":1e-15}}
//|   - case: many-points
//|     expect:
//|       - {"artifact":"pairs","path":"/rows/2/2","equals":779}
//|       - {"artifact":"summary","path":"/rows/0/0","equals":780}
//|       - {"artifact":"summary","path":"/rows/0/4","equals":0}
use scioxide_core::{ExecutionContext, NdView, StridedLayout};
use scioxide_linalg::Matrix;
use scioxide_random::{SeedableRng, SplitMix64, fill_uniforms};
use scioxide_spatial::{
    DistanceMetric, DistanceOptions, DistanceWorkspace, DistanceWorkspaceRequest, PointSet,
    PreparedDistance, condensed_index, condensed_len, condensed_to_square_into,
};

// 単位正方形の一様な点 n 個（1 行 1 点）。
let n = point_count as usize;
let mut coordinates = vec![0.0_f64; 2 * n];
let mut draws = 0;
let mut rng = SplitMix64::from_seed(seed as u64);
fill_uniforms(&mut rng, &mut coordinates, &mut draws).map_err(|e| e.to_string())?;
let (shape, strides) = ([n, 2], [2, 1]);
let layout = StridedLayout::new(&shape, &strides).map_err(|e| e.to_string())?;
let view = NdView::new(&coordinates, layout).map_err(|e| e.to_string())?;
let points = PointSet::new(view).map_err(|e| e.to_string())?;

// 逆共分散 V⁻¹（Mahalanobis の場合だけ使う）。
let inverse = [[4.0, 1.2], [1.2, 1.0]];
let dist = match metric.as_str() {
    "cityblock" => PreparedDistance::new(DistanceMetric::CityBlock),
    "chebyshev" => PreparedDistance::new(DistanceMetric::Chebyshev),
    "minkowski3" => PreparedDistance::new(DistanceMetric::Minkowski(3.0)),
    "mahalanobis" => {
        let values = vec![inverse[0][0], inverse[0][1], inverse[1][0], inverse[1][1]];
        let matrix = Matrix::from_vec(2, 2, values).map_err(|e| e.to_string())?;
        PreparedDistance::mahalanobis(&matrix)
    }
    _ => PreparedDistance::new(DistanceMetric::Euclidean),
}
.map_err(|e| e.to_string())?;
// 参照値: f64 の標準関数で定義式を直接計算する（Cholesky 分解を使わない）。
let reference = |i: usize, j: usize| {
    let (dx, dy) = (
        coordinates[2 * i] - coordinates[2 * j],
        coordinates[2 * i + 1] - coordinates[2 * j + 1],
    );
    match metric.as_str() {
        "cityblock" => dx.abs() + dy.abs(),
        "chebyshev" => dx.abs().max(dy.abs()),
        "minkowski3" => (dx.abs().powi(3) + dy.abs().powi(3)).powf(1.0 / 3.0),
        "mahalanobis" => {
            (inverse[0][0] * dx * dx + 2.0 * inverse[0][1] * dx * dy + inverse[1][1] * dy * dy)
                .sqrt()
        }
        _ => dx.hypot(dy),
    }
};

// pairwise の行列、condensed_into の圧縮表現、それを広げた行列。
let options = DistanceOptions::new();
let square = dist.pairwise(&points, &points).map_err(|e| e.to_string())?;
let square = square.as_slice();
let length = condensed_len(n).map_err(|e| e.to_string())?;
let mut condensed = vec![0.0_f64; length];
let request = DistanceWorkspaceRequest::condensed(n, options);
let mut ws = DistanceWorkspace::<f64>::workspace(request).map_err(|e| e.to_string())?;
let context = ExecutionContext::sequential();
dist.condensed_into(&points, options, &mut condensed, &mut ws, context)
    .map_err(|e| e.to_string())?;
let mut restored = vec![0.0_f64; n * n];
let request = DistanceWorkspaceRequest::square(n, options);
let mut ws = DistanceWorkspace::<f64>::workspace(request).map_err(|e| e.to_string())?;
condensed_to_square_into(n, &condensed, options, &mut restored, &mut ws, context)
    .map_err(|e| e.to_string())?;

// 全点対で、3 つの配列の一致、閉形式の位置、参照値との相対差を調べる。
let (mut layout_gap, mut reference_gap, mut misplaced) = (0.0_f64, 0.0_f64, 0_usize);
for i in 0..n {
    for j in i + 1..n {
        let k = condensed_index(n, i, j).map_err(|e| e.to_string())?;
        misplaced += usize::from(k != length - (n - i) * (n - i - 1) / 2 + (j - i - 1));
        let value = condensed[k];
        for other in [square[i * n + j], restored[i * n + j], restored[j * n + i]] {
            layout_gap = layout_gap.max((other - value).abs());
        }
        reference_gap = reference_gap.max((value - reference(i, j)).abs() / reference(i, j));
    }
}
let mut sample = vec![(0, 1), (0, n - 1), (n - 2, n - 1)];
sample.dedup();
let mut rows = Vec::new();
for (i, j) in sample {
    let k = condensed_index(n, i, j).map_err(|e| e.to_string())?;
    let closed = length - (n - i) * (n - i - 1) / 2 + (j - i - 1);
    let (value, exact) = (condensed[k], reference(i, j));
    rows.push((i, j, k, closed, value, exact, (value - exact).abs() / exact));
}
let fixed6 = serde_json::json!({ "fractionDigits": 6 });
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let pair_columns = serde_json::json!([
    { "key": "0", "label": "i", "type": "integer" },
    { "key": "1", "label": "j", "type": "integer" },
    { "key": "2", "label": "condensed_index", "type": "integer" },
    { "key": "3", "label": "閉形式 k(i, j)", "type": "integer" },
    { "key": "4", "label": "圧縮表現の値 [-]", "type": "number", "format": fixed6 },
    { "key": "5", "label": "参照値 [-]", "type": "number", "format": fixed6 },
    { "key": "6", "label": "相対差 [-]", "type": "number", "format": sci3 }
]);
emit_table_with_columns!(
    pair_columns,
    rows,
    metadata = serde_json::json!({ "id": "pairs" })
);
let summary_columns = serde_json::json!([
    { "key": "0", "label": "圧縮表現の長さ", "type": "integer" },
    { "key": "1", "label": "閉形式 n(n − 1)/2", "type": "integer" },
    { "key": "2", "label": "3 つの配列の差の最大 [-]", "type": "number", "format": sci3 },
    { "key": "3", "label": "参照値との相対差の最大 [-]", "type": "number", "format": sci3 },
    { "key": "4", "label": "位置の不一致 [件]", "type": "integer" }
]);
let summary = vec![(
    length,
    n * (n - 1) / 2,
    layout_gap,
    reference_gap,
    misplaced,
)];
emit_table_with_columns!(
    summary_columns,
    summary,
    metadata = serde_json::json!({ "id": "summary" })
);
```

既定値（$n = 6$、Euclid 距離、$s = 7$）では、圧縮表現の長さは 15 で、対 $(0, 5)$ は位置 4、最後の対 $(4, 5)$ は位置 14 にあり、`condensed_index` は閉形式と全点対で一致する。
3 つの配列はビットまで一致し、参照値との相対差の最大は $2.2 \times 10^{-16}$ で、単位丸め誤差 $2^{-53} \approx 1.1 \times 10^{-16}$ の 2 倍程度である。
Mahalanobis 距離でも、Cholesky 因子による値と 2 次形式の参照値の相対差は $3 \times 10^{-16}$ 程度に収まる。
$n = 40$ では長さ 780 の圧縮表現が、同じ情報を持つ 1600 要素の正方行列の半分以下のメモリ領域で済む。

## 作業領域と出力への反映

対ごとの距離と行列の変換は、作業領域 `DistanceWorkspace<S>` に結果を書いてから、全結果がそろった後で出力へ写す。
そのため、途中で失敗しても出力は書き換わらない（失敗時の出力の規則は[エラー仕様と部分結果](../../../concepts/errors-and-partial-results/)にある）。
出力が必要な長さより長ければ、その先の要素は変えない。

作業領域の大きさは計算の種類と点の数を表す `DistanceWorkspaceRequest` から決まる。
`DistanceWorkspaceRequest::pairwise(n_l, n_r, options)` は $n_\ell n_r$、`condensed(n, options)` は $n(n - 1)/2$、`square(n, options)` は $n^2$ 個の値を要求する。
`condensed` の要求は `condensed_into` と `square_to_condensed_into` に、`square` の要求は `condensed_to_square_into` に使う。
`DistanceWorkspace::<S>::workspace_requirements(request)` はこの要求から `DistanceWorkspaceRequirements` を返し、`scalar_len()` が値の数、`bytes::<S>()` がバイト数を返す。
`DistanceWorkspace::<S>::workspace(request)` はその大きさを割り当てた作業領域を返し、`new()` は割り当てない空の作業領域を返す。
`check(&requirements)` は足りるかを `Capacity` で返し、`try_reserve(&requirements)` は以前の容量を保ったまま広げる。
`try_reserve` が失敗したときは新しい容量の一部が残っていることがあるので、使う前にもう一度事前確保する。
事前確保の手順と `Capacity` の意味は[実行形式・作業領域・再現性](../../../concepts/workspaces-and-reproducibility/)にまとめてある。
計算そのものは作業領域を広げず、足りなければ `DimensionMismatch` を返す。

`DistanceOptions` は実行の方針とバイト数の上限を持ち、`DistanceOptions::new()` は逐次の実行と上限なしを選ぶ。
`with_max_workspace_bytes(bytes)` は作業領域が保持してよいバイト数の上限で、以前の大きな事前確保で残った容量も数え、超えると `ResourceLimit` を返す。
`with_execution_policy(ExecutionPolicy::Auto)` では、出力が 256 個以上で、ワーカー 1 つあたりの計算量がエグゼキューターの最小の計算量以上になるときに並列に動く。
計算量は $d$ 次元の 1 対あたり $d$（Mahalanobis は $d^2$、Jensen–Shannon は $16d$）、行列の変換は 1 要素あたり 1 と見積もる。
取り消しと期限は少なくとも 256 対ごとと、出力を書く直前に調べる。
wasm で動くセルは逐次で、`Auto` でも並列にはならない。

次のセルは 4 点の正方形 $(0, 0), (1, 0), (1, 1), (0, 1)$ を使い、作業領域の大きさと、失敗したときの出力を確かめる。
1 つ目の表は 3 種類の要求の値の数とバイト数（`f64`）を閉形式と比べる。
2 つ目の表は失敗する操作を順に試し、エラーの分類と、出力（あらかじめ $-1$ で埋めておく）が変わらなかったかを示す。
作業領域の要求と検証の関数は出力を書かないので、その行の最後の列は「出力なし」になる。
入力は正方形の距離行列の $(0, 1)$ 要素に加える非対称のずれ $10^{a}$ で、`square_to_condensed_into` の絶対許容誤差 $10^{-12}$ と比べる。

```rust
//| id: spatial-distance-workspace-errors
//| ref: spatial-distance-workspace-errors
//| title: 作業領域の大きさと、失敗したときに変わらない出力
//| run: reactive
//| crates: [scioxide-core, scioxide-linalg, scioxide-spatial]
//| inputs:
//|   asymmetry_exponent: {"type":"range","label":"非対称のずれの指数 a（ずれ = 10^a）[-]","min":-16,"max":-6,"step":1,"value":-10}
//| cases:
//|   - {"id":"within-tolerance","label":"a = −14","description":"ずれが許容誤差 10⁻¹² 以下なので、行列は受理され、上三角が圧縮表現に写る。","inputs":{"asymmetry_exponent":-14}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"requests","path":"/rows/0/1","equals":12}
//|       - {"artifact":"requests","path":"/rows/1/1","equals":6}
//|       - {"artifact":"requests","path":"/rows/2/3","equals":128}
//|       - {"artifact":"publication","path":"/rows/0/1","equals":"DomainError"}
//|       - {"artifact":"publication","path":"/rows/0/2","equals":true}
//|       - {"artifact":"publication","path":"/rows/1/1","equals":"DimensionMismatch"}
//|       - {"artifact":"publication","path":"/rows/1/2","equals":true}
//|       - {"artifact":"publication","path":"/rows/2/1","equals":"DimensionMismatch"}
//|       - {"artifact":"publication","path":"/rows/3/1","equals":"ResourceLimit"}
//|       - {"artifact":"publication","path":"/rows/4/1","equals":"DomainError"}
//|       - {"artifact":"publication","path":"/rows/5/1","equals":"InvalidInput"}
//|   - case: within-tolerance
//|     expect:
//|       - {"artifact":"publication","path":"/rows/0/1","equals":"受理"}
//|       - {"artifact":"publication","path":"/rows/0/2","equals":false}
use scioxide_core::{ExecutionContext, SciOxideError, NdView, StridedLayout};
use scioxide_linalg::Matrix;
use scioxide_spatial::DistanceWorkspaceRequest as Request;
use scioxide_spatial::{
    DistanceMetric, DistanceOptions, DistanceWorkspace, PointSet, PreparedDistance,
    square_to_condensed_into, validate_condensed,
};

let classify = |result: Result<(), SciOxideError>| match result {
    Ok(()) => "受理".to_string(),
    Err(error) => format!("{:?}", error.kind()),
};
let options = DistanceOptions::new();
let context = ExecutionContext::sequential();

// 作業領域の要求: 値の数とバイト数（f64）。
let requests = [
    ("pairwise(4, 3)", Request::pairwise(4, 3, options), 12),
    ("condensed(4)", Request::condensed(4, options), 6),
    ("square(4)", Request::square(4, options), 16),
];
let mut sizes = Vec::new();
for (label, request, closed) in requests {
    let requirements =
        DistanceWorkspace::<f64>::workspace_requirements(request).map_err(|e| e.to_string())?;
    let bytes = requirements.bytes::<f64>().map_err(|e| e.to_string())?;
    sizes.push((label, requirements.scalar_len(), closed, bytes));
}
let size_columns = serde_json::json!([
    { "key": "0", "label": "要求" },
    { "key": "1", "label": "scalar_len", "type": "integer" },
    { "key": "2", "label": "閉形式", "type": "integer" },
    { "key": "3", "label": "バイト数 [B]", "type": "integer" }
]);
emit_table_with_columns!(
    size_columns,

// 失敗する操作を順に試す。出力は −1 で埋めておき、失敗後に変わらないかを見る。
let corners = [0.0_f64, 0.0, 1.0, 0.0, 1.0, 1.0, 0.0, 1.0];
let (shape, strides) = ([4, 2], [2, 1]);
let layout = StridedLayout::new(&shape, &strides).map_err(|e| e.to_string())?;

let euclid = PreparedDistance::new(DistanceMetric::Euclidean).map_err(|e| e.to_string())?;

// 1. 非対称な行列を許容誤差 10⁻¹² で圧縮表現に写す。
let r2 = 2.0_f64.sqrt();
let mut square = vec![0.0, 1.0, r2, 1.0, 1.0, 0.0, 1.0, r2];
square.extend([r2, 1.0, 0.0, 1.0, 1.0, r2, 1.0, 0.0]);
square[1] += 10.0_f64.powf(asymmetry_exponent);
let matrix = Matrix::from_vec(4, 4, square).map_err(|e| e.to_string())?;
let mut out = vec![-1.0; 6];
let result = square_to_condensed_into(&matrix, 1e-12, options, &mut out, &mut ws, context);
let asymmetric = (classify(result), Some(unchanged(&out)));
// 2. 出力が 6 より短い。
let mut short = vec![-1.0; 5];

let short_output = (classify(result), Some(unchanged(&short)));
// 3. 3 点用に事前確保した作業領域で 4 点を計算する。
let mut small = DistanceWorkspace::<f64>::workspace(Request::condensed(3, options))

let mut out = vec![-1.0; 6];
```

1 つ目の表で、4 点の圧縮表現は 6 個、つまり `f64` で 48 B を要求する。
2 つ目の表では、既定のずれ $10^{-10}$ が許容誤差 $10^{-12}$ を超えるので変換は `DomainError` で拒まれ、出力の 6 個の値は $-1$ のまま残る。
$a = -14$ ではずれが許容誤差の内側に入り、変換は受理されて出力が書き換わる。
出力や作業領域が短い場合は `DimensionMismatch` で、出力に触れない。
バイト数の上限を超える要求は、作業領域を割り当てる前に `ResourceLimit` で拒まれる。

## まとめ

全点対の距離は `pairwise_into` で行優先の $n_\ell \times n_r$ 配列に書き、同じ点集合なら `condensed_into` で長さ $n(n - 1)/2$ の圧縮表現に書けば、正方行列の半分以下のメモリ領域で済む。
圧縮表現の中の対 $(i, j)$ の位置は `condensed_index` で求まり、閉形式 $k(i, j)$ と一致する。
外から受け取った配列は `validate_condensed` と `validate_distance_matrix` で検証できるが、三角不等式は調べないので、距離の公理が要る処理では呼び出し側で確かめる。
繰り返し計算するときは要求から作業領域の大きさを決めて 1 回事前確保すれば、計算は割り当てを行わず、失敗しても出力は書き換わらない。
