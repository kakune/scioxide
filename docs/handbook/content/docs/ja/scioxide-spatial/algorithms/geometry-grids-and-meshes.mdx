差分法・有限体積法・有限要素法は領域を格子やメッシュに分け、その頂点・セル・面・辺に未知数を置く。
同じ配列でも、頂点に置いた値とセルに置いた値では長さも意味も違い、取り違えると計算は誤った結果を返すか、長さの不一致で止まる。
細分したメッシュに古いメッシュの値を組み合わせても、同じ種類の誤りが起こる。
このページは点と添字の番号付け、構造格子の座標軸と周期軸、セルメッシュのトポロジー、位置を型に持つ場、メッシュの世代を順に説明する。
区間・三角形・四面体の単体メッシュは[単体メッシュ](../simplex-meshes/)で扱う。
どの規則も、配列の長さと番号付け、隣接関係、値が属するメッシュを、計算の前に一意に決めるためにある。

## 点・範囲・多重添字

`Point<S, D>` は $D = 1, 2, 3$ 次元の点で、座標を固定長配列 `[S; D]` で持つ。
スカラー型 `S` は[`RealScalar`](../../../scioxide-core/api/scalars-and-values/)（`f32` か `f64`）で、別名 `Point1`、`Point2`、`Point3` がある。
`Point::new` は全座標が有限であることを確かめ、NaN や無限大があれば `NonFinite` を返す。
$D$ が 1〜3 でなければ `InvalidInput` になる。

`Extent<D>` は添字空間の各軸の長さ $[n_0, \ldots, n_{D-1}]$、`Index<D>` はその中の多重添字 $[i_0, \ldots, i_{D-1}]$ で、別名 `Extent1`〜`Extent3`、`Index1`〜`Index3` がある。
長さ 0 の軸も許され、そのときの範囲は空である。
多重添字の線形位置は軸 0 が最も速く変わる順序で、3 次元では

$$
\ell(i_0, i_1, i_2) = i_0 + n_0\,\bigl(i_1 + n_1\, i_2\bigr)
$$

である。
これは最初の添字が最も速く変わる列優先（Fortran）の順序で、最後の添字が最も速く変わる行優先（C）の順序とは逆である。
`linearize` は成分が範囲外なら `OutOfBounds`、位置が `usize` に収まらなければ `SizeOverflow` を返す。
桁あふれを調べるのは $\ell$ だけで、全要素数 $\prod_a n_a$ が `usize` に収まる必要はない。
逆写像 `delinearize` と要素数 `element_count` は、全要素数が収まらなければ `SizeOverflow` を返す。
格子の頂点・セル・面・辺と、それらの上の場の値は、すべてこの順序で並ぶ。

## 座標軸と構造格子

`CoordinateAxis<S>` は 1 本の軸の格子点の列で、座標はすべて有限で、狭義に増加するか狭義に減少する。
向きは `orientation()` が `AxisOrientation::Increasing` か `Decreasing` で返す。

`CoordinateAxis::uniform(start, end, count)` は等間隔の軸で、両端と点数だけを保持する。
第 $i$ 点は $x_i = \mathrm{start} + (\mathrm{end} - \mathrm{start})\, i/(\mathrm{count} - 1)$ を正しく丸めた値で、両端は与えた値そのものになる。
丸めた後も狭義単調であるように、両端は相異なり、点数は 2 以上で、間隔は $|\mathrm{end} - \mathrm{start}| \ge (\mathrm{count} - 1)\,u$ を満たす必要がある。
ここで $u$ は絶対値の大きい方の端点から 0 に向かって隣の浮動小数点数までの距離である。
この条件は点数によらず $O(1)$ で確かめられ、満たさなければ `InvalidInput`、端点が NaN か無限大なら `NonFinite` になる。
`CoordinateAxis::explicit(coordinates)` は不等間隔の軸で、全座標を保持する。
2 点未満、等しい 2 点、向きの反転は `InvalidInput`、NaN や無限大の座標は `NonFinite` で拒む。
どちらの軸も第 $i$ 点を $O(1)$ で返す。

`locate(x)` は二分探索で $x$ を含む区間を $O(\log n)$ で探し、区間番号 $i$ と区間内の相対位置

$$
\theta = \frac{x - x_i}{x_{i+1} - x_i}
$$

を `IntervalLocation` で返す。
区間は格子点の順に半開で、格子点はそこから始まる区間に属するので、$\theta$ はふつう $[0, 1)$ にある。
ただし最後の格子点は最後の区間に属し、そのとき $\theta$ はちょうど 1 になる。
閉区間の外の $x$ は `DomainError`、NaN や無限大の $x$ は `NonFinite` になる。

`StructuredGrid<S, D>`（別名 `Grid1d`、`Grid2d`、`Grid3d`）は $D$ 本の軸の直積で、頂点は各軸の格子点の組、セルは各軸の区間の組である。
頂点の範囲は各軸の点数、セルの範囲はそれより 1 少ない区間数で、どちらも上の列優先の順序で番号を付ける。
各軸には `AxisTopology` を 1 つ与え、`Bounded` なら最初と最後の格子点は別々の境界になる。
`Periodic` なら最初と最後の格子点を周期 $|\mathrm{end} - \mathrm{start}|$ の継ぎ目で同一視するが、2 点は別の頂点のまま残り、互いの対として扱われる。
そのため頂点・セル・面・辺の数は、軸が周期かどうかによらない。
`StructuredGrid::uniform(start, end, counts)` は、各軸を `CoordinateAxis::uniform(start[i], end[i], counts[i])` とした `Bounded` の格子を作り、`CellMesh::uniform` はその格子のセルメッシュを作る。
境界の側は `AxisSide::Start`（最初の格子点の側）か `End`（最後の格子点の側）で指定し、座標の大小とは関係しない。

格子の `locate(point)` は各軸で `CoordinateAxis::locate` を使い、セルの多重添字と各軸の相対位置を `CellLocation` で返す。
周期軸の座標は自動では折り返さない。
`wrap_point` は周期軸の座標を周期で軸の範囲へ移し、`locate_wrapped` は折り返してから探す。
有界軸で範囲の外にある座標は、どちらの方法でも `DomainError` になる。

`refined(factors)` は軸 $a$ の各区間を `factors[a]` 等分した格子を返す。
等間隔の軸は点数を増やした等間隔の軸になり、不等間隔の軸は元の格子点をそのまま残して間に点を加える。
因子に 0 があるときと、加えた点が丸めの後で狭義単調にならないときは `InvalidInput` になる。
`with_axis` は 1 本の軸を差し替えた格子を返す。
どちらも後で述べるメッシュの世代を 1 つ進めるが、全因子が 1 の `refined` は格子を変えないので世代も変えない。

## セルメッシュのトポロジーと境界

`CellMesh<S, D>` は構造格子の上の線分・四辺形・六面体のメッシュで、別名を `SegmentMesh`、`QuadMesh`、`HexMesh` という。
セルの形は `cell_kind()` が `CellKind::Segment`、`Quadrilateral`、`Hexahedron` で返す。
メッシュは接続表を持たず、頂点・セル・面の接続を添字の算術でそのつど求める。
`cell_vertices`、`vertex_cells`、`cell_faces`、`face_cells`、`cell_neighbors`、`axis_boundary_faces` は `impl Iterator` を返し、反復は割り当てを行わない。
メッシュのメモリ領域は格子の分だけで、等間隔の軸では点の数によらず、不等間隔の軸では座標の数に比例する。

面は `FaceIndex<D>` で、法線の軸 $a$ と位置の組で表す。
軸 $b$ のセル数を $n_b$ とする。
位置の成分は法線の軸では頂点の並ぶ平面の番号（$0, \ldots, n_a$）、ほかの軸ではセルの番号である。
`TopologySizes` が返す要素数は次のとおりである。

$$
N_{\mathrm{vertex}} = \prod_{b}(n_b + 1), \quad
N_{\mathrm{cell}} = \prod_{b} n_b, \quad
N_{\mathrm{face}}^{(a)} = (n_a + 1)\prod_{b \ne a} n_b, \quad
N_{\mathrm{edge}}^{(a)} = n_a \prod_{b \ne a}(n_b + 1)
$$

$N_{\mathrm{face}}^{(a)}$ は軸 $a$ に垂直な面の数（`faces_normal_to(a)`）、$N_{\mathrm{edge}}^{(a)}$ は軸 $a$ に平行な辺の数（`edges_along(a)`）である。
ほかに面と辺の総数（`faces()`、`edges()`）と、セルから頂点への接続の数 $2^D N_{\mathrm{cell}}$（`cell_vertex_incidences()`）、セルから面への接続の数 $2D\,N_{\mathrm{cell}}$（`cell_face_incidences()`）を返す。
2 次元では、x に垂直な面と y に平行な辺は同じ線分の集合である。

`face_topology(face)` は面の位相を `FaceTopology` で返す。
`Interior` は 2 つのセルを隔てる内部の面、`Exterior { side }` は有界軸の端の面である。
`Periodic { side, paired }` は周期軸の端の面で、`paired` は継ぎ目の反対側にある対の面を指す。
継ぎ目の面の `face_cells` は継ぎ目の両側のセルを返し、継ぎ目の頂点の `vertex_cells` も両側のセルを返す。
周期軸の `cell_neighbors` は最初と最後のセルを隣とするが、軸のセルが 1 つだけならそのセルを自分の隣にはしない。

`BoundarySet<D>` は境界条件を課す面の集合で、外側の面と継ぎ目の面だけを、昇順に重複なく持つ。
`BoundarySet::axis_side(&mesh, a, side)` は軸 $a$ の一方の端の面をすべて集める。
`BoundarySet::new` に内部の面か重複した面を渡すと `InvalidInput`、範囲外の面を渡すと `OutOfBounds` になる。
集合は作ったメッシュのトークン（後述）を持ち、渡したメッシュが作ったときと同じ revision かを `is_compatible_with` で $O(1)$ で確かめられる。

## 位置を型で保証する場

`Field<T, L, D>` はメッシュの位置 `L` の各要素に値を 1 つずつ置いた不変の配列で、値の型 `T` は座標の型と独立である。
位置は型の一部なので、`Field<T, Cell, D>` を受け取る関数に頂点や面の値を渡すとコンパイルが通らない。
位置の型と別名は次のとおりである。

| 位置 `L` | 要素 | 別名 | 使えるメッシュ |
|---|---|---|---|
| `Vertex` | 頂点 | `VertexField<T, D>` | `CellMesh`、`SimplexMesh`、`AdaptiveMesh` |
| `Cell` | セル | `CellField<T, D>` | `CellMesh`、`SimplexMesh`、`AdaptiveMesh` |
| `Face<A>` | 軸 $A$ に垂直な面 | `FaceField<T, D, A>` | `CellMesh` |
| `Edge<A>` | 軸 $A$ に平行な辺 | `EdgeField<T, D, A>` | `CellMesh` |
| `UnstructuredFace` | すべての面 | `UnstructuredFaceField<T, D>` | `SimplexMesh`、`AdaptiveMesh` |
| `UnstructuredEdge` | すべての辺 | `UnstructuredEdgeField<T, D>` | `SimplexMesh`、`AdaptiveMesh` |

`FieldLocation` は `CellMesh` 上の位置を、`MeshEntities` はメッシュと位置の組み合わせを表すトレイトである。
どちらも外部からの実装を許可していないため、利用者が新しい位置や組み合わせを加えることはできない。
単体メッシュの軸に垂直な面のように意味のない組み合わせはトレイトを実装していないので、その場はコンパイルされない。
`Face<A>` と `Edge<A>` で $A \ge D$ の場合だけは実行時に調べ、`OutOfBounds` を返す。

場は `Field::new(&mesh, values)` か `Field::from_fn(&mesh, f)` で作り、値の数が要素数と違えば `DimensionMismatch` になる。
`from_fn` は要素の線形位置 $i$ ごとに `f(i)` を呼ぶ。
値の数は `Field::required_len(&mesh)` で前もって求められる。
`try_map` は同じメッシュと位置の新しい場を返し、`try_zip_map` は 2 つの場の対応する値を組み合わせる。
`try_zip_map` は 2 つの場が同じメッシュの同じ revision に属さなければ `InvalidInput` を返す（revision は後で定義する）。

`FieldView<'a, T, L, D>` は呼び出し側のスライスを借りる場である。
`FieldView::new` は値の数を確かめてメッシュのトークンを借用し、`to_owned` は値とトークンを複製して `Field` を作る。
`Field` の `clone` は値を共有するので $O(1)$ である。

## 周期格子の場と継ぎ目の確認

次のセルは $[0, 1] \times [0, 1]$ m の 2 次元格子を、x 方向 $n_x$ 個、y 方向 $n_y$ 個のセルで作る。
y 軸は有界で、x 軸は入力で周期か有界を選ぶ。
1 つ目の表は各位置の場の長さを `TopologySizes` と閉形式の要素数に比べ、周期軸でも数が変わらないことを確かめる。
2 つ目の表は x の両端の面と y の端の面の `FaceTopology`、継ぎ目の対、面に接するセルを示す。
3 つ目の表は角のセル $[0, 0]$ の隣、角の頂点を含むセル、点 $(1.1, 0.5)$ m を `locate_wrapped` で探した結果、x の始端の境界集合の大きさで、前の 3 つは周期軸かどうかで変わる。

```rust
//| id: spatial-grid-field-topology
//| ref: spatial-grid-field-topology
//| title: 周期軸を持つ 2 次元格子の場の長さ、継ぎ目、メッシュの照合
//| run: reactive
//| crates: [scioxide-core, scioxide-spatial]
//| inputs:
//|   cells_x: {"type":"range","label":"x 方向のセル数 nₓ","min":1,"max":8,"step":1,"value":4}
//|   cells_y: {"type":"range","label":"y 方向のセル数 n_y","min":1,"max":8,"step":1,"value":3}
//|   periodic_x: {"type":"checkbox","label":"x 軸を周期軸にする","value":true}
//| cases:
//|   - {"id":"bounded","label":"x 軸も有界","description":"要素数は同じで、x の端の面が Exterior になり、角のセルの隣が 1 つ減る。","inputs":{"periodic_x":false}}
//|   - {"id":"single-cell","label":"nₓ = 1（周期）","description":"周期軸のセルが 1 つなら、そのセルは自分の隣にならない。","inputs":{"cells_x":1}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"counts","path":"/rows/0/1","equals":20}
//|       - {"artifact":"counts","path":"/rows/2/1","equals":15}
//|       - {"artifact":"counts","path":"/rows/2/3","equals":15}
//|       - {"artifact":"faces","path":"/rows/0/1","equals":"Periodic { side: Start }"}
//|       - {"artifact":"faces","path":"/rows/0/2","equals":"[4, 0]"}
//|       - {"artifact":"incidence","path":"/rows/0/1","equals":3}
//|       - {"artifact":"incidence","path":"/rows/2/2","equals":"[0, 1]"}
//|   - case: bounded
//|     expect:
//|       - {"artifact":"counts","path":"/rows/0/1","equals":20}
//|       - {"artifact":"faces","path":"/rows/0/1","equals":"Exterior { side: Start }"}
//|       - {"artifact":"faces","path":"/rows/0/2","equals":null}
//|       - {"artifact":"incidence","path":"/rows/0/1","equals":2}
//|       - {"artifact":"incidence","path":"/rows/2/2","equals":"DomainError"}
//|   - case: single-cell
//|     expect:
//|       - {"artifact":"incidence","path":"/rows/0/1","equals":1}
//|       - {"artifact":"faces","path":"/rows/0/3","equals":"[0, 0]"}
use scioxide_spatial::{
    AxisSide, AxisTopology, BoundarySet, CellField, CellMesh, CoordinateAxis, EdgeField,
    FaceField, FaceIndex, FaceTopology, Grid2d, Index, Point, VertexField,
};

let (nx, ny) = (cells_x as usize, cells_y as usize);
let axis_x = CoordinateAxis::uniform(0.0_f64, 1.0, nx + 1).map_err(|e| e.to_string())?;
let axis_y = CoordinateAxis::uniform(0.0_f64, 1.0, ny + 1).map_err(|e| e.to_string())?;
let topology_x = if periodic_x {
    AxisTopology::Periodic
} else {
    AxisTopology::Bounded
};
let topologies = [topology_x, AxisTopology::Bounded];
let grid = Grid2d::new([axis_x, axis_y], topologies).map_err(|e| e.to_string())?;
let mesh = CellMesh::new(grid).map_err(|e| e.to_string())?;
let sizes = mesh.topology_sizes();

// 各位置の場の長さ、TopologySizes の値、閉形式の要素数。
let vertex = VertexField::<f64, 2>::from_fn(&mesh, |_| 0.0).map_err(|e| e.to_string())?;
let cell = CellField::<f64, 2>::from_fn(&mesh, |_| 0.0).map_err(|e| e.to_string())?;
let face_x = FaceField::<f64, 2, 0>::from_fn(&mesh, |_| 0.0).map_err(|e| e.to_string())?;
let face_y = FaceField::<f64, 2, 1>::from_fn(&mesh, |_| 0.0).map_err(|e| e.to_string())?;
let edge_x = EdgeField::<f64, 2, 0>::from_fn(&mesh, |_| 0.0).map_err(|e| e.to_string())?;
let faces_x = sizes.faces_normal_to(0).map_err(|e| e.to_string())?;
let faces_y = sizes.faces_normal_to(1).map_err(|e| e.to_string())?;
let edges_x = sizes.edges_along(0).map_err(|e| e.to_string())?;
let vertices = (nx + 1) * (ny + 1);
let counts = vec![
    ("Vertex", vertex.len(), sizes.vertices(), vertices),
    ("Cell", cell.len(), sizes.cells(), nx * ny),
    ("Face<0>（x に垂直）", face_x.len(), faces_x, (nx + 1) * ny),
    ("Face<1>（y に垂直）", face_y.len(), faces_y, nx * (ny + 1)),
    ("Edge<0>（x に平行）", edge_x.len(), edges_x, nx * (ny + 1)),
];
let count_columns = serde_json::json!([
    { "key": "0", "label": "位置" },
    { "key": "1", "label": "場の長さ", "type": "integer" },
    { "key": "2", "label": "TopologySizes", "type": "integer" },
    { "key": "3", "label": "閉形式", "type": "integer" }
]);
emit_table_with_columns!(
    count_columns,
    counts,
    metadata = serde_json::json!({ "id": "counts" })
);

// 面の位相、継ぎ目の対、面に接するセル。
let show = |index: Index<2>| format!("{:?}", index.as_array());
let probes = [(0, [0, 0]), (0, [nx, 0]), (1, [0, 0]), (1, [0, ny])];
let mut face_rows = Vec::new();
for (normal, position) in probes {
    let face = FaceIndex::new(normal, Index::new(position).map_err(|e| e.to_string())?)
        .map_err(|e| e.to_string())?;
    let (kind, paired) = match mesh.face_topology(face).map_err(|e| e.to_string())? {
        FaceTopology::Interior => ("Interior".to_string(), None),
        FaceTopology::Exterior { side } => (format!("Exterior {{ side: {side:?} }}"), None),
        FaceTopology::Periodic { side, paired } => (
            format!("Periodic {{ side: {side:?} }}"),
            Some(show(paired.index())),
        ),
    };
    let cells = mesh.face_cells(face).map_err(|e| e.to_string())?;
    let cells: Vec<String> = cells.map(show).collect();
    let label = format!("法線 {}、位置 {}", ["x", "y"][normal], show(face.index()));
    face_rows.push((label, kind, paired, cells.join(", ")));
}
let face_columns = serde_json::json!([
    { "key": "0", "label": "面" },
    { "key": "1", "label": "FaceTopology" },
    { "key": "2", "label": "継ぎ目の対", "nullText": "なし" },
    { "key": "3", "label": "接するセル" }
]);
emit_table_with_columns!(
    face_columns,
    face_rows,
    metadata = serde_json::json!({ "id": "faces" })
);

// 角のセルと頂点の接続、周期で折り返した点の位置、境界集合の大きさ。
let listed = |items: Vec<String>| (Some(items.len()), items.join(", "));
let corner = Index::new([0, 0]).map_err(|e| e.to_string())?;
let neighbors = mesh.cell_neighbors(corner).map_err(|e| e.to_string())?;
let neighbors = listed(neighbors.map(show).collect());
let around = mesh.vertex_cells(corner).map_err(|e| e.to_string())?;
let around = listed(around.map(show).collect());
let probe = Point::new([1.1, 0.5]).map_err(|e| e.to_string())?;
let located = match mesh.grid().locate_wrapped(probe) {
    Ok(location) => (None, show(location.cell())),
    Err(error) => (None, format!("{:?}", error.kind())),
};
let boundary = BoundarySet::axis_side(&mesh, 0, AxisSide::Start).map_err(|e| e.to_string())?;
let boundary = listed(boundary.faces().iter().map(|f| show(f.index())).collect());
let incidence: Vec<(&str, Option<usize>, String)> = [
    ("セル [0, 0] の隣", neighbors),
    ("頂点 [0, 0] を含むセル", around),
    ("点 (1.1, 0.5) m の locate_wrapped", located),
    ("x の始端の BoundarySet", boundary),
]
.into_iter()
.map(|(label, (count, text))| (label, count, text))
.collect();
let incidence_columns = serde_json::json!([
    { "key": "0", "label": "問い合わせ" },
    { "key": "1", "label": "個数", "type": "integer", "nullText": "—" },
    { "key": "2", "label": "結果" }
]);
emit_table_with_columns!(
    incidence_columns,
    incidence,
    metadata = serde_json::json!({ "id": "incidence" })
);
```

既定値（$n_x = 4$、$n_y = 3$、x 軸は周期）では、頂点の場は $5 \times 4 = 20$ 個、x に垂直な面の場は $5 \times 3 = 15$ 個で、どの位置でも場の長さ、`TopologySizes`、閉形式が一致する。
x の始端の面 $[0, 0]$ は `Periodic { side: Start }` で、対の面は終端の $[4, 0]$、接するセルは継ぎ目の両側の $[3, 0]$ と $[0, 0]$ である。
角のセル $[0, 0]$ の隣は継ぎ目の向こうの $[3, 0]$ を含む 3 個で、角の頂点を含むセルも 2 個になり、点 $(1.1, 0.5)$ m は x を周期で折り返してセル $[0, 1]$ に入る。
x 軸を有界にすると、要素数の表は変わらないが、x の端の面は `Exterior` になり、角のセルの隣は 2 個、角の頂点を含むセルは 1 個に減り、$(1.1, 0.5)$ m は `DomainError` になる。
$n_x = 1$ の周期軸では、継ぎ目の両側が同じセル $[0, 0]$ なので接するセルは 1 個で、セルは自分の隣にならない。
どの場合も、x の始端の `BoundarySet` は $n_y = 3$ 個の面を持つ。

## メッシュの同一性と世代トークン

新しく作ったメッシュと、その幾何か位相を変えるたびにできる新しいメッシュの 1 つ 1 つを、revisionと呼ぶ。
各 revision は `MeshToken` を持ち、場、境界の集合、境界タグ、トポロジーの対応表は、作ったときのメッシュのトークンを保持する。
トークンは族 `MeshId`、世代 `MeshGeneration`、revision ごとの識別子からなる。
族はあるメッシュとそこから導いた全 revision の集まりで、`MeshId` どうしが等しいのは一方が他方の複製のときだけである。
世代は新しく作ったメッシュでは `MeshGeneration::INITIAL`（0）であり、`refined`、`with_axis`、`with_points`、`with_cells`、`AdaptiveMesh::adapt` などが幾何か位相を変えるたびに 1 つ増える。
変更のない呼び出し（全因子 1 の `refined` など）は同じトークンを返す。

同じ親から 2 回変更すると、どちらの世代も $g + 1$ になるが、revision ごとの識別子が違う。
このような兄弟の revision は、世代が等しくても別の revision として扱われる。
`MeshToken::is_compatible_with` は族、世代、revision の識別子がすべて一致するとき、つまり 2 つのトークンが同じ revision を指すときだけ真を返す。
`ensure_compatible` は同じ判定で、一致しなければ `InvalidInput`（理由は `Inconsistent`）を返す。
`same_family` は族だけを比べる。
比較は参照の一致を見るだけなので $O(1)$ で、座標や接続は読まない。
識別子は実行中のプロセスの中でだけ意味を持ち、保存して別のプロセスで比べることはできない。
`CellMesh::new(grid)` のトークンは格子のトークンそのものなので、同じ格子（とその複製）から作ったメッシュの場は組み合わせられる。

次のセルは $4 \times 4$ セルの格子（x 軸は周期、y 軸は有界）から作った場と、4 通りの相手の場を `try_zip_map` で組み合わせる。
相手は同じ格子から作り直したメッシュ、同じ座標で別に作った格子、x 方向を因子 $r$ で細分した格子、同じ親からもう一度細分した格子である。
表は両方の世代、族が同じか（`same_family`）、revision が同じか（`is_compatible_with`）、組み合わせの結果（受理か、エラーの分類）を示す。
組み合わせが受理されるのは、revision が同じ行だけのはずである。

```rust
//| id: spatial-mesh-token-check
//| ref: spatial-mesh-token-check
//| title: 場を組み合わせるときのメッシュの族・世代・ revision の照合
//| run: reactive
//| crates: [scioxide-core, scioxide-spatial]
//| inputs:
//|   refine_x: {"type":"range","label":"x 方向の細分の因子 r","min":1,"max":4,"step":1,"value":2}
//| cases:
//|   - {"id":"unchanged","label":"r = 1","description":"変更のない細分は同じトークンを返し、組み合わせが受理される。","inputs":{"refine_x":1}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"tokens","path":"/rows/0/4","equals":true}
//|       - {"artifact":"tokens","path":"/rows/0/5","equals":"受理"}
//|       - {"artifact":"tokens","path":"/rows/1/3","equals":false}
//|       - {"artifact":"tokens","path":"/rows/1/5","equals":"InvalidInput"}
//|       - {"artifact":"tokens","path":"/rows/2/2","equals":1}
//|       - {"artifact":"tokens","path":"/rows/2/5","equals":"InvalidInput"}
//|       - {"artifact":"tokens","path":"/rows/3/1","equals":1}
//|       - {"artifact":"tokens","path":"/rows/3/2","equals":1}
//|       - {"artifact":"tokens","path":"/rows/3/3","equals":true}
//|       - {"artifact":"tokens","path":"/rows/3/4","equals":false}
//|       - {"artifact":"tokens","path":"/rows/3/5","equals":"InvalidInput"}
//|   - case: unchanged
//|     expect:
//|       - {"artifact":"tokens","path":"/rows/2/2","equals":0}
//|       - {"artifact":"tokens","path":"/rows/2/4","equals":true}
//|       - {"artifact":"tokens","path":"/rows/2/5","equals":"受理"}
//|       - {"artifact":"tokens","path":"/rows/3/5","equals":"受理"}
use scioxide_spatial::{AxisTopology, CellField, CellMesh, CoordinateAxis, Grid2d};

let axis = CoordinateAxis::uniform(0.0_f64, 1.0, 5).map_err(|e| e.to_string())?;
let topologies = [AxisTopology::Periodic, AxisTopology::Bounded];
let grid = Grid2d::new([axis.clone(), axis.clone()], topologies).map_err(|e| e.to_string())?;
let mesh = CellMesh::new(grid.clone()).map_err(|e| e.to_string())?;
let rebuilt = CellMesh::new(grid.clone()).map_err(|e| e.to_string())?;
let separate_grid = Grid2d::new([axis.clone(), axis], topologies).map_err(|e| e.to_string())?;
let separate = CellMesh::new(separate_grid).map_err(|e| e.to_string())?;
let factors = [refine_x as usize, 1];
let refined = CellMesh::new(grid.refined(factors).map_err(|e| e.to_string())?)
    .map_err(|e| e.to_string())?;
let sibling = CellMesh::new(grid.refined(factors).map_err(|e| e.to_string())?)
    .map_err(|e| e.to_string())?;

// 2 つのメッシュにセルの場を作り、try_zip_map で組み合わせる。
let combine = |left: &CellMesh<f64, 2>, right: &CellMesh<f64, 2>| -> Result<String, String> {
    let a = CellField::<f64, 2>::from_fn(left, |i| i as f64).map_err(|e| e.to_string())?;
    let b = CellField::<f64, 2>::from_fn(right, |i| i as f64).map_err(|e| e.to_string())?;
    Ok(match a.try_zip_map(&b, |x, y| x + y) {
        Ok(_) => "受理".to_string(),
        Err(error) => format!("{:?}", error.kind()),
    })
};
let pairs = [
    (
        "元の格子と、同じ格子から作り直したメッシュ",
        &mesh,
        &rebuilt,
    ),
    ("元の格子と、同じ座標で別に作った格子", &mesh, &separate),
    ("元の格子と、細分した格子", &mesh, &refined),
    (
        "細分した格子と、同じ親からもう一度細分した格子",
        &refined,
        &sibling,
    ),
];
let mut rows = Vec::new();
for (label, left, right) in pairs {
    let (l, r) = (left.mesh_token(), right.mesh_token());
    let result = combine(left, right)?;
    rows.push((
        label,
        l.generation().get(),
        r.generation().get(),
        l.same_family(r),
        l.is_compatible_with(r),
        result,
    ));
}
let columns = serde_json::json!([
    { "key": "0", "label": "組み合わせ" },
    { "key": "1", "label": "左の世代", "type": "integer" },
    { "key": "2", "label": "右の世代", "type": "integer" },
    { "key": "3", "label": "同じ族", "type": "boolean" },
    { "key": "4", "label": "同じ revision", "type": "boolean" },
    { "key": "5", "label": "try_zip_map の結果" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "tokens" })
);
```

同じ格子から作り直したメッシュはトークンを共有するので、revision が同じで、場の組み合わせは受理される。
同じ座標でも別に作った格子は族が違い、細分した格子は族が同じでも世代が違うので、どちらも `InvalidInput` になる。
同じ親を 2 回細分した 2 つの格子は、族も世代 1 も同じだが revision が違うので、やはり `InvalidInput` になる。
座標がまったく同じでも、別々に作った revision を取り違えないための規則である。
$r = 1$ では細分が何も変えないので、元の格子と同じトークンが返り、下の 2 行も受理される。
値の長さが違う場（細分した格子のセル数は $4r \times 4$）でも、長さを比べる前にトークンの照合で止まる。

## まとめ

場の値は格子とメッシュの要素の番号と同じく、軸 0 が最も速く変わる列優先の順序で並べる。
周期軸は継ぎ目の両端を別の頂点と面のまま対にして要素数を変えないので、継ぎ目の扱いは `FaceTopology::Periodic` の `paired` と接続の問い合わせで確かめる。
接続表を持たない `CellMesh` では隣接と境界を添字の算術で求められ、配列の大きさは `TopologySizes` で前もって決められる。
値を置く位置は `Field` の型で選び、意味のない位置とメッシュの組み合わせはコンパイルの段階で防ぐ。
細分や軸の差し替えの後は `MeshToken` の世代と revision が変わり、別に作った格子は族も違うので、古い revision の値との組み合わせは $O(1)$ の照合で `InvalidInput` になる。
同じ親から別々に作った兄弟の revision も世代が等しいだけでは組み合わせられないので、場は使う revision へ移してから組み合わせる。
