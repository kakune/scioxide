## 座標と点集合

座標のスカラーは `RealScalar`（`f32` または `f64`）で、複素数は扱わない。
距離は座標の型によらず `f64` の中間値で計算し、Euclid ノルムの平方和が桁あふれするか正規化数の範囲を下回ったときは尺度を調整して計算し直す。

任意次元の点の集まりは `PointSet` で表す。
1 行が 1 点、列が座標である（形状 $[n, d]$）。
`PointSet::from_points` は固定長配列 `[[S; D]]` の列を、`PointSet::from_rows` は行優先の平らな配列を、`PointSet::new` は `scioxide_core` の 2 階のビュー `NdView`（ストライドは任意）を借用する。
どの作り方も全座標の有限性を一度だけ検査し、距離、KD 木、分割、剛体変換の一括処理は座標を複製せずに読む。

分割（`ConvexHull`、`Delaunay`、`Voronoi`、`SphericalVoronoi`）は扱いが違う。
母点を座標の辞書式順に並べ替え、座標が等しい母点を 1 つにまとめた座標を所有する。
分割が返す添字はこの並べ替えた母点（正準の母点）の添字である。
入力の行とは `ConvexHull` と `Delaunay` の `input_mapping`（入力の行 → 正準添字）と `representatives`（正準添字 → 最初の入力の行）で対応させる。
`Voronoi` は `delaunay()` を通して同じ対応を引き、`SphericalVoronoi` は `input_mapping` だけを持つ。
このため、分割の結果は母点の集合だけで決まり、入力の順序によらない。
`HalfspaceIntersection` は不等式の行を並べ替えず、そのまま番号として使う。

構造格子と単体メッシュは 1〜3 次元に限り、固定長の `Point<S, D>`、`Extent<D>`、`Index<D>` を使う。
添字は軸 0 が最も速く変わる順に並べ、範囲 $[n_x, n_y, n_z]$ の添字 $[x, y, z]$ の線形位置は $x + n_x (y + n_y z)$ である。

回転は能動的な右手系の回転で、角はラジアンで表す。
四元数はスカラー部を最後に置いた $[x, y, z, w]$ の順に格納し、行列は行優先で列ベクトルに作用する。

## 厳密な判定と丸めを含む構成

組合せの決定は入力座標の行列式の厳密な符号で行う。
向きと外接円・外接球の内外の判定、凸包と Delaunay 分割の面、点の位置の探索、単体メッシュの向きの検査がこれに当たる。
浮動小数点のフィルタが大半の符号を確かめ、確かめられないときは行列式を厳密な算術で計算するので、退化した入力を含めて有限な入力なら結果は正しい。
この符号は入力として表現された浮動小数点数に対して正しいのであって、入力の測定誤差を考えたものではない。

周期格子の継ぎ目の対応や、メッシュの面と隣接の対応は、行列式ではなく整数の添字で決まる。
これも丸めを含まない。

外心、Voronoi 頂点と半直線の方向、半空間の交差の頂点、重心座標、長さ・面積・体積、回転の合成、剛体の推定は丸めを含む構成値である。
構成値は組合せの判定に使わない。
誤差の上界が証明されているのは半空間の交差の頂点だけで、ほかの構成値は各メソッドが行う検査を述べるにとどまる。
Delaunay 分割や Voronoi 図では、構成値を信頼して計算できない単体や頂点の照会だけが `NumericalInstability` を返し、ほかの項目はそのまま使える。
半空間の交差は例外で、1 つの頂点の誤差を証明できなければ構築全体が `NumericalInstability` になる。
距離や剛体の推定の残差は計算した値であり、統計的な不確かさの推定でも包含が保証された区間でもない。

## 準備・作業領域・実行

一括の計算は次の 4 つの段階に分かれる。

| 段階 | 形式 | 例 |
|---|---|---|
| 設定 | `with_*` で値を変える設定の値 | `SearchOptions`、`DistanceOptions`、`TransformOptions`、`GeometryOptions`、`AdaptationLimits` |
| 準備 | 既定の選択肢の `new(...)`、選択肢を受け取る `with_options(...)`、実行コンテキストを受け取る `build(..., cx)`。結果は不変な Plan | `KdTree::new`、`KdTree::with_options`、`PreparedDistance::new`、`Delaunay::build`、`RotationSpline::build` |
| 作業領域 | 要求量を求め（`workspace_requirements`）、事前確保する（`try_reserve`、`workspace`） | `SearchWorkspace`、`DistanceWorkspace`、`TransformWorkspace`、`GeometryWorkspace` |
| 実行 | 呼び出し側の配列と作業領域を使う `*_into(..., out, workspace, cx)` と `*_scoped(..., cx)`、既定の選択肢で逐次に実行して所有する結果を返す形 | `nearest_into`、`pairwise_into`、`apply_batch_into`、`find_simplex_scoped`、`nearest`、`pairwise`、`find_simplex` |

`*_into` の形は全計算が成功してから出力を書き換え、失敗したときは出力を変えない。
事前確保した作業領域は実行中に伸びないので、事前確保した大きさまでの呼び出しでは SciOxide の数値処理はメモリを確保しない。
ただし、注入したエグゼキューターが行う確保はそのエグゼキューターの仕様に従う。
`try_reserve` が失敗すると、それまでに伸ばした容量の一部が残ることがあるので、使う前にもう一度事前確保する。

距離、探索、変換の一括処理は、エグゼキューター、取り消し、期限を `SpatialExecutionContext` で受け取る。
`ExecutionContext`、`SolveScope`、`&mut SolveContext` のどれからでも変換でき、求解コンテキストから作っても反復回数は数えない。

分割の構築（`build`）、Delaunay 分割での点の探索（`find_simplex_scoped`）、凸包の内外判定（`contains_scoped`）、回転スプラインの準備（`RotationSpline::build`）、剛体の推定（`estimate_rigid_transform_scoped`）、適応細分（`adapt_scoped`）は `impl Into<SolveScope>` を受け取る。
これらは渡されたコンテキストの中で入れ子の求解として動き、呼び出し側の取り消しと期限に従う。
述語と組合せの計算量（分割、点の探索、内外判定）と適応細分の計算量は呼び出し側のノード数の上限に、適応細分でセルを分けた回数は細分回数の上限にも数えられる。
反復回数（分割での母点の挿入、スプラインの不動点反復、剛体推定での当てはめ）は呼び出し側の計数に記録されるが、入れ子の求解自身の上限だけを消費し、呼び出し側の反復の上限は減らさない。
回数の集計の規則は[求解ごとの上限と求解間で共有する上限](oxref:core-local-and-shared-budgets)にある。
コンテキストを受け取らない形（`new`、`with_options`、`find_simplex`、`contains`、`estimate_rigid_transform`、`adapt` など）は、取り消しも期限もない逐次の実行で同じ処理を行う。

`ExecutionPolicy::Auto` の距離、探索、変換の一括処理は、出力か照会が 256 以上になると並列実行を検討する。
この章のセルは wasm で逐次に動くので、`Auto` を指定しても並列にはならない。

## リソース上限とエラー

構成と作業領域は、バイト数、点の数、計算量などの上限を持つ。
上限を超えると `ResourceLimit` を返し、途中の結果は出力に反映しない。
分割の上限は `GeometryLimits` で、既定は 8 次元、母点と面がそれぞれ 100 万、述語の計算量と組合せの計算量がそれぞれ $10^9$、メモリが 512 MiB である。

エラーは `e.kind()`（`SciOxideErrorKind`）で分類する。

| 分類 | 起こる場面 |
|---|---|
| `NonFinite` | 座標、重み、照会の NaN または無限大 |
| `DimensionMismatch` | 点集合や配列の次元・長さの不一致、作業領域や出力の不足（収まらない一括の半径照会を含む） |
| `OutOfBounds` | メッシュ、分割、点集合の範囲の外を指す添字 |
| `DomainError` | 格子の座標範囲の外の点、入力に対して定義されない距離（零ベクトルの余弦距離など） |
| `Singular` | 空間を張らない分割の母点 |
| `InvalidInput` | 設定の誤り、検査に通らない接続、別の revision のメッシュに属する場、直交でない回転行列、節点の範囲外の補間時刻、`Strict` が拒否した母点、内点でない点、回転が一意に決まらない剛体の推定 |
| `NumericalInstability` | 悪条件か表現できない構成値、測度、距離 |
| `ResourceLimit` | 上限の超過、出力の容量を超える `KdTree::radius_into` の照会 |
| `SizeOverflow`、`AllocationFailure` | 大きさの計算の桁あふれ、メモリの確保の失敗 |
| `ExecutionStopped`、`ConvergenceFailure` | 取り消し、期限、求解の計算回数の上限（反復回数などの上限）の使い切り |

階数の足りない入力は、場所によって分類が違う。
分割の母点が超平面上にあれば `Singular`、剛体の推定で点が一直線上にあれば `InvalidInput` になる。
エラーは失敗の種類、引数か量、詳細を持ち、呼び出し元の識別子は持たない。

## 記号

| 記号 | 意味 |
|---|---|
| $n$, $d$ | 点の個数、座標の次元 |
| $d(x, y)$, $\Vert \cdot \Vert_p$ | 距離、$p$ ノルム |
| $k$, $r$, $\varepsilon$ | 近傍の個数、探索半径、近似の許容（距離の比 $1 + \varepsilon$） |
| $\varepsilon_{\text{mach}}$ | 機械イプシロン（`f64` で $2^{-52}$、`f32` で $2^{-23}$） |
| $R$, $q = (x, y, z, w)$ | 回転行列、スカラー部を最後に置いた単位四元数 |
| $\omega$, $\alpha$ | 機体座標の角速度 [rad/s]、角加速度 [rad/s²] |
| $a \cdot x + b \le 0$ | 半空間（係数 $a \in \mathbb{R}^d$、定数 $b$） |

## まとめ

組合せの判定は厳密な符号で決まり、外心や面積のような構成値は丸めを含むので、構成値で判定をやり直さない。
分割の添字は並べ替えた母点の正準添字なので、入力の行へは `input_mapping` と `representatives` で戻す（`Voronoi` は `delaunay()` を通す）。
一括の計算は設定・準備・作業領域・実行に分かれ、作業領域を一度事前確保すれば同じ大きさまでの呼び出しは確保しない。
エラーは `e.kind()` で分類でき、失敗しても出力は変わらない。
各ページは一覧の順に読めば前のページの知識だけで読めるので、まず[点・範囲・格子・メッシュの基礎](geometry-grids-and-meshes/)で格子とメッシュの表現を確かめる。
