共円の点を含む測量の格子や、数百万点の点群から分割を作るときは、結果の構造に加えて、構築がどれだけのリソースを使い、退化をどう解いたかを知る必要がある。
`scioxide-spatial` の分割の構築はリソースの上限を `GeometryLimits` で受け取り、使った量と記号摂動の使用を `GeometryProvenance` で返す。
このページでは上限と作業領域の扱い、構築情報の各量の意味を説明し、共円の格子で二つの退化の方針を比べる。
母点の正準化、`Deterministic` と `Strict` の定義、記号摂動の仕組みは[母点の正準化と退化の扱い](oxref:spatial-tessellation-sites)にある。

## リソース上限・作業領域・構築情報

構築の選択肢 `GeometryOptions` はリソース上限 `GeometryLimits` と退化の方針を持つ。
構築した分割は選択肢を保持し、照会にも同じ上限を使う。
`GeometryLimits::new()` の既定値を次の表に示す。
各上限は別々に検査し、超えると構築は `ResourceLimit` を返す。
大きな上限を設定しても、メモリ領域はあらかじめ確保されない。

| 上限 | 既定値 | 数える量 |
|---|---|---|
| `max_dimension` | 8 | 座標の次元 |
| `max_points` | 1,000,000 | 入力の母点（重複をまとめる前の行）または半空間の数 |
| `max_facets` | 1,000,000 | 構築中に同時に存在する凸包のファセット（Delaunay では持ち上げた凸包） |
| `max_predicate_terms` | $10^9$ | 1 回の構築または照会の述語の計算量 |
| `max_canonical_work` | $10^9$ | 同じ平面のファセットをまとめて分割する組合せの計算量 |
| `max_storage_bytes` | 512 MiB | 構築のメモリ領域、または作業領域のメモリ領域 |

述語の計算量は符号の評価 1 回を 1 単位とする。
浮動小数点のフィルタで符号が決まらず厳密に評価したときは、行列式の Leibniz 展開の項数を加える。
項数は $d$ 次元の向き述語で $(d+1)!$、内外判定で $d\,(d+2)!$、同次座標の $m$ 次の行列式で $m!$ である。
平面では向き述語が 6 項、`incircle` が 48 項、空間では向き述語が 24 項、`insphere` が 360 項になる。
数え方は決定論的なので、同じ入力では同じ量になる。
組合せの計算量は同じ支持超平面のファセットをまとめるときの隣接の訪問、頂点の走査、並べ替えの比較の回数である。

`new(&points)` は既定の選択肢で、`with_options(&points, options)` は与えた選択肢で、どちらも取り消しなしで構築する。
`build(&points, options, cx)` は実行コンテキストか `SolveScope` を受け取り、取り消しと期限で `ExecutionStopped` を、求解コンテキストの節点数の上限に達すると `ConvergenceFailure` を返す。
述語と組合せの計算量は、求解コンテキストの節点数にも数えられる。

`construction_requirements()` が返す `GeometryConstructionRequirements` は、構築中に使ったメモリ領域のピークである。
途中で解放した一時的なメモリ領域を含み、入力の点とアロケーターの余分は含まない。
その入力に限った値で、別の入力にはより多くのメモリ領域が要ることがある。

`ConvexHull` と `Delaunay` の照会（`contains_scoped`、`find_simplex_scoped`）の一時的なメモリ領域は、`workspace_requirements(())` が返す `GeometryWorkspaceRequirements` で表し、`GeometryWorkspace::try_reserve` で確保する。
`workspace(())` は要件を満たす作業領域を一度に作る。
確保した作業領域を使う照会は、新たな確保をしない。
一つの作業領域は要件を満たすどの分割にも使える。
`GeometryWorkspace::predicate_terms()` は、その作業領域を使った直前の照会の述語の計算量を返す。

`provenance()` が返す `GeometryProvenance` は構築の構築情報で、次の五つの量を持つ。

- `input_points` は入力の母点（半空間の交差では不等式）の数、`unique_points` は重複をまとめた後の母点の数である。
- `predicate_terms` は述語の計算量、`canonical_work` は組合せの計算量である。
- `resolved_ties` は、記号摂動が少なくとも 1 個の厳密な 0 の符号を決めたときに真になる。
  出力の単体に影響しない同点も含み、値は入力の行の順序によらない。
  持ち上げを使わない `ConvexHull` と `SphericalVoronoi` では記号摂動を使わないので、常に偽である。

`Voronoi::provenance` は双対の組み立てを含む全体の構築情報で、`delaunay().provenance()` は分割だけの構築情報である。

## 退化の方針と構築情報

次のセルは $4 \times 4$ の格子（16 点）について、`Deterministic` と `Strict` の二つの方針で `Voronoi` を作り、結果と構築情報を並べる。
格子と「座標をずらす」は[格子点での双対性の検算](oxref:spatial-delaunay-voronoi-duality)と同じで、入力行 $p$ は $(p \bmod 4,\ \lfloor p/4 \rfloor)$、ずらし量は $(p+1)^2$ に無理数に近い定数を掛けた小数部から決める 1/256 未満の値である。
「重複行を加える」は入力行 0 と同じ座標の行を末尾に加える。
表は各方針の構築の結果、入力行と母点の数、三角形と Voronoi 頂点の数、記号摂動の使用、述語と組合せの計算量を示す。
各単体の外心と、その単体が属する群の Voronoi 頂点の差の最大も示し、群の頂点が単体の外心と丸めの範囲で一致することを確かめる。
`Strict` が拒んだ行は構築の結果の欄に失敗の分類を示し、他の欄を空にする。

```rust
//| id: spatial-delaunay-degeneracy-policy
//| ref: spatial-delaunay-degeneracy-policy
//| title: Deterministic と Strict の方針で格子点の Voronoi 図を作り、構築情報を比べる
//| run: reactive
//| crates: [scioxide-spatial]
//| inputs:
//|   perturb: {"type":"checkbox","label":"座標をずらして共円をなくす","value":false}
//|   duplicate: {"type":"checkbox","label":"入力行 0 と同じ座標の行を加える","value":false}
//| cases:
//|   - {"id":"perturbed","label":"ずらした格子","description":"共円がなくなり、Strict も受け入れる。","inputs":{"perturb":true}}
//|   - {"id":"perturbed-duplicate","label":"ずらした格子と重複行","description":"重複行があると、Strict は共円がなくても拒む。","inputs":{"perturb":true,"duplicate":true}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"policies","path":"/rows/0/4","equals":18}
//|       - {"artifact":"policies","path":"/rows/0/5","equals":9}
//|       - {"artifact":"policies","path":"/rows/0/6","equals":true}
//|       - {"artifact":"policies","path":"/rows/0/8","equals":2229}
//|       - {"artifact":"policies","path":"/rows/1/1","equals":"InvalidInput"}
//|   - case: perturbed
//|     expect:
//|       - {"artifact":"policies","path":"/rows/0/6","equals":false}
//|       - {"artifact":"policies","path":"/rows/0/8","equals":229}
//|       - {"artifact":"policies","path":"/rows/1/1","equals":"成功"}
//|       - {"artifact":"policies","path":"/rows/1/4","equals":21}
//|       - {"artifact":"policies","path":"/rows/1/8","equals":256}
//|   - case: perturbed-duplicate
//|     expect:
//|       - {"artifact":"policies","path":"/rows/0/2","equals":17}
//|       - {"artifact":"policies","path":"/rows/0/3","equals":16}
//|       - {"artifact":"policies","path":"/rows/0/4","equals":21}
//|       - {"artifact":"policies","path":"/rows/1/1","equals":"InvalidInput"}
use scioxide_spatial::{GeometryDegeneracy, GeometryOptions, PointSet, Voronoi};

// 4 × 4 の格子。ずらし方は格子点での双対性の検算のセルと同じ。
let mut sites = Vec::with_capacity(17);
for p in 0..16_usize {
    let (mut dx, mut dy) = (0.0, 0.0);
    if perturb {
        let k = (p as f64 + 1.0) * (p as f64 + 1.0);
        dx = ((k * 0.754_877_666_246_692_7).fract() - 0.5) / 128.0;
        dy = ((k * 0.569_840_290_998_053_3).fract() - 0.5) / 128.0;
    }
    sites.push([(p % 4) as f64 + dx, (p / 4) as f64 + dy]);
}
if duplicate {
    sites.push(sites[0]);
}
let points = PointSet::from_points(&sites).map_err(|e| e.to_string())?;

let policies = [
    ("Deterministic", GeometryDegeneracy::Deterministic),
    ("Strict", GeometryDegeneracy::Strict),
];
let mut rows = Vec::new();
for (name, policy) in policies {
    let options = GeometryOptions::new().with_degeneracy(policy);
    let diagram = match Voronoi::with_options(&points, options) {
        Ok(diagram) => diagram,
        Err(e) => {
            let kind = format!("{:?}", e.kind());
            rows.push((
                name,
                kind,
                sites.len(),
                None,
                None,
                None,
                None,
                None,
                None,
                None,
            ));
            continue;
        }
    };
    let mesh = diagram.delaunay();
    // 群の Voronoi 頂点は群の最小番号の単体の外心で、他の単体の外心とは丸めの範囲で一致する。
    let (mut gap, mut center) = (0.0_f64, [0.0; 2]);
    for s in 0..mesh.simplex_count() {
        mesh.circumcenter_into(s, &mut center)
            .map_err(|e| e.to_string())?;
        let vertex = diagram
            .vertex(diagram.simplex_vertices()[s])
            .map_err(|e| e.to_string())?;
        gap = gap.max(
            (vertex[0] - center[0])
                .abs()
                .max((vertex[1] - center[1]).abs()),
        );
    }
    let p = diagram.provenance();
    rows.push((
        name,
        "成功".to_string(),
        p.input_points,
        Some(p.unique_points),
        Some(mesh.simplex_count()),
        Some(diagram.vertex_count()),
        Some(p.resolved_ties),
        Some(gap),
        Some(p.predicate_terms),
        Some(p.canonical_work),
    ));
}
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let columns = serde_json::json!([
    { "key": "0", "label": "方針" },
    { "key": "1", "label": "構築の結果" },
    { "key": "2", "label": "入力行 [個]", "type": "integer" },
    { "key": "3", "label": "母点 [個]", "type": "integer", "nullText": "—" },
    { "key": "4", "label": "三角形 [個]", "type": "integer", "nullText": "—" },
    { "key": "5", "label": "Voronoi 頂点 [個]", "type": "integer", "nullText": "—" },
    { "key": "6", "label": "記号摂動で同点を解消", "type": "boolean", "nullText": "—" },
    { "key": "7", "label": "外心と頂点の差の最大 [-]", "type": "number", "format": sci2, "nullText": "—" },
    { "key": "8", "label": "述語の計算量 [処理単位]", "type": "integer", "nullText": "—" },
    { "key": "9", "label": "組合せの計算量 [処理単位]", "type": "integer", "nullText": "—" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "policies" })
);
```

既定値（ずらさない格子）では、`Deterministic` は 16 個の母点から 18 個の三角形と 9 個の Voronoi 頂点を作り、記号摂動で同点を解いた（同点の解消が真）。
`Strict` は、正方形ごとに 2 個の三角形が空の外接円を共有するので、`InvalidInput` を返す。
述語の計算量はずらさない格子で 2229 処理単位、ずらした格子で 229 処理単位で、約 10 倍の差がある。
符号が厳密に 0 になる述語は浮動小数点のフィルタで決まらず、厳密な評価（`incircle` 1 回で 48 項）と記号摂動に進むからである。

「ずらした格子」では、二つの方針が同じ 21 個の三角形を作り、同点の解消は偽になる。
`Strict` の述語の計算量（256 処理単位）が `Deterministic`（229 処理単位）より多いのは、分割が一意かを確かめる分である。
「ずらした格子と重複行」では、`Deterministic` が 17 行を 16 個の母点にまとめ、三角形は重複行がないときと同じ 21 個である。
`Strict` は共円の 4 点がなくても、重複行があるので `InvalidInput` を返す。
外心と Voronoi 頂点の差はどの場合も 0 で、この格子では群の他の三角形の外心も同じ値に丸められた。

## まとめ

格子や測量点のように共円・共球の配置が避けられない入力では `Deterministic` で一つの分割を受け取り、分割が一意でないことや重複した母点を誤りとして扱いたいときは `Strict` を選ぶ。
大きな入力では `GeometryLimits` で次元、母点とファセットの数、述語と組合せの計算量、メモリ領域を制限し、超えた構築は `ResourceLimit` で止まる。
照会を繰り返すときは `workspace_requirements(())` で確保した `GeometryWorkspace` を使い回せば、照会ごとの確保がなくなる。
構築の後は `GeometryProvenance` の `predicate_terms` と `resolved_ties` で、退化が厳密な評価と記号摂動をどれだけ必要としたかを確かめられる。
