`scioxide-spatial` は計算幾何のクレートである。
構造格子と単体メッシュに型付きの場を載せ、局所細分と領域分割を行う。
向きと外接球の判定を厳密に決め、凸包、Delaunay 分割、Voronoi 図、半空間の交差を作り、その中で点を探す。
3 次元の回転と剛体変換を表して補間し、距離行列を作り、KD 木で近傍と半径の照会に答える。
座標の型は `f32` と `f64` で、既定の `std` を外すと `alloc` だけを使う `no_std` で同じ API が使える。

このページは目的に合う主な項目を示し、型どうしの関係と結果・エラーの読み方を説明する。
各項目の仕様は用途別の 5 つのページの表にあり、末尾の[用途別の表](#用途別の表)から開ける。

## 目的と主な項目

| 目的 | 主な項目 | 方法 | 表 |
|---|---|---|---|
| 点群を検査して受け渡す | `PointSet::from_points`、`PointSet::from_rows`、`PointSet::new` | 固定長配列の列、行優先の平らな配列、または行ごとに 1 点の 2 階の `NdView` を借用し、全座標の有限性を一度だけ検査する | [距離と探索](distance-and-search/) |
| 構造格子と場を作る | `CoordinateAxis`、`StructuredGrid`、`CellMesh`、`BoundarySet`、`Field` | 整数の添字から接続を求める（隣接表を持たない） | [幾何・格子・メッシュ](geometry-and-meshes/) |
| 区間・三角形・四面体のメッシュを作る | `IntervalMesh`、`TriangleMesh`、`TetrahedronMesh`、`SimplexBoundaryTags` | 明示的な接続を持ち、向きと多様体の接続を検査する | [幾何・格子・メッシュ](geometry-and-meshes/) |
| 距離行列を求める | `distance`、`pairwise`、`condensed`、`DistanceMetric`、`PreparedDistance` | 関数は Euclid 距離、`PreparedDistance` は 17 種類の名前付きの距離と標準化 Euclid 距離・Mahalanobis 距離。対をブロックに分けて回す | [距離と探索](distance-and-search/) |
| 有向 Hausdorff 距離を求める | `directed_hausdorff` | 固定のシードで並べ替えた順に調べ、最大値を超えられない点で打ち切る（Taha–Hanbury） | [距離と探索](distance-and-search/) |
| 近傍と半径内の点を探す | `KdTree`、`KdTreeOptions`、`SearchOptions` | 最も幅の広い軸の中央値で分ける KD 木 | [距離と探索](distance-and-search/) |
| 向き・外接円・外接球を判定する | `orient2d`、`orient3d`、`incircle`、`insphere`、`SimplexPredicateWorkspace` | 浮動小数点のフィルタで符号を確かめ、確かめられなければ厳密に計算する | [述語と分割](predicates-and-tessellation/) |
| 凸包・Delaunay 分割・Voronoi 図を作る | `ConvexHull`、`Delaunay`、`Voronoi`、`SphericalVoronoi` | 乱択逐次添加（挿入順は母点の正準添字のハッシュで固定）、持ち上げた点の下側凸包、その双対 | [述語と分割](predicates-and-tessellation/) |
| 半空間の交差を求める | `HalfspaceIntersection`、`IntersectionKind` | 内点を中心にした極双対の凸包 | [述語と分割](predicates-and-tessellation/) |
| 回転を表して補間する | `Rotation`、`EulerSequence`、`Slerp`、`RotationSpline` | 単位四元数、球面線形補間、角加速度が連続な 3 次スプライン | [回転と剛体変換](rotations-and-rigid-maps/) |
| 対応点から剛体変換を推定する | `estimate_rigid_transform`、`estimate_rigid_transform_with_options`、`RigidTransform` | 重み付き Kabsch 法 | [回転と剛体変換](rotations-and-rigid-maps/) |
| メッシュを局所的に細分・粗化する | `AdaptiveMesh`、`AdaptationRequest`、`TopologyMap` | 1 回の呼び出しで 1 段だけ変え、面の 2:1 平衡を保つ | [適応メッシュ](adaptive-meshes/) |
| メッシュを分割して並べ替える | `MeshPartition`、`RepartitionMap` | セルの所有者と 1 層のゴーストセル、位相を変えない置換 | [適応メッシュ](adaptive-meshes/) |

方法の数理は[数理と共通の規約](../algorithms/)から始まる各ページにあり、課題からの選び方は[方法の選び方](../choosing/)にある。

## 型の関係

### 設定・準備済みの Plan・作業領域

一括の計算は設定、準備済みの Plan、作業領域、実行コンテキストの 4 つを分けて受け取る。

- 設定は値の型である。
  `DistanceOptions`、`SearchOptions`、`TransformOptions` は実行方針と作業領域のバイト上限（`SearchOptions` は近似の相対誤差 $\varepsilon$ も）を、`GeometryOptions` は構成の上限（`GeometryLimits`）と退化した入力の扱い（`GeometryDegeneracy`）を持つ。
- 準備済みの Plan（`PreparedDistance`、`KdTree`、`ConvexHull`、`Delaunay`、`Voronoi`、`HalfspaceIntersection`、`SphericalVoronoi`、`Slerp`、`RotationSpline`）は不変で、何度でも使える。
  `KdTree`、凸包・Delaunay 分割・Voronoi 図・球面 Voronoi 図・半空間の交差、`RotationSpline`、`RepartitionMap` は、既定の設定で作る `new` と、設定を受け取る `with_options` を持つ。
- 作業領域（`DistanceWorkspace`、`SearchWorkspace`、`TransformWorkspace`、`GeometryWorkspace`）は、要求量を求めて一度事前確保すると、その大きさまでの呼び出しでは新たに確保しない。
  `GeometryWorkspace` は凸包の包含判定（`contains_scoped`）と Delaunay 分割の点の位置の探索（`find_simplex_scoped`）に使う。
- 実行コンテキストは並列実行、取り消し、期限を与える。
  距離・探索・変換の一括処理と再分割の値の転送（`*_into`）は `impl Into<SpatialExecutionContext>`、分割の構築（`build`）と照会（`find_simplex_scoped`、`contains_scoped`）、回転スプラインの準備（`RotationSpline::build`）、剛体の推定（`estimate_rigid_transform_scoped`）、適応細分（`adapt_scoped`）は `impl Into<SolveScope>` を受け取り、どちらにも逐次の `ExecutionContext::sequential()` を渡せる。
- コンテキストも作業領域も受け取らない形（`KdTree::nearest`、`pairwise`、`condensed`、`Delaunay::find_simplex`、`apply_batch`、`evaluate_rotations`、`estimate_rigid_transform`、`AdaptiveMesh::adapt` など）は、既定の設定で逐次に実行し、必要な作業領域と結果を呼び出しごとに確保して返す。

要求量の求め方は族ごとに違う。

| 族 | 要求の記述 | 要求量を返す関数 | 事前確保 |
|---|---|---|---|
| 距離 | `DistanceWorkspaceRequest::pairwise(m, n, options)`、`condensed(n, options)`、`square(n, options)` | `DistanceWorkspace::<S>::workspace_requirements(request)`（関連関数） | `DistanceWorkspace::try_reserve`、または `DistanceWorkspace::workspace(request)` |
| 探索 | `SearchWorkspaceRequest::new(k, options)` と `with_batch(queries, neighbors, workers)` | `tree.workspace_requirements(request)`（`KdTree` のメソッド） | `SearchWorkspace::try_reserve`、または `tree.workspace(request)` |
| 変換 | `TransformWorkspaceRequest` の `apply`、`euler`、`rotations`（それぞれ 1 種類のバッファーを見積もる） | `TransformWorkspace::<S>::workspace_requirements(request)`（関連関数） | `TransformWorkspace::try_reserve`、または `TransformWorkspace::workspace(request)` |
| 点の位置の探索 | 引数なし（`()`） | `ConvexHull` と `Delaunay` の `workspace_requirements(())` | `GeometryWorkspace::try_reserve`、または `workspace(())` |

`max_workspace_bytes` は、以前の大きな事前確保で残った容量も含めて、作業領域が保持する全容量を制限する。
`try_reserve` が失敗したときは容量の一部が残ることがあるので、使う前にもう一度事前確保する。

### 借用と所有

`PointSet` と `KdTree` は入力の座標を借用し、複製しない。
凸包、Delaunay 分割、Voronoi 図、球面 Voronoi 図は母点を辞書式に並べ替え、座標が等しい母点をまとめた座標を所有する。
そのため、これらが返す添字は並べ替えた後の正準添字である。
`ConvexHull` と `Delaunay` は `input_mapping`（入力の行 → 正準添字）と `representatives`（正準添字 → 最初の入力の行）を持つ。
`Voronoi` では `delaunay()` を通して同じ対応を引き、`SphericalVoronoi` は `input_mapping` だけを持つ。
`HalfspaceIntersection` は不等式を並べ替えず、まとめもしない。
構造格子、単体メッシュ、場は座標と接続を所有し、参照計数の共有によって複製の計算コストは配列の長さによらない。

### メッシュの revision と場

メッシュを変更するたびにできる新しいメッシュを、このガイドでは revisionと呼ぶ。
各メッシュは `MeshToken` を持ち、族（同じメッシュから派生した revision の集まり）、世代番号、revision ごとの識別を表す。
`StructuredGrid::refined`、`SimplexMesh::with_points`、`AdaptiveMesh::adapt` のように変更したメッシュを返すメソッドは、族を保って世代を進める。
場（`Field`）、境界集合（`BoundarySet`）、境界のタグ（`SimplexBoundaryTags`）、トポロジーの対応（`TopologyMap`）は作ったときのメッシュの revision を保持し、組み合わせる演算がそれを $O(1)$ で照合する。
同じ世代でも別の revision（同じ親から別々に作った revision）なら合わないとみなし、`InvalidInput` を返す。

## 最小の実行例

平面上の 3 点について、頂点の順序を入れ替えたときの `orient2d` の符号、共線の場合の 0、非有限の入力のエラーを確かめる。
入力はない。
出力は 4 行の表で、期待する符号と実際の結果を並べる。

```rust
//| id: spatial-api-orient2d-minimal
//| ref: spatial-api-orient2d-minimal
//| title: 向きの符号と非有限入力のエラーを確かめる
//| run: reactive
//| crates: [scioxide-spatial]
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"signs","path":"/rows/0/1","equals":"Positive"}
//|       - {"artifact":"signs","path":"/rows/1/1","equals":"Negative"}
//|       - {"artifact":"signs","path":"/rows/2/1","equals":"Zero"}
//|       - {"artifact":"signs","path":"/rows/3/1","equals":"NonFinite"}
use scioxide_spatial::orient2d;

let a = [0.0_f64, 0.0];
let b = [1.0_f64, 0.0];
let c = [0.0_f64, 1.0];
let cases = [
    ("a → b → c（反時計回り）", a, b, c, "Positive"),
    ("a → c → b（時計回り）", a, c, b, "Negative"),
    ("a → b → (2, 0)（共線）", a, b, [2.0, 0.0], "Zero"),
    ("a → b → (NaN, 1)", a, b, [f64::NAN, 1.0], "NonFinite"),
];
let mut rows = Vec::new();
for (label, p, q, r, expected) in cases {
    // 符号は PredicateSign、失敗はエラーの分類（SciOxideErrorKind）の名前で表す。
    let result = match orient2d(&p, &q, &r) {
        Ok(sign) => format!("{sign:?}"),
        Err(e) => format!("{:?}", e.kind()),
    };
    rows.push((label, result, expected));
}
let columns = serde_json::json!([
    { "key": "0", "label": "点の順序" },
    { "key": "1", "label": "orient2d の結果" },
    { "key": "2", "label": "期待する結果" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "signs" })
);
```

`Positive` は反時計回り、`Negative` は時計回り、`Zero` は 3 点が同じ直線上にあることを表す。
`Zero` は許容誤差による判定ではなく、行列式が厳密に 0 であることを意味する。
NaN を含む入力は符号を返さず、`NonFinite` のエラーになる。

## 結果・エラー・診断の読み方

### 書き込んだ件数

`nearest_into`、`radius_into`、`nearest_batch_into`、`radius_batch_into` のように結果の件数が変わる関数は、書き込んだ件数を返し、出力の先頭のその件数だけを書き換える。
残りの要素を番兵の値で埋めることはしない。
`Neighbor` は入力の行の添字と距離を持ち、距離の昇順（同じ距離なら添字の昇順）に並ぶ。

### 厳密な判定と丸めを含む構成

組合せの決定はすべて入力座標の行列式の厳密な符号で行う。
述語、凸包と Delaunay の面、点の位置の探索、単体メッシュの向きの検査がこれに当たり、退化した入力も含めて有限な入力なら結果は正しい。
外心、Voronoi 頂点と半直線の方向、半空間の交差の頂点、重心座標、体積や面積は丸めを含む構成値である。
このうち誤差の上界が証明されているのは半空間の交差の頂点だけで、次元 $d$ の頂点 $x$ は各不等式 $a\cdot x + b \le 0$ を高々 $128\,\varepsilon\,(d+1)\,(|b| + \sum_i |a_i x_i|)$ しか破らない（$\varepsilon$ は座標の型の機械イプシロン）。
Delaunay 分割と Voronoi 図では、構成値を信頼して計算できない単体や頂点の照会だけが `NumericalInstability` を返し、ほかの項目はそのまま使える。
半空間の交差と球面 Voronoi 図は例外で、1 つの頂点の誤差を証明できないとき、または球面の領域や面積を計算できないときは、構築全体が `NumericalInstability` になる。
距離は座標の型によらず `f64` の中間値で計算する。
Euclid 型のノルムはまず尺度を調整せずに平方和を求め、桁あふれするか正規化数の範囲を下回ったときだけ尺度を調整して計算し直す。

### 終了状態と構成の記録

半空間の交差が非有界なことは `IntersectionKind` で返し、エラーにはしない。
回転スプラインの `with_options` と `build` は収束しなかったことを `RotationSplineTermination` で返してエラーにはせず、結果は `Converged` のときだけスプラインを持つ。
`RotationSpline::new` は同じ未収束を `ConvergenceFailure` のエラーとして返す。
`GeometryProvenance` は、分割の構成に使った母点の数、受け入れた述語の計算量、正準化の計算量、記号摂動で 0 の符号を決めたかどうかを記録する。
剛体の推定（`RigidEstimationResult`）の残差は当てはまりの診断値で、統計的な不確かさの区間ではない。
`HausdorffResult` は計算した距離と、それを与える点の対（距離を与える点対）を持つ。

### エラーの分類

エラーは `e.kind()`（`SciOxideErrorKind`）で分類する。

| 分類 | このクレートで起こる場面 |
|---|---|
| `InvalidInput` | 設定の誤り、検査に通らないメッシュの接続、別の revision のメッシュに対する場や写像、直交でない回転行列、節点の範囲外の補間時刻、`GeometryDegeneracy::Strict` が拒否した母点、すべての半空間の真に内側にない内点、剛体の推定で回転が一意に決まらない配置 |
| `DimensionMismatch` | 点集合や配列の次元・長さの不一致、出力・作業用の配列・作業領域の不足（`KdTree::radius_batch_into` の結果が出力に収まらない場合を含む） |
| `OutOfBounds` | メッシュ、分割、点集合の範囲外の添字 |
| `NonFinite` | 座標、重み、照会の NaN または無限大 |
| `DomainError` | 格子の座標の範囲外の点、入力に対して定義されない距離（零ベクトルの余弦距離など） |
| `Singular` | 空間を張らない分割の母点（超平面上にある母点） |
| `NumericalInstability` | 悪条件か表現できない構成値（座標、測度、距離） |
| `ResourceLimit` | `GeometryLimits` や `AdaptationLimits` を超える構成、作業領域のバイト上限の超過、出力の容量を超える `KdTree::radius_into` の照会 |
| `SizeOverflow`、`AllocationFailure` | 大きさの計算の桁あふれ、メモリの確保の失敗 |
| `ExecutionStopped`、`ConvergenceFailure` | コンテキストを受け取る操作での取り消し、期限、求解の計算回数の上限（反復回数などの上限）の使い切り。`RotationSpline::new` の未収束も `ConvergenceFailure` |

エラーのとき出力は変わらない。
件数が変わる関数は、返した件数の先頭だけを書き換える。

## まとめ

目的ごとの主な項目から用途別の表へ進めば、各項目の仕様を確かめられる。
一括の計算は設定、不変な Plan、作業領域、実行コンテキストを分けて受け取り、作業領域を一度事前確保すれば同じ大きさまでの呼び出しは確保しない。
分割が返す添字は並べ替えた母点の正準添字なので、入力の行へは `input_mapping` と `representatives` で戻す（`Voronoi` は `delaunay()` を通す）。
組合せの結果は厳密な符号で決まり、構成値は丸めを含むので、検証が必要な値は独立な計算と比べる。
エラーは `e.kind()` で分類でき、失敗しても出力は変わらない。
