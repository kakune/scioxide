`scioxide-spatial` は、空間の点と形を扱う計算幾何のクレートである。
扱う問題は次の 5 つに分かれる。

| 分野 | 答える問い | 主な型・関数 |
|---|---|---|
| 格子・メッシュ・場 | 構造格子と単体メッシュの接続はどうなっているか、場がどのメッシュの revision（変更のたびにできる新しいメッシュ）に属するか | `StructuredGrid`、`CellMesh`、`TriangleMesh`、`Field`、`MeshToken` |
| 距離と近傍探索 | 点どうしの距離はいくらか、照会点に近い点はどれか、2 つの点集合はどれだけ離れているか | `PointSet`、`distance`、`pairwise`、`PreparedDistance`、`directed_hausdorff`、`KdTree` |
| 幾何述語と分割 | 3 点の向きや円の内外はどちらか、凸包・Delaunay 分割・Voronoi 図・半空間の交差はどうなるか | `orient2d`、`incircle`、`ConvexHull`、`Delaunay`、`Voronoi`、`SphericalVoronoi`、`HalfspaceIntersection` |
| 回転と剛体変換 | 姿勢をどう表して補間するか、対応点からどんな剛体変換が推定できるか | `Rotation`、`Slerp`、`RotationSpline`、`RigidTransform`、`estimate_rigid_transform` |
| 適応メッシュ | どのセルを細分・粗化し、細分の前後でセルがどう対応するか | `AdaptiveMesh`、`TopologyMap`、`MeshPartition` |

格子・メッシュ・場の型は偏微分方程式（`scioxide-pde`）でも幾何の表現として使われ、点集合、KD 木、Delaunay 分割、述語は散在点補間（`scioxide-interp`）でも使われる。
このクレートが扱うのは座標と位相で、場の転送の式や弱形式のような計算は利用する側で行う。

## 最初の計算

平面上の 5 か所の給水所 [km] から、ある地点に最も近い 2 か所を求める。
点は 1 行に 1 点を置いた 2 階のビュー `PointSet` に入れ、`KdTree::new` で Euclid 距離の KD 木の索引を作る。
探索の作業領域は先に事前確保しておき、`nearest_into` は結果を呼び出し側の配列に書く。
入力は地点の座標 $(x, y)$ [km] で、出力は近い順の 2 か所の番号、座標、距離である。

```rust
//| id: spatial-first-nearest
//| ref: spatial-first-nearest
//| title: 最寄りの給水所を KD 木で探す
//| run: reactive
//| crates: [scioxide-core, scioxide-spatial]
//| inputs:
//|   query_x: {"type":"range","label":"地点の x [km]","min":0,"max":10,"step":0.5,"value":4}
//|   query_y: {"type":"range","label":"地点の y [km]","min":0,"max":10,"step":0.5,"value":6}
//| cases:
//|   - {"id":"corner","label":"地点 (10, 0) km","description":"右下の隅では 1 番の給水所 (8, 2) が最も近い。","inputs":{"query_x":10,"query_y":0}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"nearest","path":"/rows/0/1","equals":2}
//|       - {"artifact":"nearest","path":"/rows/1/1","equals":4}
//|       - {"artifact":"nearest","path":"/rows/0/4","approx":{"value":1.4142135623730951,"rtol":1e-15}}
//|       - {"artifact":"nearest","path":"/rows/1/4","approx":{"value":1.4142135623730951,"rtol":1e-15}}
//|   - case: corner
//|     expect:
//|       - {"artifact":"nearest","path":"/rows/0/1","equals":1}
//|       - {"artifact":"nearest","path":"/rows/0/4","approx":{"value":2.8284271247461903,"rtol":1e-15}}
use scioxide_core::{ExecutionContext, NdView, StridedLayout};
use scioxide_spatial::{KdTree, Neighbor, PointSet, SearchOptions, SearchWorkspaceRequest};

// 給水所の座標 [km]。行が 1 か所、列が (x, y)。
let sites = [1.0, 1.0, 8.0, 2.0, 3.0, 7.0, 9.0, 9.0, 5.0, 5.0];
let layout = StridedLayout::new(&[5, 2], &[2, 1]).map_err(|e| e.to_string())?;
let points = PointSet::new(NdView::new(&sites, layout).map_err(|e| e.to_string())?)
    .map_err(|e| e.to_string())?;
let tree = KdTree::new(&points).map_err(|e| e.to_string())?;

// 準備: 2 近傍の候補を持てる作業領域。実行: 結果を out に書く。
let options = SearchOptions::new();
let mut workspace = tree
    .workspace(SearchWorkspaceRequest::new(2, options))
    .map_err(|e| e.to_string())?;
let mut out = [Neighbor::default(); 2];
let found = tree
    .nearest_into(
        &[query_x, query_y],
        2,
        options,
        &mut out,
        &mut workspace,
        ExecutionContext::sequential(),
    )
    .map_err(|e| e.to_string())?;
let rows: Vec<(usize, usize, f64, f64, f64)> = out[..found]
    .iter()
    .enumerate()
    .map(|(rank, v)| {
        let (x, y) = (sites[2 * v.index], sites[2 * v.index + 1]);
        (rank + 1, v.index, x, y, v.distance)
    })
    .collect();
let fixed1 = serde_json::json!({ "fractionDigits": 1 });
let fixed4 = serde_json::json!({ "fractionDigits": 4 });
let columns = serde_json::json!([
    { "key": "0", "label": "順位", "type": "integer" },
    { "key": "1", "label": "給水所の番号", "type": "integer" },
    { "key": "2", "label": "x [km]", "type": "number", "format": fixed1 },
    { "key": "3", "label": "y [km]", "type": "number", "format": fixed1 },
    { "key": "4", "label": "距離 [km]", "type": "number", "format": fixed4 }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "nearest" })
);
```

## 結果の読み方

表の各行は `Neighbor` の値である。
`index` は入力の行番号（0 から数える）で、木の内部の並びではない。
`distance` は木の距離で、ここでは Euclid 距離 [km] である。
結果は距離の昇順に並び、丸めた距離が等しければ番号の小さい順になる。

戻り値 `found` は書いた件数で、点が $k$ 個より少なければ $k$ より小さくなる。
足りない分を番兵の値で埋めることはしない。
既定の地点 $(4, 6)$ km では、2 番の給水所 $(3, 7)$ と 4 番の $(5, 5)$ がどちらも $\sqrt{2} \approx 1.414$ km の距離にあり、番号の小さい 2 番が先に来る。

座標に NaN や無限大があると、`PointSet::new` は `NonFinite` のエラーを返す。
照会点の次元が木と違うとき、出力の配列が短いとき、作業領域の事前確保が足りないときは `DimensionMismatch`、照会点に NaN や無限大があれば `NonFinite` になり、どちらの場合も出力の配列は書き換えられない。

## まとめ

`scioxide-spatial` は、格子・メッシュ・場、距離と近傍探索、幾何述語と分割、回転と剛体変換、適応メッシュを扱う。
点群は `PointSet` で一度だけ有限性を検査し、距離、探索、分割、剛体変換の一括処理に同じビューを渡せる。
近傍探索の結果は入力の行番号と距離で返り、同じ距離なら番号の小さい順に並ぶ。
組合せの判定は厳密な符号で決まり、外心や面積のような構成値は丸めを含む。
課題に合う手法を決めるには[手法の選び方](choosing/)へ、各手法の仮定と誤差を確かめるには章の構成の 1 番から順に読む。
