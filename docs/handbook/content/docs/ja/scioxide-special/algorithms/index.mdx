一つの級数や積分表示だけで特殊関数を全定義域にわたって評価すると、大きな引数での打ち消し、収束の停滞、指数のオーバーフローやアンダーフローに出会う。
`scioxide-special` は引数の領域ごとに方法を選び、原点の近くでは定義の級数や有理近似、中間では連分数・漸化式・Chebyshev 展開、大きな引数では漸近展開を使う。
このページは、35 枚の数理ページが前提にする記号と共通の仕様を説明し、ページ一覧を示す。
各関数族の定義、方法の選び方、精度の詳細は、それぞれの数理ページにある。

## 記号

| 記号 | 意味 |
|---|---|
| $\varepsilon$ | スカラー型の機械イプシロン。binary64 では $2^{-52} \approx 2.22 \times 10^{-16}$ |
| ULP | 真の値の位置での浮動小数点数の間隔。誤差を「何 ULP」と数える単位にする |
| $\eta$ | 最小の正の非正規化数。binary64 では約 $4.9 \times 10^{-324}$ |
| $P, Q$ | 正則化した下側・上側の確率。$P + Q = 1$ で、$Q$ を相補形と呼ぶ |
| $m = k^2$ | 楕円積分と Jacobi 楕円関数の母数。$k$ は法 |
| $\nu$, $n$, $l$ | 次数。$\nu$ は実数か複素数、$n$ と $l$ は整数 |
| $z$, $x$ | 引数。$z$ は複素数を含み、$x$ は実数に限る |

角度はすべてラジアンで渡す。
定義と番号は NIST の DLMF に従う。

## 共通の仕様

### 値の表現

オプション付き形式 `*_with_options` が返す `SpecialFunctionResult` は、同じ値を最大で四つの形で持つ。
通常値 `value()`、各成分を仮数と 2 の冪の指数に分けた値 `scaled()`、位相（実数では符号）と大きさの自然対数に分けた対数形 `logarithmic()`、引数についての導関数 `derivative()` である。
通常値があふれても、尺度化した値と対数形は表せる範囲で残る。
`scalar_representation()` は通常値への射影の状態を示し、`Finite`、`Overflow`、`InfiniteLimit`（文書化した $\pm\infty$ の極限）のどれかになる。
真の値が小さすぎて零に丸められても状態は `Finite` で、標準形式は符号付きの零を返す。

名前に `_scaled` が付く関数は、指数因子を掛けた別の量を返す。
たとえば `bessel_k_scaled` は $e^{z}K_\nu(z)$ を返し、`airy_ai_scaled` は実数の $x > 0$ で $e^{\frac23 x^{3/2}}\operatorname{Ai}(x)$ を返し、$x \le 0$ では因子を掛けない。
オプション付き形式の `scaled()` は同じ値を 2 の冪で表し直しただけで、名前付きの尺度化形とは違う。

対数形の関数は Gamma・Beta 関数、階乗、二項係数では `ln_*`（`ln_gamma` など）、それ以外では名前に `log` を含む（`log_erfc`、`gamma_log_q`、`normal_log_sf`、`bessel_k_log`、`hurwitz_zeta_log`）。
対数で与えた確率の逆関数は `*_inv_log*` と名付けられている（`gamma_p_inv_log` など）。
相補形は上側の確率を引き算なしに評価する形で、`erfc`、`gamma_q`、`beta_inc_q`、`normal_sf` がある。

### 推定誤差

各形は `ValueWithError` として推定誤差を持つ。
`absolute_error()` はその形の単位での絶対誤差、`relative_error()` は値が零でないときの相対誤差で、対数形の誤差は自然対数の単位で表す。
対数形は、相対誤差が $1/2$ に達すると省かれる。

`reliability()` は推定の根拠を三つに分ける。
`ModelBased` は評価の打ち切り誤差と丸め誤差のモデルから導いた値である。
`StatisticallyCalibrated` は高精度の参照値と比べて測った包絡で、関数ごとの定数 $k$ を使って $k \max(\varepsilon|v|, \eta)$ の形をとる（$v$ は値）。
`Heuristic` は被覆についての主張を持たない。
どの推定も保証された包含区間ではなく、証明付きの上下限が要るときは `scioxide-validated` を使う。
推定誤差が大きいことはエラーにならず、そのまま示される。

### 終了状態と作業量の上限

`termination()` は評価がどう終わったかを `SpecialFunctionTermination` で示す。
`Exact` は恒等式か表の厳密値、`Converged` は方法の収束判定を満たした値、`Limit` は文書化した数学的な極限（$\Gamma(0^+) = +\infty$ など）である。
`IterationLimit` は作業量の上限に達したことを示し、そのとき得られていた推定値を持つ。
`is_success()` は前の三つで真になる。
`IterationLimit` の結果を `try_value()` で通常値に射影すると `ConvergenceFailure` になり、標準形式も同じエラーを返す。
上限までに有用な推定値ができなければ、オプション付き形式も結果ではなく `ConvergenceFailure` を返す。

オプションの型（`GammaOptions`、`BesselOptions` など）は作業量の上限 `Budget` を持ち、級数の項や漸化式の段などの作業の単位で数える。
上限は精度の要求ではなく、精度は方法で決まっていて、上限を増やすと収束の遅い場合が終われるようになるだけである。
許容誤差も持つのは `SpectralOptions`（Mathieu・回転楕円体関数の打ち切り）と `EllipsoidalOptions`（第二種の楕円体調和関数と正規化定数の適応求積）だけである。
`algorithm()` は選んだ方法の識別子、`counts()` は失敗した試みも含めた計算量の計数を返す。

### 精度の目標

精度の目標は、crate の試験が照合データ（独立に生成した高精度の参照値）で確かめた範囲での、真の値からの ULP で表す。
関数の零点の近くでは目標は絶対誤差になり、絶対誤差が小さくても相対誤差は大きくなりうる。

| 実数の引数の関数 | binary64 | binary32 |
|---|---|---|
| `gamma`、`ln_gamma`、`digamma`、`polygamma`、`beta`、`ln_beta`、`factorial`、`ln_factorial`、`binomial` | 4 ULP | 1 ULP |
| 不完全 Gamma・Beta 関数とその逆関数 | 32 ULP | 1 ULP |
| `erfinv`、`erfcinv`、`normal_quantile`、`normal_isf`、`erfcx`、`log_erfc`、`dawson` | 4 ULP | 1 ULP |
| `normal_cdf`、`normal_sf`、`normal_log_cdf`、`normal_log_sf`（$[-38, 38]$） | 8 ULP | 1 ULP |
| `expint_e1`、`expint_ei`、`expint_en`、`expint_3`、`si`、`ci`（零点から離れた所） | 8 ULP | なし |
| `elliptic_k`、`elliptic_e`（$0 \le m < 1$） | 2 ULP | 1 ULP |
| Carlson 積分、不完全楕円積分、Jacobi 楕円関数 | 64 ULP | 64 ULP |
| `bessel_j`、`bessel_y`、`bessel_i`、`bessel_k`、Hankel 関数、Airy 関数 | 64 ULP | 64 ULP |
| `struve`、`modstruve`（$-5 \le \nu \le 10$、$10^{-3} \le x \le 100$） | 64 ULP | なし |
| `legendre_p`、`legendre_q`、`legendre_p_assoc` | 64 ULP | 64 ULP |
| `hyp0f1`、`hyp1f1`、`hyp2f1`、`hyperu` | 64 ULP | 64 ULP |
| `lambert_w0`、`lambert_wm1`、`wright_omega`、`dilog`、`spence` | 64 ULP | 64 ULP |
| `coulomb_f`、`coulomb_g` とその導関数 | 64 ULP | 64 ULP |

試験した範囲より広い 4160 点の binary64 の標本では、`gamma` の最大誤差は 3.7 ULP、`ln_gamma` は 1.9 ULP、`digamma` は 2.1 ULP、`beta` は 1.0 ULP だった。
同じ標本で `gamma_p` と `gamma_q` は 90 ULP、`beta_inc` は 12 ULP に達するので、不完全形の 32 ULP は試験した範囲だけの目標である。
実数の `riemann_zeta`、`dirichlet_eta`、$s > 1$ の `hurwitz_zeta` は ULP の目標を持たず、$64\varepsilon|v|$ 以下の推定誤差を返す。
複素数の引数と、表にない関数（Kelvin・放物柱・角運動量・スペクトル型の関数、Fermi–Dirac 積分など）には一様な目標がなく、オプション付き形式の推定誤差が手がかりになる。

次のセルは、閉形式か既知の定数で値が分かる点で、オプション付き形式の推定誤差と実際の誤差を並べる。
参照値は 20 桁以上の十進の定数で、f64 に読み込むと正しく丸められるので、実際の誤差は $0.5$ ULP の範囲で正確に測れる。
入力は持たず、表は推定の根拠、推定した相対誤差、実際の誤差、目標の ULP を示す。

```rust
//| id: special-index-estimate-and-ulp
//| ref: special-index-estimate-and-ulp
//| title: 既知の値で推定誤差と実際の誤差を比べる
//| run: reactive
//| crates: [scioxide-special]
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"estimates","path":"/rows/0/4","range":{"max":4}}
//|       - {"artifact":"estimates","path":"/rows/1/4","range":{"max":2}}
//|       - {"artifact":"estimates","path":"/rows/3/4","range":{"max":64}}
//|       - {"artifact":"estimates","path":"/rows/5/4","range":{"max":64}}
//|       - {"artifact":"estimates","path":"/rows/6/4","range":{"max":8}}
//|       - {"artifact":"estimates","path":"/rows/0/5","equals":"はい"}
//|       - {"artifact":"estimates","path":"/rows/8/5","equals":"はい"}
use scioxide_special::{
    SpecialFunctionResult, clausen_with_options, digamma_with_options, elliptic_k_with_options,
    expint_e1_with_options, fermi_dirac_half_with_options, gamma_with_options,
    hyp2f1_with_options, lambert_w0_with_options, riemann_zeta_with_options,
};

// 既定のオプションを型ごとに作る。
fn d<T: Default>() -> T {
    T::default()
}
// 参照値は 20 桁以上の十進定数（DLMF の閉形式と既知の定数）。
let cases: Vec<(&str, Option<u32>, f64, SpecialFunctionResult<f64>)> = vec![
    (
        "Γ(1/2) = √π",
        Some(4),
        1.7724538509055160272981674833,
        gamma_with_options(0.5, d()),
    ),
    (
        "K(1/2) = Γ(1/4)²/(4√π)",
        Some(2),
        1.8540746773013719184338503472,
        elliptic_k_with_options(0.5, d()),
    ),
    (
        "ψ(1) = −γ",
        Some(4),
        -0.5772156649015328606065120901,
        digamma_with_options(1.0, d()),
    ),
    (
        "W₀(1) = Ω",
        Some(64),
        0.5671432904097838729999686622,
        lambert_w0_with_options(1.0, d()),
    ),
    (
        "ζ(2) = π²/6",
        None,
        1.6449340668482264364724151666,
        riemann_zeta_with_options(2.0, d()),
    ),
    (
        "₂F₁(1, 1; 2; 1/2) = 2 ln 2",
        Some(64),
        1.3862943611198906188344642429,
        hyp2f1_with_options(1.0, 1.0, 2.0, 0.5, d()),
    ),
    (
        "E₁(1)",
        Some(8),
        0.2193839343955202736771637755,
        expint_e1_with_options(1.0, d()),
    ),
    (
        "Cl₂(π/2) = G（Catalan）",
        None,
        0.9159655941772190150546035149,
        clausen_with_options(std::f64::consts::FRAC_PI_2, d()),
    ),
    (
        "F₁/₂(0) = (1 − 2^(−1/2)) ζ(3/2)",
        None,
        0.7651470246254079453672687586,
        fermi_dirac_half_with_options(0.0, d()),
    ),
]
.into_iter()
.map(|(name, target, reference, result)| result.map(|r| (name, target, reference, r)))
.collect::<Result<_, _>>()
.map_err(|e| e.to_string())?;

let mut rows = Vec::new();
for (name, target, reference, result) in cases {
    let value = result.value().ok_or("通常値がない")?;
    // 参照値の位置の ULP: 2^(⌊log₂|r|⌋ − 52)。
    let ulp = 2f64.powi(reference.abs().log2().floor() as i32 - 52);
    let actual = (*value.value() - reference).abs();
    let covered = if actual <= value.absolute_error() {
        "はい"
    } else {
        "いいえ"
    };
    rows.push((
        name,
        format!("{:?}", value.reliability()),
        value.relative_error(),
        target,
        actual / ulp,
        covered,
    ));
}
let sci2 = serde_json::json!({ "notation": "scientific", "significantDigits": 2 });
let fixed1 = serde_json::json!({ "fractionDigits": 1 });
let columns = serde_json::json!([
    { "key": "0", "label": "関数と点" },
    { "key": "1", "label": "推定の根拠" },
    { "key": "2", "label": "推定相対誤差 [-]", "type": "number", "format": sci2, "nullText": "なし" },
    { "key": "3", "label": "目標 [ULP]", "type": "integer", "nullText": "一様な目標なし" },
    { "key": "4", "label": "実際の誤差 [ULP]", "type": "number", "format": fixed1 },
    { "key": "5", "label": "推定が実際の誤差を覆う" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "estimates" })
);
```

九つの点のすべてで、実際の誤差は 0 ULP、つまり正しく丸めた値に一致した。
これはブラウザの wasm での結果で、ネイティブの実行では数学ライブラリの違いにより `expint_e1` が 2 ULP になる。
目標（2〜64 ULP）は試験した範囲全体での上限で、個々の点の誤差はそれよりずっと小さいことが多い。
推定相対誤差は $4.4 \times 10^{-16}$（`elliptic_k`）から $1.5 \times 10^{-14}$（`clausen`）まであり、どの点でも実際の誤差を覆っている。
`StatisticallyCalibrated` の推定は $k\varepsilon|v|$ の形なので、$\varepsilon$ の小さな倍数になる。
`ModelBased` の推定は打ち切りと丸めの評価から積み上げた値で、この表では相対誤差 $5.5 \times 10^{-15}$ から $1.5 \times 10^{-14}$ になる。
`hyp2f1` は推定絶対誤差を持つが、この点では推定相対誤差を返しない。
一点で誤差が 0 であることは、その関数の精度を保証しない。
この表は推定誤差の読み方を示すもので、関数族ごとの照合は各数理ページのセルで行う。

## まとめと次に読むページ

オプション付き形式の結果は通常値・尺度化した値・対数形・導関数をそれぞれの推定誤差とともに持ち、通常値があふれても残りの形で値を読める。
推定誤差の根拠は `ModelBased`、`StatisticallyCalibrated`、`Heuristic` の三つで、どれも包含が保証された区間ではない。
終了状態が `IterationLimit` なら値は途中の推定値で、通常値への射影はエラーになる。
精度の目標は試験した範囲での ULP で、表にない関数や複素数の引数では推定誤差を読む。
最初に [API・分枝・値の表現](branches-tails-and-extended-families/) で引数の型と結果の読み方を確かめ、必要な関数族のページへ進む。
