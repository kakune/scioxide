この表は一般化超幾何関数と、名前の付いた低次の超幾何関数の公開項目をまとめる。
関数は `NumericScalar`（`f32`、`f64`、`Complex<f32>`、`Complex<f64>`）を受け取り、実数と複素数で同じ名前を使う。
各行は値だけを返す標準形式、`HypergeometricOptions` を受け取って `SpecialFunctionResult` を返すオプション付き形式 `*_with_options`、求解のスコープの中で評価するスコープ付き API `*_scoped(.., options, scope)` を並べる（[三つの呼び出し形](oxref:special-api-call-forms)）。
`HypergeometricOptions` は作業量の上限（既定 65536）だけを持ち、[結果型とオプション](../results-and-options/)に載せる。
名前の付いた関数のパラメータ $a$、$b$、$c$ は、引数 $z$ が複素数なら実数でも渡せる（`Parameter`）。

共通の規則として、パラメータと引数はすべて有限でなければならず、非有限の入力は `NonFinite` になる。
分母のパラメータが非正の整数なら `DomainError`（`Pole`）になる。
ただし、分子のパラメータが非正の整数でその分母より大きいときは、級数が分母の零より前で終わる多項式なので評価する。
表せない結果や計算の破綻は `NumericalInstability`、作業量の上限に達すると `ConvergenceFailure` になる。
名前の付いた関数のオプション付き形式は、値と推定誤差に加えて、隣接関係式で求めた引数についての導関数を返す。
`hyp_pfq_with_options` は導関数を返さない。
推定誤差は区間の包含区間ではない。

実数の ${}_0F_1$、${}_1F_1$、${}_2F_1$ と $U$ は、照合した範囲で両精度とも 64 ULP を目標とし、関数の零点の近くでは絶対誤差で照合する。
一般の ${}_pF_q$、${}_2F_0$、正則化した ${}_2F_1$、複素数の引数、パラメータについての導関数には一様な ULP の仕様がない。
これらは返す推定誤差を、独立に求めた高精度の参照値と照合して確かめている。
複素数の ${}_1F_1$ は $\lvert z\rvert = 10^4$ までのすべての偏角で、${}_2F_1$ は $z = 1$ から $10^{-15}$ の距離まで試験している。

## 一般化超幾何級数と保持したパラメータ

一般化超幾何関数は ${}_pF_q(a; b; z) = \sum_{k=0}^\infty \frac{(a_1)_k \cdots (a_p)_k}{(b_1)_k \cdots (b_q)_k}\frac{z^k}{k!}$ で、$(x)_k = x(x+1)\cdots(x+k-1)$ は Pochhammer 記号である。
パラメータを保持せずに一度だけ評価するときは、`hyp_pfq` とそのオプション付き形式・スコープ付き API を使う。
同じパラメータで多くの引数を評価するときと、正則化した級数やパラメータについての導関数が要るときは、パラメータを検査して保持する `HypergeometricFunction` を作る。
その `evaluate` は呼び出しごとに作業領域を確保し、`evaluate_scoped` は `workspace()` で一度作った `HypergeometricWorkspace` を使い回して確保しない。
