`scioxide-special` は、Gamma・Beta 関数と確率の裾、誤差関数、Airy・Bessel 関数、楕円積分、超幾何関数、ゼータ関数、Coulomb 波動関数、角運動量の結合係数、Mathieu・回転楕円体・楕円体調和関数、熱的な積分などを提供する。
このガイドは目的から API となる項目を示し、rustdoc に載る 705 項目を関数族ごとに 13 の表にまとめる。
表の項目名のリンクは、docs.rs の 0.1.0 の API リファレンスを指す。

多数の引数をまとめて評価する一括（バッチ）関数は提供しない。
多くの点で評価するときは、標準形式を反復子で呼んで集める。
次数の列をまとめて返す関数は、隣接する次数の漸化式を再利用する Coulomb 関数の `coulomb_sequence`、`coulomb_wave_sequence`、`coulomb_normalization_sequence` だけである。
これらは個数 `count` を受け取って値の `Vec` を返し、`*_into` 形は呼び出し側が用意したメモリ領域に詳細結果を書く。

## 型の関係

実数だけを扱う関数は `RealScalar`（`f32`、`f64`）を受け取る。
実数と複素数の両方を扱う関数は `NumericScalar` のシグネチャを持ち、同じ名前で `Complex<f32>`、`Complex<f64>` も受け取る（例：`bessel_j`、`gamma_p`、`polylog`、`wright_omega`）。
複素数の引数では解析接続を評価し、切断の位置は各関数の表に書く。
結果の型は引数の型で決まる。
次数や形状のようなパラメータは引数と同じ型で渡すが、引数が複素数なら実数でも渡せる（`Parameter`）。
例えば複素数の $z$ に対して `bessel_j(2.5, z)` は $J_{2.5}(z)$ を返す。
複素数のパラメータには複素数の引数が要る。

関数は標準形式、オプション付き形式、スコープ付き API の三つの呼び出し形を持つ。
標準形式 `f(..)` は値だけを返す。
オプション付き形式 `f_with_options(.., options)` は同じ評価から `SpecialFunctionResult` を返し、その通常値は標準形式の値とビット単位で一致する。
スコープ付き API `f_scoped(.., options, scope)` は同じ評価を求解のスコープの中で行い、オプション付き形式と同じ結果を返す。
引数 `scope` は `ExecutionContext`（新しい根の評価）か `&mut SolveContext`（親の求解の中の子の評価）である。
子の評価では、計算量が親に入れ子の計数として渡り、親の取り消しと期限が効く。

計算量が引数にも収束にもよらず有界な関数には、スコープ付き API がない。
固定の表、有理近似や Chebyshev 近似、固定の求積節点で評価する関数がこれに当たる。
例えば Γ、$\ln\Gamma$、$\psi$、Beta 関数、`erfinv`、正規分布の確率・対数確率・分位点（対数確率からの逆関数 `normal_inv_log_cdf`、`normal_inv_log_sf` は除く）、`owens_t`、階乗と二項係数、Bernoulli 数と Euler 数、`clausen`、`dilog`、シンクロトロン関数である。
実数の誤差関数と Dawson 積分も固定計算コストの核で評価するので、`erf_scoped` などのスコープ付き API は複素数の引数だけを型として受け付ける。

各関数族には不変のオプション型があり、作業量の上限 `Budget` を持つ。
既定値は多くの族で 65536 単位で、単位は級数の項や漸化式の一歩などの処理である。
オプションは精度の要求ではない。
精度は核で固定されており、上限を大きくしても収束の遅い場合が完了できるようになるだけである。
許容誤差を持つのは `SpectralOptions`（打ち切りを決める）と `EllipsoidalOptions`（求積を決める）だけである。
`AngularOptions` は作業量のほかにメモリ領域の上限も持つ。

`MathieuPlan`、`SpheroidalPlan`、`EllipsoidalHarmonicPlan`、`AngularPlan` は、多くの評価で再利用する事前計算を持つ Plan である。
前の三つは打ち切った固有値問題を解いて展開係数を保持し、`AngularPlan` は Racah の公式の階乗を素因数分解するための素数表を保持する。
Plan は不変で、作ったときのオプションを保持する。
既定の実行で準備する `new` と、スコープの中で準備する `build(.., scope)` があり、評価メソッドには `*_scoped` 版がある。
一度だけ評価するときは、Plan を内部で一つ作って一度だけ評価するワンショット関数（`mathieu_a`、`spheroidal_angular`、`ellipsoidal_harmonic`、`wigner_3j` など）を使う。

`HypergeometricFunction` は ${}_pF_q$ か Tricomi の $U$ のパラメータを検査して保持し、多くの引数で評価する。
`pfq` か `u` で作り、`hyp_pfq` と `hyperu` にない正則化した ${}_pF_q$ と、引数か一つのパラメータについての一階導関数を加える。
`AngularPlan` と `HypergeometricFunction` の所有値を返す API の評価メソッドは呼び出しごとに作業領域を確保する。
それぞれの `*_scoped` メソッドは渡された `AngularWorkspace`、`HypergeometricWorkspace` を使い、確保しない。

詳細結果 `SpecialFunctionResult<T>` は通常値、尺度化した値、対数形、引数についての導関数の四つの形を持てる。
各形は `ValueWithError`（値と推定誤差）で、意味のある推定ができない形は `None` になる。
ほかにアルゴリズムの識別子 `algorithm()`、計算量の計数 `counts()`、終了状態 `termination()`（`SpecialFunctionTermination`）、通常値への射影の状態 `scalar_representation()`（`ScalarRepresentation`）を持つ。

## 最小の実行例：三つの呼び出し形

次のセルは正則化した上側不完全 Gamma 関数 $Q(3, x)$ を三つの形で評価する。
整数の形状では部分積分から $Q(3, x) = e^{-x}(1 + x + x^2/2)$ が成り立つので、これを独立な検算に使う。
実装は $x < 3$ では下側の補償付き級数で $P$ を求めてその補数を返し、$x \ge 3$ では同じ有限和を 3 項で足す。
したがって有限和との一致が独立な検算になるのは $x < 3$ の範囲である。

入力 `budget` はオプション付き形式とスコープ付き API に渡す `GammaOptions` の作業量の上限である。
標準形式はいつも既定の上限（65536）を使う。
表は形ごとに、値、推定絶対誤差とその根拠、終了状態（失敗した場合はエラーの分類）、反復回数、有限和との差、アルゴリズムの識別子、オプション付き形式の結果との一致を示す。
最後の結論はオプション付き形式の終了状態から決める。

```rust
//| id: special-api-forms
//| ref: special-api-forms
//| title: 上側不完全 Gamma を三つの形で評価する
//| run: reactive
//| crates: [scioxide-core, scioxide-special]
//| inputs:
//|   x: {"type":"range","label":"引数 x","description":"x < 3 では下側の級数、x ≥ 3 では整数形状の有限和で評価される。","min":0.5,"max":30,"step":0.5,"value":2}
//|   budget: {"type":"range","label":"作業量の上限 [単位]","description":"オプション付き形式とスコープ付き API の GammaOptions に渡す。標準形式は既定の 65536 を使う。","min":1,"max":64,"step":1,"value":64}
//| cases:
//|   - {"id":"small-budget","label":"上限 10","description":"級数は 20 回の反復を要するので、オプション付き形式とスコープ付き API は推定値を持たずに ConvergenceFailure を返す。","inputs":{"budget":10}}
//|   - {"id":"finite-sum","label":"x = 10、上限 10","description":"x ≥ 3 では 3 項の有限和を使うので、小さい上限でも完了する。","inputs":{"x":10,"budget":10}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"forms","path":"/rows/0/1","approx":{"value":0.6766764161830634,"rtol":1e-14}}
//|       - {"artifact":"forms","path":"/rows/0/6","range":{"max":1e-15}}
//|       - {"artifact":"forms","path":"/rows/1/4","equals":"Converged"}
//|       - {"artifact":"forms","path":"/rows/1/5","equals":20}
//|       - {"artifact":"forms","path":"/rows/1/7","equals":"gamma/lower_compensated_series@1"}
//|       - {"artifact":"forms","path":"/rows/0/8","equals":true}
//|       - {"artifact":"forms","path":"/rows/2/8","equals":true}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
//|   - case: small-budget
//|     expect:
//|       - {"artifact":"forms","path":"/rows/0/6","range":{"max":1e-15}}
//|       - {"artifact":"forms","path":"/rows/1/1","equals":null}
//|       - {"artifact":"forms","path":"/rows/1/4","equals":"ConvergenceFailure"}
//|       - {"artifact":"forms","path":"/rows/2/4","equals":"ConvergenceFailure"}
//|       - {"path":"/outputs/1/state","equals":"partial"}
//|   - case: finite-sum
//|     expect:
//|       - {"artifact":"forms","path":"/rows/1/1","approx":{"value":2.769395715511576e-3,"rtol":1e-13}}
//|       - {"artifact":"forms","path":"/rows/1/5","equals":3}
//|       - {"artifact":"forms","path":"/rows/1/7","equals":"gamma/integer_upper_finite@1"}
//|       - {"path":"/outputs/1/state","equals":"satisfied"}
use scioxide_core::{Budget, ExecutionContext, SciOxideError};
use scioxide_special::{
    GammaOptions, SpecialFunctionResult, gamma_q, gamma_q_scoped, gamma_q_with_options,
};

// (形, 値, 推定絶対誤差, 推定の根拠, 終了状態またはエラー, 反復回数, 有限和との差,
//  アルゴリズム, オプション付き形式との一致)
type Row = (
    &'static str,
    Option<f64>,
    Option<f64>,
    Option<String>,
    Option<String>,
    Option<usize>,
    Option<f64>,
    Option<String>,
    Option<bool>,
);
/// オプション付き形式またはスコープ付き API の結果を表の 1 行にする。
fn row(
    form: &'static str,
    outcome: &Result<SpecialFunctionResult<f64>, SciOxideError>,
    exact: f64,
    same: Option<bool>,
) -> Row {
    match outcome {
        Ok(result) => {
            let estimate = result.value();
            let value = estimate.map(|v| *v.value());
            (
                form,
                value,
                estimate.map(|v| v.absolute_error()),
                estimate.map(|v| format!("{:?}", v.reliability())),
                Some(format!("{:?}", result.termination())),
                Some(result.counts().iterations()),
                value.map(|v| (v - exact).abs()),
                Some(result.algorithm().to_string()),
                same,
            )
        }
        // 上限内に推定値ができなければ、オプション付き形式も結果を返さずにエラーになる。
        Err(e) => {
            let kind = Some(format!("{:?}", e.kind()));
            (form, None, None, None, kind, None, None, None, same)
        }
    }
}

let a = 3.0_f64;
// 独立な検算: 整数形状の有限和（f64 の固有メソッドによる参照値）。
let exact = (-x).exp() * (1.0 + x + 0.5 * x * x);
// 標準形式: 既定の上限で値だけを返す。
let plain = gamma_q(a, x).map_err(|e| e.to_string())?;
let limit = Budget::try_from(budget as usize).map_err(|e| e.to_string())?;
let options = GammaOptions::default().with_iteration_budget(limit);
// オプション付き形式: 同じ評価から値・推定誤差・終了状態・計数を返す。
let detailed = gamma_q_with_options(a, x, options);
// スコープ付き API: 根の評価として実行し、オプション付き形式と同じ結果を返す。
let scoped = gamma_q_scoped(a, x, options, ExecutionContext::sequential());

// 一致の判定: 標準形式はオプション付き形式の通常値とビット単位で、スコープ付き API は結果全体で比べる。
let reference = detailed.as_ref().ok().and_then(|r| r.try_value().ok());
let plain_same = reference.map(|v| v.to_bits() == plain.to_bits());
let scoped_same = match (&detailed, &scoped) {
    (Ok(d), Ok(s)) => Some(d == s),
    _ => None,
};
let plain_row: Row = (
    "標準形式",
    Some(plain),
    None,
    None,
    None,
    None,
    Some((plain - exact).abs()),
    None,
    plain_same,
);
let rows = vec![
    plain_row,
    row("オプション付き形式", &detailed, exact, None),
    row("スコープ付き API", &scoped, exact, scoped_same),
];
let sci3 = serde_json::json!({ "notation": "scientific", "significantDigits": 3 });
let digits16 = serde_json::json!({ "significantDigits": 16 });
let columns = serde_json::json!([
    { "key": "0", "label": "形" },
    { "key": "1", "label": "Q(3, x)", "type": "number", "format": digits16, "nullText": "—" },
    { "key": "2", "label": "推定絶対誤差", "type": "number", "format": sci3, "nullText": "—" },
    { "key": "3", "label": "推定の根拠", "nullText": "—" },
    { "key": "4", "label": "終了状態またはエラー", "nullText": "（返しない）" },
    { "key": "5", "label": "反復回数 [回]", "type": "integer", "nullText": "—" },
    { "key": "6", "label": "|値 − 有限和|", "type": "number", "format": sci3, "nullText": "—" },
    { "key": "7", "label": "アルゴリズム", "nullText": "—" },
    { "key": "8", "label": "オプション付き形式との一致", "type": "boolean", "nullText": "—" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = serde_json::json!({ "id": "forms" })
);

// 結論: オプション付き形式の終了状態から決める。上限による停止は partial とする。
let outcome = match &detailed {
    Ok(result) => {
        let termination = result.termination();
        let outcome = if termination.is_success() {
            Outcome::satisfied("オプション付き形式が上限の内で評価を完了した")
        } else {
            Outcome::partial("上限に達し、オプション付き形式は途中の推定値だけを保持した")
                .explanation("標準形式と try_value() は ConvergenceFailure を返す。")
        };
        let mut outcome = outcome.status(format!("{termination:?}")).diagnostic(
            "反復回数",
            result.counts().iterations() as f64,
            None,
        );
        if let Some(v) = result.value() {
            outcome = outcome.diagnostic("有限和との差", (*v.value() - exact).abs(), None);
        }
        outcome
    }
    Err(e) => Outcome::partial("上限に達し、オプション付き形式は推定値を返さなかった")
        .explanation("上限を級数の反復回数以上にすると、オプション付き形式も値を返す。")
        .status(format!("{:?}", e.kind())),
};
emit_outcome!(outcome);
```

既定の入力（$x = 2$、上限 64）では、下側の補償付き級数が 20 回の反復で収束し、三つの形の値はビット単位で一致する。
有限和との差は丸め誤差の程度で、推定絶対誤差より小さい。
アルゴリズムの識別子は選ばれた方法を示し、級数では `gamma/lower_compensated_series@1`、有限和では `gamma/integer_upper_finite@1` になる。
上限を級数の反復回数より小さくすると（ケース「上限 10」）、オプション付き形式とスコープ付き API は値を持たずに `ConvergenceFailure` を返し、結論は partial になる。
標準形式は既定の上限を使うので、同じ入力でも値を返す。
$x \ge 3$ では 3 項の有限和を使うので（ケース「x = 10、上限 10」）、反復回数は 3 で、小さい上限でも完了する。

この関数では上限に達すると推定値が残らないが、上限に達する前に有用な推定値ができる関数では、オプション付き形式は終了状態 `IterationLimit` でその推定値を返す。
その場合も、標準形式と `try_value()` は `ConvergenceFailure` を返す。
推定絶対誤差は区間の包含区間ではなく、「推定の根拠」の列がその種類を示す。

## 結果・エラー・診断の読み方

失敗は `SciOxideError` で返る。
`kind()` で分類を読み、`view()` で失敗した引数と詳細を読む。
エラーは何が失敗したかだけを表し、呼び出し元の識別子を持たない。

- NaN と無限大の引数は `NonFinite` になる。
  無限遠での極限は評価しない。
- 極は `DomainError`（詳細 `Pole`）、実数の定義域の外は `DomainError`（`OutsideDomain`）になる。
  近づく向きで極限が変わる点は `DomainError`（`Undefined`）で、例えば正則化不完全 Gamma 関数の $(a, x) = (0, 0)$ がこれに当たる。
- 次数のような整数のパラメータが範囲外なら `InvalidInput`（`OutOfRange`）になる。
- 値がスカラー型の範囲を超えると `NumericalInstability`（`Overflow`）、方法が解けない打ち消しで正しい桁が残らないと `NumericalInstability`（`LossOfSignificance`）になる。
  アンダーフローする値はエラーにせず、符号付きの 0 か非正規化数で返す。
- 作業量の上限に達すると `ConvergenceFailure`（`IterationLimit`）になり、エラーは試行した計数を持つ。
- スコープ付き API で取り消しや期限に達すると `ExecutionStopped` になる。

文書化された端点の極限だけが、`Ok(±∞)` のような非有限の成功値になる。
その場合、オプション付き形式の終了状態は `Limit`、通常値への射影の状態は `InfiniteLimit` である。
0 に丸めた値や非正規化数は有効な値である。

終了状態のうち `Exact`、`Converged`、`Limit` は完了した評価で、`is_success()` が真になる。
`IterationLimit` は作業量の上限に達したことを表す。
終了状態は、推定誤差が精度の目標を満たすかどうかを表さない。

推定誤差 `ValueWithError::absolute_error()` には三つの根拠（`EstimateReliability`）がある。
`ModelBased` は評価の打ち切り誤差と丸め誤差から導いた推定である。
`StatisticallyCalibrated` は高精度の参照値と照合して測った包絡で、値 $v$ に対して $k\max(\varepsilon\lvert v\rvert, \eta)$ の形をとる。
ここで $\varepsilon$ はスカラー型の計算機イプシロン、$\eta$ は最小の正の非正規化数、$k$ は関数ごとの定数である。
`Heuristic` は被覆についての主張を持たない。
どれも区間の包含区間（証明付きの上下限）ではなく、包含区間が要るときは `scioxide-validated` を使う。
大きな推定誤差はエラーに変えず、そのまま返す。
対数形の誤差は自然対数の単位で、相対誤差が 1/2 に達すると対数形を省く。

照合データ（独立に生成した高精度の参照値）で確かめた ULP の目標は、関数族ごとに異なる。
例えば実数の Γ、$\ln\Gamma$、$\psi$、Beta 関数は binary64 で 4 ULP、binary32 で 1 ULP、実数の Bessel・Airy 関数は両精度で 64 ULP である。
この目標は照合した範囲で成り立つものである。
複素数の引数と、目標を示していない関数には一様な ULP の仕様がなく、オプション付き形式の推定誤差を使う。
各表の「仕様の要点」が関数ごとの目標を示す。

通常値への射影の状態 `ScalarRepresentation` は `Finite`、`Overflow`、`InfiniteLimit` のどれかである。
0 に丸めた結果も `Finite` で、標準形式は `Ok(±0)` を返す。
通常値があふれる場合（`Overflow`）も、オプション付き形式の `scaled()`（仮数と 2 の冪の指数に分けた値）と `logarithmic()` が値を保持できる。
`bessel_k_scaled` のような名前付きの尺度化形は、文書化した指数因子を掛けた別の関数を返す。
