この表はゼータ関数、多重対数とその仲間、Lambert W と Wright omega の公開項目をまとめる。
`NumericScalar`（`f32`、`f64`、`Complex<f32>`、`Complex<f64>`）を受け取る関数は、実数と複素数で同じ名前を使う。
`RealScalar` だけを受け取るのは `hurwitz_zeta_log`、`clausen`、`lambert_w0`、`lambert_wm1` で、複素数の Lambert W は枝の番号を引数にとる別の関数 `lambert_w_complex` である。
各行は値だけを返す標準形式、オプションを受け取って `SpecialFunctionResult` を返すオプション付き形式 `*_with_options`、求解のスコープの中で評価するスコープ付き API `*_scoped(.., options, scope)` を並べる（[三つの呼び出し形](oxref:special-api-call-forms)）。
計算量が引数によらずほぼ一定の `dilog`、`spence`、`clausen` には、スコープ付き API がない。
オプション型は、ゼータ関数と eta 関数が `ZetaOptions`、二重対数・Spence 関数・多重対数が `PolylogOptions`、Lerch 関数が `LerchOptions`、Clausen 関数が `ClausenOptions`、Lambert W と Wright omega が `LambertOptions` である。
どれも作業量の上限（`ClausenOptions` は既定 128、ほかは 65536）だけを持ち、[結果型とオプション](../results-and-options/)に載せる。

すべての行に共通して、非有限の入力は `NonFinite`、表せない結果や計算の破綻は `NumericalInstability`、作業量の上限に達すると `ConvergenceFailure` になる。
複素数の評価は主値のべきと対数を使い、切断の上では虚部の符号付きゼロで岸を選ぶ。
複素数の評価には一様な ULP の仕様はない。

## Riemann・Hurwitz ゼータ関数と eta 関数

実数の Riemann ゼータ関数と eta 関数、$s > 1$ の実数の Hurwitz ゼータ関数は、照合した範囲で両精度とも 64 ULP 以内で、オプション付き形式の推定誤差は $64\varepsilon\lvert v\rvert$ 以下である（$v$ は値）。
$s < 1$ の実数の Hurwitz ゼータ関数は導いた絶対誤差を返し、$s \in [-60, 1)$、$q \in (0, 1000]$ で試験している。
その零点の近くでは相対誤差が大きくなり得るが、エラーにはしない。

## 多重対数と Lerch 関数

実数の二重対数と Spence 関数は、照合した範囲で両精度とも 64 ULP を目標とする。
一般の位数の多重対数、Lerch 関数、複素数の引数には一様な ULP の仕様がなく、値と導関数を独立な参照値と照合している。
二重対数と Spence 関数の実数の評価は固定の項数で済むので、スコープ付き API を持たない。

## Lambert W と Wright omega

実数の $W_0$、$W_{-1}$ と Wright omega は、照合した範囲で両精度とも 64 ULP を目標とし、分岐点 $-1/e$ の近くでは絶対誤差で照合する。
どれも Halley 反復で値を求め、分岐点の近くでは $u = W + 1$ の分岐の座標の級数から反復を始める。
複素数の枝には一様な ULP の仕様がなく、推定誤差は Halley の修正量と残差から導く。
