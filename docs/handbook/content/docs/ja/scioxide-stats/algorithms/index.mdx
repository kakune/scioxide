この節の各ページは、scioxide-stats の推定量を数学的に導き、その性質と実装の仕様を結び付ける。
ここでは、すべてのページに共通する記法と規約をまとめる。

## 記法

| 記号 | 意味 |
|---|---|
| $x_1, \dots, x_n$ | 観測。$n$ は記録の数 |
| $X_{(1)} \le \dots \le X_{(n)}$ | 昇順に並べた順序統計量 |
| $\bar x$、$\bar x_w$ | 算術平均、加重平均 |
| $M_k = \sum_i (x_i - \bar x)^k$ | $k$ 次の中心モーメントの和。$m_k = M_k/n$ は母集団の中心モーメント |
| $s^2$、$\sigma^2$ | 標本分散（除数 $n-1$）、母分散 |
| $w_i$、$W = \sum w_i$、$Q = \sum w_i^2$ | 重み、総重み、重みの 2 乗和 |
| $n_{\mathrm{eff}} = W^2/Q$ | Kish の有効標本サイズ |
| $F_n$、$Q(p)$ | 経験分布関数、分位点関数 |
| $\mathrm{SE}$ | 推定量の標準誤差（推定値） |
| $u$、$\varepsilon$ | 単位丸め（f64 で $2^{-53}$）、計算機イプシロン（$2^{-52}$） |

分散・共分散は、とくに断らない限り標本の値（除数 $n-1$）を指す。
母集団の値と区別が必要な場所では式で明示する。

## 入力の検査と欠測の扱い

scioxide-stats の関数は、統計量を計算する前に入力を検査する。
非有限値（NaN、無限大）は既定で `NonFinite` として拒み、空の標本や不正な重み・確率は `InvalidInput` として拒む。
検査に通らない入力で値を推測して計算を続けることはない。
行列や N 次元配列を一括で集約する関数は、値の配置を表す借用のビューと方針を受け取る。

`BatchView` は core の `StridedLayout` を借用し、`Axis::All` または `Axis::Index(i)` で標本軸を選ぶ。
多変量では `with_coordinates` で座標軸を指定し、残りの軸を独立な一括処理に使う。
モーメント、順序統計、ビン、分布関数、核密度、単調回帰がこのビューを共有する。
重みは `Weights::<_, Model>::new` で格納と意味を組にする。
`Frequency` は u64 の独立反復数、`Mass` は相対質量、`Reliability` は信頼度、`Analytic` は逆分散のモデルである。
対応しない統計量と重みの組は型で除く。

欠測マスクと重みは、物理的なストライドによらず、一括処理の番号を外側、標本の番号を内側にした観測順で与える。
座標ごとではなく観測全体に一つずつ付ける。
`MissingPolicy` は目印で欠測とした要素を、`NonFinitePolicy` は存在する NaN・無限大を、それぞれ拒否（既定の `Reject`）するか推定から除く（`Skip`）かを決める。
欠測は値を読む前に判定する。
`StatisticsOptions` が受理方針、実行意図、モーメントの次数、保持する領域のバイト数の上限をまとめる。
既定は欠測と非有限値を拒否する逐次実行で、ワーカーの機能と上限は `ExecutionContext` が供給する。
`MergePolicy::StablePartitions` を選ぶと、実行 Plan の区画を固定した順に結合し、エグゼキューターの完了順によらない結果を得る。
除いた要素の数は結果や診断に残る（例えば `BinnedDiagnostics::skipped`、`IsotonicDiagnostics::excluded`、検定の `omitted`）。
除いたことで標本の意味が変わらないか（欠測が値に依存していないか）は、データからは検証しない。

平均・分散・ロバストな量・順序統計は `Statistic` で選ぶ。
重みのない標本の代表的な量は、ワンショット関数 `mean`、`sample_variance`、`sample_standard_deviation`、`median`、`quantile`（型 7）、`minimum`、`maximum`、`mean_confidence_interval` で直接求められる。
`statistic(values, weights, selector)` と、軸に沿って集約する `statistics(view, selector)`・`rolling_statistics` は内部で作業領域を確保し、`statistics_into` と `rolling_statistics_into` は事前確保した `StatisticsWorkspace` を使う。
中央値は `Statistic::quantile` に確率 0.5 と `QuantileRule` を渡す。
結果の `StatisticValue` は複素数の位置と実数の散らばりを分ける。

作業領域は `workspace_requirements` で必要量を照会し、`try_reserve`・`check`・`workspace` で準備する。
要件には保持するモデルや形状、ワーカーの領域、全出力の待避を含む。
事前確保後の借用実行は数値処理で確保せず、失敗時は出力を変えない。

## 呼び出しの形

同じ計算を、必要な制御の量に応じていくつかの形で呼べる。
この章では引数と戻り値の形を次の名前で呼ぶ。

| 形 | 例 | 受け取るもの | 返すもの | 実行コンテキスト |
|---|---|---|---|---|
| ワンショット関数 | `mean(&x)`、`t_test_independent(&x, &y)`、`chi2_contingency_test(table)`、`kaplan_meier(&observations)`、`bootstrap(statistic, &x, &mut rng)`、`glm_fit(design, family, &y)` | 問題のデータだけ（乱数を使う関数は生成器も） | 答え | `sequential_native()` |
| 準備を一括して行うコンストラクター | `GaussianKde::new(&x)`、`PreparedPca::new(data)`、`PreparedCca::new(x, y)` | データだけ | 準備した値 | `sequential_native()` |
| 標準形式 | `PreparedGlm::fit(inputs)`、`PreparedRegression::fit(&y)`、`PreparedHuber::fit(&y)`、`PreparedArimaFit::fit(initial, bounds, solver)` | 準備した値と入力だけ | 新しく確保した結果 | `sequential_native()` |
| オプション付き形式 | `t_test_independent_with_options(&x, &y, TTestVariance::Pooled, options)`、`GaussianKde::with_options(view, batch, options)`、`kaplan_meier_with_options(&observations, confidence, options)`、`statistics_with_options(view, selector, options)` | 入力と手法の選択、最後にオプション | 新しく確保した結果 | `sequential_native()` |
| 出力先を指定する API | `statistics_into(view, selector, options, &mut out, &mut ws, context)`、`kaplan_meier_into(..., &mut out, &mut ws, context)` | 入力、オプション、出力、作業領域、コンテキストの順 | 出力に書く | 渡したコンテキスト |
| スコープ付き API | `fit_scoped(request, solver, options, scope)`、`cox_fit_scoped(...)`、`sobol_indices_monte_carlo_scoped(..., options, scope)`、`PreparedGlm::fit_scoped(inputs, scope)` | 入力、オプション、最後にコンテキスト | 値 | 渡したコンテキスト |

標準形式とオプション付き形式は結果を新しく確保して返すので、API ガイドの表では所有値を返す API とも呼ぶ。
ワンショット関数とコンストラクターが固定する選択は次のとおりで、ほかの選択はオプション付き形式で指定する。

| 選択 | ワンショット呼び出しの値 |
|---|---|
| 重み | 重みなし（重みのモデルを主題とする関数を除く） |
| 標本の散らばりの除数 | $n-1$ |
| 分位点 | Hyndman–Fan の第 7 種（線形補間） |
| 平均の区間 | 両側 95% の Student の t 区間、自由度 $n-1$ |
| 検定の対立仮説 | 両側（Chatterjee と Page の検定は `Greater`） |
| 検定の較正 | `Auto` |
| 連続性補正 | 半単位（2×2 の表の Pearson の統計量では Yates の補正） |
| 独立二標本の t 検定 | Welch（分散が等しいと仮定しない） |
| 符号付き順位検定の差 0 | 除く（`Discard`） |
| Brunner–Munzel の参照分布 | Student の t |
| 分散の検定の中心 | 中央値 |
| Anderson–Darling の k 標本の同順位 | 中央順位 |
| 中央値の検定で併合中央値に等しい観測 | 中央値より下に数える（`Below`） |
| 単調回帰の向き | 増加 |
| ロバストな傾きの切片 | 残差の切片 $y_i - \hat\beta_1 x_i$ の中央値（`Joint`） |
| 核密度推定の帯域幅 | Scott の規則、全共分散 |
| 欠測と非有限値 | 拒否 |
| ブートストラップ | 独立な BCa、9999 回、95% |
| 置換 | 独立な乱択の割り当て、9999 回 |

乱数を使うワンショット関数も生成器を引数に取り、内部でシードを決めることはない。
オプションの型は非公開フィールド、失敗しない設定子と `Default` を持ち、準備や実行のときに値を検査する。
スコープ付き API のコンテキストには、根の計算なら `ExecutionContext` を、ほかの計算の内側で呼ぶなら親の `SolveContext` を可変で渡す。
後者では、子の評価と乱数の生成が親の作業量の上限から差し引かれる。

## 推定値・統計的不確かさ・丸め誤差

この章では三種類の「誤差」を区別する。

- 丸め誤差は、浮動小数点の演算による、厳密な算術での値との差である。
  累積器は内部の状態を 2 進の指数を別に持つ拡張範囲の値で保持し、出力に反映する分散や標準誤差を照会のたびに独立に丸める。
  試験で確かめた丸めの範囲は、すべてのデータに対する前進誤差の保証ではない。
- 統計的不確かさは、同じ母集団から別の標本を取ったときの推定値のばらつきである。
  標準誤差、信頼区間、p 値がこれを表し、記録された仮定（独立性、正規性、交換可能性など）の下での推定である。
- Monte Carlo の誤差は、リサンプリングや模擬の反復数が有限であることによる誤差である。
  bootstrap の `mean_monte_carlo_error`、置換検定の `tail_uncertainty`、検出力の Wilson 区間がこれを表す。

信頼区間・信用区間・検定の p 値は、どれも数値的な包含区間（真値を必ず含む区間）ではない。
包含が保証された区間が必要な計算は scioxide-validated の章で扱う。

## 結果の確定と終了理由

- 数学的に定義されない量（空の標本の平均、1 点の標本分散、定数列の相関、空のビンの平均）は `None` で返す。
  入力の不正、表現できない結果、計算の破綻は `Err` で返し、0 や NaN で置き換えない。
  累積器の要約の照会は `Result<Option<S>, SciOxideError>` を返し、あふれた量だけが `Err` になる。
- 累積器の `observe`・`merge` と出力先を指定する API の `_into` の関数は、すべての検査と計算が成功してから状態や出力を書き換える。
  エラーのときは呼び出し側の状態と出力を変えない。
  作業領域の中身は失敗の後に変わりうるが、再利用できる。
- 反復や上限を持つ手続きの標準形式・オプション付き形式・スコープ付き API・出力先を指定する API は、上限・取り消し・期限で止まった場合も `Ok` でレポートを返し、成否を一つの終了理由の列挙型で伝える。
  `StatsTermination::Completed` は要求した作業の完了、`Converged` は数値的な停止条件の成立、`ExactFit` は残差のない当てはめを表す。
  `is_success()` と各手法の仮定を確認し、未完了の値を収束した推定値として扱わない。
- ワンショット関数は未完了の推定値を返さず、成功以外の終了理由をエラーに変える。
  `Stopped` は `ExecutionStopped`、`RankDeficient` は `Singular`、`BudgetExhausted`・`NotConverged`・`NoProgress`・`Separated` は `ConvergenceFailure` になる。
  `ConvergenceFailure` の理由は手続きと終了理由で異なり、たとえば GLM と Huber 回帰の `BudgetExhausted` は `IterationLimit` である（対応の全体は API ガイドの[終了理由](oxref:stats-api-termination-reasons)の表にある）。
- 分位点の定義、裾平均の境界の扱い、区間の方法と自由度、検定で実際に使った較正は、結果の型に記録される。

## まとめ

入力は計算の前に検査され、非有限値や不正な設定は値を推測して補わずにエラーとして示される。
既定の設定で一度だけ計算するならワンショット関数を使い、設定を変えるときはオプション付き形式、作業領域を再利用するときは出力先を指定する API、ほかの計算の内側で呼ぶときはスコープ付き API を選ぶ。
丸め誤差、統計的不確かさ、Monte Carlo の誤差は別の量で、信頼区間や p 値は数値的な包含区間ではない。
反復を伴う手続きの結果は、終了理由の `is_success()` を確かめてから推定値として使う。
