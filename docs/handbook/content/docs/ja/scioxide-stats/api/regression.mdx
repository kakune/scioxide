このページは設計行列と応答から係数を推定する手続きと、群の平均の比較をまとめる。
設計行列に切片の列を暗黙に加えないので、切片には 1 の列を含める。
`PreparedRegression` は設計を複製して分解し、`PreparedGlm` は設計と行の情報を複製する。
`PreparedOperatorRegression`、`PreparedOperatorGlm`、`PreparedHuber` は設計を借用する。
どの準備の型もバイトの上限を受け取り、準備と、準備から作る出力と作業領域をその上限で制限する。
十分な作業領域を渡した `fit_into` は数値計算の中で確保せず、エラーのときは呼び出し側の出力を変えない。
ワンショット関数 `ordinary_least_squares(design, response)` と `glm_fit(design, family, response)` は重みなしの設計を既定の設定で当てはめる。
`glm_fit` と `huber_location` は成功の終了だけを受け付け、それ以外の終了をエラーにする（`StatsTermination` とエラーの対応は [API ガイド](oxref:stats-api-termination-reasons)）。
準備の型の `fit` は逐次のネイティブ実行で結果を確保して返す。
`fit_scoped` は実行コンテキストか親の `SolveContext` を受け取るスコープ付き API、`fit_into` は呼び出し側の出力と作業領域に書く出力先を指定する API である。
反復する手続き（GLM の IRLS、Huber 回帰、作用素の Krylov 法）は scioxide-core の `SolveContext` の上限と取り消しに従う。
上限や取り消しで止まった場合も最後に受理した反復を `Ok` で返し、成否は終了理由だけで伝える。
GLM は試行ごとのレポート `GlmReport` に終了理由と受理した反復の数をまとめ、反復を一つも受理しなかった試行もレポートを返して出力を変えない。
p 値と区間は各項目に書いた仮定の下での値で、仮定が成り立つかはデータから検証しない。
