同じ入力が式に二度現れると、通常の区間演算は二つの出現を独立に動かす。
例えば $x\in[1-h,1+h]$ に対する $x-x$ は真には零だが、区間減算は $[-2h,2h]$ を返す。
アフィン演算は入力の不確かさに共通の記号を付け、加減算で相関を保つ。
相殺の実例から一歩進め、このページでは非線形な積の剰余と、記号を減らすときに失う情報を扱う。

## アフィン形式

実数のアフィン形式を、中心 $x_0$、係数 $x_i$、雑音記号 $\varepsilon_i\in[-1,1]$、剰余集合 $\Delta_x$ で表す。

$$
\widehat x=x_0+\sum_{i=1}^{m}x_i\varepsilon_i+\Delta_x.
$$

雑音記号は確率変数ではなく、範囲だけを指定した不確かさである。
二つの形式に同じ記号が現れれば、その記号の値は共通である。
剰余集合は記号で追跡しない誤差を包み、実数では区間、複素数では実部・虚部の長方形になる。
実数の対称な剰余 $[-r_x,r_x]$ なら、周辺の値域は $[x_0-s_x,x_0+s_x]$、$s_x=\sum_i|x_i|+r_x$ で含む区間を求められる。
この区間だけを取り出すと、他の形式との共通記号の情報は失われる。

加減算では同じ記号の係数を足し引きする。
例えば $\widehat x=1+0.1\varepsilon_1$ と $\widehat y=2+0.2\varepsilon_1$ の差 $2\widehat x-\widehat y$ は零である。
別の記号 $\varepsilon_2$ で作った $\widehat y$ には、この相殺は成り立たない。
入力区間が等しいことと、同じ不確かさを共有することは別である。

### 積と非線形関数の剰余

剰余のない二つの形式を $\widehat x=x_0+u$、$\widehat y=y_0+v$ と置くと、積は

$$
\widehat x\widehat y=x_0y_0+y_0u+x_0v+uv
$$

になる。
最初の三項は中心と既存記号の係数で表せるが、$uv$ は二次なのでアフィン形式にそのまま格納できない。
$|u|\le s_x$、$|v|\le s_y$ から $|uv|\le s_xs_y$ を使うと、この部分を新しい誤差項で包める。
実装は既存の剰余と丸め誤差も含めて評価し、保持できる記号数の範囲で誤差を記録する。

一変数関数でも $f(x_0+u)=f(x_0)+f'(x_0)u+\mathcal R$ と線形化し、残りの $\mathcal R$ を包む。
滑らかな関数で入力幅が小さければ、非線形剰余は入力幅の二次の程度になる。
ただし $f'(x_0)\ne0$ なら真の値域自体に一次の幅があり、結果の全幅が常に二次になるわけではない。
極や定義域の境界をまたぐ場合は線形化の前提を満たさず、区間だけの結果へ切り替わることがある。
その場合も `AffineFallback` と `AffineReport::status()` を読む必要がある。

## コンテキストと所有

`AffineContext::new(input_symbols, options)` は入力記号の集合を作る。
`from_coefficients(&context, center, coefficients)` は係数の位置をそのコンテキストの入力記号に対応付ける。
記号を明示する場合は `context.symbol(i)` と `AffineTerm::new` を使う。
コンテキストを別々に作ると、設定や係数が同じでも記号は別物であり、形式を組み合わせると `InvalidInput` になる。
同じコンテキストまたはその複製を共有する。

| 値 | 保持するもの | 使用場面 |
|---|---|---|
| `AffineForm` | 中心・剰余・項の容量 | `unary`・`binary` で結果を所有する通常の使い方 |
| `AffineState` と `AffineTerm` の配列 | 状態と項を別々に保持 | 呼出側がメモリ領域を管理する場合 |
| `AffineView` / `AffineViewMut` | 読み取り / 書き込み用の借用 | `unary_into`・`binary_into` などで出力を再利用 |
| `AffineWorkspace` | 演算中の一時領域 | 同じコンテキストとスカラー型で繰り返す計算 |

`AffineUnary` と `AffineBinary` は演算を選び、`AffineProjection` は実部または虚部への射影を選ぶ。
複素数の形式では、一つの実数の雑音記号が実部と虚部の係数を共有する。
したがって実部と虚部の周辺区間だけを別々に操作すると、その相関も失われる。

## 一次項が相殺する二次式

$x=1/2+h\varepsilon$ に対する $p(x)=x(1-x)$ を考える。
展開すると $p(x)=1/4-h^2\varepsilon^2$ なので、真の値域は $[1/4-h^2,1/4]$ である。
通常の区間積は $[1/2-h,1/2+h]$ の二つの因子を独立に扱い、その幅は $2h$ になる。
アフィン演算では一次項が相殺し、非線形な $\varepsilon^2$ の包含区間が主な幅として残る。

次のセルは半幅 $h,h/2,h/4$ で通常の区間積とアフィン積を比べる。
すべて無次元で、$h\le1/4$ として因子を非負に保つ。
二進数で正確に表せる入力を選び、手計算した値域を独立な参照として表示する。
wasm では参照表だけを出し、証明計算は未実行とする。

```rust
//| id: validated-affine-quadratic
//| ref: validated-affine-quadratic
//| title: 一次の相関と二次の剰余
//| run: button
//| crates: [scioxide-core, scioxide-validated]
//| inputs:
//|   half_width: {"type":"range","label":"半幅 h [-]","min":0.03125,"max":0.25,"step":0.03125,"value":0.125}
//| cases:
//|   - {"id":"wide","label":"h = 1/4","inputs":{"half_width":0.25}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","approx":{"value":0.234375,"atol":1e-15}}
//|   - case: wide
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","approx":{"value":0.1875,"atol":1e-15}}
use scioxide_core::{SciOxideError, SciOxideErrorView, InvalidInputReason};
use serde_json::json;
let unsupported = |error: &SciOxideError| {
    matches!(error.view(),
SciOxideErrorView::InvalidInput { argument, reason: InvalidInputReason::UnsupportedConfiguration, .. }
if argument == scioxide_core::argument!("rounding_environment"))
};
use scioxide_validated::{
    AffineBinary, AffineContext, AffineForm, AffineOptions, DecoratedInterval as D,
};
let reference: Vec<_> = (0..3)
    .map(|k| {
        let h = half_width / 2.0_f64.powi(k);
        (h, 0.25 - h * h, 0.25, h * h)
    })
    .collect();
emit_table_with_columns!(
    [
        "半幅 h",
        "真の下端（f64 参照）",
        "真の上端",
        "真の幅（f64 参照）"
    ],
    &reference,
    metadata = json!({"id":"reference"})
);
let proof = (|| -> Result<_, SciOxideError> {
    let context = AffineContext::new(1, AffineOptions::new().with_max_symbols(8))?;
    let mut work = context.workspace::<f64>()?;
    let one = AffineForm::constant(&context, 1.0)?;
    let mut rows = Vec::new();
    for &(h, _, _, _) in &reference {
        let x = AffineForm::from_coefficients(&context, 0.5, &[h])?;
        let y = one.binary(&x, AffineBinary::Sub, &mut work)?;
        let p = x.binary(&y, AffineBinary::Mul, &mut work)?;
        let ordinary = x.report().real();
        let interval = ordinary.mul(&D::point(1.0)?.sub(&ordinary)?)?;
        let (lo, hi) = p.report().real().set().bounds().unwrap();
        let (il, iu) = interval.set().bounds().unwrap();
        rows.push((
            h,
            lo,
            hi,
            hi.unwrap() - lo.unwrap(),
            iu.unwrap() - il.unwrap(),
            p.report().retained_symbols(),
        ));
    }
    Ok(rows)
})();
let outcome = match proof {
    Ok(rows) => {
        let fmt = json!({"notation":"scientific","significantDigits":6});
        emit_table_with_columns!(
            json!([
                {"key":"0","label":"半幅 h","type":"number","format":fmt},
                {"key":"1","label":"アフィン下端","type":"number","format":fmt},
                {"key":"2","label":"アフィン上端","type":"number","format":fmt},
                {"key":"3","label":"アフィン幅","type":"number","format":fmt},
                {"key":"4","label":"区間演算の幅","type":"number","format":fmt},
                {"key":"5","label":"保持記号数","type":"integer"}
            ]),
            rows,
            metadata = json!({"id":"bounds"})
        );
        Outcome::satisfied("三つの入力幅で値域を含む区間を求めた")
    }
    Err(e) if unsupported(&e) => Outcome::unavailable("この環境では証明計算は未実行"),
    Err(e) => return Err(e.to_string()),
};
emit_outcome!(outcome);
```


既定の半幅 $1/8$ では、通常の区間積の幅は $1/4$、アフィン演算の幅は真の幅と同じ $1/64$ になる。
半幅を半分にすると、通常の区間積の幅は半分、アフィン演算の幅はこの例では四分の一になる。
アフィン包含区間が真の値域より広ければ、その差は二次の依存関係を区間で包んだ過大評価である。
これは精度の固定保証ではなく、同じ入力幅の下での式と手法の比較である。
一般の $p(x)$ で同じ縮み方を期待する前に、一次項が消えるかを確認する。

## 記号の縮約と計算量

非線形演算を重ねると誤差の記号が増えるため、`AffineOptions::with_max_symbols` で上限を決める。
`reduce(k, workspace)` は小さい係数から剰余へ移し、記号を最大 $k$ 個に減らす。
包含は保つが、他の形式との相関は一部失われるので、後の差で相殺できるとは限らない。
`retained_symbols` と `discarded_symbols` が記号数、`correlation_lost` が相関を失った履歴を表す。
一度真になった `correlation_lost` は後続の結果でも真のままである。

項数 $m$ の基本的な演算は $O(m)$ で、所有する結果を返す形は結果用のメモリ領域を確保する。
`_into` の形では項のバッファーをコンテキストの最大記号数に合わせて確保し、一時領域を再利用する。
バイト上限を超える場合は `ResourceLimit` であり、単なる幅の悪化とは区別する。
`AffineFallback` がある結果は記号を持つ近似を利用できないので、実部・虚部の包含区間を確認する。

## まとめ

アフィン形式では同じ記号の係数をまとめることで線形相関を保存する。
非線形な積や関数の残りは誤差項で包むため、値域の幅と過大評価の幅を分けて比較する。
記号の縮約は包含を保つ代わりに相関を捨てるので、診断とその後の演算も確認する。
[相殺の例題](../../examples/affine-cancellation/)で零になる差を、[API 一覧](../../api/intervals-and-affine/)で所有型と借用型の仕様を確認できる。

アフィン演算の背景は de Figueiredo・Stolfi, *Affine arithmetic: concepts and applications*, Numerical Algorithms 37（2004）, 147–158 にある。
