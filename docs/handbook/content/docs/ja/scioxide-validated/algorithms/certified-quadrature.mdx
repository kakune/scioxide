通常の適応求積は次数の異なる則の差を誤差推定に使うことが多い。
検証付き求積では真の積分値を包む剰余の上界を与える必要がある。
このページでは一つの積分区間について積分値の包含区間を導出し、区分の仮定、適応二分割、証明用データの再検証へつなげる。

## 証明の条件

有限パネル $P=[a,b]$ の幅を $h=b-a\ge0$、積分を $I_P=\int_a^b f(x)\,dx$ とする。
区間拡張 $F(P)$ がパネル全体での値を含み、$f$ が有界で積分可能なら、積分平均もその区間に入る。
従って最も基本的な包含区間は $I_P\in hF(P)$ である。
この方法は微分を必要としないが、値域が広いパネルでは包含区間も広くなる。

### 台形則の剰余

$f$ が二階連続微分可能なら、端点を結ぶ一次補間の積分が台形則 $T_P=h(f(a)+f(b))/2$ である。
補間誤差を積分すると

$$
I_P=T_P-\frac12\int_a^b(x-a)(b-x)f''(x)\,dx
$$

となる。
重み $(x-a)(b-x)$ は非負で、その積分は $h^3/6$ なので、二階導関数の包含区間 $F_2(P)$ を使えば

$$
I_P\in \frac h2\bigl(F(\{a\})+F(\{b\})\bigr)-\frac{h^3}{12}F_2(P)
$$

を得る。
例えば $f(x)=x^2$、$P=[0,1]$ なら $T_P=1/2$、$f''=2$ なので補正は $-1/6$、結果は $1/3$ である。
これは二つの求積値の差から推定した誤差ではなく、導関数の包含を前提にした包含区間である。

### 4 点 Gauss–Legendre 則

八階連続微分可能なら、7 次までの多項式に厳密な 4 点 Gauss–Legendre 則 $G_4$ を使える。
八階導関数の包含区間を $F_8(P)$ とすると

$$
I_P\in G_4(f)+\frac{h^9}{1778112000}F_8(P)
$$

になる。
節点と重み自体も厳密な実数では一般に格納できないため、SciOxide は節点を包む狭い区間上で関数値を要求する。
オラクルが点入力だけを想定してその区間の幅を無視すると、保証の前提を壊す。
高次の剰余を使うほど少ないパネルで済むことがあるが、高階導関数を狭く包めなければ利点は小さくなる。

| `QuadratureAssumption` | 必要な包含区間 | 1 パネルの要求数 | 細分 |
|---|---|---:|---|
| `IntegrableRange` | パネル全体の値域 | 1 | する |
| `TwiceContinuouslyDifferentiable` | 両端の値とパネル上の二階導関数 | 3 | する |
| `EightTimesContinuouslyDifferentiable` | 4 節点の値と八階導関数 | 5 | する |
| `IntegrableSingularity` | 有限区分全体の積分 | 1 | しない |
| `ConvergentTail` | 無限端を持つ区分全体の積分 | 1 | しない |

## API と結果の解釈

`QuadraturePiece` は一つの区分とその仮定を保持する。
複数の区分を順に並べる場合は、隙間や内部の重なりがないようにし、検証器はそれらの凸包を全領域とする。
`QuadratureAssumption` は利用者の数学的な表明であり、検証器が滑らかさを自動証明するものではない。

`QuadratureOracle` は `QuadratureRequest` の `piece`、`domain`、`query` を読む。
`query` に応じて値域、二階導関数、八階導関数、積分の包含区間を出力配列へ書く。
全成分の包含区間を与えられれば `Established`、与えられなければ `Unavailable` を返す。
`Unavailable` の出力は使われないので、未知の値を零として埋めない。
実数の成分では `IntervalBox` の虚部を厳密な零とする。

### 適応二分割と停止

生成は各正則区分をパネルで覆い、各パネルの積分値の包含区間を外向きに加算して総和を求める。
次に、許容誤差に対する半径の比が最も大きいパネルを二分する。
非有界な包含区間を持つ正則パネルは先に分割するが、全てのパネルと総和が有限になるまでは有効な提案を返せない。
特異点と尾部の区分はオラクルが積分全体を包むため、`generate` はその区分の内部を細分しない。

`ErrorTolerance` は絶対・相対許容誤差とノルムを指定する。
実数一成分なら、総和区間の半径 $r$ が $\tau_{\rm abs}+\tau_{\rm rel}|m|$ 以下になることを目標にする。
$m$ は総和区間の中点であり、幅と半径を取り違えない。
複数成分では許容誤差の成分数と出力の次元を合わせる。

`QuadratureGenerationReport` の `has_enclosure()` は全領域の有限な提案があるかを示す。
`ToleranceReached` は要求精度に達したこと、`Limit(Capacity)` はパネル容量不足、`Limit(Resolution)` は分割点を表せないことを示す。
`FixedBounds` は細分できない区分の境界などが精度改善を制限した状態である。
包含区間が残った停止なら値を読むことはできるが、要求精度を満たしたとはいえない。

### 証明用データの再検証

`QuadratureCertificate` は `QuadraturePanel` の分割、各パネルの包含区間、総和を所有する。
`view()` の `QuadratureCertificateView` を `verify` に渡すと、パネルの被覆を検査し、オラクルから各境界を再計算する。
再計算した境界が記録した境界に入り、その外向きの和が記録した総和に入ると `Verified` になる。
`QuadratureVerificationStatus` はこの包含の判定で、生成時の許容誤差を検査し直す状態ではない。
従って容量不足で止まった広い提案でも、再検証が `Verified` になることはある。

`QuadratureRejection` は提案の被覆や境界などを受理できない理由、`QuadratureInconclusive` と `QuadratureProofFailure` は必要な境界を確立できない理由である。
コールバック自身のエラーは `Err` で伝播する。
生成の終了と再検証の状態は二列で示すと、精度未達と証明失敗を分けて判断できる。

## 導関数の情報と計算量の実験

$f(x)=e^x$ を $[0,1]$ で積分すると、解析値は $e-1$ で、全ての階数の導関数も $e^x$ である。
同じ区間拡張を値域・二階・八階の要求に使えるので、剰余の情報だけを変えた比較ができる。
セルでは絶対許容誤差とパネル容量を変え、三つの仮定の包含区間、半径、パネル数、二つの終了状態を並べる。
全て無次元で、解析値の列は f64 の参照値である。
wasm では参照値と設定だけを表示する。

```rust
//| id: validated-quadrature-assumptions
//| ref: validated-quadrature-assumptions
//| title: 剰余の情報とパネル容量の比較
//| run: button
//| crates: [scioxide-core, scioxide-validated]
//| inputs:
//|   exponent: {"type":"range","label":"絶対許容誤差 10^q の指数 q","min":-10,"max":-3,"step":1,"value":-6}
//|   capacity: {"type":"range","label":"パネル容量 [個]","min":1,"max":129,"step":16,"value":65}
//| cases:
//|   - {"id":"one-panel","label":"容量 1","inputs":{"capacity":1}}
//|   - {"id":"tight","label":"許容誤差 10⁻¹⁰","inputs":{"exponent":-10}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/0","approx":{"value":1.718281828459045,"atol":1e-14}}
//|   - case: one-panel
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/2","equals":1}
//|   - case: tight
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","approx":{"value":1e-10,"atol":1e-20}}
use scioxide_core::{SciOxideError, SciOxideErrorView, InvalidInputReason};
use serde_json::json;
let unsupported = |error: &SciOxideError| {
    matches!(error.view(),
SciOxideErrorView::InvalidInput { argument, reason: InvalidInputReason::UnsupportedConfiguration, .. }
if argument == scioxide_core::argument!("rounding_environment"))
};
use scioxide_core::{Complex, ErrorTolerance, NormSelection};
use scioxide_validated::{
    DecoratedInterval as D, IntervalBox, QuadratureAssumption as A, QuadratureObligation,
    QuadraturePiece, QuadratureQuery, QuadratureRequest, QuadratureTermination,
    QuadratureVerificationStatus, QuadratureVerifier, ValidatedOptions,
};
let tolerance = 10.0_f64.powf(exponent);
let cap = capacity.round() as usize;
let reference = std::f64::consts::E - 1.0;
emit_table_with_columns!(
    [
        "参照値 e − 1（f64、保証なし）",
        "絶対許容誤差",
        "パネル容量"
    ],
    vec![(reference, tolerance, cap)],
    metadata = json!({"id":"reference"})
);
let proof = (|| -> Result<_, SciOxideError> {
    let oracle = |request: QuadratureRequest<f64>, out: &mut [IntervalBox<f64>]| {
        if request.query == QuadratureQuery::Integral {
            return Ok(QuadratureObligation::Unavailable);
        }
        let value = D::from(request.domain).exp()?.hull();
        out[0] = Complex::new(value.set(), D::point(0.0)?.set());
        Ok(QuadratureObligation::Established)
    };
    let mut rows = Vec::new();
    let mut complete = true;
    for (label, assumption) in [
        ("値域", A::IntegrableRange),
        ("台形則", A::TwiceContinuouslyDifferentiable),
        ("4点 Gauss", A::EightTimesContinuouslyDifferentiable),
    ] {
        let pieces = [QuadraturePiece {
            domain: D::new(0.0, 1.0)?.set(),
            assumption,
        }];
        let verifier =
            QuadratureVerifier::<f64>::new(&pieces, 1, &oracle, ValidatedOptions::new())?;
        let tol = ErrorTolerance::scalar(tolerance, 0.0, NormSelection::Infinity)?;
        let (report, certificate) = verifier.generate(&tol, cap)?;
        let (bounds, verified) = if let Some(c) = certificate {
            let status = verifier.verify(c.view())?;
            (c.view().total[0].re.bounds(), Some(status))
        } else {
            (None, None)
        };
        let lo = bounds.and_then(|b| b.0);
        let hi = bounds.and_then(|b| b.1);
        let radius = lo.zip(hi).map(|(lo, hi)| (hi - lo) / 2.0);
        complete &= report.termination() == QuadratureTermination::ToleranceReached
            && verified == Some(QuadratureVerificationStatus::Verified);
        rows.push((
            label,
            report.panels(),
            lo,
            hi,
            radius,
            format!("{:?}", report.termination()),
            verified.map(|s| format!("{s:?}")),
        ));
    }
    Ok((rows, complete))
})();
let outcome = match proof {
    Ok((rows, complete)) => {
        let fmt = json!({"notation":"scientific","significantDigits":8});
        emit_table_with_columns!(
            json!([
                {"key":"0","label":"仮定と求積則"},
                {"key":"1","label":"パネル数","type":"integer"},
                {"key":"2","label":"下端","type":"number","format":fmt,"nullText":"包含区間なし"},
                {"key":"3","label":"上端","type":"number","format":fmt,"nullText":"包含区間なし"},
                {"key":"4","label":"半径","type":"number","format":fmt,"nullText":"包含区間なし"},
                {"key":"5","label":"生成の終了"},
                {"key":"6","label":"再検証","nullText":"未実行"}
            ]),
            rows,
            metadata = json!({"id":"rules"})
        );
        if complete {
            Outcome::satisfied("全ての則で精度達成と再検証が完了した")
        } else {
            Outcome::partial("精度未達または証明未完了の則がある。各行の状態を参照する")
        }
    }
    Err(e) if unsupported(&e) => Outcome::unavailable("この環境では証明計算は未実行"),
    Err(e) => return Err(e.to_string()),
};
emit_outcome!(outcome);
```


同じ容量でも、値域だけの則は変化の全幅を積分するため、台形則や Gauss 則より広い結果になりやすい。
既定値では値域の則は 65 パネルで容量上限に達し、台形則は 48 パネル、Gauss 則は 1 パネルで許容誤差を満たす。
三つとも再検証は `Verified` なので、容量上限の行にも有効な広い包含区間が残っている。
台形則の局所剰余は $O(h^3)$、4 点 Gauss 則は $O(h^9)$ なので、一様細分時の全体の打切り誤差はそれぞれ $O(h^2)$、$O(h^8)$ になる。
ただし表の半径には区間拡張の過大評価と丸めも入るため、この次数が無制限に続くわけではない。
容量 1 のケースでは、広い包含区間の再検証が成功しても生成の精度目標は満たさないという違いを確認する。

## 特異点・無限区間とメモリ領域

例えば $x^{-1/2}$ の $[0,\delta]$ の積分は $2\sqrt\delta$ であり、関数値は非有界でも積分は有限である。
この区分には `IntegrableSingularity` を使い、`Integral` の要求に対してこの閉形式を外向きに評価して返せる。
無限尾部で $|f(x)|\le Ce^{-\alpha x}$、$\alpha>0$ が証明できるなら、$[A,\infty)$ の尾部積分の絶対値は $Ce^{-\alpha A}/\alpha$ 以下となる。
こうした不等式の成立と定数の包含区間も利用者が保証する必要がある。
標本が小さいことだけから尾部の上界を作ってはならない。

`workspace(ProofRequest::refinement(capacity))` はパネル容量に応じた `QuadratureWorkspace` を事前確保する。
`generate_into` は呼出側の証明用データへ書き、`verify_scoped` で同じメモリ領域を使って再検証できる。
$N$ パネルの管理計算は $O(N\log N)$、メモリ領域は成分数を固定すれば $O(N)$ で、オラクルの計算コストは別に加わる。
ワンショット呼び出しの `integrate` は二階連続微分可能な有限区間の実関数を対象とし、既定の精度と最大 4096 パネルを使う。

## まとめ

積分の保証には、値域または剰余を含む導関数の包含区間が必要である。
生成の精度達成と、証明用データの包含の再検証を別々に確認する。
特異点・尾部では、積分全体を包むオラクルの根拠が必要になる。
[誤差関数の例](../../examples/erf-certified-quadrature/)では正規化係数も含めた保証を、[API 一覧](../../api/quadrature/)では各入出力の所有と借用を確認できる。

Gauss 求積の剰余は [NIST DLMF §3.5(v)](https://dlmf.nist.gov/3.5.v)、区間による積分の包含区間は Moore・Kearfott・Cloud, *Introduction to Interval Analysis*（SIAM, 2009）の第 6 章を参照できる。
