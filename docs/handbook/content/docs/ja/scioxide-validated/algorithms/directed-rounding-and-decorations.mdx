区間演算の正しさは、「丸め誤差が加わっても、真の実数値が計算した区間の外に出ない」という包含定理（Fundamental Theorem of Interval Arithmetic）に基づく。
`scioxide-validated` は丸め制御レジスタを書き換えず、最近接偶数丸めの候補値と、誤差なし変換と指数範囲の端での厳密比較による残差の符号を組み合わせて、外向きに丸めた端点（directed outward rounding）を求める。
基本演算の各端点は、最近接の候補値から高々 1 ulp 外側にあり、計算は $O(1)$ 時間でヒープ領域を確保しない。

## 外向き有向丸めの数学的定義と包含定理

実数体 $\mathbb{R}$ における二項演算 $\odot \in \{+, -, \times, /\}$ に対し、二つの区間 $X = [a, b]$ および $Y = [c, d]$ の厳密な像集合は

$$
X \odot Y = \{ x \odot y \in \mathbb{R} \mid x \in X, \, y \in Y \}
$$

と定義される。
除算では $y=0$ を除く。
浮動小数点数に境界記号 $-\infty,+\infty$ を加えた集合を $\mathbb{F}$ とすると、下向き丸めと上向き丸めは次のように定義される。

$$
\operatorname{down}(x) = \max \{ f \in \mathbb{F} \mid f \le x \}, \quad \operatorname{up}(x) = \min \{ f \in \mathbb{F} \mid f \ge x \}
$$

このとき、区間加算に対する包含定理は

$$
X + Y = [a + c, \, b + d] \subseteq [\operatorname{down}(a + c), \, \operatorname{up}(b + d)]
$$

として定式化される。
乗算 $X \times Y$ においては、四隅の直積候補 $\{ac, ad, bc, bd\}$ の最小値と最大値に対し、

$$
X \times Y \subseteq \left[ \operatorname{down}\left(\min_{x \in \{a, b\}, y \in \{c, d\}} xy\right), \, \operatorname{up}\left(\max_{x \in \{a, b\}, y \in \{c, d\}} xy\right) \right]
$$

を満たすように端点を外向きに丸める。
これにより、丸め環境の前提が満たされる限り、計算結果の閉区間は真の像集合を包含する。

## 厳密な残差判定による有向丸め

丸め方向の切り替えはハードウェア状態と最適化に影響する。
SciOxide は対応する環境で制御状態を変更せず、最近接候補と厳密な残差判定から外向き端点を構成する。
単に機械イプシロンを加減算する方法では、値の尺度や subnormal 領域に応じた包含を保証できない。

`scioxide-validated` は、ハードウェアの制御状態を変更しないアルゴリズムを採用している。


1. **最近接候補値の算出**: まず、ハードウェア標準の「最近接偶数丸め（round-to-nearest-even）」を用いて候補値 $q = \operatorname{fl}(a \odot b)$ を計算する。
2. **厳密な残差の符号**: 加算は TwoSum、乗算は FMA または分割積で丸め残差を保つ。
   除算と平方根も候補値の積の残差から符号を決める。
   残差の式は次のとおりである。
   - 加算：$r = a + b - q$
   - 乗算：$r = a \cdot b - q$
   - 除算：$r = a - q \cdot b$
   - 平方根：$r = a - q^2$
3. **厳密な符号判定による 1 ulp 補正**: 除算では分母の符号も考慮して真値と候補の大小を決める。
   残差が非正規化数より小さくなる積や桁あふれを含む場合は、固定長の整数仮数の厳密比較へ切り替える。
   どちらの経路でも端点はビット単位で一致する。
   複数項の厳密な縮約には広い整数累積器を使い、極端な積も最終の外向き丸めまで保持する。
   - 上端は真値が $q$ より大きいときだけ、直後の表現可能数へ動かす。
     除算では真値と $q$ の差の符号は $r/b$ の符号で決まり、負の分母では $r$ の符号と逆になる。
   - 下端は真値が $q$ より小さいときだけ、直前の表現可能数へ動かす。
   - 厳密に一致している場合（$r = 0$）、両端とも $q$ となり、区間幅は広がらない。
4. **桁あふれ**: 有限の入力から候補値が無限大になった場合、真値は最大の有限値 `MAX` を超えている。
   上向きの端点は $+\infty$（非有界）、下向きの端点は `MAX` とし、負側も対称に扱う。

この設計により、制御レジスタを書き換えずに基本演算の外向き端点を得る。
$q$ は最近接値なので、補正後の端点は真値に最も近い下向き・上向きの表現可能数になる。
初等関数の包含区間や複合式全体の幅が常に 1 ulp になるわけではない。

## 特異点・非有界端点・符号付きゼロの実数論的規約

IEEE 754 浮動小数点規格と実数の集合 $\mathcal{P}(\mathbb{R})$ の演算の間には、いくつかの相違点がある。
`scioxide-validated` は実数集合の規約に従う。

### ゼロと非有界の積

IEEE 754 では $0.0 \times (+\infty)$ は未定義演算として `NaN` を返すが、実数集合論において空でない任意の実数集合 $S \subseteq \mathbb{R}$ に対するゼロ倍は、厳密に単一の点 $\{0\}$ である：

$$
\{ 0 \cdot x \mid x \in [1, +\infty) \} = \{ 0 \}
$$

したがって、`scioxide-validated` において $[0, 0] \cdot [1, +\infty)$ は `NaN` にならず、厳密に $[0, 0]$ を返す。
`ExtendedInterval` の非有界端点（`None`）は集合が無限遠に広がっていることを示す境界記号であり、無限大という実数が集合に含まれているわけではない。

### 符号付きゼロの正規化

浮動小数点数には $+0.0$ と $-0.0$ の二つのゼロがあるが、実数のゼロは一つである。
`scioxide-validated` では、下端が 0 となった場合は $-0.0$、上端が 0 となった場合は $+0.0$ に正規化して格納する。
IEEE の数値比較では正負の零は等しい。
この正規化は端点表現を一貫させるための規約であり、零どうしの大小比較が異なるためではない。

### 除算における左右極限の分離

分母区間 $Y = [c, d]$ が 0 を内部に含む場合（$c < 0 < d$）、商の集合は負側と正側に分かれる。
`scioxide-validated` は $Y$ を負の領域 $[c, -0.0]$ と正の領域 $[+0.0, d]$ に分け、符号付きゼロで片側極限を表して四隅の商を求め、二つの商区間の凸包（hull）を返す。
逆数を丸めてから乗算すると幅が広がるので、商は直接計算する。
分母が零を含む場合（端点が零の場合も含む）、decoration は `Trv` になり、分母が $\{0\}$ だけなら空集合を返す。

## Decoration の束代数と伝播則

演算の過程で付与される論理的根拠 [`Decoration`](https://docs.rs/scioxide-validated/0.1.0/scioxide_validated/enum.Decoration.html) は、全順序束（total order lattice）を形成する：

$$
\operatorname{Trv} < \operatorname{Def} < \operatorname{Dac} < \operatorname{Com}
$$

合成演算 $h(x) = (f \odot g)(x)$ が実行されるとき、結果の付随情報 $\operatorname{dec}(h)$ は以下の束演算規則に従って決定される：

$$
\operatorname{dec}(h) = \min\big( \operatorname{dec}(f), \, \operatorname{dec}(g), \, \operatorname{prop}(\odot, X, Y) \big)
$$

ここで $\operatorname{prop}(\odot, X, Y)$ は演算固有の性質を表す。
除算で分母が 0 を含んでいた場合や平方根で負領域を切り捨てた場合は $\operatorname{Trv}$ となり、結果の decoration も $\operatorname{Trv}$ になる。
さらに結果の集合が許す上限で抑えられ、空集合は $\operatorname{Trv}$、非有界な集合は $\operatorname{Dac}$ を超えない。
集合演算 `hull`・`intersection`・`restrict` の結果は常に $\operatorname{Trv}$ である。
演算が decoration を強めることはない。
`DecoratedInterval::with_decoration` は集合が許す範囲で呼出側が decoration を指定するコンストラクターであり、その根拠は呼出側が負う。

## 計算量と実行時不変条件

`DecoratedInterval` の演算と初等関数（`ElementaryEnclosure` を返すもの）は、次の条件を満たす。

1. **計算量**: 四則演算・自乗・平方根・集合演算の計算量は $O(1)$ である。
   区間の幅や値の大きさによって反復回数は変わらない。
2. **メモリ領域**: 成功した演算はヒープ領域を確保せず、スタック上の固定サイズの領域だけを使う。
   `ElementaryEnclosure` も最大二つの区間片を値として持つ。
3. **実行環境の検査**: 外向き丸めを使う演算は、出力に反映する算術の境界と利用者のコールバックから戻った時点で丸め制御レジスタ（x86（SSE2）・x86_64 では MXCSR と x87 の制御語、AArch64 では FPCR）を読み、書き換えはしない。
   内部の処理では検査を繰り返さず、呼び出しをまたいで検査結果を保持しない。
   確かめる条件は次の三つである。
   - 丸めモードが最近接偶数（Round to Nearest, Ties to Even）であること。
   - Flush-to-Zero (FTZ) と Denormals-are-Zero (DAZ) が無効で、段階的アンダーフローが働くこと。
   - 浮動小数点例外のトラップが無効（マスク済み）であること。

   これらが満たされない場合と、上記以外のアーキテクチャ（wasm32 を含む）では、包含区間を返さずに `kind()` が `SciOxideErrorKind::InvalidInput`（`view()` の理由は `InvalidInputReason::UnsupportedConfiguration`）のエラーを返す。
   構築、所属判定、`set`、`decoration`、集合演算は丸めを使わないので、この検査を行わない。

線形系・根・積分の検証は、検証のたびに元の問題から境界を再計算し、前の呼び出しの証明を使い回さない。
検証器と Plan は実行方針・計算回数の上限・バイト上限を `ValidatedOptions` として所有し、作業領域は検証器が返す要求で事前確保すると、以後の呼び出しで確保しない。
検証器で計算回数の上限に達した呼び出しはエラーではなく、結論なしの判定を返す。
ワンショット関数 `solve`・`roots`・`polynomial_roots`・`integrate` は既定の設定で同じ検証を行い、結論なしの判定をエラーに変える。
これらの仕様は API ガイドの [ワンショット関数による証明](oxref:validated-api-index-one-shot)、[検証器の設定と呼び出しの形](oxref:validated-api-index-configuration)、[作業領域の要求](oxref:validated-api-index-workspace) にある。
