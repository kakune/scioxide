精度保証付き計算では入力の集合から出力の集合を含む区間を求め、その包含区間を使って数学的な主張を確かめる。
値域の包含、方程式の解の存在、解の一意性はそれぞれ別の主張である。
幅の狭い区間が得られても、その区間に根があるとは限らない。

## 区間拡張の条件

実関数 $f$ の区間拡張 $F$ は入力区間 $X$ に対して $f(X)\subseteq F(X)$ を満たす。
`IntervalScalarFunction` を実装するクロージャは入力の全点における関数値を丸め誤差も含めて包む必要がある。
点での評価を区間の両端に代入するだけでは、区間内部の極値を取り逃がす。
検証器は狭すぎる区間拡張を見抜けないため、この条件は利用者が満たす必要がある。

実数値と複素数値を共通に扱う `IntervalBox<R>` は、実部と虚部の区間を持つ長方形である。
実数の問題では虚部を厳密な零の区間にする。
線形作用、残差、ヤコビ行列の作用には、それぞれ `IntervalLinearOperator`、`IntervalResidualOperator`、`IntervalJacobianOperator` を使う。
積分の値域と剰余の包含区間には `QuadratureOracle` を使う。

## 提案と証明

証明用データは中心、半径、探索領域、パネルなどの候補を保持するメモリ領域である。
証明用データを構築しただけでは数学的な主張は確立しない。
検証器は元の問題から必要な境界を再計算し、レポートの状態を返す。
とくに `QuadratureVerifier::generate` の成功は提案の生成を意味し、`verify` の成功と区別する。

| 処理 | 成功 | 成功しなかった場合の意味 |
|---|---|---|
| 線形系・求積の検証 | `Verified` | `Rejected` は提案を受理できない。`Inconclusive` は判定不能 |
| 根の主張の検証 | `Proved` | `Refuted` は反証。`Inconclusive` は主張も反対も未確定 |
| 根の分離・多項式の被覆 | `Complete` | 未決定の領域や容量・分解能の限界が残る |
| 求積の生成 | `ToleranceReached` | 要求精度を満たさない提案が残る場合がある。再検証が必要 |

ワンショット呼び出しの `solve`、`roots`、`polynomial_roots`、`integrate` は、検証済みまたは完全な結果だけを `Ok` で返す。
設定付きの検証器は結論なしも `Ok` のレポートで返すため、`?` の後に必ず状態を読む。
`ProofInconclusive` は評価・反復の上限、停止、非有界な境界、方法固有の判定不能を区別する。
`RefinementLimit` は出力の容量不足と、分割点などを表せない分解能の限界を区別する。

## 実行環境とメモリ領域

外向き丸めは最近接偶数丸め、段階的アンダーフロー、例外トラップの無効化を前提とする。
x86（SSE2）・x86_64・AArch64 以外ではこの前提を検査できず、`rounding_environment` を引数とする `UnsupportedConfiguration` を返す。
本書の wasm セルはこの場合だけ証明を「未実行」とし、通常の近似計算とは列を分ける。
集合の構築や交差など、丸めを使わない操作は wasm でも実行できる。

`ValidatedOptions` は評価回数・反復回数・メモリ使用量の上限と実行方針を保持する。
`LinearWorkspace`、`RootWorkspace`、`QuadratureWorkspace` は、それぞれ `LinearRequirements`、`RootRequirements`、`QuadratureRequirements` に従って事前確保する。
根と求積では `ProofRequest::proofs(k)` が一括検証数、`ProofRequest::refinement(c)` が節点・円板・パネルの容量を指定する。
容量が足りれば後続の呼び出しで作業領域を再確保せず、証明の境界自体は毎回計算し直す。
詳しい所有と借用は [API ガイド](../api/) で確認できる。

## まとめ

区間拡張は入力全体の値を包含する必要がある。
証明用データの内容と、再検証で成立した主張を区別する。
ワンショット関数は成功だけを返し、検証器は判定不能の理由も返す。
[例題](../examples/)ではこれらの違いを既知の解や値と比較できる。
