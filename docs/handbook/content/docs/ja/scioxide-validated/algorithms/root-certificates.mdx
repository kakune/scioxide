求根の反復が小さな残差で停止しても、探索領域に根が存在するとは限らない。
例えば $f(x)=x^2+10^{-20}$ は原点で残差が小さいが実根を持たない。
区間を使う検証は値と導関数の包含から存在・一意性・不在をそれぞれ確かめる。
一つの領域の主張を検証する操作と、指定した全領域を調べる根の分離を区別する。

## 証明の条件

$f$ は有界閉区間 $X=[a,b]$ の近傍で連続微分可能とする。
値の区間拡張を $F(X)\supseteq\{f(x):x\in X\}$、導関数の区間拡張を $D(X)\supseteq\{f'(x):x\in X\}$ と書く。
SciOxide に渡す二つのクロージャは同じ関数とその導関数を表し、証明中に意味を変えてはならない。
`IntervalScalarFunction` はこの呼び出し規約を表すトレイトで、クロージャがそのまま実装になる。

### 区間 Newton 写像の導出

$c\in X$ を選び、もし $x^*\in X$ が根なら、平均値の定理からある $\xi$ について

$$
0=f(x^*)=f(c)+f'(\xi)(x^*-c)
$$

と書ける。
$0\notin D(X)$ なら除算でき、全ての根は

$$
x^*\in N(X)=c-\frac{F(\{c\})}{D(X)}
$$

に含まれる。
この式の $F(\{c\})$ も点の通常計算ではなく、丸め誤差を含む包含区間である。
したがって $N(X)\cap X=\emptyset$ なら $X$ に根はない。
逆に $N(X)\subset\operatorname{int}(X)$ なら区間 Newton の包含定理により根が一意に存在する。
単に $N(X)$ が狭いことや $N(X)\cap X$ が非空であることは、存在の十分条件ではない。

別の存在証明は中間値の定理である。
端点の包含区間が厳密に逆符号、または端点・中心での包含区間が厳密な $[0,0]$ なら根の存在を示せる。
さらに $0\notin D(X)$ なら導関数は符号を変えず、関数は狭義単調なので根は高々一つである。
導関数が零を含まないことだけでは根があるとはいえず、存在の条件と組み合わせる。

| 主張 | 検証が使う十分条件 |
|---|---|
| `Empty` | $0\notin F(X)$、または $0\notin D(X)$ かつ $N(X)\cap X=\emptyset$ |
| `Exists` | 中心・端点で厳密な零、または端点の厳密な符号変化。`Unique` の証明も含意する |
| `Unique` | 存在と $0\notin D(X)$、または区間 Newton の厳密な内部包含 |

区間が空・非有界、または decoration が `Dac` 未満で連続性が分からないと、根の証明は結論なしになる。
定義域を外れた値を勝手に捨てて `Com` を付け直してはならない。
区間拡張自身が誤って狭い場合は検証器では検出できない。

## API と結果の解釈

`ScalarRootCertificate` は `region`、その中の有限な `center`、`RootClaim` を持つ。
`ScalarRootVerifier::new(&value, &derivative, options)` は二つの拡張を借用する。
`verify(certificate)` の `RootVerificationReport::status()` が唯一の判定である。

| 判定 | 読み方 | 次の判断 |
|---|---|---|
| `Proved` | 指定した主張が成立した | 主張の範囲内で結果を使う |
| `Refuted` | 主張の反対を示す事実を証明した | `evidence()` を読み、主張を修正する |
| `Inconclusive` | 主張も反対も決まっていない | 領域・拡張・作業上限を見直す |
| `NotRun` | 一括検証の欄がまだ実行されていない | 成功結果として使わない |

例えば一意な根を証明した領域で `Empty` を主張すれば `Refuted` になる。
広い区間で `Unique` を証明できなくても、直ちに `Refuted` にはならない。
`RootInconclusive` の `Reason(RootProofFailure::Inequality)` は方法の不等式が決まらなかったこと、`Domain` は拡張の連続性などの不足を示す。

### 二分木で全領域を調べる手順

`isolate(domain, tolerance, max_nodes)` は領域全体を根とする `RootIsolation` を作る。
各領域で根の不在または一意性を検証し、どちらも示せない領域を二分する。
証明済みの葉は残し、未決定の葉だけを細分する。
二分のたびに二つの子が必要なので、容量が不足すると `Limit(Capacity)` で止まる。
分割点を表せない場合は `Limit(Resolution)`、分割閾値で決着しない場合などは未決定のレポートになる。

`RootIsolationNode` は分割の軸と位置、または葉の主張を表す。
`RootIsolationView` は領域と木の借用で、`verify_isolation` に渡して葉を元の関数から再検証できる。
`RootIsolationReport::is_complete()` が真のときだけ、未調査の領域が残っていない。
一意な葉が見つかっても、別の未決定の葉に追加の根がある可能性は残る。

一変数では二つの葉が端点を共有でき、共通端点の根を両方の葉が数える場合がある。
そのため `isolated()` は必ずしも異なる根の個数ではない。
ワンショット呼び出しの `roots` はこの重複をまとめ、昇順で互いに重ならない区間を返す。
各区間は一意性を証明した最初の葉で、指定した幅に収束させた区間ではない。

次のセルは $f(x)=x^2-2$ に対する四つの主張と、$[-2,2]$ 全体の分離を実行する。
解析的な根は $\pm\sqrt2$ で、個数 2 を独立検算に使う。
入力は節点の容量だけで、値と領域は無次元である。
容量 1 では根の領域を二分できず、容量を増やすと二つの根を含む葉が得られる。

```rust
//| id: validated-root-claims-and-tree
//| ref: validated-root-claims-and-tree
//| title: 個別の主張と全根の分離
//| run: button
//| crates: [scioxide-core, scioxide-validated]
//| inputs:
//|   capacity: {"type":"range","label":"二分木の節点容量 [個]","min":1,"max":31,"step":2,"value":15}
//| cases:
//|   - {"id":"one-node","label":"容量 1","inputs":{"capacity":1}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/0","equals":2}
//|   - case: one-node
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","equals":1}
use scioxide_core::{SciOxideError, SciOxideErrorView, InvalidInputReason};
use serde_json::json;
let unsupported = |error: &SciOxideError| {
    matches!(error.view(),
SciOxideErrorView::InvalidInput { argument, reason: InvalidInputReason::UnsupportedConfiguration, .. }
if argument == scioxide_core::argument!("rounding_environment"))
};
use scioxide_core::StepTolerance;
use scioxide_validated::{
    DecoratedInterval as D, RootClaim, ScalarRootCertificate, ScalarRootVerifier,
    ValidatedOptions,
};
let n = capacity.round() as usize;
emit_table_with_columns!(
    ["既知の根の数", "節点容量"],
    vec![(2, n)],
    metadata = json!({"id":"reference"})
);
let proof = (|| -> Result<_, SciOxideError> {
    let two = D::point(2.0)?;
    let f = |x: D<f64>| x.square()?.sub(&two);
    let df = |x: D<f64>| x.mul(&two);
    let verifier = ScalarRootVerifier::new(&f, &df, ValidatedOptions::new());
    let mut claims = Vec::new();
    for (lo, hi, claim) in [
        (1.0, 2.0, RootClaim::Unique),
        (1.0, 2.0, RootClaim::Empty),
        (2.0, 3.0, RootClaim::Empty),
        (-2.0, 2.0, RootClaim::Unique),
    ] {
        let proposal = ScalarRootCertificate {
            region: D::new(lo, hi)?.set(),
            center: (lo + hi) / 2.0,
            claim,
        };
        let report = verifier.verify(proposal)?;
        claims.push((
            lo,
            hi,
            format!("{claim:?}"),
            format!("{:?}", report.status()),
            format!("{:?}", report.evidence()),
        ));
    }
    let domain = D::new(-2.0, 2.0)?.set();
    let (report, tree) = verifier.isolate(domain, StepTolerance::default(), n)?;
    let regions: Vec<_> = tree
        .isolated_regions()
        .map(|r| r[0].re.bounds().unwrap())
        .collect();
    let replay = verifier.verify_isolation(domain, tree.view())?;
    Ok((claims, report, regions, replay))
})();
let outcome = match proof {
    Ok((claims, report, regions, replay)) => {
        emit_table_with_columns!(
            ["下端", "上端", "主張", "判定", "確立した事実"],
            claims,
            metadata = json!({"id":"claims"})
        );
        emit_table_with_columns!(
            ["一意性を証明した下端", "上端"],
            regions,
            metadata = json!({"id":"regions"})
        );
        emit_table_with_columns!(
            [
                "節点数",
                "一意な葉",
                "除外した葉",
                "未決定の葉",
                "再検証の終了"
            ],
            vec![(
                report.nodes(),
                report.isolated(),
                report.excluded(),
                report.unresolved(),
                format!("{:?}", replay.termination())
            )],
            metadata = json!({"id":"tree"})
        );
        let result = if report.is_complete() && replay.is_complete() {
            Outcome::satisfied("全根の分離と再検証が完了した")
        } else {
            Outcome::partial("木に未決定の領域が残る")
        };
        result.status(format!("{:?}", report.termination()))
    }
    Err(e) if unsupported(&e) => Outcome::unavailable("この環境では証明計算は未実行"),
    Err(e) => return Err(e.to_string()),
};
emit_outcome!(outcome);
```


`[1,2]` の `Unique` と `[2,3]` の `Empty` は証明でき、`[1,2]` の `Empty` は反証される。
`[-2,2]` では導関数の包含区間が零を含むため、一度の検証では一意性を決められない。
これは実際に根が二つあるという解析的事実と矛盾しない。
全根を区別するには、分離の処理で負側と正側の領域を別々に検証する。
`Complete` と再検証の成功を確認してから、全根を調べ終えたと判断する。

## 連立方程式の Krawczyk 写像

$F:\mathbb R^n\to\mathbb R^n$、探索箱 $X$、中心 $c\in X$ に対して、$R$ を $J(c)^{-1}$ の近似とする。
写像 $T(x)=x-RF(x)$ の固定点を考えると、$R$ が正則なら固定点は $F$ の根である。
$X$ 内の線分上のヤコビ行列を包む $J(X)$ を使い、$T(X)$ を

$$
K(X)=c-RF(c)+(I-RJ(X))(X-c)
$$

で含む区間を求める。
$K(X)\subseteq X$ は箱の中に写る条件、$\|I-RJ(X)\|<1$ は縮小する条件である。
両方が成り立つと固定点定理から存在と一意性が従い、同時に $R$ の正則性も確立する。
SciOxide の `SystemRootVerifier` はこの二つをともに検査する。
$K(X)$ が一つでも成分方向で $X$ と交わらなければ不在を示せる。

値とヤコビ行列の作用は `IntervalResidualOperator` と `IntervalJacobianOperator` で与える。
ヤコビ行列を格納する必要はなく、全ての $x\in X$ と方向 $v\in V$ について $J(x)v$ を包む作用を実装する。
前処理の `IntervalLinearOperator` は一つの固定行列を表す必要がある。
複素数の問題では関数が正則であることが必要で、共役や絶対値を含む非正則な写像は実数の二倍次元に書き換える。
[連立方程式の実装例](../../examples/nonlinear-system-proof/)で通常の作用と区間作用を実装する。

## 精度と計算量

単独のスカラー検証は反復 1 回、関数・導関数の評価が合わせて 5 回以下である。
連立系の一回の検証は未知数 $n$ に対して作用素評価 $2n+3$ 回と反復 $n$ 回で、作用素内部の処理は別に加わる。
作業領域は作用素の一時領域を除いて $O(n)$ である。
`RootWorkspace` は検証数・節点容量に対応する `ProofRequest` から事前確保し、`verify_scoped`・`isolate_into` で再利用する。

多重根では導関数が零になるため、狭く分割しても単根向けの一意性条件を満たせないことがある。
近似根のすぐ近くでも丸めの幅によって端点の符号を決められない場合がある。
[Kepler 方程式](../../examples/kepler-uniqueness/)は、同じ根の周囲で提案を狭くしすぎると証明が難しくなる例である。
多項式の多重根には次の[円板内の個数の証明](../polynomial-root-counts/)を使える。

## まとめ

スカラーの根は値の符号、導関数の非零、Newton 写像の包含を組み合わせて検証する。
個別の主張の判定と、全領域の分離の終了状態を分けて読む。
連立系では箱への包含と縮小率をともに確認し、通常のヤコビ行列作用を証明用の区間作用と混同しない。
作業上限を増やしても解決しない判定不能には、多重根・定義域・丸めの幅を検討する。

包含定理は Moore・Kearfott・Cloud, *Introduction to Interval Analysis*（SIAM, 2009）の第 8 章、連立系の方法は Krawczyk, *Newton-Algorithmen zur Bestimmung von Nullstellen mit Fehlerschranken*, Computing 4（1969）, 187–201 を参照できる。
