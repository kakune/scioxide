近似解 $\widetilde x$ の残差 $b-A\widetilde x$ が小さくても、行列が悪条件なら解の誤差は大きくなりうる。
精度保証付きの線形計算は近似逆行列で残差を補正し、その補正が真の誤差をどこまで包めるかを確かめる。
ここでは実数の正方行列から導出し、区間係数・複素数・疎行列への適用条件を説明する。

## 証明の条件

$A\in\mathbb R^{n\times n}$、$b\in\mathbb R^n$ とし、$R$ を $A^{-1}$ の近似とする。
この段階では $A$ が正則であるとも、$R$ が十分正確であるとも仮定しない。
まず $B=I-RA$ を区間演算で包み、誘導無限大ノルムの上界

$$
q\ge\|B\|_\infty=\max_i\sum_j|B_{ij}|
$$

を求める。
$q<1$ なら $RA=I-B$ は Neumann 級数 $\sum_{k=0}^{\infty}B^k$ によって逆を持つ。
正方行列の積 $RA$ が正則なので $A$ も $R$ も正則となり、$Ax=b$ の解 $x^*$ が一意に存在する。
この議論は求めたい解の存在を先に仮定せず正則性を確かめるために必要である。

### 誤差方程式から半径への変換

$e=x^*-\widetilde x$、$z=R(b-A\widetilde x)$ と置くと

$$
e=z+Be
$$

が成り立つ。
ノルムを取って $\|e\|_\infty\le\|z\|_\infty+q\|e\|_\infty$ とし、右辺の誤差を左辺へ移すと

$$
\|e\|_\infty\le\rho=\frac{\|z\|_\infty}{1-q}
$$

を得る。
さらに成分ごとの行和の上界を $\mathrm{row}_i$ とすれば、$|e_i|\le|z_i|+\mathrm{row}_i\rho$ になる。
SciOxide は $z$、行和、除算を外向きに評価し、計算した半径に $1+4\varepsilon$ を掛けて再検証時の丸めにも余裕を持たせる。
$\varepsilon$ はスカラー型の機械イプシロンである。

利用者が半径ベクトル $r$ を与える場合は、$|z|+|B|r\le r$ を成分ごとに確かめる方法もある。
これは誤差の箱 $[-r,r]$ が誤差方程式で自身に写るという条件である。
`verify` はこの条件、または提案が上の縮小写像の上界を含むことを検査する。
提案が狭すぎて `Rejected(EnclosureTooNarrow)` になっても、解が箱の外にあると証明されたわけではない。
この十分条件で提案を受理できないという意味である。

### 前処理と条件数

$q$ が 1 に近いと $1/(1-q)$ が大きくなり、残差が小さくても保証半径は広がる。
一方、$q\ge1$ でも $A$ が特異とは限らず、$R$ を改善すると証明できる場合がある。
点の係数では、上のノルム誤差上界は真の誤差の高々 $(1+q)/(1-q)$ 倍に丸め・包含区間の幅の分を加えた程度である。
この比は下界 $\|e\|\ge\|z\|/(1+q)$ と上界 $\rho$ を比較すると得られる。
区間係数の不確かさがある場合へ、この点データの精度評価をそのまま拡張しない。

`bounds()` は $\|A\|$、$\|R\|$、$q$ を評価し、$q<1$ なら $\|A^{-1}\|\le\|R\|/(1-q)$ と条件数の上界も返す。
`solve()` のレポートはこれらを全て計算するわけではなく、`LinearBounds::inverse()` と `condition()` は `None` の場合がある。
残差、補正、保証半径、条件数は異なる量なので、同じ「誤差」の列にまとめない。

## API と結果の解釈

密な点行列なら `solve(&matrix, &rhs)` が最短の API である。
LU 分解と近似逆作用素を用意し、証明済みの `LinearCertificate` だけを返す。
LU の零ピボットによる `Singular` は浮動小数点の分解の失敗であり、厳密な特異性の証明ではない。

区間係数や複数の右辺には `LinearVerifier` を使い、問題の作用素と前処理の作用素を別々に渡す。
`DenseIntervalOperator::new(lower, upper)` は各成分の上下限を持つ二つの `MatrixView` を借用する。
点行列は `point(view)`、疎行列は共通の CSR 構造を持つ `SparseIntervalOperator` で表す。
疎構造の外の成分は厳密に零であり、値が不明な成分を省略してはならない。
`LuIntervalInverse::from_dense` / `from_sparse` は対応する分解から近似逆作用素を用意する。

右辺は `IntervalBox` の配列で渡す。
`point_enclosure` は保存したスカラー値そのもの、`interval_enclosure` は指定した実部・虚部の範囲を包む。
実数の問題では虚部を厳密な零にする。
複素行列のノルムは行ごとの $\sum_j(|\operatorname{Re}a_{ij}|+|\operatorname{Im}a_{ij}|)$ を使う。
これは実部と虚部を別成分として扱うノルムで、複素絶対値の行和とは異なる。

### 区間係数の全ての系を包む実験

$A=\operatorname{diag}(a_0,a_1)$、$a_0\in[2-\delta,2+\delta]$、$a_1\in[3-\delta,3+\delta]$、$b=(2,3)^T$ を考える。
$\delta<2$ なら各係数は正で、解の正確な範囲は $x_i\in[b_i/(b_i+\delta),b_i/(b_i-\delta)]$ である。
前処理を $R=\operatorname{diag}(1/2,1/3)$ とすると、厳密算術では $q=\delta/2$ となる。
$\delta=2$ では特異な行列が入力集合に含まれ、集合全体の正則性を証明できなくなる。

セルの配列は行優先で、四成分が $A_{00},A_{01},A_{10},A_{11}$ に対応する。
入力・解とも無次元である。
表の解析値は通常の f64 の除算による独立検算で、保証は `LinearVerifier` が出す区間の側にある。
wasm では解析値だけを表示する。

```rust
//| id: validated-linear-uncertainty
//| ref: validated-linear-uncertainty
//| title: 区間係数の幅と正則性の証明
//| run: button
//| crates: [scioxide-core, scioxide-linalg, scioxide-validated]
//| inputs:
//|   delta: {"type":"range","label":"対角係数の半幅 δ [-]","min":0,"max":2.5,"step":0.25,"value":0.25}
//| cases:
//|   - {"id":"singular-member","label":"δ = 2","inputs":{"delta":2}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","approx":{"value":0.8888888888888888,"atol":1e-14}}
//|   - case: singular-member
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","equals":null}
use scioxide_core::{SciOxideError, SciOxideErrorView, InvalidInputReason};
use serde_json::json;
let unsupported = |error: &SciOxideError| {
    matches!(error.view(),
SciOxideErrorView::InvalidInput { argument, reason: InvalidInputReason::UnsupportedConfiguration, .. }
if argument == scioxide_core::argument!("rounding_environment"))
};
use scioxide_linalg::MatrixView;
use scioxide_validated::{
    DenseIntervalOperator, LinearVerifier, ValidatedOptions, point_enclosure,
};
let reference: Vec<_> = [2.0, 3.0]
    .into_iter()
    .enumerate()
    .map(|(i, a)| {
        (
            i,
            (delta < a).then(|| a / (a + delta)),
            (delta < a).then(|| a / (a - delta)),
        )
    })
    .collect();
emit_table_with_columns!(
    json!([
        {"key":"0","label":"成分","type":"integer"},
        {"key":"1","label":"解析下端（f64 参照）","type":"number","nullText":"有界でない"},
        {"key":"2","label":"解析上端（f64 参照）","type":"number","nullText":"有界でない"}
    ]),
    reference,
    metadata = json!({"id":"reference"})
);
let proof = (|| -> Result<_, SciOxideError> {
    let lower = [2.0 - delta, 0.0, 0.0, 3.0 - delta];
    let upper = [2.0 + delta, 0.0, 0.0, 3.0 + delta];
    let r = [0.5, 0.0, 0.0, 1.0 / 3.0];
    let system = DenseIntervalOperator::new(
        MatrixView::from_slice(2, 2, &lower)?,
        MatrixView::from_slice(2, 2, &upper)?,
    )?;
    let inverse = DenseIntervalOperator::point(MatrixView::from_slice(2, 2, &r)?)?;
    let verifier = LinearVerifier::new(&system, &inverse, ValidatedOptions::new())?;
    let (report, certificate) =
        verifier.solve(&[point_enclosure(2.0)?, point_enclosure(3.0)?])?;
    let enclosure = certificate.map(|c| c.enclosure()).transpose()?;
    Ok((report, enclosure))
})();
let outcome = match proof {
    Ok((report, enclosure)) => {
        let rows: Vec<_> = (0..2)
            .map(|i| {
                let bounds = enclosure.as_ref().and_then(|x| x[i].re.bounds());
                (i, bounds.and_then(|b| b.0), bounds.and_then(|b| b.1))
            })
            .collect();
        let fmt = json!({"significantDigits":8});
        emit_table_with_columns!(
            json!([
                {"key":"0","label":"成分","type":"integer"},
                {"key":"1","label":"検証した下端","type":"number","format":fmt,"nullText":"証明なし"},
                {"key":"2","label":"検証した上端","type":"number","format":fmt,"nullText":"証明なし"}
            ]),
            rows,
            metadata = json!({"id":"solution"})
        );
        let q = report.bounds().map(|b| b.defect());
        emit_table_with_columns!(
            ["q の上界", "補正の上界"],
            vec![(q, report.correction())],
            metadata = json!({"id":"diagnostics"})
        );
        let result = if report.is_verified() {
            Outcome::satisfied("区間係数の全ての系を検証した")
        } else {
            Outcome::failed("この前処理では正則性を証明できなかった")
        };
        result.status(format!("{:?}", report.status()))
    }
    Err(e) if unsupported(&e) => Outcome::unavailable("この環境では証明計算は未実行"),
    Err(e) => return Err(e.to_string()),
};
emit_outcome!(outcome);
```


$\delta$ を増やすと、解析的な解の集合も保証半径も広がる。
保証区間は集合全体に対する共通の箱なので、各成分で解析的な最小区間に一致するとは限らない。
`Inconclusive(Reason(RegularityNotProved))` なら $q$ と前処理を見直す。
この実験の $\delta\ge2$ では実際に特異な成員があるが、一般の入力で同じ状態だけから特異性を結論してはいけない。

## 証明用データと作業領域の再利用

`LinearCertificate` は中心と非負の半径を所有し、`view()` / `view_mut()` はそれらの借用を返す。
`propose(rhs, center)` は利用者の近似解を中心として保証半径を求める。
`verify(rhs, certificate.view())` は既存の中心と半径を再検証する。
中心・係数・右辺を変更したら、以前の検証状態を使い回さない。

`workspace(right_hand_sides)` で `LinearWorkspace` を事前確保し、`solve_into` または `propose_into` に出力の借用とともに渡す。
`solve_block_into` は複数右辺をまとめ、行列についての一回の走査を共有する。
`Verified` 以外では線形系の出力は更新されないので、古い証明用データを今回の成功結果と誤認しない。
`LinearVerificationReport` の `status()` が判定、`LinearInconclusive` と `LinearProofFailure` が未確定の理由を表す。

密な点行列のワンショット呼び出しは $O(n^3)$ の演算と $O(n^2)$ のメモリ領域を使う。
作用素による証明では作用の計算コストが加わり、密な作用は $O(n^2)$、疎な作用は格納非零数に比例する。
疎行列であることだけで証明全体が $O(\mathrm{nnz})$ になるわけではない。

## まとめ

正則性は $q<1$、解の誤差は補正 $z$ と $1-q$ から評価する。
狭すぎる提案の棄却と正則性の判定不能を区別し、レポートが成功したときだけ出力を使う。
区間係数の保証は全ての成員を対象とするため、入力の意味を先に決める。
[Hilbert 行列の例](../../examples/hilbert-verified-solve/)では係数の丸めと保証対象の違いをさらに確認できる。

縮小写像を使う検証法は Neumaier, *Interval Methods for Systems of Equations*（Cambridge University Press, 1990）と、Rump の [Verification methods（2010）](https://www.tuhh.de/ti3/rump/intlab/ActaNumerica2010.pdf) で詳しく扱われている。
