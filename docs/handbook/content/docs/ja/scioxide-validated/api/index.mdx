`scioxide-validated` は、外向きに丸めた区間演算と、その上に構築した検証を提供する。
中心の型 [`DecoratedInterval<S>`](https://docs.rs/scioxide-validated/0.1.0/scioxide_validated/struct.DecoratedInterval.html) は、実数集合を保持する `ExtendedInterval<S>`（`scioxide-core`）と、定義域と連続性を保守的に記録する [`Decoration`](https://docs.rs/scioxide-validated/0.1.0/scioxide_validated/enum.Decoration.html) の組であり、演算を重ねても decoration が強まることはない。
初等関数は `ElementaryEnclosure`、相関を保つ演算は `AffineForm` が扱う。
線形方程式・根・積分を既定の設定で一度だけ証明するには、ワンショット関数 `solve`、`roots`、`polynomial_roots`、`integrate` を使う。
近似の提案を元の問題に対して検証するには、検証器 `LinearVerifier`、`ScalarRootVerifier`、`SystemRootVerifier`、`QuadratureVerifier` と Plan `PolynomialRootPlan` を使う。
ワンショット関数は証明が成り立った結果だけを返し、検証器と Plan は実行方針・計算回数の上限・バイト上限を `ValidatedOptions` として所有して、結論なしを含む判定をレポートで返す。
外向き丸めを使う計算は x86（SSE2）・x86_64・AArch64 の丸め環境の検査に通った場合だけ結果を返し、wasm32 では `InvalidInput`（`UnsupportedConfiguration`）のエラーになる。

## 型構造と不変条件：DecoratedInterval と Decoration

区間演算の計算結果には、単に「数値がどの範囲にあるか」という幾何学的情報だけでなく、「その演算の過程で定義域の逸脱や不連続点が存在しなかったか」という位相的・解析的情報が伴う必要がある。


[`Decoration`](https://docs.rs/scioxide-validated/0.1.0/scioxide_validated/enum.Decoration.html) は弱から強へと順序付けられた 4 段階の列挙型である：

1. **`Trv` (Trivial)**: 包含関係のみを主張する状態。
   空集合、特異点（零での除算や負数の平方根）の除外が発生した計算、一部だけ定義された初等関数、集合演算（`hull`・`intersection`・`restrict`）の結果に付く。
2. **`Def` (Defined)**: 入力区間の全域において、評価対象の写像が実数として矛盾なく定義されている。
   連続性の証明は伴わない。
3. **`Dac` (Defined and continuous)**: 入力区間の全域で関数が定義されており、かつ連続である。
   非有界区間を含む場合の上限 Decoration となる。
4. **`Com` (Compact)**: 入力および出力の双方が「非空かつ有界な閉集合（コンパクト集合）」であり、全域で連続写像である。
   最も強い数学的根拠を表す。

合成演算における Decoration は、各入力の Decoration の最小値 $\min(\text{dec}_1, \text{dec}_2)$、演算固有の制限（特異点の除外があれば `Trv`）、結果の集合が許す上限（空なら `Trv`、非有界なら `Dac`）で決まる。
演算が decoration を強めることはない。
`with_decoration` は呼出側が集合と decoration を組にするコンストラクターで、集合が許すより強い decoration（非有界な集合への `Com`、空集合への `Trv` 以外）だけを `InvalidInput`（`Inconsistent`）として拒否する。
それ以外の decoration の根拠は呼出側が負い、型で検査されるわけではない。

## 主要 API 逆引き対応表

目的とする数学的操作、呼び出すべきメソッド、シグネチャ、および適用上の注意点を以下に整理する。
`Result` を返す算術・初等関数は外向き丸めを使い、丸め環境の検査に失敗すると `InvalidInput`（`UnsupportedConfiguration`）を返す。
構築・所属判定・集合演算・取得は丸めを使わず、wasm32 でも動く。

| 実現したい操作 | 使用する型・メソッド | シグネチャの概要 | 不変条件・挙動の要点 |
|---|---|---|---|
| 有界区間の構築 | `DecoratedInterval::new` | `(S, S) -> Result<Self, SciOxideError>` | 端点は有限で $a \le b$。NaN・無限大は `NonFinite`、$a > b$ は `InvalidInput`（`Inconsistent`）。decoration は `Com` |
| 一点の区間の構築 | `DecoratedInterval::point` | `(S) -> Result<Self, SciOxideError>` | $[v, v]$ を `Com` で作る。NaN・無限大は `NonFinite` |
| decoration を指定した構築 | `DecoratedInterval::with_decoration` | `(ExtendedInterval<S>, Decoration) -> Result<Self, SciOxideError>` | 集合が許すより強い decoration は `InvalidInput`（`Inconsistent`）。根拠は呼出側が負う |
| 空区間の構築 | `DecoratedInterval::empty` | `() -> Self` | 要素を持たない区間 $\emptyset$。常に `Trv` |
| 全実数区間の構築 | `DecoratedInterval::entire` | `() -> Self` | 実数直線全体 $(-\infty, +\infty)$。自動で `Dac` |
| 半無限区間の構築 | `DecoratedInterval::from` | `(ExtendedInterval<S>) -> Self` | `ExtendedInterval::new(Some(a), None)` のように非有界端点を `None` で指定した集合から作る。decoration は集合が許す最強のもの（有界なら `Com`、非有界なら `Dac`、空なら `Trv`） |
| 二区間の加算 | `add` | `(&self, &Self) -> Result<Self, SciOxideError>` | 外向き丸め $[\operatorname{down}(a+c), \operatorname{up}(b+d)]$ |
| 符号反転 | `neg` | `(&self) -> Result<Self, SciOxideError>` | 厳密反転 $[-b, -a]$。Decoration は維持 |
| 二区間の減算 | `sub` | `(&self, &Self) -> Result<Self, SciOxideError>` | `add(&other.neg())`。同一変数の相殺は幅が広がる |
| 独立変数の乗算 | `mul` | `(&self, &Self) -> Result<Self, SciOxideError>` | 四隅の積の外向き包含。独立な二変数にのみ適用 |
| 同一変数の自乗 | `square` | `(&self) -> Result<Self, SciOxideError>` | 二つの因子が同じ変数であることを使う。$0 \in X$ なら下端は 0 |
| 区間の除算 | `div` | `(&self, &Self) -> Result<Self, SciOxideError>` | 分母の 0 を除外。定義可能商の凸包。除外があれば `Trv` |
| 逆数の計算 | `reciprocal` | `(&self) -> Result<Self, SciOxideError>` | $[1, 1].\operatorname{div}(self)$ と同等 |
| 区間の絶対値 | `abs` | `(&self) -> Result<Self, SciOxideError>` | $0 \in X$ なら下端 0、上端 $\max(\lvert a \rvert, \lvert b \rvert)$ |
| 平方根の計算 | `sqrt` | `(&self) -> Result<Self, SciOxideError>` | 負領域を除外。$a < 0$ なら `Trv`。全域負なら `empty()` |
| 一変数の初等関数 | `exp`、`ln`、`sin`、`cos`、`tan`、`atanh` など | `(&self) -> Result<ElementaryEnclosure<S>, SciOxideError>` | 最大二つの区間片と `EnclosureStatus` を返す。定義域外の入力はエラーではなく状態で示す。内部の包含区間の手順が破綻すると `NumericalInstability` |
| 二変数の初等関数・べき | `hypot`、`atan2`、`powf`、`log`、`powi` | `(&self, &Self)`、`powi` は `(&self, i32)`。戻り値は同上 | `atan2` は原点、`log` は底 1 と非正の値、`powf` は実数の定義域外の組を除外し、状態で示す。`atan2` は負の実軸をまたぐと $-\pi$ 付近と $+\pi$ 付近の二つの片になる |
| 実数点の包含判定 | `contains` | `(&self, S) -> bool` | $a \le x \le b$ を判定。空集合、NaN、無限大では `false` |
| 区間同士の包含判定 | `contains_interval` | `(&self, &Self) -> bool` | $\text{other} \subseteq \text{self}$ を判定。空区間は全てに含まれる |
| 最小凸包の生成 | `hull` | `(&self, &Self) -> Self` | 二つの区間を包含する最小区間。Decoration は `Trv` |
| 共通部分の抽出 | `intersection` | `(&self, &Self) -> Self` | 集合論的交差 $X \cap Y$。Decoration は `Trv` |
| 外部定義域による制限 | `restrict` | `(&self, &ExtendedInterval<S>) -> Self` | アプリオリな物理領域との交差。Decoration は `Trv` |
| 集合表現の取得 | `set` | `(&self) -> ExtendedInterval<S>` | 内部の `ExtendedInterval` を値として複製 |
| 付随情報の取得 | `decoration` | `(&self) -> Decoration` | 現在の `Decoration` 列挙子を取得 |
| 有界な区間への変換 | `Interval::try_from` | `(DecoratedInterval<S>) -> Result<Interval<S>, SciOxideError>` | decoration を捨てて有限の端点を取り出す。空か非有界な集合は `InvalidInput`（引数 `interval`）。確保しない |

包含区間の幅は演算によって異なる。
四則演算・逆数・自乗・平方根・絶対値・符号反転は、厳密な像の端点を隣の `f32`・`f64` へ外向きに丸めた最も狭い区間を返す。
初等関数は、点の引数に対して幅が浮動小数点数の 2 刻み以下であり、21 個の一変数関数について `f32` と `f64` で正しく丸めた参照値と照合して確かめてある。
区間の引数に対する初等関数の幅と、複合した式の幅には一般の上限はない。

## 最小実行例と結果の読み方

区間の構築、点包含判定、および初期付随情報の確認を行う最小コードセルを示す。

この実行例では、有限閉区間 $[1.0, 2.0]$ を構築し、内部点 $1.5$ の包含と外部点 $3.0$ の除外、ならびに構築時の decoration が `Com` であることを確認する。
構築と所属判定は丸めを使わない集合の比較なので、丸め環境の検査を行わず、ブラウザの wasm32 でも実行される。
出力は `inside` が真、`outside` が偽、`decoration` が `Com` である。

```rust
//| id: validated-api-membership
//| ref: validated-api-membership
//| title: 区間集合と初期の付随情報を読む
//| run: button
//| crates: [scioxide-validated]
//| tests:
//|   - case: default
//|     expect:
//|       - {"path":"/outputs/0/value/inside","equals":true}
//|       - {"path":"/outputs/0/value/outside","equals":false}
//|       - {"path":"/outputs/0/value/checked_point","equals":1.5}
//|       - {"path":"/outputs/0/value/decoration","equals":"Com"}
use scioxide_validated::DecoratedInterval;

// 1. 有限端点 [1.0, 2.0] を指定して DecoratedInterval を構築する
let interval = DecoratedInterval::new(1.0_f64, 2.0).map_err(|e| e.to_string())?;

// 2. 実数点 1.5 が区間内に含まれること（真）を確認する
let inside = interval.contains(1.5);

// 3. 実数点 3.0 が区間外に存在すること（偽）を確認する
let outside = interval.contains(3.0);

// 4. 所属判定結果と付随情報（Com）を JSON として出力する
emit_json!(&serde_json::json!({
    "inside": inside,
    "outside": outside,
    "checked_point": 1.5,
    "decoration": format!("{:?}", interval.decoration())
}));
```

## 区間演算以外の API

区間演算の上に置かれた検証は、提案（証明用データの候補）を作る処理と、元の問題から境界を再計算して提案を確かめる検証を分ける。
提案や証明用データのメモリ領域を持っているだけでは証明にならず、検証の状態だけが判定である。

| したいこと | ワンショット関数 | 検証器・Plan と関連項目 | 方法 | 検証の判定 |
|---|---|---|---|---|
| 相関を保って式を評価する | — | `AffineContext`（`AffineOptions`）、`AffineForm`、`AffineWorkspace` | アフィン演算 | `AffineReport`（外向きの包含区間、定義域の分類、相関を失ったかどうか） |
| 線形方程式 $Ax=b$ の解を含む区間を求める | `solve`（点の係数の密行列） | `LinearVerifier`（系の行列 $A$ と近似逆行列 $R$ の区間拡張）、`DenseIntervalOperator`、`SparseIntervalOperator`、`LuIntervalInverse`、`LinearCertificate` | 近似逆行列を前処理に使う縮小写像 | `LinearVerificationReport::is_verified()`（`status` が `Verified`） |
| 一変数の根の存在・一意性・不在を示す | `roots`（区間の中の根をすべて分離） | `ScalarRootVerifier`、`ScalarRootCertificate`、分離は `RootIsolation` | 区間 Newton 法 | `RootVerificationReport::is_proved()`、分離は `RootIsolationReport::is_complete()` |
| 非線形方程式系の根の存在・一意性・不在を示す | — | `SystemRootVerifier`、`SystemRootCertificate`、分離は `RootIsolation` | Krawczyk 法 | 同上 |
| 多項式の根の個数を円板ごとに示す | `polynomial_roots` | `PolynomialRootPlan`、`PolynomialRootCertificate`、`RootDisk`、分離は `PolynomialRootCover` | Rouché の包含判定と Pellet の判定 | `PolynomialVerificationReport::is_proved()`、分離は `PolynomialIsolationReport::is_complete()` |
| 有限・無限区間の定積分を含む区間を求める | `integrate`（有限区間、2 回連続微分可能な関数） | `QuadratureVerifier`、`QuadraturePiece`、`QuadratureAssumption`、`QuadratureCertificate` | 区間の矩形・台形・Gauss–Legendre 則の剰余の上界による適応二分割 | `QuadratureVerificationStatus::Verified` |

ワンショット関数は判定を返さず、検証が成り立たなければエラーを返す。
提案はどこから来てもよく、たとえば `scioxide-linalg` の近似解や `scioxide-rootfind` の根の推定値を使える。
`verify` は必要な境界をすべて元の問題から計算し直すので、証明用データは検証に成功したレポートと組にしたときだけ意味を持つ。
`LinearVerifier::solve` は解を含む区間を、`ScalarRootVerifier::isolate`・`SystemRootVerifier::isolate` は分離した葉の主張を、`PolynomialRootPlan::isolate` は円板ごとの根の個数を、それぞれ証明してから返す。
`LinearVerifier::propose` は自分の近似解の中心に誤差の上界を付け、証明が成り立ったときだけ証明用データを返す。
`QuadratureVerifier::generate` は提案を作るだけなので、`verify` に渡して証明する。

## ワンショット関数による証明

既定の設定で一度だけ証明するなら、ワンショット関数 `solve`、`roots`、`polynomial_roots`、`integrate` を使う。
どれも検証器か Plan を内部で一つ作り、作業領域と出力を確保して `ExecutionContext::sequential_native()` で走らせ、検証が成り立った結果だけを `Ok` で返す。
結論なしの判定、容量の上限、分割できない区間は `Ok` のレポートにならず、エラーとして返る。

| 関数 | 問題と既定の設定 | 返す値 | 証明が成り立たないとき |
|---|---|---|---|
| `solve(a, b)` | 点の係数の密な正方行列 $A$ と右辺 $b$。LU 分解から近似逆行列を作り、$2n + 3$ 回の作用素の適用で正則性と誤差の上界を示す。$O(n^3)$ の演算と $O(n^2)$ のメモリ領域 | `LinearCertificate`（中心と成分ごとの誤差半径） | LU の零のピボットは `Singular`（浮動小数点の分解の性質で、特異性の証明ではない）、正則性を示せないか上界が桁あふれすると `NumericalInstability` |
| `roots(f, df, lower, upper)` | 区間拡張 `f` と導関数の区間拡張 `df` で `[lower, upper]` の実数の根をすべて分離する。節点は 1023 個まで、葉 $[a, b]$ の分割の閾値は $\sqrt{\varepsilon}(1 + \max(\lvert a \rvert, \lvert b \rvert))$ | 昇順で互いに重ならない `Vec<Interval>`。各区間に根がちょうど一つあり、ほかに根はない。空のベクトルは根がないことの証明 | 節点の容量の不足、閾値まで決まらない葉（重根を含む）は `ConvergenceFailure`。空か連続性の分からない包含区間は `DomainError` |
| `polynomial_roots(coefficients, approximations)` | 昇順の係数と根の近似値。近似値ごとに半径 $\sqrt{\varepsilon}\max(\lvert \operatorname{Re} z \rvert, \lvert \operatorname{Im} z \rvert, 1)$ の円板から始め、Rouché の判定で決まらない半径を倍にし、重なる円板を併合する | `PolynomialRootCover`。各円板の中の根の個数（重複度込み）の和が次数に等しい | 個数の和が次数に届かないか半径を広げられないと `ConvergenceFailure`、零多項式は `InvalidInput` |
| `integrate(f, d2f, lower, upper)` | 2 回連続微分可能な実関数の区間拡張 `f` と 2 階導関数の区間拡張 `d2f`。台形則と剰余 $-(h^3/12) f''$ の適応二分割で、パネルは 4096 個まで。生成した証明用データを独立に検証する | 半径が $\sqrt{\varepsilon}(1 + \lvert \text{中点} \rvert)$ 以下の `Interval`。端点が等しければ $[0, 0]$ | 容量・分解能の上限と縮まらない境界は `ConvergenceFailure`、空か連続性の分からない包含区間は `DomainError`、非有界な証明は `NumericalInstability` |

`roots` と `integrate` のコールバックはコンテキストの引数を取らない `Fn(DecoratedInterval<S>) -> Result<DecoratedInterval<S>, SciOxideError>` である。
`roots` は二つの葉が共有する端点 $m$ を根として $[m, m]$ で返し、それ以外の区間は一意性を示した最初の葉で、幅は `upper − lower` より狭いとは限らない。
狭い包含区間が要るなら、得た区間の中の近似値の周りの狭い区間でもう一度呼ぶ。
区間の係数、疎行列、複数の右辺、無限区間、特異点、多成分の積分、計算回数の上限や作業領域の再利用、提案の検証には、検証器と `PolynomialRootPlan` を使う（[検証器の設定と呼び出しの形](oxref:validated-api-index-configuration)）。

次の二つのセルは四つの関数を小さな問題に一度ずつ使い、証明した包含区間と保証のない f64 の参照値を並べる。
wasm32 では四つの関数がどれも `InvalidInput`（理由 `UnsupportedConfiguration`、引数 `rounding_environment`）を返す。
二つのセルは、この拒否を見分ける関数を次の定義から共有する。

```rust
//| id: validated-api-environment
//| kind: definitions
//| title: 丸め環境の拒否を見分ける
//| crates: [scioxide-core]
use scioxide_core::{SciOxideError, SciOxideErrorView, InvalidInputReason};

/// 外向き丸めの前提を確かめられない環境での拒否だけを真にする。
pub(crate) fn unsupported(error: &SciOxideError) -> bool {
    matches!(
        error.view(),
        SciOxideErrorView::InvalidInput {
            argument,
            reason: InvalidInputReason::UnsupportedConfiguration,
            ..
        } if argument == scioxide_core::argument!("rounding_environment")
    )
}
```

最初のセルは区間を返す三つの関数を使う。
線形系は $A = \begin{pmatrix} 4 & 1 & 0 \\ 1 & 4 & 1 \\ 0 & 1 & 4 \end{pmatrix}$、$b = (1, 2, 3)$ で、厳密解は Cramer の公式から $x = (5/28, 2/7, 19/28)$ である。
根は $\cos x$ の $[0, b]$ の零点 $(2k + 1)\pi/2$、積分は $\int_0^1 e^x\,dx = e - 1$ である。
余弦と指数の包含区間は `ElementaryEnclosure::hull()` で一つの区間にまとめる。
入力 $b$ を変えると、分離する根の個数が変わる。
参照値の列はどの環境でも出るが、包含区間の列はネイティブ環境だけで埋まり、wasm32 では「未実行」と表示して outcome を `unavailable` にする。

```rust
//| id: validated-api-one-shot
//| ref: validated-api-one-shot
//| title: ワンショット関数で線形系・根・積分を証明する
//| run: button
//| uses: [validated-api-environment]
//| crates: [scioxide-core, scioxide-linalg, scioxide-validated]
//| inputs:
//|   upper: {"type":"range","label":"cos x の区間の右端 b [rad]","min":1,"max":20,"step":0.5,"value":10}
//| cases:
//|   - {"id":"wide","label":"b = 20","description":"(2k + 1)π/2 ≤ 20 の零点は k = 0, …, 5 の 6 個になる。","inputs":{"upper":20}}
//|   - {"id":"no-root","label":"b = 1.5","description":"π/2 ≈ 1.571 > 1.5 なので零点はなく、空の結果が根のないことの証明になる。","inputs":{"upper":1.5}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"one-shot-intervals","path":"/rows/0/0","equals":"solve"}
//|       - {"artifact":"one-shot-intervals","path":"/rows/0/4","approx":{"value":0.17857142857142858,"atol":1e-15}}
//|       - {"artifact":"one-shot-intervals","path":"/rows/5/1","equals":"cos x の零点 3"}
//|       - {"artifact":"one-shot-intervals","path":"/rows/6/4","approx":{"value":1.718281828459045,"atol":1e-15}}
//|   - case: wide
//|     expect:
//|       - {"artifact":"one-shot-intervals","path":"/rows/8/1","equals":"cos x の零点 6"}
//|   - case: no-root
//|     expect:
//|       - {"artifact":"one-shot-intervals","path":"/rows/3/0","equals":"integrate"}
use scioxide_core::{SciOxideError, Interval};
use scioxide_linalg::Matrix;
use scioxide_validated::{DecoratedInterval as D, integrate, roots, solve};
use serde_json::json;

let fixed15 = json!({ "fractionDigits": 15 });
let sci3 = json!({ "notation": "scientific", "significantDigits": 3 });
// 1. 参照値（f64、保証なし）: Cramer の公式の分数、cos の零点 (2k + 1)π/2、e − 1
let half_pi = std::f64::consts::FRAC_PI_2;
let zeros: Vec<f64> = (0..)
    .map(|k| f64::from(2 * k + 1) * half_pi)
    .take_while(|&z| z <= upper)
    .collect();
let mut references = vec![
    ("solve", "x₁".to_string(), 5.0 / 28.0),
    ("solve", "x₂".to_string(), 2.0 / 7.0),
    ("solve", "x₃".to_string(), 19.0 / 28.0),
];
for (k, &z) in zeros.iter().enumerate() {
    references.push(("roots", format!("cos x の零点 {}", k + 1), z));
}
references.push((
    "integrate",
    "∫₀¹ eˣ dx".to_string(),
    std::f64::consts::E - 1.0,
));
// 2. 三つのワンショット関数。どれも検証が成り立った結果だけを Ok で返す。
let proof = || -> Result<_, SciOxideError> {
    let a = Matrix::from_vec(3, 3, vec![4.0, 1.0, 0.0, 1.0, 4.0, 1.0, 0.0, 1.0, 4.0])?;
    let mut found = Vec::new();
    for x in solve(&a, &[1.0, 2.0, 3.0])?.enclosure()? {
        found.push(Interval::try_from(x.re)?);
    }
    let cos = |x: D<f64>| -> Result<D<f64>, SciOxideError> { Ok(x.cos()?.hull()) };
    let minus_sin = |x: D<f64>| x.sin()?.hull().neg();
    let zeros = roots(cos, minus_sin, 0.0, upper)?;
    let isolated = zeros.len();
    found.extend(zeros);
    let exp = |x: D<f64>| -> Result<D<f64>, SciOxideError> { Ok(x.exp()?.hull()) };
    found.push(integrate(exp, exp, 0.0, 1.0)?);
    Ok((found, isolated))
};
let proved = match proof() {
    Ok(results) => Some(results),
    Err(error) if unsupported(&error) => None,
    Err(error) => return Err(error.to_string()),
};
// 3. 区間の表。根の個数が参照と違えば、余った行の包含区間は None になる。
let found = proved.as_ref().map(|(found, _)| found.as_slice());
let mut contained = found.is_some_and(|found| found.len() == references.len());
let mut rows = Vec::new();
for (index, (call, target, reference)) in references.into_iter().enumerate() {
    let x = found.and_then(|found| found.get(index).copied());
    contained &= x.is_some_and(|x| x.contains(reference));
    let width = x.map(|x| x.upper() - x.lower());
    rows.push((
        call,
        target,
        x.map(|x| x.lower()),
        x.map(|x| x.upper()),
        reference,
        width,
    ));
}
let columns = json!([
    { "key": "0", "label": "関数" },
    { "key": "1", "label": "対象" },
    { "key": "2", "label": "包含区間の下端", "type": "number", "format": fixed15, "nullText": "未実行" },
    { "key": "3", "label": "包含区間の上端", "type": "number", "format": fixed15, "nullText": "未実行" },
    { "key": "4", "label": "参照値（f64、保証なし）", "type": "number", "format": fixed15 },
    { "key": "5", "label": "幅", "type": "number", "format": sci3, "nullText": "未実行" }
]);
emit_table_with_columns!(
    columns,
    rows,
    metadata = json!({ "id": "one-shot-intervals" })
);
let outcome = match proved {
    None => Outcome::unavailable("この環境では証明計算は未実行")
        .explanation("x86・x86_64・AArch64 のネイティブ環境で実行する。"),
    Some((_, isolated)) if contained => Outcome::satisfied(
        "三つの関数が証明した包含区間を返し、どれも参照値を含んだ",
    )
    .diagnostic("分離した cos x の零点の数", isolated as f64, None),
    Some(_) => Outcome::failed("参照値を含まない包含区間か、参照と異なる根の個数がある"),
};
emit_outcome!(outcome);
```

x86_64 のネイティブ環境では、線形系の三つの成分の包含区間の幅は $5.6 \times 10^{-17}$、$1.1 \times 10^{-16}$、$2.2 \times 10^{-16}$ で、どれも厳密解を含む。
$\cos x$ の零点は既定の $b = 10$ で $[1.25, 2.5]$、$[3.75, 5]$、$[7.5, 8.75]$ の 3 個に分離され、幅は 1.25 である。
これらは一意性を示した最初の葉で、根の近くに縮めた区間ではない。
$b = 20$ では 6 個、$b = 1.5$ では空のベクトルが返り、$[0, 1.5]$ に根がないことが証明される。
積分の包含区間は幅 $7.7 \times 10^{-8}$ で $e - 1$ を含み、半径は約束の $\sqrt{\varepsilon}(1 + \lvert \text{中点} \rvert) \approx 4.0 \times 10^{-8}$ 以下である。

次のセルは $p(z) = (z - 1)^2(z + 2) = 2 - 3z + z^3$ の根を `polynomial_roots` で数える。
根の近似値は $1 + \delta$、$1 - \delta$、$-2 - \delta$ で、ずれ $\delta$ を入力で選ぶ。
表は参照の根 $-2$（単根）と $1$（二重根）ごとに、それを含む円板の中心・半径と、その円板で証明した根の個数を示す。
円板への所属は f64 の距離で調べる保証のない検算である。
wasm32 では円板の列を「未実行」と表示して outcome を `unavailable` にする。

//| cases:
//|   - {"id":"coarse","label":"δ = 0.3","description":"近似値が根から離れると、Rouché の判定が成り立つまで円板の半径が倍になり、半径は δ の数倍になる。","inputs":{"offset":0.3}}

//|   - case: default

use serde_json::json;

let fixed6 = json!({ "fractionDigits": 6 });

// 昇順の係数 2 − 3z + z³ と、ずれ δ を持つ根の近似値

            .iter()

        multiplicity,
        center,
        disk.map(|c| c.disk.radius),
        disk.map(|c| c.count),

}
let columns = json!([
    { "key": "0", "label": "参照の根（保証なし）", "type": "number" },
    { "key": "1", "label": "重複度", "type": "integer" },
    { "key": "2", "label": "円板の中心の実部", "type": "number", "format": fixed6, "nullText": "未実行" },
    { "key": "3", "label": "円板の半径", "type": "number", "format": sci3, "nullText": "未実行" },
    { "key": "4", "label": "円板で証明した根の個数", "type": "integer", "nullText": "未実行" }

        .explanation("x86・x86_64・AArch64 のネイティブ環境で実行する。"),
    Some(cover) => Outcome::satisfied("円板ごとの根の個数の和が次数 3 に等しい被覆を証明した")

x86_64 のネイティブ環境では、既定の $\delta = 10^{-4}$ で $1 \pm \delta$ の二つの円板が併合され、中心 $1.0001$、半径 $3.2 \times 10^{-4}$ の円板に根 2 個、中心 $-2.0001$、半径 $1.2 \times 10^{-4}$ の円板に根 1 個が証明される。
$\delta = 0.3$ では二つの円板の半径が 1.1 と 0.575 に広がるが、個数は変わらない。
円板は根を含む範囲の証明であり、その半径の大きさは近似値のずれで決まる。

## 証明の判定条件

各検証器は元の問題から外向きの境界を再計算し、方法ごとの条件を確かめる。
導出と計算量は次の数理ページで説明する。

| 問題 | 判定の根拠 | 解説 |
|---|---|---|
| 線形系 | 近似逆行列による縮小率と補正の上界 | [正則性と解を含む区間](../algorithms/verified-linear-systems/) |
| 実関数・連立系の根 | 区間 Newton・Krawczyk 写像の包含 | [根の証明](../algorithms/root-certificates/) |
| 多項式 | Rouché・Pellet の厳密不等式 | [根の個数](../algorithms/polynomial-root-counts/) |
| 積分 | 値域・導関数・区分全体の積分の包含区間 | [検証付き求積](../algorithms/certified-quadrature/) |

## 検証器の設定と呼び出しの形

四つの検証器と `PolynomialRootPlan` は不変で、構築するときに `ValidatedOptions` を受け取って所有する。
検証器は問題と設定を組にするだけで、再利用する数値の準備はしない。
`PolynomialRootPlan` だけは構築時に係数を 2 のべきで拡大縮小して保持し、次数 $d$ に対して $O(d)$ の演算とメモリ領域を使う。
`ValidatedOptions::new()` は逐次実行、回数制限なし、バイト上限なしで、次の三つを変えられる。

- 実行方針（`with_execution_policy`）は、一括形の独立な証明をエグゼキューターのワーカーに最大 64 区画まで分ける。
  単独の証明は常に逐次に走り、結果は方針にもワーカー数にもよらない。
- 計算回数の上限（`with_budgets`）は、各呼び出しのエポックで使える評価回数・反復回数の局所的な上限である。
  一括形では、共通の準備の後に残った上限を証明ごとに決定論的に分ける。
  計算回数の上限に達した状態は結論なしの判定として返り、エラーにはならない。
- バイト上限（`with_byte_limit`）は、作業領域が保持する容量と、`LuIntervalInverse` のような準備済みのメモリ領域を抑える。
  超えると `ResourceLimit` のエラーになる。

各操作には作業領域と出力を自分で確保する形と、呼出側の作業領域とスコープを受け取る形が一つずつある。
前者（`verify`、`solve`、`propose`、`generate`、`isolate` など）は必要なメモリ領域を自分で確保し、`ExecutionContext::sequential_native()` で走る。
後者はレポートだけを返す `verify_scoped(…, workspace, scope)` のような `_scoped` の形か、出力も書く `solve_into(…, out, workspace, scope)` のような `_into` の形で、スコープは最後の引数である。
スコープに `ExecutionContext` を渡すと新しいエポックが始まり、`&mut SolveContext` を渡すと呼び出し元の解の子のエポックになる。
呼出側が解の識別子を作ることはない。
事前の検査で拒否された呼び出しとエラーになった呼び出しは、どの出力も変えない。
線形系の出力はレポートが `Verified` のときだけ変わる。
分離は停止で終わった `Ok` の呼び出しでもそこまでの木や円板を書き、求積の生成は全域を覆う提案ができたときだけ書く。

一括形（`verify_batch_into`、`solve_block_into`）は、証明ごとに一つのレポートの欄を受け取る。
欄は `LinearVerificationReport::not_run()`、`RootVerificationReport::not_run()`、`PolynomialVerificationReport::not_run()` で初期化し、状態 `NotRun` はまだ証明が走っていない欄を表す。
求積の一括検証は取り消しや期限で止まると、終わった検証も含めてすべての状態を `Inconclusive(Stopped(_))` にする。

## 作業領域の要求

作業領域は `LinearWorkspace`、`RootWorkspace`、`QuadratureWorkspace` の三つで、どれも同じ手順で用意する。

1. 検証器と Plan の `workspace_requirements` が要求（`LinearRequirements`、`RootRequirements`、`QuadratureRequirements`）を返す。
   線形系は右辺の列数を、根と求積は `ProofRequest` を受け取る。
2. `ProofRequest::proofs(k)` は単独の検証と k 個までの一括検証を覆う。
   `ProofRequest::refinement(c)` は、出力が c 個の節点・円板・パネルを持つ分離・被覆・生成の 1 回と、その再生を覆う。
3. 作業領域の `try_reserve` で事前確保し、`check` で `Capacity::Sufficient` か `Capacity::NeedsGrowth` かを確かめる。
   検証器と Plan の `workspace(…)` は要求の計算と事前確保をまとめて行う。
4. 容量が足りない作業領域は、コールバックを呼ぶ前に拡張される。
   要求を満たした作業領域では、以後の呼び出しは確保しない。
5. `last_attempt` は最後の呼び出しのエポック、結果（`Succeeded`・`Stopped`・`Failed`・`PreflightRejected`）、作業の回数を返す。

要求の `required_bytes` は新しい作業領域が確保する量で、`check` は再利用する作業領域が他の検証器のために保持している容量も含めてバイト上限と比べる。
一つの作業領域を複数の検証器で使うことができ、事前確保した最大の容量を保つ。
バイト上限を超える要求は `ResourceLimit`、拡張の失敗は `AllocationFailure`、短い借用出力は `DimensionMismatch` である。

## 区間拡張の提供と相関を保つ演算

検証に使う区間拡張は呼出側が提供する。
一変数の関数は `IntervalScalarFunction`、求積の照会は `QuadratureOracle` で、コンテキストの引数を取らないクロージャ `Fn(DecoratedInterval<R>)` と `Fn(QuadratureRequest<R>, &mut [IntervalBox<R>])` がそれぞれ実装する。
線形作用素・残差・ヤコビ作用素はそれぞれ `IntervalLinearOperator`、`IntervalResidualOperator`、`IntervalJacobianOperator` を実装する。
自分で実装するときは名前に `_scoped` の付かないメソッド（`enclose`、`residual_enclosure_into`、`jvp_enclosure_into`）を書き、`_scoped` のメソッドはコンテキストを捨ててそれを呼ぶ既定の実装のまま使える。
検証側は評価回数の上限を数えてから `_scoped` のメソッドを呼び、プロバイダーは別のクレートの `_scoped` の関数にコンテキストを渡すような入れ子の作業があるときだけ `_scoped` のメソッドを上書きしてコンテキストに計上する。
`IntervalLinearOperator` では `apply_enclosure_into` を書けば、`apply_enclosure_into_scoped` は停止の要求を確かめてからそれを呼ぶ既定の実装になる。
拡張が正しいことは呼出側の数学的な義務であり、検証側はこれを検出できない。
拡張は入力の集合のすべての点での値を、自身の評価の丸め誤差も含めて包む集合を返さなければならない。
点での評価や誤差の推定値は包含区間ではなく、拡張として使えない。
作用素の出力が非有界なら証明は結論なしになり、空の出力や形の変わった作用素は `InvalidInput` のエラーになる。

アフィン演算は検証器とは別の設定を持つ。
`AffineContext::new(input_symbols, AffineOptions)` が入力の雑音記号を用意し、`AffineOptions` は一つの形式が保持する記号数（既定は 16）と作業領域のバイト上限を決める。
保持しきれない項は匿名の剰余へ移り、包含区間を保ったまま相関の喪失として示される。
`context.workspace::<T>()` は保持する記号数を $m$ として $2(2m+2)$ 項分の一時領域を確保し、上限を超えると `ResourceLimit` になる。
演算は `AffineForm` の `unary`（`AffineUnary`）、`binary`（`AffineBinary`）、`project`（`AffineProjection`）、`reduce` で行い、各演算は項数 $n$ に対して $O(n)$ で結果を確保する。
`AffineBinary::Atan2` と `AffineBinary::Hypot` は実数の形式だけを受け付け、複素数の形式では `InvalidInput` になる。
`AffineView` の `unary_into`・`binary_into`・`project_into`・`reduce_into` は呼出側の `AffineViewMut` に確保せずに書く。

## 結果・エラー・診断の読み方

- **エラー**：失敗は `SciOxideError` で返る。
  `kind()` で分類し、`view()` で引数と理由を読む。
  エラーは呼び出し元の識別子を持たない。
  - `InvalidInput`：丸め環境の検査に通らない場合と非対応のアーキテクチャ（理由 `UnsupportedConfiguration`、引数 `rounding_environment`）、逆順の端点や集合が許さない decoration（理由 `Inconsistent`）、負の半径や区間の外にある中心のような不正な提案、隙間や重なりのある求積の区分、別々のコンテキストから作ったアフィン値、形が変わったり空や不正な包含区間を返したりする区間拡張。
  - `NonFinite`：NaN や無限大の端点・中心・半径・係数。
  - `DimensionMismatch`：問題と長さの合わない提案・出力・右辺。
  - `ResourceLimit`：`ValidatedOptions::byte_limit` か `AffineOptions::byte_limit` を超えるメモリ領域。
  - `SizeOverflow` と `AllocationFailure`：大きさを表せないメモリ領域と、確保できないメモリ領域。
  - `NumericalInstability`：必要な包含区間が非有界（`Overflow`）、ワンショット関数で正則性を示せない（`IllConditioned`）、内部の整合性の検査が失敗した（`Breakdown`）場合。
  - `ConvergenceFailure`：ワンショット関数が計算回数の上限・容量・分解能の上限に達した場合（理由 `EvaluationLimit`・`IterationLimit`・`ResourceLimit`・`StepSizeLimit`）と、判定が決まらないまま終わった場合（理由 `Stagnation`）。
  - `ExecutionStopped`：ワンショット関数が取り消しか期限で止まった場合。
  - `DomainError`：ワンショット関数に渡したコールバックが空の包含区間か、連続性の分からない（`Dac` 未満の decoration の）包含区間を返した場合（理由 `Undefined`）。
  - `Singular`：`solve` の LU 分解で零のピボットが出た場合。
    浮動小数点の分解の性質であり、行列が特異であることの証明ではない。

  コールバックが返したエラーはそのまま伝わる。
- **定義域外の入力**：零を含む分母や負の平方根はエラーではなく、除外して `Trv` の decoration で返る。
  初等関数は `EnclosureStatus`（`PartiallyDefined`、`Undefined`、`Inconclusive` など）で示す。
- **検証の状態**：検証器と Plan の各レポートは一つの状態を持ち、結果は次の三種類である。
  これらは `Ok` で返り、計算回数の上限に達した場合と停止の要求もエラーにならない。
  ワンショット関数は成功だけを `Ok` で返し、それ以外を上の `NumericalInstability`・`ConvergenceFailure`・`ExecutionStopped`・`DomainError` に変える。
  - 成功：線形系と求積は `Verified`、根は `Proved`。
  - 検査で提案が誤りと分かった：線形系と求積は `Rejected`、根は `Refuted`。
    `Rejected` は提案した半径や境界が狭すぎることを示すだけで、系が特異であることや積分が境界の外にあることは示さない。
    `Refuted` は主張が偽であることの証明である。
  - どちらでもない：`Inconclusive` と `ProofInconclusive` の理由。
    理由は `Unbounded`（必要な境界が有限でない）、`EvaluationLimit`・`IterationLimit`（計算回数の上限への到達）、`Stopped`（取り消しか期限）、`Reason`（方法ごとの判定の不成立）のどれかで、`Reason` には線形系の `LinearProofFailure`、根の `RootProofFailure`、求積の `QuadratureProofFailure` が入る。

  証明が成立しないことは反対の主張の証明ではなく、結論なしの根の証明は根の有無について何も言わない。
  線形系の `Rejected` は提案を確かめる `verify` だけが返し、検証器が自分で計算した半径（`solve`、`propose`、`propose_into`）は棄却されない。
- **分離と生成の終了状態**：根の分離と多項式の被覆は `RootIsolationTermination`（`Complete`、`Inconclusive`、`Limit`、`Refuted`）を返し、求積の生成は `QuadratureTermination`（`ToleranceReached`、`Inconclusive`、`Limit`、`FixedBounds`）を返す。
  `Limit` の理由 `RefinementLimit` は、出力の容量が尽きた `Capacity` と、分割する点や半径を表せない `Resolution` である。
  求積で提案を生成したときの終了状態は提案の作り方の診断で、証明ではない。
- **診断**：線形系の `LinearVerificationReport` はノルムの上界 `LinearBounds`、中心での残差の上界 `residual`、前処理後の残差の上界 `correction` を持つ。
  逆行列と条件数の上界は `bounds` だけが計算し、行列の走査を終えずに止まったレポートは上界を持たないことがある。
  根の `RootVerificationReport` はこの呼び出しで確立した最も強い事実（`evidence`）と Krawczyk 法の $\lVert I - R J(X) \rVert$ の上界（`defect`）を、多項式の `PolynomialVerificationReport` は証明した根の個数（`count`）を持つ。
  作業領域の `last_attempt` は最後の呼び出しの結果と作業の回数を返す。

## まとめと次に読むページ

`DecoratedInterval` の算術と初等関数は外向き丸めで包含区間を返し、丸め環境の検査に通らない環境では `InvalidInput`（`UnsupportedConfiguration`）を返す。
構築・所属判定・集合演算は丸めを使わず、どの環境でも動く。
線形系・根・積分を既定の設定で一度だけ証明するならワンショット関数 `solve`・`roots`・`polynomial_roots`・`integrate` を使い、結論が出なければエラーとして受け取る。
検証器と Plan は `ValidatedOptions` を所有し、作業領域は `workspace_requirements` の要求で事前確保すると以後の呼び出しで確保しない。
検証は提案を信用せずに元の問題から境界を計算し直し、レポートの状態だけが証明の判定になる。
成功（`Verified`・`Proved`）、提案の棄却や主張の反証（`Rejected`・`Refuted`）、`ProofInconclusive` の理由を持つ結論なし（`Inconclusive`）を区別して読み、結論なしを主張の否定と読まない。

- [区間演算の選び方](../choosing/)：演算の選び方と失敗の分類を確かめる。
- [外向き丸めと包含の数理](../algorithms/)：端点の丸め方と decoration の伝播則を確かめる。
- [区間の依存性と定義域の検証](../examples/)：既知の区間との照合と区間幅の増え方を確かめる。
- [Kepler 方程式と離心率](../../scioxide-rootfind/examples/kepler-equation/)：同じ方程式を通常の求根法で解き、浮動小数点の検算と包含が保証された区間の違いを確かめる。
