求積の API は被積分関数について何を仮定するか、要求された量をどう含む区間を求めるか、生成した提案をどう再検証するかを分けている。
設定を使わない最短の形は `integrate(value, second_derivative, lower, upper)` である。
許容誤差、特異点、無限尾部、多成分を扱う場合は `QuadratureVerifier` を使う。

## オラクルから証明用データまでの手順

1. `QuadraturePiece` の配列に領域の区分と仮定を指定する。
   有限の正則区分と、特異点・尾部の区分では要求される包含区間が異なる。
2. オラクルで `request.query` を分岐し、要求された量を全成分について `IntervalBox` へ書く。
   包めない要求には `Unavailable` を返し、未知の値を零にしない。
3. `QuadratureVerifier::new(&pieces, components, &oracle, options)` を作る。
   区分とオラクルは検証器が借用する。
4. `generate(&tolerance, max_panels)` で提案と生成レポートを得る。
5. 提案があれば `verify(certificate.view())` に渡し、再検証の状態を確認する。

| 観測するもの | 意味 |
|---|---|
| `has_enclosure()` | 全領域の有限な包含区間を記録した提案がある |
| `ToleranceReached` | 生成時に指定した精度を満たした |
| `panels()` | 提案を構成するパネルの数 |
| `Verified` | 元の問題から再計算した境界を提案が包含する |

`Verified` は指定した許容誤差の達成を単独で意味しない。
容量上限で止まった広い提案も検証できるので、精度達成には生成レポートと検証状態の両方を使う。
`QuadratureCertificateView::total` は成分ごとの総和の長方形で、実数問題では虚部を使わない。

## メモリ領域の確保と停止後の扱い

繰り返す場合は `QuadratureCertificate::new(capacity, components)` と `workspace(ProofRequest::refinement(capacity))` を用意する。
`generate_into` と `verify_scoped` に同じ作業領域を渡すと、必要容量を満たした後の確保を避けられる。
一括検証の停止時の状態は単独検証と混同せず、各欄を読む。
以前の呼び出しの証明用データが残っている可能性があるため、`has_enclosure()` を読まずに総和を表示しない。

[三つの仮定の実験](oxref:validated-quadrature-assumptions)は生成と再検証を同じセルで実行し、パネル容量と許容誤差を変更できる。
各剰余の導出と、特異点・尾部で必要な不等式は [求積の数理](../../algorithms/certified-quadrature/) にある。
