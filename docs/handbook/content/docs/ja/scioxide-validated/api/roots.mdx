根の API は一つの領域についての主張を検証する操作と、全ての根を覆う分離・被覆を作る操作に分かれる。
実関数の一変数問題、連立非線形方程式、多項式では入力の表し方が異なる。

## 問題と主張の組み合わせ

| 問題 | 問題の入力 | 提案するもの | 主な API |
|---|---|---|---|
| 実関数の根 | 値と導関数の区間拡張 | 区間、中心、`RootClaim` | `ScalarRootVerifier::verify` |
| 連立方程式の根 | 残差・ヤコビ行列の区間作用と固定した前処理 | 未知数ごとの箱、中心、`RootClaim` | `SystemRootVerifier::verify` |
| 多項式の個数 | 定数項から昇順の係数 | 複素円板と重複度込みの個数 | `PolynomialRootPlan::verify` |

スカラーの区間拡張は `Fn(DecoratedInterval) -> Result<DecoratedInterval, SciOxideError>` のクロージャで渡せる。
連立系には通常の作用と区間作用の実装が必要で、[円と直線の例](oxref:validated-system-provider)が四つのトレイトを示す。
多項式の Plan は係数をコピーして準備するので、係数を変える場合は Plan を作り直す。

## 所有・借用と再検証

一変数の証明用データは小さな値で、連立系の `SystemRootCertificate` は領域と中心の配列を所有する。
既に配列があるなら `SystemRootCertificateView` を直接組み立てて渡せる。
`view_mut()` で領域や主張を変えたら、以前のレポートは変更後の証明にはならない。
`RootVerificationReport::evidence()` は実際に確立した事実で、要求した主張と一致するとは限らない。

`RootWorkspace` はスカラー・連立系・多項式に共通だが、事前確保する容量は呼び出しに合わせる。
`ProofRequest::proofs(k)` は一括検証数、`refinement(c)` は節点または円板の容量を表す。
`NotRun` は一括検証の未使用の欄で、終了した証明の状態として扱わない。

## 分離結果の読み方

`RootIsolation` の木と `PolynomialRootCover` の円板群は、レポートが完全かどうかを確認して読む。
個々に証明した根があっても、未決定の領域が残れば全根の列挙とはいえない。
一変数の木の共有端点による重複は、ワンショット呼び出しの `roots` がまとめる。
多項式の被覆は個数の和と円板の分離を含めて `verify_cover` で検証できる。

[主張と二分木の実験](oxref:validated-root-claims-and-tree)、[円板の半径と個数](oxref:validated-pellet-multiplicity)で成功・反証・未確定を比較できる。
以下の索引では各型の仕様に加えて、その結果が証明する範囲を確認する。

### 多項式の根の個数
