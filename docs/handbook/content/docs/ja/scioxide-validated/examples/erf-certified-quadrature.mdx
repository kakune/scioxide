誤差関数は $\operatorname{erf}(x)=2\pi^{-1/2}\int_0^x e^{-t^2}\,dt$ で定義する。
積分だけを含む区間を求めても、正規化係数 $2/\sqrt{\pi}$ を通常の f64 値で掛ければ、全体の包含は保証されない。
ここでは $\pi=4\arctan 1$ を区間初等関数で包み、平方根と除算にも外向き丸めを使う。

被積分関数 $f(t)=e^{-t^2}$ の二階導関数は $f''(t)=(4t^2-2)e^{-t^2}$ である。
`integrate` にこの二つの区間拡張を渡す。
セルの入力 $x$ は無次元で $0\le x\le2$ とし、既定値は 1 とする。
独立な参照値は交代級数 $2\pi^{-1/2}\sum_{k\ge0}(-1)^k x^{2k+1}/(k!(2k+1))$ を f64 で評価したもので、証明には使わない。

## 導関数の包含区間の作り方

連鎖律から $f'(t)=-2te^{-t^2}$ であり、さらに微分すると $f''(t)=-2e^{-t^2}+4t^2e^{-t^2}$ となる。
従って `d2f` は $4t^2-2$ と $e^{-t^2}$ の区間積で構成できる。
同じ $t$ が複数回現れるため、この包含区間は最小とは限らないが、必要な包含は満たす。
求積器は二階導関数を数値差分で推定せず、利用者が与えた包含区間を台形則の剰余に使う。

$J=\int_0^x e^{-t^2}\,dt$ の包含区間を $[L,U]$、正の正規化係数の包含区間を $[c_-,c_+]$ とすると、$x\ge0$ では積は $[c_-L,c_+U]$ で包める。
実際のコードは符号も扱う区間積を使うので、端点の積の丸めも含められる。
$f64::consts::PI$ の一点区間を使っても、その区間は数学的な $\pi$ 自体を含むとは限らない。
そこで $\arctan(1)$ の保証付き包含区間から $\pi$ を構成する。

## 級数による独立検算

$e^{-t^2}=\sum_{k\ge0}(-1)^kt^{2k}/k!$ を積分すると、参照に使う級数が得られる。
セルでは $t_k=(-1)^kx^{2k+1}/k!$ を $t_{k+1}=-t_kx^2/(k+1)$ で更新し、$t_k/(2k+1)$ を足す。
この再帰は毎回階乗や大きなべきを計算する必要がない。
$0\le x\le2$ で 80 項を計算するが、和と定数の丸めを区間で包んでいないため、あくまで独立な数値の照合である。
参照値が包含区間に入ることだけを、積分の証明の代わりにはしない。

```rust
//| id: validated-erf-certified-quadrature
//| ref: validated-erf-certified-quadrature
//| title: 誤差関数の積分と正規化係数の包含区間
//| run: button
//| crates: [scioxide-core, scioxide-validated, scioxide-linalg]
//| inputs:
//|   x: {"type":"range","label":"積分上限 x","min":0,"max":2,"step":0.25,"value":1}
//| cases:
//|   - {"id":"zero","label":"x = 0","inputs":{"x":0}}
//|   - {"id":"two","label":"x = 2","inputs":{"x":2}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","approx":{"value":0.8427007929497149,"atol":1e-13}}
//|   - case: zero
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","approx":{"value":0,"atol":1e-13}}
//|   - case: two
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","approx":{"value":0.9953222650189527,"atol":1e-13}}
use scioxide_core::{SciOxideError, SciOxideErrorView, InvalidInputReason};
use scioxide_validated::DecoratedInterval as D;
use serde_json::json;
let unsupported = |error: &SciOxideError| {
    matches!(error.view(),
SciOxideErrorView::InvalidInput { argument,
reason: InvalidInputReason::UnsupportedConfiguration, .. }
if argument == scioxide_core::argument!("rounding_environment"))
};
let mut term = x;
let mut sum = x;
for k in 1..80 {
    term *= -x * x / (k as f64);
    sum += term / ((2 * k + 1) as f64);
}
let reference = 2.0 / std::f64::consts::PI.sqrt() * sum;
emit_table_with_columns!(
    ["x", "級数の参照値（f64、保証なし）"],
    vec![(x, reference)],
    metadata = json!({"id":"reference"})
);
let result = (|| -> Result<_, SciOxideError> {
    let f = |t: D<f64>| -> Result<D<f64>, SciOxideError> { Ok(t.square()?.neg()?.exp()?.hull()) };
    let d2f = |t: D<f64>| {
        D::point(4.0)?
            .mul(&t.square()?)?
            .sub(&D::point(2.0)?)?
            .mul(&f(t)?)
    };
    let integral = scioxide_validated::integrate(f, d2f, 0.0, x)?;
    let pi = D::point(1.0)?.atan()?.hull().mul(&D::point(4.0)?)?;
    let answer = D::from(integral).mul(&D::point(2.0)?.div(&pi.sqrt()?)?)?;
    let (lo, hi) = answer.set().bounds().unwrap();
    let rows = vec![(
        lo,
        hi,
        hi.unwrap() - lo.unwrap(),
        answer.contains(reference),
    )];
    Ok(rows)
})();
let outcome = match result {
    Ok(rows) => {
        let fmt = json!({"notation":"scientific","significantDigits":10});
        emit_table_with_columns!(
            json!([
                {"key":"0","label":"下端","type":"number","format":fmt},
                {"key":"1","label":"上端","type":"number","format":fmt},
                {"key":"2","label":"幅","type":"number","format":fmt},
                {"key":"3","label":"参照値を含む"}
            ]),
            rows,
            metadata = json!({"id":"integral"})
        );
        Outcome::satisfied("包含区間の計算が完了した")
    }
    Err(error) if unsupported(&error) => Outcome::unavailable("この環境では証明計算は未実行")
        .explanation("対応するネイティブ環境で証明を実行する。"),
    Err(error) => return Err(error.to_string()),
};
emit_outcome!(outcome);
```

## 結果の幅と許容誤差

$x=0$ では積分区間の幅が零なので積分も厳密に零で、正規化係数との積も零になる。
$x=1$ の参照値は約 $0.84270079295$、$x=2$ では約 $0.99532226502$ で、被積分関数が正なので上限とともに増える。
実装で得る幅は台形則の剰余、区間拡張の過大評価、端点と正規化係数の丸めを含む。
表示した十進桁を新しい区間の厳密な端点として使わず、返された数値を保持する。

`integrate` の既定の半径の条件は正規化前の積分の中点 $m$ に対する $\sqrt\varepsilon(1+|m|)$ である。
誤差関数の最終的な幅に同じ値がそのまま適用されるわけではなく、正規化係数との積の分も考える。
最終値に指定の許容誤差が必要なら、その係数の上界も使って積分に配分する許容誤差を決め、`QuadratureVerifier` で生成と再検証を行う。
[求積則の比較実験](oxref:validated-quadrature-assumptions)で、容量による停止と、広い包含区間の再検証の成功を分けて確認できる。

## まとめ

積分の包含区間に掛ける定数も、その誤差を含めて計算する。
二階導関数の包含区間が台形則の剰余を支える。
許容誤差やパネル数を指定する場合は [QuadratureVerifier](../../algorithms/certified-quadrature/) を使う。
