Hilbert 行列は $H_{ij}=1/(i+j+1)$（$i,j=0,\ldots,n-1$）で定義する。
その逆行列の成分は整数で、右辺を最初の単位ベクトルにすると、有理数の行列に対する厳密解は逆行列の最初の列になる。
しかし `solve` に f64 の係数を渡すと、証明の対象は丸めた行列である。
有理数の厳密解をその包含区間と比べても、含まれないことだけでは検証器の誤りにならない。

セルは次数を変え、証明された各成分の幅と、有理数の行列の厳密解を比較する。
単位はすべて無次元である。
正則性を証明できない場合は値を表示せず、エラーの分類を示す。
[線形系の数理](../../algorithms/verified-linear-systems/)の縮小率が 1 に近づくと、誤差上界が大きくなる理由を確認できる。

## 有理数の行列の厳密解

右辺 $e_0=(1,0,\ldots,0)^T$ に対する解は逆行列の第 0 列である。
Hilbert 行列の逆行列の公式から、その成分は

$$
x_i=(-1)^i(i+1){n+i\choose n-1}{n\choose n-i-1},\qquad i=0,\ldots,n-1
$$

となる。
セルでは二項係数を i128 の整数演算で計算してから表示するので、この範囲の参照値は係数の f64 丸めを経ていない。
$n=2$ なら $x=(4,-6)^T$ で、第一行は $4-3=1$、第二行は $2-2=0$ と手で検算できる。
$n$ が大きくなると符号の異なる大きな成分が打ち消し合い、係数の小さな変化が解に大きく影響する。

格納した行列を $\widehat H=H+\Delta H$、その解を $\widehat x$ とすると

$$
H(\widehat x-x)=-\Delta H\,\widehat x
$$

である。
従って $\|\widehat x-x\|\le\|H^{-1}\|\,\|\Delta H\|\,\|\widehat x\|$ となり、入力の丸めが悪条件性によって増幅されることが分かる。
この差と、$\widehat H$ の厳密解を求める計算の誤差は別である。
`solve` が後者を狭い区間で包んでも、前者は消えない。

```rust
//| id: validated-hilbert-exact-column
//| kind: definitions
//| title: 有理数の Hilbert 行列の厳密解
//| crates: []
pub(crate) fn exact_column(n: usize) -> Vec<i128> {
    let choose =
        |a: usize, b: usize| (0..b).fold(1_i128, |v, k| v * (a - k) as i128 / (k + 1) as i128);
    (0..n)
        .map(|i| {
            let sign = if i % 2 == 0 { 1 } else { -1 };
            sign * (i + 1) as i128 * choose(n + i, n - 1) * choose(n, n - i - 1)
        })
        .collect()
}
```

## 点の係数として格納した系

```rust
//| id: validated-hilbert-verified-solve
//| uses: [validated-hilbert-exact-column]
//| ref: validated-hilbert-verified-solve
//| title: Hilbert 行列の解と入力の丸め
//| run: button
//| crates: [scioxide-core, scioxide-validated, scioxide-linalg]
//| inputs:
//|   order: {"type":"range","label":"次数 n","min":2,"max":12,"step":1,"value":4}
//| cases:
//|   - {"id":"large","label":"n = 12","inputs":{"order":12}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","approx":{"value":16,"atol":1e-13}}
//|   - case: large
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","approx":{"value":144,"atol":1e-13}}
use scioxide_core::{SciOxideError, SciOxideErrorView, InvalidInputReason};
use serde_json::json;
let unsupported = |error: &SciOxideError| {
    matches!(error.view(),
SciOxideErrorView::InvalidInput { argument,
reason: InvalidInputReason::UnsupportedConfiguration, .. }
if argument == scioxide_core::argument!("rounding_environment"))
};
use scioxide_linalg::Matrix;
let n = order.round() as usize;
let exact = exact_column(n);
emit_table_with_columns!(
    ["次数", "有理数の行列の厳密解 x₀"],
    vec![(n, exact[0])],
    metadata = json!({"id":"reference"})
);
let result = (|| -> Result<_, SciOxideError> {
    let entries = (0..n)
        .flat_map(|i| (0..n).map(move |j| 1.0 / ((i + j + 1) as f64)))
        .collect();
    let a = Matrix::from_vec(n, n, entries)?;
    let mut b = vec![0.0; n];
    b[0] = 1.0;
    let certificate = scioxide_validated::solve(&a, &b)?;
    let enclosure = certificate.enclosure()?;
    let rows: Vec<_> = enclosure
        .iter()
        .enumerate()
        .map(|(i, x)| {
            let (lo, hi) = x.re.bounds().unwrap();
            (i, exact[i] as f64, lo, hi, hi.unwrap() - lo.unwrap())
        })
        .collect();
    Ok(rows)
})();
let outcome = match result {
    Ok(rows) => {
        let fmt = json!({"notation":"scientific","significantDigits":8});
        emit_table_with_columns!(
            json!([
                {"key":"0","label":"成分","type":"integer"},
                {"key":"1","label":"有理数行列の厳密解","type":"number","format":fmt},
                {"key":"2","label":"丸めた行列の下端","type":"number","format":fmt},
                {"key":"3","label":"丸めた行列の上端","type":"number","format":fmt},
                {"key":"4","label":"幅","type":"number","format":fmt}
            ]),
            rows,
            metadata = json!({"id":"solution"})
        );
        Outcome::satisfied("包含区間の計算が完了した")
    }
    Err(error) if unsupported(&error) => Outcome::unavailable("この環境では証明計算は未実行")
        .explanation("対応するネイティブ環境で証明を実行する。"),
    Err(error) => {
        Outcome::failed("解を含む区間を証明できなかった").status(format!("{:?}", error.kind()))
    }
};
emit_outcome!(outcome);
```

## 出力の読み方と証明の限界

例えば次数 4 の有理数の厳密解は $(16,-120,240,-140)^T$ である。
点の f64 係数の系では、第一成分の保証区間が 16 の少し下にあり、16 自体を含まないことがある。
表の「丸めた行列」という列名は、この違いを明示している。
区間の幅は計算誤差の上界を示すが、真の有理数係数への入力誤差を含む幅ではない。

次数を増やして証明できなくなった場合、`NumericalInstability` は縮小率などの証明条件が満たせないことを表す。
Hilbert 行列は数学的には全ての正の次数で正則なので、これを特異性の証明と解釈してはならない。
`Singular` が返る場合も通常精度の LU 分解の零ピボットである。
[混合精度の反復改良](../../../scioxide-linalg/algorithms/iterative-refinement/)は近似解の改善を扱い、このページの証明とは役割が異なる。

## 有理数の系を含む区間係数の検証

有理数の $1/(i+j+1)$ 自体を対象にするには、分子と分母の整数を点区間にして区間除算する。
その下端・上端を二つの行列に並べ、`DenseIntervalOperator::new` に渡す。
前処理には通常精度の行列の LU 分解を使うが、検証対象は上下限の間の全ての行列である。
元の有理数の Hilbert 行列はその集合に含まれるので、検証が成功すれば整数の厳密解も包含区間に入る。

次のセルは先の点係数とは別の問題を解く。
二つのセルを同じ次数にして、入力の丸めを含めたときの保証幅の違いを比較する。
既知の整数解の計算はページ内の定義を共有する。
次数は 2〜8 とし、有理数の整数解が f64 でも正確に表せる範囲で所属を確認する。

```rust
//| id: validated-hilbert-rational-system
//| ref: validated-hilbert-rational-system
//| title: 有理数の係数を区間で包む
//| run: button
//| crates: [scioxide-core, scioxide-linalg, scioxide-validated]
//| uses: [validated-hilbert-exact-column]
//| inputs:
//|   exact_order: {"type":"range","label":"区間係数の次数 n","min":2,"max":8,"step":1,"value":4}
//| cases:
//|   - {"id":"larger","label":"n = 8","inputs":{"exact_order":8}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","equals":16}
//|   - case: larger
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","equals":64}
use scioxide_core::{SciOxideError, SciOxideErrorView, InvalidInputReason};
use serde_json::json;
let unsupported = |error: &SciOxideError| {
    matches!(error.view(),
SciOxideErrorView::InvalidInput { argument, reason: InvalidInputReason::UnsupportedConfiguration, .. }
    if argument == scioxide_core::argument!("rounding_environment"))
};
use scioxide_linalg::{LuDecomposition, Matrix};
use scioxide_validated::{
    DecoratedInterval as D, DenseIntervalOperator, LinearVerifier, LuIntervalInverse,
    ValidatedOptions, point_enclosure,
};
let n = exact_order.round() as usize;
let exact = exact_column(n);
emit_table_with_columns!(
    ["次数", "有理数の厳密解 x₀"],
    vec![(n, exact[0])],
    metadata = json!({"id":"reference"})
);
let proof = (|| -> Result<_, SciOxideError> {
    let mut lower = Vec::new();
    let mut upper = Vec::new();
    let mut midpoint = Vec::new();
    for i in 0..n {
        for j in 0..n {
            let denominator = (i + j + 1) as f64;
            let bound = D::point(1.0)?.div(&D::point(denominator)?)?;
            let (lo, hi) = bound.set().bounds().unwrap();
            lower.push(lo.unwrap());
            upper.push(hi.unwrap());
            midpoint.push(1.0 / denominator);
        }
    }
    let lo = Matrix::from_vec(n, n, lower)?;
    let hi = Matrix::from_vec(n, n, upper)?;
    let mid = Matrix::from_vec(n, n, midpoint)?;
    let system = DenseIntervalOperator::new(lo.view(), hi.view())?;
    let factor = LuDecomposition::factor(&mid)?;
    let options = ValidatedOptions::new();
    let inverse = LuIntervalInverse::from_dense(&factor, options)?;
    let verifier = LinearVerifier::new(&system, &inverse, options)?;
    let mut rhs = vec![point_enclosure(0.0)?; n];
    rhs[0] = point_enclosure(1.0)?;
    let (report, certificate) = verifier.solve(&rhs)?;
    let bounds = certificate.map(|c| c.enclosure()).transpose()?;
    Ok((report, bounds))
})();
let outcome = match proof {
    Ok((report, bounds)) => {
        let rows: Vec<_> = (0..n)
            .map(|i| {
                let x = bounds.as_ref().map(|b| b[i].re);
                let ends = x.and_then(|x| x.bounds());
                (
                    i,
                    exact[i],
                    ends.and_then(|b| b.0),
                    ends.and_then(|b| b.1),
                    x.map(|x| x.contains(exact[i] as f64)),
                )
            })
            .collect();
        let fmt = json!({"significantDigits":12});
        emit_table_with_columns!(
            json!([
                {"key":"0","label":"成分","type":"integer"},
                {"key":"1","label":"有理数の厳密解","type":"integer"},
                {"key":"2","label":"下端","type":"number","format":fmt,"nullText":"証明なし"},
                {"key":"3","label":"上端","type":"number","format":fmt,"nullText":"証明なし"},
                {"key":"4","label":"厳密解を含む","nullText":"証明なし"}
            ]),
            rows,
            metadata = json!({"id":"solution"})
        );
        let result = if report.is_verified() {
            Outcome::satisfied("有理数の Hilbert 行列を含む系全体の解を含む区間を求めた")
        } else {
            Outcome::failed("区間係数の全ての系の正則性を証明できなかった")
        };
        result.status(format!("{:?}", report.status()))
    }
    Err(e) if unsupported(&e) => Outcome::unavailable("この環境では証明計算は未実行"),
    Err(e) => return Err(e.to_string()),
};
emit_outcome!(outcome);
```


区間係数では解の集合そのものが広がるので、点係数の系より幅が大きくても精度保証が悪化したとは限らない。
対象とする問題の集合が異なるからである。
入力区間の中に非常に悪条件な成員があると証明は難しくなり、元の有理数の行列の正則性だけでは集合全体の成功を保証できない。

## まとめ

保存された係数の厳密解と、有理数で定義した行列の厳密解を区別する。
悪条件では入力の丸めが解に大きく影響する。
有理数の行列自体を保証するには各係数を区間で包み、`LinearVerifier` を使う。
