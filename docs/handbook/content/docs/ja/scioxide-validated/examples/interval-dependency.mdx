区間演算の結果を読むには、包含区間が正しいことと、包含区間が狭いことを分けて考える必要がある。
ここでは、既知の区間との照合で端点と decoration を確かめ、カオス的なロジスティック写像で、式の書き方によって区間幅の増え方がどれほど変わるかを比べる。

## 既知の区間との照合

最初に、同じ変数の自乗と独立な二変数の積の違い、零を含む分母の除算での除外と decoration の格下げを、解析的に分かっている区間と照合する。

入力と期待する結果は次の四つである。
1. 区間 $X = [-1.0, 1.0]$ に対する自乗 $X^2$ の像集合は $[0.0, 1.0]$ である。
2. 独立な積 $X \cdot X$ の包含区間は $[-1.0, 1.0]$ である。
3. 分子 $[1.0, 2.0]$ を分母 $[0.0, 4.0]$ で除算した結果は、半無限区間 $[0.25, +\infty)$ である。
4. 除算で零の分母を除外したので、結果の decoration は `Decoration::Trv` である。

端点はどれも浮動小数点数で正確に表せるので、外向き丸めは端点を広げない。
セルは期待した集合の端点、得られた端点と decoration、期待した集合との一致を表に出す。
期待した集合は丸めを使わずに作るのでどの環境でも出るが、得られた端点の列はネイティブ環境だけで埋まる。

```rust
//| id: validated-enclosures
//| ref: validated-enclosures
//| title: 区間の平方・乗算・除算と演算環境を検証する
//| run: button
//| crates: [scioxide-core, scioxide-validated]
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"table-0","path":"/rows/0/0","equals":"x.square()"}
//|       - {"artifact":"table-0","path":"/rows/0/1","equals":0}
//|       - {"artifact":"table-0","path":"/rows/0/2","equals":1}
//|       - {"artifact":"table-0","path":"/rows/1/1","equals":-1}
//|       - {"artifact":"table-0","path":"/rows/1/2","equals":1}
//|       - {"artifact":"table-0","path":"/rows/2/1","approx":{"value":0.25,"atol":1e-14}}
//|       - {"artifact":"table-0","path":"/rows/2/2","equals":null}
use scioxide_core::{ExtendedInterval, SciOxideError, SciOxideErrorView, InvalidInputReason};
use scioxide_validated::DecoratedInterval as D;

// 1. 解析的に分かっている像の集合。構築は丸めを使わないので、どの環境でも作れる。
let expected = [
    ("x.square()", ExtendedInterval::new(Some(0.0), Some(1.0))),
    ("x.mul(&x)", ExtendedInterval::new(Some(-1.0), Some(1.0))),
    ("[1, 2] / [0, 4]", ExtendedInterval::new(Some(0.25), None)),
];
let mut sets = Vec::new();
for (name, set) in expected {
    sets.push((name, set.map_err(|e| e.to_string())?));
}
// 2. X = [-1, 1]、分子 [1, 2]、端に零を持つ分母 [0, 4] での外向き丸めの包含区間
let calculation = || -> Result<_, SciOxideError> {
    let x = D::new(-1.0_f64, 1.0)?;
    let numerator = D::new(1.0, 2.0)?;
    let denominator = D::new(0.0, 4.0)?;
    Ok([x.square()?, x.mul(&x)?, numerator.div(&denominator)?])
};
let unsupported = |error: &SciOxideError| {
    matches!(
        error.view(),
        SciOxideErrorView::InvalidInput {
            argument,
            reason: InvalidInputReason::UnsupportedConfiguration,
            ..
        } if argument == scioxide_core::argument!("rounding_environment")
    )
};
let enclosures = match calculation() {
    Ok(results) => Some(results),
    Err(error) if unsupported(&error) => None,
    Err(error) => return Err(error.to_string()),
};
use serde_json::json;
let rows: Vec<_> = sets
    .iter()
    .enumerate()
    .map(|(i, (name, set))| {
        let (elo, ehi) = set.bounds().unwrap();
        let y = enclosures.as_ref().map(|v| v[i]);
        let bounds = y.and_then(|v| v.set().bounds());
        (
            *name,
            elo,
            ehi,
            bounds.and_then(|b| b.0),
            bounds.and_then(|b| b.1),
            y.map(|v| format!("{:?}", v.decoration())),
            y.map(|v| v.set() == *set),
        )
    })
    .collect();
let missing = if enclosures.is_none() {
    "未実行"
} else {
    "非有界"
};
emit_table_with_columns!(
    json!([
        {"key":"0","label":"式"},
        {"key":"1","label":"期待した下端","type":"number","nullText":"−∞"},
        {"key":"2","label":"期待した上端","type":"number","nullText":"+∞"},
        {"key":"3","label":"下端","type":"number","nullText":missing},
        {"key":"4","label":"上端","type":"number","nullText":missing},
        {"key":"5","label":"decoration","nullText":"未実行"},
        {"key":"6","label":"集合の一致","nullText":"未実行"}
    ]),
    rows,
    metadata = json!({"id":"table-0"})
);
emit_outcome!(if enclosures.is_some() {
    Outcome::satisfied("既知の像を含む区間を求めた")
} else {
    Outcome::unavailable("この環境では証明計算は未実行")
});
```

ネイティブ環境（x86_64）では、三つの式すべてで「期待した集合と一致」が真になり、`x.square()` と `x.mul(&x)` の decoration は `Com`、除算の decoration は `Trv` になる。
`x.square()` の下端は `-0` と表示されるが、これは下端の零を $-0.0$ に正規化する規約によるもので、値は 0 である。
端点が正確に表せる入力なので、外向き丸めによる広がりはない。
wasm32 では包含区間の列が「未実行」と表示される。

## 区間幅の拡大要因の分離：丸め幅・感度・依存性

区間演算で得た区間の幅 $w(X) = U - L$ が広がる場合、その要因を区別する。
幅の増加には次の三つの起源がある。

1. **丸めによる幅（Rounding Width）**: 演算の真値が浮動小数点数で表せない場合、包含を保つために端点が外側の隣の浮動小数点数へ動く。
   一回の基本演算で端点が動くのは最近接値から高々 1 ulp である。
2. **入力の不確かさの伝播（Input Sensitivity）**: 入力区間がもともと持っていた幅 $w(X_{\text{in}}) > 0$ が、写像の微分係数 $|f'(x)|$ に応じて拡大される。
   これは問題そのものの性質であり、区間演算の欠陥ではない。
3. **式の依存性による過大評価（Dependency Overestimation）**: 同じ変数が式中に複数回現れると、本来は相関している値どうしが独立に動くものとして評価される。
   因数分解、`square` の利用、変数の出現を一回にする式の変形、雑音記号を共有するアフィン演算（`AffineForm`）で減らせる。

## ロジスティック写像での区間幅の増え方

カオス的な力学系では、丸めで生じた幅が二番目の要因で反復ごとに拡大され、式の書き方によっては三番目の要因も加わる。
一次元のロジスティック写像

$$
x_{n+1} = 4 x_n (1 - x_n) = 1 - (1 - 2x_n)^2
$$

を、binary64 で表した $x_0 = \operatorname{fl}(0.1)$ から反復する。
区間演算が含む区間を求めるのは、この二進数を厳密な初期値とした軌道である。

典型的な軌道のリアプノフ指数は $\lambda=\ln 2$ で、小さな初期誤差の増幅率は長時間平均で 1 反復あたり約 2 倍になる。
この平均からは binary64 の丸め誤差が約 50 回で大きくなると見積もれるが、特定の初期値の誤差や限界の反復回数を保証するものではない。
セルでは区間の幅を実際に計算し、位置をどこまで限定できるかを調べる。

二つの式は実数としては同じだが、区間演算では幅の増え方が異なる。
$X = [a, b] \subseteq [0, 1]$ に対して素朴な式 $4 \cdot X \cdot (1 - X)$ の幅は、二つの因子を独立に扱うので $4\{b(1-a) - a(1-b)\} = 4 w(X)$ となり、反復ごとに 4 倍になる。
変形した式 $1 - (1 - 2X)^2$ では $X$ が一回しか現れず、`square` は自乗の依存性を保つので、幅はおよそ $|f'(x)| w(X) = 4|1 - 2x|\, w(X)$ で増え、反復ごとの平均の増加率は $e^{\lambda} = 2$ に近づく。

次のセルは点の浮動小数点軌道と二つの式による区間を同時に反復し、幅を対数軸に描く。
破線は 1 回目の幅から $4^n$ と $2^n$ で伸ばした参照線であり、期待する形は素朴な式が $4^n$、変形した式が平均して $2^n$ に沿うことである。
表には 5 回ごとの値を出す。
反復回数 $N$ を増やすと、素朴な式の区間が非有界になる回数と、変形した式の区間幅が $O(1)$ に達する回数を確かめられる。
点の値は保証のない近似値であり、列名でそれを示す。
点の更新は基本演算だけなので、点の列はどの環境でも同じ値で出る。
区間の列とグラフはネイティブ環境だけで作られる。

```rust
//| id: validated-logistic-chaos
//| ref: validated-logistic-chaos
//| title: ロジスティック写像の点軌道と二つの式による区間包含区間
//| run: button
//| crates: [scioxide-core, scioxide-validated]
//| inputs:
//|   steps: {"type":"range","label":"反復回数 N [回]","description":"素朴な式は 30 回台で非有界になり、変形した式は 50 回前後で幅が O(1) に達する。","min":10,"max":60,"step":5,"value":30}
//| cases:
//|   - {"id":"naive-unbounded","label":"N = 40（素朴な式が非有界になる）","description":"素朴な式の区間は 37 回目に非有界になり、表の 40 回目は「非有界」になる。変形した式の幅は 40 回目で約 1.9×10⁻⁴ である。","inputs":{"steps":40}}
//|   - {"id":"rewritten-saturates","label":"N = 60（変形した式も軌道の情報を失う）","description":"変形した式の幅は 50 回目に約 0.32、55 回目以降は 1 程度になり、区間は [0, 1] 程度に広がる。","inputs":{"steps":60}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"table-0","path":"/rows/0/1","approx":{"value":0.100000000000000,"atol":1e-14}}
//|       - {"artifact":"table-0","path":"/rows/1/1","approx":{"value":0.585420538734197,"atol":1e-14}}
//|       - {"artifact":"table-0","path":"/rows/6/0","equals":30}
//|       - {"artifact":"table-0","path":"/rows/6/1","approx":{"value":0.320342475185814,"atol":1e-14}}
//|   - case: naive-unbounded
//|     expect:
//|       - {"artifact":"table-0","path":"/rows/7/1","approx":{"value":0.153548305897691,"atol":1e-14}}
//|       - {"artifact":"table-0","path":"/rows/8/0","equals":40}
//|       - {"artifact":"table-0","path":"/rows/8/1","approx":{"value":0.097904876416033,"atol":1e-14}}
//|   - case: rewritten-saturates
//|     expect:
//|       - {"artifact":"table-0","path":"/rows/10/1","approx":{"value":0.560036763222377,"atol":1e-14}}
//|       - {"artifact":"table-0","path":"/rows/12/0","equals":60}
//|       - {"artifact":"table-0","path":"/rows/12/1","approx":{"value":0.872398576618023,"atol":1e-14}}
use scioxide_core::{SciOxideError, SciOxideErrorView, InvalidInputReason};
use scioxide_validated::DecoratedInterval as D;
use serde_json::json;

let n_max = steps.round() as usize;
let x0 = 0.1_f64;
// 1. 点の軌道（f64、保証なし）: x ← 4x(1 − x)。基本演算だけなので環境によらず同じ値になる。
let mut points = vec![x0];
for _ in 0..n_max {
    let x = points[points.len() - 1];
    points.push(4.0 * x * (1.0 - x));
}
// 2. fl(0.1) を厳密な初期値とする、二つの式の区間反復
let calculation = || -> Result<_, SciOxideError> {
    let (one, two, four) = (D::point(1.0)?, D::point(2.0)?, D::point(4.0)?);
    let (mut naive, mut rewritten) = (D::point(x0)?, D::point(x0)?);
    let mut history = vec![(naive, rewritten)];
    for _ in 0..n_max {
        // 素朴な式 4·(x·(1 − x)): x が二回現れ、独立に扱われる
        naive = four.mul(&naive.mul(&one.sub(&naive)?)?)?;
        // 変形した式 1 − (1 − 2x)²: x は一回だけ現れ、自乗は square で計算する
        rewritten = one.sub(&one.sub(&two.mul(&rewritten)?)?.square()?)?;
        history.push((naive, rewritten));
    }
    Ok(history)
};
let unsupported = |error: &SciOxideError| {
    matches!(
        error.view(),
        SciOxideErrorView::InvalidInput {
            argument,
            reason: InvalidInputReason::UnsupportedConfiguration,
            ..
        } if argument == scioxide_core::argument!("rounding_environment")
    )
};
let history = match calculation() {
    Ok(history) => Some(history),
    Err(error) if unsupported(&error) => None,
    Err(error) => return Err(error.to_string()),
};
// 有界な区間の幅（非有界なら None）
let width = |y: &D<f64>| y.set().bounds().and_then(|(lo, hi)| Some(hi? - lo?));
let rows: Vec<_> = (0..=n_max)
    .step_by(5)
    .map(|n| {
        let pair = history.as_ref().map(|h| &h[n]);
        (
            n,
            points[n],
            pair.and_then(|p| width(&p.0)),
            pair.and_then(|p| width(&p.1)),
            pair.map(|p| p.1.contains(points[n])),
        )
    })
    .collect();
let fmt = json!({"notation":"scientific","significantDigits":8});
let missing = if history.is_none() {
    "未実行"
} else {
    "非有界"
};
emit_table_with_columns!(
    json!([
        {"key":"0","label":"反復回数","type":"integer"},
        {"key":"1","label":"点の値（保証なし）","type":"number","format":fmt},
        {"key":"2","label":"素朴な式の幅","type":"number","format":fmt,"nullText":missing},
        {"key":"3","label":"変形した式の幅","type":"number","format":fmt,"nullText":missing},
        {"key":"4","label":"点を含む","nullText":"未実行"}
    ]),
    rows,
    metadata = json!({"id":"table-0"})
);
match &history {
    None => emit_text!(
        "この環境では外向き丸めによる軌道の包含区間は未実行（対応するネイティブ環境が必要）"
    ),
    Some(history) => {
        // 4. 幅が正で有界な点だけを対数軸に描く（n = 0 の幅は 0）
        let series = |pick: fn(&(D<f64>, D<f64>)) -> &D<f64>| -> Vec<[f64; 2]> {
            history
                .iter()
                .enumerate()
                .filter_map(|(n, pair)| {
                    Some([n as f64, width(pick(pair)).filter(|&w| w > 0.0)?])
                })
                .collect()
        };
        let naive_points = series(|pair| &pair.0);
        let rewritten_points = series(|pair| &pair.1);
        // 最初に描いた点の幅から rateⁿ で伸ばした参照線
        let reference = |first: Option<&[f64; 2]>, rate: f64| -> Vec<[f64; 2]> {
            first.map_or(Vec::new(), |&[n0, w0]| {
                (n0 as usize..=n_max)
                    .map(|n| [n as f64, w0 * rate.powf(n as f64 - n0)])
                    .collect()
            })
        };
        let dashed = json!({"lineType": "dashed"});
        emit_line_chart!(
            &vec![
                json!({"name": "素朴な式 4·x·(1 − x)", "points": naive_points}),
                json!({"name": "変形した式 1 − (1 − 2x)²", "points": rewritten_points}),
                json!({
                    "name": "参照線 4ⁿ",
                    "points": reference(naive_points.first(), 4.0),
                    "style": dashed
                }),
                json!({
                    "name": "参照線 2ⁿ",
                    "points": reference(rewritten_points.first(), 2.0),
                    "style": dashed
                }),
            ],
            options = &json!({
                "xLabel": "反復回数 n [回]",
                "yLabel": "区間幅 w [-]",
                "yType": "log",
                "xMin": 0,
                "xMax": n_max
            })
        );
    }
}
emit_outcome!(if history.is_some() {
    Outcome::satisfied("軌道を区間で含む区間を求めた")
} else {
    Outcome::unavailable("この環境では証明計算は未実行")
});
```

x86_64 のネイティブ環境で同じセルを実行すると、1 回目の幅は素朴な式で $1.1 \times 10^{-16}$、変形した式で $3.3 \times 10^{-16}$ である。
素朴な式は参照線 $4^n$ に沿って増え、25 回目で $4.9 \times 10^{-2}$ に達する。
幅が 1 を超えると区間が $[0, 1]$ からはみ出し、幅はほぼ自乗で増えて 30 回目に $4.95 \times 10^{3}$、37 回目に非有界になる。
変形した式の幅は平均して反復ごとに約 2 倍で、30 回目に $2.9 \times 10^{-7}$、50 回目に $3.2 \times 10^{-1}$、55 回目以降は 1（$[0,1]$ 程度の区間）にとどまり、軌道の位置の情報を失う。
グラフから除いた点は、幅が 0 の $n = 0$ と、素朴な式が非有界になった回である。
表の範囲では点の値は常に変形した式の区間に入るが、これは点の値が正しいことの証明ではない。
真の軌道を含むことを保証するのは区間の側であり、点は丸め誤差が蓄積した近似値である。
wasm32 ではこの包含区間を計算せず、表の区間の列を「未実行」と表示して、グラフの代わりにその旨を出す。
近似区間で代替はしない。

## まとめと次に読むページ

既知の区間との照合では、端点を正確に表せる入力に対して自乗・独立積・零を含む分母の除算の結果と decoration を確かめた。
区間幅の増加は、丸め、入力の不確かさの伝播、式の依存性の三つに分けて読む。
ロジスティック写像では、実数として同じ式でも、変数の出現が二回の式は幅が反復ごとに 4 倍、一回の式は平均 2 倍で増える。
区間に浮動小数点の点が入ることは軌道の証明ではなく、証明は外向き丸めの包含区間そのものが担う。
wasm32 ではこの包含区間は計算されず、近似区間で代替しない。
