単位円と直線 $x=y$ の交点を連立非線形方程式として検証する。
解析的には $(x,y)=(1/\sqrt2,1/\sqrt2)$ と $(-1/\sqrt2,-1/\sqrt2)$ の二点である。
ここでは正の交点を囲む一つの箱に主張を限定し、近似値から存在と一意性を証明する手順を示す。
座標と残差は全て無次元である。

## 残差とヤコビ行列

未知数を $u=(x,y)^T$ とし、残差とヤコビ行列を

$$
F(u)=\begin{pmatrix}x^2+y^2-1\\x-y\end{pmatrix},\qquad
J(u)=\begin{pmatrix}2x&2y\\1&-1\end{pmatrix}
$$

とする。
方向 $v=(v_x,v_y)^T$ に対する作用は $J(u)v=(2xv_x+2yv_y,\ v_x-v_y)^T$ で、行列を毎回組み立てずに評価できる。
探索箱 $X$ と方向箱 $V$ についても同じ式を区間で評価すれば、全ての $u\in X$、$v\in V$ に対する作用を包める。
第一成分の自乗は `square()` とし、通常の積で同じ変数の依存性を失わないようにする。

## 点の作用と区間作用の実装

`SystemRootVerifier` は `IntervalJacobianOperator<f64>` を受け取る。
このトレイトには通常の残差・ヤコビ行列作用も必要なので、次の四つを実装する。

| トレイト | 入力 | この例の出力 |
|---|---|---|
| `ResidualOperator` | 点 $u$ | 通常精度の $F(u)$ |
| `JacobianOperator` | 点 $u$ と方向 $v$ | 通常精度の $J(u)v$ |
| `IntervalResidualOperator` | 箱 $X$ | $F(X)$ の包含区間 |
| `IntervalJacobianOperator` | 箱 $X$ と方向箱 $V$ | $J(X)V$ の包含区間 |

通常の作用の結果は近似であり、根の証明の根拠は後半の二つである。
配列の第 0 成分を $x$、第 1 成分を $y$ とし、残差も円・直線の順にそろえる。
実数の `IntervalBox` は虚部が厳密な零で、検証器がこの形を確認してから区間作用を呼ぶ。
この例は追加の一時領域を必要としないので、作業領域長は全て 0 である。

区間作用は一つ目の成分の計算後に二つ目が失敗する可能性も考え、両方を計算してから出力を更新する。
出力を書きかけのまま `Err` を返さないという作用素の規約を守るためである。
以下の定義を実行セルが `uses` で取り込む。

```rust
//| id: validated-circle-line-model
//| kind: definitions
//| title: 円と直線の残差とヤコビ行列の作用
//| crates: [scioxide-core, scioxide-validated]
use scioxide_core::{Complex, SciOxideError, JacobianOperator, ResidualOperator};
use scioxide_validated::{
    DecoratedInterval as D, IntervalBox, IntervalJacobianOperator, IntervalResidualOperator,
};
pub(crate) struct CircleLine;
fn shape(lengths: &[usize]) -> Result<(), SciOxideError> {
    for &n in lengths {
        if n != 2 {
            return Err(SciOxideError::dimension_mismatch([2], [n]));
        }
    }
    Ok(())
}
impl ResidualOperator<f64> for CircleLine {
    fn input_dimension(&self) -> usize {
        2
    }
    fn output_dimension(&self) -> usize {
        2
    }
    fn residual_workspace_len(&self) -> Result<usize, SciOxideError> {
        Ok(0)
    }
    fn residual_into(
        &self,
        x: &[f64],
        out: &mut [f64],
        _: &mut [f64],
    ) -> Result<(), SciOxideError> {
        shape(&[x.len(), out.len()])?;
        out.copy_from_slice(&[x[0] * x[0] + x[1] * x[1] - 1.0, x[0] - x[1]]);
        Ok(())
    }
}
impl JacobianOperator<f64> for CircleLine {
    fn jvp_workspace_len(&self) -> Result<usize, SciOxideError> {
        Ok(0)
    }
    fn jvp_into(
        &self,
        x: &[f64],
        v: &[f64],
        out: &mut [f64],
        _: &mut [f64],
    ) -> Result<(), SciOxideError> {
        shape(&[x.len(), v.len(), out.len()])?;
        out.copy_from_slice(&[2.0 * x[0] * v[0] + 2.0 * x[1] * v[1], v[0] - v[1]]);
        Ok(())
    }
}
impl IntervalResidualOperator<f64> for CircleLine {
    fn residual_enclosure_workspace_len(&self) -> Result<usize, SciOxideError> {
        Ok(0)
    }
    fn residual_enclosure_into(
        &self,
        x: &[IntervalBox<f64>],
        out: &mut [IntervalBox<f64>],
        _: &mut [IntervalBox<f64>],
    ) -> Result<(), SciOxideError> {
        shape(&[x.len(), out.len()])?;
        let (a, b) = (D::from(x[0].re), D::from(x[1].re));
        // 全成分を計算してから出力し、途中のエラーでは出力を変えない。
        let circle = a.square()?.add(&b.square()?)?.sub(&D::point(1.0)?)?;
        let line = a.sub(&b)?;
        let zero = D::point(0.0)?.set();
        out.copy_from_slice(&[
            Complex::new(circle.set(), zero),
            Complex::new(line.set(), zero),
        ]);
        Ok(())
    }
}
impl IntervalJacobianOperator<f64> for CircleLine {
    fn jvp_enclosure_workspace_len(&self) -> Result<usize, SciOxideError> {
        Ok(0)
    }
    fn jvp_enclosure_into(
        &self,
        x: &[IntervalBox<f64>],
        v: &[IntervalBox<f64>],
        out: &mut [IntervalBox<f64>],
        _: &mut [IntervalBox<f64>],
    ) -> Result<(), SciOxideError> {
        shape(&[x.len(), v.len(), out.len()])?;
        let (a, b) = (D::from(x[0].re), D::from(x[1].re));
        let (u, w) = (D::from(v[0].re), D::from(v[1].re));
        let first = D::point(2.0)?.mul(&a.mul(&u)?.add(&b.mul(&w)?)?)?;
        let second = u.sub(&w)?;
        let zero = D::point(0.0)?.set();
        out.copy_from_slice(&[
            Complex::new(first.set(), zero),
            Complex::new(second.set(), zero),
        ]);
        Ok(())
    }
}
```


## 箱の幅と証明の成否

中心を $c=(3/4,3/4)^T$ に固定すると、$F(c)=(1/8,0)^T$ である。
この点のヤコビ行列の逆は

$$
R=\begin{pmatrix}1/3&1/2\\1/3&-1/2\end{pmatrix}
$$

であり、点の Newton 補正 $c-RF(c)$ は両成分とも $17/24\approx0.708333$ になる。
これだけでは真の交点 $1/\sqrt2\approx0.707107$ に等しくない。
Krawczyk 写像では箱全体の導関数の変動を加え、補正点の周りをさらに含む区間を求める。

$X=[3/4-h,3/4+h]^2$ について、厳密算術では $\|I-RJ(X)\|_\infty\le4h/3$ となる。
しかしこの値が 1 未満でも、$K(X)\subseteq X$ を確認しなければ存在は証明できない。
小さすぎる $h$ では中心と真の交点のずれを箱が覆えず、大きすぎる $h$ では導関数の包含区間が広がって縮小率を抑えられない。
適度な大きさの箱が必要になる理由である。

セルは半幅だけを変え、解析的な参照点の所属と、検証器の状態・確立した事実・縮小率を並べる。
前処理の $1/3$ は f64 の近似であり、正確な逆だとは仮定しない。
`SystemRootCertificateView` は箱と中心を借用するので、それらは検証の終了まで保持する。
wasm では参照表のみを出し、証明の状態を未実行とする。

```rust
//| id: validated-circle-line-proof
//| ref: validated-circle-line-proof
//| title: 交点を囲む箱と Krawczyk の判定
//| run: button
//| crates: [scioxide-core, scioxide-linalg, scioxide-validated]
//| uses: [validated-circle-line-model]
//| inputs:
//|   half_width: {"type":"range","label":"箱の半幅 h [-]","min":0.01,"max":0.75,"step":0.01,"value":0.25}
//| cases:
//|   - {"id":"miss","label":"交点を含まない箱","inputs":{"half_width":0.01}}
//|   - {"id":"wide","label":"広い箱","inputs":{"half_width":0.75}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/0","approx":{"value":0.7071067811865476,"atol":1e-15}}
//|   - case: miss
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/3","equals":false}
//|   - case: wide
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/3","equals":true}
use scioxide_core::{SciOxideError, SciOxideErrorView, InvalidInputReason};
use serde_json::json;
let unsupported = |error: &SciOxideError| {
    matches!(error.view(),
SciOxideErrorView::InvalidInput { argument, reason: InvalidInputReason::UnsupportedConfiguration, .. }
if argument == scioxide_core::argument!("rounding_environment"))
};
use scioxide_linalg::MatrixView;
use scioxide_validated::{
    DenseIntervalOperator, RootClaim, RootVerificationStatus, SystemRootCertificateView,
    SystemRootVerifier, ValidatedOptions, interval_enclosure,
};
let root = 0.5_f64.sqrt();
let lo = 0.75 - half_width;
let hi = 0.75 + half_width;
emit_table_with_columns!(
    [
        "解析的な正の交点（f64 参照）",
        "箱の下端",
        "箱の上端",
        "参照点が箱に入る"
    ],
    vec![(root, lo, hi, lo <= root && root <= hi)],
    metadata = json!({"id":"reference"})
);
let proof = (|| -> Result<_, SciOxideError> {
    // J(3/4,3/4) の逆を f64 で近似した固定行列。検証器が精度を確かめる。
    let r = [1.0 / 3.0, 0.5, 1.0 / 3.0, -0.5];
    let inverse = DenseIntervalOperator::point(MatrixView::from_slice(2, 2, &r)?)?;
    let function = CircleLine;
    let verifier = SystemRootVerifier::new(&function, &inverse, ValidatedOptions::new())?;
    let region = [interval_enclosure(lo, hi)?; 2];
    let center = [0.75, 0.75];
    verifier.verify(SystemRootCertificateView {
        region: &region,
        center: &center,
        claim: RootClaim::Unique,
    })
})();
let outcome = match proof {
    Ok(report) => {
        emit_table_with_columns!(
            json!([
                {"key":"0","label":"検証状態"},
                {"key":"1","label":"確立した事実"},
                {"key":"2","label":"縮小率の上界","type":"number","nullText":"未計算"}
            ]),
            vec![(
                format!("{:?}", report.status()),
                format!("{:?}", report.evidence()),
                report.defect()
            )],
            metadata = json!({"id":"proof"})
        );
        match report.status() {
            RootVerificationStatus::Proved => {
                Outcome::satisfied("この箱に交点が一意に存在する")
            }
            RootVerificationStatus::Refuted => {
                Outcome::failed("一意な交点があるという主張を反証した")
            }
            _ => Outcome::partial("この箱では一意性が未確定"),
        }
        .status(format!("{:?}", report.status()))
    }
    Err(e) if unsupported(&e) => Outcome::unavailable("この環境では証明計算は未実行"),
    Err(e) => return Err(e.to_string()),
};
emit_outcome!(outcome);
```


既定の半幅 $1/4$ では箱への包含と縮小率の条件をともに満たす。
半幅 $0.01$ の箱は参照の根を含まず、残差の包含区間によって不在を示せれば `Unique` の主張は `Refuted` になる。
半幅 $0.75$ の箱は参照の根を含むが、縮小率の上界が 1 に達し、同じ検証では一意性が未確定になる。
参照点の所属と証明の成否が別であることを三つの設定で確かめる。

## 実装を別の問題へ移すとき

残差とヤコビ行列作用の成分順、入力次元、出力次元を一致させる。
微分の計算だけを別の式へ変更し、残差と違う写像を表す状態にしてはならない。
区間作用が返す包含区間には関数評価自身の丸め誤差も含める。
通常の点ヤコビ行列を一度計算し、その一点の値を箱全体の導関数として返すことはできない。

`SystemRootCertificate` を所有して `view_mut()` で領域を変更する使い方でも、主張の変更後には再検証する。
同じ次元で繰り返すなら `RootWorkspace` を事前確保して `verify_scoped` を使う。
この二変数の一回の検証は作用素評価 7 回と反復 2 回で、これに各作用の計算コストが加わる。
全領域の根を調べる場合は `isolate` と `verify_isolation` を使い、一つの箱の成功を全根の列挙と取り違えない。

## まとめ

同じ連立方程式を点の作用と区間作用の両方で表す。
Krawczyk 検証には近似逆行列の精度だけでなく、箱への包含と縮小率の条件が必要である。
箱を狭くすれば常に証明しやすいわけではなく、根の位置と導関数の変動をともに考える。
[根の数理](../../algorithms/root-certificates/)で個別の主張と全根の分離の違いを確認できる。
