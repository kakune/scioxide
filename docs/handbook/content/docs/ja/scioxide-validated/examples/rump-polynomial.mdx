大きな項どうしを引く式では、個々の項の相対誤差が小さくても最終結果を失うことがある。
次の式を $a=77617$、$b=33096$ で評価する。

$$
f(a,b)=333.75b^6+a^2(11a^2b^2-b^6-121b^4-2)+5.5b^8+\frac{a}{2b}.
$$

多項式部分を 4 倍すると整数演算になり、この入力では厳密に $-8$ となる。
したがって全体の値は $-2+a/(2b)=-54767/66192$ で、約 $-0.827396$ である。
セルは i128 の整数演算でこの相殺を独立に確かめ、元の式と簡単化した式の区間包含区間を比較する。
すべての量は無次元で、入力はこの整数対に固定する。
有理数を f64 に変換した参照値は丸めを含むが、簡単化した式を区間で計算した結果は厳密な有理数を含む。

## 大きな項の相殺と整数による検算

この入力では $b^8$ の項はおよそ $10^{36}$ の尺度だが、全体の値は 1 の程度である。
大きな項を f64 で丸めたときの絶対誤差は最終結果よりはるかに大きくなりうる。
演算ごとの相対誤差が小さいことは、相殺後の結果の相対誤差が小さいことを意味しない。

多項式部分を $P$ とすると、$333.75=1335/4$、$5.5=11/2$ から

$$
4P=1335b^6+4a^2(11a^2b^2-b^6-121b^4-2)+22b^8
$$

となり、入力が整数なら全項を整数で評価できる。
セルは固定入力のこの式を i128 で評価し、$4P=-8$ を得る。
この入力では中間値も i128 の範囲内だが、任意の整数入力へ同じ方法を無条件に拡張することはできない。
最後の有理数 $-2+77617/66192=-54767/66192$ は二進数で有限桁では表せないため、表示用の f64 値にも丸めがある。

## 二つの式の区間評価

元の式を区間で評価すれば、相殺が起きても真値の包含は維持できる。
ただし大きな中間値の丸めの幅が残るため、結果が巨大な区間になることがある。
整数計算によって正当化した簡単化後の式を区間で評価すれば、最後の小さな除算・加算の丸めだけを包める。
式の変形が有効なのは、この入力で多項式部分を厳密に相殺できることを独立に確かめたからである。

```rust
//| id: validated-rump-polynomial
//| ref: validated-rump-polynomial
//| title: Rump の式と桁落ち
//| run: button
//| crates: [scioxide-core, scioxide-validated, scioxide-linalg]
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/0","approx":{"value":-8,"atol":1e-13}}
use scioxide_core::{SciOxideError, SciOxideErrorView, InvalidInputReason};
use scioxide_validated::DecoratedInterval as D;
use serde_json::json;
let unsupported = |error: &SciOxideError| {
    matches!(error.view(),
SciOxideErrorView::InvalidInput { argument,
reason: InvalidInputReason::UnsupportedConfiguration, .. }
if argument == scioxide_core::argument!("rounding_environment"))
};
let (a, b) = (77617_i128, 33096_i128);
let integer = 1335 * b.pow(6)
    + 4 * a * a * (11 * a * a * b * b - b.pow(6) - 121 * b.pow(4) - 2)
    + 22 * b.pow(8);
let (a, b) = (a as f64, b as f64);
let naive = 333.75 * b.powi(6)
    + a * a * (11.0 * a * a * b * b - b.powi(6) - 121.0 * b.powi(4) - 2.0)
    + 5.5 * b.powi(8)
    + a / (2.0 * b);
emit_table_with_columns!(
    [
        "多項式部分の4倍（厳密）",
        "素朴な f64 値（保証なし）",
        "有理数の参照値（保証なし）"
    ],
    vec![(integer, naive, -54767.0 / 66192.0)],
    metadata = json!({"id":"reference"})
);
let result = (|| -> Result<_, SciOxideError> {
    let (a, b) = (D::point(a)?, D::point(b)?);
    let b2 = b.square()?;
    let b4 = b2.square()?;
    let b6 = b4.mul(&b2)?;
    let b8 = b4.square()?;
    let a2 = a.square()?;
    let inner = D::point(11.0)?
        .mul(&a2.mul(&b2)?)?
        .sub(&b6)?
        .sub(&D::point(121.0)?.mul(&b4)?)?
        .sub(&D::point(2.0)?)?;
    let ratio = a.div(&D::point(2.0)?.mul(&b)?)?;
    let original = D::point(333.75)?
        .mul(&b6)?
        .add(&a2.mul(&inner)?)?
        .add(&D::point(5.5)?.mul(&b8)?)?
        .add(&ratio)?;
    let simplified = D::point(-2.0)?.add(&ratio)?;
    let rows = [("元の式", original), ("簡単化した式", simplified)].map(|(name, x)| {
        let (lo, hi) = x.set().bounds().unwrap();
        (name, lo, hi, hi.unwrap() - lo.unwrap())
    });
    Ok(rows)
})();
let outcome = match result {
    Ok(rows) => {
        let fmt = json!({"notation":"scientific","significantDigits":8});
        emit_table_with_columns!(
            json!([
                {"key":"0","label":"式"},
                {"key":"1","label":"下端","type":"number","format":fmt},
                {"key":"2","label":"上端","type":"number","format":fmt},
                {"key":"3","label":"幅","type":"number","format":fmt}
            ]),
            rows,
            metadata = json!({"id":"enclosures"})
        );
        Outcome::satisfied("包含区間の計算が完了した")
    }
    Err(error) if unsupported(&error) => Outcome::unavailable("この環境では証明計算は未実行")
        .explanation("対応するネイティブ環境で証明を実行する。"),
    Err(error) => return Err(error.to_string()),
};
emit_outcome!(outcome);
```

## 表から読み取ること

最初に整数の列が $-8$ であることを確認し、次に二つの区間が有理数の参照値の周囲を含むかを見る。
元の式の f64 値と参照値の差は大きくても、元の式の区間包含区間が広ければ包含と矛盾しない。
簡単化後の包含区間の幅が数 ulp の程度になるのは、相殺する大きな項を誤差なく除去できたためである。

同じことを実測データへ適用するときは、入力の不確かさを忘れない。
ここで示した簡単化は特定の整数対についての値の恒等式で、周辺の入力全体について多項式部分が $-2$ になるという主張ではない。
入力を区間へ広げる場合は元の関数の依存性を保つ式変形や、適切なアフィン演算のモデルを改めて用意する。

## まとめ

外向き丸めは桁落ちがあっても包含を保つが、狭い包含区間を保証しない。
この固定入力では整数演算で大きな項を相殺してから除算できる。
[アフィン演算](../../algorithms/affine-arithmetic/)は、変数の相関による別の過大評価を扱う。

精度保証の方法と浮動小数点演算の関係は、Rump の [Verification methods（2010）](https://www.tuhh.de/ti3/rump/intlab/ActaNumerica2010.pdf) に詳しい。
