Wilkinson 多項式 $W(z)=\prod_{j=1}^{20}(z-j)$ は、係数の小さな変化に対する根の感度を示す例である。
整数係数は i128 で厳密に生成できるが、f64 への変換で一部の係数が丸められる。
`PolynomialRootPlan` が証明するのは保存された係数の多項式なので、無摂動でも各整数が厳密な根だとは仮定しない。

セルは $z^{19}$ の係数に $\delta$ を加え、中心 $1,\ldots,20$、半径 $r$ の円板について「根が一つある」という主張を検証する。
$\delta=-2^{-23}$ はよく使われる摂動である。
いずれも無次元で、$r<1/2$ のため円板は互いに交わらない。
`Inconclusive` は個数が零であることも、複素根が発生したことも証明しない。
全根の被覆を主張するには、別途すべての根を覆う円板と個数を検証する必要がある。

## 係数の摂動と近似根の感度

$W(z)+\delta z^{19}=0$ の単根 $z(\delta)$ を $\delta=0$ で微分すると

$$
\frac{dz}{d\delta}\bigg|_{z=j}=-\frac{j^{19}}{W'(j)},\qquad
W'(j)=(-1)^{20-j}(j-1)!(20-j)!
$$

を得る。
分子の大きなべきにより、係数の小さな変化が根の位置に大きく影響することが分かる。
これは局所的な感度の式であり、有限の摂動で根がどの円板へ移るかを保証する式ではない。
詳しい悪条件性は [Wilkinson 多項式の感度](../../../scioxide-poly/examples/wilkinson-root-sensitivity/) で扱う。

セルは $(z-j)$ を整数係数に順に掛け、最後に f64 へ変換する。
この変換で丸めが必要な係数は 5 個あり、主張の対象はその丸めた多項式である。
摂動を零に設定しても、元の整数係数を完全に保持した多項式と同じとは仮定しない。
一方、次数と係数の順序は明確で、`PolynomialRootPlan` に渡す配列は定数項から始まる。

## 円板の個数を比較する手順

半径を固定して $\delta=0$ と $\delta=-2^{-23}$ を比較し、次に同じ摂動で半径を変える。
この順序なら係数の変化と領域の変化による効果を区別できる。
半径が $1/2$ 未満なので、隣接する整数を中心とする円板は互いに交わらない。
既知の整数の位置は初期の基準であって、摂動後の根を円板内に仮定するものではない。

```rust
//| id: validated-wilkinson-root-counts
//| ref: validated-wilkinson-root-counts
//| title: Wilkinson 多項式の係数と根の個数
//| run: button
//| crates: [scioxide-core, scioxide-validated, scioxide-linalg]
//| inputs:
//|   perturbation: {"type":"range","label":"係数の摂動 δ","min":-0.00000011920928955078125,"max":0,"step":0.00000011920928955078125,"value":0}
//|   radius: {"type":"range","label":"円板の半径 r","min":0.01,"max":0.4,"step":0.01,"value":0.1}
//| cases:
//|   - {"id":"perturbed","label":"δ = −2⁻²³","inputs":{"perturbation":-0.00000011920928955078125}}
//| tests:
//|   - case: default
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/1","approx":{"value":5,"atol":1e-13}}
//|   - case: perturbed
//|     expect:
//|       - {"artifact":"reference","path":"/rows/0/2","approx":{"value":-1.1920928955078125e-07,"atol":1e-13}}
use scioxide_core::{SciOxideError, SciOxideErrorView, InvalidInputReason};
use serde_json::json;
let unsupported = |error: &SciOxideError| {
    matches!(error.view(),
SciOxideErrorView::InvalidInput { argument,
reason: InvalidInputReason::UnsupportedConfiguration, .. }
if argument == scioxide_core::argument!("rounding_environment"))
};
use scioxide_core::Complex;
use scioxide_validated::{
    PolynomialRootCertificate, PolynomialRootPlan, RootDisk, ValidatedOptions,
};
let mut exact = vec![1_i128];
for j in 1..=20 {
    let mut next = vec![0_i128; exact.len() + 1];
    for (k, &c) in exact.iter().enumerate() {
        next[k] -= j * c;
        next[k + 1] += c;
    }
    exact = next;
}
let mut coefficients: Vec<f64> = exact.iter().map(|&c| c as f64).collect();
coefficients[19] += perturbation;
let rounded = exact.iter().filter(|&&c| (c as f64) as i128 != c).count();
emit_table_with_columns!(
    ["次数", "f64 変換で丸めた係数の数", "z¹⁹ の摂動"],
    vec![(20, rounded, perturbation)],
    metadata = json!({"id":"reference"})
);
let result = (|| -> Result<_, SciOxideError> {
    let plan = PolynomialRootPlan::new(&coefficients, ValidatedOptions::new())?;
    let mut rows = Vec::new();
    for j in 1..=20 {
        let certificate = PolynomialRootCertificate {
            disk: RootDisk {
                center: Complex::new(j as f64, 0.0),
                radius,
            },
            count: 1,
        };
        let report = plan.verify(certificate)?;
        rows.push((j, radius, report.count(), format!("{:?}", report.status())));
    }
    Ok(rows)
})();
let outcome = match result {
    Ok(rows) => {
        emit_table_with_columns!(
            json!([
                {"key":"0","label":"中心の実部","type":"integer"},
                {"key":"1","label":"半径","type":"number"},
                {"key":"2","label":"証明した個数","type":"integer","nullText":"未確定"},
                {"key":"3","label":"検証状態"}
            ]),
            rows,
            metadata = json!({"id":"counts"})
        );
        Outcome::partial("円板ごとの判定を表に示した。全根の被覆は未証明")
    }
    Err(error) if unsupported(&error) => Outcome::unavailable("この環境では証明計算は未実行")
        .explanation("対応するネイティブ環境で証明を実行する。"),
    Err(error) => return Err(error.to_string()),
};
emit_outcome!(outcome);
```

## 未確定の個数と被覆の判定

`Proved` の行では、その円板に重複度込みで 1 個の根がある。
`Refuted` の行では別の個数が証明されているので、`count()` を読む。
`Inconclusive` の行の空欄は、計算が決められなかったことを表す。
実際に根が円板を出た場合と、境界に近くて不等式を証明できない場合は、未確定という表示だけでは区別できない。

全ての円板について 1 個ずつ証明でき、互いに素で個数の和が 20 なら、数学的には全根を覆う。
このセルは個々の提案の比較に限定しており、被覆の API として成功を受け取るには同じ証明用データ群を `verify_cover` へ渡す。
未確定の円板が残る場合は、近似根から `isolate` で円板を拡大・併合する方法もある。
根が集まった領域を一つの円板で数える場合は、各根を一つずつ分離したという意味にはならない。
[境界上の根の実験](oxref:validated-pellet-multiplicity)では判定不能の原因を解析的に特定できる例を確認できる。

## まとめ

係数を正確に生成することと、f64 に正確に格納することは別である。
個数の判定が未確定なら、根がないとは結論できない。
